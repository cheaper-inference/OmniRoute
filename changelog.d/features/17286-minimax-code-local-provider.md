- **feat(providers):** add the MiniMax Code provider — OmniRoute can now route chat completions through the managed MiniMax subscription gateway and, for a plain chat turn, through the locally installed MiniMax Code CLI (`mcode exec --output-format stream-json`) under the `minimax-code` / `mmcode` alias, with the credential read from the user's own local MiniMax Code profile instead of being asked for or stored by OmniRoute: the provider reads the local auth profile, and when the account rotates the token it writes the refreshed credential back to that same local profile and keeps the CLI session state in sync; the gateway transport speaks the native tool protocol, so a request that carries client tools comes back as `tool_calls` for the client to execute, and the gateway transport has no fallback: a failing gateway answers with a 502 that names the transport, while the locally installed MiniMax Code CLI stays available as an explicit transport (`MINIMAX_CODE_TRANSPORT=cli` or `auto`) — it never answers a request that asked for the gateway, and it cannot hand a tool call back to the client, so it never answers a request that carries client tools
- **feat(oauth):** the MiniMax Code provider can now be signed in from the dashboard — the provider page offers the MiniMax account device-code flow (RFC 8628 + S256-PKCE), the panel shows the verification URL and the code to confirm, and the credential that comes back is written into the local MiniMax Code profile (`~/.minimax/auth/prod/<region>/mcode-public/auth.json`), so the CLI and the local agent pick it up on their next session; the provider itself stays a no-auth provider: the dashboard connection is the account entry, the local profile is the credential
