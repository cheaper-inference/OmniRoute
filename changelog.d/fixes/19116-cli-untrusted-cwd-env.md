- **fix(cli):** a `.env` in the directory where you run `omniroute` now sets only ports (`PORT`, `API_PORT`, `DASHBOARD_PORT`), `REQUIRE_API_KEY` (`true`, `1` or `yes`), locale and time zone (`LANG`, `LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `TZ`) and `NO_COLOR`/`FORCE_COLOR`, with exact upper-case names and checked values. Before, it could set anything, and `omniroute serve` passed it to the server and every tool it spawns, so a cloned repository could choose where credentials go (`OMNIROUTE_BASE_URL`, `KILO_API_URL`, ...), load code (`NODE_OPTIONS`, `BROWSER`, `HEADROOM_PYTHON`), change the self-update source or weaken TLS. Other keys there are skipped with a warning that names them but not their values; if you wrote them yourself, set them in the shell or in `<DATA_DIR>/.env`. A context's stored token is now paired only with that context's own origin, for CLI requests and for `launch`, `configure` and `setup-*` with `--remote`. `omniroute packs` no longer falls back to `optional-packs.index.json` in the working directory; pass `--source` when the index is not next to the CLI install (#19116)
