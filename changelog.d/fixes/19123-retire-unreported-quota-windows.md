- **fix(domain):** Quota windows a provider stops reporting no longer block routing. Providers add and remove windows (OpenAI dropped the 5-hour Codex window for some plans), but OmniRoute kept a window's last reading until its own reset: a Codex plan left with only a weekly window stayed "session usage 100%" for days after its weekly window restarted, and every request failed with "All codex accounts reached configured quota threshold". A usage reading the provider's adapter attests as complete (`quotasComplete`: the payload names every window, a removed one as `null`, and all of them parse) now retires the windows it no longer reports — in the quota cache, in the snapshots a restart rehydrates (an appended retirement record, history kept), in the persisted Codex quota state and in Claude's saturation buckets — and a Codex scope recovers once every window it still has is below its limit. Codex and Claude adapters attest; partial evidence (response headers, stale cached readings, unparseable windows) still updates only what it carries. (thanks @aldoeliacim)
