- **fix(live-ws):** an open live dashboard WebSocket now loses access when its credential does. The heartbeat re-runs the connect-time check, so a connection whose API key was revoked, disabled, expired, deleted or dropped below `manage`, or whose dashboard session was signed out or ended by a password change, is closed with 4001 at the next heartbeat (15 s). API keys are checked against the database rather than the per-process key cache, on connect and on every heartbeat, so a change made by another process counts at once and a closed client cannot reconnect with the same key. If the database cannot be read during a heartbeat, the affected connections are closed too; the dashboard then reconnects. A write lock held by another process does not close a valid key connection: the check reads the key, and its `last_used_at` update is skipped and retried later.
