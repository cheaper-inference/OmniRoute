- **fix(kiro):** Every Kiro request (inference, model catalog, usage, profile discovery, API-key import) now sends one Kiro IDE identity, `KiroIDE-1.4.178-<machineId>`, with a machineId derived from the connection id so it stays stable across token refreshes. The model catalog asks like the Kiro IDE (`profileArn` first, `nextToken` pages up to 10) and keeps the list Kiro returns for the connection's egress region instead of reaching past it with an old IDE version. Model discovery now resolves the connection's own proxy, the same egress inference uses, so the listed models are the ones the connection can call. Builder ID and GitHub/Google logins, which have no profile of their own, now send the Kiro IDE's fixed profileArn on inference as well as on the catalog, so their requests no longer fail with 400 `profileArn is required for this request.`. `KIRO_IDE_VERSION` moves the identity forward without a release when Kiro raises its version floor; `KIRO_USER_AGENT` now reaches Kiro requests but stale values below the pin are ignored, and a version-gate rejection logs how to recover ([#19607](https://github.com/cheaper-inference/OmniRoute/issues/19607), [#19626](https://github.com/cheaper-inference/OmniRoute/pull/19626))
