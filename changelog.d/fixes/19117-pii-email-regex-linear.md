- **fix(pii):** the request-side email PII rule no longer takes quadratic time on long runs of characters like `ab-ab-ab-…` or `a.a.a.…`. The PII masker runs it on every request by default, even with redaction off, so one 80 KB message held the event loop for about 4 s; it now takes about 15 to 20 ms of CPU time (median of 100 calls) on the slowest input shapes found so far. Matches are unchanged, except for a second address written directly after another (`a@b.co-x@c.dd`) whose local part is longer than 64 characters after the separator: it is now matched only in part or not at all, and an address glued on after it can match from inside its domain (`…@c.dd-yy@e.ff` matches as `c.dd-yy@e.ff`) (#19117)
