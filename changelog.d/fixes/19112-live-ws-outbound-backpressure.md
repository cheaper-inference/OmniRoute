- **fix(live-ws):** the live dashboard WebSocket now closes a connection whose unsent output passes 4 MiB, so a client that stops reading, or keeps re-sending `subscribe` to replay the backlog, can no longer grow server memory without bound per connection. The welcome frame replays only the newest backlog events that fit in 1 MiB (at most 500) and echoes only known channel names, and each dropped connection logs one warning. Inbound messages no longer count as heartbeat liveness, so a client that sends application pings but does not read, or does not answer protocol pings, is reaped like any other unresponsive socket.
