- **fix(providers):** Muse Code requests no longer get "Muse Code subscriptions cover requests from the Muse Code client only" for declaring a tool under a name Muse keeps for its own client: every function name is now aliased for Muse Code and restored in the response, instead of the eight names on a fixed list that missed OpenCode's `shell` (and Codex-style `apply_patch`/`update_plan`), which refused every OpenCode turn routed to Muse Code. Responses streams restore the client's tool names everywhere they appear, including `function_call_arguments` events and the tools echoed by every response event, not only on call items. A thread that ran tools on another model can now continue on Muse Code: session ownership no longer refuses tool call ids Muse did not issue ("Muse tool continuation was not issued to this session and caller generation", 409), since they carry no account state; encrypted reasoning, item references and `previous_response_id` stay bound to the session that received them. A session whose Muse account is rate limited (Muse's "Subscription quota exhausted" 429) now gets that 429 with the reset time instead of "Muse session owner is unavailable; cross-account continuation is forbidden" (503), which clients retried in a loop (#19291)
