- **fix(db):** when `STORAGE_ENCRYPTION_KEY` is not in the process environment and the encryption module reads it from a `.env` file itself, the value is now split on the first `=` and parsed like `bin/cli/utils/parseEnvValue.mjs` (quotes, inline ` #` comments; unlike `scripts/build/bootstrap-env.mjs`, a value that starts with `#` is kept as the key). The old `split("=", 2)` dropped everything after a second `=`, so a base64 key (for example `openssl rand -base64 32`, which the error messages suggest) lost its padding and derived a different key than the CLI. Upgrade note: where this fallback is the only thing that loads the key and the old reading differs (a value with a second `=`, a quoted value containing `=`, or an unquoted value with an inline ` #` comment), data stored under the old reading still decrypts while the `.env` line stays as it is. That includes processes that inherit the environment (child processes, worker threads, `pm2 restart --update-env`): they read the same `.env` file again to find the old reading. A process that inherits the key without `OMNIROUTE_DOTENV_KEY_OLD_READING=1`, or cannot find the same `.env` (another `DATA_DIR`, working directory or home), cannot read data left under the old reading. Only provider connection tokens (API key, ID, access and refresh tokens in `provider_connections`) are re-encrypted at startup, including tokens still in the pre-3.7.9 format under the old reading. Every other encrypted value (for example settings, `providerSpecificData`, webhooks, proxy credentials, API key and JWT secrets) keeps the old encryption, so leave the `.env` line unchanged; a warning with both key lengths is logged at every start. If the line was edited, restore it. Setting the old value in the process environment instead breaks the re-encrypted tokens. Where the new reading finds no usable key but the old one did (`KEY="" # note`, `KEY="  " # note`), the old value is used, so an upgrade does not turn encryption off. As before and as in the CLI, the first key line with a non-empty value wins, even a blank one (`KEY="  "`); values are then stored in plaintext while encryption is reported as on, which this change does not fix (#0000)
