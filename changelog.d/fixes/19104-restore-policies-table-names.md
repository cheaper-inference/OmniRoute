- **fix(ops):** `bin/restore-policies.sh` no longer runs SQL taken from a snapshot. It spliced the snapshot's table names into the SQL it passes to the `sqlite3` CLI, so a crafted snapshot could run any statement, including the CLI's `writefile()`, as the operator running the restore. Table names must now be plain identifiers and the tables ordinary (not virtual) tables, or the restore is refused before anything is written; the checks and the restore read the same private copy of the snapshot, and a failed restore now rolls back instead of keeping the tables it had already emptied. The snapshot and backup paths in `restore-policies.sh`, `restore-data.sh` and `snapshot-data.sh` are now quoted as SQL strings, so a data directory with an apostrophe works, and the three scripts ignore the operator's `~/.sqliterc`, so a setting such as `.headers on` no longer makes a valid snapshot look malformed (#19104)
