- **fix(authz):** `REQUIRE_API_KEY` is now read the same way by the request gate and by both startup exposure warnings (Next server and `omniroute serve`): `true`, `1` and `yes` turn it on regardless of case or surrounding whitespace. Before, a value such as `TRUE`, `True`, `YES` or `" true"` left the gate off, so `/v1` served requests without a key, while both warnings treated the value as on and printed nothing. Deployments that set one of those spellings now actually require a key, and clients without one get `401`. Any other value, including `on`, still means off.
