- **fix(sse):** the non-streaming upstream response cap (`OMNIROUTE_MAX_NONSTREAMING_RESPONSE_BYTES`, default 64 MiB) now counts decoded bytes. It used to check only the `Content-Length` header, which is the compressed size for gzip/br bodies and is missing on chunked ones, so a few KB of gzip or an unlabelled chunked body was buffered in full. The JSON-to-SSE conversion on streaming requests, the provider pipeline's error-body peeks, the non-streaming and streaming final error-body reads, and the credential-refresh / ModelScope / recovery peeks that clone the response all use the same cap. Past it the read stops with the existing over-cap error, and the upstream connection is closed except where a clone is left for the caller (#19114)
