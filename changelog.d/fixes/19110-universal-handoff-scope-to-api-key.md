- **fix(combo):** universal handoff summaries, context-relay handoffs, session model history and `context_cache_protection` pins are now stored per API key. Before, they were keyed only by session id and combo, so on an instance where several API keys share a combo, a caller that sent the same `x-session-id` as another key (or produced the same request fingerprint) could receive that key's conversation summary or plant one for it. Requests without an API key share one bucket. Embeddings, rerank and the combo safety-net redirect do not pass the caller's key, so their `context_cache_protection` pins still go to that shared bucket, as before. Rows written by older versions are no longer read; handoffs expire within their TTL, and an in-progress session starts fresh once after the upgrade.
