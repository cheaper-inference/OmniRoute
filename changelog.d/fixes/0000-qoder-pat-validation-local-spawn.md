- **fix(providers):** validating a Qoder Personal Access Token (`pt-…`) no longer starts the local `qodercli` for remote callers. The validator now honours the local-execution permission that remote-reachable routes (`POST /api/providers/validate`, import and bulk with key validation — including through the `if` alias —, connection tests) pass for non-loopback requests; those get "validated with the local qodercli, which runs only for requests from this machine". Regular Qoder API keys still validate over HTTP, and local validation is unchanged.
