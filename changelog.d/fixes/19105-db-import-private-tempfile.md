- **fix(db):** `POST /api/db-backups/import` now stages the uploaded database in a fresh private directory (`mkdtemp`, mode 0700, as the export routes already do) as a 0600 file created exclusively. It used to write `omniroute-import-<Date.now()>.sqlite` straight into the system temp directory with default permissions (0644 under a 022 umask), so on a shared host another local user could read the uploaded credentials. A file or symlink already at that path was also reused or followed; where `fs.protected_symlinks` or `fs.protected_regular` is off, another user could use that to redirect or capture the write. The staging directory is removed after every request, provided other users cannot rename entries in the temp directory (it has the sticky bit, as `/tmp` does, or only the service user can write to it). After a successful import the live `storage.sqlite` is also mode 0600, because `copyFileSync` keeps the staging file's permissions. (#19105)
