- **fix(mcp):** `/api/mcp/*` now validates the `Origin` header for every caller, as the MCP Streamable HTTP spec requires (present and invalid → 403). Before, only dashboard-session writes were checked, so a request carrying an API key, the local CLI token, or no credential at all (loopback with login disabled) reached the MCP transport whatever its `Origin` said. Clients that send no `Origin` (the OmniRoute CLI, SDK and IDE clients) are unaffected. A browser `Origin` is accepted when it is OmniRoute's own public origin (configured base URL, trusted reverse proxy's forwarded host, direct loopback/LAN IP) or `localhost` / `127.0.0.1` / `[::1]` on any port; a browser MCP client served from any other site now gets 403 with a JSON-RPC error body (`error.data.code: "INVALID_ORIGIN"`). Refs [#17131](https://github.com/diegosouzapw/OmniRoute/issues/17131) ([#17273](https://github.com/diegosouzapw/OmniRoute/pull/17273)) — thanks @HouMinXi
