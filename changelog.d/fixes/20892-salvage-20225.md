- **fix(call-logs):** A call log whose detail artifact was published successfully no longer runs a second `UPDATE` that matches zero rows; the "mark missing" `UPDATE` now runs only for a skipped, failed or expired artifact write, so each detail-bearing request takes one less SQLite write. (salvaged from [#20225](https://github.com/cheaper-inference/OmniRoute/pull/20225), thanks @serenity-X)
- **fix(providers):** The reset time in a CodeBuddy CN rate-limit message (`请于 <time> 后重试`, China Standard Time) is now read as a retry hint, so a connection with upstream retry hints on cools down until that time instead of the base cooldown. (salvaged from [#20225](https://github.com/cheaper-inference/OmniRoute/pull/20225), thanks @serenity-X)
- **fix(db):** Loading the database settings page no longer counts the rows and reads the page usage of every table (about 300 queries) just to show the database size; it reads the page size and page count instead. The explicit refresh-stats action still returns the full per-table statistics. (salvaged from [#20225](https://github.com/cheaper-inference/OmniRoute/pull/20225), thanks @serenity-X)
- **fix(db):** The model call statistics query filters wire observations on the row it already reads instead of looking the same row up again by primary key, so the provider statistics page reads each call log once (about half the query time on 300,000 rows in a local test). (salvaged from [#20225](https://github.com/cheaper-inference/OmniRoute/pull/20225), thanks @serenity-X)
- **fix(usage):** The requests-by-provider-date report now sums archived `total_requests` instead of counting one request per summary row, and it floors raw history at `retention.usageHistory` like the main analytics route, so rows between day 7 and the rollup boundary no longer vanish from the report. (salvaged from [#20225](https://github.com/cheaper-inference/OmniRoute/pull/20225), thanks @serenity-X)
- **fix(db):** The daily and hourly usage summary tables no longer keep two redundant copies of their provider/model/date index; boot drops them and keeps the UNIQUE index that the rollup upsert needs, so each new summary bucket writes two fewer index entries per table. (salvaged from [#20225](https://github.com/cheaper-inference/OmniRoute/pull/20225), thanks @serenity-X)
