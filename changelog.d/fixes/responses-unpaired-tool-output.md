- **fix(responses):** A tool message with no `tool_call_id` is no longer sent to a Responses target as a `function_call_output` with `call_id: ""`; it is dropped like any other unmatched tool output. A `custom_tool_call` with a blank `call_id` is skipped, as a `function_call` already is, instead of being paired with a made-up id and an empty result. Strict tool-history mode still refuses a blank id.
