- **fix(dashboard):** the Combo Control Center's "Configured targets" card now shows the configured model and the pinned account in full. The row used to render the step label as its headline — and for steps created by the combo builder that label is the account name — so the model was never shown, while the account itself was cut to a truncated connection id (`abc1234…`). The model (`provider/model`, the combo name for nested combos, `provider/pattern` for wildcard targets) is now the headline, and the account is resolved from the connection row (name → displayName → email), falling back to the stored step label and finally to the full, untruncated connection id.
