- **fix(chatgpt-web):** the clean-room bridge resolves ChatGPT's Sentinel integrity module through the page's own bundle runtime instead of hand-instantiating its factory against a pinned minified dependency id. chatgpt.com assigns those ids per deployment, so when the uuid helper behind the sentinel payload moved from `TI` to `DD` (and into another chunk), every `chatgpt-web` turn failed with `[502] ChatGPT Web first-party bridge module failed to load: pageerror: Unsupported ChatGPT integrity dependency: DD` while the stored cookie and storage state stayed valid. No id is pinned and no dependency is stubbed now, and resolution stays lazy because a module script's `load` event fires before a pending top-level `await` settles ([#17833](https://github.com/diegosouzapw/OmniRoute/pull/17833))
