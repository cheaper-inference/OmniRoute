- **fix(a2a):** the `smart-routing`, `cost-analysis`, `quota-management` and `health-report` skills called back into OmniRoute with `OMNIROUTE_API_KEY`, a `manage`-scope key, whatever key the A2A caller used. With A2A enabled, `REQUIRE_API_KEY=true` and `OMNIROUTE_API_KEY` set, a restricted inference key could reach models outside its allowlist, skip its budget and quota, and read instance-wide usage and health data. Those calls now carry the caller's own key, so `/v1` and the management routes apply that key's policy. A dashboard-session caller (no API key) still uses `OMNIROUTE_API_KEY`. With `requireLogin` on, a key without `manage` scope now gets an error from `cost-analysis` and partial or empty data from `quota-management` and `health-report`. With `requireLogin` off, `health-report` still drops to the status-only health view for such a key, because the full `/api/monitoring/health` view always requires management auth. The self-loop calls no longer follow redirects. Self-loop calls also refuse to attach any API key when `OMNIROUTE_BASE_URL` is plain http to a non-loopback host, so a mis-set base URL cannot ship the caller's Bearer token in cleartext. (#19119)
