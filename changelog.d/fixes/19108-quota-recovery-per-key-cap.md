- **fix(api):** quota session recovery no longer lets one API key crowd out the others. A key may hold 64 active recovery tickets by default (`OMNIROUTE_QUOTA_RECOVERY_MAX_PER_KEY`); past that, new turns get the original quota error. Each scheduler tick now takes due tickets round-robin across keys instead of oldest-first, and expired or cancelled rows are deleted a day after they expire. Migration `227` rebuilds `idx_quota_recovery_due` with `expires_at` and `api_key_id`, so ranking and expiring due tickets read the index instead of every stored payload.
