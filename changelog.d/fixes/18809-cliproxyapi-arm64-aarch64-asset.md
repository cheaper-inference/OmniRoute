- **fix(backend):** installing or updating the embedded CLIProxyAPI on an ARM64 host (Linux, macOS, Windows) downloads the `aarch64` release asset, which is how CLIProxyAPI names its ARM builds, instead of failing with `No asset for <platform>/arm64`. Releases that still use the older `arm64` name keep working, and a release without an ARM build now lists the asset names it tried ([#18809](https://github.com/cheaper-inference/OmniRoute/issues/18809)) — thanks @nahdd123uosackr for the report
