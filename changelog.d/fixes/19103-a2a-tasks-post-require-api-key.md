- **fix(a2a):** `POST /api/a2a/tasks` (Conductor delegation) only compared the bearer against `OMNIROUTE_API_KEY` and was open when that variable was unset, even with `REQUIRE_API_KEY=true`. It now runs the same check as `GET /api/a2a/tasks` first. With `REQUIRE_API_KEY=true`, anonymous callers and unknown keys get `401` when login is off or before onboarding. Also with `REQUIRE_API_KEY=true`: when `OMNIROUTE_API_KEY` is set, management credentials (dashboard session, `manage`-scope key, write-scope access token) can now create tasks, as they already could list them, and with login off or before onboarding a valid DB key is no longer rejected. With `REQUIRE_API_KEY=true` and `OMNIROUTE_API_KEY` set, `POST` now reads the env key from the same headers as `GET`: `Authorization: Bearer <key>`, `x-api-key` with `anthropic-version` (or a Claude Code or Anthropic user agent), or `x-goog-api-key`. The last two used to get `401` on `POST` and now pass, also with login on. A bare key or a tab after `Bearer` used to pass with login off or before onboarding and now gets `401`. With `REQUIRE_API_KEY` off, a configured `OMNIROUTE_API_KEY` is still required as before.
