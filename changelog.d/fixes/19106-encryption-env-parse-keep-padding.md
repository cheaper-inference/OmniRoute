- **fix(db):** when `STORAGE_ENCRYPTION_KEY` is loaded from a `.env` file (not already in the process environment), the value is now split on the first `=` and parsed like `bin/cli/utils/parseEnvValue.mjs`. The old `split("=", 2)` dropped base64 padding after a second `=`, so the derived key differed from the CLI. Data encrypted under the old reading still decrypts if the `.env` line is left unchanged; only leave the line as-is after upgrading. Details and edge cases are in the PR (#19106)
