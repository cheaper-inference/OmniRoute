- **fix(usage):** A quota window whose previous reset time is still in the future is no longer dated as starting there. That happens when a window restarts early (a reset the account redeems upstream) and, far more often, when an unused rolling window slides its reset time forward with the clock; the recorded window could start up to a week in the future, so provider window costs and API key usage limits dropped the usage made since. The reset event now dates such a window from when it was observed; a scheduled rollover still starts at the previous reset time. (thanks @aldoeliacim)
