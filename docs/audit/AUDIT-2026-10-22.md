## 1. Security audit

### 1.1 Findings

**SEC-01 — Provider-node / jobs mutations rely entirely on middleware route classification** — INFO (latent HIGH)
`src/app/api/provider-nodes/[id]/route.ts:37-59`

```ts
export async function PUT(request: Request, { params }: { params: Promise<{ id: string }> }) {
  let rawBody: unknown;
  ...
    const validation = validateBody(updateProviderNodeSchema, rawBody);
```

No in-handler `requireManagementAuth`. The sibling POST at `src/app/api/provider-nodes/route.ts:117` is identical. Contrast the correct pattern at `src/app/api/providers/[id]/route.ts:110-112`:

```ts
export async function PUT(request: Request, { params }: { params: Promise<{ id: string }> }) {
  const authError = await requireManagementAuth(request);
```

**Why not exploitable today (verified independently):** `/api/provider-nodes` and `/api/jobs` are absent from `src/shared/constants/publicApiRoutes.ts` (grep: no matches). `src/server/authz/classify.ts:111-126` therefore returns `routeClass: "MANAGEMENT"`, and `src/proxy.ts:41-58` gates it.

**Impact if classification drifts:** unauthenticated `baseUrl` rewrite → SSRF pivot + credential exfil. `baseUrl` is only sanitized by `validateProviderNodeBaseUrl` (`:88`), which validates the URL _shape_, not the destination owner.
**Fix:** add the guard at every mutating verb in `/api/provider-nodes/**` and the whole `/api/jobs/**` tree. Single-point-of-failure auth is the defect, not the current behaviour.

**SEC-02 — Telegram webhook `kind` bypasses the outbound URL guard** — LOW
`src/app/api/webhooks/[id]/route.ts:83-92`

```ts
if (rest.url !== undefined && effectiveKind !== "telegram") {
  try {
    parseAndValidateWebhookUrl(rest.url);
```

`kind` is client-settable (`route.ts:30`), so any `url` string can be stored by declaring `kind: "telegram"`. That field then becomes `chat_id` at `src/lib/webhookDispatcher.ts:197-199`.

**Containment:** `buildTelegramUrl` hardcodes the host (`src/lib/webhooks/integrations/telegram.ts:19-26`), and delivery still passes through the DNS-pinned, private-IP-blocking `fetchWebhookUrl`. No SSRF.
**Impact:** a management user can point event delivery at an arbitrary third-party `chat_id`. Privilege-preserving, not privilege-escalating.
**Fix:** validate `chat_id` shape when `kind === "telegram"`; re-run the URL guard when `kind` transitions away.

**SEC-04 — Credentials stored in cleartext outside production** — LOW


## 2. Performance audit

### 2.1 Findings

**PERF-01 — MEDIUM — `token_ledger` has zero indexes** _(independently verified: 0 index migrations, 1 table definition)_
`src/lib/db/migrations/060_create_gamification.sql:55-63`

```sql
CREATE TABLE IF NOT EXISTS token_ledger (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  from_api_key_id TEXT NOT NULL,
  to_api_key_id TEXT NOT NULL,
```

Queries at `src/lib/db/gamification.ts:425`, `:428`, `:436-438` — the last is `WHERE from_api_key_id = ? OR to_api_key_id = ? ORDER BY created_at DESC, id DESC LIMIT ?`.

**Cost model:** append-only table → grows monotonically → **O(rows) per balance read**. `transferTokens` calls `getBalance` _inside_ its write transaction (`:405`), so read cost becomes **write-lock hold time**.
**Fix:** `idx_token_ledger_to(to_api_key_id, created_at DESC)` + `idx_token_ledger_from(from_api_key_id, created_at DESC)`, split the `OR` into `UNION ALL`, assert with `EXPLAIN QUERY PLAN`.

**PERF-02 — MEDIUM — 14 dashboard aggregates `GROUP BY` expressions no index can serve**
`src/lib/db/usageAnalytics.ts:190, 278, 324, 428, 636, 686, 810, 882, 925`

```ts
GROUP BY DATE(timestamp), LOWER(provider), LOWER(model), serviceTier
```

All 11 `usage_history` indexes are on raw columns — SQLite cannot use `idx_uh_provider` for `LOWER(provider)`, nor `idx_uh_timestamp` for `DATE(timestamp)`. Measured: **0 expression indexes** across all 212 migrations.
**Cost:** full scan + temp B-tree sort per panel per page load. `call_logs` already has the covering-index pattern (`200_provider_health_matrix_covering_index.sql`) — the team knows it; `usage_history` is the gap.
**Fix:** stored generated columns + index, or pre-aggregate from the existing `daily_usage_summary` rollups.

**PERF-03 — MEDIUM — Compression worker queue is unbounded and retains full bodies**
`open-sse/services/compression/compressionWorkerPool.ts:151`, `:210`

```ts
private readonly queue: PendingJob[] = [];
...
this.queue.push({ id: this.nextId++, body, mode, options, originalBody: body, resolve, reject, onEngineStep });
```

Pool is `size=2` with `timeoutMs=120_000` (`:168-177`). Under load, requests queue holding **two references** to the full body each (`body` + `originalBody`). Memory grows with `queue depth × body size`, unbounded.
**Fix:** hard cap the queue with a fast reject/fallback-to-sync path, and drop `originalBody` (retain one reference).

**PERF-04 — LOW — RTK recompiles regexes per compression call**
`open-sse/services/compression/engines/rtk/index.ts:345-351`

```ts
const filterPriorityPatterns: RegExp[] = matchedFilterPatterns.flatMap((pattern) => {
  try {
    return [new RegExp(pattern, "i")];
```

Same static patterns already compiled by `lineFilter.ts:29 cachedRegExp` in the same request. Third compilation site.
**Scope limit:** default path for plain text goes to the worker; this in-process path handles multimodal/vision bodies and `ultra`+`slm`.
**Fix:** export and reuse `cachedRegExp`.

**PERF-05 — LOW — LKGP cache is populated only from tests; production has no producer**
`src/lib/db/readCache.ts:197` (`getCachedLKGP`), `:208` (`setCachedLKGP`), `:226` (`invalidateCachedLKGP`).

References, repo-wide (`git grep -n 'getCachedLKGP\|setCachedLKGP'`): **zero in `src/` or `open-sse/` outside the declarations**, and 6 references in three test files — `tests/unit/db-read-cache.test.ts:195,202,204,206`, `tests/unit/combo-delete-lkgp-cleanup-12326.test.ts:87,95`, `tests/unit/delete-provider-connection-invalidates-lkgp-8887.test.ts:87,95`. `setCachedLKGP` is referenced from **one** production-shaped call site, inside a test.

`invalidateCachedLKGP` is fully wired and correct: 5 reachable call sites (`settings/lkgp.ts:94-95,111-113,165-167`, `repositories/sqliteComboRepository.ts:383-385`), key format `lkgp:${combo}:${model}` constructed at `readCache.ts:201`/`:216` and re-prefixed at `:227`, storage key `${combo}:${model}` at `settings/lkgp.ts:42`. `tests/unit/combo-delete-lkgp-cleanup-12326.test.ts` passes **6/6**, so invalidation is exercised, not assumed.

**The finding:** the cache is a coherent, tested, correctly-keyed subsystem whose _write path in production does not exist_. Routing reads call `getLKGP` directly (`open-sse/services/combo/applyStrategyOrdering.ts:69-70`, `resolveAutoStrategy.ts:334`, `staleLkgpClear.ts:37`), so the only entries the cache ever serves come from `setCachedLKGP` — which only tests call. Cost: one SQLite SELECT per combo-routed request against a cache that production never populates.

**Fix:** adopt or retire. Adopt = call `getCachedLKGP` at the three routing reads _and_ `setCachedLKGP` on the success path; retire = delete all three helpers and their 5 invalidation call sites, plus the three tests that exist solely to exercise them. A half-adoption is worse than either: the getter alone returns `null` forever.

**PERF-06 — LOW — O(C·M) catalog `JSON.stringify` per request in pool ordering**
`open-sse/services/providerConnectionPool.ts`. C = usable connections (up to 10k+ per `readCache.ts:138`), M = model catalog. **Fix:** hash on mutation, compare hashes.

**PERF-07 — LOW — cache keys are order-sensitive**
`src/lib/db/readCache.ts:125`

```ts
const cacheKey = filter && Object.keys(filter).length > 0 ? JSON.stringify(filter) : "all";
```

Same logical filter, different key order → cache miss. Canonicalize before stringify.

**PERF-08 — LOW — CLS on generated-image grids**
`MediaPageClient.tsx:392-395`, `ImageResultsInline.tsx:82-85` — `<img className="w-full" />`, no height/aspect-ratio. **Fix:** `aspect-square`/`aspect-video` on the wrapper. Do not convert to `next/image` (data-URI sources).

**PERF-09 — INFO — 288 provider modules evaluated eagerly** (304 files, 0.46 MiB)
`open-sse/config/providers/index.ts:2-291`. Fixed per process; no growth with request rate. A lazy `Proxy` **alone will not work** — `src/lib/guardrails/visionBridgeHelpers.ts:27-31` does `Object.entries(REGISTRY)` at import, forcing every getter. **Fix:** build-time metadata JSON for the two metadata-only consumers.

### 4.4 New finding — QUAL-07 — LOW — test-only exports are invisible to the dead-code gate

`scripts/check/check-dead-code.mjs --json` does report symbols: 187 entries carrying **256 unused exports**, **87 unused types**, and **24 dead files** — 256+87+24 = **367**, exactly the gate's `deadTotal` and the number ratcheted against the 377 baseline. Each symbol is shaped `{name, line, col, pos}`, e.g. `AUTH_METHODS` at `src/shared/constants/providers.ts:442`.

`src/lib/db/readCache.ts` appears **nowhere** in that output, and `npx knip --include exports --trace-export getCachedLKGP` states why:

```
src/lib/db/readCache.ts:getCachedLKGP
├── tests/unit/combo-delete-lkgp-cleanup-12326.test.ts:import[getCachedLKGP] ⎆ ✓
├── tests/unit/db-read-cache.test.ts:import[getCachedLKGP] ⎆ ✓
└── tests/unit/delete-provider-connection-invalidates-lkgp-8887.test.ts:import[getCachedLKGP] ⎆ ✓
```

**Three test files count as consumers.** An export reachable _only_ from `tests/**` is reported by neither mechanism: it is not "unused" (something imports it), and it is not "used" in any sense that affects a running build. `knip.json:60` sets `"ignoreExportsUsedInFile": true` and the workspace `ignore` lists `tests/**`, so the test edge that rescues the symbol from the report is itself excluded from remediation.

**Consequence:** "0 unused exports in production code" is not what the 256 figure means. Any export whose sole importer is a test passes the gate while shipping dead weight in `dist/`. PERF-05 is the concrete instance — a cached-read subsystem kept alive for three test files.

**Also worth knowing before planning the burn-down:** the 256 are runtime exports, the 87 are types (42 files, e.g. `QuotaStore`/`EnforceDecision` at `src/lib/quota/QuotaStore.ts:15-16`). `parseKnipMetrics` sums `exports` + `nsExports` + `types` + `nsTypes` into a single `deadExports` and ratchets one `deadTotal` (`check-dead-code.mjs:83-92`) — there is **no** separate types-vs-exports enforcement. So all 367 symbols compete against one ceiling of 377, and deleting the 87 types is worth exactly as much as deleting 87 exports.

**The obvious fix does not work — measured.** `npx knip --production --include exports --reporter json` returns `{"issues":[]}`: **0 entries, 0 symbols, exit 0.** The root package declares neither `main` nor `exports` (`package.json` — no `"main"`, no `"exports"` field; `open-sse/package.json` is `private: true` with no entry fields either), so production mode finds no production entry points and analyzes **nothing**. `--production` and `--strict` are inert in this repo and would silently report a clean bill of health. A gate built on them here is worse than no gate — it is a false green.

Test-only export detection therefore needs an explicit entry-point set (or a knip workspace override declaring `main`) before the `--production` pass means anything.

## 5. Cross-cutting themes

1. **Silent failure is the dominant defect class.** 140 empty catches (QUAL-04), compression failing open to disabled (`compressionSettings.ts:46`), decrypt falling back to plaintext (SEC-04), `provider-stats` returning 200 on DB error. The same shape appears in all four audits.

3. **The velocity policy is doing what it was designed to do.** Every number above was _known_ and _baselined_. This is managed debt, not neglect — but any "CI is green" claim must be qualified until 4.0.0 closes the phase.
4. **The request path is where the craft is.** Zero-copy SSE, bounded caches, three-layer fallback, 291 providers, 3.3% duplication, 1.2:1 tests. The debt is in persistence (indexes), structure (cycles), and types.
