# Free-Tier Catalog Recount

Run the recount after each wave that changes the free-tier catalog. It compares fact snapshots and
flags potentially stale claims on hand-written surfaces. Review each flagged line against the wave
and its source before editing it. Historical notes can legitimately quote earlier counts.

```sh
npm run release:free-tier-recount -- --before=<previous ref>
npm run release:free-tier-recount -- --before=<previous ref> --json
```

Replace `<previous ref>` with the Git ref for the pre-wave snapshot. By default the report compares
that ref with the working snapshot. Pass `--after=<git-ref>` to compare with another committed
snapshot. The report always scans the working surfaces and checks legacy spellings even when the
snapshots agree. It lists external checks to run separately. Findings leave the exit status at zero.

## Recount order

1. Wait for the wave to land or start the recount branch from the finished wave branch.
2. Use an isolated worktree on `chore/derived-free-tier-recount-<YYYYMMDD>`.
3. Run `node scripts/release/refresh-derived.mjs --profile=nightly --only=provider-reference,facts,numbers,readme-diagrams,verify-generated`.
4. Run the recount report and correct the stale claims it flags.
5. Re-check the price sentence at its source and move its check date.
6. Run the docs-counts gate in release mode and the free-tier tests in the checklist.
7. Open the recount PR.
8. Check the translation bot PR.
9. After the release, check the site and GitHub metadata listed in the report.
