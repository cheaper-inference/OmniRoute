`devin-cli-agentic` מאפשר לזמן הריצה האמיתי של Claude Code להשתמש בנקודת הקצה המקומית של OmniRoute עבור
Anthropic Messages, בעוד שה-CLI הרשמי של Devin מספק תגובות מודל דרך ACP stdio. הוא
אינו משנה את ספקי Anthropic,‏ Claude OAuth,‏ Claude Web או `devin-cli` הקיימים.

עבור קריאות לכלים בבעלות הלקוח, יש לנתב דרך `devin-cli-agentic` (כינוי `dva`),
הספק התומך בכלים בפורמט Claude. מבצע ה-ACP הישן `devin-cli` (`dv`) תומך
בטקסט בלבד: הוא מפעיל את המסכם ללא כלים של Devin ואינו יכול להחזיר קריאות לכלים. המטא-נתונים
של המודל שלו מסומנים בהתאם, כך שניתוב משולב הדורש כלים יימנע ממנו.

> **מצב נוכחי: Claude Code מקובע לגרסה `2.1.258`; האימות הלא מקוון והחי תועד לאחרונה
> בגרסה `2.1.220`.** הקיבוע לגרסה `2.1.220` השלים שלושה תרחישים מבודדים באמצעות Devin CLI
> `3000.2.17` והמודל `swe-1-7-lightning`; ההרצה החיה הסופית הוכיחה תורות `Read`,
> `Edit` ו-`Bash` בבעלות הלקוח, תוצאות מוצלחות של `npm test`, גילוי פקודות ומיומנויות
> בפרויקט, ניתוב דרך Devin בלבד ואפס תעבורה יוצאת ל-Claude. לאחר מכן הקיבוע הועלה ל-`2.1.258`
> (דור ה-CLI שאותו זהות Claude של OmniRoute מתחזה אליו, והגרסה הראשונה שמספקת
> באופן מובנה את שכבת Fable 5.1). בקיבוע החדש אומתו שכבת ההתקנה ו-`claude --version`
> בתמונת הבסיס המקובעת, וחבילת בדיקות היחידה של הגשר, `compose config` והוכחת הבידוד
> הסטטית עוברות — אך תרחיש ההדמיה הלא מקוון וחבילת שלושת התרחישים החיה
> טרם הורצו מחדש. יש להריץ אותם מחדש (ראו "עדכון כלים מקובעים") לפני הסתמכות על
> הגשר עם קיבוע זה.

## ארכיטקטורה

```text
Claude Code 2.1.258 (קונטיינר Linux מבודד שאינו root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (פורמט Claude, ספק ללא אימות)
  -> devin acp --agent-type summarizer (ACP stdio רשמי, ללא כלי Devin)
  -> חשבון Devin בכרך devin-auth הייעודי
```

סוכן ה-ACP המוגדר כברירת מחדל ב-CLI הרשמי יכול להפעיל כלים משלו, ולכן גשר זה אינו משתמש
בו. הוא מפעיל את סוכן ה-ACP הקבוע `summarizer`, שבמצב ה-CLI הרשמי שלו אין כלים, וממסגר
את בקשת Anthropic שעברה סריאליזציה כעקבת ביצוע. כאשר נדרשת פעולה נוספת בבעלות Claude,
התגובה חייבת להכיל מעטפת אחת בדיוק של כלי לקוח. כל `tool_call` או `tool_call_update`
של ACP נדחים לפני שניתן לדווח על תגובה כמוצלחת.

הסריאלייזר ב-`open-sse/executors/devin-agentic/serializer.ts` משמר את `system`,
`text`,‏ `tool_use`,‏ `tool_result`,‏ `thinking`,‏ `redacted_thinking`,‏ `tool_choice` ואת
הכלים שסופקו בידי Claude Code. תמונות ובלוקים לא מוכרים גורמים לכשל מפורש. תוצאות כלים
גדולות משתמשות בסמן קיטוע גלוי.

המפרש מקבל מעטפת עצמאית אחת מסוג `<tool>{...}</tool>` בכל תור של המודל. הוא בודק
את השם מול רשימת הכלים שבבקשה, מאמת ארגומנטים מול JSON Schema של אותו כלי, דוחה
שילוב של טקסט סיפורי ופעולות, ומתיר ניסיון תיקון מוגבל אחד. לאחר מכן Claude Code
מפעיל מקומית את `tool_use` של Anthropic שנוצר ושולח את `tool_result` בחזרה דרך
OmniRoute.

## ניתוב אוטומטי

הספק כשיר להיכלל במאגרי המועמדים `auto/*` של OmniRoute כאשר הוא אינו חסום.
כשירות כמועמד אינה מבטיחה בחירה: אסטרטגיית הניתוב של השילוב (לדוגמה,
האחרון שנודע כתקין) עשויה להעדיף ספק אחר. השתמשו ב-`dva/<model>` או בשילוב שמעדיף
את Devin כאשר נדרש שכל בקשה תעבור דרך Devin.

## בידוד ומודל איומים

התקנת Claude, החשבון והתצורה שבמארח אינם נכללים בתחום ונחשבים
אסורים. שירותי Compose:

- פועלים עם UID/GID‏ `10001:10001`, מערכת קבצים בסיסית לקריאה בלבד, הרשאות שהוסרו ו-
  `no-new-privileges`;
- משתמשים ב-`/home/bridge` פרטי, אמצעי אחסון ייעודי לתצורת Claude, נתוני OmniRoute מבודדים
  ואמצעי אחסון נפרד מסוג `devin-auth`;
- מעגנים רק סביבות עבודה וראיות זמניות של `.sandbox`;
- אינם מעגנים את תיקיית הבית של המארח, Keychain, אישורי SSH, אישורי ענן או שקע Docker;
- בונים סביבות מפורשות ומסירים משתני API/OAuth/ניתוב של Anthropic;
- מפנים את ההסקה של Claude Code רק אל `http://omniroute:20128` באמצעות מפתח מקומי בלבד.

הפרופיל הלא מקוון משתמש ברשת פנימית. בפרופיל הפעיל, OmniRoute ניגש לנקודות הקצה
הרשמיות של Devin רק דרך `network-guard`; יעדים שאינם קשורים נחסמים.
ל-Claude Code יש מגן נפרד החוסם את כל התעבורה היוצאת, והוא יכול לגשת רק לשירות OmniRoute
המקומי דרך `NO_PROXY`. קובצי הביקורת של המגנים מעוגנים רק בתהליך המגן המתאים. הסקריפטים
מאמתים את הבעלות על הקבצים, ההרשאות, מספר הקישורים וכל החלטה לפני ייצוא
ראיות נטולות אסימונים.

הריצו את הוכחת הבידוד באופן עצמאי:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

היא מאמתת את הטופולוגיה, העיגונים בעלי השם, הגדרות משתמש שאינו root/קריאה בלבד, ניתוב מקומי
מפורש, היעדר משתני סביבה רגישים, היעדר שקע Docker, חסימת הגישה אל
`api.anthropic.com` ו-`claude.ai`, בחירת ספקי Devin בלבד וכשל מפורש כאשר
הצד האחורי של ACP אינו זמין.

## הגדרה ראשונית ושימוש רגיל

בנו את התמונה המקובעת:

```bash
./scripts/devin-bridge/build
```

בצעו אימות רק עבור אמצעי האחסון המבודד של Devin:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

פקודת הכניסה משתמשת בתהליך האסימון הידני הרשמי המיועד לסביבות מרוחקות/סביבות קונטיינרים.
הערך מוזן ישירות אל בקשת הקלט של ה-CLI; הוא אינו מועבר כארגומנט לתהליך, נכתב ל-Git
או מועתק מהמארח.

הפעילו את סביבת זמן הריצה המבודדת של Claude Code:

```bash
./scripts/devin-bridge/launch
```

`launch` בודק מחדש את הבידוד, האימות של Devin וגילוי המודלים לפני הפעלת Claude Code
בתוך קונטיינר. הוא לעולם אינו מפעיל את קובץ ההרצה של Claude שבמארח. אפשר להגדיר כינויי
מודלים ב-`.env.devin-bridge`; כל ערך מוגדר חייב לשמור על הקידומת
`devin-cli-agentic/`.

## פקודות אימות

הנתיב הלא מקוון הניתן לשחזור אינו דורש חשבון Devin ואין לו גישה לאינטרנט בזמן הריצה:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

הנתיב הפעיל המאומת, המחייב הסכמה מפורשת, הוא:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

מריץ הבדיקות הפעילות ממתין בין תרחישים כדי להימנע מפתיחת הפעלות ACP ברצף מהיר,
ומאמת אירועי זרימה מובְנים של Claude במקום להסתמך על טענות טקסטואליות. שלושת
התרחישים שלו מוכיחים:

1. קריאות ישירות מהפרויקט וניתוח פגמים;
2. פעולת `Edit` אמיתית, הרצת `npm test` באמצעות `Bash` שבבעלות הלקוח ותוצאת מסוף;
3. גילוי `/bridge-check` יחד עם `bridge-proof`, קריאות מהפרויקט, הרצה מוצלחת נוספת
   של `npm test` שבבעלות הלקוח והשלמה ללא עבודה ממתינה.

השער הסופי בודק גם את ביקורת הרשת של Devin ודורש שביקורת התעבורה היוצאת של Claude
תישאר ריקה.

## עדכון כלים מקובעים

התמונה מקבעת את Node, Claude Code ו-Devin CLI בקובץ
`docker/devin-bridge/Dockerfile`. כדי לעדכן:

1. שנו את הגרסאות המפורשות;
2. החליפו את שני סכומי הביקורת של ארכיון Devin, הייחודיים לכל ארכיטקטורה, בערכים של
   הארטיפקט הרשמי;
3. בנו מחדש והריצו כל פקודת אימות לא מקוונת;
4. ודאו את הגרסאות בתוך התמונה;
5. הריצו מחדש את חבילת הבדיקות החיה והמאומתת, הכוללת שלושה תרחישים.

אין להתקין אף אחד מכלי ה-CLI באופן גלובלי במארח, ואין להחליף את אימות סכום הביקורת
בהורדה שאינה מאומתת.

## אבחון וניקוי

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  מציג ניתוב מקומי ושגיאות מסוננות של מבצע הפקודות.
- `.sandbox/evidence/mock-acp.jsonl` מתעד פעולות ACP מדומות ודטרמיניסטיות.
- `.sandbox/evidence/claude-stream.jsonl` מתעד את ההרצה הלא מקוונת האמיתית של Claude Code.
- `.sandbox/evidence/live-*.jsonl` מתעד את שלושת הזרמים החיים שאומתו.
- `.sandbox/evidence/egress.jsonl` ו-`.sandbox/evidence/claude-egress.jsonl` הם עותקים מאומתים
  וללא אסימונים של ביקורות מנגנון ההגנה.

עצרו קונטיינרים ורשתות בבעלות המערכת, תוך שימור אמצעי האחסון של ההתחברות והתצורה:

```bash
./scripts/devin-bridge/clean
```

הסירו את כל הסביבה שבבעלות הגשר, כולל אמצעי אחסון בעלי שם:

```bash
./scripts/devin-bridge/clean --all
```

## מגבלות

- הגשר מסתמך על התפקיד הקבוע `summarizer`, שאינו כולל כלים, משום ש-Devin CLI `3000.2.17`
  אינו חושף סוכן ACP ניטרלי ללא כלים. המתאם מפצה על תגובות ביניים המעוצבות כסיכום,
  אך ניסיון תיקון מוגבל יחיד עדיין עלול להיכשל באופן מפורש.
- קריאות ACP חיות עשויות להחזיר תגובות `502`/`504` זמניות. רתמת הבדיקה מרווחת בין התרחישים;
  כשל מתמשך נותר במצב סגור בעת כשל ולעולם אינו בוחר ספק אחר.
- הקשר ACP נבנה מחדש מכל בקשת Anthropic; אין שיוך לתהליך או להפעלה.
- נתמכת קריאת כלי אחת לכל תגובת מודל; קריאות מקביליות נדחות.
- אין תמיכה מפורשת בתמונות. יכולות ראייה, פלט חשיבה, בקרות מאמץ וחלון הקשר של 1M
  אינם מפורסמים כנתמכים.
- SSE משתמש באירועי מחזור חיים תקינים של Anthropic, אך נפלט לאחר איסוף סבב ה-ACP המוגבל;
  מקטעי ACP אינם מועברים באופן מצטבר.
