מסמך זה מתאר את תהליך הפריסה בפועל של OmniRoute ב-Fly.io, ומכסה שני תרחישים:

- פריסת הפרויקט הנוכחי ב-Fly.io בפעם הראשונה
- פרסום עדכוני קוד נוספים
- פרויקטים חדשים המשתמשים באותו תהליך פריסה

מדריך זה מבוסס על תצורה פעילה ומאומתת של הפרויקט הנוכחי. שם היישום הוא `omniroute`.

---

## 1. יעדי הפריסה

- פלטפורמה: Fly.io
- שיטת פריסה: פרסום ישיר באמצעות `flyctl` מקומי
- סביבת הרצה: שימוש בקבצים הקיימים `Dockerfile` ו-`fly.toml` שבמאגר
- שמירת נתונים: Fly Volume המעוגן אל `/data`
- כתובת גישה: `https://omniroute.fly.dev/`

---

## 2. תצורת המפתח של הפרויקט הנוכחי

אושר כי הקובץ `fly.toml` במאגר הנוכחי מכיל את הפריטים המרכזיים הבאים:

```toml
app = 'omniroute'
primary_region = 'sin'

[[mounts]]
  source = 'data'
  destination = '/data'

[processes]
  app = 'node run-standalone.mjs'

[http_service]
  internal_port = 20128

[env]
  TZ = "Asia/Shanghai"
  HOST = "0.0.0.0"
  HOSTNAME = "0.0.0.0"
  BIND = "0.0.0.0"
```

הערות:

- `app = 'omniroute'` קובע לאיזה יישום Fly מיועדת הפריסה
- `destination = '/data'` קובע את ספריית העיגון של אמצעי האחסון המתמיד
- בפרויקט זה חובה להגדיר `DATA_DIR=/data`, אחרת מסד הנתונים והמפתחות ייכתבו לספרייה הזמנית של הקונטיינר

## 3. דרישות מוקדמות

### 3.1 התקנת Fly CLI

Windows PowerShell:

```powershell
pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"
```

אם סקריפט ההתקנה נכשל בסביבה שלכם, ניתן גם להוריד ידנית את הקובץ הבינארי `flyctl` ולהוסיף אותו אל `PATH`.

### 3.2 התחברות לחשבון Fly שלכם

```powershell
flyctl auth login
```

### 3.3 אימות מצב ההתחברות

```powershell
flyctl auth whoami
flyctl version
```

## 4. פריסה ראשונית של הפרויקט הנוכחי

### 4.1 שכפול הקוד ומעבר לספרייה

```powershell
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
```

### 4.2 אימות שם היישום

פתחו את `fly.toml` וודאו שמופיעה בו השורה הבאה:

```toml
app = 'omniroute'
```

אם אתם פורסים ליישום חדש משלכם, תוכלו לשנות אותו לשם ייחודי גלובלית, לדוגמה:

```toml
app = 'omniroute-yourname'
```

הערה:

- ודאו שהיישום שאתם רואים במסוף תואם לערך `app` שב-`fly.toml`
- אם השתמשתם בעבר בשם אחר, כגון `oroute`, אל תבלבלו בינו לבין `omniroute`

### 4.3 יצירת היישום

אם היישום עדיין אינו קיים:

```powershell
flyctl apps create omniroute
```

אם שיניתם את שם היישום, החליפו את `omniroute` בשם שבחרתם.

### 4.4 פריסה ראשונה

```powershell
flyctl deploy
```

## 5. פרמטרים נדרשים

פרויקט זה ממליץ להגדיר לפחות את הפרמטרים הבאים ב-Fly.io.

### 5.1 פרמטרים מאומתים

הפרמטרים האלה שימשו בפריסות בפועל ביישום `omniroute` הנוכחי:

- `API_KEY_SECRET`
- `DATA_DIR`
- `JWT_SECRET`
- `MACHINE_ID_SALT`
- `NEXT_PUBLIC_BASE_URL`
- `OMNIROUTE_WS_BRIDGE_SECRET` (נדרש בייצור — המשמש לאימות גשר WebSocket )
- `STORAGE_ENCRYPTION_KEY`

### 5.2 על `INITIAL_PASSWORD`

הפרויקט הנוכחי לא מגדיר `INITIAL_PASSWORD` מכיוון שהפריסה הזו לא מחייבת זאת.

אם זה לא מוגדר:

- אתה יוצר את סיסמת לוח המחוונים באשף ההצטרפות בביקור הראשון. השלם את שלב הסיסמה: דילוג עליו מכבה את הכניסה ללוח המחוונים, מה שמשאיר את לוח המחוונים פתוח לכל מי שיכול להגיע לאפליקציה URL
- ה-proxy של Fly מגיע לאפליקציה מכתובת שאינה חוזרת, אז לאחר שליחת הסיסמה האשף מבקש אסימון Bootstrap חד פעמי, אותו האפליקציה מדפיסה ללוג שלה באותו רגע: `flyctl logs --no-tail -a omniroute | Select-String BOOTSTRAP`. אם השורה הזו נגללה מהיומן, הפעל מחדש את האפליקציה ושלח שוב את האשף כדי להדפיס אסימון חדש

כדי להגדיר את הסיסמה ללא השגחה במקום זאת, הוסף אותה לפני הביקור הראשון בלוח המחוונים (לאחר שמירת הסיסמה, מתעלמים `INITIAL_PASSWORD` ):

- `INITIAL_PASSWORD`

## 6. פרמטרים מומלצים

### 6.1 הגדרת סודות

המשתנים הבאים מומלצים עבור Fly Secrets:

| משתנה                        | המלצה             | תיאור                                          |
| ---------------------------- | ----------------- | ---------------------------------------------- |
| `API_KEY_SECRET`             | חובה              | משמש ליצירה ולאימות של מפתחות API              |
| `JWT_SECRET`                 | חובה              | משמש להפעלות התחברות ולחתימה על JWT            |
| `OMNIROUTE_WS_BRIDGE_SECRET` | חובה בסביבת ייצור | סוד אימות עבור גשר WebSocket                   |
| `STORAGE_ENCRYPTION_KEY`     | מומלץ מאוד        | מצפין מידע רגיש על חיבורים במצב מנוחה          |
| `MACHINE_ID_SALT`            | מומלץ             | יוצר מזהה יציב למכונה                          |
| `INITIAL_PASSWORD`           | אופציונלי         | מגדיר את סיסמת צד השרת הראשונית בפריסה הראשונה |
| פרטי גישה פרטיים ל-OAuth/API | לפי הצורך         | הגדרת אימות עבור פלטפורמה חיצונית              |

### 6.2 ערכים מומלצים לפרויקט הנוכחי

| משתנה                  | ערך מומלץ                   |
| ---------------------- | --------------------------- |
| `DATA_DIR`             | `/data`                     |
| `NEXT_PUBLIC_BASE_URL` | `https://omniroute.fly.dev` |

הערות:

- `DATA_DIR=/data` הוא קריטי וחייב להתאים לנקודת העגינה של Fly Volume
- `NEXT_PUBLIC_BASE_URL` משמש את המתזמן, קריאות חוזרות מצד ממשק המשתמש ותרחישים דומים

### 6.3 הגדרת כתובת URL לקריאה חוזרת של OAuth

אם עליכם להפעיל ספקים המבוססים על OAuth (לדוגמה Antigravity, Gemini, Cursor) בפריסת Fly.io, ודאו את שתי הנקודות הבאות:

1. **הגדירו את `NEXT_PUBLIC_BASE_URL` לדומיין ה-HTTPS הציבורי שלכם**

   ```powershell
   flyctl secrets set NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev -a omniroute
   ```

   אם אתם משתמשים בדומיין מותאם אישית, החליפו אותו בדומיין המתאים (לדוגמה `https://omniroute.yourdomain.com`).

2. **הגדירו את כתובת ה-URL לקריאה חוזרת במסוף הניהול של הספק**

   כל ספקי OAuth חולקים נתיב יחיד לקריאה חוזרת, `/callback` — אין נתיב קריאה חוזרת נפרד לכל ספק:

   ```text
   <NEXT_PUBLIC_BASE_URL>/callback
   ```

   לדוגמה, ללא תלות בשאלה אם מדובר ב-Gemini, Antigravity, Cursor או GitLab Duo:
   - `https://omniroute.fly.dev/callback`

   אם `NEXT_PUBLIC_BASE_URL` אינו תואם לכתובת ה-URL לקריאה חוזרת שנרשמה אצל הספק, תהליך OAuth ייכשל בשלב ההפניה מחדש בדפדפן.

## 7. הגדרת סודות בפקודה אחת

הפקודות הבאות יוצרות ערכים אקראיים מאובטחים וכותבות את כל הפרמטרים הנדרשים לפרויקט הנוכחי אל Fly Secrets בשלב אחד.

הערות:

- לא כולל את `INITIAL_PASSWORD`
- מיועד לפרויקט הנוכחי `omniroute`

```powershell
$apiKeySecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$jwtSecret = [Convert]::ToHexString((1..64 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$machineIdSalt = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$storageKey = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$wsBridgeSecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()

flyctl secrets set `
  API_KEY_SECRET=$apiKeySecret `
  JWT_SECRET=$jwtSecret `
  MACHINE_ID_SALT=$machineIdSalt `
  STORAGE_ENCRYPTION_KEY=$storageKey `
  OMNIROUTE_WS_BRIDGE_SECRET=$wsBridgeSecret `
  DATA_DIR=/data `
  NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev `
  -a omniroute
```

ב-Linux / macOS, ניתן להשתמש גם ב-`openssl rand -hex 32`:

```bash
flyctl secrets set OMNIROUTE_WS_BRIDGE_SECRET=$(openssl rand -hex 32) -a omniroute
```

הערות:

- `OMNIROUTE_WS_BRIDGE_SECRET` נדרש בסביבת ייצור; אם הוא חסר, לחיצת היד של גשר WebSocket תיכשל

אם ברצונכם להגדיר גם סיסמה ראשונית:

```powershell
flyctl secrets set INITIAL_PASSWORD=your-strong-password -a omniroute
```

## 9. עדכונים והפצות עוקבות

לאחר עדכוני קוד, תהליך השחרור פשוט:

```powershell
git pull
flyctl deploy
```

אם אתה רק צריך לעדכן פרמטרים מבלי לשנות קוד:

```powershell
flyctl secrets set KEY=value -a omniroute
```

Fly יבצע אוטומטית עדכון מתגלגל של מכונות.

### 9.1 מעקב אחר עדכוני מאגר במעלה הזרם תוך שמירה על `fly.toml` של המזלג שלך

אם המאגר הנוכחי הוא מזלג ואתה רוצה לסנכרן עדכונים מה- `https://github.com/cheaper-inference/OmniRoute` במעלה הזרם, עקוב אחר זרימת העבודה שלהלן.

ראשית, אמת את השלטים שלך:

```powershell
git remote -v
```

אתה צריך לראות לפחות:

- `origin` מצביע על המזלג שלך
- `upstream` מצביע על המאגר המקורי

אם `upstream` לא מוגדר, הוסף אותו:

```powershell
git remote add upstream https://github.com/cheaper-inference/OmniRoute.git
```

לפני הסנכרון עם ה-Upstream, אחזר את ההתחייבויות והתגים העדכניים ביותר:

```powershell
git fetch upstream --tags
```

בדוק את הגרסה הנוכחית ואת התגים במעלה הזרם:

```powershell
git describe --tags --always
git show --no-patch --oneline v3.4.7
```

> הערה: גרסת הפרויקט הנוכחית היא `v3.8.0`. הפניות של `v3.4.7` להלן נשמרות כדוגמאות היסטוריות בלבד. עבור מהדורות בפועל, השתמש `:latest` או בתג הגרסה הנוכחית (למשל `:v3.8.0`).

אם אתה רוצה למזג את `main` העדכני ביותר במעלה הזרם תוך שמירה על `fly.toml` של המזלג שלך בכוח, עקוב אחר זרימת העבודה הזו:

```powershell
git merge upstream/main
git checkout HEAD~1 -- fly.toml
git add -- fly.toml
git commit -m "chore(deploy): keep fork fly.toml"
git push origin main
```

הערות:

- `git merge upstream/main` מסנכרן את הקוד האחרון מהמאגר המקורי
- `git checkout HEAD~1 -- fly.toml` משחזר `fly.toml` של המזלג שלך מלפני המיזוג
- אם במעלה הזרם לא שינה `fly.toml`, שלב זה לא יציג שום הבדלים
- אם במעלה הזרם אכן שינה `fly.toml`, שלב זה מבטיח ששם אפליקציית Fly, הרכבת נפח, אזור ותצורת פריסה ספציפית אחרת למזלג לא יוחלפו

אם ברצונך להתיישר עם תג שחרור ספציפי (למשל `v3.4.7`), תחילה ודא שהתג כבר כלול ב- `upstream/main`:

```powershell
git merge-base --is-ancestor v3.4.7 upstream/main
```

החזרה מוצלחת פירושה ש- `upstream/main` כבר מכיל את הגרסה הזו; אתה יכול פשוט למזג `upstream/main`.

### 9.2 רצף שחרור סטנדרטי לאחר סנכרון במעלה הזרם

לאחר סנכרון עם המאגר המקורי, בצע את סדר השחרור המומלץ הבא:

1. `git fetch upstream --tags`
2. `git merge upstream/main`
3. שחזר את `fly.toml` של המזלג
4. `git push origin main`
5. `flyctl deploy`
6. `flyctl status -a omniroute`
7. `flyctl logs --no-tail -a omniroute`

זהו זרימת העבודה בפועל המשמשת בעת שדרוג הפרויקט הנוכחי ל- `v3.4.7` (הדוגמה מתייחסת לגרסה היסטורית; הגרסה הנוכחית בפועל היא `v3.8.0`).

## 11. סימנים להצלחה

לאחר פריסה מוצלחת, היומנים אמורים להציג תוכן דומה לזה:

```text
[bootstrap] Secrets persisted to: /data/server.env
[DB] SQLite database ready: /data/storage.sqlite
```

שתי הנקודות הבאות חיוניות:

- `/data/server.env` מאשר שסודות זמן הריצה נכתבים לאחסון המתמיד
- `/data/storage.sqlite` מאשר שמסד הנתונים נכתב לאחסון המתמיד

אם מופיע במקום זאת `/app/data/...`, התצורה של `DATA_DIR` שגויה ויש לתקן אותה מיד.

## 12. בעיות נפוצות

### 12.1 עמוד `Secrets` ריק

בדרך כלל יש שתי סיבות:

- עדיין לא הפעלת `flyctl secrets set`
- אתה צופה באפליקציה אחרת (למשל `oroute` במקום `omniroute`)

### 12.2 `flyctl deploy` דוחות `app not found`

תחילה צור את האפליקציה:

```powershell
flyctl apps create omniroute
```

### 12.3 ניתוח `fly.toml` נכשל

בדוק את הדברים הבאים:

- האם יש דמויות משובשות בתגובות
- האם TOML זקה והזחה נכונים

### 12.4 הנתונים אינם נמשכים

אמת את שני הדברים הבאים:

- `fly.toml` מכיל `destination = '/data'`
- `DATA_DIR` מוגדר ל- `/data`

### 12.5 האם זה יכול לרוץ ללא `INITIAL_PASSWORD`?

כֵּן. עם `INITIAL_PASSWORD` unset, אתה יוצר את סיסמת לוח המחוונים באשף ההצטרפות בביקור הראשון (סעיף 5.2 מכסה את אסימון האתחול החד-פעמי ואת שלב הסיסמה).

## 13. שימוש חוזר עבור פרויקטים חדשים

אם אתם פורסים פרויקט חדש בהתאם למסמך זה, עליכם לשנות רק את הפריטים הבאים:

1. שנו את הערך `app` בקובץ `fly.toml`
2. שנו את `NEXT_PUBLIC_BASE_URL`
3. השאירו את `DATA_DIR=/data`
4. צרו מחדש את `API_KEY_SECRET`,‏ `JWT_SECRET`,‏ `MACHINE_ID_SALT` ו-`STORAGE_ENCRYPTION_KEY`
5. לאחר הפריסה הראשונה, ודאו ביומנים שהנתונים נכתבים אל `/data`

אין לעשות שימוש חוזר במפתחות מפרויקט קודם.

## 14. רשימת פעולות מינימלית להפצת הפרויקט הנוכחי

הפקודות הנפוצות ביותר עבור הפצות עתידיות הן:

```powershell
flyctl auth whoami
flyctl status -a omniroute
flyctl secrets list -a omniroute
flyctl deploy
flyctl logs --no-tail -a omniroute
```

עבור הפצה רגילה, פקודת הליבה היא פשוט:

```powershell
flyctl deploy
```

עבור פריסה ראשונה בסביבה חדשה, השלבים העיקריים הם:

1. `flyctl auth login`
2. `flyctl apps create omniroute`
3. `flyctl secrets set ... -a omniroute`
4. `flyctl deploy`
5. `flyctl logs --no-tail -a omniroute`
