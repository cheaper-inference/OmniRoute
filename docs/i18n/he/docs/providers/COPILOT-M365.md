`copilot-m365-web` (כינוי `m365copilot`) שולח בקשות צ'אט בפורמט OpenAI דרך הפעלה מאומתת Microsoft 365 Copilot ב- `m365.cloud.microsoft/chat`. זהו אינטגרציה מקורית לא רשמית: אין צורך בתהליך פרוקסי נפרד או מארח מקומי במעלה הזרם. הספק ID, כינוי וחיבורים מיובאים קיימים ללא שינוי. `copilot-web` הוא ספק אחר עבור שירות הצרכנים ב- `copilot.microsoft.com`.

> **חדש בספקי קובצי Cookie באינטרנט?**
>
> לִקְרוֹא**`docs/getting-started/WEB-COOKIE-GUIDE.md`** לתהליך ההגדרה הכללי, הנחיות אימות, מגבלות ופתרון בעיות לפני ביצוע המדריך הספציפי לספק זה.
>
> **עבור יבוא מדור קודם:** האישור לספק זה הוא** לא עוגיה** . אל תעתיק עוגיות מ- `m365.cloud.microsoft`. האישור הוא פרמטר שאילתה WebSocket URL וקטע נתיב, שניהם נקראים מהכרטיסייה DevTools Network.

## דרישות מוקדמות

- חשבון Microsoft 365 עם גישה ל- Copilot ב- `m365.cloud.microsoft/chat`
- דפדפן מבוסס Chromium (Chrome, Edge) לבדיקת DevTools WebSocket
- גישה למודל המבוקש באותו חשבון; הזמינות משתנה בהתאם לשוכר ולרישיון

## כניסה מקורית (חשבונות עבודה או בית ספר)

לִבחוֹר**Microsoft 365 Copilot → Connect** ולהכין ניסיון כניסה. לוח המחוונים משתמש בזרימת קוד הרשאה עם PKCE; זה לא מבקש את סיסמת Microsoft או קוד MFA שלך.

1. פתח את א** לשונית דפדפן ריקה** , ואז פתח** רשת DevTools →** ולאפשר** שימור יומן** . עשה זאת לפני הניווט אל Microsoft: Windows SSO עשוי להסתיים מיד.
2. העתק את ההרשאה URL שמוצגת בתיבת הדו-שיח של החיבור ונווט אליה בכרטיסייה שהוכנה. השלם את בחירת החשבון של Microsoft או MFA אם תתבקש.
3. ביומן הרשת השמור, מצא את הבקשה ל- `https://login.microsoftonline.com/common/oauth2/nativeclient` והעתק את המלאה שלה** בקש URL** .
4. הדבק את URL הזה בתיבת הדו-שיח של החיבור והתחבר. אל תדביק קוד גולמי או את שורת הכתובת הסופי `wrongplace` URL: ההתקשרות החוזרת הנדרשת היא ניווט חולף.

כל ניסיון יפוג לאחר עשר דקות וניתן להשתמש בו פעם אחת בלבד. השרת בודק את מצבו, מאמת PKCE ויעד האימות מחדש לפני החלפת הקוד. לאחר תפוגה או כשל החלפה, התחל ניסיון חדש. ניסיון לא יכול לשרוד הפעלה מחדש של השרת.

אסימונים משתמשים במאגר פרטי החיבור הקיים ובנתיב הרענון. אימות מחדש של חיבור דורש את אותה זהות Microsoft tenant/object, לא רק אותו דוא"ל. זה שומר על המפעיל naming/settings ומחליף אישורים מיובאים מיושנים. כניסה מקורית מיועדת לחשבונות work/school ; נתיב הייבוא מדור קודם נשאר זמין עבור חיבורים קיימים ותצורות שכבות נתמכות.

ה-callback מלא URL הוא אישור חד פעמי. לעולם אל תכלול את זה בצילומי מסך, יומנים, הודעות תמיכה או התחייבויות. זרימה זו אינה פותחת דפדפן בשרת, בודקת את היסטוריית הדפדפן שלך או מפעילה שרת התקשרות חוזרת מקומית.

## לכידת אישורים (שיטת WebSocket )

1. היכנס ב- `https://m365.cloud.microsoft/chat` והתחל שיחה.
2. לִפְתוֹחַ** רשת DevTools →** .
3. סנן לפי**WS** (WebSocket).
4. לחץ על חיבור Chathub WebSocket. חפש URL שמתחיל ב- `wss://substrate.office.com/m365Copilot/Chathub/`.
5. מתוך שלה** בקש URL** , העתק:
   - ערך פרמטר השאילתה `access_token` ( JWT קצר מועד).
   - קטע נתיב Chathub אחרי `/Chathub/` (למשל `<oid>@<tenant>`).

ל- URL המלא יש את הצורה:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. ב- OmniRoute, בחר**Microsoft 365 Copilot** , בחר באפשרות API-key/import מדור קודם, והדבק את האישור בפורמט:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. נְקִישָׁה** בדיקת חיבור** ו** לְהַצִיל** .

## לכידת אישורים (ייבוא HAR )

במקום להעתיק ערכים באופן ידני מה- WebSocket URL, אתה יכול לייצא קובץ DevTools HAR :

1. לִפְתוֹחַ** רשת DevTools →** .
2. התחל או המשך שיחת Microsoft 365 Copilot (זה מפעיל את חיבור WebSocket ).
3. לחץ לחיצה ימנית בחלונית Network ובחר** שמור הכל בתור HAR עם תוכן** .
4. ב- OmniRoute, השתמש ב-** ייבוא קובץ .har** לחצן בתיבת הדו-שיח של חיבור הספק.

OmniRoute סורק את HAR עבור Chathub WebSocket URL, מחלץ את `access_token` ו- `chathubPath`, ומאוכלס את שדות האישורים באופן אוטומטי. ייבוא HAR מפענח את תפוגת JWT ומציג את משך חיי האסימון שנותר.

> **לעולם אל תבצע ייצוא HAR אמיתי, אסימון גישה או אסימון רענון.** ערכי בדיקה ותיעוד חייבים להיות תמיד מצייני מיקום.

## חיי אסימונים ורענון

ה- `access_token` הוא קצר מועד (בדרך כלל**~ 75 דקות** ). ללא אסימון רענון שמיש, עליך ללכוד מחדש את האישור לאחר פקיעת התוקף.

### רענון אוטומטי עם `refreshToken`

בספק של Microsoft 365** הוסף חיבור** אוֹ** ערוך חיבור** דו-שיח, פתח** הגדרות מתקדמות → Refresh token (אופציונלי)** . הדבק אסימון רענון Microsoft OAuth עבור היקף `substrate.office.com/sydney` ושמור. הקלט מוסווה ואינו מולא מראש באסימון המאוחסן. בעת עריכה, השאר אותו ריק כדי לשמור על האסימון הקיים; הדבק אסימון חדש כדי להחליף אותו.

כניסה מקורית רוכשת את אסימון הרענון כאשר Microsoft מחזירה אחד. עבור ייבוא מדור קודם, השתמש בהענקת קוד הרשאות Microsoft תואם קיים; ספק זה אינו מיישם או מבטיח זרימת קוד מכשיר. כאשר אסימון רענון מוגדר, OmniRoute בודק את ה- `access_token` לפני בקשות ומרענן אותו רק כאשר הוא זקוק לרענון. רענון מוצלח ממשיך גם את אסימון הרענון המסובב, תוך הימנעות מלכידה חוזרת ידנית בזמן שאסימון הרענון נשאר בתוקף.

אם `refreshToken` לא מוגדר, עליך ללכוד מחדש את האישור WebSocket באופן ידני לאחר כל תפוגה.

### בחירת שכבה

| נִדבָּך      | כינוי                | מִשׁטָח                |
| ------------ | -------------------- | ---------------------- |
| `individual` | _(בְּרִירַת מֶחדָל)_ | Consumer M365 Copilot  |
| `edu`        | `included`           | Education M365 Copilot |
| `enterprise` | `work`               | M365 Copilot for Work  |

הגדר את השכבה** הגדרות מתקדמות tier → Copilot** . כניסה מקורית אינה מגדירה זאת, כך שחשבון עבודה חייב לבחור `enterprise` (כינוי `work`) וחשבון חינוך `edu`, גם כאשר משתמשים במודל מתועד IDs: אלה בוחרים את הטון, התרחיש וסוג הרישיון שלהם, אבל אפשרויות הסוכן וההתקשרות עדיין מגיעות מהשכבה, וברירות המחדל הבודדות עלולות להיכשל על דייר עבודה. שינוי הרמה אינו מקנה רישיון דגם. עקיפות פרוטוקול מתקדם מפורשות מקבלות עדיפות ויש להשתמש בהן רק כאשר אתה יודע את ערכי החוט הנדרשים.

## דגמים וניתוב

הקטלוג המקורי כולל את כל IDs העצמאיים המתועדים בתוספת ארבעת ה- IDs המקוריים. הקטלוג הוא סטטי ובלתי תלוי בחשבון, לא בדיקה של זכאות לחשבון: מסלולים בתשלום וכינויי תאימות נשארים ברשימה גם כאשר חשבון מחובר אינו יכול להשתמש בהם. תוויות תצוגת הדגם משמיטות את שם הספק ואת לוח הזמינות לכל דגם; הספק נשאר**Microsoft 365 Copilot** . תוויות מסומנות** כינוי** אוֹ** מוֹרֶשֶׁת** לשמור על המזהים הקיימים ומיפוי הפרוטוקול שלהם, לא ערובה לגרסת מודל היסטורית. ה-proxy העצמאי** ייבוא מ /models** ההוראות אינן חלות על ספק WebSocket מקורי זה.

| משפחת דוגמניות    | IDs קנונית                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| אוֹטוֹמָטִי       | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| מוקדם יותר GPT    | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude סונטה      | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude אופוס      | `claude-opus`, `claude-opus-4.8`                                                                 |

רשומים גם כינויים כגון `auto`, `quick`, `think-deeper` וכינויים של גרסה. `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` ו- `copilot-m365-gpt-5-5-chat` הקיימים נשארים בתוקף. ה- IDs המתועד זקוק לקידומת הספק (`copilot-m365-web/claude-opus` או `m365copilot/claude-opus`): רבות הן מילים כלליות או שמות דגמים של ספקים אחרים, כך ש- `claude-opus` חשוף ממשיך לנתב כפי שהוא עושה ללא ספק זה. רישום אינו הבטחה ש- Microsoft משרת את המודל הזה לכל חשבון. ה- IDs העצמאי עוקב אחר [קטלוג הפרוטוקולים](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) הציבורי (מפת הדגם-לטון המיוצאת והמטא-נתונים של התרחישים המודעים למודל). כל הפרופילים המקומיים שומרים על `availability: "unverified"`; הכללה בקטלוג אינה מבחן חשבון מוצלח.

- סירוב רישיון דגם מפורש חוזר** 403** `m365_model_not_licensed`, לא 502. ניתוב מנעולים שמתחברים ל- connection/model, ומשאירים דגמים מורשים על החיבור שמישים.
- `InvalidCopilotLicense` הוא סירוב רישיון ברמת החשבון, המדווח בנפרד כ- `m365_account_not_licensed`.
- מצערת לכל משתמש חוזרת** 429** `m365_throttled` ומקרר את החיבור. מחזיר מיצוי גישה עדיפות** 429** `priority_access_exhausted` והוא בהיקף של דגם. תוצאה של `OutOfCredits` עם `errorCode: "ReasoningTurnExhausted"` מחזירה** 429** `reasoning_turns_exhausted` במקום זאת, גם בהיקף דגם, ללא טענה של זמן איפוס. דווח על דייר עבודה אחד להגביל את צלילי ה-"Think deeper" בזמן שגווני ה-Quick המשיכו לשרת; ההיקף הזה הוא תצפית צרכנית, לא משהו שהמאגר הזה שיחזר. לכן הניתוב גם מוציא את שאר הדגמים המתועדים של Think עמוק יותר של `gpt-5.5` ו- `gpt-5.6` מסיבוב על החיבור הזה לאותו התקררות, ומשאיר את ה-Quick tones וכל כשל אחר בדגם שלו. רמזים לניסיון חוזר נשמרים; איפוס חסר אינו מפורסם כזמן איפוס ידוע.
- סירוב בטיחות Copilot (`Disengaged`) חוזר** 400** `provider_safety_rejection`, תווית עצירת הבטיחות של הספק המשותפת. זה אף פעם לא נחשב נגד תקינות החיבור, הלקוח SDKs לא מנסה שוב 400, ועם הפעלת `PROVIDER_SAFETY_STOPS_TERMINAL` הניתוב המשולב עוצר שם במקום להפעיל מחדש את הבקשה מול יעד אחר.
- בקשות בחיבור אחד עוברות בסידרה באמצעות סמפור החשבון הקיים. העדיפו ניתוק עדיפות במקום לוחות מקבילים; הסידרה לבדה אינה מבטלת את מגבלות קצב השיחה של Microsoft.

## בקש התנהגות ומגבלות

- כלים הם** חיקוי הפקודה** , לא קריאות לפונקציות Microsoft מקוריות. בקשה התומכת בכלי משתמשת בדור אחד מאוחסן; זה לא מבלה עוד דור בבחירת כלים. רק כלים מוצהרים עם צורות ארגומנט תקפות נתמכות מוחזרות כקריאות.
- תשובה מובנית ארוכה עם דוגמה אחת נגררת נשמרת כפרוזה. זוהי היוריסטית, לא הוכחה לכוונה; יישומים עדיין חייבים לאכוף את הרשאות הכלים שלהם.
- קלט תמונה עובד כמו שלקוח האינטרנט שולח אותו. כל חלק תמונה (`image_url` כ-data URL או URLHTTPS ציבורי, או Responses `input_image`) מועלה ל- `/m365Copilot/UploadFile` לשיחת התור עם אסימון הצ'אט, וההודעה מצביעה עליו עם ביאור `ImageFile` ; הטקסט מסמן היכן הוא ישב (`[image 1]`, ...). שיחה רעננה מעלה כל תמונה בהיסטוריה, המשך רק תמונות ההודעות החדשות. עד 10 תמונות PNG, JPEG, GIF או WebP של לכל היותר 10 MiB כל אחת (40 MiB לכל בקשה); הפורמט נקרא מהבתים. HTTPS URLs מובאים דרך מגן התמונות המרוחק הציבורי בלבד, המוצמד ל-DNS. העלאה נכשלה נכשלת בבקשה (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` או `m365_image_invalid`); תור לעולם אינו ממשיך ללא תמונה שניתנה לו. חלקים אחרים שאינם טקסט (שמע, קבצים) נדחים במפורש, לא נשמטים בשקט.
- בקשת המשך ממשיכה את אותה שיחה במעלה הזרם ושולחת רק את ההודעות לאחר התשובה הקודמת. זה חייב להרחיב את התשובה בדיוק: אותו חיבור, פרופיל דגם ומערך כלים; היסטוריה ללא שינוי (שרשרת sha256 מעל כל הודעה); ומזהי קריאת הכלים של התשובה, או הטקסט שלה עד לרווח לבן. כל דבר אחר (היסטוריה ערוכה, סשן נוסף עם אותה הודעה ראשונה, תשובה אחרת, שיחה בטלה למשך 30 דקות או קרוב למכסה של 600 הודעות של Copilot, חיבור ללא מזהה) מתחיל שיחה רעננה עם כל ההיסטוריה. תור כושל לעולם לא מתחדש, ו- `InternalError` נטול תוכן נשלח מחדש פעם אחת בשיחה חדשה (** 502** `m365_internal_error` אם הוא נכשל שוב). ההמשך נשמר בזיכרון התהליך: הפעלה מחדש מתחילה שיחות חדשות.
- כל תור רץ בצ'אט הזמני של Copilot(`disableMemory=1`): השיחה שומרת על ההקשר שלה בזמן שהיא פועלת ולעולם לא מופיעה בהיסטוריית הצ'אט של החשבון. לכן, בדיקות מודל, Test All ובדיקות משולבות עשויות לחקור ספק זה מבלי להשאיר שיחות מאחור.
- לתור יש דד-ליין סרק של 120 שניות ודד-ליין כולל מוגבל. תשובות סופיות בלבד, סינון התקדמות וביטול מטופלים על ידי transport/composer. הילידים
- תשובות מבוססות אינטרנט שומרות על המקורות שלהן. Copilot מסמן ציטוט בשורה עם תווי בקרה לשימוש פרטי ושולח את המקורות כ- `references`; כל סמן הופך לקישור Markdown ממוספר (`[1](https://…)`, או URL חשוף כאשר Copilot השתמש בסמן כיעד קישור) עם ביאור `url_citation` תואם (`message.annotations`, או `delta.annotations` על הנתח הנושא את הקישור). מקור שלא מגיע לעולם נשמט, כך שהסמנים לעולם אינם מגיעים ללקוח. בעת סטרימינג, טקסט לאחר ציטוט ביטוי ממתין עד שהמקור שלו יגיע.
- סיכום ההיגיון של Copilot(`ChainOfThoughtSummary`), כאשר המודל שולח אחד, מוחזר כ- `reasoning_content`, לעולם לא כחלק מהתשובה. תקציר שמשכתב את עצמו מפסיק את הסטרימינג מבלי להיכשל בסיבוב.
- לפני כל תוכן, כשלי licence/throttle שומרים על HTTP 403/429 גם כאשר התבקשה סטרימינג. לאחר התחלת תוכן, כשלים הם אירועי שגיאה SSE, אף פעם לא סיום מוצלח. שכתוב במעלה הזרם שלא יכול להיות מיוצג על ידי הזרמת הוספה בלבד היא שגיאת זרם מפורשת; תגובות כלים שאינן זורמות ומאוחסנות שומרות על הטקסט הסופי.
- כאשר Copilot מסרבת לחיבור עצמו, תשובתו מדווחת כפי שהיא:** 401** `m365_unauthorized` עבור כניסה שנדחתה או שפג תוקפו (היכנס שוב),** 429** עם `Retry-After` שלו למצערת, וכשל בלחיצת יד אחרת, אף פעם לא כשל חיבור גנרי.

## יצירת תמונות

`POST /v1/images/generations` עם `model: "copilot-m365-web/m365-copilot-image"` (כינוי `m365copilot/m365-copilot-image`) מצייר עם כלי התמונות המובנה של Copilot, כפי שעושה לקוח האינטרנט. כל תמונה היא סיבוב Copilot אחד: היא מצטרפת עם אפשרויות התמונה של לקוח האינטרנט ומכריזה על `GenerateGraphicArt`, והתמונה מגיעה עם ערך התקדמות המצביע על חפץ בשירות המעצב של Microsoft. החפץ הזה מסרב לאסימון הצ'אט, אז OmniRoute מטביע אסימון Designer מאסימון הרענון של החיבור ומוריד את הבייטים; האסימון נשלח רק ל- `designerapp.officeapps.live.com`.

- צריך חיבור מקורי לכניסה (אסימון רענון); אסימון מודבק נכשל עם** 400** לפני כל תור הוא בילה.
- `n` הוא 1-4, סיבוב אחד כל אחד. `size` מנווט רק כיוון (רחב יותר, גבוה יותר או מרובע), ש- Copilot קורא מההנחיה; Copilot בוחר את גודל העיבוד.
- תמונות מוחזרות בשורה: `b64_json` כברירת מחדל, נתונים URL עבור `response_format: "url"`.
- תמונות שנוצרו שואבות תקציב יומי קטן, נפרד מצ'אט. כאשר הוא מנוצל הבקשה נכשלת עם** 429** . סיבוב שעונה בלי תמונה נכשל עם** 502** (אוֹ** 400** /** 503** כאשר הטקסט של Copilot נקרא כסירוב או כבעיית יכולת); ההודעה אומרת איזה.

## מודל אבטחה

- **אינטגרציה לא רשמית.** ספק זה מהנדס לאחור את פרוטוקול BizChat WebSocket. זה עלול להישבר ללא הודעה מוקדמת כאשר Microsoft משנה את נקודת הקצה.
- דגל `subscriptionRisk: true` משקף שהשילוב מסתמך על נקודת קצה לא מתועדת. הגבלות חשבון אפשריות אך לא מאושרות.
- אסימון הגישה הוא JWT קצר מועד. התייחס אליו כאל סיסמה: אל תתחייב, התחבר או תשתף אותה.
- אסימון הרענון מעניק גישה מתמשכת למשטח Microsoft 365. אחסן אותו באותה זהירות כמו מפתח API.

## פתרון בעיות

### האימות נכשל באופן מיידי

- ודא שהעתקת מ-**WebSocket URL** , לא מבקשת XHR/Fetch. האישור נמצא בפרמטר השאילתה `access_token` של חיבור Chathub WebSocket — לא בכותרת `Authorization: Bearer`.
- ודא שה- `chathubPath` כולל את קטע `<oid>@<tenant>` המלא מנתיב URL.

### האסימון יפוג לאחר ~ 75 דקות

זה צפוי. ללא `refreshToken`, אסימון הגישה הוא קצר מועד. אוֹ:

- ללכוד מחדש את האישור מ- DevTools, או
- הגדר** הגדרות מתקדמות → Refresh token (אופציונלי)** בתיבת הדו-שיח הוסף או ערוך חיבור לרענון אוטומטי.

### בדיקת החיבור עובר אבל הצ'אט מחזיר 401

לחיבור שנוצר עם** היכנס באמצעות Microsoft** , Test Connection בודק את תפוגה של אסימון הגישה ומחדש אסימון שפג תוקפו עם אסימון הרענון המאוחסן, כך שבדיקה עוברת גם מוכיחה שאסימון הרענון עדיין עובד.

עבור אישור מודבק, Test Connection בודק את צורת האישור, וכאשר האסימון נושא תוקף, שתוקף האסימון שבו הספק ישתמש לא פג (האסימון המאוחסן של החיבור זוכה להדבקה מעופשנת; אסימון רענון נחשב כמתחדש). אסימון שבוטל לפני שפג תוקפו עדיין עובר את המבחן; לאחר מכן חוזר הצ'אט** 401** `m365_unauthorized`. לְהִשְׁתַמֵשׁ** היכנס באמצעות Microsoft** שוב, או ללכוד מחדש אישור חדש.

### Copilot לא מופיע ברשימת הספקים

ודא ש- `copilot-m365-web` מופעל ב** ספקי לוח מחוונים →** . הספק עשוי להיות מוסתר כברירת מחדל בשכבות מסוימות.
