## מהו ספק?

חשבו על ספק כמו על **חברת סלולר**. בדיוק כפי שאתם זקוקים לחברת סלולר כדי לבצע שיחות, אתם זקוקים לספק AI כדי להשתמש במודלי AI. ‏OmniRoute הוא כמו טלפון שעובד עם **כל חברות הסלולר** — ניתן לעבור ביניהן באופן אוטומטי.

### סוגי ספקים

| סוג                       | מה זה                       | דוגמאות                         | עלות                   |
| ------------------------- | --------------------------- | ------------------------------- | ---------------------- |
| **חינם**                  | לא נדרש תשלום               | Kiro, Pollinations              | $0                     |
| **מפתח API**              | נדרש מפתח API               | OpenAI, Anthropic, Google       | תשלום לפי שימוש        |
| **OAuth**                 | התחברות באמצעות החשבון שלכם | Claude Code, GitHub Copilot     | מנוי                   |
| **קובץ Cookie מהאינטרנט** | משתמש בהפעלת הדפדפן שלכם    | ChatGPT Web (Codex), Gemini Web | $0 (משתמש בחשבון שלכם) |

### ספקים המשתמשים בקובצי Cookie מהאינטרנט

עיינו ב-**[WEB-COOKIE-GUIDE.md](./WEB-COOKIE-GUIDE.md)** לקבלת הוראות הגדרה כלליות, מגבלות, פתרון בעיות והנחיות אימות ייעודיות לכל ספק.

## התחלה מהירה: חיבור הספק הראשון שלכם

### הגדרה אופציונלית של ספקים חינמיים בהפעלה הראשונה

אשף ההפעלה הראשונה מציע כרטיס מפורש בשם **הגדרת ספקים חינמיים**. הוא מפיק את הרשימה העדכנית
של הספקים הזכאים ממרשם הספקים ללא אימות של OmniRoute, ולאחר מכן מאפשר לכם לסקור ולבטל את הבחירה בכל
ספק לפני האישור. OmniRoute מציג את הודעת האזהרה של הספק וקישור לאתר שלו,
כדי שתוכלו לעיין תחילה בתנאי הצד השלישי, במדיניות הפרטיות, בזמינות ובמגבלות הקצב.

פעולה זו היא אופציונלית: השלמת האשף לעולם אינה יוצרת חיבורים לספקים חינמיים ללא ידיעתכם.
היא יוצרת רק ספקים שעדיין חסרים, משאירה חיבורים קיימים שהותאמו אישית
ללא שינוי, ומדווחת בנפרד על ספקים שנוצרו, שכבר הוגדרו ושנכשלו. לאחר תוצאה חלקית, תוכלו
לנסות שוב בבטחה רק את אלה שנכשלו.

### אפשרות א': ספק חינמי (ללא כרטיס אשראי)

1. פתחו את לוח הבקרה בכתובת `http://localhost:20128`
2. עברו אל **ספקים** → **הוספת ספק**
3. בחרו אחד מהספקים החינמיים הבאים:
   - **Kiro AI** — מודלים חינמיים של Claude (ללא צורך באימות)
   - **Pollinations** — GPT-5, Claude ו-Gemini בחינם (ללא צורך במפתח)
   - **LongCat** — 10M אסימונים בחינם (הקצאה חד-פעמית, דורש חשבון + KYC)
   - **Cloudflare AI** — יותר מ-50 מודלים, 10K נוירונים ליום
   - **MLX Gemma 26B** — מודל מקומי ל-Apple Silicon (כ-38.5 אסימונים לשנייה, כ-15.9GB זיכרון RAM)
   - **MLX Qwen 3.8 27B** — מודל מקומי ל-Apple Silicon (כ-9.1 אסימונים לשנייה, כ-13.1GB זיכרון RAM)
4. לחצו על **חיבור**
5. סיימתם! כעת יש לכם גישה חינמית לבינה מלאכותית.

### אפשרות ב': ספק עם מפתח API (בתשלום)

1. קבלו מפתח API מאתר הספק:
   - **OpenAI**: https://platform.openai.com/api-keys
   - **Anthropic**: https://console.anthropic.com/
   - **Google**: https://aistudio.google.com/apikey
   - **DeepSeek**: https://platform.deepseek.com/
   - **Groq**: https://console.groq.com/
2. פתחו את לוח הבקרה בכתובת `http://localhost:20128`
3. עברו אל **ספקים** → **הוספת ספק**
4. בחרו את הספק שלכם
5. הדביקו את מפתח ה-API שלכם
6. לחצו על **חיבור**
7. סיימתם! כעת יש לכם גישה למודלים של אותו ספק.

### אפשרות ג': ספק OAuth (מינוי)

1. פתחו את לוח הבקרה בכתובת `http://localhost:20128`
2. עברו אל **ספקים** → **הוספת ספק**
3. בחרו את הספק שלכם (לדוגמה, Claude Code או GitHub Copilot)
4. לחצו על **חיבור באמצעות OAuth**
5. התחברו באמצעות החשבון שלכם
6. סיימתם! כעת יש לכם גישה למודלים הכלולים במינוי שלכם.

### אפשרות ד': מודלי MLX מקומיים (Apple Silicon)

במחשבי Mac עם Apple Silicon וזיכרון מאוחד, OmniRoute תומך בחיבור למודלי MLX מקומיים שפועלים באמצעות `mlx-lm.server`, כספקים מקומיים רגילים התואמים ל-OpenAI.

#### דרישות מקדימות

- **מחשב Mac עם Apple Silicon** (M1/M2/M3/M4), מומלץ עם 24GB ומעלה של זיכרון מאוחד
- מנהל החבילות **uv**: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- **mlx-lm**: `uv pip install mlx-lm`

#### התחלה מהירה

1. **התקינו את התלויות**:

   ```bash
   # התקינו את uv אם הוא עדיין אינו מותקן
   curl -LsSf https://astral.sh/uv/install.sh | sh

   # התקינו את mlx-lm
   uv pip install mlx-lm
   ```

2. **הפעילו ידנית את שרתי MLX** (במסופים נפרדים):

   ```bash
   # מסוף 1: Gemma 4 26B A4B IT-QAT (יציאה 11435)
   uv run mlx_lm.server --model mlx-community/gemma-4-26B-A4B-it-qat-q4_0-mlx-aligned --port 11435 --host 127.0.0.1

   # מסוף 2: Qwen 3.8 27B MLX Mixed (יציאה 11436)
   uv run mlx_lm.server --model maglun/Qwen3.8-27B-MLX-Mixed-3.80bpw --port 11436 --host 127.0.0.1
   ```

3. **התחברו בלוח הבקרה של OmniRoute**:
   - עברו אל **ספקים** → **הוספת ספק**
   - בחרו **MLX Gemma 26B** או **MLX Qwen 3.8 27B**
   - לחצו על **חיבור** (אין צורך במפתח API)

4. **השתמשו עם OpenCode**:
   ```bash
   # הגדירו את OpenCode לשימוש ב-OmniRoute
   opencode config set api.base_url http://localhost:20128/v1
   opencode config set api.key <your-omniroute-api-key>

   # השתמשו במודלי MLX
   opencode run --model mlx-gemma/gemma-4-26b
   opencode run --model mlx-qwen/qwen3.8-27b
   ```

#### ניהול זיכרון

**חשוב**: עם 24GB של זיכרון מאוחד, רק **מודל MLX גדול אחד יכול לפעול בכל זמן נתון**.

- Gemma 26B: שימוש שיא של כ-15.9GB זיכרון
- Qwen 3.8 27B: שימוש שיא של כ-13.1GB זיכרון

עליכם לנהל זאת ידנית:

- הפעילו רק שרת MLX אחד בכל פעם, או
- הפעילו את שניהם במחשבים נפרדים, או
- עצרו אחד לפני הפעלת האחר

OmniRoute אינו מנהל באופן אוטומטי את תהליכי שרת MLX — הוא רק מנתב בקשות לנקודות הקצה התואמות ל-OpenAI שאתם מגדירים.

#### תמיכה בקריאה לכלים

שני המודלים תומכים בקריאה לכלים התואמת ל-OpenAI. בדקו באמצעות:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mlx-gemma/gemma-4-26b",
    "messages": [{"role": "user", "content": "What is 2+2? Use the calculator tool."}],
    "tools": [{"type": "function", "function": {"name": "calculator", "description": "Calculate", "parameters": {"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]}}}]
  }'
```

#### פתרון בעיות

| בעיה               | פתרון                                                                     |
| ------------------ | ------------------------------------------------------------------------- |
| השרת אינו מופעל    | בדקו את `uv run mlx_lm.server --help` ואמתו את מזהי המודלים               |
| אין מספיק זיכרון   | ודאו שרק מודל אחד פועל; סגרו יישומים אחרים; בדקו את Activity Monitor      |
| החיבור נדחה        | ודאו שהשרת פועל ביציאה הנכונה (11435/11436)                               |
| תגובות איטיות      | הבקשה הראשונה טוענת את המודל לזיכרון (כ-30-60 שניות); הבקשות הבאות מהירות |
| הקריאה לכלים נכשלת | ודאו שהמודל תומך בכלים; בדקו ביומני OmniRoute אם קיימות שגיאות תרגום      |

## כיצד לחבר ספק (שלב אחר שלב)

### שלב 1: פתחו את לוח הבקרה

עברו אל `http://localhost:20128` בדפדפן.

### שלב 2: עברו אל ספקים

לחצו על **ספקים** בסרגל הצד.

### שלב 3: לחצו על הוספת ספק

לחצו על הלחצן **+ הוספת ספק**.

### שלב 4: בחרו את הספק שלכם

עיינו ברשימה או חפשו את הספק שלכם. לחצו עליו.

### שלב 5: הזינו פרטי גישה

- **ספקים חינמיים**: אין צורך בפרטי גישה — פשוט לחצו על **התחברות**
- **ספקים עם מפתח API**: הדביקו את מפתח ה-API שלכם
- **ספקי OAuth**: לחצו על **התחברות באמצעות OAuth** והיכנסו לחשבון

### שלב 6: בדקו את החיבור

לחצו על **בדיקת חיבור** כדי לוודא שהוא פועל.

### שלב 7: סיימתם!

הספק שלכם מחובר כעת. תוכלו להשתמש בו באמצעות `model: "auto"` או לציין את הספק ישירות.

## שימוש במספר ספקים

OmniRoute פועל באופן מיטבי עם **מספר ספקים**. כך תקבלו:

- **גיבוי אוטומטי** — אם ספק אחד נכשל, OmniRoute מנסה את הבא
- **מיטוב עלויות** — OmniRoute בוחר את הספק הזול ביותר לכל בקשה
- **מיטוב מהירות** — OmniRoute בוחר את הספק המהיר ביותר לכל בקשה
- **מיטוב איכות** — OmniRoute בוחר את הספק המתאים ביותר לכל משימה

### הגדרה מומלצת

חברו לפחות **3 ספקים** לקבלת החוויה הטובה ביותר:

1. **ספק חינמי אחד** (Kiro או Pollinations) — זמין תמיד
2. **ספק מהיר אחד** (Groq, Cerebras) — לתגובות מהירות
3. **ספק איכותי אחד** (OpenAI, Anthropic, Google) — למשימות מורכבות

### Qoder: בחירת אמצעי העברת פרטי ההזדהות

Qoder דורש פרטי הזדהות. לשני אמצעי ההעברה שלו יש יכולות שונות; שם מודל
לבדו אינו מציין מה חיבור מסוים מסוגל לעשות.

| פרטי הזדהות                       | אמצעי ההעברה של OmniRoute                 | קריאה לכלים מצד מבצע הקריאה                  | הזרמה                                                |
| --------------------------------- | ----------------------------------------- | -------------------------------------------- | ---------------------------------------------------- |
| PAT שמתחיל ב-`pt-`                | תהליך `qodercli` מקומי במארח של OmniRoute | לא נתמכת                                     | נאגרת: SSE נשלח רק לאחר שה-CLI מחזיר את התשובה המלאה |
| אסימון גישה שאינו PAT או מפתח API | נקודת קצה HTTP תואמת OpenAI של DashScope  | מועברת כפי שהיא, בכפוף למודל/מפתח במעלה הזרם | נתיב HTTP/SSE במעלה הזרם                             |

עבור PAT, יש להתקין את ה-CLI של Qoder באותו מארח או קונטיינר שבו נמצא OmniRoute. קובץ ההפעלה
חייב להיות ניתן לאיתור בשם `qodercli`, או שיש להגדיר את `CLI_QODER_BIN` לנתיב של קובץ ההפעלה שלו. CLI
שמותקן רק במארח Docker אינו נמצא אוטומטית בקונטיינר. קבצים בינאריים
חסרים גורמים לשגיאה מפורשת שמפנה להתקנה או להגדרת הנתיב.

לנתיב הצ'אט של PAT יש פסק זמן של 45 שניות לתהליך. הוא משטח את השיחה לכדי
הנחיה ומפעיל את ה-CLI במצב הדפסה ללא הזרמה. בקשת `stream: true` משנה
את מעטפת התגובה ל-SSE; היא אינה מספקת העברה הדרגתית של טוקנים ממעלה הזרם.
אימות CLI/הצגת רשימת מודלים משתמשים בפסק זמן נפרד של 20 שניות. אלו הן ברירות המחדל הנוכחיות
בקוד, ולא הגדרות שניתנות לתצורה בלוח הבקרה.

יש להשתמש בחיבורי PAT לצ'אט רגיל. בקשות סוכן הכוללות `tools` או `functions` מהסוג הישן
אינן כוללות חשבונות PAT במהלך בחירת פרטי ההזדהות, לרבות יעדי שילוב מוצמדים. מאגר Qoder
מעורב עדיין יכול לבחור את חשבון ה-HTTP שלו. גם קריאות ישירות למבצע ה-PAT נכשלות
באופן מפורש לפני הפעלת ה-CLI, במקום להשמיט בשקט הגדרות כלים. הגבלה זו
נוגעת לכלים שסופקו על ידי מבצע הקריאה ל-API, ולא לכלים פנימיים שבהם ה-CLI של Qoder
עשוי להשתמש בעצמו. מפתח HTTP אינו מבטיח שכל מודל תומך בכלים; בדיקות
היכולת הרגילות של המודל עדיין חלות.

OAuth בדפדפן זמין רק כאשר מנהל המערכת מגדיר את כל חמש ההגדרות:
`QODER_OAUTH_AUTHORIZE_URL`, `QODER_OAUTH_TOKEN_URL`, `QODER_OAUTH_USERINFO_URL`,
`QODER_OAUTH_CLIENT_ID` ו-`QODER_OAUTH_CLIENT_SECRET`. ערכי ברירת המחדל שלהן ריקים; התקנה
שאינה מוגדרת צריכה להשתמש בייבוא נתמך של פרטי הזדהות במקום להניח
שתהליך ההתחברות בדפדפן מוכן.

הפניות למימוש: [מבצע Qoder](../../open-sse/executors/qoder.ts),
[סביבת זמן הריצה של ה-CLI](../../open-sse/services/qoderCli.ts), וכן
[תצורת OAuth](../../src/lib/oauth/constants/oauth.ts). הזרמת PAT הדרגתית
ופסק זמן שניתן לתצורה הם שיפורים נפרדים; התנהגות זו אינה מבטיחה אותם.

## שאלות נפוצות

### "האם עליי לשלם כדי להשתמש ב-OmniRoute?"

**לא!** OmniRoute הוא חינמי ובקוד פתוח. אפשר להשתמש בספקים חינמיים (Kiro, Pollinations) מבלי לשלם דבר. התשלום נדרש רק אם בוחרים להשתמש בספקים בתשלום.

### "עם איזה ספק כדאי להתחיל?"

כדאי להתחיל עם **Kiro AI** — הוא חינמי, אינו דורש מפתח API ומעניק גישה למודלים של Claude. לאחר מכן אפשר להוסיף ספקים נוספים לפי הצורך.

### "האם אפשר להשתמש במספר ספקים בו-זמנית?"

**כן!** זו בדיוק המטרה של OmniRoute. חברו מספר ספקים והשתמשו ב-`model: "auto"` כדי לאפשר ל-OmniRoute לבחור את הספק המתאים ביותר לכל בקשה.

### "מה קורה אם ספק מפסיק לפעול?"

OmniRoute מדלג באופן אוטומטי על ספקים שכשלו ומנסה את הספק הבא. אין צורך לעשות דבר.

### "איך מנתקים ספק?"

עברו אל Providers → לחצו על הספק → לחצו על **ניתוק**.

### "האם אפשר להשתמש במפתחות ה-API הקיימים שלי?"

**כן!** אם כבר יש לכם מפתחות API עבור OpenAI, Anthropic, Google וכו', תוכלו להשתמש בהם ב-OmniRoute. פשוט הדביקו אותם בעת חיבור הספק.
