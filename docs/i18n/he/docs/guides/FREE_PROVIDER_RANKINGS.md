> **בקצרה**: OmniRoute מדרג את הספקים **החינמיים** שלו לפי איכות המודלים באמצעות **ציוני ELO של
> Arena AI (בסגנון LMArena)**. פתחו את הדף **דירוג ספקים חינמיים** בלוח הבקרה כדי
> לראות אילו ספקים חינמיים מציעים את המודלים החזקים ביותר למשימה שלכם —
> בדירוג הכולל או בסינון לפי קטגוריה (כתיבת קוד, סקירה, תיעוד, ניפוי שגיאות).

---

## מה זה

OmniRoute רושמת 377 ספקים, כולל 155 רישומי קטלוג מסומנים**free/no-auth** (מפתח ללא אישור, OAuth שכבות חופשיות או API שכבות חופשיות - עיין [במדריך השכבות החינמיות](../getting-started/FREE-TIERS-GUIDE.md) [ובמדריך המלא של השכבות החינמיות](../reference/FREE_TIERS.md) ). המלכוד: ספקי חינם משתנים מאוד באיכות הדגם. ספק ללא אישור המשרת מודל גבול הוא הרבה יותר שימושי מאשר ספק המשרת מודל קטן מדור קודם.

**דירוגי ספקים בחינם** תשובות"** איזה ספק חינמי נותן לי את הדגם הטוב ביותר?** "על ידי הצטרפות לקטלוג של כל ספק חינמי עם** ציוני איכות ממקור המונים** מה** טבלת הישגים של Arena AI** (העדפה אנושית ELO, אותו רעיון מאחורי זירת הצ'אטבוטים של LMArena). הספקים מדורגים אז לפי החוזק שלהם** הדגם החינמי הטוב ביותר** .

הדירוג מחושב משלושה מקורות אמיתיים:

1. רשימות הספקים החינמיים - `NOAUTH_PROVIDERS`, בתוספת ערכים של `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` מסומנים ב- `hasFree` (`src/shared/constants/providers.ts`).
2. קטלוג הדגמים של כל ספק ממרשם הספקים (`open-sse/config/providerRegistry.ts`).
3. ציוני התאמה למשימות שנגזרו מ-ELO המאוחסנים בטבלת `model_intelligence` DB על ידי מנוע הסנכרון Arena ELO (`src/lib/arenaEloSync.ts`).

היגיון ההצטרפות חי ב- `src/lib/freeProviderRankings.ts`.

## כיצד לגשת

### דף לוח הבקרה

פתחו את לוח הבקרה ועברו אל **עלויות → דירוג ספקים חינמיים**, או נווטו ישירות אל:

```
/dashboard/free-provider-rankings
```

הדף (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) מציג:

- **דוכן מנצחים לשלושת המקומות הראשונים** (🥇 🥈 🥉) של הספקים החינמיים המדורגים במקומות הגבוהים ביותר.
- **טבלת דירוג** מלאה עם העמודות: **דירוג**, **ספק**, **מודל מוביל**,
  **ציון**, **ציון ממוצע**, **מודלים**, **סוג**.
- **לחצני סינון לפי קטגוריה**: _כל הקטגוריות_, _ברירת מחדל_, _כתיבת קוד_, _סקירה_,
  _תיעוד_, _ניפוי שגיאות_.

תג **הסוג** של כל ספק מציין כיצד הוא ניתן בחינם:

| תג       | משמעות                                  |
| -------- | --------------------------------------- |
| `NOAUTH` | חינמי תמיד, ללא צורך בפרטי גישה         |
| `OAUTH`  | ספק OAuth עם מסלול חינמי (`hasFree`)    |
| `APIKEY` | ספק מפתח API עם מסלול חינמי (`hasFree`) |

הציונים מוצגים כתוויות קריאות לבני אדם (למשל _עילית_, _מצוין_, _טוב מאוד_,
_טוב_, _ממוצע_) במקום כמספרים גולמיים, מכיוון שהערך הבסיסי מייצג איכות דירוג
יחסית ולא אחוזים.

### נקודת קצה של API

הדף נתמך על ידי נקודת קצה ציבורית לקריאה
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

פרמטרים של השאילתה (מאומתים באמצעות Zod):

| פרמטר      | סוג    | ברירת מחדל | הערות                                                                                             |
| ---------- | ------ | ---------- | ------------------------------------------------------------------------------------------------- |
| `category` | מחרוזת | (ללא)      | אחד מבין `default`, `coding`, `review`, `documentation`, `debugging`. השמיטו לקבלת הדירוג המשולב. |
| `limit`    | מספר   | `50`       | מוגבל לטווח `1–100`.                                                                              |

מבנה התגובה:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` הוא ערך Arena ELO המקורי; `score` הוא ערך ההתאמה למשימה לאחר נרמול
(ראו להלן). ספקים שאין להם מודלים עם ציונים אינם נכללים בתגובה.

## איך פועלים הציונים

### מקור: טבלת הדירוג של Arena AI

מנוע הסנכרון של Arena ELO (`src/lib/arenaEloSync.ts`) שולף שתי טבלאות דירוג — `text` ו-`code` — מה-API של טבלת הדירוג של Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). כאשר אותו API לא מחזיר טבלה שמישה, המנוע נסוג ל-`lmarena-ai/leaderboard-dataset` הרשמי ב-datasets-server של Hugging Face (`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`, `coding` → `code`); `GET /api/intelligence/sync` מדווח על `activeSource`, `lastError` ו-`lastFailedAt`. כל רשומה בטבלת הדירוג נושאת שם מודל, ספק, `score` של ELO, רווח ביטחון ומספר הצבעות.

קטגוריות טבלת הדירוג ממופות לקטגוריות המשימות של OmniRoute:

| טבלת דירוג Arena | קטגוריות משימות של OmniRoute                      |
| ---------------- | ------------------------------------------------- |
| `text`           | `default`, `review`, `documentation`, `debugging` |
| `code`           | `coding`                                          |

### נורמליזציה (ציון התאמה למשימה)

ציוני ELO גולמיים מנורמלים לכל טבלת דירוג ל-**ערך התאמה למשימה בטווח `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

הציון לעולם אינו מגיע ל-`0` או ל-`1`, מה שמשאיר מרווח תמרון לדריסות של המשתמש. זהו שדה ה-`score` שרואים בתגובת ה-API והתווית המוצגת בלוח המחוונים.

### רמת ביטחון

כל רשומה מקבלת רמת ביטחון על סמך מספר ההצבעות ב-Arena:

| ביטחון   | הצבעות  |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### אחסון ורעננות

רשומות מנורמלות נכתבות לטבלת `model_intelligence` במסד הנתונים עם
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). הרשומות **פגות לאחר
7 ימים**, כך שספק שמפסיק להסתנכרן בסופו של דבר נושר מהרשימה במקום להציג נתונים מיושנים.

הסנכרון פועל **כברירת מחדל**:

- הוא רץ פעם אחת בהפעלת השרת ולאחר מכן על גבי טיימר תקופתי
  (`src/lib/arenaEloSync.ts`, מחובר מ-`src/instrumentation-node.ts`).
- הוא **לא חוסם ולעולם אינו קטלני** — אם השליפה מהמקור נכשלת, OmniRoute ממשיך
  לפעול והדירוגים פשוט מציגים את הנתונים התקינים האחרונים (או מצב ריק).

שני משתני סביבה שולטים בו (מתועדים ב-
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| משתנה                     | ברירת מחדל    | מטרה                                        |
| ------------------------- | ------------- | ------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | הגדירו ל-`false` כדי לבטל את הסנכרון היוצא. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | מרווח הסנכרון, בשניות.                      |

### סנכרון ידני / סטטוס / ניקוי

למפעילים, נקודת קצה ניהולית מאומתת חושפת שליטה ידנית
(`src/app/api/intelligence/sync/route.ts` — דורש אימות ניהולי):

```
GET    /api/intelligence/sync          # סטטוס הסנכרון הנוכחי (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # הפעלת סנכרון ידני; body: { "dryRun": true } לתצוגה מקדימה ללא כתיבה
DELETE /api/intelligence/sync          # ניקוי כל רשומות ה-arena_elo המסונכרנות
```

אם עמוד הדירוגים ריק, `POST /api/intelligence/sync` ידני (או פשוט
הפעלה מחדש של השרת) יאכלס אותו מחדש.

### התאמת מודלים לטבלת הדירוג

מזהי המודלים ב-Registry ושמות המודלים ב-Arena לא תמיד תואמים בדיוק. הדירוג משתמש
בהתאמה גמישה (`findMatchingIntelligence` ב-`src/lib/freeProviderRankings.ts`):

1. התאמה מדויקת על מזהה המודל המנורמל.
2. התאמה לאחר הסרת סיומת גרסה עוקבת (למשל `kimi-k2.6` → `kimi-k2`).
3. התאמת קידומת (שם מודל בטבלת הדירוג הוא קידומת של מזהה ה-Registry).

בצד הסנכרון, קידומות ספק ידועות (`anthropic/`, `openai/`, `google/`, …)
מוסרות, ומפת כינויים קטנה מרחיבה שמות קנוניים לווריאנטים ש-OmniRoute משתמש בהם
באופן פנימי, כך שהמודלים נשארים ניתנים למציאה תחת כל שם.

### איך ספק מדורג

עבור כל ספק חינמי, המנוע מדרג כל מודל בקטלוג שלו, ואז:

- **מודל מוביל** = המודל בעל הציון הגבוה ביותר של הספק.
- **ציון ממוצע** = ממוצע הציונים על פני כל המודלים המדורגים של אותו ספק.
- **מודלים** = כמה מהמודלים של הספק קיבלו ציון Arena.

הספקים ממוינים קודם לפי **ציון המודל המוביל**, ואז לפי הציון הממוצע. זה מתגמל
ספק שמספק לפחות מודל חינמי חזק אחד.

## שימוש בדירוג לבחירת ספקים חינמיים

1. **בחרו את הקטגוריה המתאימה.** השתמשו במסנן **תכנות** עבור עומסי עבודה של סוכנים/קוד, או
   השאירו אותו על **כל הקטגוריות** / **ברירת מחדל** עבור צ'אט כללי. אותו ספק עשוי
   להיות מדורג באופן שונה בין קטגוריות, משום שהמודל המוביל שלו שונה בכל טבלת דירוג.
2. **העדיפו את המקומות הראשונים להגדרה חד-פעמית.** אם ברצונכם לחבר רק ספק חינמי אחד או
   שניים, התחילו באלו המדורגים בראש הקטגוריה שלכם.
3. **בדקו את תג הסוג.** ספקי `NOAUTH` הם המהירים ביותר לחיבור (ללא
   פרטי גישה). המסלולים החינמיים מסוג `OAUTH` / `APIKEY` דורשים הרשמה קצרה, אך לעיתים קרובות מציעים
   מודלים חזקים יותר. להוראות חיבור, עיינו ב[מדריך למסלולים חינמיים](../getting-started/FREE-TIERS-GUIDE.md).
4. **חברו כמה ספקים ואפשרו ל-Auto-Combo להחליט.** אותם נתוני Arena ELO שמפעילים
   דף זה משמשים גם את **גורם ההתאמה למשימה** של מנוע הניקוד Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`, סדר פתרון
   `user_override → arena_elo → models_dev_tier → static table`). לכן, לאחר חיבור
   הספקים החינמיים המובילים, ניתוב באמצעות `model: "auto"` (למשל `auto/coding`) יעדיף
   אוטומטית את המודלים החינמיים האיכותיים יותר עבור כל בקשה. לפירוט המלא של הניקוד לפי 16 גורמים, עיינו ב-
   [Auto-Combo](../routing/AUTO-COMBO.md).
