חוזה `config/cli-tools-manifest.json` הנייטרלי מכריז על IDs קנוני, כינויים, מועמדים בינאריים, מתכוני הגדרה, טיעוני מודל ויכולות. מתאם ה-Node הרגיל ב- `bin/cli/cli-manifest.mjs` ומתאם TypeScript ב- `src/shared/constants/cliIntegrationManifest.ts` קוראים את אותו קובץ. זמן ריצה, קטלוג, תצורה, השלמה, גנרטורים ורישום עורפי נבדקים יחד על ידי `tests/unit/cli/cli-manifest-drift.test.ts`. מקוטלג אינו אומר שניתן להפעיל או להגדיר כלי. בפרט, 5dive נשארת בתצורה בלבד.

## סביבת הילד ומחזור החיים

`omniroute run`, `omniroute launch` ו- `omniroute launch-codex` יורשים רשימת הרשאות תאימות OS/terminal ומזריקים את האישורים של היעד שנבחר. סודות ספק ומסד נתונים לא קשורים אינם עוברים בירושה כברירת מחדל. `--inherit-env` משחזר באופן מפורש את הירושה המלאה של סביבה הורה; השתמש בו רק כאשר תהליך הצד השלישי הנבחר אמור לקבל את הערכים הללו. זהו סינון סביבה, לא ארגז חול OS : התהליך עדיין פועל עם הרשאות מערכת הקבצים של המתקשר.

אותות פסיקה וסיום מועברים לילד. המשגר ממתין לאירוע הסגירה של הילד לפני הסרת התצורה הזמנית. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` שולט בתקופת החסד לפני סיום כפוי (ברירת מחדל 5000 אלפיות השנייה).

## התקנה מתמשכת של Gemini

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

שתי הפקודות הראשונות קובעות את המחשב הזה עבור השרת המקומי או המרוחק שנבחר. ההגדרה שומרת על הגדרות JSON שאינן קשורות, בוחרת אימות מפתח API Gemini וכותבת את נקודת הקצה והאישורים לקובץ `.gemini/.env` פרטי. זה מסרב JSON לא חוקי במקום לדרוס אותו. נקודת הקצה URLs חייבת להיות HTTP(S), ללא אישורים מוטמעים, פרמטרי שאילתה או קטעים. ריצה יבשה מדפיסה נתיבים, לא ערכי אישורים.

`GEMINI_CLI_HOME` או `--gemini-home` בוחרים את השורש הביתי המתמשך. `run gemini` בפועל יוצר ומאוחר יותר מסיר את הבית הזמני שלו. אף מצב לא עוקף את בדיקות אמון סביבת העבודה של Gemini.

## פרופילי Codex

`configure codex` כותב `<name>.config.toml` פרטי עם דגם ונקודת הקצה של ספק OmniRoute שלו. הפנייה לאישורים מתבצעת באמצעות `OMNIROUTE_API_KEY`, לעולם אינה מוטמעת. פקודת ההשקה מגדירה את הדגם הנבחר במקש `model` ברמה העליונה, לא בתוך `model_providers`.

קובצי פרופיל נפרדים הם חוזה Codex המתועד הנוכחי; הם מכסים את תצורת המשתמש כאשר הם נבחרים עם `codex --profile <name>`. עיין [בהפניה הרשמית לפרופיל](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) ובמדריך [OmniRoute Codex](./CODEX-CLI-CONFIGURATION.md).

## ביצוע פקודה הרמטית

עם `DATA_DIR` מפורש, הגדרת `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` מונעת מההפעלה לעבור לסביבת האישורים של ברירת המחדל של ספריית נתוני המשתמש. זה שימושי עבור בדיקות בודדות. זה לא משבית קבצי סביבה אחרים שנבחרו במפורש.

## ספריית עבודה `.env`

ה- CLI קורא קבצי `.env` בסדר הזה, והקובץ הראשון להגדיר מפתח מנצח: `DATA_DIR` המפורש, ספריית הנתונים המוגדרים כברירת מחדל, ספריית העבודה הנוכחית, ואז ספריית החבילה. משתני מעטפת תמיד מנצחים.

ספריית העבודה עשויה להיות שייכת למישהו אחר (מאגר משובט, ארכיון לא ארוז), ו- `omniroute serve` מעבירה את סביבת CLI לשרת ולכל כלי שהשרת מריץ. אז `.env` שם עשוי להגדיר רק את המפתחות האלה, הרשומים ב- `bin/cli/utils/untrustedCwdEnv.mjs`:

| מַפְתֵחַ                        | ערכים מקובלים                                              |
| ------------------------------- | ---------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` או `yes` בכל מקרה, הערכים שהשרת מתייחס אליהם   |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | עד 64 אותיות, ספרות, `_`, `.`, `@` או `-`                  |
| `LANGUAGE`                      | אותו הדבר, בתוספת `:`                                      |
| `TZ`                            | עד 64 אותיות, ספרות, `_`, `+`, `-` או `/`, לא מתחיל ב- `/` |
| `NO_COLOR`, `FORCE_COLOR`       | עד 16 אותיות וספרות                                        |

כל ערך `REQUIRE_API_KEY` מקבל מפעיל את הסימון, כך שהקובץ לא יכול לבטל את הסימון עצמו. עם זאת, הוא לא קובע את התוצאה: השרת קורא עקיפת `REQUIRE_API_KEY` המאוחסנת במסד הנתונים לפני הסביבה, בעוד שאזהרת ההפעלה לגבי האזנה בכל הממשקים ללא מפתח API קוראת רק את הסביבה. עם עקיפה מאוחסנת של `false`, ספריית עבודה `REQUIRE_API_KEY=true` משאירה את API פתוחה ומסתירה את האזהרה הזו. כלל ה- `TZ` צר יותר מ- POSIX: הוא דוחה `.`, `:`, `,` ו- `<>`, כך שצורת `:Area/City` וכללים כגון `EST5EDT,M3.2.0,M11.1.0` צריכים להיות מוגדרים בקליפה או ב- `<DATA_DIR>/.env`.

השמות חייבים להתאים בדיוק, באותיות גדולות. כל שורה אחרת, ערך שנכשל בבדיקתו, ושם שאינו אותיות ASCII רגילות, ספרות ו- `_` (למשל כזה עם בת NUL או אות דומה) מדלגים. ה- CLI מדפיס אזהרה אחת הנותנת שמות למפתחות שהוא לא יכול להגדיר ואחת הנותנת שמות למפתחות מותרים שמהם התעלם, כל אחד עם מה לשנות (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). אף אחד לא מדפיס את הערכים. נתיבי קבצים בהודעות אלה, ובדוחות `.env` path `omniroute doctor`, מוחלפים כאשר הם מכילים תווי בקרה או בידי. ההגבלה אינה חלה כאשר ספריית העבודה היא ספריית הנתונים או ספריית החבילה.

`PORT`, `API_PORT` ו- `DASHBOARD_PORT` אינם ברשימה. ללא בסיס URL ממקור בעל עדיפות גבוהה יותר, ה- CLI מדבר עם `localhost:<PORT>`, וכל מה שמאזין שם מקבל את מפתח API של CLI, את אסימון ההקשר ואת ה- CLI machine token (`x-omniroute-cli-token`, ראה [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), שהשרת המקומי מקבל לשיחות ניהול מ-loopback. יציאה מספריית העבודה תאפשר לקובץ הזה לבחור את המאזין, אז הגדר את היציאות במעטפת, ב- `<DATA_DIR>/.env` או עם אפשרות `--port` של פקודות שיש להן אחת (`serve`, `launch`, `run`).

למנתח אין תחביר `export`. שורה כגון `export LD_PRELOAD=...` שמה למשתנה `export LD_PRELOAD`; מספריית העבודה היא מדלגת, ובקבצי `.env` אחרים היא מגדירה את השם המילולי הזה, ששום דבר לא קורא.

ה- CLI מצמיד את האסימון המאוחסן של הקשר (אסימון גישה או מפתח API מדור קודם) רק עם המקור של ההקשר עצמו: סכמה, מארח ויציאה, בהשוואה ל- `URL.origin`. זה חל על בקשות שנעשות דרך לקוח HTTP של CLI(`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) ועל הפקודות `launch`, `launch codex`, `configure` ו- `setup-*` שכותבות בסיס URL ומפתחות לתצורה של כלי אחר. כשהם מצביעים על שרת אחר עם `--remote`, הם משתמשים ב- `--api-key` או `OMNIROUTE_API_KEY` מפורש אם מוגדר, וללא אסימון הקשר. ההשוואה מדויקת, אז `localhost` ו- `127.0.0.1`, או מארח עם ובלי נקודה נגררת, נחשבים כשרתים שונים ולא מקבלים אסימון הקשר. URL עם פרטי משתמש, קו נטוי או רווח לבן אף פעם לא תואם, כי מנתחי URL אחרים ( `urllib` ו- `httpx` של Python, למשל) יכולים לקרוא מארח שונה ממנו. עבור בקשות ה- CLI שולח את עצמו, הסימון הזה מכסה רק את הסכימה והסמכות, כך שמזהה עם רווח בנתיב או בשאילתה שומר על האסימון.
