## מה זה (ומה זה לא)

OmniRoute מייחס עלות בדולר ארה״ב לכל בקשה שהושלמה, באמצעות הכפלת מספר
הטוקנים בתעריפי המודל. מספרים אלה משמשים את לוח המחוונים **עלויות**, את פקודות
ה-CLI‏ `omniroute cost` / `omniroute usage`, את ייצואי ה-CSV/JSON ואת התקציבים לכל מפתח API.

> **ה״עלות״ בלוח המחוונים היא מדד לחיסכון, ולא חשבון לתשלום.** OmniRoute לעולם אינו מחייב אתכם
> — הוא מנתב את הבקשות שלכם לספקים שכבר חיברתם (המינויים שלכם,
> מסלולים חינמיים ומפתחות API). ״עלות כוללת של $290״ שנצברה כולה במודלים חינמיים
> פירושה בקירוב **$290 שלא שילמתם** ל-API בתשלום. הנתון הוא _אומדן_
> של העלות שהייתה לאותה תעבורה לפי מחירי המחירון הרגילים, כדי שתוכלו לראות היכן
> מרוכז השימוש שלכם וכמה אתם חוסכים באמצעות ניתוב לספקים זולים או חינמיים יותר.

הסבר זה מופיע ישירות ב-[README](../../README.md) של הפרויקט (״ה׳עלות׳ בלוח המחוונים
היא מדד לחיסכון, ולא חשבון לתשלום״).

מכיוון שהמספר הוא אומדן:

- הוא תלוי בטבלת התמחור של OmniRoute עבור כל מודל. מודל ללא רשומת תמחור
  תורם עלות של `0` (הוא מופיע כשורת ״ישן / חינמי״ בסייר).
- תעבורה במסלול חינמי או במסגרת מינוי עדיין צוברת עלות _משוערת_ — זהו
  הסכום שאתם חוסכים, ולא סכום שאתם חייבים.

## איך מעריכים עלויות

### מקור התמחור

העלויות מגיעות מטבלת התמחור הממוזגת ב- [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts), בסדר עדיפות זה (** הכי גבוה קודם** ):

1. **עקיפת משתמש** מחירי — מוגדרים בלוח המחוונים או באמצעות `PATCH /api/pricing` (מרחב השמות `pricing` ).
2. **models.dev Sync** תמחור — נלקח מ- `https://models.dev/api.json` (מרחב השמות `models_dev_pricing` ).
3. **סנכרון LiteLLM** מחירי — נלקחו מה- `model_prices_and_context_window.json` הציבורי של LiteLLM(מרחב השמות `pricing_synced` ).
4. **ברירות מחדל מקודדות** תעריפי — נשלחים ב- [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/).

עבור אותו provider/model, ערכים משכבות בעדיפות גבוהה יותר מחליפים שדות תואמים בשכבות נמוכות יותר; שדות שנעדרים משכבה עליונה עדיין יכולים להגיע משכבה תחתונה. הסדר קבוע גם כאשר שתי עבודות הסנכרון העצמאיות פועלות בו-זמנית. `GET /api/pricing?includeSources=1` מחזירה `pricing` ו- `sourceMap`, שתוויות לכל דגם שלהם (`user`, `modelsDev`, `litellm`, `default`) מזהות את השכבה בעלת העדיפות הגבוהה ביותר המכילה את המודל הזה.

**סנכרון LiteLLM** הוא מצטרף, מושבת כברירת מחדל. משתני הסביבה שלו (ראה [`.env.example`](../../.env.example) ) הם:

| Env var                 | בְּרִירַת מֶחדָל | מַטָרָה                                                 |
| ----------------------- | ---------------- | ------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`          | אפשר סנכרון תמחור LiteLLM ברקע.                         |
| `PRICING_SYNC_INTERVAL` | `86400`          | מרווח סנכרון בשניות (יומי).                             |
| `PRICING_SYNC_SOURCES`  | `litellm`        | בחירת מקור עבור סנכרון זה בלבד; כרגע רק `litellm` נתמך. |

**models.dev Sync** נפרד מהסנכרון LiteLLM והוא מושבת גם כברירת מחדל. הפעל אותו בהגדרות (models.dev sync) או השתמש במשתנים הבאים:

| Env var                    | בְּרִירַת מֶחדָל | מַטָרָה                                                                                                               |
| -------------------------- | ---------------- | --------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(לא מוגדר)_     | ביטול הגדרה פועל בעקבות הלחצן 'הגדרות'; `1/true/on/yes` כופה על ו- `0/false/off/no` כופה (גם אם ההגדרות מאפשרות זאת). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`          | מרווח סנכרון models.dev המוגדר כברירת מחדל בשניות (יומי).                                                             |

`PRICING_SYNC_SOURCES` עושה זאת** לֹא** אפשר models.dev; הוא שולט רק בסינכרון LiteLLM. מחיקת עקיפה של משתמש אינה מנקה אף מרחב שמות מסונכרן; שכבת התמחור הזמינה הבאה הופכת יעילה. עבור דגם ללא מחיר, בדוק גם את הגדרות הסנכרון וגם את ה- `sourceMap` לפני הוספת עקיפה ידנית.

### נוסחת העלות

העלות מחושבת לפי בקשה מתוך ספירת אסימונים ושיעורי אסימון למיליון ב- [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`):

- **אסימוני קלט** (מינוס קריאות מטמון ואסימוני יצירת מטמון) קצב × `input`.
- **אסימוני קריאת מטמון** קצב × `cached` (נופל בחזרה לקצב הקלט).
- **אסימוני יצירת מטמון** קצב × `cache_creation` (נופל בחזרה לקצב הקלט).
- **אסימוני פלט** תעריף × `output`.
- **אסימוני הנמקה** קצב × `reasoning` (נופל בחזרה לקצב הפלט).

כל התעריפים מתפרשים USD ל-1,000,000 אסימונים. שכבת שירות "מהיר"/"עדיפות" או "פלקס" Codex מחילה מכפיל עלות (`getCodexFastCostMultiplier`) — למשל, flex מחויב בהנחה של 50% סמלית, מופיעה כמו** חיסכון גמיש** בלוח המחוונים.

שמות מודלים מנורמלים תחילה (קידומות נתיב ספק כגון `openai/` או `accounts/fireworks/models/` מופשטות) כך שהשורות ההיסטוריות עדיין תואמות למחיר.

### כיצד נרשמת ההוצאה

- העלות לכל בקשה מחושבת עם השלמת הבקשה. צריכת מכסה משותפת מתוכננת בתיקת לולאת האירועים הבאה דרך [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts).
- ההוצאה על מפתחות ה-API מאוחסנת ונשטפת באצוות על ידי ה- [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (ברירת מחדל של מרווח שטיפה של 60 שניות, מאגר של 1,000 כניסות). ניתן לכוונון באמצעות:

  | Env var                             | בְּרִירַת מֶחדָל | מַטָרָה                             |
  | ----------------------------------- | ---------------- | ----------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`          | מרווח שטיפה באלפיות שניות.          |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`           | מקסימום כניסות מאוחסנות לפני ההדחה. |

העלויות מעדיפות חיוב מדויק המדווח על ידי ספק (`provider_cost_usd`), לאחר מכן תמונת מצב של בקשה במחיר קטלוג (`calculated_cost_usd`), ולאחר מכן תמחור אסימון מהקטלוג הנוכחי. עלויות מאוחסנות אינן מחויבות שוב באמצעות ספירת האסימונים שלהן. שורות מדור קודם עם אסימון בלבד עדיין משתנות כאשר המחיר הקטלוגי שלהן משתנה.

### OCR והטבעות

- בקשות `/v1/ocr` מוצלחות משתמשות ב- upstream `usage_info.pages_processed`, לא בטווח העמודים המבוקש או במספר אובייקטי העמוד שהוחזרו. ההערכה היא דפים × `ocr_cost_per_page` (absolute USD/page,** לֹא** USD/million).
- בקשות עם הערות מסמכים או תיבות תוחמות דורשות תעריף `ocr_cost_per_annotated_page` נפרד. בלעדיו, העלות נותרת לא ידועה; התעריף הרגיל OCR אינו מוחלף בשקט.
- LiteLLM sync ממפה את שדה `annotation_cost_per_page` שלו במעלה הזרם ל- `ocr_cost_per_annotated_page`, תוך שמירה על ערך USD/page המוחלט וערכים להערות בלבד, כולל אפס מפורש. שדה קנוני מסופק מקבל עדיפות; מתעלמים מערכי כינוי לא חוקיים. עקיפות תמחור משתמשים שומרות על העדיפות הרגילה שלהן. ראה [מפתחות תמחור OCR של LiteLLM](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking).
- השימוש ב-OCR מאחסן את ספירת הדפים, מחיר היחידה, עלות USD מחושבת, מפתח API והחיבור שנבחר. דפים לעולם אינם מיוצגים כאסימונים. יומני שיחות מכילים מטא נתונים לחיוב, לא URLs מסמך, PDF bytes או טקסט שחולץ.
- בקשות `/v1/embeddings` מוצלחות מתעדות שורת שימוש אחת לכל אצווה פיזית, כולל אצוות נפרדות שהושלמו באותה אלפיות השנייה. חיובים המדווחים על ידי ספק עדיפות על הערכות סמליות; עטיפות משולבות אינן מוסיפות תשלום.
- היסטוריית השימוש, ניתוח העלויות, חלונות provider/account, מגבלות ההוצאה על מפתחות API, ספר עלויות הבקשות ואוסף שימוש יומי כולל חיובים אלה. מפתחות ללא יומן שומרים על חשבונאות מספרית מבלי לשמור על טקסט מקור.
- שימוש חסר או תעריפים הם** לֹא יְדוּעַ** , לא בחינם: כותרת עלות התגובה מושמטת, ומדיניות השימוש הקיימת ללא מחירים חלה על מפתחות API מוגבלים. תעריפי אפס מוגדרים במפורש נשארים שימוש תקף בעלות אפסית.

זוהי חשבונאות קדימה בלבד. קריאות OCR/embedding ישנות שמעולם לא כתבו היסטוריית שימוש לא ניתנות לשחזור מההגירה הזו. הערכות קטלוגיות הן אומדני USD, לא חשבונית, ואינן כוללות המרת מטבע, מס או הנחות.

### דיבור ותמונות

- ניסיונות מוצלחים `/v1/audio/transcriptions`, `/v1/audio/speech` ויצירת תמונות חולקים חשבונאות מספרית. שיחות ישירות ומשולבות נושאות את מקש API של המתקשר ואת החיבור שנבחר; עטיפה משולבת אף פעם לא מוסיפה חיוב שני.
- USD שדווח על ידי ספק זוכה בהערכת קטלוג, כולל חיוב אפס מפורש. OpenRouterJSON של `usage.cost` מנורמל ל- `cost_usd`. אחרת, אסימונים נמדדים משתמשים במחירי אסימון, שניות תמלול משתמשות במחירים לשנייה, קלט דיבור משתמש בספירת תווים של Unicode, ותמונות במחיר אחיד משתמשות במספר שהוחזר בפועל, לא ב- `n` המבוקש.
- בינארי OpenRouter TTS אין גוף שימוש JSON. לאחר סיום האודיו או שהמתקשר יבטל, OmniRoute שואל את הדור שלו ID ב-** אוֹתוֹ** מקור OpenRouter מוגדר. בקשת EU לעולם לא נופלת בחזרה למקור הגלובלי. זהו חיפוש מוגבל לקריאה בלבד; סינתזה לא נוסתה מחדש לצורך חשבונאות. רשומות חיוב יכולות להופיע לאחר סיום האודיו: ניסיונות חיפוש חוזרים פועלים ברקע עד כ-52 שניות, כולל מועדי רשת.
- במהלך חיפוש זה, לתגובת האודיו יש `X-OmniRoute-Cost-Status: pending` וללא כותרת עלות תגובה. החיוב הסופי שלו מופיע בהיסטוריית השימוש, בניתוח ובפנקס המפתחות לאחר התאמה. אם מטא נתונים אינם זמינים, נעשה שימוש בתמונת תעריף מוגדרת; אחרת העלות נשארת לא ידועה.
- לשניות, לדמויות ולספירת תמונות יש שדות נפרדים של יחידת חיוב, לעולם אל ספירת אסימונים מזויפת. הנהלת חשבונות שומרת רק שימוש מספרי, לא טקסט דיבור, תמלול או בתים של תמונה. הפטורים הקיימים בתמונה ללא תמחור אינם משתנים: תעריף תמונה חסר באמת אינו נועל מפתח מוגבל לאחרונה, והתגובה משמיטה את כותרת העלות במקום להכריז על השיחה כחופשית. כשל בחנות תמחור עדיין שומרת על ראיות שימוש לאכיפה סגורה.

שום מטען speech/image היסטורי אינו מומצא או ממולא. חיוב הספק נשאר אסמכתא עבור חשבוניות ועבור שיחות שלא דווח על חיובן.

## לוח הבקרה: דף העלויות

הדף **עלויות** נמצא ב-`/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`).
התצוגה הראשית שלו היא הלשונית **סקירת עלויות**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
שטוענת את כל הנתונים מ-`GET /api/usage/analytics`.

מה מוצג בו:

- **אריחי הוצאות** — הוצאה משוערת עבור _היום (1d)_, _7d_, _30d_ וטווח הזמן
  שנבחר. בורר טווח: `7d`, `30d`, `90d`, `all`.
- **מדדים מרכזיים** — בקשות בטווח הזמן, ספקים פעילים, מודלים פעילים ועלות ממוצעת
  לבקשה.
- **סייר העלויות** — טבלה הניתנת למיון ולסינון, המקובצת לפי **ספק**, **מודל**,
  **מפתח API**, **חשבון** או **רמת שירות**, ומציגה עלות, בקשות, טוקנים, עלות ממוצעת
  לבקשה ואחוז מסך העלות.
- **שימוש בטוקנים** — סך הכול / טוקני קלט / טוקני פלט ויחס קלט:פלט.
- **יעילות ניתוב** — מספר המעברים לחלופה, שיעור המעברים לחלופה וכיסוי המודל המבוקש.
- **תחזית חודשית** — חוזה את ההוצאה בסוף החודש לפי הממוצע היומי האחרון.
- **השוואת תקופות** — אחוז השינוי בין המחצית הראשונה למחצית השנייה של טווח הזמן.
- **תרשימים** — מגמת עלות יומית, נתח לפי ספק (תרשים עוגה), ספקים מובילים, מודלים מובילים, עלות
  לפי מפתח API, עלות לפי חשבון, דפוס שימוש שבועי ומפת חום של פעילות.
- **ייצוא** — הורדת טווח הזמן הנוכחי כ-**CSV** או כ-**JSON** (הכפתורים מופיעים
  ברגע שקיימים נתוני עלות שאינם אפס).

כאשר אין תעבורה מתומחרת, השורות מוצגות עם התווית "ישן / חינם" במקום `$0`,
בהתאם למודל מעקב החיסכון.

### דפי משנה קשורים של עלויות

אזור העלויות כולל גם את הדפים הבאים (כולם תחת `/dashboard/costs/`):

- **תמחור** (`/dashboard/costs/pricing`) — הצגה ודריסה של מחירים לכל מודל (מציג
  את לשונית התמחור המשותפת).
- **תקציב** (`/dashboard/costs/budget`) — הגדרת מגבלות הוצאה לכל תחום (מציג את לשונית
  התקציב המשותפת).
- **שיתוף מכסה** (`/dashboard/costs/quota-share`) — מאגרי מכסות משותפות ותצוגות של קצב
  ניצול.

## נקודות API

כל אלה דורשים אישור ניהול (loopback/JWT, via `requireManagementAuth`), אלא אם כן צוין.

### ניתוח שימוש ועלויות

| שִׁיטָה | נקודת קצה                | מַטָרָה                                                                                                                                                 |
| ------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`   | `/api/usage/analytics`   | אנליטיקה מלאה cost/usage : סיכום, מגמה יומית, לפי provider/model/API key/account/tier. שאילתה: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET`   | `/api/usage/utilization` | ניצול מכסה לכל ספק לאורך זמן. שאילתה: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                                      |
| `GET`   | `/api/usage/history`     | שורות היסטוריית שימוש גולמי.                                                                                                                            |
| `GET`   | `/api/usage/call-logs`   | יומני שיחות לפי בקשה (דגם, אסימונים, עלות, חביון, סטטוס).                                                                                               |
| `GET`   | `/api/usage/quota`       | סטטוס מכסת ספקים.                                                                                                                                       |
| `GET`   | `/api/usage/proxy-logs`  | יומני בקשת פרוקסי.                                                                                                                                      |

### תקציבים

| שִׁיטָה | נקודת קצה                | מַטָרָה                                                                      |
| ------- | ------------------------ | ---------------------------------------------------------------------------- |
| `GET`   | `/api/usage/budget`      | סיכום עלות בדיקת תקציב + עבור מפתח API אחד (נדרשת פרמטר שאילתת `apiKeyId` ). |
| `POST`  | `/api/usage/budget`      | הגדר daily/weekly/monthly USD מגבלות + סף אזהרה עבור מפתח API.               |
| `GET`   | `/api/usage/budget/bulk` | סיכומי תקציב בכמות גדולה על פני מפתחות API.                                  |

> התקציב API הוא בהיקף לפי** מפתח API** (`apiKeyId`). הגבולות המוחזרים על ידי `GET /api/usage/budget` כוללים `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`, a `warningThreshold` והסיכומים הרצים (`totalCostToday`, `totalCostMonth`, ...).

### תמחור

| שִׁיטָה  | נקודת קצה               | מַטָרָה                                                                                                                   |
| -------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | תמחור ארבע שכבות מוזג (משתמש, models.dev, LiteLLM, ברירות מחדל). `?includeSources=1` מחזיר את `pricing` + `sourceMap`.    |
| `PATCH`  | `/api/pricing`          | ביטול תמחור עבור `{ provider: { model: { input, output, cached, … } } }`.                                                 |
| `DELETE` | `/api/pricing`          | הסר עקיפות מחיר למשתמש (אופציונלי בהיקף של `?provider=&model=`); תעריפים מסונכרנים או ברירות מחדל מובנות נשארות כחסרונות. |
| `GET`    | `/api/pricing/defaults` | הצג שיעורי ברירת מחדל per-1M.                                                                                             |
| `GET`    | `/api/pricing/models`   | תמחור לפי דגם.                                                                                                            |
| `POST`   | `/api/pricing/sync`     | הפעל סנכרון ידני ממקורות חיצוניים (LiteLLM).                                                                              |
| `GET`    | `/api/pricing/sync`     | סטטוס סנכרון נוכחי.                                                                                                       |
| `DELETE` | `/api/pricing/sync`     | נקה תמחור מסונכרן LiteLLM בלבד (`pricing_synced`); נתוני models.dev נפרדים.                                               |

### נקודות קצה אחרות הרלוונטיות לעלות

| שִׁיטָה | נקודת קצה                     | מַטָרָה                                                  |
| ------- | ----------------------------- | -------------------------------------------------------- |

## CLI

ממשק שורת הפקודה של OmniRoute מספק פקודות לעלויות, שימוש ותמחור (הרשומות בקובץ
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

דוח עלויות מצטבר מ-`/api/usage/analytics`.

```bash
omniroute cost                          # 30 הימים האחרונים, מקובצים לפי ספק
omniroute cost --period 7d              # 7 הימים האחרונים
omniroute cost --group-by model         # קיבוץ לפי provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

עמודות: קבוצה, בקשות, אסימוני קלט/פלט, עלות (USD) ואחוז מהסכום הכולל. שורת סיכום כוללת
מודפסת בסוף (אלא אם משתמשים ב-`--quiet` או ב-`--output json`).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # סיכום עלויות לפי ספק
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# תקציבים
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` קוראת את `GET /api/pricing/defaults`. כדי לערוך מחירים של מודלים
> בודדים במקום זאת, השתמשו בדף **תמחור** בלוח הבקרה או ב-`PATCH /api/pricing`.

## פתרון בעיות

- **כל העלויות מוצגות כ-$0 / "Legacy / Free".** למודלים שבשימוש אין רשומת תמחור.
  הפעילו סנכרון חיצוני (`PRICING_SYNC_ENABLED=true`) והריצו `omniroute pricing sync`, או
  הגדירו מחירים ידנית דרך דף התמחור / `PATCH /api/pricing`.
- **התמחור של מודל היסטורי שגוי.** תקנו את המחיר (באמצעות דריסה או סנכרון מחדש) — העלות
  מחושבת מחדש לפי מספר האסימונים בכל קריאה של נתוני הניתוח, כך שההערכות מתעדכנות רטרואקטיבית.
- **נתוני ההוצאה מפגרים אחרי הזמן האמיתי.** ההוצאות לכל מפתח מעובדות באצוות; הנמיכו את
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` אם דרושים לכם נתונים עדכניים יותר.
