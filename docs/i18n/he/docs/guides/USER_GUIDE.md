## 🎯 תרחישי שימוש

### תרחיש 1: "יש לי מינוי Claude Pro"

**בעיה:** המכסה פוקעת בלי שנעשה בה שימוש, ויש מגבלות קצב במהלך עבודת תכנות אינטנסיבית

```
שילוב: "maximize-claude"
  1. cc/claude-opus-4-7        (ניצול מלא של המינוי)
  2. glm/glm-4.7               (גיבוי זול כשהמכסה נגמרת)
  3. if/qwen3.8-max-preview       (חלופת חירום חינמית)

עלות חודשית: $20 (מינוי) + כ-$5 (גיבוי) = $25 בסך הכול
לעומת $20 + הגעה למגבלות = תסכול
```

### תרחיש 2: "אני רוצה עלות אפסית"

**בעיה:** אין לי אפשרות לממן מינויים, ונדרש לי AI אמין לתכנות

```
שילוב: "zero-cost"
  1. if/kimi-k2.7-code          (מופיעה גישה חינמית; ייתכן שיחולו מגבלות קצב)
  2. kr/qwen3-coder-next        (חלופה חינמית של Kiro)

עלות חודשית: $0
איכות: יש לבדוק את המודל, המגבלות, הפרטיות וה-SLA עבור עומס העבודה שלכם
```

### תרחיש 3: "אני צריך תכנות 24/7, ללא הפרעות"

**בעיה:** יש מועדי הגשה, ואין לי אפשרות להרשות זמני השבתה

```
שילוב: "always-on"
  1. cc/claude-opus-4-7        (האיכות הטובה ביותר)
  2. cx/gpt-5.5                (מינוי שני)
  3. glm/glm-4.7               (זול, מתאפס מדי יום)
  4. minimax/MiniMax-M2.1      (הזול ביותר, מתאפס לאחר 5 שעות)

תוצאה: 5 שכבות חלופיות משפרות את העמידות; זמינות השירותים במעלה הזרם אינה מובטחת
עלות חודשית: $20-200 (מינויים) + $10-20 (גיבוי)
```

## 📖 הגדרת ספקים

כדי להוסיף בכמות גדולה חיבורי מפתחות API מקובץ CSV או JSON, השתמשו ב-**לוח הבקרה → ספקים → ייבוא מקובץ**. העמודות מבוססות על מיקום (`provider,name,apiKey,baseUrl,priority`); הערך `provider` חייב להיות ספק מנוהל קיים או צומת תואם. ראו [ייבוא ספקים מקובץ CSV או JSON](../providers/CSV-IMPORT.md).

### 🔐 ספקי מנוי

#### Claude Code (Pro/Max)

```bash
לוח הבקרה → ספקים → חיבור Claude Code
→ כניסה באמצעות OAuth → רענון אוטומטי של האסימון
→ מעקב אחר מכסה ל-5 שעות + מכסה שבועית

מודלים:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**טיפ מקצועי:** השתמשו ב-Opus למשימות מורכבות וב-Sonnet למהירות. OmniRoute עוקב אחר המכסה לכל מודל!

אין דפדפן במארח של OmniRoute? הפעילו את `claude setup-token` בכל מקום שבו Claude Code מחובר, והדביקו את האסימון לשנה בלשונית **אסימון הגדרה**. ראו [Claude Code עם אסימון הגדרה](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

נתיבים התואמים ל-Claude ול-Claude Code שומרים על מאמץ החשיבה `max` עבור מודלי Opus ו-Sonnet. מודלי Haiku אינם מקבלים את רמת המאמץ `max`, ולכן OmniRoute מוריד בקשה זו לתקציב חשיבה גבוה לפני שליחתה לספק במעלה הזרם.

#### OpenAI Codex (Plus/Pro)

```bash
לוח הבקרה → ספקים → חיבור Codex
→ כניסה באמצעות OAuth (יציאה 1455)
→ איפוס לאחר 5 שעות + איפוס שבועי

מודלים:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
לוח הבקרה → ספקים → חיבור GitHub
→ OAuth באמצעות GitHub
→ איפוס חודשי (ב-1 בחודש)

מודלים:
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview
```

### 💰 ספקים זולים

#### GLM-4.7 (איפוס יומי, $0.6/1M)

1. הירשמו: [Zhipu AI](https://open.bigmodel.cn)
2. קבלו מפתח API מתוכנית Coding Plan
3. לוח הבקרה → הוספת מפתח API: ספק: `glm`, מפתח API: `your-key`

**שימוש:** `glm/glm-4.7` — **טיפ מקצועי:** תוכנית Coding Plan מציעה מכסה גדולה פי 3 בשביעית מהעלות! האיפוס מתבצע מדי יום בשעה 10:00 בבוקר.

#### MiniMax M2.1 (איפוס לאחר 5 שעות, $0.20/1M)

1. הירשמו: [MiniMax](https://www.minimax.io)
2. קבלו מפתח API → לוח הבקרה → הוספת מפתח API

**שימוש:** `minimax/MiniMax-M2.1` — **טיפ מקצועי:** האפשרות הזולה ביותר להקשר ארוך (מיליון אסימונים)!

#### Kimi K2 (מחיר קבוע של $9 לחודש)

1. הירשמו למנוי: [Moonshot AI](https://platform.kimi.ai?aff=omniroute)
2. קבלו מפתח API → לוח הבקרה → הוספת מפתח API

**שימוש:** `kimi/kimi-k2.5` — **טיפ מקצועי:** מחיר קבוע של $9 לחודש עבור 10 מיליון אסימונים = עלות אפקטיבית של $0.90/1M!

#### Baidu Qianfan / ERNIE

## 🚀 פריסה

### התקנת npm גלובלית (מומלץ)

```bash
npm install -g omniroute

# יצירת תיקיית תצורה
mkdir -p ~/.omniroute

# יצירת קובץ .env (ראו .env.example)
cp .env.example ~/.omniroute/.env

# הפעלת השרת
omniroute
# או עם יציאה מותאמת אישית:
omniroute --port 3000
```

ה-CLI טוען אוטומטית את `.env` מתוך `~/.omniroute/.env` או `./.env`.

### מצב מגש מערכת

הפעילו את OmniRoute במגש המערכת:

```bash
omniroute serve --tray
```

הפקודה מסתיימת לאחר שהשרת ומגש המערכת מוכנים.

השרת ממשיך לפעול ללא המסוף.

מצב מגש המערכת נתמך ב-macOS, ב-Windows ובהפעלות Linux גרפיות. מצב מגש המערכת אינו פותח את לוח הבקרה באופן אוטומטי.

השתמשו בתפריט מגש המערכת עבור הפעולות הבאות:

- פתיחת לוח הבקרה.
- פתיחת `/dashboard/logs`.
- שינוי ההפעלה האוטומטית.
- עצירת OmniRoute.

אין לשלב את `--tray` עם האפשרויות הבאות:

- `--daemon`
- `--log`
- `--no-recovery`

מצבים אלה דורשים בעלות שונה על התהליך.

הפעילו את OmniRoute בעת הכניסה הבאה למחשב:

```bash
omniroute autostart enable
```

ההפעלה האוטומטית משתמשת במצב מגש המערכת ב-macOS, ב-Windows ובהפעלות Linux גרפיות. Linux ללא ממשק גרפי משתמש בשירות המשתמש הקיים של systemd.

השביתו הפעלה בעת הכניסה:

```bash
omniroute autostart disable
```

### הסרת התקנה

כאשר OmniRoute אינו נחוץ עוד, אנו מספקים שני סקריפטים מהירים להסרה נקייה:

| פקודה                    | פעולה                                                                                    |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| `npm run uninstall`      | מסירה את יישום המערכת, אך **שומרת את מסד הנתונים ואת ההגדרות שלכם** בתוך `~/.omniroute`. |
| `npm run uninstall:full` | מסירה את היישום וגם **מוחקת לצמיתות את כל ההגדרות, המפתחות ומסדי הנתונים**.              |

> הערה: כדי להריץ פקודות אלה, עברו לתיקיית הפרויקט של OmniRoute (אם שיבטתם אותו) והפעילו אותן. לחלופין, אם הוא הותקן באופן גלובלי, ניתן פשוט להריץ `npm uninstall -g omniroute`.

### מודלים מותאמים אישית

הוסיפו כל מזהה מודל לכל ספק מבלי לחכות לעדכון של האפליקציה:

```bash
# דרך ה-API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# רשימה: curl http://localhost:20128/api/provider-models?provider=openai
# הסרה: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

או השתמשו בדשבורד: **Providers → [Provider] → Custom Models**.

הערות:

- ספקי OpenRouter וספקים תואמי OpenAI/Anthropic מנוהלים מ-**Available Models** בלבד. הוספה ידנית, ייבוא וסנכרון אוטומטי — כולם מגיעים לאותה רשימת מודלים זמינים, ולכן אין קטע Custom Models נפרד עבור ספקים אלה.
- הקטע **Custom Models** מיועד לספקים שאינם חושפים ייבוא מנוהל של מודלים זמינים.

### ספקים מותאמים אישית תואמי OpenAI

כל גייטוויי שמדבר את ה-API של OpenAI (פרוקסי self-hosted, vLLM, אגרגטור צד שלישי)
יכול להתווסף כצומת ספק משלו:

1. **Providers → Add OpenAI Compatible**.
2. **Name**: תווית תצוגה עבור הצומת.
3. **Prefix**: שם הניתוב. לקוחות קוראים למודלים כ-`<prefix>/<model>`, כך שצומת עם
   תחילית `mygw` משרתת את `mygw/gpt-4o-mini`. שדה חובה; אין הגבלת תווים.
4. **API Type**: משפחת נקודות הקצה שהגייטוויי משרת (Chat Completions, Responses,
   Embeddings, אודיו, תמונות).
5. **Base URL**: שורש ה-API, עד `/v1` כולל (לדוגמה
   `https://gateway.example.com/v1`), ולא הנתיב המלא `/chat/completions`. גייטווייז עם
   נתיבים לא סטנדרטיים מגדירים אותם תחת **Advanced Settings** (נתיב chat, נתיב models).
6. השדה **API Key (for Check)** רק בודק את החיבור. לאחר יצירת הצומת,
   פתחו אותו והשתמשו ב-**Add Connection** כדי לאחסן את המפתח שבו הבקשות ישתמשו.

הצומת מקבלת מזהה פנימי בצורה `openai-compatible-<apiType>-<uuid>`; לעולם לא
תצטרכו להקליד אותו — התחילית היא השם הציבורי.

#### תחיליות שמורות

תחילית לא יכולה להיות המזהה או הכינוי של ספק מובנה (לדוגמה `openai`, `cf`), ולא
המזהה של ספק שהוצא משימוש. פותר המודלים בודק מזהים וכינויים מובנים לפני
צמתים מותאמים אישית, כך שצומת שמשתמשת באחת מהתחיליות האלה לעולם לא תקבל תעבורה:
`<prefix>/model` ינותב לספק המובנה במקום זאת, או ייכשל בכשל סגור (fail closed) אם אותו ספק
הוצא משימוש. יצירה או עריכה של צומת עם תחילית כזו נדחית עם:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

בחרו תחילית ייחודית (`mygw`, `acme-proxy`). אם בקשות לצומת מותאמת אישית נכשלות עם
שגיאה שמזכירה ספק מובנה או את האישורים שלו, בדקו אם התחילית של הצומת
שמורה: צמתים שנשמרו לפני שהכלל הזה היה קיים עדיין מאוחסנות, אבל התחילית שלהן מנתבת
לספק המובנה. ערכו את הצומת ותנו לה תחילית חדשה.

#### אפשרויות גייטוויי לכל חיבור

המפתחות האלה נכנסים ל-`providerSpecificData` של חיבור (לדוגמה דרך
`PUT /api/providers/{id}`):

- `toolNameMaxLength` (מספר שלם, 1–1024) — עבור חיבורים תואמי פורמט צ'אט של OpenAI שהגייטוויי שלהם
  דוחה שמות כלים ארוכים. שמות ארוכים יותר נשלחים ככינויים קצרים ומשוחזרים בחזרה
  בתגובה.
- `quotaEndpoint` — נקודת הקצה של מכסה/קרדיטים של הגייטוויי, הנקראת עבור רצועת המכסות בדשבורד ועבור
  ניתוב מודע-מכסה. עובד הן על חיבורים תואמי OpenAI והן תואמי Anthropic; המבנה המלא
  מתועד ב-`open-sse/services/usage/openaiCompatible.ts`.

```json

  "toolNameMaxLength": 64,

    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### שרשור עמיתים (Peers) של OmniRoute

אפשר להוסיף גייטוויי OmniRoute נוסף כספק **Custom OpenAI-compatible**. השתמשו
בכתובת ה-`/v1` הבסיסית של העמית ובמפתח API ייעודי עם הרשאות מינימליות שהונפק על ידי אותו עמית.

עבור שרשראות הדדיות או רבות-קפיצות, הפעילו את מנגנון מניעת הלולאות (opt-in loop guard) בכל גייטוויי:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

רק בקשות שנשלחות לכתובת URL של עמית שנמצאת ברשימת היתר מפורשת מקבלות את
הכותרת `X-OmniRoute-Peer-Trace`. גייטוויי דוחה מזהה instance חוזר או תקציב קפיצות
מוצה עם HTTP `508 Loop Detected`; ספקי upstream רגילים לא מקבלים מטא-דאטה של עמיתים.

שרשור עמיתים אינו שכפול מסד נתונים ואינו failover של מארח. כל גייטוויי שומר מצב
SQLite עצמאי, מטמונים, מוני קצב וסשנים. השתמשו ב-reverse proxy עם בדיקות תקינות או ב-failover
בצד הלקוח לזמינות active/passive או active/active, ולעולם אל תעגנו מסד נתונים SQLite אחד
לתוך מספר מופעי OmniRoute פעילים.

### Cloudflare Quick Tunnel

- זמין ב-**Dashboard → Endpoints** עבור Docker ופריסות self-hosted אחרות
- יוצר כתובת `https://*.trycloudflare.com` זמנית המפנה אל נקודת הקצה `/v1` התואמת-OpenAI הנוכחית שלכם
- ההפעלה הראשונה מתקינה את `cloudflared` רק בעת הצורך; הפעלות מחדש מאוחרות יותר עושות שימוש חוזר באותו בינארי מנוהל
- מנהרות Quick Tunnel אינן משוחזרות אוטומטית לאחר הפעלה מחדש של OmniRoute או של הקונטיינר; הפעילו אותן מחדש מלוח הבקרה בעת הצורך
- כתובות ה-URL של המנהרה הן ארעיות ומשתנות בכל עצירה/הפעלה של המנהרה
- מנהרות Quick Tunnel מנוהלות משתמשות כברירת מחדל בתעבורת HTTP/2 כדי להימנע מאזהרות רועשות על buffer של QUIC UDP בקונטיינרים מוגבלים
- הגדירו `CLOUDFLARED_PROTOCOL=quic` או `auto` אם ברצונכם לעקוף את בחירת התעבורה המנוהלת
- הגדירו `CLOUDFLARED_BIN` אם אתם מעדיפים להשתמש בבינארי `cloudflared` מותקן מראש במקום בהורדה המנוהלת
- ניתן להציג או להסתיר את הפאנלים של Cloudflare Quick Tunnel, Tailscale Funnel ו-ngrok Tunnel ב-**Settings → Appearance**. הסתרת פאנל אינה עוצרת מנהרה פעילה.

### אינטליגנציה של שער LLM (שלב 9)

- **מטמון סמנטי** — שמירה אוטומטית במטמון של תגובות שאינן streaming עם temperature=0 (עקיפה באמצעות `X-OmniRoute-No-Cache: true`)
- **אידמפוטנטיות בקשות** — הסרת כפילויות של בקשות בתוך 5 שניות באמצעות כותרת `Idempotency-Key` או `X-Request-Id`
- **מעקב התקדמות** — אירועי SSE מסוג `event: progress` במצב opt-in באמצעות כותרת `X-OmniRoute-Progress: true`

| ------------------------------ | ---------------------------------------------------------------------------------------------------- |
| **Fill First**                 | משתמש בחשבונות לפי סדר עדיפות — החשבון הראשי מטפל בכל הבקשות עד שאינו זמין                           |
| **Round Robin**                | עובר באופן מעגלי על כל החשבונות עם מגבלת דביקות (sticky) הניתנת להגדרה (ברירת מחדל: 3 קריאות לחשבון) |
| **P2C (Power of Two Choices)** | בוחר 2 חשבונות אקראיים ומנתב אל הבריא יותר מביניהם — מאזן עומסים עם מודעות לבריאות                   |
| **Random**                     | בוחר חשבון באופן אקראי לכל בקשה באמצעות ערבוב Fisher-Yates                                           |
| **Least Used**                 | מנתב אל החשבון עם חותמת הזמן `lastUsedAt` הישנה ביותר, ומפזר את התעבורה באופן שווה                   |
| **Cost Optimized**             | מנתב אל החשבון עם ערך העדיפות הנמוך ביותר, תוך אופטימיזציה לספקים בעלי העלות הנמוכה ביותר            |

**אסטרטגיות קומבו ואוטו מתקדמות** (ניתנות להגדרה לכל קומבו בנפרד או באמצעות קידומות `auto/*` — ראו [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — סדר קפדני, ללא מעבר מעגלי (round-robin)
- `weighted` — חלוקת תעבורה יחסית לפי משקלים לכל מודל
- `fill-first` — ריקון המודל הראשון עד שמגיעים למגבלות
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` ו-`cost-optimized`
- `auto` — מונע-ציון על פני כל המועמדים
- `lkgp` (Last Known Good Provider) — נעוץ בספק המוצלח האחרון, ולאחר מכן נסוג לכללים
- `context-optimized` — בוחר את המודל עם חלון ההקשר הפנוי הגדול ביותר
- `context-relay` — שרשור מודלים בעלי הקשר ארוך עבור תורות המשך

#### כותרת סשן דביק חיצוני

עבור זיקת סשן (session affinity) חיצונית (לדוגמה, סוכני Claude Code/Codex מאחורי reverse proxies), שלחו:

```http
X-Session-Id: your-session-key
```

OmniRoute מקבל גם `x_session_id` ומחזיר את מפתח הסשן הפעיל ב-`X-OmniRoute-Session-Id`.

אם אתם משתמשים ב-Nginx ושולחים כותרות עם קווים תחתונים, הפעילו:

```nginx
underscores_in_headers on;
```

#### כינויי מודלים עם תווי Wildcard

צרו דפוסי wildcard כדי למפות מחדש שמות מודלים:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

תווי ה-wildcard תומכים ב-`*` (תווים כלשהם) וב-`?` (תו בודד).

#### שרשראות Fallback

הגדירו שרשראות fallback גלובליות החלות על כל הבקשות:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### חוסן ומפסקי מעגל (Circuit Breakers)

הגדרה דרך **לוח הבקרה → הגדרות → חוסן (Resilience)**.

OmniRoute מיישמת חוסן ברמת הספק באמצעות חמישה רכיבים:

1. **תור בקשות וויסות קצב (Pacing)** — עיצוב בקשות ברמת המערכת:
   - **בקשות לדקה (RPM)** — מספר הבקשות המרבי לדקה לכל חשבון
   - **זמן מינימלי בין בקשות** — פער מינימלי באלפיות שנייה בין בקשות
   - **מספר בקשות מקסימלי במקביל** — מספר הבקשות הסימולטניות המרבי לכל חשבון

2. **תקופת צינון חיבור (Connection Cooldown)** — תצורה לפי סוג אימות עבור חיבור בודד לאחר כשלים הניתנים לניסיון חוזר:
   - **צינון בסיסי** — חלון הצינון המוגדר כברירת מחדל עבור כשלי ספק (upstream) הניתנים לניסיון חוזר
   - **שימוש ברמזי ניסיון חוזר מהספק** — מכבד רמזים סמכותיים של `Retry-After` או איפוס כאשר הם מסופקים
   - **מספר מרבי של צעדי Backoff** — רמת ה-backoff המעריכי המרבית עבור כשלים חוזרים

3. **מפסק מעגל של ספק (Provider Circuit Breaker)** — עוקב אחר כשלים מקצה-לקצה של הספק, מסמן ספק כמושבת (degraded) בסף האזהרה המוגדר, ופותח את המפסק כאשר מגיעים לסף הכשלים המוגדר:
   - **סף הידרדרות** — מספר כשלים רצופים של הספק לפני כניסה ל-`DEGRADED`
   - **סף כשלים** — מספר כשלים רצופים של הספק לפני כניסה ל-`OPEN`
   - **פסק זמן לאיפוס** — חלון הזמן לפני שהספק נבדק מחדש
   - **CLOSED** (תקין) — הבקשות זורמות כרגיל
   - **DEGRADED** — הבקשות עדיין זורמות בזמן שכשלים מוגברים נעקבים
   - **OPEN** — הספק חסום זמנית לאחר כשלים חוזרים
   - **HALF_OPEN** — בדיקה אם הספק התאושש

   מגבלות קצב `429` ברמת החיבור נשארות ב**תקופת צינון חיבור** ואינן נספרות כלפי מפסק הספק.

   מצב זמן הריצה של מפסק הספק מוצג רק ב**לוח הבקרה → בריאות (Health)**.

4. **המתנה לצינון (Wait For Cooldown)** — אם כל החיבורים המועמדים כבר נמצאים בתקופת צינון, OmniRoute יכולה להמתין לצינון המוקדם ביותר ולנסות שוב את אותה בקשת לקוח באופן אוטומטי.

5. **זיהוי אוטומטי של מגבלות קצב** — כאשר ספקים (upstream) מחזירים חלונות המתנה מפורשים, רמזים אלה עוקפים את צינון החיבור המקומי כאשר ההגדרה מופעלת.

**טיפ מקצועי:** השתמשו בדף **בריאות (Health)** כדי לבדוק ולאפס מפסקי ספקים פעילים לאחר הפסקה. דף החוסן משנה רק את התצורה.

### ייצוא / ייבוא מסד נתונים

ניהול גיבויי מסד נתונים ב**לוח הבקרה → הגדרות → מערכת ואחסון (System & Storage)**.

| פעולה                   | תיאור                                                                                                                   |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **ייצוא מסד נתונים**    | מוריד את מסד הנתונים הנוכחי של SQLite כקובץ `.sqlite`                                                                   |
| **ייצוא הכל (.tar.gz)** | מוריד ארכיון גיבוי מלא הכולל: מסד נתונים, הגדרות, שילובים, חיבורי ספקים (ללא אישורים), מטא-דאטה של מפתחות API           |
| **ייבוא מסד נתונים**    | העלאת קובץ `.sqlite` להחלפת מסד הנתונים הנוכחי. גיבוי לפני ייבוא נוצר אוטומטית אלא אם `DISABLE_SQLITE_AUTO_BACKUP=true` |

```bash
# API: ייצוא מסד נתונים
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: ייצוא הכל (ארכיון מלא)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ייבוא מסד נתונים
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**אימות ייבוא:** הקובץ המיובא מאומת מבחינת שלמות (בדיקת pragma של SQLite), טבלאות נדרשות (`provider_connections`, `provider_nodes`, `combos`, `api_keys`), וגודל (עד 100MB).

**מקרי שימוש:**

- העברת OmniRoute בין מכונות
- יצירת גיבויים חיצוניים לשחזור מאסון
- שיתוף תצורות בין חברי צוות (ייצוא הכל → שיתוף הארכיון)

### לוח ההגדרות

דף ההגדרות מאורגן ב-**7 לשוניות** לניווט נוח:

| לשונית            | תוכן                                                                                                                                                                         |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **כללי**          | כלי אחסון מערכת, התנהגות ברירת מחדל, נראות מנהרת Endpoint                                                                                                                    |
| **מראה**          | פקדי ערכת נושא (בהיר/כהה/מערכת), נראות סרגל הצד, מתגי פאנל עבור כרטיסי מנהרה של Cloudflare/Tailscale/ngrok                                                                   |
| **בינה מלאכותית** | תקציב חשיבה (passthrough / auto-strip / custom / adaptive — ראו [THINKING_BUDGET.md](./THINKING_BUDGET.md)), פרומפט מערכת גלובלי, סטטיסטיקות מטמון פרומפטים                  |
| **אבטחה**         | הגדרות התחברות/סיסמה, בקרת גישה לפי IP, אימות API עבור `/models`, חסימת ספקים, הגנה מפני הזרקת פרומפטים                                                                      |
| **ניתוב**         | אסטרטגיית ניתוב גלובלית (Fill First / Round Robin / P2C / Random / Least Used / Cost Optimized), כינויי מודלים מסוג wildcard, שרשראות גיבוי (fallback), ברירות מחדל של קומבו |
| **חוסן**          | תור בקשות, צינון חיבורים (cooldown), קונפיגורציית מפסק ספקים (breaker), והתנהגות המתנה לצינון                                                                                |
| **מתקדם**         | קונפיגורציית פרוקסי גלובלית (HTTP/SOCKS5), דריסות פרוקסי לכל ספק                                                                                                             |

הלשונית 'כללי' כבר לא משכפלת הערות לוגים ומטמון לקריאה בלבד. הגדרות שמירה ואופטימיזציה של בסיס הנתונים נשמרות דרך `/api/settings/database`; ניקוי מטמון ידני מתבצע באמצעות `DELETE /api/cache`. מגבלות השורות של לוג הבקשות ולוג הפרוקסי נשלטות על ידי `CALL_LOGS_TABLE_MAX_ROWS` ו-`PROXY_LOGS_TABLE_MAX_ROWS`.

### אסטרטגיות איזון של קומבו

הגדירו איזון לכל קומבו ב-**דשבורד → קומבו → יצירה/עריכה → אסטרטגיה**.

| אסטרטגיה           | תיאור                                                                |
| ------------------ | -------------------------------------------------------------------- |
| **Round-Robin**    | מחליפה בין המודלים ברצף                                              |
| **Priority**       | תמיד מנסה קודם את המודל הראשון; עוברת לגיבוי רק במקרה של שגיאה       |
| **Random**         | בוחרת מודל אקראי מהקומבו עבור כל בקשה                                |
| **Weighted**       | מנתבת באופן יחסי בהתבסס על משקלים שהוקצו לכל מודל                    |
| **Least-Used**     | מנתבת למודל עם מספר הבקשות האחרונות הקטן ביותר (משתמשת במדדי הקומבו) |
| **Cost-Optimized** | מנתבת למודל הזול ביותר הזמין (משתמשת בטבלת התמחור)                   |

ניתן להגדיר ברירות מחדל גלובליות של קומבו ב-**דשבורד → הגדרות → ניתוב → ברירות מחדל של קומבו**.
פסקי הזמן של יעדי קומבו יורשים כברירת מחדל את פסק הזמן של הבקשה הנוכחית. השתמשו ב-**פסק זמן ליעד (שניות)** בברירות המחדל של הקומבו או בקומבו בודד רק כאשר מגבלה קצרה יותר לכל יעד אמורה להפעיל מעבר לגיבוי מהיר יותר.

אופטימיזציות אפס-חביון של קומבו מופעלות באופן יזום (opt-in). השאירו את **אופטימיזציות אפס-החביון** כבויות כדי למנוע מתכונות החביון האלה להתחרות מול יעדי הגיבוי, לדלג על יעדים על סמך היסטוריית TTFT, או לדחוס בקשות גיבוי; הפעלתן מאפשרת בקשות גידור (hedging) מוגדרות, דילוגי TTFT חזויים ודחיסת גיבוי פרואקטיבית — המחליפות נאמנות ניתוב/בקשות בחביון זנב נמוך יותר.

השביתו את **מאגר טוקני ההיגיון (Reasoning token buffer)** כאשר ספקי ה-upstream דורשים מגבלות קפדניות של `max_tokens` / `maxOutputTokens`. כאשר האפשרות מופעלת, הניתוב המשולב (combo routing) מוסיף מרווח ביטחון למודלי היגיון רק עבור מודלים עם תקרת פלט ידועה, ומשאיר את מגבלת הטוקנים של הלקוח ללא שינוי כאשר הערך המאוגר הבטוח יחרוג מתקרה זו. אם מגבלת הלקוח כבר גבוהה מתקרה ידועה, OmniRoute מצמצם אותה לתקרה זו לפני שליחת הבקשה ל-upstream.

### לוח בקרת תקינות (Health Dashboard)

גישה דרך **Dashboard → Health**. סקירת תקינות מערכת בזמן אמת עם 6 כרטיסים:

| כרטיס                 | מה הוא מציג                                                   |
| --------------------- | ------------------------------------------------------------- |
| **System Status**     | זמן פעילות, גרסה, שימוש בזיכרון, תיקיית נתונים                |
| **Provider Health**   | מצב זמן-ריצה גלובלי של מפסק המעגל (circuit breaker) של הספקים |
| **Rate Limits**       | תקופות צינון חיבורים פעילות לפי חשבון, עם הזמן הנותר          |
| **Active Lockouts**   | נעילות פעילות ברמת המודל והחרגות זמניות                       |
| **Signature Cache**   | סטטיסטיקות מטמון ביטול כפילויות (מפתחות פעילים, שיעור פגיעות) |
| **Latency Telemetry** | צבירת זמני תגובה p50/p95/p99 לפי ספק                          |

**טיפ מקצועי:** עמוד התקינות מתרענן אוטומטית כל 10 שניות. השתמשו בכרטיס מפסק המעגל כדי לזהות אילו ספקים חווים בעיות.

## 🤖 ניתוב אוטומטי (ללא הגדרות)

OmniRoute מגיע עם **נתב אוטומטי מבוסס-ניקוד** שבוחר את המודל הטוב ביותר לכל בקשה מכל הספקים המחוברים — ללא צורך בתחזוקת שילובים. פשוט שלחו את הבקשה עם אחת מהקידומות `auto/*`, ו-OmniRoute ירכיב שילוב וירטואלי באופן דינמי, תוך דירוג המועמדים לפי זמן השהיה, עלות, שיעור הצלחה, התאמה לחלון ההקשר, התאמת המודל למשימה, תקלות אחרונות, מכסה ומצב מפסק הזרם.

| קידומת         | מיטוב עבור                                                                            |
| -------------- | ------------------------------------------------------------------------------------- |
| `auto`         | ברירת מחדל מאוזנת (זמן השהיה × עלות × שיעור הצלחה)                                    |
| `auto/coding`  | משימות תכנות: העדפה ל-Claude, GPT-5, GLM, Kimi, Qwen Coder ולמודלי התכנות של DeepSeek |
| `auto/cheap`   | העלות הנמוכה ביותר לטוקן, עם נכונות לקבל זמן השהיה גבוה יותר                          |
| `auto/fast`    | זמן ההשהיה הנמוך ביותר, ללא התחשבות בעלות                                             |
| `auto/offline` | ספקים מקומיים בלבד (Ollama, vLLM, llama.cpp) — שימושי לסביבות מבודדות מהרשת           |
| `auto/smart`   | איכות הסקת מסקנות בעדיפות ראשונה (Opus, GPT-5 xhigh, R1, הסקת המסקנות של GLM 5.1)     |
| `auto/lkgp`    | "הספק התקין האחרון הידוע" — נצמד לספק האחרון שהצליח, ולאחר מכן חוזר לכללי ברירת המחדל |

דוגמה:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

הנתב האוטומטי מתואר במלואו ב-[AUTO-COMBO.md](../routing/AUTO-COMBO.md) — כולל האופן שבו ניתן לכוונן את משקלי הניקוד, להוסיף ספקים לרשימה שחורה ולבחון החלטות ניתוב תחת **לוח הבקרה → שילוב אוטומטי**.

## 🔌 שילוב MCP ו-A2A

OmniRoute הוא גם **שרת MCP** (פרוטוקול הקשר למודל) וגם **שרת A2A**‏ (Agent-to-Agent JSON-RPC 2.0). כל סביבת פיתוח או מארח סוכנים התואמים ל-MCP יכולים לקרוא ישירות לכלים של OmniRoute — ללא צורך במעטפת נוספת.

### תעבורות MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP ניתן להזרמה**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (עבור תוספי סביבת פיתוח שמעדיפים stdio)

### חיבור Claude Desktop

ערכו את `~/Library/Application Support/Claude/claude_desktop_config.json` (ב-macOS) או את הקובץ המקביל ב-Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### חיבור Cursor / Continue / VS Code MCP

השתמשו בכתובת ה-SSE‏ `http://localhost:20128/api/mcp/sse` ובמפתח API מסוג Bearer שנוצר תחת **לוח הבקרה → מפתחות API**.

### תחומי הרשאה

MCP מגדיר כעת 32 תחומי הרשאה בעלי שם. ניתן להגביל כל מפתח Bearer לתחומי הרשאה מסוימים — ראו [MCP-SERVER.md](../frameworks/MCP-SERVER.md) לקבלת הרשימה המוסמכת של תחומי ההרשאה והכלים, ואת [A2A-SERVER.md](../frameworks/A2A-SERVER.md) לקבלת סכמת JSON-RPC.

- **מיומנויות מותאמות אישית** — הוסיפו קובץ TypeScript אל `src/lib/a2a/skills/`, רשמו אותו, והוא יהיה זמין מיד להפעלה דרך A2A

## 🔔 Webhooks

הירשמו לאירועי OmniRoute לצורך ניטור ואוטומציה בזמן אמת.

- צרו webhook דרך **לוח הבקרה → Webhooks** עם כתובת URL יעד וסוד חתימה מסוג HMAC
- אירועים זמינים: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- כל מטען נתונים כולל את `X-OmniRoute-Signature` (HMAC-SHA256) לצורך אימות
- ניסיונות חוזרים: 3 ניסיונות עם השהיה מעריכית, ולאחר מכן העברה לתור הודעות כושלות

הסכמה המלאה נמצאת ב-[WEBHOOKS.md](../frameworks/WEBHOOKS.md).

## 🛠️ ניהול תכנותי

ניתן לנהל כל משאב של OmniRoute (ספקים, שילובים, מפתחות, הגדרות) באמצעות HTTP, תוך שימוש ב**מפתח Bearer עם התחום `manage`**.

צרו את המפתח דרך **לוח הבקרה → מפתחות API → מפתח חדש → תחום: manage**, ולאחר מכן:

```bash
# הצגת רשימת הספקים
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# הוספת חיבור לספק
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# יצירת שילוב
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# הצגה/יצירה של מפתחות API
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

ראו [API_REFERENCE.md](../reference/API_REFERENCE.md) לקטלוג המלא של נקודות הקצה ולסכמות הבקשות/התגובות.

## 💻 CLI פנימי

OmniRoute כולל CLI פנימי (`omniroute …`) להגדרה, לאבחון ולשליטה בזמן ריצה. הוא **נפרד מהעמוד "כלי CLI" בלוח הבקרה**, שמגדיר כלי CLI של צד שלישי (Claude Code, Cursor, Codex, Cline, …) כדי שיוכלו לתקשר עם OmniRoute.

```bash
omniroute setup                    # אשף אינטראקטיבי (סיסמה, ספקים, שילובים)
omniroute setup --non-interactive  # מתאים ל-CI
omniroute doctor                   # אבחון תקינות (ספריית נתונים, מסד נתונים, ספקים, יציאות)
omniroute providers available      # הצגת הספקים הנתמכים
omniroute providers list           # הצגת החיבורים המוגדרים
omniroute providers test <id>      # בדיקה חיה של חיבור לספק
omniroute combos list              # הצגת שילובים
omniroute combos switch <name>     # הגדרת שילוב ברירת המחדל
omniroute models                   # הצגת המודלים הזמינים (--json, --search)
omniroute keys add | list | remove # ניהול מפתחות API מהמסוף
omniroute backup                   # יצירת תמונת מצב של התצורה ומסד הנתונים
omniroute restore [<timestamp>]    # שחזור מתמונת מצב
omniroute health                   # מצב תקינות מפורט (מנתקי מעגל, מטמון, זיכרון)
omniroute quota                    # שימוש במכסת הספק
omniroute mcp status               # מצב שרת MCP
omniroute a2a status               # מצב שרת A2A
omniroute tunnel list|create|stop  # מנהרות Cloudflare/Tailscale/ngrok
omniroute reset-password           # איפוס סיסמת מנהל המערכת
omniroute --mcp                    # הפעלת שרת MCP דרך stdio
omniroute --port 3000              # הפעלת השרת ביציאה מותאמת אישית
```

טיפ: שלבו את `omniroute doctor --json` עם כלי הניטור שלכם כדי לקבל התראות על חיבורים לא תקינים לספקים.

## 🖥️ יישום שולחן עבודה (Electron)

OmniRoute זמין כיישום שולחן עבודה מקורי עבור Windows, macOS ו-Linux.

```bash
# מתוך הספרייה electron:
cd electron
npm install

# מצב פיתוח (התחברות לשרת הפיתוח הפעיל של Next.js):
npm run dev

# מצב ייצור (משתמש בגרסת build עצמאית):
npm start
```

### בניית תוכניות התקנה

```bash
cd electron
npm run build          # הפלטפורמה הנוכחית
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg אוניברסלי)
npm run build:linux    # Linux (.AppImage)
```

פלט → `electron/dist-electron/`
