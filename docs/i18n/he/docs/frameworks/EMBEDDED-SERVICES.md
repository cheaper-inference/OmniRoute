- OmniRoute מתקין אותם תחת `DATA_DIR/services/{name}/` (מבודד מה- `package.json` של OmniRoute עצמו)
- OmniRoute משריץ ומנטר אותם כתהליכים ילדים
- OmniRoute מזריק מפתח API חולף לסביבת הילד ומסובב אותו ללא זמן השבתה (במקרה רלוונטי)
- כל מסלולי הניהול (`/api/services/*`) הם**LOCAL_ONLY** — נגיש רק מ-loopback (כלל קשה מס' 17)

│    Returns 503 service_not_running if supervisor not in "running". │
│                                                                    │
│  src/shared/constants/providers.ts                                 │
│    Entry for "9router": isEmbeddedService: true                    │
│                                                                    │
│  open-sse/config/providerRegistry.ts                               │

│                                                                    │

## 3. מכונת מצבי מחזור חיים

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
             בדיקת התקינות הצליחה   │         קריסה / SIGTERM   │
                               ┌────▼─────┐  (יציאה בתוך 5 שנ׳) │
                               │ running  │──── קריסה ──────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

המצבים מאוחסנים בטבלת מסד הנתונים `version_manager` (בעמודה `status`) ומשוקפים
במצב שבזיכרון של `ServiceSupervisor`. המצב שבזיכרון הוא הסמכות הקובעת עבור
תהליך פועל; מצב מסד הנתונים הוא גיבוי מתמיד בעת האתחול.

### מעברי מצבים

| מ־              | אירוע                                   | אל                     |
| --------------- | --------------------------------------- | ---------------------- |
| `not_installed` | `install()` מסתיים בהצלחה               | `stopped`              |
| `stopped`       | מתבצעת קריאה ל־`start()`                | `starting`             |
| `starting`      | בדיקת התקינות מחזירה 200                | `running`              |
| `starting`      | התהליך מסתיים לפני שנהיה תקין           | `error`                |
| `running`       | מתבצעת קריאה ל־`stop()`                 | `stopping` → `stopped` |
| `running`       | התהליך מסתיים באופן בלתי צפוי (< 5 שנ׳) | `error` (קריסה מהירה)  |
| `running`       | התהליך מסתיים באופן בלתי צפוי (> 5 שנ׳) | `error`                |
| `error`         | מתבצעת קריאה ל־`start()`                | `starting`             |
| כל מצב          | `stop()` בזמן `stopping`                | ללא פעולה              |

### נעילת פעולות

`ServiceSupervisor` מסדר פעולות של מחזור החיים באופן סדרתי באמצעות נעילת פעולות אסינכרונית
(`withLock()`). קריאות מקבילות ל־`start()` באותו מפקח מובילות ליצירת תהליך אחד
בדיוק; הקורא השני ממתין ומחזיר את המצב הקיים. כך נמנעים מצבי מרוץ כאשר,
לדוגמה, הפעלה אוטומטית וכפתור בממשק המשתמש מופעלים בו־זמנית.

## 4. התייחסות API

כל המסלולים מתחת `/api/services/` הם**LOCAL_ONLY** (לולאה-בק בלבד, כלל קשה מס' 17). בקשות ללא לולאה חוזרות מקבלים `403 LOCAL_ONLY` ללא קשר לאסימון אישור.

### 4.1 9נקודות קצה של נתב (11 מסלולים)

#### `POST /api/services/9router/install`

התקן את נתב 9 מ-npm. יוצר `DATA_DIR/services/9router/` עם `package.json` ו- `node_modules/` משלו. אינו מתנגש עם המחלקות של OmniRoute עצמו.

**גוף הבקשה** (הכל אופציונלי):

```json
{ "version": "latest" }
```

| שָׂדֶה    | סוּג     | בְּרִירַת מֶחדָל | תֵאוּר                       |
| --------- | -------- | ---------------- | ---------------------------- |
| `version` | `string` | `"latest"`       | תג גרסת npm או semver להתקנה |

**תגובות:**

**חיווט TPROXY :** `ensureSingboxTproxy()` (`src/mitm/tproxy/setup.ts`) כותב את `config.json` ומתחיל את המפקח לפני ש- `applyTproxy()` מתקין את כללי חומת האש TPROXY. אם המפקח חסר או לא מצליח להגיע ל- `running`, כעת הוא מתעד ברמת השגיאה (במקום לבלוע בשקט את הכשל) כך שמפעיל יכול לדעת שכללי TPROXY יושמו ללא מאזין עובד מאחוריהם.

### 4.9 פרוקסי הפוך (הטמעת לוח המחוונים של הנתב 9)

לוח המחוונים מטמיע את 9Router web UI בתוך iframe באמצעות פרוקסי הפוך פנימי בכתובת:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

פרוקסי זה:

- מעביר את הבקשה ל- `http://127.0.0.1:{port}/{path}` (לופ-בק בלבד)
- הסרת כותרות `cookie` ו- `authorization` נכנסות (ללא דליפה של הפעלת OmniRoute )
- מזריק `Authorization: Bearer {apiKey}` עבור אימות נתב 9
- מסיר מהתגובה `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*`
- משכתב תגובות HTML כדי להזריק `<base href>` ולנרמל נתיבים מוחלטים (`/foo` → `/dashboard/.../embed/foo`)

שדרוגי WebSocket עבור לוח המחוונים המוטבע מטופלים על ידי שרת נלווה ביציאה ייעודית (ראה `src/lib/services/embedWsProxy.ts`).

**בִּטָחוֹן:** מסלולי ההטמעה פרוקסי מסווגים תחת `LOCAL_ONLY_API_PREFIXES` וניתן להגיע אליהם רק דרך loopback. תוקף שמשיג JWT דרך מנהרת Cloudflare/Ngrok לא יכול לבצע פרוקסי לשירותים משובצים.

## 5. אבטחה

### אכיפת LOCAL_ONLY (כלל קשיח #17)

כל הנתיבים תחת `/api/services/` ו-`/dashboard/providers/services/*/embed/`
מסווגים כ-LOCAL_ONLY ב-`src/server/authz/routeGuard.ts`. בדיקת ה-loopback
מתבצעת ללא תנאי לפני כל ענף אימות:

```
הבקשה מגיעה
  → isLocalOnlyPath(path)?
      → לא-loopback → 403 LOCAL_ONLY (תמיד, לפני בדיקת האימות)
      → loopback    → המשך לאימות הרגיל
```

כך נמנע מ-JWT שדלף (למשל, דרך מנהרה) להפעיל `npm install` או
יצירת תהליכים. ראו `docs/security/ROUTE_GUARD_TIERS.md` למטריצת הרמות
המלאה.

### הזרקת מפתח API

‏9Router ו-Mux דורשים מפתח API/אסימון bearer עבור נקודות הקצה של HTTP שלהם.
OmniRoute:

1. יוצר מפתח באמצעות `crypto.randomBytes(32).toString("base64url")` עם
   קידומת ייעודית לשירות (`nr_` עבור 9Router,‏ `mx_` עבור Mux).
2. מצפין אותו במנוחה באמצעות AES-256-GCM (אותו צופן המשמש לפרטי הגישה של הספק).
3. מפענח ומזריק אותו כמשתנה סביבה בעת יצירת התהליך —
   `NINEROUTER_API_KEY` עבור 9Router,‏ `MUX_SERVER_AUTH_TOKEN` עבור Mux (לעולם לא כדגל CLI,
   כדי שהאסימון לא יופיע לעולם ב-`ps`/רשימות תהליכים).
4. לעולם אינו מחזיר את המפתח הגלוי בתגובת HTTP כלשהי.

CLIProxyAPI מקבל מפתח ייעודי למישור הנתונים, המוזרק בעת יצירת התהליך
(`needsApiKey: true` — משמש לסנכרון מודלים מול המתאם).

### הגנה מפני SSRF

פרוקסי ה-HTTP ההפוך (`/dashboard/.../embed/[...path]`) מוגדר באופן קשיח להעביר
רק אל `http://127.0.0.1:{port}`. הוא לעולם אינו עוקב אחר הפניות ליעדים
שאינם loopback. הספרייה `ssrf-req-filter` משמשת לדחיית כל כתובת URL של upstream
שנפתרת לכתובת מחוץ לטווח ה-loopback.

### בטיחות מעטפת (כלל קשיח #13)

`npm install` מופעל באמצעות `execFile('npm', ['install', pkg, '--prefix', dir])` —
ללא תבניות מחרוזת, ללא מעטפת וללא אינטרפולציה של נתיבים חיצוניים לתוך מחרוזת
הפקודה. ערכי זמן ריצה (יציאות, מפתחות API) מועברים דרך אובייקט ה-`env` של תהליך הבן.

### טיהור שגיאות (כלל קשיח #12)

כל תגובות השגיאה מ-`/api/services/*` עוברות דרך `buildErrorBody()` או
`sanitizeErrorMessage()`. הערכים הגולמיים של `err.stack` ו-`err.message` לעולם אינם מוחזרים
כלשונם למבצע הקריאה.

## 7. פתרון בעיות

### השירות אינו מופעל

**תסמינים:** לחצן ההפעלה מחזיר 503, והמצב נשאר `"error"` או `"starting"`.

**רשימת בדיקה:**

1. בדקו את `GET /api/services/{name}/logs` (או את חלונית היומנים בלוח הבקרה). חפשו
   שורות כמו `Error: ENOENT`,‏ `address already in use` או `Cannot find module`.
2. ודאו ש-`npm` נמצא ב-PATH: הריצו `which npm` מאותו חשבון משתמש שמפעיל את OmniRoute.
3. ודאו שהשירות מותקן: בדקו ב-`GET /api/services/{name}/status` את
   `installedVersion`. אם הערך הוא `null`, בצעו תחילה התקנה.
4. ודאו שהנתיב `DATA_DIR/services/{name}/node_modules/` קיים ואינו ריק.
5. בדקו את השדה `lastError` בתגובת הסטטוס כדי לראות את סיבת היציאה המסוננת.

### הפעלה קרה איטית (יותר מ-10 שניות עד להגעה ל-`running`)

**תסמינים:** המצב נשאר `"starting"` במשך זמן רב לפני שהוא משתנה ל-`"running"` או ל-`"error"`.

**הסבר:** ההפעלה הקרה של 9Router כוללת ייבוא של עצי תלויות גדולים (מודולי DNS,
מנהרה ו-MITM). מרווח ברירת המחדל לבדיקת תקינות הוא 2 שניות, עם 3 ניסיונות לפני
שהמפקח מכריז על פסק זמן (אך ממשיך לבצע תשאול).

**פתרון:** ניתן להגדיר את `healthIntervalMs` ואת פסק הזמן של `waitForHealthy`
(`healthIntervalMs * 3`) ב-`bootstrap.ts`. עבור שירותים שזמן ההפעלה שלהם ארוך יותר,
הגדילו את `healthIntervalMs` ל-5000 ואת `stopTimeoutMs` ל-30 000.

### התנגשות יציאות (`EADDRINUSE`)

**תסמינים:** ביומנים מופיע `address already in use :::20130`.

**גורמים:**

- תהליך אחר כבר משתמש ביציאה 20130.
- תהליך קודם של 9Router לא נעצר לחלוטין (PID זומבי).

**פתרון:**

1. שנו את יציאת ברירת המחדל באמצעות משתנה הסביבה `NINEROUTER_PORT` בקובץ `.env`.
2. אתרו וסיימו את התהליך המתנגש: `lsof -ti :20130 | xargs kill -9`.
3. ניתן להגדיר את היציאה לכל שירות בנפרד ב-`bootstrap.ts` באמצעות השדה `port`.

**הערה:** 9Router משתמש כברירת מחדל ביציאה 20130 במיוחד כדי למנוע התנגשות עם
יציאת ברירת המחדל 20128 של OmniRoute.

---

### ההרשאה נדחתה (EACCES) במהלך ההתקנה

**תסמינים:** ההתקנה מחזירה 500, וביומנים מופיע `EACCES` או `permission denied`.

**גורמים:**

- `DATA_DIR` או תיקיית האב שלה אינם ניתנים לכתיבה על ידי התהליך של OmniRoute.
- הפעלה בתוך Docker ללא הרשאות root וללא גישת כתיבה לאמצעי האחסון הממופה.

**פתרון:**

1. בדקו את `DATA_DIR` (ברירת מחדל: `~/.omniroute/`):‏ `ls -la ~/.omniroute/`
2. ודאו שמשתמש התהליך של OmniRoute הוא הבעלים של התיקייה: `chown -R $USER ~/.omniroute/`
3. ב-Docker, ודאו שלעיגון אמצעי האחסון יש את ההרשאות הנכונות עבור המשתמש בקונטיינר.

### העדכון נכשל (פסק זמן של `npm install` או שגיאת רשת)

**תסמינים:** העדכון מחזיר 500 עם `InstallError`, וביומנים מופיע פסק זמן של הרשת.

**רשימת בדיקה:**

3. נסו לבצע את ההתקנה ידנית: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. בסביבה מבודדת מהרשת, הורידו מראש את קובץ ה-tarball והשתמשו ב-`npm install /path/to/tarball.tgz`.

### השירות מציג מצב `"error"` מיד לאחר ההפעלה (קריסה מהירה)

**תסמינים:** המצב משתנה מ-`"starting"` ל-`"error"` בתוך פחות מ-5 שניות.

**רשימת בדיקה:**

3. עבור 9Router: ודאו ש-`NINEROUTER_DISABLE_MITM=true` ו-

## 8. שאלות נפוצות

**ש: האם ניתן לחשוף את נקודות הקצה של השירותים המוטמעים ללקוחות שאינם loopback?**

לא. רמת LOCAL_ONLY היא מכוונת (כלל קשיח מס' 17). נתיבים שיכולים להפעיל
`npm install` או ליצור תהליכי `node` אינם יכולים להיות נגישים מתעבורה שאינה loopback,
מכיוון ש-JWT שדלף דרך מנהרה (Cloudflare, Ngrok, Tailscale) היה מאפשר אחרת
יצירה שרירותית של תהליכים. אין החרגת ביטול עבור
`/api/services/` — בניגוד ל-`/api/mcp/`, הוא אינו נכלל ברשימת המעקפים של תחום הניהול.
ראו `docs/security/ROUTE_GUARD_TIERS.md`.

---

**ש: האם 9Router ו-CLIProxyAPI יהיו זמינים בפריסות ייצור/ענן?**

כן. שני השירותים פועלים לפי אותו מודל מקומי-תחילה כמו OmniRoute עצמו. הם פועלים
באותו מחשב ומתקשרים באמצעות loopback. "ייצור" כאן פירושו ה-VPS
או השרת המקומי שבו OmniRoute פרוס, ולא ספק ענן מרוחק.

---

**ש: כיצד ניתן לנפות שגיאות במפקח?**

1. עקבו אחר זרם יומני ה-SSE: `curl -N http://localhost:20128/api/services/9router/logs`.
2. בדקו את היומנים המובנים בפלט ה-pino של OmniRoute, המסוננים לפי
   מרחב השמות `service:supervisor`.
3. בדקו את הרשומה במסד הנתונים: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. השתמשו ב-`GET /api/services/9router/status` כדי לראות בקריאה אחת את המצב הפעיל הנוכחי, ה-PID, התקינות
   ו-`lastError`.

---

**ש: המפקח מציג `health: "degraded"` או `health: "unknown"`, אך המצב הוא `"running"`. האם זו בעיה?**

`"degraded"` פירושו שבדיקת התקינות החזירה תשובה שאינה 200. `"unknown"` פירושו שעדיין לא
הושלמה בדיקה (מצב תחרות עם התשאול הראשון). שני המצבים זמניים במהלך האתחול.
אם התקינות נשארת במצב `"degraded"` במשך יותר מ-`healthIntervalMs * 3` אלפיות שנייה לאחר
`"running"`, השירות המוטמע פועל, אך API ה-HTTP שלו אינו מגיב. בדקו
אם הפורט נכון בתגובת הסטטוס ואם השירות אכן
מאזין בפורט זה.

---

**ש: האם ניתן לשנות את מפתח ה-API של 9Router ללא הפעלה מחדש מלאה?**

לא. מפתח ה-API מועבר אל 9Router באמצעות משתנה סביבה בזמן יצירת התהליך.
לא ניתן לשנות משתני סביבה בתהליך פועל. `POST .../rotate-key`
עוצר ומפעיל מחדש את השירות באופן אוטומטי כדי להחיל את המפתח החדש. סבב המפתח
נכנס לתוקף בתוך `stopTimeoutMs` של השירות (ברירת המחדל היא 15 שניות), בתוספת זמן
האתחול שלו.

---

**ש: מהי מגבלת המאגר המעגלי ומה קורה כשהוא מתמלא?**

לכל שירות יש מאגר מעגלי ייעודי בגודל 5 MB. כאשר המאגר מלא, שורות
היומן הישנות ביותר מוסרות כדי לפנות מקום לחדשות. אירוע ה-SSE מסוג `snapshot` מחזיר
את השורות העדכניות ביותר במסגרת מגבלת `tail`. היומנים אינם נשמרים בדיסק, אלא אם
`logsBufferPath` מוגדר ברשומת מסד הנתונים.
