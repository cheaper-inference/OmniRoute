Komplett guide för att använda Codex CLI med OmniRoute som en OpenAI-kompatibel backend.

---

> **TOML är det enda formatet som fungerar.** Moderna Codex läser uteslutande
> `~/.codex/config.toml` (verifierat med codex-cli 0.147.0: `codex --help`
> dokumenterar att `-c/--config` åsidosätter inställningar som har ”lästs in från
> `~/.codex/config.toml`”). Den gamla `~/.codex/config.yaml` tillhörde den äldre
> npm-baserade CLI:n och ignoreras utan något meddelande. Kontrollpanelens generator
> (`/api/cli-tools/apply`, verktyget `codex`) skriver TOML med en försiktig
> sammanslagning — befintliga nycklar och andra providerblock bevaras, API-nyckeln
> ligger kvar i `OMNIROUTE_API_KEY` (aldrig i filen), och en kvarvarande äldre
> `config.yaml` rapporteras som en migreringsanmärkning utan att ändras.

## Färdig `config.toml` att klistra in

Ersätt `<YOUR_HOST>` och `<YOUR_KEY>` med dina värden:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # lagringsgräns i historiken per verktygsanrop

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc eller ~/.zshrc — det faktiska nyckelvärdet, aldrig i config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex som ingår i ChatGPT-appen

Om du installerade Codex via ChatGPT-skrivbordsappen kan den körbara filen
`codex` endast finnas i appaketet och ännu inte vara tillgänglig i skalets
`PATH`. Lägg till resurskatalogen i skalets startfil:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Öppna ett nytt skal och verifiera sedan:

```bash
command -v codex
codex --version
```

### Lokal OmniRoute utan autentisering: en platshållarnyckel räcker

Codex verifierar att miljövariabeln som anges av `env_key` finns
**innan** den första begäran lämnar CLI:n. Om din **lokala** OmniRoute-instans
inte kräver autentisering fungerar valfri icke-tom platshållare:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Använd i stället en riktig nyckel när OmniRoute-servern är skyddad eller fjärransluten.

> **Vanliga värdalternativ**
>
> | Åtkomst        | URL                           |
> | -------------- | ----------------------------- |
> | Lokalt nätverk | `http://192.168.0.1:20128/v1` |
> | Tailscale      | `http://100.x.x.x:20128/v1`   |
> | Loopback       | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — därför fungerar det för alla modeller

Codex CLI fasade ut `wire_api = "chat"` (Chat Completions) i februari 2026 och **kräver** nu `wire_api = "responses"` (OpenAI Responses API). Om `wire_api = "chat"` anges kraschar programmet omedelbart vid start sedan v0.138.

Många leverantörer, inklusive GLM och Kimi, erbjuder fortfarande endast en Chat Completions-slutpunkt. DeepSeek V4 erbjuder nu både ett inbyggt Responses API och en Anthropic-kompatibel slutpunkt. OmniRoute använder Responses som standard och låter varje DeepSeek-anslutning välja Anthropic-kompatibilitet.

**OmniRoute löser detta transparent:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute väljer leverantörens inbyggda protokoll och översätter vid behov
    → POST /responses (DeepSeek V4) eller /chat/completions (Mistral / GLM / Kimi / övriga)
```

Du behöver aldrig en separat översättningsproxy när du använder OmniRoute. **Alla modeller använder `wire_api = "responses"`** — OmniRoute hanterar resten.

> **`wire_api` är standardvärdet** — fältets standardvärde är `"responses"` och det kan utelämnas helt från `config.toml`. Ange det endast uttryckligen om du vill dokumentera avsikten.

## Kontextfönster och komprimering

### Fält för tokenkonfiguration

| Fält                             | Beskrivning                                                                                                                                                                                                                |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Total tokenbudget för den aktiva modellen. Ställ in den på modellens angivna gräns.                                                                                                                                        |
| `model_auto_compact_token_limit` | Tröskel som utlöser automatisk komprimering av historiken. **Maximalt: 90 % av `model_context_window`** — värden över 90 % ignoreras utan varning.                                                                         |
| `tool_output_token_limit`        | Begränsning av antalet token som lagras i historiken per utdata från verktygsanrop. Förhindrar att ett enda stort verktygssvar fyller fönstret. **Detta är inte maximal utdata** — det är en lagringsgräns för historiken. |
| `compact_prompt`                 | Infogad åsidosättning av systemprompten som används vid komprimering (v0.138+).                                                                                                                                            |

> **Anmärkning om `model_max_output_tokens`**: Det här fältet är **inte en del av konfigurationsschemat för Codex CLI** (det saknas i Codex Rust-kodbasen). Det ignoreras utan varning om det anges. Förlita dig inte på det — använd `tool_output_token_limit` för att styra hur mycket verktygsutdata som lagras i historiken.

## Modellprefix: `cx/`

Alla Codex-modeller i OmniRoute använder prefixet `cx/`:

| Codex CLI-namn          | OmniRoute-modell   |
| ----------------------- | ------------------ |
| `cx/gpt-5.5`            | GPT-5.5 standard   |
| `cx/gpt-5.4`            | GPT-5.4 standard   |
| `cx/gpt-5.4-mini`       | GPT-5.4 mini       |
| `cx/gpt-5.1-codex-mini` | GPT-5.1 Codex mini |

Andra leverantörer använder sina egna prefix (`kmc/`, `glm/`, `ds/`, `ollamacloud/`, `opencode-go/`, `mistral/`) — prefixet motsvarar leverantörens alias i OmniRoute.

## Resonemangsnivå

Styr hur mycket modellen ”tänker” innan den svarar.

| Värde    | Använd för                                       |
| -------- | ------------------------------------------------ |
| `none`   | Inget resonemang — direkt svar                   |
| `low`    | Enkla uppgifter (byt namn, formatera)            |
| `medium` | **Serverstandard** när inget anges               |
| `high`   | Medelsvåra uppgifter (refaktorering, felsökning) |
| `xhigh`  | Arkitektur, djupanalys, komplexa problem         |

```bash
# Åsidosätt per anrop
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Ange även en **sammanfattning** av resonemanget så att Desktop kan visa tanketext (inte bara krypterade blobbar):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # eller ultra när det stöds
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute-resonemangsbudget (serverinställning)

På OmniRoute-värden måste **Settings → AI → Thinking Budget** vara inställt på **`passthrough`** för att Codex resonemangsnivå/sammanfattning ska nå uppströmsleverantören. Läget **`auto` tar bort** alla `reasoning`- och `reasoning_effort`-fält från klienten och gör resonemangspanelerna tomma även när Codex är korrekt konfigurerat.

Fullständig guide: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Komprimering och promptcache är oberoende och fortsätter att fungera med `passthrough`.

## Profiler — namngivna konfigurationer per modell/arbetsflöde

Med profiler kan du byta modell + kontextfönster med en enda flagga. Varje profil är en platt
`~/.codex/<name>.config.toml` som läggs ovanpå den grundläggande `config.toml`.

> **Namngivningsregel (Codex CLI v0.137+):** filen måste vara `~/.codex/<name>.config.toml` — **utan prefixet `profile-`**.
> CLI:n tolkar `-p kimi-k27` som `~/.codex/kimi-k27.config.toml`. Om filen inte hittas används standardinställningen utan något meddelande.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # snabbt, billigt
```

```bash
codex -p low      # cx/gpt-5.5, nivå=low
```

## Generera profiler automatiskt med `omniroute setup-codex`

Om du kör OmniRoute på en VPS kan du automatiskt generera profilfiler från den aktuella modellkatalogen:

```bash
# Från en VPS (använder lokal OmniRoute på port 20128)
omniroute setup-codex

# Från valfri dator – ange adressen till din VPS
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Förhandsgranska utan att skriva filer
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Generera endast GLM- och Kimi-profiler
omniroute setup-codex --only glm,kimi

# Skriv till en anpassad katalog
omniroute setup-codex --codex-home /path/to/.codex
```

Kommandot hämtar `/v1/models`, använder finjusterade profiler för kända modeller, faller tillbaka på katalogmetadata för andra kompatibla textmodeller och skriver `~/.codex/<name>.config.toml` för varje modell. Det är idempotent och kan därför köras igen utan problem.

Om basfilen `config.toml` saknar en definition för `model_providers.omniroute` inkluderar en explicit körning av
`setup-codex` den definitionen i varje genererat överlägg, med den valda
lokala eller fjärranslutna slutpunkten. Basfilen lämnas oförändrad. En befintlig leverantörsdefinition
ärvs, inklusive dess slutpunkt och autentiseringsinställningar. Ogiltig
TOML i basfilen stoppar genereringen innan några profiler skrivs.

När du anger `--api-key` eller `OMNIROUTE_API_KEY` refererar en nyligen definierad leverantör till
`env_key = "OMNIROUTE_API_KEY"`; själva nyckeln sparas eller skrivs aldrig ut i
förhandsgranskningen. Ange den variabeln i miljön där du startar Codex. Om ingen
nyckel anges har den nya definitionen inget nyckelkrav, för en OmniRoute-instans
som är konfigurerad för att acceptera oautentiserade förfrågningar.

Den valfria automatiska katalogsynkroniseringen som beskrivs nedan bevarar leverantörsdefinitioner som redan
finns i ett överlägg, men initierar inga nya leverantörsinställningar; konfigurera leverantören
först genom en explicit konfiguration eller instrumentpanelen. Befintliga leverantörsinställningar utelämnas
från förhandsgranskningar eftersom de kan innehålla operatörshanterade autentiseringsuppgifter.

OmniRoute kan även **automatiskt synkronisera** samma profilfiler efter att en lyckad identifiering/import av leverantörsmodeller har ändrat den aktuella katalogen. Funktionen är **valfri och inaktiverad som standard**: aktivera den från **CLI Code-instrumentpanelen** ("CLI profile auto-sync" → Codex), eller ange `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (den respekterar även `CLI_ALLOW_CONFIG_WRITES`, som är aktiverad som standard). När funktionen är aktiverad skriver den endast separata profilfiler i `~/.codex/*.config.toml`; den ändrar aldrig den aktiva/standardmässiga `~/.codex/config.toml`, Codex-lb-inställningar, autentisering eller leverantörsval.

Kontrollerar hälsostatusen för din OmniRoute-instans innan Codex startas:

```bash
# Starta mot lokal OmniRoute (standardport 20128)
omniroute launch-codex

# Starta med en specifik profil
omniroute launch-codex --profile kimi-k27

# Starta mot en fjärr-VPS
omniroute launch-codex --remote http://100.x.x.x:20128/v1 --api-key sk-xxx

omniroute launch-codex --profile glm52 -- --yolo "fix this bug"
```

(`bin/cli/cli-manifest.mjs`):

```bash

omniroute configure codex

# Starta codex med omniroute-leverantören injicerad via -c-flaggor (ingen konfiguration skrivs)
omniroute run codex
```

## Långvariga uppgifter

Två OmniRoute standardinställningar kan tyst sabotera flertimmars Codex CLI sessioner. Inte heller är en Codex CLI inställning — båda live på OmniRoute sidan. Användare som migrerar en konfiguration från uppströmsproxyer som fäster konton och inaktiverar inaktiva cutoffs träffar ofta båda och drar slutsatsen OmniRoute "inte kan upprätthålla en lång session."

| Symptom                                                                                   | Trolig orsak                                                                   | Knopp                    |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------ |
| Sessionen fortsätter att byta konto / prompt-cache-kontinuitet går förlorad mellan varven | Sessionsaffinitet TTL är `0` (inaktiverad)                                     | `sessionAffinityTtlMs`   |
| Anslutningen dör halvvägs utan någon kundvändande prompt                                  | Strömmens inaktiva vakthund avfyrades efter 10 minuter utan någon uppströmsbit | `STREAM_IDLE_TIMEOUT_MS` |

Relaterade diskussioner: [#7126](https://github.com/cheaper-inference/OmniRoute/discussions/7126) (långa uppgifter släpps), [#5718](https://github.com/cheaper-inference/OmniRoute/discussions/5718) (varför affinitet förinställs som standard). Spårning: [#7287](https://github.com/cheaper-inference/OmniRoute/issues/7287).

### 1. Sessionsaffinitet — fäst en konversation till ett konto

**Standard:** `sessionAffinityTtlMs = 0` (inaktiverad).

**Var den ska ställas in**

- Instrumentbräda →** Inställningar → Routing** →** Sessionsaffinitet** →** Affinitet TTL (sekunder)** (`ComboDefaultsTab`)
- Eller PATCH inställningar med `sessionAffinityTtlMs` in** millisekunder** (Zod range `0`–`86_400_000`, dvs upp till 24 timmar)

> Omdöpt i #7274 från Codex-only `codexSessionAffinityTtlMs`. Den äldre nyckeln accepteras fortfarande som ett skrivskyddat alias; nya konfigurationer bör använda `sessionAffinityTtlMs`. Affinitet gäller nu** några** leverantör när TTL är över `0`, inte bara Codex — se [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Sessionsaffinitet.

**Vad går sönder när den stannar på 0**

Varje sväng i en Codex konversation med flera svängar dirigeras oberoende av den aktiva kombinationsstrategin och kan landa på en** olika konto per tur** . Det bryter uppströms session / prompt-cache-kontinuitet. OmniRoute konsulterar endast Codex -sessionsrubriker (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) och kroppsfält som `prompt_cache_key` / `session_id` när TTL är större än `0` (`extractSessionAffinityKey` i `src/sse/services/auth.ts`).

**Rekommenderas för en enskild uppgift på flera timmar**

Ställ in TTL** över den förväntade väggklockans längd för uppgiften** (UI max är** 86400 sekunder** = 24 timmar):

| Förväntad uppgiftslängd | Affinitet TTL (UI, sekunder) | `sessionAffinityTtlMs` |
| ----------------------- | ---------------------------- | ---------------------- |
| Några timmar            | `14400` (4h)                 | `14400000`             |
| Övernattning / ~ 12h    | `43200` (12h)                | `43200000`             |
| Hel dag                 | `86400` (24h, max)           | `86400000`             |

Valet är avsiktligt: att inaktivera affinitet gynnar belastningsbalansering mellan konton; att möjliggöra det gynnar kontinuitet för en lång agentsession. Det gör den här guiden** inte** ändra standard — operatörer som kör långa Codex uppgifter måste välja in.

### 2. Stream inaktiv timeout — dödar inte tysta resonemangsvängar

**Standard:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 minuter). Den ärver från `REQUEST_TIMEOUT_MS` när den inte är inställd; den delade baslinjen är också 600000. Se [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Timeouts.

**Vad som går sönder vid standard**

Ett Codex resonemang / verktygsväng som förblir tyst i mer än 10 minuter med** ingen riktig uppströmsbit** tvångsstängs av SSE tomgångsvakthunden (`open-sse/utils/stream.ts`). Klienten ser ofta en blottad anslutning släppa — matchning "stoppad automatiskt utan något meddelande."

Kritisk detalj: OmniRoute syntetiska SSE** hjärtslag återställs inte** den vilande klockan. Endast en riktig uppströms kroppsbit uppdaterar `lastChunkTime`. En tyst modell som fortfarande "tänker" ser identisk ut med en avstannad uppströms ur vakthundens synvinkel.

Relaterad Undici-kroppsinaktivitet: `FETCH_BODY_TIMEOUT_MS` (ställer också in på samma 10-minutersbaslinje; `0` inaktiverar den). För streaming täcker `FETCH_TIMEOUT_MS` endast anslutningsinställningar / första rubriker — när strömmen är aktiv, styrs stalls av `STREAM_IDLE_TIMEOUT_MS` och `FETCH_BODY_TIMEOUT_MS`.

**Rekommenderas för en enskild uppgift på flera timmar**

I OmniRoute -processmiljön (`.env` / compose / systemd):

```bash
# Disable stream idle + body inactivity cutoffs for long reasoning turns
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Eller höj dem över det längsta tysta gapet du förväntar dig (värdena är millisekunder):

```bash
# Example: allow up to 2 hours of silence between upstream chunks
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Starta om OmniRoute efter att ha ändrat dessa env vars.

### Konkret recept — flertimmars Codex uppgift

1. **Fäst kontot:** Dashboard → Inställningar → Routing → Sessionsaffinitet → Affinitet TTL = `43200` (12h) eller `86400` (24h max).
2. **Höj/inaktivera tomgångsavstängningar** i OmniRoute miljö:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Behåll de vanliga Codex `config.toml` (`wire_api = "responses"`, correct `base_url`, `OMNIROUTE_API_KEY`) — inga affinity/idle rattar på Codex-sidan finns för dessa två beteenden.
4. Starta om OmniRoute och starta sedan den långa Codex uppgiften.

### Standardbeslut (#7287)

| Knopp                    | Skicka standard   | Ändra i den här guiden?                                                                              |
| ------------------------ | ----------------- | ---------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (av)          | **Inga** — förblir opt-in (lastbalansering kontra kontinuitet; se diskussion #5718)                  |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min) | **Inga** — återstår 10 minuter för allmän trafik; långa Codex operatorer höjer eller inaktiverar den |

Att vända på antingen standard globalt skulle ändra beteendet för varje klient i en instans, inte bara Codex. Dokumentera knopparna; lämna standardinställningarna i fred tills ett uttryckligt operatörsbeslut säger något annat.

### Diagnostisera tomgångsskärningar

När den lediga vakthunden skjuter loggar OmniRoute en linje formad som:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Grep för `Idle timeout: no data from` (eller koden `stream_idle_timeout` / felnamn `StreamIdleTimeoutError`). Providersegmentet är vilken OmniRoute som helst som används för den begäran (`codex`, en annan leverantörs-id eller `provider` om okänd) — det är inte alltid den bokstavliga strängen `codex`.

## Felsökning

**`Error: wire_api = "chat" is no longer supported`** Ta bort `wire_api = "chat"` från din konfiguration. Ställ in `wire_api = "responses"` eller utelämna fältet (standard är `"responses"` sedan v0.138).

**`Error: model not found`** Kontrollera att modellen finns i OmniRoute med rätt prefix. Använd `omniroute models list` eller öppna `/dashboard/providers/<provider>`.

**`Authentication error`** Bekräfta att `OMNIROUTE_API_KEY` exporteras: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`** Codex validerar att env var existerar innan den första begäran görs. Exportera en riktig nyckel för skyddade servrar, eller en icke-tom platshållare som `OMNIROUTE_API_KEY=local` när din** lokal** OmniRoute instansen kräver inte auth. Starta om skalet om du lagt till det i `~/.bashrc` eller `~/.zshrc`.

**`Connection refused`** Kontrollera OmniRoute körs och att `base_url` host/port är korrekt för ditt nätverk (lokal vs Tailscale vs VPS).

**Session kraschar nära kontextgränsen** Ställ in `model_context_window` och `model_auto_compact_token_limit` explicit. Se kontextfönstret ovan.

**Packning bränder för sent** Sänk `model_auto_compact_token_limit` till 80–85 % av fönstret. Sätt aldrig över 90 %.

**Profilen laddas inte (`-p <name>` ignoreras tyst)** Bekräfta att filen finns på `~/.codex/<name>.config.toml` (inget `profile-` prefix). Kör `ls ~/.codex/*.config.toml`.

**Lång Codex uppgift sjunker i mitten av körningen / växlar konto mellan varven** Se [Långvariga uppgifter](#long-running-tasks). Aktivera sessionsaffinitet (TTL över uppgiftslängden) och höj eller inaktivera `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. Grep OmniRoute -loggar för `Idle timeout: no data from`.
