> **Πηγή αλήθειας:** `src/lib/db/reasoningCache.ts`, `open-sse/services/reasoningCache.ts`** Τελευταία ενημέρωση:** 2026-06-28 — v3.8.40

OmniRoute καταγράφει τον βοηθό `reasoning_content` που παράγεται από μοντέλα με λειτουργία σκέψης και τον επαναλαμβάνει με διαφάνεια σε αιτήματα πολλαπλών στροφών όταν το απαιτεί ο πάροχος ανάντη. Αυτό εξαλείφει τα σφάλματα HTTP 400 που εγείρουν οι αυστηροί πάροχοι όταν το ιστορικό συνομιλιών ενός πελάτη λείπει το σκεπτικό της προηγούμενης σειράς.

## Γιατί υπάρχει αυτό

Αρκετοί πάροχοι τρόπου σκέψης απορρίπτουν μια σειρά παρακολούθησης, εκτός εάν το** Το προηγούμενο μήνυμα βοηθού περιλαμβάνει το αρχικό `reasoning_content`** . Το upstream επιστρέφει 400 με μηνύματα όπως:

```
Param Incorrect: The reasoning_content in the thinking mode must be passed back to the API.
```

Αλλά οι τυπικοί πελάτες (Cursor, Cline, Roo Code, OpenAI SDK) αφαιρούν `reasoning_content` από το ιστορικό που αναπαράγουν. OmniRoute το επαναφέρει από μια κρυφή μνήμη διακομιστή, έτσι ώστε το αίτημα που βλέπει το upstream να είναι συνεπές. Το τεύχος #1628 εισήγαγε την υβριδική επιμονή memory/SQLite έτσι ώστε η κρυφή μνήμη να επιβιώνει από την επανεκκίνηση της διαδικασίας.

## Αρχιτεκτονική

```
Turn N (assistant generates):
  → response contains reasoning_content + tool_calls
  → if requiresReasoningReplay(provider, model): cacheReasoningFromAssistantMessage()
      writes (memory + DB), one entry per tool_call.id within the request scope
  → forward response to client (which may or may not retain reasoning)

Turn N+1 (client sends follow-up):
  → translator detects: requiresReasoningReplay(provider, model) === true
  → for each assistant message with tool_calls and no reasoning_content:
      lookupReasoning(buildToolCallCacheKey(scope, toolCalls[0].id)) → memory → DB
      hit  → msg.reasoning_content = cached; recordReplay()
      miss → msg.reasoning_content = "" (legacy fallback for older DeepSeek)
  → upstream sees consistent history → no 400
```

Η λήψη γίνεται σε `open-sse/handlers/chatCore.ts` (δύο τοποθεσίες, στις δύο τοποθεσίες κλήσης `cacheReasoningFromAssistantMessage` ). Η επανάληψη γίνεται στο `open-sse/translator/index.ts` μετά από εξαναγκασμό σχήματος αλλά πριν από την αποστολή.

Οι καταχωρήσεις κλήσης εργαλείου αποθηκεύονται στο `buildToolCallCacheKey()`, μια σύνοψη του εύρους αιτήματος και του αναγνωριστικού κλήσης εργαλείου, επομένως το ίδιο αναγνωριστικό που χρησιμοποιείται από άλλο κλειδί ή περίοδο λειτουργίας API δεν επιλέγει την καταχώρηση. Το εύρος προέρχεται από `buildReasoningCacheScope()`: το αναγνωριστικό κλειδιού API, συν το κλειδί συνεδρίας όταν το αίτημα έχει ένα. Επομένως, η στήλη `tool_call_id` και ο πίνακας εργαλείων εμφανίζουν αυτήν τη σύνοψη για αυτές τις καταχωρίσεις.

Οι απλές στροφές βοηθού (χωρίς εργαλειακή κλήση) πληκτρολογούνται διαφορετικά: `buildAssistantMessageCacheKey()` αφομοιώνει το εύρος της περιόδου λειτουργίας συν την κανονικοποιημένη μεταγραφή σε μορφή OpenAI μέχρι εκείνη τη στροφή, επειδή DeepSeek απαιτεί τη συλλογιστική της _κάθε_ προηγούμενης στροφής όταν υπάρχει `tools`. Για τους στόχους Responses-API (για παράδειγμα `opencode-go/deepseek-v4-flash`, δρομολογημένο σε `/responses`) το upstream body φέρει `input`, όχι `messages`, επομένως `translateRequest()` (`open-sse/translator/index.ts`) αναφέρει τη συγκεντρωτική μεταγραφή που αφομοιώθηκε μέσω μιας επιλογής επανάκλησης και οι ιστότοποι λήψης χωνεύουν την ίδια μεταγραφή. Το πάσο επανάληψης Responses εκτελείται στον άξονα OpenAI για κάθε μορφή πηγής, επομένως οι πελάτες μηνυμάτων Anthropic (Claude → OpenAI → Responses) αναπαράγονται επίσης.

## Αποθήκευση — Hybrid Memory + SQLite

Η hot διαδρομή χρησιμοποιεί ένα `Map` στη μνήμη (LRU-by-creation) που υποστηρίζεται από έναν πίνακα SQLite για ανάκτηση σφαλμάτων και ορατότητα πίνακα εργαλείων.

| Στρώμα | Εκτέλεση                                       | Σκοπός                                             |
| ------ | ---------------------------------------------- | -------------------------------------------------- |
| Μνήμη  | `Map` σε `open-sse/services/reasoningCache.ts` | Γρήγορες αναζητήσεις, έξωση ο μεγαλύτερος στα 200  |
| DB     | τραπέζι `reasoning_cache` (`src/lib/db/`)      | Επιμένει στις επανεκκινήσεις, οδηγεί τα στατιστικά |

Τα γραπτά πηγαίνουν και στα δύο. Οι αναγνώσεις συμβουλεύονται τη μνήμη πρώτα και μετά επιστρέφουν στο DB (οι επιτυχίες DB προωθούνται ξανά στη μνήμη). Οι αποτυχίες DB δεν είναι μοιραίες — η κρυφή μνήμη της μνήμης συνεχίζει να εξυπηρετεί την hot διαδρομή.

**Προεπιλογές:**

- TTL: `2h` (`TTL_MS = 2 * 60 * 60 * 1000`)
- Μέγιστες καταχωρήσεις μνήμης: `200` (`MAX_MEMORY_ENTRIES`)
- Έξωση: πρώτα το παλαιότερο `createdAt`

## Σχήμα βάσης δεδομένων

Μετανάστευση: `src/lib/db/migrations/033_create_reasoning_cache.sql`

```sql
CREATE TABLE IF NOT EXISTS reasoning_cache (
  tool_call_id   TEXT PRIMARY KEY,
  provider       TEXT NOT NULL,
  model          TEXT NOT NULL,
  reasoning      TEXT NOT NULL,
  char_count     INTEGER NOT NULL DEFAULT 0,
  created_at     TEXT NOT NULL DEFAULT (datetime('now')),
  expires_at     INTEGER NOT NULL
);
```

Ευρετήρια: `expires_at`, `provider`, `model`, `created_at`. `expires_at` αποθηκεύεται ως δευτερόλεπτα εποχής Unix. το επίπεδο SELECT κανονικοποιεί τις τιμές κειμένου παλαιού τύπου μέσω `EXPIRES_AT_EPOCH_SQL`.

## Λειτουργικές Σημειώσεις

- **Εκκαθάριση:** `cleanupReasoningCache()` εκκαθαρίζει τις καταχωρήσεις μνήμης που έχουν λήξει και εκτελεί `DELETE FROM reasoning_cache WHERE expires_at <= unixepoch('now')`. Οι υπάλληλοι του υγειονομικού ελέγχου καλούν αυτό περιοδικά.
- **Ανάκτηση σύγκρουσης:** Μετά από επανεκκίνηση, η μνήμη είναι άδεια, αλλά το DB εξακολουθεί να διατηρεί καταχωρήσεις που δεν έχουν λήξει. Η πρώτη αναζήτηση για ένα δεδομένο `tool_call_id` είναι ένα χτύπημα DB. Οι επόμενες αναζητήσεις είναι επιτυχίες μνήμης.
- **Χωρίς συλλογισμό, χωρίς κρυφή μνήμη:** `cacheReasoningFromAssistantMessage` επιστρέφει `0` όταν το μήνυμα του βοηθού δεν έχει πεδίο `reasoning_content` / `reasoning`, επομένως οι μη σκεπτόμενες απαντήσεις δεν κοστίζουν τίποτα.
- **Το γράψιμο είναι επίσης περιφραγμένο:** Και οι δύο τοποθεσίες κλήσεων στο `chatCore.ts` (χωρίς ροή και ροή) καλούν μόνο `cacheReasoningFromAssistantMessage()` όταν `requiresReasoningReplay(provider, model)` είναι `true` — το ίδιο κατηγόρημα ελέγχει την πλευρά ανάγνωσης. Οι εγκαταστάσεις που δεν αγγίζουν ποτέ έναν πάροχο επανάληψης σταματούν να πληρώνουν για την εγγραφή, την ενημέρωση ευρετηρίου και το try/catch σε κάθε απάντηση που φέρει αιτιολογία.
- **Μη αυστηροί πάροχοι:** Όταν `requiresReasoningReplay` είναι `false` και η μορφή προορισμού είναι OpenAI, ο μεταφραστής** λωρίδες** οποιοδήποτε πεδίο `reasoning_content` από εξερχόμενα μηνύματα — OpenAI Ολοκληρώσεις συνομιλίας δεν το δέχεται.

## Muse Αδιαφανής-Συλλογισμός Ιδιοκτησία

Το Muse (`muse-code`) επιστρέφει αδιαφανή συλλογισμό συνδεδεμένο με τον καλούντα (`encrypted_content`). Η επανάληψη της αναπαραγωγής με διαφορετικό λογαριασμό ή διαπιστευτήριο που υπενθύμισε αποτυγχάνει στην ανάντη, επομένως τα εγγενή αιτήματα OAuth χρησιμοποιούν ιδιοκτησία σε επίπεδο περιόδου σύνδεσης αντί για εναλλαγή ανά αίτημα (`src/sse/services/museSessionOwnership.ts`, επιβάλλεται σε `src/sse/handlers/chat.ts`). Οι ρητά επιλεγμένες συνδέσεις κλειδιού API και οι διαμορφώσεις μόνο με κλειδί API διατηρούν την υπάρχουσα δρομολόγηση χωρίς αυτήν τη λειτουργία ιδιοκτησίας.

- Παρέχετε μια σταθερή συνεδρία ID σε κάθε στροφή: `x-omniroute-session-id`, `x-omniroute-session`, `x-session-id` ή `x-codex-session-id`; εναλλακτικά χρησιμοποιήστε `prompt_cache_key`, `session_id`, `conversation_id` ή `metadata.session_id` στο σώμα (με αυτή τη σειρά προτεραιότητας). Λείπει ή είναι κενό IDs επιστροφή 400 όταν δύο ή περισσότεροι εγγενείς λογαριασμοί OAuth είναι ενεργοί. με έναν μόνο λογαριασμό OAuth δεν υπάρχει τίποτα για εναλλαγή, επομένως ένα τέτοιο αίτημα συνεχίζει να ξεκαρφιτσώνεται η δρομολόγηση. Το εύρος περιλαμβάνει το κλειδί OmniRoute API του καλούντος ID.
- Οι νέες ανεξάρτητες περίοδοι σύνδεσης κυκλοφόρησαν σε όλους τους ενεργούς εγγενείς λογαριασμούς OAuth που επιτρέπονται από την πολιτική σύνδεσης κλειδιού API, κατά σειρά σύνδεσης ID. Το Round-robin παρακάμπτει λογαριασμούς στο cooldown σύνδεσης, με κατάσταση τερματικού (`banned`, `expired`, `credits_exhausted`) ή κλειδωμένο μοντέλο για το ζητούμενο μοντέλο. Οι αποτυχίες του Muse upstream καταγράφουν το cooldown και την κατάσταση διακοπής όπως και άλλοι πάροχοι. Μια ρητά αναγκαστική σύνδεση παρακάμπτει το round-robin για μια νέα περίοδο λειτουργίας, αλλά δεν μπορεί να παρακάμψει έναν υπάρχοντα κάτοχο.
- Μέχρι ο κάτοχος να εμφανίσει μια επιτυχημένη απόκριση, μια περίοδος σύνδεσης της οποίας ο κάτοχος δεν είναι διαθέσιμος διεκδικείται εκ νέου σε έναν υγιή λογαριασμό. Μετά την πρώτη επιτυχημένη απόκριση, η περίοδος σύνδεσης παραμένει καρφιτσωμένη σε αυτόν τον κάτοχο έως ότου παραμείνει αδρανής για 30 ημέρες (`MUSE_SESSION_IDLE_TTL_MS`).
- Κάθε στροφή συνέχειας και αποτελέσματος εργαλείου παραμένει καρφιτσωμένη στον κάτοχο της περιόδου σύνδεσης: σύνδεση, ταυτότητα λογαριασμού και δημιουργία διαπιστευτηρίων συμπερασμάτων, ελέγχονται ξανά πριν από προσπάθειες ανάντη, συμπεριλαμβανομένων των επαναλήψεων ανανέωσης διαπιστευτηρίων. Οι απαντήσεις καλούν αναφορές IDs/item και το εργαλείο Ολοκληρώσεις συνομιλίας-κλήση IDs πρέπει να έχουν καταγραφεί για αυτήν την περίοδο σύνδεσης και τη δημιουργία.
- Οι εγγραφές SQLite `key_value` στον χώρο ονομάτων `muse_session_ownership` (`src/lib/db/museSessionOwnership.ts`) εξακολουθούν να είναι ιδιοκτησία και ο δρομέας περιστροφής κατά τις επανεκκινήσεις. Κάθε απάντηση αξίωσης και προβολής ανανεώνει τη σφραγίδα δραστηριότητας της περιόδου σύνδεσης. μια περίοδος αδράνειας μεγαλύτερης διάρκειας από `MUSE_SESSION_IDLE_TTL_MS` κλαδεύεται (καρφίτσα κατόχου, σημαία σερβιρίσματος και κατακερματισμένοι κατακερματισμοί opaque/reference ), το πολύ μία φορά κάθε 10 λεπτά και σε περιορισμένες παρτίδες, επομένως μια μεταγενέστερη επανάληψη του ιστορικού της αποτυγχάνει να κλείσει ως άγνωστος κάτοχος. Οι εγγραφές περιέχουν IDs σύνδεσης και κατακερματισμούς ταυτότητας λογαριασμού, διαπιστευτήρια, αδιαφανές περιεχόμενο και αναφορές συνέχειας, όχι μυστικά ή ιστορικό συνομιλιών. Οι πελάτες πρέπει να διατηρούν και να αποστέλλουν το πλήρες ιστορικό και το αδιαφανές σκεπτικό τους.
- Η άγνωστη ή ξένη αδιαφανής συλλογιστική, ένας κάτοχος που λείπει, ένας μη διαθέσιμος λογαριασμός κατόχου ή μια αλλαγή γενιάς με καταγεγραμμένο ιστορικό αποτυγχάνει να κλείσει με μια ρητή ανακατεύθυνση μεταξύ λογαριασμών 4xx/503 — ποτέ σιωπηλή και ποτέ μη συλλογιστική.
- Ένα κλειδί ίδιου λογαριασμού που υπενθύμισε υιοθετείται μόνο όταν η περίοδος λειτουργίας δεν κατέγραψε ιστορικό με δυνατότητα επανάληψης αναπαραγωγής. Οι καταγεγραμμένες συνεδρίες συνεχίζουν να αποτυγχάνουν κλειστές έως ότου ξεκινήσουν νέες.
- Μια κενή απόκριση ανάντη (`upstream_empty_response` / `empty_response`, τίποτα δεν εκπέμπεται στον καλούντα) δοκιμάζεται ξανά το πολύ δύο φορές στον ίδιο κάτοχο, μετά από 0,5 δευτ. και μετά 1,5 δευτ. (`MUSE_EMPTY_RESPONSE_RETRY_DELAYS_MS`). Εάν όλες οι προσπάθειες είναι κενές, το αρχικό 502 επιστρέφεται χωρίς σήμανση ψύξης ή διακοπής, οπότε μια ξεφλουδισμένη απάντηση δεν κλειδώνει ποτέ τον ιδιοκτήτη.
- Όλα τα αιτήματα `muse-code` παρακάμπτουν τις αναγνώσεις και τις εγγραφές στη σημασιολογική κρυφή μνήμη, συμπεριλαμβανομένων των εγγραφών ροής, επομένως η αδιαφανής έξοδος στην κρυφή μνήμη δεν μπορεί να αποκτήσει διαφορετικό κάτοχο περιόδου λειτουργίας.
