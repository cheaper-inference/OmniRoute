Το OmniRoute δημοσιεύει τεχνουργήματα npm + Docker. Αυτές οι πύλες παρέχουν προέλευση,
απογραφή (SBOM) και σάρωση CVE, όλα OSS, ενσωματωμένα στις ροές εργασίας κυκλοφορίας.
**Πρώτα η συμβουλευτική** στάση — αναφέρουν τώρα, προωθούν σε αποκλεισμό μετά την 1η
πράσινη κυκλοφορία.

| Πύλη                 | Εργαλείο                                       | Πού                               | Αποκλείει;                    | Έξοδος                                        |
| -------------------- | ---------------------------------------------- | --------------------------------- | ----------------------------- | --------------------------------------------- |
| Προέλευση SLSA (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`                 | μόνο αν αποτύχει η δημοσίευση | σήμα npmjs / `npm audit signatures`           |
| SBOM npm             | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`                 | μόνο αν αποτύχει η δημιουργία | Στοιχείο κυκλοφορίας + τεχνούργημα            |
| SBOM εικόνας         | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (συγχώνευση) | συμβουλευτική                 | Τεχνούργημα CycloneDX                         |
| Trivy CVE (SARIF)    | `aquasecurity/trivy-action`                    | `docker-publish.yml` (συγχώνευση) | συμβουλευτική                 | SARIF (HIGH+CRITICAL) → Καρτέλα Ασφάλειας     |
| Πύλη Trivy CRITICAL  | `aquasecurity/trivy-action`                    | `docker-publish.yml` (συγχώνευση) | **αποκλεισμός**               | `exit-code: '1'` σε διορθώσιμο CRITICAL       |
| osv vulnCount        | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`)     | **αποκλεισμός**               | αυξάνει `metrics.vulnCount` (κατεύθυνση:κάτω) |
| OpenSSF Scorecard    | `ossf/scorecard-action`                        | `scorecard.yml` (cron)            | συμβουλευτική                 | SARIF → Ασφάλεια + σήμα                       |

Η αύξηση CVE της εικόνας χρησιμοποιεί **δύο βήματα** στο `docker-publish.yml`: το βήμα SARIF
(`HIGH,CRITICAL`, `exit-code: 0`) διατηρεί τα HIGH+CRITICAL ορατά στην καρτέλα Ασφάλειας
χωρίς αποκλεισμό. Το βήμα _CRITICAL gate_ (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) αποτυγχάνει την κυκλοφορία σε ένα CRITICAL CVE **με διαθέσιμη διόρθωση**. Το `ignore-unfixed`
αποτρέπει τον αποκλεισμό της κυκλοφορίας για ένα CVE βασικής εικόνας χωρίς upstream patch.

## ⚠️ Διακύμανση CVE (αποκλεισμός πυλών osv/Trivy)

Τα osv και Trivy συγκρίνουν εξαρτήσεις με βάσεις δεδομένων CVE που **συνεχώς αυξάνονται**. Ένα PR
που **δεν αγγίζει εξαρτήσεις** μπορεί ξαφνικά να γίνει κόκκινο επειδή ένα νέο CVE αποκαλύφθηκε
σε μια υπάρχουσα εξάρτηση (osv: μετρημένο `vulnCount` > βασική γραμμή· Trivy: ένα νέο
διορθώσιμο CRITICAL στην εικόνα). **Αυτή είναι η ΑΝΑΜΕΝΟΜΕΝΗ λειτουργική συμπεριφορά μιας πύλης
αποκλεισμού CVE, όχι μια παλινδρόμηση προϊόντος.**

Όταν το osv ή το Trivy γίνουν κόκκινα λόγω ενός πρόσφατα αποκαλυφθέντος CVE, η λύση είναι:

1. **Αναβάθμιση της επηρεαζόμενης εξάρτησης** (προτιμότερο) — αναβάθμιση στην διορθωμένη έκδοση μέσω `package.json`
   `overrides` (μεταβατικές εξαρτήσεις) ή αναδημιουργία της εικόνας σε μια διορθωμένη βάση.
2. **Εάν δεν υπάρχει upstream διόρθωση:**
   - **osv:** επαναφορά της βασικής γραμμής `metrics.vulnCount` στο `config/quality/quality-baseline.json`
     (το `npm run quality:ratchet -- --update` δεν καλύπτει αποκλειστικές πύλες — επεξεργαστείτε την τιμή με
     το χέρι, `direction:down`) με μια σημείωση αιτιολόγησης + θέμα παρακολούθησης.
   - **Trivy:** προσθέστε μια καταχώριση στο `.trivyignore` (CVE-ID ανά γραμμή) με ένα σχόλιο
     αιτιολόγησης + θέμα παρακολούθησης. Το `ignore-unfixed: true` καλύπτει ήδη αυτόματα τα CVE χωρίς
     patches.

Και οι δύο πύλες **παρακάμπτουν ομαλά** (exit 0) όταν το εργαλείο απουσιάζει ή η μέτρηση
αποτυγχάνει (osv-scanner όχι στο PATH, osv.dev/δίκτυο μη προσβάσιμο, μη έγκυρο JSON) — μια
αποτυχία **μέτρησης** ποτέ δεν αποκλείει, μόνο μια **μετρημένη** παλινδρόμηση αποκλείει.

## Κίνδυνος από καταργημένη εξάρτηση

Το ριζικό lockfile δεν περιλαμβάνει πλέον το `extract-zip` ούτε κάποια ακμή εξάρτησης προς αυτό μετά
την αναβάθμιση του καρφιτσωμένου εργαλείου ανάπτυξης promptfoo. Με αυτόν τον τρόπο καταργείται η προηγουμένως αποδεκτή
αλυσίδα `promptfoo` → `@openai/codex-security` → `extract-zip` που παρακολουθείται στο #14482.
Οι έλεγχοι παλινδρόμησης στο `tests/unit/extract-zip-14482-exposure.test.ts` απορρίπτουν την
επανεισαγωγή της και διατηρούν την απαγόρευση εισαγωγών από κώδικα παραγωγής.

Η τρέχουσα επιδιόρθωση εξαρτήσεων περιορίζει επίσης τις παρακάμψεις συμβατότητας στον
πελάτη MSAL της Azure identity, στον πελάτη FTP του get-uri και στην εξάρτηση Zod του OpenCode v1 SDK. Η απόκτηση
διακριτικών Azure και η ανάκτηση μέσω FTP δοκιμάζονται με ελεγχόμενα επίπεδα μεταφοράς· και τα δύο πακέτα OpenCode
εκτελούν τις δικές τους σουίτες μεταγλώττισης και δοκιμών. Οι καταμετρήσεις ειδοποιήσεων ασφαλείας του μητρώου αποτελούν μετρήσεις
σε μια δεδομένη χρονική στιγμή και μπορούν να αλλάξουν μετά την υποβολή του lockfile.
