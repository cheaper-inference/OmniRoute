Ένας προσαρμοσμένος κόμβος JSON API συνδέει ένα τελικό σημείο επιχείρησης JSON που δεν εκφωνεί το πρωτόκολλο OpenAI ή Anthropic. OmniRoute συμπληρώνει ένα πρότυπο αιτήματος JSON, το στέλνει στο πλήρες τελικό σημείο URL, διαβάζει την απάντηση από μια διαδρομή απόκρισης και την επιστρέφει στον πελάτη στη μορφή του ίδιου του πελάτη (Ολοκληρώσεις συνομιλίας, Απαντήσεις, Μηνύματα, ...).

Είναι ένας κόμβος συμβατός με OpenAI με `apiType: "custom-json"`. Το αναγνωριστικό του έχει τη μορφή `openai-compatible-custom-json-<suffix>`. Η φόρμα του πίνακα ελέγχου δεν είναι ακόμη διαθέσιμη. Δημιουργήστε και επεξεργαστείτε αυτούς τους κόμβους μέσω του κόμβου παροχής API παρακάτω.

## Δημιουργήστε έναν κόμβο

`POST /api/provider-nodes` (διαχείριση εξουσιοδότησης):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` είναι το** πλήρης** τελικό σημείο URL. Δεν έχει προσαρτηθεί τίποτα (χωρίς `/chat/completions`, χωρίς `/models`) και, σε αντίθεση με άλλους κόμβους συμβατούς με OpenAI, δεν υπάρχει προεπιλεγμένο URL. Πρέπει να είναι `http(s)`, χωρίς ενσωματωμένα διαπιστευτήρια ή `#fragment` και περνά το ίδιο εξερχόμενο URL guard όπως κάθε κόμβος παρόχου, τόσο όταν ο κόμβος αποθηκεύεται όσο και σε κάθε αίτημα.
- Ένας κόμβος που στέλνει το κλειδί σύνδεσης (`authType` `bearer` ή `api-key`, συμπεριλαμβανομένου του προεπιλεγμένου) πρέπει να χρησιμοποιεί `https://`. Το απλό `http://` είναι αποδεκτό μόνο για έναν κεντρικό υπολογιστή loopback (`localhost`, `127.0.0.0/8`, `::1`) ή με `authType: "none"`, ο οποίος δεν στέλνει κλειδί. Οι ιδιωτικές διευθύνσεις LAN (`10.x`, `172.16-31.x`, `192.168.x`) δεν εξαιρούνται: οποιοσδήποτε σε αυτό το δίκτυο θα μπορούσε να διαβάσει το κλειδί. Η αποθήκευση ενός τέτοιου κόμβου αποτυγχάνει με `400` και ένας κόμβος που έχει αποθηκευτεί νωρίτερα αποτυγχάνει να κλείνει σε κάθε αίτημα με το ίδιο μήνυμα, πριν αποσταλεί οποιοδήποτε αίτημα. Για ένα κλειδωμένο τελικό σημείο σε ένα LAN, τοποθετήστε το πίσω από TLS (για παράδειγμα έναν αντίστροφο διακομιστή μεσολάβησης).
- `customJson` επικυρώνεται με Zod. άγνωστα κλειδιά απορρίπτονται. Κάθε πεδίο είναι προαιρετικό:

| Πεδίο             | Αξίες                                              | Αθέτηση                                                |
| ----------------- | -------------------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                             | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                        | `bearer`                                               |
| `authHeader`      | όνομα κεφαλίδας που χρησιμοποιείται όταν `api-key` | `X-API-Key`                                            |
| `requestTemplate` | αντικείμενο JSON (≤ 64 KB, βάθος ≤ 32)             | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | μονοπάτι πεδίου, ή `$` για ολόκληρο το σώμα        | `choices[0].message.content`                           |

- Το μυστικό παραμένει στο κλειδί API της σύνδεσης, ποτέ στο πρότυπο. `bearer` στέλνει `Authorization: Bearer <key>`; `api-key` στέλνει `<authHeader>: <key>`. Η κεφαλίδα auth δεν μπορεί να είναι `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` ή κεφαλίδα hop-by-hop. Με `none`, οι συνδέσεις δεν χρειάζονται κλειδί.
- Οι επιπλέον στατικές κεφαλίδες χρησιμοποιούν το κανονικό `customHeaders` του κόμβου (η ίδια επικύρωση με κάθε άλλο συμβατό κόμβο. Οι κεφαλίδες auth δεν επιτρέπονται εκεί).

`PUT /api/provider-nodes/<id>` δέχεται το ίδιο `customJson` και ξαναγράφει `baseUrl` και το config σε κάθε υπάρχουσα σύνδεση του κόμβου. Η παράλειψη `customJson` διατηρεί την αποθηκευμένη διαμόρφωση. Η εναλλαγή `apiType` σε `chat` ή `responses` το αφαιρεί από τον κόμβο και τις συνδέσεις του.

Στη συνέχεια, προσθέστε μια σύνδεση στον κόμβο ως συνήθως (`POST /api/providers` με το αναγνωριστικό κόμβου) και ζητήστε `<prefix>/<model>`, για παράδειγμα `biz/assistant-v1`. Το τελικό σημείο δεν εκθέτει λίστα μοντέλων, επομένως προσθέστε τα αναγνωριστικά μοντέλων με το χέρι.

## Ζητήστε πρότυπα

Τα πρότυπα είναι απλά JSON. Μια τιμή συμβολοσειράς μπορεί να περιέχει δείκτες `{{placeholder}}`. τίποτα δεν αξιολογείται ή εκτελείται και τα κλειδιά αντικειμένων δεν αντικαθίστανται ποτέ.

| Placeholder          | Αξία                                                                               |
| -------------------- | ---------------------------------------------------------------------------------- |
| `{{prompt}}`         | Κείμενο του τελευταίου μηνύματος χρήστη (τμήματα κειμένου ενωμένα με νέες γραμμές) |
| `{{messages}}`       | Η συνομιλία σε μορφή συνομιλίας OpenAI                                             |
| `{{model}}`          | Το αναγνωριστικό μοντέλου που ζητήθηκε, χωρίς το πρόθεμα παρόχου                   |
| `{{stream}}`         | Πάντα `false` — το τελικό σημείο απαντά με ένα έγγραφο JSON                        |
| `{{request.<path>}}` | Ένα πεδίο του μεταφρασμένου αιτήματος (μορφή συνομιλίας OpenAI ).                  |

- Μια τιμή που είναι ακριβώς ένα σύμβολο κράτησης θέσης διατηρεί τον τύπο JSON (`"{{messages}}"` γίνεται πίνακας). ένα σύμβολο κράτησης θέσης μέσα σε μια μεγαλύτερη συμβολοσειρά εισάγεται ως κείμενο.
- Ένα σύμβολο κράτησης θέσης που επιλύει το μηδέν αποτυγχάνει το αίτημα με HTTP 400 αντί να στείλει ένα ημιτελές ωφέλιμο φορτίο.
- Τα μονοπάτια χρησιμοποιούν σημειογραφία κουκκίδων και αριθμητικά ευρετήρια (`data.items[0].text`). `__proto__`, `prototype` και `constructor` απορρίπτονται σε κλειδιά και διαδρομές.

## Απαντήσεις

Η τιμή στο `responsePath` γίνεται η απάντηση βοηθού: οι συμβολοσειρές περνούν, άλλες τιμές JSON σειριοποιούνται. Ένα πεδίο που λείπει ή `null` ή ένα σώμα που δεν είναι JSON, επιστρέφει HTTP 502. Μεταβιβάζονται οι καταστάσεις σφάλματος ανάντη. Για πελάτες συνεχούς ροής, OmniRoute περιμένει ολόκληρη την απόκριση JSON και στη συνέχεια την εκπέμπει ως ένα κομμάτι περιεχομένου συν το τελικό κομμάτι. αυτό δεν είναι συμβολική ροή. Οι κλήσεις εργαλείων και τα πεδία χρήσης δεν αντιστοιχίζονται.

## Δεν επαναλήφθηκε ποτέ

Ένα επιχειρηματικό αίτημα μπορεί να έχει παρενέργειες ακόμα και όταν αποτύχει. Επομένως, OmniRoute το στέλνει μία φορά:

- καμία επανάληψη μεταφοράς και καμία ανακατεύθυνση που ακολουθεί.
- όχι επανάληψη σε άλλη σύνδεση (επιστροφή λογαριασμού) — η αποτυχία επιστρέφεται ως έχει και η σύνδεση δεν ψύχεται.
- δεν υπάρχει εναλλακτική λύση στον επόμενο στόχο συνδυασμού, ακόμη και για μια κενή ή αποτυχημένη απάντηση.

Τα ξεχωριστά αιτήματα πελατών και οι πίνακες σύντηξης που καλούν ρητά πολλά μοντέλα, εξακολουθούν να καλούν το τελικό σημείο ανεξάρτητα.

## Δοκιμή ενός κόμβου

Αποθήκευση μιας σύνδεσης, η σύνδεση** Δοκιμή** Οι έλεγχοι υγείας του κουμπιού και του παρασκηνίου δεν καλούν ποτέ το τελικό σημείο: επικυρώνουν μόνο την αποθηκευμένη διαμόρφωση και αναφέρουν τη σύνδεση ως μη επαληθεύσιμη.

`POST /api/provider-nodes/validate` με `"apiType": "custom-json"` και τα πεδία κόμβου (`baseUrl`, `apiKey`, `customJson`, προαιρετικά `customHeaders` και `modelId`) στέλνει ακριβώς ένα πραγματικό αίτημα, με `ping` ως το πιο πρόσφατο κείμενο χρήστη. Απαντά `{ "valid": true }` ή το upstream status (ποτέ το upstream body).

## Αποθήκευση

Η ρύθμιση παραμέτρων αποθηκεύεται στο `provider_nodes.custom_json_config_json` (μετάβαση `240_provider_node_custom_json_config.sql`) και αντιγράφεται στο `providerSpecificData.customJson` κάθε σύνδεσης.

Υλοποίηση: `open-sse/utils/customJson.ts` (επικύρωση και διαμόρφωση), `open-sse/executors/customJson.ts` (εκτελεστής), `open-sse/services/combo/noReplayLatch.ts` και `src/sse/handlers/chat/responsePolicies.ts` (χωρίς επανάληψη).
