> **Εν συντομία**: Το OmniRoute παρακολουθεί τη χρήση token κάθε αιτήματος, υπολογίζει το κόστος, επιβάλλει όριο χρήσης ανά κλειδί API και εμφανίζει αναλυτικά στοιχεία στον πίνακα ελέγχου. Αυτός ο οδηγός εξηγεί πώς λειτουργούν όλα αυτά.

**Πηγές:**

- `open-sse/services/usage.ts` (~70KB) — κύρια παρακολούθηση χρήσης
- `src/lib/usageAnalytics.ts` (~10KB) — συγκέντρωση δεδομένων για τον πίνακα ελέγχου
- `src/lib/db/quotaSnapshots.ts` — ιστορικά δεδομένα ορίων χρήσης
- `src/lib/db/usage*.ts` — πολλαπλές μονάδες βάσης δεδομένων σχετικές με τη χρήση

## Επισκόπηση

Κάθε αίτημα που διέρχεται από το OmniRoute δημιουργεί μια **εγγραφή χρήσης**, η οποία καταγράφει:

- **Ταυτότητα**: ποιο κλειδί API, ποιος πάροχος, ποιο μοντέλο, ποιος συνδυασμός
- **Token**: token προτροπής, token ολοκλήρωσης, αποθηκευμένα στην κρυφή μνήμη token, σύνολο
- **Κόστος**: ποσό σε USD (υπολογίζεται από τα δεδομένα τιμολόγησης)
- **Χρονισμός**: καθυστέρηση, χρονικές σημάνσεις έναρξης/λήξης
- **Κατάσταση**: επιτυχία, σφάλμα, περιορισμός ρυθμού κ.λπ.

Αυτές οι εγγραφές συγκεντρώνονται σε **αναλυτικά στοιχεία**, διατηρούνται ως **στιγμιότυπα ορίων χρήσης** και χρησιμοποιούνται για την επιβολή **ορίων προϋπολογισμού ανά κλειδί**.

```
Αίτημα ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    αναλυτικά  όριο    χρέωση
                    (πίνακας) (επιβολή) (εξαγωγή)
```

## Τι καταγράφεται

Η υπηρεσία `usage.ts` καταγράφει ένα **συμβάν χρήσης** για κάθε αίτημα:

| Πεδίο              | Τύπος   | Προέλευση                                                                                             |
| ------------------ | ------- | ----------------------------------------------------------------------------------------------------- |
| `id`               | string  | UUID που δημιουργείται κατά την καταγραφή                                                             |
| `apiKeyId`         | string  | Το κλειδί API που εκκίνησε το αίτημα                                                                  |
| `provider`         | string  | Αναγνωριστικό παρόχου (openai, anthropic κ.λπ.)                                                       |
| `model`            | string  | Αναγνωριστικό μοντέλου (gpt-5, claude-opus-4-6 κ.λπ.)                                                 |
| `comboId`          | string? | Αναγνωριστικό συνδυασμού, αν η δρομολόγηση έγινε μέσω συνδυασμού                                      |
| `promptTokens`     | number  | Από την απόκριση του ανάντη παρόχου                                                                   |
| `completionTokens` | number  | Από την απόκριση του ανάντη παρόχου                                                                   |
| `cachedTokens`     | number  | Token που ανακτήθηκαν από την κρυφή μνήμη (αποθήκευση προτροπών στην κρυφή μνήμη της Anthropic κ.λπ.) |
| `totalTokens`      | number  | προτροπή + συμπλήρωση                                                                                 |
| `costUsd`          | number  | Υπολογίζεται από τα δεδομένα τιμολόγησης                                                              |
| `latencyMs`        | number  | Συνολική διάρκεια του αιτήματος                                                                       |
| `status`           | enum    | `success`, `error`, `rate_limited`, `timeout`, `cancelled`                                            |
| `errorClass`       | string? | Κλάση σφάλματος αν η κατάσταση != επιτυχία                                                            |
| `timestamp`        | string  | ISO 8601 UTC                                                                                          |
| `metadata`         | object  | Προσαρμοσμένα δεδομένα που εισάγονται από πρόσθετο                                                    |

### Από πού προέρχονται τα token

Τα token εξάγονται από την απόκριση του ανάντη παρόχου στον **χειριστή αποκρίσεων**:

```ts
// Από το open-sse/handlers/chatCore.ts
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

Για παρόχους που δεν επιστρέφουν στοιχεία χρήσης (ορισμένοι πάροχοι που χρησιμοποιούν cookie ιστού), το OmniRoute **εκτιμά** τα token χρησιμοποιώντας τον ευρετικό κανόνα `~4 chars per token` (βλ. `open-sse/services/autoCombo/pipelineRouter.ts`).

### Token στην κρυφή μνήμη

Το OmniRoute παρακολουθεί τα `cached_tokens` ξεχωριστά από τα `prompt_tokens`, επειδή:

- Η αποθήκευση προτροπών στην κρυφή μνήμη της Anthropic χρεώνει μειωμένη τιμή για τα token στην κρυφή μνήμη (10% της κανονικής)
- Ορισμένοι πάροχοι επιστρέφουν `cache_read_input_tokens` που πρέπει να τιμολογούνται διαφορετικά
- Τα αναλυτικά στοιχεία μπορούν να εμφανίζουν το **ποσοστό επιτυχούς ανάκτησης από την κρυφή μνήμη** = `cached_tokens / prompt_tokens`

### Διαγνωστικά βαθμίδων εγγραφής στην κρυφή μνήμη

Ο πίνακας εύρυθμης λειτουργίας της κρυφής μνήμης προτροπών στον πίνακα ελέγχου αναλυτικών στοιχείων διακρίνει τις εγγραφές
στην κρυφή μνήμη διάρκειας 5 λεπτών και 1 ώρας που αναφέρονται από τον πάροχο. Τα πεδία
`usage.cache_creation.ephemeral_5m_input_tokens` και
`usage.cache_creation.ephemeral_1h_input_tokens` της Anthropic διατηρούνται κατά τη μετατροπή των στοιχείων χρήσης με και
χωρίς ροή και αποθηκεύονται μαζί με τις συνόψεις του αρχείου καταγραφής κλήσεων. Το συνολικό
άθροισμα εγγραφών στην κρυφή μνήμη δεν προστίθεται δεύτερη φορά σε αυτές τις κατηγορίες.

Οι κλήσεις με μόνο έναν συνολικό μετρητή εγγραφών, συμπεριλαμβανομένων των παλαιότερων εγγραφών, έχουν άγνωστη
βαθμίδα. Μια μερική ανάλυση διατηρεί ως άγνωστο το μη κατανεμημένο υπόλοιπό της· οι μη έγκυροι ή
αντικρουόμενοι μετρητές επισημαίνονται αντί να τους εκχωρείται σιωπηρά ένα TTL. Οι δείκτες
TTL στην πλευρά του αιτήματος δεν αποτελούν τεκμήριο χρεωμένης βαθμίδας.

Η εκτίμηση εγγραφών του πίνακα, σε ισοδύναμο API, καλύπτει μόνο τις αναφερόμενες βαθμίδες με διαθέσιμη τιμολόγηση, όχι
ολόκληρο το αίτημα. Για την εγγενή τιμολόγηση μοντέλων Claude/Anthropic χρησιμοποιεί 1,25 φορές την
τιμή εισόδου για εγγραφές διάρκειας 5 λεπτών και το διπλάσιο της τιμής εισόδου για εγγραφές διάρκειας 1 ώρας. Η απουσία
τιμολόγησης σημαίνει μη διαθέσιμη τιμή, όχι μηδενική. Οι τιμές καταγράφονται κατά την καταγραφή κάθε νέας κλήσης·
οι ιστορικές εγγραφές δεν επανατιμολογούνται. Επομένως, οι συνδρομητικοί λογαριασμοί μπορούν να έχουν
μια εκτίμηση σε ισοδύναμο API χωρίς το ποσό αυτό να επιβαρύνει τις χρηματικές δαπάνες ή το όριο
της συνδρομής. Οι υφιστάμενοι υπολογισμοί ορίων, προϋπολογισμού και ακριβούς κόστους ανά πάροχο παραμένουν αμετάβλητοι.

Αυτά τα διαγνωστικά χρησιμοποιούν την υπάρχουσα σύνοψη εύρυθμης λειτουργίας της κρυφής μνήμης με περιορισμένο εύρος και την υφιστάμενη πολιτική διατήρησης
του αρχείου καταγραφής κλήσεων. Δεν αλλάζουν τις προεπιλεγμένες τιμές TTL των αιτημάτων, τη δρομολόγηση ή την επιλογή λογαριασμού.
Η καταγραφή του TTL που ζητά ο πελάτης σε σύγκριση με το πραγματικό εξερχόμενο TTL στο σημείο αποστολής
προς τον πάροχο αναβάλλεται· αυτός ο πίνακας αναφέρει τις βαθμίδες των παραστατικών, όχι το πραγματικό εξερχόμενο TTL.

Υλοποίηση: `src/lib/usage/cacheWriteEstimate.ts`,
`src/lib/usage/cacheHealth.ts` και `open-sse/utils/cacheWriteUsage.ts`.

## Υπολογισμός Κόστους

Τα κόστη υπολογίζονται από **δεδομένα τιμολόγησης** που συγχρονίζονται από το LiteLLM (`src/lib/pricingSync.ts`):

| Μοντέλο           | Είσοδος $/1M | Έξοδος $/1M | Σε cache $/1M |
| ----------------- | ------------ | ----------- | ------------- |
| gpt-5             | $2.50        | $10.00      | —             |
| claude-opus-4-6   | $15.00       | $75.00      | $1.50         |
| claude-sonnet-4-5 | $3.00        | $15.00      | $0.30         |
| gemini-2.5-pro    | $1.25        | $10.00      | —             |

Ο τύπος υπολογισμού του κόστους (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **Γιατί αφαιρούνται τα αποθηκευμένα σε cache tokens από το prompt;** Το τμήμα που βρίσκεται στην cache τιμολογείται ξεχωριστά· η χρέωση της τιμής εισόδου για ολόκληρο το prompt θα οδηγούσε σε υπερβολικό υπολογισμό.

### Συγχρονισμός Τιμολόγησης

Τα δεδομένα τιμολόγησης συγχρονίζονται αυτόματα από το LiteLLM μέσω του endpoint `/api/pricing/sync` (ενεργοποιείται από την ενσωματωμένη εργασία cron και όχι από κάποια μεταβλητή περιβάλλοντος διαθέσιμη στον χρήστη):

```bash
# Μη αυτόματη ενεργοποίηση
curl -X POST http://localhost:20128/api/pricing/sync
```

Για μοντέλα χωρίς δεδομένα τιμολόγησης, το OmniRoute καταφεύγει σε **εκτίμηση του κόστους** χρησιμοποιώντας εσωτερικές μέσες τιμές (οι οποίες προέρχονται από τα δεδομένα τιμολόγησης του LiteLLM).

## Συγκέντρωση δεδομένων ανά εύρος ημερομηνιών

Η μονάδα `usageAnalytics.ts` υπολογίζει τα γραφικά στοιχεία του πίνακα ελέγχου από ακατέργαστα δεδομένα χρήσης. Υποστηρίζει 7 χρονικά εύρη:

| Εύρος    | Χρονικό διάστημα                          | Περίπτωση χρήσης                     |
| -------- | ----------------------------------------- | ------------------------------------ |
| `1d`     | Τελευταίες 24 ώρες                        | Εντοπισμός ωριαίων αιχμών κόστους    |
| `7d`     | Τελευταίες 7 ημέρες                       | Εβδομαδιαία επισκόπηση               |
| `30d`    | Τελευταίες 30 ημέρες                      | Μηνιαία χρέωση                       |
| `90d`    | Τελευταίες 90 ημέρες                      | Τριμηνιαία ανάλυση                   |
| `ytd`    | Από την 1η Ιανουαρίου του τρέχοντος έτους | Παρακολούθηση ετήσιου προϋπολογισμού |
| `all`    | Όλο το χρονικό διάστημα                   | Στατιστικά συνολικής διάρκειας       |
| `custom` | Έναρξη/λήξη που ορίζει ο χρήστης          | Έλεγχοι, έκτακτα ερωτήματα           |

### Υπολογιζόμενα γραφικά στοιχεία πίνακα ελέγχου

Για οποιοδήποτε εύρος ημερομηνιών, το επίπεδο ανάλυσης υπολογίζει:

| Γραφικό στοιχείο                   | Περιγραφή                                                                   |
| ---------------------------------- | --------------------------------------------------------------------------- |
| **Κάρτες σύνοψης**                 | Συνολικά αιτήματα, συνολικό κόστος, συνολικά token, ποσοστό επιτυχίας       |
| **Διάγραμμα ημερήσιας τάσης**      | Κόστος + token ανά ημέρα, στοιβαγμένα ανά μοντέλο                           |
| **Θερμικός χάρτης δραστηριότητας** | Πλέγμα ώρας της ημέρας × ημέρας της εβδομάδας, χρώμα = πλήθος αιτημάτων     |
| **Ανάλυση ανά μοντέλο**            | Κυκλικό διάγραμμα κόστους ανά μοντέλο                                       |
| **Ανάλυση ανά πάροχο**             | Ραβδόγραμμα αιτημάτων ανά πάροχο                                            |
| **Κορυφαία κλειδιά API**           | Πίνακας των 10 κορυφαίων κλειδιών βάσει κόστους                             |
| **Ανάλυση σφαλμάτων**              | Ποσοστό σφαλμάτων με την πάροδο του χρόνου, κυριότερες κατηγορίες σφαλμάτων |

### Πρόσβαση μέσω προγραμματισμού

````ts
import { computeAnalytics } from "@/lib/usageAnalytics";

const analytics = await computeAnalytics(
  history,              // εγγραφές ιστορικού χρήσης
  "7d",                 // χρονικό εύρος: "1d" | "7d" | "30d" | "90d" | "ytd" | "all" | "custom"
  connectionMap,        // χάρτης συνδέσεων παρόχων (connectionId → όνομα λογαριασμού)
  {
    startDate: "2025-01-01",  // προαιρετικό: για το εύρος "custom"
    endDate: "2025-06-01",   // προαιρετικό: για το εύρος "custom"
  }
);

console.log(analytics.summary.totalCost);   // 12.34 (σεντ)
console.log(analytics.byModel[0]);           // { model, cost, requests, promptTokens, completionTokens }

## Επιβολή ορίων χρήσης

Τα όρια χρήσης ανά κλειδί API επιβάλλονται σε δύο σημεία:

1. **Ήπιο όριο** (`quotaWarnAt`): προειδοποίηση στον πίνακα ελέγχου όταν η χρήση υπερβαίνει το κατώφλι
2. **Αυστηρό όριο** (`quotaLimit`): απόρριψη του αιτήματος με HTTP 429 όταν ξεπεραστεί

### Ρύθμιση παραμέτρων

```ts
// Ανά κλειδί API
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — εμφάνιση προειδοποίησης
  quotaLimit: 10_00,    // $10.00 — υποχρεωτική διακοπή
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### Ροή επιβολής

```
Αίτημα ──▶ quotaCheck()
              │
              ├── Εντός ορίου;  ──▶ επιτρέπεται
              │
              └── Υπέρβαση ορίου;  ──▶ 429 Too Many Requests
                                   με κεφαλίδα Retry-After
```

### Στιγμιότυπα ορίων χρήσης

Ο πίνακας `quotaSnapshots` αποθηκεύει την **ιστορική κατάσταση των ορίων χρήσης** για ανάλυση τάσεων:

| Πεδίο | Περιγραφή |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | Το κλειδί που παρακολουθείται |
| `window` | "day" | "week" | "month" |
| `used` | Κόστος που καταναλώθηκε σε αυτό το χρονικό διάστημα (σεντ) |
| `limit` | Το όριο (σεντ) |
| `resetAt` | Πότε επαναφέρεται το χρονικό διάστημα |
| `createdAt` | Πότε λήφθηκε το στιγμιότυπο |

Τα στιγμιότυπα λαμβάνονται **σε κάθε αίτημα** με κόστος > 0 και χρησιμοποιούνται για:

- Την απεικόνιση της γραμμής προόδου του ορίου χρήσης στον πίνακα ελέγχου
- Την εμφάνιση διαγραμμάτων τάσης ορίων χρήσης 30 ημερών
- Την ενεργοποίηση ειδοποιήσεων όταν η χρήση πλησιάζει το όριο

### Ερωτήματα αναλυτικών στοιχείων χρήσης

Η πρόσβαση στα δεδομένα χρήσης γίνεται μέσω του πίνακα ελέγχου ή των εργαλείων MCP, όχι μέσω απευθείας τελικών σημείων εξαγωγής REST. Διαθέσιμα αναλυτικά στοιχεία:

- **`/api/usage/analytics`** — συγκεντρωτικές μετρικές χρήσης (ομαδοποίηση ανά μοντέλο, πάροχο, κλειδί)

## Διατήρηση και εκκαθάριση

Τα δεδομένα χρήσης αυξάνονται κατά ~1-10KB ανά αίτημα. Σε μεγάλη κλίμακα, αυτό μπορεί να είναι σημαντικό.

### Ρυθμίσεις διατήρησης

Η διατήρηση του ιστορικού χρήσης ρυθμίζεται μέσω των Ρυθμίσεων βάσης δεδομένων στη διεπαφή χρήστη ή μέσω του `/api/settings/database`.

Από προεπιλογή, το ιστορικό χρήσης διατηρείται για **90 ημέρες**.

### Εκκαθάριση

Οι παλιές εγγραφές εκκαθαρίζονται από το `src/lib/db/cleanup.ts`:

- Ενεργοποιείται από τη διεργασία cron στο παρασκήνιο
- Διαγράφει εγγραφές από το `usage_history` που είναι παλαιότερες από τη ρυθμισμένη περίοδο διατήρησης `usageHistory`

### Εκτίμηση αποθηκευτικού χώρου

| Ρυθμός αιτημάτων       | Αποθηκευτικός χώρος 30 ημερών | Αποθηκευτικός χώρος 90 ημερών |
| ---------------------- | ----------------------------- | ----------------------------- |
| 100 αιτήματα/ημέρα     | ~3MB                          | ~9MB                          |
| 1,000 αιτήματα/ημέρα   | ~30MB                         | ~90MB                         |
| 10,000 αιτήματα/ημέρα  | ~300MB                        | ~900MB                        |
| 100,000 αιτήματα/ημέρα | ~3GB                          | ~9GB                          |

Για πολύ υψηλή κίνηση, εξετάστε το ενδεχόμενο:

- Μείωσης της περιόδου διατήρησης μέσω των Ρυθμίσεων βάσης δεδομένων
- Χρήσης του `aggregated_metrics` αντί των ακατέργαστων εγγραφών (μόνο για αναλυτικά στοιχεία)

## Συμβουλές βελτιστοποίησης κόστους

### 1. Χρησιμοποιήστε το κατάλληλο μοντέλο

```bash
# Γρήγορη απάντηση — χρησιμοποιήστε οικονομικό + γρήγορο μοντέλο
curl -d '{"model":"auto/fast","messages":[...]}'

# Σύνθετη εργασία — επιλέξτε ποιότητα
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. Ενεργοποιήστε την προσωρινή αποθήκευση

Η προσωρινή αποθήκευση προτροπών της Anthropic εξοικονομεί **90% στο επαναλαμβανόμενο πλαίσιο**:

```ts
// Η προσωρινή αποθήκευση είναι αυτόματη — απλώς συμπεριλάβετε την ίδια μεγάλη προτροπή συστήματος
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // Θα αποθηκευτεί αυτόματα στην προσωρινή μνήμη
  messages: [{ role: "user", content: "..." }],
});
```

### 3. Χρησιμοποιήστε συμπίεση

Η συμπίεση RTK + Caveman εξοικονομεί **15-95% σε συνεδρίες με εκτεταμένη χρήση εργαλείων**:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. Ορίστε όρια ανά κλειδί

Ορίζετε πάντα το `quotaLimit` για να αποτρέπετε το ανεξέλεγκτο κόστος:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // Ανώτατο όριο $10/μήνα
```

### 5. Ελέγξτε τους μεγαλύτερους καταναλωτές

Χρησιμοποιήστε τον πίνακα ελέγχου ή το **`/api/usage/analytics`** για ομαδοποίηση ανά κλειδί API και ταξινόμηση βάσει κόστους:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## Αντιμετώπιση προβλημάτων

### "Το κόστος είναι υψηλότερο από το αναμενόμενο"

1. Ελέγξτε το **`/api/usage/analytics?groupBy=model`** — εντοπίστε το ακριβό μοντέλο
2. Ελέγξτε το **`/api/usage/analytics?groupBy=apiKey`** — εντοπίστε τον καταναλωτή με υψηλή χρήση
3. Βεβαιωθείτε ότι τα δεδομένα τιμολόγησης είναι ενημερωμένα: `POST /api/pricing/sync`

### "Λείπουν εγγραφές"

- Ελέγξτε τις ρυθμίσεις διατήρησης της βάσης δεδομένων στην ενότητα Πίνακας ελέγχου → Βάση δεδομένων → Εκκαθάριση — οι παλιές εγγραφές διαγράφονται από την περιοδική εργασία εκκαθάρισης (`src/lib/db/cleanup.ts`)
- Ελέγξτε για σφάλματα στο `src/lib/db/usage*.ts` — οι αποτυχίες εγγραφής στη βάση δεδομένων καταγράφονται αλλά δεν εμφανίζονται
- Βεβαιωθείτε ότι το αίτημα έφτασε πράγματι στο `chatCore` — ελέγξτε τη δρομολόγηση combo

### "Το όριο δεν εφαρμόζεται"

- Ελέγξτε τη ρύθμιση `quotaLimit` του κλειδιού
- Βεβαιωθείτε ότι το `quotaWindow` έχει οριστεί σωστά
- Αναζητήστε εγγραφές `quotaSnapshots` — θα πρέπει να δημιουργούνται σε κάθε αίτημα
