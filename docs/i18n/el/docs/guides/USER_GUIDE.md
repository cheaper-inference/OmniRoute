## 🎯 Περιπτώσεις Χρήσης

### Περίπτωση 1: «Έχω συνδρομή Claude Pro»

**Πρόβλημα:** Το όριο λήγει αναξιοποίητο, περιορισμοί ρυθμού κατά την έντονη κωδικοποίηση

```
Combo: "maximize-claude"
  1. cc/claude-opus-4-7        # (πλήρης αξιοποίηση συνδρομής)
  2. glm/glm-4.7               # (φθηνό εφεδρικό όταν εξαντληθεί το όριο)
  3. if/qwen3.8-max-preview       # (δωρεάν εφεδρικό έκτακτης ανάγκης)

Μηνιαίο κόστος: $20 (συνδρομή) + ~$5 (εφεδρικό) = $25 συνολικά
αντί για: $20 + χτύπημα ορίων = απογοήτευση
```

### Περίπτωση 2: «Θέλω μηδενικό κόστος»

**Πρόβλημα:** Δεν μπορώ να αντέξω συνδρομές, χρειάζομαι αξιόπιστη AI κωδικοποίηση

```
Combo: "zero-cost"
  1. if/kimi-k2.7-code          # (καταχωρημένη δωρεάν πρόσβαση· ενδέχεται να ισχύουν όρια ρυθμού)
  2. kr/qwen3-coder-next        # (δωρεάν εφεδρικό Kiro)

Μηνιαίο κόστος: $0
Ποιότητα: επαληθεύστε το μοντέλο, τα όρια, την ιδιωτικότητα και το SLA για τον φόρτο εργασίας σας
```

### Περίπτωση 3: «Χρειάζομαι κωδικοποίηση 24/7, χωρίς διακοπές»

**Πρόβλημα:** Προθεσμίες, δεν αντέχω διακοπή λειτουργίας

```
Combo: "always-on"
  1. cc/claude-opus-4-7        # (καλύτερη ποιότητα)
  2. cx/gpt-5.5                # (δεύτερη συνδρομή)
  3. glm/glm-4.7               # (φθηνό, επαναφορά καθημερινά)
  4. minimax/MiniMax-M2.1      # (φθηνότατο, επαναφορά 5ω)
  5. if/deepseek-v4-flash       # (καταχωρημένη δωρεάν πρόσβαση· ενδέχεται να ισχύουν όρια ρυθμού)

Αποτέλεσμα: 5 επίπεδα εφεδρικών διευρύνουν την ανθεκτικότητα· η διαθεσιμότητα upstream δεν εγγυάται
Μηνιαίο κόστος: $20-200 (συνδρομές) + $10-20 (εφεδρικό)
```

### Περίπτωση 4: «Θέλω ΔΩΡΕΑΝ AI στο OpenClaw»

**Πρόβλημα:** Χρειάζομαι AI βοηθό σε εφαρμογές μηνυμάτων, εντελώς δωρεάν

```
Combo: "openclaw-free"
  1. if/qwen3.8-max-preview     # (καταχωρημένη δωρεάν πρόσβαση· ενδέχεται να ισχύουν όρια ρυθμού)
  2. if/deepseek-v4-flash       # (καταχωρημένη δωρεάν πρόσβαση· ενδέχεται να ισχύουν όρια ρυθμού)
  3. if/kimi-k2.7-code          # (καταχωρημένη δωρεάν πρόσβαση· ενδέχεται να ισχύουν όρια ρυθμού)

Μηνιαίο κόστος: $0
Πρόσβαση μέσω: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 Ρύθμιση παρόχων

Για μαζική προσθήκη συνδέσεων με κλειδί API από αρχείο CSV ή JSON, χρησιμοποιήστε **Πίνακας ελέγχου → Πάροχοι → Εισαγωγή από αρχείο**. Οι στήλες είναι τοποθετημένες με συγκεκριμένη σειρά (`provider,name,apiKey,baseUrl,priority`)· το `provider` πρέπει να υπάρχει ήδη ως διαχειριζόμενος πάροχος ή συμβατός κόμβος. Δείτε την ενότητα [Εισαγωγή παρόχων από αρχείο CSV ή JSON](../providers/CSV-IMPORT.md).

### 🔐 Πάροχοι συνδρομών

#### Claude Code (Pro/Max)

```bash
Πίνακας ελέγχου → Πάροχοι → Σύνδεση Claude Code
→ Σύνδεση OAuth → Αυτόματη ανανέωση token
→ Παρακολούθηση ορίων 5 ωρών + εβδομαδιαίου ορίου

Μοντέλα:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**Χρήσιμη συμβουλή:** Χρησιμοποιήστε το Opus για σύνθετες εργασίες και το Sonnet για ταχύτητα. Το OmniRoute παρακολουθεί το όριο ανά μοντέλο!

Δεν υπάρχει πρόγραμμα περιήγησης στον υπολογιστή όπου φιλοξενείται το OmniRoute; Εκτελέστε την εντολή `claude setup-token` οπουδήποτε είναι συνδεδεμένο το Claude Code και επικολλήστε το token διάρκειας ενός έτους στην καρτέλα **Token ρύθμισης**. Δείτε την ενότητα [Claude Code με token ρύθμισης](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

Οι διαδρομές που είναι συμβατές με Claude και Claude Code διατηρούν την προσπάθεια σκέψης `max` για τα
μοντέλα Opus και Sonnet. Τα μοντέλα Haiku δεν αποδέχονται το επίπεδο προσπάθειας `max`, επομένως το OmniRoute υποβαθμίζει αυτό
το αίτημα σε υψηλό προϋπολογισμό σκέψης πριν το αποστείλει upstream.

#### OpenAI Codex (Plus/Pro)

```bash
Πίνακας ελέγχου → Πάροχοι → Σύνδεση Codex
→ Σύνδεση OAuth (θύρα 1455)
→ Επαναφορά κάθε 5 ώρες + εβδομαδιαία επαναφορά

Μοντέλα:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
Πίνακας ελέγχου → Πάροχοι → Σύνδεση GitHub
→ OAuth μέσω GitHub
→ Μηνιαία επαναφορά (1η ημέρα του μήνα)

Μοντέλα:
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview
```

**AI Credits (χρέωση βάσει token).** Όταν το GitHub αναφέρει `credits_used` για τον
λογαριασμό, η κάρτα ορίων παρόχου εμφανίζει μια γραμμή **AI Credits** με τις μονάδες
που καταναλώθηκαν κατά την τρέχουσα περίοδο χρέωσης, ακόμη και σε απεριόριστα
προγράμματα οργανισμών.

**Τοπικό όριο AI Credits.** Επεξεργαστείτε μια σύνδεση GitHub και ορίστε το **Όριο AI Credits ανά
περίοδο χρέωσης** (`providerSpecificData.githubCreditLimit`). Το κενό πεδίο το απενεργοποιεί· η τιμή `0`
παρακάμπτει πάντα τη σύνδεση. Όταν η τελευταία μέτρηση χρήσης είναι ίση ή μεγαλύτερη από το όριο,
η επιλογή λογαριασμού παρακάμπτει αυτήν τη σύνδεση και η δρομολόγηση επιστρέφει στις άλλες
συνδέσεις σας, όπως ακριβώς συμβαίνει με μια διακοπή βάσει πολιτικής ορίου. Ο έλεγχος χρησιμοποιεί τη χρήση
που συλλέγει ήδη η περιοδική ανανέωση ορίων — δεν καλεί ποτέ το GitHub κατά τη διαδρομή του αιτήματος —
και λειτουργεί με ανοχή σε αποτυχίες: μια μέτρηση που λείπει ή είναι παλιά (παλαιότερη από 15 λεπτά ή από
περίοδο χρέωσης που έχει ήδη επαναφερθεί) δεν αποκλείει τη σύνδεση. Πρόκειται για τοπική δικλείδα ασφαλείας,
**όχι για εγγυημένο ανώτατο όριο δαπανών**: καθυστερήσεις στην αναφορά του GitHub, το διάστημα
ανανέωσης, αιτήματα σε εξέλιξη και χρήση εκτός OmniRoute μπορούν να προκαλέσουν υπέρβαση. Για
αυστηρό όριο, χρησιμοποιήστε τα ίδια τα εργαλεία ελέγχου δαπανών του GitHub.

## Ανάπτυξη 🚀

### Καθολική εγκατάσταση npm (Συνιστάται)

```bash
npm install -g omniroute

# Create config directory
mkdir -p ~/.omniroute

# Create .env file (see .env.example)
cp .env.example ~/.omniroute/.env

# Start server
omniroute
# Or with custom port:
omniroute --port 3000
```

Το CLI φορτώνει αυτόματα `.env` από `~/.omniroute/.env` ή `./.env`. Ένα `./.env` στον κατάλογο εργασίας μπορεί να ορίσει μόνο μια σύντομη λίστα επιτρεπόμενων κλειδιών (θύρες, `REQUIRE_API_KEY`, τοπικές ρυθμίσεις και ρυθμίσεις χρώματος). βάλε όλα τα άλλα στο `~/.omniroute/.env`. Δείτε [συμβόλαια εκκίνησης CLI](CLI-LAUNCH-CONTRACTS.md#working-directory-env).

### Λειτουργία δίσκου

Εκκινήστε OmniRoute στο δίσκο συστήματος:

```bash
omniroute serve --tray
```

Η εντολή επιστρέφει αφού ο διακομιστής και ο δίσκος είναι έτοιμοι.

Ο διακομιστής συνεχίζει χωρίς το τερματικό.

Η λειτουργία δίσκου υποστηρίζει συνεδρίες macOS, Windows και γραφικά Linux. Η λειτουργία δίσκου δεν ανοίγει αυτόματα το ταμπλό.

Χρησιμοποιήστε το μενού δίσκου για αυτές τις ενέργειες:

- Ανοίξτε τον πίνακα ελέγχου.
- Ανοίξτε `/dashboard/logs`.
- Αλλαγή αυτόματης εκκίνησης.
- Σταματήστε OmniRoute.

Μην συνδυάζετε `--tray` με αυτές τις επιλογές:

- `--daemon`
- `--log`
- `--no-recovery`

Αυτές οι λειτουργίες απαιτούν διαφορετική ιδιοκτησία διεργασιών.

Ενεργοποίηση εκκίνησης στην επόμενη σύνδεση του μηχανήματος:

```bash
omniroute autostart enable
```

Η αυτόματη εκκίνηση χρησιμοποιεί τη λειτουργία δίσκου σε συνεδρίες macOS, Windows και γραφικά Linux. Το Headless Linux χρησιμοποιεί την υπάρχουσα υπηρεσία χρήστη systemd.

Απενεργοποίηση εκκίνησης κατά τη σύνδεση:

```bash
omniroute autostart disable
```

### Απεγκατάσταση

Όταν δεν χρειάζεστε πλέον OmniRoute, παρέχουμε δύο γρήγορα σενάρια για καθαρή κατάργηση:

| Εντολή                   | Δράση                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | Καταργεί την εφαρμογή συστήματος αλλά** διατηρεί DB και τις διαμορφώσεις σας** στο `~/.omniroute`.            |
| `npm run uninstall:full` | Καταργεί οριστικά την εφαρμογή AND** διαγράφει όλες τις διαμορφώσεις, τα κλειδιά και τις βάσεις δεδομένων** . |

> Σημείωση: Για να εκτελέσετε αυτές τις εντολές, μεταβείτε στον φάκελο του έργου OmniRoute (αν τον έχετε κλωνοποιήσει) και εκτελέστε τις. Εναλλακτικά, εάν εγκατασταθεί καθολικά, μπορείτε απλά να εκτελέσετε `npm uninstall -g omniroute`.

### Άκυρο Linux (xbps-src)

Οι χρήστες Void Linux μπορούν να συσκευάσουν και να εγκαταστήσουν OmniRoute εγγενώς χρησιμοποιώντας το πλαίσιο πολλαπλής μεταγλώττισης `xbps-src`. Αυτό αυτοματοποιεί την αυτόνομη κατασκευή Node.js μαζί με τις απαιτούμενες εγγενείς συνδέσεις `better-sqlite3`.

<summary><b>Προβολή προτύπου xbps-src</b></summary>

```bash
# Template file for 'omniroute'
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"

system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# Determine target CPU arch for node-gyp
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) Install all deps – skip scripts
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Build the Next.js standalone bundle
	npm run build

	# 3) Copy static assets into standalone
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) Compile better-sqlite3 native binding
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) Place the compiled binding into the standalone bundle
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) Remove arch-specific sharp bundles
	rm -rf .next/standalone/node_modules/@img

	# 7) Copy pino runtime deps omitted by Next.js static analysis:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# Prevent removal of empty Next.js app router dirs by the post-install hook
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

```bash
# Via API

```

Σημειώσεις:

Μη αυτόματη προσθήκη, εισαγωγή και αυτόματος συγχρονισμός όλων των στοιχείων στην ίδια λίστα διαθέσιμων μοντέλων, επομένως δεν υπάρχει ξεχωριστή ενότητα Προσαρμοσμένων μοντέλων για αυτούς τους παρόχους.

### Προσαρμοσμένοι πάροχοι συμβατοί με OpenAI

Οποιαδήποτε πύλη που εκφωνεί το OpenAI API (ένας αυτο-φιλοξενούμενος διακομιστής μεσολάβησης, vLLM, ένας συγκεντρωτής τρίτου μέρους) μπορεί να προστεθεί ως δικός του κόμβος παρόχου:

1. **Πάροχοι → Προσθήκη OpenAI Συμβατό** .
2. **Ονομα** : μια ετικέτα εμφάνισης για τον κόμβο.
3. **Πρόθεμα** : το όνομα δρομολόγησης. Οι πελάτες καλούν τα μοντέλα ως `<prefix>/<model>`, επομένως ένας κόμβος με πρόθεμα `mygw` εξυπηρετεί `mygw/gpt-4o-mini`. Υποχρεούμαι; δεν υπάρχει περιορισμός χαρακτήρα.
4. **Τύπος API** : η οικογένεια τελικών σημείων που εξυπηρετεί η πύλη (Ολοκληρώσεις συνομιλίας, απαντήσεις, ενσωματώσεις, ήχος, εικόνες).
5. **Βάση URL** : η ρίζα API, μέχρι και `/v1` (για παράδειγμα `https://gateway.example.com/v1`), όχι η πλήρης διαδρομή `/chat/completions`. Οι πύλες με μη τυπικές διαδρομές τις ορίζουν** Προηγμένες ρυθμίσεις** (διαδρομή συνομιλίας, διαδρομή μοντέλων).
6. Ο** Κλειδί API (για έλεγχο)** Το πεδίο δοκιμάζει μόνο τη σύνδεση. Αφού δημιουργήσετε τον κόμβο, ανοίξτε τον και χρησιμοποιήστε τον** Προσθήκη σύνδεσης** για να αποθηκεύσετε το κλειδί που θα χρησιμοποιήσουν τα αιτήματα.

Ο κόμβος λαμβάνει ένα εσωτερικό αναγνωριστικό της μορφής `openai-compatible-<apiType>-<uuid>`. δεν χρειάζεται ποτέ να το πληκτρολογήσετε, το πρόθεμα είναι το δημόσιο όνομα.

#### Δεσμευμένα προθέματα

Ένα πρόθεμα δεν μπορεί να είναι το αναγνωριστικό ή το ψευδώνυμο ενός ενσωματωμένου παρόχου (για παράδειγμα `openai`, `cf`), ούτε το αναγνωριστικό ενός συνταξιούχου παρόχου. Η συσκευή επίλυσης μοντέλων ελέγχει τα ενσωματωμένα αναγνωριστικά και ψευδώνυμα πριν από προσαρμοσμένους κόμβους, επομένως ένας κόμβος που χρησιμοποιεί ένα από αυτά τα προθέματα δεν θα λαμβάνει ποτέ επισκεψιμότητα: `<prefix>/model` θα πήγαινε στον ενσωματωμένο πάροχο ή θα αποτύγχανε να κλείσει εάν αυτός ο πάροχος αποσύρθηκε. Η δημιουργία ή η επεξεργασία ενός κόμβου με τέτοιο πρόθεμα απορρίπτεται με:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

Επιλέξτε ένα διακριτό πρόθεμα (`mygw`, `acme-proxy`). Εάν τα αιτήματα σε έναν προσαρμοσμένο κόμβο αποτύχουν με ένα σφάλμα που ονομάζει έναν ενσωματωμένο πάροχο ή τα διαπιστευτήριά του, ελέγξτε εάν το πρόθεμα του κόμβου είναι δεσμευμένο: οι κόμβοι που αποθηκεύτηκαν πριν από την ύπαρξη αυτού του κανόνα εξακολουθούν να αποθηκεύονται, αλλά το πρόθεμά τους δρομολογείται στον ενσωματωμένο πάροχο. Επεξεργαστείτε τον κόμβο και δώστε του ένα νέο πρόθεμα.

#### Επιλογές πύλης ανά σύνδεση

Αυτά τα πλήκτρα μπαίνουν στο `providerSpecificData` μιας σύνδεσης (για παράδειγμα μέσω `PUT /api/providers/{id}`):

- `toolNameMaxLength` (ακέραιος, 1–1024) — για συνδέσεις συμβατές με μορφή συνομιλίας OpenAI των οποίων η πύλη απορρίπτει μεγάλα ονόματα εργαλείων. Τα μεγαλύτερα ονόματα αποστέλλονται ως σύντομα ψευδώνυμα και επαναφέρονται στην απάντηση.
- `quotaEndpoint` — το τελικό σημείο quota/credits της πύλης, διαβάστε για τη λωρίδα ορίου του πίνακα εργαλείων και τη δρομολόγηση με επίγνωση ορίων. Λειτουργεί και σε συνδέσεις συμβατές με OpenAI και Anthropic. το πλήρες σχήμα τεκμηριώνεται σε `open-sse/services/usage/openaiCompatible.ts`.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### Αλυσιδώνοντας OmniRoute Peers

Μια άλλη πύλη OmniRoute μπορεί να προστεθεί ως α** Προσαρμοσμένο OpenAI-συμβατό** προμηθευτής. Χρησιμοποιήστε τη βάση `/v1` URL του ομότιμου και ένα αποκλειστικό κλειδί API με τα λιγότερα προνόμια που εκδίδεται από αυτόν τον ομότιμο.

Για αμφίδρομες ή πολλαπλές αλυσίδες, ενεργοποιήστε το προστατευτικό βρόχου opt-in σε κάθε πύλη:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

Μόνο τα αιτήματα που αποστέλλονται σε έναν ρητά επιτρεπόμενο ομότιμο URL λαμβάνουν την κεφαλίδα `X-OmniRoute-Peer-Trace`. Μια πύλη απορρίπτει ένα επαναλαμβανόμενο παράδειγμα ID ή εξαντλημένο προϋπολογισμό hop με HTTP `508 Loop Detected`. Οι συνηθισμένοι πάροχοι ανάντη δεν λαμβάνουν ομότιμα μεταδεδομένα.

Η ομότιμη αλυσίδα δεν είναι αναπαραγωγή βάσης δεδομένων ή ανακατεύθυνση κεντρικού υπολογιστή. Κάθε πύλη διατηρεί ανεξάρτητη κατάσταση SQLite, κρυφές μνήμες, μετρητές ρυθμών και περιόδους σύνδεσης. Χρησιμοποιήστε έναν ελεγμένο αντίστροφο διακομιστή μεσολάβησης ή ανακατεύθυνση προγράμματος-πελάτη για διαθεσιμότητα active/passive ή active/active και ποτέ μην προσαρτήσετε μία βάση δεδομένων SQLite σε πολλές εκτελούμενες εμφανίσεις OmniRoute.

### Cloudflare Quick Tunnel

- Διαθέσιμο σε** Ταμπλό → Endpoints** για Docker και άλλες αυτο-φιλοξενούμενες αναπτύξεις
- Δημιουργεί ένα προσωρινό `https://*.trycloudflare.com` URL που προωθεί στο τρέχον τελικό σημείο `/v1` συμβατό με OpenAI
- Πρώτα ενεργοποιήστε εγκαθιστά `cloudflared` μόνο όταν χρειάζεται. αργότερα επανεκκινεί ξανά το ίδιο διαχειριζόμενο δυαδικό αρχείο
- Τα Quick Tunnels δεν αποκαθίστανται αυτόματα μετά από επανεκκίνηση OmniRoute ή κοντέινερ. ενεργοποιήστε τα ξανά από το ταμπλό όταν χρειάζεται
- Το Tunnel URLs είναι εφήμερο και αλλάζει κάθε φορά που stop/start το τούνελ
- Τα Managed Quick Tunnels έχουν προεπιλεγμένη μεταφορά HTTP/2 για την αποφυγή θορυβωδών προειδοποιήσεων buffer QUIC UDP σε περιορισμένα κοντέινερ
- Ορίστε `CLOUDFLARED_PROTOCOL=quic` ή `auto` εάν θέλετε να παρακάμψετε την επιλογή διαχειριζόμενης μεταφοράς
- Ορίστε `CLOUDFLARED_BIN` εάν προτιμάτε να χρησιμοποιείτε ένα προεγκατεστημένο δυαδικό `cloudflared` αντί για τη διαχειριζόμενη λήψη
- Τα πάνελ Cloudflare Quick Tunnel, Tailscale Funnel και ngrok Tunnel μπορούν να εμφανιστούν ή να κρυφτούν σε** Ρυθμίσεις → Εμφάνιση** . Η απόκρυψη ενός πίνακα δεν σταματά ένα τούνελ που τρέχει.

### LLM Gateway Intelligence (Φάση 9)

- **Σημασιολογική κρυφή μνήμη** — Αυτόματη αποθήκευση στην κρυφή μνήμη χωρίς ροή, αποκρίσεις θερμοκρασίας = 0 (παράκαμψη με `X-OmniRoute-No-Cache: true`)

- **Παρακολούθηση προόδου** — Συμμετοχή σε συμβάντα SSE `event: progress` μέσω κεφαλίδας `X-OmniRoute-Progress: true`

| **Πάγκος δοκιμής**        | Εκτελέστε ομαδικές δοκιμές σε συνδυασμούς πολλαπλών μορφών για να επαληθεύσετε την ορθότητα της μετάφρασης            |
| **Ζωντανή παρακολούθηση** | Παρακολουθήστε μεταφράσεις σε πραγματικό χρόνο καθώς τα αιτήματα ρέουν μέσω του διακομιστή μεσολάβησης                |

**Περιπτώσεις χρήσης:**

- Εντοπισμός σφαλμάτων γιατί ένας συγκεκριμένος συνδυασμός client/provider αποτυγχάνει
- Βεβαιωθείτε ότι οι ετικέτες σκέψης, οι κλήσεις εργαλείων και οι προτροπές συστήματος μεταφράζονται σωστά
- Συγκρίνετε διαφορές μορφής μεταξύ των μορφών OpenAI, Claude, Gemini και Responses API

### Στρατηγικές δρομολόγησης

Ρύθμιση παραμέτρων μέσω** Ρυθμίσεις → ταμπλό → Δρομολόγηση** . Ο πίνακας εργαλείων εκθέτει τις έξι στρατηγικές που χρησιμοποιούνται περισσότερο. Οι συνδυασμοί και ο αυτόματος δρομολογητής υποστηρίζουν εσωτερικά ένα ευρύτερο σύνολο.

**Στρατηγικές ορατές στον πίνακα ελέγχου (δρομολόγηση σε επίπεδο λογαριασμού):**

| Στρατηγική                    | Περιγραφή                                                                                                                         |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **Γεμίστε πρώτα**             | Χρησιμοποιεί λογαριασμούς με σειρά προτεραιότητας — ο κύριος λογαριασμός χειρίζεται όλα τα αιτήματα μέχρι να μην είναι διαθέσιμος |
| **Round Robin**               | Κυκλοφορεί σε όλους τους λογαριασμούς με ρυθμιζόμενο σταθερό όριο (προεπιλογή: 3 κλήσεις ανά λογαριασμό)                          |
| **P2C (Δύναμη δύο επιλογών)** | Επιλέγει 2 τυχαίους λογαριασμούς και διαδρομές προς τον πιο υγιή — εξισορροπεί το φορτίο με επίγνωση της υγείας                   |
| **Τυχαίος**                   | Επιλέγει τυχαία έναν λογαριασμό για κάθε αίτημα χρησιμοποιώντας τη τυχαία αναπαραγωγή Fisher-Yates                                |
| **Λιγότερο Μεταχειρισμένο**   | Διαδρομές στον λογαριασμό με την παλαιότερη χρονική σήμανση `lastUsedAt`, κατανέμοντας ομοιόμορφα την επισκεψιμότητα              |
| **Βελτιστοποιημένο κόστος**   | Διαδρομές προς τον λογαριασμό με τη χαμηλότερη τιμή προτεραιότητας, βελτιστοποίηση για παρόχους χαμηλότερου κόστους               |

**Προηγμένες συνδυαστικές και αυτόματες στρατηγικές** (με δυνατότητα διαμόρφωσης ανά σύνθετο ή μέσω προθεμάτων `auto/*` — βλέπε [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ):

- `priority` — αυστηρή τάξη, ποτέ στρογγυλή
- `weighted` — αναλογική επισκεψιμότητα διαιρεμένη κατά βάρη ανά μοντέλο
- `fill-first` — στραγγίστε το πρώτο μοντέλο μέχρι να φτάσουν τα όρια
- `round-robin` / `strict-random` / `random`
- `p2c` (Δύναμη δύο επιλογών)
- `least-used` και `cost-optimized`
- `auto` — βάσει βαθμολογίας σε όλους τους υποψηφίους
- `lkgp` (Τελευταίος γνωστός καλός πάροχος) — καρφιτσώνει στον τελευταίο επιτυχημένο πάροχο και μετά επιστρέφει στους κανόνες
- `context-optimized` — επιλέγει το μοντέλο με το μεγαλύτερο ελεύθερο παράθυρο περιβάλλοντος
- `context-relay` — αλυσίδες μοντέλων μεγάλου πλαισίου για επόμενες στροφές

#### Κεφαλίδα εξωτερικής κολλητικής περιόδου λειτουργίας

### Ανθεκτικότητα & διακόπτες κυκλώματος

Ρύθμιση παραμέτρων μέσω** Ρυθμίσεις → ταμπλό → Resilience** .

OmniRoute εφαρμόζει ανθεκτικότητα σε επίπεδο παρόχου με πέντε στοιχεία:

1. **Αίτημα ουράς και βηματοδότησης** — Διαμόρφωση αιτήματος σε επίπεδο συστήματος:
   - **Αιτήματα ανά λεπτό (RPM)** — Μέγιστα αιτήματα ανά λεπτό ανά λογαριασμό
   - **Ελάχιστος χρόνος μεταξύ αιτημάτων** — Ελάχιστο κενό σε χιλιοστά του δευτερολέπτου μεταξύ των αιτημάτων
   - **Μέγιστα ταυτόχρονα αιτήματα** — Μέγιστα ταυτόχρονα αιτήματα ανά λογαριασμό

2. **Ψύξη σύνδεσης** — Διαμόρφωση τύπου ανά εξουσιοδότηση για μία μόνο σύνδεση μετά από αποτυχίες με δυνατότητα επανάληψης δοκιμής:
   - **Ψύξη βάσης** — Προεπιλεγμένο παράθυρο ψύξης για αποτυχίες ανοδικής ροής με δυνατότητα επανάληψης δοκιμής
   - **Χρησιμοποιήστε τις συμβουλές για επανάληψη της ροής** — Τιμά τις έγκυρες υποδείξεις `Retry-After` ή επαναφοράς όταν παρέχονται
   - **Max Backoff Steps** — Μέγιστο εκθετικό επίπεδο backoff για επαναλαμβανόμενες αποτυχίες

3. **Διακόπτης κυκλώματος παρόχου** — Παρακολουθεί αποτυχίες παρόχου από άκρο σε άκρο, επισημαίνει έναν πάροχο που έχει υποβαθμιστεί στο διαμορφωμένο όριο προειδοποίησης και ανοίγει τον διακόπτη όταν επιτευχθεί το διαμορφωμένο όριο αποτυχίας:
   - **Όριο υποβάθμισης** — Διαδοχικές αποτυχίες παρόχου πριν από την είσοδο `DEGRADED`
   - **Όριο αποτυχίας** — Διαδοχικές αποτυχίες παρόχου πριν από την είσοδο `OPEN`
   - **Επαναφορά χρονικού ορίου** — Χρονικό παράθυρο πριν ελεγχθεί ξανά ο πάροχος
   - **CLOSED** (Υγιεινή) — Τα αιτήματα ρέουν κανονικά
   - **DEGRADED** — Τα αιτήματα εξακολουθούν να ρέουν ενώ παρακολουθούνται αυξημένες αστοχίες
   - **OPEN** — Ο πάροχος είναι προσωρινά αποκλεισμένος μετά από επανειλημμένες αποτυχίες
   - **HALF_OPEN** — Έλεγχος εάν ο πάροχος έχει ανακτήσει

   Τα όρια ποσοστού `429` με εμβέλεια σύνδεσης παραμένουν εντός** Ψύξη σύνδεσης** και μην υπολογίζετε στον διακόπτη παρόχου.

   Η κατάσταση χρόνου εκτέλεσης του διακόπτη παροχής εμφανίζεται σε** Ταμπλό → Health** μόνο.

4. **Περιμένετε για Cooldown** — Εάν κάθε υποψήφια σύνδεση κρυώνει ήδη, OmniRoute μπορεί να περιμένει για το νωρίτερο cooldown και να δοκιμάσει ξανά το ίδιο αίτημα πελάτη αυτόματα.

5. **Αυτόματος εντοπισμός ορίου ρυθμού** — Όταν οι πάροχοι ανάντη επιστρέφουν ρητά παράθυρα αναμονής, αυτές οι υποδείξεις παρακάμπτουν την ψύξη της τοπικής σύνδεσης όταν είναι ενεργοποιημένη η ρύθμιση.

**Επαγγελματική συμβουλή:** Χρησιμοποιήστε το** Υγεία** σελίδα για να επιθεωρήσετε και να επαναφέρετε τους διακόπτες ζωντανής παροχής μετά από διακοπή λειτουργίας. Η σελίδα Resilience αλλάζει μόνο τη διαμόρφωση.

### Εξαγωγή / Εισαγωγή βάσης δεδομένων

Διαχείριση αντιγράφων ασφαλείας βάσης δεδομένων σε** Ταμπλό → Ρυθμίσεις → Σύστημα & αποθήκευση** .

| Δράση                        | Περιγραφή                                                                                                                                                                                          |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Εξαγωγή βάσης δεδομένων**  | Πραγματοποιεί λήψη της τρέχουσας βάσης δεδομένων SQLite ως αρχείο `.sqlite`                                                                                                                        |
| **Εξαγωγή όλων (.tar.gz)**   | Λήψη ενός πλήρους αρχείου αντιγράφων ασφαλείας που περιλαμβάνει: βάση δεδομένων, ρυθμίσεις, συνδυασμούς, συνδέσεις παρόχου (χωρίς διαπιστευτήρια), μεταδεδομένα κλειδιού API                       |
| **Εισαγωγή βάσης δεδομένων** | Ανεβάστε ένα αρχείο `.sqlite` για να αντικαταστήσετε την τρέχουσα βάση δεδομένων. Ένα αντίγραφο ασφαλείας πριν από την εισαγωγή δημιουργείται αυτόματα εκτός εάν `DISABLE_SQLITE_AUTO_BACKUP=true` |

```bash
# API: Export database
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: Export all (full archive)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: Import database
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**Επικύρωση εισαγωγής:** Το εισαγόμενο αρχείο έχει επικυρωθεί ως προς την ακεραιότητα (έλεγχος SQLite pragma), τους απαιτούμενους πίνακες (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) και το μέγεθος (μέγιστο 100 MB).

**Περιπτώσεις χρήσης:**

- Μεταφορά OmniRoute μεταξύ μηχανών
- Δημιουργήστε εξωτερικά αντίγραφα ασφαλείας για αποκατάσταση από καταστροφή
- Κοινή χρήση διαμορφώσεων μεταξύ των μελών της ομάδας (εξαγωγή όλων των αρχείων κοινής χρήσης → )

### Συνδυαστικές στρατηγικές εξισορρόπησης

Διαμόρφωση εξισορρόπησης ανά σύνθετο σε** Ταμπλό → Combos → Create/Edit → Strategy** .

| Στρατηγική                             | Περιγραφή                                                                                        |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **Round-Robin**                        | Περιστρέφεται διαδοχικά μέσα από μοντέλα                                                         |
| **Προτεραιότητα**                      | Δοκιμάζει πάντα το πρώτο μοντέλο. επιστρέφει μόνο στο λάθος                                      |
| **Τυχαίος**                            | Επιλέγει ένα τυχαίο μοντέλο από τον συνδυασμό για κάθε αίτημα                                    |
| **σταθμισμένη**                        | Διαδρομές αναλογικά με βάση τα εκχωρημένα βάρη ανά μοντέλο                                       |
| **Λιγότερο Μεταχειρισμένο**            | Διαδρομές προς το μοντέλο με τα λιγότερα πρόσφατα αιτήματα (χρησιμοποιεί συνδυαστικές μετρήσεις) |
| **Βελτιστοποιημένο ως προς το κόστος** | Διαδρομές προς το φθηνότερο διαθέσιμο μοντέλο (χρησιμοποιεί τον πίνακα τιμολόγησης)              |

Μπορούν να οριστούν καθολικές προεπιλογές συνδυασμού** Ρυθμίσεις → ταμπλό → Δρομολόγηση → Combo προεπιλογές** . Τα σύνθετα χρονικά όρια στόχων κληρονομούν το χρονικό όριο του τρέχοντος αιτήματος από προεπιλογή. Χρήση** Χρονικό όριο λήξης στόχου (δευτερόλεπτα)** σε σύνθετες προεπιλογές ή σε μεμονωμένο συνδυασμό μόνο όταν ένα μικρότερο όριο ανά στόχο θα πρέπει να ενεργοποιεί ταχύτερη εναλλακτική.

Οι συνδυαστικές βελτιστοποιήσεις μηδενικού λανθάνοντος χρόνου είναι επιλέξιμες. Αδεια** Βελτιστοποιήσεις μηδενικής καθυστέρησης** απενεργοποιήθηκε για να αποτρέψει αυτές τις δυνατότητες λανθάνοντος χρόνου από την κούρσα εναλλακτικών στόχων, την παράλειψη στόχων με βάση το ιστορικό TTFT ή τη συμπίεση εναλλακτικών αιτημάτων. Η ενεργοποίησή του επιτρέπει τη διαμορφωμένη αντιστάθμιση, τις προγνωστικές παραλείψεις TTFT και την προληπτική εναλλακτική συμπίεση για την ανταλλαγή της πιστότητας routing/request για χαμηλότερο λανθάνοντα χρόνο.

Καθιστώ ανίκανο** Απομνημόνευση διακριτικού συλλογισμού** όταν οι ανάντη πάροχοι απαιτούν αυστηρά όρια `max_tokens` / `maxOutputTokens`. Όταν είναι ενεργοποιημένη, η συνδυαστική δρομολόγηση προσθέτει μόνο χώρο κεφαλής συλλογιστικού μοντέλου για μοντέλα με γνωστό όριο εξόδου και αφήνει το όριο διακριτικού πελάτη αμετάβλητο όταν η τιμή της ασφαλούς προσωρινής αποθήκευσης υπερβαίνει αυτό το όριο. Εάν το όριο πελάτη είναι ήδη πάνω από ένα γνωστό όριο, OmniRoute το στερεώνει σε αυτό το όριο πριν στείλει το αίτημα ανάντη.

## 🤖 Αυτόματη Δρομολόγηση (Χωρίς Ρύθμιση)

Το OmniRoute διαθέτει έναν **αυτόματο δρομολογητή βαθμολογίας** που επιλέγει το καλύτερο μοντέλο για κάθε αίτημα από όλους τους συνδεδεμένους παρόχους — χωρίς συνδυασμό προς συντήρηση. Απλώς στείλτε το αίτημα με ένα από τα προθέματα `auto/*` και το OmniRoute θα συναρμολογήσει έναν εικονικό συνδυασμό εν κινήσει, βαθμολογώντας τους υποψηφίους βάσει καθυστέρησης, κόστους, ποσοστού επιτυχίας, καταλληλότητας πλαισίου, καταλληλότητας μοντέλου για την εργασία, πρόσφατων αποτυχιών, ορίου χρήσης και κατάστασης διακόπτη κυκλώματος.

| Πρόθεμα        | Βελτιστοποιεί για                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------ |
| `auto`         | Ισορροπημένη προεπιλογή (καθυστέρηση × κόστος × ποσοστό επιτυχίας)                                                 |
| `auto/coding`  | Εργασίες κώδικα: προτιμά Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek coders                                     |
| `auto/cheap`   | Χαμηλότερο $/token, αποδέχεται υψηλότερη καθυστέρηση                                                               |
| `auto/fast`    | Χαμηλότερη καθυστέρηση, αγνοεί το κόστος                                                                           |
| `auto/offline` | Τοπικοί πάροχοι μόνο (Ollama, vLLM, llama.cpp) — χρήσιμο για απομονωμένες εγκαταστάσεις                            |
| `auto/smart`   | Ποιότητα συλλογισμού πρώτα (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)                                              |
| `auto/lkgp`    | "Τελευταίος Γνωστός Καλός Πάροχος" — καρφιτσώνει στον τελευταίο επιτυχή πάροχο, έπειτα εφαρμόζει κανόνες εφεδρείας |

Παράδειγμα:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

Ο αυτόματος δρομολογητής περιγράφεται πλήρως στο [AUTO-COMBO.md](../routing/AUTO-COMBO.md) — συμπεριλαμβανομένου του τρόπου ρύθμισης βαρών βαθμολόγησης, αποκλεισμού παρόχων και επιθεώρησης αποφάσεων δρομολόγησης στο **Dashboard → Auto Combo**.

## 🔌 Ενσωμάτωση MCP & A2A

Το OmniRoute είναι ταυτόχρονα **διακομιστής MCP** (Model Context Protocol) και **διακομιστής A2A** (Agent-to-Agent JSON-RPC 2.0). Οποιοδήποτε IDE ή περιβάλλον εκτέλεσης πράκτορα που είναι συμβατό με MCP μπορεί να καλεί εργαλεία του OmniRoute απευθείας — χωρίς επιπλέον περιτύλιγμα.

### Μεταφορές MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **Streamable HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (για πρόσθετα IDE που προτιμούν stdio)

### Σύνδεση του Claude Desktop

Επεξεργαστείτε το `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) ή το αντίστοιχο αρχείο σε Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Σύνδεση Cursor / Continue / VS Code MCP

Χρησιμοποιήστε τη διεύθυνση SSE `http://localhost:20128/api/mcp/sse` και ένα κλειδί API Bearer που δημιουργήθηκε στο **Dashboard → API Keys**.

### Εμβέλειες

Το MCP ορίζει αυτήν τη στιγμή 32 ονομαστικές εμβέλειες. Κάθε κλειδί Bearer μπορεί να περιοριστεί σε συγκεκριμένες εμβέλειες — δείτε το [MCP-SERVER.md](../frameworks/MCP-SERVER.md) για το αυθεντικό ευρετήριο εμβελειών και εργαλείων, και το [A2A-SERVER.md](../frameworks/A2A-SERVER.md) για το σχήμα JSON-RPC.

## 💾 Σύστημα Μνήμης

Το OmniRoute διατηρεί **μακροπρόθεσμη συνομιλιακή μνήμη** με υβριδική ανάκτηση:

- **SQLite FTS5** για αναζήτηση με λέξεις-κλειδιά σε προηγούμενες συνομιλίες

Διαχειριστείτε τις μνήμες στο **Dashboard → Memory** (αναζήτηση, επεξεργασία, εξαγωγή, εκκαθάριση). Η επιφάνεια HTTP (`/api/memory/*`) επιτρέπει στους agents να ωθούν και να αναζητούν γεγονότα μέσω προγράμματος — δείτε [MEMORY.md](../frameworks/MEMORY.md).

## 🔔 Webhooks

Εγγραφείτε σε συμβάντα του OmniRoute για παρακολούθηση και αυτοματισμό σε πραγματικό χρόνο.

- Δημιουργήστε ένα webhook στο **Dashboard → Webhooks** με URL προορισμού και μυστικό υπογραφής HMAC

- Επαναλήψεις: 3 προσπάθειες με εκθετική καθυστέρηση, έπειτα ουρά νεκρών γραμμάτων

## 🛠️ Προγραμματιστική Διαχείριση

Μπορείτε να διαχειριστείτε κάθε πόρο του OmniRoute (παρόχους, combos, κλειδιά, ρυθμίσεις) μέσω HTTP χρησιμοποιώντας ένα **Bearer κλειδί με την εμβέλεια `manage`**.

Δημιουργήστε το κλειδί στο **Dashboard → API Keys → New Key → Scope: manage**, και στη συνέχεια:

```bash
# Λίστα παρόχων
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Προσθήκη σύνδεσης παρόχου
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Δημιουργία combo
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Λίστα/δημιουργία κλειδιών API
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

Δείτε το [API_REFERENCE.md](../reference/API_REFERENCE.md) για τον πλήρη κατάλογο endpoints και τα σχήματα αιτημάτων/αποκρίσεων.

## 💻 Εσωτερικό CLI

Το OmniRoute διαθέτει ένα εσωτερικό CLI (`omniroute …`) για εγκατάσταση, διαγνωστικά και έλεγχο χρόνου εκτέλεσης. Αυτό είναι **ξεχωριστό από τη σελίδα "CLI Tools" στον πίνακα ελέγχου**, η οποία διαμορφώνει CLIs τρίτων (Claude Code, Cursor, Codex, Cline, …) ώστε να επικοινωνούν με το OmniRoute.

```bash
omniroute setup                    # Διαδραστικός οδηγός (κωδικός πρόσβασης, πάροχοι, combos)
omniroute setup --non-interactive  # Κατάλληλο για CI
omniroute doctor                   # Διαγνωστικά υγείας (data dir, DB, πάροχοι, θύρες)
omniroute providers available      # Λίστα υποστηριζόμενων παρόχων
omniroute providers list           # Λίστα διαμορφωμένων συνδέσεων
omniroute providers test <id>      # Δοκιμή σύνδεσης παρόχου σε πραγματικό χρόνο
omniroute combos list              # Λίστα combos
omniroute combos switch <name>     # Ορισμός προεπιλεγμένου combo
omniroute models                   # Λίστα διαθέσιμων μοντέλων (--json, --search)
omniroute keys add | list | remove # Διαχείριση κλειδιών API από το τερματικό
omniroute backup                   # Στιγμιότυπο διαμόρφωσης + DB
omniroute restore [<timestamp>]    # Επαναφορά από στιγμιότυπο
omniroute health                   # Λεπτομερής υγεία (breakers, cache, μνήμη)
omniroute quota                    # Χρήση ορίου παρόχου
omniroute mcp status               # Κατάσταση διακομιστή MCP
omniroute a2a status               # Κατάσταση διακομιστή A2A
omniroute tunnel list|create|stop  # Tunnels Cloudflare/Tailscale/ngrok
omniroute reset-password           # Επαναφορά κωδικού πρόσβασης διαχειριστή
omniroute --mcp                    # Εκκίνηση διακομιστή MCP μέσω stdio
omniroute --port 3000              # Εκκίνηση διακομιστή σε προσαρμοσμένη θύρα
```

Συμβουλή: συνδυάστε το `omniroute doctor --json` με το εργαλείο παρακολούθησής σας για ειδοποιήσεις σε μη υγιείς συνδέσεις παρόχων.
