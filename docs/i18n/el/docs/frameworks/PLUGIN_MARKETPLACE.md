> **Πηγή αλήθειας:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/` και
> `src/app/(dashboard)/dashboard/plugins/`
> **Τελευταία ενημέρωση:** 2026-06-28 — v3.8.40

Το OmniRoute περιλαμβάνει ένα σύστημα προσθηκών τύπου WordPress. Οι προσθήκες είναι αυτοτελείς
κατάλογοι — καθένας με ένα μανιφέστο `plugin.json` και ένα αρχείο εισόδου — οι οποίοι συνδέονται
στη διοχέτευση αιτημάτων (`onRequest` / `onResponse` / `onError`) και στα
συμβάντα κύκλου ζωής (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`).

Το **Marketplace προσθηκών** είναι το επίπεδο εντοπισμού πάνω από αυτό το σύστημα. Παρέχει
έναν κατάλογο διαθέσιμων προς εγκατάσταση προσθηκών, στον οποίο μπορείτε να περιηγηθείτε. Από προεπιλογή, ο κατάλογος είναι ένα
μικρό ενσωματωμένο αρχικό μητρώο· ένας διαχειριστής μπορεί να τον κατευθύνει σε μια προσαρμοσμένη απομακρυσμένη
URL μητρώου, οπότε η ανάκτηση ενισχύεται με έναν μηχανισμό προστασίας από SSRF που επιλύει DNS
(βλ. [Ασφάλεια](#security)).

Κάθε διαδρομή προσθηκών είναι **μόνο για loopback** (Βαθμίδα 1 — `LOCAL_ONLY`): οι προσθήκες φορτώνουν
και εκτελούν κώδικα σε θυγατρικές διεργασίες, επομένως οι διαδρομές δεν είναι προσβάσιμες από
προέλευση εκτός loopback, ανεξάρτητα από τον έλεγχο ταυτότητας. Βλ.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md).

## Πώς ταιριάζει Together

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **Επίπεδο μητρώου** — `src/lib/plugins/marketplace.ts`: παραθέτει / πραγματοποιεί αναζήτηση στον κατάλογο, επιστρέφοντας στο μητρώο σπόρων σε περίπτωση αποτυχίας.
- **Στρώμα κύκλου ζωής** — `src/lib/plugins/manager.ts` (`pluginManager` singleton): εγκατάσταση, αναβάθμιση, ενεργοποίηση, απενεργοποίηση, απεγκατάσταση, σάρωση, φόρτωση εκκίνησης.
- **Προφανές στρώμα** — `src/lib/plugins/manifest.ts`: Zod σχήμα + προεπιλογή για `plugin.json`.
- **Ερευνητής** — `src/lib/plugins/scanner.ts`: ανακαλύπτει πρόσθετα στο δίσκο κάτω από τον κατάλογο των προσθηκών.
- **Φορτωτής** — `src/lib/plugins/loader.ts`: δημιουργεί κάθε πρόσθετο σε μια ξεχωριστή θυγατρική διαδικασία Node.js και οι μεσίτες συνδέουν τις κλήσεις μέσω IPC. Το παιδί δεν είναι sandbox (δείτε "Απομόνωση εκτέλεσης προσθήκης" παρακάτω).

## Κατάλογος Marketplace

Η `listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) επιστρέφει μια λίστα από
αντικείμενα `MarketplaceEntry`:

| Πεδίο         | Τύπος    | Σημειώσεις                                       |
| ------------- | -------- | ------------------------------------------------ |
| `name`        | string   | Όνομα προσθήκης σε μορφή kebab-case              |
| `version`     | string   | semver                                           |
| `description` | string   | Σύντομη περίληψη                                 |
| `author`      | string   | Δημιουργός / οργανισμός                          |
| `license`     | string   | Αναγνωριστικό άδειας τύπου SPDX                  |
| `downloadUrl` | string   | URL λήψης πηγής (ενδέχεται να είναι κενή)        |
| `repository`  | string?  | Προαιρετική URL αποθετηρίου                      |
| `tags`        | string[] | Ετικέτες αναζήτησης/φιλτραρίσματος               |
| `downloads`   | number   | Πλήθος λήψεων                                    |
| `rating`      | number   | 0–5                                              |
| `verified`    | boolean  | Αν η καταχώριση έχει επισημανθεί ως επαληθευμένη |
| `lastUpdated` | string   | Συμβολοσειρά ημερομηνίας τύπου ISO               |

Όταν δεν έχει διαμορφωθεί προσαρμοσμένη URL μητρώου, ο κατάλογος είναι το ενσωματωμένο
`SEED_REGISTRY` (επί του παρόντος `request-logger`, `rate-limiter`, `cost-tracker` και
`theme-manager`). Το αρχικό μητρώο είναι πάντα διαθέσιμο — εάν ένα διαμορφωμένο απομακρυσμένο
μητρώο δεν είναι προσβάσιμο, επιστρέψει κατάσταση διαφορετική από `200` ή επιστρέψει μη αναγνωρισμένο
σώμα, η `listMarketplacePlugins()` καταγράφει μια προειδοποίηση και επιστρέφει στην αρχική λίστα.

> Σημείωση: ο **κατάλογος** του marketplace (περιήγηση/αναζήτηση) είναι συνδεδεμένος από άκρο σε άκρο, αλλά
> η **εγκατάσταση** με ένα κλικ από τον κατάλογο του marketplace δεν έχει υλοποιηθεί ακόμη — το
> κουμπί "Εγκατάσταση" του πίνακα ελέγχου σε μια καταχώριση marketplace εμφανίζει προς το παρόν μια
> ειδοποίηση "προσεχώς". Σήμερα, η εγκατάσταση πραγματοποιείται μέσω της ροής εγκατάστασης από τοπική διαδρομή
> (`POST /api/plugins`) και του εντοπισμού στον δίσκο (`POST /api/plugins/scan`).

## REST API

Όλα τα τελικά σημεία απαιτούν εξουσιοδότηση διαχείρισης (`requireManagementAuth`)** και** είναι μόνο για loopback — `/api/plugins` και `/api/plugins/` παρατίθενται στο `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`).

| Τελικό σημείο                    | Μέθοδος | Περιγραφή                                                                    |
| -------------------------------- | ------- | ---------------------------------------------------------------------------- |
| `/api/plugins`                   | GET     | Λίστα εγκατεστημένων προσθηκών (προαιρετικό φίλτρο `?status=` )              |
| `/api/plugins`                   | POST    | Εγκαταστήστε μια προσθήκη από τον κατάλογο πηγών προσθηκών                   |
| `/api/plugins/scan`              | POST    | Σαρώστε τον κατάλογο των προσθηκών και καταχωρήστε νέες προσθήκες            |
| `/api/plugins/marketplace`       | GET     | Καταχωρίστε τις καταχωρήσεις καταλόγου της αγοράς                            |
| `/api/plugins/[name]`            | GET     | Λάβετε λεπτομέρειες εγκατεστημένης προσθήκης                                 |
| `/api/plugins/[name]`            | DELETE  | Απεγκαταστήστε μια προσθήκη                                                  |
| `/api/plugins/[name]/activate`   | POST    | Ενεργοποίηση (φόρτωση αγκίστρων εγγραφής + )                                 |
| `/api/plugins/[name]/deactivate` | POST    | Απενεργοποίηση (απενεργοποίηση `onDeactivate`, κατάργηση εγγραφής αγκίστρων) |
| `/api/plugins/[name]/config`     | GET     | Λήψη σχήματος ρύθμισης παραμέτρων + της προσθήκης                            |
| `/api/plugins/[name]/config`     | PUT     | Ενημέρωση διαμόρφωσης προσθήκης (επικυρωμένη βάσει σχήματος)                 |

Το φίλτρο `GET /api/plugins` `status` δέχεται ένα από τα `installed` / `active` / `inactive` / `error`. Μια μη έγκυρη τιμή επιστρέφει `400`.

### Λίστα εγκατεστημένων προσθηκών

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### Εγκατάσταση από τοπικό μονοπάτι

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

Το `path` πρέπει να είναι ένα** απόλυτος** διαδρομή προς έναν κατάλογο** μέσα στον κατάλογο πηγών προσθήκης** : `plugin-sources` δίπλα στη ρίζα της προσθήκης, άρα `~/.omniroute/plugin-sources/` από προεπιλογή ή `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` όταν έχει οριστεί αυτή η μεταβλητή (`getPluginSourcesDir()` σε `src/lib/plugins/installSource.ts`). Αντιγράψτε ή κλωνοποιήστε πρώτα το πρόσθετο εκεί. Η εγκατάσταση απορρίπτεται με `400` όταν η διαδρομή περιέχει `..` ή ένα μηδενικό byte, βρίσκεται εκτός αυτού του καταλόγου, επιλύεται εκτός αυτού μέσω ενός συμβολικού συνδέσμου, περιέχει έναν συμβολικό σύνδεσμο του οποίου ο στόχος βρίσκεται εκτός αυτού ή όταν ο κατάλογος δεν υπάρχει. Ο κατάλογος πηγής πρέπει να περιέχει ένα έγκυρο `plugin.json` (ή να είναι γονέας ενός). Σε επιτυχία η απόκριση είναι `201` με την εγκατεστημένη σειρά πρόσθετων.

Σε αντίθεση με τις άλλες διαδρομές προσθήκης, αυτή απαιτεί τα διαπιστευτήρια διαχείρισης (μια περίοδο λειτουργίας πίνακα εργαλείων ή ένα κλειδί API με εύρος διαχείρισης) ακόμη και όταν η σύνδεση είναι απενεργοποιημένη (`requireLogin=false`): η εγκατάσταση κώδικα δεν είναι ποτέ μια ανώνυμη ενέργεια.

### Περιηγηθείτε στην αγορά

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### Ενημέρωση παραμέτρων προσθήκης

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` επικυρώνει κάθε παρεχόμενη τιμή έναντι του `configSchema` της προσθήκης (δηλώνεται στη δήλωση): τα πεδία `number` τιμούν `min`/`max`, τα πεδία `select` πρέπει να ταιριάζουν με το δηλωμένο `enum`. Τα κλειδιά που δεν υπάρχουν στο σχήμα επιτρέπονται.

## Ρύθμιση παραμέτρων

### Κατάλογος plugins

Τα plugins βρίσκονται στον κατάλογο δεδομένων του OmniRoute:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (ή οποιοδήποτε αρχείο υποδεικνύει το manifest.main)
```

Η `getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) επιλύει αυτόν τον κατάλογο σε
τρία βήματα:

1. **`OMNIROUTE_PLUGINS_DIR`**, όταν έχει οριστεί — χρησιμοποιείται αυτούσιο, ανεξάρτητα από την τιμή του `HOME`. Αυτό είναι
   το ρητό στοιχείο ελέγχου για Docker/K8s, όπου το δέντρο των plugins προσαρτάται μέσω bind mount σε μια διαδρομή
   που συνήθως δεν σχετίζεται καθόλου με τον αρχικό κατάλογο του container (#11827).
2. `<home>/.omniroute/plugins`, όπου το `<home>` προέρχεται από τις μεταβλητές περιβάλλοντος `HOME` / `USERPROFILE`.
3. `/tmp/.omniroute/plugins`, όταν η διεργασία δεν εξάγει καθόλου αρχικό κατάλογο.

Ο επιλυμένος κατάλογος καταγράφεται μία φορά κατά την εκκίνηση ως `scanner.dir_resolved`, αναφέροντας την
είσοδο που επικράτησε (`OMNIROUTE_PLUGINS_DIR`, `home` ή `no-home-fallback`) — έτσι, ένα image
που καταλήγει σιωπηρά στο βήμα 3 το αναφέρει, αντί να εμφανίζει απλώς μια κενή λίστα plugins.
Το `POST /api/plugins/scan` εντοπίζει οποιονδήποτε υποκατάλογο εκεί που περιέχει έγκυρο
`plugin.json` και τον καταχωρίζει· ο ίδιος κατάλογος αποτελεί τη ρίζα στην οποία η
`pluginManager.install()` αντιγράφει τα plugins, επομένως μια παράκαμψη μετακινεί μαζί την ανακάλυψη και
την εγκατάσταση.

> **Το `OMNIROUTE_PLUGINS_DIR` δεν είναι το `OMNIROUTE_PLUGIN_PATH`.** Το δεύτερο διαβάζεται μόνο από
> τον φορτωτή command-plugin του CLI (`bin/cli/plugins.mjs`) για την εύρεση npm πακέτων `omniroute-cmd-*`
> που προσθέτουν υποεντολές στο `omniroute` — δεν επηρεάζει τον σαρωτή χρόνου εκτέλεσης
> που περιγράφεται εδώ. Δείτε το [PLUGINS.md](./PLUGINS.md) για αυτήν την πλευρά.

### Προσαρμοσμένο URL μητρώου marketplace

Η προέλευση του καταλόγου marketplace διαβάζεται από τη ρύθμιση `pluginMarketplaceUrl`
(το `src/lib/plugins/marketplace.ts` διαβάζει το `settings.pluginMarketplaceUrl`). Όταν
ορίζεται σε ένα URL `http(s)`, η `listMarketplacePlugins()` ανακτά αυτό το URL και δέχεται
είτε έναν πίνακα JSON ανώτατου επιπέδου με καταχωρίσεις είτε ένα αντικείμενο με πίνακα `plugins`·
οι καταχωρίσεις χωρίς `name` τύπου string φιλτράρονται. Όταν δεν έχει οριστεί (ή όταν η ανάκτηση
αποτυγχάνει λόγω του ελέγχου SSRF / επιστρέφει μη έγκυρη απόκριση), χρησιμοποιείται το ενσωματωμένο αρχικό μητρώο.

Η καρτέλα "Marketplace" του dashboard παρέχει ένα πεδίο για αυτό το URL (το οποίο ανακτάται από το
`GET /api/settings`).

> Σημείωση υλοποίησης: η ενέργεια "Save" του dashboard στέλνει το
> `pluginMarketplaceUrl` στο `PATCH /api/settings`. Κατά τη σύνταξη αυτού του κειμένου, αυτό το
> κλειδί δεν δηλώνεται στο `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`), επομένως επαληθεύστε τη διατήρησή του στη δική σας
> έκδοση προτού βασιστείτε σε αυτό — η διαδρομή **ανάγνωσης** (`getSettings()` →
> `listMarketplacePlugins()`) λαμβάνει υπόψη το κλειδί μόλις αυτό υπάρχει στον χώρο αποθήκευσης
> ρυθμίσεων.

## Ασφάλεια

### Διαδρομή επιπέδων — loopback μόνο

Τα πρόσθετα εκτελούν κώδικα σε γεννημένες θυγατρικές διεργασίες, επομένως ολόκληρη η επιφάνεια `/api/plugins` ταξινομείται `LOCAL_ONLY` (Tier 1). Η επιβολή Loopback εκτελείται άνευ όρων** προτού** οποιονδήποτε έλεγχο ταυτότητας, επομένως ένα διακριτικό διαχείρισης που διέρρευσε και φτάνει στο κουτί μέσω μιας σήραγγας εξακολουθεί να μην μπορεί να εγκαταστήσει, να ενεργοποιήσει ή να απεγκαταστήσει μια προσθήκη. Δείτε [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) και Hard Rules #15 / #17.

### Μητρώο αγοράς SSRF guard

Ένα προσαρμοσμένο μητρώο URL είναι ρύθμιση παραμέτρων που επηρεάζει τους εισβολείς, επομένως πριν από τη λήψη του, `listMarketplacePlugins()` το εκτελεί σε δύο επίπεδα:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - Απορρίπτει οτιδήποτε δεν είναι `http:` / `https:`.
   - Απορρίπτει τους κυριολεκτικούς κεντρικούς υπολογιστές private/loopback/link-local/ULA (IPv4** και** IPv6, συμπεριλαμβανομένου IPv4-mapped) μέσω του κανονικού `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`).
   - Επιλύει** και οι δύο** `A` και `AAAA` καταγράφει και απορρίπτει το αν** κάθε** Η λυμένη διεύθυνση είναι ιδιωτική — κλείνοντας την παράκαμψη δημόσιου κεντρικού υπολογιστή → private-IP.
   - **Αποτυχία κλειστό** : μια αποτυχία ανάλυσης DNS απορρίπτει το URL.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): εφαρμόζει εκ νέου το δημόσιο προστατευτικό URL μόνο κατά την ανάκτηση και** μπλοκ ανακατευθύνσεις** (χωρίς δημόσιο → ιδιωτικό `30x` pivot).

Ένα URL που αποτυγχάνει σε κανένα επίπεδο δεν ματαιώνει το αίτημα —

> Αυτός ο προφυλακτήρας σκληρύνθηκε σε PR #3774 ειδικά για να επιλύσει το A + AAAA και να χρησιμοποιήσει το κανονικό `isPrivateHost` αντί για έναν έλεγχο IPv4-only.

### Απομόνωση εκτέλεσης προσθηκών

> **Τα πρόσθετα δεν είναι sandbox.** Το παιδί είναι μια συνηθισμένη διεργασία Node.js που εκτελείται ως χρήστης OmniRoute, χωρίς πλαίσιο VM και σημαίες δικαιωμάτων Node.js, επομένως ο κώδικας προσθήκης μπορεί να διαβάσει και να γράψει οποιοδήποτε αρχείο μπορεί ο χρήστης, να εκτελεί προγράμματα και να φτάσει στο δίκτυο. `requires.permissions` αποφασίζει μόνο ποιες μεταβλητές περιβάλλοντος θα λάβει το παιδί. οι άλλες άδειες δεν επιβάλλονται. Εγκαταστήστε μόνο προσθήκες που εμπιστεύεστε. Το όριο της διαδικασίας παρακάτω περιέχει σφάλματα και κολλάει. δεν είναι όριο ασφαλείας.

- **Απομόνωση διαδικασίας** — `loadPlugin()` (`src/lib/plugins/loader.ts`) δημιουργεί κάθε πρόσθετο σε μια ξεχωριστή θυγατρική διεργασία Node.js και επικοινωνεί μέσω IPC. Οι κλήσεις Hook έχουν χρονικό όριο με κλιμάκωση `SIGTERM` → `SIGKILL`.
- **Env λίστα επιτρεπόμενων** — το παιδί λαμβάνει μόνο ένα επιτρεπόμενο σύνολο μεταβλητών περιβάλλοντος. το ευρύτερο σύνολο χορηγείται μόνο όταν το μανιφέστο ζητά την άδεια `env`.
- **Εγκαταστήστε τον περιορισμό πηγής** — `POST /api/plugins` διαβάζει μόνο από τον κατάλογο πηγών πρόσθετων (βλ. "Εγκατάσταση από τοπική διαδρομή"): η διαδρομή είναι κανονικοποιημένη με `realpath`, πρέπει να παραμένει αυστηρά μέσα σε αυτόν τον κατάλογο και ένα δέντρο προέλευσης που φέρει συμβολικό σύνδεσμο που διαφεύγει απορρίπτεται πριν αντιγραφεί οτιδήποτε.
- **Περιορισμός διαδρομής** — install/upgrade/uninstall βεβαιώνουν ότι ο κατάλογος των προσθηκών και `manifest.main` επιλύονται** εντός** τη διαχειριζόμενη ρίζα προσθήκης πριν από οποιαδήποτε αντιγραφή ή επαναλαμβανόμενη διαγραφή (προστατεύει από παραποιημένες διαδρομές DB και διέλευση `../` στο `manifest.main`). Η ενεργοποίηση επιλύει τους συμβολικούς συνδέσμους μέσω `realpath` και αρνείται να φορτώσει ένα σημείο εισόδου που διαφεύγει από τον κατάλογο των προσθηκών.
- **Προαιρετική ακίδα ακεραιότητας** — ένα μανιφέστο μπορεί να δηλώσει ένα πεδίο `integrity` (`sha256-<base64>`, μορφή SRI ). Όταν υπάρχει, το πρόγραμμα φόρτωσης επαληθεύει τον κατακερματισμό του αρχείου καταχώρισης κατά τη φόρτωση και αρνείται να ενεργοποιήσει σε περίπτωση αναντιστοιχίας. Είναι opt-in ανίχνευση παραβίασης,** δεν** ένα όριο ασφαλείας: δεν περιορίζει τι μπορεί να κάνει μια φορτωμένη προσθήκη.
- **Δεν υπάρχουν διαπιστευτήρια πελάτη στα hook** — το περιβάλλον που μεταβιβάστηκε στα `onRequest`, `onResponse` και `onError` έχει αφαιρέσει τις κεφαλίδες `authorization`, `x-api-key`, `proxy-authorization` και `cookie` και η εγγραφή κλειδιού API δεν φέρει καμία τιμή κλειδιού (`redactPluginContext()` σε `src/lib/plugins/hooks.ts`).

## Μανιφέστο (`plugin.json`)

Επικυρώθηκε από `PluginManifestSchema` (`src/lib/plugins/manifest.ts`):

| Πεδίο              | Τύπος          | Σημειώσεις                                                       |
| ------------------ | -------------- | ---------------------------------------------------------------- |
| `name`             | σειρά          | Υποχρεούμαι; κεμπάπ-θήκη (`^[a-z0-9-]+$`), 1–100 χαρακτήρες      |
| `version`          | σειρά          | Υποχρεούμαι; semver (`MAJOR.MINOR.PATCH`)                        |
| `description`      | σειρά;         | ≤ 500 χαρακτήρες                                                 |
| `author`           | σειρά;         | ≤ 200 χαρακτήρες                                                 |
| `license`          | σειρά;         | Προεπιλογές σε `MIT`                                             |
| `main`             | σειρά;         | Αρχείο καταχώρισης? προεπιλογή σε `index.js`                     |
| `source`           | enum;          | `local` \| `marketplace` (προεπιλογή σε `local`)                 |
| `tags`             | σειρά[];       | Αναζήτηση ετικετών                                               |
| `requires`         | αντικείμενο;   | `{ omniroute?, permissions[] }`                                  |
| `hooks`            | αντικείμενο;   | Booleans που δηλώνουν ποια αγκίστρια εφαρμόζει το πρόσθετο       |
| `skills`           | αντικείμενο[]; | Προαιρετικοί ορισμοί δεξιοτήτων                                  |
| `enabledByDefault` | boolean;       | Αυτόματη ενεργοποίηση κατά την εγκατάσταση                       |
| `configSchema`     | αντικείμενο;   | Χάρτης πεδίων διαμόρφωσης (`string`/`number`/`boolean`/`select`) |
| `integrity`        | σειρά;         | Προαιρετική καρφίτσα καταχώρησης αρχείου `sha256-<base64>`       |

Τα δικαιώματα αντλούνται από το enum `network` / `file-read` / `file-write` / `env` / `exec`. Μόνο `env` έχει αποτέλεσμα χρόνου εκτέλεσης (μια ελαφρώς μεγαλύτερη λίστα επιτρεπόμενων μεταβλητών περιβάλλοντος για το παιδί). τα άλλα είναι διακηρύξεις και δεν εκτελούνται.

## Ροή κύκλου ζωής

```
εγκατάσταση (POST /api/plugins, διαδρομή)
  → σάρωση/επικύρωση manifest → αντιγραφή σε staging → επιβεβαίωση ότι το main βρίσκεται εντός του καταλόγου
  → ατομική μετονομασία σε ~/.omniroute/plugins/<name> → εισαγωγή εγγραφής στη βάση δεδομένων
  → ενεργοποίηση του onInstall → αν enabledByDefault: ενεργοποίηση

ενεργοποίηση (POST /api/plugins/{name}/activate)
  → έλεγχος περιορισμού realpath → loadPlugin() (εκκίνηση θυγατρικής διεργασίας)
  → καταχώριση δηλωμένων hooks → status = "active" → ενεργοποίηση του onActivate

απενεργοποίηση (POST /api/plugins/{name}/deactivate)
  → ενεργοποίηση του onDeactivate (ΠΡΙΝ από την κατάργηση καταχώρισης) → κατάργηση καταχώρισης των hooks
  → τερματισμός θυγατρικής διεργασίας → status = "inactive"

απεγκατάσταση (DELETE /api/plugins/{name})
  → απενεργοποίηση αν είναι ενεργό → ενεργοποίηση του onUninstall
  → αναδρομική διαγραφή του καταλόγου του plugin με έλεγχο περιορισμού → διαγραφή εγγραφής από τη βάση δεδομένων
```

Η εκ νέου εκτέλεση του `install` σε έναν κατάλογο του οποίου η έκδοση manifest είναι **αυστηρά
νεότερη** από την εγκατεστημένη έκδοση πραγματοποιεί αυτόματη αναβάθμιση (καθαρή επανεγκατάσταση· η διαμόρφωση επαναφέρεται
στις προεπιλογές). Μια ίδια ή παλαιότερη έκδοση απορρίπτεται.

## Ταμπλό

Η σελίδα του πίνακα ελέγχου στο `/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) παρέχει δύο καρτέλες:

- **Εγκατεστημένο** — παραθέτει τις εγκατεστημένες προσθήκες με τα δηλωμένα άγκιστρα, μια εναλλαγή activate/deactivate, ένα κουμπί απεγκατάστασης και μια ενέργεια "Σάρωση για προσθήκες" (`POST /api/plugins/scan`).
- **Αγορά** — εμφανίζει τον κατάλογο από `GET /api/plugins/marketplace` με ένα πεδίο για να ορίσετε το προσαρμοσμένο μητρώο URL.

Η σελίδα εμφανίζει πάντα μια προειδοποίηση ότι τα πρόσθετα εκτελούνται με τα πλήρη προνόμια της διαδικασίας OmniRoute.

Μια σελίδα διαμόρφωσης ανά πρόσθετο ζει στο `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`).
