> **Εκδοχή:** v3.8.44** Τελευταία ενημέρωση:** 28-10-2026** Ακροατήριο:** Μηχανικοί που προσθέτουν, συντηρούν ή διορθώνουν ενσωματωμένες υπηρεσίες (9Router, CLIProxyAPI, Mux, Bifrost, open-wa, LLMLingua, sing-box).

Οι ενσωματωμένες υπηρεσίες είναι τοπικά εγκατεστημένα εργαλεία διεργασίας sidecar που OmniRoute εγκαθιστά, επιβλέπει και εκθέτει ως στόχους δρομολόγησης πρώτης κατηγορίας. Σε αντίθεση με τους εξωτερικούς παρόχους (που προσεγγίζονται μέσω του Διαδικτύου μέσω κλειδιών API ), οι ενσωματωμένες υπηρεσίες εκτελούνται στον ίδιο υπολογιστή με OmniRoute και επικοινωνούν μέσω loopback.

### Διαχειριζόμενοι πυρήνες διακομιστή μεσολάβησης

Το πεδίο κεντρικού υπολογιστή προσαρμοσμένου διακομιστή μεσολάβησης δέχεται επίσης έναν σύνδεσμο πηγής V2Ray. Επιλέγω** sing-box** ή** Ακτινογραφία** ρητά και, στη συνέχεια, κάντε κλικ στην επιλογή Αποθήκευση. Η πληκτρολόγηση δεν κατεβάζει ή δεν ξεκινά ποτέ έναν πυρήνα. Η Αποθήκευση επαληθεύει το επίσημο αρχείο κυκλοφορίας, επικυρώνει τις εγγενείς ρυθμίσεις παραμέτρων, ξεκινά ένα ξεχωριστό πρόγραμμα ακρόασης localhost SOCKS και μόνο τότε γράφει την εκχώρηση μητρώου διακομιστή μεσολάβησης. Η αποτυχημένη ενεργοποίηση επαναφέρει την προηγούμενη διαχειριζόμενη διαμόρφωση και διαδικασία. `STORAGE_ENCRYPTION_KEY` απαιτείται? οι σύνδεσμοι πηγής είναι κρυπτογραφημένοι.

Τα διαχειριζόμενα αρχεία βρίσκονται υπό `DATA_DIR/services/managed-proxy/`, ξεχωριστά από TPROXY. Υπάρχει μία ιδιόκτητη διαδικασία ανά επιλεγμένο πυρήνα, έως και 100 ακροατές. Δεν έχει αλλάξει καμία προεπιλογή αυτόματης εκκίνησης ή καθολικής δρομολόγησης. Η επιτυχής αποθήκευση θυμάται την ενεργοποίηση μόνο για αυτόν τον διαχειριζόμενο πυρήνα. Η εκκίνηση της εφαρμογής επαναφέρει τους ενεργοποιημένους αποθηκευμένους πυρήνες χρησιμοποιώντας το ήδη επαληθευμένο δυαδικό αρχείο και ποτέ λήψη κατά την εκκίνηση. Η ρητή διακοπή διαγράφει αυτήν τη σημαία ενεργοποίησης. Ένα δυαδικό αρχείο που λείπει ή έχει καταστραφεί απαιτεί εκ νέου αποθήκευση μιας πηγής. Η διαγραφή μητρώου καταργεί την πηγή και το πρόγραμμα ακρόασης τοπικά. Οι συνήθεις επεξεργασίες τελικού σημείου απορρίπτονται για τις διαχειριζόμενες σειρές, έτσι ώστε η αποθηκευμένη πηγή να μην μπορεί να απομακρυνθεί σιωπηλά από τη δρομολογημένη ακροατή της.

| Μορφή πηγής                           | sing-box                                                                                         | Ακτινογραφία                                                                                     |
| ------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| VLESS, VMess, Trojan, Shadowsocks URI | Υποστηριζόμενη μετατροπή                                                                         | Υποστηριζόμενη μετατροπή                                                                         |
| Hysteria2/hy2, TUIC, AnyTLS URI       | Υποστηριζόμενη μετατροπή                                                                         | Απορρίφθηκε; χρησιμοποιήστε έναν συμβατό πυρήνα                                                  |
| TCP/raw, WebSocket, gRPC, HTTPUpgrade | Υποστηρίζεται για VLESS/VMess/Trojan                                                             | Υποστηρίζεται για VLESS/VMess/Trojan                                                             |
| XHTTP URI μεταφορά                    | Απορρίφθηκε                                                                                      | Υποστηριζόμενη μετατροπή                                                                         |
| Εγγενής εξερχόμενη JSON               | Επιτρεπόμενος διακομιστής μεσολάβησης του επιλεγμένου πυρήνα protocols/options, ελεγμένο εγγενώς | Επιτρεπόμενος διακομιστής μεσολάβησης του επιλεγμένου πυρήνα protocols/options, ελεγμένο εγγενώς |

Άγνωστες επιλογές καλωδίων, μη ασφαλείς σημαίες TLS, εξωτερικές προσθήκες, επιλογές τοπικών διαδρομών αρχείου και μη υποστηριζόμενοι συνδυασμοί απορρίπτονται αντί να απορρίπτονται σιωπηλά. Τα εγγενή αντικείμενα είναι εξερχόμενοι ορισμοί, όχι διαμορφώσεις ολόκληρου του πυρήνα. Τα εξερχόμενα control/direct/bypass δεν γίνονται δεκτά. WireGuard στο sing-box 1.14 χρησιμοποιεί τελικά σημεία, επομένως δεν γίνεται αποδεκτό ως εγγενές εξερχόμενο. Αυτός δεν είναι μετατροπέας όλων των μορφών. Οι σύνδεσμοι SSR, παλαιού τύπου whole-base64 Shadowsocks, αυθαίρετα αντικείμενα Clash και παραλλαγές μεταφοράς που λείπουν από τον πίνακα χρειάζονται ξεχωριστά υποστηριζόμενη μορφή πηγής.

`/api/services/managed-proxy` είναι ελεγμένο και μόνο για επαναφορά: GET παραθέτει τα μεταδεδομένα που έχουν διορθωθεί, POST αποθηκεύει `{core,name,sourceLink,id?,assignment?}`, PATCH δέχεται `{core,action:"start"|"stop"}`. Πρέπει να υπάρχει η αξιόπιστη γραμμή ομότιμων σφραγίδων του οικοδεσπότη. Τα εγγενή διαγνωστικά πυρήνα αποκρύπτονται επειδή μπορεί να περιέχουν διαπιστευτήρια. Τα συμβάντα κύκλου ζωής χρησιμοποιούν το υπάρχον καταγραφικό αρχείων δομημένης εφαρμογής χωρίς συνδέσμους πηγής ή ανοδικά ωφέλιμα φορτία. Επισυνάψτε μόνο απολυμανμένα αρχεία καταγραφής εφαρμογών για υποστήριξη. Οι επίσημες εκδόσεις είναι καρφιτσωμένες στο sing-box 1.14.3 και στο Xray 26.3.27 με δηλώσεις απελευθέρωσης asset SHA-256. Οι μελλοντικές ενημερώσεις απαιτούν αλλαγή της έκδοσης και όλων των επαληθευμένων συνόψεων μαζί.

│                                                                    │

## 3. Μηχανή καταστάσεων κύκλου ζωής

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
             επιτυχής έλεγχος υγείας │         κατάρρευση / SIGTERM
                               ┌────▼─────┐  (έξοδος εντός 5 s) │
                               │ running  │── κατάρρευση ───────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

Οι καταστάσεις αποθηκεύονται στον πίνακα `version_manager` της βάσης δεδομένων
(στήλη `status`) και αντικατοπτρίζονται στην κατάσταση μνήμης του
`ServiceSupervisor`. Η κατάσταση στη μνήμη είναι η έγκυρη πηγή για μια διεργασία
που εκτελείται· η κατάσταση της βάσης δεδομένων αποτελεί τη μόνιμη εφεδρική
πηγή κατά την εκκίνηση.

### Μεταβάσεις καταστάσεων

| Από             | Συμβάν                                       | Προς                        |
| --------------- | -------------------------------------------- | --------------------------- |
| `not_installed` | το `install()` ολοκληρώνεται επιτυχώς        | `stopped`                   |
| `stopped`       | καλείται το `start()`                        | `starting`                  |
| `starting`      | ο έλεγχος υγείας επιστρέφει 200              | `running`                   |
| `starting`      | η διεργασία τερματίζεται πριν καταστεί υγιής | `error`                     |
| `running`       | καλείται το `stop()`                         | `stopping` → `stopped`      |
| `running`       | η διεργασία τερματίζεται απροσδόκητα (< 5 s) | `error` (ταχεία κατάρρευση) |
| `running`       | η διεργασία τερματίζεται απροσδόκητα (> 5 s) | `error`                     |
| `error`         | καλείται το `start()`                        | `starting`                  |
| οποιαδήποτε     | `stop()` ενώ βρίσκεται σε `stopping`         | καμία ενέργεια              |

### Κλείδωμα λειτουργίας

Το `ServiceSupervisor` σειριοποιεί τις λειτουργίες κύκλου ζωής μέσω ενός ασύγχρονου
κλειδώματος λειτουργίας (`withLock()`). Οι ταυτόχρονες κλήσεις `start()` στον ίδιο
επόπτη έχουν ως αποτέλεσμα ακριβώς μία δημιουργία διεργασίας· ο δεύτερος καλών
περιμένει και λαμβάνει την υπάρχουσα κατάσταση. Αυτό αποτρέπει συνθήκες
ανταγωνισμού όταν, για παράδειγμα, η αυτόματη εκκίνηση και ένα κουμπί του
περιβάλλοντος χρήστη ενεργοποιούνται ταυτόχρονα.

Έγινε πρόθεμα `ow_` όταν δημιουργείται από `generateServiceApiKey()`. Το open-wa διαβάζει το κλειδί πίσω από μια κεφαλίδα `key`/`api_key` HTTP (όχι `Authorization: Bearer`). `/api-docs*` εξαιρείται ρητά από τον έλεγχο (`setupAuthenticationLayer` σε `dist/cli/server.js`), επομένως ο έλεγχος υγείας δεν χρειάζεται κεφαλίδα ταυτότητας.

**Σύζευξη:** Το open-wa είναι ανεπίσημο και δεν σχετίζεται με WhatsApp — ο συνδεδεμένος αριθμός ενέχει κίνδυνο απαγόρευσης από τον εντοπισμό αυτοματισμού της WhatsApp. Στην πρώτη εκκίνηση, ο κώδικας QR σύζευξης εκτυπώνεται στο stdout και εμφανίζεται μέσω της υπάρχουσας ροής Logs panel/SSE — δεν υπάρχει ακόμα αποκλειστικό τελικό σημείο εικόνας QR σε αυτήν την ενοποίηση.

### 4,7 τερματικά σημεία LLMLingua (8 διαδρομές)

LLMLingua είναι ένα `@atjsh/llmlingua-2` που αναδιπλώνεται με άμεση συμπίεση (πραγματικό μοντέλο ταξινόμησης διακριτικών ONNX, που λήφθηκε από το Hugging Face κατά την πρώτη κλήση `/compress` ). Χρησιμοποιεί το ίδιο σχήμα τελικού σημείου με το Bifrost (χωρίς κλειδί API — `needsApiKey: false`, δεν χειρίζεται ποτέ διαπιστευτήρια).

| Μέθοδος | Μονοπάτι                                       | Περιγραφή                                                                           |
| ------- | ---------------------------------------------- | ----------------------------------------------------------------------------------- |
| `POST`  | `/api/services/llmlingua/install`              | npm-εγκαταστήστε `@atjsh/llmlingua-2` + peers, γράψτε το σενάριο διακομιστή sidecar |
| `POST`  | `/api/services/llmlingua/start`                | Εκκινήστε το sidecar στη θύρα 20135 (προεπιλογή)                                    |
| `POST`  | `/api/services/llmlingua/stop`                 | Σταματήστε το πλαϊνό καρότσι                                                        |
| `POST`  | `/api/services/llmlingua/restart`              | Επανεκκινήστε το πλαϊνό καρότσι                                                     |
| `POST`  | `/api/services/llmlingua/update`               | Ενημέρωση στη νεότερη έκδοση πακέτου                                                |
| `GET`   | `/api/services/llmlingua/status`               | Ζωντανή κατάσταση + DB                                                              |
| `POST`  | `/api/services/llmlingua/auto-start`           | Εναλλαγή αυτόματης εκκίνησης                                                        |
| `POST`  | `/api/services/llmlingua/auto-restart-adopted` | Εναλλαγή αυτόματης επανεκκίνησης μιας εγκεκριμένης (προϋπάρχουσας) παρουσίας        |
| `GET`   | `/api/services/llmlingua/logs`                 | ουρά καταγραφής SSE (μέσω κοινής δυναμικής διαδρομής `[name]/logs` )                |

**Συμβόλαιο sidecar:** το σενάριο διακομιστή εκθέτει `GET /health` (το instant — δεν περιμένει στο μοντέλο) και `POST /compress` (`{ text, rate }` → `{ text, compressed, ratio }`). Το μοντέλο φορτώνεται νωχελικά στην πρώτη κλήση `/compress`.

**Καλωδίωση συμπίεσης:** `httpSidecarBackend` του `open-sse/services/compression/engines/llmlingua/index.ts` καλεί `LLMLINGUA_BASE_URL` (προεπιλογή `http://127.0.0.1:20135`) και δέχεται την απόκριση του πλαϊνού αυτοκινήτου μόνο όταν είναι αυστηρά μικρότερη από την είσοδο. Οποιαδήποτε αποτυχία (δεν εκτελείται, χρονικό όριο λήξης, απόκριση μη ενεργοποίησης) επιστρέφει στο υπόστρωμα του νήματος εργασίας (`./worker.ts`).

### 4,8 τελικά σημεία sing-box (8 διαδρομές)

Το sing-box έχει το ίδιο σχήμα τελικού σημείου με το Mux — no `rotate-key` route, no API key injection (`needsApiKey: false` in `bootstrap.ts`). | `POST`  | `/api/services/singbox/auto-start`           | Εναλλαγή αυτόματης εκκίνησης                                                   |
| `POST`  | `/api/services/singbox/auto-restart-adopted` | Εναλλαγή αυτόματης επανεκκίνησης για μια εγκεκριμένη (προϋπάρχουσα) διαδικασία |

### 4.9 Αντίστροφος διακομιστής μεσολάβησης (9 Ενσωμάτωση πίνακα εργαλείων δρομολογητή)

Ο πίνακας εργαλείων ενσωματώνει το 9Router web UI μέσα σε ένα iframe μέσω ενός εσωτερικού αντίστροφου διακομιστή μεσολάβησης στη διεύθυνση:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

Αυτός ο διακομιστής μεσολάβησης:

- Προώθηση του αιτήματος στο `http://127.0.0.1:{port}/{path}` (μόνο επαναφορά επαναφοράς)
- Απογυμνώνει τις εισερχόμενες κεφαλίδες `cookie` και `authorization` (χωρίς διαρροή της περιόδου λειτουργίας OmniRoute )
- Εισάγει `Authorization: Bearer {apiKey}` για έλεγχο ταυτότητας 9 δρομολογητή
- Αφαιρεί `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` από την απάντηση
- Ξαναγράφει τις αποκρίσεις HTML για να εισάγει `<base href>` και να ομαλοποιεί τις απόλυτες διαδρομές (`/foo` → `/dashboard/.../embed/foo`)

Οι αναβαθμίσεις WebSocket για τον ενσωματωμένο πίνακα εργαλείων χειρίζονται από έναν συνοδευτικό διακομιστή σε μια αποκλειστική θύρα (δείτε `src/lib/services/embedWsProxy.ts`).

**Ασφάλεια:** Οι διαδρομές ενσωμάτωσης διακομιστή μεσολάβησης ταξινομούνται στην κατηγορία `LOCAL_ONLY_API_PREFIXES` και είναι προσβάσιμες μόνο από το loopback. Ένας εισβολέας που αποκτά ένα JWT μέσω μιας σήραγγας Cloudflare/Ngrok δεν μπορεί να διαμεσολαβήσει σε ενσωματωμένες υπηρεσίες.

## 5. Ασφάλεια

### Επιβολή LOCAL_ONLY (αυστηρός κανόνας #17)

Όλες οι διαδρομές κάτω από `/api/services/` και `/dashboard/providers/services/*/embed/`
ταξινομούνται ως LOCAL_ONLY στο `src/server/authz/routeGuard.ts`. Ο έλεγχος loopback
εκτελείται άνευ όρων πριν από οποιονδήποτε κλάδο ελέγχου ταυτότητας:

```
το αίτημα φτάνει
  → isLocalOnlyPath(path)?
      → εκτός loopback → 403 LOCAL_ONLY (πάντα, πριν από τον έλεγχο ταυτότητας)
      → loopback       → συνέχεια στον κανονικό έλεγχο ταυτότητας
```

Αυτό αποτρέπει τη χρήση ενός JWT που έχει διαρρεύσει (π.χ. μέσω tunnel) για την
ενεργοποίηση του `npm install` ή τη δημιουργία διεργασιών. Ανατρέξτε στο
`docs/security/ROUTE_GUARD_TIERS.md` για τον πλήρη πίνακα επιπέδων.

### Εισαγωγή κλειδιού API

Τα 9Router και Mux απαιτούν κλειδί API/bearer token για τα δικά τους HTTP endpoints.
Το OmniRoute:

1. Δημιουργεί ένα κλειδί μέσω `crypto.randomBytes(32).toString("base64url")` με ένα
   πρόθεμα ειδικό για την υπηρεσία (`nr_` για το 9Router, `mx_` για το Mux).
2. Το κρυπτογραφεί κατά την αποθήκευση χρησιμοποιώντας AES-256-GCM (τον ίδιο αλγόριθμο κρυπτογράφησης που χρησιμοποιείται για τα διαπιστευτήρια παρόχων).
3. Το αποκρυπτογραφεί και το εισάγει ως μεταβλητή περιβάλλοντος κατά τη δημιουργία της διεργασίας —
   `NINEROUTER_API_KEY` για το 9Router, `MUX_SERVER_AUTH_TOKEN` για το Mux (ποτέ ως σημαία CLI,
   ώστε το token να μην εμφανίζεται ποτέ στο `ps`/στις λίστες διεργασιών).
4. Δεν επιστρέφει ποτέ το κλειδί σε μορφή απλού κειμένου σε καμία απόκριση HTTP.

Το CLIProxyAPI λαμβάνει ένα αποκλειστικό κλειδί επιπέδου δεδομένων, το οποίο εισάγεται κατά τη δημιουργία
της διεργασίας (`needsApiKey: true` — χρησιμοποιείται για συγχρονισμό μοντέλων με τον προσαρμογέα).

### Προστασία από SSRF

Ο αντίστροφος διακομιστής μεσολάβησης HTTP (`/dashboard/.../embed/[...path]`) είναι ρητά ρυθμισμένος να προωθεί
μόνο προς το `http://127.0.0.1:{port}`. Δεν ακολουθεί ποτέ ανακατευθύνσεις προς προορισμούς
εκτός loopback. Η βιβλιοθήκη `ssrf-req-filter` χρησιμοποιείται για την απόρριψη οποιουδήποτε upstream URL που
επιλύεται εκτός του εύρους loopback.

### Ασφάλεια κελύφους (αυστηρός κανόνας #13)

Το `npm install` καλείται μέσω `execFile('npm', ['install', pkg, '--prefix', dir])` —
χωρίς template literals, χωρίς κέλυφος και χωρίς παρεμβολή εξωτερικών διαδρομών στη συμβολοσειρά
εντολής. Οι τιμές χρόνου εκτέλεσης (θύρες, κλειδιά API) μεταβιβάζονται μέσω του αντικειμένου `env` της θυγατρικής διεργασίας.

### Εξυγίανση σφαλμάτων (αυστηρός κανόνας #12)

Όλες οι αποκρίσεις σφάλματος από το `/api/services/*` περνούν μέσω του `buildErrorBody()` ή του
`sanitizeErrorMessage()`. Τα ανεπεξέργαστα `err.stack` και `err.message` δεν επιστρέφονται ποτέ
αυτούσια στον καλούντα.

## 6. Προσθήκη νέας ενσωματωμένης υπηρεσίας

Ακολουθήστε αυτά τα 8 βήματα. Διαβάστε τις υπάρχουσες υλοποιήσεις στα `src/lib/services/installers/`
και `src/app/api/services/` ως την κανονιστική αναφορά.

### Βήμα 1 — Δημιουργία του προγράμματος εγκατάστασης

Δημιουργήστε το `src/lib/services/installers/{name}.ts` με πρότυπο το `ninerouter.ts`:

```typescript
export const NAME_PACKAGE = "your-npm-package";
export const NAME_DEFAULT_PORT = 20132; // επιλέξτε μια ελεύθερη θύρα

export async function install(version = "latest"): Promise<InstallResult> { ... }
export async function update(version = "latest"): Promise<InstallResult> { ... }
export async function uninstall(): Promise<void> { ... }
export function resolveSpawnArgs(apiKey: string, port: number): SpawnArgs { ... }
export async function getInstalledVersion(): Promise<string | null> { ... }
export async function getLatestVersion(): Promise<string | null> { ... }
```

Χρησιμοποιήστε το `runNpm(['install', NAME_PACKAGE, '--prefix', dir])` από το `installers/utils.ts`
— ποτέ το `execSync` ή παρεμβολή μέσω κελύφους.

### Βήμα 2 — Καταχώριση στην αρχικοποίηση

Προσθέστε μια καταχώριση `ServiceEntry` στον πίνακα `SERVICES` στο `src/lib/services/bootstrap.ts`:

```typescript
{
  tool: "myservice",
  port: NAME_DEFAULT_PORT,
  healthPath: "/health",
  healthIntervalMs: 5_000,
  stopTimeoutMs: 15_000,
  logsBufferBytes: 5_242_880,
  needsApiKey: true, // false εάν δεν απαιτείται κλειδί API
}
```

Επεκτείνετε το `buildSpawnArgsFactory()` ώστε να χειρίζεται το `cfg.tool === "myservice"`.

#### Επεκτάσιμη σύμβαση πρόσθετου παρόχου (Φάση 1, #7333)

Το `src/lib/services/providerPlugins/` εισάγει μια σύμβαση `ServiceProviderPlugin` που
συσκευάζει τα πεδία `ServiceEntry` του `bootstrap.ts` ενός backend και τα πεδία προτύπου manifest του
`serviceBackends.ts` σε ένα αντικείμενο, αντί η μορφή του ίδιου backend να
εκφράζεται ξεχωριστά σε δύο άσχετα αρχεία. Τη στιγμή της σύνταξης αυτού του κειμένου, **μόνο το `9router` έχει
μετεγκατασταθεί** — το `bootstrap.ts` παράγει την καταχώρισή του στο `SERVICES[]` από το
`getServiceProviderPlugin("9router")` (`src/lib/services/providerPlugins/registry.ts`),
προκαλώντας σφάλμα εκκίνησης εάν το πρόσθετο λείψει ποτέ. Τα `cliproxy`, `mux` και `bifrost`
παραμένουν αμετάβλητα στα προϋπάρχοντα inline literals του `SERVICES[]`.

Το `open-sse/config/providerPluginManifest.ts` απέκτησε επίσης μια πρόσθετη βοηθητική συνάρτηση
`createServiceBackendManifestEntry(pluginId, template)`, η οποία δημιουργεί μια ορθά διαμορφωμένη
`ProviderPluginManifestEntry` από μια καταχώριση `SERVICE_BACKEND_MANIFEST_TEMPLATE` — **δεν**
έχει ακόμη συνδεθεί με καμία ενεργή διαδρομή αιτημάτων (ούτε με το `generateProviderPluginManifestFromRegistry()`
ούτε με το `/v1/providers/[provider]/models`)· αυτό παραμένει εργασία για επόμενο στάδιο, αφού η σύμβαση
επαληθευτεί για ένα δεύτερο backend.

Αναβλήθηκαν για επόμενα PR και παρακολουθούνται στο issue #7333: η μετεγκατάσταση του `cliproxyapi` μέσω του
ίδιου μητρώου, η γενίκευση των `mux`/`bifrost` στην ένωση `ServiceBackendPluginId`,
η ενσωμάτωση των ειδικών περιπτώσεων δρομολόγησης executor (`open-sse/executors/index.ts`,
`open-sse/handlers/chatCore/executorProxy.ts`) στη σύμβαση πρόσθετου και η σύνδεση του
`createServiceBackendManifestEntry()` με μια ενεργή διαδρομή κώδικα manifest/μοντέλων.

### Βήμα 3 — Προσθήκη migration και αρχικών δεδομένων βάσης δεδομένων

Βεβαιωθείτε ότι η υπηρεσία διαθέτει μια γραμμή στο `version_manager` μέσω ενός migration στο

```sql
INSERT OR IGNORE INTO version_manager (tool, status, auto_start, provider_expose)

### Βήμα 4 — Δημιουργία των 7 API endpoints

```

## 7. Αντιμετώπιση προβλημάτων

### Η υπηρεσία δεν ξεκινά

**Συμπτώματα:** Το κουμπί εκκίνησης επιστρέφει 503, η κατάσταση παραμένει `"error"` ή `"starting"`.

**Λίστα ελέγχου:**

1. Ελέγξτε το `GET /api/services/{name}/logs` (ή τον πίνακα Logs στον πίνακα ελέγχου). Αναζητήστε

3. Επαληθεύστε ότι η υπηρεσία είναι εγκατεστημένη: ελέγξτε το `GET /api/services/{name}/status` για το
   `installedVersion`. Αν είναι `null`, εκτελέστε πρώτα την εγκατάσταση.
4. Ελέγξτε ότι το `DATA_DIR/services/{name}/node_modules/` υπάρχει και δεν είναι κενό.
5. Ελέγξτε το πεδίο `lastError` στην απόκριση κατάστασης για τον φιλτραρισμένο λόγο τερματισμού.

---

### Η ψυχρή εκκίνηση είναι αργή (> 10 s μέχρι να φτάσει στην κατάσταση `running`)

**Συμπτώματα:** Η κατάσταση παραμένει `"starting"` για μεγάλο χρονικό διάστημα προτού μεταβεί σε `"running"` ή `"error"`.

**Επεξήγηση:** Η ψυχρή εκκίνηση του 9Router περιλαμβάνει την εισαγωγή μεγάλων δέντρων εξαρτήσεων (μονάδες DNS,
σήραγγας και MITM). Το προεπιλεγμένο διάστημα ελέγχου εύρυθμης λειτουργίας είναι 2 s, με 3 προσπάθειες προτού ο
επόπτης δηλώσει λήξη χρονικού ορίου (αλλά συνεχίζει τον περιοδικό έλεγχο).

**Διόρθωση:** Το `healthIntervalMs` και το χρονικό όριο του `waitForHealthy`
(`healthIntervalMs * 3`) μπορούν να ρυθμιστούν στο `bootstrap.ts`. Για υπηρεσίες με μεγαλύτερους
χρόνους εκκίνησης, αυξήστε το `healthIntervalMs` σε 5000 και το `stopTimeoutMs` σε 30 000.

---

### Σύγκρουση θύρας (`EADDRINUSE`)

**Συμπτώματα:** Τα αρχεία καταγραφής εμφανίζουν `address already in use :::20130`.

**Αιτίες:**

- Μια άλλη διεργασία χρησιμοποιεί ήδη τη θύρα 20130.
- Μια προηγούμενη διεργασία του 9Router δεν τερματίστηκε πλήρως (ανενεργό PID).

**Διόρθωση:**

1. Αλλάξτε την προεπιλεγμένη θύρα μέσω της μεταβλητής περιβάλλοντος `NINEROUTER_PORT` στο `.env`.
2. Εντοπίστε και τερματίστε τη διεργασία που προκαλεί τη σύγκρουση: `lsof -ti :20130 | xargs kill -9`.
3. Η θύρα μπορεί να ρυθμιστεί ανά υπηρεσία στο `bootstrap.ts` μέσω του πεδίου `port`.

**Σημείωση:** Το 9Router χρησιμοποιεί από προεπιλογή τη θύρα 20130 ειδικά για να αποφεύγει τη σύγκρουση με
την προεπιλεγμένη θύρα 20128 του OmniRoute.

---

### Απόρριψη άδειας (EACCES) κατά την εγκατάσταση

**Συμπτώματα:** Η εγκατάσταση επιστρέφει 500 και τα αρχεία καταγραφής εμφανίζουν `EACCES` ή `permission denied`.

**Αιτίες:**

- Το `DATA_DIR` ή ο γονικός του κατάλογος δεν είναι εγγράψιμος από τη διεργασία OmniRoute.
- Εκτέλεση εντός Docker χωρίς δικαιώματα root και χωρίς πρόσβαση εγγραφής στον αντιστοιχισμένο τόμο.

**Διόρθωση:**

1. Ελέγξτε το `DATA_DIR` (προεπιλογή: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. Βεβαιωθείτε ότι ο χρήστης της διεργασίας OmniRoute είναι κάτοχος του καταλόγου: `chown -R $USER ~/.omniroute/`
3. Στο Docker, βεβαιωθείτε ότι η προσάρτηση τόμου έχει τα σωστά δικαιώματα για τον χρήστη του κοντέινερ.

---

### Η ενημέρωση αποτυγχάνει (λήξη χρονικού ορίου του `npm install` ή σφάλμα δικτύου)

**Συμπτώματα:** Η ενημέρωση επιστρέφει 500 με `InstallError` και τα αρχεία καταγραφής εμφανίζουν λήξη χρονικού ορίου δικτύου.

**Λίστα ελέγχου:**

1. Επιβεβαιώστε ότι το μητρώο npm είναι προσβάσιμο: `npm ping`.
2. Ελέγξτε για εταιρικό διακομιστή μεσολάβησης: `npm config get proxy`, `npm config get https-proxy`.
3. Δοκιμάστε την εγκατάσταση χειροκίνητα: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. Αν βρίσκεστε πίσω από απομονωμένο δίκτυο, πραγματοποιήστε εκ των προτέρων λήψη του tarball και χρησιμοποιήστε `npm install /path/to/tarball.tgz`.

---

### Η υπηρεσία εμφανίζει κατάσταση `"error"` αμέσως μετά την εκκίνηση (γρήγορη κατάρρευση)

**Συμπτώματα:** Η κατάσταση μεταβαίνει από `"starting"` σε `"error"` σε λιγότερο από 5 δευτερόλεπτα.
Το `lastError` εμφανίζει `"Fast crash (exited with code 1)"`.

**Λίστα ελέγχου:**

1. Διαβάστε το πλήρες τελευταίο τμήμα του αρχείου καταγραφής: `GET /api/services/{name}/logs?tail=500`.
2. Συνήθης αιτία: απουσία μεταβλητών περιβάλλοντος που αναμένονται από την υπηρεσία.
3. Για το 9Router: επαληθεύστε ότι τα `NINEROUTER_DISABLE_MITM=true` και
   `NINEROUTER_DISABLE_TUNNEL=true` περιλαμβάνονται στο περιβάλλον που μεταβιβάζεται κατά τη δημιουργία της διεργασίας (δείτε
   `installers/ninerouter.ts` `resolveSpawnArgs`).

---

## 8. Συχνές ερωτήσεις

**Ε: Μπορώ να εκθέσω τα τελικά σημεία των ενσωματωμένων υπηρεσιών σε πελάτες εκτός loopback;**

Όχι. Το επίπεδο LOCAL_ONLY είναι σκόπιμο (αυστηρός κανόνας #17). Οι διαδρομές που μπορούν να εκτελέσουν
`npm install` ή να εκκινήσουν διεργασίες `node` δεν πρέπει να είναι προσβάσιμες από κίνηση
εκτός loopback, επειδή ένα JWT που έχει διαρρεύσει μέσω tunnel (Cloudflare, Ngrok, Tailscale) θα
επέτρεπε διαφορετικά την αυθαίρετη εκκίνηση διεργασιών. Δεν υπάρχει δυνατότητα εξαίρεσης για
το `/api/services/` — σε αντίθεση με το `/api/mcp/`, εξαιρείται από τη λίστα παράκαμψης
του manage-scope. Ανατρέξτε στο `docs/security/ROUTE_GUARD_TIERS.md`.

---

**Ε: Θα είναι διαθέσιμα τα 9Router και CLIProxyAPI σε αναπτύξεις παραγωγής/cloud;**

Ναι. Και οι δύο υπηρεσίες ακολουθούν το ίδιο μοντέλο με προτεραιότητα στην τοπική εκτέλεση όπως το ίδιο το OmniRoute. Εκτελούνται
στο ίδιο μηχάνημα και επικοινωνούν μέσω loopback. Ο όρος «παραγωγή» εδώ σημαίνει το VPS
ή τον τοπικό διακομιστή όπου έχει αναπτυχθεί το OmniRoute, όχι έναν απομακρυσμένο πάροχο cloud.

---

**Ε: Πώς μπορώ να εντοπίσω σφάλματα στον supervisor;**

1. Παρακολουθήστε τη ροή καταγραφής SSE: `curl -N http://localhost:20128/api/services/9router/logs`.
2. Ελέγξτε τις δομημένες καταγραφές στην έξοδο pino του OmniRoute, φιλτραρισμένες βάσει του
   namespace `service:supervisor`.
3. Εξετάστε τη γραμμή της βάσης δεδομένων: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. Χρησιμοποιήστε το `GET /api/services/9router/status` για να δείτε την τρέχουσα ενεργή κατάσταση, το PID, την εύρυθμη λειτουργία
   και το `lastError` σε μία κλήση.

---

**Ε: Ο supervisor εμφανίζει `health: "degraded"` ή `health: "unknown"`, αλλά η κατάσταση είναι `"running"`. Είναι πρόβλημα;**

Το `"degraded"` σημαίνει ότι ο έλεγχος εύρυθμης λειτουργίας επέστρεψε απόκριση διαφορετική από 200. Το `"unknown"` σημαίνει ότι δεν
έχει ολοκληρωθεί ακόμη κανένας έλεγχος (ανταγωνισμός χρονισμού με την πρώτη επανάληψη ελέγχου). Και οι δύο καταστάσεις είναι παροδικές κατά την εκκίνηση.
Αν η εύρυθμη λειτουργία παραμένει `"degraded"` για περισσότερα από `healthIntervalMs * 3` ms μετά την κατάσταση
`"running"`, η ενσωματωμένη υπηρεσία εκτελείται, αλλά το HTTP API της δεν αποκρίνεται. Ελέγξτε
αν η θύρα στην απόκριση κατάστασης είναι σωστή και αν η υπηρεσία όντως
ακούει σε αυτήν τη θύρα.

---

**Ε: Μπορώ να αλλάξω το κλειδί API του 9Router χωρίς πλήρη επανεκκίνηση;**

Όχι. Το κλειδί API μεταβιβάζεται στο 9Router μέσω μιας μεταβλητής περιβάλλοντος κατά την εκκίνηση της διεργασίας.
Οι μεταβλητές περιβάλλοντος δεν μπορούν να αλλάξουν σε μια εκτελούμενη διεργασία. Το `POST .../rotate-key`
διακόπτει και επανεκκινεί αυτόματα την υπηρεσία για να εφαρμόσει το νέο κλειδί. Η εναλλαγή κλειδιού
τίθεται σε ισχύ εντός του `stopTimeoutMs` της υπηρεσίας (προεπιλογή 15 s), συν τον χρόνο
εκκίνησής της.

---

**Ε: Ποιο είναι το όριο του κυκλικού buffer και τι συμβαίνει όταν γεμίσει;**

Κάθε υπηρεσία διαθέτει έναν αποκλειστικό κυκλικό buffer 5 MB. Όταν ο buffer γεμίσει, οι παλαιότερες
γραμμές καταγραφής αφαιρούνται για να δημιουργηθεί χώρος για νέες. Το συμβάν SSE `snapshot` επιστρέφει
τις πιο πρόσφατες γραμμές εντός του ορίου `tail`. Οι καταγραφές δεν αποθηκεύονται μόνιμα στον δίσκο, εκτός αν
το `logsBufferPath` έχει οριστεί στη γραμμή της βάσης δεδομένων.
