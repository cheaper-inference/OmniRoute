## Ολοκληρώσεις Συνομιλίας

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Προσαρμοσμένες Κεφαλίδες

| Κεφαλίδα                 | Κατεύθυνση | Περιγραφή                                                                                                                                                                                                                                   |
| ------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | Αίτημα     | Ορίστε το σε `true` για παράκαμψη της κρυφής μνήμης                                                                                                                                                                                         |
| `x-omniroute-no-memory`  | Αίτημα     | Ορίστε το σε `true` για παράλειψη της εισαγωγής μνήμης + δεξιοτήτων για αυτό το αίτημα (αντίστοιχο με τη μη χρήση κρυφής μνήμης· αποφεύγει την επιβάρυνση διακριτικών/κόστους ανά κλήση)                                                    |
| `X-OmniRoute-Progress`   | Αίτημα     | Ορίστε το σε `true` για συμβάντα προόδου                                                                                                                                                                                                    |
| `X-Session-Id`           | Αίτημα     | Σταθερό κλειδί συνεδρίας για εξωτερική συνάφεια συνεδρίας                                                                                                                                                                                   |
| `x_session_id`           | Αίτημα     | Γίνεται επίσης αποδεκτή η παραλλαγή με κάτω παύλα (απευθείας HTTP)                                                                                                                                                                          |
| `X-OmniRoute-Session-Id` | Αίτημα     | Ετικέτα συνεδρίας/συνομιλίας που παρέχεται από τον καλούντα (τροφοδοτεί επίσης τη μνήμη). Όταν υπάρχει, αποθηκεύεται αυτούσια στο `call_logs.session_tag` για απόδοση κόστους ανά συνεδρία (#8249) — δεν δημιουργείται ποτέ όταν απουσιάζει |
| `Idempotency-Key`        | Αίτημα     | Κλειδί αποδιπλοποίησης (παράθυρο 5 δευτ.)                                                                                                                                                                                                   |
| `X-Request-Id`           | Αίτημα     | Εναλλακτικό κλειδί αποδιπλοποίησης                                                                                                                                                                                                          |
| `x-omniroute-connection` | Αίτημα     | Καρφιτσώνει ένα αίτημα μεμονωμένου μοντέλου σε μία σύνδεση παρόχου (λογαριασμό) βάσει του αναγνωριστικού της — δείτε [Καρφίτσωμα λογαριασμού ανά αίτημα](#account-pinning-per-request)                                                      |
| `X-OmniRoute-Cache`      | Απόκριση   | `HIT` ή `MISS` (χωρίς ροή)                                                                                                                                                                                                                  |
| `X-OmniRoute-Idempotent` | Απόκριση   | `true` εάν έγινε αποδιπλοποίηση                                                                                                                                                                                                             |
| `X-OmniRoute-Progress`   | Απόκριση   | `enabled` εάν είναι ενεργοποιημένη η παρακολούθηση προόδου                                                                                                                                                                                  |
| `X-OmniRoute-Session-Id` | Απόκριση   | Πραγματικό αναγνωριστικό συνεδρίας που χρησιμοποιήθηκε από το OmniRoute                                                                                                                                                                     |
| `X-OmniRoute-Request-Id` | Απόκριση   | Αναγνωριστικό συσχέτισης αιτήματος (όταν είναι γνωστό)                                                                                                                                                                                      |
| `X-OmniRoute-Version`    | Απόκριση   | Έκδοση δομής του OmniRoute (υπάρχει πάντα)                                                                                                                                                                                                  |
| `X-OmniRoute-Cost-Saved` | Απόκριση   | Ποσό σε USD που εξοικονομήθηκε από την κρυφή μνήμη σε περίπτωση HIT (μόνο για επιτυχίες κρυφής μνήμης)                                                                                                                                      |
| `X-OmniRoute-Decision`   | Απόκριση   | Ίχνος δρομολόγησης: `strategy=<name>; provider=<alias>; latency_ms=<n>` (το `<name>` είναι η στρατηγική συνδυασμού ή `single` για αίτημα χωρίς συνδυασμό) — υπάρχει πάντα στις αποκρίσεις ολοκλήρωσης                                       |

> Σημείωση για το Nginx: εάν βασίζεστε σε κεφαλίδες με κάτω παύλες (για παράδειγμα `x_session_id`), ενεργοποιήστε το `underscores_in_headers on;`.

#### Καθήλωση λογαριασμού ανά αίτημα

Όταν ένας πάροχος διαθέτει πολλές συνδέσεις (λογαριασμούς ή κλειδιά), το OmniRoute συνήθως επιλέγει μία
μέσω της στρατηγικής επιλογής λογαριασμού του. Εναλλακτικά, ένα αίτημα μπορεί να καθηλώσει μία συγκεκριμένη σύνδεση
με την κεφαλίδα `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Πού θα βρείτε το αναγνωριστικό.** Ανοίξτε τη σελίδα του παρόχου στον πίνακα ελέγχου
  (**Πίνακας ελέγχου → Πάροχοι → <provider>**) και κάντε κλικ στο πλακίδιο αναγνωριστικού `xxxxxxxx…` σε μια γραμμή
  σύνδεσης — αντιγράφει το πλήρες αναγνωριστικό σύνδεσης.
- **Ποια αιτήματα το λαμβάνουν υπόψη.** Αιτήματα ενός μοντέλου (`provider/model`) στα
  `/v1/chat/completions`, `/v1/messages` και `/v1/responses`. Οι συνδυασμοί αγνοούν την κεφαλίδα: καθηλώστε
  έναν λογαριασμό ανά βήμα συνδυασμού μέσω της σύνδεσης του ίδιου του βήματος.
- **Η καθήλωση είναι αυστηρή, δεν αποτελεί προτίμηση.** Χρησιμοποιείται αποκλειστικά η καθηλωμένη σύνδεση. Μια
  αποτυχία εντός του αιτήματος καταγράφει την περίοδο αναμονής του λογαριασμού, αλλά **δεν** μεταβαίνει σε
  άλλον λογαριασμό του ίδιου παρόχου.
- **Η περίοδος αναμονής και το όριο χρήσης αποδεσμεύουν την καθήλωση.** Όσο η καθηλωμένη σύνδεση βρίσκεται σε περίοδο αναμονής,
  έχει εξαντλήσει το όριό της ή αποκλείεται από μια πολιτική ορίων χρήσης, τα επόμενα αιτήματα μεταπίπτουν στις
  άλλες συνδέσεις του παρόχου, ακριβώς όπως η μη καθηλωμένη κίνηση.
- **Τα άγνωστα ή απενεργοποιημένα αναγνωριστικά αποτυγχάνουν.** Ένα αναγνωριστικό που δεν βρίσκεται στην ενεργή ομάδα του παρόχου (έχει διαγραφεί,
  απενεργοποιηθεί ή ανήκει σε άλλον πάροχο) δεν αφήνει κανέναν επιλέξιμο λογαριασμό, οπότε το αίτημα
  αποτυγχάνει αντί να δρομολογηθεί σιωπηρά αλλού.

Το Claude Code αποστέλλει προσαρμοσμένες κεφαλίδες μέσω του `ANTHROPIC_CUSTOM_HEADERS`. Τοποθετήστε το στο μπλοκ `env`
του `~/.claude/settings.json` ή σε ένα `.claude/settings.json` σε επίπεδο έργου, ώστε να καθηλώνετε διαφορετικό
λογαριασμό ανά έργο:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Πηγή: `src/sse/handlers/chat.ts` (ανάγνωση κεφαλίδας), `src/sse/services/auth.ts` και
`src/sse/services/sessionAffinityPin.ts` (αποδέσμευση καθήλωσης και έλεγχος απουσίας από την ομάδα).

> **Κεφαλίδες τηλεμετρίας κόστους:** οι επιτυχείς αποκρίσεις χωρίς ροή περιλαμβάνουν επίσης το σύνολο τηλεμετρίας κόστους `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, σταθερά 10 δεκαδικά ψηφία· `0.0000000000` για δωρεάν υπηρεσίες ή υπηρεσίες χωρίς τιμολόγηση), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` και `X-OmniRoute-Fallback-Attempts` (μόνο όταν > 0), καθώς και `X-OmniRoute-Request-Id` και `X-OmniRoute-Version`. Αυτές εκπέμπονται από τις ολοκληρώσεις συνομιλίας, τα `/v1/responses`, `/v1/messages`, **καθώς και από τα τελικά σημεία πολυμέσων** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` και `/v1/moderations` (πάντα με κόστος `0`). Το κόστος πολυμέσων υπολογίζεται ανά τύπο περιεχομένου (ανά εικόνα, ανά δευτερόλεπτο, ανά χαρακτήρα, ανά μονάδα αναζήτησης) όταν υπάρχουν διαθέσιμες τιμές, διαφορετικά είναι `0` (η λειτουργία συνεχίζεται σε περίπτωση αποτυχίας).

> **Σημασιολογία κόστους για ευστοχία κρυφής μνήμης:** σε μια ΕΥΣΤΟΧΙΑ σημασιολογικής κρυφής μνήμης (`X-OmniRoute-Cache-Hit: true`) δεν πραγματοποιείται κλήση προς ανάντη υπηρεσία, επομένως το `X-OmniRoute-Response-Cost` είναι `0.0000000000` (το **πρόσθετο** κόστος εξυπηρέτησης της ευστοχίας). Το αρχικό κόστος ή το κόστος που θα είχε προκύψει αναφέρεται ξεχωριστά στο `X-OmniRoute-Cost-Saved`. Οι καταναλωτές δεδομένων χρέωσης θα πρέπει να αθροίζουν το `X-OmniRoute-Response-Cost` (οι ευστοχίες δεν κοστίζουν τίποτα)· τα αναλυτικά στοιχεία κρυφής μνήμης μπορούν να συγκεντρώνουν το `X-OmniRoute-Cost-Saved`.

## Αποκλειστικές μισθώσεις διαχειριζόμενων συνεδριών

Η αποκλειστική μίσθωση διαχειριζόμενων συνεδριών είναι μια προαιρετική σύμβαση δρομολόγησης, ανεξάρτητη από τον πελάτη: ένας ενεργός κάτοχος
δεσμεύει μία επιλέξιμη σύνδεση OmniRoute. Δεν μισθώνει κάποιο μοντέλο, δεν απαιτεί OAuth, δεν προσδιορίζει
συγκεκριμένο πελάτη και δεν απαιτεί συγκεκριμένο πάροχο.

Το API key που χρησιμοποιείται για τον έλεγχο ταυτότητας πρέπει να διαθέτει το scope `lease:exclusive` και μια ρητή, μη κενή
λίστα `allowedConnections`. Το όριο μεταβολών της βάσης δεδομένων επιβάλλει την ταυτόχρονη παρουσία και των δύο πεδίων κατά τη
δημιουργία κλειδιού και τις μερικές ενημερώσεις.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Οι επιτυχείς αποκρίσεις απόκτησης, ανανέωσης και αποδέσμευσης περιλαμβάνουν χρονικές σημάνσεις, το `state` και την ακριβή θετική
`generation`, αλλά ποτέ την επιλεγμένη σύνδεση ή τα διαπιστευτήρια. Η ανανέωση και η αποδέσμευση παρέχουν τη
γενιά στο σώμα JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Ο ενεργός κάτοχος μιας μίσθωσης μπορεί να ζητήσει ρητά μεταδεδομένα εμφάνισης που προστατεύουν το απόρρητο για την τρέχουσα δέσμευσή του:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Αυτή η προαιρετική ενέργεια κατάστασης προστατεύεται από τον αδιαφανή κάτοχο, το ελεγμένο διαχειριζόμενο API key και την ακριβή
ενεργή γενιά μέσα σε μία συναλλαγή βάσης δεδομένων. Το `displayName` είναι μόνο το διαμορφωμένο όνομα
σύνδεσης χωρίς κενά στην αρχή ή στο τέλος· είναι `null` όταν δεν υπάρχει ασφαλές διαμορφωμένο όνομα. Το OmniRoute δεν αντικαθιστά ποτέ το όνομα με
διεύθυνση email ή παραγόμενη ταυτότητα λογαριασμού. Η τιμή παρόχου είναι μια μη ευαίσθητη ετικέτα εμφάνισης και ποτέ
ένα παραγόμενο αναγνωριστικό συμβατού παρόχου. Εξαιρούνται τα διαπιστευτήρια, τα token, τα cookie, τα ανεπεξέργαστα αναγνωριστικά σύνδεσης ή
API key, τα hash κατόχων, τα μυστικά προστασίας και τα εσωτερικά δεδομένα δρομολόγησης.

Οι αναζητήσεις με λανθασμένο κλειδί, λανθασμένο κάτοχο, παρωχημένη γενιά, καθώς και οι αναζητήσεις που λείπουν, έχουν λήξει, έχουν αποδεσμευτεί ή έχουν ακυρωθεί, επιστρέφουν όλες
το ίδιο σφάλμα `409 LEASE_FENCE_STALE` χωρίς μεταδεδομένα σύνδεσης. Ένας πελάτης που έλαβε την απόκριση αναμονής χωρητικότητας δεν διαθέτει ενεργή δέσμευση προς επιθεώρηση. Όταν η δρομολόγηση μεταφέρει μια ενεργή μίσθωση,
η ίδια γενιά παραμένει έγκυρη και η κατάσταση επιστρέφει ατομικά τη νέα δέσμευση, ποτέ την παλιά.
Οι υπάρχοντες πελάτες παραμένουν αμετάβλητοι, επειδή οι αποκρίσεις απόκτησης, ανανέωσης, αποδέσμευσης και αναμονής διατηρούν
τις προηγούμενες δομές τους.

Αυτή η σύμβαση διακομιστή δεν αλλάζει το `/status` του τυπικού OpenAI Codex. Το τυπικό Codex αναφέρει επί του παρόντος τον
πάροχο του μοντέλου του και την ενσωματωμένη κατάσταση ελέγχου ταυτότητας/λογαριασμού, αλλά δεν εμφανίζει αυθαίρετα προσαρμοσμένα
μεταδεδομένα λογαριασμού παρόχου· μια μελλοντική ενσωμάτωση πελάτη πρέπει να καλέσει αυτή την ενέργεια και να αποφασίσει πώς θα
εμφανίσει το `connection.displayName`.

Στη συνέχεια, κάθε διαχειριζόμενο αίτημα συμπερασματολογίας παρέχει και τις δύο κεφαλίδες ελέγχου:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Ο ακριβής κάτοχος, η γενιά, η ενεργή σύνδεση και το ελεγμένο API key προστατεύονται αμέσως
πριν από κάθε υποστηριζόμενη προσπάθεια προς το upstream. Η επανάληψη του κατόχου και της γενιάς με άλλο κλειδί αποτυγχάνει, ακόμη
και όταν αυτό το κλειδί επιτρέπει την ίδια σύνδεση. Οι ανεπεξέργαστες τιμές κατόχων δεν αποθηκεύονται μόνιμα, δεν καταγράφονται, δεν διατηρούνται στο
στιγμιότυπο του αιτήματος και δεν προωθούνται προς το upstream.

Η προσωρινή διεκδίκηση πόρων επιστρέφει HTTP `429` με `Retry-After` και:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Αυτή η απόκριση σημαίνει μόνο ότι το συνήθες σύνολο επιλέξιμων συνδέσεων δεν ήταν κενό και κάθε ελεύθερη υποψήφια σύνδεση
δεσμευόταν από μια ξένη ενεργή μίσθωση. Τα μη υποστηριζόμενα μοντέλα/οι μη υποστηριζόμενοι πάροχοι, η ασυμφωνία πολιτικής, η περίοδος αναμονής, το όριο χρήσης,
η εύρυθμη λειτουργία και άλλες συνήθεις αποτυχίες επιλεξιμότητας διατηρούν τις υπάρχουσες αποκρίσεις OmniRoute.

### `x-omniroute-compression`

Παράκαμψη του πλάνου συμπίεσης ανά αίτημα. Έχει την υψηλότερη προτεραιότητα — υπερισχύει της παράκαμψης συνδυασμού
δρομολόγησης, του ενεργού προφίλ, της αυτόματης ενεργοποίησης και της προεπιλογής του πίνακα. Τιμές:

| Τιμή          | Αποτέλεσμα                                                                                                                             |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `off`         | Καμία συμπίεση για αυτό το αίτημα.                                                                                                     |
| `default`     | Το προφίλ προεπιλογής που προκύπτει από τον πίνακα (αγνοεί το ενεργό προφίλ). Οι μη αντιστρεπτές μηχανές παραμένουν απενεργοποιημένες. |
| `safe`        | Μόνο αποδιπλοποίηση και σύμπτυξη κενών χαρακτήρων.                                                                                     |
| `allow-lossy` | Διατήρηση του πλάνου του χειριστή για αυτό το αίτημα, συμπεριλαμβανομένων των περιλήψεων και των αναδιατυπώσεων ύφους.                 |
| `engine:<id>` | Μία μόνο μηχανή, όταν είναι ενεργοποιημένη, π.χ. `engine:rtk`. Προαιρετική ενεργοποίηση αυτής της μηχανής ανά αίτημα.                  |
| `<combo>`     | Ένας επώνυμος συνδυασμός, με αντιστοίχιση πρώτα βάσει ονόματος (χωρίς διάκριση πεζών-κεφαλαίων) και έπειτα βάσει id.                   |

Σημειώσεις:

- Οι άγνωστες τιμές αγνοούνται (το αίτημα δεν απορρίπτεται ποτέ)· η επίλυση συνεχίζει με την κανονική σειρά προτεραιότητας του χειριστή.
- Αν πολλοί συνδυασμοί έχουν το ίδιο όνομα, χρησιμοποιήστε το **id** του συνδυασμού για ντετερμινιστική αντιστοίχιση.
- Ένας συνδυασμός του οποίου το όνομα είναι `off` ή `default` δεν μπορεί να επιλεγεί βάσει ονόματος (αυτές οι λέξεις-κλειδιά ερμηνεύονται πρώτα)· αναφερθείτε σε έναν τέτοιο συνδυασμό μέσω του id του.
- Ο κύριος διακόπτης συμπίεσης αποτελεί απόλυτο φραγμό: όταν η συμπίεση είναι απενεργοποιημένη καθολικά, αυτή η κεφαλίδα δεν μπορεί να την ενεργοποιήσει.

Το εφαρμοσμένο πλάνο επιστρέφεται στην κεφαλίδα απόκρισης:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

όπου το `<source>` είναι ένα από τα `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` ή `off`.

## Ενσωματώσεις

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Διαθέσιμοι πάροχοι: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Τα αναγνωριστικά καταλόγου έχουν τη μορφή `provider/model` (παράδειγμα: `jina-ai/jina-embeddings-v5-omni-small`). Τα απλά αναγνωριστικά μοντέλων Jina που εμφανίζονται στο μητρώο (για παράδειγμα `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) επιλύονται επίσης. Οι λειτουργίες embed/rerank/classify/segment της Jina χρησιμοποιούν πρώτα τα διαπιστευτήρια `jina-ai` του πίνακα ελέγχου· το `JINA_AI_API_KEY` χρησιμοποιείται ως εφεδρική επιλογή μόνο όταν δεν υπάρχει κλειδί στον πίνακα ελέγχου. Η κάρτα `jina-reader` προορίζεται μόνο για το Reader / `r.jina.ai` (`POST /v1/web/fetch`) και δεν παρέχει ποτέ ενσωματώσεις ή ανακατάταξη.

Τα μοντέλα του μητρώου που δηλώνουν υποστήριξη πολλαπλών τρόπων εισόδου δέχονται επίσης έως 32 δομημένα στοιχεία ανεξάρτητα από τον πάροχο.
Οι τύποι στοιχείων πολυμέσων είναι `text`, `image`, `audio`, `video` και `document`. Η `source`
των πολυμέσων είναι είτε `{"type":"url","url":"https://..."}` είτε
`{"type":"base64","data":"...","media_type":"..."}`.

Το Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
και το ψευδώνυμο οικογένειας `jina-ai/jina-embeddings-v5-omni` → omni-small) δέχεται επίσης τα εγγενή
έγγραφα EmbeddingsV5Request της Jina και **τα προωθεί χωρίς καμία αλλαγή** στο `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Οι εγγενείς τιμές `{ image | audio | video | pdf }` μπορεί να είναι ένα δημόσιο URL HTTPS, ένα URI `data:` ή ακατέργαστα
δεδομένα base64. Το OmniRoute δεν μετατρέπει αυτά τα αντικείμενα σε συμβολοσειρές ούτε ανακτά εγγενή URL εικόνων — η Jina ανακτά
τα δημόσια πολυμέσα η ίδια. Τα πρόσθετα πεδία της Jina (`task`, `normalized`, `truncate`, `embedding_type`)
προωθούνται. Τα SKU της Jina που υποστηρίζουν μόνο κείμενο εξακολουθούν να απορρίπτουν έγγραφα που δεν είναι κείμενο.

Όρια ασφάλειας και μεταφοράς:

- Τα απομακρυσμένα URL πολυμέσων πρέπει να είναι δημόσια και να χρησιμοποιούν HTTPS. Τα κανονικοποιημένα στοιχεία `{type,source:url}` ανακτώνται
  στην πλευρά του διακομιστή (επανεπικύρωση ανακατευθύνσεων, χρονικό όριο, όρια μεγέθους, δημόσιο DNS, καρφίτσωμα σύνδεσης) και
  ενσωματώνονται πριν από την κλήση προς τον πάροχο. Τα εγγενή στοιχεία της Jina `{image:"https://..."}` προωθούνται ως έχουν
  μετά τον ίδιο έλεγχο δημόσιου HTTPS· η Jina ανακτά το URL.
- Τα ενσωματωμένα πολυμέσα base64 περιορίζονται σε 8 MiB αποκωδικοποιημένων δεδομένων ανά στοιχείο και 16 MiB αποκωδικοποιημένων δεδομένων σε ολόκληρο το αίτημα.

Μετάφραση ανά πάροχο (τα κανονικοποιημένα στοιχεία δεν προωθούνται ποτέ χωρίς αλλαγές):

- Πολυτροπικά μοντέλα Jina: κάθε στοιχείο ανώτατου επιπέδου μετατρέπεται σε ένα αντικείμενο με κλειδί βάσει τρόπου εισόδου
  (`text` / `image` / `audio` / `video` / `pdf`), χρησιμοποιώντας URI δεδομένων για ενσωματωμένα πολυμέσα· ένα διάνυσμα ανά
  στοιχείο ανώτατου επιπέδου.
- Οικογένεια Gemini Embedding 2: ένας πίνακας ανώτατου επιπέδου μετατρέπεται σε ένα μόνο εγγενές
  αίτημα `models/{model}:embedContent` με `content.parts` (`text` ή `inline_data`).
- llama.cpp (`llama-cpp/<model>`, οποιοδήποτε μοντέλο έχει φορτώσει ο τοπικός διακομιστής): τα κανονικοποιημένα στοιχεία `text`
  μετατρέπονται σε απλές συμβολοσειρές, ενώ τα `image` / `audio` / `video` μετατρέπονται το καθένα σε ένα
  αντικείμενο `{"content": [part]}`, χρησιμοποιώντας τα τμήματα περιεχομένου συνομιλίας του llama-server (`image_url`,
  `input_audio` με μορφή `wav` / `mp3` / `flac`, `input_video`) με ενσωματωμένα δεδομένα· ένα διάνυσμα
  ανά στοιχείο ανώτατου επιπέδου. Ο διακομιστής πρέπει να εκτελείται με `--embedding --mmproj …`· χωρίς προβολέα,
  απορρίπτει ο ίδιος τα πολυμέσα. Το `document` δεν υποστηρίζεται.
- Άγνωστα/δυναμικά μοντέλα χωρίς ρητά μεταδεδομένα τρόπου εισόδου απορρίπτουν τη δομημένη είσοδο με HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Οι μη υποστηριζόμενοι συνδυασμοί μοντέλου/τρόπου εισόδου επιστρέφουν HTTP 400 αντί να εξαναγκάζουν τη μετατροπή του στοιχείου. Τα πεδία επέκτασης εκτός εισόδου
σε παλαιού τύπου αιτήματα συμβολοσειρών/token εξακολουθούν να προωθούνται χωρίς αλλαγές.

```bash
# Παράθεση όλων των μοντέλων ενσωματώσεων
GET /v1/embeddings
```

## Δημιουργία εικόνων

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Οι διαθέσιμοι πάροχοι περιλαμβάνουν τους OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (τοπικά), ComfyUI (τοπικά).

Το `n` επιστρέφει `n` εικόνες στο `data[]`. Για τους παρόχους των οποίων το upstream API επιστρέφει μία εικόνα ανά κλήση
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI), πραγματοποιούνται `n` ξεχωριστές upstream κλήσεις, με έως και 4 να εκτελούνται ταυτόχρονα. Ένα
σταθερό `seed` μετατοπίζεται κατά τον δείκτη κλήσης (`seed`, `seed + 1`, …), ώστε οι εικόνες να διαφέρουν αλλά να παραμένουν
αναπαραγώγιμες. Το `n` περιορίζεται σε 10. Το αίτημα αποτυγχάνει συνολικά εάν αποτύχει οποιαδήποτε κλήση. Η λίστα
των μορφών fan-out είναι η `SINGLE_IMAGE_FANOUT_FORMATS` στο
`open-sse/handlers/imageGeneration/fanOut.ts`.

Το ZenMux επαναχρησιμοποιεί την υπάρχουσα σύνδεση κλειδιού API και δέχεται τα προθέματα `zenmux/` ή `zm/`:

- Το `zenmux/openai/gpt-image-2` χρησιμοποιεί το OpenAI Images API του ZenMux. Οι επιλογές περιλαμβάνουν τα `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` και `response_format`.
- Άλλοι εκδότες, όπως το `zm/meta/muse-image-1.0`, χρησιμοποιούν το endpoint `:predict`
  του Vertex AI μέσω του ZenMux. Το `n` αντιστοιχίζεται στο `sampleCount`, το `aspect_ratio` στο `aspectRatio` και το `image_size`
  (`1K`, `2K`, `4K`) στο `sampleImageSize`. Ένα `size` σε pixel παρέχει μόνο αναλογία διαστάσεων
  και όχι εγγυημένες διαστάσεις σε pixel. Οι υποστηριζόμενες αναλογίες, αναλύσεις και πλήθη διαφέρουν ανά μοντέλο.
- Το `zm/inclusionai/ming-image-0.1-design` επιλέγει τις δικές του διαστάσεις. Παραλείψτε τα `size`,
  `aspect_ratio` και `image_size`· οι ρητές τιμές επιστρέφουν HTTP 400. Μπορούν να ζητηθούν PNG, JPEG και WebP
  μέσω του `output_format`.

Αυτή η ενσωμάτωση υποστηρίζει τη δημιουργία εικόνων από κείμενο και όχι την επεξεργασία εικόνων αναφοράς. Η έξοδος του Vertex
κανονικοποιείται σε `data[].b64_json`· το `response_format: "url"` επιστρέφει ένα upstream
HTTPS URL ή ένα URL δεδομένων base64 όταν είναι διαθέσιμα μόνο τα byte της εικόνας. Οι κενές ή φιλτραρισμένες έξοδοι
επιστρέφουν σφάλμα αντί για κενή επιτυχή απόκριση. Η πρόσβαση στα μοντέλα εξαρτάται από τον λογαριασμό ZenMux.
Δείτε το [Vertex API του ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) και το
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# Λίστα όλων των μοντέλων εικόνων
GET /v1/images/generations
```

Το `model` επιλέγει τον πάροχο OCR μέσω ενός προθέματος `provider/model`· ένα αναγνωριστικό μοντέλου χωρίς πρόθεμα (π.χ.

| Αναγνωριστικό παρόχου         | Αναγνωριστικό μοντέλου | Τιμή `model`                                               | Σημειώσεις                                                                                                                      |
| ----------------------------- | ---------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest`   | `mistral/mistral-ocr-latest` (ή μόνο `mistral-ocr-latest`) | Σύγχρονο — η απόκριση επιστρέφεται απευθείας από τη μοναδική upstream κλήση.                                                    |
| `azure-document-intelligence` | `prebuilt-read`        | `azure-document-intelligence/prebuilt-read`                | Ασύγχρονο upstream (`analyze` + polling) — δείτε παρακάτω.                                                                      |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`    | `vertex-deepseek-ocr/deepseek-ocr-maas`                    | Σύγχρονο, μέσω του συνεργαζόμενου endpoint `openapi/chat/completions` του Vertex AI — δείτε παρακάτω για έλεγχο ταυτότητας/URL. |

Και οι τρεις πάροχοι αποκρίνονται με το ίδιο σώμα στη μορφή του Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Ροή polling του Azure Document Intelligence

Το API `analyze` του Azure Document Intelligence είναι ασύγχρονο: το αρχικό αίτημα επιστρέφει μια
κεφαλίδα `Operation-Location` αντί για σώμα και το αποτέλεσμα πρέπει να ανακτηθεί μέσω polling. Ο χειριστής
(`open-sse/handlers/ocr.ts`) ελέγχει αυτό το URL κάθε δευτερόλεπτο για έως και 30 προσπάθειες, αποτυγχάνει άμεσα (δεν
συνεχίζει το polling) σε απόκριση polling που δεν είναι `ok` ή σε κατάσταση `"failed"` και επιστρέφει `504` εάν η
λειτουργία εξακολουθεί να εκτελείται αφού εξαντληθεί το όριο προσπαθειών. Η τελική απόκριση του Azure
κανονικοποιείται στην ίδια μορφή `pages`/`markdown` που χρησιμοποιεί το Mistral πριν επιστραφεί στον
καλούντα, ώστε ο κώδικας πελάτη να μη χρειάζεται ειδική διαχείριση ανά πάροχο.

### Έλεγχος ταυτότητας και επίλυση endpoint για το Vertex AI DeepSeek OCR

Το `vertex-deepseek-ocr` επαναχρησιμοποιεί τον ίδιο έλεγχο ταυτότητας Vertex AI που υποστηρίζει ήδη το OmniRoute για
κίνηση συνομιλίας/εικόνων (`open-sse/executors/vertex.ts`): το κλειδί API της σύνδεσης είναι είτε ένα
διαπιστευτήριο Service Account JSON (το οποίο ανταλλάσσεται με ένα βραχύβιο διακριτικό πρόσβασης OAuth μέσω της ροής JWT-bearer)
είτε ένα ήδη εκδοθέν διακριτικό πρόσβασης OAuth που χρησιμοποιείται ως έχει. Το upstream URL του endpoint είναι το γενικό
συνεργαζόμενο endpoint `openapi/chat/completions` του Vertex, το οποίο δημιουργείται από το έργο και την
περιοχή της σύνδεσης — ένα ρητό `providerSpecificData.project`/`providerSpecificData.region` έχει πάντα προτεραιότητα·
διαφορετικά, το έργο προκύπτει από το `project_id` του Service Account JSON και η περιοχή
έχει ως προεπιλογή το `us-central1`. Και οι δύο επιλύσεις πραγματοποιούνται στο `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) και χρησιμοποιούνται από το
`src/app/api/v1/ocr/route.ts` πριν από την προώθηση στο `handleOcr`.

### Τιμές μοντέλων (`pricing`)

Μια καταχώριση περιλαμβάνει ένα αντικείμενο `pricing` όταν το OmniRoute γνωρίζει την τιμή του μοντέλου. Η τιμή προέρχεται
από τον πίνακα τιμολόγησης που χρησιμοποιεί η λογιστική κόστους: ενσωματωμένες προεπιλογές, συγχρονισμένες τιμές και
παρακάμψεις που ορίζονται μέσω του `/api/pricing`. Αυτές είναι τιμές καταλόγου, επομένως οι πάροχοι συνδρομών επίσης
εμφανίζουν μια τιμή ανά token.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Πεδία                                                           | Μονάδα                               | Σημειώσεις                                                                                                                                                                                   |
| --------------------------------------------------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | USD ανά token, δεκαδική συμβολοσειρά | Συμβατά με το OpenRouter, ποτέ σε εκθετική σημειογραφία. Τα δύο πεδία cache εμφανίζονται μόνο όταν υπάρχει τιμή cache.                                                                       |
| `input`, `output`, `cached`, `cache_creation`                   | USD ανά 1M tokens, αριθμός           | Πεδία από παλαιότερες εκδόσεις του καταλόγου, τα οποία διατηρούνται για υπάρχοντες πελάτες. Τα `reasoning` και `long_context` εμφανίζονται επίσης όταν τα περιλαμβάνει η γραμμή τιμολόγησης. |

- Οι **συνδυασμοί** χρησιμοποιούν την τιμή του πρώτου ορατού προορισμού τους. Οι ενσωματωμένοι συνδυασμοί `auto/*` επιλέγουν έναν
  προορισμό κατά τον χρόνο του αιτήματος, επομένως δεν έχουν `pricing`.
- Τα **δωρεάν μοντέλα** εμφανίζουν `"0"` (και `0`) όταν η τιμή τους είναι μηδενική. Ένα μοντέλο χωρίς γραμμή τιμολόγησης
  εμφανίζει επίσης `"0"` όταν ο κατάλογος το επισημαίνει ως δωρεάν (`free: true`) ή όταν περιλαμβάνεται στον ενσωματωμένο κατάλογο
  δωρεάν μοντέλων.
- **Άγνωστη τιμή:** η καταχώριση δεν έχει κλειδί `pricing`.
- Οι **πάροχοι με χρέωση βάσει πιστώσεων** (όπως το Kiro) χρεώνουν ανά αίτημα και όχι ανά token. Οι
  καταχωρίσεις τους διατηρούν τα αριθμητικά πεδία ανά 1M που είχαν προηγουμένως και δεν περιλαμβάνουν πεδία συμβολοσειράς ανά token.
- Οι **παραλλαγές** (αναγνωριστικά προσπάθειας συλλογισμού, ψευδώνυμα χωρίς σκέψη, κάτοπτρα εντοπισμού και gateway)
  αντιγράφουν την τιμή του μοντέλου στο οποίο δρομολογούν.
- Τα πεδία περιλαμβάνουν μόνο τις βασικές χρεώσεις. Οι βαθμίδες μεγάλου context (το αριθμητικό πεδίο `long_context`) και
  οι πολλαπλασιαστές βαθμίδας υπηρεσίας (για παράδειγμα Codex fast ή flex) δεν αλλάζουν τα `prompt` ή
  `completion`.
- Το αντικείμενο είναι το ίδιο για κάθε μέθοδο ελέγχου ταυτότητας, συμπεριλαμβανομένου ενός αιτήματος τύπου Anthropic
  με `x-api-key` και `anthropic-version` (η απόκριση παραμένει `{ "object": "list",
"data": [...] }`). Υλοποίηση: `src/app/api/v1/models/catalogPricing.ts`.

### Προθέματα αναγνωριστικών μοντέλων (`?prefix=`)

Τα περισσότερα μοντέλα προβάλλονται με ένα **πρόθεμα παρόχου**. Το πρόθεμα που λαμβάνετε ελέγχεται από
τη σημαία λειτουργίας `MODELS_CATALOG_PREFIX_MODE` και μπορεί να παρακαμφθεί **ανά αίτημα** με μια
παράμετρο query — χρήσιμο για έναν πελάτη που θέλει μια καθαρή λίστα χωρίς να αλλάξει τη ρύθμιση
σε επίπεδο διακομιστή για όλους τους άλλους:

```bash
GET /v1/models?prefix=alias        # ένα αναγνωριστικό ανά μοντέλο — το σύντομο πρόθεμα ψευδωνύμου
GET /v1/models?prefix=dual         # και οι δύο μορφές (προεπιλογή διακομιστή)
GET /v1/models?prefix=canonical    # μόνο το πλήρες πρόθεμα αναγνωριστικού παρόχου
```

| Λειτουργία  | Εκπέμπει                                                  | Σημειώσεις                                                                                                                                                                                                                                           |
| ----------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **και** `claude/claude-sonnet-4-6` | **Προεπιλογή.** Και τα δύο αναγνωριστικά δρομολογούν στο ίδιο μοντέλο· διατηρούνται ώστε οι διαμορφώσεις πελατών που έχουν ενσωματώσει μόνιμα οποιαδήποτε από τις δύο μορφές να συνεχίσουν να λειτουργούν. Διπλασιάζει κατά προσέγγιση τον κατάλογο. |
| `alias`     | `cc/claude-sonnet-4-6`                                    | Μία καταχώριση ανά μοντέλο. Οι πάροχοι χωρίς διακριτό ψευδώνυμο εξακολουθούν να εκπέμπουν την καταχώρισή τους, επομένως δεν χάνεται τίποτα.                                                                                                          |
| `canonical` | `claude/claude-sonnet-4-6`                                | Μία καταχώριση ανά μοντέλο κάτω από το πλήρες πρόθεμα αναγνωριστικού παρόχου. Οι πάροχοι χωρίς διακριτό ψευδώνυμο (π.χ. `antigravity/…`, `agy/…`) εκπέμπουν και εδώ το μοναδικό αναγνωριστικό τους, επομένως δεν χάνεται τίποτα.                     |

Ένα κάτοπτρο σε λειτουργία `dual` μπορεί επίσης να αναγνωριστεί χωρίς την παράμετρο query: περιλαμβάνει ένα πεδίο `parent`
που παραπέμπει στο κύριο αναγνωριστικό.

Οι πελάτες που αποδίδουν έναν επιλογέα μοντέλου θα πρέπει να ζητούν `?prefix=alias` — αυτό κάνει η
[επέκταση OmniCopilot για VS Code](../guides/VSCODE-COPILOT.md).

### Φίλτρα εντοπισμού (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

Το `GET /v1/models` δέχεται προαιρετικά φίλτρα εντοπισμού. Χωρίς κανένα από αυτά, η απόκριση παραμένει
αμετάβλητη. Περιορίζουν τον κατάλογο που ήδη βλέπει ο καλών (τα δικαιώματα του κλειδιού API εφαρμόζονται πρώτα)
και εκτελούνται πριν από τη σελιδοποίηση τύπου OpenAI με `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # κάθε αναφερόμενη δυνατότητα πρέπει να είναι αληθής
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` καταλόγου· οι γραμμές χωρίς αυτό είναι `chat`
GET /v1/models?q=sonnet&limit=10                           # αντιστοίχιση χωρίς διάκριση πεζών-κεφαλαίων στο αναγνωριστικό ή το όνομα
```

| Παράμετρος    | Τιμές                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | μη αρνητικός ακέραιος, συγκρίνεται με το `context_length`                                           |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 χαρακτήρες                                                                                    |

Μια άγνωστη τιμή ή ένα `min_context` που δεν είναι μη αρνητικός ακέραιος (για παράδειγμα `1.5`),
επιστρέφει HTTP `400` και το μήνυμα παραθέτει τις έγκυρες τιμές. Υλοποίηση:
`src/app/api/v1/models/catalogFilters.ts`.

### Σύντομη λίστα μοντέλων (`POST /v1/models/query`)

Το `POST /v1/models/query` επιστρέφει μια σύντομη, ντετερμινιστική λίστα από τον ίδιο κατάλογο, με τον ίδιο
έλεγχο ταυτότητας και την ίδια ορατότητα ανά κλειδί όπως το `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Κάθε πεδίο είναι προαιρετικό. Τα `capabilities` και `exclude` δέχονται έναν πίνακα ή μια συμβολοσειρά διαχωρισμένη με κόμματα·
το `max_output` συγκρίνεται με το `max_output_tokens`. Τα αποτελέσματα ταξινομούνται πρώτα κατά `owned_by` και έπειτα κατά `id`.
Η προεπιλεγμένη τιμή του `limit` είναι `20` και οι τιμές πάνω από `100` περιορίζονται σε `100`. Μη έγκυρο JSON, ένα άγνωστο
πεδίο ή μια μη έγκυρη τιμή επιστρέφει HTTP `400`.

### Μεμονωμένα κρυφά μοντέλα συνομιλίας

Ένα μοντέλο που έχει επισημανθεί ως **Κρυφό** στη σελίδα του παρόχου του εξαιρείται από τον κατάλογο και απορρίπτεται
με HTTP `404` / `model_not_found` όταν ζητείται ρητά. Ο έλεγχος χρησιμοποιεί τον επιλυμένο
πάροχο και το μοντέλο, συμπεριλαμβανομένων των ψευδωνύμων παρόχων, των προθεμάτων κόμβων συμβατών παρόχων και των
προεπιλογών σύνδεσης. Ένας συνδυασμός παραλείπει τους κρυφούς προορισμούς και μπορεί να χρησιμοποιήσει έναν ορατό ομότιμο· όταν δεν
απομένει κανένας εκτελέσιμος προορισμός, επιστρέφει τον ίδιο κωδικό σφάλματος. Η κατάργηση της απόκρυψης τίθεται σε ισχύ στο επόμενο
αίτημα. Οι παρακάμψεις ορατότητας που αφορούν αποκλειστικά εικόνες δεν αποκρύπτουν το μοντέλο συνομιλίας με το ίδιο αναγνωριστικό.

Αυτή η μεμονωμένη ρύθμιση μοντέλου είναι ξεχωριστή από τις
[λίστες αποδοχής/απόρριψης έκθεσης μοντέλων](../routing/MODEL_EXPOSURE_LIST.md), οι οποίες φιλτράρουν την
εμφάνιση στον κατάλογο και τους υποψηφίους για αυτόματη δρομολόγηση, διατηρώντας παράλληλα τη ρητή αποστολή. Τα δικαιώματα μοντέλων
των κλειδιών API εξακολουθούν να εφαρμόζονται ανεξάρτητα. Η προεπιλεγμένη λειτουργία προθέματος καταλόγου παραμένει `dual`.

### Παραλλαγές μοντέλων χωρίς συλλογισμό

Για μοντέλα Claude με δυνατότητα συλλογισμού, το `/v1/models` εμφανίζει επίσης μια παραλλαγή **χωρίς συλλογισμό**, της οποίας το αναγνωριστικό έχει ως πρόθεμα το `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Η επιλογή αυτού του αναγνωριστικού (π.χ. σε μια διαμόρφωση Claude Code που επισυνάπτει πάντα ένα μπλοκ `thinking`) επιλύεται ξανά στο πραγματικό `<provider>/<model>` με τον συλλογισμό απενεργοποιημένο — `thinking:{type:"disabled"}` στη διαδρομή `/v1/messages` ή με την αφαίρεση των πεδίων `reasoning`/`reasoning_effort` στη διαδρομή `/v1/chat/completions`. Η παραλλαγή εμφανίζεται μόνο για μοντέλα της οικογένειας Claude που υποστηρίζουν συλλογισμό **και** αποδέχονται το `disabled` (οπότε, π.χ., εξαιρούνται τα μοντέλα αποκλειστικά προσαρμοστικού τύπου που απορρίπτουν το `disabled`). Οι διαχειριστές μπορούν να επιβάλουν την ενεργοποίηση ή την απενεργοποίηση της παραλλαγής ανά μοντέλο μέσω του `ModelSpec.noThinkingAlias`.

## Δημιουργία ήχου με το ElevenLabs

Διαμορφώστε μια σύνδεση παρόχου `elevenlabs` στο OmniRoute με το κλειδί API του ElevenLabs.
Οι πελάτες πραγματοποιούν έλεγχο ταυτότητας με το κλειδί τους για το **OmniRoute** (`Authorization: Bearer $OMNIROUTE_API_KEY`)·
η πύλη παρέχει το αποθηκευμένο κλειδί παρόχου ως `xi-api-key`. Μην αποστέλλετε ποτέ ένα κλειδί ElevenLabs
ως διακριτικό bearer της πύλης.

| Μέθοδος | Διαδρομή                    | Απόκριση                                   | Κατηγορία endpoint κλειδιού API |
| ------- | --------------------------- | ------------------------------------------ | ------------------------------- |
| POST    | `/v1/sound-generation`      | Εγγενή byte ήχου                           | `elevenlabs`                    |
| POST    | `/v1/music`                 | Εγγενή byte ήχου                           | `music`                         |
| POST    | `/v1/music/stream`          | Byte ήχου σε ροή                           | `music`                         |
| POST    | `/v1/music/detailed`        | Εγγενής πολυμερής ήχος και σχέδιο σύνθεσης | `music`                         |
| POST    | `/v1/music/detailed/stream` | Εγγενή μεταδεδομένα SSE και τμήματα ήχου   | `music`                         |
| POST    | `/v1/music/plan`            | Σχέδιο σύνθεσης JSON                       | `music`                         |

Αυτά τα endpoint συμπληρώνουν τις υπάρχουσες διαδρομές `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` και `/v1/speech-to-text`. Τα εγγενή πεδία JSON
και οι παράμετροι ερωτήματος, όπως τα `output_format` και `enable_logging`, διατηρούνται.
Οι αποκρίσεις `/v1/music/detailed` διατηρούν τα πολυμερή όριά τους· αναλύστε τες ως multipart.
Το `/v1/music/detailed/stream` επιστρέφει `text/event-stream` με μεταδεδομένα σύνθεσης και
τμήματα ήχου base64 σε συμβάντα SSE. Και οι έξι διαδρομές υποστηρίζουν προκαταρκτικά αιτήματα CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Ένα σύντομο ηχητικό εφέ. Διάρκεια: 0,5 έως 30 δευτερόλεπτα.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Η διάρκεια της μουσικής εκφράζεται σε χιλιοστά του δευτερολέπτου: 3000 έως 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Χρησιμοποιήστε το `/v1/music/stream` με το ίδιο σώμα JSON για σταδιακή παράδοση ήχου. Η σύνθεση
δέχεται ακριβώς ένα από τα `prompt` ή `composition_plan`· το `/v1/music/plan` απαιτεί `prompt`
και προαιρετικά δέχεται `source_composition_plan`. Τα εγγενή σχήματα διατηρούν πρόσθετα
πεδία παρόχου, ώστε οι εκδόσεις σχεδίων σύνθεσης και οι επιλογές λεπτομερούς ρύθμισης να φτάνουν στο ElevenLabs.

Το ενοποιημένο endpoint `/v1/music/generations` δέχεται επίσης τα `elevenlabs/music_v1`,
`elevenlabs/music_v2` και `elevenlabs/music_v2_5`. Με μια ενεργή σύνδεση ElevenLabs,
αυτά τα μοντέλα εμφανίζονται στον κατάλογο μουσικής. Αυτό το endpoint επιστρέφει
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Το πεδίο `duration` εκφράζεται σε
δευτερόλεπτα και αντιστοιχίζεται στο `music_length_ms`· ένα ρητά καθορισμένο `music_length_ms` έχει προτεραιότητα.
Το `instrumental` αντιστοιχίζεται στο `force_instrumental`, με το εγγενές πεδίο να έχει προτεραιότητα.
Χρησιμοποιήστε τα εγγενή endpoint ροής για streaming και το εγγενές endpoint σύνθεσης
για αιτήματα που καθοδηγούνται αποκλειστικά από ένα σχέδιο σύνθεσης.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Οι περιορισμοί endpoint, μοντέλου, προϋπολογισμού και σύνδεσης εφαρμόζονται πριν από μια κλήση προς τον upstream πάροχο. Οι εγγενείς
διαδρομές επιστρέφουν χωρίς αλλαγές τους κωδικούς κατάστασης και τα σώματα σφαλμάτων του upstream παρόχου, συμπεριλαμβανομένου του `402` για έναν περιορισμό
προγράμματος και του `429` για ένα όριο ποσόστωσης. Οι κεφαλίδες `character-cost`, `song-id`, `request-id` και `retry-after`
διατηρούνται όταν υπάρχουν. Ένα δωρεάν πιστωτικό υπόλοιπο δεν εγγυάται πρόσβαση σε κάθε
μοντέλο μουσικής, μορφή εξόδου ή δυνατότητα API: το ElevenLabs αποφασίζει τα δικαιώματα πρόσβασης για κάθε αίτημα.
Το ενοποιημένο endpoint διατηρεί τους κωδικούς κατάστασης σφαλμάτων στο κανονικοποιημένο περίβλημα σφάλματος του OmniRoute.

Συμβάσεις upstream: [ηχητικά εφέ](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[μουσική σύνθεση](https://elevenlabs.io/docs/api-reference/music/compose) και
[λεπτομέρειες μουσικής σε ροή](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

Όλες οι διαδρομές POST ακολουθούν την ίδια δομή: `Bearer your-api-key` + σώμα JSON επικυρωμένο μέσω Zod (`v1RerankSchema`, `v1ModerationSchema`, `v1AudioSpeechSchema` κ.λπ., βλ. `src/shared/validation/schemas.ts`). Σε περίπτωση αποτυχίας επικύρωσης του σχήματος επιστρέφεται 4xx.

Για πελάτες που δεν μπορούν να επισυνάψουν `Authorization: Bearer ...`, το OmniRoute δέχεται επίσης κλειδιά API στη διεύθυνση URL είτε μέσω παραμέτρων συμβατότητας στη συμβολοσειρά ερωτήματος (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`) είτε μέσω των αποκλειστικών τελικών σημείων `/api/v1/vscode/{token}/...` που τεκμηριώνονται παρακάτω.

```bash
# Ανακατάταξη (πάροχος μητρώου cloud ή κόμβος παρόχου συμβατού με OpenAI ως "<prefix>/<model>")
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Ταξινόμηση Jina (διαπιστευτήρια Foundation API)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Τμηματοποιητής Jina
POST /v1/segment     { "content": "...", "return_chunks": true }

# Αναζήτηση Jina (s.jina.ai· ψευδώνυμα παρόχου: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# Έλεγχοι εποπτείας
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — επιστρέφει σώμα audio/mpeg (ή της ζητούμενης μορφής)
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Το Soniox TTS απαιτεί γλώσσα και φωνή: η `language` έχει ως προεπιλογή το "en"· μια φωνή που λείπει
# ή ένα τυπικό όνομα φωνής του OpenAI (alloy, nova, …) μετατρέπεται σε "Adrian"
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# Επεξεργασία εικόνας (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# Δημιουργία βίντεο / μουσικής (αναγνωριστικό μοντέλου με πρόθεμα παρόχου)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **Κόμβοι παρόχων ανακατάταξης:** Το `POST /v1/rerank` δρομολογείται επίσης σε κόμβους παρόχων συμβατούς με το OpenAI
> (oMLX, vLLM, Infinity, TEI πίσω από μια πύλη, …), οι οποίοι προσδιορίζονται ως `<node-prefix>/<model>`. Οι κόμβοι
> loopback (`localhost`, `127.0.0.1`, `172.16.0.0/12`) είναι πάντα επιλέξιμοι, όπως και τα ονόματα κεντρικών υπολογιστών που
> παραθέτει ο διαχειριστής στο `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (π.χ. ένα όνομα υπηρεσίας Docker/Compose όπως
> το `http://reranker:8080/v1`· αυτοί καλούνται απευθείας, ποτέ μέσω `HTTP(S)_PROXY` ή του
> δεσμευμένου διακομιστή μεσολάβησης μιας σύνδεσης). Οι κόμβοι σε οποιονδήποτε άλλο
> κεντρικό υπολογιστή —ένα μηχάνημα LAN ή έναν ομότιμο κόμβο Tailscale— είναι επιλέξιμοι μόνο όταν ο διαχειριστής ενεργοποιεί τη
> σημαία δυνατότητας `RERANK_REMOTE_PROVIDER_NODES` **και** το βασικό URL του κόμβου συμμορφώνεται με την πολιτική
> εξερχόμενων URL του παρόχου (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Το βήμα ανακατάταξης της μηχανής μνήμης καλεί αυτήν τη διαδρομή μέσω
> loopback, επομένως ο ίδιος κανόνας διέπει το `rerankProviderModel` στις ρυθμίσεις μνήμης.
>
> **Μορφές τοπικού διακομιστή:** Ο κόμβος καλείται στη διεύθυνση `<base>/v1/rerank` και, σε περίπτωση 404, στη διεύθυνση `<base>/rerank`
> (Infinity, TEI). Το σώμα του ανάντη αιτήματος περιέχει τόσο την ορθογραφία Cohere/OpenAI (`documents`,
> `return_documents`) όσο και την ορθογραφία TEI (`texts`, `return_text`), ενώ η ανάντη απόκριση
> κανονικοποιείται στη δομή περιβλήματος Cohere: ο γυμνός πίνακας `[{index, score, text}]` του TEI, το `{results: [{index, score}]}`
> από απλές πύλες και το `{data: [...]}` τύπου Voyage επιστρέφονται όλα στον πελάτη ως
> `{results: [{index, relevance_score, document?}]}`, ταξινομημένα κατά βαθμολογία και περιορισμένα στο `top_n`.

> **Εντοπισμός κόμβων παρόχων:** Τα μοντέλα σε έναν κόμβο παρόχου συμβατό με το OpenAI εμφανίζονται στο `GET /v1/models`
> κάτω από το πρόθεμα του κόμβου. Οι εγγραφές που δεν περιλαμβάνουν μεταδεδομένα τελικού σημείου (σύνηθες στις τοπικές καταχωρίσεις `/v1/models`)
> κληρονομούν το `apiType` του κόμβου, ώστε τα μοντέλα ενός κόμβου `embeddings` να είναι `type: "embedding"` και τα
> μοντέλα ενός κόμβου `rerank` να είναι `type: "rerank"` αντί να χρησιμοποιούν από προεπιλογή τον τύπο συνομιλίας· ένα ρητό
> `supportedEndpoints` σε μια συγχρονισμένη ή μη αυτόματα προστεθειμένη εγγραφή εξακολουθεί να έχει προτεραιότητα.

## Files API

Τελικό σημείο αρχείων συμβατό με το OpenAI για μαζική είσοδο/έξοδο και μεταφορτώσεις με καθορισμένο σκοπό αρχείου.

| Μέθοδος | Διαδρομή                 | Περιγραφή                                                                                                                    |
| ------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| POST    | `/v1/files`              | Μεταφόρτωση αρχείου (multipart: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — μέγιστο όριο 512 MiB |
| GET     | `/v1/files`              | Παράθεση αρχείων για το πιστοποιημένο κλειδί API                                                                             |
| GET     | `/v1/files/[id]`         | Ανάκτηση των μεταδεδομένων ενός αρχείου                                                                                      |
| DELETE  | `/v1/files/[id]`         | Διαγραφή αρχείου                                                                                                             |
| GET     | `/v1/files/[id]/content` | Μετάδοση του ανεπεξέργαστου σώματος του αρχείου                                                                              |

**Έλεγχος ταυτότητας:** Κλειδί API τύπου Bearer — τα αρχεία περιορίζονται ανά κλειδί API μέσω του `getApiKeyRequestScope`. Ένα κλειδί
βλέπει, κατεβάζει και διαγράφει μόνο τα δικά του αρχεία· μια συνεδρία πίνακα ελέγχου χωρίς κλειδί διαβάζει ολόκληρο το
στιγμιότυπο· ένα αρχείο χωρίς κάτοχο (ανώνυμη μεταφόρτωση ή μεταφόρτωση μέσω συνεδρίας πίνακα ελέγχου) απορρίπτεται για κάθε
καλούντα χωρίς συνεδρία. Το `GET /v1/files` απορρίπτει έναν ανώνυμο καλούντα — καθώς και ένα παρεχόμενο κλειδί που δεν
αντιστοιχεί σε έγκυρο κλειδί — με `401`, ακόμη και όταν `REQUIRE_API_KEY=false`, αντί να παραθέτει τα αρχεία όλων των μισθωτών
(GHSA-m3hp-hq9g-fpmv, GHSA-2jm2-mpx8-6523).

## Batches API

Μαζική επεξεργασία συμβατή με το OpenAI.

| Μέθοδος | Διαδρομή                  | Περιγραφή                                                                                                                  |
| ------- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| POST    | `/v1/batches`             | Δημιουργία παρτίδας — το σώμα επικυρώνεται από το `v1BatchCreateSchema` (`input_file_id`, `endpoint`, `completion_window`) |
| GET     | `/v1/batches`             | Παράθεση παρτίδων                                                                                                          |
| GET     | `/v1/batches/[id]`        | Ανάκτηση κατάστασης παρτίδας + `request_counts`                                                                            |
| DELETE  | `/v1/batches/[id]`        | Διαγραφή ολοκληρωμένης/αποτυχημένης παρτίδας                                                                               |
| POST    | `/v1/batches/[id]/cancel` | Ακύρωση παρτίδας που βρίσκεται σε εξέλιξη                                                                                  |

**Έλεγχος ταυτότητας:** Κλειδί API τύπου Bearer. Οι παρτίδες περιορίζονται ανά κλειδί API σύμφωνα με τον ίδιο τριμερή κανόνα όπως και
τα αρχεία: πρόσβαση μόνο από το αντίστοιχο κλειδί, πρόσβαση σε ολόκληρο το στιγμιότυπο από συνεδρία πίνακα ελέγχου και απόρριψη εγγραφών χωρίς κάτοχο για κάθε
καλούντα χωρίς συνεδρία (ανάκτηση, διαγραφή, ακύρωση και έλεγχος του `input_file_id` κατά τη δημιουργία).
Το `GET /v1/batches` απορρίπτει έναν ανώνυμο καλούντα με `401`, ακόμη και όταν `REQUIRE_API_KEY=false`.

## API αναζήτησης

Αφαίρεση εξάρτησης από συγκεκριμένο πάροχο ιστού/αναζήτησης (Tavily, Brave, Exa, Serper κ.λπ.).

| Μέθοδος | Διαδρομή               | Περιγραφή                                                                                                                   |
| ------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| GET     | `/v1/search`           | Παραθέτει τους διαμορφωμένους παρόχους αναζήτησης και τις δυνατότητές τους                                                  |
| POST    | `/v1/search`           | Εκτελεί ένα ερώτημα αναζήτησης — το σώμα επικυρώνεται από το `v1SearchSchema` και υποστηρίζει προσωρινή αποθήκευση/συνένωση |
| GET     | `/v1/search/analytics` | Στατιστικά επιτυχιών/καθυστέρησης/προσωρινής αποθήκευσης ανά πάροχο                                                         |

**Έλεγχος ταυτότητας:** Κλειδί API τύπου Bearer (`extractApiKey` + `isValidApiKey`). Η πολιτική αναζήτησης επιβάλλεται μέσω του `enforceApiKeyPolicy`.

### `provider_options` των Exa και Tavily

Οι Exa και Tavily διαβάζουν πεδία ειδικά για τον πάροχο από έναν χώρο ονομάτων:
`provider_options.exa` (ή `provider_options["exa-search"]`) και `provider_options.tavily`
(ή `provider_options["tavily-search"]`). Προωθούνται μόνο τα παρακάτω κλειδιά. Καθένα
ελέγχεται βάσει του δικού του σχήματος Zod στο `open-sse/handlers/search/providerOptionsPassthrough.ts`
και ένα κλειδί λανθασμένου τύπου απορρίπτεται. Οποιοδήποτε άλλο κλειδί αγνοείται, συμπεριλαμβανομένων των στοιχείων ελέγχου ταυτότητας, της βασικής διεύθυνσης URL,
των `stream` και `outputSchema`. Τα μη εμφωλευμένα κλειδιά που χρησιμοποιούνται από άλλους παρόχους (`cx`, `depth`, ...) λειτουργούν
όπως πριν.

| Πάροχος | Πεδία ανώτατου επιπέδου                                                                                                                                                                                                                                                                                                                                                   | Εμφωλευμένα                                                                                                                                                                       |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa     | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (μη εμφωλευμένοι πρωτογενείς τύποι), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                            | Το `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` συγχωνεύεται πάνω από την προεπιλογή `{ text: true, highlights: true }` |
| Tavily  | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                                 |

Τα γενικά πεδία έχουν πάντα προτεραιότητα: `query`, `max_results`, `filters` (τομείς), `country` και το
θέμα που προκύπτει από το `search_type`. Στο Exa, το `search_type: "news"` διατηρεί το `category: "news"`.
Το Tavily αποδέχεται επίσης `search_type: "finance"` (`topic: "finance"`).

Το γενικό `time_range` μεταβιβάζεται πλέον και στους δύο παρόχους: το Exa λαμβάνει `startPublishedDate` (χρονοσήμανση ISO)
και το Tavily λαμβάνει `start_date` (`YYYY-MM-DD`). Μια ρητά καθορισμένη ημερομηνία στο `provider_options`
υπερισχύει της αντιστοιχισμένης.

Τα αποτελέσματα του Exa διατηρούν τα `id`, `highlight_scores`, `summary`, `subpages`, `entities` και `extras` στο
`provider_raw`. Τα αποτελέσματα του Tavily διατηρούν τα `images` και `favicon`.

Η λογιστική κόστους εξακολουθεί να χρησιμοποιεί το μη εμφωλευμένο μητρώο `costPerQuery`. Το Tavily χρεώνει
το `search_depth: "advanced"` με περισσότερες πιστώσεις ανά κλήση και αυτή η διαφορά δεν αποτυπώνεται στο
`usage.search_cost_usd`.

## API ανάκτησης ιστού

Εξαγάγετε περιεχόμενο από ένα URL μέσω ενός διαμορφωμένου παρόχου ανάκτησης ιστού (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Το Parallel Extract (`parallel-search`, ίδιο κλειδί API με το Parallel Search) επιστρέφει μόνο Markdown
— οποιοδήποτε άλλο `format` επιστρέφει `400` — και περιορίζει το περιεχόμενο στους 100.000 χαρακτήρες. Όταν
η ίδια η σελίδα προορισμού δεν μπορεί να εξαχθεί, η υπηρεσία ανάντη ροής το αναφέρει μέσα σε μια απόκριση HTTP 200·
το OmniRoute το εμφανίζει ως `422` με ένα σταθερό μήνυμα.

| Μέθοδος | Διαδρομή        | Περιγραφή                                                             |
| ------- | --------------- | --------------------------------------------------------------------- |
| POST    | `/v1/web/fetch` | Ανάκτηση/σάρωση ενός URL — σώμα επικυρωμένο από το `v1WebFetchSchema` |

**Έλεγχος ταυτότητας:** Κλειδί API Bearer (`extractApiKey` + `isValidApiKey`). Η πολιτική επιβάλλεται μέσω του `enforceApiKeyPolicy`.

**Εναλλακτική μετάβαση με επίγνωση ορίων χρήσης (#8297):** όταν δεν παρέχεται ρητό `provider`, η δεξαμενή
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`)
διατρέχεται με σταθερή σειρά
προτεραιότητας (πλήρης χρήση του πρώτου πριν από τον επόμενο) — ένας διαμορφωμένος πάροχος που έχει περιοριστεί λόγω ρυθμού παραλείπεται
αντί να τερματίζεται άμεσα το αίτημα, ενώ μια επαναλήψιμη αποτυχία ή αποτυχία ορίου χρήσης της υπηρεσίας ανάντη ροής
(HTTP 429 πάντοτε· 402/403 για τα δωρεάν επίπεδα τύπου ορίου χρήσης των Firecrawl/Tavily/TinyFish —
όχι για το Jina Reader και ποτέ για ένα απλό εσφαλμένο αίτημα 400) οδηγεί στον
επόμενο μη δοκιμασμένο πάροχο με διαθέσιμα διαπιστευτήρια κατά την εκτέλεση του αιτήματος. Όταν εξαντληθούν όλοι οι πάροχοι στη
δεξαμενή, το τελικό σημείο επιστρέφει ένα ενιαίο `429` (με κεφαλίδα `Retry-After`)
αντί για το προηγούμενο γενικό `400`. Όταν ζητείται ρητά ένα `provider`, **δεν** υπάρχει
σιωπηρή εναλλακτική μετάβαση — ένας ρητά καθορισμένος πάροχος που έχει περιοριστεί λόγω ρυθμού ή αποτυγχάνει
εμφανίζει το δικό του σφάλμα (`429` εάν έχει περιοριστεί λόγω ρυθμού, διαφορετικά την κατάσταση
της υπηρεσίας ανάντη ροής).

## Ροή μέσω WebSocket

```bash
GET /v1/ws?handshake=1
```

Επικυρώνει μια χειραψία αναβάθμισης WebSocket και επιστρέφει τα παραδείγματα μηνυμάτων του ενσύρματου πρωτοκόλλου (`request`, `cancel`). Τα πραγματικά πλαίσια WS διαχειρίζονται από τον συμπεριλαμβανόμενο διακομιστή WS εκτός του πίνακα διαδρομών του Next.js.

**Έλεγχος ταυτότητας:** Κλειδί API Bearer κατά τη χειραψία.

### Responses API μέσω WebSocket (μόνο codex)

```bash
# Ίδιο host:port με το HTTP API (προεπιλογή 20128)· αναβαθμίστε τη σύνδεση:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (ή: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Το πρώτο πλαίσιο ΠΡΕΠΕΙ να είναι response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Ένας διαμεσολαβητής Responses-API-over-WebSocket είναι συνδεδεμένος **αποκλειστικά με το `codex`** (υποσύστημα
ChatGPT). Ακούει στην ίδια θύρα με το API/τον πίνακα ελέγχου, στις διαδρομές `/v1/responses`,
`/responses` και `/api/v1/responses`. Στο πρώτο πλαίσιο `response.create`
πραγματοποιεί έλεγχο ταυτότητας και προετοιμασία μέσω της εσωτερικής γέφυρας `codex-responses-ws`, επιλέγει μια
σύνδεση OAuth του codex και δημιουργεί διοχέτευση προς το `wss://chatgpt.com/backend-api/codex/responses`
μέσω της μεταφοράς `wreq-js`. **Τα μοντέλα εκτός codex απορρίπτονται** (`codex_ws_provider_required`).
Για δρομολόγηση κοινής χρήσης ορίου χρησιμοποιήστε `model: "qtSd/<group>/codex/<model>"`. Υλοποιείται στα
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Έλεγχος ταυτότητας:** Κλειδί API Bearer κατά τη χειραψία. Ο συμπεριλαμβανόμενος διακομιστής HTTP (`server-ws.mjs`)
πρέπει να είναι το ενεργό σημείο εισόδου (και είναι, από προεπιλογή, όταν υπάρχει το `app/server-ws.mjs`).

#### Αναγνωριστικό μοντέλου: χρησιμοποιήστε το σκέτο αναγνωριστικό ChatGPT (χωρίς πρόθεμα `codex/`)

Το **Codex CLI** της OpenAI επικυρώνει το όνομα του μοντέλου στην πλευρά του πελάτη όταν
`supports_websockets = true` και **απορρίπτει αναγνωριστικά με πρόθεμα παρόχου** όπως
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Στείλτε το **σκέτο** αναγνωριστικό (π.χ. `gpt-5.5`). Η γέφυρα του OmniRoute είναι
μόνο για codex, επομένως επιλύει εκ νέου ένα σκέτο αναγνωριστικό ως μοντέλο codex
(`resolveCodexWsModelInfo`) πριν από τη διοχέτευση προς την υπηρεσία ανάντη ροής — παρόλο που ένα σκέτο
`gpt-5.5` θα δρομολογούνταν διαφορετικά σε άλλον πάροχο μέσω HTTP.

#### Διαμόρφωση του OpenAI Codex CLI

Κατευθύνετε το Codex CLI στο OmniRoute προσθέτοντας έναν προσαρμοσμένο πάροχο με υποστήριξη WebSocket
στο `~/.codex/config.toml` (χρησιμοποιήστε ξεχωριστό `CODEX_HOME` ώστε να μην τροποποιήσετε
μια υπάρχουσα διαμόρφωση):

```toml
model = "gpt-5.5"                 # σκέτο αναγνωριστικό — ΟΧΙ "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # χωρίς τελική κάθετο· το URL του WS παράγεται αυτόματα (χρησιμοποιήστε https/wss στην παραγωγή)
wire_api = "responses"                    # η μόνη υποστηριζόμενη τιμή από τον Φεβ 2026
supports_websockets = true                # ενεργοποιεί τη μεταφορά Responses-over-WS
env_key = "OMNIROUTE_API_KEY"             # περιέχει το κλειδί API του OmniRoute (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # ένα κλειδί API του OmniRoute (οποιοδήποτε κλειδί εάν REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

Το CLI αναβαθμίζει το `base_url + /responses` σε WebSocket και το OmniRoute το διοχετεύει
στην επιλεγμένη σύνδεση OAuth του codex. Έχει επικυρωθεί από άκρο σε άκρο με τον τοπικό
διακομιστή: το ChatGPT επιστρέφει `codex.rate_limits` + `response.created` και μεταδίδει σταδιακά την
ολοκλήρωση.

## Αυτοεξυπηρετούμενη χρήση (`/api/usage/om-usage`)

Οποιοδήποτε API key μπορεί να διαβάσει **τη δική του** χρήση και τα όρια χρήσης — χωρίς έλεγχο ταυτότητας διαχείρισης. Αυτό είναι το endpoint που χρησιμοποιεί ένας
πελάτης (CLI, ο πίνακας OmniCopilot) για να εμφανίσει σε έναν κάτοχο κλειδιού τις δαπάνες του.

```bash
# Μορφή κειμένου (η ιστορική σύμβαση — απλό κείμενο για τερματικό)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Δομημένη μορφή — αυτή που χρησιμοποιεί ένα UI
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Το κλειδί πρέπει να έχει ενεργοποιημένο το **`allowUsageCommand`** (είναι ανενεργό από προεπιλογή — ο διαχειριστής API key
του dashboard το ενεργοποιεί ή απενεργοποιεί ανά κλειδί). Χωρίς αυτό, το endpoint απαντά με `403`.

Το `?format=json` επιστρέφει μια διακριτή δομή, ώστε ο καλών να μην επιχειρεί ποτέ να διαβάσει ένα πεδίο δεδομένων από μια
άρνηση. Σε περίπτωση επιτυχίας:

```jsonc
{
  "allowed": true,
  // υπάρχει μόνο όταν το κλειδί έχει ενεργοποιήσει όρια χρήσης ανά κλειδί (ημερήσια/εβδομαδιαία σε USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // το στιγμιότυπο ορίου χρήσης του επιλεγμένου παρόχου ή null όταν δεν υπάρχει ακόμη τίποτα στην cache:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // το στιγμιότυπο κάθε σύνδεσης, ώστε ένα UI να μπορεί να αποδώσει πολλούς παρόχους δίπλα-δίπλα:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Σε περίπτωση άρνησης (`401` λανθασμένο κλειδί / `403` μη επιτρεπτό), η ίδια διαδρομή επιστρέφει
`{ "allowed": false, "error": { "message": "…" } }` — ένα υπάρχον αλλά κενό `personal`/`provider`
(το κλειδί επιτρέπεται, αλλά δεν έχουν συλλεχθεί ακόμη δεδομένα) αποτελεί διαφορετική κατάσταση από μια άρνηση και μόνο η μορφή JSON
τα διακρίνει.

**Έλεγχος ταυτότητας:** το Bearer API key του ίδιου του καλούντος, το οποίο επικυρώνεται με `isValidApiKey` — αυτό _δεν_ είναι η
επιφάνεια διαχείρισης (`/api/keys/…`), η οποία παραμένει προστατευμένη από το `requireManagementAuth`.

### Ακατέργαστα έναντι Προσαρμοσμένων βάσει Ορίου Ποσοστών Ορίων Χρήσης

Κατά τη χρήση του `/api/usage/om-usage`, οι καλούντες πρέπει να λαμβάνουν υπόψη τη διάκριση μεταξύ των
ποσοστών που παρουσιάζονται στην **έξοδο απλού κειμένου** και στη δομημένη **έξοδο JSON**:

| Παράμετρος             | Μορφή απλού κειμένου (`/api/usage/om-usage` / `@@om-usage`)                                                | Μορφή JSON (`?format=json`)                                                                      |
| :--------------------- | :--------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------- |
| **Πεδίο εξόδου**       | `NN% left` (π.χ. `20% left`)                                                                               | `provider.quotas` / `providers[].quotas`                                                         |
| **Μέτρηση**            | **Χρησιμοποιήσιμο περιθώριο προσαρμοσμένο βάσει ορίου**: εναπομένουσα χωρητικότητα πάνω από το όριο        | **Ακατέργαστο όριο χρήσης upstream**: μη προσαρμοσμένη μέτρηση του παρόχου                       |
| **Κλιμάκωση ορίου**    | Κλιμακώνεται μέσω `effectiveRemainingPercent()`, ώστε το προστατευμένο απόθεμα να εμφανίζεται ως `0% left` | Καμία (ακατέργαστες τιμές στιγμιότυπου όπως αναφέρονται από τον πάροχο)                          |
| **Δεδομένα κατωφλίου** | Ενσωματώνονται στο εμφανιζόμενο ποσοστό                                                                    | Αποθηκεύονται στο `quotaWindowThresholds` ανά σύνδεση (ή στις προεπιλογές διακομιστή)            |
| **Κύριος καταναλωτής** | Διαδραστικά CLI, προτροπές τερματικού, ανθρώπινοι χειριστές                                                | Προγραμματιστικές ενσωματώσεις, dashboard, αναλυτικά στοιχεία, συστήματα παρακολούθησης χρεώσεων |

#### Ο Τύπος Προσαρμογής βάσει Ορίου

Το OmniRoute υποστηρίζει προληπτικά όρια διακοπής χρήσης για την αποτροπή εξάντλησης του upstream (διαμορφωμένα μέσω των
`quotaWindowThresholds` της σύνδεσης, των προεπιλογών του παρόχου ή των καθολικών ρυθμίσεων ανθεκτικότητας). Όταν ένα όριο διακοπής
(π.χ. `cutoff = 25%`) είναι ενεργό σε ένα παράθυρο ορίου χρήσης, ο αποτυπωτής κειμένου υπολογίζει το εναπομένον περιθώριο ως εξής:

- Αν `remaining <= cutoff`: επιστρέφει `0%`.
- Αν `remaining > cutoff`: επιστρέφει `((remaining - cutoff) / (100 - cutoff)) * 100`.

Η μορφοποιημένη έξοδος κειμένου στρογγυλοποιεί το αποτέλεσμα στον πλησιέστερο ακέραιο (`Math.round(...)`).

#### Ενδεικτικό Παράδειγμα

Εξετάστε ένα παράθυρο παρόχου με **60% ακατέργαστη χρήση** (άρα **40% ακατέργαστο εναπομένον όριο χρήσης**) και ένα διαμορφωμένο
κατώφλι **διακοπής στο 25% του εναπομένοντος ορίου χρήσης**:

| Αναπαράσταση                          | Υπολογισμός                                        | Εναπομένον |            Έμμεσα χρησιμοποιημένο             |
| :------------------------------------ | :------------------------------------------------- | :--------: | :-------------------------------------------: |
| **Ακατέργαστο JSON (`?format=json`)** | Στιγμιότυπο upstream (`quotas[window]`)            |  **40%**   |                    **60%**                    |
| **Μορφή κειμένου (`NN% left`)**       | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` |  **20%**   | **80%** (αν υπολογιστεί ως `100 - remaining`) |

- **Γιατί το κείμενο εμφανίζει 20% να απομένει:** Από το 40% του πραγματικού ορίου χρήσης που απομένει στον λογαριασμό, το 25% δεσμεύεται από την
  πολιτική διακοπής. Ο καλών διαθέτει μόνο 15% από το 75% του χρησιμοποιήσιμου περιθωρίου που απομένει πριν ο router σταματήσει
  να δρομολογεί προς αυτήν τη σύνδεση. Η κλιμάκωση διασφαλίζει ότι η σύνδεση σηματοδοτεί εξάντληση (`0% left`) ακριβώς όταν
  σταματήσει η δρομολόγηση.
- **Γιατί το JSON διατηρεί τις ακατέργαστες τιμές:** Το ωφέλιμο φορτίο JSON επιστρέφει το ακριβές στιγμιότυπο του παρόχου (`UsageSnapshot`),
  ώστε τα εξωτερικά εργαλεία να έχουν πρόσβαση στην πραγματική upstream χρήση και στα
  `quotaWindowThresholds` σε επίπεδο σύνδεσης, χωρίς απωλεστική κλιμάκωση από την πλευρά του διακομιστή.

#### Οδηγίες Μετάβασης για Καταναλωτές

Εάν μια εξωτερική ενσωμάτωση (όπως ένα πρόσθετο επεξεργαστή ή μια επέκταση agent) αντλούσε προηγουμένως δεδομένα από το endpoint
κειμένου (`NN% left`) και υπολόγιζε το χρησιμοποιημένο ποσοστό ως `100 - NN`, η μετάβαση στο `?format=json` σημαίνει ότι:

- Η ανάγνωση των ανεπεξέργαστων τιμών JSON θα αντικατοπτρίζει την **πραγματική κατανάλωση ανάντη** (60% χρησιμοποιημένο στο παραπάνω παράδειγμα).
- Εάν η ενσωμάτωση επιθυμεί να διατηρήσει τη σημασιολογία του διαθέσιμου ορίου του endpoint κειμένου, μπορεί να αξιολογήσει
  τον τύπο του πραγματικού υπολοίπου στην πλευρά του client, χρησιμοποιώντας το `quotaWindowThresholds` για παρακάμψεις σε επίπεδο σύνδεσης.

## Σημασιολογική κρυφή μνήμη

```bash
# Λήψη στατιστικών κρυφής μνήμης
GET /api/cache/stats

# Εκκαθάριση όλων των κρυφών μνημών
DELETE /api/cache/stats
```

Παράδειγμα απόκρισης:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### Επίδραση στον λανθάνοντα χρόνο

Μια ΕΠΙΤΥΧΙΑ στη σημασιολογική κρυφή μνήμη εξυπηρετεί την απόκριση από την κρυφή μνήμη **χωρίς κλήση προς ανάντη υπηρεσία**, επομένως το αναφερόμενο `X-OmniRoute-Response-Latency` είναι σχεδόν μηδενικό
(ανεξάρτητα από τον αρχικό λανθάνοντα χρόνο της ανάντη υπηρεσίας). Οι πελάτες που είναι ευαίσθητοι στον λανθάνοντα χρόνο
(μετρήσεις επιδόσεων, παρακολούθηση p50/p99) θα πρέπει να ελέγχουν την κεφαλίδα απόκρισης
`X-OmniRoute-Cache-Latency`:

| Τιμή        | Σημασία                                                                                                           |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `synthetic` | Η απόκριση εξυπηρετήθηκε από την κρυφή μνήμη· ο λανθάνων χρόνος δεν είναι πραγματικός χρόνος της ανάντη υπηρεσίας |
| _(απούσα)_  | Απόκριση από πραγματική κλήση προς την ανάντη υπηρεσία                                                            |

### Παράκαμψη κρυφής μνήμης ανά κλειδί

Τα κλειδιά API μπορούν να εξαιρεθούν από τις αναγνώσεις της σημασιολογικής κρυφής μνήμης μέσω του `cacheDefaultMode`:

| Τιμή     | Συμπεριφορά                                                                                    |
| -------- | ---------------------------------------------------------------------------------------------- |
| `legacy` | Κανονική συμπεριφορά κρυφής μνήμης (προεπιλογή)                                                |
| `bypass` | Πλήρης παράλειψη της αναζήτησης στην κρυφή μνήμη· πάντα γίνεται κλήση προς την ανάντη υπηρεσία |

Ορίστε το κατά τη δημιουργία κλειδιού (`POST /api/keys`) ή την ενημέρωση (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### Παράκαμψη ανά αίτημα

Οποιοδήποτε αίτημα μπορεί να παρακάμψει την κρυφή μνήμη ανεξάρτητα από τις ρυθμίσεις του κλειδιού:

```
X-OmniRoute-No-Cache: true
```

Για συγχρονισμένα/εισαγόμενα μοντέλα, το `PUT /api/provider-models` δέχεται `provider`, `modelId` και
`maxOutputTokenOverride`: ένας θετικός ακέραιος ορίζει το μη αυτόματο όριο token εξόδου, ενώ η τιμή `null`
το καταργεί για να επαναφέρει την προεπιλογή. Το `GET /api/provider-models?provider=<provider>` επιστρέφει αυτές
τις τιμές στο `modelOutputOverrides`, συμπεριλαμβανομένων μοντέλων χωρίς εγγραφή προσαρμοσμένου μοντέλου. Η παράκαμψη
χρησιμοποιεί τη δυνατότητα `max_output_tokens` κατά τον χρόνο εκτέλεσης και διατηρείται μετά από νέο συγχρονισμό του μοντέλου. Η σελίδα παρόχου
που είναι συμβατού με OpenAI προσφέρει τα ίδια στοιχεία ελέγχου επεξεργασίας/εκκαθάρισης και επισημαίνει τα μοντέλα με ρητή υποστήριξη όρασης.

Οι προσαρμοσμένοι κόμβοι Chat Completions προσαρμόζουν τις ρητές εξαιρέσεις από τη συλλογιστική στο ανάντη backend. Μια
επιτυχής δοκιμή σύνδεσης επιλέγει αυτόματα στοιχεία ελέγχου προτύπου συνομιλίας για κάθε ακριβές ID μοντέλου,
του οποίου η καταχώριση `/models` αποδεικνύει μια αναγνωρισμένη τιμή `owned_by`: `vllm`, `sglang` ή `llamacpp`.
Διαφανή περιτυλίγματα συμβατά με OpenAI ενδέχεται να διατηρούν την αρχική καταχώριση μοντέλου μέσα σε ένα ένθετο
αντικείμενο `openai`· η ανίχνευση ακολουθεί έως και τρία τέτοια περιβλήματα. Μοντέλα με απούσα, άγνωστη ή
αντικρουόμενη ιδιοκτησία διατηρούν τη συνήθη συμπεριφορά OpenAI. Η ανίχνευση επαναχρησιμοποιεί το υπάρχον αίτημα καταλόγου,
δεν δημιουργεί token ολοκλήρωσης και ακυρώνεται όταν αλλάζει το τελικό σημείο σύνδεσης.

Για να καθηλώσετε τη συμπεριφορά για ένα backend που δεν εκθέτει αυτά τα μεταδεδομένα, χρησιμοποιήστε το υπάρχον API
μερικής ενημέρωσης παρόχου:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Στείλτε αυτό το σώμα με `PUT /api/providers/<connection-id>`. Σε αυτήν τη σύνδεση, μια ρητή
προσπάθεια συλλογιστικής με τιμή `none` αποστέλλεται ως `chat_template_kwargs.thinking=false` και
`chat_template_kwargs.enable_thinking=false`. Οι ρητές εγγενείς τιμές προτύπου παραμένουν καθοριστικές,
εκτός εάν ένας κανόνας συλλογιστικής στην πλευρά του διακομιστή επιβάλλει μια προσπάθεια. Η ρύθμιση εφαρμόζεται μόνο όταν μια προσαρμοσμένη
σύνδεση συμβατή με OpenAI αποστέλλει ένα σώμα Chat Completions· τα αιτήματα Responses και οι συνήθεις
πάροχοι διατηρούν την εγγενή μορφή αιτήματός τους. Ορίστε το `reasoningControl` σε `openai` για να επιβάλετε τη συνήθη απευθείας μεταβίβαση
του `reasoning_effort` του OpenAI ή παραλείψτε το/ορίστε το σε `null` για να χρησιμοποιηθεί η αυτόματη ανίχνευση.

Τα αιτήματα του ταξινομητή αυτόματης λειτουργίας του Claude Code απενεργοποιούν από προεπιλογή την εγγενή συλλογιστική όταν δεν περιέχουν
ρητά στοιχεία ελέγχου συλλογιστικής. Η ανίχνευση χρησιμοποιεί τον δείκτη συστήματος του ταξινομητή σε αιτήματα μορφής Claude
και όχι ονόματα μοντέλων ή όρια ολοκλήρωσης. Τα ρητά στοιχεία ελέγχου σώματος, οι υποστηριζόμενες κεφαλίδες προσπάθειας/συλλογιστικής,
οι κανόνες δρομολόγησης και η επιλυμένη προσπάθεια μοντέλου διατηρούν την υπάρχουσα προτεραιότητά τους. Και τα δύο στάδια του ταξινομητή
διατηρούν τις προτροπές, τα όρια ολοκλήρωσης, τις ακολουθίες διακοπής και τις πραγματικές ετυμηγορίες δικαιωμάτων από το ανάντη σύστημα·
το δεύτερο στάδιο μπορεί ακόμα να παραγάγει την αιτούμενη ορατή συλλογιστική ως απλό κείμενο.

### Έκδοση και Κανάλι Κυκλοφορίας

```bash
GET /api/system/version
```

Διαδρομή διαχείρισης μόνο μέσω loopback (έλεγχος ταυτότητας διαχειριστή). Επιστρέφει την έκδοση που εκτελείται, την πιο πρόσφατη
δημοσιευμένη έκδοση και την κατάσταση αυτόματης ενημέρωσης. Τα `releaseChannel` και `channels` είναι πρόσθετα
πεδία (rail 3.8.54)· το `channel` διατηρεί τη σημασία του — τον τρόπο ανάπτυξης που χρησιμοποιεί το πρόγραμμα ενημέρωσης
του πίνακα ελέγχου (`npm`, `source` ή `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — κανάλι npm της έκδοσης που εκτελείται: `nightly` για εκδόσεις `-nightly.*`,
  `next` για άλλες προεκδόσεις (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` για μια σταθερή έκδοση μιας
  κύριας έκδοσης παλαιότερης από το `channels.latest`, διαφορετικά `latest`. Ισχύουν οι ίδιοι κανόνες με το
  `scripts/release/dist-tag.mjs`, το οποίο επιλέγει το npm dist-tag κατά τη δημοσίευση.
- `channels` — η πιο πρόσφατη δημοσιευμένη έκδοση κάθε dist-tag, από το `npm view omniroute dist-tags` (με
  εναλλακτική χρήση HTTP του μητρώου), αποθηκευμένη στην κρυφή μνήμη με το ίδιο TTL 10 λεπτών όπως το `latest`. Το `latest` είναι πάντα παρόν
  (χρησιμοποιεί εναλλακτικά το πεδίο `latest` και κατόπιν το `"unavailable"`)· τα `next`, `nightly` και `lts` εμφανίζονται
  μόνο όταν υπάρχει το αντίστοιχο dist-tag. Ένα αίτημα `Cache-Control: no-cache` ανανεώνει και τις δύο αναζητήσεις.

Το μοντέλο καναλιών (`latest` = v3 έως τη γενική διαθεσιμότητα της 4.0, `next` = rc, `nightly` = εκδόσεις `develop`,
`lts` = διορθώσεις v3 μετά τη γενική διαθεσιμότητα της 4.0) περιγράφεται στο `docs/ops/RELEASE_STRATEGY.md`.

## Μεταγραφή ήχου

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data
```

Μεταγράψτε αρχεία ήχου χρησιμοποιώντας οποιονδήποτε διαμορφωμένο πάροχο STT. Το πρώτο τμήμα
της διαδρομής επιλέγει τον εγγενή πάροχο (`openai/…`, `deepgram/…`). Οι πύλες που
επανεξάγουν το μοντέλο άλλου προμηθευτή χρησιμοποιούν ένα πλήρως προσδιορισμένο αναγνωριστικό
(`openrouter/deepgram/nova-3`).

**Αίτημα:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**Απόκριση:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**Παραδείγματα αναγνωριστικών μοντέλων:** `openai/whisper-1` (απαιτεί κλειδί OpenAI),
`openrouter/deepgram/nova-3` (απαιτεί κλειδί OpenRouter),
`deepgram/nova-3` (απαιτεί εγγενές κλειδί Deepgram). Ένα μη προσδιορισμένο
αίτημα `deepgram/nova-3` **δεν** χρησιμοποιεί το OpenRouter.

**Υποστηριζόμενες μορφές:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`.

Χρησιμοποιήστε αυτά τα ψευδώνυμα όταν μια ενσωμάτωση δεν μπορεί να εισαγάγει μια κεφαλίδα `Authorization` και χρειάζεται το κλειδί API ενσωματωμένο στη βασική διεύθυνση URL.

```bash
# Ψευδώνυμο καταλόγου τύπου OpenAI
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# Ψευδώνυμα συνομιλίας τύπου OpenAI
POST /api/v1/vscode/{token}/chat/completions

# Ψευδώνυμα τύπου Ollama

GET /api/v1/vscode/{token}/api/tags
```

Παράδειγμα:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'
```

Σημειώσεις:

- Τα ψευδώνυμα με διακριτικό επαναχρησιμοποιούν τους ίδιους χειριστές με τα `/v1/*` και `/api/tags`· οι μορφές των αποκρίσεων παραμένουν ίδιες.
- Προτιμήστε το `Authorization: Bearer ...` όποτε το πρόγραμμα-πελάτης υποστηρίζει προσαρμοσμένες κεφαλίδες.
- Τα διακριτικά που βασίζονται σε URL ενδέχεται να εμφανίζονται σε αρχεία καταγραφής αντίστροφων διακομιστών μεσολάβησης, στο ιστορικό του προγράμματος περιήγησης και σε δεδομένα τηλεμετρίας εκτός του OmniRoute. Αντιμετωπίστε τα ως επιλογή συμβατότητας και όχι ως προεπιλεγμένη μέθοδο ελέγχου ταυτότητας.

## Όρια Token

Προϋπολογισμοί **token** ανά κλειδί API (διακριτοί από τον παραπάνω προϋπολογισμό βάσει USD). Επιβάλλονται απευθείας στη διαδρομή του αιτήματος: όταν η χρήση ενός κλειδιού στο τρέχον χρονικό παράθυρο φτάσει το όριό του, τα αιτήματα απορρίπτονται με `429 Too Many Requests`. Τα όρια μπορούν να περιορίζονται σε συγκεκριμένο `model`, συγκεκριμένο `provider` ή να εφαρμόζονται καθολικά (`global`) σε ολόκληρο το κλειδί· όταν ένα αίτημα αντιστοιχεί σε πολλά όρια, υπερισχύει το πιο περιοριστικό.

```bash
# Εμφάνιση των ορίων token ενός κλειδιού (περιλαμβάνει την τρέχουσα χρήση του χρονικού παραθύρου)
GET /api/usage/token-limits?apiKeyId=key-123

# Δημιουργία ή ενημέρωση ενός ορίου token
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Διαγραφή ενός ορίου token βάσει id
DELETE /api/usage/token-limits?id=tl-abc
```

> **Σημειώσεις σχήματος** (`setTokenLimitSchema`): Τα `apiKeyId` και `scopeType` (`model` | `provider` | `global`) είναι υποχρεωτικά. Το `scopeValue` είναι υποχρεωτικό, εκτός εάν το `scopeType` είναι `global` (π.χ. ένα αναγνωριστικό μοντέλου για εμβέλεια `model`, ένα αναγνωριστικό παρόχου για εμβέλεια `provider`). Το `tokenLimit` πρέπει να είναι θετικός ακέραιος (μετατρέπεται από συμβολοσειρά). Προαιρετικά: `id` (παραλείψτε το για δημιουργία, συμπεριλάβετέ το για ενημέρωση), `resetInterval` (`daily` | `weekly` | `monthly`, προεπιλογή `monthly`), `resetTime` (`HH:MM`), `enabled` (προεπιλογή `true`). Οι αποκρίσεις `GET` εμπλουτίζουν κάθε όριο με τα `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` και `nextResetAt`. Αυτό είναι endpoint κατηγορίας διαχείρισης (ο έλεγχος ταυτότητας επιβάλλεται κεντρικά από τη διοχέτευση εξουσιοδότησης).

## Επεξεργασία Αιτήματος

1. Ο πελάτης στέλνει αίτημα στο `/v1/*`
2. Ο χειριστής διαδρομής καλεί τα `handleChat`, `handleEmbedding`, `handleAudioTranscription` ή `handleImageGeneration`
3. Επιλύεται το μοντέλο (άμεσος πάροχος/μοντέλο ή ψευδώνυμο/συνδυασμός)
4. Επιλέγονται διαπιστευτήρια από την τοπική βάση δεδομένων, με φιλτράρισμα βάσει διαθεσιμότητας λογαριασμού
5. Για συνομιλία: το `handleChatCore` ελέγχει τη σημασιολογική cache/cache υπογραφών και επιλύει τις ρυθμίσεις συμπίεσης του συνδυασμού
6. Η προληπτική συμπίεση εκτελείται πριν από τη μετάφραση για τον πάροχο, όταν είναι ενεργοποιημένη (`lite`, Caveman, RTK ή στοιβαγμένη)
7. Ο εκτελεστής του παρόχου στέλνει το αίτημα προς την upstream υπηρεσία
8. Η απόκριση μεταφράζεται ξανά στη μορφή του πελάτη (συνομιλία) ή επιστρέφεται ως έχει (ενσωματώσεις/εικόνες/ήχος)
9. Καταγράφονται η χρήση, τα αναλυτικά στοιχεία συμπίεσης και τα αρχεία καταγραφής αιτημάτων
10. Σε περίπτωση σφαλμάτων εφαρμόζεται εναλλακτική επιλογή σύμφωνα με τους κανόνες του συνδυασμού

Πλήρης αναφορά αρχιτεκτονικής: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Ανθεκτικότητα (εκτεταμένη)

Το OmniRoute παρέχει τρεις ανεξάρτητους μηχανισμούς προσωρινής αποτυχίας· τα παρακάτω endpoints διαχείρισης επιτρέπουν στους διαχειριστές να διαβάζουν και να παρακάμπτουν τις ρυθμίσεις τους:

| Εμβέλεια                   | Αποθήκευση κατάστασης                     | Ανάγνωση                                  | Επαναφορά / εκκαθάριση                                     |
| -------------------------- | ----------------------------------------- | ----------------------------------------- | ---------------------------------------------------------- |
| Διακόπτης παρόχου          | `domain_circuit_breakers` + στη μνήμη     | `/api/monitoring/health`                  | `POST /api/resilience/reset`                               |
| Περίοδος αναμονής σύνδεσης | `rateLimitedUntil` στις συνδέσεις παρόχων | `/api/rate-limits`, `/api/providers/[id]` | (επανενεργοποιείται σταδιακά· εκκαθάριση μέσω PUT παρόχου) |
| Κλείδωμα μοντέλου          | Μητρώο διαθεσιμότητας μοντέλων στη μνήμη  | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                   |

Το `PATCH /api/resilience` δέχεται παρακάμψεις του διακόπτη παρόχου στα `providerBreaker.oauth` και `providerBreaker.apikey`. Κάθε προφίλ υποστηρίζει τα `degradationThreshold`, `failureThreshold` και `resetTimeoutMs`· τα ίδια πεδία είναι διαθέσιμα στο Dashboard → Settings → Resilience.

```bash
# Εκκαθάριση κλειδώματος ενός μοντέλου
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Διαγραφή όλων των κλειδωμάτων
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Για πλήρη εννοιολογική τεκμηρίωση και τις προεπιλεγμένες ρυθμίσεις του διακόπτη, ανατρέξτε στο [`CLAUDE.md`](../../CLAUDE.md) → «Κατάσταση χρόνου εκτέλεσης ανθεκτικότητας» και στο [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Ουρά ορίων ρυθμού και δίχτυ ασφαλείας αυτόματης ενεργοποίησης

- **Υποστηριζόμενη διαδρομή εγγραφής**: Το `POST /api/rate-limits` με σώμα `{"connectionId": "<id>", "enabled": true|false}` είναι το υποστηριζόμενο endpoint διαχείρισης για την ενεργοποίηση ή απενεργοποίηση της προστασίας από όρια ρυθμού για μια σύνδεση. Το `PUT /api/providers/[id]` σκόπιμα δεν τροποποιεί ούτε αλλάζει το `rateLimitProtection` (#11278).
- **Σημασιολογία του `enabled: false`**: Ο ορισμός του `enabled: false` καταργεί τη ρητή προστασία για τη σύνδεση, αλλά **δεν** εξαιρεί μια ενεργή σύνδεση με κλειδί API από το καθολικό δίχτυ ασφαλείας αυτόματης ενεργοποίησης (`autoEnableApiKeyProviders = true`). Στο `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), τα `false` και `undefined` είναι ισοδύναμα· οι ενεργές συνδέσεις με κλειδί API χωρίς ρητή προστασία παραμένουν προστατευμένες από το δίχτυ ασφαλείας αυτόματης ενεργοποίησης.
- **Καθολική απενεργοποίηση**: Για να λειτουργούν οι συνδέσεις με κλειδί API χωρίς ουρές ορίων ρυθμού, απενεργοποιήστε καθολικά το δίχτυ ασφαλείας μέσω `RATE_LIMIT_AUTO_ENABLE=false` (μεταβλητή περιβάλλοντος) ή `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Settings → Resilience / `PATCH /api/resilience`).

## Διακομιστής MCP

Το OmniRoute περιλαμβάνει έναν ενσωματωμένο διακομιστή Model Context Protocol με 3 τρόπους μεταφοράς (stdio, SSE, streamable-http) και εργαλεία περιορισμένης εμβέλειας. Τα παρακάτω τελικά σημεία του πίνακα ελέγχου διαβάζουν δεδομένα κατάστασης/ελέγχου και λειτουργούν ως διακομιστές μεσολάβησης για τους τρόπους μεταφοράς HTTP.

| Μέθοδος | Διαδρομή | Περιγραφή |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | Παλμός λειτουργίας, τρόπος μεταφοράς, κατάσταση σύνδεσης, τελευταία κλήση, κορυφαία εργαλεία, ποσοστό επιτυχίας 24 ωρών |
| GET | `/api/mcp/tools` | Λίστα εργαλείων MCP με `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints` |
| GET | `/api/mcp/sse` | Άνοιγμα ροής SSE για τη μεταφορά SSE (επιστρέφει `503` εάν το MCP είναι απενεργοποιημένο ή δεν αντιστοιχεί ο τρόπος μεταφοράς) |
| POST | `/api/mcp/sse` | Αποστολή πλαισίου JSON-RPC μέσω της μεταφοράς SSE |
| GET | `/api/mcp/stream` | Άνοιγμα της πλευράς SSE της μεταφοράς Streamable HTTP (μηνύματα που εκκινούν από τον διακομιστή) |
| POST | `/api/mcp/stream` | Αποστολή πλαισίου JSON-RPC μέσω της μεταφοράς Streamable HTTP |
| DELETE | `/api/mcp/stream` | Τερματισμός συνεδρίας Streamable HTTP |
| GET | `/api/mcp/audit` | Υποβολή ερωτήματος στο αρχείο καταγραφής ελέγχου — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | Συγκεντρωτικά στατιστικά ελέγχου (σύνολα, ποσοστό επιτυχίας, μέση διάρκεια, κορυφαία εργαλεία) |

**Έλεγχος ταυτότητας:** οι μεταφορές `sse`/`stream` ακολουθούν την ειδική επιφάνεια ελέγχου ταυτότητας του MCP (κλειδί API Bearer με εμβέλεια `mcp`)· οι διαδρομές `status`/`tools`/`audit*` είναι αναγνώσιμες από τον πίνακα ελέγχου (δεν απαιτείται πρόσθετος έλεγχος ταυτότητας πέρα από την πρόσβαση στον κεντρικό υπολογιστή του πίνακα ελέγχου).

> Και οι δύο μεταφορές HTTP ελέγχονται από τα `settings.mcpEnabled` και `settings.mcpTransport` — μια ασυμφωνία τρόπου μεταφοράς επιστρέφει `400`, ενώ μια απενεργοποιημένη κατάσταση MCP επιστρέφει `503`.

## Διακομιστής A2A

Το OmniRoute εκθέτει ένα endpoint A2A (Agent-to-Agent) JSON-RPC 2.0, καθώς και ένα REST wrapper για χρήση επιθεώρησης/πίνακα ελέγχου.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # προαιρετικό, εκτός αν έχει οριστεί το OMNIROUTE_API_KEY
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Υποστηριζόμενες μέθοδοι (όλες ελέγχονται από το `settings.a2aEnabled`):

| Μέθοδος          | Περιγραφή                                                              |
| ---------------- | ---------------------------------------------------------------------- |
| `message/send`   | Σύγχρονη εκτέλεση δεξιότητας· επιστρέφει `{task, artifacts, metadata}` |
| `message/stream` | Εκτέλεση ροής SSE για το ίδιο σύνολο δεξιοτήτων                        |
| `tasks/get`      | Ανάκτηση μιας εργασίας μέσω `taskId`                                   |
| `tasks/cancel`   | Ακύρωση μιας εργασίας μέσω `taskId`                                    |

Ενσωματωμένες δεξιότητες: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Κάρτα πράκτορα

```bash
GET /.well-known/agent.json
```

Επιστρέφει τη δημόσια κάρτα πράκτορα A2A (όνομα, περιγραφή, δυνατότητες, κατάλογος δεξιοτήτων, σχήμα ελέγχου ταυτότητας) — αποθηκεύεται δημόσια στην κρυφή μνήμη για 1 ώρα. Δεν απαιτείται έλεγχος ταυτότητας.

### Βοηθητικά endpoints REST

| Μέθοδος | Διαδρομή                     | Περιγραφή                                                                                                           |
| ------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| GET     | `/api/a2a/status`            | Κατάσταση ενεργοποίησης A2A + στατιστικά εργασιών + σύνοψη κάρτας πράκτορα από την κρυφή μνήμη                      |
| GET     | `/api/a2a/tasks`             | Λίστα εργασιών — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST    | `/api/a2a/tasks`             | (Δεν έχει υλοποιηθεί ως βοηθητικό endpoint REST — δημιουργήστε μέσω JSON-RPC `message/send`)                        |
| GET     | `/api/a2a/tasks/[id]`        | Ανάκτηση μίας εργασίας                                                                                              |
| POST    | `/api/a2a/tasks/[id]/cancel` | Ακύρωση μιας εργασίας                                                                                               |

**Έλεγχος ταυτότητας:** τα βοηθητικά endpoints REST εκτελούνται χωρίς έλεγχο ταυτότητας διαχείρισης (είναι αναγνώσιμα από τον πίνακα ελέγχου)· η διαδρομή JSON-RPC `/a2a` χρησιμοποιεί Bearer `OMNIROUTE_API_KEY`, εάν έχει ρυθμιστεί.

## Έλεγχος ταυτότητας

Ανατρέξτε στο [Έλεγχος ταυτότητας διαχείρισης](../guides/MANAGEMENT-AUTH.md) για τις τέσσερις
οικογένειες διαπιστευτηρίων (συνεδρία πίνακα ελέγχου, τοπικό διακριτικό CLI, Διακριτικό
Πρόσβασης `oma_live_…`, κλειδί API με εμβέλεια διαχείρισης) και τον τρόπο με τον οποίο διαφέρουν από τα κλειδιά συμπερασμού.

- Οι διαδρομές του πίνακα ελέγχου (`/dashboard/*`) χρησιμοποιούν το cookie `auth_token`
- Η σύνδεση χρησιμοποιεί το αποθηκευμένο hash κωδικού πρόσβασης, με εναλλακτική χρήση του `INITIAL_PASSWORD`
- Το `requireLogin` μπορεί να ενεργοποιηθεί ή να απενεργοποιηθεί μέσω του `/api/settings/require-login`
- Οι διαδρομές `/v1/*` απαιτούν προαιρετικά κλειδί API τύπου Bearer όταν `REQUIRE_API_KEY=true`
- Οι όροι «διακριτικό διαχείρισης» / «κλειδί API με εμβέλεια διαχείρισης» σε αυτήν την αναφορά σημαίνουν μία από τις οικογένειες του συγκεκριμένου οδηγού — όχι έναν απροσδιόριστο πρόσθετο τύπο μυστικού

> **Αλλαγή που διακόπτει τη συμβατότητα (v3.8.0)** — Τα `/api/v1/agents/tasks/*` και τα τελικά σημεία διαχείρισης χρόνου αναμονής απαιτούν πλέον **έλεγχο ταυτότητας διαχείρισης** (cookie πίνακα ελέγχου `auth_token` ή κλειδί API με εμβέλεια διαχείρισης). Οι πελάτες που προηγουμένως καλούσαν αυτές τις διαδρομές χωρίς έλεγχο ταυτότητας θα λαμβάνουν `401 Unauthorized`. Ανατρέξτε στο commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
