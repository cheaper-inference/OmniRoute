## Προσγείωση σε κλαδί απελευθέρωσης

Η omni-queue διέπει τις προσγειώσεις σε `release/vX.Y.Z`. Διαβάστε το `mode` ανώτατου επιπέδου στο `config/merge-queue/config.json` στον προεπιλεγμένο κλάδο πριν προσγειώσετε ένα PR. Δείτε [το Omni-Queue](OMNI_QUEUE.md).

- **`shadow`** εκτελεί την επικύρωση και αφήνει την προσγείωση σε μια μη αυτόματη συγχώνευση. Εφαρμόστε `omni-queue` στο εγκεκριμένο PR στην τελική του κεφαλή. Ελέγξτε την καταλληλότητα με `npm run queue -- why <PR>`. Περιμένετε την ετυμηγορία για εκείνο το κεφάλι στο `npm run queue -- history --base <branch>`. Προχωρήστε στο `would-land`. Σε `culprit-found` ή `would-dequeue`, κρατήστε πατημένο τη συγχώνευση και διορθώστε την αιτία.
- **Σκιώδεις εξαιρέσεις.** Ένα τρένο με πράσινο γεμάτο CI ενάντια στην τρέχουσα άκρη βάσης μπορεί να προχωρήσει χωρίς ξεχωριστή ετυμηγορία ουράς. Η ίδια εξαίρεση ισχύει όταν η κεφαλή PR περιέχει ήδη το τρέχον άκρο βάσης.
- **`live`** χρησιμοποιεί την ετικέτα `omni-queue` για να ενεργοποιήσει την προσγείωση. Μόνο η ουρά προσγειώνει το PR. Αφήστε τις εντολές συγχώνευσης και απευθείας πιέσεις στην ουρά.

Κάθε προσγείωση απαιτεί την άδεια του ιδιοκτήτη και τους ισχύοντες απαιτούμενους ελέγχους. Εφαρμόστε `omni-queue` μόνο αφού ο ιδιοκτήτης εξουσιοδοτήσει την προσγείωση. Η ουρά για την επαφή με προστατευμένες διαδρομές PRs απαιτεί επίσης την απόφαση `protected-approved` του κατόχου για αυτό το PR.

Το σύνολο κανόνων "Require green gates on the active release" απαιτεί πράσινο `Gate / CI` και `Gate / Quality` στο κεφάλι. Μην χρησιμοποιείτε ποτέ `--admin` για να παρακάμψετε μια κόκκινη πύλη. Ένα μπλοκ παγώματος απελευθέρωσης συγχωνεύεται στον παγωμένο κλάδο. Δείτε [τον σκληρό κανόνα 21](HARD_RULES_DETAIL.md). Ποτέ μην επισημαίνετε, συγχωνεύετε ή πιέζετε σε ένα αίτημα έλξης ότι μια άλλη περίοδος λειτουργίας λειτουργεί. Δείτε [τον σκληρό κανόνα 22](HARD_RULES_DETAIL.md).

## Το αίτημα έλξης τρένου

1. Ξεκινήστε μια διακλάδωση τρένου στο τρέχον άκρο της βάσης απελευθέρωσης. Ενσωματώστε τις ακριβείς εγκεκριμένες κεφαλές μελών χρησιμοποιώντας δεσμεύσεις συγχώνευσης. Διατηρήστε το ιστορικό δέσμευσής τους αποφεύγοντας το squash και το rebase.
2. Ανοίξτε ένα αίτημα έλξης για τον κλάδο τρένου. Επικυρώστε αυτό το PR με το δικό του πλήρες CI στην τρέχουσα άκρη βάσης. Ελέγξτε ξανά το άκρο της βάσης και τις εγκεκριμένες κεφαλές μελών πριν από την προσγείωση. Ανανεώστε το τρένο και CI του όταν αλλάξει ο επικυρωμένος υποψήφιος.
3. Προσγειώστε το τρένο PR με μια δέσμευση συγχώνευσης κάτω από την ισχύουσα λειτουργία ουράς. Στη ζωντανή λειτουργία, η μέθοδος προσγείωσης `merge-ff` της ουράς διατηρεί τις δεσμεύσεις συγχώνευσης. Οι αρχικές κεφαλές μελών γίνονται προσβάσιμες από τον κλάδο απελευθέρωσης. GitHub επισημαίνει το μέλος PRs ως συγχωνευμένο και οι δεσμεύσεις διατηρούν τους συντάκτες τους.

Ένα δημόσιο παράδειγμα είναι [PR #21071](https://github.com/cheaper-inference/OmniRoute/pull/21071). Συνδύασε 18 μέλη PRs και προσγειώθηκε με μια δέσμευση συγχώνευσης στις 24-11-2026.

Μια επιστροφή συγχρονισμού από `main` στον επόμενο κλάδο έκδοσης προσγειώνεται επίσης μέσω μιας δέσμευσης συγχώνευσης. Απαιτείται διατήρηση της καταγωγής `main` για μετέπειτα συγχρονισμό. Δείτε [Απομόνωση Δέντρου Εργασίας](WORKTREE_ISOLATION.md#sync-back-landings-are-merge-commits-never-squash).

## Το τοπικό εργαλείο επικύρωσης συγχώνευσης

```bash
scripts/release/merge-train.sh [--plan] [--fast] <base-branch> <PR#> [<PR#>...]
```

Ο επικυρωτής φέρνει τη βάση και τις κεφαλές PR και τα συνδυάζει σε ένα δέντρο εργασίας μιας χρήσης. Εκτελεί τη σουίτα ισοτιμίας μία φορά στο δέντρο που προκύπτει. Μια αποτυχημένη διένεξη ανάκτησης ή συγχώνευσης κεφαλής εξάγει αυτό το PR και το σενάριο συνεχίζει με το υπόλοιπο PRs.

- **`--plan`** εκτυπώνει τα βήματα της επιλεγμένης λειτουργίας και εξέρχεται χωρίς να δημιουργήσει ένα δέντρο εργασίας ή να έρθει σε επαφή με το τηλεχειριστήριο. Συνδυάστε το με `--fast` για να επιθεωρήσετε το γρήγορο σχέδιο.
- **`--fast`** εκτελεί τις κοινές στατικές πύλες, τα επιλεγμένα άλλα αρχεία `node:test` κάτω από `tests/unit/` και `npm run test:vitest`. Εκτελέστε μια πλήρη τοπική επικύρωση τουλάχιστον μία φορά την ημέρα στο συσσωρευμένο άκρο όταν χρησιμοποιείτε τη γρήγορη λειτουργία.
- **Πλήρης λειτουργία** προσθέτει τις πλήρως στατικές πύλες και εκτελεί `npm run test:unit` και `npm run test:vitest`.

Μια αποτυχημένη στατική πύλη επαναλειτουργεί στην ανέγγιχτη βάση εάν είναι διαθέσιμος ο αισθητήρας βάσης. Το σενάριο αναφέρει κληρονομημένες αποτυχίες και συνεχίζει όταν κάθε γραμμή αναγνωρισμένης παραβίασης εμφανίζεται επίσης στη βάση και ο συνολικός αριθμός δεν έχει αυξηθεί.

| Εξοδος | Εννοια                                                                                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`    | Εκτύπωσε το σχέδιο ή συμπλήρωσε τη σουίτα. Η σύνοψη της σουίτας παραθέτει τυχόν κληρονομικές στατικές αστοχίες και εξαγωγή PRs.                                                 |
| `1`    | Μη έγκυρα επιχειρήματα, καμία ολοκλήρωση αγοράς Git, αποτυχία πριν από την πτήση ή καμία επιβίβαση PR.                                                                          |
| `2`    | Ένας έλεγχος σουίτας απέτυχε και δεν πληροί τις προϋποθέσεις ως κληρονομούμενος. Ο χειριστής μπορεί να διχοτομήσει την παρτίδα, να βγάλει το προσβλητικό PR και να τρέξει ξανά. |

Ένα τοπικό πάσο παρέχει διαγνωστικά στοιχεία μόνο για τον φάκελο του ιδιοκτήτη. Κάθε προσγείωση εξακολουθεί να απαιτεί εξουσιοδότηση κατόχου, τους δικούς της απαιτούμενους ελέγχους και την ετυμηγορία σκιαστικής ουράς, όταν ισχύει.

## Διαβαθμίσεις

- **Per PR.** CI και Ποιότητα επιλέγουν ελέγχους βάσει των αλλαγμένων διαδρομών. Το Code PRs εκτελεί γρήγορες πύλες ποιότητας και κρουστικές δοκιμές, με ξεχωριστές εργασίες μονάδας και Vitest στο CI.
- **Ανά υποψήφιο ουρά.** CI και το Quality εκτελούν το πλήρες προφίλ του υποψηφίου που έχει συντεθεί στην ουρά αναφοράς του.
- **Ανά άκρη απελευθέρωσης.** Το Release-Green εκτελεί γρήγορες σκληρές πύλες σε ωθήσεις που ταιριάζουν με τα φίλτρα διαδρομής του. Τρεις προγραμματισμένες διαδρομές την ημέρα χρησιμοποιούν την πλήρη σάρωση για τον κλάδο απελευθέρωσης.
- **Ανά κυκλοφορία.** Ο πλήρης πίνακας CI περιλαμβάνει θραύσματα E2E, επικύρωση πακέτου, καπνό μπότας tarball και ελέγχους κάλυψης. Δείτε τη [Λίστα ελέγχου έκδοσης](RELEASE_CHECKLIST.md).

## Προαπαιτούμενα φρέσκο checkout για `merge-train.sh`

Η προκαταρκτική πτήση εκτελείται πριν από τη δημιουργία δέντρων εργασίας. Εγκαταστήστε εξαρτήσεις με `npm ci`. Επιβεβαιώστε ότι `node_modules/.bin/tsc` είναι εκτελέσιμο και ότι `node_modules/node_modules` απουσιάζει. Ελέγξτε ότι `node_modules/.bin/bun --version` έχει επιτυχία.

Εάν παραλείφθηκε η postinstall του Bun, εκτελέστε `(cd node_modules/bun && node install.js)`. Οι έλεγχοι συνέπειας παρόχου και γνωστών συμβόλων χρησιμοποιούν Bun. Ο επικυρωτής εκτελεί `npm run check:cycles:ratchet` ως πύλη αποκλεισμού. Η αυτόνομη εντολή `npm run check:cycles` είναι συμβουλευτική.
