## Προφίλ απογραφής και εκτέλεσης πύλης

### Είσοδος υποψηφίου

Οι ροές εργασίας CI και Quality Gates εκπέμπουν η καθεμία μια σταθερή ετυμηγορία: `Gate / CI` και `Gate / Quality`. Η τροποποιημένη πολιτική εισδοχής τους απαριθμεί κάθε εργασία ανάντη ως απαιτούμενη ή συμβουλευτική. Μια απαιτούμενη εργασία που ισχύει πρέπει να είναι επιτυχής: λείπει, ακυρώθηκε, παραλείφθηκε, εκκρεμεί και άγνωστα αποτελέσματα δεν μπορούν να δημιουργήσουν PASS. Μια έγκυρη ταξινόμηση μόνο για έγγραφα ή μόνο για κατάλογο μπορεί να καταστήσει μη εφαρμόσιμη μια λωρίδα κωδικών. ένα σχέδιο PR δεν είναι αποδεκτός υποψήφιος. Μια ετικέτα `hotfix` δεν παραιτείται από στοιχεία.

Και οι δύο ροές εργασίας καλύπτουν PRs σε κλάδους main/release, ωθήσεις σε `main`, μη αυτόματη αποστολή και συγχώνευση συμβάντων. Push, αποστολή και συγχώνευση-ομαδοποίηση εκτελέστε την πλήρη επιλογή. Οι ωθήσεις στο `release/**` δεν τις ξεκινούν (2026-10-18): κάθε αλλαγή εκτελούσε ήδη τον πίνακα στο PR του και ο συγχωνευμένος συνδυασμός είναι δουλειά του Release-Green (`docs/ops/RUNNER_BOX.md` → Hosted lane). Τα forks και οι ομάδες συγχώνευσης χρησιμοποιούν φιλοξενούμενους δρομείς για εργασίες που διαφορετικά επιλέγουν αυτο-φιλοξενούμενους δρομείς. πρέπει να επαληθευτεί επαρκής χωρητικότητα φιλοξενίας πριν από την κυκλοφορία.

Ένα συνηθισμένο PR εκτελεί τη γρήγορη επιλογή. Οι λωρίδες `full-code` και `full-code-e2e` της πολιτικής εισδοχής (E2E, ενσωμάτωση, τεχνούργημα πακέτου, Electron smoke, Bun SQLite, πελάτες οικοσυστήματος και πρωτοκόλλου) εκτελούνται μόνο σε πρόχειρο ουράς Mergify ή σε πλήρη εκτέλεση: `gh workflow run ci.yml --ref <branch>`.

Κάθε απόδειξη JSON προσδιορίζει το SHA που ολοκληρώθηκε, τη ροή εργασίας και την προσπάθεια. Το CLI απορρίπτει μια αναντιστοιχία checkout/event SHA. Οι δοκιμές ροής εργασιών συνδέουν τη συνδρομή πολιτικής στη λίστα `needs` της εργασίας ετυμηγορίας, έτσι ώστε μια νέα ή καταργημένη λωρίδα να μην μπορεί να εξαφανιστεί σιωπηλά. Οι αποδείξεις καλύπτουν τη δική τους ροή εργασίας, όχι τη δημοσίευση, την ανάπτυξη ή τα εσωτερικά στοιχεία ενός υπάρχοντος συμβουλευτικού σαρωτή. Η ενεργοποίηση και των δύο ονομάτων ελέγχου στους κανόνες του κλάδου είναι μια ξεχωριστή διοικητική αλλαγή. Η προσθήκη αυτών των εργασιών δεν προστατεύει από μόνη της έναν κλάδο.

### Ουρά συγχώνευσης

> **2026-11-19: η ουρά συγχώνευσης Mergify αποσύρεται** (απόφαση ιδιοκτήτη). `.mergify.yml` δεν ορίζει πλέον μια ουρά και απορρίπτει τις εντολές Mergify που συγχωνεύουν ή ξαναγράφουν ένα αίτημα έλξης. Η κυκλοφορία PRs συγχωνεύεται με το χέρι κάτω από το σύνολο κανόνων αποθετηρίου "Απαιτούνται πράσινες πύλες στην ενεργή κυκλοφορία" (`Gate / CI` + `Gate / Quality`) μέχρι να εκτελεστεί η omni-queue σε ζωντανή λειτουργία και μετά από αυτήν μέσω της omni-queue ( [OMNI_QUEUE.md](../ops/OMNI_QUEUE.md) ). Ο χειρισμός της ροής εργασίας των πρόχειρων του Mergify που περιγράφεται παρακάτω εξακολουθεί να είναι σε `ci.yml` και `quality.yml`, αλλά δεν ανοίγει πλέον κανένα πρόχειρο Mergify.

Η ετικέτα `queue` στέλνει ένα PR στην ουρά Mergify (`.mergify.yml`). Το Mergify ανοίγει ένα πρόχειρο PR σε έναν κλάδο `mergify/merge-queue/`, CI εκτελεί την πλήρη επιλογή εκεί και το αρχικό PR συγχωνεύεται όταν περάσουν `Gate / CI`, `Gate / Quality` και `Merge integrity (changelog + generated skills)`.

Το Mergify γράφει τη σύνοψη της ουράς στην περιγραφή του προχείρου και άλλες εφαρμογές μπορούν επίσης να το επεξεργαστούν. Ένα συμβάν `pull_request` `edited` σε ένα τέτοιο προσχέδιο παίρνει τη δική του ομάδα συγχρονισμού (`-queue-edit-<run_id>`), επομένως δεν μπορεί να ακυρώσει την πραγματική εκτέλεση του σχεδίου και παρακάμπτει την πύλη και τη μήτρα. Μόνο `Merge integrity` τρέχει ακόμα. Η εργασία παράλειψης πύλης φέρει διαφορετικό όνομα ελέγχου, επειδή το Mergify διαβάζει ένα παραλειφθέν `Gate / CI` ως αποτυχημένο έλεγχο και αφαιρεί το PR.

Μετά από dequeue, μια ώθηση δεν επαναφέρει πάντα το PR. Σχολιάστε `@mergifyio queue`.

### Διατηρούνται αποδεικτικά στοιχεία στον μειωτήρα αποδοχής

`scripts/quality/validate-release-acceptance.mjs` μειώνει ένα παρεχόμενο σχέδιο και τις εκδηλώσεις του. δεν αποδεικνύει ότι το σχέδιο καλύπτει ολόκληρο τον αγωγό απελευθέρωσης. Οι αναφορές του ορίζουν ρητά `releaseAcceptance: false`, ακόμη και όταν αυτό το σχέδιο είναι `VERIFIED`. Η ροή εργασίας `release-acceptance.yml` εξακολουθεί να χρησιμοποιεί σκιώδεις συσκευές, όχι πραγματικές αποδείξεις κατασκευής, πακέτου, εκκίνησης ή προώθησης.

Το CLI απαιτεί από `--evidence-root` να επαληθεύει τα διατηρούμενα στοιχεία. Τα αρχεία επιλύονται ως `<evidence-root>/<artifact_id>/<member>` και κατακερματίζονται ως SHA-256. Μια εγγραφή PASS χωρίς αποδεικτικά στοιχεία, ένα αρχείο που λείπει ή έχει αλλάξει, μια μη ασφαλής διαδρομή ή ένας συμβολικός σύνδεσμος εμποδίζει την επαλήθευση. Τα αρχεία που λείπουν δεν ισοδυναμούν με άδεια επιτυχημένα αρχεία καταγραφής. Οι υπάρχοντες έλεγχοι SHA/run/attempt παραμένουν ανεξάρτητοι: τα αντίστοιχα byte δεν μπορούν να διασώσουν μια μπαγιάτικη απόδειξη. Η ακεραιότητα του αρχείου δεν αποτελεί απόδειξη αυθεντικότητας εκτέλεσης ή προώθησης τεχνουργημάτων.

### Απόθεμα στατικής σάρωσης

Το εκδομένο απόθεμα npm-alias και η συνδρομή στατικής σάρωσης ζωντανά στο `config/quality/gate-manifest.json`. Εκτελέστε `npm run check:gate-manifest` για να επικυρώσετε ονόματα σεναρίων και ακριβείς εντολές έναντι `package.json`. οι προσθήκες, οι αφαιρέσεις και η μετατόπιση εντολών αποτυγχάνουν τόσο στο τοπικό άγκιστρο όσο και στις εργασίες αλλαγής-ταξινόμησης στο CI. Ένα ψευδώνυμο δεν είναι εργασία ροής εργασίας, παράδειγμα μήτρας ή δοκιμαστική περίπτωση: αυτές οι μετρήσεις δεν πρέπει να παρουσιάζονται ως εναλλάξιμες.

Χρησιμοποιήστε `npm run quality:scan -- --list` ή `npm run quality:scan:fast -- --list` για να επιθεωρήσετε τα επιλεγμένα ψευδώνυμα χωρίς να τα εκτελέσετε. Ο δρομέας καλεί το σημείο εισόδου npm, επομένως ο χρόνος εκτέλεσης του (συμπεριλαμβανομένου Bun όπου έχει ρυθμιστεί) διατηρείται. Το μανιφέστο καταγράφει ψευδώνυμα εκτός αυτών των προφίλ όπως καλούνται χωριστά και οι εντολές συντήρησης απαγορεύονται σε προφίλ σάρωσης μόνο για ανάγνωση.

Αυτά τα προφίλ καλύπτουν μόνο τη στατική σάρωση. Δεν πιστοποιούν τις δοκιμές προϊόντων, την κάλυψη, τη συσκευασία, τους εξωτερικούς ελέγχους ή την πλήρη αποδοχή του υποψηφίου. Η εισαγωγή ροής εργασίας χρησιμοποιεί τα συνδεδεμένα `config/quality/admission-policy.json` και `scripts/quality/admission-verdict.mjs`. Τα προφίλ παρατηρητών απελευθέρωσης παραμένουν ξεχωριστά. επιθεωρούν ανεξάρτητα τις ισχύουσες επιταγές και αποδείξεις τους. Οι πλήρεις στατικές εντολές του παρατηρητή δηλώνονται σε `config/quality/release-green-static-profile.json`, συμπεριλαμβανομένων `audit:deps`, επιλογής δοκιμής μετάλλαξης και ελέγχους μετάφρασης. Ο φορτωτής επικυρώνει εντολές npm έναντι δηλώσεων package.json και μοντελοποιημένων CI/Quality. απορρίπτει το drift αντί να εκτελεί κουπόνια φλοιού ως ορίσματα. Η απαιτούμενη έξοδος SKIP/INCOMPLETE σαρωτή δεν μπορεί να καθορίσει PASS. Το προφίλ καταγράφει τις εξωτερικές του εξαιρέσεις και δεν αντικαθιστά την φιλοξενούμενη κάλυψη, τους πίνακες δοκιμών, το πακέτο ή τα στοιχεία ανάπτυξης. Το απόθεμα πεζογραφίας παρακάτω αποτελεί αναφορά, όχι απόδειξη ότι όντως έτρεξε μια πύλη.

Τα σενάρια ζουν κάτω από `scripts/check/` (πύλες πολιτικής) και `scripts/quality/` (καστάνια). Η CI πηγή της αλήθειας είναι `.github/workflows/ci.yml`.

### Απελευθερώστε PR fast-path (`quality.yml`)

`.github/workflows/quality.yml` συμπληρώνει CI στο main/release PRs, ωθεί σε `main`, αποστέλλει και συγχωνεύει ομάδες. PRs χρησιμοποιεί γρήγορους ελέγχους με φιλτράρισμα διαδρομής. Η μόνιμα απενεργοποιημένη διπλότυπη έκδοση καταργήθηκε. οι πραγματικοί έλεγχοι build/package/boot παραμένουν σε CI. Η σουίτα μονάδας και το vitest τρέχουν μόνο σε CI (`Unit Tests (N/8)` και `Vitest`).

| Δουλειά                                          | Εκταση                                                                                                                                                          | Μπλοκάρισμα                            |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `Docs Gates (fast-path)`                         | Docs/code PRs; API docs refs και docs-all                                                                                                                       | Ναί                                    |
| `Fast Quality Gates`                             | Κωδικός PRs; στατικοί έλεγχοι, έλεγχος τύπων, έλεγχος πληκτρολόγησης πίνακα εργαλείων, δοκιμές επηρεασμένης μονάδας, δοκιμές ξεχασμένων αδελφών (συμβουλευτική) |
| `No new ESLint warnings`                         | Κωδικός PRs; προστατευτικό χνούδι με επίγνωση καταστολής                                                                                                        | Ναι, συμπεριλαμβανομένων των πιρουνιών |
| `Merge integrity (changelog + generated skills)` | Μη πρόχειρο PRs; Changelog και συγχρονισμός δεξιοτήτων που δημιουργείται                                                                                        | Ναι, συμπεριλαμβανομένων των πιρουνιών |

#### Αναφορά δοκιμών ξεχασμένων αδελφών

`npm run check:forgotten-sibling-tests` εκτελείται ως συμβουλευτικό βήμα του `Fast Quality Gates` και επαναχρησιμοποιεί τον επιλύτη εισαγωγής πίσω από τον χάρτη δοκιμής-επίδρασης. Για κάθε αλλαγμένη μονάδα παραγωγής, αναφέρει ντετερμινιστικές αλυσίδες `changed module/symbol -> static consumer -> candidate sibling test` όταν η υποψήφια δοκιμή απουσιάζει από τη διαφορά αιτήματος έλξης. Η σύνοψη Markdown και το αποτέλεσμα JSON διατηρούνται ως το τεχνούργημα ροής εργασίας `forgotten-sibling-tests` για βαθμονόμηση πριν από οποιαδήποτε κυκλοφορία αποκλεισμού.

Οι επανεξαγωγές βαρελιού και οι δυναμικές εισαγωγές αποτελούν μόνο διαγνωστικά ανάλυσης. δεν δημιουργούν ποτέ ένα αποκλειστικό εύρημα. Εξαιρέσεις που εξετάστηκαν ζωντανά στο `config/quality/forgotten-sibling-allowlist.json`. Κάθε καταχώριση πρέπει να ονομάζει το τεστ καταναλωτή και υποψηφίου, να δίνει μια συγκεκριμένη αιτιολογία και να συνδέει ένα ζήτημα GitHub ή αίτημα έλξης. Οι καταχωρήσεις με κακή μορφή αποτυγχάνουν να κλείσουν. Οι εξαιρέσεις δεν μπορούν να καταστείλουν μια διαγραμμένη δοκιμασία υποψηφίου ή μια διαφορά που προσθέτει `.skip`/`.todo`. Η αποδυνάμωση του ισχυρισμού και άλλες καλύψεις παραμένουν στην ιδιοκτησία της πύλης `check:test-masking` που μπλοκάρει ανεξάρτητα.

### Δουλειά: `lint`

Εκτελείται σε κάθε PR σε `main`. Τα μπλοκ συγχωνεύονται σε περίπτωση αποτυχίας.

| Σενάριο (`npm run ...`)           | Επικυρώνει                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Μπλοκάρισμα                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| `check:node-runtime`              | Η έκδοση Node.js βρίσκεται εντός του υποστηριζόμενου εύρους                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Ναί                                            |
| `check:cycles`                    | Κυκλικές εισαγωγές σε όλο το `src/` + `open-sse/` (βασισμένο σε AST, επιλύθηκε το tsconfig `paths` ). #### Δύο προγράμματα ελέγχου τύπου απαντούν διαφορετικά

`typecheck:core` και `check:build-typecheck` μεταγλωττίζουν διαφορετικά προγράμματα κάτω από διαφορετικές επιλογές και το ίδιο αρχείο μπορεί να είναι καθαρό στο ένα και γεμάτο λάθη στο άλλο.

`tsconfig.build.json` θέτει `"strict": false`, άρα `noImplicitAny` είναι απενεργοποιημένο. Η βασική διαμόρφωση συντάσσει μια επιμελημένη λίστα επιτρεπόμενων αρχείων 27 με αυστηρότερες επιλογές και ακολουθεί το γράφημα εισαγωγής κάθε καταχώρισης, έτσι ώστε τα αρχεία που δεν εμφανίζονται ποτέ στο πρόγραμμα δημιουργίας εξακολουθούν να ελέγχονται εκεί.

Η συνέπεια είναι σημαντική όταν κρίνουμε εάν ένα αρχείο πληκτρολογείται:** μηδενικά διαγνωστικά κάτω από `check:build-typecheck` δεν σημαίνει μηδέν** . Η απογύμνωση `@ts-nocheck` από 26 αρχεία έδειξε ότι 23 από αυτά ήταν καθαρά στο πρόγραμμα δημιουργίας. Δεκαέξι από αυτά εμφανίστηκαν περίπου 120 σιωπηρά - τυχόν σφάλματα στο αυστηρό. Ελέγξτε και τα δύο πριν καλέσετε ένα αρχείο καθαρό.

#### Οι καθρέφτες μετάφρασης είναι παράγωγα αρχεία (λειτουργία PR έναντι λειτουργίας έκδοσης)

Ένα χαρακτηριστικό PR επεξεργάζεται μόνο αγγλικές πηγές. Οι κατοπτρισμοί `docs/i18n/<locale>/**` (συμπεριλαμβανομένων των 66 αντιγράφων `llm.txt` και των μεταφρασμένων αρχείων `CHANGELOG.md` ) και `.i18n-state.json` ξαναγράφονται σε ένα βήμα από το κύμα μετάφρασης (διακλαδώσεις `docs/i18n-*` / `chore/i18n-*`, το προγραμματισμένο `i18n-mirror-refresh.yml`) και από την έκδοση (`npm run release:sync-changelog-i18n`). Επομένως, οι πύλες κατοπτρισμού εκτελούνται σε δύο λειτουργίες, οι οποίες επιλύονται από `scripts/check/lib/gateMode.mjs` (`--mode=pr|release`, μετά `OMNIROUTE_GATE_MODE`, μετά το συμβάν Actions· μια τοπική εκτέλεση είναι `release`):

- Η λειτουργία απελευθέρωσης `check:docs-sync` — εκτελεί κάθε έλεγχο. Η λειτουργία PR διατηρεί την έκδοση package.json/OpenAPI, τις επικεφαλίδες ρίζας CHANGELOG και το προστατευτικό αντικατάστασης εγγράφων και εκτυπώνει `SKIP reason=pr-mode` για τα αντίγραφα κατοπτρισμού `llm.txt` και τις μεταφρασμένες ενότητες CHANGELOG — εκτός και αν το PR γράφει mirrors: ένας κλάδος κεφαλής που δηλώνεται ως συγγραφέας της οικογένειας `docs/i18n/**` στο `config/quality/derived-paths/*.json` εκτελεί και τον έλεγχο της αλλαγής diff ή την ίδια αλλαγή, και επιλύει το diff, και επιλύει το diff. `CHANGELOG.md` `docs/i18n/<locale>/llm.txt` αυστηρά τον έλεγχο. Η βάση διαφορών δεν επιλύεται σε ένα ταμείο depth-1 (η εργασία `docs-sync-strict` ), επομένως η λειτουργία PR εκτελεί επίσης έναν έλεγχο που δεν χρειάζεται βάση: κάθε καθρέφτης `llm.txt` πρέπει να υπάρχει, να διατηρεί το διαχωριστικό του `---` και να φέρει είτε το ριζικό σώμα είτε το σώμα που μοιράζονται οι περισσότεροι καθρέφτες. Μια βάση που μετακινήθηκε αφήνει όλους τους καθρέφτες εξίσου μπαγιάτικους και περνάει. μια χειροκίνητη επεξεργασία σε έναν καθρέφτη αποτυγχάνει. Τα μεταφρασμένα αρχεία `CHANGELOG.md` δεν έχουν τέτοιο έλεγχο σε ένα ταμείο depth-1 PR.
- Το άγκιστρο πριν από τη δέσμευση τρέχει `check-docs-sync.mjs --mode=pr`: μια δέσμευση κρίνεται με βάση αυτό που κάνει. Χωρίς τη σημαία μια τοπική εκτέλεση είναι η λειτουργία απελευθέρωσης και ένα συγχωνευμένο PR που επεξεργάζεται τη ρίζα `llm.txt` θα μπλοκάρει κάθε μεταγενέστερη δέσμευση σε αυτήν τη βάση μέχρι να εκτελεστεί το κύμα. Ο ίδιος κανόνας ισχύει για κάθε πύλη με επίγνωση του τρόπου λειτουργίας που εκτελείται ένας γάντζος Husky: το άγκιστρο περνάει `--mode=pr`, και η αυστηρή ετυμηγορία παραμένει στις εκτελέσεις λειτουργίας απελευθέρωσης (η απελευθέρωση PR, ωθεί στο `main`, μια απλή τοπική εκτέλεση).
- Οι δοκιμές ενοτήτων κατοπτρικού περιεχομένου (`tests/_helpers/mirrorFreshness.ts`: `cycle-docs-mirror-contract`, `resilience-pre-dispatch-docs-mirrors`, `cli-env-quality-docs-mirrors`, `docs/*-locales`) Η λειτουργία απελευθέρωσης — επιβεβαιώνει κάθε τοπική ρύθμιση. Η λειτουργία PR επιβεβαιώνει μόνο τους καθρέφτες που είναι ενημερωμένοι με την αγγλική πηγή σύμφωνα με `.i18n-state.json` (κατακερματισμός ολόκληρου του αρχείου ή κατακερματισμός καταγεγραμμένου τμήματος της ενότητας οι δοκιμαστικές καρφίτσες) και παρακάμπτει τους παλιούς με έναν λόγο. Οι έλεγχοι προέλευσης `target_hash` εκτελούνται για κάθε τοπική ρύθμιση και στις δύο λειτουργίες. Η φρεσκάδα είναι ανά ενότητα `## `, η μονάδα `run-translation.mjs` κατακερματίζεται. μια μεγάλη ενότητα (το απόθεμα πύλης αυτού του αρχείου είναι περίπου το μισό του) σημαίνει ότι οποιαδήποτε επεξεργασία σε αυτό αφήνει αυτούς τους καθρέφτες μπαγιάτικους και οι ισχυρισμοί λειτουργίας PR παραλείπονται μέχρι το επόμενο κύμα. Μια άγκυρα που δεν περιέχει πλέον η αγγλική πηγή επιστρέφει στη σύγκριση ολόκληρου του αρχείου.
- Συμβουλευτική `i18n translation drift` — για PRs, αυστηρή για ώθηση, νυχτερινά και το κόψιμο απελευθέρωσης, επομένως ένας μπαγιάτικος καθρέφτης δεν μπορεί να αποσταλεί σε κυκλοφορία.

`scripts/i18n/sync-llm-mirrors.mjs` (εξάγεται επίσης ως `syncLlmMirrors()`, με `--dry-run`) ξαναγράφει τους καθρέφτες `llm.txt`. η ανανέωση απελευθέρωσης, το κύμα μετάφρασης και το προγραμματισμένο `i18n-mirror-refresh.yml` το εκτελούν (η ανανέωση ανιχνεύει μπαγιάτικους καθρέφτες `llm.txt` με στεγνή εκτέλεση, καθώς η αναφορά drift δεν τους αναφέρει και τους συγχρονίζει πριν από `check:docs-all`).

Τα δώδεκα README SVGs κάτω από `docs/diagrams/` δημιουργούνται (`scripts/docs/gen-readme-<name>.mjs`, `npm run docs:readme-diagrams` αναγεννά όλα αυτά). Κάθε ένα έχει μια δοκιμή μονάδας σύγκρισης byte (`tests/unit/docs/readme-*-svg.test.ts`, εργασία `test-unit`) που αποτυγχάνει όταν το δεσμευμένο αρχείο είναι μπαγιάτικο στη λειτουργία έκδοσης. σε ένα PR, `check:generated-artifacts` κρίνει ένα SVG τις επεξεργασίες PR και η μετατόπιση της βάσης αφήνεται στην ανανέωση έκδοσης (δείτε [Δημιουργημένα αρχεία και παράγωγες γραμμές βάσης](#generated-files-and-derived-baselines-written-at-release) ) — και `check:docs-counts` διαβάζει κανονικούς αριθμούς από τους κόμβους `<text>` — γι' αυτό το βήμα περιγράμματος διατηρεί κάθε περιγραμμένη συμβολοσειρά στο αρχείο ως `<text>`. Ο έλεγχος κανονικών αριθμών SVG διαβάζει τα αρχεία που παρατίθενται στο `SVG_DIAGRAM_FILES` (`scripts/check/check-docs-counts-sync.mjs`): `docs/diagrams/readme-hero.svg`, `free-tier-budget.svg`, `promise-pillars.svg`, `comparison-table.svg`, `cli-terminal.svg`, `tier-cascade.svg`, συν `public/images/tier-flow-dark.svg` και `tier-flow-light.svg`; οι αξιώσεις δωρεάν για πάντα, καταχώριση καταλόγου, επαναλαμβανόμενη ομάδα και συντελεστές βαθμολογίας διαβάζουν επίσης `promise-pillars.svg`, `free-tier-budget.svg` και `strategies-grid.svg`. Οι μετρήσεις που αντλούν αυτές οι γεννήτριες (σύνολο παρόχου, εργαλεία MCP, στρατηγικές δρομολόγησης, δωρεάν για πάντα πάροχοι,…) προέρχονται από το στιγμιότυπο δεδομένων `docs/reference/derived-facts.json` έως `scripts/docs/readmeFacts.mjs`, όχι από κυριολεκτικά, επομένως η αναγέννηση ενός διαγράμματος σε οποιοδήποτε κλάδο αναπαράγει το δεσμευμένο αρχείο. `free-tier-budget.svg` αντλεί τις σειρές του από το ίδιο στιγμιότυπο (`code.freeTierBudget`, η περίληψη του καταλόγου καταγράφει η ανίχνευση γεγονότων), έτσι μια αλλαγή σε `FREE_MODEL_BUDGETS` φτάνει στην κάρτα στην επόμενη ανανέωση αντί να γίνει κόκκινη CI.

### Παράγωγες τιμές: οι λειτουργίες πύλης `pr` και `release`

Ένα χαρακτηριστικό PR δεν γράφει ποτέ μια τιμή που εξαρτάται από την κατάσταση της βάσης του: πάροχος, μετεγκατάσταση, μετρήσεις εργαλείου MCP και στρατηγικής, αριθμούς README SVG, στιγμιότυπο γεγονότων. Ένα βήμα επαναυπολογίζει όλα αυτά, `npm run release:refresh-derived`, που εκτελούνται από την έκδοση και από το νυχτερινό παράγωγο-refresh PR. Ετσι** μεταξύ των εκδόσεων η βάση βρίσκεται πίσω από τον ζωντανό κώδικα βάσει σχεδίου** , και μια πύλη ή μια δοκιμή που συνέκρινε το δέντρο με τον ζωντανό κώδικα θα ήταν κόκκινη σε κάθε PR αφού ένας αδερφός πρόσθεσε έναν πάροχο. Επομένως, οι πύλες που κρίνουν τις προκύπτουσες τιμές τρέχουν σε μία από τις δύο λειτουργίες, οι οποίες επιλύονται με `scripts/check/lib/gateMode.mjs` (πρώτος αγώνας νίκες):

1. `--mode=pr|release` στη γραμμή εντολών.
2. η μεταβλητή περιβάλλοντος `OMNIROUTE_GATE_MODE` (`pr` ή `release`).
3. αυτόματη, από το συμβάν GitHub Actions: ένα `pull_request` του οποίου η κεφαλή δεν είναι `release/v*`, ένα `merge_group` ή μια ώθηση στο `omni-queue/**` → `pr`; οτιδήποτε άλλο (ώθηση, χρονοδιάγραμμα, αποστολή, έκδοση PR `release/v* → main`, οποιαδήποτε τοπική εκτέλεση) → `release`.

Τι `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) αποτυγχάνει σε κάθε λειτουργία:

| Τρόπος    | Αποτυγχάνει                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Χρειάζεται ζωντανά γεγονότα |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| `release` | Κάθε έλεγχος, αυστηρή ισότητα έναντι των γεγονότων που συλλέγονται από το δέντρο (η συμπεριφορά που είχε πάντα η πύλη): μια μπαγιάτικη καταμέτρηση, έκδοση, όροφος κάλυψης ή αριθμός SVG είναι μια μετατόπιση STRICT                                                                                                                                                                                                                                                                                            | Ναί                         |
| `pr`      | Μόνο αυτό που έκανε η αλλαγή διέφερε σε σχέση με τη βάση PR με τους ίδιους εξαγωγείς αξιώσεων: (1) μια διαχειριζόμενη τιμή που δεν υπήρχε στη βάση για αυτόν τον έλεγχο και το αρχείο ("PR επεξεργάστηκε έναν διαχειριζόμενο αριθμό — επαναφέρει τη γραμμή στο βασικό κείμενο"). (2) μια απαιτούμενη αξίωση η βάση έφερε και το κεφάλι χάθηκε. Τα αμετάβλητα περιεχομένου που δεν χρειάζονται στοιχεία εκτελούνται όπως στη λειτουργία έκδοσης. Οι έλεγχοι μόνο για απελευθέρωση παρατίθενται και παραλείπονται | Οχι                         |

Τα αρχεία οδηγιών του πράκτορα φέρουν** Όχι** παράγωγο μέτρημα καθόλου: `AGENTS.md`, `llm.txt` (και τα αντίγραφά του `docs/i18n/*/llm.txt` ), τα bs `AGENTS.md` fork, `open-sse/services/AGENTS.md`, `src/shared/constants/agentSkills.ts`, `skills/README.md` και κάθε `skills/*/SKILL.md` δείχνουν στην πηγή (για παράδειγμα `ROUTING_STRATEGY_VALUES` στο `src/shared/constants/routingStrategies.ts`) και αντ 'αυτού στο `npm run facts`. Το αμετάβλητο "Χωρίς παράγωγες μετρήσεις (αρχείο οδηγιών…)" αποτυγχάνει να μετρήσει εκεί (πάροχοι, μετεγκαταστάσεις, εργαλεία και πεδία MCP, στρατηγικές δρομολόγησης, παράγοντες βαθμολόγησης, πακέτα λειτουργιών) και στις δύο λειτουργίες, επομένως η ανανέωση έκδοσης δεν χρειάζεται ποτέ να ξαναγράψει ένα αρχείο οδηγιών.

Στη λειτουργία `pr` οι κλάδοι εγγραφής μπορούν να επεξεργαστούν τις διαχειριζόμενες τιμές: `chore/derived-*` (η νυχτερινή ανανέωση PR), `release/v*` και τα κύματα μετάφρασης `docs/i18n-*` και `chore/i18n-*` (`scripts/check/lib/derivedClaimsDiff.mjs`). Οι παρτίδες ουρών (`merge_group`, Mergify drafts, `omni-queue/**`) δεν κρίνονται ξανά: αθροίζουν PRs την πύλη που έχει ήδη κριθεί μία προς μία.

Κωδικοί εξόδου: `0` clean · `1` STRICT drift (ή soft drift με `--strict`) ή παραβίαση διαχειριζόμενης τιμής · `2` υποδομή — δεν ήταν δυνατή η συλλογή γεγονότων κώδικα (η ανίχνευση tsx απέτυχε ή έληξε, το χρονικό όριο είναι `OMNIROUTE_FACTS_TIMEOUT_MS`, προεπιλογή 600000 ms) ή, σε CI βάση δεν μπορούσε να επιλυθεί η βάση PR. Η έξοδος 2 δεν αποτελεί ποτέ απόκλιση τεκμηρίωσης: εκτελέστε ξανά την εργασία ή διορθώστε το περιβάλλον.

Οι εντολές πίσω από αυτό:

- `npm run facts` εκτυπώνει κάθε παράγωγο αριθμό ως JSON (`scripts/release/facts.mjs`). `--key=code.mcpTools` εκτυπώνει μία τιμή, `--snapshot` διαβάζει το δεσμευμένο στιγμιότυπο αντί για το ζωντανό δέντρο. Έξοδος 2 όταν δεν μπορούν να συλλεχθούν τα γεγονότα.
- `npm run release:refresh-derived` (`scripts/release/refresh-derived.mjs`) υπολογίζει εκ νέου τα παράγωγα αρχεία με ένα πέρασμα, με αυτή τη σειρά (αναγνωριστικά βημάτων για `--only=`): `provider-reference` (`docs/reference/PROVIDER_REFERENCE.md`), `facts` (το στιγμιότυπο), `numbers` (το σχέδιο επανεγγραφής της πύλης μετρήσεων εφαρμόζεται στα έγγραφα και στη συνέχεια μεταφέρεται στους καθρέφτες `docs/i18n/` τους), `readme-diagrams`, `skills` (το `SKILL.md` `ui-keys` `syncE2eTimings`), `e2e-timings` (τα πλήκτρα prunes `en.json` έπεσαν και, με `--rewritten-since=<ref>` — προεπιλεγμένη `origin/main` — επαναλαμβάνει ουρές αγγλικών τιμών που έχουν ξαναγραφτεί από την τελευταία έκδοση. Οι τιμές μεταφράζονται στην ίδια εκτέλεση από το backend που έχει διαμορφωθεί στο περιβάλλον ή σε `.env` (`OMNIROUTE_TRANSLATION_*`, μόνο αυτά τα κλειδιά διαβάζονται ποτέ από το Google recorders backend. αποτυγχάνει, το νυχτερινό παραλείπει τα πλήκτρα και `--allow-untranslated` `__MISSING__` γράφει επίτηδες), `llm-mirrors` και `verify-generated` (μετά από εγγραφή, `check:generated-artifacts` και `check:agent-skills-sync` στη λειτουργία απελευθέρωσης πρέπει να περάσουν, παραλείπονται στο `--check` και όταν `--only` το αφήνει έξω, μια αποτυχία είναι η έξοδος 2). Το βήμα `changelog` είναι συμμετοχή (`--with-changelog`, μόνο προφίλ έκδοσης). `--profile=nightly` δεν αγγίζει ποτέ μια αξίωση έκδοσης. Με `-- --check` δεν γράφει τίποτα και βγαίνει από το 1 όταν άλλαζε κάποιο αρχείο ή όταν μια διαχειριζόμενη τιμή χρειάζεται χειροκίνητη επεξεργασία (αναφέρονται και τα δύο). έξοδος 2 σε αστοχία υποδομής. `--json` εκτυπώνει το αποτέλεσμα ως JSON.
- `docs/reference/derived-facts.json` είναι το στιγμιότυπο των γεγονότων που χρησιμοποιήθηκε η τελευταία ανανέωση. Μόνο το refresh το γράφει. Οι γεννήτριες README SVG το διαβάζουν και οι δοκιμές μονάδων PR-time συγκρίνουν τα δεσμευμένα έγγραφα και τα αρχεία που δημιουργούνται με αυτό — ποτέ με τον ζωντανό κώδικα. Η μοναδική ζωντανή σύγκριση της σουίτας είναι "η ανανέωση κυκλοφορίας κλείνει τον κύκλο" στο `tests/unit/check-docs-counts-sync.test.ts`: με τα ζωντανά γεγονότα, το σχέδιο επανεγγραφής της ανανέωσης που εφαρμόζεται στη μνήμη δεν αφήνει drift STRICT που δεν αναφέρει και ο επανασχεδιασμός δεν αλλάζει τίποτα.

Για αναπαραγωγή τοπικά (μια τοπική εκτέλεση είναι από προεπιλογή `release`):

Αυτός ο βοηθός είναι ο** μόνο** εγκεκριμένη λειτουργία-παράβλεψη υπό όρους: `check:test-masking` μετράει `.skip(` και `{ skip: true }` αλλά όχι το υπολογισμένο `{ skip: "<reason>" }` που επιστρέφει, επομένως `tests/unit/locale-parity-mode.test.ts` καρφιτσώνει τη λίστα των δοκιμών που επιτρέπεται να το χρησιμοποιήσουν — προσθέτοντας ένα είναι μια ελεγμένη τροποποίηση σε αυτήν τη λίστα.

#### `check-ui-value-drift` — μπαγιάτικο-μετάφραση πύλη

Πιάνει τη μία παλινδρόμηση i18n που οι άλλες πύλες δομικά δεν μπορούν να δουν: μια αγγλική τιμή ξαναγράφεται και οι μεταφράσεις που προέρχονται από τα _προηγούμενα_ αγγλικά παραμένουν πίσω, έτσι οι μη Άγγλοι χρήστες συνεχίζουν να διαβάζουν αντίγραφο με σιγουριά, τώρα λάθος.

Αυτό στάλθηκε πραγματικά. `oauthModal.googleOAuthWarning` ξαναγράφτηκε όταν προσγειώθηκε το βοηθητικό πρόγραμμα σύνδεσης Antigravity (#5203);** 39 από 43 τοποθεσίες** διατήρησε κείμενο που έλεγε στους χειριστές να "αντιγράψουν το πλήρες URL και να το επικολλήσουν παρακάτω" — μια ροή που δεν μπορεί να ολοκληρωθεί για αυτόν τον πάροχο. Πέρασε απαρατήρητο μέχρι #8463 γιατί:

- `sync-ui-keys` συμπληρώνει μόνο τα κλειδιά που είναι** απών** , ποτέ αυτά που είναι** μπαγιάτικος** ;
- `check-ui-keys-coverage` μετράει το κλειδί _παρουσία_, οπότε μια μπαγιάτικη μετάφραση βαθμολογείται ως καλυμμένη.
- `check-translation-drift` παρακολουθεί την τεκμηρίωση `docs/i18n/<locale>/**.md` αντικατοπτρίζει — ποτέ δεν διαβάζει `src/i18n/messages/*.json`. Λειτουργεί σε job `docs-sync-strict`: συμβουλευτικό για PRs, αυστηρό για ώθηση και βραδινή. το κύμα μετάφρασης ανανεώνει τους καθρέφτες, όχι το χαρακτηριστικό PR.

**Με επίγνωση των διαφορών, όχι με βάση τη γραμμή βάσης.** Συγκρίνει `en.json` στη βάση συγχώνευσης με το δέντρο εργασίας. Για κάθε κλειδί του οποίου η τιμή στα αγγλικά άλλαξε, κάθε τοπική γλώσσα που εξακολουθεί να διατηρεί μια ανέγγιχτη μετάφραση είναι μπαγιάτικη. Αυτό σκόπιμα** παγώνει το προϋπάρχον χρέος** — μια διαφορά δεν μπορεί να αποκαλύψει από ποια παλιά αγγλικά προήλθε μια μακροχρόνια μετάφραση, επομένως η πύλη κρίνει μόνο τι αγγίζει η τρέχουσα αλλαγή. Η εναλλακτική λύση (μια βασική γραμμή κατακερματισμού ανά κλειδί) θα κόστιζε ένα αρχείο που δημιουργείται ~ 600 KB, 3 × η μεγαλύτερη υπάρχουσα γραμμή βάσης, που αναδεύεται σε κάθε i18n PR.

Δύο τρόποι για να το ικανοποιήσεις:

1. ενημερώστε τις επηρεαζόμενες μεταφράσεις ή
2. ρυθμίστε τα σε `__MISSING__:<new english>` — το χρόνο εκτέλεσης και, στη συνέχεια, εξυπηρετεί τα διορθωμένα αγγλικά (`src/i18n/request.ts::deepMergeFallback`, #7258) και τις βασικές ουρές για μετάφραση.

Αν η χορδή είναι** έννοια** άλλαξε, προτιμώ** μετονομασία του κλειδιού** : ένα νέο κλειδί δεν μπορεί να κληρονομήσει μια παλιά μετάφραση. Αυτό είναι το μοτίβο #8463 που χρησιμοποιείται.

```bash
npm run i18n:check-value-drift          # strict (what CI runs)
npm run i18n:check-value-drift:warn     # report only
BASE_REF=origin/release/vX.Y.Z npm run i18n:check-value-drift
```

Έξοδος 0 με `SKIP reason=base-unresolved` όταν δεν είναι δυνατή η ανάγνωση του βασικού καταλόγου (ρηχός κλώνος χωρίς το βασικό ref), αντικατοπτρίζοντας `check-openapi-breaking`. Μόνο λειτουργία έκδοσης: ένα χαρακτηριστικό PR ξαναγράφει τα αγγλικά και σταματά εκεί. η ανανέωση έκδοσης σηματοδοτεί τις μεταφράσεις που άφησε πίσω της (`node scripts/i18n/sync-ui-keys.mjs --rewritten-since=<ref>`, ίδιο `findStaleTranslations`).

Ελέγξτε αυτές τις εκθέσεις ως την έγκαιρη προειδοποίηση για τους προϋπολογισμούς που καταναλώνονται. επιθεωρήστε τις σημειώσεις `_rebaseline_*` της παραβατικής πύλης. Η εργασία δεν δημιουργεί ή ενημερώνει πλέον ένα μόνιμο ζήτημα. #12149 διατηρεί το ιστορικό της προηγούμενης αναφοράς.

**Λειτουργία νέου κώδικα (Clean-as-You-Code) — από το 2026-08-30, PR μόνο γρήγορη διαδρομή**

Στα συμβάντα `pull_request` `quality.yml` μεταβιβάζει `--base-ref <PR base SHA>` σε `check:file-size`, `check:complexity-ratchets` και `check:dead-code`. Για `check:complexity-ratchets` και `check:dead-code` η πύλη συγκρίνει HEAD με τη βάση συγχώνευσης** περιορίζεται στα αρχεία που άγγιξε το PR** (`scripts/check/newCodeMode.mjs`: η βάση συγχώνευσης υλοποιείται σε ένα πέταγμα `git worktree`, ESLint/knip τρέχει εκεί και στο HEAD, οι μετρήσεις ανά αρχείο διαφέρουν):

- **μπλοκάρισμα** — το PR πρόσθεσε παραβιάσεις cyclomatic/cognitive ή νεκρές εξαγωγές σε αρχεία που άλλαξε (`complexityNewCode=`, `cognitiveComplexityNewCode=`, `deadExportsNewCode=` στο αρχείο καταγραφής).
- **συμβουλευτικός** — το συνολικό σύνολο έναντι της παγωμένης γραμμής βάσης. Το κληρονομημένο drift δεν ερεθίζει ποτέ έναν αθώο PR. το drift παγώνει ξανά κατά τη συμφιλίωση απελευθέρωσης και παρακολουθείται από την εργασία του headroom.

`check:file-size` χρησιμοποιεί τη βασική αναφορά με τους δικούς του όρους (`scripts/check/check-file-size.mjs`, #8522): ελέγχει κάθε πηγή και δοκιμαστικό αρχείο στο δέντρο, διαβάζει τον αριθμό γραμμών του καθενός στη βάση PR με `git show` και αποτυγχάνει ένα αρχείο μόνο όταν ξεπεράσει το μεγαλύτερο ανώτατο όριο γραμμής βάσης (`frozen` / `testFrozen` ή `cap` / `testCap` ) και για ένα αρχείο εκτός της βασικής του γραμμής. Επομένως, ένα αρχείο που έχει ήδη παρασυρθεί στη βάση δεν κάνει ποτέ κόκκινο ένα αθώο PR.

`check:boundary:ratchet` εφαρμόζει τον ίδιο κανόνα στον μοναδικό του αριθμό (`scripts/quality/measure-boundary.mjs --ratchet --base-ref <sha>`): σε συμβάντα PR τόσο οι γρήγορες πύλες `quality.yml` όσο και η εργασία `ci.yml` lint περνούν τη βάση PR SHA, η δέσμευση βάσης μετράται από μια εξαγωγή `git archive` και το PR αποτυγχάνει μόνο όταν ο αριθμός των άκρων `open-sse → src` υπερβαίνει το μεγαλύτερο του `metrics.boundaryOpenSseToSrc` και το πλήθος στη βάση. Η μετατόπιση της βάσης πάνω από την οροφή αναφέρεται (`base drift herdado`), αλλά ποτέ δεν κοκκινίζει ένα αθώο PR. Το push → main διατηρεί το απόλυτο ανώτατο όριο, και μια μη επιλύσιμη βάση SHA πέφτει πίσω σε αυτό με μια προειδοποίηση.

Ένας υποψήφιος omni-queue (ένα push to `omni-queue/**`, βλέπε [OMNI_QUEUE.md](../ops/OMNI_QUEUE.md) ) λαμβάνει την ίδια αντιμετώπιση με ένα αίτημα έλξης: και οι δύο ροές εργασίας περνούν την υποψήφια βάση (`needs.changes.outputs.candidateBase`) ως `--base-ref` και `check:ts7-diagnostics-ratchet` τρέχει επίσης σε αυτήν. Για τις δύο πύλες νέου κώδικα, η βάση σύγκρισης είναι ότι το ίδιο το SHA, όχι ο πρώτος γονέας της κορυφαίας συγχώνευσης, κρίνεται έτσι κάθε αίτημα έλξης της παρτίδας.

Τα τρεξίματα `workflow_dispatch`, η απελευθέρωση-πράσινη σάρωση και η νυχτερινή εργασία κεφαλής δεν έχουν βάση PR και διατηρούν την απόλυτη (παγκόσμια) σύγκριση. Η κάλυψη, η αντιγραφή και η κάλυψη τύπου παραμένουν παγκόσμιες προς το παρόν (τα εργαλεία τους δεν παράγουν φθηνή διαφορά ανά αρχείο) υποψήφιοι — για την ίδια αντιμετώπιση.

**Κλείσιμο της φάσης στο v4.0 (LTS = πιο σφιχτό από πριν, όχι "επιστροφή στο κανονικό")**

1. Στην καθαρή συμβουλή `release/v4.0.0` : `npm run quality:headroom --json` για την εγγραφή, μετά `npm run quality:ratchet -- --update`, `check:file-size --update`, `check:complexity-ratchets --update`, `check:dead-code --update`, το `--update` — κάθε πύλης ελέγχου τύπων κάθε γραμμή βάσης πέφτει στη μετρούμενη τιμή.
2. Διαγράψτε `_policy` από `quality-baseline.json` (επαναοπλίστε `--require-tighten` και το νυχτερινό banking), επαναφέρετε `THRESHOLD = 36` (ή υψηλότερο) στο `check-openapi-coverage.mjs`.
3. Σφίξτε πέρα από τις μετρήσεις εκεί όπου η σπονδυλοποίηση απέδωσε: `cap` μεγέθους αρχείου πίσω στα 1000 (ή 800), ορόφους κάλυψης + 5, νεκρές εξαγωγές 0 για τα διαμορφωμένα πακέτα.

## Ratchet Baseline (`quality-baseline.json`)

Ο κινητήρας καστάνιας (`scripts/quality/check-quality-ratchet.mjs`) διαβάζει `quality-baseline.json` και το συγκρίνει με το φρεσκοσυλλεγμένο `quality-metrics.json`. Οποιαδήποτε μέτρηση υποχωρεί πέρα από το έψιλον της αποτυγχάνει στην κατασκευή.

Τρέχουσες μετρήσεις παρακολούθησης:

| Μετρικός              | Κατεύθυνση | Εννοια                                                   |
| --------------------- | ---------- | -------------------------------------------------------- |
| `eslintWarnings`      | `down`     | Ο αριθμός προειδοποιήσεων ESLint δεν πρέπει να αυξάνεται |
| `coverage.statements` | `up`       | Η κάλυψη της δήλωσης δεν πρέπει να πέσει                 |
| `coverage.lines`      | `up`       | Η κάλυψη της γραμμής δεν πρέπει να πέφτει                |
| `coverage.functions`  | `up`       | Η κάλυψη της λειτουργίας δεν πρέπει να πέφτει            |
| `coverage.branches`   | `up`       | Η κάλυψη των υποκαταστημάτων δεν πρέπει να πέσει         |

Για να ενημερώσετε τη γραμμή βάσης μετά από μια πραγματική βελτίωση:

```bash
npm run quality:ratchet -- --update
git add quality-baseline.json
```

Η σημαία `--update` γράφει τις τρέχουσες μετρούμενες τιμές σε `quality-baseline.json`. Η τραπεζική βελτίωση είναι δουλειά release/nightly, όχι χαρακτηριστικό PR's: `--require-tighten` (Fase 6A.5) αποτυγχάνει μια un-bank βελτίωση μόνο στη λειτουργία έκδοσης (push, χρονοδιάγραμμα, η απελευθέρωση PR, τοπικές εκτελέσεις). Σε ένα χαρακτηριστικό PR (λειτουργία πύλης `pr` ) εκτυπώνει τη βελτίωση ως πληροφορίες και περνάει. μια παλινδρόμηση αποτυγχάνει και στις δύο καταστάσεις. Κατά τη φάση της ταχύτητας είναι συμβουλευτικό παντού (`_policy.requireTighten: false`). Δείτε [Δημιουργημένα αρχεία και παράγωγες γραμμές βάσης](#generated-files-and-derived-baselines-written-at-release).

### CodeQL καστάνια: ρυθμός ανανέωσης και χειροκίνητη σκανδάλη

`check:codeql-ratchet` διαβάζει** κατάσταση repo, ανανεώθηκε βάσει χρονοδιαγράμματος — όχι ανά PR.** `gh api repos/diegosouzapw/OmniRoute/code-scanning/default-setup` αναφέρει `state: configured`, `schedule: weekly`: σάρωση προεπιλεγμένης ρύθμισης του GitHub, όχι ανάλυση ανά ώθηση. Συνέπεια: μετά από ένα PR που συγχωνεύεται οι ειδοποιήσεις FIXES, η καστάνια συνεχίζει να διαβάζει το παλιό, υψηλότερο πλήθος μέχρι να εκτελεστεί — η επόμενη προγραμματισμένη σάρωση, επομένως αναφέρει μια παλινδρόμηση σε κάθε ανοιχτό PR, συμπεριλαμβανομένων των επακόλουθων του ίδιου του PR, μέχρι να φτάσει η σάρωση.

**Χειροκίνητη ανανέωση** : `gh workflow run codeql.yml --ref release/vX.Y.Z` εκτελεί ξανά την ανάλυση και αναδημοσιεύει τις ειδοποιήσεις μέσα σε λίγα λεπτά. Διαβάστε πρώτα `.github/workflows/codeql.yml` — Η κεφαλίδα του εξηγεί ότι είναι `workflow_dispatch` -only** επειδή έρχεται σε διένεξη με την "προεπιλεγμένη ρύθμιση" του GitHub** (`CodeQL analyses from advanced configurations cannot be processed when the default setup is enabled`). Η επαναφορά των ενεργειών `push`/`pull_request`/ `schedule` απαιτεί ένα** ενέργεια του ιδιοκτήτη πρώτα** : Ρυθμίσεις → Ασφάλεια κωδικού → CodeQL: Προεπιλογή → Για προχωρημένους. Μην προσθέτετε μια σκανδάλη `schedule:` χωρίς αυτόν τον διακόπτη — θα δημιουργήσει μόνο αποτυχημένες εκτελέσεις.

**Σφίξτε τη γραμμή βάσης αφού πέσει η μέτρηση** — `node scripts/check/check-codeql-ratchet.mjs --update` γράφει το νέο μετρημένο πλήθος σε `quality-baseline.json` → `metrics.codeqlAlerts.value`, έτσι η καστάνια δεν επιτρέπει σιωπηλά μια παλινδρόμηση μέχρι το παλιό ανώτατο όριο. Παράδειγμα εργασίας (2026-09-02/03): PR #12502 διορθώθηκε 7 πραγματικές ειδοποιήσεις (13 → 6 μετρήθηκαν ανοιχτά). PR #12530 έσφιξε την παγωμένη γραμμή βάσης 11 → 6 για να ταιριάζει. τα υπόλοιπα 6 απορρίφθηκαν στη συνέχεια με αιτιολόγηση ανά συναγερμό μέχρι το 0 ανοιχτό.

**Οι απολύσεις είναι κλήση του χειριστή (Hard Rule #14)** — δεν απορρίπτει ποτέ μια ειδοποίηση CodeQL χωρίς να καταγράφει την τεχνική αιτιολόγηση στο σχόλιο απόρριψης: `won't fix` για απαίτηση ανοδικού πρωτοκόλλου, `used in tests` για εξάρτημα δοκιμής, `false positive` για απολυμαντικό CodeQL δεν μπορεί να δει (προηγούμενο: `docs/security/ERROR_SANITIZATION.md`).

## Απόκλιση του ratchet σε επίπεδο release (WS5.5, v3.8.49)

Όταν ένα ratchet (μέγεθος αρχείου, πολυπλοκότητα, προειδοποιήσεις eslint) παρουσιάζει παλινδρόμηση στο ΚΑΘΑΡΟ tip του release
— δηλαδή ο ΣΥΝΔΥΑΣΜΟΣ των merges προκάλεσε την παλινδρόμηση και κανένα μεμονωμένο PR δεν την αναπαράγει
στο δικό του branch — η διόρθωση ανήκει στον **release captain, μία φορά, στο
release branch**: προτιμήστε εξαγωγή/refactor· επανακαθορίστε το baseline μόνο με την τεκμηριωμένη
καταχώριση αιτιολόγησης. Μην επιρρίπτετε ποτέ την απόκλιση του συνδυασμού σε PR κάποιου contributor και μην
επανακαθορίζετε ποτέ το baseline ανά PR (αυτό αποκρύπτει πραγματικές παλινδρομήσεις). Πρώτα κάντε τη διάκριση: αναπαραγάγετε
την αποτυχία στο καθαρό tip μέσα σε ένα probe worktree, προτού υποθέσετε ότι την προκάλεσε το PR σας.

## Δημιουργήθηκαν αρχεία και παράγωγες γραμμές βάσης (γραμμένα κατά την κυκλοφορία)

Σχέδιο 2026-11-13 ("προερχόμενοι αριθμοί και κείμενα επιλύονται μόνο κατά την κυκλοφορία"): ένα χαρακτηριστικό PR αλλάζει το** πηγή** — `src/shared/constants/providers.ts`, `docs/openapi.yaml`, ο κατάλογος δεξιοτήτων, ο κατάλογος ελεύθερου επιπέδου, μια νέα προδιαγραφή e2e. Δεν αναγεννά τα αρχεία που υπολογίζονται από αυτήν την πηγή και δεν αποθηκεύει μια μετρημένη βελτίωση σε μια γραμμή βάσης. Αυτά τα αρχεία ξαναγράφονται μία φορά, με την ανανέωση έκδοσης (`release:refresh-derived`) ή με μια νυχτερινή ανανέωση PR. Πριν από αυτό, κάθε αδερφός PR έφερε το δικό του αναγεννημένο αντίγραφο και έρχονταν σε σύγκρουση με την επόμενη συγχώνευση (13-11-2026: 30 από 321 ανοιχτά PRs επανέγραψαν `PROVIDER_REFERENCE.md`, 26–28 ξανάγραψαν τα διαγράμματα README ).

**Ο φρουρός.** `check:pr-derived-paths` (εργασία `pr-test-policy`) αποτυγχάνει μια δυνατότητα PR που αγγίζει ένα αρχείο μιας οικογένειας στο `config/quality/derived-paths/`:

| Οικογένεια  | Αρχεία                                                                                                                                                                                              | Ξαναγράφτηκε από                                                                                                            |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `generated` | `docs/reference/derived-facts.json`; `docs/reference/PROVIDER_REFERENCE.md`; οι δώδεκα δημιουργήθηκαν README SVGs; `skills/*/references/**`; τα αρχεία `SKILL.md` που δεν έχουν προσαρμοσμένο μπλοκ | `release:refresh-derived` (γεγονότα), `gen:provider-reference`, `docs:readme-diagrams`, `generate-agent-skills.mjs --apply` |
| `baselines` | `config/quality/e2e-timings.json`                                                                                                                                                                   | `balance-e2e-shards.mjs --sync` (`syncE2eTimings()`)                                                                        |

Οι συγγραφείς (`release/v*`, `chore/derived-*` και `chore/bank-ratchet-*` για γραμμές βάσης) εξαιρούνται. έτσι είναι και ένα PR που αλλάζει μόνο μία οικογένεια συν τα συνοδευτικά του (για `generated`: τα σενάρια γεννήτριας, οι δοκιμές τους, οι είσοδοι δεξιοτήτων πράκτορα — `src/shared/constants/agentSkills.ts`, τα χειρόγραφα `skills/**` docs, `docs/openapi.yaml` — και `changelog.d/**`), π.χ. αλλαγή διάταξης ήρωα με τα αναγεννημένα αρχεία SVG του οποίου τα αρχεία `SKILL.md` διορθώθηκαν ξανά ή ένα τεστ. Ένα `SKILL.md` με χειρόγραφο μπλοκ `<!-- skill:custom-start -->` δεν ανήκει στην οικογένεια: το προσαρμοσμένο μπλοκ του παραμένει επεξεργάσιμο δίπλα σε ένα χαρακτηριστικό.

Η εκκαθάριση των ορφανών δεν κρίνεται ούτε από τις οικογένειες: ένας PR μπορεί να διαγράψει `docs/i18n/<locale>/<doc>` όταν η βάση συγχώνευσης είχε αυτόν τον καθρέφτη και `<doc>` δεν υπάρχει πλέον στο κεφάλι του PR και μπορεί να επεξεργαστεί `.i18n-state.json` μόνο για να απορρίψει τέτοια έγγραφα από `sources`. Ο φύλακας παραθέτει αυτά τα αρχεία κάτω από `orphan-cleanup`. Η διαγραφή του καθρέφτη ενός εγγράφου που εξακολουθεί να υπάρχει παραμένει παραβίαση: κανένας άλλος αγωγός δεν ακολουθεί αυτήν την κατάσταση και οι καθρέφτες `llm.txt` και `CHANGELOG.md` έχουν τους δικούς τους συντάκτες.

**Οι έλεγχοι, ανά λειτουργία πύλης** (`scripts/check/lib/gateMode.mjs`; βοηθός `scripts/check/lib/derivedArtifactScope.mjs`):

| Ελεγχος                                                                                | `release` (ώθηση, προγραμματισμός, απελευθέρωση PR, τοπικό)                          | `pr` (χαρακτηριστικό PR, παρτίδα ουράς)                                                                                                                                                                                    |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `check:agent-skills-sync`                                                              | κάθε ικανότητα πρέπει να είναι ίση με την έξοδο της γεννήτριας                       | μόνο οι δεξιότητες των οποίων το κείμενο που δημιουργήθηκε (εκτός του προσαρμοσμένου μπλοκ) ή το `references/` επεξεργάζεται το PR. αλλιώς `SKIP reason=pr-mode`                                                           |
| `check:generated-artifacts` ( χρονισμοί README SVGs + e2e, χρειάζεται πλήρες ιστορικό) | κάθε SVG ισούται με τη γεννήτρια του. κάθε προδιαγραφή έχει μια καταχώρηση χρονισμού | μόνο τα τεχνουργήματα που επεξεργάζεται η PR. τα υπόλοιπα `SKIP reason=pr-mode`? χωρίς βάση διαφοράς → κάθε τεχνούργημα που κρίθηκε (αποτυχία-κλειστό)                                                                     |
| README SVG byte-compare tests (`tests/unit/docs/readme-*-svg.test.ts`)                 | κάθε SVG                                                                             | μόνο ένα SVG το PR επεξεργάζεται, όταν η βάση επιλύει? Το ρηχό ταμείο PR του `test-unit` δεν έχει βάση, οπότε εκεί το τεστ παραλείπει με `SKIP reason=base-unresolved` και `check:generated-artifacts` κατέχει τη σύγκριση |
| πληρότητα χρονισμών e2e (`tests/unit/balance-e2e-shards.test.ts`)                      | κάθε προδιαγραφή έχει μια καταχώρηση                                                 | ο ίδιος κανόνας με τις δοκιμές SVG (μια νέα προδιαγραφή εκτελείται με το μέσο βάρος)                                                                                                                                       |
| `check-quality-ratchet.mjs --require-tighten`                                          | η μη τραπεζική βελτίωση αποτυγχάνει (εκτός εάν `_policy`)                            | αναφέρθηκε βελτίωση, ποτέ αποτυχία. μια παλινδρόμηση εξακολουθεί να αποτυγχάνει                                                                                                                                            |

Η λειτουργία απελευθέρωσης διατηρεί τις ετυμηγορίες, τους κωδικούς εξόδου και τα μηνύματα που είχαν αυτοί οι έλεγχοι πριν από τη διαίρεση. προστίθεται το πολύ μία γραμμή, ονομάζοντας την επιλυμένη λειτουργία (`[agent-skills-sync] mode=release (auto: local run)`). Οι δοκιμές παρακάμπτουν την επιλογή `{ skip: releaseOnlyUnlessTouched(...) }` του node:test, την οποία `check:test-masking` παραθέτει σε ένα μπλοκ μόνο για αναφορά (δεν είναι ούτε `.skip(` ούτε `{ skip: true }`, επομένως δεν υπολογίζεται ως σκληρή παράβλεψη). `check:generated-artifacts` εκτελείται όπου η βάση είναι επιλύσιμη: εργασία `lint` (`fetch-depth: 0`), αμέσως μετά `check:agent-skills-sync`. Τοπικά, `npm run check:generated-artifacts -- --mode=pr` δείχνει τι κρίνει αυτό το βήμα σε ένα PR. Ο συνολικός διασταυρωτικός έλεγχος του παρόχου του `check:docs-counts` ("Σύνολο αναφοράς παρόχου (έγγραφο έναντι ζωντανών λειτουργικών μονάδων)") αποτελεί μέρος της πύλης καταμέτρησης και ακολουθεί τους τρόπους λειτουργίας αυτής της πύλης.

Όχι σε οικογένεια, σκόπιμα: αρχεία πολιτικής που αποφασίζονται από άτομα (`gate-manifest.json`, οι λίστες επιτρεπόμενων, `admission-policy.json`, `provider-assets-provenance.jsonl`, `model-lifecycle.json`) και ανώτατα όρια ένα χαρακτηριστικό PR μπορεί να χρειαστεί να επεξεργαστεί μαζί με κώδικα (εγγραφές μετρήσεων `quality-baseline.json`, γραμμές βάσης typecheck/file-size/complexity, `eslint-suppressions.json` — κλαδεύονται από την εκτέλεση ESLint πριν από τη δέσμευση όταν μια παγωμένη παραβίαση PR διορθώνει μια παγωμένη παράβαση). `src/i18n/routeNamespaces.generated.json` δημιουργείται επίσης, αλλά παραμένει στη λειτουργία PRs: η εφαρμογή το εισάγει κατά το χρόνο εκτέλεσης, επομένως δεν μπορεί να περιμένει για ανανέωση.

## Αποθήκευση των μειώσεων του ratchet — η καθοδική κατεύθυνση (#8584)

Το ratchet είναι αυτοματοποιημένο μόνο κατά το ήμισυ, και μάλιστα στο λάθος μισό. Η **αύξηση** ενός ορίου είναι μια
χειροκίνητη επεξεργασία JSON που διαρκεί δέκα δευτερόλεπτα και αποτελεί τον ταχύτερο τρόπο για να ξεμπλοκάρει ένα αποτυχημένο PR.
Η **μείωση** ενός ορίου απαιτεί από κάποιον να εκτελέσει το `--update` και να κάνει commit το αποτέλεσμα — και μέχρι
να προστεθεί το job `bank-ratchet-shrinks`, κανένα workflow δεν το εκτελούσε. Η μετρημένη συνέπεια
(2026-07-25): 18 παγωμένα αρχεία βρίσκονται ήδη στο όριο των 800 γραμμών για νέα αρχεία ή κάτω από αυτό, με τη χειρότερη
περίπτωση στο 132× (`src/shared/validation/schemas.ts`, 19 γραμμές με όριο 2,523)· το
ανώτατο όριο πολυπλοκότητας μετακινήθηκε από `1794 → 2169` μέσα από ~37 σημειώσεις επανακαθορισμού baseline, με ακριβώς μία
μείωση (−1)· και η φράση «σύσφιξη μέσω `--update` στον επόμενο κύκλο» γράφτηκε 31 φορές και
τηρήθηκε μία φορά. Ένα όριο που επιβιώνει περισσότερο από τον κώδικα που το δικαιολόγησε μετατρέπει σιωπηρά κάθε ολοκληρωμένη
αποσύνθεση σε περιθώριο ανάπτυξης για όποιον επεξεργαστεί το αρχείο στη συνέχεια.

Το `nightly-release-green.yml` → job **`bank-ratchet-shrinks`** κλείνει αυτόν τον κύκλο:

|               |                                                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------------------------------- |
| Εκτελείται σε | `schedule` (3×/ημέρα) + `workflow_dispatch` — σκόπιμα **όχι** σε `push`                                             |
| Μετρά         | το υψηλότερο `release/vX.Y.Z`, με την ίδια επίλυση + προστασία από injection όπως το `release-green`                |
| Γράφει        | `check:file-size --update` και `check:complexity-ratchets --update` (και τα δύο μόνο προς μείωση εκ κατασκευής)     |
| Επαληθεύει    | `npm run check:ratchet-bank` (`scripts/quality/verify-ratchet-bank.mjs`)                                            |
| Παραδίδει     | ένα μοναδικό, πάντα ενημερωμένο PR προς το release branch — ενημερώνεται αναγκαστικά, χωρίς ποτέ να δημιουργεί spam |

Η αποθήκευση γίνεται σε παρτίδες αντί ανά push, επειδή δεν έχει απαίτηση χαμηλού latency (μια μείωση που
αποθηκεύεται εντός 8 ωρών είναι αποδεκτή), ενώ μια εκτέλεση ανά merge θα ανακατασκεύαζε επανειλημμένα το PR branch
κατά τη διάρκεια εκστρατειών συγχωνεύσεων και θα επιβάρυνε κάθε φορά το κόστος μιας πλήρους σάρωσης ESLint. Η ανίχνευση παραμένει στο
push (`release-green`)· μόνο η αποθήκευση γίνεται σε παρτίδες.

### Ο επαληθευτής ασφάλειας

Το job γράφει στα baselines χωρίς επίβλεψη, επομένως το `verify-ratchet-bank.mjs` είναι αυτό που καθιστά
αποδεκτή αυτή τη διαδικασία. Συγκρίνει μέσω diff το δέντρο μετά το `--update` με το `HEAD` και **διακόπτει το job
προτού υπάρξει οποιοδήποτε commit** — χωρίς να ανοίξει PR — εκτός εάν κάθε αλλαγή είναι μία από τις εξής:

- μια αριθμητική καταχώριση `frozen` / `testFrozen` που **μειώθηκε** ή **αφαιρέθηκε**
- `complexity-baseline.json` → `count` που **μειώθηκε**
- `quality-baseline.json` → `metrics.cognitiveComplexity.value` που **μειώθηκε**

Οτιδήποτε άλλο αποτυγχάνει: αύξηση ενός αριθμού, προσθήκη καταχώρισης, αλλαγή των `cap`/`testCap` ή
διαγραφή/επανεγγραφή μιας σημείωσης `_rebaseline_*` (αυτές οι σημειώσεις αποτελούν το ίχνος ελέγχου που εξηγεί γιατί υπάρχει κάθε
ανώτατο όριο και αποθηκεύονται μέσα στο ίδιο αντικείμενο `frozen` με τις καταχωρίσεις αρχείων).
Ένα bot που θα μπορούσε να αυξήσει ένα όριο θα ήταν σαφώς χειρότερο από την υφιστάμενη κατάσταση. Προστασία από
παλινδρόμηση: `tests/unit/verify-ratchet-bank.test.ts`.

Το job δεν κάνει ποτέ push στο `release/*` — ένας άνθρωπος συγχωνεύει το PR, ώστε μια λανθασμένη μέτρηση
να μην μπορεί να ενσωματωθεί χωρίς έλεγχο.

## Πολιτική λίστας επιτρεπόμενων

Κάθε πύλη που δεν μπορεί να αποτύχει σε προϋπάρχουσες παραβιάσεις χρησιμοποιεί μια παγωμένη λίστα επιτρεπόμενων (π.χ. `KNOWN_STALE_DOC_REFS`, `KNOWN_MISSING`, `KNOWN_RAW_SQL`). Η πολιτική είναι:

**Διορθώστε τη βασική αιτία. χρησιμοποιήστε τη λίστα επιτρεπόμενων μόνο όταν η παράβαση προϋπάρχει και δεν μπορεί να διορθωθεί στο ίδιο PR.**

Όταν προσθέτετε μια καταχώριση σε μια λίστα επιτρεπόμενων:

1. Συμπεριλάβετε ένα σχόλιο με την αιτιολόγηση.
2. Ανατρέξτε στο ζήτημα παρακολούθησης (π.χ. `// #3498 — Phase 2 feature, not yet implemented`).
3. Αφαιρέστε την καταχώριση στο ίδιο PR που διορθώνει την παράβαση — μια μπαγιάτικη καταχώριση που δεν καταστέλλει πλέον μια ενεργή παραβίαση είναι η ίδια ένα ελάττωμα (6A.3 μπαγιάτικη επιβολή θα αποτύχει στην πύλη σε μια ορφανή καταχώρηση λίστας επιτρεπόμενων μόλις εφαρμοστεί).

Κάνω** δεν** προσθέστε καταχωρίσεις στη λίστα επιτρεπόμενων για να κάνετε τις δοκιμές να περνούν πιο γρήγορα. Μια πράσινη πύλη με μια αυξανόμενη λίστα επιτρεπόμενων είναι μια λανθασμένη αίσθηση ποιότητας.

### Όταν μια πύλη αστοχεί στο PR σας

1. **Διαβάστε προσεκτικά την έξοδο της πύλης** — σας λέει ακριβώς ποιο αρχείο ή σύμβολο παραβίασε τον κανόνα.
2. **Διορθώστε την παράβαση** Οι περισσότερες πύλες — είναι ντετερμινιστικοί έλεγχοι συστήματος αρχείων που περνούν μόλις ο κώδικας είναι σωστός.
3. **Εάν η παράβαση προϋπάρχει** (δηλαδή, δεν το εισαγάγατε, αλλά η πύλη το καλύπτει τώρα): προσθέστε μια καταχώρηση στη λίστα επιτρεπόμενων με ένα σχόλιο αιτιολόγησης και ένα πρόβλημα παρακολούθησης.
4. **Αν η πύλη είναι καστάνια** (κάλυψη, προειδοποιήσεις ESLint, διπλασιασμός, πολυπλοκότητα): η αλλαγή σας έκανε τη μέτρηση χειρότερη. Διορθώστε το υποκείμενο πρόβλημα ή (σπάνια) εκτελέστε `npm run quality:ratchet -- --update` εάν η αλλαγή είναι σκόπιμη και η υποβάθμιση της μέτρησης είναι αποδεκτή — αλλά τεκμηριώστε το γιατί στην περιγραφή PR.
5. **Συμβουλευτικές πύλες** (`continue-on-error: true`) είναι ενημερωτικά —, δεν εμποδίζουν τη συγχώνευση αλλά εμφανίζονται στη σύνοψη CI. Διόρθωσέ τα πάντως.

## Προσθήκη νέου ελέγχου

1. Δημιουργήστε το `scripts/check/check-<name>.mjs` (ή `.ts`). Οι έλεγχοι πολιτικής τερματίζονται με 0/1.
   Οι έλεγχοι τύπου ratchet εκπέμπουν μια μετρική στο `quality-metrics.json` μέσω του `collect-metrics.mjs`.
2. Προσθέστε το `"check:<name>": "node scripts/check/check-<name>.mjs"` στο `package.json`.
3. Συνδέστε το στο `.github/workflows/ci.yml` κάτω από την κατάλληλη εργασία
   (πολιτική → `lint` ή `docs-sync-strict`· ratchet → `quality-gate`).
4. Αν διαθέτει λίστα επιτρεπόμενων, εφαρμόστε το `reportStaleEntries()` από το
   `scripts/check/lib/allowlist.mjs`, ώστε οι παρωχημένες καταχωρίσεις να εντοπίζονται αυτόματα.
5. Γράψτε μια δοκιμή στο `tests/unit/build/` που να καλύπτει τη λογική εντοπισμού του ελέγχου.
6. Ενημερώστε αυτό το έγγραφο (προσθέστε μια γραμμή στον σχετικό πίνακα εργασιών).

#### `check-key-completeness` — πύλη ισοτιμίας με σύνολο κλειδιών

Είναι το απόλυτο συμπλήρωμα των δύο πυλών diff-based/percentage : `check-ui-keys-coverage` επιβάλλει ένα κατώτατο όριο 80% ανά τοπική ρύθμιση (43 απόντα κλειδιά από ~ 13.000 εξακολουθούν να διαβάζονται 99,7%) και `check-new-key-coverage` κρίνει μόνο τα κλειδιά που προσθέτει ένα PR στο `en.json`. Μια παρτίδα τοπικών ρυθμίσεων δημιουργείται από το `en.json` της ημέρας που κόβεται ο κλάδος του και μεταφράζεται για μέρες, ενώ η βάση συνεχίζει να προσθέτει κλειδιά. η παρτίδα PR δεν προσθέτει κανένα κλειδί από μόνη της, επομένως και τα δύο αδέρφια έμειναν σιωπηλά όταν η παρτίδα 1 (#13044) προσγειώθηκε με 43 πλήκτρα σε εννέα τοπικές ρυθμίσεις και η παρτίδα 2 (#13660) 10 πλήκτρα σε οκτώ (2026-09-15). Διορθώστε ένα κόκκινο με `node scripts/i18n/sync-ui-keys.mjs --locale=<codes> --translate-markers`? ένα φύλλο `extra` σημαίνει ότι η πηγή το έριξε — `sync-ui-keys` το πέφτει (`--prune-extra`, η προεπιλογή). `--warn` αναφέρει χωρίς αποτυχία. `--catalog=cli` εκτελεί την ίδια σύγκριση με `bin/cli/locales` (`npm run i18n:check-keys:cli`). και τα δύο βήματα ζουν σε δουλειά `i18n-ui-coverage`. Ο απόλυτος έλεγχος είναι μόνο η λειτουργία απελευθέρωσης: μια δυνατότητα PR βλέπει `SKIP reason=pr-mode` και η επιδιόρθωση εκτελείται στην ανανέωση έκδοσης ή σε ένα κύμα μετάφρασης, ποτέ σε μια δυνατότητα PR. Αντί για ένα PR που αλλάζει τους καταλόγους τοπικών ρυθμίσεων, καθένας από αυτούς κρίνεται βάσει της βάσης συγχώνευσης (δείτε "Δύο λειτουργίες" στην εργασία `i18n-ui-coverage`).

#### πύλη `check-new-key-coverage` — με νέο κλειδί i18n

Αδερφός του `check-ui-value-drift`. Αυτό πιάνει μια αγγλική αξία που ήταν** ξαναγραφεί** ενώ οι μεταφράσεις του έμειναν πίσω. αυτό πιάνει ένα αγγλικό κλειδί που ήταν** προστέθηκε** ενώ ορισμένοι ντόπιοι δεν το έλαβαν ποτέ.

`check-ui-keys-coverage` δεν μπορεί να δει αυτήν την κατηγορία: επιβάλλει ένα ποσοστό κατώτατου ορίου ανά τοπική ρύθμιση και έντεκα κλειδιά από τα 13.000 ~ αφήνουν την κάλυψη στο 99,9%. Ένα ποσοστό ανά γλώσσα δεν μπορεί να εκφράσει "αυτή η δυνατότητα εστάλη αμετάφραστη" — ένα ολόκληρο χαρακτηριστικό μπορεί να προσγειωθεί σε μια νέα τοπική ρύθμιση χωρίς κείμενο και να μην μετακινηθεί ποτέ ο αριθμός.

Το περιστατικό που κωδικοποιεί: Η Φάση 3 του Orchestration Canvas μετέφρασε τα έντεκα κλειδιά του στις 42 τοπικές ρυθμίσεις που υπήρχαν εκείνη την εποχή. Ώρες αργότερα η παρτίδα της γλώσσας ΕΕ (#13044) οδήγησε το repo σε 51 τοπικές ρυθμίσεις και οι εννέα νεοφερμένοι (`el`, `et`, `ga`, `hr`, `lt`, `lv`, `mt`, `sl`, `sr`) δεν τα έλαβαν ποτέ. `deepMergeFallback` αντικαθιστά τα αγγλικά για ένα κλειδί που απουσιάζει, επομένως η λειτουργία αποτυχίας ήταν αμετάφραστη UI παρά κενό UI — real και αθόρυβη κατά κατασκευή.

Σαν αδερφάκι του είναι** διαφοροποιημένος** , συγκρίνοντας τα αγγλικά στη βάση συγχώνευσης με το δέντρο εργασίας, έτσι τα προϋπάρχοντα κενά παραμένουν παγωμένα και η πύλη δεν χρειαζόταν μετεγκατάσταση για να ενεργοποιηθεί.

**Ένας δείκτης `__MISSING__:<english>` δεν το ικανοποιεί (από 17-09-2026).** Ήταν η τεκμηριωμένη αναβολή — ο χρόνος εκτέλεσης επιστρέφει για να διορθώσει τα αγγλικά — έως ότου οκτώ χαρακτηριστικά PRs στις 2026-09-16 πρόσθεσαν 61 κλειδιά και σφράγισαν τον δείκτη και στις 65 τοπικές ρυθμίσεις αντί να μεταφραστούν: αυτή η πύλη δεχόταν κάθε μία, τίποτα δεν εμπόδιζε το PRs και το μπλοκάρισμα της πραγματικής μετάφρασης στη συνέχεια απέτυχε η συμβουλή g-pt για κάθε μετάφραση στο %2 το rat. > 2,5 % + 0,5). Ένας δείκτης κρίνεται πλέον ως απούσα μετάφραση. Λειτουργία απελευθέρωσης μόνο από το 2026-11-13: ένα χαρακτηριστικό PR βλέπει `SKIP reason=pr-mode` και κατά την απελευθέρωση PR (`BASE_REF=origin/main`) η πύλη κρίνει κάθε κλειδί του κύκλου που προστέθηκε. Διορθώστε ένα κόκκινο στην ανανέωση έκδοσης ή ένα κύμα μετάφρασης με `node scripts/i18n/sync-ui-keys.mjs --locale=<codes> --translate-markers --batch-size=40`, ή όλες τις τοπικές ρυθμίσεις παράλληλα με `npm run i18n:translate-new-keys` (`scripts/i18n/translate-new-keys.sh`, αποσπώμενο-ασφαλές, αρνείται να ξεκινήσει χωρίς το `OMNIROUTE_TRANSLATION_*` env). Ένα κλειδί που πρέπει να παραμείνει αγγλικό (ένα καρφιτσωμένο όνομα product/engine/flag ) ανήκει στο `scripts/i18n/untranslatable-keys.json`, ποτέ πίσω από δείκτη. `vi` απαγορεύει οριστικά τους δείκτες (`tests/unit/i18n-vi-completeness.test.ts`).

#### `check-vitest-exclusions` — παρκαρισμένη πύλη δοκιμής

Ένα αρχείο στη λίστα `exclude` του `vitest.config.ts` είναι μια δοκιμή που δεν εκτελείται και μοιάζει με κάλυψη σε όποιον διαβάζει το δέντρο. Εξήντα δύο αρχεία συσσωρεύτηκαν πίσω από το σχόλιο `// #8618 — pre-existing failure; remove this exclusion when fixed`. Το τεύχος #8618 έκλεισε στις 11-08-2026, ενώ η λίστα που παρακολουθούσε αυξήθηκε από 45 εγγραφές σε 62, κάθε νέα κληρονομώντας ένα σχόλιο που έδειχνε ένα νεκρό ζήτημα. Όταν τελικά η λίστα μετρήθηκε αρχείο με αρχείο (#13204),** 51 από τα 62 πέρασαν στο τρέχον δέντρο χωρίς αλλαγή πηγής** .

Η πύλη απαιτεί κάθε εξαίρεση που επιλύεται σε ένα πραγματικό αρχείο για να (α) να ονομάσει ένα ζήτημα παρακολούθησης και (β) να εμφανιστεί στο `config/quality/vitest-exclusions.json` με τη μετρημένη κατάστασή του, επομένως η προσθήκη μιας είναι μια διαφορά με δυνατότητα αναθεώρησης σε ένα αποκλειστικό αρχείο αντί για μια ακόμη γραμμή σε έναν πίνακα 60 καταχωρήσεων. Δεν επαναλαμβάνει σκόπιμα τα εξαιρούμενα τεστ — που κοστίζουν ~ 10 λεπτά και ανήκουν σε περιοδική εργασία. το απόθεμα καταγράφει πότε μετρήθηκε τελευταία φορά το καθένα.
