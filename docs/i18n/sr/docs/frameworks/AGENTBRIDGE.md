AgentBridge је OmniRoute-ов MITM (Man-in-the-Middle) прокси који пресреће HTTPS саобраћај IDE AI агената и преусмерава га кроз OmniRoute-ов обједињени механизам за рутирање. Подржава **10 IDE агената** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code и Trae (у фази истраживања) — што чини OmniRoute MITM проксијем са најширом подршком за AI асистенте за програмирање на тржишту.

**Локација контролне табле:** `/dashboard/tools/agent-bridge`
**Група на бочној траци:** Алатке (после Cloud Agents)
**Погледајте и:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — надгледајте сав пресретнути саобраћај у реалном времену; `docs/security/MITM-TPROXY-DECRYPT.md` (git; није компајлирано у `/docs`) — Linux TPROXY режим снимања са транспарентним дешифровањем, којим управља рута `/api/tools/agent-bridge/tproxy`.

## §1 Pregled

### Šta je AgentBridge?

Kada IDE agent (npr. GitHub Copilot, Cursor, Claude Code) uputi API poziv, on se povezuje direktno sa izvornim AI provajderom (OpenAI, Anthropic, itd.). AgentBridge presreće tu vezu transparentno na TLS nivou — bez potrebe za bilo kakvom izmenom konfiguracije agenta — i preusmerava zahtev kroz OmniRoute.

Ovo znači da možete:

- **Preusmeriti bilo kog agenta na bilo kog provajdera**: Copilot komunicira sa OpenAI? Preusmerite ga na Anthropic Claude, Gemini ili bilo kog od 376 provajdera koje OmniRoute podržava.
- **Primeniti mapiranja modela**: `gemini-3-flash` → `claude-sonnet-4.7` transparentno na nivou obrađivača.
- **Posmatrati sav saobraćaj agenata**: svaki presretnuti zahtev se objavljuje u [Traffic Inspector](./TRAFFIC_INSPECTOR.md).
- **Primeniti otpornost OmniRoute-a**: kombinovano rutiranje, prekidači kola, rezervne varijante i praćenje troškova funkcionišu i za saobraćaj IDE agenata.

## §2 Архитектура

### 2.1 Преглед компоненти

```
IDE агент (VS Code / Cursor / итд.)
    │  HTTPS (порт 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS преусмеравање
    │
    ▼
src/mitm/server.cjs  (порт 443, CJS подређени процес)
    │  разрешава одредиште према SNI-ју из Host заглавља
    │  генерише TLS сертификат за сваки SNI, потписан AgentBridge CA сертификатом
    ├── Подударање са листом заобилажења? → TCP директно прослеђивање (без дешифровања)
    ├── Подударање са одредиштем? → fetch → OmniRoute рутер (порт 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() над телом/заглављима захтева
    │               ├── TrafficBuffer.push() — објављује у Инспектор саобраћаја
    │               └── fetchRouter() → /v1/chat/completions
    └── Нема подударања? → TCP директно прослеђивање (без дешифровања)
```

### 2.2 MITM сервер (`src/mitm/server.cjs`)

Основни MITM сервер ради као Node.js CJS подређени процес (да би се избегло преписивање постојеће CJS базе кода). Он:

- Ослушкује порт 443 (захтева привилегију или `authbind`/`setcap`)
- Прима CONNECT тунеле од оперативног система (преко DNS преусмеравања у `/etc/hosts`)
- Генерише TLS сертификате за сваки SNI, потписане AgentBridge CA сертификатом (`DATA_DIR/mitm/ca.crt`)
- Разрешава одредишног агента према Host заглављу преко регистра `targets/index.ts`
- Прослеђује TypeScript слоју руковаоца путем HTTP-а на `http://127.0.0.1:20128`

`TARGET_HOSTS` се учитава из `DATA_DIR/mitm/targets.json` (који `targets/index.ts` уписује при покретању), што омогућава динамичка ажурирања без поновног покретања CJS сервера.

> **Модел коренског CA сертификата (#6684).** Горе описани модел сертификата за сваки SNI, потписаног CA сертификатом,
> јесте постојани модел коренског CA сертификата додат у #6684 (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, који поново користи CA/leaf криптографију већ
> доказану за TPROXY у `src/mitm/tproxy/dynamicCert.ts`) — он замењује
> старији појединачни статички самопотписани leaf сертификат (`src/mitm/cert/generate.ts`, који је и даље
> ограничен само на antigravity хостове), на који указује постојање само пара `server.crt`/`server.key`
> на диску. **Понашање при миграцији**: нова инсталација (без претходног
> `server.crt`) аутоматски добија модел коренског CA сертификата; инсталација која већ
> верује старом статичком leaf сертификату наставља да га користи док оператер не постави
> `MITM_ROOT_CA_ENABLED=true` и поново покрене мост (`src/mitm/cert/migration.ts`
> је чиста функција одлучивања — поуздани MITM CA сертификат који може да потпише leaf сертификат за
> **било који** хост знатно је моћнији од старог leaf сертификата са фиксним SAN-ом, па се
> прелаз никада не обавља неприметно за инсталацију којој се већ верује). CA сертификат се инсталира
> у исту `omniroute-mitm.crt` позицију складишта поверења коју је користио стари leaf сертификат
> (`cert/install.ts::installCaCert`) — није потребно чишћење двоструког поверења.

### 2.3 Основа руковаоца (`src/mitm/handlers/base.ts`)

Сви руковаоци агената проширују `MitmHandlerBase`:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Заштићене помоћне методе: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Сваки руковалац позива `hookBufferStart()` пре проксирања и `hookBufferUpdate()` по завршетку. Ове методе додају `InterceptedRequest` уносе у `globalTrafficBuffer` (погледајте [Инспектор саобраћаја](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Регистар одредишта (`src/mitm/targets/`)

Сваки агент има декларативну датотеку одредишта:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Регистар (`targets/index.ts`) извози `ALL_TARGETS` и генерише `DATA_DIR/mitm/targets.json` при покретању.

### 2.5 Директно прослеђивање и листа заобилажења (`src/mitm/passthrough.ts`)

**Листа заобилажења** (проверава се прва и има предност над подударањем са одредиштем):

- Подразумевани обрасци: хостови банака, `.gov.`, OAuth/SSO добављачи (Okta, Auth0), итд.
- Кориснички обрасци: чувају се у табели базе података `agent_bridge_bypass`
- Заобиђени хостови добијају транспарентни TCP тунел — TLS се **никада не дешифрује**

**Подразумевано директно прослеђивање** (нема подударања са одредиштем и није на листи заобилажења):

- Такође добија TCP тунел — везе се никада не прекидају
- Спречава AgentBridge да омета општи системски HTTPS саобраћај

Приоритет рутирања:

```
листа заобилажења → подударање са одредиштем → директно прослеђивање
```

### 2.6 Узводни CA сертификат (`src/mitm/upstreamTrust.ts`)

За корпоративна мрежна окружења са прилагођеним CA сертификатом:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Када је постављено, конфигурише глобални диспечер пакета `undici` са додатним CA сертификатом, омогућавајући AgentBridge-у да приступи узводним добављачима преко корпоративних проксија за завршавање TLS-а.

### 2.7 Маскирање тајни (`src/mitm/maskSecrets.ts`)

Независни clean-room скенер примењује се на тела захтева и заглавља са акредитивима
**пре** него што уђу у бафер Инспектора саобраћаја или било који дневник. Он обавља један линеарни пролаз:

- Токени са префиксима `sk-` / `ak-` / `pk-` (у стилу OpenAI/Anthropic)
- RFC 6750 акредитиви `Authorization: Bearer <token>`, са приоритетом целог токена
- Генерички дуги непрозирни токени (≥40 знакова), укључујући облике са тачкама и допунама

`sanitizeHeaders()` претвара задржана имена у мала слова, детерминистички спаја вредности низова, одбацује
заједничку листу забрањених hop-by-hop/оквирних заглавља (укључујући прокси аутентификацију), у потпуности редигује `cookie` и
`set-cookie` и прослеђује вредности акредитива скенеру.

## §3 Подешавање

### 3.1 Покретање/заустављање MITM сервера

Користите картицу AgentBridge Server на `/dashboard/tools/agent-bridge`:

| Радња                          | Опис                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Покрени сервер                 | Покреће `src/mitm/server.cjs` на порту 443. У моделу са коренским CA сертификатом, при првом покретању креира `ca.crt` и поставља активни сертификат као поуздан када је доступна sudo лозинка                                                                                                                                                                                                                                             |
| Заустави сервер                | Контролисано зауставља подређени процес                                                                                                                                                                                                                                                                                                                                                                                                    |
| Поново покрени сервер          | Заустављање + покретање (примењује измене циља и поново генерисани сертификат)                                                                                                                                                                                                                                                                                                                                                             |
| Постави сертификат као поуздан | Инсталира активни сертификат у ОС складиште поузданих сертификата: `DATA_DIR/mitm/ca.crt` у моделу са коренским CA сертификатом, односно `DATA_DIR/mitm/server.crt` у застарелој инсталацији са крајњим сертификатом                                                                                                                                                                                                                       |
| Преузми сертификат             | Преузима активни сертификат ради ручне инсталације (`omniroute-mitm-ca.crt` = `ca.crt`, односно `omniroute-mitm.crt` = `server.crt` у застарелој инсталацији са крајњим сертификатом)                                                                                                                                                                                                                                                      |
| Поново генериши сертификат     | Никада не мења модел сертификата. Застарела инсталација са крајњим сертификатом: генерише нови `server.crt`/`server.key` (поново покрените сервер да би га користио). Модел са коренским CA сертификатом: ротира `ca.crt`/`ca.key`, што није дозвољено док сервер ради; стари поуздани CA се прво уклања из поузданих (захтева sudo лозинку), иначе се ротација отказује. Клијенти након тога морају поново да поставе нови CA као поуздан |

### 3.2 Постављање сертификата као поузданог

ОС мора сматрати AgentBridge CA сертификат поузданим пре него што IDE окружења прихвате MITM везу.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Или користите дугме „Trust Cert“ на контролној табли (покреће одговарајућу команду за ваш ОС, уз упит за sudo лозинку ако је потребна).

#### IDE окружења заснована на Electron-у игноришу ОС складиште поузданих сертификата (`NODE_EXTRA_CA_CERTS`)

Нека IDE окружења — нарочито **Antigravity IDE**, као и друге апликације изведене из Electron-а / VS Code-а — садрже
сопствено Node.js извршно окружење које **не користи ОС складиште поузданих сертификата** за одлазне
`fetch`/HTTPS захтеве. Постављање CA сертификата као поузданог на нивоу ОС-а/NSS-а довољно је за изворни **позадински систем**
IDE окружења (нпр. Go језички сервер, који користи ОС пакет CA сертификата), али ће **Electron кориснички интерфејс**
и даље пријављивати TLS грешку — то се испољава тако што апликација приказује да је корисник _одјављен_ или приказује _„грешку при повезивању“_,
иако MITM евиденција показује да почетни позиви позадинског система враћају `200`. Потребна су
два корака и оба су важна:

1. Експлицитно усмерите извршно окружење на CA сертификат:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **Покрените IDE из тог shell-а.** Покретање преко иконе на радној површини / Dock-а / Start менија
   **не** наслеђује shell извезене променљиве, а `~/.config/environment.d/*.conf` се примењује тек након
   новог графичког пријављивања. Најпре потпуно затворите IDE — Electron-ово закључавање једне инстанце значи да друго
   покретање само активира постојећи процес, а ново окружење се игнорише.

Претходно наведени корак са ОС поверењем + NSS-ом остаје неопходан (Chromium мрежни стек који користе неки токови
аутентификације чита NSS складиште корисника и има сопствена статичка причвршћивања сертификата за `*.googleapis.com`, која
локално поуздани CA замењује). `NODE_EXTRA_CA_CERTS` додатно покрива Node `fetch` путању.

### 3.3 DNS усмеравање

За сваког агента чији саобраћај желите да пресретнете, његов API хост или хостови морају да се разрешавају на `127.0.0.1`. AgentBridge аутоматски управља уносима у `/etc/hosts` када укључите или искључите DNS за агента у чаробњаку за подешавање.

Пример уноса у `/etc/hosts` за GitHub Copilot:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Мапирање модела

Користите табелу за мапирање модела на свакој картици агента да бисте дефинисали мапирања извор → циљ:

| Изворни модел (изворни модел агента) | Циљни модел (OmniRoute) |
| ------------------------------------ | ----------------------- |
| `gpt-4o`                             | `claude-sonnet-4.7`     |
| `*` (џокер)                          | `claude-haiku-4.7`      |

Џокер `*` мапира сваки непрепознати модел на наведени циљ. Чува се у табели `agent_bridge_mappings`.

> **Savet — otkrijte stvarne ID-ove modela agenta.** IDE može da šalje nazive modela koji se razlikuju od
> oznaka u njegovom korisničkom interfejsu i koji se menjaju između glavnih verzija. Na primer, **Antigravity 2** šalje
> `gemini-3.1-pro-low`, `gemini-pro-agent` i `gemini-3.1-flash-lite` preko mreže — a ne
> `gemini-2.5-pro` prikazan u starijoj dokumentaciji. Pošaljite jednu poruku bez odgovarajućeg mapiranja: MITM
> beleži tačnu dolaznu vrednost `model:` i prosleđuje zahtev. Mapirajte tu doslovnu vrednost, nakon čega
> će sledeći zahtev biti presretnut i usmeren ka vašem ciljnom modelu.

### 3.5 Obaveštenje o riziku

AgentBridge presreće akreditive (OAuth tokene, API ključeve) koje IDE koristi za autentifikaciju kod udaljenih pružalaca usluga. Oni se **maskiraju pre beleženja** (pogledajte §2.7), ali su vidljivi OmniRoute MITM sloju. Pri prvom aktiviranju svakog agenta prikazuje se modalni prozor sa obaveštenjem o riziku koji se može zatvoriti.

### 3.6 Održavanje i dijagnostika

Kontrolna tabla sadrži karticu **Održavanje i dijagnostika** (`AgentBridgeMaintenanceCard`, u `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`) koja prikazuje operativne MITM rute koje ranije nisu imale korisnički interfejs. Njen podnaslov glasi: _„Samostalno testirajte cevovod za presretanje, poništite zaostalo stanje sistema i prenesite podešavanje između računara.“_ Klijentske pomoćne funkcije kartice nalaze se u `src/lib/inspector/agentBridgeMaintenanceApi.ts`.

| Dugme                    | Ruta                                   | Šta radi                                                                                                                                                                                                              |
| ------------------------ | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Dijagnostikuj**        | `GET /api/tools/agent-bridge/diagnose` | Pokreće samotestiranje cevovoda za presretanje i prikazuje izveštaj za svaku proveru (✓/✗ + savet za rešavanje problema).                                                                                             |
| **Popravi**              | `POST /api/tools/agent-bridge/repair`  | Poništava napušteno stanje MITM sistema (DNS unosi za lažiranje, korenski CA, sistemski proksi) zaostalo nakon pada ili SIGKILL signala. Idempotentno — prikazuje „Nema ničega za popravku“ kada je stanje čisto.     |
| **Ukloni CA**            | `DELETE /api/tools/agent-bridge/cert`  | Opoziva poverenje i uklanja MITM korenski CA iz skladišta poverenja operativnog sistema (eksplicitno, idempotentno). Prikazuje se samo kada je CA trenutno pouzdan; zahteva potvrdu „Ukloniti CA?“ unutar interfejsa. |
| **Izvezi konfiguraciju** | `GET /api/tools/agent-bridge/config`   | Preuzima prenosivi konfiguracioni JSON (pogledajte §3.7).                                                                                                                                                             |
| **Uvezi konfiguraciju**  | `POST /api/tools/agent-bridge/config`  | Otpremа prethodno izvezeni konfiguracioni JSON (pogledajte §3.7).                                                                                                                                                     |

Svaka kartica agenta takođe ima sopstveno dugme **Vrati podrazumevano** (`POST
/api/tools/agent-bridge/agents/{id}/reset`) — poništavanje jednim klikom za pojedinačnog agenta koje uklanja lažiranje samo za hostove tog
agenta, briše njegova sačuvana mapiranja modela i resetuje njegovo stanje `dns_enabled`/`setup_completed`,
tako da IDE ponovo komunicira sa stvarnim udaljenim pružaocem nakon potpunog ponovnog pokretanja. Ono **ne** utiče na
deljeni MITM server ili korenski CA (drugi agenti možda i dalje zavise od njih) — oni ostaju dostupni
preko kartice servera i prethodno navedene radnje **Ukloni CA**. Na Windows-u takođe, po principu najboljeg napora, pokreće
`ipconfig /flushdns`, pošto Windows DNS Client kešira unose datoteke hosts i u suprotnom neće odbaciti
upravo uklonjeno lažiranje.

**Dijagnostičke provere** (`summarizeDiagnostics()` u `src/mitm/inspector/diagnostics.ts`). Ruta pokreće probu sa sporednim efektima za svaku proveru i prosleđuje logičke vrednosti čistom sumatoru; vraća se jedinstvena ocena `healthy` uz savet za svaki neuspeh:

| Naziv provere      | Šta proverava                                         | Savet u slučaju neuspeha                                                                                                                                   |
| ------------------ | ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | Proces MITM servera je aktivan                        | „MITM server nije pokrenut. Pokrenite ga sa kartice AgentBridge.“                                                                                          |
| `server-reachable` | MITM server prihvata veze na svom portu (TCP proba)   | „MITM server ne prihvata veze na svom portu. Proverite da li je port slobodan i da li imate dozvole da ga vežete.“                                         |
| `cert-exists`      | MITM sertifikat je generisan na disku                 | „MITM sertifikat još nije generisan. Generišite ga sa kartice AgentBridge.“                                                                                |
| `cert-trusted`     | MITM korenski CA se nalazi u skladištu poverenja OS-a | „Skladište OS-a ne smatra MITM korenski CA pouzdanim, pa TLS presretanje neće uspeti. Označite sertifikat kao pouzdan sa kartice AgentBridge.“             |
| `dns-configured`   | Ciljni nazivi hostova su lažirani u `/etc/hosts`      | „Ciljni nazivi hostova nisu lažirani u /etc/hosts, pa saobraćaj nikada ne stiže do proksija. Omogućite DNS za agente čiji saobraćaj želite da presrećete.“ |

**Baner napuštenog stanja:** kada stranica otkrije stanje zaostalo nakon pada (DNS lažiranje / CA / sistemski proksi), kartica prikazuje žuti baner — _„Prethodna sesija je ostavila sistemsko stanje (DNS lažiranje, CA ili sistemski proksi). Pokrenite Popravi da biste ga očistili.“_ — i ističe dugme **Popravi**. `Repair` je ekvivalent ProxyBridge zastavice `--cleanup` na nivou aplikacije (delegira poziv funkciji `repairMitm()` u `src/mitm/manager.ts`).

> Коренски CA за MITM остаје инсталиран након заустављања/покретања како би се избегли поновљени sudo
> упити (исто понашање као код mitmproxy/Charles), па је његово уклањање експлицитна радња
> **Уклони CA**, а не нешто што се аутоматски дешава при заустављању.

### 3.7 Преносиви увоз/извоз конфигурације

AgentBridge може да серијализује стање које **оператер може да подешава** у верзионисани JSON објекат како би подешавање могло да се реплицира на више рачунара. Серијализатор је `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), а валидација се обавља помоћу `AgentBridgeConfigSchema`.

Извоз обухвата тачно три ставке (уграђене подразумеване вредности се намерно **НЕ** извозе, тако да их увоз никада не дуплира нити долази у сукоб с њима):

| Поље             | Извор                                                                | Напомене                                                                 |
| ---------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `bypassPatterns` | кориснички дефинисани обрасци заобилажења (`agent_bridge_bypass`)    | подразумевани обрасци за банке/државне институције/Okta су изузети       |
| `customHosts`    | прилагођени хостови у Traffic Inspector-у (`inspector_custom_hosts`) | сваки: `{ host, kind: "llm"\|"app"\|"custom", label? }`                  |
| `agentMappings`  | мапирања модела по агенту (`agent_bridge_mappings`)                  | `{ [agentId]: [{ source, target }] }` за сваког агента који има мапирања |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Понашање при увозу** (`POST /api/tools/agent-bridge/config`): обрасци заобилажења и мапирања по агенту се **у потпуности замењују**; прилагођени хостови се додају **идемпотентно** (`INSERT OR IGNORE`). Одговор наводи колико је ставки сваког типа примењено:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Шта **НИЈЕ** у конфигурацији: стање покренутости сервера, путање сертификата, DNS стање по агенту, путања узводног CA сертификата и TPROXY подешавања — то је стање хоста/извршавања, а не преносиво корисничко подешавање.

## §5 Безбедност

### Примењена строга правила

| Правило                             | Примена                                                                                           |
| ----------------------------------- | ------------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`      | Све грешке обрађивача се чисте пре одговора или уписа у бафер                                     |
| **#13** Прослеђивање окружења љусци | Измене `/etc/hosts` користе опцију `env` — без интерполације путања у ниску                       |
| **#15 + #17** `isLocalOnlyPath()`   | `/api/tools/agent-bridge/` је LOCAL_ONLY + SPAWN_CAPABLE — loopback се намеће пре аутентификације |

### Листа заобилажења за осетљиве хостове

Листа заобилажења обезбеђује да се саобраћај финансијских институција, OAuth/SSO добављача и других осетљивих хостова **никада не дешифрује**. Њихов TLS саобраћај пролази као транспарентан TCP тунел — OmniRoute никада не види отворени текст.

Подразумевани обрасци заобилажења обухватају:

- `*.bank.*`, `*.gov.*` (финансије/државна управа)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/идентитет)
- `*.apple.com`, `*.icloud.com` (Apple системске услуге)

Обрасци заобилажења које дода корисник чувају се у табели `agent_bridge_bypass` и имају предност над свим осталим.

### Маскирање тајни

Примењује се `maskSecrets()` из `src/mitm/maskSecrets.ts`:

- На тело сваког захтева пре `TrafficBuffer.push()`
- На свако заглавље пре евидентирања или емитовања

Обрасци: токени са префиксом `sk-`/`ak-`/`pk-`, `Bearer` токени и генерички токени дужине ≥40 знакова.

### Узводни CA сертификат

Када је `AGENTBRIDGE_UPSTREAM_CA_CERT` подешен, датотека се чита при покретању. Ако путања постоји, али датотека није читљива, AgentBridge евидентира јасну грешку и одбија да се покрене (чиме се спречавају неприметни TLS кварови у корпоративним окружењима).

### Позната ограничења

- **Порт 443 захтева привилегије**: На Linux-у, AgentBridge захтева `setcap 'cap_net_bind_service=+ep'` над Node бинарном датотеком или покретање преко `authbind`. Чаробњак за подешавање приказује упутства специфична за оперативни систем.
- **Потребно је поновно покретање IDE-а**: Након DNS преусмеравања, IDE мора бити поново покренут да би ново разрешавање хоста ступило на снагу.
- **Хардкодовани OAuth токени**: Неки агенти (Kiro, Antigravity) локално чувају OAuth токене за освежавање. Они су транспарентни за AgentBridge — он види `Bearer` токен у сваком захтеву, који се маскира пре евидентирања.
- **Electron кориснички интерфејси захтевају `NODE_EXTRA_CA_CERTS`**: IDE-ови чији кориснички интерфејс ради у оквиру уграђеног Node/Electron окружења игноришу складиште поузданости ОС-а/NSS-а и морају бити покренути из љуске са подешеним `NODE_EXTRA_CA_CERTS` (погледајте §3.2). Симптом када недостаје: позадински систем IDE-а се аутентификује (MITM приказује одговоре `200`), али кориснички интерфејс остаје одјављен.
- **Више инсталација истог IDE-а су независне**: системска инсталација (нпр. `/usr/share/antigravity/antigravity`) и корисничка локална „Full“ инсталација (нпр. `~/AntigravityIDE_Full/antigravity-ide`) представљају засебне процесе са сопственим окружењима — сваки мора бити поново покренут са уметнутим CA сертификатом. Пре поновног покретања, утврдите која инсталација је активна на основу путање њене бинарне датотеке.
- **Идентитет одређује системски упит агента, а не усмерени модел**: када поново мапирате модел агента на другог добављача, одговор и даље наводи изворни идентитет агента (нпр. Antigravity одговара „Покреће ме Gemini“) зато што IDE то умеће у системски упит. Стварни позадински систем потврдите у `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`), а не тако што ћете питати модел ко је.

## §6 Решавање проблема

### Конфликт на порту 443

Ако неки други процес већ ослушкује порт 443 (веб-сервер, VPN итд.):

```bash
lsof -i :443          # пронађите процес
sudo fuser -k 443/tcp  # принудно заустављање (користите опрезно)
```

Алтернативно, у подешавањима AgentBridge-а конфигуришите непривилеговани порт и поставите правила за преусмеравање помоћу `iptables` / `pf`.

### Сертификат није поуздан

Ако IDE приказује TLS грешке након покретања AgentBridge-а:

1. Проверите да ли је сертификат инсталиран: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) или `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Неке апликације одржавају сопствено складиште поузданих сертификата (Firefox, Chrome на Linux-у). Поново покрените „Trust Cert“ и проверите складиште сертификата специфично за NSS/Firefox.
3. Поново покрените IDE након што означите сертификат као поуздан — активне TLS сесије користе претходно стање поверења.

### IDE је одјављен / „грешка при повезивању“ упркос поузданом CA сертификату

Симптом: након преусмеравања DNS-а и означавања CA сертификата као поузданог, IDE заснован на Electron-у (нпр. Antigravity)
отвара се у **одјављеном стању** или приказује грешку при аутентификацији/повезивању, иако MITM евиденција показује да
почетни позиви (`loadCodeAssist`, `fetchAvailableModels`, …) враћају `200`.

Узрок: **уграђено Node/Electron извршно окружење IDE-а игнорише системско складиште поузданих сертификата**. Изворни
позадински систем (сервер језика написан у Go-у) верује системском CA сертификату и успешно обавља аутентификацију, али Electron интерфејс
не верује — па кориснички интерфејс сматра да је ван мреже.

Решење (оба корака): извезите `NODE_EXTRA_CA_CERTS=<ca.crt>` **и поново покрените IDE из тог
окружења командне линије**, а не преко иконе на радној површини. Прво у потпуности затворите IDE — Electron-ово закључавање једне инстанце значи да
друго покретање само активира постојећи процес, док се ново окружење игнорише. Погледајте §3.2.
Ово одговара отвореном извештају у узводном пројекту у ком самостални агент ради преко MITM-а, али IDE
варијанта не ради са истим подешавањем.

### DNS промене нису пропагиране

Проверите да ли је `/etc/hosts` ажуриран:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

Испразните DNS кеш:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE није откривен

Аутоматско откривање користи уобичајене путање за инсталацију. Ако откривање не успе, али је IDE инсталиран:

- Проверите да ли се извршна датотека IDE-а налази на нестандардној локацији
- Чаробњак за подешавање и даље ради — неуспешно откривање само значи да значка неће приказати путању инсталације

### Грешке руковаоца (добављање од узводног сервиса не успева)

Ако AgentBridge пресреће захтеве, али сви захтеви не успевају:

1. Проверите да ли је бар један добављач повезан на `/dashboard/providers`
2. Проверите евиденцију OmniRoute сервера: `APP_LOG_LEVEL=debug` у `.env`
3. Проверите да ли `OMNIROUTE_BASE_URL` упућује на исправну крајњу тачку рутера (подразумевано: `http://127.0.0.1:20128`)

## §8 План развоја

### Истраживање алата Trae

Trae је релативно нов помоћник за програмирање заснован на вештачкој интелигенцији. Пре имплементације обрађивача:

1. Идентификујте бинарну датотеку/проширење на VS Code / JetBrains продавницама или као самосталну апликацију
2. Снимите саобраћај помоћу mitmproxy да бисте открили API хостове и структуре крајњих тачака
3. Утврдите механизам аутентификације
4. Процените да ли наставити или одустати на основу услова коришћења и могућности откривања API-ја

Док се истраживање не заврши, Trae картица на контролној табли приказује ознаку „Истраживање је у току“ са везом „Пријави одрживост“. Костур обрађивача у `src/mitm/handlers/trae.ts` пријављује структурирану грешку `Још није имплементирано`.

### Агенти у листи задатака (MITM је обавезан — нема подршке за прилагођени основни URL)

Следећи алати у својим тренутним верзијама не подржавају прилагођене основне URL-ове, због чега је MITM једини начин пресретања. Процена одрживости је на чекању:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — одвојено од Kiro IDE)
- **Cowork** (Anthropic десктоп апликација)

Напомена: GitHub Copilot CLI ≥v1.0.19 подржава `COPILOT_PROVIDER_BASE_URL` — за тај алат користите директну конфигурацију уместо MITM-а.
