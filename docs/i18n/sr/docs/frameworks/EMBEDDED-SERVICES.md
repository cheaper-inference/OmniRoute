Уграђени сервиси су локално инсталирани процесни алати које OmniRoute инсталира, надзире и излаже као првокласне циљеве рутирања. За разлику од спољних провајдера (до којих се долази преко интернета преко API кључева), уграђене услуге раде на истој машини као OmniRoute и комуницирају преко повратне петље.

### Управљана прокси језгра

Прилагођено поље хост проки сервера такође прихвата V2Ray изворну везу. Изаберите** синг-бок** или** Ксраи** експлицитно, а затим кликните на Сачувај. Куцање никада не преузима или покреће језгро. Сачувај верификује званичну архиву издања, потврђује изворну конфигурацију, покреће посебан локални хост SOCKS слушалац и тек онда уписује додељивање прокси регистра. Неуспела активација враћа претходну управљану конфигурацију и процес. `STORAGE_ENCRYPTION_KEY` је обавезан; изворне везе су шифроване.

Управљане датотеке живе под `DATA_DIR/services/managed-proxy/`, одвојено од TPROXY. Постоји један процес у власништву по изабраном језгру, до 100 слушалаца. Није промењено аутоматско покретање или глобално рутирање. Успешно чување памти активацију само за ово управљано језгро; Покретање апликације враћа омогућена сачувана језгра користећи већ верификовани бинарни фајл, никада преузимање током покретања. Експлицитно заустављање брише ту заставицу за активацију. Бинарни фајл који недостаје или је оштећен захтева поновно чување извора. Брисањем регистра се локално уклања извор и слушалац; обичне измене крајње тачке се одбијају за управљане редове, тако да сачувани извор не може тихо да одступи од свог преусмереног слушаоца.

| Изворни формат                          | синг-бок                                                              | Ксраи                                                                 |
| --------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------- |
| VLESS, VMess, тројанац, Схадовсоцкс URI | Подржана конверзија                                                   | Подржана конверзија                                                   |
| Hysteria2/hy2, TUIC, AnyTLS URI         | Подржана конверзија                                                   | Одбијено; користите компатибилно језгро                               |
| TCP/raw, WebSocket, gRPC, HTTPUpgrade   | Подржано за VLESS/VMess/Trojan                                        | Подржано за VLESS/VMess/Trojan                                        |
| XHTTP URI транспорт                     | Одбијено                                                              | Подржана конверзија                                                   |
| Нативе оутбоунд JSON                    | Дозвољени прокси protocols/options изабраног језгра, изворно проверен | Дозвољени прокси protocols/options изабраног језгра, изворно проверен |

Непознате жичне опције, несигурне TLS заставице, екстерни додаци, опције локалне путање датотека и неподржане комбинације се одбијају уместо тихо одбацују. Нативни објекти су излазне дефиниције, а не конфигурације целог језгра; control/direct/bypass излазе се не прихватају. WireGuard на синг-бок 1.14 користи крајње тачке, тако да није прихваћен као изворни излаз. Ово није конвертор свих формата; SSR, старе whole-base64 Схадовсоцкс везе, произвољни Цласх објекти и транспортне варијанте које одсутне у табели захтевају одвојено подржан изворни формат.

`/api/services/managed-proxy` је аутентификован и само за повратну петљу: GET наводи редиговане метаподатке, POST чува `{core,name,sourceLink,id?,assignment?}`, PATCH прихвата `{core,action:"start"|"stop"}`. Мора бити присутан хостов поуздани пеер-стамп пипелине. Дијагностика изворног језгра је потиснута јер може да садржи акредитиве; Догађаји животног циклуса користе постојећи структурирани програм за бележење датотека без изворних веза или упстреам корисних података. Приложите само дезинфициране евиденције апликација за подршку. Званичне верзије су закачене за синг-бок 1.14.3 и Ксраи 26.3.27 са манифестима SHA-256 -а за ослобађање; будућа ажурирања захтевају промену верзије и свих верификованих сажетака заједно.

## 2. Архитектура — 4 слоја

```
┌────────────────────────────────────────────────────────────────────┐
│  Layer 1 — UI                                                      │
│  /dashboard/providers/services  (tabs: CLIProxyAPI | 9Router | Mux)│
│  Logs live (SSE), Start/Stop/Restart/Update, Settings, Install     │
│                                                                    │
│  src/app/(dashboard)/dashboard/providers/services/                 │
│    ├── page.tsx               Shell + tab routing by ?tab=         │
│    ├── tabs/                  CliproxyServiceTab, NinerouterServiceTab,│
│    │                          MuxServiceTab                        │
│    └── components/            ServiceStatusCard, ServiceLifecycleButtons,│
│                               ServiceLogsPanel, ApiKeyCard, ...    │
└──────────────────────┬─────────────────────────────────────────────┘
                       │ HTTP (Next.js fetch)
┌──────────────────────▼─────────────────────────────────────────────┐
│  Layer 2 — API (LOCAL_ONLY — loopback only)                        │
│                                                                    │
│  /api/services/9router/{install|start|stop|restart|update|         │
│                          rotate-key|status|auto-start|logs}        │
│  /api/services/cliproxy/{install|start|stop|restart|update|        │
│                           status|auto-start|logs}                  │
│  /api/services/mux/{install|start|stop|restart|update|             │
│                      status|auto-start|logs}                       │
│  /dashboard/providers/services/9router/embed/[...path]             │
│    (reverse HTTP + WebSocket proxy → 9Router upstream)             │
│                                                                    │
│  Gate: LOCAL_ONLY_API_PREFIXES includes "/api/services/" and       │
│        "/dashboard/providers/services/*/embed/"                    │
└──────────────────────┬─────────────────────────────────────────────┘
                       │ in-process calls
┌──────────────────────▼─────────────────────────────────────────────┐
│  Layer 3 — ServiceSupervisor (src/lib/services/)                   │
│                                                                    │
│  ServiceSupervisor.ts   Generic supervisor (child_process.spawn)   │
│    ├── install:    execFile('npm', ['install', pkg, '--prefix'])    │
│    ├── start:      spawn(node, [entrypoint], {env, cwd})           │
│    ├── api_key:    crypto.randomBytes(32) → env NINEROUTER_API_KEY  │
│    ├── port:       20130 for 9Router (configurable)                │
│    ├── logs:       stdio ring buffer 5 MB → SSE events             │
│    ├── health:     HTTP GET /health every 2–5 s, lazy recovery     │
│    └── lifecycle:  SIGTERM 15 s → SIGKILL                          │
│                                                                    │
│  registry.ts        getSupervisor(name) / registerSupervisor()     │
│  bootstrap.ts       Bootstraps all SERVICES[] at process start     │
│  apiKey.ts          getOrCreateApiKey(), generateServiceApiKey()   │
│  modelSync.ts       Periodic GET /v1/models → service_models table │
│  ringBuffer.ts      Circular log buffer (5 MB per service)         │
│  healthCheck.ts     Polling HTTP health probe                      │
│  installers/        ninerouter.ts, cliproxy.ts, mux.ts, openwa.ts  │
│                      (installer adapters)                          │
└──────────────────────┬─────────────────────────────────────────────┘
                       │ OpenAI-compatible HTTP (loopback)
┌──────────────────────▼─────────────────────────────────────────────┐
│  Layer 4 — Provider / Routing                                      │
│                                                                    │
│  open-sse/executors/ninerouter.ts                                  │
│    Re-looks up port and API key per-request (no caching).          │
│    Strips "9router/" prefix from model id before proxying.         │
│    Returns 503 service_not_running if supervisor not in "running". │
│                                                                    │
│  src/shared/constants/providers.ts                                 │
│    Entry for "9router": isEmbeddedService: true                    │
│                                                                    │
│  open-sse/config/providerRegistry.ts                               │
│    Models stored as "9router/{sub}/{model}" (prefixed).            │
│    Synced every 5 min by modelSync.ts.                             │
│                                                                    │
│  Mux is lifecycle-managed ONLY (Layers 1-3) — it is an agent-       │
│  orchestration daemon, not an LLM proxy, so it has no Layer 4      │
│  executor/provider entry and is never a routing target.            │
└────────────────────────────────────────────────────────────────────┘
```

## 3. Машина стања животног циклуса

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
            провера здравља успешна │         пад / SIGTERM      │
                               ┌────▼─────┐  (излаз у року од 5 s)│
                               │ running  │──── пад ─────────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

Стања се чувају у DB табели `version_manager` (колона `status`) и пресликавају
у стање у меморији компоненте `ServiceSupervisor`. Стање у меморији је меродавно за
покренут процес; стање у DB-у је трајна резервна вредност при покретању система.

### Прелази стања

| Из              | Догађај                                       | У                      |
| --------------- | --------------------------------------------- | ---------------------- |
| `not_installed` | `install()` је успешно извршен                | `stopped`              |
| `stopped`       | `start()` је позван                           | `starting`             |
| `starting`      | провера здравља враћа 200                     | `running`              |
| `starting`      | процес се завршава пре него што постане здрав | `error`                |
| `running`       | `stop()` је позван                            | `stopping` → `stopped` |
| `running`       | процес се неочекивано завршава (< 5 s)        | `error` (брз пад)      |
| `running`       | процес се неочекивано завршава (> 5 s)        | `error`                |
| `error`         | `start()` је позван                           | `starting`             |
| било које       | `stop()` током стања `stopping`               | без операције          |

### Закључавање операција

`ServiceSupervisor` серијализује операције животног циклуса помоћу асинхроног закључавања операција
(`withLock()`). Истовремени позиви `start()` над истим надзорником доводе до тачно
једног покретања процеса; други позивалац чека и враћа постојећи статус. Ово спречава
услове трке када се, на пример, аутоматско покретање и дугме у UI-ју активирају истовремено.

### 4.8 синг-бок крајње тачке (8 рута)

синг-бок има исти облик крајње тачке као Мук — без `rotate-key` руте, без ињекције API кључа (`needsApiKey: false` у `bootstrap.ts`). Њиме се само управља животним циклусом: никада није routing/LLM провајдер. `install()` преузима званичну бинарну верзију GitHub (`SagerNet/sing-box`) за закачену верзију (`SINGBOX_PINNED_VERSION` у `src/lib/services/installers/singbox.ts`) и проверава свој SHA256 у односу на контролну суму упаковану у исту датотеку пре него што је икада запише на диск — било која друга захтевана верзија је одбијена.

| Метод  | Пут                                          | Опис                                                                           |
| ------ | -------------------------------------------- | ------------------------------------------------------------------------------ |
| `POST` | `/api/services/singbox/install`              | Преузмите + и проверите закачено издање синг-бок-а                             |
| `POST` | `/api/services/singbox/start`                | Покрени синг-бок (`sing-box run -c config.json`)                               |
| `POST` | `/api/services/singbox/stop`                 | Зауставите синг-бок                                                            |
| `POST` | `/api/services/singbox/restart`              | Поново покрените синг-бок                                                      |
| `POST` | `/api/services/singbox/update`               | Re-verify/reinstall закачено ослобађање                                        |
| `GET`  | `/api/services/singbox/status`               | Ливе + DB статус                                                               |
| `POST` | `/api/services/singbox/auto-start`           | Укључите аутоматско покретање                                                  |
| `POST` | `/api/services/singbox/auto-restart-adopted` | Укључите аутоматско поновно покретање за усвојени (претходно постојећи) процес |

**TPROXY ожичење:** `ensureSingboxTproxy()` (`src/mitm/tproxy/setup.ts`) уписује `config.json` и покреће супервизор пре него што `applyTproxy()` инсталира правила TPROXY заштитног зида. Ако супервизор недостаје или не успе да достигне `running`, он се сада евидентира на нивоу грешке (уместо да тихо прогута грешку) тако да оператер може да каже да су TPROXY правила примењена без радног слушаоца иза њих.

### 4.9 Обрнути прокси (уграђена контролна табла 9Роутер)

Контролна табла уграђује 9Роутер веб UI унутар ифраме-а преко интерног обрнутог проксија на:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

Овај прокси:

- Прослеђује захтев на `http://127.0.0.1:{port}/{path}` (само повратна петља)
- Уклања долазна `cookie` и `authorization` заглавља (без цурења OmniRoute сесије)
- Убацује `Authorization: Bearer {apiKey}` за 9Роутер аутентификацију
- Скида `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` из одговора
- Преписује HTML одговоре да би убацио `<base href>` и нормализовао апсолутне путање (`/foo` → `/dashboard/.../embed/foo`)

WebSocket надоградњом за уграђену контролну таблу управља пратећи сервер на наменском порту (погледајте `src/lib/services/embedWsProxy.ts`).

**безбедност:** Уграђене проки руте су класификоване под `LOCAL_ONLY_API_PREFIXES` и до њих се може доћи само из повратне петље. Нападач који добије JWT преко Cloudflare/Ngrok тунела не може да користи прокси у уграђене услуге.

## 5. Безбедност

### Спровођење правила LOCAL_ONLY (строго правило #17)

Све руте под `/api/services/` и `/dashboard/providers/services/*/embed/`
класификоване су као LOCAL_ONLY у `src/server/authz/routeGuard.ts`. Провера повратне петље
извршава се безусловно пре било које гране аутентификације:

```
захтев стиже
  → isLocalOnlyPath(path)?
      → није повратна петља → 403 LOCAL_ONLY (увек, пре провере аутентификације)
      → повратна петља      → настави са уобичајеном аутентификацијом
```

Ово спречава да процурели JWT (нпр. преко тунела) покрене `npm install` или
стварање процеса. Погледајте `docs/security/ROUTE_GUARD_TIERS.md` за потпуну матрицу
нивоа.

### Уметање API кључа

9Router и Mux захтевају API кључ/носилачки токен за сопствене HTTP крајње тачке.
OmniRoute:

1. Генерише кључ помоћу `crypto.randomBytes(32).toString("base64url")` са
   префиксом специфичним за сервис (`nr_` за 9Router, `mx_` за Mux).
2. Шифрује га при складиштењу користећи AES-256-GCM (исту шифру која се користи за акредитиве добављача).
3. Дешифрује га и умеће као променљиву окружења при покретању —
   `NINEROUTER_API_KEY` за 9Router, `MUX_SERVER_AUTH_TOKEN` за Mux (никада као CLI
   опцију, тако да се токен никада не појављује у `ps`/листама процеса).
4. Никада не враћа кључ у облику обичног текста ни у једном HTTP одговору.

CLIProxyAPI добија наменски кључ равни података који се умеће при покретању
(`needsApiKey: true` — користи се за синхронизацију модела са адаптером).

### Заштита од SSRF-а

Обрнути HTTP прокси (`/dashboard/.../embed/[...path]`) строго је подешен да прослеђује
само на `http://127.0.0.1:{port}`. Никада не прати преусмеравања ка одредиштима која
нису у повратној петљи. Библиотека `ssrf-req-filter` користи се за одбијање сваког
узводног URL-а који се разрешава ван опсега повратне петље.

### Безбедност љуске (строго правило #13)

`npm install` се позива преко `execFile('npm', ['install', pkg, '--prefix', dir])` —
без шаблонских литерала, без љуске и без интерполације спољних путања у ниску
команде. Вредности током извршавања (портови, API кључеви) прослеђују се преко `env` објекта подређеног процеса.

### Санитизација грешака (строго правило #12)

Сви одговори о грешкама из `/api/services/*` пролазе кроз `buildErrorBody()` или
`sanitizeErrorMessage()`. Необрађени `err.stack` и `err.message` никада се не враћају
дословно позиваоцу.

## 7. Решавање проблема

### Сервис се не покреће

**Симптоми:** Дугме за покретање враћа 503, а стање остаје `"error"` или `"starting"`.

**Контролна листа:**

1. Проверите `GET /api/services/{name}/logs` (или панел Logs на контролној табли). Потражите
   редове као што су `Error: ENOENT`, `address already in use` или `Cannot find module`.
2. Проверите да ли је `npm` у PATH-у: покрените `which npm` са истог корисничког налога под којим се извршава OmniRoute.
3. Проверите да ли је сервис инсталиран: у одговору `GET /api/services/{name}/status`
   проверите `installedVersion`. Ако је `null`, прво покрените инсталацију.
4. Проверите да ли `DATA_DIR/services/{name}/node_modules/` постоји и није празан.
5. У одговору о статусу проверите поље `lastError` за пречишћени разлог прекида рада.

---

### Хладно покретање је споро (> 10 s до достизања стања `running`)

**Симптоми:** Стање дуго остаје `"starting"` пре него што пређе у `"running"` или `"error"`.

**Објашњење:** Хладно покретање 9Router-а обухвата увоз великих стабала зависности (DNS,
тунелски и MITM модули). Подразумевани интервал провере стања је 2 s, са 3 покушаја пре него што
надзорник прогласи истек времена (али наставља са проверама).

**Решење:** Временско ограничење за `healthIntervalMs` и `waitForHealthy`
(`healthIntervalMs * 3`) може се конфигурисати у `bootstrap.ts`. За сервисе којима је потребно више
времена за покретање, повећајте `healthIntervalMs` на 5000 и `stopTimeoutMs` на 30 000.

---

### Сукоб портова (`EADDRINUSE`)

**Симптоми:** Евиденција приказује `address already in use :::20130`.

**Узроци:**

- Други процес већ користи порт 20130.
- Претходни процес 9Router-а није у потпуности заустављен (зомби PID).

**Решење:**

1. Промените подразумевани порт помоћу променљиве окружења `NINEROUTER_PORT` у датотеци `.env`.
2. Пронађите и прекините конфликтни процес: `lsof -ti :20130 | xargs kill -9`.
3. Порт се може конфигурисати за сваки сервис у `bootstrap.ts` путем поља `port`.

**Напомена:** 9Router подразумевано користи порт 20130 како би се избегло преклапање са
подразумеваним портом 20128 који користи OmniRoute.

---

### Дозвола одбијена (EACCES) током инсталације

**Симптоми:** Инсталација враћа 500, а евиденција приказује `EACCES` или `permission denied`.

**Узроци:**

- OmniRoute процес нема дозволу за упис у `DATA_DIR` или његов надређени директоријум.
- Извршавање у Docker-у без root привилегија и без приступа за упис у мапирани волумен.

**Решење:**

1. Проверите `DATA_DIR` (подразумевано: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. Уверите се да је корисник под којим се извршава OmniRoute власник директоријума: `chown -R $USER ~/.omniroute/`
3. У Docker-у се уверите да монтирани волумен има одговарајуће дозволе за корисника контејнера.

---

### Ажурирање не успева (истек времена за `npm install` или мрежна грешка)

**Симптоми:** Ажурирање враћа 500 са `InstallError`, а евиденција приказује истек мрежног времена.

**Контролна листа:**

1. Потврдите да је npm регистар доступан: `npm ping`.
2. Проверите да ли се користи корпоративни proxy: `npm config get proxy`, `npm config get https-proxy`.
3. Покушајте ручну инсталацију: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. Ако сте у окружењу без приступа мрежи, унапред преузмите tarball и употребите `npm install /path/to/tarball.tgz`.

---

### Сервис приказује стање `"error"` одмах након покретања (брзи пад)

**Симптоми:** Стање прелази из `"starting"` у `"error"` за мање од 5 секунди.
`lastError` приказује `"Fast crash (exited with code 1)"`.

**Контролна листа:**

1. Прочитајте цео завршни део евиденције: `GET /api/services/{name}/logs?tail=500`.
2. Чест узрок: недостају променљиве окружења које сервис очекује.
3. За 9Router: проверите да ли су `NINEROUTER_DISABLE_MITM=true` и
   `NINEROUTER_DISABLE_TUNNEL=true` у окружењу прослеђеном приликом покретања процеса (погледајте
   `installers/ninerouter.ts` `resolveSpawnArgs`).

## 8. Честа питања

**П: Могу ли да изложим крајње тачке уграђених сервиса клијентима који не користе loopback?**

Не. Ниво LOCAL_ONLY је намеран (строго правило #17). Руте које могу да покрену
`npm install` или `node` процесе не смеју бити доступне саобраћају који не долази преко loopback-а,
јер би процурели JWT преко тунела (Cloudflare, Ngrok, Tailscale) у супротном
омогућио произвољно покретање процеса. Не постоји изузетак за
`/api/services/` — за разлику од `/api/mcp/`, он је искључен са листе заобилажења
manage опсега. Погледајте `docs/security/ROUTE_GUARD_TIERS.md`.

---

**П: Да ли ће 9Router и CLIProxyAPI бити доступни у продукционим/cloud окружењима?**

Да. Оба сервиса прате исти local-first модел као и сам OmniRoute. Покрећу се
на истој машини и комуницирају преко loopback-а. „Продукција“ овде означава VPS
или локални сервер на којем је OmniRoute постављен, а не удаљеног cloud провајдера.

**П: Како да отклоним грешке у супервизору?**

1. Пратите SSE ток логова: `curl -N http://localhost:20128/api/services/9router/logs`.
2. Проверите структуриране логове у OmniRoute pino излазу филтриране према
   простору имена `service:supervisor`.
3. Прегледајте ред у бази података: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. Користите `GET /api/services/9router/status` да бисте у једном позиву видели тренутно активно стање, PID, здравствено стање
   и `lastError`.

---

**П: Супервизор приказује `health: "degraded"` или `health: "unknown"`, али је стање `"running"`. Да ли је то проблем?**

`"degraded"` значи да је здравствена провера вратила одговор који није 200. `"unknown"` значи да
ниједна провера још није завршена (истовремено извршавање са првим циклусом провере). Оба стања су пролазна током покретања.
Ако здравствено стање остане `"degraded"` дуже од `healthIntervalMs * 3` ms након
стања `"running"`, уграђени сервис је покренут, али његов HTTP API не одговара. Проверите
да ли је порт у одговору о статусу исправан и да ли сервис заиста
ослушкује на том порту.

---

**П: Могу ли да променим 9Router API кључ без потпуног поновног покретања?**

Не. API кључ се прослеђује сервису 9Router путем променљиве окружења у тренутку покретања процеса.
Променљиве окружења се не могу мењати у процесу који је већ покренут. `POST .../rotate-key`
аутоматски зауставља и поново покреће сервис како би применио нови кључ. Ротација кључа
ступа на снагу унутар вредности `stopTimeoutMs` сервиса (подразумевано 15 s), увећане за време
његовог покретања.

---

**П: Које је ограничење кружног бафера и шта се дешава када се попуни?**

Сваки сервис има наменски кружни бафер од 5 MB. Када се бафер попуни, најстарији
редови логова се уклањају како би се ослободио простор за нове. SSE догађај `snapshot` враћа
најновије редове унутар ограничења `tail`. Логови се не чувају трајно на диску осим ако
`logsBufferPath` није подешен у реду базе података.
