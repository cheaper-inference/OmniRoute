## Аутоматско рутирање без конфигурације (`auto/` префикс)

Није потребно креирање комбинације. Користите `auto` или `auto/` варијанту директно у свом клијенту.

### Брзи примери

| Модел ID            | Понашање                                                                                                                                      |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Модели прихватљивих добављача, LKGP стратегија и уравнотежене тежине                                                                          |
| `auto/coding`       | Пондери квалитета на првом месту за задатке кодирања                                                                                          |
| `auto/fast`         | Погодује мањем кашњењу и здравим добављачима                                                                                                  |
| `auto/cheap`        | Пондери за уштеду трошкова: фаворизују ниже каталошке цене; задржава LKGP лепљивост, а не строгу врсту најјефтиније                           |
| `auto/subscription` | Само квота укључена у план, потврђено уживо; празан базен враћа HTTP 503, никада наплаћени резервни                                           |
| `auto/thrifty`      | претплата → без кључа → бесплатно → јефтино → премиум, једна по једна степеница; може наплатити                                               |
| `auto/offline`      | Фаворизира доступност квота и здравље провајдера (`offline-friendly` пакет); не офлајн закључивање — захтеви и даље иду удаљеним провајдерима |
| `auto/smart`        | Пондери квалитета на првом месту са стопом истраживања од 10%.                                                                                |
| `auto/lkgp`         | Експлицитно LKGP, са истим тежинама као подразумевани `auto`                                                                                  |
| `auto/chaos`        | Паралелни панел са једним моделом по добављачу, до пет подразумевано, враћа један одговор                                                     |

Варијанте тежине задржавају LKGP лепљивост, тако да `fast` и `cheap` изражавају преференције уместо да гарантују најниже кашњење или цену за сваки захтев. `auto/chaos` обавља више упстреам позива. `auto/thrifty` може користити плаћени капацитет; повратак на квоту плана зависи од обновљене подобности и хлађења везе, а не само од времена ресетовања. Погледајте [Рутирање на првом месту за претплату](./SUBSCRIPTION_LADDER.md).

### Категорија × Ниво састав (`auto/<category>:<tier>`)

Одвојени суфикси у стилу ОпенРоутер-а** какав пут** (категорија) из** како га оптимизовати** (ниво), тако да их можете слободно саставити (#4235 фаза Б, `open-sse/services/autoCombo/suffixComposition.ts`):

- **Категорије** : `coding` · `reasoning` · `vision` · `chat` · `multimodal`. `vision`/`multimodal` задржавају моделе који могу да виде; `reasoning` задржава reasoning/thinking моделе. `coding` и `chat` не додају филтер могућности. Категорије које нису у ћаскању бирају пондере на првом месту пре било каквог заобилажења нивоа.
- **Тиерс** (изаберите бодовне тежине / филтер базена): `fast` (брз брод) · `cheap` (псеудоним `floor`, уштеда трошкова) · `reliable` (стабилност кашњења + здравља прекидача) · `free` / `pro` (филтрирајте скуп према нивоу модела преко `classifyTier` — слободног нивоа у односу на премиум). `subscription` и `thrifty` примењују [лествицу претплате](./SUBSCRIPTION_LADDER.md) засновану на вези.

| Пример                 | Одлучује да                                                               |
| ---------------------- | ------------------------------------------------------------------------- |
| `auto/coding:fast`     | прихватљив скуп, пондери ниске латенције                                  |
| `auto/coding:cheap`    | квалификовани скуп, тежине за уштеду трошкова (алиас `auto/coding:floor`) |
| `auto/reasoning:pro`   | Само reasoning/thinking модели, премиум ниво                              |
| `auto/vision`          | модели са могућношћу вида са тежином на првом месту                       |
| `auto/multimodal:free` | модели са мултимодалном способношћу, само бесплатни ниво                  |

Било који важећи `auto/<category>[:<tier>]` се решава на захтев; одабрани подскуп се оглашава у `/v1/models` и на контролној табли (`AUTO_SUFFIX_VARIANTS` у `open-sse/services/autoCombo/builtinCatalog.ts`). Category/tier филтрирање је** неуспешно затворено подразумевано** : ако се ниједан модел који испуњава услове не подудара, виртуелна комбинација има празан скуп и разрешивач ћаскања враћа HTTP 503 (`src/sse/handlers/chatHelpers.ts`). Филтер је `narrowPoolByCategoryTier` у `open-sse/services/autoCombo/virtualFactory.ts`.

`OMNIROUTE_AUTO_FREE_FALLBACK_TO_FULL_POOL=true` враћа застарели category/tier резервни део у пуни скуп када филтер не одговара ничему; ово може одбацити захтевани ниво или ограничење способности. Филтери породице модела никада не користе ту резервну опцију, а рутирање само на основу претплате и даље захтева верификовани капацитет који је укључен у план.

> **Интелигенција модела уживо:** ауто-роутинг фитнес се информише уживо** Арена ELO** ранкингс +** модели.дев** подаци о нивоу када је `ARENA_ELO_SYNC_ENABLED` заставица укључена (иначе се враћа на статичку мапу фитнеса).

**Како користити:**

```bash
# Any IDE or CLI tool that supports OpenAI format
Base URL: http://localhost:20128/v1
API Key:  <your-endpoint-key>

# In your code/config, set model to:
model: "auto"                 # balanced default
model: "auto/coding"          # favor coding task fit
model: "auto/fast"            # favor lower latency
model: "auto/cheap"           # favor lower catalog cost
```

**Шта се дешава:**

1. OmniRoute открива `auto/` префикс у `src/sse/handlers/chat.ts`
2. Све упите** активне везе провајдера** из базе података
3. Примењује филтере акредитива, видљивости модела и квалификованости
4. Прави логичке provider/model кандидате од доступних модела, чувајући квалификоване листе дозвољених налога за слање
5. Гради а** виртуелна комбинација** у меморији (није ускладиштено у DB)
6. Руте које користе профил тежине изабране варијанте + LKGP стратегију

**Кључна својства:**

- ✅** Увек укључено:** Нема пребацивања, нема креирања комбинације, није потребна конфигурација
- ✅** динамички:** Аутоматски одражава тренутне повезане провајдере
- ✅** Лепљивост сесије:** LKGP осигурава да је последњи успешни провајдер приоритет
- ✅** Свесни више налога:** Логички provider/model кандидати задржавају листе дозвољених налога који испуњавају услове
- ✅** Није потребна сачувана комбинација:** Виртуелна конфигурација остаје у меморији; нормална метрика рутирања и стање у току рада могу и даље да постоје

### Контрола кандидата по кључу (#7819, ниво 1 + 2)

`GET /v1/auto-combo/{channel}/candidates` (`{channel}` = суфикс после `auto/`, или буквално `auto` за основни канал) је** само за читање** крајња тачка која наводи тренутну групу кандидата `auto/*` канала украшену доступношћу уживо, поново користећи постојећа читања отпорности (никада сирови прекидач `state`):

- провајдерски прекидач — `getCircuitBreaker(provider).getStatus()` / `.canExecute()`
- хлађење везе — `rateLimitedUntil` / `testStatus` на решеном реду `provider_connections`
- модел лоцкоут — `isModelLocked(provider, connectionId, model)`

Сваки кандидат такође носи `excluded` заставицу овог API кључа. Изузимања се чувају по кључу АПИ-ја (`auto_candidate_overrides` табела, миграција `128`) — OmniRoute је један закупац без `users` табеле, тако да је `apiKeyId` најближи стварни идентитет по позиваоцу — и примењује се на пригушној тачки групе кандидата у `open-sse/services/autoCombo/virtualFactory.ts` преко чистог, јединично тестираног `filterExcludedCandidates()` (`open-sse/services/autoCombo/candidateOverrides.ts`). Филтер је** неуспешно отварање** : поништени apiKeyId/channel или DB неуспех при тражењу остављају базен нефилтриран, тако да оператор без конфигурисаних надјачавања види рутирање идентично бајту пре ове функције.

**Одложено на накнадни проблем:** по-кандидату + експлицитно наручивање (Ниво 3 — се уноси у постојеће путање стратегије weighted/priority ) и причвршћивање специфичне `combo.ts` стратегије по `auto/*` каналу (Ниво 4). Погледајте #7819 план за отворено питање о томе да ли заобилажења треба да остану по-АПИ-кључу или да постану глобална с обзиром на модел са једним закупцем.

**Иза кулиса:**

```txt
Request: { model: "auto/coding" }
   ↓
src/sse/handlers/chat.ts detects prefix
   ↓
createVirtualAutoCombo('coding') → candidatePool from active connections
   ↓
handleComboChat (same engine as persisted combos)
   ↓
Auto-scoring selects best provider/model per request
```

**Фајлови имплементације:**

| Филе                                                      | Сврха                                             |
| --------------------------------------------------------- | ------------------------------------------------- |
| `open-sse/services/autoCombo/autoPrefix.ts`               | Парсер префикса (`parseAutoPrefix`)               |
| `open-sse/services/autoCombo/virtualFactory.ts`           | Креира виртуелне `AutoComboConfig` објекте        |
| `open-sse/services/autoCombo/providerRegistryAccessor.ts` | Тест кука за исмевање регистра добављача          |
| `src/sse/handlers/chat.ts`                                | Интеграција: кратки спој са аутоматским префиксом |
| `src/shared/constants/providers.ts`                       | унос система `SYSTEM_PROVIDERS.auto`              |

## Подешавања налога за сачуване аутоматске комбинације

Интелигентни аутоматски уређивач нуди опцију** Подешавања налога** одељак. Свака веза може бити Преферирана, Нормална (подразумевана), Резервисана или Изузета. Више веза може да дели ниво. Аутоматски бира унутар првог квалификованог нивоа, задржавајући своје scoring/router понашање тамо; неуспели покушаји падају на преостале конкретне рачуне, пожељније пре нормалног пре резерве. Ова комбинација никада не користи изузете везе.

Подешавање је сачувано као `config.accountPreferences`, укуцано везом ID:

```json
{
  "accountPreferences": {
    "connection-a": "preferred",
    "connection-b": "preferred",
    "connection-c": "reserve",
    "connection-d": "excluded"
  }
}
```

Изостављена или празна мапа задржава постојеће руте. Подешавања не омогућавају онемогућене везе, не одобравају приступ АПИ кључу, враћају кандидате блокиране квотом или заобилазе провере буџета. Сваки покушај је ограничен на његову конкретну везу, тако да резервни налог не може да прескочи нивое иза комбинованог рутера. Постојећи афинитет сесије може задржати налог који испуњава услове; искључивање налога везаног за изворни окрет зауставља тај окрет уместо тихе промене налога.

Конфигурисана подешавања користе аутоматску путању која је свесна налога: невезани контекстни кеш, паметни цевовод, хаос и пречице у сенци се не шаљу. Шпекулативно хеџинг је онемогућен за ове захтеве тако да резервни рачуни не могу да се такмиче са преферираним. Друге комбиноване стратегије не тумаче ову поставку. Промена комбинације са Аутоматског задржава сачуване поставке за каснији повратак.

## Комбинована имена која одговарају стварном ИД-у модела

Комбинација чији је `name` идентичан ИД-у голог модела (нпр. комбинација под називом `gpt-5.5`) је** намерни, подржани образац** , није грешка: то је механизам за замену провајдера по моделу ИД документован у [#6940](https://github.com/cheaper-inference/OmniRoute/issues/6940). Пошто се комбинована резолуција проверава пре резолуције ИД-а голог модела (`getComboForModel()` у `src/sse/services/model.ts`), захтев за голим ИД-ом `gpt-5.5` се усмерава кроз циљеве комбинације (нпр. `acme-responses/gpt-5.5`, `backup-responses/gpt-5.5`) уместо директно до једног провајдера — ово поново користи цомбо-бефоре-реврите приоритет [/#3233 изграђен за #3227,](https://github.com/cheaper-inference/OmniRoute/issues/3227) а `tests/unit/combo-name-codex-responses-rewrite.test.ts` `tests/unit/responses-combo-resolution-3227.test.ts`.

Креирање или преименовање комбинације у име које засењује прави ИД модела** никад одбијена** — то би прекинуло овај документовани ток посла. Уместо (#8530), `POST /api/combos` и `PUT /api/combos/[id]` прилажу неблокирајуће `warning` поље одговору када се (ново) име сукоби са стварним ИД-ом модела:

```json
{ "warning": { "code": "COMBO_NAME_SHADOWS_MODEL", "modelId": "gpt-5.5", "providerId": "openai" } }
```

Приликом покретања, `scanComboModelNameCollisionsAtBoot()` (`src/instrumentation-node.ts`) такође бележи `[STARTUP]` упозорење у једном реду набрајајући сваку постојећу комбинацију која сенчи ид модела, тако да оператери који су случајно погодили ово (а не намерно, по #6940) имају сигнал. Помоћник за откривање живи у `src/lib/combos/modelNameCollision.ts`.

## Позивање прилагођене комбинације од клијента

Трајне комбинације (Подешавања → Цомбос) се користе само када клијент пошаље комбинацију** тачно име** у пољу `model` — нема нејасног или делимичног подударања имена комбинације, нити укључен префикс `auto/`. Редослед резолуције (`getComboForModel()` у `src/sse/services/model.ts`):

1. тачно подударање имена комбинације (`model: "my-combo"`),
2. `combo/<name>` префикс (`model: "combo/my-combo"`),
3. модел → цомбо глоб пресликавања (`/api/model-combo-mappings`).

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"my-combo","messages":[{"role":"user","content":"Hello"}]}'
```

Две уобичајене замке:

- **`auto` не користи ваше комбинације.** `auto`/`auto/*` прави сопствени скуп кандидата са нултом конфигурацијом и консултује трајне комбинације само ако је комбинација буквално названа `auto` (не препоручује се). За рутирање кроз комбинацију, пошаљите њено тачно име — не `auto`.
- **`openrouter/auto` је стварно плаћени OpenRouter производ** („Аутоматско најбоље доступно“), а не OmniRoute алиас. То је јединствени статички модел уноса OpenRouter регистра (`open-sse/config/providers/registry/openrouter/index.ts`) и посебно се наплаћује. Користите Подешавања → Роутинг → Сакриј плаћене моделе да бисте га искључили из `auto` скупова.

Погледајте [#7992](https://github.com/cheaper-inference/OmniRoute/issues/7992) и [#7111](https://github.com/cheaper-inference/OmniRoute/issues/7111) за оригиналну конфузију у овим документима.

## Како то функционише (сталне аутоматске комбинације)

Ауто-Цомбо Енгине динамички бодује provider/model кандидате користећи** 16 декларисаних фактора** (дефинисано у `open-sse/services/autoCombo/scoring.ts` → `DEFAULT_WEIGHTS`). Подразумеване тежине сума је `1.0`; прилагођене тежине су ренормализоване помоћу `normalizeScoringWeights()`. Три фактора подразумевано имају нулту тежину: `cacheAffinity`, `resetWindowAffinity` и `reliability`. Пакети режима дају `reliability` тежину `0.03`, или `0.04` у `reliability-first`; `quality` подразумевано носи `0.03` и у `quality-first` и `0.02` у другим пакетима. `cacheAffinity` такође омогућава дедупликацију промптне кеш меморије ван пондерисаног резултата.

`quality` трацкер у меморији (`open-sse/services/routing/quality.ts`) је празан након хладног поновног покретања, тако да сваки кандидат добије неутралан `0.5` све док не пристану прва запажања.

> **Нечитљива квота (#15347).** Када провајдер има алат за преузимање квоте, али не враћа ништа читљиво (неуспешно преузимање, недостајући акредитиви, коришћење само поруке или неисправан снимак без `windows` који се може анализирати и без коначног `percentUsed`, укључујући `percentUsed: null`), кандидат даје `0` на `quota` оси и његов коначни резултат се множи са `UNREADABLE_QUOTA_SOFT_DEPRIORITIZE_FACTOR` зк0.5, `autoStrategy.ts` исти образац. као казна статуса везе. Неуспешно очитавање употребе је доказ о телеметрији, а не о провајдеру, тако да је рангирано стриктно испод сваког стварног очитавања, укључујући потврђено 100%-used, али никада није тешко блокирано или избачено. Провајдер без ограничења пријављује `unlimited: true` и оцењује као пуну квоту; провајдер без регистрованог преузимача квоте уопште нема извор телеметрије и задржава подразумевану вредност `100`.

**збир:** `0.1429 + 0.1605 + 0.1429 + 0.1143 + 0.0762 + (7 × 0.0476) + 0.00 + 0.00 + 0.03 + 0.00 = 1.0` као што је декларисано у `DEFAULT_WEIGHTS`; Кориснички конфигурисане тежине се ренормализују у дистрибуцију помоћу `normalizeScoringWeights()` пре оцењивања.

## Пакети режима

- **Пакети садрже `quality` и `reliability`** (`quality 0.02`, `quality-first 0.03`; `reliability 0.03`, `reliability-first 0.04`) и у потпуности замењују мапу тежина (`weights = pack`, није спајање). `DEFAULT_WEIGHTS` садржи `quality 0.03 / reliability 0`; избор `balanced`/`default` задржава те подразумеване вредности, док избор пакета користи горенаведене вредности тог пакета. У почетном скупу (још увек нема запажања, па је `quality 0.5`, а `reliability 1`) ова два фактора додају `+0.04` у оквиру генеричког пакета (`0.03 + 0.01`), `+0.045` у оквиру `quality-first` и `+0.05` у оквиру `reliability-first`.
- `tierAffinity`, `specificityMatch` и `resetWindowAffinity` су изричито постављени на `0` у сваком пакету.
- Кратак преглед нагласка сваког пакета:
  - **ship-fast** → latencyInv 0.3048 + health 0.2667 (здраве везе са малим кашњењем)
  - **cost-saver** → costInv 0.3324 (најјефтинији токени побеђују)
  - **quality-first** → taskFit 0.3524 + stability 0.1429 + quality 0.03, највише међу свим пакетима (најбољи модел за задатак, доследан)
  - **offline-friendly** → quota 0.3324 + health 0.2667 (максимална резерва без обзира на брзину/цену)
  - **reliability-first** → health 0.3524 + stability 0.1905 + reliability 0.04, највише међу свим пакетима (најмање изненађења)
  - **chaos-mode** → health 0.4000 + taskFit 0.1905 (пакет тежина који `auto/chaos` додељује члановима свог панела; паралелно распоређивање не чита ове тежине и ово није профил за убризгавање грешака, погледајте [CHAOS-MODE.md](../guides/CHAOS-MODE.md#autochaos-parallel-fan-out))

комбинације. Она се примењују само на стратегију `auto` и само на захтев
који их садржи; сачуване вредности `modePack`/`budgetCap`/`budgetFallback` комбинације користе се
када заглавље није присутно.

# Принудно користи најбржи профил, ограничи овај захтев на $0.05 и строго блокирај уместо прекорачења трошкова

разрешене вредности прослеђују се постојећим улазима механизма `config.modePack` / `config.budgetCap` /
`config.budgetFallback`. Сачувана вредност `config.budgetFallback` комбинације ("strict" |
"cheapest") поставља трајну смерницу; заглавље је замењује за један захтев.

## Све стратегије рутирања

OmniRoute-ов комбиновани мотор подржава** 22 стратегије рутирања** (декларисано у `src/shared/constants/routingStrategies.ts` → `ROUTING_STRATEGY_VALUES`). Сам Ауто Цомбо мотор је изложен под `auto` стратегијом; остали су доступни за трајне комбинације.

| Стратегија          | Опис                                                                                                                                                                                                                                                                                                                                                                                           |
| :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `priority`          | Уређена листа првог циља са експлицитним приоритетом                                                                                                                                                                                                                                                                                                                                           |
| `weighted`          | Пропорционално насумично извлачење по захтеву према циљној тежини; остали циљеви постају резервни (погледајте доле)                                                                                                                                                                                                                                                                            |
| `round-robin`       | Прођите кроз циљеве по редоследу, у лепљивим серијама (подразумевано 3 успеха по мети; погледајте испод)                                                                                                                                                                                                                                                                                       |
| `context-relay`     | Приоритетни редослед плус сажетак примопредаје када се разговор премести на други налог                                                                                                                                                                                                                                                                                                        |
| `fill-first`        | Попуните квоту сваког циља пре него што пређете на следећи                                                                                                                                                                                                                                                                                                                                     |
| `p2c`               | Испробајте две мете и дајте предност здравијој, бржој                                                                                                                                                                                                                                                                                                                                          |

| `least-used`        | Изаберите циљ са најмање забележених захтева у овој комбинацији (по моделу + налога)                                                                                                                                                                                                                                                                                                           |

### `weighted` семантицс

`weighted` је а** пропорционално насумично извлачење по захтеву** (`open-sse/services/combo/targetSorters.ts` → `selectWeightedTarget`), а не еквилајзер:

- Сваки захтев извлачи** један** корак са вероватноћом `weight / totalWeight`; преостали кораци су поређани по опадајућој тежини као резервни ланац за тај захтев.
- Корак чија је тежина `0` (или недостаје) је** никад нацртана** док сваки други корак има тежину > 0 — он може послужити само као резервни корак након што нацртани корак не успе. Само када** све** тежине су 0 да ли селекција постаје униформна.
- Кораци чији су сви циљеви недоступни прекидач — провајдера `OPEN`, хлађење везе, закључавање модела — уклањају се из извлачења пре него што се то деси (`open-sse/services/combo/targetResolution.ts`), тако да један здрав корак може привремено да победи сваки захтев.
- `stickyWeightedLimit` (комбинована конфигурација, подразумевани `1` = искључен) закачи извучени корак за толико узастопних успеха пре поновног цртања.

За строгу ротацију користите `round-robin`; једнаке тежине на `weighted` дају статистичку — а не строгу — равнотежу.

### Агентски режим цевовода

`pipeline` комбинација са најмање два модела може се одлучити за planner/executor рутирање помоћу `config.agenticOrchestration.enabled`. Прва мета поседује планирање и коначне одговоре; други циљ емитује позиве алата који су изворни клијенту. OmniRoute детектује наставке резултата алата из протокола захтева, пита планера да ли је потребна још једна рунда алата и динамички чини извршиоца или планера последњи корак окренут клијенту.

Опционо `config.agenticOrchestration.contextCompaction` примењује засебан буџет корисног оптерећења пре сваког слања планера или извршиоца. Омогућите га експлицитно:

```json
{
  "enabled": true,
  "defaultMaxChars": 400000,
  "targetRatio": 0.72,
  "toolResultMaxChars": 24000,
  "modelMaxChars": { "provider/planner": 175000, "provider/executor": 300000 }
}
```

Ово су серијализовани буџети JSON знакова које бира оператер, а не контекстни прозори токена или загарантована горња ограничења. Тачан модел IDs замењује подразумевани. Изнад прага, сабијање уклања идентичне дефиниције алата, скраћује доказе превеликог алата са сажетком и уклања старе комплетне групе историје према циљном односу. Задржава system/developer инструкције, последњи захтев корисника, последњу рунду алата укључујући паралелни calls/results и Gemini водећу инструкцију за рутирање. Инструкције највишег нивоа и подешавања алата су сачувани. Ознака пропуста бележи уклоњену историју; ово је детерминистичко скраћивање, а не семантички сажетак. Ако закачени контекст и даље премашује буџет, захтев враћа 413 пре него што контактира модел. Када је сабијање онемогућено или испод прага, захтев пролази непромењен.

У наставку резултата алата, OmniRoute такође зауставља извршење када два узастопна завршена круга понављају исте позиве алата са непромењеним резултатима, или када сваки експлицитно означен резултат у две узастопне рунде није успео. Промењени резултати дозвољавају поновљене позиве (на пример, анкетирање). Заштитник се ресетује на нови захтев корисника, групише паралелне позиве у један круг и подржава Anthropic, довршавања ћаскања, одговоре и Gemini историје. Планер добија разлог и поседује коначни одговор чак и ако захтева још једну рунду алата.

Додатни модели након друге мете су наређени извршиоцима резервних копија. Неуспели HTTP одговор или изузетак транспорта напредују до следећег извршиоца, носећи исту одлуку планера и изворне алате, али сопствени корак тог извршиоца и решену везу. Први успешан одговор се враћа непромењен, укључујући SSE стримовање; грешке након успешног покретања стрима не могу се поново покушати овде. Ако сви извршиоци не успеју, враћа се последњи неуспех. Клијент прекида слање заустављања.

```json
{
  "strategy": "pipeline",
  "models": [{ "model": "provider/planner" }, { "model": "provider/executor" }],
  "config": {
    "agenticOrchestration": { "enabled": true, "maxToolRounds": 8 }
  }
}
```

Извршилац може да емитује више независних позива у једном одговору. Зависни позиви се обрађују у каснијим променама клијентских алата и резултата, при чему планер прегледа сваки резултат. `maxToolRounds` подразумевано је `8` и прихвата `1`–`32`; када се постигне, планер мора дати најбољи доступни коначни одговор. Одлуке интерног планера су бафероване, док изабрани одговор окренут клијенту чува оригиналну преференцу за стримовање.

### `round-robin` лепљива серија и проширење налога

Роунд-робин је групни, а не један захтев по кораку:

- `stickyRoundRobinLimit` (комбо конфигурација, затим `comboStickyRoundRobinLimit`, затим `settings.stickyRoundRobinLimit`, подразумевано** 3** ) задржава исти циљ за толико узастопних успеха пре ротације. Подесите замену комбинације на `1` за ротацију са једним захтевом. Комбиновани уређивач приказује ефективну вредност и из ког слоја долази.
- `connectionAwareExpansion` (комбинована конфигурација, затим подешавања, подразумевано** лажно** ) проширује сваки корак на нивоу добављача у циљеве по налогу пре ротације. Стратегије групе Б (приоритетне, пондерисане, роунд-робин, насумичне, п2ц, најмање коришћене, оптимизоване за трошкове, лкгп, прво попуњавање, строго насумично, оптимизоване за контекст, оптимизоване за кеш, релеј контекста, фузија, цевовод, јев) задржавају приказ на нивоу добављача док се ово не укључи. Комбиновани уређивач излаже наследити / укључено / искључено; инхерит користи глобално подразумевано (искључено).
- Промпт-цацхе локално рутирање (`promptCacheAffinityEnabled`, подразумевано** истина** ) мења редослед закачених веза тако да одговарајући кључеви кеша остају на једном налогу. Има предност у односу на кружну и пондерисану ротацију кроз закачене кораке по налогу. Искључите га под подразумеваним подешавањима → Цомбо ако вам је потребна строга ротација. Не постоји пер-цомбо замена.

За ротацију више налога на једном моделу, радије** један корак динамичког налога** (празно `connectionId`, цео базен) са лепљивим ограничењем `1`, а не са три закачена `connectionId` с. Закачени кораци плус афинитет се скупљају на исти налог чак и док RR бројач напредује.

## Fusion strategija

`fusion` je jedina strategija koja **ne** bira jedan cilj. Ona šalje prompt
paralelno na **svaki panel model**, a zatim konfigurabilni **judge model** sintetiše
jedan konačan odgovor na osnovu svih odgovora panela. Prenešeno iz upstream `decolua/9router`
(OpenRouter-ov Fusion dizajn); implementacija u `open-sse/services/fusion.ts`.

Kako funkcioniše:

0. **Zaobilaženje sa alatima (tool-bearing bypass)** — zahtev koji nosi neprazan `tools` niz sa
   `tool_choice` koji nije eksplicitno `"none"` u potpunosti zaobilazi panel: rutira se direktno na
   jedan model (konfigurisani judge, ili `panel[0]`) sa `tools`/`tool_choice`
   prosleđenim nepromenjenim. Članovi panela nemaju pristup alatima i judge-ova
   direktiva za sintezu obeshrabruje emitovanje tool-call-a, pa agentni/tool-calling klijenti
   dobijaju stvarnu odluku o tool-call-u umesto sintetizovane proze (#6771).
1. **Fan-out** (samo za zahteve koji ne nose alate) — prompt se šalje svakom panel
   modelu odjednom, forsirano bez streaminga sa uklonjenim alatima (judge-u je potrebna
   kompletna proza za sintezu).
2. **Prikupljanje sa quorum-grace periodom** — čim stigne `minPanel` odgovora, počinje
   kratki grace tajmer za zaostale modele, a zatim fusion nastavlja sa onim što je
   prikupljeno. Ovo ograničava kaznu najsporijeg modela na ukupno vreme, ograničeno
   tvrdim timeout-om.
3. **Judge sinteza** — odgovori panela se anonimizuju (`Source 1`, `Source 2`, … — tako da
   judge procenjuje suštinu, a ne brend modela) i predaju judge-u, koji analizira
   konsenzus / kontradikcije / delimičnu pokrivenost / jedinstvene uvide / slepe tačke, a zatim
   piše **jedan** autoritativan odgovor. Judge poziv čuva klijentov originalni
   `stream` flag + alate, tako da streaming i naknadna upotreba alata i dalje funkcionišu.
4. **Graciozna degradacija** — 0 odgovora panela → `503`; tačno 1 preživeli → taj odgovor
   se vraća direktno (nema šta da se fuzioniše); panel sa jednim modelom odgovara direktno.

Član panela može takođe biti `combo-ref` korak (`{kind: "combo-ref", comboName: "..."}`) koji upućuje na
drugi combo — on se rešava kao **jedan black-box panel glas** (potpuni rekurzivni dispatch u
referencirani combo, a ne fan-out ciljeva tog combo-a), sa istom zaštitom od dubine/ciklusa koju
već koriste sve ostale strategije koje konzumiraju combo-ref (#6764).

### Konfiguracija

Konfiguriše se na `config` blob-u combo-a (bez migracije šeme — ponovo se koristi postojeća
tabela `combos`):

| Polje                                    | Tip      | Podrazumevano    | Namena                                                                                           |
| :--------------------------------------- | :------- | :--------------- | :----------------------------------------------------------------------------------------------- |
| `config.judgeModel`                      | `string` | prvi panel model | Model koji sintetiše konačan odgovor                                                             |
| `config.fusionTuning.minPanel`           | `number` | `2`              | Broj uspešnih odgovora potreban pre nego što grace tajmer počne (ograničeno na `[2, panelSize]`) |
| `config.fusionTuning.stragglerGraceMs`   | `number` | `8000`           | Koliko dugo čekati zaostale modele nakon što je kvorum postignut                                 |
| `config.fusionTuning.panelHardTimeoutMs` | `number` | `90000`          | Apsolutni limit tako da jedan zaglavljen model ne može da blokira zahtev                         |

Podrazumevane vrednosti se nalaze u `FUSION_DEFAULTS` (`open-sse/services/fusion.ts`).

## Виртуелна Auto-Combo фабрика

Auto Combo мотор не захтева претходно дефинисане комбинације. Уместо тога, `open-sse/services/autoCombo/virtualFactory.ts` изграђује кандидате у ходу:

1. Повлачи `getProviderConnections({ isActive: true })` (све омогућене конекције)
2. Филтрира на оне са важећим credentials (API кључ или OAuth токен који није истекао, преко `hasUsableOAuthToken()`)
3. Укршта са `getProviderRegistry()` за доступност модела + цене
4. За сваку торку `(provider, model, connection)`, изграђује `VirtualAutoComboCandidate`
5. Бира `connection.defaultModel` (или први модел из registry-а) као циљ за дистрибуцију
6. Оцењује сваки кандидат помоћу 16-факторског `scorePool()` и пакета тежина одговарајуће варијанте
7. Враћа резултујућу `AutoComboConfig` у меморији за `handleComboChat()` — никада се не чува у бази података

Ово значи да **додавање новог провајдера са омогућеним `auto/*` аутоматски проширује скуп кандидата** — без потребе за ручним уређивањем комбинација. Виртуелна комбинација се изграђује поново за сваки захтев, тако да новододате или новоопорављене конекције бивају одмах узете у обзир.

## Самоопоравак (Self-Healing)

- **Привремено искључивање**: Резултат < 0.2 → искључено на 5 минута (прогресивни backoff, максимум 30 минута)
- **Свесност circuit breaker-а**: OPEN → аутоматски искључено; HALF_OPEN → пробни захтеви
- **Режим инцидента**: >50% OPEN → искључује се истраживање, максимизује стабилност
- **Опоравак након пузе (cooldown)**: После искључивања, први захтев је "проба" са смањеним временским ограничењем

## Bandit истраживање

5% захтева (подесиво) се усмерава ка насумичним провајдерима ради истраживања. Онемогућено у режиму инцидента.

## API

постоји** нема наменске крајње `POST /api/combos/auto`** — Ауто-Цомбо се троши на два начина:

1. **Зеро-цонфиг (препоручено):** Пошаљите било који захтев за завршетак ћаскања са `model: "auto"` или `model: "auto/<variant>"`. Виртуелна фабрика прави комбинацију по захтеву — без постојаности, нису потребни API позиви.

2. **Трајна комбинација са `strategy: "auto"`:** Направите редовну комбинацију преко `POST /api/combos` и поставите `strategy: "auto"` плус `config.auto.weights` / `config.auto.candidatePool`. Користи се исти механизам за бодовање; комбинација се чува у `combos` и може се поново користити помоћу ID.

За откривање, `GET /api/combos/auto` наводи сваку варијанту са својим решеним скупом кандидата плус `context_length` / `max_output_tokens` — MAX преко прозора групе кандидата. Клијенти (нпр. додатак за опенцоде) морају да рекламирају ове вредности уместо `0`: нулти контекст у потпуности онемогућава аутоматско сажимање отвореног кода, дозвољавајући сесије да расту све док чишћење историје мрежног пролаза не уништи контекст. MAX је безбедно оглашавати јер аутоматски комбиновани контекст пред-филтер усмерава превелике захтеве кандидатима са великим прозорима.

```bash
# Zero-config usage (no combo creation)
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Hello"}]}'

# Persisted auto combo via the regular combos endpoint
curl -X POST http://localhost:20128/api/combos \
  -H "Content-Type: application/json" \
  -d '{"id":"my-auto","name":"Auto Coder","strategy":"auto","config":{"auto":{"candidatePool":["anthropic","google","openai"],"weights":{"quota":0.15,"health":0.3,"costInv":0.05,"latencyInv":0.35,"taskFit":0.1,"stability":0,"tierPriority":0.05}}}}'
```

### Стратегије ауто рутера

Трајне `strategy: "auto"` комбинације могу поставити `config.routerStrategy` (или застарели `config.auto.routerStrategy`) на једно од:

- `rules` — подразумевано пондерисано бодовање
- `score` — бира највиши конфигурисани пондерисани резултат. Тачне везе чувају конфигурисани редослед кандидата; постојећи `explorationRate` узорци из пуне рангиране групе.
- `cost` / `eco` — најјефтинији здрав провајдер
- `latency` / `fast` — најнижа п95 латенција са казном поузданости
- `sla-aware` / `sla` — преферирају кандидате који задовољавају п95 кашњење, стопу грешке и опциону цену SLOs
- `lkgp` — први познати добар провајдер
- `nadir` — питајте [Надирову](https://getnadir.com) одлуку API који модел у групи је потребан; опт-ин, фаил-опен за `rules`
- `decision` — питајте конфигурисани одлучујући (TypeSafe Систем Оне, ваша сопствена одлука URL, или један од сопствених модела комбинације) који модел у групи одговара захтеву; иза подразумевано искључене `COMBO_DECISION_ROUTER_ENABLED` заставице, неуспешно отварање за `rules`

### Детаљне стратегије рутера

Ауто-комбо мотор излаже 7 прикључних**RouterStrategy** имплементације које можете заменити преко `config.routerStrategy` (или застарелог `config.auto.routerStrategy`). Свака стратегија бира једног провајдера из групе кандидата, дајући `RoutingContext` (тип задатка, tool/vision наговештаји, процена токена, опциона SLA политика, опциони последњи познати-добри провајдер).

#### 1. `rules` (подразумевано) — пондерисано бодовање са 16 фактора

Обмотава постојећи механизам за бодовање. Филтрира кандидате `OPEN` прекидаче, затим покреће `scorePool()` са тренутним типом задатка и `getTaskFitness()`, бирајући провајдера са најбољим резултатом.

```ts
class RulesStrategyImpl implements RouterStrategy {
  readonly name = "rules";
  readonly description = "16-factor weighted scoring (see DEFAULT_WEIGHTS)";

  select(pool, context) {
    const eligible = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const ranked = scorePool(
      eligible.length > 0 ? eligible : pool,
      context.taskType,
      undefined,
      getTaskFitness
    );
    return { provider: ranked[0].provider /* ... */ };
  }
}
```

**Када користити** : Подразумевано. Користите када желите уравнотежен компромис за све сигнале.

**Алиас** : `rules` (без псеудонима)

---

#### 2. `cost` / `eco` — најјефтинији здрав провајдер

Сортира групу кандидата по `costPer1MTokens` (узлазно) и бира најјефтиније. Прво филтрира `OPEN` кандидате.

```ts
class CostStrategyImpl implements RouterStrategy {
  readonly name = "cost";
  readonly description = "Always selects cheapest available provider";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort((a, b) => a.costPer1MTokens - b.costPer1MTokens);
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**Када користити** : Радна оптерећења која су осетљива на трошкове, групна обрада или послови у позадини.

**Алиасес** : `cost`, `eco`

---

#### 3. `latency` / `fast` — најниже кашњење п95 са казном поузданости

Сортирај по `p95LatencyMs + (errorRate * 1000)`. Казна за стопу грешке осигурава да су непоуздани провајдери ниже рангирани чак и ако је њихова номинална латенција мала.

```ts
class LatencyStrategyImpl implements RouterStrategy {
  readonly name = "latency";
  readonly description = "Prioritizes lowest p95 latency with reliability weighting";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort(
      (a, b) => a.p95LatencyMs + a.errorRate * 1000 - (b.p95LatencyMs + b.errorRate * 1000)
    );
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**Када користити** : Радна оптерећења осетљива на кашњење као што су ћаскање у реалном времену, аутодовршавање или интерактивни помоћници за кодирање.

**Алиасес** : `latency`, `fast`

---

#### 4. `sla-aware` / `sla` — latency/error/cost SLO усклађеност

Оцењује сваког кандидата колико добро задовољава конфигурисану политику SLO :

| Фактор               | Тежина | Формула                                                |
| -------------------- | ------ | ------------------------------------------------------ |
| Оцена кашњења        | 35%    | `threshold / max(value, ε)`                            |
| Оцена грешке         | 35%    | `threshold / max(value, ε)`                            |
| Здравствени резултат | 15%    | `1.0` (CLOSED) / `0.5` (HALF_OPEN) / `0.0` (OPEN)      |
| Оцена трошкова       | 10%    | `threshold / max(value, ε)` или инверзно нормализовано |
| Оцена стабилности    | 5%     | инверзно нормализовано кашњење стддев                  |

Када `hardConstraints: true`, кандидати се сортирају првенствено по** оцена прекршаја** (колико далеко премашују било који SLO), затим по композитном резултату. Иначе је то само композитни резултат.

```ts
class SLAStrategyImpl implements RouterStrategy {
  readonly name = "sla-aware";
  readonly description =
    "Selects the provider most likely to satisfy latency, error-rate, and cost SLOs";

  select(pool, context) {
    // ... scores each candidate against policy: { targetP95Ms, maxErrorRate, maxCostPer1MTokens, hardConstraints }
  }
}
```

**SLA поља** (подешено на комбинованој конфигурацији):

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "sla-aware",
    "slaTargetP95Ms": 1500,
    "slaMaxErrorRate": 0.05,
    "slaMaxCostPer1MTokens": 5,
    "slaHardConstraints": true
  }
}
```

**Када користити** : Производно оптерећење са строгим кашњењем, стопом грешака или буџетима трошкова.

**Алиасес** : `sla-aware`, `sla`

---

#### 5. `lkgp` — први познати добар провајдер

Покушава** последњи познати добар провајдер** (ако је постављено) прво, а затим се враћа на `rules` стратегију. Корисно за лепљивост сесије — исти провајдер обрађује накнадне захтеве у разговору.

```ts
class LKGPStrategyImpl implements RouterStrategy {
  readonly name = "lkgp";
  readonly description = "Tries last known good provider first, then falls back to rules";

  select(pool, context) {
    if (context.lkgpEnabled === false) {
      return getStrategy("rules").select(pool, context);
    }

    if (context.lastKnownGoodProvider) {
      const candidates = pool.filter(
        (c) => c.provider === context.lastKnownGoodProvider && c.circuitBreakerState !== "OPEN"
      );
      if (candidates.length > 0) {
        return { provider: candidates[0].provider /* ... */ };
      }
    }

    // Fallback to rules strategy
    return getStrategy("rules").select(pool, context);
  }
}
```

**Када користити** : Разговори у више кругова у којима желите да исти провајдер обрађује накнадне захтеве (нпр. за кеширање, континуитет контекста или конзистентност цена).

**Алиас** : `lkgp` (без псеудонима)

---

#### 6. `nadir` — избор модела који је свестан брзе употребе преко Надир-а

Свака стратегија изнад рангира кандидате по сопственој телеметрији; нико од њих не чита захтев. `nadir` шаље последње окретање корисника плус ИД-ове модела групе [Надировој](https://getnadir.com) одлуци API (`POST /v1/bucket`) и руте до модела који Надир бира из тог менија (`simple` → најјефтинији модел, `complex` → гранични). Конекцију која служи том моделу и даље бира `rules`, тако да квота, здравље и цена настављају да одлучују који налог.

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "nadir",
    "nadir": {
      "apiKey": "ndr_...",
      "baseUrl": "https://api.getnadir.com",
      "timeoutMs": 2000
    }
  }
}
```

`OMNIROUTE_NADIR_API_KEY` и `OMNIROUTE_NADIR_BASE_URL` су резервни енв за два низа. `baseUrl` је потребан само за Надир који се самостално хостује (завршни `/v1` се толерише). Позиви без кључа долазе на Надиров анонимни ниво, који је ограничен на стопу по IP. Са кључем ( [креирајте га](https://app.getnadir.com/dashboard/api-keys) ), свака одлука се евидентира на вашој Надир контролној табли. Потпуно подешавање и верификација: [getnadir.com/docs/gateway-omniroute](https://getnadir.com/docs/gateway-omniroute/).

Шта оставља оквир: текст последње корисничке поруке (првих 16.000 знакова), ИД-ови модела кандидата и ознака канала `source: "omniroute"`. Нема системског упита, историје, алата или заглавља.

Понашање приликом неуспешног отварања: временско ограничење (подразумевано 2000 мс), non-2xx, недоступни хост, неисправан одговор или избор ван скупа решава се на `rules` одлуку и разлог има префикс `NadirStrategy: fallback (…)`. Након неуспелог позива, стратегија прескаче мрежу на 30 с, тако да прекид кошта једно временско ограничење на 30 с, а не једно по захтеву. Догађаји рутирања извештавају `strategy: "nadir"` само када је Надир заиста направио избор.

**Када користити** : саобраћај мешовите тежине на групи која обухвата нивое модела (мали, средњи и гранични модел), где је увек граница трошак који желите да смањите.

**Алиас** : `nadir` (без псеудонима)

#### 7. `decision` — плуггабле одлучивач бира модел

`decision` пита а** одлучујући** који модел у групи одговара захтеву, затим сужава групу на тај модел и дозвољава `rules` да изабере везу (квота, здравље и цена и даље бирају налог). Одлучујући се поставља у блок одлучивања комбинације — `config.decision` када се дугмад рутера налазе на врху `config` (оно што контролна табла пише), или `config.auto.decision` поред `config.auto.routerStrategy`:

| `decider`     | Ко одговара                                                                                                               | Потребе                                        |
| ------------- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `systemone`   | TypeSafe Систем Оне (`POST https://api.typesafe.ai/v1/systemone`), подразумевани модел `jev-latest`                       | `typesafe` везу или енв кључ                   |
| `http`        | ваш сопствени одлучи на `baseUrl`: `wire: "systemone"` (`{baseUrl}/v1/systemone`) или `"openai-chat"` (завршетак ћаскања) | `baseUrl` + `model`; кључ опционо              |
| `combo-model` | један од модела вашег добављача, позван у процесу као судија за фузију                                                    | `model` као `provider/model` (без комбинације) |

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "decision",
    "decision": {
      "decider": "http",
      "baseUrl": "https://decider.example.com",
      "wire": "openai-chat",
      "model": "qwen-small",
      "connectionId": "<stored connection id>",
      "timeoutMs": 2000,
      "minConfidence": 0.6,
      "descriptions": { "gpt-4o-mini": "Quick drafts and short answers" }
    }
  }
}
```

Поља (потврђена строгом шемом приликом чувања и поново у време захтева):

- `decider` — `systemone`, `http` или `combo-model`.
- `model` — TypeSafe модел, модел одлуке у вашем URL или `provider/model` позива комбинованог модела (до 200 знакова).
- само `baseUrl` — `http` : `http(s)` URL до 500 знакова, без акредитива, упита или фрагмента. URL који показује на овај OmniRoute (петља + `PORT`) је одбијен.
- `wire` — само `http` : `systemone` (подразумевано) или `openai-chat`.
- `connectionId` — сачувана веза чији се кључ користи (само унутар дозвољених веза позивајућег API кључа). Без тога, `systemone` чита `typesafe` везу и сваки мрежни одлучивач се враћа на `OMNIROUTE_DECISION_API_KEY`. Не постоји поље `apiKey` : кључ се никада не чува у комбинацији.
- `timeoutMs` — број, 100–5000, подразумевано 2000.
- `minConfidence` — 0–1; одговор са нижом поузданошћу се враћа на `rules` (одлучивач који пријављује непоуздање рачуна се као 0).
- `descriptions` — до 50 уноса (кључ до 300, текст до 1000 карактера), који се уносе помоћу ИД модела или `provider/model`; неподешени уноси добијају генерисани опис ранга трошкова.

**Застава.** `COMBO_DECISION_ROUTER_ENABLED` (подразумевано `false`) капије сваког доносиоца одлуке. Док је искључена, `decision` комбинација не чита акредитиве, не обавља позиве и усмерава се са `rules`; дневник каже `fallback (disabled)`. Само сачувани кључ га никада не укључује. Комбинације без блока одлучивања нису уопште погођене.

**Шта оставља кутију.** Само текст последње корисничке поруке (до 8000 карактера; chat/Claude `messages` или Одговори `input`) и мени ИД-ова модела са њиховим описима. Никада системски упит, одговори `instructions`, алати, историја, заглавља или подаци о налогу. Мрежни позиви пролазе кроз одлазну заштиту провајдера без поновних покушаја, без преусмеравања и ограничења одговора од 64 KB. `combo-model` позив је нестриминг, без алата, `temperature: 0`, са буџетом од 256 токена; одлука започета у позиву за одлучивање је одбијена.

**Неуспешно понашање** је отворен за грешке: сваки неуспех се решава у `rules` одлуци, а разлог гласи `decision(<decider>): fallback (<reason>)`, са `<reason>` једним од `disabled`, `not_configured`, `missing_credential`, `timeout`, `http_error`, `invalid_response`, `out_of_menu`, `refused`, `cooldown`, `network_error`, `recursion` или `single_option` `low_confidence` `no_user_text`. Након истека времена, HTTP грешке или мрежне грешке, крајња тачка се прескаче на 30 с. Успешан избор гласи `decision(<decider>): selected <model> from <n>; confidence <c> (<rules reason>)`. Ниједан URL, кључ, промпт или узводно тело не доспевају у евиденцију.

Комбо градитељ приказује ова поља када је стратегија рутера `decision`, са генерисаним описима као чуварима места и** Одлука о тестирању** дугме које позива `POST /api/combos/decision-preview` једном са несачуваним подешавањима (иста ознака).

**Када користити** : саобраћај мешовите тежине где желите да ниво по захтеву бира класификатор који одаберете, а не Надир посебно.

**Алиас** : `decision` (без псеудонима)

### Прилагођене стратегије рутера

Можете регистровати сопствену имплементацију `RouterStrategy` преко јавног API:

```ts
import {
  registerStrategy,
  type RouterStrategy,
} from "@omniroute/open-sse/services/autoCombo/routerStrategy";

class MyCustomStrategy implements RouterStrategy {
  readonly name = "my-custom";
  readonly description = "My custom routing strategy";

  select(pool, context) {
    // Your routing logic here
    return {
      provider: pool[0].provider,
      model: pool[0].model,
      strategy: this.name,
      reason: "MyCustomStrategy: ...",
      candidatesConsidered: pool.length,
      finalScore: 1.0,
    };
  }
}

registerStrategy("my-custom", new MyCustomStrategy());
```

Затим га користите:

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "my-custom"
  }
}
```

## Podesnost za zadatke

30+ modela ocenjeno je za 6 tipova zadataka (`coding`, `review`, `planning`, `analysis`, `debugging`, `documentation`). Podržani su wildcard obrasci (npr. `*-coder` → visoka ocena za coding).

## Ауто Вариантс Рецап

`AutoVariant` у `autoPrefix.ts` изјављује** 7 вредности** (`coding`, `fast`, `cheap`, `offline`, `smart`, `lkgp`, `chaos`). Together са голим `auto` (којим `parseAutoPrefix()` рукује као `variant: undefined`) и два равног слоја преклапања `auto/subscription` и `auto/thrifty` (`FLAT_TIER_OVERLAY_IDS` у `builtinCatalog.ts`), постоје** 10 стан модел IDs** :

`auto`, `auto/coding`, `auto/fast`, `auto/cheap`, `auto/offline`, `auto/smart`, `auto/lkgp`, `auto/chaos`, `auto/subscription`, `auto/thrifty`

Осим тога, `auto/<category>[:<tier>]` композиције, модел-породица IDs (на пример `auto/claude-opus`) и `auto/best-*` / `auto/pro-*` алиаси у `builtinCatalog.ts` такође се решавају.

## Како се нивои уклапају у Auto-Combo

Функција оцењивања са 16 фактора (`open-sse/services/autoCombo/scoring.ts`) третира припадност нивоу као два сигнала: `tierPriority` (0.0476) и `tierAffinity` (0.0476). Погледајте канонску [табелу фактора оцењивања](#how-it-works-persisted-auto-combos) изнад за комплетан скуп `DEFAULT_WEIGHTS` — замене специфичне за сваки пакет (ship-fast/cost-saver/quality-first/
offline-friendly) наведене су у табели „Профили тежина по пакету“.

Сам ниво **не** намеће да Ниво 1 буде први — ако је кашњење Нивоа 1 велико или је однос цене и квалитета неоптималан, Ниво 2 побеђује. Да бисте наметнули редослед нивоа, користите стратегију комбинације `priority` и распоредите добављаче по нивоима.

Да бисте изразито фаворизовали Ниво 1 (претплату), повећајте тежину `tierPriority`:

```json
{
  "strategy": "auto",
  "config": { "auto": { "weights": { "tierPriority": 0.3, "costInv": 0.05 } } }
}
```

Погледајте [`docs/guides/TIERS.md`](../guides/TIERS.md) за дефиниције нивоа и класификацију добављача.

## Тестирање и покривеност

### Детерминистичка матрица одлучивања о рутирању (`npm run test:combo:matrix`)

`tests/integration/combo-matrix/*.test.ts` доказује рутирање** одлука** јавних стратегија које покрива од краја до краја кроз прави комбиновани цевовод са исмевањем узводно. Покривеност укључује:

- 18 од 22 јавне `ROUTING_STRATEGY_VALUES` стратегије (наређено, пондерисано, цена, контекст, фузија, …); `quota-weighted`, `cache-optimized`, `pipeline` и `jev` матрица не примењује и ослањају се на сопствене тестове јединица.
- `quota-share` (интерно) од краја до краја: DRR правичност + засићење деприоритизација преко стварног `selectQuotaShareTarget` шава (`registerQuotaFetcher` / `setLKGP` / `__setHeadroomSaturationFetcherForTests`).
- `context-relay` универзално-хандофф покривеност за сваки број мета.

Овај пакет ради у CI (`test:integration` посао) са `--test-concurrency=1` и `--test-force-exit` тако да је детерминистички и не захтева живе акредитиве.

### Затворени живи дим (NOT у CI — прави провајдери)

| Цомманд                                | Шта ради                                                                    |
| :------------------------------------- | :-------------------------------------------------------------------------- |
| `npm run test:combo:live`              | Реално рутирање у процесу са `RUN_COMBO_LIVE=1`; снимци уживо OmniRoute DB  |
| `npm run test:combo:live:vps`          | HTTP позива против живог OmniRoute сервера (подесите `COMBO_LIVE_BASE_URL`) |
| `npm run test:combo:live:vps:failover` | Исто, са намерним сценаријима преласка на грешку                            |

Ови тестови дима остварују прави пут жице (комбиновани → провајдер → завршетак). Они су намерно искључени из CI јер захтевају акредитиве уживо и VPS приступ.
