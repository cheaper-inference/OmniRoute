## Преглед

Механизам за дељење квота праведно распоређује временски ограничену квоту добављача (нпр. Codex
5-часовни прозор, Kimi 1500 захтева/ч) између више API кључева који деле исту
везу.

**Проблем који решава:** OmniRoute прослеђује захтеве многих API кључева ка истом налогу
узводног добављача. Без логике дељења, нагли прилив захтева са кључа A може исцрпети
квоту добављача за тај сат, остављајући кључеве B и C блокираним док се прозор не ресетује.
Механизам ово спречава на следећи начин:

1. Прати текућу потрошњу сваког кључа по димензији (%, захтеви, токени, $).
2. Примењује алгоритам праведне расподеле који чува искоришћеност ресурса: кључ може позајмити од неактивних
   удела док глобални скуп није засићен.
3. Спроводи резултат у критичној путањи (`chatCore.ts`) пре него што захтев
   стигне до узводног извршиоца.

## Алгоритам: фер-Схаре Ворк-Цонсервинг

Имплементирано у `src/lib/quota/fairShare.ts`.

### Режими

| Стање                                      | Моде            | Понашање                                                           |
| ------------------------------------------ | --------------- | ------------------------------------------------------------------ |
| `globalUsedPercent < saturationThreshold`  | **Великодушно** | Кључ може да позајми до глобалног ограничења минус потрошен-укупно |
| `globalUsedPercent >= saturationThreshold` | **Строги**      | Строго спроводити индивидуално поштено учешће                      |

Подразумевано `saturationThreshold = 0.5` (енв `QUOTA_SATURATION_THRESHOLD`).

Ова два режима описују скуп у подразумеваном режиму позајмљивања, `saturation`. Група у `consent` режиму увек примењује строга правила, без обзира на засићење. Погледајте [Зајмови са сагласности (попул-он опт-ин)](#consented-lending-per-pool-opt-in).

### Одлука по димензији

За сваку активну димензију у групи, машина израчунава:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = current rolling value for this key (from QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

За `percent` димензије, `consumed` долази из књиге атрибуције (погледајте [Процентуалне димензије: атрибуција по кључу](#percent-dimensions-per-key-attribution) ).

онда:

- **`policy = hard`** : ако је `consumed > fairShareAllowed` и режим строг →** блок** .
- **`policy = soft`** : ако је `consumed > fairShareAllowed` и режим строг →** казнити** (одбацивање приоритета у комбинацији; никада хард-блок).
- **`policy = burst`** : дозволи док постоји глобални простор без обзира на поштено учешће.

### Цап абсолуто

`capValue` + `capUnit` на алокацији је строги плафон независно од режима или политике. Било која димензија где `consumed >= capValue` увек** блокова** захтев. За `percent` цап, `consumed` је само део који се приписује кључу.

### Вишедимензионална провера

Захтев је блокиран ако** било који** димензија у базену би га блокирала. Димензије су независне — 5х% исцрпљености не утиче на недељну димензију%.

### Позајмљивање

У великодушном режиму, кључ чија је алокација недовољно потрошена може да користи вишак од нераспоређених удела других кључева. Формула је:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

где `consumedByOtherKeys = consumedTotal - consumedByThisKey`. Тето глобал (поол `limit` за ту димензију) је увек тврди плафон.

### Позајмљивање са пристанком (прихватање по групи)

Сваки базен има режим позајмљивања. `saturation` је подразумевана и чува горенаведена правила. У `consent` режиму `hard` кључ пропушта свој део само у оквиру капацитета који су други кључеви пристали да позајме. Администратор поставља режим сваког базена. Сваки носилац кључа даје сопствену сагласност путем [сагласности за позајмљивање](#lending-consent).

Сагласност је проценат од 0 до 100 и опциони рок у епохи милисекундама. Кључ позајмљује тај проценат свог неактивног удела док је рок у будућности.

За једну димензију, `L` је ефективна граница: ограничење плана помножено са рачунима у групи. Капија израчунава, за кључ који захтева:

```
share_k         = w_k / 100 × L
idle_k          = max(0, share_k − consumed_k)
lent            = Σ over the other keys of lend_k / 100 × idle_k
taken           = Σ over the other keys of max(0, consumed_k − share_k)
borrowAvailable = max(0, lent − taken)
```

`w_k` је тежина кључа, или `100 / n` за сваки кључ када ниједна тежина није већа од 0. `lend_k` је активни проценат кључа, а 0 када му истекне рок. Сопствена сагласност кључа који је тражио никада се не рачуна. `hard` кључ се одбија када његова потрошња достигне свој удео плус `borrowAvailable`.

Капацитет који ниједна алокација не захтева (100 минус збир пондера) није позајмљива. Ниједан кључ није пристао да га позајми.

**Пример.** `L` је 1000.

| Кључ | Тежина | Схаре | Потрошено | позајмљује |
| ---- | ------ | ----- | --------- | ---------- |
| А    | 50     | 500   | 530       | 0%         |
| Б    | 30     | 300   | 100       | 50%        |
| Ц    | 0      | 0     | 60        | 0%         |

- Б позајмљује 50% својих неактивних 200, што је 100. Ц је већ узео 60 изнад свог удела. А може да позајми 40.
- А се сервира на 530 и одбија се када његова потрошња достигне 540.
- Пре него што је Ц користио било шта, са А на или испод свог удела, Ц је могао да позајми 100.
- Пре него што је Ц употребио било шта, са А на 530, Ц је могао да позајми 70.

**Нулта тежина.** Кључ са тежином 0 има удео од 0. Служи се само док је његова потрошња испод онога што други позајмљују. Када нико не позајмљује, одбија се од првог захтева.

**Рокови.** Ниједан задатак у позадини не истиче сагласност. Сваки захтев упоређује рок са својим временом, а рок једнак том времену је прошао. Сачувани рок који није коначан број или је прошао највећи датум који `Date` може да задржи, рачуна се као прошао.

**`soft` и `burst`.** Кредитирање их не ограничава. `soft` кључу се губи приоритет када пређе његов удео. `burst` кључ пролази док базен има места. Плафон базена и даље одбија сваки кључ када укупан број базена достигне своју границу.

**Цена на путањи захтева.** `saturation` базен не чита ништа више него раније. У `consent` скупу, бројива димензија чита друге кључеве само за `hard` кључ на или изнад његовог удела, док други кључ позајмљује. Затим врши једно читање по другом кључу, паралелно. Неуспело читање се рачуна као потрошња 0 за тај кључ. `percent` димензија не додаје читање, јер књига атрибуције садржи сваки кључ.

**Уређивање базена.** Уређивање задржава сагласност кључева који остају. Ово важи за измене алокације, замене у целој групи и `ensure` позиве. Уклоњени кључ губи сагласност, а кључ који је поново додат почиње од 0. Администраторске руте враћају сагласност сваког кључа и никада је не пишу. Пребацивање скупа назад на `saturation` задржава сваку сачувану сагласност, која нема ефекта у том режиму. Поново пребацивање скупа на `consent` поново активира сачуване сагласности чији рок није прошао. Носилац кључа може да обрише сачувану сагласност у било ком режиму.

**Надоградња.** Ако колоне `lending_percent` и `lending_until` већ постоје, миграција додаје само `borrow_mode`, а сачувани проценти остају онакви какви јесу. Сваки базен почиње у `saturation` режиму. Укључите `consent` по базену у чаробњаку за базен. Ништа се не закључује из сачуваних вредности.

**Ограничења.**

- Зајмодавац може пронаћи базен на свом плафону пре него што искористи свој удео. Капацитет који су други позајмили се урачунава у укупни фонд.
- Провера се покреће пре захтева и не резервише ништа. Истовремени захтеви читају потрошњу пре него што се било који евидентира, тако да се позајмљени капацитет може потрошити више пута, ограничено захтевима у лету. Провера дељења `saturation` режима има исто својство.

## Бројач клизног прозора

Имплементиран у `src/lib/quota/sqliteQuotaStore.ts` и `redisQuotaStore.ts`.

Два сегмента по `(apiKeyId, dimensionKey)`:

- `curr`: тренутни сегмент (`floor(nowMs / windowMs)`)
- `prev`: претходни сегмент (`curr - 1`)

Ефективна текућа вредност:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**Прецизност**: приближно 99%. Грешка износи највише 1% величине прозора на
граници између сегмената (својствено апроксимацији са 2 сегмента).

### Конкурентност

SQLite драјвер: mutex у меморији за сваки кључ `(apiKeyId | dimensionKey)` спречава
конфликт читања-измене-уписа. Образац прати заштиту од наглог истовременог прилива из `src/sse/services/auth.ts`.

Redis драјвер: Lua EVAL скрипта за атомско увећање — извршава се као једна Redis команда.

## Drajveri

### SQLite (podrazumevano, bez instalacije)

- Tabela: `quota_consumption` (pogledajte migraciju `073_quota_pools.sql` / `074_quota_consumption.sql`).
- Najbolje za implementacije sa jednom instancom.
- Svi trajni podaci čuvaju se u postojećoj OmniRoute SQLite bazi podataka (`DATA_DIR/storage.sqlite`).

### Redis (opciono, za više instanci)

- Zahteva npm paket `ioredis`.
- Brojači se čuvaju u Redis-u; metapodaci (skupovi/alokacije) i dalje se čuvaju u SQLite-u.
- Najbolje za implementacije sa više replika, gde brojači moraju biti deljeni.

### Promena drajvera

Putem korisničkog interfejsa za podešavanja (`/dashboard/settings` → Skladište kvota) ili putem promenljivih okruženja:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

Podešavanje u bazi podataka ima prednost nad okruženjem. Ako je `driver=redis`, ali URL nedostaje ili
`ioredis` nije instaliran, fabrika se vraća na SQLite i beleži upozorenje.

Redosled izbora drajvera:

1. Podešavanje u bazi podataka `quotaStore.driver`
2. Promenljiva okruženja `QUOTA_STORE_DRIVER`
3. Podrazumevano: `sqlite`

## Мулти-Дименсион

Базен може имати више димензија. Свака димензија је независна:

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // global pool ceiling for this dimension
}
```

**Пример: Codex план** (5х% + недељно%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

Захтев мора да задовољи све димензије да би био дозвољен.

### Процентуалне димензије: приписивање по кључу

План процента извештава једну цифру коришћења по налогу и прозору плана. Провајдер не даје бројач по API кључу.

Да би се та цифра поделила између кључева, сваки скуп води књигу атрибуције по налогу и прозору плана. `src/lib/quota/percentLedger.ts` држи правила књиге. `src/lib/quota/percentAttribution.ts` претвара књигу у бројеве које користи спровођење. Резултат је процена направљена од токена за сваку кључну руту.

#### Читања која покрећу књигу

Књига се помера само према сопственој фигури добављача за тражени прозор плана. Ове везе извештавају о једном:

| Провајдер                | Планирајте прозоре |
| ------------------------ | ------------------ |
| Claude, преко OAuth везе | `5h`, `weekly`     |
| Codex                    | `5h`, `weekly`     |

Ово се не рачуна као читање:

- одговор који клијент провајдера означава као застарео
- Claude прозор чији проценат провајдер није пријавио
- фигура другог прозора, или у најгорем случају преко прозора
- резервни део заглавља ограничења брзине
- неуспешно читање

Други провајдери, укључујући Claude са API кључем, немају књигу. Сваки кључ се наплаћује 0 на своје процентуалне димензије, као и пре ове промене.

Очитавање дели 30-секундни кеш сигнала засићења. Очитавање Claude је датирано када је цифра примећена у заглављима одговора или прочитана са крајње тачке коришћења, када је то време познато. Остала очитавања су датирана када је тај унос у кеш меморији направљен.

#### Шта књига чува

Сваки снимљени захтев додаје своје токене, једном, на бројач по групи, налогу и кључу. Бројач само расте. Књига садржи три ствари:

- основна линија: фигура када се књига отворила или прозор последњи пут окренут
- последња примењена фигура
- по кључу, његов бројач токена у том истом тренутку, назван његов знак

Књига се ажурира када примена или рута коришћења израчунају приписивање. Уписи се упоређују и постављају на број ревизије. Писац који изгуби поново покушава једном при новом читању.

#### Како се израчунава део кључа

Део сваког кључа се израчунава када се књига чита. Раст цифре од основне линије се дели између кључева пропорционално токенима који се усмеравају од своје ознаке.

Together, ти токени објашњавају највише једну тачку цифре по `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` токенима (подразумевано 1.000). Раст који не објашњавају је спољашњи. Основна линија је такође екстерна.

На пример, књига се отвара на 0. Кључ А затим усмерава 900.000 токена, а кључ Б усмерава 100.000. На цифри од 60, део А је 54 поена, а део Б је 6.

Бројач испод ознаке кључа се поново покренуо и рачуна се у потпуности. Кључ без ознаке, као што је кључ који се придружује групи на средини прозора, броји све своје токене. Бројка која заостаје за токенима изазива грешку која нестаје при следећем читању. Не акумулира се.

`QUOTA_PERCENT_MIN_TOKENS_PER_POINT` се чита на сваком приписивању. Вредност која није коначан број од најмање 1 пада назад на 1.000.

#### Како читање мења књигу

Примењује се прво правило подударања:

1. **Још нема књиге:** читање отвара књигу. Његова фигура је основна линија и сваки бројач је означен.
2. **Старије читање:** читање датирано пре последњег примењеног се игнорише. Тако је и очитавање чије је време ресетовања више од 30 минута раније од сачуваног.
3. **Нови прозор добављача:** време ресетовања више од 30 минута касније од сачуваног окреће књигу. Цифра постаје основна линија и сваки бројач се поново обележава. Кључеви без шалтера напуштају књигу.
4. **Завршен прозор:** сачувано време ресетовања које није после времена података очитавања значи да је прозор завршен. Читање окреће књигу, без обзира на њену фигуру.
5. **Виша цифра:** креће се само последња фигура. Основна линија и ознаке остају.
6. **Иста фигура:** фигура, основна линија и ознаке остају. Написано је само време ресетовања које недостаје књизи.
7. **Доња цифра:** нижа цифра се никада не примењује као таква. Преокреће књигу само када три ствари држе. Најмање два минута је новије од последњег примењеног читања. Ништа не каже да је прозор исти отворен. То је више од једног поена ниже.

Прозор се рачуна као исти отворен када три ствари држе. Оба времена ресетовања су позната. Они су у размаку од 30 минута један од другог. Сачувана је још увек испред читања. Нижа фигура унутар тог прозора ништа не мења.

Време ресетовања се чува само док је испред времена података очитавања које га носи. Већа цифра чува време ресетовања свог очитавања када је оно употребљиво, а у супротном чува сачувано. Једнака цифра бележи време ресетовања свог читања само када га књига нема. Ништа друго не мења. Нижа цифра која не окреће књигу не бележи време ресетовања.

#### Када се књига користи

Након читања, књига се користи осим ако њено сачувано време ресетовања није после тренутног времена. Тај случај настаје када се очитавање снимљено непосредно пре ресетовања, на пример из кеша, посматра непосредно после њега.

Без употребљивог читања, сачувана књига се користи само док још увек може да буде књига тренутног прозора. То важи у два случаја:

- његово време ресетовања је познато и још увек предстоји
- нема време ресетовања, а последње очитавање које га је променило је старо највише 15 минута

Иначе се ништа не приписује, као кад нема књиге. Књига чије је сачувано време ресетовања прошло никада се не наплаћује.

#### Извршење

Потрошња кључа на димензији процента је његов приписани део плус удео спољашњег дела. Екстерни део прво користи капацитет без захтева за алокацију (100 минус збир пондера). Само вишак се дели међу кључевима по тежини.

Та потрошња се пореди са правичним уделом кључа као и за било коју другу димензију. Строги режим и даље почиње када сигнал засићења достигне `QUOTA_SATURATION_THRESHOLD` (подразумевано 0,5). Сваки број је скалиран ефективним ограничењем: ограничење по налогу пута број налога у групи.

Апсолутно ограничење са `capUnit: "percent"` броји само део који се приписује кључу, скалиран на исти начин. Узмите ограничење по налогу од 100 и к налога. Ограничење од Н се тада достиже када део кључа на цифри рачуна за послуживање достигне N/k поена. Сваки рачун се проверава према сопственој књизи. На пример, са два налога, ограничење од 10 се постиже на 5 поена цифре једног налога.

Када се продавница не може прочитати, ништа се не приписује и сваки кључ се наплаћује 0 на тој димензији. Када писање књиге не успе, та атрибуција користи књигу онако како је прочитана. Неуспешно уписивање токена оставља токене тог захтева ван књиге. Ниједан од ових грешака не блокира захтев.

У `consent` фонду, формула за позајмљивање користи потрошњу сваког кључа на димензији процента као што је горе описано. Када се позајми други кључ, књига се чита једном и приписује сваком кључу. Без употребљиве књиге сваки кључ се наплаћује 0. Кључ са тежином тада пролази, а кључ са тежином 0 пролази само када други кључ позајмљује.

#### Пут употребе

`GET /api/quota/pools/{id}/usage` пријављује исте бројеве кроз исту функцију. Димензија процента има један унос по вези базена у `accounts`. Његови `consumedTotal` и `perKey` највишег нивоа одражавају први унос.

Рута такође примењује тренутно читање, тако да може унапредити књигу као што то чини захтев. `internal + external` се може разликовати од `consumedTotal` када нема употребљивог очитавања или када се не примењује нижа цифра.

#### Чување и задржавање

Обе продавнице квота воде књигу. На SQLite, аутоматско чишћење базе података, када је омогућено, уклања редове који нису ажурирани 60 дана. На Redis, књиге и бројачи везе са базеном деле један кључ. Истиче 60 дана након последњег записа или промене књиге. Књига која се не мења се не преписује, тако да се пресек поставља изнад најдужег прозора плана. Ручно ресетовање историје коришћења такође брише књиге о SQLite (погледајте Ограничења).

#### Ограничења

- Сав раст броја рачуна од основне линије се дели на токене, сваки кључ који је од тада преусмерен. Када је дошло до тог раста није важно.
- Дакле, употреба ван OmniRoute се наплаћује кључевима до онога што њихови токени дозвољавају. То укључује употребу направљено пре првог захтева кључа за прозор, када је књига већ била отворена.
- На пример, спољна употреба подиже рачун за 60 поена док нема кључних рута. Кључ тада усмерава 30.000 жетона и цифра достиже 60,6.
- Ако је књига била отворена пре те употребе, део кључа је 30 поена. Такође носи 7,65 екстерне употребе, са четири кључа тежине 25.
- Ако се књига отвори након те употребе, 60 поена је основна линија. Део кључа је 0,6 поена, а носи 15 спољне употребе.
- Захтев или посета рути коришћења отвара књигу. Дакле, да ли се таква употреба рачуна као основна зависи од тога када је књига отворена.
- Са подразумеваним прагом, кључ који усмерава 60.000 токена док спољна употреба подиже рачун за 60 поена добија свих 60 као сопствени део.
- Са подом од 50.000, сопствени део је 1,2 бода. Осталих 58,8 су екстерни и наплаћују се по тежини, као и свака спољна употреба.
- Поставите `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` близу онога што кошта један поен на вашем плану. Спољна употреба укључује саобраћај на истом налогу са кључева изван базена.
- Ограничење процента се примењује у сваком режиму. Ограничени кључ се може одбити док је рачун далеко испод прага засићења.
- Узмите капу од 10 и 12 тачака спољашње употребе раније у прозору. Кључ који усмерава 20.000 токена се тада одбија уз цифру рачуна од 12,4%.
- Подела је процена по обиму токена. Захтев се рачуна као његови промпт токени плус његови токени завршетка. Попусти у кеш меморији и цене модела не мењају тај број.
- Захтев који се не завршава статусом 200 не бележи токене. Примери су ток који клијент прекида везу и грешка у узводу након што је употреба потрошена.
- Коришћење које је такав захтев изазвао наплаћује се кључевима који су снимали токене, до онога што њихови токени дозвољавају. Остало је спољашње. Не помера се назад. Одговор који пријављује да нема употребе токена не бележи ни токене.
- Коришћење захтева у току може се приказати у другом делу активног кључа за цео захтев. Помера се назад тек када се захтев заврши са статусом 200.
- Коришћење већ на налогу када се књига отвори рачуна се као екстерно. Ово покрива надоградњу, нови скуп и нови налог. Коришћење у новом прозору пре првог читања такође се рачуна као екстерно.
- Сваки кључ почиње са својим тежинским уделом у тој употреби, након капацитета нема захтева за алокацију. Са једним налогом на 85% и пет кључева тежине 20, сваки почиње са 17 од 20 коришћених кључева.
- У групи са неколико налога, цифра налога за послуживање се примењује на збирни буџет. Ово је непромењено у књизи.
- Нижа цифра унутар прозора за који провајдер пријављује да је отворена није примењена. Време ресетовања које се помера уназад за више од 30 минута се третира као старо очитавање.
- У оба случаја књига задржава своје стање док не прође сачувано време ресетовања. Након тога, књига се не наплаћује док је читање не претвори.
- Лек је ручно ресетовање историје коришћења (`POST /api/settings/purge-usage-history`). Брише књиге атрибуције и њихове бројаче токена у SQLite бази података.
- `all` период чисти сваку књигу и шалтер. Краћи период прво чисти књиге које нису написане у њему. Затим брише бројаче који нису уписани у њему, већ само за везу са базеном у којој нема преостале књиге. Чувана књига и даље означава сваки кључ на свом бројачу.
- Књига чија се фигура није померила се не преписује, тако да краћи период такође може да обрише књигу тренутног прозора. Следеће читање отвара нову књигу на тренутној фигури.
- Ресетовање не додирује складиште квота Redis. Ту се књига завршава са својим прозором или истиче 60 дана након последњег писања.
- Када провајдер не шаље време ресетовања, прозор који се ресетује и поново пуни изнад старе цифре између два очитавања изгледа као већи број. Књига задржава стару основу и ознаке.
- Очитавања су датирана по локалном сату. Када прође испред добављача, или извор пријави време ресетовања мало раније, књига може раније да дође до те разлике.
- Раст у том кратком распону је подељен токенима који су у њему преусмерени. Прво читање у следећем прозору то исправља. Када окренута књига не садржи време ресетовања, тој исправци је потребна нижа цифра најмање два минута новија од последњег примењеног читања.
- Инстанце које деле очитавања датума Redis продавнице са сопственим сатовима, тако да синхронизујте те сатове. Очитавања инстанце чији сат иде иза изгледају старије и игноришу се.
- Када ниједно употребљиво очитање не стигне након сачуваног времена ресетовања, проценти удела по кључу и ограничења процената се не примењују док се очитање не врати. Без времена ресетовања, ово почиње 15 минута након последњег читања које је променило књигу.
- У Redis продавници, књига неактивна 60 дана може да истекне између чека писца и његовог писања. Затим се поново креира у ревизији изнад 1, што је важеће стање.

## Интеграција цевовода

### PRE кука (`open-sse/handlers/chatCore.ts`)

Покреће се пре упстреам извршиоца, након провере аутентификације и смерница:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → getQuotaStore().peek() per dimension
      → fairShare.decideFairShare()
      → if block → return 429 (buildErrorBody, Hard Rule #12)
      → if allow + deprioritize → set quotaSoftPenalty=true on candidate
  → executor.execute()
```

**Фаил-опен** : ако `enforceQuotaShare` избаци, захтев је дозвољен кроз `pino.warn` дневник. Ово спречава грешку у систему квоте да блокира сав саобраћај.

**Када се капацитет врати.** Одбијање на кључу или на плафону базена завршава се једном од две реченице, у оба начина позајмљивања:

- `percent` прозор: `. The <window> window resets at <time>.` Време је ресетовање које провајдер извештава.
- Бројива јединица: `. Enough <window> usage is expected to clear by <time>.` Време је горња граница од клизног прозора, ако кључ не шаље ништа друго.

`<time>` је ISO 8601 тренутак у UTC. Одбијање тада носи `Retry-After`: целе секунде до тог тренутка, плус један. Клијент који толико чека покушава поново највише једну секунду након тренутка. Када тренутак није познат, одбијање не носи ни реченицу ни заглавље. Апсолутно одбијање ограничења не носи ни једно ни друго. Јавни код остаје `quota_share_blocked`.

Одбијање дељења не додирује заједничку везу. Не поставља хлађење, закључавање модела и квар провајдера, а остали кључеви базена се и даље служе. Када свака мета комбинације одбије кључ за свој део, комбинација одговара 429 без чекања. Његов одговор носи наговештај као `Retry-After`. Путања за уграђивање завршава своје одбијање истом реченицом и не шаље `Retry-After`.

### POST кука (рекордна потрошња)

Након успешног одговора:

```
executor returns success
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → getQuotaStore().consume() per dimension
      → fail-open: errors logged as pino.warn, never propagated to client
```

**Дрифт ноте** : ако `consume` не успе након одговора, бројач котрљања се смањује. Сигнал засићења од провајдера (нпр. `anthropic-ratelimit-unified-5h-utilization`) исправља глобалну процену на следећи захтев.

### Комбинована мека казна (`open-sse/services/combo.ts`)

Када `decision.deprioritize === true`:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // default 0.7
}
```

Казна се примењује након свих осталих фактора за бодовање. Смањује вероватноћу аутоматског комбиновања одабира засићеног кључа без његовог тешког блокирања.

## Квота за самопослуживање API (опт-ин)

`GET /api/v1/me/quota/{provider}` (такође служи на `/v1/me/quota/{provider}`) омогућава API држачу кључа да чита, са сопственим кључем, колики је део њихове дељене претплате и шта их блокира. Рута је танка љуска преко `src/server/selfService/quotaHandler.ts`; поглед гради `src/lib/quota/selfView.ts` и његов уговор одговора је `src/shared/schemas/selfQuota.ts` (`SelfQuotaView` у `docs/openapi.yaml`).

### Омогућавање и аутентификација

- Ознака функције `QUOTA_SELF_PANEL`, подразумевана `false`. Док је искључен, захтев који стигне до руте добија 404. Са `REQUIRE_API_KEY=true`, API политика клијента одбија недостајући или неважећи кључ са 401 пре него што се рута покрене, без обзира на заставицу. Захтев без кључа, али сесије на контролној табли са пријавом, пропушта ту политику и добија сопствени одговор руте. Ознака се решава као и свака друга заставица (контролна табла или REST надјачавање, затим променљива окружења истог имена); види [`FEATURE_FLAGS.md`](../reference/FEATURE_FLAGS.md).
- Приказано име сваког скупа и ознака сваког распореда се враћају држачима кључева групе тачно онако како их је администратор написао. Пре него што укључите заставицу, проверите да ли су у стању да их читају ти држачи кључева.
- Кључ се чита само из заглавља: `Authorization: Bearer <key>` или `x-api-key: <key>`. Када се оба пошаљу, користи се први који потврђује. Кључ у стрингу упита или колачић се игнорише. Кључ окружења сервера је одбијен (401).
- Кључу је потребан `self:usage` опсег (403 без њега).
- Сегмент провајдера се скраћује, пише малим словима и проверава у односу на `^[a-z0-9][a-z0-9._-]{0,63}$` (400 иначе), а затим се решава преко регистра добављача, тако да псеудоним као што је `cc` чита `claude` скупове. `claude` и `anthropic` читају исте групе.

### Шта свака видљивост показује

| Видљивост      | Захтева                                                                        | Поља                                                                                                                                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сопствени удео | `self:usage`                                                                   | `pools[]` (реф, име, провајдер, политика, тежина, ограничење), `dimensions[].yourShare`, `accounts[]` са `yourShare` (на `percent` прозору без `attributed` и `external`), `blocks`, `availableModels`, `expiresAt`, `apiBaseUrl`                           |
| Ниво налога    | `self:usage` + `self:account-quota`, а добављач у кључу `sharedQuotaProviders` | додаје `dimensions[].total`, `accounts[].dimensions[].account` и `accounts[].modelWindows`, `attributed` и `external` на `yourShare` прозора `percent` и `members` на скуп са укљученим коришћењем чланова (погледајте [Коришћење чланова](#member-usage) ) |

- `sharedQuotaProviders` је поставка по кључу (`PUT /api/keys/[id]/self-service`): `null`, подразумевана, значи сваки провајдер до којег кључ стиже; `[]` значи ништа. `accountVisible` сваког базена каже која је видљивост примењена на њега.
- Траке налога и прозори модела приказани су само за налоге чију везу кључ може да користи. Када кључ има листу дозвољених веза, налог изван њега задржава свој унос `Account N` без `account` или `modelWindows`. Празна листа значи да нема ограничења, као за `/v1/me/status`. Укупан број (`dimensions[].total`) не зависи од те листе.
- Две фигуре приказане само са `self:usage` потичу од употребе других тастера. `exhausted` буџета распореда одражава потрошњу сваког кључа према том распореду. У групи чије су све тежине нула, `weight` кључа је `100 / number of members`. И једно и друго је оно што се спровођење примењује на кључ.
- Група се идентификује само помоћу `ref`, непрозирне вредности везане за позивни кључ. Његово име за приказ (`name`) је укључено онако како га је администратор написао. `ref` је изведен из кључа и скупа са тајном АПИ кључа сервера (`API_KEY_SECRET`). Клијенти не смеју да устрају на томе: мења се ако се та тајна ротира.
- Налози су наведени као `Account 1`, `Account 2`, … по реду групе. Не враћа се ИД базена, ИД везе, е-пошта налога или име налога, а одговор пролази кроз шему уговора, која испушта било које поље ван њега.
- Бројиве јединице (`requests`, `tokens`, `usd`) се пријављују као бацкет базена који примењује капија квоте: `limit` = план лимит × налоге у скупу, `fairShare` = тежина / 100 × `limit` (једнака подела када је свака тежина 0), `consumed` сопствени бројач = = `remaining` `fairShare` − `consumed` 0.
- `blocks.schedules` наводи прозоре распореда кључа (`open`/`closed`, `blackout` или `outside-window`, `retryAfterSeconds`, резервни спратови и да ли је буџет прозора потрошен); `blocks.modelCaps` наводи своје сатнице по моделу са потрошњом.
- Кључ ван сваке групе провајдера добија 200 са `pools: []`; `availableModels` ( `qtSd/` ИД-ови које кључ види у `/v1/models`), `expiresAt` и `apiBaseUrl` су и даље попуњени.
- `apiBaseUrl` је `OMNIROUTE_PUBLIC_API_BASE_URL`, затим `OMNIROUTE_PUBLIC_BASE_URL`, иначе `null`. То никада није сопствено порекло захтева.

### Сагласност за позајмицу

`PATCH /api/v1/me/quota/{provider}` бележи сопствену сагласност позивног кључа за један скуп. Користи заставу, заглавља и правила провајдера `GET`. Опсег `self:usage` дозвољава ово писање, иако се његово име чита као само за читање.

```json
{
  "pool": "qpr_0123456789abcdef0123456789abcdef",
  "lendingPercent": 30,
  "lendingUntil": 1893456000000
}
```

- `pool` је `ref` који `GET` враћа за тај скуп.
- `lendingPercent` је цео број од 0 до 100. Вредност 0 брише сагласност и њен рок. Тело са `lendingPercent` 0 је прихваћено у оба режима.
- `lendingUntil` је опционо: епох милисекунди, или `null` без рока. Мора бити у будућности и највише 8640000000000000. Вредност испод 100000000000 се чита као секунде и одбија се.
- Било које друго поље је одбијено. Тело дуже од 4096 бајтова се одбија. Читање се зауставља на тој величини, тако да се дуже тело никада не држи целим.

Провере се одвијају по редоследу ове табеле. Свако одбијање користи стандардно тело грешке са фиксном поруком. Одбијање једне од ових провера ништа не пише.

| Статус | Порука                                                                                             | Када                                                          |
| ------ | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 404    | `Not found`                                                                                        | `QUOTA_SELF_PANEL` застава је искључена.                      |
| 401    | `Valid API key required`                                                                           | Кључ недостаје или је неважећи или је кључ окружења сервера.  |
| 403    | `API key lacks the self:usage scope`                                                               | Кључу недостаје `self:usage`.                                 |
| 400    | `Invalid provider`                                                                                 | Сегмент добављача је неважећи.                                |
| 429    | `Too many lending changes. Retry later.`                                                           | Кључ је прешао границу. Одговор носи `Retry-After`.           |
| 400    | `Body must be { pool, lendingPercent, lendingUntil }. lendingPercent is an integer from 0 to 100.` | Тело није JSON, предугачко је или се не подудара са шемом.    |
| 400    | `lendingUntil must be a Unix time in milliseconds`                                                 | Рок се чита као секунде.                                      |
| 400    | `lendingUntil must be in the future`                                                               | Рок је у или пре времена захтева.                             |
| 404    | `Pool not found`                                                                                   | `ref` не именује скуп овог кључа за овог провајдера.          |
| 403    | `Lending is not enabled for this pool`                                                             | Базен је у `saturation` режиму и `lendingPercent` је изнад 0. |
| 500    | `Failed to build quota view`                                                                       | Сваки други неуспех. Његов узрок је евидентиран на серверу.   |

Ограничење је 20 захтева у 60 секунди за сваки кључ. Сваки захтев који прође проверу провајдера се рачуна, чак и онај касније одбијен или онај који ништа не мења. Има свој бројач, осим ограничења брзине захтева за кључ.

Захтев који мења сачувану сагласност уписује један `quota.pool.lending.updated` запис ревизије. Он именује кључ са старим и новим вредностима. Исти орган два пута пише једном и једном ревидира. Одговор је 200 са пуним `GET` приказом, направљеним након писања.

Приказ `GET` извештава о позајмљивању на следећи начин:

- Сваки базен носи `borrowMode` (`saturation` или `consent`), и сопствени `lendingPercent` и `lendingUntil` кључа.
- `lendingActive` је `true` само у `consent` скупу, са процентом изнад 0 и роком који није достигнут.
- У `consent` базену, сваки пребројив `dimensions[].yourShare` носи `borrowAvailable`. То је оно што кључ сада може користити изнад свог удела, позајмљеног од других кључева.
- `borrowAvailable` користи формулу капије. Чита сваки други кључ, такође док је кључ испод свог дела. За `hard` кључ који је једно додатно читање по другом кључу и пребројива димензија, паралелно.
- `borrowAvailable` је `null` за `soft` или `burst` кључ, а `null` када читање не успе.
- `borrowAvailable` је једна фигура за све остале кључеве заједно. У групи од два кључа то је сопствена фигура другог кључа.
- `borrowAvailable` још није пријављен за `percent` виндовс или `accounts[]`.
- У `saturation` скупу приказ извештава сачувану сагласност са `lendingActive: false` и без `borrowAvailable`.

### Грешке

Сваки одговор ове руте, успех или грешка, носи `Cache-Control: no-store`. Одбијање које се деси пре него што се рута покрене не носи га, на пример политику API клијента 401 или IP филтера 403. Грешке руте користе стандардно тело грешке са фиксном поруком: 400 (неважећи провајдер), 401 (недостаје или неважећи кључ), 403 (недостаје `self:usage`(зкд ), (`Failed to build quota view`) . 500 покрива сваки неуспех када захтев стигне на руту, укључујући само тражење кључа; његов узрок се евидентира на серверу и никада се не враћа. Грешке `PATCH` су наведене у [сагласности за позајмицу](#lending-consent).

### Ограничења

- `remaining` је део поштеног удела кључа који није користио. То није гаранција. Кључ се може и даље сервирати док базен има места. Једном када укупан износ скупа достигне `limit`, сваки кључ скупа се одбија, без обзира на његов сопствени `remaining`, а кључ без `self:account-quota` не може видети тај укупни износ.
- `remaining` не узима у обзир апсолутни `cap` алокације. Извршење одбија кључ када његова сопствена потрошња у прозору јединице капа достигне вредност ограничења.
- Трака на нивоу налога долази из кеша ограничења провајдера и може да одложи одлуку о примени за неколико минута. Очитавање чије је време ресетовања прошло се пријављује као `stale`.
- Прозори по моделу (`modelWindows`) се пријављују само за провајдере који данас имају мапирање плана и прозора: Claude и Codex. За друге провајдере `modelWindows` је и даље присутан када се прикажу подаци о налогу, са празном `windows` листом.
- Сопствени удео кључа у `percent` прозору је процена. Долази из књиге атрибуције и носи сва ограничења наведена у одељку „Проценат димензија: приписивање по кључу“ изнад.
- `consumed` је број који се упоређује са правичним уделом. Тачно је `attributed` плус `external`. `attributed` је део који књига даје кључ за токене које је усмерила. `external` је део употребе налога који кључеви скупа не узимају у обзир.
- Оба дела се шаљу само када је `accountVisible` тачан: кључ има `self:account-quota` и провајдер је у свом `sharedQuotaProviders`. Кључ без њега добија сам `consumed`, са истим `status` и `reason`.
- Са оба дела и сопственом тежином, држач може да реши употребу ван базена која се наплаћује на кључеве базена. Власник са опсегом налога већ види укупан износ рачуна.
- Кључ који ништа није рутирао у прозору и даље може да прочита свој спољашњи набој из `consumed`, јер је тада његов приписани део 0.
- На пример, књига се отвара на 0, са кључевима А и Б тежине 50 сваки. Кључ А усмерава 900.000 токена, а кључ Б 100.000. Рачун тада достиже 60% ограничења од 100. Тада је `attributed` 54 за кључ А и 6 за кључ Б, а `external` је 0 за оба.
- Поглед чита књигу и никада не пише њено стање. Не отвара књигу и никада не тражи од добављача читање. Са Redis складиштем, читање уклања замењена поља ревизије у позадини, као што то чине читања капије.
- Удео је `ok` само док кеш капије држи читање налога. Без једног то је `stale`, тако да се у групи без недавног захтева приказује као да је можда застарео.
- Док захтев не прође кроз скуп, деоница је недоступна. Тај захтев отвара књигу, а цифра налога у том тренутку се рачуна као коришћење ван базена.
- У групи са неколико налога, сваки унос рачуна користи сопствену књигу тог налога и ограничење једног налога. Извршење скалира обе стране према броју рачуна, тако да је пропорција иста.
- Прозори по моделу немају удео за кључ. Књига не садржи податке по моделу.
- Резервни спратови распореда се не процењују приказом: распоред се може приказати као `open` док је захтев одбијен са разлогом `schedule-reserve`.
- Када два скупа истог кључа деле везу, примена примењује једно од њих, а приказ наводи оба.
- Не постоји ограничење по адреси за неуспеле покушаје кључа: иза обрнутог проксија позиваоци могу да деле једну адресу (зависи од тога да ли су прослеђене клијентске адресе поуздане), тако да би закључавање могло да ускрати руту сваком држачу кључа. Код `REQUIRE_API_KEY=true`, API политика клијента одбија неважећи кључ пре него што се рута покрене, са телом те политике 401 уместо тела ове руте.

### Употреба чланова

Администратор може дозволити власницима кључева да виде како се употреба прозора дели између чланова групе. Опција је `memberBreakdown` базена, подразумевано искључена. Поставља се у чаробњаку базена или помоћу `PATCH /api/quota/pools/{id}`. `GET /api/quota/pools` и `GET /api/quota/pools/{id}` то пријављују.

Димензија погледа носи `members` само када све ово има:

- опција базена је укључена
- базен има највише 20 додељених кључева, а најмање три од њих могу да поднесу захтеве: активни, нису опозвани, нису забрањени и нису истекли
- `accountVisible` базена је истинит: кључ има `self:account-quota` и провајдер је у свом `sharedQuotaProviders`
- у прозору `percent`, веза налога је она коју кључ може да користи
- прочитан је сопствени удео кључа у том прозору: његов `status` није `unavailable`

Иначе `members` је одсутан. Никада није празна листа.

- Свака кришка је `{ slot, consumed, isYou }`. Шема одговора одбија било које друго својство на делу и листу од више од 20 пресека. Слице су наведене по редоследу утора.
- Постоји један исечак по додељеном кључу, укључујући кључ који више не може да поставља захтеве. Члан без употребе показује праву нулу.
- Слот 1 је увек кључ за тражење, са `isYou` труе. Остали бројеви слотова су рангови хеша са кључем. Кључ је `API_KEY_SECRET` и покрива базен, кључ за тражење и члан.
- Дакле, бројеви се не слажу између држача. За једног носиоца остају исти између посета. Могу се променити када се кључ придружи или напусти базен, или када се та тајна ротира.
- У прозору који се може бројати, исечак је бројач члана у складишту квота, исти бројач као и његов сопствени `consumed`.
- На прозору `percent` исечак је `attributed` део члана, из исте књиге који се чита као сопствени део кључа. Употреба ван базена никада се не дели на кришке. Тај набој је подељен по тежини, тако да би кришке које су га носиле показале тежине.
- Сваки поглед чита једну вредност по другом члану и прозору који се може бројати, паралелно. На прозору `percent` делови не коштају читање осим прочитане књиге. Када се једна вредност не може прочитати, тај прозор нема `members`, а сопствени удео кључа остаје.
- Опција и број употребљивих кључева се читају једном по групи, и то само за кључ који може да види податке налога. Неуспешно читање опције или броја употребљивих кључева искључује траке за тај скуп. Сервер бележи упозорење, а остатак приказа је изграђен.

Шипке немају имена или ИД. Они и даље говоре кључном носиоцу ствари о другим члановима:

- Носиоци и даље могу да упореде делове по вредностима.
- Стабилно нумерисање омогућава носиоцу да прати једног члана током времена.
- Број исечака показује колико је кључева додељено у групи.
- У групи од три кључа, неко ко зна шта је користио један кључ може рећи шта је користио последњи кључ.
- Када базен падне испод три употребљива кључа, шипке нестају. Прегледи снимљени раније и даље показују шта је сваки члан користио.
- У прозору који може да се преброји, укупни скуп минус пресеци може да покаже употребу кључева који више нису додељени.
- Члан који показује нулу на једном налогу и користи на другом може показати који члан користи који налог.
- У пребројивом скупу са политиком `hard`, део који престаје да расте на правичном уделу члана наговештава тежину тог члана.

### Серија употребе (`GET /api/v1/me/usage`)

`GET /api/v1/me/usage?range=<range>` (такође служи на `/v1/me/usage`) враћа употребу и цену сопствених захтева позивног кључа: укупне вредности, један унос по UTC дану, по дану и моделу, по моделу и по провајдеру. Дели заставу, правила аутентикације, `self:usage` опсег, `Cache-Control: no-store` и понашање грешке горње руте квоте. Кључ се проверава пре `range`. Грешке су 400 (`Invalid range`), 401, 403, 404 и 500 (`Failed to build usage`).

- `range` је један од `1d`, `7d`, `30d` (подразумевано) или `90d`. Било која друга вредност, празна вредност или поновљени параметар је 400. Скуп се зауставља на `90d` да би ограничио цену позива. Поглед чита само необрађену историју коришћења, никада дневне резимее, који немају кључ.
- Редови се бирају према ИД-у тастера за позивање. Колона имена кључа се никада не подудара, а редови снимљени без ИД-а кључа се никада не броје.
- Изградња серије покреће пет груписаних упита над редовима кључа у прозору. Изграђена серија се поново користи 60 секунди по кључу и опсегу, а поново коришћени позив не покреће ниједан. Његова `generatedAt` даје своје године.
- Прозор се завршава када је серија изграђена. Ред утиснут касније, на пример нагибом сата, се не рачуна.
- `coverage.retentionDays` је операторова необрађена поставка задржавања историје коришћења (`retention.usageHistory` у подешавањима базе података). `coverage.truncatedByRetention` је тачно када је тражени опсег дужи од те поставке. Он упоређује два броја и не проверава да ли редови заиста недостају.
- Провајдер се враћа као снимљен за сопствене захтеве кључа. Модел је забележено име после последњег `/`, а редови су груписани по њему. Комбиновани захтев чији је сваки циљ одбијен се бележи са ознаком рутирања као провајдером (име комбинације, `auto` или `combo`) и низом модела који је клијент послао. Остали одбијени захтеви, на пример због отвореног прекидача, хлађења модела или прескакања квоте, задржавају циљног добављача и модел.
- Поред бројања и трошкова, одговор носи просечно кашњење, стопе успеха и време првог и последњег захтева.
- `byModel` наводи 50 парова добављач и модел са највише захтева. Са више парова, његови уноси се не збрајају у `summary`, а `summary.uniqueModels` броји сваки снимљени модел правописа. `byModelTruncated` је тада тачно, а модел чији парови падају на обе стране реза показује делимичне укупне вредности.
- Пријављена су два трошка. `costUsd` је фактурисани трошак, како то показује аналитика коришћења. Провајдери претплате по фиксној тарифи, као што је план Claude Цоде, рачунају 0 долара тамо. `listPriceUsd` је иста употреба по цени по цени, укључујући претплате. Захтев чији модел нема ред са ценом рачуна његов сачувани трошак: трошак који је провајдер пријавио или онај који је израчунат када је захтев забележен. Само захтев са ниједним не рачуна 0, без маркера, тако да укупан износ може бити делимичан.
- Уговор о одговору је `src/shared/schemas/selfUsage.ts` (`SelfUsageSeries` у `docs/openapi.yaml`).

### Самоуслужна страница

Када је `QUOTA_SELF_PANEL` укључен, `/quota/{provider}` је јавна страница. Држач кључа тамо уписује API кључ и види скупове тог кључа за провајдера. Сваки базен приказује једну картицу по прозору базена, са коришћењем базена за свакога и сопственим уделом кључа. Сваки рачун пула има своје картице, са коришћењем рачуна и уделом кључа. Коришћење налога се појављује само када кључ може да види податке о налогу. Страница такође наводи ограничења по моделу за сваки налог и сопствену употребу кључа. Појављује се обавештење када распоред блокира кључ управо сада. Картица наводи сваку капу кључа по моделу са његовом употребом и означава оне достигнуте. `{provider}` је ИД добављача или његов псеудоним (`/quota/claude`, `/quota/cc`). Непознати провајдер и свака `/quota/*` путања док је заставица искључена, одговорите на 404. Скупови на прилагођеном чвору компатибилном са ОпенАИ или Антхропиц немају страницу. API и даље одговара уместо њих.

Страница нема сесију. Кључ се шаље само у `Authorization` заглављу `GET /api/v1/me/quota/{provider}`, `PATCH /api/v1/me/quota/{provider}` и `GET /api/v1/me/usage`, никада у URL. Кључ који сервер прихвата чува се у `sessionStorage` картици. Са „Запамти на овом уређају“ уместо тога се чува у `localStorage`, а „Заборави кључ“ га уклања из оба. Кључ који сервер одбије уклања се из складишта.

Пул у `consent` режиму приказује кредитну картицу. Тамо држач кључа поставља цео проценат од 0 до 100 неактивног дела кључа за позајмљивање. Власник такође бира колико дуго сагласност траје: док се не искључи, 1 сат, 8 сати, 24 сата, 7 дана или 30 дана. Трајање се рачуна од тренутка чувања. Док је рок на снази, носилац га може задржати. Ако тај рок прође пре Саве, картица не шаље ништа и тражи други избор. Са 0% се не шаље рок. Картица приказује сачувани рок са назначеном временском зоном. Сагласност чији је рок истекао се приказује као завршена.

За `hard` кључ, картица такође наводи, по прозору базена, који други кључеви сада позајмљују кључу. Сваки ред је једна фигура за све остале тастере заједно. У групи од два кључа то је сопствена фигура другог кључа. Број који приказ не извештава се чита као недоступан, а не као нула. За кључ `soft` или `burst` картица каже да се не примењује никаква цифра.

Група у `saturation` режиму чији кључ чува проценат изнад 0 показује само повлачење. Пише да сачувани проценат тамо нема ефекта. Његово дугме за повлачење шаље 0 без рока. Група у `saturation` режиму са меморисаним 0 не приказује кредитну картицу. Након чувања, картица која враћеном приказу више није потребна остаје са поруком док се поново не промени приказ странице.

Ништа се не чува док држалац не притисне Сачувај или Повуци. Сваки притисак шаље један `PATCH /api/v1/me/quota/{provider}` захтев, а други притисак не шаље ништа док је први на чекању. Тело носи непрозирни `ref` базена из погледа, процента и рока. Одговор је обновљени приказ квоте, а страница га приказује без другог читања. Када се два чувања преклапају, страница чита квоту једном након последњег одговора. Страница не чува сагласност у меморији претраживача.

Одбијена промена је објашњена на картици текстом изабраним из статуса HTTP. Тело грешке се не чита. 401 каже да кључ није прихваћен и поново учитава квоту. 403 каже да фонд не прима промене зајма, а 404 каже да је фонд нестао. Оба нуде дугме које поново учитава квоту. 400 или други 4кк одговор тражи од носиоца да провери проценат и рок. А 429 тражи од носиоца да сачека, са секундама `Retry-After` када их добије одговор. Одговор 5кк, 408 или грешка на мрежи говори да промена можда није сачувана и задржава откуцане вредности. Одговор ван уговора поново учитава квоту. Неуспело чување не уклања кључ само по себи. Када је поновно учитавање након што је одбијено, страница уклања кључ као код сваког одбијеног читања.

Када се кључ прихвати, страница такође приказује картицу „Подесите своје алате“ са три картице. "Claude Цоде" даје `env` блок за `~/.claude/settings.json`. „Шелл“ даје исте варијабле као `export` линије. „Claude Десктоп“ даје вредности за свој прозор за закључивање треће стране. Модели су модели поделе квоте које кључ може да захтева за тог провајдера. Када таква листа не долази са кључем, блок уместо тога укључује откривање модела мрежног пролаза. Адреса мрежног пролаза је јавно API порекло које сервер пријављује (`OMNIROUTE_PUBLIC_API_BASE_URL`, затим `OMNIROUTE_PUBLIC_BASE_URL`). Када ниједно није подешено, картица приказује чувар места и говори власнику да пита администратора. Кључ је приказан као чувар места. „Укључи мој кључ“ ставља цео кључ у текст на екрану и оно што дугме за копирање копира. То траје све док се кутија не обрише, кључ не заборави или замени или се страница не остави. Картица не шаље захтеве и не нуди преузимање датотека.

Читање API ознака `stale` је приказано као можда застарело. Читање које означава `unavailable` приказано је са својим разлогом, никада као нула.

На процентуалним плановима страница извлачи сопствени удео кључа када га API пријави. Каже да је број процена и именује своја два дела. Ограничења по моделу приказују само налог.

Када прозор носи `members`, његова картица такође приказује траку са једним сегментом по члану, по редоследу утора. Сегмент кључа питања користи боју акцента. Остали сегменти круже кроз боје дијаграма теме. Легенда текста наводи сваки сегмент са његовом вредношћу, тако да ништа не зависи од боје. Сегменти су означени `You` или `Member N`, где је Н слот.

### Наменски порт за страницу

`QUOTA_PANEL_PORT` отвара други слушалац који служи само самоуслужној страници. Искључен је осим ако променљива није подешена. `QUOTA_PANEL_HOST` је адреса везивања и подразумевано је `127.0.0.1`.

Слушалац преноси ове путање до главног порта и одговара 404 за сваку другу путању:

| Пут                                                                      | Служи                              |
| ------------------------------------------------------------------------ | ---------------------------------- |
| `/quota/{provider}`                                                      | Страница                           |
| `/api/v1/me/quota/{provider}`, `/v1/me/quota/{provider}`                 | Приказ квоте на страници гласи     |
| `/api/v1/me/usage`, `/v1/me/usage`                                       | Серија употребе коју страница чита |
| `/_next/static/`                                                         | Скрипте, стилови и фонтови израде  |
| `/favicon.ico`, `/favicon.svg`, `/icon-512.png`, `/apple-touch-icon.png` | Иконе                              |

`GET` и `HEAD` се преносе без тела. Један захтев са телом се такође преноси: `PATCH` путање приказа квоте, коју страница шаље да сачува избор позајмљивања. Било који други метод одговара на 404, осим на CONNECT захтев, чија је веза затворена без одговора. Сваки други захтев који проглашава тело одговара на 404 и његова веза је затворена. Захтеви за надоградњу се одбијају и њихова веза је затворена. Путања са сегментом тачке или маркером фрагмента је одбијена, као на API порту. Као и циљ захтева са карактером изван ASCII за штампање. На необрађени контролни карактер у циљу HTTP парсер одговара 400, пре сопствене провере овог порта. Заглавља захтева која оквир резервише за сопствену употребу се не преносе: имена која почињу са `x-middleware-`, `x-invoke-`, `x-nextjs-`, `x-now-` или `x-next-`, и имена `x-matched-path` и `next-resume`. Захтев се преноси без њих. Контролна табла, страница за пријаву, API за управљање и руте закључивања не могу се приступити преко овог порта.

`PATCH` мора да носи `Content-Type: application/json`, без параметра или само са `charset=utf-8`. Мора да носи један `Content-Length` од 1 до 4096, написан као обичне цифре, и не `Transfer-Encoding`. `PATCH` који крши једно од ових правила одговара 404. На неке криво обликоване дужине, као што је потписана или поновљена, HTTP парсер одговара 400 пре сопствене провере овог порта. Порт чита декларисане бајтове пре него што контактира главни порт и чека на њих највише 5 секунди. Тело које до тада није комплетно одговара на 404 и његова веза је затворена. Ништа не стиже до главног порта у том случају, или када клијент први напусти. Порт преноси тачно декларисане бајтове, са истим `Content-Length`. Бајтови после њих се читају као следећи захтев на вези. TLS обрнути прокси испред мора да проследи `Content-Length` и не сме поново да дели тело захтева. Главни порт проверава API кључ у `Authorization` заглављу, као и за `GET`.

Тело 404 је `{"error":"not_found","message":"Not found."}`. Неуспели релеј одговара на 502 (`api_bridge_unavailable`) или 504 (`api_bridge_timeout`) без поља `detail`.

Слушалац не чита `QUOTA_SELF_PANEL` и не укључује страницу. Док је заставица искључена, страница и њен API одговарају 404 на главном порту, а слушалац преноси тај одговор.

Под развојним сервером (`next dev`), страница не постаје интерактивна преко овог порта. Развојни хот-релоад соцкет је захтев за надоградњу, а порт га одбија. Користите главни порт док развијате.

Порт служи обичан HTTP, а страница шаље API кључеве. Задржите подразумевану адресу повезивања и ставите обрнути прокси са TLS испред њега. Адреса повезивања која није повратна петља евидентира ово обавештење:

```text
[Quota Panel] Bound to <host>. This port serves plain HTTP and the page sends API keys. Put a TLS reverse proxy in front of it.
```

Пеер који не шаље заглавље за прослеђивање рачуна се као локални на главном порту. Дакле, прокси на истом хосту мора послати `X-Forwarded-For`. Прокси на приватној адреси је поуздан за то заглавље само са `OMNIROUTE_TRUST_PROXY=private` (или `lan`). Било који други равноправни уређај се пријављује према адреси његове везе, а заглавља за прослеђивање које је послао се избацују.

Слушалац истовремено има највише 256 веза. Клијент има 10 секунди да пошаље заглавља захтева и 30 секунди да пошаље цео захтев. Веза која се одржава у стању мировања се затвара након око 5 секунди. Веза без активности 60 секунди је затворена. Ове вредности су фиксне. Поставите ограничења везе и брзине на обрнутом проксију такође испред. Обрнути прокси испред треба да задржи своје неактивне узводне везе мање од 5 секунди или да их не користи поново. Релеј главног порта користи временско ограничење упстреам порта API (`API_BRIDGE_*`).

Слушалац се такође покреће када `API_PORT` није подешен. `QUOTA_PANEL_PORT` мора бити порт од 1 до 65535, написан само цифрама. Мора се разликовати од порта на контролној табли и API порта. Док је живи WebSocket сервер укључен, он се такође мора разликовати од `LIVE_WS_PORT` (подразумевано 20132). Било која друга вредност не отвара ништа и бележи упозорење. Упозорење о одбијеној вредности именује променљиву и не понавља вредност. Порт који је већ у употреби не отвара ништа и бележи ово упозорење:

```text
[Quota Panel] Port <port> is already in use. The quota panel port stays off.
```

Са `OMNIROUTE_BASE_PATH` скупом, слушалац очекује сваку путању изнад под тим префиксом. Користите исти `OMNIROUTE_BASE_PATH` у време градње и током извођења. Напишите га са почетном косом цртом и без косе црте на крају, на пример `/omniroute`. Други облик, укључујући `/` и `/omniroute/`, оставља порт искључен са упозорењем, иако буилд прихвата те форме. Као и основна путања чији први сегмент именује руту апликације: `api`, `v1`, `v1beta`, `_next`, `quota`, `dashboard`, `docs`, `login`, `codex`, `responses`, `anthropic`, `openai`, `v0` или `connect`, у сваком случају.

Ограничења:

- `/quota/{provider}/` са косом цртом на крају одговара 404 на овом порту.
- Сервисни радник и манифест веб апликације се не приказују на овом порту.
- Прилагођени фавицон постављен на контролној табли није приказан на овом порту.
- Иконе се не приказују када апликација ради под основном путањом.
- Лука говори једноставно HTTP/1.1.
- Повезивање које не успе се не покушава поново док се процес поново не покрене.
- Слушалац нема везу или ограничење брзине по адреси клијента.
- Подешавања контејнера нису обухваћена овим одељком.

## Решавање проблема

### Redis је конфигурисан, али се не повезује

Проверите да ли је `ioredis` инсталиран (`npm ls ioredis`) и да ли је
`QUOTA_STORE_REDIS_URL` доступан. У случају неуспешног повезивања, фабрика се
враћа на SQLite (евидентирано на нивоу `warn`).

### `peek` враћа застареле податке / дозвољава захтев при грешци

Ако `peek` изазове грешку, `enforceQuotaShare` третира резултат као „дозволи“
(дозвољавање при грешци). Проверите `pino` логове за уносе `quota:enforce` и
`quota:factory` како бисте утврдили основни узрок.

### Одступање бројача потрошње

Ако се стварна потрошња код провајдера разликује од бројача, то је очекивано —
клизни прозор са 2 сегмента има грешку од приближно 1% на границама прозора, а
`consume` се извршава без чекања на резултат након одговора. Сигнал засићења
(`saturationSignals.ts`) очитава стварну искоришћеност код провајдера са TTL-ом
од 30 секунди и у складу с тим прилагођава `globalUsedPercent`.

### Скуп приказује „нема података“ за стопу потрошње

`computeBurnRate` захтева најмање 2 историјска узорка. Нови скупови без претходних
`consume` позива приказиваће `tokensPerSecond: 0` и `timeToExhaustionMs: null`.

## Миграција са localStorage

Када се `/dashboard/costs/quota-share` први пут учита, hook `useLocalStoragePoolMigration`
проверава:

1. `localStorage.getItem("omniroute:quota-share:pools")` није празан.
2. `GET /api/quota/pools` враћа `[]` (база података је празна).

Ако су оба услова испуњена, сваки застарели pool се пакетно шаље на `POST /api/quota/pools`,
а затим се localStorage кључ уклања. Миграција је идемпотентна: услов 2 спречава
поновну миграцију.

## Интерна класификација стратегије

`quota-share` је стратегија рутирања **само за интерну употребу** (`INTERNAL_ROUTING_STRATEGY_VALUES` у
`src/shared/constants/routingStrategies.ts`). Користе је искључиво системски генерисане
`qtSd/` pool комбинације и намерно је изостављена из `ROUTING_STRATEGY_VALUES`, тако да се никада
не појављује као опција коју корисник може да изабере у корисничком интерфејсу или API-ју.

## DB Резиме шеме

Три табеле додане миграцијама `078`, `079` и `085`:

- `quota_pools` + `quota_allocations` — дефиниције базена и алокације по кључу.
- `quota_consumption` — бројачи са 2 кашике по `(apiKeyId, dimensionKey)`.
- `provider_plans` — ручни план добављача замењује (димензије JSON по connectionId).

Све табеле су додате путем идемпотентних `CREATE TABLE IF NOT EXISTS` миграција.

Сагласно позајмљивање додаје три колоне: `quota_allocations.lending_percent` (цео број, подразумевано 0), `quota_allocations.lending_until` (милисекунде епохе или `NULL` без рока) и `quota_pools.borrow_mode` (подразумевано `saturation`). Његова миграција само додаје ове колоне и не уписује постојећи ред.

Књига процента атрибуције додаје `quota_percent_ledger` (један ред по групи, налогу и прозору плана) и `quota_percent_ledger_tokens` (један бројач токена по групи, налогу и API кључу). `src/lib/db/quotaPercentLedger.ts` их чита и пише.
