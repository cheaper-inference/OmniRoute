Користите овај водич да бисте изабрали најмањи поуздани развојни циклус за pull request. Он не
замењује доле повезане документе о архитектури и безбедности специфичне за појединачне области; он повезује сваки уобичајени
тип измене са његовим уговорима, усмереним проверама и покривеношћу у CI-ју.

## Путања коју прати свака измена

1. **Изаберите основу пре уређивања.** Пронађите највишу активну грану `release/v*` и направите грану од
   њеног врха. Циљајте ту грану, а не `main`. Ако је на снази замрзавање издања, немојте циљати замрзнуту
   грану; користите следећи активни циклус описан у документу
   [Модел гранања и издавања](BRANCHING_MODEL.md).
2. **Наведите уговоре.** Идентификујте сваки каталог, шему, генерисани артефакт, јавни API или кориснички
   интерфејс на који измена утиче. Табела испод даје минимални почетни скуп.
3. **Напишите или ажурирајте усмерене тестове.** Измене продукционог кода у `src/`, `open-sse/`, `electron/` или
   `bin/` захтевају аутоматизовани тест у истом PR-у. Покрените најмањи скуп тест-датотека који доказује
   понашање, а затим наведене усмерене контроле.
4. **Препустите CI-ју покретање широке матрице.** Комплетни сегменти јединичних тестова, Vitest, праг покривености и
   продукциона изградња покрећу се у PR-у. Покрените шири скуп локално само када усмерени неуспех указује на
   шири утицај или када измена обухвата неколико подсистема.
5. **Ускладите пре прегледа.** Преузмите активну основу, прегледајте њене нове commit-е и разлику своје гране у односу
   на њу, а затим извршите rebase или merge основе у складу са процесом за доприносиоце. Решите конфликте у генерисаним датотекама
   и каталозима полазећи од њиховог извора, поново их генеришите, поново покрените усмерени циклус и потврдите да
   PR и даље циља активну грану издања.
6. **Забележите доказе.** У PR шаблону наведите покренуте команде, сваку додату или измењену тест-датотеку,
   миграције или feature flag-ове и све провере које се обављају само у CI-ју, а још увек су на чекању.

## Препоручене путање према типу измене

Команде испод представљају минималне усмерене провере, а не дозволу да се прескочи тест који непосредно покрива
понашање које сте изменили.

### Провајдер

**Уговори**

- Дефиниција провајдера у `src/shared/constants/providers/` и њено састављање у
  `src/shared/constants/providers.ts`.
- Модели и могућности у `open-sse/config/providerRegistry.ts` или његовим издвојеним датотекама регистра.
- Избор извршиоца/преводиоца, OAuth конфигурација или конфигурација API кључа, ресурси контролне табле и генерисана
  референца провајдера, када је применљиво.
- Јавни акредитиви морају користити `resolvePublicCred()`; одговори са грешкама морају користити дељене помоћне функције за
  санитизацију грешака. Погледајте `docs/security/PUBLIC_CREDS.md` (git; не компајлира се у `/docs`) и
  [Санитизација грешака](../security/ERROR_SANITIZATION.md).

**Усмерени циклус**

```bash
npm run check:provider-consistency
npm run check:provider-assets
node --import tsx/esm --test tests/unit/provider-translate-path-golden.test.ts
node --import tsx/esm --test tests/unit/<provider-or-executor>.test.ts
npm run gen:provider-reference   # када се каталог промени; commit-ујте генерисану разлику
npm run lint
```

Такође тестирајте сваку породицу захтева на коју измена утиче: ћаскање, Responses, слике, угнежђивања, аудио или видео.
Прегледајте генерисане разлике каталога и референтних резултата као измене уговора; немојте их прихватати без провере.

### Усмеравање

**Уговори**

- Јавне вредности стратегија и метаподаци корисничког интерфејса у `src/shared/constants/routingStrategies.ts`.
- Диспечирање и редослед у `open-sse/services/combo.ts` и `open-sse/services/combo/`.
- Combo шеме, перзистенција, стање отпорности, могућности модела и API/UI контроле.
- [Auto-Combo механизам](../routing/AUTO-COMBO.md) и документација о отпорности када се понашање промени.

**Усмерени циклус**

```bash
node --import tsx/esm --test tests/unit/combo-<behavior>.test.ts
npm run test:combo:matrix        # измене стратегије или диспечирања
npm run check:known-symbols      # измене регистрације стратегије
npm run lint
```

Локално користите детерминистичке тестове са симулираним надређеним сервисима. Live combo smoke тестови захтевају акредитиве и
ручни су, а не замена за CI.

### UI / UX

**Уговори**

- Границе Next.js руте/странице и дељених компоненти у `src/app/` и
  `src/shared/components/`.
- Облици API одговора, стања учитавања/празног садржаја/грешке, понашање тастатуре и читача екрана,
  прилагодљив распоред, теме и проширење локалитета.
- Изворни енглески UI ниске у `src/i18n/messages/en.json`; немојте директно уписивати нови текст намењен корисницима.

**Усмерени циклус**

```bash
node --import tsx --test tests/unit/dashboard/<feature>.test.ts
npx vitest run --config vitest.config.ts tests/unit/ui/<component>.test.tsx
npm run check:dashboard-typecheck
npm run lint
```

Покрените апликацију за измене интеракције или визуелног приказа и проверите и уске и широке приказе. CI покреће
продукциону изградњу и шире скупове тестова; визуелно понашање и даље захтева усмерени тест компоненте, Playwright
тест или документовану ручну проверу примерену измени.

### i18n

**Уговори**

- `src/i18n/messages/en.json` је извор за UI; `config/i18n.json` је извор локалитета.
- CLI каталози се налазе одвојено у `bin/cli/locales/`.
- Сачувајте ICU чуваре места и ознаке без икаквих измена. Немојте преводити називе производа/провајдера/модела,
  називе протокола и заглавља, команде, идентификаторе кода/JSON-а, URL-ове, променљиве окружења или
  заштићене термине као што су `OmniRoute`, `OAuth`, `MCP` и `A2A`. Тренутна изворна листа је
  `scripts/i18n/glossary/protected-terms.json`.

**Усмерени циклус**

```bash
npm run i18n:sync-ui:dry
npm run i18n:check-ui-coverage
npm run i18n:check-value-drift
npm run i18n:check-glossary
npm run check:cli-i18n          # када се промене CLI ниске/каталози
npm run lint
```

Ово су смернице за постојећи систем, а не позив за проширење његових алата или модела кључева.
Нека i18n исправке буду строго ограничене док се пројектује заменски систем. Немојте покретати команде за превођење
које позивају спољне сервисе осим ако задатак изричито захтева генерисане преводе и
ако сте прегледали насталу разлику.

### CLI

**Уговори**

- Javne komande i zastavice u `bin/cli/`, generisane API komande, izlazni kodovi, stdout/stderr i
  strukture JSON izlaza, ponašanje konfiguracije/okruženja i datoteke uključene u paket.
- Tekstovi CLI-ja namenjeni korisnicima moraju koristiti CLI i18n sloj, a katalozi `en`/`pt-BR` moraju ostati usklađeni.
- Očuvajte Node kao podržano izvršno okruženje i ugovor objavljenog binarnog programa.

**Fokusirani ciklus**

```bash
node --import tsx/esm --test tests/unit/cli/<command>.test.ts
npm run check:cli-i18n
npm run build:cli             # izmene generisanog/upakovanog CLI-ja
npm run check:pack-policy     # izmene javne površine paketa
npm run lint
```

Koristite tačnu komandu u privremenom direktorijumu podataka kada ponašanje zavisi od parsiranja, datoteka ili izlaznog
statusa. CI obavlja šire provere artefakata paketa i ekosistema.

### Baza podataka

**Ugovori**

- Domenski moduli nalaze se u `src/lib/db/`; direktno uvozite određene module (stari sloj za ponovni izvoz `localDb.ts` je uklonjen).
- Numerisane, idempotentne SQL migracije nalaze se u `src/lib/db/migrations/`, uz transakcionu bezbednost, ponašanje pri nadogradnji,
  indekse i svakog pozivaoca na kojeg šema utiče.
- Rute i rukovaoci nikada ne izvršavaju sirovi SQL direktno.

**Fokusirani ciklus**

```bash
npm run check:migration-numbering
npm run check:db-rules
node --import tsx/esm --test tests/unit/db/<domain>.test.ts
node --import tsx/esm --test tests/unit/db/migration-<number>.test.ts
npm run lint
```

Pri dodavanju migracije testirajte i novu bazu podataka i nadogradnju sa prethodne šeme. Testovi baze podataka
moraju zatvoriti resurse i pozvati `resetDbInstance()` tokom čišćenja. Pokrenite `npm run test:bun:db` samo kada
se promeni eksperimentalna putanja Bun adaptera; Node ostaje merodavan.

### Izgradnja / implementacija

**Ugovori**

- Korenski manifesti i manifesti radnih prostora/datoteka zaključavanja, `scripts/build/`, samostalno sklapanje Next.js-a, sadržaj
  paketa `dist/`, metapodaci Electron platforme, CI tokovi rada i kontrolne oznake implementacije.
- Podržani opsezi Node verzija i dozvoljena upotreba Bun-a navedena u `CLAUDE.md` moraju ostati netaknuti.
- Artefakti izgradnje ostaju izvan praćenja; primenjuju se pravila za zavisnosti, licence, tokove rada i pakete.

**Fokusirani ciklus**

```bash
node --import tsx/esm --test tests/unit/build/<behavior>.test.ts
npm run check:build-scope
npm run check:lockfile         # izmene zavisnosti ili datoteke zaključavanja
npm run check:pack-policy      # izmene javne površine objavljenog paketa
npm run lint
```

Lokalno koristite `npm run build` samo kada izmena utiče na kompilaciju, samostalno sklapanje, resurse
ili pakovanje izvršnog okruženja. Koristite `npm run build:release` samo za validaciju izdanja/implementacije. CI izgradnja je
konačni signal za više platformi; izmene Electron-a specifične za platformu zahtevaju odgovarajuću fokusiranu izgradnju
ili dokaz osnovne provere.

## Развојне скрипте за дељену машину

Две помоћне скрипте у `scripts/dev/` дефинишу локални циклус рада на развојној машини на којој су активне и друге сесије:

```bash
scripts/dev/typecheck-touched.sh --base release/vX.Y.Z   # датотеке из merge-base(HEAD, base)..HEAD
scripts/dev/typecheck-touched.sh src/a.ts tests/unit/b.test.ts   # тачно ове датотеке
scripts/dev/new-worktree.sh fix/1234-slug release/vX.Y.Z  # изоловано радно стабло, безбедно за паралелни рад
```

- `typecheck-touched.sh` проверава типове само у измењеним `.ts/.tsx` датотекама помоћу привремене
  датотеке `tsconfig.touched.tmp.json` (`extends ./tsconfig.json`, `types: ["node"]`, `noEmit`,
  `incremental: false`) уз heap од 6 GB, па замењује проверу целог пројекта командом `tsc -p tsconfig.json`,
  која остаје без меморије на оптерећеној машини. Исписује грешке у измењеним датотекама и један ред
  са сажетком, а завршава се кодом `1` за грешке у измењеним датотекама, кодом `2` када су једине
  грешке у увезеним датотекама или када се tsc прекинуо без дијагностике (прочитајте именовани
  дневник у `_artifacts/typecheck-touched/`), односно кодом `0` када нема грешака. Привремени
  tsconfig се увек уклања; никада га немојте комитовати.
- `new-worktree.sh` серијализује истовремена покретања помоћу
  `<git-common-dir>/omniroute-new-worktree.lock` (подразумевано чека до 600 s, уз видљиву поруку;
  заглавље скрипте документује како се то може заменити) и поништава
  грану коју је направио када `git worktree add` не успе пре него што радно стабло настане, тако да
  за поновни покушај није потребно ручно извршавати `git branch -D`. Чврсто повезани `node_modules`
  и копија `.husky/_` остају непромењени.

## Локални циклус кандидата

Тестови изворног кода не могу да докажу да се упаковани артефакт успешно покреће: спискови за
паковање, уклоњене зависности и нативне бинарне датотеке отказују тек када се tarball инсталира и
покрене. `npm run dev:candidate` (`scripts/dev/candidate.mjs`) представља локалну страну тока
направи-једном / провери / промовиши из RFC #8084: прави једног кандидата, проверава управо тај
артефакт, промовише га преименовањем директоријума и враћа га на претходно стање када промовисани
слот не прође проверу исправности.

```bash
npm run dev:candidate -- run --dry-run --json  # испиши план, не мењај ништа
npm run dev:candidate -- run                   # направи + провери + промовиши, аутоматски врати уназад
npm run dev:candidate -- build                 # npm pack + инсталирај у _artifacts/candidate/<id>/
npm run dev:candidate -- validate --id <id>    # покрени на слободном порту, /api/health + /v1/models
npm run dev:candidate -- promote --id <id>     # <id> → current, current → previous
npm run dev:candidate -- rollback              # замени current и previous
npm run dev:candidate -- run --from-tarball <file.tgz>  # поново употреби tarball направљен другде (CI)
```

- **Направи једном.** `build` пакује тренутно стабло (потребан му је `dist/server.js`, па прво
  покрените `npm run build:release`) или копира `--from-tarball`, а затим инсталира tarball у
  изоловани npm префикс, јер tarball не садржи `node_modules`. Идентификатор је кратки `HEAD`
  sha (`-dirty` када стабло има локалне измене) или `tgz-<sha256>` за tarball. Чист идентификатор
  који је већ направљен поново се користи уместо поновне изградње; проследите `--force` да бисте га
  поново направили.
- **Проверавајте пакет, а не изворни код.** `validate` покреће инсталирани CLI
  (`serve --port <free port>`) са новим `DATA_DIR=<candidate>/data`, лажним тајнама и операторовим
  `OMNIROUTE_API_KEY`, `STORAGE_ENCRYPTION_KEY` и `INITIAL_PASSWORD` уклоњеним из окружења, чиме
  проверава подешавање нове инсталације за loopback без кључа. Чека да `GET /api/health` врати 200,
  захтева да `GET /v1/models` врати 200, зауставља групу процеса и бележи исход у `validation.json`
  заједно са хешом tarball датотеке.
- **Промовишите исти артефакт.** `promote` одбија кандидата без успешне провере за његов тренутни
  хеш tarball датотеке. Подразумевани активни слот је `_artifacts/candidate/current`;
  `--target <dir>` бира други директоријум на истом систему датотека, а његов претходни слот је
  `<dir>.previous`. Свако преименовање је атомско, а отказивање током поступка поништава већ
  извршена преименовања.
- **Вратите на претходно стање.** `run` поново проверава промовисани слот и замењује `current` и
  `previous` назад када та провера не успе. Кандидат који не прође прву проверу никада се не
  промовише.

Све се уписује у git-игнорисани `_artifacts/candidate/`; постојећа OmniRoute инсталација и њен
директоријум са подацима никада се не мењају. Промовисани CLI је
`_artifacts/candidate/current/prefix/bin/omniroute`; када га користите, покрените га са сопственим
`DATA_DIR`. Излазни кодови: `0` успех, `1` неуспешна провера или промоција, `2` грешка у употреби
или недостајућа изградња.

## Локална петља наспрам CI-ја

| Покретање локално за сваку измену                                                   | CI пружа шири сигнал                                                                 |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Директни тестови понашања и горенаведене провере категорија                         | Подељен комплет свих јединичних тестова и серијски тестови                           |
| `npm run lint`                                                                      | Vitest скупови тестова и механизми за пооштравање покривености/квалитета             |
| Провера типова или изградња само када то захтева уговор на који измена утиче        | Продукциона изградња, безбедност, документација, зависности и провере смерница за PR |
| Ручне провере интеракције/уживо само када аутоматизација не може да докаже понашање | Провере интеграције између послова и провере платформи конфигурисане током рада      |

Успешна фокусирана петља представља доказ о измењеном уговору, а не доказ да ће неповезане CI провере
проћи. С друге стране, немојте да свака локална измена чека комплетну матрицу репозиторијума.

## Контролна листа за усклађивање

Пре него што затражите преглед:

- Потврдите да је основна грана PR-а и даље највиша активна грана `release/v*`.
- Преузмите ту основну грану и прегледајте комитове који су додати откако сте направили своју грану.
- Прегледајте `git diff <active-base>...HEAD` ради случајних или генерисаних непотребних измена.
- Решите конфликте у каталогу и генерисаним документима ажурирањем извора и поновним генерисањем излаза.
- Након усклађивања поново покрените сваки фокусирани тест/проверу наведену у опису PR-а.
- Никада немојте ублажавати тврдње нити уклањати обавезне тестове само да бисте се ускладили са помереном основом.

За правила замрзавања издања и промене циљне гране користите
[Модел гранања и издавања](BRANCHING_MODEL.md). За потпун списак CI провера користите
[Референцу провера квалитета](../architecture/QUALITY_GATES.md).
