Како OmniRoute процењује, бележи и приказује трошак сваког захтева — и зашто број на
контролној табли представља **праћење уштеде**, а не рачун.

Погледајте и: [Корисничко упутство](./USER_GUIDE.md) · [Галерија функција](./FEATURES.md)

## Шта јесте (а шта није)

OmniRoute сваком довршавању приписује трошак у USD по захтеву тако што множи број
токена ценама одговарајућег модела. Ови бројеви се користе за контролну таблу
**Трошкови**, CLI команде `omniroute cost` / `omniroute usage`, CSV/JSON извозе и
буџете по API кључу.

> **„Трошак“ на контролној табли представља праћење уштеде, а не рачун.** OmniRoute вам
> никада ништа не наплаћује — он усмерава ваше захтеве ка добављачима које сте већ
> повезали (ваше претплате, бесплатни нивои и API кључеви). „Укупан трошак од $290“
> остварен искључиво на бесплатним моделима значи да приближно **$290 _нисте_ платили**
> API-ју који се плаћа. Тај износ је _процена_ тога колико би исти саобраћај коштао по
> стандардним каталошким ценама, како бисте могли да видите где је ваша употреба
> концентрисана и колико штедите усмеравањем ка јефтинијим/бесплатним добављачима.

Ово тумачење је директно наведено у пројектном документу [README](../../README.md)
(„'трошак' на контролној табли представља праћење уштеде, а не рачун“).

Пошто је овај број процена:

- Зависи од табеле цена коју OmniRoute има за сваки модел. Модел без уноса цене
  доприноси трошку са `0` (у прегледачу се приказује као ред „Застарело / Бесплатно“).
- Саобраћај у оквиру бесплатног нивоа и претплате и даље акумулира _процењени_
  трошак — то је износ који штедите, а не износ који дугујете.

## Како се процењују трошкови

### Извор цена

Трошкови потичу из обједињене табеле цена у [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts), овим редоследом приоритета (** највиши први** ):

1. **Корисник замењује** — цене постављене на контролној табли или преко `PATCH /api/pricing` ( `pricing` именског простора).
2. **моделс.дев синц** — цене преузете из `https://models.dev/api.json` ( `models_dev_pricing` именски простор).
3. **LiteLLM синц** — цене преузете из LiteLLM-овог јавног `model_prices_and_context_window.json` ( `pricing_synced` именског простора).
4. **Хардцодед дефаултс** — стопе се испоручују у [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/).

За исти provider/model, вредности из слојева вишег приоритета замењују поља која се подударају у нижим слојевима; поља која су одсутна из горњег слоја могу ипак доћи из нижег слоја. Редослед је фиксан чак и када се оба независна посла синхронизације покрећу у исто време. `GET /api/pricing?includeSources=1` враћа `pricing` и `sourceMap`, чије ознаке по моделу (`user`, `modelsDev`, `litellm`, `default`) идентификују слој највишег приоритета који садржи тај модел.

**LiteLLM синц** је омогућено, подразумевано онемогућено. Његове променљиве окружења (погледајте [`.env.example`](../../.env.example) ) су:

| Енв вар                 | Подразумевано | сврха                                                                        |
| ----------------------- | ------------- | ---------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`       | Омогући синхронизацију цена LiteLLM у позадини.                              |
| `PRICING_SYNC_INTERVAL` | `86400`       | Интервал синхронизације у секундама (дневно).                                |
| `PRICING_SYNC_SOURCES`  | `litellm`     | Избор извора само за ову синхронизацију; тренутно је подржан само `litellm`. |

**моделс.дев синц** је одвојено од LiteLLM синхронизације и такође је подразумевано онемогућено. Омогућите га у подешавањима (моделс.дев синхронизација) или користите ове променљиве:

| Енв вар                    | Подразумевано  | сврха                                                                                                                                     |
| -------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(неподешено)_ | Унсет прати прекидач Подешавања; `1/true/on/yes` се укључује и `0/false/off/no` принудно искључује (чак и ако подешавања то омогућавају). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`        | Подразумевани интервал синхронизације моделс.дев у секундама (дневно).                                                                    |

`PRICING_SYNC_SOURCES` доес** не** енабле моделс.дев; контролише само LiteLLM синхронизацију. Брисањем замене корисника не бришете ни синхронизовани простор имена; следећи доступни слој цена постаје ефикасан. За модел без цене, проверите и подешавања синхронизације и `sourceMap` пре него што додате ручно замена.

### Формула трошкова

Цена се израчунава по захтеву из броја токена и стопа на милион токена у [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`):

- **Улазни токени** (минус кеш читања и токени за креирање кеша) × `input` брзина.
- **Токени за читање кеша** × `cached` стопа (пада назад на улазну брзину).
- **Токени за креирање кеша** × `cache_creation` стопа (пада назад на улазну брзину).
- **Излазни токени** × `output` рате.
- **Реасонинг токенс** × `reasoning` стопа (пада назад на излазну стопу).

Све стопе се тумаче као USD на 1.000.000 токена. Ниво услуге Codex „брзи“/„приоритет“ или „флексибилни“ примењује множилац трошкова (`getCodexFastCostMultiplier`) —, нпр. флек се наплаћује уз попуст од 50% токена, приказан као** флек штедња** у контролној табли.

Називи модела се прво нормализују (префикси путање добављача као што су `openai/` или `accounts/fireworks/models/` су уклоњени) тако да историјски редови и даље одговарају цени.

### Како се евидентира потрошња

- Цена по захтеву се израчунава по завршетку захтева. Потрошња дељене квоте је заказана за следећу петљу догађаја преко [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts).
- Потрошња АПИ кључа је баферована и испрана у серијама помоћу [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (подразумевани интервал испирања од 60 секунди, бафер од 1000 уноса). Подесиво преко:

  | Енв вар                             | Подразумевано | сврха                                           |
  | ----------------------------------- | ------------- | ----------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`       | Интервал испирања у милисекундама.              |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`        | Максимални број баферованих уноса пре испирања. |

Трошкови преферирају тачну наплату коју је пријавио провајдер (`provider_cost_usd`), затим снимак захтева по каталошким ценама (`calculated_cost_usd`), а затим поновну цену токена из тренутног каталога. Сачувани трошкови се не наплаћују поново кроз њихов број токена. Застарели редови само за токене се и даље мењају када се њихова каталошка цена промени.

### OCR и уградње

- Успешни `/v1/ocr` захтеви користе упстреам `usage_info.pages_processed`, а не захтевани опсег страница или број враћених објеката странице. Процена је страница × `ocr_cost_per_page` (апсолутно USD/page,** не** USD/million).
- Захтеви са напоменама у документима или граничним оквирима захтевају посебну `ocr_cost_per_annotated_page` тарифу. Без тога, цена остаје непозната; обична OCR тарифа није тихо замењена.
- LiteLLM синц мапира своје узводно `annotation_cost_per_page` поље у `ocr_cost_per_annotated_page`, задржавајући апсолутну вредност USD/page и уносе само за напомене, укључујући експлицитну нулу. Достављено канонско поље има предност; неважеће вредности алијаса се занемарују. Замена корисничких цена задржава свој уобичајени приоритет. Погледајте [LiteLLM-ове OCR кључеве за одређивање цена](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking).
- OCR употреба чува број страница, јединичну цену, израчунату USD цену, API кључ и изабрану везу. Странице се никада не представљају као токени. Евиденције позива садрже метаподатке о обрачуну, а не документ URLs, PDF бајтове или екстраховани текст.
- Успешни `/v1/embeddings` захтеви бележе један ред употребе по физичкој групи, укључујући одвојене серије завршене у истој милисекунди. Накнаде које пријави провајдер имају предност над проценама токена; комбиновани омоти не наплаћују.
- Историја коришћења, анализа трошкова, provider/account прозори, ограничења потрошње АПИ кључева, књига трошкова захтева и дневни подаци о коришћењу укључују ове трошкове. Кључеви без евиденције задржавају нумеричко рачуноводство без задржавања изворног текста.
- Недостаје употреба или тарифе су** непознато** , није бесплатно: заглавље цене одговора је изостављено, а постојећа политика коришћења без цене се примењује на ограничене API кључеве. Експлицитно конфигурисане нулте стопе остају важеће за коришћење без трошкова.

Ово је само унапред рачуноводство. Стари OCR/embedding позиви који никада нису писали историју коришћења не могу се реконструисати из ове миграције. Процене каталога су USD процене, а не фактура, и не укључују конверзију валута, порез или попусте.

### Говор и слике

- Успешни покушаји `/v1/audio/transcriptions`, `/v1/audio/speech` и генерисања слика деле нумеричко рачуноводство. Директни и комбиновани позиви носе API тастер позиваоца и изабрану везу; комбиновани омот никада не додаје друго задужење.
- USD коју је пријавио провајдер побеђује каталошку процену, укључујући експлицитну нулту наплату. OpenRouterJSON `usage.cost` је нормализован на `cost_usd`. Иначе, измерени токени користе цене токена, секунде за транскрипцију користе цене по секунди, говорни унос користи Уницоде број знакова, а слике са фиксном ценом користе стварно враћени број, а не тражени `n`.
- Бинарни OpenRouter TTS нема тело употребе JSON. Након што се звук заврши или позивалац откаже, OmniRoute поставља упит за своју генерацију ID на** исто** конфигурисано OpenRouter порекло. EU захтев се никада не враћа на глобално порекло. Ово је ограничено претраживање само за читање; синтеза се не покушава поново за рачуноводство. Записи наплате се могу појавити након што се звук заврши: покушаји тражења се покрећу у позадини до око 52 секунде, укључујући мрежне рокове.
- Током тог тражења, аудио одговор има `X-OmniRoute-Cost-Status: pending` и нема заглавље цене одговора. Његова коначна наплата се појављује у историји коришћења, аналитици и кључној књизи након усаглашавања. Ако су метаподаци недоступни, користи се снимак конфигурисане тарифе; иначе трошак остаје непознат.
- Број секунди, знакова и слика имају засебна поља обрачунске јединице, никада лажни број токена. Рачуноводство задржава само нумеричку употребу, а не говорни текст, транскрипте или бајтове слике. Постојећа изузећа за слике без цене су непромењена: стварно недостајућа тарифа за слике не закључава поново ограничени кључ, а одговор изоставља заглавље трошкова уместо да проглашава позив бесплатним. Грешка продавнице цена и даље задржава доказе о коришћењу за примену принудног затварања.

Никаква историјска speech/image наплата није измишљена или затрпана. Наплата провајдера остаје референца за фактуре и за позиве чија наплата није пријављена.

## Контролна табла: страница Трошкови

Страница **Трошкови** налази се на `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`).
Њен главни приказ је картица **Преглед трошкова**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
која учитава све преко `GET /api/usage/analytics`.

Шта приказује:

- **Плочице потрошње** — процењена потрошња за _данас (1d)_, _7d_, _30d_ и изабрани
  период. Бирач опсега: `7d`, `30d`, `90d`, `all`.
- **Главне метрике** — захтеви у оквиру периода, активни добављачи, активни модели, просечан
  трошак по захтеву.
- **Истраживач трошкова** — табела која се може сортирати и филтрирати, груписана по **добављачу**, **моделу**,
  **API кључу**, **налогу** или **нивоу услуге**, са трошковима, захтевима, токенима, просечним
  трошком по захтеву и процентуалним уделом у укупном износу.
- **Потрошња токена** — укупан број / улазни / излазни токени и однос улазних и излазних токена.
- **Ефикасност усмеравања** — број резервних преусмеравања, стопа резервних преусмеравања и покривеност захтеваног модела.
- **Месечна прогноза** — пројектује потрошњу до краја месеца на основу недавног дневног просека.
- **Поређење периода** — процентуална промена између прве и друге половине периода.
- **Графикони** — дневни тренд трошкова, удео добављача (кружни графикон), водећи добављачи, водећи модели, трошкови
  по API кључу, трошкови по налогу, седмични образац коришћења и топлотна мапа активности.
- **Извоз** — преузимање података за тренутни период у формату **CSV** или **JSON** (дугмад се појављују
  када постоје подаци о трошковима већим од нуле).

Када нема тарифираних захтева, редови уместо `$0` приказују ознаку „Застарело / Бесплатно“,
у складу са моделом праћења уштеде.

### Повезане потстранице о трошковима

Област Трошкови такође садржи (све под `/dashboard/costs/`):

- **Цене** (`/dashboard/costs/pricing`) — приказ и измена цена по моделу (приказује
  заједничку картицу Цене).
- **Буџет** (`/dashboard/costs/budget`) — постављање ограничења потрошње по опсегу (приказује заједничку
  картицу Буџет).
- **Дељење квоте** (`/dashboard/costs/quota-share`) — скупови дељених квота и прикази
  стопе потрошње.

## API крајње тачке

Све ово захтева ауторизацију управљања (loopback/JWT, преко `requireManagementAuth`) осим ако није наведено.

### Аналитика употребе и трошкова

| Метод | Крајња тачка             | сврха                                                                                                                                                      |
| ----- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | Потпуна cost/usage аналитика: резиме, дневни тренд, од provider/model/API key/account/tier. Упит: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET` | `/api/usage/utilization` | Коришћење квоте по добављачу током времена. Упит: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                             |
| `GET` | `/api/usage/history`     | Необрађени редови историје коришћења.                                                                                                                      |
| `GET` | `/api/usage/call-logs`   | Дневници позива по захтеву (модел, токени, цена, кашњење, статус).                                                                                         |
| `GET` | `/api/usage/quota`       | Статус квоте добављача.                                                                                                                                    |
| `GET` | `/api/usage/proxy-logs`  | Дневници захтева за прокси.                                                                                                                                |

### Буџети

| Метод  | Крајња тачка             | сврха                                                                                        |
| ------ | ------------------------ | -------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | Резиме трошкова + провера буџета за један API кључ (потребан је `apiKeyId` параметар упита). |
| `POST` | `/api/usage/budget`      | Поставите daily/weekly/monthly USD лимит + праг упозорења за API кључ.                       |
| `GET`  | `/api/usage/budget/bulk` | Групни резимеи буџета преко API кључева.                                                     |

> Буџет API је обухваћен по**API кључ** (`apiKeyId`). Ограничења која враћа `GET /api/usage/budget` укључују `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`, а `warningThreshold` и текуће збројеве (`totalCostToday`, `totalCostMonth`, …).

### Прицинг

| Метод    | Крајња тачка            | сврха                                                                                                                                                       |
| -------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |

## CLI

OmniRoute CLI pruža komande za troškove, korišćenje i cene (registrovane u
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

Izveštaj o troškovima objedinjen iz `/api/usage/analytics`.

```bash
omniroute cost                          # poslednjih 30 dana, grupisano po provajderu
omniroute cost --period 7d              # poslednjih 7 dana
omniroute cost --group-by model         # grupiši po provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

Kolone: grupa, zahtevi, ulazni/izlazni tokeni, trošak (USD) i procenat ukupnog iznosa. Red sa ukupnim zbirom
ispisuje se na kraju (izostavlja se uz `--quiet` ili `--output json`).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # pregled troškova po provajderu
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# Budžeti
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` čita `GET /api/pricing/defaults`. Da biste umesto toga izmenili cene pojedinačnih modela,
> koristite stranicu **Cene** na kontrolnoj tabli ili `PATCH /api/pricing`.

## Rešavanje problema

- **Svi troškovi prikazuju $0 / „Nasleđeno / Besplatno“.** Modeli koji se koriste nemaju unos sa cenom.
  Omogućite spoljnu sinhronizaciju (`PRICING_SYNC_ENABLED=true`) i pokrenite `omniroute pricing sync` ili
  ručno podesite cene preko stranice Cene / `PATCH /api/pricing`.
- **Cena istorijskog modela je pogrešna.** Ispravite cenu (zamenite je ili ponovo sinhronizujte) — trošak se
  ponovo izračunava na osnovu broja tokena pri svakom čitanju analitike, pa se procene retroaktivno ažuriraju.
- **Potrošnja kasni za stvarnim vremenom.** Potrošnja po ključu obrađuje se grupno; smanjite
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ako su vam potrebni ažurniji podaci.
