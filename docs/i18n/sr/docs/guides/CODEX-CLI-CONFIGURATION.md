Комплетан водич за коришћење Codex CLI-ја усмереног на OmniRoute као позадински систем компатибилан са OpenAI-јем.

---

> **TOML је једини формат који се заиста примењује.** Савремени Codex чита искључиво
> `~/.codex/config.toml` (проверено са codex-cli 0.147.0: `codex --help` наводи да
> `-c/--config` замене „учитавају из `~/.codex/config.toml`“). Стари
> `~/.codex/config.yaml` припадао је застарелом npm CLI-ју и неприметно се игнорише.
> Генератор на контролној табли (`/api/cli-tools/apply`, алатка `codex`) уписује TOML уз
> конзервативно спајање — постојећи кључеви и блокови других провајдера остају сачувани,
> API кључ остаје у `OMNIROUTE_API_KEY` (никада у датотеци), а преостали застарели
> `config.yaml` пријављује се као напомена о миграцији без икаквих измена.

## config.toml спреман за налепљивање

Замените `<YOUR_HOST>` и `<YOUR_KEY>` својим вредностима:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # ограничење чувања историје по позиву алатке

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc или ~/.zshrc — стварна вредност кључа, никада у config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex укључен у ChatGPT апликацију

Ако сте Codex инсталирали преко ChatGPT десктоп апликације, бинарна датотека `codex` можда
постоји само унутар пакета апликације и још увек није на `PATH` путањи ваше љуске. Додајте
директоријум са ресурсима у датотеку која се учитава при покретању љуске:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Отворите нову љуску, а затим проверите:

```bash
command -v codex
codex --version
```

### Локални OmniRoute без аутентификације: довољан је заменски кључ

Codex проверава да ли променљива окружења наведена у `env_key` постоји
**пре** него што први захтев напусти CLI. Ако ваша **локална** OmniRoute
инстанца не захтева аутентификацију, довољна је било која непразна заменска вредност:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Уместо тога користите стварни кључ када је ваш OmniRoute сервер заштићен или удаљен.

> **Уобичајене опције за хост**
>
> | Приступ        | URL                           |
> | -------------- | ----------------------------- |
> | Локална мрежа  | `http://192.168.0.1:20128/v1` |
> | Tailscale      | `http://100.x.x.x:20128/v1`   |
> | Повратна петља | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — зашто ради са свим моделима

Codex CLI је у фебруару 2026. означио `wire_api = "chat"` (Chat Completions) као застарео и сада **захтева** `wire_api = "responses"` (OpenAI Responses API). Подешавање `wire_api = "chat"` изазива тренутни пад при покретању почев од v0.138.

Многи провајдери, укључујући GLM и Kimi, и даље нуде само Chat Completions крајњу тачку. DeepSeek V4 сада нуди и изворни Responses API и крајњу тачку компатибилну са Anthropic-ом; OmniRoute подразумевано користи Responses и омогућава да свака DeepSeek веза изабере компатибилност са Anthropic-ом.

**OmniRoute ово решава транспарентно:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute бира изворни протокол провајдера и преводи када је потребно
    → POST /responses (DeepSeek V4) или /chat/completions (Mistral / GLM / Kimi / остали)
```

Када користите OmniRoute, никада вам није потребан засебан прокси за превођење. **Сви модели користе `wire_api = "responses"`** — OmniRoute се стара за остало.

> **`wire_api` је подразумевана вредност** — поље подразумевано има вредност `"responses"` и може се потпуно изоставити из `config.toml`. Експлицитно га задајте само ако документујете намеру.

## Контекстни прозор и сажимање

### Поља за конфигурацију токена

| Поље                             | Опис                                                                                                                                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Укупан буџет токена за активни модел. Подесите га на декларисано ограничење модела.                                                                                                               |
| `model_auto_compact_token_limit` | Праг који покреће аутоматско сажимање историје. **Максимум: 90% од `model_context_window`** — вредности изнад 90% се неприметно игноришу.                                                         |
| `tool_output_token_limit`        | Ограничење броја токена који се чувају у историји по излазу позива алатке. Спречава да један велики одговор алатке попуни прозор. **Ово није максимални излаз** — већ ограничење чувања историје. |
| `compact_prompt`                 | Уграђено замењивање системског упита који се користи током сажимања (v0.138+).                                                                                                                    |

> **Напомена о `model_max_output_tokens`**: Ово поље **није део конфигурационе шеме Codex CLI-ја** (не постоји у Codex Rust бази кода). Ако се подеси, неприметно се игнорише. Немојте се ослањати на њега — користите `tool_output_token_limit` да бисте контролисали колико се излаза алатке чува у историји.

## Интензитет резоновања

Контролише колико модел „размишља“ пре него што одговори.

| Вредност | Користити за                                                 |
| -------- | ------------------------------------------------------------ |
| `none`   | Без резоновања — директан одговор                            |
| `low`    | Тривијалне задатке (преименовање, форматирање)               |
| `medium` | **Подразумевана вредност сервера** ако није задата           |
| `high`   | Задатке средње сложености (рефакторисање, отклањање грешака) |
| `xhigh`  | Архитектуру, дубоку анализу, сложене проблеме                |

```bash
# Замена вредности за појединачно покретање
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Такође подесите **сажетак** резоновања како би Desktop могао да прикаже текст размишљања (а не само шифроване блокове):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # или ultra када је подржано
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute буџет за размишљање (подешавање сервера)

На OmniRoute хосту, **Settings → AI → Thinking Budget** мора бити подешено на **`passthrough`** како би Codex интензитет/сажетак стигао до узводног сервиса. Режим **`auto` уклања** сва клијентска поља `reasoning` / `reasoning_effort` и испразниће панеле за размишљање чак и када је Codex правилно конфигурисан.

Комплетан водич: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Компресија и кеш упита су независни и настављају да раде у режиму `passthrough`.

## Профили — именоване конфигурације по моделу/току рада

Профили вам омогућавају да промените модел + контекстни прозор помоћу једне опције. Сваки профил је једноставна
`~/.codex/<name>.config.toml` датотека која се примењује преко основне `config.toml` датотеке.

> **Правило именовања (Codex CLI v0.137+):** датотека мора бити `~/.codex/<name>.config.toml` — **без префикса `profile-`**.
> CLI разрешава `-p kimi-k27` → `~/.codex/kimi-k27.config.toml`. Ако датотека није пронађена, подразумевана конфигурација се примењује без упозорења.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # брзо, јефтино
```

### Профили интензитета (исти модел, различит интензитет)

```bash
codex -p low      # cx/gpt-5.5, интензитет=low
codex -p medium   # cx/gpt-5.5, интензитет=medium
codex -p high     # cx/gpt-5.5, интензитет=high
codex -p xhigh    # cx/gpt-5.5, интензитет=xhigh (подразумевано)
codex -p chat     # cx/gpt-5.5, интензитет није подешен (подразумевана вредност сервера)
```

## Аутоматско генерисање профила помоћу `omniroute setup-codex`

Ако покрећете OmniRoute на VPS-у, можете аутоматски да генеришете датотеке профила из активног каталога модела:

```bash
# Са VPS-а (користи локални OmniRoute на порту 20128)
omniroute setup-codex

# Са било ког рачунара — усмерите на свој VPS
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Преглед без уписивања датотека
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Генеришите само GLM и Kimi профиле
omniroute setup-codex --only glm,kimi

# Упишите у прилагођени директоријум
omniroute setup-codex --codex-home /path/to/.codex
```

Команда преузима `/v1/models`, користи оптимизоване профиле за познате моделе, за остале компатибилне текстуалне моделе користи метаподатке каталога као резервну опцију и за сваки од њих уписује `~/.codex/<name>.config.toml`. Идемпотентна је — може се безбедно поново покретати.

Ако основни `config.toml` не садржи дефиницију `model_providers.omniroute`, експлицитно покретање команде
`setup-codex` укључује ту дефиницију у сваки генерисани слој конфигурације, користећи изабрану
локалну или удаљену крајњу тачку. Основна датотека остаје непромењена. Постојећа дефиниција добављача
се наслеђује, укључујући њену крајњу тачку и подешавања аутентификације. Неважећи
основни TOML зауставља генерисање пре уписивања профила.

Када наведете `--api-key` или `OMNIROUTE_API_KEY`, новодефинисани добављач упућује на
`env_key = "OMNIROUTE_API_KEY"`; сам кључ се никада не чува нити приказује у
прегледу. Подесите ту променљиву у окружењу из којег покрећете Codex. Ако
кључ није наведен, нова дефиниција не захтева кључ, што је намењено OmniRoute инстанци
конфигурисаној да прихвата захтеве без аутентификације.

Опциона аутоматска синхронизација каталога описана у наставку задржава дефиниције добављача које већ
постоје у слоју конфигурације, али не иницијализује нова подешавања добављача; најпре конфигуришите добављача
експлицитним подешавањем или преко контролне табле. Постојећа подешавања добављача се изостављају
из прегледа пробног покретања јер могу да садрже акредитиве којима управља оператер.

OmniRoute такође може **аутоматски да синхронизује** ове исте датотеке профила након што успешно откривање/увоз модела добављача измени активни каталог. Ова опција се **укључује ручно и подразумевано је искључена**: укључите је преко **CLI Code контролне табле** („CLI profile auto-sync“ → Codex) или подесите `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (такође поштује `CLI_ALLOW_CONFIG_WRITES`, који је подразумевано укључен). Када је омогућена, уписује само засебне датотеке профила `~/.codex/*.config.toml`; никада не мења активни/подразумевани `~/.codex/config.toml`, Codex-lb подешавања, аутентификацију или избор добављача.

## Дуготрајни задаци

Два OmniRoute подразумевана подешавања могу тихо да саботирају вишесатне Codex CLI сесије. Нити Codex — CLI живи на OmniRoute страни. Корисници који мигрирају конфигурацију са узводних проксија који прикачу налоге и онемогућавају искључења у мировању често погађају оба и закључују да OmniRoute „не може да издржи дугу сесију“.

| Симптом                                                                        | Вероватно узрок                                                                   | Кноб                     |
| ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- | ------------------------ |
| Сесија наставља да мења налоге / континуитет промпт-кеша се губи између окрета | Афинитет сесије TTL је `0` (онемогућено)                                          | `sessionAffinityTtlMs`   |
| Веза умире усред расуђивања без промпта окренутог клијенту                     | Контролер стрима у стању мировања је покренут после 10 минута без претходног дела | `STREAM_IDLE_TIMEOUT_MS` |

Повезане дискусије: [#7126](https://github.com/cheaper-inference/OmniRoute/discussions/7126) (дуги пад задатака), [#5718](https://github.com/cheaper-inference/OmniRoute/discussions/5718) (зашто је афинитет подразумевано искључен). Праћење: [#7287](https://github.com/cheaper-inference/OmniRoute/issues/7287).

### 1. Афинитет сесије — закачи једну конверзацију на један налог

**Подразумевано:** `sessionAffinityTtlMs = 0` (онемогућено).

**Где га поставити**

- Дасхбоард →** Подешавања → Роутинг** →** Афинитет сесије** →** Афинитет TTL (секунде)** (`ComboDefaultsTab`)
- Или PATCH подешавања са `sessionAffinityTtlMs` ин** милисекунди** (Zod опсег `0`–`86_400_000`, тј. до 24 сата)

> Преименовано у #7274 из зкб-а само `codexSessionAffinityTtlMs`. Застарели кључ се и даље прихвата као псеудоним само за читање; нове конфигурације треба да користе `sessionAffinityTtlMs`. Афинитет се сада односи на** било који** провајдер када је TTL изнад `0`, не само Codex — види [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Афинитет сесије.

**Шта се поквари када остане на 0**

Сваки заокрет вишеструког Codex разговора је независно рутиран активном комбинованом стратегијом и може доћи на** различит рачун по окрету** . То прекида континуитет узводне сесије / промпт-кеша. OmniRoute консултује само Codex заглавља сесије (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) и поља тела као што су `prompt_cache_key` / `session_id` када је TTL већи од `0` (`extractSessionAffinityKey` у `src/sse/services/auth.ts`).

**Препоручује се за вишечасовни појединачни задатак**

Поставите TTL** изнад очекиване дужине задатка на зидном сату** (UI мак је** 86400 секунди** = 24 сата):

| Очекивана дужина задатка | Афинитет TTL (UI, секунде) | `sessionAffinityTtlMs` |
| ------------------------ | -------------------------- | ---------------------- |
| Неколико сати            | `14400` (4х)               | `14400000`             |
| Ноћење / ~ 12х           | `43200` (12х)              | `43200000`             |
| Цео дан                  | `86400` (24х, максимум)    | `86400000`             |

Омогућавање је намерно: онемогућавање афинитета фаворизује балансирање оптерећења на свим налозима; омогућавајући да фаворизује континуитет за једну дугу сесију агента. Овај водич ради** не** промените подразумеване — операторе који извршавају дуге Codex задатке морају да се укључе.

### 2. Стреам идле тимеоут — не убија тихо резоновање претвара

**Подразумевано:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 минута). Наслеђује од `REQUEST_TIMEOUT_MS` када није подешен; заједничка основна линија је такође 600000. Погледајте [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → ограничења.

**Шта се квари по подразумеваној вредности**

Codex образложење/окретање алата које остаје нечујно више од 10 минута са** нема правог узводног комада** је принудно затворен од стране SSE идле ватцхдог-а (`open-sse/utils/stream.ts`). Клијент често види да је гола веза испуштена — која одговара „аутоматски заустављена без икаквог обавештења“.

Критични детаљ: OmniRoute синтетички SSE** откуцаји срца се не ресетују** неактивни сат. Само прави горњи део тела ажурира `lastChunkTime`. Тихи модел који још увек „размишља” изгледа идентично заустављеном узводно са тачке гледишта пса чувара.

Повезана неактивност тела Ундици: `FETCH_BODY_TIMEOUT_MS` (такође подразумевано подразумева исту основну линију од 10 минута; `0` је онемогућава). За стримовање, `FETCH_TIMEOUT_MS` покрива само подешавање везе / прва заглавља — када је ток активан, застојима управљају `STREAM_IDLE_TIMEOUT_MS` и `FETCH_BODY_TIMEOUT_MS`.

**Препоручује се за вишечасовни појединачни задатак**

У OmniRoute процесном окружењу (`.env` / цомпосе / системд):

```bash
# Disable stream idle + body inactivity cutoffs for long reasoning turns
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Или их подигните изнад најдуже тихе празнине коју очекујете (вредности су милисекунде):

```bash
# Example: allow up to 2 hours of silence between upstream chunks
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Поново покрените OmniRoute након промене ових енв варс.

### Конкретан рецепт — вишесатни Codex задатак

1. **Закачите налог:** Контролна табла → Подешавања → Рутирање → Сродност сесије → Афинитет TTL = `43200` (12 х) или `86400` (макс. 24 х).
2. **Подигните / онемогућите прекиде у мировању** у окружењу OmniRoute:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Задржите уобичајени Codex `config.toml` (`wire_api = "responses"`, исправан `base_url`, `OMNIROUTE_API_KEY`) — не постоје affinity/idle дугмад на страни Цодека за ова два понашања.
4. Поново покрените OmniRoute, а затим покрените дуг Codex задатак.

### Подразумевана одлука (#7287)

| Кноб                     | Испорука подразумевано | Промена у овом водичу?                                                                            |
| ------------------------ | ---------------------- | ------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (искључено)        | **бр** — остаје укључен (балансирање оптерећења наспрам континуитета; погледајте дискусију #5718) |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 мин)      | **бр** — остаје 10 минута за општи саобраћај; лонг Codex оператори га подижу или онемогућавају    |

Глобално окретање било које подразумеване вредности променило би понашање за сваког клијента инстанце, не само Codex. Документујте дугмад; оставите подразумеване вредности на миру све док експлицитна одлука оператера не каже другачије.

### Дијагностиковање прекида у празном ходу

Када се неактивни чувар активира, OmniRoute бележи линију у облику:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Греп за `Idle timeout: no data from` (или код `stream_idle_timeout` / име грешке `StreamIdleTimeoutError`). Сегмент добављача је било који OmniRoute који се користи за тај захтев (`codex`, ид другог добављача или `provider` ако је непознат) — то није увек литерални стринг `codex`.

---

## Решавање проблема

**`Error: wire_api = "chat" is no longer supported`** Уклоните `wire_api = "chat"` из ваше конфигурације. Поставите `wire_api = "responses"` или изоставите поље (подразумевано је `"responses"` од в0.138).

**`Error: model not found`** Проверите да ли модел постоји у OmniRoute са исправним префиксом. Користите `omniroute models list` или отворите `/dashboard/providers/<provider>`.

**`Authentication error`** Потврдите да је `OMNIROUTE_API_KEY` извезен: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`** Codex потврђује да енв вар постоји пре него што направи први захтев. Извезите прави кључ за заштићене сервере или непразан чувар места као што је `OMNIROUTE_API_KEY=local` када ваш** локални** OmniRoute инстанца не захтева аутх. Поново покрените љуску ако сте је додали у `~/.bashrc` или `~/.zshrc`.

**`Connection refused`** Проверите да ли је OmniRoute покренут и да је `base_url` host/port исправан за вашу мрежу (локални вс Tailscale вс VPS).

**Сесија пада близу ограничења контекста** Експлицитно поставите `model_context_window` и `model_auto_compact_token_limit`. Погледајте табелу контекстног прозора изнад.

**Збијање пали прекасно** Спустите `model_auto_compact_token_limit` на 80–85% прозора. Никада не постављајте изнад 90%.

**Профил се не учитава (`-p <name>` тихо игнорисан)** Потврдите да датотека постоји на `~/.codex/<name>.config.toml` (без `profile-` префикса). Покрени `ls ~/.codex/*.config.toml`.

**Дуги Codex задатак пада у току трчања / мења налоге између окрета** Погледајте [Дуготрајни задаци](#long-running-tasks). Омогућите афинитет сесије (TTL изнад дужине задатка) и подигните или онемогућите `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. Греп OmniRoute евиденције за `Idle timeout: no data from`.
