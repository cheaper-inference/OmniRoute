## 🎯 Случајеви употребе

### Случај 1: „Имам Claude Pro претплату"

**Проблем:** Квота истиче некоришћена, ограничења брзине током интензивног кодирања

```
Комбинација: "maximize-claude"
  1. cc/claude-opus-4-7        (потпуно искористи претплату)
  2. glm/glm-4.7               (јефтина резерва када квота истекне)
  3. if/qwen3.8-max-preview       (бесплатна резерва за хитне случајеве)

Месечни трошак: $20 (претплата) + ~$5 (резерва) = $25 укупно
у поређењу са: $20 + достизање ограничења = фрустрација
```

### Случај 2: „Желим нулти трошак"

**Проблем:** Не могу да платим претплате, потребна ми је поуздана AI подршка за кодирање

```
Комбинација: "zero-cost"
  1. if/kimi-k2.7-code          (наведен као бесплатан приступ; могу се примењивати ограничења брзине)
  2. kr/qwen3-coder-next        (Kiro бесплатна резерва)

Месечни трошак: $0
Квалитет: провери модел, ограничења, приватност и SLA за твоје потребе
```

### Случај 3: „Потребно ми је кодирање 24/7, без прекида"

**Проблем:** Рокови, не могу да дозволим паузе у раду

```
Комбинација: "always-on"
  1. cc/claude-opus-4-7        (најбољи квалитет)
  2. cx/gpt-5.5                (друга претплата)
  3. glm/glm-4.7               (јефтино, ресетује се дневно)
  4. minimax/MiniMax-M2.1      (најјефтиније, ресетовање на 5ч)
  5. if/deepseek-v4-flash       (наведен као бесплатан приступ; могу се примењивати ограничења брзине)

Резултат: 5 резервних слојева проширује отпорност; доступност на страни провајдера није гарантована
Месечни трошак: $20-200 (претплате) + $10-20 (резерва)
```

### Случај 4: „Желим БЕСПЛАТНУ AI у OpenClaw"

**Проблем:** Потребан AI асистент у апликацијама за размену поруку, потпуно бесплатно

```
Комбинација: "openclaw-free"
  1. if/qwen3.8-max-preview     (наведен као бесплатан приступ; могу се примењивати ограничења брзине)
  2. if/deepseek-v4-flash       (наведен као бесплатан приступ; могу се примењивати ограничења брзине)
  3. if/kimi-k2.7-code          (наведен као бесплатан приступ; могу се примењивати ограничења брзине)

Месечни трошак: $0
Приступ преко: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 Подешавање провајдера

Да бисте групно додали везе са API кључевима из CSV или JSON датотеке, користите **Контролна табла → Провајдери → Увези из датотеке**. Колоне су позиционе (`provider,name,apiKey,baseUrl,priority`); `provider` већ мора постојати као управљани провајдер или компатибилан чвор. Погледајте [Увоз провајдера из CSV или JSON датотеке](../providers/CSV-IMPORT.md).

### 🔐 Претплатнички провајдери

#### Claude Code (Pro/Max)

```bash
Контролна табла → Провајдери → Повежи Claude Code
→ OAuth пријављивање → Аутоматско освежавање токена
→ Праћење петочасовне и недељне квоте

Модели:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**Професионални савет:** Користите Opus за сложене задатке, а Sonnet за брзину. OmniRoute прати квоту за сваки модел!

Немате прегледач на OmniRoute хосту? Покрените `claude setup-token` било где где сте пријављени у Claude Code и налепите једногодишњи токен на картицу **Токен за подешавање**. Погледајте [Claude Code са токеном за подешавање](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

Руте компатибилне са Claude и Claude Code чувају `max` ниво интензитета размишљања за моделе Opus и Sonnet. Модели Haiku не прихватају `max` ниво интензитета, па OmniRoute пре слања надређеном сервису такав захтев своди на висок буџет за размишљање.

```bash
Модели:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
Контролна табла → Провајдери → Повежи GitHub
→ OAuth преко GitHub-а
→ Месечно ресетовање (1. у месецу)

Модели:
  gh/gpt-5.5
  gh/gpt-5.4

  gh/claude-opus-4.7
```

### 💰 Јефтини провајдери

#### GLM-4.7 (Дневно ресетовање, $0.6/1M)

1. Региструјте се: [Zhipu AI](https://open.bigmodel.cn)
2. Преузмите API кључ из Coding Plan-а
3. Контролна табла → Додај API кључ: Провајдер: `glm`, API кључ: `your-key`

**Употреба:** `glm/glm-4.7` — **Професионални савет:** Coding Plan нуди 3× већу квоту по 7 пута нижој цени! Ресетује се сваког дана у 10:00.

#### MiniMax M2.1 (Ресетовање на 5 сати, $0.20/1M)

1. Региструјте се: [MiniMax](https://www.minimax.io)
2. Преузмите API кључ → Контролна табла → Додај API кључ

**Употреба:** `minimax/MiniMax-M2.1` — **Професионални савет:** Најјефтинија опција за дугачак контекст (1M токена)!

#### Kimi K2 ($9 месечно, фиксно)

1. Претплатите се: [Moonshot AI](https://platform.kimi.ai?aff=omniroute)
2. Преузмите API кључ → Контролна табла → Додај API кључ

**Употреба:** `kimi/kimi-k2.5` — **Професионални савет:** Фиксних $9 месечно за 10M токена = ефективни трошак од $0.90/1M!

#### Baidu Qianfan / ERNIE

1. Региструјте се: [Baidu AI Cloud Qianfan](https://cloud.baidu.com/product/wenxinworkshop)
2. Направите Qianfan API кључ → Контролна табла → Додај API кључ: Провајдер: `qianfan`

**Употреба:** `qianfan/ernie-5.1`, `qianfan/ernie-x1.1` или други идентификатор Qianfan модела компатибилног са OpenAI-јем.

### 🆓 БЕСПЛАТНИ провајдери

Бесплатни провајдери без аутентификације имају прекидач поред опције **Аутентификација није потребна** на својој страници провајдера.
Његовим искључивањем онемогућава се тај провајдер, уклања се из конфигурисаног/сажетог приказа провајдера и
његови модели се уклањају из `/v1/models`.

## 🚀 Deployment

### Globalna npm instalacija (preporučeno)

```bash
npm install -g omniroute

# Kreirajte konfiguracioni direktorijum
mkdir -p ~/.omniroute

# Kreirajte .env fajl (pogledajte .env.example)
cp .env.example ~/.omniroute/.env

# Pokrenite server
omniroute
# Ili sa prilagođenim portom:
omniroute --port 3000
```

CLI automatski učitava `.env` iz `~/.omniroute/.env` ili `./.env`.

### Tray mod

Pokrenite OmniRoute u sistemskoj traci:

```bash
omniroute serve --tray
```

Komanda se vraća nakon što su server i tray spremni.

Server se nastavlja bez terminala.

Tray mod podržava macOS, Windows i grafičke Linux sesije. Tray mod ne otvara automatski dashboard.

Koristite tray meni za ove radnje:

- Otvorite dashboard.
- Otvorite `/dashboard/logs`.
- Promenite auto-pokretanje.
- Zaustavite OmniRoute.

Nemojte kombinovati `--tray` sa ovim opcijama:

- `--daemon`
- `--log`
- `--no-recovery`

Ovi modovi zahtevaju drugačije vlasništvo procesa.

Omogućite pokretanje pri sledećoj prijavi na mašinu:

```bash
omniroute autostart enable
```

Auto-pokretanje koristi tray mod na macOS, Windows i grafičkim Linux sesijama. Headless Linux koristi postojeći systemd korisnički servis.

Onemogućite pokretanje pri prijavi:

```bash
omniroute autostart disable
```

### Deinstalacija

Kada vam OmniRoute više nije potreban, obezbeđujemo dve brze skripte za čisto uklanjanje:

| Komanda                  | Radnja                                                                                              |
| ------------------------ | --------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | Uklanja sistemsku aplikaciju, ali **zadržava vašu bazu podataka i konfiguracije** u `~/.omniroute`. |

> Napomena: Da biste izvršili ove komande, idite u folder OmniRoute projekta (ako ste ga klonirali) i pokrenite ih. Alternativno, ako je instaliran globalno, možete jednostavno pokrenuti `npm uninstall -g omniroute`.

Void Linux korisnici mogu da paketuju i instaliraju OmniRoute nativno koristeći `xbps-src` framework za cross-kompilaciju. Ovo automatizuje samostalnu Node.js izgradnju zajedno sa potrebnim `better-sqlite3` native bindings.

<details>
<summary><b>Pogledajte xbps-src template</b></summary>

```bash
# Template fajl za 'omniroute'
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
checksum=009400afee90a9f32599d8fe734145cfd84098140b7287990183dde45ae2245b
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# Odredite ciljnu CPU arhitekturu za node-gyp
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) Instalirajte sve zavisnosti – preskočite skripte
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Izgradite Next.js standalone bundle
	npm run build

	# 3) Kopirajte statičke resurse u standalone
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) Kompajlirajte better-sqlite3 native binding
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) Postavite kompajlirani binding u standalone bundle
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) Uklonite arhitekturno-specifične sharp bundle-ove
	rm -rf .next/standalone/node_modules/@img

	# 7) Kopirajte pino runtime zavisnosti izostavljene Next.js statičkom analizom:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# Sprečite uklanjanje praznih Next.js app router direktorijuma post-install hook-om
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

Ako model nije naveden iznad, pokrenite `omniroute models --search <term>` ili pozovite `GET /api/models/catalog` da potvrdite dostupnost.

### Prilagođeni OpenAI-kompatibilni provajderi

Svaki gateway koji govori OpenAI API (samostalno hostovani proxy, vLLM, agregator treće strane) može se dodati kao zaseban čvor provajdera:

1. **Providers → Add OpenAI Compatible**.
2. **Name**: prikazna oznaka čvora.
3. **Prefix**: ime za rutiranje. Klijenti pozivaju modele kao `<prefix>/<model>`, tako da čvor sa prefiksom `mygw` poslužuje `mygw/gpt-4o-mini`. Obavezno; nema ograničenja znakova.
4. **API Type**: familija endpoint-a koje gateway poslužuje (Chat Completions, Responses, Embeddings, audio, slike).
5. **Base URL**: koren API-ja, do `/v1` uključujući i njega (na primer `https://gateway.example.com/v1`), a ne puna putanja `/chat/completions`. Gateway-i sa nestandardnim putanjama podešavaju ih pod **Advanced Settings** (putanja za chat, putanja za modele).
6. Polje **API Key (for Check)** služi samo za testiranje veze. Nakon kreiranja čvora otvorite ga i koristite **Add Connection** da sačuvate ključ koji će zahtevi koristiti.

Čvor dobija interni id oblika `openai-compatible-<apiType>-<uuid>`; nikada ga ne morate kucati — prefiks je javno ime.

#### Rezervisani prefiksi

Prefiks ne može biti id ili alias ugrađenog provajdera (na primer `openai`, `cf`), niti id provajdera povučenog iz upotrebe. Razrešavač modela proverava ugrađene id-ove i aliase pre prilagođenih čvorova, tako da čvor koji koristi jedan od tih prefiksa nikada ne bi primio saobraćaj: `<prefix>/model` bi umesto toga otišao ugrađenom provajderu, ili bi zahtev bezbedno odbio ako je taj provajder povučen iz upotrebe. Kreiranje ili izmena čvora sa takvim prefiksom odbija se porukom:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

Izaberite zaseban prefiks (`mygw`, `acme-proxy`). Ako zahtevi ka prilagođenom čvoru ne uspeju uz grešku koja pominje ugrađenog provajdera ili njegove kredencijale, proverite da li je prefiks čvora rezervisan: čvorovi sačuvani pre nego što je ovo pravilo postojalo i dalje su uskladišteni, ali njihov prefiks rutira ka ugrađenom provajderu. Izmenite čvor i dodelite mu novi prefiks.

#### Opcije gateway-a po vezi

Ovi ključevi idu u `providerSpecificData` veze (na primer preko `PUT /api/providers/{id}`):

- `toolNameMaxLength` (ceo broj, 1–1024) — za veze kompatibilne sa OpenAI chat formatom čiji gateway odbija duga imena alata. Duža imena šalju se kao kratki aliasi i vraćaju se u odgovoru.
- `quotaEndpoint` — endpoint gateway-a za kvote/kredite, koji se čita za traku kvota na Dashboard-u i za rutiranje koje uzima u obzir kvote. Radi i na OpenAI- i na Anthropic-kompatibilnim vezama; pun oblik dokumentovan je u `open-sse/services/usage/openaiCompatible.ts`.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### Lančano povezivanje OmniRoute peer-ova

Drugi OmniRoute gateway može se dodati kao **Custom OpenAI-compatible** provajder. Koristite `/v1` osnovni URL peer-a i namenski API ključ sa najmanjim privilegijama koji izdaje taj peer.

Za recipročne lance ili lance sa više skokova uključite opcionu zaštitu od petlji na svakom gateway-u:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

Samo zahtevi poslati na peer URL koji je eksplicitno na listi dozvoljenih dobijaju zaglavlje `X-OmniRoute-Peer-Trace`. Gateway odbija ponovljeni ID instance ili iscrpljen budžet skokova sa HTTP `508 Loop Detected`; obični upstream provajderi ne primaju nikakve peer metapodatke.

Lančano povezivanje peer-ova nije replikacija baze podataka niti failover hosta. Svaki gateway zadržava nezavisno SQLite stanje, kešove, brojače brzine zahteva i sesije. Koristite reverzni proxy sa proverom zdravlja ili failover na strani klijenta za aktivno/pasivnu ili aktivno/aktivnu dostupnost, i nikada ne montirajte jednu SQLite bazu u više pokrenutih OmniRoute instanci.

### Cloudflare Quick Tunnel

- Dostupno u **Dashboard → Endpoints** za Docker i ostala self-hosted okruženja
- Kreira privremeni `https://*.trycloudflare.com` URL koji prosleđuje ka vašoj trenutnoj OpenAI-kompatibilnoj `/v1` krajnjoj tački
- Prvo omogućavanje instalira `cloudflared` samo kada je potrebno; kasnija ponovna pokretanja ponovo koriste isti upravljani binarni fajl
- Quick Tunnels se ne obnavljaju automatski nakon ponovnog pokretanja OmniRoute-a ili kontejnera; po potrebi ih ponovo omogućite sa kontrolne table
- URL adrese tunela su kratkovečne i menjaju se pri svakom zaustavljanju/pokretanju tunela
- Upravljani Quick Tunnels podrazumevano koriste HTTP/2 transport kako bi se izbegla bučna QUIC UDP upozorenja o baferu u ograničenim kontejnerima
- Postavite `CLOUDFLARED_PROTOCOL=quic` ili `auto` ako želite da zaobiđete upravljani izbor transporta
- Postavite `CLOUDFLARED_BIN` ako preferirate korišćenje unapred instaliranog `cloudflared` binarnog fajla umesto upravljanog preuzimanja
- Paneli Cloudflare Quick Tunnel, Tailscale Funnel i ngrok Tunnel mogu se prikazati ili sakriti u **Settings → Appearance**. Sakrivanje panela ne zaustavlja pokrenuti tunel.

### Strategije rutiranja

Konfigurišite preko **Dashboard → Settings → Routing**. Kontrolna tabla izlaže šest najčešće korišćenih strategija; kombinacije i auto-ruter interno podržavaju širi skup.

**Strategije vidljive na kontrolnoj tabli (rutiranje na nivou naloga):**

| Strategija                     | Opis                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------ |
| **Fill First**                 | Koristi naloge po redosledu prioriteta — primarni nalog obrađuje sve zahteve dok ne postane nedostupan |
| **Round Robin**                | Kružno prolazi kroz sve naloge sa podesivim sticky limitom (podrazumevano: 3 poziva po nalogu)         |
| **P2C (Power of Two Choices)** | Bira 2 nasumična naloga i rutira ka zdravijem — balansira opterećenje uz uvažavanje zdravlja           |
| **Random**                     | Nasumično bira nalog za svaki zahtev koristeći Fisher-Yates shuffle                                    |
| **Least Used**                 | Rutira ka nalogu sa najstarijom `lastUsedAt` vremenskom oznakom, ravnomerno raspoređujući saobraćaj    |
| **Cost Optimized**             | Rutira ka nalogu sa najnižom vrednošću prioriteta, optimizujući za provajdere najniže cene             |

**Napredne strategije za kombinacije i auto-rutiranje** (podesive po kombinaciji ili preko `auto/*` prefiksa — pogledajte [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — strogi redosled, nikada ne rotira
- `weighted` — proporcionalna podela saobraćaja prema težinama po modelu
- `fill-first` — prazni prvi model dok se ne dostignu ograničenja
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` i `cost-optimized`
- `auto` — zasnovan na ocenama svih kandidata
- `lkgp` (Last Known Good Provider) — vezuje se za poslednjeg uspešnog provajdera, zatim se vraća na pravila
- `context-optimized` — bira model sa najvećim slobodnim kontekstnim prozorom
- `context-relay` — ulancava modele dugog konteksta za naredne korake dijaloga

#### Eksterno zaglavlje sticky sesije

Za eksterno vezivanje sesije (na primer, Claude Code/Codex agenti iza reverznih proksija), pošaljite:

```http
X-Session-Id: your-session-key
```

OmniRoute takođe prihvata `x_session_id` i vraća važeći ključ sesije u `X-OmniRoute-Session-Id`.

Ako koristite Nginx i šaljete zaglavlja sa donjim crtama, omogućite:

```nginx
underscores_in_headers on;
```

#### Alijasi modela sa džoker znakovima

Kreirajte džoker obrasce za premapiranje imena modela:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

Džokeri podržavaju `*` (bilo koji znakovi) i `?` (jedan znak).

#### Fallback lanci

Definišite globalne fallback lance koji se primenjuju na sve zahteve:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### Otpornost i prekidači kola

Konfiguriše se preko **Kontrolna tabla → Podešavanja → Otpornost**.

OmniRoute implementira otpornost na nivou provajdera sa pet komponenti:

1. **Red čekanja zahteva i tempiranje** — Oblikovanje zahteva na nivou sistema:
   - **Zahteva po minutu (RPM)** — Maksimalan broj zahteva po minutu po nalogu
   - **Minimalno vreme između zahteva** — Minimalni razmak u milisekundama između zahteva
   - **Maksimalan broj istovremenih zahteva** — Maksimalan broj simultanih zahteva po nalogu

2. **Hlađenje veze** — Konfiguracija po tipu autentifikacije za pojedinačnu vezu nakon grešaka koje se mogu ponoviti:
   - **Osnovno hlađenje** — Podrazumevani period hlađenja za uzvodne greške koje se mogu ponoviti
   - **Koristi uzvodne naznake ponovnog pokušaja** — Poštuje merodavne `Retry-After` ili naznake resetovanja kada su dostavljene
   - **Maksimalan broj koraka eksponencijalnog odlaganja** — Maksimalni nivo eksponencijalnog odlaganja za ponovljene greške

3. **Prekidač kola provajdera** — Prati greške provajdera od kraja do kraja, označava provajdera kao degradiranog pri konfigurisanom pragu upozorenja i otvara prekidač kada se dostigne konfigurisani prag grešaka:
   - **Prag degradacije** — Uzastopne greške provajdera pre ulaska u `DEGRADED`
   - **Prag grešaka** — Uzastopne greške provajdera pre ulaska u `OPEN`
   - **Istek vremena za resetovanje** — Vremenski period pre nego što se provajder ponovo testira
   - **CLOSED** (Zdravo) — Zahtevi protiču normalno
   - **DEGRADED** — Zahtevi i dalje protiču dok se prati povećan broj grešaka
   - **OPEN** — Provajder je privremeno blokiran nakon ponovljenih grešaka
   - **HALF_OPEN** — Testira se da li se provajder oporavio

   Ograničenja brzine `429` u obimu veze ostaju u okviru **Hlađenja veze** i ne uračunavaju se u prekidač provajdera.

   Stanje prekidača provajdera tokom izvršavanja prikazuje se isključivo na **Kontrolna tabla → Zdravlje**.

4. **Čekanje na hlađenje** — Ako se sve kandidatske veze već hlade, OmniRoute može sačekati najranije hlađenje i automatski ponoviti isti zahtev klijenta.

5. **Automatsko otkrivanje ograničenja brzine** — Kada uzvodni provajderi vrate eksplicitne periode čekanja, te naznake imaju prednost nad lokalnim hlađenjem veze kada je podešavanje omogućeno.

**Profesionalni savet:** Koristite stranicu **Zdravlje** da pregledate i resetujete aktivne prekidače provajdera nakon prekida rada. Stranica Otpornost menja samo konfiguraciju.

| Radnja                    | Opis                                                                                                                                                               |

`DELETE /api/cache`. Maksimalni broj redova u logovima zahteva i proksija kontroliše se pomoću
`CALL_LOGS_TABLE_MAX_ROWS` i `PROXY_LOGS_TABLE_MAX_ROWS`.

### Strategije balansiranja combo-a

Balansiranje po combo-u konfigurišite u **Dashboard → Combos → Create/Edit → Strategy**.

| Strategija         | Opis                                                                     |
| ------------------ | ------------------------------------------------------------------------ |
| **Round-Robin**    | Redom prolazi kroz modele sekvencijalno                                  |
| **Priority**       | Uvek prvo pokušava prvi model; na rezervni prelazi samo pri grešci       |
| **Random**         | Za svaki zahtev bira nasumičan model iz combo-a                          |
| **Weighted**       | Usmerava srazmerno, na osnovu težina dodeljenih svakom modelu            |
| **Least-Used**     | Usmerava na model sa najmanje nedavnih zahteva (koristi metrike combo-a) |
| **Cost-Optimized** | Usmerava na najjeftiniji dostupan model (koristi tabelu cena)            |

Globalne podrazumevane vrednosti za combo mogu se podesiti u **Dashboard → Settings → Routing → Combo Defaults**.
Timeout ciljeva combo-a podrazumevano nasleđuje trenutni timeout zahteva. Koristite **Target timeout
(seconds)** na podrazumevanim vrednostima za combo ili na pojedinačnom combo-u samo kada kraće ograničenje
po cilju treba da pokrene brži fallback.

Optimizacije combo-a sa nultom latencijom uključuju se po izboru (opt-in). Ostavite **Zero-latency optimizations** isključene
da biste sprečili da ove funkcije latencije utrkuju fallback ciljeve, preskaču ciljeve na osnovu istorije
TTFT-a ili kompresuju fallback zahteve; njihovo uključivanje omogućava da konfigurisani hedging, prediktivna
preskakanja na osnovu TTFT-a i proaktivna kompresija fallback-a zamene vernost rutiranja/zahteva za nižu
latenciju repa.

Onemogućite **Bafer tokena rasuđivanja** kada uzvodni provajderi zahtevaju stroga ograničenja `max_tokens` / `maxOutputTokens`. Kada je omogućen, kombinovano usmeravanje dodaje rezervni prostor za modele rasuđivanja samo modelima sa poznatim ograničenjem izlaza, a token limit klijenta ostavlja nepromenjenim kada bi bezbedna baferovana vrednost premašila to ograničenje. Ako je limit klijenta već iznad poznatog ograničenja, OmniRoute ga smanjuje na to ograničenje pre slanja uzvodnog zahteva.

## 🤖 Аутоматско рутирање (без конфигурације)

OmniRoute долази са **рутером вођеним оценама (score-driven auto-router)** који бира најбољи модел за сваки захтев преко свих повезаних провајдера — без потребе за одржавањем комбинација. Само пошаљите захтев са једним од `auto/*` префикса и OmniRoute ће у ходу саставити виртуелну комбинацију, оцењујући кандидате на основу латенције, цене, стопе успешности, уклапања у контекст, погодности модела за задатак, недавних отказивања, квоте и стања circuit-breaker-а.

| Префикс        | Оптимизује за                                                                                   |
| -------------- | ----------------------------------------------------------------------------------------------- |
| `auto`         | Уравнотежени подразумевани режим (латенција × цена × стопа успешности)                          |
| `auto/coding`  | Задаци програмирања: преферира Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek coders            |
| `auto/cheap`   | Најнижа цена по токену, прихвата вишу латенцију                                                 |
| `auto/fast`    | Најнижа латенција, игнорише цену                                                                |
| `auto/offline` | Само локални провајдери (Ollama, vLLM, llama.cpp) — корисно за air-gapped системе               |
| `auto/smart`   | Приоритет квалитету закључивања (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)                      |
| `auto/lkgp`    | "Last Known Good Provider" — фиксира се на последњи успешни провајдер, затим прелази на правила |

Пример:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

Аутоматски рутер је потпуно описан у [AUTO-COMBO.md](../routing/AUTO-COMBO.md) — укључујући начин подешавања тежина оцењивања, стављања провајдера на црну листу и увида у одлуке рутирања у **Dashboard → Auto Combo**.

## 🔌 MCP и A2A интеграција

OmniRoute је истовремено **MCP сервер** (Model Context Protocol) и **A2A сервер** (Agent-to-Agent JSON-RPC 2.0). Свако IDE окружење или агент домаћин компатибилан са MCP-ом може директно позивати OmniRoute алате — без потребе за додатним омотачем (wrapper).

### MCP транспорти

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **Streamable HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (за IDE додатке који преферирају stdio)

### Повезивање Claude Desktop

Уредите `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) или еквивалентну путању на Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Повезивање Cursor / Continue / VS Code MCP

Користите SSE URL `http://localhost:20128/api/mcp/sse` и Bearer API кључ генерисан у **Dashboard → API Keys**.

### Опсези (Scopes)

MCP тренутно дефинише 32 именована опсега. Сваки Bearer кључ може бити ограничен на одређене опсеге — погледајте [MCP-SERVER.md](../frameworks/MCP-SERVER.md) за меродаван преглед опсега и алата, и [A2A-SERVER.md](../frameworks/A2A-SERVER.md) за JSON-RPC шему.

## 💾 Sistem memorije

OmniRoute čuva **dugotrajnu konverzacionu memoriju** sa hibridnim pronalaženjem:

## 💻 Interni CLI

OmniRoute dolazi sa internim CLI-jem (`omniroute …`) za podešavanje, dijagnostiku i kontrolu rada. Ovo je **odvojeno od stranice „CLI Tools” u dashboard-u**, koja konfiguriše CLI alate trećih strana (Claude Code, Cursor, Codex, Cline, …) da bi mogli da komuniciraju sa OmniRoute-om.

```bash
omniroute setup                    # Interaktivni čarobnjak (lozinka, provajderi, kombinacije)
omniroute setup --non-interactive  # Pogodno za CI
omniroute doctor                   # Dijagnostika ispravnosti (data direktorijum, baza, provajderi, portovi)
omniroute providers available      # Prikaz podržanih provajdera
omniroute providers list           # Prikaz konfigurisanih konekcija
omniroute providers test <id>      # Testiranje konekcije provajdera u realnom vremenu
omniroute combos list              # Prikaz kombinacija
omniroute combos switch <name>     # Postavljanje podrazumevane kombinacije
omniroute models                   # Prikaz dostupnih modela (--json, --search)
omniroute keys add | list | remove # Upravljanje API ključevima iz terminala
omniroute backup                   # Snimak konfiguracije i baze podataka
omniroute restore [<timestamp>]    # Vraćanje iz snimka
omniroute health                   # Detaljno stanje sistema (breakeri, keš, memorija)
omniroute quota                    # Iskorišćenost kvote provajdera
omniroute mcp status                # Status MCP servera
omniroute a2a status                # Status A2A servera
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok tuneli
omniroute reset-password           # Resetovanje admin lozinke
omniroute --mcp                    # Pokretanje MCP servera preko stdio
omniroute --port 3000              # Pokretanje servera na proizvoljnom portu
```

Savet: kombinujte `omniroute doctor --json` sa alatom za monitoring da biste dobijali upozorenja o neispravnim konekcijama provajdera.
