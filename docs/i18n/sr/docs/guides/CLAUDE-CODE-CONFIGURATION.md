Usmerite **Claude Code** CLI (`claude`) ka OmniRoute-u — lokalnom ili udaljenom VPS-u —
uz profile za svaki model, po uzoru na Codex podešavanje.

---

## Brzi početak

```bash
# Pokrenite Claude Code sa lokalnim OmniRoute-om (automatski otkriva aktivni kontekst)
omniroute launch

# Sa udaljenim OmniRoute-om (nakon `omniroute connect <host>`, ovo je automatski)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Generišite profile za svaki model, a zatim pokrenite jedan od njih
omniroute setup-claude            # upisuje ~/.claude/profiles/<name>/settings.json
omniroute launch --profile glm52  # Claude Code koristi glm/glm-5.2 preko OmniRoute-a
```

## Како Claude код повезује са мрежним пролазом

Claude Цоде говори о**Anthropic Поруке API** и усмерен је на прилагођену крајњу тачку са варијаблама окружења (нема `--base-url` заставицу):

| Променљива                                   | Сврха                                                                                        |
| -------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | Роот мрежног пролаза URL (Claude код додаје `/v1/messages`).** Нема `/v1` суфикса.**         |
| `ANTHROPIC_AUTH_TOKEN`                       | Послато као `Authorization: Bearer …` — користите свој OmniRoute приступни токен / API кључ  |
| `ANTHROPIC_API_KEY`                          | Алтернатива: послато као `x-api-key`. Ако су оба постављена, `ANTHROPIC_AUTH_TOKEN` побеђује |
| `ANTHROPIC_MODEL`                            | Присилите одређени модел (замењује подразумевани бирач `/model` )                            |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → изворни `/model` наводи `claude*`/`anthropic*` моделе из `/v1/models`                  |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | Ограничите излазне токене по одговору (нпр. `65536`)                                         |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | Праг токена за аутоматско збијање                                                            |

> Енв варс се читају** једном приликом покретања** — поново покрените Claude код након што их промените.

За акредитив који се ротира уместо фиксног стринга, поставите `apiKeyHelper` у `~/.claude/settings.json` на команду која штампа тренутни акредитив на стдоут. Claude код подразумевано кешира свој излаз пет минута (`CLAUDE_CODE_API_KEY_HELPER_TTL_MS` то замењује) и шаље вредност у `Authorization: Bearer` и `x-api-key`. Скрипта мора да одштампа акредитиве и ништа друго — банер поред њега не успева помоћник на в2.1.227 +.

Овако функционише Ентра ID SSO : `scripts/cli/omniroute-sso.mjs token` штампа краткотрајни Ентра приступни токен који OmniRoute верификује уместо API кључа. Види [`docs/security/ENTRA_SSO.md`](../security/ENTRA_SSO.md).

`omniroute launch` поставља све ово за вас: решава основни URL + токен из активног контекста (тако да `omniroute connect <vps>` онда `omniroute launch` само ради), проверава здравље сервера и извршава `claude`.

## Атрибуција употребе: сесије и пројекти

OmniRoute групише захтеве сваког API кључа у** агент сесије** и евиденције које** пројекат** свака сесија на којој се ради (`agent_sessions` табела), тако да се употреба и трошкови могу извести по члану тима, по пројекту и по сесији.

Шта се снима без икаквог подешавања клијента:

| Поље     | Извор                                                                                                                                                |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сессион  | `x-claude-code-session-id` заглавље (иста вредност као `metadata.user_id.session_id`), стабилно по сесији                                            |
| Пројекат | `Primary working directory:` линија Claude код шаље у свом окружењу поруку; фасцикле радног стабла под `.claude/worktrees/` решавају у име спремишта |
| Филијала | `Current branch:` из гит статуса Claude Код се шаље са првом поруком                                                                                 |
| Клијент  | `user-agent` (`claude-cli/<version>`)                                                                                                                |

Codex (`<environment_context><cwd>`) и OpenCode (`x-opencode-session`) се препознају на исти начин. Кључеви са** но-лог** омогућено да задржи само ИД сесије и поља пројекта која су достављена у заглављу; ништа прочитано из промпта (путања, грана) се не чува.

### Експлицитно именовање пројекта (препоручено)

Радни директоријум се разликује између машина, тако да се исто спремиште може појавити на различитим путањама. Уместо тога, експлицитно пошаљите пројекат: Claude Цоде додаје сва заглавља наведена у `ANTHROPIC_CUSTOM_HEADERS` сваком захтеву модела, а OmniRoute чита два од њих:

| Хеадер                     | Валуе                                                            |
| -------------------------- | ---------------------------------------------------------------- |
| `x-omniroute-project`      | Назив пројекта, нпр. `omniroute`                                 |
| `x-omniroute-project-repo` | Нормализовани даљински, нпр. `github.com/diegosouzapw/OmniRoute` |

Оба се читају само за приписивање; они се никада не прослеђују упстреам провајдеру.

`ANTHROPIC_CUSTOM_HEADERS` се чита једном приликом покретања, а датотеке са подешавањима чувају литералне вредности, па га израчунајте када се Claude Цоде покрене. Додајте ово у `~/.zshrc` или `~/.bashrc` и наставите да покрећете `claude` из фасцикле пројекта:

```bash
claude() {
  local common name repo
  if common=$(git rev-parse --path-format=absolute --git-common-dir 2>/dev/null); then
    name=$(basename "$(dirname "$common")")  # repository name, also inside worktrees
    repo=$(git remote get-url origin 2>/dev/null \
      | sed -E 's#^[a-zA-Z][a-zA-Z0-9+.-]*://([^@/]*@)?##; s#^[^@/]+@([^:]+):#\1/#; s#\.git$##')
  else
    name=$(basename "$PWD")                  # not a git repository: folder name
  fi
  ANTHROPIC_CUSTOM_HEADERS="x-omniroute-project: ${name}${repo:+
x-omniroute-project-repo: ${repo}}" command claude "$@"
}
```

Израз `sed` уклања све акредитиве уграђене у удаљени URL. IDE екстензије покрећу Claude код без ваше шкољке, тако да се њихове сесије враћају у радни директоријум.

## Алијаси за откривање — приказ не-Claude модела у `/model` изборнику

Откривање модела преко gateway-ја у Claude Code-у приказује само идентификаторе који почињу са `claude` или `anthropic`, тако да уз `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` уграђени `/model` изборник обично приказује **само** Claude/Anthropic моделе из OmniRoute-а — `kimi/kimi-k2.6` или `glm/glm-5.2` се никада не појављује, иако се усмерава без проблема.

OmniRoute може да преслика било који омогућени модел (и комбо) под `claude/…` идентификатором, тако да пролази кроз тај филтер и појављује се у изборнику:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

Када неки од њих изаберете у Claude Code-у, OmniRoute пре усмеравања уклања `claude/` омотач и враћа прави идентификатор — истински `claude/<real-claude-model>` идентификатор (стварни Claude OAuth провајдер) увек остаје нетакнут.

Подразумевано се пресликавају само основни идентификатори. Када је укључен опциони feature flag `CATALOG_MIRROR_REFINEMENTS_ENABLED`, варијанте нивоа резоновања које каталог већ наводи (нпр. `codex/gpt-6-sol-high`) пресликавају се као и сваки други идентификатор, тако да Claude Code може да изабере експлицитан ниво напора, док се уграђени `auto/*` идентификатори које путања захтева не може да материјализује не пресликавају. То да ли се варијанте нивоа уопште приказују и даље одређује `OMNIROUTE_DISABLE_THINKING_LEVEL_VARIANTS` — пресликавање никада не додаје варијанту коју основни каталог нема.

**Ово је подразумевано искључено** и контролише се преко три нивоа (најспецифичнији побеђује), тако да обичан OmniRoute никада не удвостручује свој каталог за клијенте који не користе Claude Code:

| Ниво      | Где                                                                                   |
| --------- | ------------------------------------------------------------------------------------- |
| Модел     | Страница детаља провајдера → прекидач „Прикажи у Claude Code-у" по моделу             |
| Провајдер | Страница детаља провајдера → прекидач на нивоу провајдера (покрива све његове моделе) |
| Глобално  | Подешавања → Feature Flags → `EXPOSE_CC_DISCOVERY_ALIASES` (подразумевано искључено)  |

Променљива окружења `EXPOSE_CC_DISCOVERY_ALIASES` принудно укључује глобални ниво и има предност над подешавањем у контролној табли (екран Feature Flags тада приказује напомену „активно преко променљиве окружења"). Прекидачи на нивоу провајдера и модела одатле додатно прецизирају подешавање — нпр. глобално искључено + укључен Kimi провајдер излаже само Kimi-јеве моделе.

> ⚠️ **Неподударност прозора на не-Claude моделима.** Claude Code за сваки идентификатор који не препознаје претпоставља контекстни прозор од 200K (не може да прочита стварни прозор са `/v1/models`). За модел са већим прозором (нпр. Kimi K2 са 256K) подесите `CLAUDE_CODE_AUTO_COMPACT_WINDOW` на вредност испод стварног прозора модела, како се аутоматска компакција не би превремено покренула. Генерисани профили изнад то већ раде за сваки модел.

## Блок за почетно подешавање на контролној табли

Картица алатке Claude (**Контролна табла → CLI Code**) приказује тачан фрагмент датотеке `settings.json`
за ову инстанцу, поред дугмета са информацијама о алијасу за откривање, као и дугме за копирање:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<ваш OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<ваш OmniRoute API кључ>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

Основни URL је онај који је картица одредила (укључујући прилагођену вредност коју сте унели) и већ је
нормализован — без суфикса `/v1` и без завршне косе црте. **Кључ се никада не приказује**: блок садржи
чувар места, тако да снимак екрана или налепљени исечак не могу да открију кључ. Налепите свој кључ преко њега.

Додајте `CLAUDE_CODE_AUTO_COMPACT_WINDOW` у исти блок `env` за сваки модел чији стварни
контекстни прозор није 200K — Claude Code подразумева 200K за сваки id који не препознаје, па се
аутоматско сажимање у супротном покреће у погрешном тренутку (погледајте упозорење у претходном одељку).
Градитељ исечка прихвата и ту вредност, тако да позивалац који зна величину прозора циљног модела
може директно да је наведе.

Извор: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (чист
градитељ, покривен јединичним тестовима), који приказује `ClaudeGatewayOnboardingBlock`.

### Закључавање на један налог (опционално)

Да бисте сваки Claude Code захтев слали преко једног одређеног налога добављача, додајте
заглавље `x-omniroute-connection` путем `ANTHROPIC_CUSTOM_HEADERS` у исти блок `env`:

```jsonc
"ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>"
```

Копирајте id из ознаке `xxxxxxxx…` у реду везе на страници добављача. Закључавање се
примењује само на id-ове појединачних модела (`provider/model`), а не на комбинације. Погледајте
[Закључавање налога по захтеву](../reference/API_REFERENCE.md#account-pinning-per-request) за
тачно понашање резервног избора.

## Профили (`CLAUDE_CONFIG_DIR`)

Claude Code **нема изворне датотеке профила** (за разлику од Codex-ових `~/.codex/<name>.config.toml`).
Уобичајени механизам је `CLAUDE_CONFIG_DIR` — засебан директоријум конфигурације за сваки
профил, од којих сваки има сопствене `settings.json`, акредитиве, историју и кеш.

`omniroute setup-claude` преузима актуелни `/v1/models` каталог и уписује по један
профил за сваки модел у `~/.claude/profiles/<name>/settings.json`, поново користећи
**иста имена као `setup-codex`** (`glm52`, `kimi-k27`, `deepseek-pro`, …):

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **Токен за аутентификацију се никада не уписује у профил.** Покрените помоћу
> `omniroute launch --profile <name>` (ова команда умеће `ANTHROPIC_AUTH_TOKEN` из
> активног контекста) или сами извезите `ANTHROPIC_AUTH_TOKEN` и покрените
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`.

**Аутоматска синхронизација након откривања модела (опционо).** OmniRoute може аутоматски поново да генерише исте
`~/.claude/profiles/<name>/settings.json` датотеке кад год синхронизација модела добављача
промени актуелни каталог — тако нови или преименовани модели добијају профиле без поновног покретања
команде. Ово је **подразумевано искључено**: укључите га на **CLI Code контролној табли** („Аутоматска
синхронизација CLI профила“ → Claude Code) или подесите `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` (такође поштује
`CLI_ALLOW_CONFIG_WRITES`, који је подразумевано укључен). Када је омогућено, уписују се само датотеке профила; никада се
не мењају ваша активна/подразумевана Claude конфигурација, аутентификација нити `~/.claude/settings.json`.

### Генерисање и коришћење профила

```bash
# Локални OmniRoute
omniroute setup-claude

# Удаљени VPS (уграђује URL VPS-а у сваки профил)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Само неки добављачи
omniroute setup-claude --only glm,kimi

# Такође упишите профиле за локалне CLI добављаче (zcode, auggie, devin-cli-agentic,
# codex-app-server) који нису откривени на овом систему (подразумевано се прескачу за локално одредиште)
omniroute setup-claude --include-local

# Преглед без уписивања
omniroute setup-claude --dry-run

# Покретање профила
omniroute launch --profile kimi-k27
```

## Нивои модела (опционо)

Claude Code усмерава захтеве према нивоима могућности. Мапирајте сваки ниво на OmniRoute модел путем променљивих окружења /
подешавања ако желите различите добављаче за сваки ниво:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

У супротном, један `ANTHROPIC_MODEL` (који профили постављају) користи се за све.

## Удаљени режим

Након што покренете `omniroute connect <host>` (погледајте
[Удаљени режим](./REMOTE-MODE.md)), `omniroute launch` и `omniroute setup-claude`
аутоматски циљају тај удаљени сервер и користе његов приступни токен ограниченог опсега — нису
потребне додатне опције. Преиначите за појединачно покретање помоћу `--remote` / `--api-key`.

## Решавање проблема

**Claude Code игнорише мрежни пролаз** — потврдите да `ANTHROPIC_BASE_URL` **не садржи
`/v1`** и поново покрените `claude` (променљиве окружења се читају само једном приликом покретања). `omniroute launch`
то обавља уместо вас.

**Бирач `/model` је празан / недостају модели мрежног пролаза** — потребни су Claude Code
v2.1.219+ и `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`. У бирачу се појављују само ID-ови модела `claude*` /
`anthropic*`; принудно поставите било који други модел помоћу
`ANTHROPIC_MODEL=<id>` (то профили раде).

**`400 Ambiguous model 'claude-…'`** — Claude Code увек шаље **ID-ове модела без префикса**
(нпр. `claude-opus-4-8`), па када су повезани и добављач Claude Code (`cc/…`) и
Claude (`claude/…`), ID без префикса одговара двема путањама и
OmniRoute одбија да нагађа. Решите то на један од следећих начина: закачите ID са префиксом помоћу
`ANTHROPIC_MODEL=cc/claude-opus-4-8` или омогућите **Дај предност Claude Code-у за
Claude моделе без префикса** — преклопник на страници добављача Claude или
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (подразумевано искључено;
погледајте [Окружење](../reference/ENVIRONMENT.md)) — чиме се ID-ови `claude-*` без префикса
усмеравају на Claude Code. Експлицитни префикси добављача увек имају предност.

**Грешке при аутентификацији** — профил не садржи токен. Користите `omniroute launch --profile`
(убацује га) или извезите `ANTHROPIC_AUTH_TOKEN`.

**Профили нису изоловани** — сваки профил је засебан `CLAUDE_CONFIG_DIR`;
проверите да `echo $CLAUDE_CONFIG_DIR` унутар сесије показује на
`~/.claude/profiles/<name>`.
