OmniRoute се интегрише са добављачима чији рубни системи активно идентификују незваничне клијенте на основу отиска (TLS JA3/JA4, редослед заглавља, облик JSON тела, токени интегритета). Ова страница документује површине за прикривање које OmniRoute излаже и места на којима су имплементиране.

## Правно и етичко обавештење

Функције прикривања постоје како би OmniRoute могао да служи као слој компатибилности између званичних налога у власништву корисника (Claude Code CLI, Codex, Antigravity, Cursor итд.) и обједињеног API-ја система OmniRoute. Оне **нису** намењене заобилажењу система за откривање превара, дељењу акредитива или кршењу Услова коришћења добављача. Одржаваоци очекују од оператера да поштују услове коришћења узводног система које су прихватили приликом креирања налога.

## Слој TLS отиска

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Трајне `wreq-js` сесије креирају се лењо за сваки опсег налога и разрешени прокси. `TlsClient`
на нивоу процеса обједињује највише 128 сесија које имитирају **Chrome 124 на macOS-у** за
узводне сервисе иза Cloudflare-а. `TlsClient.fetch()` безбедно прекида рад када изворно окружење
није доступно; позивалац може изричито да изабере резервну опцију изван овог омотача.

- Профил сесије: `browser: "chrome_124", os: "macos"`
- Разрешавање проксија (приоритет): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (такође малим словима)
- Временско ограничење: `TLS_CLIENT_TIMEOUT_MS` (наслеђује се из `FETCH_TIMEOUT_MS`, подразумевано 600000)
- `wreq-js` одговор је компатибилан са fetch-ом (`headers`, `text()`, `json()`, `clone()`, `body`).
- Надзор првог бајта (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`
  завршава се чим стигну заглавља узводног сервиса, па само `TLS_CLIENT_TIMEOUT_MS` не може да ограничи
  тело које никада не испоручи први бајт. `guardTlsFirstByte()` покреће трку између првог `read()`
  тела и `TLS_FIRST_BYTE_WATCHDOG_MS` (подразумевано `10000`, `0` га онемогућава); исправно тело
  остаје непромењено, док се заустављено тело отказује у wreq читачу и омогућава да постојећа
  TLS резервна логика `proxyFetch` пређе на директни/прокси диспечер (захтев који није безбедно
  поновити, нпр. POST са телом, и даље изазива грешку уместо да буде неприметно поново послат).

### Транспорт добављача веб-колачића — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` је заједнички адаптер за пет специјализованих
транспорта веб-колачића наведених испод. Сваки танки омотач добављача бира профил прегледача/ОС-а.
Адаптер користи јединствени учитавач wreq окружења и скуп транспорта у
`open-sse/utils/tlsClient.ts`, индексиран према профилу + ОС-у + разрешеном проксију, док сваки
захтев користи `cookieMode: "ephemeral"`. Налози и захтеви зато деле везе на нивоу транспорта,
али никада не деле wreq сесију нити складиште колачића.

| Добављач   | Профил        | Емулирани ОС | Политика EOF-а тока                          |
| ---------- | ------------- | ------------ | -------------------------------------------- |
| Claude     | `chrome_146`  | Linux        | укључује `[DONE]`                            |
| Perplexity | `firefox_151` | macOS        | укључује `event: end_of_stream`              |
| Grok       | `chrome_146`  | Linux        | искључује `[DONE]`                           |
| Notion     | `chrome_146`  | Windows      | укључује `[DONE]`                            |
| LMArena    | `chrome_146`  | Windows      | без сентинела; затвара се при изворном EOF-у |

- Стримовање директно користи `ReadableStream` изворног одговора; не креира се привремена датотека
  нити помоћни процес.
- Пре излагања тока проверава се до 256 почетних бајтова. SSE добављачи баферују грешке које нису
  SSE; Grok/LMArena мапирају Cloudflare изазове на `403`, а HTML међустранице на `502`.
- Временско ограничење изворног захтева остаје обухваћено апсолутним крајњим роком у JS-у. Застој
  поништава и затвара само погођени транспорт профила/ОС-а/проксија пре него што га следећи захтев
  поново креира.
- Приоритет разрешавања проксија је `proxyUrl` по позиву → контекст налога/контролне табле ограничен
  на захтев → `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (укључујући варијанте малим словима). Грешке
  разрешавања безбедно прекидају рад уместо да допусте цурење директне везе. LMArena намерно
  разрешава у односу на `arena.ai`.
- `byteResponse` враћа `data:` URL са наведеним типом садржаја, без оштећења UTF-8 података.
- Грешке су `TlsClientUnavailableError` (пакет/додатак није доступан), `TlsClientHangError`
  (крајњи рок је прекорачен) и `WreqTransportCapacityError` (заједнички кôд грешке капацитета сесије)
  када је свих 128 ограничених места за профил/ОС/прокси активно или у процесу затварања.

Генеричка `TlsClient` сесија изнад остаје специјализована за трајно стање колачића које подржава
прегледач. Обе путање поново користе један кеширани учитавач wreq модула и закачку животног циклуса
процеса; њихови скупови остају одвојени јер су животни векови њихових колачића намерно различити.

Профиле подржава фиксирани пакет, али стварно прихватање од стране WAF-а може да се мења независно
од локалних тестова уговора. Проверите промене отиска у односу на изричито овлашћени активни налог
пре него што тврдите да постоји паритет са узводним прегледачем.

## Claude Code пакет за прикривање

Када је `cliCompatMode` укључен, OmniRoute преобликује одлазне Claude захтеве тако да се не могу разликовати од `claude-cli` саобраћаја. Три модула сарађују:

### `claudeCodeFingerprint.ts`

Израчунава отисак `cc_version` од 3 знака, уграђен у заглавље за наплату:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (чврсто кодирано; подудара се са званичним клијентом)
- Улази: знакови на индексима 4, 7 и 20 текста прве корисничке поруке + ниска верзије
- Излаз: хексадекадни префикс од 3 знака

### `claudeCodeCCH.ts` (хеш садржаја клијента)

Серверска провера интегритета коју званични Claude Code CLI израчунава помоћу Bun/Zig. OmniRoute је поново имплементира помоћу `xxhash-wasm`:

1. Серијализуј тело са резервисаним местом `cch=00000;`
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. Хексадекадна вредност од 5 знакова, допуњена нулама, малим словима
4. Замени `cch=00000;` израчунатим токеном

Константе:

- Почетна вредност: `0x6e52736ac806831e`
- Образац: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

Умеће Unicode **спојницу нулте ширине** (`U+200D`) после првог знака „осетљивих“ назива клијената, тако да их узводни филтери не могу пронаћи помоћу grep-а. Подразумевана листа речи:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Примењује се на: `system` блокове, сав `messages[].content` садржај и `tools[].description` / `tools[].function.description`. Оператер може да измени листу помоћу `setSensitiveWords()`.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` добављачи

За Anthropic посреднике трећих страна који прихватају само саобраћај „правог Claude Code-а“:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"` подразумевано
- Прекидач „Омогући redact-thinking бета-функцију“ за појединачну везу додаје `redact-thinking-2026-02-12` када CC Compatible узводни систем изричито захтева редиговане токове размишљања
- Прекидач „Омогући приказ сажетог размишљања“ за појединачну везу чува `providerSpecificData.requestDefaults.summarizeThinking` и додаје `display: "summarized"` CC Compatible захтевима за размишљање који већ нису поставили режим приказа
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (породица Opus/Sonnet 4.x)
- Подразумевана путања: `/v1/messages?beta=true`

Сродни модули у истом пакету:

- `claudeCodeConstraints.ts` — правила за температуру + контролу кеша
- `claudeCodeToolRemapper.ts` — пресликавање назива алата
- `claudeCodeExtraRemap.ts` — додатна нормализација корисног садржаја

## Antigravity Стеалтх

Antigravity захтеви чувају текст позиваоца бајт за бајт. OmniRoute не убацује знакове нулте ширине у упите или rename/inject алате да би имитирао IDE клијента.

### `antigravityHeaderScrub.ts`

Скида нерђајуће SDK маркере (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) пре прослеђивања.

### ⚠️ ризик: `ANTIGRAVITY_CREDITS=always` (врућа тачка за забрану налога)

`ANTIGRAVITY_CREDITS=always` (које користи `open-sse/executors/antigravity.ts`) руте **сваки** захтевајте преко Antigravity AI прекорачења кредита (плаћени Google кредити) уместо да дозволите да се Google-ова квота на слободном нивоу ради. Ово је документовано као карактеристика, али јесте **једини најчешћи извештај о кршењу услова услуге који видимо** — више Google Ултра налога је забрањено са `403 / "service disabled for ToS violation" / insufficient_quota` након неколико сати рада са `=always`.

Узводна примена је укључена **Google-ова страна** , ништа OmniRoute не може спречити. Име енв вар и постојећи документи чине да звучи као сигурно дугме за окретање; није.

**Зашто ово привлачи детекцију злоупотребе агресивније него коришћење само на бесплатном нивоу:**

- Одржива аутоматизована потрошња на једном Google налогу се означава другачије од бесплатних погодака квота и заустављања.
- Прекорачење кредита нема горњу стопу, тако да погрешно конфигурисани клијент може да прође неколико стотина USD за неколико минута и изгледа као препродаја АПИ кључева или саобраћај ботова.
- Вишеструки OmniRoute корисници који паралелно дођу до прекорачења кредита из истог екстерног IP стварају сигнал.

**Препоручено држање:**

1. Задржите подразумевани `ANTIGRAVITY_CREDITS=off` осим ако оператер експлицитно не прихвати ризик плаћеног кредита и извршења налога. `retry` прво шаље нормалан захтев и убризгава кредите највише једном након квалификоване квоте 429; `always` убризгава кредите на први захтев.
2. **Распоредите оптерећење на провајдере путем Ауто-Цомбо-а** (`model: "auto"` или `kr/glm/etc` -combo) уместо засићења једног Antigravity налога.
3. **Поставите RPM ограничења по вези** на страници за уређивање Antigravity провајдера (дасхбоард → Провидерс → Antigravity → конекција → лимит рате). 30–60 RPM је одбрањива горња граница за континуирану употребу.
4. **Користите стабилно, узводно умрежавање које контролише оператер** и избегавајте дељење једног налога са неповезаним корисницима или радним оптерећењима.
5. **Ако је забрањено** : жалба преко `support.google.com` → „Врати Workspace/Account приступ“ са тачним `quota_exceeded` / `service disabled` одговором тела Google послата. Рестаурација није загарантована.

Референтно окружење документује импликације рачуна и потрошње сваког кредитног режима.

#### Не само `=always`: Antigravity OAuth рутирање уопште

Суспензије нису ограничене на прекорачење кредита. Извештаји из новембра 2026. (#19223, #19266) описују неколико Google налога суспендованих током рутирања кроз `antigravity` и `agy` (Antigravity CLI) провајдере, са:

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

Оба провајдера се аутентификују са Antigravity сесијом производа OAuth, на шта упозорава обавештење о ризику на контролној табли („Овај провајдер користи ваш званични производ session/OAuth, који није овлашћен за proxy/router употребу“) пре него што се дода веза. Ниједна од горенаведених препорука не дозвољава ту употребу; они само смањују промет који носи један налог.

**Овлашћени API интерфејси за Gemini моделе.** Google нуди програмски приступ Gemini у преко свог APIs, који OmniRoute подржава као обичне добављаче АПИ кључева:

| Провајдер ид | Име контролне табле       | Акредитив                                                                       |
| ------------ | ------------------------- | ------------------------------------------------------------------------------- |
| `gemini`     | Gemini (Google AI Студио) | Gemini API кључ из Google AI Студио (доступан бесплатан ниво)                   |
| `vertex`     | Вертек AI                 | Сервисни налог JSON, OAuth приступни токен или Вертек Екпресс API кључ (Gemini) |

Ови провајдери користе Google акредитиве за API приступ, за разлику од Antigravity сесије производа. Они не чине сваку употребу у складу са захтевима нити отклањају ризик од примене: сваки је регулисан сопственим условима, које оператер мора да провери да би се применио. На пример, [Gemini API Додатни услови коришћења услуге](https://ai.google.dev/gemini-api/terms) дозвољавају само плаћене услуге када су API клијенти доступни корисницима у Европском економском простору, Швајцарској или Уједињеном Краљевству, а садржај који се шаље неплаћеним услугама може да се користи за побољшање производа Google-а. Уместо тога, Вертек AI потпада под Google Цлоуд услове ( [Услови специфичних за услугу](https://cloud.google.com/terms/service-terms) ). Цене и квоте прате те API услове, а не Antigravity претплату.

Оператери који желе да избегну Antigravity суспензије описане изнад треба да усмере Gemini саобраћај преко једног од ових провајдера уместо `antigravity` / `agy`, након што провере да ли њихова употреба одговара условима провајдера.

Тачке додира:

- `open-sse/executors/antigravity.ts` — чита `process.env.ANTIGRAVITY_CREDITS`
- `src/lib/oauth/providers/antigravity.ts` — акредитив водовод
- Оригинални извештај о инциденту: Дискусија [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## Регистар CLI отисака — `open-sse/config/cliFingerprints.ts`

Табела по добављачу која фиксира **тачан** редослед заглавља и поља JSON тела, забележен из mitmproxy трагова званичних CLI алата. Тренутно су регистровани: `codex`, `claude`, као и профили изведени током извршавања у `providerHeaderProfiles.ts` за `antigravity` и `github`.

```ts
interface CliFingerprint {
  headerOrder: string[]; // осетљиво на велика и мала слова
  bodyFieldOrder: string[]; // JSON кључеви највишег нивоа
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Укључује се или искључује за сваког добављача путем променљивих окружења (погледајте испод). Када је искључено, заглавља/кључеви тела појављују се редоследом којим су их Node/JSON генерисали — што олакшава препознавање отиска.

## MITM прокси (Antigravity, Linux/macOS/Windows)

За CLI алате чије бинарне датотеке није могуће преусмерити путем `OPENAI_BASE_URL`, OmniRoute покреће локални прокси који прекида TLS везу. Крајње тачке се налазе у `src/app/api/cli-tools/antigravity-mitm/`.

| Метод  | Крајња тачка                            | Намена                                               |
| ------ | --------------------------------------- | ---------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | Статус — покренут, pid, dnsConfigured, certExists    |
| POST   | `/api/cli-tools/antigravity-mitm`       | Покретање MITM-а (захтева `apiKey` + `sudoPassword`) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | Заустављање MITM-а                                   |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | Приказ псеудонима модела                             |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | Чување псеудонима модела за алат                     |

Циљни пресретнути хост: **`daily-cloudcode-pa.googleapis.com`** (Antigravity-јев удаљени сервер).

### Редослед покретања (`src/mitm/manager.ts::startMitm`)

1. Генерисање самопотписаног сертификата путем `selfsigned` (RSA-2048, SHA-256, 1 година) — `cert/generate.ts`
2. Инсталирање сертификата у системско складиште поузданих сертификата — `cert/install.ts`
3. Додавање уноса у hosts датотеку `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. Покретање `src/mitm/server.cjs` са `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (подразумевано `443`)
5. Чување PID-а у `<DATA_DIR>/mitm/.mitm.pid`

### Динамичко откривање складишта поузданих сертификата на Linux-у — `cert/install.ts`

`getLinuxCertConfig()` пролази кроз листу приоритета и бира први постојећи директоријум:

| Породица дистрибуција    | Директоријум                                | Команда за ажурирање     |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Назив датотеке сертификата: `omniroute-mitm.crt`. Подударање отиска путем `getCertFingerprint()` (SHA-1 над DER-ом).

Поред тога, `updateNssDatabases()` инсталира сертификат у NSS базе података појединачних корисника када је `certutil` доступан: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, све Firefox профиле (укључујући snap), под надимком **`OmniRoute MITM Root CA`**.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** PowerShell са повишеним привилегијама → `certutil -addstore Root`

### Аутентификација

Све MITM крајње тачке захтевају управљачку аутентификацију (`requireCliToolsAuth`). Sudo лозинка се кешира у опсегу модула (никада у `globalThis`) и брише се при позиву `stopMitm()`.

## Санитизација долазних заглавља

OmniRoute уклања долазна клијентска заглавља пре прослеђивања, тако да захтев који стигне из Cursor-а не открије `User-Agent: Cursor/X.Y.Z` Claude upstream серверу. Листа забрањених заглавља налази се у `src/shared/constants/upstreamHeaders.ts` и одржава се синхронизовано са Zod шемама и јединичним тестовима.

## Ажурирање отисака када их добављач промени

1. Снимите саобраћај званичног CLI-ја помоћу `mitmproxy` (TLS пресретање + dump)
2. Издвојте JA3/JA4 и дослован редослед заглавља
3. Ажурирајте одговарајући унос `CLI_FINGERPRINTS[...]`
4. Ажурирајте одговарајућу подразумевану вредност `*_USER_AGENT` у `.env.example`
5. Ако се променио и сам TLS handshake, ажурирајте одговарајући омотач добављача или опцију wreq-js `browser:`
6. Покрените TLS тестове специфичне за добављача и ручни canary тест према активном добављачу
7. Објавите у оквиру patch издања; документујте у `CHANGELOG.md`
