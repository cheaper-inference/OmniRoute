> Аутоматски уштедите 15–95% на садржају који испуњава услове. За кратак преглед погледајте [одељак README датотеке о компресији](../README.md#%EF%B8%8F-prompt-compression--save-15-95-eligible-tokens-automatically).

## Преглед

OmniRoute примењује модуларни ток компресије упита који се покреће **проактивно**, пре него што захтеви стигну до спољних добављача. То значи да се токени штеде неприметно — нису потребне никакве промене у вашем току рада.

```
Захтев клијента
  → Бирач стратегије компресије
    → Замена подешавањем комбинације? → Користи подешавање комбинације
    → Праг аутоматског покретања? → Користи аутоматски режим
    → Подразумевани режим? → Користи глобално подешавање
    → Искључено? → Прескочи компресију
  → Изабрани режим компресије
    → Искључено: Без компресије
    → Лагани: Безбедно чишћење размака/форматирања (~15%)
    → Стандардни: Уклањање сувишних речи у стилу пећинског говора (~30%)
    → Агресивни: Старење историје + сажимање (~50%)
    → Ултра: Хеуристичко скраћивање + проређивање блокова кода (~75%)
    → RTK: Филтрирање терминалског излаза/излаза алата које узима у обзир команде (опсег од 60–90% пре слања)
    → Наслагани: Уређени ток са више механизама, обично RTK па Caveman (опсег од 78–95% садржаја који испуњава услове)
  → Компримовани захтев → Добављач
```

## Режими компресије

### Искључено

Компресија се не примењује. Све поруке пролазе без измена.

### Лагани режим (уштеда од ~15%, кашњење <1ms)

Најбезбеднији режим — без семантичких промена, само чишћење форматирања:

| Техника                  | Опис                                                           |
| ------------------------ | -------------------------------------------------------------- |
| `collapseWhitespace`     | Спаја узастопне празне редове и уклања размаке на крају редова |
| `dedupSystemPrompt`      | Уклања дуплиране системске поруке                              |
| `compressToolResults`    | Компримује опширне излазе алата/функција                       |
| `removeRedundantContent` | Уклања поновљена упутства                                      |
| `replaceImageUrls`       | Скраћује URI-је са base64 подацима слика                       |

**Најбоље за:** Сталну употребу и токове рада код којих је безбедност критична.

### Стандардни режим (уштеда од ~30%)

Инспирисан пројектом [Caveman](https://github.com/JuliusBrussee/caveman) — уклања сувишне речи и опширне формулације, уз очување значења:

- Уклања сувишне речи („молим“, „мислим“, „у суштини“, „заправо“)
- Сажима опширне фразе („како би“ → „да“, „као резултат тога што“ → „јер“)
- Уклања учтиво ублажавање исказа („Да ли бисте могли...“, „Ако бисте можда могли...“)
- Више од 30 regex правила прилагођених упитима за програмирање

**Најбоље за:** Свакодневне токове рада у програмирању и тимове који воде рачуна о трошковима.

### Агресивни режим (уштеда од ~50%)

Паметно управљање историјом за дуге сесије:

- **Старење порука** — старије поруке се постепено све више компримују
- **Компресија резултата алата** — дугачки излази алата се скраћују или изостављају (први/последњи редови,
  филтрирање редова са подударањима, сажимање JSON кључева)
- **Механизми за очување структурног интегритета** — обезбеђују да парови `tool_use` + `tool_result` остану доследни
- **Уважавање контекстног прозора** — поштује ограничења броја токена за сваки модел

**Најбоље за:** Дуге сесије отклањања грешака и велике базе кода.

### Ултра режим (уштеда од ~75%)

Максимална компресија за сценарије у којима је број токена критичан:

- **Хеуристичко скраћивање** — скраћивање токена у прозном тексту на основу бодовања
- **Очување структуре** — ограђени блокови кода, уметнути кôд, URL-ови и идентификатори се
  привремено замењују ознакама и поново умећу без измена; никада се не скраћују
- **Опциони SLM ниво** — мали локални модел може додатно да побољша скраћивање када је конфигурисан
- Независан је од агресивног режима: не примењује старење порука, компресију резултата алата
  нити резервни механизам за сажимање (само неуспех SLM нивоа може да усмери резервни пролаз кроз
  агресивни режим)

**Најбоље за:** Ситуације у којима често достижете ограничења контекста.

### RTK режим (опсег од 60–90% пре слања)

RTK режим је оптимизован за опширне излазе алата који се појављују у сесијама агената за програмирање:

- Открива класе команди/излаза као што су `git status`, `git diff`, `git log`, покретачи тестова,
  TypeScript/Vite/Webpack процеси изградње, ESLint/Biome/Prettier, npm провере/инсталације, Docker евиденције, инфраструктурни
  излаз и генерички излаз љуске
- Примењује пакете JSON филтера из `open-sse/services/compression/engines/rtk/filters/`
- Увози филтере RTK TOML шеме v1 из пројектних или глобалних `filters.toml` датотека, уз проверу
  уграђених тестова и условљавање поверењем за пројектне датотеке
- Испоручује се са 55 уграђених филтера и примерима за проверу
- Уклања ANSI контролне секвенце, траке напретка, поновљене редове и неважан шум
- Чува неуспехе, грешке, упозорења, измењене датотеке, сажетке и завршни део дугачког излаза
- Подржава пројектне филтере условљене поверењем, глобалне филтере и опциони опоравак редигованог необрађеног излаза

**Најбоље за:** Сесије агената са транскриптима љуске, изградње, тестова, git, grep и излаза датотека.

### Наслагани режим (опсег од 78–95% садржаја који испуњава услове)

Наслагани режим покреће више механизама за компресију детерминистичким редоследом. Подразумевани ток је:

```txt
RTK -> Caveman
```

Тај редослед прво сажима излаз терминала/алата, а затим примењује Caveman семантичко сажимање на
преостали упит на природном језику. Наслагани токови могу да се конфигуришу глобално или путем
комбинација компресије додељених комбинацијама усмеравања.

**Најбоље за:** Мешовити контекст са великим евиденцијама алата и људским упутствима или сажетцима асистента.

## Математика уштеде из изворних пројеката

OmniRoute документује уштеде остварене компресијом на основу два извора: референтних тестова изворних пројеката и
сопствене комбинације механизама у оквиру OmniRoute-а.

| Извор   | Број из README-а изворног пројекта који се овде користи                                                                                        |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Caveman | `~75%` мање излазних токена, просечна уштеда излаза на референтним тестовима од `65%`, распон од `22-87%` и алат за компресију улаза од `~46%` |
| RTK     | Уштеда од `60-90%` за излаз команди; пример сесије: `~118,000 -> ~23,900` токена, односно уштеда од `79.7%` (`~80%`)                           |

За преклапајуће садржаје алата/контекста, подразумевана OmniRoute комбинација редом примењује механизме:

```txt
RTK -> Caveman
```

Комбиноване уштеде се множе, а не сабирају:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

Тај број од `78-95%` важи када и RTK и Caveman могу да смање исти улазни/контекстуални садржај.
Caveman режим излаза одговора је засебан: када је омогућен, користе се сопствене уштеде излаза за Caveman (`65%`
у просеку, истакнутих `~75%`, распон од `22-87%`). Укупна уштеда на наплати зависи од односа упита и излаза.

### Шта „подобно“ заправо значи

Истакнути распон од 15-95% је стваран, али важи само за **редундантан или преопширан** садржај — поновљене
редове грешака, евиденцију изградње која непрестано исписује исто упозорење, превелики `grep`/испis прочитане датотеке. То
**не** значи да сваки захтев остварује толику уштеду.

Емпиријски је потврђено (`tests/unit/compression/stacked-compression-tool-result-savings.test.ts`): покретање режима
`stacked` (RTK + Caveman) над блоком `tool_result` у Anthropic формату, који садржи 300 идентичних
редова грешке, произвело је **уштеду од 95.93% токена / 96.26% знакова** — тачно у оглашеном
распону. Међутим, исти ток обраде примењен на нормалан, нередундантан излаз алата (чисту листу подударања из `grep`,
кратак испис датотеке, обичан текст разговора) исправно производи **уштеду близу нуле**, јер
нема ничег поновљеног што би се могло уклонити, а `validateCompression()` (`validation.ts`) одбија да пошаље
прерађени садржај који би изоставио или изменио блокове кода, URL-ове, наслове, верзије или идентификаторе константи ПИСАНЕ ВЕЛИКИМ СЛОВИМА.

Ово је очекивано и безбедно понашање, а не грешка: сесија програмирања која углавном чита/претражује чисте датотеке
имаће скромну укупну уштеду чак и када је компресија у потпуности омогућена, док ће сесија која наиђе на неуспешну
петљу или преопширан линтер остварити пуни распон од 78-95% на том саобраћају. Немојте користити низак збирни
проценат уштеде једне сесије као доказ да је компресија погрешно конфигурисана — прво проверите да ли је
основни излаз алата заиста био редундантан.

## Визуелизација уштеде токена

```
Без компресије:       47K токена послато LLM-у
Уз Lite:               40K токена послато          (15% уштеде — безбедно, увек активно)
Уз Standard:           33K токена послато          (30% уштеде — правила Caveman говора)
Уз Aggressive:         24K токена послато          (50% уштеде — старење + сажимање)
Уз Ultra:              12K токена послато          (75% уштеде — хеуристичко уклањање)
Уз RTK:                19K-5K токена послато       (60-90% уштеде на излазу команди/алата)
Уз Stacked:            10K-2.5K токена послато     (подобни RTK+Caveman распон од 78-95%)
```

## Конфигурација

### Контролна табла

Идите на `Контролна табла → Контекст и кеш`:

- **Caveman** — избор режима, језички пакети, преглед и глобалне подразумеване вредности
- **RTK** — преглед филтера команди, RTK безбедносна подешавања и каталог филтера
- **Комбинације компресије** — именовани ланци механизама додељени комбинацијама рутирања
- **Праг аутоматског активирања** — аутоматски активира компресију када број токена премаши праг

### Замена по комбинацији

У одељку `Контролна табла → Контекст и кеш → Комбинације компресије` доделите комбинацију компресије комбинацији
рутирања:

```txt
Combo: "free-tier-fallback"
  Compression Combo: "coding-agent-stack"
  Pipeline: RTK -> Caveman
  Targets:
    1. if/kimi-k2.7-code
    2. if/qwen3.8-max-preview
```

Ово вам омогућава да користите вишеслојну компресију код бесплатних добављача и добављача за програмирање, док задржавате лаки режим за плаћене
претплате.

Ова додела „Замене по комбинацији“ представља засебну контролу у односу на замену **режима компресије комбинације
рутирања** (Default/Off/Lite/Standard/Aggressive/Ultra/Codex Responses — шема овог поља
такође прихвата `rtk`, `stacked` и `omniglyph`) — та замена не бира именовани ланац
комбинације компресије; она само поставља поље `compressionMode` које користи
`resolveCompressionPlan`. Може се подесити на картици комбинације (`Контролна табла → Комбинације`) или, почев од
#6760, за сваку комбинацију рутирања у листи „Додели рутирању“ у одељку
`Контролна табла → Контекст и кеш → Комбинације компресије`, одмах поред поља за потврду доделе ланца
описаног изнад. Обе површине чувају податке преко исте крајње тачке `PUT /api/combos/{id}`.

### Замена по захтеву

Пошаљите заглавље захтева `x-omniroute-compression` да бисте заменили план компресије за један
захтев. Оно има највиши приоритет — надјачава замену комбинације рутирања, активни профил,
аутоматско активирање и подразумевану вредност на панелу. Непознате вредности се занемарују (захтев се никада не одбија), а
глобални главни прекидач и даље контролише све: када је компресија глобално искључена, заглавље је не може
укључити. Вредности:

| Вредност      | Ефекат                                                                                                    |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| `off`         | Нема компресије за овај захтев.                                                                           |
| `default`     | Подразумевани профил изведен из панела (игнорише активни профил). Механизми са губицима остају искључени. |
| `safe`        | Исто као када се заглавље изостави: само дедупликација и сажимање размака.                                |
| `allow-lossy` | Задржава операторски план овог захтева, укључујући сажетке, филтере релевантности и измене стила.         |
| `engine:<id>` | Један механизам када је омогућен, нпр. `engine:rtk`. Ово је укључивање тог механизма по захтеву.          |
| `<combo>`     | Именована комбинација, која се прво подудара по имену (без обзира на величину слова), а затим по ID-у.    |

Без `allow-lossy`, `engine:<id>` или именоване комбинације, механизми са губицима се не примењују. Захтев
и даље добија дедупликацију сесије и сажимање размака када је компресија укључена.

Примењени план се враћа у заглављу одговора `X-OmniRoute-Compression: <mode>; source=<source>`,
при чему је `<source>` једно од `request-header`, `routing-override`, `active-profile`,
`auto-trigger`, `default` или `off`.

## Напредни системи компресије

Поред 7 режима описаних изнад (извор такође прихвата режиме `codex-responses` и
`omniglyph`, које овај водич не обухвата), одељци у наставку описују функције
које раде унутар тих режима или упоредо с њима: компресија резултата алата и прогресивно старење
представљају 1. и 2. корак агресивног механизма (режим Aggressive и корак `aggressive` у
наслаганом процесу), наслагани процес одређује како режим Stacked ради, компресија свесна кеша
снижава `aggressive` и `ultra` на `standard` за добављаче који користе кеширање док је компресија
укључена, а режим пећинског излаза и стилови излаза представљају опционална упутства системског упита,
подразумевано искључена, која обликују излаз модела уместо да компресују захтев.

### Компресија свесна кеша

Неки добављачи (попут Anthropic-а са кеширањем упита) подржавају **кеширање упита**,
што им омогућава да кеширају делове упита како би смањили трошкове и кашњење. Када
је кеширање омогућено, агресивна компресија заправо може **погоршати** перформансе
јер мења кеширане токене, чиме поништава кеш.

Модул `cachingAware.ts` решава ово тако што **открива контекст кеширања** и
**прилагођава стратегију компресије** у складу с њим.

#### Како функционише

1. **Откривање контекста кеширања** — Скенира тело захтева у потрази за ознакама `cache_control`
2. **Препознавање добављача који користе кеширање** — Проверава да ли циљни добављач подржава кеширање
3. **Прилагођавање стратегије** — Снижава `aggressive`/`ultra` на `standard` за добављаче који користе кеширање
4. **Прескакање системског упита** — Системски упити су обично кеширани, па их не треба компресовати

Помоћна функција стратегије такође враћа ознаку `deterministicOnly`, али градитељ плана користи
само стратегију — тренутно ништа у наставку процеса не чита ту ознаку.

#### Пример кода

```ts
import {
  detectCachingContext,
  getCacheAwareStrategy,
} from "@omniroute/open-sse/services/compression/cachingAware";

const body = {
  model: "anthropic/claude-sonnet-4.5",
  messages: [{ role: "user", content: "Hello" }],
  cache_control: { type: "ephemeral" }, // ← Ознака кеша
};

const ctx = detectCachingContext(body, { provider: "anthropic" });
// → { hasCacheControl: true, provider: "anthropic", targetFormat: null, isCachingProvider: true }

const strategy = getCacheAwareStrategy("aggressive", ctx);
// → { strategy: "standard", skipSystemPrompt: true, deterministicOnly: true }
```

#### Када користити

Компресија свесна кеша је **увек укључена** — није потребна никаква конфигурација. Активира се кад год
је компресија укључена и циљни добављач подржава кеширање упита (Anthropic, OpenAI,
итд.); изричите ознаке `cache_control` нису обавезне — сам добављач који користи кеширање
покреће снижавање режима, док саме ознаке то никада не чине (откривање ознака служи за телеметрију
кеша, а не за одлуку о стратегији).

### Прогресивно старење

Дуги разговори нагомилавају много порука, али старији делови разговора постају мање
релевантни. Модул `progressiveAging.ts` **деградира поруке према удаљености у броју реплика**
(удаљеност се мери од краја разговора). Са испорученим подразумеваним вредностима
(`verbatim: 2, light: 2, moderate: 3`):

- **Последње 2 реплике (удаљеност ≤ 2)**: Задржавају се дословно
- **Удаљеност 3**: Пећинска компресија (уклањање сувишних речи)
- **Удаљеност 4+**: Поруке асистента се сажимају; корисничке поруке се своде на први
  ред, ограничен на 120 знакова; остале улоге остају нетакнуте. Системски упити, већ остареле
  поруке и најновија корисничка порука увек се задржавају дословно без обзира на удаљеност.
  Ништа се не одбацује у потпуности, а опсег `light`
  није достижан са испорученим подразумеваним вредностима (`light` је једнако `verbatim`).

#### Пример кода

```ts
import { applyAging } from "@omniroute/open-sse/services/compression/progressiveAging";

const messages = [
  { role: "system", content: "You are a helpful assistant" },
  { role: "user", content: "What is 2+2?" },
  { role: "assistant", content: "4" },
  // ... још 50 реплика ...
];

const { messages: aged, saved } = applyAging(messages, {
  verbatim: 3, // последње 3 реплике: дословно
  light: 8, // удаљеност <= 8: блага компресија
  moderate: 20, // удаљеност <= 20: пећинска компресија
  fullSummary: 5, // захтева је тип, али је код за распоређивање по опсезима не чита
  // удаљеност > 20: сажето (асистент) / задржава се први ред (корисник)
});

// saved = број сачуваних токена
```

#### Када користити

Прогресивно старење је **увек укључено** у режиму `aggressive` — то је 2. корак функције
`compressAggressive()`. Режим Ultra га не покреће. Нарочито је ефикасно за:

- Дуготрајне сесије програмирања
- Вишедневне разговоре
- Агентске токове рада са много позива алата

### Режим пећинског излаза

Режим пећинског излаза додаје **упутства системског упита** која од самог модела траже
сажет излаз — ниво `lite` тражи сажете одговоре који задржавају потпуне реченице, `full`
тражи да „одговара сажето као паметан пећински човек“, а `ultra` тражи телеграфски излаз;
упутства само упућују захтев и не могу гарантовати резултат. Захтеви их добијају преко
`applyOutputStyles()` (`open-sse/services/compression/outputStyles/apply.ts`):
`open-sse/handlers/chatCore.ts` најпре одређује избор помоћу слоја за повратну компатибилност
(`resolveOutputStyleSelection()` у
`open-sse/services/compression/outputStyles/backCompat.ts`), који, док је `outputStyles`
празан, мапира омогућени `cavemanOutputMode` на стил излаза `terse-prose` са вредношћу
`cavemanOutputMode.intensity` (погледајте одељак о повратној компатибилности испод); избор
`outputStyles` који није празан користи се без измена, а `cavemanOutputMode.enabled` и `intensity`
тада немају ефекта, док се његово подешавање `autoClarity` и даље примењује. `outputMode.ts` садржи
текстове упутстава (`CAVEMAN_INSTRUCTION_BY_LANGUAGE`), заобилажење садржаја и
помоћну функцију за позиционирање коју уметање користи; његова сопствена функција за уметање
`applyCavemanOutputMode()` нема позиваоца у продукцији.

#### Како функционише

Овај режим не компресује улаз. Он додаје блок са упутствима у системски упит
(погледајте Како уметање функционише у наставку), а сваки режим компресије улаза изабран за захтев
и даље се извршава након тога, над телом које сада садржи блок. Пре заједничке
клаузуле о ограничењима којом се сваки ниво завршава, енглески ниво `full` гласи:

> „Одговарај сажето као паметан пећински човек. Изостави чланове (a/an/the), сувишне речи (just/really/basically/actually/simply), учтивости и ограђивање. Фрагменти су у реду. Кратки синоними (big, не extensive; fix, не implement). Задржи сав технички садржај, кôд, грешке, URL-ове и идентификаторе непромењеним.“

Ово нарочито добро функционише за:

- Генерисање кода (сажетији излаз = мање токена)
- Брза питања и одговоре (нема потребе за опширним објашњењима)
- Групну обраду (максимизује пропусност)

#### Када користити

Режим пећинског излаза се **укључује по избору**. Када је компресија укључена (`enabled: true`, главни прекидач
на страници Compression Settings), укључите га помоћу `cavemanOutputMode.enabled`; `intensity`
бира `lite`, `full` или `ultra`:

```json
{
  "enabled": true,
  "cavemanOutputMode": {
    "enabled": true,
    "intensity": "full"
  }
}
```

Прекидач **Output Mode** комбинације компресије (`outputMode`, са нивоом у `outputModeIntensity`)
поставља исти прекидач за захтеве на које се та комбинација примењује, а MCP алат
`omniroute_set_compression_engine` га уписује преко свог логичког аргумента `outputMode`.
Избор `outputStyles` који није празан има предност над овим прекидачем. На
контролној табли, укључивање стила излаза **Terse prose** умеће исти блок (погледајте Output
Styles у наставку).

| Сажети CJK (文言)                       | `terse-cjk`     | Одговор на нивоу `full`/`ultra` на класичном кинеском (文言); `lite` тражи само кратке одговоре без функционалних речи, учтивости или украшавања.                                                                                                                                 | zh (ограничено локалитетом, погледајте испод) |

Сваки стил долази са три нивоа интензитета — `lite`, `full`, `ultra` — и сваки ниво
се завршава заједничком клаузулом о ограничењима (`SHARED_BOUNDARIES` у `outputMode.ts`), која
задржава блокове кода, путање датотека, команде, грешке и URL-ове непромењеним. Текстови нивоа
`terse-prose` и `terse-cjk` додају идентификаторе на ту листу.

`terse-cjk` је ограничен на локалитет `zh` на два места. Страница Compression Settings приказује
његов ред само када је језик корисничког интерфејса контролне табле кинески (`zh-CN` или `zh-TW`), а
`applyOutputStyles()` га умеће само када је разрешени језик захтева (погледајте Избор језика
у наставку) `zh`. Скривање реда не брише сачувани избор `terse-cjk`:
API подешавања прихвата било који `id` стила, а чување других стилова на страници га задржава. У
тренутку захтева, провера језика у `applyOutputStyles()` једино је ограничење локалитета.

#### Како уметање функционише

`applyOutputStyles()` (`open-sse/services/compression/outputStyles/apply.ts`) разрешава
избор у односу на каталог (непознати идентификатори и стилови који не одговарају локализацији
се одбацују, без грешке; избор који се разреши без иједног стила оставља тело
непромењеним и прескаче се као `no_styles`), спаја изабрана упутства редоследом из
каталога,
додаје клаузулу о ограничењима **једном** (као и безбедносну клаузулу, `SAFETY_BOUNDARIES` или
њен превод, када је изабран `less-code` или `ponytail`) и започиње блок једним
маркером идемпотентности (`[OmniRoute Output Styles]`), тако да поновна примена нема ефекта. Када
разрешени језик (погледајте одељак Избор језика у наставку) има превод, уместо енглеског
упутства умеће се локализовано упутство.

За тело са непразним низом `messages`, провера идемпотентности извршава се пре
заобилажења на основу садржаја: када се маркер `[OmniRoute Output Styles]` већ налази у
пољу највишег нивоа `system` (као ниска или низ блокова садржаја) или у системској поруци
са садржајем у облику ниске, тело остаје непромењено као `already_applied` и провера
кључних речи се не извршава. У супротном, заобилажење на основу садржаја
(`shouldBypassCavemanOutputMode()` у
`open-sse/services/compression/outputMode.ts`) проверава текст последње три
поруке, без обзира на њихову улогу, и прескаче стилове за целу интеракцију када се тај
текст подудара са кључним речима које се односе на безбедност, неповратне радње или
појашњење, или са секвенцом осетљивом на редослед: `first`, `then`, `after that`,
`before`, `rollback` или `backup`, након чега унутар 240 знакова следи `delete`, `drop`,
`migrate`, `deploy` или `release`. Заобилажење се извршава док је укључен прекидач
**Auto-Clarity Bypass**
(`cavemanOutputMode.autoClarity`, подразумевано укључен); искључивањем прекидача прескаче
се провера кључних речи.

Када заобилажење пропусти интеракцију, `placeSystemInstruction()` (у истој датотеци), који
никада не прави нови `messages[0]`, поставља блок на прво од следећих места које пронађе:

1. Почетна системска порука са садржајем у облику ниске: блок се додаје после њеног текста.
2. Поље највишег нивоа `system`: блок се додаје после текста ниске или
   као нови текстуални блок у низ блокова садржаја.
3. Прва каснија системска порука са садржајем у облику ниске: блок се додаје после њеног
   текста.
4. Ништа од наведеног: блок се ставља у нову системску поруку на крају низа `messages`.

За тело без низа `messages` (или са празним низом), заобилажење на основу садржаја се не
извршава и поље највишег нивоа `system` се не узима у обзир. Блок се додаје после текста
поља `instructions` у облику ниске, осим ако то поље већ садржи маркер
`[OmniRoute Output Styles]`, када тело остаје непромењено као `already_applied`. Када
тело нема поље `instructions` у облику ниске, али садржи `input` (ниску или низ), блок
постаје `instructions`, замењујући сваку вредност тог поља која није ниска. Тело које
нема ни поље `instructions` у облику ниске ни `input` у облику ниске или низа остаје
непромењено и прескаче се као `no_messages`.

#### Како омогућити

На контролној табли: **Compression Context → Compression Settings**
(`/dashboard/context/settings`), одељак за стилове излаза: по један ред за сваки стил,
са прекидачем за укључивање/искључивање и бирачем нивоа. Стилови се умећу док је сама
компресија укључена (главни прекидач странице, `enabled`). Прекидач
**Auto-Clarity Bypass** налази се на страници **Caveman**
(`/dashboard/context/caveman`), на њеној картици **Output Mode**. Програмски,
конфигурација компресије чува избор као:

```json
{
  "outputStyles": [
    { "id": "i-have-adhd", "level": "full" },
    { "id": "less-code", "level": "lite" }
  ]
}
```

Компатибилност уназад: док је `outputStyles` празан, застарела поставка
`cavemanOutputMode.enabled` мапира се на `terse-prose` при
`cavemanOutputMode.intensity`. Блок тада почиње маркером
`[OmniRoute Output Styles]`, док је застарели инјектор `applyCavemanOutputMode()`
уметао `[OmniRoute Caveman Output Mode]`. Испод маркера, текст одговара застарелом
уметању за en, pt-BR, es, de, fr, it, ru, id и vi; за ja и zh садржи један додатни
размак пре клаузуле о ограничењима. `terse-prose` има преводе за pt-BR, es, de,
fr, it, ru, zh, ja, id и vi, тако да захтев чији је разрешени језик `hu` добија
енглески текст, док је застарели инјектор користио мађарски текст.

Избор језика стила излаза (`resolveOutputStyleLanguage()` у
`outputStyles/apply.ts`): када је `languageConfig.enabled` укључен, `autoDetect` узоркује
најновију корисничку поруку у низу `messages` захтева која садржи текст (садржај у
облику ниске или `text` њених делова садржаја) и над њом покреће детектор Caveman
механизма (`detectCompressionLanguage()`). Детектор враћа `zh` за текст са Han
знаковима без кане; у супротном враћа онај од језика `it`, `pt-BR`, `es`, `de`,
`fr`, `ru`, `ja`, `hu` и `id` који има највише подударања са назнакама, а `en` када
нема подударања — текст који не може да класификује добија енглески, никада
`defaultLanguage`, а `vi` се никада не детектује иако стилови испоручују текст на
језику `vi`. Тело Responses API-ја чува своје интеракције у `input`, који се не
узоркује, па добија `defaultLanguage`, а затим енглески. Када ниједна корисничка порука
у `messages` нема текст или када је `autoDetect` искључен, примењује се
`defaultLanguage`, а затим енглески. Када је `languageConfig.enabled` искључен, језик
је енглески — осим ако се на захтев примењује комбинација компресије (комбинација
додељена комбинацији рутирања захтева или подразумевана комбинација компресије на коју
се chatCore ослања за уграђени сложени цевовод): примена комбинације укључује
`languageConfig.enabled` за тај захтев и поставља `defaultLanguage` на основу језичких
пакета комбинације (сачувану вредност ако је она један од пакета комбинације, иначе
први пакет комбинације, који је подразумевано `en`), док се сачувани `autoDetect`
(подразумевано укључен) и даље примењује. Caveman механизам за улаз бира језик пакета
правила на другачији начин — засебно за сваки текстуални део и, када је аутоматско
откривање искључено, условљено поставком `enabledPacks`.

Матрица стил × језик је фиксирана тестом
`tests/unit/compression/output-styles-i18n-matrix.test.ts`: сваки стил у каталогу мора да има
унос у тестовом `BASELINE_LANGUAGES`; стил који није ограничен локализацијом мора да садржи
превод на pt-BR (стил `terse-cjk`, ограничен локализацијом, изузет је од овог правила), осим ако
није наведен у `KNOWN_ENGLISH_ONLY`, који сме да садржи само стилове без иједног превода —
наведени стил који има било који превод обара тест; такође, стил обара тест када
изгуби језик наведен у његовом уносу у `BASELINE_LANGUAGES`. Да бисте додали стил, погледајте
[EXTENDING_COMPRESSION.md](./EXTENDING_COMPRESSION.md#adding-an-output-style).

### Компресија резултата алата

`compressToolResult()` у `open-sse/services/compression/toolResultCompressor.ts`
компресује текст резултата алата помоћу **5 стратегија**. Испробава их овим редоследом, а
прва омогућена стратегија чија провера одговара садржају одређује резултат:

1. **`fileContent`**: садржај од 3 или више редова у којем најмање један ред, занемарујући
   почетно увлачење, почиње са `import `, `export `, `function `, `class `,
   `const `, `let `, `var ` или `return ` (кључна реч праћена размаком), или са `if`,
   `for` или `while` праћеним са `(` или ` (`, задржава првих 20 и последњих 5 редова, уз
   означавање изостављене средине.
2. **`grepSearch`**: садржај са најмање једним редом облика `<path>:<digits>:`,
   где текст пре прве двотачке не садржи размаке, задржава само такве редове, највише
   30, након чега следе број свих додатних подударања и листа датотека са подударањима;
   сваки други ред се одбацује. Један такав ред је довољан да активира стратегију, па се
   рачуна и ред евиденције који почиње временском ознаком као што је `12:30:45`.
3. **`shellOutput`**: из излаза који садржи ANSI CSI секвенцу (`ESC[` праћено цифрама или
   тачкама и зарезима, а затим словом, као код кодова боја) или знак `$` након којег
   било где у тексту следи размак уклањају се те секвенце (друге контролне секвенце,
   као што су `ESC[?25l` или OSC секвенца наслова прозора, задржавају се), а задржава се
   последњих 50 редова, при чему се узастопно поновљени редови сажимају. Пошто се ова
   провера извршава пре `json` и `errorMessage`, JSON или излаз грешке који садржи такав
   `$` никада не стиже до њих док је `shellOutput` укључен.
4. **`json`**: JSON садржај дужи од 2.000 знакова који почиње са `{` или `[` (након
   необавезних размака) и може да се рашчлани сажима се на следећи начин: низ са више од
   7 ставки задржава првих 5 и последње 2 ставке, као и укупан број ставки, док објекат
   задржава првих 20 кључева, при чему се свака вредност угнежђеног објекта или низа
   замењује чуваром места `{…N keys}` (за низ је N његова дужина) и ознаком
   `_remaining_<N>_keys` која броји кључеве одбачене након првих 20. Скаларне вредности
   копирају се у целости, тако да се објекат са 20 или мање кључева без угнежђених
   вредности само поново увлачи — минификованом објекту се повећава број знакова и он
   остаје непромењен.
5. **`errorMessage`**: излаз који било где и без обзира на величину слова садржи `error:`,
   `error ` (реч након које следи размак, као у `no error found`), `[error]`,
   `exception:`, `exception `, `[exception]` или `traceback` задржава свој први ред,
   наредних 10 редова и последња 3, уз ознаку `… [N frames elided] …` уместо редова
   између њих. Ознака се појављује само када након првог реда следи више од 13 редова,
   па се излаз грешке од 14 или мање редова не скраћује (код 12 или 13 редова последња
   3 реда понављају већ задржане редове).

Након што се стратегија подудари, чак и када ништа не уштеди, касније стратегије се не
испробавају. Када подударна стратегија не уштеди ниједан процењени токен (дужина ÷ 4,
заокружена навише) — на пример, датотека налик коду од 25 или мање редова или JSON низ
дужи од 2.000 знакова са 7 или мање ставки — агресивни механизам задржава оригинални
резултат алата: оба позиваоца (`compressAggressive()` и `compressAnthropicToolResultBlock()`)
задржавају оригинал када је `saved` 0 или мањи, док сам `compressToolResult()` ипак
враћа излаз те стратегије. Корак обраде резултата алата није коначан: резервни
сажимач механизма и даље може да скрати поруку типа `tool` или `function` дужу
од 8.192 знака (`maxTokensPerMessage`, 2.048, помножено са 4).

#### Када користити

Компресија резултата алата је 1. корак агресивног механизма (`compressAggressive()` у
`open-sse/services/compression/aggressive.ts`), па се извршава у агресивном режиму и у
кораку `aggressive` сложеног цевовода. Компресује поруке `tool` и `function` у OpenAI
формату и текст унутар Anthropic блокова `tool_result`. Свака стратегија има сопствени
прекидач у оквиру `aggressive.toolStrategies`, а сви су подразумевано укључени. На
контролној табли, прекидачи се налазе у приказу **Напредно** на страници Caveman док је
компресија укључена и подразумевани режим је Агресивни.

### Сложени цевовод

Сложени режим покреће **више механизама један за другим** — обично прво RTK
(60–90% уштеде на излазу алата), а затим Caveman над преосталим текстом (~46% уштеде
улаза). Комбиновано, то даје **прихватљив опсег од 78–95%** (погледајте горњу одељак
Математика уштеде узводно): `1 - (1 - 0.60..0.90) × (1 - 0.46)` у просеку износи ≈89%.

#### Како функционише

```
Улаз (1000 токена)
  → RTK (филтер који узима у обзир команде) → 200 токена
    → Caveman (уклањање сувишног садржаја) → 108 токена
  → Излаз (108 токена, ~89% уштеде)
```

#### Када користити

Користите сложени режим за:

- Токове рада који интензивно користе алате (агентско програмирање, истраживање)
- Пакетну обраду осетљиву на трошкове
- Случајеве када вам је потребна максимална уштеда токена

Сложени цевоводи се подешавају преко глобалне поставке компресије `stackedPipeline`
или преко именоване комбинације компресије додељене комбинацији усмеравања (погледајте
горњи одељак Замена по комбинацији) — не преко `modePack` аутоматске комбинације (то
поље само мења тежине избора модела аутоматске комбинације, а `stacked` није важећи
назив пакета).

## Zamene kompresije za kombinacije

Možete zameniti globalni režim kompresije **za svaku kombinaciju pojedinačno** kako biste precizno prilagodili ponašanje
različitim slučajevima upotrebe:

```json
{
  "id": "coding-combo",
  "strategy": "priority",
  "config": {
    "weights": { "taskFit": 0.5 },
    "modePack": "quality-first"
  },
  "compressionOverride": "aggressive"
}
```

Ovo je korisno za:

- **Kombinacije za programiranje**: Koristite režim `aggressive` za duge sesije
- **Kombinacije za brza pitanja i odgovore**: Koristite režim `lite` za brze odgovore
- **Kombinacije sa intenzivnom upotrebom alata**: Koristite režim `stacked` za maksimalne uštede
- **Produkcione kombinacije**: ostavite zamenu isključenu za dobavljače sa keširanjem — uvek aktivno
  prilagođavanje svesno keša automatski spušta `aggressive`/`ultra` na `standard`
  (režim `cache-aware` se ne može izabrati)
