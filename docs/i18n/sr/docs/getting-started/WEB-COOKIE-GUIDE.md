Пружаоци услуга са веб-колачићима омогућавају OmniRoute-у да користи AI услугу преко ваше постојеће сесије у прегледачу уместо API кључа. Корисни су када већ имате приступ услузи преко њеног веб-сајта и желите да OmniRoute користи исту аутентификовану сесију.

За разлику од пружалаца услуга који користе API кључеве, пружаоци услуга са веб-колачићима обављају аутентификацију помоћу акредитива које ваш прегледач шаље веб-сајту.

---

# Пре него што почнете

> **Важно:** Увек копирајте акредитиве из **активног мрежног захтева**, а **не** из складишта колачића у прегледачу.

Многи проблеми са аутентификацијом настају због копирања колачића са погрешног места.

## НЕМОЈТЕ копирати из складишта колачића

Већина прегледача приказује сачуване колачиће преко:

```
DevTools
→ Апликација (или Складиште)
→ Колачићи
```

Иако ови колачићи изгледају исправно, могу бити:

- застарели
- непотпуни
- без колачића који се шаљу само у аутентификованим захтевима

Коришћење ових вредности може да изазове неуспешну аутентификацију чак и ако делују исправно.

## Копирајте из активног захтева

Уместо тога, користите колачиће из успешног захтева:

```
DevTools
→ Мрежа
→ Освежите страницу
→ Отворите захтев за ћаскање или разговор
→ Заглавља захтева
→ Колачић
```

Заглавље захтева `Cookie` садржи тачне информације за аутентификацију које је ваш прегледач успешно употребио.

За већину пружалаца услуга са веб-колачићима, то је вредност коју треба налепити у OmniRoute.

---

# Опште подешавање

Поступак подешавања је исти за већину пружалаца услуга са веб-колачићима.

1. Пријавите се на веб-сајт пружаоца услуге.
2. Отворите алатке за програмере у прегледачу.
3. Отворите картицу **Мрежа**.
4. Освежите страницу.
5. Отворите аутентификовани захтев за ћаскање или разговор.
6. Копирајте потребне акредитиве за аутентификацију.
7. Отворите OmniRoute.
8. Идите на **Пружаоци услуга → Додај пружаоца услуге**.
9. Изаберите свог пружаоца услуге са веб-колачићима.
10. Налепите акредитиве.
11. Кликните на **Тестирај везу**.
12. Сачувајте пружаоца услуге.

Тачни потребни акредитиви зависе од пружаоца услуге.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) је бесплатна платформа за ћаскање намењена корисницима која не захтева регистрацију — сесија се анонимно креира при првој посети и чува се помоћу три колачића: `uid`, `si_usr_id` и `si_ses_id`. OmniRoute прослеђује исти `/api/dispatch` endpoint преко једног ID-а модела (`notrack-c`, алијас `ntw`).

### Кораци за повезивање

1. Отворите [notrack.ai](https://notrack.ai) у прегледачу и сачекајте да се постави колачић анонимне сесије.
2. Отворите **Алатке за програмере → Мрежа**, освежите страницу и кликните на било који `/api` захтев.
3. У одељку **Заглавља захтева** копирајте целу вредност заглавља `Cookie`.
4. У OmniRoute-у идите на **Добављачи → Додај добављача → NoTrack Web (бесплатно)**.
5. Налепите ниску колачића у поље `apiKey` и кликните на **Сачувај**.

OmniRoute издваја `uid`, `si_usr_id` и `si_ses_id` из налепљене ниске и поново саставља чисто заглавље `Cookie` које садржи само те парове — као и `nt_session` (`ntk_…` токен постављен за пријављене налоге), када је присутан. Ако било која од те три вредности недостаје, необрађена налепљена ниска прослеђује се непромењена како би оператери могли да експериментишу са алтернативним облицима.

### ID-еви модела

| ID модела   | Назив за приказ | Напомене                                                 |
| ----------- | --------------- | -------------------------------------------------------- |
| `notrack-c` | NoTrack C       | Подразумевано — модел `C` узводног dispatch система.     |
| `C`         | NoTrack C       | Алијас за `notrack-c` (необрађени узводни dispatch кôд). |
| `notrack`   | NoTrack C       | Алијас за `notrack-c`.                                   |
| `ntw`       | NoTrack C       | Кратак алијас за `notrack-c`.                            |

Сва четири ID-а модела мапирају се на исти узводни dispatch модел (`C`).

### Опције захтева

Извршилац прихвата следећа опционална поља у телу захтева:

| Поље тела             | Подразумевано | Намена                                                                               |
| --------------------- | ------------- | ------------------------------------------------------------------------------------ |
| `notrack_mode`        | `usual`       | Режим dispatch-а (ниска слободног облика; узводни систем прихвата `usual`, …)        |
| `notrack_max_turns`   | `6`           | Број интерних корака које узводни систем може да обави пре одговора.                 |
| `notrack_chat_id`     | `null`        | Настављање постојећег узводног ћаскања (изоставите за ново ћаскање).                 |
| `notrack_attachments` | `[]`          | Низ дескриптора узводних прилога који се прослеђује без измена.                      |
| `notrack_regenerate`  | `false`       | Поставите на `true` да бисте затражили поновно генерисан одговор за претходни корак. |

### Могућности

- Довршавање ћаскања **са стримовањем и без стримовања**.
- **Позивање алата** — поставите `tools: [...]` у захтеву; извршилац их сериализује у уговор омотача за позивање алата и одговоре модела поново рашчлањује у OpenAI `tool_calls`.
- **`response_format`** — подржани су `json_object` и `json_schema`. Извршилац издваја први JSON објекат из одговора модела и претвара га у ниску пре враћања.
- **Назнака резоновања** — извршилац емитује `reasoning` делту када узводни систем пошаље `thinking` догађај.

### Ограничења

- Узводни систем примењује квоте за анонимно коришћење — када се прекораче, извршилац враћа статус 429 са јасном поруком.
- Сви ID-еви модела разрешавају се на исти узводни dispatch модел; није могуће засебно пребацивање између модела.
- Извршилац не позива узводни `/api/chats` endpoint, па се историјом ћаскања и сесијама не управља аутоматски. Користите `notrack_chat_id` да бисте наставили постојеће узводно ћаскање.

# Шта добављачи веб-колачића могу, а шта не могу да раде

Добављачи веб-колачића поново користе интерфејс за ћаскање веб-сајта. Они **не** пружају исте могућности као званични API-ји.

## Подржано

- Аутентификација помоћу постојеће сесије прегледача
- Приступ моделима доступним преко вашег налога
- Стримовање одговора у ћаскању
- API кључ није потребан

## Није подржано

- Позивање функција
- Позивање алата
- Аутоматско уређивање датотека
- Агентски IDE токови рада
- Функције доступне само преко API-ја

Ово је очекивано понашање и **није** грешка.

Ако вам је потребно извршавање алата, аутоматско уређивање датотека или други агентски токови рада, користите **добављача са API кључем** уместо Web Cookie добављача.

# Напомена о валидацији

Успешан **Тест везе** или валидација колачића само потврђује да достављени акредитиви изгледају као да су у очекиваном формату.

Док се проблем #7857 не реши, успешна валидација **не гарантује** да ће добављач успешно извршити аутентификацију.

Ако аутентификација и даље не успева, проверите да ли сте копирали акредитиве из активног мрежног захтева, а не из складишта колачића прегледача.

---

# Решавање проблема

## Аутентификација не успева

Проверите да ли су акредитиви копирани из:

```
Мрежа
→ Заглавља захтева
→ Колачић
```

а **не** из:

```
Апликација
→ Колачићи
```

---

## Колачић ради у прегледачу, али не и у OmniRoute-у

Неки добављачи укључују колачиће који се шаљу само током аутентификованих захтева.

Поново копирајте акредитиве из новог мрежног захтева након успешног отварања разговора.

---

## Сесија је истекла

Web Cookie добављачи користе вашу постојећу сесију прегледача.

Ако сесија прегледача истекне или се одјавите, морате да копирате нови скуп акредитива. Да бисте аутоматизовали обнављање колачића за подржане веб-добављаче, погледајте пратећи алат [Проширење за синхронизацију сесије прегледача](../guides/SESSION-SYNC-EXTENSION.md).

---

## Тест везе пролази, али захтеви не успевају

Док се проблем #7857 не реши, успешна валидација не гарантује да ће захтев за аутентификацију успети.

Поново копирајте акредитиве из новог аутентификованог захтева пре даљег решавања проблема.

---

## ChatGPT Web не успева уз поруку "Unsupported ChatGPT integrity dependency"

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

Акредитив је исправан — ова грешка потиче из моста, а не из сесије. chatgpt.com додељује своје
идентификаторе модула при сваком постављању, а мост је раније користио фиксни идентификатор Sentinel помоћног модула који инстанцира, па је
нова верзија chatgpt.com која је преименовала помоћни модул прекинула сваки упит, док је колачић остао важећи. Поновна ауторизација
везе не може да реши овај проблем.

Верзије које разрешавају модул преко сопственог механизма извршавања странице не користе фиксни идентификатор и немају овај проблем. Ако видите ову
грешку, надоградите OmniRoute и поново покрените проверу везе.

# Најбоље праксе

- Копирајте акредитиве из новог аутентификованог захтева.
- Избегавајте поновну употребу старих колачића.
- Одржавајте сесију прегледача активном док користите Web Cookie добављаче.
- Третирајте копиране колачиће као осетљиве акредитиве.
- Користите добављаче са API кључем када вам је потребно позивање функција или агентски токови рада.
