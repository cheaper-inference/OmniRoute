## Како функционише

```
CLI кодови / CLI агенти (ток коришћења):
Claude / Codex / OpenCode / Cline / KiloCode / Continue / Hermes Agent / Goose / ...
           │
           ▼  (сви су усмерени на OmniRoute)
    http://YOUR_SERVER:20128/v1
           │
           ▼  (OmniRoute усмерава ка одговарајућем провајдеру)
    Anthropic / OpenAI / Gemini / DeepSeek / Groq / Mistral / ...

ACP агенти (обрнути ток покретања):
    Захтев клијента → OmniRoute → покреће CLI преко stdio/ACP-а → одговор
```

**Предности:**

- Један API кључ за управљање свим алатима
- Праћење трошкова за све CLI алате на контролној табли
- Промена модела без поновног конфигурисања сваког алата
- Ради локално и на удаљеним серверима (VPS, Docker, Akamai, Cloudflare Tunnel)

## Аутоматско конфигурисање помоћу `setup-*`

Не морате ручно да пишете конфигурацију за сваки алат. OmniRoute испоручује по једну `setup-*`
команду за сваки подржани CLI, која чита **актуелни** каталог модела из покренутог
OmniRoute-а (локалног или удаљеног) и уписује сопствену конфигурацију алата на вашем рачунару:

```bash
omniroute setup-codex        omniroute setup-claude       omniroute setup-opencode
omniroute setup-cline        omniroute setup-kilo         omniroute setup-continue
omniroute setup-cursor       omniroute setup-roo          omniroute setup-crush
omniroute setup-goose        omniroute setup-qwen         omniroute setup-aider
omniroute setup-5dive        omniroute setup-zed
```

Свака прихвата `--remote <url> --api-key <key>` (конфигурисање локалног алата за
удаљени OmniRoute), `--dry-run` (преглед без уписивања) и `--port`. Алати
без аутоматског откривања модела (Cline, Kilo, Roo, Goose, Aider, Qwen, 5dive) прихватају
`--model <id>` (и `--yes` за неинтерактивно покретање). `setup-5dive` је једини
поступак који не уписује испод `$HOME`: он конфигурише флоту 5dive агената тако што
уписује аутентификациони профил у власништву root корисника на хосту флоте, па се поново извршава преко `sudo`
и нема сопствени удаљени режим. Да бисте покренули CLI са
убаченим одговарајућим променљивама окружења, без икаквог уписивања конфигурације, користите генерички
покретач `omniroute run <target>` (claude, codex, aider, goose, opencode, qwen,
gemini — циљеви и алијаси потичу из `bin/cli/cli-manifest.mjs`); старији
покретачи за појединачне алате `omniroute launch` (Claude Code) и `omniroute launch-codex`
(Codex) и даље су доступни. Gemini CLI може само да се покрене: он је циљ команде `omniroute run`,
али нема `setup-*`/`configure` поступак.

> **Комплетна референца:** главна табела — шта свака команда уписује, све опције,
> локални наспрам удаљеног режима и који алати захтевају суфикс `/v1` — налази се у
> **[CLI интеграцијама](../guides/CLI-INTEGRATIONS.md)**.

### Покретање ових команди унутар контејнера

Команда `setup-*` извршена унутар OmniRoute контејнера уписује податке у
сопствени кориснички директоријум контејнера, који ниједан CLI на хосту не чита и који нестаје заједно са
контејнером. OmniRoute то открива и завршава се кодом `2`, уз упутства, уместо да
врши уписивање. Постоје два подржана начина да наставите — инсталирајте CLI на хосту и
употребите `omniroute connect` за повезивање са контејнером или монтирајте директоријуме конфигурације помоћу bind mount-а и подесите
`CLI_CONFIG_HOME` (compose профил `host`). Свака команда `setup-*`, као и
`omniroute configure` и `omniroute config set`, прихвата
`--allow-container-write` када заиста желите да конфигуришете CLI алате самог контејнера;
`OMNIROUTE_ALLOW_CONTAINER_CONFIG_WRITE=true` ради исто за
сервер. Погледајте
[Водич за Docker → Конфигурисање CLI алата на хосту](../guides/DOCKER_GUIDE.md#configuring-host-cli-tools-when-omniroute-runs-in-docker).

**Крајња тачка за примену** на контролној табли (`POST /api/cli-tools/apply`) примењује
исту заштиту: у контејнеру, покушај уписивања чије одредиште није монтирано са
хоста помоћу bind mount-а враћа **`422`** са `containerEphemeralTarget: true`, безбедним текстом
грешке и — за алате који имају поступак за хост (claude, codex, opencode, cline,
kilo, continue) — вредношћу `hostSetupCommand` (нпр. `omniroute setup-opencode`) коју треба покренути
на хосту; ништа се не уписује. `dryRun: true` наставља да ради у контејнерском
режиму и враћа редиговани преглед + путању одредишта без приступа диску. Садржај
прегледа није конфигурација са акредитивима коју треба копирати или увести. Примените
оригиналне уносе за алат/основни URL/API кључ/модел на хосту или користите назначену
команду за подешавање на хосту. Погледајте [Безбедност CLI конфигурације](../security/CLI-CONFIGURATION.md)
за заглавље прегледа и уговор захтева. Ово понашање је
намерно и заштићено од регресија тестом
`tests/unit/api/cli-tools/apply-container-guard.test.ts` — никада немојте „поправљати” 422
уклањањем заштите.

## Извор истине

Обједињени каталог се налази у `src/shared/constants/cliTools.ts` као `CLI_TOOLS: Record<string, CliCatalogEntry>`.

Свака ставка има следећа поља (дефинисана у `src/shared/schemas/cliCatalog.ts`):

| Поље                                            | Тип                                                          | Опис                                                                |
| ----------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------- |
| `category`                                      | `"code" \| "agent"`                                          | Страница на којој се алат приказује                                 |
| `vendor`                                        | `string`                                                     | Порекло алата („Anthropic“, „OSS (P. Gauthier)“)                    |
| `acpSpawnable`                                  | `boolean`                                                    | Може се користити и као ACP агент (приказује се ознака)             |
| `baseUrlSupport`                                | `"full" \| "partial" \| "none"`                              | Ниво подршке за прилагођену крајњу тачку. `"none"` = MITM заостатак |
| `configType`                                    | `"env" \| "custom" \| "guide" \| "custom-builder" \| "mitm"` | Механизам конфигурације                                             |
| `id`, `name`, `color`, `description`, `docsUrl` | стандардно                                                   | Основна поља за приказ                                              |

Ставке са `baseUrlSupport: "none"` се **не приказују** на страницама контролне табле — регистроване су у MITM заостатку за план 11 (погледајте `_tasks/features-v3.8.6/refactorpages/_orchestration/_plan11-mitm-backlog.md`).

### Нивои могућности (каталогизовано × откривљиво × конфигурабилно × покретљиво)

Није сваки каталогизовани алат могуће открити, конфигурисати или покренути. Сваки ниво има један
извор који га декларише, а тест одступања одржава њихову усклађеност:

| Ниво               | Значење                                                                                     | Декларисано у                                                                |
| ------------------ | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **Каталогизовано** | Појављује се у каталогу контролне табле (назив, добављач, документација, тип конфигурације) | `src/shared/constants/cliTools.ts` (`CLI_TOOLS`)                             |
| **Откривљиво**     | Откривање бинарне датотеке/конфигурације, провере исправности, путање конфигурације         | `src/shared/services/cliRuntime.ts` (`CLI_TOOLS` каталог времена извршавања) |
| **Конфигурабилно** | Подржано у `omniroute configure <cli>` (постоји поступак подешавања)                        | `bin/cli/cli-manifest.mjs` (`configure: true`)                               |
| **Покретљиво**     | Подржано у `omniroute run <target>` (дефинисано убризгавање окружења/аргумената)            | `bin/cli/cli-manifest.mjs` (`run: true`)                                     |

`bin/cli/cli-manifest.mjs` је канонски извршни манифест за површине CLI команди:
`run`, `configure` и генератори довршавања команди у љусци из њега изводе своје
листе циљева, разрешавање алијаса (на пример `kilocode`/`kilo-code`/`kilo_cli` → `kilo`)
и повезивање заставице `--model`. Заштита од одступања
`tests/unit/cli/cli-manifest-drift.test.ts` потврђује да манифест, каталог времена извршавања,
UI каталог и свака корисничка површина остају усклађени — циљ додат на једну
површину без осталих узрокује пад скупа тестова уместо неприметног одступања.

## 5. API за групну детекцију

Сва детекција алата обједињена је преко једне крајње тачке:

**`GET /api/cli-tools/all-statuses`**

- Аутентификација: `requireCliToolsAuth(request)` (исто као код осталих `/api/cli-tools/` рута)
- Враћа: `Record<toolId, ToolBatchStatus>` (тип: `src/shared/types/cliBatchStatus.ts`)
- Стратегија: `Promise.all` над свим алатима, временско ограничење од 5 секунди по алату
- Кеш: LRU у меморији, индексиран према `mtime` конфигурационе датотеке. Кеш се поништава када се `mtime` промени. Ресетује се при поновном покретању сервера.

Структура одговора за сваки алат:

```ts
interface ToolBatchStatus {
  detection: {
    installed: boolean;
    runnable: boolean;
    version?: string;
    command?: string;
    commandPath?: string;
    reason?: string;
  };
  config: {
    status: "configured" | "not_configured" | "not_installed" | "unknown" | "other";
    endpoint?: string | null;
    lastConfiguredAt?: string | null;
  };
  error?: string; // пречишћено, без трагова стека
}
```

## 10. Интерни OmniRoute CLI

Бинарна датотека `omniroute` пружа команде за управљање животним циклусом сервера, подешавање, дијагностику и управљање провајдерима. Улазна тачка: `bin/omniroute.mjs`.

```bash
omniroute                              # Покрени сервер (подразумевани порт 20128)
omniroute setup                        # Интерактивни чаробњак за подешавање
omniroute doctor                       # Провери конфигурацију, базу података, портове и извршно окружење
omniroute providers list               # Конфигурисане везе са провајдерима
omniroute providers test-all           # Тестирај сваку активну везу
omniroute reset-password               # Ресетуј администраторску лозинку
omniroute logs                         # Приказуј евиденцију захтева у реалном времену
omniroute health                       # Детаљно стање (прекидачи, кеш, меморија)
omniroute --version                    # Прикажи верзију
omniroute --help                       # Прикажи све команде
```

### Подешавање и иницијализација

```bash
omniroute setup                        # Интерактивни чаробњак за подешавање
omniroute setup --non-interactive      # Режим за CI/аутоматизацију (чита променљиве окружења + опције)
omniroute setup --password '<value>'   # Директно постави администраторску лозинку
omniroute setup --add-provider \
  --provider openai \
  --api-key '<value>' \
  --test-provider                      # Додај и тестирај провајдера у једном кораку
```

Препознате променљиве окружења за неинтерактивно подешавање:

| Променљива          | Намена                                                                |
| ------------------- | --------------------------------------------------------------------- |
| `OMNIROUTE_API_KEY` | API кључ провајдера (повезан са `--api-key` преко Commander `.env()`) |
| `DATA_DIR`          | Замена директоријума за OmniRoute податке                             |

Сви остали неинтерактивни уноси прослеђују се као опције, а не као променљиве окружења:
`--password`, `--provider`, `--provider-name`, `--provider-base-url`, `--default-model`
(погледајте горенаведене опције за `omniroute setup`).

### Дијагностика

```bash
omniroute doctor                       # Провери конфигурацију, базу података, портове, извршно окружење, меморију и доступност
omniroute doctor --json                # Машински читљив JSON
omniroute doctor --no-liveness         # Прескочи HTTP проверу стања
omniroute doctor --host 0.0.0.0        # Замени хост за проверу доступности
omniroute doctor --liveness-url <url>  # Замени пуни URL крајње тачке за проверу стања
```

Команда doctor извршава следеће провере: `Config`, `Database`, `Storage/encryption`,
`Port availability`, `Node runtime`, `Native binary` (better-sqlite3),
`Memory` и `Server liveness`. Завршава се кодом различитим од нуле ако било која провера има статус `fail`.

### Управљање провајдерима

```bash
omniroute providers available                       # OmniRoute каталог провајдера
omniroute providers available --search openai       # Филтрирај каталог према ID-у/називу/алијасу/категорији
omniroute providers available --category api-key    # Филтрирај према категорији (api-key, oauth, free, ...)
omniroute providers available --json                # Машински читљив JSON

omniroute providers list                            # Конфигурисане везе са провајдерима
omniroute providers list --json

omniroute providers test <id|name>                  # Тестирај једну конфигурисану везу
omniroute providers test-all                        # Тестирај сваку активну везу
omniroute providers validate                        # Само локална структурна валидација
omniroute providers add <provider> --credential-env PROVIDER_KEY
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth <provider>                 # Постојећи OAuth ток
omniroute providers edit <id|name> --default-model <model>
omniroute providers remove <id|name> --yes
```

`providers add/import/auth/edit/remove` првенствено користе API и зато раде над
активним локалним или удаљеним контекстом. За унос акредитива треба користити
`--credential-stdin` или `--credential-env`; `--dry-run --json` приказује само
редиговано присуство/структуру. `providers available` чита OmniRoute каталог;
`providers list/test/test-all/validate` задржавају своје локално SQLite понашање и
не захтевају да сервер буде покренут.

За прилагођени чвор компатибилан са OpenAI или Anthropic, придружите акредитиве
ID-у чвора који враћа `omniroute nodes add`, користећи `omniroute keys add "$NODE_ID" --stdin`.
Ово захтева покренут сервер и аутентификацију за управљање у активном контексту.
CLI користи `POST /api/providers`, који валидира чвор и копира подешавања његове
крајње тачке у везу. Непостојећи чвор, неуспела ауторизација или недоступан
сервер враћају грешку без креирања резервног локалног акредитива.

`nodes add --base-url` поставља крајњу тачку чвора; она се разликује од адресе сервера
у `OMNIROUTE_BASE_URL`. За OpenAPI датотеке користите
`omniroute openapi dump --format json --out ./openapi.json`; глобална опција `--output`
бира формат приказа CLI-ја, а не назив одредишне датотеке.

### Опоравак и ресетовање

```bash
omniroute reset-password                # Ресетуј администраторску лозинку (такође: omniroute-reset-password)
omniroute reset-encrypted-columns       # Прикажи упозорење + пробно извршавање ресетовања шифрованих акредитива
omniroute reset-encrypted-columns --force  # Заиста постави шифроване акредитиве у SQLite-у на null
```

### Извоз акредитива (⚠ поступајте опрезно)

```bash
omniroute auth export                                 # Прикажи упозорење + захтев за потврду — без приступа бази података
omniroute auth export --force                          # Извези ДЕШИФРОВАНЕ акредитиве СВИХ веза у stdout као JSON
omniroute auth export --force --id <id>                 # Извези само одговарајућу везу
omniroute auth export --force --format env               # Испиши редове OMNIROUTE_<PROVIDER>_<FIELD>=<value>
omniroute auth export --force --out creds.json           # Упиши у датотеку (креирану са дозволама 0600)
```

`auth export` ради **искључиво локално** (директно читање SQLite базе, без HTTP руте) и намерно исписује/уписује
вредности `apiKey`/`accessToken`/`refreshToken`/`idToken` као **обичан текст** — то је функционалност, а не
грешка. Ништа се не чита из базе података и ништа се не дешифрује без опције `--force`. Банер са
упозорењем се увек исписује на stderr пре него што се прикаже било какав обичан текст. Захтева да
`STORAGE_ENCRYPTION_KEY` буде постављен. Поље које не може да се дешифрује (застарели кључ, оштећен шифрат)
пријављује се као `<field>DecryptFailed: true`, уместо да се прекине цео извоз или открије основна грешка.

### Остале поткоманде

Оне подразумевају да је OmniRoute сервер покренут, осим ако није другачије наведено:

```bash
omniroute status                       # Свеобухватан статус током извршавања
omniroute logs                         # Стримовање евиденције захтева (--json, --search, --follow)
omniroute config list                  # Приказ конфигурисаних CLI алата

omniroute provider list                # Листа доступних провајдера (алијас за providers list)
omniroute provider add                 # Регистровање OmniRoute-а као провајдера у алату
omniroute keys add | list | remove     # Управљање API кључевима
omniroute models [provider]            # Листа модела (--json, --search)
omniroute combo list | switch | create | delete

omniroute backup                       # Снимак конфигурације + базе података
omniroute restore                      # Враћање из претходног снимка

omniroute health                       # Детаљно стање (прекидачи, кеш, меморија)
omniroute quota                        # Искоришћеност квоте провајдера
omniroute cache                        # Статус кеша
omniroute cache clear                  # Брисање семантичког кеша и кеша потписа

omniroute mcp status | restart         # Статус / поновно покретање MCP сервера
omniroute a2a status | card            # Статус A2A сервера / картица агента

omniroute tunnel list | create | stop  # Управљање тунелима (cloudflare/tailscale/ngrok)
omniroute env show | get <k> | set <k> <v>  # Преглед / постављање променљивих окружења (привремено)

omniroute test                         # Основни тест повезивости са провајдером
omniroute update                       # Провера доступности ажурирања
omniroute completion                   # Генерисање довршавања команди за љуску
```

## Управљање смерницама кључа за инференцију помоћу OmniRoute CLI-ја

Користите аутентификовани контекст за управљање (погледајте [Удаљени режим](../guides/REMOTE-MODE.md))
да бисте прегледали или ажурирали постојећи кључ за инференцију према његовом ID-у:

```bash
omniroute --output json keys policy show KEY_ID
omniroute keys policy set KEY_ID --unrestricted
omniroute --output json keys policy show KEY_ID
```

`--unrestricted` је псеудоним за `--model-access-mode all`. Ажурирањем се брише
листа дозвољених модела. Опсези, правила везе, блокирани модели, ограничења брзине
и ограничења трошкова остају сачувани, тако да те друге контроле и даље могу да одбију захтев. Изричито
`--allowed-models ""` такође бира `all`; комбинујте га са
`--model-access-mode restricted` да бисте задржали ограничени кључ без дозвољених модела.
Непразна листа раздвојена зарезима бира `restricted`, осим ако није изричито другачије наведено.
Противречна комбинација `all` и непразне листе дозвољених модела одбија се пре слања захтева.

`--rate-limit 30` поставља број захтева у минути и задржава правила за друге временске
периоде. `--max-cost 5` омогућава дневно ограничење у USD без промене недељног ограничења;
`--max-cost 0` уклања дневно ограничење и задржава постојећи прекидач ограничења употребе
и недељно ограничење. Изостављена поља смерница остају непромењена. Промене брзине прво
читају тренутне смернице; избегавајте истовремено уређивање низа ограничења брзине истог кључа.

Команде за смернице користе аутентификоване `GET`/`PATCH /api/keys/{id}` захтеве и поштују активни
контекст и глобалну опцију `--api-key`. JSON излаз садржи само поља смерница,
без сачуваног кључа или његовог маскираног приказа. Акредитив намењен искључиво
инференцији не може да одобри измене за управљање. Одговор 401/403 захтева проверу акредитива
и контекста за управљање; он не указује на грешку локалног CLI токена или соли.
Погледајте [CLI токен](../security/CLI_TOKEN.md) за засебан уговор локалне аутентификације.
