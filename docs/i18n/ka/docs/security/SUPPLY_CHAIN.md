OmniRoute აქვეყნებს npm + Docker არტიფაქტებს. ეს კარიბჭეები უზრუნველყოფენ წარმომავლობას, ინვენტარიზაციას (SBOM) და CVE სკანირებას, ყველა OSS, ინტეგრირებულია გამოშვების სამუშაო პროცესებში. **რეკომენდაციებზე დაფუძნებული** მიდგომა — ისინი ახლა აცნობებენ, ხოლო ბლოკირებაზე გადადიან 1-ლი წარმატებული გამოშვების შემდეგ.

| კარიბჭე               | ინსტრუმენტი                                    | სად                           | ბლოკავს?                                            | გამომავალი                                    |
| --------------------- | ---------------------------------------------- | ----------------------------- | --------------------------------------------------- | --------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | მხოლოდ იმ შემთხვევაში, თუ გამოქვეყნება ვერ მოხერხდა | badge npmjs / `npm audit signatures`          |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | მხოლოდ იმ შემთხვევაში, თუ გენერაცია ვერ მოხერხდა    | Release asset + artifact                      |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | რეკომენდაცია                                        | CycloneDX artifact                            |

| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **ბლოკირება**                                       | `exit-code: '1'` on fixable CRITICAL          |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ბლოკირება**                                       | ratchets `metrics.vulnCount` (direction:down) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | რეკომენდაცია                                        | SARIF → Security + badge                      |

გამოსახულების CVE რეტჩეტი იყენებს **ორ ნაბიჯს** `docker-publish.yml`-ში: SARIF ნაბიჯი (`HIGH,CRITICAL`, `exit-code: 0`) ინარჩუნებს HIGH+CRITICAL ხილვადობას უსაფრთხოების ჩანართში ბლოკირების გარეშე; _CRITICAL კარიბჭის_ ნაბიჯი (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) აჩერებს გამოშვებას CRITICAL CVE-ზე, **რომლისთვისაც ხელმისაწვდომია გამოსწორება**. `ignore-unfixed` ხელს უშლის გამოშვების ბლოკირებას საბაზისო გამოსახულების CVE-სთვის ზედა დინების პატჩის გარეშე.

## ⚠️ CVE ვარიაცია (osv/Trivy კარიბჭეების ბლოკირება)

osv და Trivy ადარებენ დამოკიდებულებებს CVE მონაცემთა ბაზებთან, რომლებიც **მუდმივად იზრდება**. PR, რომელიც **არ ეხება არანაირ დამოკიდებულებას**, შეიძლება მოულოდნელად გაწითლდეს, რადგან ახალი CVE გამოვლინდა არსებულ დამოკიდებულებაში (osv: გაზომილი `vulnCount` > საბაზისო; Trivy: ახალი გამოსწორებადი CRITICAL გამოსახულებაში). **ეს არის ბლოკირებადი CVE კარიბჭის მოსალოდნელი ოპერაციული ქცევა და არა პროდუქტის რეგრესია.**

როდესაც osv ან Trivy წითლდება ახლად გამოვლენილი CVE-ის გამო, გამოსავალია:

1.  **დაზარალებული დამოკიდებულების განახლება** (სასურველია) — განაახლეთ პატჩირებულ ვერსიამდე `package.json` `overrides`-ის (ტრანზიტული დამოკიდებულებები) მეშვეობით ან ხელახლა ააწყვეთ გამოსახულება პატჩირებულ ბაზაზე.
2.  **თუ არ არსებობს ზედა დინების გამოსწორება:**
    - **osv:** ხელახლა დააყენეთ საბაზისო `metrics.vulnCount` `config/quality/quality-baseline.json`-ში (`npm run quality:ratchet -- --update` არ მოიცავს სპეციალურ კარიბჭეებს — შეცვალეთ მნიშვნელობა ხელით, `direction:down`) დასაბუთების შენიშვნით + თრექინგის საკითხით.
    - **Trivy:** დაამატეთ ჩანაწერი `.trivyignore`-ში (CVE-ID თითო ხაზზე) დასაბუთების კომენტარით + თრექინგის საკითხით. `ignore-unfixed: true` უკვე ავტომატურად მოიცავს CVE-ებს პატჩების გარეშე.

ორივე კარიბჭე **მოხდენილად გამოტოვებს** (exit 0) როდესაც ინსტრუმენტი არ არის ან გაზომვა ვერ ხერხდება (osv-scanner არ არის PATH-ში, osv.dev/network მიუწვდომელია, არასწორი JSON) — **გაზომვის** შეცდომა არასოდეს ბლოკავს, მხოლოდ **გაზომილი** რეგრესია ბლოკავს.

## მოხსნილი დამოკიდებულების რისკი

დაფიქსირებული promptfoo-ის დეველოპერული ხელსაწყოს განახლების შემდეგ, ძირითადი lockfile აღარ შეიცავს `extract-zip`-ს ან მასთან მიმავალ დამოკიდებულების კავშირს. ამით იხსნება #14482-ში აღრიცხული, ადრე დაშვებული `promptfoo` → `@openai/codex-security` → `extract-zip` ჯაჭვი. `tests/unit/extract-zip-14482-exposure.test.ts`-ში არსებული რეგრესიის შემოწმებები უარყოფს მის ხელახლა დამატებას და ინარჩუნებს პროდუქციული კოდიდან იმპორტების აკრძალვას.

დამოკიდებულებების მიმდინარე შესწორება ასევე ზღუდავს თავსებადობის ჩანაცვლებებს Azure identity-ის MSAL კლიენტით, get-uri-ის FTP კლიენტითა და OpenCode v1 SDK-ის Zod დამოკიდებულებით. Azure-ის ტოკენის მიღება და FTP-ით მონაცემების წამოღება კონტროლირებადი ტრანსპორტებით მოწმდება; OpenCode-ის ორივე პაკეტი საკუთარ აგებისა და ტესტირების კომპლექტებს უშვებს. რეესტრის უსაფრთხოების შეტყობინებების რაოდენობები დროის კონკრეტულ მომენტში მიღებული მაჩვენებლებია და შეიძლება lockfile-ის დაფიქსირების შემდეგ შეიცვალოს.
