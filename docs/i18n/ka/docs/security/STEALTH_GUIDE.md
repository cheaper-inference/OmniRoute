## სამართლებრივი და ეთიკური შეტყობინება

შენიღბვის ფუნქციები არსებობს იმისთვის, რომ OmniRoute-მა იმოქმედოს თავსებადობის შრის სახით მომხმარებლის საკუთრებაში არსებულ ოფიციალურ ანგარიშებსა (Claude Code CLI, Codex, Antigravity, Cursor და სხვ.) და OmniRoute-ის ერთიან API-ს შორის. ისინი **არ არის** განკუთვნილი თაღლითობის გამოვლენის მექანიზმებისთვის თავის ასარიდებლად, ავტორიზაციის მონაცემების გასაზიარებლად ან პროვაიდერის მომსახურების პირობების დასარღვევად. მომვლელები მოელიან, რომ ოპერატორები დაიცავენ იმ ზედა დონის პროვაიდერის ToS-ს, რომელსაც ანგარიშების შექმნისას დაეთანხმნენ.

## TLS Fingerprinting ფენა

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

მუდმივი `wreq-js` სესიები ზარმაცად იქმნება თითოეული ანგარიშის არეალისა და განსაზღვრული პროქსისთვის.
პროცესის მასშტაბით მოქმედი `TlsClient` მაქსიმუმ 128 სესიას აერთიანებს, რომლებიც Cloudflare-ის უკან
არსებული upstream-სერვერებისთვის **macOS-ზე Chrome 124-ის** იმიტაციას ახდენენ. როდესაც ნატიური
runtime მიუწვდომელია, `TlsClient.fetch()` უსაფრთხოდ წყვეტს მუშაობას; გამომძახებელს შეუძლია ამ
wrapper-ის გარეთ აშკარად აირჩიოს სათადარიგო ვარიანტი.

- სესიის პროფილი: `browser: "chrome_124", os: "macos"`
- პროქსის განსაზღვრა (პრიორიტეტი): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (ასევე ქვედა რეგისტრის ვარიანტები)
- მოლოდინის დრო: `TLS_CLIENT_TIMEOUT_MS` (მემკვიდრეობით იღებს `FETCH_TIMEOUT_MS`-დან, ნაგულისხმევად 600000)
- `wreq-js` Response თავსებადია fetch-თან (`headers`, `text()`, `json()`, `clone()`, `body`).
- პირველი ბაიტის watchdog (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`
  სრულდება upstream-ის სათაურების მიღებისთანავე, ამიტომ მხოლოდ `TLS_CLIENT_TIMEOUT_MS` ვერ შეზღუდავს
  body-ს, რომელიც პირველ ბაიტს არასოდეს აბრუნებს. `guardTlsFirstByte()` body-ს პირველ `read()`-ს
  აჯიბრებს `TLS_FIRST_BYTE_WATCHDOG_MS`-თან (ნაგულისხმევად `10000`; `0` მას თიშავს); გამართულ body-ზე
  ეს გავლენას არ ახდენს, ხოლო გაჩერებული body აუქმებს wreq reader-ს და `proxyFetch`-ის არსებულ
  TLS-ის სათადარიგო ლოგიკას პირდაპირი/პროქსი დისპეტჩერის გამოყენების საშუალებას აძლევს (ხელახლა
  გასაშვებად არაუსაფრთხო მოთხოვნა, მაგალითად body-ს შემცველი POST, კვლავ შეცდომას აგდებს და
  შეუმჩნევლად ხელახლა არ იგზავნება).

### ვებ-cookie პროვაიდერის ტრანსპორტი — wreq-js 3.2.0

## Claude Code-ის შენიღბვის პაკეტი

როდესაც `cliCompatMode` ჩართულია, OmniRoute გამავალ Claude-ის მოთხოვნებს ისე გარდაქმნის, რომ ისინი `claude-cli`-ის ტრაფიკისგან განურჩეველი იყოს. ამაზე სამი მოდული ერთობლივად მუშაობს:

### `claudeCodeFingerprint.ts`

ითვლის ბილინგის სათაურში ჩაშენებულ 3-სიმბოლოიან `cc_version` ანაბეჭდს:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (კოდშია ფიქსირებულად ჩაწერილი; ემთხვევა ოფიციალურ კლიენტს)
- შეყვანა: პირველი მომხმარებლის შეტყობინების ტექსტის მე-4, მე-7 და მე-20 ინდექსებზე არსებული სიმბოლოები + ვერსიის სტრიქონი
- გამომავალი: 3-სიმბოლოიანი თექვსმეტობითი პრეფიქსი

### `claudeCodeCCH.ts` (კლიენტის შიგთავსის ჰეში)

სერვერის მხარეს მთლიანობის შემოწმება, რომელსაც ოფიციალური Claude Code CLI Bun/Zig-ის საშუალებით ითვლის. OmniRoute ამას `xxhash-wasm`-ით ხელახლა ახორციელებს:

1. სხეულის სერიალიზაცია `cch=00000;` ადგილმჭერის გამოყენებით
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. ნულებით შევსებული 5-სიმბოლოიანი, ქვედა რეგისტრის თექვსმეტობითი მნიშვნელობა

კონსტანტები:

- საწყისი მნიშვნელობა: `0x6e52736ac806831e`
- ნიმუში: `/\bcch=([0-9a-f]{5});/`

## Antigravity Stealth

Antigravity ითხოვს შეინახოს აბონენტის ტექსტი ბაიტი-ბაიტი. OmniRoute არ ჩასვამს ნულოვანი სიგანის სიმბოლოებს მოთხოვნებში ან rename/inject ინსტრუმენტებში IDE კლიენტის იმიტაციისთვის.

### `antigravityHeaderScrub.ts`

ზოლები უჟანგავი SDK მარკერები (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) გადაგზავნის წინ.

### ⚠️ რისკი: `ANTIGRAVITY_CREDITS=always` (ანგარიშის აკრძალვის ცხელი წერტილი)

`ANTIGRAVITY_CREDITS=always` (მოხმარებული `open-sse/executors/antigravity.ts`) მარშრუტები** ყოველი** მოითხოვეთ Antigravity AI Credit Overages-ის მეშვეობით (გადახდილი Google კრედიტები) ნაცვლად Google ის თავისუფალი დონის კვოტის კარიბჭის ნივთების დაშვების ნაცვლად. ეს არის დოკუმენტირებული, როგორც მახასიათებელი, მაგრამ ასეა** ყველაზე გავრცელებული ToS-დარღვევის ანგარიში, რომელსაც ჩვენ ვხედავთ** — მრავალი Google Ultra ანგარიშები აიკრძალა `403 / "service disabled for ToS violation" / insufficient_quota` ით `=always` ით რამდენიმე საათის გაშვების შემდეგ.

```ts
}
```

ჩართეთ ან გამორთეთ თითოეული პროვაიდერისთვის გარემოს ცვლადის მეშვეობით (იხილეთ ქვემოთ). გამორთვისას სათაურები/სხეულის გასაღებები გამოჩნდება იმ თანმიმდევრობით, რომლითაც ისინი Node-მა/JSON-მა მოგვაწოდა — რაც თითის ანაბეჭდის დადგენას ამარტივებს.

## MITM პროქსი (Antigravity, Linux/macOS/Windows)

იმ CLI-ებისთვის, რომელთა ბინარული ფაილების გადამისამართებაც `OPENAI_BASE_URL`-ის მეშვეობით შეუძლებელია, OmniRoute უშვებს ლოკალურ TLS-ტერმინირებად პროქსის. საბოლოო წერტილები მდებარეობს `src/app/api/cli-tools/antigravity-mitm/`-ის ქვეშ.

| მეთოდი | საბოლოო წერტილი                         | დანიშნულება                                           |
| ------ | --------------------------------------- | ----------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | სტატუსი — გაშვებულია, pid, dnsConfigured, certExists  |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM-ის გაშვება (საჭიროებს `apiKey` + `sudoPassword`) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM-ის გაჩერება                                      |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | მოდელის ფსევდონიმების სიის მიღება                     |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | ხელსაწყოსთვის მოდელის ფსევდონიმების შენახვა           |

გადაჭერილი სამიზნე ჰოსტი: **`daily-cloudcode-pa.googleapis.com`** (Antigravity-ის ზედა დონის სერვისი).

### გაშვების თანმიმდევრობა (`src/mitm/manager.ts::startMitm`)

1. თვითხელმოწერილი სერტიფიკატის გენერირება `selfsigned`-ის მეშვეობით (RSA-2048, SHA-256, 1 წელი) — `cert/generate.ts`
2. სერტიფიკატის დაყენება სისტემის სანდო სერტიფიკატების საცავში — `cert/install.ts`
3. ჰოსტების ჩანაწერის `127.0.0.1 daily-cloudcode-pa.googleapis.com` დამატება — `dns/dnsConfig.ts`
4. `src/mitm/server.cjs`-ის გაშვება `ROUTER_API_KEY` + `MITM_LOCAL_PORT`-ით (ნაგულისხმევი მნიშვნელობაა `443`)
5. PID-ის შენახვა `<DATA_DIR>/mitm/.mitm.pid`-ში

### Linux-ის სანდო სერტიფიკატების საცავის დინამიკური აღმოჩენა — `cert/install.ts`

`getLinuxCertConfig()` ამოწმებს პრიორიტეტულ სიას და ირჩევს პირველ არსებულ დირექტორიას:

| დისტრიბუტივების ოჯახი    | დირექტორია                                  | განახლების ბრძანება      |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

სერტიფიკატის ფაილის სახელი: `omniroute-mitm.crt`. თითის ანაბეჭდის დამთხვევა ხდება `getCertFingerprint()`-ის მეშვეობით (DER-ის SHA-1).

დამატებით, როდესაც `certutil` ხელმისაწვდომია, `updateNssDatabases()` სერტიფიკატს აყენებს თითოეული მომხმარებლის NSS მონაცემთა ბაზებში: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, Firefox-ის ყველა პროფილში (snap-ის ჩათვლით), მეტსახელით **`OmniRoute MITM Root CA`**.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** ადმინისტრატორის უფლებებით გაშვებული PowerShell → `certutil -addstore Root`

### ავთენტიფიკაცია

MITM-ის ყველა საბოლოო წერტილი მოითხოვს მართვის ავთენტიფიკაციას (`requireCliToolsAuth`). sudo-ს პაროლი ინახება მოდულის ხედვის არეში (არასოდეს `globalThis`-ში) და იშლება `stopMitm()`-ის გამოძახებისას.
