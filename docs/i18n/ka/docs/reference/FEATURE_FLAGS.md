## რა არის ფუნქციური დროშები

ფუნქციური დროშა არის სახელდებული გადამრთველი (boolean ან enum), რომლის მნიშვნელობაც შეიძლება შეიცვალოს
შესრულების დროს და შენარჩუნდეს მონაცემთა ბაზაში, პროცესის ხელახლა განთავსების საჭიროების გარეშე. თითოეული
დროშა აღწერილია `FeatureFlagDefinition`-ით, რომელსაც აქვს `key`, `label`,
`description`, `category`, `defaultValue`, `type` და `requiresRestart` მინიშნება.

### მნიშვნელობის განსაზღვრის რიგითობა

დროშის **ეფექტური მნიშვნელობა** განისაზღვრება
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts)-ის მიერ შემდეგი
პრიორიტეტით (იმარჯვებს ყველაზე მაღალი):

1. **DB გადაფარვა** — `key_value` ცხრილში, `feature_flags`
   სახელთა სივრცეში შენახული მნიშვნელობა (დაყენებული მართვის პანელიდან ან REST API-დან).
2. **გარემოს ცვლადი** — `process.env[<KEY>]`, თუ დაყენებულია და ცარიელი არ არის.
3. **განსაზღვრების ნაგულისხმევი მნიშვნელობა** — `defaultValue` ფაილიდან `featureFlagDefinitions.ts`.

boolean დროშა **ჩართულად** ითვლება, როცა მისი ეფექტური მნიშვნელობაა `"true"`,
`"1"` ან `"yes"` (იხილეთ `isFeatureFlagEnabled()`).

> [!NOTE]
> დროშების უმეტესობას ასევე აქვს **იმავე სახელის** შესაბამისი გარემოს ცვლადი,
> რომელიც დოკუმენტირებულია [`ENVIRONMENT.md`](./ENVIRONMENT.md)-ში. დროშის DB გადაფარვას
> ამ გარემოს ცვლადზე მაღალი პრიორიტეტი აქვს. დროშა, რომელსაც აქვს
> `requiresRestart: true`, დაუყოვნებლივ ინახება, მაგრამ ხელახლა მხოლოდ პროცესის
> გაშვებისას იკითხება — მისი გადართვისას მართვის პანელში გამოჩნდება ბანერი **"სერვერის გადატვირთვა"**.

## ალმების გადართვა

### დეშბორდი

გადადით **დეშბორდი → პარამეტრები → ფუნქციების ალმები**
(`/dashboard/settings/feature-flags`). ბადე
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
მხარს უჭერს:

- **ძიებას** გასაღებით ან აღწერით და **ფილტრაციას** კატეგორიის მიხედვით (ასევე სინთეზურ
  **გადატვირთვას საჭიროებს** ხედს).
- ლოგიკური ალმებისთვის **გადამრთველს**, ხოლო enum ალმებისთვის **ჩამოსაშლელ სიას**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- თითოეული ალმისთვის **წყაროს ბეჯს** — `DB`, `ENV` ან `DEF` — რომელიც აჩვენებს, საიდან
  მოდის ეფექტური მნიშვნელობა.
- **Reset** ღილაკს (ნაჩვენებია მხოლოდ `DB` წყაროდან მიღებული ალმებისთვის) override-ის
  წასაშლელად და ქვედა ნაწილში **Reset All Overrides** ღილაკს.
- **Restart Server** ბანერს, როდესაც `requiresRestart` ალმი იცვლება.

### REST API

ყველა ოპერაცია გადის ერთ route-ზე:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
თითოეული მეთოდი მოითხოვს დეშბორდის ავტენტიფიცირებულ სესიას (`401` სხვა შემთხვევაში).

#### `GET /api/settings/feature-flags`

აბრუნებს ყველა ალმს ეფექტურ მნიშვნელობასთან, წყაროსთან და შეჯამებასთან ერთად.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... ყველა 114 ალმი
  ],
  "summary": {
    "total": 114,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

დააყენეთ ან წაშალეთ ერთი override. Body: `{ key: string; value?: string }`.
`value`-ის გამოტოვება წაშლის override-ს (აღადგენს env / default მნიშვნელობას).

```bash
# DB override-ის დაყენება
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# override-ის წაშლა ("value"-ის გარეშე)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

პასუხში ბრუნდება ახალი `effectiveValue`/`source`, `previousValue`/
`previousSource` და `requiresRestart`. უცნობი გასაღებები და დასაშვები დიაპაზონის
გარეთ მყოფი enum მნიშვნელობები უარყოფილია `400`-ით.

#### `DELETE /api/settings/feature-flags`

ერთდროულად წაშლის ყველა **DB override**-ს და თითოეულ ალმს დაუბრუნებს მის env / default
მნიშვნელობას. აბრუნებს `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> `requiresRestart: true` მქონე ალმები ძალაში შედის მხოლოდ პროცესის გადატვირთვის შემდეგ.
> დეშბორდის გადატვირთვის პროცესი იძახებს `POST /api/restart`-ს და შემდეგ ამოწმებს
> `GET /api/health/ping`-ს, სანამ სერვერი ხელახლა ხელმისაწვდომი გახდება.

## ბიუჯეტის საგანგებო სარეზერვო მექანიზმი

`OMNIROUTE_EMERGENCY_FALLBACK` (კატეგორია `runtime`, ნაგულისხმევი მნიშვნელობა `true`) აკონტროლებს
უფასო საგანგებო სარეზერვო მარშრუტს ფაილში
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
როდესაც ის ჩართულია, მოთხოვნები, რომლებმაც თავიანთი ბიუჯეტი ამოწურეს, პირდაპირ უარყოფის ნაცვლად
უფასო სარეზერვო პროვაიდერთან/მოდელთან გადაიმისამართება. ამ ქცევის გასათიშად და ბიუჯეტამოწურული მოთხოვნების
წარუმატებლად დასასრულებლად დააყენეთ მისი მნიშვნელობა `false`-ზე (ან `0`-ზე) — მართვის პანელის
გადამრთველის, DB-ში მნიშვნელობის გადაფარვის ან `OMNIROUTE_EMERGENCY_FALLBACK`
გარემოს ცვლადის მეშვეობით. (მართვის პანელზე გადამრთველის სახით წარმოდგენილია PR-ებში #3741 / #3752.)

ამ სარეზერვო მექანიზმის მიერ მოწოდებული პასუხი შეიცავს სათაურს
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, ამიტომ
კლიენტს შეუძლია გაიგოს, რომ მოთხოვნა გადაიმისამართა, მის მოთხოვნასთან
`X-OmniRoute-Provider`-ის შედარების გარეშე. ყველა სხვა პასუხში ეს სათაური არ არის.
