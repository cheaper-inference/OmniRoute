## 2. წესები

1. ტოკენები, არასოდეს ლიტერალები. განზრახ დატოვებული გამონაკლისები: ყოველთვის მუქი კონსოლის
   ტერმინალი, ReactFlow SVG შტრიხები `STATUS_HEX`-ით (`src/shared/constants/statusColors.ts`) და
   კატეგორიული პალიტრები
   `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) და
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`).
2. არასოდეს დააპატჩოთ `packages/ui-kit/src` ხელით: სინქრონიზდით
   `scripts/dev/sync-ui-kit.sh <commit>`-ით; pre-commit კარი `npm run check:ui-kit-snapshot`
   (`.husky/pre-commit`) ჩაიშლება ნებისმიერ ბაიტზე, რომელიც განსხვავდება დაფიქსირებული აპსტრიმ
   კომიტისგან (ის გამოიტოვებს შემოწმებას გაფრთხილებით, როცა აპსტრიმ კლონი, `UI_KIT_CLONE` ან
   `_references/cheaper-inference-ui-kit`, არ არსებობს). როცა კიტს რაღაც აკლია, გვერდი გაუარეთ
   ადაპტერში ან ეკრანში და სთხოვეთ აპსტრიმს მისი დამატება.
3. კიტის ტექსტის ნაგულისხმევი მნიშვნელობები ინგლისურია (`label = "Loading"`, `loadingLabel = "Loading table"`…) —

   `RequestLoggerDetail`); ყოველ ნედლ `<button>`-ს ან `<input>`-ს იქ სჭირდება კომენტარი, რომელიც
   შეიცავს `kit-exception:`-ს (მიზეზით) და მთავრდება მის ზემოთ მაქსიმუმ 3 ხაზით; პალიტრის ტონები

1. შეინარჩუნეთ `src/shared/components/index.tsx`-ის საჯარო API: იგივე ექსპორტის სახელები, default ექსპორტები და მიღებული props-ები. ძველი props-ები kit-ზე გადაიყვანეთ ადაპტერის შიგნით (იხ. `Button.tsx`: `VARIANT_TO_KIT`, `SIZE_TO_KIT`).
