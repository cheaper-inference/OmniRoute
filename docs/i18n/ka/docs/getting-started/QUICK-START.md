## ნაბიჯი 1: დააინსტალირეთ OmniRoute

აირჩიეთ თქვენთვის სასურველი მეთოდი:

### ვარიანტი A: npm (რეკომენდებული)

```bash
npm install -g omniroute
```

### ვარიანტი B: Docker

```bash
docker run -d --name omniroute -p 20128:20128 diegosouzapw/omniroute:latest
```

`:latest` არის ყველაზე მაღალი **გამოქვეყნებული** სტაბილური SemVer. ის არ მიჰყვება git-ის `main` შტოს. GitOps-ისთვის გამოიყენეთ ფიქსირებული `diegosouzapw/omniroute:X.Y.Z`. იხილეთ [იმიჯის ტეგები / გამოშვების არხები](../guides/DOCKER_GUIDE.md#release-channels).

### ვარიანტი C: საწყისი კოდიდან

```bash
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
npm install
npm run dev
```

---

## ნაბიჯი 2: გაუშვით OmniRoute

```bash
omniroute
```

OmniRoute გაეშვება მისამართზე `http://localhost:20128`. მართვის პანელი ავტომატურად გაიხსნება.

---

## ნაბიჯი 3: შესაბამისი პროვაიდერის დაკავშირება

აირჩიეთ პროვაიდერი, რომლის პირობები და კვოტა თქვენს საჭიროებებს შეესაბამება. განყოფილებაში **Dashboard → Providers** დააკავშირეთ თქვენი ანგარიში ან API გასაღები, შემდეგ კი შეამოწმეთ კავშირი. უფასო წვდომა და გასაღების გარეშე ხელმისაწვდომობა გარანტირებული არ არის.

ნაგულისხმევად, `auto` გამორიცხავს პროვაიდერებს, რომლებსაც მონიშნული აქვთ `tos: avoid`, მათ შორის Kiro-ს. ანგარიშის დაკავშირება ამ პოლიტიკას არ ცვლის. განყოფილებაში **Dashboard → Combos** თანხმობის გაცხადება ყველა ავტომატურ კომბინაციაზე ვრცელდება. პროვაიდერის არჩევამდე გაეცანით [უფასო ტარიფების სახელმძღვანელოს](./FREE-TIERS-GUIDE.md).

---

## ნაბიჯი 4: შეამოწმეთ, რომ მუშაობს

[API გასაღებების](http://localhost:20128/dashboard/api-manager) გვერდიდან შექმენით ახალი გასაღები. შეინახეთ ეს გასაღები, რადგან ის ხელახლა აღარ გამოჩნდება. გაითვალისწინეთ, რომ ეს გასაღები განკუთვნილია ხელსაწყოებისთვის OmniRoute-ზე წვდომის მისაღებად და არა ზედა დონის პროვაიდერებზე წვდომისთვის.

```bash
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"
```

სიაში თქვენი დაკავშირებული მოდელები უნდა გამოჩნდეს.

## ნაბიჯი 5: მიუთითეთ OmniRoute თქვენს IDE-ს ან CLI-ს

თქვენს IDE-ში ან CLI ხელსაწყოში დააყენეთ:

```
საბაზისო URL: http://localhost:20128/v1
API გასაღები: [დააკოპირეთ მართვის პანელიდან → ბოლო წერტილები]
მოდელი:       auto
```

სულ ესაა! თქვენი IDE ახლა იყენებს OmniRoute-ს პროვაიდერის ავტომატური შერჩევით.

### IDE-ის მაგალითი: VSCode/Continue.dev

1. VSCode-ში დააინსტალირეთ [Continue.dev](https://marketplace.visualstudio.com/items?itemName=Continue.continue) გაფართოება.
2. განაახლეთ თქვენი `~/.continue/config.yaml` და დაამატეთ შემდეგი ხაზები:

```
  - name: OmniRoute - Auto
    provider: openai
    model: auto
    apiBase: http://localhost:20128/v1
    apiKey: <YOUR_KEY>
```

3. Continue.dev-ის ჩატის პანელში აირჩიეთ `OmniRoute - Auto` და მოთხოვნები OmniRoute-ში გაიგზავნება.
4. (არასავალდებულო) სავარჯიშო მკითხველისთვის — სთხოვეთ თქვენს IDE-ს, განაახლოს `config.yaml` ყველა სხვა წინასწარ მომზადებული კონფიგურაციით 😊

### CLI-ის მაგალითი: Codex CLI

1. თქვენს ოპერაციულ სისტემაში გარემოს ცვლადი მუდმივად დააყენეთ.
   macOS/Linux-ისთვის (დაამატეთ თქვენს `~/.bashrc` ან `~/.zshrc` ფაილში):

```bash
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

Windows-ისთვის (Command Prompt):

```
setx OMNIROUTE_API_KEY <YOUR_KEY>
```

2. ახლა გავუშვათ Codex, თუმცა OmniRoute-ისთვის კონფიგურირებული. გაუშვით:

```
omniroute launch-codex --model auto
```

ამის ხელით გაკეთება შეგიძლიათ `codex`-ისა და ბრძანების სტრიქონის პარამეტრების გამოყენებით, ბოლო წერტილისა და API გასაღების მისათითებლად, მაგრამ ზემოთ მოცემული ბრძანებით OmniRoute ყველაფერზე თავად იზრუნებს.

იგივე ერთბრძანებიანი გაშვება სხვა CLI-ებისთვისაც მუშაობს უნივერსალური გამშვების მეშვეობით — `omniroute run <target>` მხარს უჭერს `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen` და `gemini` ხელსაწყოებს (იხილეთ [CLI ინტეგრაციები](../guides/CLI-INTEGRATIONS.md)).

3. ახლა CLI მოთხოვნებს OmniRoute-ში უნდა აგზავნიდეს.

### დაადასტურეთ, რომ თქვენი ხელსაწყო მოთხოვნებს OmniRoute-ში მარშრუტიზებს

მოთხოვნის დეტალების ნახვა შეგიძლიათ მარცხენა გვერდითა ზოლში [მონიტორინგი/ჟურნალები](http://localhost:20128/dashboard/logs)-ზე დაწკაპუნებით. ჩანაწერებზე დაწკაპუნებით დამატებით დეტალებს იხილავთ. სხვათა შორის, შეგიძლიათ ნახოთ, რა ინფორმაცია იგზავნება თქვენი საყვარელი გარემოდან. ეს სასარგებლოა როგორც სწავლის, ისე გამართვის თვალსაზრისით.

## ხშირად დასმული კითხვები

### „მჭირდება API გასაღები?“

OmniRoute-ის API გასაღები თქვენი ხელსაწყოების ავთენტიფიკაციას უზრუნველყოფს. გარე პროვაიდერის ავტორიზაციის მონაცემები დამოკიდებულია კონკრეტულ პროვაიდერზე: ზოგიერთ მათგანს API გასაღები ან ანგარიშზე შესვლა სჭირდება. უფასო წვდომა გარანტირებული არ არის.

### „რა არის `auto`?“

`auto` OmniRoute-ს მიუთითებს, რომ თითოეული მოთხოვნისთვის ავტომატურად შეარჩიოს საუკეთესო პროვაიდერი. ის ითვალისწინებს სიჩქარეს, ღირებულებას, ხარისხსა და ხელმისაწვდომობას. დეტალებისთვის იხილეთ [Auto-Combo-ს სახელმძღვანელო](./AUTO-COMBO-GUIDE.md).

### „რა ღირს?“

თავად OmniRoute **უფასო და ღია კოდის მქონეა**. იხდით მხოლოდ იმ პროვაიდერების მომსახურებისთვის, რომლებსაც იყენებთ. ბევრ პროვაიდერს აქვს უფასო ტარიფები — იხილეთ [უფასო ტარიფების სახელმძღვანელო](./FREE-TIERS-GUIDE.md).

### „შემიძლია მისი გამოყენება Claude Code-თან / Cursor-თან / Copilot-თან?“

**დიახ!** OmniRoute მუშაობს ნებისმიერ ხელსაწყოსთან, რომელსაც OpenAI-ის ფორმატის მხარდაჭერა აქვს. უბრალოდ საბაზისო URL-ად მიუთითეთ `http://localhost:20128/v1`. დაყენების კონკრეტული ინსტრუქციებისთვის იხილეთ [CLI ხელსაწყოების სახელმძღვანელო](../reference/CLI-TOOLS.md).

### „რა მოხდება, თუ პროვაიდერი გაითიშება?“

OmniRoute ავტომატურად გამოტოვებს გაუმართავ პროვაიდერებს და შემდეგს სცდის. არაფრის გაკეთება არ გჭირდებათ. დეტალებისთვის იხილეთ [Auto-Combo-ს სახელმძღვანელო](./AUTO-COMBO-GUIDE.md).
