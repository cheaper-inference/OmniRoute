## რას წარმოადგენს

OmniRoute რეგისტრაციას უკეთებს 376 პროვაიდერს, მათ შორის კატალოგის 155 ჩანაწერს, რომლებიც მონიშნულია როგორც **უფასო/ავთენტიფიკაციის გარეშე**
(ავთენტიფიკაციის გარეშე,
უფასო დონის OAuth ან უფასო დონის API გასაღები — იხილეთ
[უფასო დონეების სახელმძღვანელო](../getting-started/FREE-TIERS-GUIDE.md) და სრული
[უფასო დონეების კატალოგი](../reference/FREE_TIERS.md)). თუმცა, უფასო პროვაიდერების მოდელების ხარისხი
მნიშვნელოვნად განსხვავდება. ავთენტიფიკაციის გარეშე მომუშავე პროვაიდერი, რომელიც მოწინავე მოდელს ემსახურება, გაცილებით სასარგებლოა,
ვიდრე ის, რომელიც მცირე ზომის მოძველებულ მოდელს ემსახურება.

**უფასო პროვაიდერების რეიტინგი** პასუხობს კითხვას „**რომელი უფასო პროვაიდერი მაძლევს საუკეთესო მოდელს?**“ —
თითოეული უფასო პროვაიდერის კატალოგის **მომხმარებელთა მიერ ერთობლივად შედგენილ ხარისხის შეფასებებთან** გაერთიანებით,
რომლებიც მიღებულია **Arena AI-ის რეიტინგიდან** (ადამიანთა უპირატესობებზე დაფუძნებული ELO — იგივე იდეა, რომელსაც ეფუძნება LMArena-ს
ჩატბოტების არენა). შემდეგ პროვაიდერების რანჟირება ხდება მათი **საუკეთესო უფასო მოდელის** შესაძლებლობების მიხედვით.

რეიტინგი გამოითვლება სამი რეალური წყაროს საფუძველზე:

1. უფასო პროვაიდერების სიები — `NOAUTH_PROVIDERS`, ასევე `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` ჩანაწერები, რომლებიც მონიშნულია `hasFree`-ით
   (`src/shared/constants/providers.ts`).
2. თითოეული პროვაიდერის მოდელების კატალოგი პროვაიდერთა რეესტრიდან
   (`open-sse/config/providerRegistry.ts`).
3. ELO-ზე დაფუძნებული, ამოცანასთან შესაბამისობის შეფასებები, რომლებიც Arena ELO-ს სინქრონიზაციის ძრავის მიერ
   ინახება `model_intelligence` მონაცემთა ბაზის ცხრილში (`src/lib/arenaEloSync.ts`).

გაერთიანების ლოგიკა განთავსებულია `src/lib/freeProviderRankings.ts`-ში.

- სრული **სარეიტინგო ცხრილი** შემდეგი სვეტებით: **ადგილი**, **პროვაიდერი**, **საუკეთესო მოდელი**,
  **ქულა**, **საშ. ქულა**, **მოდელები**, **ტიპი**.
- **კატეგორიის ფილტრის ღილაკები**: _ყველა კატეგორია_, _ნაგულისხმევი_, _კოდის წერა_, _მიმოხილვა_,
  _დოკუმენტაცია_, _გამართვა_.

თითოეული პროვაიდერის **ტიპის** ნიშნული მიუთითებს, რა სახით არის ის უფასო:

| ნიშნული  | მნიშვნელობა                                              |
| -------- | -------------------------------------------------------- |
| `NOAUTH` | ყოველთვის უფასოა, ავტორიზაციის მონაცემები საჭირო არ არის |

ქულები ნაჩვენებია ადამიანისთვის გასაგები ნიშნულებით (მაგ., _ელიტური_, _შესანიშნავი_, _ძალიან კარგი_,
_კარგი_, _საშუალო_) და არა ნედლი რიცხვებით, რადგან საბაზისო მნიშვნელობა ხარისხის ფარდობით
რეიტინგს წარმოადგენს და არა პროცენტულ მაჩვენებელს.

### API-ს საბოლოო წერტილი

გვერდის მონაცემებს უზრუნველყოფს საჯარო წაკითხვის საბოლოო წერტილი
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

მოთხოვნის პარამეტრები (მოწმდება Zod-ით):

| პარამეტრი  | ტიპი   | ნაგულისხმევი | შენიშვნები                                                                                                          |
| ---------- | ------ | ------------ | ------------------------------------------------------------------------------------------------------------------- |
| `category` | string | (არცერთი)    | ერთ-ერთი: `default`, `coding`, `review`, `documentation`, `debugging`. გამოტოვეთ გაერთიანებული რეიტინგის მისაღებად. |
| `limit`    | number | `50`         | იზღუდება `1–100` დიაპაზონით.                                                                                        |

პასუხის სტრუქტურა:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` არის Arena ELO-ს თავდაპირველი მნიშვნელობა; `score` კი ამოცანასთან შესაბამისობის ნორმალიზებული მნიშვნელობაა
(იხილეთ ქვემოთ). პროვაიდერები, რომლებსაც შეფასებული მოდელები არ აქვთ, პასუხში არ შედიან.

## როგორ მუშაობს ქულები

### წყარო: Arena AI ლიდერბორდი

Arena ELO სინქრონიზაციის ძრავა (`src/lib/arenaEloSync.ts`) იღებს ორ ლიდერბორდს — `text` და `code` — Arena AI ლიდერბორდის API-დან (`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). როდესაც ეს API არ აბრუნებს გამოყენებად დაფას, ძრავა გადადის ოფიციალურ `lmarena-ai/leaderboard-dataset`-ზე Hugging Face datasets-server-ში (`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`, `coding` → `code`); `GET /api/intelligence/sync` აჩვენებს `activeSource`, `lastError` და `lastFailedAt` ველებს. ლიდერბორდის თითოეული ჩანაწერი შეიცავს მოდელის სახელს, მწარმოებელს, ELO `score`-ს, ნდობის ინტერვალსა და ხმების რაოდენობას.

ლიდერბორდის კატეგორიები შეესაბამება OmniRoute-ის ამოცანების კატეგორიებს:

| Arena ლიდერბორდი | OmniRoute-ის ამოცანების კატეგორიები               |
| ---------------- | ------------------------------------------------- |
| `text`           | `default`, `review`, `documentation`, `debugging` |
| `code`           | `coding`                                          |

### ნორმალიზაცია (ამოცანის შესაბამისობის ქულა)

ნედლი ELO ქულები თითოეული ლიდერბორდისთვის ნორმალიზდება **ამოცანის შესაბამისობის მნიშვნელობად `[0.4, 0.98]` შუალედში**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

ქულა არასდროს აღწევს `0`-ს ან `1`-ს, რაც თავისუფალ სივრცეს ტოვებს მომხმარებლის ჩასწორებებისთვის. ეს არის ის `score` ველი, რომელსაც API პასუხში ხედავთ, და იარლიყი, რომელიც მართვის პანელზეა ნაჩვენები.

### ნდობა

თითოეული ჩანაწერი იღებს ნდობის დონეს Arena-ს ხმების რაოდენობის მიხედვით:

| ნდობა    | ხმები   |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### შენახვა და აქტუალურობა

ნორმალიზებული ჩანაწერები იწერება `model_intelligence` მონაცემთა ბაზის ცხრილში `source = "arena_elo"` მნიშვნელობით (`src/lib/db/modelIntelligence.ts`). ჩანაწერებს **ვადა ეწურებათ 7 დღის შემდეგ**, ასე რომ მომწოდებელი, რომელიც სინქრონიზაციას შეწყვეტს, საბოლოოდ ჩამოიშლება სიიდან და არ მოახდენს მოძველებული მონაცემების მიწოდებას.

სინქრონიზაცია **ნაგულისხმევად ჩართულია**:

- ის ერთხელ ეშვება სერვერის გაშვებისას, შემდეგ კი პერიოდული ტაიმერით (`src/lib/arenaEloSync.ts`, მიერთებული `src/instrumentation-node.ts`-დან).
- ის **არაა ბლოკირებადი და არასდროს ფატალური** — თუ upstream წყაროდან მონაცემების მიღება ჩავარდა, OmniRoute აგრძელებს მუშაობას და რეიტინგები უბრალოდ ბოლო წარმატებულ მონაცემებს (ან ცარიელ მდგომარეობას) აჩვენებს.

მას ორი გარემოს ცვლადი მართავს (დოკუმენტირებულია [`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)-ში):

| ცვლადი                    | ნაგულისხმევი    | დანიშნულება                                               |
| ------------------------- | --------------- | --------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`          | დააყენეთ `false`, რომ უარი თქვათ გამავალ სინქრონიზაციაზე. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24 სთ) | სინქრონიზაციის ინტერვალი წამებში.                         |

### ხელით სინქრონიზაცია / სტატუსი / გასუფთავება

ოპერატორებისთვის ავტორიზებული სამმართველო ბოლო წერტილი იძლევა ხელით მართვის საშუალებას (`src/app/api/intelligence/sync/route.ts` — საჭიროებს სამმართველო ავტორიზაციას):

```
GET    /api/intelligence/sync          # სინქრონიზაციის მიმდინარე სტატუსი (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # ხელით სინქრონიზაციის გაშვება; body: { "dryRun": true } — ჩაწერის გარეშე გადასახედად
DELETE /api/intelligence/sync          # ყველა სინქრონიზებული arena_elo ინტელექტის ჩანაწერის გასუფთავება
```

თუ რეიტინგების გვერდი ცარიელია, ხელით `POST /api/intelligence/sync` (ან უბრალოდ სერვერის გადატვირთვა) ხელახლა შეავსებს მას.

### მოდელების შესაბამება ლიდერბორდთან

რეესტრის მოდელის ID-ები და Arena-ს მოდელების სახელები ყოველთვის ზუსტად არ ემთხვევა. რეიტინგი იყენებს მოქნილ შესაბამებას (`findMatchingIntelligence` ფაილში `src/lib/freeProviderRankings.ts`):

1. ზუსტი შესაბამება ნორმალიზებული მოდელის ID-ით.
2. შესაბამება ბოლოში მდგომი ვერსიის სუფიქსის მოცილების შემდეგ (მაგ. `kimi-k2.6` → `kimi-k2`).
3. პრეფიქსით შესაბამება (ლიდერბორდის მოდელის სახელი რეესტრის ID-ის პრეფიქსია).

სინქრონიზაციის მხარეს ცნობილი მწარმოებლის პრეფიქსები (`anthropic/`, `openai/`, `google/`, …) იშლება და მცირე ფსევდონიმების რუკა კანონიკურ სახელებს OmniRoute-ის შინაგანად გამოყენებულ ვარიანტებად ახვედრებს, ასე რომ მოდელები ნებისმიერი სახელით რჩება მოძებნადი.

### როგორ ფასდება მომწოდებელი

თითოეული უფასო მომწოდებლისთვის ძრავა აფასებს მისი კატალოგის ყველა მოდელს, შემდეგ კი:

- **საუკეთესო მოდელი** = მომწოდებლის ყველაზე მაღალქულიანი მოდელი.
- **საშუალო ქულა** = ამ მომწოდებლის ყველა შეფასებული მოდელის ქულების საშუალო.
- **მოდელები** = მომწოდებლის რამდენ მოდელს ჰქონდა Arena-ს ქულა.

მომწოდებლები ჯერ **საუკეთესო მოდელის ქულით** ილაგდება, შემდეგ კი საშუალო ქულით. ეს აჯილდოებს მომწოდებელს, რომელსაც მინიმუმ ერთი ძლიერი უფასო მოდელი აქვს.

## მისი გამოყენება უფასო პროვაიდერების ასარჩევად

1. **აირჩიეთ სწორი კატეგორია.** აგენტური/კოდთან დაკავშირებული დატვირთვებისთვის გამოიყენეთ **Coding** ფილტრი, ხოლო
   ზოგადი ჩატისთვის დატოვეთ **All Categories** / **Default**. ერთი და იგივე პროვაიდერის
   რეიტინგი შეიძლება კატეგორიების მიხედვით განსხვავდებოდეს, რადგან თითოეულ რეიტინგულ ცხრილში მისი საუკეთესო მოდელი განსხვავებულია.
2. **ერთჯერადი კონფიგურაციისთვის უპირატესობა მიანიჭეთ პირველ სამეულს.** თუ მხოლოდ ერთი ან ორი უფასო
   პროვაიდერის დაკავშირება გსურთ, დაიწყეთ თქვენს კატეგორიაში უმაღლესი რეიტინგის მქონე პროვაიდერებით.
3. **შეამოწმეთ Type ნიშანი.** `NOAUTH` პროვაიდერების დაკავშირება ყველაზე სწრაფია
   (ავტორიზაციის მონაცემები არ არის საჭირო). `OAUTH` / `APIKEY` უფასო ტარიფებს სწრაფი რეგისტრაცია სჭირდება, თუმცა ისინი ხშირად
   უფრო მძლავრ მოდელებზე წვდომას უზრუნველყოფს. დაკავშირების
   ნაბიჯებისთვის იხილეთ [უფასო ტარიფების სახელმძღვანელო](../getting-started/FREE-TIERS-GUIDE.md).
4. **დააკავშირეთ რამდენიმე პროვაიდერი და არჩევანი Auto-Combo-ს მიანდეთ.** Arena ELO-ს იგივე მონაცემები, რომლებიც
   ამ გვერდს უზრუნველყოფს, ასევე მიეწოდება Auto-Combo-ს შეფასების ძრავის **ამოცანასთან შესაბამისობის ფაქტორს**
   (`open-sse/services/autoCombo/taskFitness.ts`, განსაზღვრის პრიორიტეტული მიმდევრობა:
   `user_override → arena_elo → models_dev_tier → static table`). შესაბამისად, საუკეთესო
   უფასო პროვაიდერების დაკავშირების შემდეგ, `model: "auto"`-ს გამოყენებით მარშრუტიზაცია (მაგ., `auto/coding`)
   ყოველ მოთხოვნაზე ავტომატურად მიანიჭებს უპირატესობას უფრო მაღალი ხარისხის უფასო მოდელებს. 16-ფაქტორიანი
   შეფასების სრული აღწერისთვის იხილეთ [Auto-Combo](../routing/AUTO-COMBO.md).
