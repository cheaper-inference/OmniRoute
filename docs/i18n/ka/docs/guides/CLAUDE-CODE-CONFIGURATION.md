მიუთითეთ **Claude Code** CLI-ს (`claude`) OmniRoute-ზე — ლოკალურად ან დისტანციურ VPS-ზე —
თითოეული მოდელისთვის ცალკე პროფილებით, Codex-ის კონფიგურაციის ანალოგიურად.

---

## სწრაფი დაწყება

```bash
# Claude Code-ის გაშვება ლოკალურ OmniRoute-ზე (აქტიურ კონტექსტს ავტომატურად ამოიცნობს)
omniroute launch

# დისტანციურ OmniRoute-ზე (`omniroute connect <host>`-ის შემდეგ ეს ავტომატურად ხდება)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# თითოეული მოდელისთვის პროფილების გენერირება, შემდეგ ერთ-ერთის გაშვება
omniroute setup-claude            # წერს ~/.claude/profiles/<name>/settings.json-ში
omniroute launch --profile glm52  # Claude Code, რომელიც OmniRoute-ის გავლით glm/glm-5.2-ს იყენებს
```

## როგორ უკავშირდება Claude Code კარიბჭეს

Claude Code საუბრობს**Anthropic შეტყობინებები API** და მითითებულია მორგებულ ბოლო წერტილზე გარემოს ცვლადებით (მას არ აქვს `--base-url` დროშა):

| ცვლადი                                       | მიზანი                                                                                                  |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | კარიბჭე root URL (Claude კოდი ამაგრებს `/v1/messages`).** `/v1` სუფიქსი არ არის.**                      |
| `ANTHROPIC_AUTH_TOKEN`                       | გაიგზავნა, როგორც `Authorization: Bearer …` — გამოიყენეთ თქვენი OmniRoute წვდომის ნიშანი / API გასაღები |
| `ANTHROPIC_API_KEY`                          | ალტერნატივა: იგზავნება როგორც `x-api-key`. თუ ორივე დადგა, `ANTHROPIC_AUTH_TOKEN` იმარჯვებს             |
| `ANTHROPIC_MODEL`                            | კონკრეტული მოდელის იძულება (უგულებელყოფს `/model` ამომრჩევის ნაგულისხმევს)                              |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → მშობლიური `/model` ამომრჩევი ჩამოთვლის `claude*`/`anthropic*` მოდელებს `/v1/models` დან           |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | გამომავალი ტოკენების დახურვა თითო პასუხზე (მაგ. `65536`)                                                |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | ტოკენის ბარიერი ავტომატური შეკუმშვისთვის                                                                |

> Env vars იკითხება** ერთხელ გაშვებისას** — გადატვირთეთ Claude კოდი მათი შეცვლის შემდეგ.

სერთიფიკატისთვის, რომელიც ბრუნავს ფიქსირებული სტრიქონის ნაცვლად, დააყენეთ `apiKeyHelper` `~/.claude/settings.json` ში ბრძანებაზე, რომელიც ბეჭდავს მიმდინარე სერთიფიკატს stdout-ზე. Claude კოდი ნაგულისხმევად ინახავს მის გამომავალს ხუთი წუთის განმავლობაში (`CLAUDE_CODE_API_KEY_HELPER_TTL_MS` უგულებელყოფს ამას) და აგზავნის მნიშვნელობას როგორც `Authorization: Bearer` ასევე `x-api-key` ში. სკრიპტმა უნდა დაბეჭდოს რწმუნებათა სიგელები და სხვა არაფერი — ბანერი მის გვერდით არღვევს დამხმარეს v2.1.227 +.

ასე მუშაობს Entra ID SSO : `scripts/cli/omniroute-sso.mjs token` ბეჭდავს ხანმოკლე Entra წვდომის ჟეტონს, რომელსაც OmniRoute ამოწმებს API კლავიშის ნაცვლად. იხილეთ [`docs/security/ENTRA_SSO.md`](../security/ENTRA_SSO.md).

`omniroute launch` ადგენს ამ ყველაფერს თქვენთვის: ის წყვეტს საბაზისო URL + ჟეტონს აქტიური კონტექსტიდან (ასე რომ `omniroute connect <vps>` შემდეგ `omniroute launch` უბრალოდ მუშაობს), ამოწმებს სერვერს და ახორციელებს `claude`.

## გამოყენების ატრიბუცია: სესიები და პროექტები

OmniRoute აჯგუფებს თითოეული API გასაღების მოთხოვნას** აგენტის სესიები** და ჩანაწერები, რომლებიც** პროექტი** თითოეულ სესიაზე მუშაობდა (`agent_sessions` ცხრილი), ასე რომ, გამოყენებისა და ღირებულების შესახებ შეიძლება მოხსენებული იყოს გუნდის წევრზე, პროექტზე და სესიაზე.

რა არის ჩაწერილი კლიენტის დაყენების გარეშე:

| ველი    | წყარო                                                                                                                                               |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| სესია   | `x-claude-code-session-id` სათაური (იგივე მნიშვნელობა, რაც `metadata.user_id.session_id`), სტაბილურია თითო სესიაზე                                  |
| პროექტი | `Primary working directory:` ხაზი Claude კოდი აგზავნის შეტყობინებას გარემოში; worktree საქაღალდეები `.claude/worktrees/` ქვეშ წყვეტს საცავის სახელს |
| ფილიალი | `Current branch:` git სტატუსიდან Claude კოდი აგზავნის პირველი შეტყობინებით                                                                          |
| კლიენტი | `user-agent` (`claude-cli/<version>`)                                                                                                               |

Codex (`<environment_context><cwd>`) და OpenCode (`x-opencode-session`) აღიარებულია იმავე გზით. გასაღებები** არა-ლოგი** ჩართულია შეინახოს მხოლოდ სესიის ID და სათაურის მიერ მიწოდებული პროექტის ველები; ბრძანებიდან წაკითხული არაფერი (გზა, ფილიალი) არ ინახება.

### პროექტის ცალსახად დასახელება (რეკომენდებულია)

სამუშაო დირექტორია განსხვავდება მანქანებს შორის, ამიტომ ერთი და იგივე საცავი შეიძლება გამოჩნდეს სხვადასხვა ბილიკზე. ამის ნაცვლად, პირდაპირ გაგზავნეთ პროექტი: Claude Code ამატებს `ANTHROPIC_CUSTOM_HEADERS` ში ჩამოთვლილ სათაურებს ყველა მოდელის მოთხოვნას და OmniRoute კითხულობს მათგან ორს:

| სათაური                    | ღირებულება                                                               |
| -------------------------- | ------------------------------------------------------------------------ |
| `x-omniroute-project`      | პროექტის სახელი, მაგ. `omniroute`                                        |
| `x-omniroute-project-repo` | ნორმალიზებული დისტანციური, მაგ. `github.com/cheaper-inference/OmniRoute` |

ორივე იკითხება მხოლოდ მიკუთვნებისთვის; ისინი არასოდეს გადაეგზავნება ზედა დინების პროვაიდერს.

`ANTHROPIC_CUSTOM_HEADERS` იკითხება ერთხელ გაშვებისას და პარამეტრების ფაილები ინახავს ლიტერატურულ მნიშვნელობებს, ამიტომ გამოთვალეთ იგი Claude Code-ის გაშვებისას. დაამატეთ ეს `~/.zshrc` ან `~/.bashrc` და განაგრძეთ `claude` დაწყება პროექტის საქაღალდედან:

```bash
claude() {
  local common name repo
  if common=$(git rev-parse --path-format=absolute --git-common-dir 2>/dev/null); then
    case $common in
      */.git) name=$(basename "$(dirname "$common")") ;;  # repository name, also in worktrees
      *) name=$(basename "$common" .git) ;;                # bare repository (/srv/foo.git)
    esac
    repo=$(git remote get-url origin 2>/dev/null \
      | sed -E 's#^[a-zA-Z][a-zA-Z0-9+.-]*://([^@/]*@)?##; s#^[^@/]+@([^:]+):#\1/#; s|[?#].*$||; s#\.git$##')
  else
    name=$(basename "$PWD")                                # not a git repository: folder name
  fi
  ANTHROPIC_CUSTOM_HEADERS="${ANTHROPIC_CUSTOM_HEADERS:+${ANTHROPIC_CUSTOM_HEADERS}
}x-omniroute-project: ${name}${repo:+
x-omniroute-project-repo: ${repo}}" command claude "$@"
}
```

`sed` გამოხატულება აშორებს ნებისმიერ სერთიფიკატს, შეკითხვის სტრიქონს და ფრაგმენტს, რომელიც ჩაშენებულია დისტანციურ URL ში, ხოლო სათაურები უკვე `ANTHROPIC_CUSTOM_HEADERS` ში ინახება. IDE გაფართოებები უშვებს Claude Code-ს თქვენი გარსის გარეშე, ასე რომ მათი სესიები დაუბრუნდება სამუშაო დირექტორიას.

## Discovery alias-ები — არა-Claude მოდელების გამოჩენა `/model` არჩევნეში

Claude Code-ის gateway მოდელების აღმოჩენა მხოლოდ იმ id-ებს აჩვენებს, რომლებიც იწყება `claude`-ით
ან `anthropic`-ით, ამიტომ `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`-ით ჩართული ნატიური
`/model` არჩევენი ჩვეულებრივ **მხოლოდ** OmniRoute-ის Claude/Anthropic მოდელებს აჩვენებს —
`kimi/kimi-k2.6` ან `glm/glm-5.2` არასდროს ჩანს, მიუხედავად იმისა, რომ მარშრუტიზაცია უპრობლემოდ მუშაობს.

OmniRoute-ს შეუძლია ნებისმიერი ჩართული მოდელის (და კომბოს) სარკისებრად ასახვა `claude/…` id-ით,
რომ ის გავიდეს ამ ფილტრს და გამოჩნდეს არჩევენში:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

როცა ამათგან რომელიმეს აირჩევთ Claude Code-ში, OmniRoute მარშრუტიზაციამდე `claude/` შემოსასხმელს
ხსნის და ნამდვილ id-ს აბრუნებს — ნამდვილი `claude/<real-claude-model>` id
(რეალური Claude OAuth პროვაიდერი) ყოველთვის უცვლელი რჩება.

ნაგულისხმევად მხოლოდ საბაზისო id-ები ირეკლება. ჩართული opt-in
`CATALOG_MIRROR_REFINEMENTS_ENABLED` ფლაგით, კატალოგში უკვე ჩამოთვლილი
reasoning-effort ვარიანტები (მაგ. `codex/gpt-6-sol-high`) ირეკლება ისე, როგორც ნებისმიერი სხვა
id, ასე რომ Claude Code-ს შეუძლია effort-ის კონკრეტული დონე აირჩიოს, ხოლო ჩაშენებული `auto/*` id-ები,
რომელთა მატერიალიზებაც მოთხოვნის გზა ვერ ახერხებს, არ ირეკლება. ჩამოთვლილება თავად effort ვარიანტების
მაინც `OMNIROUTE_DISABLE_THINKING_LEVEL_VARIANTS`-ით რეგულირდება — სარკე არასდროს ამატებს ისეთ ვარიანტს,
რომელიც საბაზისო კატალოგში არ არის.

**ეს ნაგულისხმევად გამორთულია** და მართულია სამდონიანი კარიბჭით (ყველაზე კონკრეტული იგებს),
ასე რომ უბრალო OmniRoute არასდროს აორმაგებს თავის კატალოგს იმ კლიენტებისთვის, რომლებიც
Claude Code-ს არ იყენებენ:

| დონე       | სად                                                                                     |
| ---------- | --------------------------------------------------------------------------------------- |
| მოდელი     | პროვაიდერის დეტალების გვერდი → თითოეული მოდელის "Expose in Claude Code" გადამრთველი     |
| პროვაიდერი | პროვაიდერის დეტალების გვერდი → პროვაიდერის დონის გადამრთველი (მოიცავს მის ყველა მოდელს) |
| გლობალური  | Settings → Feature Flags → `EXPOSE_CC_DISCOVERY_ALIASES` (ნაგულისხმევად გამორთულია)     |

`EXPOSE_CC_DISCOVERY_ALIASES` გარემოს ცვლადი აიძულებს გლობალური დონის ჩართვას
და უპირატესობას ანიჭებს dashboard-ის გადაწერას (Feature Flags ეკრანი აჩვენებს
შენიშვნას "active via environment variable", როცა ეს ხდება). თითოეული პროვაიდერის და
თითოეული მოდელის გადამრთველები ამის შემდეგ აზუსტებს — მაგ. გლობალური გამორთული + Kimi პროვაიდერი
ჩართული მხოლოდ Kimi-ს მოდელებს ამჟღავნებს.

> ⚠️ **ფანჯრის შეუსაბამობა არა-Claude მოდელებში.** Claude Code ნებისმიერი მისთვის
> უცნობი id-ისთვის 200K კონტექსტის ფანჯარას ვარაუდობს (ის ვერ კითხულობს ნამდვილ ფანჯარას
> `/v1/models`-დან). უფრო დიდი ფანჯრის მქონე მოდელისთვის (მაგ. Kimi K2-ის 256K), დააყენეთ
> `CLAUDE_CODE_AUTO_COMPACT_WINDOW` მნიშვნელობა, რომელიც მოდელის ნამდვილ ფანჯარაზე დაბალია,
> რათა ავტომატური კომპაქტიზაცია ნაადრევად არ გაეშვას. ზემოთ მოყვანილი გენერირებული პროფილები
> უკვე აკეთებენ ამას თითოეული მოდელისთვის.

## საწყისი კონფიგურაციის ბლოკი მართვის პანელზე

Claude-ის ხელსაწყოს ბარათი (**მართვის პანელი → CLI Code**) ამ ინსტანციისთვის ზუსტ `settings.json` ფრაგმენტს აჩვენებს
აღმოჩენის ფსევდონიმის საინფორმაციო ღილაკის გვერდით, კოპირების ღილაკთან ერთად:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<თქვენი OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<თქვენი OmniRoute API გასაღები>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

საბაზისო URL არის ბარათის მიერ განსაზღვრული მისამართი (მათ შორის თქვენ მიერ შეყვანილი მორგებული მნიშვნელობა), რომელიც უკვე
ნორმალიზებულია — `/v1` სუფიქსისა და ბოლოში დახრილი ხაზის გარეშე. **გასაღები არასოდეს აისახება**: ბლოკი მის ნაცვლად
შემავსებელ ტექსტს შეიცავს, ამიტომ ეკრანის ანაბეჭდიდან ან ჩასმული ფრაგმენტიდან მისი გაჟონვა შეუძლებელია. ჩაანაცვლეთ ის თქვენი გასაღებით.

იმავე `env` ბლოკში დაამატეთ `CLAUDE_CODE_AUTO_COMPACT_WINDOW` ნებისმიერი მოდელისთვის, რომლის რეალური
კონტექსტის ფანჯარა 200K არ არის — Claude Code ყველა მისთვის უცნობი id-ისთვის 200K-ს ვარაუდობს, ამიტომ
წინააღმდეგ შემთხვევაში ავტომატური კომპაქტაცია არასწორ მომენტში ამოქმედდება (იხილეთ გაფრთხილება წინა სექციაში).
ფრაგმენტის შემქმნელი ამ მნიშვნელობასაც იღებს, ამიტომ გამომძახებელს, რომელმაც სამიზნე მოდელის ფანჯრის ზომა იცის,
შეუძლია ის პირდაპირ გამოსცეს.

წყარო: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (სუფთა
შემქმნელი, მოდულური ტესტებით დაფარული), რომელსაც `ClaudeGatewayOnboardingBlock` ასახავს.

### ერთი ანგარიშის მიბმა (არასავალდებულო)

Claude Code-ის ყველა მოთხოვნის ერთი კონკრეტული პროვაიდერის ანგარიშის გავლით გასაგზავნად იმავე `env` ბლოკში
`ANTHROPIC_CUSTOM_HEADERS`-ის მეშვეობით დაამატეთ `x-omniroute-connection` სათაური:

```jsonc
"ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>"
```

დააკოპირეთ id პროვაიდერის გვერდზე, კავშირის მწკრივში მდებარე `xxxxxxxx…` ნიშნულიდან. მიბმა
ვრცელდება მხოლოდ ერთი მოდელის id-ებზე (`provider/model`) და არა კომბინაციებზე. ზუსტი
სარეზერვო ქცევის სანახავად იხილეთ [ანგარიშის მიბმა თითოეული მოთხოვნისთვის](../reference/API_REFERENCE.md#account-pinning-per-request).

## პროფილები (`CLAUDE_CONFIG_DIR`)

Claude Code-ს **პროფილების ჩაშენებული ფაილები არ გააჩნია** (Codex-ის `~/.codex/<name>.config.toml`-ისგან განსხვავებით).
იდიომატური მექანიზმია `CLAUDE_CONFIG_DIR` — თითოეული პროფილისთვის ცალკე კონფიგურაციის
დირექტორია, რომელთაგან თითოეულს საკუთარი `settings.json`, ავტორიზაციის მონაცემები, ისტორია და კეში აქვს.

`omniroute setup-claude` იღებს აქტუალურ `/v1/models` კატალოგს და თითოეული
მოდელისთვის ქმნის პროფილს მისამართზე `~/.claude/profiles/<name>/settings.json`, იმავე
**სახელების გამოყენებით, რომლებსაც `setup-codex` იყენებს** (`glm52`, `kimi-k27`, `deepseek-pro`, …):

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **ავტორიზაციის ტოკენი პროფილში არასოდეს იწერება.** გაუშვით
> `omniroute launch --profile <name>` (ის აქტიური კონტექსტიდან `ANTHROPIC_AUTH_TOKEN`-ს
> გადასცემს), ან თავად გაიტანეთ `ANTHROPIC_AUTH_TOKEN` გარემოში და გაუშვით
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`.

**ავტომატური სინქრონიზაცია მოდელების აღმოჩენის შემდეგ (სურვილისამებრ).** OmniRoute-ს შეუძლია იმავე
`~/.claude/profiles/<name>/settings.json` ფაილების ავტომატურად ხელახლა გენერირება, როდესაც პროვაიდერის მოდელების
სინქრონიზაცია აქტუალურ კატალოგს შეცვლის — შესაბამისად, ახალი ან სახელშეცვლილი მოდელები პროფილებს ბრძანების
ხელახლა გაშვების გარეშე მიიღებენ. ის **ნაგულისხმევად გამორთულია**: ჩართეთ **CLI Code-ის მართვის პანელიდან** ("CLI profile
auto-sync" → Claude Code), ან დააყენეთ `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` (ის ასევე ითვალისწინებს
`CLI_ALLOW_CONFIG_WRITES`-ს, რომელიც ნაგულისხმევად ჩართულია). ჩართვისას ის მხოლოდ პროფილის ფაილებს წერს; ის არასოდეს
ცვლის თქვენს აქტიურ/ნაგულისხმევ Claude-ის კონფიგურაციას, ავტორიზაციას ან `~/.claude/settings.json`-ს.

### პროფილების გენერირება + გამოყენება

```bash
# ლოკალური OmniRoute
omniroute setup-claude

# დისტანციური VPS (VPS-ის URL-ს თითოეულ პროფილში წერს)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# მხოლოდ ზოგიერთი პროვაიდერი
omniroute setup-claude --only glm,kimi

# ასევე შექმენით პროფილები ლოკალური CLI-ის პროვაიდერებისთვის (zcode, auggie, devin-cli-agentic,
# codex-app-server), რომლებიც ამ ჰოსტზე აღმოჩენილი არ არის (ლოკალური სამიზნისთვის ნაგულისხმევად გამოტოვებულია)
omniroute setup-claude --include-local

# წინასწარი ნახვა ჩაწერის გარეშე
omniroute setup-claude --dry-run

# პროფილის გაშვება
omniroute launch --profile kimi-k27
```

## პრობლემების მოგვარება

**Claude Code უგულებელყოფს კარიბჭეს** — დაადასტურეთ `ANTHROPIC_BASE_URL` აქვს** არა `/v1`** და გადატვირთეთ `claude` (env იკითხება ერთხელ გაშვებისას). `omniroute launch` ამუშავებს ამას თქვენთვის.

**`/model` ამომრჩევი ცარიელია / აკლია კარიბჭის მოდელები** — სჭირდება Claude Code v2.1.219 + და `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`. ამომრჩეველში გამოჩნდება მხოლოდ `claude*` / `anthropic*` მოდელი IDs ; აიძულეთ ნებისმიერი სხვა მოდელი `ANTHROPIC_MODEL=<id>` ით (ეს არის რასაც პროფილები აკეთებენ).

**`400 Ambiguous model 'claude-…'`** — Claude კოდი ყოველთვის აგზავნის** უპრეფიქსი** მოდელი IDs (მაგ. `claude-opus-4-8`), ასე რომ, როდესაც Claude Code (`cc/…`) და Claude (`claude/…`) პროვაიდერები დაკავშირებულია, შიშველი id ემთხვევა ორ მარშრუტს და OmniRoute უარს ამბობს გამოცნობაზე. გაასწორეთ ეს ნებისმიერ შემთხვევაში: ჩაამაგრეთ პრეფიქსის ID `ANTHROPIC_MODEL=cc/claude-opus-4-8` ით, ან ჩართეთ** უპირატესობა მიანიჭეთ Claude კოდს უპრეფიქსის Claude მოდელებისთვის** — გადართვა Claude პროვაიდერის გვერდზე, ან `OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (ნაგულისხმევი გამორთულია; იხილეთ [გარემო](../reference/ENVIRONMENT.md) ) — რომელიც შიშველი `claude-*` IDs ნაცვლად Claude კოდზე გადადის. პროვაიდერის აშკარა პრეფიქსები ყოველთვის იმარჯვებენ.

**"ავტომატური რეჟიმი ... ეს სესია არ არის დაშვებული" (კლასიფიკატორის მოთხოვნები დარიცხულია)** — ავტომატურ რეჟიმში Claude კოდი სთხოვს სერვერს გადახედოს მოქმედებებს საკუთარი მოდელის მოთხოვნების შიგნით ( [Anthropic docs](https://code.claude.com/docs/en/auto-mode-classifier-billing) ). ამას სჭირდება `anthropic-beta` მნიშვნელობა `dangerous-tool-use-2026-09-03` და `safeguards` სხეულის ველი, რათა მიაღწიოს Anthropic წყვილად, და `safeguard_results` პლუს ზემოთ ნაკადის ინსტრუმენტი - გამოიყენეთ IDs უცვლელად დასაბრუნებლად. OmniRoute აკეთებს ამას, როდესაც მოთხოვნა გადაეცემა მშობლიურ `claude` პროვაიდერს ან `anthropic-compatible-*` კვანძს, სტრიმინგში თუ არა (რეგრესიის დაცვა: `tests/integration/claude-auto-mode-classifier-e2e.test.ts`). სხვა სამიზნეებს არ შეუძლიათ მიმოხილვის დაბრუნება, ამიტომ Claude კოდი უბრუნდება თავის კლასიფიკატორის მოთხოვნას და აჩვენებს შეტყობინებას:

- მოდელი არა-ანთროპიულ პროვაიდერზე, ან კომბინირებული, რომელიც ჯდება ერთზე;
- Claude-Code-თან თავსებადი სარელეო კვანძი (`anthropic-compatible-cc-*`), რომელიც აღადგენს მოთხოვნის სხეულს და არ ატარებს `safeguards`;
- ძველი OmniRoute, რომელიც უსწრებს დაშვებულ ბეტა ვერსიას, ან Claude კოდის ვერსია ქვემოთ, რომელიც ჩამოთვლილია Anthropic სესიებისთვის.

გაუშვით `/status` Claude კოდში: the** ავტომატური რეჟიმის სერვერი** რიგი კითხულობს `Enabled` სანამ სერვერის მიმოხილვა აქტიურია. იქნება თუ არა ეს მოთხოვნები დარიცხული, წყვეტს Anthropic ს და არა OmniRoute.

**ავტორიზაციის შეცდომები** — პროფილს არ აქვს ნიშანი. გამოიყენეთ `omniroute launch --profile` (შეაქვს მას) ან ექსპორტზე `ANTHROPIC_AUTH_TOKEN`.

**პროფილები არ იზოლირებულია** — თითოეული პროფილი არის განსხვავებული `CLAUDE_CONFIG_DIR`; გადაამოწმეთ `echo $CLAUDE_CONFIG_DIR` სესიის წერტილებში `~/.claude/profiles/<name>` ზე.
