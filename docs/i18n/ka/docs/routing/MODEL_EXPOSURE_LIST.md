> ჩართვა, გამორთვა ნაგულისხმევად (`modelVisibilityAllowlist`/`modelVisibilityDenylist` ორივე ცარიელი ტოვებს `/v1/models` კატალოგს AND ყველა `auto/*` კანდიდატის აუზის ბაიტი იდენტურია). `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`) და-ძმა ოპერატორებისთვის, რომლებსაც სურთ კურირებული მოდელების სია იმ მიზეზების გამო, რომლებსაც საერთო არაფერი აქვთ ღირებულებასთან.

## რატომ არსებობს ეს

`hidePaidModels` პასუხობს "ეს მოდელი უფასოა?" და `hideAutoCombos` პასუხობს "საერთოდ უნდა იყოს თუ არა `auto/*` ვირტუალური იდენტიფიკაციის რეკლამირება?" — არც ოპერატორს აძლევს საშუალებას მოახდინოს მოდელების თვითნებური ქვეჯგუფი (მაგ. წარმოადგინოს ზუსტად ის მოდელები, რომლებიც მოცემულმა Claude Code/ OpenCode კლიენტმა უნდა ნახოს, ფასისგან დამოუკიდებლად). #11481 ამატებს, როგორც ორ დამოუკიდებელ, სტრიქონის მასივის პარამეტრებს.

## პარამეტრები

| გასაღები                   | ტიპი       | ნაგულისხმევი | მნიშვნელობა                                                                                  |
| -------------------------- | ---------- | ------------ | -------------------------------------------------------------------------------------------- |
| `modelVisibilityDenylist`  | `string[]` | `[]`         | კანდიდატის შესაბამისი ჩანაწერები მალავს მას catalog/candidate ფონდიდან.                      |
| `modelVisibilityAllowlist` | `string[]` | `[]`         | როდესაც არ არის ცარიელი, ONLY ჩანაწერები, რომლებიც შეესაბამება კანდიდატს, რჩება გამოვლენილი. |

ორივე იღებს 500-მდე ჩანაწერს 200-მდე სიმბოლოთი (Zod-დამოწმებულია `src/shared/validation/settingsSchemas.ts` ში). ჩანაწერი არის ან:

- ზუსტი კატალოგის id — `"gpt-4o"` (შიშველი მოდელის id) ან `"openai/gpt-4o"` (პროვაიდერის პრეფიქსი), ან
- გლობალური ნიმუში `*`/`?` — გამოყენებით, მაგ. `"openai/gpt-4*"` ან `"anthropic/*"` — მოგვარებულია იმავე გაზიარებული `globToRegex()` შესატყვისის (`src/shared/utils/globPattern.ts`) მეშვეობით, რომელიც უკვე გამოიყენება `ModelRoutingSection` ის თითო მოდელის კომბინირებული რუკების და `freeModels.ts::matchesOnlyPaidModels` მიერ.

უპირატესობა: ჯერ მოწმდება უარყოფილი სია (უარყოფილი ჩანაწერი ყოველთვის იმალება, მაშინაც კი, თუ ის ასევე ემთხვევა დაშვებულ სიას); როდესაც ნებადართული სია ცარიელია, მხოლოდ მასში შესატყვისი ჩანაწერები რჩება.

## ორი ჩახშობის წერტილი და არა ერთი

გაკვეთილი #6512-დან ( `hidePaidModels` -only კატალოგის ფილტრი მაინც აძლევს `auto/*` მარშრუტს ფასიან მოდელზე, რადგან კომბინირებული კანდიდატის ფონდი დამოუკიდებლად აშენდა) აქაც იდენტურად მოქმედებს. შესატყვისი პრედიკატი `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`) ეწოდება BOTH დან:

- `src/app/api/v1/models/catalog.ts` — `/v1/models` ჩამონათვალი თავად, იმავე 5 თითო წყაროზე chokepoint `shouldHidePaid()` უკვე კარიბჭეა (სტატიკური `PROVIDER_MODELS`, სინქრონიზებული პროვაიდერის რიგები, მორგებული რიგები, ფსევდონიმით მხარდაჭერილი რიგები, მართული სარეზერვო რიგები).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — გამოიძახა `virtualFactory.ts::buildPreparedPool` დან, ეკვივალენტური `filterPaidOnlyCandidates()` გამოძახებისთანავე, ასე რომ, უარყოფილი მოდელი ვერასოდეს შეირჩევა `auto/*` კანდიდატთა ფონდში.

## რა არის NOT გაფილტრული

ასახავს `hideAutoCombos` ს არსებულ ქცევას: გაგზავნილი მოდელის ID** ცალსახად** (არა `auto/*` მეშვეობით და არ არის აღმოჩენილი კატალოგის ჩამონათვალის მეშვეობით) არასოდეს იბლოკება გაგზავნისას — მხოლოდ advertisement/candidate-pool წევრობა იფილტრება. ეს არის დამოუკიდებელი `hidePaidModels` სგან; ოპერატორს შეიძლება სურდეს კურირებული ნაკრები იმ მიზეზების გამო, რომლებსაც საერთო არაფერი აქვთ ღირებულებასთან, ამიტომ ორივე პარამეტრი შედგენილია როგორც დამოუკიდებელი AND-ed ფილტრები, ისევე როგორც არსებული მრავალდროშიანი კომპოზიცია `catalog.ts` ში.

პარამეტრების ექსპორტი (`GET /api/settings/export-json`) მოიცავს ორივე მასივს სიტყვასიტყვით, ისევე როგორც სხვა პარამეტრების ველი — `hidePaidModels` ის კომბინირებული საფეხურის ექსპორტის ფილტრისგან განსხვავებით, აქ არ არსებობს ხელახალი ჰიდრატაციის რისკი: ექსპორტირებულ კომბინირებულ საფეხურში ჩასმული უარყოფილი ID არის ოპერატორის მარშრუტიზაციის აშკარა არჩევანი და არა ის, რაც ექსპორტის საზღვრებს სჭირდება ამოღება.

## მხოლოდ კომბინირებული ჩამონათვალი (`exposeCombosOnly`)

ცალკე ლოგიკური, ასევე ჩართვა და `false` ნაგულისხმევად, განლაგებისთვის, სადაც კომბინაციები წარმოადგენს საჯარო მოდელის ზედაპირს და პროვაიდერებს მხოლოდ უკანა ნაწილებს. როდესაც ის არის `true`, საჯარო სია (`GET /v1/models`, `GET /v1` და `getUnifiedModelsResponse()` ზე აგებული სხვა `/v1` აღმოჩენის მარშრუტები) ინახავს მხოლოდ სტრიქონებს `owned_by: "combo"` ით: მომხმარებლის კომბინაციები პლუს ჩაშენებული `auto/*` კომბინაციები (თუ `hideAutoCombos` არ მალავს მათ). ის იყენებს იმავე მწკრივის ტესტს, როგორც თითო კლავიშზე `catalogScope: "combos"`, და გასაღების საკუთარი allow/deny/scope ფილტრები კვლავ ვრცელდება ზემოთ.

ჩართეთ იგი** პარამეტრები → მარშრუტიზაცია → მოდელები API ჩამონათვალი** , ან `PATCH /api/settings {"exposeCombosOnly": true}` ით .

ზემოთ მოყვანილი სიების მსგავსად, ის მხოლოდ ცვლის რეკლამას:

- აშკარა `provider/model` id კვლავ აგზავნის და `GET /v1/models/{id}` მაინც წყვეტს მას;
- დაფის კატალოგი (`GET /api/models/catalog`, რომელსაც იყენებენ მოდელების ამომრჩევლები) არ არის შევიწროებული;
- ის არ არის ასახული `auto/*` კანდიდატის აუზებში, ამიტომ `auto/*` კომბინაციები ინარჩუნებენ სრულ აუზს.
