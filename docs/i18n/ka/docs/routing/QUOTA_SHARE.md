## მიმოხილვა

კვოტის გაზიარების ძრავა პროვაიდერის დროზე დაფუძნებულ კვოტას (მაგ., Codex-ის
5-საათიანი ფანჯარა, Kimi-ის 1500 მოთხოვნა/სთ) სამართლიანად ანაწილებს რამდენიმე API გასაღებს შორის, რომლებიც
ერთსა და იმავე კავშირს იზიარებენ.

**პრობლემა, რომელსაც ის წყვეტს:** OmniRoute მრავალი API გასაღების მოთხოვნებს ერთი და იმავე ზედა დონის
პროვაიდერის ანგარიშისკენ ამისამართებს. გაზიარების ლოგიკის გარეშე, A გასაღებიდან წამოსულმა მოთხოვნების ნაკადმა შეიძლება
ამოწუროს პროვაიდერის საათობრივი კვოტა და B და C გასაღებები დაბლოკილი დატოვოს ფანჯრის განულებამდე.
ძრავა ამას შემდეგი გზებით უშლის ხელს:

1. თითოეული გასაღების მოძრავი მოხმარების აღრიცხვა თითოეული განზომილების მიხედვით (%, მოთხოვნები, ტოკენები, $).
2. სამუშაოს შემნახველი სამართლიანი განაწილების ალგორითმის გამოყენება: გასაღებს შეუძლია ისესხოს უმოქმედო
   წილებიდან, სანამ გლობალური პული გაჯერებული არ არის.
3. შედეგის აღსრულება კრიტიკულ გზაზე (`chatCore.ts`), სანამ მოთხოვნა
   ზედა დონის შემსრულებლამდე მიაღწევს.

## ალგორითმი: სამუშაოს სამართლიანი გაზიარება

განხორციელდა `src/lib/quota/fairShare.ts` ში.

### რეჟიმები

| მდგომარეობა                                | რეჟიმი      | ქცევა                                                               |
| ------------------------------------------ | ----------- | ------------------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **გულუხვი** | გასაღები შეიძლება ისესხოს გლობალურ ლიმიტამდე მინუს მოხმარებული ჯამი |
| `globalUsedPercent >= saturationThreshold` | **მკაცრი**  | მკაცრად აღასრულეთ ინდივიდუალური სამართლიანი წილი                    |

ნაგულისხმევი `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`).

ეს ორი რეჟიმი აღწერს აუზს ნაგულისხმევი სესხის რეჟიმში, `saturation`. აუზი `consent` რეჟიმში ყოველთვის იყენებს მკაცრ წესებს, როგორიც არ უნდა იყოს გაჯერება. იხილეთ [თანხმობა დაკრედიტება (თითო ჯგუფში მონაწილეობის მიღება)](#consented-lending-per-pool-opt-in).

### განზომილების გადაწყვეტილება

აუზში თითოეული აქტიური განზომილებისთვის, ძრავა ითვლის:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = current rolling value for this key (from QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

`percent` განზომილებისთვის, `consumed` მოდის ატრიბუციის წიგნიდან (იხილეთ [პროცენტული ზომები: თითო გასაღების მიკუთვნება](#percent-dimensions-per-key-attribution) ).

შემდეგ:

- **`policy = hard`** : თუ `consumed > fairShareAllowed` და რეჟიმი მკაცრია →** ბლოკი** .
- **`policy = soft`** : თუ `consumed > fairShareAllowed` და რეჟიმი მკაცრია →** დაჯარიმება** (კომბინირებული პრიორიტეტები; არასოდეს მყარი ბლოკი).
- **`policy = burst`** : დაშვება, სანამ გლობალური სათავე სივრცე არსებობს, მიუხედავად სამართლიანი წილისა.

### Cap absoluto

`capValue` + `capUnit` განაწილებაზე არის მყარი ჭერი, დამოუკიდებელი რეჟიმისა და პოლიტიკისგან. ნებისმიერი განზომილება სადაც `consumed >= capValue` ყოველთვის** ბლოკები** თხოვნა. `percent` თავსახურისთვის `consumed` არის მხოლოდ ის ნაწილი, რომელიც მიეკუთვნება გასაღებს.

### მრავალგანზომილებიანი შემოწმება

მოთხოვნა დაბლოკილია თუ** ნებისმიერი** განზომილება აუზში დაბლოკავს მას. ზომები დამოუკიდებელია — და 5 სთ% ამოწურვა არ მოქმედებს ყოველკვირეულ% განზომილებაზე.

### სესხება

კეთილშობილურ რეჟიმში, გასაღები, რომლის განაწილებაც არასაკმარისად არის მოხმარებული, შეუძლია გამოიყენოს ჭარბი სხვა გასაღების გაუნაწილებელი აქციებიდან. ფორმულა არის:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

სადაც `consumedByOtherKeys = consumedTotal - consumedByThisKey`. ტეტო გლობალური (აუზი `limit` ამ განზომილებისთვის) ყოველთვის მყარი ჭერია.

### თანხმობითი სესხის გაცემა (თითო ჯგუფში მონაწილეობის მიღება)

თითოეულ აუზს აქვს სესხის აღების რეჟიმი. `saturation` არის ნაგულისხმევი და იცავს ზემოთ მოცემულ წესებს. `consent` რეჟიმში, `hard` კლავიში გადის თავის წილს მხოლოდ იმ სიმძლავრის ფარგლებში, რომლის გაცემაზე შეთანხმდნენ სხვა გასაღებები. ადმინისტრატორი ადგენს თითოეული აუზის რეჟიმს. თითოეული გასაღების მფლობელი ადგენს საკუთარ თანხმობას [სესხის თანხმობის](#lending-consent) მეშვეობით.

თანხმობა არის პროცენტი 0-დან 100-მდე და არჩევითი ვადა ეპოქის მილიწამებში. გასაღები აძლევს ამ პროცენტს მისი უმოქმედო წილის, სანამ ბოლო ვადა არის მომავალში.

ერთი განზომილებისთვის, `L` არის ეფექტური ლიმიტი: გეგმის ლიმიტი აჭარბებს აუზში არსებულ ანგარიშებს. კარიბჭე ითვლის მოთხოვნის გასაღებისთვის:

```
share_k         = w_k / 100 × L
idle_k          = max(0, share_k − consumed_k)
lent            = Σ over the other keys of lend_k / 100 × idle_k
taken           = Σ over the other keys of max(0, consumed_k − share_k)
borrowAvailable = max(0, lent − taken)
```

`w_k` არის გასაღების წონა, ან `100 / n` ყველა გასაღებისთვის, როდესაც წონა არ არის 0-ზე მეტი. `lend_k` არის გასაღების აქტიური პროცენტი და 0, როდესაც მისი ბოლო ვადა ამოიწურება. გასაღების მოთხოვნის საკუთარი თანხმობა არასოდეს ითვლება. `hard` კლავიშზე უარის თქმა ხდება მას შემდეგ, რაც მისი მოხმარება მიაღწევს თავის წილს პლუს `borrowAvailable`.

სიმძლავრე, რომელსაც არ აქვს განაწილება (100 გამოკლებული წონების ჯამი) არ არის სესხის აღება. არცერთი გასაღები არ დათანხმდა მის სესხებას.

**მაგალითი.** `L` არის 1000.

| გასაღები | წონა | გააზიარეთ | მოხმარებული | სესხებს |
| -------- | ---- | --------- | ----------- | ------- |
| ა        | 50   | 500       | 530         | 0%      |
| ბ        | 30   | 300       | 100         | 50%     |
| C        | 0    | 0         | 60          | 0%      |

- B სესხს გასცემს თავისი უმოქმედო 200-ის 50%-ს, რაც არის 100. C-მ უკვე აიღო 60 თავის წილზე მეტი. შეიძლება ისესხოს 40.
- A-ს ემსახურება 530-ზე და უარს აცხადებენ, როცა მისი მოხმარება 540-ს მიაღწევს.
- სანამ C გამოიყენებდა რაიმეს, A-ით ან მის წილით, C-ს შეეძლო სესხება 100.
- სანამ C რაიმეს გამოიყენებდა, A 530-ზე, C-ს შეეძლო 70-ის სესხება.

**ნულოვანი წონა.** 0 წონით გასაღებს აქვს 0 წილი. მას ემსახურება მხოლოდ მაშინ, როდესაც მისი მოხმარება ნაკლებია, ვიდრე სხვები გასესხებენ. როცა არავინ გასესხებს, მას პირველივე მოთხოვნით უარს ეუბნებიან.

**ვადები.** არცერთ ფონურ დავალებას არ ეწურება თანხმობა. თითოეული მოთხოვნა ადარებს ვადას თავის დროს და გავიდა ამ დროის ტოლი ვადა. შენახული ვადა, რომელიც არ არის სასრული რიცხვი, ან გასულია ყველაზე დიდი თარიღი, რომელსაც `Date` შეუძლია, ჩაითვლება წარსულად.

**`soft` და `burst`.** დაკრედიტება მათ არ ზღუდავს. `soft` კლავიშის პრიორიტეტიზაცია ხდება მისი წილის გასვლის შემდეგ. `burst` გასაღები გადის, სანამ აუზს აქვს ოთახი. აუზის ჭერი კვლავ უარს ამბობს ყველა გასაღებზე, როგორც კი აუზის ჯამი მიაღწევს ლიმიტს.

**ღირებულება მოთხოვნის გზაზე.** `saturation` აუზი იმაზე მეტს არაფერს კითხულობს, ვიდრე ადრე. `consent` აუზში, თვლადი განზომილება კითხულობს სხვა კლავიშებს მხოლოდ `hard` კლავიშისთვის მის წილზე ან მის ზემოთ, მაშინ როცა სხვა კლავიატურა სარგებლობს. შემდეგ ის პარალელურად კითხულობს მეორე კლავიშს. წარუმატებელი წაკითხვა ითვლება ამ გასაღებისთვის 0-ის მოხმარებად. `percent` განზომილება არ ამატებს წაკითხვას, რადგან ატრიბუციის წიგნი შეიცავს ყველა ღილაკს.

**აუზის რედაქტირება.** რედაქტირება ინარჩუნებს დარჩენილ გასაღებებზე თანხმობას. ეს ეხება განაწილების რედაქტირებას, ჯგუფის მასშტაბით ჩანაცვლებას და `ensure` ზარებს. ამოღებული გასაღები კარგავს თანხმობას, ხოლო დამატებული გასაღები იწყება 0-დან. ადმინისტრატორის მარშრუტები აბრუნებენ თითოეული გასაღების თანხმობას და არასოდეს წერენ მას. აუზის უკან `saturation` ზე გადართვა ინახავს ყველა შენახულ თანხმობას, რომელსაც არანაირი ეფექტი არ აქვს ამ რეჟიმში. აუზის კვლავ `consent` ზე გადართვა ხელახლა ააქტიურებს შენახულ თანხმობას, რომელთა ვადა არ არის გასული. გასაღების მფლობელს შეუძლია შენახული თანხმობის გასუფთავება ნებისმიერ რეჟიმში.

**განახლება.** თუ სვეტები `lending_percent` და `lending_until` უკვე არსებობს, მიგრაცია ამატებს მხოლოდ `borrow_mode` და შენახული პროცენტები რჩება ისე, როგორც არის. ყველა აუზი იწყება `saturation` რეჟიმში. ჩართეთ `consent` თითო აუზში აუზის ოსტატში. შენახული მნიშვნელობებიდან არაფერია დასკვნა.

**შეზღუდვები.**

- კრედიტორს შეუძლია იპოვოს აუზი თავის ჭერზე, სანამ ის საკუთარ წილს გამოიყენებს. ტევადობა, რომელიც სხვებმა ისესხეს, ითვლება აუზის მთლიანობაში.
- ჩეკი გადის მოთხოვნამდე და არაფერს იტოვებს. ერთდროული მოთხოვნები იკითხება მოხმარებამდე, სანამ რაიმე ჩაიწერება, ასე რომ, დაკრედიტებული სიმძლავრე შეიძლება დაიხარჯოს არაერთხელ, შეზღუდული ფრენის მოთხოვნებით. იგივე თვისება აქვს `saturation` რეჟიმის წილ შემოწმებას.

## მოძრავი ფანჯრის მთვლელი

რეალიზებულია `src/lib/quota/sqliteQuotaStore.ts`-სა და `redisQuotaStore.ts`-ში.

ორი სეგმენტი თითოეული `(apiKeyId, dimensionKey)` წყვილისთვის:

- `curr`: მიმდინარე სეგმენტი (`floor(nowMs / windowMs)`)
- `prev`: წინა სეგმენტი (`curr - 1`)

ეფექტური მოძრავი მნიშვნელობა:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**სიზუსტე**: დაახლოებით 99%. სეგმენტებს შორის საზღვარზე ცდომილება ფანჯრის ზომის მაქსიმუმ
1%-ია (ეს 2-სეგმენტიანი მიახლოების თანდაყოლილი თვისებაა).

### კონკურენტული წვდომა

SQLite-ის დრაივერი: თითოეული `(apiKeyId | dimensionKey)` გასაღებისთვის მეხსიერებაში არსებული mutex
წაკითხვა-შეცვლა-ჩაწერის შეჯიბრის მდგომარეობას თავიდან გვაცილებს. შაბლონი იმეორებს `src/sse/services/auth.ts`-ში გამოყენებულ მოთხოვნების ერთდროული მოზღვავების საწინააღმდეგო მიდგომას.

Redis-ის დრაივერი: ატომური ზრდისთვის გამოიყენება Lua EVAL სკრიპტი — ის Redis-ის ერთი ბრძანების სახით სრულდება.

## დრაივერები

### SQLite (ნაგულისხმევი, ინსტალაციის გარეშე)

- ცხრილი: `quota_consumption` (იხილეთ მიგრაციები `073_quota_pools.sql` / `074_quota_consumption.sql`).
- საუკეთესოა ერთი ინსტანციის მქონე განთავსებებისთვის.
- ყველა მუდმივი მონაცემი ინახება არსებულ OmniRoute SQLite DB-ში (`DATA_DIR/storage.sqlite`).

### Redis (არასავალდებულო, მრავალი ინსტანციისთვის)

- საჭიროებს `ioredis` npm პაკეტს.
- მრიცხველები ინახება Redis-ში; მეტამონაცემები (პულები/განაწილებები) კვლავ SQLite-ში ინახება.
- საუკეთესოა მრავალი რეპლიკის მქონე განთავსებებისთვის, სადაც მრიცხველები საზიარო უნდა იყოს.

### დრაივერების გადართვა

პარამეტრების ინტერფეისიდან (`/dashboard/settings` → Quota Store), ან გარემოს ცვლადების მეშვეობით:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

DB-ის პარამეტრს გარემოს ცვლადზე მაღალი პრიორიტეტი აქვს. თუ `driver=redis`, მაგრამ URL არ არის მითითებული ან
`ioredis` არ არის დაინსტალირებული, ფაბრიკა უბრუნდება SQLite-ს და ჟურნალში გაფრთხილებას წერს.

დრაივერის არჩევის თანმიმდევრობა:

1. DB-ის პარამეტრი `quotaStore.driver`
2. გარემოს ცვლადი `QUOTA_STORE_DRIVER`
3. ნაგულისხმევი: `sqlite`

## მრავალგანზომილებიანი

აუზს შეიძლება ჰქონდეს მრავალი განზომილება. თითოეული განზომილება დამოუკიდებელია:

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",

}
```

**მაგალითი: Codex გეგმა** (5სთ% + ყოველკვირეულად%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

მოთხოვნა უნდა აკმაყოფილებდეს დასაშვებ ყველა განზომილებას.

### პროცენტული ზომები: თითო გასაღების მიკუთვნება

პროცენტული გეგმა იტყობინება გამოყენების ერთ ციფრს თითო ანგარიშისა და გეგმის ფანჯარაში. პროვაიდერი არ აძლევს მრიცხველს API კლავიშზე.

ამ ფიგურის გასაღებებს შორის გასაყოფად, თითოეული ბლოკი ინახავს ატრიბუტების წიგნს თითო ანგარიშისა და გეგმის ფანჯარაში. `src/lib/quota/percentLedger.ts` ფლობს წიგნის წესებს. `src/lib/quota/percentAttribution.ts` აქცევს წიგნს იმ ნომრებად, რომლებსაც აღსრულება იყენებს. შედეგი არის შეფასება, რომელიც აგებულია თითოეული ძირითადი მარშრუტების ნიშნებიდან.

#### საკითხავი, რომელიც ამოძრავებს წიგნს

წიგნი მოძრაობს მხოლოდ პროვაიდერის საკუთარ ფიგურაზე მოთხოვნილი გეგმის ფანჯრისთვის. ეს კავშირები იტყობინება ერთი:

| პროვაიდერი                        | დაგეგმეთ ფანჯრები |
| --------------------------------- | ----------------- |
| Claude, OAuth კავშირის საშუალებით | `5h`, `weekly`    |
| Codex                             | `5h`, `weekly`    |

ეს არ ითვლება წასაკითხად:

- პასუხი, რომელსაც პროვაიდერის კლიენტი აღნიშნავს, როგორც მოძველებულს
- Claude ფანჯარა, რომლის პროცენტი პროვაიდერმა არ მოახსენა
- სხვა ფანჯრის ფიგურა, ან უარეს შემთხვევაში ფანჯრების გასწვრივ
- განაკვეთის ლიმიტის სათაურის სარეზერვო
- წარუმატებელი წაკითხვა

სხვა პროვაიდერებს, მათ შორის Claude API გასაღებით, არ აქვთ წიგნი. თითოეული გასაღები ირიცხება 0 პროცენტით, როგორც ამ ცვლილებამდე.

კითხვა იზიარებს გაჯერების სიგნალის 30 წამიან ქეშს. Claude კითხვა თარიღდება იმით, როდესაც ფიგურა დაფიქსირდა პასუხების სათაურებში ან წაკითხული გამოყენების ბოლო წერტილიდან, როდესაც ეს დრო ცნობილია. სხვა წაკითხვები დათარიღებულია იმ ქეშის ჩანაწერის აშენებით.

#### რასაც წიგნი ინახავს

ყოველი ჩაწერილი მოთხოვნა ამატებს თავის ჟეტონებს, ერთხელ, მრიცხველზე თითო აუზი, ანგარიში და გასაღები. მრიცხველი მხოლოდ იზრდება. წიგნი ინახავს სამ რამეს:

- საბაზისო ხაზი: ფიგურა, როდესაც წიგნი გაიხსნა ან ფანჯარა ბოლოს შემობრუნდა
- ბოლო გამოყენებული ფიგურა
- თითო კლავიშზე, მის ნიშნის მრიცხველმა იმავე მომენტში გამოიძახა მისი ნიშანი

წიგნი განახლდება, როდესაც აღსრულება ან გამოყენების მარშრუტი ითვლის მიკუთვნებას. ჩანაწერები შედარებულია და დაყენებულია გადასინჯვის ნომერზე. მწერალი, რომელიც კარგავს ხელახლა წაკითხვისას ერთხელ ცდის.

#### როგორ გამოითვლება გასაღების ნაწილი

თითოეული გასაღების ნაწილი გამოითვლება წიგნის წაკითხვისას. ფიგურის ზრდა მას შემდეგ, რაც საბაზისო ხაზი იყოფა კლავიშებს შორის იმ ჟეტონების პროპორციულად, რომლებიც თითოეული მათგანი მარშრუტებულია მისი ნიშნის შემდეგ.

Together, ეს ნიშნები ხსნის ფიგურის მაქსიმუმ ერთ წერტილს თითო `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` ჟეტონზე (ნაგულისხმევი 1000). ზრდა, რომელსაც ისინი არ ხსნიან, არის გარეგანი. საბაზისო ხაზი ასევე გარეა.

მაგალითად, წიგნი იხსნება 0-ზე. გასაღები A შემდეგ მარშრუტებს 900,000 ჟეტონს და გასაღები B მარშრუტებს 100,000. 60 ფიგურაზე A-ის ნაწილი არის 54 ქულა, ხოლო B-ის ნაწილი არის 6.

მისი გასაღების ნიშნის ქვემოთ მრიცხველი ხელახლა დაიწყო და სრულად ითვლის. გასაღები ნიშნის გარეშე, როგორიცაა გასაღები, რომელიც უერთდება აუზს ფანჯრის შუაში, ითვლის ყველა მის ნიშანს. ფიგურა, რომელიც ჩამორჩება ნიშნებს, იწვევს შეცდომას, რომელიც ქრება მომდევნო წაკითხვისას. არ გროვდება.

`QUOTA_PERCENT_MIN_TOKENS_PER_POINT` იკითხება ყველა ატრიბუტზე. მნიშვნელობა, რომელიც არ არის მინიმუმ 1-ის სასრული რიცხვი, ბრუნდება 1000-მდე.

#### როგორ ცვლის კითხვა წიგნს

პირველი შესატყვისი წესი მოქმედებს:

1. **წიგნი ჯერ არ არის:** კითხვა ხსნის წიგნს. მისი ფიგურა არის საბაზისო და ყველა მრიცხველი მონიშნულია.
2. **ძველი კითხვა:** იგნორირებულია ბოლო გამოყენებული წაკითხვამდე დათარიღებული. ასეა კითხვა, რომლის გადატვირთვის დრო 30 წუთზე მეტია ადრე შენახულზე.
3. **ახალი პროვაიდერის ფანჯარა:** გადატვირთვის დრო 30 წუთზე მეტი ხნის შემდეგ, ვიდრე შენახული დრო აბრუნებს წიგნს. ფიგურა ხდება საბაზისო ხაზი და ყველა მრიცხველი კვლავ აღინიშნება. გასაღებები მრიცხველის გარეშე ტოვებენ წიგნს.
4. **დასრულებული ფანჯარა:** შენახული გადატვირთვის დრო, რომელიც არ არის წაკითხვის მონაცემების დროის შემდეგ, ნიშნავს, რომ ფანჯარა დასრულდა. კითხვა აქცევს წიგნს, როგორიც არ უნდა იყოს მისი ფიგურა.
5. **უმაღლესი ფიგურა:** მხოლოდ ბოლო ფიგურა მოძრაობს. საბაზისო და ნიშნები რჩება.
6. **იგივე ფიგურა:** ფიგურა, საბაზისო და ნიშნები რჩება. მხოლოდ გადატვირთვის დრო აკლია წიგნს დაწერილი.
7. **ქვედა ფიგურა:** უფრო დაბალი მაჩვენებელი, როგორც ასეთი, არასოდეს გამოიყენება. წიგნს მხოლოდ მაშინ აქცევს, როცა სამი რამ ემართება. ის სულ მცირე ორი წუთით ახალია, ვიდრე ბოლო გამოყენებული კითხვა. არაფერი ამბობს, რომ ფანჯარა იგივე ღიაა. ის ერთ პუნქტზე მეტია დაბალი.

ფანჯარა ითვლება როგორც ღია, როდესაც სამი რამ დგას. ორივე გადატვირთვის დრო ცნობილია. ისინი ერთმანეთისგან 30 წუთის მანძილზე არიან. შენახული ჯერ კიდევ წინ უსწრებს კითხვას. ქვედა ფიგურა ამ ფანჯრის შიგნით არაფერს ცვლის.

გადატვირთვის დრო ინახება მხოლოდ მაშინ, როდესაც ის უსწრებს წაკითხვის მონაცემებს, რომლებიც მას ატარებს. უფრო მაღალი ფიგურა ინახავს წაკითხვის გადატვირთვის დროს, როდესაც ის გამოსაყენებელია, და სხვაგვარად ინახავს შენახულს. თანაბარი ფიგურა აღრიცხავს მისი წაკითხვის გადატვირთვის დროს მხოლოდ მაშინ, როდესაც წიგნს არ აქვს. სხვას არაფერს ცვლის. ქვედა ფიგურა, რომელიც არ აბრუნებს წიგნს, აღრიცხავს გადატვირთვის დროს.

#### როცა წიგნი გამოიყენება

წაკითხვის შემდეგ, წიგნი გამოიყენება, თუ მისი შენახული გადატვირთვის დრო არ არის მიმდინარე დროის შემდეგ. ეს შემთხვევა წარმოიქმნება, როდესაც გადატვირთვის წინ მიღებული წაკითხვა, როგორიცაა ქეშიდან მოწოდებული წაკითხვა, შეინიშნება მის შემდეგ.

გამოსაყენებელი წაკითხვის გარეშე, შენახული წიგნი გამოიყენება მხოლოდ მაშინ, როდესაც ის ჯერ კიდევ შეიძლება იყოს მიმდინარე ფანჯრის წიგნი. ეს ეხება ორ შემთხვევაში:

- მისი გადატვირთვის დრო ცნობილია და ჯერ კიდევ წინ არის
- მას არ აქვს გადატვირთვის დრო და ბოლო წაკითხვა, რომელმაც შეცვალა, არის მაქსიმუმ 15 წუთის წინანდელი

თორემ არაფერი მიეწერება, როგორც მაშინ, როცა წიგნი არ არის. წიგნი, რომლის შენახული გადატვირთვის დრო გავიდა, არასდროს ჩამოიჭრება.

#### აღსრულება

გასაღების მოხმარება პროცენტულ განზომილებაში არის მისი მიკუთვნებული ნაწილი პლუს გარე ნაწილის წილი. გარე ნაწილი პირველ რიგში იყენებს სიმძლავრის გამოყოფის პრეტენზიებს (100 გამოკლებული წონების ჯამი). მხოლოდ ჭარბი ნაწილდება გასაღებებს შორის წონის მიხედვით.

ეს მოხმარება შედარებულია გასაღების სამართლიან წილთან, როგორც ნებისმიერი სხვა განზომილებისთვის. მკაცრი რეჟიმი კვლავ იწყება, როდესაც გაჯერების სიგნალი მიაღწევს `QUOTA_SATURATION_THRESHOLD` (ნაგულისხმევი 0.5). ყველა რიცხვი სკალირებულია ეფექტური ლიმიტით: თითო ანგარიშზე ლიმიტი გამრავლებულია აუზში არსებული ანგარიშების რაოდენობაზე.

აბსოლუტური ქუდი `capUnit: "percent"` ით ითვლის მხოლოდ გასაღებს მიკუთვნებულ ნაწილს, იგივე მასშტაბით. აიღეთ თითო ანგარიშის ლიმიტი 100 და k ანგარიშით. N-ის ზღვრამდე მიღწეულია, როდესაც გასაღების ნაწილი მომსახურების ანგარიშის ფიგურაში აღწევს N/k წერტილებს. თითოეული ანგარიში მოწმდება საკუთარი წიგნის მიხედვით. მაგალითად, ორი ანგარიშით, 10-ის ლიმიტი მიიღწევა ერთი ანგარიშის ფიგურის 5 პუნქტში.

როდესაც მაღაზიის წაკითხვა შეუძლებელია, არაფერი ენიჭება და ყველა გასაღები ირიცხება 0 ამ განზომილებაში. როდესაც წიგნის დაწერა ვერ ხერხდება, ეს ატრიბუტი იყენებს წიგნს წაკითხვისას. ნიშნის წარუმატებელი ჩაწერა ტოვებს ამ მოთხოვნის ნიშნებს წიგნიდან. არცერთი ეს წარუმატებლობა არ ბლოკავს მოთხოვნას.

`consent` აუზში, სესხის გაცემის ფორმულა იყენებს თითოეული გასაღების მოხმარებას პროცენტულ განზომილებაში, როგორც ზემოთ აღწერილია. როდესაც სხვა გასაღები გასცემს, წიგნი ერთხელ იკითხება და ყველა გასაღებს მიეწერება. გამოსაყენებელი წიგნის გარეშე ყველა გასაღები იტენება 0-ით. წონით გასაღები შემდეგ გადის, ხოლო გასაღები 0 წონით გადის მხოლოდ მაშინ, როდესაც სხვა გასაღები გადის.

#### გამოყენების მარშრუტი

`GET /api/quota/pools/{id}/usage` იტყობინება იგივე ნომრები იგივე ფუნქციით. პროცენტულ განზომილებას აქვს ერთი ჩანაწერი აუზის კავშირზე `accounts` ში. მისი ზედა დონის `consumedTotal` და `perKey` ასახავს პირველ ჩანაწერს.

მარშრუტი ასევე იყენებს მიმდინარე კითხვას, ასე რომ, მას შეუძლია წიგნის წინ წაწევა, როგორც ამას აკეთებს მოთხოვნა. `internal + external` შეიძლება განსხვავდებოდეს `consumedTotal` ისგან, როდესაც არ არის გამოსაყენებელი კითხვა, ან როდესაც არ არის გამოყენებული ქვედა ფიგურა.

#### შენახვა და შენახვა

ორივე კვოტიანი მაღაზია ინახავს წიგნს. SQLite ზე, მონაცემთა ბაზის ავტომატური გასუფთავება, როდესაც ჩართულია, შლის 60 დღის განმავლობაში არ განახლებულ რიგებს. Redis ზე აუზის კავშირის წიგნები და მრიცხველები იზიარებენ ერთ კლავიშს. მას ვადა ეწურება 60 დღის შემდეგ მისი ბოლო ნიშნული ჩაწერიდან ან წიგნის შეცვლიდან. წიგნი, რომელიც არ იცვლება, ხელახლა არ იწერება, ამიტომ წყვეტა დაყენებულია ყველაზე გრძელი გეგმის ფანჯრის ზემოთ. გამოყენების ისტორიის ხელით გადატვირთვა ასევე ასუფთავებს წიგნებს SQLite ზე (იხ. შეზღუდვები).

#### შეზღუდვები

- ანგარიშის მთელი ზრდა მას შემდეგ, რაც საბაზისო ხაზი იყოფა ტოკენებით, ყოველი გასაღების მარშრუტი მას შემდეგ. როდის მოხდა ეს ზრდა, არ აქვს მნიშვნელობა.
- ასე რომ, OmniRoute გარეთ განხორციელებული გამოყენება ერიცხება კლავიშებს, რამდენადაც მათი ნიშნები იძლევა საშუალებას. ეს მოიცავს ფანჯრის გასაღების პირველ მოთხოვნამდე გამოყენებას, როდესაც წიგნი უკვე ღია იყო.

## მილსადენის ინტეგრაცია

### PRE hook (`open-sse/handlers/chatCore.ts`)

გადის ზემოთ აღმასრულებლის წინაშე, ავტორიზაციის და პოლიტიკის შემოწმების შემდეგ:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → getQuotaStore().peek() per dimension
      → fairShare.decideFairShare()
      → if block → return 429 (buildErrorBody, Hard Rule #12)
      → if allow + deprioritize → set quotaSoftPenalty=true on candidate
  → executor.execute()
```

**ჩავარდნა-გახსნა** : თუ `enforceQuotaShare` ისვრის, მოთხოვნა დაშვებულია `pino.warn` ჟურნალით. ეს ხელს უშლის კვოტის ძრავის შეცდომის დაბლოკვას ყველა ტრაფიკის.

**როცა სიმძლავრე უბრუნდება.** გასაღების წილზე ან აუზის ჭერზე უარი მთავრდება ორიდან ერთი წინადადებით, ორივე სესხის რეჟიმში:

- `percent` ფანჯარა: `. The <window> window resets at <time>.` დრო არის გადატვირთვის პროვაიდერის ინფორმაციით.
- თვლადი ერთეული: `. Enough <window> usage is expected to clear by <time>.` დრო არის ზედა ზღვარი მოცურების ფანჯრიდან, თუ გასაღები სხვას არაფერს აგზავნის.

`<time>` არის ISO 8601 მომენტი UTC ში. შემდეგ უარი ატარებს `Retry-After`: მთელ წამს ამ მომენტამდე, პლუს ერთი. კლიენტი, რომელიც ელოდება ამდენ ხანს, მყისიერებიდან მაქსიმუმ ერთი წამის შემდეგ ეცდება. როდესაც მომენტი არ არის ცნობილი, უარი არ შეიცავს არც წინადადებას და არც სათაურს. აბსოლუტური კაპიტალის უარი არც ერთს არ ახასიათებს. საჯარო კოდი რჩება `quota_share_blocked`.

გაზიარებაზე უარი არ ეხება გაზიარებულ კავშირს. ის არ აყენებს გაგრილებას, მოდელის დაბლოკვისა და პროვაიდერის ამომრთველის უკმარისობას, ხოლო აუზის სხვა გასაღებები გრძელდება. როდესაც კომბინაციის ყველა სამიზნე უარს ამბობს თავისი წილის გასაღებზე, კომბინირებული პასუხობს 429-ს მოლოდინის გარეშე. მისი პასუხი ატარებს მინიშნებას, როგორც `Retry-After`. ჩაშენების გზა ამთავრებს თავის უარს იმავე წინადადებით და არ აგზავნის `Retry-After`.

```
      → fail-open: errors logged as pino.warn, never propagated to client
```

**დრიფტის შენიშვნა** : თუ `consume` ვერ პასუხობს შემდგომ, მოძრავი მრიცხველი ითვლის. გაჯერების სიგნალი პროვაიდერისგან (მაგ. `anthropic-ratelimit-unified-5h-utilization`) ასწორებს გლობალურ შეფასებას მომდევნო მოთხოვნაზე.

### კომბინირებული რბილი ჯარიმა (`open-sse/services/combo.ts`)

როდესაც `decision.deprioritize === true`:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // default 0.7
}
```

ჯარიმა გამოიყენება ყველა სხვა შეფასების ფაქტორების შემდეგ. ეს ამცირებს გაჯერებული გასაღების არჩევის ავტომატური კომბინაციის ალბათობას მისი მყარი დაბლოკვის გარეშე.

## თვითმომსახურების კვოტა API (შეთანხმება)

`GET /api/v1/me/quota/{provider}` (ასევე ემსახურება `/v1/me/quota/{provider}`) API გასაღების მფლობელს საშუალებას აძლევს წაიკითხოს, საკუთარი გასაღებით, რამდენი საზიარო გამოწერა არის მათი და რა ბლოკავს მათ. მარშრუტი არის თხელი გარსი `src/server/selfService/quotaHandler.ts` ზე; ხედი აგებულია `src/lib/quota/selfView.ts` მიერ და მისი საპასუხო კონტრაქტი არის `src/shared/schemas/selfQuota.ts` (`SelfQuotaView` in `docs/openapi.yaml`).

### ჩართვა და ავთენტიფიკაცია

- მხატვრული დროშა `QUOTA_SELF_PANEL`, ნაგულისხმევი `false`. სანამ ის გამორთულია, მოთხოვნა, რომელიც მიაღწევს მარშრუტს, იღებს 404-ს. `REQUIRE_API_KEY=true` ით, კლიენტის API პოლიტიკა უარს ამბობს 401-ით გამოტოვებულ ან არასწორი გასაღებით, მარშრუტის გაშვებამდე, როგორიც არ უნდა იყოს დროშა. მოთხოვნა გასაღების გარეშე, მაგრამ შესული საინფორმაციო დაფის სესიით გადის ამ პოლიტიკას და იღებს მარშრუტის პასუხს. დროშა წყვეტს, როგორც ყველა სხვა დროშა (დაფა ან REST გადაფარვა, შემდეგ ამავე სახელწოდების გარემოს ცვლადი); იხილეთ [`FEATURE_FLAGS.md`](../reference/FEATURE_FLAGS.md).
- თითოეული აუზის საჩვენებელი სახელი და თითოეული განრიგის ეტიკეტი უბრუნდება აუზის გასაღების მფლობელებს ზუსტად ისე, როგორც ადმინისტრატორმა დაწერა. დროშის ჩართვამდე შეამოწმეთ, რომ ისინი შესაფერისია გასაღებების მფლობელებისთვის წასაკითხად.
- გასაღები იკითხება მხოლოდ სათაურებიდან: `Authorization: Bearer <key>` ან `x-api-key: <key>`. როდესაც ორივე იგზავნება, გამოიყენება პირველი, რომელიც ადასტურებს. მოთხოვნის სტრიქონში გასაღები ან ქუქი-ფაილი იგნორირებულია. სერვერის გარემოს გასაღები უარყოფილია (401).
- გასაღებს სჭირდება `self:usage` ფარგლები (403 მის გარეშე).
- პროვაიდერის სეგმენტი ამოჭრილია, მცირე ასოებით და მოწმდება `^[a-z0-9][a-z0-9._-]{0,63}$` სთან (400 სხვაგვარად), შემდეგ წყდება პროვაიდერის რეესტრის მეშვეობით, ასე რომ, მეტსახელი, როგორიცაა `cc` კითხულობს `claude` აუზებს. `claude` და `anthropic` კითხულობენ იგივე აუზებს.

| -------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

- `sharedQuotaProviders` არის თითო გასაღების პარამეტრი (`PUT /api/keys/[id]/self-service`): `null`, ნაგულისხმევი, ნიშნავს, რომ გასაღები აღწევს ყველა პროვაიდერს; `[]` ნიშნავს არცერთს. თითოეული აუზის `accountVisible` ამბობს, რომელი ხილვადობა ვრცელდება მასზე.
- ანგარიშის ზოლები და მოდელის ფანჯრები ნაჩვენებია მხოლოდ იმ ანგარიშებისთვის, რომელთა კავშირიც შეიძლება გამოიყენოს გასაღებმა. როდესაც გასაღებს აქვს ნებადართული კავშირების სია, ანგარიში მის გარეთ ინახავს მის `Account N` ჩანაწერს `account` ან `modelWindows` გარეშე. ცარიელი სია არ ნიშნავს შეზღუდვას, რაც შეეხება `/v1/me/status`. აუზის საერთო რაოდენობა (`dimensions[].total`) არ არის დამოკიდებული ამ სიაზე.
- მხოლოდ `self:usage` ით ნაჩვენები ორი ფიგურა მოდის სხვა გასაღებების გამოყენებისგან. გრაფიკის ბიუჯეტის `exhausted` ასახავს ყველა გასაღების მოხმარებას ამ გრაფიკის მიხედვით. აუზში, რომლის წონა ნულის ტოლია, გასაღების `weight` არის `100 / number of members`. ორივე არის ის, რაც აღსრულება ეხება გასაღებს.
- აუზი იდენტიფიცირებულია მხოლოდ `ref` ით, გაუმჭვირვალე მნიშვნელობით, რომელიც დაკავშირებულია გამოძახების გასაღებთან. მისი საჩვენებელი სახელი (`name`) შედის როგორც ადმინისტრატორმა დაწერა. `ref` მიღებულია გასაღებიდან და პულიდან სერვერის API-გასაღების საიდუმლოებით (`API_KEY_SECRET`). კლიენტებმა არ უნდა გააგრძელონ ეს: ის შეიცვლება, თუ ეს საიდუმლო ბრუნდება.
- ანგარიშები ჩამოთვლილია როგორც `Account 1`, `Account 2`, … აუზის თანმიმდევრობით. აუზის ID, კავშირის ID, ანგარიშის ელფოსტა ან ანგარიშის სახელი არ ბრუნდება და პასუხი გადის კონტრაქტის სქემით, რომელიც ტოვებს მის გარეთ არსებულ ნებისმიერ ველს.
- Countable units (`requests`, `tokens`, `usd`) are reported as the pool bucket the quota gate enforces: `limit` = plan limit × accounts in the pool, `fairShare` = weight / 100 × `limit` (equal split when every weight is 0), `consumed` = the key's own counter in the quota store, `remaining` = `fairShare` − `consumed`, floored at 0.
- `blocks.schedules` ჩამოთვლის გასაღების განრიგის ფანჯრებს (`open`/`closed`, `blackout` ან `outside-window`, `retryAfterSeconds`, სარეზერვო სართულები და იხარჯება თუ არა ფანჯრის ბიუჯეტი); `blocks.modelCaps` ჩამოთვლის თავის მოდელს საათობრივ ლიმიტებს მოხმარებით.
- გასაღები პროვაიდერის ყველა აუზის გარეთ იღებს 200 `pools: []` სთან ერთად; `availableModels` ( `qtSd/` ids, რომელიც კლავიშს ხედავს `/v1/models` ში), `expiresAt` და `apiBaseUrl` კვლავ ივსება.
- `apiBaseUrl` არის `OMNIROUTE_PUBLIC_API_BASE_URL`, შემდეგ `OMNIROUTE_PUBLIC_BASE_URL`, სხვაგან `null`. ეს არასოდეს არის მოთხოვნის საკუთარი წარმოშობა.

### სესხის გაცემის თანხმობა

`PATCH /api/v1/me/quota/{provider}` ჩაწერს დარეკვის გასაღების თანხმობას ერთ აუზზე. ის იყენებს `GET` ის დროშას, სათაურებს და პროვაიდერის წესებს. `self:usage` scope უფლებას აძლევს ამ ჩაწერას, თუმცა მისი სახელი იკითხება როგორც მხოლოდ წაკითხვადი.

```json
{
  "pool": "qpr_0123456789abcdef0123456789abcdef",
  "lendingPercent": 30,
  "lendingUntil": 1893456000000
}
```

- `pool` არის `ref`, რომელსაც `GET` აბრუნებს ამ აუზისთვის.
- `lendingPercent` არის მთელი რიცხვი 0-დან 100-მდე. მნიშვნელობა 0 ასუფთავებს თანხმობას და მის ვადას. სხეული `lendingPercent` 0-ით მიიღება ორივე რეჟიმში.
- `lendingUntil` არჩევითია: ეპოქის მილიწამები, ან `null` ვადის გარეშე. ეს უნდა იყოს მომავალში და მაქსიმუმ 8640000000000000. 1000000000000-ზე დაბალი მნიშვნელობა იკითხება წამად და უარყოფილია.
- ნებისმიერ სხვა სფეროზე უარი ეთქვა. 4096 ბაიტზე მეტ სხეულზე უარყოფილია. წაკითხვა ჩერდება ამ ზომაზე, ასე რომ, გრძელი სხეული არასოდეს ინახება მთლიანობაში.

შემოწმებები ტარდება ამ ცხრილის თანმიმდევრობით. ყოველი უარი იყენებს სტანდარტული შეცდომის ორგანოს ფიქსირებული შეტყობინებით. ერთ-ერთი ასეთი ჩეკით უარი არაფერს წერს.

| სტატუსი | შეტყობინება                                                                                        | როცა                                                            |
| ------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 404     | `Not found`                                                                                        | `QUOTA_SELF_PANEL` დროშა გამორთულია.                            |
| 401     | `Valid API key required`                                                                           | გასაღები აკლია ან არასწორია, ან არის სერვერის გარემოს გასაღები. |
| 403     | `API key lacks the self:usage scope`                                                               | გასაღებს აკლია `self:usage`.                                    |
| 400     | `Invalid provider`                                                                                 | პროვაიდერის სეგმენტი არასწორია.                                 |
| 429     | `Too many lending changes. Retry later.`                                                           | გასაღებმა ზღვარი გადალახა. პასუხი ახორციელებს `Retry-After`.    |
| 400     | `Body must be { pool, lendingPercent, lendingUntil }. lendingPercent is an integer from 0 to 100.` | სხეული არ არის JSON, ძალიან გრძელია ან არ ემთხვევა სქემას.      |
| 400     | `lendingUntil must be a Unix time in milliseconds`                                                 | ბოლო ვადა იკითხება როგორც წამი.                                 |
| 400     | `lendingUntil must be in the future`                                                               | ბოლო ვადა არის მოთხოვნის დროზე ან მის წინ.                      |
| 404     | `Pool not found`                                                                                   | `ref` არ ასახელებს ამ გასაღების აუზს ამ პროვაიდერისთვის.        |
| 403     | `Lending is not enabled for this pool`                                                             | აუზი `saturation` რეჟიმშია და `lendingPercent` 0-ზე მეტია.      |
| 500     | `Failed to build quota view`                                                                       | ნებისმიერი სხვა მარცხი. მისი მიზეზი სერვერზეა შესული.           |

ლიმიტი არის 20 მოთხოვნა 60 წამში თითოეული გასაღებისთვის. ყოველი მოთხოვნა, რომელიც გაივლის პროვაიდერის შემოწმებას, ითვლის, თუნდაც ერთი უარი მოგვიანებით ან ის, რომელიც არაფერს ცვლის. მას აქვს საკუთარი მრიცხველი, გარდა გასაღების მოთხოვნის განაკვეთის ლიმიტისა.

მოთხოვნა, რომელიც ცვლის შენახულ თანხმობას, წერს ერთ `quota.pool.lending.updated` აუდიტის ჩანაწერს. ის ასახელებს გასაღებს ძველი და ახალი მნიშვნელობებით. ორჯერ გაგზავნილი ერთი და იგივე ორგანო წერს ერთხელ და ამოწმებს ერთხელ. პასუხი არის 200 სრული `GET` ხედით, რომელიც აშენებულია ჩაწერის შემდეგ.

`GET` view იუწყება სესხის გაცემას შემდეგნაირად:

- თითოეულ აუზს აქვს `borrowMode` (`saturation` ან `consent`) და გასაღების საკუთარი `lendingPercent` და `lendingUntil`.
- `lendingActive` არის `true` მხოლოდ `consent` აუზში, 0-ზე მეტი პროცენტით და ვადა მიუღწეველია.
- `consent` აუზში, თითოეული თვლადი `dimensions[].yourShare` ატარებს `borrowAvailable`. ეს არის ის, რაც გასაღებმა შეიძლება გამოიყენოს მის წილზე მაღლა ახლა, ესესხება სხვა გასაღებები.
- `borrowAvailable` იყენებს კარიბჭის ფორმულას. ის კითხულობს ყველა სხვა კლავიშს, ასევე სანამ გასაღები მისი წილის ქვეშ იმყოფება. `hard` კლავიშისთვის, რომელიც არის ერთი დამატებითი წაკითხვა თითო კლავიშზე და თვლადი განზომილება, პარალელურად.
- `borrowAvailable` არის `null` `soft` ან `burst` გასაღებისთვის და `null`, როდესაც წაკითხვა ვერ ხერხდება.
- `borrowAvailable` არის ერთი ფიგურა ყველა სხვა გასაღებისთვის ერთად. ორი გასაღების აუზში ეს არის მეორე გასაღების საკუთარი ფიგურა.
- `borrowAvailable` ჯერ არ არის მოხსენებული `percent` windows-ისთვის ან `accounts[]` ში.
- `saturation` აუზში ხედი იტყობინება შენახული თანხმობის შესახებ `lendingActive: false` და არა `borrowAvailable`.

### შეცდომები

ამ მარშრუტის ყოველი პასუხი, წარმატება თუ შეცდომა, შეიცავს `Cache-Control: no-store`. უარი, რომელიც ხდება მარშრუტის გაშვებამდე, არ შეიცავს მას, მაგალითად, კლიენტის API პოლიტიკის 401 ან IP ფილტრის 403. მარშრუტის შეცდომები იყენებს სტანდარტული შეცდომის სხეულს ფიქსირებული შეტყობინებით: 400 (არასწორი პროვაიდერი), 401 (გადაცილებული ან არასწორი გასაღები), 403 (გამოტოვებული `self:usage`) და 50 (გამოტოვებული `Failed to build quota view`). 500 მოიცავს ნებისმიერ წარუმატებლობას მას შემდეგ, რაც მოთხოვნა მიაღწევს მარშრუტს, თავად გასაღების მოძიების ჩათვლით; მისი მიზეზი შესულია სერვერზე და აღარ დაბრუნებულა. `PATCH` ის შეცდომები ჩამოთვლილია [სესხის აღების თანხმობაში](#lending-consent).

### შეზღუდვები

- `remaining` არის გასაღების სამართლიანი წილის ნაწილი, რომელიც მას არ გამოუყენებია. ეს არ არის გარანტია. გასაღები მაინც შეიძლება მიირთვათ მის მიღმა, სანამ აუზს აქვს ადგილი. როგორც კი აუზის ჯამი მიაღწევს `limit`, აუზის ყველა გასაღებს უარს ეუბნება, როგორიც არ უნდა იყოს მისი `remaining`, და გასაღები `self:account-quota` გარეშე ვერ ხედავს ამ მთლიანს.
- `remaining` არ ითვალისწინებს განაწილების აბსოლუტურ `cap` ს. აღსრულება უარს ამბობს გასაღებზე მას შემდეგ, რაც მისი საკუთარი მოხმარება თავსახურის ერთეულის ფანჯარაში მიაღწევს თავსახურის მნიშვნელობას.
- ანგარიშის დონის ზოლი მოდის პროვაიდერის ლიმიტების ქეშიდან და შეუძლია აღსრულების გადაწყვეტილების მიღებას რამდენიმე წუთით ჩამორჩენა. კითხვა, რომლის გადატვირთვის დრო გავიდა, მოხსენებულია როგორც `stale`.
- თითო მოდელის ფანჯრები (`modelWindows`) მოხსენებულია მხოლოდ პროვაიდერებისთვის, რომლებსაც აქვთ გეგმის ფანჯრის რუქა: Claude და Codex დღეს. სხვა პროვაიდერებისთვის `modelWindows` კვლავ არსებობს, როდესაც ნაჩვენებია ანგარიშის მონაცემები, ცარიელი `windows` სიით.
- გასაღების საკუთარი წილი `percent` ფანჯარაში არის სავარაუდო. ის მომდინარეობს ატრიბუციის წიგნიდან და შეიცავს ყველა შეზღუდვას, რომელიც ჩამოთვლილია ზემოთ "პროცენტული ზომები: თითო გასაღების მიკუთვნება".
- `consumed` არის რიცხვის აღსრულება შედარებით სამართლიან წილთან. ეს არის `attributed` პლუს `external`, ზუსტად. `attributed` არის ის ნაწილი, რომელსაც წიგნი აძლევს გასაღებს იმ ნიშნებისთვის, რომლებიც მან გაიარა. `external` არის გასაღების ნაწილი ანგარიშის გამოყენებისას, რომელსაც აუზის გასაღებები არ ითვალისწინებს.
- ორივე ნაწილი იგზავნება მხოლოდ მაშინ, როდესაც აუზის `accountVisible` არის true: გასაღები აქვს `self:account-quota` და პროვაიდერი არის მის `sharedQuotaProviders` ში. გასაღები მის გარეშე იღებს `consumed` მარტო, იგივე `status` და `reason`.
- ორივე ნაწილით და საკუთარი წონით, დამჭერს შეუძლია გამოიყენოს აუზის გარეთ გაკეთებული გამოყენება, რომელიც დატენილია აუზის გასაღებებზე. ანგარიშის ფარგლების მფლობელი უკვე ხედავს ანგარიშის ჯამს.
- გასაღები, რომელმაც ფანჯარაში არაფერი გაატარა, მაინც შეუძლია წაიკითხოს მისი გარე მუხტი `consumed` დან, რადგან მისი მიკუთვნებული ნაწილი არის 0.
- მაგალითად, წიგნი იხსნება 0-ზე, A და B ღილაკებით თითოეული 50 წონით. გასაღები A მარშრუტებს 900,000 ჟეტონს და გასაღები B 100,000. შემდეგ ანგარიში აღწევს 100-ის ლიმიტის 60%-ს. შემდეგ `attributed` არის 54 კლავიშისთვის A და 6 გასაღებისთვის, და `external` არის 0 ორივესთვის.
- ხედი კითხულობს წიგნს და არასოდეს წერს მის მდგომარეობას. ის არ ხსნის წიგნს და არასოდეს სთხოვს პროვაიდერს კითხვას. Redis store-ით წაკითხვა აშორებს ჩანაცვლებულ რევიზიის ველებს ფონზე, როგორც ამას აკეთებს კარიბჭის წაკითხვები.
- წილი არის `ok` მხოლოდ მაშინ, როდესაც კარიბჭის ქეში შეიცავს ანგარიშის კითხვას. ერთის გარეშე ის არის `stale`, ასე რომ აუზში ბოლო მოთხოვნის გარეშე ჩანს, როგორც შესაძლოა მოძველებული.
- სანამ მოთხოვნა არ გაივლის აუზს, წილი მიუწვდომელია. ეს მოთხოვნა ხსნის წიგნს და იმ მომენტში ანგარიშის ფიგურა ითვლება აუზის გარეთ განხორციელებულ გამოყენებად.
- რამდენიმე ანგარიშის მქონე აუზში, თითოეული ანგარიშის ჩანაწერი იყენებს ამ ანგარიშის საკუთარ წიგნს და ერთი ანგარიშის ლიმიტს. აღსრულების მასშტაბები ორივე მხარეს აფასებს ანგარიშების რაოდენობის მიხედვით, ამიტომ პროპორცია იგივეა.
- თითო მოდელის ფანჯრები არ შეიცავს გასაღებს. წიგნი არ ინახავს თითო მოდელის მონაცემებს.
- განრიგის სარეზერვო სართულები არ არის შეფასებული ხედვით: განრიგი შეიძლება გამოჩნდეს როგორც `open` ხოლო მოთხოვნაზე უარის თქმა მიზეზით `schedule-reserve`.
- როდესაც ერთი და იგივე გასაღების ორი აუზი იზიარებს კავშირს, აღსრულება ვრცელდება ერთ-ერთ მათგანზე და ხედი ჩამოთვლის ორივეს.
- არ არსებობს თითო მისამართის შეზღუდვა გასაღების წარუმატებელ მცდელობებზე: საპირისპირო პროქსის მიღმა აბონენტებს შეუძლიათ ერთი მისამართის გაზიარება (ეს დამოკიდებულია იმაზე, არის თუ არა გადაგზავნილი კლიენტის მისამართები სანდო), ასე რომ, დაბლოკვამ შეიძლება უარყოს მარშრუტი ყველა გასაღების მფლობელთან. `REQUIRE_API_KEY=true` სთან ერთად, კლიენტის API პოლიტიკა უარს ამბობს არასწორ გასაღებზე მარშრუტის გაშვებამდე, ამ პოლიტიკის 401 ტექსტით ამ მარშრუტის ნაცვლად.

### წევრების გამოყენება

ადმინისტრატორს შეუძლია გასაღების მფლობელებს ნახონ, როგორ ნაწილდება ფანჯრის გამოყენება ფონდის წევრებს შორის. ვარიანტი არის აუზის `memberBreakdown`, ნაგულისხმევად გამორთულია. ის დაყენებულია აუზის ოსტატში ან `PATCH /api/quota/pools/{id}` ით. `GET /api/quota/pools` და `GET /api/quota/pools/{id}` შეატყობინეთ მას.

ხედის განზომილება ატარებს `members` მხოლოდ მაშინ, როდესაც ეს ყველაფერი მოქმედებს:

- აუზის ვარიანტი ჩართულია
- აუზს აქვს მაქსიმუმ 20 გამოყოფილი გასაღები და მინიმუმ სამ მათგანს შეუძლია მოთხოვნის გაკეთება: აქტიური, გაუქმებული, აკრძალული და ვადის გასვლის გარეშე.
- აუზის `accountVisible` მართალია: გასაღები აქვს `self:account-quota` და პროვაიდერი არის მის `sharedQuotaProviders` ში
- `percent` ფანჯარაში, ანგარიშის კავშირი არის ერთ-ერთი გასაღები, რომლის გამოყენებაც შეიძლება
- გასაღების საკუთარი წილი იმ ფანჯრიდან იკითხებოდა: მისი `status` არ არის `unavailable`

წინააღმდეგ შემთხვევაში `members` არ არის. ის არასოდეს არის ცარიელი სია.

- თითოეული ნაჭერი არის `{ slot, consumed, isYou }`. საპასუხო სქემა უარყოფს ნებისმიერ სხვა თვისებას ნაჭერზე და 20-ზე მეტი ნაჭრის ჩამონათვალს. ნაჭრები ჩამოთვლილია სლოტების თანმიმდევრობით.
- არის ერთი ნაჭერი თითო გამოყოფილ გასაღებზე, მათ შორის გასაღები, რომელსაც აღარ შეუძლია მოთხოვნის გაკეთება. უსარგებლო წევრი აჩვენებს ნამდვილ ნულს.
- სლოტი 1 ყოველთვის არის მოთხოვნის გასაღები, `isYou` true-ით. სხვა სლოტის ნომრები არის კლავიშიანი ჰეშის რიგები. ის იკვრება `API_KEY_SECRET` ით და ფარავს აუზს, თხოვნის გასაღებს და წევრს.
- ასე რომ, რიცხვები არ შეესაბამება მფლობელებს შორის. ერთი მფლობელისთვის ისინი იგივე რჩება ვიზიტებს შორის. ისინი შეიძლება შეიცვალოს, როდესაც გასაღები უერთდება ან ტოვებს აუზს, ან როდესაც ეს საიდუმლო ბრუნავს.
- თვლადი ფანჯარაზე ნაჭერი არის წევრის მრიცხველი კვოტების მაღაზიაში, იგივე მრიცხველი, როგორც საკუთარი `consumed`.
- `percent` ფანჯარაზე ნაჭერი არის წევრის `attributed` ნაწილი, იგივე წიგნიდან წაკითხული, როგორც გასაღების საკუთარი წილი. აუზის გარეთ გამოყენება არასოდეს იყოფა ნაჭრებად. ეს მუხტი იყოფა წონის მიხედვით, ასე რომ, ნაჭრები, რომლებიც მას ატარებდნენ, აჩვენებს წონას.
- თითოეული ხედი კითხულობს ერთ მნიშვნელობას სხვა წევრზე და თვლადი ფანჯარაზე, პარალელურად. `percent` ფანჯარაში ნაჭრების წაკითხვა არ ღირს აქციის წაკითხული წიგნის მიღმა. როდესაც ერთი მნიშვნელობის წაკითხვა შეუძლებელია, ამ ფანჯარას არ აქვს `members` და გასაღების საკუთარი წილი რჩება.
- ოფცია და გამოსაყენებელი გასაღებების რაოდენობა იკითხება ერთხელ თითო აუზზე და მხოლოდ გასაღებისთვის, რომელსაც შეუძლია ნახოს ანგარიშის მონაცემები. ოფციის ან გამოსაყენებელი კლავიშების არასწორად წაკითხვა გამორთავს ზოლებს ამ აუზისთვის. სერვერი იწერს გაფრთხილებას და დანარჩენი ხედი აგებულია.

ბარებს არ აქვთ სახელები ან პირადობის მოწმობები. ისინი კვლავ ეუბნებიან გასაღების მფლობელს სხვა წევრებზე:

- მფლობელებს ჯერ კიდევ შეუძლიათ ნაჭრების შეხამება მათი მნიშვნელობებით.
- სტაბილური ნუმერაცია საშუალებას აძლევს მფლობელს მიჰყვეს ერთ წევრს დროთა განმავლობაში.
- ნაჭრების რაოდენობა გვიჩვენებს რამდენი გასაღებია გამოყოფილი აუზში.
- სამი გასაღებისგან შემდგარ აუზში, ვინც იცის, რა გამოიყენა ერთი გასაღები, შეუძლია თქვას, რა გამოიყენა ბოლო გასაღები.
- როდესაც აუზი სამი გამოსაყენებელი გასაღების ქვემოთ ჩამოდის, ზოლები ქრება. ადრე გადაღებული ნახვები მაინც აჩვენებს, თუ რას იყენებდა თითოეული წევრი.
- თვლადი ფანჯარაზე, აუზის ჯამურ რაოდენობას მინუს ნაჭრები შეუძლია აჩვენოს გასაღებების გამოყენება, რომლებიც აღარ არის გამოყოფილი.
- წევრს, რომელიც აჩვენებს ნულს ერთ ანგარიშზე და იყენებს მეორეს, შეუძლია აჩვენოს, რომელი წევრი რომელ ანგარიშს იყენებს.
- თვლადი აუზში `hard` პოლიტიკით, ნაჭერი, რომელიც წყვეტს ზრდას წევრის სამართლიან წილზე, მიანიშნებს ამ წევრის წონაზე.

### გამოყენების სერია (`GET /api/v1/me/usage`)

`GET /api/v1/me/usage?range=<range>` (ასევე ემსახურება `/v1/me/usage`) აბრუნებს დარეკვის გასაღების საკუთარი მოთხოვნების გამოყენებას და ღირებულებას: ჯამები, ერთი ჩანაწერი UTC დღეში, დღეში და მოდელზე, მოდელზე და პროვაიდერზე. ის იზიარებს დროშას, ავთენტიფიკაციის წესებს, `self:usage` ფარგლებს, `Cache-Control: no-store` და ზემოთ მოყვანილი კვოტის მარშრუტის შეცდომის ქცევას. გასაღები შემოწმებულია `range` მდე. შეცდომები არის 400 (`Invalid range`), 401, 403, 404 და 500 (`Failed to build usage`).

- `range` არის `1d`, `7d`, `30d` (ნაგულისხმევი) ან `90d` დან ერთ-ერთი. ნებისმიერი სხვა მნიშვნელობა, ცარიელი მნიშვნელობა ან განმეორებითი პარამეტრი არის 400. კომპლექტი ჩერდება `90d` ზე ზარის ღირებულების დასაკავებლად. ხედი კითხულობს მხოლოდ ნედლეული გამოყენების ისტორიას, არასოდეს ყოველდღიურ შეჯამებებს, რომლებსაც გასაღები არ აქვთ.
- რიგები შეირჩევა ზარის გასაღების ID-ით. გასაღების სახელის სვეტი არასოდეს ემთხვევა და კლავიშის id-ის გარეშე ჩაწერილი რიგები არასოდეს ითვლება.
- სერიის აგება აწარმოებს ხუთ დაჯგუფებულ მოთხოვნას ფანჯარაში გასაღების მწკრივებზე. ჩაშენებული სერია ხელახლა გამოიყენება 60 წამის განმავლობაში თითო კლავიშზე და დიაპაზონზე, ხოლო ხელახლა გამოყენებული ზარი არ სრულდება. მისი `generatedAt` თავის ასაკს იძლევა.
- ფანჯარა მთავრდება სერიის აშენებისას. მოგვიანებით დაბეჭდილი მწკრივი, მაგალითად, საათის დახრილობით, არ ითვლება.
- `coverage.retentionDays` არის ოპერატორის გამოყენების ისტორიის შენარჩუნების პარამეტრი (`retention.usageHistory` მონაცემთა ბაზის პარამეტრებში). `coverage.truncatedByRetention` მართალია, როდესაც მოთხოვნილი დიაპაზონი აღემატება ამ პარამეტრს. ის ადარებს ორ რიცხვს და არ ამოწმებს, ნამდვილად აკლია თუ არა რიგები.
- პროვაიდერი ბრუნდება როგორც ჩაწერილია გასაღების საკუთარი მოთხოვნებისთვის. მოდელი არის ჩაწერილი სახელი მისი ბოლო `/` შემდეგ და რიგები დაჯგუფებულია მის მიხედვით. კომბინირებული მოთხოვნა, რომლის ყველა სამიზნეზე უარი თქვა, ჩაიწერება მარშრუტიზაციის ლეიბლით, როგორც პროვაიდერი (კომბოს სახელი, `auto` ან `combo`) და კლიენტის მიერ გაგზავნილი მოდელის სტრიქონი. სხვა უარყოფილი მოთხოვნები, მაგალითად, ღია ამომრთველით, მოდელის გაგრილება ან კვოტით გაჩერებული გამოტოვება, შეინახეთ სამიზნე პროვაიდერი და მოდელი.
- გარდა დათვლისა და ხარჯებისა, პასუხი ახასიათებს საშუალო შეყოვნებას, წარმატების მაჩვენებლებს და პირველი და ბოლო მოთხოვნის დროებს.
- `byModel` ჩამოთვლის 50 პროვაიდერსა და მოდელს წყვილს ყველაზე მეტი მოთხოვნით. მეტი წყვილის შემთხვევაში, მისი ჩანაწერები არ ემატება `summary` და `summary.uniqueModels` ითვლის ყველა ჩაწერილი მოდელის მართლწერას. `byModelTruncated` არის ჭეშმარიტი და მოდელი, რომლის წყვილი ხვდება ჭრილის ორივე მხარეს, აჩვენებს ნაწილობრივ ჯამებს.
- ორი ხარჯია მოხსენებული. `costUsd` არის დარიცხული ღირებულება, როგორც ამას გამოყენების ანალიტიკა აჩვენებს. ფიქსირებული სააბონენტო პროვაიდერები, როგორიცაა Claude Code გეგმა, ითვლის $0-ს. `listPriceUsd` არის იგივე გამოყენება, რომელიც ფასდება სიის ფასში, გამოწერებში შედის. მოთხოვნა, რომლის მოდელს არ აქვს ფასის მწკრივი, ითვლის მის შენახულ ღირებულებას: ღირებულებას, რომელსაც პროვაიდერი აცნობებს, ან ის, რომელიც გამოითვლება მოთხოვნის ჩაწერისას. მხოლოდ მოთხოვნა არცერთის გარეშე არ ითვლის 0-ს, მარკერის გარეშე, ასე რომ მთლიანი შეიძლება იყოს ნაწილობრივი.
- საპასუხო ხელშეკრულება არის `src/shared/schemas/selfUsage.ts` (`SelfUsageSeries` in `docs/openapi.yaml`).

### თვითმომსახურების გვერდი

`QUOTA_SELF_PANEL` ჩართულით, `/quota/{provider}` არის საჯარო გვერდი. გასაღების მფლობელი იქ აკრიფებს API კლავიშს და ხედავს ამ გასაღების აუზებს პროვაიდერისთვის. თითოეული აუზი აჩვენებს ერთ ბარათს თითო აუზის ფანჯარაში, აუზის გამოყენება ყველასთვის და გასაღების საკუთარი წილი. აუზის თითოეულ ანგარიშს აქვს საკუთარი ბარათები, ანგარიშის გამოყენებით და გასაღების წილით. ანგარიშის გამოყენება გამოჩნდება მხოლოდ მაშინ, როდესაც კლავიშს შეუძლია ანგარიშის მონაცემების ნახვა. გვერდზე ასევე ჩამოთვლილია თითოეული ანგარიშის თითო მოდელის ლიმიტები და გასაღების საკუთარი გამოყენება. შეტყობინება გამოჩნდება, როდესაც განრიგი ბლოკავს გასაღებს ახლავე. ბარათში ჩამოთვლილია გასაღების თითოეული მოდელის ქუდი მისი გამოყენებისას და აღნიშნავს მიღწეულს. `{provider}` არის პროვაიდერის id ან მისი მეტსახელი (`/quota/claude`, `/quota/cc`). უცნობი პროვაიდერი და ყველა `/quota/*` ბილიკი, სანამ დროშა გამორთულია, უპასუხეთ 404. მორგებულ OpenAI- ან Anthropic-თან თავსებად კვანძებს არ აქვთ გვერდი. API მაინც პასუხობს მათთვის.

გვერდს არ აქვს სესია. გასაღები იგზავნება მხოლოდ `Authorization` სათაურში `GET /api/v1/me/quota/{provider}`, `PATCH /api/v1/me/quota/{provider}` და `GET /api/v1/me/usage`, არასდროს URL. გასაღები, რომელსაც სერვერი იღებს, ინახება ჩანართში `sessionStorage`. „დაიმახსოვრე ამ მოწყობილობაზე“ ის სანაცვლოდ ინახება `localStorage` ში და „გასაღების დავიწყება“ აშორებს მას ორივედან. გასაღები, რომელსაც სერვერი უარყოფს, ამოღებულია მეხსიერებიდან.

აუზი `consent` რეჟიმში აჩვენებს საკრედიტო ბარათს. იქ გასაღების მფლობელი ადგენს გასასესხებლად გასაღების უმოქმედო წილის 0-დან 100-მდე მთელ პროცენტს. მფლობელი ასევე ირჩევს, რამდენ ხანს გაგრძელდება თანხმობა: გამორთვამდე, 1 საათი, 8 საათი, 24 საათი, 7 დღე ან 30 დღე. ხანგრძლივობა ითვლის შენახვის მომენტიდან. სანამ ვადა ძალაშია, მფლობელს შეუძლია შეინახოს იგი. თუ ეს ვადა გადის Save-მდე, ბარათი არაფერს აგზავნის და ითხოვს სხვა არჩევანს. 0%-ით ვადა არ იგზავნება. ბარათზე ნაჩვენებია შენახული ვადა მისი დროის ზონის დასახელებით. თანხმობა, რომლის ვადა გავიდა, ნაჩვენებია როგორც დასრულებული.

`hard` გასაღებისთვის ბარათში ასევე ჩამოთვლილია, თითო აუზის ფანჯრისთვის, თუ რა სხვა გასაღებებს აძლევს გასაღებს ახლავე. თითოეული მწკრივი არის ერთი ფიგურა ყველა სხვა გასაღებისთვის ერთად. ორი გასაღების აუზში ეს არის მეორე გასაღების საკუთარი ფიგურა. ფიგურა, რომელსაც ხედი არ აცნობს, იკითხება როგორც მიუწვდომელი და არა როგორც ნული. `soft` ან `burst` გასაღებისთვის ბარათში ნათქვამია, რომ არანაირი ფიგურა არ ვრცელდება.

აუზი `saturation` რეჟიმში, რომლის გასაღები ინახავს პროცენტს 0-ზე ზემოთ, აჩვენებს მხოლოდ ამოღებას. ნათქვამია, რომ შენახულ პროცენტს იქ არანაირი ეფექტი არ აქვს. მისი ამოღების ღილაკი აგზავნის 0-ს ვადის გარეშე. აუზი `saturation` რეჟიმში შენახული 0-ით არ აჩვენებს საკრედიტო ბარათს. შენახვის შემდეგ, ბარათი, რომელიც დაბრუნებულ ხედს აღარ სჭირდება, რჩება მის შეტყობინებაში, სანამ გვერდის ხედი კვლავ არ შეიცვლება.

არაფერი შეინახება მანამ, სანამ მფლობელი არ დააჭერს შენახვას ან ამოღებას. თითოეული პრესა აგზავნის ერთ `PATCH /api/v1/me/quota/{provider}` მოთხოვნას, ხოლო მეორე პრესა არაფერს აგზავნის, სანამ პირველი მოლოდინშია. სხეული ატარებს აუზის გაუმჭვირვალე `ref` ხედიდან, პროცენტიდან და ბოლო ვადით. პასუხი არის აღდგენილი კვოტის ხედი და გვერდი აჩვენებს მას მეორე წაკითხვის გარეშე. როდესაც ორი შენახვა ერთმანეთს ემთხვევა, გვერდი კითხულობს კვოტას ერთხელ ბოლო პასუხის შემდეგ. გვერდი არ ინახავს თანხმობას ბრაუზერის საცავში.

უარყოფილი ცვლილება ბარათზე აიხსნება HTTP სტატუსიდან არჩეული ტექსტით. შეცდომის სხეული არ იკითხება. 401 ამბობს, რომ გასაღები არ იქნა მიღებული და გადატვირთავს კვოტას. 403 ამბობს, რომ აუზი არ იღებს სესხის ცვლილებებს, ხოლო 404 ამბობს, რომ აუზი გაქრა. ორივე გთავაზობთ ღილაკს, რომელიც განაახლებს კვოტას. 400 ან სხვა 4xx პასუხი მფლობელს სთხოვს შეამოწმოს პროცენტი და ვადა. 429 სთხოვს მფლობელს დაელოდოს, `Retry-After` ის წამებით, როდესაც მათ პასუხს გასცემს. 5xx პასუხი, 408 ან ქსელის გაუმართაობა ამბობს, რომ ცვლილება შეიძლება არ იყო შენახული და ინახავს აკრეფილ მნიშვნელობებს. ხელშეკრულების მიღმა პასუხი განაახლებს კვოტას. წარუმატებელი შენახვა თავისთავად არ ხსნის გასაღებს. როდესაც გადატვირთვაზე უარის თქმის შემდეგ, გვერდი ხსნის გასაღებს, როგორც ნებისმიერ უარყოფილ კითხვაზე.

გასაღების მიღების შემდეგ, გვერდი ასევე აჩვენებს ბარათს "Set up your tools" სამი ჩანართი. "Claude Code" იძლევა `env` ბლოკს `~/.claude/settings.json` სთვის. "Shell" იძლევა იგივე ცვლადებს, როგორც `export` ხაზები. "Claude Desktop" იძლევა მნიშვნელობებს მისი მესამე მხარის დასკვნის ფანჯრისთვის. მოდელები არის კვოტების გაზიარების მოდელები, რომლებსაც გასაღები შეიძლება მოუწოდოს ამ პროვაიდერს. როდესაც ასეთი სია არ მოჰყვება გასაღებს, ბლოკი ჩართავს კარიბჭის მოდელის აღმოჩენას. კარიბჭის მისამართი არის საჯარო API წარმოშობა, რომელსაც სერვერი იტყობინება (`OMNIROUTE_PUBLIC_API_BASE_URL`, შემდეგ `OMNIROUTE_PUBLIC_BASE_URL`). როდესაც არცერთი არ არის დაყენებული, ბარათი აჩვენებს ადგილსამყოფელს და ეუბნება მფლობელს, რომ სთხოვოს ადმინისტრატორს. გასაღები ნაჩვენებია როგორც ჩანაცვლების ადგილი. "Include my key" ათავსებს მთელ კლავიშს ეკრანზე ტექსტში და რასაც კოპირების ღილაკი კოპირებს. ეს გრძელდება მანამ, სანამ ყუთი არ გასუფთავდება, გასაღები დაივიწყება ან შეიცვლება, ან გვერდი დარჩება. ბარათი არ აგზავნის მოთხოვნას და არ გვთავაზობს ფაილის ჩამოტვირთვას.

API ნიშნის `stale` კითხვა ნაჩვენებია, როგორც შესაძლოა მოძველებული. წაკითხვა, რომელიც აღნიშნავს `unavailable`, ნაჩვენებია მიზეზით, არასდროს ნულის სახით.

პროცენტულ გეგმებზე გვერდი ამახვილებს გასაღების საკუთარ წილს, როდესაც API იტყობინება. ნათქვამია, რომ რიცხვი არის სავარაუდო და ასახელებს მის ორ ნაწილს. თითო მოდელის ლიმიტები აჩვენებს მხოლოდ ანგარიშს.

როდესაც ფანჯარა ატარებს `members`, მის ბარათზე ასევე ნაჩვენებია ზოლი თითო სეგმენტით თითოეულ წევრზე, სლოტის თანმიმდევრობით. კითხვის გასაღების სეგმენტი იყენებს აქცენტის ფერს. სხვა სეგმენტები მოძრაობენ თემის დიაგრამის ფერებში. ტექსტის ლეგენდა ჩამოთვლის ყველა სეგმენტს თავისი მნიშვნელობით, ასე რომ არაფერია დამოკიდებული ფერზე. სეგმენტებს აწერია `You` ან `Member N`, სადაც N არის სლოტი.

### გამოყოფილი პორტი გვერდისთვის

`QUOTA_PANEL_PORT` ხსნის მეორე მსმენელს, რომელიც ემსახურება მხოლოდ თვითმომსახურების გვერდს. ის გამორთულია, თუ ცვლადი არ არის დაყენებული. `QUOTA_PANEL_HOST` არის bind მისამართი და ნაგულისხმევია `127.0.0.1`.

მსმენელი გადასცემს ამ ბილიკებს მთავარ პორტამდე და პასუხობს 404-ს ყველა სხვა ბილიკისთვის:

| ბილიკი                                                                   | ემსახურება                                      |
| ------------------------------------------------------------------------ | ----------------------------------------------- |
| `/quota/{provider}`                                                      | გვერდი                                          |
| `/api/v1/me/quota/{provider}`, `/v1/me/quota/{provider}`                 | კვოტის ხედვა კითხულობს გვერდზე                  |
| `/api/v1/me/usage`, `/v1/me/usage`                                       | გამოყენების სერიები, რომელსაც გვერდზე კითხულობს |
| `/_next/static/`                                                         | აგების სკრიპტები, სტილები და შრიფტები           |
| `/favicon.ico`, `/favicon.svg`, `/icon-512.png`, `/apple-touch-icon.png` | ხატები                                          |

`GET` და `HEAD` გადაცემულია სხეულის გარეშე. ასევე გადაცემულია სხეულის ერთი მოთხოვნა: კვოტის ნახვის ბილიკის `PATCH`, რომელსაც გვერდი აგზავნის დაკრედიტების არჩევანის შესანახად. ნებისმიერი სხვა მეთოდი პასუხობს 404-ს, გარდა CONNECT მოთხოვნისა, რომლის კავშირი დახურულია პასუხის გარეშე. ნებისმიერი სხვა მოთხოვნა, რომელიც აცხადებს ორგანოს პასუხობს 404 და მისი კავშირი დახურულია. განახლების მოთხოვნა უარყოფილია და მათი კავშირი დახურულია. წერტილოვანი სეგმენტის ან ფრაგმენტის მარკერის მქონე გზაზე უარი თქვას, როგორც API პორტზე. ასეა მოთხოვნის სამიზნე სიმბოლოს გარეთ დასაბეჭდად ASCII. სამიზნის ნედლეულ საკონტროლო სიმბოლოს HTTP პარსერერი პასუხობს 400-ით, ამ პორტის საკუთარი შემოწმებამდე. მოითხოვეთ სათაურები, რომლებსაც ფრეიმორკი ინახავს საკუთარი გამოყენებისთვის, არ არის გადაცემული: სახელები, რომლებიც იწყება `x-middleware-`, `x-invoke-`, `x-nextjs-`, `x-now-` ან `x-next-`, და სახელები `x-matched-path` და `next-resume`. მოთხოვნა გადაცემულია მათ გარეშე. დაფის, შესვლის გვერდის, მართვის API და დასკვნის მარშრუტების მიღწევა შეუძლებელია ამ პორტის მეშვეობით.

`PATCH` უნდა იყოს `Content-Type: application/json`, პარამეტრის გარეშე ან მხოლოდ `charset=utf-8` ით. მას უნდა ჰქონდეს ერთი `Content-Length` 1-დან 4096-მდე, დაწერილი ჩვეულებრივი ციფრებით და არა `Transfer-Encoding`. `PATCH` რომელიც არღვევს ერთ-ერთ ამ წესს, პასუხობს 404-ს. ზოგიერთი არასწორად ფორმირებული სიგრძე, როგორიცაა ხელმოწერილი ან განმეორებითი, HTTP პარსერზე პასუხობს 400-ით ამ პორტის საკუთარ შემოწმებამდე. პორტი კითხულობს დეკლარირებულ ბაიტებს, სანამ დაუკავშირდება მთავარ პორტს და ელოდება მათ მაქსიმუმ 5 წამს. სხეული, რომელიც არ არის დასრულებული, პასუხობს 404-ს და მისი კავშირი დახურულია. არაფერი აღწევს მთავარ პორტს იმ შემთხვევაში, ან როცა კლიენტი პირველი ტოვებს. პორტი გადასცემს ზუსტად დეკლარირებულ ბაიტებს, იგივე `Content-Length`. მათ შემდეგ ბაიტები იკითხება, როგორც შემდეგი მოთხოვნა კავშირის შესახებ. TLS საპირისპირო პროქსი წინ უნდა გადააგზავნოს `Content-Length` და არ უნდა ხელახლა დაშალოს მოთხოვნის სხეული. მთავარი პორტი ამოწმებს API კლავიშს `Authorization` სათაურში, რაც შეეხება `GET` ს.

404 სხეული არის `{"error":"not_found","message":"Not found."}`. წარუმატებელი რელე პასუხობს 502 (`api_bridge_unavailable`) ან 504 (`api_bridge_timeout`) `detail` ველის გარეშე.

მსმენელი არ კითხულობს `QUOTA_SELF_PANEL` და არ აბრუნებს გვერდს. სანამ დროშა გამორთულია, გვერდი და მისი API პასუხობენ 404-ს მთავარ პორტზე და მსმენელი გადასცემს ამ პასუხს.

განვითარების სერვერზე (`next dev`) გვერდი არ ხდება ინტერაქტიული ამ პორტის მეშვეობით. განვითარების ცხელი გადატვირთვის სოკეტი არის განახლების მოთხოვნა და პორტი მასზე უარს ამბობს. გამოიყენეთ მთავარი პორტი განვითარებისას.

პორტი ემსახურება უბრალო HTTP და გვერდი აგზავნის API კლავიშებს. შეინახეთ ნაგულისხმევი bind მისამართი და ჩადეთ საპირისპირო პროქსი TLS ით მის წინ. Bind მისამართი, გარდა loopback-ისა, აღრიცხავს ამ შეტყობინებას:

```text
[Quota Panel] Bound to <host>. This port serves plain HTTP and the page sends API keys. Put a TLS reverse proxy in front of it.
```

loopback peer, რომელიც არ აგზავნის გადამისამართების სათაურს, ითვლება ლოკალურად მთავარ პორტში. ასე რომ, იმავე ჰოსტის პროქსიმ უნდა გამოაგზავნოს `X-Forwarded-For`. პირადი მისამართის პროქსი სანდოა ამ სათაურისთვის მხოლოდ `OMNIROUTE_TRUST_PROXY=private` (ან `lan`). ნებისმიერი სხვა თანატოლი იტყობინება მისი კავშირის მისამართით და მის მიერ გაგზავნილი გადამისამართების სათაურები იშლება.

მსმენელი ერთდროულად ფლობს მაქსიმუმ 256 კავშირს. კლიენტს აქვს 10 წამი მოთხოვნის სათაურების გასაგზავნად და 30 წამი მთელი მოთხოვნის გასაგზავნად. უმოქმედო შენახული კავშირი იხურება დაახლოებით 5 წამის შემდეგ. კავშირი 60 წამის განმავლობაში აქტივობის გარეშე დახურულია. ეს მნიშვნელობები ფიქსირდება. დააყენეთ კავშირი და განაკვეთის ლიმიტები წინა საპირისპირო პროქსიზეც. წინა პროქსიმ უნდა შეინარჩუნოს უმოქმედო კავშირები 5 წამზე ნაკლები ხნის განმავლობაში, ან არ გამოიყენოს ისინი. მთავარი პორტის რელე იყენებს API პორტის (`API_BRIDGE_*`) ზედა დინების ვადებს.

მსმენელი ასევე იწყებს მუშაობას, როდესაც `API_PORT` არ არის დაყენებული. `QUOTA_PANEL_PORT` უნდა იყოს პორტი 1-დან 65535-მდე, დაწერილი მხოლოდ ციფრებით. ის უნდა განსხვავდებოდეს დაფის პორტისა და API პორტისგან. სანამ ცოცხალი WebSocket სერვერი ჩართულია, ის ასევე უნდა განსხვავდებოდეს `LIVE_WS_PORT` სგან (ნაგულისხმევი 20132). ნებისმიერი სხვა მნიშვნელობა არაფერს ხსნის და იწერს გაფრთხილებას. გაფრთხილება უარყოფილი მნიშვნელობის შესახებ ასახელებს ცვლადს და არ იმეორებს მნიშვნელობას. პორტი, რომელიც უკვე გამოიყენება, არაფერს ხსნის და აღრიცხავს ამ გაფრთხილებას:

```text
[Quota Panel] Port <port> is already in use. The quota panel port stays off.
```

`OMNIROUTE_BASE_PATH` კომპლექტით, მსმენელი ელის ზემოთ მოცემულ ყველა გზას ამ პრეფიქსის ქვეშ. გამოიყენეთ იგივე `OMNIROUTE_BASE_PATH` აშენების დროს და გაშვების დროს. ჩაწერეთ ის წინა ხაზებით და უკიდეგანოდ, მაგალითად `/omniroute`. სხვა ფორმა, მათ შორის `/` და `/omniroute/`, ტოვებს პორტს გაფრთხილებით, თუმცა build იღებს ამ ფორმებს. ასე მოქმედებს საბაზისო გზა, რომლის პირველი სეგმენტი ასახელებს განაცხადის მარშრუტს: `api`, `v1`, `v1beta`, `_next`, `quota`, `dashboard`, `docs`, `login`, `codex`, `responses`, `anthropic`, `openai`, `v0` ან `connect`, ნებისმიერ შემთხვევაში.

შეზღუდვები:

- `/quota/{provider}/` ბოლო ხაზით პასუხობს 404-ს ამ პორტზე.
- სერვისის მუშაკი და ვებ აპლიკაციის მანიფესტი არ ემსახურება ამ პორტს.
- დაფაზე მორგებული ფავიკონი არ არის ნაჩვენები ამ პორტზე.
- ხატები არ არის ნაჩვენები, როდესაც აპლიკაცია მუშაობს საბაზისო ბილიკზე.
- პორტში ლაპარაკობენ უბრალო HTTP/1.1.
- დაკავშირება, რომელიც ვერ ხერხდება, არ განმეორდება პროცესის ხელახლა დაწყებამდე.
- მსმენელს არ აქვს კავშირი ან განაკვეთის ლიმიტი კლიენტის მისამართზე.
- კონტეინერის დაყენება არ ვრცელდება ამ განყოფილებაში.

## პრობლემების მოგვარება

### Redis კონფიგურირებულია, მაგრამ კავშირი არ მყარდება

შეამოწმეთ, რომ `ioredis` დაყენებულია (`npm ls ioredis`) და `QUOTA_STORE_REDIS_URL`
ხელმისაწვდომია. კავშირის შეცდომის შემთხვევაში ფაბრიკა SQLite-ზე გადაერთვება (ლოგირდება
`warn` დონეზე).

### `peek` მოძველებულ შედეგს აბრუნებს / შეცდომისას ღიად მუშაობს

თუ `peek` გამონაკლისს აგდებს, `enforceQuotaShare` შედეგს განიხილავს როგორც „დაშვებას“ (შეცდომისას ღია რეჟიმი).
ძირითადი მიზეზის დასადგენად `pino`-ს ლოგებში შეამოწმეთ `quota:enforce` და `quota:factory`
ჩანაწერები.

### მოხმარების მრიცხველის აცდენა

თუ პროვაიდერის ფაქტობრივი გამოყენება მრიცხველებისგან განსხვავდება, ეს მოსალოდნელია —
2-კალათიანი მოძრავი ფანჯრის ცდომილება ფანჯრის საზღვრებთან ~1%-ია, ხოლო `consume`
პასუხის შემდეგ „გაუშვი და დაივიწყე“ პრინციპით სრულდება. გაჯერების სიგნალი (`saturationSignals.ts`)
კითხულობს პროვაიდერის რეალურ დატვირთვას 30-წამიანი TTL-ით და შესაბამისად არეგულირებს `globalUsedPercent`-ს.

### პული ხარჯვის სიჩქარისთვის „მონაცემები არ არის“-ს აჩვენებს

`computeBurnRate`-ს სულ მცირე 2 ისტორიული ნიმუში სჭირდება. ახალი პულები, რომლებზეც მანამდე
`consume` არ გამოძახებულა, აჩვენებენ `tokensPerSecond: 0`-სა და `timeToExhaustionMs: null`-ს.

## DB სქემის შეჯამება

სამი ცხრილი დამატებულია მიგრაციებით `078`, `079` და `085`:

- `quota_pools` + `quota_allocations` — აუზის განმარტებები და თითო გასაღების გამოყოფა.
- `quota_consumption` — მოძრავი 2-ვედრო მრიცხველები თითო `(apiKeyId, dimensionKey)`.
- `provider_plans` — პროვაიდერის სახელმძღვანელო გეგმა უგულებელყოფს (ზომები JSON თითო connectionId).

ყველა ცხრილი დამატებულია idempotent `CREATE TABLE IF NOT EXISTS` მიგრაციის საშუალებით.

თანხმობით დაკრედიტება ამატებს სამ სვეტს: `quota_allocations.lending_percent` (მთელი რიცხვი, ნაგულისხმევი 0), `quota_allocations.lending_until` (ეპოქის მილიწამები, ან `NULL` ვადის გარეშე) და `quota_pools.borrow_mode` (ნაგულისხმევი `saturation`). მისი მიგრაცია მხოლოდ ამატებს ამ სვეტებს და არ წერს არსებულ მწკრივს.

პროცენტული ატრიბუციის წიგნი ამატებს `quota_percent_ledger` (ერთი მწკრივი თითო აუზზე, ანგარიშზე და გეგმის ფანჯარაში) და `quota_percent_ledger_tokens` (ერთი ჟეტონის მრიცხველი თითო აუზზე, ანგარიშზე და API კლავიშზე). `src/lib/db/quotaPercentLedger.ts` კითხულობს და წერს მათ.
