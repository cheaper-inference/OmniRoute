`copilot-m365-web` (ასევე `m365copilot`) აგზავნის OpenAI ფორმატის ჩატის მოთხოვნებს ავთენტიფიცირებული Microsoft 365 Copilot სესიის მეშვეობით `m365.cloud.microsoft/chat`. ეს არის არაოფიციალური მშობლიური ინტეგრაცია: არ არის საჭირო ცალკეული პროქსი პროცესი ან ლოკალური ჰოსტი ზემოთ. პროვაიდერი ID, მეტსახელი და არსებული იმპორტირებული კავშირები უცვლელია. `copilot-web` არის სხვა პროვაიდერი მომხმარებლის მომსახურებისთვის `copilot.microsoft.com` ზე.

> **ახალი ხართ ვებ ქუქიების პროვაიდერებთან?**
>
> წაიკითხეთ**`docs/getting-started/WEB-COOKIE-GUIDE.md`** ზოგადი დაყენების პროცესისთვის, ავთენტიფიკაციის სახელმძღვანელოსთვის, შეზღუდვებისა და პრობლემების გადასაჭრელად, სანამ მიჰყვებით ამ პროვაიდერის სპეციფიკურ სახელმძღვანელოს.
>
> **მოძველებული იმპორტისთვის:** ამ პროვაიდერის სერთიფიკატი არის** არა ქუქი** . არ დააკოპიროთ ქუქიები `m365.cloud.microsoft` დან. სერთიფიკატი არის WebSocket URL მოთხოვნის პარამეტრი და ბილიკის სეგმენტი, ორივე წაკითხული DevTools ქსელის ჩანართიდან.

## წინაპირობები

- Microsoft 365 ანგარიში Copilot ზე წვდომით `m365.cloud.microsoft/chat` ზე
- Chromium-ზე დაფუძნებული ბრაუზერი (Chrome, Edge) DevTools WebSocket შემოწმებისთვის
- წვდომა მოთხოვნილ მოდელზე ამ ანგარიშზე; ხელმისაწვდომობა განსხვავდება მოიჯარისა და ლიცენზიის მიხედვით

## მშობლიური შესვლა (სამსახურის ან სკოლის ანგარიშები)

აირჩიეთ**Microsoft 365 Copilot → დაკავშირება** და მოამზადეთ შესვლის მცდელობა. დაფა იყენებს ავტორიზაციის კოდის ნაკადს PKCE ით; ის არ ითხოვს თქვენს Microsoft პაროლს ან MFA კოდს.

1. გახსენით ა** ბრაუზერის ცარიელი ჩანართი** , შემდეგ გახსენით**DevTools → ქსელი** და ჩართეთ** ჟურნალის შენახვა** . გააკეთეთ ეს Microsoft ზე ნავიგაციამდე: Windows SSO შეიძლება დაუყოვნებლივ დასრულდეს.
2. დააკოპირეთ ავტორიზაციის URL რომელიც ნაჩვენებია კავშირის დიალოგში და გადადით მასზე მომზადებულ ჩანართში. შეავსეთ Microsoft ის ანგარიშის შერჩევა ან MFA მოთხოვნის შემთხვევაში.
3. ქსელის შენახულ ჟურნალში იპოვეთ მოთხოვნა `https://login.microsoftonline.com/common/oauth2/nativeclient` ზე და დააკოპირეთ მისი სრული ვერსია** მოითხოვეთ URL** .
4. ჩასვით ეს URL კავშირის დიალოგში და დააკავშირეთ. არ ჩასვათ ნედლეული კოდი ან საბოლოო `wrongplace` მისამართების ზოლი URL: საჭირო გამოძახება არის გარდამავალი ნავიგაცია.

ყოველი მცდელობა იწურება ათი წუთის შემდეგ და შეიძლება გამოყენებულ იქნას მხოლოდ ერთხელ. კოდის გაცვლამდე სერვერი ამოწმებს მის მდგომარეობას, PKCE შემმოწმებელს და ხელახალი ავტორიზაციის სამიზნეს. ვადის გასვლის ან გაცვლის წარუმატებლობის შემდეგ, დაიწყეთ ახალი მცდელობა. მცდელობა ვერ გადარჩება სერვერის გადატვირთვაზე.

ჟეტონები იყენებენ არსებული კავშირის სერთიფიკატების შესანახს და განახლების გზას. კავშირის ხელახალი ავტორიზაცია მოითხოვს იგივე Microsoft tenant/object იდენტურობას და არა მხოლოდ იმავე ელფოსტას. ის ინახავს ოპერატორს naming/settings და ცვლის მოძველებულ იმპორტირებულ სერთიფიკატებს. მშობლიური შესვლა არის work/school ანგარიშებისთვის; მოძველებული იმპორტის გზა ხელმისაწვდომი რჩება არსებული კავშირებისთვის და მხარდაჭერილი დონის კონფიგურაციებისთვის.

სრული გამოძახება URL არის ერთჯერადი ავტორიზაცია. არასოდეს შეიტანოთ ის ეკრანის სურათებში, ჟურნალებში, მხარდაჭერის შეტყობინებებში ან ვალდებულებებში. ეს ნაკადი არ ხსნის ბრაუზერს სერვერზე, არ ამოწმებს თქვენი ბრაუზერის ისტორიას და არ იწყებს ლოკალური გამოძახების სერვერს.

## რწმუნებათა სიგელის აღება (WebSocket მეთოდი)

1. შედით `https://m365.cloud.microsoft/chat` ში და დაიწყეთ საუბარი.
2. გახსენით**DevTools → ქსელი** .
3. გაფილტვრა**WS** (WebSocket).
4. დააჭირეთ Chathub WebSocket კავშირს. მოძებნეთ URL რომელიც იწყება `wss://substrate.office.com/m365Copilot/Chathub/` ით.
5. მისი** მოითხოვეთ URL** , დააკოპირეთ:
   - `access_token` მოთხოვნის პარამეტრის მნიშვნელობა (მოკლევადიანი JWT).
   - Chathub ბილიკის სეგმენტი `/Chathub/` შემდეგ (მაგ. `<oid>@<tenant>`).

სრულ URL აქვს ფორმა:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute ში აირჩიეთ**Microsoft 365 Copilot** აირჩიეთ legacy API-key/import ვარიანტი და ჩასვით რწმუნებათა სიგელები ფორმატში:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. დააწკაპუნეთ** ტესტი კავშირი** და** შენახვა** .

## სერთიფიკატის აღება (HAR იმპორტი)

იმის ნაცვლად, რომ ხელით დააკოპიროთ მნიშვნელობები WebSocket URL დან, შეგიძლიათ DevTools HAR ფაილის ექსპორტი:

1. გახსენით**DevTools → ქსელი** .
2. დაიწყეთ ან გააგრძელეთ Microsoft 365 Copilot საუბარი (ეს იწვევს WebSocket კავშირს).
3. დააწკაპუნეთ მარჯვენა ღილაკით ქსელის პანელზე და აირჩიეთ** შეინახეთ ყველაფერი, როგორც HAR შინაარსით** .
4. OmniRoute ში გამოიყენეთ** .har ფაილის იმპორტი** ღილაკი პროვაიდერის კავშირის დიალოგზე.

OmniRoute სკანირებს HAR Chathub WebSocket URL სთვის, ამოიღებს `access_token` და `chathubPath` და ავტომატურად ავსებს რწმუნებათა სიგელების ველებს. HAR იმპორტი დეკოდირებს JWT ვადის გასვლას და აჩვენებს ტოკენის დარჩენილ სიცოცხლეს.

> **არასოდეს ჩაიდინოთ რეალური HAR ექსპორტი, წვდომის ნიშანი ან განახლების ნიშანი.** ტესტისა და დოკუმენტაციის მნიშვნელობები ყოველთვის უნდა იყოს ჩანაცვლების ადგილი.

## სიმბოლოს სიცოცხლე და განახლება

`access_token` ხანმოკლეა (ჩვეულებრივ**~ 75 წუთი** ). გამოსაყენებელი განახლების ჟეტონის გარეშე, თქვენ ხელახლა უნდა აიღოთ რწმუნებათა სიგელები ვადის გასვლის შემდეგ.

### ავტომატური განახლება `refreshToken` ით

Microsoft 365 პროვაიდერში** კავშირის დამატება** ან** კავშირის რედაქტირება** დიალოგი, გახსნა** გაფართოებული პარამეტრები → განახლების ჟეტონი (სურვილისამებრ)** . ჩასვით Microsoft OAuth განახლების ჟეტონი `substrate.office.com/sydney` სკოპისთვის და შეინახეთ. შეყვანა არის ნიღბიანი და არასოდეს ივსება წინასწარ შენახული ჟეტონით. რედაქტირებისას დატოვეთ ის ცარიელი, რომ შეინახოთ არსებული ჟეტონი; ჩასვით ახალი ჟეტონი მის ჩასანაცვლებლად.

მშობლიური შესვლა იძენს განახლების ჟეტონს, როდესაც Microsoft დააბრუნებს ერთს. ძველი იმპორტისთვის გამოიყენეთ არსებული თავსებადი Microsoft ავტორიზაციის კოდის გრანტი; ეს პროვაიდერი არ ახორციელებს და არ გვპირდება მოწყობილობის კოდის ნაკადს. კონფიგურირებული განახლების ჟეტონით, OmniRoute ამოწმებს `access_token` მოთხოვნამდე და განაახლებს მას მხოლოდ მაშინ, როცა მას განახლება სჭირდება. წარმატებული განახლება ასევე აგრძელებს შემობრუნებულ განახლების ჟეტონს, თავიდან აიცილებს ხელით ხელახლა აღებას, სანამ განახლების ჟეტონი მოქმედებს.

თუ `refreshToken` არ არის დაყენებული, თქვენ ხელახლა უნდა აიღოთ WebSocket სერთიფიკატი ხელით ყოველი ვადის გასვლის შემდეგ.

### იარუსის შერჩევა

| იარუსი       | მეტსახელი        | ზედაპირი                   |
| ------------ | ---------------- | -------------------------- |
| `individual` | _(ნაგულისხმევი)_ | სამომხმარებლო M365 Copilot |
| `edu`        | `included`       | განათლება M365 Copilot     |
| `enterprise` | `work`           | M365 Copilot სამუშაოსთვის  |

დააყენეთ იარუსი** გაფართოებული პარამეტრები → Copilot იარუსი** . მშობლიური შესვლა მას არ აყენებს, ამიტომ სამუშაო ანგარიშმა უნდა შეარჩიოს `enterprise` (ასევე `work`) და განათლების ანგარიში `edu`, ასევე დოკუმენტირებული მოდელის IDs გამოყენებისას: ისინი ირჩევენ საკუთარ ტონს, სცენარს და ლიცენზიის ტიპს, მაგრამ აგენტის და მოწვევის ვარიანტები მაინც მოდის დონისგან, და ინდივიდუალური ნაგულისხმევი შეიძლება წარუმატებელი იყოს სამუშაო მოიჯარეზე. იარუსის შეცვლა არ იძლევა სამოდელო ლიცენზიას. გაფართოებული პროტოკოლის აშკარა უგულებელყოფა უპირატესობას ანიჭებს და უნდა იქნას გამოყენებული მხოლოდ მაშინ, როდესაც იცით მავთულის საჭირო მნიშვნელობები.

## მოდელები და მარშრუტიზაცია

მშობლიურ კატალოგში შედის ყველა დოკუმენტირებული დამოუკიდებელი IDs პლუს ოთხი ორიგინალური მშობლიური IDs. კატალოგი არის სტატიკური და ანგარიშზე დამოუკიდებელი და არა ანგარიშის უფლებამოსილების გამოკვლევა: ფასიანი მარშრუტები და თავსებადობის მეტსახელები რჩება ჩამოთვლილი მაშინაც კი, როდესაც დაკავშირებულ ანგარიშს არ შეუძლია მათი გამოყენება. მოდელის ჩვენების ეტიკეტები გამოტოვებს პროვაიდერის სახელს და თითო მოდელის ხელმისაწვდომობის ქვაბის ფირფიტას; პროვაიდერი რჩება**Microsoft 365 Copilot** . ეტიკეტები მონიშნულია** მეტსახელი** ან** მემკვიდრეობა** ინარჩუნებენ არსებულ იდენტიფიკატორებს და პროტოკოლის რუკებს და არა ისტორიული მოდელის ვერსიის გარანტიას. დამოუკიდებელი პროქსი** იმპორტი / მოდელებიდან** ინსტრუქციები არ ვრცელდება ამ მშობლიურ WebSocket პროვაიდერზე.

| მოდელის ოჯახი     | კანონიკური IDs                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| ავტომატური        | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| ადრე GPT          | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude სონეტი     | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude Opus       | `claude-opus`, `claude-opus-4.8`                                                                 |

ასევე რეგისტრირებულია მეტსახელები, როგორიცაა `auto`, `quick`, `think-deeper` და ვერსიის მეტსახელები. არსებული `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` და `copilot-m365-gpt-5-5-chat` ძალაში რჩება. დოკუმენტურ IDs სჭირდება პროვაიდერის პრეფიქსი (`copilot-m365-web/claude-opus` ან `m365copilot/claude-opus`): ბევრი არის ზოგადი სიტყვები ან სხვა მომწოდებლების მოდელის სახელები, ამიტომ შიშველი `claude-opus` აგრძელებს მარშრუტიზაციას, როგორც ამას აკეთებს ამ პროვაიდერის გარეშე. რეგისტრაცია არ არის დაპირება, რომ Microsoft ემსახურება ამ მოდელს ყველა ანგარიშზე. დამოუკიდებელი IDs მიჰყვება საჯარო [პროტოკოლის კატალოგს](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) (ექსპორტირებული მოდელიდან ტონამდე რუკა და მისი მოდელის შემეცნებითი სცენარის მეტამონაცემები). ყველა მშობლიური პროფილი ინარჩუნებს `availability: "unverified"`; კატალოგში ჩართვა არ არის წარმატებული ანგარიშის ტესტი.

- აშკარა მოდელის ლიცენზიის უარი ბრუნდება** 403** `m365_model_not_licensed`, არა 502. მარშრუტიზაცია ბლოკავს connection/model წყვილს, რის გამოც ლიცენზირებული მოდელები კავშირზე გამოსაყენებლად რჩება.
- `InvalidCopilotLicense` არის ანგარიშის დონის ლიცენზიის უარყოფა, ცალკე მოხსენებული, როგორც `m365_account_not_licensed`.
- თითო მომხმარებლის დროსელი ბრუნდება** 429** `m365_throttled` და აგრილებს კავშირს. პრიორიტეტული წვდომის ამოწურვა ბრუნდება** 429** `priority_access_exhausted` და მოდელირებულია. `OutOfCredits` ის შედეგი `errorCode: "ReasoningTurnExhausted"` დაბრუნებით** 429** `reasoning_turns_exhausted` სამაგიეროდ, ასევე მოდელის მასშტაბით, გადატვირთვის დროის მოთხოვნის გარეშე. მოხსენებული იქნა ერთ-ერთ სამუშაო მაცხოვრებელზე, რომ დახურა „უფრო ღრმად“ ტონები, სანამ სწრაფი ტონები ემსახურება; ეს სფერო არის მომხმარებლის დაკვირვება და არა ის, რაც ამ საცავმა გაამრავლა. ამიტომ, მარშრუტიზაცია ასევე აშორებს `gpt-5.5` და `gpt-5.6` სხვა დოკუმენტურ Think ღრმა მოდელებს ბრუნვისგან ამ კავშირზე იმავე გაგრილებისთვის და ტოვებს Quick ტონებს და ყველა სხვა წარუმატებლობას საკუთარ მოდელზე. მიწოდებული ხელახალი ცდის მინიშნებები დაცულია; დაკარგული გადატვირთვა არ არის რეკლამირებული, როგორც გადატვირთვის ცნობილი დრო.
- Copilot უსაფრთხოების უარი (`Disengaged`) ბრუნდება** 400** `provider_safety_rejection`, საერთო პროვაიდერის უსაფრთხოების გაჩერების ეტიკეტი. ის არასოდეს ითვლის კავშირის სიჯანსაღეს, კლიენტმა SDKs არ სცადო ხელახლა 400 და `PROVIDER_SAFETY_STOPS_TERMINAL` ჩართული კომბინირებული მარშრუტიზაცია ჩერდება იქ, ნაცვლად იმისა, რომ გაიმეოროს მოთხოვნა სხვა სამიზნეზე.
- მოთხოვნა ერთ კავშირზე სერიდება არსებული ანგარიშის სემაფორის მეშვეობით. უპირატესობა მიანიჭეთ პარალელურ პანელებს; მარტო სერიალიზაცია არ გამორიცხავს Microsoft ს საუბრის სიჩქარის შეზღუდვებს.

## მოითხოვეთ ქცევა და შეზღუდვები

- ინსტრუმენტები არის** სწრაფი-ემულირებული** , არა მშობლიური Microsoft ფუნქციის ზარები. ინსტრუმენტის ჩართული მოთხოვნა იყენებს ერთ ბუფერულ თაობას; ის არ ხარჯავს სხვა თაობას ხელსაწყოების შერჩევაში. მხოლოდ დეკლარირებული ხელსაწყოები მოქმედი მხარდაჭერილი არგუმენტების ფორმებით ბრუნდება გამოძახების სახით.
- გრძელი სტრუქტურირებული პასუხი ერთი ბოლო მაგალითით შენარჩუნებულია პროზაში. ეს არის ევრისტიკული და არა განზრახვის მტკიცებულება; აპლიკაციებმა მაინც უნდა განახორციელონ საკუთარი ხელსაწყოების ნებართვები.
- სურათის შეყვანა მუშაობს ისე, როგორც მას ვებ კლიენტი აგზავნის. სურათის თითოეული ნაწილი (`image_url`, როგორც მონაცემები URL ან საჯარო HTTPS URL, ან პასუხები `input_image`) აიტვირთება `/m365Copilot/UploadFile` ზე მონაცვლეობის საუბარში ჩატის ნიშნით და შეტყობინება მიუთითებს მასზე `ImageFile` ანოტაციით; ტექსტი აღნიშნავს სად იჯდა (`[image 1]`,…). ახალი საუბარი ატვირთავს ისტორიის ყველა სურათს, გაგრძელება მხოლოდ ახალი შეტყობინებების სურათებს. 10-მდე PNG, JPEG, GIF ან WebP სურათი მაქსიმუმ 10 MiB თითოეული (40 MiB თითო მოთხოვნაზე); ფორმატი იკითხება ბაიტებიდან. HTTPS URLs მიიღება მხოლოდ საჯარო, DNS-დამაგრებული დისტანციური გამოსახულების დაცვის საშუალებით. წარუმატებელი ატვირთვა ვერ აკმაყოფილებს მოთხოვნას (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` ან `m365_image_invalid`); ბრუნი არასოდეს მიდის წინ მის მიერ მოცემული იმიჯის გარეშე. სხვა არატექსტური ნაწილები (აუდიო, ფაილები) უარყოფილია ცალსახად და არა ჩუმად.
- შემდგომი მოთხოვნა აგრძელებს იმავე საუბარს და აგზავნის მხოლოდ შეტყობინებებს წინა პასუხის შემდეგ. მან ზუსტად უნდა გააფართოვოს ეს პასუხი: იგივე კავშირი, მოდელის პროფილი და ხელსაწყოების ნაკრები; უცვლელი ისტორია (sha256 ჯაჭვი ყველა შეტყობინებაზე); და პასუხის ხელსაწყოების ზარის ID, ან მისი ტექსტი თეთრ სივრცემდე. ნებისმიერი სხვა (რედაქტირებული ისტორია, მეორე სესია იგივე პირველი შეტყობინებით, განსხვავებული პასუხი, საუბარი უმოქმედო 30 წუთის განმავლობაში ან Copilot ს 600 მესიჯთან ახლოს, კავშირი ID-ის გარეშე) იწყებს ახალ საუბარს მთელ ისტორიასთან. წარუმატებელი შემობრუნება არასოდეს განახლდება და შინაარსის ნაკლებობა `InternalError` ხელახლა იგზავნება ერთხელ ახალ საუბარში (** 502** `m365_internal_error` თუ ის კვლავ ვერ მოხერხდა). გაგრძელება ინახება პროცესის მეხსიერებაში: გადატვირთვა იწყებს ახალ საუბრებს.
- ყოველი ტრიალი გადის Copilot ს დროებით ჩატში (`disableMemory=1`): საუბარი ინარჩუნებს კონტექსტს გაშვების დროს და არასოდეს გამოჩნდება ანგარიშის ჩატის ისტორიაში. მოდელის ტესტებმა, ყველა ტესტირებამ და კომბინირებულმა ტესტებმა შეიძლება გამოიკვლიონ ეს პროვაიდერი საუბრის დატოვების გარეშე.
- ბრუნს აქვს 120 წამი უმოქმედობის ვადა და შეზღუდული საერთო ვადა. მხოლოდ საბოლოო პასუხები, პროგრესის გაფილტვრა და გაუქმება განიხილება მშობლიური transport/composer. მიერ
- ვებ-დაფუძნებული პასუხები ინახავს მათ წყაროებს. Copilot აღნიშნავს ციტატას პირადი გამოყენების საკონტროლო სიმბოლოებით და აგზავნის წყაროებს, როგორც `references`; თითოეული მარკერი ხდება დანომრილი Markdown ბმული (`[1](https://…)`, ან შიშველი URL როდესაც Copilot მარკერს ბმულის სამიზნედ იყენებს) შესაბამისი `url_citation` ანოტაციით (`message.annotations`, ან `delta.annotations` ნაწილზე, რომელიც ატარებს ბმულს). წყარო, რომელიც არასოდეს მოდის, იშლება, ამიტომ მარკერები არასოდეს აღწევს კლიენტს. სტრიმინგის დროს, ტექსტი ციტირების შემდეგ ელოდება მის წყაროს მოსვლას.
- Copilot ს მსჯელობის შეჯამება (`ChainOfThoughtSummary`), როდესაც მოდელი აგზავნის ერთს, ბრუნდება როგორც `reasoning_content` და არასდროს, როგორც პასუხის ნაწილი. რეზიუმე, რომელიც ხელახლა იწერება, წყვეტს სტრიმინგს, ბრუნვის შეუფერხებლად.
- რაიმე კონტენტამდე, licence/throttle წარუმატებლობა ინარჩუნებს HTTP 403/429 ს მაშინაც კი, როცა სტრიმინგის მოთხოვნა იყო. კონტენტის დაწყების შემდეგ, წარუმატებლობები არის SSE შეცდომის მოვლენები, არასდროს წარმატებული დასრულება. ზემოთ ნაკადის გადაწერა, რომელიც არ შეიძლება იყოს წარმოდგენილი მხოლოდ დამატებული სტრიმინგით, არის ნაკადის აშკარა შეცდომა; არასტრიმინგი და ბუფერული ხელსაწყოს პასუხები ინარჩუნებს საბოლოო ტექსტს.
- როდესაც Copilot უარს ამბობს თავად კავშირზე, მისი პასუხი იტყობინება, როგორც არის:** 401** `m365_unauthorized` უარყოფილი ან ვადაგასული შესვლისთვის (ხელახლა შედით),** 429** მისი `Retry-After` ით დატენვისთვის და ხელის ჩამორთმევის მარცხით, სხვაგვარად, არასოდეს არის ზოგადი კავშირის უკმარისობა.

## გამოსახულების გენერაცია

`POST /v1/images/generations` `model: "copilot-m365-web/m365-copilot-image"` ით (ასევე `m365copilot/m365-copilot-image`) ხატავს Copilot ის ჩაშენებული გამოსახულების ხელსაწყოთი, როგორც ამას აკეთებს ვებ კლიენტი. თითოეული სურათი არის ერთი Copilot ბრუნი: ის მონაწილეობს ვებ კლიენტის გამოსახულების ოფციების კომპლექტით და აცხადებს `GenerateGraphicArt`, და სურათი მიდის პროგრესის ჩანაწერზე, რომელიც მიუთითებს არტეფაქტზე Microsoft's Designer სერვისზე. ეს არტეფაქტი უარს ამბობს ჩატის ჟეტონზე, ამიტომ OmniRoute აჭრის დიზაინერის ჟეტონს კავშირის განახლების ტოკენიდან და ჩამოტვირთავს ბაიტებს; ჟეტონი იგზავნება მხოლოდ `designerapp.officeapps.live.com` ზე.

- საჭიროებს შესვლის ბუნებრივ კავშირს (განახლების ჟეტონი); გაკრული ჟეტონი მარცხდება** 400** სანამ რაიმე შემობრუნება დაიხარჯება.
- `n` არის 1–4, თითო ბრუნი. `size` აკონტროლებს მხოლოდ ორიენტაციას (უფრო ფართო, მაღალი ან კვადრატი), რომელიც Copilot იკითხება ბრძანებიდან; Copilot ირჩევს რენდერის ზომას.
- სურათები ბრუნდება inline: `b64_json` ნაგულისხმევად, მონაცემები URL `response_format: "url"` სთვის.
- გენერირებული სურათები ეყრდნობა მცირე დღიურ ბიუჯეტს, ჩეთისგან განცალკევებით. როდესაც ის გამოიყენება, მოთხოვნა ვერ ხერხდება** 429** . ბრუნი, რომელიც გამოსახულების გარეშე პასუხობს, ვერ ხერხდება** 502** (ან** 400** /** 503** როდესაც Copilot ს ტექსტი იკითხება, როგორც უარი ან ტევადობის პრობლემა); შეტყობინებაში ნათქვამია რომელი.

## უსაფრთხოების მოდელი

- **არაოფიციალური ინტეგრაცია.** ეს პროვაიდერი ამუშავებს BizChat WebSocket პროტოკოლს. ის შეიძლება გატყდეს გაფრთხილების გარეშე, როდესაც Microsoft ცვლის საბოლოო წერტილს.

- წვდომის ნიშანი არის ხანმოკლე JWT. მოექეცით მას, როგორც პაროლს: ნუ ჩაიდენთ მას, არ შეხვიდეთ ან გააზიაროთ.
- განახლების ჟეტონი ანიჭებს მუდმივ წვდომას Microsoft 365 ზედაპირზე. შეინახეთ იგი იმავე სიფრთხილით, როგორც API გასაღები.

## პრობლემების მოგვარება

### ავთენტიფიკაცია დაუყოვნებლივ ვერ ხერხდება

- დარწმუნდით, რომ `chathubPath` მოიცავს სრულ `<oid>@<tenant>` სეგმენტს URL ბილიკიდან.

### ჟეტონი იწურება ~ 75 წუთის შემდეგ

ეს მოსალოდნელია. `refreshToken` გარეშე წვდომის ნიშანი ხანმოკლეა. ან:

- ხელახლა აიღეთ რწმუნებათა სიგელები DevTools დან, ან
- კონფიგურაცია** გაფართოებული პარამეტრები → Refresh ჟეტონი (სურვილისამებრ)** კავშირის დამატება ან რედაქტირების დიალოგში ავტომატური განახლებისთვის.

### სატესტო კავშირი გადის, მაგრამ ჩატი აბრუნებს 401-ს

-თან შექმნილი კავშირისთვის** შედით Microsoft ით** , სატესტო კავშირი ამოწმებს წვდომის ჟეტონის ვადის გასვლას და განაახლებს ვადაგასულ ჟეტონს შენახული განახლების ჟეტონით, ასე რომ, ჩაბარების ტესტი ასევე ადასტურებს, რომ განახლების ჟეტონი კვლავ მუშაობს.

ჩასმული რწმუნებათა სიგელით, სატესტო კავშირი ამოწმებს რწმუნებათა სიგელის ფორმას და, როდესაც ჟეტონს ვადა აქვს ვადა, რომ ჟეტონი, რომელსაც პროვაიდერი გამოიყენებდა, არ გასულა (კავშირის შენახული ჟეტონი იგებს ძველ პასტას; განახლების ჟეტონი ითვლება განახლებად). ჟეტონი, რომელიც გაუქმებულია ვადის გასვლამდე, მაინც გადის ტესტს; ჩატი შემდეგ ბრუნდება** 401** `m365_unauthorized`. გამოყენება** შედით Microsoft ით** ისევ, ან ხელახლა აიღეთ ახალი რწმუნებათა სიგელები.

### Copilot არ ჩანს პროვაიდერების სიაში
