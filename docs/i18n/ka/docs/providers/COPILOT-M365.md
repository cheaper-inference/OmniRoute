`copilot-m365-web` (alias `m365copilot`) OpenAI-ის ფორმატის ჩატის მოთხოვნებს აგზავნის ავთენტიფიცირებული Microsoft 365 Copilot BizChat-ის ბრაუზერის სესიის მეშვეობით მისამართზე `m365.cloud.microsoft/chat`. ეს არაოფიციალური ინტეგრაციაა.

> **პირველად იყენებთ Web Cookie პროვაიდერებს?**
>
> სანამ ამ პროვაიდერისთვის განკუთვნილ სახელმძღვანელოს მიჰყვებით, ზოგადი დაყენების პროცესის, ავთენტიფიკაციის მითითებების, შეზღუდვებისა და პრობლემების აღმოფხვრის შესახებ ინფორმაციისთვის წაიკითხეთ **`docs/getting-started/WEB-COOKIE-GUIDE.md`**.
>
> **მნიშვნელოვანია:** ამ პროვაიდერის ავტორიზაციის მონაცემი **cookie არ არის**. არ დააკოპიროთ cookies `m365.cloud.microsoft`-დან. ავტორიზაციის მონაცემი არის WebSocket URL-ის მოთხოვნის პარამეტრი და გზის სეგმენტი, რომელთა წაკითხვაც DevTools-ის Network ჩანართიდან ხდება.

## წინაპირობები

- Microsoft 365-ის ანგარიში, რომელსაც აქვს წვდომა BizChat-ზე მისამართზე `m365.cloud.microsoft/chat`
- Chromium-ზე დაფუძნებული ბრაუზერი (Chrome, Edge) DevTools-ში WebSocket-ის შესამოწმებლად
- M365 Copilot-ის ლიცენზია (შედის Microsoft 365 Business/Enterprise-ის მრავალ გეგმაში)

## ავტორიზაციის მონაცემის აღება (WebSocket მეთოდი)

1. შედით `https://m365.cloud.microsoft/chat`-ზე და დაიწყეთ საუბარი.
2. გახსენით **DevTools → Network**.
3. გაფილტრეთ **WS**-ის (WebSocket) მიხედვით.
4. დააწკაპუნეთ Chathub-ის WebSocket კავშირზე. მოძებნეთ URL, რომელიც იწყება შემდეგით:
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. მისი **Request URL**-დან დააკოპირეთ:
   - `access_token` მოთხოვნის პარამეტრის მნიშვნელობა (მოკლევადიანი JWT).
   - Chathub-ის გზის სეგმენტი `/Chathub/`-ის შემდეგ (მაგ., `<oid>@<tenant>`).

სრული URL-ის ფორმაა:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute-ში გადადით **Providers → Add Provider**-ზე, აირჩიეთ **Microsoft 365 Copilot
   (BizChat)** და ჩასვით ავტორიზაციის მონაცემი შემდეგ ფორმატში:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. დააწკაპუნეთ **Test Connection**-სა და **Save**-ზე.

## ავტორიზაციის მონაცემის აღება (HAR-ის იმპორტი)

WebSocket URL-დან მნიშვნელობების ხელით კოპირების ნაცვლად, შეგიძლიათ DevTools-ის HAR ფაილის ექსპორტი:

1. გახსენით **DevTools → Network**.
2. დაიწყეთ ან გააგრძელეთ BizChat საუბარი (ეს ააქტიურებს WebSocket კავშირს).
3. Network პანელში დააწკაპუნეთ მარჯვენა ღილაკით და აირჩიეთ **Save all as HAR with content**.
4. OmniRoute-ში, პროვაიდერის კავშირის დიალოგურ ფანჯარაში გამოიყენეთ ღილაკი **Import .har file**.

OmniRoute HAR-ში ეძებს Chathub-ის WebSocket URL-ს, ამოიღებს `access_token`-სა და `chathubPath`-ს და ავტომატურად შეავსებს ავტორიზაციის მონაცემების ველებს. HAR-ის იმპორტი ახდენს JWT-ის ვადის ამოწურვის დროის დეკოდირებას და აჩვენებს ტოკენის დარჩენილ მოქმედების ხანგრძლივობას.

> **არასდროს ატვირთოთ რეალური HAR ექსპორტი, წვდომის ტოკენი ან განახლების ტოკენი რეპოზიტორიაში.** სატესტო და დოკუმენტაციის მნიშვნელობები ყოველთვის ჩანაცვლების ნიშნები უნდა იყოს.

## ტოკენის მოქმედების ხანგრძლივობა და განახლება

`access_token` ხანმოკლეა (ჩვეულებრივ **~ 75 წუთი** ). გამოსაყენებელი განახლების ჟეტონის გარეშე, თქვენ ხელახლა უნდა აიღოთ რწმუნებათა სიგელები ვადის გასვლის შემდეგ.

### ავტომატური განახლება `refreshToken`-ით

Microsoft 365 პროვაიდერში **კავშირის დამატება** ან **კავშირის რედაქტირება** დიალოგი, გახსნა **გაფართოებული პარამეტრები → განახლების ჟეტონი (სურვილისამებრ)** . ჩასვით Microsoft OAuth განახლების ჟეტონი `substrate.office.com/sydney` სკოპისთვის და შეინახეთ. შეყვანა არის ნიღბიანი და არასოდეს ივსება წინასწარ შენახული ჟეტონით. რედაქტირებისას დატოვეთ ის ცარიელი, რომ შეინახოთ არსებული ჟეტონი; ჩასვით ახალი ჟეტონი მის ჩასანაცვლებლად.

მიიღეთ განახლების ნიშანი Microsoft მოწყობილობის კოდიდან ან ავტორიზაციის კოდის ნაკადიდან `substrate.office.com/sydney` მდე; დაფა არ იძენს მას თქვენთვის. კონფიგურირებული განახლების ჟეტონით, OmniRoute ამოწმებს `access_token` მოთხოვნამდე და განაახლებს მას მხოლოდ მაშინ, როცა მას განახლება სჭირდება. წარმატებული განახლება ასევე აგრძელებს შემობრუნებულ განახლების ჟეტონს, თავიდან აიცილებს ხელით ხელახლა აღებას, სანამ განახლების ჟეტონი მოქმედებს.

თუ `refreshToken` დაყენებული არ არის, ყოველი ვადის ამოწურვის შემდეგ WebSocket-ის ავტორიზაციის მონაცემი ხელით თავიდან უნდა აიღოთ.

### დონის არჩევა

| დონე         | alias            | ინტერფეისი                   |
| ------------ | ---------------- | ---------------------------- |
| `individual` | _(ნაგულისხმევი)_ | სამომხმარებლო M365 Copilot   |
| `edu`        | `included`       | საგანმანათლებლო M365 Copilot |
| `enterprise` | `work`           | M365 Copilot სამუშაოსთვის    |

დააყენეთ იარუსი **გაფართოებული პარამეტრები → Copilot იარუსი** . იარუსი გავლენას ახდენს BizChat მარშრუტიზაციაზე და მოდელის წვდომაზე.

## უსაფრთხოების მოდელი

- **არაოფიციალური ინტეგრაცია.** ეს პროვაიდერი უკუინჟინერიის გზით იყენებს BizChat-ის WebSocket
  პროტოკოლს. Microsoft-ის მიერ საბოლოო წერტილის შეცვლის შემთხვევაში, მან შეიძლება გაფრთხილების გარეშე შეწყვიტოს მუშაობა.
- `subscriptionRisk: true` ალამი მიუთითებს, რომ ინტეგრაცია ეყრდნობა
  არადოკუმენტირებულ საბოლოო წერტილს. ანგარიშზე შეზღუდვების დაწესება შესაძლებელია, თუმცა დადასტურებული არ არის.
- წვდომის ტოკენი მოკლევადიანი JWT-ია. მოეპყარით მას, როგორც პაროლს: არ დაამატოთ
  რეპოზიტორიაში, არ შეიტანოთ ჟურნალში და არ გააზიაროთ.
- განახლების ტოკენი BizChat-ის ინტერფეისზე გრძელვადიან წვდომას იძლევა. შეინახეთ ის ისეთივე
  სიფრთხილით, როგორც API გასაღები.

## პრობლემების მოგვარება

### ავთენტიფიკაცია დაუყოვნებლივ ვერ სრულდება

- გადაამოწმეთ, რომ მონაცემები დააკოპირეთ **WebSocket URL-დან** და არა XHR/Fetch მოთხოვნიდან. ავტორიზაციის
  მონაცემი არის Chathub WebSocket კავშირის `access_token` მოთხოვნის პარამეტრში
  და არა `Authorization: Bearer` სათაურში.
- დარწმუნდით, რომ `chathubPath` შეიცავს URL-ის
  ბილიკიდან სრულ `<oid>@<tenant>` სეგმენტს.

### ტოკენს ვადა ~75 წუთის შემდეგ გასდის

ეს მოსალოდნელია. `refreshToken`-ის გარეშე წვდომის ტოკენი მოკლევადიანია. შეგიძლიათ:

- ხელახლა მიიღოთ ავტორიზაციის მონაცემი DevTools-იდან, ან
- კონფიგურაცია **გაფართოებული პარამეტრები → Refresh ჟეტონი (სურვილისამებრ)** კავშირის დამატება ან რედაქტირების დიალოგში ავტომატური განახლებისთვის.

### კავშირის ტესტი წარმატებულია, მაგრამ ჩატი აბრუნებს 401-ს

შესაძლოა, ტოკენს ვადა ვალიდაციასა და პირველ მოთხოვნას შორის პერიოდში გაუვიდა. ხელახლა მიიღეთ
ახალი ავტორიზაციის მონაცემი.

### Copilot არ ჩანს პროვაიდერების სიაში

დარწმუნდით, რომ `copilot-m365-web` ჩართულია განყოფილებაში **მართვის პანელი → პროვაიდერები**. ზოგიერთ
ტარიფში პროვაიდერი შესაძლოა ნაგულისხმევად დამალული იყოს.
