## რას წარმოადგენს

OmniRoute უკავშირდება **Obsidian**-ის საცავს, როგორც **კონტექსტის წყაროს** — ლოკალურ Markdown
ცოდნის ბაზას, რომელსაც აგენტები ჩაშენებული MCP სერვერის მეშვეობით კითხულობენ და მასში წერენ.
ინტეგრაცია უკავშირდება დესკტოპის აპლიკაციაში გაშვებულ, საზოგადოების მიერ შექმნილ
**Obsidian Local REST API** მოდულს, ამიტომ აგენტებს შეუძლიათ ჩანაწერების ძიება,
ფაილების წაკითხვა/ჩაწერა/ნაწილობრივი შეცვლა, საცავის შიგთავსის ჩამოთვლა, ყოველდღიურ/ყოველკვირეულ
პერიოდულ ჩანაწერებთან მუშაობა, ტეგების მართვა, Obsidian-ის ბრძანებების გაშვება და
(სურვილისამებრ) დესკტოპსა და მობილურ მოწყობილობას შორის საცავის ორმხრივი სინქრონიზაციის
კოორდინირება.

კლიენტი (`src/lib/obsidian/api.ts`) Local REST API-ს შემდეგი შესაძლებლობებით ავსებს:

- დროებითი `5xx` შეცდომებისთვის **ხელახალი ცდა მზარდი დაყოვნებით**, `AbortController`-ის მეშვეობით **30-წამიანი ლოდინის ვადა**.
- **ტიპიზებული შეცდომების კლასიფიკაცია** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- გასაგები მინიშნება **„Obsidian-თან დაკავშირება ვერ ხერხდება“**, რომელიც ყურადღებას ამახვილებს
  პორტის გავრცელებულ შეცდომაზე (HTTP `27123`-ზე, და **არა** MCP საბოლოო წერტილი `27124`-ზე)
  და Tailscale-ის ფორმატზე.
- საცავის მიმართ ფარდობითი **ბილიკების კოდირება**, რათა გამოტოვებებისა და დახრილი ხაზების შემცველი ჩანაწერების ბილიკები უსაფრთხო იყოს.

## დაყენება

Obsidian-ის ტოკენის ან საბაზო URL-ისთვის **გარემოს ცვლადი არ არსებობს** — ორივე ინახება
SQLite-ის `key_value` ცხრილში (სახელთა სივრცე `obsidian`)
`src/lib/db/obsidian.ts`-ის მეშვეობით. ტოკენი **დაშიფრული სახით ინახება** (AES-256-GCM,
ღია ტექსტთან უკუთავსებადობის სარეზერვო მექანიზმით). კონფიგურაცია შეასრულეთ Endpoint-ის
მართვის პანელის **Context Sources** ჩანართიდან (`ObsidianSourceCard`) ან პარამეტრების
REST API-ის მეშვეობით.

> [!IMPORTANT]
> **Obsidian Local REST API**-ის პლაგინი უნდა იყოს დაინსტალირებული და გაშვებული. მისი
> REST ინტერფეისი უსმენს მისამართზე **HTTP `127.0.0.1:27123`** (ნაგულისხმევი საბაზო URL).
> პორტი `27124` არის _ცალკე_ MCP/HTTPS საბოლოო წერტილი და პარამეტრების მარშრუტი მას
> ცალსახად უარყოფს. სხვა მოწყობილობიდან დაკავშირებისას გამოიყენეთ
> `http://<tailscale-ip>:27123`.

### კონფიგურაციის გასაღებები (SQLite `key_value`, სახელთა სივრცე `obsidian`)

| გასაღები          | დანიშნულება                                                     | დაშიფრულია |
| ----------------- | --------------------------------------------------------------- | ---------- |
| `api_key`         | Local REST API-ის bearer ტოკენი                                 | დიახ       |
| `base_url`        | REST-ის საბაზო URL (ნაგულისხმევი `http://127.0.0.1:27123`)      | არა        |
| `vault_path`      | საცავის დირექტორიის აბსოლუტური გზა (სინქრონიზაციისთვის)         | არა        |
| `webdav_username` | გენერირებული WebDAV მომხმარებლის სახელი (საცავის სინქრონიზაცია) | არა        |
| `webdav_password` | გენერირებული WebDAV პაროლი (საცავის სინქრონიზაცია)              | დიახ       |
| `webdav_enabled`  | ჩართულია თუ არა საცავის WebDAV სინქრონიზაცია                    | არა        |

### კონფიგურაცია REST-ის მეშვეობით

```bash
# Local REST API-ის ტოკენის შენახვა და შემოწმება (POST ამოწმებს სტატუსის მოთხოვნით)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# კავშირის სტატუსის შემოწმება (აბრუნებს connected, hasToken, baseUrl, vaultPath ველებს)
curl http://localhost:20128/api/settings/obsidian

# კავშირის გაწყვეტა (ასუფთავებს შენახულ ტოკენს)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

ყველა მეთოდი მოითხოვს მართვის პანელის ავთენტიფიკაციას. `POST` უარყოფს ნებისმიერ URL-ს
პორტზე `27124` და შენახვამდე ამოწმებს ტოკენს Local REST API-ის სტატუსის საბოლოო
წერტილის გამოძახებით.

### საცავის WebDAV სინქრონიზაცია

`src/app/api/settings/obsidian/webdav/route.ts` მართავს არასავალდებულო, WebDAV-ზე
დაფუძნებულ საცავის სინქრონიზაციას (რომელსაც `src/lib/obsidianSync.ts` წარმართავს).
მისი ჩართვისას OmniRoute მიეთითება საცავის ლოკალურ დირექტორიაზე და გენერირდება
WebDAV-ის მომხმარებლის სახელისა და პაროლის შემთხვევითი წყვილი:

```bash
# WebDAV სინქრონიზაციის ჩართვა საცავის დირექტორიისთვის (აგენერირებს მომხმარებლის სახელს/პაროლს)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV სინქრონიზაციის სტატუსის მიღება (მონაცემები ბრუნდება მხოლოდ ჩართულ მდგომარეობაში)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV სინქრონიზაციის გამორთვა (ასუფთავებს ავტორიზაციის მონაცემებს და მართულ .stignore-ს)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### უსაფრთხოება და ტრანსპორტი

WebDAV ავთენტიფიკაცია ახორციელებს თითო IP-ის წარუმატებლობის თვალყურის დევნებას და ჩაკეტვას (10 წარუმატებელი მცდელობა 60 წამიან ფანჯარაში იწვევს 5-წუთიან დაბლოკვას `429 Too Many Requests` ით და `Retry-After` ით). იმის გამო, რომ WebDAV გადასცემს საბაზისო ავთენტიფიკაციის რწმუნებათა სიგელებს, TLS შეწყვეტა (ან უსაფრთხო გვირაბზე გადაყვანა, როგორიცაა Tailscale ან Cloudflare Tunnel) მკაცრად რეკომენდირებულია WebDAV ბოლო წერტილზე წვდომისას loopback-ის გარეთ.

### კონტექსტის წყარო თითოეული API გასაღებისთვის (არასავალდებულო)

Obsidian-ის კონფიგურაცია შეიძლება განისაზღვროს **თითოეული API გასაღებისთვის**
`api_key_context_sources` ცხრილის მეშვეობით
(`src/lib/db/apiKeyContextSources.ts`). როდესაც MCP გამოძახება შეიცავს
ავთენტიფიცირებულ API გასაღების იდენტიფიკატორს, `getObsidianConfigForApiKey()`
უპირატესობას ანიჭებს ამ გასაღების საკუთარ ტოკენს/საბაზო URL-ს/საცავის გზას
(`source: "api_key"`), ხოლო მათი არარსებობის შემთხვევაში იყენებს გლობალურ
კონფიგურაციას (`source: "global"`).

არასინქრონიზაციის MCP ხელსაწყოები ამ კონფიგურაციის წაკითხვამდე მოითხოვს გამომძახებლის
იდენტობის განსაზღვრას. იდენტობის არმქონე გამომძახებელი იღებს შეტყობინებას
`Obsidian API token not configured` და საცავში მოთხოვნა არ იგზავნება. HTTP
გამომძახებლების იდენტობა განისაზღვრება მათი მოთხოვნის ავტორიზაციის მონაცემებით;
stdio გამომძახებლებისთვის შესაძლებელია `OMNIROUTE_API_KEY`-ის ან `ROUTER_API_KEY`-ის
გამოყენება. დაუდგენელი HTTP გამომძახებელი ვერ მიიღებს სერვერის გარემოს იდენტობას.
მხოლოდ შემავსებელი იდენტიფიკატორები წვდომის ავტორიზაციას არ ახდენს; მხარდაჭერილი რჩება
გარემოს მოქმედი ავტორიზაციის მონაცემი, რომელიც `env-key`-ად განისაზღვრება.
ავთენტიფიცირებული გასაღებები, რომლებსაც Obsidian-ის ცალკე კონფიგურაცია არ აქვთ,
კვლავ იყენებენ გლობალურ სარეზერვო კონფიგურაციას. ოთხი `obsidian_sync_*` ხელსაწყო
ინარჩუნებს სინქრონიზაციის ტოკენთან დაკავშირებულ საკუთარ, განცალკევებულ ქცევას.

## MCP ინსტრუმენტები (22)

განსაზღვრულია `open-sse/mcp-server/tools/obsidianTools.ts` ში. token/base-URL წყდება თითო ზარზე (ჯერ API კლავიშზე, შემდეგ გლობალურზე). ინსტრუმენტები, რომლებიც მოხვდა OmniRoute** სერვერის სინქრონიზაცია** (ოთხი `obsidian_sync_*` ინსტრუმენტი) დამატებით მოითხოვს სინქრონიზაციის ავტორიზაციის ნიშანს, რომელიც კონფიგურირებულია OmniRoute პარამეტრებში.

### წაკითხვის ხელსაწყოები (`read:obsidian`)

| ხელსაწყო                     | აღწერა                                                                                                    |
| ---------------------------- | --------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | შეამოწმეთ არის თუ არა ლოკალური REST API ხელმისაწვდომი და ავტორიზებული.                                    |
| `obsidian_search_simple`     | ჩანაწერის შინაარსის სრული ტექსტის ძიება; აბრუნებს სნიპეტებს ფაილის ბილიკებით.                             |
| `obsidian_search_structured` | ძიება JSON ლოგიკური გამოხატვის გამოყენებით (and/or/regex/path ფილტრები).                                  |
| `obsidian_read_note`         | წაიკითხეთ ჩანაწერი სარდაფის მონათესავე გზის მიხედვით; სურვილისამებრ კონკრეტული heading/block/frontmatter. |
| `obsidian_list_vault`        | ჩამოთვალეთ ფაილები და დირექტორიები სარდაფში (ჩანაწერების ხე).                                             |
| `obsidian_get_document_map`  | მიიღეთ შენიშვნის სათაურის სტრუქტურა, როგორც სათაურების რუკა → ხაზის ნომრები.                              |
| `obsidian_get_note_metadata` | მიიღეთ frontmatter, ტეგები, ბმულები, char/word რაოდენობა სრული შინაარსის გარეშე.                          |
| `obsidian_get_active_file`   | მიიღეთ ბილიკი + შინაარსი ამჟამად აქტიური ფაილის Obsidian ში.                                              |
| `obsidian_get_periodic_note` | მიიღეთ daily/weekly/monthly პერიოდული შენიშვნა თარიღისთვის (დღეს, თუ გამოტოვებულია).                      |
| `obsidian_get_tags`          | ჩამოთვალეთ ყველა სარდაფის ტეგი მათი სიხშირით.                                                             |
| `obsidian_list_commands`     | ჩამოთვალეთ ხელმისაწვდომი Obsidian ბრძანება IDs (გამოიყენეთ `obsidian_execute_command` თან ერთად).         |
| `obsidian_sync_status`       | OmniRoute სინქრონიზაციის სერვერის სტატუსი: გაშვებული, სარდაფის სახელი, პორტი, დრო, ბოლო სინქრონიზაცია.    |
| `obsidian_sync_conflicts`    | ჩამოთვალეთ მოუგვარებელი სინქრონიზაციის კონფლიქტები (გზა, კონფლიქტის გზა, აღმოჩენილი-ზე).                  |

### ჩაწერის ხელსაწყოები (`write:obsidian`)

| ხელსაწყო                         | აღწერა                                                                                               |
| -------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | შექმენით ან გადაწერეთ ჩანიშვნა მოცემული Markdown შინაარსით.                                          |
| `obsidian_append_note`           | შინაარსის დამატება შენიშვნაში; სურვილისამებრ კონკრეტულ heading/block. ზე                             |
| `obsidian_patch_note`            | ქირურგიული append/prepend/replace სათაურის, ბლოკის ან წინა მატერიის ველზე.                           |
| `obsidian_delete_note`           | სამუდამოდ წაშალეთ შენიშვნა სარდაფიდან.                                                               |
| `obsidian_move_note`             | შენიშვნის გადატანა ან სახელის შეცვლა სარდაფში.                                                       |
| `obsidian_execute_command`       | შეასრულეთ Obsidian ბრძანება მისი ბრძანებით ID.                                                       |
| `obsidian_open_file`             | გახსენით ფაილი Obsidian ში (ქმნის მას, თუ ის არ არსებობს).                                           |
| `obsidian_sync_trigger`          | ჩართეთ დაუყოვნებელი ორმხრივი დესკტოპის ↔ მობილური სარდაფის სინქრონიზაცია.                            |
| `obsidian_sync_resolve_conflict` | მოაგვარეთ სინქრონიზაციის კონფლიქტი: შეინახეთ `local` (მობილური), `remote` (დესკტოპი) ან `keep-both`. |

> [!NOTE]
> `obsidian_patch_note` სამიზნეები იღებენ `targetType` `heading | block | frontmatter` და `operation` `append | prepend | replace`, სურვილისამებრ `createTargetIfMissing`. ოთხი `obsidian_sync_*` ინსტრუმენტი ესაუბრება ადგილობრივ სინქრონიზაციის სერვერს (`http://127.0.0.1:27781` ნაგულისხმევად) და მოითხოვს სინქრონიზაციის ჟეტონს.

### ფარგლები

წაკითხვის ხელსაწყოები მოითხოვს `read:obsidian`; ჩაწერის ხელსაწყოებს სჭირდება `write:obsidian`. აღსრულება იდენტურია Notion —, რომელსაც ამუშავებს `withScopeEnforcement()` `open-sse/mcp-server/server.ts` ში, დახურულია `OMNIROUTE_MCP_ENFORCE_SCOPES=true` ზე და იძულებით ჩართულია HTTP/SSE აბონენტებისთვის, რომელთა API კლავიშს აკლია `manage`/`admin`, ნებადართული ფარგლებით მომდინარეობს `OMNIROUTE_MCP_SCOPES` დან ან API გასაღების ფარგლების კონტექსტიდან. იხილეთ [MCP-SERVER.md](./MCP-SERVER.md).

## გამოყენების შემთხვევები

- **საცავის მონაცემებზე დაფუძნებული პასუხები** — `obsidian_search_simple` / `obsidian_search_structured`,
  შემდეგ `obsidian_read_note`, რათა აგენტმა თქვენი რეალური ჩანაწერებიდან უპასუხოს.
- **ჩანაწერების შექმნა / დღიურის წარმოება** — `obsidian_write_note`, `obsidian_append_note`, ან
  ზუსტი `obsidian_patch_note`, რათა აგენტის შედეგები, შეჯამებები ან ყოველდღიური ჩანაწერები
  (`obsidian_get_periodic_note`) საცავში ჩაიწეროს.
- **საცავში ნავიგაცია** — `obsidian_list_vault`, `obsidian_get_document_map` და
  `obsidian_get_tags` სტრუქტურის შესასწავლად წაკითხვამდე/ჩაწერამდე.
- **Obsidian-ის ავტომატიზაცია** — `obsidian_list_commands` + `obsidian_execute_command`
  პლაგინების/ბრძანებების აგენტიდან სამართავად; `obsidian_open_file` ჩანაწერის UI-ში საჩვენებლად.
- **მობილური სინქრონიზაცია** — ჩართეთ WebDAV სინქრონიზაცია, შემდეგ გამოიყენეთ `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  დესკტოპსა და მობილურს შორის სინქრონიზაციის კოორდინირებისა და კონფლიქტების მოსაგვარებლად.
