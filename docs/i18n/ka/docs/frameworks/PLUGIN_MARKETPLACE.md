> **სიმართლის წყარო:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/` და
> `src/app/(dashboard)/dashboard/plugins/`
> **ბოლო განახლება:** 2026-06-28 — v3.8.40

OmniRoute-ს მოჰყვება WordPress-ის სტილის პლაგინების სისტემა. პლაგინები თვითკმარი
დირექტორიებია — თითოეულს აქვს `plugin.json` მანიფესტი და შესასვლელი ფაილი — რომლებიც
ერთვებიან მოთხოვნების დამუშავების კონვეიერში (`onRequest` / `onResponse` / `onError`) და
სასიცოცხლო ციკლის მოვლენებში (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`).

**პლაგინების მარკეტპლეისი** ამ სისტემის თავზე არსებული აღმოჩენის შრეა. ის
გთავაზობთ დასაყენებელი პლაგინების დათვალიერებად კატალოგს. ნაგულისხმევად კატალოგი
მცირე, ჩაშენებული საწყისი რეესტრია; ოპერატორს შეუძლია მიუთითოს მორგებული დისტანციური
რეესტრის URL, რა შემთხვევაშიც ამოღების ოპერაცია დაცულია DNS-რეზოლვინგიანი SSRF დამცავით
(იხილეთ [უსაფრთხოება](#security)).

პლაგინების ყველა მარშრუტი **მხოლოდ loopback-ისთვისაა** (დონე 1 — `LOCAL_ONLY`): პლაგინები
შვილობილ პროცესებში ტვირთავენ და ასრულებენ კოდს, ამიტომ მარშრუტები მიუწვდომელია
არა-loopback წყაროდან, ავტორიზაციის მიუხედავად. იხილეთ
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md).

## როგორ ჯდება Together

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **რეესტრის ფენა** — `src/lib/plugins/marketplace.ts`: ჩამოთვლის / ეძებს კატალოგს, დაბრუნდება სათესლე რეესტრში ნებისმიერი წარუმატებლობის შემთხვევაში.
- **სასიცოცხლო ციკლის ფენა** — `src/lib/plugins/manager.ts` (`pluginManager` singleton): ინსტალაცია, განახლება, გააქტიურება, გამორთვა, დეინსტალაცია, სკანირება, ჩატვირთვა.
- **მანიფესტური ფენა** — `src/lib/plugins/manifest.ts`: Zod სქემა + ნაგულისხმევი `plugin.json` სთვის.
- **სკანერი** — `src/lib/plugins/scanner.ts`: აღმოაჩენს დანამატებს დისკზე დანამატების დირექტორიაში.
- **ჩამტვირთავი** — `src/lib/plugins/loader.ts`: აწარმოებს თითოეულ დანამატს ცალკე Node.js ბავშვურ პროცესში და ბროკერები ახდენენ ზარებს IPC ზე. ბავშვი არ არის ქვიშის ყუთი (იხ. „პლაგინის შესრულების იზოლაცია“ ქვემოთ).

## მარკეტპლეისის კატალოგი

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) აბრუნებს
`MarketplaceEntry` ობიექტების სიას:

| ველი          | ტიპი     | შენიშვნები                                      |
| ------------- | -------- | ----------------------------------------------- |
| `name`        | string   | პლაგინის სახელი kebab-case ფორმატში             |
| `version`     | string   | semver                                          |
| `description` | string   | მოკლე შეჯამება                                  |
| `author`      | string   | ავტორი / ორგანიზაცია                            |
| `license`     | string   | SPDX-ის სტილის ლიცენზიის id                     |
| `downloadUrl` | string   | წყაროს ჩამოტვირთვის URL (შეიძლება ცარიელი იყოს) |
| `repository`  | string?  | რეპოზიტორიის არასავალდებულო URL                 |
| `tags`        | string[] | ძიების/ფილტრაციის ტეგები                        |
| `downloads`   | number   | ჩამოტვირთვების რაოდენობა                        |
| `rating`      | number   | 0–5                                             |
| `verified`    | boolean  | მონიშნულია თუ არა ჩანაწერი ვერიფიცირებულად      |
| `lastUpdated` | string   | ISO-ს მსგავსი თარიღის სტრიქონი                  |

როდესაც მორგებული რეესტრის URL კონფიგურირებული არ არის, კატალოგად გამოიყენება ჩაშენებული
`SEED_REGISTRY` (ამჟამად `request-logger`, `rate-limiter`, `cost-tracker` და
`theme-manager`). საწყისი რეესტრი ყოველთვის ხელმისაწვდომია — თუ კონფიგურირებული დისტანციური
რეესტრი მიუწვდომელია, აბრუნებს `200`-ისგან განსხვავებულ სტატუსს ან დაუდგენელი
ფორმატის სხეულს, `listMarketplacePlugins()` ჟურნალში წერს გაფრთხილებას და საწყის სიაზე გადადის.

> შენიშვნა: მარკეტპლეისის **კატალოგი** (დათვალიერება/ძიება) სრულად არის დაკავშირებული, მაგრამ
> კატალოგიდან მარკეტპლეისის **ერთი დაწკაპუნებით დაყენება** ჯერ არ არის განხორციელებული —
> მარკეტპლეისის ჩანაწერზე მართვის პანელის ღილაკი „დაყენება“ ამჟამად აჩვენებს
> შეტყობინებას „მალე იქნება“. ამჟამად დაყენება ხორციელდება ლოკალური ბილიკიდან დაყენების
> პროცესით (`POST /api/plugins`) და დისკზე აღმოჩენით (`POST /api/plugins/scan`).

## REST API

ყველა საბოლოო წერტილი მოითხოვს მართვის ავტორიზაციას (`requireManagementAuth`)** და** არის მხოლოდ loopback-ზე — `/api/plugins` და `/api/plugins/` ჩამოთვლილია `LOCAL_ONLY_API_PREFIXES` ში (`src/server/authz/routeGuard.ts`).

| ბოლო წერტილი                       | მეთოდი | აღწერა                                                                  |
| ---------------------------------- | ------ | ----------------------------------------------------------------------- |
| `/api/plugins`                     | GET    | ჩამოთვალეთ დაინსტალირებული დანამატები (სურვილისამებრ `?status=` ფილტრი) |
| `/api/plugins`                     | POST   | დააინსტალირეთ დანამატი მოდულების წყაროების დირექტორიადან                |
| `/api/plugins/scan`                | POST   | დაასკანირეთ მოდულების დირექტორია და დაარეგისტრირეთ ახალი დანამატები     |
| `/api/plugins/marketplace`         | GET    | ჩამოთვალეთ ბაზრის კატალოგის ჩანაწერები                                  |
| `/api/plugins/marketplace/install` | POST   | დააინსტალირეთ ბაზრის მოდული სახელით                                     |
| `/api/plugins/[name]`              | GET    | მიიღეთ დაინსტალირებული მოდულის დეტალები                                 |
| `/api/plugins/[name]`              | DELETE | მოდულის დეინსტალაცია                                                    |
| `/api/plugins/[name]/activate`     | POST   | გააქტიურება (ჩატვირთეთ + რეგისტრის კაკვები)                             |
| `/api/plugins/[name]/deactivate`   | POST   | გამორთვა (გაათავისუფლეთ `onDeactivate`, გააუქმეთ კაუჭები)               |
| `/api/plugins/[name]/config`       | GET    | მიიღეთ მოდულის კონფიგურაციის + კონფიგურაციის სქემა                      |
| `/api/plugins/[name]/config`       | PUT    | მოდულის კონფიგურაციის განახლება (დამოწმებულია სქემის მიხედვით)          |

`GET /api/plugins` `status` ფილტრი იღებს ერთს `installed` / `active` / `inactive` / `error`. არასწორი მნიშვნელობა აბრუნებს `400`.

### ჩამოთვალეთ დაინსტალირებული დანამატები

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### დააინსტალირეთ ადგილობრივი ბილიკიდან

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` უნდა იყოს** აბსოლუტური** გზა დირექტორიაში** მოდულის წყაროების დირექტორიაში** : `plugin-sources` მოდულის ფესვის გვერდით, ასე რომ `~/.omniroute/plugin-sources/` ნაგულისხმევად, ან `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` როდესაც ეს ცვლადი დაყენებულია (`getPluginSourcesDir()` in `src/lib/plugins/installSource.ts`). დააკოპირეთ ან კლონირეთ მოდული ჯერ იქ. ინსტალაციაზე უარის თქმა ხდება `400` ით, როდესაც ბილიკი შეიცავს `..` ან ნულ ბაიტს, დევს ამ დირექტორიას გარეთ, წყდება მის გარეთ სიმლინკის საშუალებით, შეიცავს სიმბმულს, რომლის სამიზნე მის გარეთაა, ან როცა დირექტორია არ არსებობს. წყაროს დირექტორია უნდა შეიცავდეს მოქმედ `plugin.json` (ან იყოს მისი მშობელი). წარმატების შემთხვევაში პასუხი არის `201` დაინსტალირებული დანამატის რიგით.

დანამატის სხვა მარშრუტებისაგან განსხვავებით, ეს მოითხოვს მართვის სერთიფიკატს (დაფის სესია ან მართვის მოცულობის API კლავიატურა) მაშინაც კი, როდესაც შესვლა გამორთულია (`requireLogin=false`): კოდის დაყენება არასდროს არის ანონიმური ქმედება. იგივე ეხება `POST /api/plugins/marketplace/install` (სხეულის `{ "name": "<plugin>" }`).

### დაათვალიერეთ ბაზარი

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### განაახლეთ მოდულის კონფიგურაცია

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` ამოწმებს სხეულს დანამატის `configSchema` სთან (გამოცხადებული მანიფესტში) `src/lib/plugins/manifest.ts` დან `validatePluginConfig()` ით: ყველა გასაღები უნდა იყოს გამოცხადებული სქემაში, მნიშვნელობები უნდა ემთხვეოდეს დეკლარირებულ ტიპს, `number` ველები პატივი `min`/`max` და `select` ველები უნდა ემთხვეოდეს დეკლარირებულ `enum` ს. ნებისმიერი დარღვევა აბრუნებს `400` და არაფერი ინახება. დანამატს, რომელიც აცხადებს, რომ არ არის `configSchema` არ აქვს კონფიგურირებადი კლავიშები, ამიტომ მოთხოვნაზე უარი თქვა `400` ით („მოდული არ აცხადებს რაიმე კონფიგურირებად გასაღებს“).

## კონფიგურაცია

### პლაგინების დირექტორია

პლაგინები ინახება OmniRoute-ის მონაცემთა დირექტორიაში:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (ან ის, რაზეც manifest.main მიუთითებს)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ამ დირექტორიას სამ
ეტაპად განსაზღვრავს:

1. **`OMNIROUTE_PLUGINS_DIR`**, თუ დაყენებულია — გამოიყენება უცვლელად, მიუხედავად იმისა,
   თუ რას მიუთითებს `HOME`. ეს არის Docker/K8s-ის ცხადი პარამეტრი, სადაც პლაგინების ხე
   bind-mount-ით თავსდება ბილიკზე, რომელსაც, როგორც წესი, კონტეინერის სახლის
   დირექტორიასთან საერთო არაფერი აქვს (#11827).
2. `<home>/.omniroute/plugins`, სადაც `<home>` მიიღება `HOME` / `USERPROFILE`
   გარემოს ცვლადებიდან.
3. `/tmp/.omniroute/plugins`, როდესაც პროცესი საერთოდ არ ექსპორტირებს სახლის
   დირექტორიას.

განსაზღვრული დირექტორია გაშვებისას ერთხელ იწერება ჟურნალში, როგორც
`scanner.dir_resolved`, იმ წყაროს მითითებით, რომელმაც უპირატესობა მიიღო
(`OMNIROUTE_PLUGINS_DIR`, `home` ან `no-home-fallback`) — ამიტომ გამოსახულება,
რომელიც შეუმჩნევლად გადადის მე-3 ეტაპზე, ამის შესახებ პირდაპირ იტყობინება და მხოლოდ
პლაგინების ცარიელ სიას არ აჩვენებს. `POST /api/plugins/scan` იქ აღმოაჩენს ყველა
ქვედირექტორიას, რომელიც მართებულ `plugin.json`-ს შეიცავს, და არეგისტრირებს მას;
იგივე დირექტორიაა ძირეული დირექტორია, რომელშიც `pluginManager.install()` პლაგინებს
აკოპირებს, ამიტომ ჩანაცვლება აღმოჩენასა და ინსტალაციას ერთად გადაადგილებს.

> **`OMNIROUTE_PLUGINS_DIR` არ არის `OMNIROUTE_PLUGIN_PATH`.** ამ უკანასკნელს მხოლოდ
> CLI-ის ბრძანების პლაგინების ჩამტვირთავი (`bin/cli/plugins.mjs`) კითხულობს იმ
> `omniroute-cmd-*` npm პაკეტების მოსაძებნად, რომლებიც `omniroute`-ს ქვებრძანებებს
> ამატებს — ის აქ აღწერილ შესრულების დროის სკანერზე გავლენას არ ახდენს. ამ მხარის
> შესახებ იხილეთ [PLUGINS.md](./PLUGINS.md).

არასწორ პასუხს), გამოიყენება ჩაშენებული საწყისი რეესტრი.

მართვის პანელის ჩანართი „Marketplace“ ამ URL-ისთვის ველს აჩვენებს (რომელიც
`GET /api/settings`-იდან იკითხება).

> განხორციელების შენიშვნა: მართვის პანელში მოქმედება „Save“

> გამოშვებაში მონაცემთა შენახვა გადაამოწმეთ — **წაკითხვის** გზა (`getSettings()` →

> საცავში აღმოჩნდება.

## უსაფრთხოება

### მარშრუტის დონის — loopback მხოლოდ

დანამატები ასრულებენ კოდს ქვირითის შვილო პროცესებში, ამიტომ მთელი `/api/plugins` ზედაპირი კლასიფიცირებულია `LOCAL_ONLY` (ტიერი 1). Loopback აღსრულება უპირობოდ მუშაობს** ადრე** ნებისმიერი ავტორიზაციის შემოწმება, ასე რომ, გაჟონილი მართვის ჟეტონი, რომელიც აღწევს ყუთს გვირაბში, ჯერ კიდევ არ შეუძლია მოდულის ინსტალაცია, გააქტიურება ან დეინსტალაცია. იხილეთ [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) და Hard Rules #15 / #17.

### ბაზრის რეესტრი SSRF მცველი

მორგებული რეესტრი URL არის თავდამსხმელზე გავლენიანი კონფიგურაცია, ამიტომ მის მიღებამდე `listMarketplacePlugins()` გადის მას ორ ფენაში:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - უარყოფს ყველაფერს , რაც არ არის `http:` / `https:`.
   - უარყოფს სიტყვასიტყვით private/loopback/link-local/ULA მასპინძლებს (IPv4** და** IPv6, მათ შორის IPv4-mapped) კანონიკური `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) მეშვეობით.
   - წყვეტს** ორივე** `A` და `AAAA` აღრიცხავს და უარყოფს თუ** ნებისმიერი** გადაწყვეტილი მისამართი არის პირადი — რომელიც ხურავს public-hostname → private-IP შემოვლით.
   - **ვერ დაიხურა** : DNS რეზოლუციის წარუმატებლობა უარყოფს URL ს.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): ხელახლა იყენებს მხოლოდ საჯარო URL მცველს მიღების დროს და** ბლოკავს გადამისამართებებს** (არ საჯარო → private `30x` pivot).

URL, რომელიც ვერ ახერხებს არცერთ ფენას, არ წყვეტს მოთხოვნას —

> ეს მცველი გამაგრდა PR #3774 ში სპეციალურად A + AAAA გადასაჭრელად და IPv4-only შემოწმების ნაცვლად კანონიკური `isPrivateHost` გამოსაყენებლად.

### დანამატის შესრულების იზოლაცია

> **დანამატები ნაგულისხმევად არ არის შეფუთული.** ბავშვი არის ჩვეულებრივი Node.js პროცესი, რომელიც მუშაობს როგორც OmniRoute მომხმარებელი, არ აქვს VM კონტექსტი და არ აქვს Node.js ნებართვის დროშები, ამიტომ მოდულის კოდს შეუძლია წაიკითხოს და დაწეროს ნებისმიერი ფაილი, რომელიც მომხმარებელს შეუძლია, გაუშვას პროგრამები და მიაღწიოს ქსელს. `requires.permissions` მხოლოდ წყვეტს გარემოს რომელ ცვლადებს მიიღებს ბავშვი; სხვა ნებართვები არ არის აღსრულებული. ჩართვა `PLUGIN_PERMISSION_MODEL_ENABLED` ფუნქციის დროშა (ნაგულისხმევად გამორთულია) აწარმოებს თითოეულ დანამატს ამ ნებართვებიდან აგებული Node.js ნებართვის მოდელის ქვეშ, გარდა `network`, რომელსაც Node.js ვერ ზღუდავს (იხ. [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#%E1%83%9C%E1%83%94%E1%83%91%E1%83%90%E1%83%A0%E1%83%97%E1%83%95%E1%83%94%E1%83%91%E1%83%98%E1%83%A1-%E1%83%A1%E1%83%98%E1%83%A1%E1%83%A2%E1%83%94%E1%83%9B%E1%83%90) ). დააინსტალირეთ მხოლოდ ის დანამატები, რომლებსაც ენდობით. ქვემოთ მოცემული პროცესის საზღვარი შეიცავს ავარიას და დაკიდებას; ეს არ არის უსაფრთხოების ზღვარი.

- **პროცესის იზოლაცია** — `loadPlugin()` (`src/lib/plugins/loader.ts`) აწარმოებს თითოეულ დანამატს ცალკე Node.js ბავშვის პროცესში და აკავშირებს IPC ზე. Hook-ის ზარებს აქვს ვადა `SIGTERM` → `SIGKILL` ესკალაციით.
- **Env ნებადართული სია** — ბავშვი იღებს მხოლოდ გარემოს ცვლადების დაშვებულ სიას; უფრო ფართო ნაკრები მიენიჭება მხოლოდ მაშინ, როდესაც manifest ითხოვს `env` ნებართვას.
- **დააინსტალირეთ წყაროს კონტეინერი** — `POST /api/plugins` კითხულობს მხოლოდ დანამატის წყაროების დირექტორიადან (იხ. "ინსტალაცია ლოკალური ბილიკიდან"): ბილიკი კანონიზირებულია `realpath` ით, მკაცრად უნდა დარჩეს ამ დირექტორიაში და წყაროს ხე, რომელსაც აქვს სიმბლაკი, რომელიც გაურბის მას, უარყოფილია, სანამ რაიმეს კოპირება მოხდება.
- **ბილიკის შეკავება** — install/upgrade/uninstall ამტკიცებს, რომ დანამატის დირექტორია და `manifest.main` წყვეტს** ფარგლებში** მართული დანამატის ფესვი ნებისმიერი ასლის ან რეკურსიული წაშლის წინ (იცავს DB გატეხილი ბილიკებისგან და `../` გადაკვეთისგან `manifest.main` ში). აქტივაცია აგვარებს symlink-ებს `realpath` საშუალებით და უარს ამბობს ჩატვირთვაზე შესვლის წერტილი, რომელიც გადის დანამატის დირექტორიაში.
- **სურვილისამებრ მთლიანობის პინი** — manifest-ს შეუძლია გამოაცხადოს `integrity` (`sha256-<base64>`, SRI ფორმატი) ველი. როდესაც არსებობს, ჩამტვირთველი ამოწმებს შესვლის ფაილის ჰეშს ჩატვირთვის დროს და უარს ამბობს გააქტიურებაზე შეუსაბამობის შემთხვევაში. ეს არის ნებაყოფლობითი გაყალბების გამოვლენა,** არა** უსაფრთხოების ზღვარი: ის არ ზღუდავს დატვირთულ დანამატს.
- **კაუჭებში კლიენტის სერთიფიკატები არ არის** — კონტექსტში, რომელიც გადავიდა `onRequest` ზე, `onResponse` და `onError` აქვს `authorization`, `x-api-key`, `proxy-authorization` და `cookie` სათაურები ამოღებული და API კლავიშის ჩანაწერს არ აქვს გასაღების მნიშვნელობა (`redactPluginContext()` in `src/lib/plugins/hooks.ts`).

| `description`      | სიმებიანი?   | ≤ 500 სიმბოლო                                                     |
| `author`           | სიმებიანი?   | ≤ 200 სიმბოლო                                                     |
| `license`          | სიმებიანი?   | ნაგულისხმევი `MIT`                                                |
| `main`             | სიმებიანი?   | შესვლის ფაილი; ნაგულისხმევია `index.js`                           |
| `source`           | სია?         | `local` \| `marketplace` (ნაგულისხმევი `local`)                   |
| `tags`             | სიმებიანი[]? | მოძებნეთ ტეგები                                                   |
| `requires`         | ობიექტი?     | `{ omniroute?, permissions[] }`                                   |
| `hooks`            | ობიექტი?     | Booleans აცხადებენ, რომელ კაკვებს ახორციელებს დანამატი            |
| `skills`           | ობიექტი[]?   | არჩევითი უნარების განმარტებები                                    |
| `enabledByDefault` | ლოგიკური?    | ავტომატური გააქტიურება ინსტალაციისას                              |
| `configSchema`     | ობიექტი?     | კონფიგურაციის ველების რუკა (`string`/`number`/`boolean`/`select`) |
| `integrity`        | სიმებიანი?   | სურვილისამებრ `sha256-<base64>` შესვლის ფაილის პინი               |

ნებართვები აღებულია enum `network` / `file-read` / `file-write` / `env` / `exec`. მხოლოდ `env` აქვს გაშვების ეფექტი (ოდნავ უფრო დიდი გარემოს ცვლადი დასაშვები სია ბავშვისთვის); დანარჩენები დეკლარაციებია და არ სრულდება.

## სასიცოცხლო ციკლის მიმდინარეობა

```
ინსტალაცია (POST /api/plugins, გზა)
  → მანიფესტის სკანირება/ვალიდაცია → დროებით საცავში კოპირება → შემოწმება, რომ main დირექტორიის შიგნითაა
  → ატომარული სახელის გადარქმევა ~/.omniroute/plugins/<name>-ში → ჩანაწერის დამატება DB-ში
  → onInstall-ის გამოძახება → თუ enabledByDefault: აქტივაცია

აქტივაცია (POST /api/plugins/{name}/activate)
  → realpath-ის მოქცევის შემოწმება → loadPlugin() (შვილობილი პროცესის გაშვება)
  → დეკლარირებული ჰუკების რეგისტრაცია → status = "active" → onActivate-ის გამოძახება

დეაქტივაცია (POST /api/plugins/{name}/deactivate)
  → onDeactivate-ის გამოძახება (რეგისტრაციის გაუქმებამდე) → ჰუკების რეგისტრაციის გაუქმება
  → შვილობილი პროცესის შეწყვეტა → status = "inactive"

დეინსტალაცია (DELETE /api/plugins/{name})
  → თუ აქტიურია, დეაქტივაცია → onUninstall-ის გამოძახება
  → პლაგინის დირექტორიის მოქცევის შემოწმებით რეკურსიული წაშლა → ჩანაწერის წაშლა DB-დან
```

`install`-ის ხელახლა გაშვება დირექტორიაზე, რომლის მანიფესტის ვერსია დაინსტალირებულ ვერსიაზე **მკაცრად
უფრო ახალია**, ავტომატურად ასრულებს განახლებას (სუფთა ხელახალი ინსტალაცია; კონფიგურაცია
ნაგულისხმევ მნიშვნელობებზე ბრუნდება). იგივე ან უფრო ძველი ვერსია უარყოფილი იქნება.

## დაფა

დაფის გვერდი `/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) შეიცავს ორ ჩანართს:

- **დაყენებულია** — ჩამოთვლის დაინსტალირებულ დანამატებს მათი დეკლარირებული კაუჭებით, activate/deactivate გადართვით, დეინსტალაციის ღილაკით და „დამატებების სკანირების“ მოქმედებით (`POST /api/plugins/scan`).
- **ბაზარი** — აჩვენებს კატალოგს `GET /api/plugins/marketplace` დან ველით, რომ დააყენოთ საბაჟო რეესტრი URL.

გვერდი ყოველთვის აჩვენებს გაფრთხილებას, რომ დანამატები მუშაობენ OmniRoute პროცესის სრული პრივილეგიებით.

თითო დანამატის კონფიგურაციის გვერდი ცხოვრობს `/dashboard/plugins/[name]/config` ზე (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`).
