## დააყენეთ დამსუფთავებელი (ერთჯერადად, სერვერზე)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ყოველ 30 წუთში, ჟურნალი ჩაიწეროს /var/log/runner-janitor.log-ში
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` აუცილებელია: წაშლამდე დამსუფთავებელი გახსნილი ფაილების ერთი სურათით
ადასტურებს, რომ ბილიკი უმოქმედოა, ხოლო ამ ხელსაწყოს გარეშე არაფერს შლის და ამის
შესახებაც გაცნობებთ (exit 1). ნებისმიერი ცვლილება ჯერ `--dry-run`-ით სცადეთ —
ის ზუსტად დაბეჭდავს, რას გააკეთებდა, და არაფერს შეცვლის.

რას აკეთებს ყოველი გაშვებისას: ასუფთავებს ჩვენსავე ნარჩენებს (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) **tmpfs-ზე 3 სთ-ის**, ხოლო დისკზე
`_work/_temp`-ში 24 სთ-ის შემდეგ; წყვეტს 75 წუთზე ძველ `next-build`-ს (არცერთი
დავალება ამდენ ხანს არ სრულდება — 2026-08-27-ს ერთი მათგანი 70 წუთის განმავლობაში
მუშაობდა მას შემდეგ, რაც GitHub-მა მისი დავალება დაკარგულად გამოაცხადა); შლის იმ
runner-ების 48 საათის checkout-ებს, რომელთა unit-იც **შეჩერებულია**; აგზავნის
გაფრთხილებას, თუ დისკი ≥ 85 %-ითაა შევსებული, მეხსიერების PSI `full/avg60` ≥ 10 %-ია,
ან listener-ების რაოდენობა `MAX_ACTIVE_RUNNERS`-ს აღემატება (omniroute/other
განაწილებით). Exit 1 = ყურადღებაა საჭირო; წაიკითხეთ ჟურნალი.

75-წუთიანი წესი ვერ აფიქსირებს build-ს, რომლის დავალებაზეც GitHub-მა უკვე ხელი ჩაიქნია. როდესაც
`Runner.Listener` თავის დავალებას ვეღარ განაახლებს, `_diag/Runner_*.log`-ში ჩანს
`POST request to …/renewjob timed out after 100 seconds`, API კი ბოლო წარმატებული განახლებიდან
დაახლოებით ათ წუთში დავალებას `completed`-ად (failure) აღნიშნავს, ხოლო `next-build` მუშაობას
მიბმული დავალების გარეშე აგრძელებს (2026-10-18: #17066-ის Build 19:43-ზე ჩავარდნილად
მოინიშნა, თუმცა ხუთი წუთის შემდეგ მისი build ჯერ კიდევ 40 GB-ს იკავებდა). უახლეს
`_diag/Worker_*.log`-ში ref გადაამოწმეთ, შემდეგ PID-ის მიხედვით SIGTERM გაუგზავნეთ მხოლოდ
build-ის ხეს — `next-build`, `npm run build`, `build-next-isolated.mjs` და
`_work`-ის worker-ები. არასოდეს შეეხოთ `Runner.Listener`-ს, `RunnerService.js`-ს ან

ონლაინ რეჟიმში.

## Runner-ის unit-ები: KillMode

Runner-ის ნაგულისხმევი `KillMode=process` unit-ის შეჩერების ან გადატვირთვისას
`Runner.Worker → npm → next-build`-ს ცოცხალს ტოვებს — ობოლი build მიბმული დავალების
გარეშე აგრძელებს RAM-ისა და CPU-ის მოხმარებას. OmniRoute-ის ყველა unit-ს აქვს drop-in
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
`KillMode=mixed`-ით: ჯერ listener-ს ეგზავნება SIGTERM, ხოლო `TimeoutStop`-ისას
მთელ cgroup-ს — SIGKILL. ის ძალაში unit-ის მომდევნო გადატვირთვისას შევა — ერთ ჯერზე
გადატვირთეთ **მხოლოდ ერთი runner და მხოლოდ მაშინ, როცა ის უმოქმედოა**, ამასთან,
უმოქმედობის შემოწმება და გადატვირთვა ერთსა და იმავე ბრძანებაში შეასრულეთ.
