`devin-cli-agentic` საშუალებას აძლევს რეალურ Claude Code runtime-ს გამოიყენოს OmniRoute-ის ლოკალური Anthropic
Messages endpoint, ხოლო ოფიციალური Devin CLI მოდელის პასუხებს ACP stdio-ის მეშვეობით აწვდის. ის
არ ცვლის არსებულ Anthropic, Claude OAuth, Claude Web ან `devin-cli` provider-ებს.

კლიენტის მიერ მართული ხელსაწყოების გამოძახებებისთვის მოთხოვნები გაატარეთ `devin-cli-agentic`-ის (alias `dva`) გავლით —
ეს არის Claude-ის ფორმატის, ხელსაწყოების მხარდაჭერის მქონე provider. ძველი `devin-cli` (`dv`) ACP executor
მხოლოდ ტექსტურია: ის უშვებს Devin-ის ხელსაწყოების გარეშე მომუშავე summarizer-ს და ხელსაწყოების გამოძახებებს ვერ აბრუნებს. მისი მოდელის
metadata შესაბამისად არის მონიშნული, რათა ხელსაწყოების მომთხოვნმა combo routing-მა მას გვერდი აუაროს.

> **მიმდინარე სტატუსი: ფიქსირებული Claude Code `2.1.258`; offline და live ვალიდაცია ბოლოს
> `2.1.220`-ზე დაფიქსირდა.** `2.1.220`-ის ფიქსირებულმა ვერსიამ Devin CLI

> `Edit` და `Bash` ეტაპები, `npm test`-ის წარმატებული შედეგები, პროექტის command-ებისა და skill-ების
> აღმოჩენა, მხოლოდ Devin-ის გავლით routing და Claude-ისკენ ნულოვანი გამავალი ტრაფიკი. შემდეგ ფიქსირებული ვერსია `2.1.258`-მდე
> განახლდა (ეს არის CLI-ის თაობა, რომლის Claude-ის იდენტობასაც OmniRoute ასახიერებს, და პირველი ხაზი, რომელიც
> Fable 5.1 დონეს ნატიურად შეიცავს). ახალ ფიქსირებულ ვერსიაზე ინსტალაციის ფენა და `claude --version`

> suite ჯერ ხელახლა არ გაშვებულა. ამ ფიქსირებულ ვერსიასთან bridge-ის გამოყენებამდე ისინი ხელახლა გაუშვით
> (იხილეთ „ფიქსირებული ხელსაწყოების განახლება“).

## არქიტექტურა

```text
Claude Code 2.1.258 (იზოლირებულ non-root Linux კონტეინერში)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-ის ფორმატი, ავთენტიკაციის არმომთხოვნი provider)
  -> devin acp --agent-type summarizer (ოფიციალური ACP stdio, Devin-ის ხელსაწყოების გარეშე)
  -> Devin-ის ანგარიში გამოყოფილ devin-auth volume-ში
```

ოფიციალური CLI-ის ნაგულისხმევ ACP agent-ს საკუთარი ხელსაწყოების შესრულება შეუძლია, ამიტომ ეს bridge მას არ
იყენებს. ის უშვებს ფიქსირებულ `summarizer` ACP agent-ს, რომლის ოფიციალურ CLI რეჟიმსაც ხელსაწყოები არ აქვს, და
სერიალიზებულ Anthropic მოთხოვნას შესრულების ტრასის სახით აფორმებს. როდესაც Claude-ის მიერ მართული სხვა
ქმედებაა საჭირო, პასუხი ზუსტად ერთ კლიენტის ხელსაწყოს envelope-ს უნდა შეიცავდეს. ნებისმიერი ACP
`tool_call` ან `tool_call_update` უარყოფილი იქნება, სანამ პასუხი წარმატებულად გამოცხადდება.

`open-sse/executors/devin-agentic/serializer.ts`-ში არსებული serializer ინარჩუნებს `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`-სა და Claude Code-ის მიერ
მოწოდებულ ხელსაწყოებს. Images და უცნობი blocks აშკარა შეცდომით სრულდება. ხელსაწყოების დიდი შედეგები
ხილულ truncation marker-ს იყენებს.

Parser თითოეული model turn-ისთვის იღებს ერთ დამოუკიდებელ `<tool>{...}</tool>` envelope-ს. ის
სახელს მოთხოვნის ხელსაწყოების სიასთან ამოწმებს, არგუმენტებს ამ ხელსაწყოს JSON
Schema-ს მიხედვით ამოწმებს, შერეულ ნარატივსა და ქმედებებს უარყოფს და ერთ შეზღუდულ გამოსწორების მცდელობას უშვებს. შემდეგ Claude Code
მიღებულ Anthropic `tool_use`-ს ლოკალურად ასრულებს და `tool_result`-ს OmniRoute-ის გავლით
უკან აგზავნის.

## ავტომატური routing

თუ provider დაბლოკილი არ არის, მისი გამოყენება შესაძლებელია OmniRoute-ის `auto/*` candidate pool-ებში.
Candidate-ის შესაბამისობა არჩევას არ უზრუნველყოფს: combo-ის routing strategy-მ (მაგალითად,
last-known-good) შესაძლოა უპირატესობა სხვა provider-ს მიანიჭოს. როდესაც აუცილებელია, რომ
ყველა მოთხოვნა Devin-ის გავლით გაიგზავნოს, გამოიყენეთ `dva/<model>` ან Devin-first combo.

## იზოლაცია და საფრთხეების მოდელი

ჰოსტის Claude-ის ინსტალაცია, ანგარიში და კონფიგურაცია განხილვის ფარგლებს გარეთაა და აკრძალულად ითვლება. Compose-ის სერვისები:

- მუშაობს UID/GID `10001:10001`-ით, მხოლოდ წაკითხვადი ძირეული ფაილური სისტემით, გაუქმებული შესაძლებლობებითა და
  `no-new-privileges`-ით;
- იყენებს კერძო `/home/bridge`-ს, Claude-ის კონფიგურაციის გამოყოფილ ტომს, იზოლირებულ OmniRoute-ის მონაცემებსა
  და ცალკე `devin-auth` ტომს;
- ამონტაჟებს მხოლოდ ერთჯერად `.sandbox` სამუშაო სივრცეებს/მტკიცებულებებს;
- არ ამონტაჟებს ჰოსტის მთავარ საქაღალდეს, Keychain-ს, SSH-ს, ღრუბლოვან ავტორიზაციის მონაცემებს ან Docker-ის სოკეტს;
- ქმნის მკაფიოდ განსაზღვრულ გარემოებს და შლის Anthropic-ის API/OAuth/მარშრუტიზაციის ცვლადებს;
- Claude Code-ის ინფერენციას მიმართავს მხოლოდ `http://omniroute:20128`-ზე, მხოლოდ ლოკალური გასაღებით.

ოფლაინ-პროფილი შიდა ქსელს იყენებს. ცოცხალ პროფილში OmniRoute ოფიციალურ Devin-ის საბოლოო წერტილებს მხოლოდ `network-guard`-ის გავლით უკავშირდება; სხვა დანიშნულების მისამართებზე წვდომა აკრძალულია.
Claude Code-ს აქვს ცალკე, ყველა გამავალი კავშირის ამკრძალავი დამცავი და მხოლოდ ლოკალურ OmniRoute-ის
სერვისთან დაკავშირება შეუძლია `NO_PROXY`-ის მეშვეობით. დამცავების აუდიტის ფაილები მხოლოდ შესაბამის დამცავ პროცესშია დამონტაჟებული. სკრიპტები ამოწმებს ფაილის მფლობელობას, რეჟიმს, ბმულების რაოდენობასა და თითოეულ გადაწყვეტილებას, სანამ
ტოკენებისგან თავისუფალ მტკიცებულებებს გაიტანს.

იზოლაციის მტკიცებულება დამოუკიდებლად გაუშვით:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

ის ამოწმებს ტოპოლოგიას, სახელდებულ დამონტაჟებებს, არა-root/მხოლოდ წაკითხვის პარამეტრებს, მკაფიო ლოკალურ მარშრუტიზაციას,
სენსიტიური გარემოს ცვლადების არარსებობას, Docker-ის სოკეტის არარსებობას, `api.anthropic.com`-სა და `claude.ai`-ზე
დაბლოკილ წვდომას, მხოლოდ Devin-ის პროვაიდერის არჩევას და აშკარა შეცდომას, როდესაც ACP-ის ბეკენდი მიუწვდომელია.

## საწყისი გამართვა და ჩვეულებრივი გამოყენება

ააგეთ დაფიქსირებულ ვერსიაზე მიბმული იმიჯი:

```bash
./scripts/devin-bridge/build
```

ავთენტიფიკაცია ჩაუტარეთ მხოლოდ იზოლირებულ Devin-ის ტომს:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

შესვლის ბრძანება იყენებს ოფიციალურ, ხელით შესაყვანი ტოკენის პროცესს, რომელიც დისტანციური/კონტეინერული
გარემოებისთვისაა განკუთვნილი. მნიშვნელობა უშუალოდ CLI-ის მოთხოვნაში შეიყვანება; ის არ გადაიცემა
პროცესის არგუმენტად, არ იწერება Git-ში და არ კოპირდება ჰოსტიდან.

გაუშვით იზოლირებული Claude Code-ის გაშვების გარემო:

```bash
./scripts/devin-bridge/launch
```

`launch` კონტეინერიზებული Claude Code-ის გაშვებამდე ხელახლა ამოწმებს იზოლაციას, Devin-ის ავთენტიფიკაციასა და მოდელების აღმოჩენას.
ის არასოდეს უშვებს ჰოსტზე არსებულ Claude-ის შესრულებად ფაილს. მოდელის ფსევდონიმების დაყენება შესაძლებელია
`.env.devin-bridge`-ში; ყველა კონფიგურირებულმა მნიშვნელობამ უნდა შეინარჩუნოს
`devin-cli-agentic/` პრეფიქსი.

## ვალიდაციის ბრძანებები

რეპროდუცირებად ოფლაინ-გზას Devin-ის ანგარიში არ სჭირდება და შესრულების დროს ინტერნეტზე წვდომა არ აქვს:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

ავთენტიფიცირებული, ცალკე ჩასართავი ცოცხალი გზა არის:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ცოცხალი ტესტების გამშვები სცენარებს შორის იცდის, რათა ACP-ის სესიები ერთბაშად არ გახსნას, და
ტექსტური მტკიცებების ნდობის ნაცვლად Claude-ის ნაკადის სტრუქტურირებულ მოვლენებს ამოწმებს. მისი სამი
სცენარი ადასტურებს:

1. პროექტის ფაილების უშუალო წაკითხვასა და დეფექტების ანალიზს;
2. რეალურ `Edit`-ს, კლიენტის მიერ მართულ `Bash` `npm test`-სა და ტერმინალურ შედეგს;
3. `/bridge-check`-სა და `bridge-proof`-ის აღმოჩენას, პროექტის ფაილების წაკითხვას, კლიენტის მიერ მართულ კიდევ ერთ წარმატებულ
   `npm test`-სა და დასრულებას დარჩენილი სამუშაოს გარეშე.

საბოლოო საკონტროლო ეტაპი ასევე ამოწმებს Devin-ის ქსელის აუდიტს და მოითხოვს, რომ Claude-ის გამავალი კავშირების აუდიტი
ცარიელი დარჩეს.

## ფიქსირებული ხელსაწყოების განახლება

იმიჯში Node, Claude Code და Devin CLI ფიქსირებულია
`docker/devin-bridge/Dockerfile`-ში. განახლებისთვის:

1. შეცვალეთ ცალსახად მითითებული ვერსიები;
2. არქიტექტურისთვის სპეციფიკური Devin-ის არქივის ორივე საკონტროლო ჯამი ჩაანაცვლეთ ოფიციალური
   არტეფაქტის მნიშვნელობებით;
3. ხელახლა ააგეთ იმიჯი და გაუშვით ოფლაინ-ვალიდაციის ყველა ბრძანება;
4. დაადასტურეთ ვერსიები იმიჯის შიგნით;
5. ხელახლა გაუშვით ავტორიზებული, სამი სცენარისგან შემდგარი ცოცხალი ტესტების ნაკრები.

არცერთი CLI არ დააინსტალიროთ გლობალურად ჰოსტზე და საკონტროლო ჯამის შემოწმება არ
ჩაანაცვლოთ შეუმოწმებელი ჩამოტვირთვით.
