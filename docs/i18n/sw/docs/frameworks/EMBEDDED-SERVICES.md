Wote wanane wanafuata modeli sawa ya usimamizi:

- OmniRoute huziweka chini ya `DATA_DIR/services/{name}/` (zilizotengwa na OmniRoute mwenyewe `package.json`)
- OmniRoute huzaa na kuzifuatilia kama mchakato wa mtoto
- OmniRoute huingiza ufunguo wa API wa muda mfupi kwenye mazingira ya mtoto na kuzungusha bila muda wa kupumzika (inapohitajika)
- Njia zote za usimamizi (`/api/services/*`) ni**LOCAL_ONLY** — kupatikana tu kutoka kwa loopback (sheria ngumu # 17)

## 2. Usanifu — 4 tabaka

```
┌────────────────────────────────────────────────────────────────────┐
│  Layer 1 — UI                                                      │
│  /dashboard/providers/services  (tabs: CLIProxyAPI | 9Router | Mux)│
│  Logs live (SSE), Start/Stop/Restart/Update, Settings, Install     │
│                                                                    │
│  src/app/(dashboard)/dashboard/providers/services/                 │
│    ├── page.tsx               Shell + tab routing by ?tab=         │
│    ├── tabs/                  CliproxyServiceTab, NinerouterServiceTab,│
│    │                          MuxServiceTab                        │
│    └── components/            ServiceStatusCard, ServiceLifecycleButtons,│
│                               ServiceLogsPanel, ApiKeyCard, ...    │
└──────────────────────┬─────────────────────────────────────────────┘
                       │ HTTP (Next.js fetch)
┌──────────────────────▼─────────────────────────────────────────────┐
│  Layer 2 — API (LOCAL_ONLY — loopback only)                        │
│                                                                    │
│  /api/services/9router/{install|start|stop|restart|update|         │
│                          rotate-key|status|auto-start|logs}        │
│  /api/services/cliproxy/{install|start|stop|restart|update|        │
│                           status|auto-start|logs}                  │
│  /api/services/mux/{install|start|stop|restart|update|             │
│                      status|auto-start|logs}                       │
│  /dashboard/providers/services/9router/embed/[...path]             │
│    (reverse HTTP + WebSocket proxy → 9Router upstream)             │
│                                                                    │
│  Gate: LOCAL_ONLY_API_PREFIXES includes "/api/services/" and       │
│        "/dashboard/providers/services/*/embed/"                    │
└──────────────────────┬─────────────────────────────────────────────┘
                       │ in-process calls
┌──────────────────────▼─────────────────────────────────────────────┐
│  Layer 3 — ServiceSupervisor (src/lib/services/)                   │
│                                                                    │
│  ServiceSupervisor.ts   Generic supervisor (child_process.spawn)   │
│    ├── install:    execFile('npm', ['install', pkg, '--prefix'])    │
│    ├── start:      spawn(node, [entrypoint], {env, cwd})           │
│    ├── api_key:    crypto.randomBytes(32) → env NINEROUTER_API_KEY  │
│    ├── port:       20130 for 9Router (configurable)                │
│    ├── logs:       stdio ring buffer 5 MB → SSE events             │
│    ├── health:     HTTP GET /health every 2–5 s, lazy recovery     │
│    └── lifecycle:  SIGTERM 15 s → SIGKILL                          │
│                                                                    │
│  registry.ts        getSupervisor(name) / registerSupervisor()     │
│  bootstrap.ts       Bootstraps all SERVICES[] at process start     │
│  apiKey.ts          getOrCreateApiKey(), generateServiceApiKey()   │
│  modelSync.ts       Periodic GET /v1/models → service_models table │
│  ringBuffer.ts      Circular log buffer (5 MB per service)         │
│  healthCheck.ts     Polling HTTP health probe                      │
│  installers/        ninerouter.ts, cliproxy.ts, mux.ts, openwa.ts  │
│                      (installer adapters)                          │
└──────────────────────┬─────────────────────────────────────────────┘
                       │ OpenAI-compatible HTTP (loopback)
┌──────────────────────▼─────────────────────────────────────────────┐
│  Layer 4 — Provider / Routing                                      │
│                                                                    │
│  open-sse/executors/ninerouter.ts                                  │
│    Re-looks up port and API key per-request (no caching).          │
│    Strips "9router/" prefix from model id before proxying.         │
│    Returns 503 service_not_running if supervisor not in "running". │
│                                                                    │
│  src/shared/constants/providers.ts                                 │
│    Entry for "9router": isEmbeddedService: true                    │
│                                                                    │
│  open-sse/config/providerRegistry.ts                               │
│    Models stored as "9router/{sub}/{model}" (prefixed).            │
│    Synced every 5 min by modelSync.ts.                             │
│                                                                    │
│  Mux is lifecycle-managed ONLY (Layers 1-3) — it is an agent-       │
│  orchestration daemon, not an LLM proxy, so it has no Layer 4      │
│  executor/provider entry and is never a routing target.            │
└────────────────────────────────────────────────────────────────────┘
```

## 3. Mashine ya hali ya mzunguko wa maisha

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
            uchunguzi wa afya sawa  │         hitilafu / SIGTERM│
                               ┌────▼─────┐  (hutoka ndani ya s 5)│
                               │ running  │─── hitilafu ─────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

Hali huhifadhiwa katika jedwali la DB la `version_manager` (safu ya `status`) na huakisiwa
katika hali ya ndani ya kumbukumbu ya `ServiceSupervisor`. Hali ya ndani ya kumbukumbu ndiyo yenye mamlaka kwa
mchakato unaoendelea; hali ya DB ndiyo mbadala endelevu wakati wa kuwasha mfumo.

### Mabadiliko ya hali

| Kutoka          | Tukio                                        | Kwenda                       |
| --------------- | -------------------------------------------- | ---------------------------- |
| `not_installed` | `install()` inafanikiwa                      | `stopped`                    |
| `stopped`       | `start()` inaitwa                            | `starting`                   |
| `starting`      | uchunguzi wa afya unarudisha 200             | `running`                    |
| `starting`      | mchakato unatoka kabla ya kuwa salama kiafya | `error`                      |
| `running`       | `stop()` inaitwa                             | `stopping` → `stopped`       |
| `running`       | mchakato unatoka bila kutarajiwa (< s 5)     | `error` (hitilafu ya haraka) |
| `running`       | mchakato unatoka bila kutarajiwa (> s 5)     | `error`                      |
| `error`         | `start()` inaitwa                            | `starting`                   |
| yoyote          | `stop()` wakati wa `stopping`                | hakuna operesheni            |

### Kufuli ya operesheni

`ServiceSupervisor` hupanga operesheni za mzunguko wa maisha kwa mfuatano kupitia kufuli ya operesheni isiyosawazishwa
(`withLock()`). Miito ya wakati mmoja ya `start()` kwenye msimamizi yuleyule husababisha
uanzishaji wa mchakato mmoja tu; mwitaji wa pili husubiri na kurudisha hali iliyopo. Hii huzuia
hali za mashindano wakati, kwa mfano, uanzishaji otomatiki na kitufe cha UI vinapotumika kwa wakati mmoja.

## 4. kumbukumbu ya API

Njia zote chini ya `/api/services/` ni**LOCAL_ONLY** (Loopback tu, kanuni ngumu #17). Maombi yasiyo ya kitanzi hupokea `403 LOCAL_ONLY` bila kujali tokeni ya uthibitishaji.

### 4.1 9Njia za mwisho za njia (njia 11)

#### `POST /api/services/9router/install`

Sakinisha 9Router kutoka npm. Huunda `DATA_DIR/services/9router/` na `package.json` yake na `node_modules/`. Haipingani na deps za OmniRoute mwenyewe.

**Omba mwili** (yote ni hiari):

```json
{ "version": "latest" }
```

| Shamba    | Aina     | Chaguomsingi | Maelezo                                    |
| --------- | -------- | ------------ | ------------------------------------------ |
| `version` | `string` | `"latest"`   | npm toleo la lebo au semver ya kusakinisha |

**Majibu:**

| Hali  | Maelezo                                                                 |
| ----- | ----------------------------------------------------------------------- |
| `200` | `{ ok: true, installedVersion: "x.y.z", path: "..." }`                  |
| `400` | Mwili batili wa ombi (Zod uthibitishaji umeshindwa)                     |
| `409` | Tayari inasakinisha (kufuli imeshikiliwa)                               |
| `500` | npm kusakinisha kumeshindwa — tazama `message` kwa hitilafu ya kirafiki |

**Vidokezo:** Hutumia `execFile('npm', [...])` — hakuna ganda, hakuna tafsiri (kanuni ngumu # 13). makosa EACCES yanaonekana kama ujumbe wa kirafiki.

---

#### `POST /api/services/9router/start`

Anzisha 9Router. Husajili msimamizi ikiwa bado hajasajiliwa, kisha piga simu `supervisor.start()`. Kutokuwa na uwezo wakati tayari unaendesha.

**Mwili wa ombi:** hakuna

**Majibu:**

| Hali  | Maelezo                                                    |
| ----- | ---------------------------------------------------------- |
| `200` | `ServiceStatus` kitu (tazama schema hapa chini)            |
| `409` | 9Router haijasakinishwa (`status: "not_installed"`)        |
| `503` | Kuanza kumeshindwa (kosa la mchakato — tazama `lastError`) |

**ServiceStatus schema:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

---

#### `POST /api/services/9router/stop`

Acha kwa neema 9Router. Hutuma SIGTERM, subiri sekunde 15, kisha SIGKILL ikiwa bado hai. Kutokuwa na uwezo wakati tayari kumesimamishwa.

**Mwili wa ombi:** hakuna

**Majibu:**

| Hali  | Maelezo                                 |
| ----- | --------------------------------------- |
| `200` | `ServiceStatus` (jimbo: "kusimamishwa") |
| `503` | Kuacha kumeshindwa bila kutarajiwa      |

---

#### `POST /api/services/9router/restart`

Sawa na `stop()` kisha `start()` chini ya kufuli ya operesheni.

**Mwili wa ombi:** hakuna

**Majibu:** sawa na `start` (inarudisha `ServiceStatus` ya mwisho).

---

#### `POST /api/services/9router/update`

Inasasisha 9Router hadi toleo jipya zaidi la npm. Ikiwa huduma inaendesha, imesimamishwa kwanza, npm install inaendeshwa (kusanikisha toleo jipya zaidi mahali), na kisha huduma inaanza tena.

**Omba mwili** (yote ni hiari):

```json
{ "version": "latest" }
```

**Majibu:**

| Hali  | Maelezo                                                         |
| ----- | --------------------------------------------------------------- |
| `200` | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400` | Mwili batili                                                    |
| `500` | sasisho la npm limeshindwa                                      |

## 5. Usalama

### Utekelezaji wa LOCAL_ONLY (kanuni thabiti #17)

Njia zote zilizo chini ya `/api/services/` na `/dashboard/providers/services/*/embed/`
zinaainishwa kama LOCAL_ONLY katika `src/server/authz/routeGuard.ts`. Ukaguzi wa loopback
huendeshwa bila masharti kabla ya tawi lolote la uthibitishaji:

```
ombi linawasili
  → isLocalOnlyPath(path)?
      → si loopback → 403 LOCAL_ONLY (daima, kabla ya ukaguzi wa uthibitishaji)
      → loopback    → endelea hadi uthibitishaji wa kawaida
```

Hii huzuia JWT iliyovuja (kwa mfano, kupitia tunnel) kuanzisha `npm install` au
kuanzisha michakato. Tazama `docs/security/ROUTE_GUARD_TIERS.md` kwa matriki kamili
ya viwango.

### Uingizaji wa ufunguo wa API

9Router na Mux zinahitaji ufunguo wa API/tokeni ya bearer kwa endpoint zao za HTTP.
OmniRoute:

1. Hutengeneza ufunguo kupitia `crypto.randomBytes(32).toString("base64url")` wenye
   kiambishi awali mahususi kwa huduma (`nr_` kwa 9Router, `mx_` kwa Mux).
2. Huusimba kwa njia fiche ukiwa umehifadhiwa kwa kutumia AES-256-GCM (algoriti ileile ya usimbaji inayotumika kwa vitambulisho vya watoa huduma).
3. Huusimbua na kuuingiza kama kigezo cha mazingira wakati wa kuanzisha mchakato —
   `NINEROUTER_API_KEY` kwa 9Router, `MUX_SERVER_AUTH_TOKEN` kwa Mux (kamwe si chaguo la CLI,
   hivyo tokeni haionekani kamwe katika `ps`/orodha za michakato).
4. Hairudishi kamwe ufunguo wa maandishi wazi katika jibu lolote la HTTP.

CLIProxyAPI hupokea ufunguo maalumu wa data-plane unaoingizwa wakati wa kuanzisha mchakato
(`needsApiKey: true` — hutumika kwa ulandanishaji wa modeli dhidi ya adapter).

### Ulinzi dhidi ya SSRF

Proksi ya HTTP ya kinyume (`/dashboard/.../embed/[...path]`) imewekwa moja kwa moja kuelekeza
tu kwa `http://127.0.0.1:{port}`. Haifuati kamwe uelekezaji upya kwenda kwenye
maeneo yasiyo ya loopback. Maktaba ya `ssrf-req-filter` hutumika kukataa URL yoyote ya upstream ambayo
hutatuliwa nje ya masafa ya loopback.

### Usalama wa shell (kanuni thabiti #13)

`npm install` huitwa kupitia `execFile('npm', ['install', pkg, '--prefix', dir])` —
hakuna template literals, hakuna shell, wala uingizaji wa njia za nje katika mfuatano wa
amri. Thamani za wakati wa utekelezaji (porti, funguo za API) hupitishwa kupitia kitu cha `env` cha mchakato mtoto.

### Usafishaji wa hitilafu (kanuni thabiti #12)

Majibu yote ya hitilafu kutoka `/api/services/*` hupitia `buildErrorBody()` au
`sanitizeErrorMessage()`. `err.stack` na `err.message` ghafi hazirudishwi kamwe
kama zilivyo kwa mwombaji.

#### Mkataba wa provider-plugin unaoweza kuchomekwa (Awamu ya 1, #7333)

`src/lib/services/providerPlugins/` inaanzisha mkataba wa `ServiceProviderPlugin` ambao
huunganisha sehemu za `ServiceEntry` za `bootstrap.ts` ya backend na sehemu za kiolezo cha manifest za `serviceBackends.ts`

zinasalia bila kubadilishwa kwenye literal za `SERVICES[]` za ndani zilizokuwepo awali.

`createServiceBackendManifestEntry(pluginId, template)` ambacho huunda
`ProviderPluginManifestEntry` yenye muundo sahihi kutoka kwenye ingizo la `SERVICE_BACKEND_MANIFEST_TEMPLATE` — **bado
hakijaunganishwa** kwenye njia yoyote hai ya maombi (si `generateProviderPluginManifestFromRegistry()`
wala `/v1/providers/[provider]/models`); hilo litasubiri kazi ya ufuatiliaji baada ya mkataba
kuthibitishwa kwa backend ya pili.

Yaliyoahirishwa hadi PR za ufuatiliaji, yanayofuatiliwa chini ya suala #7333: kuhamisha `cliproxyapi` kupitia
registry ileile, kufanya `mux`/`bifrost` kuwa za jumla ndani ya muungano wa `ServiceBackendPluginId`,
kuunganisha hali maalumu za uelekezaji wa executor (`open-sse/executors/index.ts`,
`open-sse/handlers/chatCore/executorProxy.ts`) ndani ya mkataba wa plugin, na kuunganisha
`createServiceBackendManifestEntry()` kwenye njia hai ya msimbo ya manifest/modeli.

## 7. Utatuzi wa matatizo

### Huduma haianzi

**Dalili:** Kitufe cha kuanzisha kinarejesha 503, hali inabaki `"error"` au `"starting"`.

**Orodha ya ukaguzi:**

1. Angalia `GET /api/services/{name}/logs` (au paneli ya Kumbukumbu kwenye dashibodi). Tafuta
   mistari kama `Error: ENOENT`, `address already in use`, au `Cannot find module`.
2. Thibitisha kuwa `npm` iko katika PATH: tumia `which npm` kutoka kwenye akaunti ileile ya mtumiaji inayoendesha OmniRoute.
3. Thibitisha kuwa huduma imesakinishwa: angalia `GET /api/services/{name}/status` kwa
   `installedVersion`. Ikiwa ni `null`, endesha usakinishaji kwanza.
4. Angalia kuwa `DATA_DIR/services/{name}/node_modules/` ipo na si tupu.
5. Angalia uga wa `lastError` katika jibu la hali ili kuona sababu ya kusitishwa iliyosafishwa.

---

### Uanzishaji wa kwanza ni wa polepole (> sekunde 10 kufikia `running`)

**Dalili:** Hali inabaki `"starting"` kwa muda mrefu kabla ya kubadilika kuwa `"running"` au `"error"`.

**Maelezo:** Uanzishaji wa kwanza wa 9Router unajumuisha kuleta miti mikubwa ya vitegemezi (DNS,
tunnel, moduli za MITM). Kipindi chaguo-msingi cha ukaguzi wa afya ni sekunde 2, huku majaribio 3 yakifanywa kabla
msimamizi hajatangaza kuisha kwa muda (lakini anaendelea kufanya ukaguzi).

**Suluhisho:** `healthIntervalMs` na muda wa kuisha wa `waitForHealthy`
(`healthIntervalMs * 3`) zinaweza kusanidiwa katika `bootstrap.ts`. Kwa huduma zenye muda mrefu zaidi
wa kuanza, ongeza `healthIntervalMs` hadi 5000 na `stopTimeoutMs` hadi 30 000.

---

### Mgongano wa mlango (`EADDRINUSE`)

**Dalili:** Kumbukumbu zinaonyesha `address already in use :::20130`.

**Sababu:**

- Mchakato mwingine tayari unatumia mlango 20130.
- Mchakato wa awali wa 9Router haukusimamishwa kikamilifu (PID mfu).

**Suluhisho:**

1. Badilisha mlango chaguo-msingi kupitia kigezo cha mazingira cha `NINEROUTER_PORT` katika `.env`.
2. Tafuta na usitishe mchakato unaogongana: `lsof -ti :20130 | xargs kill -9`.
3. Mlango unaweza kusanidiwa kwa kila huduma katika `bootstrap.ts` kupitia uga wa `port`.

**Kumbuka:** 9Router hutumia mlango 20130 kwa chaguo-msingi mahsusi ili kuepuka kugongana na
mlango chaguo-msingi wa OmniRoute wa 20128.

---

### Ruhusa imekataliwa (EACCES) wakati wa usakinishaji

**Dalili:** Usakinishaji unarejesha 500, kumbukumbu zinaonyesha `EACCES` au `permission denied`.

**Sababu:**

- `DATA_DIR` au saraka kuu yake haiwezi kuandikwa na mchakato wa OmniRoute.
- Inaendeshwa ndani ya Docker rootless bila ruhusa ya kuandika kwenye volume iliyounganishwa.

**Suluhisho:**

1. Angalia `DATA_DIR` (chaguo-msingi: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. Hakikisha mtumiaji wa mchakato wa OmniRoute anamiliki saraka: `chown -R $USER ~/.omniroute/`
3. Katika Docker, hakikisha volume mount ina ruhusa sahihi kwa mtumiaji wa container.

---

### Usasishaji unashindwa (kuisha kwa muda wa `npm install` au hitilafu ya mtandao)

**Dalili:** Usasishaji unarejesha 500 ikiwa na `InstallError`, kumbukumbu zinaonyesha kuisha kwa muda wa mtandao.

**Orodha ya ukaguzi:**

1. Thibitisha kuwa sajili ya npm inaweza kufikiwa: `npm ping`.
2. Angalia kama kuna proksi ya shirika: `npm config get proxy`, `npm config get https-proxy`.
3. Jaribu usakinishaji mwenyewe: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. Ikiwa uko nyuma ya air-gap, pakua tarball mapema na utumie `npm install /path/to/tarball.tgz`.

---

### Huduma inaonyesha hali ya `"error"` mara tu baada ya kuanzishwa (kuvurugika kwa haraka)

**Dalili:** Hali inabadilika kutoka `"starting"` hadi `"error"` ndani ya chini ya sekunde 5.
`lastError` inaonyesha `"Fast crash (exited with code 1)"`.

**Orodha ya ukaguzi:**

1. Soma sehemu kamili ya mwisho ya kumbukumbu: `GET /api/services/{name}/logs?tail=500`.
2. Sababu ya kawaida: kukosekana kwa vigezo vya mazingira vinavyotarajiwa na huduma.
3. Kwa 9Router: thibitisha kuwa `NINEROUTER_DISABLE_MITM=true` na
   `NINEROUTER_DISABLE_TUNNEL=true` zimo katika env inayopitishwa wakati wa spawn (angalia
   `installers/ninerouter.ts` `resolveSpawnArgs`).

## 8. Maswali Yanayoulizwa Mara kwa Mara

**Swali: Je, ninaweza kufichua endpoint za huduma zilizopachikwa kwa wateja wasio wa loopback?**

Hapana. Ngazi ya LOCAL_ONLY imekusudiwa hivyo (sheria ngumu #17). Routes zinazoweza kutekeleza
`npm install` au kuanzisha michakato ya `node` lazima zisifikiwe na trafiki isiyo ya loopback,
kwa sababu JWT iliyovuja kupitia tunnel (Cloudflare, Ngrok, Tailscale) ingeweza
kuruhusu kuanzishwa kwa michakato kiholela. Hakuna msamaha wa hiari kwa
`/api/services/` — tofauti na `/api/mcp/`, haijumuishwi kwenye orodha ya kupita
ukaguzi wa manage-scope. Angalia `docs/security/ROUTE_GUARD_TIERS.md`.

---

**Swali: Je, 9Router na CLIProxyAPI zitapatikana katika upelekaji wa uzalishaji/cloud?**

Ndiyo. Huduma zote mbili zinafuata muundo uleule unaotanguliza mazingira ya ndani kama OmniRoute yenyewe. Huendeshwa
kwenye mashine hiyo hiyo na kuwasiliana kupitia loopback. "Uzalishaji" hapa unamaanisha VPS
au seva ya ndani ambako OmniRoute imepelekwa, si mtoa huduma wa cloud wa mbali.

---

**Swali: Ninawezaje kutatua hitilafu za supervisor?**

1. Fuatilia mtiririko wa logi wa SSE: `curl -N http://localhost:20128/api/services/9router/logs`.
2. Kagua logi zilizoundwa kwa muundo katika matokeo ya pino ya OmniRoute, yaliyochujwa kwa
   namespace ya `service:supervisor`.
3. Kagua safu ya DB: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. Tumia `GET /api/services/9router/status` kuona hali ya sasa ya moja kwa moja, PID, afya,
   na `lastError` kwa ombi moja.

---

**Swali: Supervisor inaonyesha `health: "degraded"` au `health: "unknown"` lakini hali ni `"running"`. Je, hilo ni tatizo?**

`"degraded"` inamaanisha uchunguzi wa afya ulirudisha jibu lisilo la 200. `"unknown"` inamaanisha hakuna
uchunguzi ambao umekamilika bado (mkanganyiko wa muda na upigaji kura wa kwanza). Hali zote mbili ni za muda wakati wa kuanza.
Ikiwa afya itaendelea kuwa `"degraded"` kwa zaidi ya ms `healthIntervalMs * 3` baada ya
`"running"`, huduma iliyopachikwa inaendeshwa lakini HTTP API yake haijibu. Kagua
ikiwa port ni sahihi katika jibu la hali na ikiwa huduma kwa hakika
inasikiliza kwenye port hiyo.

---

**Swali: Je, ninaweza kubadilisha ufunguo wa API wa 9Router bila kuanzisha upya kikamilifu?**

Hapana. Ufunguo wa API hupitishwa kwa 9Router kupitia environment variable wakati wa kuanzisha mchakato.
Environment variables haziwezi kubadilishwa katika mchakato unaoendelea. `POST .../rotate-key`
husimamisha na kuanzisha upya huduma kiotomatiki ili kutumia ufunguo mpya. Mzunguko wa ufunguo
unaanza kutumika ndani ya `stopTimeoutMs` ya huduma (chaguo-msingi sekunde 15) pamoja na muda wake
wa kuanza.

---

**Swali: Kikomo cha ring buffer ni kipi na nini hutokea inapojaa?**

Kila huduma ina ring buffer yake maalumu ya MB 5. Buffer inapojaa, mistari ya zamani zaidi
ya logi huondolewa ili kutoa nafasi kwa mipya. Tukio la SSE `snapshot` hurudisha
mistari ya hivi karibuni zaidi ndani ya kikomo cha `tail`. Logi hazihifadhiwi kwenye diski isipokuwa
`logsBufferPath` iwe imewekwa katika safu ya DB.
