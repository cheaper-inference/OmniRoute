> **Chanzo rasmi:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, na
> `src/app/(dashboard)/dashboard/plugins/`
> **Ilisasishwa mwisho:** 2026-06-28 — v3.8.40

OmniRoute huja na mfumo wa programu-jalizi unaofanana na wa WordPress. Programu-jalizi ni saraka
zinazojitegemea — kila moja ikiwa na faili ya maelezo ya `plugin.json` na faili ya kuingilia — ambazo huunganishwa
kwenye mfululizo wa kushughulikia maombi (`onRequest` / `onResponse` / `onError`) na kwenye
matukio ya mzunguko wa maisha (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`).

**Soko la Programu-jalizi** ni safu ya ugunduzi iliyo juu ya mfumo huo. Linaweka wazi
katalogi inayoweza kuvinjariwa ya programu-jalizi zinazoweza kusakinishwa. Kwa chaguomsingi katalogi ni
rejista ndogo ya awali iliyojengewa ndani; mwendeshaji anaweza kuielekeza kwenye URL maalum ya
rejista ya mbali, ambapo uletaji hulindwa dhidi ya SSRF kwa kutumia kinga inayotatua DNS
(tazama [Usalama](#security)).

Kila njia ya programu-jalizi **inaruhusiwa kwenye loopback pekee** (Kiwango cha 1 — `LOCAL_ONLY`): programu-jalizi hupakia
na kutekeleza msimbo katika michakato-toto, kwa hivyo njia hizo haziwezi kufikiwa kutoka
chanzo kisicho cha loopback bila kujali uthibitishaji. Tazama
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md).

## Jinsi Inafaa Together

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **Safu ya Usajili** — `src/lib/plugins/marketplace.ts`: huorodhesha / hutafuta katalogi, ikirudi kwenye sajili ya mbegu kwa kutofaulu yoyote.
- **Safu ya mzunguko wa maisha** — `src/lib/plugins/manager.ts` (`pluginManager` singleton): kusakinisha, kuboresha, kuamilisha, kuzima, kufuta, kuchanganua, kupakia kuanza.
- **Safu ya dhihirisho** — `src/lib/plugins/manifest.ts`: Zod schema + chaguo-msingi za `plugin.json`.
- **Kichanganuzi** — `src/lib/plugins/scanner.ts`: hugundua programu-jalizi kwenye diski chini ya saraka ya programu-jalizi.
- **Kipakiaji** — `src/lib/plugins/loader.ts`: huzalisha kila programu-jalizi katika mchakato tofauti wa mtoto Node.js na wakala huingiza simu kupitia IPC. Mtoto si kisanduku cha mchanga (ona "Uteuzi wa programu-jalizi kutengwa" hapa chini).

## Katalogi ya Soko

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) hurejesha orodha ya
vipengee vya `MarketplaceEntry`:

| Sehemu        | Aina     | Maelezo                                            |
| ------------- | -------- | -------------------------------------------------- |
| `name`        | string   | Jina la programu-jalizi la kebab-case              |
| `version`     | string   | semver                                             |
| `description` | string   | Muhtasari mfupi                                    |
| `author`      | string   | Mwandishi / shirika                                |
| `license`     | string   | Kitambulisho cha leseni cha mtindo wa SPDX         |
| `downloadUrl` | string   | URL ya kupakua chanzo (inaweza kuwa tupu)          |
| `repository`  | string?  | URL ya hiari ya hazina                             |
| `tags`        | string[] | Lebo za kutafuta/kuchuja                           |
| `downloads`   | number   | Idadi ya upakuaji                                  |
| `rating`      | number   | 0–5                                                |
| `verified`    | boolean  | Ikiwa kipengee kimetiwa alama kuwa kimethibitishwa |
| `lastUpdated` | string   | Mfuatano wa tarehe unaofanana na ISO               |

Wakati hakuna URL maalum ya rejista iliyosanidiwa, katalogi huwa `SEED_REGISTRY`
iliyojengewa ndani (kwa sasa `request-logger`, `rate-limiter`, `cost-tracker`, na
`theme-manager`). Rejista ya awali hupatikana kila wakati — ikiwa rejista ya mbali
iliyosanidiwa haifikiki, inarejesha hali isiyo ya `200`, au inarejesha maudhui
yasiyotambulika, `listMarketplacePlugins()` hurekodi onyo na kurudi kwenye orodha ya awali.

> Kumbuka: **katalogi** ya soko (kuvinjari/kutafuta) imeunganishwa kikamilifu kuanzia mwanzo hadi mwisho, lakini
> **usakinishaji** wa mbofyo mmoja kutoka kwenye katalogi bado haujatekelezwa — kitufe cha
> "Sakinisha" cha dashibodi kwenye kipengee cha soko kwa sasa huonyesha arifa ya
> "inakuja hivi karibuni". Kwa sasa usakinishaji hufanywa kupitia mtiririko wa usakinishaji
> kutoka njia ya ndani (`POST /api/plugins`) na ugunduzi kwenye diski (`POST /api/plugins/scan`).

## REST API

Miisho yote inahitaji idhini ya usimamizi (`requireManagementAuth`)** na** ni `/api/plugins` — kitanzi pekee na `/api/plugins/` zimeorodheshwa katika `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`).

| Mwisho                             | Mbinu  | Maelezo                                                                    |
| ---------------------------------- | ------ | -------------------------------------------------------------------------- |
| `/api/plugins`                     | GET    | Orodhesha programu-jalizi zilizosakinishwa (kichujio `?status=` cha hiari) |
| `/api/plugins`                     | POST   | Sakinisha programu-jalizi kutoka kwa saraka ya vyanzo vya programu-jalizi  |
| `/api/plugins/scan`                | POST   | Changanua saraka ya programu-jalizi na usajili programu-jalizi mpya        |
| `/api/plugins/marketplace`         | GET    | Orodhesha maingizo ya katalogi ya soko                                     |
| `/api/plugins/marketplace/install` | POST   | Sakinisha programu-jalizi ya soko kwa jina                                 |
| `/api/plugins/[name]`              | GET    | Pata maelezo ya programu-jalizi iliyosakinishwa                            |
| `/api/plugins/[name]`              | DELETE | Sanidua programu-jalizi                                                    |
| `/api/plugins/[name]/activate`     | POST   | Washa (pakia ndoano za rejista + )                                         |
| `/api/plugins/[name]/deactivate`   | POST   | Zima (moto `onDeactivate`, ondoa ndoano)                                   |
| `/api/plugins/[name]/config`       | GET    | Pata schema ya usanidi wa programu-jalizi +                                |
| `/api/plugins/[name]/config`       | PUT    | Sasisha usanidi wa programu-jalizi (imeidhinishwa dhidi ya schema)         |

Kichujio cha `GET /api/plugins` `status` kinakubali mojawapo ya `installed` / `active` / `inactive` / `error`. Thamani batili inarudisha `400`.

### Orodhesha programu jalizi zilizosakinishwa

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### Sakinisha kutoka kwa njia ya ndani

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` lazima iwe ni** kabisa** njia ya saraka** ndani ya saraka ya vyanzo vya programu-jalizi** : `plugin-sources` karibu na mzizi wa programu-jalizi, kwa hivyo `~/.omniroute/plugin-sources/` kwa chaguo-msingi, au `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` wakati utofauti huo umewekwa (`getPluginSourcesDir()` in `src/lib/plugins/installSource.ts`). Nakili au utengeneze programu-jalizi hapo kwanza. Usakinishaji unakataliwa na `400` wakati njia ina `..` au null byte, iko nje ya saraka hiyo, hutatuliwa nje yake kupitia ulinganifu, ina ulinganifu ambao lengo lake liko nje yake, au wakati saraka haipo. Saraka chanzo lazima iwe na `plugin.json` halali (au uwe mzazi wa mtoto mmoja). Juu ya mafanikio jibu ni `201` na safu ya programu-jalizi iliyosakinishwa.

Tofauti na njia zingine za programu-jalizi, hii inahitaji kitambulisho cha usimamizi (kipindi cha dashibodi au kitufe API kilichodhibitiwa) hata wakati kuingia kumezimwa (`requireLogin=false`): kusakinisha msimbo kamwe si kitendo kisichojulikana. Hali hiyo hiyo inatumika kwa `POST /api/plugins/marketplace/install` (mwili `{ "name": "<plugin>" }`).

### Vinjari soko

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### Sasisha usanidi wa programu-jalizi

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` huthibitisha mwili dhidi ya `configSchema` ya programu-jalizi (iliyotangazwa kwenye faili ya maelezo) na `validatePluginConfig()` kutoka `src/lib/plugins/manifest.ts`: kila ufunguo lazima utangazwe kwenye taratibu, thamani lazima zilingane na aina iliyotangazwa, sehemu za `number` huheshimu `min`/`max`, na sehemu za `select` lazima zilingane na `enum` iliyotangazwa. Ukiukaji wowote unarudisha `400` na hakuna chochote kinachohifadhiwa. Programu-jalizi inayotangaza hakuna `configSchema` haina funguo zinazoweza kusanidiwa, kwa hivyo ombi limekataliwa na `400` ("Plugin haitangazi funguo zozote zinazoweza kusanidiwa").

## Usanidi

### Saraka ya programu-jalizi

Programu-jalizi huhifadhiwa chini ya saraka ya data ya OmniRoute:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (au chochote ambacho manifest.main inaelekeza)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) hutambua saraka hiyo kwa
hatua tatu:

1. **`OMNIROUTE_PLUGINS_DIR`**, inapowekwa — hutumiwa jinsi ilivyo, bila kujali thamani ya `HOME`. Hiki ni
   kidhibiti dhahiri kwa Docker/K8s, ambapo mti wa programu-jalizi huunganishwa kwa bind katika njia
   ambayo kwa kawaida haihusiani kabisa na saraka ya nyumbani ya kontena (#11827).
2. `<home>/.omniroute/plugins`, ambapo `<home>` hutokana na vigezo vya mazingira vya `HOME` / `USERPROFILE`.
3. `/tmp/.omniroute/plugins`, wakati mchakato hautoi kabisa saraka ya nyumbani.

Saraka iliyotambuliwa huandikwa kwenye kumbukumbu mara moja wakati wa kuanza kama `scanner.dir_resolved`, ikitaja
ingizo lililoshinda (`OMNIROUTE_PLUGINS_DIR`, `home`, au `no-home-fallback`) — hivyo image
inayoishia kimyakimya kwenye hatua ya 3 husema hivyo, badala ya kuripoti tu orodha tupu ya programu-jalizi.
`POST /api/plugins/scan` hugundua kila saraka ndogo iliyopo humo ambayo ina
`plugin.json` halali na kuisajili; saraka hiyo hiyo ndiyo mzizi ambamo
`pluginManager.install()` hunakili programu-jalizi, hivyo ubatilishaji huhamisha ugunduzi na
usakinishaji kwa pamoja.

> **`OMNIROUTE_PLUGINS_DIR` si `OMNIROUTE_PLUGIN_PATH`.** Ya pili husomwa tu na
> kipakiaji cha programu-jalizi za amri cha CLI (`bin/cli/plugins.mjs`) ili kupata vifurushi vya npm vya `omniroute-cmd-*`
> vinavyoongeza amri ndogo za `omniroute` — haina athari kwa kichanganuzi cha wakati wa utekelezaji
> kilichoelezwa hapa. Tazama [PLUGINS.md](./PLUGINS.md) kwa upande huo.

### URL maalum ya sajili ya soko

Chanzo cha katalogi ya soko husomwa kutoka kwenye mpangilio wa `pluginMarketplaceUrl`
(`src/lib/plugins/marketplace.ts` husoma `settings.pluginMarketplaceUrl`). Inapowekwa
kuwa URL ya `http(s)`, `listMarketplacePlugins()` huchota URL hiyo na kukubali
ama safu ya kiwango cha juu ya JSON ya maingizo au kipengee chenye safu ya `plugins`;
maingizo yasiyo na `name` ya aina ya string huondolewa. Isipowekwa (au uchotaji
ukizuiwa na kinga ya SSRF / ukirejesha jibu baya), sajili chaguo-msingi iliyojengewa ndani
hutumiwa.

Kichupo cha "Marketplace" kwenye dashibodi huonyesha sehemu ya URL hii (husomwa tena kutoka
`GET /api/settings`).

> Dokezo la utekelezaji: kitendo cha "Save" kwenye dashibodi hutuma
> `pluginMarketplaceUrl` kwa `PATCH /api/settings`. Wakati hati hii ikiandikwa, ufunguo huu
> haujatangazwa katika `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`), kwa hivyo thibitisha uhifadhi wake katika
> toleo lako kabla ya kuutegemea — njia ya **kusoma** (`getSettings()` →
> `listMarketplacePlugins()`) huzingatia ufunguo huo mara tu unapokuwepo kwenye hifadhi ya
> mipangilio.

## Usalama

### Kiwango cha njia — kitanzi tu

Programu-jalizi hutekeleza msimbo katika michakato inayotokana na mtoto, kwa hivyo uso mzima `/api/plugins` huainishwa `LOCAL_ONLY` (Tier 1). Utekelezaji wa Loopback huendeshwa bila masharti** kabla** ukaguzi wowote wa uthibitishaji, kwa hivyo tokeni ya usimamizi iliyovuja inayofikia kisanduku juu ya handaki bado haiwezi kusakinisha, kuamilisha, au kusanidua programu-jalizi. Tazama [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) na Kanuni Ngumu #15 / #17.

### Usajili wa soko SSRF walinzi

Usajili maalum URL ni usanidi unaoweza kuathiriwa na washambulizi, kwa hivyo kabla ya kuileta `listMarketplacePlugins()` huiendesha kupitia tabaka mbili:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - Hukataa chochote ambacho si `http:` / `https:`.
   - Inakataa wapangishi halisi private/loopback/link-local/ULA (IPv4** na** IPv6, ikijumuisha IPv4-mapped) kupitia `isPrivateHost` ya kisheria (`src/shared/network/outboundUrlGuard.ts`).
   - Inatatua** zote mbili** `A` na `AAAA` hurekodi na kukataa ikiwa** yoyote** anwani iliyosuluhishwa ni — ya faragha inayofunga jina la mwenyeji wa umma → private-IP bypass.
   - **Inashindwa kufungwa** : kushindwa kwa azimio la DNS kukataa URL.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): re-applies the public-only URL guard at fetch time and **blocks redirects** (no public → private `30x` pivot).

URL ambayo haifaulu safu yoyote haibatilishi ombi — soko huanguka kimya kimya kwenye sajili ya mbegu iliyojengewa ndani na kuweka onyo.

> Mlinzi huyu alikuwa mgumu katika PR #3774 haswa kutatua A + AAAA na kutumia `isPrivateHost` ya kisheria badala ya hundi IPv4-only.

### Kutengwa kwa utekelezaji wa programu-jalizi

> **Plugins si sandboxed kwa default.** Mtoto ni mchakato wa kawaida Node.js unaoendeshwa kama mtumiaji wa OmniRoute, bila muktadha VM na hakuna bendera za ruhusa Node.js, kwa hivyo msimbo wa programu-jalizi unaweza kusoma na kuandika faili yoyote ambayo mtumiaji anaweza, kuendesha programu na kufikia mtandao. `requires.permissions` huamua tu ni mazingira gani mtoto hupokea; ruhusa zingine hazitekelezwi. Alama ya kipengele cha `PLUGIN_PERMISSION_MODEL_ENABLED` ya kuchagua (kuzimwa kwa chaguo-msingi) huendesha kila programu-jalizi chini ya modeli ya ruhusa ya Node.js iliyojengwa kutoka kwa ruhusa hizo, isipokuwa `network`, ambayo Node.js haiwezi kuwekea vikwazo (tazama [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#permission-system) ). Sakinisha programu-jalizi unazoziamini pekee. Mpaka wa mchakato hapa chini una ajali na hutegemea; sio mpaka wa usalama.

- **Kutengwa kwa mchakato** — `loadPlugin()` (`src/lib/plugins/loader.ts`) huzalisha kila programu-jalizi katika mchakato tofauti wa mtoto Node.js na kuwasiliana kupitia IPC. Simu za ndoano zina muda wa kuisha na ongezeko la `SIGTERM` → `SIGKILL`.
- **Orodha ya ruhusa ya Env** — mtoto hupokea tu seti iliyoruhusiwa ya vigezo vya mazingira; seti pana zaidi hutolewa tu wakati faili ya maelezo inapoomba ruhusa ya `env`.
- **Sakinisha kizuizi cha chanzo** — `POST /api/plugins` inasoma tu kutoka kwa saraka ya vyanzo vya programu-jalizi (ona "Sakinisha kutoka kwa njia ya ndani"): njia imehalalishwa na `realpath`, lazima ibaki ndani kabisa ya saraka hiyo, na mti wa chanzo unaobeba ulinganifu unaotoroka umekataliwa kabla ya kitu chochote kunakiliwa.
- **Uzuiaji wa njia** — install/upgrade/uninstall inadai kwamba saraka ya programu-jalizi na `manifest.main` inasuluhisha** ndani** mzizi wa programu-jalizi unaodhibitiwa kabla ya kunakili au ufutaji unaorudiwa (walinzi dhidi ya njia za DB zilizoharibiwa na `../` traversal katika `manifest.main`). Uamilisho hutatua ulinganifu kupitia `realpath` na kukataa kupakia sehemu ya kuingilia ambayo huepuka saraka ya programu-jalizi.
- **Pini ya hiari ya uadilifu** — a faili ya maelezo inaweza kutangaza uga wa `integrity` (`sha256-<base64>`, SRI ). Ikipo, kipakiaji huthibitisha heshi ya ingizo wakati wa kupakia na kukataa kuamilisha wakati kutolingana. Ni opt-in tamper-detection,** sivyo** mpaka wa usalama: haizuii kile programu-jalizi iliyopakiwa inaweza kufanya.
- **Hakuna kitambulisho cha mteja kwenye ndoano** — muktadha uliopitishwa kwa `onRequest`, `onResponse` na `onError` umeondoa vichwa vya `authorization`, `x-api-key`, `proxy-authorization` na `cookie`, na rekodi ya ufunguo wa API haina thamani muhimu (`redactPluginContext()` katika `src/lib/plugins/hooks.ts`).

## Dhihirisha (`plugin.json`)

Imethibitishwa na `PluginManifestSchema` (`src/lib/plugins/manifest.ts`):

| Shamba             | Aina     | Vidokezo                                                           |
| ------------------ | -------- | ------------------------------------------------------------------ |
| `name`             | kamba    | Inahitajika; kebab-kesi (`^[a-z0-9-]+$`), chars 1–100              |
| `version`          | kamba    | Inahitajika; semver (`MAJOR.MINOR.PATCH`)                          |
| `description`      | kamba?   | ≤ char 500                                                         |
| `author`           | kamba?   | ≤ 200 char                                                         |
| `license`          | kamba?   | Chaguomsingi hadi `MIT`                                            |
| `main`             | kamba?   | Faili ya kuingia; chaguo-msingi kwa `index.js`                     |
| `source`           | enum?    | `local` \| `marketplace` (chaguo-msingi hadi `local`)              |
| `tags`             | kamba[]? | Tafuta vitambulisho                                                |
| `requires`         | kupinga? | `{ omniroute?, permissions[] }`                                    |
| `hooks`            | kupinga? | Booleans kutangaza ambayo kunasa zana za programu-jalizi           |
| `skills`           | kitu[]?  | Ufafanuzi wa ujuzi wa hiari                                        |
| `enabledByDefault` | boolean? | Washa kiotomatiki unaposakinisha                                   |
| `configSchema`     | kupinga? | Ramani ya sehemu za usanidi (`string`/`number`/`boolean`/`select`) |
| `integrity`        | kamba?   | Hiari `sha256-<base64>` ingizo-pini ya faili                       |

Ruhusa zimetolewa kutoka kwa enum `network` / `file-read` / `file-write` / `env` / `exec`. `env` pekee ndiyo iliyo na athari ya wakati wa utekelezaji (orodha ya ruhusa inayobadilika kidogo ya mazingira kwa mtoto); mengine ni matamko na hayatekelezwi.

## Mtiririko wa Mzunguko wa Maisha

```
install (POST /api/plugins, njia)
  → changanua/thibitisha manifest → nakili hadi staging → hakikisha main ipo ndani ya saraka
  → badilisha jina atomiki kwenda ~/.omniroute/plugins/<name> → ingiza safu ya DB
  → anzisha onInstall → ikiwa enabledByDefault: activate

activate (POST /api/plugins/{name}/activate)
  → ukaguzi wa realpath kuhakikisha ipo ndani → loadPlugin() (anzisha mchakato mtoto)
  → sajili hooks zilizotangazwa → status = "active" → anzisha onActivate

deactivate (POST /api/plugins/{name}/deactivate)
  → anzisha onDeactivate (KABLA ya kufuta usajili) → futa usajili wa hooks
  → sitisha mchakato mtoto → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → deactivate ikiwa active → anzisha onUninstall
  → ufutaji wa kujirudia uliokaguliwa kuhakikisha unabaki ndani ya saraka ya programu-jalizi → futa safu ya DB
```

Kuendesha tena `install` dhidi ya saraka ambayo toleo la manifest ni **jipya
kabisa** kuliko toleo lililosakinishwa husasisha kiotomatiki (usakinishaji upya safi; usanidi huwekwa upya
kwenye chaguomsingi). Toleo sawa au la zamani zaidi hukataliwa.

## Dashibodi

Ukurasa wa dashibodi katika `/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) hutoa tabo mbili:

- **Imesakinishwa** — huorodhesha programu-jalizi zilizosakinishwa na ndoano zake zilizotangazwa, kugeuza activate/deactivate, kitufe cha kufuta, na kitendo cha "Scan for plugins" (`POST /api/plugins/scan`).
- **Soko** — inaonyesha katalogi kutoka `GET /api/plugins/marketplace` yenye sehemu ya kuweka sajili maalum URL.

Ukurasa daima unaonyesha onyo kwamba programu-jalizi huendesha na mapendeleo kamili ya mchakato OmniRoute.

Ukurasa wa usanidi wa kila programu-jalizi huishi `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`).
