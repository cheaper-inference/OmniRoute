## Kwa Nini Kuwe na Kifurushi Tofauti cha Workspace?

`open-sse/` ni **workspace inayojitegemea** katika monorepo ya OmniRoute kwa sababu kadhaa:

1. **Uwezo wa kutumika tena** — `open-sse` huchapishwa kama `@omniroute/open-sse` kwenye npm, hivyo miradi mingine inaweza kuitumia kivyake
2. **Mipaka iliyo wazi** — injini ya utiririshaji imetenganishwa na safu ya UI/DB inayohusika mahususi na OmniRoute
3. **Utendaji** — injini haina utegemezi wowote wa Next.js, jambo linalowezesha uanzishaji wa awali ulio wa haraka zaidi katika mazingira ya CLI/serverless
4. **Udhibiti wa matoleo** — `open-sse` inaweza kutoa matoleo kwa ratiba yake yenyewe

```json
// package.json
"workspaces": ["open-sse"]
```

## Mchakato wa Ombi

Kila ombi la LLM hupitia **mchakato wenye hatua 5**:

```
                              ┌──────────────┐
   Ombi la HTTP                │  1. ELEKEZA  │   utatuzi wa combo, uteuzi wa modeli
   (Njia ya Next.js)           └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  2. TAFSIRI  │   ugeuzaji wa umbizo (OpenAI ↔ Claude ↔ Gemini)
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  3. TEKELEZA │   kitekelezaji cha mtoa huduma, HTTP, jaribio upya, kikatiza
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  4. TIRIRISHA│   ugeuzaji wa SSE, shinikizo la nyuma
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  5. REKODI   │   ufuatiliaji wa matumizi, kumbukumbu ya mwito, uainishaji wa hitilafu
                              └──────┬───────┘
                                     │
                                     ▼
                              Jibu la HTTP (SSE au JSON)
```

### Hatua ya 1: Elekeza (services/combo.ts)

**Sehemu ya kuingilia**: `handleComboChat()` katika `services/combo.ts`

Hutatua ombi kuwa jozi halisi ya `(provider, model, account, credentials)`:

- Tafuta combo kwa ID (au unda combo pepe kwa modeli za `auto/*`)
- Tumia mkakati wa uelekezaji (kipaumbele, uzani, round-robin, n.k.)
- Ondoa watoa huduma wenye matatizo (kikatiza saketi)
- Chagua lengo linalofuata linalofaa

Kwa modeli za `auto/*`, hatua hii pia:

- Huendesha algoriti ya **upimaji wa vipengele 16** (`services/autoCombo/`)
- Huchagua jozi ya `provider+model` kulingana na hali, gharama, ukawiaji, n.k.

### Hatua ya 2: Tafsiri (translator/)

Ikiwa umbizo la chanzo (k.m., OpenAI) linatofautiana na umbizo lengwa (k.m., Claude), ombi **hutafsiriwa**:

- Kidokezo cha mfumo → ujumbe wa mfumo
- Ufafanuzi wa zana → umbizo la zana linalomhusu mtoa huduma
- Vigezo vya reasoning/thinking → vilingani vinavyomhusu mtoa huduma
- Usawazishaji wa jukumu la ujumbe (`developer` → `system` kwa wasio OpenAI)

`translator/index.ts` hufichua:

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### Hatua ya 3: Tekeleza (executors/)

**Sehemu ya kuingilia**: `getExecutor(providerId).execute(request, options)`

Watoa huduma wote hutumia `DefaultExecutor` (`executors/default.ts`) kupitia mbadala wa kiwanda cha `getExecutor()`. Kitekelezaji:

- Huunda URL ya upande wa juu (`buildUrl()`)
- Huongeza vichwa vinavyomhusu mtoa huduma (`buildHeaders()`)
- Hubadilisha mwili wa ombi (`transformRequest()`)
- Hutuma ombi la HTTP likiwa na jaribio upya + ongezeko la muda wa kusubiri
- Hushughulikia uonyeshaji upya wa uthibitishaji ikihitajika (watoa huduma wa OAuth)

Vitekelezaji vyote hurithi `BaseExecutor` (`executors/base.ts`, mistari 1170 ya msimbo) ambayo hutoa:

- Mantiki ya pamoja ya kujaribu upya
- Muunganisho wa proksi
- Muunganisho wa kikatiza saketi
- Vihusishi vya kurekodi matumizi

### Hatua ya 4: Tiririsha (utils/stream.ts)

Kwa majibu yanayotiririshwa, kitekelezaji hurejesha **ReadableStream**. Kishughulikiaji:

- Hupitisha kupitia kigeuzi cha SSE (`createSSETransformStreamWithLogger`)
- Hutumia mipigo ya heartbeat ili kugundua miunganisho iliyokufa
- Hushughulikia kukatika kwa muunganisho wa kiteja kwa ustadi (`pipeWithDisconnect`)
- Hubadilisha SSE → JSON kwa viteja visivyotumia utiririshaji

Kwa majibu yasiyotiririshwa, kitekelezaji hurejesha kipengee cha JSON kilichochanganuliwa ambacho hupitishwa bila kubadilishwa.

### Hatua ya 5: Rekodi (services/usage.ts)

Baada ya jibu (iwe limefanikiwa au limeshindwa), matumizi yanarekodiwa:

- `prompt_tokens`, `completion_tokens`, `cached_tokens` kutoka kwenye jibu
- `cost_usd` inayokokotolewa kutoka kwenye data ya bei
- `latency_ms`, `status`, `error_class` ikiwa imeshindwa
- Yanahifadhiwa kwenye jedwali la `usage_history`

Vielelezo vya kumbukumbu za miito (ikiwa vimewezeshwa) huandikwa kwenye `${DATA_DIR}/call_logs/`.

### chatCore.ts (mistari 5977)

The** msimamizi mkuu wa ombi** . Licha ya ukubwa wake, ina muundo wazi:

```ts
// Pseudo-structure of chatCore.ts
export async function handleChat(request: NextRequest) {
  // 1. Auth + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. Body validation
  const body = await parseRequestBody(request);

  // 3. Format detection + translation
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. Combo routing
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // Continue to next target
    }
  }

  // 5. Emergency fallback
  return await emergencyFallback(body);
}
```

## Watekelezaji (moduli 150)

Mara nyingi faili moja kwa kila mtoaji. Madarasa ya wasii wote huongeza `BaseExecutor` na kubatilisha yale yanayotofautiana; moduli zingine ni wasaidizi wa kila mtoaji (schema za zana, adapta fetch/TTS, washughulikiaji wa quirk).

### Miundo ya Kawaida

Watoa huduma hutatuliwa kupitia `getExecutor(providerId)`, ambayo hurejesha mtekelezaji aliyesanidiwa. watoa huduma OpenAI/Anthropic-compatible hutumia `DefaultExecutor` (`executors/default.ts`). Tabia mahususi ya mtoaji (base URL, vichwa vya maandishi, toleo la API ) imesanidiwa `open-sse/config/providers/`, huku mabadiliko ya ombi yanashughulikiwa `open-sse/translator/`.

**URL maalum** imewekwa kupitia usanidi wa mtoaji:

```ts
// Provider config in open-sse/config/providers/
export default {
  id: "together",
  baseURL: "https://api.together.xyz/v1/chat/completions",
}
````

**Uthibitishaji maalum** inashughulikiwa kupitia usanidi wa uthibitishaji wa usajili wa mtoaji (API key, OAuth, wasifu wa kichwa).

**Mwili wa ombi maalum** mabadiliko (kwa mfano, Anthropic kutenganisha `system` kutoka `messages`) yamesajiliwa kwa kila mtoa huduma katika `open-sse/translator/`.

````

### The Executor Factory

`executors/index.ts` exports `getExecutor(providerId)`:

```ts
import { getExecutor } from "@omniroute/open-sse/executors";

const executor = getExecutor("anthropic");
const result = await executor.execute({
  model: "claude-sonnet-4-5",
  messages: [...],
});
````

Azimio linapitia `ExecutorRegistry` (`executors/registry.ts`): kila mtekelezaji maalumu anatangazwa katika jedwali lililojengewa ndani la `executors/index.ts` na kusajiliwa kupitia `registerExecutor(alias, instance)` kwa upakiaji wa moduli; `getExecutor()` hutafuta sajili na kurudi kwenye `DefaultExecutor` iliyohifadhiwa kwa mtoa huduma yeyote bila ingizo maalum. Lakabu kamili ya kuchora ramani ya mtekelezaji → ina sifa ya jaribio la dhahabu `tests/unit/executor-map-golden.test.ts`.

## Watafsiri

Tafsiri kati ya **miundo 3**: OpenAI, Anthropic, Gemini, pamoja na Responses API mpya.

### Wakati Tafsiri Inapofanyika

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
  body = translateRequest(body, sourceFormat, targetFormat);
}
```

Tafsiri za kawaida:

- `OpenAI → Anthropic`: sehemu tofauti ya `system`, kichwa cha `x-api-key`
- `OpenAI → Gemini`: `contents` badala ya `messages`, `systemInstruction`
- `OpenAI → Responses API`: safu ya `input`, hali ya `previous_response_id`

### Hali Maalum Zinazoshughulikiwa

- Jukumu la `developer` → `system` kwa mifumo isiyo ya OpenAI
- Jukumu la `system` → huunganishwa katika ujumbe wa kwanza wa mtumiaji kwa GLM/ERNIE
- `json_schema` → `responseMimeType` + `responseSchema` za Gemini
- `tools` → muundo wa zana unaotegemea mtoa huduma
- Vigezo vya kufikiri (o1, Claude) → thamani zinazolingana kulingana na mtoa huduma

## Seva ya MCP

`open-sse/mcp-server/` hutekeleza seva ya **Model Context Protocol**:

- **Zana 110** (usimamizi wa watoa huduma, michanganyiko, kumbukumbu, akiba, mgandamizo, proksi, ujuzi, uundaji wa uzoefu kama mchezo, programu-jalizi, Notion, Obsidian, hazina ya ndani)
- **Njia 3 za usafirishaji**: stdio, SSE, Streamable HTTP
- **Mawanda 33** kwa ajili ya uidhinishaji wa kina

### Usajili wa Zana

Zana husajiliwa kama faili zinazojitegemea katika `open-sse/mcp-server/tools/`, ambapo kila moja husafirisha jina, schema, kidhibiti na wigo:

```ts
// open-sse/mcp-server/tools/getHealth.ts
import { z } from "zod";
export default {
  name: "omniroute_get_health",
  description: "Get system health snapshot",
  scope: "read:health",
  inputSchema: z.object({}),
  handler: async (_args, ctx) => {
    return await getSystemHealth();
  },
};
```

### Njia za Usafirishaji

```ts
// stdio (matumizi ya CLI)
startMcpStdio(server);

// SSE (utiririshaji unaotegemea HTTP)
startMcpSse(server, port);

// Streamable HTTP (MCP ya kisasa)
startMcpStreamable(server, port);
```

### Uidhinishaji

Kila mwito wa zana hupitia ukaguzi wa wigo (`open-sse/mcp-server/auth/`):

```ts
if (!hasScope(apiKey, "providers:read")) {
  throw new Error("Insufficient scope");
}
```

## Vigeuzi

`open-sse/transformer/` hubadilisha kati ya miundo ya **Chat Completions** na **Responses API**.

### Kwa Nini Kigeuzi Tofauti?

Responses API ni muundo mpya wa OpenAI wenye **mazungumzo yanayohifadhi hali** (`previous_response_id`). Mteja anapotuma ombi la Responses, OmniRoute:

1. Hubadilisha Responses → Chat Completions kwa matumizi ya ndani
2. Hutuma kwa mtoa huduma (mtoa huduma yeyote anayetumia Chat Completions)
3. Hubadilisha jibu kurudi katika muundo wa Responses
4. Hutiririsha jibu lililobadilishwa kwa mteja

Kigeuzi (`transformer/responsesTransformer.ts`) hutoa:

```ts
createResponsesApiTransformStream(): TransformStream
```

Hiki hushughulikia:

- Matukio ya `response.output_item.added`
- Matukio ya `response.output_text.delta`
- Tukio la `response.completed`
- Ulinganishaji wa miito ya zana (`function_call` ↔ `tool_calls`)

## Vikwazo vya Utendaji

Injini ya uelekezaji ina viwango vikali vya utendaji:

| Operesheni                                                          | Lengo | Kipimo                                          |
| ------------------------------------------------------------------- | ----- | ----------------------------------------------- |
| Utatuzi wa combo                                                    | <10ms | Kwa malengo 50                                  |
| Ukaguzi wa kikomo cha kiwango                                       | <1ms  | Token bucket ya ndani ya kumbukumbu             |
| Fallback ya familia ya modeli                                       | <5ms  | Ufafanuzi wa familia uliohifadhiwa kwenye cache |
| Usambazaji wa ombi kwa njia husika                                  | <2ms  | Njia inayotumika sana                           |
| **Hakuna I/O inayozuia katika njia inayotumika sana ya uelekezaji** | —     | Yote ni asinkronasi                             |

## Mifumo Isiyofaa

❌ **Miito ya DB ya kisinkronasi katika `combo.ts`** — kokotoa mapema na uhifadhi kwenye cache
❌ **Mantiki ya kujaribu tena katika handlers** — tumia `retry()` kutoka kwenye huduma ya ustahimilivu
❌ **Ufikiaji wa moja kwa moja wa usanidi wa provider** — tumia getters za `providerRegistry`
❌ **Minyororo ya fallback iliyoandikwa moja kwa moja** — ifafanue katika `modelFamilyFallback.ts`
❌ **Mabadiliko ya hali kati ya maombi yanayotekelezwa kwa wakati mmoja** — tumia tu muktadha maalumu wa ombi

## Kuongeza Kipengele Kipya

### Kuongeza Huduma Mpya

1. Unda `open-sse/services/[serviceName].ts` yenye jukumu mahususi
2. Hamisha function kuu ya handler na constants zozote
3. Ongeza majaribio ya unit katika `tests/unit/services/[serviceName].test.mjs`
4. Ijumuishe kwenye mtiririko wa ombi katika `handlers/chatCore.ts` (ikiwa inahusiana na uelekezaji)
5. Sasisha mantiki ya uelekezaji katika `combo.ts` ikiwa huduma inaathiri uteuzi wa lengo
6. Iandike katika faili hii

### Kuongeza Executor Mpya

1. Unda `open-sse/executors/[provider].ts` inayopanua `BaseExecutor`
2. Isajili katika `config/providerRegistry.ts`
3. Iongeze kwenye factory ya `executors/index.ts`
4. Ongeza majaribio ya unit kwa executor
5. Iandike katika `docs/architecture/ARCHITECTURE.md`

### Kuongeza Zana Mpya ya MCP

1. Unda au sasisha `open-sse/mcp-server/tools/[category]Tools.ts`
2. Fafanua schema ya Zod kwa inputs
3. Sajili zana katika `mcp-server/index.ts`
4. Iongeze kwenye matrix ya scope katika `mcp-server/auth/`
5. Ongeza majaribio ya unit
