## Ukamilishaji wa Gumzo

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Vichwa Maalum

| Kichwa                   | Mwelekeo | Maelezo                                                                                                                                                                                                                                            |
| ------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `x-omniroute-no-memory`  | Ombi     | Weka kuwa `true` ili kuruka uingizaji wa kumbukumbu na ujuzi kwa ombi hili (huakisi kutotumia akiba; huepuka gharama ya tokeni/gharama ya kila mwito)                                                                                              |
| `X-OmniRoute-Progress`   | Ombi     | Weka kuwa `true` kwa matukio ya maendeleo                                                                                                                                                                                                          |
| `X-Session-Id`           | Ombi     | Ufunguo wa kipindi unaodumu kwa ajili ya uhusishaji wa kipindi cha nje                                                                                                                                                                             |
| `x_session_id`           | Ombi     | Lahaja yenye kistari cha chini pia inakubaliwa (HTTP ya moja kwa moja)                                                                                                                                                                             |
| `X-OmniRoute-Session-Id` | Ombi     | Lebo ya kipindi/mazungumzo iliyotolewa na mwitaji (pia hutumika kwenye kumbukumbu). Inapokuwepo, huhifadhiwa bila kubadilishwa kwenye `call_logs.session_tag` kwa uhusishaji wa gharama kwa kila kipindi (#8249) — haitengenezwi kamwe ikiwa haipo |
| `Idempotency-Key`        | Ombi     | Ufunguo wa kuondoa nakala (dirisha la sekunde 5)                                                                                                                                                                                                   |
| `X-Request-Id`           | Ombi     | Ufunguo mbadala wa kuondoa nakala                                                                                                                                                                                                                  |
| `x-omniroute-connection` | Ombi     | Funga ombi la modeli moja kwenye muunganisho mmoja wa mtoa huduma (akaunti) kwa kutumia kitambulisho chake — tazama [Kufunga akaunti kwa kila ombi](#account-pinning-per-request)                                                                  |
| `X-OmniRoute-Cache`      | Jibu     | `HIT` au `MISS` (bila utiririshaji)                                                                                                                                                                                                                |
| `X-OmniRoute-Idempotent` | Jibu     | `true` ikiwa nakala zimeondolewa                                                                                                                                                                                                                   |
| `X-OmniRoute-Progress`   | Jibu     | `enabled` ikiwa ufuatiliaji wa maendeleo umewashwa                                                                                                                                                                                                 |
| `X-OmniRoute-Session-Id` | Jibu     | Kitambulisho halisi cha kipindi kilichotumiwa na OmniRoute                                                                                                                                                                                         |
| `X-OmniRoute-Request-Id` | Jibu     | Kitambulisho cha kuoanisha ombi (kinapojulikana)                                                                                                                                                                                                   |

#### Kubandika akaunti kwa kila ombi

Mtoa huduma anapokuwa na miunganisho kadhaa (akaunti au funguo), kwa kawaida OmniRoute huchagua mmoja
kupitia mkakati wake wa uteuzi wa akaunti. Badala yake, ombi linaweza kubandika muunganisho mmoja mahususi
kwa kutumia kichwa cha `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Mahali pa kupata kitambulisho.** Fungua ukurasa wa mtoa huduma katika dashibodi
  (**Dashibodi → Watoa huduma → <mtoa huduma>**) na ubofye chipu ya kitambulisho cha `xxxxxxxx…` kwenye safu ya muunganisho
  — inakili kitambulisho kamili cha muunganisho.
- **Maombi yanayoiheshimu.** Maombi ya modeli moja (`provider/model`) kwenye
  `/v1/chat/completions`, `/v1/messages` na `/v1/responses`. Michanganyiko hupuuza kichwa hiki: bandika
  akaunti kwa kila hatua ya mchanganyiko kupitia muunganisho wa hatua hiyo badala yake.
- **Ubandikaji ni wa lazima, si mapendeleo.** Muunganisho uliobandikwa hutumiwa peke yake. Hitilafu
  ndani ya ombi hurekodi kipindi cha kusubiri cha akaunti lakini **haihamii** kwenye
  akaunti nyingine ya mtoa huduma huyo.
- **Kipindi cha kusubiri na mgawo huondoa ubandikaji.** Wakati muunganisho uliobandikwa uko katika kipindi cha kusubiri,
  umeishiwa na mgawo au umezuiwa na sera ya mgawo, maombi ya baadaye hutumia miunganisho mingine ya mtoa huduma,
  sawa kabisa na trafiki isiyobandikwa.
- **Vitambulisho visivyojulikana au vilivyozimwa hushindwa.** Kitambulisho ambacho hakipo kwenye kundi amilifu la mtoa huduma (kilichofutwa,
  kilichozimwa, au kinachomilikiwa na mtoa huduma mwingine) huacha bila akaunti inayostahiki, hivyo ombi
  hushindwa badala ya kuelekezwa kwingine bila taarifa.

Claude Code hutuma vichwa maalum kupitia `ANTHROPIC_CUSTOM_HEADERS`. Kiweke kwenye kizuizi cha `env`
cha `~/.claude/settings.json`, au kwenye `.claude/settings.json` ya kiwango cha mradi ili kubandika akaunti tofauti
kwa kila mradi:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Chanzo: `src/sse/handlers/chat.ts` (usomaji wa kichwa), `src/sse/services/auth.ts` na
`src/sse/services/sessionAffinityPin.ts` (kuondolewa kwa ubandikaji na ukaguzi wa kutokuwepo kwenye kundi).

> **Vichwa vya telemetria ya gharama:** majibu yaliyofaulu yasiyotiririshwa pia hubeba seti ya telemetria ya gharama ya `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, nafasi 10 zisizobadilika za desimali; `0.0000000000` kwa huduma za bure/zisizo na bei), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, na `X-OmniRoute-Fallback-Attempts` (ikiwa tu > 0), pamoja na `X-OmniRoute-Request-Id` na `X-OmniRoute-Version`. Hivi hutolewa na ukamilishaji wa gumzo, `/v1/responses`, `/v1/messages`, **na sehemu za mwisho za midia** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations`, na `/v1/moderations` (gharama huwa `0` kila wakati). Gharama ya midia huhesabiwa kwa kila aina ya midia (kwa kila picha, kwa kila sekunde, kwa kila herufi, kwa kila kitengo cha utafutaji) wakati bei inapatikana, vinginevyo huwa `0` (huendelea kufanya kazi hata bei inapokosekana).

> **Maana ya gharama wakati akiba imetumika:** kunapokuwa na HIT ya akiba ya kisemantiki (`X-OmniRoute-Cache-Hit: true`), hakuna ombi linalotumwa kwa huduma ya juu, hivyo `X-OmniRoute-Response-Cost` huwa `0.0000000000` (gharama **ya nyongeza** ya kuhudumia ombi kutoka kwenye akiba). Gharama ya awali/ambayo ingekuwepo huripotiwa kando katika `X-OmniRoute-Cost-Saved`. Watumiaji wa taarifa za malipo wanapaswa kujumlisha `X-OmniRoute-Response-Cost` (matumizi ya akiba hayana gharama); uchanganuzi wa akiba unaweza kujumlisha `X-OmniRoute-Cost-Saved`.

## Ukodishaji wa Kipekee wa Vipindi Vinavyodhibitiwa

Ukodishaji wa kipekee wa vipindi vinavyodhibitiwa ni mkataba wa uelekezaji wa hiari usioegemea mteja: mmiliki mmoja anayefanya kazi
anashikilia muunganisho mmoja unaostahiki wa OmniRoute. Haukodishi modeli, hauhitaji OAuth, hautambui
mteja mahususi, wala hauhitaji mtoa huduma mahususi.

Ufunguo wa API unaothibitisha utambulisho lazima uwe na mawanda ya `lease:exclusive` na orodha bayana isiyo tupu ya
`allowedConnections`. Mpaka wa ubadilishaji wa hifadhidata hulazimisha sehemu zote mbili pamoja wakati wa
kuunda ufunguo na kufanya masasisho ya sehemu.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Majibu yaliyofaulu ya kupata, kusasisha na kuachilia huonyesha mihuri ya muda, `state`, na thamani kamili chanya ya
`generation`, lakini kamwe hayaonyeshi muunganisho uliochaguliwa wala vitambulisho. Kusasisha na kuachilia huwasilisha
kizazi katika mwili wa JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Mmiliki wa ukodishaji unaotumika anaweza kuomba kwa uwazi metadata salama kwa faragha ya kuonyesha kuhusu uunganishaji wake wa sasa:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Kitendo hiki cha hiari cha hali hulindwa na mmiliki fiche, ufunguo wa API unaodhibitiwa na uliothibitishwa, pamoja na
kizazi kamili kinachotumika, vyote ndani ya muamala mmoja wa hifadhidata. `displayName` ni jina la muunganisho lililowekwa tu
baada ya nafasi za pembeni kuondolewa; huwa `null` wakati hakuna jina salama lililowekwa. OmniRoute haibadilishi kamwe jina hilo kwa
barua pepe au utambulisho wa akaunti uliozalishwa. Thamani ya mtoa huduma ni lebo isiyo nyeti ya kuonyesha na kamwe si
kitambulishi kilichozalishwa cha mtoa huduma tangamanifu. Vitambulisho, tokeni, vidakuzi, vitambulishi ghafi vya muunganisho au
ufunguo wa API, heshi za mmiliki, siri za ulinzi, na data ya ndani ya uelekezaji havijumuishwi.

Utafutaji unaotumia ufunguo usio sahihi, mmiliki asiye sahihi, kizazi kilichopitwa na wakati, au ukodishaji unaokosekana, ulioisha muda, ulioachiliwa au uliobatilishwa
wote hurudisha hitilafu ileile ya `409 LEASE_FENCE_STALE` bila metadata ya muunganisho. Mteja aliyepokea jibu la kusubiri uwezo hana uunganishaji unaotumika wa kukagua. Uelekezaji unapohamisha ukodishaji unaotumika,
kizazi kilekile huendelea kuwa halali na hali hurudisha uunganishaji mpya kiatomiki, kamwe si wa zamani.
Wateja waliopo hubaki bila kubadilika kwa sababu majibu ya kupata, kusasisha, kuachilia na kusubiri hudumisha
miundo yao ya awali.

Mkataba huu wa seva haubadilishi `/status` ya kawaida ya OpenAI Codex. Kwa sasa, Codex ya kawaida huripoti
mtoa huduma wa modeli yake na hali iliyojengewa ndani ya uthibitishaji/akaunti, lakini haionyeshi metadata maalum holela ya
akaunti ya mtoa huduma; ujumuishaji wa baadaye wa mteja lazima uite kitendo hiki na kuamua jinsi ya
kuonyesha `connection.displayName`.

Kisha kila ombi la inferensi linalodhibitiwa huwasilisha vichwa vyote viwili vya udhibiti:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Mmiliki kamili, kizazi, muunganisho unaotumika, na ufunguo wa API uliothibitishwa hulindwa mara moja
kabla ya kila jaribio la juu linalotumika. Kutumia tena mmiliki na kizazi pamoja na ufunguo mwingine hushindwa hata
wakati ufunguo huo unaruhusu muunganisho huohuo. Wamiliki ghafi hawahifadhiwi, hawaandikwi kwenye kumbukumbu, hawabakizwi katika
picha-tuli ya ombi, wala hawatumwi juu.

Mgongano wa muda hurudisha HTTP `429` pamoja na `Retry-After` na:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Jibu hili linamaanisha tu kwamba seti ya kawaida inayostahiki haikuwa tupu na kila chaguo huru
lilishikiliwa na ukodishaji unaotumika wa mhusika mwingine. Modeli/watoa huduma wasiotumika, kutolingana kwa sera, kipindi cha kusubiri, mgawo,
afya, na hitilafu nyingine za kawaida za ustahiki hudumisha majibu yao yaliyopo ya OmniRoute.

### `x-omniroute-compression`

Ubatilishaji wa mpango wa mfinyazo kwa kila ombi. Una kipaumbele cha juu zaidi — unashinda ubatilishaji wa mchanganyiko wa uelekezaji,
wasifu unaotumika, uanzishaji otomatiki, na Chaguo-msingi la paneli. Thamani:

| Thamani       | Athari                                                                                                                |
| ------------- | --------------------------------------------------------------------------------------------------------------------- |
| `off`         | Hakuna mfinyazo kwa ombi hili.                                                                                        |
| `default`     | Wasifu wa Chaguo-msingi unaotokana na paneli (hupuuza wasifu unaotumika). Injini zinazopoteza data huachwa zimezimwa. |
| `safe`        | Uondoaji wa nakala rudufu na ukunja nafasi tupu pekee.                                                                |
| `allow-lossy` | Huhifadhi mpango wa opereta kwa ombi hili, ikijumuisha muhtasari na uandishi upya wa mtindo.                          |
| `engine:<id>` | Injini moja ikiwa imewezeshwa, k.m. `engine:rtk`. Uwezeshaji wa hiari wa injini hiyo kwa kila ombi.                   |
| `<combo>`     | Mchanganyiko wenye jina, unaolinganishwa kwanza kwa jina (bila kujali herufi kubwa au ndogo), kisha kwa kitambulishi. |

Vidokezo:

- Thamani zisizojulikana hupuuzwa (ombi halikataliwi kamwe); utatuzi huendelea hadi kwenye mpangilio wa kawaida wa vipaumbele vya opereta.
- Ikiwa michanganyiko mingi ina jina moja, wasilisha **kitambulishi** cha mchanganyiko ili kupata ulinganifu thabiti.
- Mchanganyiko ambao jina lake ni `off` au `default` hauwezi kuchaguliwa kwa jina (maneno hayo muhimu hufasiriwa kwanza); rejelea mchanganyiko huo kwa kitambulishi chake.
- Swichi kuu ya mfinyazo ni kizuizi kisichoweza kuvukwa: mfinyazo unapozimwa kwa ujumla, kichwa hiki hakiwezi kuuwezesha.

Mpango uliotumika hurudiwa katika kichwa cha jibu:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

ambapo `<source>` ni mojawapo ya `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, au `off`.

## Vekta za Uwakilishi

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Watoa huduma wanaopatikana: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Vitambulisho vya katalogi vina muundo wa `provider/model` (mfano: `jina-ai/jina-embeddings-v5-omni-small`). Vitambulisho vya modeli za Jina visivyo na jina la mtoa huduma ambavyo vinaonekana kwenye sajili (kwa mfano `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) pia hutambuliwa. Operesheni za embed/rerank/classify/segment za Jina hutumia kwanza vitambulisho vya ufikiaji vya `jina-ai` kutoka kwenye dashibodi; `JINA_AI_API_KEY` hutumika kama mbadala tu wakati hakuna ufunguo wa dashibodi. Kadi ya `jina-reader` ni ya Reader / `r.jina.ai` pekee (`POST /v1/web/fetch`) na haitoi kamwe huduma za embeddings au rerank.

Modeli za sajili zinazotangaza usaidizi wa midia anuwai pia zinakubali hadi vipengee 32 vilivyoundwa kwa muundo usiofungamana na mtoa huduma.
Aina za vipengee vya midia ni `text`, `image`, `audio`, `video`, na `document`. `source` ya midia
hiyo ni `{"type":"url","url":"https://..."}` au
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
na lakabu ya familia `jina-ai/jina-embeddings-v5-omni` → omni-small) pia hukubali hati asilia za
EmbeddingsV5Request za Jina na **huzituma bila kuzibadilisha** kwa `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Thamani asilia za `{ image | audio | video | pdf }` zinaweza kuwa URL ya umma ya HTTPS, URI ya `data:`, au
base64 ghafi. OmniRoute haibadilishi objekti hizo kuwa mifuatano ya maandishi wala kupakua URL asilia za picha — Jina yenyewe hupakua
midia ya umma. Sehemu za ziada za Jina (`task`, `normalized`, `truncate`, `embedding_type`)
hutumwa kama zilivyo. SKU za Jina zinazotumia maandishi pekee bado hukataa hati zisizo za maandishi.

Mipaka ya usalama na usafirishaji:

- URL za midia ya mbali lazima ziwe za umma na zitumie HTTPS. Vipengee vya kiwango vya `{type,source:url}` hupakuliwa
  upande wa seva (uhakiki upya wa uelekezaji, muda wa kuisha, vikomo vya ukubwa, DNS ya umma, na kufungia muunganisho) na
  kupachikwa kabla ya ombi kutumwa kwa mtoa huduma. Vipengee asilia vya Jina vya `{image:"https://..."}` hutumwa kama vilivyo
  baada ya ukaguzi huohuo wa HTTPS ya umma; Jina hupakua URL.
- Midia ya base64 iliyopachikwa ina kikomo cha MiB 8 baada ya kusimbuliwa kwa kila kipengee na MiB 16 baada ya kusimbuliwa kwa ombi lote.

Ubadilishaji kulingana na mtoa huduma (vipengee vya kiwango havitumwi kamwe bila kubadilishwa):

- Modeli za midia anuwai za Jina: kila kipengee cha kiwango cha juu huwa objekti moja yenye ufunguo wa aina ya midia
  (`text` / `image` / `audio` / `video` / `pdf`), kwa kutumia URI za data kwa midia iliyopachikwa; vekta moja kwa
  kila kipengee cha kiwango cha juu.
- Familia ya Gemini Embedding 2: safu moja ya kiwango cha juu huwa ombi moja asilia la
  `models/{model}:embedContent` lenye `content.parts` (`text` au `inline_data`).
- llama.cpp (`llama-cpp/<model>`, modeli yoyote iliyopakiwa na seva ya ndani): vipengee vya kiwango vya `text`
  huwa mifuatano ya maandishi ya kawaida, na `image` / `audio` / `video` huwa objekti moja ya
  `{"content": [part]}` kila kimoja, kwa kutumia sehemu za maudhui ya gumzo za llama-server (`image_url`,
  `input_audio` yenye umbizo la `wav` / `mp3` / `flac`, `input_video`) pamoja na data iliyopachikwa; vekta moja
  kwa kila kipengee cha kiwango cha juu. Seva lazima iendeshwe kwa `--embedding --mmproj …`; bila projekta, yenyewe
  hukataa midia. `document` haitumiki.
- Modeli zisizojulikana/zinazobadilika zisizo na metadata bayana ya aina ya midia hukataa ingizo lenye muundo kwa HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Michanganyiko isiyotumika ya modeli na aina ya midia hurejesha HTTP 400 badala ya kulazimisha ubadilishaji wa kipengee. Sehemu za kiendelezi
zisizo za ingizo kwenye maombi ya zamani ya mifuatano ya maandishi/tokeni huendelea kupitishwa bila kubadilishwa.

```bash
# Orodhesha modeli zote za embedding
GET /v1/embeddings
```

### Mtiririko wa ukaguzi wa mara kwa mara wa Azure Document Intelligence

vinginevyo mradi hutokana na `project_id` ya JSON ya Service Account na eneo
hutumia `us-central1` kama chaguo-msingi. Utambuzi wote wawili hufanyika katika `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), na hutumiwa na
`src/app/api/v1/ocr/route.ts` kabla ya kutumwa kwa `handleOcr`.

### Bei za modeli (`pricing`)

Ingizo huwa na kipengee cha `pricing` wakati OmniRoute inajua bei ya modeli. Bei hutoka
kwenye jedwali la bei linalotumiwa na uhasibu wa gharama: chaguomsingi zilizojengewa ndani, bei zilizosawazishwa, na
mabadiliko yaliyowekwa kupitia `/api/pricing`. Hizi ni bei za orodha, kwa hivyo watoa huduma wa usajili pia
huonyesha bei kwa kila tokeni.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Sehemu                                                          | Kipimo                                    | Maelezo                                                                                                                                                      |
| --------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | USD kwa kila tokeni, mfuatano wa desimali | Inaoana na OpenRouter, kamwe haitumii nukuu ya kipeo. Sehemu mbili za kache huonekana tu wakati kuna bei ya kache.                                           |
| `input`, `output`, `cached`, `cache_creation`                   | USD kwa tokeni milioni 1, nambari         | Sehemu kutoka matoleo ya awali ya katalogi, zimehifadhiwa kwa ajili ya wateja waliopo. `reasoning` na `long_context` pia huonekana wakati safu ya bei inazo. |

- **Michanganyiko** hubeba bei ya lengo lao la kwanza linaloonekana. Michanganyiko iliyojengewa ndani ya `auto/*` huchagua
  lengo wakati wa ombi, kwa hivyo haina `pricing`.
- **Modeli zisizolipishwa** huonyesha `"0"` (na `0`) wakati bei yake ni sifuri. Modeli isiyo na safu ya bei
  pia huonyesha `"0"` wakati katalogi inaiweka alama kuwa ya bure (`free: true`) au katalogi iliyojengewa ndani ya modeli
  zisizolipishwa inaiorodhesha.
- **Bei isiyojulikana:** ingizo halina ufunguo wa `pricing`.
- **Watoa huduma wanaopima matumizi kwa salio** (kama vile Kiro) hutoza kwa kila ombi badala ya kwa kila tokeni. Maingizo yao
  huhifadhi sehemu za nambari kwa kila milioni 1 walizokuwa nazo awali na hayana sehemu za mifuatano ya bei kwa kila tokeni.
- **Vibadala** (vitambulisho vya juhudi za reasoning, lakabu zisizo na thinking, vioo vya discovery na gateway)
  hunakili bei ya modeli vinakoelekeza.
- Sehemu hubeba viwango vya msingi pekee. Viwango vya muktadha mrefu (sehemu ya nambari ya `long_context`) na
  vizidishi vya kiwango cha huduma (kwa mfano Codex fast au flex) havibadilishi `prompt` au
  `completion`.
- Kipengee ni sawa kwa kila mtindo wa uthibitishaji, ikijumuisha ombi la mtindo wa Anthropic
  lenye `x-api-key` na `anthropic-version` (jibu hubaki `{ "object": "list",
"data": [...] }`). Utekelezaji: `src/app/api/v1/models/catalogPricing.ts`.

### Viambishi awali vya kitambulisho cha modeli (`?prefix=`)

Modeli nyingi hutangazwa chini ya **kiambishi awali cha mtoa huduma**. Kiambishi awali unachopata hudhibitiwa na
alamisho la kipengele la `MODELS_CATALOG_PREFIX_MODE`, na kinaweza kubatilishwa **kwa kila ombi** kwa
kigezo cha hoja — jambo linalofaa kwa mteja anayetaka orodha safi bila kubadilisha mpangilio wa seva nzima
kwa kila mtu mwingine:

```bash
GET /v1/models?prefix=alias        # kitambulisho kimoja kwa kila modeli — kiambishi awali kifupi cha lakabu
GET /v1/models?prefix=dual         # miundo yote miwili (chaguomsingi la seva)
GET /v1/models?prefix=canonical    # kiambishi awali kamili cha kitambulisho cha mtoa huduma pekee
```

| Hali        | Hutoa                                                    | Maelezo                                                                                                                                                                                                                                         |
| ----------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **na** `claude/claude-sonnet-4-6` | **Chaguomsingi.** Vitambulisho vyote viwili huelekeza kwenye modeli ileile; vimehifadhiwa ili usanidi wa wateja ulioweka mojawapo ya miundo hiyo moja kwa moja uendelee kufanya kazi. Takribani huongeza ukubwa wa katalogi mara mbili.         |
| `alias`     | `cc/claude-sonnet-4-6`                                   | Ingizo moja kwa kila modeli. Watoa huduma wasio na lakabu tofauti bado hutoa ingizo lao, kwa hivyo hakuna kinachopotea.                                                                                                                         |
| `canonical` | `claude/claude-sonnet-4-6`                               | Ingizo moja kwa kila modeli chini ya kiambishi awali kamili cha kitambulisho cha mtoa huduma. Watoa huduma wasio na lakabu tofauti (kwa mfano `antigravity/…`, `agy/…`) pia hutoa kitambulisho chao kimoja hapa, kwa hivyo hakuna kinachopotea. |

Kioo cha hali ya `dual` pia kinaweza kutambuliwa bila kigezo cha hoja: hubeba sehemu ya `parent`
inayoelekeza kwenye kitambulisho msingi.

Wateja wanaoonyesha kichagua modeli wanapaswa kuomba `?prefix=alias` — hivi ndivyo
[kiendelezi cha OmniCopilot cha VS Code](../guides/VSCODE-COPILOT.md) hufanya.

### Vichujio vya ugunduzi (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` hukubali vichujio vya hiari vya ugunduzi. Bila chochote kati yavyo, jibu
halibadiliki. Vinapunguza katalogi ambayo tayari mpigaji anaiona (ruhusa za ufunguo wa API hutumika kwanza),
na hutekelezwa kabla ya uorodheshaji wa kurasa wa mtindo wa OpenAI wa `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # kila uwezo ulioorodheshwa lazima uwe kweli
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` ya katalogi; safu zisiyo nayo ni `chat`
GET /v1/models?q=sonnet&limit=10                           # ulinganishaji usiojali herufi kubwa au ndogo kwenye kitambulisho au jina
```

| Kigezo        | Thamani                                                                                             |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | nambari kamili isiyo hasi, inayolinganishwa na `context_length`                                     |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | herufi 1–200                                                                                        |

Thamani isiyojulikana, au `min_context` ambayo si nambari kamili isiyo hasi (kwa mfano `1.5`),
hurejesha HTTP `400` na ujumbe huorodhesha thamani halali. Utekelezaji:
`src/app/api/v1/models/catalogFilters.ts`.

### Orodha fupi ya modeli (`POST /v1/models/query`)

`POST /v1/models/query` hurejesha orodha fupi na bainifu kutoka kwenye katalogi ileile, ikiwa na
uthibitishaji na mwonekano kwa kila ufunguo sawa na `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Kila sehemu ni ya hiari. `capabilities` na `exclude` hukubali safu au mfuatano uliotenganishwa kwa koma;
`max_output` hulinganishwa na `max_output_tokens`. Matokeo hupangwa kwa `owned_by`, kisha `id`.
Thamani chaguo-msingi ya `limit` ni `20`, na thamani zinazozidi `100` huwekewa kikomo cha `100`. JSON batili, sehemu
isiyojulikana au thamani batili hurejesha HTTP `400`.

### Modeli za gumzo zilizofichwa moja moja

Modeli iliyowekwa alama ya **Imefichwa** kwenye ukurasa wa mtoa huduma wake huondolewa kwenye katalogi na kukataliwa
kwa HTTP `404` / `model_not_found` inapoombwa moja kwa moja. Ukaguzi hutumia mtoa huduma na
modeli zilizotambuliwa, ikiwa ni pamoja na lakabu za watoa huduma, viambishi awali vya nodi za watoa huduma wanaooana, na
mipangilio chaguo-msingi ya muunganisho. Mchanganyiko huruka malengo yaliyofichwa na unaweza kutumia modeli nyingine inayoonekana; wakati hakuna
lengo linaloweza kutekelezwa linalosalia, hurejesha msimbo uleule wa hitilafu. Kufichua huanza kutumika kwenye
ombi linalofuata. Mabadiliko ya mwonekano wa picha pekee hayafichi modeli ya gumzo yenye kitambulisho sawa.

Mpangilio huu wa modeli binafsi ni tofauti na
[orodha za kuruhusu/kuzuia uonyeshaji wa modeli](../routing/MODEL_EXPOSURE_LIST.md), ambazo huchuja utangazaji wa katalogi
na wagombea wa uelekezaji otomatiki huku zikidumisha utumaji wa moja kwa moja. Ruhusa za modeli za ufunguo wa API
zinaendelea kutumika kwa kujitegemea. Hali chaguo-msingi ya kiambishi awali cha katalogi inasalia `dual`.

### Vibadala vya modeli visivyo na uwezo wa kufikiri

Kwa modeli za Claude zenye uwezo wa kufikiri, `/v1/models` pia hutangaza kibadala cha **no-thinking** ambacho kitambulisho chake huanza na `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Kuchagua kitambulisho hiki (k.m. katika usanidi wa Claude Code ambao huambatisha kila wakati kizuizi cha `thinking`) hutatuliwa kurudi kwenye `<provider>/<model>` halisi huku uwezo wa kufikiri ukiwa umezimwa — `thinking:{type:"disabled"}` kwenye njia ya `/v1/messages`, au sehemu za `reasoning`/`reasoning_effort` zikiondolewa kwenye njia ya `/v1/chat/completions`. Kibadala hiki huorodheshwa tu kwa modeli za familia ya Claude ambazo zinatumia uwezo wa kufikiri **na** zinakubali `disabled` (kwa hivyo, kwa mfano, modeli zinazotumia hali badilifu pekee na zinazokataa `disabled` hazijumuishwi). Waendeshaji wanaweza kulazimisha kibadala kuwashwa au kuzimwa kwa kila modeli kupitia `ModelSpec.noThinkingAlias`.

## Uzalishaji wa sauti wa ElevenLabs

Sanidi muunganisho wa mtoa huduma wa `elevenlabs` katika OmniRoute kwa kutumia ufunguo wako wa API wa ElevenLabs.
Wateja huthibitisha utambulisho kwa ufunguo wao wa **OmniRoute** (`Authorization: Bearer $OMNIROUTE_API_KEY`);
gateway hutoa ufunguo wa mtoa huduma uliohifadhiwa kama `xi-api-key`. Kamwe usitume ufunguo wa ElevenLabs
kama tokeni ya bearer ya gateway.

| Mbinu | Njia                        | Jibu                                          | Kategoria ya endpoint ya ufunguo wa API |
| ----- | --------------------------- | --------------------------------------------- | --------------------------------------- |
| POST  | `/v1/sound-generation`      | Baiti asilia za sauti                         | `elevenlabs`                            |
| POST  | `/v1/music`                 | Baiti asilia za sauti                         | `music`                                 |
| POST  | `/v1/music/stream`          | Baiti za sauti zinazotiririshwa               | `music`                                 |
| POST  | `/v1/music/detailed`        | Sauti asilia ya multipart na mpango wa utunzi | `music`                                 |
| POST  | `/v1/music/detailed/stream` | Metadata asilia ya SSE na vipande vya sauti   | `music`                                 |
| POST  | `/v1/music/plan`            | Mpango wa utunzi wa JSON                      | `music`                                 |

Endpoint hizi hukamilisha njia zilizopo za `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` na `/v1/speech-to-text`. Sehemu asilia za JSON
na vigezo vya hoja kama vile `output_format` na `enable_logging` huhifadhiwa.
Majibu ya `/v1/music/detailed` huhifadhi mipaka yake ya multipart; yachanganue kama multipart.
`/v1/music/detailed/stream` hurejesha `text/event-stream` iliyo na metadata ya utunzi na
vipande vya sauti vya base64 katika matukio ya SSE. Njia zote sita zinaunga mkono ukaguzi wa awali wa CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Athari fupi ya sauti. Muda: sekunde 0.5 hadi 30.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Muda wa muziki huonyeshwa kwa milisekunde: 3000 hadi 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Tumia `/v1/music/stream` pamoja na mwili uleule wa JSON ili kuwasilisha sauti hatua kwa hatua. Utunzi
hukubali moja tu kati ya `prompt` au `composition_plan`; `/v1/music/plan` huhitaji `prompt`
na kwa hiari hukubali `source_composition_plan`. Skima asilia huhifadhi sehemu za ziada za
mtoa huduma ili matoleo ya mpango wa utunzi na chaguo za urekebishaji wa kina zifikie ElevenLabs.

Endpoint iliyounganishwa ya `/v1/music/generations` pia hukubali `elevenlabs/music_v1`,
`elevenlabs/music_v2` na `elevenlabs/music_v2_5`. Muunganisho wa ElevenLabs ukiwa amilifu,
miundo hii huonyeshwa na katalogi ya muziki. Endpoint hii hurejesha
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Sehemu yake ya `duration` hupimwa kwa
sekunde na hulingana na `music_length_ms`; `music_length_ms` iliyobainishwa wazi hupewa kipaumbele.
`instrumental` hulingana na `force_instrumental`, huku sehemu asilia ikipewa kipaumbele.
Tumia endpoint asilia za utiririshaji kwa ajili ya utiririshaji na endpoint asilia ya utunzi
kwa maombi yanayoendeshwa na mpango wa utunzi pekee.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Vizuizi vya endpoint, muundo, bajeti na muunganisho hutumika kabla ya simu kwenda kwa mtoa huduma wa juu. Njia
asilia hurejesha misimbo ya hali na miili ya hitilafu kutoka kwa mtoa huduma wa juu bila kubadilishwa, ikijumuisha `402` kwa
kizuizi cha mpango na `429` kwa kikomo cha mgao. Vichwa vya `character-cost`, `song-id`, `request-id` na `retry-after`
huhifadhiwa vinapokuwepo. Salio la mkopo bila malipo halihakikishi ufikiaji wa kila
muundo wa muziki, umbizo la matokeo au kipengele cha API: ElevenLabs huamua haki ya ufikiaji kwa kila ombi.
Endpoint iliyounganishwa huhifadhi misimbo ya hali ya hitilafu katika bahasha ya hitilafu iliyosanifishwa ya OmniRoute.

Mikataba ya mtoa huduma wa juu: [athari za sauti](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[utunzi wa muziki](https://elevenlabs.io/docs/api-reference/music/compose) na
[maelezo ya muziki unaotiririshwa](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

Kwa wateja wasioweza kuambatisha `Authorization: Bearer ...`, OmniRoute pia hukubali funguo za API kwenye URL kupitia uoanifu wa mfuatano wa hoja (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`) au vituo maalum vya `/api/v1/vscode/{token}/...` vilivyoelezwa hapa chini.

```bash
# Panga upya (mtoa huduma wa sajili ya wingu, au nodi ya mtoa huduma inayooana na OpenAI kama "<prefix>/<model>")
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Uainishaji wa Jina (vitambulisho vya Foundation API)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Kigawanyaji cha Jina
POST /v1/segment     { "content": "...", "return_chunks": true }

# Utafutaji wa Jina (s.jina.ai; lakabu za mtoa huduma: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# Udhibiti wa maudhui
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — hurejesha mwili wa audio/mpeg (au muundo ulioombwa)
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS inahitaji lugha na sauti: `language` huwa "en" kwa chaguo-msingi; sauti
# isiyokuwepo au jina la sauti ya kawaida ya OpenAI (alloy, nova, …) hubadilishwa kuwa "Adrian"
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# Uhariri wa picha (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# Uzalishaji wa video / muziki (kitambulisho cha modeli chenye kiambishi awali cha mtoa huduma)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **Nodi za watoa huduma za upangaji upya:** `POST /v1/rerank` pia huelekezwa kwenye nodi za watoa huduma zinazooana na OpenAI
> (oMLX, vLLM, Infinity, TEI nyuma ya lango, …) zinazotambulishwa kama `<node-prefix>/<model>`. Nodi za
> loopback (`localhost`, `127.0.0.1`, `172.16.0.0/12`) zinastahiki kila wakati, kama zilivyo pia hostname ambazo
> mwendeshaji anaorodhesha katika `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (k.m. jina la huduma ya Docker/Compose kama
> vile `http://reranker:8080/v1`; hizi huitwa moja kwa moja, kamwe si kupitia `HTTP(S)_PROXY` au
> proksi iliyobandikwa ya muunganisho). Nodi kwenye host nyingine yoyote
> — kifaa cha LAN au peer ya Tailscale — zinastahiki tu wakati mwendeshaji anapowasha
> alama ya kipengele ya `RERANK_REMOTE_PROVIDER_NODES` **na** URL ya msingi ya nodi inakidhi sera ya URL
> zinazotoka ya mtoa huduma (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Hatua ya kupanga upya ya injini ya kumbukumbu huita route hii kupitia
> loopback, kwa hivyo sheria hiyo hiyo inadhibiti `rerankProviderModel` katika mipangilio ya Kumbukumbu.
>
> **Miundo ya seva za ndani:** nodi huitwa katika `<base>/v1/rerank` na, inapopatikana 404, katika `<base>/rerank`
> (Infinity, TEI). Body inayotumwa upstream hubeba uandishi wa Cohere/OpenAI (`documents`,
> `return_documents`) pamoja na uandishi wa TEI (`texts`, `return_text`), na response ya upstream
> husawazishwa kuwa muundo wa bahasha ya Cohere: muundo wa moja kwa moja wa TEI wa `[{index, score, text}]`, `{results: [{index, score}]}`
> kutoka kwenye malango mepesi, na muundo wa Voyage wa `{data: [...]}` yote humrudia mteja kama
> `{results: [{index, relevance_score, document?}]}`, ikiwa imepangwa kwa alama na kuwekwa kikomo cha `top_n`.

> **Ugunduzi wa nodi za watoa huduma:** modeli kwenye nodi ya mtoa huduma inayooana na OpenAI huonekana katika `GET /v1/models`
> chini ya kiambishi awali cha nodi. Rekodi zisizo na metadata ya endpoint (hali ya kawaida kwa orodha za ndani za `/v1/models`)
> hurithi `apiType` ya nodi, kwa hivyo modeli za nodi ya `embeddings` huwa `type: "embedding"` na
> modeli za nodi ya `rerank` huwa `type: "rerank"` badala ya kutumia chat kama chaguo-msingi; thamani bayana ya
> `supportedEndpoints` kwenye rekodi iliyosawazishwa au iliyoongezwa mwenyewe bado hupewa kipaumbele.

## API ya Faili

Endpointi ya faili inayooana na OpenAI kwa ingizo/tokeo la kundi na upakiaji kulingana na madhumuni ya faili.

| Mbinu  | Njia                     | Maelezo                                                                                                             |
| ------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/files`              | Pakia faili (sehemu nyingi: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — upeo wa MiB 512 |
| GET    | `/v1/files`              | Orodhesha faili za ufunguo wa API uliothibitishwa                                                                   |
| GET    | `/v1/files/[id]`         | Pata metadata ya faili                                                                                              |
| DELETE | `/v1/files/[id]`         | Futa faili                                                                                                          |
| GET    | `/v1/files/[id]/content` | Tiririsha maudhui ghafi ya faili                                                                                    |

**Uthibitishaji:** Ufunguo wa API wa Bearer — faili huwekewa mawanda kwa kila ufunguo wa API kupitia `getApiKeyRequestScope`. Ufunguo
huona, hupakua na hufuta faili zake pekee; kipindi cha dashibodi kisicho na ufunguo husoma
instansi nzima; faili isiyo na mmiliki (iliyopakiwa bila utambulisho au kupitia kipindi cha dashibodi) huzuiwa kwa kila
mwombaji asiye wa kipindi. `GET /v1/files` humkataa mwombaji asiye na utambulisho — na ufunguo uliowasilishwa ambao
hauwezi kutambuliwa — kwa `401` hata wakati `REQUIRE_API_KEY=false`, badala ya kuorodhesha faili za

### Exa na Tavily `provider_options`

Exa na Tavily walisoma sehemu mahususi za mtoa huduma kutoka kwa mfuko ulio na nafasi ya majina: `provider_options.exa` (au `provider_options["exa-search"]`) na `provider_options.tavily` (au `provider_options["tavily-search"]`). Funguo zilizo hapa chini pekee ndizo zinazosambazwa. Kila moja inaangaliwa dhidi ya schema yake Zod ndani `open-sse/handlers/search/providerOptionsPassthrough.ts`, na ufunguo ulio na aina mbaya hudondoshwa. Kitufe kingine chochote kimepuuzwa, ikijumuisha auth, base URL, `stream` na `outputSchema`. Vifunguo bapa vinavyotumiwa na watoa huduma wengine (`cx`, `depth`, ...) hufanya kazi kama hapo awali.

| Mtoa huduma | Viwanja vya hali ya juu                                                                                                                                                                                                                                                                                                                                                   | Nested                                                                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mfano       | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (flat primitives), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                              | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` iliunganishwa juu ya `{ text: true, highlights: true }` chaguo-msingi |
| Tavily      | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                   |

Sehemu za jumla hushinda kila wakati: `query`, `max_results`, `filters` (vikoa), `country` na mada inayotokana na `search_type`. Kwenye Exa, `search_type: "news"` huweka `category: "news"`. Tavily pia anakubali `search_type: "finance"` (`topic: "finance"`).

Gharama ya utafutaji ya Firecrawl inarekodiwa kwa kila block iliyoanza ya matokeo 10 yaliyorejeshwa, kwa $0.002 (salio 2) block na angalau block moja kwa kila simu ( [Billing Firecrawl](https://docs.firecrawl.dev/billing) ): Matokeo 11 yanagharimu $0.004.

`time_range` ya jumla sasa inawafikia watoa huduma wote wawili: Exa anapata `startPublishedDate` (muhuri wa muda wa ISO ) na Tavily anapata `start_date` (`YYYY-MM-DD`). Tarehe ya wazi katika `provider_options` inabatilisha ile iliyochorwa.

Matokeo ya Exa huweka `id`, `highlight_scores`, `summary`, `subpages`, `entities` na `extras` katika `provider_raw`. Matokeo ya Tavily huweka `images` na `favicon`.

Gharama ya utafutaji ya kiunganishi imerekodiwa kuwa $0.005 kwa `depth` `fast` na `standard` na $0.05 kwa `deep` ( [Bei ya kiunganishi](https://docs.linkup.so/pages/documentation/development/pricing) ), iwe `depth` inatoka `provider_options` au mipangilio ya muunganisho.

Exa `type: "lite"` (Exa 3.0) inakubali seti ndogo ya sehemu na kukataa ombi zima wakati uga mwingine wowote umewekwa. Kwa lite, `additionalQueries`, `systemPrompt` na kila kitufe cha `contents` isipokuwa `text` na `highlights` hudondoshwa kabla ya simu. `subpages`, `subpageTarget`, `highlights.numSentences` na `highlights.highlightsPerUrl` zilizoacha kutumika hazisambazwi tena.

Uhasibu wa gharama ni sajili bapa `costPerQuery`, isipokuwa Exa, ambayo inafuata bei ya Exa mwenyewe: $0.007 kwa simu kwa `auto` (na legacy `fast`) au $0.004 kwa `lite` (na urithi `instant`), inayojumuisha matokeo 10; $0.001 kwa kila matokeo zaidi; na $0.001 kwa kila tokeo lililorejeshwa wakati `contents.summary` imewekwa. Tavily imerekodiwa kwa salio 1 ($0.008) kwa `search_depth` `basic`, `fast` na `ultra-fast`, na salio 2 ($0.016) kwa `advanced` ( [mikopo ya Tavily API](https://docs.tavily.com/documentation/api-credits) ). Simu iliyo na `auto_parameters: true` ambayo Tavily inaboresha hadi ya hali ya juu bado inarekodiwa kwa mkopo 1.

## API ya Web Fetch

Dondoa maudhui kutoka kwenye URL kupitia mtoa huduma wa web-fetch aliyesanidiwa (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, ufunguo uleule wa API kama Parallel Search) hurejesha Markdown
pekee — `format` nyingine yoyote husababisha `400` — na huweka kikomo cha maudhui kuwa herufi 100,000. Wakati
ukurasa lengwa wenyewe hauwezi kudondolewa, huduma ya juu huripoti hilo ndani ya HTTP 200;
OmniRoute hulionyesha kama `422` yenye ujumbe usiobadilika.

| Mbinu | Njia            | Maelezo                                                     |
| ----- | --------------- | ----------------------------------------------------------- |
| POST  | `/v1/web/fetch` | Leta/chambua URL — body huthibitishwa na `v1WebFetchSchema` |

**Uthibitishaji:** Ufunguo wa API wa Bearer (`extractApiKey` + `isValidApiKey`). Sera hutekelezwa kupitia `enforceApiKeyPolicy`.

**Njia mbadala inayozingatia kiasi (#8297):** wakati hakuna `provider` dhahiri iliyotolewa, kundi
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) hupitiwa kwa mpangilio thabiti
wa kipaumbele (jaza-kwanza) — mtoa huduma aliyesanidiwa lakini aliyewekewa kikomo cha kasi hurukwa
badala ya kusitisha ombi mapema, na hitilafu ya huduma ya juu inayoweza kujaribiwa tena/ya kiasi
(HTTP 429 kila wakati; 402/403 kwa viwango vya bure vya mtindo wa kiasi vya Firecrawl/Tavily/TinyFish —
si kwa Jina Reader, na kamwe si kwa ombi batili la kawaida la 400) huendelea hadi kwa
mtoa huduma mwingine mwenye kitambulisho ambaye bado hajajaribiwa wakati wa ombi. Wakati kila mtoa huduma katika
kundi ameishiwa, endpoint hurejesha `429` moja (yenye header ya `Retry-After`)
badala ya `400` ya jumla iliyokuwepo awali. Wakati `provider` dhahiri
imeombwa, **hakuna** njia mbadala ya kimyakimya — mtoa huduma dhahiri aliyewekewa
kikomo cha kasi au aliyeshindwa huonyesha hitilafu yake mwenyewe (`429` ikiwa amewekewa kikomo cha kasi, vinginevyo hali ya
huduma ya juu).

## Utiririshaji wa WebSocket

```bash
GET /v1/ws?handshake=1
```

Huthibitisha handshake ya uboreshaji wa WebSocket na kurejesha mifano ya ujumbe wa itifaki ya waya (`request`, `cancel`). Fremu halisi za WS hushughulikiwa na seva ya WS iliyojumuishwa nje ya jedwali la route la Next.js.

**Uthibitishaji:** Ufunguo wa API wa Bearer wakati wa handshake.

### API ya Responses kupitia WebSocket (codex pekee)

```bash
# Host:port sawa na API ya HTTP (chaguomsingi 20128); boresha muunganisho:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (au: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Fremu ya kwanza LAZIMA iwe response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proksi ya Responses-API-kupitia-WebSocket imeunganishwa **kwa `codex` pekee** (backend ya ChatGPT).
Husikiliza kwenye port sawa na API/dashboard katika njia `/v1/responses`,
`/responses`, na `/api/v1/responses`. Katika fremu ya kwanza ya `response.create`,
huthibitisha + kuandaa kupitia daraja la ndani la `codex-responses-ws`, huchagua
muunganisho wa OAuth wa codex, na kutengeneza handaki kwenda `wss://chatgpt.com/backend-api/codex/responses`
kupitia usafirishaji wa `wreq-js`. **Modeli zisizo za codex hukataliwa** (`codex_ws_provider_required`).
Kwa uelekezaji wa quota-share tumia `model: "qtSd/<group>/codex/<model>"`. Imetekelezwa katika
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Uthibitishaji:** Ufunguo wa API wa Bearer wakati wa handshake. Seva ya HTTP iliyojumuishwa (`server-ws.mjs`)
lazima iwe entrypoint inayotumika (ndivyo ilivyo kwa chaguomsingi, wakati `app/server-ws.mjs` ipo).

#### Kitambulisho cha modeli: tumia kitambulisho halisi cha ChatGPT (bila kiambishi awali cha `codex/`)

**Codex CLI** ya OpenAI huthibitisha jina la modeli upande wa mteja wakati
`supports_websockets = true` na **hukataa vitambulisho vyenye kiambishi awali cha mtoa huduma** kama
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Tuma kitambulisho **halisi** (kwa mfano `gpt-5.5`). Daraja la OmniRoute ni
la codex pekee, kwa hivyo hutatua upya kitambulisho halisi kama modeli ya codex
(`resolveCodexWsModelInfo`) kabla ya kutengeneza handaki kwenda huduma ya juu — ingawa kitambulisho halisi cha
`gpt-5.5` kingeelekezwa kwa mtoa huduma mwingine kupitia HTTP.

#### Kusanidi OpenAI Codex CLI

Elekeza Codex CLI kwa OmniRoute kwa kuongeza mtoa huduma maalum mwenye usaidizi wa WebSocket
kwenye `~/.codex/config.toml` (tumia `CODEX_HOME` tofauti ili kuepuka kubadilisha
usanidi uliopo):

```toml
model = "gpt-5.5"                 # kitambulisho halisi — SI "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # bila slash ya mwisho; URL ya WS hutokana nayo (tumia https/wss katika mazingira ya uzalishaji)
wire_api = "responses"                    # thamani pekee inayotumika tangu Feb 2026
supports_websockets = true                # huwezesha usafirishaji wa Responses-over-WS
env_key = "OMNIROUTE_API_KEY"             # huhifadhi ufunguo wa API wa OmniRoute (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # ufunguo wa API wa OmniRoute (ufunguo wowote ikiwa REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI huboreshwa kutoka `base_url + /responses` hadi WebSocket na OmniRoute huitengenezea handaki
kwenda kwenye muunganisho wa OAuth wa codex uliochaguliwa. Imethibitishwa mwanzo-hadi-mwisho dhidi ya seva ya ndani:
ChatGPT hurejesha `codex.rate_limits` + `response.created` na kutiririsha
ukamilishaji.

## Matumizi ya huduma binafsi (`/api/usage/om-usage`)

Ufunguo wowote wa API unaweza kusoma matumizi na migao **yake mwenyewe** — hakuna uthibitishaji wa usimamizi unaohitajika. Hiki ndicho kituo ambacho
mteja (CLI, paneli ya OmniCopilot) hutumia kumwonyesha mwenye ufunguo matumizi yake ya fedha.

```bash
# Muundo wa maandishi (mkataba wa awali — maandishi tupu kwa ajili ya terminali)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Muundo wenye mpangilio — unaotumiwa na UI

  "http://localhost:20128/api/usage/om-usage?format=json"
```

Ni lazima ufunguo uwe na **`allowUsageCommand`** iliyowezeshwa (imezimwa kwa chaguomsingi — kidhibiti cha funguo za API cha dashibodi
huiwasha au kuizima kwa kila ufunguo). Bila hiyo, kituo hujibu `403`.

`?format=json` hurejesha muundo wenye kibainishi ili mpigaji asisome kamwe sehemu ya data kutoka kwenye
jibu la kukataliwa. Inapofanikiwa:

```jsonc
{
  "allowed": true,
  // ipo tu wakati ufunguo umechagua kutumia vikomo vya matumizi vya kila ufunguo (USD ya kila siku/kila wiki):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // muhtasari wa mgao wa mtoa huduma aliyechaguliwa, au null wakati bado hakuna chochote kilichohifadhiwa kwenye akiba:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // muhtasari wa kila muunganisho, ili UI iweze kuonyesha watoa huduma kadhaa sambamba:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],

```

Inapokataliwa (`401` ufunguo mbaya / `403` hairuhusiwi), njia hiyo hiyo hurejesha
`{ "allowed": false, "error": { "message": "…" } }` — `personal`/`provider` iliyopo lakini tupu

**Uthibitishaji:** Ufunguo binafsi wa API wa Bearer wa mpigaji, unaothibitishwa kwa `isValidApiKey` — hii _si_
sehemu ya usimamizi (`/api/keys/…`), ambayo inaendelea kulindwa na `requireManagementAuth`.

### Asilimia Halisi dhidi ya Asilimia za Mgao Zilizorekebishwa kwa Kikomo

Wakati wa kutumia `/api/usage/om-usage`, wapigaji wanapaswa kutambua tofauti kati ya
asilimia zinazoonyeshwa na **matokeo ya maandishi tupu** na **matokeo ya JSON** yaliyopangwa:

| Kipengele                  | Muundo wa maandishi tupu (`/api/usage/om-usage` / `@@om-usage`)                                          | Muundo wa JSON (`?format=json`)                                                            |
| :------------------------- | :------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------- |
| **Sehemu ya matokeo**      | `NN% left` (k.m., `20% left`)                                                                            | `provider.quotas` / `providers[].quotas`                                                   |
| **Kipimo**                 | **Kiasi kinachoweza kutumika kilichorekebishwa kwa kikomo**: uwezo uliosalia juu ya kizingiti cha kikomo | **Mgao halisi wa upstream**: kipimo cha mtoa huduma ambacho hakijarekebishwa               |
| **Ubadilishaji wa kikomo** | Hubadilishwa kupitia `effectiveRemainingPercent()` ili akiba iliyolindwa isomeke kama `0% left`          | Hakuna (thamani halisi za muhtasari kama zilivyoripotiwa na mtoa huduma)                   |
| **Data ya kizingiti**      | Imejumuishwa katika asilimia inayoonyeshwa                                                               | Imehifadhiwa katika `quotaWindowThresholds` kwa kila muunganisho (au chaguomsingi za seva) |
| **Mtumiaji mkuu**          | CLI shirikishi, vidokezo vya terminali, waendeshaji wa kibinadamu                                        | Miunganisho ya kiprogramu, dashibodi, uchanganuzi, vifuatiliaji vya malipo                 |

#### Fomula ya Marekebisho ya Kikomo

OmniRoute hutumia vikomo tendaji vya mgao ili kuzuia kuisha kwa rasilimali za upstream (vinavyosanidiwa kupitia
`quotaWindowThresholds` za muunganisho, chaguomsingi za mtoa huduma, au mipangilio ya jumla ya ustahimilivu). Wakati kizingiti cha kikomo
(k.m., `cutoff = 25%`) kinatumika kwenye dirisha la mgao, kionyeshi cha maandishi hukokotoa kiasi kilichosalia kama ifuatavyo:

- Ikiwa `remaining <= cutoff`: hurejesha `0%`.
- Ikiwa `remaining > cutoff`: hurejesha `((remaining - cutoff) / (100 - cutoff)) * 100`.

Matokeo ya maandishi yaliyopangiliwa huzungusha thamani hii hadi nambari kamili iliyo karibu zaidi (`Math.round(...)`).

#### Mfano wa Ufafanuzi

Fikiria dirisha la mtoa huduma lenye **matumizi halisi ya 60%** (hivyo **mgao halisi uliosalia wa 40%**) na
kizingiti kilichosanidiwa cha **kikomo cha 25% cha mgao uliosalia**:

| Uwakilishi                           | Ukokotoaji                                         | Iliyosalia |            Matumizi Yanayodokezwa            |
| :----------------------------------- | :------------------------------------------------- | :--------: | :------------------------------------------: |
| **JSON halisi (`?format=json`)**     | Muhtasari wa upstream (`quotas[window]`)           |  **40%**   |                   **60%**                    |
| **Muundo wa maandishi (`NN% left`)** | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` |  **20%**   | **80%** (ikiwa unakokotoa `100 - remaining`) |

- **Kwa nini maandishi yanaonyesha 20% iliyosalia:** Kati ya 40% ya mgao halisi uliosalia kwenye akaunti, 25% imehifadhiwa na
  sera ya kikomo. Mpigaji ana nafasi inayoweza kutumika ya 15% tu kati ya 75% iliyosalia kabla ya kipanga-njia kuacha
  kuelekeza maombi kwenye muunganisho huu. Ubadilishaji huhakikisha muunganisho unaashiria kuisha (`0% left`) wakati hasa ambapo
  uelekezaji utasitishwa.
- **Kwa nini JSON huhifadhi thamani halisi:** Data ya JSON hurejesha muhtasari kamili wa mtoa huduma (`UsageSnapshot`)
  ili zana za nje ziweze kufikia matumizi halisi ya upstream na
  `quotaWindowThresholds` za kiwango cha muunganisho bila ubadilishaji wenye upotevu unaofanywa na seva.

#### Mwongozo wa Uhamishaji kwa Watumiaji

Ikiwa ujumuishaji wa nje (kama vile programu-jalizi ya kihariri au kiendelezi cha ajenti) hapo awali ulikusanya maandishi kutoka
endpoint (`NN% left`) na kukokotoa asilimia iliyotumika kama `100 - NN`, kuhamia kwenye `?format=json` kunamaanisha:

- Kusoma thamani ghafi za JSON kutaonyesha **matumizi halisi ya huduma chanzo** (60% imetumika katika mfano ulio hapo juu).
- Ikiwa ujumuishaji unataka kuhifadhi semantiki ya kiwango kinachoweza kutumika ya endpoint ya maandishi, unaweza kutathmini
  fomula halisi ya kiasi kilichosalia upande wa mteja kwa kutumia `quotaWindowThresholds` kwa ubatilishaji wa kiwango cha muunganisho.

### Athari kwenye muda wa kusubiri

HIT ya kashe ya kisemantiki hutoa jibu kutoka kwenye kashe **bila kufanya mwito wa upstream**, kwa hivyo `X-OmniRoute-Response-Latency` inayoripotiwa huwa karibu na sifuri
(bila kujali muda wa kusubiri wa awali wa upstream). Wateja wanaozingatia
muda wa kusubiri (vipimo vya utendaji, ufuatiliaji wa p50/p99) wanapaswa kuangalia kichwa cha jibu cha
`X-OmniRoute-Cache-Latency`:

| Thamani     | Maana                                                                    |
| ----------- | ------------------------------------------------------------------------ |
| `synthetic` | Jibu limetolewa kutoka kwenye kashe; muda huo si muda halisi wa upstream |
| _(haipo)_   | Jibu limetoka kwenye mwito halisi wa upstream                            |

### Kupita kashe kwa kila ufunguo

Funguo za API zinaweza kuchagua kutosoma kashe ya kisemantiki kupitia `cacheDefaultMode`:

| Thamani  | Tabia                                                      |
| -------- | ---------------------------------------------------------- |
| `legacy` | Tabia ya kawaida ya kashe (chaguo-msingi)                  |
| `bypass` | Ruka kabisa utafutaji wa kashe; tumia upstream kila wakati |

Weka wakati wa kuunda ufunguo (`POST /api/keys`) au kusasisha (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### Kupita kashe kwa kila ombi

Ombi lolote linaweza kupita kashe bila kujali mipangilio ya ufunguo:

```
X-OmniRoute-No-Cache: true
```

Kwa modeli zilizosawazishwa/zilizoletwa, `PUT /api/provider-models` hukubali `provider`, `modelId`, na
`maxOutputTokenOverride`: nambari kamili chanya huweka kikomo cha tokeni za matokeo kwa mikono, na `null`
hukiondoa ili kurejesha chaguo-msingi. `GET /api/provider-models?provider=<provider>` hurejesha thamani hizi
katika `modelOutputOverrides`, ikiwa ni pamoja na modeli zisizo na safu ya modeli maalum. Ubatilishaji
hutumia uwezo wa wakati wa utekelezaji wa `max_output_tokens` na hudumu baada ya modeli kusawazishwa upya. Ukurasa wa mtoa huduma
unaooana na OpenAI hutoa vidhibiti sawa vya kuhariri/kuondoa na huweka alama kwenye modeli zinazotumia uwezo wa kuona moja kwa moja.

Nodi maalum za Chat Completions hurekebisha maombi ya wazi ya kutohoji kwa ajili ya mfumo wa juu. Jaribio
la muunganisho lililofaulu huchagua kiotomatiki vidhibiti vya kiolezo cha gumzo kwa kila kitambulisho sahihi cha modeli
ambacho ingizo lake la `/models` linathibitisha thamani inayotambulika ya `owned_by`: `vllm`, `sglang`, au `llamacpp`.
Vifuniko vinavyooana na OpenAI visivyoonekana vinaweza kuhifadhi ingizo la awali la modeli ndani ya kipengee
cha `openai` kilichopachikwa; utambuzi hufuata hadi vifuniko vitatu kama hivyo. Modeli zenye umiliki unaokosekana, usiojulikana, au
unaokinzana hudumisha tabia ya kawaida ya OpenAI. Utambuzi hutumia tena ombi lililopo la katalogi,
hauzalishi tokeni zozote za ukamilishaji, na hubatilishwa wakati endpoint ya muunganisho inapobadilika.

Ili kuweka tabia hiyo kwa mfumo wa juu ambao haufichui metadata hiyo, tumia API iliyopo ya
kusasisha mtoa huduma kwa sehemu:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Tuma mwili huo kwa `PUT /api/providers/<connection-id>`. Kwenye muunganisho huo, kiwango cha wazi
cha juhudi za uhoji cha `none` hutumwa kama `chat_template_kwargs.thinking=false` na
`chat_template_kwargs.enable_thinking=false`. Thamani asilia za wazi za kiolezo hubaki na mamlaka
isipokuwa sheria ya uhoji ya upande wa seva ilazimishe kiwango cha juhudi. Mpangilio huo hutumika tu wakati muunganisho maalum
unaooana na OpenAI unapotuma mwili wa Chat Completions; maombi ya Responses na watoa huduma wa kawaida
hudumisha muundo wao asilia wa ombi. Weka `reasoningControl` kuwa `openai` ili kulazimisha upitishaji wa kawaida wa OpenAI
wa `reasoning_effort`, au iache/seti kuwa `null` ili kutumia utambuzi wa kiotomatiki.

Maombi ya kiainishaji ya hali otomatiki ya Claude Code huweka fikra asilia kuwa imezimwa kwa chaguo-msingi wakati hayana
vidhibiti vya wazi vya uhoji. Utambuzi hutumia alama ya mfumo ya kiainishaji katika maombi ya muundo wa Claude,
wala si majina ya modeli au vikomo vya ukamilishaji. Vidhibiti vya wazi vya mwili, vichwa vinavyotumika vya juhudi/fikra,
sheria za uelekezaji, na kiwango cha juhudi cha modeli kilichotatuliwa hudumisha kipaumbele chake kilichopo. Hatua zote mbili za kiainishaji
huhifadhi vidokezo vyake, vikomo vya ukamilishaji, mifuatano ya kusimamisha, na maamuzi halisi ya ruhusa kutoka mfumo wa juu;
hatua ya pili bado inaweza kutoa uhoji wake unaoonekana ulioombwa kama maandishi ya kawaida.

### Ruhusa za ufunguo wa API

`PATCH /api/keys/{id}` husasisha ruhusa za ufunguo uliopo. Tuma sehemu unazotaka kubadilisha pekee; ombi lisilo na yoyote kati ya hizo hukataliwa kwa `No valid fields to update`. Sehemu zinazokubaliwa hufafanuliwa na `updateKeyPermissionsSchema` katika `src/shared/validation/schemas/keys.ts`.

### Toleo na Mkondo wa Matoleo

```bash
GET /api/system/version
```

Njia ya usimamizi inayopatikana kupitia loopback pekee (uthibitishaji wa msimamizi). Hurejesha toleo linaloendeshwa, toleo la hivi karibuni
lililochapishwa na hali ya usasishaji wa kiotomatiki. `releaseChannel` na `channels` ni sehemu za nyongeza
(awamu ya 3.8.54); `channel` huhifadhi maana yake — hali ya uwekaji ambayo kisasishaji cha dashibodi
hutumia (`npm`, `source` au `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — mkondo wa npm wa build inayoendeshwa: `nightly` kwa matoleo ya `-nightly.*`,
  `next` kwa matoleo mengine ya awali (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` kwa toleo thabiti la
  toleo kuu la zamani kuliko `channels.latest`, vinginevyo `latest`. Kanuni sawa na
  `scripts/release/dist-tag.mjs`, ambayo huchagua dist-tag ya npm wakati wa uchapishaji.
- `channels` — kichwa kilichochapishwa cha kila dist-tag, kutoka `npm view omniroute dist-tags` (njia
  mbadala ya HTTP ya sajili), iliyohifadhiwa kwenye akiba kwa TTL ileile ya dakika 10 kama `latest`. `latest` huwa inapatikana kila wakati
  (hutumia sehemu ya `latest` kama mbadala, kisha `"unavailable"`); `next`, `nightly` na `lts` huonekana
  tu wakati dist-tag hiyo ipo. Ombi la `Cache-Control: no-cache` huonyesha upya utafutaji wote wawili.

Muundo wa mikondo (`latest` = v3 hadi 4.0 GA, `next` = rc, `nightly` = build za `develop`,
`lts` = viraka vya v3 baada ya 4.0 GA) umefafanuliwa katika `docs/ops/RELEASE_STRATEGY.md`.

## Vikomo vya Tokeni

Bajeti za **tokeni** kwa kila ufunguo wa API (tofauti na Bajeti inayotegemea USD iliyo hapo juu). Hutekelezwa moja kwa moja kwenye njia ya ombi: matumizi ya dirisha la sasa la ufunguo yanapofikia kikomo chake, maombi hukataliwa kwa `429 Too Many Requests`. Vikomo vinaweza kuhusishwa na `model` mahususi, `provider`, au kutumika kwa kiwango cha `global` kwa ufunguo mzima; vikomo kadhaa vinapolingana na ombi, kikomo chenye masharti makali zaidi hutumika.

```bash
# Orodhesha vikomo vya tokeni vya ufunguo (hujumuisha matumizi ya moja kwa moja ya dirisha)
GET /api/usage/token-limits?apiKeyId=key-123

# Unda au sasisha kikomo cha tokeni
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Futa kikomo cha tokeni kwa kutumia id
DELETE /api/usage/token-limits?id=tl-abc
```

> **Maelezo ya schema** (`setTokenLimitSchema`): `apiKeyId` na `scopeType` (`model` | `provider` | `global`) zinahitajika. `scopeValue` inahitajika isipokuwa `scopeType` iwe `global` (kwa mfano, id ya modeli kwa upeo wa `model`, au id ya mtoa huduma kwa upeo wa `provider`). `tokenLimit` lazima iwe nambari kamili chanya (hubadilishwa kutoka mfuatano wa herufi). Si lazima: `id` (iache ili kuunda, itoe ili kusasisha), `resetInterval` (`daily` | `weekly` | `monthly`, chaguo-msingi ni `monthly`), `resetTime` (`HH:MM`), `enabled` (chaguo-msingi ni `true`). Majibu ya `GET` huongezea kila kikomo taarifa za `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, na `nextResetAt`. Hiki ni kituo cha aina ya usimamizi (uthibitishaji wa ruhusa hutekelezwa kwa pamoja na mchakato wa authz).

## Ustahimilivu (uliopanuliwa)

OmniRoute hutoa mbinu tatu huru za kushughulikia hitilafu za muda; endpoints za usimamizi zilizo hapa chini huwawezesha waendeshaji kuzisoma na kuzibatilisha:

| Upeo                                 | Hifadhi ya hali                                       | Kusoma                                    | Kuweka upya / kufuta                                             |
| ------------------------------------ | ----------------------------------------------------- | ----------------------------------------- | ---------------------------------------------------------------- |
| Kivunja mzunguko cha mtoa huduma     | `domain_circuit_breakers` + kumbukumbu ya ndani       | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                     |
| Kipindi cha kusubiri cha muunganisho | `rateLimitedUntil` kwenye miunganisho ya watoa huduma | `/api/rate-limits`, `/api/providers/[id]` | (huwezeshwa tena kwa kuchelewa; futa kupitia PUT ya mtoa huduma) |
| Kufungiwa kwa modeli                 | Sajili ya ndani ya upatikanaji wa modeli              | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                         |

`PATCH /api/resilience` hukubali ubatilishaji wa kivunja mzunguko cha mtoa huduma chini ya `providerBreaker.oauth` na `providerBreaker.apikey`. Kila wasifu hutumia `degradationThreshold`, `failureThreshold`, na `resetTimeoutMs`; sehemu hizo hizo zinapatikana katika Dashibodi → Mipangilio → Ustahimilivu.

```bash
# Futa kufungiwa kwa modeli moja
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Futa hali zote za kufungiwa
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Kwa marejeleo kamili ya dhana na chaguo-msingi za kivunja mzunguko: tazama [`CLAUDE.md`](../../CLAUDE.md) → "Hali ya Ustahimilivu Wakati wa Utekelezaji" na [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Foleni ya Kikomo cha Kasi na Wavu wa Usalama wa Uwezeshaji Kiotomatiki

- **Njia ya uandishi inayotumika**: `POST /api/rate-limits` yenye mwili `{"connectionId": "<id>", "enabled": true|false}` ndiyo endpoint ya usimamizi inayotumika kuwasha au kuzima ulinzi wa kikomo cha kasi kwa muunganisho. `PUT /api/providers/[id]` kwa makusudi haibadilishi wala kugeuza `rateLimitProtection` (#11278).
- **Maana ya `enabled: false`**: Kuweka `enabled: false` huondoa ulinzi uliobainishwa moja kwa moja kwa muunganisho, lakini **hakuondoi** muunganisho amilifu wa ufunguo wa API kwenye wavu wa usalama wa uwezeshaji kiotomatiki wa kimataifa (`autoEnableApiKeyProviders = true`). Katika `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), `false` na `undefined` ni sawa; miunganisho amilifu ya ufunguo wa API isiyo na ulinzi uliobainishwa moja kwa moja huendelea kulindwa chini ya wavu wa usalama wa uwezeshaji kiotomatiki.
- **Kuzima kimataifa**: Ili kuendesha miunganisho ya ufunguo wa API bila foleni za kikomo cha kasi, zima wavu wa usalama kimataifa kupitia `RATE_LIMIT_AUTO_ENABLE=false` (mazingira) au `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Mipangilio → Ustahimilivu / `PATCH /api/resilience`).

## Seva ya A2A

OmniRoute hutoa kituo cha mwisho cha A2A (Agent-to-Agent) cha JSON-RPC 2.0 pamoja na kifungashio cha REST kwa ajili ya ukaguzi/matumizi ya dashibodi.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # si lazima isipokuwa OMNIROUTE_API_KEY imewekwa
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Mbinu zinazotumika (zote zinategemea `settings.a2aEnabled`):

| Mbinu            | Maelezo                                                             |
| ---------------- | ------------------------------------------------------------------- |
| `message/send`   | Utekelezaji sawia wa ujuzi; hurejesha `{task, artifacts, metadata}` |
| `message/stream` | Utekelezaji wa utiririshaji wa SSE wa seti ileile ya ujuzi          |
| `tasks/get`      | Leta jukumu kwa kutumia `taskId`                                    |
| `tasks/cancel`   | Ghairi jukumu kwa kutumia `taskId`                                  |

Ujuzi uliojengewa ndani: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Kadi ya Agent

```bash
GET /.well-known/agent.json
```

Hurejesha kadi ya umma ya agent wa A2A (jina, maelezo, uwezo, katalogi ya ujuzi, mpango wa uthibitishaji) — imehifadhiwa kwenye akiba hadharani kwa saa 1. Uthibitishaji hauhitajiki.

### Visaidizi vya REST

| Mbinu | Njia                         | Maelezo                                                                                                                 |
| ----- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| GET   | `/api/a2a/status`            | A2A imewezeshwa + takwimu za majukumu + muhtasari wa kadi ya agent uliohifadhiwa kwenye akiba                           |
| GET   | `/api/a2a/tasks`             | Orodhesha majukumu — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST  | `/api/a2a/tasks`             | (Haijatekelezwa kama kisaidizi cha REST — unda kupitia JSON-RPC `message/send`)                                         |
| GET   | `/api/a2a/tasks/[id]`        | Rejesha jukumu moja                                                                                                     |
| POST  | `/api/a2a/tasks/[id]/cancel` | Ghairi jukumu                                                                                                           |

**Uthibitishaji:** visaidizi vya REST huendeshwa bila uthibitishaji wa usimamizi (vinaweza kusomwa na dashibodi); njia ya JSON-RPC `/a2a` hutumia Bearer `OMNIROUTE_API_KEY` ikiwa imesanidiwa.

## Uthibitishaji

Tazama [Uthibitishaji wa Usimamizi](../guides/MANAGEMENT-AUTH.md) kwa familia nne za
vitambulisho (kipindi cha dashibodi, tokeni ya ndani ya CLI, Tokeni ya Ufikiaji ya
`oma_live_…`, ufunguo wa API wenye upeo wa usimamizi) na jinsi zinavyotofautiana na funguo za uelekezaji.

- Njia za dashibodi (`/dashboard/*`) hutumia kidakuzi cha `auth_token`
- Kuingia hutumia hashi ya nenosiri iliyohifadhiwa; ikishindikana, hutumia `INITIAL_PASSWORD`
- `requireLogin` inaweza kuwashwa au kuzimwa kupitia `/api/settings/require-login`
- Njia za `/v1/*` zinaweza kuhitaji ufunguo wa API wa Bearer wakati `REQUIRE_API_KEY=true`
- "tokeni ya usimamizi" / "ufunguo wa API wenye upeo wa usimamizi" katika rejeleo hili humaanisha mojawapo ya familia zilizo katika mwongozo huo — si aina ya ziada ya siri ambayo haijafafanuliwa

> **Mabadiliko yanayovunja utangamano (v3.8.0)** — `/api/v1/agents/tasks/*` na vituo vya usimamizi wa vipindi vya kusubiri sasa vinahitaji **uthibitishaji wa usimamizi** (kidakuzi cha `auth_token` cha dashibodi au ufunguo wa API wenye upeo wa usimamizi). Wateja ambao hapo awali walitumia njia hizi bila uthibitishaji watapokea `401 Unauthorized`. Tazama commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
