`copilot-m365-web` (alias `m365copilot`) mengirimkan permintaan obrolan format OpenAI melalui sesi Microsoft 365 Copilot yang diautentikasi di `m365.cloud.microsoft/chat`. Ini adalah integrasi asli tidak resmi: tidak diperlukan proses proxy terpisah atau localhost upstream. Penyedia ID, alias dan koneksi impor yang ada tidak berubah. `copilot-web` adalah penyedia berbeda untuk layanan konsumen di `copilot.microsoft.com`.

> **Baru mengenal penyedia Cookie Web?**
>
> Membaca**`docs/getting-started/WEB-COOKIE-GUIDE.md`** untuk proses pengaturan umum, panduan autentikasi, batasan, dan pemecahan masalah sebelum mengikuti panduan khusus penyedia ini.
>
> **Untuk impor lama:** Kredensial untuk penyedia ini adalah** bukan kue** . Jangan menyalin cookie dari `m365.cloud.microsoft`. Kredensialnya adalah parameter kueri WebSocket URL dan segmen jalur, keduanya dibaca dari tab Jaringan DevTools.

## Prasyarat

- Akun Microsoft 365 dengan akses ke Copilot di `m365.cloud.microsoft/chat`
- Browser berbasis Chromium (Chrome, Edge) untuk inspeksi DevTools WebSocket
- Akses ke model yang diminta pada akun tersebut; ketersediaan bervariasi menurut penyewa dan lisensi

## Proses masuk asli (akun kantor atau sekolah)

Memilih**Microsoft 365 Copilot → Hubungkan** dan menyiapkan upaya masuk. Dasbor menggunakan aliran kode otorisasi dengan PKCE; itu tidak meminta kata sandi Microsoft atau kode MFA Anda.

1. Buka a** tab browser kosong** , lalu buka**DevTools → Jaringan** dan aktifkan** Pertahankan catatan** . Lakukan ini sebelum menavigasi ke Microsoft: Windows SSO mungkin akan segera selesai.
2. Salin URL otorisasi yang ditunjukkan oleh dialog koneksi dan navigasikan ke sana di tab yang telah disiapkan. Lengkapi pilihan akun Microsoft atau MFA jika diminta.
3. Di log Jaringan yang disimpan, temukan permintaan ke `https://login.microsoftonline.com/common/oauth2/nativeclient` dan salin secara lengkap** Permintaan URL** .
4. Rekatkan URL itu ke dalam dialog koneksi dan sambungkan. Jangan tempelkan kode mentah atau bilah alamat `wrongplace` terakhir URL: panggilan balik yang diperlukan adalah navigasi sementara.

Setiap percobaan akan berakhir setelah sepuluh menit dan hanya dapat digunakan sekali. Server memeriksa statusnya, pemverifikasi PKCE, dan target autentikasi ulang sebelum menukarkan kode. Setelah kedaluwarsa atau kegagalan pertukaran, mulailah upaya baru. Suatu upaya tidak dapat bertahan jika server dimulai ulang.

Token menggunakan penyimpanan kredensial koneksi yang ada dan jalur penyegaran. Mengautentikasi ulang koneksi memerlukan identitas Microsoft tenant/object yang sama, bukan hanya email yang sama. Ini mempertahankan operator naming/settings dan menggantikan kredensial impor yang sudah usang. Proses masuk asli ditujukan untuk akun work/school ; jalur impor lama tetap tersedia untuk koneksi yang ada dan konfigurasi tingkat yang didukung.

URL panggilan balik penuh adalah kredensial satu kali. Jangan pernah menyertakannya dalam tangkapan layar, log, pesan dukungan, atau komitmen. Aliran ini tidak membuka browser di server, memeriksa riwayat browser Anda, atau memulai server panggilan balik lokal.

## Pengambilan kredensial (metode WebSocket )

1. Masuk di `https://m365.cloud.microsoft/chat` dan mulai percakapan.
2. Membuka**DevTools → Jaringan** .
3. Saring berdasarkan**WS** (WebSocket).
4. Klik koneksi WebSocket Chathub. Carilah URL yang diawali dengan `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Dari itu** Minta URL** , salin:
   - Nilai parameter kueri `access_token` ( JWT berumur pendek).
   - Segmen jalur Chathub setelah `/Chathub/` (misalnya `<oid>@<tenant>`).

URL lengkapnya berbentuk:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Di OmniRoute, pilih**Microsoft 365 Copilot** , pilih opsi API-key/import lama, dan tempelkan kredensial dalam format:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Klik** Uji Koneksi** Dan** Menyimpan** .

## Pengambilan kredensial (HAR import)

Daripada menyalin nilai dari WebSocket URL secara manual, Anda dapat mengekspor file DevTools HAR :

1. Membuka**DevTools → Jaringan** .
2. Mulai atau lanjutkan percakapan Microsoft 365 Copilot (ini memicu koneksi WebSocket ).
3. Klik kanan di panel Jaringan dan pilih** Simpan semua sebagai HAR dengan konten** .
4. Di OmniRoute, gunakan** Impor file .har** tombol pada dialog koneksi penyedia.

OmniRoute memindai HAR untuk Chathub WebSocket URL, mengekstrak `access_token` dan `chathubPath`, dan mengisi bidang kredensial secara otomatis. Impor HAR menerjemahkan masa berlaku JWT dan menunjukkan sisa masa pakai token.

> **Jangan pernah melakukan ekspor HAR, token akses, atau token penyegaran yang sebenarnya.** Nilai pengujian dan dokumentasi harus selalu menjadi pengganti.

## Token seumur hidup dan segarkan

`access_token` berumur pendek (biasanya**~ 75 menit** ). Tanpa token penyegaran yang dapat digunakan, Anda harus mengambil kembali kredensial setelah habis masa berlakunya.

### Penyegaran otomatis dengan `refreshToken`

Di penyedia Microsoft 365** Tambahkan koneksi** atau** Sunting koneksi** dialog, buka** Pengaturan Lanjutan → Refresh token (opsional)** . Tempelkan token penyegaran Microsoft OAuth untuk cakupan `substrate.office.com/sydney` dan simpan. Masukannya ditutupi dan tidak pernah diisi sebelumnya dengan token yang disimpan. Saat mengedit, biarkan kosong untuk mempertahankan token yang ada; tempelkan token baru untuk menggantikannya.

Proses masuk asli memperoleh token penyegaran ketika Microsoft mengembalikannya. Untuk impor lama, gunakan pemberian kode otorisasi Microsoft yang kompatibel dan sudah ada; penyedia ini tidak menerapkan atau menjanjikan aliran kode perangkat. Dengan token penyegaran yang dikonfigurasi, OmniRoute memeriksa `access_token` sebelum meminta dan menyegarkannya hanya ketika perlu disegarkan. Penyegaran yang berhasil juga mempertahankan token penyegaran yang diputar, menghindari pengambilan ulang secara manual sementara token penyegaran tetap valid.

Jika `refreshToken` tidak disetel, Anda harus mengambil kembali kredensial WebSocket secara manual setelah setiap habis masa berlakunya.

## Model dan perutean

Katalog asli mencakup semua IDs mandiri yang terdokumentasi ditambah empat IDs asli asli. Katalog bersifat statis dan tidak bergantung pada akun, bukan pemeriksaan hak akun: rute berbayar dan alias kompatibilitas tetap terdaftar meskipun akun yang terhubung tidak dapat menggunakannya. Label tampilan model menghilangkan nama penyedia dan boilerplate ketersediaan per model; penyedia tetap ada**Microsoft 365 Copilot** . Label ditandai** Alias** atau** Warisan** mempertahankan pengidentifikasi dan pemetaan protokol yang ada, bukan jaminan versi model historis. Proksi mandiri** Impor dari /models** instruksi tidak berlaku untuk penyedia WebSocket asli ini.

| Keluarga teladan  | IDs kanonik                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| Otomatis          | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| GPT sebelumnya    | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |

| Claude Opus       | `claude-opus`, `claude-opus-4.8`                                                                 |

Alias seperti `auto`, `quick`, `think-deeper`, dan alias versi juga terdaftar. `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` dan `copilot-m365-gpt-5-5-chat` yang ada tetap valid. IDs yang terdokumentasi memerlukan awalan penyedia (`copilot-m365-web/claude-opus` atau `m365copilot/claude-opus`): banyak di antaranya merupakan kata umum atau nama model vendor lain, sehingga `claude-opus` tetap melakukan perutean seperti tanpa penyedia ini. Pendaftaran bukanlah janji bahwa Microsoft menyajikan model tersebut ke setiap akun. IDs mandiri mengikuti [katalog protokol](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) publik (peta model-ke-nada yang diekspor dan metadata skenario model-aware). Semua profil asli mempertahankan `availability: "unverified"`; penyertaan dalam katalog bukanlah pengujian akun yang berhasil.

- Penolakan lisensi model eksplisit kembali** 403** `m365_model_not_licensed`, bukan 502. Perutean mengunci pasangan connection/model tersebut, sehingga model berlisensi pada koneksi dapat digunakan.
- `InvalidCopilotLicense` adalah penolakan lisensi tingkat akun, dilaporkan secara terpisah sebagai `m365_account_not_licensed`.
- Throttle per pengguna kembali** 429** `m365_throttled` dan mendinginkan koneksi. Kelelahan akses prioritas kembali terjadi** 429** `priority_access_exhausted` dan memiliki cakupan model. Hasil `OutOfCredits` dengan `errorCode: "ReasoningTurnExhausted"` kembali** 429** `reasoning_turns_exhausted` sebagai gantinya, juga mencakup model, tanpa klaim waktu penyetelan ulang. Dilaporkan pada salah satu penyewa pekerjaan untuk membatasi nada "Berpikir lebih dalam" sementara nada Cepat terus ditayangkan; cakupan itu adalah pengamatan konsumen, bukan sesuatu yang direproduksi oleh repositori ini. Oleh karena itu, perutean juga membuat model `gpt-5.5` dan `gpt-5.6` Think deep lainnya yang terdokumentasi keluar dari rotasi pada koneksi tersebut untuk cooldown yang sama, dan membiarkan nada Cepat dan setiap kegagalan lainnya pada modelnya sendiri. Petunjuk percobaan ulang yang diberikan dipertahankan; penyetelan ulang yang hilang tidak diiklankan sebagai waktu penyetelan ulang yang diketahui.
- Penolakan keamanan Copilot (`Disengaged`) kembali** 400** `provider_safety_rejection`, label penghentian keamanan penyedia bersama. Itu tidak pernah diperhitungkan terhadap kesehatan koneksi, klien SDKs tidak mencoba lagi 400, dan dengan perutean kombo yang diaktifkan `PROVIDER_SAFETY_STOPS_TERMINAL` berhenti di situ alih-alih memutar ulang permintaan terhadap target lain.
- Permintaan pada satu koneksi diserialkan melalui semaphore akun yang ada. Lebih memilih prioritas fallback daripada panel paralel; serialisasi saja tidak menghilangkan batas kecepatan percakapan Microsoft.

## Minta perilaku dan batasan

- Alatnya adalah** ditiru dengan cepat** , bukan panggilan fungsi Microsoft asli. Permintaan yang mendukung alat menggunakan satu generasi buffer; ia tidak menghabiskan generasi berikutnya untuk memilih alat. Hanya alat yang dideklarasikan dengan bentuk argumen yang didukung dan valid yang dikembalikan sebagai panggilan.
- Jawaban terstruktur panjang dengan satu contoh tambahan dipertahankan sebagai prosa. Ini adalah heuristik, bukan bukti niat; aplikasi masih harus menerapkan izin alatnya sendiri.
- Input gambar berfungsi sebagaimana klien web mengirimkannya. Setiap bagian gambar (`image_url` sebagai data URL atau URLHTTPS publik, atau Responses `input_image`) diunggah ke `/m365Copilot/UploadFile` ke dalam percakapan giliran dengan token obrolan, dan pesan menunjuk ke sana dengan anotasi `ImageFile` ; teks menandai tempatnya duduk (`[image 1]`, …). Percakapan baru mengunggah setiap gambar dalam riwayat, percakapan lanjutan hanya mengunggah gambar pesan baru. Hingga 10 PNG, JPEG, GIF atau WebP dengan masing-masing gambar paling banyak 10 MiB (40 MiB per permintaan); formatnya dibaca dari byte. HTTPS URLs diambil melalui penjaga gambar jarak jauh khusus publik yang disematkan DNS. Unggahan yang gagal menggagalkan permintaan (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` atau `m365_image_invalid`); sebuah belokan tidak akan pernah berjalan tanpa gambaran yang diberikan. Bagian non-teks lainnya (audio, file) ditolak secara eksplisit, tidak dihilangkan secara diam-diam.
- Permintaan tindak lanjut melanjutkan percakapan hulu yang sama dan hanya mengirimkan pesan setelah balasan sebelumnya. Itu harus memperluas balasan itu dengan tepat: koneksi yang sama, profil model dan rangkaian alat; sejarah yang tidak berubah (rantai sha256 di setiap pesan); dan id panggilan alat balasannya, atau teksnya hingga spasi. Apa pun yang lain (riwayat yang diedit, sesi lain dengan pesan pertama yang sama, balasan berbeda, percakapan diam selama 30 menit atau mendekati batas 600 pesan Copilot, koneksi tanpa id) memulai percakapan baru dengan keseluruhan riwayat. Giliran yang gagal tidak pernah dilanjutkan, dan `InternalError` tanpa konten dikirim ulang satu kali dalam percakapan baru (** 502** `m365_internal_error` jika gagal lagi). Lanjutan disimpan dalam memori proses: restart memulai percakapan baru.
- Setiap giliran berjalan di obrolan sementara Copilot(`disableMemory=1`): percakapan tetap mempertahankan konteksnya saat berjalan dan tidak pernah muncul di riwayat obrolan akun. Oleh karena itu, pengujian model, Uji Semua, dan pengujian kombo dapat menyelidiki penyedia ini tanpa meninggalkan percakapan.
- Sebuah giliran memiliki tenggat waktu idle 120 detik dan tenggat waktu keseluruhan yang terbatas. Jawaban terakhir, pemfilteran kemajuan, dan pembatalan ditangani oleh transport/composer. asli
- Jawaban berbasis web tetap menggunakan sumbernya. Copilot menandai kutipan sejajar dengan karakter kontrol penggunaan pribadi dan mengirimkan sumbernya sebagai `references`; setiap penanda menjadi tautan Markdown bernomor (`[1](https://…)`, atau URL kosong ketika Copilot menggunakan penanda sebagai target tautan) dengan anotasi `url_citation` yang cocok (`message.annotations`, atau `delta.annotations` pada potongan yang membawa tautan). Sumber yang tidak pernah sampai akan dibuang, sehingga penanda tidak pernah sampai ke klien. Saat streaming, teks setelah kutipan menunggu hingga sumbernya tiba.
- Ringkasan alasan Copilot(`ChainOfThoughtSummary`), ketika model mengirimkannya, dikembalikan sebagai `reasoning_content`, tidak pernah sebagai bagian dari jawaban. Ringkasan yang menulis ulang sendiri akan menghentikan streaming tanpa gagal.
- Sebelum konten apa pun, kegagalan licence/throttle mempertahankan HTTP 403/429 bahkan ketika streaming diminta. Setelah konten dimulai, kegagalan adalah peristiwa kesalahan SSE, tidak pernah berhasil diselesaikan. Penulisan ulang upstream yang tidak dapat diwakili oleh streaming hanya tambahan adalah kesalahan streaming eksplisit; respons alat non-streaming dan buffered mempertahankan teks akhir.
- Ketika Copilot menolak koneksi itu sendiri, jawabannya dilaporkan sebagaimana adanya:** 401** `m365_unauthorized` untuk proses masuk yang ditolak atau kedaluwarsa (masuk lagi),** 429** dengan `Retry-After` untuk pembatasan, dan jika tidak, kegagalan jabat tangan, tidak pernah merupakan kegagalan koneksi umum.

## Pembuatan gambar

`POST /v1/images/generations` dengan `model: "copilot-m365-web/m365-copilot-image"` (alias `m365copilot/m365-copilot-image`) menggambar dengan alat gambar bawaan Copilot, seperti yang dilakukan klien web. Setiap gambar adalah satu putaran Copilot : ia ikut serta dengan rangkaian pilihan gambar klien web dan mendeklarasikan `GenerateGraphicArt`, dan gambar tersebut tiba pada entri kemajuan yang menunjuk pada artefak di layanan Desainer Microsoft. Artefak itu menolak token obrolan, jadi OmniRoute mencetak token Desainer dari token penyegaran koneksi dan mengunduh byte; token hanya dikirim ke `designerapp.officeapps.live.com`.

- Membutuhkan koneksi masuk asli (token penyegaran); token yang ditempel gagal** 400** sebelum giliran apa pun dihabiskan.
- `n` adalah 1–4, masing-masing satu putaran. `size` hanya mengarahkan orientasi (lebih lebar, lebih tinggi atau persegi), yang Copilot baca dari prompt; Copilot memilih ukuran render.
- Gambar dikembalikan sebaris: `b64_json` secara default, data URL untuk `response_format: "url"`.
- Gambar yang dihasilkan menggunakan anggaran harian yang kecil, terpisah dari obrolan. Ketika sudah habis, permintaan gagal** 429** . Giliran yang menjawab tanpa gambar gagal** 502** (atau** 400** /** 503** ketika teks Copilot dibaca sebagai penolakan atau masalah kapasitas); pesannya mengatakan yang mana.

## Model keamanan

- **Integrasi tidak resmi.** Penyedia ini merekayasa balik protokol BizChat WebSocket. Ini mungkin rusak tanpa pemberitahuan ketika Microsoft mengubah titik akhir.
- Bendera `subscriptionRisk: true` mencerminkan bahwa integrasi bergantung pada titik akhir yang tidak terdokumentasi. Pembatasan akun dimungkinkan tetapi belum dikonfirmasi.
- Token akses adalah JWT yang berumur pendek. Perlakukan itu seperti kata sandi: jangan melakukan, mencatat, atau membagikannya.
- Token penyegaran memberikan akses berkelanjutan ke permukaan Microsoft 365. Simpan dengan hati-hati seperti kunci API.

## Pemecahan masalah

### Otentikasi langsung gagal

- Pastikan Anda menyalin dari**WebSocket URL** , bukan dari permintaan XHR/Fetch. Kredensialnya ada di parameter kueri `access_token` pada koneksi WebSocket Chathub — bukan di header `Authorization: Bearer`.
- Pastikan `chathubPath` menyertakan segmen `<oid>@<tenant>` lengkap dari jalur URL.

### Token kedaluwarsa setelah ~ 75 menit

Hal ini diharapkan. Tanpa `refreshToken`, token akses hanya berumur pendek. Salah satu:

- Ambil kembali kredensial dari DevTools, atau
- Konfigurasikan** Pengaturan Lanjutan → Refresh token (opsional)** dalam dialog Tambah atau Edit koneksi untuk penyegaran otomatis.

### Uji Koneksi berhasil tetapi obrolan kembali 401

Untuk koneksi yang dibuat dengan** Masuk dengan Microsoft** , Test Connection memeriksa masa berlaku token akses dan memperbarui token yang kadaluarsa dengan token penyegaran yang disimpan, sehingga pengujian yang lulus juga membuktikan bahwa token penyegaran masih berfungsi.

Untuk kredensial yang ditempel, Test Connection memeriksa bentuk kredensial dan, ketika token memiliki masa berlaku, berarti token yang akan digunakan penyedia belum kedaluwarsa (token yang disimpan dalam koneksi memenangkan pasta yang sudah basi; token penyegaran dihitung sebagai terbarukan). Token yang dicabut sebelum habis masa berlakunya masih lulus ujian; obrolan lalu kembali** 401** `m365_unauthorized`. Menggunakan** Masuk dengan Microsoft** lagi, atau mendapatkan kembali kredensial baru.

### Copilot tidak muncul di daftar penyedia

Pastikan `copilot-m365-web` diaktifkan di** Penyedia dasbor →** . Penyedia mungkin disembunyikan secara default di beberapa tingkatan.
