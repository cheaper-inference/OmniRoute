Gunakan panduan ini untuk memilih siklus pengembangan andal terkecil untuk sebuah pull request. Panduan ini tidak
menggantikan dokumen arsitektur dan keamanan khusus area yang ditautkan di bawah; panduan ini menghubungkan setiap
jenis perubahan umum dengan kontrak, pemeriksaan terfokus, dan cakupan CI-nya.

## Alur yang diikuti setiap perubahan

1. **Pilih basis sebelum mengedit.** Temukan branch `release/v*` aktif tertinggi dan buat branch dari
   ujungnya. Targetkan branch tersebut, bukan `main`. Jika pembekuan rilis sedang aktif, jangan targetkan branch
   yang dibekukan; gunakan siklus aktif berikutnya yang dijelaskan dalam
   [Model Branching & Rilis](BRANCHING_MODEL.md).
2. **Sebutkan kontraknya.** Identifikasi setiap katalog, skema, artefak yang dihasilkan, API publik, atau antarmuka
   pengguna yang dipengaruhi perubahan. Tabel di bawah memberikan set awal minimum.
3. **Tulis atau perbarui pengujian terfokus.** Perubahan produksi di `src/`, `open-sse/`, `electron/`, atau
   `bin/` memerlukan pengujian otomatis dalam PR yang sama. Jalankan file pengujian terkecil yang membuktikan
   perilaku tersebut, lalu pemeriksaan terfokus yang tercantum.
4. **Biarkan CI menjalankan matriks yang luas.** Seluruh shard unit, Vitest, ratchet cakupan, dan
   build produksi dijalankan pada PR. Jalankan rangkaian pengujian yang luas secara lokal hanya ketika kegagalan terfokus menunjukkan
   dampak yang lebih luas atau ketika perubahan mencakup beberapa subsistem.
5. **Selaraskan sebelum peninjauan.** Ambil basis aktif, periksa commit barunya dan diff Anda terhadap
   basis tersebut, lalu lakukan rebase atau merge basis sesuai alur kerja kontributor. Selesaikan konflik file
   yang dihasilkan dan katalog dari sumbernya, hasilkan ulang, jalankan kembali siklus terfokus, dan konfirmasikan bahwa
   PR masih menargetkan branch rilis aktif.
6. **Catat bukti.** Dalam templat PR, cantumkan perintah yang dijalankan, setiap file pengujian yang ditambahkan atau diubah,
   migrasi atau feature flag, dan semua validasi khusus CI yang masih tertunda.

## Jalur emas berdasarkan jenis perubahan

Perintah di bawah ini adalah pemeriksaan terfokus minimum, bukan izin untuk melewati tes yang secara langsung mencakup perilaku yang Anda ubah.

### Penyedia

**Kontrak**

- Definisi penyedia di `src/shared/constants/providers/` dan komposisinya di `src/shared/constants/providers.ts`.
- Model dan kemampuan di `open-sse/config/providerRegistry.ts` atau file registri yang diekstraksi.
- pemilihan Executor/translator, konfigurasi OAuth atau kunci API, dan aset dasbor. Jangan komit diagram `docs/reference/PROVIDER_REFERENCE.md` atau README yang dibuat ulang: penyegaran rilis akan menulis ulang diagram tersebut (`check:pr-derived-paths` menggagalkan fitur PR yang membawanya).
- Kredensial publik harus menggunakan `resolvePublicCred()`; respons kesalahan harus menggunakan pembantu kesalahan yang telah disanitasi bersama. Lihat `docs/security/PUBLIC_CREDS.md` (git; tidak dikompilasi menjadi `/docs`) dan [Error Sanitization](../security/ERROR_SANITIZATION.md).

**Lingkaran terfokus**

```bash
npm run check:provider-consistency
npm run check:provider-assets
node --import tsx/esm --test tests/unit/provider-translate-path-golden.test.ts
node --import tsx/esm --test tests/unit/<provider-or-executor>.test.ts
npm run gen:provider-reference   # preview the generated reference; do not commit it
npm run lint
```

Uji juga setiap kelompok permintaan yang terpengaruh: obrolan, Tanggapan, gambar, penyematan, audio, atau video. Tinjau katalog yang dihasilkan dan perbedaan emas seiring perubahan kontrak; jangan menerimanya begitu saja.

### Rute

**Kontrak**

- Nilai strategi publik dan metadata UI di `src/shared/constants/routingStrategies.ts`.
- Pengiriman dan pemesanan di bawah `open-sse/services/combo.ts` dan `open-sse/services/combo/`.
- Skema kombo, persistensi, status ketahanan, kemampuan model, dan kontrol API/UI.
- Dokumentasi [Mesin Kombo Otomatis](../routing/AUTO-COMBO.md) dan ketahanan saat perilaku berubah.

**Lingkaran terfokus**

```bash
node --import tsx/esm --test tests/unit/combo-<behavior>.test.ts
npm run test:combo:matrix        # strategy or dispatch changes
npm run check:known-symbols      # strategy registration changes
npm run lint
```

Gunakan pengujian hulu tiruan deterministik secara lokal. Asap kombo langsung memerlukan kredensial dan bersifat manual, bukan pengganti CI.

### UI / UX

**Kontrak**

- Next.js route/page dan batas komponen bersama di bawah `src/app/` dan `src/shared/components/`.
- bentuk respons API, status loading/empty/error, perilaku keyboard dan pembaca layar, tata letak responsif, tema, dan perluasan lokal.
- String sumber UI bahasa Inggris di `src/i18n/messages/en.json`; jangan melakukan hard-code pada salinan baru yang dilihat pengguna.

**Lingkaran terfokus**

```bash
node --import tsx --test tests/unit/dashboard/<feature>.test.ts
npx vitest run --config vitest.config.ts tests/unit/ui/<component>.test.tsx
npm run check:dashboard-typecheck
npm run lint
```

Jalankan aplikasi untuk interaksi atau perubahan visual dan periksa area pandang sempit dan lebar. CI menjalankan pembangunan produksi dan rangkaian yang lebih luas; perilaku visual masih memerlukan komponen terfokus, Playwright, atau pemeriksaan manual terdokumentasi yang sesuai dengan perubahan.

### i18n

**Kontrak**

- `src/i18n/messages/en.json` adalah sumber UI ; `config/i18n.json` adalah sumber lokal.
- Katalog CLI tersedia secara terpisah di bawah `bin/cli/locales/`.
- Pertahankan placeholder dan tag ICU dengan tepat. Jangan terjemahkan nama product/provider/model, nama protokol dan header, perintah, pengidentifikasi code/JSON, URLs, variabel lingkungan, atau istilah yang dilindungi seperti `OmniRoute`, `OAuth`, `MCP`, dan `A2A`. Daftar sumber saat ini adalah `scripts/i18n/glossary/protected-terms.json`.

Sebuah fitur PR hanya mengedit `src/i18n/messages/en.json` (CLI: `bin/cli/locales/en.json`); lokal lainnya diselesaikan satu kali per rilis dengan penyegaran rilis atau gelombang terjemahan (`docs/guides/I18N.md` → "Fitur PRs sentuh `en.json` saja"). `npm run check:pr-derived-paths` gagal dalam fitur PR yang mengedit katalog lokal lain.

**Lingkaran terfokus**

```bash
npm run i18n:check-ui-coverage
npm run check:ui-icu
node scripts/i18n/check-key-completeness.mjs --mode=pr      # what CI runs on your PR
node scripts/i18n/check-ui-value-drift.mjs --mode=pr
node scripts/check/check-cli-i18n.mjs --mode=pr              # when CLI strings change
npm run i18n:check-glossary
npm run lint
```

Tanpa `--mode=pr` gerbang ini berjalan dalam mode rilis secara lokal dan melaporkan setiap kunci yang ditambahkan atau ditulis ulang oleh siklus `en.json`; itu adalah pekerjaan penyegaran rilis, bukan milik Anda PR.

Ini adalah panduan untuk sistem yang sudah ada, bukan undangan untuk memperluas perangkat atau model utamanya. Biarkan patch i18n tetap dioperasi saat sistem pengganti sedang dirancang. Jangan jalankan perintah terjemahan yang memanggil layanan eksternal kecuali tugas tersebut secara eksplisit memerlukan terjemahan yang dihasilkan dan Anda telah meninjau perbedaan yang dihasilkan.

### CLI

**Kontrak**

- Perintah dan tanda publik di `bin/cli/`, perintah API yang dihasilkan, kode keluar, bentuk keluaran stdout/stderr dan JSON, perilaku config/environment, dan file paket.
- string yang dilihat pengguna CLI harus menggunakan lapisan CLI i18n ( kunci `t()` yang ada di `bin/cli/locales/en.json`). Sebuah fitur PR hanya mengedit `en.json`; `pt-BR` dan lokal lainnya selesai saat rilis.
- Pertahankan Node sebagai runtime yang didukung dan kontrak biner yang dipublikasikan.

**Lingkaran terfokus**

```bash
node --import tsx/esm --test tests/unit/cli/<command>.test.ts
node scripts/check/check-cli-i18n.mjs --mode=pr
npm run build:cli             # generated/bundled CLI changes
npm run check:pack-policy     # package-surface changes
npm run lint
```

Gunakan perintah yang tepat di direktori data sementara ketika perilakunya bergantung pada penguraian, file, atau status keluar. CI melakukan artefak paket yang lebih luas dan pemeriksaan ekosistem.

### Basis data

**Kontrak**

- Modul domain di bawah `src/lib/db/`; impor modul tertentu secara langsung (lapisan ekspor ulang `localDb.ts` lama telah dihapus).
- Migrasi SQL idempoten bernomor di bawah `src/lib/db/migrations/`, keamanan transaksi, perilaku pemutakhiran, indeks, dan setiap pemanggil yang terpengaruh oleh skema.
- Rute dan penangan tidak pernah mengeluarkan SQL mentah secara langsung.

**Lingkaran terfokus**

```bash
npm run check:migration-numbering
npm run check:db-rules
node --import tsx/esm --test tests/unit/db/<domain>.test.ts
node --import tsx/esm --test tests/unit/db/migration-<number>.test.ts
npm run lint
```

Uji database baru dan tingkatkan dari skema sebelumnya saat menambahkan migrasi. Pengujian basis data harus menutup pegangan dan memanggil `resetDbInstance()` selama pembersihan. Jalankan `npm run test:bun:db` hanya ketika jalur adaptor Bun upaya terbaik berubah; Node tetap berwibawa.

### Bangun / terapkan

**Kontrak**

- Root dan ruang kerja manifests/lockfile, `scripts/build/`, perakitan mandiri Next.js, konten paket `dist/`, metadata platform Electron, alur kerja CI, dan penjaga penerapan.
- Rentang Node yang didukung dan penggunaan Bun yang diizinkan di `CLAUDE.md` harus tetap utuh.
- Artefak yang dibangun tetap tidak terlacak; kebijakan ketergantungan, lisensi, alur kerja, dan paket berlaku.

**Lingkaran terfokus**

```bash
node --import tsx/esm --test tests/unit/build/<behavior>.test.ts
npm run check:build-scope
npm run check:lockfile         # dependency or lockfile changes
npm run check:pack-policy      # published package surface changes
npm run lint
```

Gunakan `npm run build` secara lokal hanya jika perubahan memengaruhi kompilasi, perakitan mandiri, aset, atau bundling waktu proses. Gunakan `npm run build:release` hanya untuk validasi release/deploy. build CI adalah sinyal lintas platform terakhir; Perubahan Electron khusus platform memerlukan bukti build atau smoke yang terfokus dan cocok.

## Skrip developer untuk mesin bersama

Dua helper `scripts/dev/` menangani loop lokal pada devbox tempat sesi lain sedang aktif:

```bash
scripts/dev/typecheck-touched.sh --base release/vX.Y.Z   # file dari merge-base(HEAD, base)..HEAD
scripts/dev/typecheck-touched.sh src/a.ts tests/unit/b.test.ts   # hanya file-file ini
scripts/dev/new-worktree.sh fix/1234-slug release/vX.Y.Z  # worktree terisolasi, aman dijalankan secara paralel
```

- `typecheck-touched.sh` melakukan pemeriksaan tipe hanya pada file `.ts/.tsx` yang tersentuh melalui
  `tsconfig.touched.tmp.json` sementara (`extends ./tsconfig.json`, `types: ["node"]`, `noEmit`,
  `incremental: false`) dengan heap sebesar 6 GB, sehingga menggantikan `tsc -p tsconfig.json`
  untuk seluruh proyek yang mengalami OOM pada mesin dengan beban tinggi. Skrip ini mencetak error
  dalam file yang tersentuh beserta satu baris ringkasan dan keluar dengan kode `1` untuk error
  dalam file yang tersentuh, `2` ketika satu-satunya error berada dalam file yang diimpor atau tsc
  berhenti tanpa diagnostik (baca log yang disebutkan di bawah `_artifacts/typecheck-touched/`),
  dan `0` ketika tidak ada error. tsconfig sementara selalu dihapus; jangan pernah melakukan commit
  terhadap file tersebut.
- `new-worktree.sh` menjalankan proses bersamaan secara berurutan menggunakan
  `<git-common-dir>/omniroute-new-worktree.lock` (menunggu hingga 600 detik secara default, dengan
  pesan yang terlihat; header skrip mendokumentasikan cara menggantinya) dan membatalkan
  branch yang dibuatnya ketika `git worktree add` gagal sebelum worktree tersedia, sehingga
  percobaan ulang tidak memerlukan `git branch -D` manual. `node_modules` yang menggunakan hard link
  dan salinan `.husky/_` tidak berubah.

## Loop kandidat lokal

Pengujian sumber tidak dapat membuktikan bahwa artefak terpaket dapat dimulai: daftar pemaketan,
dependensi yang dipangkas, dan biner native hanya mengalami kegagalan setelah tarball diinstal dan
dijalankan. `npm run dev:candidate` (`scripts/dev/candidate.mjs`) adalah bagian lokal dari alur
build-once / validate / promote dari RFC #8084: perintah ini membuat satu kandidat, memvalidasi
artefak yang persis sama, mempromosikannya melalui penggantian nama direktori, dan melakukan
rollback ketika slot yang dipromosikan gagal dalam pemeriksaan kesehatannya.

```bash
npm run dev:candidate -- run --dry-run --json  # cetak rencana tanpa mengubah apa pun
npm run dev:candidate -- run                   # build + validasi + promosi, rollback otomatis
npm run dev:candidate -- build                 # npm pack + instal ke _artifacts/candidate/<id>/
npm run dev:candidate -- validate --id <id>    # mulai pada port kosong, /api/health + /v1/models
npm run dev:candidate -- promote --id <id>     # <id> → current, current → previous
npm run dev:candidate -- rollback              # tukar current dan previous
npm run dev:candidate -- run --from-tarball <file.tgz>  # gunakan kembali tarball yang dibuat di tempat lain (CI)
```

- **Build sekali.** `build` memaketkan tree saat ini (memerlukan `dist/server.js`, jadi jalankan
  `npm run build:release` terlebih dahulu) atau menyalin `--from-tarball`, kemudian menginstal
  tarball ke prefix npm yang terisolasi karena tarball tidak menyertakan `node_modules`. Id-nya
  adalah sha pendek `HEAD` (`-dirty` ketika tree memiliki perubahan lokal) atau `tgz-<sha256>` untuk
  tarball. Id bersih yang sudah dibuat akan digunakan kembali alih-alih dibuat ulang; teruskan
  `--force` untuk membuatnya ulang.
- **Validasi paket, bukan sumbernya.** `validate` memulai CLI yang telah diinstal
  (`serve --port <free port>`) dengan `DATA_DIR=<candidate>/data` baru, secret palsu, serta
  `OMNIROUTE_API_KEY`, `STORAGE_ENCRYPTION_KEY`, dan `INITIAL_PASSWORD` milik operator yang
  dihapus dari environment, sehingga memeriksa postur loopback tanpa kunci dari instalasi baru.
  Perintah ini menunggu hingga `GET /api/health` mengembalikan 200, mengharuskan
  `GET /v1/models` mengembalikan 200, menghentikan grup proses, dan mencatat hasilnya dalam
  `validation.json` bersama hash tarball.
- **Promosikan artefak yang sama.** `promote` menolak kandidat yang tidak memiliki validasi berhasil
  untuk hash tarball saat ini. Slot aktif default adalah `_artifacts/candidate/current`;
  `--target <dir>` memilih direktori lain pada sistem file yang sama, dan slot sebelumnya adalah
  `<dir>.previous`. Setiap penggantian nama bersifat atomik, dan kegagalan di tengah proses akan
  membalikkan penggantian nama yang telah dijalankan.
- **Lakukan rollback.** `run` memvalidasi kembali slot yang telah dipromosikan dan menukar
  `current` serta `previous` kembali ketika pemeriksaan tersebut gagal. Kandidat yang gagal pada
  validasi pertama tidak akan pernah dipromosikan.

Semuanya ditulis di bawah `_artifacts/candidate/` yang diabaikan oleh git; instalasi OmniRoute yang
sudah ada dan direktori datanya tidak pernah disentuh. CLI yang dipromosikan berada di
`_artifacts/candidate/current/prefix/bin/omniroute`; jalankan dengan `DATA_DIR` milik Anda sendiri
saat menggunakannya. Kode keluar: `0` berhasil, `1` validasi atau promosi gagal, `2` kesalahan
penggunaan atau build tidak tersedia.

## Loop lokal versus CI

| Jalankan secara lokal untuk setiap patch                                                  | CI menyediakan sinyal yang luas                                                |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Pengujian perilaku langsung dan gate kategori di atas                                     | Suite unit lengkap yang di-shard dan pengujian serial                          |
| `npm run lint`                                                                            | Suite Vitest dan ratchet cakupan/kualitas                                      |
| Pemeriksaan tipe atau build hanya jika diwajibkan oleh kontrak yang terdampak             | Build produksi, keamanan, dokumentasi, dependensi, dan gate kebijakan PR       |
| Pemeriksaan interaksi manual/live hanya jika otomatisasi tidak dapat membuktikan perilaku | Pemeriksaan integrasi lintas-job dan platform yang dikonfigurasi oleh workflow |

Loop terfokus yang hijau merupakan bukti tentang kontrak yang diubah, bukan bukti bahwa pemeriksaan CI yang tidak terkait
akan lolos. Sebaliknya, jangan membuat setiap pengeditan lokal menunggu seluruh matriks repositori.

## Daftar periksa rekonsiliasi

Sebelum meminta peninjauan:

- Konfirmasikan bahwa basis PR masih merupakan cabang `release/v*` aktif tertinggi.
- Ambil basis tersebut dan tinjau commit yang masuk sejak Anda membuat cabang.
- Tinjau `git diff <active-base>...HEAD` untuk perubahan yang tidak disengaja atau hasil generasi.
- Selesaikan konflik katalog dan dokumen yang dihasilkan dengan memperbarui sumber dan menghasilkan ulang output.
- Jalankan ulang setiap pengujian/gate terfokus yang tercantum dalam deskripsi PR setelah rekonsiliasi.
- Jangan pernah melonggarkan assertion atau menghapus pengujian wajib hanya agar sesuai dengan basis yang telah berpindah.

Untuk aturan pembekuan rilis dan penargetan ulang, gunakan
[Model Percabangan & Rilis](BRANCHING_MODEL.md). Untuk inventaris CI lengkap, gunakan
[Referensi Gate Kualitas](../architecture/QUALITY_GATES.md).
