## Penyelesaian Chat

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Header Khusus

| Header                   | Arah       | Deskripsi                                                                                                                                                                                                                    |
| ------------------------ | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | Permintaan | Atur ke `true` untuk melewati cache                                                                                                                                                                                          |
| `x-omniroute-no-memory`  | Permintaan | Atur ke `true` untuk melewati injeksi memori + keterampilan bagi permintaan ini (mencerminkan no-cache; menghindari overhead token/biaya per panggilan)                                                                      |
| `X-OmniRoute-Progress`   | Permintaan | Atur ke `true` untuk mendapatkan peristiwa progres                                                                                                                                                                           |
| `X-Session-Id`           | Permintaan | Kunci sesi persisten untuk afinitas sesi eksternal                                                                                                                                                                           |
| `x_session_id`           | Permintaan | Varian dengan garis bawah juga diterima (HTTP langsung)                                                                                                                                                                      |
| `X-OmniRoute-Session-Id` | Permintaan | Tag sesi/percakapan yang diberikan pemanggil (juga digunakan oleh memori). Jika ada, nilainya dipertahankan apa adanya ke `call_logs.session_tag` untuk atribusi biaya per sesi (#8249) — tidak pernah dibuat saat tidak ada |
| `Idempotency-Key`        | Permintaan | Kunci deduplikasi (jendela 5 detik)                                                                                                                                                                                          |
| `X-Request-Id`           | Permintaan | Kunci deduplikasi alternatif                                                                                                                                                                                                 |
| `x-omniroute-connection` | Permintaan | Sematkan permintaan model tunggal ke satu koneksi penyedia (akun) berdasarkan ID-nya — lihat [Penyematan akun per permintaan](#account-pinning-per-request)                                                                  |
| `X-OmniRoute-Cache`      | Respons    | `HIT` atau `MISS` (non-streaming)                                                                                                                                                                                            |
| `X-OmniRoute-Idempotent` | Respons    | `true` jika dideduplikasi                                                                                                                                                                                                    |
| `X-OmniRoute-Progress`   | Respons    | `enabled` jika pelacakan progres aktif                                                                                                                                                                                       |
| `X-OmniRoute-Session-Id` | Respons    | ID sesi efektif yang digunakan oleh OmniRoute                                                                                                                                                                                |
| `X-OmniRoute-Request-Id` | Respons    | ID korelasi permintaan (jika diketahui)                                                                                                                                                                                      |
| `X-OmniRoute-Version`    | Respons    | Versi build OmniRoute (selalu ada)                                                                                                                                                                                           |
| `X-OmniRoute-Cost-Saved` | Respons    | Jumlah USD yang dihemat cache pada HIT (khusus cache hit)                                                                                                                                                                    |
| `X-OmniRoute-Decision`   | Respons    | Jejak perutean: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` adalah strategi kombinasi, atau `single` untuk permintaan non-kombinasi) — selalu ada pada respons penyelesaian                                |

> Catatan Nginx: jika Anda mengandalkan header dengan garis bawah (misalnya `x_session_id`), aktifkan `underscores_in_headers on;`.

#### Penyematan akun per permintaan

Jika suatu penyedia memiliki beberapa koneksi (akun atau kunci), OmniRoute biasanya memilih salah satunya
melalui strategi pemilihan akun. Sebagai gantinya, permintaan dapat menyematkan satu koneksi tertentu
dengan header `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Tempat menemukan ID.** Buka halaman penyedia di dasbor
  (**Dasbor → Penyedia → <provider>**) dan klik chip ID `xxxxxxxx…` pada baris koneksi
  — tindakan ini akan menyalin ID koneksi lengkap.
- **Permintaan yang mematuhinya.** Permintaan model tunggal (`provider/model`) pada
  `/v1/chat/completions`, `/v1/messages`, dan `/v1/responses`. Kombinasi mengabaikan header tersebut: sematkan
  akun untuk setiap langkah kombinasi melalui koneksi milik langkah itu sendiri.
- **Penyematan bersifat ketat, bukan sekadar preferensi.** Koneksi yang disematkan digunakan secara eksklusif. Kegagalan
  di dalam permintaan akan mencatat masa tunggu akun tersebut, tetapi **tidak** beralih ke
  akun lain dari penyedia yang sama.
- **Masa tunggu dan kuota melepaskan penyematan.** Selama koneksi yang disematkan berada dalam masa tunggu,
  kehabisan kuota, atau diblokir oleh kebijakan kuota, permintaan berikutnya akan beralih ke koneksi lain
  milik penyedia tersebut, sama seperti lalu lintas tanpa penyematan.
- **ID yang tidak dikenal atau dinonaktifkan akan menyebabkan kegagalan.** ID yang tidak berada dalam kumpulan aktif penyedia (dihapus,
  dinonaktifkan, atau dimiliki oleh penyedia lain) tidak menyisakan akun yang memenuhi syarat, sehingga permintaan
  akan gagal alih-alih dialihkan ke tempat lain secara diam-diam.

Claude Code mengirim header khusus melalui `ANTHROPIC_CUSTOM_HEADERS`. Letakkan variabel tersebut di blok `env`
pada `~/.claude/settings.json`, atau di `.claude/settings.json` tingkat proyek untuk menyematkan akun yang berbeda
bagi setiap proyek:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Sumber: `src/sse/handlers/chat.ts` (pembacaan header), `src/sse/services/auth.ts`, dan
`src/sse/services/sessionAffinityPin.ts` (pelepasan penyematan dan pemeriksaan ketiadaan dari kumpulan).

> **Header telemetri biaya:** respons sukses non-streaming juga menyertakan kumpulan telemetri biaya `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, tetap 10 angka desimal; `0.0000000000` untuk penggunaan gratis/tanpa harga), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, dan `X-OmniRoute-Fallback-Attempts` (hanya jika > 0), serta `X-OmniRoute-Request-Id` dan `X-OmniRoute-Version`. Header tersebut dihasilkan oleh penyelesaian chat, `/v1/responses`, `/v1/messages`, **dan endpoint media** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations`, dan `/v1/moderations` (biayanya selalu `0`). Biaya media dihitung per modalitas (per gambar, per detik, per karakter, per unit pencarian) jika informasi harga tersedia; jika tidak, biayanya `0` (tetap berjalan saat gagal).

> **Semantik biaya cache hit:** pada HIT cache semantik (`X-OmniRoute-Cache-Hit: true`), tidak ada panggilan upstream yang dilakukan, sehingga `X-OmniRoute-Response-Cost` bernilai `0.0000000000` (biaya **inkremental** untuk menyajikan hit tersebut). Biaya awal/yang seharusnya timbul dilaporkan secara terpisah dalam `X-OmniRoute-Cost-Saved`. Konsumen data penagihan sebaiknya menjumlahkan `X-OmniRoute-Response-Cost` (hit tidak dikenai biaya); analitik cache dapat mengagregasikan `X-OmniRoute-Cost-Saved`.

## Sewa Sesi Terkelola Eksklusif

Penyewaan sesi terkelola eksklusif adalah kontrak perutean opsional yang netral terhadap klien: satu pemilik aktif
memegang satu koneksi OmniRoute yang memenuhi syarat. Kontrak ini tidak menyewakan model, mewajibkan OAuth, mengidentifikasi
klien tertentu, atau mewajibkan penyedia tertentu.

Kunci API yang melakukan autentikasi harus memiliki cakupan `lease:exclusive` dan daftar eksplisit
`allowedConnections` yang tidak kosong. Batas mutasi basis data memberlakukan kedua bidang tersebut secara bersamaan saat
pembuatan kunci dan pembaruan parsial.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Respons akuisisi, perpanjangan, dan pelepasan yang berhasil menampilkan stempel waktu, `state`, dan nilai positif yang tepat untuk
`generation`, tetapi tidak pernah menampilkan koneksi atau kredensial yang dipilih. Perpanjangan dan pelepasan menyertakan
generasi dalam isi JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Pemilik sewa aktif dapat secara eksplisit meminta metadata tampilan yang aman bagi privasi untuk pengikatannya saat ini:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Tindakan status opsional ini dilindungi oleh pemilik opak, kunci API terkelola yang terautentikasi, dan
generasi aktif yang tepat dalam satu transaksi basis data. `displayName` hanyalah nama koneksi terkonfigurasi
yang telah dipangkas; nilainya `null` jika tidak ada nama terkonfigurasi yang aman. OmniRoute tidak pernah menggantinya dengan
email atau identitas akun yang dihasilkan. Nilai penyedia adalah label tampilan yang tidak sensitif dan tidak pernah
berupa pengidentifikasi penyedia kompatibel yang dihasilkan. Kredensial, token, cookie, ID mentah koneksi atau
kunci API, hash pemilik, rahasia pemagaran, dan data perutean internal tidak disertakan.

Pencarian dengan kunci salah, pemilik salah, generasi kedaluwarsa, data tidak ada, sewa kedaluwarsa, dilepas, atau dibatalkan semuanya
mengembalikan kesalahan `409 LEASE_FENCE_STALE` yang sama tanpa metadata koneksi. Klien yang menerima respons menunggu kapasitas tidak memiliki pengikatan aktif untuk diperiksa. Ketika perutean mengalihkan sewa aktif,
generasi yang sama tetap valid dan status secara atomik mengembalikan pengikatan baru, tidak pernah pengikatan lama.
Klien yang sudah ada tetap tidak berubah karena respons akuisisi, perpanjangan, pelepasan, dan menunggu mempertahankan
bentuk sebelumnya.

Kontrak server ini tidak mengubah `/status` OpenAI Codex standar. Codex standar saat ini melaporkan
penyedia model serta status autentikasi/akun bawaannya, tetapi tidak merender metadata akun
penyedia khusus arbitrer; integrasi klien mendatang harus memanggil tindakan ini dan menentukan cara
menampilkan `connection.displayName`.

Setiap permintaan inferensi terkelola kemudian menyertakan kedua header kontrol:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Pemilik yang tepat, generasi, koneksi aktif, dan kunci API yang terautentikasi diperiksa batas pemagarannya tepat
sebelum setiap percobaan upstream yang didukung. Memutar ulang pemilik dan generasi dengan kunci lain akan gagal bahkan
ketika kunci tersebut mengizinkan koneksi yang sama. Pemilik mentah tidak disimpan secara persisten, dicatat dalam log, dipertahankan dalam
snapshot permintaan, atau diteruskan ke upstream.

Kontensi sementara mengembalikan HTTP `429` dengan `Retry-After` dan:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Respons ini hanya berarti bahwa kumpulan biasa yang memenuhi syarat tidak kosong dan setiap kandidat bebas sedang
dipegang oleh sewa aktif milik pihak lain. Model/penyedia yang tidak didukung, ketidakcocokan kebijakan, masa jeda, kuota,
kesehatan, dan kegagalan kelayakan biasa lainnya tetap menggunakan respons OmniRoute yang sudah ada.

### `x-omniroute-compression`

Penggantian paket kompresi per permintaan. Prioritas tertinggi — mengalahkan penggantian kombinasi perutean,
profil aktif, pemicu otomatis, dan Default panel. Nilai:

| Nilai         | Efek                                                                                                                      |
| ------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `off`         | Tanpa kompresi untuk permintaan ini.                                                                                      |
| `default`     | Profil Default yang diturunkan dari panel (mengabaikan profil aktif). Mesin lossy tetap dinonaktifkan.                    |
| `safe`        | Hanya deduplikasi dan pelipatan spasi kosong.                                                                             |
| `allow-lossy` | Pertahankan paket operator untuk permintaan ini, termasuk ringkasan dan penulisan ulang gaya.                             |
| `engine:<id>` | Satu mesin jika diaktifkan, misalnya `engine:rtk`. Keikutsertaan per permintaan untuk mesin tersebut.                     |
| `<combo>`     | Kombinasi bernama, dicocokkan terlebih dahulu berdasarkan nama (tanpa membedakan huruf besar-kecil), lalu berdasarkan ID. |

Catatan:

- Nilai yang tidak dikenal diabaikan (permintaan tidak pernah ditolak); resolusi berlanjut ke urutan prioritas operator normal.
- Jika beberapa kombinasi memiliki nama yang sama, berikan **id** kombinasi untuk pencocokan deterministik.
- Kombinasi dengan nama `off` atau `default` tidak dapat dipilih berdasarkan nama (kata kunci tersebut ditafsirkan terlebih dahulu); rujuk kombinasi tersebut berdasarkan ID-nya.
- Sakelar kompresi utama merupakan gerbang mutlak: ketika kompresi dinonaktifkan secara global, header ini tidak dapat mengaktifkannya.

Paket yang diterapkan dikembalikan dalam header respons:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

dengan `<source>` merupakan salah satu dari `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, atau `off`.

## Embedding

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Penyedia yang tersedia: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

ID katalog menggunakan format `provider/model` (contoh: `jina-ai/jina-embeddings-v5-omni-small`). ID model Jina tanpa awalan yang muncul dalam registri (misalnya `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) juga dapat di-resolve. Operasi embed/rerank/classify/segment Jina terlebih dahulu menggunakan kredensial `jina-ai` dari dasbor; `JINA_AI_API_KEY` hanya digunakan sebagai fallback jika tidak ada kunci dasbor. Kartu `jina-reader` hanya untuk Reader / `r.jina.ai` (`POST /v1/web/fetch`) dan tidak pernah melayani embedding atau rerank.

Model registri yang menyatakan dukungan multimodal juga menerima hingga 32 item terstruktur
yang netral terhadap penyedia. Jenis item media adalah `text`, `image`, `audio`, `video`, dan `document`. `source`
media tersebut dapat berupa `{"type":"url","url":"https://..."}` atau
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
dan alias keluarga `jina-ai/jina-embeddings-v5-omni` → omni-small) juga menerima dokumen
EmbeddingsV5Request native milik Jina dan **meneruskannya secara utuh** ke `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Nilai native `{ image | audio | video | pdf }` dapat berupa URL HTTPS publik, URI `data:`, atau base64
mentah. OmniRoute tidak mengubah objek tersebut menjadi string atau mengambil URL gambar native — Jina mengambil
media publik itu sendiri. Bidang Jina tambahan (`task`, `normalized`, `truncate`, `embedding_type`)
diteruskan. SKU Jina khusus teks tetap menolak dokumen nonteks.

Batasan keamanan dan transportasi:

- URL media jarak jauh harus berupa HTTPS publik. Item kanonis `{type,source:url}` diambil
  di sisi server (validasi ulang pengalihan, batas waktu, batas ukuran, DNS publik, penyematan koneksi) dan
  disematkan sebelum panggilan ke penyedia. Item native Jina `{image:"https://..."}` diteruskan apa adanya
  setelah pemeriksaan HTTPS publik yang sama; Jina mengambil URL tersebut.
- Media base64 inline dibatasi hingga 8 MiB hasil dekode per item dan 16 MiB hasil dekode untuk seluruh permintaan.

Penerjemahan penyedia (item kanonis tidak pernah diteruskan tanpa perubahan):

- Model multimodal Jina: setiap item tingkat teratas menjadi satu objek dengan kunci berdasarkan modalitas
  (`text` / `image` / `audio` / `video` / `pdf`) menggunakan URI data untuk media inline; satu vektor per
  item tingkat teratas.
- Keluarga Gemini Embedding 2: satu array tingkat teratas menjadi satu permintaan native
  `models/{model}:embedContent` dengan `content.parts` (`text` atau `inline_data`).
- llama.cpp (`llama-cpp/<model>`, model apa pun yang dimuat oleh server lokal): item `text` kanonis
  menjadi string biasa, sedangkan `image` / `audio` / `video` masing-masing menjadi satu objek
  `{"content": [part]}`, menggunakan bagian konten chat milik llama-server (`image_url`,
  `input_audio` dengan format `wav` / `mp3` / `flac`, `input_video`) dengan data inline; satu vektor
  per item tingkat teratas. Server harus dijalankan dengan `--embedding --mmproj …`; tanpa proyektor, server
  akan menolak media tersebut. `document` tidak didukung.
- Model tidak dikenal/dinamis tanpa metadata modalitas eksplisit menolak input terstruktur dengan HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Kombinasi model/modalitas yang tidak didukung mengembalikan HTTP 400 alih-alih mengonversi item secara paksa. Bidang ekstensi
selain input pada permintaan string/token lama tetap diteruskan tanpa perubahan.

```bash

GET /v1/embeddings
```

## Pembuatan Gambar

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Penyedia yang tersedia mencakup OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (lokal), ComfyUI (lokal).

`n` mengembalikan `n` gambar dalam `data[]`. Penyedia yang API upstream-nya mengembalikan satu gambar per panggilan
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI) akan menerima `n` panggilan upstream terpisah, dengan maksimal 4 panggilan berjalan bersamaan. Nilai
`seed` tetap di-offset berdasarkan indeks panggilan (`seed`, `seed + 1`, …), sehingga gambar yang dihasilkan berbeda tetapi tetap
dapat direproduksi. `n` dibatasi maksimal 10. Permintaan akan gagal secara keseluruhan jika salah satu panggilan gagal. Daftar
format fan-out adalah `SINGLE_IMAGE_FANOUT_FORMATS` dalam
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux menggunakan kembali koneksi kunci API yang ada dan menerima prefiks `zenmux/` atau `zm/`:

- `zenmux/openai/gpt-image-2` menggunakan OpenAI Images API milik ZenMux. Opsi mencakup `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background`, dan `response_format`.
- Penerbit lain, seperti `zm/meta/muse-image-1.0`, menggunakan endpoint Vertex AI `:predict`
  milik ZenMux. `n` dipetakan ke `sampleCount`, `aspect_ratio` ke `aspectRatio`, dan `image_size`
  (`1K`, `2K`, `4K`) ke `sampleImageSize`. Nilai piksel `size` hanya menyediakan rasio aspek,
  bukan dimensi piksel yang dijamin. Rasio, resolusi, dan jumlah yang didukung berbeda-beda menurut model.
- `zm/inclusionai/ming-image-0.1-design` menentukan dimensinya sendiri. Jangan sertakan `size`,
  `aspect_ratio`, dan `image_size`; nilai eksplisit akan menghasilkan HTTP 400. PNG, JPEG, dan WebP
  dapat diminta menggunakan `output_format`.

Integrasi ini mendukung pembuatan gambar dari teks, bukan pengeditan gambar referensi. Output Vertex
dinormalisasi menjadi `data[].b64_json`; `response_format: "url"` mengembalikan URL HTTPS upstream
atau URL data base64 jika hanya byte gambar yang tersedia. Output kosong/terfilter
akan menghasilkan galat, bukan respons sukses yang kosong. Akses model bergantung pada akun ZenMux.
Lihat [Vertex API ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) dan
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# Cantumkan semua model gambar
GET /v1/images/generations
```

## OCR Dokumen

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model` memilih penyedia OCR melalui prefiks `provider/model`; id model tanpa prefiks (misalnya
`mistral-ocr-latest`) akan diresolusikan ke penyedia terdaftarnya, dan jika `model` tidak disertakan, nilai default-nya adalah
Mistral (`mistral-ocr-latest`). Penyedia terdaftar (`open-sse/config/ocrRegistry.ts`):

| Id penyedia                   | Id model             | Nilai `model`                                                          | Catatan                                                                                                |
| ----------------------------- | -------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (atau `mistral-ocr-latest` tanpa prefiks) | Sinkron — respons dikembalikan langsung dari satu panggilan upstream.                                  |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                            | Upstream asinkron (`analyze` + polling) — lihat di bawah.                                              |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                                | Sinkron, melalui endpoint mitra `openapi/chat/completions` Vertex AI — lihat autentikasi/URL di bawah. |

Ketiga penyedia memberikan respons dalam struktur isi yang sama seperti Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Alur polling Azure Document Intelligence

API `analyze` Azure Document Intelligence bersifat asinkron: permintaan awal mengembalikan header
`Operation-Location`, bukan isi respons, dan hasilnya harus diperiksa melalui polling. Handler
(`open-sse/handlers/ocr.ts`) melakukan polling terhadap URL tersebut setiap detik hingga maksimal 30 percobaan, langsung gagal (tidak
melanjutkan polling) jika respons polling bukan `ok` atau berstatus `"failed"`, dan mengembalikan `504` jika
operasi masih berjalan setelah batas percobaan habis. Respons akhir Azure
dinormalisasi ke dalam struktur `pages`/`markdown` yang sama dengan yang digunakan Mistral sebelum dikembalikan kepada
pemanggil, sehingga kode klien tidak perlu menangani penyedia ini secara khusus.

### Autentikasi dan resolusi endpoint OCR DeepSeek Vertex AI

`vertex-deepseek-ocr` menggunakan kembali autentikasi Vertex AI yang sama dengan yang telah didukung OmniRoute untuk
lalu lintas obrolan/gambar (`open-sse/executors/vertex.ts`): kunci API koneksi berupa
kredensial JSON Service Account (ditukar dengan token akses OAuth berumur pendek melalui alur JWT-bearer)
atau token akses OAuth yang sudah diterbitkan dan digunakan apa adanya. URL endpoint upstream adalah endpoint mitra
generik `openapi/chat/completions` milik Vertex, yang dibuat berdasarkan proyek dan
wilayah koneksi — `providerSpecificData.project`/`providerSpecificData.region` yang ditentukan secara eksplisit selalu diprioritaskan;
jika tidak, proyek diperoleh dari `project_id` dalam JSON Service Account dan wilayah
secara default adalah `us-central1`. Kedua resolusi dilakukan dalam `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), lalu digunakan oleh
`src/app/api/v1/ocr/route.ts` sebelum diteruskan ke `handleOcr`.

### Harga model (`pricing`)

Sebuah entri memuat objek `pricing` ketika OmniRoute mengetahui harga model tersebut. Harga ini berasal
dari tabel harga yang digunakan oleh penghitungan biaya: nilai default bawaan, harga yang disinkronkan, dan
penggantian yang ditetapkan melalui `/api/pricing`. Ini adalah harga katalog, sehingga penyedia langganan juga
menampilkan harga per token.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Bidang                                                          | Satuan                        | Catatan                                                                                                                                                  |
| --------------------------------------------------------------- | ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | USD per token, string desimal | Kompatibel dengan OpenRouter, tidak pernah dalam notasi eksponen. Kedua bidang cache hanya muncul jika ada harga cache.                                  |
| `input`, `output`, `cached`, `cache_creation`                   | USD per 1 juta token, angka   | Bidang dari versi katalog sebelumnya, dipertahankan untuk klien yang sudah ada. `reasoning` dan `long_context` juga muncul jika baris harga memilikinya. |

- **Combo** memuat harga target pertama yang terlihat. Combo bawaan `auto/*` memilih
  target pada saat permintaan, sehingga tidak memiliki `pricing`.
- **Model gratis** menampilkan `"0"` (dan `0`) ketika harganya nol. Model tanpa baris harga
  juga menampilkan `"0"` ketika katalog menandainya sebagai gratis (`free: true`) atau katalog
  model gratis bawaan mencantumkannya.
- **Harga tidak diketahui:** entri tidak memiliki kunci `pricing`.
- **Penyedia dengan pengukuran berbasis kredit** (seperti Kiro) menagih per permintaan, bukan per token. Entri
  mereka mempertahankan bidang numerik per 1 juta yang sebelumnya dimiliki dan tidak memuat bidang string per token.
- **Varian** (ID tingkat upaya penalaran, alias tanpa penalaran, serta mirror penemuan dan gateway)
  menyalin harga model yang menjadi tujuan peruteannya.
- Bidang tersebut hanya memuat tarif dasar. Tingkat konteks panjang (bidang numerik `long_context`) dan
  pengali tingkat layanan (misalnya Codex fast atau flex) tidak mengubah `prompt` atau
  `completion`.
- Objeknya sama untuk setiap gaya autentikasi, termasuk permintaan bergaya Anthropic
  dengan `x-api-key` dan `anthropic-version` (respons tetap berupa `{ "object": "list",
"data": [...] }`). Implementasi: `src/app/api/v1/models/catalogPricing.ts`.

### Prefiks ID model (`?prefix=`)

Sebagian besar model ditampilkan menggunakan **prefiks penyedia**. Prefiks yang diperoleh dikendalikan oleh
feature flag `MODELS_CATALOG_PREFIX_MODE`, dan dapat diganti **per permintaan** dengan
parameter kueri — berguna bagi klien yang menginginkan daftar ringkas tanpa mengubah pengaturan
seluruh server bagi semua pengguna lainnya:

```bash
GET /v1/models?prefix=alias        # satu ID per model — prefiks alias pendek
GET /v1/models?prefix=dual         # kedua bentuk (default server)
GET /v1/models?prefix=canonical    # hanya prefiks ID penyedia lengkap
```

| Mode        | Menghasilkan                                              | Catatan                                                                                                                                                                                                      |
| ----------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `dual`      | `cc/claude-sonnet-4-6` **dan** `claude/claude-sonnet-4-6` | **Default.** Kedua ID merutekan ke model yang sama; dipertahankan agar konfigurasi klien yang melakukan hardcode pada salah satu bentuk tetap berfungsi. Secara kasar menggandakan katalog.                  |
| `alias`     | `cc/claude-sonnet-4-6`                                    | Satu entri per model. Penyedia tanpa alias terpisah tetap menghasilkan entrinya, sehingga tidak ada yang hilang.                                                                                             |
| `canonical` | `claude/claude-sonnet-4-6`                                | Satu entri per model dengan prefiks ID penyedia lengkap. Penyedia tanpa alias terpisah (misalnya `antigravity/…`, `agy/…`) juga menghasilkan satu-satunya ID mereka di sini, sehingga tidak ada yang hilang. |

Mirror mode `dual` juga dapat dikenali tanpa parameter kueri: mirror tersebut memuat bidang `parent`
yang mengarah ke ID utama.

Klien yang menampilkan pemilih model sebaiknya meminta `?prefix=alias` — inilah yang dilakukan oleh
[ekstensi OmniCopilot VS Code](../guides/VSCODE-COPILOT.md).

### Filter penemuan (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` menerima filter penemuan opsional. Tanpa filter apa pun, respons
tidak berubah. Filter tersebut mempersempit katalog yang sudah dapat dilihat pemanggil (izin kunci API diterapkan terlebih dahulu),
dan dijalankan sebelum paginasi bergaya OpenAI `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # setiap kapabilitas yang dicantumkan harus bernilai true
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` katalog; baris tanpa nilai tersebut dianggap `chat`
GET /v1/models?q=sonnet&limit=10                           # pencocokan tanpa membedakan huruf besar/kecil pada ID atau nama
```

| Parameter     | Nilai                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | bilangan bulat nonnegatif, dibandingkan dengan `context_length`                                     |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 karakter                                                                                      |

Nilai yang tidak dikenal, atau `min_context` yang bukan bilangan bulat nonnegatif (misalnya `1.5`),
akan mengembalikan HTTP `400` dan pesan yang mencantumkan nilai-nilai yang valid. Implementasi:
`src/app/api/v1/models/catalogFilters.ts`.

### Daftar pendek model (`POST /v1/models/query`)

`POST /v1/models/query` mengembalikan daftar pendek yang deterministik dari katalog yang sama, dengan autentikasi
dan visibilitas per kunci yang sama seperti `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Setiap bidang bersifat opsional. `capabilities` dan `exclude` menerima array atau string yang dipisahkan koma;
`max_output` dibandingkan dengan `max_output_tokens`. Hasil diurutkan berdasarkan `owned_by`, lalu `id`.
Nilai default `limit` adalah `20`, dan nilai di atas `100` dibatasi menjadi `100`. JSON yang tidak valid, bidang yang tidak dikenal,
atau nilai yang tidak valid akan mengembalikan HTTP `400`.

### Model chat yang disembunyikan secara individual

Model yang ditandai **Tersembunyi** pada halaman penyedianya dikecualikan dari katalog dan ditolak
dengan HTTP `404` / `model_not_found` ketika diminta secara eksplisit. Pemeriksaan menggunakan
penyedia dan model yang telah diresolusi, termasuk alias penyedia, prefiks node penyedia yang kompatibel, dan
default koneksi. Kombinasi akan melewati target tersembunyi dan dapat menggunakan model seinduk yang terlihat; ketika tidak ada
target yang dapat dieksekusi, kombinasi tersebut mengembalikan kode kesalahan yang sama. Pembatalan penyembunyian berlaku pada
permintaan berikutnya. Penggantian visibilitas khusus gambar tidak menyembunyikan model chat dengan ID yang sama.

Pengaturan model individual ini terpisah dari
[daftar izin/tolak eksposur model](../routing/MODEL_EXPOSURE_LIST.md), yang memfilter penayangan katalog
dan kandidat perutean otomatis, sambil tetap mempertahankan pengiriman eksplisit. Izin model berdasarkan kunci API
tetap berlaku secara independen. Mode prefiks katalog default tetap `dual`.

### Varian model tanpa thinking

Untuk model Claude yang mendukung thinking, `/v1/models` juga menampilkan varian **tanpa thinking** dengan id yang diawali `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Memilih id ini (misalnya dalam konfigurasi Claude Code yang selalu menyertakan blok `thinking`) akan diresolusi kembali ke `<provider>/<model>` yang sebenarnya dengan penalaran dinonaktifkan — `thinking:{type:"disabled"}` pada jalur `/v1/messages`, atau bidang `reasoning`/`reasoning_effort` dihapus pada jalur `/v1/chat/completions`. Varian ini hanya dicantumkan untuk model keluarga Claude yang mendukung thinking **dan** mematuhi `disabled` (sehingga, misalnya, model khusus adaptif yang menolak `disabled` tidak disertakan). Operator dapat mengaktifkan atau menonaktifkan varian secara paksa untuk setiap model melalui `ModelSpec.noThinkingAlias`.

## Pembuatan audio ElevenLabs

Konfigurasikan koneksi penyedia `elevenlabs` di OmniRoute dengan kunci API ElevenLabs Anda.
Klien melakukan autentikasi dengan kunci **OmniRoute** mereka (`Authorization: Bearer $OMNIROUTE_API_KEY`);
gateway menyediakan kunci penyedia yang tersimpan sebagai `xi-api-key`. Jangan pernah mengirim kunci ElevenLabs
sebagai token bearer gateway.

| Metode | Jalur                       | Respons                                      | Kategori endpoint kunci API |
| ------ | --------------------------- | -------------------------------------------- | --------------------------- |
| POST   | `/v1/sound-generation`      | Byte audio native                            | `elevenlabs`                |
| POST   | `/v1/music`                 | Byte audio native                            | `music`                     |
| POST   | `/v1/music/stream`          | Byte audio streaming                         | `music`                     |
| POST   | `/v1/music/detailed`        | Audio multipart native dan rencana komposisi | `music`                     |
| POST   | `/v1/music/detailed/stream` | Metadata SSE native dan potongan audio       | `music`                     |
| POST   | `/v1/music/plan`            | Rencana komposisi JSON                       | `music`                     |

Endpoint ini melengkapi rute `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}`, dan `/v1/speech-to-text` yang sudah ada. Kolom JSON native
dan parameter kueri seperti `output_format` dan `enable_logging` tetap dipertahankan.
Respons `/v1/music/detailed` mempertahankan batas multipart-nya; uraikan sebagai multipart.
`/v1/music/detailed/stream` mengembalikan `text/event-stream` dengan metadata komposisi dan
potongan audio base64 dalam peristiwa SSE. Keenam rute mendukung preflight CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Efek suara singkat. Durasi: 0,5 hingga 30 detik.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Durasi musik dinyatakan dalam milidetik: 3000 hingga 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Gunakan `/v1/music/stream` dengan isi JSON yang sama untuk pengiriman audio secara bertahap. Komposisi
menerima tepat salah satu dari `prompt` atau `composition_plan`; `/v1/music/plan` mewajibkan `prompt`
dan secara opsional menerima `source_composition_plan`. Skema native mempertahankan kolom penyedia
tambahan agar versi rencana komposisi dan opsi penyempurnaan diteruskan ke ElevenLabs.

Endpoint terpadu `/v1/music/generations` juga menerima `elevenlabs/music_v1`,
`elevenlabs/music_v2`, dan `elevenlabs/music_v2_5`. Dengan koneksi ElevenLabs yang aktif,
model-model ini ditampilkan oleh katalog musik. Endpoint ini mengembalikan
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Kolom `duration` dinyatakan dalam
detik dan dipetakan ke `music_length_ms`; `music_length_ms` yang ditentukan secara eksplisit akan diprioritaskan.
`instrumental` dipetakan ke `force_instrumental`, dengan kolom native diprioritaskan.
Gunakan endpoint streaming native untuk streaming dan endpoint komposisi native
untuk permintaan yang hanya didasarkan pada rencana komposisi.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Pembatasan endpoint, model, anggaran, dan koneksi diterapkan sebelum pemanggilan upstream. Rute
native mengembalikan kode status dan isi kesalahan upstream tanpa perubahan, termasuk `402` untuk pembatasan
paket dan `429` untuk batas kuota. Header `character-cost`, `song-id`, `request-id`, dan `retry-after`
dipertahankan jika tersedia. Saldo kredit gratis tidak menjamin akses ke setiap
model musik, format output, atau fitur API: ElevenLabs menentukan hak akses untuk setiap permintaan.
Endpoint terpadu mempertahankan kode status kesalahan dalam amplop kesalahan OmniRoute yang dinormalisasi.

Kontrak upstream: [efek suara](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[komposisi musik](https://elevenlabs.io/docs/api-reference/music/compose), dan
[detail musik streaming](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> **Node penyedia rerank:** `POST /v1/rerank` juga merutekan permintaan ke node penyedia yang kompatibel dengan OpenAI
> (oMLX, vLLM, Infinity, TEI di belakang gateway, …) yang dialamatkan sebagai `<node-prefix>/<model>`. Node
> loopback (`localhost`, `127.0.0.1`, `172.16.0.0/12`) selalu memenuhi syarat, begitu pula nama host yang
> dicantumkan operator dalam `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (misalnya nama layanan Docker/Compose
> seperti `http://reranker:8080/v1`; node ini dipanggil secara langsung, tidak pernah melalui `HTTP(S)_PROXY` atau
> proksi tersemat milik suatu koneksi). Node pada host lain mana pun
> — perangkat LAN atau peer Tailscale — hanya memenuhi syarat ketika operator mengaktifkan
> feature flag `RERANK_REMOTE_PROVIDER_NODES` **dan** URL dasar node tersebut lolos kebijakan URL keluar
> penyedia (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Langkah rerank mesin memori memanggil rute ini melalui
> loopback, sehingga aturan yang sama berlaku untuk `rerankProviderModel` dalam pengaturan Memori.
>
> **Bentuk server lokal:** node dipanggil pada `<base>/v1/rerank` dan, jika menerima 404, pada `<base>/rerank`
> (Infinity, TEI). Isi upstream menyertakan ejaan Cohere/OpenAI (`documents`,
> `return_documents`) dan ejaan TEI (`texts`, `return_text`), sedangkan respons upstream
> dinormalisasi ke envelope Cohere: array polos TEI `[{index, score, text}]`, `{results: [{index, score}]}`
> dari gateway tipis, dan `{data: [...]}` bergaya Voyage semuanya dikembalikan kepada klien sebagai
> `{results: [{index, relevance_score, document?}]}`, diurutkan berdasarkan skor dan dibatasi hingga `top_n`.

> **Penemuan node penyedia:** model pada node penyedia yang kompatibel dengan OpenAI muncul dalam `GET /v1/models`
> di bawah prefiks node. Baris yang tidak memiliki metadata endpoint (umumnya untuk daftar `/v1/models` lokal)
> mewarisi `apiType` milik node, sehingga model milik node `embeddings` memiliki `type: "embedding"` dan model
> milik node `rerank` memiliki `type: "rerank"`, alih-alih menggunakan chat sebagai nilai default; nilai
> `supportedEndpoints` eksplisit pada baris yang disinkronkan atau ditambahkan secara manual tetap diprioritaskan.

Endpoint file yang kompatibel dengan OpenAI untuk input/output batch dan unggahan berdasarkan tujuan file.

| Metode | Jalur                    | Deskripsi                                                                                                        |
| ------ | ------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/files`              | Unggah file (multipart: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — maksimum 512 MiB |
| GET    | `/v1/files`              | Cantumkan file untuk kunci API yang terautentikasi                                                               |

### Exa dan Tavily `provider_options`

Exa dan Tavily membaca kolom khusus penyedia dari tas dengan namespace: `provider_options.exa` (atau `provider_options["exa-search"]`) dan `provider_options.tavily` (atau `provider_options["tavily-search"]`). Hanya kunci di bawah ini yang diteruskan. Masing-masing diperiksa berdasarkan skema Zod nya sendiri di `open-sse/handlers/search/providerOptionsPassthrough.ts`, dan kunci dengan tipe yang salah akan dihapus. Kunci lainnya diabaikan, termasuk auth, base URL, `stream` dan `outputSchema`. Tombol datar yang digunakan oleh penyedia lain (`cx`, `depth`, ...) berfungsi seperti sebelumnya.

| Penyedia | Bidang tingkat atas                                                                                                                                                                                                                                                                                                                                                       | Bersarang                                                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Contoh   | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (primitif datar), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                               | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` digabungkan dengan `{ text: true, highlights: true }` default |
| Tavilly  | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                           |

Bidang umum selalu menang: `query`, `max_results`, `filters` (domain), `country` dan topik turunan dari `search_type`. Di Exa, `search_type: "news"` menyimpan `category: "news"`. Tavily juga menerima `search_type: "finance"` (`topic: "finance"`).

Biaya pencarian Firecrawl dicatat per blok yang dimulai dari 10 hasil yang dikembalikan, sebesar $0,002 (2 sks) per blok dan setidaknya satu blok per panggilan ( [Penagihan Firecrawl](https://docs.firecrawl.dev/billing) ): 11 hasil berharga $0,004.

`time_range` generik sekarang menjangkau kedua penyedia: Exa mendapat `startPublishedDate` ( cap waktu ISO ) dan Tavily mendapat `start_date` (`YYYY-MM-DD`). Tanggal eksplisit di `provider_options` menggantikan tanggal yang dipetakan.

Hasil ujian menyimpan `id`, `highlight_scores`, `summary`, `subpages`, `entities` dan `extras` di `provider_raw`. Hasil Tavily tetap `images` dan `favicon`.

Biaya pencarian linkup dicatat sebesar $0,005 untuk `depth` `fast` dan `standard` dan $0,05 untuk `deep` ( [Harga linkup](https://docs.linkup.so/pages/documentation/development/pricing) ), baik `depth` berasal dari `provider_options` atau pengaturan koneksi.

Exa `type: "lite"` (Exa 3.0) menerima kumpulan bidang yang lebih kecil dan menolak seluruh permintaan ketika bidang lainnya disetel. Untuk ringan, `additionalQueries`, `systemPrompt` dan setiap kunci `contents` kecuali `text` dan `highlights` dihilangkan sebelum panggilan. `subpages`, `subpageTarget`, `highlights.numSentences` dan `highlights.highlightsPerUrl` yang tidak digunakan lagi tidak lagi diteruskan.

Akuntansi biaya adalah registri datar `costPerQuery`, kecuali Exa, yang mengikuti harga Exa sendiri: $0,007 per panggilan untuk `auto` (dan warisan `fast`) atau $0,004 untuk `lite` (dan warisan `instant`), mencakup 10 hasil; $0,001 untuk setiap hasil selanjutnya; dan $0,001 per hasil yang dikembalikan ketika `contents.summary` disetel. Tavily dicatat pada 1 kredit ($0,008) untuk `search_depth` `basic`, `fast` dan `ultra-fast`, dan 2 kredit ($0,016) untuk `advanced` ( [Tavily API credits](https://docs.tavily.com/documentation/api-credits) ). Panggilan dengan `auto_parameters: true` yang ditingkatkan Tavily ke tingkat lanjut masih dicatat sebesar 1 kredit.

## API Web Fetch

Ekstrak konten dari URL melalui penyedia web-fetch yang dikonfigurasi (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, menggunakan kunci API yang sama dengan Parallel Search) hanya
mengembalikan Markdown — `format` lainnya menghasilkan `400` — dan membatasi konten hingga 100.000 karakter. Ketika
halaman target itu sendiri tidak dapat diekstrak, layanan upstream melaporkannya di dalam HTTP 200;
OmniRoute menampilkannya sebagai `422` dengan pesan tetap.

| Metode | Jalur           | Deskripsi                                                        |
| ------ | --------------- | ---------------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Mengambil/mengikis URL — body divalidasi oleh `v1WebFetchSchema` |

**Autentikasi:** Kunci API Bearer (`extractApiKey` + `isValidApiKey`). Kebijakan diberlakukan melalui `enforceApiKeyPolicy`.

**Fallback sadar kuota (#8297):** ketika `provider` eksplisit tidak diberikan, pool
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) ditelusuri dalam urutan
prioritas tetap (isi-yang-pertama) — penyedia yang dikonfigurasi tetapi terkena pembatasan laju akan dilewati
alih-alih langsung menghentikan permintaan, dan kegagalan upstream yang dapat dicoba ulang/terkait kuota
(HTTP 429 selalu; 402/403 untuk tingkat gratis bergaya kuota Firecrawl/Tavily/TinyFish —
bukan untuk Jina Reader, dan tidak pernah untuk permintaan buruk 400 biasa) akan beralih ke
penyedia berkredensial berikutnya yang belum dicoba pada saat permintaan berlangsung. Ketika setiap penyedia dalam
pool telah habis, endpoint mengembalikan satu `429` (dengan header `Retry-After`)
alih-alih `400` generik sebelumnya. Ketika `provider` eksplisit
diminta, **tidak ada** fallback diam-diam — penyedia eksplisit yang terkena pembatasan laju atau gagal
akan menampilkan error-nya sendiri (`429` jika terkena pembatasan laju, atau status
upstream jika tidak).

## Streaming WebSocket

```bash
GET /v1/ws?handshake=1
```

Memvalidasi handshake upgrade WebSocket dan mengembalikan contoh pesan protokol wire (`request`, `cancel`). Frame WS aktual ditangani oleh server WS bawaan di luar tabel rute Next.js.

### Responses API melalui WebSocket (khusus codex)

```bash
# Host:port yang sama dengan API HTTP (default 20128); upgrade koneksi:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (atau: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Frame pertama HARUS berupa response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proxy Responses-API-over-WebSocket dihubungkan **secara eksklusif ke `codex`** (backend ChatGPT).
Proxy ini mendengarkan pada port yang sama dengan API/dasbor di jalur `/v1/responses`,
`/responses`, dan `/api/v1/responses`. Pada frame `response.create` pertama, proxy
melakukan autentikasi + persiapan melalui bridge internal `codex-responses-ws`, memilih
koneksi OAuth codex, dan membuat tunnel ke `wss://chatgpt.com/backend-api/codex/responses`
melalui transport `wreq-js`. **Model non-codex ditolak** (`codex_ws_provider_required`).
Untuk routing berbagi kuota, gunakan `model: "qtSd/<group>/codex/<model>"`. Diimplementasikan dalam
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Autentikasi:** Kunci API Bearer selama handshake. Server HTTP bawaan (`server-ws.mjs`)
harus menjadi entrypoint aktif (dan memang demikian secara default ketika `app/server-ws.mjs` tersedia).

#### ID model: gunakan ID ChatGPT polos (tanpa prefiks `codex/`)

**Codex CLI** OpenAI memvalidasi nama model di sisi klien ketika
`supports_websockets = true` dan **menolak ID berprefiks penyedia** seperti
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Kirim ID **polos** (misalnya `gpt-5.5`). Bridge OmniRoute
khusus untuk codex, sehingga bridge tersebut me-resolve ulang ID polos sebagai model codex
(`resolveCodexWsModelInfo`) sebelum membuat tunnel ke upstream — meskipun
`gpt-5.5` polos seharusnya dirutekan ke penyedia lain melalui HTTP.

#### Mengonfigurasi OpenAI Codex CLI

Arahkan Codex CLI ke OmniRoute dengan menambahkan penyedia khusus yang mendukung WebSocket
ke `~/.codex/config.toml` (gunakan `CODEX_HOME` terpisah agar tidak mengubah
konfigurasi yang sudah ada):

```toml
model = "gpt-5.5"                 # ID polos — BUKAN "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"

wire_api = "responses"                    # satu-satunya nilai yang didukung sejak Feb 2026

env_key = "OMNIROUTE_API_KEY"             # menyimpan kunci API OmniRoute (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # kunci API OmniRoute (kunci apa pun jika REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI meng-upgrade `base_url + /responses` menjadi WebSocket dan OmniRoute membuat tunnel
ke koneksi OAuth codex yang dipilih. Telah divalidasi secara end-to-end terhadap server
lokal: ChatGPT mengembalikan `codex.rate_limits` + `response.created` dan melakukan streaming
penyelesaian.

## Penggunaan mandiri (`/api/usage/om-usage`)

Kunci API apa pun dapat membaca penggunaan dan kuotanya **sendiri** — tanpa autentikasi manajemen. Ini adalah endpoint yang digunakan
klien (CLI, panel OmniCopilot) untuk menunjukkan pengeluaran kepada pemegang kunci.

```bash
# Format teks (kontrak historis — teks biasa untuk terminal)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Format terstruktur — yang digunakan oleh UI
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Kunci harus mengaktifkan **`allowUsageCommand`** (nonaktif secara default — pengelola kunci API pada dasbor
mengaktifkan atau menonaktifkannya untuk setiap kunci). Tanpa opsi ini, endpoint memberikan respons `403`.

`?format=json` mengembalikan struktur terdiskriminasi agar pemanggil tidak pernah membaca kolom data dari
respons penolakan. Saat berhasil:

```jsonc
{
  "allowed": true,
  // hanya tersedia ketika kunci memilih untuk menggunakan batas penggunaan per kunci (USD harian/mingguan):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // snapshot kuota penyedia yang dipilih, atau null jika belum ada yang disimpan dalam cache:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // snapshot setiap koneksi, agar UI dapat menampilkan beberapa penyedia secara berdampingan:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Saat ditolak (`401` untuk kunci yang salah / `403` karena tidak diizinkan), rute yang sama mengembalikan
`{ "allowed": false, "error": { "message": "…" } }` — `personal`/`provider` yang tersedia tetapi kosong
(kunci diizinkan, tetapi belum ada informasi yang diperoleh) merupakan keadaan yang berbeda dari penolakan, dan hanya format JSON
yang membedakan keduanya.

**Autentikasi:** kunci API Bearer milik pemanggil sendiri, yang divalidasi dengan `isValidApiKey` — ini _bukan_
permukaan manajemen (`/api/keys/…`), yang tetap dilindungi oleh `requireManagementAuth`.

### Persentase Kuota Mentah vs. yang Disesuaikan dengan Ambang Batas

Saat menggunakan `/api/usage/om-usage`, pemanggil perlu memperhatikan perbedaan antara
persentase yang ditampilkan oleh **output teks biasa** dan **output JSON** terstruktur:

| Aspek                 | Format teks biasa (`/api/usage/om-usage` / `@@om-usage`)                                                       | Format JSON (`?format=json`)                                             |
| :-------------------- | :------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------- |
| **Kolom output**      | `NN% left` (misalnya, `20% left`)                                                                              | `provider.quotas` / `providers[].quotas`                                 |
| **Pengukuran**        | **Jatah yang dapat digunakan setelah penyesuaian ambang batas**: kapasitas tersisa di atas ambang batas cutoff | **Kuota upstream mentah**: pengukuran penyedia yang belum disesuaikan    |
| **Penskalaan cutoff** | Diskalakan melalui `effectiveRemainingPercent()` agar cadangan yang dilindungi terbaca sebagai `0% left`       | Tidak ada (nilai snapshot mentah sebagaimana dilaporkan oleh penyedia)   |
| **Data ambang batas** | Diperhitungkan dalam persentase yang ditampilkan                                                               | Disimpan dalam `quotaWindowThresholds` per koneksi (atau default server) |
| **Pengguna utama**    | CLI interaktif, prompt terminal, operator manusia                                                              | Integrasi terprogram, dasbor, analitik, pelacak penagihan                |

#### Rumus Penyesuaian Ambang Batas

OmniRoute mendukung cutoff kuota proaktif untuk mencegah habisnya kuota upstream (dikonfigurasi melalui
`quotaWindowThresholds` koneksi, default penyedia, atau pengaturan ketahanan global). Saat ambang batas cutoff
(misalnya, `cutoff = 25%`) aktif pada suatu jendela kuota, perender teks menghitung jatah tersisa sebagai berikut:

- Jika `remaining <= cutoff`: mengembalikan `0%`.
- Jika `remaining > cutoff`: mengembalikan `((remaining - cutoff) / (100 - cutoff)) * 100`.

Output teks yang diformat membulatkan hasil ini ke bilangan bulat terdekat (`Math.round(...)`).

#### Contoh Ilustratif

Pertimbangkan jendela penyedia dengan **penggunaan mentah sebesar 60%** (sehingga **kuota mentah yang tersisa sebesar 40%**) dan ambang batas
**cutoff kuota tersisa sebesar 25%** yang telah dikonfigurasi:

| Representasi                     | Perhitungan                                        | Tersisa |             Penggunaan Tersirat             |
| :------------------------------- | :------------------------------------------------- | :-----: | :-----------------------------------------: |
| **JSON mentah (`?format=json`)** | Snapshot upstream (`quotas[window]`)               | **40%** |                   **60%**                   |
| **Format teks (`NN% left`)**     | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (jika menghitung `100 - remaining`) |

- **Mengapa teks menampilkan 20% tersisa:** Dari 40% kuota fisik yang tersisa pada akun, 25% dicadangkan oleh
  kebijakan cutoff. Pemanggil hanya memiliki sisa ruang sebesar 15% dari total 75% yang dapat digunakan sebelum router berhenti
  merutekan ke koneksi ini. Penskalaan memastikan koneksi menandakan kuota telah habis (`0% left`) tepat ketika
  perutean akan dihentikan.
- **Mengapa JSON mempertahankan nilai mentah:** Payload JSON mengembalikan snapshot penyedia yang sama persis (`UsageSnapshot`)
  sehingga alat eksternal dapat mengakses pemanfaatan upstream yang sebenarnya dan
  `quotaWindowThresholds` tingkat koneksi tanpa penskalaan lossy di sisi server.

#### Panduan Migrasi Konsumen

Jika integrasi eksternal (seperti plugin editor atau ekstensi agen) sebelumnya mengambil teks dari
endpoint (`NN% left`) dan menghitung persentase yang digunakan sebagai `100 - NN`, migrasi ke `?format=json` berarti:

- Membaca nilai JSON mentah akan mencerminkan **konsumsi upstream yang sebenarnya** (60% digunakan dalam contoh di atas).
- Jika integrasi ingin mempertahankan semantik alokasi yang dapat digunakan dari endpoint teks, integrasi tersebut dapat mengevaluasi
  rumus sisa efektif di sisi klien menggunakan `quotaWindowThresholds` untuk penggantian pada tingkat koneksi.

## Cache Semantik

```bash
# Dapatkan statistik cache
GET /api/cache/stats

# Hapus semua cache
DELETE /api/cache/stats
```

Contoh respons:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### Dampak latensi

HIT pada cache semantik menyajikan respons dari cache **tanpa panggilan
upstream**, sehingga `X-OmniRoute-Response-Latency` yang dilaporkan mendekati nol
(terlepas dari latensi upstream aslinya). Klien yang sensitif terhadap latensi
(benchmarking, pemantauan p50/p99) harus memeriksa header respons
`X-OmniRoute-Cache-Latency`:

| Nilai         | Arti                                                              |
| ------------- | ----------------------------------------------------------------- |
| `synthetic`   | Respons disajikan dari cache; latensi bukan waktu upstream aktual |
| _(tidak ada)_ | Respons dari panggilan upstream aktual                            |

### Bypass cache per kunci

Kunci API dapat memilih untuk tidak menggunakan pembacaan cache semantik melalui `cacheDefaultMode`:

| Nilai    | Perilaku                                                 |
| -------- | -------------------------------------------------------- |
| `legacy` | Perilaku cache normal (default)                          |
| `bypass` | Lewati pencarian cache sepenuhnya; selalu akses upstream |

Tetapkan saat membuat kunci (`POST /api/keys`) atau memperbaruinya (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### Bypass per permintaan

Permintaan apa pun dapat melewati cache terlepas dari pengaturan kunci:

```
X-OmniRoute-No-Cache: true
```

Untuk model yang disinkronkan/diimpor, `PUT /api/provider-models` menerima `provider`, `modelId`, dan

penyedia yang kompatibel dengan OpenAI menawarkan kontrol edit/hapus yang sama dan menandai model dengan dukungan visi eksplisit.

Node Chat Completions Kustom menyesuaikan penolakan eksplisit terhadap penalaran untuk backend upstream. Pengujian
koneksi yang berhasil secara otomatis memilih kontrol templat chat untuk setiap ID model persis
yang entri `/models`-nya membuktikan nilai `owned_by` yang dikenali: `vllm`, `sglang`, atau `llamacpp`.
Wrapper transparan yang kompatibel dengan OpenAI dapat mempertahankan entri model asli di dalam objek
`openai` bertingkat; deteksi mengikuti hingga tiga lapisan semacam itu. Model dengan kepemilikan yang tidak ada,
tidak dikenal, atau saling bertentangan tetap menggunakan perilaku OpenAI biasa. Deteksi menggunakan kembali permintaan
katalog yang sudah ada, tidak menghasilkan token penyelesaian, dan dibatalkan saat endpoint koneksi berubah.

Untuk menetapkan perilaku bagi backend yang tidak mengekspos metadata tersebut, gunakan API pembaruan
parsial penyedia yang sudah ada:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Kirim isi tersebut dengan `PUT /api/providers/<connection-id>`. Pada koneksi tersebut, upaya
penalaran eksplisit sebesar `none` dikirim sebagai `chat_template_kwargs.thinking=false` dan
`chat_template_kwargs.enable_thinking=false`. Nilai templat native eksplisit tetap menjadi acuan utama,
kecuali aturan penalaran sisi server memaksakan suatu tingkat upaya. Pengaturan ini hanya berlaku saat koneksi
kustom yang kompatibel dengan OpenAI mengirimkan isi Chat Completions; permintaan Responses dan penyedia
biasa mempertahankan bentuk permintaan native-nya. Atur `reasoningControl` menjadi `openai` untuk memaksakan
penerusan `reasoning_effort` OpenAI biasa, atau hilangkan/setel menjadi `null` untuk menggunakan deteksi otomatis.

Permintaan pengklasifikasi mode otomatis Claude Code secara default menonaktifkan pemikiran native jika
tidak memuat kontrol penalaran eksplisit. Deteksi menggunakan penanda sistem pengklasifikasi dalam permintaan
berformat Claude, bukan nama model atau batas penyelesaian. Kontrol isi eksplisit, header upaya/pemikiran yang
didukung, aturan perutean, dan upaya model yang telah ditetapkan tetap mempertahankan prioritasnya. Kedua tahap
pengklasifikasi mempertahankan prompt, batas penyelesaian, urutan penghentian, dan keputusan izin upstream
aktualnya; tahap kedua tetap dapat menghasilkan penalaran terlihat yang diminta sebagai teks biasa.

### Versi dan Kanal Rilis

```bash
GET /api/system/version
```

Rute pengelolaan khusus loopback (autentikasi admin). Mengembalikan versi yang sedang berjalan, versi terbaru
yang dipublikasikan, dan status pembaruan otomatis. `releaseChannel` dan `channels` adalah kolom tambahan
(rail 3.8.54); `channel` mempertahankan maknanya — mode deployment yang digunakan pembaru dasbor
(`npm`, `source`, atau `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — kanal npm dari build yang sedang berjalan: `nightly` untuk versi `-nightly.*`,
  `next` untuk prarilis lainnya (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` untuk versi stabil dengan
  versi mayor yang lebih lama daripada `channels.latest`, dan selain itu `latest`. Aturannya sama dengan
  `scripts/release/dist-tag.mjs`, yang memilih dist-tag npm pada saat publikasi.
- `channels` — versi terdepan yang dipublikasikan untuk setiap dist-tag, dari `npm view omniroute dist-tags` (fallback
  HTTP registry), di-cache dengan TTL 10 menit yang sama seperti `latest`. `latest` selalu tersedia
  (fallback ke kolom `latest`, lalu `"unavailable"`); `next`, `nightly`, dan `lts` hanya muncul
  jika dist-tag tersebut ada. Permintaan `Cache-Control: no-cache` menyegarkan kedua pencarian.

Model kanal (`latest` = v3 hingga GA 4.0, `next` = rc, `nightly` = build `develop`,
`lts` = patch v3 setelah GA 4.0) dijelaskan dalam `docs/ops/RELEASE_STRATEGY.md`.

# Alias percakapan bergaya OpenAI
POST /api/v1/vscode/{token}/chat/completions

## Batas Token

Anggaran **token** per kunci API (berbeda dari Anggaran berbasis USD di atas). Diberlakukan secara langsung pada jalur permintaan: ketika penggunaan jendela saat ini dari suatu kunci mencapai batasnya, permintaan ditolak dengan `429 Too Many Requests`. Batas dapat dicakup ke `model` tertentu, `provider`, atau diterapkan secara `global` di seluruh kunci; ketika beberapa batas cocok dengan suatu permintaan, batas yang paling ketat akan berlaku.

```bash
# Cantumkan batas token suatu kunci (termasuk penggunaan jendela secara langsung)
GET /api/usage/token-limits?apiKeyId=key-123

# Buat atau perbarui batas token
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Hapus batas token berdasarkan id
DELETE /api/usage/token-limits?id=tl-abc
```

> **Catatan skema** (`setTokenLimitSchema`): `apiKeyId` dan `scopeType` (`model` | `provider` | `global`) wajib diisi. `scopeValue` wajib diisi kecuali jika `scopeType` adalah `global` (misalnya id model untuk cakupan `model`, id penyedia untuk cakupan `provider`). `tokenLimit` harus berupa bilangan bulat positif (dikonversi dari string). Opsional: `id` (hilangkan untuk membuat, sertakan untuk memperbarui), `resetInterval` (`daily` | `weekly` | `monthly`, nilai default `monthly`), `resetTime` (`HH:MM`), `enabled` (nilai default `true`). Respons `GET` memperkaya setiap batas dengan `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, dan `nextResetAt`. Ini adalah endpoint kelas manajemen (autentikasi diberlakukan secara terpusat oleh pipeline otorisasi).

## Pemrosesan Permintaan

1. Klien mengirim permintaan ke `/v1/*`
2. Penangan rute memanggil `handleChat`, `handleEmbedding`, `handleAudioTranscription`, atau `handleImageGeneration`
3. Model diresolusikan (penyedia/model langsung atau alias/kombo)
4. Kredensial dipilih dari DB lokal dengan pemfilteran ketersediaan akun
5. Untuk percakapan: `handleChatCore` memeriksa cache semantik/tanda tangan dan meresolusikan pengaturan kompresi kombo
6. Kompresi proaktif dijalankan sebelum translasi penyedia saat diaktifkan (`lite`, Caveman, RTK, atau bertumpuk)
7. Eksekutor penyedia mengirim permintaan upstream
8. Respons diterjemahkan kembali ke format klien (percakapan) atau dikembalikan apa adanya (embedding/gambar/audio)
9. Penggunaan, analitik kompresi, dan log permintaan dicatat
10. Fallback diterapkan saat terjadi kesalahan sesuai dengan aturan kombo

Referensi arsitektur lengkap: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Ketahanan (diperluas)

OmniRoute menyediakan tiga mekanisme kegagalan sementara yang independen; endpoint manajemen di bawah ini memungkinkan operator membaca dan menimpanya:

| Cakupan          | Penyimpanan status                       | Baca                                      | Atur ulang / hapus                                            |
| ---------------- | ---------------------------------------- | ----------------------------------------- | ------------------------------------------------------------- |
| Pemutus penyedia | `domain_circuit_breakers` + dalam memori | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                  |
| Jeda koneksi     | `rateLimitedUntil` pada koneksi penyedia | `/api/rate-limits`, `/api/providers/[id]` | (diaktifkan kembali secara malas; hapus melalui PUT penyedia) |
| Penguncian model | Registri ketersediaan model dalam memori | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                      |

`PATCH /api/resilience` menerima penimpaan pemutus penyedia di bawah `providerBreaker.oauth` dan `providerBreaker.apikey`. Setiap profil mendukung `degradationThreshold`, `failureThreshold`, dan `resetTimeoutMs`; bidang yang sama tersedia di Dasbor → Pengaturan → Ketahanan.

```bash
# Hapus satu penguncian model
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Hapus semua penguncian
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Referensi konseptual lengkap dan nilai default pemutus: lihat [`CLAUDE.md`](../../CLAUDE.md) → "Status Runtime Ketahanan" dan [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Antrean Batas Laju & Jaring Pengaman Pengaktifan Otomatis

- **Jalur penulisan yang didukung**: `POST /api/rate-limits` dengan isi `{"connectionId": "<id>", "enabled": true|false}` adalah endpoint manajemen yang didukung untuk mengaktifkan atau menonaktifkan perlindungan batas laju bagi suatu koneksi. `PUT /api/providers/[id]` sengaja tidak mengubah atau membalik `rateLimitProtection` (#11278).
- **Semantik `enabled: false`**: Menetapkan `enabled: false` menghapus perlindungan eksplisit untuk koneksi tersebut, tetapi **tidak** mengecualikan koneksi kunci API yang aktif dari jaring pengaman pengaktifan otomatis global (`autoEnableApiKeyProviders = true`). Dalam `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), `false` dan `undefined` setara; koneksi kunci API aktif tanpa perlindungan eksplisit tetap dilindungi oleh jaring pengaman pengaktifan otomatis.
- **Penonaktifan global**: Untuk menjalankan koneksi kunci API tanpa antrean batas laju, nonaktifkan jaring pengaman secara global melalui `RATE_LIMIT_AUTO_ENABLE=false` (env) atau `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Pengaturan → Ketahanan / `PATCH /api/resilience`).

| POST | `/api/mcp/sse` | Mengirim frame JSON-RPC melalui transport SSE |

## Server A2A

OmniRoute menyediakan endpoint A2A (Agent-to-Agent) JSON-RPC 2.0 serta pembungkus REST untuk keperluan inspeksi/dasbor.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # opsional kecuali OMNIROUTE_API_KEY ditetapkan
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Metode yang didukung (semuanya bergantung pada `settings.a2aEnabled`):

| Metode           | Deskripsi                                                                  |
| ---------------- | -------------------------------------------------------------------------- |
| `message/send`   | Eksekusi keterampilan sinkron; mengembalikan `{task, artifacts, metadata}` |
| `message/stream` | Eksekusi SSE streaming untuk kumpulan keterampilan yang sama               |
| `tasks/get`      | Mengambil tugas berdasarkan `taskId`                                       |
| `tasks/cancel`   | Membatalkan tugas berdasarkan `taskId`                                     |

Keterampilan bawaan: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Kartu Agen

```bash
GET /.well-known/agent.json
```

Mengembalikan kartu agen A2A publik (nama, deskripsi, kapabilitas, katalog keterampilan, skema autentikasi) — di-cache secara publik selama 1 jam. Tidak memerlukan autentikasi.

### Pembantu REST

| Metode | Path                         | Deskripsi                                                                                                               |
| ------ | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | Status aktif A2A + statistik tugas + ringkasan kartu agen yang di-cache                                                 |
| GET    | `/api/a2a/tasks`             | Mencantumkan tugas — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Tidak diimplementasikan sebagai pembantu REST — buat melalui JSON-RPC `message/send`)                                  |
| GET    | `/api/a2a/tasks/[id]`        | Mengambil satu tugas                                                                                                    |
| POST   | `/api/a2a/tasks/[id]/cancel` | Membatalkan tugas                                                                                                       |

**Autentikasi:** pembantu REST berjalan tanpa autentikasi manajemen (dapat dibaca oleh dasbor); rute JSON-RPC `/a2a` menggunakan Bearer `OMNIROUTE_API_KEY` jika dikonfigurasi.

## Autentikasi

Lihat [Autentikasi Manajemen](../guides/MANAGEMENT-AUTH.md) untuk empat
kelompok kredensial (sesi dasbor, token CLI lokal, Token Akses `oma_live_…`,
kunci API dengan cakupan manajemen) dan perbedaannya dari kunci inferensi.

- Rute dasbor (`/dashboard/*`) menggunakan cookie `auth_token`
- Login menggunakan hash kata sandi yang tersimpan; dengan fallback ke `INITIAL_PASSWORD`
- `requireLogin` dapat diaktifkan atau dinonaktifkan melalui `/api/settings/require-login`
- Rute `/v1/*` secara opsional memerlukan kunci API Bearer ketika `REQUIRE_API_KEY=true`
- "token manajemen" / "kunci API dengan cakupan manajemen" dalam referensi ini berarti salah satu kelompok dalam panduan tersebut — bukan jenis rahasia tambahan yang tidak didefinisikan

> **Perubahan yang merusak kompatibilitas (v3.8.0)** — `/api/v1/agents/tasks/*` dan endpoint manajemen cooldown kini memerlukan **autentikasi manajemen** (cookie `auth_token` dasbor atau kunci API dengan cakupan manajemen). Klien yang sebelumnya memanggil rute ini tanpa autentikasi akan menerima `401 Unauthorized`. Lihat commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
