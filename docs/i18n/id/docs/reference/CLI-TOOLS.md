## Cara Kerjanya

```
CLI Code's / CLI Agents (alur konsumsi):
Claude / Codex / OpenCode / Cline / KiloCode / Continue / Hermes Agent / Goose / ...
           │
           ▼  (semuanya diarahkan ke OmniRoute)
    http://YOUR_SERVER:20128/v1
           │
           ▼  (OmniRoute merutekan ke penyedia yang tepat)
    Anthropic / OpenAI / Gemini / DeepSeek / Groq / Mistral / ...

ACP Agents (alur pemunculan terbalik):
    Permintaan klien → OmniRoute → menjalankan CLI melalui stdio/ACP → respons
```

**Manfaat:**

- Satu kunci API untuk mengelola semua alat
- Pelacakan biaya untuk semua CLI di dasbor
- Penggantian model tanpa mengonfigurasi ulang setiap alat
- Berfungsi secara lokal maupun di server jarak jauh (VPS, Docker, Akamai, Cloudflare Tunnel)

## Konfigurasi otomatis dengan `setup-*`

Anda tidak perlu menulis konfigurasi setiap alat dengan tangan. OmniRoute mengirimkan perintah `setup-*` per CLI yang didukung yang membaca** hidup** katalog model dari OmniRoute yang sedang berjalan (lokal atau jarak jauh) dan menulis konfigurasi alat itu sendiri di mesin Anda:

```bash
omniroute setup-codex        omniroute setup-claude       omniroute setup-opencode
omniroute setup-cline        omniroute setup-kilo         omniroute setup-continue
omniroute setup-cursor       omniroute setup-roo          omniroute setup-crush
omniroute setup-goose        omniroute setup-qwen         omniroute setup-aider
omniroute setup-5dive        omniroute setup-zed
omniroute setup-whycodes
```

Masing-masing menerima `--remote <url> --api-key <key>` (mengonfigurasi alat lokal terhadap OmniRoute jarak jauh), `--dry-run` (pratinjau tanpa menulis), dan `--port`. Alat tanpa penemuan otomatis model (Cline, Kilo, Roo, Goose, Aider, Qwen, 5dive, WhyCodes) menggunakan `--model <id>` (dan `--yes` untuk proses non-interaktif). `setup-5dive` adalah satu-satunya resep yang tidak ditulis di bawah `$HOME`: ia mengonfigurasi armada agen 5dive dengan menulis profil autentikasi milik root pada host armada, sehingga dijalankan ulang melalui `sudo` dan tidak memiliki mode jarak jauh sendiri. Untuk meluncurkan CLI dengan env yang tepat dan tidak ada konfigurasi tertulis sama sekali, gunakan peluncur `omniroute run <target>` generik (claude, codex, aider, goose, opencode, qwen, gemini, Whycodes — target dan alias berasal dari `bin/cli/cli-manifest.mjs`); peluncur per alat lama `omniroute launch` (Claude Code) dan `omniroute launch-codex` (Codex) tetap tersedia. Gemini CLI hanya untuk peluncuran: ini adalah target `omniroute run` tetapi tidak memiliki resep `setup-*`/`configure`.

> **Referensi lengkap:** tabel master - apa yang ditulis setiap perintah, setiap flag, lokal vs jarak jauh, dan alat mana yang menginginkan akhiran `/v1` - ada di dalamnya** [Integrasi CLI](../guides/CLI-INTEGRATIONS.md)** .

### Menjalankan ini di dalam wadah

Perintah `setup-*` yang dijalankan di dalam wadah OmniRoute menulis ke rumah wadah itu sendiri, yang tidak dibaca oleh host CLI dan menghilang bersama wadah tersebut. OmniRoute mendeteksinya dan keluar dari `2` dengan instruksi daripada menulis. Dua cara yang didukung ke depan — instal CLI pada host dan `omniroute connect` ke container, atau ikat-pasang direktori konfigurasi dan atur `CLI_CONFIG_HOME` (profil penulisan `host` ). Setiap perintah `setup-*`, ditambah `omniroute configure` dan `omniroute config set`, menerima `--allow-container-write` saat mengonfigurasi CLIs milik container itu sendiri yang sebenarnya Anda maksudkan; `OMNIROUTE_ALLOW_CONTAINER_CONFIG_WRITE=true` melakukan hal yang sama untuk server. Lihat [Panduan Docker → Mengonfigurasi alat host CLI](../guides/DOCKER_GUIDE.md#configuring-host-cli-tools-when-omniroute-runs-in-docker).

Dasbornya** menerapkan titik akhir** (`POST /api/cli-tools/apply`) menerapkan penjagaan yang sama: dalam sebuah wadah, penulisan yang targetnya tidak diikat dari host menjawab**`422`** dengan `containerEphemeralTarget: true`, teks kesalahan aman dan — untuk alat dengan resep host (claude, codex, opencode, cline, kilo, continue) — `hostSetupCommand` (misalnya `omniroute setup-opencode`) untuk dijalankan di host; tidak ada yang tertulis. `dryRun: true` tetap bekerja dalam mode kontainer dan mengembalikan jalur target + pratinjau yang telah disunting tanpa menyentuh disk. Pratinjau konten bukanlah konfigurasi yang mengandung kredensial untuk disalin atau diimpor. Terapkan dengan input tool/base URL/API key/model asli pada host, atau gunakan perintah pengaturan sisi host yang ditunjukkan. Lihat [keamanan konfigurasi CLI](../security/CLI-CONFIGURATION.md) untuk header pratinjau dan kontrak permintaan. Perilaku ini disengaja dan dilindungi regresi oleh `tests/unit/api/cli-tools/apply-container-guard.test.ts` — jangan pernah "memperbaiki" 422 dengan menghapus pelindungnya.

## Sumber Kebenaran

Katalog terpadu berada di `src/shared/constants/cliTools.ts` sebagai `CLI_TOOLS: Record<string, CliCatalogEntry>`.

Setiap entri memiliki bidang berikut (didefinisikan di `src/shared/schemas/cliCatalog.ts`):

| Bidang                                          | Tipe                                                         | Deskripsi                                                   |
| ----------------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------- |
| `category`                                      | `"code" \| "agent"`                                          | Halaman tempat alat ditampilkan                             |
| `vendor`                                        | `string`                                                     | Asal alat ("Anthropic", "OSS (P. Gauthier)")                |
| `acpSpawnable`                                  | `boolean`                                                    | Juga dapat digunakan sebagai Agen ACP (lencana ditampilkan) |
| `baseUrlSupport`                                | `"full" \| "partial" \| "none"`                              | Tingkat dukungan endpoint khusus. `"none"` = backlog MITM   |
| `configType`                                    | `"env" \| "custom" \| "guide" \| "custom-builder" \| "mitm"` | Mekanisme konfigurasi                                       |
| `id`, `name`, `color`, `description`, `docsUrl` | standar                                                      | Bidang tampilan utama                                       |

Entri dengan `baseUrlSupport: "none"` **tidak ditampilkan** di halaman dasbor — entri tersebut terdaftar dalam backlog MITM untuk rencana 11 (lihat `_tasks/features-v3.8.6/refactorpages/_orchestration/_plan11-mitm-backlog.md`).

### Tingkat kapabilitas (terkatalog × dapat dideteksi × dapat dikonfigurasi × dapat dijalankan)

Tidak semua alat yang terkatalog dapat dideteksi, dikonfigurasi, atau dijalankan. Setiap tingkat memiliki satu
sumber deklarasi, dan pengujian penyimpangan menjaga semuanya tetap selaras:

| Tingkat                 | Arti                                                                       | Dideklarasikan di                                                 |
| ----------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **Terkatalog**          | Muncul dalam katalog dasbor (nama, vendor, dokumentasi, tipe konfigurasi)  | `src/shared/constants/cliTools.ts` (`CLI_TOOLS`)                  |
| **Dapat dideteksi**     | Deteksi biner/konfigurasi, pemeriksaan kesehatan, jalur konfigurasi        | `src/shared/services/cliRuntime.ts` (katalog runtime `CLI_TOOLS`) |
| **Dapat dikonfigurasi** | Didukung oleh `omniroute configure <cli>` (resep penyiapan tersedia)       | `bin/cli/cli-manifest.mjs` (`configure: true`)                    |
| **Dapat dijalankan**    | Didukung oleh `omniroute run <target>` (injeksi env/argumen didefinisikan) | `bin/cli/cli-manifest.mjs` (`run: true`)                          |

`bin/cli/cli-manifest.mjs` adalah manifes eksekusi kanonis untuk antarmuka perintah CLI:
`run`, `configure`, dan generator pelengkapan shell semuanya memperoleh daftar
target, resolusi alias (misalnya `kilocode`/`kilo-code`/`kilo_cli` → `kilo`)
serta pengaturan flag `--model` darinya. Pelindung penyimpangan
`tests/unit/cli/cli-manifest-drift.test.ts` memastikan bahwa manifes, katalog runtime,
katalog UI, dan setiap antarmuka konsumen tetap sinkron — target yang ditambahkan ke
satu antarmuka tanpa ditambahkan ke yang lain akan membuat rangkaian pengujian gagal, alih-alih mengalami penyimpangan tanpa terdeteksi.

## 5. API Deteksi Batch

Semua deteksi alat diagregasikan melalui satu endpoint:

**`GET /api/cli-tools/all-statuses`**

- Autentikasi: `requireCliToolsAuth(request)` (sama seperti rute `/api/cli-tools/` lainnya)
- Mengembalikan: `Record<toolId, ToolBatchStatus>` (tipe: `src/shared/types/cliBatchStatus.ts`)
- Strategi: `Promise.all` untuk semua alat, batas waktu 5 detik per alat
- Cache: LRU dalam memori yang diindeks berdasarkan `mtime` berkas konfigurasi. Cache dibatalkan saat mtime berubah. Direset ketika server dimulai ulang.

Struktur respons per alat:

```ts
interface ToolBatchStatus {
  detection: {
    installed: boolean;
    runnable: boolean;
    version?: string;
    command?: string;
    commandPath?: string;
    reason?: string;
  };
  config: {
    status: "configured" | "not_configured" | "not_installed" | "unknown" | "other";
    endpoint?: string | null;
    lastConfiguredAt?: string | null;
  };
  error?: string; // telah disanitasi, tanpa pelacakan tumpukan
}
```

## 10. CLI Internal OmniRoute

Biner `omniroute` menyediakan perintah untuk siklus hidup server, penyiapan, diagnostik, dan pengelolaan penyedia. Titik masuk: `bin/omniroute.mjs`.

```bash
omniroute                              # Memulai server (port default 20128)
omniroute setup                        # Wizard penyiapan interaktif
omniroute doctor                       # Memeriksa konfigurasi, DB, port, runtime
omniroute providers list               # Koneksi penyedia yang dikonfigurasi
omniroute providers test-all           # Menguji setiap koneksi aktif
omniroute reset-password               # Mengatur ulang kata sandi admin
omniroute logs                         # Mengalirkan log permintaan
omniroute health                       # Status kesehatan terperinci (breaker, cache, memori)
omniroute --version                    # Menampilkan versi
omniroute --help                       # Menampilkan semua perintah
```

### Penyiapan & Inisialisasi

```bash
omniroute setup                        # Wizard penyiapan interaktif
omniroute setup --non-interactive      # Mode CI/otomatisasi (membaca variabel env + flag)
omniroute setup --password '<value>'   # Menetapkan kata sandi admin secara langsung
omniroute setup --add-provider \
  --provider openai \
  --api-key '<value>' \
  --test-provider                      # Menambahkan dan menguji penyedia sekaligus
```

Variabel lingkungan yang dikenali untuk penyiapan noninteraktif:

| Var                 | Tujuan                                                                 |
| ------------------- | ---------------------------------------------------------------------- |
| `OMNIROUTE_API_KEY` | Kunci API penyedia (terikat ke `--api-key` melalui Commander `.env()`) |
| `DATA_DIR`          | Mengganti direktori data OmniRoute                                     |

Semua input noninteraktif lainnya diteruskan sebagai flag, bukan variabel lingkungan:
`--password`, `--provider`, `--provider-name`, `--provider-base-url`, `--default-model`
(lihat opsi `omniroute setup` di atas).

### Diagnostik

```bash
omniroute doctor                       # Memeriksa konfigurasi, DB, port, runtime, memori, keaktifan
omniroute doctor --json                # JSON yang dapat dibaca mesin
omniroute doctor --no-liveness         # Melewati pemeriksaan kesehatan HTTP
omniroute doctor --host 0.0.0.0        # Mengganti host pemeriksaan keaktifan
omniroute doctor --liveness-url <url>  # Mengganti URL lengkap endpoint kesehatan
```

Doctor menjalankan pemeriksaan berikut: `Config`, `Database`, `Storage/encryption`,
`Port availability`, `Node runtime`, `Native binary` (better-sqlite3),
`Memory`, dan `Server liveness`. Proses keluar dengan kode bukan nol jika ada pemeriksaan yang berstatus `fail`.

### Pengelolaan Penyedia

```bash
omniroute providers available                       # Katalog penyedia OmniRoute
omniroute providers available --search openai       # Memfilter katalog berdasarkan id/nama/alias/kategori
omniroute providers available --category api-key    # Memfilter berdasarkan kategori (api-key, oauth, free, ...)
omniroute providers available --json                # JSON yang dapat dibaca mesin

omniroute providers list                            # Koneksi penyedia yang dikonfigurasi
omniroute providers list --json

omniroute providers test <id|name>                  # Menguji satu koneksi yang dikonfigurasi
omniroute providers test-all                        # Menguji setiap koneksi aktif
omniroute providers validate                        # Validasi struktural khusus lokal
omniroute providers add <provider> --credential-env PROVIDER_KEY
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth <provider>                 # Alur OAuth yang sudah ada
omniroute providers edit <id|name> --default-model <model>
omniroute providers remove <id|name> --yes
```

`providers add/import/auth/edit/remove` mengutamakan API sehingga dapat digunakan terhadap
konteks lokal atau jarak jauh yang aktif. Input kredensial sebaiknya menggunakan
`--credential-stdin` atau `--credential-env`; `--dry-run --json` hanya melaporkan
keberadaan/bentuk yang telah disamarkan. `providers available` membaca katalog OmniRoute;
`providers list/test/test-all/validate` mempertahankan perilaku SQLite lokalnya dan
tidak mengharuskan server berjalan.

Untuk node khusus yang kompatibel dengan OpenAI atau Anthropic, kaitkan kredensial ke
ID node yang dikembalikan oleh `omniroute nodes add`, menggunakan `omniroute keys add "$NODE_ID" --stdin`.
Ini memerlukan server yang berjalan dan autentikasi manajemen untuk konteks aktif.
CLI menggunakan `POST /api/providers`, yang memvalidasi node dan menyalin pengaturan
endpoint-nya ke koneksi. Node yang tidak ditemukan, kegagalan otorisasi, atau server
yang tidak tersedia akan menghasilkan kesalahan tanpa membuat kredensial lokal cadangan.

`nodes add --base-url` menetapkan endpoint node; ini berbeda dari alamat server
di `OMNIROUTE_BASE_URL`. Untuk file OpenAPI, gunakan
`omniroute openapi dump --format json --out ./openapi.json`; `--output` global
memilih format tampilan CLI, bukan nama file tujuan.

### Pemulihan & Pengaturan Ulang

```bash
omniroute reset-password                # Mengatur ulang kata sandi admin (juga: omniroute-reset-password)
omniroute reset-encrypted-columns       # Menampilkan peringatan + simulasi untuk pengaturan ulang kredensial terenkripsi
omniroute reset-encrypted-columns --force  # Benar-benar mengosongkan kredensial terenkripsi di SQLite
```

### Ekspor Kredensial (⚠ tangani dengan hati-hati)

```bash
omniroute auth export                                 # Menampilkan peringatan + tahap konfirmasi — tanpa akses DB
omniroute auth export --force                          # Mengekspor kredensial TERDEKRIPSI dari SEMUA koneksi ke stdout sebagai JSON
omniroute auth export --force --id <id>                 # Hanya mengekspor koneksi yang cocok
omniroute auth export --force --format env               # Menghasilkan baris OMNIROUTE_<PROVIDER>_<FIELD>=<value>
omniroute auth export --force --out creds.json           # Menulis ke file (dibuat dengan izin 0600)
```

`auth export` **hanya berjalan secara lokal** (membaca SQLite secara langsung, tanpa rute HTTP) dan sengaja mencetak/menulis
nilai `apiKey`/`accessToken`/`refreshToken`/`idToken` dalam **teks biasa** — ini adalah fitur, bukan
bug. Tidak ada yang dibaca dari basis data, dan tidak ada yang didekripsi, tanpa `--force`. Banner
peringatan selalu dicetak ke stderr sebelum teks biasa apa pun dikeluarkan. Mengharuskan
`STORAGE_ENCRYPTION_KEY` ditetapkan. Bidang yang gagal didekripsi (kunci kedaluwarsa, ciphertext rusak) dilaporkan sebagai
`<field>DecryptFailed: true`, alih-alih membatalkan seluruh ekspor atau membocorkan kesalahan yang mendasarinya.

## Mengelola kebijakan kunci inferensi dengan OmniRoute CLI

Gunakan konteks pengelolaan yang terautentikasi (lihat [Mode Jarak Jauh](../guides/REMOTE-MODE.md))
untuk memeriksa atau memperbarui kunci inferensi yang ada berdasarkan ID-nya:

```bash
omniroute --output json keys policy show KEY_ID
omniroute keys policy set KEY_ID --unrestricted
omniroute --output json keys policy show KEY_ID
```

`--unrestricted` adalah alias untuk `--model-access-mode all`. Pembaruan ini menghapus
daftar model yang diizinkan. Pembaruan tersebut mempertahankan cakupan, aturan koneksi, model yang diblokir, batas laju,
dan batas biaya, sehingga kontrol lainnya tetap dapat menolak permintaan. Penggunaan
`--allowed-models ""` secara eksplisit juga memilih `all`; gabungkan dengan
`--model-access-mode restricted` untuk mempertahankan kunci terbatas tanpa model yang diizinkan.
Daftar tidak kosong yang dipisahkan koma akan memilih `restricted`, kecuali jika ditentukan secara eksplisit.
Kombinasi `all` yang bertentangan dengan daftar izin tidak kosong akan ditolak sebelum permintaan dikirim.

`--rate-limit 30` menetapkan jumlah permintaan per menit dan mempertahankan aturan untuk jangka waktu
lainnya. `--max-cost 5` mengaktifkan batas harian dalam USD tanpa mengubah batas mingguan;
`--max-cost 0` menghapus batas harian dan mempertahankan pengaktifan batas penggunaan
serta batas mingguan yang sudah ada. Bidang kebijakan yang tidak disertakan tetap tidak berubah. Perubahan laju akan membaca
kebijakan saat ini terlebih dahulu; hindari pengeditan bersamaan pada larik batas laju milik kunci yang sama.

Perintah kebijakan menggunakan `GET`/`PATCH /api/keys/{id}` yang terautentikasi dan mengikuti konteks aktif
serta opsi global `--api-key`. Keluaran JSON hanya memuat bidang kebijakan,
tanpa kunci yang tersimpan atau representasinya yang disamarkan. Kredensial khusus inferensi
tidak dapat mengotorisasi perubahan pengelolaan. Respons 401/403 mengharuskan pemeriksaan kredensial
dan konteks pengelolaan; hal tersebut tidak membuktikan adanya kegagalan token CLI lokal atau salt.
Lihat [Token CLI](../security/CLI_TOKEN.md) untuk kontrak autentikasi lokal yang terpisah.
