Kontrak `config/cli-tools-manifest.json` netral mendeklarasikan IDs kanonik, alias, kandidat biner, resep penyiapan, argumen model, dan kemampuan. Adaptor Node biasa di `bin/cli/cli-manifest.mjs` dan adaptor TypeScript di `src/shared/constants/cliIntegrationManifest.ts` membaca file yang sama. Runtime, katalog, konfigurasi, penyelesaian, generator, dan registrasi backend diperiksa bersama oleh `tests/unit/cli/cli-manifest-drift.test.ts`. Dikatalogkan tidak berarti suatu alat dapat diluncurkan atau dikonfigurasi. Secara khusus, 5dive tetap hanya dikonfigurasikan.

## Lingkungan anak dan siklus hidup

`omniroute run`, `omniroute launch` dan `omniroute launch-codex` mewarisi daftar kompatibilitas OS/terminal yang diizinkan dan memasukkan kredensial target yang dipilih. Rahasia penyedia dan basis data yang tidak terkait tidak diwarisi secara default. `--inherit-env` secara eksplisit memulihkan warisan lingkungan induk secara penuh; hanya gunakan ketika proses pihak ketiga yang dipilih harus menerima nilai tersebut. Ini adalah pemfilteran lingkungan, bukan kotak pasir OS : prosesnya masih berjalan dengan izin sistem file pemanggil.

Sinyal interupsi dan terminasi diteruskan ke anak. Peluncur menunggu acara close anak sebelum menghapus konfigurasi sementara. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` mengontrol masa tenggang sebelum penghentian paksa (default 5000 milidetik).

`omniroute launch <tool>` (lihat [LAUNCH.md](./LAUNCH.md) ) mengikuti aturan lingkungan dan penerusan sinyal yang sama, dan menambahkan:

- **Mulai otomatis gerbang.** Untuk target lokal, ketika tidak ada gateway yang menjawab di port, peluncur akan memulai `omniroute serve --headless --no-open` terikat ke `127.0.0.1` dalam proses penuai terpisah. Setiap peluncuran yang berjalan memiliki sewa dalam `DATA_DIR/launch/leases/` (detak jantung setiap 15 detik, basi setelah 45 detik atau saat prosesnya hilang). Reaper menghentikan gateway yang dimulai setelah tidak ada sewa yang aktif untuk waktu menganggur (`OMNIROUTE_LAUNCH_IDLE_GRACE_MS`, default 10.000 milidetik). Gerbang yang dimulai oleh pengguna digunakan tetapi tidak pernah dihentikan. `--keep-gateway` atau `omniroute gateway keep` mengubah gerbang peluncur menjadi gerbang normal; `--no-start` mengembalikan perilaku fail-if-down yang lama. Target jarak jauh hanya diperiksa.
- **Sesi peluncuran.** Setiap peluncuran mencetak token sesi `olx_` yang berumur pendek dari kredensial induk (`POST /api/launch/sessions`), menjalankannya saat alat berjalan, membaca ringkasan penggunaan dan mencabutnya setelah alat keluar. Token adalah bagian ketat dari induknya: izin yang sama, katalog yang sama atau lebih sempit, umur yang lebih pendek, dan ini bukan kredensial dasbor. Alat ini menerima token sesi, bukan kredensial induk, dan permintaan diberi tag `launch:<tool>:<sessionId>` kecuali `--tag` diberikan. Gateway tanpa sesi API gagal dengan `GatewayTooOld` alih-alih kembali ke peluncuran tanpa cakupan.
- **Konfigurasi per peluncuran.** File konfigurasi alat ditulis ke direktori temp pribadi (mode 0700, awalan `omnirouter-`) dan dihapus setelah anak keluar. `SIGKILL` peluncur meninggalkan direktori; `omniroute launch --cleanup` menghapus direktori tersebut setelah berumur lebih dari satu hari.

## pengaturan persisten Gemini

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

Dua perintah pertama mengonfigurasi mesin ini untuk server lokal atau jarak jauh yang dipilih. Penyiapan mempertahankan pengaturan JSON yang tidak terkait, memilih autentikasi kunci API Gemini, dan menulis titik akhir dan kredensial ke file `.gemini/.env` pribadi. Ia menolak JSON yang tidak valid daripada menimpanya. URLs titik akhir harus berupa HTTP(S), tanpa kredensial, parameter kueri, atau fragmen yang disematkan. Jalur pencetakan kering, bukan nilai kredensial.

`GEMINI_CLI_HOME` atau `--gemini-home` memilih root rumah yang persisten. `run gemini` yang sebenarnya membuat dan kemudian menghapus rumah sementaranya sendiri. Tidak ada mode yang melewati pemeriksaan kepercayaan ruang kerja Gemini.

## profil Codex

`configure codex` menulis `<name>.config.toml` pribadi dengan model dan titik akhir penyedia OmniRoute -nya. Kredensial direferensikan melalui `OMNIROUTE_API_KEY`, tidak pernah disematkan. Perintah peluncuran menetapkan model yang dipilih pada kunci `model` tingkat atas, bukan di dalam `model_providers`.

File profil terpisah adalah kontrak Codex yang terdokumentasi saat ini; mereka melapisi konfigurasi pengguna saat dipilih dengan `codex --profile <name>`. Lihat [referensi profil resmi](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) dan [panduan OmniRoute Codex](./CODEX-CLI-CONFIGURATION.md).

## Eksekusi perintah hermetis

Dengan `DATA_DIR` yang eksplisit, pengaturan `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` mencegah startup masuk ke lingkungan kredensial direktori data pengguna default. Ini berguna untuk pengujian terisolasi. Itu tidak menonaktifkan file lingkungan lain yang dipilih secara eksplisit.

## Direktori kerja `.env`

CLI membaca file `.env` dalam urutan ini, dan file pertama yang menetapkan kunci menang: `DATA_DIR` eksplisit, direktori data default, direktori kerja saat ini, lalu direktori paket. Variabel shell selalu menang.

Direktori kerja mungkin milik orang lain (repositori yang dikloning, arsip yang belum dikemas), dan `omniroute serve` meneruskan lingkungan CLI ke server dan ke setiap alat yang dijalankan server. Jadi `.env` di sana hanya dapat menyetel kunci-kunci ini, yang tercantum di `bin/cli/utils/untrustedCwdEnv.mjs`:

| Kunci                           | Nilai yang diterima                                                           |
| ------------------------------- | ----------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` atau `yes` dalam hal apa pun, nilai yang diperlakukan oleh server |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | hingga 64 huruf, angka, `_`, `.`, `@` atau `-`                                |
| `LANGUAGE`                      | sama, ditambah `:`                                                            |
| `TZ`                            | maksimal 64 huruf, angka, `_`, `+`, `-` atau `/`, tidak dimulai dengan `/`    |
| `NO_COLOR`, `FORCE_COLOR`       | hingga 16 huruf dan angka                                                     |

Setiap nilai yang diterima `REQUIRE_API_KEY` akan mengaktifkan centang, sehingga file tidak dapat menonaktifkan centang itu sendiri. Namun hal ini tidak menentukan hasilnya: server membaca override `REQUIRE_API_KEY` yang disimpan dalam database sebelum lingkungan, sedangkan peringatan startup tentang mendengarkan pada semua antarmuka tanpa kunci API hanya membaca lingkungan. Dengan simpanan `false`, direktori kerja `REQUIRE_API_KEY=true` membiarkan API terbuka dan menyembunyikan peringatan itu. Aturan `TZ` lebih sempit daripada POSIX: ia menolak `.`, `:`, `,` dan `<>`, sehingga bentuk dan aturan `:Area/City` seperti `EST5EDT,M3.2.0,M11.1.0` harus diatur di shell atau di `<DATA_DIR>/.env`.

Nama harus sama persis, dalam huruf besar. Baris lainnya, nilai yang gagal diperiksa, dan nama yang bukan huruf ASCII biasa, angka, dan `_` (misalnya baris dengan byte NUL atau huruf serupa) dilewati. CLI mencetak satu peringatan yang memberi nama pada kunci yang tidak dapat disetel dan peringatan yang memberi nama pada kunci yang diizinkan untuk diabaikan, masing-masing dengan apa yang harus diubah (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Tidak ada yang mencetak nilainya. Jalur file dalam pesan ini, dan laporan jalur `.env` `omniroute doctor`, di-escape jika berisi karakter kontrol atau bidi. Pembatasan ini tidak berlaku bila direktori kerja adalah direktori data atau direktori paket.

`PORT`, `API_PORT` dan `DASHBOARD_PORT` tidak ada dalam daftar. Tanpa basis URL dari sumber dengan prioritas lebih tinggi, CLI berbicara dengan `localhost:<PORT>`, dan apa pun yang mendengarkan di sana akan menerima kunci API CLI, token konteks, dan token mesin CLI (`x-omniroute-cli-token`, lihat [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), yang diterima server lokal untuk panggilan manajemen dari loopback. Port dari direktori kerja akan membiarkan file tersebut memilih pendengar, jadi atur port di shell, di `<DATA_DIR>/.env` atau dengan opsi `--port` dari perintah yang memilikinya (`serve`, `launch`, `run`).

Parser tidak memiliki sintaks `export`. Baris seperti `export LD_PRELOAD=...` memberi nama variabel `export LD_PRELOAD`; dari direktori kerja itu dilewati, dan di file `.env` lainnya ia menetapkan nama literal, yang tidak terbaca apa pun.

CLI memasangkan token konteks yang disimpan (token akses atau kunci API lama) hanya dengan asal konteks itu sendiri: skema, host, dan port, dibandingkan dengan `URL.origin`. Hal ini berlaku untuk permintaan yang dibuat melalui klien HTTP CLI(`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) dan ke perintah `launch`, `launch codex`, `configure` dan `setup-*` yang menulis URL dasar dan memasukkan kunci ke dalam konfigurasi alat lain. Menunjuk ke server lain dengan `--remote`, mereka menggunakan `--api-key` atau `OMNIROUTE_API_KEY` eksplisit jika ada yang disetel, dan tidak ada token konteks. Perbandingannya tepat, jadi `localhost` dan `127.0.0.1`, atau host dengan dan tanpa titik tambahan, dihitung sebagai server berbeda dan tidak mendapatkan token konteks. URL dengan info pengguna, garis miring terbalik, atau spasi tidak pernah cocok, karena parser URL lainnya ( `urllib` dan `httpx` dari Python, misalnya) dapat membaca host yang berbeda darinya. Untuk permintaan yang dikirimkan CLI sendiri, pemeriksaan tersebut hanya mencakup skema dan otoritas, sehingga id dengan spasi di jalur atau kueri akan menyimpan token.
