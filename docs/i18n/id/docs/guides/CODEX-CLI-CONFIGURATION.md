Panduan lengkap untuk menggunakan Codex CLI yang diarahkan ke OmniRoute sebagai backend yang kompatibel dengan OpenAI.

---

> **TOML adalah satu-satunya format yang efektif.** Codex modern membaca `~/.codex/config.toml`
> secara eksklusif (diverifikasi menggunakan codex-cli 0.147.0: `codex --help` mendokumentasikan
> bahwa penggantian `-c/--config` "dimuat dari `~/.codex/config.toml`"). Berkas lama
> `~/.codex/config.yaml` merupakan milik CLI npm lawas dan diabaikan tanpa pemberitahuan.
> Generator dasbor (`/api/cli-tools/apply`, alat `codex`) menulis TOML dengan
> penggabungan konservatif — kunci yang ada dan blok penyedia lainnya dipertahankan,
> kunci API tetap berada di `OMNIROUTE_API_KEY` (tidak pernah di dalam berkas), dan sisa
> `config.yaml` lawas dilaporkan sebagai catatan migrasi tanpa disentuh.

## config.toml siap ditempel

Ganti `<YOUR_HOST>` dan `<YOUR_KEY>` dengan nilai Anda:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # batas penyimpanan riwayat per pemanggilan alat

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc atau ~/.zshrc — nilai kunci sebenarnya, jangan pernah disimpan di config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex yang disertakan di dalam aplikasi ChatGPT

Jika Anda menginstal Codex melalui aplikasi desktop ChatGPT, biner `codex` mungkin
hanya tersedia di dalam bundel aplikasi dan belum berada di `PATH` shell Anda. Tambahkan
direktori sumber daya ke berkas awal shell Anda:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Buka shell baru, lalu verifikasi:

```bash
command -v codex
codex --version
```

### OmniRoute lokal tanpa autentikasi: kunci placeholder sudah cukup

Codex memvalidasi bahwa variabel lingkungan yang disebutkan oleh `env_key` tersedia
**sebelum** permintaan pertama dikirim dari CLI. Jika instans OmniRoute **lokal**
Anda tidak memerlukan autentikasi, placeholder apa pun yang tidak kosong dapat digunakan:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Gunakan kunci asli jika server OmniRoute Anda dilindungi atau berada di lokasi jarak jauh.

> **Opsi host umum**
>
> | Akses          | URL                           |
> | -------------- | ----------------------------- |
> | Jaringan lokal | `http://192.168.0.1:20128/v1` |
> | Tailscale      | `http://100.x.x.x:20128/v1`   |
> | Loopback       | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — alasan konfigurasi ini berfungsi untuk semua model

Codex CLI menghentikan dukungan `wire_api = "chat"` (Chat Completions) pada Februari 2026 dan kini **mewajibkan** `wire_api = "responses"` (OpenAI Responses API). Menetapkan `wire_api = "chat"` menyebabkan crash langsung saat memulai sejak v0.138.

Banyak penyedia, termasuk GLM dan Kimi, masih hanya menyediakan endpoint Chat Completions. DeepSeek V4 kini menyediakan Responses API native serta endpoint yang kompatibel dengan Anthropic; OmniRoute menggunakan Responses secara default dan memungkinkan setiap koneksi DeepSeek memilih kompatibilitas Anthropic.

**OmniRoute menyelesaikan hal ini secara transparan:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute memilih protokol native penyedia dan menerjemahkannya bila diperlukan
    → POST /responses (DeepSeek V4) atau /chat/completions (Mistral / GLM / Kimi / lainnya)
```

Anda tidak pernah memerlukan proksi penerjemahan terpisah saat menggunakan OmniRoute. **Semua model menggunakan `wire_api = "responses"`** — OmniRoute menangani sisanya.

> **`wire_api` adalah nilai default** — bidang ini secara default bernilai `"responses"` dan dapat sepenuhnya dihilangkan dari `config.toml`. Tetapkan secara eksplisit hanya jika Anda ingin mendokumentasikan maksud konfigurasi.

## Jendela konteks dan pemadatan

### Kolom konfigurasi token

| Kolom                            | Deskripsi                                                                                                                                                                                                   |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Total anggaran token untuk model aktif. Atur ke batas yang dinyatakan oleh model.                                                                                                                           |
| `model_auto_compact_token_limit` | Ambang batas yang memicu pemadatan riwayat otomatis. **Maksimum: 90% dari `model_context_window`** — nilai di atas 90% diabaikan secara diam-diam.                                                          |
| `tool_output_token_limit`        | Batas token yang disimpan untuk setiap output pemanggilan alat dalam riwayat. Mencegah satu respons alat yang besar memenuhi jendela. **Ini bukan output maksimum** — ini adalah batas penyimpanan riwayat. |
| `compact_prompt`                 | Penggantian sebaris untuk prompt sistem yang digunakan selama pemadatan (v0.138+).                                                                                                                          |

> **Catatan tentang `model_max_output_tokens`**: Kolom ini **bukan bagian dari skema konfigurasi Codex CLI** (tidak ada dalam basis kode Codex Rust). Kolom ini diabaikan secara diam-diam jika diatur. Jangan mengandalkannya — gunakan `tool_output_token_limit` untuk mengontrol seberapa banyak output alat yang disimpan dalam riwayat.

## Upaya Penalaran

Mengatur seberapa banyak model "berpikir" sebelum merespons.

| Nilai    | Digunakan untuk                                 |
| -------- | ----------------------------------------------- |
| `none`   | Tanpa penalaran — respons langsung              |
| `low`    | Tugas sederhana (mengganti nama, memformat)     |
| `medium` | **Default server** jika tidak ditentukan        |
| `high`   | Tugas tingkat menengah (refaktor, debug)        |
| `xhigh`  | Arsitektur, analisis mendalam, masalah kompleks |

```bash
# Penimpaan per pemanggilan
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Tetapkan juga **ringkasan** penalaran agar Desktop dapat merender teks pemikiran (bukan hanya blob terenkripsi):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # atau ultra jika didukung
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### Anggaran Pemikiran OmniRoute (pengaturan server)

Pada host OmniRoute, **Settings → AI → Thinking Budget** harus diatur ke **`passthrough`** agar upaya/ringkasan Codex diteruskan ke upstream. Mode **`auto` menghapus** semua kolom `reasoning` / `reasoning_effort` dari klien dan akan mengosongkan panel pemikiran meskipun Codex telah dikonfigurasi dengan benar.

Panduan lengkap: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Kompresi dan cache prompt bersifat independen dan tetap berfungsi dalam mode `passthrough`.

## Profil — konfigurasi bernama untuk setiap model/alur kerja

Profil memungkinkan Anda mengganti model + jendela konteks dengan satu flag. Setiap profil berupa
`~/.codex/<name>.config.toml` datar yang ditumpangkan di atas `config.toml` dasar.

> **Aturan penamaan (Codex CLI v0.137+):** file harus berupa `~/.codex/<name>.config.toml` — **tanpa prefiks `profile-`**.
> CLI memetakan `-p kimi-k27` → `~/.codex/kimi-k27.config.toml`. Jika file tidak ditemukan, konfigurasi default diterapkan tanpa pemberitahuan.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # cepat, murah
```

### Profil upaya (model yang sama, upaya berbeda)

```bash
codex -p low      # cx/gpt-5.5, effort=low
codex -p medium   # cx/gpt-5.5, effort=medium
codex -p high     # cx/gpt-5.5, effort=high
codex -p xhigh    # cx/gpt-5.5, effort=xhigh (default)
codex -p chat     # cx/gpt-5.5, tanpa effort yang ditetapkan (default server)
```

## Membuat profil secara otomatis dengan `omniroute setup-codex`

Jika Anda menjalankan OmniRoute di VPS, Anda dapat membuat file profil secara otomatis dari katalog model aktif:

```bash
# Dari VPS (menggunakan OmniRoute lokal pada port 20128)
omniroute setup-codex

# Dari mesin mana pun — arahkan ke VPS Anda
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Pratinjau tanpa menulis file
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Hanya buat profil GLM dan Kimi
omniroute setup-codex --only glm,kimi

# Tulis ke direktori khusus
omniroute setup-codex --codex-home /path/to/.codex
```

Perintah tersebut mengambil `/v1/models`, menggunakan profil yang telah disesuaikan untuk model yang dikenali, menggunakan metadata katalog sebagai alternatif untuk model teks lain yang kompatibel, dan menulis `~/.codex/<name>.config.toml` untuk setiap model. Bersifat idempoten — aman untuk dijalankan kembali.

Jika `config.toml` dasar tidak memiliki definisi `model_providers.omniroute`, pemanggilan eksplisit
`setup-codex` akan menyertakan definisi tersebut dalam setiap overlay yang dibuat, menggunakan endpoint
lokal atau jarak jauh yang dipilih. File dasar tidak akan diubah. Definisi penyedia yang sudah ada
akan diwarisi, termasuk endpoint dan pengaturan autentikasinya. TOML dasar yang tidak valid
akan menghentikan pembuatan sebelum profil ditulis.

Saat Anda memberikan `--api-key` atau `OMNIROUTE_API_KEY`, penyedia yang baru didefinisikan akan merujuk ke
`env_key = "OMNIROUTE_API_KEY"`; kunci itu sendiri tidak pernah disimpan atau ditampilkan dalam
pratinjau. Tetapkan variabel tersebut di lingkungan tempat Anda menjalankan Codex. Tanpa
kunci yang diberikan, definisi baru tidak memiliki persyaratan kunci, untuk instans OmniRoute
yang dikonfigurasi agar menerima permintaan tanpa autentikasi.

Sinkronisasi otomatis katalog yang bersifat opsional dan dijelaskan di bawah ini mempertahankan definisi penyedia yang sudah
ada dalam overlay, tetapi tidak melakukan bootstrap terhadap pengaturan penyedia baru; konfigurasikan penyedia
terlebih dahulu melalui penyiapan eksplisit atau dasbor. Pengaturan penyedia yang sudah ada tidak disertakan
dalam pratinjau dry-run karena mungkin berisi kredensial yang dikelola oleh operator.

OmniRoute juga dapat **menyinkronkan secara otomatis** file profil yang sama ini setelah proses penemuan/impor model penyedia berhasil mengubah katalog aktif. Fitur ini **bersifat opsional dan dinonaktifkan secara default**: aktifkan dari **dasbor CLI Code** ("Sinkronisasi otomatis profil CLI" → Codex), atau tetapkan `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (fitur ini juga mematuhi `CLI_ALLOW_CONFIG_WRITES`, yang aktif secara default). Saat diaktifkan, fitur ini hanya menulis file profil `~/.codex/*.config.toml` yang terpisah; fitur ini tidak pernah mengubah `~/.codex/config.toml` aktif/default, pengaturan Codex-lb, autentikasi, atau pemilihan penyedia.

## Tugas jangka panjang

Dua default OmniRoute dapat secara diam-diam menyabotase sesi Codex CLI multi-jam. Pengaturan Codex CLI — juga tidak ada di sisi OmniRoute. Pengguna yang memigrasikan konfigurasi dari proksi upstream yang menyematkan akun dan menonaktifkan penghentian sementara sering kali menemukan keduanya dan menyimpulkan OmniRoute “tidak dapat mempertahankan sesi yang panjang.”

| Gejala                                                                             | Kemungkinan penyebabnya                                                    | Tombol                   |
| ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------ |
| Sesi terus berpindah akun/kontinuitas prompt-cache hilang antar giliran            | Afinitas sesi TTL adalah `0` (dinonaktifkan)                               | `sessionAffinityTtlMs`   |
| Koneksi terputus di tengah proses penalaran tanpa perintah yang ditujukan ke klien | Pengawas aliran menganggur diaktifkan setelah 10 menit tanpa potongan hulu | `STREAM_IDLE_TIMEOUT_MS` |

Diskusi terkait: [#7126](https://github.com/cheaper-inference/OmniRoute/discussions/7126) (tugas panjang terhenti), [#5718](https://github.com/cheaper-inference/OmniRoute/discussions/5718) (mengapa afinitas dinonaktifkan secara default). Pelacakan: [#7287](https://github.com/cheaper-inference/OmniRoute/issues/7287).

### 1. Afinitas sesi — menyematkan satu percakapan ke satu akun

**Bawaan:** `sessionAffinityTtlMs = 0` (dinonaktifkan).

**Di mana mengaturnya**

- Dasbor →** Pengaturan Perutean →** →** Afinitas sesi** →** Afinitas TTL (detik)** (`ComboDefaultsTab`)
- Atau pengaturan PATCH dengan `sessionAffinityTtlMs` in** milidetik** ( rentang Zod `0`–`86_400_000`, yaitu hingga 24 jam)

> Berganti nama menjadi #7274 dari Codex-only `codexSessionAffinityTtlMs`. Kunci lama masih diterima sebagai alias hanya-baca; konfigurasi baru harus menggunakan `sessionAffinityTtlMs`. Afinitas sekarang berlaku untuk** setiap** penyedia setelah TTL berada di atas `0`, tidak hanya Codex — lihat [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Sesi afinitas.

**Apa yang rusak jika tetap di 0**

Setiap giliran percakapan Codex multi-putaran disalurkan secara independen oleh strategi kombo aktif dan dapat mendarat di a** akun yang berbeda per giliran** . Itu memutus kesinambungan sesi upstream/prompt-cache. OmniRoute hanya berkonsultasi dengan header sesi Codex (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) dan bidang isi seperti `prompt_cache_key` / `session_id` ketika TTL lebih besar dari `0` (`extractSessionAffinityKey` di `src/sse/services/auth.ts`).

**Direkomendasikan untuk tugas tunggal multi-jam**

Atur TTL** melebihi panjang tugas yang diharapkan** (UI maks adalah** 86400 detik** = 24 jam):

| Durasi tugas yang diharapkan | Afinitas TTL (UI, detik)   | `sessionAffinityTtlMs` |
| ---------------------------- | -------------------------- | ---------------------- |
| Beberapa jam                 | `14400` (4 jam)            | `14400000`             |
| Semalam / ~ 12 jam           | `43200` (12 jam)           | `43200000`             |
| Sehari penuh                 | `86400` (24 jam, maksimum) | `86400000`             |

Keikutsertaan ini disengaja: menonaktifkan afinitas akan mendukung penyeimbangan beban di seluruh akun; mengaktifkannya akan mendukung kesinambungan untuk satu sesi agen yang panjang. Panduan ini bisa** bukan** ubah operator — default yang menjalankan tugas Codex yang panjang harus ikut serta.

### 2. Streaming batas waktu idle — tidak mematikan putaran penalaran yang tenang

**Bawaan:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 menit). Ini mewarisi dari `REQUEST_TIMEOUT_MS` ketika tidak disetel; baseline bersama juga 600000. Lihat [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Timeout.

**Apa yang rusak pada defaultnya**

Pergantian penalaran / alat Codex yang tetap diam selama lebih dari 10 menit** tidak ada bagian hulu yang nyata** ditutup paksa oleh pengawas menganggur SSE (`open-sse/utils/stream.ts`). Klien sering melihat koneksi terputus — yang cocok "berhenti secara otomatis tanpa pemberitahuan apa pun".

Detail penting: SSE sintetis OmniRoute** detak jantung tidak diatur ulang** jam menganggur. Hanya potongan bodi upstream nyata yang memperbarui `lastChunkTime`. Model pendiam yang masih “berpikir” terlihat identik dengan model yang terhenti di hulu dari sudut pandang pengawas.

Ketidakaktifan badan Undici terkait: `FETCH_BODY_TIMEOUT_MS` (juga default pada garis dasar 10 menit yang sama; `0` menonaktifkannya). Untuk streaming, `FETCH_TIMEOUT_MS` hanya mencakup pengaturan koneksi/header pertama — setelah streaming aktif, penghentian diatur oleh `STREAM_IDLE_TIMEOUT_MS` dan `FETCH_BODY_TIMEOUT_MS`.

**Direkomendasikan untuk tugas tunggal multi-jam**

Di lingkungan proses OmniRoute (`.env` / composer / systemd):

```bash
# Disable stream idle + body inactivity cutoffs for long reasoning turns
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Atau naikkan nilai tersebut di atas jeda tenang terpanjang yang Anda harapkan (nilainya adalah milidetik):

```bash
# Example: allow up to 2 hours of silence between upstream chunks
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Mulai ulang OmniRoute setelah mengubah env vars ini.

### Resep konkret — tugas Codex multi-jam

1. **Sematkan akun:** Dasbor → Pengaturan → Perutean → Afinitas sesi → Afinitas TTL = `43200` (12 jam) atau `86400` (maks 24 jam).
2. **Menaikkan/menonaktifkan batas waktu idle** di lingkungan OmniRoute:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Keep the usual Codex `config.toml` (`wire_api = "responses"`, correct `base_url`, `OMNIROUTE_API_KEY`) — no Codex-side affinity/idle knobs exist for these two behaviors.
4. Mulai ulang OmniRoute, lalu mulai tugas Codex yang panjang.

### Keputusan default (#7287)

| Tombol                   | Bawaan pengiriman   | Perubahan dalam panduan ini?                                                                              |
| ------------------------ | ------------------- | --------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (mati)          | **TIDAK** — tetap ikut serta (penyeimbangan beban vs kontinuitas; lihat Diskusi #5718)                    |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 menit) | **TIDAK** — tetap 10 menit untuk lalu lintas umum; operator Codex panjang menaikkan atau menonaktifkannya |

Membalik salah satu default secara global akan mengubah perilaku setiap klien dari sebuah instance, tidak hanya Codex. Dokumentasikan kenopnya; biarkan defaultnya saja sampai keputusan operator yang eksplisit mengatakan sebaliknya.

### Mendiagnosis pemotongan menganggur

Ketika pengawas yang menganggur menyala, OmniRoute mencatat garis yang berbentuk seperti:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Terima `Idle timeout: no data from` (atau kode `stream_idle_timeout` / nama kesalahan `StreamIdleTimeoutError`). Segmen penyedia adalah OmniRoute apa pun yang digunakan untuk permintaan itu (`codex`, id penyedia lain, atau `provider` jika tidak diketahui) — tidak selalu berupa string literal `codex`.

## Pemecahan masalah

**`Error: wire_api = "chat" is no longer supported`** Hapus `wire_api = "chat"` dari konfigurasi Anda. Setel `wire_api = "responses"` atau hilangkan bidang tersebut (defaultnya adalah `"responses"` sejak v0.138).

**`Error: model not found`** Verifikasi model ada di OmniRoute dengan awalan yang benar. Gunakan `omniroute models list` atau buka `/dashboard/providers/<provider>`.

**`Authentication error`** Konfirmasikan `OMNIROUTE_API_KEY` diekspor: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`** Codex memvalidasi bahwa env var ada sebelum membuat permintaan pertama. Ekspor kunci asli untuk server yang dilindungi, atau placeholder yang tidak kosong seperti `OMNIROUTE_API_KEY=local` saat Anda** lokal** instance OmniRoute tidak memerlukan autentikasi. Mulai ulang shell jika Anda menambahkannya ke `~/.bashrc` atau `~/.zshrc`.

**`Connection refused`** Pastikan OmniRoute berjalan dan `base_url` host/port benar untuk jaringan Anda (lokal vs Tailscale vs VPS).

**Sesi mogok mendekati batas konteks** Tetapkan `model_context_window` dan `model_auto_compact_token_limit` secara eksplisit. Lihat tabel jendela konteks di atas.

**Pemadatan terjadi terlambat** Turunkan `model_auto_compact_token_limit` ke 80–85% jendela. Jangan pernah menetapkan di atas 90%.

**Profil tidak dimuat (`-p <name>` diabaikan secara diam-diam)** Konfirmasikan file ada di `~/.codex/<name>.config.toml` (tanpa awalan `profile-` ). Jalankan `ls ~/.codex/*.config.toml`.

**Tugas Codex yang panjang turun di tengah jalan / mengalihkan akun antar putaran** Lihat [Tugas yang sudah berjalan lama](#long-running-tasks). Aktifkan afinitas sesi (TTL di atas durasi tugas) dan naikkan atau nonaktifkan `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. Ambil log OmniRoute untuk `Idle timeout: no data from`.
