OmniRoute terintegrasi dengan penyedia yang sistem edge-nya secara aktif mengidentifikasi sidik jari klien tidak resmi (TLS JA3/JA4, urutan header, struktur body JSON, token integritas). Halaman ini mendokumentasikan permukaan penyamaran yang disediakan OmniRoute dan lokasi implementasinya.

## Pemberitahuan Hukum dan Etika

Fitur penyamaran tersedia agar OmniRoute dapat bertindak sebagai lapisan kompatibilitas antara akun resmi milik pengguna (Claude Code CLI, Codex, Antigravity, Cursor, dll.) dan API terpadu OmniRoute. Fitur ini **bukan** untuk menghindari deteksi penipuan, membagikan kredensial, atau melanggar Ketentuan Layanan penyedia. Pengelola mengharapkan operator mematuhi ToS upstream yang mereka setujui saat membuat akun.

## Lapisan Fingerprinting TLS

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Sesi `wreq-js` persisten dibuat secara lazy berdasarkan cakupan akun dan proxy yang telah di-resolve. `TlsClient` pada cakupan proses mengelola pool maksimal 128 sesi yang menyamar sebagai **Chrome 124 di macOS** untuk upstream di belakang Cloudflare. `TlsClient.fetch()` gagal secara tertutup ketika runtime native tidak tersedia; pemanggil dapat secara eksplisit memilih fallback di luar wrapper ini.

- Profil sesi: `browser: "chrome_124", os: "macos"`
- Resolusi proxy (prioritas): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (juga huruf kecil)
- Batas waktu: `TLS_CLIENT_TIMEOUT_MS` (diwarisi dari `FETCH_TIMEOUT_MS`, default 600000)
- Response `wreq-js` kompatibel dengan fetch (`headers`, `text()`, `json()`, `clone()`, `body`).
- Watchdog byte pertama (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`
  selesai segera setelah header upstream tiba, sehingga `TLS_CLIENT_TIMEOUT_MS` saja tidak dapat membatasi
  body yang tidak pernah menghasilkan byte pertama. `guardTlsFirstByte()` menjalankan race antara `read()`
  pertama pada body dan `TLS_FIRST_BYTE_WATCHDOG_MS` (default `10000`, `0` menonaktifkannya); body yang sehat
  tidak terpengaruh, sedangkan body yang macet membatalkan reader wreq dan memungkinkan logika
  fallback TLS yang sudah ada pada `proxyFetch` beralih ke dispatcher langsung/proxy (permintaan yang tidak
  aman untuk diputar ulang, misalnya POST dengan body, tetap melempar error alih-alih dicoba ulang secara diam-diam).

### Transport penyedia cookie web — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` adalah adapter bersama untuk lima transport cookie web khusus
di bawah ini. Setiap wrapper penyedia yang tipis memilih profil browser/OS. Adapter menggunakan
loader runtime wreq tunggal dan pool transport di `open-sse/utils/tlsClient.ts`, dengan kunci
berdasarkan profil + OS + proxy yang telah di-resolve, sementara setiap permintaan menggunakan
`cookieMode: "ephemeral"`. Oleh karena itu, akun dan permintaan berbagi koneksi tingkat transport,
tetapi tidak pernah berbagi sesi wreq atau cookie jar.

| Penyedia   | Profil        | OS yang Diemulasi | Kebijakan EOF Stream                  |
| ---------- | ------------- | ----------------- | ------------------------------------- |
| Claude     | `chrome_146`  | Linux             | sertakan `[DONE]`                     |
| Perplexity | `firefox_151` | macOS             | sertakan `event: end_of_stream`       |
| Grok       | `chrome_146`  | Linux             | kecualikan `[DONE]`                   |
| Notion     | `chrome_146`  | Windows           | sertakan `[DONE]`                     |
| LMArena    | `chrome_146`  | Windows           | tanpa sentinel; tutup pada EOF native |

- Streaming menggunakan `ReadableStream` dari response native secara langsung; tidak ada file sementara atau sidecar yang
  dibuat.
- Hingga 256 byte awal diperiksa sebelum stream diekspos. Penyedia SSE melakukan buffering untuk error non-SSE;
  Grok/LMArena memetakan challenge Cloudflare ke `403` dan interstitial HTML ke `502`.
- Batas waktu permintaan native tetap dibungkus oleh tenggat waktu absolut JS. Hang akan membatalkan
  dan menutup hanya transport profil/OS/proxy yang terdampak sebelum permintaan berikutnya membuatnya kembali.
- Prioritas resolusi proxy adalah `proxyUrl` per pemanggilan → konteks akun/dashboard dalam cakupan permintaan →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (termasuk varian huruf kecil). Error resolusi gagal
  secara tertutup alih-alih membocorkan koneksi langsung. LMArena secara sengaja melakukan resolusi terhadap `arena.ai`.
- `byteResponse` mengembalikan URL `data:` dengan tipe konten tanpa kerusakan UTF-8.
- Error yang digunakan adalah `TlsClientUnavailableError` (paket/addon tidak tersedia), `TlsClientHangError`
  (tenggat waktu terlampaui), dan `WreqTransportCapacityError` (kode error kapasitas sesi bersama)
  ketika seluruh 128 slot profil/OS/proxy yang dibatasi sedang aktif atau dalam proses ditutup.

Sesi generik `TlsClient` di atas tetap dikhususkan untuk status cookie persisten yang didukung browser.
Kedua jalur menggunakan kembali satu loader modul wreq yang di-cache dan hook siklus hidup proses; pool keduanya tetap
terpisah karena masa aktif cookie masing-masing sengaja dibuat berbeda.

Profil-profil tersebut didukung oleh paket yang versinya dikunci, tetapi penerimaan WAF aktual dapat berubah secara independen
dari pengujian kontrak lokal. Validasi perubahan fingerprint terhadap akun aktif yang secara eksplisit diotorisasi
sebelum mengklaim paritas dengan browser upstream.

## Paket Tersamar Claude Code

Saat `cliCompatMode` aktif, OmniRoute membentuk ulang permintaan Claude keluar agar tidak dapat dibedakan dari lalu lintas `claude-cli`. Tiga modul bekerja sama:

### `claudeCodeFingerprint.ts`

Menghitung sidik jari `cc_version` sepanjang 3 karakter yang disematkan dalam header penagihan:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (ditulis langsung; cocok dengan klien resmi)
- Input: karakter pada indeks 4, 7, dan 20 dari teks pesan pengguna pertama + string versi
- Output: prefiks heksadesimal sepanjang 3 karakter

### `claudeCodeCCH.ts` (Hash Konten Klien)

Pemeriksaan integritas sisi server yang dihitung oleh Claude Code CLI resmi melalui Bun/Zig. OmniRoute mengimplementasikannya ulang dengan `xxhash-wasm`:

1. Serialisasikan isi dengan placeholder `cch=00000;`
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. Heksadesimal huruf kecil sepanjang 5 karakter yang diawali nol
4. Ganti `cch=00000;` dengan token yang dihitung

Konstanta:

- Seed: `0x6e52736ac806831e`
- Pola: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

Menyisipkan **zero-width joiner** Unicode (`U+200D`) setelah karakter pertama dari nama klien yang "sensitif" agar filter upstream tidak dapat menemukannya dengan grep. Daftar kata bawaan:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Diterapkan pada: blok `system`, semua `messages[].content`, dan `tools[].description` / `tools[].function.description`. Dapat diganti oleh operator melalui `setSensitiveWords()`.

### `claudeCodeCompatible.ts` — penyedia `anthropic-compatible-cc-*`

Untuk relay Anthropic pihak ketiga yang hanya menerima lalu lintas "Claude Code asli":

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"` secara bawaan
- Tombol per koneksi "Enable redact-thinking beta" menambahkan `redact-thinking-2026-02-12` saat upstream CC Compatible secara khusus memerlukan aliran proses berpikir yang disunting
- Tombol per koneksi "Enable summarized thinking display" menyimpan `providerSpecificData.requestDefaults.summarizeThinking` dan menambahkan `display: "summarized"` ke permintaan proses berpikir CC Compatible yang belum menetapkan mode tampilan
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (keluarga Opus/Sonnet 4.x)
- Jalur bawaan: `/v1/messages?beta=true`

Modul terkait dalam paket yang sama:

- `claudeCodeConstraints.ts` — aturan temperature + cache-control
- `claudeCodeToolRemapper.ts` — pemetaan ulang nama alat
- `claudeCodeExtraRemap.ts` — normalisasi payload tambahan

## Antigravity Siluman

permintaan Antigravity mempertahankan teks pemanggil byte demi byte. OmniRoute tidak memasukkan karakter lebar nol ke dalam prompt atau alat rename/inject untuk meniru klien IDE.

### `antigravityHeaderScrub.ts`

Strip penanda SDK tahan karat (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) sebelum meneruskan.

### ⚠️ Risiko: `ANTIGRAVITY_CREDITS=always` (hot spot pelarangan akun)

`ANTIGRAVITY_CREDITS=always` (dikonsumsi oleh `open-sse/executors/antigravity.ts`) rute** setiap** meminta melalui Antigravity AI Credit Overages (kredit Google berbayar) alih-alih membiarkan kuota tingkat gratis Google melakukan sesuatu. Ini didokumentasikan sebagai fitur, tetapi memang demikian** satu-satunya laporan pelanggaran ToS yang paling umum kami lihat** — beberapa akun Google Ultra telah diblokir dengan `403 / "service disabled for ToS violation" / insufficient_quota` setelah berjalan selama beberapa jam dengan `=always`.

Penegakan hukum di hulu sudah aktif** sisi Google** , tidak ada yang bisa dicegah OmniRoute. Nama env var dan dokumen yang ada membuatnya terdengar seperti tombol yang aman untuk diputar; itu tidak.

**Mengapa hal ini menyebabkan deteksi penyalahgunaan menjadi lebih agresif dibandingkan penggunaan tingkat gratis saja:**

- Pembelanjaan otomatis berkelanjutan pada satu akun Google ditandai secara berbeda dengan kuota-dan-berhenti tingkat gratis.
- Kelebihan kredit tidak memiliki batas tarif, sehingga klien yang salah dikonfigurasi dapat menghabiskan beberapa ratus USD dalam hitungan menit dan terlihat seperti penjualan kembali kunci API atau lalu lintas bot.
- Beberapa pengguna OmniRoute yang mendapatkan kelebihan kredit secara paralel dari IP eksternal yang sama akan menambah sinyal.

**Postur yang disarankan:**

1. Pertahankan `ANTIGRAVITY_CREDITS=off` default kecuali operator secara eksplisit menerima risiko kredit berbayar dan penegakan akun. `retry` mengirimkan permintaan normal terlebih dahulu dan menyuntikkan kredit paling banyak satu kali setelah kuota yang memenuhi syarat 429; `always` menyuntikkan kredit pada permintaan pertama.
2. **Sebarkan beban ke seluruh penyedia melalui Auto-Combo** (`model: "auto"` atau `kr/glm/etc` -combo) alih-alih memenuhi satu akun Antigravity.
3. **Tetapkan batas RPM per koneksi** di halaman edit penyedia Antigravity (Dasbor Penyedia → → Antigravity koneksi → batas kecepatan → ). 30–60 RPM adalah batas atas yang dapat dipertahankan untuk penggunaan berkelanjutan.
4. **Gunakan jaringan upstream yang stabil dan dikendalikan oleh operator** dan hindari berbagi satu akun dengan pengguna atau beban kerja yang tidak terkait.
5. **Jika dilarang** : mengajukan banding melalui `support.google.com` → "Pulihkan akses Workspace/Account " dengan isi respons `quota_exceeded` / `service disabled` yang tepat Google dikirim. Pemulihan tidak dijamin.

Referensi lingkungan mendokumentasikan implikasi akun dan pembelanjaan dari setiap mode kredit.

#### Tidak hanya `=always`: Antigravity OAuth routing secara umum

Penangguhan tersebut tidak hanya terbatas pada kelebihan kredit saja. Laporan pada bulan November 2026 (#19223, #19266) menjelaskan beberapa akun Google yang ditangguhkan saat melakukan perutean melalui penyedia `antigravity` dan `agy` (Antigravity CLI), dengan:

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

Kedua penyedia mengautentikasi dengan sesi Antigravity product OAuth, yang merupakan pemberitahuan risiko dasbor ("Penyedia ini menggunakan produk resmi Anda session/OAuth, yang tidak diizinkan untuk penggunaan proxy/router ") yang memperingatkan sebelum koneksi ditambahkan. Tidak satu pun rekomendasi di atas yang mengizinkan penggunaan tersebut; mereka hanya mengurangi jumlah lalu lintas yang dihasilkan satu akun.

**Antarmuka API resmi untuk model Gemini.** Google menawarkan akses terprogram ke Gemini melalui APIs, yang OmniRoute dukung sebagai penyedia kunci API biasa:

| ID penyedia | Nama dasbor               | Mandat                                                                      |
| ----------- | ------------------------- | --------------------------------------------------------------------------- |
| `gemini`    | Gemini (Google AI Studio) | kunci Gemini API dari Google AI Studio (tersedia tingkat gratis)            |
| `vertex`    | simpul AI                 | Akun Layanan JSON, token akses OAuth atau kunci API Vertex Express (Gemini) |

Penyedia ini menggunakan masalah kredensial Google untuk akses API, tidak seperti sesi produk Antigravity. Mereka tidak membuat setiap penggunaan patuh atau menghilangkan risiko penegakan hukum: masing-masing diatur oleh ketentuannya sendiri, yang harus diperiksa oleh operator untuk penerapannya. Misalnya, [Ketentuan Layanan Tambahan Gemini API](https://ai.google.dev/gemini-api/terms) hanya mengizinkan Layanan Berbayar ketika klien API tersedia untuk pengguna di Wilayah Ekonomi Eropa, Swiss, atau Inggris, dan konten yang dikirim ke Layanan Tidak Berbayar dapat digunakan untuk menyempurnakan produk Google. Vertex AI termasuk dalam ketentuan Google Cloud ( [Ketentuan Khusus Layanan](https://cloud.google.com/terms/service-terms) ). Harga dan kuota mengikuti ketentuan API tersebut dan bukan langganan Antigravity.

Operator yang ingin menghindari penangguhan Antigravity yang dijelaskan di atas harus merutekan lalu lintas Gemini melalui salah satu penyedia ini, bukan `antigravity` / `agy`, setelah memeriksa apakah penggunaannya sesuai dengan ketentuan penyedia.

Titik sentuh:

- `open-sse/executors/antigravity.ts` — berbunyi `process.env.ANTIGRAVITY_CREDITS`
- pipa kredensial `src/lib/oauth/providers/antigravity.ts` —
- Laporan kejadian asli: Diskusi [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## Registri Fingerprint CLI — `open-sse/config/cliFingerprints.ts`

Tabel per penyedia yang menetapkan urutan header dan urutan field body JSON secara **persis**, sebagaimana ditangkap dari trace mitmproxy CLI resmi. Saat ini terdaftar: `codex`, `claude`, serta profil yang diturunkan saat runtime dalam `providerHeaderProfiles.ts` untuk `antigravity` dan `github`.

```ts
interface CliFingerprint {
  headerOrder: string[]; // peka huruf besar-kecil
  bodyFieldOrder: string[]; // key JSON tingkat teratas
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Aktifkan atau nonaktifkan per penyedia melalui env (lihat di bawah). Saat dinonaktifkan, header/key body muncul dalam urutan apa pun yang diberikan oleh Node/JSON — mudah diidentifikasi melalui fingerprint.

## Proksi MITM (Antigravity, Linux/macOS/Windows)

Untuk CLI yang binernya tidak dapat dialihkan melalui `OPENAI_BASE_URL`, OmniRoute menjalankan proksi lokal yang mengakhiri TLS. Endpoint berada di bawah `src/app/api/cli-tools/antigravity-mitm/`.

| Metode | Endpoint                                | Tujuan                                            |
| ------ | --------------------------------------- | ------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | Status — berjalan, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | Mulai MITM (memerlukan `apiKey` + `sudoPassword`) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | Hentikan MITM                                     |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | Cantumkan alias model                             |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | Simpan alias model untuk suatu alat               |

Host target yang dicegat: **`daily-cloudcode-pa.googleapis.com`** (upstream Antigravity).

### Urutan proses mulai (`src/mitm/manager.ts::startMitm`)

1. Buat sertifikat yang ditandatangani sendiri melalui `selfsigned` (RSA-2048, SHA-256, 1 tahun) — `cert/generate.ts`
2. Instal sertifikat ke trust store sistem — `cert/install.ts`
3. Tambahkan entri hosts `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. Jalankan `src/mitm/server.cjs` dengan `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (default `443`)
5. Simpan PID ke `<DATA_DIR>/mitm/.mitm.pid`

### Deteksi trust store dinamis Linux — `cert/install.ts`

`getLinuxCertConfig()` menelusuri daftar prioritas dan memilih direktori pertama yang tersedia:

| Keluarga distro          | Direktori                                   | Perintah pembaruan       |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Nama file sertifikat: `omniroute-mitm.crt`. Pencocokan fingerprint melalui `getCertFingerprint()` (SHA-1 dari DER).

Selain itu, `updateNssDatabases()` menginstal ke DB NSS per pengguna saat `certutil` tersedia: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, semua profil Firefox (termasuk snap), dengan nama panggilan **`OmniRoute MITM Root CA`**.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** PowerShell dengan hak akses tinggi → `certutil -addstore Root`

### Autentikasi

Semua endpoint MITM memerlukan autentikasi manajemen (`requireCliToolsAuth`). Kata sandi sudo disimpan dalam cache pada cakupan modul (tidak pernah di `globalThis`) dan dihapus saat `stopMitm()`.

## Sanitasi Header Masuk

OmniRoute membersihkan header klien yang masuk sebelum meneruskannya, sehingga permintaan yang berasal dari Cursor tidak membocorkan `User-Agent: Cursor/X.Y.Z` ke upstream Claude. Lihat `src/shared/constants/upstreamHeaders.ts` untuk daftar penolakan yang dijaga tetap selaras dengan skema Zod dan pengujian unit.

## Memperbarui Sidik Jari Saat Penyedia Melakukan Rotasi

1. Tangkap lalu lintas CLI resmi dengan `mitmproxy` (intersepsi TLS + dump)
2. Ekstrak JA3/JA4 dan urutan header literal
3. Perbarui entri `CLI_FINGERPRINTS[...]` yang relevan
4. Naikkan default `*_USER_AGENT` yang sesuai di `.env.example`
5. Jika handshake TLS itu sendiri berubah, perbarui wrapper penyedia yang relevan atau opsi `browser:` wreq-js
6. Jalankan pengujian TLS khusus penyedia dan canary manual terhadap penyedia live
7. Rilis sebagai patch; dokumentasikan di `CHANGELOG.md`
