`devin-cli-agentic` ద్వారా నిజమైన Claude Code రన్టైమ్ OmniRoute యొక్క స్థానిక Anthropic
Messages ఎండ్పాయింట్ను ఉపయోగించగలదు, అదే సమయంలో అధికారిక Devin CLI మోడల్ ప్రతిస్పందనలను ACP stdio ద్వారా అందిస్తుంది. ఇది
ఇప్పటికే ఉన్న Anthropic, Claude OAuth, Claude Web లేదా `devin-cli` ప్రొవైడర్లను సవరించదు.

క్లయింట్-స్వంత టూల్ కాల్స్ కోసం, Claude-ఫార్మాట్ టూల్ సామర్థ్యం గల ప్రొవైడర్ అయిన
`devin-cli-agentic` (అలియాస్ `dva`) ద్వారా రూట్ చేయండి. లెగసీ `devin-cli` (`dv`) ACP ఎగ్జిక్యూటర్
టెక్స్ట్కు మాత్రమే పరిమితం: ఇది Devin యొక్క టూల్స్-లేని సమ్మరైజర్ను అమలు చేస్తుంది మరియు టూల్ కాల్స్ను తిరిగి ఇవ్వలేదు. టూల్ అవసరమైన కాంబో రూటింగ్ దానిని నివారించేలా దాని మోడల్
మెటాడేటా గుర్తించబడింది.

> **ప్రస్తుత స్థితి: Claude Code `2.1.258`కు పిన్ చేయబడింది; ఆఫ్లైన్ మరియు లైవ్ ధ్రువీకరణ చివరిగా
> `2.1.220`పై నమోదు చేయబడింది.** `2.1.220` పిన్ Devin CLI
> `3000.2.17` మరియు `swe-1-7-lightning` మోడల్ ద్వారా మూడు వేరుచేయబడిన దృశ్యాలను పూర్తి చేసింది; ఆ తుది లైవ్ రన్ క్లయింట్-స్వంత `Read`,
> `Edit`, మరియు `Bash` టర్న్లు, విజయవంతమైన `npm test` ఫలితాలు, ప్రాజెక్ట్ కమాండ్ మరియు స్కిల్
> డిస్కవరీ, Devin-మాత్రమే రూటింగ్, అలాగే Claude వైపు ఎలాంటి ఎగ్రెస్ లేదని నిరూపించింది. అనంతరం పిన్ను `2.1.258`కు పెంచారు
> (OmniRoute యొక్క Claude ఐడెంటిటీ అనుకరించే CLI తరం, అలాగే Fable 5.1 టైర్ను
> స్థానికంగా అందించే మొదటి విడుదల శ్రేణి). కొత్త పిన్పై, పిన్ చేసిన బేస్ ఇమేజ్లో ఇన్స్టాల్ లేయర్ మరియు `claude --version`
> ధ్రువీకరించబడ్డాయి, అలాగే బ్రిడ్జ్ యూనిట్ సూట్, `compose config` మరియు
> స్టాటిక్ ఐసోలేషన్ ప్రూఫ్ విజయవంతమయ్యాయి — అయితే ఆఫ్లైన్ మాక్ దృశ్యం మరియు లైవ్ మూడు-దృశ్యాల
> సూట్ ఇంకా మళ్లీ అమలు చేయబడలేదు. ఈ పిన్తో బ్రిడ్జ్పై ఆధారపడే ముందు వాటిని మళ్లీ అమలు చేయండి
> ("పిన్ చేసిన టూల్స్ను నవీకరించడం" చూడండి).

## ఆర్కిటెక్చర్

```text
Claude Code 2.1.258 (వేరుచేయబడిన non-root Linux కంటైనర్)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-ఫార్మాట్, ప్రమాణీకరణ-లేని ప్రొవైడర్)
  -> devin acp --agent-type summarizer (అధికారిక ACP stdio, Devin టూల్స్ లేవు)
  -> ప్రత్యేక devin-auth వాల్యూమ్లోని Devin ఖాతా
```

అధికారిక CLI యొక్క డిఫాల్ట్ ACP ఏజెంట్ తన స్వంత టూల్స్ను అమలు చేయగలదు, కాబట్టి ఈ బ్రిడ్జ్ దానిని ఉపయోగించదు.
ఇది టూల్స్ లేని అధికారిక CLI మోడ్ను కలిగిన స్థిరమైన `summarizer` ACP ఏజెంట్ను ప్రారంభించి,
సీరియలైజ్ చేసిన Anthropic అభ్యర్థనను అమలు ట్రేస్గా ఫ్రేమ్ చేస్తుంది. Claude-స్వంతమైన మరొక
చర్య అవసరమైనప్పుడు, ప్రతిస్పందనలో ఖచ్చితంగా ఒక క్లయింట్ టూల్ ఎన్వలప్ ఉండాలి. ప్రతిస్పందనను
విజయవంతమైనదిగా నివేదించడానికి ముందే ఏదైనా ACP `tool_call` లేదా `tool_call_update` తిరస్కరించబడుతుంది.

`open-sse/executors/devin-agentic/serializer.ts`లోని సీరియలైజర్ `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, మరియు
Claude Code అందించిన టూల్స్ను యథాతథంగా ఉంచుతుంది. చిత్రాలు మరియు తెలియని బ్లాక్లు స్పష్టంగా విఫలమవుతాయి. పెద్ద టూల్ ఫలితాలు
కనిపించే ట్రంకేషన్ మార్కర్ను ఉపయోగిస్తాయి.

పార్సర్ ప్రతి మోడల్ టర్న్లో ఒక స్వతంత్ర `<tool>{...}</tool>` ఎన్వలప్ను అంగీకరిస్తుంది. ఇది
అభ్యర్థనలోని టూల్ జాబితాతో పేరును తనిఖీ చేస్తుంది, ఆ టూల్ యొక్క JSON
Schemaతో ఆర్గ్యుమెంట్లను ధ్రువీకరిస్తుంది, వివరణాత్మక వచనం/చర్యలు కలిసివస్తే తిరస్కరిస్తుంది, అలాగే ఒక పరిమిత రిపేర్ను అనుమతిస్తుంది. ఆపై Claude Code
ఫలితంగా వచ్చిన Anthropic `tool_use`ను స్థానికంగా అమలు చేసి, `tool_result`ను OmniRoute ద్వారా తిరిగి
పంపుతుంది.

## ఆటో-రూటింగ్

ప్రొవైడర్ బ్లాక్ చేయబడనప్పుడు, OmniRoute యొక్క `auto/*` అభ్యర్థి పూల్లలో అర్హత పొందుతుంది.
అభ్యర్థి అర్హత ఎంపికను హామీ ఇవ్వదు: కాంబో యొక్క రూటింగ్ వ్యూహం (ఉదాహరణకు,
చివరిగా-సరిగ్గా-పనిచేసినది) మరొక ప్రొవైడర్కు ప్రాధాన్యం ఇవ్వవచ్చు. ప్రతి అభ్యర్థనను
Devin ద్వారా పంపాల్సిన అవసరం ఉన్నప్పుడు `dva/<model>` లేదా Devin-మొదటి కాంబోను ఉపయోగించండి.

## ఐసోలేషన్ మరియు ముప్పు నమూనా

హోస్ట్లోని Claude ఇన్స్టాలేషన్, ఖాతా మరియు కాన్ఫిగరేషన్ పరిధికి వెలుపల ఉంటాయి మరియు
నిషేధితమైనవిగా పరిగణించబడతాయి. Compose సేవలు:

- UID/GID `10001:10001`తో, చదవడానికి మాత్రమే అనుమతించే రూట్ ఫైల్సిస్టమ్తో, తొలగించిన సామర్థ్యాలతో మరియు
  `no-new-privileges`తో నడుస్తాయి;
- ప్రైవేట్ `/home/bridge`, ప్రత్యేక Claude కాన్ఫిగరేషన్ వాల్యూమ్, ఐసోలేట్ చేసిన OmniRoute డేటా
  మరియు విడిగా `devin-auth` వాల్యూమ్ను ఉపయోగిస్తాయి;
- తాత్కాలిక `.sandbox` వర్క్స్పేస్లు/సాక్ష్యాలను మాత్రమే మౌంట్ చేస్తాయి;
- హోస్ట్ హోమ్, Keychain, SSH, క్లౌడ్ క్రెడెన్షియల్లు లేదా Docker సాకెట్ను మౌంట్ చేయవు;
- స్పష్టమైన ఎన్విరాన్మెంట్లను నిర్మించి, Anthropic API/OAuth/రూటింగ్ వేరియబుల్లను తొలగిస్తాయి;
- స్థానికంగా మాత్రమే ఉపయోగించే కీతో Claude Code ఇన్ఫరెన్స్ను `http://omniroute:20128`కు మాత్రమే మళ్లిస్తాయి.

ఆఫ్లైన్ ప్రొఫైల్ అంతర్గత నెట్వర్క్ను ఉపయోగిస్తుంది. లైవ్ ప్రొఫైల్లో, OmniRoute అధికారిక
Devin ఎండ్పాయింట్లను `network-guard` ద్వారా మాత్రమే చేరుకుంటుంది; సంబంధం లేని గమ్యస్థానాలు నిరాకరించబడతాయి.
Claude Codeకు విడిగా అన్ని ఎగ్రెస్ను నిరాకరించే గార్డ్ ఉంటుంది మరియు `NO_PROXY` ద్వారా స్థానిక OmniRoute
సేవను మాత్రమే చేరుకోగలదు. గార్డ్ ఆడిట్ ఫైల్లు వాటి సంబంధిత గార్డ్ ప్రాసెస్ ద్వారా మాత్రమే మౌంట్ చేయబడతాయి.
టోకెన్-రహిత సాక్ష్యాన్ని ఎగుమతి చేయడానికి ముందు స్క్రిప్ట్లు ఫైల్ యాజమాన్యం, మోడ్, లింక్ సంఖ్య మరియు
ప్రతి నిర్ణయాన్ని ధృవీకరిస్తాయి.

ఐసోలేషన్ రుజువును స్వతంత్రంగా అమలు చేయండి:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

ఇది టోపాలజీ, పేరుతో ఉన్న మౌంట్లు, నాన్-రూట్/రీడ్-ఓన్లీ సెట్టింగ్లు, స్పష్టమైన స్థానిక రూటింగ్,
సున్నితమైన ఎన్విరాన్మెంట్ వేరియబుల్లు లేకపోవడం, Docker సాకెట్ లేకపోవడం, `api.anthropic.com`
మరియు `claude.ai`కు నిరోధించబడిన యాక్సెస్, Devinకు మాత్రమే పరిమితమైన ప్రొవైడర్ ఎంపిక, అలాగే
ACP బ్యాకెండ్ అందుబాటులో లేనప్పుడు స్పష్టమైన వైఫల్యాన్ని ధృవీకరిస్తుంది.

## మొదటిసారి సెటప్ మరియు సాధారణ వినియోగం

పిన్ చేసిన ఇమేజ్ను బిల్డ్ చేయండి:

```bash
./scripts/devin-bridge/build
```

ఐసోలేట్ చేసిన Devin వాల్యూమ్ను మాత్రమే ప్రామాణీకరించండి:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

లాగిన్ కమాండ్ రిమోట్/కంటైనర్ ఎన్విరాన్మెంట్ల కోసం ఉద్దేశించిన అధికారిక మాన్యువల్-టోకెన్
ఫ్లోను ఉపయోగిస్తుంది. విలువ నేరుగా CLI ప్రాంప్ట్లో నమోదు చేయబడుతుంది; అది
ప్రాసెస్ ఆర్గ్యుమెంట్గా పంపబడదు, Gitలో వ్రాయబడదు లేదా హోస్ట్ నుండి కాపీ చేయబడదు.

ఐసోలేట్ చేసిన Claude Code రన్టైమ్ను ప్రారంభించండి:

```bash
./scripts/devin-bridge/launch
```

కంటైనరైజ్ చేసిన Claude Codeను ప్రారంభించే ముందు `launch` ఐసోలేషన్, Devin ప్రామాణీకరణ మరియు
మోడల్ డిస్కవరీని మళ్లీ తనిఖీ చేస్తుంది. ఇది హోస్ట్లోని Claude ఎగ్జిక్యూటబుల్ను ఎప్పటికీ అమలు చేయదు. మోడల్ అలియాస్లను
`.env.devin-bridge`లో సెట్ చేయవచ్చు; కాన్ఫిగర్ చేసిన ప్రతి విలువ తప్పనిసరిగా
`devin-cli-agentic/` ప్రిఫిక్స్ను కలిగి ఉండాలి.

## ధృవీకరణ కమాండ్లు

పునరుత్పాదించగల ఆఫ్లైన్ మార్గానికి Devin ఖాతా అవసరం లేదు మరియు రన్టైమ్ ఇంటర్నెట్ ఉండదు:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

ప్రామాణీకరించిన, ఎంపికచేసి ఉపయోగించే లైవ్ మార్గం:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ACP సెషన్లను ఒకేసారి పెద్ద సంఖ్యలో తెరవకుండా ఉండటానికి లైవ్ రన్నర్ ప్రతి సందర్భం మధ్య వేచి ఉండి,
వచనపరమైన క్లెయిమ్లను నమ్మడానికి బదులుగా నిర్మిత Claude స్ట్రీమ్ ఈవెంట్లను ధృవీకరిస్తుంది. దాని మూడు
సందర్భాలు వీటిని రుజువు చేస్తాయి:

1. ప్రత్యక్ష ప్రాజెక్ట్ రీడ్లు మరియు లోప విశ్లేషణ;
2. నిజమైన `Edit`, క్లయింట్ యాజమాన్యంలోని `Bash` `npm test` మరియు టెర్మినల్ ఫలితం;
3. `/bridge-check`తో పాటు `bridge-proof` డిస్కవరీ, ప్రాజెక్ట్ రీడ్లు, విజయవంతమైన మరొక
   క్లయింట్ యాజమాన్యంలోని `npm test` మరియు పెండింగ్ పని లేకుండా పూర్తి కావడం.

చివరి గేట్ Devin నెట్వర్క్ ఆడిట్ను కూడా తనిఖీ చేసి, Claude ఎగ్రెస్ ఆడిట్
ఖాళీగానే ఉండాలని నిర్దేశిస్తుంది.

## పిన్ చేసిన టూల్స్ను నవీకరించడం

ఇమేజ్ `docker/devin-bridge/Dockerfile`లో Node, Claude Code మరియు Devin CLIలను నిర్దిష్ట వెర్షన్లకు పిన్ చేస్తుంది. నవీకరించడానికి:

1. స్పష్టంగా పేర్కొన్న వెర్షన్లను మార్చండి;
2. ఆర్కిటెక్చర్కు ప్రత్యేకమైన రెండు Devin ఆర్కైవ్ చెక్సమ్లను అధికారిక ఆర్టిఫాక్ట్కు సంబంధించిన విలువలతో భర్తీ చేయండి;
3. మళ్లీ బిల్డ్ చేసి, ప్రతి ఆఫ్లైన్ ధ్రువీకరణ కమాండ్ను అమలు చేయండి;
4. ఇమేజ్లోని వెర్షన్లను నిర్ధారించండి;
5. ప్రమాణీకరించిన మూడు-సన్నివేశాల లైవ్ సూట్ను మళ్లీ అమలు చేయండి.

హోస్ట్లో ఏ CLIని కూడా గ్లోబల్గా ఇన్స్టాల్ చేయవద్దు లేదా చెక్సమ్ ధ్రువీకరణను ధ్రువీకరించని డౌన్లోడ్తో భర్తీ చేయవద్దు.

## నిర్ధారణ మరియు శుభ్రపరచడం

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  లోకల్ రూటింగ్ను మరియు సున్నితమైన వివరాలు తొలగించిన ఎగ్జిక్యూటర్ లోపాలను చూపుతుంది.
- `.sandbox/evidence/mock-acp.jsonl` నిర్ధారిత mock ACP చర్యలను నమోదు చేస్తుంది.
- `.sandbox/evidence/claude-stream.jsonl` వాస్తవ Claude Code ఆఫ్లైన్ రన్ను నమోదు చేస్తుంది.
- `.sandbox/evidence/live-*.jsonl` ధ్రువీకరించిన మూడు లైవ్ స్ట్రీమ్లను నమోదు చేస్తుంది.
- `.sandbox/evidence/egress.jsonl` మరియు `.sandbox/evidence/claude-egress.jsonl` గార్డ్ ఆడిట్ల యొక్క ధ్రువీకరించిన,
  టోకెన్-రహిత కాపీలు.

లాగిన్/కాన్ఫిగ్ వాల్యూమ్లను సంరక్షిస్తూ యాజమాన్యంలోని కంటైనర్లు మరియు నెట్వర్క్లను ఆపండి:

```bash
./scripts/devin-bridge/clean
```

నేమ్డ్ వాల్యూమ్లతో సహా, బ్రిడ్జ్ యాజమాన్యంలోని పూర్తి ఎన్విరాన్మెంట్ను తొలగించండి:

```bash
./scripts/devin-bridge/clean --all
```

## పరిమితులు

- Devin CLI `3000.2.17` తటస్థమైన, టూల్స్ లేని ACP ఏజెంట్ను అందుబాటులో ఉంచనందున, బ్రిడ్జ్ స్థిరమైన no-tools `summarizer` పాత్రపై ఆధారపడుతుంది. సారాంశ-రూపంలోని మధ్యంతర ప్రతిస్పందనలను అడాప్టర్ సరిచేస్తుంది, అయినప్పటికీ పరిమితమైన ఒక రిపేర్ ఇప్పటికీ స్పష్టంగా విఫలం కావచ్చు.
- లైవ్ ACP కాల్లు తాత్కాలిక `502`/`504` ప్రతిస్పందనలను అందించవచ్చు. హార్నెస్ సన్నివేశాల మధ్య విరామం ఉంచుతుంది;
  నిరంతర వైఫల్యం fail-closed స్థితిలోనే ఉండి, మరొక ప్రొవైడర్ను ఎప్పటికీ ఎంచుకోదు.
- ప్రతి Anthropic అభ్యర్థన నుంచి ACP కాంటెక్స్ట్ పునర్నిర్మించబడుతుంది; ప్రాసెస్/సెషన్ అనుబంధం ఉండదు.
- ప్రతి మోడల్ ప్రతిస్పందనకు ఒక టూల్ కాల్కు మాత్రమే మద్దతు ఉంది; సమాంతర కాల్లు తిరస్కరించబడతాయి.
- ఇమేజ్లకు స్పష్టంగా మద్దతు లేదు. విజన్, థింకింగ్ అవుట్పుట్, ఎఫర్ట్ నియంత్రణలు మరియు 1M కాంటెక్స్ట్ విండో అందుబాటులో ఉన్నట్లు ప్రకటించబడవు.
- SSE చెల్లుబాటు అయ్యే Anthropic లైఫ్సైకిల్ ఈవెంట్లను ఉపయోగిస్తుంది, కానీ పరిమిత ACP టర్న్ సేకరించిన తర్వాత మాత్రమే విడుదల అవుతుంది;
  ACP చంక్లు క్రమానుగతంగా ఫార్వర్డ్ చేయబడవు.
