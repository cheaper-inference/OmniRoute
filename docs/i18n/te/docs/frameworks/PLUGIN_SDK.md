## త్వరిత ప్రారంభం

```ts
import { definePlugin } from "omniroute/plugins/sdk";

export default definePlugin({
  name: "my-plugin",
  priority: 50,
  onRequest: async (ctx) => {
    console.log(`Request ${ctx.requestId} for ${ctx.model}`);
  },
  onResponse: async (ctx, response) => {
    console.log(`Response for ${ctx.requestId}`);
    return response;
  },
  onError: async (ctx, error) => {
    console.error(`Error: ${error.message}`);
  },
});
```

## API సూచన

### `definePlugin(def: PluginDefinition): Plugin`

డిఫాల్ట్లతో ప్లగిన్ ఆబ్జెక్ట్ని సృష్టించే ఫ్యాక్టరీ ఫంక్షన్.

**పారామితులు:**

- `name` (స్ట్రింగ్, అవసరం) — కబాబ్-కేస్లో ప్లగిన్ పేరు
- `priority` (సంఖ్య, ఐచ్ఛికం, డిఫాల్ట్: 100) — దిగువ మొదట పరుగులు
- `enabled` (బూలియన్, ఐచ్ఛికం, డిఫాల్ట్: నిజం) — ప్రారంభించబడిందా?
- `onRequest` (ఫంక్షన్, ఐచ్ఛికం) — చాట్ హ్యాండ్లర్కు ముందు నడుస్తుంది
- `onResponse` (ఫంక్షన్, ఐచ్ఛికం) — చాట్ హ్యాండ్లర్ తర్వాత రన్ అవుతుంది
- `onError` (ఫంక్షన్, ఐచ్ఛికం) — హ్యాండ్లర్ లోపంపై రన్ అవుతుంది

### `blockRequest(response?): BlockingHookResult`

అభ్యర్థనను బ్లాక్ చేయండి మరియు ఐచ్ఛికంగా అనుకూల ప్రతిస్పందనను అందించండి.

```ts
onRequest: (ctx) => {
  if (!ctx.headers?.["x-client-team"]) {
    return blockRequest({ error: "Missing x-client-team header", status: 400 });
  }
};
```

### `modifyBody(body): PluginResult`

రిక్వెస్ట్ బాడీ ప్రొవైడర్కి చేరేలోపు దాన్ని సవరించండి.

```ts
onRequest: (ctx) => {
  return modifyBody({ ...ctx.body, temperature: 0.7 });
};
```

### `addMetadata(metadata): PluginResult`

అభ్యర్థన సందర్భానికి మెటాడేటాను అటాచ్ చేయండి.

```ts
onRequest: (ctx) => {
  return addMetadata({ source: "my-plugin", version: "1.0.0" });
};
```

## ప్లగిన్ సందర్భం (`PluginContext`)

| ఫీల్డ్       | టైప్ చేయండి               | వివరణ                             |
| ------------ | ------------------------- | --------------------------------- |
| `requestId`  | `string`                  | ప్రత్యేక అభ్యర్థన ఐడెంటిఫైయర్     |
| `model`      | `string`                  | మోడల్ పేరు అభ్యర్థించబడింది       |
| `provider`   | `string`                  | టార్గెట్ ప్రొవైడర్ ID             |
| `body`       | `Record<string, unknown>` | శరీరాన్ని అభ్యర్థించండి           |
| `headers`    | `Record<string, string>`  | అభ్యర్థన శీర్షికలు (గమనిక చూడండి) |
| `metadata`   | `Record<string, unknown>` | మార్చగల మెటాడేటా                  |
| `timestamp`  | `number`                  | సమయముద్రను అభ్యర్థించండి          |
| `apiKeyInfo` | `object` (ఐచ్ఛికం)        | API కీ మెటాడేటా (గమనిక చూడండి)    |

సందర్భం ఎప్పుడూ క్లయింట్ యొక్క ఆధారాలను కలిగి ఉండదు: `authorization`, `x-api-key`, `proxy-authorization` మరియు `cookie` హెడర్లు తీసివేయబడతాయి (ఏదైనా కేసింగ్), మరియు `apiKeyInfo` కీ యొక్క మెటాడేటాను ( `id`, `name` మరియు `scopes` వంటివి) ఉంచుతుంది కానీ కీ విలువ లేదా దాని వేలిముద్ర కాదు (`redactPluginContext()` `src/lib/plugins/hooks.ts`). ఇది `onRequest`, `onResponse` మరియు `onError` లకు వర్తిస్తుంది.

## మానిఫెస్ట్ (`plugin.json`)

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "description": "A sample plugin",
  "author": "your-name",
  "main": "index.js",
  "hooks": {
    "onRequest": { "enabled": true, "priority": 50 },
    "onResponse": true,
    "onError": false
  },
  "requires": {
    "permissions": ["network", "file-read"]
  },
  "enabledByDefault": false,
  "configSchema": {
    "apiKey": {
      "type": "string",
      "description": "API key for external service"
    },
    "maxRetries": { "type": "number", "min": 1, "max": 10, "default": 3 },
    "debug": { "type": "boolean", "default": false },
    "mode": { "type": "string", "enum": ["fast", "slow"], "default": "fast" }
  }
}
```

### హుక్ ప్రాధాన్యత

హుక్లను ప్రాధాన్యతతో కాన్ఫిగర్ చేయవచ్చు (తక్కువ విలువ = ముందుగా అమలవుతుంది):

```json
{
  "hooks": {
    "onRequest": { "enabled": true, "priority": 10 },
    "onResponse": { "enabled": true, "priority": 100 }
  }
}
```

లేదా సాధారణ boolean విలువలుగా (డిఫాల్ట్ ప్రాధాన్యత 100):

```json
{
  "hooks": {
    "onRequest": true,
    "onResponse": true
  }
}
```

## అనుమతి వ్యవస్థ

డిఫాల్ట్గా ప్లగిన్లు ఉంటాయి** శాండ్బాక్స్ లేదు** . ప్రతి యాక్టివ్ ప్లగ్ఇన్ VM సందర్భం మరియు Node.js అనుమతి ఫ్లాగ్లు లేకుండా OmniRoute వలె అదే ఆపరేటింగ్-సిస్టమ్ వినియోగదారు క్రింద ప్రత్యేక, సాధారణ Node.js చైల్డ్ ప్రాసెస్ ( `src/lib/plugins/loader.ts` లో`loadPlugin()` ) వలె నడుస్తుంది. ప్లగిన్ కోడ్ `node:fs`, `node:child_process`, `fetch` మరియు ప్రతి ఇతర Node.js API ఉపయోగించవచ్చు: ఇది OmniRoute వినియోగదారు (డేటా డైరెక్టరీతో సహా) చేయగలిగిన ఏదైనా ఫైల్ను చదవగలదు మరియు వ్రాయగలదు, ప్రోగ్రామ్లను అమలు చేసి నెట్వర్క్కు చేరుకుంటుంది.

మానిఫెస్ట్ యొక్క `requires.permissions` `network`, `file-read`, `file-write`, `env` మరియు `exec` అంగీకరిస్తుంది. డిఫాల్ట్ సెట్టింగ్లతో రన్టైమ్లో `env` మాత్రమే ప్రభావం చూపుతుంది.

### ఆప్ట్-ఇన్ అనుమతి మోడల్ (`PLUGIN_PERMISSION_MODEL_ENABLED`)

`PLUGIN_PERMISSION_MODEL_ENABLED` ఫీచర్ ఫ్లాగ్ (వర్గం `security`,** డిఫాల్ట్గా ఆఫ్** ) [Node.js అనుమతి మోడల్తో](https://nodejs.org/api/permissions.html) ప్రతి ప్లగ్ఇన్ ప్రక్రియను ప్రారంభిస్తుంది (`--permission`, ప్రతి మద్దతు ఉన్న Node.js లైన్ ద్వారా ఆమోదించబడింది: 22.22 +, 24 మరియు 26). జెండాలు మానిఫెస్ట్ నుండి `buildPermissionModelArgs()` `src/lib/plugins/permissionModel.ts` ద్వారా నిర్మించబడ్డాయి. ప్లగ్ఇన్ సక్రియం చేయబడినప్పుడు ఫ్లాగ్ చదవబడుతుంది, కాబట్టి ఇది మార్పు తర్వాత యాక్టివేట్ చేయబడిన ప్లగిన్లకు వర్తిస్తుంది; అమలులో ఉన్న ప్లగ్ఇన్ని వర్తింపజేయడానికి నిష్క్రియం చేయండి మరియు సక్రియం చేయండి.

ప్లగ్ఇన్ డేటా డైరెక్టరీ ప్లగిన్ రూట్ పక్కన `plugin-data/<plugin-name>` ఉంటుంది (డిఫాల్ట్గా`~/.omniroute/plugin-data/<plugin-name>`, `getPluginDataDir()`). ఫ్లాగ్ ఆన్తో, దాని మార్గం ప్లగ్ఇన్కి `PLUGIN_DATA_DIR` గా పంపబడుతుంది.

| అనుమతి       | ఫ్లాగ్ ఆఫ్ (డిఫాల్ట్)                                                                                                                                                                                                                    | ఫ్లాగ్ ఆన్ చేయండి                                                                                                                                                                                                                                                            |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `network`    | ఏదీ లేదు (డిక్లరేషన్ మాత్రమే).                                                                                                                                                                                                           | ఏదీ లేదు. Node.js అనుమతి మోడల్ అవుట్బౌండ్ నెట్వర్క్ యాక్సెస్ను పరిమితం చేయదు, కాబట్టి `network` డిక్లరేషన్గా ఉంటుంది మరియు ఎప్పటికీ అమలు చేయబడదు.                                                                                                                            |

ఫ్లాగ్ను వారి స్వంత డైరెక్టరీ వెలుపల చదివే (ఉదాహరణకు పేరెంట్ `node_modules` నుండి పరిష్కరించబడిన మాడ్యూల్) బ్రేక్ల ప్లగిన్లపై ఫ్లాగ్ను తిప్పడం, వాటి డేటా డైరెక్టరీని మినహాయించి ఎక్కడైనా వ్రాయండి లేదా `exec` ప్రకటించకుండానే ప్రాసెస్లను ప్రారంభించండి. ప్లగ్ఇన్పై ఫ్లాగ్తో కూడా నెట్వర్క్ యాక్సెస్ను ఉంచుతుంది మరియు OmniRoute యూజర్గా రన్ అవుతుంది, కాబట్టి మీరు విశ్వసించే ప్లగ్ఇన్లను మాత్రమే ఇన్స్టాల్ చేయండి.

## కాన్ఫిగ్ స్కీమా

కాన్ఫిగర్ చేయగల సెట్టింగ్లను `configSchema`లో నిర్వచించండి:

```json
{
  "configSchema": {
    "apiKey": { "type": "string", "description": "బాహ్య API కీ" },
    "maxRetries": { "type": "number", "min": 1, "max": 10, "default": 3 },
    "debug": { "type": "boolean", "default": false },
    "mode": { "type": "string", "enum": ["fast", "slow"], "default": "fast" }
  }
}
```

ఫీల్డ్ రకాలు: `string`, `number`, `boolean`, `select`

ఫీల్డ్ ఎంపికలు: `default`, `min`, `max`, `enum`, `description`

కాన్ఫిగ్ విలువలు డేటాబేస్లో నిల్వ చేయబడతాయి మరియు డ్యాష్బోర్డ్ కాన్ఫిగ్ పేజీ ద్వారా యాక్సెస్ చేయవచ్చు.

## ఉదాహరణలు

### రిక్వెస్ట్ లాగర్

```ts
import { definePlugin } from "omniroute/plugins/sdk";

export default definePlugin({
  name: "request-logger",
  onRequest: async (ctx) => {
    console.log(`[${new Date().toISOString()}] ${ctx.method} ${ctx.model} -> ${ctx.provider}`);
  },
});
```

### రేటు పరిమితి

```ts
import { definePlugin, blockRequest } from "omniroute/plugins/sdk";

const requests = new Map<string, number[]>();

export default definePlugin({
  name: "rate-limiter",
  priority: 10,
  onRequest: async (ctx) => {
    const key = ctx.apiKeyInfo?.id || "anonymous";
    const now = Date.now();
    const window = 60000; // 1 minute
    const maxRequests = 100;

    const timestamps = (requests.get(key) || []).filter((t) => t > now - window);
    timestamps.push(now);
    requests.set(key, timestamps);

    if (timestamps.length > maxRequests) {
      return blockRequest({ error: "Rate limit exceeded", status: 429 });
    }
  },
});
```

### ప్రతిస్పందన ట్రాన్స్ఫార్మర్

```ts
import { definePlugin } from "omniroute/plugins/sdk";

export default definePlugin({
  name: "response-transformer",
  onResponse: async (ctx, response) => {
    if (response.choices) {
      response.choices = response.choices.map((c: any) => ({
        ...c,
        message: { ...c.message, content: c.message.content.trim() },
      }));
    }
    return response;
  },
});
```
