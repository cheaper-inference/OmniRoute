> **ప్రామాణిక మూలం:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, మరియు
> `src/app/(dashboard)/dashboard/plugins/`
> **చివరిగా నవీకరించబడింది:** 2026-06-28 — v3.8.40

OmniRoute, WordPress-శైలి ప్లగిన్ వ్యవస్థతో అందించబడుతుంది. ప్లగిన్లు స్వయం-సమగ్ర
డైరెక్టరీలు — ప్రతి దానిలో ఒక `plugin.json` మానిఫెస్ట్ మరియు ఒక ఎంట్రీ ఫైల్ ఉంటాయి — ఇవి
అభ్యర్థన పైప్లైన్లో (`onRequest` / `onResponse` / `onError`) మరియు
లైఫ్సైకిల్ ఈవెంట్లలో (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
హుక్ అవుతాయి.

**ప్లగిన్ మార్కెట్ప్లేస్** అనేది ఆ వ్యవస్థపై ఉండే డిస్కవరీ లేయర్. ఇది
ఇన్స్టాల్ చేయగల ప్లగిన్లను బ్రౌజ్ చేయగల కేటలాగ్గా అందిస్తుంది. డిఫాల్ట్గా ఈ కేటలాగ్
ఒక చిన్న అంతర్నిర్మిత సీడ్ రిజిస్ట్రీగా ఉంటుంది; ఆపరేటర్ దీన్ని అనుకూల రిమోట్
రిజిస్ట్రీ URLకు నిర్దేశించవచ్చు. అటువంటి సందర్భంలో ఫెచ్ను DNS-రిజాల్వింగ్ SSRF గార్డ్
ద్వారా పటిష్ఠం చేస్తారు ([భద్రత](#security) చూడండి).

ప్రతి ప్లగిన్ రూట్ **లూప్బ్యాక్కు మాత్రమే పరిమితం** (టియర్ 1 — `LOCAL_ONLY`):
ప్లగిన్లు చైల్డ్ ప్రాసెస్లలో కోడ్ను లోడ్ చేసి అమలు చేస్తాయి, కాబట్టి ఆథెంటికేషన్తో
సంబంధం లేకుండా లూప్బ్యాక్ కాని మూలం నుండి ఈ రూట్లను చేరుకోలేరు.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) చూడండి.

## ఇది Together ఎలా సరిపోతుంది

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **రిజిస్ట్రీ లేయర్** — `src/lib/plugins/marketplace.ts`: ఏదైనా విఫలమైతే విత్తన రిజిస్ట్రీకి తిరిగి పడిపోతూ, కేటలాగ్ను జాబితా చేస్తుంది / శోధిస్తుంది.
- **జీవితచక్ర పొర** — `src/lib/plugins/manager.ts` (`pluginManager` singleton): ఇన్స్టాల్, అప్గ్రేడ్, యాక్టివేట్, డియాక్టివేట్, అన్ఇన్స్టాల్, స్కాన్, స్టార్టప్ లోడ్.
- **మానిఫెస్ట్ పొర** — `src/lib/plugins/manifest.ts`: `plugin.json` కోసం Zod స్కీమా + డిఫాల్ట్లు.
- **స్కానర్** — `src/lib/plugins/scanner.ts`: ప్లగిన్ డైరెక్టరీ క్రింద డిస్క్లో ప్లగిన్లను కనుగొంటుంది.
- **లోడర్** — `src/lib/plugins/loader.ts`: ప్రతి ప్లగ్ఇన్ను ప్రత్యేక Node.js చైల్డ్ ప్రాసెస్లో స్పాన్ చేస్తుంది మరియు బ్రోకర్లు IPC ద్వారా కాల్లను హుక్ చేస్తారు. చైల్డ్ శాండ్బాక్స్ కాదు (క్రింద ఉన్న "ప్లగిన్ ఎగ్జిక్యూషన్ ఐసోలేషన్" చూడండి).

## మార్కెట్ప్లేస్ కేటలాగ్

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) `MarketplaceEntry`
ఆబ్జెక్ట్ల జాబితాను తిరిగి ఇస్తుంది:

| ఫీల్డ్        | రకం      | గమనికలు                                 |
| ------------- | -------- | --------------------------------------- |
| `name`        | string   | kebab-case ప్లగిన్ పేరు                 |
| `version`     | string   | semver                                  |
| `description` | string   | సంక్షిప్త సారాంశం                       |
| `author`      | string   | రచయిత / సంస్థ                           |
| `license`     | string   | SPDX-శైలి లైసెన్స్ id                   |
| `downloadUrl` | string   | సోర్స్ డౌన్లోడ్ URL (ఖాళీగా ఉండవచ్చు)   |
| `repository`  | string?  | ఐచ్ఛిక రిపోజిటరీ URL                    |
| `tags`        | string[] | శోధన/ఫిల్టర్ ట్యాగ్లు                   |
| `downloads`   | number   | డౌన్లోడ్ల సంఖ్య                         |
| `rating`      | number   | 0–5                                     |
| `verified`    | boolean  | ఎంట్రీ ధృవీకరించబడినదిగా గుర్తించబడిందా |
| `lastUpdated` | string   | ISO-తరహా తేదీ స్ట్రింగ్                 |

అనుకూల రిజిస్ట్రీ URL ఏదీ కాన్ఫిగర్ చేయనప్పుడు, కేటలాగ్ అంతర్నిర్మిత
`SEED_REGISTRY`గా ఉంటుంది (ప్రస్తుతం `request-logger`, `rate-limiter`, `cost-tracker`,
మరియు `theme-manager`). సీడ్ రిజిస్ట్రీ ఎల్లప్పుడూ అందుబాటులో ఉంటుంది — కాన్ఫిగర్ చేసిన
రిమోట్ రిజిస్ట్రీని చేరుకోలేకపోయినా, అది `200` కాని స్టేటస్ను తిరిగి ఇచ్చినా లేదా
గుర్తించలేని బాడీని తిరిగి ఇచ్చినా, `listMarketplacePlugins()` హెచ్చరికను లాగ్ చేసి
సీడ్ జాబితాకు తిరిగి వెళ్తుంది.

> గమనిక: మార్కెట్ప్లేస్ **కేటలాగ్** (బ్రౌజ్/శోధన) మొదటి నుంచి చివరి వరకు అనుసంధానించబడింది,
> కానీ కేటలాగ్ నుండి ఒకే క్లిక్తో మార్కెట్ప్లేస్ **ఇన్స్టాల్** చేయడం ఇంకా అమలు కాలేదు —
> మార్కెట్ప్లేస్ ఎంట్రీపై ఉన్న డాష్బోర్డ్ "ఇన్స్టాల్" బటన్ ప్రస్తుతం
> "త్వరలో అందుబాటులోకి వస్తుంది" అనే నోటీసును చూపుతుంది. ప్రస్తుతం ఇన్స్టాలేషన్
> స్థానిక-పాత్ ఇన్స్టాల్ ఫ్లో (`POST /api/plugins`) మరియు డిస్క్పై డిస్కవరీ
> (`POST /api/plugins/scan`) ద్వారా జరుగుతుంది.

## REST API

అన్ని ముగింపు బిందువులకు నిర్వహణ ప్రమాణీకరణ అవసరం (`requireManagementAuth`)** మరియు** లూప్బ్యాక్-మాత్రమే — `/api/plugins` మరియు `/api/plugins/` `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`)లో జాబితా చేయబడ్డాయి.

| ఎండ్ పాయింట్                       | పద్ధతి | వివరణ                                                                     |
| ---------------------------------- | ------ | ------------------------------------------------------------------------- |
| `/api/plugins`                     | GET    | ఇన్స్టాల్ చేయబడిన ప్లగిన్లను జాబితా చేయండి (ఐచ్ఛిక `?status=` ఫిల్టర్)    |
| `/api/plugins`                     | POST   | ప్లగిన్ మూలాల డైరెక్టరీ నుండి ప్లగిన్ను ఇన్స్టాల్ చేయండి                  |
| `/api/plugins/scan`                | POST   | ప్లగిన్ డైరెక్టరీని స్కాన్ చేయండి మరియు కొత్త ప్లగిన్లను నమోదు చేయండి     |
| `/api/plugins/marketplace`         | GET    | మార్కెట్ ప్లేస్ కేటలాగ్ ఎంట్రీలను జాబితా చేయండి                           |
| `/api/plugins/marketplace/install` | POST   | పేరు ద్వారా మార్కెట్ప్లేస్ ప్లగిన్ను ఇన్స్టాల్ చేయండి                     |
| `/api/plugins/[name]`              | GET    | ఇన్స్టాల్ చేసిన ప్లగిన్ వివరాలను పొందండి                                  |
| `/api/plugins/[name]`              | DELETE | ప్లగిన్ను అన్ఇన్స్టాల్ చేయండి                                             |
| `/api/plugins/[name]/activate`     | POST   | సక్రియం చేయండి ( + రిజిస్టర్ హుక్స్లను లోడ్ చేయండి)                       |
| `/api/plugins/[name]/deactivate`   | POST   | డియాక్టివేట్ చేయండి (ఫైర్ `onDeactivate`, హుక్స్ రిజిస్టర్ను తీసివేయండి)  |
| `/api/plugins/[name]/config`       | GET    | ప్లగ్ఇన్ config + config స్కీమాని పొందండి                                 |
| `/api/plugins/[name]/config`       | PUT    | ప్లగిన్ కాన్ఫిగరేషన్ను నవీకరించండి (స్కీమాకు వ్యతిరేకంగా ధృవీకరించబడింది) |

`GET /api/plugins` `status` ఫిల్టర్ `installed` / `active` / `inactive` / `error` లలో ఒకదాన్ని అంగీకరిస్తుంది. చెల్లని విలువ `400` ని అందిస్తుంది.

### ఇన్స్టాల్ చేయబడిన ప్లగిన్లను జాబితా చేయండి

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### స్థానిక మార్గం నుండి ఇన్స్టాల్ చేయండి

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` తప్పనిసరిగా ఒక అయి ఉండాలి** సంపూర్ణమైన** డైరెక్టరీకి మార్గం** ప్లగిన్ మూలాల డైరెక్టరీ లోపల** : ప్లగ్ఇన్ రూట్ పక్కన `plugin-sources`, కాబట్టి డిఫాల్ట్గా `~/.omniroute/plugin-sources/`, లేదా ఆ వేరియబుల్ సెట్ చేయబడినప్పుడు `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` ( `src/lib/plugins/installSource.ts` లో`getPluginSourcesDir()` ). ముందుగా అక్కడ ప్లగిన్ని కాపీ చేయండి లేదా క్లోన్ చేయండి. మార్గంలో `..` లేదా శూన్య బైట్ ఉన్నప్పుడు, ఆ డైరెక్టరీ వెలుపల ఉన్నపుడు, సిమ్లింక్ ద్వారా దాని వెలుపల పరిష్కరించబడినప్పుడు, దాని వెలుపల లక్ష్యం ఉన్న సిమ్లింక్ని కలిగి ఉన్నప్పుడు లేదా డైరెక్టరీ ఉనికిలో లేనప్పుడు `400` తో ఇన్స్టాల్ తిరస్కరించబడుతుంది. మూలం డైరెక్టరీ తప్పనిసరిగా చెల్లుబాటు అయ్యే `plugin.json` కలిగి ఉండాలి (లేదా ఒకరి పేరెంట్ అయి ఉండాలి). విజయవంతం అయినప్పుడు, ఇన్స్టాల్ చేయబడిన ప్లగిన్ అడ్డు వరుసతో ప్రతిస్పందన `201`.

ఇతర ప్లగ్ఇన్ రూట్ల మాదిరిగా కాకుండా, లాగిన్ డిసేబుల్ చేయబడినప్పుడు కూడా దీనికి మేనేజ్మెంట్ క్రెడెన్షియల్ (డ్యాష్బోర్డ్ సెషన్ లేదా మేనేజ్-స్కోప్డ్ API కీ) అవసరం (`requireLogin=false`): కోడ్ని ఇన్స్టాల్ చేయడం అనామక చర్య కాదు. అదే `POST /api/plugins/marketplace/install` (బాడీ `{ "name": "<plugin>" }`)కి వర్తిస్తుంది.

### మార్కెట్ను బ్రౌజ్ చేయండి

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### ప్లగిన్ కాన్ఫిగరేషన్ని నవీకరించండి

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` `src/lib/plugins/manifest.ts` నుండి `validatePluginConfig()` తో ప్లగిన్ యొక్క `configSchema` (మానిఫెస్ట్లో ప్రకటించబడింది)కి వ్యతిరేకంగా బాడీని ధృవీకరిస్తుంది: ప్రతి కీ స్కీమాలో ప్రకటించబడాలి, విలువలు తప్పనిసరిగా డిక్లేర్డ్ రకానికి సరిపోలాలి, `number` ఫీల్డ్లు `min`/`max` ని గౌరవించాలి మరియు `select` ఫీల్డ్లు డిక్లేర్డ్ `enum` సరిపోలాలి. ఏదైనా ఉల్లంఘన `400` ని అందిస్తుంది మరియు ఏదీ నిల్వ చేయబడదు. `configSchema` లేదని ప్రకటించే ప్లగిన్కు కాన్ఫిగర్ చేయదగిన కీలు లేవు, కాబట్టి అభ్యర్థన `400` ("ప్లగిన్ ఏ కాన్ఫిగర్ చేయదగిన కీలను ప్రకటించదు")తో తిరస్కరించబడుతుంది.

## కాన్ఫిగరేషన్

### ప్లగిన్ డైరెక్టరీ

ప్లగిన్లు OmniRoute డేటా డైరెక్టరీ కింద ఉంటాయి:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (లేదా manifest.main సూచించే ఏదైనా)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ఆ డైరెక్టరీని
మూడు దశల్లో పరిష్కరిస్తుంది:

1. **`OMNIROUTE_PLUGINS_DIR`**, సెట్ చేసినప్పుడు — `HOME`లో ఏది ఉన్నా, యథాతథంగా ఉపయోగించబడుతుంది. ఇది
   Docker/K8s కోసం స్పష్టమైన నియంత్రణ; అక్కడ ప్లగిన్ ట్రీ సాధారణంగా కంటైనర్ హోమ్ డైరెక్టరీతో
   ఎలాంటి సంబంధం లేని పాత్లో బైండ్-మౌంట్ చేయబడుతుంది (#11827).
2. `<home>/.omniroute/plugins`, ఇక్కడ `<home>` అనేది `HOME` / `USERPROFILE`
   ఎన్విరాన్మెంట్ వేరియబుల్స్ నుండి వస్తుంది.
3. `/tmp/.omniroute/plugins`, ప్రాసెస్ ఎలాంటి హోమ్ను ఎగుమతి చేయనప్పుడు.

పరిష్కరించిన డైరెక్టరీ స్టార్టప్ సమయంలో `scanner.dir_resolved`గా ఒకసారి లాగ్ చేయబడుతుంది; అందులో
ఎంచుకోబడిన ఇన్పుట్ (`OMNIROUTE_PLUGINS_DIR`, `home`, లేదా `no-home-fallback`) పేర్కొనబడుతుంది — అందువల్ల
నిశ్శబ్దంగా 3వ దశకు చేరే ఇమేజ్, కేవలం ఖాళీ ప్లగిన్ జాబితాను నివేదించడానికి బదులుగా, ఆ విషయాన్ని తెలియజేస్తుంది.
`POST /api/plugins/scan` అక్కడ చెల్లుబాటు అయ్యే `plugin.json`ను కలిగి ఉన్న ఏ సబ్డైరెక్టరీనైనా
కనుగొని నమోదు చేస్తుంది; అదే డైరెక్టరీలోకి `pluginManager.install()` ప్లగిన్లను కాపీ చేస్తుంది,
కాబట్టి ఓవర్రైడ్ డిస్కవరీ మరియు ఇన్స్టాలేషన్ రెండింటినీ కలిపి తరలిస్తుంది.

> **`OMNIROUTE_PLUGINS_DIR` అనేది `OMNIROUTE_PLUGIN_PATH` కాదు.** రెండవది
> `omniroute` సబ్కమాండ్లను జోడించే `omniroute-cmd-*` npm ప్యాకేజీలను కనుగొనడానికి
> CLI కమాండ్-ప్లగిన్ లోడర్ (`bin/cli/plugins.mjs`) ద్వారా మాత్రమే చదవబడుతుంది — ఇక్కడ వివరించిన
> రన్టైమ్ స్కానర్పై దానికి ఎలాంటి ప్రభావం లేదు. ఆ అంశం కోసం [PLUGINS.md](./PLUGINS.md) చూడండి.

### అనుకూల మార్కెట్ప్లేస్ రిజిస్ట్రీ URL

మార్కెట్ప్లేస్ కేటలాగ్ మూలం `pluginMarketplaceUrl` సెట్టింగ్ నుండి చదవబడుతుంది
(`src/lib/plugins/marketplace.ts` అనేది `settings.pluginMarketplaceUrl`ను చదువుతుంది). దాన్ని
`http(s)` URLకు సెట్ చేసినప్పుడు, `listMarketplacePlugins()` ఆ URLను ఫెచ్ చేసి,
ఎంట్రీల టాప్-లెవల్ JSON అర్రేను లేదా `plugins` అర్రే కలిగిన ఆబ్జెక్ట్ను అంగీకరిస్తుంది;
స్ట్రింగ్ `name` లేని ఎంట్రీలు ఫిల్టర్ చేయబడతాయి. సెట్ చేయనప్పుడు (లేదా ఫెచ్
SSRF గార్డ్లో విఫలమైనప్పుడు / చెల్లని ప్రతిస్పందనను ఇచ్చినప్పుడు), అంతర్నిర్మిత సీడ్ రిజిస్ట్రీ
ఉపయోగించబడుతుంది.

డాష్బోర్డ్లోని "Marketplace" ట్యాబ్ ఈ URL కోసం ఒక ఫీల్డ్ను అందిస్తుంది (ఇది
`GET /api/settings` నుండి తిరిగి చదవబడుతుంది).

> అమలు గమనిక: డాష్బోర్డ్లోని "Save" చర్య
> `pluginMarketplaceUrl`ను `PATCH /api/settings`కు పంపుతుంది. ఇది రాస్తున్న సమయానికి,
> ఈ కీ `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`)లో ప్రకటించబడలేదు, కాబట్టి దానిపై ఆధారపడే ముందు
> మీ విడుదలలో నిల్వ కొనసాగుతుందో లేదో ధృవీకరించండి — సెట్టింగ్ల స్టోర్లో కీ ఉన్న తర్వాత
> **రీడ్** పాత్ (`getSettings()` →
> `listMarketplacePlugins()`) దానిని గౌరవిస్తుంది.

## భద్రత

### రూట్ టైర్ — లూప్బ్యాక్ మాత్రమే

ప్లగిన్లు స్పాన్డ్ చైల్డ్ ప్రాసెస్లలో కోడ్ను అమలు చేస్తాయి, కాబట్టి మొత్తం `/api/plugins` ఉపరితలం `LOCAL_ONLY` (టైర్ 1) వర్గీకరించబడుతుంది. లూప్బ్యాక్ అమలు షరతులు లేకుండా నడుస్తుంది** ముందు** ఏదైనా ప్రామాణీకరణ తనిఖీ, కాబట్టి లీక్ అయిన మేనేజ్మెంట్ టోకెన్ సొరంగం మీదుగా బాక్స్కు చేరుకోవడం ఇప్పటికీ ప్లగిన్ను ఇన్స్టాల్ చేయడం, యాక్టివేట్ చేయడం లేదా అన్ఇన్స్టాల్ చేయడం సాధ్యం కాదు. [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) మరియు హార్డ్ రూల్స్ #15 / #17 చూడండి.

### మార్కెట్ప్లేస్ రిజిస్ట్రీ SSRF గార్డ్

కస్టమ్ రిజిస్ట్రీ URL అనేది అటాకర్-ఇన్ఫ్లుయెన్సబుల్ కాన్ఫిగరేషన్, కాబట్టి దాన్ని పొందే ముందు `listMarketplacePlugins()` దానిని రెండు లేయర్ల ద్వారా రన్ చేస్తుంది:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` కాని దేనినైనా తిరస్కరిస్తుంది.
   - లిటరల్ private/loopback/link-local/ULA హోస్ట్లను తిరస్కరిస్తుంది (IPv4** మరియు** IPv6, IPv4-mapped తో సహా) కానానికల్ `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) ద్వారా.
   - పరిష్కరిస్తుంది** రెండూ** `A` మరియు `AAAA` రికార్డులు మరియు ఉంటే తిరస్కరిస్తుంది** ఏదైనా** పరిష్కరించబడిన చిరునామా ప్రైవేట్ — పబ్లిక్-హోస్ట్ పేరు → ప్రైవేట్-IP బైపాస్ను మూసివేస్తుంది.
   - **విఫలమైంది మూసివేయబడింది** : DNS రిజల్యూషన్ వైఫల్యం URL ని తిరస్కరిస్తుంది.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): పొందే సమయంలో పబ్లిక్-ఓన్లీ URL గార్డ్ని మళ్లీ వర్తింపజేస్తుంది మరియు** దారిమార్పులను బ్లాక్ చేస్తుంది** (పబ్లిక్ → ప్రైవేట్ `30x` పైవట్ లేదు).

URL ఏ పొర అయినా విఫలమైనా అభ్యర్థనను రద్దు చేయదు — మార్కెట్ప్లేస్ నిశ్శబ్దంగా అంతర్నిర్మిత సీడ్ రిజిస్ట్రీకి తిరిగి వస్తుంది మరియు హెచ్చరికను లాగ్ చేస్తుంది.

> ఈ గార్డు ప్రత్యేకంగా A + AAAA పరిష్కరించడానికి మరియు IPv4-only చెక్కు బదులుగా కానానికల్ `isPrivateHost` ఉపయోగించడానికి PR #3774 లో కఠినతరం చేయబడింది.

### ప్లగిన్ ఎగ్జిక్యూషన్ ఐసోలేషన్

> **ప్లగిన్లు డిఫాల్ట్గా శాండ్బాక్స్ చేయబడవు.** చైల్డ్ అనేది OmniRoute వినియోగదారుగా అమలు చేయబడే సాధారణ Node.js ప్రక్రియ, VM సందర్భం మరియు Node.js అనుమతి ఫ్లాగ్లు లేవు, కాబట్టి ప్లగ్ఇన్ కోడ్ వినియోగదారు చేయగలిగిన ఏదైనా ఫైల్ను చదవగలదు మరియు వ్రాయగలదు, ప్రోగ్రామ్లను అమలు చేస్తుంది మరియు నెట్వర్క్ను చేరుకుంటుంది. `requires.permissions` చైల్డ్ స్వీకరించే పర్యావరణ వేరియబుల్స్ మాత్రమే నిర్ణయిస్తుంది; ఇతర అనుమతులు అమలు చేయబడవు. ఆప్ట్-ఇన్ `PLUGIN_PERMISSION_MODEL_ENABLED` ఫీచర్ ఫ్లాగ్ (డిఫాల్ట్గా ఆఫ్) ప్రతి ప్లగ్ఇన్ను ఆ అనుమతుల నుండి నిర్మించబడిన Node.js అనుమతి మోడల్లో రన్ చేస్తుంది, `network` తప్ప Node.js పరిమితం చేయదు ( [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#%E0%B0%85%E0%B0%A8%E0%B1%81%E0%B0%AE%E0%B0%A4%E0%B0%BF-%E0%B0%B5%E0%B1%8D%E0%B0%AF%E0%B0%B5%E0%B0%B8%E0%B1%8D%E0%B0%A5) చూడండి). మీరు విశ్వసించే ప్లగిన్లను మాత్రమే ఇన్స్టాల్ చేయండి. దిగువ ప్రాసెస్ సరిహద్దు క్రాష్లు మరియు హ్యాంగ్లను కలిగి ఉంది; అది భద్రతా సరిహద్దు కాదు.

- **ప్రక్రియ ఐసోలేషన్** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ఒక ప్రత్యేక Node.js చైల్డ్ ప్రాసెస్లో ప్రతి ప్లగిన్ను స్పాన్ చేస్తుంది మరియు IPC ద్వారా కమ్యూనికేట్ చేస్తుంది. హుక్ కాల్లు `SIGTERM` → `SIGKILL` ఎస్కలేషన్తో గడువు ముగిసింది.
- **ఎన్వి అనుమతి జాబితా** — పిల్లలు అనుమతించబడిన ఎన్విరాన్మెంట్ వేరియబుల్స్ను మాత్రమే అందుకుంటారు; మానిఫెస్ట్ `env` అనుమతిని అభ్యర్థించినప్పుడు మాత్రమే విస్తృత సెట్ మంజూరు చేయబడుతుంది.
- **సోర్స్ కంటైన్మెంట్ను ఇన్స్టాల్ చేయండి** — `POST /api/plugins` ప్లగ్ఇన్ మూలాల డైరెక్టరీ నుండి మాత్రమే చదువుతుంది ("స్థానిక మార్గం నుండి ఇన్స్టాల్ చేయి" చూడండి): మార్గం `realpath` తో నియమబద్ధీకరించబడింది, ఆ డైరెక్టరీ లోపల ఖచ్చితంగా ఉండాలి మరియు దాని నుండి తప్పించుకునే ఒక సిమ్లింక్ని కలిగి ఉన్న సోర్స్ ట్రీ ఏదైనా కాపీ చేయబడే ముందు తిరస్కరించబడుతుంది.
- **మార్గం నియంత్రణ** — install/upgrade/uninstall ప్లగ్ఇన్ డైరెక్టరీ మరియు `manifest.main` పరిష్కరిస్తుంది** లోపల** ఏదైనా కాపీ లేదా రికర్సివ్ డిలీట్కు ముందు నిర్వహించబడే ప్లగ్ఇన్ రూట్ (ట్యాంపర్డ్ DB పాత్లు మరియు `manifest.main` లో `../` ట్రావర్సల్కు వ్యతిరేకంగా రక్షిస్తుంది). యాక్టివేషన్ `realpath` ద్వారా సిమ్లింక్లను పరిష్కరిస్తుంది మరియు ప్లగ్ఇన్ డైరెక్టరీ నుండి తప్పించుకునే ఎంట్రీ పాయింట్ను లోడ్ చేయడానికి నిరాకరిస్తుంది.
- **ఐచ్ఛిక సమగ్రత పిన్** — మానిఫెస్ట్ `integrity` (`sha256-<base64>`, SRI ఫార్మాట్) ఫీల్డ్ను ప్రకటించవచ్చు. ప్రస్తుతం ఉన్నప్పుడు, లోడర్ లోడ్ సమయంలో ఎంట్రీ ఫైల్ హాష్ని ధృవీకరిస్తుంది మరియు అసమతుల్యతపై సక్రియం చేయడానికి నిరాకరిస్తుంది. ఇది ఆప్ట్-ఇన్ ట్యాంపర్-డిటెక్షన్,** కాదు** భద్రతా సరిహద్దు: ఇది లోడ్ చేయబడిన ప్లగ్ఇన్ ఏమి చేయగలదో పరిమితం చేయదు.
- **హుక్స్లో క్లయింట్ ఆధారాలు లేవు** — `onRequest`, `onResponse` మరియు `onError` లకు పంపబడిన సందర్భం `authorization`, `x-api-key`, `proxy-authorization` మరియు `cookie` హెడర్లను తీసివేసింది మరియు API కీ రికార్డ్ కీ విలువను కలిగి ఉండదు ( `src/lib/plugins/hooks.ts` లో`redactPluginContext()` ).

## మానిఫెస్ట్ (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) ద్వారా ధృవీకరించబడింది:

| ఫీల్డ్             | టైప్ చేయండి  | గమనికలు                                                           |
| ------------------ | ------------ | ----------------------------------------------------------------- |
| `name`             | స్ట్రింగ్    | అవసరం; కబాబ్-కేస్ (`^[a-z0-9-]+$`), 1–100 అక్షరాలు                |
| `version`          | స్ట్రింగ్    | అవసరం; సెమ్వర్ (`MAJOR.MINOR.PATCH`)                              |
| `description`      | స్ట్రింగ్?   | ≤ 500 అక్షరాలు                                                    |
| `author`           | స్ట్రింగ్?   | ≤ 200 అక్షరాలు                                                    |
| `license`          | స్ట్రింగ్?   | `MIT` కి డిఫాల్ట్లు                                               |
| `main`             | స్ట్రింగ్?   | ఎంట్రీ ఫైల్; `index.js` కి డిఫాల్ట్లు                             |
| `source`           | enum?        | `local` \| `marketplace` ( `local` కి డిఫాల్ట్లు)                 |
| `tags`             | స్ట్రింగ్[]? | ట్యాగ్లను శోధించండి                                               |
| `requires`         | వస్తువు?     | `{ omniroute?, permissions[] }`                                   |
| `hooks`            | వస్తువు?     | బూలియన్లు ఏ ప్లగ్ఇన్ ఇంప్లిమెంట్లను హుక్స్ చేస్తుందో ప్రకటిస్తాయి |
| `skills`           | వస్తువు[]?   | ఐచ్ఛిక నైపుణ్యం నిర్వచనాలు                                        |
| `enabledByDefault` | బూలియన్?     | ఇన్స్టాల్లో ఆటో-యాక్టివేట్                                        |
| `configSchema`     | వస్తువు?     | కాన్ఫిగర్ ఫీల్డ్ల మ్యాప్ (`string`/`number`/`boolean`/`select`)   |
| `integrity`        | స్ట్రింగ్?   | ఐచ్ఛికం `sha256-<base64>` ఎంట్రీ-ఫైల్ పిన్                        |

అనుమతులు enum `network` / `file-read` / `file-write` / `env` / `exec` నుండి తీసుకోబడ్డాయి. `env` మాత్రమే రన్టైమ్ ప్రభావాన్ని కలిగి ఉంటుంది (పిల్లల కోసం కొంచెం పెద్ద పర్యావరణ-వేరియబుల్ అనుమతి జాబితా); మిగిలినవి డిక్లరేషన్లు మరియు అమలు చేయబడవు.

## జీవనచక్ర ప్రవాహం

```
ఇన్స్టాల్ (POST /api/plugins, పాత్)
  → మానిఫెస్ట్ను స్కాన్/ధృవీకరించడం → స్టేజింగ్కు కాపీ చేయడం → ప్రధాన ఫైల్ డైరెక్టరీలోనే ఉందని నిర్ధారించడం
  → ~/.omniroute/plugins/<name> లోకి అటామిక్ రీనేమ్ చేయడం → DB వరుసను చేర్చడం
  → onInstallను అమలు చేయడం → enabledByDefault అయితే: యాక్టివేట్ చేయడం

యాక్టివేట్ (POST /api/plugins/{name}/activate)
  → realpath కంటైన్మెంట్ తనిఖీ → loadPlugin() (చైల్డ్ ప్రాసెస్ను ప్రారంభించడం)
  → ప్రకటించిన హుక్స్ను నమోదు చేయడం → status = "active" → onActivateను అమలు చేయడం

డియాక్టివేట్ (POST /api/plugins/{name}/deactivate)
  → onDeactivateను అమలు చేయడం (నమోదు తొలగించే ముందు) → హుక్స్ నమోదును తొలగించడం
  → చైల్డ్ ప్రాసెస్ను నిలిపివేయడం → status = "inactive"

అన్ఇన్స్టాల్ (DELETE /api/plugins/{name})
  → యాక్టివ్గా ఉంటే డియాక్టివేట్ చేయడం → onUninstallను అమలు చేయడం
  → కంటైన్మెంట్ తనిఖీతో ప్లగిన్ డైరెక్టరీని రికర్సివ్గా తొలగించడం → DB వరుసను తొలగించడం
```

ఇన్స్టాల్ చేసిన వెర్షన్ కంటే మానిఫెస్ట్ వెర్షన్ **ఖచ్చితంగా
కొత్తది**గా ఉన్న డైరెక్టరీపై `install`ను మళ్లీ అమలు చేస్తే స్వయంచాలకంగా అప్గ్రేడ్ అవుతుంది (క్లీన్ రీఇన్స్టాల్; కాన్ఫిగరేషన్ డిఫాల్ట్లకు రీసెట్ అవుతుంది).
అదే లేదా అంతకంటే పాత వెర్షన్ తిరస్కరించబడుతుంది.

## డాష్బోర్డ్

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) వద్ద ఉన్న డాష్బోర్డ్ పేజీ రెండు ట్యాబ్లను అందిస్తుంది:

- **ఇన్స్టాల్ చేయబడింది** — వారి డిక్లేర్డ్ హుక్స్తో ఇన్స్టాల్ చేయబడిన ప్లగిన్లను జాబితా చేస్తుంది, ఒక activate/deactivate టోగుల్, అన్ఇన్స్టాల్ బటన్ మరియు "ప్లగిన్ల కోసం స్కాన్ చేయి" చర్య (`POST /api/plugins/scan`).
- **మార్కెట్ ప్లేస్** — అనుకూల రిజిస్ట్రీ URL సెట్ చేయడానికి ఫీల్డ్తో `GET /api/plugins/marketplace` నుండి కేటలాగ్ను చూపుతుంది.

OmniRoute ప్రక్రియ యొక్క పూర్తి అధికారాలతో ప్లగిన్లు నడుస్తాయని పేజీ ఎల్లప్పుడూ హెచ్చరికను చూపుతుంది.

ప్రతి ప్లగ్ఇన్ కాన్ఫిగరేషన్ పేజీ `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) వద్ద నివసిస్తుంది.
