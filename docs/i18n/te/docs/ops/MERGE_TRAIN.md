## విడుదల శాఖలో ల్యాండింగ్

ఓమ్ని-క్యూ ల్యాండింగ్లను `release/vX.Y.Z` లోకి నియంత్రిస్తుంది. PR ల్యాండింగ్ చేయడానికి ముందు డిఫాల్ట్ బ్రాంచ్లో `config/merge-queue/config.json` లో ఉన్నత-స్థాయి `mode` చదవండి. [ఓమ్ని-క్యూ](OMNI_QUEUE.md) చూడండి.

- **`shadow`** ధ్రువీకరణను అమలు చేస్తుంది మరియు ల్యాండింగ్ను మాన్యువల్ విలీనానికి వదిలివేస్తుంది. `omni-queue` దాని చివరి హెడ్లో ఆమోదించబడిన PR కి వర్తింపజేయండి. `npm run queue -- why <PR>` తో అర్హతను తనిఖీ చేయండి. `npm run queue -- history --base <branch>` లో ఆ హెడ్ కోసం తీర్పు కోసం వేచి ఉండండి. `would-land` లో కొనసాగండి. `culprit-found` లేదా `would-dequeue` లో, విలీనాన్ని పట్టుకుని, కారణాన్ని పరిష్కరించండి.
- **షాడో మినహాయింపులు.** ప్రస్తుత బేస్ టిప్కు వ్యతిరేకంగా ఆకుపచ్చ పూర్తి CI ఉన్న రైలు ప్రత్యేక క్యూ తీర్పు లేకుండా కొనసాగవచ్చు. PR హెడ్ ఇప్పటికే ప్రస్తుత బేస్ చిట్కాను కలిగి ఉన్నప్పుడు అదే మినహాయింపు వర్తిస్తుంది.
- **`live`** ల్యాండింగ్ని ట్రిగ్గర్ చేయడానికి `omni-queue` లేబుల్ని ఉపయోగిస్తుంది. క్యూ ఒక్కటే PR ని ల్యాండ్ చేస్తుంది. విలీన ఆదేశాలు మరియు ప్రత్యక్ష పుష్లను క్యూలో వదిలివేయండి.

ప్రతి ల్యాండింగ్కు యజమాని యొక్క అధికారం మరియు వర్తించే అవసరమైన తనిఖీలు అవసరం. యజమాని ల్యాండింగ్కు అధికారం ఇచ్చిన తర్వాత మాత్రమే `omni-queue` వర్తించండి. క్యూలో ఉన్న PRs రక్షిత మార్గాలను తాకడానికి కూడా ఆ PR కోసం యజమాని యొక్క `protected-approved` నిర్ణయం అవసరం.

"యాక్టివ్ రిలీజ్లో గ్రీన్ గేట్స్ అవసరం" నియమావళికి తలపై ఆకుపచ్చ `Gate / CI` మరియు `Gate / Quality` అవసరం. ఎరుపు గేట్ను దాటవేయడానికి ఎప్పుడూ `--admin` ఉపయోగించవద్దు. విడుదల ఫ్రీజ్ బ్లాక్లు స్తంభింపచేసిన శాఖలో విలీనం అవుతాయి. [కఠినమైన నియమం 21](HARD_RULES_DETAIL.md) చూడండి. మరొక సెషన్ పని చేస్తోందని పుల్ అభ్యర్థనను ఎప్పుడూ లేబుల్ చేయవద్దు, విలీనం చేయవద్దు లేదా పుష్ చేయవద్దు. [కఠినమైన నియమం 22](HARD_RULES_DETAIL.md) చూడండి.

## రైలు పుల్ అభ్యర్థన

1. ప్రస్తుత విడుదల బేస్ చిట్కా వద్ద రైలు శాఖను ప్రారంభించండి. విలీన కమిట్లను ఉపయోగించి ఖచ్చితమైన ఆమోదించబడిన సభ్య హెడ్లను ఏకీకృతం చేయండి. స్క్వాష్ మరియు రీబేస్ను నివారించడం ద్వారా వారి నిబద్ధత చరిత్రను కాపాడుకోండి.
2. రైలు శాఖ కోసం ఒక పుల్ అభ్యర్థనను తెరవండి. ప్రస్తుత ఆధార చిట్కాపై దాని స్వంత పూర్తి CI తో ఆ PR ధృవీకరించండి. ల్యాండింగ్కు ముందు బేస్ చిట్కా మరియు ఆమోదించబడిన సభ్యుల హెడ్లను మళ్లీ తనిఖీ చేయండి. ధృవీకరించబడిన అభ్యర్థి మారినప్పుడు రైలు మరియు దాని CI రిఫ్రెష్ చేయండి.
3. వర్తించే క్యూ మోడ్లో మెర్జ్ కమిట్తో రైలు PR ల్యాండ్ చేయండి. లైవ్ మోడ్లో, క్యూ యొక్క `merge-ff` ల్యాండింగ్ పద్ధతి విలీన చర్యలను భద్రపరుస్తుంది. అసలు మెంబర్ హెడ్లు రిలీజ్ బ్రాంచ్ నుండి చేరుకోవచ్చు. GitHub సభ్యుడు PRs విలీనం చేసినట్లు గుర్తు చేస్తుంది మరియు కమిట్లు వారి రచయితలను కలిగి ఉంటాయి.

ఒక పబ్లిక్ ఉదాహరణ [PR #21071](https://github.com/cheaper-inference/OmniRoute/pull/21071). ఇది 18 మంది సభ్యుల PRs కలిపి 2026-11-24న విలీన నిబద్ధతతో అడుగుపెట్టింది.

`main` నుండి తదుపరి విడుదల బ్రాంచ్కి సమకాలీకరణ కూడా విలీన కమిట్ ద్వారా వస్తుంది. తర్వాత సింక్-బ్యాక్ల కోసం `main` పూర్వీకులను సంరక్షించడం అవసరం. [వర్క్ట్రీ ఐసోలేషన్](WORKTREE_ISOLATION.md#sync-back-landings-are-merge-commits-never-squash) చూడండి.

## స్థానిక విలీనం-రైలు వాలిడేటర్

```bash
scripts/release/merge-train.sh [--plan] [--fast] <base-branch> <PR#> [<PR#>...]
```

వ్యాలిడేటర్ బేస్ మరియు PR హెడ్లను పొందుతుంది మరియు వాటిని డిస్పోజబుల్ వర్క్ట్రీలో మిళితం చేస్తుంది. ఇది ఫలిత చెట్టుపై ఒకసారి దాని పారిటీ సూట్ను అమలు చేస్తుంది. విఫలమైన హెడ్ని పొందడం లేదా విలీనం చేయడం PR ని తొలగిస్తుంది మరియు స్క్రిప్ట్ మిగిలిన PRs తో కొనసాగుతుంది.

- **`--plan`** ఎంచుకున్న మోడ్ యొక్క దశలను ప్రింట్ చేస్తుంది మరియు వర్క్ట్రీని సృష్టించకుండా లేదా రిమోట్ను సంప్రదించకుండా నిష్క్రమిస్తుంది. ఫాస్ట్ ప్లాన్ని తనిఖీ చేయడానికి దీన్ని `--fast` తో కలపండి.
- **`--fast`** సాధారణ స్టాటిక్ గేట్లను రన్ చేస్తుంది, `tests/unit/`, మరియు `npm run test:vitest` క్రింద ఎంచుకున్న మార్చబడిన `node:test` ఫైల్లు. ఫాస్ట్ మోడ్ను ఉపయోగిస్తున్నప్పుడు సేకరించిన చిట్కాపై కనీసం రోజుకు ఒకసారి పూర్తి స్థానిక ధ్రువీకరణను అమలు చేయండి.
- **పూర్తి మోడ్** పూర్తి-మాత్రమే స్టాటిక్ గేట్లను జోడిస్తుంది మరియు `npm run test:unit` మరియు `npm run test:vitest` అమలు చేస్తుంది.

బేస్ ప్రోబ్ అందుబాటులో ఉంటే, విఫలమైన స్టాటిక్ గేట్ అన్టచ్డ్ బేస్లో మళ్లీ అమలు చేయబడుతుంది. స్క్రిప్ట్ వారసత్వంగా వచ్చిన వైఫల్యాలను నివేదిస్తుంది మరియు ప్రతి గుర్తించబడిన ఉల్లంఘన లైన్ కూడా బేస్లో కనిపించినప్పుడు మరియు మొత్తం గణన పెరగనప్పుడు కొనసాగుతుంది.

| నిష్క్రమించు | అర్థం                                                                                                                                               |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`          | ప్లాన్ని ప్రింట్ చేసారు లేదా సూట్ని పూర్తి చేసారు. సూట్ సారాంశం ఏదైనా వారసత్వంగా పొందిన స్థిర వైఫల్యాలు మరియు ఎజెక్ట్ చేయబడిన PRs జాబితా చేస్తుంది. |
| `1`          | చెల్లని ఆర్గ్యుమెంట్లు, Git చెక్అవుట్ లేదు, ప్రీఫ్లైట్ విఫలమైంది లేదా PR ఎక్కలేదు.                                                                  |
| `2`          | సూట్ చెక్ విఫలమైంది మరియు వారసత్వంగా అర్హత పొందలేదు. ఆపరేటర్ బ్యాచ్ని విభజించవచ్చు, ఆక్షేపణీయ PR ఎజెక్ట్ చేయవచ్చు మరియు మళ్లీ అమలు చేయవచ్చు.        |

స్థానిక పాస్ యజమాని యొక్క డాసియర్కు మాత్రమే రోగనిర్ధారణ సాక్ష్యాలను అందిస్తుంది. ప్రతి ల్యాండింగ్కు ఇప్పటికీ యజమాని అధికారం, దాని స్వంత అవసరమైన తనిఖీలు మరియు వర్తించేటప్పుడు షాడో క్యూ తీర్పు అవసరం.

## టైరింగ్

- **ప్రతి PR.** CI మరియు నాణ్యత మార్చబడిన మార్గాల ఆధారంగా తనిఖీలను ఎంచుకోండి. కోడ్ PRs వేగవంతమైన నాణ్యత గేట్లను అమలు చేస్తుంది మరియు CI లో ప్రత్యేక యూనిట్ మరియు Vitest ఉద్యోగాలతో ప్రభావితమైన పరీక్షలు.
- **ఒక్కో క్యూ అభ్యర్థికి.** CI మరియు క్వాలిటీ కంపోజ్ చేసిన అభ్యర్థి కోసం పూర్తి ప్రొఫైల్ను దాని క్యూ రెఫరెన్స్లో అమలు చేస్తాయి.
- **ప్రతి విడుదల చిట్కా.** విడుదల-ఆకుపచ్చ దాని పాత్ ఫిల్టర్లకు సరిపోలే పుష్లపై త్వరిత హార్డ్ గేట్లను అమలు చేస్తుంది. రోజుకు మూడు షెడ్యూల్ చేసిన పరుగులు విడుదల శాఖ కోసం పూర్తి స్వీప్ను ఉపయోగిస్తాయి.
- **విడుదలకు.** పూర్తి CI మ్యాట్రిక్స్లో E2E షార్డ్లు, ప్యాకేజీ ధ్రువీకరణ, టార్బాల్ బూట్ స్మోక్ మరియు కవరేజ్ తనిఖీలు ఉంటాయి. [విడుదల చెక్లిస్ట్](RELEASE_CHECKLIST.md) చూడండి.

## `merge-train.sh` కోసం తాజా-చెక్అవుట్ ముందస్తు అవసరాలు

వర్క్ట్రీలను సృష్టించే ముందు ప్రీఫ్లైట్ నడుస్తుంది. `npm ci` తో డిపెండెన్సీలను ఇన్స్టాల్ చేయండి. `node_modules/.bin/tsc` ఎక్జిక్యూటబుల్ అని మరియు `node_modules/node_modules` లేదని నిర్ధారించండి. `node_modules/.bin/bun --version` విజయవంతమైందో లేదో తనిఖీ చేయండి.

Bun పోస్ట్ఇన్స్టాల్ దాటవేయబడితే, `(cd node_modules/bun && node install.js)` అమలు చేయండి. ప్రొవైడర్ స్థిరత్వం మరియు తెలిసిన-చిహ్న తనిఖీలు Bun ఉపయోగిస్తాయి. వాలిడేటర్ `npm run check:cycles:ratchet` నిరోధించే గేట్గా అమలు చేస్తుంది. స్వతంత్ర `npm run check:cycles` ఆదేశం సలహా.
