OmniRoute npm + Docker ఆర్టిఫాక్ట్లను ప్రచురిస్తుంది. ఈ గేట్లు ప్రొవెనెన్స్, ఇన్వెంటరీ (SBOM) మరియు CVE స్కానింగ్ను అందిస్తాయి, ఇవన్నీ OSS, రిలీజ్ వర్క్ఫ్లోలలో ప్లగ్ చేయబడ్డాయి.
**అడ్వైజరీ-ఫస్ట్** వైఖరి — అవి ఇప్పుడు నివేదిస్తాయి, 1వ గ్రీన్ రిలీజ్ తర్వాత బ్లాకింగ్కు ప్రమోట్ చేస్తాయి.

| గేట్                    | టూల్                                           | ఎక్కడ                         | బ్లాక్ చేస్తుందా?        | అవుట్పుట్                                            |
| ----------------------- | ---------------------------------------------- | ----------------------------- | ------------------------ | ---------------------------------------------------- |
| SLSA ప్రొవెనెన్స్ (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | పబ్లిష్ విఫలమైతే మాత్రమే | బ్యాడ్జ్ npmjs / `npm audit signatures`              |
| SBOM npm                | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | జనరేషన్ విఫలమైతే మాత్రమే | రిలీజ్ అసెట్ + ఆర్టిఫాక్ట్                           |
| SBOM ఇమేజ్              | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | సలహా                     | CycloneDX ఆర్టిఫాక్ట్                                |
| Trivy CVE (SARIF)       | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | సలహా                     | SARIF (HIGH+CRITICAL) → సెక్యూరిటీ ట్యాబ్            |
| Trivy CRITICAL గేట్     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **బ్లాకింగ్**            | పరిష్కరించదగిన CRITICAL పై `exit-code: '1'`          |
| osv vulnCount           | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **బ్లాకింగ్**            | `metrics.vulnCount` (దిశ:కిందికి)ని రాచెట్ చేస్తుంది |
| OpenSSF Scorecard       | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | సలహా                     | SARIF → సెక్యూరిటీ + బ్యాడ్జ్                        |

ఇమేజ్ CVE రాచెట్ `docker-publish.yml`లో **రెండు దశలను** ఉపయోగిస్తుంది: SARIF దశ (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICALని సెక్యూరిటీ ట్యాబ్లో బ్లాక్ చేయకుండా కనిపించేలా ఉంచుతుంది; _CRITICAL గేట్_ దశ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) **పరిష్కారం అందుబాటులో ఉన్న** CRITICAL CVE పై రిలీజ్ను విఫలం చేస్తుంది. `ignore-unfixed` అప్స్ట్రీమ్ ప్యాచ్ లేని బేస్-ఇమేజ్ CVE కోసం రిలీజ్ను బ్లాక్ చేయకుండా నిరోధిస్తుంది.

## ⚠️ CVE వ్యత్యాసం (osv/Trivy గేట్లను నిరోధిస్తోంది)

osv మరియు Trivy, depsను **నిరంతరం పెరుగుతూ ఉండే** CVE డేటాబేస్లతో పోలుస్తాయి. **ఎటువంటి dependenciesను మార్చని** PR కూడా, ఇప్పటికే ఉన్న depలో కొత్త CVE
వెల్లడైనందున అకస్మాత్తుగా విఫలం కావచ్చు (osv: కొలిచిన `vulnCount` > baseline; Trivy: imageలో కొత్తగా
పరిష్కరించగల CRITICAL). **ఇది నిరోధక CVE గేట్కు సంబంధించిన ఆశించిన కార్యాచరణ ప్రవర్తనే,
ఉత్పత్తిలో regression కాదు.**

కొత్తగా వెల్లడైన CVE కారణంగా osv లేదా Trivy విఫలమైనప్పుడు, పరిష్కారం:

1. **ప్రభావిత depను bump చేయండి** (ప్రాధాన్యమైనది) — `package.json`
   `overrides` (transitive deps) ద్వారా patched versionకు upgrade చేయండి లేదా patched baseపై imageను మళ్లీ build చేయండి.
2. **upstream fix లేకపోతే:**
   - **osv:** `config/quality/quality-baseline.json`లోని `metrics.vulnCount`ను మళ్లీ baseline చేయండి
     (`npm run quality:ratchet -- --update` ప్రత్యేక గేట్లను కవర్ చేయదు — సమర్థన గమనిక + tracking issueతో
     విలువను మాన్యువల్గా సవరించండి, `direction:down`).
   - **Trivy:** సమర్థన comment + tracking issueతో `.trivyignore`లో ఒక entryని
     (ఒక్కో lineకు CVE-ID) జోడించండి. patches లేని CVEలను `ignore-unfixed: true` ఇప్పటికే
     స్వయంచాలకంగా కవర్ చేస్తుంది.

అవసరమైన OSV అమలులు (`check:vuln-ratchet -- --ratchet`), scanner, report లేదా baselineను ధ్రువీకరించలేనప్పుడు
`INCOMPLETE`తో fail closed అయి exit 2తో ముగుస్తాయి.
కొలిచిన regression exit 1తో ముగుస్తుంది. Advisory అమలు ఇప్పటికీ exit 0తో `SKIP`ను నివేదించగలదు,
అయితే dependencies scanలో ఉత్తీర్ణమయ్యాయని అది నిర్ధారించదు. నిరోధక
Trivy దశకు కూడా విజయవంతమైన measurement అవసరం: అందుబాటులో లేని tools, విఫలమైన jobs
మరియు లేని image evidence, image శుభ్రంగా ఉందని ధ్రువీకరించలేవు.

## విరమించబడిన డిపెండెన్సీ ప్రమాదం

పిన్ చేసిన promptfoo డెవలప్మెంట్ సాధనాన్ని అప్గ్రేడ్ చేసిన తర్వాత, రూట్ లాక్ఫైల్లో ఇకపై `extract-zip` లేదా దానికి దారితీసే డిపెండెన్సీ ఎడ్జ్ లేదు. దీనితో #14482లో ట్రాక్ చేసిన, గతంలో ఆమోదించబడిన `promptfoo` → `@openai/codex-security` → `extract-zip` చైన్ విరమించబడింది. `tests/unit/extract-zip-14482-exposure.test.ts`లోని రిగ్రెషన్ తనిఖీలు దాని పునఃప్రవేశాన్ని తిరస్కరిస్తాయి మరియు ప్రొడక్షన్ కోడ్ నుంచి ఇంపోర్ట్లపై నిషేధాన్ని కొనసాగిస్తాయి.

ప్రస్తుత డిపెండెన్సీ మరమ్మతు, కంపాటిబిలిటీ ఓవర్రైడ్లను Azure identity యొక్క MSAL క్లయింట్కు, get-uri యొక్క FTP క్లయింట్కు మరియు OpenCode v1 SDK యొక్క Zod డిపెండెన్సీకి మాత్రమే పరిమితం చేస్తుంది. Azure టోకెన్ పొందడం మరియు FTP ద్వారా తిరిగి పొందడం నియంత్రిత ట్రాన్స్పోర్ట్లతో పరీక్షించబడ్డాయి; రెండు OpenCode ప్యాకేజీలు వాటి స్వంత బిల్డ్ మరియు టెస్ట్ సూట్లను అమలు చేస్తాయి. రిజిస్ట్రీ అడ్వైజరీ లెక్కలు ఒక నిర్దిష్ట సమయంలో తీసుకున్న కొలతలు మాత్రమే; లాక్ఫైల్ కమిట్ చేసిన తర్వాత అవి మారవచ్చు.
