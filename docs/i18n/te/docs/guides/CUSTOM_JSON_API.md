కస్టమ్ JSON API నోడ్ OpenAI లేదా Anthropic ప్రోటోకాల్ని మాట్లాడని JSON బిజినెస్ ఎండ్పాయింట్ను కలుపుతుంది. OmniRoute JSON అభ్యర్థన టెంప్లేట్ను నింపుతుంది, దానిని పూర్తి ముగింపు స్థానానికి పంపుతుంది URL, ప్రతిస్పందన మార్గం నుండి ప్రత్యుత్తరాన్ని చదివి క్లయింట్ యొక్క స్వంత ఆకృతిలో (చాట్ పూర్తిలు, ప్రతిస్పందనలు, సందేశాలు, ...) క్లయింట్కు తిరిగి పంపుతుంది.

ఇది `apiType: "custom-json"` తో OpenAI-అనుకూల నోడ్; దాని id `openai-compatible-custom-json-<suffix>` రూపాన్ని కలిగి ఉంది. డాష్బోర్డ్ ఫారమ్ ఇంకా అందుబాటులో లేదు. దిగువ ప్రొవైడర్-నోడ్ API ద్వారా ఈ నోడ్లను సృష్టించండి మరియు సవరించండి.

## నోడ్ను సృష్టించండి

`POST /api/provider-nodes` (నిర్వహణ ప్రమాణం):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` అనేది** పూర్తి** ముగింపు పాయింట్ URL. ఏదీ జోడించబడలేదు ( `/chat/completions` లేదు , `/models` లేదు ) మరియు ఇతర OpenAI-అనుకూల నోడ్ల వలె కాకుండా, డిఫాల్ట్ URL లేదు. ఇది తప్పనిసరిగా పొందుపరిచిన ఆధారాలు లేదా `#fragment` లేకుండా `http(s)` అయి ఉండాలి మరియు ఇది నోడ్ సేవ్ చేయబడినప్పుడు మరియు ప్రతి అభ్యర్థనపై ప్రతి ప్రొవైడర్ నోడ్ వలె అదే అవుట్బౌండ్ URL గార్డ్ను పాస్ చేస్తుంది.
- కనెక్షన్ కీని పంపే నోడ్ (`authType` `bearer` లేదా `api-key`, డిఫాల్ట్తో సహా) తప్పనిసరిగా `https://` ఉపయోగించాలి. సాదా `http://` అనేది లూప్బ్యాక్ హోస్ట్ (`localhost`, `127.0.0.0/8`, `::1`) లేదా `authType: "none"` తో మాత్రమే ఆమోదించబడుతుంది, ఇది కీని పంపదు. ప్రైవేట్ LAN చిరునామాలకు (`10.x`, `172.16-31.x`, `192.168.x`) మినహాయింపు లేదు: ఆ నెట్వర్క్లోని ఎవరైనా కీని చదవగలరు. అటువంటి నోడ్ను సేవ్ చేయడం `400` తో విఫలమవుతుంది మరియు ఏదైనా అభ్యర్థనను పంపే ముందు అదే సందేశంతో ప్రతి అభ్యర్థనపై ఇంతకు ముందు నిల్వ చేయబడిన నోడ్ మూసివేయబడుతుంది. LAN పై కీడ్ ఎండ్ పాయింట్ కోసం, దానిని TLS వెనుక ఉంచండి (ఉదాహరణకు రివర్స్ ప్రాక్సీ).
- `customJson` Zod తో ధృవీకరించబడింది; తెలియని కీలు తిరస్కరించబడ్డాయి. ప్రతి ఫీల్డ్ ఐచ్ఛికం:

| ఫీల్డ్            | విలువలు                                          | డిఫాల్ట్                                               |
| ----------------- | ------------------------------------------------ | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                           | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                      | `bearer`                                               |
| `authHeader`      | హెడర్ పేరు `api-key` ఉన్నప్పుడు ఉపయోగించబడుతుంది | `X-API-Key`                                            |
| `requestTemplate` | JSON వస్తువు (≤ 64 KB, లోతు ≤ 32)                | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | ఫీల్డ్ పాత్, లేదా మొత్తం శరీరం కోసం `$`          | `choices[0].message.content`                           |

- రహస్యం కనెక్షన్ యొక్క API కీలో ఉంటుంది, టెంప్లేట్లో ఎప్పుడూ ఉండదు. `bearer` `Authorization: Bearer <key>` ని పంపుతుంది; `api-key` `<authHeader>: <key>` ని పంపుతుంది. auth హెడర్ `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` లేదా హాప్-బై-హాప్ హెడర్ కాకూడదు. `none` తో, కనెక్షన్లకు కీ అవసరం లేదు.
- అదనపు స్టాటిక్ హెడర్లు నోడ్ యొక్క సాధారణ `customHeaders` ఉపయోగిస్తాయి (ప్రతి ఇతర అనుకూల నోడ్ వలె అదే ధ్రువీకరణ; auth హెడర్లు అక్కడ అనుమతించబడవు).

`PUT /api/provider-nodes/<id>` అదే `customJson` అంగీకరిస్తుంది మరియు నోడ్ యొక్క ప్రతి ఇప్పటికే ఉన్న కనెక్షన్లో `baseUrl` మరియు configని తిరిగి వ్రాస్తుంది. `customJson` ని వదిలివేయడం నిల్వ చేయబడిన కాన్ఫిగరేషన్ను ఉంచుతుంది; `apiType` `chat` లేదా `responses` కి మార్చడం వలన అది నోడ్ మరియు దాని కనెక్షన్ల నుండి తీసివేయబడుతుంది.

తర్వాత నోడ్కి సాధారణ (నోడ్ ఐడితో`POST /api/providers` ) కనెక్షన్ని జోడించి, `<prefix>/<model>` అభ్యర్థించండి, ఉదాహరణకు `biz/assistant-v1`. ఎండ్పాయింట్ మోడల్ జాబితాను బహిర్గతం చేయదు, కాబట్టి మోడల్ ఐడిలను చేతితో జోడించండి.

## టెంప్లేట్లను అభ్యర్థించండి

టెంప్లేట్లు సాదా JSON. స్ట్రింగ్ విలువ `{{placeholder}}` గుర్తులను కలిగి ఉండవచ్చు; ఏదీ మూల్యాంకనం చేయబడదు లేదా అమలు చేయబడదు మరియు ఆబ్జెక్ట్ కీలు ఎప్పుడూ ప్రత్యామ్నాయం చేయబడవు.

| ప్లేస్హోల్డర్        | విలువ                                                                      |
| -------------------- | -------------------------------------------------------------------------- |
| `{{prompt}}`         | తాజా వినియోగదారు సందేశం యొక్క వచనం (వచన భాగాలు కొత్త లైన్లతో జతచేయబడ్డాయి) |
| `{{messages}}`       | OpenAI చాట్ ఆకృతిలో సంభాషణ                                                 |
| `{{model}}`          | ప్రొవైడర్ ప్రిఫిక్స్ లేకుండా అభ్యర్థించిన మోడల్ id                         |
| `{{stream}}`         | ఎల్లప్పుడూ `false` — ఒక JSON డాక్యుమెంట్తో ఎండ్ పాయింట్ సమాధానాలు          |
| `{{request.<path>}}` | అనువదించబడిన (OpenAI చాట్ ఫార్మాట్) అభ్యర్థన యొక్క ఫీల్డ్                  |

- సరిగ్గా ఒక ప్లేస్హోల్డర్ ఉన్న విలువ దాని JSON రకాన్ని ఉంచుతుంది (`"{{messages}}"` శ్రేణి అవుతుంది); పొడవైన స్ట్రింగ్ లోపల ప్లేస్హోల్డర్ టెక్స్ట్గా చొప్పించబడింది.
- అసంపూర్తిగా ఉన్న పేలోడ్ను పంపడానికి బదులుగా HTTP 400తో అభ్యర్థనను ఏదీ పరిష్కరించని ప్లేస్హోల్డర్ విఫలమవుతుంది.
- మార్గాలు డాట్ సంజ్ఞామానం మరియు సంఖ్యా సూచికలను (`data.items[0].text`) ఉపయోగిస్తాయి. `__proto__`, `prototype` మరియు `constructor` కీలు మరియు పాత్లలో తిరస్కరించబడ్డాయి.

## ప్రతిస్పందనలు

`responsePath` వద్ద ఉన్న విలువ సహాయక ప్రత్యుత్తరం అవుతుంది: స్ట్రింగ్స్ గుండా వెళతాయి, ఇతర JSON విలువలు క్రమీకరించబడతాయి. తప్పిపోయిన లేదా `null` ఫీల్డ్ లేదా JSON కాని శరీరం, HTTP 502ని అందిస్తుంది. అప్స్ట్రీమ్ ఎర్రర్ స్టేటస్లు పాస్ చేయబడ్డాయి. స్ట్రీమింగ్ క్లయింట్ల కోసం OmniRoute మొత్తం JSON ప్రతిస్పందన కోసం వేచి ఉండి, ఆపై దాన్ని ఒక కంటెంట్ భాగంతో పాటు ముగింపు భాగం వలె విడుదల చేస్తుంది; ఇది టోకెన్ స్ట్రీమింగ్ కాదు. టూల్ కాల్లు మరియు వినియోగ ఫీల్డ్లు మ్యాప్ చేయబడలేదు.

## ఎప్పుడూ రీప్లే చేయలేదు

వ్యాపార అభ్యర్థన విఫలమైనప్పుడు కూడా దుష్ప్రభావాలను కలిగిస్తుంది. OmniRoute దీన్ని ఒకసారి పంపుతుంది:

- రవాణా పునఃప్రయత్నం లేదు మరియు దారి మళ్లింపు లేదు;
- మరొక కనెక్షన్పై మళ్లీ ప్రయత్నించవద్దు (ఖాతా ఫాల్బ్యాక్) — వైఫల్యం ఉన్నట్లుగా అందించబడుతుంది మరియు కనెక్షన్ చల్లబడదు;
- ఖాళీ లేదా విఫలమైన ప్రత్యుత్తరానికి కూడా తదుపరి కాంబో లక్ష్యానికి ఫాల్బ్యాక్ లేదు.

ప్రత్యేక క్లయింట్ అభ్యర్థనలు మరియు అనేక మోడళ్లను స్పష్టంగా పిలిచే ఫ్యూజన్ ప్యానెల్లు ఇప్పటికీ స్వతంత్రంగా ఎండ్పాయింట్ను అమలు చేస్తాయి.

## నోడ్ని పరీక్షిస్తోంది

కనెక్షన్, కనెక్షన్ని సేవ్ చేస్తోంది** పరీక్ష** బటన్ మరియు నేపథ్య ఆరోగ్య తనిఖీలు ఎండ్పాయింట్కి కాల్ చేయవు: అవి నిల్వ చేయబడిన కాన్ఫిగరేషన్ను మాత్రమే ధృవీకరిస్తాయి మరియు కనెక్షన్ ధృవీకరించబడలేదని నివేదిస్తుంది.

`"apiType": "custom-json"` మరియు నోడ్ ఫీల్డ్లతో`POST /api/provider-nodes/validate` (`baseUrl`, `apiKey`, `customJson`, ఐచ్ఛిక `customHeaders` మరియు `modelId`) ఖచ్చితంగా ఒక నిజమైన అభ్యర్థనను పంపుతుంది, `ping` తాజా వినియోగదారు వచనంగా పంపుతుంది. ఇది `{ "valid": true }` లేదా అప్స్ట్రీమ్ స్థితికి సమాధానం ఇస్తుంది (ఎప్పుడూ అప్స్ట్రీమ్ బాడీ కాదు).

## నిల్వ

కాన్ఫిగర్ `provider_nodes.custom_json_config_json` (మైగ్రేషన్ `240_provider_node_custom_json_config.sql`)లో నిల్వ చేయబడుతుంది మరియు ప్రతి కనెక్షన్ యొక్క `providerSpecificData.customJson` కి కాపీ చేయబడుతుంది.
