## ఇది ఏమిటి

OmniRoute 376 ప్రొవైడర్లను నమోదు చేస్తుంది, వాటిలో **free/no-auth** గా గుర్తించబడిన 155 క్యాటలాగ్ ఎంట్రీలు ఉన్నాయి
(no-auth,
free-tier OAuth, లేదా free-tier API key —
[ఫ్రీ టయర్స్ గైడ్](../getting-started/FREE-TIERS-GUIDE.md) మరియు పూర్తి
[ఫ్రీ టయర్స్ డైరెక్టరీ](../reference/FREE_TIERS.md) చూడండి). ఇక్కడ ఉన్న ఇబ్బంది: ఫ్రీ ప్రొవైడర్ల మోడల్
నాణ్యతలో చాలా ఎక్కువ తేడా ఉంటుంది. ఫ్రంటియర్ మోడల్ను అందించే no-auth ప్రొవైడర్,
చిన్న లెగసీ మోడల్ను అందించే దాని కంటే చాలా ఎక్కువ ఉపయోగకరంగా ఉంటుంది.

**Free Provider Rankings** ప్రతి ఫ్రీ ప్రొవైడర్ యొక్క క్యాటలాగ్ను
**Arena AI leaderboard** నుండి వచ్చే **క్రౌడ్-సోర్స్డ్ నాణ్యత స్కోర్లతో**
(మానవ-అభిరుచి ELO, LMArena chatbot arena వెనుక ఉన్న అదే భావన) జతచేయడం ద్వారా
"**ఏ ఫ్రీ ప్రొవైడర్ నాకు ఉత్తమ మోడల్ను ఇస్తుంది?**" అనే ప్రశ్నకు సమాధానం ఇస్తుంది.
అప్పుడు ప్రొవైడర్లు వారి **ఉత్తమ ఫ్రీ మోడల్** యొక్క బలం ఆధారంగా ర్యాంక్ చేయబడతారు.

ఈ ర్యాంకింగ్ మూడు వాస్తవ మూలాల నుండి లెక్కించబడుతుంది:

1. ఫ్రీ-ప్రొవైడర్ జాబితాలు — `NOAUTH_PROVIDERS`, అలాగే `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` ఎంట్రీలలో `hasFree` గా ఫ్లాగ్ చేయబడినవి
   (`src/shared/constants/providers.ts`).
2. ప్రొవైడర్ రిజిస్ట్రీ నుండి ప్రతి ప్రొవైడర్ యొక్క మోడల్ క్యాటలాగ్
   (`open-sse/config/providerRegistry.ts`).
3. Arena ELO sync engine (`src/lib/arenaEloSync.ts`) ద్వారా `model_intelligence` DB టేబుల్లో
   నిల్వ చేయబడిన ELO-డిరైవ్డ్ task-fit స్కోర్లు.

ఈ జాయిన్ లాజిక్ `src/lib/freeProviderRankings.ts` లో ఉంది.

## ఎలా యాక్సెస్ చేయాలి

### డ్యాష్బోర్డ్ పేజీ

డ్యాష్బోర్డ్ను తెరిచి **ఖర్చులు → ఉచిత ప్రొవైడర్ ర్యాంకింగ్లు**కు వెళ్లండి లేదా నేరుగా
దీనికి నావిగేట్ చేయండి:

```
/dashboard/free-provider-rankings
```

ఈ పేజీ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) కింది వాటిని చూపుతుంది:

- అత్యుత్తమంగా ర్యాంక్ పొందిన ఉచిత ప్రొవైడర్ల **టాప్-3 పోడియం** (🥇 🥈 🥉).
- **ర్యాంక్**, **ప్రొవైడర్**, **అగ్ర మోడల్**, **స్కోర్**, **సగటు స్కోర్**, **మోడల్లు**,
  **రకం** నిలువు వరుసలతో కూడిన పూర్తి **ర్యాంకింగ్ పట్టిక**.
- **వర్గ ఫిల్టర్ బటన్లు**: _అన్ని వర్గాలు_, _డిఫాల్ట్_, _కోడింగ్_, _సమీక్ష_,
  _డాక్యుమెంటేషన్_, _డీబగ్గింగ్_.

ప్రతి ప్రొవైడర్ యొక్క **రకం** బ్యాడ్జ్, అది ఏ విధంగా ఉచితమో తెలియజేస్తుంది:

| బ్యాడ్జ్ | అర్థం                                         |
| -------- | --------------------------------------------- |
| `NOAUTH` | ఎల్లప్పుడూ ఉచితం, క్రెడెన్షియల్స్ అవసరం లేదు  |
| `OAUTH`  | ఉచిత టైర్ (`hasFree`) కలిగిన OAuth ప్రొవైడర్  |
| `APIKEY` | ఉచిత టైర్ (`hasFree`) కలిగిన API-కీ ప్రొవైడర్ |

అంతర్గత విలువ శాతాన్ని కాకుండా సాపేక్ష ర్యాంకింగ్ నాణ్యతను సూచిస్తుంది కాబట్టి, స్కోర్లు
ముడి సంఖ్యలకు బదులుగా మనుషులు సులభంగా అర్థం చేసుకోగల లేబుల్ల రూపంలో (ఉదా. _అత్యున్నతం_,
_అద్భుతం_, _చాలా బాగుంది_, _బాగుంది_, _సగటు_) చూపబడతాయి.

### API ఎండ్పాయింట్

ఈ పేజీకి పబ్లిక్ రీడ్ ఎండ్పాయింట్
(`src/app/api/free-provider-rankings/route.ts`) మద్దతు ఇస్తుంది:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

క్వెరీ పారామీటర్లు (Zodతో ధృవీకరించబడతాయి):

| పారామ్     | రకం    | డిఫాల్ట్   | గమనికలు                                                                                                          |
| ---------- | ------ | ---------- | ---------------------------------------------------------------------------------------------------------------- |
| `category` | string | (ఏదీ లేదు) | `default`, `coding`, `review`, `documentation`, `debugging`లలో ఒకటి. సంయుక్త ర్యాంకింగ్ కోసం దీన్ని వదిలివేయండి. |
| `limit`    | number | `50`       | `1–100` పరిధికి పరిమితం చేయబడుతుంది.                                                                             |

ప్రతిస్పందన నిర్మాణం:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` అనేది అసలు Arena ELO విలువ; `score` అనేది సాధారణీకరించిన పని-అనుకూలత విలువ
(కింద చూడండి). స్కోర్ చేసిన మోడల్లు లేని ప్రొవైడర్లు ప్రతిస్పందన నుంచి తొలగించబడతారు.

## స్కోర్లు ఎలా పనిచేస్తాయి

### మూలం: Arena AI లీడర్బోర్డ్

Arena ELO సింక్ ఇంజిన్ (`src/lib/arenaEloSync.ts`) Arena AI లీడర్బోర్డ్ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) నుండి రెండు లీడర్బోర్డ్లను — `text`
మరియు `code` — పొందుతుంది. ఆ API ఉపయోగించదగిన బోర్డును తిరిగి ఇవ్వనప్పుడు, ఇంజిన్ Hugging Face
datasets-serverలోని అధికారిక `lmarena-ai/leaderboard-dataset`కు ఫాల్బ్యాక్ అవుతుంది
(`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`, `coding` → `code`);
`GET /api/intelligence/sync` `activeSource`, `lastError` మరియు `lastFailedAt`ను నివేదిస్తుంది.
ప్రతి లీడర్బోర్డ్ ఎంట్రీ మోడల్ పేరు, విక్రేత, ELO `score`, నమ్మక విరామం (confidence interval)
మరియు ఓటు సంఖ్యను కలిగి ఉంటుంది.

లీడర్బోర్డ్ వర్గాలు OmniRoute టాస్క్ వర్గాలకు మ్యాప్ అవుతాయి:

| Arena లీడర్బోర్డ్ | OmniRoute టాస్క్ వర్గాలు                          |
| ----------------- | ------------------------------------------------- |
| `text`            | `default`, `review`, `documentation`, `debugging` |
| `code`            | `coding`                                          |

### నార్మలైజేషన్ (టాస్క్-ఫిట్ స్కోరు)

ముడి ELO స్కోర్లు ప్రతి లీడర్బోర్డ్ కోసం **`[0.4, 0.98]` పరిధిలోని టాస్క్-ఫిట్ విలువగా**
నార్మలైజ్ చేయబడతాయి:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

ఈ స్కోరు ఎప్పుడూ `0` లేదా `1`కు చేరదు, వినియోగదారు ఓవర్రైడ్ల కోసం వెసులుబాటును వదిలివేస్తుంది.
ఇది API ప్రతిస్పందనలో మీరు చూసే `score` ఫీల్డ్ మరియు డ్యాష్బోర్డ్లో చూపించే లేబుల్.

### నమ్మకం (Confidence)

ప్రతి ఎంట్రీ Arena ఓటు సంఖ్య ఆధారంగా నమ్మకం స్థాయిని పొందుతుంది:

| నమ్మకం   | ఓట్లు   |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### నిల్వ మరియు తాజాతనం

నార్మలైజ్ చేయబడిన ఎంట్రీలు `source = "arena_elo"`తో `model_intelligence` DB టేబుల్లో
వ్రాయబడతాయి (`src/lib/db/modelIntelligence.ts`). ఎంట్రీలు **7 రోజుల తర్వాత గడువు ముగుస్తాయి**,
కాబట్టి సింక్ చేయడం ఆపివేసిన ప్రొవైడర్ పాత డేటాను అందించడానికి బదులు చివరికి జాబితా నుండి
తొలగిపోతుంది.

సింక్ **డిఫాల్ట్గా ఆన్లో** నడుస్తుంది:

- ఇది సర్వర్ ప్రారంభంలో ఒకసారి నడుస్తుంది, తర్వాత ఆవర్తన టైమర్పై నడుస్తుంది
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` నుండి వైర్ చేయబడింది).
- ఇది **నాన్-బ్లాకింగ్ మరియు ఎప్పుడూ ఫేటల్ కాదు** — అప్స్ట్రీమ్ ఫెచ్ విఫలమైతే, OmniRoute
  నడుస్తూనే ఉంటుంది మరియు ర్యాంకింగ్లు కేవలం చివరి మంచి డేటాను (లేదా ఖాళీ స్థితిని) చూపిస్తాయి.

రెండు ఎన్విరాన్మెంట్ వేరియబుల్స్ దీన్ని నియంత్రిస్తాయి
([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)లో డాక్యుమెంట్ చేయబడ్డాయి):

| వేరియబుల్                 | డిఫాల్ట్      | ఉద్దేశ్యం                                                         |
| ------------------------- | ------------- | ----------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | అవుట్బౌండ్ సింక్ నుండి మినహాయించుకోవడానికి `false`గా సెట్ చేయండి. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | సింక్ విరామం, సెకన్లలో.                                           |

### మాన్యువల్ సింక్ / స్థితి / క్లియర్

ఆపరేటర్ల కోసం, ప్రామాణీకరించబడిన మేనేజ్మెంట్ ఎండ్పాయింట్ మాన్యువల్ నియంత్రణను అందిస్తుంది
(`src/app/api/intelligence/sync/route.ts` — మేనేజ్మెంట్ ఆథ్ అవసరం):

```
GET    /api/intelligence/sync          # ప్రస్తుత సింక్ స్థితి (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # మాన్యువల్ సింక్ను ట్రిగర్ చేయండి; body: { "dryRun": true } వ్రాయకుండా ప్రివ్యూ చేయడానికి
DELETE /api/intelligence/sync          # సింక్ చేయబడిన అన్ని arena_elo ఇంటెలిజెన్స్ ఎంట్రీలను క్లియర్ చేయండి
```

ర్యాంకింగ్ పేజీ ఖాళీగా ఉంటే, మాన్యువల్ `POST /api/intelligence/sync` (లేదా కేవలం
సర్వర్ను రీస్టార్ట్ చేయడం) దాన్ని మళ్లీ నింపుతుంది.

### మోడళ్లను లీడర్బోర్డ్తో సరిపోల్చడం

రిజిస్ట్రీ మోడల్ IDలు మరియు Arena మోడల్ పేర్లు ఎల్లప్పుడూ ఖచ్చితంగా సరిపోలవు. ర్యాంకింగ్
సరళమైన సరిపోలికను ఉపయోగిస్తుంది (`src/lib/freeProviderRankings.ts`లోని
`findMatchingIntelligence`):

1. నార్మలైజ్ చేయబడిన మోడల్ IDపై ఖచ్చితమైన సరిపోలిక.
2. చివరి వెర్షన్ సఫిక్స్ను తీసివేసిన తర్వాత సరిపోలిక (ఉదా. `kimi-k2.6` → `kimi-k2`).
3. ప్రిఫిక్స్ సరిపోలిక (లీడర్బోర్డ్ మోడల్ పేరు రిజిస్ట్రీ ID యొక్క ప్రిఫిక్స్).

సింక్ వైపున, తెలిసిన విక్రేత ప్రిఫిక్స్లు (`anthropic/`, `openai/`, `google/`, …)
తీసివేయబడతాయి మరియు చిన్న అలియాస్ మ్యాప్ కెనానికల్ పేర్లను OmniRoute అంతర్గతంగా ఉపయోగించే
వేరియంట్లుగా విస్తరిస్తుంది, తద్వారా మోడళ్లు ఏ పేరు కింద అయినా కనుగొనగలవు.

### ప్రొవైడర్ ఎలా ర్యాంక్ చేయబడతారు

ప్రతి ఉచిత ప్రొవైడర్ కోసం, ఇంజిన్ దాని కాటలాగ్లోని ప్రతి మోడల్కు స్కోరు ఇస్తుంది, తర్వాత:

- **టాప్ మోడల్** = ప్రొవైడర్ యొక్క అత్యధిక స్కోరు పొందిన మోడల్.
- **సగటు స్కోరు** = ఆ ప్రొవైడర్ యొక్క స్కోరు పొందిన అన్ని మోడళ్ల సగటు స్కోరు.
- **మోడళ్లు** = ప్రొవైడర్ మోడళ్లలో ఎన్నికి Arena స్కోరు ఉంది.

ప్రొవైడర్లు ముందుగా **టాప్-మోడల్ స్కోరు** ప్రకారం, తర్వాత సగటు స్కోరు ప్రకారం
క్రమబద్ధీకరించబడతారు. ఇది కనీసం ఒక బలమైన ఉచిత మోడల్ను అందించే ప్రొవైడర్కు
ప్రయోజనం చేకూరుస్తుంది.

## ఉచిత ప్రొవైడర్లను ఎంచుకోవడానికి దీన్ని ఉపయోగించడం

1. **సరైన వర్గాన్ని ఎంచుకోండి.** ఏజెంటిక్/కోడ్ వర్క్లోడ్ల కోసం **Coding** ఫిల్టర్ను ఉపయోగించండి లేదా
   సాధారణ చాట్ కోసం **All Categories** / **Default**లోనే ఉంచండి. ప్రతి లీడర్బోర్డ్లో దాని అగ్ర మోడల్ వేర్వేరుగా ఉండటం వల్ల,
   ఒకే ప్రొవైడర్కు వర్గాలవారీగా వేర్వేరు ర్యాంకులు రావచ్చు.
2. **ఒకేసారి చేసే సెటప్ల కోసం అగ్రస్థానాల్లో ఉన్నవాటికి ప్రాధాన్యం ఇవ్వండి.** మీరు ఒకటి లేదా రెండు ఉచిత
   ప్రొవైడర్లను మాత్రమే కనెక్ట్ చేయాలనుకుంటే, మీ వర్గంలో అగ్ర ర్యాంక్లో ఉన్నవాటితో ప్రారంభించండి.
3. **Type బ్యాడ్జ్ను తనిఖీ చేయండి.** `NOAUTH` ప్రొవైడర్లను అత్యంత వేగంగా కనెక్ట్ చేయవచ్చు
   (క్రెడెన్షియల్స్ అవసరం లేదు). `OAUTH` / `APIKEY` ఉచిత టియర్లకు త్వరిత సైన్-అప్ అవసరం, కానీ అవి తరచుగా
   మరింత శక్తివంతమైన మోడళ్లను అందుబాటులో ఉంచుతాయి. కనెక్షన్ దశల కోసం
   [ఉచిత టియర్ల గైడ్](../getting-started/FREE-TIERS-GUIDE.md) చూడండి.
4. **అనేక ప్రొవైడర్లను కనెక్ట్ చేసి, Auto-Comboను నిర్ణయించనివ్వండి.** ఈ పేజీకి శక్తినిచ్చే అదే Arena ELO డేటా,
   Auto-Combo స్కోరింగ్ ఇంజిన్లోని **టాస్క్-ఫిట్నెస్ ఫ్యాక్టర్**కు కూడా డేటాను అందిస్తుంది
   (`open-sse/services/autoCombo/taskFitness.ts`, పరిష్కార క్రమం:
   `user_override → arena_elo → models_dev_tier → static table`). కాబట్టి, అగ్ర ఉచిత ప్రొవైడర్లను కనెక్ట్ చేసిన తర్వాత,
   `model: "auto"` (ఉదా. `auto/coding`)తో రూటింగ్ చేయడం ప్రతి అభ్యర్థనకు
   అధిక-నాణ్యత గల ఉచిత మోడళ్లకు స్వయంచాలకంగా ప్రాధాన్యం ఇస్తుంది. పూర్తి 16-ఫ్యాక్టర్ స్కోరింగ్ కోసం
   [Auto-Combo](../routing/AUTO-COMBO.md) చూడండి.
