OmniRouteను OpenAI-అనుకూల బ్యాకెండ్గా ఉపయోగించేలా Codex CLIను కాన్ఫిగర్ చేయడానికి పూర్తి మార్గదర్శిని.

---

> **TOML మాత్రమే సమర్థవంతమైన ఫార్మాట్.** ఆధునిక Codex ప్రత్యేకంగా
> `~/.codex/config.toml`ను మాత్రమే చదువుతుంది (codex-cli 0.147.0తో ధృవీకరించబడింది:
> `codex --help` ప్రకారం `-c/--config` ఓవర్రైడ్లు "`~/.codex/config.toml` నుంచి
> లోడ్ చేయబడతాయి"). పాత `~/.codex/config.yaml` లెగసీ npm CLIకి చెందినది,
> కాబట్టి అది ఎలాంటి హెచ్చరిక లేకుండా విస్మరించబడుతుంది. డ్యాష్బోర్డ్ జనరేటర్
> (`/api/cli-tools/apply`, సాధనం `codex`) కన్జర్వేటివ్ మెర్జ్తో TOMLను రాస్తుంది —
> ఇప్పటికే ఉన్న కీలు మరియు ఇతర ప్రొవైడర్ బ్లాక్లు భద్రపరచబడతాయి, API కీ
> `OMNIROUTE_API_KEY`లోనే ఉంటుంది (ఫైల్లో ఎప్పుడూ ఉండదు), అలాగే మిగిలిపోయిన లెగసీ
> `config.yaml`ను మార్చకుండా, దాని గురించి మైగ్రేషన్ గమనికగా నివేదిస్తుంది.

## నేరుగా పేస్ట్ చేయడానికి సిద్ధంగా ఉన్న config.toml

`<YOUR_HOST>` మరియు `<YOUR_KEY>`లను మీ విలువలతో భర్తీ చేయండి:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # ప్రతి సాధన కాల్కు చరిత్ర నిల్వ పరిమితి

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc లేదా ~/.zshrc — అసలు కీ విలువ, config.tomlలో ఎప్పుడూ ఉంచవద్దు
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: ChatGPT యాప్లో బండిల్ చేయబడిన Codex

మీరు ChatGPT డెస్క్టాప్ యాప్ ద్వారా Codexను ఇన్స్టాల్ చేసి ఉంటే, `codex` బైనరీ
యాప్ బండిల్లో మాత్రమే ఉండవచ్చు మరియు ఇంకా మీ షెల్ `PATH`లో ఉండకపోవచ్చు. రిసోర్సెస్
డైరెక్టరీని మీ షెల్ స్టార్టప్ ఫైల్కు జోడించండి:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

కొత్త షెల్ను తెరిచి, ఆపై ధృవీకరించండి:

```bash
command -v codex
codex --version
```

### ప్రామాణీకరణ అవసరం లేని స్థానిక OmniRoute: ప్లేస్హోల్డర్ కీ సరిపోతుంది

మొదటి అభ్యర్థన CLI నుంచి బయటకు వెళ్లడానికి **ముందే**, `env_key` ద్వారా సూచించబడిన
ఎన్విరాన్మెంట్ వేరియబుల్ ఉందో లేదో Codex ధృవీకరిస్తుంది. మీ **స్థానిక** OmniRoute
ఇన్స్టాన్స్కు ప్రామాణీకరణ అవసరం లేకపోతే, ఖాళీ కాని ఏ ప్లేస్హోల్డర్ అయినా పనిచేస్తుంది:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

మీ OmniRoute సర్వర్ రక్షించబడి ఉంటే లేదా రిమోట్లో ఉంటే, దానికి బదులుగా నిజమైన కీని ఉపయోగించండి.

> **సాధారణ హోస్ట్ ఎంపికలు**
>
> | యాక్సెస్          | URL                           |
> | ----------------- | ----------------------------- |
> | స్థానిక నెట్వర్క్ | `http://192.168.0.1:20128/v1` |
> | Tailscale         | `http://100.x.x.x:20128/v1`   |
> | లూప్బ్యాక్        | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — ఇది అన్ని మోడళ్లకూ ఎందుకు పనిచేస్తుంది

Codex CLI ఫిబ్రవరి 2026లో `wire_api = "chat"` (Chat Completions)ను డిప్రికేట్ చేసింది మరియు ఇప్పుడు `wire_api = "responses"` (OpenAI Responses API)ను **తప్పనిసరిగా అవసరం చేస్తుంది**. v0.138 నుంచి `wire_api = "chat"`ను సెట్ చేస్తే స్టార్టప్ సమయంలో వెంటనే క్రాష్ అవుతుంది.

GLM మరియు Kimiతో సహా అనేక ప్రొవైడర్లు ఇప్పటికీ Chat Completions ఎండ్పాయింట్ను మాత్రమే అందిస్తున్నాయి. DeepSeek V4 ఇప్పుడు స్థానిక Responses APIతో పాటు Anthropic-అనుకూల ఎండ్పాయింట్ను కూడా అందిస్తోంది; OmniRoute డిఫాల్ట్గా Responsesను ఉపయోగిస్తుంది మరియు ప్రతి DeepSeek కనెక్షన్కు Anthropic అనుకూలతను ఎంచుకునే వీలు కల్పిస్తుంది.

**OmniRoute దీన్ని పారదర్శకంగా పరిష్కరిస్తుంది:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute ప్రొవైడర్ యొక్క స్థానిక ప్రోటోకాల్ను ఎంచుకుని, అవసరమైనప్పుడు అనువదిస్తుంది
    → POST /responses (DeepSeek V4) లేదా /chat/completions (Mistral / GLM / Kimi / ఇతరాలు)
```

OmniRouteను ఉపయోగిస్తున్నప్పుడు మీకు ఎప్పుడూ ప్రత్యేక ట్రాన్స్లేషన్ ప్రాక్సీ అవసరం లేదు. **అన్ని మోడళ్లు `wire_api = "responses"`ను ఉపయోగిస్తాయి** — మిగతాదంతా OmniRoute నిర్వహిస్తుంది.

> **`wire_api` డిఫాల్ట్ విలువ** — ఈ ఫీల్డ్ డిఫాల్ట్గా `"responses"`ను ఉపయోగిస్తుంది మరియు దీన్ని `config.toml` నుంచి పూర్తిగా తొలగించవచ్చు. మీ ఉద్దేశాన్ని డాక్యుమెంట్ చేయాలనుకున్నప్పుడు మాత్రమే దీన్ని స్పష్టంగా సెట్ చేయండి.

## కాంటెక్స్ట్ విండో మరియు కాంపాక్షన్

### టోకెన్ కాన్ఫిగరేషన్ ఫీల్డ్లు

| ఫీల్డ్                           | వివరణ                                                                                                                                                                                   |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | యాక్టివ్ మోడల్కు మొత్తం టోకెన్ బడ్జెట్. దీన్ని మోడల్ ప్రకటించిన పరిమితికి సెట్ చేయండి.                                                                                                  |
| `model_auto_compact_token_limit` | ఆటోమేటిక్ హిస్టరీ కాంపాక్షన్ను ట్రిగ్గర్ చేసే థ్రెషోల్డ్. **గరిష్ఠం: `model_context_window`లో 90%** — 90% కంటే ఎక్కువ విలువలు ఎలాంటి సూచన లేకుండా విస్మరించబడతాయి.                      |
| `tool_output_token_limit`        | ప్రతి టూల్ కాల్ అవుట్పుట్కు హిస్టరీలో నిల్వ చేసే టోకెన్ల పరిమితి. ఒకే పెద్ద టూల్ రెస్పాన్స్ విండోను నింపకుండా నిరోధిస్తుంది. **ఇది గరిష్ఠ అవుట్పుట్ కాదు** — ఇది హిస్టరీ నిల్వ పరిమితి. |
| `compact_prompt`                 | కాంపాక్షన్ సమయంలో ఉపయోగించే సిస్టమ్ ప్రాంప్ట్కు ఇన్లైన్ ఓవర్రైడ్ (v0.138+).                                                                                                             |

> **`model_max_output_tokens` గురించి గమనిక**: ఈ ఫీల్డ్ **Codex CLI కాన్ఫిగ్ స్కీమాలో భాగం కాదు** (Codex Rust కోడ్బేస్లో లేదు). దీన్ని సెట్ చేసినా ఎలాంటి సూచన లేకుండా విస్మరించబడుతుంది. దీనిపై ఆధారపడవద్దు — హిస్టరీలో ఎంత టూల్ అవుట్పుట్ నిల్వ చేయాలో నియంత్రించడానికి `tool_output_token_limit`ను ఉపయోగించండి.

## రీజనింగ్ శ్రమ

ప్రతిస్పందించే ముందు మోడల్ ఎంతగా "ఆలోచించాలి" అనేదాన్ని నియంత్రిస్తుంది.

| విలువ    | దేనికి ఉపయోగించాలి                               |
| -------- | ------------------------------------------------ |
| `none`   | రీజనింగ్ లేదు — నేరుగా ప్రతిస్పందన               |
| `low`    | అతి సులభమైన పనులు (పేరు మార్చడం, ఫార్మాట్ చేయడం) |
| `medium` | పేర్కొననప్పుడు **సర్వర్ డిఫాల్ట్**               |
| `high`   | మధ్యస్థ పనులు (రీఫ్యాక్టరింగ్, డీబగ్ చేయడం)      |
| `xhigh`  | ఆర్కిటెక్చర్, లోతైన విశ్లేషణ, సంక్లిష్ట సమస్యలు  |

```bash
# ప్రతి అమలుకు ఓవర్రైడ్
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Desktop ఆలోచనల టెక్స్ట్ను (ఎన్క్రిప్ట్ చేసిన బ్లాబ్లను మాత్రమే కాకుండా) రెండర్ చేయగలిగేలా రీజనింగ్ **సారాంశాన్ని** కూడా సెట్ చేయండి:

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # మద్దతు ఉన్నప్పుడు ultra కూడా ఉపయోగించవచ్చు
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute థింకింగ్ బడ్జెట్ (సర్వర్ సెట్టింగ్)

OmniRoute హోస్ట్లో, Codex శ్రమ/సారాంశం అప్స్ట్రీమ్కు చేరాలంటే **Settings → AI → Thinking Budget** తప్పనిసరిగా **`passthrough`**గా ఉండాలి. **`auto` మోడ్** అన్ని క్లయింట్ `reasoning` / `reasoning_effort` ఫీల్డ్లను తొలగిస్తుంది మరియు Codex సరిగ్గా కాన్ఫిగర్ చేసినప్పటికీ థింకింగ్ ప్యానెల్లను ఖాళీ చేస్తుంది.

పూర్తి గైడ్: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

కంప్రెషన్ మరియు ప్రాంప్ట్ క్యాష్ స్వతంత్రంగా ఉంటాయి మరియు `passthrough` కింద కూడా పనిచేస్తూనే ఉంటాయి.

## ప్రొఫైల్లు — ఒక్కో మోడల్/వర్క్ఫ్లోకు పేరు పెట్టిన కాన్ఫిగరేషన్లు

ఒకే ఫ్లాగ్తో మోడల్ + కాంటెక్స్ట్ విండోను మార్చడానికి ప్రొఫైల్లు మిమ్మల్ని అనుమతిస్తాయి. ప్రతి ప్రొఫైల్, బేస్ `config.toml`పై ఓవర్లే అయ్యే ఫ్లాట్
`~/.codex/<name>.config.toml` ఫైల్.

> **పేరు పెట్టే నియమం (Codex CLI v0.137+):** ఫైల్ తప్పనిసరిగా `~/.codex/<name>.config.toml` అయి ఉండాలి — **`profile-` ప్రిఫిక్స్ ఉండకూడదు**.
> CLIలో `-p kimi-k27` → `~/.codex/kimi-k27.config.toml`గా పరిష్కరించబడుతుంది. ఫైల్ కనుగొనబడకపోతే, ఎలాంటి హెచ్చరిక లేకుండా డిఫాల్ట్ వర్తిస్తుంది.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # వేగవంతమైనది, చౌకైనది
```

## `omniroute setup-codex`తో ప్రొఫైల్లను స్వయంచాలకంగా రూపొందించడం

మీరు OmniRouteను VPSలో అమలు చేస్తుంటే, ప్రత్యక్ష మోడల్ కేటలాగ్ నుంచి ప్రొఫైల్ ఫైల్లను స్వయంచాలకంగా రూపొందించవచ్చు:

```bash
# VPS నుంచి (పోర్ట్ 20128లో స్థానిక OmniRouteను ఉపయోగిస్తుంది)
omniroute setup-codex

# ఏ మెషీన్ నుంచైనా — మీ VPSను సూచించండి
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# ఫైల్లను వ్రాయకుండానే ప్రివ్యూ చేయండి
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# GLM మరియు Kimi ప్రొఫైల్లను మాత్రమే రూపొందించండి
omniroute setup-codex --only glm,kimi

# అనుకూల డైరెక్టరీలో వ్రాయండి
omniroute setup-codex --codex-home /path/to/.codex
```

ఈ కమాండ్ `/v1/models`ను పొందుతుంది, తెలిసిన మోడల్ల కోసం ట్యూన్ చేసిన ప్రొఫైల్లను ఉపయోగిస్తుంది, ఇతర అనుకూల టెక్స్ట్ మోడల్ల కోసం కేటలాగ్ మెటాడేటాను ప్రత్యామ్నాయంగా ఉపయోగిస్తుంది, అలాగే ప్రతి దానికీ `~/.codex/<name>.config.toml`ను వ్రాస్తుంది. ఇది ఐడెంపోటెంట్ — మళ్లీ అమలు చేయడం సురక్షితం.

ప్రాథమిక `config.toml`లో `model_providers.omniroute` నిర్వచనం లేకపోతే, స్పష్టంగా అమలు చేసిన
`setup-codex` ఎంచుకున్న స్థానిక లేదా రిమోట్ ఎండ్పాయింట్ను ఉపయోగించి, రూపొందించిన ప్రతి
ఓవర్లేలో ఆ నిర్వచనాన్ని చేర్చుతుంది. ఇది ప్రాథమిక ఫైల్ను మార్చదు. ఇప్పటికే ఉన్న ప్రొవైడర్
నిర్వచనం దాని ఎండ్పాయింట్ మరియు ప్రామాణీకరణ సెట్టింగ్లతో సహా వారసత్వంగా పొందబడుతుంది. చెల్లని
ప్రాథమిక TOML ఉంటే, ప్రొఫైల్లను వ్రాయకముందే వాటి రూపకల్పన ఆగిపోతుంది.

మీరు `--api-key` లేదా `OMNIROUTE_API_KEY`ను అందించినప్పుడు, కొత్తగా నిర్వచించిన ప్రొవైడర్
`env_key = "OMNIROUTE_API_KEY"`ను సూచిస్తుంది; కీ స్వయంగా ఎప్పటికీ సేవ్ చేయబడదు లేదా
ప్రివ్యూలో ముద్రించబడదు. మీరు Codexను ప్రారంభించే ఎన్విరాన్మెంట్లో ఆ వేరియబుల్ను సెట్ చేయండి. కీని
అందించకపోతే, ప్రామాణీకరణ లేని అభ్యర్థనలను ఆమోదించేలా కాన్ఫిగర్ చేసిన OmniRoute ఇన్స్టాన్స్ కోసం
కొత్త నిర్వచనంలో కీ అవసరం ఉండదు.

క్రింద వివరించిన ఐచ్ఛిక కేటలాగ్ ఆటో-సింక్, ఓవర్లేలో ఇప్పటికే ఉన్న ప్రొవైడర్ నిర్వచనాలను
ఉంచుతుంది, కానీ కొత్త ప్రొవైడర్ సెట్టింగ్లను బూట్స్ట్రాప్ చేయదు; ముందుగా స్పష్టమైన సెటప్ లేదా
డ్యాష్బోర్డ్ ద్వారా ప్రొవైడర్ను కాన్ఫిగర్ చేయండి. ఇప్పటికే ఉన్న ప్రొవైడర్ సెట్టింగ్లలో ఆపరేటర్
నిర్వహించే క్రెడెన్షియల్లు ఉండవచ్చు కాబట్టి, అవి డ్రై-రన్ ప్రివ్యూల నుంచి తొలగించబడతాయి.

విజయవంతమైన ప్రొవైడర్ మోడల్ డిస్కవరీ/ఇంపోర్ట్ ప్రత్యక్ష కేటలాగ్ను మార్చిన తర్వాత, OmniRoute ఇదే ప్రొఫైల్ ఫైల్లను **స్వయంచాలకంగా సింక్** చేయగలదు. ఇది **ఐచ్ఛికం మరియు డిఫాల్ట్గా ఆఫ్లో ఉంటుంది**: **CLI Code డ్యాష్బోర్డ్**లో ("CLI profile auto-sync" → Codex) దీన్ని టాగుల్ చేయండి లేదా `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true`ను సెట్ చేయండి (ఇది డిఫాల్ట్గా ఆన్లో ఉండే `CLI_ALLOW_CONFIG_WRITES`ను కూడా గౌరవిస్తుంది). ప్రారంభించినప్పుడు, ఇది వేర్వేరు `~/.codex/*.config.toml` ప్రొఫైల్ ఫైల్లను మాత్రమే వ్రాస్తుంది; సక్రియ/డిఫాల్ట్ `~/.codex/config.toml`, Codex-lb సెట్టింగ్లు, ప్రామాణీకరణ లేదా ప్రొవైడర్ ఎంపికను ఎప్పటికీ మార్చదు.

## `omniroute launch-codex`తో Codexను ప్రారంభించడం

Codexను ప్రారంభించే ముందు మీ OmniRoute ఇన్స్టాన్స్ ఆరోగ్యాన్ని తనిఖీ చేస్తుంది:

```bash
# స్థానిక OmniRouteతో ప్రారంభించండి (డిఫాల్ట్ పోర్ట్ 20128)
omniroute launch-codex

# నిర్దిష్ట ప్రొఫైల్తో ప్రారంభించండి
omniroute launch-codex --profile kimi-k27

# రిమోట్ VPSతో ప్రారంభించండి
omniroute launch-codex --remote http://100.x.x.x:20128/v1 --api-key sk-xxx

# codexకు అదనపు ఆర్గ్యుమెంట్లను పంపండి
omniroute launch-codex --profile glm52 -- --yolo "fix this bug"
```

రెండు సాధారణ మానిఫెస్ట్-ఆధారిత ఎంట్రీ పాయింట్లకు కూడా Codex ఒక లక్ష్యం
(`bin/cli/cli-manifest.mjs`):

```bash
# ఇంటరాక్టివ్ మోడల్ పికర్ → ~/.codex/<name>.config.tomlను వ్రాస్తుంది (TOML, env_key)
omniroute configure codex

# -c ఫ్లాగ్ల ద్వారా omniroute ప్రొవైడర్ను ఇంజెక్ట్ చేసి codexను ప్రారంభించండి (కాన్ఫిగ్ వ్రాయబడదు)
omniroute run codex
```

## దీర్ఘకాల పనులు

రెండు OmniRoute డిఫాల్ట్లు నిశ్శబ్దంగా బహుళ-గంటల Codex CLI సెషన్లను నాశనం చేయగలవు. Codex CLI సెట్టింగ్ — రెండూ కూడా OmniRoute వైపు లైవ్ కాదు. అప్స్ట్రీమ్ ప్రాక్సీల నుండి కాన్ఫిగర్ను మైగ్రేట్ చేసే యూజర్లు ఖాతాలను పిన్ చేసే మరియు నిష్క్రియ కటాఫ్లను డిసేబుల్ చేసే కాన్ఫిగర్ను తరచుగా రెండింటినీ కొట్టి, OmniRoute “సుదీర్ఘ సెషన్ను కొనసాగించలేరు” అని ముగించారు.

| లక్షణం                                                                              | కారణం కావచ్చు                                                                    | నాబ్                     |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------ |
| సెషన్ ఖాతాలను మార్చడాన్ని ఉంచుతుంది / ప్రాంప్ట్-కాష్ కొనసాగింపు మలుపుల మధ్య పోతుంది | సెషన్ అనుబంధం TTL `0` (డిజేబుల్ చేయబడింది)                                       | `sessionAffinityTtlMs`   |
| క్లయింట్-ఫేసింగ్ ప్రాంప్ట్ లేకుండా కనెక్షన్ మధ్య-తార్కికంగా చనిపోతుంది              | స్ట్రీమ్ ఐడిల్ వాచ్డాగ్ అప్స్ట్రీమ్ భాగం లేకుండా 10 నిమిషాల తర్వాత తొలగించబడింది | `STREAM_IDLE_TIMEOUT_MS` |

సంబంధిత చర్చలు: [#7126](https://github.com/cheaper-inference/OmniRoute/discussions/7126) (దీర్ఘ టాస్క్ డ్రాప్స్), [#5718](https://github.com/cheaper-inference/OmniRoute/discussions/5718) (అనుబంధం ఎందుకు డిఫాల్ట్ అవుతుంది). ట్రాకింగ్: [#7287](https://github.com/cheaper-inference/OmniRoute/issues/7287).

### 1. సెషన్ అనుబంధం — ఒక సంభాషణను ఒక ఖాతాకు పిన్ చేయండి

**డిఫాల్ట్:** `sessionAffinityTtlMs = 0` (వికలాంగ).

**ఎక్కడ సెట్ చేయాలి**

- డాష్బోర్డ్ →** సెట్టింగులు → రూటింగ్** →** సెషన్ అనుబంధం** →** అనుబంధం TTL (సెకన్లు)** (`ComboDefaultsTab`)
- లేదా `sessionAffinityTtlMs` inతో PATCH సెట్టింగ్లు** మిల్లీసెకన్లు** (Zod పరిధి `0`–`86_400_000`, అంటే 24 గంటల వరకు)

> కోడెక్స్-మాత్రమే `codexSessionAffinityTtlMs` నుండి #7274 లో పేరు మార్చబడింది. లెగసీ కీ ఇప్పటికీ చదవడానికి-మాత్రమే అలియాస్గా ఆమోదించబడింది; కొత్త configs `sessionAffinityTtlMs` ని ఉపయోగించాలి. అనుబంధం ఇప్పుడు వర్తిస్తుంది** ఏదైనా** ప్రదాత ఒకసారి TTL `0` పైన ఉంటే, Codex — మాత్రమే కాదు [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → సెషన్ అనుబంధాన్ని చూడండి.

**0 వద్ద ఉన్నప్పుడు ఏది విచ్ఛిన్నమవుతుంది**

మల్టీ-టర్న్ Codex సంభాషణ యొక్క ప్రతి మలుపు సక్రియ కాంబో వ్యూహం ద్వారా స్వతంత్రంగా మళ్లించబడుతుంది మరియు ఒక** ఒక్కో మలుపుకు వేర్వేరు ఖాతా** . అది అప్స్ట్రీమ్ సెషన్ / ప్రాంప్ట్-కాష్ కొనసాగింపును విచ్ఛిన్నం చేస్తుంది. TTL `0` ఎక్కువగా ఉన్నప్పుడు OmniRoute Codex సెషన్ హెడర్లను (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) మరియు `prompt_cache_key` / `session_id` వంటి బాడీ ఫీల్డ్లను మాత్రమే సంప్రదిస్తుంది ( `src/sse/services/auth.ts` లో`extractSessionAffinityKey` ).

**బహుళ-గంటల సింగిల్ టాస్క్ కోసం సిఫార్సు చేయబడింది**

TTL సెట్ చేయండి** టాస్క్ యొక్క ఊహించిన గోడ-గడియార పొడవు కంటే ఎక్కువ** (UI గరిష్టం** 86400 సెకన్లు** = 24 గంటలు):

| ఆశించిన పని పొడవు | అనుబంధం TTL (UI, సెకన్లు) | `sessionAffinityTtlMs` |
| ----------------- | ------------------------- | ---------------------- |
| కొన్ని గంటలు      | `14400` (4గం)             | `14400000`             |
| రాత్రిపూట / ~ 12h | `43200` (12గం)            | `43200000`             |
| పూర్తి రోజు       | `86400` (24గం, గరిష్టంగా) | `86400000`             |

ఆప్ట్-ఇన్ ఉద్దేశపూర్వకమైనది: అనుబంధాన్ని నిలిపివేయడం ఖాతాల అంతటా లోడ్-బ్యాలెన్సింగ్కు అనుకూలంగా ఉంటుంది; దీన్ని ప్రారంభించడం ఒక దీర్ఘ ఏజెంట్ సెషన్ కోసం కొనసాగింపుకు అనుకూలంగా ఉంటుంది. ఈ గైడ్ చేస్తుంది** కాదు** డిఫాల్ట్ — ఆపరేటర్లను మార్చండి దీర్ఘ Codex టాస్క్లను అమలు చేయడం తప్పక ఎంచుకోవాలి.

### 2. స్ట్రీమ్ నిష్క్రియ సమయం ముగిసింది — నిశ్శబ్ద తార్కిక మలుపులను చంపదు

**డిఫాల్ట్:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 నిమిషాలు). సెట్ చేయనప్పుడు ఇది `REQUEST_TIMEOUT_MS` నుండి వారసత్వంగా పొందుతుంది; షేర్డ్ బేస్లైన్ కూడా 600000. [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → టైమ్అవుట్లను చూడండి.

**డిఫాల్ట్లో ఏది విచ్ఛిన్నమవుతుంది**

10 నిమిషాల కంటే ఎక్కువసేపు నిశ్శబ్దంగా ఉండే Codex రీజనింగ్ / టూల్ టర్న్** నిజమైన అప్స్ట్రీమ్ భాగం లేదు** SSE నిష్క్రియ వాచ్డాగ్ (`open-sse/utils/stream.ts`) ద్వారా బలవంతంగా మూసివేయబడింది. క్లయింట్ తరచుగా బేర్ కనెక్షన్ డ్రాప్ — సరిపోలికను చూస్తుంది "ఏ నోటిఫికేషన్ లేకుండా స్వయంచాలకంగా ఆగిపోయింది."

క్లిష్టమైన వివరాలు: OmniRoute యొక్క సింథటిక్ SSE** హృదయ స్పందన రీసెట్ కాదు** నిష్క్రియ గడియారం. నిజమైన అప్స్ట్రీమ్ బాడీ భాగం మాత్రమే `lastChunkTime` ని అప్డేట్ చేస్తుంది. ఇప్పటికీ "ఆలోచిస్తూ" ఉన్న నిశ్శబ్ద మోడల్ వాచ్డాగ్ యొక్క కోణం నుండి ఆగిపోయిన అప్స్ట్రీమ్తో సమానంగా కనిపిస్తుంది.

సంబంధిత Undici శరీర నిష్క్రియాత్మకత: `FETCH_BODY_TIMEOUT_MS` (అదే 10 నిమిషాల బేస్లైన్కు కూడా డిఫాల్ట్ అవుతుంది; `0` దానిని నిలిపివేస్తుంది). స్ట్రీమింగ్ కోసం, `FETCH_TIMEOUT_MS` కనెక్షన్ సెటప్/మొదటి హెడర్లు — మాత్రమే కవర్ చేస్తుంది, ఒకసారి స్ట్రీమ్ సక్రియంగా ఉంటే, స్టాల్స్ `STREAM_IDLE_TIMEOUT_MS` మరియు `FETCH_BODY_TIMEOUT_MS` ద్వారా నిర్వహించబడతాయి.

**బహుళ-గంటల సింగిల్ టాస్క్ కోసం సిఫార్సు చేయబడింది**

OmniRoute ప్రక్రియ వాతావరణంలో (`.env` / compose / systemd):

```bash
# Disable stream idle + body inactivity cutoffs for long reasoning turns
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

లేదా మీరు ఆశించే పొడవైన నిశ్శబ్ద గ్యాప్ కంటే వాటిని పెంచండి (విలువలు మిల్లీసెకన్లు):

```bash
# Example: allow up to 2 hours of silence between upstream chunks
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

ఈ env varలను మార్చిన తర్వాత OmniRoute పునఃప్రారంభించండి.

### కాంక్రీట్ రెసిపీ — బహుళ-గంటల Codex టాస్క్

1. **ఖాతాను పిన్ చేయండి:** డాష్బోర్డ్ → సెట్టింగ్లు → రూటింగ్ → సెషన్ అనుబంధం → అనుబంధం TTL = `43200` (12h) లేదా `86400` (24h గరిష్టంగా).
2. **నిష్క్రియ కటాఫ్లను పెంచండి / నిలిపివేయండి** OmniRoute వాతావరణంలో:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. ఈ రెండు ప్రవర్తనల కోసం సాధారణ Codex `config.toml` (`wire_api = "responses"`, సరైన `base_url`, `OMNIROUTE_API_KEY`) — ఏ కోడెక్స్-సైడ్ affinity/idle నాబ్లు ఉండకుండా ఉంచండి.
4. OmniRoute పునఃప్రారంభించండి, ఆపై పొడవైన Codex పనిని ప్రారంభించండి.

### డిఫాల్ట్ నిర్ణయం (#7287)

| నాబ్                     | షిప్ డిఫాల్ట్      | ఈ గైడ్లో మార్పు చేయాలా?                                                                                           |
| ------------------------ | ------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (ఆఫ్)          | **నం** — ఎంపికగా మిగిలిపోయింది (లోడ్-బ్యాలెన్సింగ్ vs కొనసాగింపు; చర్చ #5718 చూడండి)                              |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 నిమి) | **నం** సాధారణ ట్రాఫిక్ కోసం — 10 నిమిషాలు మిగిలి ఉంది; దీర్ఘ Codex ఆపరేటర్లు దీన్ని పెంచుతారు లేదా నిలిపివేస్తారు |

ప్రపంచవ్యాప్తంగా డిఫాల్ట్గా ఏదైనా ఫ్లిప్ చేయడం అనేది Codex మాత్రమే కాకుండా ప్రతి క్లయింట్కు ప్రవర్తనను మారుస్తుంది. గుబ్బలను డాక్యుమెంట్ చేయండి; స్పష్టమైన ఆపరేటర్ నిర్ణయం వేరే విధంగా చెప్పే వరకు డిఫాల్ట్లను వదిలివేయండి.

### నిష్క్రియ కోతలను నిర్ధారించడం

నిష్క్రియ వాచ్డాగ్ కాల్పులు జరిపినప్పుడు, OmniRoute ఆకారంలో ఉన్న లైన్ను లాగ్ చేస్తుంది:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

`Idle timeout: no data from` కోసం Grep (లేదా కోడ్ `stream_idle_timeout` / లోపం పేరు `StreamIdleTimeoutError`). ప్రొవైడర్ సెగ్మెంట్ అనేది ఆ అభ్యర్థన కోసం ఉపయోగించిన OmniRoute (`codex`, మరొక ప్రొవైడర్ ఐడి లేదా `provider` తెలియకపోతే) — ఇది ఎల్లప్పుడూ లిటరల్ స్ట్రింగ్ `codex` కాదు.

## సమస్య పరిష్కారం

**`Error: wire_api = "chat" is no longer supported`**
మీ కాన్ఫిగ్ నుండి `wire_api = "chat"`ను తొలగించండి. `wire_api = "responses"`గా సెట్ చేయండి లేదా ఆ ఫీల్డ్ను వదిలివేయండి (v0.138 నుండి డిఫాల్ట్గా `"responses"` ఉంటుంది).

**`Error: model not found`**
సరైన ప్రిఫిక్స్తో ఆ మోడల్ OmniRouteలో ఉందో లేదో ధృవీకరించండి. `omniroute models list` ఉపయోగించండి లేదా `/dashboard/providers/<provider>` తెరవండి.

**`Authentication error`**
`OMNIROUTE_API_KEY` ఎక్స్పోర్ట్ చేయబడిందని నిర్ధారించండి: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
మొదటి అభ్యర్థన చేయడానికి ముందు env var ఉందో లేదో Codex ధృవీకరిస్తుంది. రక్షిత సర్వర్ల కోసం
నిజమైన కీని ఎక్స్పోర్ట్ చేయండి లేదా మీ **స్థానిక** OmniRoute ఇన్స్టాన్స్కు
ప్రమాణీకరణ అవసరం లేనప్పుడు `OMNIROUTE_API_KEY=local` వంటి ఖాళీ కాని ప్లేస్హోల్డర్ను ఉపయోగించండి.
దాన్ని `~/.bashrc` లేదా `~/.zshrc`కు జోడించినట్లయితే shellను పునఃప్రారంభించండి.

**`Connection refused`**
OmniRoute రన్ అవుతోందని, అలాగే మీ నెట్వర్క్కు (స్థానికం vs Tailscale vs VPS) సంబంధించి `base_url` హోస్ట్/పోర్ట్ సరైనదని ధృవీకరించండి.

**కాంటెక్స్ట్ పరిమితికి సమీపంలో సెషన్ క్రాష్ అవుతోంది**
`model_context_window` మరియు `model_auto_compact_token_limit`ను స్పష్టంగా సెట్ చేయండి. పైన ఉన్న కాంటెక్స్ట్ విండో పట్టికను చూడండి.

**కాంపాక్షన్ చాలా ఆలస్యంగా ప్రారంభమవుతోంది**
`model_auto_compact_token_limit`ను విండోలో 80–85%కి తగ్గించండి. ఎప్పుడూ 90% కంటే ఎక్కువగా సెట్ చేయవద్దు.

**ప్రొఫైల్ లోడ్ కావడం లేదు (`-p <name>` నిశ్శబ్దంగా విస్మరించబడుతోంది)**
ఫైల్ `~/.codex/<name>.config.toml` వద్ద ఉందని నిర్ధారించండి (`profile-` ప్రిఫిక్స్ లేకుండా). `ls ~/.codex/*.config.toml` రన్ చేయండి.

**దీర్ఘకాలం నడిచే Codex టాస్క్ మధ్యలో ఆగిపోతోంది / టర్న్ల మధ్య ఖాతాలు మారుతున్నాయి**
[దీర్ఘకాలం నడిచే టాస్క్లు](#long-running-tasks) చూడండి. సెషన్ అఫినిటీని ప్రారంభించండి (టాస్క్ నిడివి కంటే ఎక్కువ TTLతో), అలాగే `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`ను పెంచండి లేదా నిలిపివేయండి. `Idle timeout: no data from` కోసం OmniRoute లాగ్లలో grep చేయండి.
