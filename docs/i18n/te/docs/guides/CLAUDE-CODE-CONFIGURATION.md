**Claude Code** CLI (`claude`)ని OmniRoute వైపు మళ్లించండి — స్థానికంగా లేదా రిమోట్ VPSలో —
Codex సెటప్ను ప్రతిబింబించేలా, ఒక్కో మోడల్కు ప్రత్యేక ప్రొఫైల్లతో.

---

## త్వరిత ప్రారంభం

```bash
# స్థానిక OmniRouteతో Claude Codeను ప్రారంభించండి (సక్రియ కాంటెక్స్ట్ను స్వయంచాలకంగా గుర్తిస్తుంది)
omniroute launch

# రిమోట్ OmniRouteతో (`omniroute connect <host>` తర్వాత, ఇది స్వయంచాలకంగా జరుగుతుంది)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# ఒక్కో మోడల్కు ప్రొఫైల్లను రూపొందించి, ఆపై ఒకదాన్ని ప్రారంభించండి
omniroute setup-claude            # ~/.claude/profiles/<name>/settings.jsonకు వ్రాస్తుంది
omniroute launch --profile glm52  # OmniRoute ద్వారా glm/glm-5.2ను ఉపయోగించే Claude Code
```

## Claude Code ఒక గేట్వేకి ఎలా కనెక్ట్ అవుతుంది

Claude Code **Anthropic Messages API**తో కమ్యూనికేట్ చేస్తుంది మరియు environment variables ద్వారా అనుకూల
endpointకు మళ్లించబడుతుంది (దీనికి `--base-url` flag లేదు):

| Variable                                     | ఉద్దేశ్యం                                                                                                |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | గేట్వే root URL (Claude Code `/v1/messages`ను జోడిస్తుంది). **`/v1` suffix ఉండకూడదు.**                   |
| `ANTHROPIC_AUTH_TOKEN`                       | `Authorization: Bearer …`గా పంపబడుతుంది — మీ OmniRoute access token / API keyని ఉపయోగించండి              |
| `ANTHROPIC_API_KEY`                          | ప్రత్యామ్నాయం: `x-api-key`గా పంపబడుతుంది. రెండూ సెట్ చేస్తే, `ANTHROPIC_AUTH_TOKEN`కు ప్రాధాన్యం ఉంటుంది |
| `ANTHROPIC_MODEL`                            | నిర్దిష్ట మోడల్ను బలవంతంగా ఉపయోగిస్తుంది (`/model` picker defaultను override చేస్తుంది)                  |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → స్థానిక `/model` picker, `/v1/models` నుండి `claude*`/`anthropic*` మోడల్లను జాబితా చేస్తుంది       |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | ఒక్కో responseకు output tokensపై పరిమితి విధిస్తుంది (ఉదా. `65536`)                                      |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | auto-compaction కోసం token threshold                                                                     |

> Env vars **ప్రారంభ సమయంలో ఒక్కసారి మాత్రమే** చదవబడతాయి — వాటిని మార్చిన తర్వాత Claude Codeను పునఃప్రారంభించండి.

`omniroute launch` వీటన్నింటినీ మీ కోసం సెట్ చేస్తుంది: ఇది సక్రియ context నుండి base URL + tokenను
పరిష్కరిస్తుంది (కాబట్టి `omniroute connect <vps>` తర్వాత `omniroute launch`
నేరుగా పనిచేస్తుంది), server health-check నిర్వహించి, `claude`ను exec చేస్తుంది.

## డిస్కవరీ అలియాస్లు — `/model` పికర్లో Claude కాని మోడళ్లను చూపించడం

Claude Code యొక్క గేట్వే మోడల్ డిస్కవరీ `claude` లేదా `anthropic` తో ప్రారంభమయ్యే id లను మాత్రమే జాబితా చేస్తుంది. కాబట్టి `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` ఉన్నప్పుడు, స్వదేశీ `/model` పికర్ సాధారణంగా OmniRoute యొక్క Claude/Anthropic మోడళ్లను **మాత్రమే** చూపిస్తుంది — `kimi/kimi-k2.6` లేదా `glm/glm-5.2` వంటివి రూటింగ్ సరిగ్గా జరిగినప్పటికీ ఎప్పుడూ కనిపించవు.

OmniRoute ఏ ఎనేబుల్ చేయబడిన మోడల్నైనా (మరియు కాంబోను) `claude/…` id కింద మిర్రర్ చేయగలదు, తద్వారా అది ఆ ఫిల్టర్ను దాటి పికర్లో కనిపిస్తుంది:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

Claude Code లో వీటిలో ఒకదాన్ని ఎంచుకున్నప్పుడు, OmniRoute రూటింగ్ చేయడానికి ముందు `claude/` ర్యాపర్ను తొలగించి అసలు id కి తిరిగి మారుస్తుంది — నిజమైన `claude/<real-claude-model>` id (అసలు Claude OAuth ప్రొవైడర్) ఎల్లప్పుడూ అలాగే ఉంచబడుతుంది.

డిఫాల్ట్గా బేస్ id లు మాత్రమే మిర్రర్ చేయబడతాయి. ఆప్ట్-ఇన్ `CATALOG_MIRROR_REFINEMENTS_ENABLED` ఫీచర్ ఫ్లాగ్ ఆన్ చేస్తే, కేటలాగ్ ఇప్పటికే జాబితా చేసిన రీజనింగ్-ఎఫర్ట్ వేరియంట్లు (ఉదా. `codex/gpt-6-sol-high`) ఏ ఇతర id లాగానే మిర్రర్ చేయబడతాయి, తద్వారా Claude Code స్పష్టమైన ఎఫర్ట్ స్థాయిని ఎంచుకోగలదు, అలాగే రిక్వెస్ట్ పాత్ మెటీరియలైజ్ చేయలేని బిల్ట్-ఇన్ `auto/*` id లు మిర్రర్ చేయబడవు. ఎఫర్ట్ వేరియంట్లు అసలు జాబితా చేయబడతాయా లేదా అనేది ఇంకా `OMNIROUTE_DISABLE_THINKING_LEVEL_VARIANTS` ద్వారానే నియంత్రించబడుతుంది — మిర్రర్ బేస్ కేటలాగ్లో లేని వేరియంట్ను ఎప్పుడూ జోడించదు.

**ఇది డిఫాల్ట్గా ఆఫ్లో ఉంటుంది** మరియు మూడు-స్థాయి గేట్ ద్వారా నియంత్రించబడుతుంది (అత్యంత నిర్దిష్టమైనది గెలుస్తుంది), కాబట్టి Claude Code ఉపయోగించని క్లయింట్ల కోసం సాధారణ OmniRoute తన కేటలాగ్ను ఎప్పుడూ రెట్టింపు చేయదు:

| స్థాయి    | ఎక్కడ                                                                                |
| --------- | ------------------------------------------------------------------------------------ |
| మోడల్     | ప్రొవైడర్ వివరాల పేజీ → ప్రతి-మోడల్ "Expose in Claude Code" టాగిల్                   |
| ప్రొవైడర్ | ప్రొవైడర్ వివరాల పేజీ → ప్రొవైడర్-స్థాయి టాగిల్ (దాని అన్ని మోడళ్లను కవర్ చేస్తుంది) |
| గ్లోబల్   | Settings → Feature Flags → `EXPOSE_CC_DISCOVERY_ALIASES` (డిఫాల్ట్ ఆఫ్)              |

`EXPOSE_CC_DISCOVERY_ALIASES` ఎన్విరాన్మెంట్ వేరియబుల్ గ్లోబల్ స్థాయిని బలవంతంగా ఆన్ చేస్తుంది మరియు డాష్బోర్డ్ ఓవర్రైడ్ కంటే ప్రాధాన్యత పొందుతుంది (అలా జరిగినప్పుడు Feature Flags స్క్రీన్ "active via environment variable" అనే నోట్ను చూపిస్తుంది). ప్రతి-ప్రొవైడర్ మరియు ప్రతి-మోడల్ టాగిళ్లు అక్కడి నుండి రిఫైన్ చేస్తాయి — ఉదా. గ్లోబల్ ఆఫ్ + Kimi ప్రొవైడర్ ఆన్ అయితే కేవలం Kimi మోడళ్లు మాత్రమే బహిర్గతమవుతాయి.

> ⚠️ **Claude కాని మోడళ్లపై విండో అసంగతి.** Claude Code తాను గుర్తించని ఏ id కైనా 200K కాంటెక్స్ట్ విండోను ఊహిస్తుంది (అది `/v1/models` నుండి నిజమైన విండోను చదవలేదు). మరింత పెద్ద విండో ఉన్న మోడల్ కోసం (ఉదా. Kimi K2 యొక్క 256K), ఆటో-కాంపాక్షన్ ముందుగానే ట్రిగ్గర్ అవ్వకుండా ఉండటానికి `CLAUDE_CODE_AUTO_COMPACT_WINDOW` ను మోడల్ యొక్క నిజమైన విండో కంటే తక్కువ విలువకు సెట్ చేయండి. పైన జనరేట్ చేయబడిన ప్రొఫైళ్లు ఇప్పటికే దీన్ని ప్రతి మోడల్ కోసం చేస్తాయి.

## డ్యాష్బోర్డ్లో ఆన్బోర్డింగ్ బ్లాక్

Claude టూల్ కార్డ్ (**Dashboard → CLI Code**) ఈ ఇన్స్టాన్స్కు సంబంధించిన ఖచ్చితమైన `settings.json` ఫ్రాగ్మెంట్ను, డిస్కవరీ-అలియాస్ సమాచార బటన్ పక్కన, కాపీ బటన్తో ప్రదర్శిస్తుంది:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<మీ OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<మీ OmniRoute API కీ>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

బేస్ URL అనేది కార్డ్ పరిష్కరించినదే (మీరు నమోదు చేసిన అనుకూల ఓవర్రైడ్తో సహా), ఇప్పటికే సాధారణీకరించబడింది — `/v1` సఫిక్స్ ఉండదు, చివరలో స్లాష్ ఉండదు. **కీ ఎప్పటికీ ప్రదర్శించబడదు**: బ్లాక్లో ప్లేస్హోల్డర్ ఉంటుంది, కాబట్టి స్క్రీన్షాట్ లేదా పేస్ట్ చేసిన స్నిపెట్ ద్వారా కీ లీక్ కాదు. దాని స్థానంలో మీ కీని పేస్ట్ చేయండి.

వాస్తవ కాంటెక్స్ట్ విండో 200K కాని ఏ మోడల్కైనా అదే `env` బ్లాక్ కింద `CLAUDE_CODE_AUTO_COMPACT_WINDOW`ను జోడించండి — Claude Code తాను గుర్తించని ప్రతి idకి 200Kగా భావిస్తుంది, కాబట్టి అలా చేయకపోతే ఆటో-కాంపాక్షన్ తప్పు సమయంలో ప్రారంభమవుతుంది (మునుపటి విభాగంలోని హెచ్చరికను చూడండి). స్నిపెట్ బిల్డర్ కూడా ఆ విలువను అంగీకరిస్తుంది, కాబట్టి లక్ష్య మోడల్ విండో తెలిసిన కాలర్ దానిని నేరుగా ఉత్పత్తి చేయగలదు.

మూలం: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (స్వచ్ఛమైన బిల్డర్, యూనిట్-టెస్ట్ చేయబడింది), `ClaudeGatewayOnboardingBlock` ద్వారా ప్రదర్శించబడుతుంది.

### ఒక ఖాతాను పిన్ చేయండి (ఐచ్ఛికం)

ప్రతి Claude Code అభ్యర్థనను ఒక నిర్దిష్ట ప్రొవైడర్ ఖాతా ద్వారా పంపడానికి, అదే `env` బ్లాక్లో `ANTHROPIC_CUSTOM_HEADERS` ద్వారా `x-omniroute-connection` హెడర్ను జోడించండి:

```jsonc
"ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>"
```

ప్రొవైడర్ పేజీలోని కనెక్షన్ వరుసలో ఉన్న `xxxxxxxx…` చిప్ నుంచి idని కాపీ చేయండి. ఈ పిన్ సింగిల్-మోడల్ idలకు (`provider/model`) మాత్రమే వర్తిస్తుంది, కాంబోలకు కాదు. ఖచ్చితమైన ఫాల్బ్యాక్ ప్రవర్తన కోసం [ప్రతి అభ్యర్థనకు ఖాతా పిన్నింగ్](../reference/API_REFERENCE.md#account-pinning-per-request) చూడండి.

## ప్రొఫైల్లు (`CLAUDE_CONFIG_DIR`)

Claude Codeలో **స్థానిక ప్రొఫైల్ ఫైళ్లు లేవు** (Codexలోని `~/.codex/<name>.config.toml` మాదిరిగా).
సాధారణంగా ఉపయోగించే విధానం `CLAUDE_CONFIG_DIR` — ప్రతి ప్రొఫైల్కు ఒక ప్రత్యేక కాన్ఫిగరేషన్ డైరెక్టరీ,
ప్రతిదానిలో దాని స్వంత `settings.json`, ఆధారాలు, చరిత్ర మరియు కాష్ ఉంటాయి.

`omniroute setup-claude` ప్రత్యక్ష `/v1/models` కేటలాగ్ను పొందుతుంది మరియు ప్రతి మోడల్కు
`~/.claude/profiles/<name>/settings.json` వద్ద ఒక ప్రొఫైల్ను వ్రాస్తుంది, అలాగే
**`setup-codex`లో ఉన్న అవే పేర్లను** (`glm52`, `kimi-k27`, `deepseek-pro`, …) తిరిగి ఉపయోగిస్తుంది:

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **ప్రామాణీకరణ టోకెన్ను ప్రొఫైల్లో ఎప్పుడూ వ్రాయరు.** `omniroute launch --profile <name>`తో
> ప్రారంభించండి (ఇది సక్రియ కాంటెక్స్ట్ నుండి `ANTHROPIC_AUTH_TOKEN`ను చొప్పిస్తుంది), లేదా మీరే
> `ANTHROPIC_AUTH_TOKEN`ను ఎక్స్పోర్ట్ చేసి
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`ను అమలు చేయండి.

**మోడల్ డిస్కవరీ తర్వాత స్వయంచాలక సమకాలీకరణ (ఎంచుకుంటే మాత్రమే).** ప్రొవైడర్ మోడల్
సమకాలీకరణ వల్ల ప్రత్యక్ష కేటలాగ్ మారినప్పుడల్లా OmniRoute ఇవే
`~/.claude/profiles/<name>/settings.json` ఫైళ్లను స్వయంచాలకంగా మళ్లీ రూపొందించగలదు — తద్వారా కమాండ్ను
మళ్లీ అమలు చేయకుండానే కొత్త/పేరు మార్చిన మోడల్లకు ప్రొఫైల్లు లభిస్తాయి. ఇది **డిఫాల్ట్గా ఆఫ్లో ఉంటుంది**:
**CLI Code డాష్బోర్డ్** నుండి దీన్ని టాగుల్ చేయండి ("CLI profile auto-sync" → Claude Code), లేదా
`OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true`ను సెట్ చేయండి (ఇది డిఫాల్ట్గా ఆన్లో ఉండే
`CLI_ALLOW_CONFIG_WRITES`ను కూడా గౌరవిస్తుంది). ప్రారంభించినప్పుడు ఇది ప్రొఫైల్ ఫైళ్లను మాత్రమే వ్రాస్తుంది;
ఇది మీ సక్రియ/డిఫాల్ట్ Claude కాన్ఫిగరేషన్ను, ప్రామాణీకరణను లేదా `~/.claude/settings.json`ను ఎప్పుడూ మార్చదు.

### ప్రొఫైల్లను రూపొందించడం + ఉపయోగించడం

```bash
# స్థానిక OmniRoute
omniroute setup-claude

# రిమోట్ VPS (ప్రతి ప్రొఫైల్లో VPS URLను పొందుపరుస్తుంది)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# కొన్ని ప్రొవైడర్లు మాత్రమే
omniroute setup-claude --only glm,kimi

# ఈ హోస్ట్లో గుర్తించబడని local-CLI ప్రొవైడర్లకు (zcode, auggie, devin-cli-agentic,
# codex-app-server) కూడా ప్రొఫైల్లను వ్రాయండి (స్థానిక లక్ష్యానికి డిఫాల్ట్గా దాటవేయబడతాయి)
omniroute setup-claude --include-local

# వ్రాయకుండా ప్రివ్యూ చేయండి
omniroute setup-claude --dry-run

# ఒక ప్రొఫైల్ను ప్రారంభించండి
omniroute launch --profile kimi-k27
```

## మోడల్ స్థాయులు (ఐచ్ఛికం)

Claude Code సామర్థ్య స్థాయులకు రూట్ చేస్తుంది. ఒక్కో స్థాయికి వేర్వేరు ప్రొవైడర్లను ఉపయోగించాలనుకుంటే, env /
సెట్టింగ్ల ద్వారా ప్రతి స్థాయిని ఒక OmniRoute మోడల్కు మ్యాప్ చేయండి:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

లేకపోతే, అన్నింటికీ ఒకే `ANTHROPIC_MODEL` (ప్రొఫైల్లు సెట్ చేసేది) ఉపయోగించబడుతుంది.

## రిమోట్ మోడ్

మీరు `omniroute connect <host>` అమలు చేసిన తర్వాత (చూడండి
[రిమోట్ మోడ్](./REMOTE-MODE.md)), `omniroute launch` మరియు `omniroute setup-claude`
ఆ రిమోట్ సర్వర్ను స్వయంచాలకంగా లక్ష్యంగా చేసుకుని, దాని పరిధి-పరిమిత యాక్సెస్ టోకెన్ను ఉపయోగిస్తాయి — అదనపు
ఫ్లాగ్లు అవసరం లేదు. ప్రతి అమలుకు `--remote` / `--api-key`తో ఓవర్రైడ్ చేయండి.

## సమస్య పరిష్కారం

**Claude Code గేట్వేని విస్మరిస్తోంది** — `ANTHROPIC_BASE_URL`లో **`/v1`
లేదని** నిర్ధారించి, `claude`ను పునఃప్రారంభించండి (ప్రారంభ సమయంలో env ఒక్కసారి మాత్రమే చదవబడుతుంది). `omniroute launch`
దీన్ని మీ కోసం నిర్వహిస్తుంది.

**`/model` ఎంపిక సాధనం ఖాళీగా ఉంది / గేట్వే మోడల్లు లేవు** — Claude Code
v2.1.219+ మరియు `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` అవసరం. ఎంపిక సాధనంలో `claude*` /
`anthropic*` మోడల్ IDలు మాత్రమే కనిపిస్తాయి; ఇతర మోడల్ను
`ANTHROPIC_MODEL=<id>`తో బలవంతంగా ఉపయోగించండి (ప్రొఫైల్లు చేసేది ఇదే).

**`400 Ambiguous model 'claude-…'`** — Claude Code ఎల్లప్పుడూ **ప్రిఫిక్స్ లేని**
మోడల్ IDలను (ఉదా. `claude-opus-4-8`) పంపుతుంది, కాబట్టి Claude Code (`cc/…`) మరియు
Claude (`claude/…`) ప్రొవైడర్లు రెండూ కనెక్ట్ అయి ఉన్నప్పుడు, ప్రిఫిక్స్ లేని id రెండు రూట్లతో సరిపోలుతుంది మరియు
OmniRoute ఊహించడానికి నిరాకరిస్తుంది. దీన్ని ఈ రెండింటిలో ఏదో ఒక విధంగా పరిష్కరించండి: `ANTHROPIC_MODEL=cc/claude-opus-4-8`తో
ప్రిఫిక్స్ ఉన్న idను పిన్ చేయండి, లేదా **ప్రిఫిక్స్ లేని Claude మోడల్ల కోసం Claude Codeకు
ప్రాధాన్యత ఇవ్వండి** అనే ఎంపికను ప్రారంభించండి — Claude ప్రొవైడర్ పేజీలోని టాగుల్, లేదా
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (డిఫాల్ట్గా ఆఫ్;
చూడండి [ఎన్విరాన్మెంట్](../reference/ENVIRONMENT.md)) — ఇది ప్రిఫిక్స్ లేని `claude-*`
IDలను బదులుగా Claude Codeకు రూట్ చేస్తుంది. స్పష్టమైన ప్రొవైడర్ ప్రిఫిక్స్లకు ఎల్లప్పుడూ ప్రాధాన్యత ఉంటుంది.

**ప్రామాణీకరణ లోపాలు** — ప్రొఫైల్లో టోకెన్ ఉండదు. `omniroute launch --profile`
(దాన్ని ఇంజెక్ట్ చేస్తుంది) ఉపయోగించండి లేదా `ANTHROPIC_AUTH_TOKEN`ను ఎక్స్పోర్ట్ చేయండి.

**ప్రొఫైల్లు వేరుగా ఉండటం లేదు** — ప్రతి ప్రొఫైల్ ఒక ప్రత్యేక `CLAUDE_CONFIG_DIR`;
సెషన్లో `echo $CLAUDE_CONFIG_DIR` అమలు చేసి, అది
`~/.claude/profiles/<name>`ను సూచిస్తోందని ధృవీకరించండి.
