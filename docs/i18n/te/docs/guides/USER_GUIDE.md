## 🎯 వినియోగ సందర్భాలు

### సందర్భం 1: "నాకు Claude Pro సబ్స్క్రిప్షన్ ఉంది"

**సమస్య:** ఉపయోగించని కోటా గడువు ముగుస్తుంది, భారీ కోడింగ్ సమయంలో రేట్ పరిమితులు ఎదురవుతాయి

```
కాంబో: "maximize-claude"
  1. cc/claude-opus-4-7        (సబ్స్క్రిప్షన్ను పూర్తిగా ఉపయోగించండి)
  2. glm/glm-4.7               (కోటా అయిపోయినప్పుడు చౌకైన బ్యాకప్)
  3. if/qwen3.8-max-preview       (అత్యవసర పరిస్థితుల్లో ఉచిత ప్రత్యామ్నాయం)

నెలవారీ ఖర్చు: $20 (సబ్స్క్రిప్షన్) + ~$5 (బ్యాకప్) = మొత్తం $25
దీనికి బదులుగా $20 చెల్లించి + పరిమితులు ఎదుర్కోవడం = నిరాశ
```

### సందర్భం 2: "నాకు ఎలాంటి ఖర్చూ వద్దు"

**సమస్య:** సబ్స్క్రిప్షన్లను భరించలేను, నమ్మదగిన AI కోడింగ్ అవసరం

```
కాంబో: "zero-cost"
  1. if/kimi-k2.7-code          (ఉచిత యాక్సెస్గా జాబితా చేయబడింది; రేట్ పరిమితులు వర్తించవచ్చు)
  2. kr/qwen3-coder-next        (Kiro ఉచిత ప్రత్యామ్నాయం)

నెలవారీ ఖర్చు: $0
నాణ్యత: మీ పనిభారానికి అనుగుణంగా మోడల్, పరిమితులు, గోప్యత మరియు SLAను ధృవీకరించండి
```

### సందర్భం 3: "అంతరాయాలు లేకుండా 24/7 కోడింగ్ కావాలి"

**సమస్య:** గడువులు ఉన్నాయి, సేవ నిలిచిపోవడాన్ని భరించలేను

```
కాంబో: "always-on"
  1. cc/claude-opus-4-7        (అత్యుత్తమ నాణ్యత)
  2. cx/gpt-5.5                (రెండవ సబ్స్క్రిప్షన్)
  3. glm/glm-4.7               (చౌకైనది, ప్రతిరోజూ రీసెట్ అవుతుంది)
```

- డ్యాష్బోర్డ్ను తెరవండి.
- `/dashboard/logs`ను తెరవండి.
- ఆటో-స్టార్ట్ను మార్చండి.
- OmniRouteను ఆపండి.

ఈ ఆప్షన్లతో `--tray`ను కలిపి ఉపయోగించవద్దు:

- `--daemon`
- `--log`
- `--no-recovery`

ఈ మోడ్లకు వేర్వేరు ప్రాసెస్ యాజమాన్యం అవసరం.

తదుపరి మెషీన్ లాగిన్ సమయంలో స్టార్టప్ను ప్రారంభించండి:

```bash
omniroute autostart enable
```

macOS, Windows మరియు గ్రాఫికల్ Linux సెషన్లలో ఆటో-స్టార్ట్ ట్రే మోడ్ను ఉపయోగిస్తుంది. హెడ్లెస్ Linux ఇప్పటికే ఉన్న systemd యూజర్ సర్వీస్ను ఉపయోగిస్తుంది.

లాగిన్ సమయంలో స్టార్టప్ను నిలిపివేయండి:

```bash
omniroute autostart disable
```

### అన్ఇన్స్టాల్ చేయడం

మీకు ఇకపై OmniRoute అవసరం లేనప్పుడు, పూర్తిగా తొలగించడానికి మేము రెండు శీఘ్ర స్క్రిప్ట్లను అందిస్తున్నాము:

| కమాండ్                   | చర్య                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| `npm run uninstall`      | సిస్టమ్ యాప్ను తొలగిస్తుంది, కానీ `~/.omniroute`లోని **మీ DB మరియు కాన్ఫిగరేషన్లను ఉంచుతుంది**.  |
| `npm run uninstall:full` | యాప్ను తొలగించడంతో పాటు **అన్ని కాన్ఫిగరేషన్లు, కీలు మరియు డేటాబేస్లను శాశ్వతంగా తొలగిస్తుంది**. |

> గమనిక: ఈ కమాండ్లను అమలు చేయడానికి, OmniRoute ప్రాజెక్ట్ ఫోల్డర్కు వెళ్లి (మీరు దాన్ని క్లోన్ చేసి ఉంటే) వాటిని అమలు చేయండి. ప్రత్యామ్నాయంగా, గ్లోబల్గా ఇన్స్టాల్ చేసి ఉంటే, మీరు కేవలం `npm uninstall -g omniroute`ను అమలు చేయవచ్చు.

### Void Linux (xbps-src)

Void Linux వినియోగదారులు `xbps-src` క్రాస్-కంపైలేషన్ ఫ్రేమ్వర్క్ను ఉపయోగించి OmniRouteను స్థానికంగా ప్యాకేజ్ చేసి ఇన్స్టాల్ చేయవచ్చు. ఇది అవసరమైన `better-sqlite3` నేటివ్ బైండింగ్లతో పాటు Node.js స్వతంత్ర బిల్డ్ను ఆటోమేట్ చేస్తుంది.

```bash

pkgname=omniroute

do_build() {
	# node-gyp కోసం లక్ష్య CPU ఆర్కిటెక్చర్ను నిర్ధారించండి
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) అన్ని డిపెండెన్సీలను ఇన్స్టాల్ చేయండి – స్క్రిప్ట్లను దాటవేయండి
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Next.js స్వతంత్ర బండిల్ను బిల్డ్ చేయండి
	npm run build

	# 3) స్టాటిక్ అసెట్లను స్వతంత్ర బండిల్లోకి కాపీ చేయండి
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) better-sqlite3 నేటివ్ బైండింగ్ను కంపైల్ చేయండి
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) కంపైల్ చేసిన బైండింగ్ను స్వతంత్ర బండిల్లో ఉంచండి
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) ఆర్కిటెక్చర్-నిర్దిష్ట sharp బండిల్లను తొలగించండి
	rm -rf .next/standalone/node_modules/@img

	# 7) Next.js స్టాటిక్ విశ్లేషణ విస్మరించిన pino రన్టైమ్ డిపెండెన్సీలను కాపీ చేయండి:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# పోస్ట్-ఇన్స్టాల్ హుక్ ద్వారా ఖాళీ Next.js యాప్ రౌటర్ డైరెక్టరీలు తొలగించబడకుండా నిరోధించండి
	for _d in \

		.next/standalone/.next/server/app/dashboard/settings \

}
```

## 🧩 అధునాతన ఫీచర్లు

### అనుకూల నమూనాలు

యాప్ అప్డేట్ కోసం వేచి ఉండకుండా ఏదైనా ప్రొవైడర్కి ఏదైనా మోడల్ ID జోడించండి:

```bash
# Via API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# List: curl http://localhost:20128/api/provider-models?provider=openai
# Remove: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

లేదా డాష్బోర్డ్ని ఉపయోగించండి:** ప్రొవైడర్లు → [ప్రొవైడర్] → కస్టమ్ మోడల్స్** .

గమనికలు:

- OpenRouter మరియు OpenAI/Anthropic-compatible ప్రొవైడర్లు నుండి నిర్వహించబడుతున్నాయి** అందుబాటులో ఉన్న నమూనాలు** మాత్రమే. మాన్యువల్ యాడ్, దిగుమతి మరియు స్వయంచాలకంగా ఒకే అందుబాటులో ఉన్న మోడల్ జాబితాలో మొత్తం భూమిని సమకాలీకరించండి, కాబట్టి ఆ ప్రొవైడర్ల కోసం ప్రత్యేక కస్టమ్ మోడల్ల విభాగం లేదు.
- ది** అనుకూల నమూనాలు** విభాగం నిర్వహించబడే అందుబాటులో ఉన్న-మోడల్ దిగుమతులను బహిర్గతం చేయని ప్రొవైడర్ల కోసం ఉద్దేశించబడింది.

### అనుకూల OpenAI-అనుకూల ప్రొవైడర్లు

OpenAI API (స్వీయ-హోస్ట్ చేసిన ప్రాక్సీ, vLLM, మూడవ పక్ష అగ్రిగేటర్) మాట్లాడే ఏదైనా గేట్వే దాని స్వంత ప్రొవైడర్ నోడ్గా జోడించబడుతుంది:

1. **ప్రొవైడర్లు → OpenAI అనుకూలతను జోడించండి** .
2. **పేరు** : నోడ్ కోసం ఒక ప్రదర్శన లేబుల్.
3. **ఉపసర్గ** : రూటింగ్ పేరు. క్లయింట్లు మోడల్లను `<prefix>/<model>` అని పిలుస్తారు, కాబట్టి `mygw` ఉపసర్గతో కూడిన నోడ్ `mygw/gpt-4o-mini` ఉపయోగపడుతుంది. అవసరం; పాత్ర పరిమితి లేదు.
4. **API రకం** : గేట్వే అందించే ఎండ్పాయింట్ కుటుంబం (చాట్ పూర్తిలు, ప్రతిస్పందనలు, ఎంబెడ్డింగ్లు, ఆడియో, చిత్రాలు).
5. **బేస్ URL** : API రూట్, `/v1` వరకు మరియు సహా (ఉదాహరణకు `https://gateway.example.com/v1`), పూర్తి `/chat/completions` మార్గం కాదు. ప్రామాణికం కాని మార్గాలతో గేట్వేలు వాటిని కింద ఉంచాయి** అధునాతన సెట్టింగ్లు** (చాట్ పాత్, మోడల్స్ పాత్).
6. ది**API కీ (తనిఖీ కోసం)** ఫీల్డ్ కనెక్షన్ని మాత్రమే పరీక్షిస్తుంది. నోడ్ను సృష్టించిన తర్వాత, దాన్ని తెరిచి ఉపయోగించండి** కనెక్షన్ జోడించండి** అభ్యర్థనలు ఉపయోగించే కీని నిల్వ చేయడానికి.

నోడ్ రూపం `openai-compatible-<apiType>-<uuid>` యొక్క అంతర్గత idని పొందుతుంది; మీరు దీన్ని ఎప్పటికీ టైప్ చేయవలసిన అవసరం లేదు, ఉపసర్గ అనేది పబ్లిక్ పేరు.

#### రిజర్వు చేయబడిన ఉపసర్గలు

ఉపసర్గ అనేది అంతర్నిర్మిత ప్రొవైడర్ యొక్క id లేదా మారుపేరు (ఉదాహరణకు `openai`, `cf`) లేదా రిటైర్డ్ ప్రొవైడర్ యొక్క id కాకూడదు. కస్టమ్ నోడ్ల ముందు మోడల్ రిజల్యూర్ అంతర్నిర్మిత idలు మరియు మారుపేర్లను తనిఖీ చేస్తుంది, కాబట్టి ఆ ప్రిఫిక్స్లలో ఒకదానిని ఉపయోగించే నోడ్ ఎప్పటికీ ట్రాఫిక్ని అందుకోదు: బదులుగా `<prefix>/model` అంతర్నిర్మిత ప్రొవైడర్కి వెళుతుంది లేదా ఆ ప్రొవైడర్ రిటైర్ చేయబడితే మూసివేయబడుతుంది. అటువంటి ఉపసర్గతో నోడ్ని సృష్టించడం లేదా సవరించడం దీనితో తిరస్కరించబడుతుంది:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

ఒక ప్రత్యేక ఉపసర్గ (`mygw`, `acme-proxy`) ఎంచుకోండి. కస్టమ్ నోడ్కు అభ్యర్థనలు అంతర్నిర్మిత ప్రొవైడర్ లేదా దాని ఆధారాలను పేర్కొనే లోపంతో విఫలమైతే, నోడ్ యొక్క ఉపసర్గ రిజర్వ్ చేయబడిందో లేదో తనిఖీ చేయండి: ఈ నియమం ఉనికిలో ఉండక ముందు సేవ్ చేయబడిన నోడ్లు ఇప్పటికీ నిల్వ చేయబడి ఉంటాయి, కానీ వాటి ఉపసర్గ మార్గాలు అంతర్నిర్మిత ప్రొవైడర్కు. నోడ్ని సవరించి, దానికి కొత్త ఉపసర్గను ఇవ్వండి.

#### ప్రతి-కనెక్షన్ గేట్వే ఎంపికలు

ఈ కీలు కనెక్షన్ యొక్క `providerSpecificData` లో వెళ్తాయి (ఉదాహరణకు `PUT /api/providers/{id}` ద్వారా):

- `toolNameMaxLength` (పూర్ణాంకం, 1–1024) — OpenAI చాట్-ఫార్మాట్ అనుకూల కనెక్షన్ల కోసం, దీని గేట్వే పొడవైన సాధనాల పేర్లను తిరస్కరించింది. పొడవైన పేర్లు చిన్న మారుపేర్లుగా పంపబడతాయి మరియు ప్రతిస్పందనలో పునరుద్ధరించబడతాయి.
- `quotaEndpoint` — గేట్వే యొక్క quota/credits ముగింపు స్థానం, డాష్బోర్డ్ కోటా స్ట్రిప్ మరియు కోటా-అవేర్ రూటింగ్ కోసం చదవండి. OpenAI- మరియు ఆంత్రోపిక్-అనుకూల కనెక్షన్లు రెండింటిలోనూ పని చేస్తుంది; పూర్తి ఆకారం `open-sse/services/usage/openaiCompatible.ts` లో డాక్యుమెంట్ చేయబడింది.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### చైనింగ్ OmniRoute పీర్స్

మరొక OmniRoute గేట్వేని a వలె జోడించవచ్చు** అనుకూల OpenAI-అనుకూలమైనది** ప్రొవైడర్. పీర్ యొక్క `/v1` బేస్ URL మరియు ఆ పీర్ జారీ చేసిన డెడికేటెడ్, మినిస్ట్ ప్రివిలేజ్ API కీని ఉపయోగించండి.

పరస్పర లేదా బహుళ-హాప్ చైన్ల కోసం, ప్రతి గేట్వేలో ఆప్ట్-ఇన్ లూప్ గార్డ్ను ప్రారంభించండి:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

స్పష్టంగా అనుమతించబడిన పీర్ URL కి పంపిన అభ్యర్థనలు మాత్రమే `X-OmniRoute-Peer-Trace` హెడర్ను స్వీకరిస్తాయి. HTTP `508 Loop Detected` తో పునరావృతమయ్యే ID లేదా అయిపోయిన హాప్ బడ్జెట్ను గేట్వే తిరస్కరిస్తుంది; సాధారణ అప్స్ట్రీమ్ ప్రొవైడర్లు పీర్ మెటాడేటాను స్వీకరించరు.

పీర్ చైనింగ్ అనేది డేటాబేస్ రెప్లికేషన్ లేదా హోస్ట్ ఫెయిల్ఓవర్ కాదు. ప్రతి గేట్వే స్వతంత్ర SQLite స్థితి, కాష్లు, రేట్ కౌంటర్లు మరియు సెషన్లను ఉంచుతుంది. active/passive లేదా active/active లభ్యత కోసం ఆరోగ్య తనిఖీ చేసిన రివర్స్ ప్రాక్సీ లేదా క్లయింట్ ఫెయిల్ఓవర్ని ఉపయోగించండి మరియు ఒక SQLite డేటాబేస్ను బహుళ రన్నింగ్ OmniRoute ఇన్స్టాన్స్లలోకి మౌంట్ చేయవద్దు.

### డెడికేటెడ్ ప్రొవైడర్ రూట్లు

మోడల్ ధ్రువీకరణతో నిర్దిష్ట ప్రొవైడర్కు నేరుగా రూట్ అభ్యర్థనలు:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

ప్రొవైడర్ ప్రిఫిక్స్ మిస్ అయినట్లయితే స్వయంచాలకంగా జోడించబడుతుంది. సరిపోలని మోడల్లు తిరిగి `400`.

### నెట్వర్క్ ప్రాక్సీ కాన్ఫిగరేషన్

```bash
# Set global proxy
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# Per-provider proxy
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# Test proxy
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**ప్రాధాన్యత:** కీ-నిర్దిష్ట → కాంబో-నిర్దిష్ట → ప్రొవైడర్-నిర్దిష్ట → గ్లోబల్ → ఎన్విరాన్మెంట్.

### మోడల్ కేటలాగ్ API

```bash
curl http://localhost:20128/api/models/catalog
```

రకాల (`chat`, `embedding`, `image`) ప్రొవైడర్ ద్వారా సమూహం చేయబడిన మోడల్లను అందిస్తుంది.

### క్లౌడ్ సమకాలీకరణ

- పరికరాల అంతటా ప్రొవైడర్లు, కాంబోలు మరియు సెట్టింగ్లను సమకాలీకరించండి
- సమయం ముగిసింది + వైఫల్యంతో స్వయంచాలక నేపథ్య సమకాలీకరణ
- ఉత్పత్తిలో సర్వర్ వైపు `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` ని ఇష్టపడండి

### Cloudflare త్వరిత సొరంగం

- లో అందుబాటులో ఉంది** డాష్బోర్డ్ → ముగింపు పాయింట్లు** Docker మరియు ఇతర స్వీయ-హోస్ట్ విస్తరణల కోసం
- మీ ప్రస్తుత OpenAI-అనుకూల `/v1` ఎండ్పాయింట్కి ఫార్వార్డ్ చేసే తాత్కాలిక `https://*.trycloudflare.com` URL సృష్టిస్తుంది
- ముందుగా అవసరమైనప్పుడు మాత్రమే `cloudflared` ఇన్స్టాల్లను ప్రారంభించండి; తర్వాత పునఃప్రారంభించబడిన అదే నిర్వహించబడే బైనరీని మళ్లీ ఉపయోగిస్తుంది
- OmniRoute లేదా కంటైనర్ రీస్టార్ట్ తర్వాత త్వరిత సొరంగాలు స్వయంచాలకంగా పునరుద్ధరించబడవు; అవసరమైనప్పుడు వాటిని డాష్బోర్డ్ నుండి మళ్లీ ప్రారంభించండి
- టన్నెల్ URLs అశాశ్వతమైనవి మరియు మీరు టన్నెల్ను stop/start ప్రతిసారీ మారుతాయి
- నిర్బంధ కంటైనర్లలో ధ్వనించే QUIC UDP బఫర్ హెచ్చరికలను నివారించడానికి HTTP/2 రవాణాకు డిఫాల్ట్గా నిర్వహించబడే త్వరిత సొరంగాలు
- మీరు నిర్వహించబడే రవాణా ఎంపికను భర్తీ చేయాలనుకుంటే `CLOUDFLARED_PROTOCOL=quic` లేదా `auto` సెట్ చేయండి
- మీరు నిర్వహించబడే డౌన్లోడ్కు బదులుగా ప్రీఇన్స్టాల్ చేసిన `cloudflared` బైనరీని ఉపయోగించాలనుకుంటే `CLOUDFLARED_BIN` సెట్ చేయండి
- Cloudflare క్విక్ టన్నెల్, Tailscale ఫన్నెల్ మరియు ngrok టన్నెల్ ప్యానెల్లను ఇందులో చూపవచ్చు లేదా దాచవచ్చు** సెట్టింగులు → స్వరూపం** . ప్యానెల్ను దాచడం వల్ల నడుస్తున్న సొరంగం ఆగదు.

### LLM గేట్వే ఇంటెలిజెన్స్ (ఫేజ్ 9)

- **సెమాంటిక్ కాష్** — స్వయంచాలక-కాష్లు నాన్-స్ట్రీమింగ్, ఉష్ణోగ్రత = 0 ప్రతిస్పందనలు ( `X-OmniRoute-No-Cache: true` తో బైపాస్)
- **ఐడెంపోటెన్సీని అభ్యర్థించండి** — `Idempotency-Key` లేదా `X-Request-Id` హెడర్ ద్వారా 5సెలోపు అభ్యర్థనలను నకిలీ చేస్తుంది
- **ప్రోగ్రెస్ ట్రాకింగ్** — `X-OmniRoute-Progress: true` హెడర్ ద్వారా SSE `event: progress` ఈవెంట్లను ప్రారంభించండి

### అనువాదకుని ప్లేగ్రౌండ్

ద్వారా యాక్సెస్** డాష్బోర్డ్ → అనువాదకుడు** . ప్రొవైడర్ల మధ్య API అభ్యర్థనలను OmniRoute ఎలా అనువదిస్తుందో డీబగ్ చేయండి మరియు దృశ్యమానం చేయండి.

| మోడ్                  | ప్రయోజనం                                                                                                 |
| --------------------- | -------------------------------------------------------------------------------------------------------- |
| **ప్లేగ్రౌండ్**       | source/target ఫార్మాట్లను ఎంచుకోండి, అభ్యర్థనను అతికించండి మరియు తక్షణమే అనువదించబడిన అవుట్పుట్ను చూడండి |
| **చాట్ టెస్టర్**      | ప్రాక్సీ ద్వారా ప్రత్యక్ష చాట్ సందేశాలను పంపండి మరియు పూర్తి request/response చక్రాన్ని తనిఖీ చేయండి     |
| **టెస్ట్ బెంచ్**      | అనువాద ఖచ్చితత్వాన్ని ధృవీకరించడానికి బహుళ ఫార్మాట్ కలయికలలో బ్యాచ్ పరీక్షలను అమలు చేయండి                |
| **ప్రత్యక్ష మానిటర్** | ప్రాక్సీ ద్వారా అభ్యర్థనలు ప్రవహిస్తున్నప్పుడు నిజ-సమయ అనువాదాలను చూడండి                                 |

**సందర్భాలలో ఉపయోగించండి:**

- నిర్దిష్ట client/provider కలయిక ఎందుకు విఫలమవుతుందో డీబగ్ చేయండి
- ఆలోచన ట్యాగ్లు, టూల్ కాల్లు మరియు సిస్టమ్ ప్రాంప్ట్లు సరిగ్గా అనువదించబడుతున్నాయని ధృవీకరించండి
- OpenAI, Claude, Gemini, మరియు ప్రతిస్పందనల API ఫార్మాట్ల మధ్య ఫార్మాట్ తేడాలను సరిపోల్చండి

### రూటింగ్ వ్యూహాలు

ద్వారా కాన్ఫిగర్ చేయండి** డాష్బోర్డ్ → సెట్టింగ్లు → రూటింగ్** . డాష్బోర్డ్ ఆరు ఎక్కువగా ఉపయోగించే వ్యూహాలను బహిర్గతం చేస్తుంది; కాంబోలు మరియు ఆటో-రూటర్ అంతర్గతంగా విస్తృత సెట్కు మద్దతు ఇస్తాయి.

**డాష్బోర్డ్-కనిపించే వ్యూహాలు (ఖాతా-స్థాయి రూటింగ్):**

| వ్యూహం                        | వివరణ                                                                                                          |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **ముందుగా పూరించండి**         | ప్రాధాన్యత క్రమంలో ఖాతాలను ఉపయోగిస్తుంది — ప్రాథమిక ఖాతా అందుబాటులో లేని వరకు అన్ని అభ్యర్థనలను నిర్వహిస్తుంది |
| **రౌండ్ రాబిన్**              | కాన్ఫిగర్ చేయగల స్టిక్కీ పరిమితితో అన్ని ఖాతాల ద్వారా సైకిల్లు (డిఫాల్ట్: ప్రతి ఖాతాకు 3 కాల్లు)               |
| **P2C (రెండు ఎంపికల శక్తి)**  | 2 యాదృచ్ఛిక ఖాతాలు మరియు ఆరోగ్యకరమైన వాటి కోసం మార్గాలను ఎంచుకుంటుంది - ఆరోగ్యంపై అవగాహనతో బ్యాలెన్స్ లోడ్     |
| **యాదృచ్ఛికంగా**              | ఫిషర్-యేట్స్ షఫుల్ ఉపయోగించి ప్రతి అభ్యర్థన కోసం యాదృచ్ఛికంగా ఖాతాను ఎంచుకుంటుంది                              |
| **తక్కువగా ఉపయోగించబడింది**   | పాత `lastUsedAt` టైమ్స్టాంప్తో ఖాతాకు మార్గాలు, ట్రాఫిక్ను సమానంగా పంపిణీ చేస్తుంది                            |
| **ఖర్చు ఆప్టిమైజ్ చేయబడింది** | అత్యల్ప ప్రాధాన్యత విలువ కలిగిన ఖాతాకు రూట్లు, తక్కువ ధర కలిగిన ప్రొవైడర్ల కోసం ఆప్టిమైజ్ చేయడం                |

**అధునాతన కాంబో మరియు ఆటో స్ట్రాటజీలు** (కాంబోకు లేదా `auto/*` ఉపసర్గల ద్వారా కాన్ఫిగర్ చేయవచ్చు — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) చూడండి):

- `priority` - కఠినమైన క్రమం, ఎప్పుడూ రౌండ్-రాబిన్స్ కాదు
- `weighted` — అనుపాత ట్రాఫిక్ ప్రతి మోడల్ బరువుల ద్వారా విభజించబడింది
- `fill-first` — పరిమితులు కొట్టే వరకు మొదటి మోడల్ను తీసివేయండి
- `round-robin` / `strict-random` / `random`
- `p2c` (రెండు ఎంపికల శక్తి)
- `least-used` మరియు `cost-optimized`
- `auto` — అభ్యర్థులందరిలో స్కోర్-డ్రైవెన్
- `lkgp` (చివరిగా తెలిసిన మంచి ప్రొవైడర్) — చివరిగా విజయవంతమైన ప్రొవైడర్కు పిన్ చేసి, ఆపై నిబంధనలకు తిరిగి వస్తుంది
- `context-optimized` — అతిపెద్ద ఉచిత సందర్భ విండోతో మోడల్ను ఎంచుకుంటుంది
- `context-relay` — ఫాలో-అప్ మలుపుల కోసం దీర్ఘ-సందర్భ నమూనాల గొలుసులు

#### బాహ్య అంటుకునే సెషన్ హెడర్

బాహ్య సెషన్ అనుబంధం కోసం (ఉదాహరణకు, రివర్స్ ప్రాక్సీల వెనుక ఉన్న Claude Code/Codex ఏజెంట్లు), పంపండి:

```http
X-Session-Id: your-session-key
```

OmniRoute కూడా `x_session_id` అంగీకరిస్తుంది మరియు `X-OmniRoute-Session-Id` లో ప్రభావవంతమైన సెషన్ కీని అందిస్తుంది.

మీరు Nginxని ఉపయోగిస్తే మరియు అండర్స్కోర్-ఫారమ్ హెడర్లను పంపితే, ప్రారంభించండి:

```nginx
underscores_in_headers on;
```

#### వైల్డ్కార్డ్ మోడల్ మారుపేర్లు

మోడల్ పేర్లను రీమాప్ చేయడానికి వైల్డ్కార్డ్ నమూనాలను సృష్టించండి:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

వైల్డ్కార్డ్లు `*` (ఏదైనా అక్షరాలు) మరియు `?` (ఒకే అక్షరం)కి మద్దతు ఇస్తాయి.

#### ఫాల్బ్యాక్ చైన్స్

అన్ని అభ్యర్థనలకు వర్తించే గ్లోబల్ ఫాల్బ్యాక్ చైన్లను నిర్వచించండి:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### సాధారణ ప్రొవైడర్ కలయికలు & రూటింగ్ నమూనాలు

బహుళ ప్రొవైడర్లను కలపడం మరియు OmniRoute లో వాటి మధ్య రూటింగ్ చేయడం కోసం ఇక్కడ ఉదాహరణ నమూనాలు ఉన్నాయి:

#### 1. కోడింగ్ ఏజెంట్ కాంబో: Cost/Speed ఫాల్బ్యాక్తో హై-ఎండ్ రీజనింగ్

కోడింగ్ ఏజెంట్లకు అనువైనది (OpenCode, Claude కోడ్, Cursor, Cline). ముందుగా సరిహద్దు రీజనింగ్ మోడల్లకు రూట్లు, కోటా ఎగ్జాషన్ లేదా ఎర్రర్ల కారణంగా ఫాస్ట్ కోడింగ్ మోడల్లకు తిరిగి వస్తాయి.

- **డాష్బోర్డ్** : కాంబోస్ → కొత్త కాంబో → పేరు: `agent-coding` → వ్యూహం: `Priority`
- **మోడల్స్** :
  1. `claude/claude-sonnet-4-6` (ప్రాధమిక కోడింగ్ ఏజెంట్)
  2. `openai/gpt-4o` (సెకండరీ హై-కెపాసిటీ ఫాల్బ్యాక్)
  3. `deepseek/deepseek-v4-flash` (అధిక సామర్థ్యం, తక్కువ ఖర్చుతో కూడిన ఫాల్బ్యాక్)

```bash
# Example via API
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

#### 2. ఫ్రీ-టైర్ ఆటో ఫెయిల్ఓవర్ కాంబో

API ఖర్చులు లేకుండా సమయ వ్యవధిని పెంచడానికి బహుళ ఫ్రీ-టైర్ మరియు కీలెస్ ప్రొవైడర్లను కలిగి ఉంటుంది.

- **వ్యూహం** : `Least Used` లేదా `Round Robin` (కోటాలలో లోడ్ను పంపిణీ చేస్తుంది)
- **మోడల్స్** :
  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

```bash
# Example via CLI
omniroute combo create free-stack \
  --models "groq/llama-3.3-70b-versatile,gemini/gemini-2.5-flash,cerebras/gpt-oss-120b" \
  --strategy round-robin
```

#### 3. మల్టీమోడల్ / విజన్ & టెక్స్ట్ పైప్లైన్

ఇమేజ్ అవగాహన మరియు కోడ్ ఉత్పత్తితో కూడిన వర్క్ఫ్లోల కోసం హై-స్పీడ్ టెక్స్ట్ జనరేషన్తో ప్రత్యేకమైన విజన్ మోడల్లను జత చేయడం.

- **నమూనా** : `Priority` కాంబో ముందుగా దృష్టి-సామర్థ్యం గల మోడల్లను మరియు చివరిగా అధిక-నిర్గమాంశ text/code మోడల్ను జాబితా చేస్తుంది.
- **మోడల్స్** :
  1. `gemini/gemini-2.5-pro` (బలమైన image/multimodal గ్రహణశక్తి)
  2. `openai/gpt-4o` (సమతుల్య దృష్టి మరియు సాధన వినియోగం)
  3. `deepseek/deepseek-v4-flash` (Text/code తరం)

### రెసిలెన్స్ & సర్క్యూట్ బ్రేకర్లు

ద్వారా కాన్ఫిగర్ చేయండి** డాష్బోర్డ్ → సెట్టింగ్లు → రెసిలెన్స్** .

OmniRoute ఐదు భాగాలతో ప్రొవైడర్-స్థాయి స్థితిస్థాపకతను అమలు చేస్తుంది:

1. **క్యూ & పేసింగ్ని అభ్యర్థించండి** — సిస్టమ్-స్థాయి అభ్యర్థన ఆకృతి:
   - **నిమిషానికి అభ్యర్థనలు (RPM)** - ఒక్కో ఖాతాకు నిమిషానికి గరిష్ట అభ్యర్థనలు
   - **అభ్యర్థనల మధ్య కనీస సమయం** - అభ్యర్థనల మధ్య మిల్లీసెకన్లలో కనీస గ్యాప్
   - **గరిష్ట ఏకకాల అభ్యర్థనలు** - ఒక్కో ఖాతాకు గరిష్ట ఏకకాల అభ్యర్థనలు

2. **కనెక్షన్ కూల్డౌన్** — మళ్లీ ప్రయత్నించగల వైఫల్యాల తర్వాత ఒకే కనెక్షన్ కోసం ప్రతి ప్రమాణ-రకం కాన్ఫిగరేషన్:
   - **బేస్ కూల్డౌన్** — మళ్లీ ప్రయత్నించదగిన అప్స్ట్రీమ్ వైఫల్యాల కోసం డిఫాల్ట్ కూల్డౌన్ విండో
   - **అప్స్ట్రీమ్ మళ్లీ ప్రయత్నించు సూచనలను ఉపయోగించండి** — అందించినప్పుడు అధికారిక `Retry-After` లేదా రీసెట్ సూచనలను గౌరవిస్తుంది
   - **గరిష్ట బ్యాక్ఆఫ్ దశలు** - పునరావృత వైఫల్యాల కోసం గరిష్ట ఎక్స్పోనెన్షియల్ బ్యాక్ఆఫ్ స్థాయి

3. **ప్రొవైడర్ సర్క్యూట్ బ్రేకర్** — ఎండ్-టు-ఎండ్ ప్రొవైడర్ వైఫల్యాలను ట్రాక్ చేస్తుంది, కాన్ఫిగర్ చేయబడిన హెచ్చరిక థ్రెషోల్డ్ వద్ద డిగ్రేడ్ చేయబడిన ప్రొవైడర్ను గుర్తు చేస్తుంది మరియు కాన్ఫిగర్ చేయబడిన వైఫల్యం థ్రెషోల్డ్ చేరుకున్నప్పుడు బ్రేకర్ను తెరుస్తుంది:
   - **క్షీణత థ్రెషోల్డ్** — `DEGRADED` లోకి ప్రవేశించే ముందు వరుస ప్రొవైడర్ వైఫల్యాలు
   - **వైఫల్యం థ్రెషోల్డ్** — `OPEN` లోకి ప్రవేశించే ముందు వరుస ప్రొవైడర్ వైఫల్యాలు
   - **గడువు ముగిసింది** — ప్రొవైడర్ మళ్లీ పరీక్షించబడటానికి ముందు సమయ విండో
   - **CLOSED** (ఆరోగ్యకరమైనది) - అభ్యర్థనలు సాధారణంగా ప్రవహిస్తాయి
   - **DEGRADED** - ఎలివేటెడ్ వైఫల్యాలు ట్రాక్ చేయబడినప్పుడు అభ్యర్థనలు ఇప్పటికీ ప్రవహిస్తాయి
   - **OPEN** — పునరావృత వైఫల్యాల తర్వాత ప్రొవైడర్ తాత్కాలికంగా బ్లాక్ చేయబడింది
   - **HALF_OPEN** - ప్రొవైడర్ కోలుకున్నారో లేదో పరీక్షించడం

   కనెక్షన్-స్కోప్డ్ `429` రేట్ పరిమితులు అలాగే ఉంటాయి** కనెక్షన్ కూల్డౌన్** మరియు ప్రొవైడర్ బ్రేకర్ వైపు లెక్కించవద్దు.

   ప్రొవైడర్ బ్రేకర్ రన్టైమ్ స్థితి ఆన్లో చూపబడింది** డాష్బోర్డ్ → ఆరోగ్యం** మాత్రమే.

4. **కూల్డౌన్ కోసం వేచి ఉండండి** — ప్రతి అభ్యర్థి కనెక్షన్ ఇప్పటికే చల్లబడి ఉంటే, OmniRoute తొలి కూల్డౌన్ కోసం వేచి ఉండి, అదే క్లయింట్ అభ్యర్థనను స్వయంచాలకంగా మళ్లీ ప్రయత్నించవచ్చు.

5. **రేట్ లిమిట్ ఆటో-డిటెక్షన్** — అప్స్ట్రీమ్ ప్రొవైడర్లు స్పష్టమైన నిరీక్షణ విండోలను తిరిగి ఇచ్చినప్పుడు, సెట్టింగ్ ప్రారంభించబడినప్పుడు ఆ సూచనలు స్థానిక కనెక్షన్ కూల్డౌన్ను భర్తీ చేస్తాయి.

**ప్రో చిట్కా:** ఉపయోగించండి** ఆరోగ్యం** అంతరాయం తర్వాత లైవ్ ప్రొవైడర్ బ్రేకర్లను తనిఖీ చేయడానికి మరియు రీసెట్ చేయడానికి పేజీ. స్థితిస్థాపకత పేజీ కాన్ఫిగరేషన్ను మాత్రమే మారుస్తుంది.

| **ఎగుమతి డేటాబేస్**                    | ప్రస్తుత SQLite డేటాబేస్ను `.sqlite` ఫైల్గా డౌన్లోడ్ చేస్తుంది                                                                                                    |
| **అన్నింటినీ ఎగుమతి చేయండి (.tar.gz)** | పూర్తి బ్యాకప్ ఆర్కైవ్ను డౌన్లోడ్ చేస్తుంది: డేటాబేస్, సెట్టింగ్లు, కాంబోలు, ప్రొవైడర్ కనెక్షన్లు (క్రెడెన్షియల్స్ లేవు), API కీ మెటాడేటా                         |
| **దిగుమతి డేటాబేస్**                   | ప్రస్తుత డేటాబేస్ భర్తీ చేయడానికి `.sqlite` ఫైల్ను అప్లోడ్ చేయండి. `DISABLE_SQLITE_AUTO_BACKUP=true` తప్ప, ముందస్తు దిగుమతి బ్యాకప్ స్వయంచాలకంగా సృష్టించబడుతుంది |

```bash
# API: Export database
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: Export all (full archive)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: Import database
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**దిగుమతి ధృవీకరణ:** దిగుమతి చేయబడిన ఫైల్ సమగ్రత (SQLite ప్రాగ్మా తనిఖీ), అవసరమైన పట్టికలు (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) మరియు పరిమాణం (గరిష్టంగా 100MB) కోసం ధృవీకరించబడింది.

**కేసులను ఉపయోగించండి:**

- యంత్రాల మధ్య OmniRoute మైగ్రేట్ చేయండి
- విపత్తు పునరుద్ధరణ కోసం బాహ్య బ్యాకప్లను సృష్టించండి
- బృంద సభ్యుల మధ్య కాన్ఫిగరేషన్లను భాగస్వామ్యం చేయండి (అన్ని → షేర్ ఆర్కైవ్ను ఎగుమతి చేయండి)

### సెట్టింగ్ల డాష్బోర్డ్

సెట్టింగుల పేజీ నిర్వహించబడింది** 7 ట్యాబ్లు** సులభమైన నావిగేషన్ కోసం:

| ట్యాబ్            | కంటెంట్లు                                                                                                                                                                                      |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| **స్వరూపం**       | థీమ్ నియంత్రణలు (light/dark/system), సైడ్బార్ విజిబిలిటీ, Cloudflare/Tailscale/ngrok టన్నెల్ కార్డ్ల కోసం ప్యానెల్ టోగుల్లు                                                                    |
| **AI**            | థింకింగ్ బడ్జెట్ (పాస్త్రూ / ఆటో-స్ట్రిప్ / కస్టమ్ / అడాప్టివ్ — చూడండి [THINKING_BUDGET.md](./THINKING_BUDGET.md) ), గ్లోబల్ సిస్టమ్ ప్రాంప్ట్, ప్రాంప్ట్ కాష్ గణాంకాలు                       |

| **స్థితిస్థాపకత** | క్యూ, కనెక్షన్ కూల్డౌన్, ప్రొవైడర్ బ్రేకర్ కాన్ఫిగరేషన్ మరియు వెయిట్-ఫర్ కూల్డౌన్ ప్రవర్తనను అభ్యర్థించండి                                                                                     |

సాధారణం ఇకపై చదవడానికి మాత్రమే లాగింగ్ మరియు కాష్ నోట్లను నకిలీ చేయదు. డేటాబేస్ నిలుపుదల మరియు ఆప్టిమైజేషన్ సెట్టింగ్లు `/api/settings/database` ద్వారా కొనసాగించబడతాయి; మాన్యువల్ కాష్ క్లియరింగ్ `DELETE /api/cache` ఉపయోగిస్తుంది. అభ్యర్థన మరియు ప్రాక్సీ లాగ్ వరుస క్యాప్లు `CALL_LOGS_TABLE_MAX_ROWS` మరియు `PROXY_LOGS_TABLE_MAX_ROWS` ద్వారా నియంత్రించబడతాయి.

### ఖర్చులు & బడ్జెట్ నిర్వహణ

ద్వారా యాక్సెస్** డాష్బోర్డ్ → ఖర్చులు** .

| ట్యాబ్             | ప్రయోజనం                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| **బడ్జెట్**        | daily/weekly/monthly బడ్జెట్లు మరియు నిజ-సమయ ట్రాకింగ్తో ప్రతి API కీకి ఖర్చు పరిమితులను సెట్ చేయండి |
| **ధర నిర్ణయించడం** | మోడల్ ధర నమోదులను వీక్షించండి మరియు సవరించండి — ప్రతి ప్రొవైడర్కు 1K input/output టోకెన్ల ధర         |

```bash
# API: Set a budget
curl -X POST http://localhost:20128/api/usage/budget \
  -H "Content-Type: application/json" \
  -d '{"keyId": "key-123", "limit": 50.00, "period": "monthly"}'

# API: Get current budget status
curl http://localhost:20128/api/usage/budget
```

**ఖర్చు ట్రాకింగ్:** ప్రతి అభ్యర్థన టోకెన్ వినియోగాన్ని లాగ్ చేస్తుంది మరియు ధర పట్టికను ఉపయోగించి ధరను గణిస్తుంది. లో విచ్ఛిన్నాలను వీక్షించండి** డాష్బోర్డ్ → వినియోగం** ప్రొవైడర్, మోడల్ మరియు API కీ ద్వారా.

### ఆడియో ట్రాన్స్క్రిప్షన్

OmniRoute OpenAI-అనుకూల ముగింపు పాయింట్ ద్వారా ఆడియో ట్రాన్స్క్రిప్షన్కు మద్దతు ఇస్తుంది:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# Example with curl
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

`deepgram/nova-3` అనేది స్థానిక డీప్గ్రామ్ మార్గం మరియు దీనికి డీప్గ్రామ్ API కీ అవసరం. OpenRouter మాత్రమే కాన్ఫిగర్ చేయబడితే, `openrouter/deepgram/nova-3` ఉపయోగించండి.

**స్పీచ్-టు-టెక్స్ట్ (ట్రాన్స్క్రిప్షన్)** ప్రొవైడర్లు:

- `groq/` (Groq విస్పర్ టర్బో)
- `deepgram/` (నోవా కుటుంబం)

- `qwen/`

**టెక్స్ట్-టు-స్పీచ్ (`POST /v1/audio/speech`)** ప్రొవైడర్లు:

### కాంబో బ్యాలెన్సింగ్ వ్యూహాలు

ప్రతి కాంబో బ్యాలెన్సింగ్ను కాన్ఫిగర్ చేయండి** డాష్బోర్డ్ → కాంబోస్ → Create/Edit → వ్యూహం** .

| వ్యూహం                        | వివరణ                                                                            |
| ----------------------------- | -------------------------------------------------------------------------------- |
| **రౌండ్-రాబిన్**              | వరుసగా మోడల్స్ ద్వారా తిరుగుతుంది                                                |
| **ప్రాధాన్యత**                | ఎల్లప్పుడూ మొదటి మోడల్ను ప్రయత్నిస్తుంది; లోపం మీద మాత్రమే తిరిగి వస్తుంది       |
| **యాదృచ్ఛికంగా**              | ప్రతి అభ్యర్థన కోసం కాంబో నుండి యాదృచ్ఛిక మోడల్ను ఎంచుకుంటుంది                   |
| **బరువెక్కింది**              | ఒక్కో మోడల్కు కేటాయించిన బరువుల ఆధారంగా దామాషా ప్రకారం మార్గాలు                  |
| **అతి తక్కువ వాడినది**        | అతి తక్కువ ఇటీవలి అభ్యర్థనలతో మోడల్కు మార్గాలు (కాంబో మెట్రిక్లను ఉపయోగిస్తుంది) |
| **ఖర్చు-ఆప్టిమైజ్ చేయబడింది** | అందుబాటులో ఉన్న చౌకైన మోడల్కు మార్గాలు (ధర పట్టికను ఉపయోగిస్తుంది)               |

గ్లోబల్ కాంబో డిఫాల్ట్లను సెట్ చేయవచ్చు** డాష్బోర్డ్ → సెట్టింగ్లు → రూటింగ్ → కాంబో డిఫాల్ట్లు** . కాంబో లక్ష్యం గడువు ముగిసింది డిఫాల్ట్గా ప్రస్తుత అభ్యర్థన గడువు ముగిసింది. ఉపయోగించండి** లక్ష్య సమయం ముగిసింది (సెకన్లు)** కాంబో డిఫాల్ట్లు లేదా వ్యక్తిగత కాంబోలో ప్రతి-లక్ష్య పరిమితి తక్కువగా ఉన్నప్పుడు మాత్రమే ఫాల్బ్యాక్ను వేగవంతం చేస్తుంది.

జీరో-లేటెన్సీ కాంబో ఆప్టిమైజేషన్లు ఎంపిక చేయబడ్డాయి. వదిలేయండి** జీరో-లేటెన్సీ ఆప్టిమైజేషన్లు** ఫాల్బ్యాక్ లక్ష్యాలను రేసింగ్ చేయడం, TTFT చరిత్ర ఆధారంగా లక్ష్యాలను దాటవేయడం లేదా ఫాల్బ్యాక్ అభ్యర్థనలను కుదించడం నుండి ఈ జాప్యం లక్షణాలను నిరోధించడానికి నిలిపివేయబడింది; దీన్ని ఎనేబుల్ చేయడం ద్వారా కాన్ఫిగర్ చేయబడిన హెడ్జింగ్, ప్రిడిక్టివ్ TTFT స్కిప్లు మరియు తక్కువ టెయిల్ జాప్యం కోసం routing/request ఫిడిలిటీని ట్రేడ్ చేయడానికి ప్రోయాక్టివ్ ఫాల్బ్యాక్ కంప్రెషన్ను అనుమతిస్తుంది.

ఆపివేయి** రీజనింగ్ టోకెన్ బఫర్** అప్స్ట్రీమ్ ప్రొవైడర్లకు కఠినమైన `max_tokens` / `maxOutputTokens` పరిమితులు అవసరమైనప్పుడు. ప్రారంభించబడినప్పుడు, కాంబో రూటింగ్ అనేది తెలిసిన అవుట్పుట్ క్యాప్తో మోడల్ల కోసం రీజనింగ్-మోడల్ హెడ్రూమ్ను మాత్రమే జోడిస్తుంది మరియు సురక్షితమైన బఫర్డ్ విలువ ఆ టోపీని మించిపోయినప్పుడు క్లయింట్ టోకెన్ పరిమితిని మార్చకుండా వదిలివేస్తుంది. క్లయింట్ పరిమితి ఇప్పటికే తెలిసిన టోపీ కంటే ఎక్కువగా ఉంటే, అప్స్ట్రీమ్ అభ్యర్థనను పంపే ముందు OmniRoute దానిని ఆ టోపీకి బిగిస్తుంది.

## 🤖 ఆటో-రూటింగ్ (కాన్ఫిగరేషన్ అవసరం లేదు)

OmniRoute ప్రతి కనెక్ట్ చేయబడిన ప్రొవైడర్లోనూ ప్రతి అభ్యర్థనకు ఉత్తమ మోడల్ను ఎంచుకునే **స్కోర్-ఆధారిత ఆటో-రూటర్**తో వస్తుంది — నిర్వహించాల్సిన కాంబో ఏదీ లేదు. `auto/*` ప్రిఫిక్స్లలో ఒకదానితో అభ్యర్థనను పంపితే చాలు; OmniRoute వెంటనే ఒక వర్చువల్ కాంబోను రూపొందించి, లేటెన్సీ, ఖర్చు, విజయ శాతం, కాంటెక్స్ట్ అనుకూలత, టాస్క్కు మోడల్ సామర్థ్యం, ఇటీవలి వైఫల్యాలు, కోటా, సర్క్యూట్-బ్రేకర్ స్థితి ఆధారంగా అభ్యర్థి మోడల్లకు స్కోర్ ఇస్తుంది.

| ప్రిఫిక్స్     | దేనికి అనుకూలీకరిస్తుంది                                                                                    |
| -------------- | ----------------------------------------------------------------------------------------------------------- |
| `auto`         | సమతుల్య డిఫాల్ట్ (లేటెన్సీ × ఖర్చు × విజయ శాతం)                                                             |
| `auto/coding`  | కోడింగ్ టాస్క్లు: Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek కోడర్లకు ప్రాధాన్యం ఇస్తుంది               |
| `auto/cheap`   | అత్యల్ప $/token, అధిక లేటెన్సీని అంగీకరిస్తుంది                                                             |
| `auto/fast`    | అత్యల్ప లేటెన్సీ, ఖర్చును పట్టించుకోదు                                                                      |
| `auto/offline` | స్థానిక-మాత్రమే ప్రొవైడర్లు (Ollama, vLLM, llama.cpp) — ఎయిర్-గ్యాప్డ్ సెటప్లకు ఉపయోగకరం                    |
| `auto/smart`   | రీజనింగ్ నాణ్యతకు మొదటి ప్రాధాన్యం (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)                               |
| `auto/lkgp`    | "చివరిగా విజయవంతమైన ప్రొవైడర్" — చివరిగా విజయవంతమైన ప్రొవైడర్కే పిన్ చేసి, ఆపై నియమాలకు ఫాల్బ్యాక్ అవుతుంది |

ఉదాహరణ:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

స్కోరింగ్ వెయిట్లను ఎలా సర్దుబాటు చేయాలి, ప్రొవైడర్లను బ్లాక్లిస్ట్ చేయడం ఎలా, అలాగే **Dashboard → Auto Combo**లో రూటింగ్ నిర్ణయాలను ఎలా పరిశీలించాలి అనే వివరాలతో సహా ఆటో-రూటర్ గురించి [AUTO-COMBO.md](../routing/AUTO-COMBO.md)లో పూర్తిగా వివరించబడింది.

## 🔌 MCP & A2A ఇంటిగ్రేషన్

OmniRoute ఒక **MCP సర్వర్** (Model Context Protocol) మరియు ఒక **A2A సర్వర్** (Agent-to-Agent JSON-RPC 2.0) రెండూ. ఏదైనా MCP-అనుకూల IDE లేదా ఏజెంట్ హోస్ట్ OmniRoute టూల్లను నేరుగా కాల్ చేయగలదు — అదనపు ర్యాపర్ అవసరం లేదు.

### MCP ట్రాన్స్పోర్ట్లు

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **స్ట్రీమ్ చేయగల HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (stdioను ఇష్టపడే IDE ప్లగిన్ల కోసం)

### Claude Desktopను కనెక్ట్ చేయండి

`~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) లేదా Windows/Linuxలో దానికి సమానమైన ఫైల్ను సవరించండి:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCPను కనెక్ట్ చేయండి

SSE URL `http://localhost:20128/api/mcp/sse`ను మరియు **Dashboard → API Keys**లో రూపొందించిన Bearer API కీని ఉపయోగించండి.

### స్కోప్లు

MCP ప్రస్తుతం 32 పేరుగల స్కోప్లను నిర్వచిస్తుంది. ప్రతి Bearer కీని నిర్దిష్ట స్కోప్లకు పరిమితం చేయవచ్చు — ప్రామాణిక స్కోప్ మరియు టూల్ జాబితా కోసం [MCP-SERVER.md](../frameworks/MCP-SERVER.md)ను, JSON-RPC స్కీమా కోసం [A2A-SERVER.md](../frameworks/A2A-SERVER.md)ను చూడండి.

## 🧠 నైపుణ్యాల వ్యవస్థ

ఏజెంట్లు మరియు A2A ఎండ్పాయింట్ డొమైన్-నిర్దిష్ట రొటీన్లను (ఉదా. `code-review`, `summarize`, `extract-facts`, `web-research`) అమలు చేయగలిగేలా OmniRoute విస్తరించదగిన **నైపుణ్య ఫ్రేమ్వర్క్ను** (`src/lib/skills/`) అందిస్తుంది.

- **మార్కెట్ప్లేస్ UI** — **డ్యాష్బోర్డ్ → నైపుణ్యాలు** నుండి నైపుణ్యాలను బ్రౌజ్ చేసి, ఇన్స్టాల్ చేయండి

- **అనుకూల నైపుణ్యాలు** — `src/lib/a2a/skills/`లో ఒక TypeScript ఫైల్ను ఉంచి, దాన్ని నమోదు చేస్తే, అది వెంటనే A2A ద్వారా అమలు చేయదగినదిగా మారుతుంది

పూర్తి సూచన: [SKILLS.md](../frameworks/SKILLS.md).

## 💾 మెమరీ వ్యవస్థ

OmniRoute హైబ్రిడ్ రిట్రీవల్తో **దీర్ఘకాలిక సంభాషణ మెమరీని** నిల్వ చేస్తుంది:

- గత సంభాషణ టర్న్లలో కీవర్డ్ శోధన కోసం **SQLite FTS5**
- భావార్థ రీకాల్ కోసం **Qdrant వెక్టర్ స్టోర్** (ఐచ్ఛికం)
- **ఆటోమేటిక్ ఫ్యాక్ట్ ఎక్స్ట్రాక్షన్** — ప్రతి సెషన్ తర్వాత ఎంటిటీలు, ప్రాధాన్యతలు మరియు నిర్ణయాలు సంగ్రహించబడి, `memory_facts` పట్టికలో నిల్వ చేయబడతాయి
- మెమరీలు ఒక్కో API కీకి మరియు ఒక్కో సెషన్కు ప్రత్యేకంగా పరిమితం చేయబడతాయి

**డ్యాష్బోర్డ్ → మెమరీ**లో మెమరీలను నిర్వహించండి (శోధించండి, సవరించండి, ఎగుమతి చేయండి, పూర్తిగా తొలగించండి). HTTP ఇంటర్ఫేస్ (`/api/memory/*`) ద్వారా ఏజెంట్లు ప్రోగ్రామాటిక్గా ఫ్యాక్ట్లను పంపించవచ్చు మరియు ప్రశ్నించవచ్చు — [MEMORY.md](../frameworks/MEMORY.md) చూడండి.

## 🔔 వెబ్హుక్లు

రియల్-టైమ్ పర్యవేక్షణ మరియు ఆటోమేషన్ కోసం OmniRoute ఈవెంట్లకు సబ్స్క్రైబ్ చేయండి.

- లక్ష్య URL మరియు HMAC సంతక సీక్రెట్తో **డ్యాష్బోర్డ్ → వెబ్హుక్లు**లో ఒక వెబ్హుక్ను సృష్టించండి
- అందుబాటులో ఉన్న ఈవెంట్లు: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- ధృవీకరణ కోసం ప్రతి పేలోడ్లో `X-OmniRoute-Signature` (HMAC-SHA256) ఉంటుంది
- మళ్లీ ప్రయత్నాలు: ఎక్స్పోనెన్షియల్ బ్యాక్ఆఫ్తో 3 ప్రయత్నాలు, ఆ తర్వాత డెడ్-లెటర్ క్యూ

## 🛠️ ప్రోగ్రామాటిక్ నిర్వహణ

**`manage` స్కోప్ ఉన్న Bearer కీని** ఉపయోగించి HTTP ద్వారా ప్రతి OmniRoute వనరును (ప్రొవైడర్లు, కాంబోలు, కీలు, సెట్టింగ్లు) నిర్వహించవచ్చు.

**డ్యాష్బోర్డ్ → API కీలు → కొత్త కీ → స్కోప్: manage**లో కీని రూపొందించి, ఆపై:

```bash
# ప్రొవైడర్లను జాబితా చేయండి
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# ప్రొవైడర్ కనెక్షన్ను జోడించండి
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# కాంబోను సృష్టించండి
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API కీలను జాబితా చేయండి/సృష్టించండి
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

పూర్తి ఎండ్పాయింట్ కేటలాగ్ మరియు రిక్వెస్ట్/రెస్పాన్స్ స్కీమాల కోసం [API_REFERENCE.md](../reference/API_REFERENCE.md) చూడండి.

## 💻 అంతర్గత CLI

సెటప్, డయాగ్నస్టిక్స్ మరియు రన్టైమ్ నియంత్రణ కోసం OmniRoute అంతర్గత CLI (`omniroute …`)తో వస్తుంది. ఇది **డ్యాష్బోర్డ్లోని "CLI సాధనాలు" పేజీకి భిన్నమైనది**; ఆ పేజీ మూడవ పక్ష CLIలను (Claude Code, Cursor, Codex, Cline, …) కాన్ఫిగర్ చేసి, అవి OmniRouteతో కమ్యూనికేట్ చేయగలిగేలా చేస్తుంది.

```bash
omniroute setup                    # ఇంటరాక్టివ్ విజార్డ్ (పాస్వర్డ్, ప్రొవైడర్లు, కాంబోలు)
omniroute setup --non-interactive  # CIకి అనుకూలమైనది
omniroute doctor                   # ఆరోగ్య డయాగ్నస్టిక్స్ (డేటా డైరెక్టరీ, DB, ప్రొవైడర్లు, పోర్టులు)
omniroute providers available      # మద్దతు ఉన్న ప్రొవైడర్లను జాబితా చేయండి
omniroute providers list           # కాన్ఫిగర్ చేసిన కనెక్షన్లను జాబితా చేయండి
omniroute providers test <id>      # ప్రొవైడర్ కనెక్షన్ను ప్రత్యక్షంగా పరీక్షించండి
omniroute combos list              # కాంబోలను జాబితా చేయండి
omniroute combos switch <name>     # డిఫాల్ట్ కాంబోను సెట్ చేయండి
omniroute models                   # అందుబాటులో ఉన్న మోడళ్లను జాబితా చేయండి (--json, --search)
omniroute keys add | list | remove # టెర్మినల్ నుండి API కీలను నిర్వహించండి
omniroute backup                   # కాన్ఫిగరేషన్ + DB స్నాప్షాట్
omniroute restore [<timestamp>]    # స్నాప్షాట్ నుండి పునరుద్ధరించండి
omniroute health                   # వివరణాత్మక ఆరోగ్య స్థితి (బ్రేకర్లు, కాష్, మెమరీ)
omniroute quota                    # ప్రొవైడర్ కోటా వినియోగం
omniroute mcp status               # MCP సర్వర్ స్థితి
omniroute a2a status               # A2A సర్వర్ స్థితి
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok టన్నెల్లు
omniroute reset-password           # అడ్మిన్ పాస్వర్డ్ను రీసెట్ చేయండి
omniroute --mcp                    # stdio ద్వారా MCP సర్వర్ను ప్రారంభించండి
omniroute --port 3000              # అనుకూల పోర్టులో సర్వర్ను ప్రారంభించండి
```

చిట్కా: అనారోగ్యకరమైన ప్రొవైడర్ కనెక్షన్లపై హెచ్చరికలు పొందడానికి `omniroute doctor --json`ను మీ మానిటరింగ్ సాధనంతో జత చేయండి.

## 🖥️ డెస్క్టాప్ అప్లికేషన్ (Electron)

OmniRoute Windows, macOS మరియు Linux కోసం స్థానిక డెస్క్టాప్ అప్లికేషన్గా అందుబాటులో ఉంది.

### ఇన్స్టాలేషన్

```bash
# electron డైరెక్టరీ నుండి:
cd electron
npm install

# డెవలప్మెంట్ మోడ్ (రన్ అవుతున్న Next.js డెవ్ సర్వర్కు కనెక్ట్ అవుతుంది):
npm run dev

# ప్రొడక్షన్ మోడ్ (స్టాండ్అలోన్ బిల్డ్ను ఉపయోగిస్తుంది):
npm start
```

### ఇన్స్టాలర్లను బిల్డ్ చేయడం

```bash
cd electron
npm run build          # ప్రస్తుత ప్లాట్ఫారమ్
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg యూనివర్సల్)
npm run build:linux    # Linux (.AppImage)
```

అవుట్పుట్ → `electron/dist-electron/`

### ముఖ్య ఫీచర్లు

| ఫీచర్                        | వివరణ                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------ |
| **సర్వర్ సిద్ధస్థితి**       | విండోను చూపించే ముందు సర్వర్ను పోలింగ్ చేస్తుంది (ఖాళీ స్క్రీన్ ఉండదు)         |
| **సిస్టమ్ ట్రే**             | ట్రేకు మినిమైజ్ చేయడం, పోర్టును మార్చడం, ట్రే మెను నుండి నిష్క్రమించడం         |
| **పోర్ట్ నిర్వహణ**           | ట్రే నుండి సర్వర్ పోర్టును మార్చడం (సర్వర్ను స్వయంచాలకంగా పునఃప్రారంభిస్తుంది) |
| **కంటెంట్ సెక్యూరిటీ పాలసీ** | సెషన్ హెడర్ల ద్వారా కఠినమైన CSP                                                |
| **ఒకే ఇన్స్టాన్స్**          | ఒక సమయంలో ఒక అప్లికేషన్ ఇన్స్టాన్స్ మాత్రమే రన్ అవుతుంది                       |
| **ఆఫ్లైన్ మోడ్**             | బండిల్ చేసిన Next.js సర్వర్ ఇంటర్నెట్ లేకుండా పనిచేస్తుంది                     |
