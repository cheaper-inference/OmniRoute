Web Cookie ప్రొవైడర్లు API కీకి బదులుగా మీ ప్రస్తుత బ్రౌజర్ సెషన్ ద్వారా AI సేవను ఉపయోగించడానికి OmniRouteను అనుమతిస్తాయి. మీరు ఇప్పటికే ఒక సేవకు దాని వెబ్సైట్ ద్వారా యాక్సెస్ కలిగి ఉండి, అదే ప్రామాణీకరించిన సెషన్ను OmniRoute ఉపయోగించాలని కోరుకున్నప్పుడు ఇవి ఉపయోగకరంగా ఉంటాయి.

API-key ప్రొవైడర్లకు భిన్నంగా, Web Cookie ప్రొవైడర్లు మీ బ్రౌజర్ వెబ్సైట్కు పంపే ఆధారాలను ఉపయోగించి ప్రామాణీకరిస్తాయి.

# ప్రారంభించే ముందు

> **ముఖ్యమైనది:** ఆధారాలను ఎల్లప్పుడూ **ప్రత్యక్ష నెట్వర్క్ అభ్యర్థన** నుండి కాపీ చేయండి, మీ బ్రౌజర్ Cookie స్టోరేజ్ నుండి **కాదు**.

తప్పు ప్రదేశం నుండి cookiesను కాపీ చేయడం వల్ల అనేక ప్రామాణీకరణ సమస్యలు ఏర్పడతాయి.

## Cookie స్టోరేజ్ నుండి కాపీ చేయవద్దు

చాలా బ్రౌజర్లు నిల్వ చేసిన cookiesను ఈ మార్గంలో చూపిస్తాయి:

```
DevTools
→ అప్లికేషన్ (లేదా స్టోరేజ్)
→ Cookies
```

ఈ cookies సరైనవిగా కనిపించినప్పటికీ, అవి:

- పాతవి కావచ్చు
- అసంపూర్ణంగా ఉండవచ్చు
- ప్రామాణీకరించిన అభ్యర్థనలపై మాత్రమే పంపే cookiesను కలిగి ఉండకపోవచ్చు

ఈ విలువలు చెల్లుబాటు అయ్యేవిగా కనిపించినప్పటికీ, వాటిని ఉపయోగించడం ప్రామాణీకరణ వైఫల్యాలకు కారణం కావచ్చు.

## ప్రత్యక్ష అభ్యర్థన నుండి కాపీ చేయండి

బదులుగా, విజయవంతమైన అభ్యర్థనలోని cookiesను ఉపయోగించండి:

```
DevTools
→ నెట్వర్క్
→ పేజీని రిఫ్రెష్ చేయండి
→ చాట్ లేదా సంభాషణ అభ్యర్థనను తెరవండి
→ అభ్యర్థన హెడర్లు
→ Cookie
```

`Cookie` అభ్యర్థన హెడర్లో మీ బ్రౌజర్ విజయవంతంగా ఉపయోగించిన ఖచ్చితమైన ప్రామాణీకరణ సమాచారం ఉంటుంది.

చాలా Web Cookie ప్రొవైడర్ల కోసం, OmniRouteలో అతికించాల్సిన విలువ ఇదే.

# సాధారణ సెటప్

చాలా Web Cookie ప్రొవైడర్లకు సెటప్ ప్రక్రియ ఒకే విధంగా ఉంటుంది.

1. ప్రొవైడర్ వెబ్సైట్కు సైన్ ఇన్ చేయండి.
2. బ్రౌజర్ Developer Toolsను తెరవండి.
3. **నెట్వర్క్** ట్యాబ్ను తెరవండి.
4. పేజీని రిఫ్రెష్ చేయండి.
5. ప్రామాణీకరించిన చాట్ లేదా సంభాషణ అభ్యర్థనను తెరవండి.
6. అవసరమైన ప్రామాణీకరణ ఆధారాలను కాపీ చేయండి.
7. OmniRouteను తెరవండి.
8. **ప్రొవైడర్లు → ప్రొవైడర్ను జోడించండి**కు వెళ్లండి.
9. మీ Web Cookie ప్రొవైడర్ను ఎంచుకోండి.
10. ఆధారాలను అతికించండి.
11. **కనెక్షన్ను పరీక్షించండి**పై క్లిక్ చేయండి.
12. ప్రొవైడర్ను సేవ్ చేయండి.

అవసరమైన ఖచ్చితమైన ఆధారాలు ప్రొవైడర్పై ఆధారపడి ఉంటాయి.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) అనేది సైన్అప్ అవసరం లేని ఉచిత వినియోగదారు చాట్ ప్లాట్ఫారమ్ — మొదటిసారి సందర్శించినప్పుడు సెషన్ అనామకంగా సృష్టించబడుతుంది మరియు `uid`, `si_usr_id`, `si_ses_id` అనే మూడు కుకీల ద్వారా కొనసాగుతుంది. OmniRoute అదే `/api/dispatch` ఎండ్పాయింట్ను ఒకే మోడల్ id (`notrack-c`, అలియాస్ `ntw`) ద్వారా ప్రాక్సీ చేస్తుంది.

### కనెక్ట్ చేయడానికి దశలు

1. మీ బ్రౌజర్లో [notrack.ai](https://notrack.ai) తెరిచి, అనామక సెషన్ కుకీ సెట్ అయ్యేలా చేయండి.
2. **DevTools → Network** తెరిచి, పేజీని రిఫ్రెష్ చేసి, ఏదైనా `/api` అభ్యర్థనపై క్లిక్ చేయండి.
3. **Request Headers**లో, పూర్తి `Cookie` హెడర్ విలువను కాపీ చేయండి.
4. OmniRouteలో, **Providers → Add Provider → NoTrack Web (Free)**కు వెళ్లండి.
5. కుకీ స్ట్రింగ్ను `apiKey` ఫీల్డ్లో అతికించి, **Save** చేయండి.

OmniRoute అతికించిన స్ట్రింగ్ నుండి `uid`, `si_usr_id`, `si_ses_id`లను సంగ్రహించి, ఆ జతలు మాత్రమే ఉన్న శుభ్రమైన `Cookie` హెడర్ను మళ్లీ నిర్మిస్తుంది — అలాగే, అందుబాటులో ఉన్నప్పుడు లాగిన్ చేసిన ఖాతాల కోసం సెట్ చేయబడిన `nt_session` (`ntk_…` టోకెన్)ను కూడా జోడిస్తుంది. ఈ మూడింటిలో ఏదైనా లేకపోతే, ఆపరేటర్లు ప్రత్యామ్నాయ ఆకృతులతో ప్రయోగాలు చేయగలిగేలా అతికించిన ముడి స్ట్రింగ్ ఎలాంటి మార్పు లేకుండా ఫార్వర్డ్ చేయబడుతుంది.

### మోడల్ idలు

| మోడల్ id    | ప్రదర్శన పేరు | గమనికలు                                                 |
| ----------- | ------------- | ------------------------------------------------------- |
| `notrack-c` | NoTrack C     | డిఫాల్ట్ — అప్స్ట్రీమ్ డిస్పాచ్ మోడల్ `C`.              |
| `C`         | NoTrack C     | `notrack-c`కు అలియాస్ (ముడి అప్స్ట్రీమ్ డిస్పాచ్ కోడ్). |
| `notrack`   | NoTrack C     | `notrack-c`కు అలియాస్.                                  |
| `ntw`       | NoTrack C     | `notrack-c`కు సంక్షిప్త అలియాస్.                        |

నాలుగు మోడల్ idలు ఒకే అప్స్ట్రీమ్ డిస్పాచ్ మోడల్కు (`C`) మ్యాప్ అవుతాయి.

### అభ్యర్థన ఎంపికలు

ఎగ్జిక్యూటర్ అభ్యర్థన బాడీలోని ఈ ఐచ్ఛిక ఫీల్డ్లను అంగీకరిస్తుంది:

| బాడీ ఫీల్డ్           | డిఫాల్ట్ | ప్రయోజనం                                                                              |
| --------------------- | -------- | ------------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`  | డిస్పాచ్ మోడ్ (స్వేచ్ఛా-రూప స్ట్రింగ్; అప్స్ట్రీమ్ `usual`, …ను అంగీకరిస్తుంది)       |
| `notrack_max_turns`   | `6`      | సమాధానమివ్వడానికి ముందు అప్స్ట్రీమ్ తీసుకోగల అంతర్గత టర్న్ల సంఖ్య.                    |
| `notrack_chat_id`     | `null`   | ఇప్పటికే ఉన్న అప్స్ట్రీమ్ చాట్ను కొనసాగించండి (కొత్త చాట్ కోసం వదిలివేయండి).          |
| `notrack_attachments` | `[]`     | అప్స్ట్రీమ్ అటాచ్మెంట్ డిస్క్రిప్టర్ల పాస్-త్రూ అర్రే.                                |
| `notrack_regenerate`  | `false`  | మునుపటి టర్న్కు సమాధానాన్ని మళ్లీ రూపొందించమని అభ్యర్థించడానికి `true`గా సెట్ చేయండి. |

### సామర్థ్యాలు

- **స్ట్రీమింగ్ మరియు నాన్-స్ట్రీమింగ్** చాట్ కంప్లీషన్లు.
- **టూల్ కాలింగ్** — అభ్యర్థనలో `tools: [...]`ను సెట్ చేయండి; ఎగ్జిక్యూటర్ వాటిని టూల్-కాల్ ఎన్వలప్ కాంట్రాక్ట్లోకి సీరియలైజ్ చేసి, మోడల్ ప్రతిస్పందనలను తిరిగి OpenAI `tool_calls`గా పార్స్ చేస్తుంది.
- **`response_format`** — `json_object` మరియు `json_schema`కు మద్దతు ఉంది. ఎగ్జిక్యూటర్ మోడల్ సమాధానం నుండి మొదటి JSON ఆబ్జెక్ట్ను సంగ్రహించి, తిరిగి పంపే ముందు దాన్ని స్ట్రింగ్గా మారుస్తుంది.
- **రీజనింగ్ సూచన** — అప్స్ట్రీమ్ `thinking` ఈవెంట్ను పంపినప్పుడు, ఎగ్జిక్యూటర్ `reasoning` డెల్టాను విడుదల చేస్తుంది.

### పరిమితులు

- అప్స్ట్రీమ్ అనామక వినియోగ కోటాలను అమలు చేస్తుంది — అవి మించిపోయినప్పుడు, ఎగ్జిక్యూటర్ స్నేహపూర్వక సందేశంతో 429ను చూపిస్తుంది.
- అన్ని మోడల్ idలు ఒకే అప్స్ట్రీమ్ డిస్పాచ్ మోడల్కు పరిష్కరించబడతాయి; ఒక్కో మోడల్కు ప్రత్యేక స్విచ్ లేదు.
- ఎగ్జిక్యూటర్ అప్స్ట్రీమ్ యొక్క `/api/chats` ఎండ్పాయింట్ను కాల్ చేయదు, కాబట్టి చాట్ చరిత్ర / సెషన్లు స్వయంచాలకంగా నిర్వహించబడవు. ఇప్పటికే ఉన్న అప్స్ట్రీమ్ చాట్ను కొనసాగించడానికి `notrack_chat_id`ను ఉపయోగించండి.

# వెబ్ కుకీ ప్రొవైడర్లు ఏమి చేయగలవు మరియు ఏమి చేయలేవు

వెబ్ కుకీ ప్రొవైడర్లు వెబ్సైట్ యొక్క చాట్ ఇంటర్ఫేస్ను తిరిగి ఉపయోగిస్తాయి. అవి అధికారిక APIలతో సమానమైన సామర్థ్యాలను **అందించవు**.

## మద్దతు ఉన్నవి

- మీ ప్రస్తుత బ్రౌజర్ సెషన్ను ఉపయోగించి ప్రామాణీకరించడం
- మీ ఖాతా ద్వారా అందుబాటులో ఉన్న మోడళ్లను యాక్సెస్ చేయడం
- చాట్ ప్రతిస్పందనలను స్ట్రీమ్ చేయడం
- API కీ అవసరం లేదు

## మద్దతు లేనివి

- ఫంక్షన్ కాలింగ్
- టూల్ కాలింగ్
- ఆటోమేటిక్ ఫైల్ ఎడిటింగ్
- ఏజెంటిక్ IDE వర్క్ఫ్లోలు
- APIలో మాత్రమే అందుబాటులో ఉండే ఫీచర్లు

ఇది ఊహించిన ప్రవర్తనే మరియు **బగ్ కాదు**.

మీకు టూల్ ఎగ్జిక్యూషన్, ఆటోమేటిక్ ఫైల్ ఎడిటింగ్ లేదా ఇతర ఏజెంట్ వర్క్ఫ్లోలు అవసరమైతే, Web Cookie ప్రొవైడర్కు బదులుగా **API-key ప్రొవైడర్ను** ఉపయోగించండి.

# ధ్రువీకరణ పరిమితి

విజయవంతమైన **Test Connection** లేదా కుకీ ధ్రువీకరణ, అందించిన క్రెడెన్షియల్స్ ఆశించిన ఫార్మాట్లో ఉన్నట్లు కనిపిస్తున్నాయని మాత్రమే నిర్ధారిస్తుంది.

Issue #7857 పరిష్కరించబడే వరకు, విజయవంతమైన ధ్రువీకరణ ప్రొవైడర్ విజయవంతంగా ప్రామాణీకరిస్తుందని **హామీ ఇవ్వదు**.

ప్రామాణీకరణ ఇప్పటికీ విఫలమైతే, మీరు క్రెడెన్షియల్స్ను బ్రౌజర్ కుకీ స్టోరేజ్ నుండి కాకుండా, సక్రియ నెట్వర్క్ రిక్వెస్ట్ నుండి కాపీ చేశారని నిర్ధారించుకోండి.

# సమస్య పరిష్కారం

## ప్రామాణీకరణ విఫలమవుతుంది

క్రెడెన్షియల్స్ను దీని నుండి కాపీ చేశారని నిర్ధారించుకోండి:

```
Network
→ Request Headers
→ Cookie
```

మరియు దీని నుండి **కాదు**:

```
Application
→ Cookies
```

## సెషన్ గడువు ముగిసింది

Web Cookie ప్రొవైడర్లు మీ ప్రస్తుత బ్రౌజర్ సెషన్ను ఉపయోగిస్తారు.

మీ బ్రౌజర్ సెషన్ గడువు ముగిసినా లేదా మీరు సైన్ అవుట్ చేసినా, మీరు కొత్త క్రెడెన్షియల్స్ సమితిని కాపీ చేయాలి. మద్దతు ఉన్న వెబ్ ప్రొవైడర్ల కోసం కుకీ పునరుద్ధరణను ఆటోమేట్ చేయడానికి, [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) సహాయక టూల్ను చూడండి.

## "Unsupported ChatGPT integrity dependency"తో ChatGPT Web విఫలమవుతుంది

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

క్రెడెన్షియల్ సరిగ్గానే ఉంది — ఆ ఎర్రర్ బ్రిడ్జ్ నుండి వస్తుంది, సెషన్ నుండి కాదు. chatgpt.com ప్రతి డిప్లాయ్మెంట్కు దాని
మాడ్యూల్ IDలను కేటాయిస్తుంది, అలాగే బ్రిడ్జ్ తాను ఇన్స్టాన్షియేట్ చేసే Sentinel సహాయక మాడ్యూల్ IDని స్థిరంగా పిన్ చేసేది, కాబట్టి
ఆ సహాయక మాడ్యూల్కు పేరు మార్చిన chatgpt.com రీబిల్డ్ వల్ల కుకీ చెల్లుబాటులో ఉన్నప్పటికీ ప్రతి టర్న్ విఫలమైంది. కనెక్షన్ను మళ్లీ ఆథరైజ్
చేయడం ద్వారా దీనిని పరిష్కరించలేరు.

పేజీ సొంత రన్టైమ్ ద్వారా మాడ్యూల్ను రిజాల్వ్ చేసే బిల్డ్లు ఏ IDని పిన్ చేయవు మరియు ఈ సమస్యను ఎదుర్కోవు. మీకు ఈ
ఎర్రర్ కనిపిస్తే, OmniRouteను అప్గ్రేడ్ చేసి కనెక్షన్ తనిఖీని మళ్లీ అమలు చేయండి.

# ఉత్తమ పద్ధతులు

- తాజాగా ప్రామాణీకరించబడిన రిక్వెస్ట్ నుండి క్రెడెన్షియల్స్ను కాపీ చేయండి.
- పాత కుకీలను తిరిగి ఉపయోగించకుండా ఉండండి.
- Web Cookie ప్రొవైడర్లను ఉపయోగిస్తున్నప్పుడు మీ బ్రౌజర్ సెషన్ను యాక్టివ్గా ఉంచండి.
- కాపీ చేసిన కుకీలను సున్నితమైన క్రెడెన్షియల్స్గా పరిగణించండి.
- మీకు ఫంక్షన్ కాలింగ్ లేదా ఏజెంట్ వర్క్ఫ్లోలు అవసరమైనప్పుడు API-key ప్రొవైడర్లను ఉపయోగించండి.
