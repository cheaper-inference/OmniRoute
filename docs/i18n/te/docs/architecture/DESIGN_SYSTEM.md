> **స్థితి:** డాష్బోర్డ్ నిర్మించబడింది**Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), ఈ రిపోజిటరీలో వర్క్స్పేస్ `packages/ui-kit` (`@omniroute/ui-kit`; అప్స్ట్రీమ్ స్నాప్షాట్ `packages/ui-kit/UPSTREAM.md` లో పిన్ చేయబడింది మరియు `npm run check:ui-kit-snapshot` ద్వారా రక్షించబడుతుంది)గా చేర్చబడింది. కాంతి కానానికల్ థీమ్; డిఫాల్ట్ ప్రాధాన్యత `system`. డిఫాల్ట్ పాలెట్ కిట్**Editions** ప్రదర్శన (వెచ్చని కాగితం న్యూట్రల్స్ మరియు రాగి యాస `#e5ac82`, `packages/ui-kit/src/ci-editions.css`); సెట్టింగ్లు → స్వరూపం → రంగుల పాలెట్ ఆఫర్లు**Classic** , లైమ్ యాసతో కిట్ బేస్ టోకెన్లు. Switzer అనేది UI మరియు డిస్ప్లే టెక్స్ట్ (`--ci-font-ui`; `--ci-font-display` మరియు `--ci-font-mono` దానికి పరిష్కరిస్తుంది), కిట్ ద్వారా స్వయంగా హోస్ట్ చేయబడింది (`packages/ui-kit/src/ci-fonts.css`, `ci-tokens.css` ద్వారా దిగుమతి చేయబడింది). ప్రతి చిహ్నం ఒక Lucide గ్లిఫ్.
>
> Inter అనేది Switzer నుండి తప్పిపోయిన గ్లిఫ్ల కోసం ఫాల్బ్యాక్; సిస్టమ్ మోనోస్పేస్ స్టాక్ `--ci-font-code` కి `--font-mono` మ్యాప్లు.
>
> `Switzer` కి గ్లిఫ్ లేనప్పుడు`src/app/globals.css` ఫాల్బ్యాక్ ఫాంట్లను ఎంచుకుంటుంది: సిరిలిక్, గ్రీక్ మరియు వియత్నామీస్ కోసం `Inter`, మరియు `html[dir="rtl"]` కింద మాత్రమే అరబిక్ స్క్రిప్ట్ కోసం `Vazirmatn`.

`src/app/globals.css`:

```css
:root,
.ci-theme {
  --ci-font-ui:
    "Switzer", "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif;
  --ci-font-code: ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace;
  --font-mono: var(--ci-font-code);
}
```

## 1. వస్తువులు ఎక్కడ నివసిస్తున్నాయి

- **కిట్.** `packages/ui-kit/src` అనేది `packages/ui-kit/UPSTREAM.md` లో పిన్ చేయబడిన కమిట్లో అప్స్ట్రీమ్ `src/` యొక్క బైట్-ఫర్-బైట్ కాపీ (ఇది లైసెన్స్ అధికారాన్ని కూడా నమోదు చేస్తుంది); `PATCHES.md` స్థానిక ప్యాచ్లను జాబితా చేస్తుంది. ఇది ఎటువంటి నిర్మాణం లేకుండా మూలంగా వినియోగించబడుతుంది: `next.config.mjs` దానిని ట్రాన్స్పైల్ చేస్తుంది మరియు `tsconfig.json` మ్యాప్లు `@omniroute/ui-kit` → `packages/ui-kit/src` మరియు `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` (`vitest.config.ts` మరియు `vitest.mcp.config.ts` ఒకే మారుపేరును కలిగి ఉంటాయి). కిట్ కాంపోనెంట్ను దాని సబ్పాత్ (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`...) ద్వారా దిగుమతి చేయండి, `@omniroute/ui-kit` బారెల్ ద్వారా ఎప్పుడూ: బ్యారెల్ ప్రతి ఇంపోర్టర్లోకి ప్రతి కాంపోనెంట్ను (తేదీ పికర్తో సహా) లాగుతుంది. కిట్ స్టైల్షీట్ `src/app/globals.css` (`@import "../../packages/ui-kit/src/ci-styles.css"`, పూర్తి షీట్: కోర్ `ci-ui.css` ప్లస్ ప్రతి ప్యాటర్న్ ఫ్యామిలీ) ద్వారా ప్రవేశిస్తుంది.
- **టోకెన్లు.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` టోకెన్లను ప్రకటించింది; `src/app/globals.css` వాటిని వారసత్వ OmniRoute పేర్లకు (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) బ్రిడ్జ్ చేస్తుంది కాబట్టి ఇప్పటికే ఉన్న `var(--color-*)` రీడ్లు మరియు Tailwind యుటిలిటీలు పని చేస్తూనే ఉంటాయి. కొత్త కోడ్ Tailwind యుటిలిటీలను ఉపయోగిస్తుంది (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`...) లేదా కిట్ తరగతులు — ఎప్పుడూ హెక్స్ విలువను కలిగి ఉండదు (`tests/unit/design-kit-bridge.test.ts` వంతెనను అమలు చేస్తుంది). `text-primary` `--text-color-primary` ద్వారా `--color-primary-ink` కి పరిష్కరిస్తుంది, కాబట్టి `bg-primary`/`border-primary` యాస ఉపరితలాన్ని ఉంచేటప్పుడు ప్రాథమిక వచనం చదవగలిగేలా ఉంటుంది: Editions కింద ఇది కిట్ యొక్క `--ci-color-accent-active` (కాంతిలో లోతైన కాపర్ `#99562f`, చీకటిలో రాగి యాస); Classic కింద, కాంతిలో lime-800 మరియు చీకటిలో లైమ్ యాస. చార్ట్ సిరీస్ `--color-chart-1` ఉపయోగిస్తుంది … `--color-chart-8`, ప్రతి ఒక్కటి టెక్స్ట్-సురక్షిత `--color-chart-N-ink` మరియు అపారదర్శక `--color-chart-N-subtle` చిప్ టింట్, కిట్ సిరీస్ ఆర్డర్లో కేటాయించబడింది (`ciChartSeriesOrder`).
- **థీమ్స్.** `<html className="ci-theme">` (`src/app/layout.tsx`) పత్రాన్ని కిట్ థీమ్లోకి ఎంచుకుంటుంది. ప్రాధాన్యత `light`, `dark` లేదా `system` ( `src/shared/constants/appConfig.ts` లో`THEME_CONFIG.defaultTheme = "system"` ; `system` `prefers-color-scheme` ని అనుసరిస్తుంది ). `src/store/themeStore.ts` లోని `applyTheme()` ( `THEME_BOOT_SCRIPT` చేత ప్రతిబింబించబడింది, `src/app/layout.tsx` లో ఇన్లైన్ చేయబడింది, ఇది హైడ్రేషన్కు ముందు నడుస్తుంది) `data-theme="dark"|"light"` సెట్ చేస్తుంది మరియు `.dark` క్లాస్ని `<html>` లో కలిసి టోగుల్ చేస్తుంది. కిట్ యొక్క డార్క్ టోకెన్ సెట్ `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`)లో కీ చేయబడింది; OmniRoute యొక్క స్వంత డార్క్ ఓవర్రైడ్లు ( `globals.css` లోని `.dark` బ్లాక్) మరియు `.dark` క్లాస్లో లెగసీ Tailwind `dark:` యుటిలిటీస్ కీ. యాక్సెంట్ కలర్ ప్రీసెట్లు లేవు: యాస ఎల్లప్పుడూ కిట్ నుండి వస్తుంది మరియు స్టోర్ లోడ్ అయినప్పుడు పాత బిల్డ్ నుండి పెర్సిస్టెడ్ ప్రీసెట్ డ్రాప్ చేయబడుతుంది.
- **ప్యాలెట్లు.** రెండు, కిట్ నుండి రెండూ (`src/shared/constants/appearancePalette.ts`): `editions`, డిఫాల్ట్ మరియు `classic`. Editions అనేది `<html>` పై కిట్ యొక్క `data-ci-appearance="editions"` లక్షణం, ఇది `ci-editions.css` ( `ci-ui.css` ద్వారా దిగుమతి చేయబడింది) `data-theme` తో కలుపుతుంది; Classic అనేది లక్షణం లేకపోవడం. రూట్ లేఅవుట్ సర్వర్ లక్షణాన్ని రెండర్ చేస్తుంది, కాబట్టి సందర్శకుడు ఏమీ నిల్వ చేయని (లేదా JS) ప్రతి ఉపరితలంపై Editions పొందుతాడు — డాష్బోర్డ్, లాగిన్, `/status`, ఎర్రర్ పేజీలు, `/docs` మరియు PWA. ఎంపిక అదే `theme` స్టోర్లో ( `src/store/themeStore.ts` లో`palette`, `setPalette()`, `applyPalette()` ) థీమ్ పక్కన కొనసాగుతుంది మరియు `THEME_BOOT_SCRIPT` ద్వారా పెయింట్కు ముందు వర్తించబడుతుంది (`src/shared/utils/themeBootScript.ts`, లేఅవుట్ యొక్క `<head>` లో ఇన్లైన్ చేయబడింది), ఇది నిల్వ చేయబడిన పాలెట్ `"classic"` అయినప్పుడు మాత్రమే లక్షణాన్ని తొలగిస్తుంది; `src/app/global-error.tsx`, రూట్ లేఅవుట్ వెలుపల, అదే స్టోర్ నుండి ఇది వర్తిస్తుంది. మరే ఇతర మూలకంపై `data-ci-appearance` ఉంచవద్దు: కిట్ `html:root:has([data-ci-appearance="editions"])` తో సరిపోలుతుంది, కాబట్టి ఒక వారసుడు మొత్తం పత్రాన్ని మారుస్తాడు. Editions `data-ci-editions-variant="landing"` వేరియంట్ మార్కెటింగ్ పేజీల కోసం, డాష్బోర్డ్ కాదు. బ్రౌజర్ క్రోమ్: సర్వర్ డిఫాల్ట్, Editions `viewport.themeColor` లో ( `prefers-color-scheme` కి ఒక ట్యాగ్) మరియు వెబ్ మానిఫెస్ట్ — `PWA_THEME_COLORS` `src/shared/constants/pwaThemeColors.ts` లో రెండర్ చేస్తుంది, Editions `--ci-color-background` (`#f3f1e9` / `#11120f`) యొక్క ఒక అద్దం, `tests/unit/pwa-theme-colors.test.ts` ద్వారా `ci-editions.css` కి పిన్ చేయబడింది. లైవ్ `<meta name="theme-color">` అప్పుడు నిల్వ చేయబడిన పాలెట్ మరియు మోడ్ను అనుసరిస్తుంది: `THEME_BOOT_SCRIPT` పెయింట్కు ముందు ట్యాగ్లను తిరిగి వ్రాస్తుంది మరియు థీమ్ స్టోర్ యొక్క చర్యలు ప్రతి మార్పులోనూ దీన్ని చేస్తాయి ( `src/shared/utils/themeColorMeta.ts` లో`resolveThemeColor()` / `applyThemeColor()`, `CLASSIC_PAGE_BACKGROUND` కిట్ యొక్క `ciTokens` నుండి చదవబడుతుంది). స్పష్టమైన light/dark థీమ్ ప్రతి ట్యాగ్ను ఆ మోడ్కు సెట్ చేస్తుంది; `system` ఒక్కో స్కీమ్కు ఒక రంగును ఉంచుతుంది. మానిఫెస్ట్ Editions అలాగే ఉంటుంది : ఇది ప్రాధాన్యత లేకుండా ప్రతి ఇన్స్టాల్కు ఒకసారి పొందబడుతుంది. మొనాకో ప్రోబ్ (`monacoKitTheme.ts`) నుండి దాని రంగులను చదువుతుంది; Editions కింద ప్రోబ్ రీడ్ ఒక సింక్రోనస్ పాస్ కోసం రూట్ `data-theme` తిప్పుతుంది, ఎందుకంటే కిట్ Editions light/dark రూట్ నుండి పరిష్కరిస్తుంది.

## 2. నియమాలు

1. లిటరల్స్ను కాకుండా టోకెన్లను ఉపయోగించాలి. ఉద్దేశపూర్వకంగా ఉంచిన మినహాయింపులు: ఎల్లప్పుడూ డార్క్గా ఉండే కన్సోల్ టెర్మినల్ మరియు

   పాలెట్కు చెందిన పరిష్కరించబడిన హెక్స్ ప్రతిరూపం. కేటగిరికల్ పాలెట్లు ఇకపై మినహాయింపు కావు:

   `src/shared/components`) రా `<select>`, `<textarea>` లేదా `<table>` ఉండకూడదు, అలాగే జాబితాలో పేర్కొన్న
   మినహాయింపులకు (`Select` అడాప్టర్కు చెందిన నేటివ్ బ్రాంచ్, `RequestLoggerDetail`) వెలుపల చేతితో రూపొందించిన
   `role="dialog"` ఉండకూడదు; అక్కడి ప్రతి రా `<button>` లేదా `<input>`కు, దానికి గరిష్ఠంగా 3 లైన్ల ముందు ముగిసేలా
   కారణంతో కూడిన `kit-exception:` ఉన్న కామెంట్ అవసరం; పాలెట్ హ్యూలు మరియు `dark:` వేరియంట్లు
   టెస్ట్ జాబితాలో పేర్కొన్న ఫైళ్లలో మాత్రమే ఉండాలి.
7. PRకు ముందు రెండు థీమ్లను మరియు 390 px వ్యూపోర్ట్ను ధృవీకరించండి (స్క్రీన్షాట్లతో); `tests/e2e/a11y.spec.ts`
   axeను అమలు చేస్తుంది.

## 4. అడాప్టర్ను జోడించడం లేదా మార్చడం

1. `src/shared/components/index.tsx` యొక్క పబ్లిక్ API ని అలాగే ఉంచండి: అదే export పేర్లు, default exports మరియు
   ఆమోదించబడిన props. లెగసీ props ని అడాప్టర్ లోపల kit కు మ్యాప్ చేయండి (`Button.tsx` చూడండి: `VARIANT_TO_KIT`,
   `SIZE_TO_KIT`).
2. Kit ని subpath ద్వారా import చేయండి (`@omniroute/ui-kit/<component>`).
3. Kit లోపాల కోసం workaround లు అడాప్టర్లో ఉంటాయి (లేదా పరిష్కారం స్టైల్ అయితే `globals.css` `@layer components`
   లో), ఎప్పుడూ `packages/ui-kit/src` లో కాదు.
4. `tests/unit/ui/adapters/<name>.test.tsx` ని జోడించండి లేదా అప్డేట్ చేయండి. అనేక callers ఉన్న అడాప్టర్ కోసం,
   మార్పుకు ముందు మరియు తర్వాత రెండర్ చేయబడిన markup ని పోల్చండి — padding లేదా wrapper మార్పులు ప్రతి స్క్రీన్కు
   వ్యాపిస్తాయి.

## 5. Kit ని అప్డేట్ చేయడం

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` లో పిన్ చేయబడిన సంస్కరణను అప్స్ట్రీమ్ రెపో యొక్క సరికొత్త `v*` ట్యాగ్తో సరిపోల్చుతుంది మరియు విడుదల ముగిసినప్పుడు సమకాలీకరణ ఆదేశాన్ని ముద్రిస్తుంది.

రోజువారీ `UI Kit upstream watch` వర్క్ఫ్లో (`.github/workflows/ui-kit-upstream-watch.yml`) అదే తనిఖీని అమలు చేస్తుంది. పిన్ వెనుకగా ఉన్నప్పుడు, రోలింగ్ బ్రాంచ్ `chore/ui-kit-sync-latest` లో అత్యధిక `release/vX.Y.Z` శాఖకు వ్యతిరేకంగా `scripts/ci/ui-kit-sync-pr.sh` ఒక సమకాలీకరణ PR తెరిచి ఉంచుతుంది. ఇది ఎప్పటికీ విలీనం కాదు: ప్రతి కిట్ విడుదలకు ఇప్పటికీ స్థానిక VPS పై దృశ్య తనిఖీ అవసరం. కొత్త విడుదల ముగిసినప్పుడు బ్రాంచ్ పునర్నిర్మించబడుతుంది మరియు లేకపోతే ఒంటరిగా మిగిలిపోతుంది. చేతితో నెట్టబడిన కమిట్లతో కూడిన ఓపెన్ PR ఓవర్రైట్ చేయబడదు మరియు మెయింటెయినర్ మూసివేసిన సంస్కరణ కోసం PR కొత్త విడుదల వరకు మూసివేయబడి ఉంటుంది.

PR తెరవబడనప్పుడు (లక్ష్యం విడుదల స్తంభింపజేయబడింది, PR చేతితో నెట్టబడింది, PR మూసివేయబడింది లేదా PR టోకెన్ సెట్ చేయబడలేదు) వర్క్ఫ్లో ఒక ట్రాకింగ్ సమస్యను తెరిచి ఉంచుతుంది, అది ఎందుకు అని చెబుతుంది.

వర్క్ఫ్లో రెండు రహస్యాలను ఉపయోగిస్తుంది:

- `secrets.UI_KIT_READ_TOKEN`: ప్రైవేట్ అప్స్ట్రీమ్ రెపో కోసం చదవడానికి మాత్రమే టోకెన్. అప్స్ట్రీమ్ చెక్ డేటాను చదవలేనప్పుడు (టోకెన్ లేదు, పని చేయడం ఆగిపోయిన టోకెన్ లేదా GitHub అందుబాటులో లేదు), ఇది `unknown` నివేదిస్తుంది మరియు `0` కోడ్తో నిష్క్రమిస్తుంది. వర్క్ఫ్లో ఒక హెచ్చరికను వ్రాస్తుంది మరియు ఒక ప్రత్యేక ట్రాకింగ్ సమస్యను తెరిచి ఉంచడానికి ప్రయత్నిస్తుంది; తర్వాత విజయవంతమైన రన్ యాక్సెస్ తిరిగి వచ్చిన తర్వాత దాన్ని మూసివేస్తుంది. GitHub ఇష్యూ API వైఫల్యం ఉద్యోగంలో విఫలమవుతుంది.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: కంటెంట్లు మరియు పుల్ రిక్వెస్ట్లతో రైట్ యాక్సెస్తో ఈ రిపోజిటరీపై చక్కటి టోకెన్. అంకితమైన టోకెన్ కాన్ఫిగర్ చేయబడినప్పుడు మాత్రమే ఈ వర్క్ఫ్లో సమకాలీకరణ PRs తెరుస్తుంది లేదా నవీకరిస్తుంది; అది లేకుండా, వర్క్ఫ్లో శాఖను నెట్టివేస్తుంది మరియు PR తెరవబడలేదని నివేదిస్తుంది.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` ఆ కమిట్లోని అప్స్ట్రీమ్ `src/` కాపీ చేస్తుంది (`latest` = సరికొత్త `v*` ట్యాగ్) `packages/ui-kit/src`, ఒకే అనుమతించబడిన పరివర్తనను వర్తింపజేస్తుంది (ఇది సంబంధిత దిగుమతుల నుండి `.js` ప్రత్యయాన్ని తొలగిస్తుంది), మరియు వర్క్స్పేస్ వెర్షన్ను `packages/ui-kit/package.json` మరియు `package-lock.json` అప్స్ట్రీమ్కు సెట్ చేస్తుంది. తర్వాత: `git diff packages/ui-kit` సమీక్షించండి, ప్రొవైడర్లు, సెట్టింగ్లు, కాంబోలు, యూసేజ్ మరియు ఎండ్పాయింట్పై రెండు థీమ్లలో విజువల్ పాస్ చేయండి, `npm run check:ui-kit-snapshot` మరియు `npm run test:vitest:ui` రన్ చేయండి మరియు అప్స్ట్రీమ్ చేంజ్లాగ్తో PR తెరవండి.

  HarfBuzzతో Switzer పాత్రలకు ఆకృతినిచ్చి, వాటిని వెక్టర్ అవుట్లైన్లుగా (`<defs>` పాత్లు మరియు `<use>`) గీస్తుంది;
  Switzerలో లేని బాణాలు మరియు జ్యామితీయ చిహ్నాలు దాని స్వంత మెట్రిక్లపై గీయబడతాయి. ఎల్లప్పుడూ అవుట్లైన్లే,
  ఎంబెడ్ చేసిన ఫాంట్ కాదు: Switzer లైసెన్స్ (`packages/ui-kit/src/fonts/FFL.txt`) లిఖితపూర్వక
  సమ్మతి లేకుండా సబ్సెట్టింగ్ మరియు ఫార్మాట్ మార్పిడిని నిషేధిస్తుంది, కానీ వెక్టర్ డ్రాయింగ్లను అనుమతిస్తుంది;
  కాబట్టి Switzer `@font-face` లేదా `data:` URIని తిరిగి ప్రవేశపెట్టవద్దు. ఫైల్లో మిగిలే ఏకైక
  ఫాంట్, నిజమైన కోడ్ టెక్స్ట్గా మిగిలే వాటి కోసం ఉపయోగించే OFL IBM Plex Mono సబ్సెట్
  (`scripts/docs/readme-fonts.mjs`); అది ఆ అక్షరాల నుంచి నిర్మించబడుతుంది, ఎంబెడ్ చేయలేని ఏ గ్లిఫ్ ఉన్నా లోపాన్ని విసురుతుంది.
- **మళ్లీ జనరేట్ చేయడం.** `npm run docs:readme-diagrams` మొత్తం పన్నెండింటినీ README క్రమంలో తిరిగి రాసి, ప్రతి
  ఫైల్కు దాని పరిమాణంతో ఒక లైన్ను ప్రింట్ చేస్తుంది. ఒక్క జనరేటర్ను కూడా స్వతంత్రంగా అమలు చేయవచ్చు
  (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget`కు `node --import tsx/esm` అవసరం, ఎందుకంటే దాని గణాంకాలు
  `open-sse/config/freeModelCatalog.ts`లోని లైవ్ కాటలాగ్ లోడర్ నుంచి వస్తాయి; కాటలాగ్ మార్పు వల్ల కలిగే CI పరిణామం
  `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict`లో ఉంది). జనరేటర్ను మరియు SVGని కలిపి కమిట్ చేయండి.
- **రుజువు.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` స్థానిక పరీక్షలో ఫైల్‌ను రెండర్ చేస్తుంది (`<img>` ట్యాగ్, నిర్బంధ `Content-Security-Policy`, `image/svg+xml` ప్రతిస్పందన), లేత మరియు ముదురు ఫ్రేమ్‌లను తీసి, పేజీ చేసిన బాహ్య ఫాంట్ అభ్యర్థనలను తెలియజేస్తుంది; వాటి సంఖ్య 0 కావాలి.

- **పరిమాణ పరిమితి.** ప్రతి ఫైల్ 200 KB కంటే తక్కువగా ఉండాలి (ప్రతి కాలదోష పరీక్ష దీన్ని నిర్ధారిస్తుంది); ఏ README
  చిత్రానికైనా 500 KB గరిష్ఠ పరిమితి (SVG studio వాలిడేటర్ నియమం).
- **ఉమ్మడి పాఠ్యం, లెక్కలు gate నుంచి.** ప్రతి జనరేటర్ దాని రేఖాచిత్రం యొక్క కాపీని `*_COPY` స్థిరాంకం (లేదా ప్రత్యక్ష కేటలాగ్ నుండి రూపొందించడం)లో తీసుకువెళుతుంది, అది గీసిన వచనం మరియు అవుట్లైనింగ్ దశ యొక్క ఇన్పుట్ రెండూ. కానానికల్ బొమ్మలు `<text>` నోడ్లలో ఉంటాయి (ఒకసారి వివరించిన తర్వాత కనిపించదు, `fill-opacity:0`), `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) ద్వారా చదవబడుతుంది; గేట్ చదివే రేఖాచిత్రాల యొక్క స్టెల్నెస్ పరీక్షలు జనరేట్ చేయబడిన ఫైల్లో దాని వ్యాలిడేటర్లను కూడా అమలు చేస్తాయి, కాబట్టి కోడ్ నుండి డ్రిఫ్ట్ అయ్యే ఫిగర్ పరీక్షలో విఫలమవుతుంది — గేట్ చదివే మూలాన్ని సరిదిద్దుతుంది, జనరేటర్లోని సంఖ్యను ఎప్పటికీ కాదు.
