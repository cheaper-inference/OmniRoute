> లో నిర్వచించబడింది — ఇదే ఏకైక ప్రామాణిక మూలం. డ్యాష్బోర్డ్ మరియు REST API రెండూ
> ఆ ఫైల్ నుంచే చదువుతాయి, కాబట్టి దిగువ పట్టిక దానితో 1:1 సరిపోలేలా రూపొందించబడింది.

## ఫీచర్ ఫ్లాగ్లు అంటే ఏమిటి

ఫీచర్ ఫ్లాగ్ అనేది పేరు కలిగిన టాగిల్ (boolean లేదా enum); దాని విలువను
రన్టైమ్లో మార్చి, డేటాబేస్లో నిల్వ చేయవచ్చు, ఇందుకు ప్రాసెస్ను మళ్లీ డిప్లాయ్ చేయాల్సిన అవసరం లేదు. ప్రతి
ఫ్లాగ్ను `key`, `label`, `description`, `category`, `defaultValue`, `type`,
మరియు `requiresRestart` సూచన కలిగిన `FeatureFlagDefinition` వివరిస్తుంది.

### పరిష్కార ప్రాధాన్యత క్రమం

ఫ్లాగ్ యొక్క **ప్రభావవంతమైన విలువ**ను
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ఈ
ప్రాధాన్యత క్రమంలో పరిష్కరిస్తుంది (అత్యధిక ప్రాధాన్యత గలది అమలవుతుంది):

1. **DB ఓవర్రైడ్** — `feature_flags` నేమ్స్పేస్ కింద `key_value` పట్టికలో
   నిల్వ చేయబడిన విలువ (డ్యాష్బోర్డ్ లేదా REST API ద్వారా సెట్ చేయబడుతుంది).
2. **ఎన్విరాన్మెంట్ వేరియబుల్** — సెట్ చేయబడి, ఖాళీగా లేకపోతే `process.env[<KEY>]`.
3. **నిర్వచన డిఫాల్ట్** — `featureFlagDefinitions.ts` నుంచి తీసుకున్న `defaultValue`.

boolean ఫ్లాగ్ ప్రభావవంతమైన విలువ `"true"`,
`"1"`, లేదా `"yes"` అయినప్పుడు అది **ప్రారంభించబడినట్లు** పరిగణించబడుతుంది
(`isFeatureFlagEnabled()` చూడండి).

> [!NOTE]
> చాలా ఫ్లాగ్లకు [`ENVIRONMENT.md`](./ENVIRONMENT.md)లో డాక్యుమెంట్ చేయబడిన
> **అదే పేరు** గల సంబంధిత ఎన్విరాన్మెంట్ వేరియబుల్ కూడా ఉంటుంది. ఫ్లాగ్ యొక్క DB ఓవర్రైడ్కు
> ఆ ఎన్విరాన్మెంట్ వేరియబుల్ కంటే అధిక ప్రాధాన్యత ఉంటుంది. `requiresRestart: true`
> గల ఫ్లాగ్ వెంటనే నిల్వ చేయబడుతుంది, కానీ ప్రాసెస్ ప్రారంభ సమయంలో మాత్రమే మళ్లీ చదవబడుతుంది
> — దాన్ని టాగిల్ చేసినప్పుడు డ్యాష్బోర్డ్లో **"సర్వర్ను పునఃప్రారంభించండి"** బ్యానర్ కనిపిస్తుంది.

## ఫ్లాగ్లను టాగుల్ చేయడం

### డాష్బోర్డ్

**Dashboard → Settings → Feature Flags** కు నావిగేట్ చేయండి
(`/dashboard/settings/feature-flags`). గ్రిడ్
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
ఇవన్నీ అందిస్తుంది:

- కీ లేదా వివరణ ద్వారా **శోధన**, అలాగే వర్గం ద్వారా **ఫిల్టర్** చేయడం (అదనంగా సింథటిక్
  **Requires Restart** వీక్షణ).
- బూలియన్ ఫ్లాగ్ల కోసం **టాగుల్**, enum ఫ్లాగ్ల కోసం **డ్రాప్డౌన్**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- ప్రతి ఫ్లాగ్కు ఒక **సోర్స్ బ్యాడ్జ్** — `DB`, `ENV`, లేదా `DEF` — ప్రభావవంతమైన విలువ
  ఎక్కడి నుంచి వచ్చిందో చూపిస్తుంది.
- ఓవర్రైడ్ను తొలగించడానికి (`DB`-సోర్స్డ్ ఫ్లాగ్లకు మాత్రమే చూపించే) **Reset**
  బటన్, అలాగే దిగువన **Reset All Overrides** బటన్.
- `requiresRestart` ఫ్లాగ్ మార్చబడినప్పుడు **Restart Server** బ్యానర్.

### REST API

అన్ని ఆపరేషన్లు ఒకే రూట్ ద్వారా జరుగుతాయి:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
ప్రతి మెథడ్కు ప్రామాణీకరించబడిన డాష్బోర్డ్ సెషన్ అవసరం (లేకపోతే `401`).

లాగిన్ నిలిపివేయబడినప్పుడు (`requireLogin=false`) ఈ రూట్ అందరికీ తెరవబడి ఉంటుంది, అయితే
రక్షిత ఫ్లాగ్లకు మినహాయింపు ఉంటుంది: Security వర్గంలోని ప్రతి ఫ్లాగ్తో పాటు
`OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`,
`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS`,
`MITM_DISABLE_TLS_VERIFY`, `OMNIROUTE_MCP_ENFORCE_SCOPES` మరియు
`SKILLS_SANDBOX_NETWORK_ENABLED` (`protectedFeatureFlags.ts` లోని
`isProtectedFeatureFlag()`). వీటిలో ఒకదానిపై `PUT`, అలాగే వీటిలో ఒకదానికి DB ఓవర్రైడ్
ఉన్నప్పుడు `DELETE` చేయాలంటే, డాష్బోర్డ్ సెషన్, `manage`-స్కోప్ API కీ,
రైట్ స్కోప్ లేదా అంతకంటే ఎక్కువ ఉన్న `oma_` యాక్సెస్ టోకెన్, లేదా లూప్బ్యాక్ నుండి
పంపబడిన CLI టోకెన్ లేదా అంతర్గత-సర్వీస్ టోకెన్ అవసరం. లాగిన్ ప్రారంభించబడినప్పుడు
ఇది కంటే పరిమితమైన సెట్ వర్తిస్తుంది: రూట్ కేవలం సెషన్ లేదా `manage`-స్కోప్ కీని
మాత్రమే అంగీకరిస్తుంది.

#### `GET /api/settings/feature-flags`

ప్రతి ఫ్లాగ్ను దాని ప్రభావవంతమైన విలువ, సోర్స్ మరియు సారాంశంతో తిరిగి ఇస్తుంది.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... అన్ని 119 ఫ్లాగ్లు
  ],
  "summary": {
    "total": 119,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ఒకే ఓవర్రైడ్ను సెట్ చేయండి లేదా తొలగించండి. బాడీ: `{ key: string; value?: string }`.
`value` ను వదిలివేస్తే ఓవర్రైడ్ తొలగించబడుతుంది (env / default పునరుద్ధరించబడుతుంది).

```bash
# DB ఓవర్రైడ్ను సెట్ చేయండి
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ఓవర్రైడ్ను తొలగించండి ("value" లేదు)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

ప్రతిస్పందనలో కొత్త `effectiveValue`/`source`, `previousValue`/
`previousSource` మరియు `requiresRestart` తిరిగి ఇవ్వబడతాయి. తెలియని కీలు మరియు
పరిమితికి వెలుపల ఉన్న enum విలువలు `400` తో తిరస్కరించబడతాయి.

#### `DELETE /api/settings/feature-flags`

అన్ని DB ఓవర్రైడ్లను ఒకేసారి తొలగించి, ప్రతి ఫ్లాగ్ను దాని env / default
విలువకు పునరుద్ధరిస్తుంది. `{ cleared: <count>, message: "..." }` ను తిరిగి ఇస్తుంది.

> [!NOTE]
> `requiresRestart: true` ఉన్న ఫ్లాగ్లు ప్రాసెస్ రీలోడ్ అయిన తర్వాత మాత్రమే ప్రభావం చూపుతాయి.
> డాష్బోర్డ్ రీస్టార్ట్ ఫ్లో `POST /api/restart` ను కాల్ చేసి, సర్వర్ తిరిగి అందుబాటులోకి
> వచ్చే వరకు `GET /api/health/ping` ను పోలింగ్ చేస్తుంది.

## అత్యవసర బడ్జెట్ ఫాల్బ్యాక్

`OMNIROUTE_EMERGENCY_FALLBACK` (`runtime` వర్గం, డిఫాల్ట్ `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)లోని
అత్యవసర ఉచిత ఫాల్బ్యాక్ మార్గాన్ని నియంత్రిస్తుంది.
ఇది ప్రారంభించబడి ఉన్నప్పుడు, తమ బడ్జెట్ పూర్తిగా అయిపోయిన అభ్యర్థనలు పూర్తిగా విఫలమయ్యే బదులు ఉచిత ఫాల్బ్యాక్
ప్రొవైడర్/మోడల్కు మళ్లించబడతాయి. ఈ ప్రవర్తనను నిలిపివేసి, బడ్జెట్ అయిపోయిన అభ్యర్థనలు
విఫలమయ్యేలా చేయడానికి, డ్యాష్బోర్డ్ టాగుల్, DB ఓవర్రైడ్ లేదా
`OMNIROUTE_EMERGENCY_FALLBACK` ఎన్విరాన్మెంట్ వేరియబుల్ ద్వారా దీనిని `false` (లేదా `0`)గా సెట్ చేయండి.
(PRలు #3741 / #3752లో డ్యాష్బోర్డ్ టాగుల్గా అందుబాటులోకి తీసుకురాబడింది.)

ఈ ఫాల్బ్యాక్ ద్వారా అందించబడిన ప్రతిస్పందనలో
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` ఉంటుంది, కాబట్టి క్లయింట్ తన
అభ్యర్థనతో `X-OmniRoute-Provider`ను పోల్చాల్సిన అవసరం లేకుండానే అది దారి మళ్లించబడిందని గుర్తించగలదు.
ప్రతి ఇతర ప్రతిస్పందనలో ఈ హెడర్ ఉండదు.
