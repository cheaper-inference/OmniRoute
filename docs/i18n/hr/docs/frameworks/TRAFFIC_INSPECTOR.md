Traffic Inspector je ugrađeni OmniRouteov alat za otklanjanje pogrešaka u HTTPS prometu — alat nalik na Charles Proxy / mitmweb / HTTP Toolkit koji **prepoznaje LLM-ove** i **agente**. Nalazi se na `/dashboard/tools/traffic-inspector` i prima promet uživo iz najviše 5 istodobnih izvora snimanja.

**Lokacija na nadzornoj ploči:** `/dashboard/tools/traffic-inspector`
**Grupa na bočnoj traci:** Alati (nakon AgentBridgea)
**Vidi također:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge je 1. način snimanja.

### Arhitektura u jednom odlomku

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) zajednički je kružni međuspremnik u memoriji (zadano 1000 unosa, podesivo putem `INSPECTOR_BUFFER_SIZE`). Svi izvori snimanja zapisuju u njega putem `push()`. Klasa međuspremnika klasificira svaki unos pomoću `kindDetector.ts` (utvrđuje je li riječ o LLM zahtjevu), izračunava `contextKey` (SHA-256 otisak sistemskog upita) i šalje podatke svim WebSocket pretplatnicima putem `globalTrafficBuffer.subscribe()`. Nadzorna ploča povezuje se putem `GET /api/tools/traffic-inspector/ws` te nakon povezivanja prima snimku trenutačnog stanja, a zatim događaje `new`/`update`/`clear`.

## §2 Načini snimanja

Traffic Inspector podržava **5 istodobnih izvora snimanja**. Svaki se može neovisno uključiti ili isključiti. Polje `source` u svakom objektu `InterceptedRequest` (`src/mitm/inspector/types.ts`) ima jednu od vrijednosti `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"` ili `"tproxy"`.

### Način 1 — AgentBridge (zadano, uvijek uključeno)

**Izvor:** AgentBridge rukovatelji (`src/mitm/handlers/base.ts`)
**Mehanizam:** Svaki poziv `intercept()` u `MitmHandlerBase` poziva `hookBufferStart()` prije prosljeđivanja i `hookBufferUpdate()` nakon dovršetka. Nije potrebna nikakva dodatna konfiguracija — radi čim se AgentBridge pokrene.
**Doseg:** 9 IDE agenata konfiguriranih u sustavu AgentBridge
**Napomena:** Polje `source` u objektu `InterceptedRequest` = `"agent-bridge"`

### Način 2 — Prilagođeni hostovi (DNS preusmjeravanje)

**Izvor:** Korisnički definiran popis hostova (tablica `inspector_custom_hosts`)
**Mehanizam:** Dodavanjem hosta putem korisničkog sučelja dodaje se `127.0.0.1 <host>` u `/etc/hosts` (zahtijeva sudo). Postojeći AgentBridge MITM poslužitelj (port 443) dinamički generira SNI certifikat za novi host.
**Doseg:** Svaka aplikacija koja koristi dodani host — nije potrebna promjena konfiguracije aplikacije
**Napomena:** `source` = `"custom-host"`

Primjeri upotrebe:

- Nadzor hosta `api.openai.com` iz Python skripti
- Otklanjanje pogrešaka za `my-internal-llm.company.com`
- Snimanje prometa s mobilnih uređaja na istoj mreži (putem ARP lažiranja — napredno)

### Način 3 — HTTP_PROXY osluškivač (port 8080)

**Izvor:** Aplikacije koje upotrebljavaju varijable okruženja `HTTP_PROXY`/`HTTPS_PROXY`
**Mehanizam:** Sekundarni osluškivač na portu 8080 (`src/mitm/inspector/httpProxyServer.ts`) koji djeluje kao standardni eksplicitni HTTP/HTTPS proxy. Prihvaća `CONNECT` tunele (HTTPS) i izravne HTTP zahtjeve.
**Doseg:** Svaka aplikacija koja poštuje varijablu okruženja `HTTP_PROXY` — bez promjene DNS-a i bez naredbe sudo
**Napomena:** `source` = `"http-proxy"`

```bash
# Brzo snimanje za jednu naredbu:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# Trajno snimanje u sesiji ljuske:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**Ograničenje TLS-a:** HTTPS prolazi kroz običan `CONNECT` tunel: osluškivač prosljeđuje šifrirane bajtove bez izmjena i bilježi samo metapodatke (host, port, vrijeme). Nikada ne dešifrira HTTPS i ne postoji postavka koja bi omogućila dešifriranje u ovom načinu rada. Za snimanje tijela HTTPS poruka usmjerite host kroz Način 1 (AgentBridge), Način 2 (Prilagođeni hostovi) ili Način 5 (TPROXY dešifriranje).

**Sukob portova:** Ako se port 8080 već koristi, AgentBridge vraća 409 sa strukturiranom pogreškom. Promijenite port putem varijable okruženja `INSPECTOR_HTTP_PROXY_PORT`.

### Način 4 — Proxy na razini cijelog sustava (napredno, uključivanje po želji)

**Izvor:** Postavke proxyja na razini operacijskog sustava (primjenjuju se na sve aplikacije na računalu)
**Mehanizam:** Upotrebljava API-je operacijskog sustava za preusmjeravanje cjelokupnog HTTP/HTTPS prometa kroz HTTP_PROXY osluškivač:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **Doseg:** Svaka aplikacija na računalu koja poštuje postavke proxyja sustava
  **Napomena:** `source` = `"system-proxy"`

**Sigurnosni mehanizmi:**

- Mjerač vremena za automatsko isključivanje (zadano 30 min, može se konfigurirati putem `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES`)
- Prethodno stanje proxyja sustava sprema se u bazu podataka i vraća pri poništavanju
- Nadzorna ploča prikazuje upit „Vraćanje proxyja sustava” ako korisnik napusti stranicu dok je proxy aktivan
- Korisničko sučelje prikazuje oznaku `⚠ Napredno` + eksplicitni potvrdni okvir za potvrdu

### Način 5 — TPROXY transparentno dešifriranje (Linux, root, uključivanje po želji)

**Izvor:** TPROXY jezgre + usmjeravanje prema pravilima (`src/mitm/tproxy/`)
**Mehanizam:** Označava nove lokalne odlazne TCP veze prema ciljnom portu (zadano `443`) u lancu `mangle OUTPUT`, naredba `ip rule` preusmjerava označene pakete na lokalnu isporuku, a cilj `TPROXY` lanca `mangle PREROUTING` predaje ih transparentnom (**IP_TRANSPARENT**) osluškivaču (zadani port `8443`). Osluškivač prekida TLS pomoću krajnjeg certifikata koji dinamički CA izdaje **na zahtjev za svaki SNI naziv hosta**, snima dešifriranu razmjenu te prosljeđuje zahtjev, ponovno šifriran, izvornom odredištu.
**Doseg:** **Proizvoljni** odredišni hostovi na ciljnom portu — bez lažiranja putem `/etc/hosts`, bez varijable okruženja `HTTP_PROXY` i bez promjene proxyja na razini cijelog sustava. Presretnuti proces ne zahtijeva promjenu konfiguracije, ali mora vjerovati dinamičkom CA-u.
**Napomena:** `source` = `"tproxy"`

**Zahtjevi:** Samo Linux (**IP_TRANSPARENT** je dostupan samo na Linuxu), mogućnost **CAP_NET_ADMIN** (root) i izvorni N-API dodatak koji se mora izgraditi pomoću C alata (`npm run build:native:tproxy`). Kada nisu dostupni, prekidač na nadzornoj ploči onemogućen je uz opis „TPROXY dešifriranje zahtijeva Linux + root + izvorni dodatak”. Pravila vatrozida primjenjuju se i poništavaju transakcijski (rušenje nikada ne ostavlja pravilo `mangle`) te se uklanjaju pri ponovnom pokretanju. Mehanizam protiv petlje temeljen na SO_MARK sprječava ponovno presretanje proslijeđenog prometa koji je proxy ponovno šifrirao.

Ovo je opsežan podsustav s vlastitim namjenskim vodičem za operatere — pogledajte `docs/security/MITM-TPROXY-DECRYPT.md` (git; nije ugrađen u `/docs`) za cjelovit recept vatrozida, dinamički CA za svaki SNI + instalacijski program za spremište pouzdanih certifikata, lokalnu rutu, pojedinosti o zaštiti od petlje i konfiguracijsku shemu. Prekidačem se upravlja putem `GET / POST / DELETE /api/tools/agent-bridge/tproxy` (napomena: ruta se nalazi pod prefiksom AgentBridge, a ne pod prefiksom Traffic Inspector).

### 3.2 Popis zahtjeva (lijevo okno)

- **Virtualiziran** (`useVirtualList` + `ResizeObserver`): obrađuje 1000 stavki bez zamrzavanja
- **Automatsko pomicanje** s prekidačem za pauziranje tijekom pregleda
- **Status označen bojama**: zeleno (2xx), žuto (3xx), crveno (4xx/5xx), sivo (u tijeku)
- **Emoji agenta**: 🔵 Antigravity, 🟢 Copilot, 🟠 Kiro, 🟣 Codex, 🔷 Cursor, 🟤 Zed, 🟡 Claude Code, ⚫ Open Code, 🌐 prilagođeni host
- **Traka boje konteksta**: lijevi obrub od 1 px obojen prema `contextKey` (SHA-256 sistemskog upita) — vizualno grupira povezane razgovore
- **Lijeno učitavanje tijela**: samo se tijelo odabranog zahtjeva materijalizira u karticama s pojedinostima (izbjegava iscrtavanje 1000 × 1 MB tijela)

### 3.3 Okno s pojedinostima — 7 kartica

| Kartica               | Sadržaj                                                                                         | Napomene                                                                                            |

- Može se sažeti na traku od 48 px (samo ikone); kliknite redak u traci kako biste je proširili

## §4 Značajke prilagođene LLM-ovima

### 4.1 Detektor vrste (`src/mitm/inspector/kindDetector.ts`)

Klasificira svaki zahtjev kao `"llm"`, `"app"` ili `"unknown"` koristeći 4 signala:

1. **Registar poslužitelja** — ~18 poznatih naziva poslužitelja LLM API-ja (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot itd.)
2. **Uzorci putanja** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses` itd.
3. **Struktura tijela** — otkriva polja `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input`
4. **Naznake korisničkog agenta** — `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor` u UA nizu

Prilagođeni poslužitelji dodani putem načina rada 2 nasljeđuju svoj `kind` iz unosa u obrascu (zadana je vrijednost `"custom"`).

### 4.2 Spajanje SSE događaja (`src/mitm/inspector/sseMerger.ts`)

**Neovisna implementacija razvijena od nule.** Raščlanjivanje događaja slijedi
[WHATWG algoritam za događaje koje šalje poslužitelj](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream),
dok rekonstrukcija slijedi javne sheme strujanja za [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming) i
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent).

Rekonstruira konačnu poruku asistenta iz neobrađenih SSE delta događaja:

- **Anthropic**: akumulira `content_block_delta` prema indeksu; obrađuje `text_delta`, `input_json_delta` (pozive alata), `thinking_delta`
- **OpenAI**: akumulira odabire/pozive alata sučelja Chat Completions i izlazne stavke sučelja Responses API
  prema indeksu
- **Gemini**: akumulira `candidates[i].content.parts`
- **Nepoznato**: vraća neobrađene događaje bez izmjena

Kartica Odgovor prikazuje preklopnik: **„Neobrađeni događaji ↔ Spojeno”**.

### 4.3 Normalizator razgovora (`src/mitm/inspector/conversationNormalizer.ts`)

**Neovisna implementacija razvijena od nule.** Normalizacija je definirana lokalnim
ugovorima crne kutije i javnim shemama poruka za OpenAI, Anthropic i Gemini; ne
upotrebljava se izvorni kôd uzvodne implementacije.

Pretvara formate poruka OpenAI-ja, Anthropica i Geminija u jedinstveni `NormalizedConversation` prije iscrtavanja:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // poruke / sadržaji / upit iz tijela zahtjeva
  response: NormalizedTurn[]; // odgovor asistenta (spojen putem sseMerger)
  contextKey: string | null; // SHA-256 otisak sistemskog upita
}
```

Vrste blokova: `text`, `tool_use`, `tool_result`. Kartica Razgovor upotrebljava ovu strukturu neovisno o pružatelju usluge.

### 4.4 Bojanje ključa konteksta (`src/mitm/inspector/contextKey.ts`)

- Izračunava `SHA-256` sistemskog upita (prva poruka `role:system`, polje `system` ili Geminijev `systemInstruction`)
- Vraća heksadecimalni prefiks od 12 znakova (`"a3f9c2..."`)
- Sučelje preslikava ključ u determinističku HSL boju trake lijevog obruba
- **Filtar „isti kontekst”**: klik na oznaku `ctx #a3f` dodaje filtar koji prikazuje samo zahtjeve s istim otiskom

To olakšava vizualno razlikovanje različitih „persona” ili zadataka koji se izvode u istoj sesiji agenta.

### 4.5 Izdvajanje metapodataka LLM-a

Za LLM zahtjeve kartica Pojedinosti LLM-a izdvaja:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // iz tijela zahtjeva ili odgovora
  messages: number; // broj izmjena
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // true ako je odgovor SSE
  mappedTo: string | null; // zaglavlje x-omniroute-mapped
  costEstimateUsd: number | null; // procijenjeni trošak na temelju cijena OmniRoutea
}
```

### 4.6 Filtar aktivnih zahtjeva u stvarnom vremenu

Polje `status` zahtjeva ima tip `number | "in-flight" | "error"` — unos se
dodaje kao `"in-flight"` čim zahtjev započne i **ažurira na mjestu**
kada stigne odgovor (ili pogreška). Preklopnik **„Uživo”** na alatnoj traci
(`liveOnly`, i18n ključ `trafficInspector.liveOnly`) ograničava popis na unose
čiji je `status === "in-flight"`, omogućujući praćenje otvorenih veza u stvarnom vremenu.

Filtar je čisti predikat na klijentskoj strani u
`src/lib/inspector/matchesTrafficFilter.ts`:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

Stanje preklopnika nalazi se u `useTrafficFilters` (hookovima nadzorne ploče inspektora) i
kombinira se s ostalim filtrima (profil, poslužitelj, agent, izvor, status, kontekst).

### 4.7 Pripisivanje procesa (Linux)

Na Linuxu se svaki presretnuti zahtjev može pripisati **izvornom lokalnom
procesu**. U `InterceptedRequest` dodaju se dva neobavezna polja:

```ts
pid?: number;          // identifikator izvornog procesa (samo Linux)
processName?: string;  // naziv izvornog procesa (samo Linux)
```

`src/mitm/inspector/processAttribution.ts` preslikava privremeni port _klijenta_
veze u PID + naziv na sljedeći način:

1. Čita `/proc/net/tcp` i `/proc/net/tcp6` kako bi pronašao inode utičnice za
   port (`parseProcNetTcpForInode`, čisti parser koji se može testirati pomoću testnih podataka).
2. Pretražuje `/proc/<pid>/fd/` radi simboličke poveznice na `socket:[<inode>]`.
3. Čita naziv procesa iz `/proc/<pid>/comm`.

Predmemorija s TTL-om od 1 sekunde ograničava trošak pregledavanja procfs-a pod opterećenjem. Pripisivanje se
izvodi **prema najboljoj mogućnosti** — svaki se neuspjeh razrješava u `null` i nikada ne blokira snimanje. Na
sustavima macOS/Windows funkcija vraća `null` (privremena implementacija; podrška za `lsof`/`GetExtendedTcpTable`
bit će dodana naknadno).

## §6 Sigurnost

Traffic Inspector prikazuje **sav presretnuti HTTPS promet**, uključujući zaglavlja za autorizaciju i tijela zahtjeva. Primjenjuju se sljedeće kontrole:

| Kontrola                        | Pojedinosti                                                                                                                                                                                                     |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                  | Sve rute i WebSocket krajnja točka dostupne su samo putem povratne petlje (provodi se u `routeGuard.ts` prije autentifikacije)                                                                                  |
| **Maskiranje tajnih podataka**  | Linearni skener `maskSecret()` redigira vjerodajnice Bearer prema RFC-u 6750, ključeve s prefiksom pružatelja i duge neprozirne tokene prije `TrafficBuffer.push()`                                             |
| **Ograničenje veličine tijela** | Tijela > `INSPECTOR_MAX_BODY_KB` (zadano 1024 KB) skraćuju se uz obavijest `"(skraćeno radi performansi)"`                                                                                                      |
| **Sanitizacija zaglavlja**      | Nazivi se pretvaraju u mala slova; odbacuju se zaglavlja za uokvirivanje, hop-by-hop i autentifikaciju proxyja; kolačići se potpuno redigiraju; vrijednosti vjerodajnica prosljeđuju se funkciji `maskSecret()` |
| **CSP**                         | Stroga Politika sigurnosti sadržaja na stranicama alata Traffic Inspector radi sprječavanja XSS-a putem umetnutih tijela odgovora                                                                               |
| **Bez zadane trajne pohrane**   | `TrafficBuffer` se nalazi u memoriji i gubi se pri ponovnom pokretanju poslužitelja. Sesije se trajno pohranjuju samo kada se izričito snimaju                                                                  |

### Primijenjena stroga pravila

| Pravilo                           | Primjena                                                                                |
| --------------------------------- | --------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Svi HTTP odgovori s pogreškama iz ruta alata Traffic Inspector sanitiziraju se          |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` je LOCAL_ONLY + SPAWN_CAPABLE (naredbe proxyja sustava) |

### Poznata ograničenja

- **Način rada proxyja na razini cijelog sustava** utječe na sve aplikacije na računalu, uključujući VPN klijente i SSO. Uvijek ga koristite s mjeračem vremena za automatsko onemogućavanje. Nemojte ga koristiti na zajedničkim računalima.
- **HTTPS putem tunela CONNECT**: Način rada 3 (HTTP_PROXY) bilježi samo metapodatke tunela za HTTPS odredišta i nikada ih ne dešifrira. To je namjerno — dešifriranje bi zahtijevalo da svaki klijent vjeruje MITM certifikatu, pa slušatelj zadržava obostrano HTTPS šifriranje. Upotrijebite AgentBridge, Custom Hosts ili TPROXY decrypt kada su vam potrebna HTTPS tijela.
- **Tvrdo kodirani nizovi u nekim komponentama**: Neke komponente korisničkog sučelja (F7/F8) sadrže mali broj tvrdo kodiranih nizova koji još nisu obuhvaćeni i18n ključevima. Dokumentirani su kao poznato ograničenje u izvješću o nedostacima i18n-a; bit će migrirani u naknadnom prolazu. Obuhvaćeni nizovi ukrasne su oznake korisničkog sučelja koje nije potrebno prevoditi za funkcionalnu upotrebu.

## §7 Rješavanje problema

### Prekid WebSocket veze

Ako praćenje uživo prikazuje "Veza je prekinuta":

1. Provjerite radi li poslužitelj još uvijek: `GET /api/tools/traffic-inspector/capture-modes`
2. Ponovno učitajte stranicu — WebSocket se ponovno povezuje i prima novu snimku
3. Ako je poslužitelj ponovno pokrenut, međuspremnik u memoriji je izbrisan — stari zapisi više nisu dostupni osim ako je sesija bila snimljena

### Sukob na priključku 8080

Ako se način rada HTTP_PROXY ne uspije pokrenuti:

```bash
lsof -i :8080    # pronađite proces
```

Promijenite priključak:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### Sistemski proxy nije vraćen na prethodne postavke

Ako se OmniRoute sruši dok je aktivan način rada sistemskog proxyja:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

Nadzorna ploča također će pri sljedećem učitavanju ponuditi opciju "Vrati postavke sistemskog proxyja" ako otkrije da stanje baze podataka pokazuje da je proxy bio aktivan.

### Pun međuspremnik

Kada međuspremnik dosegne `INSPECTOR_BUFFER_SIZE` (zadano 1000), novi zapisi potiskuju najstarije. Ako se važni zahtjevi gube:

- Povećajte `INSPECTOR_BUFFER_SIZE` (npr. 5000) — time se povećava potrošnja memorije radi duljeg zadržavanja
- Snimite sesiju kako biste relevantno razdoblje trajno pohranili u bazu podataka
