`copilot-m365-web` (alias `m365copilot`) šalje zahtjeve za razgovor u OpenAI formatu putem
autentificirane sesije preglednika Microsoft 365 Copilot BizChat na adresi
`m365.cloud.microsoft/chat`. Ovo je neslužbena integracija.

> **Prvi se put susrećete s pružateljima Web Cookie?**
>
> Prije nego što nastavite s ovim vodičem specifičnim za pružatelja, pročitajte **`docs/getting-started/WEB-COOKIE-GUIDE.md`** radi upoznavanja s općim postupkom postavljanja, smjernicama za autentifikaciju, ograničenjima i rješavanjem problema.
>
> **Važno:** Vjerodajnica za ovog pružatelja **nije kolačić**. Nemojte kopirati
> kolačiće s domene `m365.cloud.microsoft`. Vjerodajnica se sastoji od parametra upita
> WebSocket URL-a i segmenta putanje, koji se čitaju na kartici Network u DevTools alatima.

## Preduvjeti

- Microsoft 365 račun s pristupom usluzi BizChat na adresi `m365.cloud.microsoft/chat`
- Preglednik temeljen na Chromiumu (Chrome, Edge) za pregled WebSocket veza u DevTools alatima
- Licenca za M365 Copilot (uključena u mnoge Microsoft 365 Business/Enterprise planove)

## Dohvaćanje vjerodajnice (metoda WebSocket)

1. Prijavite se na `https://m365.cloud.microsoft/chat` i započnite razgovor.
2. Otvorite **DevTools → Network**.
3. Filtrirajte prema **WS** (WebSocket).
4. Kliknite WebSocket vezu Chathub. Potražite URL koji počinje s
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Iz njegova polja **Request URL** kopirajte:
   - Vrijednost parametra upita `access_token` (kratkotrajni JWT).
   - Segment putanje Chathub nakon `/Chathub/` (npr. `<oid>@<tenant>`).

Cijeli URL ima sljedeći oblik:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. U aplikaciji OmniRoute idite na **Providers → Add Provider**, odaberite **Microsoft 365 Copilot
   (BizChat)** i zalijepite vjerodajnicu u sljedećem formatu:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Kliknite **Test Connection**, a zatim **Save**.

## Dohvaćanje vjerodajnice (uvoz HAR datoteke)

Umjesto ručnog kopiranja vrijednosti iz WebSocket URL-a, možete izvesti DevTools HAR
datoteku:

1. Otvorite **DevTools → Network**.
2. Započnite ili nastavite BizChat razgovor (time se pokreće WebSocket veza).
3. Desnom tipkom miša kliknite unutar ploče Network i odaberite **Save all as HAR with content**.
4. U aplikaciji OmniRoute upotrijebite gumb **Import .har file** u dijaloškom okviru veze s pružateljem.

OmniRoute pretražuje HAR datoteku radi pronalaženja Chathub WebSocket URL-a, izdvaja
`access_token` i `chathubPath` te automatski popunjava polja vjerodajnica. Pri
uvozu HAR datoteke dekodira se vrijeme isteka JWT-a i prikazuje preostalo vrijeme valjanosti tokena.

> **Nikada nemojte pohraniti stvarni HAR izvoz, pristupni token ili token za osvježavanje u repozitorij.** Vrijednosti za testiranje i
> dokumentaciju uvijek moraju biti zamjenske vrijednosti.

## Trajanje tokena i osvježavanje

`access_token` kratkog je vijeka (obično **~75 minuta**). Bez upotrebljivog tokena
za osvježavanje morate ponovno dohvatiti vjerodajnicu nakon isteka.

### Automatsko osvježavanje pomoću `refreshToken`

U dijaloškom okviru **Dodaj vezu** ili **Uredi vezu** davatelja Microsoft 365 otvorite
**Napredne postavke → Token za osvježavanje (nije obavezno)**. Zalijepite Microsoftov OAuth token za osvježavanje
za opseg `substrate.office.com/sydney` i spremite. Unos je maskiran i nikad se unaprijed ne popunjava pohranjenim tokenom. Prilikom uređivanja ostavite ga praznim kako biste zadržali postojeći token;
zalijepite novi token da biste ga zamijenili.

Token za osvježavanje dohvatite putem Microsoftova tijeka koda uređaja ili autorizacijskog koda
s opsegom `substrate.office.com/sydney`; nadzorna ploča ga ne dohvaća umjesto vas.
Kada je token za osvježavanje konfiguriran, OmniRoute provjerava `access_token` prije zahtjeva
i osvježava ga samo kada ga je potrebno osvježiti. Uspješno osvježavanje također sprema rotirani token za osvježavanje, čime se izbjegava ručno ponovno dohvaćanje dok je token za osvježavanje valjan.

Ako `refreshToken` nije postavljen, morate ručno ponovno dohvatiti vjerodajnicu za WebSocket
nakon svakog isteka.

| Razina       | Alias      | Površina                          |

| `individual` | _(zadano)_ | M365 Copilot za potrošače         |

## Sigurnosni model

- **Neslužbena integracija.** Ovaj pružatelj obrnutim inženjeringom rekonstruira BizChat WebSocket
  protokol. Može prestati raditi bez prethodne najave kada Microsoft promijeni krajnju točku.
- Oznaka `subscriptionRisk: true` ukazuje na to da se integracija oslanja na
  nedokumentiranu krajnju točku. Ograničenja računa moguća su, ali nisu potvrđena.
- Pristupni token kratkotrajni je JWT. Postupajte s njim kao s lozinkom: nemojte ga predavati u repozitorij,
  zapisivati u zapisnike ni dijeliti.
- Token za osvježavanje omogućuje dugoročan pristup sučelju BizChat. Pohranite ga uz
  istu razinu zaštite kao API ključ.

## Otklanjanje poteškoća

### Provjera autentičnosti odmah ne uspijeva

- Provjerite jeste li kopirali iz **WebSocket URL-a**, a ne iz XHR/Fetch zahtjeva. Vjerodajnica se nalazi u parametru upita `access_token` Chathub WebSocket veze — a ne u zaglavlju `Authorization: Bearer`.
- Provjerite uključuje li `chathubPath` cijeli segment `<oid>@<tenant>` iz putanje URL-a.

### Token istječe nakon otprilike 75 minuta

To je očekivano. Bez `refreshToken` pristupni token kratko traje. Učinite jedno od sljedećeg:

- Ponovno dohvatite vjerodajnicu iz alata DevTools ili
- Konfigurirajte **Napredne postavke → Token za osvježavanje (neobavezno)** u dijaloškom okviru za dodavanje ili uređivanje veze kako biste omogućili automatsko osvježavanje.

### Testiranje veze prolazi, ali chat vraća 401

Token je možda istekao između provjere valjanosti i prvog zahtjeva. Ponovno dohvatite svježu vjerodajnicu.

### Copilot se ne pojavljuje na popisu pružatelja

Provjerite je li `copilot-m365-web` omogućen u odjeljku **Nadzorna ploča → Pružatelji**. Pružatelj je prema zadanim postavkama možda skriven u nekim razinama usluge.
