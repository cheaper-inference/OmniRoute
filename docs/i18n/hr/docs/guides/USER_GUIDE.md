## 🎯 Slučajevi korištenja

### Slučaj 1: "Imam pretplatu na Claude Pro"

**Problem:** Kvota istječe neiskorištena, ograničenja stope prilikom intenzivnog programiranja

```
Kombinacija: "maximize-claude"
  1. cc/claude-opus-4-7        (potpuno iskoristite pretplatu)
  2. glm/glm-4.7               (jeftina rezerva kad kvota istekne)
  3. if/qwen3.8-max-preview       (besplatna rezerva za hitne slučajeve)

Mjesečni trošak: $20 (pretplata) + ~$5 (rezerva) = $25 ukupno
u odnosu na $20 + dosezanje ograničenja = frustracija
```

### Slučaj 2: "Želim nulti trošak"

**Problem:** Ne mogu si priuštiti pretplate, treba pouzdana AI podrška za programiranje

```
Kombinacija: "zero-cost"
  1. if/kimi-k2.7-code          (navedeni besplatan pristup; mogu se primjenjivati ograničenja stope)
  2. kr/qwen3-coder-next        (Kiro besplatna rezerva)

Mjesečni trošak: $0
Kvaliteta: provjerite model, ograničenja, privatnost i SLA za vaše radno opterećenje
```

### Slučaj 3: "Trebam programiranje 24/7, bez prekida"

**Problem:** Rokovi, ne mogu si priuštiti prekide u radu

```
Kombinacija: "always-on"
  1. cc/claude-opus-4-7        (najbolja kvaliteta)
  2. cx/gpt-5.5                (druga pretplata)
  3. glm/glm-4.7               (jeftino, dnevno resetiranje)
  4. minimax/MiniMax-M2.1      (najjeftinije, resetiranje na 5h)
  5. if/deepseek-v4-flash       (navedeni besplatan pristup; mogu se primjenjivati ograničenja stope)

Rezultat: 5 razina rezerve proširuje otpornost sustava; dostupnost izvora nije zagarantirana
Mjesečni trošak: $20-200 (pretplate) + $10-20 (rezerva)
```

### Slučaj 4: "Želim BESPLATNI AI u OpenClaw"

**Problem:** Potreban AI asistent u aplikacijama za razmjenu poruka, potpuno besplatno

```
Kombinacija: "openclaw-free"
  1. if/qwen3.8-max-preview     (navedeni besplatan pristup; mogu se primjenjivati ograničenja stope)
  2. if/deepseek-v4-flash       (navedeni besplatan pristup; mogu se primjenjivati ograničenja stope)
  3. if/kimi-k2.7-code          (navedeni besplatan pristup; mogu se primjenjivati ograničenja stope)

Mjesečni trošak: $0
Pristup putem: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 Postavljanje pružatelja

Za grupno dodavanje veza s API ključem iz CSV ili JSON datoteke upotrijebite **Nadzorna ploča → Pružatelji → Uvoz iz datoteke**. Stupci su pozicijski (`provider,name,apiKey,baseUrl,priority`); `provider` već mora postojati kao upravljani pružatelj ili kompatibilni čvor. Pogledajte [Uvoz pružatelja iz CSV ili JSON datoteke](../providers/CSV-IMPORT.md).

### 🔐 Pretplatnički pružatelji

#### Claude Code (Pro/Max)

```bash
Nadzorna ploča → Pružatelji → Poveži Claude Code
→ OAuth prijava → Automatsko osvježavanje tokena
→ Praćenje 5-satne i tjedne kvote

Modeli:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**Savjet:** Upotrijebite Opus za složene zadatke, a Sonnet za brzinu. OmniRoute prati kvotu po modelu!

Nemate preglednik na OmniRoute hostu? Pokrenite `claude setup-token` bilo gdje gdje ste prijavljeni u Claude Code i zalijepite jednogodišnji token u karticu **Setup Token**. Pogledajte [Claude Code s tokenom za postavljanje](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

Claude i rute kompatibilne s Claude Codeom zadržavaju razinu razmišljanja `max` za modele Opus i Sonnet. Modeli Haiku ne prihvaćaju razinu napora `max`, pa OmniRoute taj zahtjev smanjuje na visoki proračun za razmišljanje prije nego što ga pošalje uzvodno.

#### OpenAI Codex (Plus/Pro)

```bash
Nadzorna ploča → Pružatelji → Poveži Codex
→ OAuth prijava (ulaz 1455)
→ 5-satno i tjedno resetiranje

Modeli:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
Nadzorna ploča → Pružatelji → Poveži GitHub
→ OAuth putem GitHuba
→ Mjesečno resetiranje (1. u mjesecu)

Modeli:
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview
```

**AI krediti (naplata na temelju tokena).** Kada GitHub za račun prijavi `credits_used`, kartica Ograničenja pružatelja prikazuje redak **AI krediti** s brojem kredita potrošenih u trenutačnom obračunskom razdoblju, uključujući neograničene organizacijske planove.

**Lokalno ograničenje AI kredita.** Uredite GitHub vezu i postavite **AI Credits limit per
billing period** (`providerSpecificData.githubCreditLimit`). Prazno onemogućuje ograničenje; `0`
uvijek preskače vezu. Kada je posljednje očitanje upotrebe jednako ograničenju ili veće od njega,
odabir računa preskače tu vezu, a usmjeravanje se vraća na vaše druge veze, jednako kao kod
prekida uzrokovanog pravilima kvote. Provjera čita upotrebu koju već prikuplja periodično
osvježavanje kvote — nikada ne poziva GitHub na putanji zahtjeva — i ne blokira u slučaju
nedostupnih podataka: nedostajuće ili zastarjelo očitanje (starije od 15 minuta ili iz obračunskog
razdoblja koje je već resetirano) ne blokira vezu. Ovo je lokalna zaštita, **a ne zajamčena gornja
granica potrošnje**: kašnjenja u GitHubovom izvještavanju, interval osvježavanja, zahtjevi u tijeku i
upotreba izvan OmniRoutea mogu premašiti to ograničenje. Za strogu gornju granicu upotrijebite
vlastite GitHubove kontrole potrošnje.

### 💰 Jeftini pružatelji

1. Registrirajte se: [Zhipu AI](https://open.bigmodel.cn)
2. Nabavite API ključ iz Coding Plana
3. Nadzorna ploča → Dodaj API ključ: Pružatelj: `glm`, API ključ: `your-key`

**Upotreba:** `glm/glm-4.7` — **Savjet:** Coding Plan nudi 3× veću kvotu uz 1/7 troška! Resetiranje svaki dan u 10:00.

#### MiniMax M2.1 (5-satno resetiranje, $0.20/1M)

1. Registrirajte se: [MiniMax](https://www.minimax.io)
2. Nabavite API ključ → Nadzorna ploča → Dodaj API ključ

**Upotreba:** `minimax/MiniMax-M2.1` — **Savjet:** Najjeftinija opcija za dugačak kontekst (1M tokena)!

#### Kimi K2 ($9/mjesečno, fiksno)

1. Pretplatite se: [Moonshot AI](https://platform.kimi.ai?aff=omniroute)
2. Nabavite API ključ → Nadzorna ploča → Dodaj API ključ

**Upotreba:** `kimi/kimi-k2.5` — **Savjet:** Fiksnih $9/mjesečno za 10M tokena = efektivni trošak od $0.90/1M!

#### Baidu Qianfan / ERNIE

1. Registrirajte se: [Baidu AI Cloud Qianfan](https://cloud.baidu.com/product/wenxinworkshop)
2. Izradite Qianfan API ključ → Nadzorna ploča → Dodaj API ključ: Pružatelj: `qianfan`

**Upotreba:** `qianfan/ernie-5.1`, `qianfan/ernie-x1.1` ili drugi ID modela kompatibilan s Qianfan OpenAI API-jem.

uklanja njegove modele iz `/v1/models`.

```bash
Nadzorna ploča → Poveži Kiro → AWS Builder ID ili Google/GitHub → ~50 kredita mjesečno

Modeli: kr/claude-sonnet-4.5, kr/claude-haiku-4.5
```

## 🎨 Kombinacije

Kartice kombinacija možete preslagati direktno u **Dashboard → Combos** povlačenjem ručke na svakoj kartici. Redoslijed se pohranjuje u SQLite i vraća prilikom ponovnog učitavanja.

### Primjer 1: Maksimalno iskoristi pretplatu → jeftina rezerva


## 🚀 implementacija

### Globalna npm instalacija (preporučeno)

```bash
npm install -g omniroute

# Create config directory
mkdir -p ~/.omniroute

# Create .env file (see .env.example)
cp .env.example ~/.omniroute/.env

# Start server
omniroute
# Or with custom port:
omniroute --port 3000
```

CLI automatski učitava `.env` iz `~/.omniroute/.env` ili `./.env`. `./.env` u radnom direktoriju može postaviti samo kratku listu dopuštenih ključeva (portovi, `REQUIRE_API_KEY`, lokalne postavke i postavke boja); sve ostalo stavi u `~/.omniroute/.env`. Pogledajte [ugovore o pokretanju CLI](CLI-LAUNCH-CONTRACTS.md#working-directory-env).

### Način ladice

Pokrenite OmniRoute u programskoj traci:

```bash
omniroute serve --tray
```

Naredba se vraća nakon što su poslužitelj i tray spremni.

Poslužitelj nastavlja bez terminala.

Tray način rada podržava macOS, Windows i grafičke Linux sesije. Način ladice ne otvara nadzornu ploču automatski.

Koristite izbornik trake za ove radnje:

- Otvori nadzornu ploču.
- Otvorite `/dashboard/logs`.
- Promjena automatskog pokretanja.
- Zaustavi OmniRoute.

Nemojte kombinirati `--tray` s ovim opcijama:

- `--daemon`
- `--log`
- `--no-recovery`

Ovi načini zahtijevaju različito vlasništvo nad procesom.

Omogući pokretanje pri sljedećoj prijavi na stroj:

```bash
omniroute autostart enable
```

Automatsko pokretanje koristi način ladice na macOS, Windows i grafičkim Linux sesijama. Headless Linux koristi postojeću korisničku uslugu systemd.

Onemogući pokretanje pri prijavi:

```bash
omniroute autostart disable
```

<details>
<summary><b>Pogledajte predložak xbps-src</b></summary>

```bash
# Template file for 'omniroute'
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
checksum=009400afee90a9f32599d8fe734145cfd84098140b7287990183dde45ae2245b
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# Determine target CPU arch for node-gyp
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) Install all deps – skip scripts
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Build the Next.js standalone bundle
	npm run build

	# 3) Copy static assets into standalone
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) Compile better-sqlite3 native binding
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) Place the compiled binding into the standalone bundle
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) Remove arch-specific sharp bundles
	rm -rf .next/standalone/node_modules/@img

	# 7) Copy pino runtime deps omitted by Next.js static analysis:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# Prevent removal of empty Next.js app router dirs by the post-install hook
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

### Varijable okoline

| Varijabilna                             | Zadano                    | Opis                                                                                                                                                            |
| --------------------------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `JWT_SECRET`                            | _(automatski generirano)_ | JWT tajna potpisivanja — automatski generirana pri prvom pokretanju i ostala u `server.env`; postavite ga eksplicitno kada je direktorij podataka kratkotrajan  |
| `INITIAL_PASSWORD`                      | _(nije postavljeno)_      | Prva lozinka za prijavu. npm/source instalacije počinju sa `CHANGEME`: zamijenite ga. Nije postavljeno: čarobnjak za integraciju                                |
| `DATA_DIR`                              | `~/.omniroute`            | Direktorij podataka (db, korištenje, zapisnici)                                                                                                                 |
| `PORT`                                  | zadani okvir              | Servisni priključak (`20128` u primjerima)                                                                                                                      |
| `HOSTNAME`                              | zadani okvir              | Poveži host (Docker je zadana vrijednost `0.0.0.0`)                                                                                                             |

| `NEXT_PUBLIC_CLOUD_URL`                 | `https://omniroute.dev`   | Baza krajnje točke sinkronizacije oblaka URL (zamjenjuje stari `CLOUD_URL`)                                                                                     |
| `API_KEY_SECRET`                        | _(automatski generirano)_ | HMAC tajna za generirane API ključeve — automatski generira pri prvom pokretanju i ostaje u `server.env`                                                        |
| `REQUIRE_API_KEY`                       | `false`                   | Primjeni ključ API nositelja na `/v1/*`                                                                                                                         |

| `OMNIROUTE_MEMORY_MB`                   | `512`                     | Node.js ograničenje hrpe u MB                                                                                                                                   |

### Prilagođeni modeli

Dodajte bilo koji model ID bilo kojem pružatelju usluga bez čekanja na ažuriranje aplikacije:

```bash
# Via API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# List: curl http://localhost:20128/api/provider-models?provider=openai
# Remove: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

Ili upotrijebite nadzornu ploču:** Dobavljači → [Dobavljač] → Prilagođeni modeli** .

Bilješke:

- OpenRouter i OpenAI/Anthropic-compatible pružateljima se upravlja iz** Dostupni modeli** samo. Ručno dodavanje, uvoz i automatska sinkronizacija sve se nalazi na istom popisu dostupnih modela, tako da ne postoji poseban odjeljak prilagođenih modela za te pružatelje usluga.
- The** Prilagođeni modeli** odjeljak namijenjen je pružateljima koji ne izlažu upravljani uvoz dostupnog modela.

### Prilagođeni pružatelji kompatibilni s OpenAI-jem

Bilo koji pristupnik koji govori OpenAI API (proxy s vlastitim hostom, vLLM, agregator treće strane) može se dodati kao vlastiti čvor pružatelja:

1. **Pružatelji → Dodaj OpenAI kompatibilan** .
2. **Ime** : oznaka prikaza za čvor.
3. **Prefiks** : naziv usmjeravanja. Klijenti nazivaju modele `<prefix>/<model>`, tako da čvor s prefiksom `mygw` služi `mygw/gpt-4o-mini`. Potreban; nema ograničenja znakova.
4. **API Vrsta** : obitelj krajnjih točaka koju pristupnik služi (završeci razgovora, odgovori, ugradnje, zvuk, slike).
5. **Baza URL** : API korijen, do i uključujući `/v1` (na primjer `https://gateway.example.com/v1`), ne puna `/chat/completions` staza. Gateways s nestandardnim stazama postavite ih pod** Napredne postavke** (put za chat, put za modele).
6. The**API ključ (za provjeru)** polje samo testira vezu. Nakon što stvorite čvor, otvorite ga i koristite** Dodaj vezu** za pohranjivanje ključa koji će zahtjevi koristiti.

Čvor dobiva interni ID u obliku `openai-compatible-<apiType>-<uuid>`; ne morate ga nikada upisati, prefiks je javno ime.

#### Rezervirani prefiksi

Prefiks ne može biti ID ili pseudonim ugrađenog pružatelja usluga (na primjer `openai`, `cf`), niti ID povučenog pružatelja usluga. Razrešivač modela provjerava ugrađene ID-ove i pseudonime prije prilagođenih čvorova, tako da čvor koji koristi jedan od tih prefiksa nikada ne bi primio promet: `<prefix>/model` bi umjesto toga išao ugrađenom pružatelju ili se ne bi zatvorio ako bi se taj pružatelj povukao. Stvaranje ili uređivanje čvora s takvim prefiksom odbija se s:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

Odaberite poseban prefiks (`mygw`, `acme-proxy`). Ako zahtjevi prema prilagođenom čvoru ne uspije uz pogrešku koja imenuje ugrađenog pružatelja usluga ili njegove vjerodajnice, provjerite je li prefiks čvora rezerviran: čvorovi spremljeni prije nego što je ovo pravilo postojalo i dalje su pohranjeni, ali njihovi prefiksi usmjeravaju prema ugrađenom pružatelju usluga. Uredite čvor i dajte mu novi prefiks.

#### Opcije pristupnika za svaku vezu

Ovi ključevi idu u `providerSpecificData` veze (na primjer putem `PUT /api/providers/{id}`):

- `toolNameMaxLength` (cijeli broj, 1–1024) — za OpenAI chat-format kompatibilne veze čiji pristupnik odbija duga imena alata. Dulja imena šalju se kao kratki aliasi i vraćaju u odgovor.
- `quotaEndpoint` — krajnja točka quota/credits pristupnika, pročitajte za traku kvote nadzorne ploče i usmjeravanje s obzirom na kvote. Radi na OpenAI- i Anthropic-kompatibilnim vezama; puni oblik je dokumentiran u `open-sse/services/usage/openaiCompatible.ts`.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### Ulančavanje OmniRoute ravnopravnih

Drugi OmniRoute pristupnik može se dodati kao** Prilagođeno OpenAI-kompatibilno** davatelj usluga. Koristite ravnopravnu `/v1` bazu URL i namjenski API ključ s najmanjom privilegijom koji je izdao taj ravnopravni uređaj.

Za recipročne lance ili lance s više skokova, omogućite opt-in loop guard na svakom pristupniku:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

Samo zahtjevi poslani izričito dopuštenom peer URL primaju `X-OmniRoute-Peer-Trace` zaglavlje. Gateway odbija ponovljenu instancu ID ili iscrpljeni proračun skoka sa HTTP `508 Loop Detected`; obični uzvodni pružatelji usluga ne primaju ravnopravne metapodatke.

Peer lančano nije replikacija baze podataka ili failover hosta. Svaki gateway čuva neovisno SQLite stanje, predmemorije, brojače stopa i sesije. Za dostupnost active/passive ili active/active koristite provjereni obrnuti proxy ili klijentski failover i nikada ne montirajte jednu SQLite bazu podataka u više pokrenutih OmniRoute instanci.

### Cloudflare Brzi tunel

- Dostupno u** Kontrolna ploča → Krajnje točke** za Docker i druge samodomaćene implementacije
- Stvara privremeni `https://*.trycloudflare.com` URL koji prosljeđuje vašoj trenutnoj `/v1` točki kompatibilnoj s OpenAI-jem
- Prvo omogući instaliranje `cloudflared` samo kada je potrebno; kasnije ponovno pokretanje ponovno koristi istu upravljanu binarnu datoteku
- Brzi tuneli se ne vraćaju automatski nakon ponovnog pokretanja OmniRoute ili spremnika; ponovno ih omogućite s nadzorne ploče kada je potrebno
- Tunel URLs je efemeran i mijenja se svaki put kada stop/start tunelom
- Upravljani brzi tuneli zadano postavljaju HTTP/2 prijenos kako bi izbjegli bučna upozorenja QUIC UDP međuspremnika u ograničenim spremnicima
- Postavite `CLOUDFLARED_PROTOCOL=quic` ili `auto` ako želite poništiti izbor upravljanog transporta
- Postavite `CLOUDFLARED_BIN` ako radije koristite unaprijed instaliranu `cloudflared` binarnu datoteku umjesto upravljanog preuzimanja
- Cloudflare Quick Tunnel, Tailscale Funnel i ngrok Tunnel mogu se prikazati ili sakriti u** Postavke → Izgled** . Skrivanje ploče ne zaustavlja tunel koji radi.

### LLM Gateway Intelligence (faza 9)

- **Semantička predmemorija** — Automatski predmemorira odgovore bez strujanja, temperaturu = 0 (zaobići sa `X-OmniRoute-No-Cache: true`)
- **Idempotencija zahtjeva** — Deduplicira zahtjeve unutar 5 s putem `Idempotency-Key` ili `X-Request-Id` zaglavlja
- **Praćenje napretka** — Opt-in SSE `event: progress` događaji putem `X-OmniRoute-Progress: true` zaglavlja

### Strategije usmjeravanja

Konfigurirajte putem** Nadzorna ploča → Postavke → Usmjeravanje** . Nadzorna ploča otkriva šest najčešće korištenih strategija; kombinacije i automatski usmjerivač interno podržavaju širi skup.

**Strategije vidljive na nadzornoj ploči (usmjeravanje na razini računa):**

| Strategija                | Opis                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **Prvo ispunite**         | Koristi račune prema redoslijedu prioriteta — primarni račun obrađuje sve zahtjeve dok ne postane nedostupan |
| **Razigravanje**          | Kruži kroz sve račune s podesivim ljepljivim ograničenjem (zadano: 3 poziva po računu)                       |
| **P2C (Moć dva izbora)**  | Odabire 2 nasumična računa i usmjerava na zdraviji — uravnotežuje opterećenje sa sviješću o zdravlju         |
| **Slučajno**              | Nasumično odabire račun za svaki zahtjev koristeći Fisher-Yatesovo miješanje                                 |
| **Najmanje korišteno**    | Usmjerava prema računu s najstarijom `lastUsedAt` vremenskom oznakom, ravnomjerno raspoređujući promet       |
| **Optimizirani troškovi** | Usmjerava prema računu s najnižom vrijednošću prioriteta, optimizirajući za pružatelje s najnižom cijenom    |

**Napredne kombinirane i automatske strategije** (podesivo po kombinaciji ili putem `auto/*` prefiksa — vidi [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ):

- `priority` — strogi red, nikad kružno
- `weighted` — proporcionalni promet podijeljen po težinama po modelu
- `fill-first` — pražnjenje prvog modela dok se ne dostignu ograničenja
- `round-robin` / `strict-random` / `random`
- `p2c` (Moć dva izbora)
- `least-used` i `cost-optimized`
- `auto` — vođeno bodovanjem svih kandidata
- `lkgp` (Last Known Good Provider) — pričvršćuje na posljednjeg uspješnog pružatelja, a zatim se vraća na pravila
- `context-optimized` — odabire model s najvećim prozorom slobodnog konteksta
- `context-relay` — lanci dugokontekstualnih modela za naknadne zaokrete

#### Vanjsko ljepljivo zaglavlje sesije

Za vanjski afinitet sesije (na primjer, Claude Code/Codex agenti iza obrnutih proxyja), pošaljite:

```http

```

### Otpornost i prekidači

Konfigurirajte putem** Nadzorna ploča → Postavke → Otpornost** .

OmniRoute implementira otpornost na razini pružatelja usluga s pet komponenti:

1. **Red čekanja i tempo zahtjeva** — Oblikovanje zahtjeva na razini sustava:
   - **Zahtjevi po minuti (RPM)** — Maksimalan broj zahtjeva po minuti po računu
   - **Min. vrijeme između zahtjeva** — Minimalni razmak u milisekundama između zahtjeva
   - **Maks. istodobnih zahtjeva** — Maksimalan broj istodobnih zahtjeva po računu

2. **Hlađenje veze** — Konfiguracija po vrsti autentifikacije za jednu vezu nakon neuspjeha koji se mogu ponoviti:
   - **Osnovno hlađenje** — Zadani prozor za hlađenje za kvarove uzvoda koji se mogu ponovno pokušati
   - **Koristite upstream savjete za ponovni pokušaj** — Poštuje mjerodavne savjete `Retry-After` ili poništavanje ako su navedeni
   - **Maks. koraci odustajanja** — Maksimalna eksponencijalna razina povlačenja za opetovane kvarove

3. **Prekidač strujnog kruga dobavljača** — Prati kvarove dobavljača s kraja na kraj, označava da je usluga degradiran na konfiguriranom pragu upozorenja i otvara prekidač kada se dosegne konfigurirani prag kvara:
   - **Prag degradacije** — Uzastopni kvarovi pružatelja prije ulaska `DEGRADED`
   - **Prag neuspjeha** — Uzastopni kvarovi pružatelja prije ulaska `OPEN`
   - **Poništi vremensko ograničenje** — Vremenski okvir prije ponovnog testiranja pružatelja usluga
   - **CLOSED** (Zdravo) — Zahtjevi teku normalno
   - **DEGRADED** — Zahtjevi i dalje teku dok se prate povišeni kvarovi
   - **OPEN** — Davatelj je privremeno blokiran nakon opetovanih kvarova
   - **HALF_OPEN** — Testiranje je li se pružatelj oporavio

   Ograničenja stope `429` s opsegom veze ostaju** Hlađenje veze** i ne računaju se prema razbijaču pružatelja usluga.

   Stanje izvođenja prekidača pružatelja prikazano je na** Nadzorna ploča → Zdravlje** samo.

4. **Pričekajte hlađenje** — Ako se svaka kandidatska veza već hladi, OmniRoute može pričekati najranije hlađenje i automatski ponovno pokušati isti zahtjev klijenta.

5. **Automatsko otkrivanje ograničenja brzine** — Kada pružatelji uzlaznih usluga vrate eksplicitne prozore čekanja, ti savjeti nadjačavaju hlađenje lokalne veze kada je postavka omogućena.

**Stručni savjet:** Koristite** Zdravlje** stranicu za pregled i resetiranje prekidača pružatelja usluga uživo nakon prekida. Stranica Resilience mijenja samo konfiguraciju.

### Kombinirane strategije balansiranja

Konfigurirajte balansiranje po kombinaciji** Nadzorna ploča → kombinacije → Create/Edit → strategija** .

| Strategija                | Opis                                                                           |
| ------------------------- | ------------------------------------------------------------------------------ |
| **Round-Robin**           | Rotira kroz modele uzastopno                                                   |
| **Prioritet**             | Uvijek isprobava prvi model; vraća se samo na grešku                           |
| **Slučajno**              | Odabire slučajni model iz kombinacije za svaki zahtjev                         |
| **Ponderirano**           | Rute proporcionalno na temelju dodijeljenih težina po modelu                   |
| **Najmanje korišteno**    | Usmjerava do modela s najmanje nedavnih zahtjeva (koristi kombiniranu metriku) |
| **Troškovno optimiziran** | Rute do najjeftinijeg dostupnog modela (koristi tablicu cijena)                |

Mogu se postaviti globalne zadane kombinacije** Nadzorna ploča → Postavke → Usmjeravanje → Combo Defaults** . Combo target timeout prema zadanim postavkama nasljeđuje trenutni timeout zahtjeva. Koristiti** Ciljano vrijeme čekanja (sekunde)** na zadanim postavkama kombinacije ili pojedinačnoj kombinaciji samo kada bi kraće ograničenje po cilju trebalo pokrenuti brže vraćanje.

Kombinirane optimizacije bez kašnjenja su opt-in. Otiđi** Optimizacije bez kašnjenja** onemogućeno kako bi se spriječilo da ove značajke latencije utrkuju rezervne ciljeve, preskaču ciljeve na temelju TTFT povijesti ili komprimiraju rezervne zahtjeve; omogućavanje omogućuje konfiguriranu zaštitu, prediktivno preskakanje TTFT -a i proaktivnu pomoćnu kompresiju za razmjenu vjernosti routing/request za nižu latenciju repa.

Onemogući** Međuspremnik tokena obrazloženja** kada uzvodni pružatelji usluga zahtijevaju stroga ograničenja `max_tokens` / `maxOutputTokens`. Kada je omogućeno, kombinirano usmjeravanje samo dodaje prostor za model rezoniranja za modele s poznatim ograničenjem izlaza i ostavlja ograničenje tokena klijenta nepromijenjenim kada bi vrijednost sigurnog međuspremnika premašila to ograničenje. Ako je ograničenje klijenta već iznad poznatog ograničenja, OmniRoute ga spušta na to ograničenje prije slanja uzlaznog zahtjeva.

## 🤖 Automatsko usmjeravanje (bez konfiguracije)

OmniRoute dolazi s **usmjerivačem temeljenim na bodovanju** koji automatski bira najbolji model za svaki zahtjev među svim povezanim pružateljima usluga — nema potrebe za održavanjem kombinacija. Samo pošaljite zahtjev s jednim od `auto/*` prefiksa i OmniRoute će u hodu sastaviti virtualnu kombinaciju, bodujući kandidate na temelju latencije, troška, stope uspjeha, prilagodbe konteksta, prikladnosti modela za zadatak, nedavnih neuspjeha, kvote i stanja sklopke za prekid (circuit-breaker).

| Prefiks        | Optimizira za                                                                                         |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| `auto`         | Balansirana zadana postavka (latencija × trošak × stopa uspjeha)                                      |
| `auto/coding`  | Zadaci kodiranja: preferira Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek coder modele               |
| `auto/cheap`   | Najniža cijena po tokenu, prihvaća veću latenciju                                                     |
| `auto/fast`    | Najniža latencija, zanemaruje trošak                                                                  |
| `auto/offline` | Samo lokalni pružatelji (Ollama, vLLM, llama.cpp) — korisno za izolirane (air-gapped) sustave         |
| `auto/smart`   | Prvenstveno kvaliteta zaključivanja (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)                        |
| `auto/lkgp`    | "Last Known Good Provider" — vezuje se na posljednjeg uspješnog pružatelja, zatim se vraća na pravila |

Primjer:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refaktoriraj ovu Python funkciju" }],
    "stream": true
  }'
```

Automatski usmjerivač je detaljno opisan u [AUTO-COMBO.md](../routing/AUTO-COMBO.md) — uključujući kako podesiti težine bodovanja, staviti pružatelje na crnu listu i pregledati odluke o usmjeravanju u **Dashboard → Auto Combo**.

## 🔌 Integracija s MCP i A2A

OmniRoute je istovremeno **MCP poslužitelj** (Model Context Protocol) i **A2A poslužitelj** (Agent-to-Agent JSON-RPC 2.0). Svaki IDE ili agentski host kompatibilan s MCP-om može izravno pozivati OmniRoute alate — bez potrebe za dodatnim omotačem.

### MCP prijenosi

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **Streamable HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (za IDE dodatke koji preferiraju stdio)

### Povezivanje s Claude Desktop

Uredite `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) ili odgovarajuću datoteku na Windows/Linux sustavu:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Povezivanje s Cursor / Continue / VS Code MCP

Koristite SSE URL `http://localhost:20128/api/mcp/sse` i Bearer API ključ generiran u **Dashboard → API Keys**.

### Opsezi (Scopes)

MCP trenutno definira 32 imenovana opsega. Svaki Bearer ključ može se ograničiti na određene opsege — pogledajte [MCP-SERVER.md](../frameworks/MCP-SERVER.md) za autoritativni popis opsega i alata, te [A2A-SERVER.md](../frameworks/A2A-SERVER.md) za JSON-RPC shemu.

Pretplatite se na OmniRoute događaje za praćenje i automatizaciju u stvarnom vremenu.

## 🛠️ Programsko upravljanje

Možete upravljati svakim OmniRoute resursom (davatelji usluga, kombinacije, ključevi, postavke) putem HTTP-a koristeći **Bearer ključ s opsegom `manage`**.

```bash
# Popis davatelja usluga

  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Dodavanje veze s davateljem usluga
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \

curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Popis/kreiranje API ključeva
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

## 💻 Interni CLI

OmniRoute isporučuje interni CLI (`omniroute …`) za postavljanje, dijagnostiku i kontrolu izvođenja. Ovo je **odvojeno od stranice "CLI Tools" u nadzornoj ploči**, koja konfigurira CLI alate trećih strana (Claude Code, Cursor, Codex, Cline, …) da mogu komunicirati s OmniRoute-om.

```bash
omniroute setup                    # Interaktivni čarobnjak (lozinka, dobavljači, kombinacije)
omniroute setup --non-interactive  # Prilagođeno za CI
omniroute doctor                   # Dijagnostika stanja (podatkovni direktorij, baza podataka, dobavljači, portovi)
omniroute providers available      # Ispis podržanih dobavljača
omniroute providers list           # Ispis konfiguriranih veza
omniroute providers test <id>      # Testiranje veze dobavljača u stvarnom vremenu
omniroute combos list              # Ispis kombinacija
omniroute combos switch <name>     # Postavljanje zadane kombinacije
omniroute models                   # Ispis dostupnih modela (--json, --search)
omniroute keys add | list | remove # Upravljanje API ključevima iz terminala
omniroute backup                   # Snimka konfiguracije i baze podataka
omniroute restore [<timestamp>]    # Vraćanje iz snimke
omniroute health                   # Detaljno stanje (breakeri, predmemorija, memorija)
omniroute quota                    # Iskorištenost kvote dobavljača
omniroute mcp status                # Status MCP servera
omniroute a2a status                # Status A2A servera
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok tuneli
omniroute reset-password           # Resetiranje administratorske lozinke
omniroute --mcp                    # Pokretanje MCP servera preko stdio
omniroute --port 3000              # Pokretanje servera na prilagođenom portu
```

Savjet: kombinirajte `omniroute doctor --json` s vašim alatom za nadzor za obavijesti o neispravnim vezama s dobavljačima.
