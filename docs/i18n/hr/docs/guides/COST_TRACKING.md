Kako OmniRoute procjenjuje, bilježi i prijavljuje trošak svakog zahtjeva — i zašto broj na
nadzornoj ploči predstavlja **praćenje uštede**, a ne račun.

Pogledajte i: [Korisnički vodič](./USER_GUIDE.md) · [Galerija značajki](./FEATURES.md)

---

## Što jest (i što nije)

OmniRoute svakom dovršetku pripisuje trošak u USD po zahtjevu množenjem broja
tokena s cijenama modela. Ti brojevi koriste se na nadzornoj ploči **Troškovi**, u
CLI naredbama `omniroute cost` / `omniroute usage`, CSV/JSON izvozima i proračunima po API ključu.

> **„Trošak” na nadzornoj ploči predstavlja praćenje uštede, a ne račun.** OmniRoute vam
> nikada ništa ne naplaćuje — usmjerava vaše zahtjeve pružateljima koje ste već povezali
> (vlastite pretplate, besplatne razine i API ključevi). „Ukupni trošak od $290” ostvaren
> isključivo na besplatnim modelima znači da je to približno **$290 koje _niste_ platili**
> API-ju koji se plaća. Iznos je _procjena_ koliko bi isti promet koštao prema standardnim
> cijenama, kako biste mogli vidjeti gdje je koncentrirana vaša upotreba i koliko štedite
> usmjeravanjem prema jeftinijim ili besplatnim pružateljima.

Ovo je tumačenje izravno navedeno u projektnom dokumentu [README](../../README.md)
(„'trošak' na nadzornoj ploči predstavlja praćenje uštede, a ne račun”).

Budući da je broj procjena:

- Ovisi o tablici cijena koju OmniRoute ima za svaki model. Model bez zapisa o cijeni
  pridonosi trošku s `0` (u pregledniku se prikazuje kao redak „Naslijeđeno / besplatno”).
- Promet putem besplatne razine i pretplate i dalje ostvaruje _procijenjeni_ trošak — to je
  iznos koji štedite, a ne iznos koji dugujete.

## Kako se procjenjuju troškovi

### Izvor cijena

Troškovi dolaze iz spojene tablice cijena u [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts), ovim redoslijedom prednosti (** prvi najviši** ):

1. **Korisnička nadjačavanja** — cijene postavljene na nadzornoj ploči ili putem `PATCH /api/pricing` ( `pricing` imenski prostor).
2. **modeli.dev sink** — cijene dohvaćene iz `https://models.dev/api.json` ( `models_dev_pricing` imenski prostor).
3. **LiteLLM sinkronizacija** — cijene dohvaćene iz LiteLLM-ovog javnog `model_prices_and_context_window.json` ( `pricing_synced` imenskog prostora).
4. **Tvrdo kodirane zadane postavke** — cijene isporučene u [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/).

Za isti provider/model, vrijednosti iz slojeva višeg prioriteta prepisuju odgovarajuća polja u nižim slojevima; polja koja su odsutna u gornjem sloju ipak mogu doći iz nižeg sloja. Redoslijed je fiksan čak i kada se oba nezavisna zadatka sinkronizacije izvode u isto vrijeme. `GET /api/pricing?includeSources=1` vraća `pricing` i `sourceMap`, čije oznake po modelu (`user`, `modelsDev`, `litellm`, `default`) identificiraju sloj najvišeg prioriteta koji sadrži taj model.

**LiteLLM sinkronizacija** je opt-in, onemogućen prema zadanim postavkama. Njegove varijable okruženja (vidi [`.env.example`](../../.env.example) ) su:

| Env var                 | Zadano    | Svrha                                                                         |
| ----------------------- | --------- | ----------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | Omogući pozadinsku LiteLLM sinkronizaciju cijena.                             |
| `PRICING_SYNC_INTERVAL` | `86400`   | Interval sinkronizacije u sekundama (dnevno).                                 |
| `PRICING_SYNC_SOURCES`  | `litellm` | Odabir izvora samo za ovu sinkronizaciju; trenutno je podržan samo `litellm`. |

**modeli.dev sink** odvojen je od LiteLLM sinkronizacije i također je onemogućen prema zadanim postavkama. Omogućite ga u postavkama (models.dev sync) ili upotrijebite ove varijable:

| Env var                    | Zadano               | Svrha                                                                                                                                                          |
| -------------------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(nije postavljeno)_ | Poništenje slijedi nakon prekidača postavki; `1/true/on/yes` se prisilno uključuje, a `0/false/off/no` se prisilno isključuje (čak i ako Postavke to omoguće). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`              | Zadani interval sinkronizacije models.dev u sekundama (dnevno).                                                                                                |

`PRICING_SYNC_SOURCES` radi** ne** omogućiti models.dev; kontrolira samo LiteLLM sinkronizaciju. Brisanje nadjačavanja korisnika ne briše niti sinkronizirani prostor imena; sljedeći dostupni sloj cijena postaje učinkovit. Za model bez cijene, provjerite postavke sinkronizacije i `sourceMap` prije dodavanja ručnog nadjačavanja.

### Formula troška

Trošak se izračunava po zahtjevu iz broja tokena i stope po milijun tokena u [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`):

- **Ulazni tokeni** (minus čitanja predmemorije i tokeni za stvaranje predmemorije) × `input` stopa.
- **Tokeni za čitanje predmemorije** × `cached` brzina (vraća se na ulaznu brzinu).
- **Tokeni za stvaranje predmemorije** × `cache_creation` brzina (vraća se na ulaznu brzinu).
- **Izlazni žetoni** × `output` stopa.
- **Tokeni obrazloženja** × `reasoning` stopa (vraća se na izlaznu brzinu).

Sve se stope tumače kao USD po 1.000.000 tokena. Codex "brza"/"prioritetna" ili "fleksibilna" razina usluge primjenjuje multiplikator troškova (`getCodexFastCostMultiplier`) — npr. flex se naplaćuje s popustom od 50% simbola, pojavljuje se kao** fleksibilna štednja** u nadzornoj ploči.

Nazivi modela prvo se normaliziraju (prefiksi staza pružatelja usluga kao što su `openai/` ili `accounts/fireworks/models/` se uklanjaju) tako da povijesni redovi i dalje odgovaraju cijeni.

### Kako se bilježi potrošnja

- Trošak po zahtjevu izračunava se po završetku zahtjeva. Potrošnja dijeljene kvote zakazana je na sljedećem otkucaju petlje događaja putem [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts).
- Potrošnja API ključa sprema se u međuspremnik i ispire u serijama od strane [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (zadani interval ispiranja od 60 s, međuspremnik od 1000 unosa). Podesivo putem:

  | Env var                             | Zadano  | Svrha                                     |
  | ----------------------------------- | ------- | ----------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | Interval ispiranja u milisekundama.       |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | Maks. međuspremnik unosa prije ispiranja. |

Troškovi preferiraju točnu naknadu koju je prijavio pružatelj (`provider_cost_usd`), zatim snimku zahtjeva prema kataloškoj cijeni (`calculated_cost_usd`), zatim ponovno određivanje cijene tokena iz trenutnog kataloga. Pohranjeni troškovi ne naplaćuju se ponovno putem broja tokena. Redovi samo naslijeđenih tokena i dalje se mijenjaju kada se promijeni njihova kataloška cijena.

### OCR i ugradnje

- Uspješni `/v1/ocr` zahtjevi koriste uzvodni `usage_info.pages_processed`, a ne zatraženi raspon stranica ili broj vraćenih objekata stranice. Procjena je stranica × `ocr_cost_per_page` (apsolutni USD/page,** ne** USD/million).
- Zahtjevi s primjedbama na dokumentima ili graničnim okvirima zahtijevaju zasebnu `ocr_cost_per_annotated_page` tarifu. Bez toga, cijena ostaje nepoznata; obična OCR tarifa nije tiho zamijenjena.
- LiteLLM sync preslikava svoje uzvodno `annotation_cost_per_page` polje u `ocr_cost_per_annotated_page`, zadržavajući apsolutnu USD/page vrijednost i unose samo za komentare, uključujući eksplicitnu nulu. Isporučeno kanonsko polje ima prednost; nevažeće vrijednosti pseudonima se zanemaruju. Nadjačavanja korisničkih cijena zadržavaju svoj uobičajeni prioritet. Pogledajte [LiteLLMOCR ključeve cijena](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking).
- OCR usage pohranjuje broj stranica, jediničnu cijenu, izračunatu USD cijenu, API ključ i odabranu vezu. Stranice se nikada ne predstavljaju kao tokeni. Zapisnici poziva sadrže metapodatke o naplati, a ne dokument URLs, PDF bajtove ili izdvojeni tekst.
- Uspješni `/v1/embeddings` zahtjevi bilježe jedan red upotrebe po fizičkoj seriji, uključujući odvojene serije dovršene u istoj milisekundi. Naknade koje prijavljuje pružatelj usluga imaju prednost pred procjenama tokena; kombinirani omoti ne dodaju naknadu.
- Povijest korištenja, analitika troškova, provider/account prozori, ograničenja potrošnje ključeva API-ja, knjiga troškova zahtjeva i skupna dnevna upotreba uključuju ove naknade. Ključevi bez dnevnika zadržavaju numerički obračun bez zadržavanja izvornog teksta.
- Nedostaju korištenje ili tarife** nepoznato** , nije besplatno: zaglavlje cijene odgovora je izostavljeno, a postojeća pravila upotrebe bez cijene primjenjuju se na ograničene API ključeve. Eksplicitno konfigurirane nulte stope ostaju važeće bez troška korištenja.

Ovo je računovodstvo samo za unaprijed. Stari OCR/embedding pozivi koji nikada nisu napisali povijest korištenja ne mogu se rekonstruirati iz ove migracije. Kataloške procjene su USD procjene, a ne faktura i ne uključuju konverziju valuta, porez ili popuste.

### Govor i slike

- Uspješni `/v1/audio/transcriptions`, `/v1/audio/speech` i pokušaji generiranja slika dijele numeričko računovodstvo. Izravni i kombinirani pozivi nose API ključ pozivatelja i odabranu vezu; kombinirani omotač nikada ne dodaje drugo zaduženje.
- USD kojeg je prijavio pružatelj nadmašuje katalošku procjenu, uključujući eksplicitnu nultu naknadu. OpenRouter-ov JSON `usage.cost` je normaliziran na `cost_usd`. U suprotnom, izmjereni tokeni koriste cijene tokena, sekunde transkripcije koriste cijene po sekundi, govorni unos koristi broj Unicode znakova, a slike fiksne cijene koriste stvarno vraćeni broj, a ne traženi `n`.
- Binarni OpenRouter TTS nema JSON tijelo upotrebe. Nakon što zvuk završi ili pozivatelj otkaže, OmniRoute postavlja upit o svojoj generaciji ID na** isti** konfigurirano OpenRouter porijeklo. Zahtjev EU nikada se ne vraća na globalno izvorište. Ovo je ograničeno pretraživanje samo za čitanje; sinteza se ne pokušava ponovno za računovodstvo. Zapisi o naplati mogu se pojaviti nakon završetka zvuka: ponovni pokušaji pretraživanja izvode se u pozadini do otprilike 52 sekunde, uključujući mrežne rokove.
- Tijekom tog traženja, audio odgovor ima `X-OmniRoute-Cost-Status: pending` i nema zaglavlje cijene odgovora. Njegovo konačno terećenje pojavljuje se u povijesti korištenja, analitici i glavnoj knjizi nakon usklađivanja. Ako metapodaci nisu dostupni, koristi se konfigurirana snimka tarife; inače trošak ostaje nepoznat.
- Brojevi sekundi, znakova i slika imaju zasebna polja obračunske jedinice, nikad lažni brojevi tokena. Računovodstvo zadržava samo numeričku upotrebu, ne govorni tekst, transkripte ili bajtove slika. Postojeća izuzeća za slike bez cijene su nepromijenjena: tarifa za slike koje stvarno nedostaju ne zaključava ograničeni ključ, a odgovor izostavlja zaglavlje cijene umjesto da proglašava poziv besplatnim. Neuspješna trgovina s cijenama još uvijek zadržava dokaze o korištenju za provedbu zatvaranja nakon pogreške.

Nikakva povijesna naknada speech/image nije izmišljena niti zatrpana. Naplata davatelja usluga ostaje referenca za fakture i za pozive čija cijena nije prijavljena.

## Nadzorna ploča: stranica Troškovi

Stranica **Troškovi** nalazi se na `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`).
Njezin je glavni prikaz kartica **Pregled troškova**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
koja sve podatke učitava putem `GET /api/usage/analytics`.

Što prikazuje:

- **Kartice potrošnje** — procijenjena potrošnja za _Danas (1d)_, _7d_, _30d_ i odabrano
  razdoblje. Odabir raspona: `7d`, `30d`, `90d`, `all`.
- **Glavne metrike** — zahtjevi u razdoblju, aktivni pružatelji, aktivni modeli, prosječni
  trošak po zahtjevu.
- **Istraživač troškova** — tablica s mogućnošću sortiranja i filtriranja, grupirana prema **pružatelju**, **modelu**,
  **API ključu**, **računu** ili **razini usluge**, s troškom, zahtjevima, tokenima, prosječnim
  troškom po zahtjevu i postotnim udjelom u ukupnom iznosu.
- **Upotreba tokena** — ukupan broj / ulazni / izlazni tokeni i omjer ulaznih i izlaznih tokena.
- **Učinkovitost usmjeravanja** — broj prebacivanja na rezervnu opciju, stopa prebacivanja i pokrivenost zatraženog modela.
- **Mjesečna prognoza** — predviđa potrošnju do kraja mjeseca na temelju nedavnog dnevnog prosjeka.
- **Usporedba razdoblja** — postotna promjena između prve i druge polovice razdoblja.
- **Grafikoni** — dnevni trend troškova, udio pružatelja (kružni grafikon), vodeći pružatelji, vodeći modeli, trošak
  po API ključu, trošak po računu, tjedni obrazac upotrebe i toplinska karta aktivnosti.
- **Izvoz** — preuzimanje trenutačnog razdoblja kao **CSV** ili **JSON** (gumbi se prikazuju
  kada postoje podaci s troškom većim od nule).

Kada nema tarifiranog prometa, retci se prikazuju s oznakom „Naslijeđeno / Besplatno” umjesto `$0`,
u skladu s modelom praćenja ušteda.

### Povezane podstranice Troškova

Područje Troškovi također sadržava sljedeće stranice (sve pod `/dashboard/costs/`):

- **Cijene** (`/dashboard/costs/pricing`) — pregled i nadjačavanje cijena po modelu (prikazuje
  zajedničku karticu Cijene).
- **Proračun** (`/dashboard/costs/budget`) — postavljanje ograničenja potrošnje po opsegu (prikazuje zajedničku
  karticu Proračun).
- **Dijeljenje kvote** (`/dashboard/costs/quota-share`) — skupovi dijeljenih kvota i prikazi
  stope potrošnje.

## API krajnje točke

Sve to zahtijeva autorizaciju upravljanja (loopback/JWT, putem `requireManagementAuth`), osim ako nije navedeno.

### Analitika korištenja i troškova

| metoda | Krajnja točka            | Svrha                                                                                                                                                       |
| ------ | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/analytics`   | Potpuna cost/usage analitika: sažetak, dnevni trend, po provider/model/API key/account/tier. upit: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET`  | `/api/usage/utilization` | Iskorištenost kvote po pružatelju tijekom vremena. Upit: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                       |
| `GET`  | `/api/usage/history`     | Neobrađeni retci povijesti korištenja.                                                                                                                      |
| `GET`  | `/api/usage/call-logs`   | Zapisi poziva po zahtjevu (model, tokeni, cijena, latencija, status).                                                                                       |
| `GET`  | `/api/usage/quota`       | Status kvote pružatelja usluga.                                                                                                                             |
| `GET`  | `/api/usage/proxy-logs`  | Dnevnici zahtjeva za proxy.                                                                                                                                 |

### Proračuni

| metoda | Krajnja točka            | Svrha                                                                                              |
| ------ | ------------------------ | -------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | Sažetak troškova + provjera proračuna za jedan API ključ (potreban je `apiKeyId` parametar upita). |
| `POST` | `/api/usage/budget`      | Postavi daily/weekly/monthly USD ograničava + prag upozorenja za API ključ.                        |
| `GET`  | `/api/usage/budget/bulk` | Skupni proračunski sažeci po API ključevima.                                                       |

> Proračun API je obuhvaćen prema** ključ API** (`apiKeyId`). Ograničenja koja vraća `GET /api/usage/budget` uključuju `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`, a `warningThreshold` i tekuće ukupne iznose (`totalCostToday`, `totalCostMonth`, …).

## CLI

OmniRouteov CLI pruža naredbe za troškove, upotrebu i cijene (registrirane u
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

Izvješće o troškovima agregirano iz `/api/usage/analytics`.

```bash
omniroute cost                          # posljednjih 30 dana, grupirano prema pružatelju
omniroute cost --period 7d              # posljednjih 7 dana
omniroute cost --group-by model         # grupiranje prema provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

Stupci: grupa, zahtjevi, ulazni/izlazni tokeni, trošak (USD) i % ukupnog iznosa. Redak sa sveukupnim iznosom
ispisuje se na kraju (ne prikazuje se uz `--quiet` ili `--output json`).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # sažetak troškova po pružatelju
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# Proračuni
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` čita `GET /api/pricing/defaults`. Za uređivanje cijena pojedinačnih modela
> umjesto toga upotrijebite stranicu **Cijene** na nadzornoj ploči ili `PATCH /api/pricing`.

## Rješavanje problema

- **Svi troškovi prikazuju $0 / „Legacy / Free”.** Modeli koji se upotrebljavaju nemaju zapis o cijeni.
  Omogućite vanjsku sinkronizaciju (`PRICING_SYNC_ENABLED=true`) i pokrenite `omniroute pricing sync` ili
  ručno postavite cijene putem stranice Cijene / `PATCH /api/pricing`.
- **Povijesni model ima pogrešnu cijenu.** Ispravite cijenu (nadjačavanjem ili ponovnom sinkronizacijom) — trošak se
  ponovno izračunava iz broja tokena pri svakom čitanju analitike, pa se procjene retroaktivno ažuriraju.
- **Potrošnja kasni za stvarnim vremenom.** Potrošnja po ključu obrađuje se skupno; smanjite
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ako su vam potrebni ažurniji podaci.
