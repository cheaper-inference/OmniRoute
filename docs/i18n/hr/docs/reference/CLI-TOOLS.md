## Kako funkcionira

```
CLI alati za kodiranje / CLI agenti (tijek potrošnje):
Claude / Codex / OpenCode / Cline / KiloCode / Continue / Hermes Agent / Goose / ...
           │
           ▼  (svi su usmjereni na OmniRoute)
    http://YOUR_SERVER:20128/v1
           │
           ▼  (OmniRoute usmjerava prema odgovarajućem pružatelju)
    Anthropic / OpenAI / Gemini / DeepSeek / Groq / Mistral / ...

ACP agenti (obrnuti tijek pokretanja):
    Zahtjev klijenta → OmniRoute → pokreće CLI putem stdio/ACP-a → odgovor
```

**Prednosti:**

- Jedan API ključ za upravljanje svim alatima
- Praćenje troškova svih CLI alata na nadzornoj ploči
- Promjena modela bez ponovnog konfiguriranja svakog alata
- Radi lokalno i na udaljenim poslužiteljima (VPS, Docker, Akamai, Cloudflare Tunnel)

## Auto-konfiguriraj sa `setup-*`

Ne morate ručno pisati konfiguraciju svakog alata. OmniRoute isporučuje naredbu `setup-*` po podržanom CLI u koja čita** živjeti** katalog modela iz pokrenutog OmniRoute (lokalnog ili udaljenog) i piše vlastitu konfiguraciju alata na vašem računalu:

```bash
omniroute setup-codex        omniroute setup-claude       omniroute setup-opencode
omniroute setup-cline        omniroute setup-kilo         omniroute setup-continue
omniroute setup-cursor       omniroute setup-roo          omniroute setup-crush
omniroute setup-goose        omniroute setup-qwen         omniroute setup-aider
omniroute setup-5dive        omniroute setup-zed
omniroute setup-whycodes
```

Svaki prihvaća `--remote <url> --api-key <key>` (konfigurirajte lokalni alat protiv udaljenog OmniRoute), `--dry-run` (pregled bez pisanja) i `--port`. Alati bez automatskog otkrivanja modela (Cline, Kilo, Roo, Goose, Aider, Qwen, 5dive, WhyCodes) uzimaju `--model <id>` (i `--yes` za neinteraktivna izvođenja). `setup-5dive` je jedini recept koji ne piše pod `$HOME`: on konfigurira flotu 5dive agenta pisanjem autentificiranog profila u vlasništvu roota na hostu flote, tako da se ponovno izvršava kroz `sudo` i nema vlastiti daljinski način rada. Za pokretanje CLI s umetnutim pravim env-om i bez ikakve napisane konfiguracije, upotrijebite generički pokretač `omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini, whycodes — ciljevi i aliasi dolaze iz `bin/cli/cli-manifest.mjs`); naslijeđeni pokretači po alatima `omniroute launch` (Claude kod) i `omniroute launch-codex` (Codex) ostaju dostupni. Gemini CLI je samo za pokretanje: to je `omniroute run` cilj, ali nema `setup-*`/`configure` recept.

> **Puna referenca:** glavna tablica — što svaka naredba piše, svaka zastavica, lokalna naspram udaljene, i koji alati žele `/v1` sufiks — živi u** [CLI integracije](../guides/CLI-INTEGRATIONS.md)** .

### Pokretanje ovih unutar spremnika

Naredba `setup-*` koja se izvršava unutar OmniRoute spremnika upisuje u vlastiti dom spremnika, koji nijedan host CLI ne čita i koji nestaje sa spremnikom. OmniRoute to otkriva i izlazi iz `2` s uputama umjesto pisanja. Dva podržana načina naprijed — instalirajte CLI na glavno računalo i `omniroute connect` na spremnik ili pričvrstite konfiguracijske direktorije i postavite `CLI_CONFIG_HOME` (sastavite `host` profil). Svaka naredba `setup-*`, plus `omniroute configure` i `omniroute config set`, prihvaća `--allow-container-write` kada konfigurirate vlastiti CLIs spremnika je ono što ste zapravo mislili; `OMNIROUTE_ALLOW_CONTAINER_CONFIG_WRITE=true` radi isto za poslužitelj. Pogledajte [Vodič Docker → Konfiguriranje host CLI alata](../guides/DOCKER_GUIDE.md#configuring-host-cli-tools-when-omniroute-runs-in-docker).

Kontrolna ploča** primijeniti krajnju točku** (`POST /api/cli-tools/apply`) nameće istu zaštitu: u spremniku odgovara pisanje čiji cilj nije montiran vezanjem s glavnog računala**`422`** sa `containerEphemeralTarget: true`, sigurnim tekstom pogreške i — za alate s glavnim receptom (claude, codex, opencode, cline, kilo, continue) — `hostSetupCommand` (npr. `omniroute setup-opencode`) za izvođenje na glavnom računalu; ništa nije napisano. `dryRun: true` nastavlja raditi u načinu spremnika i vraća redigirani pretpregled + ciljne staze bez dodirivanja diska. Sadržaj pretpregleda nije konfiguracija koja nosi vjerodajnice za kopiranje ili uvoz. Primijenite s izvornim tool/base URL/API key/model ulazima na glavnom računalu ili upotrijebite naznačenu naredbu za postavljanje na strani glavnog računala. Pogledajte [sigurnost konfiguracije CLI](../security/CLI-CONFIGURATION.md) za zaglavlje pregleda i ugovor zahtjeva. Ovo ponašanje je namjerno i regresijski ga štiti `tests/unit/api/cli-tools/apply-container-guard.test.ts` — nikada ne "popravljajte" 422 uklanjanjem zaštite.

## Izvor istine

Objedinjeni katalog nalazi se u `src/shared/constants/cliTools.ts` kao `CLI_TOOLS: Record<string, CliCatalogEntry>`.

Svaki unos ima sljedeća polja (definirana u `src/shared/schemas/cliCatalog.ts`):

| Polje                                           | Tip                                                          | Opis                                                                                    |
| ----------------------------------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| `category`                                      | `"code" \| "agent"`                                          | Na kojoj se stranici alat prikazuje                                                     |
| `vendor`                                        | `string`                                                     | Podrijetlo alata ("Anthropic", "OSS (P. Gauthier)")                                     |
| `acpSpawnable`                                  | `boolean`                                                    | Može se upotrebljavati i kao ACP agent (prikazuje oznaku)                               |
| `baseUrlSupport`                                | `"full" \| "partial" \| "none"`                              | Razina podrške za prilagođenu krajnju točku. `"none"` = popis neriješenih MITM zadataka |
| `configType`                                    | `"env" \| "custom" \| "guide" \| "custom-builder" \| "mitm"` | Mehanizam konfiguracije                                                                 |
| `id`, `name`, `color`, `description`, `docsUrl` | standard                                                     | Osnovna polja za prikaz                                                                 |

Unosi s vrijednošću `baseUrlSupport: "none"` **ne prikazuju se** na stranicama nadzorne ploče — registrirani su u popisu neriješenih MITM zadataka za plan 11 (pogledajte `_tasks/features-v3.8.6/refactorpages/_orchestration/_plan11-mitm-backlog.md`).

### Razine mogućnosti (katalogizirano × moguće otkriti × moguće konfigurirati × moguće pokrenuti)

Nije svaki katalogizirani alat moguće otkriti, konfigurirati ili pokrenuti. Svaka razina ima jedan
deklarativni izvor, a test odstupanja održava ih usklađenima:

| Razina                   | Značenje                                                                                       | Deklarirano u                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **Katalogizirano**       | Pojavljuje se u katalogu nadzorne ploče (naziv, dobavljač, dokumentacija, vrsta konfiguracije) | `src/shared/constants/cliTools.ts` (`CLI_TOOLS`)                  |
| **Moguće otkriti**       | Otkrivanje binarne datoteke/konfiguracije, provjere ispravnosti, putanje konfiguracije         | `src/shared/services/cliRuntime.ts` (izvršni katalog `CLI_TOOLS`) |
| **Moguće konfigurirati** | Podržava ga `omniroute configure <cli>` (postoji recept za postavljanje)                       | `bin/cli/cli-manifest.mjs` (`configure: true`)                    |
| **Moguće pokrenuti**     | Podržava ga `omniroute run <target>` (definirano je umetanje varijabli okruženja/argumenata)   | `bin/cli/cli-manifest.mjs` (`run: true`)                          |

`bin/cli/cli-manifest.mjs` kanonski je izvršni manifest za površine CLI naredbi:
`run`, `configure` i generatori automatskog dovršavanja u ljusci iz njega izvode svoje
popise ciljeva, razrješavanje pseudonima (primjerice `kilocode`/`kilo-code`/`kilo_cli` → `kilo`)
i povezivanje zastavice `--model`. Zaštita od odstupanja
`tests/unit/cli/cli-manifest-drift.test.ts` potvrđuje da manifest, izvršni
katalog, katalog korisničkog sučelja i sve potrošačke površine ostaju usklađeni — cilj dodan
na jednu površinu bez ostalih uzrokuje pad skupa testova umjesto neprimjetnog odstupanja.

## 5. API za skupno otkrivanje

Otkrivanje svih alata objedinjeno je putem jedne krajnje točke:

**`GET /api/cli-tools/all-statuses`**

- Autentifikacija: `requireCliToolsAuth(request)` (isto kao za ostale rute `/api/cli-tools/`)
- Vraća: `Record<toolId, ToolBatchStatus>` (tip: `src/shared/types/cliBatchStatus.ts`)
- Strategija: `Promise.all` za sve alate, vremensko ograničenje od 5 s po alatu
- Predmemorija: LRU u memoriji, indeksiran prema `mtime` konfiguracijske datoteke. Predmemorija se poništava kada se `mtime` promijeni. Ponovno se postavlja pri ponovnom pokretanju poslužitelja.

Struktura odgovora po alatu:

```ts
interface ToolBatchStatus {
  detection: {
    installed: boolean;
    runnable: boolean;
    version?: string;
    command?: string;
    commandPath?: string;
    reason?: string;
  };
  config: {
    status: "configured" | "not_configured" | "not_installed" | "unknown" | "other";
    endpoint?: string | null;
    lastConfiguredAt?: string | null;
  };
  error?: string; // pročišćeno, bez tragova stoga
}
```

## 10. Interni OmniRoute CLI

Binarna datoteka `omniroute` pruža naredbe za životni ciklus poslužitelja, postavljanje, dijagnostiku i upravljanje pružateljima usluga. Ulazna točka: `bin/omniroute.mjs`.

```bash
omniroute                              # Pokreni poslužitelj (zadani port 20128)
omniroute setup                        # Interaktivni čarobnjak za postavljanje
omniroute doctor                       # Provjeri konfiguraciju, bazu podataka, portove i izvršno okruženje
omniroute providers list               # Konfigurirane veze s pružateljima usluga
omniroute providers test-all           # Testiraj svaku aktivnu vezu
omniroute reset-password               # Ponovno postavi administratorsku lozinku
omniroute logs                         # Prati zapisnike zahtjeva
omniroute health                       # Detaljno stanje (prekidači, predmemorija, memorija)
omniroute --version                    # Ispiši verziju
omniroute --help                       # Prikaži sve naredbe
```

### Postavljanje i inicijalizacija

```bash
omniroute setup                        # Interaktivni čarobnjak za postavljanje
omniroute setup --non-interactive      # Način rada za CI/automatizaciju (čita varijable okruženja + zastavice)
omniroute setup --password '<value>'   # Izravno postavi administratorsku lozinku
omniroute setup --add-provider \
  --provider openai \
  --api-key '<value>' \
  --test-provider                      # Dodaj i testiraj pružatelja usluga u jednom koraku
```

Prepoznate varijable okruženja za neinteraktivno postavljanje:

| Var                 | Namjena                                                                      |
| ------------------- | ---------------------------------------------------------------------------- |
| `OMNIROUTE_API_KEY` | API ključ pružatelja usluga (povezan s `--api-key` putem Commander `.env()`) |
| `DATA_DIR`          | Nadjačava OmniRoute direktorij podataka                                      |

Svi ostali neinteraktivni ulazni podaci prosljeđuju se kao zastavice, a ne kao varijable okruženja:
`--password`, `--provider`, `--provider-name`, `--provider-base-url`, `--default-model`
(pogledajte prethodno navedene opcije naredbe `omniroute setup`).

### Dijagnostika

```bash
omniroute doctor                       # Provjeri konfiguraciju, bazu podataka, portove, izvršno okruženje, memoriju i dostupnost
omniroute doctor --json                # Strojno čitljiv JSON
omniroute doctor --no-liveness         # Preskoči HTTP provjeru stanja
omniroute doctor --host 0.0.0.0        # Nadjačaj host za provjeru dostupnosti
omniroute doctor --liveness-url <url>  # Nadjačaj puni URL krajnje točke za provjeru stanja
```

Naredba doctor izvodi sljedeće provjere: `Config`, `Database`, `Storage/encryption`,
`Port availability`, `Node runtime`, `Native binary` (better-sqlite3),
`Memory` i `Server liveness`. Završava s kodom različitim od nule ako bilo koja provjera ima rezultat `fail`.

### Upravljanje pružateljima usluga

```bash
omniroute providers available                       # Katalog pružatelja usluga OmniRoute
omniroute providers available --search openai       # Filtriraj katalog prema ID-u/nazivu/pseudonimu/kategoriji
omniroute providers available --category api-key    # Filtriraj prema kategoriji (api-key, oauth, free, ...)
omniroute providers available --json                # Strojno čitljiv JSON

omniroute providers list                            # Konfigurirane veze s pružateljima usluga
omniroute providers list --json

omniroute providers test <id|name>                  # Testiraj jednu konfiguriranu vezu
omniroute providers test-all                        # Testiraj svaku aktivnu vezu
omniroute providers validate                        # Strukturna provjera valjanosti samo lokalno
omniroute providers add <provider> --credential-env PROVIDER_KEY
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth <provider>                 # Postojeći OAuth tijek
omniroute providers edit <id|name> --default-model <model>
omniroute providers remove <id|name> --yes
```

`providers add/import/auth/edit/remove` primarno koriste API i stoga rade s
aktivnim lokalnim ili udaljenim kontekstom. Za unos vjerodajnica treba upotrebljavati
`--credential-stdin` ili `--credential-env`; `--dry-run --json` izvještava samo
o redigiranoj prisutnosti/strukturi. `providers available` čita OmniRoute katalog;
`providers list/test/test-all/validate` zadržavaju svoje lokalno SQLite ponašanje i
ne zahtijevaju pokretanje poslužitelja.

Za prilagođeni čvor kompatibilan s OpenAI-jem ili Anthropicom pridružite vjerodajnice
ID-u čvora koji vrati `omniroute nodes add`, koristeći `omniroute keys add "$NODE_ID" --stdin`.
Za to su potrebni pokrenuti poslužitelj i autentifikacija za upravljanje aktivnim kontekstom.
CLI koristi `POST /api/providers`, koji provjerava valjanost čvora i kopira njegove postavke
krajnje točke u vezu. Nepostojeći čvor, neuspjela autorizacija ili nedostupan
poslužitelj vraćaju pogrešku bez stvaranja lokalne zamjenske vjerodajnice.

`nodes add --base-url` postavlja krajnju točku čvora; ona se razlikuje od adrese poslužitelja
u `OMNIROUTE_BASE_URL`. Za OpenAPI datoteke upotrijebite
`omniroute openapi dump --format json --out ./openapi.json`; globalna opcija `--output`
odabire format prikaza CLI-ja, a ne naziv odredišne datoteke.

### Oporavak i ponovno postavljanje

```bash
omniroute reset-password                # Ponovno postavi administratorsku lozinku (također: omniroute-reset-password)
omniroute reset-encrypted-columns       # Prikaži upozorenje + probno izvođenje ponovnog postavljanja šifriranih vjerodajnica
omniroute reset-encrypted-columns --force  # Doista postavi šifrirane vjerodajnice u SQLiteu na null
```

### Izvoz vjerodajnica (⚠ postupajte oprezno)

```bash
omniroute auth export                                 # Prikaži upozorenje + zahtjev za potvrdu — bez pristupa bazi podataka
omniroute auth export --force                          # Izvezi DEŠIFRIRANE vjerodajnice SVIH veza u stdout kao JSON
omniroute auth export --force --id <id>                 # Izvezi samo odgovarajuću vezu
omniroute auth export --force --format env               # Ispiši retke OMNIROUTE_<PROVIDER>_<FIELD>=<value>
omniroute auth export --force --out creds.json           # Zapiši u datoteku (stvorenu s dopuštenjima 0600)
```

`auth export` je **isključivo lokalna** naredba (izravno čitanje iz SQLite-a, bez HTTP rute) koja namjerno ispisuje/zapisuje
vrijednosti `apiKey`/`accessToken`/`refreshToken`/`idToken` kao **običan tekst** — to je značajka, a ne
pogreška. Bez opcije `--force` ništa se ne čita iz baze podataka niti se išta dešifrira. Natpis upozorenja
uvijek se ispisuje na stderr prije ispisa bilo kakvog običnog teksta. Zahtijeva postavljanje varijable
`STORAGE_ENCRYPTION_KEY`. Polje koje se ne uspije dešifrirati (zastarjeli ključ, oštećen šifrirani tekst) prijavljuje se kao
`<field>DecryptFailed: true` umjesto prekidanja cijelog izvoza ili otkrivanja temeljne pogreške.

## Upravljanje pravilima ključa za izvođenje zaključivanja pomoću OmniRoute CLI-ja

Upotrijebite autentificirani kontekst upravljanja (pogledajte [Udaljeni način rada](../guides/REMOTE-MODE.md))
kako biste pregledali ili ažurirali postojeći ključ za izvođenje zaključivanja prema njegovu ID-u:

```bash
omniroute --output json keys policy show KEY_ID
omniroute keys policy set KEY_ID --unrestricted
omniroute --output json keys policy show KEY_ID
```

`--unrestricted` je pseudonim za `--model-access-mode all`. Ažuriranjem se briše
popis dopuštenih modela. Opsezi, pravila povezivanja, blokirani modeli, ograničenja stope
i ograničenja troškova ostaju sačuvani, pa te druge kontrole i dalje mogu odbiti zahtjev. Izričito
navođenje `--allowed-models ""` također odabire `all`; kombinirajte ga s
`--model-access-mode restricted` kako biste zadržali ograničeni ključ bez dopuštenih modela.
Popis odvojen zarezima koji nije prazan odabire `restricted`, osim ako nije izričito navedeno drukčije.
Proturječna kombinacija `all` i popisa dopuštenih modela koji nije prazan odbija se prije slanja zahtjeva.

`--rate-limit 30` postavlja broj zahtjeva po minuti i zadržava pravila za ostale vremenske
prozore. `--max-cost 5` omogućuje dnevno ograničenje u USD-u bez promjene tjednog ograničenja;
`--max-cost 0` uklanja dnevno ograničenje te zadržava postojeću postavku ograničenja upotrebe
i tjedno ograničenje. Izostavljena polja pravila ostaju nepromijenjena. Pri promjeni stope najprije
se čitaju trenutačna pravila; izbjegavajte istodobne izmjene polja ograničenja stope za isti ključ.

Naredbe za pravila koriste autentificirane zahtjeve `GET`/`PATCH /api/keys/{id}` te poštuju aktivni
kontekst i globalnu opciju `--api-key`. JSON izlaz sadržava samo polja pravila,
bez pohranjenog ključa ili njegova maskiranog prikaza. Vjerodajnica namijenjena samo izvođenju zaključivanja
ne može odobriti promjene upravljanja. Odgovor 401/403 zahtijeva provjeru vjerodajnice za upravljanje
i konteksta; ne potvrđuje lokalni kvar CLI tokena ili soli.
Za zaseban lokalni ugovor o autentifikaciji pogledajte [CLI token](../security/CLI_TOKEN.md).
