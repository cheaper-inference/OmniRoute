## Gratis tokens per maand: ~ 11,3 miljard zoals anderen tellen · ~ 90M Real

</div>

> **~ 11,3 miljard gratis tokens / maand**<br/> <sub> telde zoals andere catalogi tellen: elke rij opgeteld, inclusief beëindigde aanbiedingen </sub>
>
> **~ 90M echt vandaag**<br/> <sub> elk gedeeld quotum één keer geteld: wat je daadwerkelijk kunt gebruiken </sub>
>
> **Alles is hier gratis. Geen betaalmuur.**<br/> ★ [Vind je het leuk? Geef ons een ster op GitHub](https://github.com/cheaper-inference/OmniRoute)

Andere catalogi rekenen vanaf US$ 19 per jaar tot US$ 49 voor levenslange toegang tot live data. Hier is alles gratis. <sub> Prijzen gecontroleerd op 18-11-2026.</sub>

<sub>Catalogus voor het laatst gecontroleerd op 23-11-2026. [Hoe we → tellen](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **Breng uw eigen provideraccounts mee.** Dit zijn gratis niveaus van derden, geen tokensubsidie van OmniRoute. Meld u aan, ontvang inloggegevens waar een provider erom vraagt en koppel de gegevens die u kunt gebruiken. Elke aanbieder bepaalt zijn eigen limieten, beschikbaarheid en voorwaarden.
>
> Met de hand vrije niveaus stapelen betekent tientallen SDKs, tientallen tarieflimieten en geen duidelijk idee van wat je nog over hebt. OmniRoute houdt 214 catalogusrijen bij met gratis toegang en berekent het werkelijke cijfer uit 12 pools met een gepubliceerd quotum, waarbij elke gedeelde pool één keer wordt geteld. Quota die alleen opengaan na een regionale identiteitscontrole (tegenwoordig ModelScope) worden afzonderlijk weergegeven, +~ 6 miljoen achter de regionale identiteitsverificatie, en nooit opgeteld bij het werkelijke cijfer. Wat er nog over is, verschijnt op het dashboard (`/dashboard/free-tiers`).

## Installeer, sluit een provider aan en routeer vervolgens via één eindpunt

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>`auto` heeft een in aanmerking komende route nodig. Een nieuwe installatie kan geen in aanmerking komende sleutelloze doelen hebben, en een sleutelloze provider kan clients van derden afwijzen. Raadpleeg de [Free Tiers Guide](docs/getting-started/FREE-TIERS-GUIDE.md) voordat u een provider kiest.</sub>

## Combo's: het vlaggenschip

1. **Begin met `auto`.** Stel het model in uw OpenAI-compatibele client in. OmniRoute bouwt een virtuele combo van aangesloten aanbieders en scoort kandidaten live.
2. **Bewaar een combo voor meer controle.** Kies een naam, doelgroeplijst en strategie en gebruik die naam vervolgens als model. De strategie bepaalt welk doel het eerst gaat en hoe de rest wordt geprobeerd.

Een combo routeert automatisch tussen modellen. Bij uitputting van quota, falen van een provider of uitsluiting van modellen probeert het het volgende geschikte, gezonde doel te bereiken.

### Zero-config: gebruik gewoon `auto`

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

Varianten stemmen de gewichten af. De laatst bekende goede routering blijft bij de laatste succesvolle provider totdat deze faalt en vervolgens opnieuw scoort. `auto/fast` en `auto/cheap` drukken voorkeuren uit zonder het snelste of goedkoopste model te garanderen.

| Model ID            | Gedrag                                                                                                                                                                                                                                                                                                  |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`              | Evenwichtige standaardgewichten.                                                                                                                                                                                                                                                                        |
| `auto/fast`         | Bevordert een lage latentie en de gezondheid van de provider.                                                                                                                                                                                                                                           |
| `auto/cheap`        | Is voorstander van lagere catalogusprijzen.                                                                                                                                                                                                                                                             |
| `auto/coding`       | Kwaliteit staat voorop bij het genereren van code.                                                                                                                                                                                                                                                      |
| `auto/smart`        | Kwaliteit staat voorop met 10% verkenning (standaard 5%).                                                                                                                                                                                                                                               |
| `auto/lkgp`         | Expliciete laatst bekende goede routing met dezelfde gewichten als `auto`.                                                                                                                                                                                                                              |
| `auto/subscription` | Gebruikt alleen live-geverifieerde abonnementsquota. Retourneert HTTP 503 wanneer er geen beschikbaar is en vermijdt gefactureerde terugval.                                                                                                                                                            |
| `auto/thrifty`      | Plan → keyless → gratis → goedkope → premium. Kan gefactureerde modellen bereiken en keert terug naar het plan wanneer quota en cooldown dit toestaan.                                                                                                                                                  |
| `auto/offline`      | Is voorstander van quota en speelruimte bij tarieflimieten. Verzoeken gaan nog steeds naar uw providers.                                                                                                                                                                                                |
| `auto/chaos`        | Eén model per provider parallel, maximaal vijf standaard of tien indien geconfigureerd. Eén upstream-oproep per model. Retourneert het hoogst gerangschikte antwoord of het laatste succesvolle paneelantwoord als het topmodel faalt. Gebruik `fusion` om antwoorden met een rechter te synthetiseren. |

Voorbeelden van categorieën en optionele lagen zijn `auto/coding:fast`, `auto/coding:free`, `auto/reasoning:pro` en `auto/vision`. Als geen enkele verbonden kandidaat overeenkomt, retourneert het verzoek HTTP 503 en blijft de pool beperkt. [Gids voor automatische combinaties](./docs/routing/AUTO-COMBO.md) · [Routering op basis van abonnement](./docs/routing/SUBSCRIPTION_LADDER.md)

### Of bouw uw eigen: 22 routeringsstrategieën

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

De CLI accepteert 15 van de 22 strategieën. Het dashboard en de combo's API accepteren alle 22.

| Strategie           | Gedrag                                                                                                                                                                                                                                                                              |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Kandidaten rangschikken live met de Auto-Combo-scorer met 16 factoren.                                                                                                                                                                                                              |
| `cache-optimized`   | Geef de voorkeur aan het account dat waarschijnlijk het promptvoorvoegsel in de cache bevat.                                                                                                                                                                                        |
| `context-optimized` | Probeer eerst het grootste bekende contextvenster.                                                                                                                                                                                                                                  |
| `context-relay`     | Bewaar uw bestelling en geef een gespreksoverzicht door bij het wisselen van account.                                                                                                                                                                                               |
| `cost-optimized`    | Sorteer op catalogusinvoertokenprijs, onbekenden als laatste. De kosten voor de definitieve aanvraag kunnen verschillen.                                                                                                                                                            |
| `expiry-first`      | Het bestedingsquotum verloopt waarschijnlijk, het hoogste resterende per uur totdat het eerst opnieuw wordt ingesteld.                                                                                                                                                              |
| `fill-first`        | Blijf op het eerste beschikbare doel totdat het op is of mislukt, en ga dan verder.                                                                                                                                                                                                 |
| `fusion`            | Voer tegelijkertijd een vraag uit aan een panel en laat een rechter één antwoord synthetiseren.                                                                                                                                                                                     |
| `headroom`          | Kies de meest vrije capaciteit over 5-uurs- en wekelijkse vensters.                                                                                                                                                                                                                 |
| `jev`               | TypeSafe Jev kiest welke vermeldingen in uw gerangschikte lijst worden uitgevoerd. Schakel `COMBO_JEV_STRATEGY_ENABLED` in om per aanvraag een uittreksel te versturen en maak gebruik van betaalde TypeSafe -oproepen. Als deze is uitgeschakeld, is uw bestelling van toepassing. |
| `least-used`        | Kies het doelwit met de minste geregistreerde verzoeken in deze combinatie.                                                                                                                                                                                                         |
| `lkgp`              | Probeer eerst de laatste succesvolle aanbieder, anders bewaar je je bestelling.                                                                                                                                                                                                     |
| `p2c`               | Neem een voorbeeld van twee doelen en kies op basis van succespercentage en latentie.                                                                                                                                                                                               |
| `pipeline`          | Voer de uitvoer van elke stap achtereenvolgens in het volgende doel in en retourneer alleen het uiteindelijke antwoord.                                                                                                                                                             |
| `priority`          | Probeer doelen in uw bestelling. Sessiekleverigheid behoudt het.                                                                                                                                                                                                                    |
| `quota-weighted`    | Sla uitgeputte accounts over en profiteer van overgebleven quota en lading tijdens de vlucht.                                                                                                                                                                                       |
| `random`            | Shuffle voor elk verzoek. Hetzelfde eerste doelwit kan zich herhalen.                                                                                                                                                                                                               |
| `reset-aware`       | Scoor het resterende quotum en de tijd om te resetten in sessie- en wekelijkse vensters.                                                                                                                                                                                            |
| `reset-window`      | Probeer het account waarvan het quotumvenster het snelst wordt gereset.                                                                                                                                                                                                             |
| `round-robin`       | Roteer in volgorde, standaard drie successen per doel.                                                                                                                                                                                                                              |
| `strict-random`     | Deel vanuit een geschud kaartspel, zodat elk doelwit één keer leidt voordat het wordt herhaald.                                                                                                                                                                                     |
| `weighted`          | Teken een eerste doelwit op gewicht en bewaar de rest als reservedoel. De splitsing is statistisch. Gebruik `round-robin` voor strikte rotatie.                                                                                                                                     |

Quotastrategieën maken gebruik van live gegevens waar providers deze rapporteren, inclusief abonnementsperioden van 5 uur en wekelijkse abonnementen. `fusion` en `pipeline` maken meerdere upstream-aanroepen per verzoek.

De scorer met 16 factoren maakt gebruik van quota, gezondheid, kosten, latentie, taakgeschiktheid, stabiliteit, niveauprioriteit, niveauaffiniteit, specificiteitsmatch, contextaffiniteit, cacheaffiniteit, sessiebeschikbaarheid, reset-vensteraffiniteit, verbindingsdichtheid, kwaliteit en betrouwbaarheid. Gewichten variëren per profiel. Cache-affiniteit, reset-venster-affiniteit en betrouwbaarheid hebben standaard nul gewicht. ### Veerkracht is ingebouwd: 3 onafhankelijke lagen

Fouten worden op drie manieren afgehandeld, dus één slecht model haalt het account niet uit de lucht, en één slecht account haalt de provider er niet uit.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Als een hele provider uitvalt

De** stroomonderbreker van de leverancier** wordt geopend na 8 (OAuth) of 12 (API -sleutel) fouten met status 408, 500, 502, 503 of 504. Combo's slaan die provider over terwijl deze open is. Na 60 s of 30 s beslist één sondeverzoek of deze wordt gesloten.

#### Als voor één sleutel of account een tariefbeperking geldt

De** verbinding afkoelen** bank alleen die verbinding, met exponentieel uitstel van 5 s (OAuth) of 3 s (API sleutel). Andere sleutels voor dezelfde provider blijven actief.

#### Als één model wordt geweigerd

De** model vergrendeling** blokkeert alleen dat model op die verbinding na een per-model 429, 404 of toegangsweigering. Andere modellen op dezelfde verbinding blijven werken.

Verboden, verlopen en kredietloze verbindingen zijn terminale toestanden, geen cooldowns: ze wachten tot jij ze repareert.

## Volledige CLI, MCP en A2A

> OmniRoute levert een opdrachtregelclient mee** 91 commando's en commandogroepen op het hoogste niveau** (754 commando's tellen subcommando's), an**MCP server met 110 tools en 33 scopes** , en een**A2A agent met 6 vaardigheden** . Scripts, terminals en AI -agents kunnen allemaal dezelfde gateway bedienen.

### Een echte CLI, niet alleen `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

De globale `--output table|json|jsonl|csv` vlag maakt dezelfde opdrachten bruikbaar vanuit scripts en CI.

### Externe modus: de CLI op uw laptop, OmniRoute op een server

Log eenmalig in op een externe server. De CLI slaat het op als een** context** , en latere opdrachten worden tegen die server uitgevoerd totdat u terugschakelt.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Tokenbereik | <img width="2000" height="0" alt=""> Wat het toestaat                       |
| ----------- | --------------------------------------------------------------------------- |
| `read`      | Lijst en inspecteer: modellen, status, logs, gebruik                        |
| `write`     | `read` plus configureren en toepassen: clientconfiguratie, sleutels, config |
| `admin`     | `write` plus beheren: tokens, providers, diensten, beleid                   |

Een kale host krijgt `http://` en poort 20128; geef een volledige `https://` URL door als de server achter TLS zit. Routes die processen kunnen voortbrengen, blijven alleen loopback, ongeacht het token.

### Sluit een agent aan

Een agent, of uw eigen code, kan via elk van deze interfaces routing, providers, combo's, cache, compressie en geheugen aansturen. HTTP -paden worden door de gateway bediend, standaard op `http://localhost:20128`.

| Interface               | Eindpunt of opdracht       | Gebruik het voor                                                                              |
| ----------------------- | -------------------------- | --------------------------------------------------------------------------------------------- |
| MCP over stdio          | `omniroute --mcp`          | Claude Desktop, Cursor en andere lokale MCP clients                                           |
| MCP via streambare HTTP | `/api/mcp/stream`          | Externe MCP clients: 110 tools, 33 scopes, elke oproep wordt naar het auditlogboek geschreven |
| MCP boven SSE           | `/api/mcp/sse`             | Klanten die nog gebruik maken van het SSE vervoer                                             |
| A2A ontdekking          | `/.well-known/agent.json`  | Agentenkaart: vertelt andere agenten wat OmniRoute kan doen                                   |
| A2A uitvoering          | `POST /a2a`                | JSON-RPC 2.0-taken, synchroon of gestreamd via SSE, voor 6 vaardigheden                       |
| REST API                | `/v1/*`                    | OpenAI-compatibele chat, reacties, insluitingen, afbeeldingen, audio en OCR                   |
| Webhaken                | `/api/webhooks`            | Gebeurtenissen voor Slack, Discord, Telegram of een URL met HMAC -ondertekening               |
| Op afstand CLI          | `omniroute connect <host>` | Bestuur een extern exemplaar met toegangstokens met bereik                                    |

De zes A2A vaardigheden zijn `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` en `list-capabilities`.

**Voordat u verbinding maakt:**

- **MCP over HTTP start uitgeschakeld.** Schakel het in met `omniroute mcp enable --transport streamable-http` of vanaf de pagina Eindpunten van het dashboard. Er is één HTTP -transport tegelijk actief: `streamable-http` bedient `/api/mcp/stream`, `sse` bedient `/api/mcp/sse`.
- **A2A start uitgeschakeld.** Schakel het in op de pagina Eindpunten van het dashboard. `POST /a2a` volgt dan dezelfde API-sleutelregels als `/v1`.
- **Op afstand MCP heeft een passende sleutel nodig.** `/api/mcp/*` beantwoordt standaard alleen loopback. Stuur vanaf een andere host een sleutel met `manage` of `admin` (alle tools), of met `mcp:connect` plus de scopes van de tools die je nodig hebt. Voor sleutels zonder `manage`/`admin` worden gereedschapsbereiken altijd afgedwongen.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

## Bespaar automatisch 15-95% tokens —

### Hoe het werkt — pipeline, architectuur en besparingswiskunde

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

Standaard gestapelde combo voert `RTK → Caveman` uit. Wanneer beide op dezelfde tool/context payload werken, worden de besparingen samengesteld:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Codeblokken, URLs, JSON en gestructureerde gegevens zijn dat wel** altijd beschermd** door de conserveringsengine.

> **Waarom veel tokens gebruiken als weinig tokens voldoende zijn?** Elk verzoek passeert de compressiepijplijn van OmniRoute** transparant** — geen klantwijzigingen. Het is nu een** stapel van 12 samenstelbare motoren** die in volgorde worden uitgevoerd en mixen en matchen per routeringscombo — voortbouwend op ideeën van [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) en [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

## Meer installatiemethoden — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` volgt de hoogste** gepubliceerd** stabiele SemVer. Het volgt git `main` niet. Pin `:X.Y.Z` voor GitOps. Zie [Docker Release Channels](docs/guides/DOCKER_GUIDE.md#release-channels). De afbeelding wordt vastgezet**`OMNIROUTE_MEMORY_MB=1024`** . Dat is genoeg voor het dashboard en een lichte babbel.** Codeermiddelen** (`POST /v1/responses` van Claude Code, Codex, Grok, …) hebben een veel grotere V8-heap nodig of het proces `FATAL ERROR` s op ~ 12 GiB onder twee overlappende lange contexten. Grootte van de container boven de heap (native buffers bevinden zich buiten V8):

| <img width="2000" height="0" alt=""> Werklast | Hoop (`-e OMNIROUTE_MEMORY_MB`) | Container (`--memory`) |
| --------------------------------------------- | ------------------------------- | ---------------------- |
| Dashboard / lichte chat                       | `1024` (standaard afbeelding)   | ≥ 2 g                  |
| Eén codeermiddel                              | `8192`                          | ≥ 10 gr                |
| Twee gelijktijdige lange `/v1/responses`      | `10240`–`12288`                 | ≥ 12–16 g              |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Volledige tabel: [Docker Gids — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Pre-release Docker kanaal:** `diegosouzapw/omniroute:next` en `diegosouzapw/omniroute:next-web` volgen de huidige standaard `release/v*` vertakking. Deze veranderlijke tags zijn alleen bedoeld voor het testen van niet-uitgebrachte oplossingen en zijn dat ook** niet ondersteund voor productie** . Zie [Docker -releasekanalen](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

Standaard `bun install` en globale installatie (`bun install -g omniroute`) worden ondersteund via Bun runtime-detectie:

- **Ingebouwde `bun:sqlite`** : OmniRoute gebruikt Bun's ingebouwde `bun:sqlite` -stuurprogramma wanneer het onder Bun draait, en valt terug naar `better-sqlite3` op Node.js of `sql.js`.
- **Automatische Webpack-bundelselectie in dev** : Development (`bun run dev`) detecteert Bun automatisch en schakelt Turbopack uit ten gunste van Webpack om incompatibiliteit met native V8-bindingen te voorkomen. Productiebuilds (`bun run build`) volgen `OMNIROUTE_USE_TURBOPACK` precies zoals op Node: Turbopack standaard, `OMNIROUTE_USE_TURBOPACK=0` om te bouwen met Webpack (`Dockerfile.bun` stelt het bloot als een `--build-arg`).
- **Toegewijd Bun Dockerbestand** : Meerfasige `Dockerfile.bun` voor native Bun -productie-implementaties (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ Snellere/slankere installatie (sla de native build over)**

De native SQLite engine (`better-sqlite3`) is een** optioneel** afhankelijkheid, dus een globale installatie blokkeert nooit het compileren vanaf de broncode: het gebruikt een vooraf gebouwd binair bestand wanneer er één overeenkomt met je platform/Node, en valt anders transparant terug naar een pure-JS-engine (`node:sqlite` op Knooppunt 22 +, anders de gebundelde `sql.js` WASM) — geen bouwtools vereist.

Om de post-installatie over te slaan** inheemse warming-up** geheel (CI, hoofdloze of langzame machines). Let op: hiermee wordt alleen de oorspronkelijke SQLite -opwarmstap (`scripts/postinstall.mjs`) overgeslagen; de binary-copy/repair hook (`scripts/build/postinstall.mjs`) werkt nog steeds normaal:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

Voor de snelste installaties liever** pnpm** (inhoudsgerichte winkel + harde links — zie hierboven). Voor een dashboardvrije, headless runtime gebruikt u het Docker `base` profiel (hierboven) of de [Termux-handleiding](docs/guides/TERMUX_GUIDE.md). De CLI en het webdashboard worden via hetzelfde proces op één poort bediend, dus er is tegenwoordig geen afzonderlijk CLI-only pakket.

## Dankbetuigingen

OmniRoute staat op de schouders van reuzen. Het begon als een vork van** [9router](https://github.com/decolua/9router)** en een TypeScript poort van het Go-project** [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)** — en van daaruit werd elk subsysteem hieronder geïnspireerd door een open-sourceproject dat daar als eerste arriveerde. Ieder vormde een betonnen stuk OmniRoute. Dit is onze dank aan hen allemaal. 🙏

> ⭐ sterrentellingen geverifieerd op basis van GitHub's REST API op 16 november 2026 — ga deze projecten een ster geven. Tellingen zijn een exact gedateerde momentopname en zullen uiteraard veranderen. GrokBridge heeft op die datum HTTP 404 geretourneerd; de toeschrijving ervan blijft behouden.
