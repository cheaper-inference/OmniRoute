Hoe OmniRoute de kosten van elk verzoek schat, registreert en rapporteert — en waarom het
getal op het dashboard een **besparingstracker** is en geen factuur.

Zie ook: [Gebruikershandleiding](./USER_GUIDE.md) · [Functieoverzicht](./FEATURES.md)

---

## Wat het is (en wat het niet is)

OmniRoute kent aan elke voltooiing kosten per verzoek in USD toe door de aantallen tokens
te vermenigvuldigen met de tarieven van een model. Deze cijfers vormen de basis voor het
dashboard **Kosten**, de CLI-opdrachten `omniroute cost` / `omniroute usage`, CSV-/JSON-exports
en budgetten per API-sleutel.

> **De 'kosten' op het dashboard zijn een besparingstracker, geen factuur.** OmniRoute brengt
> je nooit kosten in rekening — het routeert je verzoeken naar providers die je al hebt
> gekoppeld (je eigen abonnementen, gratis niveaus en API-sleutels). Als er uitsluitend via
> gratis modellen "$290 totale kosten" zijn opgebouwd, betekent dit dat je ongeveer **$290
> _niet_ aan een betaalde API hebt uitgegeven**. Het bedrag is een _schatting_ van wat
> hetzelfde verkeer tegen standaardlijstprijzen zou hebben gekost, zodat je kunt zien waar
> je gebruik zich concentreert en hoeveel je bespaart door naar goedkopere/gratis providers
> te routeren.

Deze duiding wordt rechtstreeks vermeld in de [README](../../README.md) van het project
("de 'kosten' op het dashboard zijn een besparingstracker, geen factuur").

Omdat het bedrag een schatting is:

- Het hangt af van de prijstabel die OmniRoute voor elk model heeft. Een model zonder
  prijsvermelding draagt `0` aan de kosten bij (het wordt in de verkenner weergegeven als
  een rij "Verouderd / Gratis").
- Verkeer via gratis niveaus en abonnementen bouwt nog steeds _geschatte_ kosten op — dat
  is het bedrag dat je bespaart, niet een bedrag dat je verschuldigd bent.

## Hoe de kosten worden geschat

### De prijsbron

De kosten komen uit de samengevoegde prijstabel in [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts), in deze volgorde van prioriteit (** hoogste eerst** ):

1. **Gebruikersoverschrijvingen** — prijzen ingesteld in het dashboard of via `PATCH /api/pricing` (de `pricing` naamruimte).
2. **models.dev-synchronisatie** — -prijzen opgehaald uit `https://models.dev/api.json` (de `models_dev_pricing` naamruimte).
3. **LiteLLM -synchronisatie** — prijzen opgehaald uit de openbare `model_prices_and_context_window.json` van LiteLLM(de `pricing_synced` naamruimte).
4. **Hardgecodeerde standaardwaarden** — tarieven verzonden in [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/).

Voor dezelfde provider/model overschrijven waarden uit lagen met een hogere prioriteit overeenkomende velden in lagere lagen; velden die ontbreken in een bovenste laag kunnen toch afkomstig zijn uit een lagere laag. De volgorde staat vast, zelfs als beide onafhankelijke synchronisatietaken tegelijkertijd worden uitgevoerd. `GET /api/pricing?includeSources=1` retourneert `pricing` en `sourceMap`, waarvan de labels per model (`user`, `modelsDev`, `litellm`, `default`) de laag met de hoogste prioriteit identificeren die dat model bevat.

**LiteLLM -synchronisatie** is opt-in, standaard uitgeschakeld. De omgevingsvariabelen (zie [`.env.example`](../../.env.example) ) zijn:

| Env var                 | Standaard | Doel                                                                                        |
| ----------------------- | --------- | ------------------------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | Schakel LiteLLM prijssynchronisatie op de achtergrond in.                                   |
| `PRICING_SYNC_INTERVAL` | `86400`   | Synchronisatie-interval in seconden (dagelijks).                                            |
| `PRICING_SYNC_SOURCES`  | `litellm` | Bronselectie alleen voor deze synchronisatie; momenteel wordt alleen `litellm` ondersteund. |

**models.dev-synchronisatie** staat los van de LiteLLM synchronisatie en is ook standaard uitgeschakeld. Schakel het in via Instellingen (models.dev sync) of gebruik deze variabelen:

| Env var                    | Standaard         | Doel                                                                                                                                                               |
| -------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `MODELS_DEV_SYNC_ENABLED`  | _(uitgeschakeld)_ | Uitschakelen volgt de schakelaar Instellingen; `1/true/on/yes` wordt ingeschakeld en `0/false/off/no` wordt uitgeschakeld (zelfs als Instellingen dit inschakelt). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`           | Standaard synchronisatie-interval van models.dev in seconden (dagelijks).                                                                                          |

`PRICING_SYNC_SOURCES` wel** niet** modellen.dev inschakelen; het bestuurt alleen de LiteLLM synchronisatie. Als u een gebruikersoverschrijving verwijdert, worden de gesynchroniseerde naamruimten niet gewist; de volgende beschikbare prijslaag wordt van kracht. Voor een ongeprijsd model controleert u zowel de synchronisatie-instellingen als de `sourceMap` voordat u een handmatige overschrijving toevoegt.

### De kostenformule

De kosten worden per verzoek berekend op basis van het aantal tokens en de tarieven per miljoen tokens in [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`):

- **Invoertokens** (minus cache-lezingen en tokens voor het maken van caches) × `input` snelheid.
- **In cache gelezen tokens** × `cached` -tarief (valt terug naar het invoertarief).
- **Tokens voor het maken van caches** × `cache_creation` -tarief (valt terug naar het invoertarief).
- **Uitvoertokens** × `output` tarief.
- **Redeneringsfiches** × `reasoning` -snelheid (valt terug naar de uitvoersnelheid).

Alle tarieven worden geïnterpreteerd als USD per 1.000.000 tokens. Een Codex "fast"/"priority" of "flex" servicelaag past een kostenvermenigvuldiger toe (`getCodexFastCostMultiplier`) — bijvoorbeeld flex wordt gefactureerd met een tokenkorting van 50%, weergegeven als** flex sparen** in het dashboard.

Modelnamen worden eerst genormaliseerd (providerpadvoorvoegsels zoals `openai/` of `accounts/fireworks/models/` worden verwijderd), zodat historische rijen nog steeds overeenkomen met een prijs.

### Hoe de uitgaven worden geregistreerd

- De kosten per verzoek worden berekend na de respons en geregistreerde ‘fire-and-forget’-procedures, zodat er nooit latentie voor de client ontstaat. Het verbruik van gedeelde quota wordt gepland bij de volgende event-loop tick via [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts).
- De uitgaven voor API-sleutels worden in batches gebufferd en leeggemaakt door de [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (standaard spoelinterval van 60 seconden, buffer voor 1.000 invoer). Afstembaar via:

  | Env var                             | Standaard | Doel                                           |
  | ----------------------------------- | --------- | ---------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`   | Spoelinterval in milliseconden.                |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`    | Max. gebufferde invoeren vóór het doorspoelen. |

De kostencijfers van het dashboard zijn** niet** gelezen uit een opgeslagen dollarbedrag per rij — worden ze telkens opnieuw berekend op basis van tokenaantallen en de huidige prijstabel elke keer dat het analyse-eindpunt wordt uitgevoerd. Dat betekent dat het corrigeren van een verkeerde prijs (en het opnieuw synchroniseren) de historische kostenramingen met terugwerkende kracht bijwerkt.

## Dashboard: de pagina Kosten

De pagina **Kosten** bevindt zich op `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`).
De hoofdweergave is het tabblad **Kostenoverzicht**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
dat alle gegevens laadt via `GET /api/usage/analytics`.

Wat wordt weergegeven:

- **Uitgaventegels** — geschatte uitgaven voor _Vandaag (1d)_, _7d_, _30d_ en de geselecteerde
  periode. Periodekiezer: `7d`, `30d`, `90d`, `all`.
- **Kerncijfers** — aanvragen binnen de periode, actieve providers, actieve modellen, gemiddelde
  kosten per aanvraag.
- **Kostenverkenner** — een sorteerbare/filterbare tabel, gegroepeerd op **provider**, **model**,
  **API-sleutel**, **account** of **serviceniveau**, met kosten, aanvragen, tokens, gemiddelde
  kosten per aanvraag en aandeel van het totaal in %.
- **Tokengebruik** — totaal aantal tokens / invoertokens / uitvoertokens en de verhouding invoer:uitvoer.
- **Routeringsefficiëntie** — aantal fallbacks, fallbackpercentage en dekking van aangevraagde modellen.
- **Maandprognose** — projecteert de uitgaven aan het einde van de maand op basis van het recente daggemiddelde.
- **Periodevergelijking** — procentuele verandering tussen de eerste en tweede helft van de periode.
- **Grafieken** — dagelijkse kostentrend, aandeel per provider (cirkeldiagram), belangrijkste providers, belangrijkste modellen, kosten
  per API-sleutel, kosten per account, wekelijks gebruikspatroon en een activiteitenheatmap.
- **Exporteren** — download de huidige periode als **CSV** of **JSON** (de knoppen verschijnen
  zodra er kostengegevens hoger dan nul zijn).

Wanneer er geen geprijsd verkeer is, worden rijen weergegeven met het label "Verouderd / Gratis" in plaats van `$0`,
in overeenstemming met het model voor het bijhouden van besparingen.

### Gerelateerde subpagina's van Kosten

Het gedeelte Kosten bevat ook (allemaal onder `/dashboard/costs/`):

- **Prijzen** (`/dashboard/costs/pricing`) — bekijk en overschrijf prijzen per model (geeft
  het gedeelde tabblad Prijzen weer).
- **Budget** (`/dashboard/costs/budget`) — stel uitgavenlimieten per bereik in (geeft het gedeelde
  tabblad Budget weer).
- **Quotumdeling** (`/dashboard/costs/quota-share`) — gedeelde quotumpools en weergaven van het
  verbruikstempo.

## API -eindpunten

Deze vereisen allemaal managementauthenticatie (loopback/JWT, via `requireManagementAuth`), tenzij anders aangegeven.

### Gebruiks- en kostenanalyse

| Methode | Eindpunt                 | Doel                                                                                                                                                                     |
| ------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET`   | `/api/usage/analytics`   | Volledige cost/usage -analyse: samenvatting, dagelijkse trend, door provider/model/API key/account/tier. Query: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET`   | `/api/usage/utilization` | Quotagebruik per provider in de loop van de tijd. Zoekopdracht: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                             |
| `GET`   | `/api/usage/history`     | Ruwe gebruiksgeschiedenisrijen.                                                                                                                                          |
| `GET`   | `/api/usage/call-logs`   | Gesprekslogboeken per aanvraag (model, tokens, kosten, latentie, status).                                                                                                |
| `GET`   | `/api/usage/quota`       | Quotumstatus van provider.                                                                                                                                               |
| `GET`   | `/api/usage/proxy-logs`  | Logboeken van proxyverzoeken.                                                                                                                                            |

### Budgetten

| Methode | Eindpunt                 | Doel                                                                                        |
| ------- | ------------------------ | ------------------------------------------------------------------------------------------- |
| `GET`   | `/api/usage/budget`      | Kostenoverzicht + budgetcontrole voor één API sleutel (`apiKeyId` -queryparameter vereist). |
| `POST`  | `/api/usage/budget`      | Stel daily/weekly/monthly USD limieten + waarschuwingsdrempel in voor een API sleutel.      |
| `GET`   | `/api/usage/budget/bulk` | Bulkbudgetsamenvattingen over API sleutels.                                                 |

> Het budget API heeft een scope per**API sleutel** (`apiKeyId`). Limieten die door `GET /api/usage/budget` worden geretourneerd, zijn onder meer `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`, a `warningThreshold` en de lopende totalen (`totalCostToday`, `totalCostMonth`, ...).

### Prijzen

| Methode  | Eindpunt                | Doel                                                                                                                                                                    |
| -------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | Samengevoegde vierlaagse prijzen (gebruiker, models.dev, LiteLLM, standaardwaarden). `?includeSources=1` retourneert `pricing` + `sourceMap`.                           |
| `PATCH`  | `/api/pricing`          | Prijzen voor `{ provider: { model: { input, output, cached, … } } }` overschrijven.                                                                                     |
| `DELETE` | `/api/pricing`          | Verwijder gebruikersprijsoverschrijvingen (optioneel bepaald door `?provider=&model=`); gesynchroniseerde tarieven of ingebouwde standaardwaarden blijven als fallback. |
| `GET`    | `/api/pricing/defaults` | Toon standaard per-1M -fallback-percentages.                                                                                                                            |
| `GET`    | `/api/pricing/models`   | Prijzen aangepast per model.                                                                                                                                            |
| `POST`   | `/api/pricing/sync`     | Activeer een handmatige synchronisatie vanaf externe bronnen (LiteLLM).                                                                                                 |
| `GET`    | `/api/pricing/sync`     | Huidige synchronisatiestatus.                                                                                                                                           |
| `DELETE` | `/api/pricing/sync`     | Alleen LiteLLM-gesynchroniseerde prijzen wissen (`pricing_synced`); models.dev-gegevens zijn gescheiden.                                                                |

## CLI

De CLI van OmniRoute biedt opdrachten voor kosten, gebruik en prijzen (geregistreerd in
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

Een kostenrapport dat is samengesteld uit `/api/usage/analytics`.

```bash
omniroute cost                          # afgelopen 30d, gegroepeerd op provider
omniroute cost --period 7d              # afgelopen 7 dagen
omniroute cost --group-by model         # groeperen op provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

Kolommen: groep, aanvragen, inkomende/uitgaande tokens, kosten (USD) en % van het totaal. Aan het einde
wordt een regel met het eindtotaal weergegeven (onderdrukt met `--quiet` of `--output json`).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # kostenoverzicht per provider
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# Budgetten
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` leest `GET /api/pricing/defaults`. Gebruik in plaats daarvan de dashboardpagina **Prijzen** of `PATCH /api/pricing`
> om prijzen van afzonderlijke modellen te bewerken.

## Probleemoplossing

- **Alle kosten worden weergegeven als $0 / "Legacy / Free".** De gebruikte modellen hebben geen prijsvermelding.
  Schakel externe synchronisatie in (`PRICING_SYNC_ENABLED=true`) en voer `omniroute pricing sync` uit, of
  stel prijzen handmatig in via de pagina Prijzen / `PATCH /api/pricing`.
- **Een historisch model heeft een onjuiste prijs.** Corrigeer de prijs (via een overschrijving of door opnieuw te synchroniseren) — de kosten worden
  bij elke analyse-uitlezing opnieuw berekend op basis van het aantal tokens, zodat schattingen met terugwerkende kracht worden bijgewerkt.
- **De uitgaven lopen achter op de actuele situatie.** Uitgaven per sleutel worden in batches verwerkt; verlaag
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` als u actuelere cijfers nodig hebt.
