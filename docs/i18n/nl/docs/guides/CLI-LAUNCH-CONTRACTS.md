Het neutrale `config/cli-tools-manifest.json` contract declareert canonieke IDs, aliassen, binaire kandidaten, installatierecepten, modelargumenten en mogelijkheden. De gewone Node-adapter in `bin/cli/cli-manifest.mjs` en de TypeScript adapter in `src/shared/constants/cliIntegrationManifest.ts` lezen hetzelfde bestand. Runtime, catalogus, configuratie, voltooiing, generatoren en backend-registratie worden samen gecontroleerd door `tests/unit/cli/cli-manifest-drift.test.ts`. Gecatalogiseerd zijn betekent niet dat een tool kan worden gestart of geconfigureerd. In het bijzonder blijft 5dive alleen configureren.

## Kindomgeving en levenscyclus

`omniroute run`, `omniroute launch` en `omniroute launch-codex` nemen een toelatingslijst voor OS/terminal compatibiliteit over en injecteren de inloggegevens van het geselecteerde doel. Niet-gerelateerde provider- en databasegeheimen worden standaard niet overgenomen. `--inherit-env` herstelt expliciet de volledige overerving van de ouderomgeving; gebruik het alleen wanneer het geselecteerde externe proces deze waarden zou moeten ontvangen. Dit is omgevingsfiltering, geen OS sandbox: het proces wordt nog steeds uitgevoerd met de bestandssysteemrechten van de aanroeper.

Onderbrekings- en beëindigingssignalen worden doorgestuurd naar het kind. Het opstartprogramma wacht op de close-gebeurtenis van het kind voordat de tijdelijke configuratie wordt verwijderd. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` beheert de respijtperiode vóór gedwongen beëindiging (standaard 5000 milliseconden).

## Gemini persistente installatie

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

De eerste twee opdrachten configureren deze machine voor de geselecteerde lokale of externe server. Setup behoudt niet-gerelateerde JSON instellingen, selecteert Gemini API-sleutelauthenticatie en schrijft het eindpunt en de inloggegevens naar een privé `.gemini/.env` bestand. Het weigert ongeldige JSON in plaats van het te overschrijven. Eindpunt URLs moet HTTP(S) zijn, zonder ingebedde referenties, queryparameters of fragmenten. Proefafdrukpaden, geen referentiewaarden.

`GEMINI_CLI_HOME` of `--gemini-home` selecteert de persistente thuisroot. Een daadwerkelijke `run gemini` creëert en verwijdert later een eigen tijdelijke woning. Geen van beide modi omzeilt de werkruimte-vertrouwenscontroles van Gemini.

## Codex -profielen

`configure codex` schrijft een privé- `<name>.config.toml` met een model en het bijbehorende OmniRoute providereindpunt. Er wordt naar referenties verwezen via `OMNIROUTE_API_KEY`, nooit ingebed. Met het startcommando wordt het geselecteerde model ingesteld op de `model` -sleutel op het hoogste niveau, niet binnen `model_providers`.

Aparte profielbestanden zijn het huidige gedocumenteerde Codex contract; ze overlappen de gebruikersconfiguratie wanneer geselecteerd met `codex --profile <name>`. Zie [de officiële profielreferentie](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) en [de OmniRoute Codex gids](./CODEX-CLI-CONFIGURATION.md).

## Hermetische commando-uitvoering

Met een expliciete `DATA_DIR` voorkomt het instellen `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` dat het opstarten doorvalt naar de referentieomgeving van de standaardgebruikersgegevensmap. Dit is handig voor geïsoleerde tests. Andere expliciet geselecteerde omgevingsbestanden worden niet uitgeschakeld.

## Werkmap `.env`

De CLI leest `.env` bestanden in deze volgorde, en het eerste bestand dat een sleutel instelt, wint: de expliciete `DATA_DIR`, de standaardgegevensmap, de huidige werkmap en vervolgens de pakketmap. Shell-variabelen winnen altijd.

De werkmap kan van iemand anders zijn (een gekloonde repository, een uitgepakt archief), en `omniroute serve` geeft de CLI -omgeving door aan de server en aan elke tool die de server draait. Dus een `.env` mag daar alleen deze sleutels instellen, vermeld in `bin/cli/utils/untrustedCwdEnv.mjs`:

| Sleutel                         | Geaccepteerde waarden                                                      |
| ------------------------------- | -------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` of `yes` in ieder geval de waarden die de server behandelt     |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | maximaal 64 letters, cijfers, `_`, `.`, `@` of `-`                         |
| `LANGUAGE`                      | hetzelfde, plus `:`                                                        |
| `TZ`                            | maximaal 64 letters, cijfers, `_`, `+`, `-` of `/`, niet beginnend met `/` |
| `NO_COLOR`, `FORCE_COLOR`       | maximaal 16 letters en cijfers                                             |

Elke waarde `REQUIRE_API_KEY` accepteert, schakelt de controle in, zodat het bestand de controle niet zelf kan uitschakelen. Het bepaalt echter niet het resultaat: de server leest een `REQUIRE_API_KEY` override die in de database is opgeslagen vóór de omgeving, terwijl de opstartwaarschuwing over het luisteren op alle interfaces zonder een API -sleutel alleen de omgeving leest. Met een opgeslagen overschrijving van `false` laat een werkmap `REQUIRE_API_KEY=true` de API open en verbergt die waarschuwing. De `TZ` regel is smaller dan POSIX: hij verwerpt `.`, `:`, `,` en `<>`, dus de `:Area/City` -vorm en regels zoals `EST5EDT,M3.2.0,M11.1.0` moeten in de shell of in `<DATA_DIR>/.env` worden ingesteld.

Namen moeten exact overeenkomen, in hoofdletters. Elke andere regel, een waarde die niet wordt gecontroleerd en een naam die niet uit gewone ASCII letters, cijfers en `_` bestaat (bijvoorbeeld een met een NUL byte of een gelijksoortige letter), worden overgeslagen. De CLI drukt één waarschuwing af met de namen van de sleutels die hij niet kan instellen en één met de namen van de toegestane sleutels die hij negeerde, elk met wat er moet worden gewijzigd (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Geen van beide drukt de waarden af. Bestandspaden in deze berichten, en de `.env` -pad `omniroute doctor` -rapporten, worden voorzien van escapetekens als ze controle- of bidi-tekens bevatten. De beperking is niet van toepassing als de werkmap de gegevensmap of de pakketmap is.

`PORT`, `API_PORT` en `DASHBOARD_PORT` staan niet op de lijst. Zonder een basis URL van een bron met hogere prioriteit, praat de CLI met `localhost:<PORT>`, en wat daar ook luistert, ontvangt de API sleutel van CLI, het contexttoken en het CLI -machinetoken (`x-omniroute-cli-token`, zie [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), die de lokale server accepteert voor managementoproepen van loopback. Een poort uit de werkmap zou dat bestand de luisteraar laten kiezen, dus stel de poorten in de shell in, in `<DATA_DIR>/.env` of met de `--port` -optie van opdrachten die er één hebben (`serve`, `launch`, `run`).

De parser heeft geen `export` syntaxis. Een regel zoals `export LD_PRELOAD=...` noemt een variabele `export LD_PRELOAD`; vanuit de werkmap wordt het overgeslagen, en in andere `.env` bestanden wordt die letterlijke naam ingesteld, die door niets wordt gelezen.

De CLI koppelt het opgeslagen token van een context (toegangstoken of oudere API -sleutel) alleen aan de eigen oorsprong van die context: schema, host en poort, vergeleken als `URL.origin`. Dit is van toepassing op verzoeken die worden gedaan via de HTTP client van CLI(`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) en op de `launch`, `launch codex`, `configure` en `setup-*` commando's die een basis URL en sleutel in de configuratie van een ander hulpmiddel schrijven. Gericht op een andere server met `--remote` gebruiken ze een expliciete `--api-key` of `OMNIROUTE_API_KEY` als die is ingesteld, en geen contexttoken. De vergelijking is exact, dus `localhost` en `127.0.0.1`, of een host met en zonder een trailing dot, tellen als verschillende servers en krijgen geen contexttoken. Een URL met gebruikersinfo, een backslash of witruimte komt nooit overeen, omdat andere URL parsers (bijvoorbeeld `urllib` en `httpx` van Python) er een andere host van kunnen lezen. Voor verzoeken die de CLI zelf verzendt, heeft die controle alleen betrekking op het schema en de autoriteit, dus een id met een spatie in het pad of de query behoudt het token.
