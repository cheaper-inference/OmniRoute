`devin-cli-agentic` laat de echte Claude Code-runtime gebruikmaken van OmniRoute's lokale
Anthropic Messages-endpoint, terwijl de officiële Devin CLI modelantwoorden levert via ACP stdio. Het
wijzigt de bestaande providers voor Anthropic, Claude OAuth, Claude Web of `devin-cli` niet.

Routeer toolaanroepen die door de client worden beheerd via `devin-cli-agentic` (alias `dva`), de
toolcompatibele provider in Claude-indeling. De verouderde `devin-cli` (`dv`) ACP-executor
ondersteunt alleen tekst: deze voert Devins summarizer zonder tools uit en kan geen toolaanroepen retourneren. De
modelmetadata is dienovereenkomstig gemarkeerd, zodat combinatieroutering waarvoor tools vereist zijn deze provider vermijdt.

> **Huidige status: vastgezet op Claude Code `2.1.258`; offline- en livevalidatie voor het laatst vastgelegd
> op `2.1.220`.** Met de vastgezette versie `2.1.220` zijn drie geïsoleerde scenario's uitgevoerd via Devin CLI
> `3000.2.17` en model `swe-1-7-lightning`; die laatste live-uitvoering bewees clientgestuurde `Read`-,
> `Edit`- en `Bash`-beurten, succesvolle resultaten van `npm test`, detectie van projectcommando's en skills,
> routering uitsluitend via Devin en geen enkel uitgaand verzoek naar Claude. De vastgezette versie is daarna verhoogd naar `2.1.258`
> (de CLI-generatie die OmniRoute's Claude-identiteit nabootst en de eerste versie die
> de Fable 5.1-laag standaard bevat). Met de nieuwe vastgezette versie zijn de installatielaag en `claude --version`
> geverifieerd op de vastgezette basisimage, en slagen de unit-tests voor de bridge, `compose config` en het
> statische isolatiebewijs — maar het offline mockscenario en de live suite met drie scenario's
> zijn nog niet opnieuw uitgevoerd. Voer deze opnieuw uit (zie "Vastgezette tools bijwerken") voordat u met
> deze vastgezette versie op de bridge vertrouwt.

## Architectuur

```text
Claude Code 2.1.258 (geïsoleerde Linux-container zonder rootrechten)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-indeling, provider zonder authenticatie)
  -> devin acp --agent-type summarizer (officiële ACP stdio, zonder Devin-tools)
  -> Devin-account in het speciale devin-auth-volume
```

De standaard ACP-agent van de officiële CLI kan zijn eigen tools uitvoeren, dus deze bridge gebruikt
deze niet. De bridge start de vaste `summarizer` ACP-agent, waarvan de officiële CLI-modus geen tools heeft, en
verpakt het geserialiseerde Anthropic-verzoek als een uitvoeringstrace. Wanneer een andere door Claude beheerde
actie nodig is, moet het antwoord exact één clienttoolenvelop bevatten. Elke ACP-
`tool_call` of `tool_call_update` wordt geweigerd voordat een antwoord als
geslaagd kan worden gerapporteerd.

De serializer in `open-sse/executors/devin-agentic/serializer.ts` behoudt `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` en de
tools die door Claude Code worden aangeleverd. Afbeeldingen en onbekende blokken leiden expliciet tot een fout. Grote toolresultaten
gebruiken een zichtbare afkappingsmarkering.

De parser accepteert per modelbeurt één zelfstandige `<tool>{...}</tool>`-envelop. Deze controleert
de naam aan de hand van de toollijst van het verzoek, valideert argumenten met het JSON Schema van die tool,
weigert een combinatie van verhalende tekst en acties en staat één begrensde herstelpoging toe. Claude Code voert vervolgens
de resulterende Anthropic-`tool_use` lokaal uit en stuurt het `tool_result` via
OmniRoute terug.

## Automatische routering

De provider komt in aanmerking voor OmniRoute's `auto/*`-kandidaatpools wanneer deze niet is geblokkeerd.
In aanmerking komen garandeert geen selectie: de routeringsstrategie van de combinatie (bijvoorbeeld
last-known-good) kan de voorkeur geven aan een andere provider. Gebruik `dva/<model>` of een combinatie met Devin als
eerste keuze wanneer elk verzoek via Devin moet worden gerouteerd.

## Isolatie- en dreigingsmodel

De Claude-installatie, het account en de configuratie van de host vallen buiten het bereik en worden als
verboden beschouwd. De Compose-services:

- worden uitgevoerd met UID/GID `10001:10001`, met een alleen-lezen rootbestandssysteem, ingetrokken capabilities en
  `no-new-privileges`;
- gebruiken een privémap `/home/bridge`, een afzonderlijk Claude-configuratievolume, geïsoleerde OmniRoute-gegevens
  en een apart `devin-auth`-volume;
- koppelen uitsluitend tijdelijke `.sandbox`-werkruimten/bewijsbestanden;
- koppelen niet de thuismap van de host, Keychain, SSH, cloudreferenties of de Docker-socket;
- stellen expliciete omgevingen samen en verwijderen Anthropic API-/OAuth-/routeringsvariabelen;
- leiden Claude Code-inferentie uitsluitend naar `http://omniroute:20128` met een uitsluitend lokale sleutel.

Het offlineprofiel gebruikt een intern netwerk. In het liveprofiel bereikt OmniRoute de
officiële Devin-eindpunten uitsluitend via `network-guard`; niet-gerelateerde bestemmingen worden geweigerd.
Claude Code heeft een afzonderlijke egress-beveiliging die alles weigert en kan via `NO_PROXY` uitsluitend de lokale
OmniRoute-service bereiken. Auditbestanden van de beveiligingen worden alleen door hun eigen beveiligingsproces gekoppeld. De
scripts verifiëren bestandseigendom, modus, aantal links en elke beslissing voordat
tokenvrij bewijsmateriaal wordt geëxporteerd.

Voer het isolatiebewijs onafhankelijk uit:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Dit valideert de topologie, benoemde koppelingen, instellingen voor niet-root/alleen-lezen, expliciete lokale routering,
afwezigheid van gevoelige omgevingsvariabelen, afwezigheid van de Docker-socket, geblokkeerde toegang tot
`api.anthropic.com` en `claude.ai`, selectie van uitsluitend Devin als provider en expliciet falen wanneer
de ACP-backend niet beschikbaar is.

## Eerste installatie en normaal gebruik

Bouw de vastgepinde image:

```bash
./scripts/devin-bridge/build
```

Authenticeer uitsluitend het geïsoleerde Devin-volume:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

De aanmeldopdracht gebruikt de officiële handmatige tokenprocedure die bedoeld is voor externe/container-
omgevingen. De waarde wordt rechtstreeks bij de CLI-prompt ingevoerd; deze wordt niet als
procesargument doorgegeven, naar Git geschreven of vanaf de host gekopieerd.

Start de geïsoleerde Claude Code-runtime:

```bash
./scripts/devin-bridge/launch
```

`launch` controleert vóór het starten van de
gecontaineriseerde Claude Code opnieuw de isolatie, Devin-authenticatie en modeldetectie. Het voert nooit het Claude-programma van de host uit. Modelaliassen kunnen worden
ingesteld in `.env.devin-bridge`; elke geconfigureerde waarde moet het
voorvoegsel `devin-cli-agentic/` behouden.

## Validatieopdrachten

Het reproduceerbare offlinepad vereist geen Devin-account en heeft tijdens uitvoering geen internettoegang:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Het optionele, geauthenticeerde livepad is:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

De live-runner wacht tussen scenario's om te voorkomen dat ACP-sessies in een piek worden geopend en
valideert gestructureerde Claude-streamgebeurtenissen in plaats van tekstuele beweringen te vertrouwen. De drie
scenario's bewijzen:

1. rechtstreeks lezen van het project en analyse van defecten;
2. een echte `Edit`, een door de client beheerde `Bash`-uitvoering van `npm test` en een eindresultaat;
3. detectie van `/bridge-check` plus `bridge-proof`, het lezen van het project, nog een geslaagde
   door de client beheerde uitvoering van `npm test` en voltooiing zonder openstaand werk.

De laatste controle controleert ook de Devin-netwerkaudit en vereist dat de Claude-egress-audit
leeg blijft.

## Vastgezette tools bijwerken

De image zet Node, Claude Code en Devin CLI vast in
`docker/devin-bridge/Dockerfile`. Bijwerken:

1. wijzig de expliciete versies;
2. vervang beide architectuurspecifieke controlesommen van het Devin-archief door waarden voor het officiële
   artefact;
3. bouw opnieuw en voer elke offline validatieopdracht uit;
4. bevestig de versies in de image;
5. voer de geverifieerde live-suite met drie scenario's opnieuw uit.

Installeer geen van beide CLI's globaal op de host en vervang de controle op controlesommen niet door een
niet-geverifieerde download.

## Diagnose en opschoning

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  toont lokale routering en opgeschoonde executor-fouten.
- `.sandbox/evidence/mock-acp.jsonl` registreert deterministische mock-ACP-acties.
- `.sandbox/evidence/claude-stream.jsonl` registreert de echte offline-uitvoering van Claude Code.
- `.sandbox/evidence/live-*.jsonl` registreert de drie gevalideerde live-streams.
- `.sandbox/evidence/egress.jsonl` en `.sandbox/evidence/claude-egress.jsonl` zijn gevalideerde,
  tokenvrije kopieën van de guard-audits.

Stop de bijbehorende containers en netwerken, maar behoud de volumes voor aanmelding en configuratie:

```bash
./scripts/devin-bridge/clean
```

Verwijder de volledige omgeving die bij de bridge hoort, inclusief benoemde volumes:

```bash
./scripts/devin-bridge/clean --all
```

## Beperkingen

- De bridge is afhankelijk van de vaste `summarizer`-rol zonder tools, omdat Devin CLI `3000.2.17`
  geen neutrale ACP-agent zonder tools beschikbaar stelt. De adapter compenseert voor tussentijdse
  antwoorden in samenvattingsvorm, maar één begrensde herstelpoging kan nog steeds expliciet mislukken.
- Live ACP-aanroepen kunnen tijdelijke `502`-/`504`-antwoorden retourneren. De harness spreidt de scenario's;
  aanhoudende fouten blijven fail-closed en er wordt nooit een andere provider geselecteerd.
- De ACP-context wordt opnieuw opgebouwd vanuit elk Anthropic-verzoek; er is geen proces-/sessieaffiniteit.
- Per modelantwoord wordt één toolaanroep ondersteund; parallelle aanroepen worden geweigerd.
- Afbeeldingen worden expliciet niet ondersteund. Visie, thinking-uitvoer, inspanningsinstellingen en een
  contextvenster van 1M worden niet aangeboden.
- SSE gebruikt geldige Anthropic-lifecycle-events, maar wordt pas uitgezonden nadat de begrensde ACP-beurt is
  verzameld; ACP-chunks worden niet incrementeel doorgestuurd.
