تتيح `devin-cli-agentic` لبيئة تشغيل Claude Code الحقيقية استخدام نقطة نهاية رسائل Anthropic
المحلية في OmniRoute، بينما توفّر واجهة Devin CLI الرسمية استجابات النموذج عبر ACP stdio. وهي
لا تعدّل موفّري Anthropic أو Claude OAuth أو Claude Web أو `devin-cli` الحاليين.

بالنسبة إلى استدعاءات الأدوات المملوكة للعميل، وجّه الطلبات عبر `devin-cli-agentic` (بالاسم المستعار `dva`)، وهو
الموفّر الداعم للأدوات بتنسيق Claude. أما منفّذ ACP القديم `devin-cli` (`dv`) فهو
نصي فقط: إذ يشغّل ملخّص Devin من دون أدوات ولا يمكنه إرجاع استدعاءات أدوات. وقد وُسِمت بيانات
نموذجه الوصفية وفقًا لذلك، بحيث تتجنبه مسارات المجموعات التي تتطلب أدوات.

> **الحالة الحالية: إصدار Claude Code المثبّت هو `2.1.258`؛ وآخر تحقق مسجّل في وضعي عدم الاتصال
> والاتصال المباشر كان على `2.1.220`.** أكمل الإصدار المثبّت `2.1.220` ثلاثة سيناريوهات معزولة عبر Devin CLI
> `3000.2.17` والنموذج `swe-1-7-lightning`؛ وقد أثبت ذلك التشغيل المباشر النهائي نجاح دورات `Read`
> و`Edit` و`Bash` المملوكة للعميل، ونجاح نتائج `npm test`، واكتشاف أوامر المشروع ومهاراته،
> والتوجيه عبر Devin فقط، وانعدام أي حركة صادرة إلى Claude. بعد ذلك رُفع الإصدار المثبّت إلى `2.1.258`
> (وهو جيل CLI الذي تنتحل هوية Claude في OmniRoute هويته، وأول إصدار يوفّر
> فئة Fable 5.1 بشكل أصلي). في الإصدار المثبّت الجديد، جرى التحقق من طبقة التثبيت و`claude --version`
> على صورة الأساس المثبّتة، كما نجحت حزمة اختبارات الوحدة للجسر و`compose config` وإثبات
> العزل الثابت — لكن لم يُعَد بعد تشغيل سيناريو المحاكاة دون اتصال ولا حزمة السيناريوهات الثلاثة
> المباشرة. أعِد تشغيلها (راجع "تحديث الأدوات المثبّتة") قبل الاعتماد على الجسر مع هذا الإصدار المثبّت.

## البنية

```text
Claude Code 2.1.258 (حاوية Linux معزولة لمستخدم غير جذري)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (موفّر بتنسيق Claude ومن دون مصادقة)
  -> devin acp --agent-type summarizer (واجهة ACP stdio الرسمية، من دون أدوات Devin)
  -> حساب Devin في وحدة التخزين المخصصة devin-auth
```

يمكن لوكيل ACP الافتراضي في CLI الرسمية تنفيذ أدواته الخاصة، ولذلك لا يستخدم هذا الجسر
ذلك الوكيل. بل يبدأ وكيل ACP الثابت `summarizer`، الذي لا يحتوي وضع CLI الرسمي الخاص به على أدوات،
ويؤطّر طلب Anthropic المتسلسل على هيئة أثر تنفيذ. عندما يلزم إجراء آخر مملوك لـClaude،
يجب أن تحتوي الاستجابة على غلاف واحد بالضبط لأداة العميل. ويُرفض أي
`tool_call` أو `tool_call_update` من ACP قبل إمكان الإبلاغ عن نجاح الاستجابة.

يحافظ المُسلسِل في `open-sse/executors/devin-agentic/serializer.ts` على `system` و
`text` و`tool_use` و`tool_result` و`thinking` و`redacted_thinking` و`tool_choice` والأدوات
التي يوفّرها Claude Code. وتفشل الصور والكتل غير المعروفة بصورة صريحة. وتستخدم نتائج الأدوات
الكبيرة علامة اقتطاع مرئية.

يقبل المحلّل غلافًا مستقلاً واحدًا بالشكل `<tool>{...}</tool>` لكل دورة من النموذج. ويتحقق
من الاسم مقابل قائمة أدوات الطلب، ويتحقق من صحة الوسائط وفق مخطط JSON الخاص بتلك الأداة،
ويرفض المزج بين السرد والإجراءات، ويسمح بمحاولة إصلاح واحدة محدودة. بعد ذلك ينفّذ Claude Code
ناتج Anthropic المتمثل في `tool_use` محليًا، ويرسل `tool_result` مجددًا عبر
OmniRoute.

## التوجيه التلقائي

يكون الموفّر مؤهلاً للدخول في مجموعات المرشحين `auto/*` في OmniRoute عندما لا يكون محظورًا.
ولا تضمن أهلية المرشح اختياره: فقد تفضّل استراتيجية توجيه المجموعة (على سبيل المثال،
آخر خيار معروف بأنه صالح) موفّرًا آخر. استخدم `dva/<model>` أو مجموعة تمنح Devin الأولوية عندما
تحتاج إلى تمرير كل طلب عبر Devin.

## العزل ونموذج التهديدات

يُعد تثبيت Claude على المضيف وحسابه وإعداداته خارج النطاق، ويُتعامل معها على أنها
محظورة. خدمات Compose:

- تعمل باستخدام UID/GID بالقيمة `10001:10001`، مع نظام ملفات جذري للقراءة فقط، وإسقاط الإمكانات، وتفعيل
  `no-new-privileges`؛
- تستخدم `/home/bridge` خاصًا، ووحدة تخزين مخصصة لإعدادات Claude، وبيانات OmniRoute معزولة،
  ووحدة تخزين منفصلة باسم `devin-auth`؛
- لا تُركّب سوى مساحات عمل/أدلة `.sandbox` القابلة للتخلص منها؛
- لا تُركّب الدليل الرئيسي للمضيف، أو Keychain، أو بيانات اعتماد SSH أو الخدمات السحابية، أو مقبس Docker؛
- تُنشئ بيئات صريحة وتزيل متغيرات Anthropic الخاصة بواجهة API وOAuth والتوجيه؛
- توجّه استدلال Claude Code حصريًا إلى `http://omniroute:20128` باستخدام مفتاح محلي فقط.

يستخدم ملف التعريف غير المتصل شبكة داخلية. في ملف التعريف المباشر، يصل OmniRoute إلى
نقاط نهاية Devin الرسمية فقط عبر `network-guard`؛ وتُحظر الوجهات غير ذات الصلة.
يمتلك Claude Code حارس خروج منفصلًا يمنع كل الاتصالات، ولا يمكنه الوصول إلا إلى خدمة OmniRoute
المحلية عبر `NO_PROXY`. لا تُركّب ملفات تدقيق الحراس إلا من خلال عملية الحارس الخاصة بها. تتحقق
البرامج النصية من ملكية الملفات، ووضعها، وعدد روابطها، وكل قرار قبل تصدير
أدلة خالية من الرموز المميزة.

شغّل إثبات العزل بشكل مستقل:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

يتحقق هذا من الطوبولوجيا، ووحدات التركيب المسماة، وإعدادات التشغيل دون صلاحيات الجذر/للقراءة فقط، والتوجيه المحلي
الصريح، وغياب متغيرات البيئة الحساسة، وغياب مقبس Docker، وحظر الوصول إلى
`api.anthropic.com` و`claude.ai`، واختيار موفّر Devin فقط، والفشل الصريح عندما
لا تكون الواجهة الخلفية لـ ACP متاحة.

## الإعداد لأول مرة والاستخدام المعتاد

أنشئ الصورة المثبّتة الإصدار:

```bash
./scripts/devin-bridge/build
```

صادِق فقط على وحدة تخزين Devin المعزولة:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

يستخدم أمر تسجيل الدخول تدفق الرمز المميز اليدوي الرسمي والمخصص لبيئات
الحاويات/البيئات البعيدة. تُدخل القيمة مباشرةً في مطالبة CLI؛ ولا تُمرر كوسيطة
للعملية، ولا تُكتب إلى Git، ولا تُنسخ من المضيف.

شغّل بيئة تشغيل Claude Code المعزولة:

```bash
./scripts/devin-bridge/launch
```

يعيد `launch` التحقق من العزل، ومصادقة Devin، واكتشاف النماذج قبل تشغيل
Claude Code داخل الحاوية. ولا يشغّل مطلقًا ملف Claude التنفيذي الخاص بالمضيف. يمكن تعيين
الأسماء المستعارة للنماذج في `.env.devin-bridge`؛ ويجب أن تحتفظ كل قيمة مُعدّة
بالبادئة `devin-cli-agentic/`.

## أوامر التحقق

لا يتطلب المسار غير المتصل القابل لإعادة الإنتاج حساب Devin، ولا يتضمن اتصالًا بالإنترنت وقت التشغيل:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

المسار المباشر الموثّق والمشروط بالاشتراك هو:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ينتظر مشغّل الاختبارات المباشرة بين السيناريوهات لتجنب فتح جلسات ACP على دفعات،
ويتحقق من أحداث تدفق Claude المهيكلة بدلًا من الوثوق بالادعاءات النصية. وتُثبت
سيناريوهاته الثلاثة ما يلي:

1. القراءة المباشرة للمشروع وتحليل العيوب؛
2. تنفيذ `Edit` حقيقي، وتشغيل `Bash` `npm test` مملوك للعميل، والحصول على نتيجة نهائية؛
3. اكتشاف `/bridge-check` و`bridge-proof`، وقراءة المشروع، وتشغيل
   `npm test` آخر ناجح ومملوك للعميل، والإكمال دون عمل معلّق.

تتحقق البوابة النهائية أيضًا من تدقيق شبكة Devin، وتشترط أن يظل تدقيق خروج Claude
فارغًا.

## تحديث الأدوات المثبّتة بإصدارات محددة

تثبّت الصورة إصدارات Node وClaude Code وDevin CLI في
`docker/devin-bridge/Dockerfile`. للتحديث:

1. غيّر الإصدارات المحددة صراحةً؛
2. استبدل قيمتي المجموع الاختباري لأرشيف Devin الخاصتين بالمعماريتين بقيم الأثر الرسمي؛
3. أعد البناء وشغّل جميع أوامر التحقق دون اتصال؛
4. تحقّق من الإصدارات داخل الصورة؛
5. أعد تشغيل مجموعة الاختبارات المباشرة الموثّقة المكوّنة من ثلاثة سيناريوهات.

لا تثبّت أيًا من أداتي CLI تثبيتًا عامًا على المضيف، ولا تستبدل التحقق من المجموع الاختباري
بتنزيل لم يتم التحقق منه.

## التشخيص والتنظيف

- يعرض `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  التوجيه المحلي وأخطاء المنفّذ المنقّحة.
- يسجّل `.sandbox/evidence/mock-acp.jsonl` إجراءات ACP الوهمية الحتمية.
- يسجّل `.sandbox/evidence/claude-stream.jsonl` تشغيل Claude Code الحقيقي دون اتصال.
- تسجّل `.sandbox/evidence/live-*.jsonl` التدفقات المباشرة الثلاثة التي تم التحقق منها.
- يُعدّ `.sandbox/evidence/egress.jsonl` و`.sandbox/evidence/claude-egress.jsonl` نسختين تم التحقق
  منهما وخاليتين من الرموز المميزة لعمليات تدقيق الحماية.

أوقف الحاويات والشبكات المملوكة مع الاحتفاظ بوحدات تخزين تسجيل الدخول/الإعدادات:

```bash
./scripts/devin-bridge/clean
```

أزل البيئة الكاملة المملوكة للجسر، بما في ذلك وحدات التخزين المسماة:

```bash
./scripts/devin-bridge/clean --all
```

## القيود

- يعتمد الجسر على دور `summarizer` الثابت الذي لا يستخدم أدوات، لأن Devin CLI `3000.2.17`
  لا يوفّر وكيل ACP محايدًا بلا أدوات. يعوّض المهايئ عن الاستجابات الوسيطة المصاغة كملخصات،
  لكن قد تظل محاولة إصلاح واحدة محدودة تفشل بشكل صريح.
- قد تُرجع استدعاءات ACP المباشرة استجابات `502`/`504` عابرة. تفصل أداة الاختبار بين السيناريوهات؛
  ويظل الفشل المستمر مغلقًا بشكل آمن ولا يختار مزوّدًا آخر مطلقًا.
- يُعاد إنشاء سياق ACP من كل طلب Anthropic؛ ولا يوجد ارتباط بالعملية/الجلسة.
- يُدعم استدعاء أداة واحد لكل استجابة من النموذج؛ وتُرفض الاستدعاءات المتوازية.
- الصور غير مدعومة صراحةً. ولا يُعلَن عن الرؤية أو مخرجات التفكير أو عناصر التحكم في الجهد أو
  نافذة سياق بحجم 1M.
- يستخدم SSE أحداث دورة حياة Anthropic صالحة، لكنه يُرسَل بعد جمع دورة ACP المحدودة؛
  ولا تُمرَّر أجزاء ACP تدريجيًا.
