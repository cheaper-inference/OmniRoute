> **آخر تحديث:** 2026-09-02 — v3.8.51
> **الجمهور المستهدف:** المهندسون المسؤولون عن صيانة عمليات التكامل التخفيّة الخاصة بكل مزوّد.

يتكامل OmniRoute مع مزوّدين تعمل واجهاتهم الطرفية على أخذ بصمات نشطة للعملاء غير الرسميين (TLS JA3/JA4، وترتيب الترويسات، وبنية جسم JSON، ورموز التكامل). توثّق هذه الصفحة أسطح التخفي التي يتيحها OmniRoute ومواضع تنفيذها.

## إشعار قانوني وأخلاقي

توجد ميزات التخفي لكي يتمكن OmniRoute من العمل كطبقة توافق بين الحسابات الرسمية المملوكة للمستخدمين (Claude Code CLI، وCodex، وAntigravity، وCursor، وغيرها) وواجهة API الموحّدة لـ OmniRoute. وهي **ليست** مخصّصة للتحايل على اكتشاف الاحتيال، أو مشاركة بيانات الاعتماد، أو انتهاك شروط خدمة المزوّد. يتوقع المشرفون من المشغّلين الالتزام بشروط خدمة الجهات المنبع التي وافقوا عليها عند إنشاء الحسابات.

## طبقة بصمة TLS

### `open-sse/utils/tlsClient.ts` — wreq-js ‏(Chrome 124)

تُنشأ جلسات `wreq-js` الدائمة بشكل كسول لكل نطاق حساب ووكيل محلول. يحتفظ `TlsClient` على مستوى العملية بتجمّع لا يتجاوز 128 جلسة تنتحل شخصية **Chrome 124 على macOS** للوجهات الأصلية الموجودة خلف Cloudflare. يفشل `TlsClient.fetch()` بشكل مغلق عندما تكون بيئة التشغيل الأصلية غير متاحة؛ ويمكن للمستدعي تحديد خيار احتياطي صراحةً خارج هذا المغلّف.

- ملف تعريف الجلسة: `browser: "chrome_124", os: "macos"`
- تحليل الوكيل (حسب الأولوية): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (وكذلك الصيغ ذات الأحرف الصغيرة)
- المهلة: `TLS_CLIENT_TIMEOUT_MS` (ترث من `FETCH_TIMEOUT_MS`، والقيمة الافتراضية 600000)
- استجابة `wreq-js` متوافقة مع fetch ‏(`headers`، و`text()`، و`json()`، و`clone()`، و`body`).
- مراقب البايت الأول (`open-sse/utils/tlsFirstByteWatchdog.ts`، ‏#12656): يُحلّ `TlsClient.fetch()`
  بمجرد وصول ترويسات الوجهة الأصلية، ولذلك لا يستطيع `TLS_CLIENT_TIMEOUT_MS` وحده تقييد جسم
  لا يُنتج بايته الأول مطلقًا. يجعل `guardTlsFirstByte()` أول استدعاء `read()` للجسم في سباق
  مع `TLS_FIRST_BYTE_WATCHDOG_MS` (القيمة الافتراضية `10000`، وتؤدي القيمة `0` إلى تعطيله)؛ ولا يتأثر
  الجسم السليم، بينما يؤدي الجسم المتوقف إلى إلغاء قارئ wreq ويسمح لمنطق الرجوع الاحتياطي الحالي لـTLS
  في `proxyFetch` بالانتقال إلى موزّع الاتصال المباشر/الوكيل (أما الطلب غير الآمن لإعادة التشغيل، مثل
  طلب POST ذي جسم، فسيظل يطرح خطأً بدلًا من إعادة محاولته بصمت).

### نقل موفّر ملفات تعريف ارتباط الويب — wreq-js 3.2.0

يمثّل `open-sse/services/tlsClientBase.ts` المهايئ المشترك لوسائل نقل ملفات تعريف ارتباط الويب
الخمس المتخصصة أدناه. يحدد كل مغلّف رفيع خاص بموفّر ملف تعريف للمتصفح/نظام التشغيل. يستخدم المهايئ
محمّل بيئة تشغيل wreq الوحيد وتجمّع النقل في `open-sse/utils/tlsClient.ts`، مع الفهرسة حسب
ملف التعريف + نظام التشغيل + الوكيل المحلول، بينما يستخدم كل طلب `cookieMode: "ephemeral"`. لذلك
تتشارك الحسابات والطلبات الاتصالات على مستوى النقل، لكنها لا تتشارك أبدًا جلسة wreq أو مخزن ملفات تعريف الارتباط.

| الموفّر    | ملف التعريف   | نظام التشغيل المُحاكى | سياسة نهاية تدفق EOF                         |
| ---------- | ------------- | --------------------- | -------------------------------------------- |
| Claude     | `chrome_146`  | Linux                 | تضمين `[DONE]`                               |
| Perplexity | `firefox_151` | macOS                 | تضمين `event: end_of_stream`                 |
| Grok       | `chrome_146`  | Linux                 | استبعاد `[DONE]`                             |
| Notion     | `chrome_146`  | Windows               | تضمين `[DONE]`                               |
| LMArena    | `chrome_146`  | Windows               | لا توجد علامة ختامية؛ الإغلاق عند EOF الأصلي |

- يستهلك البث `ReadableStream` الخاص بالاستجابة الأصلية مباشرةً؛ ولا يُنشأ أي ملف مؤقت أو عملية
  جانبية.
- يُفحص ما يصل إلى 256 بايتًا أوليًا قبل إتاحة التدفق. تخزّن موفّرات SSE أخطاء غير SSE مؤقتًا؛
  ويربط Grok/LMArena تحديات Cloudflare بالحالة `403` وصفحات HTML البينية بالحالة `502`.
- تظل مهلة الطلب الأصلية مغلّفة بموعد نهائي صارم ومطلق في JS. يؤدي التعليق إلى إبطال وإغلاق
  وسيلة النقل المتأثرة فقط لملف التعريف/نظام التشغيل/الوكيل قبل أن يعيد الطلب التالي إنشاءها.
- تكون أولوية تحليل الوكيل لكل استدعاء كما يلي: `proxyUrl` → سياق الحساب/لوحة المعلومات الخاص بالطلب →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (بما في ذلك الصيغ ذات الأحرف الصغيرة). تفشل أخطاء التحليل
  بشكل مغلق بدلًا من تسريب اتصال مباشر. يتعمد LMArena إجراء التحليل مقابل `arena.ai`.
- يعيد `byteResponse` عنوان URL من النوع `data:` ومحددًا بنوع المحتوى من دون إتلاف UTF-8.
- الأخطاء هي `TlsClientUnavailableError` (الحزمة/الملحق غير متاح)، و`TlsClientHangError`
  (تجاوز الموعد النهائي)، و`WreqTransportCapacityError` (رمز خطأ سعة الجلسة المشتركة)
  عندما تكون جميع خانات ملف التعريف/نظام التشغيل/الوكيل المحدودة البالغ عددها 128 نشطة أو قيد الإغلاق.

تظل جلسة `TlsClient` العامة أعلاه متخصصة في حالة ملفات تعريف الارتباط الدائمة والمدعومة بالمتصفح.
يعيد كلا المسارين استخدام محمّل واحد مخزّن مؤقتًا لوحدة wreq وخطاف دورة حياة العملية؛ بينما تظل
تجمّعاتهما منفصلة لأن مدد صلاحية ملفات تعريف الارتباط الخاصة بهما مختلفة عمدًا.

تدعم الحزمة المثبّتة ملفات التعريف، لكن قبول WAF الفعلي يمكن أن يتغير بصورة مستقلة عن اختبارات
العقد المحلية. تحقّق من تغييرات البصمة باستخدام حساب فعلي مصرّح به صراحةً قبل الادعاء بالتكافؤ
مع متصفح الوجهة الأصلية.

## حزمة Claude Code Stealth

عند تشغيل `cliCompatMode` ، يعيد OmniRoute تشكيل طلبات Claude الصادرة بحيث لا يمكن تمييزها عن حركة مرور `claude-cli`. تتعاون ثلاث وحدات:

### `claudeCodeFingerprint.ts`

يحسب بصمة 3-char `cc_version` المضمنة في رأس الفاتورة:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (مشفر؛ يطابق العميل الرسمي)
- المدخلات: الأحرف في الفهرس 4، 7، 20 من نص رسالة المستخدم الأول سلسلة إصدار +
- الإخراج: بادئة سداسية عشرية ذات 3 أحرف

### `claudeCodeCCH.ts` (تجزئة محتوى العميل)

التحقق من سلامة جانب الخادم من حساب Claude Code الرسمي CLI عبر عمليات إعادة تنفيذ Bun/Zig. OmniRoute باستخدام `xxhash-wasm`:

1. تسلسل النص باستخدام العنصر النائب `cch=00000;`
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. حرف سداسي صغير مكون من 5 أحرف مبطنة بصفر
4. استبدل `cch=00000;` بالرمز المميز المحسوب

الثوابت:

- البذرة : `0x6e52736ac806831e`
- النمط: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

إدراج Unicode** نجار العرض صفر** (`U+200D`) بعد الحرف الأول من أسماء العملاء "الحساسة" حتى لا تتمكن عوامل التصفية الأولية من استيعابها. قائمة الكلمات الافتراضية:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

يتم تطبيقه على: كتل `system` ، وجميع `messages[].content`، و `tools[].description` / `tools[].function.description`. يمكن تجاوز عامل التشغيل عبر `setSensitiveWords()`.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*`

بالنسبة لمرحلات Anthropic التابعة لجهات خارجية والتي تقبل فقط حركة مرور "رمز Claude الحقيقي":

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"` بشكل افتراضي
- يضيف مفتاح التبديل "تمكين الإصدار التجريبي من التفكير المنقح" `redact-thinking-2026-02-12` عندما يتطلب المنبع المتوافق مع CC على وجه التحديد تدفقات تفكير منقحة
- يقوم "تمكين عرض التفكير الملخص" لكل اتصال بتبديل تخزين `providerSpecificData.requestDefaults.summarizeThinking` وإضافة `display: "summarized"` إلى طلبات التفكير المتوافقة CC التي لم تقم بالفعل بتعيين وضع عرض
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (عائلة Opus/Sonnet 4.x)
- المسار الافتراضي: `/v1/messages?beta=true`

الوحدات الشقيقة في نفس الحزمة:

- `claudeCodeConstraints.ts` — درجة الحرارة قواعد التحكم في ذاكرة التخزين +
- إعادة تعيين اسم أداة `claudeCodeToolRemapper.ts` —
- `claudeCodeExtraRemap.ts` — تطبيع الحمولة الإضافية

## Antigravity التخفي

تحافظ طلبات Antigravity على نص المتصل بالبايت مقابل البايت. لا يقوم OmniRoute بإدراج أحرف ذات عرض صفري في المطالبات أو أدوات rename/inject لتقليد عميل IDE.

### `antigravityHeaderScrub.ts`

شرائط علامات SDK غير القابل للصدأ (`x-stainless-lang`، `x-stainless-package-version`، `x-stainless-os`، `x-stainless-arch`، `x-stainless-runtime`، `x-stainless-runtime-version`، `x-stainless-timeout`، `x-stainless-retry-count`، `x-stainless-helper-method`) قبل إعادة التوجيه.

### ⚠️ Risk: `ANTIGRAVITY_CREDITS=always` (نقطة ساخنة لحظر الحساب)

طرق `ANTIGRAVITY_CREDITS=always` (التي يستهلكها `open-sse/executors/antigravity.ts`).** كل** اطلب من خلال Antigravity AI Credit Overages (أرصدة Google المدفوعة) بدلاً من السماح لحصص Google ذات الطبقة المجانية ببوابة الأشياء. تم توثيق هذا كميزة، لكنه كذلك** تقرير انتهاك شروط الخدمة الأكثر شيوعًا الذي نراه** — تم حظر حسابات Google Ultra المتعددة باستخدام `403 / "service disabled for ToS violation" / insufficient_quota` بعد تشغيلها لبضع ساعات باستخدام `=always`.

الإنفاذ المنبع قيد التشغيل** جانب Google** ، لا شيء يمكن أن يمنعه OmniRoute. يجعل اسم env var والمستندات الموجودة الأمر يبدو وكأنه مقبض آمن يمكن قلبه؛ ليس كذلك.

**لماذا يؤدي هذا إلى جذب اكتشاف إساءة الاستخدام بقوة أكبر من استخدام الطبقة المجانية فقط:**

- يشير الإنفاق الآلي المستدام على حساب Google واحد بشكل مختلف عن حصص مرات الدخول والتوقف في الطبقة المجانية.
- ليس لتجاوزات الائتمان حد أقصى للسعر، لذلك يمكن للعميل الذي تم تكوينه بشكل خاطئ حرق عدة مئات USD في دقائق ويبدو وكأنه إعادة بيع مفتاح واجهة برمجة التطبيقات أو حركة مرور الروبوت.
- يؤدي ضرب العديد من مستخدمي OmniRoute إلى أرصدة زائدة بالتوازي من نفس IP الخارجي إلى تفاقم الإشارة.

**الموقف الموصى به:**

1. احتفظ بـ `ANTIGRAVITY_CREDITS=off` الافتراضي ما لم يقبل المشغل صراحةً مخاطر الائتمان المدفوع وإنفاذ الحساب. يرسل `retry` الطلب العادي أولاً ويدخل الاعتمادات مرة واحدة على الأكثر بعد الحصة المؤهلة 429؛ تقوم `always` بحقن الاعتمادات عند الطلب الأول.
2. **قم بتوزيع الحمل عبر مقدمي الخدمة عبر التحرير والسرد التلقائي** (`model: "auto"` أو `kr/glm/etc` -combo) بدلاً من تشبع حساب Antigravity واحد.
3. **تعيين حدود RPM لكل اتصال** في صفحة تحرير موفر Antigravity (موفرو → للوحة المعلومات → Antigravity → حد معدل اتصال → ). 30-60 RPM هو الحد الأعلى الذي يمكن الدفاع عنه للاستخدام المستمر.
4. **استخدم شبكات المنبع المستقرة التي يتحكم فيها المشغل** وتجنب مشاركة حساب واحد عبر مستخدمين أو أحمال عمل غير مرتبطة.
5. **إذا حظرت** : الاستئناف عبر `support.google.com` → "استعادة الوصول Workspace/Account " مع إرسال نص استجابة `quota_exceeded` / `service disabled` الدقيق Google. الاستعادة ليست مضمونة.

يوثق مرجع البيئة آثار الحساب والإنفاق لكل وضع من أوضاع الاعتمادات.

#### ليس فقط `=always`: توجيه Antigravity OAuth بشكل عام

ولا يقتصر التعليق على تجاوزات الائتمان. تصف التقارير الواردة في نوفمبر 2026 (#19223, #19266) العديد من حسابات Google التي تم تعليقها أثناء التوجيه عبر `antigravity` و `agy` (Antigravity CLI)، مع:

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

يقوم كلا الموفرين بالمصادقة مع جلسة منتج Antigravity OAuth ، وهذه هي الحالة التي يحذر منها إشعار المخاطر الخاص بلوحة المعلومات ("يستخدم هذا الموفر منتجك الرسمي session/OAuth، وهو غير مصرح له باستخدام proxy/router ") قبل إضافة الاتصال. لا تسمح أي من التوصيات المذكورة أعلاه بهذا الاستخدام؛ فهي تقلل فقط من مقدار حركة المرور التي يحملها حساب واحد.

**واجهات API المعتمدة لنماذج Gemini.** يوفر Google وصولًا برمجيًا إلى Gemini من خلال APIs، والذي يدعمه OmniRoute كموفري مفاتيح API عاديين:

| معرف المزود | اسم لوحة القيادة            | بيانات الاعتماد                                                           |
| ----------- | --------------------------- | ------------------------------------------------------------------------- |
| `gemini`    | Gemini (استوديو Google AI ) | مفتاح Gemini API من Google AI Studio (الطبقة المجانية متاحة)              |
| `vertex`    | فيرتكس AI                   | حساب الخدمة JSON أو رمز الوصول OAuth أو مفتاح Vertex Express API (Gemini) |

يستخدم هؤلاء الموفرون مشكلات بيانات الاعتماد Google للوصول إلى API ، على عكس جلسة منتج Antigravity. فهي لا تجعل كل استخدام متوافقًا أو تزيل مخاطر التنفيذ: فكل منها تحكمه شروطه الخاصة، والتي يجب على المشغل التحقق من نشرها. على سبيل المثال، تسمح [شروط الخدمة الإضافية لـ Gemini API](https://ai.google.dev/gemini-api/terms) بالخدمات المدفوعة فقط عندما يتم توفير عملاء API للمستخدمين في المنطقة الاقتصادية الأوروبية أو سويسرا أو المملكة المتحدة، ويمكن استخدام المحتوى المرسل إلى الخدمات غير المدفوعة لتحسين منتجات Google. تندرج Vertex AI ضمن شروط Google Cloud بدلاً من ذلك ( [شروط الخدمة الخاصة](https://cloud.google.com/terms/service-terms) ). تتبع الأسعار والحصص شروط API هذه بدلاً من اشتراك Antigravity.

يجب على المشغلين الذين يرغبون في تجنب عمليات تعليق Antigravity الموضحة أعلاه توجيه حركة مرور Gemini عبر أحد هؤلاء المزودين بدلاً من `antigravity` / `agy`، بعد التحقق من أن استخدامهم يتوافق مع شروط المزود.

نقاط اللمس:

- `open-sse/executors/antigravity.ts` — يقرأ `process.env.ANTIGRAVITY_CREDITS`
- `src/lib/oauth/providers/antigravity.ts` — السباكة الاعتماد
- تقرير الحادث الأصلي: مناقشة [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## سجل بصمات CLI — `open-sse/config/cliFingerprints.ts`

جدول خاص بكل مزوّد يثبّت الترتيب **الدقيق** للترويسات وترتيب حقول جسم JSON، كما جرى التقاطهما من سجلات mitmproxy الخاصة بأدوات CLI الرسمية. الأدوات المسجّلة حاليًا: `codex` و`claude`، بالإضافة إلى ملفات التعريف المشتقة في وقت التشغيل ضمن `providerHeaderProfiles.ts` لكل من `antigravity` و`github`.

```ts
interface CliFingerprint {
  headerOrder: string[]; // حساس لحالة الأحرف
  bodyFieldOrder: string[]; // مفاتيح JSON ذات المستوى الأعلى
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

يمكن التبديل لكل مزوّد عبر متغيرات البيئة (انظر أدناه). عند التعطيل، تظهر الترويسات/مفاتيح الجسم بأي ترتيب يوفّره Node/JSON — ما يجعل اكتشاف البصمة سهلًا.

## وكيل MITM ‏(Antigravity، وLinux/macOS/Windows)

بالنسبة إلى أدوات CLI التي لا يمكن إعادة توجيه ملفاتها التنفيذية عبر `OPENAI_BASE_URL`، يشغّل OmniRoute وكيلًا محليًا ينهي اتصال TLS. توجد نقاط النهاية ضمن `src/app/api/cli-tools/antigravity-mitm/`.

| الطريقة | نقطة النهاية                            | الغرض                                            |
| ------- | --------------------------------------- | ------------------------------------------------ |
| GET     | `/api/cli-tools/antigravity-mitm`       | الحالة — التشغيل، pid، dnsConfigured، certExists |
| POST    | `/api/cli-tools/antigravity-mitm`       | بدء MITM (يتطلب `apiKey` + `sudoPassword`)       |
| DELETE  | `/api/cli-tools/antigravity-mitm`       | إيقاف MITM                                       |
| GET     | `/api/cli-tools/antigravity-mitm/alias` | عرض الأسماء البديلة للنماذج                      |
| PUT     | `/api/cli-tools/antigravity-mitm/alias` | حفظ الأسماء البديلة للنماذج لأداة                |

المضيف المستهدف اعتراضه: **`daily-cloudcode-pa.googleapis.com`** (الخادم الرئيسي لـ Antigravity).

### تسلسل البدء (`src/mitm/manager.ts::startMitm`)

1. إنشاء شهادة موقّعة ذاتيًا عبر `selfsigned` ‏(RSA-2048، SHA-256، سنة واحدة) — `cert/generate.ts`
2. تثبيت الشهادة في مخزن الثقة الخاص بالنظام — `cert/install.ts`
3. إضافة إدخال المضيفين `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. تشغيل `src/mitm/server.cjs` مع `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (القيمة الافتراضية `443`)
5. حفظ PID في `<DATA_DIR>/mitm/.mitm.pid`

### الاكتشاف الديناميكي لمخزن الثقة في Linux — `cert/install.ts`

تمرّ الدالة `getLinuxCertConfig()` عبر قائمة أولويات وتختار أول دليل موجود:

| عائلة التوزيعة           | الدليل                                      | أمر التحديث              |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

اسم ملف الشهادة: `omniroute-mitm.crt`. تتم مطابقة البصمة عبر `getCertFingerprint()` ‏(SHA-1 لبيانات DER).

بالإضافة إلى ذلك، تثبّت `updateNssDatabases()` الشهادة في قواعد بيانات NSS الخاصة بكل مستخدم عندما تكون `certutil` متاحة: `~/.pki/nssdb`، و`~/snap/chromium/.../nssdb`، وجميع ملفات تعريف Firefox (بما فيها snap)، تحت الاسم المستعار **`OmniRoute MITM Root CA`**.

### macOS / Windows

- **macOS:** ‏`security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** ‏PowerShell بصلاحيات مرتفعة → `certutil -addstore Root`

### المصادقة

تتطلب جميع نقاط نهاية MITM مصادقة إدارية (`requireCliToolsAuth`). تُخزّن كلمة مرور sudo مؤقتًا ضمن نطاق الوحدة (وليس في `globalThis` مطلقًا)، وتُمسح عند استدعاء `stopMitm()`.

## تحديث البصمات عندما يغيّرها المزوّد

1. التقط حركة مرور CLI الرسمية باستخدام `mitmproxy` (اعتراض TLS + تفريغ)
2. استخرج JA3/JA4 والترتيب الحرفي للترويسات
3. حدّث إدخال `CLI_FINGERPRINTS[...]` ذي الصلة
4. حدّث القيمة الافتراضية المطابقة لـ `*_USER_AGENT` في `.env.example`
5. إذا تغيّرت مصافحة TLS نفسها، فحدّث غلاف المزوّد ذي الصلة أو خيار `browser:` في wreq-js
6. شغّل اختبارات TLS الخاصة بالمزوّد واختبار كناري يدويًا مقابل المزوّد الفعلي
7. انشر ضمن إصدار تصحيحي؛ ووثّق ذلك في `CHANGELOG.md`
