تنشر OmniRoute عناصر npm + Docker. توفر هذه البوابات إثبات المنشأ، وجرد المكونات البرمجية (SBOM)، وفحص CVE، وكلها مفتوحة المصدر (OSS)، ومدمجة في سير عمل الإصدار.
نهج **استشاري أولاً** — يتم الإبلاغ عنها الآن، ثم يتم ترقيتها إلى حظر بعد الإصدار الأخضر الأول.

| البوابة               | الأداة                                         | المكان                        | هل تحظر؟            | المخرجات                                        |
| --------------------- | ---------------------------------------------- | ----------------------------- | ------------------- | ----------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | فقط إذا فشل النشر   | شارة npmjs / `npm audit signatures`             |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | فقط إذا فشل التوليد | أصل الإصدار + عنصر                              |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | استشاري             | عنصر CycloneDX                                  |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | استشاري             | SARIF (عالي+حرج) ← علامة تبويب الأمان           |
| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **حظر**             | `exit-code: '1'` عند وجود CRITICAL قابل للإصلاح |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **حظر**             | تعدل `metrics.vulnCount` (الاتجاه: تنازلي)      |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | استشاري             | SARIF ← الأمان + شارة                           |

يستخدم نظام تعديل CVE للصور **خطوتين** في `docker-publish.yml`: خطوة SARIF (`HIGH,CRITICAL`، `exit-code: 0`) تبقي HIGH+CRITICAL مرئية في علامة تبويب الأمان دون حظر؛ خطوة _بوابة CRITICAL_ (`severity: CRITICAL`، `ignore-unfixed: true`، `exit-code: 1`) تفشل الإصدار عند وجود CVE حرج **مع توفر إصلاح**. تمنع `ignore-unfixed` حظر الإصدار بسبب CVE في الصورة الأساسية بدون تصحيح من المصدر.

## ⚠️ تفاوت CVE (بوابات osv/Trivy مانعة)

يقارن osv وTrivy التبعيات بقواعد بيانات CVE التي **تنمو باستمرار**. يمكن أن يتحول طلب سحب
لا **يغيّر أي تبعيات** فجأةً إلى حالة فشل بسبب الإفصاح عن CVE جديد
في تبعية موجودة (osv: تجاوز قيمة `vulnCount` المقاسة لخط الأساس؛ Trivy: وجود ثغرة CRITICAL
جديدة قابلة للإصلاح في الصورة). **هذا سلوك تشغيلي متوقع لبوابة CVE مانعة،
وليس تراجعًا في المنتج.**

عندما يفشل osv أو Trivy بسبب CVE أُفصح عنه حديثًا، يكون الحل كما يلي:

1. **حدّث التبعية المتأثرة** (الخيار المفضّل) — رقِّها إلى الإصدار المصحّح عبر `package.json`
   و`overrides` (للتبعيات المتعدية)، أو أعد بناء الصورة باستخدام صورة أساسية مصحّحة.
2. **إذا لم يتوفر إصلاح من المصدر:**
   - **osv:** أعد تعيين خط أساس `metrics.vulnCount` في `config/quality/quality-baseline.json`
     (لا يشمل `npm run quality:ratchet -- --update` البوابات المخصصة — عدّل القيمة
     يدويًا، مع `direction:down`) مع ملاحظة تبرير + مشكلة للتتبع.
   - **Trivy:** أضف إدخالًا إلى `.trivyignore` (معرّف CVE واحد في كل سطر) مع تعليق
     يوضح التبرير + مشكلة للتتبع. يغطي `ignore-unfixed: true` بالفعل تلقائيًا حالات CVE
     التي لا تتوفر لها تصحيحات.

تفشل عمليات تنفيذ OSV المطلوبة (`check:vuln-ratchet -- --ratchet`) وفق مبدأ الإغلاق الآمن بالحالة
`INCOMPLETE` ورمز الخروج 2 عندما يتعذر التحقق من أداة الفحص أو التقرير أو خط الأساس.
أما التراجع المقاس فيُرجع رمز الخروج 1. ولا يزال بإمكان التنفيذ الاستشاري الإبلاغ عن `SKIP`
مع رمز الخروج 0، وهذا لا يثبت أن التبعيات اجتازت الفحص. تتطلب خطوة
Trivy المانعة أيضًا قياسًا ناجحًا: فلا يمكن للأدوات غير المتاحة أو المهام الفاشلة
أو أدلة الصورة المفقودة اعتماد الصورة على أنها خالية من الثغرات.

## مخاطر الاعتماد المتقاعد

لم يعد ملف القفل الجذري يتضمن `extract-zip` أو حافة اعتماد تؤدي إليه بعد
ترقية أداة التطوير promptfoo ذات الإصدار المثبّت. يؤدي ذلك إلى إيقاف سلسلة
`promptfoo` → `@openai/codex-security` → `extract-zip` المقبولة سابقًا والمتتبعة في #14482.
ترفض فحوصات الانحدار في `tests/unit/extract-zip-14482-exposure.test.ts` إعادة
إدخالها، وتُبقي الحظر المفروض على عمليات الاستيراد من كود الإنتاج.

يقصر إصلاح الاعتماد الحالي أيضًا تجاوزات التوافق على عميل MSAL الخاص بـ Azure identity،
وعميل FTP الخاص بـ get-uri، واعتماد Zod الخاص بـ OpenCode v1 SDK. يُختبر الحصول على رموز
Azure والاسترداد عبر FTP باستخدام وسائل نقل خاضعة للتحكم؛ وتُشغّل كلتا حزمتي OpenCode
مجموعتي البناء والاختبار الخاصتين بهما. تمثل أعداد تحذيرات السجل قياسات في نقطة زمنية
محددة، وقد تتغير بعد إيداع ملف القفل.
