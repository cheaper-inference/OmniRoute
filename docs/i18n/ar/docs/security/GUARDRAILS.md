> المسارات ومسارات الاستجابة التي تصل إليها الخطافات، وترويسات التعطيل المدمجة (#16412)،
> ووضع حظر الحقن كحدّ إلزامي (#16413)، وما يرى الاستجابة قبل مرحلة ما بعد الاستدعاء)

تفرض حواجز الحماية تحويلات السلامة والسياسات والمحتوى عند الحدود
بين OmniRoute والمزودين الأصليين. يستطيع كل حاجز حماية فحص
(ورفض أو تحويل أو توصيف، اختياريًا) حمولات الطلبات (`preCall`)
واستجابات المزودين الأصليين (`postCall`).

يعمل النظام وفق مبدأ **الفشل المفتوح** (fail-open): إذا رمى حاجز حماية استثناءً
أثناء التنفيذ، يسجّل السجل الخطأ ويتابع مع حاجز الحماية التالي بدلاً من
إفشال الطلب. الحظر قرار صريح (`block: true`)، وليس صدفة أبدًا.
الاستثناء الوحيد هو الطلب المُجهَض: عندما تُجهَض `signal` الخاصة بالمستدعي،
فإن حاجز الحماية الرامي يرفض تشغيل الخطاف بدلاً من تخطّيه.

الخطافات **لا** تعمل على كل مسار ولا على كل استجابة. اقرأ
[التغطية والحدود](#coverage-and-limits) قبل الاعتماد على حاجز حماية
كضابط أمني.

### جسر الرؤية (`visionBridge.ts`) — جسر الوسيلة PR-1

يحتوي النموذج الأساسي GLM 5.3 و `glm-5.3-{low,high,max}` على بيانات تعريف `supportsVision:false` registry/spec واضحة. تظل متغيرات GLM 5.3 Flash نماذج رؤية أصلية. يدخل مسار `/v1/messages` الخاص بـ Claude Code في سلسلة حاجز الحماية المسبق للاتصال `handleChat` المشترك** قبل** الترجمة من Claude إلى OpenAI؛ يجب وصف صور نتائج أداة `Read` المتداخلة أو معالجتها قبل أن ترفعها الترجمة إلى محتوى OpenAI `image_url` (#17069).

يعترض الطلبات الحاملة للصورة التي تستهدف** نماذج غير مرئية** وإما أن يعيد توجيه الطلب بالكامل إلى نموذج قادر على الرؤية أو يستبدل أجزاء الصورة بأوصاف نصية ينتجها نموذج رؤية قابل للتكوين قبل استدعاء المنبع. يتيح ذلك لموفري النصوص فقط التعامل بشفافية مع الحمولات متعددة الوسائط.

تدفق:

1. قم بالتخطي إذا كان النموذج المستهدف يدعم الرؤية بالفعل (ما لم يظهر في قائمة الجسر القسري `isVisionBridgeForcedModel`).
2. قم باستخراج أجزاء الصورة عبر `extractImageParts(messages)` (`visionBridgeHelpers.ts`) الذي يقوم بتفويض ملف** كاشف الوسائط الموحد** `detectMediaParts()` في `open-sse/utils/mediaParts.ts` — المصدر الوحيد للحقيقة الذي تتم مشاركته مع مرشح توافق التحرير والسرد. يتم إدراج الاستخراج في القائمة المسموح بها للأشكال التي يمكن لـ `replaceImageParts` لصقها مرة أخرى (عقد استبدال ↔): OpenAI `image_url` و Anthropic base64 `source.type:"base64"` و Anthropic URL `source.type:"url"` و Responses API `input_image`. يتم أيضًا استخراج الصور المطابقة المتداخلة داخل Claude Code `tool_result.content` ومخرجات أداة الاستجابات واستبدالها في مساراتها الأصلية؛ أشكال المؤشر فقط هي مواد تصفية مجمعة ولا يتم استخراجها. تخطي إذا لم يتم العثور على أي شيء.
3. حل تكوين وقت التشغيل عبر `resolveVisionBridgeRuntimeSettings()` (`src/shared/constants/modalityBridgeDefaults.ts`): فوز مفاتيح إعدادات `modalityBridge*` الجديدة؛ تظل مفاتيح `visionBridge*` القديمة عبارة عن** دورة احتياطية واحدة** (نافذة التراجع). قم بالتخطي قبل أي اجتياز للوسائط عند تعطيل الجسر.
4. محدد الوضع (`modalityBridgeVisionMode`، انظر الجدول أدناه) يقرر إعادة التوجيه مقابل الوصف. تقوم إعادة التوجيه بإرجاع `modifiedPayload` مع تبديل `model` فقط، بالإضافة إلى meta `{ rerouted, fromModel, toModel, imagesKept }`.
5. وصف المسار: قم بتغطية الصور في `maxImages`، وقم بإنشاء موجه إدراك المهمة، واستشر ذاكرة التخزين المؤقت للوصف، واستدعاء نموذج الرؤية** بالتوازي** (`Promise.allSettled`)، وحقن أجزاء النص `[Image N]: <description>` في مكانها. يؤدي الوصف الفاشل إلى `null`: يتم الاحتفاظ بالصورة الأولية لأهداف unknown/vision-capable (#4012)، ولكن a** تم تأكيد الهدف المباشر للنص فقط** أو تحصل المجموعة ذات الرؤية الصفرية على كعب نص `(unavailable — no vision-capable provider connected)` واضح لكل صورة غير موصوفة، بما في ذلك حالات الفشل الجزئي والصور التي تتجاوز الحد الأقصى لاستدعاء الوصف (#17069). يظل التحرير والسرد الفاشل الموجود في الوصف الاحتياطي في مكانه (#8430).
6. إرجاع `modifiedPayload` + meta (`imagesProcessed`, `descriptions`, `processingTimeMs`, `visionModel`).

#### محدد الوضع (`modalityBridgeVisionMode`)

| وضع        | تقصير | سلوك                                                                                                                                                                                                                                       |
| ---------- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`     | ✔     | إرشادي قديم، لم يمس (#6640/#7204): يتم إعادة توجيه النماذج غير المجمعة/`auto/` إلى أفضل نموذج رؤية ما لم يكن النموذج الأصلي يحتوي بالفعل على بيانات اعتماد قابلة للاستخدام (ثم قم بالوصف)؛ تصف أهداف التحرير والسرد دائمًا.                |
| `describe` |       | قم دائمًا بوصف — حيث تم تخطي كتلة إعادة التوجيه بالكامل؛ النموذج الذي اختاره المستخدم يجيب دائمًا.                                                                                                                                         |
| `reroute`  |       | فرض إعادة التوجيه: يتم تجاوز حارس نموذج الاحتفاظ بالاعتماد. إعادة التوجيه-** هدف** لا يزال حارس بيانات الاعتماد يطبق — في حالة عدم وجود هدف رؤية قابل للاستخدام، ويتم حظر الجسر بخطأ واضح بدلاً من وصف أو إرسال صور أولية إلى هدف نصي فقط. |

الأوضاع القسرية ماس كهربائى** قبل** يعمل الكشف عن مجريات الأمور السيارات. سلوك `auto` مطابق للبايت لحاجز الحماية pre-PR-1.

#### نطاق مفتاح واجهة برمجة التطبيقات (`visionBridgeKeyScope.ts`)

عندما يقوم مفتاح API الخاص بالمتصل بتقييد `allowedConnections` أو تجمعات الحصص (`allowedQuotas`) أو النماذج (`allowedModels` / `blockedModels` / `modelAccessMode: "restricted"` / `disableNonPublicModels`)، يختار الجسر فقط إعادة التوجيه ويصف النماذج التي قد يستخدمها المفتاح، على الاتصالات التي قد يستخدمها المفتاح. يمر استدعاء الوصف دائمًا عبر الحلقة الذاتية OmniRoute مع رأس `x-omniroute-self-loop-key-id` ، لذا فإن طلب الدردشة المتلقي يفرض اتصال هذا المفتاح وسياسة النموذج مرة أخرى. يحترم `enforceApiKeyPolicy()` هذا الرأس فقط مع حامل الحلقة الذاتية، لذلك يمكنه فقط تضييق الوصول، ويتم رفض المعرف الذي لم يتم حله.

إذا لم يكن هناك نموذج رؤية مسموح به للمفتاح، أ** تم تأكيد الهدف النصي فقط** يرفض طلب الصورة محليًا باستخدام HTTP 400 واضحًا بدلاً من إعادة توجيه بايتات الصورة إلى مصدر غير قادر (#17069). بالنسبة للأهداف ذات القدرة على الرؤية غير المعروفة أو الأصلية، يحتفظ مسار الوصف بسلوك الفتح الفاشل السابق (meta `{ skipped: true, reason: "no_permitted_vision_model" }`). الطلبات التي لا تحتوي على مفتاح، والمفاتيح التي لا تحتوي على هذه القيود، تعمل تمامًا كما كانت من قبل.

#### وصف المهام على علم بالموجه (`modalityBridgeVisionTaskAware`)

تقصير** حقيقي** . `composeVisionPrompt()` (`visionBridgeHelpers.ts`) يلحق نص** رسالة المستخدم الأخيرة** (تم اقتطاعه إلى 500 حرف) إلى موجه الوصف الأساسي، وتوجيه الوصف نحو ما طلبه المستخدم فعليًا (نمط المخطوطة والرؤية والوكيل) ومطالبة نموذج الرؤية بنسخ النص المرئي. مع إيقاف تشغيل العلامة — أو عدم وجود نص للمستخدم — يتم استخدام الموجه الأساسي دون تغيير.

الطلب المتوافق مع OpenAI الخاص بالحلقة الذاتية (`callVisionModelSingle()` in `visionBridgeHelpers.ts`) يطلب دائمًا `image_url.detail: "high"` — دون قيد أو شرط، لكل caller/provider، وليس بوابة على أي إشارة عميل. يؤدي أخذ العينات منخفضة التفاصيل إلى انخفاض دقة OCR بالنسبة لمهمة نسخ النص التي تطلبها هذه المطالبة، لذا فإن استدعاء الوصف نفسه يطلب دائمًا تفاصيل عالية بغض النظر عن مستوى التفاصيل الذي استخدمه الطلب الوارد الأصلي. يؤثر هذا فقط على نص طلب الوصف الداخلي؛ لا يغير كيفية قيام OmniRoute بإعادة توجيه `image_url.detail` الخاص بالمتصل بناءً على الطلب الأساسي — الذي يتم تطبيق الإعداد الافتراضي بشكل منفصل، وفقط لعملاء OpenCode المكتشفين، في `defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`). لا يحتوي فرع تنسيق السلك Anthropic للحلقة الذاتية الوصف على حقل `detail` ولا يتأثر بأي من الوضعين الافتراضيين.

#### وصف سقف الإخراج (`modalityBridgeVisionMaxChars`)

| مفتاح                          | تقصير | يتراوح           |
| ------------------------------ | ----- | ---------------- |
| `modalityBridgeVisionMaxChars` | `0`   | `0` أو 100-50000 |

`0` (افتراضي) يعني** لا يوجد غطاء** — يتم تمرير الوصف الذي تم إرجاعه بواسطة `callVisionModel()` دون تعديل، مع الحفاظ على السلوك الحالي. أي قيمة في النطاق 100-50000 تقطع الوصف بلاحقة `…` قبل أن يتم ربطه مرة أخرى كـ `[Image N]: <description>` (`VisionBridgeGuardrail.preCall()` في `src/lib/guardrails/visionBridge.ts`). ارفع هذا للمهام OCR ذات التفاصيل الثقيلة حيث يحتاج النموذج النهائي إلى النسخ الكامل؛ قم بخفضه إلى استخدام الرمز المميز في نماذج الرؤية الثرثارة. يوجد حقل لوحة المعلومات في اللوحة المتقدمة لعلامة التبويب Vision (`modality-bridge-max-chars` في `ModalityBridgeVisionTab.tsx`) ويثبت أي قيمة بين 1 و 99 حتى الطابق 100 مع ترك `0` صريحًا دون تغيير — `0` هي قيمة Zod صالحة في حد ذاتها (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`)، وليست مجرد القيمة الافتراضية "unset".

#### وصف ذاكرة التخزين المؤقت (`modalityBridge/bridgeCache.ts`)

ذاكرة تخزين مؤقت LRU + TTL في الذاكرة لوصف المخرجات، ومشاركتها على مستوى العملية. المفتاح = `sha256(imageRef + composedPrompt + configuredBridgeModel)` مع تأطير بادئة الطول (بدون تصادمات بين حدود المجال). المكون النموذجي هو** تم تكوينه** نموذج الجسر، وليس النموذج الذي أجاب فعليًا على — `callVisionModel` قد يتراجع داخليًا، وقد يؤدي إدخال المفتاح في كل محاولة إلى تجزئة ذاكرة التخزين المؤقت. لا يتم تخزين الوصفات الفاشلة أبدًا. إعدادات:

| مفتاح                           | تقصير  | يتراوح  |
| ------------------------------- | ------ | ------- |
| `modalityBridgeCacheEnabled`    | `true` | —       |
| `modalityBridgeCacheTtlMinutes` | `60`   | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`  | 10–5000 |

#### تطبيع الصورة عن بعد (جلب describe/base64 ذاتي الحلقة)

عندما يجلب الجسر أ** بعيد** الصورة نفسها — Anthropic تصف الاتصال الذاتي وتحويل base64 بتنسيق claude-wire (`ensureBase64ImagesForClaudeWire`)، وكلاهما عبر `fetchRemoteImageAsDataUri()` في `visionBridgeHelpers.ts` — ويتم تمرير البيانات الناتجة URI عبر `normalizeDataUri()` (`open-sse/utils/imageNormalize.ts`) قبل تضمينها في طلب نموذج الرؤية. يتم تصغير حجم الصور كبيرة الحجم إلى a** 2048 بكسل حافة طويلة** (مطابقة حجم تغيير الحجم OpenAI/Anthropic يتم تطبيقها بالفعل من جانب الخادم)، مما يؤدي إلى قطع تحميل bytes/latency دون تغيير ما يراه نموذج الرؤية. يستخدم تغيير الحجم `sharp`، ويتم تحميله عبر الاستيراد الديناميكي: على النظام الأساسي الذي يفشل فيه تحميل ثنائيه الأصلي، `normalizeDataUri()`** لا يلقي أبدا** — فإنه يعود إلى مرور البايتات الأصلية، لذلك يستمر مسار describe/base64-conversion في العمل دائمًا. يتم أيضًا تمرير وحدات البايت غير الصورية (عملية الجلب التي لم تُرجع صورة قابلة لفك التشفير) دون تغيير. تم تحديد نطاق هذا التطبيع ليشمل الصور التي يجلبها الجسر من أجل الاتصال الذاتي الخاص به — ولا يتم تطبيقه أبدًا على حمولة المرور الخام للمتصل، بما يتوافق مع مبدأ طفرة الاشتراك فقط (Hard Rule #20).

#### إعدادات مخطط + الهجرة

تم التحقق من صحة مفاتيح `modalityBridge*` الجديدة بواسطة Zod في `updateSettingsSchema` (`src/shared/validation/settingsSchemas.ts`): `modalityBridgeVisionEnabled` `modalityBridgeVisionMode` و `modalityBridgeVisionModel` `modalityBridgeVisionTaskAware` `modalityBridgeVisionPrompt` `modalityBridgeVisionTimeout` `modalityBridgeVisionMaxImages` و `modalityBridgeVisionMaxChars` و `modalityBridgeCache*` trio ومجموعة `modalityBridgeAudio*` التي يستخدمها جسر الصوت. يقوم Migration `141_modality_bridge_settings.sql` بنسخ قيم `visionBridge*` القديمة الحالية إلى المفاتيح الجديدة المطابقة (غير فعالة، ولا يقوم أبدًا بالكتابة فوق قيمة `modalityBridge*` التي حددها المشغل)؛ تظل المفاتيح القديمة مقبولة كبديل للقراءة لدورة إصدار واحدة.

#### الشفافية رأس احصائيات +

تحمل الاستجابات الوصفية المحولة `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` (تم إنشاؤها بواسطة `buildModalityBridgeHeader()` في `modalityBridge/bridgeStats.ts`، ومختومة بـ `withModalityBridgeHeader()` في `src/sse/handlers/chatHelpers.ts`). الحصول على الطلبات المعاد توجيهها** لا** الرأس — لم يتم المساس بالحمولة النافعة ومبادلة النموذج مرئية بالفعل في حقل `model` لجسم الاستجابة.

`GET /api/modality-bridge/stats` (مصادقة الإدارة، نفس الطبقة مثل `GET /api/settings`) تقوم بإرجاع عدادات كل طريقة في الذاكرة `{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs, latencySamples, averageLatencyMs, lastUsedAt }` لـ `vision` و `audio` و `video`. `averageLatencyMs` يستخدم `latencySamples`، وليس كل المحاولات، كمقام لها؛ لا تؤدي العملية بدون توقيت إلى تصنيع عينة مقدارها صفر مللي ثانية. يظل `bridged` هو الاسم المستعار المتوافق مع الإصدارات السابقة للتحويلات الناجحة؛ المحاولات الفاشلة لا تزيده. يتم إعادة تعيين العدادات عند إعادة تشغيل العملية حسب التصميم (القياس عن بعد، وليس المحاسبة).

#### تكوين لوحة القيادة

صفحة لوحة التحكم المخصصة هي `/dashboard/settings/modality-bridge`. تحافظ علامات التبويب `Vision` و `Audio` و `Video` القابلة للعنونة عبر عنوان URL على معلمات الاستعلام أثناء تبديل قيمة `tab`. تعرض علامة التبويب Vision التمكين والوضع واختيار النموذج (بما في ذلك الإعداد الافتراضي التلقائي) والمطالبة بالمهمة وحدود timeout/image/description-length/cache المتقدمة وعدادات وقت التشغيل وطلب العينة المحمي. علامة التبويب "الصوت" نشطة أيضًا: فهي تعرض التمكين ومنتقي طراز STT فقط مع تلقائي وحدود timeout/max-clip وعدادات الصوت واختبار عينة `input_audio`. تعمل علامة تبويب الفيديو: فهي تُبلغ عن حالة وقت تشغيل FFmpeg/ffprobe — واحدة من أربع حالات UI صريحة (`unknown` أثناء طيران المسبار أو عدم اكتماله، `restricted` على مضيف لوحة معلومات غير استرجاعية حيث يتم تخطي المسبار من جانب العميل، `unavailable` بمجرد فحصه وتأكيد فقدانه، أو `available` مع إصدارات FFmpeg/ffprobe ) يستمر — في حدود enable/model/frame/video/timeout ، ويقوم بتصفية منتقي النموذج إلى النماذج القادرة على الرؤية، ويكشف عن عدادات الفيديو.

بطاقة Vision Bridge السابقة ضمن إعدادات AI هي رابط توافق للصفحة الجديدة؛ لم يعد يملك نسخة ثانية من النموذج. يقوم موفرو الوسائط أيضًا بربط مسارات عمل تحويل الصورة إلى نص وتحويل الكلام إلى نص إلى علامات تبويب Modality Bridge المقابلة دون إزالة ساحة لعب تحويل الكلام إلى نص الموجودة.

**تجاوز قبول الحلقة الذاتية:** عندما يتم توجيه استدعاء الوصف من خلال حلقة `/v1` الذاتية الخاصة بـ OmniRoute(نموذج موفر غير قياسي)، يرسل الطلب الفرعي `x-omniroute-admission-bypass: internal` ويتم مصادقته باستخدام بيانات اعتماد الحلقة الذاتية التي تم حلها — حارس `sk_omniroute` المحلي في الوضع المحلي، أو مفتاح `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` env (#1350) الذي تم تكوينه بواسطة المشغل، لذلك لا يزال بإمكان عمليات نشر `REQUIRE_API_KEY=true` تشغيل استدعاء الوصف. يتم تنفيذ التجاوز فقط لبيانات الاعتماد الدقيقة هذه، لذلك لا يمكن للعملاء الخارجيين استخدام الرأس لتخطي القبول.

الإعدادات الافتراضية القديمة تعيش في `src/shared/constants/visionBridgeDefaults.ts`; الإعدادات الافتراضية الجديدة mode/task-aware/cache ومحلل الإعدادات موجودة في `src/shared/constants/modalityBridgeDefaults.ts`. يكشف حاجز الحماية عن خيار منشئ `deps` حتى تتمكن الاختبارات من حقن تطبيقات `getSettings` و `callVisionModel` المزيفة.

### جسر الصوت (`audioBridge.ts`) — جسر الوسيلة PR-3

يعترض طلبات الدردشة المحملة بالصوت قبل أن تصل إلى هدف غير معروف بقبول إدخال الصوت. لا يقوم بإعادة توجيه طلب الدردشة مطلقًا: يتم نسخ الأجزاء الصوتية من خلال نقطة النهاية متعددة الأجزاء المتوافقة مع OpenAI ويستمر نموذج الدردشة المختار مع النصوص النصية.

تدفق:

1. حل `supportsAudio` من خلال `getResolvedModelCapabilities()`. تفوز البيانات التعريفية الصريحة لسجل الموفر، ثم البيانات التعريفية للنموذج الثابت، ثم تتم مزامنة `modalities_input`. قائمة الإدخال المعلنة بدون `audio` هي `false`؛ لا يوجد دليل على القدرة يبقى `null`. يقوم كل من `false` و `null` بتنشيط الجسر المحافظ، بينما يتجاوزه `true`.
2. قم بحل إعدادات `modalityBridgeAudio*` واستخرج أجزاء صوتية عالية المستوى قابلة للتقسيم من كل رسالة من خلال كاشف `detectMediaParts()` المشترك. أشكال الأسلاك المدعومة هي OpenAI `input_audio` و `audio_url` و `source.media_type: "audio/*"`. تم اكتشاف الصوت المتداخل للتوجيه ولكن لم تتم إزالته بواسطة مسار الوصلة. العمل متوج بـ `modalityBridgeAudioMaxClips`؛ الأجزاء اللاحقة تبقى على حالها.
3. قم بتكريم `provider/model` الذي تم تكوينه، أو اسمح `selectAudioBridgeModel()` بالسير على `AUDIO_TRANSCRIPTION_PROVIDERS` بترتيب كتالوج مستقر وحدد النموذج الأول باستخدام بيانات اعتماد موفر نشط قابلة للاستخدام.
4. يقوم `callAudioTranscription()` بتحويل صوت base64/data-URI إلى `file` متعدد الأجزاء، أو تنزيل `audio_url` عن بعد من خلال الحرس الصادر العام فقط مع تثبيت DNS وحد 25 MB. ثم يقوم بعد ذلك POSTs الملف والنموذج المحدد إلى الحلقة الذاتية `/v1/audio/transcriptions` المحلية، والتي تمت مصادقتها باستخدام `resolveSelfLoopBearer()`. يقوم مسار النسخ الحالي بإجراء بحث عادي عن بيانات الاعتماد ومعالجة cooldown/rate-limit وإرسال الموفر.
5. المكالمات الناجحة تستبدل أجزائها بـ `[Audio N]: <transcript>`. يتم تشغيل المكالمات باستخدام `Promise.allSettled`: يؤدي الفشل الفردي إلى الحفاظ على الجزء الصوتي الأصلي (عقد #4012 ). إذا فشلت كل مكالمة وتم إثبات الهدف `supportsAudio === false`، تصبح الأجزاء `[Audio N]: (unavailable — no STT provider connected)` (عقد #8430 ). بالنسبة لهدف غير معروف (`null`)، تظل نتيجة الفشل التام دون تغيير. يتلقى الهدف النصي فقط الذي تم إثباته والذي لا يحتوي على بيانات اعتماد STT قابلة للاستخدام نفس كعب الروتين الصريح دون إصدار مكالمة شبكة.

تستخدم النصوص الناجحة ذاكرة التخزين المؤقت Modality Bridge LRU/TTL على مستوى العملية. يجمع المفتاح بين مرجع الصوت وملصق تشغيل `audio-transcription` المستقر ونموذج STT المحدد؛ لا يتم تخزين حالات الفشل مؤقتًا أبدًا. تقوم المحاولات الصوتية بتحديث عدادات `bridged` و `cacheHits` و `failures` و `lastUsedAt` المشتركة. الاستجابات المحولة تحمل `x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>`; لا تتلقى الطلبات التي لم تمسها شريحة جسر الصوت.

إعدادات وقت التشغيل مدعومة بقاعدة البيانات وتم التحقق من صحتها بواسطة Zod:

| مفتاح                         | تقصير   | يتراوح           |
| ----------------------------- | ------- | ---------------- |
| `modalityBridgeAudioEnabled`  | `true`  | —                |
| `modalityBridgeAudioModel`    | `""`    | تلقائي أو STT ID |
| `modalityBridgeAudioTimeout`  | `60000` | 1000–300000      |
| `modalityBridgeAudioMaxClips` | `3`     | 1–10             |

تظل ذاكرة التخزين المؤقت المشتركة خاضعة للتحكم بواسطة `modalityBridgeCacheEnabled` و `modalityBridgeCacheTtlMinutes` و `modalityBridgeCacheMaxEntries`.

### جسر الفيديو (`videoBridge.ts`, `videoBridgePipeline.ts`)

يعترض أجزاء الفيديو ذات المستوى الأعلى في إكمالات الدردشة `messages` والردود API `input` قبل استدعاء هدف بدون دعم فيديو أصلي معروف. الأشكال المدعومة هي `input_video`، `video_url`، `video_source`، HTTPS URLs، و `data:video/*;base64,...` data URIs. لا يتم التعامل مع أسماء الملفات العادية في النص على أنها فيديو.

تمتلك `VideoBridgeGuardrail.preCall` (`videoBridge.ts`) اجتياز الطلب، وفحص capability/policy ، والتجميع لكل طلب، وحمولة الاستجابة. يتم الحصول على — لكل فيديو، وذاكرة التخزين المؤقت للنتيجة الكاملة، التي تصف تسلسل الإطار (الذي يدمج أي نص صوتي يعلنه المتصل)، ويتم إخفاء metrics/abort/cleanup — لكل محاولة خلف `processVideoPart` في `videoBridgePipeline.ts`، ويتم استدعاؤه مرة واحدة لكل جزء فيديو داخل حلقة `preCall`. تحدد هذه الوحدة أيضًا حدود المنفذ الصريحة `VideoMediaBrokerPort` (الحصول على البايتات واستخراج الإطارات التي تم أخذ عينات منها)، و `VideoAudioTranscriptionPort` (دمج نسخة صوتية معلنة بواسطة المتصل مع التسميات التوضيحية التي تم أخذ عينات منها)، و `VideoDrilldownPort` (شكل المتجر الخام القديم). يتكون الإنتاج STT والاحتفاظ بالإطار حول منفذ الوصف من خلال `createVideoSttAdapter` و `createVideoDrilldownAdapter`؛ يستخدم الأخير دورة حياة المقبض غير الشفاف المشترك.

لا يقوم مسار طلب `/v1` العام أبدًا باستيراد أو استدعاء عملية فرعية. يتم تنزيل مقاطع الفيديو عن بعد ضمن حد 50 MiB ؛ تحتوي مقاطع فيديو Base64 المضمّنة على حد أقصى قدره 36 MiB مفكك التشفير لكل فيديو، لذا يمكن أن يظل مظروف model/messages/framing داخل حد قبول طلب JSON العام وهو 50 MiB. يتم التحقق من تقديرات الطول المضمن والحجم الذي تم فك تشفيره قبل التخصيص. مطلوب HTTPS على URL البعيد الأولي وفي كل عملية إعادة توجيه، وذلك باستخدام الحرس الصادر العام فقط الموجود مع تثبيت DNS. ثم تعبر البايتات حدود وسيط `POST /api/modality-bridge/video/extract` الداخلية الدقيقة. هذا المسار هو `LOCAL_ONLY` و `SPAWN_CAPABLE`، ويقبل فقط طلب استرجاع موثوق ومصادق عليه لكل عملية، ولا يقبل أبدًا URL أو مسار نظام الملفات أو قائمة قابلة للتنفيذ أو قائمة وسيطات. يفرض خط أنابيب حجم الجسم API وقارئ الجسم التزايدي للمعالج بشكل مستقل حدًا أقصى لمدخلات الوسيط قدره 50 MiB. تقوم قائمة الانتظار المحددة الخاصة بها بتشغيل عملية استخراج واحدة في كل مرة، وتسمح بأربع مهام معلقة، وتحدد الحد الأقصى للإدخال المعلق عند 100 MiB.

داخل الوسيط، يقرأ `ffprobe` ملفًا محليًا خاصًا؛ تستثني القائمة المسموح بها للتنسيق الثابت تنسيقات قوائم التشغيل والبيان. بالنسبة لحاويات عائلة MOV المسموح بها، تظل مراجع بيانات MOV الخارجية معطلة بشكل افتراضي، ولا يقوم الأمر الثابت بالاشتراك فيها. يستخدم كل من `ffprobe` و `ffmpeg` القائمة البيضاء لبروتوكول `file` -only ، وخيط واحد، ومصفوفات وسيطات ثابتة، ولا يوجد غلاف، ويتم حل الملفات التنفيذية من `PATH`. تدفقات غلاف الصورة المرفقة ليست مرشحة قابلة للتشغيل. يجب أن تستوفي جميع التدفقات القابلة للتشغيل الحدود، ويفضل التدفق الافتراضي الصريح قبل الرجوع الحتمي ذي المؤشر الأدنى. تقتصر مقاطع الفيديو على 600 ثانية، و8,192 بكسل لكل بُعد، و33,554,432 بكسل مصدر. عينات FFmpeg من 1 إلى 16 إطارًا JPEG للنقطة الوسطى، وتتصغير الحافة الطويلة إلى 1024 بكسل على الأكثر دون ترقية المدخلات الأصغر، ولا تتلقى أبدًا URL. أخذ العينات هو `uniform` بشكل افتراضي. تقوم سياسات `scene_aware` وسياسات `segment_aware` التجريبية بإجراء تمرير FFmpeg ثابت إضافي واحد عبر الدفق المحلي الذي تم التحقق من صحته بالفعل، وتحديد الطوابع الزمنية لمشهد `showinfo` المحدود، والرجوع بشكل حتمي إلى نفس نقاط المنتصف الموحدة عند فشل الكاشف، أو انتهاء المهلة، أو الإخراج المشوه، أو مجموعة مرشحة فارغة. يقوم الوضع المدرك للقطاع بتخصيص عينات النقطة الوسطى بشكل متناسب مع فترات المشهد التي تم التحقق من صحتها؛ يتم تفصيل الأدلة المدركة للقطاعات والسلوك الاحتياطي أدناه. يتم تطبيق الحد الأقصى المكون من 16 إطارًا بعد الاختيار في كل سياسة. عندما يكون للطلب المدرك للمشهد ميزانية إطار واحد فقط، فإنه يستخدم نقطة المنتصف الموحدة لنافذة الفيديو الكامل النشطة أو نافذة التركيز ويبلغ `policyEffective: uniform`: لا يمكن لإطار مشهد واحد محدد الحفاظ على كلا الطرفين الزمنيين. قد يوفر المتصل بشكل اختياري نافذة تركيز محدودة (ثواني `start`/`end` )؛ يتم تثبيت الحدود على مدة الوسائط، ويتم رفض النوافذ المعكوسة أو غير المحدودة، ويتم تنفيذ جميع سياسات أخذ العينات فقط داخل الفاصل الزمني الذي تمت تسويته. يتم تضمين النافذة الناتجة في بيانات تعريف العينات وفي بادئة الوصف غير الموثوق بها حتى تتمكن النماذج النهائية من التمييز بين مقتطف مركز من المخطط الزمني الكامل.

التركيز على التسمية التوضيحية الدلالية هو إعداد منفصل وصريح. يحافظ وضع تحليل `full` الافتراضي على موجه الإطار الموجود ولا يعيد توجيه نص الطلب مطلقًا إلى نموذج التسمية التوضيحية. في وضع `focused` ، يقرأ الجسر فقط أحدث `text`/`input_text` غير الفارغة التي قام المستخدم بتأليفها من نفس حاوية الدردشة أو الردود، ويقوم بتطبيعها إلى NFC، ويطوي أحرف التحكم والمسافات البيضاء، ويحدها إلى 500 نقطة كود Unicode. تعود النتيجة الفارغة إلى موجه `full` الدقيق. يتم إجراء تسلسل للتلميح القابل للاستخدام كـ JSON في كتلة سياق مستخدم غير موثوق به وقد يعطي الأولوية فقط للتفاصيل التي يمكن ملاحظتها؛ ولا يمكن تجاوز التحذير المنفصل بشأن اتباع التعليمات المرئية أو المسموعة في وسائل الإعلام. لا يستنتج التركيز النصي أبدًا `start`/`end` أو يغير أداة أخذ العينات الزمنية.

#### FU-07 أدلة القطاع الهيكلي

يستخدم `segment_aware` تمريرة واحدة محددة للتحليل المسبق عبر دفق الفيديو المحلي الذي تم التحقق من صحته بالفعل. يتم تغيير حجم سلسلة التصفية الثابتة أولاً إلى عرض 320 بكسل على الأكثر، وتكتشف تغيرات المشهد والفواصل الزمنية المجمدة، ثم تقوم بأخذ عينات بمعدل إطار واحد في الثانية للحصول على معلومات التمويه ومتوسط اللون و spatial/temporal. يقتصر التمرير على 600 عينة هيكلية، وخيط FFmpeg/filter واحد، ونفس بروتوكول `file` -only والقوائم المسموح بها للحاويات، وحدود إخراج العملية 1 MiB ، و30 ثانية على الأكثر داخل abort/deadline. المشترك للوسيط، ولا يقبل أبدًا أمرًا أو مرشحًا أو مسارًا أو URL من الطلب.

القيم الهيكلية هي أدلة أخذ العينات الحتمية، وليس فهم الفيديو الدلالي. ولا تستنتج الموضوعات أو الإجراءات أو التسميات التوضيحية أو الكلام أو نية المستخدم. تشكل حدود المشهد والتجميد مقاطع؛ تؤثر تغطية التجميد والتمويه والتعرض والتفاصيل المكانية والتغيير الزمني فقط على كيفية تخصيص ميزانية الإطار الحالية من 1 إلى 16. يتم تحديد الجزء المجمد بالكامل بإطار واحد، بينما تتنافس المقاطع غير المجمدة على الميزانية المتبقية. عندما يفوق عدد الحدود عدد الإطارات، يتم الاحتفاظ بتغطية الخط الزمني الموحدة بحيث لا يمكن للتخفيضات المبكرة السريعة أن تخفي مقطعًا طويلًا زائدًا. يتم دمج حدود المشهد ضمن دقة التحليل التي تبلغ ثانية واحدة لحدود التجميد.

تفشل عوامل التصفية المفقودة، أو دليل malformed/empty ، أو خطأ الكاشف، أو مهلة التحليل المسبق المحددة في سياسة نقطة المنتصف الموحدة الدقيقة. لا يفشل فتح المتصل أو الموعد النهائي للوسيط: فهو ينهي العملية الفرعية أثناء الرحلة، ويمنع استخراج الإطار لاحقًا، وتتم إزالة الشجرة المؤقتة الخاصة في `finally`.

تولد `scripts/perf/video-bridge-fu07-eval.ts` تركيبات FFmpeg حقيقية حتمية لتوفير استدعاءات التسمية التوضيحية بعد الإلغاء، وتخصيص ميزانية الحركة الكثيفة، وأدلة blur/exposure/SI-TI ، والتخفيضات السريعة ذات الذيل الطويل، والإيجابيات الكاذبة التدريجية. فهو يسجل وقت جدار التحليل المسبق، وحيثما يتوفر `/usr/bin/time` ، فإن الطفل CPU وذروة RSS. إن فحوصات الجودة الخاصة بها هي عبارة عن أوراكل هيكلية فقط. تظل جودة نموذج التسمية التوضيحية الحقيقية `HOLD` لأن هذا الحزام لا يحتوي على نقطة نهاية معتمدة أو حكم مجمد. تظل المدخرات النقدية أيضًا `HOLD` ما لم يقدم `--caption-cost-per-call-usd` تقديرًا إيجابيًا صريحًا لكل مكالمة؛ النص لا يختلق أيًا من النتيجتين أبدًا.

يقتصر كل إطار على 4 MiB، وجميع الإطارات الأولية معًا إلى 23 MiB، واستجابة الوسيط المتسلسلة إلى 32 MiB. تتم إزالة الدليل المؤقت الخاص في `finally`. لا يقوم OmniRoute بتجميع FFmpeg ولا يقبل مسارًا مخصصًا قابلاً للتنفيذ. قبل التسميات التوضيحية، يطبق الجسر ممرًا محافظًا لإلغاء البيانات المكررة: يتم تقليل كل JPEG إلى مخزن مؤقت بتدرج رمادي يبلغ 16 × و16 ويتم مقارنته فقط بالإطار الأخير الذي تم الاحتفاظ به. بالنسبة لميزانية التسميات التوضيحية المطلوبة التي تزيد عن إطار واحد، يوفر الاستخراج مجموعة مرشحة محدودة تصل إلى ضعف تلك الميزانية ولا تزيد أبدًا عن 16 إطارًا. يتم تطبيق الحد الأقصى المطلوب فقط بعد إلغاء البيانات المكررة، مع الحفاظ على المرشحين المختارين الأول والأخير أثناء التخفيض النهائي عندما تكون الميزانية اثنين على الأقل. تستخدم سياسة `grayscale-16x16-mean-cells-v2` ذات الإصدار الأكبر من متوسط دلتا luma ونسبة الخلايا المصغرة التي تبلغ دلتا المقيسة 0.05 على الأقل. العتبة المكررة هي الثابت 0.04، الذي تم اختياره لإمكانية التنبؤ بدلاً من عرضه كإعداد وقت التشغيل. تحافظ هذه الإشارة الثانوية عالية التباين على الحركة الصغيرة وتغييرات النص المرئي التي يمكن أن تخفيها المقارنة المتوسطة فقط. تفشل أخطاء المقارنة أو وحدة فك التشفير في الفتح وتحافظ على التغطية. تفصل بيانات التعريف الناتجة بين المرشحين المستخرجين والإطارات المستخدمة بنجاح والتكرارات المرئية التي تم إسقاطها.

قد يطلب جزء الفيديو المحدد بوضوح ورقة اتصال ذات طابع زمني. يتكون الجسر على الأكثر من 4 أعمدة و16 إطارًا لشبكة JPEG. تقوم كل خلية بحجم 512 بكسل بحرق الطابع الزمني المصدر الخاص بها في نطاق سفلي عالي التباين، بينما تظل نفس الطوابع الزمنية في البيانات الوصفية النصية من أجل الارتباط والتدقيق في المراحل النهائية. يظل JPEG الكامل متوجًا عند 32 MiB. إذا لم يتمكن `sharp` من فك تشفير الشبكة أو إنشائها، فسيعود الجسر إلى إطارات JPEG الفردية؛ لا يزال إحباط العميل ينتشر من خلال عملية الورقة.

يتم فصل الأدلة الترويجية عمدا عن المعيار الدقيق للتركيبة الاصطناعية. تحدد `scripts/perf/video-bridge-contact-sheet-eval.ts` أداة A/B ذات إصدار المخطط لنماذج الرؤية الحقيقية المتوافقة مع OpenAI. فهو يقيس الرموز المميزة التي أبلغ عنها الموفر، وزمن الاستجابة الشامل للجدار (بما في ذلك تكوين الورقة)، وعدد مكالمات النموذج، والاحتفاظ بالحقائق المحددة بالبيان. لا تتم كتابة استجابات النموذج الأولي للتقرير؛ يتم الاحتفاظ فقط بملخصات SHA-256 والحقيقة المطابقة IDs. لا يقوم الحزام بإجراء اتصال بالشبكة أو النموذج المدفوع ما لم يتم تمرير `--execute-real` وتكوين `--model` و `OMNIROUTE_BASE_URL` و `OMNIROUTE_API_KEY`. وبدون هذا التشغيل الحقيقي الصريح، يظل حكمها المقروء آليًا `HOLD`؛ قياسات payload/call-count الاصطناعية وحدها ليست دليلاً على الترويج.

تستهلك `scripts/perf/video-bridge-promotion-eval.ts` المنفصلة ملاحظات FU-07 أو FU-09. يتطلب قبول الترقية جميع أنواع السيناريوهات الاصطناعية الثمانية بالإضافة إلى مقطع حقيقي معقم، وثلاثة تكرارات مُقاسة على الأقل لكل دور وحالة، وجميع المقاييس العشرة المعلنة، وملخصات media/prompt/expected-fact/settings المجمدة، ومراقبة IDs الفريدة، وترتيب A/B المصنف الذي تم التحقق منه. يربط إيصال التنفيذ ملخص المجموعة والمرشح الدقيق SHA ومراجعة النموذج. تظل القياسات المفقودة أو غير الصالحة `HOLD`، بما في ذلك CPU فوق 30 ثانية، أو الذروة RSS فوق 512 MiB أو التحليل المسبق فوق 30 ثانية. هذه هي الحدود القصوى لقبول الأدلة، وليست ضمانًا جديدًا لإنفاذ RSS في وقت التشغيل.

تتطلب FU-07 الاحتفاظ بالجودة بنسبة 98% على الأقل وزمن استجابة p95 لا يزيد عن 1.2x خط الأساس، بالإضافة إلى تحسين استدعاء التسميات التوضيحية المتوازنة لحالة الأحرف المطلقة بنسبة 0.05 عند مكالمات التسميات التوضيحية المتوسطة المكافئة، أو ما لا يقل عن 10% أقل من متوسط مكالمات التسميات التوضيحية بعد الحذف. يتطلب FU-09 ما لا يقل عن 0.85 جودة، واحتفاظ بنسبة 95%، وتقليل زمن الوصول المتوسط بنسبة 20%، وتقليل الرمز المميز بنسبة 10%. يؤدي فقدان الحقائق الحرجة أو الامتثال للحقن أو الاستخدام المفقود إلى منع الترويج. لا يمكن لتنفيذ واحد أن يروج لأي شيء: يؤكد `--previous-report` عمليتي تنفيذ متميزتين وغير متداخلتين ومؤهلتين على التوالي لنفس policy/model revision/candidate/corpus. لا يمكن لتجربة أخذ العينات تأكيد تجربة ورقة جهات الاتصال.

يجب على هواة الجمع تسجيل الإجابات في الذاكرة وحفظ مقاييس `responseDigest` plus وارتباطات المراقبة، وليس نص الرد أبدًا. يقرأ المستهلك أيضًا الملاحظات الأولية القديمة ولكنه لا ينسخ هذا النص مطلقًا في تقاريره. يتم قبول واحد بالضبط من `responseDigest` أو `rawResponseText` لكل ملاحظة. تظل القائمة المسموح بها التي تم إصدارها فارغة باستخدام الإعداد الافتراضي `hold` غير القابل للتغيير. يتطلب الإدخال المؤهل مرجع الأدلة والسياسة ومراجعة النموذج والمرشح الدقيق SHA وملخص البيان واثنين من تشغيل IDs المتميزين؛ يتم رفض السياقات المتضاربة. تعتبر هذه البيانات الوصفية بمثابة عقد تدقيق، وليست دليلاً على أن الملف المشار إليه يحتوي على قياسات حقيقية. قم بمراجعة الإيصالات الفعلية قبل إضافة أي قيد. تكشف نقطة نهاية إحصائيات الإدارة ولوحة معلومات الفيديو عن الاستعداد المحافظ. لا يؤدي الاسم المستعار للنموذج الذي تم تكوينه وحده إلى إنشاء المراجعة الخاصة به أو المرشح قيد التشغيل SHA، لذا فإن لوحة المعلومات الحالية تشير إلى `HOLD` بدلاً من إعادة استخدام الأهلية من سياق تنفيذ آخر. يبقى الاختيار التجريبي الصريح منفصلاً عن الترقية؛ لا يتم تغيير أي افتراضي تلقائيًا.

يمكن للمتصلين إرفاق مصفوفة `transcript.cues` اختيارية بجزء فيديو مدعوم عندما يكون لديهم نص محاذي بالفعل. يجب أن يحمل كل إشارة `text`، وفاصل زمني `start`/`end` محدود داخل المدة التي تم فحصها، و `source` في القائمة البيضاء (`client`، `embedded`، أو `audio-bridge`)؛ `confidence` الافتراضي هو `1` ويجب أن يبقى بين `0` و `1`. يتم طي الإشارات المكررة بالضبط. لا يبدأ OmniRoute أبدًا في النسخ من بيانات التعريف هذه: يتم نسخ الإشارات التي تم التحقق من صحتها إلى النتيجة الموصوفة مع المصدر والثقة والفاصل الزمني، ويتم تقديمها كملاحظات غير موثوقة إلى جانب التسميات التوضيحية للإطار. يتم رفض النص غير الصالح أو خارج النطاق أو النص الخالي من المصدر بدلاً من دمجه في تدفق التسميات التوضيحية. تقوم كل من قنوات نص نص الطلب بتطبيع المصدر المقدم إلى `client`، بما في ذلك تسميات `embedded` أو `audio-bridge` المؤكدة ذاتيًا. يمكن فقط للمحول المملوك للخادم تعيين تلك التسميات الموثوقة من خلال وسيطة `trustedSource` للتعليمات البرمجية فقط؛ لا يمكن لحقل طلب JSON الوصول إلى تلك الوسيطة. يظل النص النصي محتوى مشتقًا من الوسائط غير موثوق به، بغض النظر عن مصدره، ويجب ألا يحدد التفويض مطلقًا.

يمكن للمتصل المتقدم توفير مسار `audioTranscript` لنفس الفيديو؛ ويتم التعامل معه على أنه نص مقدم من العميل، وليس دليلاً على نسخ الخادم. يقوم نظام الاندماج بإجراء ملاحظات مرئية وصوتية في موعد نهائي واحد وإلغاء الإشارة، ويأمر بها وفقًا لجدول زمني مشترك، ويطوي التكرارات الدقيقة، ويبلغ عن نتيجة جزئية عندما ينجح جانب واحد فقط. يتحلل `audioTranscript` غير الصالح إلى تلك النتيجة الجزئية — ويتم الاحتفاظ بالوصف المرئي ويسجل فرع الصوت رمز فشل معقم — بدلاً من فشل الفيديو بأكمله. يتم الاحتفاظ بالتوفر لكل فرع، والعلامة الجزئية، ورموز الفشل المعقمة في النتيجة الموصوفة، وفي البيانات التعريفية لحاجز الحماية (`audioFusionRuns`/`audioFusionPartials`/ `audioFusionFailureCodes`)، وفي البيانات التعريفية لذاكرة التخزين المؤقت للنتائج، وفي عدادات دمج الجسر. لا يقوم مسار Video Bridge الافتراضي باستدعاء تحويل الكلام إلى نص أو تنزيل نسخة ثانية من الوسائط؛ وبدون هذا المسار الصريح، يظل الفيديو فقط.

**الاحتفاظ بالنص (#12150 P1).** ينطبق هذا تلقائيًا عندما يعرض جسر الفيديو (نفسه مُشترك) — نصية ولا توجد علامة استبقاء منفصلة. عندما يعرض طلب أي إشارة نصية ( `transcript` مُعلن عنها بواسطة المتصل أو `audioTranscript` مدمجة)، يقوم حاجز الحماية بوضع علامة عليها `videoBridgeObserved` وينتج ظلًا منقحًا لوصف الفيديو — وهو عرض مطابق يتم فيه استبدال نص النص الحر لكل إشارة بـ `[redacted-video-transcript]`، ويتم إنشاؤه عن طريق استبدال حقل الإشارة المنظم قبل تجميع السلسلة (وليس عن طريق تحليل النص المسطح، لذلك لا يوجد محتوى إشارة — متعارض أو العادية، بما في ذلك الأجسام التي تحتوي على `]` مثل `[inaudible]`/`[music]` — يمكنها البقاء على قيد الحياة). يقوم نص طلب سجل المكالمات المستمر بتبديل كل جزء نصي مشتق من الفيديو لهذا الظل المنقح، المطابق لمساواة المحتوى؛ تتم إعادة قراءة مرساة `fullText` من حمولة حاجز حماية ما قبل الاتصال النهائي، لذلك لا تزال المطابقة ناجحة بعد أن تعيد حواجز الحماية المتسلسلة اللاحقة ( PII وأقنعة بيانات الاعتماد، والأولويات 10/95) كتابة نص الوصف في مكانه وبعد حقن system-prompt/handoff/memory يعيد تشكيل مصفوفة الرسائل. الجسم المرسل إلى المنبع للنموذج لم يتغير. لا يملأ الطلب الذي تمت ملاحظته أيضًا أي ذاكرة دائمة (يتم تخطي كل من الاستخراج المشتق من الطلب والاستجابة)، لذلك لا يمكن لرد النموذج الخاص أن يردد النص المكتوب في الذاكرة.

**حقول الفيديو الخام (#12430).** عندما يتم تمكين الجسر ويكون دعم الفيديو الأصلي غير معروف أو غائبًا، تقوم حقول `transcript`/`audioTranscript` المحددة أيضًا بتنشيط `videoBridgeObserved`، حتى بعد فشل الوصف أو حد `maxVideos`. عدد `null` والسلاسل الفارغة؛ الحقول الغائبة والبيانات الوصفية غير المتعلقة بالفيديو لا تفعل ذلك. تقوم النسخ المحتفظ بها بتنقيح هذه الحقول أو حذف الطلب، ويتم تجاوز caches/Memory.

في تلك المسارات الاحتياطية، تصبح إشارات المتصل الصالحة أجزاء `text`/`input_text` مدعومة بدلاً من حقول الموفر غير القياسية. يظل كلا المسارين المقدمين حسب الطلب غير موثوقين بملاحظات `client` ، مع تحذير صريح بأن الفيديو لم يتم وصفه ولم يتم التحقق من الطوابع الزمنية مقابل الوسائط. يتم تطبيق ميزانيات إجمالي 256-cue/64-KiB الحالية وميزانيات كل إشارة عبر المسارين معًا؛ يجب أن تتناسب الطوابع الزمنية مع سقف الوسيط البالغ 600 ثانية وأي نافذة تركيز مقدمة. يتم تجاهل المسارات غير الصالحة، ولا تتم إعادة توجيهها كنص عشوائي؛ لا يزال من الممكن استخدام الأخوة الصالحين ما لم يتم تجاوز ميزانيتهم المجمعة. حقول Null/empty لا تضيف أي نص. لا تتم إضافة أي جلب للوسائط أو تحويل صوتي إلى نص من خلال هذا الإجراء الاحتياطي. تتم إزالة حقول امتداد النص من حامل الفيديو الاحتياطي وكائنات `video_url`/`source` الخاصة به. تظل القائمة المسموح بها لأسلاك OpenAI صارمة؛ تظل شركات نقل الفيديو الأصلية غير المعروفة متاحة وتحتفظ الأهداف النصية المعروفة فقط بعلامات آمنة. تعمل ظلال التنقيح المنظمة على حماية النص المكتوب الملحق، بينما يظل الطلب الأصلي المملوك للمتصل بدون تغيير. تحتفظ الأهداف المدعومة الأصلية والجسور المعطلة بسلوك التجاوز الحالي الخاص بها.

تستخدم النسخ الإضافية المحتجزة نفس إشارة الطلب المرصودة. تحل لقطة طلب العميل الأولية الأولية، والطلب المعلق في الذاكرة، وسجل الطلبات المرفوضة المبكرة محل حقول النص في أجزاء الفيديو بشكل هيكلي؛ يتم تنقيح مطالبات السلسلة التي تم تصنيعها بواسطة مراحل خط الأنابيب وتسليم السياق عند مخزن نص الطلب المستمر. علامة `video_content_removed` المستمرة تجعل استمرار `previous_response_id` يفشل في الإغلاق بدلاً من إعادة بناء النص الذي تم تجاهله عمدًا. إذا فقد الطلب الذي تمت ملاحظته ظل التنقيح لكل جزء قبل التسجيل، أو حتى فشل أحد ظلال الفيديو العديدة في المطابقة بعد طفرات الطلب اللاحقة، فسيتم حذف نص الطلب المحتفظ به بالكامل بدلاً من الاحتفاظ بالنص المنقح جزئيًا.

بالنسبة للطلب الذي تمت ملاحظته، قد تقتبس الاستجابة النموذجية أي جزء من النص بدون حدود إشارة منظمة. ولذلك يتم استبدال سجل المكالمات المستمر الخاص به `responseBody` بعلامة الإغفال؛ لا يتم الاحتفاظ بالقطعة الأثرية التفصيلية لخط الأنابيب (والتي يمكن أن تتضمن أجسام upstream/client وأجزاء الدفق). تتجاوز ذاكرات التخزين المؤقت الدلالية والعجزية والاستدلالية عمليات القراءة والكتابة لهذا الطلب. يبقى طلب الموفر والاستجابة المرئية للعميل دون تغيير. يتم استنزاف بايتات Keepalive المبكرة من المخزن المؤقت المؤقت عند حذف القطعة الأثرية التفصيلية. يُبلغ تحذير EventStream المشوه الخاص بـ Kiro فقط عن عدد بايتات الحمولة النافعة، وليس محتوياته أو الخطأ الأولي لمحلل JSON. هذا لا يدعي أن كل تشخيص provider/plugin غير ذي صلة قد تم تدقيقه؛ يتم تتبع عملية مسح الحوض المحتجز الأوسع في #11658.

دورة حياة `/api/modality-bridge/video/drilldown` الداخلية عبارة عن ركيزة منفصلة لذاكرة التخزين المؤقت loopback/token-authenticated. تتطلب كل عملية أيضًا ID رئيسيًا معتمًا أساسيًا. قبل تمكين مستدعي الإنتاج، يجب أن يشتق ذلك ID من المستأجر الذي تمت مصادقته ويجب ألا يعيد توجيه القيمة المحددة من قبل العميل مطلقًا. تربط مفاتيح ذاكرة التخزين المؤقت هذا المبدأ بالجلسة الأساسية ومرجع الفيديو IDs، وتخزن فقط مفاتيح SHA-256-derived الخاصة بها، ونطاق كل من عمليات القراءة والحذف لنفس المبدأ. تخزن ذاكرة التخزين المؤقت 16 إطارًا JPEG مشتقًا على الأكثر لكل إدخال، وتنتهي صلاحيتها بعد عشر دقائق، وتدعم قراءات `start`/`end` المقيدة أو حذف الجلسة الصريحة.

يقتصر كل مدير على 16 إدخالاً و64 MiB من بيانات JPEG الأساسية. هذه الحدود مستقلة عن سقف 64-entry/256 MiB العالمي: يؤدي ضغط الحصص الرئيسية إلى طرد الإدخالات الأقل استخدامًا لهذا المدير الرئيسي فقط قبل النظر في إخلاء LRU العالمي. يتم مسح الإدخالات منتهية الصلاحية من المحاسبة الرئيسية والعالمية على نشاط ذاكرة التخزين المؤقت، في حين أن الإلغاء وفشل التحقق من الصحة لا يؤدي إلى استبدال جزئي.

ترفض ذاكرة التخزين المؤقت Base64 غير المتعارف عليه، والحشو الزائد، والوسائط غير JPEG، و JPEGs المشوهة أو المقطوعة، و JPEGs التي تنتج تحذيرًا أثناء فك تشفير `sharp` لصورة كاملة محددة. فهو يعيد تشفير كل صورة مقبولة باعتبارها JPEG أساسية، ويستمد العرض والارتفاع من البايتات التي تم فك تشفيرها بدلاً من الثقة في حقول المتصل، ويتجاهل أي بايتات زائدة متعددة اللغات بدلاً من الاحتفاظ بها. يتم تحميل المخزن المؤقت المضغوط المتعارف عليه فقط على كلا الحصتين. يشتمل حد سلك JSON على حمل Base64 لسقف الإدخال الذي تم فك تشفيره بمقدار 32 MiB. يسجل كل اشتقاق مخزن JPEG format/resolution وسياسة أخذ العينات وإصدار الاشتقاق ووقت الإنشاء وتجزئة المحتوى المحسوب بواسطة الخادم والمرجع الأصلي المجزأ بالإضافة إلى تجزئة المحتوى الأصلي للمتصل الموثوق به. يتم التحقق من الإلغاء بين مراحل decode/hash غير المتزامنة قبل الالتزام بذاكرة التخزين المؤقت الذرية.

يقوم منتج الإنتاج بإعادة استخدام إطارات الوسيط المشتقة بالفعل فقط بعد التحليل المرئي الناجح، مع عدم وجود مقطع فيديو ثانٍ download/extraction. ويتطلب ذلك عامل التشغيل `modalityBridgeVideoDrilldownEnabled=true`، و `drilldown: true` الصارم لكل جزء، وسجل مفتاح API المعتمد ID. لا تثبت قيم principal/session المعلنة من قبل العميل الملكية أبدًا. وبدون هذه الشروط الثلاثة، لا يتم تجزئة الإطارات الإضافية أو تغيير حجمها أو الاحتفاظ بها. يؤدي فشل الاستبقاء إلى الحفاظ على الاستجابة المرئية القابلة للاستخدام. تتجاوز الطلبات التي تمت الموافقة عليها ذاكرة التخزين المؤقت لنتائج الفيديو بالكامل، لذا لا تعيد النتائج المخزنة مؤقتًا تشغيل المقابض أبدًا.

تعرض استجابات JSON و SSE الناجحة أربعة مقابض غير شفافة على الأكثر في رأس `x-omniroute-video-drilldown` المحدود. يمكن لأصول المتصفح المعتمدة قراءة هذا الرأس دون توسيع سياسة أصل CORS. تستخدم المقابض الجديدة `v1.<32-byte random base64url token>`، ويحتفظ السجل فقط بتجزئة SHA-256 الخاصة بها. يقبل المحلل اللغوي reader/header أيضًا الرموز المميزة ذات 64 سداسيًا. المستهلك العام المصادق عليه هو `GET /api/v1/video-bridge/drilldown?handle=...`، وهو مسور بشكل مستقل بواسطة `modalityBridgeVideoDrilldownRemoteEnabled=true`. يؤدي الخطأ الصريح المستمر إلى إبطال الوصول حتى عند تمكين الإجراء الاحتياطي القديم `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_REMOTE_ENABLED` env. الاحتفاظ بالإنتاج لديه احتياطي `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_ENABLED` القديم المماثل. يتم إيقاف كلا الخيارين الاحتياطيين بشكل افتراضي.

يستمد المستهلك الملكية من المفتاح المصادق عليه ويطبق السياسة الرئيسية: ينتمي كل من GET و DELETE إلى فئة نقطة النهاية `video` ، بما في ذلك الأسماء المستعارة `/v1` و `/api/v1`. يجب أن تتضمن المفاتيح ذات القائمة المسموح بها لنقاط النهاية غير الفارغة `video`؛ تظل المفاتيح غير المقيدة متوافقة. يقوم المستهلك بإرجاع نفس الرقم 404 للمقابض غير المعروفة والمنتهية الصلاحية ومقابض المفاتيح الأخرى. فهو يقبل `variant=preview|standard|detail` (الحد الأقصى لبعد JPEG 320/640/1280، لم تتم ترقيته مطلقًا)، `limit=1..8` (أو الاسم المستعار القديم `frames` ، وليس كلاهما أبدًا)، و `page` القائم على الصفر، وثواني التركيز الاختيارية `start`/`end`. يتم رفض مفاتيح الاستعلام المكررة ونوافذ التركيز المعكوسة. يحتوي كل متغير تم إرجاعه على تجزئة لمحتواه الفعلي وبيانات تعريف الدقة الفعلية المرتبطة بالمصدر المحتفظ به. يتم اشتقاق المتغيرات عند القراءة بدلاً من تخزينها كنسخ إضافية محتجزة. استجابة JSON ، بما في ذلك Base64/envelope، محددة بـ 32 MiB؛ ترجع الصفحة كبيرة الحجم 413 ويجب على العميل طلب إطارات أقل. يقرأ التحقق من الإلغاء حول كل تغيير حجم ويعيد التحقق من صلاحية المقبض قبل العودة. `DELETE` من قبل المالك عاجز. يؤدي الحذف أو انتهاء صلاحية TTL إلى تحرير محاسبة المصدر والاستخدام المحتفظ بها.

المخزن المشترك هو عملية محلية: تنتهي صلاحية المقابض عند إعادة التشغيل ولا يمكن نقلها بين عمليات OmniRoute المستقلة. تكشف إحصائيات الإدارة عن سياسة الاحتفاظ الفعالة/عن بعد وتجميع entries/bytes المحتفظ به فقط، وليس الوسائط أو المراجع أو IDs الرئيسي أو المقابض. تعرض لوحة إعدادات الفيديو هذه القيم ويمكن أن تستمر في تبديل مفتاحي الموافقة. لا تمثل وثائق التنفيذ هذه دليلاً مباشرًا للنشر أو الترويج؛ يتم تتبع قبول النموذج الحقيقي بشكل منفصل.

تتم تسمية الإطارات بشكل تسلسلي باستخدام نموذج الفيديو الذي تم تكوينه. يرث تجاوز الفيديو الفارغ إعداد الرؤية؛ إذا كان كلاهما فارغًا، يقوم جهاز التوجيه التلقائي Vision بتحديد النموذج الفعال القادر على الرؤية. تستبدل التسميات التوضيحية الناجحة الجزء الأصلي ببادئة `[Video description:` مستقرة والتي تحدد أيضًا النص على أنه ملاحظة غير موثوقة مستمدة من الوسائط وتخبر النماذج النهائية بعدم اتباع الإرشادات الموجودة في الوسائط. تشتمل مفاتيح ذاكرة التخزين المؤقت للتسمية التوضيحية للإطار على بايتات JPEG والموجه والطابع الزمني والنموذج الفعال؛ يتم تخزين التسميات التوضيحية الناجحة فقط مؤقتًا. تحتفظ إدخالات ذاكرة التخزين المؤقت بنموذج المنتج الناجح الفعلي، بما في ذلك النموذج الاحتياطي؛ يُبلغ الجسر عن `mixed` عندما يتم إنتاج إطارات مختلفة بواسطة نماذج مختلفة. تؤدي نتيجة ذاكرة التخزين المؤقت إلى إعادة استخدام هوية المنتج بدلاً من إعادة تسميتها كخطة التوجيه المطلوبة. يتم تحديد ذاكرة التخزين المؤقت لنتائج الفيديو بالكامل على كل إدخال يغير موجه — للإخراج، والنموذج الفعال، وسياسة أخذ العينات، وعدد الإطارات، ووضع التحليل الدلالي، وبصمة SHA-256 لتلميح التركيز المعياري، ونافذة التركيز، و `transcript`، و `audioTranscript`، وعلامة ورقة الاتصال — لذا فإن تغيير أي من هذه الأبعاد يعد بمثابة تفويت لذاكرة التخزين المؤقت، وليس إعادة استخدام قديمة أبدًا. إن إصدار سياسة الحذف المرئي والعتبة وعدد الإطارات المرشحة المحددة واضح أيضًا في مفتاح ذاكرة التخزين المؤقت للنتائج وبيانات التعريف؛ وبالتالي، لا يمكن لتغيير السياسة إعادة استخدام وصف الفيديو بأكمله القديم. تحافظ البيانات التعريفية للإصدار 4 من ذاكرة التخزين المؤقت للنتيجة على الوضع وبصمة الإصبع، وليست مهمة المستخدم الأولية أبدًا. تُبلغ بيانات تعريف الدرابزين عن أوضاع التحليل المطلوبة والفعالة؛ يتم الإبلاغ عن وضع `focused` المطلوب بدون نص المستخدم القابل للاستخدام بشكل فعال `full`.

يستخرج حاجز الحماية كل جزء فيديو مدعوم ولكنه لا يصف أكثر من `modalityBridgeVideoMaxVideos`. بالنسبة للهدف الذي ثبت أنه يحتوي على `supportsVideo === false`، تصبح مقاطع الفيديو الفاشلة والمتجاوزة الحد علامات نصية آمنة صريحة بحيث لا يبقى أي فيديو خام. عندما تكون القدرة غير معروفة، تحتفظ تلك الأجزاء بحامل الفيديو الخاص بها؛ يتبع أي نص احتياطي تحويل النص المحدود أعلاه. الأهداف مع `supportsVideo === true` تتجاوز الجسر. تنتشر إشارة إلغاء طلب العميل من خلال التنزيل وقائمة انتظار الوسيط والعمليات الفرعية ومكالمات التسميات التوضيحية؛ تتوقف عمليات الإجهاض بين مقاطع الفيديو ولا تفشل مطلقًا في فتح الوسائط الأولية.

يتم تثبيت قيم مهلة الفيديو التي تزيد عن 120 ثانية على الموعد النهائي للوسيط؛ يتم رفض الإعدادات الجديدة التي تزيد عن هذا الحد. يتطلب `GET /api/modality-bridge/video/runtime` منطقة استرجاع مختومة موثوقة قبل المصادقة أو فحص وقت التشغيل، ثم يتطلب مصادقة الإدارة. تقوم بإرجاع إصدارات `available` فقط، وإصدارات FFmpeg/ffprobe المعقمة، وسبب ثابت عندما يكون وقت التشغيل غير متاح. نقطة نهاية الاستخراج الداخلي ليست تحميلًا عامًا API: يُرجع تشبع قائمة الانتظار `503` بالإضافة إلى `Retry-After`، ويؤدي قطع اتصال المتصل إلى إرجاع `499`، ويعيد الموعد النهائي للوسيط الثابت `504`. تضيف الاستجابات المحولة `video->text;model=<visionModel>;parts=<videos>` إلى رأس `x-omniroute-modality-bridge` المركزي دون إزالة مقاطع الرؤية أو الصوت.

### قناع PII (`piiMasker.ts`)

يعمل على** كلاهما** مراحل.

- **`preCall`** يستنسخ الحمولة، ويمشي `system` و `messages` و `input` و `prompt` (بما في ذلك عناصر السلسلة العادية)، ويطبق `processPII()` (من `@/shared/utils/inputSanitizer`) على حقول السلسلة `content`/`text`. عند `PII_REDACTION_ENABLED=true`، يتم تنقيح PII المكتشف في الحمولة الصادرة. وهذا مستقل عن `INPUT_SANITIZER_MODE` (الذي يتحكم فقط في سياسة الحقن الفوري). عند إيقاف التنقيح، يتم احتساب اكتشاف سجلات المكالمات دون إعادة كتابة المحتوى.
- **`postCall`** استنساخ الاستجابة بعمق، وتشغيل `sanitizePIIResponse()` بالإضافة إلى قناع شكل Responses-API (يغطي `maskResponsesOutput` — `output_text` و `output[].content[].text`). في حالة حدوث أي تنقيح، تحل الاستجابة المعدلة محل الاستجابة الأصلية.

الدرابزين لا يحجب أبدًا؛ فهو يضيف تعليقات توضيحية فقط (`meta.detections`، `meta.redacted`) أو يعيد الكتابة.

**قبو قابل للعكس (`PII_REVERSIBLE_VAULT_ENABLED`، `false` الافتراضي).** عندما يكون كل من `PII_REDACTION_ENABLED` و `PII_REVERSIBLE_VAULT_ENABLED` في وضع التشغيل (DB override > env > default، اقرأ مرة واحدة لكل طلب)، يفتح `handleChat` قبوًا واحدًا لكل طلب عميل (`src/lib/pii/requestTokenVaultScope.ts`) ويمرره إلى ممر الاتصال المسبق كـ `GuardrailContext.tokenVault`. يقوم المخفي بعد ذلك بكتابة رموز بديلة مثل `<<PII_EMAIL_QWERTYUI_1>>` بدلاً من `[EMAIL_REDACTED]`، للقواعد المضمنة والتحقق من صحتها (GDPR/POPIA) والقواعد المخصصة على حدٍ سواء. الرقم هو 8 أحرف كبيرة عشوائية لكل طلب، وتحصل نفس القيمة على نفس الرمز المميز داخل الطلب. فقط النعناع المقنع: يعمل حارس الحقن الفوري و `/api/guardrails/test` بدون قبو ويحتفظان بالعناصر النائبة.

- يرى الموفر وكل مرحلة من مراحل التحرير والسرد وإعادة المحاولة وعضو لجنة الدمج وحكم الدمج الرموز المميزة فقط. تتم استعادة الرموز المميزة مرة واحدة، في استجابة 2xx التي تترك `handleChat`: لكل حقل على SSE الذي تم تحليله (لا يزال يتم حل تقسيم الرمز المميز عبر الأحداث؛ ويتم تخطي وسيطات استدعاء الأداة JSON) أو لكل حقل على نص JSON ، مع `Content-Length` المعاد حسابه. تتم استعادة نص المحتوى والمنطق ووسيطات استدعاء الأداة. تحتفظ أجسام الخطأ (4xx/5xx) بالرموز المميزة.
- تظل حالات الفشل خاصة: إذا فشلت عملية سك العملة أو رفض المخزن قيمة (1000 إدخال، 256 حرفًا لكل قيمة، إجمالي 64 KB )، تتم كتابة العنصر النائب بدلاً من ذلك؛ الرمز المميز الذي لا يمكن للمخزن حله، أو الاستعادة التي تفشل، تظل حرفية ولا يتم تسجيل سوى عدد. لا يحتوي القبو على مؤقتات ولا حالة عالمية؛ يتم مسحه عند انتهاء دفق الاستجابة أو إلغاؤه أو حدوث أخطاء.
- عند سك طلب الرموز المميزة، يتم تخطي استخراج الذاكرة وحفظ العجز وكلا الكتابة في ذاكرة التخزين المؤقت الدلالية، لأنه لا يمكن لأي طلب لاحق حل هذه الرموز المميزة. في سجلات المكالمات، يحمل طلب الموفر والاستجابة الرموز المميزة؛ لا يزال نص طلب العميل المسجل هو إدخال العميل الأولي، كما هو الحال مع التنقيح العادي.
- تستخدم الرموز المميزة رقمًا عشوائيًا لكل طلب، لذلك تتغير بادئة المطالبة في كل دورة: لا يتم الضغط على التخزين المؤقت للمطالبة من جانب الموفر للدورات المقنعة، والرمز المميز الذي يعود في دورة لاحقة (على سبيل المثال عبر `previous_response_id`) ينتمي إلى طلب قديم ويظل حرفيًا.

#### اختيار لكل نوع، وأنماط مخصصة وعدادات الكشف

**لوحة المعلومات إعدادات → → Security → PII اخفاء** يختار _ما_ ملثما. لا يقوم بتشغيل الإخفاء: لا يزال هذا `PII_REDACTION_ENABLED` (طلب) و `PII_RESPONSE_SANITIZATION` (استجابة + SSE)، وكلاهما متوقفان افتراضيًا.

- **اختيار لكل نوع** — المعرفات المضمنة مدرجة في `src/shared/constants/piiTypes.ts` (`PII_BUILTIN_TYPES`). "غير محدد" يعني كل نوع (كان السلوك قبل هذا الإعداد موجودًا). يتم تعيين نمط `ssn_us` الخاص بمحرك الطلب إلى `ssn`. القوالب (الحد الأدنى، القياسي، المالي، البرازيلي، USA، GDPR، POPIA، كامل) تملأ فقط مربعات الاختيار الموجودة في UI.
- **معرفات GDPR و POPIA** — اثني عشر معرفًا مدمجًا يغطي معرفات EU والمعرفات الشخصية لجنوب إفريقيا (الجدول أدناه). توجد التعابير المنطقية والمصادقات وعلامات الاختصاص في جدول واحد، `src/shared/utils/piiPatterns.ts`، والذي يستهلكه كل من معقم الاستجابة (`src/lib/piiSanitizer.ts`) وقناع الطلب (`src/shared/utils/inputSanitizer.ts`). يتم تنقيح المطابقة فقط عندما يقبلها المدقق؛ إن مجرد تشغيل الأرقام لا يكفي أبدًا. المشغل الذي حفظ تحديدًا ضيقًا قبل وجود هذه المعرفات، يحتفظ بالسلوك الذي كان عليه حتى يتم تحديد المعرفات الجديدة.
- **أنماط مخصصة** — ما يصل إلى 20 نمطًا من أنماط regex أو أحرف البدل (`*` = حتى 64 حرفًا غير مسافات بيضاء، `?` = واحد). تصبح التطابقات `[CUSTOM_REDACTED]`. يمر كل نمط عبر `compilePiiCustomPattern()` (`src/shared/utils/piiCustomPatterns.ts`): على الأكثر 500 حرف، والأعلام تقتصر على `g i m s u`، ويجب أن يتم تجميعها، ويجب أن تمر `safe-regex` (التراجع الكارثي)، ويجب ألا تتطابق مع سلسلة فارغة أو عنصر نائب للتنقيح. يتم رفض النمط الذي يفشل عند حفظه وعند اختباره، ويتم تخطي الصف المخزن الذي يفشل في وقت التشغيل بدلاً من تجميعه. تعمل الأنماط المخصصة فقط أثناء تشغيل الإخفاء.
- **عدادات الكشف** عدد — لكل نوع (القيم غير المتطابقة أبدًا)، يتم حفظه في الذاكرة وإعادة تعيينه عند إعادة التشغيل (`src/lib/pii/piiDetectionStats.ts`). إنها تزيد فقط أثناء تشغيل الإخفاء.

الإعدادات موجودة في جدول `key_value` (مساحة الاسم `pii_settings`, `src/lib/db/piiSettings.ts`) ويتم قراءتها من خلال ذاكرة تخزين مؤقت مدتها 1 ثانية. API:

| طريقة  | طريق                     | غاية                                                                    |
| ------ | ------------------------ | ----------------------------------------------------------------------- |
| `GET`  | `/api/settings/pii`      | دولة العلم، `enabledTypes`، `customPatterns`، عدادات الكشف              |
| `PUT`  | `/api/settings/pii`      | استبدل `enabledTypes` (`null` = all) and/or `customPatterns`            |
| `POST` | `/api/settings/pii/test` | نموذج واحد للتشغيل الجاف مقابل عينة لا تقل عن 8 KB؛ لا يتم تخزين أي شيء |

تتطلب الثلاثة جميعها مصادقة الإدارة والتحقق من صحة الجسم باستخدام Zod (`src/shared/validation/schemas/piiSettings.ts`). مع تعطيل تسجيل الدخول (`requireLogin=false`) `GET` ونقطة نهاية الاختبار مفتوحة، ولكن `PUT` لا تزال بحاجة إلى جلسة لوحة معلومات، أو مفتاح `manage` -scope API ، أو رمز وصول `oma_` مع نطاق كتابة أو أعلى، أو رمز CLI المميز أو رمز الخدمة الداخلية المرسل من الاسترجاع.

### الحقن الفوري (`promptInjection.ts`)

يكتشف الهياكل العدائية في المحتوى الذي يقدمه المستخدم ويفرض السياسة التي تم تكوينها. يتم تحديد السلوك بواسطة متغيرات البيئة وخيارات المنشئ:

| جلسة        | البيئة فار                                                                                                   | تقصير  | تأثير                                                                                                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------ | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ممكّن       | `INPUT_SANITIZER_ENABLED`                                                                                    | `true` | عندما `false`، ماس كهربائى الدرابزين.                                                                                                                                         |
| وضع         | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                              | `warn` | سياسة الحقن: `block` أو `warn` أو `log`. (تم قبول `redact` للتوافق الخلفي ولكنه كذلك** لا** نص حقن الشريط. يتم التحكم في طلب إعادة كتابة PII بواسطة `PII_REDACTION_ENABLED`.) |
| عتبة الكتلة | خيار `blockThreshold` / `INPUT_SANITIZER_BLOCK_THRESHOLD` (الاسم المستعار `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high` | الحد الأدنى من الخطورة المطلوبة للحظر. يتم مراقبة الوسيط فقط بشكل افتراضي.                                                                                                    |

**أسبقية الوضع** (`getMode`): المتصل `options.mode` → `INJECTION_GUARD_MODE`** تجاوز علامة ميزة DB** (لوحة المعلومات إعدادات → علامات ميزات → ) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env → `warn`. وبالتالي، فإن تجاوز لوحة المعلومات يفوز على env vars، وبالتالي تتحكم ميزة Flags UI في حارس التشغيل المباشر (بدون إعادة تشغيل). قراءة DB آمنة من الفشل: إذا حدث خطأ، يعود الحارس إلى السلوك القائم على البيئة، وعندما لا يتم تعيين تجاوز، يكون السلوك مطابقًا لدقة البيئة فقط.

مصادر الكشف:

1. `sanitizeRequest()` من `@/shared/utils/inputSanitizer` (مجموعة الكاشف المشتركة المستخدمة في مكان آخر في المسار).
2. المدمج في `DEFAULT_GUARD_PATTERNS` (حاليا `system_override_inline` و `markdown_system_block`، وكلاهما خطورة `high` ).
3. يتم تمرير `customPatterns` الاختياري عبر خيارات المُنشئ (السلاسل أو regex أو سجلات `{ name, pattern, severity }` ).

عندما `mode === "block"`** و** يفي اكتشاف واحد على الأقل بحد الخطورة، وترجع `preCall` `{ block: true, message: "Request rejected: suspicious content detected" }`. في الوضعين `warn`/`log` يقوم حاجز الحماية بتسجيل المكالمة ولكنه يسمح بالاتصال. يتم أيضًا تصدير المساعد المشترك `evaluatePromptInjection()` للمتصلين الذين يحتاجون إلى تقييم المطالبات دون المرور عبر السجل.

**مسح ملزمة (v3.8.20):** يقوم الكاشف بفحص فقط** أول 16 KB** من النص الفوري المنضم — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16384 بايت) في `src/shared/utils/inputSanitizer.ts`. كل من `detectInjection()` و `evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` قبل تشغيل حلقة النمط. توجد توجيهات الحقن بالقرب من الجزء العلوي من المدخلات، لذا فإن هذا يضع حدًا أقصى لـ regex CPU/GC على حمولات متعددة مئات كيلوبايت دون إضعاف الكشف (راجع #3932، #4041).

### قناع بيانات الاعتماد (`credentialMasker.ts`)

يعمل على** كلاهما** المراحل الأخيرة في السلسلة الافتراضية (الأولوية `95`). يقوم بتنقيح أنماط مفتاح API / الرمز السري المعروفة من الحمولة الصادرة (محتوى الرسالة، وسائط استدعاء الأداة، نتائج الأداة)** و** استجابة الموفر، لذلك لا يتم تسريب بيانات الاعتماد التي تم لصقها في المطالبة (أو تكرارها مرة أخرى بواسطة نتيجة الأداة) إلى الموفر الرئيسي أو إعادتها إلى العميل.

- **الاشتراك فقط** ، نفس اتفاقية تنقيح PII (القاعدة الصعبة #20-adjacent): معطلة ما لم `settings.credentialRedactionEnabled === true`** أو** `CREDENTIAL_REDACTION_ENABLED=true`. مع إيقاف تشغيله، يصبح حاجز الحماية غير قابل للتشغيل ولا — أبدًا ولا يُعاد كتابته أبدًا.
- يمشي `redactCredentials()` على شجرة payload/response الكاملة (`walkValue()`، النموذج الأولي الآمن للتلوث، وآمن للدورة عبر `WeakSet`) ويستبدل المطابقات بعنصر نائب `[REDACTED:<type>]` ، مستنسخًا فقط الفروع التي تغيرت بالفعل.
- يغطي `CREDENTIAL_PATTERNS` مفاتيح موفر LLM (OpenAI، OpenAI-proj، Anthropic، Google، Hugging Face، Replicate)، رموز VCS/SaaS (GitHub، Slack، Linear، Notion، npm، Postman، Discord)، مفاتيح الدفع (Stripe، Square)، المفاتيح السحابية (مفتاح وصول AWS ، Twilio، SendGrid، Mailgun)، المفاتيح الخاصة / JWTs، سلاسل اتصال تحمل بيانات الاعتماد (`mongodb://user:pass@...`، وما إلى ذلك)، ونمط قيمة رأس `Authorization`/`x-api-key`/`api-key`/`apikey` العام. يتم تنقيح المفاتيح على شكل رأس (`authorization`, `x-api-key`, `api-key`, `apikey`) هيكليًا (القيمة فقط، مع الحفاظ على بادئة المخطط مثل `Bearer `/`Basic ` ) بدلاً من التعبير العادي للنص العام.
- الدرابزين لا يحجب أبدًا؛ فهو يعيد كتابة (`modifiedPayload` / `modifiedResponse`) فقط ويعلق (`meta.credentialsRedacted`, `meta.count`).

حارس الانحدار : `tests/unit/credential-masker-guardrail.test.ts`.

```typescript
interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

يُشير الحارس (guardrail) إلى "لا تغيير" بإرجاع `void` أو `{}` أو
`{ block: false }`. أما إرجاع `modifiedPayload`/`modifiedResponse` فيستبدل
القيمة المتدفقة عبر السلسلة للحرّاس اللاحقين.
يحمل `signal?: AbortSignal` دورة حياة المُستدعي إلى داخل الحرّاس. يُعد إجهاض الطلب
الاستثناء المقصود لمبدأ الفشل المفتوح (fail-open): تتوقف جسور الوسائط عن العمل
وتُنظّف دون استعادة الوسائط الخام إلى هدف معروف أنه لا يدعمها.

## السجل (`registry.ts`)

يكشف الكائن المفرد `guardrailRegistry` ما يلي:

- `register(guardrail)` — يضيف حارسًا (أو يستبدله بالاسم المُطبَّع) و
  يعيد الترتيب تصاعديًا حسب `priority`.
- `clear()` / `list()` — أدوات مساعدة إدارية.
- `runPreCallHooks(payload, context)` — يتنقل عبر الحرّاس النشطين، ويمرّر
  الحمولة عبر `modifiedPayload`، ويتوقف عند أول `block: true`.
- `runPostCallHooks(response, context)` — نفس التدفق على جانب الاستجابة.
- `resetGuardrailsForTests({ registerDefaults })` — يمسح الحالة ويعيد
  تسجيل الإعدادات الافتراضية اختياريًا لعزل اختباري نظيف.

يعيد كلا المُشغِّلين `{ blocked, payload|response, results, guardrail?, message? }`
حيث `results` عبارة عن مصفوفة من سجلات `GuardrailExecutionResult` تتضمن
حقول `blocked` و`skipped` و`modified` و`error` و`meta` لكل حارس،
وهي مفيدة للتتبّع.

### تعطيل الحرّاس لكل طلب

يجمع `resolveDisabledGuardrails({ apiKeyInfo, body, headers })` قائمة
مُزالة التكرار من أسماء الحرّاس التي ينبغي تخطّيها للطلب
الحالي. توجد خمس قنوات، تُقرأ بهذا الترتيب وتُدمج في قائمة واحدة
(الظهور الأول هو الذي يفوز عند إزالة التكرار):

1. `apiKeyInfo.disabledGuardrails`
2. حقل `disabledGuardrails` في جسم الطلب (المستوى الأعلى)
3. حقل `metadata.disabledGuardrails` في جسم الطلب (فقط عندما يكون `metadata` كائنًا)
4. الترويسة `x-omniroute-disabled-guardrails`
5. الترويسة القديمة `x-disabled-guardrails`

تُدمج القنوات الخمس جميعها، بما فيها الترويستان: فإرسال كلٍّ من
`x-omniroute-disabled-guardrails` و`x-disabled-guardrails` يتخطّى اتحاد
قائمتيهما، ولم يعد إرسال الترويسة الحديثة فارغة يُخفي الترويسة القديمة
([#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412)، أُصلح في
[#16805](https://github.com/diegosouzapw/OmniRoute/pull/16805)).

قد تكون القيم مصفوفات من السلاسل النصية أو سلسلة نصية مفصولة بفواصل؛ وتُقتطع
الأسماء وتُطبَّع إلى صيغة kebab-case الصغيرة (`pii_masker` → `pii-masker`)،
وتُسقط الإدخالات الفارغة. تُمرَّر النتيجة عبر `context.disabledGuardrails`
إلى السجل، الذي يتخطّى الحرّاس المطابقين (`skipped: true` في `results`).

لا تؤثر قائمة التعطيل إلا في **السجل**. فوضع `block` الخاص بحقن الأوامر
حدٌّ إلزامي: فالوسيط injection-guard
(`src/middleware/promptInjectionGuard.ts`) يستدعي `evaluatePromptInjection()`
دون أي قائمة تعطيل يتحكم بها المُستدعي (وقد أُزيل استدعاء
`resolveDisabledGuardrails({ body })` الميت الذي كان يُجريه في
[#16934](https://github.com/diegosouzapw/OmniRoute/pull/16934))، لذا يظل الطلب
الذي يعطّل `prompt-injection` مرفوضًا في وضع `block`. هذا مقصود
بالتصميم. إذ تتحكم جهة الاستدعاء في قنوات التعطيل (جسم الطلب،
metadata، الترويسات)، ولا يجوز للمُستدعي إيقاف عنصر
تحكم أمني ضبطه المشغّل
([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)). أما اتحاد
الترويسات من [#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412)
فيغيّر فقط أيّ حرّاس السجل يُتخطّون؛ ولا يسمح للعميل بتجاوز
الوسيط. تُتتبَّع سياسات الحرّاس الإلزامية لكل مفتاح ولكل مجموعة في
RFC الإصدار v4 رقم [#16417](https://github.com/diegosouzapw/OmniRoute/issues/16417).
راجع [التغطية والحدود](#coverage-and-limits).

## أمر التنفيذ

لكل طلب يتدفق عبر `src/sse/handlers/chat.ts` و `open-sse/handlers/chatCore.ts` (مسارات الدردشة العائلية المدرجة ضمن [التغطية والحدود](#coverage-and-limits) ):

1. يقوم `resolveDisabledGuardrails(...)` بإنشاء قائمة التخطي من مفتاح API والنص والرؤوس.
2. تقوم `guardrailRegistry.runPreCallHooks(body, ctx)` بتشغيل حواجز الحماية بترتيب تصاعدي للأولوية:
   - يتم تسجيل حواجز الحماية المعطلة على أنها `skipped`.
   - قد يقوم كل `preCall` الخاص بحاجز الحماية بإعادة كتابة الحمولة عبر `modifiedPayload`.
   - تقوم `block: true` الأولى بقصر دوائر السلسلة ويعيد المعالج استجابة رفض الدرابزين.
3. تتدفق الحمولة (التي يُحتمل إعادة كتابتها) إلى توجيه التحرير والسرد والإرسال إلى المنبع.
4. **غير البث فقط:** بعد تجميع الرد، يقوم `guardrailRegistry.runPostCallHooks(...)` بتشغيل نفس السلسلة على الرد. `block: true` هنا يسقط الاستجابة الأولية ويعيد HTTP 400. تتخطى الاستجابات المتدفقة هذه الخطوة تمامًا.
5. **قبو قابل للعكس فقط:** عندما يتم سك الرموز المميزة للطلب، يستعيدها `handleChat` عند استجابة 2xx التي يعودها، بعد خطافات ما بعد المكالمة وتحويل PII المتدفق، لذلك يرى `PII_RESPONSE_SANITIZATION` الرموز المميزة و PII التي تم إنشاؤها بواسطة النموذج، ولم يتم استعادتها أبدًا.

يتم تسجيل حواجز الحماية التي يتم رميها باستخدام `error: <message>` ويتم تسجيلها عبر `logger.warn`، لكن السلسلة تستمر في عدم فتح — حسب التصميم.

### ما لم يتم تغطيته

- **الوسائط والتضمينات وطرق البيانات** (`/v1/images/*`, `/v1/embeddings`, `/v1/audio/*`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/rerank`, `/v1/search`, `/v1/moderations`) لا تصل أبدا إلى التسجيل. لا يوجد هناك أي إخفاء PII أو إخفاء بيانات الاعتماد أو جسر الطريقة. فحصهم الوحيد هو البرمجيات الوسيطة القديمة لحماية الحقن.
- **الردود المتدفقة** لا تحصل على أي حواجز حماية بعد المكالمة: لا توجد مكالمة ما بعد الاتصال `pii-masker` أو `credential-masker` ، ولا يوجد حظر ما بعد المكالمة. ينطبق تحويل PII المتدفق فقط (عند تشغيل `PII_RESPONSE_SANITIZATION` ). لا يتم تنقيح بيانات الاعتماد التي تم تكرارها في الاستجابة المتدفقة.
- **تعطيل القنوات مقابل البرامج الوسيطة (حسب التصميم):** تقوم البرمجيات الوسيطة بتقييم الحقن الفوري باستدعاء `evaluatePromptInjection()` الخاص بها، دون تمرير أي قائمة تعطيل يتحكم فيها المتصل. يعد وضع `block` حدًا إلزاميًا لا يمكن للتعطيلات التي يتحكم فيها المتصل تجاوزها، بما في ذلك مسارات عائلة الدردشة ( [#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413) ). يؤدي تعطيل `prompt-injection` إلى تخطي حاجز حماية التسجيل فقط.

### ما يرى استجابة قبل ما بعد المكالمة

على المسار غير المتدفق، يكون الترتيب هو: استخراج الذاكرة، تنفيذ الأداة المدمجة → ، حواجز حماية ما بعد المكالمة → ، خروج كتلة ما بعد المكالمة → ، خروج متجر ذاكرة التخزين المؤقت الدلالي →.

- **استخراج الذاكرة** و** تنفيذ الأداة** شاهد الاستجابة قبل أن تتمكن حواجز حماية ما بعد المكالمة من إعادة كتابتها أو حظرها. منذ [#16401](https://github.com/diegosouzapw/OmniRoute/pull/16401) ، يقوم استخراج الذاكرة بتشغيل النص المستخرج من خلال `sanitizePII` عندما يكون `PII_RESPONSE_SANITIZATION` قيد التشغيل (سواء كان متدفقًا أو غير متدفق)، ولكن الاستجابة التي يتم حظرها لاحقًا بعد الاتصال لا تزال متاحة للذاكرة والأدوات.
- **ذاكرة التخزين المؤقت الدلالية** يقوم بتخزين الاستجابة بعد المكالمة اللاحقة، لذلك يقوم بتخزين الاستجابة المعاد كتابتها، ولا يتم تخزين الاستجابة المحظورة مؤقتًا أبدًا. يتم إدخال إدخالات ذاكرة التخزين المؤقت بواسطة مفتاح API.

متغيرات البيئة التي تقرأها حواجز الحماية المدمجة:

| عامل                                  | يستخدم من قبل              | تأثير                                                                                                    |
| ------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------- |

| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (المصب)       | يتحكم في سلوك قناع جانب الاستجابة.                                                                       |

## حواجز الحماية المخصصة

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

الخطوات:

1. أنشئ `src/lib/guardrails/myGuardrail.ts` موسِّعًا `BaseGuardrail`.
2. نفِّذ `preCall` و/أو `postCall`.
3. إما أن تُسجِّل عند وقت الاستيراد (بالدفع من `registerDefaultGuardrails`) أو
   استدعِ `guardrailRegistry.register(...)` في وقت التشغيل — يستبدل السجل
   أي حاجز حماية سابق يحمل الاسم المُطبَّع نفسه.
4. أضف اختبارات ضمن `tests/unit/` (أمثلة موجودة:
   `tests/unit/guardrails-registry.test.ts`،
   `tests/unit/prompt-injection-guard.test.ts`،
   `tests/unit/guardrails/visionBridge.test.ts`).

## تغطية مسارات حاجز الحقن والفريق الأحمر (المرحلة 8 · الكتلة D)

يغطي حاجز الحقن (`createInjectionGuard` / `withInjectionGuard`) جميع المسارات
التي تقبل أوامر المستخدم. وهو يحترم `INJECTION_GUARD_MODE` (الافتراضي `warn` = تسجيل فقط؛
`block` = يعيد HTTP 400 `SECURITY_001`).

| النوع         | المسارات                                                                                                                                             | الوضع الافتراضي |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| نصية (موجودة) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn            |
| توليدية       | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn            |
| بيانات        | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn            |

يغطي استخراج النص (`extractMessageContents`) الحقول `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`.

**الفريق الأحمر (ليليًا، `nightly-llm-security.yml`):** يتحقق promptfoo من أن كل مسار يحجب
مجموعة OWASP-LLM في `INJECTION_GUARD_MODE=block`؛ بينما يشغِّل garak مسبارات (يتخطاها دون توفر السر).
تم تضمين `moderations` حرصًا على الاتساق. وضع الحجب حدٌّ إلزامي: فدالة `evaluatePromptInjection()`
تتجاهل قائمة التعطيل الخاصة بكل طلب التي يمررها لها البرنامج الوسيط، لذا فإن `disabledGuardrails`
**لا** يعفي أي مسار منها ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)).

سير العمل الليلي (`.github/workflows/nightly-llm-security.yml`، cron + التشغيل
اليدوي) يتضمن مهمتين:

- **`promptfoo-guard` (مانعة)** — تشغِّل `promptfoo eval -c promptfooconfig.yaml`
  مع `INJECTION_GUARD_MODE=block`. تؤكد كل حالة عدائية (مثل "تجاهل جميع
  التعليمات السابقة…"، ومحاولات كسر الحماية بأسلوب DAN) أن الاستجابة تحمل
  `error.code === "SECURITY_001"`، أي أن الحاجز رفض الطلب فعليًا.
- **`garak` (استشارية)** — تشغِّل garak `--probes promptinject,dan,leakreplay`
  ضد نسخة OmniRoute محلية (`http://localhost:20128/v1`). وهي مشروطة بسر
  المزوّد (`PROMPTFOO_PROVIDER_KEY`)؛ تتخطى بسلاسة عند غيابه وهي مُلحَقة بـ
  `|| true`، لذا تُبلِغ عن النتائج دون إفشال CI.

تمتد تغطية أداة الحاجز المساعدة (`createInjectionGuard` / `withInjectionGuard`)
لتشمل كل مسار `/v1` حامل للأوامر؛ ويُستخرج نص الأمر من
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` بواسطة
`extractMessageContents()` في `src/shared/utils/inputSanitizer.ts`.
