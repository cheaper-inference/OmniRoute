## التوجيه التلقائي بدون تكوين (بادئة `auto/` )

لا يلزم إنشاء التحرير والسرد. استخدم `auto` أو متغير `auto/` مباشرة في عميلك.

### أمثلة سريعة

| موديل ID            | سلوك                                                                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`              | نماذج المزودين المؤهلين واستراتيجية LKGP والأوزان المتوازنة                                                                                |
| `auto/coding`       | أوزان الجودة أولاً لمهام البرمجة                                                                                                           |
| `auto/fast`         | يفضل الكمون المنخفض ومقدمي الخدمات الصحية                                                                                                  |
| `auto/cheap`        | الأوزان الموفرة للتكلفة: تفضل أسعار الكتالوج المنخفضة؛ يحافظ على لزوجة LKGP ، وليس من النوع الأول الأرخص الصارم                            |
| `auto/subscription` | الحصة المضمنة في الخطة فقط، والتي تم التحقق منها بشكل مباشر؛ يُرجع التجمع الفارغ HTTP 503، ولا يعد احتياطيًا مفوترًا أبدًا                 |
| `auto/thrifty`      | اشتراك → بدون مفتاح → مجاني → رخيص → premium، درجة واحدة في كل مرة؛ يمكن الفاتورة                                                          |
| `auto/offline`      | يفضل توفر الحصص وصحة مقدم الخدمة (حزمة `offline-friendly` )؛ لا تزال طلبات — للاستدلال دون اتصال بالإنترنت تذهب إلى موفري الخدمات البعيدين |
| `auto/smart`        | أوزان الجودة أولاً بمعدل استكشاف 10%                                                                                                       |
| `auto/lkgp`         | LKGP صريح، بنفس أوزان `auto` الافتراضية                                                                                                    |
| `auto/chaos`        | لوحة متوازية تحتوي على نموذج واحد لكل مزود، وما يصل إلى خمسة بشكل افتراضي، وتعرض إجابة واحدة                                               |

تحتفظ متغيرات الوزن بثبات LKGP ، لذا يعبر `fast` و `cheap` عن التفضيلات بدلاً من ضمان أقل زمن وصول أو سعر لكل طلب. يقوم `auto/chaos` بإجراء مكالمات متعددة للمنبع. قد تستخدم `auto/thrifty` السعة المدفوعة؛ تعتمد العودة إلى حصة الخطة على تجديد الأهلية وفترة تباطؤ الاتصال، وليس فقط وقت إعادة التعيين. راجع [توجيه الاشتراك أولاً](./SUBSCRIPTION_LADDER.md).

### تكوين الطبقة × (`auto/<category>:<tier>`)

لاحقات نمط OpenRouter منفصلة** أي نوع من الطريق** (الفئة) من** كيفية تحسينه** (الطبقة)، حتى تتمكن من تأليفها بحرية (#4235 Phase B, `open-sse/services/autoCombo/suffixComposition.ts`):

- **فئات** : `coding` · `reasoning` · `vision` · `chat` · `multimodal`. `vision`/`multimodal` يحتفظ بالنماذج القادرة على الرؤية؛ `reasoning` يحتفظ بنماذج reasoning/thinking. لا يضيف `coding` و `chat` مرشحًا للقدرة. تحدد الفئات غير المخصصة للدردشة أوزان الجودة أولاً قبل تجاوز أي طبقة.
- **طبقات** (اختر أوزان التسجيل / مرشح المجمع): `fast` (الشحن السريع) · `cheap` (الاسم المستعار `floor`، موفر التكلفة) · `reliable` (استقرار زمن الاستجابة لقاطع الدائرة الصحية + ) · `free` / `pro` (قم بتصفية المجمع حسب طبقة الطراز عبر `classifyTier` — الطبقة المجانية مقابل premium). يطبق `subscription` و `thrifty` [سلم الاشتراك](./SUBSCRIPTION_LADDER.md) القائم على الاتصال.

| مثال                   | يقرر ل                                                                         |
| ---------------------- | ------------------------------------------------------------------------------ |
| `auto/coding:fast`     | التجمع المؤهل، الأوزان ذات الكمون المنخفض                                      |
| `auto/coding:cheap`    | المجموعة المؤهلة، الأوزان الموفرة للتكلفة (الاسم المستعار `auto/coding:floor`) |
| `auto/reasoning:pro`   | موديلات reasoning/thinking فقط، الطبقة المميزة                                 |
| `auto/vision`          | نماذج قادرة على الرؤية مع أوزان الجودة أولاً                                   |
| `auto/multimodal:free` | الطرازات التي تدعم الوسائط المتعددة، الطبقة المجانية فقط                       |

أي `auto/<category>[:<tier>]` صالحة تحل عند الطلب؛ يتم الإعلان عن مجموعة فرعية منسقة في `/v1/models` ولوحة المعلومات (`AUTO_SUFFIX_VARIANTS` في `open-sse/services/autoCombo/builtinCatalog.ts`). تصفية Category/tier هي** فشل مغلقة افتراضيا** : إذا لم تتطابق أي نماذج مؤهلة، فإن المجموعة الافتراضية تحتوي على تجمع فارغ وسيقوم محلل الدردشة بإرجاع HTTP 503 (`src/sse/handlers/chatHelpers.ts`). المرشح هو `narrowPoolByCategoryTier` في `open-sse/services/autoCombo/virtualFactory.ts`.

يقوم `OMNIROUTE_AUTO_FREE_FALLBACK_TO_FULL_POOL=true` باستعادة احتياطي category/tier القديم إلى المجموعة الكاملة عندما لا يتطابق الفلتر مع أي شيء؛ يمكن أن يؤدي هذا إلى تجاهل الطبقة المطلوبة أو قيد القدرة. لا تستخدم عوامل تصفية عائلة النماذج هذا الإجراء الاحتياطي أبدًا، ولا يزال توجيه الاشتراك فقط يتطلب سعة مضمنة في الخطة تم التحقق منها.

> **الذكاء النموذجي المباشر:** يتم إبلاغ لياقة التوجيه التلقائي عن طريق البث المباشر** الساحة ELO** تصنيفات +** models.dev** بيانات الطبقة عندما تكون علامة `ARENA_ELO_SYNC_ENABLED` قيد التشغيل (تعود إلى خريطة اللياقة الثابتة بخلاف ذلك).

**كيفية الاستخدام:**

```bash
# Any IDE or CLI tool that supports OpenAI format
Base URL: http://localhost:20128/v1
API Key:  <your-endpoint-key>

# In your code/config, set model to:
model: "auto"                 # balanced default
model: "auto/coding"          # favor coding task fit
model: "auto/fast"            # favor lower latency
model: "auto/cheap"           # favor lower catalog cost
```

**ماذا يحدث:**

1. يكتشف OmniRoute البادئة `auto/` في `src/sse/handlers/chat.ts`
2. الاستعلامات كافة** اتصالات المزود النشطة** من قاعدة البيانات
3. يطبق عوامل تصفية بيانات الاعتماد ورؤية النموذج والأهلية
4. إنشاء مرشحات provider/model منطقية من النماذج المتاحة، مع الاحتفاظ بالقوائم المسموح بها للحسابات المؤهلة للإرسال
5. يبني أ** التحرير والسرد الظاهري** في الذاكرة (غير مخزنة في DB)
6. المسارات باستخدام إستراتيجية ملف تعريف الوزن المتغير + LKGP

**الخصائص الرئيسية:**

- ✅** تشغيل دائمًا:** لا يوجد تبديل، لا إنشاء التحرير والسرد، لا حاجة للتكوين
- ✅** متحرك:** يعكس مقدمي الخدمات المتصلين الحاليين تلقائيًا
- ✅** ثبات الجلسة:** يضمن LKGP إعطاء الأولوية لآخر مزود ناجح
- ✅** علم بالحسابات المتعددة:** يحتفظ مرشحو provider/model المنطقيون بالقوائم المسموح بها للحسابات المؤهلة
- ✅** لا يلزم التحرير والسرد المحفوظ:** يبقى التكوين الظاهري في الذاكرة؛ لا يزال من الممكن أن تستمر مقاييس التوجيه العادية وحالة وقت التشغيل

### التحكم المرشح لكل مفتاح (#7819، المستوى 1 + 2)

`GET /v1/auto-combo/{channel}/candidates` (`{channel}` = اللاحقة بعد `auto/`، أو `auto` الحرفي للقناة الأساسية) هو** للقراءة فقط** نقطة النهاية التي تسرد مجموعة المرشحين الحالية لقناة `auto/*` المزينة بإمكانية الوصول المباشر، وإعادة استخدام قراءات المرونة الحالية (لا تستخدم الكسارة الأولية `state`):

- مزود قاطع الدائرة — `getCircuitBreaker(provider).getStatus()` / `.canExecute()`
- اتصال التهدئة — `rateLimitedUntil` / `testStatus` على صف `provider_connections` الذي تم حله
- نموذج تأمين — `isModelLocked(provider, connectionId, model)`

يحمل كل مرشح أيضًا علم `excluded` الخاص بمفتاح API. يتم تخزين الاستثناءات لكل مفتاح واجهة برمجة التطبيقات ( جدول `auto_candidate_overrides` ، ترحيل `128`) — OmniRoute هو مستأجر فردي بدون جدول `users` ، لذا `apiKeyId` هي أقرب هوية حقيقية لكل متصل — ويتم فرضها عند نقطة تجمع المرشحين في `open-sse/services/autoCombo/virtualFactory.ts` عبر `filterExcludedCandidates()` النقي الذي تم اختباره بواسطة الوحدة (`open-sse/services/autoCombo/candidateOverrides.ts`). الفلتر هو** فشل مفتوح** : يؤدي كل من عدم تعيين apiKeyId/channel أو فشل بحث DB إلى ترك المجموعة دون تصفية، لذلك يرى المشغل الذي لم يتم تكوين تجاوزات أن التوجيه مطابق لما قبل هذه الميزة.

**تم تأجيله لمسألة لاحقة:** أوزان كل مرشح + ترتيب صريح (المستوى 3 — يغذي مسارات استراتيجية weighted/priority الحالية) وتثبيت استراتيجية `combo.ts` محددة لكل قناة `auto/*` (المستوى 4). راجع خطة #7819 للسؤال المفتوح حول ما إذا كان يجب أن تظل التجاوزات لكل مفتاح واجهة برمجة التطبيقات (API) أم أن تصبح عالمية في ضوء نموذج المستأجر الفردي.

**خلف الكواليس:**

```txt
Request: { model: "auto/coding" }
   ↓
src/sse/handlers/chat.ts detects prefix
   ↓
createVirtualAutoCombo('coding') → candidatePool from active connections
   ↓
handleComboChat (same engine as persisted combos)
   ↓
Auto-scoring selects best provider/model per request
```

**ملفات التنفيذ:**

| ملف                                                       | غاية                                     |
| --------------------------------------------------------- | ---------------------------------------- |
| `open-sse/services/autoCombo/autoPrefix.ts`               | محلل البادئة (`parseAutoPrefix`)         |
| `open-sse/services/autoCombo/virtualFactory.ts`           | ينشئ كائنات `AutoComboConfig` الافتراضية |
| `open-sse/services/autoCombo/providerRegistryAccessor.ts` | ربط اختبار للسخرية من تسجيل الموفر       |
| `src/sse/handlers/chat.ts`                                | التكامل: ماس كهربائى للبادئة التلقائية   |
| `src/shared/constants/providers.ts`                       | دخول نظام `SYSTEM_PROVIDERS.auto`        |

## تفضيلات الحساب للمجموعات التلقائية المحفوظة

يقدم المحرر التلقائي الذكي خيارًا اختياريًا** تفضيلات الحساب** قسم. يمكن أن يكون كل اتصال مفضلاً أو عاديًا (الافتراضي) أو احتياطيًا أو مستبعدًا. يمكن لاتصالات متعددة مشاركة الطبقة. التحديد التلقائي ضمن الطبقة المؤهلة الأولى، مع الاحتفاظ بسلوك scoring/router الخاص بها هناك؛ وتتساقط المحاولات الفاشلة على بقية الحسابات الملموسة، مفضلة قبل العادية قبل الاحتياطية. لا يتم استخدام الاتصالات المستبعدة أبدًا بواسطة هذا التحرير والسرد.

يتم تخزين الإعداد كـ `config.accountPreferences`، مرتبطًا بالاتصال ID:

```json
{
  "accountPreferences": {
    "connection-a": "preferred",
    "connection-b": "preferred",
    "connection-c": "reserve",
    "connection-d": "excluded"
  }
}
```

تحتفظ الخريطة المحذوفة أو الفارغة بالتوجيه الحالي. لا تعمل التفضيلات على تمكين الاتصالات المعطلة أو منح الوصول إلى مفتاح API أو استعادة المرشحين المحظورين أو تجاوز عمليات التحقق من الميزانية. تقتصر كل محاولة على اتصالها الملموس، لذلك لا يمكن للحساب الاحتياطي الانتقال إلى المستويات خلف جهاز التوجيه المجمع. قد يحتفظ تقارب الجلسة الحالية بحساب مؤهل؛ باستثناء الحساب المرتبط بمحطات التوقف الأصلية التي تتحول بدلاً من تغيير الحسابات بصمت.

تستخدم التفضيلات التي تم تكوينها المسار التلقائي المدرك للحساب: لا يتم إرسال ذاكرة التخزين المؤقت غير المرتبطة للسياق، والخطوط الذكية، واختصارات الفوضى والظل. تم تعطيل تحوط المضاربة لهذه الطلبات، لذا لا يمكن للحسابات الاحتياطية أن تتنافس مع الحسابات المفضلة. استراتيجيات التحرير والسرد الأخرى لا تفسر هذا الإعداد. يؤدي تغيير التحرير والسرد بعيدًا عن Auto إلى الاحتفاظ بالتفضيلات المحفوظة للتبديل مرة أخرى لاحقًا.

## أسماء التحرير والسرد التي تتطابق مع معرف النموذج الحقيقي

التحرير والسرد الذي يكون `name` مطابقًا لمعرف النموذج المجرد (على سبيل المثال، التحرير والسرد المسمى `gpt-5.5`) هو** نمط متعمد ومدعوم** ، ليس خطأً: إنها آلية التراجع لموفر معرف النموذج الموثقة في [#6940](https://github.com/cheaper-inference/OmniRoute/issues/6940). نظرًا لأنه يتم التحقق من دقة التحرير والسرد قبل تحليل معرف النموذج العاري (`getComboForModel()` في `src/sse/services/model.ts`) ، يتم توجيه طلب المعرف المجرد `gpt-5.5` عبر أهداف التحرير والسرد (على سبيل المثال `acme-responses/gpt-5.5`، `backup-responses/gpt-5.5`) بدلاً من مباشرة إلى موفر واحد — وهذا يعيد استخدام أسبقية التحرير والسرد قبل إعادة الكتابة المصممة لـ [#3227/#3233](https://github.com/cheaper-inference/OmniRoute/issues/3227) ويتم اختبار الانحدار بواسطة `tests/unit/responses-combo-resolution-3227.test.ts` و `tests/unit/combo-name-codex-responses-rewrite.test.ts`.

يعد إنشاء مجموعة تحرير وسرد أو إعادة تسميتها لاسم يظلل معرف النموذج الحقيقي** رفض أبدا** — القيام بذلك من شأنه أن يكسر سير العمل الموثق هذا. بدلاً من ذلك (#8530)، يقوم `POST /api/combos` و `PUT /api/combos/[id]` بإرفاق حقل `warning` غير محظور بالاستجابة عندما يصطدم الاسم (الجديد) بمعرف نموذج حقيقي:

```json
{ "warning": { "code": "COMBO_NAME_SHADOWS_MODEL", "modelId": "gpt-5.5", "providerId": "openai" } }
```

عند التمهيد، يسجل `scanComboModelNameCollisionsAtBoot()` (`src/instrumentation-node.ts`) أيضًا تحذير `[STARTUP]` من سطر واحد يسرد كل مجموعة موجودة تظلل معرف النموذج، لذلك يكون لدى المشغلين الذين يصلون إلى هذا عن طريق الصدفة (وليس عن قصد، لكل #6940) إشارة. مساعد الكشف يعيش في `src/lib/combos/modelNameCollision.ts`.

## استدعاء التحرير والسرد المخصص من العميل

يتم استخدام المجموعات المستمرة (إعدادات → Combos) فقط عندما يرسل العميل المجموعة** الاسم الدقيق** في حقل `model` — لا يوجد أي مطابقة غامضة أو جزئية لاسم التحرير والسرد، ولا توجد بادئة `auto/`. ترتيب القرار (`getComboForModel()` في `src/sse/services/model.ts`):

1. مطابقة تامة لاسم التحرير والسرد (`model: "my-combo"`) ،
2. `combo/<name>` (`model: "combo/my-combo"`)،
3. تعيينات نموذج → combo glob (`/api/model-combo-mappings`).

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"my-combo","messages":[{"role":"user","content":"Hello"}]}'
```

اثنين من المزالق المشتركة:

- **`auto` لا يستخدم المجموعات الخاصة بك.** يقوم `auto`/`auto/*` ببناء مجموعة مرشحات ذات تكوين صفري خاص به ويستشير فقط المجموعات المستمرة إذا تم تسمية المجموعة حرفيًا `auto` (غير مستحسن). للتوجيه عبر التحرير والسرد، أرسل اسمه الدقيق — وليس `auto`.
- **`openrouter/auto` هو منتج OpenRouter حقيقي مدفوع الأجر** ("أفضل ما هو متاح تلقائيًا")، وليس الاسم المستعار OmniRoute. إنه إدخال النموذج الثابت الوحيد لسجل OpenRouter (`open-sse/config/providers/registry/openrouter/index.ts`) ويتم إصدار فاتورة به بشكل منفصل. استخدم الإعدادات → Routing → لإخفاء النماذج المدفوعة لاستبعادها من مجموعات `auto`.

انظر [#7992](https://github.com/cheaper-inference/OmniRoute/issues/7992) و [#7111](https://github.com/cheaper-inference/OmniRoute/issues/7111) للتعرف على الارتباك الأصلي في هذه المستندات.

## كيف يعمل (المجموعات التلقائية المستمرة)

يقوم محرك التحرير والسرد التلقائي بتسجيل المرشحين provider/model بشكل ديناميكي باستخدام** 16 العوامل المعلنة** (محدد في `open-sse/services/autoCombo/scoring.ts` → `DEFAULT_WEIGHTS`). مجموع الأوزان الافتراضية هو `1.0`؛ تتم إعادة تطبيع الأوزان المخصصة بواسطة `normalizeScoringWeights()`. ثلاثة عوامل لها وزن صفر افتراضيًا: `cacheAffinity` و `resetWindowAffinity` و `reliability`. حزم الوضع تعطي `reliability` وزن `0.03`، أو `0.04` في `reliability-first`؛ يحمل `quality` `0.03` افتراضيًا وفي `quality-first` و `0.02` في الحزم الأخرى. يعمل `cacheAffinity` أيضًا على إلغاء البيانات المكررة في ذاكرة التخزين المؤقت خارج النتيجة المرجحة.

> **حصة غير قابلة للقراءة (#15347).** عندما يكون لدى موفر خدمة جلب الحصص ولكنه لا يُرجع أي شيء قابل للقراءة (فشل الجلب، أو فقدان بيانات الاعتماد، أو استخدام الرسائل فقط، أو لقطة مشوهة بدون `windows` قابل للتحليل ولا `percentUsed` محدود، بما في ذلك `percentUsed: null`)، يسجل المرشح `0` على محور `quota` ويتم ضرب نتيجته النهائية بـ `UNREADABLE_QUOTA_SOFT_DEPRIORITIZE_FACTOR` (0.5، `autoStrategy.ts`) ، وهو نفس نمط العقوبة الميسرة مثل حالة الاتصال عقوبة. تعتبر قراءة الاستخدام الفاشلة دليلاً على القياس عن بعد، وليس الموفر، لذا فهي تحتل مرتبة أقل تمامًا من أي قراءة حقيقية، بما في ذلك قراءة -used المؤكدة بنسبة 100%، ولكن لا يتم حظرها أو طردها مطلقًا. يقوم مقدم الخدمة الذي ليس له حد أقصى بإبلاغ `unlimited: true` ويسجل الحصة الكاملة؛ الموفر الذي ليس لديه أداة جلب حصص مسجلة ليس لديه مصدر قياس عن بعد على الإطلاق ويحتفظ بالإعداد الافتراضي `100`.

**مجموع:** `0.1429 + 0.1605 + 0.1429 + 0.1143 + 0.0762 + (7 × 0.0476) + 0.00 + 0.00 + 0.03 + 0.00 = 1.0` كما هو معلن في `DEFAULT_WEIGHTS`; تتم إعادة تطبيع الأوزان التي قام المستخدم بتكوينها إلى توزيع بواسطة `normalizeScoringWeights()` قبل التسجيل.

### عناصر التحكم لكل طلب (الترويسات) — #6023 / #6024 / #6025 / #3470

يمكن توجيه مجموعة `auto` **لكل طلب** عبر ثلاث ترويسات، دون تعديل الإعدادات المخزنة
للمجموعة. لا تنطبق هذه الترويسات إلا على استراتيجية `auto` وعلى الطلب الذي
يحملها فقط؛ وتُستخدم قيم `modePack`/`budgetCap`/`budgetFallback` المحفوظة للمجموعة
عند غياب الترويسة.


تُعد عملية الحسم دالة خالصة (`open-sse/services/autoCombo/requestControls.ts`)؛ وتُمرَّر
القيم المحسومة إلى مدخلات المحرك الحالية `config.modePack` / `config.budgetCap` /
`config.budgetFallback`. تحدد قيمة `config.budgetFallback` المخزنة للتوليفة ("strict" |
"cheapest") السياسة الدائمة؛ وتتجاوزها الترويسة لطلب واحد فقط.

## جميع استراتيجيات التوجيه

يدعم محرك التحرير والسرد OmniRoute** 22 استراتيجية توجيه** (معلن في `src/shared/constants/routingStrategies.ts` → `ROUTING_STRATEGY_VALUES`). يتم الكشف عن محرك Auto Combo نفسه ضمن إستراتيجية `auto` ؛ الآخرون متاحون للمجموعات المستمرة.

| :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `priority`          | قائمة مرتبة للهدف الأول ذات أولوية واضحة                                                                                                                                                                                                                                                                                                                               |
| `weighted`          | السحب العشوائي النسبي لكل طلب حسب الوزن المستهدف؛ تصبح الأهداف الأخرى احتياطية (انظر أدناه)                                                                                                                                                                                                                                                                            |
| `round-robin`       | التنقل بين الأهداف بالترتيب، على دفعات ثابتة (3 نجاحات لكل هدف بشكل افتراضي؛ انظر أدناه)                                                                                                                                                                                                                                                                               |
| `context-relay`     | ترتيب الأولوية بالإضافة إلى ملخص التسليم عندما تنتقل المحادثة إلى حساب آخر                                                                                                                                                                                                                                                                                             |

تقوم إستراتيجية `jev` بإجراء مكالمات TypeSafe مدفوعة الأجر فقط عند تمكين `COMBO_JEV_STRATEGY_ENABLED`. مفتاح TypeSafe المخزن وحده لا يمكّنه. مع إزالة العلم، يحتفظ السرد بأمر المشغل دون إجراء هذا الاتصال (`open-sse/services/combo/jevAsk.ts`).

### دلالات `weighted`

`weighted` هو أ** السحب العشوائي النسبي لكل طلب** (`open-sse/services/combo/targetSorters.ts` → `selectWeightedTarget`)، وليس هدف التعادل:

- يرسم كل طلب** واحد** خطوة مع احتمال `weight / totalWeight`; يتم ترتيب الخطوات المتبقية حسب الوزن التنازلي كسلسلة احتياطية لهذا الطلب.
- خطوة وزنها `0` (أو مفقودة) هي** لم يتم رسمها أبدًا** في حين أن أي خطوة أخرى لها وزن > 0 — فإنها يمكن أن تكون بمثابة خطوة احتياطية فقط بعد فشل الخطوة المرسومة. فقط عندما** الجميع** الأوزان 0 هل يصبح الاختيار موحدًا.
- تتم إزالة الخطوات التي تكون جميع أهدافها قاطع دائرة موفر — غير متاح `OPEN` وفترة تباطؤ الاتصال وقفل النموذج — من السحب قبل حدوثه (`open-sse/services/combo/targetResolution.ts`)، لذلك يمكن لخطوة صحية واحدة أن تفوز بكل طلب مؤقتًا.
- `stickyWeightedLimit` (تكوين التحرير والسرد، إيقاف `1` = الافتراضي) يثبت الخطوة المرسومة للعديد من النجاحات المتتالية قبل إعادة الرسم.

للتناوب الصارم استخدم `round-robin`؛ الأوزان المتساوية على `weighted` تعطي إحصائية — وليس رصيد — صارمًا.

### وضع خط أنابيب الوكيل

يمكن لمجموعة `pipeline` التي تحتوي على نموذجين على الأقل الاشتراك في توجيه planner/executor باستخدام `config.agenticOrchestration.enabled`. الهدف الأول يملك التخطيط والإجابات النهائية؛ يرسل الهدف الثاني مكالمات الأداة الأصلية للعميل. يكتشف OmniRoute استمرارية نتيجة الأداة من بروتوكول الطلب، ويسأل المخطط عما إذا كانت هناك حاجة إلى جولة أداة أخرى، ويجعل المنفذ أو المخطط ديناميكيًا الخطوة النهائية التي تواجه العميل.

تطبق `config.agenticOrchestration.contextCompaction` الاختيارية ميزانية حمولة منفصلة قبل إرسال كل مخطط أو منفذ. تمكينه صراحة:

```json
{
  "enabled": true,
  "defaultMaxChars": 400000,
  "targetRatio": 0.72,
  "toolResultMaxChars": 24000,
  "modelMaxChars": { "provider/planner": 175000, "provider/executor": 300000 }
}
```

هذه هي ميزانيات أحرف JSON المتسلسلة التي يحددها المشغل، وليست نوافذ سياق الرمز المميز أو حدود المنبع المضمونة. النموذج الدقيق IDs يتجاوز النموذج الافتراضي. فوق الحد الأدنى، يزيل الضغط تعريفات الأداة المتطابقة، ويقطع أدلة الأداة كبيرة الحجم بملخص، ويزيل مجموعات السجل الكامل القديمة باتجاه النسبة المستهدفة. فهو يحتفظ بتعليمات system/developer ، وآخر طلب للمستخدم، وآخر جولة للأداة بما في ذلك calls/results المتوازي، وتعليمات التوجيه الرائدة لـ Gemini. يتم الاحتفاظ بتعليمات المستوى الأعلى وإعدادات الأداة. تسجل علامة الإغفال التاريخ المحذوف؛ وهذا تشذيب حتمي، وليس تلخيصًا دلاليًا. إذا كان السياق المثبت لا يزال يتجاوز الميزانية، فسيقوم الطلب بإرجاع 413 قبل الاتصال بالنموذج. مع تعطيل الضغط أو أقل من الحد، يمر الطلب دون تغيير.

في استمرارات نتيجة الأداة، يتوقف OmniRoute أيضًا عن التنفيذ عندما تكرر جولتان مكتملتان متتاليتان نفس استدعاءات الأداة مع نتائج غير متغيرة، أو عندما تفشل كل نتيجة محددة بشكل واضح في جولتين متتاليتين. تسمح النتائج المتغيرة بالمكالمات المتكررة (على سبيل المثال، الاستقصاء). يقوم الحارس بإعادة التعيين بناءً على طلب مستخدم جديد، ويجمع المكالمات المتوازية في جولة واحدة، ويدعم Anthropic، وإكمالات الدردشة، والردود، وتاريخ Gemini. يتلقى المخطط السبب ويمتلك الإجابة النهائية حتى لو طلب جولة أخرى من الأدوات.

يتم طلب نماذج إضافية بعد الهدف الثاني من خلال النسخ الاحتياطية للمنفذ. تتقدم استجابة HTTP الفاشلة أو استثناء النقل إلى المنفذ التالي، ويحمل نفس قرار المخطط والأدوات الأصلية ولكن خطوة ذلك المنفذ تحث على الاتصال وحله. يتم إرجاع الاستجابة الناجحة الأولى دون تغيير، بما في ذلك تدفق SSE ؛ لا يمكن إعادة محاولة الفشل بعد بدء البث الناجح هنا. إذا فشل جميع المنفذين، فسيتم إرجاع الفشل الأخير. العميل يلغي إيقاف الإرسال.

```json
{
  "strategy": "pipeline",
  "models": [{ "model": "provider/planner" }, { "model": "provider/executor" }],
  "config": {
    "agenticOrchestration": { "enabled": true, "maxToolRounds": 8 }
  }
}
```

قد يقوم المنفذ بإصدار مكالمات مستقلة متعددة في استجابة واحدة. تتم معالجة المكالمات التابعة في دورات لاحقة لنتائج أداة العميل، مع قيام المخطط بمراجعة كل نتيجة. يتم تعيين `maxToolRounds` افتراضيًا على `8` ويقبل `1`–`32`؛ وبمجرد الوصول إليه، يجب على المخطط أن ينتج أفضل إجابة نهائية متاحة. يتم تخزين قرارات المخطط الداخلي مؤقتًا، بينما تحافظ الاستجابة المحددة التي تواجه العميل على تفضيل البث الأصلي.

### `round-robin` دفعة لزجة وتوسيع الحساب

يتم تجميع روبن الجولة، وليس طلبًا واحدًا لكل خطوة:

- `stickyRoundRobinLimit` (تكوين التحرير والسرد، ثم `comboStickyRoundRobinLimit`، ثم `settings.stickyRoundRobinLimit`، الافتراضي** 3** ) يحتفظ بنفس الهدف للعديد من النجاحات المتتالية قبل التناوب. قم بتعيين تجاوز التحرير والسرد على `1` للتدوير لطلب واحد. يُظهر محرر التحرير والسرد القيمة الفعالة والطبقة التي جاءت منها.
- `connectionAwareExpansion` (تكوين التحرير والسرد، ثم الإعدادات، الافتراضي** خطأ شنيع** ) يوسع كل خطوة على مستوى مقدم الخدمة إلى أهداف لكل حساب قبل التناوب. استراتيجيات المجموعة-ب (الأولوية، الموزونة، المستديرة، العشوائية، p2c، الأقل استخدامًا، التكلفة المحسنة، lkgp، التعبئة أولاً، العشوائية الصارمة، تحسين السياق، تحسين ذاكرة التخزين المؤقت، ترحيل السياق، الاندماج، خط الأنابيب، jev) تحافظ على عرض على مستوى الموفر حتى يتم تشغيله. يكشف محرر التحرير والسرد عن الوراثة / التشغيل / الإيقاف ؛ يستخدم الوراثة الإعداد الافتراضي العالمي (إيقاف).
- التوجيه المحلي لذاكرة التخزين المؤقت (`promptCacheAffinityEnabled`، default** حقيقي** ) يعيد ترتيب الاتصالات المثبتة بحيث تظل مفاتيح ذاكرة التخزين المؤقت المطابقة في حساب واحد. وله الأسبقية على التدوير الدائري والتدوير الموزون عبر الخطوات المثبتة لكل حساب. قم بإيقاف تشغيله ضمن الإعدادات الافتراضية → Combo إذا كنت بحاجة إلى تناوب صارم. لا يوجد تجاوز لكل التحرير والسرد.

بالنسبة للتناوب متعدد الحسابات على نموذج واحد، تفضل** خطوة حساب ديناميكي واحدة** ( `connectionId` فارغة، تجمع كامل) مع حد لزج `1`، وليس ثلاثة `connectionId` s. تنهار الخطوات المثبتة بالإضافة إلى التقارب على نفس الحساب حتى أثناء تقدم عداد RR.

## استراتيجية Fusion

تُعد `fusion` الاستراتيجية الوحيدة التي **لا** تختار هدفًا واحدًا. فهي توزّع الموجّه
على **كل نماذج اللجنة بالتوازي**، ثم يقوم **نموذج حَكَم** قابل للتهيئة بتجميع
إجابة نهائية واحدة من جميع ردود اللجنة. نُقلت من المشروع الأصلي `decolua/9router`
(تصميم Fusion الخاص بـ OpenRouter)؛ والتنفيذ موجود في `open-sse/services/fusion.ts`.

آلية العمل:

0. **تجاوز الطلبات المتضمنة أدوات** — يتخطى الطلب الذي يحمل مصفوفة `tools` غير فارغة، مع
   عدم تعيين `tool_choice` صراحةً إلى `"none"`، اللجنة بالكامل: إذ يُوجَّه مباشرةً إلى
   نموذج واحد (الحَكَم المُهيّأ، أو `panel[0]`) مع تمرير `tools`/`tool_choice`
   دون تعديل. لا يملك أعضاء اللجنة وصولًا إلى الأدوات، كما أن توجيه التجميع الخاص بالحَكَم
   يثبط إصدار استدعاءات الأدوات، وبذلك تحصل التطبيقات العميلة الوكيلة/المستدعية للأدوات
   على قرار حقيقي بشأن استدعاء الأداة بدلًا من نص مُجمَّع (#6771).
1. **التوزيع المتوازي** (للطلبات غير المتضمنة أدوات فقط) — يُرسل الموجّه إلى كل نماذج
   اللجنة دفعةً واحدة، مع فرض عدم استخدام البث وإزالة الأدوات (يحتاج الحَكَم إلى
   نصوص كاملة لتجميعها).
2. **الجمع وفق النصاب وفترة السماح** — بمجرد وصول `minPanel` من الإجابات، يبدأ مؤقت
   سماح قصير للمتأخرين، ثم تتابع Fusion بما جُمع من إجابات.
   يحد ذلك من تأثير أبطأ نموذج على الوقت الإجمالي، ضمن مهلة قصوى صارمة.
3. **تجميع الحَكَم** — تُخفى هويات إجابات اللجنة (`Source 1`، `Source 2`، … — كي
   يقيّم الحَكَم المضمون لا العلامة التجارية للنموذج) وتُسلَّم إلى الحَكَم، الذي يحلل
   التوافق / التناقضات / التغطية الجزئية / الرؤى الفريدة / النقاط العمياء، ثم
   يكتب إجابة موثوقة **واحدة**. يحتفظ استدعاء الحَكَم بقيمة `stream` الأصلية الخاصة
   بالعميل وبالأدوات، لذا يظل البث واستخدام الأدوات في المراحل اللاحقة ممكنين.
4. **التدهور السلس** — 0 من إجابات اللجنة ← `503`؛ ناجٍ واحد فقط ← تُعاد تلك الإجابة
   مباشرةً (فلا يوجد ما يمكن دمجه)؛ واللجنة ذات النموذج الواحد تُجيب مباشرةً.

يمكن أيضًا أن يكون عضو اللجنة خطوة `combo-ref` ‏(`{kind: "combo-ref", comboName: "..."}`) تشير
إلى مجموعة أخرى — وتُحل باعتبارها **صوتًا واحدًا من أصوات اللجنة كصندوق أسود** (عملية توجيه
تكرارية كاملة إلى المجموعة المشار إليها، وليست توزيعًا متوازيًا على أهداف تلك المجموعة)،
مع وسائل الحماية نفسها من العمق/الدورات التي تستخدمها بالفعل كل استراتيجية أخرى تستهلك
combo-ref ‏(#6764).

### التهيئة

تُضبط الإعدادات في كائن `config` الخاص بالمجموعة (دون ترحيل للمخطط — إذ يعيد استخدام
جدول `combos` الحالي):

| الحقل                                    | النوع    | القيمة الافتراضية   | الغرض                                                                              |
| :--------------------------------------- | :------- | :------------------ | :--------------------------------------------------------------------------------- |
| `config.judgeModel`                      | `string` | أول نموذج في اللجنة | النموذج الذي يجمع الإجابة النهائية                                                 |
| `config.fusionTuning.minPanel`           | `number` | `2`                 | عدد الإجابات الناجحة المطلوبة قبل بدء مؤقت السماح (مقيّد بالنطاق `[2, panelSize]`) |
| `config.fusionTuning.stragglerGraceMs`   | `number` | `8000`              | مدة انتظار المتأخرين بعد بلوغ النصاب                                               |
| `config.fusionTuning.panelHardTimeoutMs` | `number` | `90000`             | حد أقصى مطلق كي لا يتمكن نموذج عالق من تعطيل الطلب                                 |

توجد القيم الافتراضية في `FUSION_DEFAULTS` ‏(`open-sse/services/fusion.ts`).

```bash

  -H "Content-Type: application/json" \
  -d '{

    "strategy": "fusion",
    "targets": [
      { "model": "cc/claude-opus-4-7" },
      { "model": "cx/gpt-5.5" },
      { "model": "glm/glm-5.1" }
    ],
    "config": {
      "judgeModel": "cc/claude-opus-4-7",
      "fusionTuning": { "minPanel": 2, "stragglerGraceMs": 8000, "panelHardTimeoutMs": 90000 }
    }
  }'
```

ثم استدعِها مثل أي مجموعة أخرى: `{"model":"fusion-panel","messages":[...]}`.

## مصنع Auto-Combo الافتراضي

لا يتطلب محرك Auto Combo مجموعات مُعرَّفة مسبقًا. بدلًا من ذلك، ينشئ `open-sse/services/autoCombo/virtualFactory.ts` المرشحين أثناء التشغيل:

1. يستدعي `getProviderConnections({ isActive: true })` (جميع الاتصالات المُمكَّنة)
2. يرشّح الاتصالات التي لديها بيانات اعتماد صالحة (مفتاح API أو رمز OAuth غير منتهي الصلاحية عبر `hasUsableOAuthToken()`)
3. يقارنها مع `getProviderRegistry()` للتحقق من توافر النماذج والأسعار
4. ينشئ `VirtualAutoComboCandidate` لكل صف `(provider, model, connection)`
5. يختار `connection.defaultModel` (أو النموذج الأول في السجل) بوصفه هدف التوجيه
6. يمنح كل مرشح درجة باستخدام `scorePool()` ذي العوامل الـ16 وحزمة أوزان المتغير
7. يعيد `AutoComboConfig` الناتج والموجود في الذاكرة إلى `handleComboChat()` — ولا يتم حفظه مطلقًا في قاعدة البيانات

يعني هذا أن **إضافة مزود جديد مع تمكين `auto/*` توسّع مجموعة المرشحين تلقائيًا** — دون الحاجة إلى تعديل المجموعة يدويًا. يُعاد إنشاء المجموعة الافتراضية لكل طلب، ولذلك تُلتقط الاتصالات المضافة حديثًا أو التي استعادت حالتها السليمة فورًا.

## التعافي الذاتي

- **الاستبعاد المؤقت**: الدرجة < 0.2 ← الاستبعاد لمدة 5 دقائق (تراجع تدريجي، بحد أقصى 30 دقيقة)
- **مراعاة قاطع الدائرة**: OPEN ← استبعاد تلقائي؛ HALF_OPEN ← طلبات فحص
- **وضع الحوادث**: أكثر من 50% في حالة OPEN ← تعطيل الاستكشاف وتعظيم الاستقرار
- **التعافي بعد فترة التهدئة**: بعد الاستبعاد، يكون الطلب الأول بمثابة "فحص" بمهلة زمنية مخفّضة

## استكشاف Bandit

يتم توجيه 5% من الطلبات (قابلة للتهيئة) إلى مزودين عشوائيين لأغراض الاستكشاف. يُعطَّل ذلك في وضع الحوادث.

## API

هنالك** لا توجد نقطة نهاية `POST /api/combos/auto` مخصصة** يتم استهلاك مجموعة — التلقائية بطريقتين:

1. **التكوين الصفري (مستحسن):** أرسل أي طلب لإكمال الدردشة مع `model: "auto"` أو `model: "auto/<variant>"`. يقوم المصنع الافتراضي ببناء التحرير والسرد لكل طلب — بدون ثبات، ولا حاجة إلى مكالمات API.

2. **التحرير والسرد المستمر مع `strategy: "auto"`:** قم بإنشاء مجموعة تحرير وسرد عادية عبر `POST /api/combos` وقم بتعيين `strategy: "auto"` plus `config.auto.weights` / `config.auto.candidatePool`. يتم استخدام نفس محرك التسجيل؛ يتم تخزين التحرير والسرد في `combos` ويمكن إعادة استخدامه بواسطة ID.

للاكتشاف، يقوم `GET /api/combos/auto` بإدراج كل متغير مع مجموعة المرشحين التي تم حلها بالإضافة إلى `context_length` / `max_output_tokens` — MAX عبر نوافذ مجموعة المرشحين. يجب على العملاء (على سبيل المثال، البرنامج المساعد opencode) الإعلان عن هذه القيم بدلاً من `0`: يعطل السياق الصفري الضغط التلقائي للكود المفتوح بالكامل، مما يسمح للجلسات بالنمو حتى تؤدي عملية تطهير محفوظات البوابة إلى تدمير السياق. يعد MAX آمنًا للإعلان لأن التصفية المسبقة لسياق التحرير والسرد التلقائي توجه الطلبات كبيرة الحجم إلى المرشحين ذوي النوافذ الكبيرة.

```bash
# Zero-config usage (no combo creation)
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Hello"}]}'

# Persisted auto combo via the regular combos endpoint
curl -X POST http://localhost:20128/api/combos \
  -H "Content-Type: application/json" \
  -d '{"id":"my-auto","name":"Auto Coder","strategy":"auto","config":{"auto":{"candidatePool":["anthropic","google","openai"],"weights":{"quota":0.15,"health":0.3,"costInv":0.05,"latencyInv":0.35,"taskFit":0.1,"stability":0,"tierPriority":0.05}}}}'
```

### استراتيجيات جهاز التوجيه التلقائي

يمكن لمجموعات `strategy: "auto"` المستمرة تعيين `config.routerStrategy` (أو `config.auto.routerStrategy` القديم) على أحد:

- `rules` — التهديف المرجح الافتراضي
- يحدد `score` — أعلى درجة مرجحة تم تكوينها. تحافظ الروابط الدقيقة على ترتيب المرشحين المحدد؛ عينات `explorationRate` الموجودة من المجموعة الكاملة المصنفة.
- `cost` / `eco` — أرخص مزود صحي
- `latency` / `fast` — أدنى زمن وصول p95 مع عقوبة الموثوقية
- `sla-aware` / `sla` — يفضلون المرشحين الذين يستوفون زمن الوصول p95 ومعدل الخطأ والتكلفة الاختيارية SLOs
- `lkgp` — آخر مزود جيد معروف أولاً
- `nadir` — اسأل قرار [نادر](https://getnadir.com) API الذي نموذج في التجمع يحتاج بسرعة؛ الاشتراك، فشل مفتوح ل `rules`
- `decision` — اسأل محددًا تم تكوينه (TypeSafe System One، أو قرارك الخاص URL، أو أحد نماذج التحرير والسرد الخاصة) أي نموذج في المجموعة يناسب الطلب؛ خلف علامة `COMBO_DECISION_ROUTER_ENABLED` الافتراضية، يمكن فتح الفشل على `rules`

### استراتيجيات جهاز التوجيه بالتفصيل

يعرض محرك التحرير والسرد التلقائي 7 قابلة للتوصيل**RouterStrategy** التطبيقات التي يمكنك تبديلها عبر `config.routerStrategy` (أو `config.auto.routerStrategy` القديم). تختار كل إستراتيجية موفرًا واحدًا من مجموعة المرشحين، مع إعطاء `RoutingContext` (نوع المهمة، تلميحات tool/vision ، تقدير الرمز المميز، سياسة SLA الاختيارية، موفر اختياري لآخر جيد معروف).

#### 1. `rules` (افتراضي) — تسجيل مرجح بـ 16 عاملًا

يلتف محرك التسجيل الحالي. يقوم بتصفية المرشحين لقاطع الدائرة `OPEN` ، ثم يقوم بتشغيل `scorePool()` مع نوع المهمة الحالي و `getTaskFitness()`، واختيار الموفر الذي حصل على أعلى الدرجات.

```ts
class RulesStrategyImpl implements RouterStrategy {
  readonly name = "rules";
  readonly description = "16-factor weighted scoring (see DEFAULT_WEIGHTS)";

  select(pool, context) {
    const eligible = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const ranked = scorePool(
      eligible.length > 0 ? eligible : pool,
      context.taskType,
      undefined,
      getTaskFitness
    );
    return { provider: ranked[0].provider /* ... */ };
  }
}
```

**متى تستخدم** : تقصير. استخدمه عندما تريد مقايضة متوازنة عبر جميع الإشارات.

**الاسم المستعار** : `rules` (بدون اسم مستعار)

---

#### 2. `cost` / `eco` — أرخص مزود صحي

فرز مجموعة المرشحين حسب `costPer1MTokens` (تصاعدي) واختيار الأرخص. تصفية مرشحي `OPEN` أولاً.

```ts
class CostStrategyImpl implements RouterStrategy {
  readonly name = "cost";
  readonly description = "Always selects cheapest available provider";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort((a, b) => a.costPer1MTokens - b.costPer1MTokens);
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**متى تستخدم** : أعباء العمل الحساسة للتكلفة أو معالجة الدُفعات أو المهام الخلفية.

**الأسماء المستعارة** : `cost`، `eco`

---

#### 3. `latency` / `fast` — أدنى زمن وصول p95 مع عقوبة الموثوقية

فرز حسب `p95LatencyMs + (errorRate * 1000)`. تضمن عقوبة معدل الخطأ تصنيف مقدمي الخدمة غير الموثوقين في مرتبة أقل حتى لو كان زمن الاستجابة الاسمي الخاص بهم منخفضًا.

```ts
class LatencyStrategyImpl implements RouterStrategy {
  readonly name = "latency";
  readonly description = "Prioritizes lowest p95 latency with reliability weighting";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort(
      (a, b) => a.p95LatencyMs + a.errorRate * 1000 - (b.p95LatencyMs + b.errorRate * 1000)
    );
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**متى تستخدم** : أعباء العمل الحساسة لزمن الاستجابة مثل الدردشة في الوقت الفعلي، أو الإكمال التلقائي، أو مساعدي البرمجة التفاعلية.

**الأسماء المستعارة** : `latency`، `fast`

---

#### 4. `sla-aware` / `sla` — latency/error/cost SLO الامتثال

يسجل كل مرشح حسب مدى استيفائه لسياسة SLO التي تم تكوينها:

| عامل           | وزن | صيغة                                              |
| -------------- | --- | ------------------------------------------------- |
| درجة الكمون    | 35% | `threshold / max(value, ε)`                       |
| درجة الخطأ     | 35% | `threshold / max(value, ε)`                       |
| النتيجة الصحية | 15% | `1.0` (CLOSED) / `0.5` (HALF_OPEN) / `0.0` (OPEN) |
| درجة التكلفة   | 10% | `threshold / max(value, ε)` أو معكوس تطبيع        |
| درجة الاستقرار | 5%  | الكمون الطبيعي العكسي stddev                      |

عندما `hardConstraints: true`، يتم فرز المرشحين في المقام الأول حسب** درجة الانتهاك** (إلى أي مدى تتجاوز أي SLO)، ثم بالنتيجة المركبة. وإلا فهي مجرد النتيجة المركبة.

```ts
class SLAStrategyImpl implements RouterStrategy {
  readonly name = "sla-aware";
  readonly description =
    "Selects the provider most likely to satisfy latency, error-rate, and cost SLOs";

  select(pool, context) {
    // ... scores each candidate against policy: { targetP95Ms, maxErrorRate, maxCostPer1MTokens, hardConstraints }
  }
}
```

**SLA** (تم تعيينه في تكوين التحرير والسرد):

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "sla-aware",
    "slaTargetP95Ms": 1500,
    "slaMaxErrorRate": 0.05,
    "slaMaxCostPer1MTokens": 5,
    "slaHardConstraints": true
  }
}
```

**متى تستخدم** : أعباء عمل الإنتاج ذات زمن وصول صارم أو معدل خطأ أو ميزانيات تكلفة.

**الأسماء المستعارة** : `sla-aware`، `sla`

---

#### 5. `lkgp` — آخر مزود جيد معروف أولاً

يحاول** آخر مزود جيد معروف** (إذا تم ضبطها) أولاً، ثم تعود إلى استراتيجية `rules`. مفيد لثبات الجلسة — يتعامل نفس المزود مع طلبات المتابعة في المحادثة.

```ts
class LKGPStrategyImpl implements RouterStrategy {
  readonly name = "lkgp";
  readonly description = "Tries last known good provider first, then falls back to rules";

  select(pool, context) {
    if (context.lkgpEnabled === false) {
      return getStrategy("rules").select(pool, context);
    }

    if (context.lastKnownGoodProvider) {
      const candidates = pool.filter(
        (c) => c.provider === context.lastKnownGoodProvider && c.circuitBreakerState !== "OPEN"
      );
      if (candidates.length > 0) {
        return { provider: candidates[0].provider /* ... */ };
      }
    }

    // Fallback to rules strategy
    return getStrategy("rules").select(pool, context);
  }
}
```

**متى تستخدم** : محادثات متعددة المنعطفات حيث تريد من نفس الموفر التعامل مع طلبات المتابعة (على سبيل المثال، للتخزين المؤقت أو استمرارية السياق أو اتساق التسعير).

**الاسم المستعار** : `lkgp` (بدون اسم مستعار)

---

#### 6. `nadir` — اختيار النموذج السريع عبر نادر

كل استراتيجية أعلاه تصنف المرشحين حسب قياسهم عن بعد؛ لا أحد منهم يقرأ الطلب. يرسل `nadir` آخر دور للمستخدم بالإضافة إلى معرفات نماذج المجموعة إلى قرار [Nadir](https://getnadir.com) API (`POST /v1/bucket`) ويوجه إلى النموذج الذي يختاره Nadir من تلك القائمة (`simple` → أرخص نموذج قادر، `complex` → النموذج الحدودي). لا يزال يتم اختيار الاتصال الذي يخدم هذا النموذج بواسطة `rules`، لذا تستمر الحصة والصحة والتكلفة في تحديد الحساب.

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "nadir",
    "nadir": {
      "apiKey": "ndr_...",
      "baseUrl": "https://api.getnadir.com",
      "timeoutMs": 2000
    }
  }
}
```

`OMNIROUTE_NADIR_API_KEY` و `OMNIROUTE_NADIR_BASE_URL` عبارة عن احتياطيات env للسلسلتين. `baseUrl` مطلوب فقط من أجل Nadir المستضاف ذاتيًا (يتم السماح `/v1` اللاحق). يتم إجراء المكالمات بدون مفتاح على مستوى نادر المجهول، وهو معدل محدود لكل IP. باستخدام المفتاح ( [إنشاء واحد](https://app.getnadir.com/dashboard/api-keys) )، يتم تسجيل كل قرار في لوحة معلومات نادر الخاصة بك. الإعداد الكامل والتحقق: [getnadir.com/docs/gateway-omniroute](https://getnadir.com/docs/gateway-omniroute/).

ما يترك الصندوق: نص رسالة المستخدم الأخيرة (أول 16 ألف حرف)، ومعرفات النماذج المرشحة، وعلامة قناة `source: "omniroute"`. لا يوجد موجه النظام أو التاريخ أو الأدوات أو الرؤوس.

سلوك الفشل هو فشل مفتوح: مهلة (افتراضية 2000 مللي ثانية)، non-2xx، مضيف غير قابل للوصول، استجابة مشوهة أو تحديد خارج التجمع يحل قرار `rules` والسبب مسبوق بـ `NadirStrategy: fallback (…)`. بعد مكالمة فاشلة، تتخطى الإستراتيجية الشبكة لمدة 30 ثانية، وبالتالي فإن انقطاع الخدمة يكلف مهلة واحدة لكل 30 ثانية بدلاً من مهلة واحدة لكل طلب. تقوم أحداث التوجيه بالإبلاغ عن `strategy: "nadir"` فقط عندما يقوم نادر بالاختيار بالفعل.

**متى تستخدم** : حركة مرور مختلطة الصعوبة على مجموعة تمتد عبر طبقات النموذج (نموذج صغير ومتوسط ونموذج حدودي)، حيث تكون الحدود دائمًا هي التكلفة التي تريد خفضها.

**الاسم المستعار** : `nadir` (بدون اسم مستعار)

---

#### 7. `decision` — قابل للتوصيل يختار النموذج

`decision` يسأل أ** مقرر** النموذج الموجود في المجموعة الذي يناسب الطلب، ثم يقوم بتضييق المجموعة إلى هذا النموذج ويتيح `rules` اختيار الاتصال (لا تزال الحصة النسبية والصحة والتكلفة تختار الحساب). يتم تعيين أداة التحديد في كتلة قرار التحرير والسرد — `config.decision` عندما تكون مقابض جهاز التوجيه أعلى `config` (ما تكتبه لوحة المعلومات)، أو `config.auto.decision` بجوار `config.auto.routerStrategy`:

| `decider`     | من يجيب                                                                                                         | الاحتياجات                                       |
| ------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `systemone`   | TypeSafe System One (`POST https://api.typesafe.ai/v1/systemone`)، النموذج الافتراضي `jev-latest`               | اتصال `typesafe` أو مفتاح env                    |
| `http`        | المقرر الخاص بك في `baseUrl`: `wire: "systemone"` (`{baseUrl}/v1/systemone`) أو `"openai-chat"` (إكمال الدردشة) | `baseUrl` + `model`; مفتاح اختياري               |
| `combo-model` | أحد نماذج مزود الخدمة الخاص بك، والذي يتم استدعاؤه في عملية مثل قاضي الاندماج                                   | `model` ك `provider/model` (بدون التحرير والسرد) |

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "decision",
    "decision": {
      "decider": "http",
      "baseUrl": "https://decider.example.com",
      "wire": "openai-chat",
      "model": "qwen-small",
      "connectionId": "<stored connection id>",
      "timeoutMs": 2000,
      "minConfidence": 0.6,
      "descriptions": { "gpt-4o-mini": "Quick drafts and short answers" }
    }
  }
}
```

الحقول (يتم التحقق من صحتها بواسطة مخطط صارم عند الحفظ ومرة أخرى عند الطلب):

- `decider` — `systemone` أو `http` أو `combo-model`.
- نموذج `model` — TypeSafe ، أو نموذج القرار في URL الخاص بك، أو `provider/model` لاستدعاء نموذج التحرير والسرد (ما يصل إلى 200 حرف).
- `baseUrl` — `http` فقط: `http(s)` URL يصل إلى 500 حرف، بدون بيانات اعتماد أو استعلام أو جزء. تم رفض URL الذي يشير إلى OmniRoute (الاسترجاع + `PORT`).
- `wire` — `http` فقط: `systemone` (افتراضي) أو `openai-chat`.
- `connectionId` — هو الاتصال المخزن الذي يتم استخدام مفتاحه (فقط داخل الاتصالات المسموح بها لمفتاح API المتصل). وبدون ذلك، يقرأ `systemone` اتصال `typesafe` ويعود كل محدد للشبكة إلى `OMNIROUTE_DECISION_API_KEY`. لا يوجد حقل `apiKey` : لا يتم تخزين المفتاح مطلقًا في مجموعة التحرير والسرد.
- `timeoutMs` — عدد صحيح، 100-5000، الافتراضي 2000.
- `minConfidence` — 0–1; تعود الإجابة ذات الثقة المنخفضة إلى `rules` (يُحسب المُقرر الذي يُبلغ عن عدم وجود ثقة على أنه 0).
- `descriptions` — ما يصل إلى 50 إدخالًا (مفتاح يصل إلى 300، نص يصل إلى 1000 حرف)، مرتبطًا بمعرف الطراز أو `provider/model`؛ تحصل الإدخالات غير المحددة على وصف تصنيف التكلفة الذي تم إنشاؤه.

**علَم.** `COMBO_DECISION_ROUTER_ENABLED` (الافتراضي `false`) يبواب كل مقرر. أثناء إيقاف تشغيله، لا يقرأ التحرير والسرد `decision` أي بيانات اعتماد، ولا يجري أي اتصال ويوجه باستخدام `rules`؛ السجل يقول `fallback (disabled)`. المفتاح المخزن وحده لا يقوم بتشغيله أبدًا. لا تتأثر المجموعات التي لا تحتوي على كتلة قرار على الإطلاق.

**ما يترك الصندوق.** فقط نص رسالة المستخدم الأخيرة (ما يصل إلى 8000 حرف؛ chat/Claude `messages` أو الردود `input`) وقائمة معرفات النماذج مع أوصافها. لا يطالبك النظام أبدًا أو الردود `instructions` الأدوات أو السجل أو الرؤوس أو بيانات الحساب. تمر مكالمات الشبكة من خلال حارس الموفر الخارجي دون إعادة المحاولة، أو إعادة التوجيه، وبحد أقصى للاستجابة يبلغ 64 KB. استدعاء `combo-model` غير متدفق، وخالي من الأدوات، `temperature: 0`، بميزانية مكونة من 256 رمزًا؛ تم رفض القرار الذي بدأ داخل مكالمة القرار.

**Failure behavior** is fail-open: any failure resolves to the `rules` decision, and the reason reads `decision(<decider>): fallback (<reason>)`, with `<reason>` one of `disabled`, `not_configured`, `missing_credential`, `timeout`, `http_error`, `invalid_response`, `out_of_menu`, `refused`, `cooldown`, `network_error`, `recursion`, `low_confidence`, `single_option` or `no_user_text`. After a timeout, HTTP error or network error the endpoint is skipped for 30 s. A successful pick reads `decision(<decider>): selected <model> from <n>; confidence <c> (<rules reason>)`. No URL, key, prompt or upstream body reaches the log.

يعرض منشئ التحرير والسرد هذه الحقول عندما تكون استراتيجية جهاز التوجيه هي `decision`، مع الأوصاف التي تم إنشاؤها كعناصر نائبة و** قرار الاختبار** الزر الذي يستدعي `POST /api/combos/decision-preview` مرة واحدة باستخدام الإعدادات غير المحفوظة (نفس العلامة).

**متى تستخدم** : حركة مرور مختلطة الصعوبة حيث تريد اختيار الطبقة لكل طلب بواسطة مصنف تختاره، وليس بواسطة نادر على وجه التحديد.

**الاسم المستعار** : `decision` (بدون اسم مستعار)

### استراتيجيات جهاز التوجيه المخصص

يمكنك تسجيل تنفيذ `RouterStrategy` الخاص بك عبر API العام:

```ts
import {
  registerStrategy,
  type RouterStrategy,
} from "@omniroute/open-sse/services/autoCombo/routerStrategy";

class MyCustomStrategy implements RouterStrategy {
  readonly name = "my-custom";
  readonly description = "My custom routing strategy";

  select(pool, context) {
    // Your routing logic here
    return {
      provider: pool[0].provider,
      model: pool[0].model,
      strategy: this.name,
      reason: "MyCustomStrategy: ...",
      candidatesConsidered: pool.length,
      finalScore: 1.0,
    };
  }
}

registerStrategy("my-custom", new MyCustomStrategy());
```

ثم استخدمه:

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "my-custom"
  }
}
```

### دليل اختيار استراتيجية جهاز التوجيه

| حالة الاستخدام         | الإستراتيجية | سبب                                       |
| ---------------------- | ------------ | ----------------------------------------- |

| تقليل التكلفة          | `cost`       | دائما يختار الأرخص                        |
| تقليل الكمون           | `latency`    | يختار أسرع مزود موثوق                     |
| SLOs صارم              | `sla-aware`  | المرشحات حسب عتبات p95/error/cost         |
| دردشة متعددة المنعطفات | `lkgp`       | لزوجة الجلسة                              |
| صعوبة مختلطة           | `nadir`      | يختار طبقة النموذج لكل موجه               |

```json
  }
```

## خلاصة المتغيرات التلقائية

يعلن `AutoVariant` في `autoPrefix.ts`** 7 القيم** (`coding`، `fast`، `cheap`، `offline`، `smart`، `lkgp`، `chaos`). Together مع `auto` المجرد (يتم التعامل معه بواسطة `parseAutoPrefix()` كـ `variant: undefined`) والطبقة المسطحة التي تتراكب `auto/subscription` و `auto/thrifty` (`FLAT_TIER_OVERLAY_IDS` في `builtinCatalog.ts`)، هناك** 10 نموذج مسطح IDs** :

`auto`, `auto/coding`, `auto/fast`, `auto/cheap`, `auto/offline`, `auto/smart`, `auto/lkgp`, `auto/chaos`, `auto/subscription`, `auto/thrifty`

بالإضافة إلى ذلك، يتم أيضًا حل تركيبات `auto/<category>[:<tier>]` وmodel-family IDs (على سبيل المثال `auto/claude-opus`) والأسماء المستعارة `auto/best-*` / `auto/pro-*` في `builtinCatalog.ts`.

## كيف تتكامل المستويات مع Auto-Combo

تتعامل دالة التقييم ذات العوامل الستة عشر (`open-sse/services/autoCombo/scoring.ts`) مع الانتماء إلى المستوى باعتباره إشارتين: `tierPriority` ‏(0.0476) و`tierAffinity` ‏(0.0476). راجع [جدول عوامل التقييم الأساسي](#how-it-works-persisted-auto-combos) أعلاه للاطلاع على مجموعة `DEFAULT_WEIGHTS` الكاملة — أما التجاوزات الخاصة بكل حزمة (ship-fast/cost-saver/quality-first/
offline-friendly) فهي مدرجة في جدول "ملفات تعريف الأوزان لكل حزمة".

لا يفرض المستوى وحده **تقديم المستوى 1** — فإذا كان زمن استجابة المستوى 1 سيئًا أو كانت موازنة التكلفة مقابل الجودة دون المستوى الأمثل، يفوز المستوى 2. لفرض ترتيب المستويات، استخدم استراتيجية التجميع `priority` ورتّب المزوّدين حسب المستوى.

لتفضيل المستوى 1 (الاشتراك) بشدة، زِد وزن `tierPriority`:

```json
{
  "strategy": "auto",
  "config": { "auto": { "weights": { "tierPriority": 0.3, "costInv": 0.05 } } }
}
```

راجع [`docs/guides/TIERS.md`](../guides/TIERS.md) للاطلاع على تعريفات المستويات وتصنيف المزوّدين.

## الاختبار والتغطية

### مصفوفة قرار التوجيه الحتمي (`npm run test:combo:matrix`)

`tests/integration/combo-matrix/*.test.ts` يثبت التوجيه** قرار** من الاستراتيجيات العامة التي تغطيها من البداية إلى النهاية من خلال خط أنابيب التحرير والسرد الحقيقي مع المنبع المستهزئ. التغطية تشمل:

- 18 من 22 استراتيجية `ROUTING_STRATEGY_VALUES` (مرتبة، مرجحة، التكلفة، السياق، الدمج، ...)؛ لا يتم ممارسة `quota-weighted` و `cache-optimized` و `pipeline` و `jev` بواسطة المصفوفة وتعتمد على اختبارات الوحدة الخاصة بها.
- `quota-share` (داخلي) من النهاية إلى النهاية: DRR الإنصاف + التشبع deprioritization عبر التماس `selectQuotaShareTarget` الحقيقي (`registerQuotaFetcher` / `setLKGP` / `__setHeadroomSaturationFetcherForTests`).
- `context-relay` تغطية عالمية للتسليم عبر كل عدد مستهدف.

يعمل هذا الجناح في CI (وظيفة `test:integration` ) مع `--test-concurrency=1` و `--test-force-exit` لذا فهو حتمي ولا يتطلب بيانات اعتماد حية.

### دخان حي مسور (NOT في CI — مقدمي الخدمات الحقيقيين)

| يأمر                                   | ماذا يفعل                                                                       |
| :------------------------------------- | :------------------------------------------------------------------------------ |
| `npm run test:combo:live`              | التوجيه الحقيقي قيد التشغيل باستخدام `RUN_COMBO_LIVE=1`؛ لقطات حية OmniRoute DB |

تمارس اختبارات الدخان هذه مسار السلك الحقيقي (إكمال combo → Provider → ). لقد تم استبعادهم عمدًا من CI لأنهم يحتاجون إلى بيانات اعتماد مباشرة ووصول إلى VPS.
