> **مصدر الحقيقة:** `src/lib/plugins/` (`marketplace.ts`، `manager.ts`، `manifest.ts`،
> `scanner.ts`، `loader.ts`)، و`src/app/api/plugins/`، و
> `src/app/(dashboard)/dashboard/plugins/`
> **آخر تحديث:** 2026-06-28 — v3.8.40

يأتي OmniRoute مزودًا بنظام إضافات على غرار WordPress. الإضافات هي أدلة
مستقلة بذاتها — يحتوي كل منها على ملف بيان `plugin.json` وملف دخول — وترتبط
بمسار معالجة الطلبات (`onRequest` / `onResponse` / `onError`) وبأحداث
دورة الحياة (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`).

يمثّل **سوق الإضافات** طبقة الاكتشاف المبنية فوق ذلك النظام. وهو يوفّر
كتالوجًا قابلًا للتصفح للإضافات المتاحة للتثبيت. يستخدم الكتالوج افتراضيًا
سجلًا أوليًا مدمجًا صغيرًا؛ ويمكن للمشغّل توجيهه إلى عنوان URL لسجل بعيد
مخصص، وفي هذه الحالة تُحصّن عملية الجلب بواسطة آلية حماية من SSRF تحلّ أسماء
DNS (راجع [الأمان](#security)).

جميع مسارات الإضافات **مقصورة على واجهة الاسترجاع** (المستوى 1 — `LOCAL_ONLY`):
تحمّل الإضافات الشيفرة وتنفذها في عمليات فرعية، ولذلك يتعذر الوصول إلى
المسارات من أي مصدر غير واجهة الاسترجاع، بصرف النظر عن المصادقة. راجع
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md).

## كيف يناسب Together

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **طبقة التسجيل** — `src/lib/plugins/marketplace.ts`: يسرد / يبحث في الكتالوج، ويعود إلى السجل الأولي في حالة أي فشل.
- **طبقة دورة الحياة** — `src/lib/plugins/manager.ts` (`pluginManager` Singleton): التثبيت والترقية والتنشيط وإلغاء التنشيط وإلغاء التثبيت والمسح الضوئي وتحميل بدء التشغيل.
- **الطبقة الظاهرة** — `src/lib/plugins/manifest.ts`: مخطط Zod + الافتراضي لـ `plugin.json`.
- **الماسح الضوئي** — `src/lib/plugins/scanner.ts`: يكتشف المكونات الإضافية الموجودة على القرص ضمن دليل المكونات الإضافية.
- **محمل** — `src/lib/plugins/loader.ts`: يولد كل مكون إضافي في عملية فرعية منفصلة Node.js ويقوم الوسطاء بتوصيل المكالمات عبر IPC. الطفل ليس صندوق حماية (راجع "عزل تنفيذ البرنامج الإضافي" أدناه).

## كتالوج السوق

تعيد `listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) قائمة من
كائنات `MarketplaceEntry`:

| الحقل         | النوع    | ملاحظات                                  |
| ------------- | -------- | ---------------------------------------- |
| `name`        | string   | اسم الإضافة بصيغة kebab-case             |
| `version`     | string   | semver                                   |
| `description` | string   | ملخص قصير                                |
| `author`      | string   | المؤلف / المؤسسة                         |
| `license`     | string   | معرّف ترخيص بنمط SPDX                    |
| `downloadUrl` | string   | عنوان URL لتنزيل المصدر (قد يكون فارغًا) |
| `repository`  | string?  | عنوان URL اختياري للمستودع               |
| `tags`        | string[] | وسوم البحث/التصفية                       |
| `downloads`   | number   | عدد التنزيلات                            |
| `rating`      | number   | 0–5                                      |
| `verified`    | boolean  | ما إذا كان الإدخال معلّمًا على أنه موثّق |
| `lastUpdated` | string   | سلسلة تاريخ بصيغة شبيهة بـ ISO           |

عند عدم تكوين عنوان URL لسجل مخصص، يكون الكتالوج هو `SEED_REGISTRY` المدمج
(ويتضمن حاليًا `request-logger` و`rate-limiter` و`cost-tracker`
و`theme-manager`). يظل السجل الأولي متاحًا دائمًا — فإذا تعذر الوصول إلى سجل
بعيد مُكوّن، أو أعاد حالة غير `200`، أو أعاد محتوى غير معروف، تسجّل
`listMarketplacePlugins()` تحذيرًا وتعود إلى القائمة الأولية.

> ملاحظة: **كتالوج** السوق (التصفح/البحث) موصول بالكامل من البداية إلى النهاية،
> لكن **التثبيت** بنقرة واحدة من السوق عبر الكتالوج لم يُنفذ بعد — إذ يعرض زر
> "تثبيت" في لوحة المعلومات ضمن إدخال السوق حاليًا إشعارًا يفيد بأنه
> "قريبًا". يتم التثبيت حاليًا من خلال مسار التثبيت من مسار محلي
> (`POST /api/plugins`) والاكتشاف على القرص (`POST /api/plugins/scan`).

## REST API

تتطلب جميع نقاط النهاية مصادقة الإدارة (`requireManagementAuth`)** و** يتم إدراج — `/api/plugins` و `/api/plugins/` للاسترجاع فقط في `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`).

| نقطة النهاية                     | طريقة  | وصف                                                             |
| -------------------------------- | ------ | --------------------------------------------------------------- |
| `/api/plugins`                   | GET    | قائمة المكونات الإضافية المثبتة (مرشح `?status=` الاختياري)     |
| `/api/plugins`                   | POST   | قم بتثبيت مكون إضافي من دليل مصادر البرنامج المساعد             |
| `/api/plugins/scan`              | POST   | قم بمسح دليل المكونات الإضافية وتسجيل المكونات الإضافية الجديدة |
| `/api/plugins/marketplace`       | GET    | قائمة إدخالات كتالوج السوق                                      |
| `/api/plugins/[name]`            | GET    | احصل على تفاصيل البرنامج المساعد المثبت                         |
| `/api/plugins/[name]`            | DELETE | قم بإلغاء تثبيت البرنامج المساعد                                |
| `/api/plugins/[name]/activate`   | POST   | التنشيط (تحميل خطافات تسجيل + )                                 |
| `/api/plugins/[name]/deactivate` | POST   | إلغاء التنشيط (إطلاق `onDeactivate`، إلغاء تسجيل الخطافات)      |
| `/api/plugins/[name]/config`     | GET    | احصل على مخطط تكوين البرنامج المساعد +                          |
| `/api/plugins/[name]/config`     | PUT    | تحديث تكوين البرنامج المساعد (تم التحقق من صحته مقابل المخطط)   |

يقبل مرشح `GET /api/plugins` `status` واحدًا من `installed` / `active` / `inactive` / `error`. تُرجع قيمة غير صالحة `400`.

### قائمة المكونات الإضافية المثبتة

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### التثبيت من المسار المحلي

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

يجب أن يكون `path`** مطلق** المسار إلى الدليل** داخل دليل مصادر البرنامج المساعد** : `plugin-sources` بجوار جذر البرنامج المساعد، لذلك `~/.omniroute/plugin-sources/` افتراضيًا، أو `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` عند تعيين هذا المتغير (`getPluginSourcesDir()` في `src/lib/plugins/installSource.ts`). انسخ المكوّن الإضافي أو انسخه هناك أولاً. يتم رفض التثبيت باستخدام `400` عندما يحتوي المسار على `..` أو بايت فارغ، أو يقع خارج هذا الدليل، أو يتم حله خارجه من خلال رابط رمزي، أو يحتوي على رابط رمزي هدفه خارجه، أو عندما لا يكون الدليل موجودًا. يجب أن يحتوي الدليل المصدر على `plugin.json` صالح (أو يكون أحد الوالدين). عند النجاح، تكون الاستجابة `201` مع صف البرنامج المساعد المثبت.

على عكس مسارات المكونات الإضافية الأخرى، يتطلب هذا المسار بيانات اعتماد الإدارة (جلسة لوحة معلومات أو مفتاح API محدد النطاق) حتى عند تعطيل تسجيل الدخول (`requireLogin=false`): تثبيت التعليمات البرمجية ليس إجراءً مجهولًا على الإطلاق.

### تصفح السوق

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### تحديث تكوين البرنامج المساعد

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

يتحقق `PUT .../config` من صحة كل قيمة مقدمة مقابل `configSchema` للمكون الإضافي (المعلن عنه في البيان): حقول `number` Honor `min`/`max`، يجب أن تتطابق حقول `select` مع `enum` المعلنة. يُسمح بالمفاتيح غير الموجودة في المخطط.

## الإعدادات

### دليل الإضافات

توجد الإضافات ضمن دليل بيانات OmniRoute:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (أو أي ملف يشير إليه manifest.main)
```

تحدد `getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ذلك الدليل عبر
ثلاث خطوات:

1. **`OMNIROUTE_PLUGINS_DIR`**، عند تعيينه — يُستخدم حرفيًا، بصرف النظر عن قيمة `HOME`. هذا هو
   الخيار الصريح لـ Docker/K8s، حيث تُربط شجرة الإضافات بمسار
   لا تكون له عادةً أي صلة بدليل المنزل الخاص بالحاوية (#11827).
2. `<home>/.omniroute/plugins`، حيث تأتي `<home>` من متغيري البيئة `HOME` / `USERPROFILE`.
3. `/tmp/.omniroute/plugins`، عندما لا تصدّر العملية أي دليل منزل على الإطلاق.

يُسجَّل الدليل المحدد مرة واحدة عند بدء التشغيل باسم `scanner.dir_resolved`، مع ذكر
المدخل الذي تم اختياره (`OMNIROUTE_PLUGINS_DIR` أو `home` أو `no-home-fallback`) — ولذلك فإن الصورة
التي تنتقل بصمت إلى الخطوة 3 توضح ذلك، بدلًا من الاكتفاء بالإبلاغ عن قائمة إضافات فارغة.
يكتشف `POST /api/plugins/scan` أي دليل فرعي هناك يحتوي على ملف
`plugin.json` صالح ويسجله؛ والدليل نفسه هو الجذر الذي تنسخ
`pluginManager.install()` الإضافات إليه، ولذلك ينقل التجاوز الاكتشاف
والتثبيت معًا.

> **`OMNIROUTE_PLUGINS_DIR` ليس `OMNIROUTE_PLUGIN_PATH`.** لا يقرأ الأخير سوى
> محمّل إضافات الأوامر في CLI (`bin/cli/plugins.mjs`) للعثور على حزم npm من النمط `omniroute-cmd-*`
> التي تضيف أوامر فرعية إلى `omniroute` — ولا يؤثر في الماسح وقت التشغيل
> الموصوف هنا. راجع [PLUGINS.md](./PLUGINS.md) لمعرفة تفاصيل ذلك الجانب.

### عنوان URL مخصص لسجل السوق

يُقرأ مصدر كتالوج السوق من الإعداد `pluginMarketplaceUrl`
(`src/lib/plugins/marketplace.ts` يقرأ `settings.pluginMarketplaceUrl`). عند
تعيينه إلى عنوان URL من نوع `http(s)`، تجلب `listMarketplacePlugins()` ذلك العنوان وتقبل
إما مصفوفة JSON من الإدخالات في المستوى الأعلى أو كائنًا يحتوي على مصفوفة `plugins`؛
وتُستبعد الإدخالات التي لا تحتوي على `name` من نوع سلسلة نصية. عند عدم تعيينه (أو عندما يفشل الجلب
في اجتياز حماية SSRF / يعيد استجابة غير صالحة)، يُستخدم سجل البذور المضمّن.

تعرض علامة تبويب "السوق" في لوحة المعلومات حقلًا لعنوان URL هذا (تُقرأ قيمته مجددًا من
`GET /api/settings`).

> ملاحظة تنفيذية: يرسل إجراء "حفظ" في لوحة المعلومات
> `pluginMarketplaceUrl` إلى `PATCH /api/settings`. وقت كتابة هذا النص، لم يكن هذا
> المفتاح معلنًا في `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`)، لذا تحقّق من استمرارية تخزينه في
> إصدارك قبل الاعتماد عليه — إذ يحترم مسار **القراءة** (`getSettings()` →
> `listMarketplacePlugins()`) المفتاح بمجرد وجوده في مخزن الإعدادات.

## حماية

### مستوى المسار — الاسترجاع فقط

تنفذ المكونات الإضافية التعليمات البرمجية في العمليات الفرعية الناتجة، لذلك يتم تصنيف سطح `/api/plugins` بأكمله على `LOCAL_ONLY` (المستوى 1). يتم تشغيل فرض الاسترجاع دون قيد أو شرط** قبل** أي فحص مصادقة، لذلك لا يزال رمز الإدارة المتسرب الذي يصل إلى المربع عبر النفق غير قادر على تثبيت مكون إضافي أو تنشيطه أو إلغاء تثبيته. راجع [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) والقواعد الصارمة #15 / #17.

### حارس تسجيل السوق SSRF

السجل المخصص URL هو تكوين قابل للتأثير من قبل المهاجم، لذلك قبل جلبه، يقوم `listMarketplacePlugins()` بتشغيله عبر طبقتين:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - يرفض أي شيء ليس `http:` / `https:`.
   - يرفض مضيفي private/loopback/link-local/ULA الحرفيين (IPv4** و** IPv6، بما في ذلك IPv4-mapped) عبر `isPrivateHost` الأساسي (`src/shared/network/outboundUrlGuard.ts`).
   - يحل** كلاهما** يسجل `A` و `AAAA` ويرفض if** أي** العنوان الذي تم حله هو — الخاص الذي يغلق اسم المضيف العام → تجاوز IP الخاص.
   - **فشل مغلقة** : فشل قرار DNS يرفض URL.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): إعادة تطبيق حارس URL العام فقط في وقت الجلب و** كتل عمليات إعادة التوجيه** (لا يوجد محور → خاص `30x` عام).

لا يؤدي URL الذي يفشل في أي من الطبقتين إلى إحباط الطلب — ويعود السوق بصمت إلى السجل الأساسي المدمج ويسجل تحذيرًا.

> تمت تقوية هذا الحارس في PR #3774 خصيصًا لحل A + AAAA واستخدام `isPrivateHost` الأساسي بدلاً من فحص IPv4-only.

### عزل تنفيذ البرنامج المساعد

> **الإضافات ليست في وضع الحماية.** الطفل عبارة عن عملية Node.js عادية تعمل كمستخدم OmniRoute ، بدون سياق VM ولا علامات إذن Node.js ، لذلك يمكن لرمز البرنامج المساعد قراءة وكتابة أي ملف يستطيع المستخدم تشغيل البرامج والوصول إلى الشبكة. تقرر `requires.permissions` فقط متغيرات البيئة التي يتلقاها الطفل؛ لا يتم فرض الأذونات الأخرى. قم بتثبيت المكونات الإضافية التي تثق بها فقط. تحتوي حدود العملية أدناه على أعطال وتعليقات؛ إنها ليست حدودًا أمنية.

- **عزل العملية** — `loadPlugin()` (`src/lib/plugins/loader.ts`) يولد كل مكون إضافي في عملية فرعية منفصلة Node.js ويتواصل عبر IPC. مكالمات الخطاف لها مهلة مع تصعيد `SIGTERM` → `SIGKILL`.
- **القائمة المسموح بها للبيئة** — يتلقى الطفل فقط مجموعة من متغيرات البيئة المدرجة في القائمة المسموح بها؛ يتم منح المجموعة الأوسع فقط عندما يطلب البيان إذن `env`.
- **تثبيت احتواء المصدر** يقرأ — `POST /api/plugins` فقط من دليل مصادر المكونات الإضافية (راجع "التثبيت من مسار محلي"): يتم تحديد المسار باستخدام `realpath`، ويجب أن يبقى بشكل صارم داخل هذا الدليل، ويتم رفض الشجرة المصدر التي تحمل رابطًا رمزيًا يفلت منه قبل نسخ أي شيء.
- **احتواء المسار** يؤكد — install/upgrade/uninstall أن دليل البرنامج المساعد وحل `manifest.main`** داخل** جذر البرنامج المساعد المُدار قبل أي نسخة أو حذف متكرر (يحمي من العبث بمسارات DB واجتياز `../` في `manifest.main`). يعمل التنشيط على حل الارتباطات الرمزية عبر `realpath` ويرفض تحميل نقطة إدخال تهرب من دليل البرنامج المساعد.
- **دبوس التكامل الاختياري** — قد يعلن البيان عن حقل `integrity` (تنسيق `sha256-<base64>`، SRI ). عند وجوده، يتحقق المُحمل من تجزئة ملف الإدخال في وقت التحميل ويرفض التنشيط في حالة عدم التطابق. إنه خيار كشف العبث،** لا** حدود الأمان: لا تحدد ما يمكن أن يفعله البرنامج الإضافي المحمل.
- **لا توجد بيانات اعتماد العميل في الخطافات** — تمت إزالة الرؤوس التي تم تمريرها إلى `onRequest` و `onResponse` و `onError` من `authorization` و `x-api-key` و `proxy-authorization` و `cookie` ، ولا يحمل سجل مفتاح API أي قيمة مفتاح (`redactPluginContext()` في `src/lib/plugins/hooks.ts`).

## مانيفست (`plugin.json`)

تم التحقق منها بواسطة `PluginManifestSchema` (`src/lib/plugins/manifest.ts`):

| مجال               | يكتب     | ملحوظات                                                           |
| ------------------ | -------- | ----------------------------------------------------------------- |
| `name`             | خيط      | مطلوب؛ حالة كباب (`^[a-z0-9-]+$`) ، 1-100 حرف                     |
| `version`          | خيط      | مطلوب؛ سمفر (`MAJOR.MINOR.PATCH`)                                 |
| `description`      | خيط؟     | ≤ 500 حرف                                                         |
| `author`           | خيط؟     | ≤ 200 حرف                                                         |
| `license`          | خيط؟     | الإعدادات الافتراضية إلى `MIT`                                    |
| `main`             | خيط؟     | ملف الدخول؛ الإعدادات الافتراضية ل `index.js`                     |
| `source`           | التعداد؟ | `local` \| `marketplace` (الافتراضي هو `local`)                   |
| `tags`             | خيط[]؟   | علامات البحث                                                      |
| `requires`         | هدف؟     | `{ omniroute?, permissions[] }`                                   |
| `hooks`            | هدف؟     | القيم المنطقية التي تعلن عن الخطافات التي ينفذها البرنامج المساعد |
| `skills`           | هدف[]؟   | تعريفات المهارات الاختيارية                                       |
| `enabledByDefault` | منطقي؟   | التنشيط التلقائي عند التثبيت                                      |
| `configSchema`     | هدف؟     | خريطة حقول التكوين (`string`/`number`/`boolean`/`select`)         |
| `integrity`        | خيط؟     | دبوس ملف إدخال `sha256-<base64>` اختياري                          |

يتم استخلاص الأذونات من التعداد `network` / `file-read` / `file-write` / `env` / `exec`. فقط `env` له تأثير وقت التشغيل (قائمة مسموح بها لمتغيرات البيئة أكبر قليلاً للطفل)؛ والبعض الآخر عبارة عن إعلانات ولا يتم تنفيذها.

## تدفق دورة الحياة

```
install (POST /api/plugins، المسار)
  → فحص/التحقق من ملف البيان → النسخ إلى منطقة التجهيز → التأكد من وجود main داخل الدليل
  → إعادة تسمية ذرّية إلى ~/.omniroute/plugins/<name> → إدراج صف في قاعدة البيانات
  → تشغيل onInstall → إذا كان enabledByDefault: التفعيل

activate (POST /api/plugins/{name}/activate)
  → التحقق من الاحتواء باستخدام realpath → loadPlugin() (إنشاء عملية فرعية)
  → تسجيل الخطافات المعلنة → status = "active" → تشغيل onActivate

deactivate (POST /api/plugins/{name}/deactivate)
  → تشغيل onDeactivate (قبل إلغاء التسجيل) → إلغاء تسجيل الخطافات
  → إنهاء العملية الفرعية → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → إلغاء التفعيل إذا كانت الإضافة نشطة → تشغيل onUninstall
  → حذف متكرر لدليل الإضافة بعد التحقق من الاحتواء → حذف صف قاعدة البيانات
```

تؤدي إعادة تشغيل `install` على دليل يحتوي ملف بيان بإصدار **أحدث بشكل صارم**
من الإصدار المثبّت إلى ترقية تلقائية (إعادة تثبيت نظيفة؛ تُعاد التهيئة إلى
القيم الافتراضية). ويُرفض الإصدار المطابق أو الأقدم.

## لوحة القيادة

توفر صفحة لوحة المعلومات في `/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) علامتي تبويب:

- **تم التثبيت** يسرد — المكونات الإضافية المثبتة مع خطافاتها المعلنة، وتبديل activate/deactivate ، وزر إلغاء التثبيت، وإجراء "البحث عن المكونات الإضافية" (`POST /api/plugins/scan`).
- **السوق** يعرض — الكتالوج من `GET /api/plugins/marketplace` مع حقل لتعيين التسجيل المخصص URL.

تعرض الصفحة دائمًا تحذيرًا بأن المكونات الإضافية تعمل مع الامتيازات الكاملة لعملية OmniRoute.

توجد صفحة التكوين لكل مكون إضافي في `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`).
