- يقوم OmniRoute بتثبيتها تحت `DATA_DIR/services/{name}/` (معزولة عن `package.json` الخاص بـ OmniRoute)
- OmniRoute تفرز وتراقبها كعمليات فرعية
- يقوم OmniRoute بإدخال مفتاح API سريع الزوال في بيئة الطفل ويقوم بتدويره دون توقف (حيثما أمكن)
- جميع طرق الإدارة (`/api/services/*`) هي**LOCAL_ONLY** يمكن الوصول إلى — فقط من خلال الاسترجاع (القاعدة الثابتة رقم 17)

## 3. آلة حالات دورة الحياة

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
                  نجاح فحص الصحة    │         تعطّل / SIGTERM    │
                               ┌────▼─────┐  (خروج خلال 5 ث)     │
                               │ running  │──── تعطّل ──────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

تُخزَّن الحالات في جدول قاعدة البيانات `version_manager` (العمود `status`) وتُعكس
في حالة `ServiceSupervisor` الموجودة في الذاكرة. تكون الحالة الموجودة في الذاكرة هي المرجع المعتمد
للعملية قيد التشغيل؛ أما حالة قاعدة البيانات فهي البديل الدائم عند الإقلاع.

### انتقالات الحالة

| من              | الحدث                               | إلى                    |
| --------------- | ----------------------------------- | ---------------------- |
| `not_installed` | نجاح `install()`                    | `stopped`              |
| `stopped`       | استدعاء `start()`                   | `starting`             |
| `starting`      | يُرجع فحص الصحة 200                 | `running`              |
| `starting`      | خروج العملية قبل أن تصبح سليمة      | `error`                |
| `running`       | استدعاء `stop()`                    | `stopping` → `stopped` |
| `running`       | خروج العملية بشكل غير متوقع (< 5 ث) | `error` (تعطّل سريع)   |
| `running`       | خروج العملية بشكل غير متوقع (> 5 ث) | `error`                |
| `error`         | استدعاء `start()`                   | `starting`             |
| أي حالة         | `stop()` أثناء `stopping`           | بلا إجراء              |

### قفل العمليات

ينفّذ `ServiceSupervisor` عمليات دورة الحياة تسلسليًا من خلال قفل عمليات غير متزامن
(`withLock()`). تؤدي استدعاءات `start()` المتزامنة على المشرف نفسه إلى إنشاء
عملية واحدة فقط؛ إذ ينتظر المستدعي الثاني ويُرجع الحالة الحالية. يمنع ذلك
حالات التسابق عندما يحدث، على سبيل المثال، التشغيل التلقائي والضغط على زر في واجهة المستخدم في الوقت نفسه.

## 4. مرجع API

جميع الطرق تحت `/api/services/` هي**LOCAL_ONLY** (الاسترجاع فقط، القاعدة الصعبة رقم 17). تتلقى طلبات عدم الاسترجاع `403 LOCAL_ONLY` بغض النظر عن رمز المصادقة المميز.

### 4.1 9 نقاط نهاية جهاز التوجيه (11 مسارًا)

#### `POST /api/services/9router/install`

تثبيت 9Router من npm. يخلق `DATA_DIR/services/9router/` مع `package.json` و `node_modules/` الخاصة به. لا يتعارض مع عروض OmniRoute الخاصة.

**هيئة الطلب** (كلها اختيارية):

```json
{ "version": "latest" }
```

| مجال      | يكتب     | تقصير      | وصف                               |
| --------- | -------- | ---------- | --------------------------------- |
| `version` | `string` | `"latest"` | علامة إصدار npm أو semver للتثبيت |

**الردود:**

| حالة  | وصف                                                    |
| ----- | ------------------------------------------------------ |
| `200` | `{ ok: true, installedVersion: "x.y.z", path: "..." }` |
| `400` | نص الطلب غير صالح (فشل التحقق من صحة Zod )             |
| `409` | تم التثبيت بالفعل (تم القفل)                           |
| `500` | فشل تثبيت npm — راجع `message` لمعرفة الخطأ المألوف    |

### 4.9 الوكيل العكسي (تضمين لوحة معلومات جهاز التوجيه 9)

تقوم لوحة المعلومات بتضمين 9Router web UI داخل إطار iframe عبر وكيل عكسي داخلي على:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

هذا الوكيل:

- إعادة توجيه الطلب إلى `http://127.0.0.1:{port}/{path}` (الاسترجاع فقط)
- إزالة رؤوس `cookie` و `authorization` الواردة (لا يوجد تسرب لجلسة OmniRoute )
- يقوم بإدخال `Authorization: Bearer {apiKey}` لمصادقة 9Router
- يزيل `set-cookie` و `content-security-policy` و `x-frame-options` `cross-origin-*` من الاستجابة
- يعيد كتابة استجابات HTML لحقن `<base href>` وتطبيع المسارات المطلقة (`/foo` → `/dashboard/.../embed/foo`)

تتم معالجة ترقيات WebSocket للوحة المعلومات المضمنة بواسطة خادم مصاحب على منفذ مخصص (راجع `src/lib/services/embedWsProxy.ts`).

**حماية:** يتم تصنيف مسارات الوكيل المضمنة ضمن `LOCAL_ONLY_API_PREFIXES` ولا يمكن الوصول إليها إلا من خلال الاسترجاع. لا يمكن للمهاجم الذي يحصل على JWT عبر نفق Cloudflare/Ngrok التوكيل في الخدمات المضمنة.

تُصنَّف جميع المسارات الواقعة ضمن `/api/services/` و`/dashboard/providers/services/*/embed/`
على أنها LOCAL_ONLY في `src/server/authz/routeGuard.ts`. يُنفَّذ فحص عنوان الاسترجاع
دون شروط قبل أي فرع للمصادقة:

```
يصل الطلب
  → isLocalOnlyPath(path)?
      → ليس عنوان استرجاع → 403 LOCAL_ONLY (دائمًا، قبل فحص المصادقة)
      → عنوان استرجاع     → المتابعة إلى المصادقة العادية
```

يمنع هذا استخدام JWT مُسرَّب (مثلًا عبر نفق) لتشغيل `npm install` أو
إنشاء العمليات. راجع `docs/security/ROUTE_GUARD_TIERS.md` للاطلاع على مصفوفة
المستويات الكاملة.

### حقن مفتاح API

يتطلب 9Router وMux مفتاح API/رمز حامل لنقاط نهاية HTTP الخاصة بهما.
يقوم OmniRoute بما يلي:

1. ينشئ مفتاحًا عبر `crypto.randomBytes(32).toString("base64url")` مع بادئة
   خاصة بالخدمة (`nr_` لـ9Router، و`mx_` لـMux).
2. يشفّره عند التخزين باستخدام AES-256-GCM (وهي خوارزمية التشفير نفسها المستخدمة لبيانات اعتماد المزوّد).
3. يفك تشفيره ويحقنه بصفته متغير بيئة عند إنشاء العملية —
   `NINEROUTER_API_KEY` لـ9Router، و`MUX_SERVER_AUTH_TOKEN` لـMux (وليس أبدًا كخيار CLI،
   ولذلك لا يظهر الرمز مطلقًا في `ps`/قوائم العمليات).
4. لا يعيد مفتاح النص الصريح مطلقًا في أي استجابة HTTP.

يتلقى CLIProxyAPI مفتاحًا مخصصًا لمستوى البيانات يُحقن عند إنشاء العملية
(`needsApiKey: true` — يُستخدم لمزامنة النماذج مع المحوّل).

### الحماية من SSRF

وُكِّل وكيل HTTP العكسي (`/dashboard/.../embed/[...path]`) برمجيًا لإعادة التوجيه
فقط إلى `http://127.0.0.1:{port}`. ولا يتبع مطلقًا عمليات إعادة التوجيه إلى وجهات
ليست ضمن نطاق الاسترجاع. تُستخدم مكتبة `ssrf-req-filter` لرفض أي عنوان URL علوي
يُحل إلى عنوان خارج نطاق الاسترجاع.

### سلامة الصدفة (القاعدة الصارمة #13)

يُستدعى `npm install` عبر `execFile('npm', ['install', pkg, '--prefix', dir])` —
من دون قوالب نصية، أو صدفة، أو استيفاء لمسارات خارجية في سلسلة الأمر.
تُمرَّر قيم وقت التشغيل (المنافذ ومفاتيح API) عبر كائن `env` الخاص بالعملية الفرعية.

### تنقية الأخطاء (القاعدة الصارمة #12)

تمر جميع استجابات الأخطاء من `/api/services/*` عبر `buildErrorBody()` أو
`sanitizeErrorMessage()`. ولا تُعاد قيمتا `err.stack` و`err.message` الخام
حرفيًا إلى المستدعي مطلقًا.

## 6. إضافة خدمة مضمنة جديدة

اتبع هذه الخطوات الثماني. اقرأ عمليات التنفيذ الحالية في `src/lib/services/installers/`
و`src/app/api/services/` بوصفها المرجع المعتمد.

### الخطوة 1 — إنشاء المثبّت

أنشئ `src/lib/services/installers/{name}.ts` على غرار `ninerouter.ts`:

```typescript
export const NAME_PACKAGE = "your-npm-package";
export const NAME_DEFAULT_PORT = 20132; // اختر منفذًا متاحًا

export async function install(version = "latest"): Promise<InstallResult> { ... }
export async function update(version = "latest"): Promise<InstallResult> { ... }
export async function uninstall(): Promise<void> { ... }
export function resolveSpawnArgs(apiKey: string, port: number): SpawnArgs { ... }
export async function getInstalledVersion(): Promise<string | null> { ... }
export async function getLatestVersion(): Promise<string | null> { ... }
```

استخدم `runNpm(['install', NAME_PACKAGE, '--prefix', dir])` من `installers/utils.ts`
— ولا تستخدم أبدًا `execSync` أو الاستيفاء عبر الصدفة.

### الخطوة 2 — التسجيل في التمهيد

أضف `ServiceEntry` إلى مصفوفة `SERVICES` في `src/lib/services/bootstrap.ts`:

```typescript
{
  tool: "myservice",
  port: NAME_DEFAULT_PORT,
  healthPath: "/health",
  healthIntervalMs: 5_000,
  stopTimeoutMs: 15_000,
  logsBufferBytes: 5_242_880,
  needsApiKey: true, // false إذا لم تكن هناك حاجة إلى مفتاح API
}
```

وسّع `buildSpawnArgsFactory()` لمعالجة `cfg.tool === "myservice"`.

#### عقد إضافة المزوّد القابل للتركيب (المرحلة 1، #7333)

يقدّم `src/lib/services/providerPlugins/` عقد `ServiceProviderPlugin` الذي
يجمع حقول `ServiceEntry` الخاصة بـ`bootstrap.ts` للواجهة الخلفية وحقول قالب البيان
في `serviceBackends.ts` ضمن كائن واحد، بدلًا من التعبير عن بنية الواجهة الخلفية نفسها
بشكل منفصل في ملفين غير مرتبطين. حتى وقت كتابة هذا النص، **لم يُرحَّل سوى `9router`**
— إذ يستمد `bootstrap.ts` إدخال `SERVICES[]` الخاص به من
`getServiceProviderPlugin("9router")` (`src/lib/services/providerPlugins/registry.ts`)،
مع طرح خطأ عند بدء التشغيل إذا أصبحت الإضافة مفقودة في أي وقت. وتظل `cliproxy` و`mux` و`bifrost`
على القيم الحرفية المضمنة الموجودة مسبقًا في `SERVICES[]` دون تغيير.

حصل `open-sse/config/providerPluginManifest.ts` أيضًا على دالة مساعدة إضافية
`createServiceBackendManifestEntry(pluginId, template)` تنشئ
`ProviderPluginManifestEntry` صحيح البنية من إدخال `SERVICE_BACKEND_MANIFEST_TEMPLATE` — وهي
**غير موصولة** حتى الآن بأي مسار طلب فعلي (لا `generateProviderPluginManifestFromRegistry()`
ولا `/v1/providers/[provider]/models`)؛ ويظل ذلك عملًا لاحقًا بعد إثبات صلاحية العقد
لواجهة خلفية ثانية.

أُجِّلت إلى طلبات سحب لاحقة، ويجري تتبعها ضمن المشكلة #7333: ترحيل `cliproxyapi` عبر
السجل نفسه، وتعميم `mux`/`bifrost` ضمن اتحاد `ServiceBackendPluginId`،
ودمج المعالجة الخاصة بتوجيه المنفّذ (`open-sse/executors/index.ts`،
`open-sse/handlers/chatCore/executorProxy.ts`) في عقد الإضافة، وربط
`createServiceBackendManifestEntry()` بمسار فعلي للبيان/النماذج.

### الخطوة 3 — إضافة الترحيل وبيانات DB الأولية

تأكد من وجود صف للخدمة في `version_manager` عبر ترحيل في
`src/lib/db/migrations/`. يجب أن يحتوي الصف على:

## 7. استكشاف الأخطاء وإصلاحها

### الخدمة لا تبدأ

**الأعراض:** يُرجع زر البدء الحالة 503، وتظل الحالة `"error"` أو `"starting"`.

**قائمة التحقق:**

1. تحقّق من `GET /api/services/{name}/logs` (أو لوحة السجلات في لوحة المعلومات). ابحث
   عن أسطر مثل `Error: ENOENT` أو `address already in use` أو `Cannot find module`.
2. تحقّق من وجود `npm` في PATH: نفّذ `which npm` من حساب المستخدم نفسه الذي يشغّل OmniRoute.
3. تحقّق من تثبيت الخدمة: افحص `GET /api/services/{name}/status` بحثًا عن
   `installedVersion`. إذا كانت `null`، فنفّذ التثبيت أولًا.
4. تحقّق من أن `DATA_DIR/services/{name}/node_modules/` موجود وليس فارغًا.
5. تحقّق من الحقل `lastError` في استجابة الحالة لمعرفة سبب الخروج المنقّح.

---

### بدء التشغيل البارد بطيء (> 10 ثوانٍ للوصول إلى `running`)

**الأعراض:** تظل الحالة `"starting"` مدة طويلة قبل أن تنتقل إلى `"running"` أو `"error"`.

**التفسير:** يتضمن بدء التشغيل البارد لـ 9Router استيراد أشجار اعتمادات كبيرة (وحدات DNS
والنفق وMITM). الفاصل الزمني الافتراضي لفحص الصحة هو ثانيتان، مع 3 محاولات قبل أن
تعلن عملية الإشراف انتهاء المهلة (لكنها تواصل الاستقصاء).

**الإصلاح:** يمكن ضبط `healthIntervalMs` ومهلة `waitForHealthy`
(`healthIntervalMs * 3`) في `bootstrap.ts`. بالنسبة إلى الخدمات التي تستغرق وقتًا أطول
لبدء التشغيل، زِد `healthIntervalMs` إلى 5000 و`stopTimeoutMs` إلى 30 000.

---

### تعارض المنفذ (`EADDRINUSE`)

**الأعراض:** تعرض السجلات `address already in use :::20130`.

**الأسباب:**

- هناك عملية أخرى تستخدم المنفذ 20130 بالفعل.
- لم تتوقف عملية 9Router سابقة بالكامل (PID متروك).

**الإصلاح:**

1. غيّر المنفذ الافتراضي عبر متغير البيئة `NINEROUTER_PORT` في `.env`.
2. ابحث عن العملية المتعارضة وأنهِها: `lsof -ti :20130 | xargs kill -9`.
3. يمكن ضبط المنفذ لكل خدمة في `bootstrap.ts` عبر الحقل `port`.

**ملاحظة:** يستخدم 9Router المنفذ 20130 افتراضيًا، تحديدًا لتجنب التعارض مع
المنفذ الافتراضي 20128 لـ OmniRoute.

---

### رفض الإذن (EACCES) عند التثبيت

**الأعراض:** يُرجع التثبيت الحالة 500، وتعرض السجلات `EACCES` أو `permission denied`.

**الأسباب:**

- لا يملك مسار `DATA_DIR` أو المجلد الأب له صلاحية الكتابة بواسطة عملية OmniRoute.
- التشغيل داخل Docker دون صلاحيات الجذر ومن دون إمكانية الكتابة إلى وحدة التخزين المعيّنة.

**الإصلاح:**

1. تحقّق من `DATA_DIR` (الافتراضي: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. تأكّد من أن مستخدم عملية OmniRoute يملك المجلد: `chown -R $USER ~/.omniroute/`
3. في Docker، تأكّد من أن وحدة التخزين المركّبة تملك الأذونات الصحيحة لمستخدم الحاوية.

---

### فشل التحديث (انتهاء مهلة `npm install` أو خطأ في الشبكة)

**الأعراض:** يُرجع التحديث الحالة 500 مع `InstallError`، وتعرض السجلات انتهاء مهلة الشبكة.

**قائمة التحقق:**

1. تأكّد من إمكانية الوصول إلى سجل npm: `npm ping`.
2. تحقّق من وجود وكيل مؤسسي: `npm config get proxy` و`npm config get https-proxy`.
3. جرّب التثبيت يدويًا: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. إذا كنت خلف شبكة معزولة، فنزّل حزمة tarball مسبقًا واستخدم `npm install /path/to/tarball.tgz`.

---

### تعرض الخدمة الحالة `"error"` فورًا بعد البدء (تعطل سريع)

**الأعراض:** تنتقل الحالة من `"starting"` إلى `"error"` في أقل من 5 ثوانٍ.
يعرض `lastError` القيمة `"Fast crash (exited with code 1)"`.

**قائمة التحقق:**

1. اقرأ ذيل السجل الكامل: `GET /api/services/{name}/logs?tail=500`.
2. سبب شائع: متغيرات البيئة التي تتوقعها الخدمة مفقودة.
3. بالنسبة إلى 9Router: تحقّق من تمرير `NINEROUTER_DISABLE_MITM=true` و
   `NINEROUTER_DISABLE_TUNNEL=true` في البيئة عند إنشاء العملية (راجع
   `resolveSpawnArgs` في `installers/ninerouter.ts`).

## 8. الأسئلة الشائعة

**س: هل يمكنني إتاحة نقاط نهاية الخدمات المضمّنة للعملاء من خارج واجهة الاسترجاع؟**

لا. فئة LOCAL_ONLY مقصودة (القاعدة الصارمة رقم 17). يجب ألا تكون المسارات التي يمكنها استدعاء
`npm install` أو إنشاء عمليات `node` قابلة للوصول من حركة بيانات آتية من خارج واجهة الاسترجاع،
لأن تسرّب JWT عبر نفق (Cloudflare أو Ngrok أو Tailscale) سيتيح بخلاف ذلك
إنشاء عمليات عشوائية. لا يوجد استثناء اختياري للمسار
`/api/services/` — فعلى خلاف `/api/mcp/`، هو مستبعد من قائمة تجاوز نطاق الإدارة.
راجع `docs/security/ROUTE_GUARD_TIERS.md`.

---

**س: هل ستتوفر 9Router وCLIProxyAPI في عمليات النشر الإنتاجية/السحابية؟**

نعم. تتبع كلتا الخدمتين النموذج المحلي أولًا نفسه الذي يتبعه OmniRoute. وتعملان
على الجهاز نفسه وتتواصلان عبر واجهة الاسترجاع. ويُقصد بمصطلح «الإنتاج» هنا خادم VPS
أو الخادم المحلي الذي نُشر عليه OmniRoute، وليس مزوّد خدمات سحابية بعيدًا.

---

**س: كيف يمكنني تصحيح أخطاء المشرف؟**

1. تابع تدفق سجل SSE: `curl -N http://localhost:20128/api/services/9router/logs`.
2. افحص السجلات المهيكلة في مخرجات pino الخاصة بـ OmniRoute بعد تصفيتها حسب
   مساحة الاسم `service:supervisor`.
3. افحص صف قاعدة البيانات: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. استخدم `GET /api/services/9router/status` للاطلاع على الحالة المباشرة الحالية ومعرّف العملية PID والصحة
   و`lastError` في استدعاء واحد.

---

**س: يعرض المشرف `health: "degraded"` أو `health: "unknown"`، لكن الحالة هي `"running"`. هل هذه مشكلة؟**

تعني `"degraded"` أن فحص الصحة أعاد استجابة لا تحمل الرمز 200. وتعني `"unknown"` أنه لم
يكتمل أي فحص بعد (حالة تسابق مع أول استقصاء). وكلتا الحالتين مؤقتتان أثناء بدء التشغيل.
إذا ظلت الصحة في الحالة `"degraded"` لأكثر من `healthIntervalMs * 3` مللي ثانية بعد
`"running"`، فهذا يعني أن الخدمة المضمّنة تعمل، لكن واجهة HTTP API الخاصة بها لا تستجيب. تحقّق
مما إذا كان المنفذ صحيحًا في استجابة الحالة، وما إذا كانت الخدمة تستمع بالفعل
على ذلك المنفذ.

---

**س: هل يمكنني تغيير مفتاح API الخاص بـ 9Router دون إعادة تشغيل كاملة؟**

لا. يُمرَّر مفتاح API إلى 9Router عبر متغير بيئة عند إنشاء العملية.
ولا يمكن تغيير متغيرات البيئة في عملية قيد التشغيل. يوقف `POST .../rotate-key`
الخدمة ويعيد تشغيلها تلقائيًا لتطبيق المفتاح الجديد. ويصبح تدوير المفتاح
ساريًا خلال مدة `stopTimeoutMs` الخاصة بالخدمة (15 ثانية افتراضيًا)، بالإضافة إلى وقت
بدء تشغيلها.

---

**س: ما حد المخزن المؤقت الحلقي، وماذا يحدث عند امتلائه؟**

لكل خدمة مخزن مؤقت حلقي مخصص بسعة 5 MB. وعندما يمتلئ المخزن المؤقت، تُزال أقدم
أسطر السجل لإفساح المجال للأسطر الجديدة. يعيد حدث SSE المسمى `snapshot`
أحدث الأسطر ضمن حد `tail`. ولا تُحفظ السجلات على القرص إلا إذا
ضُبط `logsBufferPath` في صف قاعدة البيانات.
