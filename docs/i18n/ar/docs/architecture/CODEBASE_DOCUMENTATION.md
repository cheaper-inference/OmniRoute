من دون ابتكار وحدات جديدة.

## 1. المكدس التقني

| المجال               | الخيار                                                                                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| إطار عمل الويب       | **Next.js 16** ‏(App Router، ومخرجات مستقلة، ومن دون برمجيات وسيطة عامة)                                                                                   |
| اللغة                | **TypeScript 6.0+** — الهدف `ES2022`، و`module: esnext`، و`moduleResolution: bundler`، و`strict: false`                                                    |
| بيئة التشغيل         | **Node.js** ‏`>=22.22.2 <23` أو `>=24.0.0 <27` (يُفرض عبر `engines` + `SUPPORTED_NODE_RANGE`)                                                              |
| قاعدة البيانات       | **SQLite** عبر `better-sqlite3` (نسخة مفردة، مع تسجيل WAL)                                                                                                 |
| تطبيق سطح المكتب     | **Electron 41** + ‏`electron-builder` 26.10 (مساحة عمل منفصلة في `electron/`)                                                                              |
| الاختبارات           | **مشغّل الاختبارات الأصلي في Node** (اختبارات الوحدة/التكامل)، و**Vitest** ‏(MCP وautoCombo وذاكرة التخزين المؤقت)، و**Playwright** ‏(e2e + protocols-e2e) |
| البناء               | مخرجات Next.js المستقلة عبر `scripts/build/build-next-isolated.mjs`                                                                                        |
| التدقيق/التنسيق      | إعداد ESLint المسطّح + Prettier ‏(`lint-staged` عبر خطاف Husky لما قبل الالتزام)                                                                           |
| نظام الوحدات         | ESM في كل مكان (`"type": "module"`)                                                                                                                        |
| واجهة لوحة المعلومات | **Tailwind CSS 4** + حزمة **Keak CI UI Kit** المضمّنة مع المشروع (`packages/ui-kit`)، وأيقونات Lucide — راجع `DESIGN_SYSTEM.md`                            |
| مساحات العمل         | مساحات عمل npm — ‏`open-sse`، و`packages/browser-pool`، و`packages/ui-kit`                                                                                 |

الأسماء المستعارة للمسارات (`tsconfig.json`):

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`
- `@omniroute/ui-kit` → `packages/ui-kit/src`، و`@omniroute/ui-kit/*` → `packages/ui-kit/src/*`

منفذ HTTP الافتراضي: **`20128`** (تشترك واجهة API ولوحة المعلومات في العملية نفسها). دليل
البيانات هو متغير البيئة `DATA_DIR`، وتكون قيمته الافتراضية `~/.omniroute/`.

### 3.1 جهاز توجيه التطبيقات `src/app/` —

يعرض جهاز توجيه التطبيق كلاً من لوحة المعلومات UI و public/management HTTP API. هنالك** لا الوسيطة العالمية** يتم اعتراض — لكل مسار.

قطاعات المستوى الأعلى ضمن `src/app/`:

| طريق                                                                          | غاية                                                |
| ----------------------------------------------------------------------------- | --------------------------------------------------- |
| `api/`                                                                        | جميع طرق HTTP API (انظر التفاصيل أدناه)             |

#### 3.1.2a `src/app/api/services/` — إدارة الخدمات المضمنة

طرق تثبيت وبدء وإيقاف ومراقبة 9Router و CLIProxyAPI. يتم تصنيف جميع المسارات**LOCAL_ONLY** (الاسترجاع فقط، القاعدة الصلبة #17) لأنها يمكنها استدعاء `npm install` وتوليد العمليات الفرعية.

```
src/app/api/services/
├── 9router/
│   ├── _lib.ts             getOrInitSupervisor() helper
│   ├── install/route.ts    POST — npm install via execFile
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — npm install newer version
│   ├── rotate-key/route.ts POST — generate new API key + restart
│   ├── status/route.ts     GET  — live + DB status + version metadata
│   └── auto-start/route.ts POST — toggle auto_start flag
├── cliproxy/
│   ├── _lib.ts             getOrInitSupervisor() helper
│   ├── install/route.ts    POST — npm install
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — npm install newer version
│   ├── status/route.ts     GET  — live + DB status + version metadata

    └── logs/route.ts       GET  — SSE log tail (shared by all services)
```

لوحة القيادة المقابلة UI: صفحة `src/app/(dashboard)/dashboard/providers/services/` — ذات علامتي تبويب (CLIProxyAPI + 9Router). الوكيل العكسي لـ 9Router المضمن UI: `src/app/(dashboard)/dashboard/providers/services/[name]/embed/[[...path]]/route.ts`

الغوص العميق: `docs/frameworks/EMBEDDED-SERVICES.md`

## 11. الاصطلاحات

- **نمط الشيفرة**: مسافة بادئة بمقدار مسافتين، وعلامات اقتباس مزدوجة، وعرض 100 محرف، وفواصل منقوطة،
  وفواصل لاحقة وفق `es5` — يفرضها Prettier عبر `lint-staged`.
- **عمليات الاستيراد**: خارجية ← داخلية (`@/`، و`@omniroute/open-sse`) ← نسبية.
- **التسمية**: الملفات بصيغة `camelCase` أو `kebab-case`، والمكوّنات بصيغة `PascalCase`،
  والثوابت بصيغة `UPPER_SNAKE`.
- **ESLint**: القواعد `no-eval` و`no-implied-eval` و`no-new-func` = `error` في كل مكان؛
  والقاعدة `no-explicit-any` = `warn` في `open-sse/` و`tests/`، و`error` في الأماكن الأخرى.
- **TypeScript**: ‏`strict: false` (نهج متوارث). فضّل الأنواع الصريحة على
  الاستدلال عند الحدود بين الوحدات.
- **قاعدة البيانات**: لا تكتب SQL خامًا مطلقًا في المسارات أو المعالجات — استخدم دائمًا
  وحدات `src/lib/db/`. لا تستورد مطلقًا من ملف تجميعي — استخدم وحدات `src/lib/db/*` المحددة مباشرةً.
- **كتابة أنواع كيانات قاعدة البيانات (#3512)**: يجب أن تستخدم الدالة التي تكتب
  شكل صف جدول في قاعدة البيانات أو تقرؤه واجهة TS مسمّاة في معاملات الإدخال أو القيمة المعادة، تحاكي أعمدة ذلك الجدول
  بنسبة 1:1، بدلًا من `any` أو نوع مجهول مضمن في موضع الاستدعاء. ضع
  الواجهة بجوار الدالة (مثل `export interface UsageEntry` في
  `src/lib/usage/usageHistory.ts` أعلى `saveRequestUsage`)، وأبقِ الحقول الفردية
  اختيارية أو قابلة للقيمة الفارغة عندما يملأ كتّاب مختلفون الصف
  تدريجيًا، وفضّل `unknown` على `any` للحقل الذي يختلف شكله
  بين المستدعين (مع توثيق ذلك في الحقل؛ مثلًا، يقبل `UsageEntry.tokens`
  كلاً من بيانات الاستخدام الخام ذات الشكل الخاص بالمزوّد والشكل الموحّد). حالما يصل
  عدد مرات `any` في ملف إلى الصفر بهذه الطريقة، أضفه إلى قائمة السماح
  `check:any-budget:t11` ‏(`scripts/check/check-t11-any-budget.mjs`،
  و`maxAny: 0`) كي لا يتراجع. هذا اصطلاح للدفعة الأولى — أما
  التنظيف الأوسع لعبارة «لا أنواع `any` مجهولة» فيتم تكراريًا عبر بقية
  قاعدة الشيفرة.
- **الأخطاء**: استخدم try/catch مع أنواع أخطاء محددة، وسجّل باستخدام سياق pino. لا
  تتجاهل الأخطاء بصمت في تدفقات SSE مطلقًا؛ استخدم إشارات الإلغاء للتنظيف.
- **الأمان**: لا تستخدم `eval()` أو `new Function()` أو eval الضمني مطلقًا. تحقّق
  من جميع المدخلات باستخدام Zod. شفّر بيانات الاعتماد وهي مخزنة (AES-256-GCM). حافظ على
  مزامنة قائمة الحظر `src/shared/constants/upstreamHeaders.ts` مع
  طبقة التنقية/التحقق.
- **عمليات الإيداع**: Conventional Commits — ‏`feat(scope): subject`. النطاقات المسموح بها:
  `db`، و`sse`، و`oauth`، و`dashboard`، و`api`، و`cli`، و`docker`، و`ci`، و`mcp`،
  و`a2a`، و`memory`، و`skills`.
- **الفروع**: البادئات `feat/`، و`fix/`، و`refactor/`، و`docs/`، و`test/`،
  و`chore/`. لا تُجرِ إيداعًا مباشرًا إلى `main` مطلقًا.
- **Husky**: يشغّل خطاف ما قبل الإيداع `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11`؛ ويشغّل خطاف ما قبل الدفع `check:any-budget:t11` + `check:tracked-artifacts` (بوابات سريعة؛ تستثني `test:unit`).

## 12. قواعد صارمة (من CLAUDE.md)

1. لا تُضمِّن أبدًا الأسرار أو بيانات الاعتماد في الالتزامات.
2. لا تستخدم أبدًا الاستيراد التجميعي — استخدم وحدات `src/lib/db/*` المحددة مباشرةً.
3. لا تستخدم أبدًا `eval()` أو `new Function()` أو أي تقييم ضمني.
4. لا تُجرِ أبدًا التزامات مباشرةً على `main`.
5. لا تكتب أبدًا SQL خامًا في المسارات — استخدم دائمًا وحدات `src/lib/db/`.
6. لا تتجاهل الأخطاء بصمت أبدًا في تدفقات SSE.
7. تحقّق دائمًا من صحة المدخلات باستخدام مخططات Zod.
8. أدرج دائمًا اختبارات عند تغيير شيفرة الإنتاج.
9. يجب أن تظل التغطية ≥ 60% (التعليمات، والأسطر، والدوال، والفروع).
