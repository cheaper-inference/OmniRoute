## إكمالات المحادثة

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### الرؤوس المخصّصة

| Header                   | Direction | Description                                                                                                                                                                       |
| ------------------------ | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | طلب       | اضبطه على `true` لتجاوز ذاكرة التخزين المؤقت                                                                                                                                      |
| `x-omniroute-no-memory`  | طلب       | اضبطه على `true` لتخطي حقن الذاكرة + المهارات لهذا الطلب (يماثل no-cache؛ ويتجنب الحمل الزائد للرموز/التكلفة لكل استدعاء)                                                         |
| `X-OmniRoute-Progress`   | طلب       | اضبطه على `true` لتفعيل أحداث التقدم                                                                                                                                              |
| `X-Session-Id`           | طلب       | مفتاح جلسة ثابت لتحقيق ارتباط الجلسة الخارجية                                                                                                                                     |
| `x_session_id`           | طلب       | يُقبل أيضًا الإصدار الذي يستخدم الشرطة السفلية (HTTP مباشر)                                                                                                                       |
| `X-OmniRoute-Session-Id` | طلب       | وسم الجلسة/المحادثة الذي يقدمه المستدعي (ويُمرر أيضًا إلى الذاكرة). عند وجوده، يُحفظ حرفيًا في `call_logs.session_tag` لإسناد التكلفة لكل جلسة (#8249) — ولا يتم إنشاؤه عند غيابه |
| `Idempotency-Key`        | طلب       | مفتاح إزالة التكرار (نافذة مدتها 5 ثوانٍ)                                                                                                                                         |
| `X-Request-Id`           | طلب       | مفتاح بديل لإزالة التكرار                                                                                                                                                         |
| `x-omniroute-connection` | طلب       | تثبيت طلب نموذج واحد على اتصال موفر واحد (حساب) بواسطة معرّفه — راجع [تثبيت الحساب لكل طلب](#account-pinning-per-request)                                                         |
| `X-OmniRoute-Cache`      | استجابة   | `HIT` أو `MISS` (للطلبات غير المتدفقة)                                                                                                                                            |
| `X-OmniRoute-Idempotent` | استجابة   | `true` إذا تمت إزالة التكرار                                                                                                                                                      |
| `X-OmniRoute-Progress`   | استجابة   | `enabled` إذا كان تتبع التقدم مفعّلًا                                                                                                                                             |
| `X-OmniRoute-Session-Id` | استجابة   | معرّف الجلسة الفعلي الذي يستخدمه OmniRoute                                                                                                                                        |
| `X-OmniRoute-Request-Id` | استجابة   | معرّف ارتباط الطلب (عند معرفته)                                                                                                                                                   |
| `X-OmniRoute-Version`    | استجابة   | إصدار بنية OmniRoute (موجود دائمًا)                                                                                                                                               |
| `X-OmniRoute-Cost-Saved` | استجابة   | المبلغ بالدولار الأمريكي الذي تم توفيره بفضل ذاكرة التخزين المؤقت عند حدوث `HIT` (لإصابات ذاكرة التخزين المؤقت فقط)                                                               |
| `X-OmniRoute-Decision`   | استجابة   | تتبع التوجيه: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` هي استراتيجية الدمج، أو `single` للطلب غير المدمج) — موجود دائمًا في استجابات الإكمال                 |

> ملاحظة Nginx: إذا كنت تعتمد على رؤوس تستخدم الشرطة السفلية (مثل `x_session_id`)، فعّل `underscores_in_headers on;`.

#### تثبيت الحساب لكل طلب

عندما يكون لدى موفر عدة اتصالات (حسابات أو مفاتيح)، يختار OmniRoute عادةً أحدها
من خلال استراتيجية اختيار الحساب. ويمكن للطلب بدلًا من ذلك تثبيت اتصال محدد
باستخدام الرأس `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **أين يمكن العثور على المعرّف.** افتح صفحة الموفر في لوحة التحكم
  (**Dashboard → Providers → <provider>**) وانقر على شريحة المعرّف `xxxxxxxx…` في صف الاتصال — سيؤدي ذلك إلى نسخ معرّف الاتصال الكامل.
- **الطلبات التي تحترمه.** الطلبات ذات النموذج الواحد (`provider/model`) على
  `/v1/chat/completions` و`/v1/messages` و`/v1/responses`. تتجاهل التركيبات الرأس: ثبّت حسابًا لكل خطوة في التركيبة من خلال اتصال الخطوة نفسه.
- **التثبيت صارم وليس تفضيلًا.** يُستخدم الاتصال المثبّت حصريًا. يسجّل حدوث فشل داخل الطلب فترة تبريد للحساب، لكنه **لا** ينتقل إلى حساب شقيق لدى الموفر نفسه.
- **فترة التبريد والحصة تحرران التثبيت.** أثناء دخول الاتصال المثبّت في فترة تبريد، أو استنفاد حصته أو حظره بواسطة سياسة حصة، تعود الطلبات اللاحقة إلى الاتصالات الأخرى لدى الموفر، تمامًا كما يحدث مع حركة المرور غير المثبّتة.
- **تفشل المعرّفات غير المعروفة أو المعطّلة.** إذا لم يكن المعرّف ضمن مجموعة الموفر النشطة (محذوفًا أو معطّلًا أو تابعًا لموفر آخر)، فلن يبقى أي حساب مؤهل، ولذلك يفشل الطلب بدلًا من توجيهه بصمت إلى مكان آخر.

يرسل Claude Code الرؤوس المخصصة من خلال `ANTHROPIC_CUSTOM_HEADERS`. ضعه في كتلة `env`
في `~/.claude/settings.json`، أو في `.claude/settings.json` على مستوى المشروع لتثبيت حساب مختلف لكل مشروع:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

المصدر: `src/sse/handlers/chat.ts` (قراءة الرأس)، و
`src/sse/services/auth.ts` و`src/sse/services/sessionAffinityPin.ts` (تحرير التثبيت والتحقق من الغياب عن المجموعة).

> **رؤوس بيانات تكلفة الاستخدام:** تحمل استجابات النجاح غير المتدفقة أيضًا مجموعة بيانات تكلفة الاستخدام `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (بالدولار الأمريكي، 10 منازل عشرية ثابتة؛ `0.0000000000` للمجاني/غير المسعّر)، و`X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`، و`X-OmniRoute-Model`، و`X-OmniRoute-Provider`، و`X-OmniRoute-Latency-Ms`، و`X-OmniRoute-Cache-Hit`، و`X-OmniRoute-Fallback-Attempts` (فقط عندما تكون القيمة أكبر من 0)، بالإضافة إلى `X-OmniRoute-Request-Id` و`X-OmniRoute-Version`. تُصدر هذه الرؤوس من خلال إكمالات الدردشة، و`/v1/responses`، و`/v1/messages`، **ونقاط نهاية الوسائط** — `/v1/embeddings`، و`/v1/images/generations`، و`/v1/audio/speech`، و`/v1/audio/transcriptions`، و`/v1/rerank`، و`/v1/videos/generations`، و`/v1/music/generations`، و`/v1/moderations` (بتكلفة `0` دائمًا). تُحتسب تكلفة الوسائط لكل نوع من أنواع الوسائط (لكل صورة، ولكل ثانية، ولكل حرف، ولكل وحدة بحث) عند توفر التسعير، وإلا فتكون `0` (مع استمرار التشغيل عند الفشل).

> **دلالات تكلفة إصابة ذاكرة التخزين المؤقت:** عند حدوث إصابة في ذاكرة التخزين المؤقت الدلالية (`X-OmniRoute-Cache-Hit: true`)، لا يُجرى أي استدعاء للجهة السابقة، ولذلك تكون قيمة `X-OmniRoute-Response-Cost` هي `0.0000000000` (أي التكلفة **الإضافية** لتقديم الاستجابة المخزنة). وتُبلّغ التكلفة الأصلية/المفترضة بشكل منفصل في `X-OmniRoute-Cost-Saved`. يجب على مستهلكي الفوترة جمع `X-OmniRoute-Response-Cost` (فالإصابات لا تكلّف شيئًا)؛ بينما يمكن لتحليلات ذاكرة التخزين المؤقت تجميع `X-OmniRoute-Cost-Saved`.

## عقود إيجار الجلسات المُدارة الحصرية

يُعدّ تأجير الجلسات المُدارة الحصري عقد توجيه اختياريًا ومحايدًا تجاه العميل: يحتفظ مالك نشط
واحد باتصال OmniRoute مؤهل واحد. ولا يؤجّر نموذجًا، ولا يتطلب OAuth، ولا يحدد عميلًا
معينًا، ولا يتطلب موفرًا معينًا.

يجب أن يمتلك مفتاح API المُصادِق النطاق `lease:exclusive` وقائمة `allowedConnections` صريحة وغير فارغة.
وتفرض حدود تغيير قاعدة البيانات وجود كلا الحقلين معًا عند إنشاء المفتاح وإجراء التحديثات الجزئية.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

تعرض استجابات الاكتساب والتجديد والتحرير الناجحة الطوابع الزمنية و`state` و`generation` الموجب
الدقيق، لكنها لا تعرض الاتصال المحدد أو بيانات الاعتماد مطلقًا. يرسل التجديد والتحرير قيمة
الجيل في نص JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

يمكن لمالك إيجار نشط طلب بيانات عرض آمنة للخصوصية صراحةً للارتباط الحالي:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

يُؤمَّن إجراء الحالة الاختياري هذا بواسطة المالك غير الشفاف، ومفتاح API المُدار المُصادَق عليه،
والجيل النشط الدقيق، وذلك ضمن معاملة واحدة في قاعدة البيانات. لا يكون `displayName` سوى اسم
الاتصال المُكوَّن بعد إزالة المسافات الزائدة؛ ويكون `null` عند عدم وجود اسم مُكوَّن آمن. لا
يستبدل OmniRoute هذا الاسم مطلقًا ببريد إلكتروني أو بهوية حساب مُولَّدة. وتكون قيمة الموفر
تسمية عرض غير حساسة، وليست مطلقًا معرّف موفر متوافق مُولَّدًا. تُستبعد بيانات الاعتماد،
والرموز المميزة، وملفات تعريف الارتباط، ومعرّفات الاتصال أو مفاتيح API الخام، وتجزئات المالكين،
وأسرار الحماية، وبيانات التوجيه الداخلية.

تُرجع عمليات البحث باستخدام مفتاح خاطئ أو مالك خاطئ أو جيل قديم أو قيمة مفقودة أو منتهية الصلاحية
أو مُحرَّرة أو مُبطلة الخطأ نفسه `409 LEASE_FENCE_STALE` دون بيانات وصفية للاتصال. ولا يملك العميل
الذي تلقى استجابة انتظار السعة أي ارتباط نشط لفحصه. وعندما ينقل التوجيه إيجارًا نشطًا، يظل
الجيل نفسه صالحًا، وتُرجع الحالة الارتباط الجديد ذريًا، وليس القديم مطلقًا. وتظل العملاء الحاليون
دون تغيير لأن استجابات الاكتساب والتجديد والتحرير والانتظار تحتفظ بأشكالها السابقة.

لا يغيّر عقد الخادم هذا نقطة النهاية `/status` الخاصة بـ OpenAI Codex القياسي. يبلّغ Codex
القياسي حاليًا عن موفر نموذجه وحالة المصادقة/الحساب المضمّنة فيه، لكنه لا يعرض بيانات حساب
موفر مخصص عشوائية؛ ويجب على تكامل عميل لاحق استدعاء هذا الإجراء وتحديد كيفية عرض
`connection.displayName`.

يجب أن يرسل كل طلب استدلال مُدار بعد ذلك رأسي التحكم معًا:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

تُؤمَّن قيمة المالك الدقيقة والجيل الدقيق والاتصال النشط ومفتاح API المُصادَق عليه مباشرةً قبل
كل محاولة مدعومة مع المنبع. وتفشل إعادة استخدام المالك والجيل مع مفتاح آخر حتى عندما يسمح ذلك
المفتاح بالاتصال نفسه. ولا تُحفظ المالكين الخام أو تُسجَّل أو تُحتفظ بها في لقطة الطلب أو تُمرَّر
إلى المنبع.

يعيد التعارض المؤقت HTTP `429` مع `Retry-After` وما يلي:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

تعني هذه الاستجابة فقط أن مجموعة المؤهلين العادية لم تكن فارغة، وأن كل مرشح متاح كان محجوزًا
بواسطة إيجار نشط أجنبي. أما النماذج/الموفرون غير المدعومين، وعدم تطابق السياسة، وفترة التهدئة،
والحصة، والصحة، وغيرها من حالات فشل الأهلية العادية، فتحتفظ باستجاباتها الحالية في OmniRoute.

### `x-omniroute-compression`

تجاوز لكل طلب لخطة الضغط. يتمتع بأعلى أولوية — ويتغلب على تجاوز مجموعة التوجيه،
والملف النشط، والمشغل التلقائي، وDefault في اللوحة. القيم:

| Value         | Effect                                                                            |
| ------------- | --------------------------------------------------------------------------------- |
| `off`         | لا ضغط لهذا الطلب.                                                                |
| `default`     | ملف Default المشتق من اللوحة (يتجاهل الملف النشط). وتظل المحركات الفاقدة متوقفة.  |
| `safe`        | إزالة التكرار وطيّ المسافات البيضاء فقط.                                          |
| `allow-lossy` | الاحتفاظ بخطة المشغّل لهذا الطلب، بما في ذلك الملخصات وإعادة كتابة الأسلوب.       |
| `engine:<id>` | محرك واحد عند تمكينه، مثل `engine:rtk`. تفعيل اختياري لذلك المحرك لكل طلب.        |
| `<combo>`     | مجموعة مُسمّاة، تتم مطابقتها بالاسم (دون حساسية لحالة الأحرف) أولًا، ثم بالمعرّف. |

ملاحظات:

- تُتجاهل القيم غير المعروفة (ولا يُرفض الطلب مطلقًا)؛ ويستمر الحل وفق أولوية المشغّل العادية.
- إذا اشتركت مجموعات متعددة في اسم واحد، فأرسل **المعرّف** `id` للمجموعة لضمان تطابق حتمي.
- لا يمكن تحديد مجموعة اسمها `off` أو `default` بالاسم (إذ تُفسَّر تلك الكلمات المفتاحية أولًا)؛ ويجب الإشارة إلى هذه المجموعة بمعرّفها.
- مفتاح الضغط الرئيسي هو بوابة صارمة: عند تعطيل الضغط عالميًا، لا يمكن لهذا الرأس تفعيله.

تُعاد الخطة المطبقة في رأس الاستجابة:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

حيث يكون `<source>` واحدًا من `request-header` أو `routing-override` أو `active-profile` أو `auto-trigger` أو `default` أو `off`.

## التضمينات

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "كان الطعام لذيذًا"
}
```

المزوّدون المتاحون: Nebius وOpenAI وMistral وTogether AI وFireworks وNVIDIA و**OpenRouter** وJina AI.

معرّفات الكتالوج هي `provider/model` (مثال: `jina-ai/jina-embeddings-v5-omni-small`). كما تُحلّ معرّفات نماذج Jina المجرّدة التي تظهر في السجل (مثل `jina-embeddings-v5-text-small` و`jina-reranker-v3.5`). تستخدم نماذج Jina للتضمين وإعادة الترتيب والتصنيف والتقسيم بيانات اعتماد لوحة التحكم `jina-ai` أولًا؛ أما `JINA_AI_API_KEY` فهو بديل يُستخدم فقط عند عدم وجود مفتاح في لوحة التحكم. بطاقة `jina-reader` مخصّصة لـ Reader / `r.jina.ai` فقط (`POST /v1/web/fetch`)، ولا تقدّم التضمينات أو إعادة الترتيب مطلقًا.

تقبل نماذج السجل التي تعلن عن دعم متعدد الوسائط أيضًا ما يصل إلى 32 عنصرًا منظمًا محايدًا تجاه المزوّد. أنواع عناصر الوسائط هي `text` و`image` و`audio` و`video` و`document`. أما `source` الخاص بالوسائط فهو إما `{"type":"url","url":"https://..."}` أو
`{"type":"base64","data":"...","media_type":"..."}`.

تقبل Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small` و`jina-ai/jina-embeddings-v5-omni-nano` والاسم المستعار للعائلة `jina-ai/jina-embeddings-v5-omni` → omni-small) أيضًا مستندات Jina الأصلية الخاصة بـ EmbeddingsV5Request، وتُمرّرها **كما هي** إلى `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "دراجة حمراء" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "وصف توضيحي" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

يمكن أن تكون قيم `{ image | audio | video | pdf }` الأصلية عنوان URL عامًّا عبر HTTPS، أو معرّف URI من نوع `data:`، أو قيمة base64 خام. لا يحوّل OmniRoute هذه الكائنات إلى سلاسل نصية ولا يجلب عناوين URL الأصلية للصور — إذ تتولى Jina جلب الوسائط العامة بنفسها. وتُمرّر حقول Jina الإضافية (`task` و`normalized` و`truncate` و`embedding_type`). ولا تزال وحدات Jina SKU المخصّصة للنص فقط ترفض المستندات غير النصية.

حدود الأمان والنقل:

- يجب أن تكون عناوين URL للوسائط البعيدة عامة وتستخدم HTTPS. تُجلب عناصر `{type,source:url}` الأساسية من جهة الخادم (مع إعادة التحقق من عمليات إعادة التوجيه، وحدود للمهلة والحجم، وDNS عام، وتثبيت الاتصال) وتُضمّن قبل استدعاء المزوّد. أما عناصر Jina الأصلية من الشكل `{image:"https://..."}` فتُمرّر كما هي بعد التحقق نفسه من استخدام HTTPS العام؛ وتتولى Jina جلب عنوان URL.
- تقتصر وسائط base64 المضمّنة على 8 MiB بعد فك الترميز لكل عنصر، وعلى 16 MiB بعد فك الترميز للطلب بأكمله.

ترجمة المزوّد (لا تُمرّر العناصر الأساسية دون تغيير):

- نماذج Jina متعددة الوسائط: يصبح كل عنصر من المستوى الأعلى كائنًا واحدًا ذا مفتاح للوسيط (`text` / `image` / `audio` / `video` / `pdf`) باستخدام معرّفات URI من نوع data للوسائط المضمّنة؛ ومتجه واحد لكل عنصر من المستوى الأعلى.
- عائلة Gemini Embedding 2: تتحول مصفوفة واحدة من المستوى الأعلى إلى طلب أصلي واحد من نوع `models/{model}:embedContent` مع `content.parts` (`text` أو `inline_data`).
- llama.cpp (`llama-cpp/<model>`، وأي نموذج حمّله الخادم المحلي): تتحول عناصر `text` الأساسية إلى سلاسل نصية عادية، بينما تتحول عناصر `image` و`audio` و`video` إلى كائن واحد من الشكل `{"content": [part]}` لكل منها، باستخدام أجزاء محتوى المحادثة الخاصة بـ llama-server (`image_url` و`input_audio` بالتنسيق `wav` / `mp3` / `flac` و`input_video`) مع بيانات مضمّنة؛ ومتجه واحد لكل عنصر من المستوى الأعلى. يجب أن يعمل الخادم باستخدام `--embedding --mmproj …`؛ وبدون جهاز إسقاط، سيرفض الوسائط بنفسه. أما `document` فغير مدعوم.
- ترفض النماذج غير المعروفة/الديناميكية التي لا تتضمن بيانات وصفية صريحة للوسائط الإدخال المنظم مع HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "دراجة حمراء" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

تُرجع مجموعات النماذج/الوسائط غير المدعومة HTTP 400 بدلًا من تحويل العنصر قسرًا. وتستمر حقول الامتداد غير الخاصة بالإدخال في طلبات السلاسل النصية/الرموز القديمة في المرور دون تغيير.

```bash
# سرد جميع نماذج التضمين
GET /v1/embeddings
```

## إنشاء الصور

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

تشمل موفّرات الخدمة المتاحة OpenAI (GPT Image 2) وxAI (Grok Image) وTogether AI (FLUX) وFireworks AI وNebius (FLUX) وHyperbolic وNanoBanana و**OpenRouter** و**ZenMux** وSD WebUI (محلي) وComfyUI (محلي).

يعيد `n` عددًا قدره `n` من الصور في `data[]`. أما الموفّرون الذين تعيد واجهة برمجة التطبيقات الأساسية لديهم صورة واحدة لكل استدعاء
(Black Forest Labs وStability AI وLeonardo وIdeogram وHaiper وHyperbolic وMagnific/Freepik
وNVIDIA NIM وCloudflare Workers AI)، فيحصلون على `n` استدعاءات منفصلة للواجهة الأساسية، بحد أقصى 4 استدعاءات قيد التنفيذ. تتم إزاحة `seed` ثابتة وفق فهرس الاستدعاء (`seed` و`seed + 1` و…)، بحيث تختلف الصور مع بقائها قابلة لإعادة الإنتاج. الحد الأقصى لـ`n` هو 10. يفشل الطلب بالكامل إذا فشل أي استدعاء. قائمة التنسيقات التي تستخدم التوزيع المتعدد هي `SINGLE_IMAGE_FANOUT_FORMATS` في
`open-sse/handlers/imageGeneration/fanOut.ts`.

يعيد ZenMux استخدام اتصال مفتاح API الحالي ويقبل البادئات `zenmux/` أو `zm/`:

- يستخدم `zenmux/openai/gpt-image-2` واجهة OpenAI Images API الخاصة بـZenMux. تشمل الخيارات `size`،
  و`quality` و`n` و`output_format` و`output_compression` و`background` و`response_format`.
- تستخدم الناشرات الأخرى، مثل `zm/meta/muse-image-1.0`، نقطة نهاية Vertex AI `:predict` الخاصة بـZenMux. تُحوَّل `n` إلى `sampleCount`، و`aspect_ratio` إلى `aspectRatio`، و`image_size`
  (`1K` و`2K` و`4K`) إلى `sampleImageSize`. يوفّر `size` بالبكسل نسبة أبعاد فقط، ولا يضمن أبعادًا بالبكسل. تختلف النسب والدقة والأعداد المدعومة حسب النموذج.
- يختار `zm/inclusionai/ming-image-0.1-design` أبعاده الخاصة. احذف `size`،
  و`aspect_ratio` و`image_size`؛ إذ تعيد القيم الصريحة HTTP 400. يمكن طلب PNG وJPEG وWebP باستخدام `output_format`.

يدعم هذا التكامل إنشاء الصور من النص، وليس تحرير الصور المرجعية. تتم تسوية مخرجات Vertex إلى `data[].b64_json`؛ ويعيد `response_format: "url"` عنوان URL للمصدر الأساسي باستخدام HTTPS أو عنوان URL لبيانات base64 عندما لا تتوفر إلا بايتات الصورة. تؤدي المخرجات الفارغة أو التي تمت تصفيتها إلى إرجاع خطأ بدلًا من نجاح فارغ. يعتمد الوصول إلى النماذج على حساب ZenMux. راجع [واجهة Vertex API الخاصة بـZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) و[واجهة OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

يتيح اتصال تسجيل الدخول إلى Microsoft 365 Copilot استخدام `copilot-m365-web/m365-copilot-image` عبر أداة الصور المضمنة في Copilot: دور Copilot واحد لكل صورة (`n` من 1 إلى 4)، مع استخدام `size` لتوجيه الاتجاه فقط، وإرجاع الصور مضمنة (`b64_json`، أو عنوان URL للبيانات عند استخدام
`response_format: "url"`). راجع [Microsoft 365 Copilot](../providers/COPILOT-M365.md#image-generation).

```bash
# سرد جميع نماذج الصور
GET /v1/images/generations
```

## التعرف الضوئي على المستندات

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

يحدد `model` موفر خدمة التعرف الضوئي على المستندات عبر بادئة `provider/model`؛ ويُحلّ معرّف النموذج المجرد (مثل
`mistral-ocr-latest`) إلى موفر الخدمة المسجل له، بينما تكون القيمة الافتراضية عند حذف `model`
هي Mistral (`mistral-ocr-latest`). موفرو الخدمة المسجلون (`open-sse/config/ocrRegistry.ts`):

| Provider id                   | Model id             | `model` value                                               | Notes                                                                                                          |
| ----------------------------- | -------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (or bare `mistral-ocr-latest`) | متزامن — يُعاد الرد مباشرةً من الاستدعاء الأولي الوحيد.                                                        |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                 | الاستدعاء الأولي غير متزامن (`analyze` + poll) — راجع أدناه.                                                   |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                     | متزامن، عبر نقطة نهاية الشريك `openapi/chat/completions` الخاصة بـ Vertex AI — راجع أدناه للمصادقة وعنوان URL. |

يستجيب موفرو الخدمة الثلاثة جميعًا بجسم بنفس بنية Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### تدفق الاستطلاع في Azure Document Intelligence

تتسم واجهة `analyze` في Azure Document Intelligence بعدم التزامن: يعيد الطلب الأولي ترويسة
`Operation-Location` بدلًا من جسم، ويجب إجراء استطلاع للنتيجة. يجري المعالج
(`open-sse/handlers/ocr.ts`) استطلاعًا لذلك العنوان كل ثانية لمدة تصل إلى 30 محاولة، ويفشل فورًا (ولا
يواصل الاستطلاع) عند تلقي رد استطلاع غير `ok` أو حالة `"failed"`، ويعيد `504` إذا كانت العملية لا تزال قيد التشغيل بعد استنفاد عدد المحاولات المسموح به. تتم تسوية استجابة Azure النهائية إلى البنية نفسها
`pages`/`markdown` المستخدمة مع Mistral قبل إعادتها إلى المستدعي، ولذلك لا يحتاج رمز العميل إلى معالجة خاصة بموفر الخدمة.

### مصادقة Vertex AI DeepSeek OCR وحل نقطة النهاية

يعيد `vertex-deepseek-ocr` استخدام مصادقة Vertex AI نفسها التي يدعمها OmniRoute مسبقًا لحركة
الدردشة/الصور (`open-sse/executors/vertex.ts`): يكون مفتاح واجهة برمجة التطبيقات الخاص بالاتصال إما بيانات اعتماد JSON لحساب خدمة (يتم تبادلها للحصول على رمز وصول OAuth قصير الأجل عبر تدفق JWT-bearer) أو رمز وصول OAuth مُصدَرًا مسبقًا ويُستخدم كما هو. يُنشأ عنوان URL لنقطة النهاية الأولية من نقطة نهاية الشريك العامة `openapi/chat/completions` الخاصة بـ Vertex، استنادًا إلى مشروع الاتصال ومنطقته — وتكون قيمة
`providerSpecificData.project`/`providerSpecificData.region` الصريحة لها الأولوية دائمًا؛ وإلا يُستخلص المشروع من
`project_id` في JSON الخاص بحساب الخدمة، وتكون المنطقة الافتراضية هي
`us-central1`. يحدث كلا الحلين في `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken` و`resolveVertexOcrBaseUrl`)، ويُستهلكان بواسطة
`src/app/api/v1/ocr/route.ts` قبل التوزيع إلى `handleOcr`.

### أسعار النماذج (`pricing`)

يحتوي الإدخال على كائن `pricing` عندما يعرف OmniRoute سعر النموذج. يأتي السعر
من جدول الأسعار الذي يستخدمه احتساب التكلفة: الإعدادات الافتراضية المضمّنة، والأسعار المتزامنة،
والتجاوزات المحددة عبر `/api/pricing`. هذه أسعار القائمة، ولذلك يعرض موفرو الاشتراكات
أيضًا سعرًا لكل رمز مميّز.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| الحقول                                                          | الوحدة                                      | الملاحظات                                                                                                                                       |
| --------------------------------------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | الدولار الأمريكي لكل رمز مميّز، سلسلة عشرية | متوافقة مع OpenRouter، ولا تستخدم مطلقًا ترميز الأسّ. يظهر حقلا ذاكرة التخزين المؤقت فقط عند وجود سعر لذاكرة التخزين المؤقت.                    |
| `input`, `output`, `cached`, `cache_creation`                   | الدولار الأمريكي لكل مليون رمز مميّز، رقم   | حقول من إصدارات الكتالوج السابقة، ومُبقية للعملاء الحاليين. يظهر الحقلان `reasoning` و`long_context` أيضًا عندما يحتوي صف الأسعار على قيمتيهما. |

- تحمل **التركيبات** سعر هدفها الأول الظاهر. تختار تركيبات `auto/*` المضمّنة
  هدفًا في وقت الطلب، ولذلك لا تحتوي على `pricing`.
- تعرض **النماذج المجانية** `"0"` (و`0`) عندما يكون سعرها صفرًا. كما يعرض النموذج الذي لا يحتوي على صف أسعار
  `"0"` عندما يحدد الكتالوج أنه مجاني (`free: true`) أو عندما يدرجه كتالوج النماذج المجانية المضمّن.
- **السعر غير المعروف:** لا يحتوي الإدخال على مفتاح `pricing`.
- **الموفّرون الذين يحاسبون وفق الرصيد** (مثل Kiro) يحاسبون لكل طلب بدلًا من كل رمز مميّز. وتحتفظ إدخالاتهم
  بالحقول الرقمية لكل مليون رمز مميّز التي كانت لديهم سابقًا، ولا تحتوي على حقول سلاسل نصية لكل رمز مميّز.
- **المتغيرات** (معرّفات جهد الاستدلال، والأسماء المستعارة دون التفكير، ونسخ الاكتشاف والبوابة)
  تنسخ سعر النموذج الذي توجّه إليه.
- تحمل الحقول الأسعار الأساسية فقط. ولا تغيّر مستويات السياق الطويل (حقل `long_context` الرقمي)
  ومضاعفات مستوى الخدمة (مثل Codex السريع أو المرن) قيمة `prompt` أو
  `completion`.
- يكون الكائن نفسه لكل أساليب المصادقة، بما في ذلك الطلب بأسلوب Anthropic
  مع `x-api-key` و`anthropic-version` (وتظل الاستجابة `{ "object": "list",
"data": [...] }`). التنفيذ: `src/app/api/v1/models/catalogPricing.ts`.

### بادئات معرّفات النماذج (`?prefix=`)

يُعلن عن معظم النماذج باستخدام **بادئة الموفّر**. ويتحكم في البادئة التي تحصل عليها
علامة الميزات `MODELS_CATALOG_PREFIX_MODE`، ويمكن تجاوزها **لكل طلب** باستخدام
معلمة استعلام — وهو أمر مفيد لعميل يريد قائمة نظيفة دون تغيير الإعداد على مستوى الخادم للجميع:

```bash
GET /v1/models?prefix=alias        # معرّف واحد لكل نموذج — بادئة الاسم المستعار المختصر
GET /v1/models?prefix=dual         # كلا النموذجين (الإعداد الافتراضي للخادم)
GET /v1/models?prefix=canonical    # بادئة معرّف الموفّر الكاملة فقط
```

| الوضع       | ما يُصدِره                                              | الملاحظات                                                                                                                                                                              |
| ----------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **و** `claude/claude-sonnet-4-6` | **الافتراضي.** يوجّه كلا المعرّفين إلى النموذج نفسه؛ وأُبقي عليهما حتى تظل إعدادات العملاء التي ثبّتت أيًا من الصيغتين تعمل. يضاعف حجم الكتالوج تقريبًا.                               |
| `alias`     | `cc/claude-sonnet-4-6`                                  | إدخال واحد لكل نموذج. يظل الموفّرون الذين لا يملكون اسمًا مستعارًا مميزًا يصدِرون إدخالاتهم، لذلك لا يضيع شيء.                                                                         |
| `canonical` | `claude/claude-sonnet-4-6`                              | إدخال واحد لكل نموذج تحت بادئة معرّف الموفّر الكاملة. يصدِر الموفّرون الذين لا يملكون اسمًا مستعارًا مميزًا (مثل `antigravity/…` و`agy/…`) معرّفهم الوحيد هنا أيضًا، لذلك لا يضيع شيء. |

يمكن أيضًا التعرّف على نسخة معكوسة في وضع `dual` دون معلمة الاستعلام: إذ تحتوي على حقل `parent`
يشير إلى المعرّف الأساسي.

ينبغي للعملاء الذين يعرضون منتقي نماذج طلب `?prefix=alias` — فهذا ما يفعله
[امتداد OmniCopilot لـ VS Code](../guides/VSCODE-COPILOT.md).

### عوامل تصفية الاكتشاف (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

تقبل `GET /v1/models` عوامل تصفية اختيارية للاكتشاف. وتظل الاستجابة
دون تغيير عند عدم استخدام أي منها. وهي تضيّق نطاق الكتالوج الذي يراه المتصل بالفعل (تُطبّق أذونات مفتاح API أولًا)،
وتُنفّذ قبل تقسيم الصفحات باستخدام `limit` / `after` بأسلوب OpenAI:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # يجب أن تكون كل قدرة مدرجة صحيحة
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` في الكتالوج؛ والصفوف التي لا تحتوي عليه تكون `chat`
GET /v1/models?q=sonnet&limit=10                           # مطابقة غير حساسة لحالة الأحرف للمعرّف أو الاسم
```

| المعلمة       | القيم                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | عدد صحيح غير سالب، تتم مقارنته مع `context_length`                                                  |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | من 1 إلى 200 محرفًا                                                                                 |

تؤدي القيمة غير المعروفة، أو قيمة `min_context` التي ليست عددًا صحيحًا غير سالب (مثل `1.5`)،
إلى إرجاع HTTP `400`، وتسرد الرسالة القيم الصالحة. التنفيذ:
`src/app/api/v1/models/catalogFilters.ts`.

### القائمة المختصرة للنماذج (`POST /v1/models/query`)

يعيد `POST /v1/models/query` قائمة قصيرة وحتمية من الكتالوج نفسه، مع نفس
المصادقة وإمكانية الرؤية لكل مفتاح مثل `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

جميع الحقول اختيارية. يقبل `capabilities` و`exclude` مصفوفة أو سلسلة مفصولة بفواصل؛
وتتم مقارنة `max_output` مع `max_output_tokens`. تُرتب النتائج حسب `owned_by` ثم `id`.
تكون القيمة الافتراضية لـ `limit` هي `20`، وتُحد القيم التي تتجاوز `100` إلى `100`. تؤدي
صيغة JSON غير صالحة، أو حقل غير معروف، أو قيمة غير صالحة إلى إرجاع HTTP `400`.

### نماذج الدردشة المخفية بشكل فردي

يُستبعد النموذج المحدد بأنه **مخفي** في صفحة موفره من الكتالوج، ويُرفض
مع HTTP `404` / `model_not_found` عند طلبه صراحةً. يستخدم الفحص موفر النموذج المحلول
والنموذج نفسه، بما في ذلك الأسماء المستعارة للموفرين، وبادئات عقد موفري التوافق،
والإعدادات الافتراضية للاتصال. تتجاوز المجموعة الأهداف المخفية ويمكنها استخدام نظير مرئي؛
وعندما لا يبقى أي هدف قابل للتنفيذ، فإنها تُرجع رمز الخطأ نفسه. يسري إلغاء الإخفاء في الطلب
التالي. لا تؤدي تجاوزات الرؤية الخاصة بالصور فقط إلى إخفاء نموذج الدردشة الذي يحمل المعرّف نفسه.

يُعد إعداد النموذج الفردي هذا منفصلًا عن
[قوائم السماح/المنع الخاصة بإظهار النماذج](../routing/MODEL_EXPOSURE_LIST.md)، التي تعمل على تصفية
إعلانات الكتالوج ومرشحي التوجيه التلقائي مع الإبقاء على التوجيه الصريح. وتستمر أذونات
النماذج الخاصة بمفتاح API في التطبيق بشكل مستقل. ويظل وضع بادئة الكتالوج الافتراضي هو `dual`.

### متغيرات النماذج بدون التفكير

بالنسبة إلى نماذج Claude القادرة على التفكير، يعلن `/v1/models` أيضًا عن متغير
**بدون التفكير** يكون معرّفه مسبوقًا بـ `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

يؤدي اختيار هذا المعرّف (مثلًا في إعداد Claude Code الذي يرفق دائمًا كتلة `thinking`)
إلى الحل مجددًا إلى `<provider>/<model>` الحقيقي مع كبت الاستدلال — أي
`thinking:{type:"disabled"}` في مسار `/v1/messages`، أو إسقاط حقلي
`reasoning`/`reasoning_effort` في مسار `/v1/chat/completions`. لا تُدرج هذه الصيغة
إلا لنماذج عائلة Claude التي تدعم التفكير **وتحترم** `disabled` (ولذلك تُستبعد مثلًا
النماذج التكيفية فقط التي ترفض `disabled`). ويمكن للمشغلين فرض تفعيل الصيغة أو تعطيلها
لكل نموذج عبر `ModelSpec.noThinkingAlias`.

## إنشاء الصوت باستخدام ElevenLabs

كوّن اتصال مزوّد `elevenlabs` في OmniRoute باستخدام مفتاح API الخاص بـ ElevenLabs.
يصادق العملاء باستخدام مفتاح **OmniRoute** الخاص بهم (`Authorization: Bearer $OMNIROUTE_API_KEY`)؛
وتزوّد البوابة مزوّد الخدمة بالمفتاح المخزّن باعتباره `xi-api-key`. لا ترسل مفتاح ElevenLabs
مطلقًا باعتباره رمز حامل البوابة.

| الطريقة | المسار                      | الاستجابة                               | فئة نقطة نهاية مفتاح API |
| ------- | --------------------------- | --------------------------------------- | ------------------------ |
| POST    | `/v1/sound-generation`      | وحدات بايت صوتية أصلية                  | `elevenlabs`             |
| POST    | `/v1/music`                 | وحدات بايت صوتية أصلية                  | `music`                  |
| POST    | `/v1/music/stream`          | وحدات بايت صوتية صوتية متدفقة           | `music`                  |
| POST    | `/v1/music/detailed`        | صوت أصلي متعدد الأجزاء وخطة تأليف       | `music`                  |
| POST    | `/v1/music/detailed/stream` | بيانات وصفية أصلية عبر SSE ومقاطع صوتية | `music`                  |
| POST    | `/v1/music/plan`            | خطة تأليف بصيغة JSON                    | `music`                  |

تكمّل نقاط النهاية هذه المسارات الحالية `/v1/audio/speech` و`/v1/audio/transcriptions`
و`/v1/voices` و`/v1/text-to-speech/{voiceId}` و`/v1/speech-to-text`. يتم الحفاظ على حقول JSON
الأصلية ومعلمات الاستعلام مثل `output_format` و`enable_logging`.
تحتفظ استجابات `/v1/music/detailed` بحدود الأجزاء المتعددة؛ لذا حلّلها على أنها متعددة الأجزاء.
تعيد `/v1/music/detailed/stream` نوع المحتوى `text/event-stream` مع بيانات وصفية للتأليف
ومقاطع صوتية بترميز base64 ضمن أحداث SSE. تدعم المسارات الستة جميعها طلبات CORS التمهيدية.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# مؤثر صوتي قصير. المدة: من 0.5 إلى 30 ثانية.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# تُعبَّر مدة الموسيقى بالمللي ثانية: من 3000 إلى 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

استخدم `/v1/music/stream` مع نص JSON نفسه لتسليم الصوت تدريجيًا. يقبل التأليف واحدًا فقط من
`prompt` أو `composition_plan`؛ وتتطلب `/v1/music/plan` قيمة `prompt`، وتقبل اختياريًا
`source_composition_plan`. تحافظ المخططات الأصلية على حقول إضافية للمزوّد، بحيث تصل إصدارات
خطط التأليف وخيارات الضبط الدقيق إلى ElevenLabs.

تقبل نقطة النهاية الموحدة `/v1/music/generations` أيضًا
`elevenlabs/music_v1` و`elevenlabs/music_v2` و`elevenlabs/music_v2_5`. عند وجود اتصال نشط
بـ ElevenLabs، تُعرَض هذه النماذج في كتالوج الموسيقى. تعيد نقطة النهاية هذه
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. وتكون قيمة الحقل `duration`
بالثواني، وتُحوَّل إلى `music_length_ms`؛ وتكون الأولوية لقيمة `music_length_ms` الصريحة.
ويُحوَّل `instrumental` إلى `force_instrumental`، مع إعطاء الأولوية للحقل الأصلي.
استخدم نقاط النهاية الأصلية للبث، ونقطة نهاية التأليف الأصلية للطلبات المعتمدة فقط على خطة تأليف.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

تُطبَّق قيود نقطة النهاية والنموذج والميزانية والاتصال قبل إجراء استدعاء إلى المزوّد الأعلى.
تعيد المسارات الأصلية رموز حالة المزوّد الأعلى ونصوص الأخطاء دون تغيير، بما في ذلك `402`
عند وجود قيد على الخطة و`429` عند بلوغ حد الحصة. ويتم الحفاظ على ترويسات
`character-cost` و`song-id` و`request-id` و`retry-after` عند وجودها. لا يضمن رصيد ائتماني مجاني
إمكانية الوصول إلى كل نموذج موسيقى أو تنسيق إخراج أو ميزة API؛ إذ تحدد ElevenLabs الاستحقاق
لكل طلب. وتحافظ نقطة النهاية الموحدة على رموز حالة الأخطاء ضمن غلاف الأخطاء الموحّد في OmniRoute.

عقود المزوّد الأعلى: [المؤثرات الصوتية](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert)،
[تأليف الموسيقى](https://elevenlabs.io/docs/api-reference/music/compose) و
[تفاصيل بث الموسيقى](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

```bash
# إعادة الترتيب (موفر سجل سحابي، أو عقدة موفر متوافقة مع OpenAI بالصيغة "<prefix>/<model>")
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# تصنيف Jina (بيانات اعتماد Foundation API)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# أداة تقسيم Jina
POST /v1/segment     { "content": "...", "return_chunks": true }

# بحث Jina (s.jina.ai؛ الأسماء المستعارة للموفر: jina-search وjina-ai وjina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# الإشراف على المحتوى
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# تحويل النص إلى كلام — يعيد جسمًا من audio/mpeg (أو بالتنسيق المطلوب)
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# يتطلب تحويل النص إلى كلام في Soniox لغةً وصوتًا: تكون `language` افتراضيًا "en"؛ ويُحوَّل
# الصوت المفقود أو اسم صوت قياسي من OpenAI (alloy وnova و…) إلى "Adrian"
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# تحرير صورة (متعدد الأجزاء)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# توليد الفيديو/الموسيقى (معرّف نموذج مسبوق بالموفر)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **عُقد مزوّدي إعادة الترتيب:** يوجّه `POST /v1/rerank` أيضًا إلى عُقد مزوّدين متوافقة مع OpenAI
> (oMLX وvLLM وInfinity وTEI خلف بوابة، …) ويُشار إليها بصيغة `<node-prefix>/<model>`. تكون عُقد
> loopback (`localhost` و`127.0.0.1` و`172.16.0.0/12`) مؤهلة دائمًا، وكذلك أسماء المضيفين التي
> يدرجها المشغّل في `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (مثل اسم خدمة Docker/Compose
> كـ `http://reranker:8080/v1`؛ ويُتصل بهذه العُقد مباشرةً، وليس عبر `HTTP(S)_PROXY` أو الوكيل
> المثبّت لاتصال). لا تكون العُقد الموجودة على أي مضيف آخر — مثل جهاز على الشبكة المحلية أو نظير
> Tailscale — مؤهلةً إلا عند تمكين المشغّل لميزة
> `RERANK_REMOTE_PROVIDER_NODES` **واجتياز عنوان URL الأساسي للعقدة لسياسة عناوين URL الصادرة للمزوّد**
> (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> يستدعي محرّك الذاكرة خطوة إعادة الترتيب هذه عبر loopback، ولذلك تنطبق القاعدة نفسها على
> `rerankProviderModel` في إعدادات الذاكرة.
>
> **أشكال الخادم المحلي:** يُستدعىَت العقدة على العنوان `<base>/v1/rerank`، وعند تلقي 404 على العنوان
> `<base>/rerank` (Infinity وTEI). يحمل نص الطلب المرسل إلى المنبع كلا صيغتي Cohere/OpenAI
> (`documents` و`return_documents`) وصيغة TEI (`texts` و`return_text`)، وتُطبَّع استجابة المنبع
> إلى غلاف Cohere: تعود قائمة TEI العارية `[{index, score, text}]`، و`{results: [{index, score}]}`
> من البوابات الوسيطة البسيطة، وكذلك `{data: [...]}` بأسلوب Voyage، إلى العميل بصيغة
> `{results: [{index, relevance_score, document?}]}`، مرتبةً حسب الدرجة ومحدودةً بـ `top_n`.

> **اكتشاف عُقد المزوّد:** تظهر النماذج الموجودة على عقدة مزوّد متوافقة مع OpenAI في
> `GET /v1/models` ضمن بادئة العقدة. ترث الصفوف التي لا تحتوي على بيانات وصفية لنقطة النهاية (وهو أمر
> شائع في قوائم `/v1/models` المحلية) قيمة `apiType` الخاصة بالعقدة، ولذلك تكون نماذج عقدة
> `embeddings` من النوع `type: "embedding"`، وتكون نماذج عقدة `rerank` من النوع `type: "rerank"`،
> بدلًا من تعيينها افتراضيًا إلى chat؛ أما `supportedEndpoints` الصريحة في صف تمت مزامنته أو
> إضافته يدويًا فتظل لها الأولوية.

| ------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------- |

### مجموعات search/fetch المسماة

يقبل كل من `POST /v1/search` و `POST /v1/web/fetch` `model` كاسم مجمع محفوظ. استخدم إما `model` أو `provider` صريحًا؛ إرسال كل من العائدات `400`. بدون أي من الحقلين، يظل التحديد التلقائي للموفر الحالي بدون تغيير.

يعرض كل من Combo Builder وكتالوج Add Model الخاص به إدخالات عمليات الويب الأصلية للموفرين المتصلين، حتى عندما لا يكون لديهم قائمة نماذج LLM. يظهر سيربر** البحث على شبكة الإنترنت** ; عروض تافيلي** بحث الويب / استخراج الصفحة** ، ويظهر موفري خدمة الجلب فقط** استخراج الصفحة** . اختر الإدخال والحساب كالمعتاد. يخدم إدخال Tavily واحد كلا نقطتي نهاية الويب؛ لا تتم إضافة إدخالات العملية هذه إلى محددات عميل الدردشة فقط أو تحقيقات نموذج الدردشة.

على سبيل المثال، قم بإنشاء** أولوية** التحرير والسرد المسمى `shared-free` مع هذه الأهداف المرتبة:

1. `openai/gpt-4o`
2. `tavily-search/web`
3. `serper-search/web`
4. `jina-reader/fetch`

ثم استخدم نفس الاسم على كل سطح:

```json
{ "model": "shared-free", "query": "Open source speech recognition", "max_results": 5 }
```

```json
{ "model": "shared-free", "url": "https://example.com", "format": "markdown" }
```

يعتبر البحث تافيلي ثم سيربر؛ جلب يعتبر تافيلي ثم جينا القارئ؛ تتخطى الدردشة موفري search/fetch المخصصين وتأخذ في الاعتبار OpenAI. يأتي التوافق من سجلات منفذ search/fetch ، وليس من الكلمات الموجودة في اسم النموذج. تسبق عملية التصفية تحديد بيانات الاعتماد وإرسالها، ولا تقوم مطلقًا بتحرير المجموعة المحفوظة.

تدعم المسارات غير المخصصة للدردشة `priority` و `fill-first` `round-robin` `weighted` و `random` و `strict-random` و `least-used` و `p2c`. يتم رفض إستراتيجيات تركيب الدردشة فقط مثل `fusion` و `pipeline` و `context-relay` في مسارات غير الدردشة بدلاً من تطبيقها بصمت على البحث أو الوسائط التي تم إنشاؤها. يعالج محرك التحرير والسرد الموجود الإجراء الاحتياطي المطلوب، بما في ذلك حالات فشل الحصص الأولية، ويحتفظ بالخطوة IDs ودبابيس الحساب والقوائم المسموح بها للحساب لكل خطوة والمراجع المتداخلة ونطاقات connection/quota للمتصل وسياسة الوصول إلى التحرير والسرد. تحتفظ النتائج بمخطط search/fetch الأصلي الخاص بها، بما في ذلك الموفر الفعلي؛ يحدد `X-OmniRoute-Combo-Trace` قرار التوجيه. مجموعات غير معروفة ترجع `404`؛ المجموعات والمجموعات غير النشطة التي لا تحتوي على أهداف متوافقة تُرجع `400`.

تستخدم كل محاولة تحرير وسرد موفرًا صريحًا واحدًا. لا يمكن استدعاء تجمع الموفر التلقائي الأصلي خلف ظهر المجموعة. تحتفظ طلبات الموفر الصريحة بسلوك الموفر الفردي الحالي. تقوم طلبات الدردشة المباشرة التي تستهدف موفري search/fetch المخصصين بإرجاع JSON `400` قابل للتنفيذ بدلاً من الوقوع في منفذ تنفيذي على طراز OpenAI.

### طرق التحرير والسرد الخاصة بالقدرة

قد تحتوي المجموعات المحفوظة على كائن `routes` الذي تكون مفاتيحه عبارة عن إمكانيات API. يمتلك كل مسار قائمة الأهداف والإستراتيجية وتكوين وقت التشغيل الخاص به. تظل خطط الدردشة ذات المستوى الأعلى `models` و `strategy` و `config` هي خطة الدردشة المتوافقة مع القديم؛ المجموعات القديمة التي لا تحتوي على `routes` تستمر في العمل دون تغيير.

مفاتيح المسار المدعومة هي `chat` `search` `web-fetch` `embeddings` `rerank` `images` `image-edits` `videos` `music` `ocr` `audio-speech` `audio-transcriptions` و `audio-translations` و `audio-generation`. يحدث إسقاط نقطة النهاية قبل تحديد بيانات الاعتماد أو التسجيل أو الإرسال. تحدد مراجع التحرير والسرد المتداخلة مسار التحرير والسرد الفرعي لنفس الإمكانية.

يقبل `POST /v1/music/generations` و `POST /v1/ocr` اسم التحرير والسرد في `model`. يقبل `POST /v1/music` الأصلي المتوافق مع ElevenLabs أيضًا اسم التحرير والسرد في `model_id`، ولكن يجب أن يكون كل هدف قابل للاستخدام على نقطة النهاية الأصلية تلك نموذجًا موسيقيًا ElevenLabs بحيث يتم الحفاظ على عقد الاستجابة الثنائية الخاص به. يقبل `POST /v1/sound-generation` التحرير والسرد `audio-generation` في `model_id` تحت نفس القيد الثنائي الأصلي. استخدم `/v1/music/generations` لموفري الموسيقى غير المتجانسين.

**التحديد التلقائي:** وبدون `provider`، فإن أرخص مزود مزود باتصال تم تكوينه يعمل أولاً، ثم الموفر التالي الأرخص هو تجاوز الفشل. يتم استخدام موفري الملاذ الأخير المجاني (`duckduckgo-free`) فقط عندما لا يتم تكوين أي شيء آخر. يتم احتساب SearXNG المستضاف ذاتيًا على أنه تم تكوينه بمجرد أن يقوم اتصاله بتخزين `baseUrl` حقيقي (وليس موفر الكتالوج الافتراضي `http://localhost:8888/search`): ثم يتم تصنيفه كموفر $0 قبل المزودين ذوي المفاتيح، مع أرخص مزود مفاتيح كتجاوز الفشل، بما في ذلك عندما يجيب SearXNG على 400 أو 401 أو 403 أو 404. لا يتم احتساب `baseUrl` الذي لا يعد `http(s)` URL صالحًا أو الذي يشير إلى عنوان بيانات تعريف السحابة. اتصال SearXNG الذي يخزن رمزًا مميزًا يتم ترتيبه بهذه الطريقة فقط عبر `https://` أو الاسترجاع `http://`. عبر `http://` العادي عن بعد، لا يتم تجاوز الفشل أبدًا ويبقى الملاذ الأخير، ويستخدم فقط عندما لا يتم تكوين أي موفر آخر أو عند الطلب بالاسم، لذلك فهو يرسل الرمز المميز بنص واضح في هاتين الحالتين.

### اكسا وتافيلي `provider_options`

يقوم Exa وTavily بقراءة الحقول الخاصة بالموفر من حقيبة مساحة الاسم: `provider_options.exa` (أو `provider_options["exa-search"]`) و `provider_options.tavily` (أو `provider_options["tavily-search"]`). تتم إعادة توجيه المفاتيح أدناه فقط. يتم فحص كل واحد مقابل مخطط Zod الخاص به في `open-sse/handlers/search/providerOptionsPassthrough.ts`، ويتم إسقاط المفتاح الذي يحتوي على نوع خاطئ. يتم تجاهل أي مفتاح آخر، بما في ذلك auth وbase URL و `stream` و `outputSchema`. تعمل المفاتيح المسطحة التي يستخدمها مقدمو الخدمات الآخرون (`cx`، `depth`، ...) كما كانت من قبل.

| مزود   | حقول المستوى الأعلى                                                                                                                                                                                                                                                                                                                                                       | متداخلة                                                                                                                               |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| إكسا   | `type`، `category`، `userLocation`، `moderation`، `additionalQueries`، `objective`، `systemPrompt`، `compliance` (الأوليات المسطحة)، `startPublishedDate`، `endPublishedDate`                                                                                                                                                                                             | تم دمج `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` على `{ text: true, highlights: true }` الافتراضي |
| تافيلي | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                     |

الحقول العامة تفوز دائمًا: `query` و `max_results` و `filters` (المجالات) و `country` والموضوع المشتق من `search_type`. في Exa، `search_type: "news"` يحتفظ `category: "news"`. يقبل Tavily أيضًا `search_type: "finance"` (`topic: "finance"`).

يتم تسجيل تكلفة بحث الزحف الناري لكل كتلة بدأت مكونة من 10 نتائج تم إرجاعها، بسعر 0.002 USD (اعتمادان) للكتل وكتلة واحدة على الأقل لكل مكالمة ( [فواتير الزحف الناري](https://docs.firecrawl.dev/billing) ): 11 نتيجة بتكلفة 0.004 دولار أمريكي.

يصل الآن `time_range` العام إلى كلا الموفرين: يحصل Exa على `startPublishedDate` (ISO timestamp) ويحصل Tavily على `start_date` (`YYYY-MM-DD`). التاريخ الصريح في `provider_options` يتجاوز التاريخ المعين.

نتائج Exa تحافظ على `id` و `highlights` (كل تمييز، وليس فقط أول واحد يستخدم كـ `snippet`) و `highlight_scores` و `summary` و `subpages` و `entities` و `extras` في `provider_raw`. نتائج Tavily تحافظ على `images` و `favicon`.

يتم تسجيل تكلفة البحث عن الارتباط بمبلغ 0.005 USD لـ `depth` `fast` و `standard` و0.05 USD لـ `deep` ( [تسعير الارتباط](https://docs.linkup.so/pages/documentation/development/pricing) )، سواء أتى `depth` من `provider_options` أو من إعدادات الاتصال.

يقبل Exa `type: "lite"` (Exa 3.0) مجموعة أصغر من الحقول ويرفض الطلب بالكامل عند تعيين أي حقل آخر. بالنسبة إلى lite، يتم إسقاط `additionalQueries` و `systemPrompt` وكل مفتاح `contents` باستثناء `text` و `highlights` قبل المكالمة. لم يعد يتم إعادة توجيه `subpages` و `subpageTarget` و `highlights.numSentences` و `highlights.highlightsPerUrl` المهملة.

محاسبة التكاليف هي السجل الثابت `costPerQuery`، باستثناء Exa، الذي يتبع تسعير Exa الخاص: 0.007 USD لكل استدعاء لـ `auto` (و `fast` القديم) أو 0.004 USD لـ `lite` (و `instant` القديم)، ويغطي 10 نتائج؛ 0.001 دولار لكل نتيجة إضافية؛ و0.001 دولار لكل نتيجة يتم إرجاعها عند تعيين `contents.summary`. تم تسجيل Tavily برصيد واحد (0.008 دولار) لـ `search_depth` `basic` و `fast` و `ultra-fast` و 2 رصيد (0.016 دولار) لـ `advanced` ( [أرصدة Tavily API](https://docs.tavily.com/documentation/api-credits) ). المكالمة مع `auto_parameters: true` التي يقوم Tavily بترقيتها إلى المستوى المتقدم لا تزال مسجلة برصيد واحد.

## جلب الويب API

استخرج المحتوى من URL عبر موفر جلب الويب الذي تم تكوينه (Firecrawl، Jina Reader، Tavily Extract، TinyFish Fetch، Nimble Extract، Parallel Extract، Keenable Fetch).

استخراج متوازي (`parallel-search`، نفس مفتاح API مثل البحث الموازي) يُرجع Markdown فقط — أي `format` آخر هو `400` — ويشتمل المحتوى على 100000 حرف. عندما لا يمكن استخراج الصفحة المستهدفة نفسها، يقوم المنبع بالإبلاغ عنها داخل HTTP 200؛ تظهر OmniRoute على أنها `422` برسالة ثابتة.

يقوم Keenable Fetch (`keenable-search`) أيضًا بإرجاع Markdown فقط (أي `format` آخر هو `400`) ويحد المحتوى من 100000 حرف. إنه يعمل بدون مفتاح: يستخدم طلب `provider: "keenable-search"` الصريح بدون اتصال نقطة النهاية بدون مفتاح الخاصة بـ Keenable (حدود معدل كل IP). المفتاح الذي تم تكوينه يرفع هذه الحدود فقط؛ يستخدم التحديد التلقائي Keenable فقط عند تكوين المفتاح.

| طريقة | طريق            | وصف                                                                   |
| ----- | --------------- | --------------------------------------------------------------------- |
| POST  | `/v1/web/fetch` | Fetch/scrape a URL — تم التحقق من صحة الجسم بواسطة `v1WebFetchSchema` |

**المصادقة:** حامل مفتاح API (`extractApiKey` + `isValidApiKey`). يتم فرض السياسة عبر `enforceApiKeyPolicy`.

تستخدم المجموعات المسماة [عقد توجيه `model`](#named-searchfetch-combinations) أعلاه، مع الحفاظ على الخيارات والاستجابات الخاصة بالجلب.

**احتياطي مدرك للحصص (#8297):** عندما لا يتم إعطاء `provider` أو `model` ، يتم تنفيذ التجمع (`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` → `parallel-search` → `keenable-search`) بترتيب أولوية ثابت (الملء أولاً) — يتم تخطي موفر معدل محدود ولكن تم تكوينه بدلاً من قصر دائرة الطلب، وفشل retryable/quota المنبع (HTTP 429 دائمًا؛ 402/403 for Firecrawl/Tavily/TinyFish الطبقات المجانية بنمط الحصص — غير المخصصة لـ Jina Reader، وليس أبدًا لطلب سيء 400 عادي) تنتقل إلى موفر الاعتماد التالي الذي لم تتم تجربته في وقت الطلب. عندما يتم استنفاد كل موفر في التجمع، تقوم نقطة النهاية بإرجاع `429` واحد (برأس `Retry-After` ) بدلاً من `400` العام السابق. عندما يتم طلب `provider` صريح، هناك** لا** التراجع الصامت — يظهر الموفر الصريح ذو المعدل المحدود أو الفاشل الخطأ الخاص به (`429` إذا كان المعدل محدودًا، وإلا فإن الحالة الأولية).

## البث عبر WebSocket

```bash
GET /v1/ws?handshake=1
```

يتحقق من صحة مصافحة ترقية WebSocket ويعيد رسائل المثال الخاصة ببروتوكول السلك (`request` و`cancel`). تُعالَج إطارات WS الفعلية بواسطة خادم WS المضمّن خارج جدول مسارات Next.js.

**المصادقة:** مفتاح API لحامل الطلب أثناء المصافحة.

### واجهة Responses API عبر WebSocket (codex فقط)

```bash
# المضيف:المنفذ نفسهما المستخدمان في واجهة HTTP (الافتراضي 20128)؛ ترقية الاتصال:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (أو: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# يجب أن تكون الإطار الأول response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

يعمل وكيل Responses-API-over-WebSocket **حصريًا مع `codex`** (الواجهة الخلفية لـ ChatGPT). ويستمع على المنفذ نفسه الذي تعمل عليه الواجهة و/أو لوحة المعلومات، وعلى المسارات `/v1/responses` و`/responses` و`/api/v1/responses`. عند وصول إطار `response.create` الأول، يجري المصادقة + التحضير عبر جسر `codex-responses-ws` الداخلي، ويختار اتصال OAuth خاصًا بـ codex، ثم ينقل الاتصال النفقي إلى
`wss://chatgpt.com/backend-api/codex/responses`
عبر ناقل `wreq-js`. **تُرفض النماذج غير التابعة لـ codex** (`codex_ws_provider_required`).
لاستخدام توجيه مشاركة الحصة، استعمل `model: "qtSd/<group>/codex/<model>"`. تم التنفيذ في
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**المصادقة:** مفتاح API لحامل الطلب أثناء المصافحة. يجب أن يكون خادم HTTP المضمّن (`server-ws.mjs`)
هو نقطة الدخول النشطة (وهو كذلك افتراضيًا عند وجود `app/server-ws.mjs`).

#### معرّف النموذج: استخدم معرّف ChatGPT العاري (من دون بادئة `codex/`)

يتحقق **Codex CLI** من اسم النموذج من جانب العميل عند
تعيين `supports_websockets = true`، ويرفض **معرّفات الموفّرين** مثل
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). أرسل المعرّف **العاري** (مثل `gpt-5.5`). جسر OmniRoute مخصص لـ codex فقط،
لذلك يعيد حل المعرّف العاري بوصفه نموذج codex
(`resolveCodexWsModelInfo`) قبل إنشاء النفق إلى المصدر الأساسي — رغم أن
`gpt-5.5` العاري سيوجَّه بخلاف ذلك إلى موفّر آخر عبر HTTP.

#### تكوين OpenAI Codex CLI

وجّه Codex CLI إلى OmniRoute بإضافة موفّر مخصص مع دعم WebSocket إلى
`~/.codex/config.toml` (استخدم `CODEX_HOME` منفصلًا لتجنب تعديل تكوين موجود):

```toml
model = "gpt-5.5"                 # معرّف عارٍ — ليس "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # دون شرطة مائلة زائدة؛ يُشتق عنوان WS (استخدم https/wss في الإنتاج)
wire_api = "responses"                    # القيمة المدعومة الوحيدة منذ فبراير 2026
supports_websockets = true                # يفعّل ناقل Responses-over-WS
env_key = "OMNIROUTE_API_KEY"             # يحتوي على مفتاح API الخاص بـ OmniRoute (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # مفتاح API خاص بـ OmniRoute (أي مفتاح إذا كانت REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

ترقّي CLI العنوان `base_url + /responses` إلى WebSocket، وتنقل OmniRoute الاتصال النفقي
إلى اتصال OAuth المحدد الخاص بـ codex. تم التحقق من ذلك من البداية إلى النهاية مقابل الخادم المحلي: يعيد ChatGPT
`codex.rate_limits` + `response.created` ويبث الإكمال.

## الحصص والإبلاغ عن القضايا

| طريقة | طريق                | وصف                                                                                    |
| ----- | ------------------- | -------------------------------------------------------------------------------------- |
| GET   | `/v1/quotas/check`  | قم بالتحقق المسبق من الحصة النسبية لـ `provider` + `accountId` قبل إصدار مفتاح مسجل    |
| POST  | `/v1/issues/report` | الإبلاغ عن فشل إصدار quota/key إلى GitHub (يتطلب الرمز المميز `GITHUB_ISSUES_REPO` + ) |

**المصادقة:** يأخذ `/v1/quotas/check` مفتاح Bearer API (`isAuthenticated`). `/v1/issues/report` هو للإدارة فقط (`requireManagementAuth`)، مثل `/api/v1/registered-keys`: جلسة لوحة المعلومات، أو رمز CLI المحلي، أو مفتاح API مع نطاق `manage`/`admin` ؛ مفاتيح API للاستدلال فقط تحصل على `403`.

### استعادة حصة الجلسة (الاشتراك)

يمكن إيقاف `POST /v1/chat/completions` أو `POST /v1/responses` غير المتدفق الذي يفشل بسبب خطأ في الحصة النهائية (`402`/`429`/`503` الذي يقول جسمه أن الحصة أو الاعتمادات قد استنفدت) وإعادة تشغيله لاحقًا بدلاً من إرجاع الخطأ. يختار المتصل كل طلب بثلاثة رؤوس:

| رأس                          | قيمة                                          |
| ---------------------------- | --------------------------------------------- |
| `x-omniroute-quota-recovery` | `auto`                                        |
| `x-omniroute-session`        | معرف الجلسة، `[A-Za-z0-9._:-]{1,128}`         |
| `x-omniroute-recovery-turn`  | تحويل المعرف الفريد داخل الجلسة (نفس القاعدة) |

فقط `stream: false` المنعطفات التي لا تحتوي على أدوات أو سجل أدوات أو `previous_response_id` ولا يوجد دبوس `x-omniroute-connection` هي المؤهلة، ويجب تعيين `STORAGE_ENCRYPTION_KEY` (يتم تخزين الطلب مشفرًا لمدة تصل إلى 24 ساعة). الرد إذن هو `202` مع `recovery.poll`؛ استطلاع `GET /v1/quota-recoveries/{id}` (`202` أثناء الانتظار، `200` مع الجثة المستردة عند الانتهاء) أو الإلغاء باستخدام `DELETE`. تكون التذاكر مرئية فقط للمفتاح API الذي قام بإنشائها. الإعادة التي تكون نتيجتها غير مؤكدة تنتهي بـ `needs_confirmation` بدلاً من إرسالها مرتين. المصدر : `src/lib/quota/quotaSessionRecovery.ts`.

## استخدام الخدمة الذاتية (`/api/usage/om-usage`)

يمكن قراءة أي مفتاح API** خاص بها** الاستخدام والحصص — لا مصادقة الإدارة. هذه هي نقطة النهاية التي يستخدمها العميل (CLI، لوحة OmniCopilot ) لإظهار إنفاق حامل المفتاح.

```bash
# Text form (the historical contract — plain text for a terminal)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Structured form — what a UI consumes
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

يجب أن يكون المفتاح**`allowUsageCommand`** ممكّن (متوقف عن التشغيل افتراضيًا، يقوم مدير مفتاح واجهة — التطبيقات (API) بلوحة المعلومات بتبديله لكل مفتاح). بدونها تجيب نقطة النهاية على `403`.

تقوم `?format=json` بإرجاع شكل مميز بحيث لا يقرأ المتصل مطلقًا حقل بيانات في حالة الرفض. على النجاح:

```jsonc
{
  "allowed": true,
  // present only when the key opted into per-key usage limits (daily/weekly/5-hour USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // the selected provider quota snapshot, or null when nothing is cached yet:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // every connection's snapshot, so a UI can render several providers side by side:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

عند الرفض (مفتاح `401` السيئ / `403` غير مسموح به) يُرجع نفس المسار `{ "allowed": false, "error": { "message": "…" } }` — a `personal`/`provider` موجود ولكن فارغ (المفتاح مسموح به، لم يتم تعلم أي شيء بعد) هي حالة مختلفة عن حالة الرفض، ولا يميزهما سوى نموذج JSON.

**المصادقة:** مفتاح API الخاص بحامل المتصل، والذي تم التحقق من صحته باستخدام `isValidApiKey` — وهذا _ليس_ سطح الإدارة (`/api/keys/…`)، الذي يبقى خلف `requireManagementAuth`.

### النسب المئوية للحصص الخام مقابل القطع المعدلة

عند استهلاك `/api/usage/om-usage`، يجب على المتصلين ملاحظة الفرق بين النسب التي تقدمها** إخراج نص عادي** والمنظم** إخراج JSON** :

| وجه                  | تنسيق نص عادي (`/api/usage/om-usage` / `@@om-usage`)                                    | تنسيق JSON (`?format=json`)                                               |
| :------------------- | :-------------------------------------------------------------------------------------- | :------------------------------------------------------------------------ |
| **مجال الإخراج**     | `NN% left` (على سبيل المثال، `20% left`)                                                | `provider.quotas` / `providers[].quotas`                                  |
| **قياس**             | **البدل القابل للاستخدام المعدل حسب القطع** : القدرة المتبقية فوق عتبة القطع            | **حصة المنبع الخام** : قياس مزود غير المعدل                               |
| **تحجيم القطع**      | تم القياس عبر `effectiveRemainingPercent()` بحيث تتم قراءة المحمية المحمية كـ `0% left` | لا شيء (قيم اللقطة الأولية كما أبلغ عنها الموفر)                          |
| **بيانات العتبة**    | تم دمجها في النسبة المئوية المعروضة                                                     | مخزنة في `quotaWindowThresholds` لكل اتصال (أو إعدادات الخادم الافتراضية) |
| **المستهلك الأساسي** | CLIs التفاعلية، والمطالبات الطرفية، والمشغلين البشريين                                  | عمليات التكامل البرنامجي ولوحات المعلومات والتحليلات وأجهزة تتبع الفواتير |

#### صيغة تعديل القطع

يدعم OmniRoute قطع الحصص الاستباقية لمنع استنفاد المنبع (يتم تكوينه عبر اتصال `quotaWindowThresholds` أو إعدادات الموفر الافتراضية أو إعدادات المرونة العامة). عندما يكون حد القطع (على سبيل المثال، `cutoff = 25%`) نشطًا في نافذة الحصة النسبية، يقوم عارض النص بحساب البدل المتبقي على النحو التالي:

- إذا `remaining <= cutoff`: ترجع `0%`.
- إذا `remaining > cutoff`: ترجع `((remaining - cutoff) / (100 - cutoff)) * 100`.

يقوم إخراج النص المنسق بتقريب هذا إلى أقرب عدد صحيح (`Math.round(...)`).

#### مثال توضيحي

النظر في نافذة مزود مع** 60% استخدام خام** (لذلك** 40% من الحصة الخام المتبقية** ) وتكوينه** 25% من الحصص المتبقية** عتبة:

| التمثيل                       | حساب                                               |  متبقي  |              المستخدمة ضمنا              |
| :---------------------------- | :------------------------------------------------- | :-----: | :--------------------------------------: |
| **JSON خام (`?format=json`)** | لقطة المنبع (`quotas[window]`)                     | **40%** |                 **60%**                  |
| **تنسيق النص (`NN% left`)**   | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (في حالة حساب `100 - remaining`) |

- **لماذا يظهر النص 20% من اليسار:** من أصل 40% من الحصة المادية المتبقية في الحساب، يتم حجز 25% بواسطة سياسة القطع. يتبقى لدى المتصل 15% فقط من 75% من المساحة المخصصة للاستخدام قبل أن يتوقف جهاز التوجيه عن التوجيه إلى هذا الاتصال. يضمن القياس استنفاد إشارات الاتصال (`0% left`) تمامًا عند توقف التوجيه.
- **لماذا تحافظ JSON على القيم الأولية:** تقوم حمولة JSON بإرجاع لقطة الموفر الدقيقة (`UsageSnapshot`) حتى تتمكن الأدوات الخارجية من الوصول إلى الاستخدام المنبع للحقيقة الأرضية و `quotaWindowThresholds` على مستوى الاتصال دون تحجيم الفقد من جانب الخادم.

#### إرشادات هجرة المستهلك

إذا كان التكامل الخارجي (مثل البرنامج الإضافي للمحرر أو ملحق الوكيل) قد قام مسبقًا بإلغاء نقطة نهاية النص (`NN% left`) وحساب النسبة المئوية المستخدمة كـ `100 - NN`، فإن الترحيل إلى `?format=json` يعني:

- سوف تعكس قراءة قيم JSON الخام** الاستهلاك الفعلي للمنبع** (60% مستخدمة في المثال أعلاه).
- إذا كان التكامل يرغب في الحفاظ على دلالات البدل القابل للاستخدام لنقطة نهاية النص، فيمكنه تقييم الصيغة الفعالة المتبقية من جانب العميل باستخدام `quotaWindowThresholds` لتجاوزات مستوى الاتصال.

### تأثير زمن الاستجابة

تُرجع إصابة ذاكرة التخزين المؤقت الدلالية الاستجابة من ذاكرة التخزين المؤقت **من دون
إجراء استدعاء للمنبع**، ولذلك تكون قيمة `X-OmniRoute-Response-Latency` المُبلّغ عنها قريبة من الصفر
(بغض النظر عن زمن استجابة المنبع الأصلي). ينبغي للعملاء الحساسين لزمن الاستجابة
(المقارنة المعيارية، ومراقبة p50/p99) التحقق من ترويسة الاستجابة
`X-OmniRoute-Cache-Latency`:

| القيمة      | المعنى                                                                       |
| ----------- | ---------------------------------------------------------------------------- |
| `synthetic` | الاستجابة مقدمة من ذاكرة التخزين المؤقت؛ زمن الاستجابة ليس زمن المنبع الفعلي |
| _(absent)_  | الاستجابة من استدعاء فعلي للمنبع                                             |

### تجاوز ذاكرة التخزين المؤقت لكل مفتاح

| `legacy` | السلوك العادي لذاكرة التخزين المؤقت (افتراضيًا)                       |

## توافق إدارة CLIProxyAPI

تستجيب OmniRoute لنقاط النهاية الإدارية الثلاث الخاصة بـ [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)
التي تستدعيها لوحات معلومات الاستخدام لقراءة حدود اشتراكات Claude وCodex
(مثل مصدر حدود الاستخدام `cliproxy` في T3 Code). وجّه عنوان URL الأساسي للعميل إلى
OmniRoute واستخدم مفتاح API ذي نطاق `manage` كمفتاحه الإداري. تُخدَم المسارات
على `/v0/management/*` وعلى `/api/v0/management/*`.

| الطريقة | المسار                       | الوصف                                                                                                                               |
| ------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| GET     | `/v0/management/auth-files`  | اتصالات OAuth الخاصة بـ Claude وCodex بالشكل `{ files: [{ id, auth_index, provider, email, disabled, id_token }] }`. لا توجد رموز   |
| POST    | `/v0/management/api-call`    | النص `{ auth_index, method, url, header?, data? }`. يرسل طلبًا واحدًا مسموحًا به باستخدام رمز الحساب ويُرجع `{ status_code, body }` |
| POST    | `/v0/management/reset-quota` | النص `{ auth_index }`. يمسح فترة تهدئة الاتصال، وحالات حظر النماذج، وفترات التهدئة لكل نطاق في Codex لحساب واحد                     |

- `auth_index` هو معرّف اتصال OmniRoute. و`provider` هو `claude` أو `codex` (لاتصالات OAuth
  فقط؛ ولا يُدرج موفّر مفتاح API الخاص بـ `anthropic`). بالنسبة إلى Codex،
  فإن `id_token.chatgpt_account_id` هو معرّف مساحة العمل المخزّن، و`plan_type` هي الخطة المخزّنة.
- إن `api-call` ليس وكيلاً عامًا. فهو يقبل فقط Claude `GET
https://api.anthropic.com/api/oauth/usage` وCodex `GET https://chatgpt.com/backend-api/wham/usage`، و`GET .../wham/rate-limit-reset-credits` و
  `POST .../wham/rate-limit-reset-credits/consume`، وكل منها لحساب يطابق الموفّر فقط. ويُرجع أي شيء آخر
  `403` من دون الاتصال بالمنبع. ويتم تجاهل ترويسة `Authorization` الخاصة بالمتصل (بما في ذلك العنصر النائب `$TOKEN$`): إذ تحقن OmniRoute
  رمز وصول الاتصال، وتحدّثه أولًا عندما يقترب من انتهاء صلاحيته، ولا تمرر إلا
  الترويسات المسموح بها (`anthropic-beta`؛ `OpenAI-Beta` و`Originator` و`Chatgpt-Account-Id`؛
  `Accept` و`Content-Type`). ويُستخدَم معرّف مساحة العمل المخزّن افتراضيًا عند غياب `Chatgpt-Account-Id`.
  تنتهي مهلة الطلبات بعد 15 ثانية وتستخدم الوكيل الخاص بالاتصال.
- يترك `reset-quota` الحالات النهائية (banned وexpired وcredits_exhausted) كما هي. ويُرجع
  `404` عند استخدام `auth_index` غير معروف.

**المصادقة:** جلسة لوحة المعلومات أو مفتاح API ذي نطاق `manage`، وهو مطلوب حتى عند تعطيل تسجيل الدخول
(المسارات موجودة في `ALWAYS_PROTECTED_API_PATHS`). تحصل المفاتيح المخصصة للاستدلال فقط على `403`. المصدر:
`src/lib/cliproxyCompat/managementApi.ts`.

بالنسبة لنماذج synced/imported ، يقبل `PUT /api/provider-models` `provider` و `modelId` و `maxOutputTokenOverride`: يقوم العدد الصحيح الموجب بتعيين الحد الأقصى لرمز الإخراج اليدوي، ويقوم `null` بمسحه لاستعادة الإعداد الافتراضي. تقوم `GET /api/provider-models?provider=<provider>` بإرجاع هذه القيم في `modelOutputOverrides`، بما في ذلك النماذج التي لا تحتوي على صف نموذج مخصص. يستخدم التجاوز إمكانية `max_output_tokens` في وقت التشغيل ويستمر في إعادة مزامنة النموذج. توفر صفحة الموفر المتوافقة مع OpenAI نفس عناصر التحكم edit/clear ونماذج العلامات مع دعم واضح للرؤية.

في عقدة موفر متوافقة، تقوم مسارات الكتابة (`POST` و `PUT` و `PATCH` و `DELETE` و `/api/provider-models/validate-and-add`) بتخزين معرف النموذج باعتباره معرف المنبع المجرد: يحتوي المعرف الذي تم لصقه من قائمة سابقة على أي مكدس بادئ من بادئة العقدة الخاصة، وتردد الاستجابات صدى المعرف المخزن. يتم تخزين المعرفات المقطوعة لموفري الخدمة الأساسية (على سبيل المثال `nvidia/nemotron-…`) حرفيًا. `/v1/models` لا يصدر أبدًا معرف `<prefix>/<prefix>/<model>` مكدسًا.

تعمل عقد إكمال الدردشة المخصصة على تكييف عمليات إلغاء الاشتراك المنطقية الصريحة مع الواجهة الخلفية الأولية. يقوم اختبار الاتصال الناجح تلقائيًا بتحديد عناصر تحكم قالب الدردشة لكل نموذج محدد ID الذي يثبت إدخال `/models` قيمة `owned_by` المعترف بها: `vllm` أو `sglang` أو `llamacpp`. قد تحافظ الأغلفة الشفافة المتوافقة مع OpenAI على إدخال النموذج الأصلي داخل كائن `openai` متداخل؛ يتبع الكشف ما يصل إلى ثلاثة من هذه المظاريف. تحافظ النماذج ذات الملكية المفقودة أو غير المعروفة أو المتضاربة على سلوك OpenAI العادي. يعيد الاكتشاف استخدام طلب الكتالوج الموجود، ولا ينشئ أي رموز مميزة للإكمال، ويتم إبطاله عندما تتغير نقطة نهاية الاتصال.

لتثبيت سلوك الواجهة الخلفية التي لا تكشف عن البيانات التعريفية، استخدم تحديث الموفر الجزئي الموجود API:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

أرسل تلك الهيئة مع `PUT /api/providers/<connection-id>`. في هذا الصدد، يتم إرسال جهد التفكير الواضح لـ `none` كـ `chat_template_kwargs.thinking=false` و `chat_template_kwargs.enable_thinking=false`. تظل قيم القالب الأصلية الصريحة موثوقة ما لم تفرض قاعدة الاستدلال من جانب الخادم بذل جهد. ينطبق الإعداد فقط عندما يرسل اتصال مخصص متوافق مع OpenAI نصًا لإتمام الدردشة؛ تحتفظ طلبات الاستجابات ومقدمو الخدمات العاديون بشكل الطلب الأصلي. اضبط `reasoningControl` على `openai` لفرض عبور OpenAI `reasoning_effort` العادي، أو احذف it/set إلى `null` لاستخدام الكشف التلقائي.

يطلب مصنف الوضع التلقائي Claude Code التفكير الأصلي الافتراضي لتعطيله عندما لا يحتوي على ضوابط تفكير صريحة. يستخدم الاكتشاف علامة نظام المصنف في طلبات تنسيق Claude، وليس أسماء النماذج أو حدود الاكتمال. تحافظ عناصر التحكم الصريحة في الجسم ورؤوس effort/thinking المدعومة وقواعد التوجيه وجهود النموذج التي تم حلها على أولويتها الحالية. تحتفظ كلتا مرحلتي المصنف بالمطالبات وحدود الإكمال وتسلسلات التوقف وأحكام الأذونات الأولية الحقيقية؛ لا يزال بإمكان المرحلة الثانية إنتاج المنطق المرئي المطلوب كنص عادي.

#### مصدر الحد النموذجي

`GET /api/models?withLimits=1` (أيضًا `true`; `0`/`false` أو حذفه يبقي الحمولة الافتراضية دون تغيير) يضيف `contextWindow` و `maxInputTokens` و `maxOutputTokens` وكائن `capsSource` إلى كل صف نموذج. يسمي `capsSource` القاعدة التي توفر كل حد، لذلك يمكن تتبع الحد المفاجئ (على سبيل المثال 128k في نموذج 1M) إلى أصله. القيم التي تم حلها هي نفس القيم التي يستخدمها التوجيه؛ تضيف العلامة الحقول فقط ولا تغير القيمة أبدًا. يتم رفض أي قيمة `withLimits` أخرى باستخدام `400`.

| قيمة `capsSource`                            | أصل                                                           |
| -------------------------------------------- | ------------------------------------------------------------- |
| `override:context`                           | تجاوز نافذة السياق المستمر (`model_context_overrides`)        |

### التنقل لأسفل إطار الفيديو

يقرأ `GET /api/v1/video-bridge/drilldown` المقبض غير الشفاف المرتبط بالمستأجر والذي تم إرجاعه في `x-omniroute-video-drilldown` بعد طلب Video Bridge الذي تمت الموافقة عليه بشكل صريح. تتطلب كل من القراءات و `DELETE` دائمًا مفتاح API صالحًا وإذن `modalityBridgeVideoDrilldownRemoteEnabled` المستقل للمشغل. يتطلب الاحتفاظ بالإنتاج بالإضافة إلى ذلك `modalityBridgeVideoDrilldownEnabled` و `drilldown: true` الصارم لكل جزء. إذا كان المفتاح يحتوي على قائمة مسموح بها لنقاط النهاية غير فارغة، فيجب أن تتضمن `video` لكل من GET و DELETE، سواء كان المتصل يستخدم `/v1` أو `/api/v1`.

استعلام GET : مطلوب `handle`؛ اختياري `variant` (`preview` و `standard` و `detail`) و `limit` (1–8؛ يتم قبول `frames` القديمة ولكن لا يمكن دمجها مع `limit`) و `page` ذات الأساس الصفري و `start`/`end` ثانية. عندما يتم توفير حدي التركيز، يجب أن يكون `end` أكبر من `start`. تم رفض مفاتيح الاستعلام Duplicate/unknown. تحتوي الاستجابات الناجحة على `derivation`، `durationSeconds`، `frames`، `hasMore`، `page`، و `variant`، و `focusWindow` الاختياري؛ تم تحديد الحد الأقصى لـ no-store JSON بـ 32 MiB بما في ذلك Base64. يعود الناتج المتضخم 413؛ طلب إطارات أقل.

`DELETE /api/v1/video-bridge/drilldown?handle=...` ترجع `{ "removed": 0|1 }`. لا يمكن تمييز 404 استجابات غير معروفة ومنتهية الصلاحية وعبر المفاتيح GETs ؛ لا يمكن للمفتاح المتقاطع DELETE إزالة إدخال المالك. يؤدي الوصول المعطل إلى إرجاع 403، ومصادقة missing/invalid 401، والاستعلامات غير الصالحة 400، والإلغاء 499، والأخطاء المؤقتة 503. تكون المقابض معالجة محلية، وتنتهي صلاحيتها بعد عشر دقائق، ولا تنجو من إعادة التشغيل. تستخدم المقابض الجديدة `v1.` بالإضافة إلى رمز Base64URL عشوائي بحجم 32 بايت؛ يتم الاحتفاظ بالتجزئات الرمزية فقط. تظل الرموز القديمة ذات 64 سداسيًا قابلة للقراءة من الناحية التركيبية من أجل التوافق. راجع [حواجز حماية Video Bridge](../security/GUARDRAILS.md#video-bridge-videobridgets-videobridgepipelinets) للحصول على الموافقة والحصص وتفاصيل الاشتقاق المتغير.

### الإصدار وقناة الإصدار

```bash
GET /api/system/version
```

مسار إدارة الاسترجاع فقط (مصادقة المسؤول). إرجاع الإصدار قيد التشغيل وأحدث إصدار منشور وحالة التحديث التلقائي. `releaseChannel` و `channels` هما حقلان إضافيان (السكك الحديدية 3.8.54)؛ يحتفظ `channel` بمعناه — وضع النشر الذي يستخدمه مُحدِّث لوحة المعلومات (`npm` أو `source` أو `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- قناة `releaseChannel` — npm للإصدار قيد التشغيل: `nightly` لإصدارات `-nightly.*` ، `next` للإصدارات المسبقة الأخرى (`-rc.*`، `-beta.*`، `-alpha.*`)، `lts` لإصدار مستقر من تخصص أقدم من `channels.latest`، وإلا `latest`. نفس قواعد `scripts/release/dist-tag.mjs`، التي تختار علامة التوزيع npm في وقت النشر.
- `channels` — رأس منشور لكل علامة dist، من `npm view omniroute dist-tags` (التسجيل HTTP الاحتياطي)، تم تخزينه مؤقتًا باستخدام نفس TTL 10 دقائق مثل `latest`. `latest` موجود دائمًا (يعود إلى الحقل `latest` ، ثم `"unavailable"`)؛ تظهر `next` و `nightly` و `lts` فقط عند وجود علامة التوزيع هذه. يقوم طلب `Cache-Control: no-cache` بتحديث كلا عمليتي البحث.

نموذج القناة (`latest` = v3 حتى 4.0 GA، `next` = rc، `nightly` = `develop` builds، `lts` = v3 patch بعد 4.0 GA) موصوف في `docs/ops/RELEASE_STRATEGY.md`.

## نسخ الصوت

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data
```

يمكنك نسخ الملفات الصوتية باستخدام أي موفّر STT مُكوَّن. يحدد مقطع المسار
الأول الموفّر الأصلي (`openai/…`، `deepgram/…`). أما البوابات التي تعيد
تصدير نموذج موفّر آخر، فتستخدم معرّفًا مؤهلًا
(`openrouter/deepgram/nova-3`).

**الطلب:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**الاستجابة:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**أمثلة على معرّفات النماذج:** `openai/whisper-1` (يتطلب مفتاح OpenAI)،
`openrouter/deepgram/nova-3` (يتطلب مفتاح OpenRouter)،
`deepgram/nova-3` (يتطلب مفتاح Deepgram الأصلي). لا يستخدم طلب
`deepgram/nova-3` العاري OpenRouter.

**التنسيقات المدعومة:** `mp3`، `wav`، `m4a`، `flac`، `ogg`، `webm`.

**Gemini Live (`gemini/gemini-3.5-transcribe-live`):** نسخ الملفات في وضع الملف
عبر WebSocket الخاص بـ Gemini Live (يتطلب مفتاح Gemini API). يُحوَّل الملف المرفوع إلى PCM أحادي
القناة بتردد 16 kHz باستخدام `ffmpeg`
(يجب أن يكون موجودًا في `PATH`، ما لم يكن الملف بالفعل WAV بتنسيق PCM أحادي القناة بتردد 16 kHz)،
ثم يُبث إلى الجلسة ويُعاد النص النهائي بالشكل `{ "text": "..." }`. يتم تمرير حقلي النموذج
`language` و`prompt` الاختياريين إلى الجهة الأخرى. الحدود: تؤدي التحميلات التي تتجاوز 25 MiB أو
الصوت المُفكَّك الذي تزيد مدته عن 10 دقائق إلى استجابة
`413`؛ وإذا استغرقت عملية التحويل أكثر من 60 ثانية، فسيتم إنهاؤها وتُعاد الاستجابة
`504`. يُرسل مفتاح API في ترويسة `x-goog-api-key` فقط، وليس مطلقًا في عنوان URL الخاص بـ WebSocket.

`Authorization` ويحتاج إلى تضمين مفتاح API في عنوان URL الأساسي.

```bash
# اسم مستعار للفهرس بنمط OpenAI
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# أسماء مستعارة للدردشة بنمط OpenAI
POST /api/v1/vscode/{token}/chat/completions
POST /api/v1/vscode/{token}/responses

# أسماء مستعارة بنمط Ollama
POST /api/v1/vscode/{token}/api/chat
GET /api/v1/vscode/{token}/api/tags
```

مثال:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'
```

ملاحظات:

- تعيد الأسماء المستعارة المستعينة بالرموز استخدام المعالجات نفسها الخاصة بـ `/v1/*` و`/api/tags`؛ وتظل أشكال الاستجابات متطابقة.
- يُفضّل استخدام `Authorization: Bearer ...` كلما كان العميل يدعم الترويسات المخصّصة.
- قد تظهر الرموز المستندة إلى عناوين URL في سجلات الوكيل العكسي وسجل المتصفح وبيانات القياس عن بُعد خارج OmniRoute. تعامل معها كخيار للتوافق، وليس كنمط المصادقة الافتراضي.

## الميزانية

```bash
# الحصول على حالة الميزانية لجميع مفاتيح API
GET /api/usage/budget

# تعيين ميزانية أو تحديثها
POST /api/usage/budget
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "dailyLimitUsd": 5.00,
  "weeklyLimitUsd": 30.00,
  "monthlyLimitUsd": 100.00,
  "warningThreshold": 0.8,
  "resetInterval": "monthly"
}
```

> **ملاحظات المخطط** (`setBudgetSchema`): الحقل `apiKeyId` مطلوب؛ ويجب أن تكون قيمة واحدة على الأقل من `dailyLimitUsd` أو `weeklyLimitUsd` أو `monthlyLimitUsd` أكبر من الصفر. الحقول الاختيارية: `warningThreshold` (من 0 إلى 1)، و`resetInterval` (`daily` | `weekly` | `monthly`)، و`resetTime` (`HH:MM`). يُرجع التنسيق القديم `{keyId, limit, period}` الاستجابة `400 Bad Request`.

## حدود الرموز

ميزانيات **الرموز** لكل مفتاح API (متميزة عن الميزانية المستندة إلى USD أعلاه). تُفرض مباشرةً ضمن مسار الطلب: عندما يصل استخدام النافذة الحالية للمفتاح إلى الحد الخاص به، تُرفض الطلبات مع `429 Too Many Requests`. يمكن تحديد نطاق الحدود لنموذج `model` محدد، أو موفّر `provider`، أو تطبيقها `global` على المفتاح بأكمله؛ وعند تطابق عدة حدود مع طلب ما، يسري الحد الأكثر تقييدًا.

```bash
# سرد حدود الرموز الخاصة بمفتاح (يتضمن استخدام النافذة المباشر)
GET /api/usage/token-limits?apiKeyId=key-123

# إنشاء حد للرموز أو تحديثه
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# حذف حد للرموز حسب المعرّف
DELETE /api/usage/token-limits?id=tl-abc
```

> **ملاحظات المخطط** (`setTokenLimitSchema`): الحقلان `apiKeyId` و`scopeType` (`model` | `provider` | `global`) مطلوبان. يكون `scopeValue` مطلوبًا ما لم يكن `scopeType` هو `global` (مثلًا: معرّف نموذج لنطاق `model` أو معرّف موفّر لنطاق `provider`). يجب أن يكون `tokenLimit` عددًا صحيحًا موجبًا (يُحوَّل من سلسلة نصية). اختياري: `id` (يُحذف عند الإنشاء ويُحدَّد عند التحديث)، و`resetInterval` (`daily` | `weekly` | `monthly`، والقيمة الافتراضية `monthly`)، و`resetTime` (`HH:MM`)، و`enabled` (القيمة الافتراضية `true`). تُثري استجابات `GET` كل حد بالحقول `tokensUsed` و`remaining` و`windowStart` و`periodStartAt` و`nextResetAt`. هذه نقطة نهاية من فئة الإدارة (تُفرض المصادقة مركزيًا عبر مسار تفويض الوصول).

## معالجة الطلبات

1. يرسل العميل الطلب إلى `/v1/*`
2. يستدعي معالج المسار `handleChat` أو `handleEmbedding` أو `handleAudioTranscription` أو `handleImageGeneration`
3. تتم تسوية النموذج (موفّر/نموذج مباشر أو اسم مستعار/تركيبة)
4. تُحدَّد بيانات الاعتماد من قاعدة البيانات المحلية مع تصفية الحسابات المتاحة
5. بالنسبة إلى الدردشة: يتحقق `handleChatCore` من ذاكرة التخزين المؤقت الدلالية/القائمة على التوقيع، ويحل إعدادات ضغط التركيبات
6. يُنفَّذ الضغط الاستباقي قبل ترجمة الموفّر عند تفعيله (`lite` أو Caveman أو RTK أو بشكل متسلسل)
7. يرسل منفّذ الموفّر الطلب إلى الخدمة الأصلية
8. تُترجم الاستجابة مجددًا إلى تنسيق العميل (الدردشة)، أو تُعاد كما هي (التضمينات/الصور/الصوت)
9. يُسجَّل الاستخدام وتحليلات الضغط وسجلات الطلبات
10. يُطبَّق الإجراء الاحتياطي عند حدوث أخطاء وفقًا لقواعد التركيبة

المرجع الكامل للبنية: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## المرونة (موسّعة)

يعرِض OmniRoute ثلاث آليات مستقلة للإخفاقات المؤقتة؛ وتتيح نقاط الإدارة أدناه للمشغّلين قراءتها وتجاوزها:

| النطاق             | تخزين الحالة                             | القراءة                                   | إعادة الضبط / المسح                           |
| ------------------ | ---------------------------------------- | ----------------------------------------- | --------------------------------------------- |
| قاطع مزوّد الخدمة  | `domain_circuit_breakers` + الذاكرة      | `/api/monitoring/health`                  | `POST /api/resilience/reset`                  |
| فترة تهدئة الاتصال | `rateLimitedUntil` على اتصالات المزوّدين | `/api/rate-limits`, `/api/providers/[id]` | (يُعاد التمكين بتكاسل؛ يُمسح عبر PUT للمزوّد) |
| قفل النموذج        | سجل توفّر النماذج في الذاكرة             | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`      |

يقبل `PATCH /api/resilience` تجاوزات قاطع المزوّد ضمن `providerBreaker.oauth` و`providerBreaker.apikey`. يدعم كل ملف `degradationThreshold` و`failureThreshold` و`resetTimeoutMs`؛ وتُعرَض الحقول نفسها في لوحة المعلومات ← الإعدادات ← المرونة.

```bash
# مسح قفل نموذج واحد
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# مسح جميع الأقفال
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

للاطّلاع على المرجع المفاهيمي الكامل والإعدادات الافتراضية للقاطع: راجع [`CLAUDE.md`](../../CLAUDE.md) ← "حالة تشغيل المرونة" و[`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### قائمة انتظار تحديد المعدل وشبكة الأمان للتمكين التلقائي

- **مسار الكتابة المدعوم**: يُعد `POST /api/rate-limits` مع النص `{"connectionId": "<id>", "enabled": true|false}` نقطة الإدارة المدعومة لتبديل حماية تحديد المعدل لاتصال ما. لا يقوم `PUT /api/providers/[id]` عمدًا بتعديل `rateLimitProtection` أو تبديله (#11278).
- **دلالات `enabled: false`**: يؤدي تعيين `enabled: false` إلى إزالة الحماية الصريحة للاتصال، لكنه **لا** يخرج اتصال مفتاح API النشط من شبكة الأمان العالمية للتمكين التلقائي (`autoEnableApiKeyProviders = true`). في `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`)، تكون `false` و`undefined` متكافئتين؛ وتظل اتصالات مفاتيح API النشطة التي لا تتضمن حماية صريحة محمية ضمن شبكة الأمان للتمكين التلقائي.
- **التعطيل العام**: لتشغيل اتصالات مفاتيح API من دون قوائم انتظار لتحديد المعدل، عطّل شبكة الأمان عالميًا عبر `RATE_LIMIT_AUTO_ENABLE=false` (متغير البيئة) أو `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (الإعدادات ← المرونة / `PATCH /api/resilience`).

## خادم MCP

يقوم OmniRoute بشحن خادم Model context Protocol مضمن مع 3 وسائل نقل (stdio و SSE وstreamable-http) وأدوات محددة النطاق. تقرأ نقاط نهاية لوحة المعلومات أدناه بيانات status/audit والوكيل الذي ينقله HTTP.

| طريقة | طريق | وصف |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | نبض القلب، النقل، حالة الاتصال بالإنترنت، المكالمة الأخيرة، أفضل الأدوات، معدل النجاح على مدار 24 ساعة |
| GET | `/api/mcp/tools` | قائمة أدوات MCP مع `name`، `description`، `scopes`، `phase`، `auditLevel`، `sourceEndpoints` |
| GET | `/api/mcp/sse` | فتح دفق SSE لنقل SSE (إرجاع `503` في حالة تعطيل MCP أو عدم تطابق النقل) |
| POST | `/api/mcp/sse` | أرسل إطار JSON-RPC على وسيلة النقل SSE |
| GET | `/api/mcp/stream` | افتح جانب SSE من نقل HTTP القابل للتدفق (الرسائل التي يبدأها الخادم) |
| POST | `/api/mcp/stream` | أرسل إطار JSON-RPC على وسيلة النقل HTTP القابلة للتدفق |
| DELETE | `/api/mcp/stream` | قم بإنهاء جلسة HTTP القابلة للبث |
| GET | `/api/mcp/audit` | سجل تدقيق الاستعلام — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | إحصائيات التدقيق الإجمالية (الإجمالي، معدل النجاح، متوسط المدة، أهم الأدوات) |

**المصادقة:** تحترم عمليات النقل `sse`/`stream` سطح المصادقة الخاص بـ MCP (مفتاح Bearer API مع نطاق `mcp` )؛ يمكن قراءة مسارات `status`/`tools`/`audit*` من لوحة المعلومات (لا يلزم الحصول على مصادقة إضافية بعد الوصول إلى مضيف لوحة المعلومات).

> كل من وسائل النقل HTTP مسورة بواسطة `settings.mcpEnabled` و `settings.mcpTransport` — حيث يؤدي عدم تطابق النقل إلى إرجاع `400`، بينما تقوم حالة تعطيل MCP بإرجاع `503`.

## خادم A2A

يتيح OmniRoute نقطة نهاية JSON-RPC 2.0 لـ A2A (من وكيل إلى وكيل)، بالإضافة إلى غلاف REST لأغراض الفحص ولوحة المعلومات.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # اختياري ما لم يتم تعيين OMNIROUTE_API_KEY
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

الأساليب المدعومة (تخضع جميعها لـ `settings.a2aEnabled`):

| Method           | الوصف                                                    |
| ---------------- | -------------------------------------------------------- |
| `message/send`   | تنفيذ متزامن للمهارة؛ يعيد `{task, artifacts, metadata}` |
| `message/stream` | تنفيذ متدفق عبر SSE لمجموعة المهارات نفسها               |
| `tasks/get`      | جلب مهمة باستخدام `taskId`                               |
| `tasks/cancel`   | إلغاء مهمة باستخدام `taskId`                             |

المهارات المضمنة: `smart-routing` و`quota-management` و`provider-discovery` و`cost-analysis` و`health-report`.

### بطاقة الوكيل

```bash
GET /.well-known/agent.json
```

يعيد بطاقة وكيل A2A العامة (الاسم والوصف والإمكانات وكتالوج المهارات ومخطط المصادقة)، ويتم تخزينها مؤقتًا بشكل عام لمدة ساعة واحدة. لا تتطلب مصادقة.

### أدوات REST المساعدة

| Method | Path                         | الوصف                                                                                                           |
| ------ | ---------------------------- | --------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | حالة تفعيل A2A + إحصاءات المهام + ملخص بطاقة الوكيل المخزنة مؤقتًا                                              |
| GET    | `/api/a2a/tasks`             | سرد المهام — `?state=submitted\|working\|completed\|failed\|cancelled` و`?skill=` و`?limit=` (≤200) و`?offset=` |
| POST   | `/api/a2a/tasks`             | (غير منفّذ كأداة REST مساعدة — أنشئ المهمة عبر JSON-RPC باستخدام `message/send`)                                |
| GET    | `/api/a2a/tasks/[id]`        | استرداد مهمة واحدة                                                                                              |
| POST   | `/api/a2a/tasks/[id]/cancel` | إلغاء مهمة                                                                                                      |

**المصادقة:** تعمل أدوات REST المساعدة من دون مصادقة الإدارة (ويمكن للوحة المعلومات قراءتها)؛ ويستخدم مسار JSON-RPC `/a2a` الرمز Bearer `OMNIROUTE_API_KEY` إذا تم تكوينه.

نقاط نهاية للتحليلات في الوقت الفعلي لمراقبة التوجيه والضغط وتنوع موفري الخدمة. تشغّل هذه النقاط صفحات `/dashboard/analytics/*`.

### تحليلات التوجيه التلقائي

| الطريقة | المسار                               | الوصف                                                                                                             |
| ------- | ------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| GET     | `/api/analytics/auto-routing`        | إحصاءات التوجيه التلقائي المجمّعة: إجمالي الاستدعاءات، وتوزيع الاستراتيجيات، وتوزيع المستويات، وأبرز موفري الخدمة |
| GET     | `/api/analytics/auto-routing?days=7` | إحصاءات ضمن إطار زمني (الافتراضي 24 ساعة)                                                                         |

**مثال على الاستجابة**:

```json
{
  "window": "24h",
  "totalCalls": 1234,
  "strategyBreakdown": {
    "rules": 800,
    "cost": 200,
    "latency": 150,
    "sla-aware": 50,
    "lkgp": 34
  },
  "tierBreakdown": {
    "ultra": 100,
    "pro": 500,
    "standard": 400,
    "free": 234
  },
  "topProviders": [
    { "provider": "openai", "calls": 500, "avgLatencyMs": 850 },
    { "provider": "anthropic", "calls": 300, "avgLatencyMs": 1200 }
  ]
}
```

### تحليلات الضغط

| الطريقة | المسار                       | الوصف                                                                                             |
| ------- | ---------------------------- | ------------------------------------------------------------------------------------------------- |
| GET     | `/api/analytics/compression` | إحصاءات الضغط المجمّعة: الرموز المميزة المحفوظة، ونسبة التوفير، وتوزيع الأوضاع، واستخدام المحركات |

## المصادقة

راجع [مصادقة الإدارة](../guides/MANAGEMENT-AUTH.md) للاطّلاع على عائلات بيانات الاعتماد
الأربع (جلسة لوحة التحكم، ورمز CLI محلي، و`oma_live_…` لرمز الوصول، ومفتاح API
المحدّد بنطاق الإدارة) وكيف تختلف عن مفاتيح الاستدلال.

- تستخدم مسارات لوحة التحكم (`/dashboard/*`) ملف تعريف الارتباط `auth_token`
- يستخدم تسجيل الدخول تجزئة كلمة المرور المحفوظة؛ مع الرجوع إلى `INITIAL_PASSWORD`
- يمكن تبديل `requireLogin` عبر `/api/settings/require-login`
- تتطلب مسارات `/v1/*` اختياريًا مفتاح API لحامل الطلب عندما تكون قيمة `REQUIRE_API_KEY=true`
- تعني عبارة "رمز الإدارة" / "مفتاح API المحدّد بنطاق الإدارة" في هذا المرجع إحدى العائلات الواردة في ذلك الدليل — وليست نوعًا إضافيًا غير معرّف من الأسرار

> **تغيير جذري (v3.8.0)** — تتطلب الآن `/api/v1/agents/tasks/*` ونقاط نهاية إدارة فترة التهدئة **مصادقة الإدارة** (ملف تعريف ارتباط لوحة التحكم `auth_token` أو مفتاح API محدّد بنطاق الإدارة). سيتلقى العملاء الذين كانوا يستدعون هذه المسارات سابقًا دون مصادقة الاستجابة `401 Unauthorized`. راجع الالتزام `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
