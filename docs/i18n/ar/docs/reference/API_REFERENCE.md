## إكمالات المحادثة

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### الترويسات المخصّصة

| الترويسة                 | الاتجاه   | الوصف                                                                                                                                                                   |
| ------------------------ | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | الطلب     | اضبطها على `true` لتجاوز ذاكرة التخزين المؤقت                                                                                                                           |
| `x-omniroute-no-memory`  | الطلب     | اضبطها على `true` لتخطّي إدراج الذاكرة والمهارات لهذا الطلب (يماثل عدم استخدام ذاكرة التخزين المؤقت؛ ويتجنب العبء الإضافي للرموز المميزة/التكلفة لكل استدعاء)           |
| `X-OmniRoute-Progress`   | الطلب     | اضبطها على `true` لتلقّي أحداث التقدم                                                                                                                                   |
| `X-Session-Id`           | الطلب     | مفتاح جلسة ثابت لترابط الجلسات الخارجية                                                                                                                                 |
| `x_session_id`           | الطلب     | صيغة الشرطة السفلية مقبولة أيضًا (عبر HTTP المباشر)                                                                                                                     |
| `X-OmniRoute-Session-Id` | الطلب     | وسم جلسة/محادثة يقدّمه المستدعي (ويغذّي الذاكرة أيضًا). عند وجوده، يُحفظ حرفيًا في `call_logs.session_tag` لإسناد التكلفة لكل جلسة (#8249) — ولا يُنشأ مطلقًا عند غيابه |
| `Idempotency-Key`        | الطلب     | مفتاح إزالة التكرار (نافذة مدتها 5 ثوانٍ)                                                                                                                               |
| `X-Request-Id`           | الطلب     | مفتاح بديل لإزالة التكرار                                                                                                                                               |
| `x-omniroute-connection` | الطلب     | ثبّت طلب نموذج واحد على اتصال مزوّد واحد (حساب) باستخدام معرّفه — راجع [تثبيت الحساب لكل طلب](#account-pinning-per-request)                                             |
| `X-OmniRoute-Cache`      | الاستجابة | `HIT` أو `MISS` (من دون بث)                                                                                                                                             |
| `X-OmniRoute-Idempotent` | الاستجابة | `true` إذا أُزيل التكرار                                                                                                                                                |
| `X-OmniRoute-Progress`   | الاستجابة | `enabled` إذا كان تتبّع التقدم مفعّلًا                                                                                                                                  |
| `X-OmniRoute-Session-Id` | الاستجابة | معرّف الجلسة الفعلي الذي تستخدمه OmniRoute                                                                                                                              |
| `X-OmniRoute-Request-Id` | الاستجابة | معرّف ربط الطلب (عندما يكون معروفًا)                                                                                                                                    |
| `X-OmniRoute-Version`    | الاستجابة | إصدار بناء OmniRoute (موجود دائمًا)                                                                                                                                     |
| `X-OmniRoute-Cost-Saved` | الاستجابة | المبلغ بالدولار الأمريكي الذي وفّرته ذاكرة التخزين المؤقت عند `HIT` (إصابات ذاكرة التخزين المؤقت فقط)                                                                   |
| `X-OmniRoute-Decision`   | الاستجابة | تتبّع التوجيه: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` هي استراتيجية التركيب، أو `single` لطلب غير مركّب) — موجود دائمًا في استجابات الاكتمال     |

> ملاحظة حول Nginx: إذا كنت تعتمد على ترويسات تحتوي على شرطات سفلية (مثل `x_session_id`)، ففعّل `underscores_in_headers on;`.

#### تثبيت الحساب لكل طلب

عندما يكون لدى موفّر عدة اتصالات (حسابات أو مفاتيح)، يختار OmniRoute عادةً أحدها
عبر استراتيجية اختيار الحساب. ويمكن للطلب بدلًا من ذلك تثبيت اتصال محدد
باستخدام الترويسة `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **مكان العثور على المعرّف.** افتح صفحة الموفّر في لوحة المعلومات
  (**لوحة المعلومات → الموفّرون → <provider>**) وانقر على شريحة المعرّف `xxxxxxxx…` في صف اتصال
  — سيؤدي ذلك إلى نسخ معرّف الاتصال كاملًا.
- **الطلبات التي تحترمه.** طلبات النموذج الواحد (`provider/model`) على
  `/v1/chat/completions` و`/v1/messages` و`/v1/responses`. تتجاهل التركيبات هذه الترويسة: ثبّت
  حسابًا لكل خطوة في التركيبة عبر الاتصال الخاص بالخطوة بدلًا من ذلك.
- **التثبيت صارم وليس تفضيلًا.** يُستخدم الاتصال المثبّت حصريًا. ويؤدي
  أي فشل داخل الطلب إلى تسجيل فترة التهدئة للحساب، لكنه **لا** ينتقل إلى
  حساب شقيق لدى الموفّر نفسه.
- **فترة التهدئة والحصة تحرران التثبيت.** عندما يكون الاتصال المثبّت في فترة تهدئة،
  أو تكون حصته مستنفدة، أو يكون محظورًا بموجب سياسة حصة، تعود الطلبات اللاحقة إلى اتصالات
  الموفّر الأخرى، تمامًا مثل حركة البيانات غير المثبّتة.
- **تفشل المعرّفات غير المعروفة أو المعطّلة.** إذا لم يكن المعرّف ضمن مجموعة الموفّر النشطة (بسبب حذفه
  أو إلغاء تنشيطه أو انتمائه إلى موفّر آخر)، فلن يتبقى أي حساب مؤهل، وبالتالي يفشل الطلب
  بدلًا من توجيهه بصمت إلى مكان آخر.

يرسل Claude Code الترويسات المخصصة عبر `ANTHROPIC_CUSTOM_HEADERS`. ضعه في كتلة `env`
داخل `~/.claude/settings.json`، أو في `.claude/settings.json` على مستوى المشروع لتثبيت حساب
مختلف لكل مشروع:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

المصدر: `src/sse/handlers/chat.ts` (قراءة الترويسة)، و`src/sse/services/auth.ts` و
`src/sse/services/sessionAffinityPin.ts` (تحرير التثبيت والتحقق من عدم الوجود في المجموعة).

> **ترويسات قياس التكلفة:** تحمل استجابات النجاح غير المتدفقة أيضًا مجموعة قياس التكلفة `X-OmniRoute-*` — وهي `X-OmniRoute-Response-Cost` (بالدولار الأمريكي، بدقة ثابتة من 10 منازل عشرية؛ `0.0000000000` للخدمات المجانية أو غير المسعّرة)، و`X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`، و`X-OmniRoute-Model`، و`X-OmniRoute-Provider`، و`X-OmniRoute-Latency-Ms`، و`X-OmniRoute-Cache-Hit`، و`X-OmniRoute-Fallback-Attempts` (فقط عندما تكون > 0)، بالإضافة إلى `X-OmniRoute-Request-Id` و`X-OmniRoute-Version`. تصدر هذه الترويسات عن إكمالات المحادثة، و`/v1/responses`، و`/v1/messages`، **وكذلك نقاط نهاية الوسائط** — `/v1/embeddings`، و`/v1/images/generations`، و`/v1/audio/speech`، و`/v1/audio/transcriptions`، و`/v1/rerank`، و`/v1/videos/generations`، و`/v1/music/generations`، و`/v1/moderations` (بتكلفة `0` دائمًا). تُحسب تكلفة الوسائط وفقًا لكل نمط (لكل صورة، أو ثانية، أو محرف، أو وحدة بحث) عندما يكون التسعير متاحًا، وإلا فتكون `0` (السماح بالمتابعة عند الفشل).

> **دلالات تكلفة إصابة ذاكرة التخزين المؤقت:** عند حدوث إصابة في ذاكرة التخزين المؤقت الدلالية (`X-OmniRoute-Cache-Hit: true`)، لا يُجرى أي استدعاء لخدمة المنبع، ولذلك تكون قيمة `X-OmniRoute-Response-Cost` هي `0.0000000000` (التكلفة **الإضافية** لخدمة الإصابة). ويُبلّغ عن التكلفة الأصلية/التي كانت ستُستحق بشكل منفصل في `X-OmniRoute-Cost-Saved`. ينبغي لمستهلكي بيانات الفوترة جمع قيم `X-OmniRoute-Response-Cost` (فالإصابات بلا تكلفة)؛ ويمكن لتحليلات ذاكرة التخزين المؤقت تجميع قيم `X-OmniRoute-Cost-Saved`.

## عقود إيجار الجلسات المُدارة الحصرية

يُعد تأجير الجلسات المُدارة الحصرية عقد توجيه اختياريًا ومحايدًا تجاه العملاء: يحتفظ مالك نشط واحد
باتصال OmniRoute واحد مؤهل. ولا يؤجر نموذجًا، ولا يتطلب OAuth، ولا يحدد
عميلاً بعينه، ولا يتطلب موفرًا بعينه.

يجب أن يمتلك مفتاح API المستخدم للمصادقة النطاق `lease:exclusive` وقائمة صريحة غير فارغة
من `allowedConnections`. يفرض حدّ التعديل في قاعدة البيانات وجود كلا الحقلين معًا عند إنشاء المفتاح
وعند إجراء التحديثات الجزئية.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

تعرض استجابات الاستحواذ والتجديد والتحرير الناجحة الطوابع الزمنية و`state` والقيمة الموجبة الدقيقة
لـ`generation`، لكنها لا تعرض مطلقًا الاتصال المحدد أو بيانات الاعتماد. يمرر التجديد والتحرير
قيمة التوليد في متن JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

يمكن لمالك عقد إيجار نشط أن يطلب صراحةً بيانات وصفية للعرض تراعي الخصوصية لارتباطه الحالي:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

يُحاط إجراء الحالة الاختياري هذا بسياج يعتمد على المالك المعتم، ومفتاح API المُدار والمصادَق عليه، وقيمة
التوليد النشطة الدقيقة ضمن معاملة واحدة في قاعدة البيانات. لا تمثل `displayName` سوى اسم الاتصال المضبوط
بعد إزالة المسافات الزائدة؛ وتكون `null` عند عدم وجود اسم مضبوط وآمن. لا يستبدل OmniRoute بها مطلقًا
عنوان بريد إلكتروني أو هوية حساب مُنشأة. تمثل قيمة الموفر تسمية عرض غير حساسة، وليست مطلقًا
معرّفًا مُنشأً لموفر متوافق. وتُستبعد بيانات الاعتماد، والرموز المميزة، وملفات تعريف الارتباط، ومعرّفات الاتصال أو مفاتيح
API الخام، وتجزيئات المالك، وأسرار السياج، وبيانات التوجيه الداخلية.

تُرجع عمليات البحث التي تتضمن مفتاحًا خاطئًا، أو مالكًا خاطئًا، أو توليدًا قديمًا، أو عقدًا مفقودًا، أو منتهي الصلاحية، أو محررًا، أو مُبطلاً
الخطأ نفسه `409 LEASE_FENCE_STALE` من دون بيانات وصفية للاتصال. لا يمتلك العميل الذي تلقى استجابة انتظار السعة ارتباطًا نشطًا لفحصه. عندما ينقل التوجيه عقد إيجار نشطًا،
تظل قيمة التوليد نفسها صالحة وتُرجع الحالة الارتباط الجديد ذريًا، وليس القديم مطلقًا.
وتبقى البرامج العميلة الحالية دون تغيير لأن استجابات الاستحواذ والتجديد والتحرير والانتظار تحتفظ
ببنياتها السابقة.

لا يغير عقد الخادم هذا `/status` القياسي الخاص بـOpenAI Codex. يُبلغ Codex القياسي حاليًا عن
موفر نموذجه وحالة المصادقة/الحساب المضمنة، لكنه لا يعرض بيانات وصفية عشوائية لحساب
موفر مخصص؛ ويجب على تكامل عميل لاحق استدعاء هذا الإجراء وتحديد كيفية
عرض `connection.displayName`.

بعد ذلك، يمرر كل طلب استدلال مُدار ترويستي التحكم كلتيهما:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

يُفرض السياج على المالك الدقيق، وقيمة التوليد، والاتصال النشط، ومفتاح API المصادَق عليه مباشرةً
قبل كل محاولة مدعومة مع موفر علوي. تفشل إعادة استخدام المالك وقيمة التوليد مع مفتاح آخر حتى
عندما يسمح ذلك المفتاح بالاتصال نفسه. لا تُخزَّن قيم المالك الخام، ولا تُسجَّل، ولا يُحتفظ بها في
لقطة الطلب، ولا تُمرَّر إلى الموفر العلوي.

يُرجع التنافس المؤقت HTTP `429` مع `Retry-After` وما يلي:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

تعني هذه الاستجابة فقط أن المجموعة العادية المؤهلة لم تكن فارغة وأن كل مرشح متاح
كان مشغولاً بعقد إيجار نشط لمالك آخر. تحتفظ النماذج/الموفرون غير المدعومين، وعدم تطابق السياسة، وفترة التهدئة، والحصة،
والحالة الصحية، وغيرها من حالات فشل الأهلية العادية باستجابات OmniRoute الحالية الخاصة بها.

### `x-omniroute-compression`

تجاوز خطة الضغط لكل طلب. له الأولوية القصوى — إذ يتفوق على تجاوز مجموعة التوجيه،
والملف الشخصي النشط، والتشغيل التلقائي، والقيمة الافتراضية للوحة. القيم:

| القيمة        | التأثير                                                                                            |
| ------------- | -------------------------------------------------------------------------------------------------- |
| `off`         | لا يوجد ضغط لهذا الطلب.                                                                            |
| `default`     | الملف الشخصي الافتراضي المستمد من اللوحة (يتجاهل الملف الشخصي النشط). تبقى المحركات الفاقدة معطلة. |
| `safe`        | إزالة التكرار وطي المسافات البيضاء فقط.                                                            |
| `allow-lossy` | الاحتفاظ بخطة المشغّل لهذا الطلب، بما في ذلك الملخصات وإعادات كتابة الأسلوب.                       |
| `engine:<id>` | محرك واحد عند تمكينه، مثل `engine:rtk`. اشتراك اختياري لكل طلب في ذلك المحرك.                      |
| `<combo>`     | مجموعة مسماة، تُطابق أولاً حسب الاسم (من دون حساسية لحالة الأحرف)، ثم حسب المعرّف.                 |

ملاحظات:

- تُتجاهل القيم غير المعروفة (ولا يُرفض الطلب مطلقًا)؛ ويتابع الحل وفق ترتيب أولوية المشغّل المعتاد.
- إذا اشتركت عدة مجموعات في الاسم نفسه، فمرر **id** الخاص بالمجموعة للحصول على تطابق حتمي.
- لا يمكن تحديد مجموعة اسمها `off` أو `default` بالاسم (إذ تُفسر هاتان الكلمتان المفتاحيتان أولاً)؛ أشر إلى مثل هذه المجموعة باستخدام معرّفها.
- مفتاح الضغط الرئيسي بوابة صارمة: عندما يكون الضغط معطلاً عموميًا، لا يمكن لهذه الترويسة تمكينه.

تُعاد الخطة المطبقة في ترويسة الاستجابة:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

حيث تكون `<source>` واحدة من `request-header` أو `routing-override` أو `active-profile` أو `auto-trigger` أو `default` أو `off`.

## التضمينات

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

المزوّدون المتاحون: Nebius، OpenAI، Mistral، Together AI، Fireworks، NVIDIA، **OpenRouter**، Jina AI.

معرّفات الكتالوج بالصيغة `provider/model` (مثال: `jina-ai/jina-embeddings-v5-omni-small`). كما يمكن التعرّف على معرّفات نماذج Jina المجرّدة التي تظهر في السجل (على سبيل المثال `jina-embeddings-v5-text-small` و`jina-reranker-v3.5`). تستخدم عمليات التضمين وإعادة الترتيب والتصنيف والتقسيم في Jina بيانات اعتماد لوحة التحكم `jina-ai` أولًا؛ ولا يُستخدم `JINA_AI_API_KEY` إلا كخيار احتياطي عند عدم وجود مفتاح في لوحة التحكم. بطاقة `jina-reader` مخصصة فقط لـ Reader / `r.jina.ai` ‏(`POST /v1/web/fetch`) ولا توفر مطلقًا التضمينات أو إعادة الترتيب.

تقبل نماذج السجل التي تعلن عن دعم متعدد الوسائط أيضًا ما يصل إلى 32 عنصرًا منظمًا
ومحايدًا تجاه المزوّد. أنواع عناصر الوسائط هي `text` و`image` و`audio` و`video` و`document`. ويكون `source`
الخاص بالوسائط إما `{"type":"url","url":"https://..."}` أو
`{"type":"base64","data":"...","media_type":"..."}`.

يقبل Jina v5 Omni ‏(`jina-ai/jina-embeddings-v5-omni-small` و`jina-ai/jina-embeddings-v5-omni-nano`
والاسم المستعار للعائلة `jina-ai/jina-embeddings-v5-omni` → omni-small) أيضًا مستندات EmbeddingsV5Request الأصلية الخاصة بـ Jina
ويقوم **بتمريرها كما هي** إلى `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

قد تكون قيم `{ image | audio | video | pdf }` الأصلية عنوان URL عامًا عبر HTTPS، أو معرّف URI من نوع `data:`، أو بيانات
base64 أولية. لا يحوّل OmniRoute تلك الكائنات إلى سلاسل نصية ولا يجلب عناوين URL الأصلية للصور — إذ تسترجع Jina
الوسائط العامة بنفسها. تُمرَّر حقول Jina الإضافية (`task` و`normalized` و`truncate` و`embedding_type`).
ولا تزال وحدات SKU النصية فقط من Jina ترفض المستندات غير النصية.

حدود الأمان والنقل:

- يجب أن تكون عناوين URL للوسائط البعيدة عامة وتستخدم HTTPS. تُجلب عناصر `{type,source:url}` القياسية
  من جانب الخادم (مع إعادة التحقق من عمليات إعادة التوجيه، والمهلة الزمنية، وحدود الحجم، وDNS العام، وتثبيت الاتصال)، ثم
  تُضمَّن قبل استدعاء المزوّد. أما عناصر Jina الأصلية من نوع `{image:"https://..."}` فتُمرَّر كما هي
  بعد إجراء التحقق نفسه من كونها عامة وتستخدم HTTPS؛ وتتولى Jina جلب عنوان URL.
- يقتصر حجم وسائط base64 المضمّنة على 8 MiB بعد فك الترميز لكل عنصر، وعلى 16 MiB بعد فك الترميز عبر الطلب بأكمله.

الترجمة الخاصة بالمزوّد (لا تُمرَّر العناصر القياسية دون تغيير مطلقًا):

- نماذج Jina متعددة الوسائط: يتحول كل عنصر من المستوى الأعلى إلى كائن واحد ذي مفتاح خاص بالوسيلة
  (`text` / `image` / `audio` / `video` / `pdf`) مع استخدام معرّفات URI للبيانات للوسائط المضمّنة؛ متجه واحد لكل
  عنصر من المستوى الأعلى.
- عائلة Gemini Embedding 2: تتحول مصفوفة واحدة من المستوى الأعلى إلى طلب أصلي واحد
  من نوع `models/{model}:embedContent` مع `content.parts` ‏(`text` أو `inline_data`).
- ‏llama.cpp ‏(`llama-cpp/<model>`، أي نموذج حمّله الخادم المحلي): تتحول عناصر `text` القياسية
  إلى سلاسل نصية عادية، بينما يتحول كل عنصر من `image` / `audio` / `video` إلى كائن
  `{"content": [part]}` واحد، باستخدام أجزاء محتوى الدردشة الخاصة بـ llama-server ‏(`image_url`،
  و`input_audio` بالتنسيق `wav` / `mp3` / `flac`، و`input_video`) مع بيانات مضمّنة؛ متجه واحد
  لكل عنصر من المستوى الأعلى. يجب تشغيل الخادم باستخدام `--embedding --mmproj …`؛ ومن دون جهاز إسقاط
  يرفض الخادم الوسائط بنفسه. النوع `document` غير مدعوم.
- ترفض النماذج غير المعروفة/الديناميكية التي لا تحتوي على بيانات وصفية صريحة للوسائط الإدخال المنظم عبر HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

تُرجع تركيبات النموذج/الوسيلة غير المدعومة HTTP 400 بدلًا من فرض تحويل العنصر. وتستمر حقول
الامتداد غير الخاصة بالإدخال في طلبات السلاسل النصية/الرموز القديمة في المرور دون تغيير.

```bash
# سرد جميع نماذج التضمين
GET /v1/embeddings
```

## توليد الصور

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

تشمل المزوّدات المتاحة OpenAI (GPT Image 2)، وxAI (Grok Image)، وTogether AI (FLUX)، وFireworks AI، وNebius (FLUX)، وHyperbolic، وNanoBanana، و**OpenRouter**، و**ZenMux**، وSD WebUI (محلي)، وComfyUI (محلي).

يُرجع `n` عددًا مقداره `n` من الصور في `data[]`. أمّا المزوّدات التي تُرجع واجهة API الأصلية لديها صورة واحدة لكل استدعاء
(Black Forest Labs، وStability AI، وLeonardo، وIdeogram، وHaiper، وHyperbolic، وMagnific/Freepik،
وNVIDIA NIM، وCloudflare Workers AI)، فتتلقى `n` من الاستدعاءات الأصلية المنفصلة، بحد أقصى 4 استدعاءات قيد التنفيذ في الوقت نفسه. تتم
إزاحة قيمة `seed` الثابتة وفق فهرس الاستدعاء (`seed`، و`seed + 1`، و…)، بحيث تختلف الصور مع بقائها
قابلة لإعادة الإنتاج. الحد الأقصى لقيمة `n` هو 10. يفشل الطلب بالكامل إذا فشل أي استدعاء. توجد قائمة
تنسيقات التوزيع في `SINGLE_IMAGE_FANOUT_FORMATS` ضمن
`open-sse/handlers/imageGeneration/fanOut.ts`.

يعيد ZenMux استخدام اتصال مفتاح API الحالي ويقبل البادئتين `zenmux/` أو `zm/`:

- يستخدم `zenmux/openai/gpt-image-2` واجهة OpenAI Images API الخاصة بـ ZenMux. تشمل الخيارات `size`،
  و`quality`، و`n`، و`output_format`، و`output_compression`، و`background`، و`response_format`.
- يستخدم الناشرون الآخرون، مثل `zm/meta/muse-image-1.0`، نقطة نهاية Vertex AI المسماة `:predict`
  والخاصة بـ ZenMux. تُطابَق `n` مع `sampleCount`، و`aspect_ratio` مع `aspectRatio`، و`image_size`
  (`1K`، و`2K`، و`4K`) مع `sampleImageSize`. لا توفّر قيمة `size` بالبكسل سوى نسبة أبعاد،
  ولا تضمن أبعادًا محددة بالبكسل. تختلف النسب والدقات والأعداد المدعومة باختلاف النموذج.
- يختار `zm/inclusionai/ming-image-0.1-design` أبعاده بنفسه. احذف `size`،
  و`aspect_ratio`، و`image_size`؛ إذ تؤدي القيم الصريحة إلى إرجاع HTTP 400. يمكن طلب PNG وJPEG وWebP
  باستخدام `output_format`.

يدعم هذا التكامل توليد الصور من النص، وليس تحرير الصور المرجعية. تُوحَّد مخرجات Vertex
في `data[].b64_json`؛ وتُرجع `response_format: "url"` عنوان HTTPS URL من المصدر
أو عنوان URL لبيانات base64 عندما لا تتوفر سوى بايتات الصورة. تؤدي المخرجات الفارغة أو الخاضعة للتصفية
إلى إرجاع خطأ بدلًا من نجاح فارغ. يعتمد الوصول إلى النماذج على حساب ZenMux.
راجع [واجهة Vertex API الخاصة بـ ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) و
[واجهة OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# سرد جميع نماذج الصور
GET /v1/images/generations
```

## التعرّف الضوئي على المحارف في المستندات

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

يحدّد `model` مزوّد OCR من خلال بادئة `provider/model`؛ ويُربط معرّف النموذج المجرّد (مثل
`mistral-ocr-latest`) بالمزوّد المسجّل له، وإذا أُغفل `model` فسيكون الإعداد الافتراضي هو
Mistral (`mistral-ocr-latest`). المزوّدات المسجّلة (`open-sse/config/ocrRegistry.ts`):

| معرّف المزوّد                 | معرّف النموذج        | قيمة `model`                                                   | ملاحظات                                                                                                     |
| ----------------------------- | -------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (أو `mistral-ocr-latest` مجرّدًا) | متزامن — تُرجع الاستجابة مباشرةً من الاستدعاء الأصلي الوحيد.                                                |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                    | المصدر غير متزامن (`analyze` مع الاستقصاء) — راجع أدناه.                                                    |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                        | متزامن، عبر نقطة نهاية الشريك `openapi/chat/completions` الخاصة بـ Vertex AI — راجع أدناه للمصادقة/العنوان. |

تستجيب المزوّدات الثلاثة جميعها ببنية واحدة مماثلة لبنية Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### تدفّق الاستقصاء في Azure Document Intelligence

واجهة `analyze` الخاصة بـ Azure Document Intelligence غير متزامنة: يُرجع الطلب الأولي
ترويسة `Operation-Location` بدلًا من نص استجابة، ويجب استقصاء النتيجة. يستقصي المعالج
(`open-sse/handlers/ocr.ts`) عنوان URL هذا كل ثانية لما يصل إلى 30 محاولة، ويفشل سريعًا (من دون
مواصلة الاستقصاء) عند استجابة استقصاء ليست `ok` أو حالة `"failed"`، ويُرجع `504` إذا ظلت
العملية قيد التشغيل بعد استنفاد عدد المحاولات. تُوحَّد استجابة Azure النهائية
في البنية نفسها التي تتضمن `pages`/`markdown` والمستخدمة من Mistral قبل إرجاعها إلى
المستدعي، لذلك لا تحتاج شيفرة العميل إلى معالجة المزوّد كحالة خاصة.

### مصادقة Vertex AI DeepSeek OCR وتحديد نقطة النهاية

يعيد `vertex-deepseek-ocr` استخدام مصادقة Vertex AI نفسها التي يدعمها OmniRoute بالفعل
لحركة المحادثات/الصور (`open-sse/executors/vertex.ts`): يكون مفتاح API الخاص بالاتصال إما بيانات اعتماد
Service Account بتنسيق JSON (تُستبدل برمز وصول OAuth قصير الأجل عبر تدفّق JWT-bearer)
أو رمز وصول OAuth صادر مسبقًا يُستخدم كما هو. عنوان URL لنقطة النهاية الأصلية هو نقطة نهاية الشريك العامة
`openapi/chat/completions` الخاصة بـ Vertex، ويُنشأ من مشروع الاتصال
ومنطقته — تكون القيمة الصريحة لـ `providerSpecificData.project`/`providerSpecificData.region` هي المعتمدة دائمًا؛
وإلا فيُستمد المشروع من `project_id` في ملف JSON الخاص بـ Service Account، وتكون المنطقة الافتراضية
هي `us-central1`. يحدث كلا التحديدين في `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`، و`resolveVertexOcrBaseUrl`)، وتستخدمهما
`src/app/api/v1/ocr/route.ts` قبل التوجيه إلى `handleOcr`.

### أسعار النماذج (`pricing`)

يتضمن الإدخال كائن `pricing` عندما يعرف OmniRoute سعر النموذج. يأتي السعر من
جدول التسعير الذي تستخدمه محاسبة التكاليف: القيم الافتراضية المضمّنة، والأسعار المتزامنة،
والتجاوزات التي تُعيَّن من خلال `/api/pricing`. هذه أسعار قائمة، ولذلك يعرض موفرو الاشتراكات أيضًا
سعرًا لكل رمز مميز.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| الحقول                                                          | الوحدة                                 | ملاحظات                                                                                                                          |
| --------------------------------------------------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | دولار أمريكي لكل رمز مميز، سلسلة عشرية | متوافقة مع OpenRouter، ولا تستخدم أبدًا صيغة الأسس. لا يظهر حقلا ذاكرة التخزين المؤقت إلا عند وجود سعر لها.                      |
| `input`, `output`, `cached`, `cache_creation`                   | دولار أمريكي لكل مليون رمز مميز، رقم   | حقول من إصدارات الكتالوج السابقة، احتُفظ بها للعملاء الحاليين. يظهر `reasoning` و`long_context` أيضًا عندما يتضمنهما صف التسعير. |

- تحمل **التركيبات** سعر أول هدف ظاهر لها. تختار تركيبات `auto/*` المضمّنة
  هدفًا في وقت الطلب، ولذلك لا تتضمن `pricing`.
- تعرض **النماذج المجانية** `"0"` (و`0`) عندما يكون سعرها صفرًا. كما يعرض النموذج الذي لا يملك صف تسعير
  `"0"` عندما يضع الكتالوج علامة أنه مجاني (`free: true`) أو عندما يدرجه كتالوج
  النماذج المجانية المضمّن.
- **السعر غير المعروف:** لا يحتوي الإدخال على المفتاح `pricing`.
- **الموفرون الذين يحتسبون التكلفة بالرصيد** (مثل Kiro) يصدرون الفواتير لكل طلب بدلًا من كل رمز مميز. تحتفظ
  إدخالاتهم بالحقول الرقمية لكل مليون رمز مميز التي كانت لديهم سابقًا، ولا تحتوي على حقول السلاسل النصية لكل رمز مميز.
- تنسخ **المتغيرات** (معرّفات جهد الاستدلال، والأسماء البديلة التي لا تستخدم التفكير، ومرايا الاكتشاف والبوابة)
  سعر النموذج الذي توجّه إليه.
- لا تحمل الحقول سوى المعدلات الأساسية. لا تغيّر شرائح السياق الطويل (الحقل الرقمي `long_context`) ولا
  مضاعِفات مستوى الخدمة (مثل Codex السريع أو المرن) قيمة `prompt` أو
  `completion`.
- يكون الكائن نفسه لكل أساليب المصادقة، بما في ذلك طلب بأسلوب Anthropic
  يستخدم `x-api-key` و`anthropic-version` (تظل الاستجابة `{ "object": "list",
"data": [...] }`). التنفيذ: `src/app/api/v1/models/catalogPricing.ts`.

### بادئات معرّفات النماذج (`?prefix=`)

تُعرض معظم النماذج تحت **بادئة الموفّر**. تتحكم علامة الميزة
`MODELS_CATALOG_PREFIX_MODE` في البادئة التي تحصل عليها، ويمكن تجاوزها **لكل طلب** باستخدام
معامل استعلام — وهو أمر مفيد للعميل الذي يريد قائمة مرتبة دون تغيير الإعداد العام
للخادم بالنسبة إلى جميع المستخدمين الآخرين:

```bash
GET /v1/models?prefix=alias        # معرّف واحد لكل نموذج — بادئة الاسم البديل القصيرة
GET /v1/models?prefix=dual         # كلا الشكلين (الإعداد الافتراضي للخادم)
GET /v1/models?prefix=canonical    # بادئة معرّف الموفّر الكاملة فقط
```

| الوضع       | ما يُصدره                                               | ملاحظات                                                                                                                                                                              |
| ----------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `dual`      | `cc/claude-sonnet-4-6` **و** `claude/claude-sonnet-4-6` | **الوضع الافتراضي.** يوجّه كلا المعرّفين إلى النموذج نفسه؛ احتُفظ بهما لكي تظل إعدادات العملاء التي ثبّتت أيًا من الشكلين تعمل. يضاعف حجم الكتالوج تقريبًا.                          |
| `alias`     | `cc/claude-sonnet-4-6`                                  | إدخال واحد لكل نموذج. يظل الموفّرون الذين لا يملكون اسمًا بديلًا مميزًا يصدرون إدخالاتهم، لذلك لا يُفقد شيء.                                                                         |
| `canonical` | `claude/claude-sonnet-4-6`                              | إدخال واحد لكل نموذج تحت بادئة معرّف الموفّر الكاملة. يصدر الموفّرون الذين لا يملكون اسمًا بديلًا مميزًا (مثل `antigravity/…` و`agy/…`) معرّفهم الوحيد هنا أيضًا، لذلك لا يُفقد شيء. |

يمكن أيضًا التعرّف على مرآة وضع `dual` دون معامل الاستعلام: إذ تتضمن حقل `parent`
يشير إلى المعرّف الأساسي.

ينبغي للعملاء الذين يعرضون منتقي نماذج طلب `?prefix=alias` — وهذا ما تفعله
[إضافة OmniCopilot لـ VS Code](../guides/VSCODE-COPILOT.md).

### مرشحات الاكتشاف (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

تقبل `GET /v1/models` مرشحات اكتشاف اختيارية. تظل الاستجابة
دون تغيير في حال عدم استخدام أي منها. وهي تضيّق نطاق الكتالوج الذي يراه المستدعي بالفعل (تُطبَّق أذونات مفتاح API أولًا)،
وتعمل قبل ترقيم الصفحات بأسلوب OpenAI باستخدام `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # يجب أن تكون كل إمكانية مدرجة صحيحة
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` في الكتالوج؛ الصفوف التي لا تتضمنه تُعد `chat`
GET /v1/models?q=sonnet&limit=10                           # مطابقة غير حساسة لحالة الأحرف على المعرّف أو الاسم
```

| المعلّمة      | القيم                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | عدد صحيح غير سالب، تتم مقارنته مع `context_length`                                                  |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | من 1 إلى 200 حرف                                                                                    |

تؤدي القيمة غير المعروفة، أو قيمة `min_context` التي ليست عددًا صحيحًا غير سالب (مثل `1.5`)،
إلى إرجاع HTTP `400`، وتسرد الرسالة القيم الصالحة. التنفيذ:
`src/app/api/v1/models/catalogFilters.ts`.

### القائمة المختصرة للنماذج (`POST /v1/models/query`)

يعيد `POST /v1/models/query` قائمة قصيرة وحتمية من الكتالوج نفسه، مع المصادقة نفسها
وإمكانية الرؤية الخاصة بكل مفتاح كما في `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

كل حقل اختياري. تقبل `capabilities` و`exclude` مصفوفة أو سلسلة مفصولة بفواصل؛
وتتم مقارنة `max_output` مع `max_output_tokens`. تُرتّب النتائج حسب `owned_by`، ثم `id`.
القيمة الافتراضية لـ`limit` هي `20`، وتُقيّد القيم الأعلى من `100` عند `100`. تؤدي بيانات JSON غير الصالحة، أو
وجود حقل غير معروف، أو قيمة غير صالحة إلى إرجاع HTTP `400`.

### نماذج المحادثة المخفية بشكل فردي

يُستبعد من الكتالوج أي نموذج يحمل علامة **مخفي** في صفحة موفّره، ويُرفض
مع HTTP `404` / `model_not_found` عند طلبه صراحةً. يستخدم الفحص الموفّر
والنموذج اللذين جرى حلّهما، بما في ذلك الأسماء البديلة للموفّرين، وبادئات عُقد الموفّرين المتوافقين،
والإعدادات الافتراضية للاتصال. تتخطى المجموعة الأهداف المخفية ويمكنها استخدام نموذج شقيق مرئي؛ وعندما لا
يبقى أي هدف قابل للتنفيذ، فإنها تعيد رمز الخطأ نفسه. يسري إلغاء الإخفاء مع الطلب
التالي. لا تؤدي تجاوزات الرؤية الخاصة بالصور فقط إلى إخفاء نموذج المحادثة ذي المعرّف نفسه.

إعداد النموذج الفردي هذا منفصل عن
[قوائم السماح/المنع لإظهار النماذج](../routing/MODEL_EXPOSURE_LIST.md)، التي ترشّح النماذج المُعلنة في الكتالوج
ومرشحي التوجيه التلقائي، مع الإبقاء على الإرسال الصريح. وتستمر صلاحيات النماذج الخاصة بمفتاح API
في التطبيق بشكل مستقل. يظل وضع بادئة الكتالوج الافتراضي `dual`.

### متغيرات النماذج من دون تفكير

بالنسبة إلى نماذج Claude التي تدعم التفكير، يعلن `/v1/models` أيضًا عن متغير **من دون تفكير** يبدأ معرّفه بالبادئة `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

يؤدي تحديد هذا المعرّف (على سبيل المثال، في إعداد Claude Code يرفق دائمًا كتلة `thinking`) إلى حلّه مرة أخرى إلى `<provider>/<model>` الحقيقي مع تعطيل الاستدلال — باستخدام `thinking:{type:"disabled"}` في مسار `/v1/messages`، أو إسقاط حقلي `reasoning`/`reasoning_effort` في مسار `/v1/chat/completions`. لا يُدرج المتغير إلا لنماذج عائلة Claude التي تدعم التفكير **وتلتزم** بالقيمة `disabled` (لذلك، على سبيل المثال، تُستبعد النماذج التكيفية فقط التي ترفض `disabled`). يمكن للمشغّلين فرض تفعيل المتغير أو تعطيله لكل نموذج عبر `ModelSpec.noThinkingAlias`.

## توليد الصوت باستخدام ElevenLabs

هيّئ اتصال مزوّد `elevenlabs` في OmniRoute باستخدام مفتاح ElevenLabs API الخاص بك.
تُجري التطبيقات العميلة المصادقة باستخدام مفتاح **OmniRoute** الخاص بها (`Authorization: Bearer $OMNIROUTE_API_KEY`)؛
وتوفر البوابة مفتاح المزوّد المخزّن بوصفه `xi-api-key`. لا ترسل أبدًا مفتاح ElevenLabs
بصفته رمز حامل البوابة.

| الطريقة | المسار                      | الاستجابة                           | فئة نقطة نهاية مفتاح API |
| ------- | --------------------------- | ----------------------------------- | ------------------------ |
| POST    | `/v1/sound-generation`      | بايتات صوتية أصلية                  | `elevenlabs`             |
| POST    | `/v1/music`                 | بايتات صوتية أصلية                  | `music`                  |
| POST    | `/v1/music/stream`          | بايتات صوتية متدفقة                 | `music`                  |
| POST    | `/v1/music/detailed`        | صوت أصلي متعدد الأجزاء وخطة تأليف   | `music`                  |
| POST    | `/v1/music/detailed/stream` | بيانات SSE وصفية أصلية ومقاطع صوتية | `music`                  |
| POST    | `/v1/music/plan`            | خطة تأليف بصيغة JSON                | `music`                  |

تُكمّل نقاط النهاية هذه المسارات الحالية `/v1/audio/speech` و`/v1/audio/transcriptions`
و`/v1/voices` و`/v1/text-to-speech/{voiceId}` و`/v1/speech-to-text`. تُحفظ حقول JSON الأصلية
ومعاملات الاستعلام مثل `output_format` و`enable_logging`.
تحتفظ استجابات `/v1/music/detailed` بحدودها متعددة الأجزاء؛ لذا حلّلها بوصفها متعددة الأجزاء.
تُرجع `/v1/music/detailed/stream` النوع `text/event-stream` مع بيانات التأليف الوصفية
ومقاطع صوتية بترميز base64 ضمن أحداث SSE. تدعم المسارات الستة جميعها طلبات CORS التمهيدية.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# مؤثر صوتي قصير. المدة: من 0.5 إلى 30 ثانية.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# تُعبّر مدة الموسيقى بالمللي ثانية: من 3000 إلى 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

استخدم `/v1/music/stream` مع نص JSON نفسه لتسليم الصوت تدريجيًا. يقبل التأليف
واحدًا فقط من `prompt` أو `composition_plan`؛ وتتطلب `/v1/music/plan` الحقل `prompt`
وتقبل اختياريًا `source_composition_plan`. تحتفظ المخططات الأصلية بحقول المزوّد الإضافية
كي تصل إصدارات خطة التأليف وخيارات الضبط الدقيق إلى ElevenLabs.

تقبل نقطة النهاية الموحدة `/v1/music/generations` أيضًا `elevenlabs/music_v1`
و`elevenlabs/music_v2` و`elevenlabs/music_v2_5`. عند وجود اتصال ElevenLabs نشط،
تُعرض هذه النماذج في كتالوج الموسيقى. تُرجع نقطة النهاية هذه
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. يُقاس الحقل `duration` فيها
بالثواني ويُربط بـ`music_length_ms`؛ وتكون الأولوية لقيمة `music_length_ms` الصريحة.
يُربط `instrumental` بـ`force_instrumental`، مع إعطاء الأولوية للحقل الأصلي.
استخدم نقاط نهاية البث الأصلية للبث، ونقطة نهاية التأليف الأصلية
للطلبات التي تعتمد فقط على خطة تأليف.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

تُطبّق قيود نقطة النهاية والنموذج والميزانية والاتصال قبل إجراء استدعاء إلى الخدمة العليا. تُرجع
المسارات الأصلية رموز حالة الخدمة العليا ونصوص الأخطاء دون تغيير، بما في ذلك `402` لقيود الخطة
و`429` لتجاوز حد الحصة. تُحفظ الترويسات `character-cost` و`song-id` و`request-id` و`retry-after`
عند وجودها. لا يضمن رصيد مجاني الوصول إلى كل نموذج موسيقي
أو تنسيق إخراج أو ميزة API؛ إذ تحدد ElevenLabs الاستحقاق لكل طلب.
تحفظ نقطة النهاية الموحدة رموز حالة الخطأ ضمن غلاف الأخطاء الموحّد الخاص بـOmniRoute.

عقود الخدمة العليا: [المؤثرات الصوتية](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert)،
[التأليف الموسيقي](https://elevenlabs.io/docs/api-reference/music/compose) و
[تفاصيل بث الموسيقى](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> **عُقد موفّري إعادة الترتيب:** يوجّه `POST /v1/rerank` الطلبات أيضًا إلى عُقد موفّرين متوافقة مع OpenAI
> ‏(oMLX وvLLM وInfinity وTEI خلف بوابة، …) تتم عنونتها بالصيغة `<node-prefix>/<model>`. تكون عُقد الاسترجاع
> الحلقي (`localhost` و`127.0.0.1` و`172.16.0.0/12`) مؤهلة دائمًا، وكذلك أسماء المضيفين التي يدرجها
> المشغّل في `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (مثل اسم خدمة Docker/Compose على غرار
> `http://reranker:8080/v1`؛ إذ يجري الاتصال بها مباشرةً، ولا تمر مطلقًا عبر `HTTP(S)_PROXY` أو
> الوكيل المثبّت لاتصال ما). أما العُقد الموجودة على أي مضيف آخر
> — سواء كان جهازًا على الشبكة المحلية أو نظيرًا عبر Tailscale — فلا تكون مؤهلة إلا عندما يفعّل المشغّل
> علامة الميزة `RERANK_REMOTE_PROVIDER_NODES` **و** يجتاز عنوان URL الأساسي للعقدة سياسة
> عناوين URL الصادرة للموفّر (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> تستدعي خطوة إعادة الترتيب في محرّك الذاكرة هذا المسار عبر
> الاسترجاع الحلقي، لذا تنطبق القاعدة نفسها على `rerankProviderModel` في إعدادات الذاكرة.
>
> **أشكال الخادم المحلي:** تُستدعى العقدة عند `<base>/v1/rerank`، وعند تلقي 404، عند `<base>/rerank`
> ‏(Infinity وTEI). يتضمن نص الطلب المرسل إلى الخدمة العليا كلاً من صياغة Cohere/OpenAI ‏(`documents`
> و`return_documents`) وصياغة TEI ‏(`texts` و`return_text`)، وتُطبَّع استجابة الخدمة العليا إلى غلاف
> Cohere: إذ يُعاد كلٌّ من مصفوفة TEI المجرّدة `[{index, score, text}]`، و`{results: [{index, score}]}`
> من البوابات الخفيفة، و`{data: [...]}` بأسلوب Voyage إلى العميل بالصيغة
> `{results: [{index, relevance_score, document?}]}`، مرتبةً حسب الدرجة ومحدودةً بالقيمة `top_n`.

> **اكتشاف عُقد الموفّرين:** تظهر النماذج الموجودة على عقدة موفّر متوافقة مع OpenAI في `GET /v1/models`
> تحت بادئة العقدة. ترث الصفوف التي لا تتضمن بيانات وصفية لنقطة النهاية (وهو أمر شائع في قوائم `/v1/models` المحلية)
> قيمة `apiType` الخاصة بالعقدة، بحيث تكون نماذج عقدة `embeddings` من النوع `type: "embedding"` ونماذج عقدة
> `rerank` من النوع `type: "rerank"` بدلًا من تعيين الدردشة افتراضيًا؛ وتظل قيمة
> `supportedEndpoints` الصريحة في صف متزامن أو مضاف يدويًا ذات أولوية.

### خيارات `provider_options` الخاصة بـExa وTavily

يقرأ Exa وTavily الحقول الخاصة بالمزوّد من حاوية ذات مساحة أسماء:
`provider_options.exa` (أو `provider_options["exa-search"]`) و`provider_options.tavily`
(أو `provider_options["tavily-search"]`). لا تُمرَّر إلا المفاتيح أدناه. ويُتحقق من كل مفتاح
باستخدام مخطط Zod الخاص به في `open-sse/handlers/search/providerOptionsPassthrough.ts`،
ويُستبعد أي مفتاح من نوع غير صحيح. ويُتجاهل أي مفتاح آخر، بما في ذلك المصادقة وعنوان URL الأساسي
و`stream` و`outputSchema`. تواصل المفاتيح المسطحة التي تستخدمها المزوّدات الأخرى (`cx` و`depth` و...) العمل
كما كانت من قبل.

| المزوّد | الحقول ذات المستوى الأعلى                                                                                                                                                                                                                                                                                                                                                 | المتداخلة                                                                                                                                                             |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa     | `type`، `category`، `userLocation`، `moderation`، `additionalQueries`، `objective`، `systemPrompt`، `compliance` (قيم أولية مسطحة)، `startPublishedDate`، `endPublishedDate`                                                                                                                                                                                              | تُدمج `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` فوق القيمة الافتراضية `{ text: true, highlights: true }` |
| Tavily  | `search_depth`، `chunks_per_source`، `time_range`، `start_date`، `end_date`، `include_published_date`، `filter_by_published_date`، `include_answer`، `include_raw_content`، `include_images`، `include_image_descriptions`، `include_favicon`، `include_domains_mode`، `language`، `filter_by_language`، `auto_parameters`، `exact_match`، `include_usage`، `safe_search` | —                                                                                                                                                                     |

تكون الأولوية دائمًا للحقول العامة: `query` و`max_results` و`filters` (النطاقات) و`country` والموضوع
المشتق من `search_type`. في Exa، يحافظ `search_type: "news"` على `category: "news"`.
ويقبل Tavily أيضًا `search_type: "finance"` ‏(`topic: "finance"`).

يصل الحقل العام `time_range` الآن إلى كلا المزوّدين: يحصل Exa على `startPublishedDate` (طابع زمني
بتنسيق ISO)، ويحصل Tavily على `start_date` ‏(`YYYY-MM-DD`). ويتجاوز التاريخ المحدد صراحةً في `provider_options`
التاريخ المعيَّن تلقائيًا.

تحتفظ نتائج Exa بـ`id` و`highlight_scores` و`summary` و`subpages` و`entities` و`extras` في
`provider_raw`. وتحتفظ نتائج Tavily بـ`images` و`favicon`.

لا تزال محاسبة التكلفة تستخدم السجل المسطح `costPerQuery`. يحتسب Tavily تكلفة
`search_depth: "advanced"` بعدد أكبر من الأرصدة لكل استدعاء، ولا يظهر هذا الفرق في
`usage.search_cost_usd`.

## واجهة برمجة تطبيقات جلب الويب

استخرج المحتوى من عنوان URL عبر موفّر جلب ويب مُهيأ (Firecrawl أو Jina
Reader أو Tavily Extract أو TinyFish Fetch أو Nimble Extract أو Parallel Extract).

يُرجع Parallel Extract (`parallel-search`، باستخدام مفتاح API نفسه الخاص بـ Parallel Search) محتوى Markdown
فقط — وأي `format` آخر ينتج عنه `400` — ويحدّ المحتوى عند 100,000 حرف. عندما
يتعذر استخراج الصفحة المستهدفة نفسها، تُبلغ الخدمة المصدرية بذلك ضمن استجابة HTTP 200؛
ويعرض OmniRoute ذلك كخطأ `422` مع رسالة ثابتة.

| الطريقة | المسار          | الوصف                                                                    |
| ------- | --------------- | ------------------------------------------------------------------------ |
| POST    | `/v1/web/fetch` | جلب/استخراج عنوان URL — يُتحقق من النص الأساسي بواسطة `v1WebFetchSchema` |

**المصادقة:** مفتاح API من نوع Bearer (`extractApiKey` + `isValidApiKey`). تُفرض السياسة عبر `enforceApiKeyPolicy`.

**الرجوع الاحتياطي المراعي للحصة (#8297):** عند عدم تحديد `provider` صراحةً، يتم اجتياز
المجموعة (`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`)
بترتيب أولوية ثابت
(الملء أولًا) — ويجري تخطي الموفّر المُهيأ الذي يخضع لتحديد المعدل
بدلًا من إنهاء الطلب مبكرًا، كما يؤدي فشل المصدر القابل لإعادة المحاولة/المرتبط بالحصة
(HTTP 429 دائمًا؛ و402/403 للحصص المجانية من نمط Firecrawl/Tavily/TinyFish —
وليس لـ Jina Reader، وأبدًا ليس لطلب 400 عادي غير صالح) إلى الانتقال إلى
الموفّر التالي غير المجرّب ذي بيانات الاعتماد وقت الطلب. عند استنفاد جميع الموفّرين في
المجموعة، تُرجع نقطة النهاية استجابة `429` واحدة (مع ترويسة `Retry-After`)
بدلًا من استجابة `400` العامة السابقة. عند طلب `provider` صراحةً،
لا يوجد **أي** رجوع احتياطي صامت — إذ يعرض الموفّر الصريح الخاضع لتحديد المعدل أو الذي يفشل
الخطأ الخاص به (`429` إذا كان خاضعًا لتحديد المعدل، وإلا فحالة
المصدر).

## البث عبر WebSocket

```bash
GET /v1/ws?handshake=1
```

يتحقق من مصافحة ترقية WebSocket ويُرجع أمثلة رسائل بروتوكول الاتصال (`request` و`cancel`). تُعالَج إطارات WS الفعلية بواسطة خادم WS المضمّن خارج جدول مسارات Next.js.

**المصادقة:** مفتاح API من نوع Bearer أثناء المصافحة.

### واجهة Responses API عبر WebSocket (لـ codex فقط)

```bash
# المضيف:المنفذ نفسه لواجهة HTTP API (الافتراضي 20128)؛ رقِّ الاتصال:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (أو: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# يجب أن يكون الإطار الأول response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

يتم توصيل وكيل Responses-API-over-WebSocket **حصريًا بـ `codex`** (الواجهة الخلفية لـ ChatGPT).
ويستمع على المنفذ نفسه الخاص بواجهة API/لوحة المعلومات عند المسارات `/v1/responses`
و`/responses` و`/api/v1/responses`. عند أول إطار `response.create`، يُجري
المصادقة + التحضير عبر جسر `codex-responses-ws` الداخلي، ويحدد
اتصال codex OAuth، وينشئ نفقًا إلى `wss://chatgpt.com/backend-api/codex/responses`
عبر نقل `wreq-js`. **تُرفض النماذج غير التابعة لـ codex** (`codex_ws_provider_required`).
لتوجيه مشاركة الحصة، استخدم `model: "qtSd/<group>/codex/<model>"`. تم التنفيذ في
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**المصادقة:** مفتاح API من نوع Bearer أثناء المصافحة. يجب أن يكون خادم HTTP المضمّن (`server-ws.mjs`)
هو نقطة الدخول النشطة (وهو كذلك افتراضيًا عند وجود `app/server-ws.mjs`).

#### معرّف النموذج: استخدم معرّف ChatGPT المجرّد (من دون بادئة `codex/`)

تتحقق **Codex CLI** من OpenAI من اسم النموذج من جانب العميل عندما تكون
`supports_websockets = true`، و**ترفض المعرّفات المسبوقة باسم الموفّر** مثل
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). أرسل المعرّف **المجرّد** (مثل `gpt-5.5`). جسر OmniRoute
مخصص لـ codex فقط، لذا يعيد تحليل المعرّف المجرّد باعتباره نموذج codex
(`resolveCodexWsModelInfo`) قبل إنشاء النفق إلى المصدر — رغم أن
`gpt-5.5` المجرّد كان سيوجَّه بخلاف ذلك إلى موفّر آخر عبر HTTP.

#### تهيئة OpenAI Codex CLI

وجّه Codex CLI إلى OmniRoute بإضافة موفّر مخصص يدعم WebSocket
إلى `~/.codex/config.toml` (استخدم `CODEX_HOME` منفصلًا لتجنب تعديل
تهيئة موجودة):

```toml

[model_providers.omniroute]
```


إلى اتصال codex OAuth المحدد. تم التحقق منه من طرف إلى طرف باستخدام الخادم

الإكمال.

## الاستخدام بالخدمة الذاتية (`/api/usage/om-usage`)

يمكن لأي مفتاح API قراءة استخدامه وحصصه **الخاصة به** — دون مصادقة إدارية. هذه هي نقطة النهاية التي
يستخدمها العميل (CLI، أو لوحة OmniCopilot) لعرض إنفاق حامل المفتاح.

```bash
# الصيغة النصية (العقد التاريخي — نص عادي للطرفية)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# الصيغة المنظّمة — ما تستهلكه واجهة المستخدم
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

يجب أن يكون الخيار **`allowUsageCommand`** مفعّلًا للمفتاح (وهو معطّل افتراضيًا — ويقوم مدير مفاتيح API
في لوحة المعلومات بتبديله لكل مفتاح). من دونه، تستجيب نقطة النهاية بالحالة `403`.

يعيد `?format=json` بنية تمييزية بحيث لا يقرأ المستدعي أبدًا حقل بيانات من استجابة
رفض. عند النجاح:

```jsonc
{
  "allowed": true,
  // لا يظهر إلا عندما يكون المفتاح قد اختار حدود استخدام خاصة بكل مفتاح (بالدولار الأمريكي يوميًا/أسبوعيًا):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // لقطة حصة المزوّد المحدد، أو null عندما لا يكون أي شيء مخزّنًا مؤقتًا بعد:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // لقطة كل اتصال، كي تتمكن واجهة المستخدم من عرض عدة مزوّدين جنبًا إلى جنب:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

عند الرفض (مفتاح غير صالح بالحالة `401` / غير مسموح بالحالة `403`)، يعيد المسار نفسه
`{ "allowed": false, "error": { "message": "…" } }` — تختلف حالة وجود `personal`/`provider` مع كونه فارغًا
(المفتاح مسموح، لكن لم تُجمع أي معلومات بعد) عن حالة الرفض، ولا تميّز بينهما إلا صيغة JSON.

**المصادقة:** مفتاح API من نوع Bearer الخاص بالمستدعي، ويجري التحقق منه باستخدام `isValidApiKey` — وهذه _ليست_
واجهة الإدارة (`/api/keys/…`)، التي تظل محمية بواسطة `requireManagementAuth`.

### النسب المئوية الخام للحصص مقابل النسب المعدّلة وفق حد القطع

عند استهلاك `/api/usage/om-usage`، ينبغي للمستدعين ملاحظة الفرق بين النسب المئوية التي يعرضها
**الإخراج النصي العادي** وتلك التي يعرضها **إخراج JSON** المنظّم:

| الجانب               | تنسيق النص العادي (`/api/usage/om-usage` / `@@om-usage`)                              | تنسيق JSON (`?format=json`)                                                  |
| :------------------- | :------------------------------------------------------------------------------------ | :--------------------------------------------------------------------------- |
| **حقل الإخراج**      | `NN% left` (مثلًا، `20% left`)                                                        | `provider.quotas` / `providers[].quotas`                                     |
| **القياس**           | **المقدار القابل للاستخدام المعدّل وفق حد القطع**: السعة المتبقية فوق عتبة القطع      | **حصة المنبع الخام**: قياس المزوّد غير المعدّل                               |
| **تحجيم حد القطع**   | يُحجّم عبر `effectiveRemainingPercent()` بحيث يظهر الاحتياطي المحمي على أنه `0% left` | لا يوجد (قيم اللقطة الخام كما أبلغ عنها المزوّد)                             |
| **بيانات العتبة**    | مضمّنة في النسبة المئوية المعروضة                                                     | مخزّنة في `quotaWindowThresholds` لكل اتصال (أو الإعدادات الافتراضية للخادم) |
| **المستهلك الأساسي** | واجهات CLI التفاعلية، ومطالبات الطرفية، والمشغّلون البشريون                           | عمليات التكامل البرمجية، ولوحات المعلومات، والتحليلات، ومتتبعات الفوترة      |

#### معادلة التعديل وفق حد القطع

يدعم OmniRoute حدود قطع استباقية للحصص لمنع استنفاد موارد المنبع (تُضبط عبر
`quotaWindowThresholds` الخاصة بالاتصال، أو إعدادات المزوّد الافتراضية، أو إعدادات المرونة العامة). عندما تكون عتبة قطع
(مثلًا، `cutoff = 25%`) نشطة ضمن نافذة حصة، يحسب عارض النص المقدار المتبقي كما يلي:

- إذا كان `remaining <= cutoff`: تُعاد `0%`.
- إذا كان `remaining > cutoff`: تُعاد `((remaining - cutoff) / (100 - cutoff)) * 100`.

يقرّب الإخراج النصي المنسّق هذه القيمة إلى أقرب عدد صحيح (`Math.round(...)`).

#### مثال توضيحي

لنفترض وجود نافذة مزوّد ذات **استخدام خام بنسبة 60%** (وبالتالي **حصة خام متبقية بنسبة 40%**) مع عتبة قطع مضبوطة
على **25% من الحصة المتبقية**:

| التمثيل                         | العملية الحسابية                                   | المتبقي |           الاستخدام الضمني           |
| :------------------------------ | :------------------------------------------------- | :-----: | :----------------------------------: |
| **JSON الخام (`?format=json`)** | لقطة المنبع (`quotas[window]`)                     | **40%** |               **60%**                |
| **التنسيق النصي (`NN% left`)**  | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (عند حساب `100 - remaining`) |

- **لماذا يعرض النص تبقي 20%:** من أصل 40% من الحصة الفعلية المتبقية في الحساب، تحتفظ سياسة
  القطع بنسبة 25%. لا يتبقى للمستدعي سوى 15% من أصل 75% من الهامش القابل للاستخدام قبل أن يتوقف الموجّه
  عن توجيه الطلبات إلى هذا الاتصال. يضمن التحجيم أن يشير الاتصال إلى الاستنفاد (`0% left`) تمامًا عندما
  يتوقف التوجيه.
- **لماذا يحافظ JSON على القيم الخام:** تعيد حمولة JSON لقطة المزوّد الدقيقة (`UsageSnapshot`)
  بحيث تتمكن الأدوات الخارجية من الوصول إلى الاستخدام الحقيقي للمنبع وإعدادات
  `quotaWindowThresholds` على مستوى الاتصال دون تحجيم فاقد للمعلومات من جانب الخادم.

#### إرشادات ترحيل المستهلكين

إذا كان تكامل خارجي (مثل مكوّن إضافي للمحرر أو امتداد للوكيل) يستخرج سابقًا بيانات من نقطة النهاية النصية
(`NN% left`) ويحسب النسبة المئوية المستخدمة بوصفها `100 - NN`، فإن الانتقال إلى `?format=json` يعني:

- ستعكس قراءة قيم JSON الأولية **الاستهلاك الفعلي في المصدر الأعلى** (60% مستخدمة في المثال أعلاه).
- إذا أراد التكامل الحفاظ على دلالات الحصة القابلة للاستخدام الخاصة بنقطة النهاية النصية، فيمكنه تقييم
  صيغة المتبقي الفعلي من جانب العميل باستخدام `quotaWindowThresholds` للتجاوزات على مستوى الاتصال.

## ذاكرة التخزين المؤقت الدلالية

```bash
# الحصول على إحصاءات ذاكرة التخزين المؤقت
GET /api/cache/stats

# مسح جميع ذاكرات التخزين المؤقت
DELETE /api/cache/stats
```

مثال على الاستجابة:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### التأثير في زمن الاستجابة

عند العثور على نتيجة مطابقة في ذاكرة التخزين المؤقت الدلالية، تُقدَّم الاستجابة من ذاكرة التخزين المؤقت **من دون إجراء استدعاء
للخدمة المصدرية**، ولذلك تكون قيمة `X-OmniRoute-Response-Latency` المُبلَّغ عنها قريبة من الصفر
(بغض النظر عن زمن استجابة الخدمة المصدرية الأصلي). ينبغي للعملاء الحساسين لزمن الاستجابة
(اختبارات الأداء، ومراقبة p50/p99) التحقق من ترويسة الاستجابة
`X-OmniRoute-Cache-Latency`:

| القيمة      | المعنى                                                                              |
| ----------- | ----------------------------------------------------------------------------------- |
| `synthetic` | قُدِّمت الاستجابة من ذاكرة التخزين المؤقت؛ والزمن ليس زمنًا حقيقيًا للخدمة المصدرية |
| _(غائبة)_   | الاستجابة ناتجة عن استدعاء حقيقي للخدمة المصدرية                                    |

### تجاوز ذاكرة التخزين المؤقت لكل مفتاح

يمكن لمفاتيح API إلغاء الاشتراك في عمليات القراءة من ذاكرة التخزين المؤقت الدلالية عبر `cacheDefaultMode`:

| القيمة   | السلوك                                                                      |
| -------- | --------------------------------------------------------------------------- |
| `legacy` | السلوك العادي لذاكرة التخزين المؤقت (الافتراضي)                             |
| `bypass` | تخطي البحث في ذاكرة التخزين المؤقت بالكامل؛ واستدعاء الخدمة المصدرية دائمًا |

يُضبط عند إنشاء المفتاح (`POST /api/keys`) أو تحديثه (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### التجاوز لكل طلب

يمكن لأي طلب تجاوز ذاكرة التخزين المؤقت بغض النظر عن إعدادات المفتاح:

```
X-OmniRoute-No-Cache: true
```

| ----------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

إلى مسحه واستعادة القيمة الافتراضية. تُرجع `GET /api/provider-models?provider=<provider>` هذه
القيم ضمن `modelOutputOverrides`، بما في ذلك النماذج التي لا تملك سجل نموذج مخصصًا. يستخدم التجاوز
إمكانية وقت التشغيل `max_output_tokens` ويستمر بعد إعادة مزامنة النموذج. وتوفّر صفحة الموفّر المتوافق مع OpenAI
عناصر التحكم نفسها للتحرير/المسح، وتضع علامة على النماذج التي تدعم الرؤية صراحةً.

تُكيّف عُقد Chat Completions المخصصة عمليات إلغاء الاشتراك الصريحة في الاستدلال مع الواجهة الخلفية المصدرية. يؤدي
اختبار الاتصال الناجح تلقائيًا إلى تحديد عناصر التحكم في قالب الدردشة لكل معرّف نموذج مطابق تمامًا
يثبت إدخاله في `/models` قيمة `owned_by` معروفة: `vllm` أو `sglang` أو `llamacpp`.
قد تحتفظ أغلفة OpenAI المتوافقة والشفافة بإدخال النموذج الأصلي داخل كائن
`openai` متداخل؛ ويتتبع الاكتشاف ما يصل إلى ثلاثة أغلفة من هذا النوع. تحتفظ النماذج ذات الملكية المفقودة أو غير المعروفة أو
المتعارضة بسلوك OpenAI المعتاد. يعيد الاكتشاف استخدام طلب الكتالوج الحالي،
ولا يولّد أي رموز إكمال، ويُبطَل عند تغيّر نقطة نهاية الاتصال.

لتثبيت هذا السلوك لواجهة خلفية لا تعرض تلك البيانات الوصفية، استخدم واجهة API الحالية
للتحديث الجزئي للموفّر:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

أرسل هذا المتن باستخدام `PUT /api/providers/<connection-id>`. في ذلك الاتصال، يُرسل
مستوى استدلال صريح بقيمة `none` على هيئة `chat_template_kwargs.thinking=false` و
`chat_template_kwargs.enable_thinking=false`. تظل قيم القالب الأصلية الصريحة هي المرجع المعتمد
ما لم تفرض قاعدة استدلال من جانب الخادم مستوىً معينًا. لا ينطبق الإعداد إلا عندما يرسل اتصال
مخصص متوافق مع OpenAI متن Chat Completions؛ إذ تحتفظ طلبات Responses والموفّرون العاديون
ببنية طلباتهم الأصلية. عيّن `reasoningControl` إلى `openai` لفرض تمرير
`reasoning_effort` المعتاد في OpenAI، أو احذفه/عيّنه إلى `null` لاستخدام الاكتشاف التلقائي.

تجعل طلبات مصنّف الوضع التلقائي في Claude Code التفكير الأصلي معطّلًا افتراضيًا عندما لا تحتوي
على عناصر تحكم صريحة في الاستدلال. يستخدم الاكتشاف علامة النظام الخاصة بالمصنّف ضمن الطلبات بتنسيق Claude،
وليس أسماء النماذج أو حدود الإكمال. تحتفظ عناصر التحكم الصريحة في المتن، وترويسات مستوى الاستدلال/التفكير
المدعومة، وقواعد التوجيه، ومستوى استدلال النموذج بعد حله، بأولويتها الحالية. تحتفظ مرحلتا المصنّف
بالمطالبات وحدود الإكمال وتسلسلات الإيقاف وأحكام الأذونات الفعلية من المصدر؛ ولا يزال بإمكان
المرحلة الثانية إنتاج الاستدلال المرئي المطلوب كنص عادي.

### الإصدار وقناة الإصدار

```bash
GET /api/system/version
```

مسار إدارة مخصص لواجهة الاسترجاع فقط (يتطلب مصادقة المسؤول). يُرجع الإصدار قيد التشغيل، وأحدث
إصدار منشور، وحالة التحديث التلقائي. الحقلان `releaseChannel` و`channels` حقول إضافية
(المسار 3.8.54)؛ ويحتفظ `channel` بمعناه — وضع النشر الذي يستخدمه مُحدِّث لوحة المعلومات
(`npm` أو `source` أو `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — قناة npm للبنية قيد التشغيل: `nightly` للإصدارات ذات اللاحقة `-nightly.*`،
  و`next` للإصدارات التجريبية الأخرى (`-rc.*` و`-beta.*` و`-alpha.*`)، و`lts` لإصدار مستقر من
  إصدار رئيسي أقدم من `channels.latest`، وإلا فتكون `latest`. وهي القواعد نفسها المستخدمة في
  `scripts/release/dist-tag.mjs`، الذي يختار وسم توزيع npm عند النشر.
- `channels` — أحدث إصدار منشور لكل وسم توزيع، من `npm view omniroute dist-tags` (مع استخدام
  HTTP للسجل كخيار احتياطي)، ويُخزّن مؤقتًا بمدة صلاحية قدرها 10 دقائق، مثل `latest`. يكون `latest` موجودًا دائمًا
  (ويعود احتياطيًا إلى الحقل `latest`، ثم إلى `"unavailable"`)؛ ولا تظهر `next` و`nightly` و`lts`
  إلا عند وجود وسم التوزيع المقابل. يؤدي طلب `Cache-Control: no-cache` إلى تحديث عمليتي البحث كلتيهما.

نموذج القنوات (`latest` = v3 حتى الإصدار العام 4.0، و`next` = rc، و`nightly` = بُنى `develop`،
و`lts` = تصحيحات v3 بعد الإصدار العام 4.0) موضح في `docs/ops/RELEASE_STRATEGY.md`.

استخدم هذه الأسماء البديلة عندما يتعذر على أحد التكاملات إدخال ترويسة `Authorization` ويحتاج إلى تضمين مفتاح API في عنوان URL الأساسي.

```bash
# اسم بديل للفهرس بنمط OpenAI
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# أسماء بديلة للدردشة بنمط OpenAI

# أسماء بديلة بنمط Ollama
POST /api/v1/vscode/{token}/api/chat

```

مثال:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'
```

ملاحظات:

- تعيد الأسماء البديلة ذات الرموز استخدام معالجات الطلبات نفسها المستخدمة مع `/v1/*` و`/api/tags`؛ وتظل بُنى الاستجابات متطابقة.
- يُفضّل استخدام `Authorization: Bearer ...` متى كان العميل يدعم الترويسات المخصصة.
- قد تظهر الرموز المضمنة في عناوين URL في سجلات الوكيل العكسي وسجل المتصفح وبيانات القياس عن بُعد خارج OmniRoute. تعامل معها كخيار للتوافق، وليس كوضع المصادقة الافتراضي.

## حدود الرموز

ميزانيات **الرموز** لكل مفتاح API (وهي منفصلة عن الميزانية المستندة إلى الدولار الأمريكي أعلاه). تُطبَّق مباشرةً ضمن مسار الطلب: عندما يصل استخدام المفتاح خلال النافذة الحالية إلى الحد المسموح به، تُرفض الطلبات بالحالة `429 Too Many Requests`. يمكن حصر الحدود في `model` محدد أو `provider`، أو تطبيقها بشكل `global` على المفتاح بأكمله؛ وعندما تتطابق عدة حدود مع طلب، يُطبَّق الحد الأكثر تقييدًا.

```bash
# سرد حدود الرموز لمفتاح (يتضمن الاستخدام الحالي ضمن النافذة)
GET /api/usage/token-limits?apiKeyId=key-123

# إنشاء حد للرموز أو تحديثه
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# حذف حد للرموز حسب المعرّف
DELETE /api/usage/token-limits?id=tl-abc
```

> **ملاحظات المخطط** (`setTokenLimitSchema`): الحقلان `apiKeyId` و`scopeType` (`model` | `provider` | `global`) مطلوبان. الحقل `scopeValue` مطلوب ما لم يكن `scopeType` هو `global` (على سبيل المثال، معرّف نموذج لنطاق `model` أو معرّف مزوّد لنطاق `provider`). يجب أن يكون `tokenLimit` عددًا صحيحًا موجبًا (مع تحويله من سلسلة نصية). الحقول الاختيارية: `id` (احذفه للإنشاء وقدّمه للتحديث)، و`resetInterval` (`daily` | `weekly` | `monthly`، والقيمة الافتراضية `monthly`)، و`resetTime` (`HH:MM`)، و`enabled` (القيمة الافتراضية `true`). تُثري استجابات `GET` كل حد بالحقول `tokensUsed` و`remaining` و`windowStart` و`periodStartAt` و`nextResetAt`. هذه نقطة نهاية من فئة الإدارة (يُفرض الاستيثاق مركزيًا بواسطة مسار authz).

## معالجة الطلبات

1. يرسل العميل طلبًا إلى `/v1/*`
2. يستدعي معالج المسار `handleChat` أو `handleEmbedding` أو `handleAudioTranscription` أو `handleImageGeneration`

5. بالنسبة إلى المحادثة: يتحقق `handleChatCore` من ذاكرة التخزين المؤقت الدلالية/الخاصة بالتوقيع، ويحدّد إعدادات ضغط التركيبة
6. يُنفَّذ الضغط الاستباقي قبل التحويل الخاص بالمزوّد عندما يكون مفعّلًا (`lite` أو Caveman أو RTK أو الوضع المكدّس)

9. يُسجَّل الاستخدام وتحليلات الضغط وسجلات الطلبات
10. يُطبَّق الانتقال الاحتياطي عند حدوث أخطاء وفقًا لقواعد التركيبة

## المرونة (موسّع)

يوفّر OmniRoute ثلاث آليات مستقلة للتعامل مع حالات الفشل المؤقت؛ وتتيح نقاط الإدارة أدناه للمشغّلين قراءتها وتجاوز إعداداتها:

| النطاق             | تخزين الحالة                                 | القراءة                                   | إعادة الضبط / المسح                                           |
| ------------------ | -------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------- |
| قاطع المزوّد       | `domain_circuit_breakers` + الذاكرة الداخلية | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                  |
| فترة تهدئة الاتصال | `rateLimitedUntil` في اتصالات المزوّد        | `/api/rate-limits`, `/api/providers/[id]` | (تُعاد إتاحته تدريجيًا عند الحاجة؛ يُمسح عبر طلب PUT للمزوّد) |
| حظر النموذج        | سجل توافر النماذج في الذاكرة                 | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                      |

تقبل نقطة النهاية `PATCH /api/resilience` تجاوزات قاطع المزوّد ضمن `providerBreaker.oauth` و`providerBreaker.apikey`. يدعم كل ملف تعريف `degradationThreshold` و`failureThreshold` و`resetTimeoutMs`؛ كما تتوفر الحقول نفسها في لوحة المعلومات ← الإعدادات ← المرونة.

```bash
# مسح حظر نموذج واحد
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# مسح جميع حالات الحظر
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

للاطّلاع على المرجع المفاهيمي الكامل والقيم الافتراضية للقاطع: راجع [`CLAUDE.md`](../../CLAUDE.md) ← "حالة وقت تشغيل المرونة" و[`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### قائمة انتظار حدود المعدّل وشبكة أمان التفعيل التلقائي

- **مسار الكتابة المدعوم**: تُعدّ `POST /api/rate-limits` ذات النص `{"connectionId": "<id>", "enabled": true|false}` نقطة الإدارة المدعومة لتفعيل حماية حدود المعدّل أو تعطيلها لاتصال ما. لا يعدّل `PUT /api/providers/[id]` قيمة `rateLimitProtection` أو يعكسها عمدًا (#11278).
- **دلالات `enabled: false`**: يؤدي تعيين `enabled: false` إلى إزالة الحماية الصريحة للاتصال، لكنه **لا** يستثني اتصالًا نشطًا يستخدم مفتاح API من شبكة أمان التفعيل التلقائي العامة (`autoEnableApiKeyProviders = true`). في `reconcileEnabledConnections` ضمن (`open-sse/services/rateLimitManager.ts`)، تُعدّ `false` و`undefined` متكافئتين؛ وتظل اتصالات مفاتيح API النشطة التي لا تتمتع بحماية صريحة محمية ضمن شبكة أمان التفعيل التلقائي.
- **التعطيل العام**: لتشغيل اتصالات مفاتيح API من دون قوائم انتظار حدود المعدّل، عطّل شبكة الأمان عموميًا عبر `RATE_LIMIT_AUTO_ENABLE=false` (متغير البيئة) أو `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (الإعدادات ← المرونة / `PATCH /api/resilience`).

## خادم MCP

يتضمن OmniRoute خادمًا مضمّنًا لبروتوكول سياق النموذج مع 3 وسائل نقل (stdio، وSSE، وstreamable-http) وأدوات محددة النطاق. تقرأ نقاط نهاية لوحة المعلومات أدناه بيانات الحالة/التدقيق وتعمل كوكيل لوسائل نقل HTTP.

| الطريقة | المسار | الوصف |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | نبضات الاتصال، ووسيلة النقل، وحالة الاتصال، وآخر استدعاء، والأدوات الأكثر استخدامًا، ومعدل النجاح خلال 24 ساعة |
| GET | `/api/mcp/tools` | قائمة أدوات MCP التي تتضمن `name`، و`description`، و`scopes`، و`phase`، و`auditLevel`، و`sourceEndpoints` |
| GET | `/api/mcp/sse` | فتح تدفق SSE لوسيلة نقل SSE (يعيد `503` إذا كان MCP معطّلًا أو كانت وسيلة النقل غير متطابقة) |
| POST | `/api/mcp/sse` | إرسال إطار JSON-RPC عبر وسيلة نقل SSE |
| GET | `/api/mcp/stream` | فتح جانب SSE من وسيلة نقل HTTP القابلة للبث (الرسائل التي يبدأها الخادم) |
| POST | `/api/mcp/stream` | إرسال إطار JSON-RPC عبر وسيلة نقل HTTP القابلة للبث |
| DELETE | `/api/mcp/stream` | إنهاء جلسة HTTP قابلة للبث |
| GET | `/api/mcp/audit` | الاستعلام عن سجل التدقيق — `?limit=`، و`?offset=`، و`?tool=`، و`?success=true                                | false`، و`?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | إحصاءات تدقيق مجمّعة (الإجماليات، ومعدل النجاح، ومتوسط المدة، والأدوات الأكثر استخدامًا) |

**المصادقة:** تحترم وسيلتا النقل `sse`/`stream` سطح المصادقة الخاص بـMCP (مفتاح API من نوع Bearer بنطاق `mcp`)؛ ويمكن قراءة مسارات `status`/`tools`/`audit*` من لوحة المعلومات (لا يلزم إجراء مصادقة إضافي بخلاف إمكانية الوصول إلى مضيف لوحة المعلومات).

> تخضع وسيلتا نقل HTTP كلتاهما لـ`settings.mcpEnabled` و`settings.mcpTransport` — يؤدي عدم تطابق وسيلة النقل إلى إرجاع `400`، بينما تؤدي حالة تعطيل MCP إلى إرجاع `503`.

## خادم A2A

يوفّر OmniRoute نقطة نهاية A2A (من وكيل إلى وكيل) تستخدم JSON-RPC 2.0، بالإضافة إلى غلاف REST لأغراض الفحص ولوحة المعلومات.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # اختياري ما لم يكن OMNIROUTE_API_KEY معيّنًا
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

الأساليب المدعومة (جميعها خاضعة لإعداد `settings.a2aEnabled`):

| الأسلوب          | الوصف                                                     |
| ---------------- | --------------------------------------------------------- |
| `message/send`   | تنفيذ متزامن للمهارة؛ يُرجع `{task, artifacts, metadata}` |
| `message/stream` | تنفيذ متدفق عبر SSE لمجموعة المهارات نفسها                |
| `tasks/get`      | جلب مهمة بواسطة `taskId`                                  |
| `tasks/cancel`   | إلغاء مهمة بواسطة `taskId`                                |

المهارات المدمجة: `smart-routing`، و`quota-management`، و`provider-discovery`، و`cost-analysis`، و`health-report`.

### بطاقة الوكيل

```bash
GET /.well-known/agent.json
```

يُرجع بطاقة وكيل A2A العامة (الاسم، والوصف، والإمكانات، ودليل المهارات، ونظام المصادقة) — وتُخزّن مؤقتًا بشكل عام لمدة ساعة واحدة. لا تتطلب مصادقة.

### أدوات REST المساعدة

| الأسلوب | المسار                       | الوصف                                                                                                              |
| ------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| GET     | `/api/a2a/status`            | حالة تفعيل A2A + إحصاءات المهام + ملخص بطاقة الوكيل المخزّن مؤقتًا                                                 |
| GET     | `/api/a2a/tasks`             | سرد المهام — `?state=submitted\|working\|completed\|failed\|cancelled`، و`?skill=`، و`?limit=` (≤200)، و`?offset=` |
| POST    | `/api/a2a/tasks`             | (غير منفّذ كأداة REST مساعدة — أنشئ المهمة عبر JSON-RPC باستخدام `message/send`)                                   |
| GET     | `/api/a2a/tasks/[id]`        | استرداد مهمة واحدة                                                                                                 |
| POST    | `/api/a2a/tasks/[id]/cancel` | إلغاء مهمة                                                                                                         |

**المصادقة:** تعمل أدوات REST المساعدة دون مصادقة إدارية (يمكن للوحة المعلومات قراءتها)؛ ويستخدم مسار JSON-RPC ‏`/a2a` الرمز المميز Bearer ‏`OMNIROUTE_API_KEY` إذا كان مهيّأً.

## المصادقة

راجع [مصادقة الإدارة](../guides/MANAGEMENT-AUTH.md) للتعرّف على عائلات بيانات الاعتماد الأربع
(جلسة لوحة المعلومات، ورمز CLI المحلي، ورمز الوصول `oma_live_…`،
ومفتاح API بنطاق الإدارة) وكيف تختلف عن مفاتيح الاستدلال.

- تستخدم مسارات لوحة المعلومات (`/dashboard/*`) ملف تعريف الارتباط `auth_token`
- يستخدم تسجيل الدخول تجزئة كلمة المرور المحفوظة؛ مع الرجوع احتياطيًا إلى `INITIAL_PASSWORD`
- يمكن تبديل `requireLogin` عبر `/api/settings/require-login`
- قد تتطلب مسارات `/v1/*` اختياريًا مفتاح API من نوع Bearer عندما تكون `REQUIRE_API_KEY=true`
- يُقصد بـ «رمز الإدارة» / «مفتاح API بنطاق الإدارة» في هذا المرجع إحدى العائلات الواردة في ذلك الدليل — وليس نوعًا إضافيًا غير معرّف من الأسرار

> **تغيير غير متوافق (v3.8.0)** — تتطلب الآن `/api/v1/agents/tasks/*` ونقاط نهاية إدارة فترة الانتظار **مصادقة الإدارة** (ملف تعريف الارتباط `auth_token` الخاص بلوحة المعلومات أو مفتاح API بنطاق الإدارة). ستتلقى التطبيقات العميلة التي كانت تستدعي هذه المسارات سابقًا من دون مصادقة الاستجابة `401 Unauthorized`. راجع الالتزام `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
