## 🎯 حالات الاستخدام

### الحالة 1: "لدي اشتراك Claude Pro"

**المشكلة:** تنتهي صلاحية الحصة من دون استخدامها، وتظهر حدود المعدل أثناء البرمجة المكثفة

```
التوليفة: "maximize-claude"
  1. cc/claude-opus-4-7        (استخدام الاشتراك بالكامل)
  2. glm/glm-4.7               (خيار احتياطي رخيص عند نفاد الحصة)
  3. if/qwen3.8-max-preview       (خيار احتياطي مجاني للطوارئ)

التكلفة الشهرية: $20 (الاشتراك) + نحو $5 (الخيار الاحتياطي) = إجمالي $25
مقابل $20 + بلوغ الحدود = إحباط
```

### الحالة 2: "أريد تكلفة صفرية"

**المشكلة:** لا أستطيع تحمّل تكلفة الاشتراكات، وأحتاج إلى ذكاء اصطناعي موثوق للبرمجة

```
التوليفة: "zero-cost"
  1. if/kimi-k2.7-code          (وصول مجاني مُدرج؛ قد تُطبّق حدود المعدل)
  2. kr/qwen3-coder-next        (خيار Kiro الاحتياطي المجاني)

التكلفة الشهرية: $0
الجودة: تحقّق من النموذج والحدود والخصوصية واتفاقية مستوى الخدمة لأعباء عملك
```

### الحالة 3: "أحتاج إلى البرمجة على مدار الساعة طوال أيام الأسبوع، بلا انقطاع"

**المشكلة:** لدي مواعيد نهائية، ولا يمكنني تحمّل فترات التوقف

```
التوليفة: "always-on"
  1. cc/claude-opus-4-7        (أفضل جودة)
  2. cx/gpt-5.5                (اشتراك ثانٍ)
  3. glm/glm-4.7               (رخيص، ويُعاد تعيينه يوميًا)
  4. minimax/MiniMax-M2.1      (الأرخص، ويُعاد تعيينه كل 5 ساعات)
  5. if/deepseek-v4-flash       (وصول مجاني مُدرج؛ قد تُطبّق حدود المعدل)

النتيجة: توسّع 5 طبقات احتياطية نطاق المرونة؛ ولا يمكن ضمان توافر الخدمات الأساسية
التكلفة الشهرية: $20-200 (الاشتراكات) + $10-20 (الخيار الاحتياطي)
```

### الحالة 4: "أريد ذكاءً اصطناعيًا مجانيًا في OpenClaw"

**المشكلة:** أحتاج إلى مساعد ذكاء اصطناعي في تطبيقات المراسلة، مجانًا بالكامل

```
التوليفة: "openclaw-free"
  1. if/qwen3.8-max-preview     (وصول مجاني مُدرج؛ قد تُطبّق حدود المعدل)
  2. if/deepseek-v4-flash       (وصول مجاني مُدرج؛ قد تُطبّق حدود المعدل)
  3. if/kimi-k2.7-code          (وصول مجاني مُدرج؛ قد تُطبّق حدود المعدل)

التكلفة الشهرية: $0
الوصول عبر: WhatsApp، Telegram، Slack، Discord، iMessage، Signal...
```

## 📖 إعداد موفّري الخدمة

لإضافة اتصالات مفاتيح API بشكل جماعي من ملف CSV أو JSON، استخدم **لوحة التحكم → موفّرو الخدمة → استيراد من ملف**. تعتمد الأعمدة على ترتيبها (`provider,name,apiKey,baseUrl,priority`)؛ ويجب أن يكون `provider` موجودًا مسبقًا كموفّر خدمة مُدار أو كعقدة متوافقة. راجع [استيراد موفّري الخدمة من ملف CSV أو JSON](../providers/CSV-IMPORT.md).

### 🔐 موفّرو الاشتراكات

#### Claude Code (Pro/Max)

```bash
لوحة التحكم → موفّرو الخدمة → ربط Claude Code
→ تسجيل الدخول عبر OAuth → تحديث الرمز المميز تلقائيًا
→ تتبّع الحصة كل 5 ساعات + أسبوعيًا

النماذج:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**نصيحة احترافية:** استخدم Opus للمهام المعقدة وSonnet للسرعة. يتتبّع OmniRoute الحصة لكل نموذج!

لا يوجد متصفح على مضيف OmniRoute؟ شغّل `claude setup-token` في أي مكان تم فيه تسجيل الدخول إلى Claude Code، والصق الرمز المميز الصالح لمدة عام في علامة التبويب **رمز الإعداد**. راجع [استخدام Claude Code مع رمز إعداد](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

تحافظ مسارات Claude والمسارات المتوافقة مع Claude Code على مستوى جهد التفكير `max` لنماذج Opus وSonnet. لا تقبل نماذج Haiku مستوى الجهد `max`، لذا يخفض OmniRoute ذلك الطلب إلى ميزانية تفكير مرتفعة قبل إرساله إلى المزوّد الأساسي.

#### OpenAI Codex (Plus/Pro)

```bash
لوحة التحكم → موفّرو الخدمة → ربط Codex
→ تسجيل الدخول عبر OAuth (المنفذ 1455)
→ إعادة تعيين كل 5 ساعات + أسبوعيًا

النماذج:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
لوحة التحكم → موفّرو الخدمة → ربط GitHub
→ المصادقة عبر OAuth من خلال GitHub
→ إعادة تعيين شهرية (في اليوم الأول من الشهر)

النماذج:
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview
```

### 💰 موفّرو الخدمة منخفضو التكلفة

#### GLM-4.7 (إعادة تعيين يومية، $0.6/1M)

1. سجّل: [Zhipu AI](https://open.bigmodel.cn)
2. احصل على مفتاح API من Coding Plan
3. لوحة التحكم → إضافة مفتاح API: موفّر الخدمة: `glm`، مفتاح API: `your-key`

**الاستخدام:** `glm/glm-4.7` — **نصيحة احترافية:** توفّر Coding Plan حصة أكبر 3 مرات بتكلفة تعادل 1/7! تتم إعادة التعيين يوميًا الساعة 10:00 صباحًا.

#### MiniMax M2.1 (إعادة تعيين كل 5 ساعات، $0.20/1M)

1. سجّل: [MiniMax](https://www.minimax.io)
2. احصل على مفتاح API ← لوحة التحكم ← إضافة مفتاح API

**الاستخدام:** `minimax/MiniMax-M2.1` — **نصيحة احترافية:** الخيار الأقل تكلفة للسياق الطويل (مليون رمز مميز)!

#### Kimi K2 (سعر ثابت $9/شهريًا)

1. اشترك: [Moonshot AI](https://platform.kimi.ai?aff=omniroute)
2. احصل على مفتاح API ← لوحة التحكم ← إضافة مفتاح API

**الاستخدام:** `kimi/kimi-k2.5` — **نصيحة احترافية:** سعر ثابت قدره $9/شهريًا مقابل 10 ملايين رمز مميز = تكلفة فعلية قدرها $0.90/1M!

## 🚀 النشر

### التثبيت العام عبر npm (موصى به)

```bash
npm install -g omniroute

# إنشاء دليل الإعدادات
mkdir -p ~/.omniroute

# إنشاء ملف .env (راجع .env.example)
cp .env.example ~/.omniroute/.env

# بدء تشغيل الخادم
omniroute
# أو باستخدام منفذ مخصص:
omniroute --port 3000
```

تحمّل CLI ملف `.env` تلقائيًا من `~/.omniroute/.env` أو `./.env`.

### وضع صينية النظام

شغّل OmniRoute في صينية النظام:

```bash
omniroute serve --tray
```

ينتهي الأمر بعد أن يصبح الخادم وصينية النظام جاهزين.

يستمر الخادم في العمل من دون الطرفية.

يدعم وضع صينية النظام macOS وWindows وجلسات Linux الرسومية. لا يفتح وضع صينية النظام لوحة التحكم تلقائيًا.

استخدم قائمة صينية النظام لتنفيذ الإجراءات التالية:

- فتح لوحة التحكم.
- فتح `/dashboard/logs`.
- تغيير إعداد التشغيل التلقائي.
- إيقاف OmniRoute.

لا تستخدم `--tray` مع الخيارات التالية:

- `--daemon`
- `--log`
- `--no-recovery`

تتطلب هذه الأوضاع ملكية مختلفة للعملية.

فعّل التشغيل عند تسجيل الدخول التالي إلى الجهاز:

```bash
omniroute autostart enable
```

يستخدم التشغيل التلقائي وضع صينية النظام على macOS وWindows وجلسات Linux الرسومية. يستخدم Linux دون واجهة رسومية خدمة مستخدم systemd الحالية.

عطّل التشغيل عند تسجيل الدخول:

```bash
omniroute autostart disable
```

### متغيرات البيئة

| المتغير                                 | القيمة الافتراضية                    | الوصف                                                                                                              |
| --------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| `JWT_SECRET`                            | `omniroute-default-secret-change-me` | سر توقيع JWT (**يجب تغييره في بيئة الإنتاج**)                                                                      |
| `INITIAL_PASSWORD`                      | `CHANGEME`                           | كلمة مرور تسجيل الدخول الأول                                                                                       |
| `DATA_DIR`                              | `~/.omniroute`                       | دليل البيانات (قاعدة البيانات، والاستخدام، والسجلات)                                                               |
| `PORT`                                  | القيمة الافتراضية لإطار العمل        | منفذ الخدمة (`20128` في الأمثلة)                                                                                   |
| `HOSTNAME`                              | القيمة الافتراضية لإطار العمل        | المضيف الذي يتم الارتباط به (يستخدم Docker القيمة `0.0.0.0` افتراضيًا)                                             |
| `NODE_ENV`                              | القيمة الافتراضية لبيئة التشغيل      | اضبطه على `production` عند النشر                                                                                   |
| `NEXT_PUBLIC_BASE_URL`                  | `http://localhost:20128`             | عنوان URL الأساسي العام الذي يظهر في لوحة المعلومات ويُتاح للخادم (يحل محل `BASE_URL` القديم)                      |
| `NEXT_PUBLIC_CLOUD_URL`                 | `https://omniroute.dev`              | عنوان URL الأساسي لنقطة نهاية المزامنة السحابية (يحل محل `CLOUD_URL` القديم)                                       |
| `API_KEY_SECRET`                        | `endpoint-proxy-api-key-secret`      | سر HMAC لمفاتيح API المُنشأة                                                                                       |
| `REQUIRE_API_KEY`                       | `false`                              | فرض استخدام مفتاح API من نوع Bearer على `/v1/*`                                                                    |
| `ALLOW_API_KEY_REVEAL`                  | `false`                              | السماح لمستخدمي لوحة المعلومات المصادَق عليهم بإظهار القيم الكاملة لمفاتيح API المخزنة عند الطلب                   |
| `PROVIDER_LIMITS_SYNC_INTERVAL_MINUTES` | `70`                                 | وتيرة تحديث بيانات حدود المزوّد المخزنة مؤقتًا من جانب الخادم؛ تظل أزرار التحديث في الواجهة تشغّل المزامنة اليدوية |
| `DISABLE_SQLITE_AUTO_BACKUP`            | `false`                              | تعطيل لقطات SQLite التلقائية قبل الكتابة/الاستيراد/الاستعادة؛ تظل النسخ الاحتياطية اليدوية متاحة                   |
| `APP_LOG_TO_FILE`                       | `true`                               | تمكين إخراج سجلات التطبيق والتدقيق إلى القرص                                                                       |
| `AUTH_COOKIE_SECURE`                    | `false`                              | فرض سمة `Secure` على ملف تعريف ارتباط المصادقة (خلف وكيل عكسي يستخدم HTTPS)                                        |
| `CLOUDFLARED_BIN`                       | غير معيّن                            | استخدام ملف `cloudflared` ثنائي موجود بدلًا من التنزيل المُدار                                                     |
| `CLOUDFLARED_PROTOCOL`                  | `http2`                              | بروتوكول النقل للأنفاق السريعة المُدارة (`http2` أو `quic` أو `auto`)                                              |
| `OMNIROUTE_MEMORY_MB`                   | `512`                                | حد ذاكرة الكومة لـ Node.js بالميغابايت                                                                             |
| `PROMPT_CACHE_MAX_SIZE`                 | `50`                                 | الحد الأقصى لعدد إدخالات ذاكرة التخزين المؤقت للمطالبات                                                            |
| `SEMANTIC_CACHE_MAX_SIZE`               | `100`                                | الحد الأقصى لعدد إدخالات ذاكرة التخزين المؤقت الدلالية                                                             |

للاطلاع على المرجع الكامل لمتغيرات البيئة، راجع [README](../README.md).

## 🧩 الميزات المتقدمة

### النماذج المخصصة

أضِف أي معرّف نموذج إلى أي موفّر دون انتظار تحديث التطبيق:

```bash
# عبر API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# السرد: curl http://localhost:20128/api/provider-models?provider=openai
# الإزالة: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

أو استخدم لوحة التحكم: **الموفّرون → [الموفّر] → النماذج المخصصة**.

ملاحظات:

- يُدار OpenRouter والموفّرون المتوافقون مع OpenAI/Anthropic من قسم **النماذج المتاحة** فقط. فالإضافة اليدوية والاستيراد والمزامنة التلقائية جميعها تذهب إلى قائمة النماذج المتاحة نفسها، لذا لا يوجد قسم منفصل للنماذج المخصصة لهؤلاء الموفّرين.
- قسم **النماذج المخصصة** مخصّص للموفّرين الذين لا يوفّرون استيرادات مُدارة للنماذج المتاحة.

### موفّرون مخصصون متوافقون مع OpenAI

يمكن إضافة أي بوابة تتحدث واجهة OpenAI API (بروكسي مُستضاف ذاتيًا، vLLM، مجمِّع تابع لجهة خارجية) كعقدة موفّر خاصة بها:

1. **الموفّرون → إضافة موفّر متوافق مع OpenAI**.
2. **الاسم**: تسمية عرض للعقدة.
3. **البادئة**: اسم التوجيه. يستدعي العملاء النماذج بالشكل `<prefix>/<model>`، لذا فإن عقدة ذات بادئة `mygw` تقدّم `mygw/gpt-4o-mini`. حقل مطلوب؛ ولا يوجد أي قيد على الأحرف.
4. **نوع API**: عائلة نقاط النهاية التي تقدّمها البوابة (Chat Completions، Responses، Embeddings، الصوت، الصور).
5. **عنوان URL الأساسي**: جذر واجهة API، حتى `/v1` بما في ذلك (على سبيل المثال `https://gateway.example.com/v1`)، وليس المسار الكامل `/chat/completions`. تضبط البوابات ذات المسارات غير القياسية مساراتها ضمن **الإعدادات المتقدمة** (مسار الدردشة، مسار النماذج).
6. حقل **مفتاح API (للتحقق)** يختبر الاتصال فقط. بعد إنشاء العقدة، افتحها واستخدم **إضافة اتصال** لتخزين المفتاح الذي ستستخدمه الطلبات.

تحصل العقدة على معرّف داخلي بالشكل `openai-compatible-<apiType>-<uuid>`؛ لن تحتاج أبدًا إلى كتابته، فالبادئة هي الاسم العلني.

#### البادئات المحجوزة

لا يمكن أن تكون البادئة معرّفًا أو اسمًا مستعارًا لموفّر مدمج (على سبيل المثال `openai`، `cf`)، ولا معرّفًا لموفّر متقاعد. يتحقق محلِّل النماذج من المعرّفات والأسماء المستعارة المدمجة قبل العقد المخصصة، لذا فإن عقدة تستخدم إحدى تلك البادئات لن تستقبل أي حركة مرور أبدًا: فطلب `<prefix>/model` سيتجه إلى الموفّر المدمج بدلًا منها، أو سيفشل فشلًا مغلقًا إذا كان ذلك الموفّر متقاعدًا. يُرفض إنشاء أو تعديل عقدة بمثل هذه البادئة مع الخطأ التالي:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

اختر بادئة مميزة (`mygw`، `acme-proxy`). إذا فشلت الطلبات إلى عقدة مخصصة مع خطأ يذكر اسم موفّر مدمج أو بيانات اعتماده، فتحقق مما إذا كانت بادئة العقدة محجوزة: فالعقد المحفوظة قبل وجود هذه القاعدة ما تزال مخزّنة، لكن بادئتها توجَّه إلى الموفّر المدمج. عدِّل العقدة وامنحها بادئة جديدة.

#### خيارات البوابة لكل اتصال

تُوضع هذه المفاتيح في `providerSpecificData` الخاصة بالاتصال (على سبيل المثال عبر `PUT /api/providers/{id}`):

- `toolNameMaxLength` (عدد صحيح، 1–1024) — للاتصالات المتوافقة مع تنسيق دردشة OpenAI التي ترفض بوابتها أسماء الأدوات الطويلة. تُرسَل الأسماء الأطول كأسماء مستعارة قصيرة وتُستعاد في الاستجابة.
- `quotaEndpoint` — نقطة نهاية الحصة/الرصيد الخاصة بالبوابة، تُقرأ لشريط الحصص في لوحة التحكم وللتوجيه الواعي بالحصص. تعمل على الاتصالات المتوافقة مع كلٍّ من OpenAI وAnthropic؛ الشكل الكامل موثّق في `open-sse/services/usage/openaiCompatible.ts`.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### ربط نظراء OmniRoute

يمكن إضافة بوابة OmniRoute أخرى كموفّر **مخصص متوافق مع OpenAI**. استخدم عنوان URL الأساسي `/v1` الخاص بالنظير ومفتاح API مخصصًا بأقل الامتيازات يصدره ذلك النظير.

للسلاسل التبادلية أو متعددة القفزات، فعِّل حارس الحلقات الاختياري على كل بوابة:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

فقط الطلبات المُرسَلة إلى عنوان URL نظير مدرج صراحةً في القائمة المسموح بها تستقبل ترويسة `X-OmniRoute-Peer-Trace`. وترفض البوابة معرّف نسخة مكررًا أو ميزانية قفزات مستنفَدة مع HTTP `508 Loop Detected`؛ أما موفّرو المنبع العاديون فلا يستقبلون أي بيانات وصفية خاصة بالنظراء.

ربط النظراء ليس نسخًا متماثلًا لقاعدة البيانات ولا تبديلًا احتياطيًا للمضيف. تحتفظ كل بوابة بحالة SQLite مستقلة، وذواكر تخزين مؤقت، وعدّادات معدل، وجلسات خاصة بها. استخدم بروكسيًا عكسيًا مزوّدًا بفحص صحي أو تبديلًا احتياطيًا على جانب العميل لتحقيق توافر نشط/خامل أو نشط/نشط، ولا تُركِّب أبدًا قاعدة بيانات SQLite واحدة في عدة نسخ OmniRoute قيد التشغيل.

### Cloudflare Quick Tunnel

- متاح في **لوحة التحكم ← نقاط النهاية** لعمليات نشر Docker وغيرها من عمليات الاستضافة الذاتية
- يُنشئ عنوان URL مؤقتًا `https://*.trycloudflare.com` يُحيل إلى نقطة نهاية `/v1` الحالية المتوافقة مع OpenAI لديك
- عند التفعيل الأول، يُثبِّت `cloudflared` فقط عند الحاجة؛ وعمليات إعادة التشغيل اللاحقة تعيد استخدام نفس الملف الثنائي المُدار
- لا تتم استعادة Quick Tunnels تلقائيًا بعد إعادة تشغيل OmniRoute أو الحاوية؛ أعد تفعيلها من لوحة التحكم عند الحاجة
- عناوين URL الخاصة بالأنفاق مؤقتة وتتغير في كل مرة توقف/تشغّل فيها النفق
- تستخدم Quick Tunnels المُدارة بشكل افتراضي نقل HTTP/2 لتجنُّب تحذيرات مخزن QUIC UDP المؤقت المزعجة في الحاويات المقيَّدة الموارد
- عيِّن `CLOUDFLARED_PROTOCOL=quic` أو `auto` إذا أردت تجاوز خيار النقل المُدار
- عيِّن `CLOUDFLARED_BIN` إذا كنت تفضّل استخدام ملف ثنائي `cloudflared` مثبَّت مسبقًا بدلاً من التنزيل المُدار
- يمكن إظهار أو إخفاء لوحات Cloudflare Quick Tunnel وTailscale Funnel وngrok Tunnel في **الإعدادات ← المظهر**. إخفاء لوحة لا يوقف نفقًا قيد التشغيل.

### ذكاء بوابة LLM (المرحلة 9)

- **التخزين المؤقت الدلالي** — يخزّن تلقائيًا الاستجابات غير المتدفقة ذات temperature=0 (تجاوز ذلك عبر `X-OmniRoute-No-Cache: true`)
- **منع تكرار الطلبات** — يزيل تكرار الطلبات خلال 5 ثوانٍ عبر ترويسة `Idempotency-Key` أو `X-Request-Id`
- **تتبُّع التقدم** — أحداث SSE `event: progress` الاختيارية عبر ترويسة `X-OmniRoute-Progress: true`

### استراتيجيات التوجيه

قم بالتكوين عبر **لوحة التحكم ← الإعدادات ← التوجيه**. تعرض لوحة التحكم الاستراتيجيات الست الأكثر استخدامًا؛ بينما تدعم الكومبو والموجّه التلقائي داخليًا مجموعة أوسع.

**الاستراتيجيات المرئية في لوحة التحكم (التوجيه على مستوى الحساب):**

| الاستراتيجية             | الوصف                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------- |
| **الملء أولاً**          | يستخدم الحسابات بترتيب الأولوية — الحساب الأساسي يعالج جميع الطلبات حتى يصبح غير متاح |
| **التناوب الدائري**      | يتنقل عبر جميع الحسابات مع حد لاصق قابل للتكوين (الافتراضي: 3 استدعاءات لكل حساب)     |
| **P2C (قوة الاختيارين)** | يختار حسابين عشوائيًا ويوجّه إلى الأكثر صحة — يوازن الحمل مع الوعي بالحالة الصحية     |
| **عشوائي**               | يختار حسابًا عشوائيًا لكل طلب باستخدام خلط Fisher-Yates                               |
| **الأقل استخدامًا**      | يوجّه إلى الحساب صاحب أقدم طابع زمني `lastUsedAt`، موزِّعًا الحركة بالتساوي           |
| **مُحسَّن للتكلفة**      | يوجّه إلى الحساب ذي أدنى قيمة أولوية، مُحسِّنًا لصالح المزوّدين الأقل تكلفة           |

**استراتيجيات الكومبو والاستراتيجيات التلقائية المتقدمة** (قابلة للتكوين لكل كومبو أو عبر بادئات `auto/*` — راجع [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — ترتيب صارم، دون تناوب دائري أبدًا
- `weighted` — تقسيم الحركة تناسبيًا حسب أوزان كل نموذج
- `fill-first` — استنزاف النموذج الأول حتى بلوغ الحدود
- `round-robin` / `strict-random` / `random`
- `p2c` (قوة الاختيارين)
- `least-used` و`cost-optimized`
- `auto` — قائم على النقاط عبر جميع المرشحين
- `lkgp` (آخر مزوّد جيد معروف) — يثبّت على آخر مزوّد ناجح، ثم يعود إلى القواعد
- `context-optimized` — يختار النموذج صاحب أكبر نافذة سياق متاحة
- `context-relay` — يربط نماذج السياق الطويل تسلسليًا للأدوار اللاحقة

#### ترويسة الجلسة اللاصقة الخارجية

لتقارب الجلسات الخارجي (على سبيل المثال، وكلاء Claude Code/Codex خلف بروكسيات عكسية)، أرسل:

```http
X-Session-Id: your-session-key
```

يقبل OmniRoute أيضًا `x_session_id` ويُعيد مفتاح الجلسة الفعلي في `X-OmniRoute-Session-Id`.

إذا كنت تستخدم Nginx وترسل ترويسات بصيغة الشرطة السفلية، فعِّل:

```nginx
underscores_in_headers on;
```

#### 1. مجموعة وكيل البرمجة: استدلال عالي الأداء مع احتياطي للتكلفة/السرعة

مثالية لوكلاء البرمجة (OpenCode وClaude Code وCursor وCline). توجّه الطلبات مبدئيًا إلى نماذج الاستدلال المتقدمة، مع التبديل إلى نماذج برمجة سريعة عند استنفاد الحصة أو حدوث أخطاء.

- **لوحة التحكم**: المجموعات ← مجموعة جديدة ← الاسم: `agent-coding` ← الاستراتيجية: `Priority`
- **النماذج**:
  1. `claude/claude-sonnet-4-6` (وكيل البرمجة الأساسي)
  2. `openai/gpt-4o` (احتياطي ثانوي عالي السعة)
  3. `deepseek/deepseek-v4-flash` (احتياطي عالي الكفاءة ومنخفض التكلفة)

```bash
# مثال عبر API

  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

- **الاستراتيجية**: `Least Used` أو `Round Robin` (توزّع الحمل عبر الحصص)
- **النماذج**:
  1. `groq/llama-3.3-70b-versatile`

- **النماذج**:
  1. `gemini/gemini-2.5-pro` (فهم قوي للصور/الوسائط المتعددة)
  2. `openai/gpt-4o` (توازن بين الرؤية واستخدام الأدوات)
  3. `deepseek/deepseek-v4-flash` (توليد النصوص/التعليمات البرمجية)

### المرونة وقواطع الدائرة

التكوين عبر **لوحة التحكم ← الإعدادات ← المرونة**.

تنفّذ OmniRoute المرونة على مستوى المزود عبر خمسة مكوّنات:

1. **قائمة انتظار الطلبات وتنظيم الإيقاع** — تشكيل الطلبات على مستوى النظام:
   - **الطلبات في الدقيقة (RPM)** — الحد الأقصى للطلبات في الدقيقة لكل حساب
   - **الحد الأدنى للوقت بين الطلبات** — أصغر فجوة بالمللي ثانية بين الطلبات
   - **الحد الأقصى للطلبات المتزامنة** — الحد الأقصى للطلبات الآنية لكل حساب

2. **فترة تهدئة الاتصال** — تكوين لكل نوع مصادقة لاتصال واحد بعد حالات الفشل القابلة لإعادة المحاولة:
   - **فترة التهدئة الأساسية** — نافذة التهدئة الافتراضية لحالات فشل المنبع القابلة لإعادة المحاولة
   - **استخدام تلميحات إعادة المحاولة من المنبع** — يلتزم بتلميحات `Retry-After` الموثوقة أو تلميحات إعادة التعيين عند توفّرها
   - **الحد الأقصى لخطوات التراجع** — أقصى مستوى للتراجع الأسي عند تكرار حالات الفشل

3. **قاطع دائرة المزود** — يتتبّع حالات فشل المزود من الطرف إلى الطرف، ويوسم المزود كمتدهور عند عتبة التحذير المكوَّنة، ويفتح القاطع عند بلوغ عتبة الفشل المكوَّنة:
   - **عتبة التدهور** — عدد حالات فشل المزود المتتالية قبل الدخول في `DEGRADED`
   - **عتبة الفشل** — عدد حالات فشل المزود المتتالية قبل الدخول في `OPEN`
   - **مهلة إعادة التعيين** — النافذة الزمنية قبل اختبار المزود مجددًا
   - **CLOSED** (سليم) — تتدفّق الطلبات بشكل طبيعي
   - **DEGRADED** — تستمر الطلبات في التدفق مع تتبُّع حالات الفشل المتصاعدة
   - **OPEN** — يُحظر المزود مؤقتًا بعد حالات فشل متكررة
   - **HALF_OPEN** — اختبار ما إذا كان المزود قد تعافى

   تبقى حدود المعدل `429` الخاصة بالاتصال ضمن **فترة تهدئة الاتصال** ولا تُحتسب في قاطع المزود.

   تُعرض حالة قاطع المزود أثناء التشغيل في **لوحة التحكم ← الصحة** فقط.

4. **الانتظار حتى التهدئة** — إذا كانت جميع الاتصالات المرشّحة في فترة تهدئة بالفعل، يمكن لـ OmniRoute انتظار أقرب تهدئة وإعادة طلب العميل نفسه تلقائيًا.

5. **الاكتشاف التلقائي لحد المعدل** — عندما يعيد مزوّدو المنبع نوافذ انتظار صريحة، تتجاوز تلك التلميحات فترة تهدئة الاتصال المحلية عند تمكين هذا الإعداد.

**نصيحة احترافية:** استخدم صفحة **الصحة** لفحص قواطع المزود الحية وإعادة تعيينها بعد انقطاع. صفحة المرونة تغيّر التكوين فقط.

### تصدير / استيراد قاعدة البيانات

إدارة النسخ الاحتياطية لقاعدة البيانات في **لوحة التحكم ← الإعدادات ← النظام والتخزين**.

| الإجراء                    | الوصف                                                                                                                                        |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **تصدير قاعدة البيانات**   | تنزيل قاعدة بيانات SQLite الحالية كملف `.sqlite`                                                                                             |
| **تصدير الكل (.tar.gz)**   | تنزيل أرشيف نسخة احتياطية كامل يتضمن: قاعدة البيانات، الإعدادات، المجموعات، اتصالات المزود (دون بيانات اعتماد)، البيانات الوصفية لمفاتيح API |
| **استيراد قاعدة البيانات** | رفع ملف `.sqlite` لاستبدال قاعدة البيانات الحالية. تُنشأ نسخة احتياطية قبل الاستيراد تلقائيًا ما لم يُضبط `DISABLE_SQLITE_AUTO_BACKUP=true`  |

```bash
# API: تصدير قاعدة البيانات
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: تصدير الكل (الأرشيف الكامل)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: استيراد قاعدة البيانات
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**التحقق من الاستيراد:** يُتحقق من الملف المستورد من حيث السلامة (فحص pragma في SQLite)، والجداول المطلوبة (`provider_connections` و`provider_nodes` و`combos` و`api_keys`)، والحجم (بحد أقصى 100 ميغابايت).

**حالات الاستخدام:**

- ترحيل OmniRoute بين الأجهزة
- إنشاء نسخ احتياطية خارجية للتعافي من الكوارث
- مشاركة التكوينات بين أعضاء الفريق (تصدير الكل ← مشاركة الأرشيف)

### لوحة الإعدادات

صفحة الإعدادات منظَّمة في **7 علامات تبويب** لتسهيل التنقل:

| التبويب              | المحتويات                                                                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **عام**              | أدوات تخزين النظام، السلوك الافتراضي، إظهار أنفاق نقاط النهاية (Endpoint)                                                                                                                        |
| **المظهر**           | أدوات التحكم في السمة (فاتح/داكن/النظام)، إظهار الشريط الجانبي، مفاتيح تبديل اللوحات لبطاقات أنفاق Cloudflare/Tailscale/ngrok                                                                    |
| **الذكاء الاصطناعي** | ميزانية التفكير (passthrough / auto-strip / custom / adaptive — راجع [THINKING_BUDGET.md](./THINKING_BUDGET.md))، موجه النظام العام، إحصاءات ذاكرة التخزين المؤقت للموجهات                       |
| **الأمان**           | إعدادات تسجيل الدخول/كلمة المرور، التحكم في الوصول عبر IP، مصادقة API لـ `/models`، حظر المزودين، الحماية من حقن الموجهات                                                                        |
| **التوجيه**          | استراتيجية التوجيه العامة (Fill First / Round Robin / P2C / Random / Least Used / Cost Optimized)، الأسماء المستعارة للنماذج بأحرف البدل، سلاسل الرجوع الاحتياطي، الإعدادات الافتراضية للمجموعات |
| **المرونة**          | قائمة انتظار الطلبات، فترة تهدئة الاتصال، إعداد قاطع المزود، وسلوك انتظار التهدئة                                                                                                                |
| **متقدم**            | إعداد البروكسي العام (HTTP/SOCKS5)، وتجاوزات البروكسي لكل مزود                                                                                                                                   |

لم يعد تبويب "عام" يكرر ملاحظات التسجيل وذاكرة التخزين المؤقت للقراءة فقط. يتم حفظ إعدادات
الاحتفاظ بقاعدة البيانات وتحسينها عبر `/api/settings/database`؛ أما مسح ذاكرة التخزين المؤقت
يدويًا فيستخدم `DELETE /api/cache`. يتم التحكم في حدود صفوف سجلات الطلبات وسجلات البروكسي عبر
`CALL_LOGS_TABLE_MAX_ROWS` و`PROXY_LOGS_TABLE_MAX_ROWS`.

### استراتيجيات موازنة المجموعات (Combo)

قم بتكوين الموازنة لكل مجموعة في **لوحة المعلومات ← المجموعات ← إنشاء/تعديل ← الاستراتيجية**.

| الاستراتيجية       | الوصف                                                                     |
| ------------------ | ------------------------------------------------------------------------- |
| **Round-Robin**    | يتناوب على النماذج بالتتابع                                               |
| **Priority**       | يحاول دائمًا النموذج الأول؛ ولا يرجع إلى الاحتياطي إلا عند حدوث خطأ       |
| **Random**         | يختار نموذجًا عشوائيًا من المجموعة لكل طلب                                |
| **Weighted**       | يوجه بشكل متناسب بناءً على الأوزان المخصصة لكل نموذج                      |
| **Least-Used**     | يوجه إلى النموذج صاحب أقل عدد من الطلبات الحديثة (يستخدم مقاييس المجموعة) |
| **Cost-Optimized** | يوجه إلى أرخص نموذج متاح (يستخدم جدول التسعير)                            |

يمكن تعيين الإعدادات الافتراضية العامة للمجموعات في **لوحة المعلومات ← الإعدادات ← التوجيه ← الإعدادات الافتراضية للمجموعات**.
ترث مهلات أهداف المجموعة مهلة الطلب الحالية افتراضيًا. استخدم **مهلة الهدف
(بالثواني)** في الإعدادات الافتراضية للمجموعات أو في مجموعة فردية فقط عندما يجب أن يؤدي
حد أقصر لكل هدف إلى تسريع الرجوع الاحتياطي.

تحسينات المجموعات صفرية زمن الاستجابة اختيارية (opt-in). اترك **تحسينات زمن الاستجابة الصفري**
معطلة لمنع ميزات زمن الاستجابة هذه من منافسة الأهداف الاحتياطية، أو تخطي الأهداف بناءً على
سجل TTFT، أو ضغط الطلبات الاحتياطية؛ أما تفعيلها فيسمح للتحوط المُكوَّن (hedging)، وتخطيات
TTFT التنبؤية، وضغط الرجوع الاحتياطي الاستباقي بمقايضة دقة التوجيه/الطلب مقابل
زمن استجابة أدنى عند الذيل (tail latency).

عطّل **مخزن رموز الاستدلال المؤقت** عندما تتطلب جهات التزويد في المنبع حدودًا صارمة لـ
`max_tokens` / `maxOutputTokens`. عند تمكينه، لا يضيف التوجيه المركّب سعةً احتياطية لنماذج
الاستدلال إلا للنماذج ذات الحد الأقصى المعروف للمخرجات، ويترك حد رموز العميل دون تغيير عندما
تتجاوز القيمة المخزّنة الآمنة ذلك الحد الأقصى. وإذا كان حد العميل أعلى أصلًا من حد أقصى معروف،
فإن OmniRoute يُخفِضه إلى ذلك الحد الأقصى قبل إرسال الطلب إلى المنبع.

### لوحة معلومات الصحة

يمكن الوصول إليها عبر **لوحة التحكم → الصحة**. نظرة عامة على صحة النظام في الوقت الفعلي مع 6 بطاقات:

| البطاقة                            | ما تعرضه                                                                    |
| ---------------------------------- | --------------------------------------------------------------------------- |
| **حالة النظام**                    | مدة التشغيل، الإصدار، استخدام الذاكرة، دليل البيانات                        |
| **صحة المزوّدات**                  | حالة التشغيل العامة لقاطع الدائرة الخاص بالمزوّدات                          |
| **حدود المعدل**                    | فترات تهدئة الاتصالات النشطة لكل حساب مع الوقت المتبقي                      |
| **عمليات الحظر النشطة**            | عمليات الحظر النشطة على مستوى النموذج والاستبعادات المؤقتة                  |
| **ذاكرة التخزين المؤقت للتوقيعات** | إحصاءات ذاكرة التخزين المؤقت لإزالة التكرار (المفاتيح النشطة، معدل الإصابة) |
| **قياس زمن الاستجابة**             | تجميع زمن الاستجابة p50/p95/p99 لكل مزوّد                                   |

**نصيحة احترافية:** تُحدِّث صفحة الصحة نفسها تلقائيًا كل 10 ثوانٍ. استخدم بطاقة قاطع الدائرة لتحديد المزوّدين الذين يواجهون مشكلات.

## 🤖 التوجيه التلقائي (دون إعداد)

يأتي OmniRoute مزودًا **بموجّه تلقائي قائم على الدرجات** يختار أفضل نموذج لكل طلب عبر جميع المزوّدين المتصلين — دون الحاجة إلى صيانة أي تركيبة. ما عليك سوى إرسال الطلب باستخدام إحدى بادئات `auto/*`، وسيُنشئ OmniRoute تركيبة افتراضية ديناميكيًا، مع تقييم المرشحين بناءً على زمن الاستجابة والتكلفة ومعدل النجاح وملاءمة السياق ومدى ملاءمة النموذج للمهمة والإخفاقات الأخيرة والحصة وحالة قاطع الدائرة.

| البادئة        | ما تعمل على تحسينه                                                                       |
| -------------- | ---------------------------------------------------------------------------------------- |
| `auto`         | الإعداد الافتراضي المتوازن (زمن الاستجابة × التكلفة × معدل النجاح)                       |
| `auto/coding`  | مهام البرمجة: يفضّل Claude وGPT-5 وGLM وKimi وQwen Coder ونماذج DeepSeek البرمجية        |
| `auto/cheap`   | أقل تكلفة لكل رمز، مع قبول زمن استجابة أعلى                                              |
| `auto/fast`    | أقل زمن استجابة، مع تجاهل التكلفة                                                        |
| `auto/offline` | المزوّدون المحليون فقط (Ollama وvLLM وllama.cpp) — مفيد للبيئات المعزولة عن الشبكة       |
| `auto/smart`   | جودة الاستدلال أولًا (Opus وGPT-5 xhigh وR1 واستدلال GLM 5.1)                            |
| `auto/lkgp`    | "آخر مزوّد معروف بأنه يعمل جيدًا" — يثبّت آخر مزوّد ناجح، ثم يعود إلى القواعد عند الحاجة |

مثال:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

يُشرَح الموجّه التلقائي بالكامل في [AUTO-COMBO.md](../routing/AUTO-COMBO.md) — بما في ذلك كيفية ضبط أوزان التقييم، وإدراج المزوّدين في القائمة السوداء، وفحص قرارات التوجيه ضمن **لوحة المعلومات → التركيبة التلقائية**.

## 🔌 تكامل MCP وA2A

يعمل OmniRoute بوصفه **خادم MCP** (بروتوكول سياق النموذج) و**خادم A2A** (اتصال وكيل إلى وكيل باستخدام JSON-RPC 2.0). يمكن لأي بيئة تطوير متكاملة أو مضيف وكيل متوافق مع MCP استدعاء أدوات OmniRoute مباشرةً — دون الحاجة إلى غلاف إضافي.

### وسائل نقل MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP القابل للبث**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (لملحقات بيئات التطوير المتكاملة التي تفضّل stdio)

### توصيل Claude Desktop

حرّر `~/Library/Application Support/Claude/claude_desktop_config.json` على macOS أو الملف المكافئ على Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### توصيل Cursor / Continue / VS Code MCP

استخدم عنوان URL الخاص بـSSE، وهو `http://localhost:20128/api/mcp/sse`، ومفتاح واجهة API من نوع Bearer تم إنشاؤه ضمن **لوحة المعلومات → مفاتيح API**.

### النطاقات

يعرّف MCP حاليًا 32 نطاقًا مسمّى. يمكن تقييد كل مفتاح Bearer بنطاقات محددة — راجع [MCP-SERVER.md](../frameworks/MCP-SERVER.md) للاطلاع على القائمة المرجعية للنطاقات والأدوات، و[A2A-SERVER.md](../frameworks/A2A-SERVER.md) للاطلاع على مخطط JSON-RPC.

## 🧠 نظام المهارات

يوفّر OmniRoute **إطار عمل قابلًا للتوسعة للمهارات** (`src/lib/skills/`) كي تتمكن الوكلاء ونقطة نهاية A2A من تشغيل إجراءات خاصة بمجالات محددة (مثل `code-review` و`summarize` و`extract-facts` و`web-research`).

- **واجهة سوق المهارات** — تصفّح المهارات وثبّتها من **لوحة التحكم → المهارات**
- **نطاقات مخصّصة لكل مفتاح** — قيّد المهارات التي يمكن لكل مفتاح API استدعاؤها
- **مهارات مخصّصة** — ضع ملف TypeScript في `src/lib/a2a/skills/`، وسجّله، وسيصبح قابلًا للاستدعاء فورًا عبر A2A

المرجع الكامل: [SKILLS.md](../frameworks/SKILLS.md).

## 💾 نظام الذاكرة

يحتفظ OmniRoute **بذاكرة محادثات طويلة الأمد** باستخدام استرجاع هجين:

- **SQLite FTS5** للبحث بالكلمات المفتاحية في التفاعلات السابقة
- **مخزن Qdrant للمتجهات** (اختياري) للاسترجاع الدلالي
- **استخراج تلقائي للحقائق** — تُلخّص الكيانات والتفضيلات والقرارات بعد كل جلسة وتُخزّن في جدول `memory_facts`
- تُعزل الذكريات حسب كل مفتاح API وكل جلسة

أدِر الذكريات من **لوحة التحكم → الذاكرة** (البحث والتعديل والتصدير والحذف النهائي). تتيح واجهة HTTP (`/api/memory/*`) للوكلاء إرسال الحقائق والاستعلام عنها برمجيًا — راجع [MEMORY.md](../frameworks/MEMORY.md).

## 🔔 خطافات الويب

اشترك في أحداث OmniRoute للمراقبة والأتمتة في الوقت الفعلي.

- أنشئ خطاف ويب في **لوحة التحكم → خطافات الويب** مع عنوان URL المستهدف وسر توقيع HMAC
- الأحداث المتاحة: `request.completed` و`request.failed` و`provider.unavailable` و`budget.exceeded` و`combo.switched` و`circuit_breaker.opened` و`circuit_breaker.closed`
- تتضمن كل حمولة `X-OmniRoute-Signature` ‏(HMAC-SHA256) للتحقق
- إعادة المحاولة: 3 محاولات مع تراجع أُسّي، ثم النقل إلى قائمة الرسائل غير القابلة للتسليم

المخطط الكامل في [WEBHOOKS.md](../frameworks/WEBHOOKS.md).

## 🛠️ الإدارة البرمجية

يمكنك إدارة كل مورد في OmniRoute (المزوّدون والمجموعات والمفاتيح والإعدادات) عبر HTTP باستخدام **مفتاح Bearer ذي النطاق `manage`**.

أنشئ المفتاح في **لوحة التحكم → مفاتيح API → مفتاح جديد → النطاق: manage**، ثم:

```bash
# سرد المزوّدين
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# إضافة اتصال بمزوّد
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# إنشاء مجموعة
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# سرد/إنشاء مفاتيح API
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

راجع [API_REFERENCE.md](../reference/API_REFERENCE.md) للاطلاع على الكتالوج الكامل لنقاط النهاية ومخططات الطلبات/الاستجابات.

## 💻 واجهة سطر الأوامر الداخلية

يتضمن OmniRoute واجهة سطر أوامر داخلية (`omniroute …`) للإعداد والتشخيص والتحكم في وقت التشغيل. وهي **منفصلة عن صفحة "أدوات سطر الأوامر" في لوحة التحكم**، التي تهيئ أدوات سطر أوامر تابعة لجهات خارجية (Claude Code وCursor وCodex وCline و…) لكي تتمكن من الاتصال بـ OmniRoute.

```bash
omniroute setup                    # معالج تفاعلي (كلمة المرور، والموفرون، والتركيبات)
omniroute setup --non-interactive  # ملائم لبيئات CI
omniroute doctor                   # تشخيصات السلامة (دليل البيانات، وقاعدة البيانات، والموفرون، والمنافذ)
omniroute providers available      # عرض الموفرين المدعومين
omniroute providers list           # عرض الاتصالات المهيأة
omniroute providers test <id>      # اختبار اتصال بموفر مباشرةً
omniroute combos list              # عرض التركيبات
omniroute combos switch <name>     # تعيين التركيبة الافتراضية
omniroute models                   # عرض النماذج المتاحة (--json، --search)
omniroute keys add | list | remove # إدارة مفاتيح API من الطرفية
omniroute backup                   # إنشاء لقطة للإعدادات وقاعدة البيانات
omniroute restore [<timestamp>]    # الاستعادة من لقطة
omniroute health                   # تفاصيل السلامة (قواطع الدارة، وذاكرة التخزين المؤقت، والذاكرة)
omniroute quota                    # استخدام حصة الموفر
omniroute mcp status               # حالة خادم MCP
omniroute a2a status               # حالة خادم A2A
omniroute tunnel list|create|stop  # أنفاق Cloudflare/Tailscale/ngrok
omniroute reset-password           # إعادة تعيين كلمة مرور المسؤول
omniroute --mcp                    # تشغيل خادم MCP عبر stdio
omniroute --port 3000              # تشغيل الخادم على منفذ مخصص
```

نصيحة: استخدم `omniroute doctor --json` مع أداة المراقبة لديك لإصدار تنبيهات عند وجود اتصالات غير سليمة بالموفرين.

## 🖥️ تطبيق سطح المكتب (Electron)

يتوفر OmniRoute كتطبيق أصلي لسطح المكتب لأنظمة Windows وmacOS وLinux.

### التثبيت

```bash
# من دليل electron:
cd electron
npm install

# وضع التطوير (الاتصال بخادم تطوير Next.js قيد التشغيل):
npm run dev

# وضع الإنتاج (يستخدم إصدارًا مستقلًا):
npm start
```

### إنشاء حزم التثبيت

```bash
cd electron
npm run build          # المنصة الحالية
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg عام)
npm run build:linux    # Linux (.AppImage)
```

المخرجات ← `electron/dist-electron/`

### الميزات الرئيسية

| الميزة                 | الوصف                                                        |
| ---------------------- | ------------------------------------------------------------ |
| **جاهزية الخادم**      | يستطلع الخادم قبل إظهار النافذة (من دون شاشة فارغة)          |
| **علبة النظام**        | التصغير إلى العلبة، وتغيير المنفذ، والخروج من قائمة العلبة   |
| **إدارة المنافذ**      | تغيير منفذ الخادم من العلبة (مع إعادة تشغيل الخادم تلقائيًا) |
| **سياسة أمان المحتوى** | سياسة CSP مقيّدة عبر ترويسات الجلسة                          |
| **نسخة واحدة**         | لا يمكن تشغيل أكثر من نسخة واحدة من التطبيق في الوقت نفسه    |
| **وضع عدم الاتصال**    | يعمل خادم Next.js المضمّن من دون اتصال بالإنترنت             |

### متغيرات البيئة

| المتغير               | القيمة الافتراضية | الوصف                                     |
| --------------------- | ----------------- | ----------------------------------------- |
| `OMNIROUTE_PORT`      | `20128`           | منفذ الخادم                               |
| `OMNIROUTE_MEMORY_MB` | `512`             | حد ذاكرة الكومة لـ Node.js ‏(64–16384 MB) |
