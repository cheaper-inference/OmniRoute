يعلن عقد `config/cli-tools-manifest.json` المحايد عن IDs الأساسي والأسماء المستعارة والمرشحات الثنائية ووصفات الإعداد والوسائط النموذجية والقدرات. يقرأ محول العقدة العادي في `bin/cli/cli-manifest.mjs` ومحول TypeScript في `src/shared/constants/cliIntegrationManifest.ts` نفس الملف. يتم التحقق من وقت التشغيل والكتالوج والتكوين والإكمال والمولدات وتسجيل الواجهة الخلفية معًا بواسطة `tests/unit/cli/cli-manifest-drift.test.ts`. لا يعني الفهرسة أنه يمكن تشغيل الأداة أو تكوينها. على وجه الخصوص، يبقى 5dive للتكوين فقط.

## بيئة الطفل ودورة حياته

يرث `omniroute run` و `omniroute launch` و `omniroute launch-codex` القائمة المسموح بها لتوافق OS/terminal ويدخلون بيانات اعتماد الهدف المحدد. لا يتم توريث أسرار الموفر وقاعدة البيانات غير ذات الصلة بشكل افتراضي. يستعيد `--inherit-env` بشكل صريح الوراثة الكاملة للبيئة الأصلية؛ استخدمه فقط عندما تتلقى عملية الطرف الثالث المحددة هذه القيم. هذا هو تصفية البيئة، وليس وضع الحماية OS : لا تزال العملية تعمل بأذونات نظام ملفات المتصل.

يتم إرسال إشارات المقاطعة والإنهاء إلى الطفل. ينتظر المشغل الحدث الوثيق للطفل قبل إزالة التكوين المؤقت. تتحكم `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` في فترة السماح قبل الإنهاء القسري (الافتراضي 5000 مللي ثانية).

يتبع `omniroute launch <tool>` (انظر [LAUNCH.md](./LAUNCH.md) ) نفس قواعد البيئة وإعادة توجيه الإشارة، ويضيف:

- **بوابة التشغيل التلقائي.** بالنسبة لهدف محلي، عندما لا تستجيب أي بوابة على المنفذ، يبدأ المشغل `omniroute serve --headless --no-open` المرتبط بـ `127.0.0.1` في إطار عملية حصادة منفصلة. كل عملية إطلاق جارية تحمل عقد إيجار بـ `DATA_DIR/launch/leases/` (نبضات القلب كل 15 ثانية، قديمة بعد 45 ثانية أو عند انتهاء عمليتها). يقوم الحاصد بإيقاف البوابة التي بدأها بمجرد عدم تفعيل عقد الإيجار لفترة الخمول (`OMNIROUTE_LAUNCH_IDLE_GRACE_MS`، الافتراضي 10000 مللي ثانية). يتم استخدام البوابة التي بدأها المستخدم ولكنها لم تتوقف مطلقًا. يقوم `--keep-gateway` أو `omniroute gateway keep` بتحويل بوابة المشغل إلى بوابة عادية؛ يستعيد `--no-start` سلوك الفشل القديم. يتم فحص الأهداف البعيدة فقط.
- **إطلاق الجلسات.** كل إطلاق يصدر رمزًا مميزًا لجلسة `olx_` قصيرة العمر من بيانات الاعتماد الأصلية (`POST /api/launch/sessions`)، وينبض به أثناء تشغيل الأداة، ويقرأ ملخص الاستخدام ويبطله بعد خروج الأداة. الرمز المميز عبارة عن مجموعة فرعية صارمة من أصله: نفس الأذونات، ونفس الكتالوج أو أضيق، وعمره أقصر، وهو ليس بيانات اعتماد لوحة المعلومات. تتلقى الأداة رمز الجلسة، وليس بيانات الاعتماد الأصلية أبدًا، ويتم وضع علامة على الطلبات `launch:<tool>:<sessionId>` ما لم يتم إعطاء `--tag`. تفشل البوابة التي لا تحتوي على الجلسة API مع `GatewayTooOld` بدلاً من الرجوع إلى الإطلاق غير المشمول.
- **التكوين لكل إطلاق.** تتم كتابة ملفات تكوين الأداة إلى دليل مؤقت خاص (الوضع 0700، البادئة `omnirouter-`) وإزالتها بعد خروج الطفل. يترك `SIGKILL` للمشغل الدليل خلفه؛ تقوم `omniroute launch --cleanup` بإزالة هذه الدلائل بمجرد مرور أكثر من يوم واحد عليها.

## Gemini الإعداد المستمر

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

يقوم الأمران الأولان بتكوين هذا الجهاز للخادم المحلي أو البعيد المحدد. يحتفظ برنامج الإعداد بإعدادات JSON غير ذات الصلة، ويحدد مصادقة مفتاح Gemini API، ويكتب نقطة النهاية وبيانات الاعتماد في ملف `.gemini/.env` خاص. يرفض JSON غير صالح بدلاً من الكتابة فوقه. يجب أن تكون نقطة النهاية URLs هي HTTP(S)، بدون بيانات اعتماد مضمنة أو معلمات استعلام أو أجزاء. يطبع التشغيل الجاف المسارات، وليس قيم بيانات الاعتماد.

`GEMINI_CLI_HOME` أو `--gemini-home` يحدد جذر المنزل المستمر. يقوم `run gemini` الفعلي بإنشاء منزله المؤقت وإزالته لاحقًا. لا يتجاوز أي من الوضعين عمليات التحقق من الثقة في مساحة عمل Gemini.

## الملفات الشخصية Codex

`configure codex` يكتب `<name>.config.toml` خاص مع نموذج ونقطة نهاية موفر OmniRoute الخاص به. تتم الإشارة إلى بيانات الاعتماد من خلال `OMNIROUTE_API_KEY`، ولا يتم تضمينها أبدًا. يقوم أمر التشغيل بتعيين النموذج المحدد على مفتاح `model` ذو المستوى الأعلى، وليس داخل `model_providers`.

ملفات التعريف المنفصلة هي عقد Codex الموثق الحالي؛ يقومون بتراكب تكوين المستخدم عند تحديده باستخدام `codex --profile <name>`. راجع [مرجع الملف الشخصي الرسمي](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) [ودليل OmniRoute Codex](./CODEX-CLI-CONFIGURATION.md).

## تنفيذ الأمر المحكم

باستخدام `DATA_DIR` الصريح، يمنع إعداد `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` بدء التشغيل من الوصول إلى بيئة بيانات اعتماد دليل بيانات المستخدم الافتراضية. وهذا مفيد للاختبارات المعزولة. ولا يقوم بتعطيل ملفات البيئة الأخرى المحددة بشكل صريح.

## دليل العمل `.env`

يقرأ CLI ملفات `.env` بهذا الترتيب، ويفوز الملف الأول الذي يقوم بتعيين مفتاح: `DATA_DIR` الصريح، ودليل البيانات الافتراضي، ودليل العمل الحالي، ثم دليل الحزمة. متغيرات Shell تفوز دائمًا.

قد ينتمي دليل العمل إلى شخص آخر (مستودع مستنسخ، أرشيف غير مضغوط)، ويقوم `omniroute serve` بتمرير بيئة CLI إلى الخادم وإلى كل أداة يقوم الخادم بتشغيلها. لذلك قد يقوم `.env` هناك بتعيين هذه المفاتيح المدرجة في `bin/cli/utils/untrustedCwdEnv.mjs` فقط:

| مفتاح                           | القيم المقبولة                                                               |
| ------------------------------- | ---------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true` أو `1` أو `yes` على أي حال، القيم التي يعاملها الخادم على أنها موجودة |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | ما يصل إلى 64 حرفًا أو رقمًا `_` أو `.` أو `@` أو `-`                        |
| `LANGUAGE`                      | نفسه، بالإضافة إلى `:`                                                       |
| `TZ`                            | ما يصل إلى 64 حرفًا أو رقمًا أو `_` أو `+` أو `-` أو `/`، ولا يبدأ بـ `/`    |
| `NO_COLOR`, `FORCE_COLOR`       | ما يصل إلى 16 حرفًا ورقمًا                                                   |

كل قيمة يقبلها `REQUIRE_API_KEY` تؤدي إلى تشغيل الفحص، لذلك لا يمكن للملف إيقاف تشغيل الفحص نفسه. ومع ذلك، فهو لا يقرر النتيجة: يقرأ الخادم تجاوز `REQUIRE_API_KEY` المخزن في قاعدة البيانات قبل البيئة، بينما يقرأ تحذير بدء التشغيل بشأن الاستماع على جميع الواجهات بدون مفتاح API البيئة فقط. مع التجاوز المخزن لـ `false`، يترك دليل العمل `REQUIRE_API_KEY=true` API مفتوحًا ويخفي هذا التحذير. قاعدة `TZ` أضيق من POSIX: فهي ترفض `.` و `:` و `,` و `<>`، لذلك يجب تعيين شكل `:Area/City` وقواعد مثل `EST5EDT,M3.2.0,M11.1.0` في الصدفة أو في `<DATA_DIR>/.env`.

يجب أن تتطابق الأسماء تمامًا، بالأحرف الكبيرة. يتم تخطي أي سطر آخر، والقيمة التي تفشل في التحقق منها، والاسم الذي لا يتكون من أحرف ASCII العادية والأرقام و `_` (على سبيل المثال، اسم يحتوي على بايت NUL أو حرف مشابه). يطبع CLI تحذيرًا واحدًا يُسمي المفاتيح التي لا يمكنه تعيينها، وواحدًا يُسمي المفاتيح المسموح بها التي تجاهلها، مع كل ما يجب تغييره (`TZ (expected a zone name such as Europe/Berlin)`، `lang (write the name as LANG)`). ولا يطبع أي منهما القيم. يتم تخطي مسارات الملفات في هذه الرسائل وتقارير مسار `.env` `omniroute doctor` عندما تحتوي على أحرف تحكم أو ثنائية الاتجاه. لا يتم تطبيق التقييد عندما يكون دليل العمل هو دليل البيانات أو دليل الحزمة.

`PORT` و `API_PORT` و `DASHBOARD_PORT` غير موجودة في القائمة. بدون URL أساسي من مصدر ذي أسبقية أعلى، يتحدث CLI إلى `localhost:<PORT>`، وأي شخص يستمع هناك يتلقى مفتاح CLI الخاص بـ API ورمز السياق ورمز جهاز CLI (`x-omniroute-cli-token`، راجع [CLI_TOKEN.md](../security/CLI_TOKEN.md) ) ، والذي يقبله الخادم المحلي لاستدعاءات الإدارة من الاسترجاع. سيسمح منفذ من دليل العمل لهذا الملف باختيار المستمع، لذا قم بتعيين المنافذ في الصدفة، في `<DATA_DIR>/.env` أو باستخدام خيار `--port` للأوامر التي تحتوي على واحد (`serve`, `launch`, `run`).

لا يحتوي المحلل اللغوي على بناء جملة `export`. سطر مثل `export LD_PRELOAD=...` يسمي المتغير `export LD_PRELOAD`؛ يتم تخطيه من دليل العمل، وفي ملفات `.env` الأخرى، يتم تعيين الاسم الحرفي الذي لا يقرأه شيء.

يقوم CLI بإقران الرمز المميز المخزن للسياق (رمز الوصول أو مفتاح API القديم) فقط مع أصل هذا السياق: المخطط والمضيف والمنفذ، مقارنة بـ `URL.origin`. ينطبق هذا على الطلبات المقدمة من خلال عميل CLI's HTTP (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) وعلى أوامر `launch` و `launch codex` و `configure` و `setup-*` التي تكتب URL أساسي ومفتاح في تكوين أداة أخرى. يشيرون إلى خادم آخر باستخدام `--remote`، ويستخدمون `--api-key` أو `OMNIROUTE_API_KEY` صريحًا إذا تم تعيينه، ولا يوجد رمز مميز للسياق. المقارنة دقيقة، لذا فإن `localhost` و `127.0.0.1` أو مضيف بنقطة زائدة أو بدونها، يتم اعتبارهما خوادم مختلفة ولا يحصلان على رمز مميز للسياق. لا تتطابق وحدات URL التي تحتوي على معلومات المستخدم أو الشرطة المائلة العكسية أو المسافة البيضاء أبدًا، لأن محللي URL الآخرين (على سبيل المثال، `urllib` و `httpx` في بايثون) يمكنهم قراءة مضيف مختلف منها. بالنسبة للطلبات التي يرسلها CLI بنفسه، فإن هذا الفحص يغطي فقط المخطط والسلطة، لذلك يحتفظ المعرف الذي يحتوي على مسافة في المسار أو الاستعلام بالرمز المميز.
