> **باختصار**: يصنّف OmniRoute مزوّديه **المجانيين** حسب جودة النماذج باستخدام **درجات ELO الخاصة بـ Arena AI
> (على غرار LMArena)**. افتح صفحة **تصنيفات المزوّدين المجانيين** في
> لوحة المعلومات لمعرفة المزوّدين المجانيين الذين يوفّرون أقوى النماذج لمهمتك —
> إجمالًا، أو بعد التصفية حسب الفئة (البرمجة، المراجعة، التوثيق، تصحيح الأخطاء).

---

## ما هو؟

تسجل OmniRoute 377 مزودًا، بما في ذلك 155 إدخالًا للكتالوج تم وضع علامة عليها**free/no-auth** (بدون مصادقة، أو مفتاح OAuth ذو الطبقة المجانية، أو مفتاح API ذو الطبقة المجانية - راجع [دليل المستويات المجانية](../getting-started/FREE-TIERS-GUIDE.md) [ودليل الطبقات المجانية](../reference/FREE_TIERS.md) الكامل). المصيد: يختلف مقدمو الخدمة المجانية بشكل كبير في جودة النموذج. يعد موفر عدم المصادقة الذي يخدم نموذجًا حدوديًا أكثر فائدة بكثير من موفر يخدم نموذجًا قديمًا صغيرًا.

**تصنيفات المزودين المجانية** الإجابات "** ما هو المزود المجاني الذي يمنحني أفضل نموذج؟** " من خلال الانضمام إلى كتالوج كل مزود مجاني مع** درجات الجودة من مصادر جماهيرية** من** الساحة AI المتصدرين** (التفضيل البشري ELO، نفس الفكرة وراء ساحة الدردشة الآلية LMArena). يتم بعد ذلك تصنيف مقدمي الخدمة حسب قوة خدماتهم** أفضل نموذج مجاني** .

يتم حساب الترتيب من ثلاثة مصادر حقيقية:

1. يسرد الموفر المجاني — `NOAUTH_PROVIDERS`، بالإضافة إلى إدخالات `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` التي تم وضع علامة عليها `hasFree` (`src/shared/constants/providers.ts`).
2. كتالوج نموذج كل موفر من سجل الموفر (`open-sse/config/providerRegistry.ts`).
3. تم تخزين نتائج ملائمة المهام المشتقة من ELO في جدول `model_intelligence` DB بواسطة محرك مزامنة Arena ELO (`src/lib/arenaEloSync.ts`).

منطق الانضمام يعيش في `src/lib/freeProviderRankings.ts`.

## كيفية الوصول

### صفحة لوحة المعلومات

افتح لوحة المعلومات وانتقل إلى **التكاليف ← تصنيفات المزوّدين المجانيين**، أو انتقل مباشرةً إلى:

```
/dashboard/free-provider-rankings
```

تعرض الصفحة (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) ما يلي:

- **منصة لأفضل 3 مزوّدين** (🥇 🥈 🥉) من المزوّدين المجانيين الأعلى تصنيفًا.
- **جدول تصنيف** كاملًا بالأعمدة: **الترتيب**، **المزوّد**، **أفضل نموذج**،
  **الدرجة**، **متوسط الدرجة**، **النماذج**، **النوع**.
- **أزرار تصفية الفئات**: _كل الفئات_، _الافتراضي_، _البرمجة_، _المراجعة_،
  _التوثيق_، _تصحيح الأخطاء_.

توضّح شارة **النوع** الخاصة بكل مزوّد كيفية إتاحته مجانًا:

| الشارة   | المعنى                                             |
| -------- | -------------------------------------------------- |
| `NOAUTH` | مجاني دائمًا، ولا يتطلب بيانات اعتماد              |
| `OAUTH`  | مزوّد OAuth لديه فئة مجانية (`hasFree`)            |
| `APIKEY` | مزوّد يعتمد مفتاح API ولديه فئة مجانية (`hasFree`) |

تُعرض الدرجات في صورة تسميات سهلة القراءة (مثل _نخبوي_، _ممتاز_، _جيد جدًا_،
_جيد_، _متوسط_) بدلًا من أرقام أولية، لأن القيمة الأساسية تعبّر عن جودة
تصنيف نسبية، وليست نسبة مئوية.

### نقطة نهاية API

تعتمد الصفحة على نقطة نهاية عامة للقراءة
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

معاملات الاستعلام (يتم التحقق منها باستخدام Zod):

| المعامل    | النوع  | الافتراضي | ملاحظات                                                                                                   |
| ---------- | ------ | --------- | --------------------------------------------------------------------------------------------------------- |
| `category` | string | (لا يوجد) | إحدى القيم `default`، `coding`، `review`، `documentation`، `debugging`. احذفه للحصول على التصنيف الموحّد. |
| `limit`    | number | `50`      | تُقيَّد قيمته بالنطاق `1–100`.                                                                            |

بنية الاستجابة:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

تمثّل `eloRaw` قيمة Arena ELO الأصلية؛ أما `score` فهي قيمة ملاءمة المهمة المطبّعة
(انظر أدناه). ويُستبعد من الاستجابة أي مزوّد لا يملك نماذج حاصلة على درجات.

## كيف تعمل الدرجات

### المصدر: لوحة المتصدرين Arena AI

يجلب محرك مزامنة Arena ELO (`src/lib/arenaEloSync.ts`) لوحتَي متصدرين — `text` و`code` — من واجهة برمجة تطبيقات لوحة المتصدرين Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). وعندما لا تُرجع تلك الواجهة أي لوحة قابلة للاستخدام، يعود المحرك إلى مجموعة البيانات الرسمية `lmarena-ai/leaderboard-dataset` على خادم Hugging Face datasets-server
(`src/lib/arenaEloHfSource.ts`، بترخيص CC-BY-4.0؛ `overall` → `text`،
`coding` → `code`)؛ ويُبلغ `GET /api/intelligence/sync` عن `activeSource` و`lastError` و
`lastFailedAt`. يحمل كل إدخال في لوحة المتصدرين اسم النموذج والمورّد ودرجة ELO (`score`) وفاصل الثقة وعدد الأصوات.

تُربط فئات لوحة المتصدرين بفئات مهام OmniRoute:

| لوحة متصدرين Arena | فئات مهام OmniRoute                               |
| ------------------ | ------------------------------------------------- |
| `text`             | `default`, `review`, `documentation`, `debugging` |
| `code`             | `coding`                                          |

### التطبيع (درجة ملاءمة المهمة)

تُطبَّع درجات ELO الخام لكل لوحة متصدرين إلى **قيمة ملاءمة مهمة ضمن `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

لا تصل الدرجة أبدًا إلى `0` أو `1`، مما يترك هامشًا للتجاوزات اليدوية من المستخدم. هذا هو حقل
`score` الذي تراه في استجابة واجهة برمجة التطبيقات والتسمية المعروضة على لوحة المعلومات.

### الثقة

يحصل كل إدخال على مستوى ثقة بناءً على عدد أصوات Arena:

| الثقة    | الأصوات |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### التخزين والحداثة

تُكتب الإدخالات المُطبَّعة في جدول قاعدة البيانات `model_intelligence` مع
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). **تنتهي صلاحية الإدخالات بعد
7 أيام**، لذا فإن المورّد الذي يتوقف عن المزامنة يختفي في النهاية بدلًا من تقديم
بيانات متقادمة.

تعمل المزامنة **مفعَّلة افتراضيًا**:

- تعمل مرة واحدة عند بدء تشغيل الخادم ثم على مؤقّت دوري
  (`src/lib/arenaEloSync.ts`، موصول من `src/instrumentation-node.ts`).
- وهي **غير حاجبة ولا تكون قاتلة أبدًا** — إذا فشل الجلب من المصدر الخارجي، يستمر OmniRoute في
  العمل وتعرض الترتيبات ببساطة آخر بيانات صالحة (أو حالة فارغة).

يتحكم متغيّرا بيئة في ذلك (موثَّقان في
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| المتغير                   | الافتراضي         | الغرض                                                  |
| ------------------------- | ----------------- | ------------------------------------------------------ |
| `ARENA_ELO_SYNC_ENABLED`  | `true`            | اضبطه على `false` لإلغاء الاشتراك في المزامنة الصادرة. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24 ساعة) | فترة المزامنة، بالثواني.                               |

### المزامنة اليدوية / الحالة / المسح

للمشغّلين، تتيح نقطة نهاية إدارية مُصادَق عليها تحكمًا يدويًا
(`src/app/api/intelligence/sync/route.ts` — تتطلب مصادقة إدارية):

```
GET    /api/intelligence/sync          # حالة المزامنة الحالية (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # تشغيل مزامنة يدوية؛ الجسم: { "dryRun": true } للمعاينة دون كتابة
DELETE /api/intelligence/sync          # مسح جميع إدخالات معلومات arena_elo المُزامَنة
```

إذا كانت صفحة الترتيبات فارغة، فإن `POST /api/intelligence/sync` يدوي (أو ببساطة
إعادة تشغيل الخادم) يعيد تعبئتها.

### مطابقة النماذج مع لوحة المتصدرين

لا تتطابق معرّفات النماذج في السجل مع أسماء نماذج Arena دائمًا بشكل دقيق. يستخدم الترتيب
مطابقة مرنة (`findMatchingIntelligence` في `src/lib/freeProviderRankings.ts`):

1. تطابق تام على معرّف النموذج المُطبَّع.
2. تطابق بعد إزالة لاحقة الإصدار الزائدة (مثل `kimi-k2.6` → `kimi-k2`).
3. تطابق البادئة (اسم نموذج لوحة المتصدرين هو بادئة لمعرّف السجل).

على جانب المزامنة، تُزال بادئات المورّدين المعروفة (`anthropic/`، `openai/`، `google/`، …)
وتوسِّع خريطة أسماء مستعارة صغيرة الأسماءَ القياسية إلى المتغيرات التي يستخدمها OmniRoute
داخليًا، بحيث تبقى النماذج قابلة للعثور عليها تحت أي اسم.

### كيف يُرتَّب المورّد

لكل مورّد مجاني، يُقيّم المحرك كل نموذج في فهرسه، ثم:

- **أفضل نموذج** = النموذج الأعلى درجة لدى المورّد.
- **متوسط الدرجة** = متوسط الدرجة عبر جميع نماذج ذلك المورّد المُقيَّمة.
- **النماذج** = عدد نماذج المورّد التي حصلت على درجة Arena.

تُرتَّب المورّدون حسب **درجة أفضل نموذج** أولًا، ثم حسب متوسط الدرجة. هذا يكافئ
المورّد الذي يقدّم نموذجًا مجانيًا قويًا واحدًا على الأقل.

## استخدامه لاختيار المزوّدين المجانيين

1. **اختر الفئة المناسبة.** استخدم عامل التصفية **البرمجة** لأعباء عمل الوكلاء/البرمجة، أو
   اتركه على **جميع الفئات** / **الافتراضي** للدردشة العامة. قد يختلف ترتيب المزوّد نفسه
   بين الفئات لأن نموذجه الأفضل يختلف باختلاف لوحة الصدارة.
2. **فضّل المراكز الثلاثة الأولى للإعدادات أحادية المحاولة.** إذا كنت تريد الاتصال بمزوّد
   مجاني واحد أو اثنين فقط، فابدأ بالمزوّدين الأعلى ترتيبًا في فئتك.
3. **تحقّق من شارة النوع.** مزوّدو `NOAUTH` هم الأسرع في الاتصال (من دون
   بيانات اعتماد). تتطلب المستويات المجانية من `OAUTH` / `APIKEY` تسجيلًا سريعًا، لكنها غالبًا ما تتيح
   نماذج أقوى. راجع [دليل المستويات المجانية](../getting-started/FREE-TIERS-GUIDE.md) للاطلاع على
   خطوات الاتصال.
4. **اتصل بعدة مزوّدين ودع Auto-Combo يقرر.** إن بيانات Arena ELO نفسها التي تشغّل
   هذه الصفحة تغذّي أيضًا **عامل الملاءمة للمهمة** في محرك تسجيل النقاط Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`، ترتيب الحل
   `user_override → arena_elo → models_dev_tier → static table`). لذا، بعد الاتصال
   بأفضل المزوّدين المجانيين، سيؤدي التوجيه باستخدام `model: "auto"` (مثل `auto/coding`) إلى
   تفضيل النماذج المجانية الأعلى جودة تلقائيًا لكل طلب. راجع
   [Auto-Combo](../routing/AUTO-COMBO.md) للاطلاع على نظام التسجيل الكامل ذي العوامل الستة عشر.
