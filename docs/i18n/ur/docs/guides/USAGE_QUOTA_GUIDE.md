- `src/lib/db/quotaSnapshots.ts` — کوٹے کا تاریخی ڈیٹا
- `src/lib/db/usage*.ts` — استعمال سے متعلق متعدد DB ماڈیولز

## جائزہ

OmniRoute سے گزرنے والی ہر درخواست ایک **استعمال کا ریکارڈ** بناتی ہے، جس میں درج ذیل معلومات محفوظ ہوتی ہیں:

- **شناخت**: کون سی API کلید، فراہم کنندہ، ماڈل، کومبو
- **ٹوکنز**: پرامپٹ ٹوکنز، تکمیلی ٹوکنز، کیش شدہ ٹوکنز، کل تعداد
- **لاگت**: USD رقم (قیمتوں کے ڈیٹا سے حساب کی گئی)
- **وقت**: تاخیر، آغاز/اختتام کے ٹائم اسٹیمپس
- **حالت**: کامیابی، خرابی، شرح کی حد کا اطلاق، وغیرہ

```
درخواست ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    تجزیات     کوٹا    بلنگ
                    (ڈیش بورڈ) (نفاذ)  (برآمد)
```

## کیا ریکارڈ کیا جاتا ہے

`usage.ts` سروس ہر درخواست کے لیے ایک **استعمال کا واقعہ** ریکارڈ کرتی ہے:

| فیلڈ               | قسم     | ماخذ                                                       |
| ------------------ | ------- | ---------------------------------------------------------- |
| `id`               | اسٹرنگ  | ریکارڈ کرتے وقت تیار کردہ UUID                             |
| `apiKeyId`         | اسٹرنگ  | وہ API کلید جس سے درخواست شروع ہوئی                        |
| `provider`         | اسٹرنگ  | فراہم کنندہ کی ID (openai، anthropic، وغیرہ)               |
| `model`            | اسٹرنگ  | ماڈل کی ID (gpt-5، claude-opus-4-6، وغیرہ)                 |
| `comboId`          | اسٹرنگ؟ | اگر کومبو کے ذریعے روٹ کیا گیا ہو تو کومبو کی ID           |
| `promptTokens`     | عدد     | اپ اسٹریم جواب سے                                          |
| `completionTokens` | عدد     | اپ اسٹریم جواب سے                                          |
| `cachedTokens`     | عدد     | کیش ہٹ ٹوکنز (Anthropic پرامپٹ کیشنگ، وغیرہ)               |
| `totalTokens`      | عدد     | پرامپٹ + تکمیل                                             |
| `costUsd`          | عدد     | قیمتوں کے ڈیٹا سے حساب کردہ                                |
| `latencyMs`        | عدد     | درخواست کا ابتدا سے انتہا تک دورانیہ                       |
| `status`           | اینم    | `success`, `error`, `rate_limited`, `timeout`, `cancelled` |
| `errorClass`       | اسٹرنگ؟ | اگر اسٹیٹس کامیاب نہ ہو تو خرابی کی کلاس                   |
| `timestamp`        | اسٹرنگ  | ISO 8601 UTC                                               |
| `metadata`         | آبجیکٹ  | پلگ اِن کے ذریعے شامل کردہ حسبِ ضرورت ڈیٹا                 |

### ٹوکنز کہاں سے آتے ہیں

ٹوکنز **ریسپانس ہینڈلر** میں اپ اسٹریم فراہم کنندہ کے جواب سے اخذ کیے جاتے ہیں:

```ts
// open-sse/handlers/chatCore.ts سے
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

جو فراہم کنندگان استعمال کی معلومات واپس نہیں کرتے (کچھ ویب کوکی فراہم کنندگان)، ان کے لیے OmniRoute، `~4 chars per token` کے تخمینی اصول سے ٹوکنز کا **اندازہ** لگاتا ہے (دیکھیے `open-sse/services/autoCombo/pipelineRouter.ts`)۔

### کیش شدہ ٹوکنز

OmniRoute، `cached_tokens` کو `prompt_tokens` سے الگ ٹریک کرتا ہے کیونکہ:

- Anthropic پرامپٹ کیشنگ میں کیش شدہ ٹوکنز پر کم شرح وصول کی جاتی ہے (معمول کی شرح کا 10%)
- کچھ فراہم کنندگان `cache_read_input_tokens` واپس کرتے ہیں جن کی قیمت الگ مقرر ہونی چاہیے
- تجزیات میں **کیش ہٹ کی شرح** = `cached_tokens / prompt_tokens` دکھائی جا سکتی ہے

### کیش رائٹ درجوں کی تشخیص

تجزیاتی ڈیش بورڈ کا پرامپٹ کیش کی صحت کا پینل فراہم کنندہ کی رپورٹ کردہ
5 منٹ اور 1 گھنٹے کی کیش رائٹس میں فرق کرتا ہے۔ Anthropic کے
`usage.cache_creation.ephemeral_5m_input_tokens` اور
`usage.cache_creation.ephemeral_1h_input_tokens` کو اسٹریمنگ اور
نان اسٹریمنگ استعمال کی معلومات کی تبدیلی کے دوران برقرار رکھا جاتا ہے اور کال لاگ کے خلاصوں کے ساتھ محفوظ کیا جاتا ہے۔ مجموعی
کیش رائٹ مقدار کو ان زمروں میں دوبارہ شامل نہیں کیا جاتا۔

جن کالز میں صرف مجموعی رائٹ کاؤنٹر ہوتا ہے، بشمول پرانے ریکارڈز، ان کا درجہ نامعلوم
ہوتا ہے۔ جزوی تفصیل میں غیر مختص باقی مقدار کو نامعلوم رکھا جاتا ہے؛ غلط یا
متضاد کاؤنٹرز کو خاموشی سے TTL تفویض کرنے کے بجائے نشان زد کیا جاتا ہے۔ درخواست کی جانب کے
TTL نشانات بل کیے گئے درجے کا ثبوت نہیں ہیں۔

پینل کا API کے مساوی رائٹ تخمینہ صرف رپورٹ کردہ، قیمت والے درجوں کا احاطہ کرتا ہے، پوری
درخواست کا نہیں۔ مقامی Claude/Anthropic ماڈل کی قیمتوں کے لیے یہ 5 منٹ کی رائٹس پر
ان پٹ شرح کا 1.25 گنا اور 1 گھنٹے کی رائٹس پر ان پٹ شرح کا دو گنا استعمال کرتا ہے۔ غیر موجود
قیمت کو غیر دستیاب سمجھا جاتا ہے، صفر نہیں۔ ہر نئی کال لاگ کرتے وقت قیمتیں ریکارڈ کی جاتی ہیں؛
تاریخی ریکارڈز کی قیمت دوبارہ نہیں لگائی جاتی۔ لہٰذا سبسکرپشن اکاؤنٹس کے لیے
API کے مساوی تخمینہ موجود ہو سکتا ہے، بغیر اس رقم کے نقد خرچ یا سبسکرپشن
کوٹے کی صورت میں لاگو ہوئے۔ کوٹے، بجٹ اور فراہم کنندہ کی عین لاگت کے موجودہ حسابات میں کوئی تبدیلی نہیں ہوتی۔

یہ تشخیصی معلومات کیش کی صحت کے موجودہ محدود خلاصے اور کال لاگ
کو محفوظ رکھنے کے نظام کو استعمال کرتی ہیں۔ یہ درخواست کے طے شدہ TTL، روٹنگ یا اکاؤنٹ کے انتخاب کو تبدیل نہیں کرتیں۔
فراہم کنندہ کو ارسال کرنے کے مقام پر کلائنٹ کے مطلوبہ TTL اور مؤثر طور پر بھیجے جانے والے TTL کو ریکارڈ کرنا
مؤخر کیا گیا ہے؛ یہ پینل رسید میں درج درجات رپورٹ کرتا ہے، مؤثر طور پر بھیجے جانے والا TTL نہیں۔

نفاذ: `src/lib/usage/cacheWriteEstimate.ts`،
`src/lib/usage/cacheHealth.ts`، اور `open-sse/utils/cacheWriteUsage.ts`۔

## لاگت کا حساب

لاگت کا حساب LiteLLM سے ہم وقت کیے گئے **قیمتوں کے ڈیٹا** (`src/lib/pricingSync.ts`) کی بنیاد پر کیا جاتا ہے:

| ماڈل              | اِن پٹ $/1M | آؤٹ پٹ $/1M | کیش شدہ $/1M |
| ----------------- | ----------- | ----------- | ------------ |
| gpt-5             | $2.50       | $10.00      | —            |
| claude-opus-4-6   | $15.00      | $75.00      | $1.50        |
| claude-sonnet-4-5 | $3.00       | $15.00      | $0.30        |
| gemini-2.5-pro    | $1.25       | $10.00      | —            |

لاگت کا فارمولا (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **کیش شدہ ٹوکنز کو پرامپٹ سے کیوں منہا کیا جاتا ہے؟** کیش شدہ حصے کی قیمت الگ سے مقرر کی جاتی ہے؛ پورے پرامپٹ پر اِن پٹ کی قیمت عائد کرنے سے لاگت زائد شمار ہوگی۔

### قیمتوں کی ہم وقتی

قیمتوں کا ڈیٹا `/api/pricing/sync` اینڈ پوائنٹ کے ذریعے LiteLLM سے خودکار طور پر ہم وقت کیا جاتا ہے (یہ بلٹ اِن cron ٹاسک کے ذریعے متحرک ہوتا ہے، صارف کے لیے دستیاب env var کے ذریعے نہیں):

```bash
# دستی طور پر متحرک کریں
curl -X POST http://localhost:20128/api/pricing/sync
```

جن ماڈلز کے لیے قیمتوں کا ڈیٹا دستیاب نہ ہو، ان کی **تخمینی لاگت** معلوم کرنے کے لیے OmniRoute داخلی اوسط نرخ استعمال کرتا ہے (جو LiteLLM کے قیمتوں کے ڈیٹا سے حاصل کیے گئے ہیں)۔

## تاریخ کی حد کے لحاظ سے تجمیع

`usageAnalytics.ts` ماڈیول خام استعمال کے ڈیٹا سے ڈیش بورڈ ویجٹس کا حساب لگاتا ہے۔ یہ 7 زمانی حدود کی معاونت کرتا ہے:

| حد       | دورانیہ                         | استعمال کی صورت                        |
| -------- | ------------------------------- | -------------------------------------- |
| `1d`     | گزشتہ 24 گھنٹے                  | فی گھنٹہ لاگت میں اچانک اضافے کی شناخت |
| `7d`     | گزشتہ 7 دن                      | ہفتہ وار جائزہ                         |
| `30d`    | گزشتہ 30 دن                     | ماہانہ بلنگ                            |
| `90d`    | گزشتہ 90 دن                     | سہ ماہی تجزیہ                          |
| `ytd`    | موجودہ سال کی یکم جنوری سے      | سالانہ بجٹ کی نگرانی                   |
| `all`    | تمام وقت                        | پوری مدت کے اعداد و شمار               |
| `custom` | صارف کی متعین کردہ ابتدا/اختتام | آڈٹس، حسبِ ضرورت استفسارات             |

### حساب کیے جانے والے ڈیش بورڈ ویجٹس

کسی بھی تاریخ کی حد کے لیے، تجزیاتی تہہ درج ذیل کا حساب لگاتی ہے:

| ویجٹ                             | تفصیل                                                  |
| -------------------------------- | ------------------------------------------------------ |
| **خلاصے کے کارڈز**               | کل درخواستیں، کل لاگت، کل ٹوکنز، کامیابی کی شرح        |
| **روزانہ رجحان کا چارٹ**         | روزانہ لاگت + ٹوکنز، ماڈل کے لحاظ سے تہہ در تہہ        |
| **سرگرمی کا حرارتی نقشہ**        | دن کا گھنٹہ × ہفتے کا دن گرڈ، رنگ = درخواستوں کی تعداد |
| **ماڈل کے لحاظ سے تقسیم**        | ماڈل کے لحاظ سے لاگت کا پائی چارٹ                      |
| **فراہم کنندہ کے لحاظ سے تقسیم** | فراہم کنندہ کے لحاظ سے درخواستوں کا بار چارٹ           |
| **سرفہرست API کلیدیں**           | لاگت کے لحاظ سے سرفہرست 10 کلیدوں کی جدول              |
| **خرابیوں کا تجزیہ**             | وقت کے ساتھ خرابیوں کی شرح، خرابیوں کی نمایاں اقسام    |

### پروگرام کے ذریعے رسائی

````ts
import { computeAnalytics } from "@/lib/usageAnalytics";

const analytics = await computeAnalytics(
  history,              // استعمال کی تاریخ کے ریکارڈز
  "7d",                 // زمانی حد: "1d" | "7d" | "30d" | "90d" | "ytd" | "all" | "custom"
  connectionMap,        // فراہم کنندہ کے کنکشن کا نقشہ (connectionId → اکاؤنٹ کا نام)
  {
    startDate: "2025-01-01",  // اختیاری: "custom" حد کے لیے
    endDate: "2025-06-01",   // اختیاری: "custom" حد کے لیے
  }
);

console.log(analytics.summary.totalCost);   // 12.34 (سینٹ)
console.log(analytics.byModel[0]);           // { model, cost, requests, promptTokens, completionTokens }

## کوٹے کا نفاذ

ہر API کلید کا کوٹا دو جگہوں پر نافذ کیا جاتا ہے:

1. **نرم حد** (`quotaWarnAt`): استعمال مقررہ حد سے بڑھنے پر ڈیش بورڈ پر انتباہ
2. **سخت حد** (`quotaLimit`): حد سے تجاوز ہونے پر درخواست HTTP 429 کے ساتھ مسترد

### ترتیب

```ts
// ہر API کلید کے لیے
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — انتباہ دکھائیں
  quotaLimit: 10_00,    // $10.00 — مکمل طور پر روک دیں
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### نفاذ کا بہاؤ

```
Request ──▶ quotaCheck()
              │
              ├── Within limit?  ──▶ allow
              │
              └── Over limit?  ──▶ 429 Too Many Requests
                                   with Retry-After header
```

### کوٹے کے اسنیپ شاٹس

`quotaSnapshots` جدول رجحانات کے تجزیے کے لیے **کوٹے کی تاریخی حالت** محفوظ کرتی ہے:

| فیلڈ | تفصیل |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | وہ کلید جس کی نگرانی کی جا رہی ہے |
| `window` | "دن" | "ہفتہ" | "مہینہ" |
| `used` | اس دورانیے میں استعمال شدہ لاگت (سینٹ) |
| `limit` | حد (سینٹ) |
| `resetAt` | دورانیہ کب دوبارہ شروع ہوتا ہے |
| `createdAt` | اسنیپ شاٹ کب لیا گیا |

اسنیپ شاٹس **ہر اس درخواست پر** لیے جاتے ہیں جس کی لاگت > 0 ہو، اور انہیں درج ذیل کے لیے استعمال کیا جاتا ہے:

- ڈیش بورڈ میں کوٹے کی پیش رفت کی پٹی دکھانا
- کوٹے کے 30 روزہ رجحان کے چارٹس دکھانا
- استعمال حد کے قریب پہنچنے پر انتباہات جاری کرنا

## برقرار رکھنا اور صفائی

استعمال کا ڈیٹا ہر درخواست پر تقریباً 1-10KB بڑھتا ہے۔ بڑے پیمانے پر یہ خاصا زیادہ ہو سکتا ہے۔

### برقرار رکھنے کی ترتیبات

استعمال کی تاریخ کو برقرار رکھنے کی مدت UI میں ڈیٹابیس کی ترتیبات یا `/api/settings/database` کے ذریعے متعین کی جاتی ہے۔

بطور ڈیفالٹ، استعمال کی تاریخ **90 دن** تک برقرار رکھی جاتی ہے۔

### صفائی

پرانے ریکارڈز کو `src/lib/db/cleanup.ts` کے ذریعے صاف کیا جاتا ہے:

- پس منظر میں چلنے والے cron عمل سے شروع ہوتا ہے
- `usage_history` سے ایسے ریکارڈز حذف کرتا ہے جو `usageHistory` کی متعین کردہ برقرار رکھنے کی مدت سے پرانے ہوں

### اسٹوریج کا تخمینہ

| درخواستوں کی شرح     | 30 دن کا اسٹوریج | 90 دن کا اسٹوریج |
| -------------------- | ---------------- | ---------------- |
| 100 درخواستیں/دن     | ~3MB             | ~9MB             |
| 1,000 درخواستیں/دن   | ~30MB            | ~90MB            |
| 10,000 درخواستیں/دن  | ~300MB           | ~900MB           |
| 100,000 درخواستیں/دن | ~3GB             | ~9GB             |

بہت زیادہ ٹریفک کی صورت میں، غور کریں:

- ڈیٹابیس کی ترتیبات کے ذریعے برقرار رکھنے کی مدت کم کرنے پر
- خام ریکارڈز کے بجائے `aggregated_metrics` استعمال کرنے پر (صرف تجزیات کے لیے)

## لاگت کی اصلاح کے مشورے

### 1. درست ماڈل استعمال کریں

```bash
# فوری جواب — سستا + تیز استعمال کریں
curl -d '{"model":"auto/fast","messages":[...]}'

# پیچیدہ کام — معیار کو ترجیح دیں
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. کیشنگ فعال کریں

Anthropic کی پرامپٹ کیشنگ سے **بار بار استعمال ہونے والے سیاق و سباق پر 90% بچت** ہوتی ہے:

```ts
// کیشنگ خودکار ہے — بس وہی بڑا سسٹم پرامپٹ شامل کریں
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // خودکار طور پر کیش کیا جائے گا
  messages: [{ role: "user", content: "..." }],
});
```

### 3. کمپریشن استعمال کریں

RTK + Caveman کمپریشن سے **ٹولز کے زیادہ استعمال والے سیشنز میں 15-95% بچت** ہوتی ہے:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. ہر کلید کے لیے کوٹا مقرر کریں

بے قابو اخراجات سے بچنے کے لیے ہمیشہ `quotaLimit` مقرر کریں:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // $10 ماہانہ کی حد
```

### 5. سب سے زیادہ استعمال کرنے والوں کا جائزہ لیں

API کلید کے لحاظ سے گروپ بنانے اور لاگت کے لحاظ سے ترتیب دینے کے لیے ڈیش بورڈ یا **`/api/usage/analytics`** استعمال کریں:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## مسائل کا حل

### "لاگت توقع سے زیادہ ہے"

1. **`/api/usage/analytics?groupBy=model`** دیکھیں — مہنگا ماڈل تلاش کریں
2. **`/api/usage/analytics?groupBy=apiKey`** دیکھیں — زیادہ استعمال کرنے والا تلاش کریں
3. تصدیق کریں کہ قیمتوں کا ڈیٹا تازہ ترین ہے: `POST /api/pricing/sync`

### "ریکارڈز موجود نہیں ہیں"

- ڈیش بورڈ → ڈیٹابیس → صفائی کے تحت DB میں ڈیٹا برقرار رکھنے کی ترتیبات دیکھیں — پرانے ریکارڈز وقفے وقفے سے چلنے والے صفائی کے کام کے ذریعے حذف کیے جاتے ہیں (`src/lib/db/cleanup.ts`)
- `src/lib/db/usage*.ts` میں خرابیوں کی جانچ کریں — DB میں لکھنے کی ناکامیاں لاگ کی جاتی ہیں لیکن ظاہر نہیں کی جاتیں
- تصدیق کریں کہ درخواست واقعی `chatCore` تک پہنچی تھی — کومبو روٹنگ کی جانچ کریں

### "کوٹا نافذ نہیں ہو رہا"

- کلید کی `quotaLimit` ترتیب دیکھیں
- تصدیق کریں کہ `quotaWindow` درست طور پر مقرر ہے
- `quotaSnapshots` ریکارڈز تلاش کریں — یہ ہر درخواست پر بننے چاہییں
