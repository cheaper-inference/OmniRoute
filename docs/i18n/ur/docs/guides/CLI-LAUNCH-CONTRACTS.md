غیر جانبدار `config/cli-tools-manifest.json` معاہدہ کیننیکل IDs، عرف، بائنری امیدواروں، سیٹ اپ کی ترکیبیں، ماڈل دلائل اور صلاحیتوں کا اعلان کرتا ہے۔ `bin/cli/cli-manifest.mjs` میں سادہ نوڈ اڈاپٹر اور `src/shared/constants/cliIntegrationManifest.ts` میں TypeScript اڈاپٹر ایک ہی فائل کو پڑھتے ہیں۔ رن ٹائم، کیٹلاگ، کنفیگر، تکمیل، جنریٹرز اور بیک اینڈ رجسٹریشن کو `tests/unit/cli/cli-manifest-drift.test.ts` کے ذریعے ایک ساتھ چیک کیا جاتا ہے۔ کیٹلاگ ہونے کا مطلب یہ نہیں ہے کہ کوئی ٹول لانچ یا کنفیگر کیا جا سکتا ہے۔ خاص طور پر، 5dive صرف کنفیگر رہتا ہے۔

## بچوں کا ماحول اور لائف سائیکل

`omniroute run`، `omniroute launch` اور `omniroute launch-codex` ایک OS/terminal مطابقت کی اجازت کی فہرست کو وراثت میں لیتے ہیں اور منتخب ہدف کے اسناد کو انجیکشن دیتے ہیں۔ غیر متعلقہ فراہم کنندہ اور ڈیٹا بیس کے راز بطور ڈیفالٹ وراثت میں نہیں ملتے ہیں۔ `--inherit-env` واضح طور پر مکمل والدین کے ماحول کی وراثت کو بحال کرتا ہے۔ اسے صرف اس وقت استعمال کریں جب منتخب تھرڈ پارٹی عمل کو وہ اقدار ملنی چاہئیں۔ یہ ماحول کی فلٹرنگ ہے، OS سینڈ باکس نہیں: یہ عمل اب بھی کالر کے فائل سسٹم کی اجازت کے ساتھ چلتا ہے۔

مداخلت اور ختم ہونے کے سگنل بچے کو بھیجے جاتے ہیں۔ لانچر عارضی کنفیگریشن کو ہٹانے سے پہلے بچے کے قریبی ایونٹ کا انتظار کرتا ہے۔ `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` جبری برطرفی سے پہلے اضافی مدت کو کنٹرول کرتا ہے (پہلے سے طے شدہ 5000 ملی سیکنڈ)۔

## Gemini مسلسل سیٹ اپ

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

پہلی دو کمانڈز اس مشین کو منتخب مقامی یا ریموٹ سرور کے لیے کنفیگر کرتی ہیں۔ سیٹ اپ غیر متعلقہ JSON ترتیبات کو محفوظ رکھتا ہے، Gemini API-key auth کو منتخب کرتا ہے، اور ایک نجی `.gemini/.env` فائل میں اختتامی نقطہ اور اسناد لکھتا ہے۔ یہ غلط JSON اوور رائٹ کرنے کے بجائے انکار کرتا ہے۔ اختتامی نقطہ URLs HTTP(S) ہونا چاہیے، بغیر ایمبیڈڈ اسناد، استفسار کے پیرامیٹرز یا ٹکڑوں کے۔ ڈرائی رن راستے پرنٹ کرتا ہے، اسنادی اقدار نہیں۔

`GEMINI_CLI_HOME` یا `--gemini-home` مستقل ہوم روٹ کو منتخب کرتا ہے۔ ایک حقیقی `run gemini` اپنا عارضی گھر بناتا ہے اور بعد میں ہٹاتا ہے۔ کوئی بھی موڈ Gemini کے ورک اسپیس ٹرسٹ چیک کو نظرانداز نہیں کرتا ہے۔

## Codex پروفائلز

`configure codex` ایک ماڈل اور اس کے OmniRoute فراہم کنندہ اختتامی نقطہ کے ساتھ ایک نجی `<name>.config.toml` لکھتا ہے۔ اسناد کا حوالہ `OMNIROUTE_API_KEY` کے ذریعے دیا جاتا ہے، کبھی سرایت نہیں کیا جاتا۔ لانچ کمانڈ منتخب ماڈل کو ٹاپ لیول `model` کلید پر سیٹ کرتی ہے، `model_providers` کے اندر نہیں۔

علیحدہ پروفائل فائلیں موجودہ دستاویزی Codex معاہدہ ہے۔ `codex --profile <name>` کے ساتھ منتخب ہونے پر وہ صارف کی ترتیب کو اوورلے کرتے ہیں۔ [آفیشل پروفائل کا حوالہ](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) اور [OmniRoute Codex گائیڈ](./CODEX-CLI-CONFIGURATION.md) دیکھیں۔

## ہرمیٹک کمانڈ پر عمل درآمد

واضح `DATA_DIR` کے ساتھ، `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` ترتیب دینا سٹارٹ اپ کو پہلے سے طے شدہ صارف ڈیٹا ڈائرکٹری کے اسنادی ماحول میں جانے سے روکتا ہے۔ یہ الگ تھلگ ٹیسٹوں کے لیے مفید ہے۔ یہ دیگر واضح طور پر منتخب کردہ ماحولیاتی فائلوں کو غیر فعال نہیں کرتا ہے۔

## ورکنگ ڈائرکٹری `.env`

CLI اس ترتیب میں `.env` فائلوں کو پڑھتا ہے، اور کلیدی جیتنے والی پہلی فائل: واضح `DATA_DIR`، ڈیفالٹ ڈیٹا ڈائرکٹری، موجودہ ورکنگ ڈائرکٹری، پھر پیکیج ڈائرکٹری۔ شیل متغیر ہمیشہ جیتتے ہیں۔

ورکنگ ڈائرکٹری کسی اور کی ہو سکتی ہے (کلون شدہ ذخیرہ، ایک غیر پیک شدہ آرکائیو)، اور `omniroute serve` CLI ماحول کو سرور اور سرور کے چلنے والے ہر ٹول پر منتقل کرتا ہے۔ لہذا وہاں ایک `.env` صرف یہ چابیاں ترتیب دے سکتا ہے، جو `bin/cli/utils/untrustedCwdEnv.mjs` میں درج ہے:

| چابی                            | قبول شدہ اقدار                                                   |
| ------------------------------- | ---------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`، `1` یا `yes` کسی بھی صورت میں، سرور جن اقدار کو مانتا ہے |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 64 حروف، ہندسوں، `_`، `.`، `@` یا `-` تک                         |
| `LANGUAGE`                      | وہی، علاوہ `:`                                                   |
| `TZ`                            | 64 حروف، ہندسوں، `_`، `+`، `-` یا `/` تک، `/` سے شروع نہیں ہوتے  |
| `NO_COLOR`, `FORCE_COLOR`       | 16 حروف اور ہندسوں تک                                            |

`REQUIRE_API_KEY` کی قبول کردہ ہر قدر چیک کو آن کر دیتی ہے، لہذا فائل خود چیک آف نہیں کر سکتی۔ یہ نتیجہ کا فیصلہ نہیں کرتا، اگرچہ: سرور ماحول سے پہلے ڈیٹا بیس میں ذخیرہ شدہ `REQUIRE_API_KEY` اوور رائڈ کو پڑھتا ہے، جب کہ API کلید کے بغیر تمام انٹرفیس پر سننے کے بارے میں ابتدائی انتباہ صرف ماحول کو پڑھتا ہے۔ `false` کے ذخیرہ شدہ اوور رائڈ کے ساتھ، ایک ورکنگ ڈائرکٹری `REQUIRE_API_KEY=true` API کو کھلا چھوڑ دیتی ہے اور اس انتباہ کو چھپا دیتی ہے۔ `TZ` اصول POSIX سے تنگ ہے: یہ `.`، `:`، `,` اور `<>` کو مسترد کرتا ہے، لہذا `:Area/City` شکل اور `EST5EDT,M3.2.0,M11.1.0` جیسے قواعد کو شیل میں یا `<DATA_DIR>/.env` میں سیٹ کرنا ہوگا۔

اوپری صورت میں، ناموں کو بالکل مماثل ہونا چاہیے۔ کوئی دوسری سطر، ایک قدر جو اس کی جانچ میں ناکام ہو جاتی ہے، اور ایک ایسا نام جو سادہ ASCII حروف، ہندسوں اور `_` نہیں ہے (مثال کے طور پر NUL بائٹ والا یا ایک جیسا ایک جیسا خط) کو چھوڑ دیا جاتا ہے۔ CLI ایک انتباہ پرنٹ کرتا ہے جو ان چابیاں کے نام دیتا ہے جو اسے سیٹ نہیں کر سکتا اور ایک جس کے نام کی اجازت دی جاتی ہے اسے نظر انداز کیا جاتا ہے، ہر ایک کو کیا تبدیل کرنا ہے (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`)۔ نہ ہی اقدار پرنٹ کرتا ہے۔ ان پیغامات میں فائل پاتھ، اور `.env` پاتھ `omniroute doctor` رپورٹس، اس وقت بچ جاتے ہیں جب ان میں کنٹرول یا بولی والے حروف ہوتے ہیں۔ جب ورکنگ ڈائرکٹری ڈیٹا ڈائرکٹری یا پیکیج ڈائرکٹری ہو تو پابندی لاگو نہیں ہوتی۔

`PORT`، `API_PORT` اور `DASHBOARD_PORT` فہرست میں نہیں ہیں۔ ایک اعلی ترجیحی ذریعہ سے بیس URL کے بغیر، CLI `localhost:<PORT>` سے بات کرتا ہے، اور جو بھی وہاں سنتا ہے وہ CLI کی API کلید، سیاق و سباق کا ٹوکن اور CLI مشین ٹوکن (`x-omniroute-cli-token`، دیکھیں [CLI_TOKEN.md](../security/CLI_TOKEN.md) ) وصول کرتا ہے، جسے مقامی سرور انتظامیہ loop سے کالوں کے لیے قبول کرتا ہے۔ ورکنگ ڈائرکٹری سے ایک پورٹ اس فائل کو سننے والے کو منتخب کرنے دیتا ہے، لہذا بندرگاہوں کو شیل میں، `<DATA_DIR>/.env` میں یا `--port` آپشن کے ساتھ ترتیب دیں جن میں ایک ہے (`serve`, `launch`, `run`)۔

تجزیہ کار کے پاس کوئی `export` نحو نہیں ہے۔ ایک لائن جیسے `export LD_PRELOAD=...` متغیر `export LD_PRELOAD` نام دیتی ہے۔ ورکنگ ڈائرکٹری سے اسے چھوڑ دیا جاتا ہے، اور دوسری `.env` فائلوں میں یہ وہ لفظی نام سیٹ کرتا ہے، جسے کچھ نہیں پڑھتا۔

CLI سیاق و سباق کے ذخیرہ شدہ ٹوکن (ایکسیس ٹوکن یا لیگیسی API کلید) کو صرف اس سیاق و سباق کی اپنی اصلیت کے ساتھ جوڑتا ہے: اسکیم، میزبان اور پورٹ، `URL.origin` کے مقابلے میں۔ یہ CLI کے HTTP کلائنٹ (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) کے ذریعے کی گئی درخواستوں اور `launch`, `launch codex`, `configure` اور `setup-*` کمانڈز پر لاگو ہوتا ہے جو ایک بیس URL اور کلید کو دوسرے ٹول کی تشکیل میں لکھتے ہیں۔ `--remote` کے ساتھ دوسرے سرور کی طرف اشارہ کرتے ہوئے، وہ ایک واضح `--api-key` یا `OMNIROUTE_API_KEY` استعمال کرتے ہیں اگر کوئی سیٹ ہے، اور کوئی سیاق و سباق کا ٹوکن نہیں ہے۔ موازنہ بالکل درست ہے، لہذا `localhost` اور `127.0.0.1`، یا ٹریلنگ ڈاٹ کے ساتھ اور بغیر کسی میزبان کو، مختلف سرورز کے طور پر شمار کریں اور کوئی سیاق و سباق کا ٹوکن حاصل نہ کریں۔ صارف کی معلومات کے ساتھ ایک URL ، بیک سلیش یا وائٹ اسپیس کبھی مماثل نہیں ہے، کیونکہ دوسرے URL تجزیہ کار (مثال کے طور پر Python کے `urllib` اور `httpx`) اس سے مختلف میزبان پڑھ سکتے ہیں۔ درخواستوں کے لیے CLI خود بھیجتا ہے، یہ چیک صرف اسکیم اور اتھارٹی کا احاطہ کرتا ہے، لہذا راستے یا استفسار میں جگہ کے ساتھ ایک آئی ڈی ٹوکن رکھتا ہے۔
