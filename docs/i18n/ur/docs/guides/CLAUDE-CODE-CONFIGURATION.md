**Claude Code** CLI (`claude`) کو OmniRoute کی طرف پوائنٹ کریں — مقامی یا ریموٹ VPS —
فی ماڈل پروفائلز کے ساتھ، Codex سیٹ اپ کی طرز پر۔

---

## فوری آغاز

```bash
# Claude Code کو مقامی OmniRoute کے ساتھ چلائیں (فعال کانٹیکسٹ خودکار طور پر دریافت کرتا ہے)
omniroute launch

# ریموٹ OmniRoute کے ساتھ ( `omniroute connect <host>` کے بعد یہ خودکار ہے)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# فی ماڈل پروفائلز بنائیں، پھر ان میں سے ایک چلائیں
omniroute setup-claude            # ~/.claude/profiles/<name>/settings.json میں لکھتا ہے
omniroute launch --profile glm52  # OmniRoute کے ذریعے glm/glm-5.2 استعمال کرنے والا Claude Code
```

## Claude Code گیٹ وے سے کیسے جڑتا ہے

Claude Code، **Anthropic Messages API** سے رابطہ کرتا ہے اور اسے ماحولیاتی متغیرات کے ذریعے ایک حسبِ ضرورت
اینڈ پوائنٹ کی طرف پوائنٹ کیا جاتا ہے (اس میں `--base-url` فلیگ موجود نہیں):

| متغیر                                        | مقصد                                                                                                      |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | گیٹ وے کا روٹ URL (Claude Code آخر میں `/v1/messages` شامل کرتا ہے)۔ **آخر میں `/v1` نہ لگائیں۔**         |
| `ANTHROPIC_AUTH_TOKEN`                       | `Authorization: Bearer …` کے طور پر بھیجا جاتا ہے — اپنا OmniRoute رسائی ٹوکن / API کلید استعمال کریں     |
| `ANTHROPIC_API_KEY`                          | متبادل: `x-api-key` کے طور پر بھیجا جاتا ہے۔ اگر دونوں سیٹ ہوں تو `ANTHROPIC_AUTH_TOKEN` کو ترجیح ملتی ہے |
| `ANTHROPIC_MODEL`                            | کسی مخصوص ماڈل کو لازمی بنائیں (`/model` پِکر کے ڈیفالٹ کو اوور رائیڈ کرتا ہے)                            |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → مقامی `/model` پِکر، `/v1/models` سے `claude*`/`anthropic*` ماڈلز دکھاتا ہے                         |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | فی جواب آؤٹ پٹ ٹوکنز کی حد مقرر کریں (مثلاً `65536`)                                                      |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | خودکار کمپیکشن کے لیے ٹوکن کی حد                                                                          |

> ماحولیاتی متغیرات **اسٹارٹ اپ پر صرف ایک بار** پڑھے جاتے ہیں — انہیں تبدیل کرنے کے بعد Claude Code دوبارہ شروع کریں۔

`omniroute launch` یہ سب آپ کے لیے سیٹ کرتا ہے: یہ فعال کانٹیکسٹ سے بنیادی URL + ٹوکن
حاصل کرتا ہے (لہٰذا `omniroute connect <vps>` کے بعد `omniroute launch`
براہِ راست کام کرتا ہے)، سرور کی صحت جانچتا ہے، اور `claude` کو چلاتا ہے۔

## ڈسکوری الائسز — `/model` چنندہ میں غیر Claude ماڈلز ظاہر کریں

Claude Code کی گیٹ وے ماڈل ڈسکوری صرف ان آئی ڈیز کو فہرست میں شامل کرتی ہے جو `claude` یا `anthropic` سے شروع ہوتی ہیں، اس لیے `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` کے ساتھ مقامی `/model` چنندہ عام طور پر **صرف** OmniRoute کے Claude/Anthropic ماڈلز دکھاتا ہے — کوئی `kimi/kimi-k2.6` یا `glm/glm-5.2` کبھی ظاہر نہیں ہوتا، اگرچہ وہ بالکل درست روٹ ہوتا ہے۔

OmniRoute کسی بھی فعال ماڈل (اور کومبو) کو `claude/…` آئی ڈی کے تحت مرر کر سکتا ہے تاکہ وہ اس فلٹر سے گزر جائے اور چنندہ میں نظر آئے:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

جب آپ Claude Code میں ان میں سے کوئی ایک منتخب کرتے ہیں، تو OmniRoute روٹنگ سے پہلے `claude/` ریپر ہٹا کر اصل آئی ڈی بحال کر دیتا ہے — ایک حقیقی `claude/<real-claude-model>` آئی ڈی (اصل Claude OAuth پرووائیڈر) ہمیشہ بغیر کسی تبدیلی کے ویسے ہی رہنے دی جاتی ہے۔

پہلے سے طے شدہ طور پر صرف بنیادی آئی ڈیز مرر ہوتی ہیں۔ اختیاری `CATALOG_MIRROR_REFINEMENTS_ENABLED` فیچر فلیگ آن ہونے پر، وہ reasoning-effort ویریئنٹس جو کیٹلاگ پہلے سے فہرست میں رکھتا ہے (مثلاً `codex/gpt-6-sol-high`) کسی بھی دوسری آئی ڈی کی طرح مرر ہوتے ہیں، تاکہ Claude Code ایک واضح effort لیول منتخب کر سکے، اور وہ بلٹ اِن `auto/*` آئی ڈیز جنہیں ریکویسٹ پاتھ مٹیریلائز نہیں کر سکتا، مرر نہیں ہوتیں۔ آیا effort ویریئنٹس اصل میں فہرست میں آتے بھی ہیں یا نہیں، یہ اب بھی `OMNIROUTE_DISABLE_THINKING_LEVEL_VARIANTS` سے کنٹرول ہوتا ہے — مرر کبھی بھی کوئی ایسا ویریئنٹ شامل نہیں کرتا جو بنیادی کیٹلاگ میں موجود نہ ہو۔

**یہ پہلے سے طے شدہ طور پر بند ہے** اور ایک تین درجاتی گیٹ سے کنٹرول ہوتا ہے (سب سے مخصوص درجہ غالب آتا ہے)، تاکہ ایک سادہ OmniRoute ان کلائنٹس کے لیے اپنی کیٹلاگ کبھی دوگنی نہ کرے جو Claude Code استعمال نہیں کرتے:

| درجہ      | کہاں                                                                             |
| --------- | -------------------------------------------------------------------------------- |
| ماڈل      | پرووائیڈر تفصیلی صفحہ → فی ماڈل "Claude Code میں ظاہر کریں" ٹوگل                 |
| پرووائیڈر | پرووائیڈر تفصیلی صفحہ → پرووائیڈر لیول ٹوگل (اس کے تمام ماڈلز کو کور کرتا ہے)    |
| گلوبل     | ترتیبات → فیچر فلیگز → `EXPOSE_CC_DISCOVERY_ALIASES` (پہلے سے طے شدہ طور پر بند) |

`EXPOSE_CC_DISCOVERY_ALIASES` ماحولیاتی متغیر گلوبل درجے کو زبردستی آن کر دیتا ہے اور ڈیش بورڈ اوور رائڈ پر ترجیح رکھتا ہے (جب ایسا ہوتا ہے تو فیچر فلیگز اسکرین ایک "ماحولیاتی متغیر کے ذریعے فعال" نوٹ دکھاتی ہے)۔ فی پرووائیڈر اور فی ماڈل ٹوگلز وہاں سے مزید باریک بینی کرتے ہیں — مثلاً گلوبل بند + Kimi پرووائیڈر آن صرف Kimi کے ماڈلز ظاہر کرتا ہے۔

> ⚠️ **غیر Claude ماڈلز پر ونڈو کی عدم مطابقت۔** Claude Code کسی بھی ایسی آئی ڈی کے لیے 200K کانٹیکسٹ ونڈو فرض کرتا ہے جسے وہ پہچانتا نہیں (وہ `/v1/models` سے اصل ونڈو نہیں پڑھ سکتا)۔ بڑی ونڈو والے ماڈل کے لیے (مثلاً Kimi K2 کی 256K)، `CLAUDE_CODE_AUTO_COMPACT_WINDOW` کو ماڈل کی اصل ونڈو سے کم قدر پر سیٹ کریں تاکہ auto-compaction قبل از وقت متحرک نہ ہو۔ اوپر دیے گئے تیار کردہ پروفائلز یہ کام پہلے سے فی ماڈل کرتے ہیں۔

## ڈیش بورڈ پر آن بورڈنگ بلاک

Claude ٹول کارڈ (**ڈیش بورڈ → CLI کوڈ**) اس انسٹینس کے لیے عین `settings.json` فریگمنٹ کو ڈسکوری الیاس کے معلوماتی بٹن کے ساتھ، ایک کاپی بٹن سمیت رینڈر کرتا ہے:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

بیس URL وہی ہے جسے کارڈ نے ریزولو کیا ہے (بشمول آپ کے درج کردہ کسٹم اوور رائیڈ کے)، اور یہ پہلے ہی نارملائزڈ ہے — نہ `/v1` لاحقہ، نہ آخر میں سلیش۔ **کلید کبھی رینڈر نہیں کی جاتی**: بلاک میں ایک پلیس ہولڈر دیا جاتا ہے، اس لیے اسکرین شاٹ یا پیسٹ کیا گیا اسنیپٹ اسے افشا نہیں کر سکتا۔ اس کی جگہ اپنی کلید پیسٹ کریں۔

کسی بھی ایسے ماڈل کے لیے، جس کی اصل کانٹیکسٹ ونڈو 200K نہیں ہے، اسی `env` بلاک کے تحت `CLAUDE_CODE_AUTO_COMPACT_WINDOW` شامل کریں — Claude Code ہر اس id کے لیے 200K فرض کرتا ہے جسے وہ نہیں پہچانتا، لہٰذا بصورت دیگر خودکار کمپیکشن غلط مقام پر شروع ہوتی ہے (پچھلے سیکشن میں انتباہ دیکھیں)۔ اسنیپٹ بلڈر یہ قدر بھی قبول کرتا ہے، اس لیے ہدف ماڈل کی ونڈو جاننے والا کالر اسے براہِ راست آؤٹ پٹ کر سکتا ہے۔

ماخذ: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (خالص بلڈر، یونٹ ٹیسٹ شدہ)، جسے `ClaudeGatewayOnboardingBlock` رینڈر کرتا ہے۔

### ایک اکاؤنٹ پن کریں (اختیاری)

Claude Code کی ہر درخواست کو کسی ایک مخصوص پرووائیڈر اکاؤنٹ کے ذریعے بھیجنے کے لیے، اسی `env` بلاک میں `ANTHROPIC_CUSTOM_HEADERS` کے ذریعے `x-omniroute-connection` ہیڈر شامل کریں:

```jsonc
"ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>"
```

پرووائیڈر صفحے پر کنکشن کی قطار میں موجود `xxxxxxxx…` چِپ سے id کاپی کریں۔ پن صرف سنگل ماڈل ids (`provider/model`) پر لاگو ہوتا ہے، کومبوز پر نہیں۔ درست فال بیک رویے کے لیے [فی درخواست اکاؤنٹ پننگ](../reference/API_REFERENCE.md#account-pinning-per-request) دیکھیں۔

## پروفائلز (`CLAUDE_CONFIG_DIR`)

Claude Code میں **مقامی پروفائل فائلیں موجود نہیں ہیں** (Codex کی `~/.codex/<name>.config.toml` کے برعکس)۔
اس کا روایتی طریقۂ کار `CLAUDE_CONFIG_DIR` ہے — ہر پروفائل کے لیے ایک علیحدہ کنفیگ ڈائریکٹری،
جس میں اس کی اپنی `settings.json`، اسناد، ہسٹری اور کیش ہوتی ہیں۔

`omniroute setup-claude` فعال `/v1/models` کیٹلاگ حاصل کرتا ہے اور ہر ماڈل کے لیے
`~/.claude/profiles/<name>/settings.json` پر ایک پروفائل لکھتا ہے، جس میں
**`setup-codex` والے ہی نام** (`glm52`، `kimi-k27`، `deepseek-pro`، …) دوبارہ استعمال کیے جاتے ہیں:

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **توثیقی ٹوکن کبھی بھی پروفائل میں نہیں لکھا جاتا۔** اسے
> `omniroute launch --profile <name>` کے ذریعے چلائیں (یہ فعال کانٹیکسٹ سے `ANTHROPIC_AUTH_TOKEN`
> شامل کرتا ہے)، یا خود `ANTHROPIC_AUTH_TOKEN` ایکسپورٹ کریں اور
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude` چلائیں۔

**ماڈل کی دریافت کے بعد خودکار ہم وقت سازی (اختیاری)۔** جب بھی کسی فراہم کنندہ کے ماڈلز کی
ہم وقت سازی فعال کیٹلاگ کو تبدیل کرے، OmniRoute انہی
`~/.claude/profiles/<name>/settings.json` فائلوں کو خودکار طور پر دوبارہ بنا سکتا ہے — تاکہ نئے یا
تبدیل شدہ نام والے ماڈلز کو کمانڈ دوبارہ چلائے بغیر پروفائلز مل جائیں۔ یہ **بطور ڈیفالٹ بند** ہے:
اسے **CLI Code ڈیش بورڈ** ("CLI پروفائل کی خودکار ہم وقت سازی" → Claude Code) سے ٹوگل کریں، یا
`OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` سیٹ کریں (یہ `CLI_ALLOW_CONFIG_WRITES` کا بھی لحاظ
رکھتا ہے، جو بطور ڈیفالٹ فعال ہے)۔ فعال ہونے پر یہ صرف پروفائل فائلیں لکھتا ہے؛ یہ کبھی بھی آپ کی
فعال/ڈیفالٹ Claude کنفیگ، توثیق، یا `~/.claude/settings.json` کو تبدیل نہیں کرتا۔

### پروفائلز بنانا + استعمال کرنا

```bash
# مقامی OmniRoute
omniroute setup-claude

# ریموٹ VPS (ہر پروفائل میں VPS URL شامل کرتا ہے)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# صرف کچھ فراہم کنندگان
omniroute setup-claude --only glm,kimi

# مقامی CLI فراہم کنندگان (zcode، auggie، devin-cli-agentic،
# codex-app-server) کے لیے بھی پروفائلز لکھیں جو اس ہوسٹ پر دریافت نہیں ہوئے (مقامی ہدف کے لیے بطور ڈیفالٹ چھوڑ دیے جاتے ہیں)
omniroute setup-claude --include-local

# لکھے بغیر پیش منظر دیکھیں
omniroute setup-claude --dry-run

# ایک پروفائل چلائیں
omniroute launch --profile kimi-k27
```

## ماڈل کے درجات (اختیاری)

Claude Code صلاحیت کے درجات کی بنیاد پر روٹنگ کرتا ہے۔ اگر آپ ہر درجے کے لیے مختلف فراہم کنندگان استعمال کرنا چاہتے ہیں، تو env /
settings کے ذریعے ہر درجے کو ایک OmniRoute ماڈل سے میپ کریں:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

بصورتِ دیگر، ہر چیز کے لیے ایک ہی `ANTHROPIC_MODEL` (جسے پروفائلز سیٹ کرتے ہیں) استعمال کیا جاتا ہے۔

اضافی فلیگ کی ضرورت نہیں۔ ہر بار چلانے کے لیے `--remote` / `--api-key` کے ذریعے اسے اوور رائیڈ کریں۔

## مسائل کا ازالہ

**Claude Code گیٹ وے کو نظر انداز کرتا ہے** — تصدیق کریں کہ `ANTHROPIC_BASE_URL` میں **کوئی
`/v1` نہیں** ہے اور `claude` کو دوبارہ شروع کریں (env کو آغاز کے وقت صرف ایک بار پڑھا جاتا ہے)۔ `omniroute launch`
یہ کام آپ کے لیے سنبھالتا ہے۔

**`/model` چننے والا خالی ہے / گیٹ وے ماڈلز غائب ہیں** — اس کے لیے Claude Code
v2.1.219+ اور `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` درکار ہیں۔ چننے والے میں صرف `claude*` /
`anthropic*` ماڈل IDs ظاہر ہوتی ہیں؛ کسی بھی دوسرے ماڈل کو
`ANTHROPIC_MODEL=<id>` کے ساتھ زبردستی استعمال کریں (پروفائلز یہی کرتے ہیں)۔

**`400 Ambiguous model 'claude-…'`** — Claude Code ہمیشہ **بغیر سابقے کے**
ماڈل IDs بھیجتا ہے (مثلاً `claude-opus-4-8`)، لہٰذا جب Claude Code (`cc/…`) اور
Claude (`claude/…`) دونوں فراہم کنندگان منسلک ہوں، تو سابقے کے بغیر id دو روٹس سے مطابقت رکھتی ہے اور
OmniRoute اندازہ لگانے سے انکار کر دیتا ہے۔ اسے کسی بھی طریقے سے درست کریں: سابقے والی id کو
`ANTHROPIC_MODEL=cc/claude-opus-4-8` کے ذریعے مقرر کریں، یا **بغیر سابقے والے Claude ماڈلز کے لیے Claude Code کو
ترجیح دیں** فعال کریں — Claude فراہم کنندہ کے صفحے پر موجود ٹوگل، یا
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (بطور ڈیفالٹ بند؛
دیکھیں [ماحول](../reference/ENVIRONMENT.md)) — جو بغیر سابقے والی `claude-*`
IDs کو اس کے بجائے Claude Code کی طرف روٹ کرتا ہے۔ فراہم کنندہ کے واضح سابقے ہمیشہ فوقیت رکھتے ہیں۔

**تصدیقِ شناخت کی خرابیاں** — پروفائل میں کوئی ٹوکن موجود نہیں ہوتا۔ `omniroute launch --profile`
استعمال کریں (یہ اسے داخل کر دیتا ہے) یا `ANTHROPIC_AUTH_TOKEN` ایکسپورٹ کریں۔

**پروفائلز الگ تھلگ نہیں رہتے** — ہر پروفائل ایک الگ `CLAUDE_CONFIG_DIR` ہے؛
تصدیق کریں کہ سیشن کے اندر `echo $CLAUDE_CONFIG_DIR` اس مقام کی طرف اشارہ کرتا ہے:
`~/.claude/profiles/<name>`۔
