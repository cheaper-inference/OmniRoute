> **خلاصہ**: OmniRoute اپنے **مفت** فراہم کنندگان کو ماڈل کے معیار کے لحاظ سے **Arena AI
> (LMArena طرز کے) ELO اسکورز** استعمال کرتے ہوئے درجہ دیتا ہے۔ ڈیش بورڈ میں **مفت فراہم کنندگان کی درجہ بندی** کا صفحہ کھولیں تاکہ معلوم ہو سکے کہ کون سے مفت فراہم کنندگان آپ کے کام کے لیے مضبوط ترین ماڈلز فراہم کرتے ہیں —
> مجموعی طور پر، یا زمرے کے لحاظ سے فلٹر کر کے (کوڈنگ، جائزہ، دستاویزات، ڈی بگنگ)۔

---

## یہ کیا ہے

OmniRoute تین سو چھہتّر (376) فراہم کنندگان رجسٹر کرتا ہے، جن میں سے ایک سو پچپن (155) کیٹلاگ اندراجات **مفت/بغیر تصدیق (free/no-auth)** کے طور پر نشان زد ہیں (no-auth، free-tier OAuth، یا free-tier API key — دیکھیے [مفت ٹائرز گائیڈ](../getting-started/FREE-TIERS-GUIDE.md) اور مکمل [مفت ٹائرز ڈائریکٹری](../reference/FREE_TIERS.md))۔ اصل مسئلہ یہ ہے: مفت فراہم کنندگان ماڈل کے معیار میں بہت زیادہ فرق رکھتے ہیں۔ ایک no-auth فراہم کنندہ جو فرنٹیئر ماڈل فراہم کر رہا ہو، اس سے کہیں زیادہ مفید ہے جو ایک چھوٹا پرانا (legacy) ماڈل دے رہا ہو۔

**Free Provider Rankings (مفت فراہم کنندگان کی درجہ بندی)** اس سوال کا جواب دیتی ہے کہ "**کون سا مفت فراہم کنندہ مجھے بہترین ماڈل دیتا ہے؟**" — یہ ہر مفت فراہم کنندہ کے کیٹلاگ کو **Arena AI لیڈربورڈ** سے حاصل شدہ **عوامی ذرائع پر مبنی معیار کے اسکورز** (انسانی ترجیح پر مبنی ELO، وہی تصور جو LMArena چیٹ بوٹ ارینا کے پیچھے ہے) کے ساتھ ملا کر کرتی ہے۔ اس کے بعد فراہم کنندگان کو ان کے **بہترین مفت ماڈل** کی طاقت کی بنیاد پر درجہ دیا جاتا ہے۔

یہ درجہ بندی تین حقیقی ذرائع سے شمار کی جاتی ہے:

1. مفت فراہم کنندگان کی فہرستیں — `NOAUTH_PROVIDERS`، کے ساتھ ساتھ `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` کے وہ اندراجات جن پر `hasFree` کا جھنڈا لگا ہوا ہے
   (`src/shared/constants/providers.ts`)۔
2. ہر فراہم کنندہ کا ماڈل کیٹلاگ، جو فراہم کنندہ رجسٹری سے آتا ہے
   (`open-sse/config/providerRegistry.ts`)۔
3. ELO سے اخذ کردہ ٹاسک-فِٹ اسکورز جو Arena ELO سنک انجن
   (`src/lib/arenaEloSync.ts`) کے ذریعے `model_intelligence` ڈیٹابیس ٹیبل میں محفوظ کیے جاتے ہیں۔

جوائن (ملانے) کی منطق `src/lib/freeProviderRankings.ts` میں موجود ہے۔

## رسائی کا طریقہ

### ڈیش بورڈ صفحہ

ڈیش بورڈ کھولیں اور **لاگتیں → مفت فراہم کنندگان کی درجہ بندی** پر جائیں، یا براہِ راست یہاں جائیں:

```
/dashboard/free-provider-rankings
```

یہ صفحہ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) درج ذیل دکھاتا ہے:

- بہترین درجہ رکھنے والے مفت فراہم کنندگان کے لیے **سرفہرست 3 کا پوڈیم** (🥇 🥈 🥉)۔
- ایک مکمل **درجہ بندی کی جدول**، جس کے کالم ہیں: **درجہ**، **فراہم کنندہ**، **بہترین ماڈل**،
  **اسکور**، **اوسط اسکور**، **ماڈلز**، **قسم**۔
- **زمرہ فلٹر بٹنز**: _تمام زمرے_، _ڈیفالٹ_، _کوڈنگ_، _جائزہ_،
  _دستاویزات_، _ڈی بگنگ_۔

ہر فراہم کنندہ کا **قسم** بیج بتاتا ہے کہ وہ کس طرح مفت ہے:

| بیج      | مطلب                                              |
| -------- | ------------------------------------------------- |
| `NOAUTH` | ہمیشہ مفت، کسی اسناد کی ضرورت نہیں                |
| `OAUTH`  | مفت درجے (`hasFree`) کے ساتھ OAuth فراہم کنندہ    |
| `APIKEY` | مفت درجے (`hasFree`) کے ساتھ API کلید فراہم کنندہ |

اسکورز خام اعداد کے بجائے انسانی طور پر قابلِ فہم لیبلز کی صورت میں دکھائے جاتے ہیں (مثلاً _اعلیٰ ترین_، _شاندار_، _بہت اچھا_،
_اچھا_، _اوسط_)، کیونکہ بنیادی قدر فیصد نہیں بلکہ معیار کی نسبتی
درجہ بندی ہے۔

### API اینڈ پوائنٹ

یہ صفحہ ایک عوامی، صرف پڑھنے کے اینڈ پوائنٹ
(`src/app/api/free-provider-rankings/route.ts`) سے تقویت پاتا ہے:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

استفساری پیرامیٹرز (Zod کے ذریعے توثیق شدہ):

| پیرامیٹر   | قسم    | ڈیفالٹ      | نوٹس                                                                                                              |
| ---------- | ------ | ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `category` | اسٹرنگ | (کوئی نہیں) | `default`، `coding`، `review`، `documentation`، `debugging` میں سے ایک۔ مشترکہ درجہ بندی کے لیے اسے شامل نہ کریں۔ |
| `limit`    | عدد    | `50`        | `1–100` کی حد تک محدود کیا جاتا ہے۔                                                                               |

جواب کی ساخت:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` اصل Arena ELO قدر ہے؛ `score` معمول پر لائی گئی کام سے مطابقت کی قدر ہے
(ذیل میں ملاحظہ کریں)۔ جن فراہم کنندگان کے کسی ماڈل کا اسکور موجود نہ ہو، انہیں جواب سے خارج کر دیا جاتا ہے۔

## اسکور کیسے کام کرتے ہیں

### ماخذ: Arena AI لیڈر بورڈ

Arena ELO سنک انجن (`src/lib/arenaEloSync.ts`) Arena AI لیڈر بورڈ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) سے دو لیڈر بورڈز — `text`
اور `code` — حاصل کرتا ہے۔ جب وہ API کوئی قابلِ استعمال بورڈ واپس نہیں کرتی، تو انجن
Hugging Face datasets-server پر موجود سرکاری `lmarena-ai/leaderboard-dataset` کی طرف لوٹتا
ہے (`src/lib/arenaEloHfSource.ts`، CC-BY-4.0؛ `overall` → `text`،
`coding` → `code`)؛ `GET /api/intelligence/sync` یہ `activeSource`، `lastError` اور
`lastFailedAt` رپورٹ کرتا ہے۔ ہر لیڈر بورڈ اندراج کے ساتھ ماڈل کا نام، وینڈر، ELO
`score`، کنفیڈنس انٹروal، اور ووٹوں کی تعداد ہوتی ہے۔

لیڈر بورڈ کیٹیگریز کا نقشہ OmniRoute ٹاسک کیٹیگریز پر اس طرح بنتا ہے:

| Arena لیڈر بورڈ | OmniRoute ٹاسک کیٹیگریز                           |
| --------------- | ------------------------------------------------- |
| `text`          | `default`، `review`، `documentation`، `debugging` |
| `code`          | `coding`                                          |

### نارملائزیشن (ٹاسک-فِٹ اسکور)

خام ELO اسکورز کو فی لیڈر بورڈ نارملائز کیا جاتا ہے تاکہ **`[0.4, 0.98]` کے درمیان ایک ٹاسک-فِٹ ویلیو** بنے:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

اسکور کبھی `0` یا `1` تک نہیں پہنچتا، تاکہ صارف کی اوور رائڈز کے لیے گنجائش باقی رہے۔ یہی
وہ `score` فیلڈ ہے جو آپ کو API رسپانس میں نظر آتی ہے اور وہی لیبل ہے جو ڈیش بورڈ پر دکھایا
جاتا ہے۔

### اعتماد (کنفیڈنس)

ہر اندراج کو Arena ووٹوں کی تعداد کی بنیاد پر ایک اعتماد کی سطح ملتی ہے:

| اعتماد   | ووٹ     |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### اسٹوریج اور تازگی

نارملائز شدہ اندراجات `model_intelligence` DB ٹیبل میں
`source = "arena_elo"` کے ساتھ لکھے جاتے ہیں (`src/lib/db/modelIntelligence.ts`)۔ اندراجات
**7 دن بعد ختم ہو جاتے ہیں**، اس لیے جو پرووائیڈر سنک کرنا بند کر دے، وہ پرانا ڈیٹا
دینے کے بجائے بالآخر فہرست سے باہر ہو جاتا ہے۔

سنک **ڈیفالٹ طور پر چالو** رہتی ہے:

- یہ سرور اسٹارٹ اپ پر ایک بار چلتی ہے اور پھر ایک وقفے وقفے کے ٹائمر پر
  (`src/lib/arenaEloSync.ts`، جو `src/instrumentation-node.ts` سے جڑی ہوئی ہے)۔
- یہ **غیر بلاکنگ ہے اور کبھی بھی مہلک نہیں** — اگر اپ اسٹریم فِچ ناکام ہو جائے، تو
  OmniRoute چلتا رہتا ہے اور رینکنگز بس آخری صحیح ڈیٹا (یا ایک خالی حالت) دکھاتی ہیں۔

دو ماحول متغیرات (environment variables) اسے کنٹرول کرتے ہیں (دستاویز
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) میں):

| متغیر                     | ڈیفالٹ        | مقصد                                                 |
| ------------------------- | ------------- | ---------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | آؤٹ باؤنڈ سنک سے باہر نکلنے کے لیے `false` سیٹ کریں۔ |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | سنک کا وقفہ، سیکنڈز میں۔                             |

### دستی سنک / اسٹیٹس / صاف کرنا

آپریٹرز کے لیے، ایک مستند انتظامی اینڈ پوائنٹ دستی کنٹرول فراہم کرتا ہے
(`src/app/api/intelligence/sync/route.ts` — انتظامی تصدیق درکار ہے):

```
GET    /api/intelligence/sync          # موجودہ سنک اسٹیٹس (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # دستی سنک شروع کریں؛ body: { "dryRun": true } بغیر لکھے پیش منظر کے لیے
DELETE /api/intelligence/sync          # تمام سنک شدہ arena_elo intelligence اندراجات صاف کریں
```

اگر رینکنگز کا صفحہ خالی ہو، تو ایک دستی `POST /api/intelligence/sync` (یا بس
سرور کو دوبارہ شروع کرنا) اسے دوبارہ بھر دیتا ہے۔

### ماڈلز کا لیڈر بورڈ سے میلان

رجسٹری ماڈل IDs اور Arena ماڈل نام ہمیشہ بالکل میل نہیں کھاتے۔ رینکنگ لچکدار میلان
استعمال کرتی ہے (`src/lib/freeProviderRankings.ts` میں `findMatchingIntelligence`):

1. نارملائز شدہ ماڈل ID پر بالکل میل۔
2. آخری ورژن سفکس ہٹانے کے بعد میل (مثلاً `kimi-k2.6` → `kimi-k2`)۔
3. پریفکس میل (لیڈر بورڈ کا کوئی ماڈل نام رجسٹری ID کا پریفکس ہو)۔

سنک کی جانب، معروف وینڈر پریفکسز (`anthropic/`، `openai/`، `google/`، …) ہٹا دیے
جاتے ہیں اور ایک چھوٹا سا alias نقشہ باقاعدہ (canonical) ناموں کو ان شکلوں میں پھیلاتا ہے جو
OmniRoute اندرونی طور پر استعمال کرتا ہے، تاکہ ماڈل کسی بھی نام کے تحت قابلِ تلاش رہیں۔

### پرووائیڈر کی رینکنگ کیسے ہوتی ہے

ہر مفت پرووائیڈر کے لیے، انجن اس کے کیٹلاگ کے ہر ماڈل کو اسکور کرتا ہے، پھر:

- **Top Model (ٹاپ ماڈل)** = پرووائیڈر کا سب سے زیادہ اسکور حاصل کرنے والا ماڈل۔
- **Avg Score (اوسط اسکور)** = اس پرووائیڈر کے تمام اسکور شدہ ماڈلز کا اوسط اسکور۔
- **Models (ماڈلز)** = پرووائیڈر کے کتنے ماڈلز کے پاس Arena اسکور موجود تھا۔

پرووائیڈرز کو پہلے **ٹاپ ماڈل اسکور** کے حساب سے، پھر اوسط اسکور کے حساب سے ترتیب دیا
جاتا ہے۔ یہ اس پرووائیڈر کو فائدہ دیتا ہے جو کم از کم ایک مضبوط مفت ماڈل پیش کرتا ہے۔

## مفت فراہم کنندگان منتخب کرنے کے لیے اس کا استعمال

1. **درست زمرہ منتخب کریں۔** ایجنٹ پر مبنی/کوڈ ورک لوڈز کے لیے **کوڈنگ** فلٹر استعمال کریں، یا
   عمومی چیٹ کے لیے اسے **تمام زمرے** / **ڈیفالٹ** پر رہنے دیں۔ ایک ہی فراہم کنندہ
   مختلف زمروں میں مختلف درجہ حاصل کر سکتا ہے، کیونکہ ہر لیڈر بورڈ پر اس کا سرفہرست ماڈل مختلف ہوتا ہے۔
2. **ایک مرتبہ کی سیٹ اپ کے لیے پوڈیم کو ترجیح دیں۔** اگر آپ صرف ایک یا دو مفت
   فراہم کنندگان سے جڑنا چاہتے ہیں، تو اپنے زمرے میں سرفہرست درجہ رکھنے والوں سے آغاز کریں۔
3. **قسم کا بیج چیک کریں۔** `NOAUTH` فراہم کنندگان سے جڑنا سب سے تیز ہے (کسی
   اسناد کی ضرورت نہیں)۔ `OAUTH` / `APIKEY` کے مفت درجات کے لیے فوری سائن اپ درکار ہوتا ہے، لیکن اکثر یہ
   زیادہ طاقتور ماڈلز تک رسائی فراہم کرتے ہیں۔ کنکشن کے مراحل کے لیے [مفت درجات کی گائیڈ](../getting-started/FREE-TIERS-GUIDE.md)
   دیکھیں۔
4. **متعدد فراہم کنندگان سے جڑیں اور Auto-Combo کو فیصلہ کرنے دیں۔** Arena ELO کا وہی ڈیٹا جو
   اس صفحے کو تقویت دیتا ہے، Auto-Combo اسکورنگ انجن کے **کام کے لیے موزونیت کے عامل** کو بھی فراہم کیا جاتا ہے
   (`open-sse/services/autoCombo/taskFitness.ts`، ترجیحی ترتیب
   `user_override → arena_elo → models_dev_tier → static table`)۔ لہٰذا سرفہرست مفت فراہم کنندگان سے جڑنے کے بعد،
   `model: "auto"` (مثلاً `auto/coding`) کے ساتھ روٹنگ ہر درخواست کے لیے
   خودکار طور پر اعلیٰ معیار کے مفت ماڈلز کو ترجیح دے گی۔ مکمل 16 عاملی اسکورنگ کے لیے
   [Auto-Combo](../routing/AUTO-COMBO.md) دیکھیں۔
