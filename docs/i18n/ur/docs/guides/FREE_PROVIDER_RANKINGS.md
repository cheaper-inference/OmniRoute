> **خلاصہ**: OmniRoute اپنے **مفت** فراہم کنندگان کو ماڈل کے معیار کے لحاظ سے **Arena AI
> (LMArena طرز کے) ELO اسکورز** استعمال کرتے ہوئے درجہ دیتا ہے۔ ڈیش بورڈ میں **مفت فراہم کنندگان کی درجہ بندی** کا صفحہ کھولیں تاکہ معلوم ہو سکے کہ کون سے مفت فراہم کنندگان آپ کے کام کے لیے مضبوط ترین ماڈلز فراہم کرتے ہیں —
> مجموعی طور پر، یا زمرے کے لحاظ سے فلٹر کر کے (کوڈنگ، جائزہ، دستاویزات، ڈی بگنگ)۔

---

## یہ کیا ہے

OmniRoute 376 فراہم کنندگان رجسٹر کرتا ہے، جن میں کیٹلاگ کی 155 ایسی اندراجات شامل ہیں جنہیں **مفت/بغیر تصدیق**
کے طور پر نشان زد کیا گیا ہے (بغیر تصدیق،
مفت درجے کا OAuth، یا مفت درجے کی API کلید — دیکھیے
[مفت درجات کی رہنما دستاویز](../getting-started/FREE-TIERS-GUIDE.md) اور مکمل
[مفت درجات کی ڈائریکٹری](../reference/FREE_TIERS.md))۔ مسئلہ یہ ہے: مفت فراہم کنندگان کے ماڈلز کا معیار
بہت زیادہ مختلف ہوتا ہے۔ کسی جدید ترین ماڈل کو پیش کرنے والا بغیر تصدیق کا فراہم کنندہ،
کسی چھوٹے پرانے ماڈل کو پیش کرنے والے فراہم کنندہ سے کہیں زیادہ مفید ہوتا ہے۔

**مفت فراہم کنندگان کی درجہ بندیاں** اس سوال کا جواب دیتی ہیں کہ "**کون سا مفت فراہم کنندہ مجھے بہترین ماڈل دیتا ہے؟**"،
جس کے لیے ہر مفت فراہم کنندہ کے کیٹلاگ کو **اجتماعی طور پر حاصل کردہ معیار کے اسکورز** کے ساتھ جوڑا جاتا ہے، جو
**Arena AI لیڈر بورڈ** سے لیے جاتے ہیں (انسانی ترجیحات پر مبنی ELO، وہی تصور جو LMArena
چیٹ بوٹ ایرینا کے پسِ پشت ہے)۔ پھر فراہم کنندگان کو ان کے **بہترین مفت ماڈل** کی قابلیت کے مطابق درجہ دیا جاتا ہے۔

درجہ بندی کا حساب تین حقیقی ذرائع سے لگایا جاتا ہے:

1. مفت فراہم کنندگان کی فہرستیں — `NOAUTH_PROVIDERS`، نیز `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` کی وہ اندراجات جن پر `hasFree` نشان زد ہے
   (`src/shared/constants/providers.ts`)۔
2. فراہم کنندہ رجسٹری سے ہر فراہم کنندہ کا ماڈل کیٹلاگ
   (`open-sse/config/providerRegistry.ts`)۔
3. ELO سے اخذ کردہ کام کے لیے موزونیت کے اسکورز، جنہیں Arena ELO مطابقت سازی انجن
   (`src/lib/arenaEloSync.ts`) کے ذریعے `model_intelligence` DB ٹیبل میں محفوظ کیا جاتا ہے۔

جوڑنے کی منطق `src/lib/freeProviderRankings.ts` میں موجود ہے۔

## رسائی کا طریقہ

### ڈیش بورڈ صفحہ

ڈیش بورڈ کھولیں اور **لاگتیں → مفت فراہم کنندگان کی درجہ بندی** پر جائیں، یا براہِ راست یہاں جائیں:

```
/dashboard/free-provider-rankings
```

یہ صفحہ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) درج ذیل دکھاتا ہے:

- بہترین درجہ رکھنے والے مفت فراہم کنندگان کے لیے **سرفہرست 3 کا پوڈیم** (🥇 🥈 🥉)۔
- ایک مکمل **درجہ بندی کی جدول**، جس کے کالم ہیں: **درجہ**، **فراہم کنندہ**، **بہترین ماڈل**،
  **اسکور**، **اوسط اسکور**، **ماڈلز**، **قسم**۔
- **زمرہ فلٹر بٹنز**: _تمام زمرے_، _ڈیفالٹ_، _کوڈنگ_، _جائزہ_،
  _دستاویزات_، _ڈی بگنگ_۔

ہر فراہم کنندہ کا **قسم** بیج بتاتا ہے کہ وہ کس طرح مفت ہے:

| بیج      | مطلب                                              |
| -------- | ------------------------------------------------- |
| `NOAUTH` | ہمیشہ مفت، کسی اسناد کی ضرورت نہیں                |
| `OAUTH`  | مفت درجے (`hasFree`) کے ساتھ OAuth فراہم کنندہ    |
| `APIKEY` | مفت درجے (`hasFree`) کے ساتھ API کلید فراہم کنندہ |

اسکورز خام اعداد کے بجائے انسانی طور پر قابلِ فہم لیبلز کی صورت میں دکھائے جاتے ہیں (مثلاً _اعلیٰ ترین_، _شاندار_، _بہت اچھا_،
_اچھا_، _اوسط_)، کیونکہ بنیادی قدر فیصد نہیں بلکہ معیار کی نسبتی
درجہ بندی ہے۔

### API اینڈ پوائنٹ

یہ صفحہ ایک عوامی، صرف پڑھنے کے اینڈ پوائنٹ
(`src/app/api/free-provider-rankings/route.ts`) سے تقویت پاتا ہے:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

استفساری پیرامیٹرز (Zod کے ذریعے توثیق شدہ):

| پیرامیٹر   | قسم    | ڈیفالٹ      | نوٹس                                                                                                              |
| ---------- | ------ | ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `category` | اسٹرنگ | (کوئی نہیں) | `default`، `coding`، `review`، `documentation`، `debugging` میں سے ایک۔ مشترکہ درجہ بندی کے لیے اسے شامل نہ کریں۔ |
| `limit`    | عدد    | `50`        | `1–100` کی حد تک محدود کیا جاتا ہے۔                                                                               |

جواب کی ساخت:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` اصل Arena ELO قدر ہے؛ `score` معمول پر لائی گئی کام سے مطابقت کی قدر ہے
(ذیل میں ملاحظہ کریں)۔ جن فراہم کنندگان کے کسی ماڈل کا اسکور موجود نہ ہو، انہیں جواب سے خارج کر دیا جاتا ہے۔

## اسکور کیسے کام کرتے ہیں

### ماخذ: Arena AI لیڈربورڈ

Arena ELO سنک انجن (`src/lib/arenaEloSync.ts`) دو لیڈربورڈز — `text`
اور `code` — Arena AI لیڈربورڈ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) سے حاصل کرتا ہے۔ جب وہ API
کوئی قابلِ استعمال بورڈ واپس نہیں کرتا، تو انجن Hugging Face datasets-server پر موجود آفیشل
`lmarena-ai/leaderboard-dataset` کی طرف رجوع کرتا ہے
(`src/lib/arenaEloHfSource.ts`، CC-BY-4.0؛ `overall` → `text`،
`coding` → `code`)؛ `GET /api/intelligence/sync` `activeSource`، `lastError` اور
`lastFailedAt` کی رپورٹ دیتا ہے۔ ہر لیڈربورڈ اندراج میں
ماڈل کا نام، وینڈر، ELO `score`، کانفیڈنس انٹرول، اور ووٹ کاؤنٹ شامل ہوتا ہے۔

لیڈربورڈ کیٹیگریز OmniRoute ٹاسک کیٹیگریز سے منسلک ہوتی ہیں:

| Arena لیڈربورڈ | OmniRoute ٹاسک کیٹیگریز                           |
| -------------- | ------------------------------------------------- |
| `text`         | `default`، `review`، `documentation`، `debugging` |
| `code`         | `coding`                                          |

### نارملائزیشن (ٹاسک-فِٹ اسکور)

خام ELO اسکورز ہر لیڈربورڈ کے لیے **`[0.4, 0.98]` کی حد میں ٹاسک-فِٹ ویلیو** میں نارملائز کیے جاتے ہیں:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

اسکور کبھی `0` یا `1` تک نہیں پہنچتا، تاکہ صارف کی اووررائڈز کے لیے گنجائش باقی رہے۔ یہ وہی
`score` فیلڈ ہے جو آپ کو API رسپانس میں نظر آتی ہے اور ڈیش بورڈ پر دکھایا جانے والا لیبل ہے۔

### کانفیڈنس

ہر اندراج کو Arena ووٹ کاؤنٹ کی بنیاد پر ایک کانفیڈنس لیول ملتا ہے:

| کانفیڈنس | ووٹس    |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### اسٹوریج اور تازگی

نارملائز شدہ اندراجات `source = "arena_elo"` کے ساتھ
`model_intelligence` DB ٹیبل میں لکھے جاتے ہیں (`src/lib/db/modelIntelligence.ts`)۔ اندراجات
**7 دن بعد ایکسپائر ہو جاتے ہیں**، لہٰذا جو پرووائیڈر سنک کرنا بند کر دیتا ہے وہ بالآخر
فہرست سے باہر ہو جاتا ہے، بجائے اس کے کہ پرانا ڈیٹا پیش کرتا رہے۔

سنک **ڈیفالٹ طور پر فعال** چلتا ہے:

- یہ سرور اسٹارٹ اپ پر ایک بار چلتا ہے اور پھر وقفے وقفے والے ٹائمر پر
  (`src/lib/arenaEloSync.ts`، `src/instrumentation-node.ts` سے منسلک)۔
- یہ **نان-بلاکنگ ہے اور کبھی فیٹل نہیں** — اگر اپ اسٹریم فیچ ناکام ہو جائے، تو OmniRoute
  چلتا رہتا ہے اور رینکنگز صرف آخری اچھا ڈیٹا دکھاتی ہیں (یا خالی اسٹیٹ)۔

دو اینوائرمنٹ ویری ایبلز اسے کنٹرول کرتے ہیں (دستاویزات:
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| ویری ایبل                 | ڈیفالٹ        | مقصد                                                 |
| ------------------------- | ------------- | ---------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | آؤٹ باؤنڈ سنک سے باہر نکلنے کے لیے `false` سیٹ کریں۔ |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | سنک کا وقفہ، سیکنڈز میں۔                             |

### دستی سنک / اسٹیٹس / کلیئر

آپریٹرز کے لیے، ایک تصدیق شدہ مینجمنٹ اینڈ پوائنٹ دستی کنٹرول فراہم کرتا ہے
(`src/app/api/intelligence/sync/route.ts` — مینجمنٹ auth درکار ہے):

```
GET    /api/intelligence/sync          # موجودہ سنک اسٹیٹس (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # دستی سنک شروع کریں؛ body: { "dryRun": true } بغیر لکھے پیش منظر کے لیے
DELETE /api/intelligence/sync          # تمام سنک شدہ arena_elo intelligence اندراجات کو صاف کریں
```

اگر رینکنگز کا صفحہ خالی ہو، تو دستی `POST /api/intelligence/sync` (یا بس
سرور کو دوبارہ شروع کرنا) اسے دوبارہ بھر دیتا ہے۔

### ماڈلز کو لیڈربورڈ سے ملانا

رجسٹری ماڈل IDs اور Arena ماڈل نام ہمیشہ بالکل میل نہیں کھاتے۔ رینکنگ لچکدار
ملاپ استعمال کرتی ہے (`src/lib/freeProviderRankings.ts` میں `findMatchingIntelligence`):

1. نارملائزڈ ماڈل ID پر عین ملاپ۔
2. آخری ورژن سفکس ہٹانے کے بعد ملاپ (مثلاً `kimi-k2.6` → `kimi-k2`)۔
3. پری فکس ملاپ (لیڈربورڈ ماڈل کا نام رجسٹری ID کا پری فکس ہو)۔

سنک والے جانب، معلوم وینڈر پری فکسز (`anthropic/`، `openai/`، `google/`, …)
ہٹا دیے جاتے ہیں اور ایک چھوٹا alias map کینونیکل ناموں کو ان ویرینٹس میں پھیلا دیتا ہے
جو OmniRoute اندرونی طور پر استعمال کرتا ہے، تاکہ ماڈلز کسی بھی نام کے تحت قابلِ تلاش رہیں۔

### پرووائیڈر کی رینکنگ کیسے ہوتی ہے

ہر مفت پرووائیڈر کے لیے، انجن اس کے کیٹلاگ کے ہر ماڈل کو اسکور کرتا ہے، پھر:

- **بہترین ماڈل** = پرووائیڈر کا سب سے زیادہ اسکور کرنے والا ماڈل۔
- **اوسط اسکور** = اس پرووائیڈر کے تمام اسکور شدہ ماڈلز کا اوسط اسکور۔
- **ماڈلز** = پرووائیڈر کے کتنے ماڈلز کے پاس Arena اسکور موجود تھا۔

پرووائیڈرز کو پہلے **ٹاپ-ماڈل اسکور** کے لحاظ سے ترتیب دیا جاتا ہے، پھر اوسط اسکور کے
لحاظ سے۔ یہ اس پرووائیڈر کو فائدہ دیتا ہے جو کم از کم ایک مضبوط مفت ماڈل پیش کرتا ہے۔

## مفت فراہم کنندگان منتخب کرنے کے لیے اس کا استعمال

1. **درست زمرہ منتخب کریں۔** ایجنٹ پر مبنی/کوڈ ورک لوڈز کے لیے **کوڈنگ** فلٹر استعمال کریں، یا
   عمومی چیٹ کے لیے اسے **تمام زمرے** / **ڈیفالٹ** پر رہنے دیں۔ ایک ہی فراہم کنندہ
   مختلف زمروں میں مختلف درجہ حاصل کر سکتا ہے، کیونکہ ہر لیڈر بورڈ پر اس کا سرفہرست ماڈل مختلف ہوتا ہے۔
2. **ایک مرتبہ کی سیٹ اپ کے لیے پوڈیم کو ترجیح دیں۔** اگر آپ صرف ایک یا دو مفت
   فراہم کنندگان سے جڑنا چاہتے ہیں، تو اپنے زمرے میں سرفہرست درجہ رکھنے والوں سے آغاز کریں۔
3. **قسم کا بیج چیک کریں۔** `NOAUTH` فراہم کنندگان سے جڑنا سب سے تیز ہے (کسی
   اسناد کی ضرورت نہیں)۔ `OAUTH` / `APIKEY` کے مفت درجات کے لیے فوری سائن اپ درکار ہوتا ہے، لیکن اکثر یہ
   زیادہ طاقتور ماڈلز تک رسائی فراہم کرتے ہیں۔ کنکشن کے مراحل کے لیے [مفت درجات کی گائیڈ](../getting-started/FREE-TIERS-GUIDE.md)
   دیکھیں۔
4. **متعدد فراہم کنندگان سے جڑیں اور Auto-Combo کو فیصلہ کرنے دیں۔** Arena ELO کا وہی ڈیٹا جو
   اس صفحے کو تقویت دیتا ہے، Auto-Combo اسکورنگ انجن کے **کام کے لیے موزونیت کے عامل** کو بھی فراہم کیا جاتا ہے
   (`open-sse/services/autoCombo/taskFitness.ts`، ترجیحی ترتیب
   `user_override → arena_elo → models_dev_tier → static table`)۔ لہٰذا سرفہرست مفت فراہم کنندگان سے جڑنے کے بعد،
   `model: "auto"` (مثلاً `auto/coding`) کے ساتھ روٹنگ ہر درخواست کے لیے
   خودکار طور پر اعلیٰ معیار کے مفت ماڈلز کو ترجیح دے گی۔ مکمل 16 عاملی اسکورنگ کے لیے
   [Auto-Combo](../routing/AUTO-COMBO.md) دیکھیں۔
