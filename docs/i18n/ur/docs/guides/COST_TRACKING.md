OmniRoute ہر درخواست کی لاگت کا تخمینہ کیسے لگاتا، اسے ریکارڈ کرتا، اور اس کی رپورٹ
کیسے پیش کرتا ہے — اور ڈیش بورڈ پر موجود عدد **بچت کا ٹریکر** کیوں ہے، بل کیوں نہیں۔

یہ بھی دیکھیں: [صارف کی رہنما کتاب](./USER_GUIDE.md) · [خصوصیات کی گیلری](./FEATURES.md)

## یہ کیا ہے (اور کیا نہیں ہے)

OmniRoute ٹوکن کی تعداد کو ماڈل کے نرخوں سے ضرب دے کر ہر تکمیل کے لیے فی درخواست
USD لاگت منسوب کرتا ہے۔ یہ اعداد **لاگتیں** ڈیش بورڈ، `omniroute cost` / `omniroute usage`
CLI، CSV/JSON برآمدات، اور فی API کلید بجٹ کو تقویت دیتے ہیں۔

> **ڈیش بورڈ کی "لاگت" بچت کا ٹریکر ہے، بل نہیں۔** OmniRoute آپ سے کبھی رقم وصول نہیں کرتا
> — یہ آپ کی درخواستوں کو ان فراہم کنندگان تک بھیجتا ہے جنہیں آپ پہلے ہی منسلک کر چکے ہیں
> (آپ کی اپنی سبسکرپشنز، مفت درجات، اور API کلیدیں)۔ مفت ماڈلز پر مکمل طور پر جمع ہونے والی
> "$290 کل لاگت" کا مطلب ہے کہ تقریباً **$290 آپ نے کسی بامعاوضہ API کو ادا _نہیں_ کیے**۔
> یہ عدد اس بات کا _تخمینہ_ ہے کہ معیاری فہرستی نرخوں پر اسی ٹریفک کی لاگت کتنی ہوتی، تاکہ
> آپ دیکھ سکیں کہ آپ کا استعمال کہاں مرتکز ہے اور سستے/مفت فراہم کنندگان تک روٹنگ سے آپ
> کتنی بچت کر رہے ہیں۔

یہ وضاحت منصوبے کی [README](../../README.md) میں براہِ راست بیان کی گئی ہے ("ڈیش بورڈ کی
'لاگت' بچت کا ٹریکر ہے، بل نہیں")۔

چونکہ یہ عدد ایک تخمینہ ہے:

- یہ ہر ماڈل کے لیے OmniRoute کے پاس موجود قیمتوں کے جدول پر منحصر ہے۔ قیمت کا اندراج نہ
  رکھنے والا ماڈل `0` لاگت شامل کرتا ہے (ایکسپلورر میں یہ "پرانا / مفت" قطار کے طور پر دکھائی دیتا ہے)۔
- مفت درجے اور سبسکرپشن کی ٹریفک پر بھی ایک _تخمینی_ لاگت جمع ہوتی ہے — یہ وہ رقم ہے
  جو آپ بچا رہے ہیں، نہ کہ وہ رقم جو آپ پر واجب الادا ہے۔

## اخراجات کا اندازہ کیسے لگایا جاتا ہے۔

### قیمت کا ذریعہ

قیمتیں [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) میں ضم شدہ قیمتوں کے جدول سے آتی ہیں، اس ترتیب میں ترجیح (**سب سے پہلے** ):

1. **صارف اوور رائیڈ کرتا ہے۔** — قیمتیں ڈیش بورڈ میں یا `PATCH /api/pricing` ( `pricing` نام کی جگہ) کے ذریعے سیٹ کی جاتی ہیں۔
2. **models.dev مطابقت پذیری** — قیمتوں کا تعین `https://models.dev/api.json` ( `models_dev_pricing` نام کی جگہ) سے حاصل کیا گیا۔
3. **LiteLLM مطابقت پذیری** — قیمتیں LiteLLM کے عوامی `model_prices_and_context_window.json` ( `pricing_synced` نام کی جگہ) سے حاصل کی گئیں۔
4. **ہارڈ کوڈ شدہ ڈیفالٹس** — شرحیں [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) میں بھیج دی گئیں۔

اسی provider/model کے لیے، اعلی ترجیحی پرتوں کی قدریں نچلی تہوں میں مماثل فیلڈز کو اوور رائٹ کرتی ہیں۔ اوپری پرت سے غیر موجود فیلڈز اب بھی نچلی پرت سے آسکتے ہیں۔ جب دونوں آزاد مطابقت پذیر کام ایک ہی وقت میں چلتے ہیں تب بھی آرڈر طے ہوتا ہے۔ `GET /api/pricing?includeSources=1` `pricing` اور `sourceMap` لوٹاتا ہے، جن کے فی ماڈل لیبلز (`user`, `modelsDev`, `litellm`, `default`) اس ماڈل پر مشتمل سب سے زیادہ ترجیحی پرت کی نشاندہی کرتے ہیں۔

**LiteLLM مطابقت پذیری** آپٹ ان ہے، بطور ڈیفالٹ غیر فعال ہے۔ اس کے ماحولیاتی متغیرات ( [`.env.example`](../../.env.example) دیکھیں) ہیں:

| Env var                 | طے شدہ    | مقصد                                                                              |
| ----------------------- | --------- | --------------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | پس منظر LiteLLM قیمتوں کی مطابقت پذیری کو فعال کریں۔                              |
| `PRICING_SYNC_INTERVAL` | `86400`   | مطابقت پذیری وقفہ سیکنڈوں میں (روزانہ)۔                                           |
| `PRICING_SYNC_SOURCES`  | `litellm` | صرف اس مطابقت پذیری کے لیے ماخذ کا انتخاب؛ فی الحال صرف `litellm` تعاون یافتہ ہے۔ |

**models.dev مطابقت پذیری** LiteLLM مطابقت پذیری سے الگ ہے اور بطور ڈیفالٹ غیر فعال بھی ہے۔ اسے ترتیبات میں فعال کریں (models.dev sync) یا ان متغیرات کا استعمال کریں:

| Env var                    | طے شدہ      | مقصد                                                                                                                                            |
| -------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(غیر سیٹ)_ | سیٹنگز ٹوگل کے بعد سیٹنگ سیٹ نہیں کرتا ہے۔ `1/true/on/yes` کو چالو کرتا ہے اور `0/false/off/no` کو آف کرتا ہے (چاہے ترتیبات اسے فعال کرتی ہوں)۔ |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`     | ڈیفالٹ models.dev سنک وقفہ سیکنڈوں میں (روزانہ)۔                                                                                                |

`PRICING_SYNC_SOURCES` کرتا ہے۔**نہیں** models.dev کو فعال کریں؛ یہ صرف LiteLLM مطابقت پذیری کو کنٹرول کرتا ہے۔ صارف کے اوور رائڈ کو حذف کرنے سے یا تو مطابقت پذیر نام کی جگہ صاف نہیں ہوتی ہے۔ اگلی دستیاب قیمتوں کی پرت مؤثر ہو جاتی ہے۔ غیر قیمتی ماڈل کے لیے، دستی اوور رائڈ شامل کرنے سے پہلے مطابقت پذیری کی ترتیبات اور `sourceMap` دونوں کو چیک کریں۔

### لاگت کا فارمولا

[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`):

- **ان پٹ ٹوکنز** (مائنس کیشے ریڈز اور کیش تخلیق ٹوکنز) × `input` کی شرح۔
- **کیشے پڑھنے والے ٹوکنز** × `cached` شرح (ان پٹ کی شرح پر واپس آتی ہے)۔
- **کیشے بنانے والے ٹوکن** × `cache_creation` شرح (ان پٹ کی شرح پر واپس آتی ہے)۔
- **آؤٹ پٹ ٹوکنز** × `output` شرح۔
- **استدلال کے ٹوکن** × `reasoning` شرح (آؤٹ پٹ کی شرح پر واپس آتی ہے)۔

تمام شرحوں کو USD فی 1,000,000 ٹوکن سے تعبیر کیا جاتا ہے۔ ایک Codex "تیز"/"ترجیح" یا "فلیکس" سروس ٹائر لاگت کے ضرب کا اطلاق کرتا ہے (`getCodexFastCostMultiplier`) — مثلاً فلیکس پر 50% ٹوکن ڈسکاؤنٹ پر بل کیا جاتا ہے، جیسا کہ منظر عام پر آتا ہے۔**فلیکس بچت** ڈیش بورڈ میں

ماڈل کے نام پہلے نارمل کیے جاتے ہیں (فراہم کرنے والے کے راستے کے سابقہ جیسے `openai/` یا `accounts/fireworks/models/` کو چھین لیا جاتا ہے) لہذا تاریخی قطاریں اب بھی قیمت سے ملتی ہیں۔

### خرچ کیسے ریکارڈ کیا جاتا ہے۔

- فی درخواست لاگت درخواست کی تکمیل پر شمار کی جاتی ہے۔ مشترکہ کوٹہ کی کھپت [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) کے ذریعے اگلے ایونٹ-لوپ ٹک پر طے کی گئی ہے۔
- API کلیدی خرچ [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (پہلے سے طے شدہ 60s فلش وقفہ، 1,000-انٹری بفر) کے ذریعے بیچوں میں بفر اور فلش کیا جاتا ہے۔ ٹیون ایبل بذریعہ:

  | Env var                             | طے شدہ  | مقصد                                         |
  | ----------------------------------- | ------- | -------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | ملی سیکنڈ میں فلش وقفہ۔                      |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | فلش سے پہلے زیادہ سے زیادہ بفر شدہ اندراجات۔ |

لاگتیں فراہم کنندہ کی طرف سے رپورٹ کردہ عین مطابق چارج (`provider_cost_usd`) کو ترجیح دیتی ہیں، پھر ایک کیٹلاگ کی قیمت والی درخواست کا سنیپ شاٹ (`calculated_cost_usd`)، پھر موجودہ کیٹلاگ سے ٹوکن ری پرائسنگ۔ ذخیرہ شدہ قیمتیں ان کے ٹوکن شمار کے ذریعے دوبارہ وصول نہیں کی جاتی ہیں۔ لیگیسی ٹوکن صرف قطاریں تب بھی تبدیل ہوتی ہیں جب ان کی کیٹلاگ کی قیمت تبدیل ہوتی ہے۔

### OCR اور سرایت کرنا

- `/v1/ocr` کامیاب درخواستیں upstream `usage_info.pages_processed` استعمال کرتی ہیں، نہ کہ درخواست کردہ صفحہ کی حد یا واپس کیے گئے صفحہ کی اشیاء کی تعداد۔ تخمینہ صفحات × `ocr_cost_per_page` (مطلق USD/page،**نہیں** USD/million)۔
- دستاویز یا باؤنڈنگ باکس تشریحات والی درخواستوں کے لیے علیحدہ `ocr_cost_per_annotated_page` ٹیرف کی ضرورت ہوتی ہے۔ اس کے بغیر، قیمت نامعلوم رہتی ہے؛ عام OCR ٹیرف خاموشی سے تبدیل نہیں کیا جاتا ہے۔
- LiteLLM مطابقت پذیری `ocr_cost_per_annotated_page` میں اپنے اپ اسٹریم `annotation_cost_per_page` فیلڈ کا نقشہ بناتا ہے، مطلق USD/page قدر اور صرف تشریح کے اندراجات کو برقرار رکھتا ہے، بشمول واضح صفر۔ ایک فراہم کردہ کینونیکل فیلڈ کو فوقیت حاصل ہے۔ غلط عرفی اقدار کو نظر انداز کر دیا گیا ہے۔ صارف کی قیمتوں کا تعین ان کی عام ترجیح کو برقرار رکھتا ہے۔ [LiteLLM کی OCR قیمتوں کی چابیاں](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) دیکھیں۔
- OCR کا استعمال صفحہ کی گنتی، یونٹ کی قیمت، حسابی USD لاگت، API کلید اور منتخب کنکشن کو محفوظ کرتا ہے۔ صفحات کو کبھی بھی ٹوکن کے طور پر پیش نہیں کیا جاتا ہے۔ کال لاگز میں بلنگ میٹا ڈیٹا ہوتا ہے، نہ کہ دستاویز URLs، PDF بائٹس یا نکالا گیا متن۔
- کامیاب `/v1/embeddings` فی فزیکل بیچ کے استعمال کی ایک قطار کو ریکارڈ کرنے کی درخواست کرتا ہے، بشمول ایک ہی ملی سیکنڈ میں مکمل ہونے والے علیحدہ بیچز۔ فراہم کنندہ کی طرف سے رپورٹ کردہ چارجز ٹوکن تخمینوں پر فوقیت رکھتے ہیں۔ کومبو ریپر چارج شامل نہیں کرتے ہیں۔
- استعمال کی سرگزشت، لاگت کے تجزیات، provider/account ونڈوز، API- کلیدی اخراجات کی حد، درخواست لاگت لیجر اور روزانہ استعمال کے رول اپ میں یہ چارجز شامل ہیں۔ نو-لاگ کیز ماخذ متن کو برقرار رکھے بغیر عددی اکاؤنٹنگ کو برقرار رکھتی ہیں۔
- لاپتہ استعمال یا ٹیرف ہیں **نامعلوم** مفت نہیں: جوابی لاگت کا ہیڈر چھوڑ دیا گیا ہے، اور موجودہ غیر قیمتی استعمال کی پالیسی محدود API کیز پر لاگو ہوتی ہے۔ واضح طور پر ترتیب شدہ صفر کی قیمتیں درست صفر لاگت کے استعمال پر رہیں۔

یہ صرف فارورڈ اکاؤنٹنگ ہے۔ پرانی OCR/embedding کالز جنہوں نے استعمال کی تاریخ کبھی نہیں لکھی اس منتقلی سے دوبارہ تشکیل نہیں دی جا سکتی۔ کیٹلاگ کے تخمینے USD تخمینے ہیں، انوائس نہیں، اور ان میں کرنسی کی تبدیلی، ٹیکس یا چھوٹ شامل نہیں ہے۔

## ڈیش بورڈ: اخراجات کا صفحہ

**اخراجات** کا صفحہ `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`) پر موجود ہے۔
اس کا مرکزی منظر **اخراجات کا جائزہ** ٹیب ہے
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`)،
جو تمام ڈیٹا `GET /api/usage/analytics` سے لوڈ کرتا ہے۔

یہ کیا دکھاتا ہے:

- **اخراجات کی ٹائلز** — _آج (1d)_، _7d_، _30d_، اور منتخب کردہ
  مدت کے تخمینی اخراجات۔ مدت منتخب کرنے کے اختیارات: `7d`، `30d`، `90d`، `all`۔
- **نمایاں میٹرکس** — مدت کے دوران درخواستیں، فعال فراہم کنندگان، فعال ماڈلز، اور فی
  درخواست اوسط لاگت۔
- **کاسٹ ایکسپلورر** — ایک قابلِ ترتیب/فلٹر جدول، جس کی گروپ بندی **فراہم کنندہ**، **ماڈل**،
  **API کلید**، **اکاؤنٹ**، یا **سروس ٹیئر** کے لحاظ سے کی جا سکتی ہے، اور جس میں لاگت، درخواستیں، ٹوکنز، فی درخواست اوسط
  لاگت، اور کل میں حصہ % شامل ہیں۔
- **ٹوکن کا استعمال** — کل / ان پٹ / آؤٹ پٹ ٹوکنز اور ان پٹ:آؤٹ پٹ تناسب۔
- **روٹنگ کی کارکردگی** — فال بیک کی تعداد، فال بیک کی شرح، اور درخواست کردہ ماڈل کی کوریج۔
- **ماہانہ پیش گوئی** — حالیہ یومیہ اوسط کی بنیاد پر مہینے کے اختتام تک کے اخراجات کا تخمینہ۔
- **مدت کا موازنہ** — مدت کے پہلے اور دوسرے نصف کے درمیان % تبدیلی۔
- **چارٹس** — یومیہ لاگت کا رجحان، فراہم کنندگان کا حصہ (پائی)، سرفہرست فراہم کنندگان، سرفہرست ماڈلز، API کلید
  کے لحاظ سے لاگت، اکاؤنٹ کے لحاظ سے لاگت، ہفتہ وار استعمال کا پیٹرن، اور سرگرمی کا ہیٹ میپ۔
- **برآمد** — موجودہ مدت کو **CSV** یا **JSON** کے طور پر ڈاؤن لوڈ کریں (بٹن اس وقت
  ظاہر ہوتے ہیں جب لاگت کا ڈیٹا صفر سے زیادہ ہو)۔

جب قیمت شدہ ٹریفک موجود نہ ہو تو قطاریں `$0` کے بجائے "Legacy / Free" لیبل کے طور پر رینڈر ہوتی ہیں،
جو بچت ٹریکر ماڈل کی عکاسی کرتا ہے۔

### اخراجات سے متعلق ذیلی صفحات

اخراجات کے حصے میں یہ صفحات بھی شامل ہیں (سبھی `/dashboard/costs/` کے تحت):

- **قیمت بندی** (`/dashboard/costs/pricing`) — ہر ماڈل کی قیمتیں دیکھیں اور انہیں اوور رائیڈ کریں (مشترکہ
  قیمت بندی ٹیب کو رینڈر کرتا ہے)۔
- **بجٹ** (`/dashboard/costs/budget`) — ہر دائرۂ کار کے لیے اخراجات کی حدود مقرر کریں (مشترکہ
  بجٹ ٹیب کو رینڈر کرتا ہے)۔
- **کوٹا شیئر** (`/dashboard/costs/quota-share`) — مشترکہ کوٹا پولز اور خرچ ہونے کی شرح
  کے مناظر۔

## API اینڈ پوائنٹس

ان سب کے لیے مینجمنٹ توثیق (لوپ بیک/JWT، بذریعہ `requireManagementAuth`) درکار ہے، سوائے اس کے کہ
کچھ اور درج ہو۔

### استعمال اور لاگت کے تجزیات

| طریقہ | اینڈ پوائنٹ              | مقصد                                                                                                                                                               |
| ----- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET` | `/api/usage/analytics`   | لاگت/استعمال کے مکمل تجزیات: خلاصہ، یومیہ رجحان، فراہم کنندہ/ماڈل/API کلید/اکاؤنٹ/ٹیئر کے لحاظ سے۔ کوئری: `range`، `startDate`، `endDate`، `apiKeyIds`، `presets`۔ |
| `GET` | `/api/usage/utilization` | وقت کے ساتھ ہر فراہم کنندہ کے کوٹے کا استعمال۔ کوئری: `range` (`1h`/`24h`/`7d`/`30d`)، `provider`۔                                                                 |
| `GET` | `/api/usage/history`     | استعمال کی تاریخ کی خام قطاریں۔                                                                                                                                    |
| `GET` | `/api/usage/call-logs`   | ہر درخواست کے کال لاگز (ماڈل، ٹوکنز، لاگت، تاخیر، اسٹیٹس)۔                                                                                                         |
| `GET` | `/api/usage/quota`       | فراہم کنندہ کے کوٹے کی حالت۔                                                                                                                                       |
| `GET` | `/api/usage/proxy-logs`  | پراکسی درخواست کے لاگز۔                                                                                                                                            |

### بجٹس

| طریقہ  | اینڈ پوائنٹ              | مقصد                                                                                  |
| ------ | ------------------------ | ------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | ایک API کلید کے لیے لاگت کا خلاصہ + بجٹ کی جانچ (`apiKeyId` کوئری پیرامیٹر درکار ہے)۔ |
| `POST` | `/api/usage/budget`      | ایک API کلید کے لیے یومیہ/ہفتہ وار/ماہانہ USD حدود + انتباہی حد مقرر کریں۔            |
| `GET`  | `/api/usage/budget/bulk` | API کلیدوں میں مجموعی بجٹ کے خلاصے۔                                                   |

> بجٹ API کا دائرۂ کار ہر **API کلید** (`apiKeyId`) تک محدود ہے۔ `GET /api/usage/budget`
> کی واپس کردہ حدود میں `dailyLimitUsd`، `weeklyLimitUsd`، `monthlyLimitUsd`،
> ایک `warningThreshold`، اور جاری مجموعے (`totalCostToday`، `totalCostMonth`، …) شامل ہیں۔

### قیمت بندی

| طریقہ    | اینڈ پوائنٹ             | مقصد                                                                                                                        |
| -------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | چار تہوں کے مشترکہ نرخ (صارف، models.dev، LiteLLM، طے شدہ)۔ `?includeSources=1` سے `pricing` + `sourceMap` ملتے ہیں۔        |
| `PATCH`  | `/api/pricing`          | `{ provider: { model: { input, output, cached, … } } }` کے لیے قیمت بندی اوور رائیڈ کریں۔                                   |
| `DELETE` | `/api/pricing`          | صارف کی متبادل نرخ قدریں ہٹاتا ہے (اختیاری حد `?provider=&model=`)؛ ہم وقت شدہ نرخ یا اندرونی طے شدہ قدریں متبادل رہتی ہیں۔ |
| `GET`    | `/api/pricing/defaults` | فی 1M ڈیفالٹ فال بیک نرخ دکھائیں۔                                                                                           |
| `GET`    | `/api/pricing/models`   | ماڈل کے لحاظ سے کلید شدہ قیمت بندی۔                                                                                         |
| `POST`   | `/api/pricing/sync`     | بیرونی ذرائع (LiteLLM) سے دستی ہم وقتی آغاز کریں۔                                                                           |
| `GET`    | `/api/pricing/sync`     | ہم وقتی کی موجودہ حالت۔                                                                                                     |
| `DELETE` | `/api/pricing/sync`     | صرف LiteLLM کے ہم وقت شدہ نرخ (`pricing_synced`) صاف کرتا ہے؛ models.dev کا ڈیٹا الگ ہے۔                                    |

### لاگت سے متعلق دیگر اینڈ پوائنٹس

## CLI

OmniRoute کا CLI لاگت، استعمال، اور قیمتوں سے متعلق کمانڈز فراہم کرتا ہے (جو
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) میں رجسٹرڈ ہیں)۔

### `omniroute cost`

`/api/usage/analytics` سے مجموعی لاگت کی رپورٹ۔

```bash
omniroute cost                          # گزشتہ 30d، فراہم کنندہ کے لحاظ سے گروپ کردہ
omniroute cost --period 7d              # گزشتہ 7 دن
omniroute cost --group-by model         # provider | model | combo | api-key | day کے لحاظ سے گروپ کریں
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

کالمز: گروپ، درخواستیں، اِن/آؤٹ ٹوکنز، لاگت (USD)، اور کل کا فیصد۔ آخر میں مجموعی کل کی سطر
پرنٹ کی جاتی ہے (جسے `--quiet` یا `--output json` کے ذریعے چھپایا جا سکتا ہے)۔

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ہر فراہم کنندہ کے لیے لاگت کا خلاصہ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# بجٹس
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`، `GET /api/pricing/defaults` کو پڑھتا ہے۔ اس کے بجائے انفرادی ماڈلز
> کی قیمتوں میں ترمیم کرنے کے لیے **Pricing** ڈیش بورڈ صفحہ یا `PATCH /api/pricing` استعمال کریں۔

## مسائل کا حل

- **تمام لاگتیں $0 / "Legacy / Free" دکھاتی ہیں۔** زیرِ استعمال ماڈلز کے لیے قیمت کا کوئی اندراج موجود نہیں۔
  بیرونی سنک فعال کریں (`PRICING_SYNC_ENABLED=true`) اور `omniroute pricing sync` چلائیں، یا
  Pricing صفحے / `PATCH /api/pricing` کے ذریعے دستی طور پر قیمتیں مقرر کریں۔
- **کسی تاریخی ماڈل کی قیمت غلط ہے۔** قیمت درست کریں (اوور رائیڈ یا دوبارہ سنک کریں) — ہر بار اینالیٹکس پڑھنے پر
  لاگت کو ٹوکنز کی تعداد سے دوبارہ شمار کیا جاتا ہے، اس لیے تخمینے سابقہ مدت کے لیے بھی اپ ڈیٹ ہو جاتے ہیں۔
- **اخراجات حقیقی وقت سے پیچھے ہیں۔** ہر کلید کے اخراجات بیچز میں پراسیس کیے جاتے ہیں؛ اگر آپ کو زیادہ تازہ اعداد و شمار درکار ہوں تو
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` کم کریں۔
