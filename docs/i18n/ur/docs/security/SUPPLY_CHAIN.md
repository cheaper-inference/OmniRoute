OmniRoute npm + Docker آرٹفیکٹس شائع کرتا ہے۔ یہ گیٹس provenance، inventory (SBOM) اور CVE سکیننگ فراہم کرتے ہیں، یہ سب OSS ہیں، اور ریلیز ورک فلوز میں شامل ہیں۔ **مشاورتی-پہلے** کا رویہ — وہ ابھی رپورٹ کرتے ہیں، اور پہلی کامیاب ریلیز کے بعد بلاک کرنے کی سطح پر ترقی دیتے ہیں۔

| گیٹ                   | ٹول                                            | کہاں                          | بلاک کرتا ہے؟           | آؤٹ پٹ                                         |
| --------------------- | ---------------------------------------------- | ----------------------------- | ----------------------- | ---------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | صرف اگر پبلش ناکام ہو   | badge npmjs / `npm audit signatures`           |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | صرف اگر جنریشن ناکام ہو | Release asset + artifact                       |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | مشاورتی                 | CycloneDX artifact                             |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | مشاورتی                 | SARIF (HIGH+CRITICAL) → Security tab           |
| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **بلاک کرنے والا**      | `exit-code: '1'` on fixable CRITICAL           |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **بلاک کرنے والا**      | `metrics.vulnCount` کو رچٹ کرتا ہے (سمت: نیچے) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | مشاورتی                 | SARIF → سیکیورٹی + بیج                         |

امیج CVE رچٹ `docker-publish.yml` میں **دو مراحل** استعمال کرتا ہے: SARIF مرحلہ (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL کو سیکیورٹی ٹیب میں بلاک کیے بغیر مرئی رکھتا ہے؛ _CRITICAL گیٹ_ مرحلہ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) ایک CRITICAL CVE پر ریلیز کو ناکام کر دیتا ہے **جس کا حل دستیاب ہو**۔ `ignore-unfixed` ایک بیس-امیج CVE کے لیے ریلیز کو بلاک ہونے سے روکتا ہے جس میں کوئی اپ اسٹریم پیچ نہ ہو۔

## ⚠️ CVE میں تغیر (osv/Trivy گیٹس کو روکنے والا)

osv اور Trivy انحصارات کا موازنہ ان CVE ڈیٹابیسز سے کرتے ہیں جو **مسلسل بڑھتے رہتے ہیں**۔ کوئی PR
جو **کسی انحصار کو تبدیل نہیں کرتا** اچانک سرخ ہو سکتا ہے، کیونکہ کسی موجودہ انحصار میں ایک نیا CVE
ظاہر کر دیا گیا ہو (osv: ناپا گیا `vulnCount` > بیس لائن؛ Trivy: امیج میں ایک نیا
قابلِ اصلاح CRITICAL)۔ **یہ کسی روکنے والے CVE گیٹ کا متوقع عملیاتی رویہ ہے،
پروڈکٹ کی خرابی نہیں۔**

جب کسی نئے ظاہر کردہ CVE کی وجہ سے osv یا Trivy سرخ ہو جائے، تو حل یہ ہے:

1. **متاثرہ انحصار کا ورژن بڑھائیں** (ترجیحی طریقہ) — `package.json` میں
   `overrides` (بالواسطہ انحصارات) کے ذریعے پیچ شدہ ورژن پر اپ گریڈ کریں، یا پیچ شدہ بیس پر امیج دوبارہ بنائیں۔
2. **اگر اپ اسٹریم حل دستیاب نہ ہو:**
   - **osv:** `config/quality/quality-baseline.json` میں `metrics.vulnCount` کی بیس لائن دوبارہ متعین کریں
     (`npm run quality:ratchet -- --update` مخصوص گیٹس کا احاطہ نہیں کرتا — قدر کو
     دستی طور پر، `direction:down` کے ساتھ، جواز کے نوٹ + ٹریکنگ ایشو سمیت ترمیم کریں)۔
   - **Trivy:** `.trivyignore` میں ایک اندراج شامل کریں (ہر سطر میں ایک CVE-ID)، ساتھ میں جواز پر مبنی
     تبصرہ + ٹریکنگ ایشو شامل کریں۔ `ignore-unfixed: true` پہلے ہی بغیر
     پیچ والے CVEs کا خودکار طور پر احاطہ کرتا ہے۔

لازمی OSV عمل درآمد (`check:vuln-ratchet -- --ratchet`) اسکینر، رپورٹ یا بیس لائن کی توثیق نہ ہو سکنے پر
`INCOMPLETE` کے ساتھ فیل-کلوز ہوتے ہیں اور ایگزٹ کوڈ 2 دیتے ہیں۔
ناپی گئی تنزلی ایگزٹ کوڈ 1 دیتی ہے۔ مشاورتی عمل درآمد اب بھی ایگزٹ کوڈ 0 کے ساتھ `SKIP` رپورٹ کر سکتا ہے،
جو یہ ثابت نہیں کرتا کہ انحصارات اسکین میں کامیاب ہوئے۔ روکنے والے
Trivy مرحلے کے لیے بھی کامیاب پیمائش ضروری ہے: غیر دستیاب ٹولز، ناکام جابز
اور امیج کے گم شدہ شواہد کسی امیج کے صاف ہونے کی تصدیق نہیں کر سکتے۔

## متروک شدہ dependency کا خطرہ

pinned promptfoo development tool کو upgrade کرنے کے بعد root lockfile میں اب `extract-zip` یا اس کی طرف جانے والا کوئی dependency edge شامل نہیں ہے۔
اس سے #14482 میں track کی گئی، پہلے قبول شدہ
`promptfoo` → `@openai/codex-security` → `extract-zip` chain متروک ہو جاتی ہے۔
`tests/unit/extract-zip-14482-exposure.test.ts` میں موجود regression checks اس کے
دوبارہ شامل کیے جانے کو مسترد کرتے ہیں اور production code سے imports پر پابندی برقرار رکھتے ہیں۔

موجودہ dependency repair، compatibility overrides کو Azure identity کے
MSAL client، get-uri کے FTP client، اور OpenCode v1 SDK کی Zod dependency تک بھی محدود کرتی ہے۔ Azure token
acquisition اور FTP retrieval کو controlled transports کے ساتھ test کیا گیا ہے؛ دونوں OpenCode
packages اپنی build اور test suites چلاتے ہیں۔ Registry advisory counts کسی ایک وقت کی پیمائش
ہوتی ہیں اور lockfile commit ہونے کے بعد تبدیل ہو سکتی ہیں۔

## بیک لاگ (Backlog): سکور کارڈ ایڈوائزری (Scorecard advisory) → بلاکنگ (blocking)

سکور کارڈ رپورٹنگ (Scorecard reporting) کے ساتھ پہلی گرین ریلیز کے بعد:

- سکور کارڈ (Scorecard): سکور ریچیٹ (score ratchet) (ماپے گئے سکور کو منجمد کرتا ہے؛ کم نہیں ہو سکتا)۔

فیز 7 گیٹس (Phase 7 gates) (osv-scanner, gitleaks, actionlint+zizmor) کی تکمیل کرتا ہے: zizmor خود ورک فلوز (workflows) کا آڈٹ کرتا ہے؛ سکور کارڈ (Scorecard) ریپو پوسچر (repo posture) کو مجموعی طور پر ماپتا ہے۔
