## گیٹ انوینٹری اور ایگزیکیوشن پروفائلز

### امیدوار داخلہ

CI اور کوالٹی گیٹس کے ورک فلو سے ہر ایک ایک مستحکم فیصلے کا اخراج کرتا ہے: `Gate / CI` اور `Gate / Quality`۔ ان کی ورژن شدہ داخلہ پالیسی ہر اپ اسٹریم ملازمت کو ضرورت یا مشورے کے مطابق شمار کرتی ہے۔ ایک قابل اطلاق مطلوبہ کام کا کامیاب ہونا ضروری ہے: غائب، منسوخ، نظر انداز، زیر التواء اور نامعلوم نتائج PASS قائم نہیں کر سکتے۔ ایک درست دستاویزات صرف یا صرف کیٹلاگ کی درجہ بندی ایک کوڈ لین کو ناقابل اطلاق بنا سکتی ہے۔ ایک مسودہ PR قبول شدہ امیدوار نہیں ہے۔ `hotfix` لیبل ثبوت سے دستبردار نہیں ہوتا ہے۔

دونوں ورک فلوز PRs main/release شاخوں میں ڈھانپتے ہیں، `main` کی طرف دھکیلتے ہیں، دستی ڈسپیچ اور ضم کرنے والے گروپ ایونٹس۔ پش، ڈسپیچ اور ضم کرنے والے گروپ مکمل انتخاب کو چلاتے ہیں۔ `release/**` کو دھکیلنے سے وہ شروع نہیں ہوتے ہیں (2026-10-18): ہر تبدیلی نے پہلے سے ہی اپنے PR پر میٹرکس چلایا ہے اور ضم شدہ مجموعہ ریلیز-گرین کا کام ہے (`docs/ops/RUNNER_BOX.md` → ہوسٹڈ لین)۔ فورکس اور انضمام گروپ ملازمتوں کے لیے ہوسٹڈ رنر کا استعمال کرتے ہیں جو بصورت دیگر خود میزبان رنرز کو منتخب کرتے ہیں۔ رول آؤٹ سے پہلے کافی میزبانی کی صلاحیت کی تصدیق ہونی چاہیے۔

ایک عام PR تیزی سے انتخاب چلاتا ہے۔ داخلہ پالیسی کی `full-code` اور `full-code-e2e` لین (E2E, integration , package artifact , Electron smoke , Bun SQLite, ایکو سسٹم اور پروٹوکول کلائنٹس ) صرف Mergify قطار کے مسودے پر چلتے ہیں یا مکمل طور پر چلتے ہیں: `gh workflow run ci.yml --ref <branch>`۔

ہر JSON رسید چیک آؤٹ SHA، ورک فلو چلانے اور کوشش کی نشاندہی کرتی ہے۔ CLI ایک checkout/event SHA مماثلت کو مسترد کرتا ہے۔ ورک فلو ٹیسٹ پالیسی کی رکنیت کو فیصلے کی نوکری کی `needs` فہرست سے منسلک کرتے ہیں لہذا ایک نئی یا ہٹائی گئی لین خاموشی سے غائب نہیں ہوسکتی ہے۔ رسیدیں ان کے اپنے ورک فلو کا احاطہ کرتی ہیں، نہ کہ اشاعت، تعیناتی، یا موجودہ ایڈوائزری اسکینر کے اندرونی حصے۔ برانچ رولز میں دونوں چیک ناموں کو چالو کرنا ایک الگ انتظامی تبدیلی ہے۔ ان ملازمتوں کو شامل کرنا خود ایک برانچ کی حفاظت نہیں کرتا ہے۔

### قطار کو ضم کریں۔

`queue` لیبل Mergify قطار (`.mergify.yml`) میں PR بھیجتا ہے۔ Mergify `mergify/merge-queue/` برانچ پر ایک ڈرافٹ PR کھولتا ہے، CI وہاں مکمل انتخاب چلاتا ہے، اور `Gate / CI`، `Gate / Quality` اور `Merge integrity (changelog + generated skills)` پاس ہونے پر اصل PR ضم ہو جاتا ہے۔

Mergify اپنی قطار کا خلاصہ ڈرافٹ کی تفصیل میں لکھتا ہے، اور دیگر ایپس بھی اس میں ترمیم کر سکتی ہیں۔ اس طرح کے ڈرافٹ پر ایک `pull_request` `edited` ایونٹ اپنا کنکرنسی گروپ (`-queue-edit-<run_id>`) لیتا ہے لہذا یہ ڈرافٹ کے حقیقی رن کو منسوخ نہیں کر سکتا، اور یہ گیٹ اور میٹرکس کو چھوڑ دیتا ہے۔ صرف `Merge integrity` اب بھی چلتا ہے۔ اسکپڈ گیٹ جاب میں ایک مختلف چیک کا نام ہوتا ہے، کیوں کہ مرگائف ایک skipped `Gate / CI` ناکام چیک کے طور پر پڑھتا ہے اور PR کو ڈیکیو کرتا ہے۔

dequeue کے بعد، ایک دھکا ہمیشہ PR کی درخواست نہیں کرتا ہے۔ اس پر `@mergifyio queue` تبصرہ کریں۔

### قبولیت کم کرنے والے میں ثبوت کو برقرار رکھا

`scripts/quality/validate-release-acceptance.mjs` فراہم کردہ منصوبہ اور اس کے ظاہر کو کم کرتا ہے۔ اس سے یہ ثابت نہیں ہوتا ہے کہ منصوبہ مکمل ریلیز پائپ لائن کا احاطہ کرتا ہے۔ اس کی رپورٹوں میں واضح طور پر `releaseAcceptance: false` تعین کیا گیا ہے، یہاں تک کہ جب وہ منصوبہ `VERIFIED` ہو۔ `release-acceptance.yml` ورک فلو اب بھی شیڈو فکسچر استعمال کرتا ہے، اصلی تعمیر، پیکیج، بوٹ یا پروموشن کی رسیدیں نہیں۔

CLI کو `--evidence-root` کی ضرورت ہوتی ہے کہ وہ رکھے گئے شواہد کی تصدیق کرے۔ فائلوں کو `<evidence-root>/<artifact_id>/<member>` کے بطور حل کیا جاتا ہے اور SHA-256 کے بطور ہیش کیا جاتا ہے۔ بغیر ثبوت کے PASS ریکارڈ، گمشدہ یا تبدیل شدہ فائل، ایک غیر محفوظ راستہ یا symlink تصدیق کو روکتا ہے۔ گم شدہ فائلیں خالی کامیاب لاگز کے برابر نہیں ہیں۔ موجودہ SHA/run/attempt چیک آزاد رہتے ہیں: مماثل بائٹس باسی رسید کو نہیں بچا سکتے۔ فائل کی سالمیت عمل درآمد کی صداقت یا آرٹفیکٹ کے فروغ کا ثبوت نہیں ہے۔

### جامد اسکین انوینٹری

ورژن شدہ npm-alias انوینٹری اور static-scan کی رکنیت `config/quality/gate-manifest.json` میں رہتی ہے۔ اسکرپٹ کے ناموں اور `package.json` کے خلاف عین حکموں کی توثیق کرنے کے لیے `npm run check:gate-manifest` چلائیں۔ اضافہ، ہٹانا اور کمانڈ ڈرفٹ مقامی ہک اور CI میں تبدیلی کی درجہ بندی دونوں کاموں کو ناکام بنا دیتے ہیں۔ عرف ایک ورک فلو جاب، میٹرکس مثال یا ٹیسٹ کیس نہیں ہے: ان شماروں کو قابل تبادلہ کے طور پر پیش نہیں کیا جانا چاہیے۔

`npm run quality:scan -- --list` یا `npm run quality:scan:fast -- --list` کا استعمال منتخب کردہ عرفی ناموں پر عمل کیے بغیر ان کا معائنہ کرنے کے لیے کریں۔ رنر این پی ایم انٹری پوائنٹ کو طلب کرتا ہے، لہذا اس کا رن ٹائم (بشمول Bun جہاں کنفیگر کیا گیا ہے) محفوظ رہتا ہے۔ مینی فیسٹ ان پروفائلز کے باہر عرفی ناموں کو ریکارڈ کرتا ہے جیسا کہ الگ سے درخواست کی گئی ہے، اور دیکھ بھال کے احکام صرف پڑھنے کے لیے اسکین پروفائلز میں منع ہیں۔

یہ پروفائلز صرف جامد اسکین کا احاطہ کرتے ہیں۔ وہ پروڈکٹ ٹیسٹ، کوریج، پیکیجنگ، بیرونی چیک یا امیدوار کی مکمل ریلیز قبولیت کی تصدیق نہیں کرتے ہیں۔ ورک فلو داخلہ منسلک `config/quality/admission-policy.json` اور `scripts/quality/admission-verdict.mjs` استعمال کرتا ہے۔ ریلیز مبصر پروفائلز الگ الگ رہتے ہیں؛ ان کے قابل اطلاق چیکوں اور رسیدوں کا آزادانہ طور پر معائنہ کریں۔ مکمل مبصر کے جامد کمانڈز کا اعلان `config/quality/release-green-static-profile.json` میں کیا جاتا ہے، بشمول `audit:deps`، میوٹیشن ٹیسٹ سلیکشن اور ترجمہ چیک۔ لوڈر package.json اور ماڈل شدہ CI/Quality ڈیکلریشنز کے خلاف npm کمانڈز کی توثیق کرتا ہے۔ یہ شیل ٹوکن کو بطور دلیل دینے کے بجائے بڑھے ہوئے کو مسترد کرتا ہے۔ مطلوبہ سکینر SKIP/INCOMPLETE آؤٹ پٹ PASS قائم نہیں کر سکتا۔ پروفائل اپنے بیرونی اخراج کو ریکارڈ کرتا ہے اور میزبان کوریج، ٹیسٹ میٹرکس، پیکج یا تعیناتی ثبوت کو تبدیل نہیں کرتا ہے۔ نیچے دی گئی نثر کی فہرست ایک حوالہ ہے، اس بات کا ثبوت نہیں کہ واقعی ایک گیٹ چلا۔

اسکرپٹ `scripts/check/` (پالیسی گیٹس) اور `scripts/quality/` (ریچیٹ انجن) کے تحت رہتے ہیں۔ CI سچائی کا ذریعہ `.github/workflows/ci.yml` ہے۔

### جاری کریں PR فاسٹ پاتھ (`quality.yml`)

`.github/workflows/quality.yml` main/release PRs پر CI تکمیل کرتا ہے، `main`، ڈسپیچ اور ضم گروپوں کو دھکیلتا ہے۔ PRs پاتھ فلٹرڈ فاسٹ چیک کا استعمال کرتا ہے۔ مستقل طور پر غیر فعال ڈپلیکیٹ تعمیر کو ہٹا دیا گیا تھا۔ اصلی build/package/boot چیک CI میں ہی رہتے ہیں۔ یونٹ سویٹ اور ویٹسٹ صرف CI (`Unit Tests (N/8)` اور `Vitest`) میں چلتے ہیں۔

| جاب                                              | دائرہ کار                                                                                          | بلاک کرنا          |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------- | ------------------ |
| `Docs Gates (fast-path)`                         | Docs/code PRs; API docs refs اور docs-all                                                          | جی ہاں             |
| `Fast Quality Gates`                             | کوڈ PRs; جامد چیک، ٹائپ چیک، ڈیش بورڈ ٹائپ چیک، متاثرہ یونٹ ٹیسٹ، بھولے ہوئے بھائی کے ٹیسٹ (مشورہ) |
| `No new ESLint warnings`                         | کوڈ PRs; دبانے سے آگاہ لنٹ گارڈ                                                                    | جی ہاں، کانٹے سمیت |
| `Merge integrity (changelog + generated skills)` | غیر مسودہ PRs; چینج لاگ اور جنریٹڈ اسکل سنک                                                        | جی ہاں، کانٹے سمیت |

#### بھولے بھائی کے ٹیسٹ رپورٹ

`npm run check:forgotten-sibling-tests` `Fast Quality Gates` کے ایک مشاورتی قدم کے طور پر چلتا ہے اور ٹیسٹ-امپیکٹ میپ کے پیچھے امپورٹ ریزولور کو دوبارہ استعمال کرتا ہے۔ ہر تبدیل شدہ پروڈکشن ماڈیول کے لیے، جب امیدوار ٹیسٹ پل-ریکوسٹ ڈِف سے غیر حاضر ہوتا ہے تو یہ ڈیٹرمنسٹک `changed module/symbol -> static consumer -> candidate sibling test` چینز کی اطلاع دیتا ہے۔ مارک ڈاؤن کا خلاصہ اور JSON نتیجہ کسی بھی بلاکنگ رول آؤٹ سے پہلے کیلیبریشن کے لیے `forgotten-sibling-tests` ورک فلو آرٹفیکٹ کے طور پر برقرار رکھا جاتا ہے۔

بیرل کی دوبارہ برآمدات اور متحرک درآمدات صرف ریزولیوشن تشخیص ہیں۔ وہ کبھی بھی بلاکنگ فائنڈنگ نہیں بناتے ہیں۔ جائزہ لیا مستثنیات `config/quality/forgotten-sibling-allowlist.json` میں رہتے ہیں۔ ہر اندراج میں صارف اور امیدوار کے ٹیسٹ کا نام ہونا چاہیے، ایک مخصوص دلیل دینا چاہیے، اور GitHub مسئلے یا پل کی درخواست کو لنک کرنا چاہیے۔ غلط اندراجات ناکام ہو گئے بند ہو گئے۔ مستثنیات حذف شدہ امیدوار ٹیسٹ یا `.skip`/`.todo` کو شامل کرنے والے فرق کو دبا نہیں سکتے۔ دعوی کو کمزور کرنا اور دیگر ماسکنگ آزادانہ طور پر بلاک کرنے والے `check:test-masking` گیٹ کی ملکیت رہتی ہے۔

`typecheck:core` اور `check:build-typecheck` مختلف آپشنز کے تحت مختلف پروگراموں کو مرتب کرتے ہیں، اور ایک ہی فائل ایک میں صاف اور دوسری میں غلطیوں سے بھری ہوسکتی ہے۔

`tsconfig.build.json` سیٹ کرتا ہے `"strict": false`، تو `noImplicitAny` آف ہے۔ بنیادی تشکیل سخت اختیارات کے ساتھ ایک کیوریٹڈ 27 فائل کی اجازت کی فہرست مرتب کرتی ہے اور ہر اندراج کے درآمدی گراف کی پیروی کرتی ہے، لہذا وہ فائلیں جو کبھی بھی تعمیراتی پروگرام میں ظاہر نہیں ہوتی ہیں ان کی جانچ پڑتال کی جاتی ہے۔

یہ فیصلہ کرتے وقت نتیجہ اہمیت رکھتا ہے کہ آیا فائل ٹائپ کی گئی ہے:** `check:build-typecheck` کے تحت صفر کی تشخیص کا مطلب صفر نہیں ہے۔** . 26 فائلوں سے `@ts-nocheck` ہٹانے سے ان میں سے 23 کو بلڈ پروگرام میں صاف دکھایا گیا۔ ان میں سے سولہ میں تقریباً 120 مضمر غلطیاں سامنے آئیں۔ فائل کو صاف کرنے سے پہلے دونوں کو چیک کریں۔

#### ٹرانسلیشن آئینے ماخوذ فائلیں ہیں (PR موڈ بمقابلہ ریلیز موڈ)

ایک خصوصیت PR صرف انگریزی ذرائع میں ترمیم کرتی ہے۔ `docs/i18n/<locale>/**` آئینہ (بشمول 66 `llm.txt` کاپیاں اور ترجمہ شدہ `CHANGELOG.md` فائلیں) اور `.i18n-state.json` ترجمہ لہر (`docs/i18n-*` / `chore/i18n-*` برانچز، شیڈولڈ `i18n-mirror-refresh.yml`) اور ریلیز (`npm run release:sync-changelog-i18n`) کے ذریعے ایک قدم میں دوبارہ لکھا جاتا ہے۔ لہذا آئینہ کے دروازے دو طریقوں میں چلتے ہیں، جو `scripts/check/lib/gateMode.mjs` (`--mode=pr|release`، پھر `OMNIROUTE_GATE_MODE`، پھر ایکشن ایونٹ؛ ایک مقامی رن ہے `release`):

- `check:docs-sync` — release mode runs every check. PR mode keeps the package.json/OpenAPI version, the root CHANGELOG headings and the superseded-docs guard, and prints `SKIP reason=pr-mode` for the `llm.txt` mirror copies and the translated CHANGELOG sections — unless the PR writes mirrors: a head branch declared as a writer of the `docs/i18n/**` family in `config/quality/derived-paths/*.json` runs both checks strictly, and, when the diff base resolves, a change whose own diff edits `docs/i18n/<locale>/llm.txt` or `CHANGELOG.md` runs that check strictly. The diff base does not resolve in a depth-1 checkout (the `docs-sync-strict` job), so PR mode also runs one check that needs no base: every `llm.txt` mirror must exist, keep its `---` separator and carry either the root body or the body most mirrors share. A base that moved leaves all mirrors equally stale and passes; a hand edit to one mirror fails. The translated `CHANGELOG.md` files have no such check in a depth-1 PR checkout.
- پری کمٹ ہک `check-docs-sync.mjs --mode=pr` چلاتا ہے : ایک کمٹ کا فیصلہ اس بات پر کیا جاتا ہے کہ وہ کیا کرتا ہے۔ جھنڈے کے بغیر ایک مقامی رن ریلیز موڈ ہے، اور ایک ضم شدہ PR جو روٹ `llm.txt` میں ترمیم کرتا ہے اس بیس پر ہر بعد کی کمٹ کو اس وقت تک روک دے گا جب تک کہ لہر نہ چل جائے۔ ہسکی ہک کے چلنے والے کسی بھی موڈ سے آگاہ گیٹ کے لیے بھی یہی اصول ہے: ہک `--mode=pr` سے گزرتا ہے، اور سخت فیصلہ ریلیز موڈ رنز کے ساتھ رہتا ہے (ریلیز PR، pushes to `main`، ایک سادہ لوکل رن)۔
- آئینہ مواد یونٹ ٹیسٹ (`tests/_helpers/mirrorFreshness.ts`: `cycle-docs-mirror-contract`, `resilience-pre-dispatch-docs-mirrors`, `cli-env-quality-docs-mirrors`, `docs/*-locales`) — ریلیز موڈ ہر مقام پر زور دیتا ہے۔ PR موڈ صرف ان آئینوں پر زور دیتا ہے جو `.i18n-state.json` (پوری فائل ہیش، یا ٹیسٹ پن کے سیکشن کا ریکارڈ شدہ سیکشن ہیش) کے مطابق انگریزی ماخذ کے ساتھ موجودہ ہیں اور باسی کو ایک وجہ کے ساتھ چھوڑ دیتا ہے۔ `target_hash` پرووینس چیک دونوں طریقوں میں ہر لوکیل کے لیے چلتے ہیں۔ تازگی فی `## ` سیکشن ہے، یونٹ `run-translation.mjs` ہیشز؛ ایک لمبا سیکشن (اس فائل کی گیٹ انوینٹری اس کا تقریباً نصف ہے) کا مطلب ہے کہ اس میں کوئی بھی ترمیم ان عکسوں کو باسی چھوڑ دیتی ہے، اور ان کے پی آر موڈ کے دعوے اگلی لہر تک چھوڑ جاتے ہیں۔ ایک اینکر جس میں انگریزی ماخذ اب شامل نہیں ہے وہ پوری فائل کے موازنہ پر واپس آتا ہے۔
- `i18n translation drift` — PRs پر ایڈوائزری، پش پر سخت، رات کے وقت اور ریلیز کٹ، لہذا ایک باسی آئینہ ریلیز میں نہیں بھیج سکتا۔

`scripts/i18n/sync-llm-mirrors.mjs` ( `syncLlmMirrors()` کے طور پر بھی برآمد کیا جاتا ہے، `--dry-run` کے ساتھ) `llm.txt` آئینے کو دوبارہ لکھتا ہے۔ ریلیز ریفریش، ٹرانسلیشن ویو اور شیڈولڈ `i18n-mirror-refresh.yml` اسے چلاتے ہیں (ریفریش ڈرائی رن کے ساتھ باسی `llm.txt` آئینوں کا پتہ لگاتا ہے، کیونکہ ڈرفٹ رپورٹ ان کی فہرست نہیں دیتی ہے، اور `check:docs-all` سے پہلے انہیں ہم آہنگ کرتی ہے)۔

`docs/diagrams/` کے تحت بارہ README SVGs پیدا ہوتے ہیں (`scripts/docs/gen-readme-<name>.mjs`؛ `npm run docs:readme-diagrams` ان سب کو دوبارہ تخلیق کرتا ہے)۔ ہر ایک کا بائٹ کمپیئر یونٹ ٹیسٹ (`tests/unit/docs/readme-*-svg.test.ts`, job `test-unit`) ہوتا ہے جو اس وقت ناکام ہو جاتا ہے جب کمٹڈ فائل ریلیز موڈ میں باسی ہو جاتی ہے۔ ایک PR میں، `check:generated-artifacts` ایک SVG میں PR کی ترمیم کا فیصلہ کرتا ہے اور بیس کے بڑھنے کو ریلیز ریفریش پر چھوڑ دیا جاتا ہے (دیکھیں [جنریٹڈ فائلز اور اخذ کردہ بیس لائنز](#generated-files-and-derived-baselines-written-at-release) ) — اور `check:docs-counts` اپنے `<text>` نوڈز — سے کینونیکل نمبرز پڑھتے ہیں جس کی وجہ سے آؤٹ لائننگ `<text>` فائل میں ہر سٹیپ میں آؤٹ لائننگ سٹیپ کو ظاہر کرتی ہے۔ SVG کینونیکل نمبر چیک `SVG_DIAGRAM_FILES` (`scripts/check/check-docs-counts-sync.mjs`): `docs/diagrams/readme-hero.svg`, `free-tier-budget.svg`, `promise-pillars.svg`, `comparison-table.svg`, `cli-terminal.svg`, `tier-cascade.svg`, علاوہ `public/images/tier-flow-dark.svg` اور `tier-flow-light.svg`؛ میں درج فائلوں کو پڑھتا ہے۔ فری-ایور، کیٹلاگ-انٹری، ریکرنگ پول اور اسکورنگ فیکٹرز کے دعوے `promise-pillars.svg`، `free-tier-budget.svg` اور `strategies-grid.svg` بھی پڑھتے ہیں۔ یہ جنریٹرز جو شمار کرتے ہیں (فراہم کرنے والے کی کل، MCP ٹولز، روٹنگ کی حکمت عملی، مفت ہمیشہ کے لیے فراہم کرنے والے، …) حقائق کے سنیپ شاٹ `docs/reference/derived-facts.json` سے `scripts/docs/readmeFacts.mjs` کے ذریعے آتے ہیں، لٹریلز سے نہیں، اس لیے کسی بھی برانچ پر ڈایاگرام کو دوبارہ بنانا کمٹڈ فائل کو دوبارہ تیار کرتا ہے۔ `free-tier-budget.svg` اسی اسنیپ شاٹ سے اپنی قطاریں کھینچتا ہے (`code.freeTierBudget`، کیٹلاگ کا خلاصہ حقائق کی تحقیقات کے ریکارڈز)، لہذا `FREE_MODEL_BUDGETS` میں تبدیلی CI سرخ کرنے کے بجائے اگلے ریفریش پر کارڈ تک پہنچ جاتی ہے۔

### اخذ کردہ اقدار: `pr` اور `release` گیٹ موڈز

ایک فیچر PR کبھی بھی ایسی قدر نہیں لکھتا جو اس کی بنیاد کی حالت پر منحصر ہو: فراہم کنندہ، منتقلی، MCP-ٹول اور حکمت عملی شمار، README SVG نمبرز، حقائق کا اسنیپ شاٹ۔ ایک قدم ان سب کی دوبارہ گنتی کرتا ہے، `npm run release:refresh-derived`، ریلیز کے ذریعے چلایا جاتا ہے اور رات کے وقت اخذ کردہ-ریفریش PR کے ذریعے۔ تو** ریلیز کے درمیان بیس ڈیزائن کے لحاظ سے لائیو کوڈ کے پیچھے ہوتا ہے۔** ، اور ایک گیٹ یا ٹیسٹ جو درخت کا لائیو کوڈ کے ساتھ موازنہ کرتا ہے، بہن بھائی کے فراہم کنندہ کو شامل کرنے کے بعد ہر PR پر سرخ ہو جائے گا۔ گیٹس جو اخذ کردہ اقدار کا فیصلہ کرتے ہیں لہذا دو طریقوں میں سے ایک میں چلتے ہیں، `scripts/check/lib/gateMode.mjs` (پہلے میچ کی جیت):

1. کمانڈ لائن پر `--mode=pr|release` ؛
2. `OMNIROUTE_GATE_MODE` ماحولیاتی متغیر (`pr` یا `release`)؛
3. خودکار، GitHub ایکشن ایونٹ سے: ایک `pull_request` جس کا سر `release/v*` نہیں ہے، `merge_group`، یا `omni-queue/**` → `pr` کی طرف دھکیلنا؛ باقی سب کچھ (دھکا، شیڈول، ڈسپیچ، ریلیز PR `release/v* → main`، کوئی بھی مقامی رن) → `release`۔

کیا `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) ہر موڈ میں ناکام ہوتا ہے:

| موڈ       | ناکام ہو جاتا ہے۔                                                                                                                                                                                                                                                                                                                                                                                              | زندہ حقائق کی ضرورت ہے۔ |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| `release` | ہر چیک، درخت سے جمع کیے گئے حقائق کے خلاف سخت مساوات (وہ رویہ جو گیٹ کا ہمیشہ ہوتا تھا): ایک باسی شمار، ورژن، کوریج فلور یا SVG نمبر ایک STRICT بہاؤ ہے                                                                                                                                                                                                                                                        | جی ہاں                  |
| `pr`      | صرف وہی تبدیلی تھی جو PR بیس کے خلاف ایک ہی کلیم ایکسٹریکٹرز کے ساتھ مختلف تھی: (1) ایک منظم قدر جو اس چیک اور فائل کے لیے بیس میں موجود نہیں تھی ("PR ایک منظم نمبر میں ترمیم کی — نے لائن کو بیس ٹیکسٹ پر بحال کیا")؛ (2) ایک مطلوبہ دعویٰ جو اڈہ لے گیا اور سر کھو گیا۔ مواد کے انویریئنٹس جن کو حقائق کی ضرورت نہیں ہوتی ہے جیسا کہ ریلیز موڈ میں چلایا جاتا ہے۔ صرف ریلیز چیکز درج ہیں اور چھوڑے گئے ہیں۔ | نہیں                    |

ایجنٹ کی ہدایات کی فائلیں لے جاتی ہیں۔** نہیں** ماخوذ شمار بالکل: `AGENTS.md`، `llm.txt` (اور اس کی `docs/i18n/*/llm.txt` کاپیاں)، bs `AGENTS.md` فورک، `open-sse/services/AGENTS.md`، `src/shared/constants/agentSkills.ts`، `skills/README.md` اور ہر `skills/*/SKILL.md` ماخذ کی طرف اشارہ کرتا ہے (مثال کے طور پر `src/shared/constants/routingStrategies.ts` میں `ROUTING_STRATEGY_VALUES` ) اور اس کی بجائے `npm run facts` کی طرف۔ غیر متزلزل "کوئی اخذ کردہ شمار نہیں (ایجنٹ-انسٹرکشن فائل …)" دونوں طریقوں میں وہاں گنتی (فراہم کرنے والے، منتقلی، MCP ٹولز اور اسکوپس، روٹنگ کی حکمت عملی، اسکورنگ عوامل، موڈ پیک) میں ناکام ہوجاتا ہے، لہذا ریلیز ریفریش کو کبھی بھی انسٹرکشن فائل کو دوبارہ لکھنا نہیں پڑتا ہے۔

`pr` موڈ میں مصنف کی شاخیں منظم اقدار میں ترمیم کر سکتی ہیں: `chore/derived-*` (نائٹلی ریفریش PR)، `release/v*`، اور ترجمہ کی لہریں `docs/i18n-*` اور `chore/i18n-*` (`scripts/check/lib/derivedClaimsDiff.mjs`)۔ قطار کے بیچوں (`merge_group`, Mergify drafts , `omni-queue/**`) کا دوبارہ فیصلہ نہیں کیا جاتا ہے: وہ ایک ایک کرکے پہلے سے طے شدہ گیٹ کو PRs کرتے ہیں۔

Exit codes: `0` clean · `1` STRICT drift (or soft drift with `--strict`) or a managed-value violation · `2` infrastructure — the code facts could not be collected (the tsx probe failed or timed out; the timeout is `OMNIROUTE_FACTS_TIMEOUT_MS`, default 600000 ms) or, in CI, the PR diff base could not be resolved. An exit 2 is never a documentation divergence: re-run the job or fix the environment.

جہاں ہر موڈ چلتا ہے:

| جہاں                                                                                                 | موڈ                                                                                                                                                                                                       |
| ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| خصوصیت PR — `ci.yml` job `docs-sync-strict`, `quality.yml` قدم "دستاویزات کی درستگی"                 | `pr` (خودکار)؛ جاب بیس کو `BASE_SHA` کے طور پر پاس کرتی ہے اور `fetch-depth: 2` کے ساتھ چیک آؤٹ کرتی ہے۔                                                                                                  |
| `merge_group`، `omni-queue/**` امیدوار، ضم ٹرین کی مکمل گیٹ لسٹ                                      | `pr`                                                                                                                                                                                                      |
| PR (`release/v* → main`)، پش، شیڈول اور مینوئل رنز جاری کریں۔                                        | `release`                                                                                                                                                                                                 |
| ریلیز گرین (`scripts/quality/validate-release-green.mjs`)                                            | HARD اشیاء `OMNIROUTE_GATE_MODE=pr` کے ساتھ چلتی ہیں ("کیا بنیاد ٹوٹ گئی؟")؛ DRIFT آئٹم `derived-refresh` `npm run release:refresh-derived -- --check` چلاتا ہے (سخت نظریہ، کبھی بھی بیس ریڈ نہیں کھولتا) |
| ریلیز (`/generate-release` مراحل 0a اور 1؛ مہارت کی وائرنگ ایک الگ مالک کی منظور شدہ تبدیلی ہے)      | `npm run release:refresh-derived` اخذ کردہ فائلوں کو لکھتا ہے۔ ریلیز PR کے اپنے چیک پھر `release` موڈ میں چلتے ہیں۔                                                                                       |
| `nightly-derived-refresh.yml` (روزانہ، سب سے زیادہ `release/vX.Y.Z`، ریلیز فریز کے تحت چھوڑ دیا گیا) | `npm run release:refresh-derived -- --profile=nightly` ایک فرق پر یہ ONE PR `chore/derived-refresh` سے کھلا رکھتا ہے۔ کبھی ضم نہیں ہوتا                                                                   |

اس کے پیچھے احکام:

- `npm run facts` ہر اخذ کردہ نمبر کو JSON (`scripts/release/facts.mjs`) کے بطور پرنٹ کرتا ہے۔ `--key=code.mcpTools` ایک قدر پرنٹ کرتا ہے، `--snapshot` لائیو ٹری کی بجائے کمٹڈ سنیپ شاٹ پڑھتا ہے۔ 2 سے باہر نکلیں جب حقائق اکٹھے نہ کیے جا سکیں۔
- `npm run release:refresh-derived` (`scripts/release/refresh-derived.mjs`) اخذ کردہ فائلوں کی دوبارہ گنتی ایک پاس میں کرتا ہے، اس ترتیب میں ( `--only=` کے لیے مرحلہ وار ids): `provider-reference` (`docs/reference/PROVIDER_REFERENCE.md`) , `facts` (اسنیپ شاٹ)، `numbers` (کاؤنٹس گیٹ کا دوبارہ لکھنے کا منصوبہ دستاویزات پر لاگو کیا جاتا ہے، پھر ان کے `docs/i18n/` ) `ui-keys` `readme-diagrams` `skills` `SKILL.md` `syncE2eTimings` `e2e-timings` `en.json` دیا گیا اور، `--rewritten-since=<ref>` — کے ساتھ ڈیفالٹ `origin/main` — دوبارہ قطاریں آخری ریلیز کے بعد سے دوبارہ لکھی گئیں؛ اقدار کا ترجمہ `.env` اینڈ کے ذریعہ اسی رن میں کیا جاتا ہے جو `OMNIROUTE_TRANSLATION_*` ماحول میں ترتیب دیا گیا ہے، یا صرف وہ کلیدیں پڑھی جاتی ہیں جو ماحول میں ہیں Google انجن بیک اینڈ کے بغیر کبھی بھی `__MISSING__` مارکر نہیں لکھتا: ریلیز پروفائل فیل ہو جاتا ہے، رات کے وقت کلیدوں کو چھوڑ دیتا ہے، اور `--allow-untranslated` انہیں مقصد کے مطابق لکھتا ہے)، `llm-mirrors` اور `verify-generated` (لکھنے کے بعد، `check:generated-artifacts` اور `check:agent-skills-sync` ریلیز موڈ میں پاس کرنا ضروری ہے؛ `--check` میں چھوڑ دیا جاتا ہے اور جب یہ `--only` سے باہر ہو جاتا ہے)۔ `changelog` مرحلہ آپٹ ان ہے (`--with-changelog`، صرف پروفائل ریلیز)۔ `--profile=nightly` کبھی بھی ورژن کے دعوے کو نہیں چھوتا۔ `-- --check` کے ساتھ یہ کچھ نہیں لکھتا اور 1 سے باہر نکلتا ہے جب کوئی فائل تبدیل ہوتی ہے یا مینیجڈ ویلیو کو دستی ترمیم کی ضرورت ہوتی ہے (دونوں کی فہرست)؛ بنیادی ڈھانچے کی ناکامی پر 2 سے باہر نکلیں۔ `--json` نتیجہ کو JSON کے بطور پرنٹ کرتا ہے۔
- `docs/reference/derived-facts.json` ان حقائق کا سنیپ شاٹ ہے جو آخری ریفریش استعمال کیا گیا تھا۔ صرف ریفریش اسے لکھتا ہے۔ README SVG جنریٹرز اسے پڑھتے ہیں، اور PR-time یونٹ ٹیسٹ اس کے ساتھ کمٹڈ دستاویزات اور تیار کردہ فائلوں کا موازنہ کرتے ہیں — کبھی لائیو کوڈ کے ساتھ نہیں۔ سوٹ کا واحد لائیو موازنہ `tests/unit/check-docs-counts-sync.test.ts` میں "ریلیز ریفریش سائیکل کو بند کر دیتا ہے" ہے: لائیو حقائق کے ساتھ، میموری میں لاگو ریفریش کے دوبارہ لکھنے کا منصوبہ کوئی STRICT بہاؤ نہیں چھوڑتا ہے جو اس کی اطلاع نہیں دیتا ہے، اور دوبارہ منصوبہ بندی سے کچھ بھی نہیں بدلتا ہے۔

مقامی طور پر دوبارہ پیش کرنے کے لیے (ایک مقامی رن ڈیفالٹ `release` پر):

```bash
npm run check:docs-counts                                       # release: strict, live facts
node scripts/check/check-docs-counts-sync.mjs --mode=pr          # what a feature PR is judged on
OMNIROUTE_GATE_MODE=pr BASE_REF="origin/release/v$(node -p "require('./package.json').version")" npm run check:docs-counts
npm run release:refresh-derived -- --check                       # what the release would rewrite
```

حل کرنے کے قابل بنیاد کے بغیر (کوئی `BASE_SHA`/`BASE_REF`، کوئی مقامی `origin/release/v<version>` نہیں) ایک مقامی `pr` رن ایک وارننگ پرنٹ کرتا ہے اور فیل ہونے کے بجائے فرق کو چھوڑ دیتا ہے۔

| `check-translation-ratio`          | حقیقی ترجمہ کا تناسب فی لوکیل (ایک جیسی سے انگریزی / پلیس ہولڈر / اجازت کی فہرست سے باہر غائب پتے) `config/quality/i18n-translation-baseline.json` + slack سے زیادہ نہیں ہونا چاہئے | ہاں (صرف ریلیز موڈ) |

Needs `fetch-depth: 0` — the value-drift gate diffs `en.json` against the merge base.

**دو موڈ (2026-11-13 سے)۔** ایک خصوصیت PR `en.json` (اور `bin/cli/locales/en.json`) میں چابیاں جوڑتی یا دوبارہ لکھتی ہے اور کسی دوسرے مقام کو نہیں چھوتی ہے۔ `check:pr-derived-paths` (job `pr-test-policy`, family `config/quality/derived-paths/translation.json`) ایک خصوصیت PR ناکام کرتا ہے جو کرتا ہے۔ دیگر لوکیلز فی ریلیز ایک بار `release:refresh-derived` کے ذریعے مکمل کیے جاتے ہیں، جو `scripts/i18n/sync-ui-keys.mjs` میں `syncUiKeys()` کہتے ہیں (گمشدہ چابیاں شامل کریں، گرے ہوئے کو کاٹیں، `rewrittenSinceRef` کے ساتھ دوبارہ لکھے گئے انگریزی کے ترجمہ کو نشان زد کریں، ترجمہ کریں)، یا ترجمہ لہر کے ذریعے۔ گیٹس `scripts/check/lib/gateMode.mjs` سے موڈ کو پڑھتے ہیں: `pr` موڈ میں (فیچر PRs، `merge_group`، `omni-queue/**`) پرنٹ `SKIP reason=pr-mode` اور ایگزٹ 0 کے اوپر ریلیز موڈ گیٹس؛ `release` موڈ میں (ریلیز PR, pushes to `main`, `workflow_dispatch`, local run) وہ پہلے کی طرح سخت ہیں، اور PR کی ریلیز پر diff-Aware والوں کو `BASE_REF=origin/main` مل جاتا ہے، اس لیے وہ سائیکل کو شامل یا دوبارہ لکھنے والی ہر کلید کا فیصلہ کرتے ہیں۔ فیچر-PR فیصلے کا مقامی طور پر `--mode=pr` کے ساتھ پیش نظارہ کریں۔

ایک PR جو اب بھی `pr` موڈ میں لوکل کیٹلاگ کو تبدیل کرتا ہے (ترجمے کی لہر، ریلیز ریفریش، صرف ترجمہ کے لیے فکس) کو نہیں چھوڑا جاتا: `check-key-completeness` ہر ایک کیٹلاگ کو جج کرتا ہے جو اس نے انضمام کی بنیاد پر ایک ہی کیٹلاگ کے خلاف تبدیل کیا تھا (`scripts/i18n/lib/touched-catalogs.mjs`) اور کیٹلاگ کھو جانے والی کلید پر ناکام ہوجاتا ہے، کلیدی `en.json` `__MISSING__:` میں تبدیل کرتا ہے یا اصلی متن میں تبدیل ہوتا ہے ایک ایسی قدر جو اب انگریزی سٹرنگ کے placeholders/tags انٹرپول نہیں کرتی ہے جس کو PR نے ہاتھ نہیں لگایا۔ PR میں نئے کیٹلاگ میں پورے `en.json` کلید کا سیٹ ہونا ضروری ہے۔ یہ احاطہ کرتا ہے، کیٹلاگ کے لیے PR چھوتا ہے، تناسب اور CLI- برابری کے دروازے کیا دیکھیں گے۔

لوکل پیریٹی یونٹ ٹیسٹ (`cli-i18n-catalog`, `i18n-pt-br`, `i18n-vi-completeness`, `i18n-placeholder-parity`) `tests/_helpers/localeParityMode.ts` کے ذریعے انہی طریقوں کی پیروی کرتے ہیں: `pr` موڈ میں وہ کلیدی برابری کے دعوے کو چھوڑ دیتے ہیں اور ریلیز پر چھوڑتے ہیں ان کلیدوں کی پلیس ہولڈر برابری کو ریفریش کرتے ہیں جن کی انگلش انضمام کی بنیاد کے بعد سے تبدیل ہو جاتی ہے (ہر کلید جب اسے پڑھتی ہے' یونٹ شاٹ آؤٹ نہیں کر سکتی)۔ وہ مددگار ہے۔** صرف** sanctioned mode-conditional skip: `check:test-masking` `.skip(` اور `{ skip: true }` کو شمار کرتا ہے لیکن اس کی واپسی کی گئی `{ skip: "<reason>" }` نہیں، لہذا `tests/unit/locale-parity-mode.test.ts` ٹیسٹوں کی فہرست کو پن کرتا ہے جو اسے استعمال کرنے کی اجازت دیتا ہے — شامل کرنا اس فہرست میں ایک جائزہ شدہ ترمیم ہے۔

#### `check-ui-value-drift` — باسی ترجمہ گیٹ

ایک i18n رجعت کو پکڑتا ہے جسے دوسرے دروازے ساختی طور پر نہیں دیکھ سکتے ہیں: ایک انگریزی قدر دوبارہ لکھی جاتی ہے اور _previous_انگریزی سے اخذ کردہ ترجمے پیچھے رہتے ہیں، اس لیے غیر انگریزی استعمال کنندہ اعتماد سے پڑھتے رہتے ہیں، اب غلط نقل۔

یہ اصلی کے لئے بھیج دیا گیا ہے۔ `oauthModal.googleOAuthWarning` کو دوبارہ لکھا گیا جب Antigravity لاگ ان مددگار (#5203);** 43 میں سے 39 مقامات** آپریٹرز کو "مکمل URL کاپی کریں اور اسے نیچے چسپاں کریں" — ایک ایسا بہاؤ جو اس فراہم کنندہ کے لیے مکمل نہیں ہو سکتا متن کو برقرار رکھا۔ یہ #8463 تک کسی کا دھیان نہیں گیا کیونکہ:

- `sync-ui-keys` صرف بیک فلز چابیاں ہیں جو ہیں۔** غیر حاضر** , وہ کبھی نہیں ہیں** باسی** ;
- `check-ui-keys-coverage` کلیدی _موجودگی_ کو شمار کرتا ہے، لہذا ایک باسی ترجمہ اسکور کے طور پر احاطہ کرتا ہے؛
- `check-translation-drift` `docs/i18n/<locale>/**.md` دستاویزات کو ٹریک کرتا ہے — یہ کبھی نہیں پڑھتا `src/i18n/messages/*.json`۔ یہ جاب `docs-sync-strict` میں چلتا ہے: PRs پر ایڈوائزری، پش پر سخت اور رات کے وقت۔ ترجمہ کی لہر آئینے کو تازہ کرتی ہے، خصوصیت PR نہیں۔

**اختلاف سے آگاہ، بیس لائن کی حمایت یافتہ نہیں۔** یہ کام کرنے والے درخت سے مرج بیس پر `en.json` موازنہ کرتا ہے۔ ہر اس کلید کے لیے جس کی انگریزی کی قدر بدل گئی ہے، کوئی بھی مقامی زبان جس میں ابھی تک اچھوت ترجمہ ہے وہ باسی ہے۔ یہ جان بوجھ کر** پہلے سے موجود قرض کو منجمد کرتا ہے۔** — a diff یہ ظاہر نہیں کر سکتا کہ کون سی پرانی انگریزی کا دیرینہ ترجمہ آیا ہے، اس لیے گیٹ صرف وہی فیصلہ کرتا ہے جو موجودہ تبدیلی کو چھوتی ہے۔ متبادل (ایک فی کلید ہیش بیس لائن) کی لاگت ایک ~ 600 KB فائل ہوگی، 3 × سب سے بڑی موجودہ بیس لائن، ہر i18n PR پر منتھنی۔

اسے مطمئن کرنے کے دو طریقے:

1. متاثرہ تراجم کو اپ ڈیٹ کریں، یا
2. رن ٹائم انہیں `__MISSING__:<new english>` — پر سیٹ کریں پھر درست انگریزی (`src/i18n/request.ts::deepMergeFallback`, #7258) اور ترجمے کے لیے کلیدی قطاریں پیش کریں۔

اگر تار کی** معنی** تبدیل، ترجیح** کلید کا نام تبدیل کرنا** : ایک نئی کلید باسی ترجمہ کی وارث نہیں ہو سکتی۔ یہی پیٹرن #8463 استعمال ہوتا ہے۔

```bash
npm run i18n:check-value-drift          # strict (what CI runs)
npm run i18n:check-value-drift:warn     # report only
BASE_REF=origin/release/vX.Y.Z npm run i18n:check-value-drift
```

`SKIP reason=base-unresolved` کے ساتھ 0 سے باہر نکلتا ہے جب بیس کیٹلاگ کو نہیں پڑھا جا سکتا ہے (بیس ریف کے بغیر اتلی کلون)، `check-openapi-breaking` کی عکس بندی کر رہا ہے۔ صرف ریلیز موڈ: ایک فیچر PR انگریزی کو دوبارہ لکھتا ہے اور وہیں رک جاتا ہے۔ ریلیز ریفریش ان تراجم کو نشان زد کرتا ہے جو اس نے پیچھے چھوڑے تھے (`node scripts/i18n/sync-ui-keys.mjs --rewritten-since=<ref>`, same `findStaleTranslations`)۔

`pull_request` واقعات پر `quality.yml` `--base-ref <PR base SHA>` سے `check:file-size`, `check:complexity-ratchets` اور `check:dead-code` گزرتا ہے۔ `check:complexity-ratchets` اور `check:dead-code` کے لیے گیٹ HEAD موازنہ merge-base سے کرتا ہے** PR کو چھونے والی فائلوں تک محدود** (`scripts/check/newCodeMode.mjs`: مرج کی بنیاد ایک پھینکے ہوئے `git worktree` میں تیار کی جاتی ہے، ESLint/knip وہاں چلتا ہے اور HEAD پر، فی فائل کی گنتی مختلف ہوتی ہے):

## Ratchet بیس لائن (`quality-baseline.json`)

ریچیٹ انجن (`scripts/quality/check-quality-ratchet.mjs`) `quality-baseline.json` پڑھتا ہے اور اس کا موازنہ تازہ جمع کیے گئے `quality-metrics.json` سے کرتا ہے۔ کوئی بھی میٹرک جو اپنے ایپسیلون سے آگے بڑھتا ہے وہ تعمیر میں ناکام ہوجاتا ہے۔

موجودہ ٹریک کردہ میٹرکس:

| میٹرک                 | سمت    | مطلب                                     |
| --------------------- | ------ | ---------------------------------------- |
| `eslintWarnings`      | `down` | ESLint وارننگ کی تعداد نہیں بڑھنی چاہیے۔ |

### CodeQL ratchet: کیڈینس اور دستی ٹرگر کو ریفریش کریں۔

`check:codeql-ratchet` پڑھتا ہے۔** ریپو اسٹیٹ، ایک شیڈول — پر ریفریش نہیں فی PR۔** `gh api repos/diegosouzapw/OmniRoute/code-scanning/default-setup` رپورٹ کرتا ہے `state: configured`, `schedule: weekly`: GitHub کا ڈیفالٹ سیٹ اپ اسکین، فی پش تجزیہ نہیں۔ نتیجہ: ایک PR کے بعد جو FIXES انتباہات کے ضم ہو جاتا ہے، ratchet اس وقت تک پرانی، اعلیٰ گنتی کو پڑھتا رہتا ہے جب تک کہ اگلا طے شدہ سکین — نہیں چلاتا، لہذا یہ ہر کھلے PR پر ریگریشن کی اطلاع دیتا ہے، بشمول فکسنگ PR کے اپنے فالو اپس، جب تک کہ سکین مکمل نہ ہو جائے۔

**دستی ریفریش** : `gh workflow run codeql.yml --ref release/vX.Y.Z` تجزیہ کو دوبارہ چلاتا ہے اور منٹوں میں الرٹس کو دوبارہ شائع کرتا ہے۔ `.github/workflows/codeql.yml` پہلے — پڑھیں اس کا ہیڈر بتاتا ہے کہ یہ `workflow_dispatch` -only ہے۔** کیونکہ یہ GitHub کے "ڈیفالٹ سیٹ اپ" سے متصادم ہے** (`CodeQL analyses from advanced configurations cannot be processed when the default setup is enabled`) `push`/`pull_request`/ `schedule` ٹرگرز کو بحال کرنے کے لیے ایک کی ضرورت ہے۔** پہلے مالک کی کارروائی** : سیٹنگز → کوڈ سیکیورٹی → CodeQL: ڈیفالٹ → ایڈوانسڈ۔ اس سوئچ — کے بغیر `schedule:` ٹرگر شامل نہ کریں یہ صرف ناکام رنز بنائے گا۔

**گنتی میں کمی کے بعد بیس لائن کو سخت کریں۔** — `node scripts/check/check-codeql-ratchet.mjs --update` نئی ناپی گئی گنتی کو `quality-baseline.json` → `metrics.codeqlAlerts.value` میں لکھتا ہے، اس لیے شافٹ خاموشی سے پرانی چھت تک واپس جانے کی اجازت نہیں دیتا ہے۔ کام کی مثال (2026-09-02/03): PR #12502 فکسڈ 7 اصلی الرٹس (13 → 6 ماپا کھلا)؛ PR #12530 نے منجمد بیس لائن 11 → 6 کو میچ کرنے کے لیے سخت کر دیا۔ بقیہ 6 کو پھر 0 کھلے پر فی الرٹ جواز کے ساتھ برخاست کر دیا گیا۔

**برطرفی آپریٹر کی کال ہے (سخت اصول #14)** — برخاستگی کے تبصرے میں تکنیکی جواز کو ریکارڈ کیے بغیر کبھی بھی CodeQL الرٹ کو مسترد نہیں کرتا ہے: `won't fix` upstream-protocol کی ضرورت کے لیے، `used in tests` ٹیسٹ فکسچر کے لیے، `false positive` سینیٹائزر کے لیے CodeQL نہیں دیکھ سکتا (نظیر: `docs/security/ERROR_SANITIZATION.md`)۔

مصنفین (`release/v*`, `chore/derived-*`, اور `chore/bank-ratchet-*` بنیادی خطوط کے لیے ) مستثنیٰ ہیں؛ اسی طرح ایک PR ہے جو صرف ایک خاندان کے علاوہ اس کے ساتھیوں کو تبدیل کرتا ہے ( `generated` کے لیے: جنریٹر اسکرپٹس، ان کے ٹیسٹ، ایجنٹ کے ہنر کے ان پٹ — `src/shared/constants/agentSkills.ts`، ہاتھ سے لکھے ہوئے `skills/**` دستاویزات، `docs/openapi.yaml` — اور `changelog.d/**`)، جیسے ہیرو لے SVG کو تبدیل کرتا ہے، جس کی مہارت کو دوبارہ پڑھا جاتا ہے دوبارہ تخلیق شدہ `SKILL.md` فائلیں۔ ہاتھ سے لکھا ہوا `<!-- skill:custom-start -->` بلاک والا `SKILL.md` خاندان میں نہیں ہے: اس کا حسب ضرورت بلاک کسی خصوصیت کے ساتھ قابل تدوین رہتا ہے۔

یتیم صفائی کا فیصلہ خاندانوں کے ذریعہ بھی نہیں کیا جاتا ہے: ایک PR `docs/i18n/<locale>/<doc>` حذف کر سکتا ہے جب انضمام کی بنیاد میں وہ آئینہ ہو اور `<doc>` اب PR کے سر میں موجود نہیں ہے، اور `.i18n-state.json` میں ترمیم کر سکتا ہے صرف ایسی دستاویزات کو `sources` سے چھوڑنے کے لیے۔ گارڈ ان فائلوں کو `orphan-cleanup` کے تحت درج کرتا ہے۔ کسی دستاویز کے آئینہ کو حذف کرنا جو اب بھی موجود ہے خلاف ورزی رہتی ہے: کوئی دوسری پائپ لائن اس کو ٹریک نہیں کرتی ہے، اور `llm.txt` اور `CHANGELOG.md` آئینے کے اپنے مصنف ہیں۔

خاندان میں نہیں، جان بوجھ کر: لوگوں کی طرف سے طے شدہ پالیسی فائلیں (`gate-manifest.json`, the allowlists , `admission-policy.json`, `provider-assets-provenance.jsonl`, `model-lifecycle.json`) اور ایک خصوصیت PR کوڈ کے ساتھ مل کر ترمیم کرنا پڑ سکتی ہے (`quality-baseline.json` میٹرک اندراجات، typecheck/file-size/complexity بیس لائنز، `eslint-suppressions.json` — pruned a pre-qzkzen a pre- ESLint جب PR کے ذریعے کاٹ دی جاتی ہے۔ خلاف ورزی)۔ `src/i18n/routeNamespaces.generated.json` بھی تیار ہوتا ہے لیکن فیچر PRs میں رہتا ہے: ایپ اسے رن ٹائم پر درآمد کرتی ہے، اس لیے یہ ریفریش کا انتظار نہیں کر سکتی۔

## ریچیٹ کی کمیوں کو محفوظ کرنا — تنزلی کی سمت (#8584)

ریچیٹ صرف نصف خودکار ہے، اور وہ بھی غلط نصف۔ حد کو **بڑھانا** ایک
دستی JSON ترمیم ہے جس میں دس سیکنڈ لگتے ہیں اور یہ سرخ PR کو بحال کرنے کا تیز ترین طریقہ ہے۔
حد کو **کم کرنے** کے لیے کسی کو `--update` چلانا اور نتیجہ commit کرنا پڑتا ہے — اور جب تک
`bank-ratchet-shrinks` جاب شامل نہیں ہوئی، کوئی workflow اسے نہیں چلاتا تھا۔ ناپا گیا نتیجہ
(2026-07-25): 18 منجمد فائلیں پہلے ہی نئی فائل کی 800 لائنوں والی حد پر یا اس سے کم تھیں، بدترین
132× پر (`src/shared/validation/schemas.ts`، 19 لائنوں کے لیے 2,523 کی حد)؛

### حفاظتی تصدیق کار

یہ جاب بغیر نگرانی کے baselines میں لکھتی ہے، اس لیے `verify-ratchet-bank.mjs` ہی اسے
قابلِ قبول بناتا ہے۔ یہ `--update` کے بعد کے tree کا `HEAD` کے ساتھ diff لیتا ہے اور **کسی بھی commit
کے وجود میں آنے سے پہلے جاب ختم کر دیتا ہے** — کوئی PR نہیں کھولتا — جب تک ہر تبدیلی ان میں سے کوئی ایک نہ ہو:

بغیر جائزے کے شامل نہیں ہو سکتی۔

## اجازت کی فہرست کی پالیسی

ہر وہ گیٹ جو پہلے سے موجود خلاف ورزیوں پر ناکام نہیں ہو سکتا ایک منجمد اجازت فہرست (مثال کے طور پر، `KNOWN_STALE_DOC_REFS`، `KNOWN_MISSING`، `KNOWN_RAW_SQL`) استعمال کرتا ہے۔ پالیسی یہ ہے:

**بنیادی وجہ کو درست کریں؛ اجازت کی فہرست کا استعمال صرف اس صورت میں کریں جب خلاف ورزی پہلے سے موجود ہو اور اسے اسی PR میں ٹھیک نہیں کیا جا سکتا۔**

اجازت کی فہرست میں اندراج شامل کرتے وقت:

1. جواز کے ساتھ ایک تبصرہ شامل کریں۔
2. ٹریکنگ کے مسئلے کا حوالہ دیں (مثلاً، `// #3498 — Phase 2 feature, not yet implemented`)۔
3. اسی PR میں اندراج کو ہٹا دیں جو خلاف ورزی — کو ٹھیک کرتا ہے ایک باسی اندراج جو اب کسی فعال خلاف ورزی کو دبا نہیں سکتا ہے بذات خود ایک خرابی ہے (6A.3 باسی نفاذ ایک بار لاگو ہونے کے بعد یتیم اجازت نامے کے اندراج پر گیٹ کو ناکام کردے گا)۔

کرو** نہیں** ٹیسٹوں کو تیزی سے پاس کرنے کے لیے اجازت نامے کے اندراجات شامل کریں۔ بڑھتی ہوئی اجازت کی فہرست کے ساتھ ایک سبز گیٹ معیار کا غلط احساس ہے۔

### جب آپ کے PR پر ایک گیٹ ناکام ہوجاتا ہے۔

1. **گیٹ آؤٹ پٹ کو احتیاط سے پڑھیں** — یہ آپ کو بالکل بتاتا ہے کہ کس فائل یا علامت نے اصول کی خلاف ورزی کی ہے۔
2. **خلاف ورزی کو درست کریں۔** — سب سے زیادہ گیٹس ڈیٹرمنسٹک فائل سسٹم چیک ہیں جو کوڈ کے درست ہوتے ہی پاس ہو جاتے ہیں۔
3. **اگر خلاف ورزی پہلے سے موجود ہے۔** (یعنی، آپ نے اسے متعارف نہیں کرایا لیکن گیٹ اب اس کا احاطہ کرتا ہے): جواز کے تبصرے اور ٹریکنگ کے مسئلے کے ساتھ اجازت دینے والی فہرست میں اندراج شامل کریں۔
4. **اگر گیٹ ایک شافٹ ہے۔** (کوریج، ESLint وارننگز، نقل، پیچیدگی): آپ کی تبدیلی نے میٹرک کو مزید خراب کر دیا۔ بنیادی مسئلے کو ٹھیک کریں، یا (شاذ و نادر ہی) `npm run quality:ratchet -- --update` چلائیں اگر تبدیلی جان بوجھ کر ہو اور میٹرک انحطاط قابل قبول — ہے لیکن PR تفصیل میں کیوں دستاویز کریں۔
5. **مشاورتی دروازے** (`continue-on-error: true`) معلوماتی — ہیں وہ انضمام کو بلاک نہیں کرتے بلکہ CI خلاصہ میں ظاہر ہوتے ہیں۔ انہیں بہرحال ٹھیک کریں۔

#### `check-key-completeness` — کلیدی سیٹ برابری گیٹ

`scripts/i18n/check-key-completeness.mjs` (`npm run i18n:check-keys`, job `i18n-ui-coverage`) ہر `src/i18n/messages/<locale>.json` کے لیف کلید کا `en.json` سے موازنہ کرتا ہے اور کسی بھی غیر حاضر یا اضافی پتے پر ناکام ہوجاتا ہے، قطع نظر اس سے کہ چابی کب شامل کی گئی ہو۔ `__MISSING__:` پلیس ہولڈرز کو حاضر شمار کیا جاتا ہے (ان کا مواد تناسب گیٹ کا کاروبار ہے)۔ یہ دو diff-based/percentage گیٹس کی مکمل تکمیل ہے: `check-ui-keys-coverage` فی لوکیل میں 80 % فلور نافذ کرتا ہے ( ~ 13,000 میں سے 43 غیر حاضر چابیاں اب بھی 99.7 % پڑھتی ہیں) اور `check-new-key-coverage` صرف ان کلیدوں کا فیصلہ کرتا ہے جو PR `en.json` میں شامل کرتا ہے۔ ایک لوکل بیچ اس دن کے `en.json` سے تیار ہوتا ہے جس دن اس کی شاخ کاٹی جاتی ہے اور دنوں تک ترجمہ ہوتا ہے جب کہ بیس چابیاں جوڑتا رہتا ہے۔ بیچ PR خود کوئی کلید شامل نہیں کی گئی، اس لیے دونوں بہن بھائی خاموش رہے جب بیچ 1 (#13044) نے نو لوکلز میں 43 کیز شارٹ کیں اور بیچ 2 (#13660) 10 کیز شارٹ آٹھ میں (2026-09-15)۔ `node scripts/i18n/sync-ui-keys.mjs --locale=<codes> --translate-markers` کے ساتھ ایک سرخ کو درست کریں؛ ایک `extra` لیف کا مطلب ہے کہ ذریعہ نے اسے گرایا — `sync-ui-keys` اسے گرا دیتا ہے (`--prune-extra`، ڈیفالٹ)۔ `--warn` ناکام ہوئے بغیر رپورٹ کرتا ہے۔ `--catalog=cli` `bin/cli/locales` (`npm run i18n:check-keys:cli`) پر ایک ہی موازنہ چلاتا ہے۔ دونوں مراحل جاب `i18n-ui-coverage` میں رہتے ہیں۔ مکمل چیک صرف ریلیز موڈ ہے: ایک فیچر PR `SKIP reason=pr-mode` دیکھتا ہے اور فکس ریلیز ریفریش یا ٹرانسلیشن ویو میں چلتا ہے، کبھی بھی کسی فیچر PR میں نہیں۔ ایک PR جو مقامی کیٹلاگ کو تبدیل کرتا ہے ان میں سے ہر ایک کو انضمام کی بنیاد کے خلاف فیصلہ کیا گیا ہے (جواب `i18n-ui-coverage` کے تحت "دو موڈز" دیکھیں)۔

#### `check-new-key-coverage` — نیو کلید i18n گیٹ

`check-ui-value-drift` کا بہنوئی کہ ایک انگریزی قدر پکڑتی ہے جو کہ تھی۔** دوبارہ لکھا** جبکہ اس کے تراجم پیچھے رہ گئے تھے۔ یہ ایک انگریزی کلید پکڑتا ہے جو کہ تھی۔** شامل کیا** جبکہ کچھ مقامی لوگوں نے اسے کبھی حاصل نہیں کیا۔

`check-ui-keys-coverage` اس کلاس کو نہیں دیکھ سکتا: یہ فی لوکل فی صد فلور نافذ کرتا ہے، اور ~ 13,000 میں سے گیارہ غیر حاضر کیز 99.9% پر کوریج چھوڑتی ہیں۔ فی زبان ایک فیصد "اس خصوصیت کو بغیر ترجمہ کے بھیج دیا گیا" — کا اظہار نہیں کر سکتا ہے، ایک پوری خصوصیت بغیر کسی متن کے ایک نئے مقام پر اتر سکتی ہے اور کبھی بھی نمبر کو منتقل نہیں کر سکتی ہے۔

واقعہ جس میں یہ انکوڈ کرتا ہے: آرکیسٹریشن کینوس کے فیز 3 نے اس وقت موجود 42 مقامات پر اپنی گیارہ کلیدوں کا ترجمہ کیا۔ گھنٹوں بعد EU-Language بیچ (#13044) نے ریپو کو 51 لوکلز تک پہنچایا، اور نو نئے آنے والوں (`el`, `et`, `ga`, `hr`, `lt`, `lv`, `mt`, `sl`, `sr`) نے انہیں کبھی موصول نہیں کیا۔ `deepMergeFallback` غیر حاضر کلید کے لیے انگریزی کی جگہ لیتا ہے، اس لیے ناکامی کا موڈ خالی UI — اصلی کی بجائے غیر ترجمہ شدہ UI تھا، اور تعمیر کے لحاظ سے خاموش تھا۔

اس کے بھائی کی طرح ہے۔** اختلاف سے آگاہ** , کام کرنے والے درخت کے خلاف ضم ہونے کی بنیاد پر انگریزی کا موازنہ کرنا، لہذا پہلے سے موجود خلا جمے رہتے ہیں اور گیٹ کو آن کرنے کے لیے کسی منتقلی کی ضرورت نہیں ہے۔
