ویب کوکی فراہم کنندگان OmniRoute کو API کلید کے بجائے آپ کے موجودہ براؤزر سیشن کے ذریعے کسی AI سروس کو استعمال کرنے دیتے ہیں۔ یہ اس وقت مفید ہوتے ہیں جب آپ کو پہلے ہی کسی سروس کی ویب سائٹ کے ذریعے اس تک رسائی حاصل ہو اور آپ چاہتے ہوں کہ OmniRoute اسی تصدیق شدہ سیشن کو استعمال کرے۔

API کلید والے فراہم کنندگان کے برعکس، ویب کوکی فراہم کنندگان ان اسناد کے ذریعے تصدیق کرتے ہیں جو آپ کا براؤزر ویب سائٹ کو بھیجتا ہے۔

# شروع کرنے سے پہلے

> **اہم:** اسناد ہمیشہ کسی **فعال نیٹ ورک درخواست** سے نقل کریں، اپنے براؤزر کے کوکی اسٹوریج سے **نہیں**۔

تصدیق کے بہت سے مسائل غلط جگہ سے کوکیز نقل کرنے کی وجہ سے پیدا ہوتے ہیں۔

## کوکی اسٹوریج سے نقل نہ کریں

زیادہ تر براؤزرز ذخیرہ شدہ کوکیز کو درج ذیل راستے سے دکھاتے ہیں:

```
DevTools
→ Application (یا Storage)
→ Cookies
```

اگرچہ یہ کوکیز درست نظر آتی ہیں، لیکن ممکن ہے کہ وہ:

- پرانی ہوں
- نامکمل ہوں
- ان کوکیز سے محروم ہوں جو صرف تصدیق شدہ درخواستوں کے ساتھ بھیجی جاتی ہیں

ان اقدار کو استعمال کرنے سے تصدیق ناکام ہو سکتی ہے، چاہے وہ بظاہر درست ہی کیوں نہ نظر آئیں۔

## فعال درخواست سے نقل کریں

اس کے بجائے، کسی کامیاب درخواست کی کوکیز استعمال کریں:

```
DevTools
→ Network
→ صفحہ ریفریش کریں
→ کوئی چیٹ یا گفتگو کی درخواست کھولیں
→ Request Headers
→ Cookie
```

`Cookie` درخواست ہیڈر میں عین وہی تصدیقی معلومات شامل ہوتی ہیں جنہیں آپ کے براؤزر نے کامیابی کے ساتھ استعمال کیا تھا۔

زیادہ تر ویب کوکی فراہم کنندگان کے لیے، یہی وہ قدر ہے جسے OmniRoute میں چسپاں کیا جانا چاہیے۔

# عمومی سیٹ اپ

زیادہ تر ویب کوکی فراہم کنندگان کے لیے سیٹ اپ کا عمل یکساں ہے۔

1. فراہم کنندہ کی ویب سائٹ میں سائن اِن کریں۔
2. براؤزر کے Developer Tools کھولیں۔
3. **Network** ٹیب کھولیں۔
4. صفحہ ریفریش کریں۔
5. کوئی تصدیق شدہ چیٹ یا گفتگو کی درخواست کھولیں۔
6. مطلوبہ تصدیقی اسناد نقل کریں۔
7. OmniRoute کھولیں۔
8. **فراہم کنندگان → فراہم کنندہ شامل کریں** پر جائیں۔
9. اپنا ویب کوکی فراہم کنندہ منتخب کریں۔
10. اسناد چسپاں کریں۔
11. **کنکشن کی جانچ کریں** پر کلک کریں۔
12. فراہم کنندہ محفوظ کریں۔

درکار اسناد کی درست نوعیت فراہم کنندہ پر منحصر ہوتی ہے۔

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) صارفین کے لیے ایک مفت چیٹ پلیٹ فارم ہے جس پر سائن اپ کی ضرورت نہیں — پہلے وزٹ پر سیشن گمنام طور پر بنایا جاتا ہے اور تین کوکیز کے ذریعے برقرار رہتا ہے: `uid`، `si_usr_id`، اور `si_ses_id`۔ OmniRoute اسی `/api/dispatch` اینڈ پوائنٹ کو ایک واحد ماڈل آئی ڈی (`notrack-c`، عرف `ntw`) کے ذریعے پراکسی کرتا ہے۔

### منسلک ہونے کے مراحل

1. اپنے براؤزر میں [notrack.ai](https://notrack.ai) کھولیں اور گمنام سیشن کوکی سیٹ ہونے دیں۔
2. **DevTools → Network** کھولیں، صفحہ ریفریش کریں، اور کسی بھی `/api` درخواست پر کلک کریں۔
3. **Request Headers** میں، مکمل `Cookie` ہیڈر کی قدر کاپی کریں۔
4. OmniRoute میں، **Providers → Add Provider → NoTrack Web (Free)** پر جائیں۔
5. کوکی اسٹرنگ کو `apiKey` فیلڈ میں پیسٹ کریں اور **Save** کریں۔

OmniRoute پیسٹ کی گئی اسٹرنگ سے `uid`، `si_usr_id`، اور `si_ses_id` اخذ کرتا ہے اور صرف ان جوڑوں کے ساتھ ایک صاف `Cookie` ہیڈر دوبارہ بناتا ہے — نیز موجود ہونے کی صورت میں `nt_session` (لاگ اِن اکاؤنٹس کے لیے سیٹ کیا جانے والا `ntk_…` ٹوکن) بھی شامل کرتا ہے۔ اگر ان تینوں میں سے کوئی ایک موجود نہ ہو تو پیسٹ کی گئی خام اسٹرنگ کو بغیر کسی تبدیلی کے فارورڈ کر دیا جاتا ہے، تاکہ آپریٹرز متبادل ساختوں کے ساتھ تجربہ کر سکیں۔

### ماڈل آئی ڈیز

| ماڈل آئی ڈی | ڈسپلے نام | نوٹس                                          |
| ----------- | --------- | --------------------------------------------- |
| `notrack-c` | NoTrack C | ڈیفالٹ — اپ اسٹریم ڈسپیچ ماڈل `C`۔            |
| `C`         | NoTrack C | `notrack-c` کا عرف (خام اپ اسٹریم ڈسپیچ کوڈ)۔ |
| `notrack`   | NoTrack C | `notrack-c` کا عرف۔                           |
| `ntw`       | NoTrack C | `notrack-c` کا مختصر عرف۔                     |

چاروں ماڈل آئی ڈیز ایک ہی اپ اسٹریم ڈسپیچ ماڈل (`C`) سے میپ ہوتی ہیں۔

### درخواست کے اختیارات

ایگزیکیوٹر درخواست کی باڈی میں درج ذیل اختیاری فیلڈز قبول کرتا ہے:

| باڈی فیلڈ             | ڈیفالٹ  | مقصد                                                                           |
| --------------------- | ------- | ------------------------------------------------------------------------------ |
| `notrack_mode`        | `usual` | ڈسپیچ موڈ (آزاد ساخت کی اسٹرنگ؛ اپ اسٹریم `usual` وغیرہ قبول کرتا ہے)          |
| `notrack_max_turns`   | `6`     | جواب دینے سے پہلے اپ اسٹریم کے اندرونی ٹرنز کی زیادہ سے زیادہ تعداد۔           |
| `notrack_chat_id`     | `null`  | موجودہ اپ اسٹریم چیٹ دوبارہ شروع کریں (نئی چیٹ کے لیے شامل نہ کریں)۔           |
| `notrack_attachments` | `[]`    | اپ اسٹریم اٹیچمنٹ ڈسکرپٹرز کی پاس تھرو ارے۔                                    |
| `notrack_regenerate`  | `false` | پچھلے ٹرن کے لیے دوبارہ تیار کردہ جواب کی درخواست کرنے کے لیے `true` سیٹ کریں۔ |

### صلاحیتیں

- **اسٹریمنگ اور نان اسٹریمنگ** چیٹ کمپلیشنز۔
- **ٹول کالنگ** — درخواست میں `tools: [...]` سیٹ کریں؛ ایگزیکیوٹر انہیں ٹول کال اینویلپ کنٹریکٹ میں سیریلائز کرتا ہے اور ماڈل کے جوابات کو واپس OpenAI `tool_calls` میں پارس کرتا ہے۔
- **`response_format`** — `json_object` اور `json_schema` معاونت یافتہ ہیں۔ ایگزیکیوٹر ماڈل کے جواب سے پہلا JSON آبجیکٹ اخذ کرتا ہے اور اسے واپس کرنے سے پہلے اسٹرنگ میں تبدیل کرتا ہے۔
- **ریزننگ کا اشارہ** — جب اپ اسٹریم کوئی `thinking` ایونٹ بھیجتا ہے تو ایگزیکیوٹر ایک `reasoning` ڈیلٹا خارج کرتا ہے۔

### حدود

- اپ اسٹریم گمنام استعمال کے کوٹے نافذ کرتا ہے — حد عبور ہونے پر ایگزیکیوٹر صارف دوست پیغام کے ساتھ 429 ظاہر کرتا ہے۔
- تمام ماڈل آئی ڈیز ایک ہی اپ اسٹریم ڈسپیچ ماڈل پر ریزولو ہوتی ہیں؛ ہر ماڈل کے لیے الگ سوئچ موجود نہیں ہے۔
- ایگزیکیوٹر اپ اسٹریم کے `/api/chats` اینڈ پوائنٹ کو کال نہیں کرتا، اس لیے چیٹ ہسٹری / سیشنز خودکار طور پر منظم نہیں ہوتے۔ موجودہ اپ اسٹریم چیٹ دوبارہ شروع کرنے کے لیے `notrack_chat_id` استعمال کریں۔

# ویب کوکی پرووائیڈرز کیا کر سکتے ہیں اور کیا نہیں

ویب کوکی پرووائیڈرز کسی ویب سائٹ کے چیٹ انٹرفیس کو دوبارہ استعمال کرتے ہیں۔ وہ آفیشل APIs جیسی صلاحیتیں فراہم **نہیں** کرتے۔

## معاونت یافتہ

- اپنے موجودہ براؤزر سیشن کے ذریعے توثیق کریں
- اپنے اکاؤنٹ کے ذریعے دستیاب ماڈلز تک رسائی حاصل کریں
- چیٹ کے جوابات کو اسٹریم کریں
- کسی API کلید کی ضرورت نہیں

## معاونت یافتہ نہیں

- فنکشن کالنگ
- ٹول کالنگ
- خودکار فائل ایڈیٹنگ
- ایجنٹ پر مبنی IDE ورک فلو
- صرف API کے ذریعے دستیاب خصوصیات

یہ متوقع طرزِ عمل ہے اور **کوئی** بگ نہیں ہے۔

اگر آپ کو ٹول چلانے، خودکار فائل ایڈیٹنگ، یا دیگر ایجنٹ ورک فلو درکار ہوں، تو Web Cookie provider کے بجائے **API-key provider** استعمال کریں۔

# توثیق سے متعلق اہم وضاحت

کامیاب **Test Connection** یا کوکی کی توثیق صرف یہ تصدیق کرتی ہے کہ فراہم کردہ اسناد بظاہر متوقع فارمیٹ میں ہیں۔

Issue #7857 حل ہونے تک، کامیاب توثیق اس بات کی **ضمانت نہیں دیتی** کہ provider کامیابی سے تصدیقِ شناخت کر پائے گا۔

اگر تصدیقِ شناخت پھر بھی ناکام ہو، تو یقینی بنائیں کہ آپ نے اسناد کو براؤزر کی کوکی اسٹوریج کے بجائے کسی فعال نیٹ ورک درخواست سے کاپی کیا ہے۔

# خرابیوں کا ازالہ

## تصدیقِ شناخت ناکام ہو جاتی ہے

تصدیق کریں کہ اسناد یہاں سے کاپی کی گئی ہیں:

```
Network
→ Request Headers
→ Cookie
```

اور یہاں سے **نہیں**:

```
Application
→ Cookies
```

---

## کوکی براؤزر میں کام کرتی ہے لیکن OmniRoute میں نہیں

کچھ providers میں ایسی کوکیز شامل ہوتی ہیں جو صرف تصدیق شدہ درخواستوں کے دوران بھیجی جاتی ہیں۔

کسی گفتگو کو کامیابی سے کھولنے کے بعد، ایک تازہ نیٹ ورک درخواست سے اسناد دوبارہ کاپی کریں۔

---

## سیشن کی میعاد ختم ہو گئی

Web Cookie providers آپ کا موجودہ براؤزر سیشن استعمال کرتے ہیں۔

اگر آپ کے براؤزر سیشن کی میعاد ختم ہو جائے یا آپ سائن آؤٹ کر دیں، تو آپ کو اسناد کا نیا مجموعہ کاپی کرنا ہوگا۔ معاونت یافتہ web providers کے لیے کوکی کی تجدید خودکار بنانے کی غرض سے، [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) کے ساتھی ٹول کو دیکھیں۔

## Test Connection کامیاب ہوتا ہے لیکن درخواستیں ناکام ہو جاتی ہیں

Issue #7857 حل ہونے تک، توثیق کا کامیاب ہونا اس بات کی ضمانت نہیں دیتا کہ تصدیقِ شناخت کی درخواست کامیاب ہوگی۔

مزید خرابیوں کا ازالہ کرنے سے پہلے، کسی تازہ تصدیق شدہ درخواست سے اپنی اسناد دوبارہ کاپی کریں۔

## ChatGPT Web میں "Unsupported ChatGPT integrity dependency" کی خرابی

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

اسناد درست ہیں — یہ خرابی سیشن سے نہیں بلکہ bridge سے آتی ہے۔ chatgpt.com ہر deployment کے لیے اپنے
module ids مقرر کرتا ہے، اور bridge اس Sentinel helper کی id کو pin کرتا تھا جسے وہ instantiate کرتا ہے، لہٰذا
chatgpt.com کی ایسی rebuild جس نے helper کا نام تبدیل کر دیا، ہر turn کو ناکام بنا دیتی تھی جبکہ کوکی بدستور درست رہتی تھی۔ کنکشن کو دوبارہ authorize کرنے سے
یہ مسئلہ حل نہیں ہو سکتا۔

وہ builds جو ماڈیول کو صفحے کے اپنے runtime کے ذریعے resolve کرتی ہیں، کسی id کو pin نہیں کرتیں اور اس مسئلے سے متاثر نہیں ہوتیں۔ اگر آپ کو یہ
خرابی نظر آئے، تو OmniRoute کو اپ گریڈ کریں اور کنکشن کی جانچ دوبارہ چلائیں۔

# Provider کی مثال

کسی مخصوص provider کے لیے مکمل مرحلہ وار رہنمائی یہاں دیکھیں:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web گائیڈ Web Cookie provider کے لیے مکمل سیٹ اپ کا طریقہ دکھاتی ہے اور حوالہ جاتی implementation کے طور پر کام کرتی ہے۔

# بہترین طریقۂ کار

- اسناد کو کسی تازہ تصدیق شدہ درخواست سے کاپی کریں۔
- پرانی کوکیز دوبارہ استعمال کرنے سے گریز کریں۔
- Web Cookie providers استعمال کرتے وقت اپنے براؤزر سیشن کو فعال رکھیں۔
- کاپی کی گئی کوکیز کو حساس اسناد تصور کریں۔
- جب آپ کو فنکشن کالنگ یا ایجنٹ ورک فلو درکار ہوں تو API-key providers استعمال کریں۔
