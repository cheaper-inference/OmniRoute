> **حقیقت کا مستند ماخذ:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`)، `src/app/api/plugins/`، اور
> `src/app/(dashboard)/dashboard/plugins/`
> **آخری بار اپ ڈیٹ کیا گیا:** 2026-06-28 — v3.8.40

OmniRoute ایک WordPress طرز کے پلگ اِن سسٹم کے ساتھ آتا ہے۔ پلگ اِن خود کفیل
ڈائریکٹریاں ہیں — ہر ایک میں ایک `plugin.json` مینی فیسٹ اور ایک انٹری فائل ہوتی ہے — جو
درخواست کی پائپ لائن (`onRequest` / `onResponse` / `onError`) اور
لائف سائیکل ایونٹس (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`) سے
منسلک ہوتے ہیں۔

**پلگ اِن مارکیٹ پلیس** اس سسٹم کے اوپر موجود دریافت کی تہہ ہے۔ یہ
انسٹال کیے جا سکنے والے پلگ اِنز کا قابلِ براؤز کیٹلاگ فراہم کرتی ہے۔ بطور ڈیفالٹ یہ کیٹلاگ
ایک مختصر پہلے سے موجود سیڈ رجسٹری ہے؛ آپریٹر اسے حسبِ ضرورت ریموٹ
رجسٹری URL کی طرف بھیج سکتا ہے، ایسی صورت میں fetch کو DNS-resolving SSRF گارڈ
کے ذریعے محفوظ بنایا جاتا ہے
([سیکیورٹی](#security) دیکھیں)۔

ہر پلگ اِن روٹ **صرف loopback کے لیے** ہے (Tier 1 — `LOCAL_ONLY`): پلگ اِنز
child processes میں کوڈ لوڈ اور execute کرتے ہیں، اس لیے auth سے قطع نظر یہ روٹس
کسی non-loopback origin سے قابلِ رسائی نہیں ہوتے۔ دیکھیے
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)۔

## یہ کس طرح Together فٹ بیٹھتا ہے۔

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **رجسٹری پرت** — `src/lib/plugins/marketplace.ts`: کیٹلاگ کی فہرستیں / تلاش کرتا ہے، کسی بھی ناکامی پر بیج رجسٹری میں واپس آتا ہے۔
- **لائف سائیکل پرت** — `src/lib/plugins/manager.ts` (`pluginManager` سنگلٹن): انسٹال کریں، اپ گریڈ کریں، ایکٹیویٹ کریں، غیر فعال کریں، ان انسٹال کریں، اسکین کریں، اسٹارٹ اپ لوڈ کریں۔
- **مینی فیسٹ پرت** — `src/lib/plugins/manifest.ts`: Zod اسکیما + ڈیفالٹس `plugin.json` کے لیے۔
- **سکینر** — `src/lib/plugins/scanner.ts`: پلگ ان ڈائرکٹری کے تحت ڈسک پر پلگ ان دریافت کرتا ہے۔
- **لوڈر** — `src/lib/plugins/loader.ts`: ہر پلگ ان کو ایک علیحدہ Node.js چائلڈ پروسیس میں پھیلاتا ہے اور بروکرز IPC پر کالز ہک کرتے ہیں۔ بچہ سینڈ باکس نہیں ہے (نیچے "پلگ ان ایگزیکیوشن آئسولیشن" دیکھیں)۔

## مارکیٹ پلیس کیٹلاگ

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`)
`MarketplaceEntry` آبجیکٹس کی ایک فہرست لوٹاتا ہے:

| فیلڈ          | قسم      | نوٹس                                       |
| ------------- | -------- | ------------------------------------------ |
| `name`        | string   | kebab-case پلگ اِن نام                     |
| `version`     | string   | semver                                     |
| `description` | string   | مختصر خلاصہ                                |
| `author`      | string   | مصنف / ادارہ                               |
| `license`     | string   | SPDX طرز کا لائسنس id                      |
| `downloadUrl` | string   | ماخذ کا ڈاؤن لوڈ URL (خالی ہو سکتا ہے)     |
| `repository`  | string?  | اختیاری ریپوزٹری URL                       |
| `tags`        | string[] | تلاش/فلٹر کے ٹیگز                          |
| `downloads`   | number   | ڈاؤن لوڈز کی تعداد                         |
| `rating`      | number   | 0–5                                        |
| `verified`    | boolean  | آیا اندراج کو تصدیق شدہ نشان زد کیا گیا ہے |
| `lastUpdated` | string   | ISO طرز کی تاریخ کی اسٹرنگ                 |

جب کوئی حسبِ ضرورت رجسٹری URL ترتیب نہ دیا گیا ہو تو کیٹلاگ بلٹ اِن
`SEED_REGISTRY` ہوتا ہے (فی الحال `request-logger`، `rate-limiter`، `cost-tracker`، اور
`theme-manager`)۔ سیڈ رجسٹری ہمیشہ دستیاب رہتی ہے — اگر ترتیب دی گئی ریموٹ
رجسٹری ناقابلِ رسائی ہو، non-`200` اسٹیٹس لوٹائے، یا ناقابلِ شناخت
body لوٹائے، تو `listMarketplacePlugins()` ایک انتباہ لاگ کرتا ہے اور سیڈ فہرست پر واپس آ جاتا ہے۔

> نوٹ: مارکیٹ پلیس **کیٹلاگ** (براؤز/تلاش) ایک سرے سے دوسرے سرے تک مربوط ہے، لیکن
> کیٹلاگ سے ایک کلک میں مارکیٹ پلیس **انسٹالیشن** ابھی نافذ نہیں کی گئی — کسی مارکیٹ پلیس
> اندراج پر ڈیش بورڈ کا "انسٹال کریں" بٹن فی الحال
> "جلد آ رہا ہے" کا نوٹس دکھاتا ہے۔ آج انسٹالیشن مقامی پاتھ کے انسٹال
> فلو (`POST /api/plugins`) اور ڈسک پر دریافت (`POST /api/plugins/scan`) کے ذریعے ہوتی ہے۔

## REST API

تمام اینڈ پوائنٹس کے لیے انتظامی توثیق کی ضرورت ہوتی ہے (`requireManagementAuth`)** اور** صرف لوپ بیک ہیں — `/api/plugins` اور `/api/plugins/` `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) میں درج ہیں۔

| اختتامی نقطہ                       | طریقہ  | تفصیل                                                        |
| ---------------------------------- | ------ | ------------------------------------------------------------ |
| `/api/plugins`                     | GET    | انسٹال کردہ پلگ ان کی فہرست بنائیں (اختیاری `?status=` فلٹر) |
| `/api/plugins`                     | POST   | پلگ ان سورس ڈائرکٹری سے پلگ ان انسٹال کریں۔                  |
| `/api/plugins/scan`                | POST   | پلگ ان ڈائرکٹری کو اسکین کریں اور نئے پلگ ان رجسٹر کریں۔     |
| `/api/plugins/marketplace`         | GET    | مارکیٹ پلیس کیٹلاگ اندراجات کی فہرست بنائیں                  |
| `/api/plugins/marketplace/install` | POST   | نام سے مارکیٹ پلیس پلگ ان انسٹال کریں۔                       |
| `/api/plugins/[name]`              | GET    | انسٹال شدہ پلگ ان کی تفصیلات حاصل کریں۔                      |
| `/api/plugins/[name]`              | DELETE | ایک پلگ ان ان انسٹال کریں۔                                   |
| `/api/plugins/[name]/activate`     | POST   | چالو کریں ( + رجسٹر ہکس لوڈ کریں)                            |
| `/api/plugins/[name]/deactivate`   | POST   | غیر فعال کریں (فائر `onDeactivate`، غیر رجسٹر ہکس)           |
| `/api/plugins/[name]/config`       | GET    | پلگ ان config + config اسکیما حاصل کریں۔                     |
| `/api/plugins/[name]/config`       | PUT    | پلگ ان کی تشکیل کو اپ ڈیٹ کریں (اسکیما کے خلاف توثیق شدہ)    |

`GET /api/plugins` `status` فلٹر `installed` / `active` / `inactive` / `error` میں سے ایک کو قبول کرتا ہے۔ ایک غلط قدر `400` لوٹاتی ہے۔

### انسٹال کردہ پلگ ان کی فہرست بنائیں

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### مقامی راستے سے انسٹال کریں۔

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` ایک ہونا ضروری ہے۔** مطلق** ڈائریکٹری کا راستہ** پلگ ان سورس ڈائرکٹری کے اندر** : `plugin-sources` پلگ ان روٹ کے آگے، لہذا `~/.omniroute/plugin-sources/` بطور ڈیفالٹ، یا `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` جب وہ متغیر سیٹ ہو (`getPluginSourcesDir()` میں `src/lib/plugins/installSource.ts`)۔ پہلے وہاں پلگ ان کو کاپی یا کلون کریں۔ `400` کے ساتھ انسٹال سے انکار کر دیا جاتا ہے جب پاتھ میں `..` یا null بائٹ ہوتا ہے، اس ڈائرکٹری سے باہر ہوتا ہے، اس کے باہر symlink کے ذریعے حل ہوتا ہے، ایک Symlink پر مشتمل ہوتا ہے جس کا ہدف اس سے باہر ہوتا ہے، یا جب ڈائریکٹری موجود نہیں ہوتی ہے۔ سورس ڈائرکٹری میں ایک درست `plugin.json` ہونا چاہیے (یا ایک کا والدین ہونا)۔ کامیابی پر جواب نصب شدہ پلگ ان قطار کے ساتھ `201` ہے۔

دوسرے پلگ ان روٹس کے برعکس، اس کے لیے انتظامی اسناد (ڈیش بورڈ سیشن یا مینیج اسکوپڈ API کلید) کی ضرورت ہوتی ہے یہاں تک کہ جب لاگ ان غیر فعال ہو (`requireLogin=false`): کوڈ انسٹال کرنا کبھی بھی گمنام عمل نہیں ہوتا ہے۔ یہی بات `POST /api/plugins/marketplace/install` (body `{ "name": "<plugin>" }`) پر بھی لاگو ہوتی ہے۔

### بازار کو براؤز کریں۔

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### پلگ ان کی ترتیب کو اپ ڈیٹ کریں۔

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` پلگ ان کے `configSchema` کے خلاف باڈی کی توثیق کرتا ہے `src/lib/plugins/manifest.ts` سے `validatePluginConfig()` کے ساتھ: ہر کلید کا اعلان اسکیما میں ہونا چاہیے، اقدار کا اعلان کردہ قسم سے مماثل ہونا چاہیے، `number` فیلڈز کا اعزاز `min`/`max`، اور `select` فیلڈز کا اعلان کردہ `enum` سے مماثل ہونا چاہیے۔ کوئی بھی خلاف ورزی `400` واپس کرتی ہے اور کچھ بھی محفوظ نہیں ہوتا ہے۔ ایک پلگ ان جو `configSchema` کا اعلان نہیں کرتا ہے اس میں کوئی قابل ترتیب کلید نہیں ہے، لہذا درخواست کو `400` کے ساتھ مسترد کر دیا جاتا ہے ("پلگ ان کسی قابل ترتیب کلید کا اعلان نہیں کرتا ہے")۔

## Configuration

### Plugin ڈائریکٹری

Plugins، OmniRoute data ڈائریکٹری کے تحت موجود ہوتے ہیں:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (یا وہ فائل جس کی طرف manifest.main اشارہ کرتا ہے)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) اس ڈائریکٹری کو
تین مراحل میں resolve کرتا ہے:

1. **`OMNIROUTE_PLUGINS_DIR`**، جب سیٹ ہو — `HOME` کی قدر سے قطع نظر، اسے من و عن استعمال کیا جاتا ہے۔ یہ
   Docker/K8s کے لیے واضح knob ہے، جہاں plugin tree کسی ایسے path پر bind-mounted ہوتا ہے
   جس کا عموماً container کی home ڈائریکٹری سے کوئی تعلق نہیں ہوتا (#11827)۔
2. `<home>/.omniroute/plugins`، جہاں `<home>` کی قدر `HOME` / `USERPROFILE`
   environment variables سے حاصل ہوتی ہے۔
3. `/tmp/.omniroute/plugins`، جب process کسی home کو export نہ کرے۔

resolve شدہ ڈائریکٹری startup پر ایک بار `scanner.dir_resolved` کے طور پر log کی جاتی ہے،
اور اس input کا نام بھی دیا جاتا ہے جو منتخب ہوا (`OMNIROUTE_PLUGINS_DIR`، `home`، یا
`no-home-fallback`) — تاکہ step 3 پر خاموشی سے پہنچنے والی image محض خالی plugin list
رپورٹ کرنے کے بجائے اس کی وضاحت بھی کرے۔ `POST /api/plugins/scan` وہاں موجود ہر ایسی
subdirectory کو دریافت اور رجسٹر کرتا ہے جس میں درست `plugin.json` ہو؛ یہی ڈائریکٹری وہ
root بھی ہے جس میں `pluginManager.install()` plugins کو copy کرتا ہے، اس لیے override
سے discovery اور installation دونوں ایک ساتھ منتقل ہوتے ہیں۔

> **`OMNIROUTE_PLUGINS_DIR`، `OMNIROUTE_PLUGIN_PATH` نہیں ہے۔** مؤخر الذکر کو صرف
> CLI command-plugin loader (`bin/cli/plugins.mjs`) پڑھتا ہے تاکہ ایسے `omniroute-cmd-*` npm
> packages تلاش کیے جا سکیں جو `omniroute` subcommands شامل کرتے ہیں — اس کا یہاں بیان کردہ
> runtime scanner پر کوئی اثر نہیں ہوتا۔ اس پہلو کے لیے [PLUGINS.md](./PLUGINS.md) دیکھیں۔

### حسبِ ضرورت marketplace registry URL

marketplace catalog کا source، `pluginMarketplaceUrl` setting سے پڑھا جاتا ہے
(`src/lib/plugins/marketplace.ts`، `settings.pluginMarketplaceUrl` کو پڑھتا ہے)۔ جب
اسے کسی `http(s)` URL پر سیٹ کیا جائے تو `listMarketplacePlugins()` اس URL کو fetch کرتا
ہے اور entries کی top-level JSON array یا `plugins` array رکھنے والا object قبول کرتا
ہے؛ جن entries میں string `name` موجود نہ ہو انہیں filter کر دیا جاتا ہے۔ جب یہ سیٹ نہ
ہو (یا جب fetch، SSRF guard میں ناکام ہو / خراب response واپس کرے)، تو built-in seed
registry استعمال کی جاتی ہے۔

dashboard کا "Marketplace" tab اس URL کے لیے ایک field فراہم کرتا ہے (جسے
`GET /api/settings` سے دوبارہ پڑھا جاتا ہے)۔

> نفاذ سے متعلق نوٹ: dashboard کا "Save" action،
> `pluginMarketplaceUrl` کو `PATCH /api/settings` پر بھیجتا ہے۔ تحریر کے وقت یہ
> key، `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) میں اعلان شدہ نہیں ہے، اس لیے اس پر
> انحصار کرنے سے پہلے اپنی release میں persistence کی تصدیق کریں — **read** path
> (`getSettings()` → `listMarketplacePlugins()`) settings store میں key موجود ہونے
> کے بعد اسے استعمال کرتا ہے۔

## سیکورٹی

### روٹ ٹائر — لوپ بیک صرف

پلگ ان بچوں کے پیدا کردہ عمل میں کوڈ پر عمل درآمد کرتے ہیں، لہذا پوری `/api/plugins` سطح کو `LOCAL_ONLY` (ٹائر 1) کی درجہ بندی کیا جاتا ہے۔ لوپ بیک نفاذ غیر مشروط طور پر چلتا ہے۔** پہلے** کسی بھی تصدیق کی جانچ پڑتال، لہذا سرنگ کے اوپر باکس تک پہنچنے والا ایک لیک شدہ مینجمنٹ ٹوکن پھر بھی پلگ ان کو انسٹال، چالو یا ان انسٹال نہیں کر سکتا۔ دیکھیں [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) اور سخت اصول #15 / #17۔

### مارکیٹ پلیس رجسٹری SSRF گارڈ

ایک حسب ضرورت رجسٹری URL حملہ آور سے متاثر کن کنفیگریشن ہے، لہذا اسے لانے سے پہلے `listMarketplacePlugins()` اسے دو پرتوں سے چلاتا ہے:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - کسی بھی چیز کو رد کرتا ہے جو `http:` / `https:` نہیں ہے۔
   - لفظی private/loopback/link-local/ULA میزبانوں کو مسترد کرتا ہے (IPv4** اور** IPv6، بشمول IPv4-mapped) کیننیکل `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) کے ذریعے۔
   - حل کرتا ہے۔** دونوں** `A` اور `AAAA` ریکارڈ کرتا ہے اور اگر مسترد کرتا ہے۔** کوئی بھی** حل شدہ پتہ نجی — ہے عوامی میزبان نام → نجی-IP بائی پاس کو بند کر رہا ہے۔
   - **فیل بند** : ایک DNS قرارداد کی ناکامی URL کو مسترد کرتی ہے۔
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): لانے کے وقت اور صرف عوامی URL گارڈ کو دوبارہ لاگو کرتا ہے۔** بلاکس ری ڈائریکٹ** (کوئی عوامی → نجی `30x` محور نہیں)۔

ایک URL جو کسی بھی پرت میں ناکام ہوجاتا ہے وہ درخواست کو منسوخ نہیں کرتا ہے — مارکیٹ پلیس خاموشی سے بلٹ ان سیڈ رجسٹری پر واپس آجاتی ہے اور ایک انتباہ لاگ ان کرتا ہے۔

> اس گارڈ کو PR #3774 میں خاص طور پر A + AAAA حل کرنے اور IPv4-only چیک کے بجائے کینونیکل `isPrivateHost` استعمال کرنے کے لیے سخت کیا گیا تھا۔

### پلگ ان پر عمل درآمد تنہائی

> **پلگ انز بطور ڈیفالٹ سینڈ باکس نہیں ہوتے ہیں۔** بچہ ایک عام Node.js عمل ہے جو OmniRoute صارف کے طور پر چل رہا ہے، جس میں VM سیاق و سباق اور Node.js اجازت کے جھنڈے نہیں ہیں، لہذا پلگ ان کوڈ کسی بھی فائل کو پڑھ اور لکھ سکتا ہے جو صارف کر سکتا ہے، پروگرام چلا سکتا ہے اور نیٹ ورک تک پہنچ سکتا ہے۔ `requires.permissions` صرف فیصلہ کرتا ہے کہ بچے کو کون سے ماحول کے متغیرات حاصل ہوں گے۔ دوسری اجازتیں نافذ نہیں ہیں۔ آپٹ ان `PLUGIN_PERMISSION_MODEL_ENABLED` فیچر فلیگ (بطور ڈیفالٹ آف) ہر پلگ ان کو ان اجازتوں سے بنائے گئے Node.js پرمشن ماڈل کے تحت چلاتا ہے، سوائے `network`، جس پر Node.js پابندی نہیں لگا سکتا (دیکھیں [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#%D8%A7%D8%AC%D8%A7%D8%B2%D8%AA-%DA%A9%D8%A7-%D9%86%D8%B8%D8%A7%D9%85) )۔ صرف پلگ ان انسٹال کریں جن پر آپ بھروسہ کریں۔ عمل کی باؤنڈری ذیل میں کریش اور ہینگ پر مشتمل ہے۔ یہ سیکورٹی کی حد نہیں ہے۔

- **عمل تنہائی** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ہر پلگ ان کو ایک علیحدہ Node.js چائلڈ پروسیس میں پھیلاتا ہے اور IPC پر بات چیت کرتا ہے۔ ہک کالز کا ٹائم آؤٹ `SIGTERM` → `SIGKILL` اضافہ کے ساتھ ہوتا ہے۔
- **Env کی اجازت کی فہرست** — بچے کو ماحولیاتی متغیرات کا صرف ایک اجازت یافتہ سیٹ ملتا ہے۔ وسیع تر سیٹ صرف اس وقت دیا جاتا ہے جب مینی فیسٹ `env` کی اجازت کی درخواست کرتا ہے۔
- **سورس کنٹینمنٹ انسٹال کریں۔** — `POST /api/plugins` صرف پلگ ان سورس ڈائرکٹری سے پڑھتا ہے (دیکھیں "مقامی راستے سے انسٹال کریں"): راستہ `realpath` کے ساتھ کینونیکلائز کیا جاتا ہے، اس ڈائرکٹری کے اندر سختی سے رہنا چاہیے، اور ایک سورس ٹری جس میں ایک سملنک ہوتا ہے جو اس سے بچ جاتا ہے اسے کسی بھی چیز کی کاپی کرنے سے پہلے انکار کر دیا جاتا ہے۔
- **راستے پر قابو پانا** — install/upgrade/uninstall زور دیتے ہیں کہ پلگ ان ڈائرکٹری اور `manifest.main` حل کرتے ہیں۔** کے اندر** کسی بھی کاپی یا تکراری حذف کرنے سے پہلے منظم پلگ ان کی جڑ ( `manifest.main` میں چھیڑ چھاڑ DB راستوں اور `../` traversal کے خلاف محافظ)۔ ایکٹیویشن symlinks کو `realpath` کے ذریعے حل کرتی ہے اور ایک انٹری پوائنٹ لوڈ کرنے سے انکار کرتی ہے جو پلگ ان ڈائرکٹری سے بچ جاتا ہے۔
- **اختیاری سالمیت پن** — ایک مینی فیسٹ `integrity` (`sha256-<base64>`، SRI فارمیٹ) فیلڈ کا اعلان کر سکتا ہے۔ موجود ہونے پر، لوڈر لوڈ کے وقت انٹری فائل ہیش کی تصدیق کرتا ہے اور مماثلت نہ ہونے پر چالو کرنے سے انکار کرتا ہے۔ یہ چھیڑ چھاڑ کا آپٹ ان ہے،** نہیں** ایک حفاظتی حد: یہ اس بات کو محدود نہیں کرتا کہ بھری ہوئی پلگ ان کیا کر سکتی ہے۔
- **ہکس میں کلائنٹ کی کوئی اسناد نہیں ہیں۔** — سیاق و سباق `onRequest`، `onResponse` اور `onError` کو دیا گیا ہے اس سے `authorization`، `x-api-key`، `proxy-authorization` اور `cookie` ہیڈرز کو ہٹا دیا گیا ہے، اور API کلیدی ریکارڈ میں کوئی کلیدی قدر نہیں ہے (`redactPluginContext()` in `src/lib/plugins/hooks.ts`)۔

## لائف سائیکل کا بہاؤ

```
install (POST /api/plugins، path)
  → manifest کو اسکین/توثیق کریں → staging میں کاپی کریں → یقینی بنائیں کہ main ڈائریکٹری کے اندر ہے
  → اٹامک rename کے ذریعے ~/.omniroute/plugins/<name> میں منتقل کریں → DB میں قطار داخل کریں
  → onInstall چلائیں → اگر enabledByDefault ہو: activate کریں

activate (POST /api/plugins/{name}/activate)
  → realpath containment کی جانچ → loadPlugin() (child process شروع کریں)
  → اعلان کردہ hooks رجسٹر کریں → status = "active" → onActivate چلائیں

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate چلائیں (unregister کرنے سے پہلے) → hooks کو unregister کریں
  → child process ختم کریں → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → اگر active ہو تو deactivate کریں → onUninstall چلائیں
  → containment کی جانچ کے ساتھ plugin ڈائریکٹری کو بار بار حذف کریں → DB کی قطار حذف کریں
```

کسی ایسی ڈائریکٹری پر `install` دوبارہ چلانے سے، جس کے manifest کا version نصب شدہ version سے **سختی سے
نیا** ہو، خودکار طور پر اپ گریڈ ہو جاتا ہے (صاف از سرِ نو تنصیب؛ config دوبارہ
ڈیفالٹ اقدار پر سیٹ ہو جاتی ہے)۔ یکساں یا پرانا version مسترد کر دیا جاتا ہے۔

## ڈیش بورڈ

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) پر ڈیش بورڈ صفحہ دو ٹیبز فراہم کرتا ہے:

- **انسٹال** — ان کے اعلان کردہ ہکس، ایک activate/deactivate ٹوگل، ایک ان انسٹال بٹن، اور "پلگ ان کے لیے اسکین" ایکشن (`POST /api/plugins/scan`) کے ساتھ انسٹال کردہ پلگ انز کی فہرست بناتا ہے۔
- **بازار** — اپنی مرضی کی رجسٹری URL کو سیٹ کرنے کے لیے `GET /api/plugins/marketplace` سے کیٹلاگ کو فیلڈ کے ساتھ دکھاتا ہے۔

صفحہ ہمیشہ ایک انتباہ دکھاتا ہے کہ پلگ انز OmniRoute عمل کے مکمل مراعات کے ساتھ چلتے ہیں۔

فی پلگ ان تشکیل صفحہ `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) پر رہتا ہے۔
