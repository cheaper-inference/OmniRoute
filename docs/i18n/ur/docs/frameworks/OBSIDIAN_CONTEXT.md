> `src/app/api/settings/obsidian/webdav/route.ts` (ترتیباتی APIs)۔ ٹول رجسٹریشن
> اور اسکوپ وائرنگ `open-sse/mcp-server/server.ts` میں موجود ہے۔

## یہ کیا ہے

OmniRoute ایک **Obsidian** والٹ سے بطور **سیاقی ماخذ** منسلک ہوتا ہے — ایک مقامی Markdown
نالج بیس جسے ایجنٹس بلٹ اِن MCP سرور کے ذریعے پڑھتے اور اس میں لکھتے ہیں۔ یہ
انٹیگریشن ڈیسک ٹاپ ایپ کے اندر چلنے والے کمیونٹی پلگ اِن **Obsidian Local REST API**
سے رابطہ کرتا ہے، تاکہ ایجنٹس نوٹس تلاش کر سکیں، فائلیں پڑھ/لکھ/پیچ کر سکیں، والٹ کی
فہرست دیکھ سکیں، روزانہ/ہفتہ وار دوریاتی نوٹس کے ساتھ کام کر سکیں، ٹیگز منظم کر سکیں،
Obsidian کمانڈز چلا سکیں، اور (اختیاری طور پر) دو طرفہ ڈیسک ٹاپ↔موبائل والٹ سنک کو
مربوط کر سکیں۔

کلائنٹ (`src/lib/obsidian/api.ts`) Local REST API کو درج ذیل خصوصیات کے ساتھ ریپ کرتا ہے:

- عارضی `5xx` خرابیوں کے لیے **بیک آف کے ساتھ دوبارہ کوشش**، اور `AbortController` کے ذریعے **30 سیکنڈ کا ٹائم آؤٹ**۔
- **ٹائپ شدہ خرابیوں کی درجہ بندی** — `ObsidianAuthError` (401/403)،
  `ObsidianNotFoundError` (404)، `ObsidianServerError` (5xx)، `ObsidianTimeoutError`۔
- ایک **آسان فہم "Obsidian تک رسائی ممکن نہیں" اشارہ** جو پورٹ کی عام غلطی
  (HTTP کے لیے `27123`، `27124` پر موجود MCP اینڈ پوائنٹ **نہیں**) اور Tailscale فارمیٹ کی وضاحت کرتا ہے۔
- والٹ سے متعلق **پاتھ انکوڈنگ** تاکہ اسپیسز/سلیشز والے نوٹ پاتھ محفوظ رہیں۔

## سیٹ اپ

Obsidian ٹوکن یا بنیادی URL کے لیے **کوئی environment variable موجود نہیں ہے** — دونوں
`src/lib/db/obsidian.ts` کے ذریعے SQLite کی `key_value` ٹیبل (namespace `obsidian`) میں
محفوظ کیے جاتے ہیں۔ ٹوکن کو **محفوظ حالت میں خفیہ کیا جاتا ہے** (AES-256-GCM، نیز
سادہ متن کے ساتھ پسماندہ مطابقت کا fallback)۔ Endpoint ڈیش بورڈ کے **Context Sources** ٹیب
(`ObsidianSourceCard`) سے، یا ترتیبات کی REST API کے ذریعے تشکیل کریں۔

> [!IMPORTANT]
> **Obsidian Local REST API** پلگ اِن کا انسٹال اور فعال ہونا ضروری ہے۔ اس کا REST
> انٹرفیس **HTTP `127.0.0.1:27123`** (ڈیفالٹ بنیادی URL) پر سنتا ہے۔ پورٹ `27124`
> ایک _علیحدہ_ MCP/HTTPS endpoint ہے اور ترتیبات کا route اسے واضح طور پر مسترد کرتا ہے۔
> کسی دوسرے آلے سے منسلک ہوتے وقت `http://<tailscale-ip>:27123` استعمال کریں۔

### کنفیگریشن کلیدیں (SQLite `key_value`، namespace `obsidian`)

| کلید              | مقصد                                              | خفیہ کردہ |
| ----------------- | ------------------------------------------------- | --------- |
| `api_key`         | Local REST API کا bearer ٹوکن                     | ہاں       |
| `base_url`        | REST بنیادی URL (ڈیفالٹ `http://127.0.0.1:27123`) | نہیں      |
| `vault_path`      | vault ڈائریکٹری کا مطلق path (sync کے لیے)        | نہیں      |
| `webdav_username` | تیار کردہ WebDAV صارف نام (vault sync)            | نہیں      |
| `webdav_password` | تیار کردہ WebDAV پاس ورڈ (vault sync)             | ہاں       |
| `webdav_enabled`  | آیا WebDAV vault sync فعال ہے                     | نہیں      |

### REST کے ذریعے تشکیل کریں

```bash
# Local REST API ٹوکن محفوظ + توثیق کریں (POST اسٹیٹس چیک کے ذریعے توثیق کرتا ہے)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# کنکشن اسٹیٹس چیک کریں (connected، hasToken، baseUrl، vaultPath واپس کرتا ہے)
curl http://localhost:20128/api/settings/obsidian

# منقطع کریں (محفوظ شدہ ٹوکن صاف کرتا ہے)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

تمام طریقوں کے لیے ڈیش بورڈ کی تصدیق درکار ہے۔ `POST` پورٹ `27124` پر موجود کسی بھی URL
کو مسترد کرتا ہے اور محفوظ کرنے سے پہلے Local REST API کے اسٹیٹس endpoint کو کال کر کے ٹوکن کی توثیق کرتا ہے۔

### WebDAV vault sync

`src/app/api/settings/obsidian/webdav/route.ts` ایک اختیاری WebDAV کی پشت پناہی والا
vault sync منظم کرتا ہے (جسے `src/lib/obsidianSync.ts` چلاتا ہے)۔ اسے فعال کرنے پر OmniRoute
کو ایک مقامی vault ڈائریکٹری کی طرف متوجہ کیا جاتا ہے اور ایک بے ترتیب WebDAV صارف نام/پاس ورڈ جوڑا تیار کیا جاتا ہے:

```bash
# کسی vault ڈائریکٹری کے لیے WebDAV sync فعال کریں (صارف نام/پاس ورڈ تیار کرتا ہے)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV sync اسٹیٹس حاصل کریں (اسناد صرف فعال ہونے کی صورت میں واپس آتی ہیں)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV sync غیر فعال کریں (اسناد + منظم کردہ .stignore صاف کرتا ہے)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### سیکیورٹی اور ٹرانسپورٹ

WebDAV کی توثیق فی IP ناکامی سے باخبر رہنے اور لاک آؤٹ کو نافذ کرتی ہے (60 سیکنڈ کی ونڈو میں 10 ناکام کوششیں `429 Too Many Requests` اور `Retry-After` کے ساتھ 5 منٹ کے لاک آؤٹ کو متحرک کرتی ہیں)۔ چونکہ WebDAV بنیادی تصدیقی اسناد کو منتقل کرتا ہے، اس لیے لوپ بیک سے باہر WebDAV اینڈ پوائنٹ تک رسائی حاصل کرتے وقت TLS (یا محفوظ سرنگ جیسے Tailscale یا Cloudflare Tunnel پر روٹنگ) کو ختم کرنے کی سختی سے سفارش کی جاتی ہے۔

### فی API کلید context source (اختیاری)

Obsidian کنفیگریشن کو `api_key_context_sources` ٹیبل
(`src/lib/db/apiKeyContextSources.ts`) کے ذریعے **فی API کلید** محدود کیا جا سکتا ہے۔
جب کوئی MCP کال ایک تصدیق شدہ API کلید id کے ساتھ آتی ہے تو `getObsidianConfigForApiKey()`
اس کلید کے اپنے ٹوکن/بنیادی URL/vault path (`source: "api_key"`) کو ترجیح دیتا ہے، اور
بصورت دیگر عالمی کنفیگریشن (`source: "global"`) پر fallback کرتا ہے۔

غیر sync MCP ٹولز کو یہ کنفیگریشن پڑھنے سے پہلے کال کنندہ کی شناخت کا تعین درکار ہوتا ہے۔
بغیر شناخت کے کال کنندہ کو `Obsidian API token not configured` موصول ہوتا ہے، اور کوئی vault
درخواست نہیں بھیجی جاتی۔ HTTP کال کنندگان کی شناخت ان کی درخواست کی اسناد کے ذریعے کی جاتی ہے؛ stdio کال کنندگان
`OMNIROUTE_API_KEY` یا `ROUTER_API_KEY` کے ذریعے شناخت حاصل کر سکتے ہیں۔ ایسا HTTP کال کنندہ
جس کی شناخت کا تعین نہ ہو سکے، سرور کی environment شناخت کا وارث نہیں بن سکتا۔ صرف placeholder IDs
رسائی کی اجازت نہیں دیتیں؛ ایک درست environment سند جو `env-key` سے resolve ہوتی ہو، بدستور معاونت یافتہ ہے۔
ایسی تصدیق شدہ کلیدیں جن کے لیے فی کلید Obsidian کنفیگریشن موجود نہ ہو، عالمی fallback برقرار رکھتی ہیں۔
چاروں `obsidian_sync_*` ٹولز اپنا علیحدہ sync-token رویہ برقرار رکھتے ہیں۔

## MCP ٹولز (22)

`open-sse/mcp-server/tools/obsidianTools.ts` میں بیان کیا گیا ہے۔ token/base-URL فی کال حل کیے جاتے ہیں (فی-API-key پہلے، پھر عالمی)۔ ٹولز جو OmniRoute کو مارتے ہیں۔** مطابقت پذیری سرور** (چار `obsidian_sync_*` ٹولز) اضافی طور پر OmniRoute سیٹنگز میں کنفیگر کردہ Sync auth ٹوکن کی ضرورت ہوتی ہے۔

### پڑھنے کے اوزار (`read:obsidian`)

| ٹول                          | تفصیل                                                                                           |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | چیک کریں کہ آیا مقامی REST API قابل رسائی اور تصدیق شدہ ہے۔                                     |
| `obsidian_search_simple`     | نوٹ کے مواد کی مکمل متن کی تلاش؛ فائل پاتھ کے ساتھ ٹکڑوں کو واپس کرتا ہے۔                       |
| `obsidian_search_structured` | JSON لاجک ایکسپریشن (and/or/regex/path فلٹرز) کا استعمال کرتے ہوئے تلاش کریں۔                   |
| `obsidian_read_note`         | والٹ رشتہ دار راستے کے ذریعے ایک نوٹ پڑھیں؛ اختیاری طور پر ایک مخصوص heading/block/frontmatter. |
| `obsidian_list_vault`        | والٹ میں فائلوں اور ڈائریکٹریوں کی فہرست بنائیں (اندراجات کا درخت)۔                             |
| `obsidian_get_document_map`  | → لائن نمبرز کے عنوانات کے نقشے کے طور پر نوٹ کی سرخی کا ڈھانچہ حاصل کریں۔                      |
| `obsidian_get_note_metadata` | مکمل مواد کے بغیر فرنٹ میٹر، ٹیگز، لنکس، char/word شمار حاصل کریں۔                              |
| `obsidian_get_active_file`   | Obsidian میں فی الحال فعال فائل کا پاتھ + مواد حاصل کریں۔                                       |
| `obsidian_get_periodic_note` | تاریخ کے لیے daily/weekly/monthly متواتر نوٹ حاصل کریں (آج اگر چھوڑ دیا جائے)۔                  |
| `obsidian_get_tags`          | تمام والٹ ٹیگز کو ان کی تعدد کے ساتھ درج کریں۔                                                  |
| `obsidian_list_commands`     | دستیاب Obsidian کمانڈ IDs کی فہرست بنائیں ( `obsidian_execute_command` کے ساتھ استعمال کریں)۔   |
| `obsidian_sync_status`       | OmniRoute مطابقت پذیری سرور کی حیثیت: چل رہا ہے، والٹ کا نام، پورٹ، اپ ٹائم، آخری مطابقت پذیری. |
| `obsidian_sync_conflicts`    | غیر حل شدہ مطابقت پذیری کے تنازعات کی فہرست بنائیں (راستہ، تنازعہ کا راستہ، پتہ چلا ہوا)۔       |

| `obsidian_sync_resolve_conflict` | مطابقت پذیری کا تنازعہ حل کریں: `local` (موبائل)، `remote` (ڈیسک ٹاپ) یا `keep-both` رکھیں۔ |

> [!NOTE]
> `obsidian_patch_note` اہداف `heading | block | frontmatter` کے `targetType` اور `append | prepend | replace` کے `operation` اختیاری `createTargetIfMissing` کے ساتھ قبول کرتے ہیں۔ چار `obsidian_sync_*` ٹولز مقامی مطابقت پذیری سرور سے بات کرتے ہیں (`http://127.0.0.1:27781` بذریعہ ڈیفالٹ) اور مطابقت پذیری ٹوکن کی ضرورت ہوتی ہے۔

### دائرہ کار

پڑھنے والے ٹولز کے لیے `read:obsidian` ضرورت ہوتی ہے۔ تحریری ٹولز کو `write:obsidian` کی ضرورت ہوتی ہے۔ نفاذ `open-sse/mcp-server/server.ts` میں `withScopeEnforcement()` کے ذریعے ہینڈل کردہ Notion — کی طرح ہے، `OMNIROUTE_MCP_ENFORCE_SCOPES=true` پر گیٹ کیا جاتا ہے اور HTTP/SSE کال کرنے والوں کے لیے مجبور کیا جاتا ہے جن کی API کلید میں `manage`/`admin` کی کمی ہے، `OMNIROUTE_MCP_SCOPES` یا API کلید کے دائرہ کار کے سیاق و سباق سے حاصل کردہ اسکوپس کے ساتھ۔ [MCP-SERVER.md](./MCP-SERVER.md) دیکھیں۔

## اینڈ پوائنٹس

| طریقہ    | راستہ                           | مقصد                                                             |
| -------- | ------------------------------- | ---------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | `{ connected, hasToken, baseUrl, vaultPath }` واپس کرتا ہے۔      |
| `POST`   | `/api/settings/obsidian`        | ٹوکن محفوظ اور توثیق کرتا ہے (پورٹ `27124` مسترد کر دی جاتی ہے)۔ |
| `DELETE` | `/api/settings/obsidian`        | منقطع کرتا ہے (محفوظ شدہ ٹوکن صاف کرتا ہے)۔                      |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV سنک کی حالت اور اسناد (فعال ہونے کے دوران)۔               |
| `POST`   | `/api/settings/obsidian/webdav` | والٹ ڈائریکٹری کے لیے WebDAV سنک فعال کرتا ہے۔                   |
| `DELETE` | `/api/settings/obsidian/webdav` | WebDAV سنک غیر فعال کرتا ہے۔                                     |

> یہ ڈیش بورڈ کی ترتیبات کے روٹس ہیں۔ خود والٹ تک Obsidian
> Local REST API (ترتیب شدہ `base_url`) اور اوپر دیے گئے MCP ٹولز کے ذریعے رسائی حاصل کی جاتی ہے —
> کوئی عوامی `/v1` Obsidian پراکسی اینڈ پوائنٹ موجود نہیں ہے۔

## استعمال کے منظرنامے

- **والٹ پر مبنی جوابات** — `obsidian_search_simple` / `obsidian_search_structured`
  اور پھر `obsidian_read_note`، تاکہ ایجنٹ آپ کے حقیقی نوٹس کی بنیاد پر جواب دے۔
- **نوٹ لکھنا / روزنامچہ نویسی** — ایجنٹ کی آؤٹ پٹ، خلاصے، یا روزانہ کے نوٹس
  (`obsidian_get_periodic_note`) والٹ میں درج کرنے کے لیے `obsidian_write_note`، `obsidian_append_note`، یا
  مخصوص تبدیلیوں کے لیے `obsidian_patch_note`۔
- **والٹ میں نیویگیشن** — پڑھنے/لکھنے سے پہلے ساخت دریافت کرنے کے لیے `obsidian_list_vault`، `obsidian_get_document_map`، اور
  `obsidian_get_tags`۔
- **Obsidian آٹومیشن** — ایجنٹ کے ذریعے پلگ انز/کمانڈز چلانے کے لیے `obsidian_list_commands` + `obsidian_execute_command`؛
  UI میں نوٹ دکھانے کے لیے `obsidian_open_file`۔
- **موبائل سنک** — WebDAV سنک فعال کریں، پھر ڈیسک ٹاپ↔موبائل ہم وقت سازی اور تنازعات حل کرنے کے لیے `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  استعمال کریں۔
