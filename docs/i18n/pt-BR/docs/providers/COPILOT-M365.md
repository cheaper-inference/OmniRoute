`copilot-m365-web` (também conhecido como `m365copilot`) envia solicitações de bate-papo no formato OpenAI por meio de uma sessão Microsoft 365 Copilot autenticada em `m365.cloud.microsoft/chat`. Esta é uma integração nativa não oficial: nenhum processo de proxy separado ou upstream de localhost é necessário. O provedor ID, o alias e as conexões importadas existentes permanecem inalterados. `copilot-web` é um provedor diferente para o serviço ao consumidor em `copilot.microsoft.com`.

> **Novo nos provedores de cookies da Web?**
>
> Ler**`docs/getting-started/WEB-COOKIE-GUIDE.md`** para obter informações sobre o processo de configuração geral, orientações sobre autenticação, limitações e solução de problemas antes de seguir este guia específico do provedor.
>
> **Para importações legadas:** A credencial para este provedor é** não é um biscoito** . Não copie cookies de `m365.cloud.microsoft`. A credencial é um parâmetro de consulta WebSocket URL e um segmento de caminho, ambos lidos na guia Rede DevTools.

## Pré-requisitos

- Uma conta Microsoft 365 com acesso ao Copilot no `m365.cloud.microsoft/chat`
- Um navegador baseado em Chromium (Chrome, Edge) para inspeção DevTools WebSocket
- Acesso ao modelo solicitado nessa conta; a disponibilidade varia de acordo com o inquilino e a licença

## Login nativo (contas corporativas ou escolares)

Escolher**Microsoft 365 Copilot → Conectar** e prepare uma tentativa de login. O painel usa um fluxo de código de autorização com PKCE; ele não solicita sua senha Microsoft ou código MFA.

1. Abra um** guia do navegador em branco** , em seguida, abra**DevTools →** e habilitar** Preservar registro** . Faça isso antes de navegar para Microsoft: Windows SSO pode terminar imediatamente.
2. Copie o URL de autorização mostrado na caixa de diálogo de conexão e navegue até ele na guia preparada. Conclua a seleção da conta de Microsoft ou MFA se solicitado.
3. No log de rede preservado, encontre a solicitação para `https://login.microsoftonline.com/common/oauth2/nativeclient` e copie seu conteúdo completo** Solicitar URL** .
4. Cole esse URL na caixa de diálogo de conexão e conecte-se. Não cole um código bruto ou a barra de endereço `wrongplace` final URL: o retorno de chamada necessário é uma navegação transitória.

Cada tentativa expira após dez minutos e só pode ser usada uma vez. O servidor verifica seu estado, verificador PKCE e alvo de reautenticação antes de trocar o código. Após expiração ou falha na troca, inicie uma nova tentativa. Uma tentativa não pode sobreviver a uma reinicialização do servidor.

Os tokens usam o armazenamento de credenciais de conexão existente e o caminho de atualização. A reautenticação de uma conexão requer a mesma identidade Microsoft tenant/object, e não apenas o mesmo e-mail. Ele preserva o operador naming/settings e substitui credenciais importadas obsoletas. O login nativo é para contas work/school ; o caminho de importação herdado permanece disponível para conexões existentes e configurações de camada suportadas.

O retorno de chamada completo URL é uma credencial única. Nunca inclua isso em capturas de tela, logs, mensagens de suporte ou commits. Esse fluxo não abre um navegador no servidor, não inspeciona o histórico do navegador nem inicia um servidor de retorno de chamada local.

## Captura de credenciais (método WebSocket )

1. Faça login no `https://m365.cloud.microsoft/chat` e inicie uma conversa.
2. Abrir**DevTools →** .
3. Filtrar por**WS** (WebSocket).
4. Clique na conexão Chathub WebSocket. Procure um URL começando com `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Do seu** Solicitar URL** , copie:
   - O valor do parâmetro de consulta `access_token` (um JWT de curta duração).
   - O segmento do caminho do Chathub após `/Chathub/` (por exemplo, `<oid>@<tenant>`).

O URL completo tem a forma:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Em OmniRoute, selecione**Microsoft 365 Copilot** , escolha a opção herdada API-key/import e cole a credencial no formato:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Clique** Conexão de teste** e** Salvar** .

## Captura de credenciais (importação HAR )

Em vez de copiar manualmente os valores do WebSocket URL, você pode exportar um arquivo DevTools HAR :

1. Abrir**DevTools →** .
2. Inicie ou continue uma conversa Microsoft 365 Copilot (isso aciona a conexão WebSocket ).
3. Clique com o botão direito no painel Rede e selecione** Salve tudo como HAR com conteúdo** .
4. Em OmniRoute, use o** Importar arquivo .har** botão na caixa de diálogo de conexão do provedor.

OmniRoute verifica o HAR em busca do Chathub WebSocket URL, extrai `access_token` e `chathubPath` e preenche os campos de credenciais automaticamente. A importação HAR decodifica a expiração JWT e mostra o tempo de vida restante do token.

> **Nunca confirme uma exportação HAR, token de acesso ou token de atualização real.** Os valores de teste e documentação devem sempre ser espaços reservados.

## Vida útil e atualização do token

O `access_token` tem vida curta (normalmente**~ 75 minutos** ). Sem um token de atualização utilizável, você deverá capturar novamente a credencial após expirar.

### Atualização automática com `refreshToken`

No provedor Microsoft 365** Adicionar conexão** ou** Editar conexão** diálogo, aberto** Configurações avançadas token de atualização → (opcional)** . Cole um token de atualização Microsoft OAuth para o escopo `substrate.office.com/sydney` e salve. A entrada é mascarada e nunca preenchida com o token armazenado. Ao editar deixe em branco para manter o token existente; cole um novo token para substituí-lo.

O login nativo adquire o token de atualização quando Microsoft retorna um. Para importações legadas, use uma concessão de código de autorização Microsoft compatível existente; este provedor não implementa nem promete um fluxo de código de dispositivo. Com um token de atualização configurado, OmniRoute verifica o `access_token` antes das solicitações e o atualiza somente quando precisa ser atualizado. Uma atualização bem-sucedida também persiste no token de atualização rotacionado, evitando a recaptura manual enquanto o token de atualização permanece válido.

Se `refreshToken` não estiver configurado, você deverá capturar novamente a credencial WebSocket manualmente após cada expiração.

## Modelos e roteamento

O catálogo nativo inclui todos IDs autônomos documentados mais os quatro IDs nativos originais. O catálogo é estático e independente de conta, não é uma investigação de direitos de conta: rotas pagas e aliases de compatibilidade permanecem listados mesmo quando uma conta conectada não pode usá-los. Os rótulos de exibição do modelo omitem o nome do fornecedor e o padrão de disponibilidade por modelo; o provedor permanece**Microsoft 365 Copilot** . Etiquetas marcadas** Alias** ou** Legado** retêm seus identificadores e mapeamentos de protocolo existentes, não uma garantia de uma versão histórica do modelo. O proxy autônomo** Importar de /modelos** as instruções não se aplicam a este provedor WebSocket nativo.

| GPT anterior      | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |

Aliases como `auto`, `quick`, `think-deeper` e aliases de versão também são registrados. Os `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` e `copilot-m365-gpt-5-5-chat` existentes permanecem válidos. O IDs documentado precisa do prefixo do provedor (`copilot-m365-web/claude-opus` ou `m365copilot/claude-opus`): muitas são palavras genéricas ou nomes de modelos de outros fornecedores, portanto, um `claude-opus` simples mantém o roteamento como acontece sem esse provedor. O registro não é uma promessa de que Microsoft sirva esse modelo para todas as contas. O IDs independente segue o [catálogo de protocolo](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) público (o mapa modelo para tom exportado e seus metadados de cenário com reconhecimento de modelo). Todos os perfis nativos retêm `availability: "unverified"`; a inclusão no catálogo não é um teste de conta bem-sucedido.

- Uma recusa explícita de licença de modelo retorna** 403** `m365_model_not_licensed`, não 502. O roteamento bloqueia esse par connection/model, deixando os modelos licenciados na conexão utilizáveis.
- `InvalidCopilotLicense` é uma recusa de licença em nível de conta, relatada separadamente como `m365_account_not_licensed`.
- Um acelerador por usuário retorna** 429** `m365_throttled` e esfria a conexão. Retornos de exaustão de acesso prioritário** 429** `priority_access_exhausted` e tem escopo de modelo. Um resultado de `OutOfCredits` com retornos `errorCode: "ReasoningTurnExhausted"`** 429** em vez disso, `reasoning_turns_exhausted` também tem escopo de modelo, sem tempo de reinicialização reivindicado. Foi relatado que um inquilino de trabalho limitou os tons "Pense mais profundamente" enquanto os tons Rápidos continuavam servindo; esse escopo é uma observação do consumidor, não algo que este repositório tenha reproduzido. O roteamento, portanto, também tira os outros modelos documentados de `gpt-5.5` e `gpt-5.6` da rotação nessa conexão para o mesmo resfriamento e deixa os tons rápidos e todas as outras falhas em seu próprio modelo. As dicas de nova tentativa fornecidas são preservadas; uma redefinição ausente não é anunciada como um tempo de redefinição conhecido.
- Uma recusa de segurança Copilot (`Disengaged`) retorna** 400** `provider_safety_rejection`, o rótulo de parada de segurança do provedor compartilhado. Isso nunca conta para a integridade da conexão, o cliente SDKs não tenta novamente um 400 e, com `PROVIDER_SAFETY_STOPS_TERMINAL` habilitado, o roteamento combinado para lá em vez de repetir a solicitação em outro destino.
- As solicitações em uma conexão são serializadas por meio do semáforo de conta existente. Prefira substitutos prioritários em vez de painéis paralelos; a serialização por si só não elimina os limites de taxa de conversação de Microsoft.

## Solicitar comportamento e limites

- As ferramentas são** emulado por prompt** , não chamadas de função Microsoft nativas. Uma solicitação habilitada para ferramenta usa uma geração em buffer; não passa mais uma geração selecionando ferramentas. Somente ferramentas declaradas com formas de argumento válidas e suportadas são retornadas como chamadas.
- Uma resposta longa e estruturada com um único exemplo final é preservada como prosa. Esta é uma heurística, não uma prova de intenção; os aplicativos ainda devem impor suas próprias permissões de ferramenta.
- A entrada de imagem funciona da mesma forma que o cliente web a envia. Cada parte da imagem (`image_url` como um data URL ou um HTTPS URL público ou um Responses `input_image`) é carregada no `/m365Copilot/UploadFile` na conversa do turno com o token de bate-papo, e a mensagem aponta para ele com uma anotação `ImageFile` ; o texto marca onde estava (`[image 1]`,…). Uma nova conversa carrega todas as imagens do histórico, uma continuação apenas as imagens das novas mensagens. Até 10 imagens PNG, JPEG, GIF ou WebP de no máximo 10 MiB cada (40 MiB por solicitação); o formato é lido a partir dos bytes. HTTPS URLs são obtidos por meio do protetor de imagem remota fixado por DNS, somente público. Um upload com falha falha na solicitação (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` ou `m365_image_invalid`); uma virada nunca acontece sem uma imagem que lhe foi dada. Outras partes não textuais (áudio, arquivos) são rejeitadas explicitamente, e não descartadas silenciosamente.
- Uma solicitação de acompanhamento continua a mesma conversa upstream e envia apenas as mensagens após a resposta anterior. Deve estender exatamente essa resposta: mesma conexão, perfil de modelo e conjunto de ferramentas; um histórico inalterado (uma cadeia sha256 sobre cada mensagem); e os IDs de chamada de ferramenta da resposta ou seu texto até o espaço em branco. Qualquer outra coisa (um histórico editado, outra sessão com a mesma primeira mensagem, uma resposta diferente, uma conversa inativa por 30 minutos ou perto do limite de 600 mensagens do Copilot, uma conexão sem ID) inicia uma nova conversa com todo o histórico. Um turno com falha nunca é retomado e um `InternalError` sem conteúdo é reenviado uma vez em uma nova conversa (** 502** `m365_internal_error` se falhar novamente). As continuações são mantidas na memória do processo: uma reinicialização inicia novas conversas.
- Cada turno é executado no chat temporário do Copilot(`disableMemory=1`): a conversa mantém seu contexto enquanto é executada e nunca aparece no histórico de chat da conta. Os testes de modelo, Testar tudo e testes combinados podem, portanto, sondar esse provedor sem deixar as conversas para trás.
- Uma curva tem um prazo ocioso de 120 segundos e um prazo geral limitado. Respostas apenas finais, filtragem de progresso e cancelamento são gerenciadas pelo transport/composer. nativo
- As respostas baseadas na Web mantêm suas fontes. Copilot marca uma citação embutida com caracteres de controle de uso privado e envia as fontes como `references`; cada marcador se torna um link Markdown numerado (`[1](https://…)`, ou o URL simples quando Copilot usou o marcador como destino do link) com uma anotação `url_citation` correspondente (`message.annotations`, ou `delta.annotations` no pedaço que carrega o link). Uma fonte que nunca chega é descartada, portanto os marcadores nunca chegam ao cliente. Durante o streaming, o texto após uma citação aguarda até que sua fonte chegue.
- O resumo de raciocínio de Copilot(`ChainOfThoughtSummary`), quando o modelo envia um, é retornado como `reasoning_content`, nunca como parte da resposta. Um resumo que se reescreve interrompe a transmissão sem falhar na curva.
- Antes de qualquer conteúdo, as falhas licence/throttle retêm HTTP 403/429 mesmo quando o streaming foi solicitado. Após o início do conteúdo, as falhas são eventos de erro SSE, nunca uma conclusão bem-sucedida. Uma reescrita upstream que não pode ser representada por streaming somente de acréscimo é um erro de stream explícito; as respostas da ferramenta sem streaming e com buffer mantêm o texto final.
- Quando Copilot recusa a conexão em si, sua resposta é relatada como está:** 401** `m365_unauthorized` para um login rejeitado ou expirado (faça login novamente),** 429** com seu `Retry-After` para limitação e uma falha de handshake, caso contrário, nunca uma falha de conexão genérica.

## Geração de imagem

`POST /v1/images/generations` com `model: "copilot-m365-web/m365-copilot-image"` (também conhecido como `m365copilot/m365-copilot-image`) desenha com a ferramenta de imagem integrada do Copilot, assim como o cliente web faz. Cada imagem é uma vez Copilot : ela aceita os conjuntos de opções de imagem do cliente web e declara `GenerateGraphicArt`, e a imagem chega em uma entrada de progresso apontando para um artefato no serviço Designer do Microsoft. Esse artefato recusa o token de bate-papo, então OmniRoute cria um token do Designer a partir do token de atualização da conexão e baixa os bytes; o token só é enviado para `designerapp.officeapps.live.com`.

- Precisa de uma conexão de login nativa (um token de atualização); um token colado falha com** 400** antes de qualquer turno ser gasto.
- `n` é 1–4, um turno cada. `size` apenas orienta a orientação (mais larga, mais alta ou quadrada), que Copilot lê no prompt; Copilot escolhe o tamanho da renderização.
- As imagens são retornadas in-line: `b64_json` por padrão, um dado URL para `response_format: "url"`.
- As imagens geradas dependem de um pequeno orçamento diário, separado do chat. Quando é usado, a solicitação falha com** 429** . Uma curva que responde sem imagem falha com** 502** (ou** 400** /** 503** quando o texto de Copilot parece uma recusa ou um problema de capacidade); a mensagem diz qual.

## Modelo de segurança

- **Integração não oficial.** Este provedor faz engenharia reversa do protocolo BizChat WebSocket. Pode quebrar sem aviso prévio quando Microsoft altera o endpoint.
- O sinalizador `subscriptionRisk: true` reflete que a integração depende de um endpoint não documentado. Restrições de conta são possíveis, mas não confirmadas.
- O token de acesso é um JWT de curta duração. Trate-a como uma senha: não a comprometa, registre ou compartilhe.
- O token de atualização concede acesso contínuo à superfície Microsoft 365. Armazene-o com o mesmo cuidado que uma chave API.

## Solução de problemas

### A autenticação falha imediatamente

- Verifique se você copiou do**WebSocket URL** , não de uma solicitação XHR/Fetch. A credencial está no parâmetro de consulta `access_token` da conexão WebSocket do Chathub — e não em um cabeçalho `Authorization: Bearer`.
- Certifique-se de que `chathubPath` inclua o segmento `<oid>@<tenant>` completo do caminho URL.

### O token expira após ~ 75 minutos

Isto é esperado. Sem `refreshToken`, o token de acesso tem vida curta. Qualquer:

- Capture novamente a credencial de DevTools ou
- Configurar** Configurações avançadas → Token de atualização (opcional)** na caixa de diálogo Adicionar ou editar conexão para atualização automática.

### O teste de conexão passa, mas o chat retorna 401

Para uma conexão criada com** Faça login com Microsoft** , o Test Connection verifica a expiração do token de acesso e renova um token expirado com o token de atualização armazenado, portanto, um teste aprovado também prova que o token de atualização ainda funciona.

Para uma credencial colada, o Test Connection verifica o formato da credencial e, quando o token expira, se o token que o provedor usaria não expirou (o token armazenado da conexão ganha uma pasta obsoleta; um token de atualização conta como renovável). Um token revogado antes de expirar ainda passa no teste; chat então retorna** 401** `m365_unauthorized`. Usar** Faça login com Microsoft** novamente ou capture novamente uma nova credencial.

### Copilot não aparece na lista de provedores

Certifique-se de `copilot-m365-web` esteja ativado em** Provedores → do painel** . O provedor pode estar oculto por padrão em algumas camadas.
