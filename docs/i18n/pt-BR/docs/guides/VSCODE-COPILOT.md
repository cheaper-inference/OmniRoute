## Configurar

1. **Execute OmniRoute** — `npm install -g omniroute && omniroute` (painel em `http://localhost:20128`).
2. **Instale a extensão** — procure "OmniRoute" na visualização Extensões.
3. **Conectar** — mantenha o `http://localhost:20128` padrão ou defina a chave URL e API do servidor por meio**OmniRoute: Gerenciar conexão** .
4. **Escolha um modelo** — Copilot Bate-papo → seletor de modelo →** Gerenciar modelos…** →**OmniRoute** e marque o que deseja.

Para configurações de conexão, abra o** ícone OmniRoute na barra de atividades** (ou execute `OmniRoute: Manage Connection`) e defina:

- **Servidor URL** — a raiz do servidor, por exemplo, `http://omniroute.example.com:20128`. O sufixo `/v1` é anexado pela extensão; não inclua.
- **chave API** — obrigatório quando a política de autenticação de inferência do servidor exige um. Armazenado através do código VS SecretStorage, nunca em `settings.json`; chaves específicas do espaço de trabalho estão disponíveis. Use uma chave autorizada para os modelos que deseja expor.

A extensão também fornece um indicador de conexão, atualização de modelo, contexto de modelo e metadados de preços (combos incluídos), raciocínio transmitido com um** Esforço de pensamento** menu no VS Code 1.120 +, um indicador de limite diário da barra de status e painel de uso (OmniRoute 3.8.50 +), configuração CLI e uma guia opcional do painel. O modelo selecionado e a política do servidor determinam os recursos que você pode usar.

## O que o seletor exibirá

A extensão não exibe a resposta bruta de `GET /v1/models` — ela a formata, e a quantidade que você
vê é menor que o tamanho do catálogo por dois motivos intencionais.

### Ela solicita um id por modelo

`MODELS_CATALOG_PREFIX_MODE` usa **`dual`** como padrão, o que anuncia cada modelo duas vezes — uma
com o prefixo curto do alias e outra com o prefixo canônico do provedor — para que configurações de
clientes mais antigos continuem resolvendo ambas as formas:

```
cc/claude-sonnet-4-6        ← prefixo do alias
claude/claude-sonnet-4-6    ← prefixo canônico, mesmo modelo
```

A extensão solicita **`GET /v1/models?prefix=alias`** para que seja retornado um id por modelo, sem
alterar a configuração global do servidor para seus outros clientes. Em uma instância de referência,
isso reduziu **2345 entradas para 1396 — 949 duplicatas, nenhum modelo perdido.**

Se você preferir corrigir isso no servidor para _todos_ os clientes, defina a feature flag
`MODELS_CATALOG_PREFIX_MODE` como `alias` no painel. Consulte
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) para ver o
parâmetro de consulta e a tabela de cada modo.

### Ela oculta modelos que não podem ser usados em chats

O catálogo também lista modelos de imagem, vídeo, áudio, rerank, embedding e moderação. Eles
seriam rejeitados de qualquer forma em uma solicitação de chat:

```
HTTP 400 — O modelo '<id>' é um modelo de geração de imagens e não pode ser usado em
/v1/chat/completions. Em vez disso, use POST /v1/images/generations.
```

por isso, eles são filtrados pelo campo `type` antes de chegarem ao seletor. **Os modelos da
Responses API são mantidos** — cada entrada Codex / GPT-5.x anuncia `supported_endpoints: ["responses"]`,
e o OmniRoute faz a tradução para `/v1/chat/completions`, portanto eles podem ser usados normalmente.

### Provedores que você nunca configurou

O catálogo lista modelos de provedores com uma **conexão ativa**, além de todos os provedores
**noAuth** — aqueles que não exigem chave e que compõem grande parte do nível gratuito. Isso é
intencional. Para ocultá-los, adicione-os a `blockedProviders` nas configurações do painel; nada
muda na extensão.

## Dashboard em uma aba do VS Code

`omnicopilot.dashboardOpen: "editor"` renderiza o dashboard do OmniRoute em uma aba do editor por meio do
Simple Browser, em vez de em um navegador externo. A incorporação é **habilitada explicitamente no servidor** por meio de
`DASHBOARD_ALLOW_EMBED=vscode`, que fornece as páginas HTML com
`frame-ancestors 'self' vscode-webview:` em vez do padrão `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. A superfície da API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) mantém os
cabeçalhos restritivos em ambos os casos.

> ⚠️ **Essa é uma opção de tempo de build, não de runtime.** O Next.js compila `headers()` no manifesto de
> rotas, portanto, `next.config.mjs` lê a variável enquanto o bundle é criado
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Exportá-la antes de iniciar um servidor já compilado não altera nada — os cabeçalhos ficam incorporados.

```bash
# a variável precisa estar presente no comando de BUILD
DASHBOARD_ALLOW_EMBED=vscode npm run build        # ou npm run build:release
npm start
```

| Como você instalou         | É possível habilitar a incorporação?                                                                                                            |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| A partir do código-fonte   | ✅ defina a variável no comando de build, como mostrado acima                                                                                   |
| `npm install -g omniroute` | ❌ o pacote publicado inclui um bundle pré-compilado — em vez disso, faça o build a partir do código-fonte                                      |
| Imagem Docker              | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — a imagem pré-compilada no Docker Hub não permite incorporação |

Sem um build com incorporação habilitada, a página recusa ser exibida em um frame; a extensão detecta isso pelos
cabeçalhos da resposta e recorre ao navegador externo — nada para de funcionar, e ela informa isso uma vez.
Consulte [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) e a issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Configurando suas outras ferramentas de dentro VS Code

**`OmniRoute: Configure Coding CLI`** impulsiona o `omniroute` CLI para escrever perfis prontos para uso para 16 ferramentas: Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code, Kilo, Roo, Gemini CLI, Zed, WhyCodes e 5dive. A extensão invoca comandos `setup-*` no terminal integrado; instale uma versão do OmniRoute CLI que inclua o comando selecionado. Consulte o [guia de integração CLI](CLI-INTEGRATIONS.md) para obter os arquivos e sinalizadores que cada receita usa e o [registro da ferramenta de extensão](https://github.com/cheaper-inference/OmniCopilot/blob/main/src/cliBridge.ts).

A chave API é entregue ao CLI por meio `OMNIROUTE_API_KEY`, nunca na linha de comando. As receitas de configuração podem persistir credenciais na configuração da ferramenta de destino. Ao compartilhar uma chave específica do espaço de trabalho com a configuração de nível de usuário de uma ferramenta, a extensão solicita primeiro a confirmação.

## Solução de problemas

| Sintoma                                                      | Causa / correção                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Nenhum modelo OmniRoute no seletor                           | Servidor inacessível. O ponto da barra de status fica cinza; execute `OmniRoute: Check Connection`. A descoberta é silenciosa por natureza e não contribui com modelos, em vez de sugestões.                                                                                                                        |
| Cada modelo aparece duas vezes                               | Você está em uma atualização OmniCopilot anterior a 1.0.1 —. A extensão agora solicita `?prefix=alias`.                                                                                                                                                                                                             |
| Um modelo image/audio costumava ser listado e desapareceu    | Intencional desde 1.0.1 —, nunca poderia responder a uma solicitação de chat.                                                                                                                                                                                                                                       |
| Painel ausente na barra de atividades                        | O código VS move contêineres de visualização extras para o** “…”** estouro na parte inferior da barra de atividades e um contêiner oculto ao clicar com o botão direito permanece oculto. Clique com o botão direito na marca → da barra de atividades**OmniRoute** , ou abra-o com `OmniRoute: Manage Connection`. |
| O painel abre no navegador apesar do modo `editor`           | O servidor não foi** construído** com `DASHBOARD_ALLOW_EMBED=vscode` (veja acima) — configurá-lo na inicialização em uma instalação pré-construída não faz nada. A retirada é deliberada.                                                                                                                           |
| A lista de modelos ficou obsoleta após a mudança de provedor | `OmniRoute: Refresh Models` ou o link ↻ no painel.                                                                                                                                                                                                                                                                  |
| O painel diz _Online (modelos bloqueados)_, seletor vazio    | O servidor rejeita a chave. Salve a chave certa com** Salvar e testar** . Se a chave foi fixada no servidor (habilitada ou com acesso aos modelos), a extensão não percebe por si só: execute `OmniRoute: Refresh Models` ou abra o painel OmniRoute.                                                               |
