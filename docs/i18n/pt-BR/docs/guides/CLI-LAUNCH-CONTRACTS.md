O contrato `config/cli-tools-manifest.json` neutro declara IDs canônico, aliases, candidatos binários, receitas de configuração, argumentos de modelo e capacidades. O adaptador Node simples em `bin/cli/cli-manifest.mjs` e o adaptador TypeScript em `src/shared/constants/cliIntegrationManifest.ts` leem o mesmo arquivo. Tempo de execução, catálogo, configuração, conclusão, geradores e registro de backend são verificados juntos por `tests/unit/cli/cli-manifest-drift.test.ts`. Estar catalogado não significa que uma ferramenta possa ser lançada ou configurada. Em particular, o 5dive permanece apenas para configuração.

## Ambiente infantil e ciclo de vida

`omniroute run`, `omniroute launch` e `omniroute launch-codex` herdam uma lista de permissões de compatibilidade OS/terminal e injetam as credenciais do alvo selecionado. Os segredos do provedor e do banco de dados não relacionados não são herdados por padrão. `--inherit-env` restaura explicitamente a herança completa do ambiente pai; use-o somente quando o processo de terceiros selecionado receber esses valores. Esta é uma filtragem de ambiente, não uma sandbox OS : o processo ainda é executado com as permissões do sistema de arquivos do chamador.

Os sinais de interrupção e encerramento são encaminhados para a criança. O inicializador aguarda o evento de fechamento do filho antes de remover a configuração temporária. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` controla o período de carência antes do encerramento forçado (padrão 5.000 milissegundos).

## configuração persistente Gemini

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

Os dois primeiros comandos configuram esta máquina para o servidor local ou remoto selecionado. A instalação preserva configurações JSON não relacionadas, seleciona a autenticação da chave de API Gemini e grava o endpoint e a credencial em um arquivo `.gemini/.env` privado. Ele recusa JSON inválido em vez de substituí-lo. O endpoint URLs deve ser HTTP(S), sem credenciais incorporadas, parâmetros de consulta ou fragmentos. A simulação imprime caminhos, não valores de credenciais.

`GEMINI_CLI_HOME` ou `--gemini-home` seleciona a raiz inicial persistente. Um `run gemini` real cria e posteriormente remove seu próprio lar temporário. Nenhum dos modos ignora as verificações de confiança do espaço de trabalho do Gemini.

## perfis Codex

`configure codex` grava um `<name>.config.toml` privado com um modelo e seu endpoint do provedor OmniRoute. As credenciais são referenciadas por meio de `OMNIROUTE_API_KEY`, nunca incorporadas. O comando de inicialização define o modelo selecionado na chave `model` de nível superior, não dentro `model_providers`.

Arquivos de perfil separados são o contrato Codex documentado atual; eles se sobrepõem à configuração do usuário quando selecionados com `codex --profile <name>`. Veja [a referência oficial do perfil](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) e [o guia OmniRoute Codex](./CODEX-CLI-CONFIGURATION.md).

## Execução de comando hermético

Com um `DATA_DIR` explícito, a configuração `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` evita que a inicialização caia no ambiente de credenciais do diretório de dados do usuário padrão. Isto é útil para testes isolados. Ele não desativa outros arquivos de ambiente explicitamente selecionados.

## Diretório de trabalho `.env`

O CLI lê os arquivos `.env` nesta ordem, e o primeiro arquivo a definir uma chave vence: o `DATA_DIR` explícito, o diretório de dados padrão, o diretório de trabalho atual e, em seguida, o diretório do pacote. Variáveis do shell sempre vencem.

O diretório de trabalho pode pertencer a outra pessoa (um repositório clonado, um arquivo descompactado) e `omniroute serve` passa o ambiente CLI para o servidor e para todas as ferramentas que o servidor executa. Portanto, um `.env` pode definir apenas estas chaves, listadas em `bin/cli/utils/untrustedCwdEnv.mjs`:

| Chave                           | Valores aceitos                                                                |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `REQUIRE_API_KEY`               | `true`, `1` ou `yes` em qualquer caso, os valores que o servidor trata como em |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | até 64 letras, dígitos, `_`, `.`, `@` ou `-`                                   |
| `LANGUAGE`                      | o mesmo, mais `:`                                                              |
| `TZ`                            | até 64 letras, dígitos, `_`, `+`, `-` ou `/`, sem começar com `/`              |
| `NO_COLOR`, `FORCE_COLOR`       | até 16 letras e dígitos                                                        |

Cada valor `REQUIRE_API_KEY` aceita ativa a verificação, portanto o arquivo não pode desativar a verificação sozinho. Porém, ele não decide o resultado: o servidor lê uma substituição `REQUIRE_API_KEY` armazenada no banco de dados antes do ambiente, enquanto o aviso de inicialização sobre a escuta em todas as interfaces sem uma chave API lê apenas o ambiente. Com uma substituição armazenada de `false`, um diretório de trabalho `REQUIRE_API_KEY=true` deixa o API aberto e oculta esse aviso. A regra `TZ` é mais restrita que POSIX: ela rejeita `.`, `:`, `,` e `<>`, então a forma `:Area/City` e regras como `EST5EDT,M3.2.0,M11.1.0` devem ser definidas no shell ou em `<DATA_DIR>/.env`.

Os nomes devem corresponder exatamente, em letras maiúsculas. Qualquer outra linha, um valor que falhe na verificação e um nome que não seja simples letras ASCII, dígitos e `_` (por exemplo, um com um byte NUL ou uma letra semelhante) são ignorados. O CLI imprime um aviso que nomeia as chaves que ele não pode definir e outro que nomeia as chaves permitidas que ele ignorou, cada uma com o que alterar (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Nenhum dos dois imprime os valores. Os caminhos de arquivo nessas mensagens e os relatórios `.env` path `omniroute doctor` têm escape quando contêm caracteres de controle ou bidi. A restrição não se aplica quando o diretório de trabalho é o diretório de dados ou o diretório de pacotes.

`PORT`, `API_PORT` e `DASHBOARD_PORT` não estão na lista. Sem um URL base de uma fonte de maior precedência, o CLI fala com `localhost:<PORT>`, e tudo o que escuta lá recebe a chave API do CLI, o token de contexto e o token da máquina CLI (`x-omniroute-cli-token`, consulte [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), que o servidor local aceita para chamadas de gerenciamento de loopback. Uma porta do diretório de trabalho permitiria que esse arquivo escolhesse o ouvinte, então defina as portas no shell, em `<DATA_DIR>/.env` ou com a opção `--port` de comandos que possuem uma (`serve`, `launch`, `run`).

O analisador não possui sintaxe `export`. Uma linha como `export LD_PRELOAD=...` nomeia uma variável `export LD_PRELOAD`; do diretório de trabalho ele é ignorado e em outros arquivos `.env` ele define esse nome literal, que nada lê.

O CLI emparelha o token armazenado de um contexto (token de acesso ou chave API herdada) apenas com a própria origem desse contexto: esquema, host e porta, comparados como `URL.origin`. Isso se aplica a solicitações feitas por meio do cliente HTTP do CLI(`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) e aos comandos `launch`, `launch codex`, `configure` e `setup-*` que gravam um URL base e uma chave na configuração de outra ferramenta. Apontados para outro servidor com `--remote`, eles usam um `--api-key` ou `OMNIROUTE_API_KEY` explícito, se houver algum definido, e nenhum token de contexto. A comparação é exata, então `localhost` e `127.0.0.1`, ou um host com e sem ponto final, contam como servidores diferentes e não recebem nenhum token de contexto. Um URL com userinfo, uma barra invertida ou um espaço em branco nunca corresponde, porque outros analisadores URL ( `urllib` e `httpx` do Python, por exemplo) podem ler um host diferente dele. Para solicitações que o CLI envia sozinho, essa verificação cobre apenas o esquema e a autoridade, portanto, um id com um espaço no caminho ou consulta mantém o token.
