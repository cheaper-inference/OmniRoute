## Tokens grátis por mês: ~ 11,3 bilhões conforme outros contam · ~ 90 milhões de reais

</div>

> **~ 11,3 bilhões de tokens grátis/mês**<br/> <sub> contou da mesma forma que outros catálogos contam: cada linha somada, ofertas encerradas incluídas </sub>
>
> **~ 90 milhões de reais hoje**<br/> <sub> cada cota compartilhada contada uma vez: o que você realmente pode usar </sub>
>
> **Tudo aqui é grátis. Sem acesso pago.**<br/> ★ [Gostou? Marque-nos no GitHub](https://github.com/cheaper-inference/OmniRoute)

Outros catálogos cobram de US$ 19 por ano a US US$ 49 por acesso vitalício a dados ao vivo. Aqui tudo é grátis. Preços <sub> verificados em 18/11/2026.</sub>

<sub>Catálogo auditado pela última vez em 23/11/2026. [Como contamos →](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **Traga suas próprias contas de provedor.** Esses são níveis gratuitos de terceiros, não uma concessão de token do OmniRoute. Cadastre-se, obtenha credenciais onde um provedor as solicitar e conecte aquelas que você pode usar. Cada provedor define seus próprios limites, disponibilidade e termos.
>
> Empilhar níveis gratuitos manualmente significa dezenas de SDKs, dezenas de limites de taxas e nenhuma ideia clara do que resta. OmniRoute mantém 214 linhas de catálogo com acesso livre e calcula o valor real de 12 pools com cota publicada, cada pool compartilhado contado uma vez. As cotas que só abrem após uma verificação de identidade regional (hoje, ModelScope) são mostradas separadamente, +~ 6 milhões atrás da verificação de identidade regional, e nunca adicionadas ao número real. O que resta aparece no painel (`/dashboard/free-tiers`).

## Instalar, conectar um provedor e rotear por meio de um endpoint

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>`auto` precisa de uma rota qualificada. Uma nova instalação não pode ter alvos sem chave qualificados e um provedor sem chave pode rejeitar clientes de terceiros. Consulte o [Guia de níveis gratuitos](docs/getting-started/FREE-TIERS-GUIDE.md) antes de escolher um provedor.</sub>

## Combos: o carro-chefe

1. **Comece com `auto`.** Defina o modelo em seu cliente compatível com OpenAI. OmniRoute cria um combo virtual de provedores conectados e pontua os candidatos ao vivo.
2. **Salve um combo para ter mais controle.** Escolha um nome, uma lista de metas e uma estratégia e, em seguida, use esse nome como modelo. A estratégia define qual alvo será atingido primeiro e como os demais serão tentados.

Um combo é roteado automaticamente entre modelos. No esgotamento da cota, falha do provedor ou bloqueio do modelo, ele tenta o próximo alvo elegível e íntegro.

### Configuração zero: basta usar `auto`

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

Variantes ajustam os pesos. O último roteamento válido permanece com o último provedor bem-sucedido até falhar e, em seguida, é remarcado. `auto/fast` e `auto/cheap` expressam preferências sem garantir o modelo mais rápido ou mais barato.

| Modelo ID           | Comportamento                                                                                                                                                                                                                                                                                  |
| :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Pesos padrão balanceados.                                                                                                                                                                                                                                                                      |
| `auto/fast`         | Favorece a baixa latência e a saúde do provedor.                                                                                                                                                                                                                                               |
| `auto/cheap`        | Favorece preços de catálogo mais baixos.                                                                                                                                                                                                                                                       |
| `auto/coding`       | Pesos de qualidade em primeiro lugar para geração de código.                                                                                                                                                                                                                                   |
| `auto/smart`        | Pesos de qualidade com 10% de exploração (padrão 5%).                                                                                                                                                                                                                                          |
| `auto/lkgp`         | Roteamento explícito de último valor conhecido com os mesmos pesos que `auto`.                                                                                                                                                                                                                 |
| `auto/subscription` | Usa apenas cota de plano verificada ao vivo. Retorna HTTP 503 quando nenhum estiver disponível e evita substituto cobrado.                                                                                                                                                                     |
| `auto/thrifty`      | Plano → keyless → grátis → barato → premium. Pode atingir modelos faturados e retornar ao plano quando a cota e o cooldown permitirem.                                                                                                                                                         |
| `auto/offline`      | Favorece a margem de cota e limite de taxa. As solicitações ainda vão para seus provedores.                                                                                                                                                                                                    |
| `auto/chaos`        | Um modelo por provedor em paralelo, até cinco por padrão ou dez quando configurado. Uma chamada upstream por modelo. Retorna a resposta com melhor classificação ou a última resposta bem-sucedida do painel se o modelo principal falhar. Use `fusion` para sintetizar respostas com um juiz. |

Exemplos de categoria e nível opcional incluem `auto/coding:fast`, `auto/coding:free`, `auto/reasoning:pro` e `auto/vision`. Se nenhum candidato conectado corresponder, a solicitação retornará HTTP 503 e o pool permanecerá restrito. [Guia de combinação automática](./docs/routing/AUTO-COMBO.md) · [Roteamento que prioriza a assinatura](./docs/routing/SUBSCRIPTION_LADDER.md)

### Ou crie a sua própria: 22 estratégias de roteamento

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

O CLI aceita 15 das 22 estratégias. O painel e os combos API aceitam todos os 22.

| Estratégia          | Comportamento                                                                                                                                                                                                                            |
| :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Os candidatos à classificação vivem com o marcador Auto-Combo de 16 fatores.                                                                                                                                                             |
| `cache-optimized`   | Prefira a conta que provavelmente conterá o prefixo do prompt no cache.                                                                                                                                                                  |
| `context-optimized` | Experimente primeiro a maior janela de contexto conhecida.                                                                                                                                                                               |
| `context-relay`     | Mantenha seu pedido e passe um resumo da conversa ao trocar de conta.                                                                                                                                                                    |
| `cost-optimized`    | Classifique por preço do token de entrada do catálogo, por último as incógnitas. O custo da solicitação final pode ser diferente.                                                                                                        |
| `expiry-first`      | Cota de gastos com probabilidade de expirar, maior sobra por hora até ser reiniciada primeiro.                                                                                                                                           |
| `fill-first`        | Permaneça no primeiro alvo disponível até que ele acabe ou falhe e depois siga em frente.                                                                                                                                                |
| `fusion`            | Consulte um painel em paralelo e peça a um juiz que sintetize uma resposta.                                                                                                                                                              |
| `headroom`          | Escolha a capacidade mais livre em janelas semanais e de 5 horas.                                                                                                                                                                        |
| `jev`               | TypeSafe Jev escolhe quais entradas em sua lista de classificação serão executadas. Ative o `COMBO_JEV_STRATEGY_ENABLED` para enviar um trecho por solicitação e usar chamadas TypeSafe pagas. Com ele desativado, seu pedido se aplica. |
| `least-used`        | Escolha o alvo com o menor número de solicitações registradas neste combo.                                                                                                                                                               |
| `lkgp`              | Experimente primeiro o último fornecedor bem-sucedido, caso contrário, mantenha seu pedido.                                                                                                                                              |
| `p2c`               | Experimente dois alvos e escolha por taxa de sucesso e latência.                                                                                                                                                                         |
| `pipeline`          | Alimente a saída de cada etapa no próximo alvo em sequência e retorne apenas a resposta final.                                                                                                                                           |
| `priority`          | Experimente alvos em seu pedido. A aderência da sessão a preserva.                                                                                                                                                                       |
| `quota-weighted`    | Ignore contas esgotadas e aproveite a cota restante e a carga em voo.                                                                                                                                                                    |
| `random`            | Embaralhe para cada solicitação. O mesmo primeiro alvo pode ser repetido.                                                                                                                                                                |
| `reset-aware`       | Pontue a cota restante e o tempo para redefinir nas janelas de sessão e semanais.                                                                                                                                                        |
| `reset-window`      | Experimente a conta cuja janela de cota será redefinida mais rapidamente.                                                                                                                                                                |
| `round-robin`       | Gire em ordem, três sucessos por alvo por padrão.                                                                                                                                                                                        |
| `strict-random`     | Distribua a partir de um baralho embaralhado para que cada alvo lidere uma vez antes de repetir.                                                                                                                                         |
| `weighted`          | Desenhe um primeiro alvo por peso e mantenha o resto como substitutos. A divisão é estatística. Use `round-robin` para rotação estrita.                                                                                                  |

As estratégias de cotas usam dados em tempo real onde os provedores os reportam, incluindo janelas de assinatura semanais e de 5 horas. `fusion` e `pipeline` fazem múltiplas chamadas upstream por solicitação.

O marcador de 16 fatores usa cota, integridade, custo, latência, ajuste de tarefa, estabilidade, prioridade de nível, afinidade de nível, correspondência de especificidade, afinidade de contexto, afinidade de cache, disponibilidade de sessão, afinidade de janela de redefinição, densidade de conexão, qualidade e confiabilidade. Os pesos variam de acordo com o perfil. A afinidade de cache, a afinidade de janela de redefinição e a confiabilidade têm peso zero por padrão. [Fatores de pontuação](./docs/routing/AUTO-COMBO.md#how-it-works-persisted-auto-combos)

### A resiliência está integrada em: 3 camadas independentes

As falhas são tratadas em três escopos, de modo que um modelo incorreto não desativa sua conta e uma conta incorreta não desativa seu provedor.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Se um provedor inteiro estiver inoperante

O** disjuntor do fornecedor** abre após 8 (OAuth) ou 12 (API key) falhas com status 408, 500, 502, 503 ou 504. Os combos ignoram esse provedor enquanto ele está aberto. Após 60 ou 30 s, uma solicitação de teste decide se será fechada.

#### Se uma chave ou conta tiver taxa limitada

O** resfriamento da conexão** bancada apenas essa conexão, com backoff exponencial de 5 s (OAuth) ou 3 s (tecla API ). Outras chaves do mesmo provedor continuam sendo veiculadas.

#### Se um modelo for recusado

O** bloqueio de modelo** bloqueia apenas esse modelo nessa conexão após um modelo 429, 404 ou negação de acesso. Outros modelos na mesma conexão continuam servindo.

Conexões banidas, expiradas e sem crédito são estados terminais, não tempos de espera: elas esperam que você as conserte.

## CLI, MCP e A2A completos

> OmniRoute fornece um cliente de linha de comando com** 91 comandos e grupos de comandos de nível superior** (754 comandos contando subcomandos), um** servidor MCP com 110 ferramentas e 33 escopos** , e um** agente A2A com 6 habilidades** . Scripts, terminais e agentes AI podem operar no mesmo gateway.

### Um verdadeiro CLI, não apenas `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

O sinalizador global `--output table|json|jsonl|csv` torna os mesmos comandos utilizáveis em scripts e CI.

### Modo remoto: o CLI no seu laptop, OmniRoute em um servidor

Faça login uma vez em um servidor remoto. O CLI o salva como um** contexto** e comandos posteriores são executados nesse servidor até você voltar.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Escopo do token | <img width="2000" height="0" alt=""> O que permite                             |
| --------------- | ------------------------------------------------------------------------------ |
| `read`          | Liste e inspecione: modelos, status, logs, uso                                 |
| `write`         | `read` plus configure e aplique: configuração do cliente, chaves, configuração |
| `admin`         | `write` plus gerencia: tokens, provedores, serviços, política                  |

Um host simples obtém `http://` e porta 20128; passe um `https://` URL completo quando o servidor estiver atrás de TLS. As rotas que podem gerar processos permanecem apenas em loopback, qualquer que seja o token.

### Conecte um agente

Um agente, ou seu próprio código, pode conduzir roteamento, provedores, combos, cache, compactação e memória através de qualquer uma dessas interfaces. Os caminhos HTTP são atendidos pelo gateway, por padrão em `http://localhost:20128`.

| Interface                   | Ponto final ou comando     | Use-o para                                                                                  |
| --------------------------- | -------------------------- | ------------------------------------------------------------------------------------------- |
| MCP sobre stdio             | `omniroute --mcp`          | Claude Desktop, Cursor e outros clientes MCP locais                                         |
| MCP sobre HTTP transmitível | `/api/mcp/stream`          | Clientes MCP remotos: 110 ferramentas, 33 escopos, cada chamada gravada no log de auditoria |
| MCP sobre SSE               | `/api/mcp/sse`             | Clientes que ainda utilizam o transporte SSE                                                |
| descoberta A2A              | `/.well-known/agent.json`  | Cartão de Agente: informa a outros agentes o que OmniRoute pode fazer                       |
| execução A2A                | `POST /a2a`                | Tarefas JSON-RPC 2.0, síncronas ou transmitidas por SSE, em 6 habilidades                   |
| REST API                    | `/v1/*`                    | Bate-papo, respostas, embeddings, imagens, áudio e OCR compatíveis com OpenAI               |
| Webhooks                    | `/api/webhooks`            | Eventos para Slack, Discord, Telegram ou qualquer URL com assinatura HMAC                   |
| CLI remoto                  | `omniroute connect <host>` | Gere uma instância remota com tokens de acesso com escopo definido                          |

As seis habilidades A2A são `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` e `list-capabilities`.

**Antes de conectar:**

- **MCP sobre HTTP inicia desabilitado.** Ative-o com `omniroute mcp enable --transport streamable-http` ou na página Endpoints do painel. Um transporte HTTP está ativo por vez: `streamable-http` atende `/api/mcp/stream`, `sse` atende `/api/mcp/sse`.
- **A2A inicia desabilitado.** Habilite-o na página Endpoints do painel. `POST /a2a` segue as mesmas regras de chave de API que `/v1`.
- **MCP remoto precisa de uma chave adequada.** `/api/mcp/*` responde apenas loopback por padrão. De outro host, envie uma chave com `manage` ou `admin` (todas as ferramentas), ou com `mcp:connect` mais os escopos das ferramentas que você precisa. Para chaves sem `manage`/`admin`, os escopos da ferramenta são sempre aplicados.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

## Economize 15–95% de tokens — automaticamente

### Como funciona pipeline —, arquitetura e matemática de economia

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

O combo empilhado padrão é executado `RTK → Caveman`. Quando ambos atuam na mesma carga útil tool/context, a economia aumenta:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Blocos de código, URLs, JSON e dados estruturados são** sempre protegido** pelo mecanismo de preservação.

> **Por que usar muitos tokens quando poucos tokens resolvem?** Cada solicitação passa pelo pipeline de compactação do OmniRoute** transparentemente** — nenhuma alteração no cliente. Agora é um** pilha de 12 motores combináveis** que são executados em ordem e combinados por combinação de roteamento — com base em ideias de [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) e [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

### Além dos estilos de saída — dos motores, o dial adaptativo e o controle por solicitação

Molde a resposta, direcione a janela de contexto do modelo ou escolha um plano de compactação por solicitação.

#### Estilos de saída

| Estilo                                           | <img width="2000" height="0" alt=""> O que faz                                         |
| ------------------------------------------------ | -------------------------------------------------------------------------------------- |
| Prosa concisa                                    | Corta enchimento e cobertura preservando detalhes técnicos.                            |
| Menos código                                     | Solicita a menor alteração funcional e reutiliza o código existente.                   |
| Rabo de cavalo (desenvolvedor sênior preguiçoso) | Verifica o que pode ser reutilizado ou removido e solicita uma correção da causa raiz. |
| Eu tenho ADHD (ação primeiro)                    | Inicia a ação, numera as etapas e termina com uma próxima etapa concreta.              |
| Conciso CJK (文言)                               | Usa chinês clássico conciso. Disponível para `zh`.                                     |

Cada estilo possui intensidades `lite`, `full` e `ultra`. Adicione um estilo com uma entrada no registro de estilo de saída.

#### Orçamento de contexto adaptativo

| Contexto | Opções                                                                                                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Política | `reserve-output` (padrão) reserva espaço para resposta e uma margem de segurança. `percentage` usa um compartilhamento da janela de contexto. `absolute` define um alvo de token fixo.                |
| Modo     | `floor` pode escalar o plano selecionado para caber na janela de contexto. `replace-autotrigger` usa o orçamento para escalonamento automático. `off` mantém o disparo automático do limite de token. |

#### Onde a compressão é decidida

| Ordem | Fonte <img width="2000" height="0" alt="">                                   |
| ----- | ---------------------------------------------------------------------------- |
| 1     | Cabeçalho de solicitação `x-omniroute-compression` reconhecido               |
| 2     | Substituição de combinação de roteamento                                     |
| 3     | Perfil nomeado ativo                                                         |
| 4     | Orçamento de contexto adaptável ou acionamento automático de limite de token |
| 5     | Padrão do painel de compactação                                              |
| 6     | Desativado quando nenhum plano se aplica                                     |

O switch de compactação global tem prioridade sobre esta tabela. O cabeçalho de resposta `X-OmniRoute-Compression` relata `<mode>; source=<source>`.

[Guia de compactação](docs/compression/COMPRESSION_GUIDE.md) · [compactação RTK](docs/compression/RTK_COMPRESSION.md) · [Mecanismos de compactação](docs/compression/COMPRESSION_ENGINES.md)

O chicote de avaliação opcional (`npm run eval:compression`) compara a fidelidade da resposta e a economia de token em um corpus fixo.

## Mais métodos de instalação — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` segue o mais alto** publicado** estável SemVer. Ele não rastreia git `main`. Fixe `:X.Y.Z` para GitOps. Consulte [os canais de lançamento Docker](docs/guides/DOCKER_GUIDE.md#release-channels). Os pinos da imagem**`OMNIROUTE_MEMORY_MB=1024`** . Isso é suficiente para o painel e um bate-papo leve.** Agentes de codificação** (`POST /v1/responses` do código Claude, Codex, Grok,…) precisa de um heap V8 muito maior ou do processo `FATAL ERROR` s em ~ 12 GiB sob dois contextos longos sobrepostos. Dimensione o contêiner acima do heap (os buffers nativos ficam fora do V8):

| Carga de trabalho <img width="2000" height="0" alt=""> | Pilha (`-e OMNIROUTE_MEMORY_MB`) | Contêiner (`--memory`) |
| ------------------------------------------------------ | -------------------------------- | ---------------------- |
| Painel / bate-papo leve                                | `1024` (imagem padrão)           | ≥ 2 g                  |
| Um agente de codificação                               | `8192`                           | ≥ 10 g                 |
| Dois `/v1/responses` longos simultâneos                | `10240`–`12288`                  | ≥ 12–16 g              |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Tabela completa: [Guia Docker — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Canal Docker de pré-lançamento:** `diegosouzapw/omniroute:next` e `diegosouzapw/omniroute:next-web` seguem o branch `release/v*` padrão atual. Essas tags mutáveis destinam-se apenas ao teste de correções não lançadas e são** não suportado para produção** . Consulte [Canais de lançamento Docker](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

`bun install` padrão e a instalação global (`bun install -g omniroute`) são suportados por meio da detecção de tempo de execução Bun :

- **`bun:sqlite` integrado** : OmniRoute usa o driver `bun:sqlite` integrado do Bun ao executar no Bun, recorrendo ao `better-sqlite3` no Node.js ou `sql.js`.
- **Seleção automática de empacotador Webpack em dev** : O desenvolvimento (`bun run dev`) detecta automaticamente Bun e desativa Turbopack em favor do Webpack para evitar incompatibilidades de ligação nativa do V8. As compilações de produção (`bun run build`) seguem `OMNIROUTE_USE_TURBOPACK` exatamente como no Node: Turbopack por padrão, `OMNIROUTE_USE_TURBOPACK=0` para compilar com o Webpack (`Dockerfile.bun` o expõe como um `--build-arg`).
- **Dockerfile Bun dedicado** : `Dockerfile.bun` de vários estágios para implantações de produção Bun nativas (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ Instalação mais rápida / enxuta (pule a compilação nativa)**

O mecanismo SQLite nativo (`better-sqlite3`) é um** opcional** dependência, portanto, uma instalação global nunca bloqueia a compilação a partir da fonte: ela usa um binário pré-construído quando um corresponde ao seu platform/Node e, caso contrário, recorre de forma transparente a um mecanismo JS puro (`node:sqlite` no nó 22 +, caso contrário, o pacote `sql.js` WASM) — não requer ferramentas de construção.

Para pular a pós-instalação** aquecimento nativo** inteiramente ( máquinas CI, headless ou lentas). Nota: isso apenas ignora a etapa de aquecimento nativa SQLite (`scripts/postinstall.mjs`); o gancho binary-copy/repair (`scripts/build/postinstall.mjs`) ainda funciona normalmente:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

Para instalações mais rápidas prefira** pnpm** (hard links + da loja endereçada ao conteúdo — veja acima). Para um tempo de execução sem painel e sem interface, use o perfil Docker `base` (acima) ou o [guia Termux](docs/guides/TERMUX_GUIDE.md). O CLI e o painel da web são atendidos pelo mesmo processo em uma porta, portanto, atualmente não existe um pacote separado apenas para CLI.

### Como contribuir

1. Bifurque o repositório
2. Filial do** ativo** `release/vX.Y.Z` tip (não `main`) — consulte [Modelo de ramificação e liberação](docs/ops/BRANCHING_MODEL.md)
3. Crie sua ramificação de recursos (`git checkout -b feat/amazing-feature`)
4. Confirme suas alterações (`git commit -m 'feat: add amazing feature'`)
5. Empurre para o ramo (`git push origin feat/amazing-feature`)
6. Abra uma solicitação pull com** base = aquele ramo `release/vX.Y.Z`**

Consulte [CONTRIBUTING.md](CONTRIBUTING.md) para orientações detalhadas.
