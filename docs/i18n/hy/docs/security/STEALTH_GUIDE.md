OmniRoute-ը ինտեգրվում է այն մատակարարների հետ, որոնց եզրային համակարգերն ակտիվորեն մատնահետքում են ոչ պաշտոնական հաճախորդներին (TLS JA3/JA4, վերնագրերի հերթականություն, JSON մարմնի կառուցվածք, ամբողջականության թոքեններ)։ Այս էջը նկարագրում է OmniRoute-ի տրամադրած քողարկման մակերեսները և դրանց իրականացման վայրերը։

## Իրավական և էթիկական ծանուցում

Քողարկման գործառույթները նախատեսված են, որպեսզի OmniRoute-ը կարողանա ծառայել որպես համատեղելիության շերտ՝ օգտատերերին պատկանող պաշտոնական հաշիվների (Claude Code CLI, Codex, Antigravity, Cursor և այլն) և OmniRoute-ի միասնական API-ի միջև։ Դրանք **նախատեսված չեն** խարդախության հայտնաբերումը շրջանցելու, հավատարմագրերը համօգտագործելու կամ մատակարարի Ծառայությունների մատուցման պայմանները խախտելու համար։ Սպասարկողները ակնկալում են, որ օպերատորները կհետևեն հաշիվներ ստեղծելիս իրենց ընդունած վերին հոսքի ToS-ին։

## TLS մատնահետքերի շերտ

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Մշտական `wreq-js` աշխատաշրջանները ծուլորեն ստեղծվում են յուրաքանչյուր հաշվի տիրույթի և որոշված պրոքսիի համար։ Ամբողջ գործընթացի համար նախատեսված `TlsClient`-ը պահոցում պահում է առավելագույնը 128 աշխատաշրջան, որոնք Cloudflare-ի հետևում գտնվող վերին հոսքերի համար նմանակում են **Chrome 124-ը macOS-ում**։ `TlsClient.fetch()`-ը փակ ռեժիմով ձախողվում է, երբ նատիվ գործարկման միջավայրն անհասանելի է․ կանչող կողմը կարող է բացահայտորեն ընտրել հետադարձ տարբերակ այս փաթաթիչից դուրս։

- Աշխատաշրջանի պրոֆիլ՝ `browser: "chrome_124", os: "macos"`
- Պրոքսիի որոշում (ըստ առաջնահերթության)՝ `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (նաև փոքրատառ տարբերակները)
- Սպասման սահմանաչափ՝ `TLS_CLIENT_TIMEOUT_MS` (ժառանգվում է `FETCH_TIMEOUT_MS`-ից, լռելյայն՝ 600000)
- `wreq-js` Response-ը համատեղելի է fetch-ի հետ (`headers`, `text()`, `json()`, `clone()`, `body`)։
- Առաջին բայթի վերահսկիչ (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656)․ `TlsClient.fetch()`-ը
  ավարտվում է, հենց որ վերին հոսքի վերնագրերը հասնում են, ուստի միայն `TLS_CLIENT_TIMEOUT_MS`-ը չի կարող սահմանափակել
  մարմինը, որը երբեք առաջին բայթ չի տրամադրում։ `guardTlsFirstByte()`-ը մարմնի առաջին `read()`-ը
  մրցակցեցնում է `TLS_FIRST_BYTE_WATCHDOG_MS`-ի հետ (լռելյայն՝ `10000`, `0`-ն անջատում է այն)․ առողջ մարմնի վրա
  դա չի ազդում, իսկ կասեցված մարմնի դեպքում չեղարկվում է wreq ընթերցիչը, և `proxyFetch`-ի՝ TLS-ի համար արդեն գոյություն ունեցող
  հետադարձ տրամաբանությունը շարունակում է աշխատանքը ուղիղ/պրոքսի դիսպետչերի միջոցով (կրկնակի ուղարկման համար ոչ անվտանգ հարցումը, օրինակ՝
  մարմնով POST-ը, միևնույն է, սխալ է նետում՝ լուռ կրկնվելու փոխարեն)։

### Վեբ-քուքիների մատակարարի փոխադրում — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts`-ը ստորև ներկայացված հինգ մասնագիտացված
վեբ-քուքիների փոխադրումների ընդհանուր ադապտերն է։ Յուրաքանչյուր բարակ մատակարարի փաթաթիչ ընտրում է դիտարկիչի/ՕՀ-ի պրոֆիլ։ Ադապտերն
օգտագործում է `open-sse/utils/tlsClient.ts`-ի միակ wreq գործարկման միջավայրի բեռնիչը և փոխադրումների պահոցը՝
բանալին կազմելով պրոֆիլից + ՕՀ-ից + որոշված պրոքսիից, մինչդեռ յուրաքանչյուր հարցում օգտագործում է `cookieMode: "ephemeral"`։ Հետևաբար հաշիվներն ու
հարցումները համատեղ օգտագործում են փոխադրման մակարդակի կապերը, բայց երբեք՝ wreq աշխատաշրջանը կամ քուքիների պահոցը։

| Մատակարար  | Պրոֆիլ        | Նմանակված ՕՀ | Հոսքի EOF-ի քաղաքականություն               |
| ---------- | ------------- | ------------ | ------------------------------------------ |
| Claude     | `chrome_146`  | Linux        | ներառել `[DONE]`                           |
| Perplexity | `firefox_151` | macOS        | ներառել `event: end_of_stream`             |
| Grok       | `chrome_146`  | Linux        | բացառել `[DONE]`                           |
| Notion     | `chrome_146`  | Windows      | ներառել `[DONE]`                           |
| LMArena    | `chrome_146`  | Windows      | առանց վերջանիշի․ փակել նատիվ EOF-ի դեպքում |

- Հոսքային փոխանցումն անմիջապես սպառում է նատիվ պատասխանի `ReadableStream`-ը․ ժամանակավոր ֆայլ կամ օժանդակ
  գործընթաց չի ստեղծվում։
- Մինչև հոսքը հասանելի դարձնելը ստուգվում են սկզբնական առավելագույնը 256 բայթերը։ SSE մատակարարները բուֆերացնում են ոչ SSE
  սխալները․ Grok/LMArena-ն Cloudflare-ի ստուգումները վերագրում է `403`-ին, իսկ HTML միջանկյալ էջերը՝ `502`-ին։
- Նատիվ հարցման սպասման սահմանաչափը շարունակում է փաթաթված մնալ JS-ի բացարձակ վերջնաժամկետով։ Կախվելը անվավեր է դարձնում
  և փակում է միայն տվյալ պրոֆիլի/ՕՀ-ի/պրոքսիի փոխադրումը, նախքան հաջորդ հարցումը կվերստեղծի այն։
- Պրոքսիի որոշման առաջնահերթությունը հետևյալն է՝ յուրաքանչյուր կանչի `proxyUrl` → հարցման տիրույթով սահմանափակված հաշվի/կառավարման վահանակի համատեքստ →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (ներառյալ փոքրատառ տարբերակները)։ Որոշման սխալները փակ ռեժիմով
  ձախողվում են՝ ուղիղ կապի արտահոսքի փոխարեն։ LMArena-ն միտումնավոր կատարում է որոշումը `arena.ai`-ի նկատմամբ։
- `byteResponse`-ը վերադարձնում է բովանդակության տեսակ պարունակող `data:` URL՝ առանց UTF-8-ի աղավաղման։
- Սխալներն են՝ `TlsClientUnavailableError` (փաթեթը/հավելումն անհասանելի է), `TlsClientHangError`
  (վերջնաժամկետը գերազանցվել է) և `WreqTransportCapacityError` (աշխատաշրջանների ընդհանուր տարողության սխալի կոդը),
  երբ պրոֆիլի/ՕՀ-ի/պրոքսիի բոլոր 128 սահմանափակ տեղերը ակտիվ են կամ փակման փուլում։

Վերևի ընդհանուր նշանակության `TlsClient` աշխատաշրջանը շարունակում է մասնագիտացված մնալ դիտարկիչով ապահովվող քուքիների
մշտական վիճակի համար։ Երկու ուղիներն էլ վերօգտագործում են մեկ քեշավորված wreq մոդուլի բեռնիչ և գործընթացի կենսացիկլի կեռիկ․ դրանց պահոցները մնում են
առանձին, քանի որ քուքիների կենսաժամկետները միտումնավոր տարբեր են։

Պրոֆիլներն աջակցվում են ամրագրված փաթեթի կողմից, սակայն իրական WAF-ի ընդունումը կարող է փոխվել տեղական
պայմանագրային թեստերից անկախ։ Մատնահետքերի փոփոխությունները ստուգեք բացահայտորեն լիազորված իրական հաշվի միջոցով՝
նախքան վերին հոսքի դիտարկիչի հետ համարժեքություն պնդելը։

## Claude Code-ի քողարկման փաթեթ

Երբ `cliCompatMode`-ը միացված է, OmniRoute-ը վերաձևավորում է ելքային Claude հարցումները, որպեսզի դրանք չտարբերվեն `claude-cli` թրաֆիկից։ Համագործակցում են երեք մոդուլներ․

### `claudeCodeFingerprint.ts`

Հաշվում է վճարումների վերնագրում ներդրված 3-նիշանոց `cc_version` մատնահետքը․

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (կոշտ կոդավորված է, համապատասխանում է պաշտոնական հաճախորդին)
- Մուտքային տվյալներ՝ օգտատիրոջ առաջին հաղորդագրության տեքստի 4, 7 և 20 ինդեքսներում գտնվող նիշերը + տարբերակի տողը
- Ելքային տվյալ՝ 3-նիշանոց տասնվեցական նախածանց

### `claudeCodeCCH.ts` (Հաճախորդի բովանդակության հեշ)

Սերվերային ամբողջականության ստուգում, որը պաշտոնական Claude Code CLI-ն հաշվարկում է Bun/Zig-ի միջոցով։ OmniRoute-ը դա վերաիրականացնում է `xxhash-wasm`-ով․

1. Սերիականացնել մարմինը՝ օգտագործելով `cch=00000;` տեղապահը
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. Ձախից զրոներով լրացված, փոքրատառ 5-նիշանոց տասնվեցական արժեք
4. Փոխարինել `cch=00000;`-ը հաշվարկված թոքենով

Հաստատուններ․

- Սերմ՝ `0x6e52736ac806831e`
- Կաղապար՝ `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

«Զգայուն» հաճախորդների անունների առաջին նիշից հետո տեղադրում է Unicode-ի **զրոյական լայնությամբ միացնող** (`U+200D`), որպեսզի վերին հոսքի զտիչները չկարողանան դրանք գտնել grep-ով։ Լռելյայն բառացանկը՝

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Կիրառվում է՝ `system` բլոկների, բոլոր `messages[].content`-ների և `tools[].description` / `tools[].function.description`-ների նկատմամբ։ Օպերատորը կարող է վերասահմանել `setSensitiveWords()`-ի միջոցով։

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` մատակարարներ

Երրորդ կողմի Anthropic ռելեների համար, որոնք ընդունում են միայն «իրական Claude Code» թրաֆիկ․

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- Լռելյայն՝ `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- Յուրաքանչյուր կապի «Միացնել redact-thinking բետան» փոխարկիչն ավելացնում է `redact-thinking-2026-02-12`, երբ CC Compatible վերին հոսքը հատուկ պահանջում է խմբագրված մտածողության հոսքեր
- Յուրաքանչյուր կապի «Միացնել ամփոփ մտածողության ցուցադրումը» փոխարկիչը պահպանում է `providerSpecificData.requestDefaults.summarizeThinking`-ը և ավելացնում `display: "summarized"` այն CC Compatible մտածողության հարցումներին, որոնցում ցուցադրման ռեժիմն արդեն սահմանված չէ
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x ընտանիք)
- Լռելյայն ուղի՝ `/v1/messages?beta=true`

Նույն փաթեթի հարակից մոդուլները․

- `claudeCodeConstraints.ts` — ջերմաստիճանի + cache-control-ի կանոններ
- `claudeCodeToolRemapper.ts` — գործիքների անունների վերաքարտեզագրում
- `claudeCodeExtraRemap.ts` — լրացուցիչ օգտակար բեռի նորմալացում

## Antigravity Stealth

Antigravity հարցումները պահպանում են զանգահարողի տեքստը բայթ-բայթ: OmniRoute զրոյական լայնությամբ նիշեր չի տեղադրում հուշումների կամ rename/inject գործիքների մեջ՝ IDE հաճախորդին ընդօրինակելու համար:

### `antigravityHeaderScrub.ts`

Շերտավորեք չժանգոտվող SDK մարկերները (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) նախքան վերահասցեավորումը։

### ⚠️ Ռիսկ. `ANTIGRAVITY_CREDITS=always` (հաշվի արգելման թեժ կետ)

`ANTIGRAVITY_CREDITS=always` (սպառվում է `open-sse/executors/antigravity.ts`) երթուղիներով** ամեն** խնդրեք Antigravity AI Credit Overages-ի միջոցով (վճարված Google վարկեր)՝ Google ի ազատ մակարդակի քվոտաները բաց թողնելու փոխարեն: Սա փաստագրված է որպես հատկանիշ, բայց այդպես է** ToS-ի խախտման միակ ամենատարածված զեկույցը, որը մենք տեսնում ենք** — մի քանի Google Ultra հաշիվներն արգելվել են `403 / "service disabled for ToS violation" / insufficient_quota` ով `=always` ով մի քանի ժամ աշխատելուց հետո:

Վերին հոսանքի կիրառումը միացված է**Google ի կողմը** , ոչ մի բան OmniRoute կարող է կանխել. env var անվանումը և առկա փաստաթղթերը ստիպում են այն հնչել որպես անվտանգ կոճակ՝ շրջելու համար. դա չէ:

**Ինչու՞ սա ավելի ագրեսիվ է դարձնում չարաշահումների հայտնաբերումը, քան միայն անվճար մակարդակի օգտագործումը.**

- Կայուն ավտոմատացված ծախսերը մեկ Google հաշվի վրա տարբերվում են, քան անվճար մակարդակի հիթեր-քվոտա-և-դադարները:
- Վարկային գերավճարները չունեն տոկոսադրույքի առաստաղ, ուստի սխալ կազմաձևված հաճախորդը կարող է րոպեների ընթացքում այրել մի քանի հարյուր USD և նմանվել API-բանալու վերավաճառքին կամ բոտի տրաֆիկին:
- Մի քանի OmniRoute օգտատերեր, որոնք միաժամանակ միևնույն արտաքին IP ից ստանում են ավելորդ վարկեր, միացնում են ազդանշանը:

**Առաջարկվող կեցվածքը.**

1. Պահպանեք լռելյայն `ANTIGRAVITY_CREDITS=off` քանի դեռ օպերատորը բացահայտորեն չի ընդունում վճարովի վարկի և հաշիվների կատարման ռիսկը: `retry` սկզբում ուղարկում է սովորական հարցումը և ներարկում է կրեդիտներ առավելագույնը մեկ անգամ՝ համապատասխան քվոտայից հետո՝ 429; `always` վարկեր է ներարկում առաջին իսկ խնդրանքով:
2. **Տարածեք բեռը մատակարարների վրա Auto-Combo-ի միջոցով** (`model: "auto"` կամ `kr/glm/etc` -combo) մեկ Antigravity հաշիվը հագեցնելու փոխարեն։
3. **Սահմանեք RPM ի մեկ կապի սահմանները** Antigravity մատակարարի խմբագրման էջում (Dashboard → Providers → Antigravity → կապի → տոկոսադրույքի սահմանաչափ): 30–60 RPM ը պաշտպանելի վերին սահման է՝ կայուն օգտագործման համար:
4. **Օգտագործեք կայուն, օպերատորի կողմից վերահսկվող վերին հոսքի ցանց** և խուսափեք մեկ հաշիվ կիսելուց ոչ կապակցված օգտատերերի կամ աշխատանքային ծանրաբեռնվածության հետ:
5. **Եթե արգելվի** Բողոքարկում `support.google.com` → միջոցով «Վերականգնել Workspace/Account մուտքը» Google `quota_exceeded` / `service disabled` պատասխանի ճշգրիտ մարմնի միջոցով: Վերականգնումը երաշխավորված չէ։

Շրջակա միջավայրի տեղեկանքը փաստաթղթավորում է յուրաքանչյուր վարկային ռեժիմի հաշվի և ծախսերի հետևանքները:

#### Ոչ միայն `=always`. Antigravity OAuth երթուղավորում ընդհանրապես

Կասեցումները չեն սահմանափակվում միայն վարկային գերակատարումներով։ 2026 թվականի նոյեմբերի հաշվետվությունները (#19223, #19266) նկարագրում են մի քանի Google հաշիվներ, որոնք կասեցվել են `antigravity` և `agy` (Antigravity CLI) պրովայդերների միջոցով երթուղի անցնելիս՝

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

Երկու մատակարարներն էլ նույնականացնում են Antigravity արտադրանքի OAuth նիստի միջոցով, ինչի մասին զգուշացնում է վահանակի ռիսկի ծանուցումը («Այս մատակարարն օգտագործում է ձեր պաշտոնական session/OAuth արտադրանքը, որը լիազորված չէ proxy/router օգտագործման համար») նախազգուշացնում է կապի ավելացումից առաջ: Վերոնշյալ առաջարկություններից ոչ մեկը թույլ չի տալիս այդ օգտագործումը. նրանք միայն նվազեցնում են, թե որքան տրաֆիկ է կրում մեկ հաշիվը:

**Լիազորված API միջերեսներ Gemini մոդելների համար:** Google առաջարկում է ծրագրային մուտք դեպի Gemini իր APIs միջոցով, որը OmniRoute աջակցում է որպես սովորական API-բանալների մատակարարներ.

| Մատակարարի ID | Վահանակի անունը            | Հավատարմագիր                                                                     |
| ------------- | -------------------------- | -------------------------------------------------------------------------------- |
| `gemini`      | Gemini (Google AI ստուդիա) | Gemini API բանալի Google AI ստուդիայից (անվճար մակարդակ հասանելի է)              |
| `vertex`      | Vertex AI                  | Ծառայության հաշիվ JSON, OAuth մուտքի նշան կամ Vertex Express API բանալի (Gemini) |

Այս պրովայդերները օգտագործում են հավատարմագրերի Google հարցեր API մուտքի համար, ի տարբերություն Antigravity արտադրանքի նիստի: Նրանք բոլոր օգտագործումը չեն համապատասխանում կամ վերացնում կիրառման ռիսկը. յուրաքանչյուրը ղեկավարվում է իր պայմաններով, որոնք օպերատորը պետք է ստուգի դրանց տեղակայման համար: Օրինակ, [Gemini API Ծառայությունների լրացուցիչ պայմանները](https://ai.google.dev/gemini-api/terms) թույլատրում են միայն Վճարովի ծառայությունները, երբ API հաճախորդները հասանելի են դառնում Եվրոպական տնտեսական տարածքում, Շվեյցարիայում կամ Միացյալ Թագավորության օգտատերերին, և Չվճարված ծառայություններին ուղարկված բովանդակությունը կարող է օգտագործվել Google ի արտադրանքը բարելավելու համար: Vertex AI ընկնում է Google Cloud-ի պայմանների փոխարեն ( [Ծառայության հատուկ պայմաններ](https://cloud.google.com/terms/service-terms) ): Գները և քվոտաները հետևում են այդ API պայմաններին, այլ ոչ թե Antigravity բաժանորդագրությանը:

Օպերատորները, ովքեր ցանկանում են խուսափել վերը նկարագրված Antigravity կասեցումներից, պետք է Gemini երթևեկությունը անցնեն այս մատակարարներից մեկի միջոցով `antigravity` / `agy` փոխարեն՝ ստուգելուց հետո, որ դրանց օգտագործումը համապատասխանում է մատակարարի պայմաններին:

Հպման կետեր.

- `open-sse/executors/antigravity.ts` — կարդում է `process.env.ANTIGRAVITY_CREDITS`
- `src/lib/oauth/providers/antigravity.ts` — հավատարմագրային սանտեխնիկա
- Միջադեպի սկզբնական զեկույց. Քննարկում [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## CLI մատնահետքերի ռեեստր — `open-sse/config/cliFingerprints.ts`

Յուրաքանչյուր մատակարարի համար նախատեսված աղյուսակ, որն ամրագրում է պաշտոնական CLI-ների mitmproxy հետքերից ստացված վերնագրերի և JSON մարմնի դաշտերի դասավորության **ճշգրիտ** հերթականությունը։ Ներկայում գրանցված են՝ `codex`, `claude`, ինչպես նաև `providerHeaderProfiles.ts`-ում կատարման ժամանակ ձևավորվող պրոֆիլները՝ `antigravity`-ի և `github`-ի համար։

```ts
interface CliFingerprint {
  headerOrder: string[]; // մեծատառերի և փոքրատառերի նկատմամբ զգայուն
  bodyFieldOrder: string[]; // JSON-ի վերին մակարդակի բանալիներ
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Յուրաքանչյուր մատակարարի համար միացրեք կամ անջատեք env-ի միջոցով (տե՛ս ստորև)։ Անջատված լինելու դեպքում վերնագրերը/մարմնի բանալիները հայտնվում են Node/JSON-ի տրամադրած ցանկացած հերթականությամբ, ինչը հեշտացնում է մատնահետքի որոշումը։

## MITM պրոքսի (Antigravity, Linux/macOS/Windows)

Այն CLI-ների համար, որոնց երկուական ֆայլերը հնարավոր չէ վերահղել `OPENAI_BASE_URL`-ի միջոցով, OmniRoute-ը գործարկում է տեղային TLS-ն ավարտող պրոքսի։ Վերջնակետերը գտնվում են `src/app/api/cli-tools/antigravity-mitm/`-ի ներքո։

| Մեթոդ  | Վերջնակետ                               | Նպատակ                                                   |
| ------ | --------------------------------------- | -------------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | Կարգավիճակ՝ running, pid, dnsConfigured, certExists      |
| POST   | `/api/cli-tools/antigravity-mitm`       | Գործարկել MITM-ը (պահանջում է `apiKey` + `sudoPassword`) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | Կանգնեցնել MITM-ը                                        |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | Թվարկել մոդելների այլանունները                           |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | Պահպանել գործիքի մոդելների այլանունները                  |

Ընդհատվող նպատակային հոսթ՝ **`daily-cloudcode-pa.googleapis.com`** (Antigravity-ի վերին հոսքի ծառայությունը)։

### Գործարկման հաջորդականություն (`src/mitm/manager.ts::startMitm`)

1. Ստեղծել ինքնաստորագրված վկայագիր `selfsigned`-ի միջոցով (RSA-2048, SHA-256, 1 տարի) — `cert/generate.ts`
2. Տեղադրել վկայագիրը համակարգի վստահության պահոցում — `cert/install.ts`
3. Ավելացնել hosts գրառում՝ `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. Գործարկել `src/mitm/server.cjs`-ը՝ `ROUTER_API_KEY` + `MITM_LOCAL_PORT`-ով (լռելյայն՝ `443`)
5. Պահպանել PID-ը `<DATA_DIR>/mitm/.mitm.pid`-ում

### Linux-ի վստահության պահոցի դինամիկ հայտնաբերում — `cert/install.ts`

`getLinuxCertConfig()`-ը հերթով ստուգում է առաջնահերթությունների ցանկը և ընտրում առաջին գոյություն ունեցող գրացուցակը։

| Դիստրիբուտիվների ընտանիք | Գրացուցակ                                   | Թարմացման հրաման         |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Վկայագրի ֆայլի անուն՝ `omniroute-mitm.crt`։ Մատնահետքի համընկնումը կատարվում է `getCertFingerprint()`-ի միջոցով (DER-ի SHA-1)։

Բացի այդ, երբ հասանելի է `certutil`-ը, `updateNssDatabases()`-ը վկայագիրը տեղադրում է յուրաքանչյուր օգտատիրոջ NSS տվյալների բազաներում՝ `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, Firefox-ի բոլոր պրոֆիլներում (ներառյալ snap-ը), **`OmniRoute MITM Root CA`** մականվամբ։

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** բարձրացված արտոնություններով PowerShell → `certutil -addstore Root`

### Նույնականացում

Բոլոր MITM վերջնակետերը պահանջում են կառավարման նույնականացում (`requireCliToolsAuth`)։ sudo գաղտնաբառը քեշավորվում է մոդուլի տիրույթում (երբեք ոչ `globalThis`-ում) և մաքրվում է `stopMitm()`-ի ժամանակ։

## Մուտքային վերնագրերի մաքրում

OmniRoute-ը փոխանցելուց առաջ մաքրում է հաճախորդի մուտքային վերնագրերը, որպեսզի Cursor-ից ստացված հարցումը Claude-ի վերին հոսքին չբացահայտի `User-Agent: Cursor/X.Y.Z`-ը։ Արգելացանկը տե՛ս `src/shared/constants/upstreamHeaders.ts`-ում. այն համաժամեցված է Zod սխեմաների և միավորային թեստերի հետ։

## Մատնահետքերի թարմացում, երբ մատակարարը դրանք փոխում է

1. Գրանցեք պաշտոնական CLI-ի թրաֆիկը `mitmproxy`-ով (TLS գաղտնազերծում + արտահանում)
2. Դուրս բերեք JA3/JA4-ը և վերնագրերի ճշգրիտ հերթականությունը
3. Թարմացրեք համապատասխան `CLI_FINGERPRINTS[...]` գրառումը
4. Թարմացրեք համապատասխան `*_USER_AGENT` լռելյայն արժեքը `.env.example`-ում
5. Եթե փոխվել է հենց TLS ձեռքսեղմումը, թարմացրեք համապատասխան մատակարարի փաթեթավորիչը կամ wreq-js-ի `browser:` տարբերակը
6. Գործարկեք մատակարարին հատուկ TLS թեստերը և ձեռքով փորձնական ստուգում կատարեք գործող մատակարարի նկատմամբ
7. Թողարկեք շտկումային տարբերակով. փաստագրեք `CHANGELOG.md`-ում
