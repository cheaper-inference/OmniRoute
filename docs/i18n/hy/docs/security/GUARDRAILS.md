> **Վերջին թարմացումը՝** 2026-10-17 — v3.8.52 (ավելացվել է [Ծածկույթ և սահմանափակումներ](#coverage-and-limits) բաժինը՝
> նշելով, թե որպիսի երթուղիների և պատասխանի ուղիների են հասնում հուքերը, միավորված անջատման վերնագրերը (#16412), ներմուծման
> արգելափակման ռեժիմը՝ որպես պարտադիր սահմանագիծ (#16413), և թե ինչն է տեսնում պատասխանը հետկանչից առաջ)

Պաշտպանիչ սահմանափակումներն ապահովում են անվտանգությունը, քաղաքականությունների կիրառումը և բովանդակության փոխակերպումները
OmniRoute-ի ու վերին մակարդակի մատակարարների միջև սահմանագծում։ Յուրաքանչյուր պաշտպանիչ սահմանափակում կարող է ստուգել (և
ըստ անհրաժեշտության մերժել, փոխակերպել կամ ծանոթագրել) հարցման տվյալները (`preCall`) և
վերին մակարդակից ստացված պատասխանները (`postCall`)։

Համակարգը գործում է **fail-open** սկզբունքով․ եթե պաշտպանիչ սահմանափակումը կատարման ընթացքում բացառություն է նետում, ռեեստրը
գրանցում է սխալը և հարցումը ձախողելու փոխարեն շարունակում է հաջորդ պաշտպանիչ սահմանափակման կատարմամբ։
Արգելափակումը հստակ որոշում է (`block: true`) և երբեք պատահականություն չէ։
Միակ բացառությունը չեղարկված հարցումն է․ երբ կանչողի `signal`-ը չեղարկված է,
բացառություն նետող պաշտպանիչ սահմանափակումը բաց թողնվելու փոխարեն մերժում է հուքի կատարումը։

Հուքերը **չեն** գործարկվում բոլոր երթուղիներում կամ բոլոր պատասխանների համար։ Նախքան պաշտպանիչ սահմանափակումը որպես
անվտանգության վերահսկիչ միջոց կիրառելը կարդացեք [Ծածկույթ և սահմանափակումներ](#coverage-and-limits) բաժինը։

### Vision Bridge (`visionBridge.ts`) — Modality Bridge PR-1

GLM 5.3 բազային մոդելը և `glm-5.3-{low,high,max}` ունեն հստակ `supportsVision:false` registry/spec մետատվյալներ: GLM 5.3 Flash տարբերակները մնում են հայրենի տեսողության մոդելներ: Claude Code-ի `/v1/messages` երթուղին մտնում է ընդհանուր `handleChat` նախնական զանգի պահակային շղթա** առաջ** Claude-to-OpenAI թարգմանություն; Ներդրված `Read` գործիքի արդյունքների պատկերները պետք է նկարագրվեն կամ մշակվեն, նախքան թարգմանությունը դրանք վերածի OpenAI `image_url` բովանդակության (#17069):

Ընդհատում է պատկերներ կրող հարցումները, որոնք ուղղված են** ոչ տեսողական մոդելներ** և կամ վերաուղղորդում է ամբողջ հարցումը դեպի տեսողություն ունեցող մոդել, կամ փոխարինում է պատկերի մասերը տեքստային նկարագրություններով, որոնք արտադրվել են կարգավորելի տեսողության մոդելի կողմից մինչև վերին հոսքի զանգը: Սա թույլ է տալիս միայն տեքստային մատակարարներին թափանցիկ կերպով կառավարել բազմամոդալ ծանրաբեռնվածությունը:

Հոսք:

1. Բաց թողնել, եթե թիրախային մոդելն արդեն աջակցում է տեսլականին (եթե այն չի երևում պարտադիր կամուրջների ցանկում `isVisionBridgeForcedModel`):
2. Արտահանեք պատկերի մասերը `extractImageParts(messages)` (`visionBridgeHelpers.ts`) միջոցով, որը պատվիրակում է** միասնական մեդիա դետեկտոր** `detectMediaParts()` ն `open-sse/utils/mediaParts.ts` — ում ճշմարտության միակ աղբյուրն է, որը համօգտագործվում է համատեղելիության ֆիլտրի հետ: Արդյունահանումը թույլատրված է այն ձևերին, որոնք `replaceImageParts` կարող է միաձուլվել (քաղվածքը ↔ փոխարինում է պայմանագրին). OpenAI `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"` և պատասխաններ API `input_image`: Claude Code `tool_result.content` ի և Responses գործիքի ելքերում տեղադրված համապատասխան պատկերները նույնպես հանվում և փոխարինվում են իրենց սկզբնական ուղիներով. Միայն ցուցիչով ձևերը համակցված զտիչ նյութ են և չեն արդյունահանվում: Բաց թողնել, եթե ոչ մեկը չի գտնվել:
3. Լուծել գործարկման ժամանակի կազմաձևը `resolveVisionBridgeRuntimeSettings()` միջոցով (`src/shared/constants/modalityBridgeDefaults.ts`). նոր `modalityBridge*` կարգավորումների ստեղները հաղթելու են; ժառանգական `visionBridge*` ստեղները մնում են ա** մեկ ցիկլով հետադարձ** (հետադարձ պատուհան): Բաց թողնել ցանկացած մեդիա անցում, երբ կամուրջն անջատված է:
4. Ռեժիմի ընտրիչը (`modalityBridgeVisionMode`, տե՛ս ստորև բերված աղյուսակը) որոշում է վերափոխումը և նկարագրությունը: Reroute-ը վերադարձնում է `modifiedPayload` միայն `model` փոխանակմամբ, գումարած meta `{ rerouted, fromModel, toModel, imagesKept }`:
5. Նկարագրեք ուղին. կափարիչ պատկերներ `maxImages` ում, կազմեք առաջադրանքի տեղյակ հուշումը, խորհրդակցեք նկարագրության քեշի հետ, զանգահարեք տեսողության մոդելը** զուգահեռաբար** (`Promise.allSettled`), և դրանց տեղում ներարկեք `[Image N]: <description>` տեքստային մասեր: Անհաջող նկարագրությունը տալիս է `null`. չմշակված պատկերը պահպանվում է unknown/vision-capable թիրախների համար (#4012), բայց a** հաստատված է միայն տեքստային ուղղակի թիրախ** կամ zero-vision կոմբինատը ստանում է բացահայտ `(unavailable — no vision-capable provider connected)` տեքստի կոճղ յուրաքանչյուր չնկարագրված պատկերի համար, ներառյալ մասնակի ձախողումները և նկարագրության զանգի գլխարկից դուրս գտնվող պատկերները (#17069): Գոյություն ունեցող բոլոր ձախողված կոմբինատի նկարագրությունը մնում է տեղում (#8430):
6. Վերադարձեք `modifiedPayload` + meta (`imagesProcessed`, `descriptions`, `processingTimeMs`, `visionModel`).

| `auto`     | ✔          | Legacy heuristic, untouched (#6640/#7204). ոչ համակցված/`auto/` մոդելները վերափոխվում են դեպի լավագույն տեսողության մոդելը, եթե սկզբնական մոդելն արդեն չունի օգտագործելի հավատարմագրեր (այնուհետև նկարագրեք); համակցված թիրախները միշտ նկարագրում են:                          |
| `describe` |            | Միշտ նկարագրեք — վերերթուղու բլոկն ամբողջությամբ բաց է թողնվել. օգտատիրոջ ընտրած մոդելը միշտ պատասխանում է.                                                                                                                                                                    |
| `reroute`  |            | Հարկադիր վերափոխում. պահապանը շրջանցվում է: Վերափոխումը -** թիրախ** հավատարմագրային պահակախումբը դեռևս կիրառում է — երբ չկա օգտագործելի տեսողության թիրախ, կամուրջը արգելափակում է հստակ սխալով, այլ ոչ թե հում պատկերները նկարագրելով կամ ուղարկելով միայն տեքստային թիրախին: |

Հարկադիր ռեժիմների կարճ միացում** առաջ** ավտոմատ էվրիստիկ վազք; `auto` վարքագիծը բայթ-նույնական է pre-PR-1 ի պաշտպանիչ բազրիքին:

#### API-բանալու շրջանակ (`visionBridgeKeyScope.ts`)

Երբ զանգահարողի API ստեղնը սահմանափակում է `allowedConnections`, քվոտա լողավազաններ (`allowedQuotas`) կամ մոդելներ (`allowedModels` / `blockedModels` / `modelAccessMode: "restricted"` / `disableNonPublicModels`), կամուրջը ընտրում է միայն վերափոխման երթուղին և նկարագրում է այն մոդելները, որոնք կարող է օգտագործել բանալին, իսկ միացումների վրա՝ բանալին կարող է օգտագործել: Այնուհետև նկարագրված զանգը միշտ անցնում է OmniRoute ինքնահոսքի միջով `x-omniroute-self-loop-key-id` վերնագրով, այնպես որ ստացող զրույցի հարցումը նորից կիրարկում է այդ բանալու կապը և մոդելի քաղաքականությունը: `enforceApiKeyPolicy()` հարգում է այդ վերնագիրը միայն ինքնահանգուցային կրիչի հետ միասին, ուստի այն կարող է միայն նեղացնել մուտքը, և id-ն, որը չի լուծվում, մերժվում է:

Եթե տեսողության ոչ մի մոդել չի թույլատրվում բանալին, ա** հաստատված միայն տեքստային թիրախ** մերժում է պատկերի հարցումը լոկալ՝ հստակ HTTP 400-ով, փոխարենը պատկերի բայթերը փոխանցելու անկարող հոսանքին (#17069): Անհայտ կամ բնիկ տեսողության հնարավորություն ունեցող թիրախների համար նկարագրության ուղին պահպանում է իր նախկին վարքագիծը խափանման պատճառով (meta `{ skipped: true, reason: "no_permitted_vision_model" }`): Առանց բանալիի հարցումները և առանց այս սահմանափակումների բանալիներն իրենց պահում են ճիշտ այնպես, ինչպես նախկինում:

#### Առաջադրանքների տեղյակ նկարագրության հուշում (`modalityBridgeVisionTaskAware`)

Կանխադրված** ճշմարիտ** . `composeVisionPrompt()` (`visionBridgeHelpers.ts`) կցում է տեքստը** վերջին օգտվողի հաղորդագրությունը** (կտրված է 500 նիշով) բազային նկարագրության հուշումը՝ ուղղորդելով նկարագրությունը դեպի այն, ինչ իրականում խնդրել է օգտատերը (codex-vision-proxy pattern) և խնդրելով տեսողության մոդելին արտագրել տեսանելի տեքստը: Եթե դրոշն անջատված է — կամ ոչ օգտվողի տեքստ — բազային հուշումն օգտագործվում է անփոփոխ:

Նկարագրված ինքնակարգավորման սեփական OpenAI-ի հետ համատեղելի հարցումը (`callVisionModelSingle()` in `visionBridgeHelpers.ts`) միշտ պահանջում է `image_url.detail: "high"` — անվերապահորեն, յուրաքանչյուր caller/provider համար, որը փակված չէ որևէ հաճախորդի ազդանշանի վրա: Ցածր մանրամասների նմուշառումը նվազեցնում է OCR ճշգրտությունը հենց տեքստի տառադարձման առաջադրանքի համար, որը պահանջում է այս հրահանգը, ուստի նկարագրության զանգն ինքնին միշտ պահանջում է բարձր մանրամասնություններ՝ անկախ նրանից, թե որ մանրամասների մակարդակն է օգտագործվել սկզբնական մուտքային հարցումը: Սա ազդում է միայն ներքին նկարագրության հարցման մարմնի վրա. այն չի փոխում, թե ինչպես է OmniRoute ուղարկում զանգահարողի սեփական `image_url.detail` — առաջնային հարցումով, որը լռելյայն կիրառվում է առանձին, և միայն հայտնաբերված OpenCode հաճախորդների համար՝ `defaultImageDetail()` ում (`open-sse/handlers/chatCore/upstreamBody.ts`): Describe self-loop-ի Anthropic լարային ձևաչափի ճյուղը չունի `detail` դաշտ և չի ազդում լռելյայն որևէ մեկի վրա:

#### Նկարագրեք ելքային գլխարկը (`modalityBridgeVisionMaxChars`)

| Բանալին                        | Կանխադրված | Շրջանակ           |
| ------------------------------ | ---------- | ----------------- |
| `modalityBridgeVisionMaxChars` | `0`        | `0` կամ 100–50000 |

`0` (կանխադրված) նշանակում է** ոչ մի գլխարկ** — `callVisionModel()` ի վերադարձած նկարագրությունը փոխանցվում է չփոփոխված՝ պահպանելով գոյություն ունեցող վարքագիծը: 100–50000 միջակայքի ցանկացած արժեք կրճատում է նկարագրությունը `…` վերջածանցով, նախքան այն ետ կցվում է որպես `[Image N]: <description>` (`VisionBridgeGuardrail.preCall()` in `src/lib/guardrails/visionBridge.ts`): Բարձրացրեք սա մանրամասներով ծանր OCR առաջադրանքների համար, որտեղ ներքևող մոդելին անհրաժեշտ է ամբողջական տառադարձում. իջեցրեք այն մինչև կապակցված նշանի օգտագործումը շատախոս տեսողության մոդելներում: Վահանակի դաշտը ապրում է Vision ներդիրի Ընդլայնված վահանակի վրա (`modality-bridge-max-chars` in `ModalityBridgeVisionTab.tsx`) և սեղմում է ցանկացած արժեք 1-ից 99-ի միջև մինչև 100 հարկ, մինչդեռ բացահայտ `0` անձեռնմխելի է թողնում — `0` ինքնին վավեր Zod արժեք է (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), ոչ միայն «չսահմանված» կանխադրվածը:

#### Նկարագրեք քեշը (`modalityBridge/bridgeCache.ts`)

Հիշողության մեջ LRU + TTL քեշը ելքերը նկարագրելու համար, ընդհանուր գործընթացում: Բանալի = `sha256(imageRef + composedPrompt + configuredBridgeModel)` երկարության նախածանցով շրջանակով (դաշտ-սահմանային բախումներ չկան): Մոդելի բաղադրիչն է** կազմաձևված** կամուրջի մոդելը, այլ ոչ թե այն մոդելը, որն իրականում պատասխանել է — `callVisionModel`, կարող է ներսից հետ ընկնել, և յուրաքանչյուր փորձի համար ստեղնավորումը մասնատում է քեշը: Չհաջողված նկարագրությունները երբեք չեն պահվում քեշում: Կարգավորումներ:

| Բանալին                         | Կանխադրված | Շրջանակ |
| ------------------------------- | ---------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`     | —       |
| `modalityBridgeCacheTtlMinutes` | `60`       | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`      | 10–5000 |

#### Հեռավոր պատկերի նորմալացում (self-loop describe/base64 fetch)

Երբ կամուրջը բերում է ա** հեռավոր** պատկերն ինքնին — the Anthropic նկարագրում է ինքնազանգը և claude-wire-format base64 փոխակերպումը (`ensureBase64ImagesForClaudeWire`), երկուսն էլ `fetchRemoteImageAsDataUri()` միջոցով `visionBridgeHelpers.ts` — ում ստացված տվյալները URI փոխանցվում են `normalizeDataUri()` (`open-sse/utils/imageNormalize.ts`) միջով, նախքան vision-model հարցումը ներկառուցվելը: Չափերի չափի պատկերները կրճատվում են a** 2048px երկար եզր** (համապատասխանում է չափափոխման գլխարկին OpenAI/Anthropic արդեն կիրառվում է սերվերի կողմից), որը կրճատում է վերբեռնումը bytes/latency առանց փոխելու այն, ինչ տեսնում է տեսողության մոդելը: Չափափոխումը օգտագործում է `sharp`, որը բեռնված է դինամիկ ներմուծման միջոցով. հարթակում, որտեղ նրա բնիկ երկուականը չի բեռնվում, `normalizeDataUri()`** երբեք չի նետում** — այն ետ է ընկնում դեպի սկզբնական բայթերի անցում, ուստի describe/base64-conversion ուղին միշտ շարունակում է աշխատել: Ոչ պատկերային բայթերը (վերբեռնում, որը չի վերադարձրել վերծանվող պատկեր) նույնպես փոխանցվում են անձեռնմխելի: Այս նորմալացումը նախատեսված է այն պատկերների համար, որոնք կամուրջը վերցնում է իր ինքնազանգման համար — այն երբեք չի կիրառվում զանգահարողի չմշակված անցումային ծանրաբեռնվածության վրա, որը համահունչ է միայն ընտրված մուտացիայի սկզբունքին (Hard Rule #20):

#### Կարգավորումների սխեման + միգրացիա

Նոր `modalityBridge*` ստեղները Zod-ով վավերացված են `updateSettingsSchema` (`src/shared/validation/settingsSchemas.ts`)՝ `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCache*` եռյակը և `modalityBridgeAudio*` խումբը, որն օգտագործվում է Audio Bridge-ի կողմից։ Միգրացիան `141_modality_bridge_settings.sql` պատճենում է գոյություն ունեցող `visionBridge*` արժեքները համապատասխան նոր ստեղների վրա (idempotent, երբեք չի վերագրում օպերատորի կողմից սահմանված `modalityBridge*` արժեքը); ժառանգական ստեղները մնում են ընդունված որպես մեկ թողարկման շրջանի ընթերցման հետադարձ կապ:

#### Թափանցիկության վերնագրի + վիճակագրություն

Նկարագրել-փոխակերպված պատասխանները կրում են `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` (կառուցված `buildModalityBridgeHeader()` ի կողմից `modalityBridge/bridgeStats.ts` ում, դրոշմված `withModalityBridgeHeader()` ով `src/sse/handlers/chatHelpers.ts` ում): Վերաուղղորդված հարցումները ստանում են** ոչ** վերնագիր — ծանրաբեռնվածությունն անձեռնմխելի էր, և մոդելի փոխանակումն արդեն տեսանելի է պատասխան մարմնի `model` դաշտում:

`GET /api/modality-bridge/stats` (կառավարման auth, նույն մակարդակը, ինչ `GET /api/settings`) վերադարձնում է հիշողության մեջ մեկ մոդալության հաշվիչներ `{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs, latencySamples, averageLatencyMs, lastUsedAt }` `vision`, `audio` և `video` համար: `averageLatencyMs` օգտագործում է `latencySamples`, ոչ բոլոր փորձերը, որպես իր հայտարար. առանց ժամանակացույցի գործողությունը չի ստեղծում զրոյական միլիվայրկյանանոց նմուշ: `bridged` մնում է հաջող փոխարկումների համար հետհամատեղելի կեղծանունը. ձախողված փորձերը չեն ավելացնում այն: Գործընթացի վերագործարկման ժամանակ հաշվիչները վերականգնվում են նախագծով (հեռաչափություն, ոչ հաշվառում):

#### Վահանակի կազմաձևում

Նվիրված վահանակի էջը `/dashboard/settings/modality-bridge` է: Դրա URL-հասցեավոր `Vision`, `Audio` և `Video` ներդիրները պահպանում են հարցման պարամետրերը `tab` արժեքը փոխելիս: Vision ներդիրը բացահայտում է միացումը, ռեժիմը, մոդելի ընտրությունը (ներառյալ ավտոմատ լռելյայն), առաջադրանքների մասին տեղեկացված հուշումները, timeout/image/description-length/cache առաջադեմ սահմանափակումները, գործարկման ժամանակի հաշվիչները և պահպանված նմուշի հարցումը: Աուդիո ներդիրը նույնպես ակտիվ է. այն բացահայտում է միացումը, միայն STT մոդելի ընտրիչը Auto-ով, timeout/max-clip սահմանաչափեր, աուդիո հաշվիչներ և `input_audio` նմուշի թեստ: «Վիդեո» ներդիրը գործում է. այն հայտնում է FFmpeg/ffprobe գործարկման վիճակի մասին — չորս հստակ UI վիճակներից մեկը (`unknown`, երբ զոնդը թռիչքի մեջ է կամ չի կարող ավարտվել, `restricted` ոչ շրջադարձային վահանակի հոսթինգի վրա, որտեղ զոնդը բաց է թողնվել հաճախորդի կողմից, `unavailable` մեկ անգամ զոնդավորվել և հաստատվել է, որ բացակայում է, կամ `available` — FFmpeg/ffprobe մոդելների ընտրողների տարբերակների համար): տեսողության enable/model/frame/video/timeout մոդելներ և բացահայտում է վիդեո հաշվիչները:

Նախկին Vision Bridge քարտը AI կարգավորումներում համատեղելիության հղում է դեպի նոր էջի; այն այլևս չունի ձևի երկրորդ օրինակը: Media Providers-ը նաև կապում է Image-to-Text և Speech-to-Text աշխատանքային հոսքերը համապատասխան Modality Bridge ներդիրներին՝ չհեռացնելով գոյություն ունեցող Speech-to-Text խաղահրապարակը:

**Self-loop ընդունման շրջանցում.** երբ նկարագրված զանգի երթուղիներն անցնում են OmniRoute ի սեփական `/v1` ինքնահանգույցով (ոչ ստանդարտ մատակարարի մոդել), ենթահարկն ուղարկում է `x-omniroute-admission-bypass: internal` և վավերացվում է լուծված ինքնահանգուցային հավատարմագրով — տեղական `sk_omniroute` sentinel-ը տեղական ռեժիմում կամ օպերատորի կողմից կազմաձևված `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` env ստեղնը (#1350) դեռ կարող է գործարկել `REQUIRE_API_KEY=true` զանգը: Շրջանցումը հարգվում է միայն այդ ճշգրիտ հավատարմագրերի համար, ուստի արտաքին հաճախորդները չեն կարող օգտագործել վերնագիրը՝ մուտքը բաց թողնելու համար:

Ժառանգական կանխադրումները ապրում են `src/shared/constants/visionBridgeDefaults.ts` ում; նոր mode/task-aware/cache կանխադրվածները և կարգավորումների լուծիչը գործում են `src/shared/constants/modalityBridgeDefaults.ts` ում: Պաշտպանական բազրիքը բացահայտում է `deps` կոնստրուկտորի տարբերակը, որպեսզի թեստերը կարողանան կեղծ `getSettings` և `callVisionModel` իրականացումներ ներարկել:

### Աուդիո կամուրջ (`audioBridge.ts`) — Modality Bridge PR-3

Ընդհատում է աուդիո կրող զրույցի հարցումները, նախքան դրանք հասնում են թիրախին, որը հայտնի չէ, որ ընդունում է աուդիո մուտքագրումը: Այն երբեք չի փոխում զրույցի հարցումը. աուդիո մասերը տառադարձվում են գոյություն ունեցող OpenAI-ի հետ համատեղելի բազմամաս վերջակետի միջոցով, և ընտրված զրույցի մոդելը շարունակվում է տեքստային տառադարձումներով:

Հոսք:

1. Լուծիր `supportsAudio` `getResolvedModelCapabilities()` միջոցով: Հաղթում է բացահայտ մատակարար-ռեգիստրի մետատվյալները, այնուհետև ստատիկ մոդելի մետատվյալները, այնուհետև համաժամեցված `modalities_input`: Հայտարարված մուտքագրման ցուցակն առանց `audio` ն `false` է; ոչ մի կարողության ապացույց չի մնում `null`. Ե՛վ `false`, և՛ `null` ակտիվացնում են պահպանողական կամուրջը, մինչդեռ `true` շրջանցում է այն։
2. Լուծեք `modalityBridgeAudio*` կարգավորումները և յուրաքանչյուր հաղորդագրությունից հանեք վերին մակարդակի աուդիո մասերը համօգտագործվող `detectMediaParts()` դետեկտորի միջոցով: Աջակցվող մետաղալարերի ձևերն են OpenAI `input_audio`, `audio_url` և `source.media_type: "audio/*"`: Ներդրված ձայնը հայտնաբերվում է երթուղման համար, բայց չի հեռացվում միացման ճանապարհով: Աշխատանքը սահմանափակված է `modalityBridgeAudioMaxClips` ով; հետագա մասերը մնում են անձեռնմխելի:
3. Հարգեք կազմաձևված `provider/model` կամ թույլ տվեք `selectAudioBridgeModel()` քայլել `AUDIO_TRANSCRIPTION_PROVIDERS` կայուն կատալոգի կարգով և ընտրել առաջին մոդելը, որն ունի օգտագործելի ակտիվ մատակարարի հավատարմագիր:
4. `callAudioTranscription()` base64/data-URI աուդիոը փոխակերպում է բազմամասանի `file` կամ ներբեռնում է հեռակառավարվող `audio_url` միայն հանրային ելքային պաշտպանիչի միջոցով DNS ամրացմամբ և 25 MB կապով: Այնուհետև այն POSTs ֆայլը և ընտրված մոդելը տեղական `/v1/audio/transcriptions` ինքնատիրույթի մեջ՝ վավերացված `resolveSelfLoopBearer()` ով: Գոյություն ունեցող տառադարձման երթուղին իրականացնում է հավատարմագրերի նորմալ որոնում, cooldown/rate-limit մշակում և մատակարարի առաքում:
5. Հաջողված զանգերն իրենց մասերը փոխարինում են `[Audio N]: <transcript>` ով: Զանգերը գործարկվում են `Promise.allSettled` ով. անհատական ձախողումը պահպանում է այդ սկզբնական աուդիո մասը (#4012 պայմանագիր): Եթե յուրաքանչյուր զանգ ձախողվի, և թիրախն ապացուցվի `supportsAudio === false`, մասերը դառնում են `[Audio N]: (unavailable — no STT provider connected)` (#8430 պայմանագիր): Անհայտ թիրախի համար (`null`) անհաջող արդյունքը մնում է անձեռնմխելի: Միայն տեքստով ապացուցված թիրախը, որն առանց օգտագործելի STT հավատարմագրի, ստանում է նույն բացահայտ կոճակը՝ առանց ցանցային զանգ տալու:

Հաջող տառադարձումներն օգտագործում են գործընթացի լայնածավալ Modality Bridge LRU/TTL քեշը: Բանալին միավորում է աուդիո տեղեկանքը, կայուն `audio-transcription` գործողության պիտակը և ընտրված STT մոդելը; ձախողումները երբեք չեն պահվում: Ձայնային փորձերը թարմացնում են ընդհանուր `bridged`, `cacheHits`, `failures` և `lastUsedAt` հաշվիչներ: Փոխակերպված պատասխանները կրում են `x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>`; չձեռնարկված հարցումները չեն ստանում Audio Bridge հատված:

Runtime-ի կարգավորումները DB-ով ապահովված են և Zod-ով վավերացված.

| Բանալին                       | Կանխադրված | Շրջանակ         |
| ----------------------------- | ---------- | --------------- |
| `modalityBridgeAudioEnabled`  | `true`     | —               |
| `modalityBridgeAudioModel`    | `""`       | Ավտո կամ STT ID |
| `modalityBridgeAudioTimeout`  | `60000`    | 1000–300000     |
| `modalityBridgeAudioMaxClips` | `3`        | 1–10            |

Համօգտագործվող քեշը շարունակում է վերահսկվել `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes` և `modalityBridgeCacheMaxEntries` կողմից:

### Video Bridge (`videoBridge.ts`, `videoBridgePipeline.ts`)

Ընդհատում է վերին մակարդակի վիդեո մասերը Chat Completions `messages` ում և Responses API `input` ում, նախքան թիրախը, որը հայտնի չէ բնիկ տեսաաջակցությամբ: Աջակցվող ձևերն են `input_video`, `video_url`, `video_source`, HTTPS URLs և `data:video/*;base64,...` տվյալների URIs: Պարզ ֆայլերի անունները տեքստում չեն դիտվում որպես տեսանյութ:

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`)-ին է պատկանում հարցումների անցումը, capability/policy ստուգումը, յուրաքանչյուր հարցման համախմբումը և պատասխանի օգտակար բեռը: Մեկ տեսանյութի աշխատանքի համար — ձեռքբերում, ամբողջ արդյունքի քեշը, որը նկարագրում է կադրերի հաջորդականությունը (որը միաձուլում է զանգահարողի կողմից հայտարարված ցանկացած աուդիո սղագրություն) և յուրաքանչյուր փորձի արդյունքում metrics/abort/cleanup — թաքնված է `processVideoPart` հետևում `videoBridgePipeline.ts` ում, որը կոչվում է մեկ անգամ յուրաքանչյուր տեսանյութի մասում `preCall` ի օղակում: Այդ մոդուլը նաև սահմանում է բացահայտ պորտի սահմանները `VideoMediaBrokerPort` (բայթերի ձեռքբերում և նմուշառված շրջանակների արդյունահանում), `VideoAudioTranscriptionPort` (զանգահարողի կողմից հայտարարված աուդիո տառադարձման միաձուլումը ընտրված ենթագրերի հետ) և `VideoDrilldownPort` (հումքային պահեստի ձևը): Արտադրության STT և շրջանակի պահպանումը կազմված են նկարագրող պորտի շուրջ `createVideoSttAdapter` և `createVideoDrilldownAdapter` միջոցով; վերջինս օգտագործում է ընդհանուր անթափանց բռնակով կյանքի ցիկլը:

Հանրային `/v1` հարցումների ուղին երբեք չի ներմուծում կամ կանչում ենթապրոցեսը: Հեռավոր տեսանյութերը ներբեռնվում են 50 MiB սահմանով; inline base64 տեսահոլովակները ունեն պահպանողական 36 MiB վերծանված յուրաքանչյուր տեսանյութի գլխարկ, այնպես որ model/messages/framing ծրարը կարող է մնալ հանրային JSON խնդրանքի ընդունման սահմանաչափի ներսում՝ 50 MiB: Ներդիր երկարության և վերծանված չափերի գնահատումները ստուգվում են նախքան տեղաբաշխումը: HTTPS պահանջվում է սկզբնական հեռակառավարման URL և յուրաքանչյուր վերահղման վրա՝ օգտագործելով գոյություն ունեցող բացառապես հանրային ելքային պահակը DNS ամրացմամբ: Այնուհետև բայթերն անցնում են `POST /api/modality-bridge/video/extract` բրոքերի ճշգրիտ ներքին սահմանը: Այդ երթուղին և՛ `LOCAL_ONLY` է, և՛ `SPAWN_CAPABLE`, ընդունում է միայն յուրաքանչյուր գործընթացի կողմից վավերացված, վստահելի հանգույցի վերադարձի հարցում և երբեք չի ընդունում URL, ֆայլային համակարգի ուղի, գործարկվող կամ փաստարկների ցանկ: API մարմնի չափի խողովակաշարը և կարգավորիչի աճող մարմնի ընթերցիչը ինքնուրույն են կիրառում 50 MiB բրոքերի մուտքագրման գլխարկը: Դրա սահմանափակ հերթը միաժամանակ կատարում է մեկ արդյունահանում, թույլ է տալիս չորս սպասող աշխատանք և փակում է սպասվող մուտքը 100 MiB ով:

Բրոքերի ներսում `ffprobe` կարդում է մասնավոր տեղական ֆայլը. ֆիքսված ձևաչափի թույլտվությունների ցանկը բացառում է երգացանկերի և մանիֆեստների ձևաչափերը: Թույլատրված MOV-ընտանեկան կոնտեյներների համար արտաքին MOV տվյալների հղումները մնում են լռելյայն անջատված, և ֆիքսված հրամանը չի մասնակցում դրանց: Ե՛վ `ffprobe`, և՛ `ffmpeg` օգտագործում են `file` -only արձանագրության սպիտակ ցուցակը, մեկ շարանը, ֆիքսված արգումենտների զանգվածները, առանց կեղևի և `PATH` ից լուծված գործադիրներ: Կցված նկարի շապիկի հոսքերը նվագարկվող թեկնածուներ չեն: Բոլոր նվագարկվող հոսքերը պետք է բավարարեն սահմանները, և նախընտրելի է հստակ կանխադրված հոսքը նախքան որոշիչ ամենացածր ինդեքսով հետադարձը: Տեսանյութերը սահմանափակված են 600 վայրկյանով, 8,192 պիքսել մեկ չափման և 33,554,432 աղբյուրի պիքսել: FFmpeg նմուշառում է 1–16 միջնակետ JPEG շրջանակներ, մեծացնում է երկար եզրը մինչև առավելագույնը 1024 պիքսել՝ առանց ավելի փոքր մուտքերի մեծացման և երբեք չի ստանում URL: Նմուշառումը լռելյայնորեն `uniform` է: Ընտրովի `scene_aware` և փորձարարական `segment_aware` քաղաքականությունները կատարում են մեկ լրացուցիչ ֆիքսված FFmpeg անցում արդեն վավերացված տեղական հոսքի վրայով, ընտրում են սահմանափակված `showinfo` տեսարանի ժամանակի դրոշմակնիքները և դետերմինիստիկորեն վերադառնում են նույն միատեսակ միջնակետերին դետեկտորի խափանումների, ժամանակի ավարտի, սխալ ձևաչափի կամ դատարկ թեկնածուների հավաքածուի դեպքում: Սեգմենտի տեղյակ ռեժիմը հատկացնում է միջին կետի նմուշները համաչափ տեսարանի վավերացված միջակայքերին. Սեգմենտից տեղյակ ապացույցները և հետադարձ պահվածքը մանրամասն ներկայացված են ստորև: Կոշտ 16 շրջանակի գլխարկը կիրառվում է յուրաքանչյուր քաղաքականության մեջ ընտրությունից հետո: Երբ տեսարանին ծանոթ հարցումն ունի միայն մեկ կադրի բյուջե, այն օգտագործում է ակտիվ ամբողջական տեսանյութի կամ ֆոկուսի պատուհանի միատեսակ միջնակետը և հայտնում `policyEffective: uniform`. մեկ ընտրված տեսարանի կադրը չի կարող պահպանել երկու ժամանակավոր ծայրերը: Զանգահարողը կարող է կամայականորեն տրամադրել վերջավոր կենտրոնացման պատուհան (`start`/`end` վայրկյան); սահմանները սեղմվում են մեդիայի տևողության վրա, հակադարձ կամ անվերջ պատուհանները մերժվում են, և նմուշառման բոլոր քաղաքականությունները կատարվում են միայն նորմալացված միջակայքում: Ստացված պատուհանը ներառված է նմուշառման մետատվյալներում և անվստահելի նկարագրության նախածանցում, որպեսզի ներքևի մոդելները կարողանան տարբերել կենտրոնացված հատվածը ամբողջական ժամանակացույցից:

Իմաստային ենթագրերի կենտրոնացումը առանձին, բացահայտ կարգավորում է: Լռելյայն `full` վերլուծության ռեժիմը պահպանում է առկա շրջանակի հուշումը և երբեք հարցման տեքստը չի ուղարկում վերնագրի մոդելին: `focused` ռեժիմում կամուրջը կարդում է միայն վերջին ոչ դատարկ օգտատիրոջ հեղինակած `text`/`input_text` նույն Chat-ի կամ Responses կոնտեյներից, այն նորմալացնում է NFC, քանդում է կառավարման նիշերն ու բացատները և սահմանափակում է 500 Unicode ծածկագրի կետերով: Դատարկ արդյունքը վերադառնում է ճշգրիտ `full` հուշմանը: Օգտագործելի ակնարկը սերիականացված է որպես JSON հատուկ անվստահելի օգտվողի համատեքստային բլոկում և կարող է առաջնահերթություն տալ միայն դիտելի մանրամասներին. այն չի կարող անտեսել լրատվամիջոցներում տեսանելի կամ լսելի հրահանգներին հետևելու առանձին նախազգուշացումը: Տեքստային ֆոկուսը երբեք չի ենթադրում `start`/`end` կամ չի փոխում ժամանակավոր նմուշառիչը:

#### FU-07 կառուցվածքային հատվածի ապացույցներ

`segment_aware` օգտագործում է մեկ սահմանափակ նախավերլուծական անցում արդեն վավերացված տեղական տեսահոսքի միջոցով: Ֆիքսված ֆիլտրի շղթան սկզբում մասշտաբվում է առավելագույնը 320 պիքսել լայնությամբ, հայտնաբերում է տեսարանների փոփոխությունները և սառեցված ընդմիջումները, այնուհետև նմուշառում է 1 կադր վայրկյանում արագությամբ՝ մշուշման, միջին լումայի և spatial/temporal տեղեկատվության համար: Անցումը սահմանափակվում է 600 կառուցվածքային նմուշներով, մեկ FFmpeg/filter շղթայով, նույն `file` -only արձանագրության և կոնտեյների թույլտվությունների ցանկով, 1 MiB գործընթացի ելքային կապով և առավելագույնը 30 վայրկյանով բրոքերի ընդհանուր abort/deadline. ի ներսում: Այն երբեք չի ընդունում հարցումից հրաման, զտիչ, ուղի կամ URL :

Կառուցվածքային արժեքները դետերմինիստական նմուշառման ապացույցներ են, այլ ոչ թե իմաստային տեսանյութերի ըմբռնում: Նրանք չեն եզրակացնում թեմաներ, գործողություններ, ենթագրեր, խոսք կամ օգտվողի մտադրություն: Տեսարանի և սառեցման սահմանները կազմում են հատվածներ; սառեցման ծածկույթը, մշուշումը, բացահայտումը, տարածական մանրամասները և ժամանակային փոփոխությունները միայն ազդում են գոյություն ունեցող 1-16 շրջանակային բյուջեի բաշխման վրա: Լիովին սառեցված հատվածը ծածկված է մեկ շրջանակով, մինչդեռ չսառեցված հատվածները մրցում են մնացած բյուջեի համար: Երբ սահմանները գերազանցում են շրջանակները, ժամանակացույցի միատեսակ ծածկույթը պահպանվում է, այնպես որ արագ վաղ կրճատումները չեն կարող թաքցնել երկար հետևող հատվածը: Սառեցման սահմանի 1-վայրկյան վերլուծության լուծաչափում տեսարանի սահմանները միավորվում են:

Բացակայող ֆիլտրերը, malformed/empty ապացույցները, դետեկտորի սխալը կամ սահմանափակված նախնական վերլուծության ժամկետը բացակայում է ճշգրիտ միատեսակ միջին կետի քաղաքականության համար: Զանգահարողի ընդհատման կամ միջնորդի վերջնաժամկետը չի բացվում. այն դադարեցնում է թռիչքի ընթացքում ենթագործընթացը, կանխում է ավելի ուշ շրջանակի արդյունահանումը, և մասնավոր ժամանակավոր ծառը հանվում է `finally` ում:

`scripts/perf/video-bridge-fu07-eval.ts` ստեղծում է դետերմինիստական իրական FFmpeg հարմարանքներ՝ վերնագիր-զանգից հետո խնայողությունների, խիտ շարժման բյուջեի բաշխման, blur/exposure/SI-TI ապացույցների, երկար պոչով արագ կրճատումների և կեղծ պոզիտիվների աստիճանական մարման համար: Այն գրանցում է նախավերլուծական պատի ժամանակը և, որտեղ `/usr/bin/time` հասանելի է, երեխայի CPU և peak RSS: Դրա որակի ստուգումները միայն կառուցվածքային օրակուլներ են: Իրական ենթագրերի մոդելի որակը մնում է `HOLD` քանի որ այս զրահը չունի լիազորված վերջնակետ կամ սառեցված դատավոր: Դրամական խնայողությունները նույնպես մնում են `HOLD` եթե `--caption-cost-per-call-usd` չտրամադրի բացահայտ դրական գնահատական մեկ զանգի համար. սցենարը երբեք չի կեղծում որևէ արդյունք:

Յուրաքանչյուր շրջանակ սահմանափակված է 4 MiB, բոլոր չմշակված շրջանակները միասին մինչև 23 MiB, իսկ սերիականացված բրոքերային պատասխանը մինչև 32 MiB: Մասնավոր ժամանակավոր գրացուցակը հեռացվում է `finally` ում: OmniRoute չի փաթեթավորում FFmpeg և չի ընդունում հատուկ գործարկվող ուղի: Ենթագրերից առաջ կամուրջը կիրառում է պահպանողական տեսողական կրկնօրինակման անցում. յուրաքանչյուր JPEG կրճատվում է մինչև 16 × 16 մոխրագույն սանդղակի բուֆեր և համեմատվում է միայն պահպանված վերջին կադրի հետ: Մեկ շրջանակից բարձր ենթագրերի պահանջվող բյուջեի համար արդյունահանումը տրամադրում է սահմանափակված թեկնածուների խումբ՝ մինչև այդ բյուջեի կրկնակի չափով և ոչ ավելի, քան 16 կադր: Պահանջվող շեմը կիրառվում է միայն կրկնօրինակումից հետո, իսկ առաջին և վերջնական ընտրված թեկնածուները պահպանվում են վերջնական նոսրացման ժամանակ, երբ բյուջեն առնվազն երկուսն է: Տարբերակված `grayscale-16x16-mean-cells-v2` քաղաքականությունը օգտագործում է միջին լումա դելտաի ավելի մեծը և մանրապատկերների բջիջների հարաբերակցությունը, որոնց նորմալացված դելտան առնվազն 0,05 է: Կրկնվող շեմը 0.04 հաստատունն է, որն ընտրված է կանխատեսելիության համար, այլ ոչ թե որպես գործարկման ժամանակի կարգավորում: Բարձր կոնտրաստային այս երկրորդային ազդանշանը պահպանում է փոքր շարժումները և տեսանելի տեքստի փոփոխությունները, որոնք կարող են թաքցնել միայն միջին համեմատությունը: Համեմատիչի կամ ապակոդավորիչի սխալները բաց չեն և պահպանում են ծածկույթը: Ելքային մետատվյալներն առանձնացնում են արդյունահանված թեկնածուներին, հաջողությամբ օգտագործված շրջանակները և տեսողական կրկնօրինակները՝ հեռացված:

Հստակորեն նշված տեսանյութի հատվածը կարող է պահանջել ժամանակի դրոշմված կոնտակտային թերթիկ: Կամուրջը կառուցում է առավելագույնը 4 սյունանի, 16 շրջանակի JPEG ցանց: Յուրաքանչյուր 512 պիքսելանոց բջիջ այրում է իր աղբյուրի ժամանակի դրոշմը բարձր կոնտրաստային ներքևի գոտու մեջ, մինչդեռ նույն ժամանակի դրոշմակնիքները մնում են տեքստային մետատվյալներում՝ ներքևի ասոցիացիայի և աուդիտի համար: Ամբողջական JPEG մնում է 32 MiB սահմաններում: Եթե `sharp` չի կարող վերծանել կամ կազմել ցանցը, կամուրջը հետ է ընկնում դեպի առանձին JPEG շրջանակներ; հաճախորդի ընդհատումը դեռ տարածվում է թերթիկի գործողության միջոցով:

Խթանման ապացույցները միտումնավոր առանձնացված են սինթետիկ կազմի միկրոհենանիշից: `scripts/perf/video-bridge-contact-sheet-eval.ts` սահմանում է սխեմայի տարբերակով A/B ամրագոտիներ իրական OpenAI-ի հետ համատեղելի տեսողության մոդելների համար: Այն չափում է մատակարարի կողմից հաղորդված նշանները, պատի վերջից մինչև վերջ հետաձգվածությունը (ներառյալ թերթի կազմը), մոդելի զանգերի քանակը և մանիֆեստի կողմից սահմանված փաստերի պահպանումը: Հում մոդելի պատասխանները չեն գրվում հաշվետվությանը. պահպանվում են միայն SHA-256 մարսումները և համապատասխանող փաստերը IDs : Սարքավորումը չի կատարում ցանցի կամ վճարովի մոդելի զանգ, քանի դեռ `--execute-real` չի փոխանցվել, և `--model`, `OMNIROUTE_BASE_URL` և `OMNIROUTE_API_KEY` կազմաձևված չեն: Առանց այդ բացահայտ իրական վազքի, դրա մեքենայաընթեռնելի դատավճիռը մնում է `HOLD`; սինթետիկ payload/call-count չափումները միայն խթանման ապացույց չեն:

Զանգահարողները կարող են կամընտիր `transcript.cues` զանգված կցել աջակցվող տեսանյութի մասին, երբ նրանք արդեն ունեն հավասարեցված տեքստ: Յուրաքանչյուր նշան պետք է ունենա `text`, վերջավոր `start`/`end` ինտերվալ փորձված տևողության ներսում և սպիտակ ցուցակում ներառված `source` (`client`, `embedded` կամ `audio-bridge`); `confidence` լռելյայն սահմանում է `1` և պետք է մնա `0` և `1` միջև: Ճշգրիտ կրկնօրինակ ազդանշանները փլուզված են: OmniRoute երբեք չի սկսում տառադարձումը այս մետատվյալներից. վավերացված ազդանշանները պատճենվում են նկարագրված արդյունքի մեջ՝ աղբյուրով, վստահությամբ և ընդմիջումով և ցուցադրվում են որպես անվստահելի դիտարկումներ շրջանակի ենթագրերի կողքին: Անվավեր, տիրույթից դուրս կամ առանց ծագման տեքստը մերժվում է, այլ ոչ թե խառնվում ենթագրերի հոսքի մեջ: Հարցման մարմնի տառադարձման երկու ալիքներն էլ նորմալացնում են մատակարարված ծագումը `client` ին, ներառյալ ինքնահաստատված `embedded` կամ `audio-bridge` պիտակները: Միայն սերվերին պատկանող ադապտերը կարող է նշանակել այդ վստահելի պիտակները միայն կոդով `trustedSource` արգումենտի միջոցով; Հարցման JSON դաշտը չի կարող հասնել այդ արգումենտին: Տառադարձման տեքստը մնում է անվստահելի լրատվամիջոցներից ստացված բովանդակություն՝ անկախ դրա ծագումից և երբեք չպետք է որոշի թույլտվությունը:

Ընդլայնված զանգահարողը կարող է տրամադրել `audioTranscript` հետքեր նույն տեսանյութի համար. այն դիտվում է որպես հաճախորդի կողմից տրամադրված տեքստ, այլ ոչ սերվերի տառադարձման ապացույց: The fusion seam-ը կատարում է տեսողական և աուդիո դիտարկումները մեկ վերջնաժամկետում և ընդհատում է ազդանշանը, պատվիրում է դրանք ընդհանուր ժամանակացույցի վրա, քանդում է ճշգրիտ կրկնօրինակները և հաղորդում մասնակի արդյունք, երբ միայն մեկ կողմն է հաջողության հասնում: Անվավեր `audioTranscript` վերածվում է այդ մասնակի արդյունքի — տեսողական նկարագրությունը պահվում է, և աուդիո մասնաճյուղը ձայնագրում է ախտահանված ձախողման կոդ — ՝ ամբողջ տեսանյութը ձախողելու փոխարեն: Մասնաճյուղի հասանելիությունը, մասնակի դրոշակը և ախտահանված խափանման կոդերը պահպանվում են նկարագրված արդյունքում, պաշտպանական բազրիքների մետատվյալներում (`audioFusionRuns`/`audioFusionPartials`/ `audioFusionFailureCodes`), արդյունքների քեշի մետատվյալներում և կամրջի միաձուլման հաշվիչներում: Video Bridge-ի կանխադրված ուղին չի կանչում խոսքի տեքստ կամ ներբեռնում երկրորդ մեդիա պատճենը. առանց այդ հստակ ուղու, այն մնում է միայն տեսահոլովակ:

**Սղագրության պահպանում (#12150 P1):** Սա ինքնաբերաբար կիրառվում է, երբ Video Bridge-ը (ինքնին մասնակցում է) ներկայացնում է տառադարձման նշան — առանձին պահպանման դրոշ չկա: Երբ հարցումը արտագրում է որևէ տառադարձում (զանգողի կողմից հայտարարված `transcript` կամ միաձուլված `audioTranscript`), պաշտպանական բազկաթոռը նշում է այն `videoBridgeObserved` և ստեղծում է տեսանյութի նկարագրության սրբագրված ստվեր — նույնական արտապատկերում, որում յուրաքանչյուր ազդանշանի ազատ տեքստի մարմինը փոխարինվում է `[redacted-video-transcript]` ով, որը կառուցվում է նախքան կառուցվածքը փոխարինելով՝ փոխարինելով դաշտը: հարթեցված տեքստ, այնպես որ ոչ մի նշանային բովանդակություն — հակառակորդ կամ սովորական, ներառյալ `]` պարունակող մարմինները, ինչպիսիք են `[inaudible]`/`[music]` — չեն կարող գոյատևել): Մշտական զանգերի գրանցամատյանի հարցման մարմինը փոխում է տեսանյութից ստացված տեքստի յուրաքանչյուր հատված այդ խմբագրված ստվերով, որը համապատասխանում է բովանդակության հավասարությանը. `fullText` խարիսխը վերընթերցվում է ավարտված նախնական զանգի պահակային բեռնատարից, այնպես որ համընկնումը դեռևս հաջողվում է այն բանից հետո, երբ ավելի ուշ շղթայական պաշտպանիչ բազրիքները ( PII և հավատարմագրերի դիմակներ, առաջնահերթություններ 10/95) վերաշարադրեն նկարագրության տեքստը տեղում և system-prompt/handoff/memory ներարկումից հետո վերափոխեն հաղորդագրությունների զանգվածը: Մոդելի ուղղությամբ ուղարկված մարմինն անփոփոխ է: Դիտարկված հարցումը նաև չունի կայուն հիշողություն (ինչպես հարցումից, այնպես էլ պատասխանից ստացված արդյունահանումը բաց է թողնվում), ուստի մոդելի սեփական պատասխանը չի կարող կրկնօրինակել տեքստը Հիշողության մեջ:

**Հում վիդեո դաշտեր (#12430):** Երբ կամուրջը միացված է, և հայրենի տեսանյութերի աջակցությունն անհայտ է կամ բացակայում է, սահմանված `transcript`/`audioTranscript` դաշտերը նույնպես ակտիվացնում են `videoBridgeObserved`, նույնիսկ նկարագրության ձախողումից կամ `maxVideos` սահմանափակումից հետո: `null` և դատարկ տողերի հաշվարկ; բացակայող դաշտերը և ոչ վիդեո մետատվյալները՝ ոչ: Պահպանված պատճենները խմբագրում են այս դաշտերը կամ բաց թողնում հարցումը, և caches/Memory շրջանցվում է:

Այդ հետադարձ ուղիներում զանգահարողի վավեր ազդանշանները դառնում են աջակցվող `text`/`input_text` մասեր, այլ ոչ ստանդարտ մատակարարի դաշտեր: Հարցման միջոցով տրամադրված երկու հետքերը մնում են անվստահելի `client` դիտարկումներ՝ բացահայտ նախազգուշացմամբ, որ տեսանյութը նկարագրված չէ, և ժամանակի դրոշմակնիքները չեն ստուգվել լրատվամիջոցների նկատմամբ: Գոյություն ունեցող 256-cue/64-KiB ընդհանուր և մեկ ցուցիչի բյուջեները կիրառվում են երկու ուղիներում միասին. Ժամային դրոշմանիշները պետք է համապատասխանեն միջնորդի 600 վայրկյանանոց առաստաղին և ցանկացած մատակարարված ֆոկուսային պատուհանին: Անվավեր հետքերը հեռացվում են, չեն ուղարկվում որպես կամայական տեքստ; վավեր քույրը կամ եղբայրը դեռ կարող են օգտագործվել, քանի դեռ նրանց համակցված բյուջեն չի գերազանցվել: Null/empty դաշտերը տեքստ չեն ավելացնում: Ոչ մի մեդիա առբերում կամ տառադարձում չի ավելացվել այս հետադարձով: Տառադարձման ընդլայնման դաշտերը հեռացվում են հետադարձ վիդեո կրիչից և դրա `video_url`/`source` օբյեկտներից: OpenAI մետաղալարերի թույլտվությունների ցանկը մնում է խիստ. Անհայտ բնիկ վիդեո կրիչները մնում են հասանելի, իսկ հայտնի միայն տեքստային թիրախները պահում են անվտանգ մարկերներ: Կառուցվածքային խմբագրման ստվերները պաշտպանում են կցված տառադարձման տեքստը, մինչդեռ զանգահարողի պատկանող սկզբնական հարցումը մնում է անփոփոխ: Մայրենի կողմից աջակցվող թիրախները և հաշմանդամ կամուրջները պահպանում են իրենց առկա շրջանցիկ վարքը:

Լրացուցիչ պահպանված պատճեններն օգտագործում են նույն դիտարկվող հարցումի ազդանշանը: Հաճախորդի հարցումների չմշակված նախնական պահակակետը, հիշողության մեջ առկախ հարցումը և վաղաժամ մերժված հարցումների գրանցամատյանը կառուցվածքայինորեն փոխարինում են տառադարձման դաշտերը վիդեո մասերում. լարային հուշումները, որոնք սինթեզվում են խողովակաշարի փուլերի և համատեքստի փոխանցման միջոցով, վերադասավորվում են շարունակական պահանջի մարմնի լվացարանում: Մշտական `video_content_removed` նշիչը ստիպում է `previous_response_id` շարունակությունը փակվել, այլ ոչ թե վերակառուցել միտումնավոր հեռացված տեքստը: Եթե դիտարկված հարցումը կորցնում է իր յուրաքանչյուր մասի խմբագրման ստվերը նախքան գրանցումը, կամ նույնիսկ մի քանի տեսանյութի ստվերներից մեկը չի համընկնում ավելի ուշ հարցումների մուտացիաներից հետո, պահպանված հարցման մարմինն ամբողջությամբ բաց է թողնվում՝ մասնակիորեն խմբագրված տառադարձումը պահպանելու փոխարեն:

Դիտարկված հարցման դեպքում մոդելային պատասխանը կարող է մեջբերել տառադարձության ցանկացած հատված՝ առանց կառուցվածքային ազդանշանի սահմանի: Հետևաբար, դրա շարունակական զանգերի մատյան `responseBody` փոխարինվում է բացթողման նշիչով. խողովակաշարի մանրամասն արտեֆակտը (որը կարող է ներառել upstream/client մարմիններ և հոսքի կտորներ) չի պահպանվել: Իմաստային, անզորություն և պատճառաբանություն-կրկնակի քեշերի շրջանցում ընթերցում և գրում է այդ խնդրանքի համար: Մատակարարի հարցումը և հաճախորդի տեսանելի պատասխանը մնում են անփոփոխ: Վաղ պահվող բայթերը հեռացվում են ժամանակավոր բուֆերից, երբ մանրամասն արտեֆակտը բաց է թողնվում: Kiro ի սխալ EventStream նախազգուշացումը հաղորդում է միայն օգտակար բայթերի քանակը, ոչ երբեք դրա բովանդակությունը կամ JSON վերլուծիչի չմշակված սխալը: Սա չի պնդում, որ յուրաքանչյուր անկապ provider/plugin ախտորոշում ենթարկվել է աուդիտի. ավելի լայն պահված լվացարան ավլելը հետևվում է #11658 ում:

Ներքին `/api/modality-bridge/video/drilldown` կյանքի ցիկլը առանձին, loopback/token-authenticated քեշի ենթաշերտ է: Յուրաքանչյուր գործողություն պահանջում է նաև կանոնական անթափանց ID սկզբունք: Մինչ արտադրական զանգահարողը միացված է, այն պետք է ստանա այդ ID վավերացված վարձակալից և երբեք չպետք է փոխանցի հաճախորդի կողմից ընտրված արժեքը: Քեշի ստեղները կապում են այդ սկզբունքը կանոնական նիստի և տեսահղման IDs հետ, պահում են միայն իրենց SHA-256-derived ստեղները, և ընթերցումների և ջնջման շրջանակը նույն հիմնականին են: Քեշը պահում է առավելագույնը 16 ստացված JPEG շրջանակ յուրաքանչյուր մուտքի համար, սպառվում է տասը րոպե հետո և աջակցում է սահմանափակված `start`/`end` ընթերցումներ կամ բացահայտ աշխատաշրջանի ջնջում:

Յուրաքանչյուր հիմնական սահմանափակված է 16 գրառումներով և 64 MiB կանոնական JPEG տվյալների: Այդ սահմանները անկախ են գլոբալ 64-entry/256 MiB առաստաղից. հիմնական քվոտային ճնշումը վտարում է միայն այդ տնօրենի ամենաքիչ օգտագործված գրառումները, նախքան գլոբալ LRU վտարումը դիտարկելը: Ժամկետանց գրառումները մաքրվում են ինչպես հիմնական, այնպես էլ գլոբալ հաշվառումից՝ քեշի գործունեության վերաբերյալ, մինչդեռ չեղարկման և վավերացման ձախողումը մասնակի փոխարինում չի կատարում:

Քեշը մերժում է ոչ կանոնական Base64-ը, ավելորդ լցոնումը, ոչ JPEG մեդիան, սխալ կամ կտրված JPEGs և JPEGs, որոնք նախազգուշացում են առաջացնում սահմանափակ ամբողջական պատկերով `sharp` վերծանման ժամանակ: Այն վերակոդավորում է յուրաքանչյուր ընդունված պատկեր՝ որպես կանոնական JPEG, լայնությունը և բարձրությունը ստանում է վերծանված բայթերից՝ զանգահարողի դաշտերին վստահելու փոխարեն, և դրանք չպահելու փոխարեն հեռացնում է հետին պոլիգլոտ բայթերը: Միայն սահմանափակված կանոնական սեղմված բուֆերը գանձվում է երկու քվոտաների վրա: JSON մետաղալարերի սահմանաչափը ներառում է Base64 վերադիր 32 MiB վերծանված մուտքային առաստաղի համար: Յուրաքանչյուր պահված ածանցում գրանցում է իր վավերացված JPEG format/resolution, նմուշառման քաղաքականությունը, ածանցյալ տարբերակը, ստեղծման ժամանակը, սերվերի կողմից հաշվարկված բովանդակության հեշը և հեշավորված ծնողի հղումը, գումարած վստահելի զանգահարողի ծնողի բովանդակության հեշը: Չեղարկումը ստուգվում է ասինխրոն decode/hash փուլերի միջև՝ նախքան ատոմային քեշի միացումը:

Արտադրական արտադրողը վերօգտագործում է արդեն ստացված բրոքերային շրջանակները միայն հաջող տեսողական վերլուծությունից հետո, առանց երկրորդ տեսանյութի download/extraction. Այն պահանջում է `modalityBridgeVideoDrilldownEnabled=true` օպերատոր, խիստ `drilldown: true` յուրաքանչյուր մասի համար և վավերացված API-բանալի գրառում ID: Հաճախորդի կողմից հայտարարված principal/session արժեքները երբեք սեփականություն չեն հաստատում: Առանց բոլոր երեք պայմանների այն չի խաշում, չափափոխում կամ պահպանում լրացուցիչ շրջանակներ: Պահպանման ձախողումը պահպանում է օգտագործելի տեսողական արձագանքը: Համաձայնեցված հարցումները շրջանցում են ամբողջ տեսանյութի արդյունքների քեշը, որպեսզի քեշավորված արդյունքները երբեք չվերարտադրվեն բռնակները:

JSON և SSE հաջող պատասխանները բացահայտում են առավելագույնը չորս անթափանց բռնակներ սահմանափակված `x-omniroute-video-drilldown` վերնագրում: Բրաուզերի լիազորված սկզբնաղբյուրները կարող են կարդալ այդ վերնագիրը՝ առանց CORS ծագման քաղաքականության ընդլայնման: Նոր բռնակներն օգտագործում են `v1.<32-byte random base64url token>`, իսկ ռեեստրը պահպանում է միայն իրենց SHA-256 հեշերը: reader/header վերլուծիչն ընդունում է նաև ժառանգական 64 վեցանկյուն խորհրդանիշներ: Հավաստագրված հանրային սպառողը `GET /api/v1/video-bridge/drilldown?handle=...` ն է՝ անկախ `modalityBridgeVideoDrilldownRemoteEnabled=true` կողմից: Բացահայտ շարունակվող կեղծ չեղարկում է մուտքը նույնիսկ այն դեպքում, երբ ժառանգական `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_REMOTE_ENABLED` env հետադարձ կապը միացված է: Արտադրության պահպանումն ունի `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_ENABLED` նման ժառանգություն: Երկու հետնորդներն էլ լռելյայն անջատված են:

Սպառողը ստանում է իր սեփականությունը վավերացված բանալիից և կիրառում է հիմնական քաղաքականությունը. և՛ GET, և՛ DELETE պատկանում են `video` վերջնակետի կատեգորիային, ներառյալ `/v1` և `/api/v1` կեղծանունները: Ոչ դատարկ վերջնակետի թույլատրելի ցուցակով բանալիները պետք է ներառեն `video`; անսահմանափակ բանալիները մնում են համատեղելի: Սպառողը վերադարձնում է նույն 404-ը անհայտ, ժամկետանց և այլ բանալու բռնակների համար: Այն ընդունում է `variant=preview|standard|detail` (առավելագույն JPEG չափը 320/640/1280, երբեք բարձրացված), `limit=1..8` (կամ ժառանգված `frames` կեղծանունը, երբեք երկուսն էլ), զրոյական `page` և կամընտիր `start`/`end` ֆոկուս վայրկյաններ: Հարցման կրկնօրինակ ստեղները և հակադարձ ֆոկուսային պատուհանները մերժվում են: Յուրաքանչյուր վերադարձված տարբերակ ունի իր իրական բովանդակության և փաստացի լուծման մետատվյալների հեշը՝ կապված պահպանված աղբյուրի հետ: Տարբերակները ստացվում են ընթերցման ժամանակ, այլ ոչ թե պահվում են որպես լրացուցիչ պահպանված պատճեններ: JSON պատասխանը, ներառյալ Base64/envelope, սահմանվում է 32 MiB; չափազանց մեծ էջը վերադարձնում է 413, և հաճախորդը պետք է պահանջի ավելի քիչ շրջանակներ: Կարդում է չեկի չեղարկումը յուրաքանչյուր չափափոխման շուրջ և նորից ստուգում է բռնակի վավերականությունը՝ վերադառնալուց առաջ: `DELETE` սեփականատիրոջ կողմից անզոր է. ջնջումը կամ TTL ժամկետի ավարտը թողարկում է պահպանված աղբյուրը և օգտագործման հաշվառումը:

Համօգտագործվող խանութը գործընթացային է. բռնակները սպառվում են վերագործարկման ժամանակ և չեն փոխանցվում անկախ OmniRoute գործընթացների միջև: Կառավարման վիճակագրությունը ցույց է տալիս արդյունավետ պահպանման/հեռակառավարման քաղաքականությունը և միավորում է միայն պահպանված entries/bytes, ոչ երբեք լրատվամիջոցները, հղումները, հիմնական IDs կամ բռնակները: Տեսանյութի կարգավորումների վահանակը ցույց է տալիս այդ արժեքները և կարող է պահպանել երկու համաձայնության անջատիչները: Իրականացման այս փաստաթուղթը կենդանի տեղակայման կամ առաջխաղացման ապացույց չէ. իրական մոդելի ընդունումը հետևվում է առանձին:

Շրջանակները մակագրված են հաջորդաբար կազմաձևված Video մոդելի հետ: Դատարկ Video override-ը ժառանգում է Vision պարամետրը. եթե երկուսն էլ դատարկ են, Vision ավտոմատ երթուղիչը ընտրում է արդյունավետ տեսողական մոդելը: Հաջող ենթագրերը փոխարինում են սկզբնական մասի կայուն `[Video description:` նախածանցով, որը նաև նշում է տեքստը որպես անվստահելի մեդիայից ստացված դիտարկում և հորդորում է ներքևում գտնվող մոդելներին չհետևել լրատվամիջոցներում հայտնաբերված հրահանգներին: Շրջանակի վերնագրերի քեշի ստեղները ներառում են JPEG բայթերը, հուշումը, ժամանակի դրոշմը և արդյունավետ մոդելը; միայն հաջողված ենթագրերը պահվում են քեշում: Քեշի գրառումները պահպանում են իրական հաջող արտադրողի մոդելը, ներառյալ հետադարձ մոդելը. կամուրջը հայտնում է `mixed`, երբ տարբեր մոդելների կողմից արտադրվում էին տարբեր շրջանակներ: Քեշը վերօգտագործում է արտադրողի ինքնությունը՝ որպես պահանջվող երթուղային պլան վերանշանակելու փոխարեն: Ամբողջ տեսանյութի արդյունքների քեշը միացված է յուրաքանչյուր մուտքի վրա, որը փոխում է ելքային — հուշումը, արդյունավետ մոդելը, նմուշառման քաղաքականությունը, շրջանակների քանակը, իմաստային վերլուծության ռեժիմը, նորմալացված ֆոկուսի հուշման SHA-256 մատնահետքը, ֆոկուս պատուհանը, `transcript`, `audioTranscript` և կոնտակտային թերթիկի դրոշը —, այնպես որ այդ չափսերից որևէ մեկը փոխելը երբեք չի կարող վերօգտագործվել: Տեսողական հեռացման քաղաքականության տարբերակը, շեմը և սահմանափակված թեկնածուների շրջանակների քանակը նույնպես հստակ են արդյունքների քեշի բանալիում և մետատվյալներում. Հետևաբար, քաղաքականության փոփոխությունը չի կարող կրկին օգտագործել հնացած ամբողջական տեսանյութի նկարագրությունը: Result-cache v4 մետատվյալները պահպանում են ռեժիմը և մատնահետքը, ոչ երբեք օգտագործողի հում խնդիրը: Guardrail-ի մետատվյալները հաղորդում են ինչպես պահանջված, այնպես էլ արդյունավետ վերլուծության եղանակները. Հայցված `focused` ռեժիմն առանց օգտագործողի օգտագործման տեքստի հաղորդվում է որպես արդյունավետ `full`:

Պաշտպանական բազկաթոռը հանում է բոլոր աջակցվող տեսանյութերը, բայց նկարագրում է ոչ ավելի, քան `modalityBridgeVideoMaxVideos`: Որպես թիրախ, որն ապացուցված է `supportsVideo === false`, ձախողված և չափից ավելի սահմանափակված տեսանյութերը դառնում են բացահայտ անվտանգ տեքստային նշիչներ, այնպես որ ոչ մի հում տեսանյութ գոյատևում է: Երբ հնարավորություններն անհայտ են, այդ մասերը պահպանում են իրենց տեսագրման կրիչը. ցանկացած հետադարձ տառադարձում հետևում է վերը նշված սահմանափակված տեքստի փոխակերպմանը: `supportsVideo === true` ով թիրախները շրջանցում են կամուրջը. Հաճախորդի պահանջի ընդհատման ազդանշանը տարածվում է ներբեռնման, բրոքերային հերթի, ենթագործընթացների և ենթագրերի զանգերի միջոցով. ընդհատում է վիդեոների միջև ընկած հատվածը և երբեք չի բացվում հում լրատվամիջոցների համար:

Runtime-ի կարգավորումները DB-ով ապահովված են և Zod-ով վավերացված.

| Բանալին                             | Կանխադրված  | Շրջանակ / վարքագիծ                                                                                               |
| ----------------------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`     | Ընտրովի գործարկման ժամանակ, միանալ                                                                               |
| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full` պահպանում է ընդհանուր ենթագրերը. `focused` օգտագործում է սահմանափակ, անվստահելի վերջին օգտվողի համատեքստը |

| `modalityBridgeVideoMaxVideos`      | `1`         | 1–4                                                                                                              |
| `modalityBridgeVideoTimeout`        | `120000`    | 1000–120000 ms                                                                                                   |

120 վայրկյանից ավելի տեսահոլովակի դադարի արժեքները, որոնք պահպանվում են, պահպանվում են բրոքերի վերջնաժամկետի համար. նոր կարգավորումները, որոնք գրում են այդ սահմանից բարձր, մերժվում են: `GET /api/modality-bridge/video/runtime` պահանջում է վստահելի դրոշմակնիք ունեցող loopback տեղակայում նախքան նույնականացումը կամ գործարկման ժամանակի հետաքննությունը, այնուհետև պահանջում է կառավարման վավերացում: Այն վերադարձնում է միայն `available`, ախտահանված FFmpeg/ffprobe տարբերակները և ֆիքսված պատճառ, երբ գործարկման ժամանակը անհասանելի է: Ներքին արդյունահանման վերջնակետը հանրային վերբեռնման API չէ. հերթի հագեցվածությունը վերադարձնում է `503` գումարած `Retry-After`, զանգահարողի անջատումը վերադարձնում է `499`, իսկ բրոքերի ֆիքսված վերջնաժամկետը վերադարձնում է `504`: Փոխակերպված պատասխանները `video->text;model=<visionModel>;parts=<videos>` ավելացնում են կենտրոնական `x-omniroute-modality-bridge` վերնագրին՝ առանց Vision կամ Audio հատվածները հեռացնելու:

### PII Masker (`piiMasker.ts`)

Վազում է** երկուսն էլ** փուլերը.

- **`preCall`** կլոնավորում է օգտակար բեռը, քայլում է `system`, `messages`, `input` և `prompt` (ներառյալ պարզ լարային տարրերը) և կիրառում `processPII()` ( `@/shared/utils/inputSanitizer` ից) լարային `content`/`text` դաշտերում: Երբ `PII_REDACTION_ENABLED=true`, հայտնաբերված PII վերագրվում է ելքային ծանրաբեռնվածության մեջ: Սա անկախ է `INPUT_SANITIZER_MODE` ից (որը վերահսկում է միայն արագ ներարկման քաղաքականությունը): Երբ խմբագրումն անջատված է, զանգը գրանցում է հայտնաբերումը առանց բովանդակությունը վերաշարադրելու:
- **`postCall`** խորը կլոնավորում է պատասխանը, գործարկում `sanitizePIIResponse()` և Responses-API-ձևավորող դիմակը (`maskResponsesOutput` — ծածկում է `output_text` և `output[].content[].text`): Եթե որևէ փոփոխություն տեղի ունենա, փոփոխված պատասխանը փոխարինում է բնօրինակին:

Պաշտպանական երկաթուղին երբեք չի արգելափակվում. այն միայն նշում է (`meta.detections`, `meta.redacted`) կամ վերաշարադրում:

#### Յուրաքանչյուր տեսակի ընտրություն, հատուկ նախշեր և հայտնաբերման հաշվիչներ

**Վահանակի վահանակ → Կարգավորումներ → Անվտանգություն → PII դիմակավորում** ընտրում է _ինչ_ը դիմակավորված է: Այն չի միացնում դիմակավորումը. դա դեռ `PII_REDACTION_ENABLED` (խնդրանք) և `PII_RESPONSE_SANITIZATION` (պատասխան + SSE), երկուսն էլ լռելյայն անջատված են:

- **Յուրաքանչյուր տեսակի ընտրություն** — ներկառուցված ID-ները թվարկված են `src/shared/constants/piiTypes.ts` ում (`PII_BUILTIN_TYPES`): Չսահմանված նշանակում է ամեն տեսակ (այս կարգավորումից առաջ գոյություն ունեցող վարքագիծը): Հարցման շարժիչի `ssn_us` օրինակը քարտեզագրվում է `ssn` ին: Կաղապարները (նվազագույն, ստանդարտ, ֆինանսական, բրազիլերեն, USA, GDPR, POPIA, լրիվ) լրացնում են միայն UI ի վանդակները:
- **GDPR և POPIA նույնացուցիչներ** — տասներկու ներկառուցված ID, որոնք ծածկում են EU և հարավաֆրիկյան անձնական նույնացուցիչները (ստորև բերված աղյուսակը): Նրանց ռեգեքսները, վավերացնողները և իրավասության պիտակները ապրում են մեկ աղյուսակում՝ `src/shared/utils/piiPatterns.ts`, որը սպառում են և՛ արձագանքման ախտահանիչը (`src/lib/piiSanitizer.ts`), և՛ հարցումների դիմակավորողը (`src/shared/utils/inputSanitizer.ts`): Համընկնումը վերագրվում է միայն այն դեպքում, երբ վավերացնողն ընդունում է այն. թվանշանների մերկ շարքը երբեք բավարար չէ: Օպերատորը, ով պահպանել է նեղացված ընտրությունը մինչ այս id-ների գոյությունը, պահպանում է իր վարքագիծը մինչև նոր ID-ների նշումը:
- **Պատվերով նախշեր** — մինչև 20 ռեգեքս կամ գծագրերի նախշեր (`*` = մինչև 64 առանց սպիտակ տարածության նիշ, `?` = մեկ): Լուցկիները դառնում են `[CUSTOM_REDACTED]`. Յուրաքանչյուր օրինաչափություն անցնում է `compilePiiCustomPattern()` (`src/shared/utils/piiCustomPatterns.ts`). առավելագույնը 500 նիշ, դրոշները սահմանափակվում են `g i m s u` ով, պետք է կազմվեն, պետք է անցնեն `safe-regex` (աղետալի հետընթաց) և չպետք է համընկնեն դատարկ տողի կամ խմբագրման տեղապահի հետ: Ձախողվող օրինաչափությունը մերժվում է, երբ պահպանվում է և փորձարկվում, և պահված տողը, որը ձախողվում է, բաց է թողնվում գործարկման ժամանակ՝ կոմպիլյացիայի փոխարեն: Հատուկ նախշերը գործում են միայն այն ժամանակ, երբ դիմակավորումը միացված է:
- **Հայտնաբերման հաշվիչներ** — յուրաքանչյուր տիպի հաշվում (երբեք չհամընկնող արժեքներ), պահվում են հիշողության մեջ և վերագործարկվում վերագործարկման ժամանակ (`src/lib/pii/piiDetectionStats.ts`): Դրանք միայն ավելանում են, երբ դիմակավորումը միացված է:

Կարգավորումներն ապրում են `key_value` աղյուսակում (անվանատարածք `pii_settings`, `src/lib/db/piiSettings.ts`) և կարդացվում են 1 վ քեշի միջոցով: API:

| Մեթոդ  | Ճանապարհ                 | Նպատակը                                                               |
| ------ | ------------------------ | --------------------------------------------------------------------- |
| `GET`  | `/api/settings/pii`      | Դրոշի վիճակ, `enabledTypes`, `customPatterns`, հայտնաբերման հաշվիչներ |
| `PUT`  | `/api/settings/pii`      | Փոխարինել `enabledTypes` (`null` = բոլորը) and/or `customPatterns`    |
| `POST` | `/api/settings/pii/test` | Չորացնել մեկ օրինակ՝ առավելագույնը 8 KB նմուշի դեմ; ոչինչ չի պահվում  |

Երեքն էլ պահանջում են կառավարման վավերացում և մարմինը վավերացնել Zod ով (`src/shared/validation/schemas/piiSettings.ts`): Եթե մուտքն անջատված է (`requireLogin=false`) `GET`, և թեստի վերջնակետը բաց է, բայց `PUT` դեռ անհրաժեշտ է վահանակի նիստ, `manage` -scope API ստեղն, `oma_` մուտքի նշան՝ գրելու շրջանակով կամ ավելի բարձր, կամ CLI թոքեն կամ ներքին սպասարկման նշան, որն ուղարկվում է loopback-ից:

#### GDPR (EU) և POPIA (Հարավային Աֆրիկա) նույնացուցիչներ

| ID                  | Նույնացուցիչ                | Վավերացում                                                                        |
| ------------------- | --------------------------- | --------------------------------------------------------------------------------- |
| `iban`              | IBAN                        | Հայտնի երկիր, այդ երկրի ճշգրիտ երկարությունը, ISO 13616 MOD-97-10                 |
| `eu_vat`            | EU VAT համարը               | Անդամ-պետության հայտնի նախածանցը և այդ պետության համարի ձևաչափը (ոչ VIES որոնում) |
| `es_dni_nie`        | Իսպաներեն DNI / NIE         | Վերահսկիչ նամակ (արժեքի ռեժիմ 23); NIE `X/Y/Z` + 7 նիշ է                          |
| `it_codice_fiscale` | Իտալական Codice Fiscale     | Վերահսկիչ նամակ odd/even դիրքի աղյուսակներից                                      |

### Արագ ներարկում (`promptInjection.ts`)

Հայտնաբերում է հակառակորդ կառույցները օգտվողների կողմից տրամադրված բովանդակության մեջ և կիրառում է կազմաձևված քաղաքականությունը: Վարքագիծը պայմանավորված է շրջակա միջավայրի փոփոխականներով և կոնստրուկտորների ընտրանքներով.

| Կարգավորում       | Env var                                                                                                 | Կանխադրված | Էֆեկտ                                                                                                                                                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Միացված է         | `INPUT_SANITIZER_ENABLED`                                                                               | `true`     | Երբ `false`, պաշտպանական բազրիքը կարճ միանում է:                                                                                                                                                                            |
| Ռեժիմ             | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                         | `warn`     | Ներարկման քաղաքականություն՝ `block`, `warn` կամ `log`: (`redact` ընդունված է back-compat-ի համար, բայց ընդունում է** ոչ** շերտի ներարկման տեքստ; PII վերագրանցման հարցումը վերահսկվում է `PII_REDACTION_ENABLED` ի կողմից:) |
| Արգելափակման շեմը | `blockThreshold` տարբերակ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (alias `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`     | Արգելափակման համար պահանջվող նվազագույն խստությունը: Միջինը լռելյայն դեպքում միայն դիտարկելն է:                                                                                                                             |

**Ռեժիմի գերակայություն** (`getMode`)՝ կանչող `options.mode` → `INJECTION_GUARD_MODE`**DB հատկանիշի-դրոշի վերագրում** (Dashboard → Settings → Feature Flags) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env → `warn`. Հետևաբար, վահանակի անտեսումը հաղթում է env vars-ին, ուստի Feature Flags UI վերահսկում է վազող պահակը ուղիղ (առանց վերագործարկման): DB ընթերցումը անվտանգ է ձախողման համար. եթե այն սխալվում է, պահակը հետ է ընկնում env-ի վրա հիմնված վարքագծին, և երբ չի սահմանվում գերակայություն, վարքագիծը նույնական է env-միայն լուծմանը:

Հայտնաբերման աղբյուրներ.

1. `sanitizeRequest()` `@/shared/utils/inputSanitizer` ից (համօգտագործվող դետեկտորների հավաքածու, որն օգտագործվում է խողովակաշարի այլ վայրերում):
2. Ներկառուցված `DEFAULT_GUARD_PATTERNS` (ներկայումս `system_override_inline` և `markdown_system_block`, երկուսն էլ `high` խստություն):
3. Ընտրովի `customPatterns` փոխանցվում է կոնստրուկտորի ընտրանքների միջոցով (տողեր, ռեգեքս կամ `{ name, pattern, severity }` գրառումներ):

Երբ `mode === "block"`** և** առնվազն մեկ հայտնաբերում համապատասխանում է խստության շեմին, `preCall` վերադարձնում է `{ block: true, message: "Request rejected: suspicious content detected" }`: `warn`/`log` ռեժիմներում պահակային գծերը գրանցվում են, բայց թույլ են տալիս զանգը: Համօգտագործվող `evaluatePromptInjection()` օգնականը նաև արտահանվում է զանգահարողների համար, ովքեր պետք է գնահատեն հուշումները՝ առանց գրանցամատյան անցնելու:

**Սկան կապված (v3.8.20):** դետեկտորը միայն ստուգում է** առաջին 16 KB** միացված հուշագրի տեքստի — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 բայթ) `src/shared/utils/inputSanitizer.ts` ում: Ե՛վ `detectInjection()`, և՛ `evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` նախշերի հանգույցը գործարկելուց առաջ: Ներարկման հրահանգները տեղադրվում են մուտքի վերին մասում, ուստի սա փակում է regex CPU/GC հարյուրավոր ԿԲ ծանրաբեռնվածության վրա՝ առանց հայտնաբերման թուլացման (տես #3932, #4041):

### Հավատարմագրերի դիմակ (`credentialMasker.ts`)

Վազում է** երկուսն էլ** փուլերը, վերջինը լռելյայն շղթայում (առաջնահերթություն `95`): Վերականգնում է հայտնի API-բանալու / գաղտնի նշանի օրինաչափությունները ելքային բեռնվածքից (հաղորդագրությունների բովանդակություն, գործիքի կանչի փաստարկներ, գործիքի արդյունքներ)** և** մատակարարի պատասխանը, այնպես որ հավատարմագրերը, որոնք տեղադրվում են հուշման մեջ (կամ արձագանքվում են գործիքի արդյունքով) չեն արտահոսում վերին հոսքի մատակարարին կամ ետ հաճախորդին:

- **Միայն միանալ** , նույն կոնվենցիան, ինչ PII խմբագրումը (Հարդ կանոն #20- հարակից). անջատված է, եթե `settings.credentialRedactionEnabled === true`** կամ** `CREDENTIAL_REDACTION_ENABLED=true`. Անջատված լինելու դեպքում պաշտպանական բազրիքը ոչ-օպ — է այն երբեք չի արգելափակում և երբեք չի վերագրվում:
- `redactCredentials()` քայլում է ամբողջական payload/response ծառի վրա (`walkValue()`, նախատիպ-աղտոտման-անվտանգ, ցիկլով անվտանգ՝ `WeakSet` միջոցով) և փոխարինում է լուցկիները `[REDACTED:<type>]` տեղապահով՝ կլոնավորելով միայն իրականում փոխված ճյուղերը:
- `CREDENTIAL_PATTERNS` covers LLM provider keys (OpenAI, OpenAI-proj, Anthropic, Google, Hugging Face, Replicate), VCS/SaaS tokens (GitHub, Slack, Linear, Notion, npm, Postman, Discord), payment keys (Stripe, Square), cloud keys (AWS access key, Twilio, SendGrid, Mailgun), private keys / JWTs, credential-bearing connection strings (`mongodb://user:pass@...`, etc.), and a generic `Authorization`/`x-api-key`/`api-key`/`apikey` header-value pattern. Header-shaped keys (`authorization`, `x-api-key`, `api-key`, `apikey`) are redacted structurally (value only, scheme prefix like `Bearer `/`Basic ` preserved) rather than via the generic text regex.
- Պաշտպանական երկաթուղին երբեք չի արգելափակվում. այն միայն վերագրում է (`modifiedPayload` / `modifiedResponse`) և նշում (`meta.credentialsRedacted`, `meta.count`):

Հետընթաց պահակ՝ `tests/unit/credential-masker-guardrail.test.ts`.

## Բազային պայմանագիր (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true-ն կարճամիացնում է շղթան
  message?: string; // ցուցադրվում է արգելափակելիս
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // վերադարձվում է preCall-ից՝ հարցումը վերաշարադրելու համար
  modifiedResponse?: TValue; // վերադարձվում է postCall-ից՝ պատասխանը վերաշարադրելու համար
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

Guardrail-ը «փոփոխություն չկա» ազդանշան է տալիս՝ վերադարձնելով `void`, `{}` կամ
`{ block: false }`։ `modifiedPayload`/`modifiedResponse` վերադարձնելը
փոխարինում է շղթայով հոսող արժեքը հետևյալ guardrail-ների համար։
`signal?: AbortSignal`-ը կանչողի կյանքի ցիկլը տեղափոխում է guardrail-ներ։ Հարցման
abort-ը գիտակցված fail-open բացառություն է. մեդիա կամուրջները դադարեցնում են
աշխատանքը և մաքրում են ռեսուրսները՝ առանց հում մեդիան վերականգնելու այնպիսի
թիրախի վրա, որի մասին հայտնի է, որ այն չի աջակցում։

## Ռեեստր (`registry.ts`)

`guardrailRegistry` սինգլտոնը բացում է հետևյալը․

- `register(guardrail)` — ավելացնում է (կամ փոխարինում՝ ըստ նորմալացված անվան)
  guardrail և վերադասավորում աճող `priority`-ով։
- `clear()` / `list()` — վարչական օժանդակ մեթոդներ։
- `runPreCallHooks(payload, context)` — կրկնում է ակտիվ guardrail-ները,
  payload-ը թելադրում `modifiedPayload`-ի միջով և կանգնեցնում առաջին
  `block: true`-ի վրա։
- `runPostCallHooks(response, context)` — նույն հոսքը պատասխանի կողմում։
- `resetGuardrailsForTests({ registerDefaults })` — մաքրում է վիճակը և ըստ
  ցանկության վերագրանցում է լռելյայնները՝ մաքուր թեստային մեկուսացման համար։

Երկու runner-ներն էլ վերադարձնում են
`{ blocked, payload|response, results, guardrail?, message? }`, որտեղ
`results`-ը `GuardrailExecutionResult` գրառումների զանգված է, որն ընդգրկում է
յուրաքանչյուր guardrail-ի `blocked`, `skipped`, `modified`, `error` և `meta`
դաշտերը՝ օգտակար հետևելիության (tracing) համար։

### Guardrail-ների անջատում ըստ հարցման

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })`-ը հավաքում է
guardrail-ների անունների կրկնօրինակներից մաքրված ցուցակ, որոնք պետք է բաց
թողնվեն ընթացիկ հարցման համար։ Կա հինգ ալիք, որոնք կարդացվում են այս
հերթականությամբ և միավորվում մեկ ցուցակի մեջ (կրկնօրինակները մաքրելիս հաղթում
է առաջին հանդիպածը)․

1. `apiKeyInfo.disabledGuardrails`
2. Հարցման մարմնի `disabledGuardrails` (վերին մակարդակ)
3. Հարցման մարմնի `metadata.disabledGuardrails` (միայն երբ `metadata`-ն օբյեկտ է)
4. `x-omniroute-disabled-guardrails` վերնագիրը
5. Հին (legacy) `x-disabled-guardrails` վերնագիրը

Բոլոր հինգ ալիքները միավորվում են, ներառյալ երկու վերնագրերը. և՛
`x-omniroute-disabled-guardrails`, և՛ `x-disabled-guardrails` ուղարկելը բաց է
թողնում նրանց ցուցակների միավորումը, իսկ դատարկ ժամանակակից վերնագիրը այլևս չի
թաքցնում հինը
([#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412), շտկվել է
[#16805](https://github.com/diegosouzapw/OmniRoute/pull/16805)-ում)։

Արժեքները կարող են լինել տողերի զանգվածներ կամ ստորակետով բաժանված տող. անունները
կտրվում են (trim) և նորմալացվում փոքրատառ kebab-case-ի (`pii_masker` →
`pii-masker`), իսկ դատարկ գրառումները հեռացվում են։ Արդյունքը փոխանցվում է
`context.disabledGuardrails`-ի միջով ռեեստրին, որը բաց է թողնում
համապատասխանող guardrail-ները (`results`-ում `skipped: true`)։

Անջատման ցուցակը ազդում է միայն **ռեեստրի** վրա։ Prompt-injection `block`
ռեժիմը պարտադիր սահման է. injection-guard middleware-ը
(`src/middleware/promptInjectionGuard.ts`) կանչում է `evaluatePromptInjection()`-ը
առանց որևէ կանչողի կողմից կառավարվող անջատման ցուցակի (այն մեռած
`resolveDisabledGuardrails({ body })` կանչը, որն այն նախկինում կատարում էր,
հեռացվել է
[#16934](https://github.com/diegosouzapw/OmniRoute/pull/16934)-ում), ուստի
`prompt-injection`-ը անջատող հարցումը դեռևս մերժվում է `block` ռեժիմում։ Սա
միտումնավոր է։ Անջատման ալիքները կառավարվում են կանչողի կողմից (հարցման մարմին,
metadata, վերնագրեր), և կանչողը չպետք է կարողանա անջատել անվտանգության այն
վերահսկումը, որը սահմանել է օպերատորը
([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413))։
[#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412)-ից վերնագրերի
միավորումը փոխում է միայն այն, թե որ ռեեստրային guardrail-ներն են բաց թողնվում.
այն չի թույլ տալիս client-ին շրջանցել middleware-ը։ Պարտադիր per-key և
per-group guardrail քաղաքականությունները հետևվում են v4 RFC
[#16417](https://github.com/diegosouzapw/OmniRoute/issues/16417)-ում։
Տես [Ծածկույթը և սահմանափակումները](#coverage-and-limits)։

## Կատարման կարգ

Յուրաքանչյուր հարցման համար, որն անցնում է `src/sse/handlers/chat.ts` և
`open-sse/handlers/chatCore.ts` ֆայլերով (չաթ-ընտանիքի երթուղիները, որոնք թվարկված են
[Ծածկույթ և սահմանափակումներ](#coverage-and-limits) բաժնում).

1. `resolveDisabledGuardrails(...)`-ը կառուցում է բաց թողնման ցանկը API բանալուց,
   մարմնից և վերնագրերից։
2. `guardrailRegistry.runPreCallHooks(body, ctx)`-ը գործարկում է guardrail-ները աճող
   առաջնահերթության կարգով.
   - Անջատված guardrail-ները գրանցվում են որպես `skipped`։
   - Յուրաքանչյուր guardrail-ի `preCall`-ը կարող է վերագրել payload-ը `modifiedPayload`-ի միջոցով։
   - Առաջին `block: true`-ն ընդհատում է շղթան, և մշակիչը վերադարձնում է
     guardrail-ի մերժման պատասխան։
3. (Հնարավոր է՝ վերագրված) payload-ն անցնում է combo երթուղավորման և upstream
   ուղարկման փուլերին։
4. **Միայն ոչ հոսքային (non-streaming).** պատասխանը հավաքվելուց հետո
   `guardrailRegistry.runPostCallHooks(...)`-ը գործարկում է նույն շղթան պատասխանի
   վրա։ Այստեղ `block: true`-ն հեռացնում է upstream պատասխանը և վերադարձնում HTTP 400։ Հոսքային պատասխանները ամբողջությամբ բաց են թողնում այս քայլը։

Սխալ նետող guardrail-ները գրանցվում են `error: <message>`-ով և լոգավորվում
`logger.warn`-ի միջոցով, բայց շղթան շարունակվում է — ըստ նախագծի fail-open սկզբունքով։

## Ծածկույթ և սահմանափակումներ

Guardrail-ների ռեեստրը միացված է միայն չաթի pipeline-ին։ Այս սահմանափակումները
ամրագրված են `tests/unit/guardrail-pipeline-wiring-characterization.test.ts` և
`tests/unit/guardrail-pipeline-characterization.test.ts` թեստերով. վարքագիծը փոխվելիս
գիտակցաբար թարմացրեք այդ թեստերը։

### Որտեղ են գործարկվում hook-երը

| Hook / կառավարում                   | Որտեղ է գործարկվում                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `runPreCallHooks`                   | Հարցումներ, որոնք մշակվում են `handleChat`-ի կողմից (`src/sse/handlers/chat.ts`). `/v1/chat/completions`, `/v1/completions`, `/v1/messages`, `/v1/responses` (և `/v1/responses/*`), `/v1/relay/chat/completions`, `/v1/providers/{provider}/chat/completions`, `/v1/api/chat`, `/v1/antigravity`, `/v1beta/models/*` և Telegram-ի չաթի պրոքսին։ Ինչպես նաև վահանակի թեստային endpoint `/api/guardrails/test`։ Pre-call արգելափակումը վերադարձնում է HTTP 400։ |
| `runPostCallHooks`                  | **Միայն ոչ հոսքային** չաթի պատասխանների վրա (`open-sse/handlers/chatCore/nonStreamingResponse.ts`)։ Հոսքային պատասխանները երբեք չեն հասնում դրան։                                                                                                                                                                                                                                                                                                             |
| Հոսքային PII                        | `createPiiSseTransform` (`src/lib/streamingPiiTransform.ts`), միացված է `streamingPipeline.ts`-ում, երբ `PII_RESPONSE_SANITIZATION`-ը միացված է։ Դա guardrail չէ, ուստի անջատման ալիքները չեն ազդում դրա վրա։                                                                                                                                                                                                                                                 |
| Injection-guard middleware (հնացած) | Յուրաքանչյուր prompt պարունակող `/v1` երթուղի, ներառյալ չաթ-ընտանիքը (տես [երթուղիների ծածկույթ](#injection-guard-route-coverage--red-team-phase-8--block-d))։ Միայն prompt injection։                                                                                                                                                                                                                                                                        |

### Ինչը չի ծածկվում

- **Մեդիա, embeddings և տվյալների երթուղիներ** (`/v1/images/*`, `/v1/embeddings`,
  `/v1/audio/*`, `/v1/videos/generations`, `/v1/music/generations`,
  `/v1/rerank`, `/v1/search`, `/v1/moderations`) երբեք չեն հասնում ռեեստրին։ Այնտեղ
  չի գործարկվում PII-ի քողարկում, credential-ների քողարկում կամ modality bridge։ Նրանց
  միակ ստուգումը հնացած injection-guard middleware-ն է։
- **Հոսքային պատասխանները** չեն ստանում post-call guardrail-ներ՝ ոչ `pii-masker` կամ
  `credential-masker` post-call, և ոչ էլ post-call արգելափակում։ Կիրառվում է միայն
  հոսքային PII վերափոխումը (երբ `PII_RESPONSE_SANITIZATION`-ը միացված է)։ Հոսքային
  պատասխանում հետ ուղարկված credential-ը չի մաքրվում։
- **Անջատման ալիքներն ընդդեմ middleware-ի (ըստ նախագծի).** middleware-ը գնահատում է
  prompt injection-ը իր սեփական `evaluatePromptInjection()` կանչով՝ չփոխանցելով
  կանչողի կողմից վերահսկվող անջատման որևէ ցանկ։ `block` ռեժիմը պարտադիր սահման է, որը
  կանչողի կողմից վերահսկվող անջատումները չեն կարող շրջանցել, ներառյալ չաթ-ընտանիքի
  երթուղիներում
  ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413))։ `prompt-injection`-ի
  անջատումը միայն բաց է թողնում ռեեստրի guardrail-ը։

### Ինչն է տեսնում պատասխանը post-call-ից առաջ

Ոչ հոսքային ուղու վրա կարգը հետևյալն է՝ հիշողության արտահանում → ներկառուցված
գործիքի կատարում → post-call guardrail-ներ → post-call արգելափակման ելք →
semantic-cache-ի պահպանում։

- **Հիշողության արդյունահանումը** և **գործիքների կատարումը** տեսնում են պատասխանը, նախքան post-call պաշտպանիչ մեխանիզմները (guardrails) կկարողանան այն վերաշարադրել կամ արգելափակել: Սկսած [#16401](https://github.com/diegosouzapw/OmniRoute/pull/16401)-ից, հիշողության արդյունահանումը արդյունահանված տեքստն անցկացնում է `sanitizePII`-ի միջով, երբ `PII_RESPONSE_SANITIZATION`-ը միացված է (ինչպես հոսքային, այնպես էլ ոչ հոսքային ռեժիմներում), սակայն պատասխանը, որը post-call-ը հետագայում արգելափակում է, արդեն իսկ տրամադրվել է հիշողությանը և գործիքներին:
- **Սեմանտիկ քեշը** պատասխանը պահպանում է post-call-ից հետո, ուստի այն պահպանում է վերաշարադրված պատասխանը, իսկ արգելափակված պատասխանը երբեք չի քեշավորվում: Քեշի գրառումները բանալիացված են ըստ API բանալու:

## Կարգավորում

Ներկառուցված պահապանների (guardrails) կողմից կարդացվող միջավայրի փոփոխականներ.

| Փոփոխական                             | Օգտագործող                 | Ազդեցություն                                                                                               |
| ------------------------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`         | Սահմանեք `false`՝ հայտնաբերումն ամբողջությամբ անջատելու համար:                                             |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`         | Ներարկման քաղաքականություն՝ `warn`, `block` կամ `log`: Հին `redact` արժեքը չի վերագրում ներարկման տեքստը:  |
| `INJECTION_GUARD_MODE`                | `prompt-injection`         | Ներարկման պահապանի ռեժիմ. նաև DB feature flag, որը **գերակայում է** միջավայրի փոփոխականներին (DB > ENV):   |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`         | Լրջության նվազագույն մակարդակ, որը մերժվում է `MODE=block` դեպքում՝ `high` (լռելյայն), `medium` կամ `low`: |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`         | `INPUT_SANITIZER_BLOCK_THRESHOLD`-ի հին այլանունը:                                                         |
| `PII_REDACTION_ENABLED`               | `pii-masker`               | Երբ `true` է, հարցման PII-ն թաքցվում է (անկախ ներարկման ռեժիմից):                                          |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (ներքևի հոսք) | Կառավարում է պատասխանի կողմի մասկավորիչի վարքը:                                                            |

Modality Bridge պահապանները աշխատանքային (runtime) կարգավորումները կարդում են
DB-ի վրա հիմնված կարգավորումների պահոցից (`getSettings()`), այլ ոչ թե միջավայրի
փոփոխականներից: Vision-ի հիմնական բանալիներն են
`modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`,
`modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`,
`modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`,
`modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`,
`modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes` և
`modalityBridgeCacheMaxEntries`: Հին
`visionBridge*` բանալիները ընդունվում են միայն որպես փաստաթղթավորված մեկ ցիկլով
ընթերցման fallback. վահանակից (dashboard) գրառումներն օգտագործում են հիմնական
բանալիները: Լռելյայն արժեքներն ու fallback լուծիչը (resolver) գտնվում են
`src/shared/constants/modalityBridgeDefaults.ts` ֆայլում, իսկ հին հաստատունները
պահպանված են `src/shared/constants/visionBridgeDefaults.ts` ֆայլում:

Աուդիոն օգտագործում է `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`,
`modalityBridgeAudioTimeout` և `modalityBridgeAudioMaxClips` բանալիները՝ գումարած
ընդհանուր `modalityBridgeCache*` կարգավորումները: Աուդիոն չունի հին բանալիների
fallback, քանի որ այս բանալիները ներմուծվել են Modality Bridge սխեմայի հետ
միասին:

Վիդեոն օգտագործում է `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`,
`modalityBridgeVideoModel`,
`modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`,
`modalityBridgeVideoMaxVideos` և
`modalityBridgeVideoTimeout` բանալիները՝ գումարած ընդհանուր `modalityBridgeCache*`
կարգավորումները: Այն լռելյայն անջատված է, քանի որ FFmpeg/ffprobe-ը կամընտիր
օպերացիոն կախվածություններ են, իսկ կադրերի ենթագրումն ավելացնում է ուշացում և
մոդելի ծախս:

## Պատվերով Guardrail-ներ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

Քայլեր.

1. Ստեղծեք `src/lib/guardrails/myGuardrail.ts`՝ ընդլայնելով `BaseGuardrail`-ը։
2. Իրականացրեք `preCall` և/կամ `postCall`։
3. Կա՛մ գրանցեք import-ի պահին (push `registerDefaultGuardrails`-ից), կա՛մ
   կանչեք `guardrailRegistry.register(...)`-ը աշխատանքի ընթացքում — registry-ն
   փոխարինում է նույն նորմալացված անունով ցանկացած նախորդ guardrail-ի։
4. Ավելացրեք թեստեր `tests/unit/`-ում (առկա օրինակներ՝
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`)։

## Թեստավորում

Օգտագործեք `resetGuardrailsForTests()`-ը թեստերի միջև՝ հայտնի վիճակից սկսելու համար։
Փոխանցեք `{ registerDefaults: false }`՝ դատարկ registry-ով սկսելու և միայն
թեստավորվող guardrail-ները գրանցելու համար։ Vision Bridge-ը ընդունում է dependency
injection (`deps.getSettings`, `deps.callVisionModel`); Audio Bridge-ը բացում է
համարժեք seam-եր կարգավորումների, հնարավորությունների, STT մոդելի ընտրության,
credential-ների ստուգումների և տառադարձման համար։ Ուստի թեստերը կարող են ստուգել
երկու հոսքերն էլ՝ առանց DB կամ ցանցային հասանելիության։

## Injection-guard-ի route-ների ծածկույթ և red-team (Փուլ 8 · Բլոկ D)

Injection-guard-ը (`createInjectionGuard` / `withInjectionGuard`) ծածկում է բոլոր route-ները,
որոնք ընդունում են օգտատիրոջ prompt-ներ։ Այն հարգում է `INJECTION_GUARD_MODE`-ը
(լռելյայն `warn` = միայն log; `block` = վերադարձնում է HTTP 400 `SECURITY_001`)։

| Տիպ          | Route-ներ                                                                                                                                            | Լռելյայն ռեժիմ |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| Տեքստ (առկա) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn           |
| Գեներատիվ    | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn           |
| Տվյալներ     | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn           |

Տեքստի արդյունահանումը (`extractMessageContents`) ծածկում է `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`։

**Red-team (գիշերային, `nightly-llm-security.yml`):** promptfoo-ն վավերացնում է, որ յուրաքանչյուր
route արգելափակում է OWASP-LLM corpus-ը `INJECTION_GUARD_MODE=block` ռեժիմում. garak-ը գործարկում է
probe-ներ (բաց է թողնում առանց secret-ի)։ `moderations`-ը ներառված է համահունչության համար։
Block ռեժիմը պարտադիր սահման է. `evaluatePromptInjection()`-ը անտեսում է middleware-ի
կողմից փոխանցված ըստ հարցման անջատման ցուցակը, ուստի `disabledGuardrails`-ը **չի**
ազատում route-ը դրանից ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413))։

Գիշերային workflow-ն (`.github/workflows/nightly-llm-security.yml`, cron + ձեռքով
գործարկում) ունի երկու job.

- **`promptfoo-guard` (արգելափակող)** — գործարկում է `promptfoo eval -c promptfooconfig.yaml`՝
  `INJECTION_GUARD_MODE=block`-ով։ Յուրաքանչյուր adversarial դեպք (օրինակ՝ «անտեսիր բոլոր
  նախորդ հրահանգները…», DAN-ոճի jailbreak-ներ) պնդում է, որ պատասխանը պարունակում է
  `error.code === "SECURITY_001"`, այսինքն՝ guard-ը իրոք մերժել է հարցումը։
- **`garak` (խորհրդատվական)** — գործարկում է garak-ը `--probes promptinject,dan,leakreplay`-ով
  տեղական OmniRoute instance-ի դեմ (`http://localhost:20128/v1`)։ Կախված է provider-ի
  secret-ից (`PROMPTFOO_PROVIDER_KEY`); բաց է թողնվում սահուն և ունի `|| true`
  վերջածանց, ուստի զեկուցում է՝ առանց CI-ն ձախողելու։

Guard helper-ի (`createInjectionGuard` / `withInjectionGuard`) ծածկույթը
ընդգրկում է յուրաքանչյուր prompt կրող `/v1` route; prompt-ի տեքստը վերցվում է
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` դաշտերից
`extractMessageContents()`-ի միջոցով՝ `src/shared/utils/inputSanitizer.ts`-ում։
