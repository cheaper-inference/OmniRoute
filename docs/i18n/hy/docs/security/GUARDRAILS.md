> **Ճշմարտության աղբյուրը.** `src/lib/guardrails/`

Պաշտպանական պատնեշներն ապահովում են անվտանգության, քաղաքականության և բովանդակության փոխակերպումներ OmniRoute և հոսանքին հակառակ մատակարարների միջև: Յուրաքանչյուր պաշտպանիչ երկաթուղի կարող է ստուգել (և ըստ ցանկության մերժել, վերափոխել կամ ծանոթագրել) պահանջել օգտակար բեռներ (`preCall`) և վերին հոսքի պատասխանները (`postCall`):

Համակարգն է** ձախողել-բաց** Եթե կատարման ընթացքում պահակային բազրիքը նետվում է, գրանցամատյանը գրանցում է սխալը և շարունակում է հաջորդ պահակային բազրիքով, այլ ոչ թե հարցումը ձախողելու: Արգելափակումը բացահայտ որոշում է (`block: true`), երբեք պատահականություն: Մի բացառություն է ընդհատված խնդրանքը. երբ զանգահարողի `signal` ընդհատվում է, գցող պաշտպանական բազրիքը մերժում է կեռիկի վազքը՝ բաց թողնելու փոխարեն:

Կեռիկներն անում են** ոչ** վազել յուրաքանչյուր երթուղու կամ յուրաքանչյուր պատասխանի վրա: Կարդացեք [Ծածկույթը և սահմանափակումները](#coverage-and-limits) ՝ նախքան որպես անվտանգության հսկողություն հենվելը պաշտպանիչ բազրիքին:

## Ներկառուցված Պահակներ

Ռեեստրն ավտոմատ կերպով բեռնում է այս պաշտպանիչ բազրիքները ներմուծման ժամանակ առաջնահերթ կարգով (տես `registry.ts` → `registerDefaultGuardrails()`):

| ----------------- | ------------------- | -------------- | ------------------------- |
| `1`               | `agent-guard`       | `preCall`      | `agentGuard/guardrail.ts` |
| `5`               | `vision-bridge`     | `preCall`      | `visionBridge.ts`         |
| `6`               | `audio-bridge`      | `preCall`      | `audioBridge.ts`          |

| `95`              | `credential-masker` | `pre` + `post` | `credentialMasker.ts`     |

Ստորին առաջնահերթ համարները գործարկվում են** առաջին** .

### Vision Bridge (`visionBridge.ts`) — Modality Bridge PR-1

GLM 5.3 բազային մոդելը և `glm-5.3-{low,high,max}` ունեն հստակ `supportsVision:false` registry/spec մետատվյալներ: GLM 5.3 Flash տարբերակները մնում են հայրենի տեսողության մոդելներ: Claude Code-ի `/v1/messages` երթուղին մտնում է ընդհանուր `handleChat` նախնական զանգի պահակային շղթա** առաջ** Claude-to-OpenAI թարգմանություն; Nested `Read` գործիքի արդյունքի պատկերները պետք է նկարագրվեն կամ մշակվեն, նախքան թարգմանությունը դրանք վերածի OpenAI `image_url` բովանդակության (#17069):

Ընդհատում է պատկերներ կրող հարցումները, որոնք ուղղված են** ոչ տեսողական մոդելներ** և կամ վերաուղղորդում է ամբողջ հարցումը դեպի տեսողություն ունեցող մոդել, կամ փոխարինում է պատկերի մասերը տեքստային նկարագրություններով, որոնք արտադրվել են կարգավորելի տեսողության մոդելի կողմից մինչև վերին հոսքի զանգը: Սա թույլ է տալիս միայն տեքստային մատակարարներին թափանցիկ կերպով կառավարել բազմամոդալ ծանրաբեռնվածությունը:

Հոսք:

1. Բաց թողնել, եթե թիրախային մոդելն արդեն աջակցում է տեսլականին (եթե այն չի երևում պարտադիր կամուրջների ցանկում `isVisionBridgeForcedModel`):
2. Արտահանեք պատկերի մասերը `extractImageParts(messages)` (`visionBridgeHelpers.ts`) միջոցով, որը պատվիրակում է** միասնական մեդիա դետեկտոր** `detectMediaParts()` ն `open-sse/utils/mediaParts.ts` — ում ճշմարտության միակ աղբյուրն է, որը համօգտագործվում է համատեղելիության ֆիլտրի հետ: Արդյունահանումը թույլատրված է այն ձևերին, որոնք `replaceImageParts` կարող է միաձուլվել (քաղվածքը ↔ փոխարինում է պայմանագրին). OpenAI `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"` և պատասխաններ API `input_image`: Claude Code `tool_result.content` ի և Responses գործիքի ելքերում տեղադրված համապատասխան պատկերները նույնպես հանվում և փոխարինվում են իրենց սկզբնական ուղիներով. Միայն ցուցիչով ձևերը համակցված զտիչ նյութ են և չեն արդյունահանվում: Բաց թողնել, եթե ոչ մեկը չի գտնվել:
3. Լուծել գործարկման ժամանակի կազմաձևումը `resolveVisionBridgeRuntimeSettings()` միջոցով (`src/shared/constants/modalityBridgeDefaults.ts`). նոր `modalityBridge*` կարգավորումների ստեղները հաղթում են; ժառանգական `visionBridge*` ստեղները մնում են ա** մեկ ցիկլով հետադարձ** (հետադարձ պատուհան): Բաց թողնել ցանկացած մեդիա անցում, երբ կամուրջն անջատված է:
4. Ռեժիմի ընտրիչը (`modalityBridgeVisionMode`, տե՛ս ստորև բերված աղյուսակը) որոշում է վերափոխումը և նկարագրությունը: Reroute-ը վերադարձնում է `modifiedPayload` միայն `model` փոխանակմամբ, գումարած meta `{ rerouted, fromModel, toModel, imagesKept }`:
5. Նկարագրեք ուղին. կափարիչ պատկերներ `maxImages` ում, կազմեք առաջադրանքի տեղյակ հուշումը, խորհրդակցեք նկարագրության քեշի հետ, զանգահարեք տեսողության մոդելը** զուգահեռաբար** (`Promise.allSettled`), և դրանց տեղում ներարկեք `[Image N]: <description>` տեքստային մասեր: Անհաջող նկարագրությունը տալիս է `null`. չմշակված պատկերը պահպանվում է unknown/vision-capable թիրախների համար (#4012), բայց a** հաստատված է միայն տեքստային ուղղակի թիրախ** կամ zero-vision կոմբինատը ստանում է բացահայտ `(unavailable — no vision-capable provider connected)` տեքստի կոճղ յուրաքանչյուր չնկարագրված պատկերի համար, ներառյալ մասնակի ձախողումները և նկարագրության զանգի գլխարկից դուրս գտնվող պատկերները (#17069): Գոյություն ունեցող բոլոր ձախողված կոմբինատի նկարագրությունը մնում է տեղում (#8430):
6. Վերադարձեք `modifiedPayload` + meta (`imagesProcessed`, `descriptions`, `processingTimeMs`, `visionModel`).

#### Ռեժիմի ընտրիչ (`modalityBridgeVisionMode`)

| Ռեժիմ      | Կանխադրված | Վարքագիծ                                                                                                                                                                                                                                                                       |
| ---------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`     | ✔          | Legacy heuristic, untouched (#6640/#7204). ոչ համակցված/`auto/` մոդելները վերափոխվում են դեպի լավագույն տեսողության մոդելը, եթե սկզբնական մոդելն արդեն չունի օգտագործելի հավատարմագրեր (այնուհետև նկարագրեք); համակցված թիրախները միշտ նկարագրում են:                          |
| `describe` |            | Միշտ նկարագրեք — վերերթուղու բլոկն ամբողջությամբ բաց է թողնվել. օգտատիրոջ ընտրած մոդելը միշտ պատասխանում է.                                                                                                                                                                    |
| `reroute`  |            | Հարկադիր վերափոխում. պահապանը շրջանցվում է: Վերափոխումը -** թիրախ** հավատարմագրային պահակախումբը դեռևս կիրառում է — երբ չկա օգտագործելի տեսողության թիրախ, կամուրջը արգելափակում է հստակ սխալով, այլ ոչ թե հում պատկերները նկարագրելով կամ ուղարկելով միայն տեքստային թիրախին: |

Հարկադիր ռեժիմների կարճ միացում** առաջ** ավտոմատ էվրիստիկ վազք; `auto` վարքագիծը բայթ-նույնական է pre-PR-1 ի պաշտպանիչ բազրիքին:

#### API-բանալու շրջանակ (`visionBridgeKeyScope.ts`)

Երբ զանգահարողի API ստեղնը սահմանափակում է `allowedConnections`, քվոտա լողավազաններ (`allowedQuotas`) կամ մոդելներ (`allowedModels` / `blockedModels` / `modelAccessMode: "restricted"` / `disableNonPublicModels`), կամուրջը ընտրում է միայն վերափոխման երթուղին և նկարագրում է այն մոդելները, որոնք կարող է օգտագործել բանալին, իսկ միացումների վրա՝ բանալին կարող է օգտագործել: Այնուհետև նկարագրված զանգը միշտ անցնում է OmniRoute ինքնահոսքի միջով `x-omniroute-self-loop-key-id` վերնագրով, այնպես որ ստացող զրույցի հարցումը նորից կիրարկում է այդ բանալու կապը և մոդելի քաղաքականությունը: `enforceApiKeyPolicy()` հարգում է այդ վերնագիրը միայն ինքնահանգույցի կրիչի հետ միասին, ուստի այն կարող է միայն նեղացնել մուտքը, և id-ն, որը չի լուծվում, մերժվում է:

Եթե տեսողության ոչ մի մոդել չի թույլատրվում բանալին, ա** հաստատված միայն տեքստային թիրախ** մերժում է պատկերի հարցումը լոկալ՝ հստակ HTTP 400-ով, փոխարենը պատկերի բայթերը փոխանցելու անկարող հոսանքին (#17069): Անհայտ կամ բնիկ տեսողության հնարավորություն ունեցող թիրախների համար նկարագրության ուղին պահպանում է իր նախկին վարքագիծը խափանման պատճառով (meta `{ skipped: true, reason: "no_permitted_vision_model" }`): Առանց բանալիի հարցումները և առանց այս սահմանափակումների բանալիներն իրենց պահում են ճիշտ այնպես, ինչպես նախկինում:

#### Առաջադրանքների տեղյակ նկարագրության հուշում (`modalityBridgeVisionTaskAware`)

Կանխադրված** ճշմարիտ** . `composeVisionPrompt()` (`visionBridgeHelpers.ts`) կցում է տեքստը** վերջին օգտվողի հաղորդագրությունը** (կտրված է 500 նիշով) բազային նկարագրության հուշումը՝ ուղղորդելով նկարագրությունը դեպի այն, ինչ իրականում խնդրել է օգտատերը (codex-vision-proxy pattern) և խնդրելով տեսողության մոդելին արտագրել տեսանելի տեքստը: Եթե դրոշն անջատված է — կամ ոչ օգտվողի տեքստ — բազային հուշումն օգտագործվում է անփոփոխ:

Նկարագրված ինքնակարգավորման սեփական OpenAI-ի հետ համատեղելի հարցումը (`callVisionModelSingle()` in `visionBridgeHelpers.ts`) միշտ պահանջում է `image_url.detail: "high"` — անվերապահորեն, յուրաքանչյուր caller/provider համար, որը փակված չէ որևէ հաճախորդի ազդանշանի վրա: Ցածր մանրամասների նմուշառումը նվազեցնում է OCR ճշգրտությունը հենց տեքստի տառադարձման առաջադրանքի համար, որը պահանջում է այս հրահանգը, ուստի նկարագրության զանգն ինքնին միշտ պահանջում է բարձր մանրամասնություններ՝ անկախ նրանից, թե որ մանրամասների մակարդակն է օգտագործվել սկզբնական մուտքային հարցումը: Սա ազդում է միայն ներքին նկարագրության հարցման մարմնի վրա. այն չի փոխում, թե ինչպես է OmniRoute ուղարկում զանգահարողի սեփական `image_url.detail` — առաջնային հարցումով, որը լռելյայն կիրառվում է առանձին, և միայն հայտնաբերված OpenCode հաճախորդների համար՝ `defaultImageDetail()` ում (`open-sse/handlers/chatCore/upstreamBody.ts`): Describe self-loop-ի Anthropic լարային ձևաչափի ճյուղը չունի `detail` դաշտ և չի ազդում լռելյայն որևէ մեկի վրա:

#### Նկարագրեք ելքային գլխարկը (`modalityBridgeVisionMaxChars`)

| Բանալին                        | Կանխադրված | Շրջանակ           |
| ------------------------------ | ---------- | ----------------- |
| `modalityBridgeVisionMaxChars` | `0`        | `0` կամ 100–50000 |

`0` (կանխադրված) նշանակում է** ոչ մի գլխարկ** — `callVisionModel()` ով վերադարձված նկարագրությունը փոխանցվում է չփոփոխված՝ պահպանելով գոյություն ունեցող վարքագիծը: 100–50000 միջակայքի ցանկացած արժեք կրճատում է նկարագրությունը `…` վերջածանցով, նախքան այն ետ կցվում է որպես `[Image N]: <description>` (`VisionBridgeGuardrail.preCall()` in `src/lib/guardrails/visionBridge.ts`): Բարձրացրեք սա մանրամասներով ծանր OCR առաջադրանքների համար, որտեղ ներքևի մոդելին անհրաժեշտ է ամբողջական տառադարձում. իջեցրեք այն մինչև կապակցված նշանի օգտագործումը շատախոս տեսողության մոդելներում: Վահանակի դաշտը ապրում է Vision ներդիրի Ընդլայնված վահանակի վրա (`modality-bridge-max-chars` in `ModalityBridgeVisionTab.tsx`) և սեղմում է ցանկացած արժեք 1-ից 99-ի միջև մինչև 100 հարկ, մինչդեռ բացահայտ `0` անձեռնմխելի է թողնում — `0` ինքնին վավեր Zod արժեք է (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), ոչ միայն «չսահմանված» կանխադրվածը:

#### Նկարագրեք քեշը (`modalityBridge/bridgeCache.ts`)

Հիշողության մեջ LRU + TTL քեշը ելքերը նկարագրելու համար, ընդհանուր գործընթացում: Բանալի = `sha256(imageRef + composedPrompt + configuredBridgeModel)` երկարության նախածանցով շրջանակով (դաշտ-սահմանային բախումներ չկան): Մոդելի բաղադրիչն է** կազմաձևված** կամուրջի մոդելը, այլ ոչ թե այն մոդելը, որն իրականում պատասխանել է — `callVisionModel`, կարող է ներսից հետ ընկնել, և յուրաքանչյուր փորձի համար ստեղնավորումը կմասնատեր քեշը: Չհաջողված նկարագրությունները երբեք չեն պահվում քեշում: Կարգավորումներ:

| Բանալին                         | Կանխադրված | Շրջանակ |
| ------------------------------- | ---------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`     | —       |
| `modalityBridgeCacheTtlMinutes` | `60`       | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`      | 10–5000 |

#### Հեռավոր պատկերի նորմալացում (self-loop describe/base64 fetch)

Երբ կամուրջը բերում է ա** հեռավոր** պատկերն ինքնին — the Anthropic նկարագրում է ինքնազանգը և claude-wire-format base64 փոխակերպումը (`ensureBase64ImagesForClaudeWire`), երկուսն էլ `fetchRemoteImageAsDataUri()` միջոցով `visionBridgeHelpers.ts` — ում ստացված տվյալները URI փոխանցվում են `normalizeDataUri()` (`open-sse/utils/imageNormalize.ts`) միջով, նախքան vision-model հարցումը ներկառուցվելը: Չափերի չափի պատկերները կրճատվում են a** 2048 px երկար եզր** (համապատասխանում է չափափոխման գլխարկին OpenAI/Anthropic արդեն կիրառվում է սերվերի կողմից), որը կրճատում է վերբեռնումը bytes/latency առանց փոխելու այն, ինչ տեսնում է տեսողության մոդելը: Չափափոխումը օգտագործում է `sharp`, որը բեռնված է դինամիկ ներմուծման միջոցով. հարթակում, որտեղ նրա բնիկ երկուականը չի բեռնվում, `normalizeDataUri()`** երբեք չի նետում** — այն վերադառնում է դեպի սկզբնական բայթերի անցում, ուստի describe/base64-conversion ուղին միշտ շարունակում է աշխատել: Ոչ պատկերային բայթերը (վերաբերում, որը չի վերադարձրել վերծանվող պատկեր) նույնպես փոխանցվում են անձեռնմխելի: Այս նորմալացումը նախատեսված է այն պատկերների համար, որոնք կամուրջը վերցնում է իր ինքնազանգման համար — այն երբեք չի կիրառվում զանգահարողի չմշակված անցումային ծանրաբեռնվածության վրա, որը համահունչ է միայն ընտրված մուտացիայի սկզբունքին (Hard Rule #20):

#### Կարգավորումների սխեման + միգրացիա

Նոր `modalityBridge*` ստեղները Zod-ով վավերացված են `updateSettingsSchema` (`src/shared/validation/settingsSchemas.ts`)՝ `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCache*` եռյակը և `modalityBridgeAudio*` խումբը, որն օգտագործվում է Audio Bridge-ի կողմից։ Միգրացիան `141_modality_bridge_settings.sql` պատճենում է գոյություն ունեցող `visionBridge*` արժեքները համապատասխան նոր ստեղների վրա (idempotent, երբեք չի վերագրում օպերատորի կողմից սահմանված `modalityBridge*` արժեքը); ժառանգված ստեղները մնում են ընդունված որպես մեկ թողարկման շրջանի ընթերցման հետադարձ տարբերակ:

#### Թափանցիկության վերնագրի + վիճակագրություն

Նկարագրել-փոխակերպված պատասխանները կրում են `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` (կառուցված `buildModalityBridgeHeader()` ի կողմից `modalityBridge/bridgeStats.ts` ում, դրոշմված `withModalityBridgeHeader()` ով `src/sse/handlers/chatHelpers.ts` ում): Վերաուղղորդված հարցումները ստանում են** ոչ** վերնագիր — ծանրաբեռնվածությունն անձեռնմխելի էր, և մոդելի փոխանակումն արդեն տեսանելի է պատասխան մարմնի `model` դաշտում:

`GET /api/modality-bridge/stats` (կառավարման auth, նույն մակարդակը, ինչ `GET /api/settings`) վերադարձնում է հիշողության մեջ մեկ մոդալության հաշվիչներ `{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs, latencySamples, averageLatencyMs, lastUsedAt }` `vision`, `audio` և `video` համար: `averageLatencyMs` օգտագործում է `latencySamples`, ոչ բոլոր փորձերը, որպես իր հայտարար. առանց ժամանակացույցի գործողությունը զրոյական միլիվայրկյանանոց նմուշ չի ստեղծում: `bridged` մնում է հաջող փոխարկումների համար հետհամատեղելի կեղծանունը. անհաջող փորձերը չեն ավելացնում այն: Գործընթացի վերագործարկման ժամանակ հաշվիչները վերականգնվում են նախագծով (հեռաչափություն, ոչ հաշվառում):

#### Վահանակի կազմաձևում

Նվիրված վահանակի էջը `/dashboard/settings/modality-bridge` է: Դրա URL-հասցեավոր `Vision`, `Audio` և `Video` ներդիրները պահպանում են հարցման պարամետրերը `tab` արժեքը փոխելու ընթացքում: Vision ներդիրը բացահայտում է միացումը, ռեժիմը, մոդելի ընտրությունը (ներառյալ ավտոմատ լռելյայն), առաջադրանքների մասին տեղեկացված հուշումները, timeout/image/description-length/cache առաջադեմ սահմանափակումները, գործարկման ժամանակի հաշվիչները և պահպանված նմուշի հարցումը: Աուդիո ներդիրը նույնպես ակտիվ է. այն բացահայտում է միացումը, միայն STT մոդելի ընտրիչը Auto-ով, timeout/max-clip սահմանաչափեր, աուդիո հաշվիչներ և `input_audio` նմուշի թեստ: «Վիդեո» ներդիրը գործում է. այն հայտնում է FFmpeg/ffprobe գործարկման վիճակի մասին — չորս հստակ UI վիճակներից մեկը (`unknown`, երբ զոնդը թռիչքի մեջ է կամ չի կարող ավարտվել, `restricted` ոչ շրջադարձային վահանակի հոսթինգի վրա, որտեղ զոնդը բաց է թողնվել հաճախորդի կողմից, `unavailable` մեկ անգամ զոնդավորվել և հաստատվել է, որ բացակայում է, կամ `available` — FFmpeg/ffprobe մոդելների ընտրողների տարբերակների համար): տեսողության enable/model/frame/video/timeout մոդելներ և բացահայտում է վիդեո հաշվիչները:

Նախկին Vision Bridge քարտը AI կարգավորումներում համատեղելիության հղում է դեպի նոր էջի; այն այլևս չունի ձևի երկրորդ օրինակը: Media Providers-ը նաև կապում է Image-to-Text և Speech-to-Text աշխատանքային հոսքերը համապատասխան Modality Bridge ներդիրներին՝ չհեռացնելով գոյություն ունեցող Speech-to-Text խաղահրապարակը:

**Self-loop ընդունման շրջանցում.** երբ նկարագրված զանգի երթուղիներն անցնում են OmniRoute ի սեփական `/v1` ինքնահանգույցով (ոչ ստանդարտ մատակարարի մոդել), ենթահարկն ուղարկում է `x-omniroute-admission-bypass: internal` և վավերացվում է լուծված ինքնահանգուցային հավատարմագրով — տեղական `sk_omniroute` sentinel-ը տեղական ռեժիմում կամ օպերատորի կողմից կազմաձևված `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` env ստեղնը (#1350) դեռ կարող է գործարկել `REQUIRE_API_KEY=true` զանգը: Շրջանցումը հարգվում է միայն այդ ճշգրիտ հավատարմագրերի համար, ուստի արտաքին հաճախորդները չեն կարող օգտագործել վերնագիրը՝ մուտքը բաց թողնելու համար:

Ժառանգական կանխադրումները ապրում են `src/shared/constants/visionBridgeDefaults.ts` ում; նոր mode/task-aware/cache կանխադրվածները և կարգավորումների լուծիչը գործում են `src/shared/constants/modalityBridgeDefaults.ts` ում: Պաշտպանական բազրիքը բացահայտում է `deps` կոնստրուկտորի տարբերակը, որպեսզի թեստերը կարողանան կեղծ `getSettings` և `callVisionModel` իրականացումներ ներարկել:

### Աուդիո կամուրջ (`audioBridge.ts`) — Modality Bridge PR-3

Ընդհատում է աուդիո կրող զրույցի հարցումները, նախքան դրանք հասնում են թիրախին, որը հայտնի չէ, որ ընդունում է աուդիո մուտքագրումը: Այն երբեք չի փոխում զրույցի հարցումը. աուդիո մասերը տառադարձվում են գոյություն ունեցող OpenAI-ի հետ համատեղելի բազմամաս վերջակետի միջոցով, և ընտրված զրույցի մոդելը շարունակվում է տեքստային տառադարձումներով:

Հոսք:

1. Լուծիր `supportsAudio` `getResolvedModelCapabilities()` միջոցով: Հաղթում է բացահայտ մատակարար-ռեգիստրի մետատվյալները, այնուհետև ստատիկ մոդելի մետատվյալները, այնուհետև համաժամեցված `modalities_input`: Հայտարարված մուտքագրման ցուցակն առանց `audio` ն `false` է; ոչ մի կարողության ապացույց չի մնում `null`. Ե՛վ `false`, և՛ `null` ակտիվացնում են պահպանողական կամուրջը, մինչդեռ `true` շրջանցում է այն։
2. Լուծեք `modalityBridgeAudio*` կարգավորումները և յուրաքանչյուր հաղորդագրությունից հանեք վերին մակարդակի աուդիո մասերը համօգտագործվող `detectMediaParts()` դետեկտորի միջոցով: Աջակցվող մետաղալարերի ձևերն են OpenAI `input_audio`, `audio_url` և `source.media_type: "audio/*"`: Ներդրված ձայնը հայտնաբերվում է երթուղման համար, բայց չի հեռացվում միացման ճանապարհով: Աշխատանքը սահմանափակված է `modalityBridgeAudioMaxClips` ով; հետագա մասերը մնում են անձեռնմխելի:
3. Հարգեք կազմաձևված `provider/model` կամ թույլ տվեք `selectAudioBridgeModel()` քայլել `AUDIO_TRANSCRIPTION_PROVIDERS` կայուն կատալոգի կարգով և ընտրել առաջին մոդելը, որն ունի օգտագործելի ակտիվ մատակարարի հավատարմագիր:
4. `callAudioTranscription()` base64/data-URI աուդիոը փոխակերպում է բազմամասանի `file` կամ ներբեռնում է հեռակառավարվող `audio_url` միայն հանրային ելքային պաշտպանիչի միջոցով DNS ամրացմամբ և 25 MB կապով: Այնուհետև այն POSTs ֆայլը և ընտրված մոդելը տեղական `/v1/audio/transcriptions` ինքնատիրույթի մեջ՝ վավերացված `resolveSelfLoopBearer()` ով: Գոյություն ունեցող տառադարձման երթուղին իրականացնում է հավատարմագրերի նորմալ որոնում, cooldown/rate-limit մշակում և մատակարարի առաքում:
5. Հաջողված զանգերն իրենց մասերը փոխարինում են `[Audio N]: <transcript>` ով: Զանգերը գործարկվում են `Promise.allSettled` ով. անհատական ձախողումը պահպանում է այդ սկզբնական աուդիո մասը (#4012 պայմանագիր): Եթե յուրաքանչյուր զանգ ձախողվի, և թիրախն ապացուցվի `supportsAudio === false`, մասերը դառնում են `[Audio N]: (unavailable — no STT provider connected)` (#8430 պայմանագիր): Անհայտ թիրախի համար (`null`) անհաջող արդյունքը մնում է անձեռնմխելի: Միայն տեքստով ապացուցված թիրախը, որն առանց օգտագործելի STT հավատարմագրի, ստանում է նույն բացահայտ կոճակը՝ առանց ցանցային զանգ տալու:

Հաջող տառադարձումներն օգտագործում են գործընթացի լայնածավալ Modality Bridge LRU/TTL քեշը: Բանալին միավորում է աուդիո տեղեկանքը, կայուն `audio-transcription` գործողության պիտակը և ընտրված STT մոդելը; ձախողումները երբեք չեն պահվում: Ձայնային փորձերը թարմացնում են ընդհանուր `bridged`, `cacheHits`, `failures` և `lastUsedAt` հաշվիչներ: Փոխակերպված պատասխանները կրում են `x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>`; չձեռնարկված հարցումները չեն ստանում Audio Bridge հատված:

Runtime-ի կարգավորումները DB-ով ապահովված են և Zod-ով վավերացված.

| Բանալին                       | Կանխադրված | Շրջանակ         |
| ----------------------------- | ---------- | --------------- |
| `modalityBridgeAudioEnabled`  | `true`     | —               |
| `modalityBridgeAudioModel`    | `""`       | Ավտո կամ STT ID |
| `modalityBridgeAudioTimeout`  | `60000`    | 1000–300000     |
| `modalityBridgeAudioMaxClips` | `3`        | 1–10            |

Համօգտագործվող քեշը շարունակում է վերահսկվել `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes` և `modalityBridgeCacheMaxEntries` կողմից:

### Video Bridge (`videoBridge.ts`, `videoBridgePipeline.ts`)

Ընդհատում է վերին մակարդակի վիդեո մասերը Chat Completions `messages` ում և Responses API `input` ում, նախքան թիրախը, որը հայտնի չէ բնիկ տեսաաջակցությամբ: Աջակցվող ձևերն են `input_video`, `video_url`, `video_source`, HTTPS URLs և `data:video/*;base64,...` տվյալների URIs: Պարզ ֆայլերի անունները տեքստում չեն դիտվում որպես տեսանյութ:

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`)-ին է պատկանում հարցումների անցումը, capability/policy ստուգումը, յուրաքանչյուր հարցման համախմբումը և պատասխանի օգտակար բեռը: Մեկ տեսանյութի աշխատանքի համար — ձեռքբերում, ամբողջ արդյունքի քեշը, որը նկարագրում է կադրերի հաջորդականությունը (որը միաձուլում է զանգահարողի կողմից հայտարարված ցանկացած աուդիո սղագրություն) և յուրաքանչյուր փորձի արդյունքում metrics/abort/cleanup — թաքնված է `processVideoPart` հետևում `videoBridgePipeline.ts` ում, որը կոչվում է մեկ անգամ յուրաքանչյուր տեսանյութի մասում `preCall` ի օղակում: Այդ մոդուլը նաև սահմանում է բացահայտ պորտի սահմանները `VideoMediaBrokerPort` (բայթերի ձեռքբերում և նմուշառված շրջանակների արդյունահանում), `VideoAudioTranscriptionPort` (զանգահարողի կողմից հայտարարված աուդիո տառադարձման միաձուլումը ընտրված ենթագրերի հետ) և `VideoDrilldownPort` (հումքային պահեստի ձևը): Արտադրության STT և շրջանակի պահպանումը կազմված են նկարագրող պորտի շուրջ `createVideoSttAdapter` և `createVideoDrilldownAdapter` միջոցով; վերջինս օգտագործում է ընդհանուր անթափանց բռնակով կյանքի ցիկլը:

Հանրային `/v1` հարցումների ուղին երբեք չի ներմուծում կամ կանչում ենթապրոցեսը: Հեռավոր տեսանյութերը ներբեռնվում են 50 MiB սահմանով; inline base64 տեսահոլովակները ունեն պահպանողական 36 MiB վերծանված յուրաքանչյուր տեսանյութի գլխարկ, այնպես որ model/messages/framing ծրարը կարող է մնալ հանրային JSON խնդրանքի ընդունման սահմանաչափի ներսում՝ 50 MiB: Ներդիր երկարության և վերծանված չափերի գնահատումները ստուգվում են նախքան տեղաբաշխումը: HTTPS պահանջվում է սկզբնական հեռակառավարման URL և յուրաքանչյուր վերահղման վրա՝ օգտագործելով գոյություն ունեցող բացառապես հանրային ելքային պահակը DNS ամրացմամբ: Այնուհետև բայթերն անցնում են `POST /api/modality-bridge/video/extract` բրոքերի ճշգրիտ ներքին սահմանը: Այդ երթուղին և՛ `LOCAL_ONLY` է, և՛ `SPAWN_CAPABLE`, ընդունում է միայն յուրաքանչյուր գործընթացի կողմից վավերացված, վստահելի հանգույցի վերադարձի հարցում և երբեք չի ընդունում URL, ֆայլային համակարգի ուղի, գործարկվող կամ փաստարկների ցանկ: API մարմնի չափի խողովակաշարը և կարգավորիչի աճող մարմնի ընթերցիչը ինքնուրույն են կիրառում 50 MiB բրոքերի մուտքագրման գլխարկը: Դրա սահմանափակ հերթը միաժամանակ կատարում է մեկ արդյունահանում, թույլ է տալիս չորս սպասող աշխատանք և փակում է սպասվող մուտքը 100 MiB ով:

Բրոքերի ներսում `ffprobe` կարդում է մասնավոր տեղական ֆայլ; ֆիքսված ձևաչափի թույլտվության ցանկը բացառում է երգացանկի և մանիֆեստի ձևաչափերը: Թույլատրված MOV-ընտանեկան կոնտեյներների համար արտաքին MOV տվյալների հղումները մնում են լռելյայն անջատված, և ֆիքսված հրամանը չի մասնակցում դրանց: Ե՛վ `ffprobe`, և՛ `ffmpeg` օգտագործում են `file` -only արձանագրության սպիտակ ցուցակը, մեկ շարանը, ֆիքսված արգումենտների զանգվածները, առանց կեղևի և `PATH` ից լուծված գործադիրներ: Կցված նկարի շապիկի հոսքերը նվագարկվող թեկնածուներ չեն: Բոլոր նվագարկվող հոսքերը պետք է բավարարեն սահմանները, և նախընտրելի է հստակ կանխադրված հոսքը նախքան որոշիչ ամենացածր ինդեքսով հետադարձը: Տեսանյութերը սահմանափակված են 600 վայրկյանով, 8192 պիքսել մեկ հարթությունում և 33554432 աղբյուրի պիքսել: FFmpeg նմուշառում է 1–16 միջնակետ JPEG շրջանակներ, մեծացնում է երկար եզրը մինչև առավելագույնը 1024 պիքսել՝ առանց ավելի փոքր մուտքերի մեծացման և երբեք չի ստանում URL: Նմուշառումը լռելյայնորեն `uniform` է: Ընտրովի `scene_aware` և փորձարարական `segment_aware` քաղաքականությունները կատարում են մեկ լրացուցիչ ֆիքսված FFmpeg անցում արդեն վավերացված տեղական հոսքի վրայով, ընտրում են սահմանափակված `showinfo` տեսարանի ժամանակի դրոշմակնիքները և դետերմինիստիկորեն վերադառնում են նույն միատեսակ միջնակետերին դետեկտորի խափանումների, ժամանակի ավարտի, սխալ ձևաչափի կամ դատարկ թեկնածուների հավաքածուի դեպքում: Սեգմենտի տեղյակ ռեժիմը հատկացնում է միջին կետի նմուշները համաչափ տեսարանի վավերացված միջակայքերին. Սեգմենտից տեղյակ ապացույցները և հետադարձ պահվածքը մանրամասն ներկայացված են ստորև: Կոշտ 16 շրջանակի գլխարկը կիրառվում է յուրաքանչյուր քաղաքականության մեջ ընտրությունից հետո: Երբ տեսարանին ծանոթ հարցումն ունի միայն մեկ կադրի բյուջե, այն օգտագործում է ակտիվ ամբողջական տեսանյութի կամ ֆոկուսի պատուհանի միատեսակ միջնակետը և հայտնում `policyEffective: uniform`. մեկ ընտրված տեսարանի կադրը չի կարող պահպանել երկու ժամանակավոր ծայրերը: Զանգահարողը կարող է կամայականորեն տրամադրել վերջավոր կենտրոնացման պատուհան (`start`/`end` վայրկյան); սահմանները սեղմվում են մեդիայի տևողության վրա, հակադարձ կամ անվերջ պատուհանները մերժվում են, և նմուշառման բոլոր քաղաքականությունները կատարվում են միայն նորմալացված միջակայքում: Ստացված պատուհանը ներառված է նմուշառման մետատվյալներում և անվստահելի նկարագրության նախածանցում, որպեսզի ներքևի մոդելները կարողանան տարբերել կենտրոնացված հատվածը ամբողջական ժամանակացույցից:

Իմաստային ենթագրերի ֆոկուսը առանձին, բացահայտ կարգավորում է: Լռելյայն `full` վերլուծության ռեժիմը պահպանում է առկա շրջանակի հուշումը և երբեք հարցման տեքստը չի ուղարկում վերնագրի մոդելին: `focused` ռեժիմում կամուրջը կարդում է միայն վերջին ոչ դատարկ օգտատիրոջ հեղինակած `text`/`input_text` նույն Chat-ի կամ Responses կոնտեյներից, այն նորմալացնում է NFC, քանդում է կառավարման նիշերն ու բացատները և սահմանափակում է 500 Unicode ծածկագրի կետերով: Դատարկ արդյունքը վերադառնում է ճշգրիտ `full` հուշմանը: Օգտագործելի ակնարկը սերիականացված է որպես JSON հատուկ անվստահելի օգտվողի համատեքստի բլոկում և կարող է առաջնահերթություն տալ միայն դիտելի մանրամասներին. այն չի կարող անտեսել լրատվամիջոցներում տեսանելի կամ լսելի հրահանգներին հետևելու առանձին նախազգուշացումը: Տեքստային ֆոկուսը երբեք չի ենթադրում `start`/`end` կամ չի փոխում ժամանակավոր նմուշառիչը:

#### FU-07 կառուցվածքային հատվածի ապացույցներ

`segment_aware` օգտագործում է մեկ սահմանափակ նախավերլուծական անցում արդեն վավերացված տեղական տեսահոսքի միջոցով: Ֆիքսված ֆիլտրի շղթան սկզբում մասշտաբվում է առավելագույնը 320 պիքսել լայնությամբ, հայտնաբերում է տեսարանների փոփոխությունները և սառեցված ընդմիջումները, այնուհետև նմուշառում է 1 կադր վայրկյանում արագությամբ՝ մշուշման, միջին լումայի և spatial/temporal տեղեկատվության համար: Անցումը սահմանափակվում է 600 կառուցվածքային նմուշներով, մեկ FFmpeg/filter շղթայով, նույն `file` -only արձանագրության և կոնտեյների թույլտվությունների ցանկով, 1 MiB գործընթացի ելքային կապով և առավելագույնը 30 վայրկյանով բրոքերի ընդհանուր abort/deadline. ի ներսում: Այն երբեք չի ընդունում հարցումից հրաման, զտիչ, ուղի կամ URL :

Կառուցվածքային արժեքները դետերմինիստական նմուշառման ապացույցներ են, այլ ոչ թե իմաստային տեսանյութերի ըմբռնում: Նրանք չեն եզրակացնում թեմաներ, գործողություններ, ենթագրեր, խոսք կամ օգտվողի մտադրություն: Տեսարանի և սառեցման սահմանները կազմում են հատվածներ; սառեցնել ծածկույթը, մշուշումը, բացահայտումը, տարածական մանրամասները և ժամանակային փոփոխությունները միայն ազդում են գոյություն ունեցող 1-16 շրջանակային բյուջեի բաշխման վրա: Լիովին սառեցված հատվածը ծածկված է մեկ շրջանակով, մինչդեռ չսառեցված հատվածները մրցում են մնացած բյուջեի համար: Երբ սահմանները գերազանցում են շրջանակները, ժամանակացույցի միատեսակ ծածկույթը պահպանվում է, այնպես որ արագ վաղ կրճատումները չեն կարող թաքցնել երկար հետևող հատվածը: Սառեցման սահմանի 1-վայրկյան վերլուծության լուծաչափում տեսարանի սահմանները միավորվում են:

Բացակայող ֆիլտրերը, malformed/empty ապացույցները, դետեկտորի սխալը կամ սահմանափակված նախնական վերլուծության ժամկետը բացակայում է ճշգրիտ միատեսակ միջին կետի քաղաքականության համար: Զանգահարողի ընդհատման կամ միջնորդի վերջնաժամկետը չի բացվում. այն դադարեցնում է թռիչքի ընթացքում ենթագործընթացը, կանխում է ավելի ուշ շրջանակի արդյունահանումը, և մասնավոր ժամանակավոր ծառը հանվում է `finally` ում:

`scripts/perf/video-bridge-fu07-eval.ts` ստեղծում է դետերմինիստական իրական FFmpeg հարմարանքներ՝ վերնագիր-զանգից հետո խնայողությունների, խիտ շարժման բյուջեի բաշխման, blur/exposure/SI-TI ապացույցների, երկար պոչով արագ կրճատումների և կեղծ պոզիտիվների աստիճանական մարման համար: Այն գրանցում է նախավերլուծության պատի ժամանակը և, որտեղ `/usr/bin/time` հասանելի է, երեխայի CPU և peak RSS: Դրա որակի ստուգումները միայն կառուցվածքային օրակուլներ են: Իրական ենթագրերի մոդելի որակը մնում է `HOLD` քանի որ այս զրահը չունի լիազորված վերջնակետ կամ սառեցված դատավոր: Դրամական խնայողությունները նույնպես մնում են `HOLD` քանի դեռ `--caption-cost-per-call-usd` չի տրամադրում բացահայտ դրական գնահատական մեկ զանգի համար. սցենարը երբեք չի ստեղծում որևէ արդյունք:

Յուրաքանչյուր շրջանակ սահմանափակված է 4 MiB, բոլոր չմշակված շրջանակները միասին մինչև 23 MiB, իսկ սերիականացված բրոքերային պատասխանը մինչև 32 MiB: Մասնավոր ժամանակավոր գրացուցակը հեռացվում է `finally` ում: OmniRoute չի փաթեթավորում FFmpeg և չի ընդունում հատուկ գործարկվող ուղի: Ենթագրերից առաջ կամուրջը կիրառում է պահպանողական տեսողական կրկնօրինակման անցում. յուրաքանչյուր JPEG կրճատվում է մինչև 16 × 16 մոխրագույն սանդղակի բուֆեր և համեմատվում է միայն պահպանված վերջին կադրի հետ: Մեկ շրջանակից բարձր ենթագրերի պահանջվող բյուջեի համար արդյունահանումը տրամադրում է սահմանափակված թեկնածուների խումբ՝ մինչև այդ բյուջեի կրկնակի չափով և ոչ ավելի, քան 16 կադր: Պահանջվող շեմը կիրառվում է միայն կրկնօրինակումից հետո, իսկ առաջին և վերջնական ընտրված թեկնածուները պահպանվում են վերջնական նոսրացման ժամանակ, երբ բյուջեն առնվազն երկուսն է: Տարբերակված `grayscale-16x16-mean-cells-v2` քաղաքականությունը օգտագործում է միջին լումա դելտաի ավելի մեծը և մանրապատկերների բջիջների հարաբերակցությունը, որոնց նորմալացված դելտան առնվազն 0,05 է: Կրկնվող շեմը 0.04 հաստատունն է, որն ընտրված է կանխատեսելիության համար, այլ ոչ թե որպես գործարկման ժամանակի կարգավորում: Բարձր հակադրություն ունեցող այս երկրորդային ազդանշանը պահպանում է փոքր շարժումները և տեսանելի տեքստի փոփոխությունները, որոնք կարող են թաքցնել միայն միջին համեմատությունը: Համեմատիչի կամ ապակոդավորիչի սխալները չեն բացվում և պահպանում են ծածկույթը: Ելքային մետատվյալներն առանձնացնում են արդյունահանված թեկնածուներին, հաջողությամբ օգտագործված շրջանակները և տեսողական կրկնօրինակները՝ հեռացված:

Հստակորեն նշված տեսանյութի հատվածը կարող է պահանջել ժամանակի դրոշմված կոնտակտային թերթիկ: Կամուրջը կառուցում է առավելագույնը 4 սյունանի, 16 շրջանակի JPEG ցանց: Յուրաքանչյուր 512 պիքսելանոց բջիջ այրում է իր աղբյուրի ժամանակի դրոշմը բարձր կոնտրաստային ներքևի գոտու մեջ, մինչդեռ նույն ժամանակի դրոշմակնիքները մնում են տեքստային մետատվյալներում՝ ներքևի ասոցիացիայի և աուդիտի համար: Ամբողջական JPEG մնում է 32 MiB սահմաններում: Եթե `sharp` չի կարող վերծանել կամ կազմել ցանցը, կամուրջը հետ է ընկնում դեպի առանձին JPEG շրջանակներ; հաճախորդի ընդհատումը դեռ տարածվում է թերթիկի գործողության միջոցով:

Խթանման ապացույցները միտումնավոր առանձնացված են սինթետիկ կազմի միկրոհենանիշից: `scripts/perf/video-bridge-contact-sheet-eval.ts` սահմանում է սխեմայի տարբերակով A/B ամրագոտիներ իրական OpenAI-ի հետ համատեղելի տեսողության մոդելների համար: Այն չափում է մատակարարի կողմից հաղորդված նշանները, պատի վերջից մինչև վերջ հետաձգվածությունը (ներառյալ թերթի կազմը), մոդելի զանգերի քանակը և մանիֆեստի կողմից սահմանված փաստերի պահպանումը: Հում մոդելի պատասխանները չեն գրվում հաշվետվությանը. պահպանվում են միայն SHA-256 մարսումները և համապատասխանող փաստերը IDs : Սարքավորումը չի կատարում ցանցի կամ վճարովի մոդելի զանգ, քանի դեռ `--execute-real` չի փոխանցվել, և `--model`, `OMNIROUTE_BASE_URL` և `OMNIROUTE_API_KEY` կազմաձևված չեն: Առանց այդ բացահայտ իրական վազքի, դրա մեքենայաընթեռնելի դատավճիռը մնում է `HOLD`; սինթետիկ payload/call-count չափումները միայն խթանման ապացույց չեն:

Առանձին `scripts/perf/video-bridge-promotion-eval.ts` սպառում է FU-07 կամ FU-09 դիտարկումները։ Խթանման ընդունումը պահանջում է բոլոր ութ սինթետիկ սցենարներ, գումարած ախտահանված իրական տեսահոլովակ, առնվազն երեք չափված կրկնություն՝ յուրաքանչյուր դերի և դեպքի համար, բոլոր տասը հայտարարված չափորոշիչները, սառեցված media/prompt/expected-fact/settings ամփոփումները, եզակի դիտարկման IDs և ստուգված սերմնավորված A/B կարգը: Կատարման անդորրագիրը կապում է կորպուսի ամփոփումը, ճշգրիտ թեկնածուն SHA և մոդելի վերանայումը: Չափումները բացակայում են կամ անվավեր են մնում `HOLD`, ներառյալ CPU 30 վրկ-ից բարձր, գագաթնակետ RSS 512 MiB ից բարձր կամ նախնական վերլուծություն 30 վրկ-ից բարձր: Սրանք ապացույցների ընդունման կափարիչներ են, այլ ոչ թե նոր գործարկման RSS կատարման երաշխիք:

FU-07 պահանջում է առնվազն 98% որակի պահպանում և p95 ուշացում՝ ոչ ավելի, քան 1,2 անգամ բազային, գումարած կա՛մ 0.05 բացարձակ դեպքերի հավասարակշռված միջին հիշողության բարելավում համարժեք միջին ենթագրերի զանգերի դեպքում, կա՛մ առնվազն 10%-ով ավելի քիչ միջին ենթագրերից հետո: FU-09 պահանջում է առնվազն 0,85 որակ, 95% պահպանում, 20% միջին ուշացման կրճատում և 10% նշանի կրճատում: Կրիտիկական փաստի կորուստը, ներարկման համապատասխանությունը կամ բացակայող օգտագործումը խոչընդոտում են առաջխաղացմանը: Մեկ կատարումը չի կարող որևէ բան խթանել. `--previous-report` հաստատում է նույն policy/model revision/candidate/corpus. ի երկու հստակ, չհամընկնվող, հաջորդաբար համապատասխան կատարումները: Նմուշառման փորձը չի կարող հաստատել կոնտակտային թերթիկի փորձը:

Կոլեկցիոները պետք է պատասխաններ հավաքեն հիշողության մեջ և պահպանեն `responseDigest` գումարած չափումները և դիտորդական կապերը, երբեք չպատասխանեն տեքստը: Սպառողը նաև կարդում է ժառանգական հում դիտարկումները, բայց երբեք այդ տեքստը չի պատճենում իր զեկույցներում: Յուրաքանչյուր դիտարկման համար ընդունված է `responseDigest` կամ `rawResponseText` ճշգրիտ մեկը: Տարբերակված թույլտվությունների ցանկը դատարկ է մնում անփոփոխ `hold` լռելյայնով: Իրավասու մուտքի համար պահանջվում է իր ապացույցների տեղեկանքը, քաղաքականությունը, մոդելի վերանայումը, ճշգրիտ թեկնածուն SHA, մանիֆեստի ամփոփում և երկու հստակ գործարկում IDs; հակասական ենթատեքստերը մերժվում են: Այս մետատվյալները աուդիտի պայմանագիր են, այլ ոչ թե ապացույց, որ հղված ֆայլը պարունակում է իրական չափումներ: Վերանայեք փաստացի անդորրագրերը նախքան որևէ գրառում ավելացնելը: Կառավարման վիճակագրության վերջնակետը և վիդեո վահանակը բացահայտում են պահպանողական պատրաստակամությունը: Կազմաձևված մոդելի կեղծանունը միայնակ չի հաստատում իր վերանայումը կամ առաջադրվող SHA թեկնածուն, ուստի ընթացիկ վահանակը զեկուցում է `HOLD` այլ ոչ թե այլ կատարման համատեքստից վերօգտագործելու իրավասությունը: Ակնհայտ փորձարարական ընտրությունը մնում է առանձնացված խթանումից. ոչ մի լռելյայն ինքնաբերաբար չի փոխվում:

Զանգահարողները կարող են կամընտիր `transcript.cues` զանգված կցել աջակցվող տեսանյութի մասին, երբ նրանք արդեն ունեն հավասարեցված տեքստ: Յուրաքանչյուր նշան պետք է ունենա `text`, վերջավոր `start`/`end` ինտերվալ փորձված տևողության ներսում և սպիտակ ցուցակում ներառված `source` (`client`, `embedded` կամ `audio-bridge`); `confidence` լռելյայն սահմանում է `1` և պետք է մնա `0` և `1` միջև: Ճշգրիտ կրկնօրինակ ազդանշանները փլուզված են: OmniRoute երբեք չի սկսում տառադարձումը այս մետատվյալներից. վավերացված ազդանշանները պատճենվում են նկարագրված արդյունքի մեջ՝ աղբյուրով, վստահությամբ և ընդմիջումով և ցուցադրվում են որպես անվստահելի դիտարկումներ շրջանակի ենթագրերի կողքին: Անվավեր, տիրույթից դուրս կամ առանց ծագման տեքստը մերժվում է, այլ ոչ թե խառնվում ենթագրերի հոսքի մեջ: Հարցման մարմնի տառադարձման երկու ալիքներն էլ նորմալացնում են `client` ի մատակարարված ծագումը, ներառյալ ինքնահաստատված `embedded` կամ `audio-bridge` պիտակները: Միայն սերվերին պատկանող ադապտերը կարող է նշանակել այդ վստահելի պիտակները միայն կոդով `trustedSource` արգումենտի միջոցով; Հարցման JSON դաշտը չի կարող հասնել այդ արգումենտին: Տառադարձման տեքստը մնում է անվստահելի լրատվամիջոցներից ստացված բովանդակություն՝ անկախ դրա ծագումից և երբեք չպետք է որոշի թույլտվությունը:

Ընդլայնված զանգահարողը կարող է տրամադրել `audioTranscript` հետքեր նույն տեսանյութի համար. այն դիտվում է որպես հաճախորդի կողմից տրամադրված տեքստ, այլ ոչ սերվերի տառադարձման ապացույց: The fusion seam-ը կատարում է տեսողական և աուդիո դիտարկումները մեկ վերջնաժամկետում և ընդհատում է ազդանշանը, պատվիրում է դրանք ընդհանուր ժամանակացույցի վրա, քանդում է ճշգրիտ կրկնօրինակները և հաղորդում մասնակի արդյունք, երբ միայն մեկ կողմն է հաջողության հասնում: Անվավեր `audioTranscript` վերածվում է այդ մասնակի արդյունքի — տեսողական նկարագրությունը պահվում է, և աուդիո մասնաճյուղը ձայնագրում է ախտահանված ձախողման կոդ — ՝ ամբողջ տեսանյութը ձախողելու փոխարեն: Մասնաճյուղի հասանելիությունը, մասնակի դրոշակը և ախտահանված խափանման կոդերը պահպանվում են նկարագրված արդյունքում, պաշտպանական բազրիքների մետատվյալներում (`audioFusionRuns`/`audioFusionPartials`/ `audioFusionFailureCodes`), արդյունքների քեշի մետատվյալներում և կամրջի միաձուլման հաշվիչներում: Video Bridge-ի կանխադրված ուղին չի կանչում խոսքի տեքստ կամ ներբեռնում երկրորդ մեդիա պատճենը. առանց այդ հստակ ուղու, այն մնում է միայն տեսահոլովակ:

**Սղագրության պահպանում (#12150 P1):** Սա ինքնաբերաբար կիրառվում է, երբ Video Bridge-ը (ինքն է մասնակցում) ներկայացնում է տառադարձման հուշում — առանձին պահպանման դրոշ չկա: Երբ հարցումը արտագրում է որևէ տառադարձում (զանգողի կողմից հայտարարված `transcript` կամ միաձուլված `audioTranscript`), պաշտպանական բազկաթոռը նշում է այն `videoBridgeObserved` և ստեղծում է տեսանյութի նկարագրության սրբագրված ստվեր — նույնական արտապատկերում, որում յուրաքանչյուր ազդանշանի ազատ տեքստի մարմինը փոխարինվում է `[redacted-video-transcript]` ով, որը կառուցվում է նախքան կառուցվածքը փոխարինելով՝ փոխարինելով դաշտը: հարթեցված տեքստ, այնպես որ ոչ մի նշանային բովանդակություն — հակառակորդ կամ սովորական, ներառյալ `]` պարունակող մարմինները, ինչպիսիք են `[inaudible]`/`[music]` — չեն կարող գոյատևել): Մշտական զանգերի գրանցամատյանի հարցման մարմինը փոխում է տեսանյութից ստացված տեքստի յուրաքանչյուր հատված այդ խմբագրված ստվերով, որը համապատասխանում է բովանդակության հավասարությանը. `fullText` խարիսխը վերընթերցվում է ավարտված նախնական զանգի պահակային բեռնատարից, այնպես որ համընկնումը դեռևս հաջողվում է այն բանից հետո, երբ ավելի ուշ շղթայական պաշտպանիչ բազրիքները ( PII և հավատարմագրերի դիմակներ, առաջնահերթություններ 10/95) վերաշարադրեն նկարագրության տեքստը տեղում և system-prompt/handoff/memory ներարկումից հետո վերափոխեն հաղորդագրությունների զանգվածը: Մոդելի ուղղությամբ ուղարկված մարմինն անփոփոխ է: Դիտարկված հարցումը նաև չունի կայուն հիշողություն (ինչպես հարցումից, այնպես էլ պատասխանից ստացված արդյունահանումը բաց է թողնվում), ուստի մոդելի սեփական պատասխանը չի կարող կրկնօրինակել տեքստը Հիշողության մեջ:

**Հում վիդեո դաշտեր (#12430):** Երբ կամուրջը միացված է, և հայրենի տեսանյութերի աջակցությունն անհայտ է կամ բացակայում է, սահմանված `transcript`/`audioTranscript` դաշտերը նույնպես ակտիվացնում են `videoBridgeObserved`, նույնիսկ նկարագրության ձախողումից կամ `maxVideos` սահմանափակումից հետո: `null` և դատարկ տողերի հաշվարկ; բացակայող դաշտերը և ոչ վիդեո մետատվյալները՝ ոչ: Պահպանված պատճենները խմբագրում են այս դաշտերը կամ բաց թողնում հարցումը, և caches/Memory շրջանցվում է:

Այդ հետադարձ ուղիներում զանգահարողի վավեր ազդանշանները դառնում են աջակցվող `text`/`input_text` մասեր, այլ ոչ ստանդարտ մատակարարի դաշտեր: Հարցման միջոցով տրամադրված երկու հետքերը մնում են անվստահելի `client` դիտարկումներ՝ բացահայտ նախազգուշացմամբ, որ տեսանյութը նկարագրված չէ, և ժամանակի դրոշմակնիքները չեն ստուգվել լրատվամիջոցների նկատմամբ: Գոյություն ունեցող 256-cue/64-KiB ընդհանուր և մեկ ցուցիչի բյուջեները կիրառվում են երկու ուղիների վրա միասին. Ժամային դրոշմանիշները պետք է համապատասխանեն միջնորդի 600 վայրկյանանոց առաստաղին և ցանկացած մատակարարված ֆոկուսային պատուհանին: Անվավեր հետքերը հեռացվում են, չեն ուղարկվում որպես կամայական տեքստ; վավեր եղբայրը կամ եղբայրը դեռ կարող են օգտագործվել, եթե նրանց համակցված բյուջեն չգերազանցվի: Null/empty դաշտերը տեքստ չեն ավելացնում: Ոչ մի մեդիա առբերում կամ տառադարձում չի ավելացվել այս հետադարձով: Տառադարձման ընդլայնման դաշտերը հեռացվում են հետադարձ վիդեո կրիչից և դրա `video_url`/`source` օբյեկտներից: OpenAI մետաղալարերի թույլտվությունների ցանկը մնում է խիստ. Անհայտ բնիկ վիդեո կրիչները մնում են հասանելի, իսկ հայտնի միայն տեքստային թիրախները պահում են անվտանգ մարկերներ: Կառուցվածքային խմբագրման ստվերները պաշտպանում են կցված տառադարձման տեքստը, մինչդեռ զանգահարողի պատկանող սկզբնական հարցումը մնում է անփոփոխ: Մայրենի կողմից աջակցվող թիրախները և հաշմանդամ կամուրջները պահպանում են իրենց առկա շրջանցիկ վարքը:

Լրացուցիչ պահպանված պատճենները օգտագործում են նույն դիտարկվող հարցումի ազդանշանը: Հաճախորդի հարցումների չմշակված նախնական պահակակետը, հիշողության մեջ առկախ հարցումը և վաղաժամ մերժված հարցումների գրանցամատյանը կառուցվածքայինորեն փոխարինում են տառադարձման դաշտերը վիդեո մասերում. լարային հուշումները, որոնք սինթեզվում են խողովակաշարի փուլերի և համատեքստի փոխանցման միջոցով, վերադասավորվում են շարունակական պահանջի մարմնի լվացարանում: Մշտական `video_content_removed` նշիչը ստիպում է `previous_response_id` շարունակությունը փակվել, այլ ոչ թե վերակառուցել միտումնավոր հեռացված տեքստը: Եթե դիտարկված հարցումը կորցնում է իր յուրաքանչյուր մասի խմբագրման ստվերը նախքան գրանցումը, կամ նույնիսկ մի քանի տեսանյութի ստվերներից մեկը չի համընկնում ավելի ուշ հարցումների մուտացիաներից հետո, պահպանված հարցման մարմինն ամբողջությամբ բաց է թողնվում՝ մասնակիորեն խմբագրված տառադարձումը պահպանելու փոխարեն:

Դիտարկված հարցման դեպքում մոդելային պատասխանը կարող է մեջբերել տառադարձության ցանկացած հատված՝ առանց կառուցվածքային ազդանշանի սահմանի: Հետևաբար, դրա շարունակական զանգերի մատյան `responseBody` փոխարինվում է բացթողումների նշիչով. խողովակաշարի մանրամասն արտեֆակտը (որը կարող է ներառել upstream/client մարմիններ և հոսքի կտորներ) չի պահպանվել: Իմաստային, անզորություն և պատճառաբանություն-կրկնակի քեշերի շրջանցում ընթերցում և գրում է այդ խնդրանքի համար: Մատակարարի հարցումը և հաճախորդի տեսանելի պատասխանը մնում են անփոփոխ: Վաղ պահվող բայթերը հեռացվում են ժամանակավոր բուֆերից, երբ մանրամասն արտեֆակտը բաց է թողնվում: Kiro ի սխալ EventStream նախազգուշացումը հաղորդում է միայն օգտակար բայթերի քանակը, ոչ երբեք դրա բովանդակությունը կամ JSON վերլուծիչի չմշակված սխալը: Սա չի պնդում, որ յուրաքանչյուր անկապ provider/plugin ախտորոշում ենթարկվել է աուդիտի. ավելի լայն պահված լվացարանի մաքրումը հետևվում է #11658 ում:

Ներքին `/api/modality-bridge/video/drilldown` կյանքի ցիկլը առանձին, loopback/token-authenticated քեշի ենթաշերտ է: Յուրաքանչյուր գործողություն պահանջում է նաև կանոնական անթափանց ID սկզբունք: Մինչ արտադրական զանգահարողը միացված է, այն պետք է ստանա այդ ID վավերացված վարձակալից և երբեք չպետք է փոխանցի հաճախորդի կողմից ընտրված արժեքը: Քեշի ստեղները կապում են այդ սկզբունքը կանոնական նիստի և տեսահղման IDs հետ, պահում են միայն իրենց SHA-256-derived ստեղները, և ընթերցումների և ջնջման շրջանակը նույն հիմնականին են: Քեշը պահում է առավելագույնը 16 ստացված JPEG շրջանակ յուրաքանչյուր մուտքի համար, սպառվում է տասը րոպե հետո և աջակցում է սահմանափակված `start`/`end` ընթերցումներ կամ բացահայտ աշխատաշրջանի ջնջում:

Յուրաքանչյուր հիմնական սահմանափակված է 16 գրառումներով և 64 MiB կանոնական JPEG տվյալների: Այդ սահմանները անկախ են գլոբալ 64-entry/256 MiB առաստաղից. հիմնական քվոտային ճնշումը վտարում է միայն այդ տնօրենի ամենաքիչ օգտագործված գրառումները, նախքան գլոբալ LRU վտարումը դիտարկելը: Ժամկետանց գրառումները մաքրվում են ինչպես հիմնական, այնպես էլ գլոբալ հաշվառումից՝ քեշի գործունեության վերաբերյալ, մինչդեռ չեղարկման և վավերացման ձախողումը մասնակի փոխարինում չի կատարում:

Քեշը մերժում է ոչ կանոնական Base64-ը, ավելորդ լցոնումը, ոչ JPEG մեդիան, սխալ կամ կտրված JPEGs և JPEGs, որոնք նախազգուշացում են առաջացնում սահմանափակ ամբողջական պատկերով `sharp` վերծանման ժամանակ: Այն վերակոդավորում է յուրաքանչյուր ընդունված պատկեր՝ որպես կանոնական JPEG, լայնությունը և բարձրությունը ստանում է վերծանված բայթերից՝ զանգահարողի դաշտերին վստահելու փոխարեն, և դրանք չպահելու փոխարեն հեռացնում է հետին պոլիգլոտ բայթերը: Միայն սահմանափակված կանոնական սեղմված բուֆերը գանձվում է երկու քվոտաների վրա: JSON մետաղալարերի սահմանաչափը ներառում է Base64 վերադիր 32 MiB վերծանված մուտքային առաստաղի համար: Յուրաքանչյուր պահված ածանցում գրանցում է իր վավերացված JPEG format/resolution, նմուշառման քաղաքականությունը, ածանցյալ տարբերակը, ստեղծման ժամանակը, սերվերի կողմից հաշվարկված բովանդակության հեշը և հեշավորված ծնողի հղումը, գումարած վստահելի զանգահարողի ծնողի բովանդակության հեշը: Չեղարկումը ստուգվում է ասինխրոն decode/hash փուլերի միջև՝ նախքան ատոմային քեշի միացումը:

Արտադրական արտադրողը վերօգտագործում է արդեն ստացված բրոքերային շրջանակները միայն հաջող տեսողական վերլուծությունից հետո, առանց երկրորդ տեսանյութի download/extraction. Այն պահանջում է `modalityBridgeVideoDrilldownEnabled=true` օպերատոր, խիստ `drilldown: true` յուրաքանչյուր մասի համար և վավերացված API-բանալի գրառում ID: Հաճախորդի կողմից հայտարարված principal/session արժեքները երբեք սեփականություն չեն հաստատում: Առանց բոլոր երեք պայմանների այն չի խաշում, չափափոխում կամ պահպանում լրացուցիչ շրջանակներ: Պահպանման ձախողումը պահպանում է օգտագործելի տեսողական արձագանքը: Համաձայնեցված հարցումները շրջանցում են ամբողջ տեսանյութի արդյունքների քեշը, որպեսզի քեշավորված արդյունքները երբեք չվերարտադրվեն բռնակները:

JSON և SSE հաջող պատասխանները բացահայտում են առավելագույնը չորս անթափանց բռնակներ սահմանափակված `x-omniroute-video-drilldown` վերնագրում: Բրաուզերի լիազորված սկզբնաղբյուրները կարող են կարդալ այդ վերնագիրը՝ առանց CORS ծագման քաղաքականության ընդլայնման: Նոր բռնակներն օգտագործում են `v1.<32-byte random base64url token>`, իսկ ռեեստրը պահպանում է միայն իրենց SHA-256 հեշերը: reader/header վերլուծիչն ընդունում է նաև ժառանգական 64 վեցանկյուն խորհրդանիշներ: Հավաստագրված հանրային սպառողը `GET /api/v1/video-bridge/drilldown?handle=...` ն է՝ անկախ `modalityBridgeVideoDrilldownRemoteEnabled=true` կողմից: Հստակ շարունակվող կեղծ չեղարկում է մուտքը նույնիսկ այն դեպքում, երբ ժառանգական `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_REMOTE_ENABLED` env հետադարձ կապը միացված է: Արտադրության պահպանումն ունի `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_ENABLED` նման ժառանգություն: Երկու հետնորդներն էլ լռելյայն անջատված են:

Սպառողը ստանում է իր սեփականությունը վավերացված բանալիից և կիրառում է հիմնական քաղաքականությունը. և՛ GET, և՛ DELETE պատկանում են `video` վերջնակետի կատեգորիային, ներառյալ `/v1` և `/api/v1` կեղծանունները: Ոչ դատարկ վերջնակետի թույլատրելի ցուցակով բանալիները պետք է ներառեն `video`; անսահմանափակ բանալիները մնում են համատեղելի: Սպառողը վերադարձնում է նույն 404-ը անհայտ, ժամկետանց և այլ բանալու բռնակների համար: Այն ընդունում է `variant=preview|standard|detail` (առավելագույն JPEG չափը 320/640/1280, երբեք բարձրացված), `limit=1..8` (կամ ժառանգված `frames` կեղծանունը, երբեք երկուսն էլ), զրոյական `page` և կամընտիր `start`/`end` ֆոկուս վայրկյաններ: Կրկնվող հարցումների ստեղները և հակադարձ ֆոկուսային պատուհանները մերժվում են: Յուրաքանչյուր վերադարձված տարբերակ ունի իր իրական բովանդակության և փաստացի լուծման մետատվյալների հաշը՝ կապված պահպանված աղբյուրի հետ: Տարբերակները ստացվում են ընթերցման ժամանակ, այլ ոչ թե պահվում են որպես լրացուցիչ պահպանված պատճեններ: JSON պատասխանը, ներառյալ Base64/envelope, սահմանվում է 32 MiB; չափազանց մեծ էջը վերադարձնում է 413, և հաճախորդը պետք է պահանջի ավելի քիչ շրջանակներ: Կարդում է չեկի չեղարկումը յուրաքանչյուր չափափոխման շուրջ և նորից ստուգում է բռնակի վավերականությունը՝ վերադառնալուց առաջ: `DELETE` սեփականատիրոջ կողմից անզոր է. ջնջումը կամ TTL ժամկետի ավարտը թողարկում է պահպանված աղբյուրը և օգտագործման հաշվառումը:

Համօգտագործվող խանութը գործընթացային է. բռնակները սպառվում են վերագործարկման ժամանակ և չեն փոխանցվում անկախ OmniRoute գործընթացների միջև: Կառավարման վիճակագրությունը ցույց է տալիս արդյունավետ պահպանման/հեռակառավարման քաղաքականությունը և միավորում է միայն պահպանված entries/bytes, ոչ երբեք լրատվամիջոցները, հղումները, հիմնական IDs կամ բռնակները: Տեսանյութի կարգավորումների վահանակը ցույց է տալիս այդ արժեքները և կարող է պահպանել երկու համաձայնության անջատիչները: Իրականացման այս փաստաթուղթը կենդանի տեղակայման կամ առաջխաղացման ապացույց չէ. իրական մոդելի ընդունումը հետևվում է առանձին:

Շրջանակները մակագրված են հաջորդաբար կազմաձևված Video մոդելի հետ: Դատարկ Video override-ը ժառանգում է Vision պարամետրը. եթե երկուսն էլ դատարկ են, Vision ավտոմատ երթուղիչը ընտրում է արդյունավետ տեսողական մոդելը: Հաջող ենթագրերը փոխարինում են սկզբնական մասի կայուն `[Video description:` նախածանցով, որը նաև նշում է տեքստը որպես անվստահելի մեդիայից ստացված դիտարկում և հորդորում է ներքևում գտնվող մոդելներին չհետևել լրատվամիջոցներում հայտնաբերված հրահանգներին: Շրջանակի վերնագրերի քեշի ստեղները ներառում են JPEG բայթերը, հուշումը, ժամանակի դրոշմը և արդյունավետ մոդելը; միայն հաջողված ենթագրերը պահվում են քեշում: Քեշի գրառումները պահպանում են իրական հաջող արտադրողի մոդելը, ներառյալ հետադարձ մոդելը. կամուրջը հայտնում է `mixed`, երբ տարբեր մոդելների կողմից արտադրվում էին տարբեր շրջանակներ: Քեշը վերօգտագործում է արտադրողի ինքնությունը՝ որպես պահանջվող երթուղային պլան վերանշանակելու փոխարեն: Ամբողջ տեսանյութի արդյունքների քեշը միացված է յուրաքանչյուր մուտքի վրա, որը փոխում է ելքային — հուշումը, արդյունավետ մոդելը, նմուշառման քաղաքականությունը, շրջանակների քանակը, իմաստային վերլուծության ռեժիմը, նորմալացված ֆոկուսի հուշման SHA-256 մատնահետքը, ֆոկուս պատուհանը, `transcript`, `audioTranscript` և կոնտակտային թերթիկի դրոշը —, այնպես որ այդ չափսերից որևէ մեկը փոխելը երբեք չի կարող վերօգտագործվել: Տեսողական հեռացման քաղաքականության տարբերակը, շեմը և սահմանափակված թեկնածուների շրջանակների քանակը նույնպես հստակ են արդյունքների քեշի բանալիում և մետատվյալներում. Հետևաբար, քաղաքականության փոփոխությունը չի կարող կրկին օգտագործել հնացած ամբողջական տեսանյութի նկարագրությունը: Result-cache v4 մետատվյալները պահպանում են ռեժիմը և մատնահետքը, ոչ երբեք օգտագործողի հում խնդիրը: Guardrail-ի մետատվյալները հաղորդում են ինչպես պահանջված, այնպես էլ արդյունավետ վերլուծության եղանակները. Հայցված `focused` ռեժիմն առանց օգտագործողի օգտագործման տեքստի հաղորդվում է որպես արդյունավետ `full`:

Պաշտպանական բազրիքը հանում է բոլոր աջակցվող տեսահոլովակի մասերը, բայց նկարագրում է ոչ ավելի, քան `modalityBridgeVideoMaxVideos`: Որպես թիրախ, որն ապացուցված է `supportsVideo === false`, ձախողված և չափից ավելի սահմանափակված տեսանյութերը դառնում են բացահայտ անվտանգ տեքստային նշիչներ, այնպես որ ոչ մի հում տեսանյութ գոյատևում է: Երբ հնարավորություններն անհայտ են, այդ մասերը պահպանում են իրենց տեսագրման կրիչը. ցանկացած հետադարձ տառադարձում հետևում է վերը նշված սահմանափակված տեքստի փոխակերպմանը: `supportsVideo === true` ով թիրախները շրջանցում են կամուրջը. Հաճախորդի պահանջի ընդհատման ազդանշանը տարածվում է ներբեռնման, բրոքերային հերթի, ենթագործընթացների և ենթագրերի զանգերի միջոցով. ընդհատում է վիդեոների միջև ընկած հատվածը և երբեք չի բացվում հում լրատվամիջոցների համար:

Runtime-ի կարգավորումները DB-ով ապահովված են և Zod-ով վավերացված.

| Բանալին                             | Կանխադրված  | Շրջանակ / վարքագիծ                                                                                               |
| ----------------------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`     | Ընտրովի գործարկման ժամանակ, միանալ                                                                               |
| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full` պահպանում է ընդհանուր ենթագրերը. `focused` օգտագործում է սահմանափակ, անվստահելի վերջին օգտվողի համատեքստը |

| `modalityBridgeVideoMaxVideos`      | `1`         | 1–4                                                                                                              |
| `modalityBridgeVideoTimeout`        | `120000`    | 1000–120000 ms                                                                                                   |

120 վայրկյանից ավելի տեսահոլովակի դադարի արժեքները, որոնք պահպանվում են, պահպանվում են բրոքերի վերջնաժամկետի համար. նոր կարգավորումները, որոնք գրում են այդ սահմանաչափից բարձր, մերժվում են: `GET /api/modality-bridge/video/runtime` պահանջում է վստահելի դրոշմակնիք ունեցող loopback տեղակայում նախքան նույնականացումը կամ գործարկման ժամանակի հետաքննությունը, այնուհետև պահանջում է կառավարման վավերացում: Այն վերադարձնում է միայն `available`, ախտահանված FFmpeg/ffprobe տարբերակները և ֆիքսված պատճառ, երբ գործարկման ժամանակը անհասանելի է: Ներքին արդյունահանման վերջնակետը հանրային վերբեռնման API չէ. հերթի հագեցվածությունը վերադարձնում է `503` գումարած `Retry-After`, զանգահարողի անջատումը վերադարձնում է `499`, իսկ բրոքերի ֆիքսված վերջնաժամկետը վերադարձնում է `504`: Փոխակերպված պատասխանները `video->text;model=<visionModel>;parts=<videos>` ավելացնում են կենտրոնական `x-omniroute-modality-bridge` վերնագրին՝ առանց Vision կամ Audio հատվածները հեռացնելու:

### PII Masker (`piiMasker.ts`)

Վազում է** երկուսն էլ** փուլերը.

- **`preCall`** կլոնավորում է օգտակար բեռը, քայլում է `system`, `messages`, `input` և `prompt` (ներառյալ պարզ լարային տարրերը) և կիրառում `processPII()` ( `@/shared/utils/inputSanitizer` ից) լարային `content`/`text` դաշտերում: Երբ `PII_REDACTION_ENABLED=true`, հայտնաբերված PII վերագրվում է ելքային բեռնվածքում: Սա անկախ է `INPUT_SANITIZER_MODE` ից (որը վերահսկում է միայն արագ ներարկման քաղաքականությունը): Երբ խմբագրումն անջատված է, զանգը գրանցում է հայտնաբերումը առանց բովանդակությունը վերաշարադրելու:
- **`postCall`** խորը կլոնավորում է պատասխանը, գործարկում `sanitizePIIResponse()` և Responses-API-ձևավորող դիմակը (`maskResponsesOutput` — ծածկում է `output_text` և `output[].content[].text`): Եթե որևէ փոփոխություն տեղի ունենա, փոփոխված պատասխանը փոխարինում է բնօրինակին:

Պաշտպանական երկաթուղին երբեք չի արգելափակվում. այն միայն նշում է (`meta.detections`, `meta.redacted`) կամ վերաշարադրում:

**Հետադարձելի պահոց (`PII_REVERSIBLE_VAULT_ENABLED`, լռելյայն `false`):** Երբ երկուսն էլ `PII_REDACTION_ENABLED` և `PII_REVERSIBLE_VAULT_ENABLED` միացված են (DB override > env > լռելյայն, կարդալ մեկ անգամ յուրաքանչյուր հարցումով), `handleChat` բացում է մեկ պահոց յուրաքանչյուր հաճախորդի հարցումով (`src/lib/pii/requestTokenVaultScope.ts`) և փոխանցում այն նախնական զանգին որպես `GuardrailContext.tokenVault`: Այնուհետև դիմակավորողը գրում է փոխարինող նշաններ, ինչպիսիք են `<<PII_EMAIL_QWERTYUI_1>>` `[EMAIL_REDACTED]` փոխարեն, ներկառուցված, վավերացված (GDPR/POPIA) և սովորական կանոնների համար: Nonce-ը 8 պատահական մեծատառ տառ է յուրաքանչյուր հարցում, և նույն արժեքը ստանում է նույն նշանը հարցումում: Միայն դիմակավորները. արագ ներարկման պահակը և `/api/guardrails/test` աշխատում են առանց պահոցի և պահում են տեղապահները:

- Մատակարարը, յուրաքանչյուր համակցված ոտք, նորից փորձ, միաձուլման վահանակի անդամ և միաձուլման դատավորը տեսնում են միայն նշանները: Նշանները վերականգնվում են մեկ անգամ՝ 2xx պատասխանի վրա, որը թողնում է `handleChat`. վերլուծված SSE յուրաքանչյուր դաշտում (իրադարձությունների միջև բաժանված նշանը դեռևս լուծվում է, գործիքի կանչի արգումենտները JSON-ից դուրս են մնացել) կամ JSON մարմնի յուրաքանչյուր դաշտում՝ վերահաշվարկված `Content-Length` ով: Վերականգնվում են բովանդակության և հիմնավորման տեքստը և գործիքի կանչի փաստարկները: Սխալի մարմինները (4xx/5xx) պահում են նշանները:
- Խափանումները մնում են գաղտնի. եթե հատումը ձախողվի կամ պահոցը հրաժարվի արժեքից (1000 գրառում, 256 նիշ մեկ արժեքի համար, ընդհանուր 64 KB ), փոխարենը գրվում է տեղապահը. նշան, որը պահոցը չի կարող լուծել, կամ վերականգնումը, որը ձախողվում է, մնում է բառացի և գրանցվում է միայն հաշվարկը: Պահոցը չունի ժամանակաչափեր և գլոբալ վիճակ. այն ջնջվում է, երբ պատասխանների հոսքն ավարտվում է, չեղարկվում կամ սխալվում է:
- Երբ հարցումը հատում է նշանները, հիշողության արդյունահանումը, անզորության պահպանումը և երկու իմաստային քեշի գրառումները բաց են թողնվում, քանի որ հետագա ոչ մի հարցում չի կարող լուծել այդ նշանները: Զանգերի մատյաններում մատակարարի հարցումը և պատասխանը կրում են նշաններ; գրանցված հաճախորդի հարցման մարմինը դեռևս հաճախորդի չմշակված մուտքն է, ինչպես պարզ խմբագրման դեպքում:
- Նշաններն օգտագործում են մեկ հարցման պատահական ոչ մի բան, այնպես որ հուշման նախածանցը փոխվում է ամեն հերթափոխի ժամանակ. մատակարարի կողմից հուշումների քեշավորումը չի դիպչում դիմակավորված շրջադարձերի համար, և նշանը, որը վերադառնում է ավելի ուշ հերթով (օրինակ՝ `previous_response_id` միջոցով) պատկանում է հին հարցումին և մնում է բառացի:

#### Յուրաքանչյուր տեսակի ընտրություն, հատուկ նախշեր և հայտնաբերման հաշվիչներ

**Վահանակի վահանակ → Կարգավորումներ → Անվտանգություն → PII դիմակավորում** ընտրում է _ինչ_ը դիմակավորված է: Այն չի միացնում դիմակավորումը. դա դեռ `PII_REDACTION_ENABLED` (խնդրանք) և `PII_RESPONSE_SANITIZATION` (պատասխան + SSE), երկուսն էլ լռելյայն անջատված են:

- **Յուրաքանչյուր տեսակի ընտրություն** — ներկառուցված ID-ները թվարկված են `src/shared/constants/piiTypes.ts` ում (`PII_BUILTIN_TYPES`): Չսահմանված նշանակում է ամեն տեսակ (այս կարգավորումից առաջ գոյություն ունեցող վարքագիծը): Հարցման շարժիչի `ssn_us` օրինակը քարտեզագրվում է `ssn` ին: Կաղապարները (նվազագույն, ստանդարտ, ֆինանսական, բրազիլերեն, USA, GDPR, POPIA, լրիվ) լրացնում են միայն UI ի վանդակները:
- **GDPR և POPIA նույնացուցիչներ** — տասներկու ներկառուցված ID, որոնք ծածկում են EU և հարավաֆրիկյան անձնական նույնացուցիչները (ստորև բերված աղյուսակը): Նրանց ռեգեքսները, վավերացնողները և իրավասության պիտակները ապրում են մեկ աղյուսակում՝ `src/shared/utils/piiPatterns.ts`, որը սպառում են և՛ արձագանքման ախտահանիչը (`src/lib/piiSanitizer.ts`), և՛ հարցումների դիմակավորողը (`src/shared/utils/inputSanitizer.ts`): Համընկնումը վերագրվում է միայն այն դեպքում, երբ վավերացնողն ընդունում է այն. թվանշանների մերկ շարքը երբեք բավարար չէ: Օպերատորը, ով պահպանել է նեղացված ընտրությունը մինչ այս id-ների գոյությունը, պահպանում է իր վարքագիծը մինչև նոր ID-ների նշումը:
- **Պատվերով նախշեր** — մինչև 20 ռեգեքս կամ նիշերի նախշեր (`*` = մինչև 64 առանց սպիտակ տարածության նիշ, `?` = մեկ): Լուցկիները դառնում են `[CUSTOM_REDACTED]`. Յուրաքանչյուր օրինաչափություն անցնում է `compilePiiCustomPattern()` (`src/shared/utils/piiCustomPatterns.ts`). առավելագույնը 500 նիշ, դրոշները սահմանափակվում են `g i m s u` ով, պետք է կազմվեն, պետք է անցնեն `safe-regex` (աղետալի հետընթաց) և չպետք է համընկնեն դատարկ տողի կամ խմբագրման տեղապահի հետ: Ձախողվող օրինաչափությունը մերժվում է, երբ պահպանվում և փորձարկվում է, և պահված տողը, որը ձախողվում է, բաց է թողնվում գործարկման ժամանակ՝ կազմման փոխարեն: Հատուկ նախշերը գործում են միայն այն ժամանակ, երբ դիմակավորումը միացված է:
- **Հայտնաբերման հաշվիչներ** — յուրաքանչյուր տիպի հաշվում (երբեք չհամապատասխանող արժեքներ), պահվում են հիշողության մեջ և վերագործարկվում են վերագործարկման ժամանակ (`src/lib/pii/piiDetectionStats.ts`): Դրանք միայն ավելանում են, երբ դիմակավորումը միացված է:

Կարգավորումներն ապրում են `key_value` աղյուսակում (անվանատարածք `pii_settings`, `src/lib/db/piiSettings.ts`) և կարդացվում են 1 վ քեշի միջոցով: API:

| Մեթոդ  | Ճանապարհ                 | Նպատակը                                                               |
| ------ | ------------------------ | --------------------------------------------------------------------- |
| `GET`  | `/api/settings/pii`      | Դրոշի վիճակ, `enabledTypes`, `customPatterns`, հայտնաբերման հաշվիչներ |
| `PUT`  | `/api/settings/pii`      | Փոխարինել `enabledTypes` (`null` = բոլորը) and/or `customPatterns`    |
| `POST` | `/api/settings/pii/test` | Չորացնել մեկ օրինակ՝ առավելագույնը 8 KB նմուշի դեմ; ոչինչ չի պահվում  |

Երեքն էլ պահանջում են կառավարման վավերացում և մարմինը վավերացնել Zod ով (`src/shared/validation/schemas/piiSettings.ts`): Եթե մուտքն անջատված է (`requireLogin=false`) `GET`, և թեստի վերջնակետը բաց է, բայց `PUT` դեռ անհրաժեշտ է վահանակի նիստ, `manage` -scope API ստեղն, `oma_` մուտքի նշան՝ գրելու շրջանակով կամ ավելի բարձր, կամ CLI թոքեն կամ ներքին սպասարկման նշան, որն ուղարկվում է loopback-ից:

### Արագ ներարկում (`promptInjection.ts`)

Հայտնաբերում է հակառակորդ կառույցները օգտվողների կողմից տրամադրված բովանդակության մեջ և կիրառում է կազմաձևված քաղաքականությունը: Վարքագիծը պայմանավորված է շրջակա միջավայրի փոփոխականներով և կոնստրուկտորների ընտրանքներով.

| Կարգավորում       | Env var                                                                                                 | Կանխադրված | Էֆեկտ                                                                                                                                                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Միացված է         | `INPUT_SANITIZER_ENABLED`                                                                               | `true`     | Երբ `false`, պաշտպանական բազրիքը կարճ միանում է:                                                                                                                                                                            |
| Ռեժիմ             | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                         | `warn`     | Ներարկման քաղաքականություն՝ `block`, `warn` կամ `log`: (`redact` ընդունված է back-compat-ի համար, բայց ընդունում է** ոչ** շերտի ներարկման տեքստ; PII վերագրանցման հարցումը վերահսկվում է `PII_REDACTION_ENABLED` ի կողմից:) |
| Արգելափակման շեմը | `blockThreshold` տարբերակ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (alias `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`     | Արգելափակման համար պահանջվող նվազագույն խստությունը: Միջինը լռելյայն դեպքում միայն դիտարկելն է:                                                                                                                             |

**Ռեժիմի գերակայություն** (`getMode`)՝ կանչող `options.mode` → `INJECTION_GUARD_MODE`**DB հատկանիշի-դրոշի վերագրում** (Dashboard → Settings → Feature Flags) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env → `warn`. Հետևաբար, վահանակի անտեսումը հաղթում է env vars-ին, ուստի Feature Flags UI վերահսկում է վազող պահակը ուղիղ (առանց վերագործարկման): DB ընթերցումը անվտանգ է ձախողման համար. եթե այն սխալվում է, պահակը հետ է ընկնում env-ի վրա հիմնված վարքագծին, և երբ չի սահմանվում գերակայություն, վարքագիծը նույնական է env-միայն լուծմանը:

Հայտնաբերման աղբյուրներ.

1. `sanitizeRequest()` `@/shared/utils/inputSanitizer` ից (համօգտագործվող դետեկտորների հավաքածու, որն օգտագործվում է խողովակաշարի այլ վայրերում):
2. Ներկառուցված `DEFAULT_GUARD_PATTERNS` (ներկայումս `system_override_inline` և `markdown_system_block`, երկուսն էլ `high` խստություն):
3. Ընտրովի `customPatterns` փոխանցվում է կոնստրուկտորի ընտրանքների միջոցով (տողեր, ռեգեքս կամ `{ name, pattern, severity }` գրառումներ):

Երբ `mode === "block"`** և** առնվազն մեկ հայտնաբերում համապատասխանում է խստության շեմին, `preCall` վերադարձնում է `{ block: true, message: "Request rejected: suspicious content detected" }`: `warn`/`log` ռեժիմներում պահակային բազրիքները գրանցվում են, բայց թույլ են տալիս զանգը: Համօգտագործվող `evaluatePromptInjection()` օգնականը նաև արտահանվում է այն զանգահարողների համար, ովքեր պետք է գնահատեն հուշումները՝ առանց գրանցամատյան անցնելու:

**Սկան կապված (v3.8.20):** դետեկտորը միայն ստուգում է** առաջին 16 KB** միացված հուշագրի տեքստի — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 բայթ) `src/shared/utils/inputSanitizer.ts` ում: Ե՛վ `detectInjection()`, և՛ `evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` նախշերի հանգույցը գործարկելուց առաջ: Ներարկման հրահանգները տեղադրվում են մուտքի վերին մասում, ուստի սա փակում է regex CPU/GC հարյուրավոր ԿԲ ծանրաբեռնվածության վրա՝ առանց հայտնաբերման թուլացման (տես #3932, #4041):

### Հավատարմագրերի դիմակ (`credentialMasker.ts`)

Վազում է** երկուսն էլ** փուլերը, վերջինը լռելյայն շղթայում (առաջնահերթություն `95`): Վերականգնում է հայտնի API-բանալու / գաղտնի նշանի օրինաչափությունները ելքային բեռնվածքից (հաղորդագրությունների բովանդակություն, գործիքի կանչի փաստարկներ, գործիքի արդյունքներ)** և** մատակարարի պատասխանը, այնպես որ հավատարմագրերը, որոնք տեղադրվում են հուշման մեջ (կամ արձագանքվում են գործիքի արդյունքով) չեն արտահոսում վերին հոսքի մատակարարին կամ ետ հաճախորդին:

- **Միայն միանալ** , նույն կոնվենցիան, ինչ PII խմբագրումը (Հարդ կանոն #20- հարակից). անջատված է, եթե `settings.credentialRedactionEnabled === true`** կամ** `CREDENTIAL_REDACTION_ENABLED=true`. Անջատված լինելու դեպքում պաշտպանական բազրիքը ոչ-օպ — է այն երբեք չի արգելափակում և երբեք չի վերագրվում:
- `redactCredentials()` քայլում է ամբողջական payload/response ծառի վրա (`walkValue()`, նախատիպ-աղտոտման-անվտանգ, ցիկլով անվտանգ՝ `WeakSet` միջոցով) և փոխարինում է լուցկիները `[REDACTED:<type>]` տեղապահով՝ կլոնավորելով միայն իրականում փոխված ճյուղերը:
- `CREDENTIAL_PATTERNS` covers LLM provider keys (OpenAI, OpenAI-proj, Anthropic, Google, Hugging Face, Replicate), VCS/SaaS tokens (GitHub, Slack, Linear, Notion, npm, Postman, Discord), payment keys (Stripe, Square), cloud keys (AWS access key, Twilio, SendGrid, Mailgun), private keys / JWTs, credential-bearing connection strings (`mongodb://user:pass@...`, etc.), and a generic `Authorization`/`x-api-key`/`api-key`/`apikey` header-value pattern. Header-shaped keys (`authorization`, `x-api-key`, `api-key`, `apikey`) are redacted structurally (value only, scheme prefix like `Bearer `/`Basic ` preserved) rather than via the generic text regex.
- Պիտակի հետևում գտնվող արժեքը քողարկվում է նույնիսկ այն դեպքում, երբ այն չունի մատակարարի նախածանց՝ `DB_PASSWORD=…`, `AWS_SECRET_ACCESS_KEY=…`, `client_secret: …`, `?api_key=…` (պիտակներ՝ `password`, `passwd`, `secret`, `secret_key`, `secret_access_key`, `api_key`, `access_token`, `refresh_token`, `auth_token`, ցանկացած նախածանցով, ինչպիսին է `DB_`)։ Պիտակը և բաժանարարը մնում են, և արժեքը դառնում է `[REDACTED:secret]`: Արժեքին անհրաժեշտ է 12 կամ ավելի նիշ, այնպես որ `password: required` նման արձակը մնում է ընթեռնելի. արժեքը, որը սկսվում է `$` ով կամ `%` (փոփոխական հղում), մնում է միայնակ:
- Պաշտպանական երկաթուղին երբեք չի արգելափակվում. այն միայն վերագրում է (`modifiedPayload` / `modifiedResponse`) և նշում (`meta.credentialsRedacted`, `meta.count`):

Հետընթաց պահակ՝ `tests/unit/credential-masker-guardrail.test.ts`.

### Գործակալ գվարդիա (`agentGuard/`)

Գործակալի պահակը հաճախորդին դասակարգում է `claude` կամ `anthropic` մատակարարին ուղղված հարցումների հետևում իր վերնագրերից: `AGENT_GUARD_MODE` ընդունում է երեք արժեք՝ `off` (կանխադրված), `monitor` և `block`: `off` ով ոչ մի վերնագիր չի կարդացվում և ոչինչ չի գրանցվում:

Պաշտոնական գործակալները ճանաչվում են այս վերնագրերով (համեմատած մեծատառերի անզգայունությամբ).

- Claude ծածկագիր. `User-Agent` սկսվող `claude-cli/` կամ `claude-code/`, կամ `x-app: cli` `anthropic-beta` վերնագրի հետ միասին կամ `User-Agent`, որը պարունակում է `claude`:
- Anthropic SDKs. `User-Agent` սկսած `Anthropic/`, `AsyncAnthropic/`, `anthropic-typescript/` կամ `anthropic-python/`:

Լոգերի լռելյայն մակարդակը արտադրության մեջ (`info`) ցույց է տալիս գծերի երկու տեսակները: `APP_LOG_LEVEL=warn` ով մնացել են միայն հայտնի երրորդ կողմի տողերը:

Մատյան դաշտեր՝ `agent`, `thirdParty`, `provider`, `model`, `apiKeyId`, `userAgent`, `xApp`, `anthropicBeta`, `xTitle`, `referer`, `stainless`: Վերնագրի արժեքները և մոդելի տողը ծածկված են 200 նիշով: Հղորդը գրանցված է առանց հարցման տողի, հատվածի և օգտվողի տեղեկատվության: API ստեղնը, `Authorization`, `x-api-key` և թխուկները երբեք չեն կարդացվում:

Ֆայլեր՝ `src/lib/guardrails/agentGuard/classifier.ts`, `src/lib/guardrails/agentGuard/policy.ts`, `src/lib/guardrails/agentGuard/guardrail.ts`, `src/lib/guardrails/agentGuard/settings.ts`, `src/lib/guardrails/agentGuard/logLine.ts`, `src/lib/guardrails/agentGuard/enforcement.ts`, `src/sse/handlers/chat/agentGuardGate.ts`:

**Դասակարգման սահմանները (երկու ռեժիմները).**

- Պաշտոնական SDK վրա կառուցված գործակալը, որը ոչ մի `X-Title`, `HTTP-Referer` կամ սեփական `User-Agent` չի ուղարկում, նման է SDK ին: Միայն `x-stainless-*` վերնագրերը հաճախորդին պաշտոնական չեն դարձնում:
- Երրորդ կողմի գործակալները համընկնում են ամբողջ բառի նշաններով `User-Agent`, `X-Title` և `HTTP-Referer` (կամ `Referer`): Չգրանցված հաճախորդները հայտնվում են որպես `unknown`:
- Բրաուզերի վրա հիմնված հաճախորդների հարցումները կրում են զննարկիչի սեփական `User-Agent` և ցուցադրվում են որպես անհայտ, բացառությամբ այն դեպքերի, երբ `X-Title` կամ ուղղորդողը կրում է երրորդ կողմի հայտնի նշան:
- Մեկ մատյան տող յուրաքանչյուր դիտարկված հարցումի համար. զբաղված դեպքերի համար ակնկալեք ծավալ:

#### Մոնիտոր

`AGENT_GUARD_MODE=monitor` ով հարցումները, որոնց մոդելային տողերի անունները `claude` կամ `anthropic` մատակարարին են դասակարգվում ըստ իրենց հաճախորդի վերնագրերի: Երբ հաճախորդը պաշտոնական գործակալ չէ, `tag: "AGENT_GUARD"` ով մեկ մատյան տող է գրվում: Այն `warn` է երրորդ կողմի հայտնի գործակալի և `info` անհայտ հաճախորդի համար: Առաջնահերթություն `1`. պաշտպանիչ բազրիքը կարդում է միայն վերնագրերը և երբեք չի փոխում օգտակար բեռը, ուստի այն անցնում է մեդիա կամուրջներից առաջ: `monitor` երբեք չի արգելափակում:

**`monitor` ի սահմանները.**

- Յուրաքանչյուր ազդանշան հաճախորդի կողմից վերահսկվող վերնագիր է: Սա դիտարկում է, ոչ թե մուտքի վերահսկում:
- Մատակարարը կարդացվում `qtSd/<group>/<provider>/<model>` մոդելի `cc/…` `provider/model` նախքան մոդելի լուծումը. Մերկ մոդելի ID-ները, մոդելների անունները, կոմբինատները և հետագայում երթուղիների նորմալացումը չեն պահպանվում: Այդ խնդրանքները չեն պահպանվում։
- Զանգահարողը կարող է բաց թողնել այն յուրաքանչյուր խնդրանքով ռեեստրի անջատման ալիքների միջոցով (տես [Անջատում Պաշտպանական գծերի յուրաքանչյուր հարցում](#disabling-guardrails-per-request) ): Բաց թողնված հարցումները չեն պահպանվում:
- Այն աշխատում է միայն այնտեղ, որտեղ աշխատում է `runPreCallHooks` (տես [Ծածկույթ և սահմանափակումներ](#coverage-and-limits) ):

#### Արգելափակել

`AGENT_GUARD_MODE=block` հետ նախապես կանչվող պահակապակույտը ոչինչ չի անում: Փոխարենը զրույցի վարիչը որոշում է կայացնում.

1. Որոշումը կայացվում է այն ժամանակ, երբ թիրախը պատրաստվում է ուղարկվել, մատակարարի վրա, որին լուծվել է հարցումը: Մատակարարների անունները, մերկ մոդելի ID-ները, բաժնետոմսերի բաժնետոմսերի նույնականացումը և յուրաքանչյուր համակցված թիրախ ծածկված են:
2. Այն չի գործում պահակային բազրիքների գրանցամատյանում, ուստի յուրաքանչյուր հարցման անջատման ալիքները չեն կիրառվում դրա վրա:
3. Երրորդ կողմի հայտնի գործակալը մերժվում է: Անհայտ հաճախորդը գրանցված է որպես `monitor` ում և մերժվել է միայն `AGENT_GUARD_STRICT=true` ով: Claude կոդը և պաշտոնական Anthropic SDKs երբեք չեն մերժվում։
4. Մերժումը HTTP 403 է `error.type` `permission_error` եւ `error.code` `client_agent_not_allowed`. Մարմինը OpenAI-ի ոճի սխալ է: Anthropic ֆորմատի հարցումների դեպքում այն նաև կրում է `type: "error"` վերին մակարդակում: `Retry-After` վերնագիր չկա, և մերժումը վերադարձվում է մինչև որևէ հոսքի մեկնարկը:
5. Մերժումը մատակարարի ձախողում չէ: Այն չի դիպչում մատակարարի անջատիչին, կապի սառեցմանը կամ մոդելի արգելափակմանը:
6. Կոմբինատում մերժված թիրախը բաց է թողնվում, իսկ մնացած թիրախները վազում են: Հարցումը ձախողվում է քաղաքականության սխալի դեպքում, երբ առնվազն մեկ թիրախ մերժվել է, և ոչ մի թիրախ չի անցել պահակախմբին: Համակցումը պահպանում է իր սեփական սխալը, երբ վերին մակարդակի գրառումը անվանում է մեկ այլ հայտնի մատակարարի՝ նախածանցով կամ քայլի մատակարարի ID-ով: `fallbackOnlyOnQuotaExhaustion` հետ մերժված առաջնահերթ թիրախը բաց է թողնվում նույն կերպ և չի դադարեցնում համակցումը: Ստվերային թիրախը ստուգվում և գրանցվում է, բայց այն երբեք չի հաշվվում որպես թիրախ, որը անցել է պահակախմբի կողքով:
7. `fusion` կոմբինատը ձախողվում է նախքան վահանակի գործարկումը, երբ դատավորը, որը կօգտագործի ֆյուժն ծառայությունը, կմերժվի: Այդ դատավորը գալիս է կոմբինատի կոնֆիգուրացիայից կամ գլոբալ համակցված լռելյայններից: Նույն ստուգումը կատարվում է, երբ միաձուլման կոմբին հասնում է անվտանգության ցանցի վերահղման միջոցով:
8. Մեկ մատյան գիծ յուրաքանչյուր հարցման և մատակարարի համար՝ `tag: "AGENT_GUARD"`, `warn` մերժման համար և նույն դաշտերը, ինչ `monitor`.
9. Ներքին սխալի դեպքում պահակը չի բացվում: Հարցումը շարունակվում է, և մեկ `warn` տող `agent guard failed open` գրանցվում է:

**`block` ի սահմանները.**

- Յուրաքանչյուր ազդանշան հաճախորդի կողմից վերահսկվող վերնագիր է: Հաճախորդը, որն ուղարկում է `User-Agent: claude-cli/…` համարվում է Claude կոդ: `block` կանխում է չփոփոխված երրորդ կողմի գործակալները: Դա մուտքի վերահսկում չէ:
- Վստահված սերվերը, որը քերթում է նույնականացնող վերնագրերը, ցանկացած հաճախորդ վերածում է անհայտի: Նման հաճախորդին սպասարկում են առանց `AGENT_GUARD_STRICT` և մերժում դրա հետ։ Աշխատեք պահակին այն օրինակի վրա, որը կանգնած է հաճախորդներին: Երկրորդ OmniRoute օրինակը առաջինի հետևում տեսնում է առաջինի վերնագրերը:
- `AGENT_GUARD_STRICT` հրաժարվում է յուրաքանչյուր հաճախորդից այն մատակարարներից, որոնք Claude ծածկագիր կամ պաշտոնական SDK չեն: Դա ներառում է բրաուզերի վրա հիմնված հաճախորդներ և վահանակի խաղահրապարակ: Վահանակի համակցված կենդանի փորձարկումն ազատված է նաև անվտանգության ցանցի վերահղման միջոցով:
- Որոշ առանձնահատկություններ ստեղծում են իրենց սեփական զրույցի հարցումը հաճախորդի հարցումը փոխանցելու փոխարեն: Նրանցից չորսն այն հետ են ուղարկում OmniRoute ի `/v1/...` երթուղիներով.
  - խմբաքանակային աշխատանքներ (`src/lib/batches/dispatch.ts`)
  - MCP եզրակացության գործիքներ (`open-sse/mcp-server/tools/inferenceTools.ts`)
  - A2A խելացի երթուղի (`src/lib/a2a/skills/smartRouting.ts`)
  - տեսողության կամուրջը, երբ այն նկարագրում է պատկերը OmniRoute միջոցով (`src/lib/guardrails/visionBridgeHelpers.ts`)
- Telegram chat-ի վստահված անձը (`src/lib/telegram/chatProxy.ts`) ստեղծում է իր հարցումը ընթացքի մեջ և անմիջապես զանգահարում է զրույցի կառավարիչին:
- Այդ ներքին հարցումները կրում են OmniRoute ի սեփական վերնագրերը, այլ ոչ թե հաճախորդի վերնագրերը, որոնք սկսել են դրանք: Պահակը նրանց դասում է որպես անհայտ հաճախորդների։
- Առանց `AGENT_GUARD_STRICT`, այդ ներքին հարցումները մատուցվում են հսկվող մատակարարներին, ով էլ որ լինի սկզբնական հաճախորդը: Երրորդ կողմի գործակալը, որը նրանց միջոցով հասնում է Claude, չի մերժվում:
- `AGENT_GUARD_STRICT` հետ այդ ներքին հարցումները մերժվում են հսկվող մատակարարներից, ովքեր սկսել են դրանք, ներառյալ Claude կոդը:
- Միայն այն հարցումները, որոնք անցնում են զրույցի կարգավորիչով, մուտք են գործում: Մոդելի վավերացումը (`src/lib/modelValidation/runner.ts`) ուղղակիորեն կանչում է հարցման միջուկը և փակված չէ:
- Ծածկված են միայն `claude` և `anthropic` մատակարարները: Մեկ այլ մատակարարի կողմից սպասարկվող Claude մոդելները ապահովագրված չեն, ինչպես նաև `claude-web` մատակարարը:
- Որոշ կոմբինացիաներ անվանում են իրենց մնացած թիրախները՝ առանց մատակարարի նախածանցի, որպես մերկ մոդելի նույնականացում կամ ներկառուցված համադրություն: Երբ այդ թիրախները անհասանելի են անկապ պատճառով (բաց անջատիչ, սառեցում, արգելափակում), հարցումը ձախողվում է քաղաքականության սխալի պատճառով:
- Բաց թողնված համակցված թիրախը մաքրում է այդ թիրախի վերջին հայտնի-լավ քորոցը, ինչպես դա անում է ցանկացած բաց թողնված թիրախ:
- Միաձուլման դատավորը, որը կոչվում է հսկվող մատակարարի նախածանցով, մերժվում է մինչև կոլեգիայի գործարկումը: Այն ընդգրկում է `anthropic/…`, `claude/…`, այլանուն, ինչպիսին է `cc/…`, համատեքստի վերջածանց, ինչպիսին է `[1m]`, և այդ մատակարարների քվոտա-բաժնետոմսերի անունները:
- Միաձուլման դատավորը, որը գրված է որպես մերկ մոդելի ID կամ որպես մոդելային կեղծանուն, որը լուծում է հսկվող մատակարարին, մերժվում է միայն այն դեպքում, երբ այն ուղարկվում է: Վահանակն արդեն գործարկվել է մինչ այդ: Դատավորին իր մատակարարի նախածանցով անվանելը խուսափում է դրանից: Ոչ մի դատավորի ուղղագրություն չի հասնում հսկվող մատակարարին առանց մերժման:
- Նախնական ստուգումը մերժում է կազմաձևված Claude դատավորը նույնիսկ այն դեպքում, երբ միաձուլման ծառայությունը թողնում է այդ դատավորին գործարկման ժամանակ: Ծառայությունը բաց է թողնում դատավորին, որը օպերատորը թաքցրել է, և դատավորին, որը չի կարող վերցնել հարցման լրատվամիջոցը: Երկրորդ գործը վերաբերում է չհաստատված տեսողության ապահովմանը և այլ լրատվամիջոցներին, որոնք դատավորը չի ընդունում: Երկու համակցված ուղիներն էլ այսպես են վարվում:
- Անվտանգության ցանցի վերահղման ժամանակ կոմբինացիոն ծառայությունը ստանում է դատարկ կարգավորումներ: Այնտեղ երբեք չի օգտագործվում դատավոր, որը սահմանված է միայն գլոբալ համակցված լռելյայններում:
- Մինչ `block` միացված է, հաճախորդը, որից պահակը կհրաժարվի հսկվող մատակարարից, չի օգտագործում կողային մեքենայի արագ ուղին որևէ մոդելի համար: `AGENT_GUARD_STRICT` ի ներքո դա յուրաքանչյուր անհայտ հաճախորդ է: Իր ռելեի նշանի ստուգումից հետո `POST /v1/relay/chat/completions/bifrost` պատասխանում է այդ հարցումներին 503-ով և `X-Bifrost-Fallback` վերնագրով:
- `POST /v1/messages/count_tokens` տեղական գնահատական է տալիս հաճախորդին, ում պահակը կհրաժարվի մատակարարից, որին մոդելը որոշում է:
- Մեկ բանալիով բացառություն չկա:

## Բազային պայմանագիր (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true-ն կարճամիացնում է շղթան
  message?: string; // ցուցադրվում է արգելափակելիս
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // վերադարձվում է preCall-ից՝ հարցումը վերաշարադրելու համար
  modifiedResponse?: TValue; // վերադարձվում է postCall-ից՝ պատասխանը վերաշարադրելու համար
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

Guardrail-ը «փոփոխություն չկա» ազդանշան է տալիս՝ վերադարձնելով `void`, `{}` կամ
`{ block: false }`։ `modifiedPayload`/`modifiedResponse` վերադարձնելը
փոխարինում է շղթայով հոսող արժեքը հետևյալ guardrail-ների համար։
`signal?: AbortSignal`-ը կանչողի կյանքի ցիկլը տեղափոխում է guardrail-ներ։ Հարցման
abort-ը գիտակցված fail-open բացառություն է. մեդիա կամուրջները դադարեցնում են
աշխատանքը և մաքրում են ռեսուրսները՝ առանց հում մեդիան վերականգնելու այնպիսի
թիրախի վրա, որի մասին հայտնի է, որ այն չի աջակցում։

## Գրանցամատյան (`registry.ts`)

The singleton `guardrailRegistry` բացահայտում է.

- `register(guardrail)` — ավելացնում է (կամ փոխարինում է նորմավորված անունով) պաշտպանական բազրիք և վերադասավորում է `priority` աճով:
- `clear()` / `list()` — վարչական օգնականներ.
- `runPreCallHooks(payload, context)` — կրկնում է ակտիվ պաշտպանիչ ռելսերը, անցում է օգտակար բեռը `modifiedPayload` միջով և կանգ է առնում առաջին `block: true` վրա:
- `runPostCallHooks(response, context)` — նույն հոսքը արձագանքման կողմում:
- `resetGuardrailsForTests({ registerDefaults })` — մաքրում է վիճակը և կամայականորեն վերագրանցում է լռելյայն մաքուր թեստային մեկուսացման համար:

Երկու վազորդներն էլ վերադարձնում են `{ blocked, payload|response, results, guardrail?, message? }` որտեղ `results` `GuardrailExecutionResult` գրառումների զանգված է, որը ներառում է per-guardrail `blocked`, `skipped`, `modified`, `error` և `meta` դաշտերը, որոնք օգտակար են հետագծման համար:

### Անջատելով պահակակետերը ըստ պահանջի

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` համախմբում է պաշտպանական բազրիքների անունների կրկնօրինակված ցուցակը, որը պետք է բաց թողնել ընթացիկ հարցման համար: Կան հինգ ալիքներ, որոնք կարդացվում են այս հերթականությամբ և միավորվում մեկ ցուցակի մեջ (առաջին դեպքը հաղթում է կրկնօրինակման ժամանակ).

1. `apiKeyInfo.disabledGuardrails`
2. Հայցեք մարմնի `disabledGuardrails` (վերին մակարդակ)
3. Հայցել մարմնի `metadata.disabledGuardrails` (միայն այն դեպքում, երբ `metadata` օբյեկտ է)
4. Վերնագիր `x-omniroute-disabled-guardrails`
5. Ժառանգական վերնագիր `x-disabled-guardrails`

Բոլոր հինգ ալիքները միավորված են, ներառված են երկու վերնագրերը. և՛ `x-omniroute-disabled-guardrails`, և՛ `x-disabled-guardrails` ուղարկելը բաց է թողնում նրանց ցուցակների միավորումը, և դատարկ ժամանակակից վերնագիրն այլևս չի թաքցնում ժառանգվածը ( [#16412](https://github.com/cheaper-inference/OmniRoute/issues/16412), ամրագրված է [#16805](https://github.com/cheaper-inference/OmniRoute/pull/16805) ում):

Արժեքները կարող են լինել տողերի զանգված կամ ստորակետերով բաժանված տող. անունները կտրվում և նորմալացվում են փոքրատառերի քյաբաբի (`pii_masker` → `pii-masker`), իսկ դատարկ գրառումները հանվում են: Արդյունքը `context.disabledGuardrails` միջոցով փոխանցվում է գրանցամատյան, որը բաց է թողնում համապատասխան պահակակետերը (`skipped: true` in `results`):

Անջատման ցանկը ազդում է միայն** գրանցամատյան** . Prompt-injection `block` ռեժիմը պարտադիր սահման է. injection-guard middleware (`src/middleware/promptInjectionGuard.ts`) կանչում է `evaluatePromptInjection()` առանց զանգահարողի կողմից վերահսկվող անջատումների ցանկի (մեռած `resolveDisabledGuardrails({ body })` զանգը, որը նախկինում անում էր, հանվել էր [#16934](https://github.com/cheaper-inference/OmniRoute/pull/16934) ում), ուստի `prompt-injection` անջատող հարցումը դեռ մերժվում է `block` ռեժիմում: Սա դիզայնով է: Անջատված ալիքները վերահսկվում են զանգահարողի կողմից (հարցման մարմին, մետատվյալներ, վերնագրեր), և զանգահարողը չպետք է կարողանա անջատել օպերատորի կողմից սահմանված անվտանգության կառավարումը ( [#16413](https://github.com/cheaper-inference/OmniRoute/issues/16413) ): [#16412](https://github.com/cheaper-inference/OmniRoute/issues/16412) ի վերնագրերի միավորումը փոխում է միայն այն ռեեստրի պաշտպանիչ բազրիքները, որոնք բաց են թողնվել. այն թույլ չի տալիս հաճախորդին շրջանցել միջին ծրագիրը: Պարտադիր մեկ բանալիով և մեկ խմբի համար պաշտպանիչ բազրիքների կանոնները հետևվում են v4 RFC [#16417](https://github.com/cheaper-inference/OmniRoute/issues/16417) ում: Տես [Ծածկույթը և սահմանները](#coverage-and-limits) :

## Կատարման կարգը

`src/sse/handlers/chat.ts` և
`open-sse/handlers/chatCore.ts`-ով անցնող յուրաքանչյուր հարցման համար (չաթի ընտանիքի երթուղիները, որոնք նշված են
[Ծածկույթ և սահմանափակումներ](#coverage-and-limits) բաժնում)՝

1. `resolveDisabledGuardrails(...)`-ը բաց թողնվող ցանկը կազմում է API բանալուց, մարմնից
   և վերնագրերից։
2. `guardrailRegistry.runPreCallHooks(body, ctx)`-ը գործարկում է պաշտպանիչ մեխանիզմները՝ ըստ առաջնահերթության աճման կարգի.
   - Անջատված պաշտպանիչ մեխանիզմները գրանցվում են որպես `skipped`։
   - Յուրաքանչյուր պաշտպանիչ մեխանիզմի `preCall`-ը կարող է վերաշարադրել payload-ը `modifiedPayload`-ի միջոցով։
   - Առաջին `block: true`-ը կարճ միացնում է շղթան, և մշակիչը վերադարձնում է պաշտպանիչ մեխանիզմի մերժման պատասխանը։
3. (Հնարավոր վերաշարադրված) payload-ը փոխանցվում է combo երթուղավորմանը և վերին հոսքի dispatch-ին։
4. **Միայն չհոսքային ռեժիմում.** պատասխանը հավաքելուց հետո
   `guardrailRegistry.runPostCallHooks(...)`-ը նույն շղթան գործարկում է պատասխանի վրա։ Այստեղ `block: true`-ը հեռացնում է վերին հոսքի պատասխանը և վերադարձնում HTTP 400։ Հոսքային պատասխաններն այս քայլն ամբողջությամբ բաց են թողնում։
5. **Միայն շրջելի պահոցի դեպքում.** երբ հարցումը ստեղծել է թոքեններ, `handleChat`-ը դրանք վերականգնում է իր վերադարձվող 2xx պատասխանում՝ post-call hook-երից և հոսքային PII-ի փոխակերպումից հետո, այնպես որ `PII_RESPONSE_SANITIZATION`-ը տեսնում է թոքեններն ու մոդելի կողմից ստեղծված PII-ն, բայց երբեք՝ վերականգնված սկզբնական արժեքը։

Բացառություններ նետող պաշտպանիչ մեխանիզմները գրանցվում են `error: <message>` արժեքով և գրանցամատյանում արձանագրվում են `logger.warn`-ի միջոցով, սակայն շղթան շարունակվում է. սա նախագծված վարքագծով fail-open է։

## Ծածկույթ և սահմանափակումներ

Պաշտպանական երկաթուղային ռեեստրը միացված է միայն զրույցի խողովակաշարին: Այս սահմանները ամրացված են `tests/unit/guardrail-pipeline-wiring-characterization.test.ts` և `tests/unit/guardrail-pipeline-characterization.test.ts`; միտումնավոր թարմացրեք այդ թեստերը, երբ վարքագիծը փոխվում է:

### Որտեղ հոսում են կեռիկները

| Կեռիկ / հսկողություն                       | Վազում է                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `runPreCallHooks`                          | `handleChat` (`src/sse/handlers/chat.ts`) կողմից մշակված հարցումներ՝ `/v1/chat/completions`, `/v1/completions`, `/v1/messages`, `/v1/responses` (և `/v1/responses/*`), `/v1/relay/chat/completions`, `/v1/providers/{provider}/chat/completions`, `/v1/api/chat`, `/v1/antigravity`, `/v1beta/models/*` և Telegram չաթի վստահված անձ: Նաև վահանակի փորձարկման վերջնակետը `/api/guardrails/test`: Նախնական զանգի արգելափակումը վերադարձնում է HTTP 400: |
| `runPostCallHooks`                         | **Չհոսքային** միայն զրույցի պատասխանները (`open-sse/handlers/chatCore/nonStreamingResponse.ts`): Հոսքային պատասխանները երբեք դրան չեն հասնում:                                                                                                                                                                                                                                                                                                         |
| Հոսքային PII                               | `createPiiSseTransform` (`src/lib/streamingPiiTransform.ts`), խողովակաշարով `streamingPipeline.ts` ում, երբ `PII_RESPONSE_SANITIZATION` միացված է: Այն պաշտպանիչ բազրիք չէ, ուստի անջատված ալիքները չեն ազդում դրա վրա:                                                                                                                                                                                                                                |
| Հետադարձելի PII պահոց                      | Հարցումները մշակվում են միայն `handleChat` կողմից, երբ `PII_REDACTION_ENABLED` և `PII_REVERSIBLE_VAULT_ENABLED` միացված են: Նշանները հատվում են `pii-masker` նախնական զանգի միջոցով և վերականգնվում `handleChat` ելքի մոտ (`src/lib/pii/requestTokenVaultScope.ts`): Հարցման համար `pii-masker` անջատելը նշանակում է, որ ոչինչ չկա:                                                                                                                    |
| Injection-guard middleware (ժառանգություն) | Յուրաքանչյուր արագ կրող `/v1` երթուղի, ներառյալ զրույցի ընտանիքը (տես [երթուղու ծածկույթը](#injection-guard-route-coverage--red-team-phase-8--block-d) ): Միայն արագ ներարկում:                                                                                                                                                                                                                                                                        |

### Այն, ինչ ծածկված չէ

- **Մեդիա, ներկառուցումներ և տվյալների երթուղիներ** (`/v1/images/*`, `/v1/embeddings`, `/v1/audio/*`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/rerank`, `/v1/search`, `/v1/moderations`) երբեք գրանցամատյան չի հասնում։ Ոչ մի PII դիմակավորում, հավատարմագրերի քողարկում կամ մոդալության կամուրջ չի անցնում այնտեղ: Նրանց միակ ստուգումը ժառանգական ներարկման-պահպանիչ միջնակարգ ծրագիրն է:
- **Հոսքային պատասխաններ** չստացե՛ք հետզանգման պահակակետեր. ոչ մի `pii-masker` կամ `credential-masker` հետզանգ, և ոչ մի հետզանգի արգելափակում: Կիրառվում է միայն հոսքային PII փոխակերպումը (երբ `PII_RESPONSE_SANITIZATION` միացված է): Հոսքային պատասխանում ստացված հավատարմագիրը չի խմբագրվում:
- **Անջատել ալիքներն ընդդեմ միջին ծրագրի (ըստ դիզայնի).** Միջնակարգ ծրագիրը գնահատում է արագ ներարկումը `evaluatePromptInjection()` ին իր իսկ զանգով՝ առանց զանգահարողի կողմից վերահսկվող անջատումների ցանկի անցնելու: `block` ռեժիմը պարտադիր սահման է, որը զանգահարողի կողմից կառավարվող անջատումները չեն կարող շրջանցել, ներառյալ զրույցի ընտանեկան երթուղիներում ( [#16413](https://github.com/cheaper-inference/OmniRoute/issues/16413) ): `prompt-injection` անջատելու դեպքում բաց է թողնվում միայն ռեեստրի պաշտպանիչ բազուկը:

### Ինչ արձագանք է տեսնում հետզանգից առաջ

Ոչ հոսքային ուղու վրա կարգը հետևյալն է. հիշողության արդյունահանում → ներկառուցված գործիքի կատարում → հետզանգման պահակաձողեր → հետզանգման բլոկ ելք → իմաստային-քեշ պահեստից:

- **Հիշողության արդյունահանում** և** գործիքի կատարում** տեսեք արձագանքը, նախքան հետզանգված պահակային բազկաթոռները կարողանան վերաշարադրել կամ արգելափակել այն: [#16401](https://github.com/cheaper-inference/OmniRoute/pull/16401) ից ի վեր, հիշողության արդյունահանումը գործարկում է արդյունահանված տեքստը `sanitizePII` միջոցով, երբ `PII_RESPONSE_SANITIZATION` միացված է (ինչպես հոսքային, այնպես էլ ոչ հոսքային), բայց պատասխանը, որ հետզանգման հետագա արգելափակումները դեռևս առաջարկվել են հիշողությանը և գործիքներին:
- **Իմաստային քեշը** պահում է պատասխանը հետզանգից հետո, ուստի այն պահում է վերագրված պատասխանը, և արգելափակված պատասխանը երբեք չի պահվում: Քեշի գրառումները մուտքագրվում են ըստ API ստեղնի:

## Կոնֆիգուրացիա

Շրջակա միջավայրի փոփոխականները, որոնք կարդացվում են ներկառուցված պահակակետերով.

| Փոփոխական                             | Օգտագործված է              | Էֆեկտ                                                                                                                              |
| ------------------------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`         | Սահմանեք `false` ամբողջությամբ անջատելու հայտնաբերումը:                                                                            |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`         | Ներարկման քաղաքականություն՝ `warn`, `block` կամ `log`: `redact` ժառանգական արժեքը չի վերագրում ներարկման տեքստը:                   |
| `INJECTION_GUARD_MODE`                | `prompt-injection`         | Ներարկման պահակի ռեժիմ; նաեւ DB հատկանիշի դրոշը, որ** գերագնահատում է** env vars (DB > ENV).                                       |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`         | Նվազագույն խստությունը, որը մերժում է `MODE=block` ՝ `high` (կանխադրված), `medium` կամ `low`:                                      |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`         | Ժառանգական կեղծանուն `INPUT_SANITIZER_BLOCK_THRESHOLD` համար:                                                                      |
| `PII_REDACTION_ENABLED`               | `pii-masker`               | Երբ `true`, հարցումը PII վերադասավորվում է (անկախ ներարկման ռեժիմից):                                                              |
| `PII_REVERSIBLE_VAULT_ENABLED`        | `pii-masker`, `handleChat` | `PII_REDACTION_ENABLED` միջոցով անանուխ դարձրեք շրջելի նշաններ և վերականգնեք դրանք 2xx պատասխաններով:                              |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (ներքև)       | Վերահսկում է արձագանքման կողմի դիմակավորող պահվածքը:                                                                               |
| `AGENT_GUARD_MODE`                    | `agent-guard`              | `off` (կանխադրված), `monitor` կամ `block`: Նաև DB հատկանիշի դրոշակ (DB > ENV):                                                     |
| `AGENT_GUARD_STRICT`                  | `agent-guard`              | `false` (կանխադրված) կամ `true`. `block` հետ նույնպես հրաժարվում է չբացահայտված հաճախորդներից: Նաև DB հատկանիշի դրոշակ (DB > ENV): |

Modality Bridge-ի պաշտպանիչ բազրիքները կարդում են գործարկման ժամանակի կազմաձևը DB-ով ապահովված կարգավորումների խանութից (`getSettings()`), այլ ոչ թե env vars-ից: Vision-ի հիմնական բանալիներն են `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes` և `modalityBridgeCacheMaxEntries`: Ժառանգական `visionBridge*` ստեղները ընդունվում են միայն որպես փաստաթղթավորված մեկ շրջանի հետադարձ ընթերցում; վահանակի գրություններում օգտագործվում են հիմնական ստեղները: Կանխադրվածները և հետադարձ լուծիչը ապրում են `src/shared/constants/modalityBridgeDefaults.ts` ում, իսկ ժառանգական հաստատունները պահպանվում են `src/shared/constants/visionBridgeDefaults.ts` ում:

Աուդիոն օգտագործում է `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout` և `modalityBridgeAudioMaxClips`, գումարած ընդհանուր `modalityBridgeCache*` կարգավորումները: Աուդիոն չունի ժառանգական բանալիների հետադարձ կապ, քանի որ այս ստեղները ներկայացվել են Modality Bridge սխեմայի հետ:

Տեսանյութն օգտագործում է `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos` և `modalityBridgeVideoTimeout`, գումարած ընդհանուր `modalityBridgeCache*` կարգավորումները: Այն անջատված է լռելյայնորեն, քանի որ FFmpeg/ffprobe կամընտիր գործառնական կախվածություն է, իսկ շրջանակի ենթագրերը ավելացնում են ուշացում և մոդելի արժեքը:

## Պատվերով Guardrail-ներ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

Քայլեր.

1. Ստեղծեք `src/lib/guardrails/myGuardrail.ts`՝ ընդլայնելով `BaseGuardrail`-ը։
2. Իրականացրեք `preCall` և/կամ `postCall`։
3. Կա՛մ գրանցեք import-ի պահին (push `registerDefaultGuardrails`-ից), կա՛մ
   կանչեք `guardrailRegistry.register(...)`-ը աշխատանքի ընթացքում — registry-ն
   փոխարինում է նույն նորմալացված անունով ցանկացած նախորդ guardrail-ի։
4. Ավելացրեք թեստեր `tests/unit/`-ում (առկա օրինակներ՝
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`)։

## Թեստավորում

Օգտագործեք `resetGuardrailsForTests()`-ը թեստերի միջև՝ հայտնի վիճակից սկսելու համար։
Փոխանցեք `{ registerDefaults: false }`՝ դատարկ registry-ով սկսելու և միայն
թեստավորվող guardrail-ները գրանցելու համար։ Vision Bridge-ը ընդունում է dependency
injection (`deps.getSettings`, `deps.callVisionModel`); Audio Bridge-ը բացում է
համարժեք seam-եր կարգավորումների, հնարավորությունների, STT մոդելի ընտրության,
credential-ների ստուգումների և տառադարձման համար։ Ուստի թեստերը կարող են ստուգել
երկու հոսքերն էլ՝ առանց DB կամ ցանցային հասանելիության։

## Ներարկման երթուղու ծածկույթ և կարմիր թիմ (փուլ 8 · բլոկ D)

Ներարկման պահակը (`createInjectionGuard` / `withInjectionGuard`) ընդգրկում է բոլոր երթուղիները, որոնք ընդունում են օգտվողի հուշումները: Այն հարգում է `INJECTION_GUARD_MODE` (միայն լռելյայն `warn` = log; `block` = վերադարձնում է HTTP 400 `SECURITY_001`):

| Տեսակ        | Երթուղիներ                                                                                                                                           | Կանխադրված ռեժիմ |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| Տեքստ (առկա) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | զգուշացնել       |
| Գեներատիվ    | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | զգուշացնել       |
| Տվյալներ     | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | զգուշացնել       |

Տեքստի արդյունահանումը (`extractMessageContents`) ներառում է `messages`/`input`/`prompt`/`query` + `documents`/`instructions`/`system`:

**Կարմիր թիմ (գիշերային, `nightly-llm-security.yml`):** promptfoo-ն հաստատում է, որ յուրաքանչյուր երթուղի արգելափակում է OWASP-LLM կորպուսը `INJECTION_GUARD_MODE=block` ում; garak-ն աշխատում է զոնդերով (բաց է թողնում առանց գաղտնիքի): `moderations` ներառված է հետևողականության համար: Արգելափակման ռեժիմը պարտադիր սահման է. `evaluatePromptInjection()` անտեսում է յուրաքանչյուր հարցման անջատման ցանկը, իսկ միջին ծրագիրը անցնում է այն, ուստի `disabledGuardrails` անում է:** ոչ** ազատել երթուղին դրանից ( [#16413](https://github.com/cheaper-inference/OmniRoute/issues/16413) ):

Գիշերային աշխատանքային հոսքը (`.github/workflows/nightly-llm-security.yml`, cron + ձեռնարկի առաքում) ունի երկու աշխատանք.

- **`promptfoo-guard` (արգելափակում)** — աշխատում է `promptfoo eval -c promptfooconfig.yaml` ով `INJECTION_GUARD_MODE=block`: Յուրաքանչյուր հակառակորդ դեպք (օրինակ՝ «անտեսել բոլոր նախորդ հրահանգները…», DAN ոճի jailbreaks) պնդում է, որ պատասխանը կրում է `error.code === "SECURITY_001"`, այսինքն՝ պահակը իրականում մերժել է հարցումը:
- **`garak` (խորհրդատվական)** — գործարկում է garak `--probes promptinject,dan,leakreplay` տեղական OmniRoute օրինակի դեմ (`http://localhost:20128/v1`): Փակված է մատակարարի գաղտնիքի վրա (`PROMPTFOO_PROVIDER_KEY`); նրբագեղորեն բաց է թողնում և ածանցվում է `|| true`, ուստի հաղորդում է առանց ձախողման CI:

Coverage of the guard helper (`createInjectionGuard` / `withInjectionGuard`) spans every prompt-bearing `/v1` route; prompt text is pulled from `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` by `extractMessageContents()` in `src/shared/utils/inputSanitizer.ts`.
