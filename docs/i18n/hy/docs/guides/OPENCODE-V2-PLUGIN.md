`@omniroute/opencode-plugin-v2`-ը ձեր ամբողջ OmniRoute կատալոգը՝ մոդելները, կոմբոները և
ավտոկոմբոները, ավելացնում է OpenCode v2-ի մոդելների ընտրիչում՝ ցուցադրվող անուններով, գնագոյացմամբ և անվճար մակարդակի
սահմանաչափերով։

Այն `@omniroute/opencode-plugin`-ից առանձին փաթեթ է, քանի որ OpenCode v1-ը և v2-ը
փլագինները բեռնում են տարբեր պայմանագրերով։ Ընտրեք ձեր OpenCode-ի հիմնական տարբերակին համապատասխանողը․
դրանց միջև ոչինչ ընդհանուր չէ, ուստի մեկի թարմացումը երբեք չի պարտադրում թարմացնել մյուսը։

## Պահանջներ

- OpenCode v2։
- Հասանելի OmniRoute դարպաս (`http://localhost:20128`՝ լռելյայն)։
- Node.js 22 կամ 24։

## Տեղադրում

Ավելացրեք փլագինը `opencode.json`-ում․

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Այնուհետև մոդելները հայտնվում են որպես `omniroute/<provider>/<model>`․ `providerId`-ը որոշում է այդ նախածանցը և
այն ինտեգրման նույնացուցիչը, որի տակ OpenCode-ը պահում է հավատարմագիրը։

## Հավատարմագրեր

Փլագինը դարպասի բանալին որոնում է երեք տեղում՝ հետևյալ հերթականությամբ․

1. **OpenCode-ում ձեր միացրած հավատարմագիրը։** Փլագինը գրանցում է ինտեգրում, որպեսզի
   OpenCode-ի սեփական նույնականացման հոսքը կարողանա պահել բանալին։ `opencode.json`-ում ոչինչ չի հայտնվում․ նախընտրեք այս տարբերակը։
2. `apiKey`-ը՝ փլագինի ընտրանքներում, յուրաքանչյուր նախագծի համար առանձին վերագրանցման նպատակով։ Այն բանալին տեղադրում է մի ֆայլում, որը
   կարող եք ներառել commit-ում։
3. `OMNIROUTE_API_KEY`-ը՝ միջավայրում։

Եթե երեքից ոչ մեկը չկա, կատալոգը դատարկ է մնում, և փլագինը գործարկման ժամանակ մեկ անգամ հայտնում է այդ մասին՝
ձեզ լուռ դատարկ ընտրիչով թողնելու փոխարեն։

### Կառավարման թոքենն այլ բանալի է

Կոմբոները, մատակարարների վիճակը և հարստացված տվյալները (ցուցադրվող անուններ, գնագոյացում, անվճար մակարդակի սահմանաչափեր) ստացվում են
դարպասի `/api/*` վերջնակետերից, որոնք տեղակայումների մեծ մասում պաշտպանված են **կառավարման** թոքենով,
այլ ոչ թե ինֆերենցիայի բանալիով․

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<կառավարման ընթերցման թոքեն>"
}
```

Եթե սահմանված չէ, `managementReadToken`-ը հետադարձաբար օգտագործում է `apiKey`-ը։ Երբ դարպասը մերժում է այդ հետադարձ տարբերակը,
կատալոգը միևնույն է հրապարակվում է, սակայն ցուցադրվող անունների փոխարեն՝ մոդելների սկզբնական նույնացուցիչներով, առանց կանոնական
այլանունների կրկնությունների հեռացման, գնագոյացման և կոմբոների։ Երբ դա տեղի է ունենում, փլագինը յուրաքանչյուր վերջնակետի համար մեկ անգամ զգուշացնում է՝
նշելով վերջնակետը և կորցրած հնարավորությունները, որպեսզի սահմանափակված ընտրիչի պատճառը երբեք առեղծված չմնա։

| `apiFormat.anthropicModels`      | `[]`                                            | Ամբողջական մոդելի ID-ներ ուղղվել են Anthropic ին                                                                                                                                                                                                                                                                                                                                         |
| `logLevel` / `startupDebug`      | `warn` / `false`                                | Լոգերի խոսակցություն                                                                                                                                                                                                                                                                                                                                                                     |

Օգտագործման հիշողությունը լռելյայն միացված է: Առանց կառավարման նշանի այն մնում է իներտ (գործարկման ծանուցումը գրանցվում է) և ոչինչ չի վերականգնվում:

## Ինչպես կատալոգը թարմ է մնում

Կատալոգը բերվում է ծուլորեն և պահվում է `modelCacheTtlMs` համար, իսկ սկավառակի լուսանկարը հասանելի է պահում վերջին հայտնի կատալոգը, երբ դարպասն անհասանելի է — իսկ անջատումը ձեզ ոչինչ չի արժենում, բացի թարմությունից: Մոդելները և կոմպոզիցիաները հրապարակվում են հենց որ նրանք հասնում են. ավտոմատ կոմբինացիաները, մատակարարների ցանկը և հարստացման ծածկույթը ծալվում են, երբ վայրէջք են կատարում, ուստի մեկ դանդաղ վերջնակետը չի կարող պատանդ պահել ամբողջ ընտրողին:

Անունները հաջորդում են `Provider - Model[ (Editor)][ · budget][ (route)]`. մատակարարը ցուցադրվում է ամեն անգամ, երբ id-ը կրում է մեկը (առանց նախածանցի id արտասանվում է առանց նախածանցի), առաջատար `🆓` նշում է անվճար մուտքերը, և դրանց ազատ մակարդակի բյուջեն մնում է որպես `· 1M tokens/month` վերջածանց, բացահայտ `Editor: Model` անվան խմբագրիչը տեղափոխվում է `combo - <slug>` փակագծեր (առանց այլ խմբագիրների՝ առանց խմբագիրների ազատ գրառումների) պատկերակը։ Երկու գրառում, որոնք կիսում են անունը, ստանում են երթուղու վերջածանց — `(no-think)` —, որպեսզի նրանք մնան տարբերվող: `providerTag` (կանխադրված `true`) փոխում է վերջին խմբագրի փակագծերը:

Ձեռքով թարմացման հրաման չկա. OpenCode v2 հրամանները հուշման ձևանմուշներ են, այլ ոչ թե հետադարձ զանգեր, ուստի հավելվածը չի կարող բացահայտել այն: Թարմացումները հետևում են TTL ին; հյուրընկալողին խնդրում են վերաբեռնել միայն այն դեպքում, երբ կատալոգը կամ ծածկույթն իրականում փոխվել է, ոչ մի անգամ մեկ թարմացման համար:

## Գործիքների կանչը Gemini-ում

Gemini-ն մերժում է ամբողջ հարցումը, եթե դրա գործիքների հայտարարությունները պարունակում են `$schema` կամ `additionalProperties`՝ պատասխանելով `400 INVALID_ARGUMENT`։ Հավելումը հեռացնում է այդ բանալի բառերը այս մատակարարի Gemini մոդելին ուղարկվող գործիքների սխեմաներից և բոլոր մյուս հարցումները թողնում է անփոփոխ։ `$ref`պարունակող գործիքն ուղարկվում է անփոփոխ՝ առանց մաքրման, քանի որ հղումը հեռացնելը կընդլայներ սխեման՝ դարձնելով այն «ընդունել ամեն ինչ»։
Այն անջատելու համար սահմանեք`"geminiSanitization": false`։
