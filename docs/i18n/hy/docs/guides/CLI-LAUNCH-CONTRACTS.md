Չեզոք `config/cli-tools-manifest.json` պայմանագիրը հայտարարում է կանոնական IDs, այլանուններ, երկուական թեկնածուներ, տեղադրման բաղադրատոմսեր, մոդելային փաստարկներ և հնարավորություններ: Պարզ Node ադապտեր `bin/cli/cli-manifest.mjs` ում և TypeScript ադապտեր `src/shared/constants/cliIntegrationManifest.ts` ում կարդում են նույն ֆայլը: Գործարկման ժամանակը, կատալոգը, կազմաձևումը, ավարտը, գեներատորները և հետին պլանի գրանցումը ստուգվում են միասին `tests/unit/cli/cli-manifest-drift.test.ts` կողմից: Կատալոգավորված լինելը չի նշանակում, որ գործիքը կարող է գործարկվել կամ կազմաձևվել: Մասնավորապես, 5dive-ը մնում է միայն կարգավորելու համար:

## Երեխաների միջավայրը և կյանքի ցիկլը

`omniroute run`, `omniroute launch` և `omniroute launch-codex` ժառանգում են OS/terminal համատեղելիության թույլտվության ցանկը և ներարկում ընտրված թիրախի հավատարմագրերը: Անկապ մատակարարի և տվյալների բազայի գաղտնիքները լռելյայն չեն ժառանգվում: `--inherit-env` բացահայտորեն վերականգնում է ծնող-միջավայրի ամբողջական ժառանգությունը. օգտագործել այն միայն այն ժամանակ, երբ ընտրված երրորդ կողմի գործընթացը պետք է ստանա այդ արժեքները: Սա միջավայրի զտիչ է, ոչ թե OS ավազատուփ. գործընթացը դեռ աշխատում է զանգահարողի ֆայլային համակարգի թույլտվություններով:

Ընդհատման և դադարեցման ազդանշանները փոխանցվում են երեխային: Գործարկիչը սպասում է երեխայի փակ իրադարձությանը, նախքան ժամանակավոր կոնֆիգուրացիան հեռացնելը: `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` վերահսկում է արտոնյալ ժամանակահատվածը մինչև հարկադիր դադարեցումը (կանխադրված 5000 միլիվայրկյան):

## Gemini համառ կարգավորում

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

Առաջին երկու հրամանները կարգավորում են այս մեքենան ընտրված տեղական կամ հեռավոր սերվերի համար: Setup-ը պահպանում է անկապ JSON կարգավորումները, ընտրում է Gemini API-բանալու վավերացումը և վերջնակետն ու հավատարմագրերը գրում մասնավոր `.gemini/.env` ֆայլում: Այն հրաժարվում է անվավեր JSON այլ ոչ թե վերագրանցում այն: URLs վերջնակետը պետք է լինի HTTP(S), առանց ներկառուցված հավաստագրերի, հարցման պարամետրերի կամ դրվագների: Dry-run-ը տպում է ուղիներ, ոչ թե հավատարմագրային արժեքներ:

`GEMINI_CLI_HOME` կամ `--gemini-home` ընտրում է մշտական տնային արմատը: Իրական `run gemini` ստեղծում և հետագայում հեռացնում է իր սեփական ժամանակավոր տունը: Ոչ մի ռեժիմ չի շրջանցում Gemini ի աշխատանքային տարածքի վստահության ստուգումները:

## Codex պրոֆիլներ

`configure codex` գրում է մասնավոր `<name>.config.toml` մոդելով և դրա OmniRoute մատակարարի վերջնակետով: Հավատարմագրերը հղվում են `OMNIROUTE_API_KEY` միջոցով, երբեք չեն ներկառուցված: Գործարկման հրամանը ընտրված մոդելը դնում է վերին մակարդակի `model` ստեղնի վրա, ոչ թե `model_providers` ներսում:

Առանձին պրոֆիլի ֆայլերը ընթացիկ փաստաթղթավորված Codex պայմանագիրն են. նրանք ծածկում են օգտվողի կոնֆիգուրացիան, երբ ընտրվում է `codex --profile <name>` ով: Տես [պաշտոնական պրոֆիլի հղումը](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) և [OmniRoute Codex ուղեցույցը](./CODEX-CLI-CONFIGURATION.md) :

## Հերմետիկ հրամանի կատարում

Հստակ `DATA_DIR` դեպքում, `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` կարգավորումը թույլ չի տալիս գործարկման մեկնարկին անցնել կանխադրված օգտատիրոջ տվյալների գրացուցակի հավատարմագրերի միջավայր: Սա օգտակար է մեկուսացված թեստերի համար: Այն չի անջատում այլ հստակ ընտրված միջավայրի ֆայլեր:

## Աշխատանքային տեղեկատու `.env`

CLI կարդում է `.env` ֆայլերը այս հերթականությամբ, և հաղթում է առաջին ֆայլը, որը սահմանում է բանալին՝ հստակ `DATA_DIR`, տվյալների լռելյայն գրացուցակը, ընթացիկ աշխատանքային գրացուցակը, ապա փաթեթի գրացուցակը: Shell փոփոխականները միշտ հաղթում են:

Աշխատանքային գրացուցակը կարող է պատկանել մեկ ուրիշին (կլոնավորված պահոց, չփաթեթավորված արխիվ), և `omniroute serve` CLI միջավայրը փոխանցում է սերվերին և սերվերի կողմից գործարկվող յուրաքանչյուր գործիքին: Այսպիսով, `.env` այնտեղ կարող է սահմանել միայն այս ստեղները, որոնք նշված են `bin/cli/utils/untrustedCwdEnv.mjs` ում.

| Բանալին                         | Ընդունված արժեքներ                                                                           |
| ------------------------------- | -------------------------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` կամ `yes` ամեն դեպքում, այն արժեքները, որոնք սերվերը վերաբերվում է որպես միացված |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | մինչև 64 տառ, թվանշան, `_`, `.`, `@` կամ `-`                                                 |
| `LANGUAGE`                      | նույնը, գումարած `:`                                                                         |
| `TZ`                            | մինչև 64 տառ, թվանշան, `_`, `+`, `-` կամ `/`, `/` ով չսկսվող                                 |
| `NO_COLOR`, `FORCE_COLOR`       | մինչև 16 տառ և թվանշան                                                                       |

Յուրաքանչյուր արժեք, որն ընդունում է `REQUIRE_API_KEY` միացնում է ստուգումը, ուստի ֆայլն ինքն իրեն չի կարող անջատել չեկը: Այնուամենայնիվ, այն չի որոշում արդյունքը. սերվերը կարդում է տվյալների բազայում պահպանված `REQUIRE_API_KEY` վերափոխումը շրջակա միջավայրից առաջ, մինչդեռ գործարկման նախազգուշացումը բոլոր ինտերֆեյսներում առանց API ստեղնի լսելու մասին կարդում է միայն միջավայրը: `false` ի պահպանված վերափոխման դեպքում աշխատանքային գրացուցակը `REQUIRE_API_KEY=true` բաց է թողնում API ը և թաքցնում այդ նախազգուշացումը: `TZ` կանոնն ավելի նեղ է, քան POSIX. այն մերժում է `.`, `:`, `,` և `<>`, ուստի `:Area/City` ձևը և կանոնները, ինչպիսիք են `EST5EDT,M3.2.0,M11.1.0` պետք է տեղադրվեն կեղևում կամ `<DATA_DIR>/.env` ում:

Անունները պետք է ճիշտ համապատասխանեն մեծատառով: Ցանկացած այլ տող, արժեք, որը չի ստուգվում, և անունը, որը պարզ ASCII տառեր, թվանշաններ և `_` չեն (օրինակ՝ NUL բայտով կամ նմանվող տառով) բաց են թողնվում: CLI ը տպում է մեկ նախազգուշացում, որն անվանում է այն ստեղները, որոնք նա չի կարող սահմանել, և մեկը, որն անվանում է թույլատրված ստեղները, որոնք այն անտեսել են, որոնցից յուրաքանչյուրը պետք է փոխի (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`): Երկուսն էլ չեն տպում արժեքները: Այս հաղորդագրությունների ֆայլերի ուղիները և `.env` ուղու `omniroute doctor` հաշվետվությունները դուրս են մնում, երբ դրանք պարունակում են հսկիչ կամ bidi նիշեր: Սահմանափակումը չի կիրառվում, երբ աշխատանքային գրացուցակը տվյալների գրացուցակն է կամ փաթեթի գրացուցակը:

`PORT`, `API_PORT` և `DASHBOARD_PORT` ցուցակում չկան: Առանց բազային URL ավելի բարձր գերադաս աղբյուրից, CLI խոսում է `localhost:<PORT>` հետ, և ինչ լսում է այնտեղ, ստանում է CLI ի API ստեղնը, համատեքստի նշանը և CLI մեքենայի նշանը (`x-omniroute-cli-token`, տե՛ս [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), որը տեղական սերվերն ընդունում է կառավարման զանգերի համար loopback-ից: Աշխատանքային գրացուցակի մի նավահանգիստը թույլ կտա այդ ֆայլին ընտրել լսողին, ուստի տեղադրեք նավահանգիստները shell-ում, `<DATA_DIR>/.env` ով կամ հրամանների `--port` տարբերակով, որոնք ունեն մեկ (`serve`, `launch`, `run`):

Վերլուծիչը չունի `export` շարահյուսություն: Մի տող, ինչպիսին `export LD_PRELOAD=...` է, անվանում է փոփոխական `export LD_PRELOAD`; աշխատանքային գրացուցակից այն բաց է թողնվում, իսկ մյուս `.env` ֆայլերում սահմանում է այդ բառացի անունը, որը ոչինչ չի կարդում։

CLI ն զուգավորում է համատեքստի պահպանված նշանը (մուտքի նշան կամ ժառանգական API ստեղն) միայն այդ համատեքստի սեփական ծագման հետ՝ սխեմա, հոսթ և նավահանգիստ՝ համեմատած `URL.origin` հետ: Սա վերաբերում է CLI ի HTTP հաճախորդի միջոցով արված հարցումներին (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) և `launch`, `launch codex`, `configure` և `setup-*` հրամաններին, որոնք գրում են բազային URL և բանալի մեկ այլ գործիքի կազմաձևում: Նշված `--remote` ով մեկ այլ սերվերի վրա, նրանք օգտագործում են բացահայտ `--api-key` կամ `OMNIROUTE_API_KEY`, եթե մեկը սահմանված է, և առանց համատեքստի նշան: Համեմատությունը ճշգրիտ է, ուստի `localhost` և `127.0.0.1`, կամ հոսթինգը հետագծային կետով և առանց դրա, համարվում են տարբեր սերվերներ և չեն ստանում համատեքստի նշան: Օգտվողի տեղեկություններով, հետադարձ տողով կամ բացատով URL երբեք չեն համընկնում, քանի որ մյուս URL վերլուծիչները (օրինակ՝ Python-ի `urllib` և `httpx`) կարող են կարդալ դրանից տարբեր հոսթ: Հարցումների համար CLI ինքն է ուղարկում, այդ ստուգումը ընդգրկում է միայն սխեման և հեղինակությունը, այնպես որ ճանապարհին կամ հարցումում բացատ ունեցող ID-ն պահում է նշանը:
