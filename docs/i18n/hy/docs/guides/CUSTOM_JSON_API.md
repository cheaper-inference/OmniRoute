Հատուկ JSON API հանգույցը միացնում է JSON բիզնեսի վերջնակետը, որը չի խոսում OpenAI կամ Anthropic արձանագրությունը: OmniRoute լրացնում է JSON հարցման ձևանմուշը, այն ուղարկում է ամբողջական վերջնական կետ URL, պատասխանը կարդում է պատասխանի ուղուց և այն վերադարձնում հաճախորդին հաճախորդի սեփական ձևաչափով (Զրույցի լրացումներ, պատասխաններ, հաղորդագրություններ, ...):

Այն OpenAI-ի հետ համատեղելի հանգույց է `apiType: "custom-json"` ով; դրա id-ն ունի `openai-compatible-custom-json-<suffix>` ձևը: Վահանակի ձևը դեռ հասանելի չէ: Ստեղծեք և խմբագրեք այս հանգույցները ներքևում գտնվող մատակարար-հանգույց API միջոցով:

## Ստեղծեք հանգույց

`POST /api/provider-nodes` (կառավարման հեղինակություն):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` է** ամբողջական** վերջակետ URL. Ոչինչ կցված չէ (ոչ `/chat/completions`, ոչ `/models`) և, ի տարբերություն OpenAI-ի հետ համատեղելի այլ հանգույցների, չկա լռելյայն URL: Այն պետք է լինի `http(s)`, առանց ներկառուցված հավատարմագրերի կամ `#fragment`, և այն անցնում է նույն ելքային URL պահակը, ինչպես յուրաքանչյուր մատակարարի հանգույց, և՛ երբ հանգույցը պահվում է, և՛ յուրաքանչյուր խնդրանքով:
- Մի հանգույց, որն ուղարկում է կապի բանալին (`authType` `bearer` կամ `api-key`, ներառյալ լռելյայն) պետք է օգտագործի `https://`: Պարզ `http://` ընդունվում է միայն loopback հոսթի համար (`localhost`, `127.0.0.0/8`, `::1`) կամ `authType: "none"` ով, որը ոչ մի բանալի չի ուղարկում: Մասնավոր LAN հասցեները (`10.x`, `172.16-31.x`, `192.168.x`) չեն ազատվում. այդ ցանցում յուրաքանչյուրը կարող է կարդալ բանալին: Նման հանգույցի պահպանումը ձախողվում է `400` ով, և նախկինում պահված հանգույցը ձախողվում է փակվել յուրաքանչյուր հարցում նույն հաղորդագրությամբ, նախքան որևէ հարցում ուղարկելը: LAN վրա ստեղնավորված վերջնակետի համար դրեք այն TLS հետևում (օրինակ՝ հակադարձ պրոքսի):
- `customJson` վավերացված է Zod ով; անհայտ բանալիները մերժվում են: Յուրաքանչյուր դաշտ կամընտիր է.

| Դաշտ              | Արժեքներ                                         | Կանխադրված                                             |
| ----------------- | ------------------------------------------------ | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                           | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                      | `bearer`                                               |
| `authHeader`      | վերնագրի անունը օգտագործվում է `api-key` ժամանակ | `X-API-Key`                                            |
| `requestTemplate` | JSON օբյեկտ (≤ 64 KB, խորություն ≤ 32)           | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | դաշտային ճանապարհ, կամ `$` ամբողջ մարմնի համար   | `choices[0].message.content`                           |

- Գաղտնիքը մնում է կապի API բանալիում, ոչ երբեք կաղապարի մեջ: `bearer` ուղարկում է `Authorization: Bearer <key>`; `api-key` ուղարկում `<authHeader>: <key>`. Հաստատման վերնագիրը չի կարող լինել `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` կամ hop-by-hop վերնագիր: `none` ի հետ կապերը բանալին կարիք չունեն:
- Լրացուցիչ ստատիկ վերնագրերը օգտագործում են հանգույցի կանոնավոր `customHeaders` (նույն վավերացումը, ինչ բոլոր մյուս համատեղելի հանգույցները. auth վերնագրերն այնտեղ թույլատրված չեն):

`PUT /api/provider-nodes/<id>` ընդունում է նույն `customJson` և վերագրում է `baseUrl` և կոնֆիգուրը հանգույցի յուրաքանչյուր գոյություն ունեցող կապի վրա: `customJson` բացթողումը պահպանում է պահված կազմաձևը. `apiType` ին `chat` ին կամ `responses` անցնելը հեռացնում է այն հանգույցից և դրա միացումներից:

Այնուհետև սովորականի պես միացում ավելացրեք հանգույցին (`POST /api/providers` հանգույցի id-ով) և խնդրեք `<prefix>/<model>`, օրինակ `biz/assistant-v1`: Վերջնական կետը չի բացահայտում մոդելների ցանկը, այնպես որ ձեռքով ավելացրեք մոդելի ID-ները:

## Կաղապարներ խնդրեք

Կաղապարները պարզ JSON են: Լարի արժեքը կարող է պարունակել `{{placeholder}}` մարկերներ; ոչինչ չի գնահատվում կամ կատարվում, և օբյեկտի ստեղները երբեք չեն փոխարինվում:

| Տեղապահ              | Արժեք                                                                        |
| -------------------- | ---------------------------------------------------------------------------- |
| `{{prompt}}`         | Օգտվողի վերջին հաղորդագրության տեքստը (տեքստի մասերը միացված են նոր տողերով) |
| `{{messages}}`       | Զրույցը OpenAI chat ձևաչափով                                                 |
| `{{model}}`          | Պահանջվող մոդելի ID-ն՝ առանց մատակարարի նախածանցի                            |
| `{{stream}}`         | Միշտ `false` — վերջնակետը պատասխանում է մեկ JSON փաստաթղթով                  |
| `{{request.<path>}}` | Թարգմանված (OpenAI chat ձևաչափ) հարցման դաշտ                                 |

- Արժեքը, որը ճիշտ մեկ տեղապահ է, պահպանում է իր JSON տեսակը (`"{{messages}}"` դառնում է զանգված); ավելի երկար տողի ներսում տեղապահը տեղադրվում է որպես տեքստ:
- Տեղապահը, որը լուծում է ոչնչին, ձախողում է հարցումը HTTP 400-ի միջոցով՝ թերի բեռ ուղարկելու փոխարեն:
- Ճանապարհները օգտագործում են կետերի նշում և թվային ինդեքսներ (`data.items[0].text`): `__proto__`, `prototype` և `constructor` մերժվում են բանալիներում և ուղիներում:

## Պատասխաններ

`responsePath` ի արժեքը դառնում է օգնականի պատասխանը. տողերը անցնում են, մյուս JSON արժեքները սերիականացվում են: Բացակայող կամ `null` դաշտը կամ մարմինը, որը JSON չէ, վերադարձնում է HTTP 502: Վերին հոսքի սխալի կարգավիճակները փոխանցվում են: Հոսքային հաճախորդների համար OmniRoute սպասում է JSON ողջ պատասխանին, այնուհետև այն թողարկում է որպես բովանդակության մեկ կտոր գումարած ավարտի հատվածը; սա նշանային հոսք չէ: Գործիքների զանգերը և օգտագործման դաշտերը քարտեզագրված չեն:

## Երբեք չի վերարտադրվել

Բիզնեսի հարցումը կարող է ունենալ կողմնակի ազդեցություններ նույնիսկ այն դեպքում, երբ այն ձախողվում է: Հետևաբար, OmniRoute մեկ անգամ ուղարկում է.

- ոչ մի տրանսպորտի կրկնություն և ոչ մի վերահղում.
- այլ կապի վրա նորից չփորձեք (հաշվի հետադարձ կապ) — խափանումը վերադարձվում է այնպես, ինչպես կա, և կապը չի սառեցվում;
- ոչ մի հետադարձ հաջորդ համակցված թիրախին, նույնիսկ դատարկ կամ ձախողված պատասխանի համար:

Հաճախորդների առանձին հարցումները և միաձուլման վահանակները, որոնք բացահայտորեն կանչում են մի քանի մոդելներ, դեռևս ինքնուրույն են կանչում վերջնակետը:

## Հանգույցի փորձարկում

Կապի պահպանում, կապ** Փորձարկում** կոճակը և ֆոնային առողջության ստուգումները երբեք չեն կանչում վերջնակետը. դրանք միայն վավերացնում են պահված կոնֆիգուրգը և հայտնում կապը որպես չստուգելի:

`POST /api/provider-nodes/validate` `"apiType": "custom-json"` ով և հանգույցի դաշտերով (`baseUrl`, `apiKey`, `customJson`, կամընտիր `customHeaders` և `modelId`) ուղարկում է ուղիղ մեկ իրական հարցում՝ `ping` ով որպես օգտվողի վերջին տեքստ: Այն պատասխանում է `{ "valid": true }` կամ վերին հոսքի կարգավիճակին (երբեք հոսանքին հակառակ մարմնին):

## Պահպանում
