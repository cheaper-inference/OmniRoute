## Ինչ է այն (և ինչ չէ)

OmniRoute-ը յուրաքանչյուր ավարտված հարցմանը վերագրում է USD-ով արժեք՝ թոքենների
քանակները բազմապատկելով մոդելի գնային դրույքաչափերով։ Այս թվերն օգտագործվում են
**Ծախսեր** վահանակում, `omniroute cost` / `omniroute usage` CLI-ում, CSV/JSON
արտահանումներում և առանձին API բանալիների բյուջեներում։

> **Վահանակի «ծախսը» խնայողությունների հաշվիչ է, այլ ոչ թե հաշիվ։** OmniRoute-ը ձեզանից
> երբեք գումար չի գանձում. այն ձեր հարցումներն ուղղորդում է այն մատակարարներին, որոնց դուք
> արդեն միացրել եք՝ ձեր սեփական բաժանորդագրությունները, անվճար մակարդակները և API բանալիները։
> Միայն անվճար մոդելներով կուտակված «$290 ընդհանուր ծախսը» նշանակում է մոտավորապես
> **$290, որը դուք _չեք վճարել_** վճարովի API-ին։ Այդ թիվը նույն տրաֆիկի՝ ստանդարտ հրապարակված
> գներով հնարավոր արժեքի _գնահատականն_ է, որպեսզի կարողանաք տեսնել, թե որտեղ է կենտրոնացած
> ձեր օգտագործումը և որքան եք խնայում՝ հարցումներն ավելի էժան/անվճար մատակարարներին ուղղորդելով։

Այս մեկնաբանությունն ուղղակիորեն նշված է նախագծի [README](../../README.md)-ում («վահանակի
«ծախսը» խնայողությունների հաշվիչ է, այլ ոչ թե հաշիվ»)։

Քանի որ այդ թիվը գնահատական է՝

- Այն կախված է յուրաքանչյուր մոդելի համար OmniRoute-ի ունեցած գնային աղյուսակից։ Գնային
  գրառում չունեցող մոդելը ծախսին ավելացնում է `0` (դիտարկիչում այն ցուցադրվում է որպես
  «Հնացած / Անվճար» տող)։
- Անվճար մակարդակների և բաժանորդագրությունների տրաֆիկի համար նույնպես կուտակվում է
  _գնահատված_ ծախս. դա ձեր խնայած գումարն է, ոչ թե վճարման ենթակա գումար։

## Ինչպես են գնահատվում ծախսերը

### Գնային աղբյուրը

Ծախսերը գալիս են [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) ում միավորված գնագոյացման աղյուսակից՝ այս գերակայության կարգով (** ամենաբարձրը առաջինը** ):

1. **Օգտատիրոջ անտեսում** — գները սահմանված են վահանակում կամ `PATCH /api/pricing` միջոցով ( `pricing` անվանատարածք):
2. **models.dev համաժամեցում** — գները վերցված են `https://models.dev/api.json` ից ( `models_dev_pricing` անվանումների տարածությունից):
3. **LiteLLM համաժամեցում** — գները բերված են LiteLLM ի հանրային `model_prices_and_context_window.json` ից ( `pricing_synced` անվանումների տարածությունից):
4. **Կոշտ կոդավորված կանխադրվածներ** — գները առաքվում են [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) ով:

Նույն provider/model համար ավելի բարձր առաջնահերթ շերտերի արժեքները վերագրանցում են համապատասխան դաշտերը ստորին շերտերում. վերին շերտից բացակայող դաշտերը դեռ կարող են առաջանալ ստորին շերտից: Պատվերը ամրագրված է նույնիսկ այն դեպքում, երբ երկու անկախ համաժամացման աշխատանքները միաժամանակ աշխատում են: `GET /api/pricing?includeSources=1` վերադարձնում է `pricing` և `sourceMap`, որոնց յուրաքանչյուր մոդելի պիտակները (`user`, `modelsDev`, `litellm`, `default`) նույնացնում են այդ մոդելը պարունակող ամենաառաջնահերթ շերտը:

**LiteLLM համաժամեցում** միացված է, լռելյայն անջատված է: Դրա միջավայրի փոփոխականները (տես [`.env.example`](../../.env.example) ) են.

| Env var                 | Կանխադրված | Նպատակը                                                                                    |
| ----------------------- | ---------- | ------------------------------------------------------------------------------------------ |
| `PRICING_SYNC_ENABLED`  | `false`    | Միացնել ֆոնային LiteLLM գնագոյացման համաժամացումը:                                         |
| `PRICING_SYNC_INTERVAL` | `86400`    | Համաժամեցման միջակայքը վայրկյաններով (օրական):                                             |
| `PRICING_SYNC_SOURCES`  | `litellm`  | Աղբյուրի ընտրություն միայն այս համաժամացման համար. ներկայումս միայն `litellm` է աջակցվում: |

**models.dev համաժամեցում** առանձին է LiteLLM sync-ից և նաև անջատված է լռելյայնորեն: Միացրեք այն Կարգավորումներում (models.dev sync) կամ օգտագործեք այս փոփոխականները.

| Env var                    | Կանխադրված     | Նպատակը                                                                                                                                                            |
| -------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `MODELS_DEV_SYNC_ENABLED`  | _(չսահմանված)_ | Unset-ը հետևում է Կարգավորումների փոխարկիչին; `1/true/on/yes` ստիպում է միացնել, իսկ `0/false/off/no` անջատում է (նույնիսկ եթե կարգավորումները թույլ են տալիս դա): |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`        | Կանխադրված models.dev համաժամացման միջակայքը վայրկյաններով (օրական):                                                                                               |

`PRICING_SYNC_SOURCES` անում** ոչ** միացնել models.dev; այն վերահսկում է միայն LiteLLM համաժամացումը: Օգտագործողի վերագրանցումը ջնջելը չի ջնջում համաժամեցված անվանատարածքը. հաջորդ հասանելի գնային շերտը դառնում է արդյունավետ: Անգին մոդելի համար ստուգեք և՛ համաժամացման կարգավորումները, և՛ `sourceMap` ՝ նախքան ձեռքով փոխարինում ավելացնելը:

### Արժեքի բանաձևը

Արժեքը հաշվարկվում է մեկ հարցման միջոցով՝ խորհրդանիշների հաշվարկից և մեկ միլիոն նշանի դրույքաչափերից [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) ում (`computeCostFromPricing` / `calculateCost`):

- **Մուտքագրեք նշաններ** (մինուս քեշի ընթերցումները և քեշի ստեղծման նշանները) × `input` տոկոսադրույքը:
- **Քեշի ընթերցման նշաններ** × `cached` տոկոսադրույքը (հետ է ընկնում մուտքային արագությանը):
- **Քեշի ստեղծման նշաններ** × `cache_creation` տոկոսադրույքը (հետ է ընկնում մուտքային արագությանը):
- **Ելքային նշաններ** × `output` տոկոսադրույքը.
- **Պատճառաբանության նշաններ** × `reasoning` տոկոսադրույքը (հետ է ընկնում ելքային արագությանը):

Բոլոր դրույքաչափերը մեկնաբանվում են որպես USD 1,000,000 նշանի համար: Codex «արագ»/«առաջնահերթ» կամ «flex» ծառայության մակարդակը կիրառում է ծախսերի բազմապատկիչ (`getCodexFastCostMultiplier`) — օրինակ՝ flex-ը գանձվում է 50% խորհրդանշական զեղչով, որը երևում է որպես** flex խնայողություններ** վահանակում:

Մոդելների անունները սկզբում նորմալացվում են (մատակարարի ուղու նախածանցները, ինչպիսիք են `openai/` կամ `accounts/fireworks/models/`, հանվում են), ուստի պատմական տողերը դեռ համընկնում են գնի հետ:

### Ինչպես է գրանցվում ծախսերը

- Մեկ հարցման արժեքը հաշվարկվում է հարցման ավարտից հետո: Համատեղ քվոտայի սպառումը պլանավորվում է հաջորդ իրադարձության հանգույցով [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) միջոցով:
- API-բանալու ծախսը բուֆերացված և խմբաքանակով մաքրվում է [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) ի կողմից (60-ականների լռելյայն ինտերվալ, 1000 մուտքի բուֆեր): Կարգավորելի միջոցով՝

  | Env var                             | Կանխադրված | Նպատակը                                           |
  | ----------------------------------- | ---------- | ------------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`    | Լվացման միջակայքը միլիվայրկյաններով:              |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`     | Մաքսիմալ բուֆերացված գրառումները նախքան լվացումը: |

Ծախսերը նախընտրում են ճշգրիտ մատակարարի կողմից զեկուցված վճար (`provider_cost_usd`), այնուհետև կատալոգի գնով հարցման նկարը (`calculated_cost_usd`), այնուհետև ընթացիկ կատալոգից տոկենային վերագնահատում: Պահպանված ծախսերը կրկին չեն գանձվում իրենց նշանների հաշվումներով: Միայն ժառանգական նշաններով տողերը դեռ փոխվում են, երբ դրանց կատալոգի գինը փոխվում է:

### OCR եւ embeddings

- `/v1/ocr` հաջող հարցումները օգտագործում են `usage_info.pages_processed` վերին հոսանքը, այլ ոչ թե պահանջվող էջի տիրույթը կամ վերադարձված էջի օբյեկտների քանակը: Գնահատումը կազմում է էջեր × `ocr_cost_per_page` (բացարձակ USD/page,** ոչ** USD/million):
- Փաստաթղթերի կամ սահմանային տուփի ծանոթագրություններով հարցումները պահանջում են առանձին `ocr_cost_per_annotated_page` սակագին: Առանց դրա արժեքը մնում է անհայտ. սովորական OCR սակագինը լուռ չի փոխարինվում.
- LiteLLM sync-ը քարտեզագրում է իր վերին հոսանքում `annotation_cost_per_page` դաշտը `ocr_cost_per_annotated_page` մեջ՝ պահպանելով USD/page բացարձակ արժեքը և միայն ծանոթագրության գրառումները, ներառյալ բացահայտ զրո: Առաջնահերթություն է տրվում մատակարարված կանոնական դաշտը. կեղծանունների արժեքներն անտեսվում են: Օգտատիրոջ գնագոյացման գերակայությունները պահպանում են իրենց սովորական առաջնահերթությունը: Տես [LiteLLM ի OCR գնագոյացման բանալիները](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) :
- OCR օգտագործումը պահպանում է էջի քանակը, միավորի գինը, հաշվարկված USD արժեքը, API բանալին և ընտրված կապը: Էջերը երբեք չեն ներկայացվում որպես նշաններ: Զանգերի մատյանները պարունակում են վճարման մետատվյալներ, այլ ոչ թե URLs փաստաթղթի, PDF բայթ կամ արդյունահանված տեքստ:
- `/v1/embeddings` հաջող հարցումները գրանցում են օգտագործման մեկ տող յուրաքանչյուր ֆիզիկական խմբաքանակի համար, ներառյալ առանձին խմբաքանակները, որոնք ավարտվել են նույն միլիվայրկյանում: Մատակարարի կողմից ներկայացված վճարները գերակայում են խորհրդանշական գնահատականներից. համակցված փաթաթանները լիցք չեն ավելացնում:
- Օգտագործման պատմությունը, Ծախսերի վերլուծությունը, provider/account պատուհանները, API-բանալինների ծախսերի սահմանաչափերը, հարցում-ծախսերի գրանցամատյանը և ամենօրյա օգտագործման ցուցակները ներառում են այս վճարները: No-log ստեղները պահպանում են թվային հաշվառում՝ առանց սկզբնական տեքստի պահպանման:
- Օգտագործումը կամ սակագները բացակայում են** անհայտ** , ոչ անվճար. պատասխան-արժեքի վերնագիրը բաց է թողնված, և գոյություն ունեցող ոչ գնային օգտագործման քաղաքականությունը վերաբերում է սահմանափակ API ստեղներին: Հստակորեն կազմաձևված զրոյական դրույքաչափերը մնում են վավեր զրոյական ծախսերի օգտագործման համար:

Սա միայն առաջնային հաշվառում է: Հին OCR/embedding զանգերը, որոնք երբեք չեն գրել օգտագործման պատմություն, չեն կարող վերակառուցվել այս միգրացիայից: Կատալոգի գնահատականները USD գնահատումներ են, ոչ թե հաշիվ-ապրանքագիր և չեն ներառում արժույթի փոխարկումը, հարկերը կամ զեղչերը:

### Խոսք և պատկերներ

- `/v1/audio/transcriptions`, `/v1/audio/speech` և պատկերի ստեղծման հաջող փորձերը կիսում են թվային հաշվառումը: Ուղղակի և համակցված զանգերը կրում են զանգահարողի API ստեղնը և ընտրված կապը; համակցված փաթաթան երբեք երկրորդ դեբետ չի ավելացնում:
- Մատակարարի կողմից զեկուցված USD հաղթում է կատալոգի գնահատականին, ներառյալ բացահայտ զրոյական վճարը: OpenRouter ի JSON `usage.cost` նորմալացվում է `cost_usd`: Հակառակ դեպքում, չափված թոքեններն օգտագործում են նշանների գները, տառադարձման վայրկյանները՝ մեկ վայրկյանի համար, խոսքի մուտքագրումը օգտագործում է Յունիկոդի նիշերի հաշվարկը, իսկ համարժեք պատկերներում օգտագործվում է փաստացի վերադարձված թիվը, այլ ոչ թե պահանջվող `n`:
- Երկուական OpenRouter TTS չունի JSON օգտագործման մարմին: Այն բանից հետո, երբ աուդիոն ավարտվի կամ զանգահարողը չեղարկի, OmniRoute հարցումներ է կատարում իր սերնդի ID ի վրա** նույնը** կազմաձևված OpenRouter ծագում: EU հարցումը երբեք չի վերադառնում համաշխարհային ծագմանը: Սա սահմանափակված, միայն կարդալու որոնում է. սինթեզը չի կրկնվում հաշվապահական հաշվառման համար: Վճարման գրառումները կարող են հայտնվել աուդիո ձայնագրության ավարտից հետո. որոնումների կրկնվող փորձերն աշխատում են հետին պլանում մինչև մոտ 52 վայրկյան, ներառյալ ցանցի վերջնաժամկետները:
- Այդ որոնման ընթացքում աուդիո պատասխանն ունի `X-OmniRoute-Cost-Status: pending` և պատասխան-արժեքի վերնագիր: Դրա վերջնական լիցքը հայտնվում է օգտագործման պատմության, վերլուծության և հիմնական մատյանում հաշտեցումից հետո: Եթե մետատվյալներն անհասանելի են, ապա օգտագործվում է կարգավորված սակագնի պատկերը. հակառակ դեպքում արժեքը մնում է անհայտ:
- Վայրկյանները, նիշերը և պատկերների քանակը ունեն առանձին հաշվարկային միավորի դաշտեր, երբեք կեղծ նշանների հաշվարկներ: Հաշվապահական հաշվառումը պահպանում է միայն թվային օգտագործումը, ոչ թե խոսքի տեքստը, տառադարձումները կամ պատկերի բայթերը: Գոյություն ունեցող ոչ գնային պատկերների բացառությունները անփոփոխ են. իրականում բացակայող պատկերի սակագինը չի կողպում սահմանափակ բանալին, և պատասխանը բաց է թողնում ծախսերի վերնագիրը, այլ ոչ թե զանգը հայտարարում է անվճար: Գնագոյացման խանութի ձախողումը դեռևս պահպանում է օգտագործման ապացույցները ձախողման պատճառով փակված կիրառման համար:

Ոչ մի պատմական speech/image լիցք չի հորինվում կամ լրացվում: Մատակարարի հաշվարկը մնում է հղում ապրանքագրերի և զանգերի համար, որոնց վճարը չի հաղորդվել:

## Վահանակ․ Ծախսերի էջը

**Ծախսեր** էջը գտնվում է `/dashboard/costs`
հասցեում (`src/app/(dashboard)/dashboard/costs/`)։
Դրա հիմնական տեսքը **Ծախսերի ակնարկ** ներդիրն է
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
որն ամբողջ տվյալները բեռնում է `GET /api/usage/analytics`-ից։

Ինչ է այն ցուցադրում․

- **Ծախսերի սալիկներ** — գնահատված ծախսը՝ _Այսօր (1d)_, _7d_, _30d_ և ընտրված
  ժամանակահատվածի համար։ Միջակայքի ընտրիչ՝ `7d`, `30d`, `90d`, `all`։
- **Հիմնական չափանիշներ** — ժամանակահատվածում կատարված հարցումներ, ակտիվ մատակարարներ, ակտիվ մոդելներ,
  մեկ հարցման միջին արժեք։
- **Ծախսերի հետազոտիչ** — տեսակավորվող/զտվող աղյուսակ՝ խմբավորված ըստ **մատակարարի**, **մոդելի**,
  **API բանալու**, **հաշվի** կամ **սպասարկման մակարդակի**, որը ներառում է արժեքը, հարցումները, թոքենները, մեկ հարցման
  միջին արժեքը և ընդհանուրի մեջ մասնաբաժինը՝ %-ով։
- **Թոքենների օգտագործում** — ընդհանուր / մուտքային / ելքային թոքեններ և մուտքային:ելքային հարաբերակցություն։
- **Երթուղավորման արդյունավետություն** — պահուստային անցումների քանակ, պահուստային անցումների հաճախականություն և հարցված մոդելի ծածկույթ։
- **Ամսական կանխատեսում** — կանխատեսում է ամսվա վերջի ծախսը՝ հիմնվելով վերջին օրերի միջին օրական ծախսի վրա։
- **Ժամանակահատվածների համեմատություն** — պատուհանի առաջին և երկրորդ կեսերի միջև %-ային փոփոխությունը։
- **Գծապատկերներ** — ծախսերի օրական միտում, մատակարարների մասնաբաժին (շրջանաձև), առաջատար մատակարարներ, առաջատար մոդելներ, ծախսեր
  ըստ API բանալու, ծախսեր ըստ հաշվի, օգտագործման շաբաթական օրինաչափություն և ակտիվության ջերմային քարտեզ։
- **Արտահանում** — ներբեռնեք ընթացիկ ժամանակահատվածի տվյալները **CSV** կամ **JSON** ձևաչափով (կոճակները հայտնվում են,
  երբ առկա են զրոյից մեծ ծախսային տվյալներ)։

Երբ գնանշված տրաֆիկ չկա, տողերում `$0`-ի փոխարեն ցուցադրվում է «Ժառանգական / Անվճար» պիտակը՝
արտացոլելով խնայողությունների հետագծման մոդելը։

### Ծախսերին առնչվող ենթաէջեր

Ծախսերի բաժինը նաև ներառում է (բոլորը՝ `/dashboard/costs/`-ի ներքո)․

- **Գնագոյացում** (`/dashboard/costs/pricing`) — դիտեք և վերասահմանեք յուրաքանչյուր մոդելի գները (ցուցադրում է
  ընդհանուր Գնագոյացման ներդիրը)։
- **Բյուջե** (`/dashboard/costs/budget`) — սահմանեք ծախսերի սահմանաչափեր յուրաքանչյուր շրջանակի համար (ցուցադրում է ընդհանուր
  Բյուջեի ներդիրը)։
- **Քվոտայի համօգտագործում** (`/dashboard/costs/quota-share`) — ընդհանուր քվոտաների ֆոնդեր և սպառման արագության
  դիտումներ։

## API վերջնակետեր

Այս բոլորը պահանջում են կառավարման auth (loopback/JWT, via `requireManagementAuth`), եթե նշված չէ:

### Օգտագործման և ծախսերի վերլուծություն

| Մեթոդ | Վերջնակետ                | Նպատակը                                                                                                                                                                   |
| ----- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | Ամբողջական cost/usage վերլուծություն՝ ամփոփում, օրական միտում, ըստ provider/model/API key/account/tier. Հարցում՝ `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`: |
| `GET` | `/api/usage/utilization` | Մեկ մատակարարի քվոտայի օգտագործումը ժամանակի ընթացքում: Հարցում՝ `range` (`1h`/`24h`/`7d`/`30d`), `provider`                                                              |
| `GET` | `/api/usage/history`     | Հում օգտագործման պատմության տողեր:                                                                                                                                        |
| `GET` | `/api/usage/call-logs`   | Մեկ պահանջով զանգերի մատյաններ (մոդել, նշաններ, արժեք, հետաձգում, կարգավիճակ):                                                                                            |
| `GET` | `/api/usage/quota`       | Մատակարարի քվոտայի կարգավիճակը:                                                                                                                                           |
| `GET` | `/api/usage/proxy-logs`  | Վստահված անձի հարցումների տեղեկամատյաններ:                                                                                                                                |

### Բյուջեներ

| Մեթոդ  | Վերջնակետ                | Նպատակը                                                                                              |
| ------ | ------------------------ | ---------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | Արժեքի ամփոփագիր + բյուջեի ստուգում մեկ API ստեղնի համար (պահանջվում է `apiKeyId` հարցման պարամետր): |
| `POST` | `/api/usage/budget`      | Սահմանեք daily/weekly/monthly USD սահմանափակում + նախազգուշացման շեմը API ստեղնի համար:              |
| `GET`  | `/api/usage/budget/bulk` | Բյուջեի զանգվածային ամփոփագրեր API ստեղների վրա:                                                     |

> Բյուջեի API նախատեսված է ըստ**API բանալի** (`apiKeyId`). `GET /api/usage/budget` կողմից վերադարձված սահմանաչափերը ներառում են `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`, a `warningThreshold` և ընթացիկ ընդհանուր գումարները (`totalCostToday`, `totalCostMonth`, …):

### Գնագոյացում

| Մեթոդ    | Վերջնակետ               | Նպատակը                                                                                                                                                                               |
| -------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | Միաձուլված չորս շերտի գնագոյացում (user, models.dev, LiteLLM, լռելյայն): `?includeSources=1` վերադարձնում `pricing` + `sourceMap`.                                                    |

| `GET`    | `/api/pricing/defaults` | Ցույց տալ կանխադրված per-1M հետադարձ տոկոսադրույքները:                                                                                                                                |
| `GET`    | `/api/pricing/models`   | Գինը՝ ըստ մոդելի:                                                                                                                                                                     |
| `POST`   | `/api/pricing/sync`     | Գործարկեք ձեռքով համաժամեցում արտաքին աղբյուրներից (LiteLLM):                                                                                                                         |
| `GET`    | `/api/pricing/sync`     | Ընթացիկ համաժամացման կարգավիճակը:                                                                                                                                                     |
| `DELETE` | `/api/pricing/sync`     | Մաքրել միայն LiteLLM-ով համաժամացված գները (`pricing_synced`); models.dev տվյալները առանձին են:                                                                                       |

### Ծախսերի հետ կապված այլ վերջնակետեր

## CLI

OmniRoute-ի CLI-ն տրամադրում է ծախսերի, օգտագործման և գնագոյացման հրամաններ (գրանցված են
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)-ում)։

### `omniroute cost`

Ծախսերի հաշվետվություն՝ համախմբված `/api/usage/analytics`-ից։

```bash
omniroute cost                          # վերջին 30 օրը՝ խմբավորված ըստ մատակարարի
omniroute cost --period 7d              # վերջին 7 օրը
omniroute cost --group-by model         # խմբավորել ըստ provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

Սյունակներ՝ խումբ, հարցումներ, մուտքային/ելքային թոքեններ, ծախս (USD) և ընդհանուրի տոկոսը։ Վերջում
արտածվում է հանրագումարի տողը (չի ցուցադրվում `--quiet` կամ `--output json` տարբերակների դեպքում)։

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ծախսերի ամփոփում՝ ըստ մատակարարի
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# Բյուջեներ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`-ը կարդում է `GET /api/pricing/defaults`-ը։ Փոխարենը առանձին մոդելների
> գները խմբագրելու համար օգտագործեք կառավարման վահանակի **Գնագոյացում** էջը կամ `PATCH /api/pricing`։

## Խնդիրների լուծում

- **Բոլոր ծախսերը ցուցադրվում են որպես $0 / «Ժառանգական / Անվճար»։** Օգտագործվող մոդելների համար գնագոյացման գրառում չկա։
  Միացրեք արտաքին համաժամացումը (`PRICING_SYNC_ENABLED=true`) և գործարկեք `omniroute pricing sync`, կամ
  գները ձեռքով սահմանեք Գնագոյացման էջի / `PATCH /api/pricing`-ի միջոցով։
- **Պատմական մոդելի գինը սխալ է հաշվարկված։** Ուղղեք գինը (վերագրեք կամ կրկին համաժամացրեք). ծախսը
  վերլուծական տվյալների յուրաքանչյուր ընթերցման ժամանակ վերահաշվարկվում է թոքենների քանակից, ուստի գնահատականները հետադարձ ուժով թարմացվում են։
- **Ծախսերի տվյալները հետ են մնում իրական ժամանակից։** Ըստ բանալու ծախսերը մշակվում են փաթեթներով. նվազեցրեք
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS`-ը, եթե ավելի թարմ տվյալներ են անհրաժեշտ։
