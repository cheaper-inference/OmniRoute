## 🎯 Օգտագործման դեպքեր

### Դեպք 1. «Ես ունեմ Claude Pro-ի բաժանորդագրություն»

**Խնդիր.** Քվոտայի ժամկետն ավարտվում է առանց այն օգտագործելու, իսկ ինտենսիվ ծրագրավորման ժամանակ գործում են հաճախականության սահմանափակումներ

```
Համակցություն՝ "maximize-claude"
  1. cc/claude-opus-4-7        (լիովին օգտագործել բաժանորդագրությունը)
  2. glm/glm-4.7               (էժան պահուստային տարբերակ՝ քվոտան սպառվելու դեպքում)
  3. if/qwen3.8-max-preview       (անվճար արտակարգ պահուստային տարբերակ)

Ամսական ծախս՝ $20 (բաժանորդագրություն) + ~$5 (պահուստային տարբերակ) = ընդհանուր՝ $25
$20 վճարելու և սահմանափակումներին բախվելու փոխարեն՝ առանց հիասթափության
```

### Դեպք 2. «Ես ուզում եմ զրոյական ծախս»

**Խնդիր.** Չեմ կարող ինձ թույլ տալ բաժանորդագրություններ, անհրաժեշտ է հուսալի AI ծրագրավորման համար

```
Համակցություն՝ "zero-cost"
  1. if/kimi-k2.7-code          (նշված է որպես անվճար հասանելիություն. կարող են գործել հաճախականության սահմանափակումներ)
  2. kr/qwen3-coder-next        (Kiro-ի անվճար պահուստային տարբերակ)

Ամսական ծախս՝ $0
Որակ՝ ձեր աշխատանքային ծանրաբեռնվածության համար ստուգեք մոդելը, սահմանափակումները, գաղտնիությունը և SLA-ն
```

### Դեպք 3. «Ինձ անհրաժեշտ է շուրջօրյա ծրագրավորում՝ առանց ընդհատումների»

**Խնդիր.** Սեղմ ժամկետներ են, չեմ կարող ինձ թույլ տալ պարապուրդ

```
Համակցություն՝ "always-on"
  1. cc/claude-opus-4-7        (լավագույն որակ)
  2. cx/gpt-5.5                (երկրորդ բաժանորդագրություն)
  3. glm/glm-4.7               (էժան, վերականգնվում է ամեն օր)
  4. minimax/MiniMax-M2.1      (ամենաէժանը, վերականգնում՝ 5 ժ)
  5. if/deepseek-v4-flash       (նշված է որպես անվճար հասանելիություն. կարող են գործել հաճախականության սահմանափակումներ)

Արդյունք՝ պահուստային անցման 5 մակարդակն ընդլայնում է կայունությունը. արտաքին ծառայությունների հասանելիությունը երաշխավորված չէ
```

- Փոխել ավտոմատ գործարկման կարգավորումը։
- Կանգնեցնել OmniRoute-ը։

Մի՛ համակցեք `--tray`-ը հետևյալ ընտրանքների հետ․

- `--daemon`
- `--log`
- `--no-recovery`

Այս ռեժիմները պահանջում են գործընթացների կառավարման տարբեր եղանակներ։

Միացրեք գործարկումը համակարգ հաջորդ մուտք գործելիս․

```bash
omniroute autostart enable
```

Ավտոմատ գործարկումն օգտագործում է համակարգային դարակի ռեժիմը macOS-ում, Windows-ում և գրաֆիկական Linux աշխատաշրջաններում։ Առանց գրաֆիկական միջավայրի Linux-ն օգտագործում է գոյություն ունեցող systemd օգտատիրոջ ծառայությունը։

Անջատեք մուտք գործելիս ավտոմատ գործարկումը․

```bash
omniroute autostart disable
```

### Ապատեղադրում

Երբ OmniRoute-ն այլևս անհրաժեշտ չէ, մաքուր հեռացման համար տրամադրում ենք երկու արագ սկրիպտ․

| Հրաման                   | Գործողություն                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------ |
| `npm run uninstall`      | Հեռացնում է համակարգային հավելվածը, բայց **պահպանում է ձեր ՏԲ-ն և կազմաձևումները** `~/.omniroute`-ում։ |
| `npm run uninstall:full` | Հեռացնում է հավելվածը ԵՎ ընդմիշտ **ջնջում է բոլոր կազմաձևումները, բանալիներն ու տվյալների բազաները**։  |

> Նշում․ այս հրամանները գործարկելու համար անցեք OmniRoute նախագծի պանակ (եթե կլոնավորել եք այն) և գործարկեք դրանք։ Որպես այլընտրանք, եթե այն տեղադրված է գլոբալ կերպով, կարող եք պարզապես գործարկել `npm uninstall -g omniroute`։

### Void Linux (xbps-src)

Void Linux-ի օգտատերերը կարող են փաթեթավորել և տեղադրել OmniRoute-ը բնիկ եղանակով՝ օգտագործելով `xbps-src` խաչաձև կոմպիլյացիայի շրջանակը։ Այն ավտոմատացնում է Node.js-ի ինքնուրույն հավաքումը՝ անհրաժեշտ `better-sqlite3` բնիկ կապակցումների հետ միասին։

```bash
pkgname=omniroute

system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false

	# Որոշել node-gyp-ի նպատակային պրոցեսորի ճարտարապետությունը
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) Տեղադրել բոլոր կախվածությունները՝ բաց թողնելով սկրիպտները
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Հավաքել Next.js-ի ինքնուրույն փաթեթը
	npm run build

	# 3) Պատճենել ստատիկ ռեսուրսներն ինքնուրույն փաթեթի մեջ
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) Հեռացնել ճարտարապետությանը հատուկ sharp փաթեթները
	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# Կանխել Next.js հավելվածի երթուղիչի դատարկ պանակների հեռացումը հետտեղադրման մշակիչի կողմից

export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"

exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

## 🧩 Ընդլայնված հնարավորություններ

### Պատվերով մոդելներ

Ավելացրեք ցանկացած մոդելի ID ցանկացած մատակարարի համար՝ առանց հավելվածի թարմացում սպասելու.

```bash
# API-ի միջոցով
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# Ցուցակը. curl http://localhost:20128/api/provider-models?provider=openai
# Հեռացնելը. curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

Կամ օգտագործեք Dashboard-ը. **Մատակարարներ → [Մատակարար] → Պատվերով մոդելներ**։

Նշումներ.

- OpenRouter-ը և OpenAI/Anthropic-համատեղելի մատակարարները կառավարվում են միայն **Հասանելի մոդելներ** բաժնից։ Ձեռքով ավելացումը, ներմուծումը և ավտոմատ համաժամացումը բոլորը հայտնվում են նույն հասանելի մոդելների ցանկում, ուստի այդ մատակարարների համար առանձին «Պատվերով մոդելներ» բաժին չկա։
- **Պատվերով մոդելներ** բաժինը նախատեսված է այն մատակարարների համար, որոնք չեն ապահովում կառավարվող հասանելի մոդելների ներմուծում։

### Պատվերով OpenAI-համատեղելի մատակարարներ

Ցանկացած գեյթվեյ, որն աշխատում է OpenAI API-ով (ինքնահոստինգ պրոքսի, vLLM, երրորդ կողմի ագրեգատոր),
կարող է ավելացվել որպես առանձին մատակարարի հանգույց.

1. **Մատակարարներ → Ավելացնել OpenAI-համատեղելի**։
2. **Անուն**. հանգույցի ցուցադրվող պիտակը։
3. **Նախածանց**. երթուղավորման անունը։ Հաճախորդները մոդելներին դիմում են որպես `<prefix>/<model>`, ուստի
   `mygw` նախածանցով հանգույցը սպասարկում է `mygw/gpt-4o-mini`-ն։ Պարտադիր է. նիշերի սահմանափակում չկա։
4. **API-ի տեսակ**. endpoint-ների ընտանիքը, որը սպասարկում է գեյթվեյը (Chat Completions, Responses,
   Embeddings, աուդիո, պատկերներ)։
5. **Բազային URL**. API-ի արմատը՝ մինչև և ներառյալ `/v1` (օրինակ՝
   `https://gateway.example.com/v1`), ոչ թե ամբողջական `/chat/completions` ուղին։ Ոչ ստանդարտ
   ուղիներով գեյթվեյները դրանք սահմանում են **Ընդլայնված կարգավորումներ** բաժնում (chat path, models path)։
6. **API բանալի (ստուգման համար)** դաշտը միայն ստուգում է կապը։ Հանգույցը ստեղծելուց հետո
   բացեք այն և օգտագործեք **Ավելացնել կապ**՝ հարցումներում օգտագործվելիք բանալին պահպանելու համար։

Հանգույցը ստանում է `openai-compatible-<apiType>-<uuid>` ձևի ներքին id. այն երբեք հարկավոր չէ
մուտքագրել, նախածանցն է հրապարակային անունը։

#### Պահված նախածանցներ

Նախածանցը չի կարող լինել ներկառուցված մատակարարի id կամ այլանուն (օրինակ՝ `openai`, `cf`), ինչպես նաև
հանված մատակարարի id։ Մոդելի լուծիչը նախքան պատվերով հանգույցները ստուգում է ներկառուցված id-ներն ու
այլանունները, ուստի այդ նախածանցներից մեկն օգտագործող հանգույցը երբեք տրաֆիկ չէր ստանա.
`<prefix>/model`-ը կուղղվեր ներկառուցված մատակարարին, կամ կձախողեր փակ ռեժիմով (fail closed), եթե այդ
մատակարարը հանված լիներ։ Նման նախածանցով հանգույց ստեղծելը կամ խմբագրելը մերժվում է հետևյալ սխալով.

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

Ընտրեք չկրկնվող նախածանց (`mygw`, `acme-proxy`)։ Եթե պատվերով հանգույցին ուղղված հարցումները ձախողվում են
սխալով, որը հիշատակում է ներկառուցված մատակարար կամ նրա հավատարմագրերը, ստուգեք՝ արդյոք հանգույցի նախածանցը
պահված չէ. մինչ այս կանոնի առաջացումը պահպանված հանգույցները դեռ գոյություն ունեն, բայց դրանց նախածանցը
երթուղավորվում է դեպի ներկառուցված մատակարարը։ Խմբագրեք հանգույցը և տվեք նրան նոր նախածանց։

#### Յուրաքանչյուր կապի գեյթվեյի ընտրանքներ

Այս բանալիները տեղադրվում են կապի `providerSpecificData`-ում (օրինակ՝
`PUT /api/providers/{id}`-ի միջոցով).

- `toolNameMaxLength` (ամբողջ թիվ, 1–1024) — OpenAI chat-ձևաչափի համատեղելի կապերի համար, որոնց
  գեյթվեյը մերժում է գործիքների երկար անունները։ Ավելի երկար անուններն ուղարկվում են որպես կարճ
  այլանուններ և վերականգնվում են պատասխանում։
- `quotaEndpoint` — գեյթվեյի քվոտայի/կրեդիտների endpoint-ը, որը կարդացվում է վահանակի քվոտայի տողի և
  քվոտային հաշվառումով երթուղավորման համար։ Աշխատում է և՛ OpenAI-, և՛ Anthropic-համատեղելի կապերի վրա.
  ամբողջական ձևը նկարագրված է `open-sse/services/usage/openaiCompatible.ts`-ում։

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### OmniRoute peer-ների շղթայավորում

Մեկ այլ OmniRoute գեյթվեյ կարելի է ավելացնել որպես **Պատվերով OpenAI-համատեղելի** մատակարար։ Օգտագործեք
peer-ի `/v1` բազային URL-ը և այդ peer-ի կողմից տրված հատուկ, նվազագույն արտոնություններով API բանալի։

Փոխադարձ կամ բազմացայլ (multi-hop) շղթաների համար միացրեք ցիկլի պաշտպանության opt-in մեխանիզմը յուրաքանչյուր
գեյթվեյի վրա.

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

Միայն հստակ թույլատրված ցանկում (allowlist) նշված peer URL-ին ուղարկված հարցումներն են ստանում
`X-OmniRoute-Peer-Trace` վերնագիրը։ Գեյթվեյը կրկնված instance ID-ն կամ սպառված hop-ների բյուջեն մերժում է
HTTP `508 Loop Detected` սխալով. սովորական upstream մատակարարները peer-ի մետատվյալներ չեն ստանում։

Peer-ների շղթայավորումը տվյալների բազայի ռեպլիկացիա կամ հոստի failover չէ։ Յուրաքանչյուր գեյթվեյ պահպանում է
անկախ SQLite վիճակ, քեշեր, rate-ի հաշվիչներ և սեսիաներ։ Active/passive կամ active/active հասանելիության
համար օգտագործեք առողջության ստուգումներով reverse proxy կամ client failover և երբեք մի կցեք (mount) մեկ
SQLite տվյալների բազա միաժամանակ աշխատող մի քանի OmniRoute օրինակների։

### Մատակարարին հատուկ երթուղիներ

Երթուղավորեք հարցումները ուղղակիորեն որոշակի մատակարարի՝ մոդելի վավերացմամբ.

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

Մատակարարի նախածանցն ավտոմատ ավելացվում է, եթե բացակայում է։ Անհամապատասխան մոդելները վերադարձնում են `400`։

### Ցանցային պրոքսիի կարգավորում

```bash
# Սահմանել գլոբալ պրոքսի
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# Մատակարարին հատուկ պրոքսի
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# Ստուգել պրոքսին
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**Առաջնահերթություն.** Բանալի-հատուկ → Combo-հատուկ → Provider-հատուկ → Գլոբալ → Միջավայր։

### Մոդելների կատալոգի API

```bash
curl http://localhost:20128/api/models/catalog
```

Վերադարձնում է մոդելները՝ խմբավորված ըստ provider-ի և տիպերի (`chat`, `embedding`, `image`)։

### Ամպային սինխրոնացում

- Սինխրոնացրեք provider-ները, combo-ները և կարգավորումները սարքերի միջև
- Ավտոմատ ֆոնային սինխրոնացում timeout-ով + fail-fast
- Production-ում նախընտրեք սերվերային `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` փոփոխականները

### Cloudflare Quick Tunnel

- Հասանելի է **Dashboard → Endpoints** բաժնում Docker-ի և այլ self-hosted տեղակայումների համար
- Ստեղծում է ժամանակավոր `https://*.trycloudflare.com` URL, որը վերահասցեավորում է դեպի ձեր ընթացիկ OpenAI-համատեղելի `/v1` endpoint-ը
- Առաջին միացումը տեղադրում է `cloudflared`-ը միայն անհրաժեշտության դեպքում. հաջորդ վերագործարկումները օգտագործում են նույն կառավարվող binary-ն
- Quick Tunnels-ը չի վերականգնվում ավտոմատ կերպով OmniRoute-ի կամ container-ի վերագործարկումից հետո. անհրաժեշտության դեպքում կրկին միացրեք դրանք dashboard-ից
- Tunnel-ի URL-ները ժամանակավոր են և փոխվում են tunnel-ի յուրաքանչյուր դադարեցման/գործարկման ժամանակ
- Կառավարվող Quick Tunnels-ը լռությամբ օգտագործում է HTTP/2 տրանսպորտ՝ սահմանափակված container-ներում QUIC UDP բուֆերի աղմկոտ նախազգուշացումներից խուսափելու համար
- Սահմանեք `CLOUDFLARED_PROTOCOL=quic` կամ `auto`, եթե ցանկանում եք փոխարինել կառավարվող տրանսպորտի ընտրությունը
- Սահմանեք `CLOUDFLARED_BIN`, եթե նախընտրում եք օգտագործել նախապես տեղադրված `cloudflared` binary-ն կառավարվող ներբեռնման փոխարեն
- Cloudflare Quick Tunnel, Tailscale Funnel և ngrok Tunnel վահանակները կարելի է ցույց տալ կամ թաքցնել **Settings → Appearance** բաժնում։ Վահանակի թաքցնումը չի դադարեցնում աշխատող tunnel-ը։

### LLM Gateway-ի խելացի հնարավորություններ (Փուլ 9)

- **Semantic Cache** — Ավտոմատ քեշավորում է non-streaming, temperature=0 պատասխանները (շրջանցեք `X-OmniRoute-No-Cache: true` header-ով)
- **Հարցումների իդեմպոտենտություն** — Ոչ-կրկնակիացնում է հարցումները 5 վայրկյանի ընթացքում `Idempotency-Key` կամ `X-Request-Id` header-ի միջոցով
- **Ընթացքի հետևում** — Opt-in SSE `event: progress` իրադարձություններ `X-OmniRoute-Progress: true` header-ի միջոցով

### Երթուղավորման ռազմավարություններ

Կարգավորեք **Dashboard → Settings → Routing** բաժնի միջոցով։ Dashboard-ը բացում է վեց ամենաշատ օգտագործվող ռազմավարությունները. combo-ները և auto-router-ը ներքուստ աջակցում են ավելի լայն շարք։

**Dashboard-ում տեսանելի ռազմավարություններ (հաշիվ-մակարդակի երթուղավորում).**

| Ռազմավարություն                | Նկարագրություն                                                                                                   |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| **Fill First**                 | Օգտագործում է հաշիվները ըստ առաջնահերթության — հիմնական հաշիվը մշակում է բոլոր հարցումները, մինչև հասանելի չլինի |
| **Round Robin**                | Պտտվում է բոլոր հաշիվների միջով կարգավորելի sticky սահմանով (լռությամբ՝ 3 կանչ մեկ հաշվի համար)                  |
| **P2C (Power of Two Choices)** | Ընտրում է 2 պատահական հաշիվ և երթուղավորում է ավելի առողջին — հավասարակշռում է բեռը՝ հաշվի առնելով առողջությունը |
| **Random**                     | Պատահականորեն ընտրում է հաշիվ յուրաքանչյուր հարցման համար Fisher-Yates shuffle-ի միջոցով                         |
| **Least Used**                 | Երթուղավորում է ամենահին `lastUsedAt` ժամանակագրությամբ հաշվին՝ հավասարաչափ բաշխելով traffic-ը                   |
| **Cost Optimized**             | Երթուղավորում է ամենացածր priority արժեքով հաշվին՝ օպտիմալացնելով ամենաէժան provider-ների համար                  |

**Ընդլայնված combo և auto ռազմավարություններ** (կարգավորվում են ըստ combo-ի կամ `auto/*` նախածանցների միջոցով — տես [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — խիստ հերթականություն, երբեք չի կիրառում round-robin
- `weighted` — համամասնական traffic բաժանում ըստ մեկ մոդելի կշիռների
- `fill-first` — սպառում է առաջին մոդելը մինչև սահմանաչափերը լրանան
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` և `cost-optimized`
- `auto` — միավոր-կենտրոնացված բոլոր թեկնածուների վրայով
- `lkgp` (Last Known Good Provider) — ամրակապում է վերջին հաջող provider-ին, ապա վերադառնում կանոններին
- `context-optimized` — ընտրում է ամենամեծ ազատ context պատուհանով մոդելը
- `context-relay` — շղթայնում է երկար context-ով մոդելները հետևյալ հերթերի համար

#### Արտաքին Sticky Session Header

Արտաքին session affinity-ի համար (օրինակ՝ reverse proxy-ների հետևում գտնվող Claude Code/Codex agents), ուղարկեք․

```http
X-Session-Id: your-session-key
```

OmniRoute-ը նաև ընդունում է `x_session_id` և վերադարձնում արդյունավետ session բանալին `X-OmniRoute-Session-Id`-ում։

Եթե օգտագործում եք Nginx և ուղարկում եք underscore-ով header-ներ, միացրեք․

```nginx
underscores_in_headers on;
```

#### Wildcard մոդելի անվանափոխություններ

Ստեղծեք wildcard ձևանմուշներ մոդելների անունները վերաեզրույթագրելու համար․

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

Wildcard-ները աջակցում են `*` (ցանկացած նիշ) և `?` (մեկ նիշ)։

#### Fallback շղթաներ

Սահմանեք գլոբալ fallback շղթաներ, որոնք կիրառվում են բոլոր հարցումների վրա․

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### Provider-ների սովորական համադրություններ և երթուղավորման ձևանմուշներ

Ահա մի քանի provider-ների համադրելու և OmniRoute-ում դրանց միջև երթուղավորման օրինակելի ձևանմուշներ․

#### 1. Կոդավորման գործակալի կոմբո. բարձր մակարդակի դատողություն՝ ծախսերի/արագության պահուստային տարբերակով

Իդեալական է կոդավորման գործակալների (OpenCode, Claude Code, Cursor, Cline) համար։ Սկզբում հղումները ուղղվում են առաջատար դատողության մոդելներին՝ քվոտայի սպարման կամ սխալների դեպքում անցնելով արագ կոդավորման մոդելների։

- **Վահանակ**: Կոմբոներ → Նոր կոմբո → Անուն՝ `agent-coding` → Ռազմավարություն՝ `Priority`
- **Մոդելներ**:
  1. `claude/claude-sonnet-4-6` (Հիմնական կոդավորման գործակալ)
  2. `openai/gpt-4o` (Երկրորդական բարձր հզորությամբ պահուստային)
  3. `deepseek/deepseek-v4-flash` (Բարձր արդյունավետությամբ, ծախսարդյունավետ պահուստային)

```bash
# Օրինակ API-ի միջոցով
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

#### 2. Անվճար մակարդակի ավտոմատ փոխանցման կոմբո

Միավորում է մի քանի անվճար մակարդակի և առանց բանալիի մատակարարներ՝ առանց API ծախսերի առավելագույն աշխատաժամանակ ապահովելու համար։

- **Ռազմավարություն**: `Least Used` կամ `Round Robin` (բաշխում է բեռը քվոտաների միջև)
- **Մոդելներ**:
  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

```bash
# Օրինակ CLI-ի միջոցով
omniroute combo create free-stack \
  --models "groq/llama-3.3-70b-versatile,gemini/gemini-2.5-flash,cerebras/gpt-oss-120b" \
  --strategy round-robin
```

#### 3. Մուլտիմոդալ / տեսողական և տեքստային հոսքագիծ

Մասնագիտացված տեսողական մոդելների զուգավորում արագ տեքստի գեներացիայի հետ՝ պատկերների ըմբռնման և կոդի գեներացիայի աշխատանքային հոսքերի համար։

- **Օրինակելիություն**: `Priority` կոմբո, որը նախ թվարկում է տեսողական հնարավորություններով մոդելները, իսկ վերջում՝ բարձր թողունակությամբ տեքստ/կոդ մոդելը։
- **Մոդելներ**:
  1. `gemini/gemini-2.5-pro` (Ուժեղ պատկերի/մուլտիմոդալ ըմբռնում)
  2. `openai/gpt-4o` (Հավասարակշռված տեսողություն և գործիքների օգտագործում)
  3. `deepseek/deepseek-v4-flash` (Տեքստի/կոդի գեներացիա)

### Կայունություն և շղթայի անջատիչներ

Կազմաձևեք **Վահանակ → Կարգավորումներ → Կայունություն** բաժնում։

OmniRoute-ն իրականացնում է մատակարարի մակարդակի կայունություն հինգ բաղադրիչով.

1. **Հարցումների հերթ և տեմպացում** — Համակարգային մակարդակի հարցումների ձևավորում.
   - **Հարցումներ րոպեում (RPM)** — Առավելագույն հարցումներ րոպեում մեկ հաշվի համար
   - **Նվազագույն ժամանակ հարցումների միջև** — Հարցումների միջև նվազագույն ընդմիջում՝ միլիվայրկյաններով
   - **Միաժամանակյա հարցումների առավելագույն թիվ** — Առավելագույն միաժամանակյա հարցումներ մեկ հաշվի համար

2. **Միացման սառեցում** — Մեկ միացման կազմաձևում ըստ նույնականացման տեսակի՝ կրկնելի սխալներից հետո.
   - **Բազային սառեցում** — Վերին հոսքի կրկնելի սխալների համար լռելյայն սառեցման պատուհան
   - **Օգտագործել վերին հոսքի կրկնման հուշումները** — Հարգում է լիազոր `Retry-After` կամ վերագործարկման հուշումները, երբ դրանք տրամադրված են
   - **Հետաձգման առավելագույն քայլեր** — Կրկնվող սխալների համար էքսպոնենցիալ հետաձգման առավելագույն մակարդակ

3. **Մատակարարի շղթայի անջատիչ** — Հետևում է մատակարարի ծայրից ծայր սխալներին, նշում է մատակարարը որպես վատթարացած կազմաձևված նախազգուշական շեմին և բացում է անջատիչը, երբ հասնում է կազմաձևված սխալի շեմին.
   - **Վատթարացման շեմ** — Մատակարարի հաջորդական սխալներ մինչև `DEGRADED` վիճակի մուտքը
   - **Սխալի շեմ** — Մատակարարի հաջորդական սխալներ մինչև `OPEN` վիճակի մուտքը
   - **Վերագործարկման ժամանակաչափ** — Ժամանակահատված մինչև մատակարարի կրկնակի ստուգումը
   - **CLOSED** (Առողջ) — Հարցումներն անցնում են սովորական կերպով
   - **DEGRADED** — Հարցումները դեռ անցնում են, մինչ բարձրացված սխալները հետևվում են
   - **OPEN** — Մատակարարը ժամանակավորապես արգելափակված է կրկնվող սխալներից հետո
   - **HALF_OPEN** — Ստուգվում է, թե արդյոք մատակարարը վերականգնվել է

   Միացման մակարդակի `429` սահմանափակումները մնում են **Միացման սառեցում** բաժնում և չեն հաշվարկվում մատակարարի անջատիչի համար։

   Մատակարարի անջատիչի գործարկման վիճակը ցույց է տրվում միայն **Վահանակ → Առողջություն** էջում։

4. **Սպասել սառեցմանը** — Եթե բոլոր թեկնածու միացումներն արդեն սառեցման մեջ են, OmniRoute-ը կարող է սպասել ամենավաղ սառեցմանը և ավտոմատ կերպով կրկնել նույն հաճախորդի հարցումը։

5. **Արագության սահմանափակման ավտոհայտնաբերում** — Երբ վերին հոսքի մատակարարները վերադարձնում են հստակ սպասման պատուհաններ, այդ հուշումները գերակշռում են տեղական միացման սառեցումը, երբ կարգավորումը միացված է։

**Պրոֆեսիոնալ խորհուրդ.** Օգտագործեք **Առողջություն** էջը՝ խափանումից հետո գործող մատակարարների անջատիչները ստուգելու և վերագործարկելու համար։ Կայունության էջը փոխում է միայն կազմաձևը։

### Տվյալների բազայի արտահանում / ներմուծում

Կառավարեք տվյալների բազայի պահուստավորման պատճենները **Վահանակ → Կարգավորումներ → Համակարգ և պահեստավորում** բաժնում։

| Գործողություն                 | Նկարագրություն                                                                                                                                                                      |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Արտահանել տվյալների բազան** | Ներբեռնում է ընթացիկ SQLite տվյալների բազան որպես `.sqlite` ֆայլ                                                                                                                    |
| **Արտահանել ամենը (.tar.gz)** | Ներբեռնում է ամբողջական պահուստավորման արխիվ, ներառյալ՝ տվյալների բազան, կարգավորումները, կոմբոները, մատակարարների միացումները (առանց հավատարմագրերի), API բանալիների մետատվյալները |
| **Ներմուծել տվյալների բազա**  | Վերբեռնեք `.sqlite` ֆայլ՝ ընթացիկ տվյալների բազան փոխարինելու համար։ Ներմուծումից առաջ պահուստավորման պատճենն ավտոմատ ստեղծվում է, եթե `DISABLE_SQLITE_AUTO_BACKUP=true` չէ         |

```bash
# API. Տվյալների բազայի արտահանում
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API. Ամենի արտահանում (ամբողջական արխիվ)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API. Տվյալների բազայի ներմուծում
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**Ներմուծման վավերացում.** Ներմուծված ֆայլը ստուգվում է ամբողջականության (SQLite pragma ստուգում), պահանջվող աղյուսակների (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) և չափի (առավելագույնը 100 ՄԲ) առումով։

**Օգտագործման դեպքեր.**

- Փոխանցեք OmniRoute-ը մեքենաների միջև
- Ստեղծեք արտաքին պահուստավորման պատճեններ աղետից վերականգնման համար
- Կիսվեք կազմաձևերով թիմի անդամների հետ (արտահանեք ամենը → կիսվեք արխիվով)

### Կարգավորումների վահանակ

Կարգավորումների էջը կազմակերպված է **7 ներդիրների** մեջ՝ հեշտ նավարկության համար.

| Ներդիր             | Բովանդակություն                                                                                                                                                                   |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Ընդհանուր**      | Համակարգի պահեստավորման գործիքներ, լռելյայն վարքագիծ, Endpoint թունելի տեսանելիություն                                                                                            |
| **Տեսք**           | Թեմայի կառավարումներ (բաց/մուգ/համակարգային), կողային վահանակի տեսանելիություն, Cloudflare/Tailscale/ngrok թունելային քարտերի վահանակի փոխարկիչներ                                |
| **AI**             | Մտածման բյուջե (passthrough / auto-strip / custom / adaptive — տե՛ս [THINKING_BUDGET.md](./THINKING_BUDGET.md)), գլոբալ համակարգային prompt, prompt-ի քեշի վիճակագրություն        |
| **Անվտանգություն** | Մուտքանունի/գաղտնաբառի կարգավորումներ, IP հասանելիության կառավարում, API նույնականացում `/models`-ի համար, մատակարարների արգելափակում, prompt-injection պաշտպանություն            |
| **Երթուղավորում**  | Գլոբալ երթուղավորման ռազմավարություն (Fill First / Round Robin / P2C / Random / Least Used / Cost Optimized), wildcard մոդելային այլանուններ, fallback շղթաներ, combo լռելյայններ |
| **Կայունություն**  | Հարցումների հերթ, միացման cooldown, մատակարարի breaker-ի կարգավորում և cooldown-ի սպասման վարքագիծ                                                                                |
| **Ընդլայնված**     | Գլոբալ պրոքսիի կարգավորում (HTTP/SOCKS5), ըստ մատակարարի պրոքսիի վերասահմանումներ                                                                                                 |

Ընդհանուր բաժինն այլևս չի կրկնում միայն-կարդացման մատյանի և քեշի նշումները։ Տվյալների բազայի պահպանման և
օպտիմալացման կարգավորումները պահպանվում են `/api/settings/database`-ի միջոցով. քեշի ձեռքով մաքրումն օգտագործում է
`DELETE /api/cache`։ Հարցումների և պրոքսիի մատյանների տողերի սահմանափակումները կառավարվում են
`CALL_LOGS_TABLE_MAX_ROWS` և `PROXY_LOGS_TABLE_MAX_ROWS`-ով։

Հասանելիություն՝ **Վահանակ → Ծախսեր**-ի միջոցով։

| Ներդիր          | Նպատակ                                                                                                         |
| --------------- | -------------------------------------------------------------------------------------------------------------- |
| **Բյուջե**      | Սահմանեք ծախսերի սահմանաչափեր ըստ API բանալու՝ օրական/շաբաթական/ամսական բյուջեներով և իրական ժամանակի հետևմամբ |

```bash
# API. Ստանալ բյուջեի ընթացիկ կարգավիճակը
```

### Combo-ների հավասարակշռման ռազմավարություններ

Կարգավորեք յուրաքանչյուր combo-ի հավասարակշռումը **Վահանակ → Combos → Ստեղծել/Խմբագրել → Ռազմավարություն** բաժնում։

| Ռազմավարություն    | Նկարագրություն                                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------------------------------- |
| **Round-Robin**    | Հաջորդաբար հերթափոխում է մոդելները                                                                              |
| **Priority**       | Միշտ փորձում է առաջին մոդելը. fallback է կատարում միայն սխալի դեպքում                                           |
| **Random**         | Յուրաքանչյուր հարցման համար combo-ից ընտրում է պատահական մոդել                                                  |
| **Weighted**       | Երթուղավորում է համամասնորեն՝ ըստ յուրաքանչյուր մոդելին նշանակված կշիռների                                      |
| **Least-Used**     | Երթուղավորում է դեպի վերջին ժամանակում ամենաքիչ հարցումներ ունեցած մոդելը (օգտագործում է combo-ի չափորոշիչները) |
| **Cost-Optimized** | Երթուղավորում է դեպի ամենաէժան հասանելի մոդելը (օգտագործում է գնագոյացման աղյուսակը)                            |

Combo-ի գլոբալ լռելյայնները կարելի է սահմանել **Վահանակ → Կարգավորումներ → Երթուղավորում → Combo-ի լռելյայններ** բաժնում։
Combo թիրախների timeout-ները լռելյայն ժառանգում են ընթացիկ հարցման timeout-ը։ Օգտագործեք **Թիրախի timeout
(վայրկյաններ)** combo-ի լռելյայնների կամ առանձին combo-ի համար միայն այն դեպքում, երբ ավելի կարճ ըստ-թիրախի
սահմանաչափը պետք է ակտիվացնի ավելի արագ fallback։

Zero-latency combo օպտիմալացումները կամավոր են (opt-in)։ Թողեք **Zero-latency օպտիմալացումները** անջատված՝
կանխելու համար, որ այս latency հնարավորությունները մրցեն fallback թիրախների դեմ, բաց թողնեն թիրախներ TTFT
պատմության հիման վրա կամ սեղմեն fallback հարցումները. միացնելը թույլ է տալիս կարգավորված hedging-ին,
կանխատեսող TTFT բացթողումներին և ակտիվ fallback սեղմմանը զոհել երթուղավորման/հարցման ճշգրտությունը՝ ավելի ցածր tail
latency-ի դիմաց։

Անջատեք **Reasoning token-ների բուֆերը**, երբ վերևային մատակարարները պահանջում են խիստ
`max_tokens` / `maxOutputTokens` սահմանափակումներ: Միացված վիճակում combo routing-ը reasoning մոդելի
լրացուցիչ պահուստ է ավելացնում միայն հայտնի ելքային սահման ունեցող մոդելների համար և հաճախորդի token սահմանափակումը թողնում է
անփոփոխ, երբ ապահով բուֆերացված արժեքը կգերազանցի այդ սահմանը: Եթե հաճախորդի սահմանափակումն արդեն գերազանցում է
հայտնի սահմանը, OmniRoute-ը նվազեցնում է այն մինչև այդ սահմանը՝ նախքան վերևային հարցումն ուղարկելը:

### Առողջության վահանակ

Մուտք գործեք **Վահանակ → Առողջություն** բաժնի միջոցով: Համակարգի առողջության իրական ժամանակում ակնարկ 6 քարտով.

| Քարտ                             | Ինչ է ցույց տալիս                                                                           |
| -------------------------------- | ------------------------------------------------------------------------------------------- |
| **Համակարգի վիճակ**              | Աշխատանքի տևողություն, տարբերակ, հիշողության օգտագործում, տվյալների կատալոգ                 |
| **Մատակարարի առողջություն**      | Մատակարարի circuit breaker-ի գլոբալ գործարկման վիճակ                                        |
| **Հարցումների սահմանափակումներ** | Ակտիվ միացման սառեցումներ ըստ հաշվի՝ մնացած ժամանակով                                       |
| **Ակտիվ կողպումներ**             | Մոդելի մակարդակի ակտիվ կողպումներ և ժամանակավոր բացառումներ                                 |
| **Ստորագրության քեշ**            | Կրկնօրինակների վերացման քեշի վիճակագրություն (ակտիվ բանալիներ, հարվածների հաճախականություն) |
| **Ձգձգման հեռաչափություն**       | p50/p95/p99 ձգձգման ագրեգացիա ըստ մատակարարի                                                |

**Օգտակար խորհուրդ.** Առողջություն էջը ավտոմատ կերպով թարմացվում է ամեն 10 վայրկյանը: Օգտագործեք circuit breaker քարտը՝ պարզելու համար, թե որ մատակարարներն են խնդիրներ ունենում:

## 🤖 Ավտոմատ երթուղավորում (առանց կարգավորման)

OmniRoute-ը ներառում է **գնահատականով կառավարվող ավտոմատ երթուղիչ**, որը յուրաքանչյուր հարցման համար ընտրում է լավագույն մոդելը բոլոր միացված մատակարարներից՝ առանց համակցություններ սպասարկելու անհրաժեշտության։ Պարզապես ուղարկեք հարցումը `auto/*` նախածանցներից մեկով, և OmniRoute-ն ընթացքի մեջ կկազմի վիրտուալ համակցություն՝ թեկնածուներին գնահատելով ըստ ուշացման, արժեքի, հաջողության գործակցի, համատեքստին համապատասխանության, առաջադրանքի համար մոդելի պիտանիության, վերջին ձախողումների, քվոտայի և շղթայի անջատիչի վիճակի։

| Նախածանց       | Օպտիմալացնում է                                                                                                |
| -------------- | -------------------------------------------------------------------------------------------------------------- |
| `auto`         | Հավասարակշռված լռելյայն տարբերակ (ուշացում × արժեք × հաջողության գործակից)                                     |
| `auto/coding`  | Ծրագրավորման առաջադրանքներ. նախընտրում է Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek ծրագրավորման մոդելները |
| `auto/cheap`   | Նվազագույն $/token, ընդունում է ավելի բարձր ուշացում                                                           |
| `auto/fast`    | Նվազագույն ուշացում, անտեսում է արժեքը                                                                         |
| `auto/offline` | Միայն տեղային մատակարարներ (Ollama, vLLM, llama.cpp)՝ օգտակար մեկուսացված միջավայրերի համար                    |
| `auto/smart`   | Նախևառաջ՝ դատողության որակ (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)                                          |
| `auto/lkgp`    | «Վերջին հայտնի լավ մատակարար»՝ ամրագրվում է վերջին հաջող մատակարարին, ապա անցնում է պահուստային կանոններին     |

Օրինակ՝

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

Ավտոմատ երթուղիչն ամբողջությամբ նկարագրված է [AUTO-COMBO.md](../routing/AUTO-COMBO.md)-ում՝ ներառյալ գնահատման կշիռների ճշգրտումը, մատակարարներին սև ցուցակում ներառելը և երթուղավորման որոշումները **Կառավարման վահանակ → Auto Combo** բաժնում դիտելը։

## 🔌 MCP և A2A ինտեգրում

OmniRoute-ը միաժամանակ **MCP սերվեր** (Model Context Protocol) և **A2A սերվեր** (Agent-to-Agent JSON-RPC 2.0) է։ MCP-ի հետ համատեղելի ցանկացած IDE կամ գործակալի հոսթ կարող է անմիջապես կանչել OmniRoute-ի գործիքները՝ առանց լրացուցիչ փաթաթիչի։

### MCP փոխադրամիջոցներ

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **Հոսքային HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (stdio նախընտրող IDE հավելումների համար)

### Claude Desktop-ի միացում

Խմբագրեք `~/Library/Application Support/Claude/claude_desktop_config.json` ֆայլը (macOS-ում) կամ դրա համարժեքը Windows/Linux-ում՝

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCP-ի միացում

Օգտագործեք SSE URL-ը՝ `http://localhost:20128/api/mcp/sse`, և Bearer API բանալի, որը ստեղծվել է **Կառավարման վահանակ → API բանալիներ** բաժնում։

### Հասանելիության շրջանակներ

MCP-ն ներկայում սահմանում է 32 անվանված շրջանակ։ Յուրաքանչյուր Bearer բանալի կարող է սահմանափակվել որոշակի շրջանակներով. շրջանակների և գործիքների պաշտոնական ցանկի համար տե՛ս [MCP-SERVER.md](../frameworks/MCP-SERVER.md), իսկ JSON-RPC սխեմայի համար՝ [A2A-SERVER.md](../frameworks/A2A-SERVER.md)։

## 🧠 Հմտությունների համակարգ

OmniRoute-ը տրամադրում է ընդլայնելի **հմտությունների շրջանակ** (`src/lib/skills/`), որպեսզի գործակալները և A2A վերջնակետը կարողանան գործարկել առարկայական ոլորտին հատուկ ընթացակարգեր (օրինակ՝ `code-review`, `summarize`, `extract-facts`, `web-research`)։

- **Շուկայի միջերես** — Դիտեք և տեղադրեք հմտություններ **Կառավարման վահանակ → Հմտություններ** բաժնից

- **Հատուկ հմտություններ** — Տեղադրեք TypeScript ֆայլ `src/lib/a2a/skills/` պանակում, գրանցեք այն, և այն անմիջապես հնարավոր կլինի կանչել A2A-ի միջոցով

## 💾 Հիշողության համակարգ

OmniRoute-ը պահպանում է **երկարաժամկետ խոսակցական հիշողությունը**՝ հիբրիդային որոնմամբ․

- **SQLite FTS5**՝ նախորդ երկխոսության քայլերում հիմնաբառերով որոնման համար

- **Փաստերի ավտոմատ արտահանում** — էությունները, նախապատվությունները և որոշումներն ամփոփվում են յուրաքանչյուր աշխատաշրջանից հետո և պահվում `memory_facts` աղյուսակում
- Հիշողությունները մեկուսացվում են ըստ API բանալու և աշխատաշրջանի

Կառավարեք հիշողությունները **Կառավարման վահանակ → Հիշողություն** բաժնում (որոնում, խմբագրում, արտահանում, մաքրում)։ HTTP միջերեսը (`/api/memory/*`) գործակալներին թույլ է տալիս ծրագրային եղանակով ուղարկել և հարցումներ կատարել փաստերի վերաբերյալ․ տե՛ս [MEMORY.md](../frameworks/MEMORY.md)։

## 🔔 Վեբհուքներ

Բաժանորդագրվեք OmniRoute-ի իրադարձություններին՝ իրական ժամանակում մշտադիտարկման և ավտոմատացման համար։

- Ստեղծեք վեբհուք **Կառավարման վահանակ → Վեբհուքներ** բաժնում՝ նշելով նպատակային URL-ը և HMAC ստորագրման գաղտնաբառը

- Կրկնափորձեր՝ 3 փորձ՝ էքսպոնենցիալ ուշացմամբ, այնուհետև՝ չմշակված հաղորդագրությունների հերթ

## 🛠️ Ծրագրային կառավարում

Դուք կարող եք HTTP-ի միջոցով կառավարել OmniRoute-ի յուրաքանչյուր ռեսուրս (մատակարարներ, համակցություններ, բանալիներ, կարգավորումներ)՝ օգտագործելով **Bearer բանալի՝ `manage` հասանելիության շրջանակով**։

Ստեղծեք բանալին **Կառավարման վահանակ → API բանալիներ → Նոր բանալի → Հասանելիության շրջանակ՝ manage** բաժնում, այնուհետև՝

```bash
# Ցուցադրել մատակարարները
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Ավելացնել մատակարարի միացում
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Ստեղծել համակցություն
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Ցուցադրել/ստեղծել API բանալիներ
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

Վերջնակետերի ամբողջական կատալոգի և հարցման/պատասխանի սխեմաների համար տե՛ս [API_REFERENCE.md](../reference/API_REFERENCE.md)։

## 💻 Ներքին CLI

OmniRoute-ը ներառում է ներքին CLI (`omniroute …`)՝ սկզբնական կարգավորման, ախտորոշման և կատարման ժամանակ կառավարման համար։ Սա **առանձին է կառավարման վահանակի «CLI գործիքներ» էջից**, որը կարգավորում է երրորդ կողմի CLI-ները (Claude Code, Cursor, Codex, Cline, …), որպեսզի դրանք կարողանան հաղորդակցվել OmniRoute-ի հետ։

```bash
omniroute setup                    # Ինտերակտիվ օգնական (գաղտնաբառ, մատակարարներ, համակցություններ)
omniroute setup --non-interactive  # Հարմար է CI-ի համար
omniroute doctor                   # Համակարգի վիճակի ախտորոշում (տվյալների պանակ, ՏԲ, մատակարարներ, պորտեր)
omniroute providers available      # Ցուցադրել աջակցվող մատակարարները
omniroute providers list           # Ցուցադրել կարգավորված կապերը
omniroute providers test <id>      # Իրական ժամանակում ստուգել մատակարարի կապը
omniroute combos list              # Ցուցադրել համակցությունները
omniroute combos switch <name>     # Սահմանել լռելյայն համակցությունը
omniroute models                   # Ցուցադրել հասանելի մոդելները (--json, --search)
omniroute keys add | list | remove # Կառավարել API բանալիները տերմինալից
omniroute backup                   # Ստեղծել կարգավորումների + ՏԲ-ի պատճեն
omniroute restore [<timestamp>]    # Վերականգնել պատճենից
omniroute health                   # Մանրամասն վիճակ (անջատիչներ, քեշ, հիշողություն)
omniroute quota                    # Մատակարարի քվոտայի օգտագործում
omniroute mcp status               # MCP սերվերի վիճակ
omniroute a2a status               # A2A սերվերի վիճակ
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok թունելներ
omniroute reset-password           # Վերակայել ադմինիստրատորի գաղտնաբառը
omniroute --mcp                    # Գործարկել MCP սերվերը stdio-ի միջոցով
omniroute --port 3000              # Գործարկել սերվերը հատուկ պորտով
```

Հուշում․ օգտագործեք `omniroute doctor --json`-ը ձեր մոնիթորինգի գործիքի հետ՝ մատակարարների անսարք կապերի մասին ծանուցումներ ստանալու համար։
