Ուղղորդեք **Claude Code** CLI-ը (`claude`) դեպի OmniRoute՝ տեղային կամ հեռակա VPS-ում՝
յուրաքանչյուր մոդելի համար առանձին պրոֆիլներով՝ Codex-ի կարգավորումների նմանությամբ։

---

## Արագ մեկնարկ

```bash
# Գործարկել Claude Code-ը տեղային OmniRoute-ի հետ (ակտիվ համատեքստը հայտնաբերվում է ավտոմատ)
omniroute launch

# Հեռակա OmniRoute-ի հետ (`omniroute connect <host>`-ից հետո սա կատարվում է ավտոմատ)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Ստեղծել յուրաքանչյուր մոդելի համար առանձին պրոֆիլներ, ապա գործարկել դրանցից մեկը
omniroute setup-claude            # գրանցում է ~/.claude/profiles/<name>/settings.json-ում
omniroute launch --profile glm52  # Claude Code՝ OmniRoute-ի միջոցով glm/glm-5.2-ն օգտագործելով
```

---

## Ինչպես Claude Code-ը միանում է դարպասին

Claude Code խոսում է**Anthropic Հաղորդագրություններ API** և ուղղված է հարմարեցված վերջնակետին՝ շրջակա միջավայրի փոփոխականներով (այն չունի `--base-url` դրոշ):

| Փոփոխական                                    | Նպատակը                                                                                                  |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | Դարպասի արմատ URL (Claude կոդը կցում է `/v1/messages`):** Ոչ `/v1` վերջածանց:**                          |
| `ANTHROPIC_AUTH_TOKEN`                       | Ուղարկված է որպես `Authorization: Bearer …` — օգտագործեք ձեր OmniRoute մուտքի նշանը / API ստեղնը         |
| `ANTHROPIC_API_KEY`                          | Այլընտրանք. ուղարկված է որպես `x-api-key`: Եթե երկուսն էլ սահմանեն, ապա `ANTHROPIC_AUTH_TOKEN` հաղթում է |
| `ANTHROPIC_MODEL`                            | Պարտադրել որոշակի մոդել (շրջանցում է `/model` ընտրիչի լռելյայն)                                          |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → հայրենի `/model` ընտրիչը թվարկում է `claude*`/`anthropic*` մոդելները `/v1/models` ից               |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | Կափարիչով ելքային նշանները մեկ պատասխանի համար (օր. `65536`)                                             |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | Ավտոմատ սեղմման նշանի շեմը                                                                               |

> Env vars են ընթերցվում** մեկ անգամ գործարկման ժամանակ** — վերագործարկեք Claude կոդը դրանք փոխելուց հետո:

Հավատարմագրի համար, որը պտտվում է ֆիքսված տողի փոխարեն, `apiKeyHelper` `~/.claude/settings.json` ում դրեք հրաման, որը տպում է ընթացիկ հավատարմագիրը stdout-ում: Claude կոդը լռելյայնորեն պահում է իր ելքը հինգ րոպեով (`CLAUDE_CODE_API_KEY_HELPER_TTL_MS` վերացնում է դա) և ուղարկում է արժեքը և՛ `Authorization: Bearer`, և՛ `x-api-key`: Սցենարը պետք է տպի հավատարմագրերը, և ոչ մի այլ բան — դրոշակի կողքին, որը ձախողում է օգնականը v2.1.227 + ում:

Entra ID SSO այսպես է աշխատում. `scripts/cli/omniroute-sso.mjs token` տպում է կարճատև Entra մուտքի նշան, որը OmniRoute ստուգում է API ստեղնի փոխարեն: Տես [`docs/security/ENTRA_SSO.md`](../security/ENTRA_SSO.md).

`omniroute launch` սահմանում է այս ամենը ձեզ համար. այն լուծում է հիմնական URL + նշանը ակտիվ համատեքստից (այնպես որ `omniroute connect <vps>` ապա `omniroute launch` պարզապես աշխատում է), ստուգում է սերվերի առողջությունը և կատարում է `claude`:

## Օգտագործման վերագրում՝ նիստեր և նախագծեր

OmniRoute խմբավորում է API ստեղնի յուրաքանչյուր հարցումը** գործակալի նիստեր** և արձանագրում է, որը** նախագիծը** յուրաքանչյուր նիստի վրա աշխատել է (`agent_sessions` աղյուսակ), այնպես որ օգտագործման և ծախսերի մասին կարող են զեկուցվել յուրաքանչյուր թիմի անդամի, յուրաքանչյուր նախագծի և մեկ նստաշրջանի համար:

Այն, ինչ գրանցվում է առանց հաճախորդի տեղադրման.

| Դաշտ       | Աղբյուր                                                                                                                                                               |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Նիստ       | `x-claude-code-session-id` վերնագիր (նույն արժեքը, ինչ `metadata.user_id.session_id`), կայուն մեկ նստաշրջանի համար                                                    |
| Նախագիծ    | `Primary working directory:` տող Claude կոդը ուղարկում է իր միջավայրում հաղորդագրություն. worktree թղթապանակները `.claude/worktrees/` ի տակ լուծում են պահեստի անունը |
| Մասնաճյուղ | `Current branch:` git կարգավիճակից Claude կոդը ուղարկում է առաջին հաղորդագրությամբ                                                                                    |
| Հաճախորդ   | `user-agent` (`claude-cli/<version>`)                                                                                                                                 |

Codex (`<environment_context><cwd>`) և OpenCode (`x-opencode-session`) ճանաչվում են նույն կերպ: Ստեղներ հետ** ոչ մատյան** միացված է պահպանել միայն նիստի ID-ն և վերնագրի կողմից տրամադրված նախագծի դաշտերը. հուշումից (ուղի, ճյուղ) կարդացված ոչինչ չի պահվում:

### Նախագծի հստակ անվանում (խորհուրդ է տրվում)

Աշխատանքային գրացուցակը տարբերվում է մեքենաների միջև, ուստի նույն պահեստը կարող է հայտնվել տարբեր ուղիների տակ: Փոխարենը ուղղակիորեն ուղարկեք նախագիծը. Claude Code-ը յուրաքանչյուր մոդելի հարցում ավելացնում է `ANTHROPIC_CUSTOM_HEADERS` ում նշված վերնագրերը, և OmniRoute կարդում է դրանցից երկուսը.

| Վերնագիր                   | Արժեք                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------ |
| `x-omniroute-project`      | Նախագծի անվանումը, օրինակ՝ `omniroute`                                               |
| `x-omniroute-project-repo` | Նորմալացված հեռակառավարման վահանակ, օրինակ՝ `github.com/cheaper-inference/OmniRoute` |

Երկուսն էլ կարդացվում են միայն վերագրման համար. դրանք երբեք չեն փոխանցվում հոսանքին հակառակ մատակարարին:

`ANTHROPIC_CUSTOM_HEADERS` կարդացվում է մեկ անգամ գործարկման ժամանակ, և կարգավորումների ֆայլերը պահում են բառացի արժեքներ, այնպես որ հաշվարկեք այն, երբ գործարկվի Claude Code: Ավելացրե՛ք սա `~/.zshrc` կամ `~/.bashrc` և շարունակե՛ք սկսել `claude` նախագծի պանակից.

```bash
claude() {
  local common name repo
  if common=$(git rev-parse --path-format=absolute --git-common-dir 2>/dev/null); then
    case $common in
      */.git) name=$(basename "$(dirname "$common")") ;;  # repository name, also in worktrees
      *) name=$(basename "$common" .git) ;;                # bare repository (/srv/foo.git)
    esac
    repo=$(git remote get-url origin 2>/dev/null \
      | sed -E 's#^[a-zA-Z][a-zA-Z0-9+.-]*://([^@/]*@)?##; s#^[^@/]+@([^:]+):#\1/#; s|[?#].*$||; s#\.git$##')
  else
    name=$(basename "$PWD")                                # not a git repository: folder name
  fi
  ANTHROPIC_CUSTOM_HEADERS="${ANTHROPIC_CUSTOM_HEADERS:+${ANTHROPIC_CUSTOM_HEADERS}
}x-omniroute-project: ${name}${repo:+
x-omniroute-project-repo: ${repo}}" command claude "$@"
}
```

`sed` արտահայտությունը ջնջում է ցանկացած հավատարմագրերը, հարցման տողը և հատվածը, որոնք ներկառուցված են հեռավոր URL ում, իսկ վերնագրերն արդեն `ANTHROPIC_CUSTOM_HEADERS` ում են պահվում: IDE ընդլայնումները գործարկում են Claude Code առանց ձեր կեղևի, այնպես որ դրանց նիստերը վերադառնում են աշխատանքային գրացուցակ:

## Հայտնաբերման կեղծանուններ — ոչ Claude մոդելների ցուցադրում `/model` ընտրիչում

Claude Code-ի gateway-ի մոդելների հայտնաբերումը ցուցակում է միայն `claude` կամ `anthropic`-ով սկսվող id-ները, ուստի `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` դեպքում ներկառուցված `/model` ընտրիչը սովորաբար ցույց է տալիս **միայն** OmniRoute-ի Claude/Anthropic մոդելները․ `kimi/kimi-k2.6`-ը կամ `glm/glm-5.2`-ը երբեք չի հայտնվում, թեև այն ճիշտ է երթուղավորվում։

OmniRoute-ը կարող է ցանկացած միացված մոդել (և combo) արտացոլել `claude/…` id-ի ներքո, որպեսզի այն անցնի այդ ֆիլտրը և հայտնվի ընտրիչում․

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

Երբ Claude Code-ում ընտրում եք դրանցից մեկը, OmniRoute-ը հանում է `claude/` փաթաթանը՝ երթուղավորումից առաջ վերադարձնելով իրական id-ն․ իսկական `claude/<real-claude-model>` id-ն (իրական Claude OAuth մատակարարը) միշտ մնում է անփոփոխ։

Լռելյայնորեն արտացոլվում են միայն բազային id-ները։ Ընտրովի `CATALOG_MIRROR_REFINEMENTS_ENABLED` feature flag-ը միացված լինելու դեպքում կատալոգում արդեն ցուցակված reasoning-effort տարբերակները (օր․ `codex/gpt-6-sol-high`) արտացոլվում են ցանկացած այլ id-ի պես, այնպես որ Claude Code-ը կարող է ընտրել հստակ effort մակարդակ, իսկ ներկառուցված `auto/*` id-ները, որոնք հարցման ուղին չի կարող իրականացնել, չեն արտացոլվում։ Արդյոք effort տարբերակները ընդհանրապես ցուցակվում են, դա դեռևս որոշում է `OMNIROUTE_DISABLE_THINKING_LEVEL_VARIANTS`-ը․ հայելին երբեք չի ավելացնում այնպիսի տարբերակ, որը բազային կատալոգը չունի։

**Սա լռելյայնորեն անջատված է** և կառավարվում է եռամակարդակ դարպասով (ամենակոնկրետը հաղթում է), այնպես որ պարզ OmniRoute-ը երբեք չի կրկնապատկում իր կատալոգը այն կլիենտների համար, որոնք չեն օգտագործում Claude Code․

| Մակարդակ  | Որտեղ                                                                                   |
| --------- | --------------------------------------------------------------------------------------- |
| Մոդել     | Մատակարարի մանրամասն էջ → յուրաքանչյուր մոդելի «Ցուցադրել Claude Code-ում» անջատիչ      |
| Մատակարար | Մատակարարի մանրամասն էջ → մատակարարի մակարդակի անջատիչ (ընդգրկում է բոլոր իր մոդելները) |
| Գլոբալ    | Կարգավորումներ → Feature Flags → `EXPOSE_CC_DISCOVERY_ALIASES` (լռելյայնորեն անջատված)  |

`EXPOSE_CC_DISCOVERY_ALIASES` միջավայրի փոփոխականը հարկադրաբար միացնում է գլոբալ մակարդակը և գերակայում է dashboard-ի փոփոխությանը (այդ դեպքում Feature Flags էկրանը ցույց է տալիս «ակտիվ է միջավայրի փոփոխականի միջոցով» նշում)։ Մատակարարի և մոդելի մակարդակների անջատիչները այնտեղից ճշգրտում են — օր․ գլոբալ անջատված + Kimi մատակարարը միացված բացում է միայն Kimi-ի մոդելները։

> ⚠️ **Պատուհանի անհամապատասխանություն ոչ Claude մոդելների դեպքում։** Claude Code-ը ցանկացած չճանաչված id-ի համար ենթադրում է 200K կոնտեքստային պատուհան (այն չի կարող կարդալ իրական պատուհանը `/v1/models`-ից)։ Ավելի մեծ պատուհան ունեցող մոդելի համար (օր․ Kimi K2-ի 256K) սահմանեք `CLAUDE_CODE_AUTO_COMPACT_WINDOW`-ը մոդելի իրական պատուհանից ցածր արժեքի, որպեսզի auto-compaction-ը վաղաժամ չգործարկվի։ Վերևում նշված գեներացված պրոֆիլներն արդեն սա անում են յուրաքանչյուր մոդելի համար։

## Վահանակի սկզբնական կարգավորման բլոկը

Claude գործիքի քարտը (**Վահանակ → CLI Code**) ցուցադրում է այս օրինակի համար նախատեսված
`settings.json`-ի ճշգրիտ հատվածը՝ հայտնաբերման կեղծանվան տեղեկությունների կոճակի կողքին և պատճենման կոճակով․

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

Բազային URL-ը քարտի կողմից որոշվածն է (ներառյալ ձեր մուտքագրած անհատական վերասահմանումը) և արդեն
նորմալացված է՝ առանց `/v1` վերջածանցի և առանց վերջավոր շեղագծի։ **Բանալին երբեք չի ցուցադրվում**․ բլոկը պարունակում է
տեղապահ, ուստի սքրինշոթը կամ տեղադրված հատվածը չեն կարող այն արտահոսքի ենթարկել։ Փոխարինեք այն ձեր բանալիով։

Նույն `env` բլոկում ավելացրեք `CLAUDE_CODE_AUTO_COMPACT_WINDOW` ցանկացած մոդելի համար, որի իրական
համատեքստի պատուհանը 200K չէ․ Claude Code-ը ենթադրում է 200K իր կողմից չճանաչված յուրաքանչյուր id-ի համար, ուստի
հակառակ դեպքում ավտոմատ կոմպակտացումը գործարկվում է սխալ պահին (տե՛ս նախորդ բաժնի զգուշացումը)։
Հատվածի կառուցիչը նույնպես ընդունում է այդ արժեքը, ուստի նպատակային մոդելի պատուհանը ճանաչող կանչողը
կարող է այն ուղղակիորեն արտածել։

Աղբյուր՝ `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (մաքուր
կառուցիչ՝ միավորային թեստերով), որը ցուցադրվում է `ClaudeGatewayOnboardingBlock`-ի կողմից։

### Ամրագրել մեկ հաշիվ (ըստ ցանկության)

Claude Code-ի յուրաքանչյուր հարցում մեկ կոնկրետ մատակարարի հաշվով ուղարկելու համար նույն `env` բլոկում
`ANTHROPIC_CUSTOM_HEADERS`-ի միջոցով ավելացրեք `x-omniroute-connection` վերնագիրը․

```jsonc
"ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>"
```

Պատճենեք id-ն մատակարարի էջում կապի տողի `xxxxxxxx…` նշապիտակից։ Ամրագրումը կիրառվում է միայն
մեկ մոդել պարունակող id-ների (`provider/model`) համար, ոչ թե համակցությունների։ Ճշգրիտ պահուստային վարքագծի համար տե՛ս
[Հաշվի ամրագրում՝ ըստ հարցման](../reference/API_REFERENCE.md#account-pinning-per-request)։

## Պրոֆիլներ (`CLAUDE_CONFIG_DIR`)

Claude Code-ը **չունի ներկառուցված պրոֆիլային ֆայլեր** (ի տարբերություն Codex-ի `~/.codex/<name>.config.toml`-ի)։
Ընդունված մեխանիզմը `CLAUDE_CONFIG_DIR`-ն է՝ յուրաքանչյուր պրոֆիլի համար առանձին կազմաձևման պանակ՝
իր սեփական `settings.json`-ով, նույնականացման տվյալներով, պատմությամբ և քեշով։

`omniroute setup-claude`-ը ստանում է գործող `/v1/models` կատալոգը և յուրաքանչյուր
մոդելի համար ստեղծում մեկ պրոֆիլ `~/.claude/profiles/<name>/settings.json` հասցեում՝ կրկին օգտագործելով
**նույն անունները, ինչ `setup-codex`-ը** (`glm52`, `kimi-k27`, `deepseek-pro`, …)։

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **Նույնականացման տոկենը երբեք չի գրվում պրոֆիլում։** Գործարկեք
> `omniroute launch --profile <name>` հրամանով (այն ակտիվ համատեքստից ներարկում է `ANTHROPIC_AUTH_TOKEN`-ը),
> կամ ինքներդ արտահանեք `ANTHROPIC_AUTH_TOKEN`-ը և գործարկեք
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`։

**Ավտոմատ համաժամացում՝ մոդելների հայտնաբերումից հետո (ըստ ցանկության)։** OmniRoute-ը կարող է ավտոմատ կերպով վերաստեղծել այս նույն
`~/.claude/profiles/<name>/settings.json` ֆայլերը, երբ մատակարարի մոդելների
համաժամացումը փոխում է գործող կատալոգը, որպեսզի նոր կամ վերանվանված մոդելները պրոֆիլներ ստանան՝ առանց հրամանը
կրկին գործարկելու։ Այն **լռելյայն անջատված է**․ միացրեք այն **CLI Code վահանակից** («CLI պրոֆիլների
ավտոմատ համաժամացում» → Claude Code) կամ սահմանեք `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` (այն նաև հաշվի է առնում
`CLI_ALLOW_CONFIG_WRITES`-ը, որը լռելյայն միացված է)։ Միացված լինելու դեպքում այն գրում է միայն պրոֆիլային ֆայլերը և երբեք
չի փոխում ձեր ակտիվ կամ լռելյայն Claude-ի կազմաձևումը, նույնականացման տվյալները կամ `~/.claude/settings.json`-ը։

### Պրոֆիլների ստեղծում և օգտագործում

```bash
# Տեղային OmniRoute
omniroute setup-claude

# Հեռակա VPS (VPS-ի URL-ը ներառում է յուրաքանչյուր պրոֆիլում)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Միայն որոշ մատակարարներ
omniroute setup-claude --only glm,kimi

# Նաև ստեղծել պրոֆիլներ այս հոսթում չհայտնաբերված տեղային CLI մատակարարների համար (zcode, auggie, devin-cli-agentic,
# codex-app-server) (տեղային թիրախի դեպքում լռելյայն բաց են թողնվում)
omniroute setup-claude --include-local

# Նախադիտել՝ առանց գրելու
omniroute setup-claude --dry-run

# Գործարկել պրոֆիլը
omniroute launch --profile kimi-k27
```

## Մոդելների մակարդակներ (ըստ ցանկության)

Claude Code-ը հարցումներն ուղղորդում է ըստ հնարավորությունների մակարդակների։ Եթե ցանկանում եք յուրաքանչյուր մակարդակի համար օգտագործել տարբեր մատակարարներ, env /
կարգավորումների միջոցով յուրաքանչյուր մակարդակ համապատասխանեցրեք OmniRoute մոդելի հետ․

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
```

## Հեռավար ռեժիմ

Երբ գործարկեք `omniroute connect <host>`-ը (տե՛ս
[Հեռավար ռեժիմ](./REMOTE-MODE.md)), `omniroute launch`-ը և `omniroute setup-claude`-ը
ինքնաբերաբար կթիրախավորեն այդ հեռավար սերվերը և կօգտագործեն դրա սահմանափակված հասանելիության թոքենը՝ առանց
լրացուցիչ դրոշակների։ Առանձին կանչի համար վերասահմանեք `--remote` / `--api-key`-ով։

## Անսարքությունների վերացում

**Claude Code-ն անտեսում է դարպասը** — հաստատել `ANTHROPIC_BASE_URL` ունի** ոչ `/v1`** և վերագործարկեք `claude` (env-ն կարդացվում է մեկ անգամ գործարկման ժամանակ): `omniroute launch` դա անում է ձեզ համար:

**`/model` ընտրիչը դատարկ է / բացակայում է դարպասների մոդելները** — անհրաժեշտ է Claude Code v2.1.219 + և `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`: Միայն `claude*` / `anthropic*` մոդելը IDs հայտնվում է ընտրիչում; ստիպել ցանկացած այլ մոդել `ANTHROPIC_MODEL=<id>` ով (սա անում են պրոֆիլները):

**`400 Ambiguous model 'claude-…'`** — Claude կոդը միշտ ուղարկում է** առանց նախածանցի** IDs մոդելը (օր. `claude-opus-4-8`), այնպես որ, երբ և՛ Claude Code (`cc/…`), և՛ Claude (`claude/…`) մատակարարները միացված են, մերկ id-ը համընկնում է երկու երթուղիների հետ, և OmniRoute հրաժարվում է կռահել: Ուղղեք դա ցանկացած ձևով. ամրացրեք նախածանցով id `ANTHROPIC_MODEL=cc/claude-opus-4-8` ով կամ միացրեք** Նախընտրեք Claude ծածկագիրը unprefixed Claude մոդելների համար** — փոխարկեք Claude մատակարարի էջի վրա կամ `OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (կանխադրված անջատված է, տես [Շրջակա միջավայր](../reference/ENVIRONMENT.md) ) — որը փոխարենը ուղղում է `claude-*` IDs Claude կոդ: Հստակ մատակարարի նախածանցները միշտ հաղթում են:

**«ավտո ռեժիմ… այս նստաշրջանը չի համապատասխանում» (դասակարգիչի հարցումները վճարվում են)** — ավտոմատ ռեժիմում Claude կոդը խնդրում է սերվերին վերանայել գործողությունները իր մոդելի հարցումներում ( [Anthropic docs](https://code.claude.com/docs/en/auto-mode-classifier-billing) ): Դրան անհրաժեշտ է `anthropic-beta` արժեքը `dangerous-tool-use-2026-09-03` և `safeguards` մարմնի դաշտը, որպեսզի հասնեն Anthropic որպես զույգ, և `safeguard_results` գումարած վերին հոսքի գործիքը-օգտագործեք IDs անփոփոխ վերադառնալու համար: OmniRoute դա անում է, երբ հարցումը ուղղորդվում է հայրենի `claude` մատակարարին կամ `anthropic-compatible-*` հանգույցին, հեռարձակվում է, թե ոչ (ռեգեսիոն պահակ՝ `tests/integration/claude-auto-mode-classifier-e2e.test.ts`): Այլ թիրախները չեն կարող վերադարձնել վերանայումը, ուստի Claude կոդը վերադառնում է իր սեփական դասակարգչի հարցումներին և ցույց է տալիս ծանուցումը.

- մոդել ոչ Anthropic մատակարարի վրա, կամ կոմբին, որը վայրէջք է կատարում մեկի վրա.
- Claude-Code-ի հետ համատեղելի ռելե հանգույց (`anthropic-compatible-cc-*`), որը վերակառուցում է հարցման մարմինը և չի կրում `safeguards`;
- ավելի հին OmniRoute, որը հնացել է թույլատրված ցուցակի բետաների կամ Claude Code տարբերակի տակ, որը նշված է Anthropic էջերում gateway նիստերի համար:

Գործարկեք `/status` ն Claude կոդը՝ the** Ավտոմատ ռեժիմի սերվեր** տողը կարդում է `Enabled` մինչ սերվերի վերանայումն ակտիվ է: Արդյո՞ք այդ խնդրանքները վճարվում են, դա որոշում է Anthropic, ոչ թե OmniRoute:

**Հավաստագրման սխալներ** — պրոֆիլը չունի նշան: Օգտագործեք `omniroute launch --profile` (ներարկում է այն) կամ արտահանեք `ANTHROPIC_AUTH_TOKEN`:
