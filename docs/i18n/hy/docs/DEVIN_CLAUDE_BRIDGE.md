`devin-cli-agentic`-ը թույլ է տալիս, որ իրական Claude Code գործարկման միջավայրը օգտագործի OmniRoute-ի տեղային Anthropic
Messages վերջնակետը, մինչդեռ պաշտոնական Devin CLI-ն մոդելի պատասխանները տրամադրում է ACP stdio-ի միջոցով։ Այն
չի փոփոխում գոյություն ունեցող Anthropic, Claude OAuth, Claude Web կամ `devin-cli` մատակարարները։

Հաճախորդի կողմից կառավարվող գործիքների կանչերի համար հարցումներն ուղղորդեք `devin-cli-agentic`-ի միջոցով (այլանունը՝ `dva`)՝
Claude ձևաչափով, գործիքներ աջակցող մատակարարի։ Հին `devin-cli` (`dv`) ACP կատարիչը
միայն տեքստային է․ այն գործարկում է Devin-ի՝ առանց գործիքների ամփոփիչը և չի կարող վերադարձնել գործիքների կանչեր։ Դրա մոդելի
մետատվյալները համապատասխանաբար նշված են, որպեսզի գործիքներ պահանջող համակցված ուղղորդումը խուսափի դրանից։

> **Ընթացիկ կարգավիճակ․ ֆիքսված է Claude Code `2.1.258` տարբերակը․ անցանց և կենդանի վավերացումները վերջին անգամ գրանցվել են
> `2.1.220` տարբերակի համար։** `2.1.220` ֆիքսված տարբերակը հաջողությամբ անցել է երեք մեկուսացված սցենար Devin CLI
> `3000.2.17`-ի և `swe-1-7-lightning` մոդելի միջոցով․ այդ վերջնական կենդանի գործարկումը հաստատել է հաճախորդի կողմից կառավարվող `Read`,
> `Edit` և `Bash` քայլերը, `npm test`-ի հաջող արդյունքները, նախագծի հրամանների ու հմտությունների
> հայտնաբերումը, միայն Devin-ով ուղղորդումը և Claude-ի զրոյական ելքային երթևեկությունը։ Այնուհետև ֆիքսված տարբերակը բարձրացվել է մինչև `2.1.258`
> (CLI-ի այն սերունդը, որի ինքնությունն է նմանակում OmniRoute-ի Claude-ը, և առաջին շարքը, որը
> Fable 5.1 մակարդակը մատակարարում է ներկառուցված կերպով)։ Նոր ֆիքսված տարբերակում տեղադրման շերտը և `claude --version`-ը
> ստուգվել են ֆիքսված բազային պատկերի վրա, իսկ կամրջի միավորային թեստերի հավաքածուն, `compose config`-ը և
> մեկուսացման ստատիկ ապացույցը հաջողությամբ անցնում են, սակայն անցանց կեղծ սցենարը և կենդանի երեք սցենարից բաղկացած
> հավաքածուն դեռևս կրկին չեն գործարկվել։ Նախքան այս ֆիքսված տարբերակով կամրջին ապավինելը՝ կրկին գործարկեք դրանք (տե՛ս «Ֆիքսված գործիքների թարմացում» բաժինը)։

## Ճարտարապետություն

```text
Claude Code 2.1.258 (մեկուսացված, ոչ արմատային Linux կոնտեյներ)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude ձևաչափով, նույնականացում չպահանջող մատակարար)
  -> devin acp --agent-type summarizer (պաշտոնական ACP stdio, առանց Devin գործիքների)
  -> Devin հաշիվ՝ առանձնացված devin-auth հատորում
```

Պաշտոնական CLI-ի լռելյայն ACP գործակալը կարող է կատարել իր սեփական գործիքները, ուստի այս կամուրջը
այն չի օգտագործում։ Այն գործարկում է ֆիքսված `summarizer` ACP գործակալը, որի պաշտոնական CLI ռեժիմը գործիքներ չունի, և
սերիականացված Anthropic հարցումը ձևակերպում է որպես կատարման հետագիծ։ Երբ անհրաժեշտ է Claude-ի կողմից կառավարվող
ևս մեկ գործողություն, պատասխանը պետք է պարունակի հաճախորդի գործիքի ուղիղ մեկ ծրար։ Ցանկացած ACP
`tool_call` կամ `tool_call_update` մերժվում է՝ նախքան պատասխանը որպես
հաջողված ներկայացնելը։

`open-sse/executors/devin-agentic/serializer.ts`-ում գտնվող սերիականացուցիչը պահպանում է `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` դաշտերը և
Claude Code-ի տրամադրած գործիքները։ Պատկերներն ու անհայտ բլոկները հանգեցնում են հստակ ձախողման։ Գործիքների մեծ արդյունքների
դեպքում օգտագործվում է տեսանելի կրճատման նշիչ։

Վերլուծիչը յուրաքանչյուր մոդելային քայլի համար ընդունում է մեկ ինքնուրույն `<tool>{...}</tool>` ծրար։ Այն
ստուգում է անունը հարցման գործիքների ցանկի նկատմամբ, վավերացնում է արգումենտներն այդ գործիքի JSON
Schema-ի համաձայն, մերժում է պատմողական տեքստի և գործողությունների խառնուրդը և թույլատրում է մեկ սահմանափակ վերականգնման փորձ։ Այնուհետև Claude Code-ը
տեղային եղանակով կատարում է ստացված Anthropic `tool_use`-ը և `tool_result`-ը հետ է ուղարկում
OmniRoute-ի միջոցով։

## Ինքնաշխատ ուղղորդում

Մատակարարը կարող է ներառվել OmniRoute-ի `auto/*` թեկնածուների խմբերում, երբ այն արգելափակված չէ։
Թեկնածուի համապատասխան լինելը չի երաշխավորում ընտրությունը․ համակցության ուղղորդման ռազմավարությունը (օրինակ՝
last-known-good) կարող է նախընտրել մեկ այլ մատակարար։ Օգտագործեք `dva/<model>` կամ Devin-ին առաջնահերթություն տվող համակցություն, երբ
պահանջվում է, որ յուրաքանչյուր հարցում անցնի Devin-ի միջոցով։

## Մեկուսացում և սպառնալիքների մոդել

Հոսթի Claude-ի տեղադրումը, հաշիվը և կազմաձևումը դիտարկման շրջանակից դուրս են և համարվում են
արգելված։ Compose ծառայությունները՝

- աշխատում են UID/GID `10001:10001`-ով՝ միայն կարդալու համար հասանելի արմատային ֆայլային համակարգով, հեռացված հնարավորություններով և
  `no-new-privileges`-ով,
- օգտագործում են մասնավոր `/home/bridge`, Claude-ի կազմաձևման առանձին հատոր, մեկուսացված OmniRoute տվյալներ
  և առանձին `devin-auth` հատոր,
- կցում են միայն մեկանգամյա օգտագործման `.sandbox` աշխատանքային տարածքներ/ապացույցներ,
- չեն կցում հոսթի տնային պանակը, Keychain-ը, SSH-ը, ամպային հավատարմագրերը կամ Docker socket-ը,
- կառուցում են հստակ սահմանված միջավայրեր և հեռացնում Anthropic API/OAuth/ուղղորդման փոփոխականները,
- Claude Code-ի եզրակացումները ուղղորդում են միայն դեպի `http://omniroute:20128`՝ օգտագործելով միայն տեղային բանալի։

Անցանց պրոֆիլն օգտագործում է ներքին ցանց։ Ակտիվ պրոֆիլում OmniRoute-ը պաշտոնական Devin վերջնակետերին հասնում է
միայն `network-guard`-ի միջոցով, իսկ կապը չառնչվող հասցեների հետ արգելվում է։
Claude Code-ն ունի ելքային տրաֆիկն ամբողջությամբ արգելող առանձին պաշտպանիչ շերտ և `NO_PROXY`-ի միջոցով կարող է հասնել միայն տեղային OmniRoute
ծառայությանը։ Պաշտպանիչ շերտերի աուդիտի ֆայլերը կցվում են միայն իրենց համապատասխան պաշտպանիչ գործընթացին։
Սկրիպտները ստուգում են ֆայլերի սեփականատիրությունը, ռեժիմը, հղումների քանակը և յուրաքանչյուր որոշում՝ նախքան
թոքեններ չպարունակող ապացույցների արտահանումը։

Մեկուսացման ապացույցը գործարկեք առանձին՝

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Այն վավերացնում է տոպոլոգիան, անվանված կցումները, ոչ արմատային օգտատիրոջ/միայն կարդալու կարգավորումները, հստակ տեղային ուղղորդումը,
զգայուն միջավայրի փոփոխականների բացակայությունը, Docker socket-ի բացակայությունը, դեպի
`api.anthropic.com` և `claude.ai` հասանելիության արգելափակումը, միայն Devin մատակարարի ընտրությունը և հստակ ձախողումը, երբ
ACP հետնամասը հասանելի չէ։

## Առաջին անգամվա կարգավորում և սովորական օգտագործում

Կառուցեք ամրագրված տարբերակով պատկերը՝

```bash
./scripts/devin-bridge/build
```

Նույնականացրեք միայն մեկուսացված Devin հատորը՝

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Մուտքի հրամանն օգտագործում է հեռավոր/կոնտեյներային միջավայրերի համար նախատեսված՝ ձեռքով թոքեն մուտքագրելու պաշտոնական
գործընթացը։ Արժեքը մուտքագրվում է անմիջապես CLI-ի հուշման դաշտում․ այն չի փոխանցվում որպես
գործընթացի արգումենտ, չի գրվում Git-ում և չի պատճենվում հոսթից։

Գործարկեք մեկուսացված Claude Code կատարման միջավայրը՝

```bash
./scripts/devin-bridge/launch
```

`launch`-ը, նախքան կոնտեյներացված Claude Code-ը գործարկելը, կրկին ստուգում է մեկուսացումը, Devin-ի նույնականացումը
և մոդելների հայտնաբերումը։ Այն երբեք չի գործարկում հոսթի Claude գործարկելի ֆայլը։ Մոդելների կեղծանունները կարող են
սահմանվել `.env.devin-bridge`-ում․ կազմաձևված յուրաքանչյուր արժեք պետք է պահպանի
`devin-cli-agentic/` նախածանցը։

## Վավերացման հրամաններ

Վերարտադրելի անցանց ուղին Devin հաշիվ չի պահանջում և կատարման ընթացքում չունի համացանցային կապ՝

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Նույնականացում պահանջող, ըստ ցանկության միացվող ակտիվ ուղին հետևյալն է՝

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Ակտիվ գործարկիչը սցենարների միջև սպասում է՝ ACP աշխատաշրջանները կտրուկ հաջորդականությամբ չբացելու համար, և
տեքստային պնդումներին վստահելու փոխարեն վավերացնում է Claude-ի հոսքի կառուցվածքավորված իրադարձությունները։ Դրա երեք
սցենարներն ապացուցում են՝

1. նախագծի ուղղակի ընթերցում և թերությունների վերլուծություն,
2. իրական `Edit`, հաճախորդի կողմից կառավարվող `Bash` `npm test` և վերջնական արդյունք,
3. `/bridge-check` և `bridge-proof` հայտնաբերում, նախագծի ընթերցում, հաճախորդի կողմից կառավարվող ևս մեկ հաջող
   `npm test` և ավարտ՝ առանց սպասող աշխատանքի։

Վերջնական անցակետը նաև ստուգում է Devin-ի ցանցային աուդիտը և պահանջում, որ Claude-ի ելքային տրաֆիկի աուդիտը
դատարկ մնա։

## Ֆիքսված տարբերակներով գործիքների թարմացում

Պատկերում Node-ի, Claude Code-ի և Devin CLI-ի տարբերակները ֆիքսված են
`docker/devin-bridge/Dockerfile`-ում։ Թարմացնելու համար՝

1. փոխեք բացահայտ նշված տարբերակները,
2. ճարտարապետություններից յուրաքանչյուրին հատուկ Devin արխիվի ստուգիչ գումարը փոխարինեք պաշտոնական
   արտեֆակտի համապատասխան արժեքով,
3. վերակառուցեք և գործարկեք անցանց վավերացման բոլոր հրամանները,
4. հաստատեք պատկերի ներսում առկա տարբերակները,
5. կրկին գործարկեք նույնականացում պահանջող՝ երեք սցենարից բաղկացած իրական միջավայրի փաթեթը։

Մի տեղադրեք CLI-ներից որևէ մեկը հոսթում՝ գլոբալ եղանակով, և ստուգիչ գումարով վավերացումը մի
փոխարինեք չվավերացված ներբեռնմամբ։

## Ախտորոշում և մաքրում

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  ցուցադրում է տեղային երթուղավորումը և զգայուն տվյալներից մաքրված կատարիչի սխալները։
- `.sandbox/evidence/mock-acp.jsonl`-ը գրանցում է կանխորոշված mock ACP գործողությունները։
- `.sandbox/evidence/claude-stream.jsonl`-ը գրանցում է Claude Code-ի իրական անցանց գործարկումը։
- `.sandbox/evidence/live-*.jsonl`-ը գրանցում է վավերացված երեք իրական հոսքերը։
- `.sandbox/evidence/egress.jsonl`-ը և `.sandbox/evidence/claude-egress.jsonl`-ը պաշտպանիչ
  աուդիտների վավերացված, թոքեններ չպարունակող պատճեններն են։

Կանգնեցրեք պատկանող կոնտեյներներն ու ցանցերը՝ պահպանելով մուտքի/կազմաձևման հատորները․

```bash
./scripts/devin-bridge/clean
```

Հեռացրեք կամրջին պատկանող ամբողջ միջավայրը՝ ներառյալ անվանակոչված հատորները․

```bash
./scripts/devin-bridge/clean --all
```

## Սահմանափակումներ

- Կամուրջը հիմնվում է գործիքներ չօգտագործող ֆիքսված `summarizer` դերի վրա, քանի որ Devin CLI `3000.2.17`-ը
  գործիքներ չօգտագործող չեզոք ACP գործակալ չի տրամադրում։ Ադապտերը փոխհատուցում է ամփոփման ձև ունեցող
  միջանկյալ պատասխանները, սակայն սահմանափակված մեկ ուղղումը, միևնույն է, կարող է բացահայտ ձախողվել։
- Իրական ACP կանչերը կարող են վերադարձնել անցողիկ `502`/`504` պատասխաններ։ Փորձարկման համակարգը սցենարների միջև
  դադար է պահպանում․ շարունակական ձախողման դեպքում համակարգը մնում է մերժման անվտանգ ռեժիմում և երբեք այլ մատակարար չի ընտրում։
- ACP համատեքստը վերակառուցվում է Anthropic-ի յուրաքանչյուր հարցումից․ գործընթացի/նստաշրջանի
  հետ կապվածություն չկա։
- Մոդելի յուրաքանչյուր պատասխանի համար աջակցվում է գործիքի մեկ կանչ․ զուգահեռ կանչերը մերժվում են։
- Պատկերների աջակցությունը բացահայտորեն բացակայում է։ Տեսողական մշակումը, մտածողության ելքային տվյալները, ջանքի կառավարման տարրերը և 1M
  համատեքստային պատուհանը չեն հայտարարվում։
- SSE-ն օգտագործում է Anthropic-ի կենսացիկլի վավեր իրադարձություններ, սակայն դրանք թողարկվում են սահմանափակված ACP քայլը
  հավաքելուց հետո․ ACP հատվածներն աստիճանաբար չեն փոխանցվում։
