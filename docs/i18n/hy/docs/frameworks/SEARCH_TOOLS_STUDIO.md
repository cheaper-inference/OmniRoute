## Ներդիրներ

### Որոնման ներդիր

Գոյություն ունեցող `SearchForm` + `ResultsPanel` + `RerankPanel` վերածում է ներդիրի.

- Հարցում → արդյունքները (վերնագիր, URL, հատված, համապատասխանության միավոր):
- Մատակարարի մետատվյալները Config վահանակում (արժեք, չափաբաժին, կարգավիճակ):
- Վերադասակարգել բաժինը. ընտրել վերադասավորման մոդել, վերադասավորել արդյունքները, ցույց տալ `positionDelta`:
- Դատարկ վիճակ CTA հետ, երբ որոնողական պրովայդերներ կազմաձևված չեն:
- Որոնման պատմությունը `SearchHistory.tsx` միջոցով:
- Զանգում է `POST /v1/search` (առկա վերջնակետ, փոփոխություններ չկան):

### Scrape Tab

Նոր ներդիր URL ից `POST /v1/web/fetch` միջոցով բովանդակություն հանելու համար (ստեղծվել է 05 պլանում).

- Մուտքագրում. URL + ամբողջ էջը միացնել + ձևաչափի ընտրիչը (նշել / տեքստ / HTML):
- Ներկայացրեք → fetch → render `ScrapeResult.tsx`.
- `ScrapeResult` ցուցադրում է markdown նախադիտումը + հումքի միացում:
- Գլխարկ՝ եթե պատասխան մարմին >** 256 KB** , UI ցույց է տալիս `(truncated, view raw)` և բացվում է հում Մոնակոյի մոդալով (D21):
- Մետատվյալների վահանակ՝ մատակարար (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search), ուշացում, ծախս, պատասխանի չափ, հղումների քանակը:
- Օգտագործում է `useScrapeFetch.ts` կեռիկ:

### Համեմատել ներդիր

Գործում է նույն query/URL մինչև** Զուգահեռաբար 4 պրովայդեր** (D22):

- Կողք կողքի սյունակներ յուրաքանչյուր մատակարարի համար:
- Չափումներ՝ ուշացում, ծախս, արդյունքների քանակ, պատասխանի չափ:
- URL համընկնման հաշվարկ որոնման համար (համօգտագործվող URLs ի քանակն ընդդեմ նախնական արդյունքի):
- Զանգում է `POST /v1/search` (որոնում) կամ `POST /v1/web/fetch` (գրում) յուրաքանչյուր մատակարարի համար:

## Մատակարարների կատալոգ

`ProviderCatalog.tsx` ներկայացնում է `GET /api/search/providers` ից մատակարարների ամբողջական ցանկը (ընդլայնված է F4-ում՝ ներառելով առբերման մատակարարներին).

| `kind` | `"search"` (24 մատակարար) կամ `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-որոնում, զուգահեռ որոնում, enable-search) |

Կարգավիճակն է** ստացված պահանջի ժամանակ** ստուգելով, թե արդյոք առկա են հավատարմագրեր, և արդյոք բոլոր ստեղները ներկայումս սառեցման փուլում են:

`codex-search` (Codex Վեբ Որոնումը) չունի սեփական բանալի. այն կրկին օգտագործում է միացված Codex (ChatGPT) հաշիվը, ուստի յուրաքանչյուր որոնում ծախսում է ChatGPT բաժանորդագրության քվոտան և տևում է մոտ 10–40 վրկ: Այն աշխատում է, երբ հարցումն այն անվանում է. ավտոմատ ընտրությանը անհրաժեշտ է `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` հատկանիշի դրոշակ (կանխադրված անջատված):

## Backend Փոփոխություններ

Այս հատկանիշի համար անհրաժեշտ էր միայն մեկ հետին պլանի փոփոխություն.

### Ընդլայնված `GET /api/search/providers`

`src/app/api/search/providers/route.ts` տարածվել է հետևյալի վրա.

- Ներառեք յուրաքանչյուր առբերման մատակարար (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`, `keenable-search`) զանգվածում:
- Ավելացնել `kind: "search" | "fetch"` յուրաքանչյուր կետին:
- Ավելացրեք `status: "configured" | "missing" | "rate_limited"` որը ստացվում է կենդանի հավատարմագրման վիճակից:
- Պահպանեք հետընթաց համատեղելիությունը — գոյություն ունեցող դաշտերը (`id`, `name` և այլն) անփոփոխ:
