> **Ճշմարտության աղբյուր՝** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/` և
> `src/app/(dashboard)/dashboard/plugins/`
> **Վերջին թարմացումը՝** 2026-06-28 — v3.8.40

OmniRoute-ը տրամադրվում է WordPress-ի ոճով փլագինային համակարգով։ Փլագիններն ինքնաբավ
պանակներ են, որոնցից յուրաքանչյուրն ունի `plugin.json` մանիֆեստ և մուտքային ֆայլ, որոնք կցվում
են հարցումների մշակման շղթային (`onRequest` / `onResponse` / `onError`) և
կենսացիկլի իրադարձություններին (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)։

**Փլագինների շուկան** այդ համակարգի վրա կառուցված հայտնաբերման շերտն է։ Այն
տրամադրում է տեղադրվող փլագինների զննարկելի կատալոգ։ Լռելյայնորեն կատալոգը
փոքր ներկառուցված սկզբնական ռեեստր է․ օպերատորը կարող է այն ուղղորդել դեպի հատուկ հեռավար
ռեեստրի URL, որի դեպքում հարցումը պաշտպանվում է DNS լուծող SSRF պաշտպանիչով
(տե՛ս [Անվտանգություն](#security))։

Փլագինների յուրաքանչյուր երթուղի **հասանելի է միայն loopback-ից** (Մակարդակ 1 — `LOCAL_ONLY`)․ փլագինները
բեռնում և կատարում են կոդը դուստր գործընթացներում, ուստի երթուղիները հասանելի չեն
ոչ loopback սկզբնաղբյուրից՝ անկախ նույնականացումից։ Տե՛ս
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)։

## Ինչպես է այն համապատասխանում Together

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **Ռեեստրի շերտ** — `src/lib/plugins/marketplace.ts`. ցուցակագրում/որոնում է կատալոգը՝ ցանկացած ձախողման դեպքում վերադառնալով սերմերի գրանցամատյան:
- **Կյանքի ցիկլի շերտ** — `src/lib/plugins/manager.ts` (`pluginManager` singleton). տեղադրել, թարմացնել, ակտիվացնել, ապաակտիվացնել, տեղահանել, սկանավորել, գործարկել բեռնումը:
- **Դրսեւորվող շերտ** — `src/lib/plugins/manifest.ts`. Zod սխեման + լռելյայն է `plugin.json` համար:
- **Սկաներ** — `src/lib/plugins/scanner.ts`. հայտնաբերում է պլագիններ սկավառակի վրա plugin գրացուցակի տակ:
- **Բեռնիչ** — `src/lib/plugins/loader.ts`. յուրաքանչյուր պլագին ստեղծում է առանձին Node.js երեխայի գործընթացում և բրոքերները կապում են զանգերը IPC վրա: Երեխան ավազատուփ չէ (տես ստորև՝ «Plugin execution մեկուսացում»):

## Շուկայի կատալոգ

`listMarketplacePlugins()`-ը (`src/lib/plugins/marketplace.ts`) վերադարձնում է
`MarketplaceEntry` օբյեկտների ցուցակ․

| Դաշտ          | Տեսակ    | Նշումներ                                       |
| ------------- | -------- | ---------------------------------------------- |
| `name`        | string   | kebab-case ձևաչափով փլագինի անուն              |
| `version`     | string   | semver                                         |
| `description` | string   | Կարճ ամփոփագիր                                 |
| `author`      | string   | Հեղինակ / կազմակերպություն                     |
| `license`     | string   | SPDX-ի ոճով արտոնագրի նույնացուցիչ             |
| `downloadUrl` | string   | Աղբյուրի ներբեռնման URL (կարող է դատարկ լինել) |
| `repository`  | string?  | Ռեպոզիտորիայի ոչ պարտադիր URL                  |
| `tags`        | string[] | Որոնման/զտման պիտակներ                         |
| `downloads`   | number   | Ներբեռնումների քանակ                           |
| `rating`      | number   | 0–5                                            |
| `verified`    | boolean  | Արդյոք գրառումը նշված է որպես հաստատված        |
| `lastUpdated` | string   | ISO-ին մոտ ձևաչափով ամսաթվի տող                |

Երբ հատուկ ռեեստրի URL կազմաձևված չէ, կատալոգը ներկառուցված
`SEED_REGISTRY`-ն է (ներկայում՝ `request-logger`, `rate-limiter`, `cost-tracker` և
`theme-manager`)։ Սկզբնական ռեեստրը միշտ հասանելի է․ եթե կազմաձևված հեռավար
ռեեստրն անհասանելի է, վերադարձնում է `200`-ից տարբեր կարգավիճակ կամ վերադարձնում է չճանաչված
մարմին, `listMarketplacePlugins()`-ը գրանցում է նախազգուշացում և անցնում սկզբնական ցուցակին։

> Նշում․ շուկայի **կատալոգը** (զննում/որոնում) ամբողջությամբ կապակցված է, սակայն
> կատալոգից մեկ սեղմումով շուկայական **տեղադրումը** դեռ իրականացված չէ․
> շուկայի գրառման համար կառավարման վահանակի «Տեղադրել» կոճակը ներկայում ցուցադրում է
> «շուտով հասանելի կլինի» ծանուցում։ Այս պահին տեղադրումը կատարվում է տեղային ուղու տեղադրման
> հոսքի (`POST /api/plugins`) և սկավառակի վրա հայտնաբերման (`POST /api/plugins/scan`) միջոցով։

## REST API

Բոլոր վերջնակետերը պահանջում են կառավարման հեղինակություն (`requireManagementAuth`)** և** են loopback-ը միայն — `/api/plugins` և `/api/plugins/` թվարկված են `LOCAL_ONLY_API_PREFIXES` ում (`src/server/authz/routeGuard.ts`):

| Վերջնակետ                        | Մեթոդ  | Նկարագրություն                                                  |
| -------------------------------- | ------ | --------------------------------------------------------------- |
| `/api/plugins`                   | GET    | Ցուցակեք տեղադրված պլագինները (ըստ ցանկության `?status=` ֆիլտր) |
| `/api/plugins`                   | POST   | Տեղադրեք plugin plugin աղբյուրների գրացուցակից                  |
| `/api/plugins/scan`              | POST   | Սկանավորեք հավելումների գրացուցակը և գրանցեք նոր պլագիններ      |
| `/api/plugins/marketplace`       | GET    | Ցուցակ շուկայի կատալոգի գրառումները                             |
| `/api/plugins/[name]`            | GET    | Ստացեք տեղադրված plugin մանրամասները                            |
| `/api/plugins/[name]`            | DELETE | Տեղահանել plugin                                                |
| `/api/plugins/[name]/activate`   | POST   | Ակտիվացնել (բեռնել + ռեգիստրի կեռիկներ)                         |
| `/api/plugins/[name]/deactivate` | POST   | Ապաակտիվացնել (կրակել `onDeactivate`, չգրանցել կեռիկները)       |
| `/api/plugins/[name]/config`     | GET    | Ստացեք plugin config + config schema                            |
| `/api/plugins/[name]/config`     | PUT    | Թարմացրեք հավելվածի կազմաձևը (վավերացված է սխեմայի համաձայն)    |

`GET /api/plugins` `status` զտիչը ընդունում է `installed` / `active` / `inactive` / `error` ից մեկը: Անվավեր արժեքը վերադարձնում է `400`:

### Ցուցակեք տեղադրված պլագինները

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### Տեղադրեք տեղական ճանապարհից

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` պետք է լինի ան** բացարձակ** ուղին դեպի գրացուցակ** plugin աղբյուրների գրացուցակի ներսում** `plugin-sources` plugin արմատի կողքին, այնպես որ `~/.omniroute/plugin-sources/` լռելյայն, կամ `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` երբ այդ փոփոխականը դրված է (`getPluginSourcesDir()` in `src/lib/plugins/installSource.ts`): Սկզբում պատճենեք կամ կլոնավորեք հավելվածը այնտեղ: Տեղադրումը մերժվում է `400` ով, երբ ուղին պարունակում է `..` կամ զրոյական բայթ, գտնվում է այդ գրացուցակից դուրս, լուծվում է դրանից դուրս՝ symlink-ի միջոցով, պարունակում է symlink, որի թիրախը գտնվում է դրանից դուրս, կամ երբ գրացուցակը գոյություն չունի: Աղբյուրի գրացուցակը պետք է պարունակի վավեր `plugin.json` (կամ լինի մեկի ծնող): Հաջողության դեպքում պատասխանը `201` է տեղադրված պլագինների շարքով:

Ի տարբերություն այլ պլագինների երթուղիների, այս մեկը պահանջում է կառավարման հավատարմագիր (վահանակի նիստ կամ կառավարման շրջանակով API բանալի) նույնիսկ այն դեպքում, երբ մուտքն անջատված է (`requireLogin=false`). կոդի տեղադրումը երբեք անանուն գործողություն չէ:

### Թերթիր շուկան

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### Թարմացրեք plugin-ի կազմաձևը

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` վավերացնում է յուրաքանչյուր տրամադրված արժեքը հավելյալի `configSchema` ի համեմատ (հայտարարված է մանիֆեստում). `number` դաշտերը հարգում են `min`/`max`, `select` դաշտերը պետք է համապատասխանեն հայտարարված `enum` ին: Սխեմայում չներկայացված բանալիները թույլատրվում են:

## Կազմաձևում

### Փլագինների գրացուցակ

Փլագինները գտնվում են OmniRoute-ի տվյալների գրացուցակի ներքո․

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (կամ այն ֆայլը, որին հղվում է manifest.main-ը)
```

`getDefaultPluginDir()`-ը (`src/lib/plugins/scanner.ts`) այդ գրացուցակը որոշում է
երեք քայլով․

1. **`OMNIROUTE_PLUGINS_DIR`**, երբ այն սահմանված է՝ օգտագործվում է բառացիորեն՝ անկախ `HOME`-ի արժեքից։ Սա
   Docker/K8s-ի համար նախատեսված բացահայտ կարգավորիչն է, որտեղ փլագինների ծառը bind-mount-ով միացվում է մի ուղու,
   որը սովորաբար որևէ կապ չունի կոնտեյների տնային գրացուցակի հետ (#11827)։
2. `<home>/.omniroute/plugins`, որտեղ `<home>`-ը վերցվում է `HOME` / `USERPROFILE`
   միջավայրի փոփոխականներից։
3. `/tmp/.omniroute/plugins`, երբ գործընթացն ընդհանրապես տնային գրացուցակ չի արտահանում։

Որոշված գրացուցակը մեկնարկի ժամանակ մեկ անգամ գրանցվում է մատյանում որպես `scanner.dir_resolved`՝ նշելով
գերակշռած մուտքային արժեքը (`OMNIROUTE_PLUGINS_DIR`, `home` կամ `no-home-fallback`)։ Այսպիսով՝ այն image-ը,
որը լռելյայն անցնում է 3-րդ քայլին, հայտնում է այդ մասին՝ պարզապես փլագինների դատարկ ցանկ հաղորդելու փոխարեն։
`POST /api/plugins/scan`-ը հայտնաբերում է այնտեղ գտնվող ցանկացած ենթագրացուցակ, որը պարունակում է վավեր
`plugin.json`, և գրանցում է այն։ Նույն գրացուցակն այն արմատն է, որի մեջ
`pluginManager.install()`-ը պատճենում է փլագինները, ուստի վերասահմանումը հայտնաբերումն ու
տեղադրումը տեղափոխում է միասին։

> **`OMNIROUTE_PLUGINS_DIR`-ը `OMNIROUTE_PLUGIN_PATH` չէ։** Վերջինս կարդացվում է միայն
> CLI հրամանների փլագինների բեռնիչի (`bin/cli/plugins.mjs`) կողմից՝ `omniroute-cmd-*` npm
> փաթեթները գտնելու համար, որոնք ավելացնում են `omniroute` ենթահրամաններ․ այն որևէ ազդեցություն չունի այստեղ
> նկարագրված runtime սկանավորիչի վրա։ Այդ մասի մասին տե՛ս [PLUGINS.md](./PLUGINS.md)։

### Marketplace-ի հատուկ registry URL

Marketplace կատալոգի աղբյուրը կարդացվում է `pluginMarketplaceUrl` կարգավորումից
(`src/lib/plugins/marketplace.ts`-ը կարդում է `settings.pluginMarketplaceUrl`)։ Երբ
այն սահմանված է որպես `http(s)` URL, `listMarketplacePlugins()`-ը հարցում է կատարում այդ URL-ին և ընդունում
է կա՛մ վերին մակարդակի JSON գրառումների զանգված, կա՛մ `plugins` զանգվածով օբյեկտ։
Տողային `name` չունեցող գրառումները զտվում են։ Երբ այն սահմանված չէ (կամ երբ հարցումը
չի անցնում SSRF պաշտպանությունը / վերադարձնում է անվավեր պատասխան), օգտագործվում է ներկառուցված սկզբնական registry-ն։

Կառավարման վահանակի «Marketplace» ներդիրը ցուցադրում է այս URL-ի համար նախատեսված դաշտ (հետ է կարդացվում
`GET /api/settings`-ից)։

> Իրականացման նշում․ կառավարման վահանակի «Save» գործողությունն ուղարկում է
> `pluginMarketplaceUrl`-ը դեպի `PATCH /api/settings`։ Այս տեքստը գրելու պահին այդ
> բանալին հայտարարված չէ `updateSettingsSchema`-ում
> (`src/shared/validation/settingsSchemas.ts`), ուստի, նախքան դրա վրա հույս դնելը, ստուգեք պահպանումը ձեր
> թողարկման մեջ։ **Ընթերցման** ուղին (`getSettings()` →
> `listMarketplacePlugins()`) հաշվի է առնում բանալին, հենց որ այն առկա է կարգավորումների
> պահոցում։

## Անվտանգություն

### Միայն երթուղիների մակարդակի — հանգույց

Փլագինները գործարկում են կոդը ծնված երեխայի գործընթացներում, ուստի ամբողջ `/api/plugins` մակերեսը դասակարգվում է `LOCAL_ONLY` (1-ին մակարդակ): Loopback-ի կիրառումը գործում է անվերապահորեն** առաջ** ցանկացած իսկության ստուգում, այնպես որ կառավարման արտահոսքի նշանը, որը թունելի վրայով հասնում է տուփին, դեռևս չի կարող տեղադրել, ակտիվացնել կամ հեռացնել փլագինը: Տես [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) և Hard Rules #15 / #17:

### Շուկայի ռեեստրի SSRF պահակ

Մաքսային գրանցամատյան URL հարձակվողի վրա ազդող կոնֆիգուրացիա է, ուստի նախքան այն բերելը, `listMarketplacePlugins()` այն անցնում է երկու շերտով.

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - Մերժում է այն ամենը, ինչը `http:` / `https:` չէ:
   - Մերժում է բառացի private/loopback/link-local/ULA հյուրընկալողներին (IPv4** և** IPv6, ներառյալ IPv4-mapped) կանոնական `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) միջոցով։
   - Լուծում է** երկուսն էլ** `A` եւ `AAAA` արձանագրում եւ մերժում է, եթե** ցանկացած** լուծված հասցեն մասնավոր է — որը փակում է public-hostname → private-IP շրջանցումը:
   - **Չհաջողվեց փակել** DNS լուծման ձախողումը մերժում է URL ը:
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`). Վերստին կիրառում է բացառապես հանրային URL պահակը բեռնման պահին և** արգելափակում է վերահղումները** (չկա հանրային → private `30x` pivot):

URL, որը ձախողում է որևէ շերտ, չի ընդհատում հարցումը — շուկան լուռ ընկնում է ներկառուցված սերմերի գրանցամատյան և գրանցում է նախազգուշացում:

> Այս պահակը կարծրացվել է PR #3774 ում հատուկ A + AAAA լուծելու և IPv4-only չեկի փոխարեն կանոնական `isPrivateHost` օգտագործելու համար:

### Plugin-ի կատարման մեկուսացում

> **Փլագինները ավազապատված չեն:** Երեխան սովորական Node.js պրոցես է, որն աշխատում է որպես OmniRoute օգտատեր, առանց VM համատեքստի և Node.js թույլտվության դրոշների, այնպես որ plugin կոդը կարող է կարդալ և գրել ցանկացած ֆայլ, որը օգտվողը կարող է, գործարկել ծրագրեր և հասնել ցանց: `requires.permissions` միայն որոշում է, թե ինչ միջավայրի փոփոխականներ է ստանում երեխան. մյուս թույլտվությունները չեն կիրառվում: Տեղադրեք միայն պլագինները, որոնց վստահում եք: Ստորև բերված գործընթացի սահմանը պարունակում է վթարներ և կախումներ. դա անվտանգության սահման չէ:

- **Գործընթացի մեկուսացում** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ստեղծում է յուրաքանչյուր փլագին առանձին Node.js երեխայի գործընթացում և հաղորդակցվում IPC միջոցով: Կեռիկի զանգերն ունեն ժամանակի վերջ `SIGTERM` → `SIGKILL` էսկալացիայով:
- **Env թույլտվությունների ցուցակ** — երեխան ստանում է միայն շրջակա միջավայրի փոփոխականների թույլատրելի շարքը. ավելի լայն հավաքածուն տրվում է միայն այն դեպքում, երբ մանիֆեստը պահանջում է `env` թույլտվություն:
- **Տեղադրեք աղբյուրի պարունակությունը** — `POST /api/plugins` կարդում է միայն plugin-ի աղբյուրների գրացուցակից (տես «Տեղադրել տեղական ուղուց»). ուղին կանոնականացված է `realpath` ով, պետք է խստորեն մնա այդ գրացուցակի ներսում, և սկզբնաղբյուր ծառը, որը կրում է խորհրդանշական հղում, որը խուսափում է դրանից, մերժվում է նախքան որևէ բան պատճենելը:
- **Ուղու զսպում** — install/upgrade/uninstall պնդում է, որ plugin-ի գրացուցակը և `manifest.main` լուծում են** ներսում** կառավարվող պլագինի արմատը ցանկացած պատճենից կամ ռեկուրսիվ ջնջումից առաջ (պաշտպանում է կեղծված DB ուղիներից և `../` անցումից `manifest.main` ում): Ակտիվացումը լուծում է symlinks-ը `realpath` միջոցով և հրաժարվում է բեռնել մուտքի կետը, որը դուրս է գալիս plugin գրացուցակից:
- **Ընտրովի ամբողջականության քորոց** — a manifest-ը կարող է հայտարարել `integrity` (`sha256-<base64>`, SRI ձևաչափ) դաշտ: Երբ առկա է, բեռնիչը ստուգում է մուտքի ֆայլի հեշը բեռնման ժամանակ և հրաժարվում է ակտիվացնել անհամապատասխանության դեպքում: Սա ընտրովի է կեղծման հայտնաբերում,** ոչ** անվտանգության սահման. այն չի սահմանափակում այն, ինչ կարող է անել բեռնված փլագինը:
- **Կեռիկներում հաճախորդի հավատարմագրեր չկան** — համատեքստում, որը փոխանցվել է `onRequest`, `onResponse` և `onError` հանվել են `authorization`, `x-api-key`, `proxy-authorization` և `cookie` վերնագրերը, իսկ API բանալի գրառումը չունի առանցքային արժեք (`redactPluginContext()` `src/lib/plugins/hooks.ts` ում):

## Մանիֆեստ (`plugin.json`)

Վավերացված է `PluginManifestSchema` (`src/lib/plugins/manifest.ts`):

| Դաշտ               | Տեսակ     | Նշումներ                                                                  |
| ------------------ | --------- | ------------------------------------------------------------------------- |
| `name`             | լար       | Պահանջվում է; քյաբաբ-պատյան (`^[a-z0-9-]+$`), 1–100 char                  |
| `version`          | լար       | Պահանջվում է; սեմվեր (`MAJOR.MINOR.PATCH`)                                |
| `description`      | լար?      | ≤ 500 նիշ                                                                 |
| `author`           | լար?      | ≤ 200 նիշ                                                                 |
| `license`          | լար?      | Կանխադրված է `MIT` ին                                                     |
| `main`             | լար?      | Մուտքի ֆայլ; լռելյայն է `index.js`                                        |
| `source`           | թվա՞մ     | `local` \| `marketplace` (կանխադրված է `local`)                           |
| `tags`             | լար[]?    | Որոնել պիտակներ                                                           |
| `requires`         | օբյեկտ?   | `{ omniroute?, permissions[] }`                                           |
| `hooks`            | օբյեկտ?   | Բուլյաններ, որոնք հայտարարում են, թե որ կեռիկներն է իրականացնում plugin-ը |
| `skills`           | օբյեկտ[]? | Կամընտիր հմտությունների սահմանումներ                                      |
| `enabledByDefault` | բուլյան?  | Ավտոմատ ակտիվացնել տեղադրման ժամանակ                                      |
| `configSchema`     | օբյեկտ?   | Կազմաձևման դաշտերի քարտեզ (`string`/`number`/`boolean`/`select`)          |
| `integrity`        | լար?      | Ընտրովի `sha256-<base64>` մուտքի ֆայլի փին                                |

Թույլտվությունները վերցված են enum `network` / `file-read` / `file-write` / `env` / `exec`-ից: Միայն `env` ունի գործարկման ժամանակի էֆեկտ (երեխայի համար շրջակա միջավայրի փոփոխականների թույլտվության մի փոքր ավելի մեծ ցուցակ); մյուսները հայտարարագրեր են և չեն կատարվում։

## Կենսացիկլի հոսք

```
install (POST /api/plugins, ուղի)
  → սկանավորել/վավերացնել մանիֆեստը → պատճենել staging տարածք → համոզվել, որ main-ը գրացուցակի ներսում է
  → ատոմային վերանվանում դեպի ~/.omniroute/plugins/<name> → ավելացնել տող DB-ում
  → կանչել onInstall → եթե enabledByDefault է՝ activate

activate (POST /api/plugins/{name}/activate)
  → realpath-ի պատկանելիության ստուգում → loadPlugin() (գործարկել ենթապրոցես)
  → գրանցել հայտարարված hook-երը → status = "active" → կանչել onActivate

deactivate (POST /api/plugins/{name}/deactivate)
  → կանչել onDeactivate (գրանցումից հանելուց ԱՌԱՋ) → գրանցումից հանել hook-երը
  → ավարտել ենթապրոցեսը → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → եթե ակտիվ է՝ deactivate → կանչել onUninstall
  → պատկանելիության ստուգմամբ ռեկուրսիվորեն ջնջել plugin-ի գրացուցակը → ջնջել տողը DB-ից
```

`install`-ի կրկնակի գործարկումը մի գրացուցակի համար, որի մանիֆեստի տարբերակը **խստորեն
ավելի նոր է**, քան տեղադրված տարբերակը, ավտոմատ թարմացում է կատարում (մաքուր վերատեղադրում․ կազմաձևումը
վերակայվում է լռելյայն արժեքներին)։ Նույն կամ ավելի հին տարբերակը մերժվում է։

| --------------- | ------- | ----------------------------------------------------------- |
| `id`            | TEXT PK | UUID                                                        |
| `name`          | TEXT    | Եզակի                                                       |
| `version`       | TEXT    | semver․ լռելյայն՝ `1.0.0`                                   |
| `description`   | TEXT    | Ոչ պարտադիր                                                 |
| `author`        | TEXT    | Ոչ պարտադիր                                                 |
| `license`       | TEXT    | Լռելյայն՝ `MIT`                                             |
| `main`          | TEXT    | Մուտքային ֆայլ․ լռելյայն՝ `index.js`                        |
| `source`        | TEXT    | Լռելյայն՝ `local`                                           |
| `tags`          | TEXT    | JSON զանգված․ լռելյայն՝ `[]`                                |
| `status`        | TEXT    | `installed` \| `active` \| `inactive` \| `error`            |
| `enabled`       | INT     | 0/1․ լռելյայն՝ 0                                            |
| `manifest`      | TEXT    | Ամբողջական մանիֆեստի JSON-ը                                 |
| `config`        | TEXT    | JSON․ լռելյայն՝ `{}`                                        |

| `hooks`         | TEXT    | Հայտարարված hook-երի անունների JSON զանգված․ լռելյայն՝ `[]` |
| `permissions`   | TEXT    | JSON զանգված․ լռելյայն՝ `[]`                                |

(`090_plugin_metrics.sql`, `091_plugin_analytics.sql`)։
