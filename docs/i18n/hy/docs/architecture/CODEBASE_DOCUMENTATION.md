>
> Բարձր մակարդակի ճարտարապետական գծապատկերների և յուրաքանչյուր ենթահամակարգի հիմքում ընկած հիմնավորումների համար կարդացեք
> [ARCHITECTURE.md](./ARCHITECTURE.md)։ Առանձին ենթահամակարգերի մանրամասն նկարագրությունների համար
> (Auto Combo, MCP սերվեր, A2A սերվեր, Skills, Memory, Cloud Agents, Resilience,
> Compression և այլն) տե՛ս այս `docs/` գրացուցակում դրանց նվիրված ֆայլերը։

Այս ֆայլը նկարագրում է **այն, ինչ այսօր առկա է շտեմարանում**, որպեսզի նոր ինժեները
կարողանա կողմնորոշվել ծառում, հասկանալ կատարման ժամանակի շերտավորումը և իմանալ՝ որտեղ ավելացնել կոդը՝
առանց նոր մոդուլներ հորինելու։

| Բաղադրիչ                    | Ընտրություն                                                                                                                                 |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Վեբ շրջանակ                 | **Next.js 16** (App Router, ինքնուրույն ելքային տարբերակ, առանց գլոբալ միջնորդաշերտի)                                                       |
| Լեզու                       | **TypeScript 6.0+** — թիրախ՝ `ES2022`, `module: esnext`, `moduleResolution: bundler`, `strict: false`                                       |
| Կատարման միջավայր           | **Node.js** `>=22.22.2 <23` կամ `>=24.0.0 <27` (պարտադրվում է `engines` + `SUPPORTED_NODE_RANGE` միջոցով)                                   |
| Տվյալների բազա              | **SQLite**՝ `better-sqlite3`-ի միջոցով (միաեզակի օրինակ, WAL մատենավարում)                                                                  |
| Սեղանադիր հավելված          | **Electron 41** + `electron-builder` 26.10 (առանձին աշխատանքային տարածք՝ `electron/`)                                                       |
| Թեստեր                      | **Node-ի ներկառուցված թեստային գործարկիչ** (մոդուլային/ինտեգրացիոն), **Vitest** (MCP, autoCombo, քեշ), **Playwright** (e2e + protocols-e2e) |
| Կառուցում                   | Next.js-ի ինքնուրույն տարբերակ՝ `scripts/build/build-next-isolated.mjs`-ի միջոցով                                                           |
| Լինթինգ/ձևաչափում           | ESLint-ի հարթ կազմաձև + Prettier (`lint-staged`՝ Husky-ի նախնական կոմիթի միջոցով)                                                           |
| Մոդուլային համակարգ         | Ամենուր ESM (`"type": "module"`)                                                                                                            |
| Կառավարման վահանակի միջերես | **Tailwind CSS 4** + նախագծում ներառված **Keak CI UI Kit** (`packages/ui-kit`), Lucide պատկերակներ — տե՛ս `DESIGN_SYSTEM.md`                |
| Աշխատանքային տարածքներ      | npm աշխատանքային տարածքներ — `open-sse`, `packages/browser-pool`, `packages/ui-kit`                                                         |

Ուղիների այլանուններ (`tsconfig.json`)՝

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`
- `@omniroute/ui-kit` → `packages/ui-kit/src`, `@omniroute/ui-kit/*` → `packages/ui-kit/src/*`

Լռելյայն HTTP պորտ՝ **`20128`** (API-ն և կառավարման վահանակն օգտագործում են նույն գործընթացը)։ Տվյալների
պանակը սահմանվում է `DATA_DIR` միջավայրի փոփոխականով, իսկ լռելյայն արժեքն է `~/.omniroute/`։

### 3.1 `src/app/` — App Router

App Router-ը ներկայացնում է ինչպես վահանակի UI-ն, այնպես էլ հանրային/կառավարման HTTP API-ն։
**Գլոբալ middleware չկա** — ընդհատումը կատարվում է ըստ առանձին երթուղու։

Վերին մակարդակի սեգմենտները `src/app/`-ի ներքո՝

| Ճանապարհ                                                                      | Նպատակ                                                 |
| ----------------------------------------------------------------------------- | ------------------------------------------------------ |
| `api/`                                                                        | Բոլոր HTTP API երթուղիները (տե՛ս բացադրությունը ստորև) |
| `a2a/`                                                                        | A2A JSON-RPC 2.0 վերջնակետ (`POST /a2a`)               |
| `.well-known/agent.json/`                                                     | A2A Agent Card հայտնաբերման փաստաթուղթ                 |
| `(dashboard)/`                                                                | Վահանակի UI (երթուղիների խումբ, առանց URL նախածանցի)   |
| `auth/`, `login/`, `forgot-password/`, `callback/`                            | Նույնականացման հոսքեր                                  |
| `landing/`                                                                    | Մարքեթինգային/landing էջ                               |
| `docs/`                                                                       | Ներկառուցված API փաստաթղթերի դիտիչ                     |
| `status/`, `maintenance/`, `offline/`                                         | Գործառնական էջեր                                       |
| `privacy/`, `terms/`                                                          | Իրավական էջեր                                          |
| `400/`, `401/`, `403/`, `408/`, `429/`, `500/`, `502/`, `503/`                | Ստատիկ սխալների էջեր                                   |
| `error.tsx`, `global-error.tsx`, `not-found.tsx`, `forbidden/`, `loading.tsx` | Ֆրեյմվորկի սխալների/բեռնման boundary-ներ               |
| `layout.tsx`, `page.tsx`, `globals.css`, `manifest.ts`                        | Արմատային shell                                        |

## 9. Հարցման pipeline (Ամփոփում)

![Հարցման pipeline (/v1/chat/completions)](../diagrams/exported/request-pipeline.svg)

> Աղբյուր՝ [diagrams/request-pipeline.mmd](../diagrams/request-pipeline.mmd)

```
Client request
  → /v1/chat/completions (route.ts)
     CORS preflight check
     Zod validation (chatCompletionsSchema in shared/validation/schemas.ts)
     Auth (extractApiKey + isValidApiKey OR requireManagementAuth)
     Route authorization (src/server/authz/pipeline.ts)
     API-key policy (src/shared/utils/apiKeyPolicy.ts; enforced on the selected path)
     Guardrails (PII masker, prompt injection, vision bridge)
  → handleChatCore() (open-sse/handlers/chatCore.ts)
     Cache check (semantic + read cache)
     Rate limit (rateLimitManager, accountSemaphore)
     Combo routing (if model resolves to a combo)
       resolveComboTargets (open-sse/services/combo.ts) → per-target dispatch
     translateRequest()  (open-sse/translator/request/*)
     getExecutor(providerId).execute()  (open-sse/executors/*)
       fetch upstream → retry/backoff via accountFallback
     translateResponse() (open-sse/translator/response/*)
     SSE stream OR JSON response
     If Responses API: TransformStream via open-sse/transformer/responsesTransformer.ts
  → Compliance audit (src/lib/compliance/)
  → Response to client
```

## 10. Ինչպես ներդրում կատարել

### Ավելացնել նոր մատակարար

1. Գրանցեք `src/shared/constants/providers.ts`-ում (բեռնման ժամանակ ստուգվում է Zod-ի միջոցով)։
2. Եթե հատուկ տրամաբանություն է պահանջվում, ավելացրեք կատարիչ `open-sse/executors/`-ում
   (`BaseExecutor`-ի ընդլայնմամբ)։
3. Եթե այն չի աշխատում OpenAI ձևաչափով, ավելացրեք թարգմանիչ `open-sse/translator/`-ում։
4. Եթե հիմնված է OAuth-ի վրա, ավելացրեք կազմաձևում `src/lib/oauth/providers/` և
   `src/lib/oauth/services/` ուղիներում։
5. Գրանցեք մոդելները `open-sse/config/providerRegistry.ts`-ում (կամ ձևաչափին հատուկ
   գրանցամատյանում՝ `open-sse/config/`-ի ներքո)։
6. Գրեք թեստեր `tests/unit/`-ում։

### Ավելացնել նոր API երթուղի

1. Ստեղծեք `src/app/api/your-route/route.ts`։
2. Հետևեք այս ձևանմուշին՝ CORS → հարցման մարմնի ստուգում Zod-ով → նույնականացում → մշակողին փոխանցում։
3. Եթե հարցման կառուցվածքը նոր է, ավելացրեք Zod սխեման `src/shared/validation/schemas.ts`-ում։
4. Եթե նախատեսված է միայն կառավարման համար, ավելացրեք ուղին `src/shared/constants/publicApiRoutes.ts`-ում
   (հանրային API մակերեսի արգելացանկ)։
5. Ավելացրեք թեստեր `tests/unit/`-ում։
6. Թարմացրեք `docs/reference/API_REFERENCE.md`-ը և `docs/openapi.yaml`-ը։

### Ավելացնել նոր DB մոդուլ

1. Ստեղծեք `src/lib/db/yourModule.ts` և ներմուծեք `getDbInstance()`-ը `./core.ts`-ից։
2. Արտահանեք CRUD ֆունկցիաներ ձեր տիրույթի համար։
3. Նոր աղյուսակների դեպքում ավելացրեք միգրացիա `src/lib/db/migrations/`-ում՝ հաջորդական
   համարակալմամբ, իդեմպոտենտ և տրանզակցիոն։
4. Ներմուծողներն օգտագործում են ուղիղ ներմուծումներ `@/lib/db/yourModule`-ից (առանց barrel-ի՝ հին `localDb.ts` վերաարտահանման շերտը հեռացվել է)։
5. Ավելացրեք թեստեր `tests/unit/`-ում։

### Ավելացնել նոր MCP գործիք

3. Գրանցեք գործիքը `open-sse/mcp-server/server.ts`-ում։
4. Ավելացրեք թեստեր `open-sse/mcp-server/__tests__/`-ում։
5. Թարմացրեք [MCP-SERVER.md](../frameworks/MCP-SERVER.md)-ը։

## 11. Պայմանավորվածություններ

- **Կոդի ոճ**: 2 բացատով նահանջ, կրկնակի չակերտներ, 100 նիշ լայնություն, կետ-ստորակետեր,
  `es5` վերջնային ստորակետեր՝ կիրառվում է Prettier-ի կողմից՝ `lint-staged`-ի միջոցով։
- **Ներմուծումներ**: արտաքին → ներքին (`@/`, `@omniroute/open-sse`) → հարաբերական։
- **Անվանումներ**: ֆայլերը՝ `camelCase` կամ `kebab-case`, բաղադրիչները՝ `PascalCase`,
  հաստատունները՝ `UPPER_SNAKE`։
- **ESLint**: `no-eval`, `no-implied-eval`, `no-new-func` = `error` ամենուրեք,
  `no-explicit-any` = `warn`՝ `open-sse/`-ում և `tests/`-ում, իսկ այլուր՝ error։
- **TypeScript**: `strict: false` (ժառանգված մոտեցում)։ Մոդուլների սահմանների համար
  տիպերի ենթադրությունից գերադասեք բացահայտ տիպերը։
- **Տվյալների բազա**: երբեք մի գրեք անմշակ SQL երթուղիներում կամ մշակողներում՝ միշտ աշխատեք
  `src/lib/db/` մոդուլների միջոցով։ Երբեք մի կատարեք barrel ներմուծում՝ ուղղակիորեն օգտագործեք հատուկ `src/lib/db/*` մոդուլները։
- **DB էությունների տիպավորում (#3512)**: ֆունկցիան, որը գրում կամ կարդում է DB աղյուսակի
  տողի կառուցվածքը, պետք է ընդունի/վերադարձնի այդ աղյուսակի սյունակները 1:1 արտացոլող
  անվանված TS ինտերֆեյս, այլ ոչ թե `any` կամ կանչի վայրում սահմանված անանուն ներկառուցված տիպ։ Տեղադրեք
  ինտերֆեյսը ֆունկցիայի կողքին (օրինակ՝ `export interface UsageEntry`-ը
  `src/lib/usage/usageHistory.ts`-ում՝ `saveRequestUsage`-ից վերև), առանձին
  դաշտերը պահեք ոչ պարտադիր/nullable, երբ տարբեր գրողներ աստիճանաբար են լրացնում տողը,
  և `any`-ի փոխարեն նախընտրեք `unknown`, երբ դաշտի կառուցվածքը տարբեր է
  կանչողների միջև (փաստաթղթավորված դաշտում, օրինակ՝ `UsageEntry.tokens`-ն
  ընդունում է թե՛ մատակարարի սկզբնական կառուցվածքով օգտագործման տվյալները, թե՛ նորմալացված կառուցվածքը)։ Երբ
  ֆայլի `any`-ների քանակն այս եղանակով հասնի զրոյի, ավելացրեք այն
  `check:any-budget:t11` թույլատրվածների ցանկում (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`), որպեսզի հետընթաց հնարավոր չլինի։ Սա առաջին փուլի պայմանավորվածություն է՝
  ավելի լայն «առանց անանուն `any`-ի» մաքրումը կրկնողականորեն իրականացվում է կոդային բազայի
  մնացած մասում։
- **Սխալներ**: օգտագործեք try/catch՝ սխալների կոնկրետ տիպերով, գրանցամատյանում գրեք pino համատեքստով։ Երբեք
  լուռ մի կլանեք SSE հոսքերի սխալները․ մաքրման համար օգտագործեք ընդհատման ազդանշաններ։
- **Անվտանգություն**: երբեք մի օգտագործեք `eval()` / `new Function()` / անուղղակի eval։ Ստուգեք
  բոլոր մուտքային տվյալները Zod-ով։ Պահպանման ընթացքում գաղտնագրեք հավատարմագրերը (AES-256-GCM)։ Պահեք
  `src/shared/constants/upstreamHeaders.ts` արգելացանկը համահունչ
  մաքրման/ստուգման շերտին։
- **Commit-ներ**: Conventional Commits՝ `feat(scope): subject`։ Թույլատրված շրջանակներն են՝
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`։
- **Ճյուղեր**: նախածանցներ՝ `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`։ Երբեք commit մի կատարեք անմիջապես `main`-ում։
- **Husky**: pre-commit-ը գործարկում է `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11`, իսկ pre-push-ը՝ `check:any-budget:t11` + `check:tracked-artifacts` (արագ ստուգումներ՝ առանց `test:unit`-ի)։

## 12. Խիստ կանոններ (CLAUDE.md-ից)

1. Երբեք մի՛ commit արեք գաղտնիքներ կամ նույնականացման տվյալներ։
2. Երբեք մի՛ օգտագործեք barrel import. անմիջապես օգտագործեք համապատասխան `src/lib/db/*` մոդուլները։
3. Երբեք մի՛ օգտագործեք `eval()` / `new Function()` / անուղղակի eval։
4. Երբեք commit մի՛ արեք անմիջապես `main` ճյուղում։
5. Երբեք routes-ում մի՛ գրեք raw SQL. միշտ օգտագործեք `src/lib/db/` մոդուլները։
6. Երբեք լուռ մի՛ անտեսեք SSE հոսքերի սխալները։
7. Միշտ վավերացրեք մուտքային տվյալները Zod սխեմաներով։
8. Production կոդը փոփոխելիս միշտ ներառեք թեստեր։
9. Ծածկույթը պետք է մնա ≥ 60% (հրահանգներ, տողեր, ֆունկցիաներ, ճյուղեր)։
