> **Կարգավիճակ.** վահանակը կառուցված է **Keak CI UI Kit**-ի (`@keak/cheaper-inference-ui-kit`) վրա, որը ներառված է
> որպես workspace `packages/ui-kit` (`@omniroute/ui-kit`; upstream-ի պատկերը ամրագրված է
> `packages/ui-kit/UPSTREAM.md`-ում և պաշտպանված է `npm run check:ui-kit-snapshot`-ով)։ Կանոնիկ
> թեման լուսավորն է (Light); լռելյայն նախընտրությունը `system` է։ Ակցենտային գույնը Keak lime-ն է (`--ci-color-accent`)։ Inter-ը
> (letter-spacing 0, `--ci-letter-spacing-ui`) UI-ի տառատեսակն է, Instrument Serif-ը՝ միայն մեծ, հազված ցուցադրման
> տեքստի համար (`.ci-dashboard-display`), IBM Plex Mono-ն՝ կոդի համար — բոլորը ինքնահոսթինգ են արվում
> `src/app/globals.css`-ի սկզբում գտնվող `@fontsource/*` ներմուծումների միջոցով։ Յուրաքանչյուր պատկերակ Lucide գլիֆ է։

## 1. Որտեղ է ինչ գտնվում

- **Հավաքածու.** `packages/ui-kit/src`-ը upstream `src/`-ի բայթ առ բայթ պատճենն է՝
  `packages/ui-kit/UPSTREAM.md`-ում ամրագրված commit-ի պահին (որը նաև գրանցում է լիցենզիայի թույլտվությունը); `PATCHES.md`-ը թվարկում է լոկալ
  patch-երը (չկան): Այն օգտագործվում է որպես սկզբնաղբյուր՝ առանց build-ի. `next.config.mjs`-ը transpile է անում այն, իսկ
  `tsconfig.json`-ը համապատասխանեցնում է `@omniroute/ui-kit` → `packages/ui-kit/src` և `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` (`vitest.config.ts`-ը և `vitest.mcp.config.ts`-ը կրում են նույն alias-ը): Հավաքածուի
  կոմպոնենտ ներմուծեք ենթաճանապարհով (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), երբեք ոչ
  `@omniroute/ui-kit` barrel-ի միջոցով. barrel-ը յուրաքանչյուր importer-ի մեջ է քաշում բոլոր կոմպոնենտները (ներառյալ date picker-ը):
  Հավաքածուի stylesheet-ը մտնում է `src/app/globals.css`-ի միջոցով
  (`@import "../../packages/ui-kit/src/ci-ui.css"`):
- **Տոկեններ.** `packages/ui-kit/src/ci-tokens.css`-ը հայտարարում է `--ci-*` տոկենները; `src/app/globals.css`-ը
  դրանք կապում է OmniRoute-ի հին անուններին (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`), այնպես որ առկա `var(--color-*)` կարդացումները և Tailwind
  utility-ները շարունակեն աշխատել: Նոր կոդը օգտագործում է Tailwind utility-ները (`bg-surface`, `text-text-muted`,
  `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) կամ հավաքածուի class-ները՝ երբեք ոչ hex
  արժեք (`tests/unit/design-kit-bridge.test.ts`-ը պարտադրում է այդ կապը): `text-primary`-ն լուծարվում է
  `--color-primary-ink`-ի՝ `--text-color-primary`-ի միջոցով (lime-800՝ բաց թեմայում, lime ակցենտը՝ մուգ
  թեմայում), այնպես որ հիմնական տեքստը մնում է ընթեռնելի, մինչ `bg-primary`/`border-primary`-ը պահպանում են
  lime մակերեսը: Գծապատկերների շարքերը օգտագործում են `--color-chart-1` … `--color-chart-5`:
- **Թեմաներ.** `<html className="ci-theme">`-ը (`src/app/layout.tsx`) փաստաթուղթը միացնում է հավաքածուի թեմային:
  Նախընտրությունը `light`, `dark` կամ `system` է (`THEME_CONFIG.defaultTheme = "system"`՝
  `src/shared/constants/appConfig.ts`-ում; `system`-ը հետևում է `prefers-color-scheme`-ին): `applyTheme()`-ը
  `src/store/themeStore.ts`-ում (արտացոլված է `src/app/layout.tsx`-ի inline bootstrap սկրիպտում, որն աշխատում է
  hydration-ից առաջ) սահմանում է `data-theme="dark"|"light"` և միասին փոխարկում `<html>`-ի `.dark` class-ը:
  Հավաքածուի մուգ թեմայի տոկենների հավաքածուն կապված է `data-theme="dark"`-ին (`packages/ui-kit/src/ci-tokens.css`);
  OmniRoute-ի սեփական մուգ override-ները (`globals.css`-ի `.dark` բլոկը) և հին Tailwind `dark:`
  utility-ները կապված են `.dark` class-ին: Ակցենտի գույնի preset-ներ չկան. ակցենտը միշտ գալիս է
  հավաքածուից, իսկ ավելի հին build-ից պահպանված preset-ը հեռացվում է store-ի բեռնման ժամանակ:
- **Կոմպոնենտներ (ադապտերներ).** `src/shared/components/index.tsx`-ը պահպանում է OmniRoute-ի կոմպոնենտների
  API-ն (նույն անունները, default արտահանումները և props-երը), իսկ դրա հիմքում ընկած պրիմիտիվները հավաքածուի վրա
  կառուցված ադապտերներ են՝ ձևեր (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`),
  overlay-ներ և հետադարձ կապ
  (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`),
  կառուցվածք (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) և աղյուսակներ
  (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`): Ադապտերը ներմուծում է հավաքածուի
  կոմպոնենտը ենթաճանապարհով և համապատասխանեցնում է հին props-ները դրան — օրինակ, `Button variant="primary"`-ը
  հավաքածուի `default` կոճակն է (`--ci-button-primary-*`՝ հակադարձ մակերեսը բաց թեմայում, ակցենտը իր
  `--ci-color-accent-foreground` թանաքով մուգ թեմայում), `danger`-ը `destructive` է, իսկ `warning`-ը `outline` է՝
  գումարած `.ci-button--warning` ընդլայնումը: `globals.css`-ի վերջի
  `.ci-button--warning` և `.ci-badge[data-tone]` կանոնները (`@layer components`) OmniRoute-ի ընդլայնումներ են
  հավաքածուի class-ների վերևում: `tests/unit/ui/adapters/*.test.tsx`-ը ամրագրում է յուրաքանչյուր ադապտեր:
- **Կեղև.** `src/app/(dashboard)/layout.tsx`-ը render է անում `DashboardLayout`-ը, որը render է անում
  `src/shared/components/layouts/DashboardShell.tsx`-ը՝ հավաքածուի `SidebarProvider` / `Sidebar` /
  `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), OmniRoute-ի նավիգացիոն տրամաբանությամբ
  `src/shared/components/Sidebar.tsx`-ում: «Անցում դեպի բովանդակություն» հղումը դեպի `#main-content` առաջին
  ֆոկուսավորվող տարրն է: `src/shared/components/Header.tsx`-ը պարունակում է հավաքածուի `SidebarTrigger`-ը (կեղևի միակ sidebar
  փոխարկիչը), Keak `ProductSwitcher`-ը և command-palette-ի բացիչը; այն ցույց է տալիս երթուղու վերնագիրը միայն այն

  սեփական `PageHeader` ունեցող էջն ունենա մեկ `h1`: `src/shared/components/CommandPalette.tsx`-ը հավաքածուի `Dialog` է:
- **Պատկերակներ.** `<Icon name="material_name">`-ը (`src/shared/components/Icon.tsx`) անունը (էկրանների

  չեզոք placeholder գլիֆ (`data-icon-missing="true"`) և production-ից դուրս գրանցում է console
  նախազգուշացում: `npm run gen:icon-map`-ը տպում է օգտագործվող, բայց քարտեզից բացակայող անունները
  (`tests/unit/icon-map-coverage.test.ts`-ը ձախողվում է Lucide պատկերակ չունեցող ցանկացած անվան դեպքում;

  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]`-ը վերագրում է literal
  `<span className="material-symbols-outlined">` span-երը `<Icon>`-ի:
- **Ապրանքանիշ.** `src/shared/components/OmniRouteLogo.tsx`-ը փաթաթում է հավաքածուն. default արտահանում
  `OmniRouteLogo`-ն render է անում `ProductIcon product="omniroute" variant="glyph"` (inline SVG,

  անուն՝ «Keak OmniRoute») կամ white-label օպերատորների համար՝ նրանց սեփական `name`/`logoSrc`: Product-switcher-ի
  նպատակակետերը գտնվում են `src/shared/constants/keakProducts.ts`-ում (`KEAK_PRODUCT_LINKS`,
  `KEAK_ACTIVE_PRODUCT`): Ինքնուրույն էկրանները — `src/app/login/page.tsx`, `src/app/status/page.tsx`,

## 2. Կանոններ

1. Տոկեններ, երբեք լիտերալներ։ Բացառությունները թողնված են դիտավորյալ՝ միշտ մուգ կոնսոլային տերմինալը, ReactFlow SVG-ի stroke-երը `STATUS_HEX`-ի միջոցով (`src/shared/constants/statusColors.ts`) և կատեգորիկ պալիտրաները՝
   `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) և
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`)։
2. Երբեք մի փոփոխեք `packages/ui-kit/src`-ը ձեռքով. համաժամացրեք `scripts/dev/sync-ui-kit.sh <commit>`-ով.
   pre-commit ստուգիչ `npm run check:ui-kit-snapshot`-ը (`.husky/pre-commit`) ձախողվում է ցանկացած բայթի վրա, որը
   տարբերվում է ամրացված upstream commit-ից (այն բաց է թողնվում նախազգուշացումով, երբ upstream clone-ը՝
   `UI_KIT_CLONE` կամ `_references/cheaper-inference-ui-kit`-ը, բացակայում է)։ Երբ kit-ում ինչ-որ բան բացակայում է,
   շրջանցեք այն adapter-ում կամ էկրանում և խնդրեք այն upstream-ից։
3. Kit-ի տեքստային լռելյայն արժեքները անգլերեն են (`label = "Loading"`, `loadingLabel = "Loading table"`…) — ամեն անգամ, երբ kit-ի կոմպոնենտը ցուցադրում է տեքստ, փոխանցեք թարգմանված տողեր `useTranslations(...)`-ից։
4. Tailwind-ի utility-ները գերակշռում են kit-ի կոմպոնենտների class-ներին (kit-ը հայտարարում է
   `@layer theme, base, components, utilities`, և նրա կանոնները ապրում են `components`-ում) — օգտագործեք utility-ները
   բացների և layout-ի համար, ոչ թե kit-ի կոմպոնենտները վերագունավորելու համար։
5. Վերնագրեր. `.ci-heading` (Inter, առանց tracking-ի) էջի և բաժինների վերնագրերի համար. `.ci-dashboard-display`
   (Instrument Serif) միայն մեծ, նոսր ցուցադրողական տեքստի համար, ինչպիսին է սխալի էջի status կոդը։
6. `tests/unit/dashboard-kit-sweep.test.ts`-ը պահպանում է kit-ի ընդունումը՝ ոչ մի Material ligature span
   `src/app`-ի կամ `src/shared/components`-ի տակ. dashboard ծառում (`src/app/(dashboard)` և
   `src/shared/components`) ոչ մի հում `<select>`, `<textarea>` կամ `<table>` և ոչ մի ձեռքով ստեղծված
   `role="dialog"` թվարկված բացառություններից դուրս (`Select` adapter-ի native ճյուղը,
   `RequestLoggerDetail`). այնտեղ ամեն հում `<button>` կամ `<input>` պետք է ունենա մեկնաբանություն, որը պարունակում է
   `kit-exception:` (պատճառով) և ավարտվում է առավելագույնը 3 տող վերև. պալիտրայի երանգները և `dark:` տարբերակները
   միայն թեստի թվարկած ֆայլերում։
7. PR-ից առաջ ստուգեք երկու թեմաները և 390 px-ոց viewport-ը (սքրինշոթներով). `tests/e2e/a11y.spec.ts`-ը գործարկում է
   axe-ը։

## 3. Էկրանի ավելացում

1. Բացեք էջը kit-ի `PageHeader`-ով (`@omniroute/ui-kit/page-header`, `compact` dashboard-ի
   ներսում) — վերնագիր, նկարագրություն և `actions`։ Shell-ի header-ն այնուհետև հեռացնում է իր սեփական վերնագիրը։
2. Կառուցեք կառավարման տարրերը `@/shared/components`-ից (adapter-ները) և օգտագործեք kit-ի կոմպոնենտները ենթուղու միջոցով, որտեղ adapter չկա
   (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`,
   `Slider`…)։
3. Պատկերակներ. `<Icon name="…" />`։ Նոր անունն ավելացվում է `ICON_MAP`-ում սեմանտիկորեն համապատասխանող Lucide
   կոմպոնենտի հետ. `npm run gen:icon-map`-ը թվարկում է դեռևս բացակայող անունները։
4. Գույներ. սեմանտիկ utility-ներ (`text-success`, `bg-warning-bg`, `border-border`…) և
   `var(--color-chart-N)` գրաֆիկների շարքերի համար. ոչ մի hex արժեք և ոչ մի `dark:` տարբերակ, որը միայն կրկնում է գույնը։
5. Տեքստ. ամեն տող, ներառյալ kit-ի կոմպոնենտներին փոխանցվող label-ները, գալիս է `useTranslations`-ից։ Նոր
   բանալիներն ավելացվում են `src/i18n/messages/en.json`, `pt-BR.json` և `vi.json` ֆայլերում (վիետնամերեն parity
   թեստը ամրացնում է անգլերեն յուրաքանչյուր բանալի). մնացած locale-ները լրացվում են i18n sync-ով։
6. PR-ից առաջ գործարկեք պաշտպանիչ ստուգումները՝ `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (միակ ստուգումը, որը բռնում է `iconMap.ts`-ում կրկնված import-ը),
   `npm run check:ui-icu` և էկրանի սեփական թեստերը։

## 4. Ադապտերի ավելացում կամ փոփոխում

1. Պահպանեք `src/shared/components/index.tsx`-ի հանրային API-ն՝ նույն export անունները, default export-ները և ընդունվող props-ները։ Հին (legacy) props-ները արտապատկերեք kit-ի վրա ադապտերի ներսում (տե՛ս `Button.tsx`՝ `VARIANT_TO_KIT`, `SIZE_TO_KIT`)։
2. Ներմուծեք kit-ը ենթաճանապարհով (`@omniroute/ui-kit/<component>`)։
3. Kit-ի բացթողումների շրջանցիկ լուծումները տեղակայվում են ադապտերում (կամ `globals.css`-ի `@layer components`-ում, երբ ուղղումը ոճային է), երբեք ոչ `packages/ui-kit/src`-ում։
4. Ավելացրեք կամ թարմացրեք `tests/unit/ui/adapters/<name>.test.tsx`։ Շատ կանչողներ ունեցող ադապտերի դեպքում համեմատեք render արված նշագոյացումը (markup) փոփոխությունից առաջ և հետո. padding-ի կամ wrapper-ի փոփոխությունները տարածվում են բոլոր էկրանների վրա։

## 5. Kit-ի թարմացում

`scripts/dev/sync-ui-kit.sh <commit> [clone]`-ը պատճենում է տվյալ commit-ի upstream `src/`-ը `packages/ui-kit/src`-ի մեջ և կիրառում է միակ թույլատրելի փոխակերպումը (այն հեռացնում է `.js` վերջածանցը հարաբերական import-ներից)։ Ապա՝ դիտարկեք `git diff packages/ui-kit`, կատարեք տեսողական ստուգում providers, settings, combos, usage և endpoint էջերում երկու թեմաներով, գործարկեք `npm run check:ui-kit-snapshot` և `npm run test:vitest:ui`, և բացեք PR-ը upstream changelog-ի հետ միասին։
