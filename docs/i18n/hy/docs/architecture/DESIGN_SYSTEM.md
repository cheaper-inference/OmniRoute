> **Կարգավիճակ․** կառավարման վահանակը կառուցված է **Keak CI UI Kit**-ի (`@keak/cheaper-inference-ui-kit`) հիման վրա և ներառված է
> որպես `packages/ui-kit` աշխատանքային տարածք (`@omniroute/ui-kit`; վերին հոսքի պատկերը ամրագրված է
> `packages/ui-kit/UPSTREAM.md`-ում և վերահսկվում է `npm run check:ui-kit-snapshot`-ի միջոցով)։ Բաց թեման կանոնականն է,
> իսկ կանխադրված նախապատվությունը՝ `system`։ Կանխադրված գունապնակը հավաքածուի **Editions** տեսքն է
> (թղթի տաք չեզոք երանգներ և պղնձագույն շեշտադրում՝ `#e5ac82`, `packages/ui-kit/src/ci-editions.css`)։ Կարգավորումներ →
> Արտաքին տեսք → Գունապնակ բաժինն առաջարկում է **Դասական** տարբերակը՝ հավաքածուի հիմնական թոքենները լայմագույն շեշտադրմամբ։ Switzer-ը
> միակ տառատեսակն է միջերեսի, ցուցադրական և կոդային տեքստերի համար (`--ci-font-ui`; `--ci-font-display` և
> `--ci-font-mono` հղվում են դրան) և ինքնուրույն հոսթավորվում է հենց հավաքածուի կողմից (`packages/ui-kit/src/ci-fonts.css`,
> որը ներմուծվում է `ci-tokens.css`-ի կողմից)։ Switzer-ում բացակայող գրանշանները փոխարինվում են մեկ առ մեկ (`src/app/globals.css`)․
> Inter-ը՝ կիրիլիցայի, հունարենի և վիետնամերենի համար, իսկ միայն `html[dir="rtl"]`-ի ներքո՝ Vazirmatn-ը արաբական գրի համար։
> Յուրաքանչյուր պատկերակ Lucide-ի գրանշան է։

## 1. Որտեղ ինչն է գտնվում

- **Կոմպլեկտ։** `packages/ui-kit/src`-ը վերին հոսքի `src/`-ի բայթ առ բայթ պատճենն է՝
  `packages/ui-kit/UPSTREAM.md`-ում ամրագրված commit-ի դրությամբ (այնտեղ գրանցված է նաև արտոնագրային թույլտվությունը), իսկ `PATCHES.md`-ում թվարկված են տեղային
  շտկումները (չկան)։ Այն օգտագործվում է որպես սկզբնաղբյուր՝ առանց build-ի․ `next.config.mjs`-ը transpile է անում այն, իսկ
  `tsconfig.json`-ը `@omniroute/ui-kit` → `packages/ui-kit/src` և `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` համապատասխանեցումներ է սահմանում (`vitest.config.ts`-ը և `vitest.mcp.config.ts`-ը պարունակում են նույն alias-ը)։ Կոմպլեկտի
  բաղադրիչը ներմուծեք իր ենթուղով (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), ոչ երբեք
  `@omniroute/ui-kit` barrel-ի միջոցով․ barrel-ը յուրաքանչյուր ներմուծողի մեջ ներառում է բոլոր բաղադրիչները (ներառյալ ամսաթվի ընտրիչը)։
  Կոմպլեկտի stylesheet-ը ներմուծվում է `src/app/globals.css`-ի միջոցով
  (`@import "../../packages/ui-kit/src/ci-ui.css"`)։
- **Թոքեններ։** `packages/ui-kit/src/ci-tokens.css`-ը հայտարարում է `--ci-*` թոքենները, իսկ `src/app/globals.css`-ը
  դրանք կապում է OmniRoute-ի հին անվանումներին (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`), որպեսզի գոյություն ունեցող `var(--color-*)` ընթերցումները և Tailwind-ի
  utility-ները շարունակեն աշխատել։ Նոր կոդն օգտագործում է Tailwind-ի utility-ները (`bg-surface`, `text-text-muted`,
  `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) կամ կոմպլեկտի class-երը՝ երբեք ոչ hex արժեք
  (`tests/unit/design-kit-bridge.test.ts`-ը պարտադրում է այս կապի պահպանումը)։ `text-primary`-ն
  `--text-color-primary`-ի միջոցով վերածվում է `--color-primary-ink`-ի, որպեսզի հիմնական տեքստը մնա ընթեռնելի, մինչդեռ
  `bg-primary`/`border-primary`-ը պահպանում են շեշտադրող մակերեսը․ Editions-ի դեպքում դա կոմպլեկտի
  `--ci-color-accent-active`-ն է (բաց թեմայում՝ մուգ պղնձագույն `#99562f`, մուգ թեմայում՝ պղնձագույն շեշտադրում), իսկ Classic-ի դեպքում՝
  lime-800 բաց թեմայում և lime շեշտադրում՝ մուգ թեմայում։ Դիագրամների շարքերն օգտագործում են
  `--color-chart-1` … `--color-chart-5`։
- **Թեմաներ։** `<html className="ci-theme">`-ը (`src/app/layout.tsx`) փաստաթղթի համար միացնում է կոմպլեկտի թեման։
  Նախապատվությունը կարող է լինել `light`, `dark` կամ `system` (`THEME_CONFIG.defaultTheme = "system"`՝
  `src/shared/constants/appConfig.ts`-ում, իսկ `system`-ը հետևում է `prefers-color-scheme`-ին)։ `src/store/themeStore.ts`-ի
  `applyTheme()`-ը (որի կրկնօրինակն է `THEME_BOOT_SCRIPT`-ը՝ ներկառուցված `src/app/layout.tsx`-ում և գործարկվող
  hydration-ից առաջ) սահմանում է `data-theme="dark"|"light"`-ը և միաժամանակ միացնում կամ անջատում `<html>`-ի `.dark` class-ը։
  Կոմպլեկտի մուգ թոքենների հավաքածուն հիմնված է `data-theme="dark"`-ի վրա (`packages/ui-kit/src/ci-tokens.css`),
  իսկ OmniRoute-ի սեփական մուգ վերասահմանումները (`globals.css`-ի `.dark` բլոկը) և հին Tailwind `dark:`
  utility-ները հիմնված են `.dark` class-ի վրա։ Շեշտադրման գույնի պատրաստի տարբերակներ չկան․ շեշտադրումը միշտ տրամադրում է
  կոմպլեկտը, իսկ ավելի հին build-ից պահպանված պատրաստի տարբերակը հեռացվում է store-ի բեռնման ժամանակ։
- **Ներկապնակներ։** Կան երկուսը, և երկուսն էլ կոմպլեկտից են (`src/shared/constants/appearancePalette.ts`)՝ `editions`՝
  լռելյայն տարբերակը, և `classic`։ Editions-ը կոմպլեկտի `data-ci-appearance="editions"` attribute-ն է `<html>`-ի վրա, որը
  `ci-editions.css`-ը (`ci-ui.css`-ի կողմից ներմուծված) համադրում է `data-theme`-ի հետ, իսկ Classic-ը այդ attribute-ի
  բացակայությունն է։ Արմատային layout-ը server-render է անում attribute-ը, ուստի ոչինչ չպահպանած այցելուն (կամ առանց JS-ի այցելուն)
  Editions է ստանում բոլոր մակերեսների համար՝ dashboard, մուտքի էջ, `/status`, սխալի էջեր, `/docs` և PWA։ Ընտրությունը
  թեմայի կողքին պահպանվում է նույն `theme` store-ում (`palette`, `setPalette()`, `applyPalette()`՝
  `src/store/themeStore.ts`-ում) և մինչև արտապատկերումը կիրառվում է `THEME_BOOT_SCRIPT`-ի միջոցով
  (`src/shared/utils/themeBootScript.ts`, ներկառուցված layout-ի `<head>`-ում), որը attribute-ը հեռացնում է
  միայն այն դեպքում, երբ պահպանված ներկապնակը `"classic"` է․ արմատային layout-ից դուրս գտնվող `src/app/global-error.tsx`-ը
  կիրառում է այն նույն store-ից։ `data-ci-appearance`-ը մի դրեք որևէ այլ տարրի վրա․ կոմպլեկտն այն համադրում է
  `html:root:has([data-ci-appearance="editions"])`-ի միջոցով, ուստի մեկ ժառանգ տարրն ամբողջ փաստաթուղթը կփոխարկի։
  Editions-ի `data-ci-editions-variant="landing"` տարբերակը նախատեսված է մարքեթինգային էջերի, ոչ թե dashboard-ի համար։
  Բրաուզերի chrome-ը (`viewport.themeColor`, վեբ manifest-ը) չի կարող կարդալ CSS-ը կամ պահպանված ընտրությունը, ուստի այն
  հետևում է լռելյայն տարբերակին․ `src/shared/constants/pwaThemeColors.ts`-ի `PWA_THEME_COLORS`-ը Editions-ի
  `--ci-color-background`-ի (`#f3f1e9` / `#11120f`) միակ կրկնօրինակն է, որը `ci-editions.css`-ին ամրագրված է
  `tests/unit/pwa-theme-colors.test.ts`-ի միջոցով։ Monaco-ն իր գույները կարդում է փորձանմուշից (`monacoKitTheme.ts`)։
  Editions-ի դեպքում փորձանմուշի ընթերցումը մեկ համաժամանակյա անցման համար փոխում է արմատային `data-theme`-ը, քանի որ կոմպլեկտը
  Editions-ի բաց/մուգ տարբերակները որոշում է արմատից։
- **Բաղադրիչներ (ադապտերներ)։** `src/shared/components/index.tsx`-ը պահպանում է OmniRoute-ի բաղադրիչների API-ն (նույն
  անունները, լռելյայն export-ները և props-երը), իսկ դրա հիմքում ընկած primitive-ները կոմպլեկտի վրայի ադապտերներ են՝ form-եր
  (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), overlay-ներ և հետադարձ կապի տարրեր
  (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`),

## 2. Կանոններ

1. Նշաններ, երբեք բառացի: Բացառություններ, որոնք դիտավորյալ պահվում են. միշտ մութ վահանակի տերմինալը և `STATUS_HEX` (`src/shared/constants/statusColors.ts`), փաթեթի կարգավիճակի ներկապնակի լուծված վեցանկյուն հայելին այն զանգողների համար, ովքեր բառացի վեցանկյունի կարիք ունեն: Կատեգորիկ գունապնակներն այլևս բացառություն չեն. դրանք օգտագործում են փաթեթի հինգ գծապատկերների նշանները (`--color-chart-1..5`) `src/shared/utils/categoricalPalette.ts` միջոցով, իսկ երթուղային ռազմավարությունների համար՝ `src/app/(dashboard)/dashboard/combos/strategyPalette.ts`; ReactFlow եզրերը և նվագախմբային կտավը կարդում են թեմայից տեղյակ `--orch-status-*` փոփոխականները (`src/shared/components/flow/edgeStyles.ts`):
2. Երբեք մի կարկատեք `packages/ui-kit/src` ձեռքով. համաժամեցեք `scripts/dev/sync-ui-kit.sh <commit>` հետ; pre-commit gate `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) ձախողվում է ցանկացած բայթի վրա, որը տարբերվում է ամրացված վերին հոսքի կատարումից (այն բաց է թողնում նախազգուշացումով, երբ վերընթաց կլոնը՝ `UI_KIT_CLONE` կամ `_references/cheaper-inference-ui-kit`, բացակայում է): Երբ հավաքածուին ինչ-որ բան պակասում է, աշխատեք դրա շուրջը ադապտերում կամ էկրանին և խնդրեք դրա համար:
3. Հավաքածուի տեքստի լռելյայն նախադրյալներն են անգլերենը (`label = "Loading"`, `loadingLabel = "Loading table"`…) – փոխանցեք թարգմանված տողերը `useTranslations(...)` ից, երբ հավաքածուի բաղադրիչը ներկայացնում է տեքստը:

Tailwind կոմունալ ծառայությունները հաղթում են հանդերձանքի բաղադրիչների դասերին (կոմպլեկտը հայտարարում է `@layer theme, base, components, utilities` և դրա կանոնները գործում են `components` ում) — օգտագործեք կոմունալ ծրագրերը տարածության և դասավորության համար, այլ ոչ թե հավաքածուի բաղադրիչները նորից գունավորելու համար:

## 5. Կոմպլեկտի թարմացում

`npm run check:ui-kit-upstream` համեմատում է `packages/ui-kit/UPSTREAM.md` ում ամրացված տարբերակը վերընթաց ռեպո-ի նորագույն `v*` պիտակի հետ և տպում է համաժամացման հրամանը, երբ թողարկումը դուրս է գալիս:

Ամենօրյա `UI Kit upstream watch` աշխատանքային հոսքը (`.github/workflows/ui-kit-upstream-watch.yml`) նույն ստուգումն է կատարում: Մինչ քորոցը ետևում է, `scripts/ci/ui-kit-sync-pr.sh` բաց է պահում մեկ համաժամեցման PR ամենաբարձր `release/vX.Y.Z` ճյուղի դեմ՝ շարժվող `chore/ui-kit-sync-latest` ճյուղի վրա: Այն երբեք չի միաձուլվում. հավաքածուի յուրաքանչյուր թողարկում դեռ կարիք ունի տեղական VPS ի տեսողական ստուգման: Մասնաճյուղը վերակառուցվում է, երբ թողարկվում է ավելի նոր թողարկում և հակառակ դեպքում մենակ է մնում: Բաց PR ձեռքով սեղմված պարտավորություններով չի վերագրվում, իսկ PR այն տարբերակի համար, որը փակված չմիաձուլված պահպանողը փակ է մնում մինչև նոր թողարկումը:

Երբ ոչ մի PR չի կարող բացվել (նպատակային թողարկումը սառեցված է, PR ձեռքով սեղմում է կատարումը, PR ն փակված է կամ PR նշան չի դրված), աշխատանքային հոսքը բաց է պահում հետևելու մեկ խնդիր, որն ասում է, թե ինչու:

Աշխատանքային հոսքը օգտագործում է երկու գաղտնիք.

- `secrets.UI_KIT_READ_TOKEN`. միայն կարդալու նշան մասնավոր վերին հոսքի ռեպո-ի համար: Երբ աշխատանքային հոսքը չի կարող կարդալ հոսանքին հակառակ (ոչ մի նշան, նշան, որը դադարել է աշխատել կամ GitHub անհասանելի է), գործարկումը մնում է կանաչ, բայց գրում է նախազգուշացում և բաց է պահում մեկ առանձին թողարկում, որն ինքն իրեն փակվում է մեկ անգամ, երբ ավելի ուշ գործարկումը կարող է նորից կարդալ դեպի վերև:
- `secrets.UI_KIT_SYNC_PR_TOKEN`. այս պահոցում մանրակրկիտ նշան է, որը պարունակում է Բովանդակություն և Pull հարցումներ գրելու հասանելիություն: Լռելյայն `GITHUB_TOKEN` այստեղ չի կարող ստեղծել PRs, և նրա բացած PR չի գործարկի CI: Առանց այս նշանի աշխատանքային հոսքը միայն հրում է ճյուղը:

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` պատճենում է `src/` վերին հոսանքով այդ commit-ում (`latest` = նորագույն `v*` պիտակը) `packages/ui-kit/src` մեջ, կիրառում է մեկ թույլատրելի փոխակերպումը (այն հանում է `.js` վերջածանցը հարաբերական ներմուծումից) և աշխատանքային տարածքի տարբերակը `packages/ui-kit/package.json` ով և `package-lock.json` դնում է վերին հոսանքով: Այնուհետև՝ վերանայեք `git diff packages/ui-kit`, կատարեք տեսողական անցում պրովայդերների, կարգավորումների, կոմբինացիաների, օգտագործման և վերջնակետի վերաբերյալ երկու թեմաներում, գործարկեք `npm run check:ui-kit-snapshot` և `npm run test:vitest:ui` և բացեք PR վերին հոսքի փոփոխության լոգով:

  դրա վավերացնողները գեներացված ֆայլի վրա, ուստի կոդից շեղված թիվը ձախողում է թեստը․ ուղղեք այն սկզբնաղբյուրը, որը
  կարդում է դարպասը, և երբեք՝ գեներատորի թիվը։
