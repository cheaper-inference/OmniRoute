Web Cookie մատակարարները OmniRoute-ին թույլ են տալիս API բանալու փոխարեն օգտագործել AI ծառայություն՝ ձեր դիտարկիչի առկա աշխատաշրջանի միջոցով։ Դրանք օգտակար են, երբ դուք արդեն հասանելիություն ունեք որևէ ծառայության՝ դրա կայքի միջոցով, և ցանկանում եք, որ OmniRoute-ն օգտագործի նույն նույնականացված աշխատաշրջանը։

Ի տարբերություն API բանալի օգտագործող մատակարարների՝ Web Cookie մատակարարները նույնականացումն իրականացնում են՝ օգտագործելով այն հավատարմագրերը, որոնք ձեր դիտարկիչն ուղարկում է կայքին։

# Նախքան սկսելը

> **Կարևոր․** Հավատարմագրերը միշտ պատճենեք **ակտիվ ցանցային հարցումից**, այլ **ոչ թե** ձեր դիտարկիչի Cookie-ների պահոցից։

Նույնականացման բազմաթիվ խնդիրներ առաջանում են սխալ տեղից Cookie-ներ պատճենելու պատճառով։

## ՄԻ՛ պատճենեք Cookie-ների պահոցից

Դիտարկիչների մեծ մասը պահպանված Cookie-ները ցուցադրում է հետևյալ բաժնում․

```
Մշակողի գործիքներ
→ Հավելված (կամ Պահոց)
→ Cookie-ներ
```

Թեև այս Cookie-ները կարող են ճիշտ թվալ, դրանք կարող են լինել՝

- հնացած
- ոչ ամբողջական
- առանց այն Cookie-ների, որոնք ուղարկվում են միայն նույնականացված հարցումների ժամանակ

Այս արժեքների օգտագործումը կարող է նույնականացման ձախողումներ առաջացնել, նույնիսկ եթե դրանք վավեր են թվում։

## Պատճենեք ակտիվ հարցումից

Փոխարենը՝ օգտագործեք հաջող հարցման Cookie-ները․

```
Մշակողի գործիքներ
→ Ցանց
→ Թարմացրեք էջը
→ Բացեք զրույցի կամ խոսակցության հարցում
→ Հարցման վերնագրեր
→ Cookie
```

`Cookie` հարցման վերնագիրը պարունակում է նույնականացման ճշգրիտ տվյալները, որոնք ձեր դիտարկիչը հաջողությամբ օգտագործել է։

Web Cookie մատակարարների մեծ մասի դեպքում հենց այս արժեքը պետք է տեղադրել OmniRoute-ում։

---

# Ընդհանուր կարգավորում

Կարգավորման գործընթացը Web Cookie մատակարարների մեծ մասի համար նույնն է։

1. Մուտք գործեք մատակարարի կայք։
2. Բացեք դիտարկիչի Մշակողի գործիքները։
3. Բացեք **Ցանց** ներդիրը։
4. Թարմացրեք էջը։
5. Բացեք նույնականացված զրույցի կամ խոսակցության հարցում։
6. Պատճենեք պահանջվող նույնականացման հավատարմագրերը։
7. Բացեք OmniRoute-ը։
8. Անցեք **Մատակարարներ → Ավելացնել մատակարար**։
9. Ընտրեք ձեր Web Cookie մատակարարին։
10. Տեղադրեք հավատարմագրերը։
11. Սեղմեք **Փորձարկել կապը**։
12. Պահպանեք մատակարարին։

Պահանջվող ճշգրիտ հավատարմագրերը կախված են մատակարարից։

| Մատակարար                       | Հավատարմագրերի ձևաչափ              | Մատակարարի ուղեցույց             |

> Թարմացրեք այս աղյուսակը, երբ ավելացվում են նոր Web Cookie մատակարարներ կամ փոխվում են առկա մատակարարների նույնականացման պահանջները։

## NoTrack (notrack-web)

NoTrack-ը ([notrack.ai](https://notrack.ai)) սպառողների համար նախատեսված անվճար զրույցի հարթակ է, որը գրանցում չի պահանջում․ աշխատաշրջանն անանուն կերպով ստեղծվում է առաջին այցելության ժամանակ և պահպանվում երեք թխուկների միջոցով՝ `uid`, `si_usr_id` և `si_ses_id`։ OmniRoute-ը նույն `/api/dispatch` վերջնակետը պրոքսիավորում է մեկ մոդելի նույնացուցիչի միջոցով (`notrack-c`, կեղծանունը՝ `ntw`)։

### Միացման քայլերը

1. Ձեր դիտարկիչում բացեք [notrack.ai](https://notrack.ai)-ը և թույլ տվեք, որ անանուն աշխատաշրջանի թխուկը սահմանվի։
2. Բացեք **Մշակողի գործիքներ → Ցանց**, թարմացրեք էջը և սեղմեք ցանկացած `/api` հարցման վրա։
3. **Հարցման վերնագրեր** բաժնում պատճենեք `Cookie` վերնագրի ամբողջական արժեքը։
4. OmniRoute-ում անցեք **Մատակարարներ → Ավելացնել մատակարար → NoTrack Web (անվճար)**։
5. Տեղադրեք թխուկների տողը `apiKey` դաշտում և սեղմեք **Պահպանել**։

OmniRoute-ը տեղադրված տողից առանձնացնում է `uid`, `si_usr_id` և `si_ses_id` արժեքները և վերակառուցում է մաքուր `Cookie` վերնագիր, որը պարունակում է միայն այդ զույգերը, ինչպես նաև `nt_session`-ը (մուտք գործած հաշիվների համար սահմանվող `ntk_…` նշանը), եթե այն առկա է։ Եթե երեքից որևէ մեկը բացակայում է, տեղադրված սկզբնական տողը փոխանցվում է անփոփոխ, որպեսզի օպերատորները կարողանան փորձարկել այլ ձևաչափեր։

### Մոդելների նույնացուցիչները

| Մոդելի նույնացուցիչ | Ցուցադրվող անուն | Նշումներ                                                             |
| ------------------- | ---------------- | -------------------------------------------------------------------- |
| `notrack-c`         | NoTrack C        | Լռելյայն՝ սկզբնաղբյուրի դիսպետչերացման `C` մոդելը։                   |
| `C`                 | NoTrack C        | `notrack-c`-ի կեղծանունը (սկզբնաղբյուրի դիսպետչերացման անմշակ կոդը)։ |
| `notrack`           | NoTrack C        | `notrack-c`-ի կեղծանունը։                                            |
| `ntw`               | NoTrack C        | `notrack-c`-ի կարճ կեղծանունը։                                       |

Բոլոր չորս մոդելների նույնացուցիչները համապատասխանում են սկզբնաղբյուրի նույն դիսպետչերացման մոդելին (`C`)։

### Հարցման ընտրանքները

Կատարիչը հարցման մարմնում ընդունում է հետևյալ ոչ պարտադիր դաշտերը․

| Մարմնի դաշտ           | Լռելյայն արժեք | Նպատակ                                                                         |
| --------------------- | -------------- | ------------------------------------------------------------------------------ |
| `notrack_mode`        | `usual`        | Դիսպետչերացման ռեժիմ (ազատ ձևաչափի տող․ սկզբնաղբյուրն ընդունում է `usual`, …)  |
| `notrack_max_turns`   | `6`            | Ներքին քայլերի քանակը, որոնք սկզբնաղբյուրը կարող է կատարել նախքան պատասխանելը։ |
| `notrack_chat_id`     | `null`         | Շարունակել սկզբնաղբյուրում առկա զրույցը (նոր զրույցի համար բաց թողեք)։         |
| `notrack_attachments` | `[]`           | Սկզբնաղբյուրի կցորդների նկարագրիչների՝ անփոփոխ փոխանցվող զանգված։              |
| `notrack_regenerate`  | `false`        | Սահմանեք `true`՝ նախորդ քայլի համար վերաստեղծված պատասխան խնդրելու նպատակով։   |

### Հնարավորությունները

- Զրույցի պատասխաններ՝ **հոսքային և ոչ հոսքային** ռեժիմներով։
- **Գործիքների կանչում** — հարցման մեջ սահմանեք `tools: [...]`․ կատարիչը դրանք սերիականացնում է գործիքի կանչի ծրարային պայմանագրի մեջ և մոդելի պատասխանները կրկին վերլուծում է OpenAI-ի `tool_calls` ձևաչափով։
- **`response_format`** — աջակցվում են `json_object` և `json_schema` ձևաչափերը։ Կատարիչը մոդելի պատասխանից առանձնացնում է առաջին JSON օբյեկտը և վերադարձնելուց առաջ այն վերածում է տողի։
- **Դատողության հուշում** — կատարիչը թողարկում է `reasoning` տարբերություն, երբ սկզբնաղբյուրն ուղարկում է `thinking` իրադարձություն։

### Սահմանափակումները

- Սկզբնաղբյուրը կիրառում է անանուն օգտագործման քվոտաներ․ դրանք գերազանցելու դեպքում կատարիչը վերադարձնում է 429՝ հասկանալի հաղորդագրությամբ։
- Մոդելների բոլոր նույնացուցիչները համապատասխանում են սկզբնաղբյուրի նույն դիսպետչերացման մոդելին․ ըստ մոդելի առանձին փոխարկում չկա։
- Կատարիչը չի կանչում սկզբնաղբյուրի `/api/chats` վերջնակետը, ուստի զրույցների պատմությունը / աշխատաշրջաններն ինքնաբերաբար չեն կառավարվում։ Սկզբնաղբյուրում առկա զրույցը շարունակելու համար օգտագործեք `notrack_chat_id`։

# Ինչ կարող են և չեն կարող անել վեբ-թխուկների մատակարարները

Վեբ-թխուկների մատակարարները վերօգտագործում են կայքի զրույցի միջերեսը։ Դրանք **չեն** տրամադրում նույն հնարավորությունները, ինչ պաշտոնական API-ները։

## Աջակցվում է

- Նույնականացում՝ օգտագործելով դիտարկիչի ձեր առկա աշխատաշրջանը
- Ձեր հաշվի միջոցով հասանելի մոդելների օգտագործում
- Զրույցի պատասխանների հոսքային փոխանցում
- API բանալի չի պահանջվում

## Չի աջակցվում

- Ֆունկցիաների կանչում
- Գործիքների կանչում
- Ֆայլերի ավտոմատ խմբագրում
- Գործակալային IDE աշխատանքային հոսքեր
- Միայն API-ի միջոցով հասանելի գործառույթներ

Սա սպասվող վարքագիծ է և **սխալ չէ**։

Եթե ձեզ անհրաժեշտ է գործիքների գործարկում, ֆայլերի ավտոմատ խմբագրում կամ այլ գործակալային աշխատանքային հոսքեր, Web Cookie մատակարարի փոխարեն օգտագործեք **API բանալիով մատակարար**։

# Վավերացման սահմանափակում

Հաջող **Կապի ստուգումը** կամ cookie-ի վավերացումը միայն հաստատում է, որ տրամադրված հավատարմագրերը, ըստ երևույթին, ունեն ակնկալվող ձևաչափը։

Քանի դեռ Issue #7857-ը լուծված չէ, հաջող վավերացումը **չի երաշխավորում**, որ մատակարարի նույնականացումը հաջողությամբ կկատարվի։

Եթե նույնականացումը շարունակում է ձախողվել, համոզվեք, որ հավատարմագրերը պատճենել եք ակտիվ ցանցային հարցումից, այլ ոչ թե դիտարկիչի cookie-ների պահոցից։

---

# Խնդիրների վերացում

## Նույնականացումը ձախողվում է

Համոզվեք, որ հավատարմագրերը պատճենվել են այստեղից՝

```
Network
→ Request Headers
→ Cookie
```

և **ոչ** այստեղից՝

```
Application
→ Cookies
```

---

## Cookie-ն աշխատում է դիտարկիչում, բայց ոչ OmniRoute-ում

Որոշ մատակարարներ ներառում են cookie-ներ, որոնք ուղարկվում են միայն նույնականացված հարցումների ժամանակ։

Զրույցը հաջողությամբ բացելուց հետո կրկին պատճենեք հավատարմագրերը թարմ ցանցային հարցումից։

---

## Աշխատաշրջանի ժամկետը լրացել է

Web Cookie մատակարարներն օգտագործում են դիտարկիչի ձեր առկա աշխատաշրջանը։

Եթե դիտարկիչի ձեր աշխատաշրջանի ժամկետը լրանում է կամ դուրս եք գալիս հաշվից, պետք է պատճենեք հավատարմագրերի նոր հավաքածու։ Աջակցվող վեբ մատակարարների համար cookie-ների թարմացումն ավտոմատացնելու նպատակով օգտվեք ուղեկից [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) գործիքից։

---

## Կապի ստուգումը հաջողվում է, բայց հարցումները ձախողվում են

Քանի դեռ Issue #7857-ը լուծված չէ, հաջող վավերացումը չի երաշխավորում, որ նույնականացման հարցումը հաջողությամբ կկատարվի։

Նախքան խնդրի հետագա ախտորոշումը՝ կրկին պատճենեք ձեր հավատարմագրերը թարմ նույնականացված հարցումից։

## ChatGPT Web-ը ձախողվում է "Unsupported ChatGPT integrity dependency" սխալով

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

Հավատարմագիրը ճիշտ է. այդ սխալը գալիս է կամրջակից, ոչ թե աշխատաշրջանից։ chatgpt.com-ը յուրաքանչյուր տեղակայման համար սահմանում է իր
մոդուլների ID-ները, իսկ կամրջակը նախկինում ամրագրում էր իր ստեղծած Sentinel օժանդակ մոդուլի ID-ն, ուստի
chatgpt.com-ի այնպիսի վերակառուցումը, որը վերանվանել էր օժանդակ մոդուլը, խափանում էր յուրաքանչյուր հարցում, մինչդեռ cookie-ն շարունակում էր վավեր մնալ։ Կապի
վերահաստատումը չի կարող լուծել խնդիրը։

Այն տարբերակները, որոնք մոդուլը որոշում են էջի սեփական գործարկման միջավայրի միջոցով, որևէ ID չեն ամրագրում և այս խնդրին չեն բախվում։ Եթե տեսնում եք այս
սխալը, թարմացրեք OmniRoute-ը և կրկին գործարկեք կապի ստուգումը։

# Լավագույն գործելակերպեր

- Հավատարմագրերը պատճենեք թարմ նույնականացված հարցումից։
- Խուսափեք հին cookie-ների կրկնակի օգտագործումից։
- Web Cookie մատակարարներից օգտվելիս դիտարկիչի ձեր աշխատաշրջանը պահեք ակտիվ։
- Պատճենված cookie-ները դիտարկեք որպես գաղտնի հավատարմագրեր։
- Երբ ձեզ անհրաժեշտ են ֆունկցիաների կանչում կամ գործակալային աշխատանքային հոսքեր, օգտագործեք API բանալիով մատակարարներ։
