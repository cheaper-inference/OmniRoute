Անհաջողությունները դասակարգվում են նախքան կրկնակի որոշումներ կայացնելը:

Անցումային ձախողումները, ինչպիսիք են ժամանակի ընդհատումները, ցանցի սխալները, սակագների սահմանափակումները և մատակարարի 5xx պատասխանները, կարող են ձախողվել: Սպառված քվոտան կամ վարկը (քվոտա 429 կամ 402 վճարում է պահանջվում) երբեք չի փորձարկվում նույն մատակարարի վրա, բայց չի անցնում մեկ այլին, որի քվոտան առանձին է: Նույնականացման սխալները, թույլտվության սխալները, անվավեր հարցումները, անհասանելի մոդելները և անհայտ ձախողումները կուրորեն չեն փորձարկվում:

Լռելյայն խաչաձև մատակարարների քաղաքականությունը թույլ է տալիս մինչև երեք մատակարարի փորձ, կրկնում է արագության սահմանաչափերը և ժամկետները, ձախողվում է սպառված քվոտայի դեպքում և ադմինիստրատիվ անջատումը անջատում է ժամանակավոր միացման վիճակից:

## Որտեղ այն կիրառվում է

- **Կոմբոներ** ձախողվել են իրենց թիրախների միջև՝ համաձայն կոմբոյի սեփական ռազմավարության և պարամետրերի:
- **Մերկ մոդելի ID** (առանց `provider/` նախածանցի), որը մի քանի ակտիվ պրովայդերներ են ծառայում, առանց այդ ճշգրիտ անվան համակցման, նախ ուղարկվում է մատակարարի եզրակացություն ընտրողներին: Եթե այդ փորձը ձախողվի այնպես, որ քաղաքականությունը ձախողվի, նույն հարցումն ուղարկվում է հաջորդ ակտիվ մատակարարին, որը սպասարկում է ID-ն: Արձագանքը պարունակում է `x-omniroute-fallback-attempts` ՝ նախքան պատասխանողից փորձված մատակարարների քանակությունը:
  - Յուրաքանչյուր փոխարինող իրավասու է ճիշտ այնպես, կարծես եզրակացությունն ընտրել է այն: Թիրախը, որը API բանալին արգելափակում է կամ չի ընդունում, բաց է թողնվում առանց վերին հոսքի զանգի, և հաճախորդը ստանում է իրական վերընթաց սխալը, այլ ոչ թե քաղաքականության մերժումը թիրախի համար, որը երբեք չի անվանել:
  - Միայն ձախողված պատասխանը շարունակվում է. ոչինչ չի ձախողվում առաջին հոսքային բայթից հետո:
  - Արտակարգ իրավիճակների հետադարձ մոդելի փոխանակումը կիրառվում է միայն պահանջվող մոդելի յուրաքանչյուր մատակարարի ձախողումից հետո:
  - Միացմանը (`x-omniroute-connection`) ամրացված հարցումը մնում է դրա վրա:
  - Նախածանցով id (`provider/model`) երբեք չի փոխադրվում այլ մատակարարի:

Շրջանակային վիճակներն են `closed`, `open` և `half_open`: Սառեցումը նախատեսում է սահմանափակ զոնդ; հաջող զոնդը փակում է միացումը, իսկ ձախողված զոնդը նորից բացում է այն:
