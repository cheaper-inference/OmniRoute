## Վայրէջք ազատման ճյուղի վրա

Ամենահերթը կառավարում է վայրէջքները `release/vX.Y.Z` ում: Նախքան PR վայրէջք կատարելը, կարդացեք `mode` վերին մակարդակը `config/merge-queue/config.json` ում կանխադրված ճյուղում: Տես [Omni-Queue](OMNI_QUEUE.md) :

- **`shadow`** գործարկում է վավերացումը և թողնում է վայրէջքը ձեռքով միաձուլման: Կիրառեք `omni-queue` հաստատված PR ին իր վերջնական գլխում: Ստուգեք իրավասությունը `npm run queue -- why <PR>` հետ: Սպասեք այդ գլխի դատավճռին `npm run queue -- history --base <branch>`։ Շարունակեք `would-land`. `culprit-found` ում կամ `would-dequeue` պահեք միաձուլումը և շտկեք պատճառը:
- **Ստվերային բացառություններ.** Կանաչ լրիվ CI ով գնացքը ընթացիկ բազային հուշումով կարող է շարունակվել առանց առանձին հերթի դատավճիռ: Նույն բացառությունը կիրառվում է, երբ PR գլուխն արդեն պարունակում է ընթացիկ բազային հուշում:
- **`live`** օգտագործում է `omni-queue` պիտակը վայրէջք գործարկելու համար: Հերթը միայնակ վայրէջք է կատարում PR ին: Թողնել միաձուլման հրամանները և ուղղակիորեն մղել հերթին:

Յուրաքանչյուր վայրէջք պահանջում է սեփականատիրոջ թույլտվությունը և կիրառելի պահանջվող ստուգումները: Կիրառեք `omni-queue` միայն այն բանից հետո, երբ սեփականատերը թույլ կտա վայրէջք կատարել: Հերթագրված PRs հպվելով պաշտպանված ուղիներին նաև պահանջում է սեփականատիրոջ `protected-approved` որոշումը այդ PR համար:

«Ակտիվ արձակման վրա կանաչ դարպասներ պահանջել» կանոնակարգը պահանջում է կանաչ `Gate / CI` և `Gate / Quality` գլխի վրա: Երբեք մի օգտագործեք `--admin` կարմիր դարպասը շրջանցելու համար: Ազատման սառեցման բլոկները միաձուլվում են սառեցված ճյուղի մեջ: Տես [Դժվար կանոն 21](HARD_RULES_DETAIL.md) : Երբեք մի պիտակավորեք, միաձուլեք կամ մղեք ձգման խնդրանքին, որ մեկ այլ աշխատաշրջան աշխատում է: Տես [Դժվար կանոն 22](HARD_RULES_DETAIL.md) :

## Գնացքի ձգման հարցում

1. Գործարկեք գնացքի ճյուղը ընթացիկ թողարկման բազային հուշումով: Ինտեգրել ճշգրիտ հաստատված անդամների ղեկավարները՝ օգտագործելով միաձուլման պարտավորությունները: Պահպանեք նրանց պարտավորությունների պատմությունը՝ խուսափելով squash-ից և rebase-ից:
2. Բացեք գնացքի ճյուղի մեկ ձգման հարցումը: Վավերացրեք այդ PR իր ամբողջական CI ով ընթացիկ բազային հուշում: Վայրէջքից առաջ նորից ստուգեք հիմքի ծայրը և հաստատված անդամի գլուխները: Թարմացրեք գնացքը և դրա CI, երբ վավերացված թեկնածուն փոխվի:
3. Վայրէջք կատարեք PR գնացքը միաձուլման կատարմամբ՝ կիրառելի հերթի ռեժիմում: Ուղիղ ռեժիմում հերթի `merge-ff` վայրէջքի մեթոդը պահպանում է միաձուլման պարտավորությունները: Անդամների սկզբնական գլուխները հասանելի են դառնում թողարկման ճյուղից: GitHub նշում է PRs անդամին որպես միավորված, և պարտավորությունները պահպանում են իրենց հեղինակներին:

Հասարակական օրինակ է [PR #21071](https://github.com/cheaper-inference/OmniRoute/pull/21071). Այն միավորեց 18 անդամ PRs և վայրէջք կատարեց միաձուլման հանձնառությամբ 2026-11-24-ին:

Համաժամեցումը `main` ից դեպի հաջորդ թողարկման ճյուղ նույնպես վայրէջք է կատարում միաձուլման կատարման միջոցով: Հետագայում համաժամացման համար անհրաժեշտ է պահպանել `main` ծագումը: Տես [Աշխատանքային ծառի մեկուսացում](WORKTREE_ISOLATION.md#sync-back-landings-are-merge-commits-never-squash) :

## Տեղական միաձուլման գնացքի վավերացուցիչը

```bash
scripts/release/merge-train.sh [--plan] [--fast] <base-branch> <PR#> [<PR#>...]
```

Վալիդատորը վերցնում է հիմքը և PR գլուխները և միավորում դրանք միանգամյա աշխատանքային ծառի մեջ: Այն աշխատում է իր հավասարության փաթեթը մեկ անգամ ստացված ծառի վրա: Գլխի ձախողված բեռնման կամ միաձուլման հակամարտությունը դուրս է մղում այդ PR և սցենարը շարունակվում է մնացած PRs ով:

- **`--plan`** տպում է ընտրված ռեժիմի քայլերը և դուրս է գալիս առանց աշխատանքային ծառ ստեղծելու կամ հեռակառավարման վահանակին կապվելու: Միավորեք այն `--fast` հետ՝ արագ պլանը ստուգելու համար:
- **`--fast`** գործարկում է ընդհանուր ստատիկ դարպասները, ընտրված փոխված `node:test` ֆայլերը `tests/unit/` ի տակ և `npm run test:vitest`: Գործարկեք ամբողջական տեղական վավերացում օրական առնվազն մեկ անգամ կուտակված հուշումով, երբ օգտագործում եք արագ ռեժիմ:
- **Ամբողջական ռեժիմ** ավելացնում է միայն ստատիկ դարպասները և գործարկում `npm run test:unit` և `npm run test:vitest`:

Խափանվող ստատիկ դարպասը նորից գործարկվում է չհպված բազայի վրա, եթե առկա է բազային զոնդը: Սցենարը հաղորդում է ժառանգված ձախողումների մասին և շարունակվում է, երբ յուրաքանչյուր ճանաչված խախտման տող նույնպես հայտնվում է բազայի վրա, և ընդհանուր թիվը չի աճել:

| Ելք | Իմաստը                                                                                                                             |
| --- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `0` | Տպել է պլանը կամ լրացրել փաթեթը: Հավաքածուի ամփոփագրում թվարկված են ցանկացած ժառանգված ստատիկ խափանումներ և հեռացված PRs:          |
| `1` | Անվավեր արգումենտներ, Git-ի վճարում չկա, ձախողված նախավերթ կամ PR չի նստել:                                                        |
| `2` | Սուիթ ստուգումը ձախողվեց և չհամապատասխանեց որպես ժառանգական: Օպերատորը կարող է բաժանել խմբաքանակը, հեռացնել վիրավորող PR և կրկնել: |

Տեղական անցագիրը տրամադրում է ախտորոշիչ ապացույցներ միայն սեփականատիրոջ դոսիեի համար: Յուրաքանչյուր վայրէջք դեռ պահանջում է սեփականատիրոջ թույլտվություն, իր պահանջվող ստուգումները և ստվերային հերթի վճիռը, երբ կիրառելի է:

## Շերտավորում

- **Per PR.** CI և Quality-ն ընտրում են ստուգումներ՝ հիմնված փոխված ուղիների վրա: Code PRs ն գործարկում է արագ որակի դարպասներ և ազդակիր թեստեր՝ CI ում առանձին միավորի և Vitest աշխատատեղերով:
- **Հերթի թեկնածուին:** CI և Quality-ը գործարկում են կազմված թեկնածուի ամբողջական պրոֆիլը իր հերթագրում:
- **Մեկ թողարկման հուշում:** Release-Green-ը արագ կոշտ դարպասներ է բացում իր ուղու զտիչներին համապատասխանող հրումներով: Օրական երեք պլանավորված վազք օգտագործում է ամբողջական մաքրումը թողարկման ճյուղի համար:
