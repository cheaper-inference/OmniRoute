`@omniroute/opencode-plugin-v2` lisab kogu teie OmniRoute'i kataloogi — mudelid, kombinatsioonid ja
automaatsed kombinatsioonid — OpenCode v2 mudelivalijasse koos kuvatavate nimede, hinnastuse ning
tasuta kasutustaseme limiitidega.

See on paketist `@omniroute/opencode-plugin` eraldiseisev pakett, sest OpenCode v1 ja v2 laadivad
pistikprogramme erinevate lepingute kaudu. Valige oma OpenCode'i põhiversioonile vastav pakett;
need ei jaga omavahel midagi, mistõttu ühe uuendamine ei sunni kunagi teist uuendama.

## Nõuded

- OpenCode v2.
- Kättesaadav OmniRoute'i lüüs (vaikimisi `http://localhost:20128`).
- Node.js 22 või 24.

## Paigaldamine

Lisage pistikprogramm faili `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Seejärel kuvatakse mudelid kujul `omniroute/<provider>/<model>`; `providerId` määrab selle prefiksi ja
integratsiooni ID, mille alla OpenCode identimisteabe salvestab.

## Identimisteave

Pistikprogramm otsib lüüsi võtit kolmest kohast järgmises järjekorras:

1. **OpenCode'is ühendatud identimisteave.** Pistikprogramm registreerib integratsiooni, et
   OpenCode'i enda autentimisvoog saaks võtme salvestada. Faili `opencode.json` ei lisata midagi — eelistage seda.
2. Pistikprogrammi suvandites olev `apiKey` projektipõhiseks alistamiseks. See salvestab võtme faili,
   mille võite versioonihaldusse lisada.
3. Keskkonnas olev `OMNIROUTE_API_KEY`.

Kui ühtegi neist kolmest pole määratud, on kataloog tühi ning pistikprogramm teatab sellest käivitamisel
ühe korra, selle asemel et jätta teile vaikivalt tühi mudelivalija.

### Haldustõend on eraldi võti

Kombinatsioonid, pakkujate seisund ja rikastatud andmed (kuvatavad nimed, hinnastus ning tasuta kasutustaseme limiidid) pärinevad
lüüsi `/api/*` otspunktidest, mida enamik juurutusi kaitseb järelduspäringute võtme asemel **haldus**tõendiga:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

Kui `managementReadToken` jäetakse määramata, kasutatakse varuvariandina `apiKey` väärtust. Kui lüüs selle varuvariandi
tagasi lükkab, avaldatakse kataloog siiski, kuid kuvatavate nimede asemel kasutatakse mudelite toor-ID-sid,
kanooniliste aliaste duplikaate ei eemaldata ning hinnastus ja kombinatsioonid puuduvad. Pistikprogramm hoiatab sellisel juhul
iga otspunkti kohta ühe korra, nimetades otspunkti ja kaotsi läinud andmed — nii ei jää piiratud funktsionaalsusega mudelivalija kunagi mõistatuseks.

## Kuidas kataloog värske püsib

Kataloog tõmmatakse laisalt ja salvestatakse vahemällu `modelCacheTtlMs` jaoks ning ketta hetktõmmis hoiab viimase teadaoleva kataloogi saadaval, kui lüüsile ei pääse. — katkestus ei maksa teile muud kui värskust. Mudelid ja kombod avaldatakse kohe pärast nende saabumist; automaatkombinatsioonid, pakkujate loend ja rikastamise ülekate klapivad maandumisel sisse, nii et üks aeglane lõpp-punkt ei saa kogu valijat pantvangis hoida.

Nimed järgivad `Provider - Model[ (Editor)][ · budget][ (route)]`: pakkuja kuvatakse alati, kui ID kannab seda (kaldkriipsuta ID renderdab ilma eesliiteta), ees olev `🆓` tähistab vabu kirjeid ja nende vaba tasandi eelarve jääb `· 1M tokens/month` sufiksina, selgesõnalise `Editor: Model` `combo - <slug>` redaktor liigub lõppsulgu (muu nimetuseta redaktorit ei ole vaba ikoonina arvatakse ja kombitakse). Kaks kirjet, millel on ühine nimi, saavad marsruudi järelliide — `(no-think)` —, et need oleksid eristatavad. `providerTag` (vaikimisi `true`) lülitab redigeerija lõpus oleva sulgu sisse.

Käsitsi värskenduskäsku pole: OpenCode v2 käsud on viipamallid, mitte tagasihelistamised, nii et pistikprogramm ei saa seda paljastada. Värskendused järgivad TTL; hostil palutakse uuesti laadida ainult siis, kui kataloog või ülekate on tegelikult muutunud, mitte kunagi värskendamise ajal.

## Tööriistade väljakutsumine Geminis

Gemini lükkab tagasi kogu päringu, mille tööriistadeklaratsioonid sisaldavad atribuuti `$schema` või `additionalProperties`, vastates veaga `400 INVALID_ARGUMENT`. Pistikprogramm eemaldab need võtmesõnad selle pakkuja Gemini mudelile mõeldud tööriistaskeemidest ja jätab kõik muud päringud muutmata. `$ref`-i sisaldav tööriist edastatakse eemaldamise asemel muutmata kujul, sest viite eemaldamine laiendaks skeemi tähendusele „aktsepteeri kõike”.
Selle väljalülitamiseks määrake `"geminiSanitization": false`.

## Veaotsing

| Sümptom                                                            | Põhjus                                                                                                         |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Picker ei näita OmniRoute mudelit                                  | Ühtegi võtit ei lahendatud (kontrollige käivitushoiatust) või lüüs on kättesaamatu                             |
| Toores mudeli ID-d, kombinatsioonid puuduvad, hinnakujundus puudub | Halduse lõpp-punktid keeldusid märgi — komplektist `managementReadToken`                                       |
| Lühike või tühi `freeOnly` kataloog                                | Ükski haldusluba või keeldutud luba — luges hostilogis värskenduse kokkuvõtte rida (`unmatched-free` count)    |
| Seanss on `opencode-<id>/...` külge kinnitatud                     | v1 pistikprogramm avaldas `opencode-<id>`; v2 avaldab `<id>` paljalt, seega valige `<id>/...` alt mudel uuesti |

Keskkonnamuutujad peavad jõudma avatud koodi serveri protsessi: kui host töötab teenusena, on `opencode models` käivitav shell ja serverikeskkond erinevad, seega eksportige võti sinna, kuhu server seda loeb.
