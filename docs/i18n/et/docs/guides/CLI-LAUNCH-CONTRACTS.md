Neutraalne `config/cli-tools-manifest.json` leping deklareerib kanoonilist IDs, varjunimesid, binaarkandidaate, seadistusretsepte, mudeli argumendid ja võimalused. Tavaline Node adapter `bin/cli/cli-manifest.mjs` ja TypeScript adapter `src/shared/constants/cliIntegrationManifest.ts` loevad sama faili. Tööaega, kataloogi, konfigureerimist, lõpetamist, generaatoreid ja taustaprogrammi registreerimist kontrollib koos `tests/unit/cli/cli-manifest-drift.test.ts`. Kataloogis olemine ei tähenda, et tööriista saab käivitada või konfigureerida. Eelkõige jääb 5sukeldumine ainult konfigureerimiseks.

## Lapse keskkond ja elutsükkel

`omniroute run`, `omniroute launch` ja `omniroute launch-codex` pärivad OS/terminal ühilduvuse lubatud loendi ja sisestavad valitud sihtmärgi mandaadid. Mitteseotud pakkuja ja andmebaasi saladusi vaikimisi ei pärida. `--inherit-env` taastab selgesõnaliselt täieliku vanem-keskkonna pärandi; kasutage seda ainult siis, kui valitud kolmanda osapoole protsess peaks need väärtused vastu võtma. See on keskkonna filtreerimine, mitte OS liivakast: protsess töötab endiselt helistaja failisüsteemi lubadega.

Katkestus- ja lõpetamissignaalid edastatakse lapsele. Käivitaja ootab enne ajutise konfiguratsiooni eemaldamist lapse sulgemissündmust. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` juhib ajapikendusperioodi enne sundlõpetamist (vaikimisi 5000 millisekundit).

## Gemini püsiv seadistus

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

Esimesed kaks käsku konfigureerivad selle masina valitud kohaliku või kaugserveri jaoks. Seadistamine säilitab sõltumatud JSON -sätted, valib Gemini API-võtme autentimise ning kirjutab lõpp-punkti ja mandaadi privaatsesse `.gemini/.env` faili. See keeldub kehtetust JSON selle asemel, et seda üle kirjutada. Lõpp-punkt URLs peab olema HTTP(S), ilma mandaatideta, päringuparameetrite või fragmentideta. Kuivkäivitamisega prinditakse teed, mitte mandaadiväärtusi.

`GEMINI_CLI_HOME` või `--gemini-home` valib püsiva kodujuure. Tegelik `run gemini` loob ja hiljem eemaldab oma ajutise kodu. Kumbki režiim ei lähe mööda Gemini tööruumi usalduskontrollist.

## Codex profiilid

`configure codex` kirjutab privaatset `<name>.config.toml` koos mudeli ja selle OmniRoute pakkuja lõpp-punktiga. Mandaatidele viidatakse `OMNIROUTE_API_KEY` kaudu, mitte kunagi manustatud. Käivituskäsk määrab valitud mudeli ülataseme `model` klahvile, mitte `model_providers` sees.

Eraldi profiilifailid on praegune dokumenteeritud Codex leping; `codex --profile <name>` valikul katavad need kasutaja konfiguratsiooni. Vaadake [ametlikku profiiliviidet](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) ja [OmniRoute Codex juhendit](./CODEX-CLI-CONFIGURATION.md).

## Hermeetiline käsu täitmine

Selgesõnalise `DATA_DIR` korral takistab `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` seadistus käivitamisel langemast kasutajaandmete vaikekataloogi mandaadikeskkonda. See on kasulik isoleeritud testide jaoks. See ei keela teisi selgesõnaliselt valitud keskkonnafaile.

## Töökataloog `.env`

CLI loeb `.env` -faile selles järjekorras ja võidab esimene fail, mis määrab võtme: selgesõnaline `DATA_DIR`, vaikeandmete kataloog, praegune töökataloog ja seejärel paketikataloog. Shelli muutujad võidavad alati.

Töökataloog võib kuuluda kellelegi teisele (kloonitud hoidla, lahtipakkitud arhiiv) ja `omniroute serve` edastab CLI keskkonna serverile ja igale serveri käivitatavale tööriistale. Seega võib `.env` seada ainult need `bin/cli/utils/untrustedCwdEnv.mjs` loetletud võtmed:

| Võti                            | Aktsepteeritud väärtused                                                     |
| ------------------------------- | ---------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` või `yes` on igal juhul väärtused, mida server käsitleb kui sees |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | kuni 64 tähte, numbrit, `_`, `.`, `@` või `-`                                |
| `LANGUAGE`                      | sama, pluss `:`                                                              |
| `TZ`                            | kuni 64 tähte, numbrit, `_`, `+`, `-` või `/`, mis ei alga `/`               |
| `NO_COLOR`, `FORCE_COLOR`       | kuni 16 tähte ja numbrit                                                     |

Iga väärtus, mille `REQUIRE_API_KEY` aktsepteerib, lülitab kontrolli sisse, nii et fail ei saa seda ise välja lülitada. See aga ei otsusta tulemust: server loeb enne keskkonda andmebaasi salvestatud `REQUIRE_API_KEY` -alistust, samal ajal kui käivitushoiatus kõigi liideste kuulamise kohta ilma API -võtmeta loeb ainult keskkonda. Kui `false` on salvestatud, jätab töökataloog `REQUIRE_API_KEY=true` API avatuks ja peidab selle hoiatuse. `TZ` reegel on kitsam kui POSIX: see lükkab tagasi `.`, `:`, `,` ja `<>`, seega tuleb `:Area/City` vorm ja sellised reeglid nagu `EST5EDT,M3.2.0,M11.1.0` määrata kestas või `<DATA_DIR>/.env`.

Nimed peavad vastama täpselt, suurtähtedega. Kõik muud read, väärtus, mida ei kontrollita, ja nimi, mis ei ole tavalised ASCII tähed, numbrid ja `_` (nt NUL baidiga või sarnase tähega), jäetakse vahele. CLI prindib ühe hoiatuse, mis nimetab võtmed, mida ta ei saa määrata, ja ühe, mis annab nimed lubatud võtmetele, mida ta ignoreerib, kusjuures igaühel on kirjas, mida muuta (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Kumbki ei prindi väärtusi. Failiteed nendes sõnumites ja `.env` tee `omniroute doctor` aruannetes on paokood, kui need sisaldavad kontroll- või kahesuunalisi märke. Piirang ei kehti, kui töökataloog on andmekataloog või paketikataloog.

`PORT`, `API_PORT` ja `DASHBOARD_PORT` pole loendis. Ilma kõrgema tähtsusega allika URL baasita suhtleb CLI `localhost:<PORT>` ja kõik, mis seal kuulavad, saab CLI-i API võtme, kontekstimärgi ja CLI masina märgi (`x-omniroute-cli-token`, vt [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), mille kohalik server võtab vastu looppback-i halduskutseid. Töökataloogi port võimaldab sellel failil kuulaja valida, nii et määrake pordid kestas, `<DATA_DIR>/.env` is või käskude `--port` valikuga, millel on üks (`serve`, `launch`, `run`).

Parseril puudub `export` süntaks. Rida, näiteks `export LD_PRELOAD=...` nimetab muutujat `export LD_PRELOAD`; töökataloogist jäetakse see vahele ja teistes `.env` -failides määrab see sõnasõnalise nime, mida miski ei loe.

CLI seob konteksti salvestatud loa (pääsuluba või pärand API -võti) ainult selle konteksti päritoluga: skeemi, hosti ja pordiga, võrreldes `URL.origin`. See kehtib CLIHTTP kliendi (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) kaudu tehtud päringute kohta ning `launch`, `launch codex`, `configure` ja `setup-*` käskude kohta, mis kirjutavad URL baasi ja võtme teise tööriista konfiguratsiooni. Osutades teisele serverile `--remote` iga, kasutavad nad selgesõnalist `--api-key` või `OMNIROUTE_API_KEY` kui see on määratud, ja kontekstimärki pole. Võrdlus on täpne, seega loetakse `localhost` ja `127.0.0.1` või lõpupunktiga ja ilma selleta hosti erinevateks serveriteks ega saa kontekstimärki. Kasutajainfoga URL, kaldkriips või tühik ei sobi kunagi, sest teised URL parserid (näiteks Pythoni `urllib` ja `httpx`) saavad sellest lugeda erinevat hosti. Päringute puhul saadab CLI ise, see kontroll hõlmab ainult skeemi ja volitusi, nii et ID, mille teel või päringus on tühik, jätab märgi alles.
