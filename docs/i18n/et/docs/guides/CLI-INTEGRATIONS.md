Jagatud käivitatava manifesti, piiratud alamkeskkondade ja püsiva Gemini seadistuse kohta vaadake [jaotist CLI käivituslepingud](./CLI-LAUNCH-CONTRACTS.md).

OmniRoute saadab `setup-*` -käskude perekonda, mis konfigureerib kodeerimise CLI (Codex, Claude Code, OpenCode, Cline, …), et kasutada OmniRoute taustaprogrammina —, nii et tööriist räägib** üks** lõpp-punkti ja OmniRoute marsruudid õige pakkujani koos automaatse tagavaraga. Seadistuskäsud kasutavad teie aktiivset kohalikku või kaug- OmniRoute -konteksti ja konfigureerivad tööriista sisse** sinu** masin. Kataloogipõhised retseptid toovad mudelid serverist; ühe mudeli retseptid aktsepteerivad `--model` või küsivad mudelit ID. API klahvile viitab keskkonnamuutuja kõikjal, kus tööriist seda toetab. Allpool on märgitud käsud, mis püsivad tööriista kohaliku keskkonna failis.

Kataloog ja automatiseerimiskäsud hõlmavad erinevaid tööriistakomplekte:

| Pind                           | Count | Mida see tähendab                                                                           |
| ------------------------------ | ----- | ------------------------------------------------------------------------------------------- |
| Tööriistade kataloog           | 39    | Dokumenteeritud kodeerimistööriistad ja -agendid, sealhulgas käsitsi ja IDE integratsioonid |
| `omniroute run <target>`       | 8     | Käivitage adapterid, mis pakuvad sihtmärgi lõpp-punkti, mandaate ja mudelit                 |
| `omniroute configure <target>` | 12    | Interaktiivsed konfiguratsiooniretseptid, mida toetavad `setup-*` käsklused                 |
| `setup-*` käsud                | 16    | Registreeritud häälestuskäsud, sealhulgas guided/manual redaktori häälestus                 |

Arvud kajastavad [tööriista manifesti](../../config/cli-tools-manifest.json) ja [käsuregistrit](../../bin/cli/commands/registry.mjs) 2026-11-17. Kataloogikirje ei tähenda käivitusadapterit. Täieliku inventari leiate [CLI tööriistade kataloogist](../reference/CLI-TOOLS.md).

Samuti on olemas üldine kanderakett — `omniroute run <target>` —, mis loob `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen`, `gemini` või `whycodes` õige env-ga, ilma konfiguratsiooni kirjutamata. Sihtmärgid ja nende varjunimed pärinevad kanoonilisest manifestist `bin/cli/cli-manifest.mjs` (`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`, `open-code`, `qwen-code`, `gemini-cli`, `why-codes|why`) ja `omniroute completion` pakub samu manifestist tuletatud sihtsõnu. `omniroute launch <tool>` käivitab toetatud kodeerimistööriista käivituskohase seansimärgi ja mudeliloendiga, mis on koostatud teie ühendatud pakkujatest, ning käivitab automaatselt kohaliku lüüsi, kui ükski ei tööta (vt [LAUNCH.md](./LAUNCH.md) ). Pärand tööriistapõhised käivitusseadmed — `omniroute launch` ilma tööriista nimeta (Claude Code) ja `omniroute launch-codex` (Codex) — jäävad kättesaadavaks.

Pakkuja liitumine on saadaval samast local/remote kontekstist. Allpool olevad API-first käsud hoiavad halduse autentimise teenusepakkuja mandaatidest eraldi ega prindi kunagi mandaati struktureeritud väljundis:

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

Skriptide puhul eelista `--credential-stdin` või `--credential-env`; `--credential` säilitatakse kontrollitud kohalikuks kasutamiseks. `providers remove` nõuab `--yes` mitteinteraktiivses terminalis ja kõik viis käsku järgivad aktiivset konteksti või globaalseid `--base-url`/`--api-key` suvandeid.

Pakkuja valijad lükkavad tagasi mitmetähenduslikud ID eesliited, nimed või pakkujanimed; kasutage täisühendust ID kui mitu ühendust ühtivad. Loomise ja muutmise käsud loevad salvestatud ühenduse tagasi ja eemaldamine kinnitab, et see pole enam loetav. Import jätab olemasoleva provider/name paari vahele. Imporditud kirjed ei saa alistada CLI-le edastatud halduse lõpp-punkti, konteksti ega haldusmandaate.

Kahe kõige rikkalikuma integratsiooni ühekordse käsitsi kirjutatud põhiseadistuse kohta vaadake iga tööriista kohta tehtud süvasukeldumisi:

- [Claude koodi konfiguratsioon](./CLAUDE-CODE-CONFIGURATION.md)
- [Codex CLI konfiguratsioon](./CODEX-CLI-CONFIGURATION.md)
- [Kaugrežiim](./REMOTE-MODE.md) — juhtige oma sülearvutist kaug OmniRoute d (VPS / Tailnet).
- [VS Kood Copilot Vestlus](./VSCODE-COPILOT.md) — OmniCopilot laiendus; see võib neid `setup-*` -käske teie eest toimetada ka redaktorist

## Meistrilaud

Iga käsk austab** aktiivne kontekst** (seatud `omniroute connect`, vt [Kaugrežiim](./REMOTE-MODE.md) ) või selgesõnalisi `--remote <url> --api-key <key>` lippe. "Kohalik vs kaugjuhtimispult" tähendab allpool: ilma lippudeta sihib see `http://localhost:20128`; `--remote` (või aktiivse kaugkontekstiga) konfigureerib see selle serveri taustaprogrammiks ja kirjutab konfiguratsiooni lokaalselt. Märkused lippude kohta (kontrollitud käsuallikas):

- `--remote <url>` — kasutage kaug- OmniRoute (alistab `--port` ja aktiivse konteksti). `--api-key <key>` annab selle serveri mandaadi (vaikimisi `OMNIROUTE_API_KEY` env var või aktiivse konteksti tunnus).
- `--only <patterns>` — komadega eraldatud alamstringid; säilita ainult sobiv mudel IDs (nt `--only glm,kimi`). Saadaval seadmetes `setup-codex`, `setup-claude`, `setup-opencode`, `setup-continue`, `setup-cursor`, `setup-crush`, `setup-zed`.
- `--dry-run` — prindib täpselt seda, mis oleks kirjutatud ilma failisüsteemi puudutamata. Saadaval iga `setup-*` käsu puhul** välja arvatud** `setup-cursor` (mis ei kirjuta kunagi faili).
- `--model <id>` — on nõutav (või interaktiivselt valitud) tööriistade jaoks, millel pole mudeli automaatset tuvastamist: Cline, Kilo, Roo, Goose, Qwen, Gemini, Aider, 5dive, WhyCodes. Need tööriistad aktsepteerivad ka `--yes` mitteinteraktiivsete käitamiste jaoks (mis nõuab seejärel `--model`). `setup-opencode` kasutab `--model`, et määrata vaikimisi tipptasememudel.
- `--model <id>` `omniroute run` -s järgib manifesti sihtmärgipõhist juhtmestikku (`bin/cli/cli-manifest.mjs`):** abistaja** saab `--model openai/<id>` ja** avatud kood** `--model omniroute/<id>` (eesliide lisatakse ainult siis, kui id seda veel ei kanna);** qwen** ja** kaksikud** saada id sõna-sõnalt;** claude** saab selle `ANTHROPIC_MODEL` kaudu,** hani** `GOOSE_MODEL` kaudu,** miks koodid** `-P omniroute -m <id>` kaudu ja** koodeks** `-c model_providers.omniroute.*` args kaudu.**Qwen on ainus käivitatav sihtmärk, mis nõuab `--model`-d** — `omniroute run qwen` ilma selleta väljub `2` selge veaga.
- `--port <port>` — kohalik OmniRoute port (vaikimisi `20128`, ignoreeritakse, kui `--remote` on määratud). Esineb kõigis `setup-*` ja mõlemas kanderaketis.
- `omniroute run` väljumiskoodid: lapse CLI enda väljumiskoodi levitatakse sõna-sõnalt; `2` = kehtetud argumendid (toetamata sihtmärk, puudub nõutav `--model`, konteinerikaitse); `127` = sihtbinaar ei ole `PATH`; `130`/`143`/`129`, kui käivitamise lõpetab `SIGINT`/`SIGTERM`/`SIGHUP`; `1` = muu käitusaja käivitamise tõrge.
- Kaks käivitusprogrammi (`launch`, `launch-codex`) aktsepteerivad `--profile <name>`, et valida `setup-claude` / `setup-codex` kirjutatud profiil, millele lisanduvad `claude` / `codex` binaarfaili ülekandeargid.

Interaktiivset valijat jagavad ka seadistusretseptid:

```bash
# Pick from the active local or remote model catalog and configure the target.
omniroute configure claude
omniroute configure opencode --provider glm
omniroute configure qwen --model qwen/qwen3.8-max-preview --yes
omniroute configure gemini
omniroute configure whycodes
```

`configure` delegeerib praegu `codex`, `claude`, `opencode`, `qwen`, `gemini`, `aider`, `goose`, `cline`, `continue`, `kilo`, `5dive` ja `whycodes` testitud retseptidele . Ainult IDE-, MITM ja ainult juhistega kataloogikirjed jäävad selgesõnalisteks `setup-*`/manuaalseteks voogudeks ja neid ei esitata käivitatavate sihtmärkidena.

> `setup-opencode` on** kerge openai-ühilduv** OpenCode integratsioon. Samuti on olemas rikkalikum pluginate integreerimine — `omniroute setup opencode` —, mis installib `@omniroute/opencode-plugin`. Need on erinevad käsud; ülaltoodud tabel dokumenteerib `setup-opencode`.
>
> Pistikprogramm on saadaval kahes paketis, üks OpenCode majori kohta, kuna kaks laadijat ootavad erinevaid sisenemispunkte: `@omniroute/opencode-plugin` OpenCode v1 jaoks ja `@omniroute/opencode-plugin-v2` OpenCode v2 jaoks. Pakett v2 on uus (`0.1.0`) ja järgib endiselt liikuvat hostlepingut, nii et see loeb kuju OpenCode seemned kataloogi mustandisse, mitte ei eelda seda. Installige see, lisades `opencode.json`-sse kirje `plugins` ; `omniroute setup opencode` installib endiselt v1 paketi. Valikud ja mandaadi otsimise järjekord on pakendis README.

## Kohalik kasutus

Kui OmniRoute töötab aadressil `localhost:20128`, käivitage lihtsalt oma tööriista
seadistuskäsk. Kataloog hangitakse kohalikust serverist.

```bash
# Codex: kirjuta iga sobitatud mudeli jaoks profiil kataloogi ~/.codex/
omniroute setup-codex
codex --profile glm52            # kasuta loodud profiili

# Claude Code: kirjuta mudelipõhised profiilid ja käivita seejärel üks neist
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode: kirjuta openai-ühilduv pakkuja koos kõigi kataloogi mudelitega
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # viidatakse kujul {env:OMNIROUTE_API_KEY}, ei salvestata kunagi kettale
opencode -m omniroute/glm/glm-5.2 "..."

# Automaattuvastuseta tööriistad vajavad selgesõnaliselt määratud mudelit:
omniroute setup-aider --model glm/glm-5.2
omniroute setup-qwen --model qwen/qwen3.8-max-preview

# Eelvaade ilma midagi kirjutamata:
omniroute setup-continue --dry-run
```

Käivitage ilma ühtegi konfiguratsiooni kirjutamata (ainult keskkonnamuutujate sisestamine):

```bash
omniroute launch                 # Claude Code → kohalik OmniRoute
omniroute launch-codex           # Codex CLI → kohalik OmniRoute
omniroute launch-codex --profile glm52
omniroute run claude --model openai/gpt-5.4
omniroute run codex --model openai/gpt-5.4 --dry-run --json
omniroute run aider --model glm/glm-5.2 -- --message "vasta OK"
omniroute run goose --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "vasta OK"
omniroute run qwen --model glm/glm-5.2 -- -p "vasta OK"
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "vasta OK"

# Selgesõnaline käsutee: edasta muutmata kõik, mis järgneb märgile --
omniroute run claude -- --print-system-prompt "vaata see diff üle"
```

## Kaugkasutus

Suunake mis tahes seadistuskäsk kaugesse OmniRoute'i, kasutades `--remote` + `--api-key`.
Kataloog hangitakse kaugserverist ja konfiguratsioon kirjutatakse teie kohalikku masinasse.

```bash
# OpenCode kauge VPS-i vastu, säilita ainult glm/kimi mudelid
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx \
  --only glm,kimi
opencode -m omniroute/glm/glm-5.2 "..."   # ekspordi esmalt OMNIROUTE_API_KEY

# Codexi profiilid kaugkataloogist
omniroute setup-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Käivita CLI otse kaugserveri vastu
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

Selle asemel, et iga kord `--remote`/`--api-key` edastada, logige üks kord sisse ja
laske **aktiivsel kontekstil** need automaatselt määrata:

```bash
omniroute connect 192.168.0.15        # loob piiratud õigustega loa ja salvestab konteksti
omniroute setup-codex                 # ← kasutab nüüd kaugkataloogi
omniroute setup-opencode              # ← sama
omniroute launch                      # ← Claude Code kaugserveri vastu
```

Kontekstide, õigusalade ja lubade halduse kohta vaadake jaotist [Kaugrežiim](./REMOTE-MODE.md).

## 5 sukeldumisagendi laevastikku

[5dive](https://5dive.ai) juhib pikaajaliste kodeerimisagentide parki, millest igaüks on oma Unixi kasutaja alluvuses süsteemne üksus. See ei ole kodeeriv CLI ise, seega pole `omniroute run` jaoks midagi — käivitamiseks. `5dive` on** ainult konfigureeritav** sihtmärk.

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

Mõlemad vormid kirjutavad ühe 5 sukeldumise** autentimisprofiil** ja iga selle profiiliga seotud `claude` iste räägib seejärel OmniRoute-ga. Selle eesmärgi jaoks on iseloomulikud kolm asja:

- **See töötab masinapargi hostis juurna.** 5sukeldumise verbid toimivad kohalikes süsteemsetes üksustes ja juur-omanduses osariigis; kaugrežiimi pole. Retsept käivitatakse uuesti `sudo` kaudu, kui see pole veel juurkasutaja (`--no-sudo` lülitab selle välja ja prindib selle asemel käsu).
- **Lõpp-punkt peab olema `https://` välja arvatud juhul, kui see on loopback.** Agendi API klahv kasutab seda URL iga taotluse korral ja 5dive keeldub tavatekstist väljaspool kasti lõpp-punkti. Privaatne LAN aadress ei ole erand.
- **Iga istme enda mudelinõel ületab profiili.** Profiilil on `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL`, kuid endiselt aktsiamudeli ID-ga kinnitatud iste ebaõnnestub esimesel pöördel _"Valitud mudeliga on probleem"_. Pass `--agent <name>` (korduv), et kinnitada ka istmed; retsept prindib käsu, kui te seda ei tee.

API võti antakse 5sukeldumisele sisse** stdin** (`--api-key=-`), nii et seda ei kuvata kunagi `ps` väljundis.

Profiili suunamine OmniRoute poole** kombineeritud** Autopargi pakkuja tõrkesiirde tagab pigem ühe mudeli kui ühe mudeli: kui esmane lõpp-punkt langes [#11578](https://github.com/cheaper-inference/OmniRoute/issues/11578) salvestatud käitamise keskpaigas kõvasti alla, lõpetas agent oma ülejäänud sammud varurežiimil ega tuvastanud katkestust.

## Natiivsete sõltuvuste säilitamine värskendamisel: `--include=optional`

Kui värskendate käsuga `omniroute update` (pärast kinnitamist või lipuga `--apply`),
käivitab OmniRoute paigalduse alati koos lipuga `--include=optional`:

```bash
npm install -g omniroute@latest --include=optional
```

See **ei ole** lipp, mille peate käsule `omniroute update` edastama — värskendaja
rakendab selle alati. See tagab, et `optionalDependencies` (`better-sqlite3`, `keytar`,
`tls-client`, LLMLingua SLM-i pinu) säilivad värskendamisel isegi siis, kui teie npm-i
konfiguratsioonis on määratud `omit=optional`, mis muidu eemaldaks märkamatult natiivse
SQLite'i draiveri ja operatsioonisüsteemi võtmerõnga seose. Täpse käsu eelvaatamiseks ilma seda rakendamata:

```bash
omniroute update --dry-run
# [KUIVKÄIVITUS] Käivitataks: npm install -g omniroute@latest --include=optional
```

Muud `omniroute update` lipud (lähtekoodist kontrollitud): `--check` (väljumiskood 1,
kui versioon on aegunud), `--apply` (paigalda kinnitust küsimata), `--changelog`, `--no-backup`,
`--yes`.

## Google Gemini CLI käsu `omniroute run gemini` kaudu

Leping on kontrollitud paketiga `@google/gemini-cli` 0.50.0: CLI arvestab muutujaga
`GOOGLE_GEMINI_BASE_URL` ja saadab selle aadressile päringu `POST /v1beta/models/<model>:generateContent`
(ning `:streamGenerateContent?alt=sse`) — täpselt OmniRoute'i natiivsele
Gemini liidesele (`/v1beta`). `omniroute run gemini` seadistab selle automaatselt:

- `GOOGLE_GEMINI_BASE_URL` → aktiivne OmniRoute'i baas-URL (juuraadress, ilma `/v1`-ta);
- `GEMINI_API_KEY` → lahendatud OmniRoute'i pääsutunnus (suvand/keskkond/kontekst);
- **ajutine isoleeritud `GEMINI_CLI_HOME`**, mille `.gemini/settings.json`
  valib autentimiseks `gemini-api-key`, et salvestatud Google OAuthi seanss (Code Assist)
  ei alistaks kunagi OmniRoute'ile suunatud käivitust — eemaldatakse pärast väljumist;
- **keskkonnahügieen**: alamprotsessi keskkonnast eemaldatakse `GOOGLE_API_KEY`,
  `GOOGLE_GENAI_USE_VERTEXAI` ja `GOOGLE_GENAI_USE_GCA` (mis suunaksid
  autentimise ümber Vertexile/Code Assistile) ning täiendava turvameetmena määratakse
  `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key` — teisi `run`-i sihtmärke
  käsitletakse nende vastuoluliste muutujate puhul samamoodi;
- parameetri `--model <id>` lisamine suvandist `--provider`/`--model`.

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

Gemini tööruumi usaldamise kaitse kehtib endiselt ilma kasutajaliideseta režiimis — lisage
ise `--skip-trust` (või usaldage kataloogi interaktiivselt); käivitaja
ei lähe sellest tahtlikult mööda. See käivitaja erineb **ACP
registreerimisest** (`src/lib/acp/registry.ts`, `gemini --acp`), mis jääb
agendiprotokolli integratsiooniks lehel `/dashboard/acp-agents`.

## Tegelik suitsutestide läbivaatus (valikuline)

Deterministlikud käivitusplaani regressioonitestid töötavad CI-s (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`). TEGELIKE binaarfailide valideerimiseks TEGELIKU
OmniRoute'i serveri vastu on saadaval valikuline testiraamistik failis
`tests/integration/upstream-cli-smoke.int.test.ts`. Seda ei käivitata kunagi automaatselt
(kõik alamtestid jäetakse vahele, kui `RUN_CLI_SMOKE=1` pole määratud), autentimisandmed edastatakse keskkonnamuutuja
NIME kaudu (mitte kunagi väärtusena), võtmekujulised stringid eemaldatakse kogu salvestatud väljundist,
sihtmärgid, mille binaarfail pole installitud, jäetakse vahele ning tõrked liigitatakse kategooriatesse
autentimine / ülesvool / konfiguratsioon, mitte pelgaks kahendväärtuseks:

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

Valikuline: `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` piirab läbivaatust;
`OMNIROUTE_SMOKE_TIMEOUT_MS` alistab sihtmärgipõhise 120-sekundilise ajalõpu.
