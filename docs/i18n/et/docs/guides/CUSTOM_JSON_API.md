Kohandatud JSON API sõlm ühendab JSON -äri lõpp-punkti, mis ei räägi OpenAI või Anthropic protokolli. OmniRoute täidab JSON päringu malli, saadab selle täielikule lõpp-punktile URL, loeb vastuse vastuse teelt ja tagastab selle kliendile kliendi enda vormingus (vestluse lõpetamised, vastused, sõnumid jne).

See on OpenAI-ga ühilduv sõlm, millel on `apiType: "custom-json"`; selle id on kujul `openai-compatible-custom-json-<suffix>`. Armatuurlaua vorm pole veel saadaval. Looge ja redigeerige need sõlmed alloleva teenusepakkuja-sõlme API kaudu.

## Loo sõlm

`POST /api/provider-nodes` (juhtkonna autentimine):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` on** täielik** lõpp-punkt URL. Midagi ei lisata (no `/chat/completions`, no `/models`) ja erinevalt teistest OpenAI-ga ühilduvatest sõlmedest pole vaikimisi URL. See peab olema `http(s)`, ilma manustatud mandaatideta või `#fragment`, ja see läbib sama väljamineva URL kaitse nagu iga pakkuja sõlm nii sõlme salvestamisel kui ka iga päringu korral.
- Sõlm, mis saadab ühenduse võtme (`authType` `bearer` või `api-key`, sealhulgas vaikeseade), peab kasutama `https://`. Tavaline `http://` on aktsepteeritud ainult loopback hosti (`localhost`, `127.0.0.0/8`, `::1`) või `authType: "none"` puhul, mis ei saada võtit. Privaatsed LAN -aadressid (`10.x`, `172.16-31.x`, `192.168.x`) ei ole vabastatud: igaüks selles võrgus võib võtit lugeda. Sellise sõlme salvestamine nurjub `400` abil ja varem salvestatud sõlm suletakse iga sama sõnumiga päringu korral enne päringu saatmist. LAN võtmega lõpp-punkti jaoks asetage see TLS taha (näiteks pöördpuhverserver).
- `customJson` on kinnitatud Zod ga; tundmatud võtmed lükatakse tagasi. Iga väli on valikuline:

| Väli              | Väärtused                                  | Vaikimisi                                              |
| ----------------- | ------------------------------------------ | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                     | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                | `bearer`                                               |
| `authHeader`      | päise nimi, mida kasutatakse kui `api-key` | `X-API-Key`                                            |
| `requestTemplate` | JSON objekt (≤ 64 KB, sügavus ≤ 32)        | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | põllurada ehk `$` kogu keha jaoks          | `choices[0].message.content`                           |

- Saladus jääb ühenduse API võtmesse, mitte kunagi malli. `bearer` saadab `Authorization: Bearer <key>`; `api-key` saadab `<authHeader>: <key>`. Auth-päis ei saa olla `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` ega hüppeliselt päis. `none` puhul pole ühendused võtit vaja.
- Ekstra staatilised päised kasutavad sõlme tavalist `customHeaders` (sama valideerimine nagu igal teisel ühilduval sõlmel; autentimispäised pole seal lubatud).

`PUT /api/provider-nodes/<id>` aktsepteerib sama `customJson` ja kirjutab ümber `baseUrl` ja konfiguratsiooni igas sõlme olemasolevas ühenduses. `customJson` väljajätmine säilitab salvestatud konfiguratsiooni; `apiType` ümberlülitamine `chat` või `responses` eemaldab selle sõlmest ja selle ühendustest.

Seejärel lisa ühendus sõlmega nagu tavaliselt (`POST /api/providers` sõlme ID-ga) ja küsi `<prefix>/<model>`, näiteks `biz/assistant-v1`. Lõpp-punkt ei näita mudelite loendit, seega lisage mudeli ID-d käsitsi.

## Taotle malle

Mallid on tavalised JSON. Stringi väärtus võib sisaldada `{{placeholder}}` markereid; midagi ei hinnata ega käivitata ning objektivõtmeid ei asendata kunagi.

| Kohatäide            | Väärtus                                                              |
| -------------------- | -------------------------------------------------------------------- |
| `{{prompt}}`         | Viimase kasutajateate tekst (tekstiosad on ühendatud reavahetustega) |
| `{{messages}}`       | Vestlus OpenAI vestlusvormingus                                      |
| `{{model}}`          | Taotletud mudeli ID ilma pakkuja eesliiteta                          |
| `{{stream}}`         | Alati `false` — lõpp-punkti vastused ühe JSON dokumendiga            |
| `{{request.<path>}}` | Tõlgitud (OpenAI vestlusvormingus) taotluse väli                     |

- Väärtus, mis on täpselt üks kohahoidja, säilitab oma JSON tüübi (`"{{messages}}"` muutub massiiviks); tekstina lisatakse pikema stringi sees olev kohatäide.
- Kohatäide, mis ei lahenda midagi, lükkab HTTP 400 päringu läbi, selle asemel et saata mittetäielik koormus.
- Teed kasutavad punktitähistust ja numbrilisi indekseid (`data.items[0].text`). `__proto__`, `prototype` ja `constructor` lükatakse võtmetes ja radades tagasi.

## Vastused

`responsePath` väärtusest saab abivastus: stringid läbivad, teised JSON väärtused järjestatakse. Puuduv või `null` väli või keha, mis ei ole JSON, tagastab HTTP 502. Ülesvoolu veaolekud edastatakse. Voogesitusklientide puhul ootab OmniRoute kogu JSON vastust ja väljastab selle siis ühe sisutükina pluss viimistlustüki; see ei ole märgi voogesitus. Tööriistakutsed ja kasutusväljad ei ole kaardistatud.

## Pole kordagi taasesitatud

Äritaotlusel võivad olla kõrvalmõjud isegi siis, kui see ebaõnnestub. Seetõttu saadab OmniRoute selle ühe korra:

- transpordi uuesti proovimist ja ümbersuunamise jälgimist pole;
- ei proovi uuesti teisel ühendusel (konto varundamine) — tõrge tagastatakse sellisel kujul ja ühendust ei jahutata;
- ei mingit tagasiminekut järgmisele kombineeritud sihtmärgile, isegi tühja või ebaõnnestunud vastuse korral.

Eraldi kliendipäringud ja liitpaneelid, mis kutsuvad selgesõnaliselt mitut mudelit, kutsuvad lõpp-punkti siiski iseseisvalt.

## Sõlme testimine

Ühenduse salvestamine, ühendus** Test** nuppu ja tausta tervisekontrollid ei kutsu kunagi lõpp-punkti: nad kinnitavad ainult salvestatud konfiguratsiooni ja teatavad ühendusest kui kontrollimatust.

`POST /api/provider-nodes/validate` koos `"apiType": "custom-json"` ja sõlmeväljadega (`baseUrl`, `apiKey`, `customJson`, valikuline `customHeaders` ja `modelId`) saadab täpselt ühe reaalse päringu, mille kasutajatekst on `ping`. See vastab `{ "valid": true }` või ülesvoolu olekule (mitte kunagi ülesvoolu kehale).

## Säilitamine

Konfiguratsioon salvestatakse `provider_nodes.custom_json_config_json` -sse (migratsiooni `240_provider_node_custom_json_config.sql`) ja kopeeritakse iga ühenduse kausta `providerSpecificData.customJson`.

Rakendamine: `open-sse/utils/customJson.ts` (valideerimine ja mallimine), `open-sse/executors/customJson.ts` (käivitaja), `open-sse/services/combo/noReplayLatch.ts` ja `src/sse/handlers/chat/responsePolicies.ts` (taasesitamine).
