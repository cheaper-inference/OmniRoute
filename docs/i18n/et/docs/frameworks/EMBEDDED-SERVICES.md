### Hallatud puhverserveri tuumad

Kohandatud puhverserveri hostiväli aktsepteerib ka V2Ray allika linki. Valige** laulukast** või** röntgen** selgesõnaliselt, seejärel klõpsake nuppu Salvesta. Tippimine ei laadi kunagi alla ega käivita tuuma. Salvestamine kontrollib ametlikku väljalaskearhiivi, kinnitab algkonfiguratsiooni, käivitab eraldiseisva localhost SOCKS kuulaja ja alles seejärel kirjutab puhverserveri registri määrangu. Ebaõnnestunud aktiveerimine taastab eelmise hallatud konfiguratsiooni ja protsessi. `STORAGE_ENCRYPTION_KEY` on nõutav; allika lingid on krüpteeritud.

Hallatavad failid asuvad `DATA_DIR/services/managed-proxy/` all, TPROXY st eraldi. Valitud tuuma kohta on üks protsess, kuni 100 kuulajat. Autostarti ega globaalse marsruutimise vaikeseadet ei muudeta. Edukas salvestamine jätab meelde ainult selle hallatud tuuma aktiveerimise; rakenduse käivitamisel taastatakse lubatud salvestatud tuumad, kasutades juba kinnitatud binaarfaili, mitte kunagi alglaadimisaegset allalaadimist. Selgesõnaline Stop kustutab selle aktiveerimislipu. Puuduv või kahjustatud binaar nõuab allika uuesti salvestamist. Registri kustutamine eemaldab allika ja kuulaja kohapeal; Tavalised lõpp-punkti muudatused lükatakse hallatud ridade puhul tagasi, nii et salvestatud allikas ei saa vaikselt oma marsruutitud kuulajast eemalduda.

| Lähtevorming                              | laulukast                                                                  | röntgen                                                                    |
| ----------------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| VLESS, VMess, troojalane, Shadowsocks URI | Toetatud konversioon                                                       | Toetatud konversioon                                                       |
| Hysteria2/hy2, TUIC, AnyTLS URI           | Toetatud konversioon                                                       | Tagasi lükatud; kasutage ühilduvat südamikku                               |
| TCP/raw, WebSocket, gRPC, HTTPUpgrade     | Toetatud VLESS/VMess/Trojan jaoks                                          | Toetatud VLESS/VMess/Trojan jaoks                                          |
| XHTTP URI transport                       | Tagasi lükatud                                                             | Toetatud konversioon                                                       |
| Algne väljaminev JSON                     | Valitud tuuma lubatud puhverserver protocols/options, kontrollitud algselt | Valitud tuuma lubatud puhverserver protocols/options, kontrollitud algselt |

Tundmatud juhtmevalikud, ebaturvalised TLS lipud, välised pistikprogrammid, kohaliku failitee valikud ja toetamata kombinatsioonid lükatakse pigem tagasi kui vaikselt kõrvale. Natiivsed objektid on väljaminevad määratlused, mitte kogu tuuma konfiguratsioonid; control/direct/bypass väljaminekuid ei aktsepteerita. Sing-box 1.14 WireGuard kasutab lõpp-punkte, seega ei aktsepteerita seda loomuliku väljaminevana. See ei ole kõigi vormingute konverter; SSR, pärand whole-base64 Shadowsocksi lingid, suvalised Clashi objektid ja tabelist puuduvad transpordivariandid vajavad eraldi toetatud lähtevormingut.

`/api/services/managed-proxy` on autentitud ja ainult tagasisilmus: GET loetleb redigeeritud metaandmed, POST salvestab `{core,name,sourceLink,id?,assignment?}`, PATCH aktsepteerib `{core,action:"start"|"stop"}`. Olemas peab olema hosti usaldusväärne partnertempli konveier. Põhiline põhidiagnostika on alla surutud, kuna see võib sisaldada mandaate; elutsükli sündmused kasutavad olemasolevat struktureeritud rakenduste faililogerit ilma lähtelinkideta või ülesvoolu kasulike koormusteta. Toe saamiseks lisage ainult puhastatud rakenduste logid. Ametlikud versioonid on kinnitatud sing-box 1.14.3 ja Xray 26.3.27 koos release-asset SHA-256 manifestidega; tulevased värskendused nõuavad versiooni ja kõigi kinnitatud kokkuvõtete koos muutmist.

│    Returns 503 service_not_running if supervisor not in "running". │
│                                                                    │
│  src/shared/constants/providers.ts                                 │
│    Entry for "9router": isEmbeddedService: true                    │
│                                                                    │
│  open-sse/config/providerRegistry.ts                               │
│    Models stored as "9router/{sub}/{model}" (prefixed).            │
│    Synced every 5 min by modelSync.ts.                             │
│                                                                    │
│  Mux is lifecycle-managed ONLY (Layers 1-3) — it is an agent-       │

## 3. Elutsükli olekumasin

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
           seisundikontroll korras  │         krahh / SIGTERM    │
                               ┌────▼─────┐  (väljub 5 s jooksul)│
                               │ running  │──── krahh ──────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

Olekud salvestatakse andmebaasi tabelisse `version_manager` (veerg `status`) ja neid
peegeldatakse `ServiceSupervisor`-i mälusiseses olekus. Töötava protsessi korral on
autoriteetne mälusisene olek; andmebaasi olek on algkäivitamisel kasutatav püsiv varuvariant.

### Olekute üleminekud

| Lähteolek       | Sündmus                            | Sihtolek               |
| --------------- | ---------------------------------- | ---------------------- |
| `not_installed` | `install()` õnnestub               | `stopped`              |
| `stopped`       | kutsutakse `start()`               | `starting`             |
| `starting`      | seisundikontroll tagastab 200      | `running`              |
| `starting`      | protsess väljub enne korrasolekut  | `error`                |
| `running`       | kutsutakse `stop()`                | `stopping` → `stopped` |
| `running`       | protsess väljub ootamatult (< 5 s) | `error` (kiire krahh)  |
| `running`       | protsess väljub ootamatult (> 5 s) | `error`                |
| `error`         | kutsutakse `start()`               | `starting`             |
| mis tahes       | `stop()`, kui olek on `stopping`   | toiminguta             |

### Toimingulukk

`ServiceSupervisor` jadastab elutsükli toimingud asünkroonse toiminguluku
(`withLock()`) kaudu. Sama järelevaataja samaaegsete `start()`-kutsete korral
käivitatakse täpselt üks protsess; teine kutsuja ootab ja tagastab olemasoleva oleku.
See hoiab ära võistlusolukorrad, kui näiteks automaatkäivitus ja kasutajaliidese nupp
aktiveeruvad samal ajal.

### 4.9 Pöördpuhverserver (9ruuteri armatuurlaua manustatud)

Armatuurlaud manustab 9Router web UI iframe'i sisemise pöördpuhverserveri kaudu aadressil:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

See puhverserver:

- Edastab päringu `http://127.0.0.1:{port}/{path}` (ainult loopback)
- Eemaldab sissetulevad `cookie` ja `authorization` päised ( OmniRoute seansi leke puudub)
- Sisestab `Authorization: Bearer {apiKey}` 9-ruuteri autentimiseks
- Eemaldab vastusest `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*`
- Kirjutab HTML vastused ümber, et sisestada `<base href>` ja normaliseerida absoluutsed teed (`/foo` → `/dashboard/.../embed/foo`)

Manustatud armatuurlaua WebSocket versiooniuuendusi haldab kaasserver spetsiaalses pordis (vt `src/lib/services/embedWsProxy.ts`).

**Turvalisus:** Manustatud puhverserveri marsruudid on klassifitseeritud `LOCAL_ONLY_API_PREFIXES` alla ja neile pääseb juurde ainult loopback kaudu. Ründaja, kes saab JWT Cloudflare/Ngrok tunneli kaudu, ei saa manustatud teenustesse puhverserverit kasutada.

## 5. Turvalisus

### LOCAL_ONLY jõustamine (range reegel #17)

Kõik marsruudid asukohtades `/api/services/` ja `/dashboard/providers/services/*/embed/` on
failis `src/server/authz/routeGuard.ts` klassifitseeritud kui LOCAL_ONLY. Tagasisideaadressi kontroll
käivitatakse tingimusteta enne mis tahes autentimisharu:

```
päring saabub
  → isLocalOnlyPath(path)?
      → pole tagasisideaadress → 403 LOCAL_ONLY (alati, enne autentimise kontrolli)
      → tagasisideaadress      → jätka tavapärase autentimisega
```

See takistab lekkinud JWT-l (nt tunneli kaudu) käivitada toimingut `npm install` või
protsesside loomist. Täieliku tasemete maatriksi leiate failist
`docs/security/ROUTE_GUARD_TIERS.md`.

### API-võtme sisestamine

9Router ja Mux nõuavad oma HTTP-lõpp-punktide jaoks API-võtit / kandjatõendit.
OmniRoute:

1. Genereerib võtme käsuga `crypto.randomBytes(32).toString("base64url")`, kasutades
   teenusepõhist prefiksit (`nr_` 9Routeri jaoks, `mx_` Muxi jaoks).
2. Krüpteerib selle salvestamisel AES-256-GCM-iga (sama šiffer, mida kasutatakse teenusepakkuja identimisteabe jaoks).
3. Dekrüpteerib ja sisestab selle protsessi käivitamisel keskkonnamuutujana —
   `NINEROUTER_API_KEY` 9Routeri jaoks, `MUX_SERVER_AUTH_TOKEN` Muxi jaoks (mitte kunagi CLI
   lipuna, mistõttu tõendit ei kuvata käsu `ps` väljundis ega protsessiloendites).
4. Ei tagasta kunagi lihttekstivõtit üheski HTTP-vastuses.

CLIProxyAPI saab käivitamisel spetsiaalse andmekihi võtme
(`needsApiKey: true` — kasutatakse mudelite sünkroonimiseks adapteriga).

### Kaitse SSRF-i vastu

HTTP pöördpuhverserver (`/dashboard/.../embed/[...path]`) on püsikodeeritud edastama
päringuid ainult aadressile `http://127.0.0.1:{port}`. See ei järgi kunagi ümbersuunamisi
sihtkohtadesse, mis pole tagasisideaadressid. Teeki `ssrf-req-filter` kasutatakse kõigi
ülesvoolu-URL-ide tagasilükkamiseks, mis lahenduvad väljapoole tagasisideaadresside vahemikku.

### Kestprogrammi turvalisus (range reegel #13)

`npm install` käivitatakse kujul `execFile('npm', ['install', pkg, '--prefix', dir])` —
ilma malliliteraalide, kestprogrammi või väliste teede käsustringi interpoleerimiseta.
Käitusaegsed väärtused (pordid, API-võtmed) edastatakse alamprotsessi objekti `env` kaudu.

### Vigade puhastamine (range reegel #12)

Kõik `/api/services/*` veavastused läbivad funktsiooni `buildErrorBody()` või
`sanitizeErrorMessage()`. Töötlemata `err.stack` ja `err.message` väärtusi ei tagastata
helistajale kunagi sõna-sõnalt.

## 7. Tõrkeotsing

### Teenus ei käivitu

**Sümptomid:** Käivitusnupp tagastab 503, olek jääb väärtusele `"error"` või `"starting"`.

**Kontrollnimekiri:**

1. Kontrollige päringut `GET /api/services/{name}/logs` (või juhtpaneeli logipaneeli). Otsige
   ridu, nagu `Error: ENOENT`, `address already in use` või `Cannot find module`.
2. Veenduge, et `npm` oleks PATH-is: käivitage `which npm` sama kasutajakonto alt, mille all OmniRoute töötab.
3. Veenduge, et teenus oleks installitud: kontrollige päringust `GET /api/services/{name}/status`
   välja `installedVersion`. Kui selle väärtus on `null`, käivitage esmalt installimine.
4. Kontrollige, et `DATA_DIR/services/{name}/node_modules/` oleks olemas ega oleks tühi.
5. Kontrollige olekuvastuse väljalt `lastError` puhastatud väljumispõhjust.

---

### Külmkäivitus on aeglane (olekuni `running` jõudmine võtab > 10 s)

**Sümptomid:** Olek püsib kaua väärtusel `"starting"`, enne kui muutub väärtuseks `"running"` või `"error"`.

**Selgitus:** 9Routeri külmkäivitus hõlmab suurte sõltuvuspuude (DNS-i,
tunneli- ja MITM-moodulite) importimist. Vaikimisi on tervisekontrolli intervall 2 s ja enne
järelevaataja ajalõputeate väljastamist tehakse 3 katset (kuid kontrollimist jätkatakse).

**Lahendus:** `healthIntervalMs` ja `waitForHealthy` ajalõpp
(`healthIntervalMs * 3`) on failis `bootstrap.ts` seadistatavad. Pikema
käivitusajaga teenuste puhul suurendage `healthIntervalMs` väärtuseni 5000 ja `stopTimeoutMs` väärtuseni 30 000.

---

### Pordikonflikt (`EADDRINUSE`)

**Sümptomid:** Logides kuvatakse `address already in use :::20130`.

**Põhjused:**

- Mõni muu protsess kasutab juba porti 20130.
- Eelmist 9Routeri protsessi ei peatatud täielikult (zombi-PID).

**Lahendus:**

1. Muutke vaikeporti `.env`-failis keskkonnamuutuja `NINEROUTER_PORT` kaudu.
2. Leidke konfliktne protsess ja lõpetage see: `lsof -ti :20130 | xargs kill -9`.
3. Porti saab failis `bootstrap.ts` iga teenuse jaoks välja `port` kaudu seadistada.

**Märkus:** 9Router kasutab vaikimisi porti 20130, et vältida konflikti
OmniRoute'i vaikepordiga 20128.

---

### Installimisel puudub juurdepääsuõigus (EACCES)

**Sümptomid:** Installimine tagastab 500, logides kuvatakse `EACCES` või `permission denied`.

**Põhjused:**

- OmniRoute'i protsessil puudub kataloogi `DATA_DIR` või selle ülemkataloogi kirjutusõigus.
- Käitamine juurkasutajata Dockeris ilma ühendatud kettale kirjutamise õiguseta.

**Lahendus:**

1. Kontrollige kataloogi `DATA_DIR` (vaikimisi `~/.omniroute/`): `ls -la ~/.omniroute/`
2. Veenduge, et kataloog kuuluks kasutajale, kelle all OmniRoute'i protsess töötab: `chown -R $USER ~/.omniroute/`
3. Veenduge Dockeris, et andmeköite ühendusel oleksid konteineri kasutaja jaoks õiged õigused.

---

### Värskendamine nurjub (`npm install` ajalõpp või võrgutõrge)

**Sümptomid:** Värskendamine tagastab 500 koos veaga `InstallError`, logides kuvatakse võrgu ajalõpp.

**Kontrollnimekiri:**

1. Veenduge, et npm-i register oleks kättesaadav: `npm ping`.
2. Kontrollige ettevõtte puhverserveri seadeid: `npm config get proxy`, `npm config get https-proxy`.
3. Proovige installida käsitsi: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. Kui internetiühendus puudub, laadige tarball eelnevalt alla ja kasutage käsku `npm install /path/to/tarball.tgz`.

---

### Teenuse olekuks kuvatakse kohe pärast käivitamist `"error"` (kiire krahh)

**Sümptomid:** Olek muutub väärtuselt `"starting"` väärtuseks `"error"` vähem kui 5 sekundiga.
Väljal `lastError` kuvatakse `"Fast crash (exited with code 1)"`.

**Kontrollnimekiri:**

1. Lugege täielikku logilõppu: `GET /api/services/{name}/logs?tail=500`.
2. Levinud põhjus: teenuse nõutavad keskkonnamuutujad puuduvad.
3. 9Routeri puhul veenduge, et `NINEROUTER_DISABLE_MITM=true` ja
   `NINEROUTER_DISABLE_TUNNEL=true` oleksid käivitamisel edastatavas keskkonnas (vt
   `installers/ninerouter.ts` funktsiooni `resolveSpawnArgs`).

## 8. KKK

**K: Kas ma saan teha manustatud teenuste lõpp-punktid kättesaadavaks klientidele, kes ei kasuta tagasisideaadressi?**

Ei. LOCAL_ONLY tase on tahtlik (range reegel nr 17). Marsruudid, mis saavad käivitada
`npm install` või luua `node` protsesse, ei tohi olla kättesaadavad liiklusele, mis ei
pärine tagasisideaadressilt, sest tunneli (Cloudflare, Ngrok, Tailscale) kaudu lekkinud JWT
võimaldaks vastasel juhul suvalisi protsesse luua. `/api/services/` jaoks puudub
sellest loobumise erand — erinevalt marsruudist `/api/mcp/` on see haldusõiguse
kontrollist möödumise loendist välja jäetud. Vt `docs/security/ROUTE_GUARD_TIERS.md`.

---

**K: Kas 9Router ja CLIProxyAPI on saadaval tootmis- või pilvekeskkondades?**

Jah. Mõlemad teenused järgivad sama kohalik-kõigepealt mudelit nagu OmniRoute ise. Need
töötavad samas masinas ja suhtlevad tagasisideaadressi kaudu. „Tootmiskeskkond“ tähendab
siin VPS-i või kohalikku serverit, kuhu OmniRoute on juurutatud, mitte kaugpilveteenuse
pakkujat.

---

**K: Kuidas järelevaataja tööd siluda?**

1. Jälgige SSE logivoogu: `curl -N http://localhost:20128/api/services/9router/logs`.
2. Kontrollige OmniRoute'i pino väljundis olevaid struktureeritud logisid, filtreerides
   nimeruumi `service:supervisor` järgi.
3. Uurige andmebaasirida: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. Kasutage päringut `GET /api/services/9router/status`, et näha ühe kutsega praegust
   reaalajas olekut, PID-d, seisundit ja välja `lastError`.

---

**K: Järelevaataja näitab `health: "degraded"` või `health: "unknown"`, kuid olek on `"running"`. Kas see on probleem?**

`"degraded"` tähendab, et seisundikontroll tagastas vastuse, mille kood ei olnud 200.
`"unknown"` tähendab, et ükski kontroll pole veel lõpule jõudnud (võidujooks esimese
küsitlusega). Mõlemad on käivitamise ajal ajutised. Kui seisund püsib väärtusel
`"degraded"` kauem kui `healthIntervalMs * 3` ms pärast oleku `"running"` saavutamist,
siis manustatud teenus töötab, kuid selle HTTP API ei vasta. Kontrollige, kas olekuvastuses
olev port on õige ja kas teenus tegelikult kuulab sellel pordil.

---

**K: Kas ma saan 9Routeri API-võtit muuta ilma täieliku taaskäivituseta?**

Ei. API-võti edastatakse 9Routerile protsessi loomise ajal keskkonnamuutuja kaudu.
Töötava protsessi keskkonnamuutujaid ei saa muuta. `POST .../rotate-key` peatab teenuse
automaatselt ja käivitab selle uuesti, et uus võti rakendada. Võtme vahetamine jõustub
teenuse `stopTimeoutMs` aja (vaikimisi 15 s) ja sellele lisanduva käivitusaja jooksul.

---

**K: Kui suur on ringpuhvri piirang ja mis juhtub selle täitumisel?**

Igal teenusel on eraldi 5 MB ringpuhver. Kui puhver saab täis, eemaldatakse vanimad
logiread, et teha ruumi uutele. SSE sündmus `snapshot` tagastab piirangu `tail` piires
kõige uuemad read. Logisid ei salvestata kettale, kui andmebaasireal pole määratud
`logsBufferPath`.
