AgentBridge on OmniRoute'i MITM-puhverserver (vahendusrünne ehk Man-in-the-Middle), mis püüab kinni IDE tehisintellektiagentide HTTPS-liikluse ja suunab selle ümber OmniRoute'i ühtse marsruutimismootori kaudu. See toetab **10 IDE agenti** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code ja Trae (uurimisel) — tehes OmniRoute'ist turu kõige laiema katvusega MITM-puhverserveri tehisintellektipõhistele programmeerimisabilistele.

**Juhtpaneeli asukoht:** `/dashboard/tools/agent-bridge`
**Külgriba rühm:** Tööriistad (pärast jaotist Pilveagendid)
**Vaata ka:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — jälgi kogu kinnipüütud liiklust reaalajas; `docs/security/MITM-TPROXY-DECRYPT.md` (git; ei kompileerita kataloogi `/docs`) — Linuxi TPROXY läbipaistev dekrüptimisega hõiverežiim, mida juhib marsruut `/api/tools/agent-bridge/tproxy`.

## §1 Ülevaade

### Mis on AgentBridge?

Kui IDE agent (nt GitHub Copilot, Cursor, Claude kood) teeb API -kõne, ühendub see otse ülesvoolu AI pakkujaga (OpenAI, Anthropic jne). AgentBridge katkestab selle ühenduse läbipaistvalt TLS tasemel – ilma agendi konfiguratsiooni muutmist nõudmata – ja kirjutab päringu ümber OmniRoute kaudu.

See tähendab, et saate:

- **Suunake mis tahes agent mis tahes teenusepakkuja juurde** : Copilot räägid OpenAI-ga? Suunake see ümber Anthropic Claude, Gemini või mõnele OmniRoute 377 pakkujale.
- **Rakendage mudeli vastendusi** : `gemini-3-flash` → `claude-sonnet-4.7` läbipaistvalt käitleja tasemel.
- **Jälgige kogu agendiliiklust** : iga pealtkuulatud päring avaldatakse [liiklusinspektorile](./TRAFFIC_INSPECTOR.md).
- **Rakendage OmniRoute vastupidavust** : kombineeritud marsruutimine, kaitselülitid, varud ja kulude jälgimine ka IDE agendi liikluse jaoks.

## §2 Arhitektuur

### 2.1 Komponentide ülevaade

```
IDE agent (VS Code / Cursor / jne)
    │  HTTPS (port 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS-i ümbersuunamine
    │
    ▼
src/mitm/server.cjs  (port 443, CJS-i alamprotsess)
    │  tuvastab sihtkoha Host-päise SNI järgi
    │  genereerib iga SNI jaoks AgentBridge'i CA allkirjastatud TLS-serdi
    ├── Möödaviiguloendi vaste? → TCP otseühendus (dekrüptimist ei toimu)
    ├── Sihtkoha vaste? → fetch → OmniRoute'i marsruuter (port 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() päringu kehal/päistel
    │               ├── TrafficBuffer.push() — avaldab liiklusinspektorile
    │               └── fetchRouter() → /v1/chat/completions
    └── Vastet pole? → TCP otseühendus (dekrüptimist ei toimu)
```

### 2.2 MITM-server (`src/mitm/server.cjs`)

Põhiline MITM-server töötab Node.js-i CJS-i alamprotsessina (et vältida olemasoleva CJS-koodibaasi ümberkirjutamist). See:

- Kuulab porti 443 (vajab eriõigusi või `authbind`/`setcap`)
- Võtab operatsioonisüsteemilt vastu CONNECT-tunneleid (`/etc/hosts`-i DNS-i ümbersuunamise kaudu)
- Genereerib iga SNI jaoks AgentBridge'i CA (`DATA_DIR/mitm/ca.crt`) allkirjastatud TLS-serdid
- Tuvastab sihtagendi Host-päise järgi registri `targets/index.ts` kaudu
- Edastab päringud TypeScripti töötlejakihile HTTP kaudu aadressil `http://127.0.0.1:20128`

`TARGET_HOSTS` laaditakse failist `DATA_DIR/mitm/targets.json` (mille `targets/index.ts` käivitamisel kirjutab), võimaldades dünaamilisi uuendusi ilma CJS-serverit taaskäivitamata.

> **Juur-CA mudel (#6684).** Eespool kirjeldatud iga SNI jaoks CA allkirjastatud serdi
> mudel on muudatuses #6684 lisatud püsiv juur-CA mudel (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, mis taaskasutab TPROXY jaoks failis
> `src/mitm/tproxy/dynamicCert.ts` juba tõestatud CA-/lõppserdi krüptograafiat) — see asendab
> varasema ühe staatilise iseallkirjastatud lõppserdi (`src/mitm/cert/generate.ts`, mille
> ulatus piirdub endiselt ainult antigravity hostidega), mille olemasolule viitab kettal olev
> failipaar `server.crt`/`server.key`. **Migreerimiskäitumine**: värske install (varasema
> `server.crt`-ita) saab juur-CA mudeli automaatselt; install, mis juba
> usaldas vana staatilist lõppserti, jätkab selle kasutamist seni, kuni operaator määrab
> `MITM_ROOT_CA_ENABLED=true` ja taaskäivitab silla (`src/mitm/cert/migration.ts`
> on puhas otsustusfunktsioon — usaldatud MITM-i CA, mis saab allkirjastada lõppserdi
> **mis tahes** hostile, on oluliselt võimsam kui vana fikseeritud SAN-idega lõppsert, mistõttu
> juba usaldatud installi puhul ei toimu üleminek kunagi vaikimisi). CA-sert installitakse
> samasse usaldusväärsuse hoidla pessa `omniroute-mitm.crt`, mida kasutas vana lõppsert
> (`cert/install.ts::installCaCert`) — topeltusalduse puhastamist pole vaja.

### 2.3 Töötleja baasklass (`src/mitm/handlers/base.ts`)

Kõik agentide töötlejad laiendavad klassi `MitmHandlerBase`:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Kaitstud abimeetodid: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Iga töötleja kutsub enne proksimist välja `hookBufferStart()` ja pärast lõpetamist `hookBufferUpdate()`. Need lisavad kirjed `InterceptedRequest` globaalsesse puhvrisse `globalTrafficBuffer` (vt [Liiklusinspektor](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Sihtkohtade register (`src/mitm/targets/`)

Igal agendil on deklaratiivne sihtkohafail:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Register (`targets/index.ts`) ekspordib `ALL_TARGETS` ja loob käivitamisel faili `DATA_DIR/mitm/targets.json`.

### 2.5 Otseühendus ja möödaviiguloend (`src/mitm/passthrough.ts`)

**Möödaviiguloend** (kontrollitakse esimesena ja sellel on sihtkoha vaste ees prioriteet):

- Vaikemustrid: panganduse hostid, `.gov.`, OAuth-/SSO-pakkujad (Okta, Auth0) jne
- Kasutaja mustrid: talletatakse andmebaasitabelis `agent_bridge_bypass`
- Möödaviidavad hostid saavad läbipaistva TCP-tunneli — TLS-i **ei dekrüptita kunagi**

**Vaikimisi otseühendus** (sihtkoha vastet pole ja host pole möödaviiguloendis):

- Saab samuti TCP-tunneli — ühendusi ei katkestata kunagi
- Takistab AgentBridge'il üldist süsteemi HTTPS-liiklust häirimast

Marsruutimise prioriteet:

```
möödaviiguloend → sihtkoha vaste → otseühendus
```

### 2.6 Ülesvoolu CA-sert (`src/mitm/upstreamTrust.ts`)

Kohandatud CA-ga ettevõtte võrgukeskkondade jaoks:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Kui see on määratud, konfigureerib see `undici` globaalse dispetšeri täiendava CA-serdiga, võimaldades AgentBridge'il jõuda ülesvoolu teenusepakkujateni ettevõtte TLS-i lõpetavate prokside kaudu.

### 2.7 Saladuste maskeerimine (`src/mitm/maskSecrets.ts`)

Sõltumatut puhasruumi skannerit rakendatakse päringu kehadele ja mandaadipäistele
**enne**, kui need jõuavad liiklusinspektori puhvrisse või mis tahes logisse. See teeb ühe lineaarse läbimise:

- Eesliitega `sk-` / `ak-` / `pk-` sõned (OpenAI/Anthropicu laadis)
- RFC 6750 `Authorization: Bearer <token>` mandaadid, eelistades terviklikku sõnet
- Üldised pikad läbipaistmatud sõned (≥40 märki), sealhulgas punktidega ja täitemärkidega vormid

`sanitizeHeaders()` teisendab allesjäetud nimed väiketähtedeks, ühendab massiivväärtused deterministlikult, eemaldab
ühise hüppelt-hüppele-/raamistuspäiste keeluloendi (sealhulgas proksi autentimise), redigeerib täielikult päised `cookie` ja
`set-cookie` ning delegeerib mandaadiväärtused skannerile.

## §3 Seadistamine

### 3.1 MITM-serveri käivitamine/peatamine

Kasutage AgentBridge'i serverikaarti asukohas `/dashboard/tools/agent-bridge`:

| Toiming                      | Kirjeldus                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Käivita server               | Käivitab faili `src/mitm/server.cjs` pordil 443. Juur-CA mudeli korral loob see esimesel käivitamisel faili `ca.crt` ja lisab aktiivse sertifikaadi usaldusväärsete hulka, kui sudo parool on saadaval                                                                                                                                                                                                                                      |
| Peata server                 | Sulgeb alamprotsessi korrektselt                                                                                                                                                                                                                                                                                                                                                                                                            |
| Taaskäivita server           | Peatab ja käivitab uuesti (rakendab sihtmärgi muudatused ja uuesti genereeritud sertifikaadi)                                                                                                                                                                                                                                                                                                                                               |
| Usalda sertifikaati          | Installib aktiivse sertifikaadi operatsioonisüsteemi usaldushoidlasse: juur-CA mudeli korral `DATA_DIR/mitm/ca.crt`, pärand-lehtsertifikaadiga installi korral `DATA_DIR/mitm/server.crt`                                                                                                                                                                                                                                                   |
| Laadi sertifikaat alla       | Laadib aktiivse sertifikaadi käsitsi installimiseks alla (`omniroute-mitm-ca.crt` = `ca.crt` või pärand-lehtsertifikaadiga installi korral `omniroute-mitm.crt` = `server.crt`)                                                                                                                                                                                                                                                             |
| Genereeri sertifikaat uuesti | Ei muuda kunagi sertifikaadimudelit. Pärand-lehtsertifikaadiga install: väljastab uued `server.crt`/`server.key` failid (nende kasutuselevõtuks taaskäivitage server). Juur-CA mudel: roteerib failid `ca.crt`/`ca.key`; serveri töötamise ajal toimingust keeldutakse. Vana usaldatud CA eemaldatakse esmalt usaldusväärsete hulgast (vajab sudo parooli) või roteerimine katkestatakse. Seejärel peavad kliendid uut CA-d uuesti usaldama |

### 3.2 Sertifikaadi usaldamine

Enne kui IDE-d MITM-ühenduse aktsepteerivad, peab operatsioonisüsteem AgentBridge'i CA-sertifikaati usaldama.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Või kasutage töölaual nuppu „Usalda sertifikaati” (käivitab teie operatsioonisüsteemile sobiva käsu ja kuvab vajaduse korral sudo parooli viiba).

#### Electronil põhinevad IDE-d eiravad operatsioonisüsteemi usaldushoidlat (`NODE_EXTRA_CA_CERTS`)

Mõned IDE-d — eelkõige **Antigravity IDE** ja teised Electronil / VS Code'il põhinevad rakendused — sisaldavad oma Node.js-i käituskeskkonda, mis **ei kasuta operatsioonisüsteemi usaldushoidlat** väljaminevate `fetch`/HTTPS-päringute jaoks. CA usaldamine operatsioonisüsteemi/NSS-i tasemel on piisav IDE loomuliku **taustaprotsessi** jaoks (nt Go keeleserver, mis kasutab operatsioonisüsteemi CA-kimpu), kuid **Electroni kasutajaliideses** esineb endiselt TLS-i tõrge — rakendus näib olevat _välja logitud_ või kuvab _„ühenduse tõrke”_, kuigi MITM-i logi näitab, et taustaprotsessi alglaadimispäringud tagastavad `200`. Vajalikud on kaks toimingut ja mõlemad on olulised:

1. Suunake käituskeskkond otse CA-le:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **Käivitage IDE sellest kestast.** Töölauaikooni / Docki / Start-menüü kaudu käivitamisel
   kestamuutujaid **ei pärita** ja `~/.config/environment.d/*.conf` rakendub alles pärast
   uut graafilist sisselogimist. Sulgege IDE esmalt täielikult — Electroni üksikeksemplari lukk
   tähendab, et teine käivitus toob lihtsalt olemasoleva protsessi esiplaanile ja uut keskkonda eiratakse.

Ülaltoodud operatsioonisüsteemi usaldamise + NSS-i toiming on endiselt vajalik (mõne autentimisvoo kasutatav Chromiumi võrgupinu loeb kasutajapõhist NSS-i hoidlat ja sellel on oma staatilised kinnistused domeeni `*.googleapis.com` jaoks, mille kohalikult usaldatud CA alistab). `NODE_EXTRA_CA_CERTS` katab lisaks Node'i `fetch`-tee.

### 3.3 DNS-marsruutimine

Iga agendi puhul, mille liiklust soovite pealt kuulata, peavad selle API-hostid lahenema aadressiks `127.0.0.1`. AgentBridge haldab `/etc/hosts` kirjeid automaatselt, kui lülitate seadistusviisardis agendi DNS-i sisse või välja.

GitHub Copiloti `/etc/hosts` kirjete näide:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Mudelite vastendamine

Kasutage iga agendikaardi mudelite vastendamise tabelit, et määratleda lähte- → sihtmudeli vastendused:

| Lähte mudel (agendi omamudel) | Sihtmudel (OmniRoute) |
| ----------------------------- | --------------------- |
| `gpt-4o`                      | `claude-sonnet-4.7`   |
| `*` (metamärk)                | `claude-haiku-4.7`    |

Metamärk `*` vastendab iga tundmatu mudeli määratud sihtmudeliga. Salvestatakse tabelisse `agent_bridge_mappings`.

> **Nõuanne — tehke kindlaks agendi tegelikud mudeli-ID-d.** IDE võib saata mudelinimesid, mis erinevad
> selle kasutajaliidese siltidest ja muutuvad põhiversioonide vahel. Näiteks saadab **Antigravity 2**
> võrgu kaudu `gemini-3.1-pro-low`, `gemini-pro-agent` ja `gemini-3.1-flash-lite` — mitte vanemates
> dokumentides näidatud `gemini-2.5-pro`. Saatke üks vestlus ilma sobiva vastenduseta: MITM
> logib täpse sissetuleva `model:` väärtuse ja edastab päringu muutmata kujul. Vastendage see sõnasõnaline väärtus ning
> järgmine päring peetakse kinni ja suunatakse teie sihtmärgile.

### 3.5 Riskiteade

AgentBridge püüab kinni identimisteabe (OAuthi tokenid, API-võtmed), mida IDE kasutab autentimiseks ülesvoolu teenusepakkujate juures. See teave **maskeeritakse enne logimist** (vt §2.7), kuid on OmniRoute'i MITM-kihile nähtav. Iga agendi esmakordsel aktiveerimisel kuvatakse suletav riskiteate modaalaken.

### 3.6 Hooldus ja diagnostika

Töölaual on kaart **Hooldus ja diagnostika** (`AgentBridgeMaintenanceCard`, asukohas `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`), mis teeb kasutajaliideses kättesaadavaks MITM-i toimingumarsruudid, millel varem kasutajaliides puudus. Selle alapealkiri on: _„Testige andmehõivekonveierit, tühistage alles jäänud süsteemiolek ja teisaldage seadistus ühest masinast teise.“_ Kaardi kliendi abifunktsioonid asuvad failis `src/lib/inspector/agentBridgeMaintenanceApi.ts`.

| Nupp                         | Marsruut                               | Mida see teeb                                                                                                                                                                                              |
| ---------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Diagnoosi**                | `GET /api/tools/agent-bridge/diagnose` | Käivitab andmehõivekonveieri enesetesti ja kuvab iga kontrolli kohta aruande (✓/✗ + parandussoovitus).                                                                                                     |
| **Paranda**                  | `POST /api/tools/agent-bridge/repair`  | Tühistab krahhi või SIGKILL-i järel alles jäänud omanikuta MITM-i süsteemioleku (DNS-i võltsimiskirjed, juur-CA, süsteemi puhverserver). Idempotentne — puhta oleku korral teatab „Midagi pole parandada“. |
| **Eemalda CA**               | `DELETE /api/tools/agent-bridge/cert`  | Tühistab MITM-i juur-CA usalduse ja eemaldab selle OS-i usaldushoidlast (eksplitsiitne, idempotentne). Kuvatakse ainult siis, kui CA on praegu usaldatud; nõuab reasisest kinnitust „Kas eemaldada CA?“.   |
| **Ekspordi konfiguratsioon** | `GET /api/tools/agent-bridge/config`   | Laadib alla teisaldatava konfiguratsiooni JSON-i (vt §3.7).                                                                                                                                                |
| **Impordi konfiguratsioon**  | `POST /api/tools/agent-bridge/config`  | Laadib üles varem eksporditud konfiguratsiooni JSON-i (vt §3.7).                                                                                                                                           |

Igal agendikaardil on ka oma nupp **Taasta vaikeseaded** (`POST
/api/tools/agent-bridge/agents/{id}/reset`) — ühe klõpsuga agendipõhine tagasivõtmistoiming, mis eemaldab võltsimise ainult selle
agendi hostidelt, kustutab salvestatud mudelivastendused ning lähtestab selle `dns_enabled`/`setup_completed`
oleku, et IDE suhtleks pärast täielikku taaskäivitamist taas tegeliku ülesvooluteenusega. See **ei** mõjuta
jagatud MITM-serverit ega juur-CA-d (teised agendid võivad neist endiselt sõltuda) — need jäävad ligipääsetavaks
serverikaardi ja ülaltoodud toimingu **Eemalda CA** kaudu. Windowsis käivitatakse võimaluse korral ka
`ipconfig /flushdns`, sest Windowsi DNS-klient puhverdab hosts-faili kirjeid ega kustuta
äsja eemaldatud võltskirjet muidu.

**Diagnostikakontrollid** (`summarizeDiagnostics()` failis `src/mitm/inspector/diagnostics.ts`). Marsruut käivitab iga kontrolli jaoks kõrvalmõjudega sondi ja edastab kahendväärtused puhtale kokkuvõttefunktsioonile; tagastatakse üks `healthy` hinnang koos iga tõrke parandussoovitusega:

| Kontrolli nimi     | Mida see kontrollib                                    | Soovitus tõrke korral                                                                                                                                                  |
| ------------------ | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | MITM-serveri protsess on aktiivne                      | „MITM-server ei tööta. Käivitage see AgentBridge'i vahekaardilt.“                                                                                                      |
| `server-reachable` | MITM-server võtab oma pordil ühendusi vastu (TCP-sond) | „MITM-server ei võta oma pordil ühendusi vastu. Kontrollige, kas port on vaba ja kas teil on õigus seda siduda.“                                                       |
| `cert-exists`      | MITM-sertifikaat on kettale genereeritud               | „MITM-sertifikaati pole veel genereeritud. Genereerige see AgentBridge'i vahekaardilt.“                                                                                |
| `cert-trusted`     | MITM-i juur-CA asub OS-i usaldushoidlas                | „OS-i hoidla ei usalda MITM-i juur-CA-d, mistõttu TLS-i pealtkuulamine nurjub. Usaldage sertifikaati AgentBridge'i vahekaardil.“                                       |
| `dns-configured`   | Siht-hostinimed on failis `/etc/hosts` võltsitud       | „Siht-hostinimed pole failis /etc/hosts võltsitud, mistõttu liiklus ei jõua kunagi puhverserverisse. Lubage DNS nende agentide jaoks, mille liiklust soovite hõivata.“ |

**Omanikuta oleku bänner:** kui leht tuvastab krahhist maha jäänud oleku (DNS-i võltsimine / CA / süsteemi puhverserver), kuvab kaart merevaigukarva bänneri — _„Eelmine seanss jättis süsteemioleku alles (DNS-i võltsimine, CA või süsteemi puhverserver). Käivitage selle puhastamiseks parandamine.“_ — ja tõstab esile nupu **Paranda**. `Repair` on ProxyBridge'i lipu `--cleanup` rakenduskihi analoog (see delegeerib funktsioonile `repairMitm()` failis `src/mitm/manager.ts`).

> MITM-juur-CA jääb peatamiste ja käivitamiste vahel installituks, et vältida korduvaid sudo
> viipasid (sama käitumine nagu mitmproxy/Charles puhul), seega on selle eemaldamine eraldi
> toiming **Eemalda CA**, mitte miski, mis toimub peatamisel automaatselt.

### 3.7 Teisaldatava konfiguratsiooni import/eksport

AgentBridge saab **operaatori kohandatava** oleku serialiseerida versioonitud JSON-plokiks, et seadistust saaks eri masinates kopeerida. Serialiseerija asub failis `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`) ja seda valideerib `AgentBridgeConfigSchema`.

Eksport sisaldab täpselt kolme osa (sisseehitatud vaikeväärtusi tahtlikult **EI** ekspordita, et importimine neid kunagi ei dubleeriks ega nendega vastuollu satuks):

| Väli             | Allikas                                                         | Märkused                                                                |
| ---------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `bypassPatterns` | kasutaja määratud möödaviigumustrid (`agent_bridge_bypass`)     | panga-/riigiasutuste/Okta vaikemustrid jäetakse välja                   |
| `customHosts`    | Traffic Inspectori kohandatud hostid (`inspector_custom_hosts`) | igaüks: `{ host, kind: "llm"\|"app"\|"custom", label? }`                |
| `agentMappings`  | agendipõhised mudelivastendused (`agent_bridge_mappings`)       | `{ [agentId]: [{ source, target }] }` iga vastendusi omava agendi kohta |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Importimise käitumine** (`POST /api/tools/agent-bridge/config`): möödaviigumustrid ja agendipõhised vastendused **asendatakse täielikult**; kohandatud hostid lisatakse **idempotentselt** (`INSERT OR IGNORE`). Vastus näitab, mitu kirjet igast liigist rakendati:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Mida konfiguratsioon **EI** sisalda: serveri töötamise olek, serditeed, agendipõhine DNS-i olek, ülesvoolu CA tee ega TPROXY sätted — need on hosti/käituskeskkonna olek, mitte teisaldatavad eelistused.

### Tundlike hostide möödaviiguloend

Möödaviiguloend tagab, et finantsasutuste, OAuthi/SSO pakkujate ja muude tundlike hostide liiklust **ei dekrüptita kunagi**. Nende TLS-liiklus läbib süsteemi läbipaistva TCP-tunnelina — OmniRoute ei näe kunagi avateksti.

Vaikimisi möödaviigumustrid hõlmavad järgmist:

- `*.bank.*`, `*.gov.*` (finantsasutused/valitsusasutused)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/identiteet)
- `*.apple.com`, `*.icloud.com` (Apple'i süsteemiteenused)

Kasutaja lisatud möödaviigumustrid salvestatakse tabelisse `agent_bridge_bypass` ja need on kõigest muust ülimuslikud.

### Saladuste maskeerimine

Rakendatakse funktsiooni `maskSecrets()` failist `src/mitm/maskSecrets.ts`:

- Igale päringu kehale enne `TrafficBuffer.push()` väljakutsumist
- Igale päisele enne logimist või leviedastust

Mustrid: eesliitega `sk-`/`ak-`/`pk-` pääsmikud, `Bearer`-pääsmikud ja üldised vähemalt 40 märgi pikkused pääsmikud.

### Ülesvoolu CA-sertifikaat

Kui `AGENTBRIDGE_UPSTREAM_CA_CERT` on määratud, loetakse fail käivitamisel sisse. Kui tee on olemas, kuid fail pole loetav, logib AgentBridge selge vea ja keeldub käivitumast (see hoiab ettevõttekeskkondades ära varjatud TLS-tõrked).

### Teadaolevad piirangud

- **Port 443 nõuab eriõigusi**: Linuxis vajab AgentBridge Node'i binaarfailile käsku `setcap 'cap_net_bind_service=+ep'` või käitamist `authbind` kaudu. Seadistusviisard kuvab operatsioonisüsteemipõhised juhised.
- **IDE tuleb taaskäivitada**: pärast DNS-i ümbersuunamist tuleb IDE taaskäivitada, et uus hostinime lahendus jõustuks.
- **Püsikodeeritud OAuthi pääsmikud**: mõned agendid (Kiro, Antigravity) talletavad OAuthi värskenduspääsmikke kohapeal. Need on AgentBridge'i jaoks läbipaistvad — see näeb igas päringus Bearer-pääsmikku, mis enne logimist maskeeritakse.
- **Electroni kasutajaliidesed vajavad muutujat `NODE_EXTRA_CA_CERTS`**: IDE-d, mille kasutajaliides töötab komplekti kuuluvas Node'i/Electroni käituskeskkonnas, eiravad operatsioonisüsteemi/NSS-i usaldushoidlat ja need tuleb käivitada shellist, kus `NODE_EXTRA_CA_CERTS` on määratud (vt §3.2). Puuduva muutuja sümptom: IDE tagasüsteem autentib (MITM näitab vastuseid `200`), kuid kasutajaliides jääb väljalogituks.
- **Sama IDE mitu installi on üksteisest sõltumatud**: süsteemiinstall (nt `/usr/share/antigravity/antigravity`) ja kasutaja kohalik „Full”-install (nt `~/AntigravityIDE_Full/antigravity-ide`) on eraldi protsessid oma käituskeskkondadega — igaüks tuleb uuesti käivitada koos sisestatud CA-ga. Enne taaskäivitamist tuvastage binaarfaili tee järgi, milline neist töötab.
- **Identiteedi määrab agendi süsteemiviip, mitte marsruuditud mudel**: kui vastendate agendi mudeli ümber teisele pakkujale, väidab vastus endiselt, et tal on agendi algne identiteet (nt Antigravity vastab „Minu mootoriks on Gemini”), sest IDE sisestab selle süsteemiviipa. Kontrollige tegelikku tagasüsteemi tabelitest `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`), mitte mudelilt küsides, kes ta on.

## §6 Tõrkeotsing

### Pordi 443 konflikt

Kui mõni teine protsess juba kuulab porti 443 (veebiserver, VPN jne):

```bash
lsof -i :443          # leia protsess
sudo fuser -k 443/tcp  # sundlõpeta (kasuta ettevaatlikult)
```

Teise võimalusena seadista AgentBridge'i sätetes mitteprivilegeeritud port ning lisa `iptables` / `pf` ümbersuunamisreeglid.

### Sertifikaati ei usaldata

Kui IDE kuvab pärast AgentBridge'i käivitamist TLS-i tõrkeid:

1. Kontrolli, kas sertifikaat paigaldati: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) või `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Mõned rakendused haldavad oma usaldushoidlat (Firefox, Chrome Linuxis). Käivita „Trust Cert” uuesti ja kontrolli NSS-i/Firefoxi-spetsiifilist sertifikaadihoidlat.
3. Pärast usalduse määramist taaskäivita IDE — pooleliolevad TLS-seansid kasutavad vana usaldusolekut.

### IDE-st on välja logitud / „ühenduse viga” hoolimata usaldatud CA-st

Sümptom: pärast DNS-i ümbersuunamist ja CA usaldamist avaneb Electronil põhinev IDE (nt Antigravity)
**väljalogituna** või kuvab autentimis-/ühendusvea, kuigi MITM-i logi näitab, et
alglaadimiskutsed (`loadCodeAssist`, `fetchAvailableModels`, …) tagastavad `200`.

Põhjus: IDE-ga **kaasasolev Node'i/Electroni käituskeskkond eirab operatsioonisüsteemi usaldushoidlat**. Natiivne
taustateenus (Go keeleserver) usaldab operatsioonisüsteemi CA-d ja autendib, kuid Electroni kasutajaliides
seda ei tee — seetõttu peab kasutajaliides ennast võrguühenduseta olevaks.

Lahendus (mõlemad toimingud): ekspordi `NODE_EXTRA_CA_CERTS=<ca.crt>` **ja käivita IDE uuesti sellest
kestast**, mitte töölauaikoonilt. Sulge IDE esmalt täielikult — Electroni üksikeksemplari lukk tähendab,
et teine käivitus lihtsalt aktiveerib olemasoleva protsessi ning uut keskkonda eiratakse. Vaata §3.2.
See vastab avalikule ülesvoolu veateatele, mille kohaselt töötab eraldiseisev agent MITM-i kaudu, kuid IDE
variant nurjub sama seadistuse korral.

### DNS pole levinud

Kontrolli, kas `/etc/hosts` värskendati:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

Tühjenda DNS-i vahemälu:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE-d ei tuvastatud

Automaatne tuvastamine kasutab tavapäraseid paigaldusteid. Kui tuvastamine nurjub, kuid IDE on paigaldatud:

- Kontrolli, kas IDE kahendfail asub ebastandardses asukohas
- Seadistusviisard töötab endiselt — tuvastamise nurjumine tähendab vaid seda, et märk ei kuva paigaldusteed

### Töötleja tõrked (ülesvoolust toomine nurjub)

Kui AgentBridge püüab päringud kinni, kuid kõik päringud nurjuvad:

1. Kontrolli aadressil `/dashboard/providers`, et ühendatud oleks vähemalt üks teenusepakkuja
2. Kontrolli OmniRoute'i serveri logisid: `APP_LOG_LEVEL=debug` failis `.env`
3. Kontrolli, et `OMNIROUTE_BASE_URL` osutaks õigele ruuteri lõpp-punktile (vaikeväärtus: `http://127.0.0.1:20128`)

## §8 Teekaart

### Trae uurimine

Trae on suhteliselt uus tehisintellektil põhinev programmeerimisassistent. Enne töötleja rakendamist:

1. Tuvastage binaarfail/laiendus VS Code'i / JetBrainsi poodides või eraldiseisva rakendusena
2. Jäädvustage liiklus mitmproxy abil, et tuvastada API hostid ja lõpp-punktide struktuur
3. Tehke kindlaks autentimismehhanism
4. Hinnake kasutustingimuste ja API tuvastatavuse põhjal, kas jätkata või mitte

Kuni uurimine on lõpule viidud, kuvatakse Trae kaardil juhtpaneelil märk „Uurimisel“ koos lingiga „Teata teostatavusest“. Töötleja toes failis `src/mitm/handlers/trae.ts` väljastab struktureeritud vea `Pole veel rakendatud`.

### Ootel olevad agendid (MITM on nõutav — kohandatud baas-URL-i tugi puudub)

Järgmised tööriistad ei toeta oma praegustes versioonides kohandatud baas-URL-e, mistõttu on MITM ainus liikluse pealtkuulamise võimalus. Teostatavuse hindamine on ootel:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — Kiro IDE-st eraldiseisev)
- **Cowork** (Anthropicu töölauarakendus)

Märkus. GitHub Copilot CLI ≥v1.0.19 toetab muutujat `COPILOT_PROVIDER_BASE_URL` — selle tööriista puhul kasutage MITM-i asemel otsekonfiguratsiooni.
