OmniRoute integreerub kolme kategooria CLI-tööriistadega, mis on jaotatud kolme eraldi töölaualehe vahel:

| Leht            | Marsruut                | Põhimõte                                                                             | Arv          |
| --------------- | ----------------------- | ------------------------------------------------------------------------------------ | ------------ |
| **CLI-koodid**  | `/dashboard/cli-code`   | Kodeerimistööriistad, mille suunate OmniRoute'i (klient → CLI → OmniRoute → pakkuja) | 26           |
| **CLI-agendid** | `/dashboard/cli-agents` | Autonoomsed agendid, mille suunate OmniRoute'i (sama voog, laiem ulatus)             | 10           |
| **ACP-agendid** | `/dashboard/acp-agents` | CLI-d, mille OmniRoute käivitab stdio/ACP kaudu taustsüsteemina (vastupidine voog)   | vt registrit |

Pärandmarsruudid suunatakse 308 kaudu ümber: `/dashboard/cli-tools` → `/dashboard/cli-code`, `/dashboard/agents` → `/dashboard/acp-agents`.

## Kuidas see töötab

```
CLI-koodid / CLI-agendid (tarbimisvoog):
Claude / Codex / OpenCode / Cline / KiloCode / Continue / Hermes Agent / Goose / ...
           │
           ▼  (kõik suunatakse OmniRoute'i)
    http://YOUR_SERVER:20128/v1
           │
           ▼  (OmniRoute suunab päringu õigele pakkujale)
    Anthropic / OpenAI / Gemini / DeepSeek / Groq / Mistral / ...

ACP-agendid (vastupidine käivitusvoog):
    Kliendi päring → OmniRoute → käivitab CLI stdio/ACP kaudu → vastus
```

**Eelised:**

- Üks API-võti kõigi tööriistade haldamiseks
- Kõigi CLI-de kulude jälgimine töölaual
- Mudelite vahetamine ilma iga tööriista ümber seadistamata
- Töötab nii kohalikult kui ka kaugserverites (VPS, Docker, Akamai, Cloudflare Tunnel)

## Automaatne seadistamine käskudega `setup-*`

Iga tööriista konfiguratsiooni ei pea käsitsi kirjutama. OmniRoute sisaldab iga toetatud CLI jaoks käsku `setup-*`, mis loeb töötava OmniRoute’i (kohaliku või kaug-) **reaalajas** mudelikataloogi ja kirjutab teie masinasse tööriista enda konfiguratsiooni:

```bash
omniroute setup-codex        omniroute setup-claude       omniroute setup-opencode
omniroute setup-cline        omniroute setup-kilo         omniroute setup-continue
omniroute setup-cursor       omniroute setup-roo          omniroute setup-crush
omniroute setup-goose        omniroute setup-qwen         omniroute setup-aider
omniroute setup-5dive        omniroute setup-zed
```

Kõik käsud aktsepteerivad suvandeid `--remote <url> --api-key <key>` (kohaliku tööriista seadistamiseks kaug-OmniRoute’iga), `--dry-run` (eelvaade ilma kirjutamiseta) ja `--port`. Mudelite automaatse tuvastamiseta tööriistad (Cline, Kilo, Roo, Goose, Aider, Qwen, 5dive) võtavad suvandi `--model <id>` (ja mitteinteraktiivsete käivituste jaoks `--yes`). `setup-5dive` on ainus retsept, mis ei kirjuta asukohta `$HOME`: see seadistab 5dive’i agentide parve, kirjutades parve hosti juurkasutajale kuuluva autentimisprofiili, mistõttu käivitab see end uuesti käsu `sudo` kaudu ja sellel puudub oma kaugrežiim. CLI käivitamiseks õigesti sisestatud keskkonnamuutujatega ja ilma konfiguratsiooni kirjutamata kasutage üldist käivitajat `omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini — sihtmärgid ja aliased pärinevad failist `bin/cli/cli-manifest.mjs`); pärandkäivitajad `omniroute launch` (Claude Code) ja `omniroute launch-codex` (Codex) on endiselt saadaval. Gemini CLI-d saab ainult käivitada: see on käsu `omniroute run` sihtmärk, kuid sellel puudub `setup-*`/`configure`-retsept.

> **Täielik viide:** põhitabel — mida iga käsk kirjutab, kõik lipud, kohalik ja kaugrežiim ning millised tööriistad vajavad järelliidet `/v1` — asub jaotises
> **[CLI integratsioonid](../guides/CLI-INTEGRATIONS.md)**.

### Nende käskude käitamine konteineris

OmniRoute’i konteineris käivitatud käsk `setup-*` kirjutab konteineri enda kodukataloogi, mida ükski hosti CLI ei loe ja mis kaob koos konteineriga. OmniRoute tuvastab selle ning lõpetab kirjutamise asemel koodiga `2` ja kuvab juhised. Edasi liikumiseks on kaks toetatud viisi — installige CLI hosti ja looge konteineriga ühendus käsu `omniroute connect` abil või haakige konfiguratsioonikataloogid bind-mount-meetodil ja määrake `CLI_CONFIG_HOME` (compose’i profiil `host`). Iga käsk `setup-*`, samuti `omniroute configure` ja `omniroute config set`, aktsepteerib suvandit `--allow-container-write`, kui tegelikult soovitegi seadistada konteineri enda CLI-sid; serveri puhul teeb sama `OMNIROUTE_ALLOW_CONTAINER_CONFIG_WRITE=true`. Vaadake
[Dockeri juhend → Hosti CLI-tööriistade seadistamine](../guides/DOCKER_GUIDE.md#configuring-host-cli-tools-when-omniroute-runs-in-docker).

Töölaua **rakendamise lõpp-punkt** (`POST /api/cli-tools/apply`) jõustab sama kaitse: konteineris vastab hostist bind-mount-meetodil haakimata sihtkohta kirjutamise katse koodiga **`422`**, sisaldades väärtust `containerEphemeralTarget: true`, turvalist veateksti ning — hostiretseptiga tööriistade puhul (claude, codex, opencode, cline, kilo, continue) — väljal `hostSetupCommand` hostis käivitatavat käsku (nt `omniroute setup-opencode`); midagi ei kirjutata. `dryRun: true` töötab ka konteinerirežiimis ning tagastab redigeeritud eelvaate ja sihttee ilma ketast muutmata. Eelvaate sisu ei ole mandaate sisaldav konfiguratsioon, mida saaks kopeerida või importida. Rakendage algsete tööriista, baas-URL-i, API-võtme ja mudeli sisenditega hostis või kasutage näidatud hostipoolset seadistuskäsku. Eelvaate päise ja päringulepingu kohta vaadake dokumenti [CLI konfiguratsiooni turvalisus](../security/CLI-CONFIGURATION.md). Selline käitumine on tahtlik ja regressioonide eest kaitstud testiga `tests/unit/api/cli-tools/apply-container-guard.test.ts` — ärge kunagi „parandage” vastust 422 kaitse eemaldamisega.

## Tõeallikas

Ühtne kataloog asub failis `src/shared/constants/cliTools.ts` kujul `CLI_TOOLS: Record<string, CliCatalogEntry>`.

Igal kirjel on järgmised väljad (määratletud failis `src/shared/schemas/cliCatalog.ts`):

| Väli                                            | Tüüp                                                         | Kirjeldus                                                  |
| ----------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| `category`                                      | `"code" \| "agent"`                                          | Millisel lehel tööriist kuvatakse                          |
| `vendor`                                        | `string`                                                     | Tööriista päritolu ("Anthropic", "OSS (P. Gauthier)")      |
| `acpSpawnable`                                  | `boolean`                                                    | Kasutatav ka ACP Agent-ina (kuvatakse märk)                |
| `baseUrlSupport`                                | `"full" \| "partial" \| "none"`                              | Kohandatud lõpp-punkti toe tase. `"none"` = MITM-i tööjärg |
| `configType`                                    | `"env" \| "custom" \| "guide" \| "custom-builder" \| "mitm"` | Seadistusmehhanism                                         |
| `id`, `name`, `color`, `description`, `docsUrl` | standard                                                     | Peamised kuvamisväljad                                     |

Kirjeid, millel on `baseUrlSupport: "none"`, juhtpaneeli lehtedel **ei kuvata** — need on registreeritud plaani 11 MITM-i tööjärjekorras (vt `_tasks/features-v3.8.6/refactorpages/_orchestration/_plan11-mitm-backlog.md`).

### Võimekustasemed (kataloogitud × tuvastatav × seadistatav × käivitatav)

Mitte iga kataloogitud tööriist pole tuvastatav, seadistatav või käivitatav. Igal tasemel on üks
määratlev allikas ning kõrvalekalletest kontrolliv test hoiab need sünkroonis:

| Tase             | Tähendus                                                                                    | Määratletud failis                                               |
| ---------------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| **Kataloogitud** | Kuvatakse juhtpaneeli kataloogis (nimi, tarnija, dokumentatsioon, seadistuse tüüp)          | `src/shared/constants/cliTools.ts` (`CLI_TOOLS`)                 |
| **Tuvastatav**   | Binaarfaili/seadistuse tuvastamine, tervisekontrollid, seadistuste asukohad                 | `src/shared/services/cliRuntime.ts` (`CLI_TOOLS` käituskataloog) |
| **Seadistatav**  | Toetatud käsuga `omniroute configure <cli>` (seadistusretsept on olemas)                    | `bin/cli/cli-manifest.mjs` (`configure: true`)                   |
| **Käivitatav**   | Toetatud käsuga `omniroute run <target>` (keskkonna/argumentide sisestamine on määratletud) | `bin/cli/cli-manifest.mjs` (`run: true`)                         |

`bin/cli/cli-manifest.mjs` on CLI käsuliideste kanooniline täitmismanifest:
`run`, `configure` ja käsurea automaatse lõpetamise generaatorid tuletavad sellest kõik oma
sihtloendid, aliaste lahendamise (näiteks `kilocode`/`kilo-code`/`kilo_cli` → `kilo`)
ning lipu `--model` sidumise. Kõrvalekallete kontroll
`tests/unit/cli/cli-manifest-drift.test.ts` kinnitab, et manifest, käituskataloog,
kasutajaliidese kataloog ja kõik tarbijaliidesed püsivad sünkroonis — ühele
liidesele ilma teisteta lisatud siht põhjustab testikomplekti nurjumise, mitte märkamatu kõrvalekalde.

## 5. Pakktuvastuse API

Kõigi tööriistade tuvastamine koondatakse ühe lõpp-punkti kaudu:

**`GET /api/cli-tools/all-statuses`**

- Autentimine: `requireCliToolsAuth(request)` (sama nagu teistel `/api/cli-tools/` marsruutidel)
- Tagastab: `Record<toolId, ToolBatchStatus>` (tüüp: `src/shared/types/cliBatchStatus.ts`)
- Strateegia: `Promise.all` kõigi tööriistade jaoks, iga tööriista ajalõpp 5 s
- Vahemälu: mälusisene LRU, mis indekseeritakse konfiguratsioonifaili `mtime` järgi. Vahemälu tühistatakse, kui mtime muutub. Lähtestatakse serveri taaskäivitamisel.

Vastuse struktuur tööriista kohta:

```ts
interface ToolBatchStatus {
  detection: {
    installed: boolean;
    runnable: boolean;
    version?: string;
    command?: string;
    commandPath?: string;
    reason?: string;
  };
  config: {
    status: "configured" | "not_configured" | "not_installed" | "unknown" | "other";
    endpoint?: string | null;
    lastConfiguredAt?: string | null;
  };
  error?: string; // puhastatud, pinu tagasijälgi pole
}
```

## 10. Sisemine OmniRoute’i CLI

Binaarfail `omniroute` pakub käske serveri elutsükli, seadistamise, diagnostika ja teenusepakkujate haldamiseks. Sisenemispunkt: `bin/omniroute.mjs`.

```bash
omniroute                              # Käivita server (vaikeport 20128)
omniroute setup                        # Interaktiivne seadistusviisard
omniroute doctor                       # Kontrolli konfiguratsiooni, andmebaasi, porte ja käituskeskkonda
omniroute providers list               # Konfigureeritud teenusepakkujaühendused
omniroute providers test-all           # Testi kõiki aktiivseid ühendusi
omniroute reset-password               # Lähtesta administraatori parool
omniroute logs                         # Voogedasta päringuloge
omniroute health                       # Üksikasjalik seisund (kaitselülitid, vahemälu, mälu)
omniroute --version                    # Kuva versioon
omniroute --help                       # Kuva kõik käsud
```

### Seadistamine ja lähtestamine

```bash
omniroute setup                        # Interaktiivne seadistusviisard
omniroute setup --non-interactive      # CI-/automatiseerimisrežiim (loeb keskkonnamuutujaid ja lippe)
omniroute setup --password '<value>'   # Määra administraatori parool otse
omniroute setup --add-provider \
  --provider openai \
  --api-key '<value>' \
  --test-provider                      # Lisa ja testi teenusepakkujat ühe toiminguga
```

Mitteinteraktiivse seadistamise tunnustatud keskkonnamuutujad:

| Muutuja             | Otstarve                                                                       |
| ------------------- | ------------------------------------------------------------------------------ |
| `OMNIROUTE_API_KEY` | Teenusepakkuja API-võti (seotud lipuga `--api-key` Commander-i `.env()` kaudu) |
| `DATA_DIR`          | OmniRoute’i andmekataloogi alistamine                                          |

Kõik muud mitteinteraktiivsed sisendid edastatakse lippudena, mitte keskkonnamuutujatena:
`--password`, `--provider`, `--provider-name`, `--provider-base-url`, `--default-model`
(vt ülal käsu `omniroute setup` suvandeid).

### Diagnostika

```bash
omniroute doctor                       # Kontrolli konfiguratsiooni, andmebaasi, porte, käituskeskkonda, mälu ja serveri aktiivsust
omniroute doctor --json                # Masinloetav JSON
omniroute doctor --no-liveness         # Jäta HTTP-seisundipäring vahele
omniroute doctor --host 0.0.0.0        # Alista aktiivsuskontrolli host
omniroute doctor --liveness-url <url>  # Alista seisundi lõpp-punkti täielik URL
```

Käsk doctor teeb järgmised kontrollid: `Config`, `Database`, `Storage/encryption`,
`Port availability`, `Node runtime`, `Native binary` (better-sqlite3),
`Memory` ja `Server liveness`. Kui mõne kontrolli tulemus on `fail`, lõpetab see nullist erineva väljumiskoodiga.

### Teenusepakkujate haldamine

```bash
omniroute providers available                       # OmniRoute’i teenusepakkujate kataloog
omniroute providers available --search openai       # Filtreeri kataloogi ID/nime/aliase/kategooria järgi
omniroute providers available --category api-key    # Filtreeri kategooria järgi (api-key, oauth, free, ...)
omniroute providers available --json                # Masinloetav JSON

omniroute providers list                            # Konfigureeritud teenusepakkujaühendused
omniroute providers list --json

omniroute providers test <id|name>                  # Testi üht konfigureeritud ühendust
omniroute providers test-all                        # Testi kõiki aktiivseid ühendusi
omniroute providers validate                        # Ainult lokaalne struktuuri valideerimine
omniroute providers add <provider> --credential-env PROVIDER_KEY
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth <provider>                 # Olemasolev OAuthi voog
omniroute providers edit <id|name> --default-model <model>
omniroute providers remove <id|name> --yes
```

Käsud `providers add/import/auth/edit/remove` kasutavad eeskätt API-t ja töötavad seetõttu
aktiivse kohaliku või kaugkontekstiga. Identimisteabe sisestamiseks tuleks kasutada
`--credential-stdin` või `--credential-env`; `--dry-run --json` esitab ainult
redigeeritud olemasolu-/struktuuriteabe. `providers available` loeb OmniRoute’i kataloogi;
`providers list/test/test-all/validate` säilitavad oma kohaliku SQLite’i käitumise ega
nõua serveri töötamist.

Kohandatud OpenAI-ga või Anthropicuga ühilduva sõlme puhul seo identimisteave
käsu `omniroute nodes add` tagastatud sõlme ID-ga, kasutades käsku `omniroute keys add "$NODE_ID" --stdin`.
See nõuab töötavat serverit ja aktiivse konteksti haldusautentimist.
CLI kasutab päringut `POST /api/providers`, mis valideerib sõlme ja kopeerib selle lõpp-punkti
sätted ühendusse. Puuduv sõlm, autoriseerimistõrge või kättesaamatu
server tagastab vea ilma kohaliku varuidentimisteabeta.

`nodes add --base-url` määrab sõlme lõpp-punkti; see erineb muutujas
`OMNIROUTE_BASE_URL` olevast serveri aadressist. OpenAPI failide puhul kasuta käsku
`omniroute openapi dump --format json --out ./openapi.json`; globaalne `--output`
valib CLI kuvavormingu, mitte sihtfaili nime.

### Taastamine ja lähtestamine

```bash
omniroute reset-password                # Lähtesta administraatori parool (ka: omniroute-reset-password)
omniroute reset-encrypted-columns       # Kuva hoiatus + krüpteeritud identimisteabe lähtestamise proovikäivitus
omniroute reset-encrypted-columns --force  # Määra krüpteeritud identimisteabe väärtuseks SQLite’is tegelikult null
```

### Identimisteabe eksportimine (⚠ käsitse ettevaatlikult)

```bash
omniroute auth export                                 # Kuva hoiatus + kinnitusvärav — puudub juurdepääs andmebaasile
omniroute auth export --force                          # Ekspordi KÕIGI ühenduste DEKRÜPTITUD identimisteave JSON-ina standardväljundisse
omniroute auth export --force --id <id>                 # Ekspordi ainult sobiv ühendus
omniroute auth export --force --format env               # Väljasta read kujul OMNIROUTE_<PROVIDER>_<FIELD>=<value>
omniroute auth export --force --out creds.json           # Kirjuta faili (luuakse õigustega 0600)
```

`auth export` on **ainult lokaalne** (loeb SQLite'i otse, HTTP-marsruuti pole) ning väljastab/kirjutab tahtlikult
**lihttekstina** `apiKey`/`accessToken`/`refreshToken`/`idToken` väärtused — see on funktsioon, mitte
viga. Ilma liputa `--force` ei loeta andmebaasist ega dekrüptita midagi. Enne lihtteksti väljastamist
kuvatakse stderr-is alati hoiatusbänner. Muutuja `STORAGE_ENCRYPTION_KEY` peab olema
määratud. Väli, mille dekrüptimine ebaõnnestub (aegunud võti, rikutud šifreeritud tekst), esitatakse kujul
`<field>DecryptFailed: true`, selle asemel et katkestada kogu eksport või avaldada aluseks olev viga.

## Järeldusvõtme poliitika haldamine OmniRoute CLI abil

Kasutage autenditud halduskonteksti (vt [Kaugrežiim](../guides/REMOTE-MODE.md)),
et kontrollida või uuendada olemasolevat järeldusvõtit selle ID järgi:

```bash
omniroute --output json keys policy show KEY_ID
omniroute keys policy set KEY_ID --unrestricted
omniroute --output json keys policy show KEY_ID
```

`--unrestricted` on parameetri `--model-access-mode all` alias. Uuendamine tühjendab
mudelite lubatud loendi. See säilitab ulatused, ühendusreeglid, blokeeritud mudelid,
kiiruspiirangud ja kulupiirangud, mistõttu võivad need muud juhtelemendid päringu
endiselt tagasi lükata. Selgesõnaline `--allowed-models ""` valib samuti väärtuse
`all`; kombineerige see parameetriga `--model-access-mode restricted`, et säilitada
piiratud võti, millel pole lubatud mudeleid. Mittetühi komadega eraldatud loend valib
väärtuse `restricted`, kui seda pole selgesõnaliselt teisiti määratud. Vastuoluline
kombinatsioon `all` koos mittetühja lubatud loendiga lükatakse enne päringu saatmist tagasi.

`--rate-limit 30` määrab päringute arvu minutis ja säilitab muude ajavahemike reeglid.
`--max-cost 5` lubab päevase USD ülempiiri ilma nädalast ülempiiri muutmata;
`--max-cost 0` eemaldab päevase ülempiiri ning säilitab olemasoleva kasutuspiirangu
lüliti ja nädalase ülempiiri. Väljajäetud poliitikaväljad jäävad muutmata.
Kiiruspiirangu muutmisel loetakse esmalt praegune poliitika; vältige sama võtme
kiiruspiirangute massiivi samaaegset muutmist.

Poliitikakäsud kasutavad autenditud päringuid `GET`/`PATCH /api/keys/{id}` ning
järgivad aktiivset konteksti ja globaalset suvandit `--api-key`. JSON-väljund sisaldab
ainult poliitikavälju, mitte salvestatud võtit ega selle maskitud kuju. Ainult
järeldamiseks mõeldud mandaat ei saa haldusmuudatusi autoriseerida. Vastuse 401/403
korral tuleb kontrollida haldusmandaati ja konteksti; see ei tõenda kohaliku CLI
tokeni ega soola tõrget. Eraldiseisva kohaliku autentimislepingu kohta vt
[CLI token](../security/CLI_TOKEN.md).
