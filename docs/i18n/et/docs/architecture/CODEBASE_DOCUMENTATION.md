## 1. Tehnoloogiapinu

| Valdkond            | Valik                                                                                                                                           |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Veebiraamistik      | **Next.js 16** (App Router, autonoomne väljund, globaalne middleware puudub)                                                                    |
| Keel                | **TypeScript 6.0+** — siht `ES2022`, `module: esnext`, `moduleResolution: bundler`, `strict: false`                                             |
| Käituskeskkond      | **Node.js** `>=22.22.2 <23` või `>=24.0.0 <27` (jõustatakse `engines` + `SUPPORTED_NODE_RANGE` kaudu)                                           |
| Andmebaas           | **SQLite** `better-sqlite3` kaudu (üksikeksemplar, WAL-logimine)                                                                                |
| Töölauarakendus     | **Electron 41** + `electron-builder` 26.10 (eraldi tööruum asukohas `electron/`)                                                                |
| Testid              | **Node'i sisseehitatud testikäitaja** (ühik-/integratsioonitestid), **Vitest** (MCP, autoCombo, vahemälu), **Playwright** (e2e + protocols-e2e) |
| Koostamine          | Next.js-i autonoomne väljund skripti `scripts/build/build-next-isolated.mjs` kaudu                                                              |
| Lintimine/vormindus | ESLinti lame konfiguratsioon + Prettier (`lint-staged` Husky pre-commit-konksu kaudu)                                                           |
| Moodulisüsteem      | Kõikjal ESM (`"type": "module"`)                                                                                                                |
| Juhtpaneeli UI      | **Tailwind CSS 4** + lähtekoodiga kaasatud **Keak CI UI Kit** (`packages/ui-kit`), Lucide'i ikoonid — vt `DESIGN_SYSTEM.md`                     |
| Tööruumid           | npm-i tööruumid — `open-sse`, `packages/browser-pool`, `packages/ui-kit`                                                                        |

Teealiased (`tsconfig.json`):

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`
- `@omniroute/ui-kit` → `packages/ui-kit/src`, `@omniroute/ui-kit/*` → `packages/ui-kit/src/*`

HTTP vaikeport: **`20128`** (API ja juhtpaneel kasutavad sama protsessi). Andmete
kataloog määratakse keskkonnamuutujaga `DATA_DIR`; vaikimisi on see `~/.omniroute/`.

### 3.1 `src/app/` — rakenduse ruuter

| Tee                                                                           | Eesmärk                                              |

> Allikas: [diagrams/request-pipeline.mmd](../diagrams/request-pipeline.mmd)

```
Client request
  → /v1/chat/completions (route.ts)
     CORS preflight check
     Zod validation (chatCompletionsSchema in shared/validation/schemas.ts)
     Auth (extractApiKey + isValidApiKey OR requireManagementAuth)
     Route authorization (src/server/authz/pipeline.ts)
     API-key policy (src/shared/utils/apiKeyPolicy.ts; enforced on the selected path)
     Guardrails (PII masker, prompt injection, vision bridge)
  → handleChatCore() (open-sse/handlers/chatCore.ts)
     Cache check (semantic + read cache)
     Rate limit (rateLimitManager, accountSemaphore)
     Combo routing (if model resolves to a combo)
       resolveComboTargets (open-sse/services/combo.ts) → per-target dispatch
     translateRequest()  (open-sse/translator/request/*)
     getExecutor(providerId).execute()  (open-sse/executors/*)
       fetch upstream → retry/backoff via accountFallback
     translateResponse() (open-sse/translator/response/*)
     SSE stream OR JSON response
     If Responses API: TransformStream via open-sse/transformer/responsesTransformer.ts
  → Compliance audit (src/lib/compliance/)
  → Response to client
```

## 10. Kuidas panustada

### Uue tarnija lisamine

1. Registreeri tarnija `src/shared/constants/providers.ts` (Zod-valideerimine laadimisel).
2. Lisa teostaja `open-sse/executors/`, kui on vaja kohandatud loogikat
   (laienda `BaseExecutor`).
3. Lisa tõlki `open-sse/translator/`, kui see ei räägi OpenAI formaati.
4. Kui põhineb OAuth-l, lisa konfiguratsioon `src/lib/oauth/providers/` alla ja
   `src/lib/oauth/services/`.
5. Registreeri mudelid `open-sse/config/providerRegistry.ts` (või vormispetsiifiline
   registri `open-sse/config/` all).
6. Kirjuta testid `tests/unit/` alla.

### Uue API marsruudi lisamine

1. Loo `src/app/api/your-route/route.ts`.
2. Järgi mustrit: CORS → Zod keha valideerimine → autentimine → käsitseja delegeerimine.
3. Kui uus päringu kuju: lisa Zod skeem `src/shared/validation/schemas.ts`.
4. Kui ainult halduslik: lisa tee `src/shared/constants/publicApiRoutes.ts`
   (keelunimekiri avaliku API pinna jaoks).
5. Lisa testid `tests/unit/` alla.
6. Uuenda `docs/reference/API_REFERENCE.md` ja `docs/openapi.yaml`.

### Uue DB mooduli lisamine

1. Loo `src/lib/db/yourModule.ts` ja impordi `getDbInstance()`Failist `./core.ts`.
2. Ekspordi CRUD funktsioonid oma domeenile.
3. Kui uued tabelid: lisa migratsioon `src/lib/db/migrations/`, järjestatult
   nummerdatud, idempotentne, transaktsiooniline.
4. Importijad kasutavad otseseid importe `@/lib/db/yourModule` (mitte barrel – vana `localDb.ts` re-ekspordikiht on eemaldatud).
5. Lisa testid `tests/unit/` alla.

### Uue MCP tööriista lisamine

1. Lisa tööriista määratlus `open-sse/mcp-server/tools/` alla (või laienda
   `open-sse/mcp-server/schemas/tools.ts`).
2. Määra vastav(at) ulatused `src/shared/constants/mcpScopes.ts`.
3. Registreeri tööriist `open-sse/mcp-server/server.ts`.
4. Lisa testid `open-sse/mcp-server/__tests__/` alla.
5. Uuenda [MCP-SERVER.md](../frameworks/MCP-SERVER.md).

### Uue A2A oskuse lisamine

Vaata [A2A-SERVER.md § Uue oskuse lisamine](../frameworks/A2A-SERVER.md). Oskused asuvad
`src/lib/a2a/skills/` ja registreeritakse A2A ülesannete halduri kaudu.

## 11. Konventsioonid

- **Koodi stiil** : 2 tühikuga taane, jutumärgid, 100 tähemärgi laius, semikoolonid, `es5` lõpukomad — jõustab Prettier `lint-staged` kaudu.
- **Import** : väline → sisemine (`@/`, `@omniroute/open-sse`) → suhteline.
- **Nime panemine** : failid `camelCase` või `kebab-case`, komponendid `PascalCase`, konstandid `UPPER_SNAKE`.
- **ESLint** : `no-eval`, `no-implied-eval`, `no-new-func` = `error` kõikjal; `no-explicit-any` = `warn` sisse `open-sse/` ja `tests/`, viga mujal.
- **TypeScript** : `strict: false` (pärandatud poos). Eelistage mooduliüleste piiride jaoks selgesõnalisi tüüpe järeldustele.
- **Andmebaas** : ärge kunagi kirjutage marsruutidele toores SQL d või käitlejad — läbivad alati `src/lib/db/` -moodulid. Ärge kunagi tünniga imporditud — kasutage konkreetseid `src/lib/db/*` mooduleid otse.
- **DB-olemi sisestamine (#3512)** : funktsioon, mis kirjutab või loeb DB tabeli rea kuju, peaks take/return nimega TS liidese, mis peegeldab selle tabeli veerge 1:1, mitte `any` või inline anonüümset tüüpi kõne saidil. Asetage liides funktsiooni kõrvale (nt `export interface UsageEntry` `src/lib/usage/usageHistory.ts` -s `saveRequestUsage` kohal), jätke üksikud väljad optional/nullable kui erinevad kirjutajad täidavad rida järk-järgult, ja eelistage `unknown` -le `any` välja puhul, mille kuju on helistajate lõikes erinev (dokumenteeritud väljal, nt `UsageEntry.tokens` aktsepteerib nii töötlemata pakkujakujulist kasutamist kui ka normaliseeritud kuju). Kui faili `any` arv jõuab sel viisil nulli, lisage see `check:any-budget:t11` lubatud loendisse (`scripts/check/check-t11-any-budget.mjs`, `maxAny: 0`), et see ei saaks taanduda. See on esimese lõigu konventsioon — laiem "anonüümset `any` pole" puhastamine iteratiivne kogu ülejäänud koodibaasi ulatuses.
- **Vead** : try/catch konkreetsete veatüüpidega, logi pino kontekstiga. Ärge kunagi vaikselt neelake SSE voogudes esinevaid vigu; kasutage puhastamiseks katkestamise signaale.
- **Turvalisus** : ärge kunagi kasutage `eval()` / `new Function()` / implied eval. Kinnitage kõik sisendid Zod-ga. Krüpteeri mandaadid puhkeolekus (AES-256-GCM). Hoidke `src/shared/constants/upstreamHeaders.ts` denylist sanitize/validation -kihiga joondatud.
- **Kohustub** : Tavalised kohustused — `feat(scope): subject`. Lubatud ulatused: `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`, `a2a`, `memory`, `skills`.
- **Filiaalid** : eesliited `feat/`, `fix/`, `refactor/`, `docs/`, `test/`, `chore/`. Ärge kunagi pühenduge otse `main`.
- **Husky** : pre-commit jookseb `lint-staged` + `check:docs-sync` + `check:any-budget:t11`; eeltõuke jookseb `check:any-budget:t11` + `check:tracked-artifacts` (kiirväravad; välja arvatud `test:unit`).
