የWeb Cookie አቅራቢዎች OmniRoute ከAPI ቁልፍ ይልቅ ነባሩን የአሳሽ ክፍለ ጊዜዎን በመጠቀም የAI አገልግሎትን እንዲጠቀም ያስችሉታል። አንድን አገልግሎት በድረ ገጹ በኩል የመጠቀም ፈቃድ ካለዎት እና OmniRoute ያንኑ የተረጋገጠ ክፍለ ጊዜ እንዲጠቀም ከፈለጉ ጠቃሚ ናቸው።

ከAPI ቁልፍ አቅራቢዎች በተለየ፣ የWeb Cookie አቅራቢዎች አሳሽዎ ወደ ድረ ገጹ የሚልከውን የማረጋገጫ መረጃ በመጠቀም ማንነትን ያረጋግጣሉ።

# ከመጀመርዎ በፊት

> **አስፈላጊ፦** ሁልጊዜ የማረጋገጫ መረጃን ከ**ቀጥታ የአውታረ መረብ ጥያቄ** ይቅዱ፤ ከአሳሽዎ የCookie ማከማቻ **አይቅዱ**።

ብዙ የማንነት ማረጋገጫ ችግሮች የሚከሰቱት cookies ከተሳሳተ ቦታ በመቅዳት ነው።

## ከCookie ማከማቻ አይቅዱ

አብዛኛዎቹ አሳሾች የተከማቹ cookiesን በሚከተለው መንገድ ያሳያሉ፦

```
DevTools
→ Application (or Storage)
→ Cookies
```

እነዚህ cookies ትክክለኛ ቢመስሉም፣ ምናልባት፦

- ጊዜ ያለፈባቸው
- ያልተሟሉ
- በማንነት በተረጋገጡ ጥያቄዎች ላይ ብቻ የሚላኩ cookies የጎደሏቸው

ሊሆኑ ይችላሉ። እነዚህን እሴቶች መጠቀም፣ ትክክለኛ ቢመስሉም እንኳ፣ የማንነት ማረጋገጫ ውድቀትን ሊያስከትል ይችላል።

## ከቀጥታ ጥያቄ ይቅዱ

በምትኩ፣ ከተሳካ ጥያቄ የተገኙ cookiesን ይጠቀሙ፦

```
DevTools
→ Network
→ Refresh the page
→ Open a chat or conversation request
→ Request Headers
→ Cookie
```

የ`Cookie` ጥያቄ ራስጌ፣ አሳሽዎ በተሳካ ሁኔታ የተጠቀመበትን ትክክለኛ የማረጋገጫ መረጃ ይዟል።

ለአብዛኛዎቹ የWeb Cookie አቅራቢዎች፣ ይህ ወደ OmniRoute መለጠፍ ያለበት እሴት ነው።

---

# አጠቃላይ ማዋቀር

ለአብዛኛዎቹ የWeb Cookie አቅራቢዎች የማዋቀር ሂደቱ ተመሳሳይ ነው።

1. ወደ አቅራቢው ድረ ገጽ ይግቡ።
2. የአሳሹን የገንቢ መሣሪያዎች ይክፈቱ።
3. የ**Network** ትርን ይክፈቱ።
4. ገጹን ያድሱ።
5. የማንነት ማረጋገጫ ያለውን የውይይት ወይም የንግግር ጥያቄ ይክፈቱ።
6. የሚያስፈልገውን የማረጋገጫ መረጃ ይቅዱ።
7. OmniRouteን ይክፈቱ።
8. ወደ **Providers → Add Provider** ይሂዱ።
9. የWeb Cookie አቅራቢዎን ይምረጡ።
10. የማረጋገጫ መረጃውን ይለጥፉ።
11. **Test Connection**ን ጠቅ ያድርጉ።
12. አቅራቢውን ያስቀምጡ።

የሚያስፈልገው ትክክለኛ የማረጋገጫ መረጃ እንደ አቅራቢው ይለያያል።

---

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) ምዝገባ የማያስፈልገው ነፃ የተጠቃሚዎች የውይይት መድረክ ነው — ክፍለ-ጊዜው በመጀመሪያው ጉብኝት ስም-አልባ ሆኖ የሚፈጠር ሲሆን፣ በሦስት ኩኪዎች በኩል ይቆያል፦ `uid`፣ `si_usr_id` እና `si_ses_id`። OmniRoute ተመሳሳዩን `/api/dispatch` የመጨረሻ ነጥብ በአንድ የሞዴል መለያ (`notrack-c`፣ ቅጽል `ntw`) በኩል ያስተላልፋል።

### ለመገናኘት የሚከተሉ ደረጃዎች

1. [notrack.ai](https://notrack.ai)ን በአሳሽዎ ውስጥ ይክፈቱ እና የስም-አልባው ክፍለ-ጊዜ ኩኪ እንዲቀናበር ይፍቀዱ።
2. **DevTools → Network**ን ይክፈቱ፣ ገጹን ያድሱ እና ማንኛውንም `/api` ጥያቄ ጠቅ ያድርጉ።
3. በ**Request Headers** ውስጥ፣ ሙሉውን የ`Cookie` ራስጌ እሴት ይቅዱ።
4. በOmniRoute ውስጥ፣ ወደ **Providers → Add Provider → NoTrack Web (Free)** ይሂዱ።
5. የኩኪውን ሕብረቁምፊ ወደ `apiKey` መስክ ይለጥፉ እና **Save**ን ይጫኑ።

OmniRoute ከተለጠፈው ሕብረቁምፊ `uid`፣ `si_usr_id` እና `si_ses_id`ን አውጥቶ እነዚያን ጥንዶች ብቻ የያዘ ንጹሕ የ`Cookie` ራስጌ እንደገና ይገነባል — እንዲሁም `nt_session` (ለገቡ መለያዎች የሚቀናበረው `ntk_…` ቶከን) ካለ ያክላል። ከሦስቱ አንዱ ከጎደለ፣ አስተዳዳሪዎች በአማራጭ ቅርጾች መሞከር እንዲችሉ የተለጠፈው ጥሬ ሕብረቁምፊ ሳይቀየር ይተላለፋል።

### የጥያቄ አማራጮች

አስፈጻሚው በጥያቄው አካል ላይ የሚከተሉትን አማራጭ መስኮች ይቀበላል፦

| የአካል መስክ              | ነባሪ     | ዓላማ                                                    |

### ችሎታዎች

- **የዥረት እና ዥረት-አልባ** የውይይት ማጠናቀቂያዎች።
- **የመሣሪያ ጥሪ** — በጥያቄው ላይ `tools: [...]`ን ያቀናብሩ፤ አስፈጻሚው ወደ መሣሪያ-ጥሪ የመጠቅለያ ውል ተከታታይ ያደርጋቸዋል እና የሞዴሉን ምላሾች መልሶ ወደ OpenAI `tool_calls` ይተነትናል።
- **`response_format`** — `json_object` እና `json_schema` ይደገፋሉ። አስፈጻሚው ከሞዴሉ ምላሽ የመጀመሪያውን JSON ነገር አውጥቶ ከመመለሱ በፊት ወደ ሕብረቁምፊ ይቀይረዋል።
- **የማመዛዘን ፍንጭ** — የላይኛው ስርዓት `thinking` ክስተት ሲልክ፣ አስፈጻሚው የ`reasoning` ልዩነት ያወጣል።

### ገደቦች

- የላይኛው ስርዓት የስም-አልባ አጠቃቀም ኮታዎችን ያስፈጽማል — ገደቡ ሲደረስ፣ አስፈጻሚው 429ን ተጠቃሚ-ተስማሚ ከሆነ መልዕክት ጋር ያሳያል።
- ሁሉም የሞዴል መለያዎች ወደ ተመሳሳዩ የላይኛው ስርዓት ማሰራጫ ሞዴል ይዛመዳሉ፤ ለየሞዴሉ የተለየ መቀየሪያ የለም።
- አስፈጻሚው የላይኛውን ስርዓት `/api/chats` የመጨረሻ ነጥብ አይጠራም፤ ስለዚህ የውይይት ታሪክ / ክፍለ-ጊዜዎች በራስ-ሰር አይተዳደሩም። ነባር የላይኛው ስርዓት ውይይትን ከቆመበት ለመቀጠል `notrack_chat_id`ን ይጠቀሙ።
