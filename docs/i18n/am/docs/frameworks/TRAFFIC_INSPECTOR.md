### አርክቴክቸሩ በአንድ አንቀጽ

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) በጋራ የሚጠቀሙበት፣ በማህደረ ትውስታ ውስጥ የሚገኝ ቀለበት ቋት ነው (ነባሪው 1000 ግቤቶች ሲሆን፣ በ`INSPECTOR_BUFFER_SIZE` ሊዋቀር ይችላል)። ሁሉም የቀረጻ ምንጮች `push()`ን በመጠቀም ወደ እሱ ይጽፋሉ። የቋቱ ክፍል `kindDetector.ts`ን በመጠቀም እያንዳንዱን ግቤት ይመድባል (የLLM ጥያቄ መሆኑን ይወስናል)፣ `contextKey`ን (የሥርዓት መጠየቂያው SHA-256 አሻራ) ያሰላል፣ እንዲሁም በ`globalTrafficBuffer.subscribe()` በኩል ለሁሉም የWebSocket ተመዝጋቢዎች ያሰራጫል። ዳሽቦርዱ በ`GET /api/tools/traffic-inspector/ws` በኩል ይገናኛል፤ ሲገናኝም ቅጽበታዊ ቅጂ ይቀበላል፣ ከዚያም `new`/`update`/`clear` ክስተቶች ይከተላሉ።

## §2 የቀረጻ ሁነታዎች

Traffic Inspector **5 በአንድ ጊዜ የሚሰሩ የቀረጻ ምንጮችን** ይደግፋል። እያንዳንዳቸው ለብቻቸው ሊበሩ ወይም ሊጠፉ ይችላሉ። በእያንዳንዱ `InterceptedRequest` (`src/mitm/inspector/types.ts`) ላይ ያለው `source` መስክ ከ `"agent-bridge"`፣ `"custom-host"`፣ `"http-proxy"`፣ `"system-proxy"` ወይም `"tproxy"` አንዱ ነው።

### ሁነታ 1 — AgentBridge (ነባሪ፣ ሁልጊዜ የበራ)

**ምንጭ፦** AgentBridge ማስተናገጃዎች (`src/mitm/handlers/base.ts`)
**ዘዴ፦** በ`MitmHandlerBase` ውስጥ ያለው እያንዳንዱ `intercept()` ጥሪ፣ ጥያቄውን ከማስተላለፉ በፊት `hookBufferStart()`ን እና ሲጠናቀቅ `hookBufferUpdate()`ን ይጠራል። ምንም ተጨማሪ ውቅር አያስፈልግም — AgentBridge መስራት እንደጀመረ ወዲያውኑ ይሰራል።
**ሽፋን፦** በAgentBridge ውስጥ የተዋቀሩት 9 የIDE ወኪሎች
**ማስታወሻ፦** በ`InterceptedRequest` ውስጥ ያለው `source` መስክ = `"agent-bridge"`

### ሁነታ 2 — ብጁ አስተናጋጆች (የDNS አቅጣጫ ማስቀየር)

**ምንጭ፦** በተጠቃሚ የተወሰነ የአስተናጋጆች ዝርዝር (`inspector_custom_hosts` ሰንጠረዥ)
**ዘዴ፦** በUI በኩል አስተናጋጅ ማከል፣ `127.0.0.1 <host>`ን ወደ `/etc/hosts` ያክላል (sudo ያስፈልጋል)። ነባሩ የAgentBridge MITM አገልጋይ (ወደብ 443) ለአዲሱ አስተናጋጅ የSNI ምስክር ወረቀትን በተለዋዋጭ ሁኔታ ያመነጫል።
**ሽፋን፦** የታከለውን አስተናጋጅ የሚጠቀም ማንኛውም መተግበሪያ — የመተግበሪያውን ውቅር መቀየር አያስፈልግም
**ማስታወሻ፦** `source` = `"custom-host"`

የአጠቃቀም ምሳሌዎች፦

- `api.openai.com`ን ከPython ስክሪፕቶች መከታተል
- `my-internal-llm.company.com`ን ማረም
- በተመሳሳይ አውታረ መረብ ላይ ካሉ ተንቀሳቃሽ መሣሪያዎች ትራፊክን መቅረጽ (በARP spoofing — የላቀ)

### ሁነታ 3 — HTTP_PROXY አድማጭ (ወደብ 8080)

**ምንጭ፦** `HTTP_PROXY`/`HTTPS_PROXY` የአካባቢ ተለዋዋጮችን የሚጠቀሙ መተግበሪያዎች
**ዘዴ፦** እንደ መደበኛ ግልጽ የHTTP/HTTPS ተኪ የሚሰራ በወደብ 8080 (`src/mitm/inspector/httpProxyServer.ts`) ላይ ያለ ሁለተኛ አድማጭ። `CONNECT` ቱነሎችን (HTTPS) እና ቀጥተኛ የHTTP ጥያቄዎችን ይቀበላል።
**ሽፋን፦** `HTTP_PROXY` envን የሚያከብር ማንኛውም መተግበሪያ — የDNS ለውጥም ሆነ sudo አያስፈልግም
**ማስታወሻ፦** `source` = `"http-proxy"`

```bash
# ለአንድ ትዕዛዝ ፈጣን ቀረጻ፦
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# በአንድ የshell ክፍለ ጊዜ ውስጥ ዘላቂ ቀረጻ፦
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**የTLS ገደብ፦** HTTPS በቀላል `CONNECT` ቱነል በኩል ያልፋል፦ አድማጩ የተመሰጠሩትን ባይቶች ሳይነካ ያስተላልፋል እና ሜታዳታን ብቻ ይመዘግባል (አስተናጋጅ፣ ወደብ፣ ጊዜ)። HTTPSን በፍጹም አይፈታም፣ እና ለዚህ ሁነታ ምስጠራ መፍታትን የሚያበራ ቅንብር የለም። የHTTPS ይዘቶችን ለመቅረጽ፣ አስተናጋጁን በሁነታ 1 (AgentBridge)፣ በሁነታ 2 (ብጁ አስተናጋጆች) ወይም በሁነታ 5 (TPROXY ምስጠራ መፍታት) በኩል ያስተላልፉ።

**የወደብ ግጭት፦** ወደብ 8080 ጥቅም ላይ ከሆነ፣ AgentBridge ከተዋቀረ ስህተት ጋር 409ን ይመልሳል። ወደቡን በ`INSPECTOR_HTTP_PROXY_PORT` env var በኩል ይቀይሩ።

### ሁነታ 4 — ስርዓት-አቀፍ ተኪ (የላቀ፣ በምርጫ የሚነቃ)

**ምንጭ፦** የOS-ደረጃ የተኪ ቅንብሮች (በማሽኑ ላይ ላሉ ሁሉም መተግበሪያዎች ይተገበራል)
**ዘዴ፦** ሁሉንም የHTTP/HTTPS ትራፊክ በHTTP_PROXY አድማጩ በኩል ለማዘዋወር የOS APIዎችን ይጠቀማል፦

- **macOS፦** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux፦** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows፦** `netsh winhttp set proxy 127.0.0.1:8080`
  **ሽፋን፦** በማሽኑ ላይ የስርዓት ተኪ ቅንብሮችን የሚያከብር እያንዳንዱ መተግበሪያ
  **ማስታወሻ፦** `source` = `"system-proxy"`

**የደህንነት ዘዴዎች፦**

- በራስ-ሰር የማሰናከያ ጊዜ ቆጣሪ (ነባሪው 30 ደቂቃ፣ በ`INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` ሊዋቀር ይችላል)
- የቀድሞው የስርዓት ተኪ ሁኔታ በDB ውስጥ ይቀመጣል እና ሲመለስ ወደ ቀድሞ ሁኔታው ይመለሳል
- ተጠቃሚው ሁነታው ንቁ እያለ ከገጹ ለመውጣት ከሞከረ፣ ዳሽቦርዱ "የስርዓት ተኪውን በመመለስ ላይ" የሚል ጥያቄ ያሳያል
- UI የ`⚠ የላቀ` ባጅ + ግልጽ የማረጋገጫ አመልካች ሳጥን ያሳያል

### ሁነታ 5 — TPROXY ግልጽ የምስጠራ መፍቻ (Linux፣ root፣ በምርጫ የሚነቃ)

**ምንጭ፦** Kernel TPROXY + የመመሪያ መስመር ማዘዋወር (`src/mitm/tproxy/`)
**ዘዴ፦** በ`mangle OUTPUT` ውስጥ ወደ ዒላማ ወደብ (ነባሪ `443`) የሚደረጉ አዲስ አካባቢያዊ ወጪ የTCP ግንኙነቶችን ምልክት ያደርጋል፤ `ip rule` ምልክት የተደረገባቸውን ፓኬቶች ወደ አካባቢያዊ መድረሻ እንደገና ያዘዋውራል፤ እንዲሁም የ`mangle PREROUTING` `TPROXY` ዒላማ ፓኬቶቹን ለግልጽ (**IP_TRANSPARENT**) አድማጭ (ነባሪ ወደብ `8443`) ያስረክባል። አድማጩ በተለዋዋጭ CA **ለእያንዳንዱ የSNI አስተናጋጅ ስም በተጠየቀ ጊዜ** በሚሰጥ የleaf ምስክር ወረቀት TLSን ያቋርጣል፣ ምስጠራው የተፈታውን ልውውጥ ይቀርጻል፣ እና ጥያቄውን እንደገና መስጥሮ ወደ መጀመሪያው መድረሻ ያስተላልፋል።
**ሽፋን፦** በዒላማው ወደብ ላይ ያሉ **ማናቸውም** መድረሻ አስተናጋጆች — የ`/etc/hosts` ማስመሰል፣ `HTTP_PROXY` env ወይም ስርዓት-አቀፍ የተኪ ማሻሻያ አያስፈልግም። ተጠልፎ የሚመረመረው ሂደት ምንም የውቅር ለውጥ አያስፈልገውም፣ ነገር ግን ተለዋዋጩን CA ማመን አለበት።
**ማስታወሻ፦** `source` = `"tproxy"`

**መስፈርቶች፦** Linux ብቻ (**IP_TRANSPARENT** በLinux ብቻ ይገኛል)፣ የ**CAP_NET_ADMIN** ችሎታ (root)፣ እና በC toolchain (`npm run build:native:tproxy`) መገንባት ያለበት ቤተኛ N-API addon። እነዚህ በማይገኙበት ጊዜ፣ በዳሽቦርዱ ላይ ያለው መቀያየሪያ "የTPROXY ምስጠራ መፍታት Linux + root + ቤተኛውን addon ይፈልጋል" በሚል የመሣሪያ ፍንጭ ይሰናከላል። የfirewall ደንቦቹ በግብይታዊ ሁኔታ ይተገበራሉ/ይመለሳሉ (ብልሽት የ`mangle` ደንብን በፍጹም ትቶ አይሄድም) እና ዳግም ሲነሳ ይጸዳሉ። SO_MARK-ተኮር የፀረ-ዑደት ዘዴ፣ ተኪው ራሱ እንደገና መስጥሮ የሚያስተላልፈው ግንኙነት እንደገና ተጠልፎ እንዳይመረመር ይከላከላል።

ይህ የራሱ የተለየ የኦፕሬተር መመሪያ ያለው ጉልህ ንዑስ-ስርዓት ነው — ሙሉውን የfirewall አሠራር፣ ለእያንዳንዱ SNI የሚመነጨውን ተለዋዋጭ CA + የtrust-store ጫኚ፣ አካባቢያዊ-ብቻ መስመርን፣ የፀረ-ዑደት ዝርዝሮችን እና የውቅር መርሐግብሩን ለማየት `docs/security/MITM-TPROXY-DECRYPT.md`ን (git፤ ወደ `/docs` አይጠናቀርም) ይመልከቱ። መቀያየሪያው በ`GET / POST / DELETE /api/tools/agent-bridge/tproxy` ይቆጣጠራል (ማስታወሻ፦ መስመሩ በTraffic Inspector ቅድመ ቅጥያ ሳይሆን በAgentBridge ቅድመ ቅጥያ ስር ይገኛል)።

## §4 LLM-ን የሚያውቁ ባህሪያት

### 4.1 ዓይነት መለያ (`src/mitm/inspector/kindDetector.ts`)

እያንዳንዱን ጥያቄ 4 ምልክቶችን በመጠቀም `"llm"`፣ `"app"` ወይም `"unknown"` ብሎ ይመድባል፦

1. **የአስተናጋጅ መዝገብ** — ~18 የሚታወቁ የLLM API አስተናጋጅ ስሞች (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot, ወዘተ)
2. **የዱካ ንድፎች** — `/v1/chat/completions`፣ `/v1/messages`፣ `/generateContent`፣ `/v1/responses`፣ ወዘተ
3. **የይዘት ቅርጽ** — `messages[]` (OpenAI/Claude)፣ `contents[]` (Gemini)፣ `prompt`፣ `input` መስኮችን ይለያል
4. **የተጠቃሚ-ወኪል ፍንጮች** — በUA ሕብረቁምፊ ውስጥ `codex`፣ `claude`፣ `gemini`፣ `antigravity`፣ `kiro`፣ `copilot`፣ `cursor`

በMode 2 በኩል የታከሉ ብጁ አስተናጋጆች `kind`-ቸውን ከቅጹ ግቤት ይወርሳሉ (ነባሪው `"custom"` ነው)።

### 4.2 SSE አዋሃጅ (`src/mitm/inspector/sseMerger.ts`)

**ራሱን የቻለ ከባዶ የተተገበረ አተገባበር።** የክስተት ትንተናው
[የWHATWG በአገልጋይ የሚላኩ ክስተቶች ስልተ ቀመር](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)ን የሚከተል ሲሆን፣
መልሶ መገንባቱ ደግሞ ይፋዊዎቹን [OpenAI](https://platform.openai.com/docs/api-reference/chat/create)፣
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming) እና
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
የዥረት መርሐግብሮች ይከተላል።

ከጥሬ የSSE ልዩነት ክስተቶች የመጨረሻውን የረዳት መልዕክት መልሶ ይገነባል፦

- **Anthropic**፦ `content_block_delta`ን በማውጫ ያከማቻል፤ `text_delta`፣ `input_json_delta` (የመሣሪያ ጥሪዎች)፣ `thinking_delta`ን ይይዛል
- **OpenAI**፦ የChat Completions ምርጫዎችን/የመሣሪያ ጥሪዎችን እና የResponses API ውጤት ንጥሎችን
  በማውጫ ያከማቻል
- **Gemini**፦ `candidates[i].content.parts`ን ያከማቻል
- **ያልታወቀ**፦ ጥሬ ክስተቶችን እንዳሉ ይመልሳል

የResponse ትር መቀያየሪያ ያሳያል፦ **"ጥሬ ክስተቶች ↔ የተዋሃደ"**።

### 4.3 የውይይት መደበኛ አድራጊ (`src/mitm/inspector/conversationNormalizer.ts`)

**ራሱን የቻለ ከባዶ የተተገበረ አተገባበር።** መደበኛ ማድረግ በአካባቢያዊ ጥቁር-ሳጥን
ውሎች እና በይፋዊዎቹ OpenAI፣ Anthropic እና Gemini የመልዕክት መርሐግብሮች ይገለጻል፤ ምንም የላይኛው ምንጭ
የአተገባበር ምንጭ ጥቅም ላይ አልዋለም።

OpenAI፣ Anthropic እና Gemini የመልዕክት ቅርጸቶችን ከማሳየት በፊት ወደ አንድ `NormalizedConversation` ይቀይራል፦

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // ከጥያቄው አካል የሚመጡ messages / contents / prompt
  response: NormalizedTurn[]; // የረዳት ምላሽ (በsseMerger የተዋሃደ)
  contextKey: string | null; // የSHA-256 የስርዓት-prompt አሻራ
}
```

የብሎክ ዓይነቶች፦ `text`፣ `tool_use`፣ `tool_result`። የConversation ትር አቅራቢው ማንም ቢሆን ይህን ቅርጽ ይጠቀማል።

### 4.4 የአውድ ቁልፍ ቀለም መስጠት (`src/mitm/inspector/contextKey.ts`)

- የስርዓት prompt-ን `SHA-256` ያሰላል (የመጀመሪያው `role:system` መልዕክት፣ ወይም `system` መስክ፣ ወይም የGemini `systemInstruction`)
- ባለ12-ቁምፊ ሄክስ ቅድመ ቅጥያ ይመልሳል (`"a3f9c2..."`)
- የፊት ገጽ ቁልፉን ለግራ-ድንበር አሞሌው ወደ የተወሰነ HSL ቀለም ይዛመዳል
- **የ"ተመሳሳይ አውድ" ማጣሪያ**፦ `ctx #a3f` ቺፕን ጠቅ ማድረግ ተመሳሳይ አሻራ ያላቸውን ጥያቄዎች ብቻ ለማሳየት ማጣሪያ ያክላል

ይህም በአንድ የወኪል ክፍለ ጊዜ ውስጥ የሚሰሩ የተለያዩ "ስብዕናዎች" ወይም ተግባራትን በእይታ መለየት ቀላል ያደርገዋል።

### 4.5 የLLM ሜታዳታ ማውጣት

ለLLM ጥያቄዎች፣ የLLM Details ትር የሚከተሉትን ያወጣል፦

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // ከጥያቄው አካል ወይም ከምላሹ
  messages: number; // የዙር ብዛት
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // ምላሹ SSE ከሆነ true
  mappedTo: string | null; // x-omniroute-mapped ራስጌ
  costEstimateUsd: number | null; // በOmniRoute ዋጋ አወጣጥ ላይ የተመሠረተ የተገመተ ወጪ
}
```

### 4.6 በሂደት ላይ ያሉ ጥያቄዎች የቀጥታ ማጣሪያ

የጥያቄው `status` መስክ `number | "in-flight" | "error"` ነው — ጥያቄው እንደጀመረ ግቤቱ
እንደ `"in-flight"` ይገፋል፣ እና ምላሹ (ወይም ስህተቱ) ሲደርስ **ባለበት ይዘምናል**። የመሣሪያ አሞሌው **"ቀጥታ"** መቀያየሪያ
(`liveOnly`፣ i18n ቁልፍ `trafficInspector.liveOnly`) ዝርዝሩን
`status === "in-flight"` ወደሆኑ ግቤቶች ይገድባል፣ ይህም ክፍት ግንኙነቶችን በቅጽበት እንዲመለከቱ ያስችልዎታል።

ማጣሪያው በ
`src/lib/inspector/matchesTrafficFilter.ts` ውስጥ ያለ ንጹህ፣ በደንበኛ-ጎን የሚሰራ ማጣሪያ ነው፦

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

የመቀያየሪያው ሁኔታ በ`useTrafficFilters` (የመርማሪው ዳሽቦርድ hooks) ውስጥ ይኖራል፣ እና
ከሌሎቹ ማጣሪያዎች (መገለጫ፣ አስተናጋጅ፣ ወኪል፣ ምንጭ፣ ሁኔታ፣ አውድ) ጋር ይጣመራል።

### 4.7 የሂደት ባለቤትነት መለየት (Linux)

በLinux ላይ፣ እያንዳንዱ የተጠለፈ ጥያቄ **ጥያቄውን ከጀመረው አካባቢያዊ
ሂደት** ጋር ሊያያዝ ይችላል። ሁለት አማራጭ መስኮች ወደ `InterceptedRequest` ታክለዋል፦

```ts
pid?: number;          // የጀመረው ሂደት መለያ (በLinux ላይ ብቻ)
processName?: string;  // የጀመረው ሂደት ስም (በLinux ላይ ብቻ)
```

`src/mitm/inspector/processAttribution.ts` የግንኙነቱን _የደንበኛ_
ጊዜያዊ ወደብ ከPID + ስም ጋር በሚከተለው መንገድ ያዛምዳል፦

1. ለወደቡ የsocket inode-ን ለማግኘት `/proc/net/tcp` እና `/proc/net/tcp6`ን ያነባል
   (`parseProcNetTcpForInode`፣ በfixture ሊሞከር የሚችል ንጹህ parser)።
2. ወደ `socket:[<inode>]` የሚያመለክት symlink ለማግኘት `/proc/<pid>/fd/`ን ይቃኛል።
3. የሂደቱን ስም ከ`/proc/<pid>/comm` ያነባል።

የ1 ሰከንድ TTL መሸጎጫ በጭነት ጊዜ የprocfs ቅኝት ወጪን ይገድባል። ባለቤትነት መለየቱ
**በተቻለ መጠን** የሚከናወን ነው — ማንኛውም ውድቀት ወደ `null` ይፈታል እና ቀረጻውን ፈጽሞ አያግድም። በ
macOS/Windows ላይ ፋንክሽኑ `null` ይመልሳል (stub፤ የ`lsof`/`GetExtendedTcpTable`
ድጋፍ ቀጣይ ሥራ ነው)።

### የሚታወቁ ገደቦች

- **የስርዓት-አቀፍ proxy ሁነታ** VPN ደንበኞችን እና SSOን ጨምሮ በማሽኑ ላይ ያሉ ሁሉንም መተግበሪያዎች ይነካል። ሁልጊዜ ከራስ-ሰር ማሰናከያ ጊዜ ቆጣሪ ጋር ይጠቀሙበት። በጋራ በሚጠቀሙባቸው ማሽኖች ላይ አይጠቀሙበት።
- **CONNECT tunnel HTTPS**፦ Mode 3 (HTTP_PROXY) ለHTTPS መዳረሻዎች የtunnel ሜታዳታን ብቻ ይይዛል፣ በፍጹምም ዲክሪፕት አያደርጋቸውም። ይህ ሆን ተብሎ የተደረገ ነው — ዲክሪፕት ማድረግ እያንዳንዱ ደንበኛ የMITM ሰርተፍኬትን እንዲያምን ይጠይቃል፤ ስለዚህ listener HTTPSን ከጫፍ እስከ ጫፍ እንደተመሰጠረ ያቆየዋል። የHTTPS ይዘቶች ሲያስፈልጉዎት AgentBridge፣ Custom Hosts ወይም TPROXY ዲክሪፕት ይጠቀሙ።
- **በአንዳንድ አካላት ውስጥ በቀጥታ የተጻፉ ሕብረቁምፊዎች**፦ አንዳንድ የUI አካላት (F7/F8) እስካሁን በi18n ቁልፎች ያልተሸፈኑ ጥቂት በቀጥታ የተጻፉ ሕብረቁምፊዎች አሏቸው። እነዚህ በi18n ክፍተት ሪፖርት ውስጥ እንደ የሚታወቅ ገደብ ተመዝግበዋል፤ በቀጣይ ዙር ይዛወራሉ። የተነኩት ሕብረቁምፊዎች ለተግባራዊ አጠቃቀም ትርጉም የማያስፈልጋቸው የUI ማስዋቢያ መለያዎች ናቸው።

### የስርዓት ፕሮክሲ ወደ ቀድሞው አለመመለስ

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows፦**

```cmd
netsh winhttp reset proxy
```

### ቋቱ ሙሉ ነው

ቋቱ `INSPECTOR_BUFFER_SIZE` ላይ ሲደርስ (ነባሪው 1000)፣ አዲስ ግቤቶች በጣም የቆዩትን ያስወጣሉ። አስፈላጊ ጥያቄዎች እየጠፉ ከሆነ፦

## §8 የAPI ማጣቀሻ

ሁሉም መስመሮች `LOCAL_ONLY` (በloopback ብቻ) እና `SPAWN_CAPABLE` (የስርዓት proxy ትዕዛዞች) ናቸው። `src/server/authz/routeGuard.ts`ን ይመልከቱ።

መሠረታዊ ዱካ፦ `/api/tools/traffic-inspector/`

### የጥያቄ አስተዳደር

| ዘዴ     | ዱካ                          | መግለጫ                                                                           |
| ------ | --------------------------- | ------------------------------------------------------------------------------ |
| GET    | `/requests`                 | ጥያቄዎችን ዘርዝር (ሊጣራ የሚችል፦ `?profile=llm&host=&agent=&status=&source=&sessionId=`) |
| GET    | `/requests/{id}`            | የአንድ ጥያቄ ዝርዝሮች                                                                 |
| DELETE | `/requests`                 | በማህደረ ትውስታ ያለውን buffer አጽዳ                                                     |
| POST   | `/requests/{id}/replay`     | ተመሳሳዩን ጥያቄ በOmniRoute router በኩል እንደገና አስፈጽም                                   |
| PUT    | `/requests/{id}/annotation` | በጥያቄ ላይ ማስታወሻ አስቀምጥ ወይም አዘምን                                                   |

### WebSocket

| ዘዴ  | ዱካ    | መግለጫ                                                                          |
| --- | ----- | ----------------------------------------------------------------------------- |
| GET | `/ws` | የቀጥታ WebSocket ዥረት። ሲገናኝ `snapshot`ን፣ ከዚያም `new`/`update`/`clear` ክስተቶችን ይልካል |

### ወደ ውጭ መላክ

| ዘዴ  | ዱካ            | መግለጫ                                 |
| --- | ------------- | ------------------------------------ |
| GET | `/export.har` | አሁን የተጣራውን ዝርዝር እንደ HAR 1.2 ወደ ውጭ ላክ |

### ብጁ hosts

| ዘዴ     | ዱካ              | መግለጫ                                 |
| ------ | --------------- | ------------------------------------ |
| GET    | `/hosts`        | ብጁ hostsን ዘርዝር                       |
| POST   | `/hosts`        | host ጨምር (`/etc/hosts`ን በራስ-ሰር ያርታል) |
| DELETE | `/hosts/{host}` | hostን አስወግድ                          |
| PATCH  | `/hosts/{host}` | `enabled`ን ቀያይር                      |

### የቀረጻ ሁነታዎች

| ዘዴ   | ዱካ                            | መግለጫ                                                           |
| ---- | ----------------------------- | -------------------------------------------------------------- |
| GET  | `/capture-modes`              | የAgentBridge / ብጁ-hosts / HTTP_PROXY / የስርዓት-proxy ሁነታዎች ሁኔታ   |
| POST | `/capture-modes/http-proxy`   | HTTP_PROXY listenerን ጀምር/አቁም (`{action: "start"\|"stop"}`)     |
| POST | `/capture-modes/system-proxy` | በመላው ስርዓት የሚሠራ proxyን ተግብር/መልስ (`{action: "apply"\|"revert"}`) |

> **TPROXY ዲክሪፕት** (የቀረጻ ሁነታ 5) በAgentBridge ቅድመ ቅጥያ ሥር ባለ **የተለየ** መስመር —
> `GET / POST / DELETE /api/tools/agent-bridge/tproxy` — እንጂ
> በ`/api/tools/traffic-inspector/` ሥር አይደለም።
> `docs/security/MITM-TPROXY-DECRYPT.md`ን ይመልከቱ (git፤ ወደ `/docs` አልተጠናቀረም)።

### ክፍለ ጊዜዎች
