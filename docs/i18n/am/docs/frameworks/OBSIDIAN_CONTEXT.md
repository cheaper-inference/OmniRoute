## ምንድን ነው

OmniRoute ከ**Obsidian** vault ጋር እንደ **የአውድ ምንጭ** ይገናኛል — ወኪሎች
አብሮ በተሰራው MCP አገልጋይ አማካይነት የሚያነቡትና የሚጽፉበት አካባቢያዊ Markdown
የእውቀት ማከማቻ ነው። ውህደቱ በዴስክቶፕ መተግበሪያው ውስጥ ከሚሰራው
የማህበረሰብ **Obsidian Local REST API** plugin ጋር ይገናኛል፤ በዚህም ወኪሎች
ማስታወሻዎችን መፈለግ፣ ፋይሎችን ማንበብ/መጻፍ/ማስተካከል፣ vaultን መዘርዘር፣
ከዕለታዊ/ሳምንታዊ ወቅታዊ ማስታወሻዎች ጋር መስራት፣ tagsን ማስተዳደር፣
የObsidian ትዕዛዞችን ማስኬድ እና (እንደ አማራጭ) ባለሁለት አቅጣጫ
የዴስክቶፕ↔ሞባይል vault ማመሳሰልን ማስተባበር ይችላሉ።

ደንበኛው (`src/lib/obsidian/api.ts`) Local REST APIን በሚከተሉት ባህሪያት ይሸፍናል፦

- ለጊዜያዊ `5xx` ስህተቶች **ከbackoff ጋር ዳግም መሞከር**፣ በ`AbortController` በኩል **የ30 ሰከንድ timeout**።
- **በtype የተደረገ የስህተት ምደባ** — `ObsidianAuthError` (401/403)፣
  `ObsidianNotFoundError` (404)፣ `ObsidianServerError` (5xx)፣ `ObsidianTimeoutError`።
- የተለመደውን የport ስህተት (HTTP በ`27123` ላይ፣ በ`27124` ላይ ያለው MCP
  endpoint **አይደለም**) እና የTailscale ቅርጸቱን የሚጠቅስ ቀላል
  **«Obsidianን ማግኘት አልተቻለም» ፍንጭ**።
- ክፍተት/slash ያላቸው የማስታወሻ ዱካዎች ደህንነታቸው እንዲጠበቅ፣ ከvault አንጻር
  የሚደረግ **የዱካ ኢንኮዲንግ**።

## ማዋቀር

ለObsidian token ወይም base URL **ምንም environment variable የለም** — ሁለቱም በ
`src/lib/db/obsidian.ts` አማካኝነት በSQLite `key_value` table (namespace `obsidian`) ውስጥ
ይቀመጣሉ። token በማከማቻ ላይ ሳለ **የተመሰጠረ ነው** (AES-256-GCM፣ ከ
plaintext backward-compat fallback ጋር)። ከEndpoint dashboard **Context Sources** tab
(`ObsidianSourceCard`) ወይም በsettings REST API በኩል ያዋቅሩ።

> [!IMPORTANT]
> **Obsidian Local REST API** plugin መጫንና እየሰራ መሆን አለበት። የREST
> interface በ**HTTP `127.0.0.1:27123`** (ነባሪው base URL) ላይ ያዳምጣል። Port `27124`
> _የተለየ_ MCP/HTTPS endpoint ሲሆን በsettings route በግልጽ ውድቅ ይደረጋል።
> ከሌላ device ለመገናኘት `http://<tailscale-ip>:27123` ይጠቀሙ።

### የማዋቀሪያ keys (SQLite `key_value`፣ namespace `obsidian`)

| Key               | ዓላማ                                           | የተመሰጠረ |
| ----------------- | --------------------------------------------- | ------ |
| `api_key`         | የLocal REST API bearer token                  | አዎ     |
| `base_url`        | የREST base URL (ነባሪ `http://127.0.0.1:27123`) | አይ     |
| `vault_path`      | ወደvault directory የሚወስድ absolute path (ለsync) | አይ     |
| `webdav_username` | የተፈጠረ WebDAV username (vault sync)            | አይ     |
| `webdav_password` | የተፈጠረ WebDAV password (vault sync)            | አዎ     |
| `webdav_enabled`  | WebDAV vault sync የነቃ መሆኑን                    | አይ     |

### በREST በኩል ማዋቀር

```bash
# የLocal REST API tokenን ያስቀምጡ + ያረጋግጡ (POST በstatus check ያረጋግጣል)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# የconnection statusን ያረጋግጡ (connected, hasToken, baseUrl, vaultPath ይመልሳል)
curl http://localhost:20128/api/settings/obsidian

# Connectionን ያቋርጡ (የተቀመጠውን token ያጸዳል)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

ሁሉም methods የdashboard authentication ይፈልጋሉ። `POST` በport `27124` ላይ ያለ
ማንኛውንም URL ውድቅ ያደርጋል፣ እንዲሁም tokenን ከማስቀመጡ በፊት የLocal REST API
status endpointን በመጥራት ያረጋግጣል።

### WebDAV vault sync

`src/app/api/settings/obsidian/webdav/route.ts` አማራጭ WebDAV-backed
vault syncን (በ`src/lib/obsidianSync.ts` የሚንቀሳቀስ) ያስተዳድራል። እሱን ማንቃት OmniRouteን
ወደlocal vault directory ያመለክታል፣ እንዲሁም የዘፈቀደ WebDAV username/password ጥንድ
ይፈጥራል፦

```bash
# ለvault directory WebDAV syncን ያንቁ (username/password ይፈጥራል)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# የWebDAV sync statusን ያግኙ (credentials የሚመለሱት ከነቃ ብቻ ነው)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV syncን ያሰናክሉ (credentials + የሚተዳደረውን .stignore ያጸዳል)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### ደህንነት እና ትራንስፖርት

WebDAV ማረጋገጫ በየአይ ፒ አለመሳካት መከታተል እና መቆለፍን ያስፈጽማል (በ60 ሰከንድ መስኮት ውስጥ 10 ያልተሳኩ ሙከራዎች በ `429 Too Many Requests` እና `Retry-After` የ5 ደቂቃ መቆለፊያን ያስነሳል)። WebDAV መሰረታዊ የማረጋገጫ ምስክርነቶችን ስለሚያስተላልፍ፣ TLS ማቋረጥ (ወይም ደህንነቱ በተጠበቀ መሿለኪያ እንደ Tailscale ወይም Cloudflare Tunnel) ወደ WebDAV የመጨረሻ ነጥብ ከ loopback ውጪ ሲደርሱ በጣም ይመከራል።

### ለእያንዳንዱ API key context source (አማራጭ)

የObsidian config በ`api_key_context_sources` table
(`src/lib/db/apiKeyContextSources.ts`) አማካኝነት **ለእያንዳንዱ API key** ሊገደብ ይችላል።
አንድ MCP call የተረጋገጠ API key id ሲይዝ፣ `getObsidianConfigForApiKey()` የዚያን key
የራሱን token/base-URL/vault-path (`source: "api_key"`) ቅድሚያ ይሰጣል፤ አለበለዚያ ወደ
global config (`source: "global"`) fallback ያደርጋል።

sync ያልሆኑ MCP tools ይህን config ከማንበባቸው በፊት የተረጋገጠ caller identity
ይፈልጋሉ። identity የሌለው caller `Obsidian API token not configured` የሚል ምላሽ
ይቀበላል፣ እና ምንም vault request አይላክም። HTTP callers በrequest credentials
አማካኝነት ይለያሉ፤ stdio callers ደግሞ በ`OMNIROUTE_API_KEY` ወይም
`ROUTER_API_KEY` አማካኝነት ሊለዩ ይችላሉ። ያልተለየ HTTP caller የserverን
environment identity ሊወርስ አይችልም። Placeholder IDs ብቻቸውን accessን
አይፈቅዱም፤ ወደ`env-key` የሚፈታ valid environment credential መደገፉን ይቀጥላል።
የተረጋገጡ keys የራሳቸው per-key Obsidian config ከሌላቸው global fallbackን ይጠቀማሉ።
አራቱ `obsidian_sync_*` tools የተለየውን sync-token behavior እንደያዙ ይቀጥላሉ።

## MCP መሳሪያዎች (22)

በ `open-sse/mcp-server/tools/obsidianTools.ts` ይገለጻል። token/base-URL በጥሪ (በኤፒአይ-ቁልፍ መጀመሪያ፣ ከዚያም አለምአቀፍ) ይፈታል። OmniRoute የመታ መሳሪያዎች** የማመሳሰል አገልጋይ** (አራቱ `obsidian_sync_*` መሳሪያዎች) በተጨማሪም በ OmniRoute ቅንብሮች ውስጥ የተዋቀረው የማመሳሰል ማረጋገጫ ቶከንን ይፈልጋሉ።

### መሳሪያዎችን ይፃፉ (`write:obsidian`)

| መሳሪያ                             | መግለጫ                                                                  |
| -------------------------------- | --------------------------------------------------------------------- |
| `obsidian_write_note`            | በተሰጠው Markdown ይዘት ማስታወሻ ይፍጠሩ ወይም ይፃፉ።                                |
| `obsidian_append_note`           | ይዘትን በማስታወሻ ላይ አክል; እንደ አማራጭ ወደ አንድ የተወሰነ heading/block.              |
| `obsidian_patch_note`            | በቀዶ append/prepend/replace ርዕስ፣ ብሎክ ወይም የፊት ጉዳይ መስክ ላይ።               |
| `obsidian_delete_note`           | ከካዝናው ላይ ማስታወሻን እስከመጨረሻው ሰርዝ።                                         |
| `obsidian_move_note`             | በመደርደሪያው ውስጥ ያለ ማስታወሻ ይውሰዱ ወይም እንደገና ይሰይሙ።                            |
| `obsidian_execute_command`       | Obsidian ትዕዛዝ በእሱ ትዕዛዝ ያስፈጽሙ ID.                                      |
| `obsidian_open_file`             | በ Obsidian ውስጥ ፋይል ይክፈቱ (ከሌለው ይፈጥራል)።                                 |
| `obsidian_sync_trigger`          | ወዲያውኑ ባለሁለት አቅጣጫ ያለው ዴስክቶፕ ↔ የሞባይል ቮልት ማመሳሰልን ያስነሱ።                   |
| `obsidian_sync_resolve_conflict` | የማመሳሰል ግጭትን ይፍቱ `local` (ሞባይል)፣ `remote` (ዴስክቶፕ) ወይም `keep-both` አቆይ። |

> [!NOTE]
> `obsidian_patch_note` ኢላማዎች `heading | block | frontmatter` `createTargetIfMissing` ጋር `targetType` እና `operation` `append | prepend | replace`። አራቱ `obsidian_sync_*` መሳሪያዎች ከአካባቢው የማመሳሰል አገልጋይ ጋር ይነጋገራሉ (`http://127.0.0.1:27781` በነባሪ) እና የማመሳሰል ማስመሰያ ያስፈልጋቸዋል።

### ወሰኖች

የንባብ መሳሪያዎች `read:obsidian` ያስፈልጋቸዋል; የመጻፍ መሳሪያዎች `write:obsidian` ያስፈልጋቸዋል . ማስፈጸሚያ `open-sse/mcp-server/server.ts` `withScopeEnforcement()` ከሚስተናገደው Notion — ጋር ተመሳሳይ ነው፣ በ `OMNIROUTE_MCP_ENFORCE_SCOPES=true` ላይ የተከለለ እና API ቁልፍ `manage`/`admin` ለሌለው ለ HTTP/SSE ደዋዮች የሚገደድ፣ ከ `OMNIROUTE_MCP_SCOPES` ወይም ከ API ቁልፍ ወሰን አውድ የተገኘ ነው። [MCP-SERVER.md](./MCP-SERVER.md) ይመልከቱ.

## የአጠቃቀም ሁኔታዎች

- **በvault ላይ የተመሠረቱ መልሶች** — `obsidian_search_simple` / `obsidian_search_structured`
  ከዚያም `obsidian_read_note`፤ ይህም ወኪሉ ከእውነተኛ ማስታወሻዎችዎ ተነስቶ እንዲመልስ ያደርጋል።
- **ማስታወሻ መጻፍ / ዕለታዊ ማስታወሻ መያዝ** — `obsidian_write_note`፣ `obsidian_append_note`፣ ወይም
  የወኪሉን ውጤት፣ ማጠቃለያዎችን ወይም ዕለታዊ ማስታወሻዎችን
  (`obsidian_get_periodic_note`) ወደ vault ለመመዝገብ ትክክለኛ ክፍልን የሚያርም `obsidian_patch_note`።
- **በvault ውስጥ ማሰስ** — ከማንበብ/ከመጻፍ በፊት መዋቅሩን ለማሰስ `obsidian_list_vault`፣ `obsidian_get_document_map` እና
  `obsidian_get_tags`።
- **የObsidian አውቶሜሽን** — ፕለጊኖችን/ትዕዛዞችን ከወኪል ለማስኬድ `obsidian_list_commands` + `obsidian_execute_command`፤
  አንድን ማስታወሻ በUI ውስጥ ለማሳየት `obsidian_open_file`።
- **የሞባይል ማመሳሰል** — የWebDAV ማመሳሰልን ያንቁ፣ ከዚያም ዴስክቶፕ↔ሞባይልን ለማስተባበር እና ግጭቶችን ለመፍታት `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  ይጠቀሙ።
