የገለልተኛ `config/cli-tools-manifest.json` ውል ቀኖናዊ IDs፣ ተለዋጭ ስሞችን፣ ሁለትዮሽ እጩዎችን፣ የቅንብር የምግብ አዘገጃጀት መመሪያዎችን፣ የሞዴል ክርክሮችን እና ችሎታዎችን ያውጃል። በ `bin/cli/cli-manifest.mjs` ውስጥ ያለው ግልጽ የመስቀለኛ መንገድ አስማሚ እና በ `src/shared/constants/cliIntegrationManifest.ts` ውስጥ ያለው TypeScript አስማሚ ተመሳሳይ ፋይል አንብቧል። የሩጫ ጊዜ፣ ካታሎግ፣ ማዋቀር፣ ማጠናቀቅ፣ የጄነሬተሮች እና የኋለኛ ክፍል ምዝገባ በ `tests/unit/cli/cli-manifest-drift.test.ts` አንድ ላይ ተረጋግጧል። ካታሎግ ተደረገ ማለት አንድ መሣሪያ ሊጀመር ወይም ሊዋቀር ይችላል ማለት አይደለም። በተለይ 5dive ውቅረት-ብቻ ይቀራል።

## የሕፃን አካባቢ እና የህይወት ዑደት

`omniroute run`, `omniroute launch` እና `omniroute launch-codex` የ OS/terminal ተኳሃኝነት ፍቃድ ዝርዝር ይወርሳሉ እና የተመረጠውን ኢላማ ምስክርነቶችን ያስገቡ። ያልተገናኙ አቅራቢዎች እና የውሂብ ጎታ ሚስጥሮች በነባሪነት አይወርሱም። `--inherit-env` ሙሉ የወላጅ-አካባቢን ውርስ በግልፅ ይመልሳል; የተመረጠው የሶስተኛ ወገን ሂደት እነዚህን እሴቶች መቀበል ሲኖርበት ብቻ ይጠቀሙበት። ይህ የአካባቢ ማጣሪያ እንጂ የ OS ማጠሪያ አይደለም፡ ሂደቱ አሁንም በጠዋቂው የፋይል ስርዓት ፍቃዶች ይሰራል።

የማቋረጥ እና የማቋረጥ ምልክቶች ለልጁ ይላካሉ. አስጀማሪው ጊዜያዊ ውቅረትን ከማስወገድዎ በፊት የልጁን ቅርብ ክስተት ይጠብቃል። `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` በግዳጅ ከመቋረጡ በፊት የእፎይታ ጊዜን ይቆጣጠራል (ነባሪ 5000 ሚሊሰከንዶች)።

## Gemini የማያቋርጥ ማዋቀር

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

የመጀመሪያዎቹ ሁለት ትዕዛዞች ይህንን ማሽን ለተመረጠው አካባቢያዊ ወይም የርቀት አገልጋይ ያዋቅሩታል። ማዋቀር ያልተዛመዱ JSON ቅንብሮችን ይጠብቃል፣ Gemini API-key authን ይመርጣል እና የመጨረሻ ነጥቡን እና ምስክርነቱን ወደ የግል `.gemini/.env` ፋይል ይጽፋል። ልክ ያልሆነ JSON ከመፃፍ ይልቅ ውድቅ ያደርጋል። የመጨረሻ URLs HTTP(S) መሆን አለበት፣ ያለ የተካተቱ ምስክርነቶች፣ የጥያቄ መለኪያዎች ወይም ቁርጥራጮች። የደረቁ አሂድ ህትመቶች ዱካዎች እንጂ የማረጋገጫ እሴቶች አይደሉም።

`GEMINI_CLI_HOME` ወይም `--gemini-home` ዘላቂውን የቤት ስር ይመርጣል። ትክክለኛ `run gemini` የራሱን ጊዜያዊ ቤት ይፈጥራል እና በኋላ ያስወግዳል። የትኛውም ሁነታ Gemini ን የስራ ቦታ-የእምነት ፍተሻዎችን አያልፍም።

## Codex መገለጫዎች

`configure codex` በሞዴል እና በ OmniRoute አቅራቢው የመጨረሻ ነጥብ የግል `<name>.config.toml` ይጽፋል። ምስክርነቶች በ `OMNIROUTE_API_KEY` በኩል ተጠቅሰዋል፣ በጭራሽ አልተካተቱም። የማስጀመሪያው ትዕዛዝ የተመረጠውን ሞዴል በከፍተኛ ደረጃ `model` ቁልፍ ያስቀምጣል እንጂ በ `model_providers` ውስጥ አይደለም።

የተለዩ የመገለጫ ፋይሎች አሁን ያለው Codex ውል ናቸው; በ `codex --profile <name>` ሲመረጡ የተጠቃሚውን ውቅረት ይሸፍናሉ. [ኦፊሴላዊውን የመገለጫ ማጣቀሻ](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) እና [የ OmniRoute Codex መመሪያን](./CODEX-CLI-CONFIGURATION.md) ይመልከቱ።

## Hermetic ትዕዛዝ አፈጻጸም

ግልጽ በሆነ `DATA_DIR`፣ `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` ማቀናበር ጅምር ወደ ነባሪ የተጠቃሚ ውሂብ ማውጫ የማረጋገጫ አካባቢ እንዳይወድቅ ይከላከላል። ይህ ለገለልተኛ ሙከራዎች ጠቃሚ ነው. ሌሎች በግልጽ የተመረጡ የአካባቢ ፋይሎችን አያሰናክልም።

## የስራ ማውጫ `.env`

CLI በዚህ ቅደም ተከተል `.env` ፋይሎችን ያነባል, እና ቁልፍን ለማዘጋጀት የመጀመሪያው ፋይል ያሸንፋል ግልጽ `DATA_DIR`, ነባሪ የውሂብ ማውጫ, የአሁኑ የስራ ማውጫ, ከዚያም የጥቅል ማውጫ. የሼል ተለዋዋጮች ሁልጊዜ ያሸንፋሉ።

የስራ ማውጫው የሌላ ሰው ሊሆን ይችላል (ክሎድ ማከማቻ፣ ያልታሸገ ማህደር)፣ እና `omniroute serve` የ CLI አካባቢን ወደ አገልጋዩ እና አገልጋዩ ለሚሰራው እያንዳንዱ መሳሪያ ያስተላልፋል። ስለዚህ አንድ `.env` በ `bin/cli/utils/untrustedCwdEnv.mjs` ውስጥ የተዘረዘሩትን እነዚህን ቁልፎች ብቻ ሊያዘጋጅ ይችላል

| ቁልፍ                             | ተቀባይነት ያላቸው እሴቶች                                           |
| ------------------------------- | ---------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` ወይም `yes` በማንኛውም ሁኔታ አገልጋዩ እንደበራ የሚመለከታቸው እሴቶች |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | እስከ 64 ፊደሎች፣ አሃዞች፣ `_`፣ `.`፣ `@` ወይም `-`                   |
| `LANGUAGE`                      | ተመሳሳይ, በተጨማሪም `:`                                          |
| `TZ`                            | እስከ 64 ፊደሎች፣ አሃዞች፣ `_`፣ `+`፣ `-` ወይም `/`፣ በ `/` አይጀመርም     |
| `NO_COLOR`, `FORCE_COLOR`       | እስከ 16 ፊደሎች እና አሃዞች                                        |

`REQUIRE_API_KEY` የሚቀበለው እያንዳንዱ እሴት ቼኩን ያበራል፣ ስለዚህ ፋይሉ በራሱ ቼኩን ማጥፋት አይችልም። ውጤቱን አይወስንም ነገር ግን አገልጋዩ ከአካባቢው በፊት በመረጃ API ውስጥ የተከማቸ የ `REQUIRE_API_KEY` መሻርን ያነባል። በተከማቸ የ `false` መሻር፣ የስራ ማውጫ `REQUIRE_API_KEY=true` API ን ይተዋል እና ያንን ማስጠንቀቂያ ይደብቃል። የ `TZ` ህግ POSIX የበለጠ ጠባብ ነው `.`, `:`, `,` እና `<>` አይቀበልም, ስለዚህ `EST5EDT,M3.2.0,M11.1.0` `:Area/City` ቅርፅ እና ደንቦች በሼል ውስጥ ወይም በ `<DATA_DIR>/.env` ውስጥ መቀመጥ አለባቸው.

ስሞች በአቢይ ሆሄያት በትክክል መመሳሰል አለባቸው። ሌላ ማንኛውም መስመር፣ ቼኩን ያልወደቀ እሴት፣ እና ግልጽ ያልሆነ ASCII ፊደላት፣ አሃዞች እና `_` (ለምሳሌ NUL ባይት ወይም የሚመስል ፊደል ያለው) ስም ተዘሏል። CLI የማያስቀምጣቸውን ቁልፎች የሚሰይም እና ችላ ያላትን የተፈቀዱ ቁልፎችን የሚሰይም አንድ ማስጠንቀቂያ ያትማል እያንዳንዱ ምን መቀየር እንዳለበት (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). ሁለቱም እሴቶቹን አያትሙም። በእነዚህ መልዕክቶች ውስጥ ያሉ የፋይል ዱካዎች እና የ `.env` ዱካ `omniroute doctor` ዘገባዎች የቁጥጥር ወይም የቢዲ ቁምፊዎችን ሲይዙ ያመልጣሉ። የስራ ማውጫው የውሂብ ማውጫው ወይም የጥቅል ማውጫው ሲሆን እገዳው አይተገበርም.

`PORT`፣ `API_PORT` እና `DASHBOARD_PORT` በዝርዝሩ ውስጥ የሉም። ከቅድመ-ቅድመ-ቅድመ-መሠረታዊ URL ሳይኖር, CLI ወደ `localhost:<PORT>` ይነጋገራል, እና እዚያ የሚያዳምጠው የ CLIAPI ቁልፍ, የአውድ ቶከን እና የ CLI ማሽን ማስመሰያ (`x-omniroute-cli-token`, [CLI_TOKEN.md](../security/CLI_TOKEN.md) ይመልከቱ) ይቀበላል, ይህም የአካባቢው አገልጋይ ከ loopback የአስተዳደር ጥሪዎችን ይቀበላል. ከስራ ማውጫው ውስጥ ያለው ወደብ ያ ፋይል ሰሚውን እንዲመርጥ ያስችለዋል፣ስለዚህ ወደቦችን በሼል ውስጥ፣ በ `<DATA_DIR>/.env` ወይም በ `--port` አማራጭ ትዕዛዝ ያዘጋጁ (`serve`፣ `launch`፣ `run`)።

ተንታኙ ምንም `export` አገባብ የለውም። እንደ `export LD_PRELOAD=...` ያሉ መስመሮች ተለዋዋጭ `export LD_PRELOAD` ስሞች; ከስራ ማውጫው ተዘልሏል፣ እና በሌሎች `.env` ፋይሎች ውስጥ ምንም የማያነብ ትክክለኛ ስም ያዘጋጃል።

CLI የአውድ የተከማቸ ማስመሰያ (መዳረሻ ማስመሰያ ወይም ቅርስ API ቁልፍ) ከዚ አውድ አመጣጥ ጋር ብቻ ያጣምራል፡ እቅድ፣ አስተናጋጅ እና ወደብ፣ ከ `URL.origin` ጋር ሲነጻጸር። ይህ በ CLIHTTP ደንበኛ (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) እና በ `launch`, `launch codex`, `configure` እና `setup-*` ትዕዛዞች ላይ ቤዝ URL የሚጽፉ እና ወደ ሌላ መሳሪያ ውቅር የሚገቡ ጥያቄዎችን ይመለከታል። `--remote` ያለው ሌላ አገልጋይ ላይ ሲጠቁሙ አንዱ ከተዋቀረ ግልጽ `--api-key` ወይም `OMNIROUTE_API_KEY` ይጠቀማሉ እና ምንም የአውድ ማስመሰያ የለም። ንጽጽሩ ትክክለኛ ነው፣ስለዚህ `localhost` እና `127.0.0.1`፣ወይም አስተናጋጅ ያለው እና ያለ መከታተያ ነጥብ፣እንደ ተለያዩ አገልጋዮች ይቆጥሩ እና ምንም የአውድ ማስመሰያ አያገኙም። URL ከuserinfo ፣ ከኋላ ቀርፋፋ ወይም ነጭ ቦታ በጭራሽ አይዛመድም ፣ ምክንያቱም ሌሎች URL ተንታኞች (Python's `urllib` እና `httpx`፣ ለምሳሌ) ከእሱ የተለየ አስተናጋጅ ማንበብ ይችላሉ። ለጥያቄዎች CLI እራሱን ይልካል፣ ቼኩ እቅዱን እና ስልጣንን ብቻ ይሸፍናል፣ ስለዚህ በመንገዱ ላይ ቦታ ያለው መታወቂያ ወይም መጠይቁን ይጠብቃል።
