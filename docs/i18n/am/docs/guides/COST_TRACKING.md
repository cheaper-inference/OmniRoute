## ምን እንደሆነ (እና ምን እንዳልሆነ)

OmniRoute የቶክን ብዛቶችን በሞዴሉ የዋጋ ተመኖች በማባዛት ለእያንዳንዱ completion በአንድ ጥያቄ የሚወጣውን የUSD ወጪ ይመድባል። እነዚህ ቁጥሮች የ**ወጪዎች** ዳሽቦርድን፣ `omniroute cost` / `omniroute usage` CLIን፣ የCSV/JSON ውጪ ማስተላለፎችን እና የእያንዳንዱ API ቁልፍ በጀቶችን ያንቀሳቅሳሉ።

> **የዳሽቦርዱ "ወጪ" የቁጠባ መከታተያ እንጂ የክፍያ መጠየቂያ አይደለም።** OmniRoute በፍጹም ክፍያ አያስከፍልዎትም
> — ጥያቄዎችዎን ቀድሞውኑ ወዳገናኟቸው አቅራቢዎች (የራስዎ የደንበኝነት ምዝገባዎች፣
> ነጻ ደረጃዎች እና API ቁልፎች) ይመራል። ሙሉ በሙሉ በነጻ ሞዴሎች ላይ የተከማቸ "$290 ጠቅላላ ወጪ" ማለት በግምት
> **ለሚከፈልበት API ያልከፈሉት $290** ማለት ነው። ይህ አኃዝ ተመሳሳይ ትራፊክ በመደበኛ የዝርዝር ዋጋዎች ምን ያህል ሊያስወጣ እንደሚችል የሚያሳይ _ግምት_ ነው፤ ስለዚህ አጠቃቀምዎ የት እንደተከማቸ እና ወደ ርካሽ/ነጻ አቅራቢዎች መምራት ምን ያህል እንደሚያቆጥብልዎት ማየት ይችላሉ።

ይህ አተያይ በፕሮጀክቱ [README](../../README.md) ውስጥ በቀጥታ ተገልጿል ("የዳሽቦርዱ
'ወጪ' የቁጠባ መከታተያ እንጂ የክፍያ መጠየቂያ አይደለም")።

ቁጥሩ ግምት ስለሆነ፦

- ይህ OmniRoute ለእያንዳንዱ ሞዴል ባለው የዋጋ ሰንጠረዥ ላይ ይመሰረታል። የዋጋ
  ግቤት የሌለው ሞዴል `0` ወጪ ያበረክታል (በመዳሰሻው ውስጥ እንደ "የቆየ / ነጻ" ረድፍ ይታያል)።
- የነጻ ደረጃ እና የደንበኝነት ምዝገባ ትራፊክም ቢሆን _የተገመተ_ ወጪ ያከማቻል — ይህ የሚቆጥቡት መጠን እንጂ የሚፈለግብዎት ክፍያ አይደለም።

## ወጪዎች እንዴት እንደሚገመቱ

### የዋጋ ምንጭ

ወጪዎች በ [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) ውስጥ ካለው የተዋሃደ የዋጋ አሰጣጥ ሰንጠረዥ ይመጣሉ፣ በዚህ ቅደም ተከተል **መጀመሪያ ከፍተኛው** )::

1. **ተጠቃሚ ይሽራል።** — ዋጋዎች በዳሽቦርድ ወይም በ `PATCH /api/pricing` (የ `pricing` ስም ቦታ) ተቀምጠዋል።
2. **ሞዴሎች.dev ማመሳሰል** — ዋጋ ከ `https://models.dev/api.json` (የ `models_dev_pricing` ስም ቦታ) ተገኝቷል።
3. **LiteLLM ማመሳሰል** ከ LiteLLM የህዝብ `model_prices_and_context_window.json` (የ `pricing_synced` ስም ቦታ) የተገኙ — ዋጋዎች።
4. **ሃርድ ኮድ የተደረገባቸው ነባሪዎች** — ተመኖች በ [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) ተልከዋል።

ለተመሳሳይ provider/model, ከከፍተኛ-ቅድመ-ቅድመ-ደረጃዎች ዋጋዎች በዝቅተኛ ንብርብሮች ውስጥ ተዛማጅ መስኮችን ይተካዋል; ከላይኛው ሽፋን ላይ የማይገኙ መስኮች አሁንም ከታችኛው ንብርብር ሊመጡ ይችላሉ. ሁለቱም ገለልተኛ የማመሳሰል ስራዎች በተመሳሳይ ጊዜ ሲሰሩ ትዕዛዙ ተስተካክሏል. `GET /api/pricing?includeSources=1` `pricing` እና `sourceMap` ይመልሳል፣ በእያንዳንዱ ሞዴል መለያቸው (`user`፣ `modelsDev`፣ `litellm`፣ `default`) ያንን ሞዴል የያዘውን ከፍተኛ ቅድሚያ የሚሰጠውን ንብርብር ይለያሉ።

**LiteLLM ማመሳሰል** መርጦ መግባት ነው፣ በነባሪነት ተሰናክሏል። የአካባቢ ተለዋዋጮች ( [`.env.example`](../../.env.example) ይመልከቱ) የሚከተሉት ናቸው

| ኢንቭ var                 | ነባሪ       | ዓላማ                                                    |
| ----------------------- | --------- | ------------------------------------------------------ |
| `PRICING_SYNC_ENABLED`  | `false`   | የበስተጀርባ LiteLLM ዋጋ ማመሳሰልን አንቃ።                         |
| `PRICING_SYNC_INTERVAL` | `86400`   | የማመሳሰል ክፍተት በሰከንዶች (በየቀኑ)።                             |
| `PRICING_SYNC_SOURCES`  | `litellm` | ለዚህ ማመሳሰል ብቻ የምንጭ ምርጫ; በአሁኑ ጊዜ `litellm` ብቻ ነው የሚደገፈው። |

**ሞዴሎች.dev ማመሳሰል** ከ LiteLLM ማመሳሰል የተለየ ነው እና በነባሪነትም ተሰናክሏል። በቅንብሮች (models.dev sync) ውስጥ አንቃው ወይም እነዚህን ተለዋዋጮች ተጠቀም፦

| ኢንቭ var                    | ነባሪ         | ዓላማ                                                                                        |
| -------------------------- | ----------- | ------------------------------------------------------------------------------------------ |
| `MODELS_DEV_SYNC_ENABLED`  | _(ያልተቀናበረ)_ | ማራገፍ የቅንጅቶች መቀያየርን ይከተላል; `1/true/on/yes` በርቷል እና `0/false/off/no` ያስገድዳል (ቅንብሮች ቢያነቃቁትም)። |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`     | ነባሪ ሞዴሎች.dev የማመሳሰል ክፍተት በሰከንዶች (በየቀኑ)።                                                    |

`PRICING_SYNC_SOURCES` ያደርጋል **አይደለም** ሞዴሎችን አንቃ.dev; የ LiteLLM ማመሳሰልን ብቻ ይቆጣጠራል። የተጠቃሚን መሻር መሰረዝ የተመሳሰሉትን የስም ቦታ አያጸዳውም፤ የሚቀጥለው የዋጋ አሰጣጥ ንብርብር ውጤታማ ይሆናል። ዋጋ ላልተከፈለ ሞዴል፣ በእጅ መሻርን ከማከልዎ በፊት ሁለቱንም የማመሳሰል ቅንብሮችን እና `sourceMap` ያረጋግጡ።

### የወጪ ቀመር

ወጪው በ [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`) ውስጥ ካለው የማስመሰያ ብዛት እና የአንድ ሚሊዮን-ቶከን ተመኖች በጥያቄ ይሰላል፦

- **የግቤት ማስመሰያዎች** (መሸጎጫ ንባቦች እና መሸጎጫ-መፍጠር ቶከኖች ሲቀነሱ) × `input` ተመን።
- **መሸጎጫ የተነበቡ ቶከኖች** × `cached` መጠን (ወደ የግብአት መጠን ይመለሳል)።
- **መሸጎጫ-የመፍጠር ምልክቶች** × `cache_creation` መጠን (ወደ የግብአት መጠን ይመለሳል)።
- **የውጤት ምልክቶች** × `output` ተመን.
- **የማመዛዘን ምልክቶች** × `reasoning` መጠን (ወደ የውጤት መጠን ይመለሳል)።

ሁሉም ተመኖች እንደ USD በ1,000,000 ቶከኖች ይተረጎማሉ። Codex "ፈጣን"/"ቅድሚያ" ወይም "ተለዋዋጭ" የአገልግሎት ደረጃ የወጪ ማባዣ (`getCodexFastCostMultiplier`) — ለምሳሌ ፍሌክስ በ50% የቶከን ቅናሽ ተከፍሏል **ተጣጣፊ ቁጠባዎች** በዳሽቦርዱ ውስጥ.

የሞዴል ስሞች መጀመሪያ መደበኛ ናቸው (እንደ `openai/` ወይም `accounts/fireworks/models/` ያሉ የአቅራቢ-መንገድ ቅድመ ቅጥያዎች ተወግደዋል) ስለዚህ ታሪካዊ ረድፎች አሁንም ከዋጋ ጋር ይዛመዳሉ።

### ወጪ እንዴት ተመዝግቧል

- የኤፒአይ-ቁልፍ ወጪ በ [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (በነባሪ የ60ዎቹ የፍሰት ክፍተት፣ 1,000-የመግቢያ ቋት) በቡድን ታጭቆ ይታጠባል። የሚስተካከል በ፡

  | ----------------------------------- | ------- | -------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | የፈሳሽ ክፍተት በሚሊሰከንዶች።        |

### OCR እና መክተቻዎች

- የተሳካላቸው `/v1/ocr` ጥያቄዎች የላይኛውን `usage_info.pages_processed` ይጠቀማሉ እንጂ የተጠየቀውን የገጽ ክልል ወይም የተመለሱ የገጽ ዕቃዎች ብዛት አይደለም። ግምቱ ገጾች × `ocr_cost_per_page` (ፍፁም USD/page፣**አይደለም** USD/million)።
- የሰነድ ወይም የማሰሪያ ሳጥን ማብራሪያዎች ያላቸው ጥያቄዎች የተለየ `ocr_cost_per_annotated_page` ታሪፍ ያስፈልጋቸዋል። ያለሱ, ዋጋው ሳይታወቅ ይቀራል; የተለመደው OCR ታሪፍ በፀጥታ አልተተካም።
- LiteLLM የላይኛውን `annotation_cost_per_page` መስክ ወደ `ocr_cost_per_annotated_page` ያመሳስለዋል፣ ይህም ፍፁም USD/page እሴት እና ማብራሪያ-ብቻ ግቤቶችን፣ ግልጽ ዜሮን ጨምሮ። የቀረበ ቀኖናዊ መስክ ቅድሚያ ይሰጣል; ልክ ያልሆኑ ተለዋጭ ስሞች ችላ ተብለዋል። የተጠቃሚ ዋጋ መሻሮች መደበኛ ቅድሚያቸውን እንደያዙ ይቆያሉ። [የ LiteLLM's OCR የዋጋ አወጣጥ ቁልፎችን](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) ይመልከቱ።
- OCR አጠቃቀም የገጽ ብዛትን፣ የክፍል ዋጋን፣ የተሰላ USD ወጪን፣ API ቁልፍን እና የተመረጠ ግንኙነትን ያከማቻል። ገፆች በጭራሽ እንደ ማስመሰያዎች አይወከሉም። የጥሪ ምዝግብ ማስታወሻዎች የሂሳብ አከፋፈል ሜታዳታ እንጂ URLs፣ PDF ባይት ወይም የወጣ ጽሑፍ አይደለም የያዙት።
- የተሳካላቸው `/v1/embeddings` ጥያቄዎች በአንድ ሚሊሰከንድ ውስጥ የተጠናቀቁትን የተለያዩ ስብስቦችን ጨምሮ አንድ የአጠቃቀም ረድፍ በአንድ አካላዊ ስብስብ ይመዘግባል። በአቅራቢዎች የተዘገበ ክፍያዎች ከቶከን ግምቶች ቅድሚያ ይሰጣሉ; የኮምቦ መጠቅለያዎች ክፍያ አይጨምሩም.
- የአጠቃቀም ታሪክ፣ የወጪዎች ትንታኔ፣ provider/account መስኮቶች፣ የኤፒአይ-ቁልፍ ወጪዎች ገደቦች፣ የጥያቄ-ወጪ ደብተር እና የዕለታዊ አጠቃቀም ጥቅል እነዚህን ክፍያዎች ያካትታሉ። የምዝግብ ማስታወሻ ቁልፎች የምንጭ ጽሑፍን ሳይይዙ የቁጥር ሂሳብን ይይዛሉ።
- የጠፋ አጠቃቀም ወይም ታሪፎች ናቸው።**የማይታወቅ** ነፃ አይደለም፡ የምላሽ-ወጪ ራስጌ ተጥሏል፣ እና አሁን ያለው ዋጋ የሌለው የአጠቃቀም መመሪያ በተወሰኑ API ቁልፎች ላይ ተፈጻሚ ይሆናል። በግልጽ የተዋቀሩ ዜሮ ተመኖች ልክ የዜሮ ወጪ አጠቃቀም ይቆያሉ።

ይህ ወደፊት-ብቻ የሂሳብ አያያዝ ነው። የአጠቃቀም ታሪክን ፈጽሞ ያልጻፉ የድሮ OCR/embedding ጥሪዎች ከዚህ ፍልሰት እንደገና ሊገነቡ አይችሉም። የካታሎግ ግምቶች USD ግምቶች እንጂ ደረሰኝ አይደሉም፣ እና የገንዘብ ልወጣን፣ ታክስን ወይም ቅናሾችን አያካትቱም።

## CLI

የOmniRoute CLI የወጪ፣ የአጠቃቀም እና የዋጋ ትዕዛዞችን ያቀርባል (በ
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) ውስጥ የተመዘገቡ)።

### `omniroute cost`

ከ`/api/usage/analytics` የተጠቃለለ የወጪ ሪፖርት።

```bash
omniroute cost                          # ያለፉት 30d፣ በአቅራቢ የተመደበ
omniroute cost --period 7d              # ያለፉት 7 ቀናት
omniroute cost --group-by model         # በ provider | model | combo | api-key | day መድብ
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ዓምዶች፦ ቡድን፣ ጥያቄዎች፣ የገቡ/የወጡ ቶከኖች፣ ወጪ (USD) እና ከጠቅላላው ያለው %። በመጨረሻ
አጠቃላይ ድምር መስመር ይታተማል (በ`--quiet` ወይም `--output json` ይታገዳል)።

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # የእያንዳንዱ አቅራቢ የወጪ ማጠቃለያ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# በጀቶች
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` `GET /api/pricing/defaults`ን ያነባል። በምትኩ የእያንዳንዱን ሞዴል
> ዋጋ ለማርትዕ፣ የ**ዋጋ አወጣጥ** ዳሽቦርድ ገጽን ወይም `PATCH /api/pricing`ን ይጠቀሙ።
