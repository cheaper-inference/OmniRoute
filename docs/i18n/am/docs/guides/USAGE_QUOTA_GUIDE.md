## አጠቃላይ እይታ

በOmniRoute በኩል የሚያልፍ እያንዳንዱ ጥያቄ የሚከተሉትን የሚይዝ **የአጠቃቀም መዝገብ** ያመነጫል፦

- **ማንነት**: የትኛው API ቁልፍ፣ አቅራቢ፣ ሞዴል እና combo
- **ቶከኖች**: የመጠየቂያ ቶከኖች፣ የማጠናቀቂያ ቶከኖች፣ የተሸጎጡ ቶከኖች፣ ጠቅላላ
- **ወጪ**: የUSD መጠን (ከዋጋ ውሂብ የሚሰላ)
- **ጊዜ**: መዘግየት፣ የመጀመሪያ/ማብቂያ ጊዜ ማህተሞች
- **ሁኔታ**: ስኬት፣ ስህተት፣ የፍጥነት ገደብ፣ ወዘተ።

እነዚህ መዝገቦች ወደ **ትንታኔዎች** ይጠቃለላሉ፣ እንደ **የኮታ ቅጽበታዊ መዝገቦች** በቋሚነት ይቀመጣሉ፣ እንዲሁም **ለእያንዳንዱ ቁልፍ የበጀት ገደቦችን** ለማስከበር ጥቅም ላይ ይውላሉ።

```
ጥያቄ ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                     ትንታኔዎች  ኮታ    ክፍያ
                     (ዳሽቦርድ) (ማስከበር) (መላክ)
```

## የሚመዘገቡት ምንድን ናቸው

የ`usage.ts` አገልግሎት ለእያንዳንዱ ጥያቄ **የአጠቃቀም ክስተት** ይመዘግባል፦

| መስክ                | ዓይነት       | ምንጭ                                                        |
| ------------------ | ---------- | ---------------------------------------------------------- |
| `id`               | ሕብረቁምፊ     | በመመዝገብ ጊዜ የሚፈጠር UUID                                       |
| `apiKeyId`         | ሕብረቁምፊ     | ጥያቄውን ያስጀመረው የAPI ቁልፍ                                      |
| `provider`         | ሕብረቁምፊ     | የአቅራቢ መለያ (openai፣ anthropic፣ ወዘተ)                         |
| `model`            | ሕብረቁምፊ     | የሞዴል መለያ (gpt-5፣ claude-opus-4-6፣ ወዘተ)                     |
| `comboId`          | ሕብረቁምፊ?    | በጥምረት በኩል ከተመራ፣ የጥምረቱ መለያ                                  |
| `promptTokens`     | ቁጥር        | ከላይኛው አቅራቢ ምላሽ                                             |
| `completionTokens` | ቁጥር        | ከላይኛው አቅራቢ ምላሽ                                             |
| `cachedTokens`     | ቁጥር        | በመሸጎጫ የተገኙ ቶከኖች (የAnthropic ግቤት መሸጎጥ፣ ወዘተ)                 |
| `totalTokens`      | ቁጥር        | ግቤት + ማጠናቀቂያ                                               |
| `costUsd`          | ቁጥር        | ከዋጋ ውሂብ የሚሰላ                                               |
| `latencyMs`        | ቁጥር        | የጥያቄው ከመጀመሪያ እስከ መጨረሻ የሚወስደው ጊዜ                            |
| `status`           | ተዘርዛሪ ዓይነት | `success`, `error`, `rate_limited`, `timeout`, `cancelled` |
| `errorClass`       | ሕብረቁምፊ?    | ሁኔታው ስኬት ካልሆነ፣ የስህተት ክፍል                                   |
| `timestamp`        | ሕብረቁምፊ     | ISO 8601 UTC                                               |
| `metadata`         | ነገር        | በተሰኪ የተጨመረ ብጁ ውሂብ                                          |

### ቶከኖች ከየት ይመጣሉ

ቶከኖች በ**ምላሽ አስተናጋጁ** ውስጥ ከላይኛው አቅራቢ ምላሽ ይወጣሉ፦

```ts
// ከ open-sse/handlers/chatCore.ts
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

የአጠቃቀም ውሂብ ለማይመልሱ አቅራቢዎች (አንዳንድ በድር ኩኪ የሚሠሩ አቅራቢዎች)፣ OmniRoute የ`~4 chars per token` ግምታዊ ዘዴን በመጠቀም ቶከኖችን **ይገምታል** (`open-sse/services/autoCombo/pipelineRouter.ts` ይመልከቱ)።

### የተሸጎጡ ቶከኖች

OmniRoute `cached_tokens`ን ከ`prompt_tokens` ለይቶ ይከታተላል፤ ምክንያቱም፦

- የAnthropic ግቤት መሸጎጥ ለተሸጎጡ ቶከኖች ዝቅተኛ ክፍያ ያስከፍላል (ከመደበኛው 10%)
- አንዳንድ አቅራቢዎች በተለየ ዋጋ መሰላት ያለበትን `cache_read_input_tokens` ይመልሳሉ
- ትንታኔዎች **በመሸጎጫ የመገኘት መጠን** = `cached_tokens / prompt_tokens` ማሳየት ይችላሉ

### የመሸጎጫ ጽሑፍ ደረጃ ምርመራዎች

የትንታኔ ዳሽቦርዱ የግቤት መሸጎጫ ጤና ፓነል በአቅራቢው የተሪፖርት የተደረጉ
የ5 ደቂቃ እና የ1 ሰዓት የመሸጎጫ ጽሑፎችን ይለያል። የAnthropic
`usage.cache_creation.ephemeral_5m_input_tokens` እና
`usage.cache_creation.ephemeral_1h_input_tokens` በዥረት እና
በዥረት ባልሆነ የአጠቃቀም መረጃ ለውጥ ወቅት ተጠብቀው ከጥሪ መዝገብ ማጠቃለያዎች ጋር ይቀመጣሉ። የተዋሃደው
ጠቅላላ የመሸጎጫ ጽሑፍ መጠን በእነዚህ ምድቦች ላይ ለሁለተኛ ጊዜ አይጨመርም።

የቆዩ መዝገቦችን ጨምሮ፣ የተዋሃደ የጽሑፍ ቆጣሪ ብቻ ያላቸው ጥሪዎች ደረጃቸው
ያልታወቀ ነው። ከፊል ዝርዝር ሲኖር፣ ያልተመደበው ቀሪ ያልታወቀ ሆኖ ይቆያል፤ ልክ ያልሆኑ ወይም
የሚጋጩ ቆጣሪዎች TTL በዝምታ ከመመደብ ይልቅ ምልክት ይደረግባቸዋል። በጥያቄ በኩል ያሉ
የTTL ምልክቶች ክፍያ የተጠየቀበትን ደረጃ አያረጋግጡም።

የፓነሉ ከAPI ጋር አቻ የሆነ የጽሑፍ ወጪ ግምት የሚሸፍነው ሪፖርት የተደረጉና ዋጋ የተመደበላቸውን ደረጃዎች ብቻ እንጂ
ሙሉ ጥያቄውን አይደለም። ለመደበኛው የClaude/Anthropic ሞዴል ዋጋ አሰጣጥ፣ ለ5 ደቂቃ ጽሑፎች
የግቤት ዋጋውን 1.25 እጥፍ እና ለ1 ሰዓት ጽሑፎች የግቤት ዋጋውን ሁለት እጥፍ ይጠቀማል። የጎደለ
ዋጋ እንደማይገኝ ይቆጠራል እንጂ ዜሮ አይደለም። እያንዳንዱ አዲስ ጥሪ ሲመዘገብ ዋጋዎቹ ይቀመጣሉ፤
የቀድሞ መዝገቦች ዋጋ እንደገና አይሰላም። ስለዚህ የደንበኝነት ምዝገባ መለያዎች ያንን መጠን

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

````ts
## የኮታ ገደብ ማስከበር

ለእያንዳንዱ የAPI ቁልፍ የሚመደበው ኮታ በሁለት ቦታዎች ይከበራል፦

1. **ለስላሳ ገደብ** (`quotaWarnAt`): አጠቃቀሙ ከመነሻ ገደቡ ሲያልፍ በዳሽቦርድ ላይ ማስጠንቀቂያ ይታያል
2. **ጥብቅ ገደብ** (`quotaLimit`): ገደቡ ሲታለፍ ጥያቄው በHTTP 429 ውድቅ ይደረጋል

### ውቅር

```ts
// ለእያንዳንዱ የAPI ቁልፍ
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — ማስጠንቀቂያ አሳይ
  quotaLimit: 10_00,    // $10.00 — ጥብቅ ማቆሚያ
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### የገደብ ማስከበር ፍሰት

```
Request ──▶ quotaCheck()
              │
              ├── Within limit?  ──▶ allow
              │
              └── Over limit?  ──▶ 429 Too Many Requests
                                   with Retry-After header
```

### የኮታ ቅጽበታዊ ቅጂዎች

የ`quotaSnapshots` ሰንጠረዥ ለአዝማሚያ ትንተና **ታሪካዊ የኮታ ሁኔታን** ያስቀምጣል፦

| መስክ | መግለጫ |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | እየተከታተለ ያለው ቁልፍ |
| `window` | "ቀን" | "ሳምንት" | "ወር" |
| `used` | በዚህ የጊዜ መስኮት ውስጥ ጥቅም ላይ የዋለ ወጪ (ሳንቲም) |
| `limit` | ገደቡ (ሳንቲም) |
| `resetAt` | የጊዜ መስኮቱ ዳግም የሚጀምርበት ጊዜ |

ከ0 በላይ ወጪ በሚጠቀም **በእያንዳንዱ ጥያቄ** ላይ ቅጽበታዊ ቅጂዎች ይወሰዳሉ፣ እናም ለሚከተሉት ያገለግላሉ፦

- በዳሽቦርዱ ላይ የኮታ ሂደት አሞሌን ማሳየት
- የ30 ቀን የኮታ አዝማሚያ ገበታዎችን ማሳየት

## ማቆያ እና ማጽዳት

የአጠቃቀም ውሂብ በእያንዳንዱ ጥያቄ ~1-10KB ያድጋል። በከፍተኛ መጠን ሲሠራ፣ ይህ ከፍተኛ መጠን ሊኖረው ይችላል።

### የማቆያ ቅንብሮች

የአጠቃቀም ታሪክ ማቆያ በተጠቃሚ በይነገጹ ውስጥ ባሉት የውሂብ ጎታ ቅንብሮች ወይም በ`/api/settings/database` በኩል ይዋቀራል።

በነባሪ፣ የአጠቃቀም ታሪክ ለ**90 ቀናት** ይቆያል።

### ማጽዳት

የቆዩ መዝገቦች በ`src/lib/db/cleanup.ts` ይጸዳሉ፦

- በጀርባ በሚሠራው የcron ሂደት ይቀሰቀሳል
- ከተዋቀረው የ`usageHistory` ማቆያ ጊዜ በላይ የቆዩ መዝገቦችን ከ`usage_history` ይሰርዛል

### የማከማቻ ግምት

| የጥያቄ መጠን       | የ30 ቀን ማከማቻ | የ90 ቀን ማከማቻ |
| -------------- | ----------- | ----------- |
| 100 ጥያቄ/ቀን     | ~3MB        | ~9MB        |
| 1,000 ጥያቄ/ቀን   | ~30MB       | ~90MB       |
| 10,000 ጥያቄ/ቀን  | ~300MB      | ~900MB      |
| 100,000 ጥያቄ/ቀን | ~3GB        | ~9GB        |

ለእጅግ ከፍተኛ የጥያቄ ፍሰት፣ የሚከተሉትን ያስቡበት፦

- በውሂብ ጎታ ቅንብሮች በኩል የማቆያ ጊዜውን መቀነስ
- ከጥሬ መዝገቦች ይልቅ `aggregated_metrics`ን መጠቀም (ለትንታኔ ብቻ)

## ወጪን ለማመቻቸት ጠቃሚ ምክሮች

### 1. ተገቢውን ሞዴል ይጠቀሙ

```bash
# ፈጣን መልስ — ርካሽ + ፈጣን ይጠቀሙ
curl -d '{"model":"auto/fast","messages":[...]}'

# ውስብስብ ተግባር — ጥራትን ይጠቀሙ
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. መሸጎጥን ያንቁ

የAnthropic ፕሮምፕት መሸጎጥ **በተደጋጋሚ በሚጠቀሙበት አውድ ላይ 90% ይቆጥባል**፦

```ts
// መሸጎጡ በራስ-ሰር ይከናወናል — ተመሳሳዩን ትልቅ የስርዓት ፕሮምፕት ማካተት ብቻ ይበቃል
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // በራስ-ሰር ይሸጎጣል
  messages: [{ role: "user", content: "..." }],
});
```

### 3. መጭመቅን ይጠቀሙ

የRTK + Caveman መጭመቅ **መሣሪያዎችን በብዛት በሚጠቀሙ ክፍለ ጊዜዎች 15-95% ይቆጥባል**፦

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. ለእያንዳንዱ ቁልፍ የአጠቃቀም ገደብ ያዘጋጁ

ከቁጥጥር ውጭ የሆነ ወጪን ለመከላከል ሁልጊዜ `quotaLimit` ያዘጋጁ፦

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // የ$10/ወር ገደብ
```

በAPI ቁልፍ ለመቧደን እና በወጪ ለመደርደር ዳሽቦርዱን ወይም **`/api/usage/analytics`** ይጠቀሙ፦

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## ችግሮችን መፍታት

### "ወጪው ከተጠበቀው በላይ ነው"

1. **`/api/usage/analytics?groupBy=model`** ይፈትሹ — ውዱን ሞዴል ያግኙ
2. **`/api/usage/analytics?groupBy=apiKey`** ይፈትሹ — በብዛት የሚጠቀመውን ያግኙ
3. የዋጋ ውሂቡ ወቅታዊ መሆኑን ያረጋግጡ፦ `POST /api/pricing/sync`

### "መዝገቦች ጎድለዋል"

- በዳሽቦርድ → የውሂብ ጎታ → ማጽዳት ስር ያሉትን የDB ማቆያ ቅንብሮች ይፈትሹ — የቆዩ መዝገቦች በየጊዜው በሚከናወነው የማጽዳት ተግባር ይሰረዛሉ (`src/lib/db/cleanup.ts`)
- በ`src/lib/db/usage*.ts` ውስጥ ስህተቶች እንዳሉ ይፈትሹ — በDB ላይ የመጻፍ አለመሳካቶች ይመዘገባሉ፣ ግን በግልጽ አይታዩም
- ጥያቄው በእርግጥ `chatCore` መድረሱን ያረጋግጡ — የcombo ማዘዋወርን ይፈትሹ

### "የአጠቃቀም ገደቡ እየተተገበረ አይደለም"

- የቁልፉን `quotaLimit` ቅንብር ይፈትሹ
- `quotaWindow` በትክክል መዘጋጀቱን ያረጋግጡ
- የ`quotaSnapshots` መዝገቦችን ይፈልጉ — በእያንዳንዱ ጥያቄ መፈጠር አለባቸው
