ብጁ JSON API መስቀለኛ መንገድ የ OpenAI ወይም Anthropic ፕሮቶኮሉን የማይናገር JSON ንግድ የመጨረሻ ነጥብ ያገናኛል። OmniRoute የ JSON ጥያቄ አብነት ሞልቶ ወደተጠናቀቀው የመጨረሻ ነጥብ URL ይልካል፣ መልሱን ከምላሽ መንገድ አንብቦ ለደንበኛው በራሱ ቅርጸት (የውይይት ማጠናቀቂያ፣ ምላሾች፣ መልዕክቶች፣ ...) ይመልሳል።

ከ `apiType: "custom-json"` ጋር ከOpenAI ጋር ተኳሃኝ የሆነ መስቀለኛ መንገድ ነው; መታወቂያው `openai-compatible-custom-json-<suffix>` ቅጽ አለው። የዳሽቦርዱ ቅጹ እስካሁን አይገኝም። ከታች በአቅራቢው-node API እነዚህን አንጓዎች ይፍጠሩ እና ያርትዑ።

## መስቀለኛ መንገድ ይፍጠሩ

`POST /api/provider-nodes` (የአስተዳደር ማረጋገጫ)፡-

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` ነው።** ተጠናቀቀ** የመጨረሻ ነጥብ URL. ምንም ነገር አልተጨመረም ( `/chat/completions` የለም፣ ምንም `/models` የለም ) እና እንደሌሎች የOpenAI-ተኳሃኝ አንጓዎች በተቃራኒ ምንም ነባሪ URL የለም። `http(s)` መሆን አለበት፣ ያለተከተተ ምስክርነቶች ወይም `#fragment`፣ እና ልክ እንደ እያንዳንዱ አቅራቢ መስቀለኛ መንገድ ወደ ውጭ የሚወጣ URL ጠባቂ ያልፋል፣ ሁለቱም መስቀለኛ መንገድ ሲቀመጥ እና በእያንዳንዱ ጥያቄ።
- የግንኙነት ቁልፉን (`authType` `bearer` ወይም `api-key`፣ ነባሪውን ጨምሮ) የሚልክ መስቀለኛ መንገድ `https://` መጠቀም አለበት። Plain `http://` የሚቀበለው ለ loopback አስተናጋጅ (`localhost`፣ `127.0.0.0/8`፣ `::1`) ወይም ከ `authType: "none"` ጋር ብቻ ነው፣ እሱም ምንም ቁልፍ አይልክም። የግል LAN አድራሻዎች (`10.x`, `172.16-31.x`, `192.168.x`) ነፃ አይደሉም፡ በዚያ አውታረ መረብ ላይ ያለ ማንኛውም ሰው ቁልፉን ማንበብ ይችላል። እንደዚህ ያለ መስቀለኛ መንገድ ማስቀመጥ `400` ጋር አልተሳካም, እና ማንኛውም ጥያቄ ከመላኩ በፊት ቀደም ሲል የተከማቸ መስቀለኛ መንገድ በእያንዳንዱ ጥያቄ ላይ ተመሳሳይ መልእክት ይዘጋል. በ LAN ላይ ላለ ቁልፍ የመጨረሻ ነጥብ፣ ከ TLS ጀርባ (ለምሳሌ ተገላቢጦሽ ፕሮክሲ) ያድርጉት።
- `customJson` በ Zod የተረጋገጠ ነው; ያልታወቁ ቁልፎች ውድቅ ተደርገዋል። እያንዳንዱ መስክ አማራጭ ነው፡-

| መስክ               | እሴቶች                                    | ነባሪ                                                    |
| ----------------- | --------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                  | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`             | `bearer`                                               |
| `authHeader`      | `api-key` በሚሆንበት ጊዜ ጥቅም ላይ የዋለው የራስጌ ስም | `X-API-Key`                                            |
| `requestTemplate` | JSON ነገር (≤ 64 KB፣ ጥልቀት ≤ 32)           | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | የመስክ መንገድ, ወይም `$` ለሙሉ አካል              | `choices[0].message.content`                           |

- ሚስጥሩ በግንኙነቱ API ቁልፍ ውስጥ ይቆያል፣ በጭራሽ በአብነት ውስጥ የለም። `bearer` `Authorization: Bearer <key>` ይልካል; `api-key` `<authHeader>: <key>` ይልካል . የማረጋገጫው ራስጌ `Host`፣ `Content-Type`፣ `Content-Length`፣ `Connection`፣ `Transfer-Encoding`፣ `Authorization`፣ `Cookie` ወይም ሆፕ-በሆፕ ራስጌ ሊሆን አይችልም። በ `none`፣ ግንኙነቶች ምንም ቁልፍ አያስፈልጋቸውም።
- ተጨማሪ የማይንቀሳቀሱ ራስጌዎች የመስቀለኛ ክፍሉን መደበኛ `customHeaders` ይጠቀማሉ (ከሌሎች ተኳሃኝ አንጓዎች ጋር አንድ አይነት ማረጋገጫ፣ የማረጋገጫ ራስጌዎች እዚያ አይፈቀዱም)።

`PUT /api/provider-nodes/<id>` ተመሳሳዩን `customJson` ተቀብሎ `baseUrl` እና አወቃቀሩን በእያንዳንዱ ነባር የኖድ ግንኙነት ላይ ይጽፋል። `customJson` መተው የተከማቸ ውቅረትን ያቆያል; `apiType` ወደ `chat` ወይም `responses` መቀየር ከኖድ እና ግንኙነቶቹ ያስወግደዋል.

ከዚያ እንደተለመደው በመስቀለኛ መንገድ ላይ ግንኙነትን ይጨምሩ (`POST /api/providers` ከመስቀለኛ መታወቂያው ጋር) እና `<prefix>/<model>` ይጠይቁ ለምሳሌ `biz/assistant-v1`. የመጨረሻው ነጥብ ምንም የሞዴል ዝርዝር አያጋልጥም፣ ስለዚህ የሞዴሉን መታወቂያዎች በእጅ ያክሉ።

## አብነቶችን ይጠይቁ

አብነቶች ግልጽ JSON ናቸው። የሕብረቁምፊ እሴት `{{placeholder}}` ማርከሮችን ሊይዝ ይችላል። ምንም ነገር አልተገመገመም ወይም አልተተገበረም, እና የነገር ቁልፎች በጭራሽ አይተኩም.

| ቦታ ያዥ                | ዋጋ                                                        |
| -------------------- | --------------------------------------------------------- |
| `{{prompt}}`         | የቅርብ ጊዜ የተጠቃሚ መልእክት ጽሑፍ (የጽሑፍ ክፍሎች ከአዲስ መስመሮች ጋር ተቀላቅለዋል) |
| `{{messages}}`       | ውይይቱ በ OpenAI ውይይት ቅርጸት                                   |
| `{{model}}`          | የተጠየቀው የሞዴል መታወቂያ፣ ያለ አቅራቢው ቅድመ ቅጥያ                       |
| `{{stream}}`         | ሁልጊዜ `false` — የመጨረሻው ነጥብ በአንድ JSON ሰነድ ይመልሳል             |
| `{{request.<path>}}` | የተተረጎመው መስክ (OpenAI የውይይት ቅርጸት) ጥያቄ                       |

- በትክክል አንድ ቦታ ያዥ የሆነ እሴት JSON አይነትን ይይዛል (`"{{messages}}"` ድርድር ይሆናል)። ረዘም ያለ ሕብረቁምፊ ውስጥ ያለ ቦታ ያዥ እንደ ጽሑፍ ገብቷል።
- ምንም ነገር ያልፈታ ቦታ ያዥ ያልተሟላ የክፍያ ጭነት ከመላክ ይልቅ በ HTTP 400 ጥያቄውን አይወድቅም።
- ዱካዎች የነጥብ ኖታ እና የቁጥር ኢንዴክሶችን (`data.items[0].text`) ይጠቀማሉ። `__proto__`፣ `prototype` እና `constructor` በቁልፍ እና መንገዶች ውድቅ ተደርገዋል።

## ምላሾች

በ `responsePath` ላይ ያለው እሴት የረዳት ምላሽ ይሆናል፡ ሕብረቁምፊዎች ያልፋሉ፣ ሌሎች JSON እሴቶች በቅደም ተከተል ተቀምጠዋል። የጎደለ ወይም `null` መስክ፣ ወይም JSON ያልሆነ አካል HTTP 502 ይመልሳል። ወደላይ የስህተት ሁኔታዎች ያልፋሉ። ለዥረት ደንበኞች OmniRoute ሙሉውን JSON ምላሽ ይጠብቃል እና እንደ አንድ የይዘት ቁራጭ እና የማጠናቀቂያውን ክፍል ያወጣል; ይህ ማስመሰያ ዥረት አይደለም። የመሳሪያ ጥሪዎች እና የአጠቃቀም መስኮች አልተዘጋጁም።

## ዳግም አልተጫወተም።

የንግድ ጥያቄ ሳይሳካ ቢቀርም የጎንዮሽ ጉዳቶች ሊኖረው ይችላል። OmniRoute ስለዚህ አንድ ጊዜ ይልካል፡-

- ምንም የማጓጓዣ ድጋሚ መሞከር እና ምንም አቅጣጫ መቀየር የለም;
- በሌላ ግንኙነት ላይ እንደገና አይሞክሩ (የመለያ ውድቀት) — አለመሳካቱ እንደነበረው ተመልሶ ግንኙነቱ አይቀዘቅዝም;
- ለሚቀጥለው ጥምር ዒላማ ምንም መውደቅ የለም፣ ባዶ ወይም ያልተሳካ ምላሽ እንኳን።

የተለያዩ የደንበኛ ጥያቄዎች እና የተለያዩ ሞዴሎችን በግልፅ የሚጠሩ የውህደት ፓነሎች አሁንም የማጠቃለያ ነጥቡን በግል ይጥራሉ።

## መስቀለኛ መንገድን መሞከር

ግንኙነትን በማስቀመጥ ላይ, ግንኙነቱ** ሙከራ** የአዝራር እና የጀርባ የጤና ፍተሻዎች የመጨረሻውን ነጥብ በጭራሽ አይጠሩም: የተከማቸ ውቅረትን ብቻ ያረጋግጣሉ እና ግንኙነቱን ማረጋገጥ እንደማይቻል ሪፖርት ያደርጋሉ.

`POST /api/provider-nodes/validate` ከ `"apiType": "custom-json"` እና የመስቀለኛ ክፍል ቦታዎች (`baseUrl`፣ `apiKey`፣ `customJson`፣ አማራጭ `customHeaders` እና `modelId`) በትክክል አንድ ትክክለኛ ጥያቄ ይልካል፣ `ping` እንደ የቅርብ ጊዜ የተጠቃሚ ጽሑፍ። እሱ `{ "valid": true }` ወይም ወደ ላይ ያለውን ሁኔታ ይመልሳል (በፍፁም ወደላይ አካል አይሆንም)።

## ማከማቻ

ውቅሩ በ `provider_nodes.custom_json_config_json` (ሚግሬሽን `240_provider_node_custom_json_config.sql`) ውስጥ ተከማችቶ ወደ እያንዳንዱ የግንኙነት `providerSpecificData.customJson` ይገለበጣል።
