## TL;DR — OmniRoute በእርግጥ ምን ያህል ነፃ inference ያጠቃልላል?

እነዚህ አሃዞች በካታሎጉ ውስጥ የሚገኙ የተለያዩ የሶስተኛ-ወገን መለያዎችን እና የብቁነት ሁኔታዎችን ይገልጻሉ። OmniRoute ይህን በጀት አይሰጥም፤ አስፈላጊዎቹን መለያዎች ወይም ማረጋገጫዎች ማግኘት፣ ብቁ አቅራቢዎችን ማገናኘት እና ገደቦቻቸውን ማክበር አለብዎት። በተግባር ሊጠቀሙበት የሚችሉት አቅም ከዚህ ያነሰ ሊሆን ይችላል፤ ብቁ መንገድ በሌለበት አዲስ ጭነት ላይ ዜሮ እንኳን ሊሆን ይችላል። `tos: avoid` ተብለው የተሰየሙ አቅራቢዎች በነባሪ ከራስ-ሰር ማዘዋወር ውስጥ አይካተቱም።

**የተረጋገጠው 2026-10-08:** [Cerebras](https://www.cerebras.ai/pricing) የክፍያ ዘዴ የሚያስፈልገው፣ ከ30 ቀናት በኋላ የሚያበቃ የአንድ ጊዜ $5 የማስተዋወቂያ ክሬዲት ያቀርባል። [Gemini](https://ai.google.dev/gemini-api/docs/rate-limits) የፕሮጀክት/ሞዴል/ደረጃ የጥያቄ መጠን ገደቦችን ያትማል፤ በመጠን ከተገለጸው ወርሃዊ አጠቃላይ ቁጥር ውጭ ይቆያል።

- **አንድ መዝገብ በትክክል ምን ያረጋግጣል።** ማንኛውም መዝገብ በየረድፉ የእምነት ደረጃ አይይዝም፣ API-ውም እንዲህ ያለ መረጃ አያቀርብም — እያንዳንዱን አኃዝ ተመሳሳይ፣ ግን ያልተገለጸ ጥራት ያለው ግምት እንደሆነ ይቆጥሩ። ሁለት እውነታዎች ግን የተለዩ ናቸው፤ እነሱም ከግምት ይልቅ በእጅ የተመረጡ ስለሆኑ ነው፦ 44 መዝገቦች በተለየ ሰነድ የተረጋገጠ ጠንካራ ማቆሚያ አላቸው (ከእነዚህ 39ኙ የxKiro ረድፎች ናቸው፣ እነሱም ሁሉ አንድ የዕለት ፈቃድ ይጋራሉ)፣ እና 22 መዝገቦች የፕሮምፕት ሥልጠና መግለጫ አላቸው። `hardStopGuaranteed` የሚዘጋጀው የአቅራቢው የራሱ ውሎች የነጻ ፈቃዱን ማለፍ ጥያቄውን እንደሚከለክል እንጂ በዝምታ ክፍያ እንደማይጀምር ሲሉ ብቻ ነው፤ ምንጩም ከመዝገቡ አጠገብ ባለ አስተያየት ውስጥ ይገኛል። በነባሪነት ወደ `true` አይቀየርም፣ እና ማንም ያላረጋገጠው መዝገብ ሳይሞላ ይቀራል። ስለዚህ የጠንካራ ማቆሚያ ምልክት አለመኖሩ “እንደሚከፍልዎ የታወቀ ነው” ማለት ሳይሆን “እንዳለ አልተረጋገጠም” ማለት ነው። **STRICT ሁነታ** (የመርጦ መጠቀሚያው `freeAccessPolicy=strict` የማዞሪያ ጠባቂ) የሚተማመነው ይህን ምልክት በያዙ መዝገቦች ላይ ብቻ ነው፤ ሌሎች እያንዳንዱ የነጻ ደረጃ `no-hard-stop` ተብሎ ይወገዳል (ይመልከቱ `open-sse/services/autoCombo/strictZeroCostFilter.ts`)። ጠባቂው የመረጃ ስብስብን ሲያጣራ፣ ለኦፕሬተሩ የሚታየው ሎግ የተወገዱትን ብዛትና የ`no-hard-stop` ድርሻቸውን ሁለቱንም ያሳያል።
- `estMonthlyFreeTokens` = በየወሩ በተደጋጋሚ የሚሰጡ ቶከኖች ብቻ። **አንድ ጊዜ የሚሰጡ የመመዝገቢያ ክሬዲቶች አይደገሙም** እና እንደ 0 ይቆጠራሉ። የተቋረጡ ደረጃዎችም 0 ናቸው።
- የዕለት ቶከን ገደብ → `monthly = daily × 30`። RPD ብቻ ከተመዘገበ → `RPD × ~800 output tokens × 30`። RPM/TPM ብቻ (የዕለት ገደብ ከሌለ) → **ያልተገደበ** (ከዚህ በታች ይመልከቱ)።
- **የነጻ መዳረሻ አለ፣ ግን የታተመ የቶከን ገደብ የለም** (`glm-cn`, `tencent`, `baidu`, `kilo-gateway`, `opencode-zen`, `gemini`, `nvidia`)፦ እነዚህ በፍጥነት/በአንድ ጊዜ ጥያቄዎች ብዛት የተገደቡ ናቸው። `recurring-uncapped` ብለን እንመድባቸዋለን እና **በፍጹም አንድ ላይ አንደምራቸውም** — `RPM × 24/7 × 30d` ማባዛት የማይጨበጥ ከፍተኛ ገደብ ያስገኛል (እኛ የምንተወው ይህ የተጋነነ ግምት ነው)። የNVIDIA API ለሙከራ ጥቅም ብቻ ነው፤ ከታች ያለውን የToS ማስጠንቀቂያ ይመልከቱ።
- **የተቀማጭ-ገንዘብ መክፈቻ ጭማሪ፦** የነጻ ኮታን በቋሚነት የሚያሳድግ አንድ ጊዜ የሚደረግ ትንሽ ተጨማሪ ክፍያ (OpenRouter፦ $10 → 1000 req/day ≈ +24M/mo)። እንደ የተለየ አኃዝ ይሪፖርት ይደረጋል፣ ከቀጣይ ዋና ጠቅላላ ድምር ግን ውጭ ይቀመጣል።
- **በብቁነት የተገደቡ ኮታዎች** (`eligibilityGate: "regional-identity"`)፦ ከክልል ጋር የተያያዘ የማንነት ማረጋገጫ (በአሁኑ ጊዜ በዋናው ቻይና የእውነተኛ ስም ማረጋገጫ) ከተጠናቀቀ በኋላ ብቻ የሚከፈት እውነተኛ በየወሩ የሚደገም ኮታ ነው። ከተመሳሳይ የመረጃ ስብስብ ማስወገጃ ደንብ ጋር በመጠቀም ወደ ተለየ አኃዝ (`gatedRecurringTokens`) ይቆጠራል፣ ወደ ቀጣይ ዋና ጠቅላላ ድምር ግን በፍጹም አይገባም። የአጠቃቀሙ ሥርዓት (`freeType`) አይቀየርም፣ ስለዚህ የማዞሪያ ሥርዓቱም አይቀየርም።
- **የማስረጃ ክፍሎች።** ደንቡ ይህ ነው፦ በካታሎጉ ውስጥ ያለ ቁጥር ምንጩን ከመዝገቡ አጠገብ ባለ `// evidence:` አስተያየት ውስጥ ይጠቅሳል — `public-page` (ማንኛውም ሰው ሊያነበው የሚችል የአቅራቢ ገጽ)፣ `api-public` (የአቅራቢው ማንነት ማረጋገጫ የማያስፈልገው endpoint፣ ለምሳሌ በrouter.bynara.id ያለው የNaraRouter ይፋዊ የዕቅድ endpoint)፣ ወይም `console-verified <date> por <who>` (አኃዙ በመለያ ኮንሶል ውስጥ ብቻ የሚታይ ነው፤ አስተያየቱ ማን እንዳየውና መቼ እንዳየው፣ እንዲሁም ገደቡ እንዳለ የሚገልጸውን ይፋዊ ገጽ ይመዘግባል)። የዛሬው ሁኔታ፦ በ2026-09-02 እንደገና የተመረመሩት አምስቱ ብሎኮች ይህን ይይዛሉ (`gemini`, `groq`, `mistral`, `ollama-cloud`, `nara`)፤ ከ2026-09-02 ዳግም ምርመራ በፊት የነበሩ መዝገቦች እስኪነኩ ድረስ የቀድሞውን ምርምር ይወርሳሉ፤ ማንኛውም **አዲስ ወይም የተቀየረ** ቁጥር የማስረጃ አስተያየት ከሌለው ሳንካ ነው። ዛሬ የኮንሶል ማረጋገጫ ያለው `mistral` ብቻ ነው።

## የእኛ ቁጥር ከሌሎች አሰባሳቢዎች ቁጥር ያነሰ የሆነው ለምንድን ነው

በዚህ ዘርፍ ያሉ አብዛኞቹ የ«በወር ነፃ ቶከኖች» ቁጥሮች ለእያንዳንዱ ሞዴል የተሰጡ ቁጥሮች ድምር ናቸው። የእኛ ግን ሆን ተብሎ እንዲህ አይደለም፦

- **እያንዳንዱ የጋራ ማጠራቀሚያ አንድ ጊዜ ብቻ ይቆጠራል።** የMistral ነፃ ዕቅድ ለእያንዳንዱ ድርጅት በወር አንድ የ1B ፈቃድ ነው፤ በአምስት ሞዴሎች ስር መዘርዘሩ 5B አያደርገውም። በየሞዴሉ ቢደመር፣ የራሳችን ካታሎግ **~7.4B** ይሆን ነበር (በ2026-09-03 እንደገና የተሰላ፤ ይህ ቁጥር በCI አይገደብም — ካታሎጉ በተቀየረ ቁጥር እንደገና ይለኩት) — ዋናው ርዕስ **~1.47B** የሚለው የእያንዳንዱ አቅራቢ አንድ መለያ በእውነት ሊጠቀምበት የሚችለው መጠን ይህ ስለሆነ ነው።
- **የዕለት ገደቦች ይቀየራሉ፣ የፍጥነት ገደቦች ግን አይቀየሩም።** በሰነድ የተገለጸ የቶከን/ቀን ገደብ `× 30` ይሆናል፤ በሰነድ የተገለጸ የጥያቄዎች/ቀን ገደብ `RPD × ~800 tokens × 30` ይሆናል፤ በደቂቃ የጥያቄዎችን ብዛት ብቻ የሚያትም አቅራቢ **ምንም** ወርሃዊ ቁጥር የለውም እና _ያልተገደበ_ ተብሎ ይዘረዘራል፤ ፈጽሞ በድምሩ ውስጥ አይገባም። የፍጥነት ገደብን በ24/7 ማባዛት እኛ የማንቀበለው ማጋነን ነው።
- **ከክልላዊ የማንነት ማረጋገጫ ጀርባ ያሉ ኮታዎች ለብቻቸው ይታያሉ** (`+~6M behind regional identity verification`)፣ ምክንያቱም አብዛኞቹ አንባቢዎች ሊጠቀሙባቸው አይችሉም።
- **የምዝገባ ክሬዲቶች ለመጀመሪያው ወር ብቻ ናቸው** እና እንደ ሁለተኛ ቁጥር ይገለጻሉ፤ ከቋሚው ቁጥር ጋር ፈጽሞ አይቀላቀሉም።
- **ቁጥሩ በCI ይረጋገጣል።** `npm run check:docs-counts` ከካታሎጉ ድምሮቹን እንደገና ያሰላል፤ ይህ ፋይል፣ README ወይም የበጀት ካርዱ ከእነሱ ሲለይ ግንባታውን ያሳክታል።

> **የToS ምልክት ምክረ ሃሳብ ብቻ ነው፣ የማዞሪያ መግቢያ መስፈርት አይደለም።** `tos` ምልክት የተሰጣቸው አቅራቢዎች አሁንም በነባሪነት በማዞሪያ እና በጥምረት/መተኪያ ውስጥ ይካተታሉ፤ ምልክቱ በ`/dashboard/free-tiers` እና `/api/free-tier/summary` ላይ ብቻ ይታያል። `excludeTosAvoid` የጥያቄ መለኪያው የማጠቃለያ እይታን ብቻ ይነካል፣ አጠቃላይ ማዞሪያን አይነካም። ውሳኔው በ`open-sse/config/freeTierCatalog.ts` ውስጥ ይገኛል (መረጃ ለመስጠት ብቻ ነው፣ በማዞሪያ ሞተሮች አይነበብም)።

> ራስዎ ለሚያስተናግዱት፣ ለአንድ ተጠቃሚ የግል ፕሮክሲ የእያንዳንዱ አቅራቢ የአጠቃቀም ደንቦች አጭር ግምገማ። `caution` = ሊመረመር የሚገባ የግል አጠቃቀም ወይም የፕሮክሲ አንቀጽ፤ `ambiguous` = ግልጽ ያልሆነ፤ `ok` = በግልጽ የተፈቀደ። ለመረጃ ብቻ ነው፣ የሕግ ምክር አይደለም — ውሳኔውን እርስዎ ይወስናሉ።
