## በ `setup-*` በራስ-አዋቅር

የእያንዳንዱን መሳሪያ ውቅር በእጅ መጻፍ አያስፈልግም። OmniRoute የሚለውን የሚያነብ የ `setup-*` ትዕዛዝ በእያንዳንዱ የሚደገፍ CLI ይልካል** መኖር** የሞዴል ካታሎግ ከሩጫ OmniRoute (አካባቢያዊ ወይም የርቀት መቆጣጠሪያ) እና የመሳሪያውን የራሱን ውቅር በማሽንዎ ላይ ይጽፋል

```bash
omniroute setup-codex        omniroute setup-claude       omniroute setup-opencode
omniroute setup-cline        omniroute setup-kilo         omniroute setup-continue
omniroute setup-cursor       omniroute setup-roo          omniroute setup-crush
omniroute setup-goose        omniroute setup-qwen         omniroute setup-aider
omniroute setup-5dive        omniroute setup-zed
omniroute setup-whycodes
```

እያንዳንዱ `--remote <url> --api-key <key>` (የአካባቢውን መሳሪያ ከርቀት OmniRoute ጋር ያዋቅሩ)፣ `--dry-run` (ሳይፃፍ ቅድመ እይታ) እና `--port` ይቀበላል። ያለ ሞዴል ራስ-ግኝት (Cline, Kilo, Roo, Goose, Aider, Qwen, 5dive, WhyCodes) መሳሪያዎች `--model <id>` (እና `--yes` መስተጋብራዊ ላልሆኑ ሩጫዎች) ይወስዳሉ. `setup-5dive` በ `$HOME` ስር የማይጽፈው አንዱ የምግብ አዘገጃጀት መመሪያ ነው፡ የስርወ-ባለቤትነት ማረጋገጫን በ የበረራ አስተናጋጁ ላይ በመፃፍ 5dive agent መርከቦችን ያዋቅራል፣ ስለዚህ በ `sudo` እንደገና ይሰራል እና የራሱ የርቀት ሁነታ የለውም። CLI ለማስጀመር ትክክለኛው ኢንቪ የተከተተ እና ምንም አይነት ውቅረት ያልተጻፈበት፣ አጠቃላይ የሆነውን `omniroute run <target>` ማስጀመሪያን ተጠቀም (claude, codex, aider, goose, opencode, qwen, gemini, whycodes — ኢላማዎች እና ተለዋጭ ስሞች ከ `bin/cli/cli-manifest.mjs` የመጡ ናቸው); የቅርስ በመሳሪያ አስጀማሪዎች `omniroute launch` (Claude Code) እና `omniroute launch-codex` (Codex) ይገኛሉ። Gemini CLI ማስጀመሪያ-ብቻ ነው `omniroute run` ኢላማ ነው ነገር ግን `setup-*`/`configure` የምግብ አሰራር የለውም።

> **ሙሉ ማጣቀሻ፡** ዋናው ጠረጴዛ - እያንዳንዱ ትዕዛዝ የሚጽፈውን, እያንዳንዱን ባንዲራ, አካባቢያዊ vs የርቀት መቆጣጠሪያ እና የትኞቹ መሳሪያዎች `/v1` ቅጥያ ይፈልጋሉ - ይኖራል.** [CLI ውህደቶች](../guides/CLI-INTEGRATIONS.md)** .

### እነዚህን በእቃ ማጠራቀሚያ ውስጥ ማስኬድ

በ OmniRoute ኮንቴይነር ውስጥ የተተገበረ `setup-*` ትእዛዝ በእቃ መያዣው ቤት ውስጥ ይጽፋል፣ ማንም አስተናጋጅ CLI የማያነብ እና ከእቃ መያዣው ጋር ይጠፋል። OmniRoute ያንን አግኝቶ ከመጻፍ ይልቅ በመመሪያው ከ `2` ይወጣል። ሁለት የሚደገፉ መንገዶች ወደፊት - CLI በአስተናጋጁ ላይ እና `omniroute connect` ወደ መያዣው ላይ ይጫኑት ወይም ኮንግረስ ዲርስን ያስሩ እና `CLI_CONFIG_HOME` ያዘጋጁ (የ `host` ፕሮፋይል ያዘጋጁ)። እያንዳንዱ `setup-*` ትእዛዝ፣ እንዲሁም `omniroute configure` እና `omniroute config set`፣ የመያዣውን የራሱ CLIs ሲያዋቅሩ `--allow-container-write` ይቀበላል እርስዎ በትክክል ለማለት የፈለጉት ነው። `OMNIROUTE_ALLOW_CONTAINER_CONFIG_WRITE=true` ለአገልጋዩም እንዲሁ ያደርጋል። [Docker መመሪያን ይመልከቱ → አስተናጋጅ CLI መሳሪያዎችን በማዋቀር ላይ](../guides/DOCKER_GUIDE.md#configuring-host-cli-tools-when-omniroute-runs-in-docker) ።

ዳሽቦርዱ** የመጨረሻ ነጥብ ተግብር** (`POST /api/cli-tools/apply`) ተመሳሳይ ጥበቃን ያስፈጽማል፡ በኮንቴይነር ውስጥ ኢላማው ያልተያያዘ ጽሁፍ ከአስተናጋጁ መልስ ይሰጣል**`422`** ከ `containerEphemeralTarget: true` ጋር, ደህንነቱ የተጠበቀ የስህተት ጽሑፍ እና - ለመሳሪያዎች በአስተናጋጅ የምግብ አዘገጃጀት መመሪያ (ክላውድ, ኮዴክስ, ክፍት ኮድ, ክላይን, ኪሎ, ቀጥል) - `hostSetupCommand` (ለምሳሌ `omniroute setup-opencode`) በምትኩ በአስተናጋጁ ላይ እንዲሰራ; ምንም አልተጻፈም. `dryRun: true` በመያዣ ሞድ ውስጥ መስራቱን ይቀጥላል እና ዲስክን ሳይነካ የተቀየረ ቅድመ እይታ + ኢላማ መንገድን ይመልሳል። ቅድመ-ዕይታ ይዘት ለመቅዳት ወይም ለማስመጣት ምስክርነት ያለው ውቅር አይደለም። በአስተናጋጁ ላይ ከመጀመሪያው tool/base URL/API key/model ግብዓቶች ጋር ያመልክቱ ወይም የተጠቆመውን የአስተናጋጅ-ጎን ማዋቀር ትዕዛዙን ይጠቀሙ። ለቅድመ እይታ ራስጌ [CLI ውቅር ደህንነትን](../security/CLI-CONFIGURATION.md) ይመልከቱ እና ውል ይጠይቁ። ይህ ባህሪ ሆን ተብሎ እና በድግግሞሽ የሚጠበቀው በ `tests/unit/api/cli-tools/apply-container-guard.test.ts` - ጠባቂውን በማንሳት 422 ን በጭራሽ "ማስተካከል".

## 5. የቡድን ማወቂያ API

ሁሉም የመሣሪያ ማወቂያዎች በአንድ endpoint በኩል ተሰባስበዋል፦

**`GET /api/cli-tools/all-statuses`**

- ማረጋገጫ፦ `requireCliToolsAuth(request)` (ከሌሎች የ`/api/cli-tools/` routes ጋር ተመሳሳይ)
- የሚመልሰው፦ `Record<toolId, ToolBatchStatus>` (ዓይነት፦ `src/shared/types/cliBatchStatus.ts`)
- ስልት፦ በሁሉም መሣሪያዎች ላይ `Promise.all`፣ ለእያንዳንዱ መሣሪያ የ5 ሰከንድ timeout
- መሸጎጫ፦ በconfig ፋይል `mtime` የሚጠቀስ የማህደረ ትውስታ ውስጥ LRU። mtime ሲቀየር መሸጎጫው ዋጋ አልባ ይደረጋል። አገልጋዩ ዳግም ሲጀምር ዳግም ይጀመራል።

ለእያንዳንዱ መሣሪያ የምላሹ ቅርጽ፦

```ts
interface ToolBatchStatus {
  detection: {
    installed: boolean;
    runnable: boolean;
    version?: string;
    command?: string;
    commandPath?: string;
    reason?: string;
  };
  config: {
    status: "configured" | "not_configured" | "not_installed" | "unknown" | "other";
    endpoint?: string | null;
    lastConfiguredAt?: string | null;
  };
  error?: string; // የተጣራ፣ የstack trace የሌለው
}
```

## 10. ውስጣዊ OmniRoute CLI

የ`omniroute` ባይነሪ ለሰርቨር የሕይወት ዑደት፣ ማዋቀር፣ ምርመራዎች እና የአቅራቢ አስተዳደር ትዕዛዞችን ይሰጣል። መግቢያ ነጥብ፦ `bin/omniroute.mjs`።

```bash
omniroute                              # ሰርቨሩን አስጀምር (ነባሪ ፖርት 20128)
omniroute setup                        # መስተጋብራዊ የማዋቀር አዋቂ
omniroute doctor                       # ውቅርን፣ DBን፣ ፖርቶችን እና runtimeን ፈትሽ
omniroute providers list               # የተዋቀሩ የአቅራቢ ግንኙነቶች
omniroute providers test-all           # እያንዳንዱን ንቁ ግንኙነት ፈትሽ
omniroute reset-password               # የአስተዳዳሪውን የይለፍ ቃል ዳግም አስጀምር
omniroute logs                         # የጥያቄ ሎጎችን በቀጥታ አሰራጭ
omniroute health                       # ዝርዝር የጤና ሁኔታ (breakers፣ cache፣ memory)
omniroute --version                    # ስሪቱን አትም
omniroute --help                       # ሁሉንም ትዕዛዞች አሳይ
```

### ማዋቀር እና ማስጀመር

```bash
  --provider openai \
  --api-key '<value>' \
  --test-provider                      # አቅራቢን በአንድ ጊዜ ጨምር እና ፈትሽ
```

| ተለዋዋጭ               | ዓላማ                                                           |
| ------------------- | ------------------------------------------------------------- |
| `OMNIROUTE_API_KEY` | የአቅራቢ API ቁልፍ (በCommander `.env()` በኩል ከ`--api-key` ጋር የተያያዘ) |
| `DATA_DIR`          | የOmniRoute ውሂብ ማውጫን ተካ                                        |

ሁሉም ሌሎች መስተጋብራዊ ያልሆኑ ግብዓቶች እንደ flags ይተላለፋሉ፣ እንደ የአካባቢ ተለዋዋጮች አይደለም፦
`--password`፣ `--provider`፣ `--provider-name`፣ `--provider-base-url`፣ `--default-model`
(ከላይ ያሉትን የ`omniroute setup` አማራጮች ይመልከቱ)።

### ምርመራዎች

```bash
omniroute doctor                       # ውቅርን፣ DBን፣ ፖርቶችን፣ runtimeን፣ memoryን እና livenessን ፈትሽ
omniroute doctor --json                # በማሽን ሊነበብ የሚችል JSON
omniroute doctor --no-liveness         # የHTTP ጤና መመርመሪያን ዝለል
omniroute doctor --host 0.0.0.0        # የliveness hostን ተካ
omniroute doctor --liveness-url <url>  # ሙሉውን የጤና endpoint URL ተካ
```

doctor እነዚህን ፍተሻዎች ያካሂዳል፦ `Config`፣ `Database`፣ `Storage/encryption`፣
`Port availability`፣ `Node runtime`፣ `Native binary` (better-sqlite3)፣
`Memory` እና `Server liveness`። ማንኛውም ፍተሻ `fail` ከሆነ ዜሮ ባልሆነ ኮድ ይወጣል።

### የአቅራቢ አስተዳደር

```bash
omniroute providers available                       # የOmniRoute አቅራቢ ካታሎግ
omniroute providers available --search openai       # ካታሎጉን በid/name/alias/category አጣራ
omniroute providers available --category api-key    # በምድብ አጣራ (api-key፣ oauth፣ free፣ ...)
omniroute providers available --json                # በማሽን ሊነበብ የሚችል JSON

omniroute providers list                            # የተዋቀሩ የአቅራቢ ግንኙነቶች
omniroute providers list --json

omniroute providers test <id|name>                  # አንድ የተዋቀረ ግንኙነትን ፈትሽ
omniroute providers test-all                        # እያንዳንዱን ንቁ ግንኙነት ፈትሽ
omniroute providers validate                        # አካባቢያዊ-ብቻ መዋቅራዊ ማረጋገጫ
omniroute providers add <provider> --credential-env PROVIDER_KEY
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth <provider>                 # ነባር OAuth ፍሰት
omniroute providers edit <id|name> --default-model <model>
omniroute providers remove <id|name> --yes
```

`providers add/import/auth/edit/remove` API-ቀዳሚ ናቸው፤ ስለዚህም
በንቁው አካባቢያዊ ወይም የርቀት context ላይ ይሰራሉ። የማረጋገጫ መረጃ ግብዓት
`--credential-stdin` ወይም `--credential-env`ን መጠቀም አለበት፤ `--dry-run --json`
የተደበቀ መኖር/ቅርጽን ብቻ ሪፖርት ያደርጋል። `providers available` የOmniRoute ካታሎግን ያነባል፤
`providers list/test/test-all/validate` አካባቢያዊ የSQLite ባህሪያቸውን ይዘው ይቆያሉ እና
ሰርቨሩ እየሰራ እንዲሆን አይጠይቁም።

ለብጁ OpenAI-compatible ወይም Anthropic-compatible node፣
በ`omniroute nodes add` የተመለሰውን node ID በመጠቀም በ`omniroute keys add "$NODE_ID" --stdin`
የማረጋገጫ መረጃን ከnodeው ጋር ያያይዙ።
ይህ ለንቁው context የሚሰራ ሰርቨር እና የአስተዳደር ማረጋገጫ ይፈልጋል።
CLIው `POST /api/providers`ን ይጠቀማል፤ ይህም nodeውን ያረጋግጣል እና የendpoint
ቅንብሮቹን ወደ ግንኙነቱ ይቀዳል። የጠፋ node፣ የፍቃድ ውድቀት ወይም የማይገኝ
ሰርቨር አካባቢያዊ fallback የማረጋገጫ መረጃ ሳይፈጥር ስህተት ይመልሳል።

`nodes add --base-url` የnode endpointን ያዘጋጃል፤ ይህም በ`OMNIROUTE_BASE_URL`
ውስጥ ካለው የሰርቨር አድራሻ የተለየ ነው። ለOpenAPI ፋይሎች
`omniroute openapi dump --format json --out ./openapi.json`ን ይጠቀሙ፤ ዓለም አቀፉ `--output`
የCLI ማሳያ ቅርጸትን ይመርጣል እንጂ የመድረሻ ፋይል ስምን አይደለም።

### መልሶ ማግኘት እና ዳግም ማስጀመር

```bash
omniroute reset-password                # የአስተዳዳሪውን የይለፍ ቃል ዳግም አስጀምር (እንዲሁም፦ omniroute-reset-password)
omniroute reset-encrypted-columns       # ለተመሰጠሩ የማረጋገጫ መረጃዎች ዳግም ማስጀመሪያ ማስጠንቀቂያ + dry-run አሳይ
omniroute reset-encrypted-columns --force  # በSQLite ውስጥ ያሉ የተመሰጠሩ የማረጋገጫ መረጃዎችን በእርግጥ null አድርግ
```

### የማረጋገጫ መረጃ ወደ ውጭ መላክ (⚠ በጥንቃቄ ይያዙ)

```bash
omniroute auth export                                 # ማስጠንቀቂያ + የማረጋገጫ ደረጃ አሳይ — የDB መዳረሻ የለም
omniroute auth export --force                          # የሁሉንም ግንኙነቶች ዲክሪፕት የተደረጉ የማረጋገጫ መረጃዎች እንደ JSON ወደ stdout ላክ
omniroute auth export --force --id <id>                 # የሚዛመደውን ግንኙነት ብቻ ወደ ውጭ ላክ
omniroute auth export --force --format env               # OMNIROUTE_<PROVIDER>_<FIELD>=<value> መስመሮችን አውጣ
omniroute auth export --force --out creds.json           # ወደ ፋይል ጻፍ (በ0600 ፈቃዶች የሚፈጠር)
```

`auth export` **በአካባቢያዊ ማሽን ብቻ** የሚሰራ ነው (SQLiteን በቀጥታ ያነባል፤ የHTTP መስመር የለውም)፣ እንዲሁም
የ**ግልጽ ጽሑፍ** `apiKey`/`accessToken`/`refreshToken`/`idToken` እሴቶችን ሆን ብሎ ያትማል/ይጽፋል — ይህ ባህሪው እንጂ
ስህተት አይደለም። `--force` ከሌለ ከውሂብ ጎታው ምንም አይነበብም፣ እንዲሁም ምንም ዲክሪፕት አይደረግም። ማንኛውም ግልጽ ጽሑፍ ከመውጣቱ በፊት የማስጠንቀቂያ ሰንደቅ ሁልጊዜ ወደ stderr
ይታተማል። `STORAGE_ENCRYPTION_KEY` መዋቀር አለበት። ዲክሪፕት ማድረግ ያልተሳካለት መስክ (ጊዜው ያለፈበት ቁልፍ፣ የተበላሸ ciphertext) ሙሉውን export ከማቋረጥ ወይም ዋናውን ስህተት ከማጋለጥ ይልቅ
`<field>DecryptFailed: true` ተብሎ ሪፖርት ይደረጋል።

### ሌሎች ንዑስ ትዕዛዞች

በተለየ ሁኔታ ካልተገለጸ በስተቀር፣ እነዚህ እየሰራ ያለ OmniRoute አገልጋይ እንዳለ ይገምታሉ፦

```bash
omniroute status                       # አጠቃላይ የአሂድ ጊዜ ሁኔታ
omniroute logs                         # የጥያቄ ምዝግቦችን በቀጥታ ያስተላልፉ (--json, --search, --follow)
omniroute config list                  # የተዋቀሩ CLI መሣሪያዎችን ያሳዩ

omniroute provider list                # የሚገኙ አቅራቢዎችን ይዘርዝሩ (የ providers list ተለዋጭ ስም)
omniroute provider add                 # OmniRouteን በአንድ መሣሪያ ላይ እንደ አቅራቢ ይመዝግቡ
omniroute keys add | list | remove     # የAPI ቁልፎችን ያስተዳድሩ
omniroute models [provider]            # ሞዴሎችን ይዘርዝሩ (--json, --search)
omniroute combo list | switch | create | delete

omniroute backup                       # የውቅረት + DB ቅጽበታዊ ቅጂ
omniroute restore                      # ከቀድሞ ቅጽበታዊ ቅጂ ወደነበረበት ይመልሱ

omniroute health                       # ዝርዝር የጤና ሁኔታ (breakers፣ cache፣ memory)
omniroute quota                        # የአቅራቢ ኮታ አጠቃቀም
omniroute cache                        # የcache ሁኔታ
omniroute cache clear                  # semantic + signature cachesን ያጽዱ

omniroute mcp status | restart         # የMCP አገልጋይ ሁኔታ / ዳግም ማስጀመር
omniroute a2a status | card            # የA2A አገልጋይ ሁኔታ / የወኪል ካርድ

omniroute tunnel list | create | stop  # tunnelsን ያስተዳድሩ (cloudflare/tailscale/ngrok)
omniroute env show | get <k> | set <k> <v>  # የአካባቢ ተለዋዋጮችን ይመርምሩ / ያዋቅሩ (ጊዜያዊ)

omniroute test                         # የአቅራቢ ግንኙነት መሠረታዊ ሙከራ
omniroute update                       # ዝማኔዎችን ይፈትሹ
omniroute completion                   # የshell completionን ያመንጩ
```

## የinference-key መመሪያን በOmniRoute CLI ያስተዳድሩ

ነባር inference keyን በIDው ለመመርመር ወይም ለማዘመን፣ ማንነቱ የተረጋገጠ የአስተዳደር አውድ ይጠቀሙ ([የርቀት ሁነታ](../guides/REMOTE-MODE.md)ን ይመልከቱ)፦

```bash
omniroute --output json keys policy show KEY_ID
omniroute keys policy set KEY_ID --unrestricted
omniroute --output json keys policy show KEY_ID
```

`--unrestricted` ለ`--model-access-mode all` ተለዋጭ ስም ነው። ዝማኔው የሞዴል የፍቃድ ዝርዝሩን ያጸዳል። ወሰኖችን፣ የግንኙነት ደንቦችን፣ የታገዱ ሞዴሎችን፣ የፍጥነት ገደቦችን እና የወጪ ገደቦችን እንዳሉ ያቆያል፤ ስለዚህ እነዚያ ሌሎች መቆጣጠሪያዎች አሁንም ጥያቄን ሊከለክሉ ይችላሉ። `--allowed-models ""`ን በግልጽ መጠቀምም `all`ን ይመርጣል፤ ምንም የተፈቀዱ ሞዴሎች የሌሉት የተገደበ ቁልፍ ለማቆየት ከ`--model-access-mode restricted` ጋር ያጣምሩት። ባዶ ያልሆነ በኮማ የተለየ ዝርዝር፣ በግልጽ ሌላ ካልተገለጸ በስተቀር፣ `restricted`ን ይመርጣል። እርስ በርሱ የሚጋጭ `all` ከባዶ ያልሆነ የፍቃድ ዝርዝር ጋር ከተጣመረ፣ ጥያቄው ከመላኩ በፊት ውድቅ ይደረጋል።

`--rate-limit 30` በደቂቃ የሚፈቀዱ ጥያቄዎችን ያዘጋጃል፣ ለሌሎች የጊዜ መስኮቶች ያሉ ደንቦችንም እንዳሉ ያቆያል። `--max-cost 5` ሳምንታዊውን ገደብ ሳይቀይር ዕለታዊውን የUSD ጣሪያ ያነቃል፤ `--max-cost 0` ዕለታዊውን ጣሪያ ያስወግዳል፣ ነባሩን የአጠቃቀም ገደብ ማብሪያና ሳምንታዊውን ጣሪያ ግን እንዳሉ ያቆያል። ያልተጠቀሱ የመመሪያ መስኮች ሳይቀየሩ ይቀራሉ። የፍጥነት ለውጦች መጀመሪያ የአሁኑን መመሪያ ያነባሉ፤ የአንድን ቁልፍ የፍጥነት-ገደብ ድርድር በአንድ ጊዜ ከማርትዕ ይቆጠቡ።

የመመሪያ ትዕዛዞች ማንነቱ የተረጋገጠ `GET`/`PATCH /api/keys/{id}`ን ይጠቀማሉ፣ ንቁውን አውድ እና ዓለም አቀፉን `--api-key` አማራጭም ያከብራሉ። የJSON ውጤቱ የመመሪያ መስኮችን ብቻ ይይዛል፤ የተከማቸውን ቁልፍ ወይም የተሸፈነውን ውክልናውን አያካትትም። ለinference ብቻ የሚያገለግል ማረጋገጫ የአስተዳደር ለውጦችን መፍቀድ አይችልም። 401/403 ከተከሰተ የአስተዳደር ማረጋገጫውን እና አውዱን መፈተሽ ያስፈልጋል፤ ይህ ግን የአካባቢያዊ CLI-token ወይም salt ብልሽት መኖሩን አያረጋግጥም። ለተለየው የአካባቢያዊ ማረጋገጫ ውል [CLI Token](../security/CLI_TOKEN.md)ን ይመልከቱ።
