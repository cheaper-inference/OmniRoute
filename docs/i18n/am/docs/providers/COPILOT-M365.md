`copilot-m365-web` (ቅጽል `m365copilot`) የ OpenAI-format ውይይት ጥያቄዎችን በ Microsoft 365 Copilot ክፍለ ጊዜ በ `m365.cloud.microsoft/chat` ይልካል። ይህ ኦፊሴላዊ ያልሆነ ቤተኛ ውህደት ነው፡ ምንም የተለየ የተኪ ሂደት ወይም የአካባቢ አስተናጋጅ ወደላይ አያስፈልግም። አቅራቢው ID፣ ተለዋጭ ስም እና አሁን ያሉ ከውጪ የሚመጡ ግንኙነቶች አልተለወጡም። `copilot-web` በ `copilot.microsoft.com` ላይ ለፍጆታ አገልግሎት የተለየ አቅራቢ ነው።

> **ለድር ኩኪ አቅራቢዎች አዲስ?**
>
> አንብብ**`docs/getting-started/WEB-COOKIE-GUIDE.md`** ይህንን አቅራቢ-ተኮር መመሪያ ከመከተልዎ በፊት ለአጠቃላይ ማዋቀር ሂደት፣ የማረጋገጫ መመሪያ፣ ገደቦች እና መላ ፍለጋ።
>
> **ለቅርስ ማስመጣት፡-** የዚህ አቅራቢ ምስክርነት ነው።** ኩኪ አይደለም** . ኩኪዎችን ከ `m365.cloud.microsoft` አትቅዱ . ምስክርነቱ የ WebSocket URL መጠይቅ መለኪያ እና ዱካ ክፍል ነው፣ ሁለቱም ከ DevTools አውታረ መረብ ትር ይነበባሉ።

## ቅድመ-ሁኔታዎች

- የ Microsoft 365 መለያ በ Copilot ወደ `m365.cloud.microsoft/chat` መዳረሻ ያለው
- Chromium ላይ የተመሰረተ አሳሽ (Chrome፣ Edge) ለ DevTools WebSocket ፍተሻ
- በዚያ መለያ ላይ የተጠየቀውን ሞዴል መድረስ; ተገኝነት በተከራይ እና በፈቃድ ይለያያል

## ቤተኛ መግባት (የስራ ወይም የትምህርት ቤት መለያዎች)

ይምረጡ**Microsoft 365 Copilot → አገናኝ** እና የመግባት ሙከራ ያዘጋጁ። ዳሽቦርዱ ከ PKCE ጋር የፈቃድ-ኮድ ፍሰት ይጠቀማል; የእርስዎን Microsoft የይለፍ ቃል ወይም MFA ኮድ አይጠይቅም።

1. ክፈት ሀ** ባዶ የአሳሽ ትር** ፣ ከዚያ ይክፈቱ**DevTools → አውታረ መረብ** እና አንቃ** ምዝግብ ማስታወሻን አቆይ** . ወደ Microsoft ከመሄድዎ በፊት ይህንን ያድርጉ Windows SSO ወዲያውኑ ሊጨርስ ይችላል።
2. በግንኙነት መገናኛው የሚታየውን URL የፈቀዳ ቅዳ እና በተዘጋጀው ትር ውስጥ ወደ እሱ ይሂዱ። ከተጠየቀ የ Microsoft መለያ ምርጫን ወይም MFA ይሙሉ።
3. በተጠበቀው የአውታረ መረብ መዝገብ ውስጥ የ `https://login.microsoftonline.com/common/oauth2/nativeclient` ጥያቄን ይፈልጉ እና ሙሉውን ይቅዱ** URL ጠይቅ** .
4. ያንን URL ወደ የግንኙነት መገናኛው ይለጥፉ እና ያገናኙ። ጥሬ ኮድ ወይም የመጨረሻውን `wrongplace` አድራሻ-አሞሌ URL አይለጥፉ፡ የሚፈለገው መልሶ ጥሪ ጊዜያዊ አሰሳ ነው።

እያንዳንዱ ሙከራ ከአስር ደቂቃዎች በኋላ ጊዜው ያበቃል እና አንድ ጊዜ ብቻ መጠቀም ይቻላል. አገልጋዩ ኮዱን ከመቀየሩ በፊት ሁኔታውን፣ PKCE አረጋጋጭ እና የማረጋገጫ ኢላማውን ይፈትሻል። ጊዜው ካለፈ በኋላ ወይም የልውውጡ ውድቀት ካለቀ በኋላ አዲስ ሙከራ ይጀምሩ። አንድ ሙከራ ከአገልጋይ ዳግም መጀመር አይችልም።

ቶከኖች ያለውን የግንኙነት ምስክርነት ማከማቻ እና የማደስ ዱካ ይጠቀማሉ። ግንኙነትን እንደገና ማረጋገጥ አንድ አይነት ኢሜይል ብቻ ሳይሆን ተመሳሳይ Microsoft tenant/object ማንነትን ይፈልጋል። ኦፕሬተር naming/settings ይጠብቃል እና ጊዜ ያለፈባቸውን ከውጭ የሚመጡ ምስክርነቶችን ይተካል። ቤተኛ መግባት ለ work/school መለያዎች ነው፤ የቅርስ የማስመጣት ዱካ ለነባር ግንኙነቶች እና ለሚደገፉ የደረጃ ውቅሮች እንዳለ ይቆያል።

ሙሉ መልሶ መደወል URL የአንድ ጊዜ ምስክርነት ነው። በቅጽበታዊ ገጽ እይታዎች፣ ምዝግብ ማስታወሻዎች፣ የድጋፍ መልእክቶች ወይም ድርጊቶች ውስጥ በጭራሽ አያካትቱት። ይህ ፍሰት በአገልጋዩ ላይ አሳሽ አይከፍትም ፣ የአሳሽ ታሪክዎን አይመረምርም ፣ ወይም የአካባቢ መልሶ ጥሪ አገልጋይ አይጀምርም።

## የማረጋገጫ ቀረጻ (WebSocket ዘዴ)

1. በ `https://m365.cloud.microsoft/chat` ይግቡ እና ውይይት ይጀምሩ።
2. ክፈት**DevTools → አውታረ መረብ** .
3. አጣራ በ**WS** (WebSocket)
4. የ Chathub WebSocket ግንኙነትን ጠቅ ያድርጉ። በ `wss://substrate.office.com/m365Copilot/Chathub/` የሚጀምር URL ይፈልጉ።
5. ከሱ** URL ጠይቅ** ቅዳ፡
   - የ `access_token` መጠይቅ መለኪያ እሴት (አጭር ጊዜ የሚቆይ JWT)።
   - `/Chathub/` በኋላ ያለው የቻቱብ መንገድ ክፍል (ለምሳሌ `<oid>@<tenant>`)።

ሙሉው URL የሚከተለው ቅጽ አለው፡-

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute ውስጥ፣ ይምረጡ**Microsoft 365 Copilot** , የድሮውን API-key/import አማራጭ ይምረጡ እና ምስክርነቱን በቅርጸት ይለጥፉ

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. ጠቅ ያድርጉ** ግንኙነትን ይሞክሩ** እና** አስቀምጥ** .

## የማረጋገጫ ቀረጻ (HAR ማስመጣት)

እሴቶችን ከ WebSocket URL በእጅ ከመቅዳት ይልቅ የ DevTools HAR ፋይል ወደ ውጭ መላክ ይችላሉ፡-

1. ክፈት**DevTools → አውታረ መረብ** .
2. የ Microsoft 365 Copilot ውይይት ይጀምሩ ወይም ይቀጥሉ (ይህ የ WebSocket ግንኙነትን ያነሳሳል)።
3. በአውታረ መረብ ፓነል ላይ በቀኝ ጠቅ ያድርጉ እና ይምረጡ** ሁሉንም እንደ HAR በይዘት ያስቀምጡ** .
4. በ OmniRoute፣ ይጠቀሙ** የሃር ፋይል አስመጣ** በአቅራቢው የግንኙነት መገናኛ ላይ ያለው አዝራር.

OmniRoute ለ Chathub WebSocket URLHAR ይቃኛል፣ `access_token` እና `chathubPath` ያወጣል እና የማረጋገጫ ቦታዎችን በራስ ሰር ይሞላል። የ HAR ማስመጣት የ JWT የአገልግሎት ማብቂያ ጊዜን ይፈታዋል እና የቀረውን ቶከን የህይወት ዘመን ያሳያል።

> **እውነተኛ HAR ወደ ውጪ መላክ፣ የመዳረሻ ማስመሰያ ወይም የማደስ ማስመሰያ በጭራሽ አታድርጉ።** የፈተና እና የሰነድ እሴቶች ሁልጊዜ ቦታ ያዥ መሆን አለባቸው።

## የህይወት ዘመን ማስመሰያ እና አድስ

`access_token` አጭር ነው (በተለምዶ**~ 75 ደቂቃዎች** ). ጥቅም ላይ ሊውል የሚችል የማደስ ማስመሰያ ከሌለ፣ ጊዜው ካለፈ በኋላ ማረጋገጫውን እንደገና ማንሳት አለብዎት።

### በ `refreshToken` ራስ-ሰር አድስ

በ Microsoft 365 አቅራቢዎች ውስጥ** ግንኙነት ጨምር** ወይም** ግንኙነትን ያርትዑ** መገናኛ, ክፍት** የላቁ ቅንብሮች → አድስ ማስመሰያ (አማራጭ)** . ለ `substrate.office.com/sydney` ወሰን የ Microsoft OAuth አድስ ማስመሰያ ይለጥፉ እና ያስቀምጡ። ግብአቱ ተሸፍኗል እና በተከማቸ ማስመሰያ በጭራሽ አይሞላም። አርትዖት በሚደረግበት ጊዜ ነባሩን ማስመሰያ ለማቆየት ባዶውን ይተዉት; እሱን ለመተካት አዲስ ማስመሰያ ይለጥፉ።

ቤተኛ መግባት Microsoft አንዱን ስትመልስ የማደስ ማስመሰያውን ያገኛል። ለውርስ ማስመጣት፣ አሁን ያለውን ተኳሃኝ Microsoft የፈቀዳ-ኮድ ስጦታን ተጠቀም። ይህ አቅራቢ የመሣሪያ-ኮድ ፍሰትን አይተገበርም ወይም ቃል አይገባም። የማደስ ማስመሰያ ተዋቅሮ፣ OmniRoute ከመጠየቁ በፊት `access_token` ን ይፈትሽ እና የሚያድስ ሲፈልግ ብቻ ያድሳል። የተሳካ እድሳት እንዲሁ የተሽከረከረውን የማደስ ማስመሰያ እንደቀጠለ ነው፣የእድሳት ማስመሰያው ግን የሚሰራ ሆኖ ሳለ በእጅ እንደገና ከመያዝ በማስቀረት።

`refreshToken` ካልተዋቀረ የ WebSocket ምስክርነቱን ከእያንዳንዱ ማብቂያ በኋላ እራስዎ እንደገና ማንሳት አለብዎት።

## ሞዴሎች እና መስመሮች

የቤተኛ ካታሎግ ሁሉንም በሰነድ የተደገፈ ብቻውን IDs እና አራቱን ኦርጅናል ቤተኛ IDs ያካትታል። ካታሎጉ የማይንቀሳቀስ እና በሂሳብ ላይ የተመሰረተ ነው እንጂ የመለያ መብት አይደለም፡ የሚከፈልባቸው መንገዶች እና የተኳኋኝነት ተለዋጭ ስሞች የተገናኘ መለያ ሊጠቀምባቸው በማይችልበት ጊዜም ይቆያሉ። የሞዴል ማሳያ መለያዎች የአቅራቢውን ስም እና በእያንዳንዱ ሞዴል ተገኝነት ቦይለር ሰሌዳን ያስወግዳሉ። አቅራቢው ይቀራል**Microsoft 365 Copilot** . መለያዎች ምልክት ተደርጎባቸዋል** ተለዋጭ ስም** ወይም** ቅርስ** ለታሪካዊ ሞዴል ስሪት ዋስትና ሳይሆን ነባር መለያዎቻቸውን እና የፕሮቶኮል ካርታዎችን ያቆዩ። ራሱን የቻለ ፕሮክሲዎች** ከ/ሞዴሎች አስመጣ** መመሪያዎች ለዚህ ተወላጅ WebSocket አቅራቢ አይተገበሩም።

## ባህሪ እና ገደቦችን ይጠይቁ

- መሳሪያዎች ናቸው።** ፈጣን-ተመስሏል** ቤተኛ Microsoft ተግባር ጥሪዎች አይደሉም። በመሳሪያ የነቃ ጥያቄ አንድ የታሸገ ትውልድ ይጠቀማል። መሳሪያዎችን በመምረጥ ሌላ ትውልድ አያጠፋም. ልክ የሆኑ የሚደገፉ የክርክር ቅርጾች ያላቸው የታወጁ መሳሪያዎች ብቻ እንደ ጥሪ ይመለሳሉ።
- ረጅም የተዋቀረ መልስ ከአንድ ተከታይ ምሳሌ ጋር በስድ ንባብ ተቀምጧል። ይህ ሂውሪስቲክ ነው, የዓላማ ማረጋገጫ አይደለም; አፕሊኬሽኖች አሁንም የራሳቸውን የመሳሪያ ፈቃዶች ማስፈጸም አለባቸው።
- የምስል ግቤት የድር ደንበኛ በሚልክበት መንገድ ይሰራል። እያንዳንዱ የምስል ክፍል (`image_url` እንደ ዳታ URL ወይም የወል HTTPS URL፣ ወይም ምላሾች `input_image`) ወደ `/m365Copilot/UploadFile` ወደ ተራው ውይይት ከቻት ቶከን ጋር ይሰቀላል፣ እና መልእክቱ በ `ImageFile` ማብራሪያ ይጠቁማል። ጽሑፉ በተቀመጠበት (`[image 1]`, ...) ላይ ምልክት ያደርጋል. አዲስ ውይይት በታሪክ ውስጥ ያለ እያንዳንዱን ምስል ይሰቅላል፣ የቀጠለው ደግሞ የአዲሶቹ መልዕክቶች ምስሎች ብቻ ነው። እስከ 10 PNG, JPEG, GIF ወይም WebP እያንዳንዳቸው ቢበዛ 10 MiB ምስሎች (በጥያቄ 40 MiB ); ቅርጸቱ የሚነበበው ከባይት ነው። HTTPS URLs በአደባባይ-ብቻ፣ ዲ ኤን ኤስ በተሰካው የርቀት ምስል ጠባቂ በኩል ይመጣሉ። ያልተሳካ ሰቀላ ጥያቄውን አልተሳካለትም (** 502** `m365_image_upload_failed`፣** 400** `m365_image_rejected` ወይም `m365_image_invalid`); ያለ ምስል ተሰጥቷል መዞር በጭራሽ አይሄድም። ሌሎች የጽሑፍ ያልሆኑ ክፍሎች (ድምጽ፣ ፋይሎች) በግልጽ ውድቅ ይደረጋሉ፣ በጸጥታ አይጣሉም።
- የክትትል ጥያቄ ያው የወዲያኛው ውይይት ይቀጥላል እና መልእክቶቹን ከቀዳሚው ምላሽ በኋላ ይልካል። ያንን ምላሽ በትክክል ማራዘም አለበት: ተመሳሳይ ግንኙነት, የሞዴል መገለጫ እና የመሳሪያ ስብስብ; ያልተለወጠ ታሪክ (በእያንዳንዱ መልእክት ላይ የ sha256 ሰንሰለት); እና የምላሹ የመሳሪያ ጥሪ መታወቂያዎች፣ ወይም እስከ ነጭ ቦታ ድረስ ያለው ጽሑፍ። ሌላ ማንኛውም ነገር (የተስተካከለ ታሪክ፣ ሌላ ክፍለ ጊዜ ተመሳሳይ የመጀመሪያ መልዕክት ያለው፣ የተለየ ምላሽ፣ ውይይት ለ30 ደቂቃ ስራ ፈት ወይም ወደ Copilot's 600-message cap ቅርብ፣ ያለ መታወቂያ ግንኙነት) ከመላው ታሪክ ጋር አዲስ ውይይት ይጀምራል። ያልተሳካ ተራ ከቆመበት አይቀጥልም፣ እና ይዘት የሌለው `InternalError` በአዲስ ውይይት አንድ ጊዜ እንደገና ይላካል (** 502** `m365_internal_error` እንደገና ካልተሳካ). ቀጣይነት በሂደት ማህደረ ትውስታ ውስጥ ይቀመጣሉ፡ ዳግም መጀመር ትኩስ ንግግሮችን ይጀምራል።

- የ Copilot የማመዛዘን ማጠቃለያ (`ChainOfThoughtSummary`)፣ ሞዴሉ አንድ ሲልክ፣ እንደ `reasoning_content` ነው የሚመለሰው፣ በጭራሽ እንደ መልሱ አካል ነው። እራሱን እንደገና የሚጽፈው ማጠቃለያ ተራውን ሳይወድቅ መልቀቅ ያቆማል።
- ከማንኛውም ይዘት በፊት፣ licence/throttle አለመሳካቶች HTTP 403/429 መልቀቅ በተጠየቀ ጊዜም ያቆያል። ይዘቱ ከጀመረ በኋላ፣ ውድቀቶች SSE ስህተት ክስተቶች ናቸው፣ በጭራሽ የተሳካ ውጤት የለም። በአባሪ-ብቻ ዥረት መወከል የማይችል የላይ ዥረት እንደገና መፃፍ ግልጽ የሆነ የዥረት ስህተት ነው። የማይለቀቁ እና የታሸጉ የመሳሪያ ምላሾች የመጨረሻውን ጽሑፍ ይዘው ይቆያሉ።
- Copilot ግንኙነቱን በራሱ እምቢ ሲል መልሱ እንደሚከተለው ነው የሚዘገበው፡-** 401** `m365_unauthorized` ላልተቀበለው ወይም ጊዜው ያለፈበት መግቢያ (እንደገና ይግቡ)፣** 429** በእሱ `Retry-After` ለስሮትል፣ እና የእጅ መጨባበጥ አለመሳካት ካልሆነ፣ በጭራሽ አጠቃላይ የግንኙነት አለመሳካት።

## ምስል ማመንጨት

`POST /v1/images/generations` በ `model: "copilot-m365-web/m365-copilot-image"` (ቅጽል `m365copilot/m365-copilot-image`) የድር ደንበኛ እንደሚያደርገው በ Copilot አብሮ በተሰራው የምስል መሳሪያ ይስላል። እያንዳንዱ ምስል አንድ Copilot መታጠፊያ ነው፡ ከድር ደንበኛ ምስል አማራጭ ጋር መርጦ ገብቶ `GenerateGraphicArt` ያውጃል፣ እና ምስሉ በ Microsoft ዲዛይነር አገልግሎት ላይ ያለ ቅርስ በመጠቆም ግስጋሴ ላይ ይደርሳል። ያ ቅርስ የውይይት ቶከንን አይቀበልም፣ ስለዚህ OmniRoute የዲዛይነር ቶከንን ከግንኙነቱ አድስ ማስመሰያ ፈጠረ እና ባይት ያውርዳል። ምልክቱ ወደ `designerapp.officeapps.live.com` ብቻ ነው የሚላከው።

- ቤተኛ የመግባት ግንኙነት ይፈልጋል (የማደስ ምልክት)። የተለጠፈ ማስመሰያ አልተሳካም።** 400** ማንኛውም ተራ ከማለቁ በፊት.
- `n` 1-4 ነው፣ እያንዳንዱ አንድ ዙር። `size` ብቻ አቅጣጫውን ይመራል (ሰፊ፣ ረጅም ወይም ካሬ)፣ Copilot ከጥያቄው ያነበባል፤ Copilot የማሳያውን መጠን ይመርጣል።
- ምስሎች ወደ መስመር ውስጥ ይመለሳሉ `b64_json` በነባሪ፣ የውሂብ URL ለ `response_format: "url"`።
- የተፈጠሩ ምስሎች በትንሽ ዕለታዊ በጀት ከውይይት የተለዩ ናቸው። ጥቅም ላይ ሲውል ጥያቄው አይሳካም** 429** . ያለ ምስል የሚመልስ መዞር አይሳካም።** 502** (ወይም** 400** /** 503** የ Copilot ጽሑፍ እንደ እምቢታ ወይም የአቅም ችግር ሲነበብ); መልእክቱ የትኛውን ይላል።

## የደህንነት ሞዴል

- **ኦፊሴላዊ ያልሆነ ውህደት.** ይህ አቅራቢ የ BizChat WebSocket ፕሮቶኮሉን ገልብጧል። Microsoft የመጨረሻ ነጥቡን ሲቀይር ያለማሳወቂያ ሊሰበር ይችላል።
- `subscriptionRisk: true` ባንዲራ የሚያንፀባርቀው ውህደቱ ሰነድ በሌለው የመጨረሻ ነጥብ ላይ ነው። የመለያ ገደቦች ሊኖሩ ይችላሉ ግን አልተረጋገጡም።
- የመዳረሻ ማስመሰያው ለአጭር ጊዜ የሚቆይ JWT ነው። እንደ የይለፍ ቃል ያዙት፡ አታስገቡት፣ አትግቡ ወይም አያጋሩት።
- የማደስ ማስመሰያው Microsoft 365 ወለል ቀጣይነት ያለው መዳረሻ ይሰጣል። ልክ እንደ API ቁልፍ በተመሳሳይ ጥንቃቄ ያከማቹ።

## መላ መፈለግ

### ማረጋገጥ ወዲያውኑ አይሳካም።

- ከ መገልበጥዎን ያረጋግጡ**WebSocket URL** , ከ XHR/Fetch ጥያቄ አይደለም. ምስክርነቱ በ `access_token` መጠይቅ ግቤት ውስጥ ያለው የ Chathub WebSocket ግንኙነት — በ `Authorization: Bearer` ራስጌ ውስጥ አይደለም።
- `chathubPath` ሙሉውን `<oid>@<tenant>` ክፍል ከ URL መንገድ ማካተቱን ያረጋግጡ።

### ማስመሰያ ከ ~ 75 ደቂቃዎች በኋላ ጊዜው ያልፍበታል።

ይህ ይጠበቃል። `refreshToken` ከሌለ የመዳረሻ ማስመሰያው ለአጭር ጊዜ የሚቆይ ነው። ወይ፡-

- ምስክርነቱን ከ DevTools, ወይም እንደገና ይያዙ
- አዋቅር** የላቁ ቅንብሮች → አድስ ማስመሰያ (አማራጭ)** በራስሰር ለማደስ የግንኙነት አክል ወይም አርትዕ ውስጥ።

### ግንኙነትን ይሞክሩ ግን ቻት 401 ይመለሳል

ጋር ለተፈጠረ ግንኙነት** በ Microsoft ይግቡ** , Test Connection የመዳረሻ ቶከን ማብቂያ ጊዜን ይፈትሻል እና ጊዜው ያለፈበትን ማስመሰያ በተከማቸ የማደስ ቶከን ያድሳል፣ ስለዚህ የማለፊያ ሙከራ የማደስ ቶከን አሁንም እንደሚሰራ ያረጋግጣል።

ለተለጠፈ ምስክርነት፣ Test Connection የማረጋገጫውን ቅርፅ ይፈትሻል እና ማስመሰያው የአገልግሎት ጊዜው ሲያበቃ አቅራቢው የሚጠቀመው ማስመሰያ ጊዜው አላለፈም (የግንኙነቱ የተከማቸ ማስመሰያ የቆየ ለጥፍ አሸንፏል፤ የማደስ ማስመሰያ እንደ ታዳሽ ይቆጠራል)። ጊዜው ከማለፉ በፊት የተሻረ ምልክት አሁንም ፈተናውን ያልፋል; ውይይት ከዚያም ይመለሳል** 401** `m365_unauthorized`. ተጠቀም** በ Microsoft ይግቡ** እንደገና፣ ወይም አዲስ ምስክርነት እንደገና ይያዙ።

### Copilot በአቅራቢው ዝርዝር ውስጥ አይታይም።

`copilot-m365-web` መንቃቱን ያረጋግጡ** ዳሽቦርድ → አቅራቢዎች** . አቅራቢው በነባሪነት በአንዳንድ ደረጃዎች ሊደበቅ ይችላል።
