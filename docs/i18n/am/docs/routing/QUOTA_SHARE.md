## አጠቃላይ እይታ

የኮታ ማጋሪያ ሞተሩ ተመሳሳይ ግንኙነትን በሚጋሩ በርካታ API ቁልፎች መካከል የአቅራቢውን ጊዜ-ተኮር ኮታ (ለምሳሌ፣ የCodex የ5-ሰዓት መስኮት፣ የKimi 1500 ጥያቄዎች/ሰዓት) በፍትሐዊነት ያሰራጫል።

**የሚፈታው ችግር:** OmniRoute ብዙ API ቁልፎችን በተመሳሳይ የላይኛው ደረጃ አቅራቢ መለያ በኩል ያስተላልፋል። የማጋሪያ አመክንዮ ከሌለ፣ ከቁልፍ A የሚመጣ ድንገተኛ የጥያቄ ጭማሪ የአቅራቢውን የሰዓቱን ኮታ ሊያሟጥጥ ይችላል፤ ይህም ቁልፎች B እና C መስኮቱ ዳግም እስኪጀመር ድረስ እንዲታገዱ ያደርጋል። ሞተሩ ይህን የሚከላከለው፦

1. የእያንዳንዱን ቁልፍ ተንከባላይ ፍጆታ በየልኬቱ (%, ጥያቄዎች፣ ቶከኖች፣ $) በመከታተል።
2. ሥራን የማያባክን ፍትሐዊ-ድርሻ ስልተ ቀመር በመተግበር፦ ዓለም አቀፉ ክምችት እስካልሞላ ድረስ አንድ ቁልፍ ከስራ ፈት ድርሻዎች መዋስ ይችላል።
3. ጥያቄው የላይኛው ደረጃ አስፈጻሚ ጋር ከመድረሱ በፊት ውጤቱን በዋናው የማስፈጸሚያ መንገድ (`chatCore.ts`) ላይ ተፈጻሚ በማድረግ።

## አልጎሪዝም፡ ፍትሃዊ-ተጋራ ስራ-መቆጠብ

በ `src/lib/quota/fairShare.ts` ውስጥ ተተግብሯል.

### ሁነታዎች

| ሁኔታ                                        | ሁነታ     | ባህሪ                                         |
| ------------------------------------------ | ------- | ------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **ለጋስ** | ቁልፉ ፍጆታ-ጠቅላላ ሲቀነስ እስከ አለምአቀፍ ገደብ ሊበደር ይችላል። |
| `globalUsedPercent >= saturationThreshold` | **ጥብቅ** | የግለሰብ ፍትሃዊ ድርሻን በጥብቅ ያስፈጽሙ                  |

ነባሪ `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`)።

እነዚህ ሁለት ሁነታዎች ገንዳውን በነባሪ የብድር ሁነታ ይገልፃሉ `saturation`. በ `consent` ሁነታ ውስጥ ያለ ገንዳ ሁል ጊዜ ጥብቅ ህጎችን ይተገበራል ፣ ምንም ይሁን ምን ሙሌት። [ፈቃድ ያለው ብድር (በአንድ ገንዳ መርጦ መግባት)](#consented-lending-per-pool-opt-in) ይመልከቱ።

### የአንድ-ልኬት ውሳኔ

በገንዳው ውስጥ ላለው እያንዳንዱ ንቁ ልኬት ሞተሩ ያሰላል፡-

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = current rolling value for this key (from QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

ለ `percent` ልኬቶች፣ `consumed` በምትኩ ከመያዣው መጽሃፍ ይመጣል ( [የመቶኛ ልኬቶች፡ በአንድ-ቁልፍ ባህሪ](#percent-dimensions-per-key-attribution) ይመልከቱ)።

ከዚያም፡-

- **`policy = hard`** : `consumed > fairShareAllowed` እና ሁነታ ጥብቅ ከሆነ →** አግድ** .
- **`policy = soft`** : `consumed > fairShareAllowed` እና ሁነታ ጥብቅ ከሆነ →** መቅጣት** (በኮምቦ ውስጥ ቅድሚያ መስጠት; በጭራሽ ጠንካራ-ማገድ).
- **`policy = burst`** ፍትሃዊ ድርሻ ምንም ይሁን ምን ግሎባል ዋና ክፍል ሲኖር ፍቀድ።

### ካፕ በፍጹም

`capValue` + `capUnit` በአድልዎ ላይ ከሞድ ወይም ፖሊሲ ነፃ የሆነ ጠንካራ ጣሪያ ነው። `consumed >= capValue` ሁልጊዜ የት ማንኛውም ልኬት** ብሎኮች** ጥያቄው ። ለ `percent` cap፣ `consumed` ለቁልፍ የተሰጠው ክፍል ብቻ ነው።

### ባለብዙ-ልኬት ቼክ

ከሆነ ጥያቄ ታግዷል** ማንኛውም** በገንዳው ውስጥ ያለው ልኬት ያግደዋል. ልኬቶች ነፃ ናቸው — የ 5h% ድካም የሳምንት% ልኬት ላይ ተጽዕኖ አያሳድርም።

### መበደር

ለጋስ ሁነታ፣ ምደባው ብዙም ጥቅም ላይ ያልዋለበት ቁልፍ ከሌሎች ቁልፎች ያልተመደቡ አክሲዮኖች ትርፍ ሊጠቀም ይችላል። ቀመሩ፡-

```
maxAllowed = globalLimit - consumedByOtherKeys
```

`consumedByOtherKeys = consumedTotal - consumedByThisKey` የት . ቴቶ ግሎባል (ፑል `limit` ለዛ ልኬት) ምንጊዜም ጠንካራ ጣሪያ ነው።

### የተፈቀደ ብድር (በአንድ ገንዳ መርጦ መግባት)

እያንዳንዱ ገንዳ የብድር ሁነታ አለው. `saturation` ነባሪው ነው እና ህጎቹን ከላይ ያስቀምጣል። በ `consent` ሁነታ የ `hard` ቁልፍ ድርሻውን የሚያልፈው ሌሎች ቁልፎች ለመበደር በተስማሙበት አቅም ብቻ ነው። አስተዳዳሪው የእያንዳንዱን ገንዳ ሁኔታ ያዘጋጃል። እያንዳንዱ ቁልፍ ያዥ [በብድር ፈቃድ](#lending-consent) በኩል የራሱን ፈቃድ ያዘጋጃል።

ስምምነት ከ0 ወደ 100 መቶኛ እና የአማራጭ የመጨረሻ ቀን በኤክስ ሚሊሰከንዶች ውስጥ ነው። ቁልፉ ያንን የስራ ፈት ድርሻ መቶኛ ያበድራል የጊዜ ገደቡ ወደፊት ነው።

ለአንድ ልኬት፣ `L` ውጤታማው ገደብ ነው፡ እቅዱ በገንዳው ውስጥ ያሉትን ሂሳቦች ይገድባል። በሩ ያሰላል፣ ለሚጠየቀው ቁልፍ፡-

```
share_k         = w_k / 100 × L
idle_k          = max(0, share_k − consumed_k)
lent            = Σ over the other keys of lend_k / 100 × idle_k
taken           = Σ over the other keys of max(0, consumed_k − share_k)
borrowAvailable = max(0, lent − taken)
```

`w_k` የቁልፉ ክብደት ነው፣ ወይም ማንኛውም ክብደት ከ0 በላይ ካልሆነ `100 / n` ለእያንዳንዱ ቁልፍ ነው `lend_k` የጠያቂው ቁልፍ የራሱ ፍቃድ በጭራሽ አይቆጠርም። የ `hard` ቁልፍ ፍጆታው የአክሲዮን ድርሻውን ከጨመረ በኋላ `borrowAvailable` ውድቅ ይሆናል።

ምንም የምደባ ይገባኛል ጥያቄ (ከክብደቱ ድምር 100 ሲቀነስ) አቅም ማበደር አይቻልም። ምንም ቁልፍ ለማበደር አልተስማማም።

**ለምሳሌ።** `L` 1000 ነው።

| ቁልፍ | ክብደት | አጋራ | ተበላ | ያበድራል። |
| --- | ---- | --- | --- | ------ |
| ሀ   | 50   | 500 | 530 | 0%     |
| ለ   | 30   | 300 | 100 | 50%    |
| ሲ   | 0    | 0   | 60  | 0%     |

- B 50% ስራ ፈት 200 ያበድራል ይህም 100 ነው. ሲ ቀድሞውንም 60 ከድርሻው በላይ ወስዷል። 40 ሊበደር ይችላል።
- A በ 530 ይቀርባል እና ፍጆታው 540 ሲደርስ ውድቅ ይደረጋል.
- C ማንኛውንም ነገር ከመጠቀሙ በፊት፣ ከ A ጋር ወይም ከድርሻው በታች፣ C 100 መበደር ይችላል።
- C ማንኛውንም ነገር ከመጠቀሙ በፊት፣ A በ 530፣ C 70 መበደር ይችላል።

**ዜሮ ክብደት።** ክብደት 0 ያለው ቁልፍ የ0 ድርሻ አለው። የሚቀርበው ፍጆታው ሌሎች ከሚያበድሩት በታች ሲሆን ብቻ ነው። ማንም አበዳሪ ሲያገኝ ከመጀመሪያው ጥያቄ ውድቅ ይደረጋል።

**የጊዜ ገደብ** ምንም የበስተጀርባ ተግባር ፈቃዱን አያልቅም። እያንዳንዱ ጥያቄ ቀነ-ገደቡን ከራሱ ጊዜ ጋር ያወዳድራል, እና ከዚያ ጊዜ ጋር እኩል የሆነ ቀነ-ገደብ አልፏል. የተከማቸ ቀነ ገደብ ያልተገደበ ቁጥር ወይም `Date` ሊይዘው ከሚችለው ትልቁ ቀን ያለፈ፣ ያለፈ ሆኖ ይቆጠራል።

**`soft` እና `burst`.** ብድር መስጠት አይገድባቸውም። የ `soft` ቁልፍ ድርሻውን ካለፈ በኋላ ከቀዳሚነት ተሰርዟል። ገንዳው ክፍል ሲኖረው `burst` ቁልፍ ያልፋል። የመዋኛ ገንዳው አጠቃላይ ገደብ ገደቡን ላይ ከደረሰ በኋላ የገንዳው ጣሪያ አሁንም እያንዳንዱን ቁልፍ ውድቅ ያደርጋል።

**በጥያቄው መንገድ ላይ ወጪ.** `saturation` ገንዳ ከበፊቱ የበለጠ ምንም አያነብም። በ `consent` ገንዳ ውስጥ፣ ሊቆጠር የሚችል ልኬት ለ `hard` ቁልፍ ከአክሲዮኑ ላይ ወይም ከዚያ በላይ ሲያነብ ሌላ ቁልፍ ያበድራል። ከዚያም በትይዩ አንድ በአንድ በሌላ ቁልፍ እንዲነበብ ያደርጋል። ያልተሳካ ንባብ ለዚያ ቁልፍ እንደ 0 ፍጆታ ይቆጠራል። የ `percent` ልኬት ምንም ማንበብ አይጨምርም፣ ምክንያቱም የባለቤትነት መጽሐፉ እያንዳንዱን ቁልፍ ይይዛል።

**ገንዳ ማረም.** አርትዖት የሚቆዩትን ቁልፎች ፈቃድ ይጠብቃል። ይህ ለምደባ አርትዖቶች፣ የቡድን-አቀፍ መተኪያዎች እና `ensure` ጥሪዎችን ይይዛል። የተወገደ ቁልፍ ፈቃዱን ያጣል፣ እና የተጨመረው ቁልፍ በ0 ይጀምራል። የአስተዳዳሪ መንገዶች የእያንዳንዱን ቁልፍ ፈቃድ ይመልሱ እንጂ በጭራሽ አይፃፉም። ገንዳውን ወደ `saturation` መመለስ እያንዳንዱን የተከማቸ ፍቃድ ይጠብቃል፣ ይህም በዚያ ሁነታ ምንም ተጽእኖ የለውም። ገንዳውን ወደ `consent` መቀየር ቀነ ገደብ ያላለፈውን የተከማቹ ፍቃዶችን እንደገና ያንቀሳቅሰዋል። ቁልፍ ያዥ በሁለቱም ሁነታ የተከማቸ ፍቃድን ማጽዳት ይችላል።

**በማሻሻል ላይ።** አምዶች `lending_percent` እና `lending_until` ካሉ፣ ፍልሰቱ `borrow_mode` ብቻ ይጨምራል፣ እና የተከማቹ መቶኛዎች እንደነበሩ ይቆያሉ። እያንዳንዱ ገንዳ በ `saturation` ሁነታ ይጀምራል። በመዋኛ ገንዳ አዋቂ ውስጥ `consent` ን ያብሩ። ከተቀመጡት ዋጋዎች ምንም ነገር አልተገመተም.

**ገደቦች.**

- አበዳሪው የራሱን ድርሻ ከመጠቀሙ በፊት ገንዳውን በጣሪያው ላይ ማግኘት ይችላል. ሌሎች የተበደሩት አቅም ወደ ገንዳው ጠቅላላ መጠን ይቆጠራል።
- ቼኩ ከጥያቄው በፊት ይሰራል እና ምንም ነገር አይይዝም። በተመሳሳይ ጊዜ የሚቀርቡ ጥያቄዎች ፍጆታ ከመመዝገቡ በፊት ይነበባል፣ ስለዚህ የብድር አቅም በበረራ ላይ ባሉ ጥያቄዎች የተገደበ ከአንድ ጊዜ በላይ ሊውል ይችላል። የ `saturation` ሁነታ ድርሻ ቼክ ተመሳሳይ ንብረት አለው።

## ተንከባላይ መስኮት ቆጣሪ

በ`src/lib/quota/sqliteQuotaStore.ts` እና `redisQuotaStore.ts` ውስጥ ተተግብሯል።

ለእያንዳንዱ `(apiKeyId, dimensionKey)` ሁለት ባልዲዎች፦

- `curr`፦ የአሁኑ ባልዲ (`floor(nowMs / windowMs)`)
- `prev`፦ የቀድሞው ባልዲ (`curr - 1`)

ውጤታማው ተንከባላይ እሴት፦

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**ትክክለኛነት**፦ ~99% ትክክለኛ። ስህተቱ በባልዲዎቹ መካከል ባለው ወሰን ላይ ቢበዛ ከመስኮቱ መጠን 1% ነው (ይህም በ2-ባልዲ ግምቱ ውስጣዊ ባህሪ ነው)።

### ተመሳሳይ ጊዜ አፈጻጸም

የSQLite ነጂ፦ ለእያንዳንዱ `(apiKeyId | dimensionKey)` ቁልፍ ያለው የውስጠ-ማህደረ ትውስታ mutex የማንበብ-ማሻሻል-መጻፍ ውድድርን ይከላከላል። ንድፉ የ`src/sse/services/auth.ts` anti-thundering-herd አቀራረብን ይከተላል።

የRedis ነጂ፦ ለአቶሚክ ጭማሪ Lua EVAL ስክሪፕት — እንደ አንድ የRedis ትዕዛዝ ይሰራል።

### Redis (አማራጭ፣ ባለብዙ-ኢንስታንስ)

- ቆጣሪዎች በRedis ውስጥ ይከማቻሉ፤ ሜታዳታ (ፑሎች/ድልድሎች) ግን በSQLite ውስጥ ይቀጥላል።
- ቆጣሪዎች መጋራት ለሚኖርባቸው ባለብዙ-ረፕሊካ ማሰማራቶች በጣም ተስማሚ ነው።

### ማንቀሳቀሻዎችን መቀየር

በቅንብሮች UI (`/dashboard/settings` → የኮታ ማከማቻ)፣ ወይም በenv vars፦

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

የDB ቅንብር ከenv ቅድሚያ አለው። `driver=redis` ከሆነ ነገር ግን URL ከሌለ ወይም
`ioredis` ካልተጫነ፣ ፋብሪካው ወደ SQLite ተመልሶ ማስጠንቀቂያ ይመዘግባል።

የማንቀሳቀሻ ምርጫ ቅደም ተከተል፦

1. የDB ቅንብር `quotaStore.driver`
2. Env `QUOTA_STORE_DRIVER`
3. ነባሪ፦ `sqlite`

መጽሐፉ የሚዘመነው የማስፈጸሚያ ወይም የአጠቃቀም መንገድ መለያውን ሲያሰላ ነው። ጽሁፎች በክለሳ ቁጥር ላይ ተነጻጽረው ተቀምጠዋል። የተሸነፈ ፀሃፊ በአዲስ ንባብ አንዴ ይሞክራል።

#### የአንድ ቁልፍ ክፍል እንዴት እንደሚሰላ

Together፣ እነዚያ ቶከኖች ከሥዕሉ አንድ ነጥብ ቢበዛ በአንድ `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` ቶከኖች (ነባሪ 1,000) ያብራራሉ። ያላስረዱት እድገት ውጫዊ ነው። መሰረቱም ውጫዊ ነው።

ለምሳሌ መፅሃፍ በ 0 ይከፈታል። ከዛም 900,000 ቶከኖች እና ቁልፍ ቢ መንገዶች 100,000 ይከፈታል። በ60 አኃዝ የA ክፍል 54 ነጥብ እና ለ ክፍል 6 ነው።

ከቁልፍ ምልክት በታች ያለው ቆጣሪ እንደገና ተጀምሮ ሙሉ በሙሉ ይቆጠራል። ምልክት የሌለበት ቁልፍ፣ ለምሳሌ በመስኮቱ መሃል ላይ ገንዳውን የሚቀላቀል ቁልፍ፣ ሁሉንም ምልክቶች ይቆጥራል። ቶከኖቹን የሚዘገይ አሃዝ በሚቀጥለው ንባብ ላይ የሚጠፋ ስህተት ያስከትላል። አይከማችም።

`QUOTA_PERCENT_MIN_TOKENS_PER_POINT` በእያንዳንዱ ባህሪ ላይ ይነበባል. ቢያንስ 1 የመጨረሻ ቁጥር ያልሆነ እሴት ወደ 1,000 ይመለሳል።

#### ንባብ መጽሐፉን እንዴት እንደሚለውጥ

የመጀመሪያው ተዛማጅ ህግ ተግባራዊ ይሆናል፡-

1. **እስካሁን ምንም መጽሐፍ የለም፡** ንባቡ መጽሐፉን ይከፍታል። የእሱ አሃዝ የመነሻ መስመር ነው እና እያንዳንዱ ቆጣሪ ምልክት ተደርጎበታል.
2. **የቆየ ንባብ፡-** ከመጨረሻው የተተገበረው በፊት የተጻፈ ንባብ ችላ ይባላል። ዳግም የማስጀመሪያ ጊዜው ከተከማቸ ከ30 ደቂቃ በላይ የቀደመ ንባብም እንዲሁ።
3. **አዲስ የአቅራቢ መስኮት፡-** ዳግም ማስጀመሪያ ጊዜ ከተከማቸ 30 ደቂቃ በላይ ዘግይቶ መጽሐፉን ይለውጣል። ምስሉ መነሻ ይሆናል እና እያንዳንዱ ቆጣሪ እንደገና ምልክት ይደረግበታል። ቆጣሪ የሌላቸው ቁልፎች መጽሐፉን ለቀው ይወጣሉ።
4. **የተጠናቀቀ መስኮት;** ከንባብ ጊዜ በኋላ ያልሆነ የተከማቸ ዳግም ማስጀመሪያ ጊዜ መስኮቱ አልቋል ማለት ነው። ንባቡ ምንም ይሁን ምን መጽሐፉን ይለውጠዋል።
5. **ከፍተኛ ቁጥር፡** የመጨረሻው ምስል ብቻ ይንቀሳቀሳል. መነሻው እና ምልክቶቹ ይቆያሉ.
6. **ተመሳሳይ ምስል:** ስዕሉ, የመነሻ መስመር እና ምልክቶች ይቆያሉ. መጽሐፉ የጎደለው ዳግም ማስጀመሪያ ጊዜ ብቻ ነው የተጻፈው።
7. **የታችኛው ምስል:** ዝቅተኛ አሃዝ በጭራሽ እንደዚህ አይተገበርም። መጽሐፉን የሚያዞረው ሦስት ነገሮች ሲያዙ ብቻ ነው። ከመጨረሻው የተተገበረው ንባብ ቢያንስ ሁለት ደቂቃ አዲስ ነው። መስኮቱ አንድ አይነት ክፍት ነው የሚል ምንም ነገር የለም። ከአንድ ነጥብ በላይ ዝቅ ያለ ነው።

መስኮቱ ሶስት ነገሮች ሲይዙ እንደ አንድ አይነት ክፍት ይቆጠራል. ሁለቱም ዳግም ማስጀመር ጊዜዎች ይታወቃሉ። እርስ በእርሳቸው በ 30 ደቂቃዎች ውስጥ ናቸው. የተቀመጠው አሁንም ከማንበብ በፊት ነው። በመስኮቱ ውስጥ ያለው የታችኛው ምስል ምንም አይለውጥም.

የዳግም ማስጀመሪያ ጊዜ የሚቀመጠው ከተሸከመው የንባብ የውሂብ ጊዜ ቀደም ብሎ ሲሆን ብቻ ነው። ከፍ ያለ አሃዝ የንባብ ዳግም ማስጀመሪያ ሰዓቱን ያከማቻል ያ ጥቅም ላይ ሲውል እና የተከማቸውን በሌላ መንገድ ያስቀምጣል። አንድ እኩል አሃዝ የንባብ ጊዜውን የሚመዘግብው መጽሐፉ ምንም ሳይኖረው ሲቀር ብቻ ነው። ሌላ ምንም አይቀይረውም። መጽሐፉን የማያዞር ዝቅተኛ አኃዝ ምንም ዳግም የማስጀመር ጊዜ አይመዘግብም።

ሊጠቅም የሚችል ንባብ ከሌለ፣ የተከማቸ መፅሐፍ ጥቅም ላይ የሚውለው የአሁኑ የመስኮት ደብተር መሆን ሲችል ብቻ ነው። ይህም በሁለት ሁኔታዎች ውስጥ ነው.

- የዳግም ማስጀመሪያው ጊዜ ይታወቃል እና አሁንም ወደፊት ነው።
- ዳግም የማስጀመሪያ ጊዜ የለውም፣ እና የተለወጠው የመጨረሻው ንባብ ቢበዛ 15 ደቂቃ ነው።

ያለበለዚያ ምንም ነገር አይገለጽም ፣ መጽሐፍ በማይኖርበት ጊዜ። የተከማቸ ዳግም ማስጀመሪያ ጊዜ ያለፈበት መጽሐፍ በጭራሽ አይከፈልም።

ፍጹም የሆነ ኮፍያ ከ `capUnit: "percent"` ጋር ለቁልፍ የተሰጠውን ክፍል ብቻ ይቆጥራል፣ በተመሳሳይ መንገድ ይመዘናል። የ 100 እና k መለያዎች በአንድ መለያ ገደብ ይውሰዱ። የ N ቆብ የሚደርሰው በአገልግሎት ሰጪው መለያ ቁጥር ቁልፉ ክፍል N/k ነጥቦች ላይ ሲደርስ ነው። እያንዳንዱ መለያ በራሱ መጽሐፍ ላይ ምልክት ይደረግበታል። ለምሳሌ፣ በሁለት መለያዎች፣ የ10 ካፕ በአንድ መለያ ቁጥር 5 ነጥብ ላይ ይደርሳል።

መደብሩ ሊነበብ በማይችልበት ጊዜ ምንም ነገር አይገለጽም እና እያንዳንዱ ቁልፍ በዚያ ልኬት ላይ 0 እንዲከፍል ይደረጋል። የመፅሃፍ መፃፍ ሳይሳካ ሲቀር ያ ባህሪው መፅሃፉን እንደተነበበ ይጠቀማል። ያልተሳካ ማስመሰያ መጻፍ የጥያቄውን ምልክቶች ከመጽሐፉ ወጥቷል። ከእነዚህ ውድቀቶች መካከል አንዳቸውም ጥያቄን አያግደውም።

በ `consent` ገንዳ ውስጥ፣ የአበዳሪ ቀመሩ የእያንዳንዱን ቁልፍ ፍጆታ ከላይ በተገለፀው የመቶኛ መጠን ይጠቀማል። ሌላ ቁልፍ ሲያበድር መጽሐፉ አንድ ጊዜ ይነበባል እና ለእያንዳንዱ ቁልፍ ይገለጻል። ሊጠቅም የሚችል መፅሃፍ ከሌለ እያንዳንዱ ቁልፍ እንዲከፍል ይደረጋል 0. ክብደት ያለው ቁልፍ ከዚያም ያልፋል እና 0 ክብደት ያለው ቁልፍ ሌላ ቁልፍ ሲያበድር ብቻ ያልፋል።

#### የአጠቃቀም መንገድ

`GET /api/quota/pools/{id}/usage` በተመሳሳዩ ተግባር ተመሳሳይ ቁጥሮችን ሪፖርት ያደርጋል። የመቶኛ ልኬት በአንድ ገንዳ ግንኙነት በ `accounts` ውስጥ አንድ ግቤት አለው። የእሱ ከፍተኛ ደረጃ `consumedTotal` እና `perKey` የመጀመሪያውን ግቤት ያንፀባርቃሉ።

መንገዱ የአሁኑን ንባብም ተግባራዊ ያደርጋል፣ ስለዚህ መጽሐፉን በጥያቄ መልክ ማራመድ ይችላል። ጥቅም ላይ የሚውል ንባብ በማይኖርበት ጊዜ ወይም ዝቅተኛ አሃዝ በማይተገበርበት ጊዜ `internal + external` ከ `consumedTotal` ሊለያይ ይችላል።

#### ማከማቻ እና ማቆየት።

ሁለቱም የኮታ መደብሮች መጽሐፉን ያስቀምጣሉ. በ SQLite ላይ፣ አውቶማቲክ የውሂብ ጎታ ማጽዳት ሲነቃ ለ60 ቀናት ያልተዘመኑ ረድፎችን ያስወግዳል። በ Redis ላይ፣ የመዋኛ ግንኙነት መጽሐፍት እና ቆጣሪዎች አንድ ቁልፍ ይጋራሉ። የመጨረሻው ማስመሰያ መፃፍ ወይም መጽሐፍ ከተለወጠ ከ60 ቀናት በኋላ ጊዜው ያልፍበታል። የማይለወጥ መጽሐፍ እንደገና አልተፃፈም, ስለዚህ መቆራረጡ ከረዥም የእቅድ መስኮቱ በላይ ተዘጋጅቷል. በእጅ የአጠቃቀም ታሪክ ዳግም ማስጀመር በ SQLite ላይ ያሉትን መጽሃፍቶች ያጸዳል (ገደቦችን ይመልከቱ)።

## የቧንቧ መስመር ውህደት

### PRE መንጠቆ (`open-sse/handlers/chatCore.ts`)

ወደ ላይ ካለው ፈጻሚው በፊት፣ ከተረጋገጠ እና የፖሊሲ ማረጋገጫ በኋላ ይሰራል፡-

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → getQuotaStore().peek() per dimension
      → fairShare.decideFairShare()
      → if block → return 429 (buildErrorBody, Hard Rule #12)
      → if allow + deprioritize → set quotaSoftPenalty=true on candidate
  → executor.execute()
```

**አልተሳካም-ክፍት** ፦ `enforceQuotaShare` ከወረወረ፣ ጥያቄው በ `pino.warn` ሎግ ይፈቀዳል። ይህ የኮታ-ሞተር ሳንካ ሁሉንም ትራፊክ እንዳይዘጋ ይከላከላል።

**አቅም ሲመለስ።** በቁልፍ ድርሻ ወይም በገንዳ ጣሪያ ላይ እምቢ ማለት ከሁለት ዓረፍተ ነገሮች በአንዱ ያበቃል ፣ በሁለቱም የመበደር ዘዴዎች

- `percent` መስኮት `. The <window> window resets at <time>.` ሰዓቱ ዳግም ማስጀመር አቅራቢው ሪፖርት ያደርጋል።
- ሊቆጠር የሚችል አሃድ `. Enough <window> usage is expected to clear by <time>.` ጊዜው ከተንሸራታች መስኮቱ በላይኛው ገደብ ነው፣ ቁልፉ ሌላ ምንም የሚልክ ከሆነ።

`<time>` በ UTC ውስጥ ISO 8601 ቅጽበታዊ ነው። እምቢታው `Retry-After`: ሙሉ ሴኮንዶች እስከዚያ ቅጽበት ድረስ፣ አንድ ሲደመር። ይህን ያህል ጊዜ የሚጠብቅ ደንበኛ ከቅጽበት በኋላ ቢበዛ አንድ ሰከንድ ይሞክራል። ቅጽበታዊው በማይታወቅበት ጊዜ እምቢታው ዓረፍተ ነገሩን ወይም ራስጌውን አይወስድም. ፍጹም ኮፍያ አለመቀበል ሁለቱንም አይሸከምም። የህዝብ ኮድ `quota_share_blocked` ይቆያል.

የአክሲዮን እምቢታ የተጋራውን ግንኙነት አይነካም። ምንም ማቀዝቀዣ አያዘጋጅም ፣ ምንም የሞዴል መቆለፊያ እና የአቅራቢዎች ብልሽት የለም ፣ እና ሌሎች የመዋኛ ቁልፎች መሰጠታቸውን ቀጥለዋል። እያንዳንዱ የኮምቦ ኢላማ ለድርሻ የሚሆን ቁልፍ እምቢ ሲል፣ ኮምቦው 429 ሳይጠብቅ ይመልሳል። መልሱ `Retry-After` የሚል ፍንጭ ይይዛል። የመክተት መንገድ እምቢታውን በተመሳሳይ ዓረፍተ ነገር ያበቃል እና ምንም `Retry-After` አይልክም.

## የራስ አገልግሎት ኮታ API (መርጦ መግባት)

### ማንቃት እና ማረጋገጥ

- የባህሪ ባንዲራ `QUOTA_SELF_PANEL`፣ ነባሪ `false`። ጠፍቶ እያለ፣ መንገዱ ላይ የደረሰው ጥያቄ 404. በ `REQUIRE_API_KEY=true`፣ የደንበኛ API ፖሊሲ መንገዱ ከመሄዱ በፊት 401 የጠፋ ወይም ትክክል ያልሆነ ቁልፍ እምቢ ይላል። ምንም ቁልፍ የሌለው ጥያቄ ግን በመለያ የገባ ዳሽቦርድ ክፍለ ጊዜ ያንን መመሪያ አልፏል እና የመንገዱን የራሱ መልስ ያገኛል። ባንዲራ እንደሌሎች ባንዲራዎች ይፈታል (ዳሽቦርድ ወይም REST መሻር፣ ከዚያ ተመሳሳይ ስም ያለው የአካባቢ ተለዋዋጭ)። [`FEATURE_FLAGS.md`](../reference/FEATURE_FLAGS.md) ተመልከት.
- የእያንዳንዱ ገንዳ ማሳያ ስም እና የእያንዳንዱ የጊዜ ሰሌዳ መለያ አስተዳዳሪው እንደጻፋቸው ወደ ገንዳው ቁልፍ መያዣዎች ይመለሳሉ። ባንዲራውን ከማብራትዎ በፊት በእነዚያ ቁልፍ ያዢዎች ለማንበብ ብቁ መሆናቸውን ያረጋግጡ።
- ቁልፉ የሚነበበው ከራስጌዎች ብቻ ነው `Authorization: Bearer <key>` ወይም `x-api-key: <key>`. ሁለቱም ሲላኩ, የመጀመሪያው የሚያረጋግጥ ጥቅም ላይ ይውላል. በመጠይቁ ሕብረቁምፊ ወይም ኩኪ ውስጥ ያለው ቁልፍ ችላ ተብሏል። የአገልጋዩ አካባቢ ቁልፍ ውድቅ ተደርጓል (401)።
- ቁልፉ `self:usage` ወሰን (403 ያለሱ) ያስፈልገዋል.
- የአቅራቢው ክፍል ተቆርጧል፣ ካዝና ዝቅ ተደርጎ በ `^[a-z0-9][a-z0-9._-]{0,63}$` (400 ካልሆነ) ተረጋግጧል፣ ከዚያም በአገልግሎት ሰጪው መዝገብ ቤት ተፈትቷል፣ ስለዚህ እንደ `cc` ያለ ተለዋጭ ስም `claude` ገንዳዎችን ያነባል። `claude` እና `anthropic` ተመሳሳይ ገንዳዎችን አንብበዋል.

- የመለያ አሞሌዎች እና የሞዴል መስኮቶች የሚታዩት ግንኙነታቸው ቁልፍ ሊጠቀምባቸው ለሚችሉ መለያዎች ብቻ ነው። ቁልፉ የተፈቀዱ ግንኙነቶች ዝርዝር ሲኖረው፣ ከሱ ውጭ ያለ መለያ `account` ወይም `modelWindows` ሳይኖር `Account N` መግባቱን ያቆያል። ባዶ ዝርዝር ማለት ምንም ገደብ የለም, እንደ `/v1/me/status`. የገንዳው ጠቅላላ (`dimensions[].total`) በዚያ ዝርዝር ላይ የተመካ አይደለም።
- በ `self:usage` ብቻ የሚታዩ ሁለት አሃዞች ከሌሎች ቁልፎች አጠቃቀም የመጡ ናቸው። የመርሃግብር በጀት `exhausted` በዚያ መርሐግብር ስር ያሉትን የእያንዳንዱን ቁልፍ ፍጆታ ያንፀባርቃል። ክብደቱ ሁሉም ዜሮ በሆነ ገንዳ ውስጥ የቁልፉ `weight` `100 / number of members` ነው። ሁለቱም ማስፈጸሚያ በቁልፍ ላይ የሚተገበሩ ናቸው.
- ገንዳ የሚለየው በ `ref` ብቻ ነው፣ ከጥሪ ቁልፉ ጋር የተያያዘ ግልጽ ያልሆነ እሴት። የማሳያ ስሙ (`name`) አስተዳዳሪው እንደጻፈው ተካቷል። አንድ `ref` ከቁልፍ እና ገንዳው ከአገልጋዩ ኤፒአይ-ቁልፍ ሚስጥር (`API_KEY_SECRET`) የተገኘ ነው። ደንበኞች በሱ ላይ መቆየት የለባቸውም፡ ምስጢሩ ከተቀየረ ይቀየራል።
- መለያዎች እንደ `Account 1`፣ `Account 2`፣ … በመዋኛ ቅደም ተከተል ተዘርዝረዋል። ምንም የመዋኛ መታወቂያ ፣ የግንኙነት መታወቂያ ፣ የመለያ ኢ-ሜል ወይም የመለያ ስም አልተመለሰም ፣ እና ምላሹ በውሉ እቅድ ውስጥ ያልፋል ፣ ይህም ማንኛውንም መስክ ከእሱ ውጭ ይጥላል።
- ሊቆጠሩ የሚችሉ አሃዶች (`requests`፣ `tokens`፣ `usd`) ገንዳው ባልዲ ኮታ በሩ እንደሚያስፈጽም ሪፖርት ተደርጓል `limit` = እቅድ ገደብ × በገንዳ ውስጥ ያሉ ሒሳቦች፣ `fairShare` = ክብደት / 100 × `limit` (እያንዳንዱ ክብደት `consumed` ሲሆን እኩል ይከፈላል) `remaining` `consumed` = የራሱ ቆጣሪ = `fairShare` − በኮታ ውስጥ በ 0.
- `blocks.schedules` የቁልፉን የጊዜ ሰሌዳ መስኮቶች ይዘረዝራል (`open`/`closed`, `blackout` ወይም `outside-window`, `retryAfterSeconds`, የተጠባባቂ ወለሎች እና የመስኮቱ በጀት ጥቅም ላይ እንደዋለ); `blocks.modelCaps` በየሞዴሉ የሰዓት ካፒታሎችን ከፍጆታ ጋር ይዘረዝራል።
- ከእያንዳንዱ የአቅራቢ ገንዳ ውጭ ያለው ቁልፍ 200 በ `pools: []` ያገኛል። `availableModels` (የ `qtSd/` መታወቂያ ቁልፉ በ `/v1/models` ውስጥ ያያል)፣ `expiresAt` እና `apiBaseUrl` አሁንም ተሞልተዋል።
- `apiBaseUrl` `OMNIROUTE_PUBLIC_API_BASE_URL` ነው ከዛ `OMNIROUTE_PUBLIC_BASE_URL` ሌላም `null`። መቼም የጥያቄው መነሻ አይደለም።

### የብድር ስምምነት

`PATCH /api/v1/me/quota/{provider}` የመደወያ ቁልፉን ለአንድ ገንዳ የራሱን ፍቃድ ይመዘግባል። የ `GET` ባንዲራ፣ ራስጌ እና አቅራቢ ደንቦችን ይጠቀማል። ምንም እንኳን ስሙ ተነባቢ-ብቻ ተብሎ ቢነበብም የ `self:usage` ወሰን ይህንን አንድ እንዲጽፍ ይፈቅዳል።

```json
{
  "pool": "qpr_0123456789abcdef0123456789abcdef",
  "lendingPercent": 30,
  "lendingUntil": 1893456000000
}
```

- `pool` ለዚያ ገንዳ የሚመለሰው `ref` ነው `GET`
- `lendingPercent` ከ 0 እስከ 100 ያለው ኢንቲጀር ነው። `lendingPercent` 0 ያለው አካል በሁለቱም ሁነታ ተቀባይነት አለው።
- `lendingUntil` አማራጭ ነው፡ epoch ሚሊሰከንዶች ወይም `null` ያለ ምንም ገደብ። ወደፊት እና ቢበዛ 86400000000000 መሆን አለበት።ከ10000000000 በታች የሆነ እሴት እንደ ሰከንድ ይነበባል እና ውድቅ ተደርጓል።
- ሌላ ማንኛውም መስክ ውድቅ ተደርጓል። ከ4096 ባይት በላይ የሆነ አካል ውድቅ ተደርጓል። ንባቡ የሚቆመው በዚያ መጠን ነው፣ ስለዚህ ረዘም ያለ አካል በጭራሽ ሙሉ በሙሉ አይያዝም።

ቼኮች በዚህ ሰንጠረዥ ቅደም ተከተል ይሰራሉ. ማንኛውም እምቢታ መደበኛውን የስህተት አካል ከቋሚ መልእክት ጋር ይጠቀማል። ከእነዚህ ቼኮች በአንዱ እምቢ ማለት ምንም ነገር አይጽፍም.

ገደቡ ለእያንዳንዱ ቁልፍ በ60 ሰከንድ 20 ጥያቄዎች ነው። የአቅራቢውን ቼክ የሚያልፉ ጥያቄዎች ሁሉ ይቆጠራሉ፣ ሌላው ቀርቶ በኋላ ውድቅ የተደረገ ወይም ምንም የማይለውጠው። ከቁልፉ የጥያቄ መጠን ገደብ ውጪ የራሱ ቆጣሪ አለው።

የተከማቸ ስምምነትን የሚቀይር ጥያቄ አንድ `quota.pool.lending.updated` የኦዲት መዝገብ ይጽፋል። ቁልፉን ከአሮጌው እና ከአዲሱ እሴቶች ጋር ይሰየማል. ሁለት ጊዜ የተላከው አካል አንድ ጊዜ ይጽፋል አንድ ጊዜ ደግሞ ኦዲት ያደርጋል። መልሱ 200 ከሙሉ `GET` እይታ ጋር ነው፣ ከተጻፈ በኋላ የተሰራ።

`GET` እይታ ብድርን እንደሚከተለው ያሳያል፡-

- እያንዳንዱ ገንዳ `borrowMode` (`saturation` ወይም `consent`)፣ እና ቁልፉ የራሱ `lendingPercent` እና `lendingUntil` ይይዛል።
- `lendingActive` `true` በ `consent` ገንዳ ውስጥ ብቻ ነው፣ መቶኛ ከ0 በላይ ያለው እና የመጨረሻው ቀን አልደረሰም።
- በ `consent` ገንዳ ውስጥ፣ እያንዳንዱ ሊቆጠር የሚችል `dimensions[].yourShare` `borrowAvailable` ይይዛል። ቁልፉ አሁን ካለው ድርሻ በላይ ሊጠቀም የሚችለው በሌሎች ቁልፎች የተበደረ ነው።
- `borrowAvailable` የበሩን ቀመር ይጠቀማል። ሌላውን ቁልፍ ያነባል፣ እንዲሁም ቁልፉ በእሱ ድርሻ ስር እያለ። ለ `hard` ቁልፍ በሌላ ቁልፍ አንድ ተጨማሪ ማንበብ እና ሊቆጠር የሚችል ልኬት፣ በትይዩ።
- `borrowAvailable` `null` ለ `soft` ወይም `burst` ቁልፍ ሲሆን `null` ደግሞ ማንበብ ሲወድቅ ነው።
- `borrowAvailable` ለሁሉም ሌሎች ቁልፎች አንድ ላይ አንድ ምስል ነው። በሁለት ቁልፎች ገንዳ ውስጥ የሌላኛው ቁልፍ የራሱ ምስል ነው።
- `borrowAvailable` ለ `percent` መስኮቶች ወይም በ `accounts[]` እስካሁን አልተዘገበም።
- በ `saturation` ገንዳ ውስጥ እይታው የተከማቸ ስምምነትን በ `lendingActive: false` እና ምንም `borrowAvailable` ሪፖርት ያደርጋል።

### ስህተቶች

የዚህ መንገድ እያንዳንዱ ምላሽ፣ ስኬት ወይም ስህተት፣ `Cache-Control: no-store` ይይዛል። መንገዱ ከመሄዱ በፊት የሚከሰት እምቢተኛነት አይሸከምም ለምሳሌ የደንበኛው API ፖሊሲ 401 ወይም የ IP ማጣሪያ 403. የመንገዱ ስህተቶች መደበኛውን የስህተት አካል በቋሚ መልእክት ይጠቀማሉ፡ 400 (ልክ ያልሆነ አቅራቢ)፣ 401 (የጠፋ ወይም የተሳሳተ ቁልፍ)፣ 403 (የጠፋ `self:usage`), 5g off (40) እና `Failed to build quota view`)። 500 ጥያቄው ወደ መንገዱ እንደደረሰ ማንኛውንም ውድቀት ይሸፍናል, ቁልፍ ፍለጋን ጨምሮ; መንስኤው በአገልጋዩ ላይ ተመዝግቧል እና ተመልሶ አልተመለሰም። የ `PATCH` ስህተቶች [በአበዳሪ ፍቃድ](#lending-consent) ውስጥ ተዘርዝረዋል.

### ገደቦች

- `remaining` ያልተጠቀመበት የቁልፉ ትክክለኛ ድርሻ አካል ነው። ዋስትና አይደለም. ገንዳው ክፍል ሲኖረው ቁልፍ አሁንም ከሱ በላይ ሊቀርብ ይችላል። የመዋኛ ገንዳው አጠቃላይ መጠን `limit` ከደረሰ በኋላ እያንዳንዱ የመዋኛ ቁልፍ እምቢ ይላል የራሱ `remaining` ምንም ይሁን ምን እና ያለ `self:account-quota` ቁልፍ ያንን ድምር ማየት አይችልም።
- `remaining` የምደባውን ፍፁም `cap` ግምት ውስጥ አያስገባም። ማስፈጸሚያ ቁልፉን ውድቅ የሚያደርገው በካፒቢው ክፍል መስኮት ውስጥ ያለው የራሱ ፍጆታ የካፕ ዋጋው ላይ ከደረሰ በኋላ ነው።
- የመለያ ደረጃ አሞሌ የሚመጣው ከአገልግሎት ሰጪው መሸጎጫ ይገድባል እና የማስፈጸሚያ ውሳኔውን በጥቂት ደቂቃዎች ውስጥ ሊያዘገየው ይችላል። ዳግም ማስጀመር ጊዜ ያለፈበት ንባብ `stale` ተብሎ ተዘግቧል።
- የፔር-ሞዴል መስኮቶች (`modelWindows`) ሪፖርት የተደረገው የፕላን-መስኮት ካርታ ላላቸው አቅራቢዎች ብቻ ነው Claude እና Codex ዛሬ። ለሌሎች አቅራቢዎች `modelWindows` የመለያ ውሂብ በሚታይበት ጊዜ ከባዶ `windows` ዝርዝር ጋር አለ።
- `percent` መስኮት ቁልፍ የራሱ ድርሻ ግምት ነው። እሱ ከባለቤትነት መፅሃፉ የመጣ ሲሆን ከላይ በ"ፐርሰንት ልኬቶች፡ በአንድ ቁልፍ ባህሪ" ስር የተዘረዘሩትን ሁሉንም ገደቦች ይሸከማል።
- `consumed` ከተገቢው ድርሻ ጋር ሲወዳደር የቁጥር ማስፈጸሚያ ነው። በትክክል `attributed` ሲደመር `external` ነው። `attributed` መጽሐፉ ለተሻገሩት ቶከኖች ቁልፍ የሚሰጠው ክፍል ነው። `external` የመዋኛ ቁልፎች የማይቆጠሩበት የመለያው አጠቃቀም ቁልፍ አካል ነው።
- ሁለቱም ክፍሎች የሚላኩት የገንዳው `accountVisible` እውነት ሲሆን፡ ቁልፉ `self:account-quota` አለው እና አቅራቢው በ `sharedQuotaProviders` ውስጥ ነው። ያለሱ ቁልፍ `consumed` ብቻውን ያገኛል፣ በተመሳሳይ `status` እና `reason`.
- ከሁለቱም ክፍሎች እና የራሱ ክብደት ጋር አንድ ያዥ ወደ ገንዳው ቁልፎች ከተሞላው ገንዳ ውጭ የተሰራውን አጠቃቀም ሊሠራ ይችላል። የመለያው ወሰን ያለው ያዥ የሒሳቡን አጠቃላይ ሁኔታ አስቀድሞ ያያል።

### የአባል አጠቃቀም

### ተከታታይ አጠቃቀም (`GET /api/v1/me/usage`)

`GET /api/v1/me/usage?range=<range>` (እንዲሁም በ `/v1/me/usage` አገልግሏል) የጥሪ ቁልፉን አጠቃቀም እና ወጪ ይመልሳል የራሱ ጥያቄዎች፡ ድምር፣ አንድ ግቤት በ UTC ቀን፣ በቀን እና ሞዴል፣ በአንድ ሞዴል እና በአቅራቢ። ባንዲራውን፣ የማረጋገጫ ህጎቹን፣ የ `self:usage` ወሰንን፣ `Cache-Control: no-store` እና ከላይ ያለውን የኮታ መስመር የስህተት ባህሪን ይጋራል። ቁልፉ ከ `range` በፊት ተረጋግጧል. ስህተቶች 400 (`Invalid range`)፣ 401፣ 403፣ 404 እና 500 (`Failed to build usage`) ናቸው።

- `range` ከ `1d`፣ `7d`፣ `30d` (ነባሪው) ወይም `90d` አንዱ ነው። ሌላ ማንኛውም እሴት፣ ባዶ እሴት ወይም ተደጋጋሚ ግቤት 400 ነው። ዝግጅቱ በ `90d` ላይ ይቆማል የጥሪ ወጪን ለማያያዝ። እይታው የጥሬ አጠቃቀም ታሪክን ብቻ ያነባል፣ ምንም ቁልፍ ያልያዘው ዕለታዊ ማጠቃለያዎችን አያውቅም።
- ረድፎች የሚመረጡት በጥሪ ቁልፉ መታወቂያ ነው። የቁልፍ ስም አምድ በጭራሽ አይዛመድም እና ያለ ቁልፍ መታወቂያ የተመዘገቡ ረድፎች በጭራሽ አይቆጠሩም።
- ተከታታይ መገንባት በመስኮቱ ውስጥ ባሉት የቁልፍ ረድፎች ላይ አምስት የተቧደኑ መጠይቆችን ያካሂዳል። የተገነባው ተከታታይ በቁልፍ እና በክልል ለ60 ሰከንድ በድጋሚ ጥቅም ላይ ይውላል፣ እና በድጋሚ ጥቅም ላይ የዋለ ጥሪ ምንም አይሰራም። `generatedAt` እድሜውን ይሰጣል።
- ተከታታይ ሲገነባ መስኮቱ ያበቃል. በኋላ ላይ የታተመ ረድፍ፣ ለምሳሌ በሰዓት skew፣ አይቆጠርም።
- `coverage.retentionDays` የኦፕሬተሩ ጥሬ አጠቃቀም-ታሪክ ማቆያ መቼት ነው (በመረጃ ቋት ቅንብሮች ውስጥ `retention.usageHistory` )። የተጠየቀው ክልል ከዚያ ቅንብር ሲረዝም `coverage.truncatedByRetention` እውነት ነው። ሁለቱን ቁጥሮች ያወዳድራል እና ረድፎች በትክክል ጠፍተዋል እንደሆነ አያረጋግጥም።
- አቅራቢው ለቁልፉ በራሱ ጥያቄዎች ተመዝግቦ ይመለሳል። ሞዴል ከመጨረሻው `/` በኋላ የተቀዳው ስም ነው፣ እና ረድፎች በእሱ ይመደባሉ። እያንዳንዱ ኢላማው ውድቅ የተደረገበት ጥምር ጥያቄ በማዞሪያ መለያው እንደ አቅራቢ (የጥምር ስም፣ `auto` ወይም `combo`) እና ደንበኛው የላከው ሞዴል ሕብረቁምፊ ይመዘገባል። ሌሎች ውድቅ የተደረጉ ጥያቄዎች፣ ለምሳሌ በክፍት ሰርክታርተር፣ በሞዴል ማቀዝቀዣ ወይም በኮታ የቆመ ዝላይ፣ የታለመውን አቅራቢ እና ሞዴል ያስቀምጡ።
- ከቆጠራዎች እና ወጪዎች በተጨማሪ፣ ምላሹ አማካኝ መዘግየትን፣ የስኬት ተመኖችን እና የመጀመሪያ እና የመጨረሻ ጥያቄ ጊዜዎችን ይይዛል።
- `byModel` 50 አቅራቢ-እና-ሞዴል ጥንዶችን ብዙ ጥያቄዎችን ይዘረዝራል። ከብዙ ጥንዶች ጋር ግመቶቹ እስከ `summary` አይጨመሩም፣ እና `summary.uniqueModels` እያንዳንዱን የተቀዳ ሞዴል ሆሄ ይቆጥራል። `byModelTruncated` ከዚያ እውነት ነው, እና ጥንዶቹ በሁለቱም የተቆረጡ ጎኖች ላይ የሚወድቁበት ሞዴል ከፊል ድምር ያሳያል.
- ሁለት ወጪዎች ተዘግበዋል. የአጠቃቀም ትንታኔ እንደሚያሳየው `costUsd` የሚከፈለው ወጪ ነው። እንደ Claude Code ዕቅድ ያሉ ጠፍጣፋ የደንበኝነት ምዝገባ አቅራቢዎች እዚያ $0 ይቆጥራሉ። `listPriceUsd` ተመሳሳዩ የአጠቃቀም ዋጋ በዝርዝሩ ዋጋ ነው፣ የደንበኝነት ምዝገባዎች ተካትተዋል። ሞዴሉ ምንም የዋጋ ረድፍ የሌለው ጥያቄ የተከማቸ ወጪውን ይቆጥራል፡ አቅራቢው ሪፖርት ያደረገው ወጪ፣ ወይም ጥያቄው ሲመዘገብ የተሰላ። ጥያቄ ብቻ ከሁለቱም 0 አይቆጠርም፣ ምንም ምልክት የለውም፣ ስለዚህ አጠቃላይ ከፊል ሊሆን ይችላል።
- የምላሽ ውል `src/shared/schemas/selfUsage.ts` (`SelfUsageSeries` in `docs/openapi.yaml`) ነው።

### የራስ አገልግሎት ገጽ

`QUOTA_SELF_PANEL` በርቶ፣ `/quota/{provider}` የህዝብ ገጽ ነው። አንድ ቁልፍ ያዥ API ቁልፍን እዚያው ይጽፋል እና የዚያን ቁልፍ ገንዳዎች ለአቅራቢው ያያል። እያንዳንዱ ገንዳ በገንዳው መስኮት አንድ ካርድ ያሳያል፣ ገንዳው ለሁሉም የሚጠቀምበት እና የቁልፉ የራሱ ድርሻ ያለው። የመዋኛ ገንዳው እያንዳንዱ መለያ የራሱ ካርዶች አሉት፣ ከመለያው አጠቃቀም እና ከቁልፍ ድርሻ ጋር። የመለያው አጠቃቀም ቁልፉ የመለያ ውሂብን ማየት ሲችል ብቻ ይታያል። ገጹ እንዲሁ የእያንዳንዱ መለያ የሞዴል ገደቦችን እና የቁልፉን የራሱ አጠቃቀም ይዘረዝራል። መርሐግብር ቁልፉን ሲዘጋው ማስታወቂያ ይታያል። አንድ ካርድ እያንዳንዱን የሞዴል ቁልፍ ከጥቅሙ ጋር ይዘረዝራል እና የተደረሰውን ምልክት ያደርጋል። `{provider}` የአቅራቢ መታወቂያ ወይም ተለዋጭ ስም ነው (`/quota/claude`፣ `/quota/cc`)። ያልታወቀ አቅራቢ፣ እና ባንዲራ ጠፍቶ እያለ እያንዳንዱ `/quota/*` መንገድ፣ መልስ 404. በብጁ OpenAI- ወይም Anthropic-ተኳሃኝ መስቀለኛ መንገድ ላይ ያሉ ገንዳዎች ምንም ገጽ የላቸውም። API አሁንም ለእነሱ መልስ ይሰጣል.

ገጹ ክፍለ ጊዜ የለውም። ቁልፉ የሚላከው በ `Authorization`, `PATCH /api/v1/me/quota/{provider}` እና `GET /api/v1/me/usage` ውስጥ ብቻ `GET /api/v1/me/quota/{provider}`, በጭራሽ በ URL ውስጥ. አገልጋዩ የሚቀበለው ቁልፍ በትሩ `sessionStorage` ውስጥ ተቀምጧል። በ "በዚህ መሳሪያ ላይ አስታውስ" በምትኩ `localStorage` ውስጥ ተቀምጧል እና "ቁልፍ እርሳ" ከሁለቱም ያስወግዳል. አገልጋዩ ያልተቀበለው ቁልፍ ከማከማቻው ይወገዳል።

በ `consent` ሁነታ ላይ ያለ ገንዳ የብድር ካርድ ያሳያል። እዚያም ቁልፍ ያዢው ለመበደር ከ 0 እስከ 100 የሚሆነውን የቁልፉን የስራ ፈትነት መቶኛ ያዘጋጃል። እንዲሁም ያዢው ፈቃዱ ለምን ያህል ጊዜ እንደሚቆይ ይመርጣል፡ እስኪጠፋ ድረስ፣ 1 ሰዓት፣ 8 ሰዓት፣ 24 ሰዓት፣ 7 ቀናት ወይም 30 ቀናት። የቆይታ ጊዜ ከተቀመጠበት ጊዜ ጀምሮ ይቆጠራል። ቀነ ገደብ በሥራ ላይ እያለ፣ ያዢው በምትኩ ሊያቆየው ይችላል። ያ ቀነ ገደብ ከማስቀመጥ በፊት ካለፈ ካርዱ ምንም አይልክም እና ሌላ ምርጫ ይጠይቃል። ከ 0% ጋር ምንም የጊዜ ገደብ አልተላከም። ካርዱ የተከማቸ ቀነ ገደብ የሰዓት ሰቅ የተሰየመበትን ያሳያል። ቀነ-ገደቡ ያለፈበት ስምምነት እንደተጠናቀቀ ታይቷል።

ለ `hard` ቁልፍ ካርዱ በፑል መስኮት፣ ለቁልፉ አሁን ምን አይነት ሌሎች ቁልፎች እንደሚያበድሩ ይዘረዝራል። እያንዳንዱ ረድፍ ለሁሉም ሌሎች ቁልፎች አንድ ላይ አንድ አሃዝ ነው። በሁለት ቁልፎች ገንዳ ውስጥ የሌላኛው ቁልፍ የራሱ ምስል ነው። እይታው የማይዘግበው አሃዝ እንደ ዜሮ ሳይሆን እንደማይገኝ ይነበባል። ለ `soft` ወይም `burst` ቁልፍ ካርዱ ምንም አሃዝ አይተገበርም ይላል።

ቁልፉ መቶኛ ከ0 በላይ የሚያከማች `saturation` ሁነታ ላይ ያለ ገንዳ መውጣትን ብቻ ያሳያል። የተከማቸ መቶኛ እዚያ ምንም ተጽእኖ እንደሌለው ይናገራል. የማውጣት አዝራሩ ያለ ገደብ 0 ይልካል። በ `saturation` ሁነታ ላይ ያለ ገንዳ የተከማቸ 0 ምንም የብድር ካርድ አያሳይም። ከቁጠባ በኋላ የተመለሰው እይታ የማይፈልገው ካርድ የገጹ እይታ እንደገና እስኪቀየር ድረስ ከመልዕክቱ ጋር ይቆያል።

ያዢው አስቀምጥ ወይም ማውጣትን እስኪጫን ድረስ ምንም ነገር አይቀመጥም። እያንዳንዱ ፕሬስ አንድ `PATCH /api/v1/me/quota/{provider}` ጥያቄ ይልካል ፣ እና ሁለተኛው ፕሬስ የመጀመሪያው በመጠባበቅ ላይ እያለ ምንም አይልክም። አካሉ የመዋኛ ገንዳውን ግልጽ ያልሆነ `ref` ከእይታ፣ በመቶኛ እና ከማለቂያው ጊዜ ይይዛል። መልሱ እንደገና የተገነባው የኮታ እይታ ነው, እና ገጹ ምንም ሁለተኛ ሳይነበብ ያሳያል. ሁለት ቁጠባዎች ሲደራረቡ፣ ገጹ ከመጨረሻው መልስ አንድ ጊዜ ኮታውን ያነባል። ገጹ በአሳሽ ማከማቻ ውስጥ ፈቃዱን አያስቀምጥም።

ውድቅ የተደረገ ለውጥ በካርዱ ላይ ከ HTTP ሁኔታ በተመረጠው ጽሑፍ ተብራርቷል. የስህተት አካሉ አልተነበበም። A 401 ቁልፉ ተቀባይነት አላገኘም ይላል እና ኮታውን እንደገና ይጭናል. አንድ 403 ገንዳው የብድር ለውጦችን እየወሰደ አይደለም ይላል, እና 404 ገንዳው ጠፍቷል ይላል. ሁለቱም ኮታውን እንደገና የሚጭን ቁልፍ ይሰጣሉ። 400 ወይም ሌላ 4xx መልስ ያዢው መቶኛ እና የመጨረሻውን ጊዜ እንዲያረጋግጥ ይጠይቃል። A 429 ያዢው እንዲጠብቅ ይጠይቃል፣ መልሱ ሲሰጣቸው በ `Retry-After` ሰከንዶች። 5xx መልስ፣ 408 ወይም የአውታረ መረብ አለመሳካት ለውጡ አልተቀመጠም ይላል እና የተተየቡ እሴቶችን ይጠብቃል። ከኮንትራቱ ውጭ ያለው መልስ ኮታውን እንደገና ይጭናል. ያልተሳካ ማስቀመጫ ቁልፉን በራሱ አያስወግደውም። ከተከለከለ በኋላ እንደገና ሲጫን ገጹ እንደማንኛውም ያልተነበበ ቁልፉን ያስወግዳል።

ቁልፉ አንዴ ከተቀበለ በኋላ ገጹ በተጨማሪ ሶስት ትሮች ያለው "የእርስዎን መሳሪያዎች ያዘጋጁ" ካርድ ያሳያል. "Claude ኮድ" የ `env` ብሎክ ለ `~/.claude/settings.json` ይሰጣል። "ሼል" እንደ `export` መስመሮች ተመሳሳይ ተለዋዋጭዎችን ይሰጣል. "Claude ዴስክቶፕ" ለሶስተኛ ወገን የማጣቀሻ መስኮት እሴቶቹን ይሰጣል። ሞዴሎቹ ቁልፉ ለዚያ አቅራቢ ሊጠራው የሚችለው የኮታ መጋራት ሞዴሎች ናቸው። እንደዚህ አይነት ዝርዝር ከቁልፉ ጋር በማይመጣበት ጊዜ እገዳው በምትኩ የጌትዌይ ሞዴል ግኝትን ያበራል። የመተላለፊያ መንገድ አድራሻው የአገልጋዩ ዘገባ የወል API ምንጭ ነው (`OMNIROUTE_PUBLIC_API_BASE_URL`፣ ከዚያም `OMNIROUTE_PUBLIC_BASE_URL`)። አንዳቸውም ካልተዋቀሩ ካርዱ ቦታ ያዥ ያሳያል እና ያዢው አስተዳዳሪውን እንዲጠይቅ ይነግረዋል። ቁልፉ እንደ ቦታ ያዥ ነው የሚታየው። "ቁልፌን አካትት" የሚለውን ሙሉ ቁልፉን በጽሁፉ ላይ በስክሪኑ ላይ ያስቀምጣቸዋል እና የቅጂ አዝራሩ በምን እንደሚገለበጥ። ያ ሳጥኑ እስኪጸዳ ድረስ, ቁልፉ እስኪረሳ ወይም እስኪተካ ድረስ, ወይም ገጹ እስኪተወ ድረስ ይቆያል. ካርዱ ምንም አይነት ጥያቄ አይልክም እና ምንም ፋይል ማውረድ አይሰጥም.

API ምልክቶች `stale` ማንበብ ጊዜ ያለፈበት ሊሆን ይችላል። `unavailable` የሚል ምልክት ያለው ንባብ ከምክንያቱ ጋር ነው የሚታየው እንጂ ዜሮ ሆኖ አያውቅም።

በፐርሰንት ዕቅዶች ላይ API ሲዘግብ ገጹ የራሱን ቁልፍ ይሳባል። ቁጥሩ ግምት ነው ይላል እና ሁለቱን ክፍሎች ይሰይማል። የአንድ ሞዴል ገደቦች መለያውን ብቻ ያሳያሉ።

`GET` እና `HEAD` ያለ አካል ይተላለፋሉ። ከአካል ጋር አንድ ጥያቄ እንዲሁ ይተላለፋል፡ የኮታ እይታ ዱካ `PATCH` ፣ ገጹ የብድር ምርጫን ለማስቀመጥ የሚልክ ነው። ማንኛውም ሌላ ዘዴ መልስ 404, አንድ CONNECT ጥያቄ በስተቀር, የማን ግንኙነት ምንም መልስ ተዘግቷል. አካልን የሚገልጽ ሌላ ማንኛውም ጥያቄ 404 ይመልሳል እና ግንኙነቱ ተዘግቷል። የማሻሻያ ጥያቄዎች ውድቅ ተደርገዋል እና ግንኙነታቸው ተዘግቷል። ልክ እንደ API ወደብ የነጥብ ክፍል ወይም ቁርጥራጭ ምልክት ያለው መንገድ ውድቅ ተደርጓል። ከህትመት ውጭ የሆነ ገጸ ባህሪ ያለው የጥያቄ ኢላማም እንዲሁ ነው ASCII በዒላማው ውስጥ ያለ ጥሬ መቆጣጠሪያ ቁምፊ 400 በ HTTP ተንታኝ ምላሽ ተሰጥቶታል፣ ይህ ወደብ የራሱ ቼክ ከመደረጉ በፊት። ማዕቀፉ ለራሱ ጥቅም ያስቀመጠውን ራስጌዎች ጠይቅ፡- `x-middleware-`, `x-invoke-`, `x-nextjs-`, `x-now-` ወይም `x-next-` እና ስሞች `x-matched-path` እና `next-resume` የሚጀምሩ ስሞች። ጥያቄው ያለ እነርሱ ነው የሚተላለፈው። ዳሽቦርዱ፣ የመግቢያ ገጹ፣ የአስተዳደር API እና የማጣቀሻ መንገዶች በዚህ ወደብ ሊደርሱ አይችሉም።

`PATCH` `Content-Type: application/json` መሸከም አለበት፣ ምንም መለኪያ የሌለው ወይም በ `charset=utf-8` ብቻ። አንድ `Content-Length` ከ1 እስከ 4096፣ እንደ ግልጽ አሃዞች የተጻፈ እና ምንም `Transfer-Encoding` መያዝ አለበት። ከእነዚህ ደንቦች ውስጥ አንዱን የሚጥስ `PATCH` 404. አንዳንድ የተበላሹ ርዝመቶች ለምሳሌ የተፈረመ ወይም የተደጋገመ 400 ምላሽ በ HTTP ተንታኝ ይህ ወደብ በራሱ ቼክ በፊት. ወደቡ ዋናውን ወደብ ከማግኘቱ በፊት የታወጀውን ባይት ያነባል እና ቢበዛ 5 ሰከንድ ይጠብቃቸዋል። ያልተጠናቀቀ አካል 404 ን ይመልስና ግንኙነቱ ተዘግቷል። በዚህ ጉዳይ ላይ ምንም ነገር ወደ ዋናው ወደብ አይደርስም, ወይም ደንበኛው መጀመሪያ ሲወጣ. ወደቡ በትክክል የተገለጸውን ባይት ያስተላልፋል፣ ከተመሳሳይ `Content-Length` ጋር። ከነሱ በኋላ ባይት በግንኙነቱ ላይ እንደሚቀጥለው ጥያቄ ይነበባል። ከፊት ያለው የ TLS ተገላቢጦሽ ተኪ `Content-Length` ማስተላለፍ አለበት እና የጥያቄውን አካል እንደገና መቆራረጥ የለበትም። ዋናው ወደብ በ `Authorization` ራስጌ ውስጥ የ API ቁልፍን ይፈትሻል፣ እንደ `GET`።

404 አካሉ `{"error":"not_found","message":"Not found."}` ነው። ያልተሳካ ቅብብሎሽ መልሶች 502 (`api_bridge_unavailable`) ወይም 504 (`api_bridge_timeout`) `detail` መስክ ጋር።

ሰሚው `QUOTA_SELF_PANEL` አያነብም, እና ገጹን አያበራም. ባንዲራው ጠፍቶ እያለ ገጹ እና API በዋናው ወደብ ላይ 404 ን ይመልሱ እና አድማጩ ያንን መልስ ያስተላልፋል።

በልማት አገልጋይ (`next dev`) ስር ገጹ በዚህ ወደብ መስተጋብራዊ አይሆንም። የዕድገት ትኩስ-ዳግም መጫን ሶኬት የማሻሻያ ጥያቄ ነው፣ እና ወደቡ እምቢ አለ። በማደግ ላይ እያሉ ዋናውን ወደብ ይጠቀሙ።

ወደቡ ተራ HTTP ያገለግላል እና ገጹ API ቁልፎችን ይልካል። ነባሪውን የመያዣ አድራሻ ያስቀምጡ እና ከፊት ለፊቱ TLS ያለው ተገላቢጦሽ ፕሮክሲ ያድርጉ። ከloopback ሌላ የማሰር አድራሻ ይህንን ማስታወቂያ ይመዘግባል፡-

```text
[Quota Panel] Bound to <host>. This port serves plain HTTP and the page sends API keys. Put a TLS reverse proxy in front of it.
```

ምንም የማስተላለፊያ ራስጌ የማይልክ loopback አቻ በዋናው ወደብ ላይ እንደ አካባቢያዊ ይቆጠራል። ስለዚህ በተመሳሳዩ አስተናጋጅ ላይ ያለ ተኪ `X-Forwarded-For` መላክ አለበት። በግላዊ አድራሻ ላይ ያለ ተኪ የሚታመነው በ `OMNIROUTE_TRUST_PROXY=private` (ወይም `lan`) ብቻ ነው። ማንኛውም ሌላ አቻ በግንኙነቱ አድራሻ ሪፖርት ይደረጋል፣ እና የላካቸው የማስተላለፊያ ራስጌዎች ይወድቃሉ።

ሰሚው ቢበዛ 256 ግንኙነቶችን በአንድ ጊዜ ይይዛል። አንድ ደንበኛ የጥያቄውን ራስጌ ለመላክ 10 ሰከንድ እና ሙሉ ጥያቄውን ለመላክ 30 ሰከንድ አለው። ስራ ፈትቶ የኖረ ግንኙነት ከ5 ሰከንድ በኋላ ይዘጋል። ለ60 ሰከንድ ምንም እንቅስቃሴ የሌለው ግንኙነት ተዘግቷል። እነዚህ እሴቶች ቋሚ ናቸው. በግንኙነት እና በተለዋዋጭ ፕሮክሲ ላይም ተመን ገደቦችን ያዘጋጁ። ከፊት ያለው የተገላቢጦሽ ተኪ ግንኙነቶቹን ከ5 ሰከንድ ባነሰ ጊዜ ውስጥ ስራ ፈትቶ ማቆየት አለበት ወይም እንደገና ጥቅም ላይ አይውልም። ወደ ዋናው ወደብ የሚደረገው ቅብብል API ወደብ (`API_BRIDGE_*`) ወደ ላይ ያለውን የጊዜ ማብቂያዎችን ይጠቀማል።

ሰሚው የሚጀምረው `API_PORT` ሳይዘጋጅ ሲቀር ነው። `QUOTA_PANEL_PORT` ከ 1 እስከ 65535 በዲጂት ብቻ የተጻፈ ወደብ መሆን አለበት። ከዳሽቦርድ ወደብ እና ከ API ወደብ የተለየ መሆን አለበት። የቀጥታ WebSocket አገልጋይ በርቶ ሳለ፣ ከ `LIVE_WS_PORT` (ነባሪ 20132) የተለየ መሆን አለበት። ሌላ ማንኛውም እሴት ምንም ነገር አይከፍትም እና ማስጠንቀቂያ ይመዘግባል። ውድቅ ስለተደረገው እሴት ማስጠንቀቂያ ተለዋዋጭውን ይሰይማል እና እሴቱን አይደግምም። ቀድሞውንም ጥቅም ላይ የዋለ ወደብ ምንም ነገር አይከፍትም እና ይህን ማስጠንቀቂያ ይመዘግባል፡-

```text
[Quota Panel] Port <port> is already in use. The quota panel port stays off.
```

በ `OMNIROUTE_BASE_PATH` ስብስብ፣ አድማጩ በዚያ ቅድመ ቅጥያ ስር ያሉትን ሁሉንም መንገዶች ይጠብቃል። በግንባታ ጊዜ እና በሂደት ጊዜ ተመሳሳይ `OMNIROUTE_BASE_PATH` ይጠቀሙ። በመሪ ስሌሽ ይፃፉ እና ምንም ተከታይ ስሌሽ የለም፣ ለምሳሌ `/omniroute`። ሌላ ቅርጽ፣ `/` እና `/omniroute/` ጨምሮ፣ ግንባታው እነዚያን ቅጾች ቢቀበልም ወደቡን በማስጠንቀቂያ ይወጣል። እንደዚሁ የመሠረት ዱካ `connect` ክፍል የማመልከቻውን መንገድ `api` `v0` `v1` `dashboard` `v1beta` `quota` `_next` `docs` `login` `anthropic` `codex` `responses` `openai`

- የአገልግሎት ሰራተኛው እና የድር መተግበሪያ መግለጫው በዚህ ወደብ ላይ አይቀርቡም።
- በዳሽቦርዱ ውስጥ የተዘጋጀ ብጁ favicon በዚህ ወደብ ላይ አይታይም።
- አፕሊኬሽኑ በመሠረታዊ ዱካ ስር ሲሄድ አዶዎች አይታዩም።
- ወደቡ ግልጽ HTTP/1.1. ይናገራል
- ሂደቱ እንደገና እስኪጀምር ድረስ ያልተሳካ ማሰሪያ እንደገና አይሞከርም።

## ከ localStorage የሚደረግ ሽግግር

## DB Schema ማጠቃለያ

ሶስት ሰንጠረዦች በስደት `078`፣ `079` እና `085` ተጨምረዋል

- `quota_pools` + `quota_allocations` — ገንዳ ትርጓሜዎች እና በእያንዳንዱ-ቁልፍ ምደባዎች።
- `quota_consumption` — የሚንከባለል ባለ2-ባልዲ ቆጣሪ በ `(apiKeyId, dimensionKey)`።
- `provider_plans` — በእጅ አቅራቢ ፕላን ይሽራል (ልኬቶች JSON በ connectionId)።

በ idempotent `CREATE TABLE IF NOT EXISTS` ፍልሰት በኩል የታከሉ ሁሉም ጠረጴዛዎች።

የፈቃድ ብድር ሶስት አምዶችን ይጨምራል `quota_allocations.lending_percent` (ኢንቲጀር፣ ነባሪ 0)፣ `quota_allocations.lending_until` (epoch milliseconds፣ ወይም `NULL` ያለ ገደብ) እና `quota_pools.borrow_mode` (ነባሪ `saturation`)። የእሱ ፍልሰት እነዚህን አምዶች ብቻ ይጨምራል እና ምንም ነባር ረድፍ አይጽፍም።

የመቶኛ መለያ መጽሐፍ `quota_percent_ledger` (በአንድ ረድፍ በአንድ ገንዳ፣ መለያ እና እቅድ መስኮት) እና `quota_percent_ledger_tokens` (አንድ ማስመሰያ ቆጣሪ በአንድ ገንዳ፣ መለያ እና API ቁልፍ) ይጨምራል። `src/lib/db/quotaPercentLedger.ts` አንብቦ ይጽፋቸዋል።
