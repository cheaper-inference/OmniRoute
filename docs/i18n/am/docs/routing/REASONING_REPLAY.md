## ይህ ለምን አለ?

በርካታ የአስተሳሰብ ሞድ አቅራቢዎች የክትትል ማዞሪያን አይቀበሉም።** የቀድሞ ረዳት መልእክት ዋናውን `reasoning_content` ያካትታል** . ወደ ላይ ያለው 400 በመሳሰሉት መልዕክቶች ይመልሳል፡-

```
Param Incorrect: The reasoning_content in the thinking mode must be passed back to the API.
```

ነገር ግን የተለመዱ ደንበኞች (Cursor፣ Cline፣ Roo Code፣ OpenAI SDK) `reasoning_content` እንደገና ከሚጫወቱት ታሪክ ያርቁ። OmniRoute ከአገልጋይ-ጎን መሸጎጫ ወደነበረበት ይመልሳል ስለዚህ የላይኞቹ የሚታየው ጥያቄ ወጥነት ያለው ነው። እትም #1628 ድቅል memory/SQLite ጽናት አስተዋውቋል ስለዚህም መሸጎጫው ይድናል ሂደቱ እንደገና ይጀምራል።

## አርክቴክቸር

```
Turn N (assistant generates):
  → response contains reasoning_content + tool_calls
  → if requiresReasoningReplay(provider, model): cacheReasoningFromAssistantMessage()
      writes (memory + DB), keyed by every tool_call.id
  → forward response to client (which may or may not retain reasoning)

Turn N+1 (client sends follow-up):
  → translator detects: requiresReasoningReplay(provider, model) === true
  → for each assistant message with tool_calls and no reasoning_content:
      lookupReasoning(toolCalls[0].id) → memory → DB
      hit  → msg.reasoning_content = cached; recordReplay()
      miss → msg.reasoning_content = "" (legacy fallback for older DeepSeek)
  → upstream sees consistent history → no 400
```

ቀረጻ የሚከናወነው በ `open-sse/handlers/chatCore.ts` (ሁለት ጣቢያዎች፣ በሁለቱ `cacheReasoningFromAssistantMessage` የጥሪ ጣቢያዎች) ነው። ድጋሚ ማጫወት የሚከናወነው ከመርሃግብር ማስገደድ በኋላ ግን ከመላክ በፊት በ `open-sse/translator/index.ts` ነው።

ግልጽ (የመሳሪያ-ጥሪ ያልሆኑ) ረዳት መታጠፊያዎች በተለያየ መንገድ ተቆልፈዋል `buildAssistantMessageCacheKey()` የክፍለ ጊዜውን ወሰን እና መደበኛውን የ OpenAI-ቅርጸት ግልባጭ እስከዚያው ድረስ ያዋህዳል፣ ምክንያቱም DeepSeek አንድ ጊዜ `tools` ከተገኘ _እያንዳንዱ_ የቀደመ ተራ ምክንያትን ይፈልጋል። ለምላሾች-ኤፒአይ ኢላማዎች (ለምሳሌ `opencode-go/deepseek-v4-flash`፣ ወደ `/responses` ተዘዋውሯል) ወደ ላይ ያለው አካል `input` እንጂ `messages` አይደለም፣ስለዚህ `translateRequest()` (`open-sse/translator/index.ts`) የምሰሶውን ግልባጭ በመልሶ መደወያ አማራጭ በኩል ሪፖርት ያደርጋል እና የተያዙ ቦታዎች ያንኑ ግልባጭ ያዋህዳሉ። የምላሾች ድጋሚ ማጫወት ይለፍ በ OpenAI ምሰሶ ላይ ለእያንዳንዱ የምንጭ ቅርጸት ይሰራል፣ስለዚህ Anthropic መልእክቶች ደንበኞች (Claude → OpenAI → ምላሾች) እንደገና ይጫወታሉ።

## ማከማቻ — ድብልቅ ማህደረ ትውስታ + SQLite

ሞቃታማው መንገድ ለብልሽት መልሶ ማግኛ እና ዳሽቦርድ ታይነት በ SQLite ሰንጠረዥ የተደገፈ ውስጠ ትውስታ `Map` (LRU-በመፍጠር) ይጠቀማል።

| ንብርብር     | መተግበር                                         | ዓላማ                                 |
| --------- | --------------------------------------------- | ----------------------------------- |
| ማህደረ ትውስታ | `Map` በ `open-sse/services/reasoningCache.ts` | ፈጣን ፍለጋዎች፣ እድሜያቸው 200 ሆነው ያስወጣሉ።    |
| DB        | `reasoning_cache` ሰንጠረዥ (`src/lib/db/`)       | በድጋሚ ጅምር ላይ ይቀጥላል፣ ስታቲስቲክስን ያንቀሳቅሳል |

ለሁለቱም ይጽፋል። መጀመሪያ ማህደረ ትውስታን ያማክሩ እና ወደ DB ይመለሱ (DB hits ወደ ማህደረ ትውስታ ይመለሳሉ) ያነባል። DB አለመሳካቶች ገዳይ ያልሆኑ — የማህደረ ትውስታ መሸጎጫ ሞቃታማውን መንገድ ማገልገሉን ቀጥሏል።

**ነባሪዎች፡-**

- TTL: `2h` (`TTL_MS = 2 * 60 * 60 * 1000`)
- ከፍተኛ የማህደረ ትውስታ ግቤቶች `200` (`MAX_MEMORY_ENTRIES`)
- ማፈናቀል፡ የድሮ `createdAt` መጀመሪያ

## የውሂብ ጎታ ንድፍ

ስደት `src/lib/db/migrations/033_create_reasoning_cache.sql`

```sql
CREATE TABLE IF NOT EXISTS reasoning_cache (
  tool_call_id   TEXT PRIMARY KEY,
  provider       TEXT NOT NULL,
  model          TEXT NOT NULL,
  reasoning      TEXT NOT NULL,
  char_count     INTEGER NOT NULL DEFAULT 0,
  created_at     TEXT NOT NULL DEFAULT (datetime('now')),
  expires_at     INTEGER NOT NULL
);
```

ኢንዴክሶች `expires_at`, `provider`, `model`, `created_at`. `expires_at` እንደ Unix epoch ሰከንዶች ተከማችቷል; የ SELECT ንብርብር የቀድሞ የጽሑፍ እሴቶችን በ `EXPIRES_AT_EPOCH_SQL` በኩል መደበኛ ያደርገዋል።

## REST API

መሸጎጫው በ `src/app/api/cache/reasoning/route.ts` ስር ሁለት የመጨረሻ ነጥቦችን ያጋልጣል። ሁለቱም የአስተዳደር ማረጋገጫ ያስፈልጋቸዋል (`isAuthenticated` ከ `@/shared/utils/apiAuth`)።

| ዘዴ     | የመጨረሻ ነጥብ                                                 | መግለጫ                                                  |
| ------ | --------------------------------------------------------- | ----------------------------------------------------- |
| GET    | `/api/cache/reasoning`                                    | ስታትስቲክስ + በፓጋኒት የተደረጉ ግቤቶች                            |
| GET    | `/api/cache/reasoning?provider=deepseek&model=...&limit=` | የተጣራ ዝርዝር (`limit` ወደ `[1, 200]` ተጣብቋል)               |
| DELETE | `/api/cache/reasoning`                                    | ሁሉንም ነገር ያጽዱ (ትውስታ + DB) እና hit/miss ቆጠራዎችን ዳግም ያስጀምሩ |
| DELETE | `/api/cache/reasoning?provider=deepseek`                  | ለአንድ አቅራቢ ብቻ ግቤቶችን ያጽዱ                                |
| DELETE | `/api/cache/reasoning?toolCallId=call_abc`                | ነጠላ ግቤት ሰርዝ                                           |

## ተግባራዊ ማስታወሻዎች

- **ማጽዳት፡** `cleanupReasoningCache()` ጊዜው ያለፈባቸው የማህደረ ትውስታ ምዝግቦችን ያጸዳል እና `DELETE FROM reasoning_cache WHERE expires_at <= unixepoch('now')` ያስኬዳል። የጤና አጠባበቅ ሰራተኞች ይህንን በየጊዜው ይደውላሉ.

- **ምንም ምክንያት የለም፣ መሸጎጫ የለም፡** `cacheReasoningFromAssistantMessage` የረዳት መልእክቱ `reasoning_content` / `reasoning` መስክ ከሌለው `0` ይመልሳል፣ ስለዚህ የማያስቡ ምላሾች ምንም ዋጋ አያስከፍሉም።
- **መፃፍም ተዘግቷል፡-** ሁለቱም የጥሪ ጣቢያዎች በ `chatCore.ts` (በዥረት የማይለቀቁ እና በዥረት መልቀቅ) ወደ `cacheReasoningFromAssistantMessage()` ይደውሉ `requiresReasoningReplay(provider, model)` `true` — ሲሆን ተመሳሳይ የተነበበ የጎን ቼኮችን ይተነብያል። የድጋሚ አጫውት አቅራቢን ፈጽሞ የማይነኩ ጭነቶች ለጽሑፍ፣ ለኢንዴክስ ማሻሻያ እና ለ try/catch ለእያንዳንዱ ምክንያታዊ-አማካይ ምላሽ መክፈል ያቆማሉ።
