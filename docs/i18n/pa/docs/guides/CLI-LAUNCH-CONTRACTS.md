ਨਿਰਪੱਖ `config/cli-tools-manifest.json` ਇਕਰਾਰਨਾਮਾ ਕੈਨੋਨੀਕਲ IDs, ਉਪਨਾਮ, ਬਾਈਨਰੀ ਉਮੀਦਵਾਰਾਂ, ਸੈੱਟਅੱਪ ਪਕਵਾਨਾਂ, ਮਾਡਲ ਆਰਗੂਮੈਂਟਾਂ ਅਤੇ ਸਮਰੱਥਾਵਾਂ ਦਾ ਐਲਾਨ ਕਰਦਾ ਹੈ। `bin/cli/cli-manifest.mjs` ਵਿੱਚ ਪਲੇਨ ਨੋਡ ਅਡਾਪਟਰ ਅਤੇ `src/shared/constants/cliIntegrationManifest.ts` ਵਿੱਚ TypeScript ਅਡਾਪਟਰ ਇੱਕੋ ਫਾਈਲ ਨੂੰ ਪੜ੍ਹਦੇ ਹਨ। `tests/unit/cli/cli-manifest-drift.test.ts` ਦੁਆਰਾ ਰਨਟਾਈਮ, ਕੈਟਾਲਾਗ, ਸੰਰਚਨਾ, ਸੰਪੂਰਨਤਾ, ਜਨਰੇਟਰ ਅਤੇ ਬੈਕਐਂਡ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਦੀ ਜਾਂਚ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। ਸੂਚੀਬੱਧ ਹੋਣ ਦਾ ਮਤਲਬ ਇਹ ਨਹੀਂ ਹੈ ਕਿ ਕੋਈ ਟੂਲ ਲਾਂਚ ਜਾਂ ਕੌਂਫਿਗਰ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ। ਖਾਸ ਤੌਰ 'ਤੇ, 5ਡਾਈਵ ਸਿਰਫ਼ ਸੰਰਚਨਾ ਲਈ ਰਹਿੰਦਾ ਹੈ।

## ਬਾਲ ਵਾਤਾਵਰਣ ਅਤੇ ਜੀਵਨ ਚੱਕਰ

`omniroute run`, `omniroute launch` ਅਤੇ `omniroute launch-codex` ਇੱਕ OS/terminal ਅਨੁਕੂਲਤਾ ਅਨੁਮਤੀ ਸੂਚੀ ਪ੍ਰਾਪਤ ਕਰਦੇ ਹਨ ਅਤੇ ਚੁਣੇ ਹੋਏ ਟੀਚੇ ਦੇ ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ ਨੂੰ ਇੰਜੈਕਟ ਕਰਦੇ ਹਨ। ਗੈਰ-ਸੰਬੰਧਿਤ ਪ੍ਰਦਾਤਾ ਅਤੇ ਡੇਟਾਬੇਸ ਭੇਦ ਮੂਲ ਰੂਪ ਵਿੱਚ ਵਿਰਾਸਤ ਵਿੱਚ ਨਹੀਂ ਹੁੰਦੇ ਹਨ। `--inherit-env` ਸਪੱਸ਼ਟ ਤੌਰ 'ਤੇ ਪੂਰੇ ਮਾਤਾ-ਪਿਤਾ-ਵਾਤਾਵਰਣ ਵਿਰਾਸਤ ਨੂੰ ਬਹਾਲ ਕਰਦਾ ਹੈ; ਇਸਨੂੰ ਸਿਰਫ਼ ਉਦੋਂ ਹੀ ਵਰਤੋ ਜਦੋਂ ਚੁਣੀ ਤੀਜੀ-ਧਿਰ ਪ੍ਰਕਿਰਿਆ ਨੂੰ ਉਹ ਮੁੱਲ ਪ੍ਰਾਪਤ ਹੋਣੇ ਚਾਹੀਦੇ ਹਨ। ਇਹ ਵਾਤਾਵਰਣ ਫਿਲਟਰਿੰਗ ਹੈ, ਇੱਕ OS ਸੈਂਡਬਾਕਸ ਨਹੀਂ: ਪ੍ਰਕਿਰਿਆ ਅਜੇ ਵੀ ਕਾਲਰ ਦੇ ਫਾਈਲਸਿਸਟਮ ਅਨੁਮਤੀਆਂ ਨਾਲ ਚੱਲਦੀ ਹੈ।

ਰੁਕਾਵਟ ਅਤੇ ਸਮਾਪਤੀ ਦੇ ਸੰਕੇਤ ਬੱਚੇ ਨੂੰ ਭੇਜੇ ਜਾਂਦੇ ਹਨ। ਲਾਂਚਰ ਅਸਥਾਈ ਸੰਰਚਨਾ ਨੂੰ ਹਟਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਬੱਚੇ ਦੇ ਨਜ਼ਦੀਕੀ ਇਵੈਂਟ ਦੀ ਉਡੀਕ ਕਰਦਾ ਹੈ। `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` ਜ਼ਬਰਦਸਤੀ ਸਮਾਪਤੀ (ਡਿਫਾਲਟ 5000 ਮਿਲੀਸਕਿੰਟ) ਤੋਂ ਪਹਿਲਾਂ ਗ੍ਰੇਸ ਪੀਰੀਅਡ ਨੂੰ ਨਿਯੰਤਰਿਤ ਕਰਦਾ ਹੈ।

## Gemini ਸਥਾਈ ਸੈੱਟਅੱਪ

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

ਪਹਿਲੀਆਂ ਦੋ ਕਮਾਂਡਾਂ ਇਸ ਮਸ਼ੀਨ ਨੂੰ ਚੁਣੇ ਹੋਏ ਲੋਕਲ ਜਾਂ ਰਿਮੋਟ ਸਰਵਰ ਲਈ ਸੰਰਚਿਤ ਕਰਦੀਆਂ ਹਨ। ਸੈੱਟਅੱਪ ਗੈਰ-ਸੰਬੰਧਿਤ JSON ਸੈਟਿੰਗਾਂ ਨੂੰ ਸੁਰੱਖਿਅਤ ਰੱਖਦਾ ਹੈ, Gemini API-ਕੁੰਜੀ ਪ੍ਰਮਾਣਿਕਤਾ ਨੂੰ ਚੁਣਦਾ ਹੈ, ਅਤੇ ਇੱਕ ਪ੍ਰਾਈਵੇਟ `.gemini/.env` ਫਾਈਲ ਵਿੱਚ ਅੰਤਮ ਬਿੰਦੂ ਅਤੇ ਪ੍ਰਮਾਣ ਪੱਤਰ ਲਿਖਦਾ ਹੈ। ਇਹ ਇਸ ਨੂੰ ਓਵਰਰਾਈਟ ਕਰਨ ਦੀ ਬਜਾਏ ਅਵੈਧ JSON ਇਨਕਾਰ ਕਰਦਾ ਹੈ। ਅੰਤਮ ਬਿੰਦੂ URLs ਲਾਜ਼ਮੀ ਤੌਰ 'ਤੇ HTTP(S) ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ, ਬਿਨਾਂ ਏਮਬੇਡ ਕੀਤੇ ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ, ਪੁੱਛਗਿੱਛ ਪੈਰਾਮੀਟਰਾਂ ਜਾਂ ਟੁਕੜਿਆਂ ਦੇ। ਡਰਾਈ-ਰਨ ਪ੍ਰਿੰਟ ਮਾਰਗ, ਪ੍ਰਮਾਣਿਕ ਮੁੱਲ ਨਹੀਂ।

`GEMINI_CLI_HOME` ਜਾਂ `--gemini-home` ਪਰਸਿਸਟੈਂਟ ਹੋਮ ਰੂਟ ਦੀ ਚੋਣ ਕਰਦਾ ਹੈ। ਇੱਕ ਅਸਲ `run gemini` ਆਪਣਾ ਅਸਥਾਈ ਘਰ ਬਣਾਉਂਦਾ ਹੈ ਅਤੇ ਬਾਅਦ ਵਿੱਚ ਹਟਾ ਦਿੰਦਾ ਹੈ। ਕੋਈ ਵੀ ਮੋਡ Gemini ਦੇ ਵਰਕਸਪੇਸ-ਟਰੱਸਟ ਜਾਂਚਾਂ ਨੂੰ ਬਾਈਪਾਸ ਨਹੀਂ ਕਰਦਾ ਹੈ।

## Codex ਪ੍ਰੋਫਾਈਲ

`configure codex` ਇੱਕ ਮਾਡਲ ਅਤੇ ਇਸਦੇ OmniRoute ਪ੍ਰਦਾਤਾ ਅੰਤਮ ਬਿੰਦੂ ਦੇ ਨਾਲ ਇੱਕ ਨਿੱਜੀ `<name>.config.toml` ਲਿਖਦਾ ਹੈ। ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ ਨੂੰ `OMNIROUTE_API_KEY` ਦੁਆਰਾ ਹਵਾਲਾ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ, ਕਦੇ ਵੀ ਏਮਬੈਡ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਲਾਂਚ ਕਮਾਂਡ ਚੁਣੇ ਹੋਏ ਮਾਡਲ ਨੂੰ ਉੱਚ-ਪੱਧਰੀ `model` ਕੁੰਜੀ 'ਤੇ ਸੈੱਟ ਕਰਦੀ ਹੈ, `model_providers` ਦੇ ਅੰਦਰ ਨਹੀਂ।

ਵੱਖਰੀ ਪ੍ਰੋਫਾਈਲ ਫਾਈਲਾਂ ਮੌਜੂਦਾ ਦਸਤਾਵੇਜ਼ੀ Codex ਇਕਰਾਰਨਾਮੇ ਹਨ; ਉਹ ਉਪਭੋਗਤਾ ਸੰਰਚਨਾ ਨੂੰ ਓਵਰਲੇਅ ਕਰਦੇ ਹਨ ਜਦੋਂ `codex --profile <name>` ਨਾਲ ਚੁਣਿਆ ਜਾਂਦਾ ਹੈ। [ਅਧਿਕਾਰਤ ਪ੍ਰੋਫਾਈਲ ਹਵਾਲਾ](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) ਅਤੇ [OmniRoute Codex ਗਾਈਡ](./CODEX-CLI-CONFIGURATION.md) ਦੇਖੋ।

## ਹਰਮੇਟਿਕ ਕਮਾਂਡ ਐਗਜ਼ੀਕਿਊਸ਼ਨ

ਇੱਕ ਸਪੱਸ਼ਟ `DATA_DIR` ਦੇ ਨਾਲ, `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` ਸੈੱਟ ਕਰਨਾ ਸ਼ੁਰੂਆਤੀ ਨੂੰ ਡਿਫੌਲਟ ਉਪਭੋਗਤਾ ਡੇਟਾ ਡਾਇਰੈਕਟਰੀ ਦੇ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਵਾਤਾਵਰਣ ਵਿੱਚ ਜਾਣ ਤੋਂ ਰੋਕਦਾ ਹੈ। ਇਹ ਅਲੱਗ-ਥਲੱਗ ਟੈਸਟਾਂ ਲਈ ਲਾਭਦਾਇਕ ਹੈ। ਇਹ ਹੋਰ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਚੁਣੀਆਂ ਗਈਆਂ ਵਾਤਾਵਰਣ ਫਾਈਲਾਂ ਨੂੰ ਅਯੋਗ ਨਹੀਂ ਕਰਦਾ ਹੈ।

## ਵਰਕਿੰਗ-ਡਾਇਰੈਕਟਰੀ `.env`

CLI ਇਸ ਕ੍ਰਮ ਵਿੱਚ `.env` ਫਾਈਲਾਂ ਨੂੰ ਪੜ੍ਹਦਾ ਹੈ, ਅਤੇ ਇੱਕ ਕੁੰਜੀ ਨੂੰ ਸੈੱਟ ਕਰਨ ਵਾਲੀ ਪਹਿਲੀ ਫਾਈਲ ਜਿੱਤਦੀ ਹੈ: ਸਪਸ਼ਟ `DATA_DIR`, ਡਿਫੌਲਟ ਡੇਟਾ ਡਾਇਰੈਕਟਰੀ, ਮੌਜੂਦਾ ਕਾਰਜਕਾਰੀ ਡਾਇਰੈਕਟਰੀ, ਫਿਰ ਪੈਕੇਜ ਡਾਇਰੈਕਟਰੀ। ਸ਼ੈੱਲ ਵੇਰੀਏਬਲ ਹਮੇਸ਼ਾ ਜਿੱਤਦੇ ਹਨ।

ਵਰਕਿੰਗ ਡਾਇਰੈਕਟਰੀ ਕਿਸੇ ਹੋਰ ਦੀ ਹੋ ਸਕਦੀ ਹੈ (ਇੱਕ ਕਲੋਨ ਕੀਤਾ ਰਿਪੋਜ਼ਟਰੀ, ਇੱਕ ਅਨਪੈਕਡ ਪੁਰਾਲੇਖ), ਅਤੇ `omniroute serve` CLI ਵਾਤਾਵਰਣ ਨੂੰ ਸਰਵਰ ਅਤੇ ਸਰਵਰ ਦੁਆਰਾ ਚੱਲਣ ਵਾਲੇ ਹਰੇਕ ਟੂਲ ਨੂੰ ਪਾਸ ਕਰਦਾ ਹੈ। ਇਸ ਲਈ ਉੱਥੇ ਇੱਕ `.env` ਸਿਰਫ਼ ਇਹ ਕੁੰਜੀਆਂ ਸੈੱਟ ਕਰ ਸਕਦਾ ਹੈ, `bin/cli/utils/untrustedCwdEnv.mjs` ਵਿੱਚ ਸੂਚੀਬੱਧ:

| ਕੁੰਜੀ                           | ਸਵੀਕਾਰ ਕੀਤੇ ਮੁੱਲ                                                                  |
| ------------------------------- | --------------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` ਜਾਂ `yes` ਕਿਸੇ ਵੀ ਸਥਿਤੀ ਵਿੱਚ, ਸਰਵਰ ਉਹਨਾਂ ਮੁੱਲਾਂ ਨੂੰ ਮੰਨਦਾ ਹੈ ਜਿਵੇਂ ਕਿ |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 64 ਅੱਖਰ, ਅੰਕ, `_`, `.`, `@` ਜਾਂ `-` ਤੱਕ                                           |
| `LANGUAGE`                      | ਉਹੀ, ਪਲੱਸ `:`                                                                     |
| `TZ`                            | 64 ਅੱਖਰ, ਅੰਕ, `_`, `+`, `-` ਜਾਂ `/` ਤੱਕ, `/` ਨਾਲ ਸ਼ੁਰੂ ਨਹੀਂ ਹੁੰਦੇ                 |
| `NO_COLOR`, `FORCE_COLOR`       | 16 ਅੱਖਰਾਂ ਅਤੇ ਅੰਕਾਂ ਤੱਕ                                                           |

ਹਰ ਮੁੱਲ `REQUIRE_API_KEY` ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ ਚੈੱਕ ਨੂੰ ਚਾਲੂ ਕਰਦਾ ਹੈ, ਇਸਲਈ ਫਾਈਲ ਆਪਣੇ ਆਪ ਚੈੱਕ ਨੂੰ ਬੰਦ ਨਹੀਂ ਕਰ ਸਕਦੀ। ਇਹ ਨਤੀਜੇ ਦਾ ਫੈਸਲਾ ਨਹੀਂ ਕਰਦਾ, ਹਾਲਾਂਕਿ: ਸਰਵਰ ਵਾਤਾਵਰਣ ਤੋਂ ਪਹਿਲਾਂ ਡੇਟਾਬੇਸ ਵਿੱਚ ਸਟੋਰ ਕੀਤੇ ਇੱਕ `REQUIRE_API_KEY` ਓਵਰਰਾਈਡ ਨੂੰ ਪੜ੍ਹਦਾ ਹੈ, ਜਦੋਂ ਕਿ ਇੱਕ API ਕੁੰਜੀ ਤੋਂ ਬਿਨਾਂ ਸਾਰੇ ਇੰਟਰਫੇਸਾਂ 'ਤੇ ਸੁਣਨ ਬਾਰੇ ਸ਼ੁਰੂਆਤੀ ਚੇਤਾਵਨੀ ਸਿਰਫ ਵਾਤਾਵਰਣ ਨੂੰ ਪੜ੍ਹਦੀ ਹੈ। `false` ਦੇ ਸਟੋਰ ਕੀਤੇ ਓਵਰਰਾਈਡ ਦੇ ਨਾਲ, ਇੱਕ ਵਰਕਿੰਗ-ਡਾਇਰੈਕਟਰੀ `REQUIRE_API_KEY=true` API ਨੂੰ ਖੁੱਲ੍ਹਾ ਛੱਡ ਦਿੰਦੀ ਹੈ ਅਤੇ ਉਸ ਚੇਤਾਵਨੀ ਨੂੰ ਲੁਕਾਉਂਦੀ ਹੈ। `TZ` ਨਿਯਮ POSIX ਨਾਲੋਂ ਛੋਟਾ ਹੈ: ਇਹ `.`, `:`, `,` ਅਤੇ `<>` ਰੱਦ ਕਰਦਾ ਹੈ, ਇਸਲਈ `:Area/City` ਫਾਰਮ ਅਤੇ ਨਿਯਮ ਜਿਵੇਂ ਕਿ `EST5EDT,M3.2.0,M11.1.0` ਸ਼ੈੱਲ ਜਾਂ `<DATA_DIR>/.env` ਵਿੱਚ ਸੈੱਟ ਕੀਤੇ ਜਾਣੇ ਚਾਹੀਦੇ ਹਨ।

ਵੱਡੇ ਕੇਸ ਵਿੱਚ, ਨਾਮ ਬਿਲਕੁਲ ਮੇਲ ਖਾਂਦੇ ਹੋਣੇ ਚਾਹੀਦੇ ਹਨ। ਕੋਈ ਹੋਰ ਲਾਈਨ, ਇੱਕ ਮੁੱਲ ਜੋ ਇਸਦੀ ਜਾਂਚ ਵਿੱਚ ਅਸਫਲ ਹੋ ਜਾਂਦਾ ਹੈ, ਅਤੇ ਇੱਕ ਨਾਮ ਜੋ ਸਧਾਰਨ ASCII ਅੱਖਰ, ਅੰਕ ਅਤੇ `_` ਨਹੀਂ ਹੈ (ਉਦਾਹਰਨ ਲਈ ਇੱਕ NUL ਬਾਈਟ ਵਾਲਾ ਜਾਂ ਇੱਕ ਸਮਾਨ ਅੱਖਰ) ਨੂੰ ਛੱਡ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ। CLI ਇੱਕ ਚੇਤਾਵਨੀ ਪ੍ਰਿੰਟ ਕਰਦਾ ਹੈ ਜੋ ਉਹਨਾਂ ਕੁੰਜੀਆਂ ਨੂੰ ਨਾਮ ਦਿੰਦਾ ਹੈ ਜੋ ਇਹ ਸੈਟ ਨਹੀਂ ਕਰ ਸਕਦਾ ਹੈ ਅਤੇ ਇੱਕ ਜਿਸ ਨੂੰ ਨਾਮ ਦੇਣ ਦੀ ਇਜਾਜ਼ਤ ਵਾਲੀਆਂ ਕੁੰਜੀਆਂ ਨੂੰ ਅਣਡਿੱਠ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਹਰ ਇੱਕ ਨੂੰ ਕੀ ਬਦਲਣਾ ਹੈ (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`)। ਨਾ ਹੀ ਮੁੱਲ ਛਾਪਦਾ ਹੈ। ਇਹਨਾਂ ਸੁਨੇਹਿਆਂ ਵਿੱਚ ਫਾਈਲ ਪਾਥ, ਅਤੇ `.env` path `omniroute doctor` ਰਿਪੋਰਟਾਂ, ਉਦੋਂ ਬਚ ਜਾਂਦੀਆਂ ਹਨ ਜਦੋਂ ਉਹਨਾਂ ਵਿੱਚ ਕੰਟਰੋਲ ਜਾਂ ਬਿੱਡੀ ਅੱਖਰ ਹੁੰਦੇ ਹਨ। ਪਾਬੰਦੀ ਉਦੋਂ ਲਾਗੂ ਨਹੀਂ ਹੁੰਦੀ ਜਦੋਂ ਕਾਰਜਸ਼ੀਲ ਡਾਇਰੈਕਟਰੀ ਡੇਟਾ ਡਾਇਰੈਕਟਰੀ ਜਾਂ ਪੈਕੇਜ ਡਾਇਰੈਕਟਰੀ ਹੁੰਦੀ ਹੈ।

`PORT`, `API_PORT` ਅਤੇ `DASHBOARD_PORT` ਸੂਚੀ ਵਿੱਚ ਨਹੀਂ ਹਨ। ਇੱਕ ਉੱਚ-ਪ੍ਰਧਾਨ ਸਰੋਤ ਤੋਂ ਇੱਕ ਅਧਾਰ URL ਤੋਂ ਬਿਨਾਂ, CLI `localhost:<PORT>` ਨਾਲ ਗੱਲ ਕਰਦਾ ਹੈ, ਅਤੇ ਜੋ ਵੀ ਉੱਥੇ ਸੁਣਦਾ ਹੈ ਉਹ CLI ਦੀ API ਕੁੰਜੀ, ਸੰਦਰਭ ਟੋਕਨ ਅਤੇ CLI ਮਸ਼ੀਨ ਟੋਕਨ (`x-omniroute-cli-token`, ਵੇਖੋ [CLI_TOKEN.md](../security/CLI_TOKEN.md) ) ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ, ਜਿਸ ਨੂੰ ਸਥਾਨਕ ਸਰਵਰ ਪ੍ਰਬੰਧਨ loop ਕਾਲਾਂ ਲਈ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ। ਵਰਕਿੰਗ ਡਾਇਰੈਕਟਰੀ ਵਿੱਚੋਂ ਇੱਕ ਪੋਰਟ ਉਸ ਫਾਈਲ ਨੂੰ ਸੁਣਨ ਵਾਲੇ ਨੂੰ ਚੁਣਨ ਦਿੰਦੀ ਹੈ, ਇਸਲਈ ਪੋਰਟਾਂ ਨੂੰ ਸ਼ੈੱਲ ਵਿੱਚ, `<DATA_DIR>/.env` ਵਿੱਚ ਜਾਂ ਕਮਾਂਡਾਂ ਦੇ `--port` ਵਿਕਲਪ ਨਾਲ ਸੈੱਟ ਕਰੋ ਜਿਨ੍ਹਾਂ ਵਿੱਚ ਇੱਕ (`serve`, `launch`, `run`) ਹੈ।

ਪਾਰਸਰ ਦਾ ਕੋਈ `export` ਸੰਟੈਕਸ ਨਹੀਂ ਹੈ। ਇੱਕ ਲਾਈਨ ਜਿਵੇਂ ਕਿ `export LD_PRELOAD=...` ਇੱਕ ਵੇਰੀਏਬਲ `export LD_PRELOAD` ਨਾਮ ਦਿੰਦੀ ਹੈ; ਵਰਕਿੰਗ ਡਾਇਰੈਕਟਰੀ ਤੋਂ ਇਸ ਨੂੰ ਛੱਡ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ, ਅਤੇ ਹੋਰ `.env` ਫਾਈਲਾਂ ਵਿੱਚ ਇਹ ਉਹ ਸ਼ਾਬਦਿਕ ਨਾਮ ਸੈੱਟ ਕਰਦਾ ਹੈ, ਜਿਸਨੂੰ ਕੁਝ ਨਹੀਂ ਪੜ੍ਹਦਾ।

CLI ਇੱਕ ਪ੍ਰਸੰਗ ਦੇ ਸਟੋਰ ਕੀਤੇ ਟੋਕਨ (ਐਕਸੈਸ ਟੋਕਨ ਜਾਂ ਪੁਰਾਤਨ API ਕੁੰਜੀ) ਨੂੰ ਸਿਰਫ਼ ਉਸ ਸੰਦਰਭ ਦੇ ਆਪਣੇ ਮੂਲ ਨਾਲ ਜੋੜਦਾ ਹੈ: ਸਕੀਮ, ਹੋਸਟ ਅਤੇ ਪੋਰਟ, `URL.origin` ਦੀ ਤੁਲਨਾ ਵਿੱਚ। ਇਹ CLI ਦੇ HTTP ਕਲਾਇੰਟ (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) ਦੁਆਰਾ ਕੀਤੀਆਂ ਗਈਆਂ ਬੇਨਤੀਆਂ ਅਤੇ `launch`, `launch codex`, `configure` ਅਤੇ `setup-*` ਕਮਾਂਡਾਂ 'ਤੇ ਲਾਗੂ ਹੁੰਦਾ ਹੈ ਜੋ ਕਿਸੇ ਹੋਰ ਟੂਲ ਦੀ ਸੰਰਚਨਾ ਵਿੱਚ ਅਧਾਰ URL ਅਤੇ ਕੁੰਜੀ ਨੂੰ ਲਿਖਦੇ ਹਨ। `--remote` ਦੇ ਨਾਲ ਕਿਸੇ ਹੋਰ ਸਰਵਰ ਵੱਲ ਇਸ਼ਾਰਾ ਕੀਤਾ ਗਿਆ, ਉਹ ਇੱਕ ਸਪਸ਼ਟ `--api-key` ਜਾਂ `OMNIROUTE_API_KEY` ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਹਨ ਜੇਕਰ ਇੱਕ ਸੈੱਟ ਹੈ, ਅਤੇ ਕੋਈ ਸੰਦਰਭ ਟੋਕਨ ਨਹੀਂ ਹੈ। ਤੁਲਨਾ ਬਿਲਕੁਲ ਸਹੀ ਹੈ, ਇਸਲਈ `localhost` ਅਤੇ `127.0.0.1`, ਜਾਂ ਟ੍ਰੇਲਿੰਗ ਡਾਟ ਦੇ ਨਾਲ ਅਤੇ ਬਿਨਾਂ ਇੱਕ ਹੋਸਟ, ਵੱਖਰੇ ਸਰਵਰਾਂ ਵਜੋਂ ਗਿਣੋ ਅਤੇ ਕੋਈ ਸੰਦਰਭ ਟੋਕਨ ਪ੍ਰਾਪਤ ਨਹੀਂ ਕਰੋ। ਉਪਭੋਗਤਾ ਜਾਣਕਾਰੀ ਵਾਲਾ ਇੱਕ URL, ਇੱਕ ਬੈਕਸਲੈਸ਼ ਜਾਂ ਵ੍ਹਾਈਟਸਪੇਸ ਕਦੇ ਵੀ ਮੇਲ ਨਹੀਂ ਖਾਂਦਾ, ਕਿਉਂਕਿ ਹੋਰ URL ਪਾਰਸਰ (ਉਦਾਹਰਣ ਲਈ, ਪਾਈਥਨ ਦੇ `urllib` ਅਤੇ `httpx`) ਇਸ ਤੋਂ ਇੱਕ ਵੱਖਰੇ ਹੋਸਟ ਨੂੰ ਪੜ੍ਹ ਸਕਦੇ ਹਨ। ਬੇਨਤੀਆਂ ਲਈ CLI ਖੁਦ ਭੇਜਦਾ ਹੈ, ਇਹ ਚੈੱਕ ਸਿਰਫ ਸਕੀਮ ਅਤੇ ਅਥਾਰਟੀ ਨੂੰ ਕਵਰ ਕਰਦਾ ਹੈ, ਇਸਲਈ ਮਾਰਗ ਜਾਂ ਪੁੱਛਗਿੱਛ ਵਿੱਚ ਸਪੇਸ ਵਾਲੀ ਇੱਕ ਆਈਡੀ ਟੋਕਨ ਰੱਖਦਾ ਹੈ।
