## ਇਹ ਕੀ ਹੈ (ਅਤੇ ਕੀ ਨਹੀਂ ਹੈ)

OmniRoute ਟੋਕਨਾਂ ਦੀ ਗਿਣਤੀ ਨੂੰ ਮਾਡਲ ਦੀਆਂ ਕੀਮਤ ਦਰਾਂ ਨਾਲ ਗੁਣਾ ਕਰਕੇ ਹਰ ਕੰਪਲੀਸ਼ਨ ਲਈ
ਪ੍ਰਤੀ-ਬੇਨਤੀ USD ਲਾਗਤ ਨਿਰਧਾਰਤ ਕਰਦਾ ਹੈ। ਇਹ ਸੰਖਿਆਵਾਂ **ਲਾਗਤਾਂ** ਡੈਸ਼ਬੋਰਡ,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON ਐਕਸਪੋਰਟਾਂ ਅਤੇ ਪ੍ਰਤੀ-API-ਕੁੰਜੀ ਬਜਟਾਂ ਨੂੰ ਚਲਾਉਂਦੀਆਂ ਹਨ।

> **ਡੈਸ਼ਬੋਰਡ ਦੀ "ਲਾਗਤ" ਇੱਕ ਬੱਚਤ ਟਰੈਕਰ ਹੈ, ਬਿੱਲ ਨਹੀਂ।** OmniRoute ਕਦੇ ਵੀ ਤੁਹਾਡੇ ਤੋਂ
> ਫੀਸ ਨਹੀਂ ਲੈਂਦਾ — ਇਹ ਤੁਹਾਡੀਆਂ ਬੇਨਤੀਆਂ ਨੂੰ ਉਹਨਾਂ ਪ੍ਰਦਾਤਾਵਾਂ ਵੱਲ ਰੂਟ ਕਰਦਾ ਹੈ ਜਿਨ੍ਹਾਂ ਨੂੰ ਤੁਸੀਂ ਪਹਿਲਾਂ ਹੀ
> ਕਨੈਕਟ ਕੀਤਾ ਹੋਇਆ ਹੈ (ਤੁਹਾਡੀਆਂ ਆਪਣੀਆਂ ਸਬਸਕ੍ਰਿਪਸ਼ਨਾਂ, ਮੁਫ਼ਤ ਟੀਅਰਾਂ ਅਤੇ API ਕੁੰਜੀਆਂ)। ਪੂਰੀ ਤਰ੍ਹਾਂ ਮੁਫ਼ਤ
> ਮਾਡਲਾਂ ਉੱਤੇ ਇਕੱਠੀ ਹੋਈ "$290 ਕੁੱਲ ਲਾਗਤ" ਦਾ ਅਰਥ ਹੈ ਕਿ ਤੁਸੀਂ ਕਿਸੇ ਭੁਗਤਾਨਯੋਗ API ਨੂੰ ਲਗਭਗ
> **$290 ਦਾ ਭੁਗਤਾਨ _ਨਹੀਂ_ ਕੀਤਾ**। ਇਹ ਅੰਕੜਾ ਇਸ ਗੱਲ ਦਾ _ਅਨੁਮਾਨ_ ਹੈ ਕਿ ਮਿਆਰੀ ਸੂਚੀ ਕੀਮਤਾਂ ਉੱਤੇ
> ਇਸੇ ਟ੍ਰੈਫ਼ਿਕ ਦੀ ਕਿੰਨੀ ਲਾਗਤ ਹੋਣੀ ਸੀ, ਤਾਂ ਜੋ ਤੁਸੀਂ ਦੇਖ ਸਕੋ ਕਿ ਤੁਹਾਡੀ ਵਰਤੋਂ ਕਿੱਥੇ ਕੇਂਦ੍ਰਿਤ ਹੈ ਅਤੇ
> ਸਸਤੇ/ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾਵਾਂ ਵੱਲ ਰੂਟਿੰਗ ਕਰਕੇ ਤੁਸੀਂ ਕਿੰਨੀ ਬੱਚਤ ਕਰ ਰਹੇ ਹੋ।

ਇਹ ਵਿਆਖਿਆ ਪ੍ਰੋਜੈਕਟ [README](../../README.md) ਵਿੱਚ ਸਿੱਧੇ ਤੌਰ ਉੱਤੇ ਦਿੱਤੀ ਗਈ ਹੈ ("ਡੈਸ਼ਬੋਰਡ ਦੀ
'ਲਾਗਤ' ਇੱਕ ਬੱਚਤ ਟਰੈਕਰ ਹੈ, ਬਿੱਲ ਨਹੀਂ")।

ਕਿਉਂਕਿ ਇਹ ਸੰਖਿਆ ਇੱਕ ਅਨੁਮਾਨ ਹੈ:

- ਇਹ ਹਰ ਮਾਡਲ ਲਈ OmniRoute ਕੋਲ ਮੌਜੂਦ ਕੀਮਤ ਸਾਰਣੀ ਉੱਤੇ ਨਿਰਭਰ ਕਰਦੀ ਹੈ। ਜਿਸ ਮਾਡਲ ਲਈ ਕੋਈ ਕੀਮਤ
  ਐਂਟਰੀ ਨਹੀਂ ਹੈ, ਉਹ `0` ਲਾਗਤ ਜੋੜਦਾ ਹੈ (ਐਕਸਪਲੋਰਰ ਵਿੱਚ ਇਹ "ਪੁਰਾਣਾ / ਮੁਫ਼ਤ" ਕਤਾਰ ਵਜੋਂ ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ)।
- ਮੁਫ਼ਤ-ਟੀਅਰ ਅਤੇ ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਟ੍ਰੈਫ਼ਿਕ ਲਈ ਵੀ ਇੱਕ _ਅਨੁਮਾਨਿਤ_ ਲਾਗਤ ਇਕੱਠੀ ਹੁੰਦੀ ਹੈ — ਇਹ ਉਹ
  ਰਕਮ ਹੈ ਜੋ ਤੁਸੀਂ ਬਚਾ ਰਹੇ ਹੋ, ਨਾ ਕਿ ਉਹ ਰਕਮ ਜੋ ਤੁਹਾਨੂੰ ਦੇਣੀ ਹੈ।

## ਲਾਗਤਾਂ ਦਾ ਅੰਦਾਜ਼ਾ ਕਿਵੇਂ ਲਗਾਇਆ ਜਾਂਦਾ ਹੈ

### ਕੀਮਤ ਸਰੋਤ

ਲਾਗਤਾਂ [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) ਵਿੱਚ ਵਿਲੀਨ ਮੁੱਲ ਸਾਰਣੀ ਤੋਂ ਆਉਂਦੀਆਂ ਹਨ, ਤਰਜੀਹ ਦੇ ਇਸ ਕ੍ਰਮ ਵਿੱਚ (**ਸਭ ਤੋਂ ਪਹਿਲਾਂ** ):

1. **ਉਪਭੋਗਤਾ ਓਵਰਰਾਈਡ ਕਰਦਾ ਹੈ** — ਕੀਮਤਾਂ ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਜਾਂ `PATCH /api/pricing` ( `pricing` ਨੇਮਸਪੇਸ) ਰਾਹੀਂ ਸੈੱਟ ਕੀਤੀਆਂ ਗਈਆਂ ਹਨ।
2. **models.dev ਸਿੰਕ** — ਕੀਮਤ `https://models.dev/api.json` ( `models_dev_pricing` ਨੇਮਸਪੇਸ) ਤੋਂ ਪ੍ਰਾਪਤ ਕੀਤੀ ਗਈ।
3. **LiteLLM ਸਮਕਾਲੀਕਰਨ** — ਕੀਮਤਾਂ LiteLLM ਦੇ ਜਨਤਕ `model_prices_and_context_window.json` ( `pricing_synced` ਨੇਮਸਪੇਸ) ਤੋਂ ਪ੍ਰਾਪਤ ਕੀਤੀਆਂ ਗਈਆਂ ਹਨ।
4. **ਹਾਰਡਕੋਡ ਕੀਤੇ ਪੂਰਵ-ਨਿਰਧਾਰਤ** — ਦਰਾਂ [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) ਵਿੱਚ ਭੇਜੀਆਂ ਗਈਆਂ।

ਉਸੇ provider/model ਲਈ, ਉੱਚ-ਪ੍ਰਾਥਮਿਕਤਾ ਵਾਲੀਆਂ ਪਰਤਾਂ ਦੇ ਮੁੱਲ ਹੇਠਲੀਆਂ ਲੇਅਰਾਂ ਵਿੱਚ ਮੇਲ ਖਾਂਦੀਆਂ ਫੀਲਡਾਂ ਨੂੰ ਓਵਰਰਾਈਟ ਕਰਦੇ ਹਨ; ਉੱਪਰਲੀ ਪਰਤ ਤੋਂ ਗੈਰਹਾਜ਼ਰ ਖੇਤਰ ਅਜੇ ਵੀ ਹੇਠਲੀ ਪਰਤ ਤੋਂ ਆ ਸਕਦੇ ਹਨ। ਆਰਡਰ ਉਦੋਂ ਵੀ ਸਥਿਰ ਹੁੰਦਾ ਹੈ ਜਦੋਂ ਦੋਵੇਂ ਸੁਤੰਤਰ ਸਿੰਕ ਜੌਬਾਂ ਇੱਕੋ ਸਮੇਂ 'ਤੇ ਚੱਲਦੀਆਂ ਹਨ। `GET /api/pricing?includeSources=1` `pricing` ਅਤੇ `sourceMap` ਵਾਪਸ ਕਰਦਾ ਹੈ, ਜਿਸ ਦੇ ਪ੍ਰਤੀ-ਮਾਡਲ ਲੇਬਲ (`user`, `modelsDev`, `litellm`, `default`) ਉਸ ਮਾਡਲ ਵਾਲੀ ਸਭ ਤੋਂ ਵੱਧ ਤਰਜੀਹ ਵਾਲੀ ਪਰਤ ਦੀ ਪਛਾਣ ਕਰਦੇ ਹਨ।

**LiteLLM ਸਮਕਾਲੀਕਰਨ** ਔਪਟ-ਇਨ ਹੈ, ਮੂਲ ਰੂਪ ਵਿੱਚ ਅਯੋਗ ਹੈ। ਇਸਦੇ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ ( [`.env.example`](../../.env.example) ਵੇਖੋ) ਹਨ:

| Env var                 | ਡਿਫਾਲਟ    | ਮਕਸਦ                                                              |
| ----------------------- | --------- | ----------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | ਪਿਛੋਕੜ LiteLLM ਕੀਮਤ ਸਮਕਾਲੀਕਰਨ ਨੂੰ ਸਮਰੱਥ ਬਣਾਓ।                     |
| `PRICING_SYNC_INTERVAL` | `86400`   | ਸਕਿੰਟਾਂ ਵਿੱਚ ਸਿੰਕ ਅੰਤਰਾਲ (ਰੋਜ਼ਾਨਾ)।                               |
| `PRICING_SYNC_SOURCES`  | `litellm` | ਸਿਰਫ਼ ਇਸ ਸਿੰਕ ਲਈ ਸਰੋਤ ਚੋਣ; ਵਰਤਮਾਨ ਵਿੱਚ ਸਿਰਫ਼ `litellm` ਸਮਰਥਿਤ ਹੈ। |

**models.dev ਸਿੰਕ** LiteLLM ਸਿੰਕ ਤੋਂ ਵੱਖ ਹੈ ਅਤੇ ਡਿਫੌਲਟ ਤੌਰ 'ਤੇ ਅਯੋਗ ਵੀ ਹੈ। ਇਸਨੂੰ ਸੈਟਿੰਗਾਂ (models.dev ਸਿੰਕ) ਵਿੱਚ ਸਮਰੱਥ ਕਰੋ ਜਾਂ ਇਹਨਾਂ ਵੇਰੀਏਬਲਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ:

| Env var                    | ਡਿਫਾਲਟ     | ਮਕਸਦ                                                                                                                                         |
| -------------------------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(ਅਨਸੈੱਟ)_ | ਅਨਸੈੱਟ ਸੈਟਿੰਗਾਂ ਟੌਗਲ ਦੀ ਪਾਲਣਾ ਕਰਦਾ ਹੈ; `1/true/on/yes` ਚਾਲੂ ਕਰਦਾ ਹੈ ਅਤੇ `0/false/off/no` ਬੰਦ ਕਰਦਾ ਹੈ (ਭਾਵੇਂ ਸੈਟਿੰਗਾਂ ਇਸਨੂੰ ਸਮਰੱਥ ਕਰਦੀਆਂ ਹਨ)। |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`    | ਡਿਫੌਲਟ models.dev ਸਿੰਕ ਅੰਤਰਾਲ ਸਕਿੰਟਾਂ ਵਿੱਚ (ਰੋਜ਼ਾਨਾ)।                                                                                        |

`PRICING_SYNC_SOURCES` ਕਰਦਾ ਹੈ**ਨਹੀਂ** models.dev ਨੂੰ ਸਮਰੱਥ ਕਰੋ; ਇਹ ਸਿਰਫ਼ LiteLLM ਸਿੰਕ ਨੂੰ ਕੰਟਰੋਲ ਕਰਦਾ ਹੈ। ਯੂਜ਼ਰ ਓਵਰਰਾਈਡ ਨੂੰ ਮਿਟਾਉਣ ਨਾਲ ਸਿੰਕ ਕੀਤੇ ਨੇਮਸਪੇਸ ਨੂੰ ਸਾਫ਼ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ; ਅਗਲੀ ਉਪਲਬਧ ਕੀਮਤ ਪਰਤ ਪ੍ਰਭਾਵੀ ਹੋ ਜਾਂਦੀ ਹੈ। ਬਿਨਾਂ ਕੀਮਤ ਵਾਲੇ ਮਾਡਲ ਲਈ, ਮੈਨੂਅਲ ਓਵਰਰਾਈਡ ਜੋੜਨ ਤੋਂ ਪਹਿਲਾਂ ਸਿੰਕ ਸੈਟਿੰਗਾਂ ਅਤੇ `sourceMap` ਦੋਵਾਂ ਦੀ ਜਾਂਚ ਕਰੋ।

### ਲਾਗਤ ਫਾਰਮੂਲਾ

[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`) ਵਿੱਚ ਪ੍ਰਤੀ ਬੇਨਤੀ ਟੋਕਨ ਗਿਣਤੀ ਅਤੇ ਪ੍ਰਤੀ-ਮਿਲੀਅਨ-ਟੋਕਨ ਦਰਾਂ ਤੋਂ ਲਾਗਤ ਦੀ ਗਣਨਾ ਕੀਤੀ ਜਾਂਦੀ ਹੈ:

- **ਇਨਪੁਟ ਟੋਕਨ** (ਘਟਾਓ ਕੈਸ਼ ਰੀਡਜ਼ ਅਤੇ ਕੈਸ਼-ਰਚਨਾ ਟੋਕਨ) × `input` ਦਰ।
- **ਕੈਸ਼-ਰੀਡ ਟੋਕਨ** × `cached` ਦਰ (ਇਨਪੁਟ ਦਰ 'ਤੇ ਵਾਪਸ ਆਉਂਦੀ ਹੈ)।
- **ਕੈਸ਼-ਰਚਨਾ ਟੋਕਨ** × `cache_creation` ਦਰ (ਇਨਪੁਟ ਦਰ 'ਤੇ ਵਾਪਸ ਆਉਂਦੀ ਹੈ)।
- **ਆਉਟਪੁੱਟ ਟੋਕਨ** × `output` ਦਰ।
- **ਤਰਕਸ਼ੀਲ ਟੋਕਨ** × `reasoning` ਦਰ (ਆਉਟਪੁੱਟ ਦਰ 'ਤੇ ਵਾਪਸ ਆਉਂਦੀ ਹੈ)।

ਸਾਰੀਆਂ ਦਰਾਂ ਨੂੰ USD ਪ੍ਰਤੀ 1,000,000 ਟੋਕਨਾਂ ਵਜੋਂ ਸਮਝਿਆ ਜਾਂਦਾ ਹੈ। ਇੱਕ Codex "ਤੇਜ਼"/"ਪ੍ਰਾਥਮਿਕਤਾ" ਜਾਂ "ਫਲੈਕਸ" ਸੇਵਾ ਟੀਅਰ ਇੱਕ ਲਾਗਤ ਗੁਣਕ (`getCodexFastCostMultiplier`) ਨੂੰ ਲਾਗੂ ਕਰਦਾ ਹੈ — ਜਿਵੇਂ ਕਿ ਫਲੈਕਸ ਨੂੰ 50% ਟੋਕਨ ਛੂਟ 'ਤੇ ਬਿਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਇਸ ਤਰ੍ਹਾਂ ਸਾਹਮਣੇ ਆਉਂਦਾ ਹੈ**ਫਲੈਕਸ ਬੱਚਤ** ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ.

ਮਾਡਲ ਦੇ ਨਾਮ ਪਹਿਲਾਂ ਸਧਾਰਣ ਕੀਤੇ ਜਾਂਦੇ ਹਨ (ਪ੍ਰਦਾਤਾ-ਪਾਥ ਅਗੇਤਰ ਜਿਵੇਂ ਕਿ `openai/` ਜਾਂ `accounts/fireworks/models/` ਹਟਾ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ) ਇਸਲਈ ਇਤਿਹਾਸਕ ਕਤਾਰਾਂ ਅਜੇ ਵੀ ਕੀਮਤ ਨਾਲ ਮੇਲ ਖਾਂਦੀਆਂ ਹਨ।

### ਖਰਚ ਕਿਵੇਂ ਰਿਕਾਰਡ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

- ਪ੍ਰਤੀ ਬੇਨਤੀ ਲਾਗਤ ਦੀ ਗਣਨਾ ਬੇਨਤੀ ਪੂਰੀ ਹੋਣ 'ਤੇ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। ਸ਼ੇਅਰਡ-ਕੋਟੇ ਦੀ ਖਪਤ [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) ਰਾਹੀਂ ਅਗਲੀ ਇਵੈਂਟ-ਲੂਪ ਟਿਕ 'ਤੇ ਨਿਯਤ ਕੀਤੀ ਗਈ ਹੈ।
- API-ਕੁੰਜੀ ਖਰਚ ਨੂੰ [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (ਡਿਫੌਲਟ 60 ਫਲੱਸ਼ ਅੰਤਰਾਲ, 1,000-ਐਂਟਰੀ ਬਫਰ) ਦੁਆਰਾ ਬੈਚਾਂ ਵਿੱਚ ਬਫਰ ਅਤੇ ਫਲੱਸ਼ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਇਸ ਰਾਹੀਂ ਟਿਊਨੇਬਲ:

  | Env var                             | ਡਿਫਾਲਟ  | ਮਕਸਦ                                  |
  | ----------------------------------- | ------- | ------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | ਮਿਲੀਸਕਿੰਟ ਵਿੱਚ ਫਲੱਸ਼ ਅੰਤਰਾਲ।          |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | ਫਲੱਸ਼ ਤੋਂ ਪਹਿਲਾਂ ਅਧਿਕਤਮ ਬਫਰਡ ਐਂਟਰੀਆਂ। |

ਲਾਗਤਾਂ ਇੱਕ ਸਹੀ ਪ੍ਰਦਾਤਾ-ਰਿਪੋਰਟ ਕੀਤੇ ਚਾਰਜ (`provider_cost_usd`), ਫਿਰ ਇੱਕ ਕੈਟਾਲਾਗ-ਕੀਮਤ ਬੇਨਤੀ ਸਨੈਪਸ਼ਾਟ (`calculated_cost_usd`), ਫਿਰ ਮੌਜੂਦਾ ਕੈਟਾਲਾਗ ਤੋਂ ਟੋਕਨ ਰੀਪ੍ਰਾਈਸਿੰਗ ਨੂੰ ਤਰਜੀਹ ਦਿੰਦੀਆਂ ਹਨ। ਸਟੋਰ ਕੀਤੀਆਂ ਲਾਗਤਾਂ ਨੂੰ ਉਹਨਾਂ ਦੇ ਟੋਕਨ ਕਾਉਂਟਸ ਦੁਆਰਾ ਦੁਬਾਰਾ ਚਾਰਜ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਪੁਰਾਤਨ ਟੋਕਨ-ਸਿਰਫ ਕਤਾਰਾਂ ਅਜੇ ਵੀ ਬਦਲਦੀਆਂ ਹਨ ਜਦੋਂ ਉਹਨਾਂ ਦੀ ਕੈਟਾਲਾਗ ਕੀਮਤ ਬਦਲਦੀ ਹੈ।

### OCR ਅਤੇ ਏਮਬੈਡਿੰਗਸ

- ਸਫਲ `/v1/ocr` ਬੇਨਤੀਆਂ ਅੱਪਸਟ੍ਰੀਮ `usage_info.pages_processed` ਵਰਤੋਂ ਕਰਦੀਆਂ ਹਨ, ਨਾ ਕਿ ਬੇਨਤੀ ਕੀਤੀ ਪੇਜ ਰੇਂਜ ਜਾਂ ਵਾਪਸ ਕੀਤੇ ਪੇਜ ਆਬਜੈਕਟ ਦੀ ਸੰਖਿਆ। ਅੰਦਾਜ਼ਾ ਪੰਨੇ × `ocr_cost_per_page` (ਸੰਪੂਰਨ USD/page,**ਨਹੀਂ** USD/million)।
- ਦਸਤਾਵੇਜ਼ ਜਾਂ ਬਾਉਂਡਿੰਗ-ਬਾਕਸ ਐਨੋਟੇਸ਼ਨ ਵਾਲੀਆਂ ਬੇਨਤੀਆਂ ਲਈ ਇੱਕ ਵੱਖਰੇ `ocr_cost_per_annotated_page` ਟੈਰਿਫ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ। ਇਸ ਤੋਂ ਬਿਨਾਂ, ਲਾਗਤ ਅਣਜਾਣ ਰਹਿੰਦੀ ਹੈ; ਸਧਾਰਣ OCR ਟੈਰਿਫ ਨੂੰ ਚੁੱਪਚਾਪ ਬਦਲਿਆ ਨਹੀਂ ਜਾਂਦਾ ਹੈ।
- LiteLLM ਸਿੰਕ ਇਸਦੇ ਅੱਪਸਟ੍ਰੀਮ `annotation_cost_per_page` ਫੀਲਡ ਨੂੰ `ocr_cost_per_annotated_page` ਵਿੱਚ ਮੈਪ ਕਰਦਾ ਹੈ, ਪੂਰਨ USD/page ਮੁੱਲ ਅਤੇ ਸਿਰਫ਼ ਐਨੋਟੇਸ਼ਨ-ਐਂਟਰੀਆਂ ਨੂੰ ਬਰਕਰਾਰ ਰੱਖਦਾ ਹੈ, ਜਿਸ ਵਿੱਚ ਸਪੱਸ਼ਟ ਜ਼ੀਰੋ ਵੀ ਸ਼ਾਮਲ ਹੈ। ਇੱਕ ਸਪਲਾਈ ਕੀਤਾ ਕੈਨੋਨੀਕਲ ਖੇਤਰ ਤਰਜੀਹ ਲੈਂਦਾ ਹੈ; ਅਵੈਧ ਉਪਨਾਮ ਮੁੱਲਾਂ ਨੂੰ ਅਣਡਿੱਠ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਉਪਭੋਗਤਾ ਕੀਮਤ ਓਵਰਰਾਈਡ ਆਪਣੀ ਆਮ ਤਰਜੀਹ ਨੂੰ ਬਰਕਰਾਰ ਰੱਖਦੇ ਹਨ। [LiteLLM ਦੀਆਂ OCR ਕੀਮਤ ਕੁੰਜੀਆਂ](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) ਦੇਖੋ।
- OCR ਵਰਤੋਂ ਪੰਨੇ ਦੀ ਗਿਣਤੀ, ਯੂਨਿਟ ਕੀਮਤ, ਗਣਿਤ USD ਲਾਗਤ, API ਕੁੰਜੀ ਅਤੇ ਚੁਣੇ ਹੋਏ ਕਨੈਕਸ਼ਨ ਨੂੰ ਸਟੋਰ ਕਰਦੀ ਹੈ। ਪੰਨਿਆਂ ਨੂੰ ਕਦੇ ਵੀ ਟੋਕਨ ਵਜੋਂ ਨਹੀਂ ਦਰਸਾਇਆ ਜਾਂਦਾ ਹੈ। ਕਾਲ ਲੌਗਸ ਵਿੱਚ ਬਿਲਿੰਗ ਮੈਟਾਡੇਟਾ ਸ਼ਾਮਲ ਹੁੰਦਾ ਹੈ, ਨਾ ਕਿ ਦਸਤਾਵੇਜ਼ URLs, PDF ਬਾਈਟਸ ਜਾਂ ਐਕਸਟਰੈਕਟ ਕੀਤਾ ਟੈਕਸਟ।
- ਸਫਲ `/v1/embeddings` ਬੇਨਤੀਆਂ ਪ੍ਰਤੀ ਭੌਤਿਕ ਬੈਚ ਵਿੱਚ ਇੱਕ ਵਰਤੋਂ ਕਤਾਰ ਨੂੰ ਰਿਕਾਰਡ ਕਰਦੀ ਹੈ, ਜਿਸ ਵਿੱਚ ਇੱਕੋ ਮਿਲੀਸਕਿੰਟ ਵਿੱਚ ਪੂਰੇ ਕੀਤੇ ਗਏ ਵੱਖਰੇ ਬੈਚ ਸ਼ਾਮਲ ਹਨ। ਪ੍ਰਦਾਤਾ-ਰਿਪੋਰਟ ਕੀਤੇ ਖਰਚੇ ਟੋਕਨ ਅਨੁਮਾਨਾਂ ਨਾਲੋਂ ਪਹਿਲ ਦਿੰਦੇ ਹਨ; ਕੰਬੋ ਰੈਪਰ ਚਾਰਜ ਨਹੀਂ ਜੋੜਦੇ ਹਨ।
- ਵਰਤੋਂ ਦਾ ਇਤਿਹਾਸ, ਲਾਗਤਾਂ ਦੇ ਵਿਸ਼ਲੇਸ਼ਣ, provider/account ਵਿੰਡੋਜ਼, API-ਕੁੰਜੀ ਖਰਚ ਸੀਮਾਵਾਂ, ਬੇਨਤੀ-ਲਾਗਤ ਬਹੀ ਅਤੇ ਰੋਜ਼ਾਨਾ ਵਰਤੋਂ ਦੇ ਰੋਲਅੱਪ ਵਿੱਚ ਇਹ ਖਰਚੇ ਸ਼ਾਮਲ ਹਨ। ਨੋ-ਲੌਗ ਕੁੰਜੀਆਂ ਸਰੋਤ ਟੈਕਸਟ ਨੂੰ ਬਰਕਰਾਰ ਰੱਖੇ ਬਿਨਾਂ ਸੰਖਿਆਤਮਕ ਲੇਖਾਕਾਰੀ ਨੂੰ ਬਰਕਰਾਰ ਰੱਖਦੀਆਂ ਹਨ।
- ਗੁੰਮ ਵਰਤੋਂ ਜਾਂ ਟੈਰਿਫ ਹਨ **ਅਗਿਆਤ** , ਮੁਫ਼ਤ ਨਹੀਂ: ਜਵਾਬ-ਕੀਮਤ ਸਿਰਲੇਖ ਨੂੰ ਛੱਡ ਦਿੱਤਾ ਗਿਆ ਹੈ, ਅਤੇ ਮੌਜੂਦਾ ਗੈਰ-ਕੀਮਤ-ਵਰਤੋਂ ਨੀਤੀ ਸੀਮਤ API ਕੁੰਜੀਆਂ 'ਤੇ ਲਾਗੂ ਹੁੰਦੀ ਹੈ। ਸਪੱਸ਼ਟ ਤੌਰ 'ਤੇ ਕੌਂਫਿਗਰ ਕੀਤੀਆਂ ਜ਼ੀਰੋ ਦਰਾਂ ਵੈਧ ਜ਼ੀਰੋ-ਕੀਮਤ ਵਰਤੋਂ ਰਹਿੰਦੀਆਂ ਹਨ।

ਇਹ ਸਿਰਫ਼ ਫਾਰਵਰਡ ਅਕਾਊਂਟਿੰਗ ਹੈ। ਪੁਰਾਣੀ OCR/embedding ਕਾਲਾਂ ਜਿਨ੍ਹਾਂ ਨੇ ਕਦੇ ਵੀ ਵਰਤੋਂ ਇਤਿਹਾਸ ਨਹੀਂ ਲਿਖਿਆ, ਇਸ ਮਾਈਗ੍ਰੇਸ਼ਨ ਤੋਂ ਪੁਨਰਗਠਨ ਨਹੀਂ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ। ਕੈਟਾਲਾਗ ਅਨੁਮਾਨ USD ਅੰਦਾਜ਼ੇ ਹਨ, ਕੋਈ ਇਨਵੌਇਸ ਨਹੀਂ, ਅਤੇ ਮੁਦਰਾ ਪਰਿਵਰਤਨ, ਟੈਕਸ ਜਾਂ ਛੋਟ ਸ਼ਾਮਲ ਨਹੀਂ ਕਰਦੇ ਹਨ।

## ਡੈਸ਼ਬੋਰਡ: ਲਾਗਤਾਂ ਪੰਨਾ

**ਲਾਗਤਾਂ** ਪੰਨਾ `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`) 'ਤੇ ਮੌਜੂਦ ਹੈ।
ਇਸਦਾ ਮੁੱਖ ਦ੍ਰਿਸ਼ **ਲਾਗਤ ਸੰਖੇਪ** ਟੈਬ
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`) ਹੈ,
ਜੋ `GET /api/usage/analytics` ਤੋਂ ਸਾਰਾ ਡਾਟਾ ਲੋਡ ਕਰਦੀ ਹੈ।

ਇਹ ਕੀ ਦਿਖਾਉਂਦਾ ਹੈ:

- **ਖਰਚ ਟਾਈਲਾਂ** — _ਅੱਜ (1d)_, _7d_, _30d_, ਅਤੇ ਚੁਣੀ ਹੋਈ
  ਮਿਆਦ ਲਈ ਅਨੁਮਾਨਿਤ ਖਰਚ। ਮਿਆਦ ਚੋਣਕਾਰ: `7d`, `30d`, `90d`, `all`।
- **ਮੁੱਖ ਮੈਟ੍ਰਿਕਸ** — ਮਿਆਦ ਅੰਦਰ ਬੇਨਤੀਆਂ, ਸਰਗਰਮ ਪ੍ਰਦਾਤਾ, ਸਰਗਰਮ ਮਾਡਲ, ਪ੍ਰਤੀ
  ਬੇਨਤੀ ਔਸਤ ਲਾਗਤ।
- **ਲਾਗਤ ਐਕਸਪਲੋਰਰ** — ਇੱਕ ਕ੍ਰਮਬੱਧ/ਫਿਲਟਰ ਕਰਨਯੋਗ ਸਾਰਣੀ, ਜਿਸਨੂੰ **ਪ੍ਰਦਾਤਾ**, **ਮਾਡਲ**,
  **API ਕੁੰਜੀ**, **ਖਾਤਾ**, ਜਾਂ **ਸੇਵਾ ਟੀਅਰ** ਮੁਤਾਬਕ ਸਮੂਹਬੱਧ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਅਤੇ ਜਿਸ ਵਿੱਚ ਲਾਗਤ, ਬੇਨਤੀਆਂ, ਟੋਕਨ, ਔਸਤ
  ਲਾਗਤ/ਬੇਨਤੀ ਅਤੇ ਕੁੱਲ ਹਿੱਸੇਦਾਰੀ % ਸ਼ਾਮਲ ਹਨ।
- **ਟੋਕਨ ਵਰਤੋਂ** — ਕੁੱਲ / ਇਨਪੁੱਟ / ਆਉਟਪੁੱਟ ਟੋਕਨ ਅਤੇ ਇਨਪੁੱਟ:ਆਉਟਪੁੱਟ ਅਨੁਪਾਤ।
- **ਰੂਟਿੰਗ ਕੁਸ਼ਲਤਾ** — ਫਾਲਬੈਕ ਗਿਣਤੀ, ਫਾਲਬੈਕ ਦਰ ਅਤੇ ਬੇਨਤੀ ਕੀਤੇ ਮਾਡਲ ਦੀ ਕਵਰੇਜ।
- **ਮਾਸਿਕ ਪੂਰਵ-ਅਨੁਮਾਨ** — ਹਾਲੀਆ ਰੋਜ਼ਾਨਾ ਔਸਤ ਤੋਂ ਮਹੀਨੇ ਦੇ ਅੰਤ ਤੱਕ ਦੇ ਖਰਚ ਦਾ ਅਨੁਮਾਨ ਲਗਾਉਂਦਾ ਹੈ।
- **ਮਿਆਦ ਦੀ ਤੁਲਨਾ** — ਮਿਆਦ ਦੇ ਪਹਿਲੇ ਅਤੇ ਦੂਜੇ ਅੱਧ ਵਿਚਕਾਰ % ਤਬਦੀਲੀ।
- **ਚਾਰਟ** — ਰੋਜ਼ਾਨਾ ਲਾਗਤ ਰੁਝਾਨ, ਪ੍ਰਦਾਤਾ ਹਿੱਸੇਦਾਰੀ (ਪਾਈ), ਸਿਖਰਲੇ ਪ੍ਰਦਾਤਾ, ਸਿਖਰਲੇ ਮਾਡਲ, API ਕੁੰਜੀ
  ਮੁਤਾਬਕ ਲਾਗਤ, ਖਾਤੇ ਮੁਤਾਬਕ ਲਾਗਤ, ਹਫ਼ਤਾਵਾਰੀ ਵਰਤੋਂ ਪੈਟਰਨ ਅਤੇ ਗਤੀਵਿਧੀ ਹੀਟਮੈਪ।
- **ਨਿਰਯਾਤ** — ਮੌਜੂਦਾ ਮਿਆਦ ਨੂੰ **CSV** ਜਾਂ **JSON** ਵਜੋਂ ਡਾਊਨਲੋਡ ਕਰੋ (ਬਟਨ
  ਉਦੋਂ ਦਿਖਾਈ ਦਿੰਦੇ ਹਨ ਜਦੋਂ ਗੈਰ-ਸਿਫ਼ਰ ਲਾਗਤ ਡਾਟਾ ਮੌਜੂਦ ਹੋਵੇ)।

ਜਦੋਂ ਕੋਈ ਕੀਮਤਬੱਧ ਟ੍ਰੈਫਿਕ ਨਹੀਂ ਹੁੰਦਾ, ਤਾਂ ਕਤਾਰਾਂ `$0` ਦੀ ਬਜਾਏ "ਪੁਰਾਤਨ / ਮੁਫ਼ਤ" ਲੇਬਲ ਵਜੋਂ ਰੈਂਡਰ ਹੁੰਦੀਆਂ ਹਨ,
ਜੋ ਬੱਚਤ-ਟਰੈਕਰ ਮਾਡਲ ਨੂੰ ਦਰਸਾਉਂਦਾ ਹੈ।

### ਲਾਗਤਾਂ ਨਾਲ ਸੰਬੰਧਿਤ ਉਪ-ਪੰਨੇ

ਲਾਗਤਾਂ ਖੇਤਰ ਵਿੱਚ ਇਹ ਵੀ ਸ਼ਾਮਲ ਹਨ (ਸਾਰੇ `/dashboard/costs/` ਦੇ ਅਧੀਨ):

- **ਕੀਮਤ ਨਿਰਧਾਰਨ** (`/dashboard/costs/pricing`) — ਪ੍ਰਤੀ-ਮਾਡਲ ਕੀਮਤਾਂ ਵੇਖੋ ਅਤੇ ਓਵਰਰਾਈਡ ਕਰੋ (ਸਾਂਝੀ
  ਕੀਮਤ ਨਿਰਧਾਰਨ ਟੈਬ ਨੂੰ ਰੈਂਡਰ ਕਰਦਾ ਹੈ)।
- **ਬਜਟ** (`/dashboard/costs/budget`) — ਪ੍ਰਤੀ-ਸਕੋਪ ਖਰਚ ਸੀਮਾਵਾਂ ਸੈੱਟ ਕਰੋ (ਸਾਂਝੀ
  ਬਜਟ ਟੈਬ ਨੂੰ ਰੈਂਡਰ ਕਰਦਾ ਹੈ)।
- **ਕੋਟਾ ਹਿੱਸੇਦਾਰੀ** (`/dashboard/costs/quota-share`) — ਸਾਂਝੇ-ਕੋਟੇ ਦੇ ਪੂਲ ਅਤੇ ਬਰਨ-ਰੇਟ
  ਦ੍ਰਿਸ਼।

## API ਐਂਡਪੌਇੰਟ

ਜੇ ਹੋਰ ਨਾ ਦੱਸਿਆ ਗਿਆ ਹੋਵੇ, ਤਾਂ ਇਨ੍ਹਾਂ ਸਾਰਿਆਂ ਲਈ ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣੀਕਰਨ (loopback/JWT, `requireManagementAuth` ਰਾਹੀਂ)
ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ।

### ਵਰਤੋਂ ਅਤੇ ਲਾਗਤ ਵਿਸ਼ਲੇਸ਼ਣ

| ਵਿਧੀ  | ਐਂਡਪੌਇੰਟ                 | ਉਦੇਸ਼                                                                                                                                                       |
| ----- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | ਸੰਪੂਰਨ ਲਾਗਤ/ਵਰਤੋਂ ਵਿਸ਼ਲੇਸ਼ਣ: ਸੰਖੇਪ, ਰੋਜ਼ਾਨਾ ਰੁਝਾਨ, ਪ੍ਰਦਾਤਾ/ਮਾਡਲ/API ਕੁੰਜੀ/ਖਾਤਾ/ਟੀਅਰ ਮੁਤਾਬਕ। ਕੁਐਰੀ: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`। |
| `GET` | `/api/usage/utilization` | ਸਮੇਂ ਦੇ ਨਾਲ ਪ੍ਰਤੀ-ਪ੍ਰਦਾਤਾ ਕੋਟਾ ਵਰਤੋਂ। ਕੁਐਰੀ: `range` (`1h`/`24h`/`7d`/`30d`), `provider`।                                                                   |
| `GET` | `/api/usage/history`     | ਕੱਚੀਆਂ ਵਰਤੋਂ ਇਤਿਹਾਸ ਕਤਾਰਾਂ।                                                                                                                                 |
| `GET` | `/api/usage/call-logs`   | ਪ੍ਰਤੀ-ਬੇਨਤੀ ਕਾਲ ਲੌਗ (ਮਾਡਲ, ਟੋਕਨ, ਲਾਗਤ, ਲੇਟੈਂਸੀ, ਸਥਿਤੀ)।                                                                                                     |
| `GET` | `/api/usage/quota`       | ਪ੍ਰਦਾਤਾ ਕੋਟਾ ਸਥਿਤੀ।                                                                                                                                         |
| `GET` | `/api/usage/proxy-logs`  | ਪ੍ਰੌਕਸੀ ਬੇਨਤੀ ਲੌਗ।                                                                                                                                          |

### ਬਜਟ

| ਵਿਧੀ   | ਐਂਡਪੌਇੰਟ                 | ਉਦੇਸ਼                                                                         |
| ------ | ------------------------ | ----------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | ਇੱਕ API ਕੁੰਜੀ ਲਈ ਲਾਗਤ ਸੰਖੇਪ + ਬਜਟ ਜਾਂਚ (`apiKeyId` ਕੁਐਰੀ ਪੈਰਾਮੀਟਰ ਲਾਜ਼ਮੀ ਹੈ)। |
| `POST` | `/api/usage/budget`      | ਇੱਕ API ਕੁੰਜੀ ਲਈ ਰੋਜ਼ਾਨਾ/ਹਫ਼ਤਾਵਾਰੀ/ਮਾਸਿਕ USD ਸੀਮਾਵਾਂ + ਚੇਤਾਵਨੀ ਹੱਦ ਸੈੱਟ ਕਰੋ।  |
| `GET`  | `/api/usage/budget/bulk` | API ਕੁੰਜੀਆਂ ਲਈ ਇਕੱਠੇ ਬਜਟ ਸੰਖੇਪ।                                               |

> ਬਜਟ API ਪ੍ਰਤੀ **API ਕੁੰਜੀ** (`apiKeyId`) ਦੇ ਦਾਇਰੇ ਵਿੱਚ ਹੈ। ਇਸ ਵੱਲੋਂ ਵਾਪਸ ਕੀਤੀਆਂ ਸੀਮਾਵਾਂ
> `GET /api/usage/budget` ਵਿੱਚ `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> ਇੱਕ `warningThreshold`, ਅਤੇ ਚੱਲ ਰਹੇ ਕੁੱਲ (`totalCostToday`, `totalCostMonth`, …) ਸ਼ਾਮਲ ਹਨ।

### ਕੀਮਤ ਨਿਰਧਾਰਨ

| ਵਿਧੀ     | ਐਂਡਪੌਇੰਟ                | ਉਦੇਸ਼                                                                                                                                   |
| -------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | ਚਾਰ ਪਰਤਾਂ ਦੀ ਮਿਲੀ ਹੋਈ ਕੀਮਤ (ਵਰਤੋਂਕਾਰ, models.dev, LiteLLM, ਡਿਫ਼ਾਲਟ)। `?includeSources=1` ਇਹ `pricing` + `sourceMap` ਵਾਪਸ ਕਰਦਾ ਹੈ।       |

| `DELETE` | `/api/pricing`          | ਵਰਤੋਂਕਾਰ ਦੇ ਕੀਮਤ ਓਵਰਰਾਈਡ ਹਟਾਓ; ਚਾਹੋ ਤਾਂ `?provider=&model=` ਨਾਲ ਦਾਇਰਾ ਸੀਮਿਤ ਕਰੋ। ਸਮਕਾਲੀ ਦਰਾਂ ਜਾਂ ਅੰਦਰਲੇ ਡਿਫ਼ਾਲਟ ਬਦਲ ਵਜੋਂ ਬਚੇ ਰਹਿੰਦੇ ਹਨ। |
| `GET`    | `/api/pricing/defaults` | ਪ੍ਰਤੀ-1M ਮੂਲ ਫਾਲਬੈਕ ਦਰਾਂ ਦਿਖਾਓ।                                                                                                         |
| `GET`    | `/api/pricing/models`   | ਮਾਡਲ ਮੁਤਾਬਕ ਕੁੰਜੀਬੱਧ ਕੀਮਤ ਨਿਰਧਾਰਨ।                                                                                                      |
| `POST`   | `/api/pricing/sync`     | ਬਾਹਰੀ ਸਰੋਤਾਂ (LiteLLM) ਤੋਂ ਹੱਥੀਂ ਸਿੰਕ ਸ਼ੁਰੂ ਕਰੋ।                                                                                        |
| `GET`    | `/api/pricing/sync`     | ਮੌਜੂਦਾ ਸਿੰਕ ਸਥਿਤੀ।                                                                                                                      |
| `DELETE` | `/api/pricing/sync`     | ਸਿਰਫ਼ LiteLLM ਤੋਂ ਸਮਕਾਲੀ ਕੀਤੀਆਂ ਕੀਮਤਾਂ (`pricing_synced`) ਸਾਫ਼ ਕਰੋ; models.dev ਡਾਟਾ ਵੱਖਰਾ ਹੈ।                                           |

## CLI

OmniRoute ਦਾ CLI ਲਾਗਤ, ਵਰਤੋਂ ਅਤੇ ਕੀਮਤ-ਨਿਰਧਾਰਨ ਕਮਾਂਡਾਂ ਉਪਲਬਧ ਕਰਵਾਉਂਦਾ ਹੈ (ਜੋ
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) ਵਿੱਚ ਰਜਿਸਟਰ ਕੀਤੀਆਂ ਗਈਆਂ ਹਨ)।

### `omniroute cost`

`/api/usage/analytics` ਤੋਂ ਇਕੱਤਰ ਕੀਤੀ ਲਾਗਤ ਰਿਪੋਰਟ।

```bash
omniroute cost                          # ਪਿਛਲੇ 30d, ਪ੍ਰਦਾਤਾ ਅਨੁਸਾਰ ਸਮੂਹਬੱਧ
omniroute cost --period 7d              # ਪਿਛਲੇ 7 ਦਿਨ
omniroute cost --group-by model         # provider | model | combo | api-key | day ਅਨੁਸਾਰ ਸਮੂਹਬੱਧ ਕਰੋ
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ਕਾਲਮ: ਸਮੂਹ, ਬੇਨਤੀਆਂ, ਇਨਪੁੱਟ/ਆਉਟਪੁੱਟ ਟੋਕਨ, ਲਾਗਤ (USD), ਅਤੇ ਕੁੱਲ ਦਾ ਪ੍ਰਤੀਸ਼ਤ। ਅੰਤ ਵਿੱਚ
ਸਮੁੱਚੇ ਕੁੱਲ ਦੀ ਇੱਕ ਲਾਈਨ ਦਿਖਾਈ ਜਾਂਦੀ ਹੈ (`--quiet` ਜਾਂ `--output json` ਨਾਲ ਇਸ ਨੂੰ ਲੁਕਾਇਆ ਜਾਂਦਾ ਹੈ)।

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ਪ੍ਰਤੀ-ਪ੍ਰਦਾਤਾ ਲਾਗਤ ਸੰਖੇਪ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ਬਜਟ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`, `GET /api/pricing/defaults` ਤੋਂ ਡਾਟਾ ਪੜ੍ਹਦਾ ਹੈ। ਇਸ ਦੀ ਬਜਾਏ ਵੱਖ-ਵੱਖ ਮਾਡਲਾਂ
> ਦੀਆਂ ਕੀਮਤਾਂ ਸੋਧਣ ਲਈ, **ਕੀਮਤ-ਨਿਰਧਾਰਨ** ਡੈਸ਼ਬੋਰਡ ਪੰਨਾ ਜਾਂ `PATCH /api/pricing` ਵਰਤੋ।

## ਸਮੱਸਿਆ-ਨਿਵਾਰਨ

- **ਸਾਰੀਆਂ ਲਾਗਤਾਂ $0 / "ਪੁਰਾਤਨ / ਮੁਫ਼ਤ" ਦਿਖਾਉਂਦੀਆਂ ਹਨ।** ਵਰਤੋਂ ਅਧੀਨ ਮਾਡਲਾਂ ਲਈ ਕੋਈ ਕੀਮਤ ਐਂਟਰੀ ਨਹੀਂ ਹੈ।
  ਬਾਹਰੀ ਸਿੰਕ ਚਾਲੂ ਕਰੋ (`PRICING_SYNC_ENABLED=true`) ਅਤੇ `omniroute pricing sync` ਚਲਾਓ, ਜਾਂ
  ਕੀਮਤ-ਨਿਰਧਾਰਨ ਪੰਨੇ / `PATCH /api/pricing` ਰਾਹੀਂ ਕੀਮਤਾਂ ਹੱਥੀਂ ਸੈੱਟ ਕਰੋ।
- **ਕਿਸੇ ਪੁਰਾਣੇ ਮਾਡਲ ਦੀ ਕੀਮਤ ਗਲਤ ਹੈ।** ਕੀਮਤ ਠੀਕ ਕਰੋ (ਓਵਰਰਾਈਡ ਜਾਂ ਮੁੜ-ਸਿੰਕ ਕਰੋ)—ਹਰ ਵਿਸ਼ਲੇਸ਼ਣ ਰੀਡ ਸਮੇਂ
  ਟੋਕਨ ਗਿਣਤੀਆਂ ਤੋਂ ਲਾਗਤ ਮੁੜ ਗਿਣੀ ਜਾਂਦੀ ਹੈ, ਇਸ ਲਈ ਅਨੁਮਾਨ ਪਿਛਲੀ ਮਿਆਦ ਲਈ ਵੀ ਅੱਪਡੇਟ ਹੋ ਜਾਂਦੇ ਹਨ।
- **ਖਰਚ ਅਸਲ ਸਮੇਂ ਤੋਂ ਪਿੱਛੇ ਰਹਿੰਦਾ ਹੈ।** ਪ੍ਰਤੀ-ਕੁੰਜੀ ਖਰਚ ਨੂੰ ਬੈਚਾਂ ਵਿੱਚ ਸੰਸਾਧਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ; ਜੇ ਤੁਹਾਨੂੰ
  ਵਧੇਰੇ ਤਾਜ਼ਾ ਅੰਕੜਿਆਂ ਦੀ ਲੋੜ ਹੈ ਤਾਂ `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ਘਟਾਓ।
