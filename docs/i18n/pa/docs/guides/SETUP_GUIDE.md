## ਢੰਗ ਇੰਸਟਾਲ ਕਰੋ

### npm (ਸਿਫਾਰਸ਼ੀ)

```bash
npm install -g omniroute
omniroute
```

ਡੈਸ਼ਬੋਰਡ `http://localhost:20128` 'ਤੇ ਖੁੱਲ੍ਹਦਾ ਹੈ ਅਤੇ API ਬੇਸ URL `http://localhost:20128/v1` ਹੈ।

> **npm ਉਪਭੋਗਤਾ:** ਜੇਕਰ npm ਚੇਤਾਵਨੀ ਦਿੰਦਾ ਹੈ ਕਿ ਇੰਸਟਾਲ ਸਕ੍ਰਿਪਟਾਂ ਨੂੰ ਬਲੌਕ ਕੀਤਾ ਗਿਆ ਸੀ (ਉਦਾਹਰਨ ਲਈ, `omniroute`, `better-sqlite3`), [ਟ੍ਰਬਲਸ਼ੂਟਿੰਗ — npm install-scripts blocked](./TROUBLESHOOTING.md#npm-install-scripts-blocked-warning-global-install) ਵੇਖੋ।

### pnpm

```bash
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core
omniroute
```

> **pnpm ਉਪਭੋਗਤਾ:** `better-sqlite3` ਅਤੇ `@swc/core` ਲਈ ਮੂਲ ਬਿਲਡ ਸਕ੍ਰਿਪਟਾਂ ਨੂੰ ਸਮਰੱਥ ਕਰਨ ਲਈ `--allow-build` ਫਲੈਗ ਦੀ ਲੋੜ ਹੈ। `pnpm approve-builds -g` ਕਮਾਂਡ pnpm v11 'ਤੇ ਗਲੋਬਲ ਸਥਾਪਨਾਵਾਂ ਲਈ ਸਮਰਥਿਤ ਨਹੀਂ ਹੈ।

### Arch Linux (AUR)

```bash
yay -S omniroute-bin
systemctl --user enable --now omniroute.service
```

[AUR ਪੈਕੇਜ](https://aur.archlinux.org/packages/omniroute-bin) OmniRoute ਸਥਾਪਿਤ ਕਰਦਾ ਹੈ ਅਤੇ ਇੱਕ systemd ਉਪਭੋਗਤਾ ਸੇਵਾ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ।

### ਸਰੋਤ ਤੋਂ

```bash
npm install
PORT=20128 DASHBOARD_PORT=20129 NEXT_PUBLIC_BASE_URL=http://localhost:20129 npm run dev
```

> **Windows ਨੋਟ:** ਮੂਲ ਰੂਪ ਵਿੱਚ, OmniRoute `%APPDATA%\omniroute` ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ ਜਦੋਂ ਵਿਰਾਸਤੀ `%USERPROFILE%\.omniroute` ਡਾਇਰੈਕਟਰੀ ਮੌਜੂਦ ਨਹੀਂ ਹੁੰਦੀ ਹੈ। ਇੱਕ ਵੱਖਰੀ ਡਾਟਾ-ਡਾਇਰੈਕਟਰੀ ਟਿਕਾਣਾ ਚੁਣਨ ਲਈ `DATA_DIR` ਸੈੱਟ ਕਰੋ।

> **ਨੋਟ:** `npm install` ਪਹਿਲੀ ਵਾਰ `.env.example` ਤੋਂ `.env` ਸਵੈ-ਤਿਆਰ ਕਰਦਾ ਹੈ। ਅਗਲੀਆਂ ਸਥਾਪਨਾਵਾਂ ਮੌਜੂਦਾ `.env` ਓਵਰਰਾਈਟ ਨਹੀਂ ਕਰਨਗੀਆਂ, ਇਸਲਈ ਕਸਟਮਾਈਜ਼ੇਸ਼ਨਾਂ ਨੂੰ ਸੁਰੱਖਿਅਤ ਰੱਖਿਆ ਜਾਂਦਾ ਹੈ। ਦੁਬਾਰਾ ਬੀਜਣ ਲਈ, ਦੁਬਾਰਾ ਚੱਲਣ ਤੋਂ ਪਹਿਲਾਂ `.env` ਮਿਟਾਓ।

### Docker

ਕੰਪੋਜ਼ ਪ੍ਰੋਫਾਈਲਾਂ ਅਤੇ ਕੈਡੀ HTTPS ਸਮੇਤ ਪੂਰੇ Docker ਸੈੱਟਅੱਪ ਲਈ [Docker ਗਾਈਡ](./DOCKER_GUIDE.md) ਦੇਖੋ।

### ਡੈਸਕਟਾਪ ਐਪ (Electron)

OmniRoute Electron 41 + ਇਲੈਕਟ੍ਰੋਨ-ਬਿਲਡਰ 26.10 'ਤੇ ਬਣਿਆ ਇੱਕ ਡੈਸਕਟਾਪ ਰੈਪਰ ਭੇਜਦਾ ਹੈ। ਉਪਲਬਧ ਸਕ੍ਰਿਪਟਾਂ (ਵਰਕਸਪੇਸ ਰੂਟ):

```bash
npm run electron:dev          # Run desktop with hot-reload
npm run electron:build        # Build for current OS (auto-detected)
npm run electron:build:win    # Windows installer (NSIS + portable)
npm run electron:build:mac    # macOS (dmg + zip, arm64+x64)
npm run electron:build:linux  # Linux (AppImage + deb + rpm)
npm run electron:smoke:packaged  # Smoke-test packaged build
```

ਡੈਸਕਟਾਪ ਇੰਸਟੌਲਰਾਂ ਦੀਆਂ ਰੀਲੀਜ਼ਾਂ GitHub ਰੀਲੀਜ਼ਾਂ ਨਾਲ ਜੁੜੀਆਂ ਹੋਈਆਂ ਹਨ। ਪੂਰੀ Electron ਡੂੰਘਾਈ-ਡਾਈਵ (ਸਾਈਨਿੰਗ, IPC ਬ੍ਰਿਜ, ਡਿਸਟ੍ਰੋਸ) ਲਈ, [`ELECTRON_GUIDE.md`](./ELECTRON_GUIDE.md) _(criado em fase posterior)_ ਦੇਖੋ।

### ਸਿਰ ਰਹਿਤ ਸਰਵਰ (CI/automation)

ਗੈਰ-ਹਾਜ਼ਰ ਸੈੱਟਅੱਪਾਂ ਲਈ (Docker, Kubernetes, CI), ਵਰਤੋ:

```bash
omniroute setup --non-interactive
omniroute providers test-batch
```

env vars (`INITIAL_PASSWORD`, `OMNIROUTE_WS_BRIDGE_SECRET`, ਆਦਿ) ਦੇ ਨਾਲ ਮਿਲਾ ਕੇ, ਇਹ ਤੁਹਾਨੂੰ ਇੱਕ OmniRoute ਉਦਾਹਰਣ ਨੂੰ ਪੂਰੀ ਤਰ੍ਹਾਂ ਸਕ੍ਰਿਪਟ ਕਰਨ ਯੋਗ ਬਣਾਉਣ ਦਿੰਦਾ ਹੈ।

### CLI ਵਿਕਲਪ

| ਹੁਕਮ                    | ਵਰਣਨ                                                                             |
| ----------------------- | -------------------------------------------------------------------------------- |
| `omniroute`             | ਸਰਵਰ ਸਟਾਰਟ ਕਰੋ (`PORT=20128`, API ਅਤੇ ਡੈਸ਼ਬੋਰਡ ਇੱਕੋ ਪੋਰਟ 'ਤੇ)                    |
| `omniroute setup`       | ਪਾਸਵਰਡ ਅਤੇ ਪਹਿਲੇ ਪ੍ਰਦਾਤਾ ਲਈ ਮਾਰਗਦਰਸ਼ਨ CLI ਆਨਬੋਰਡਿੰਗ                              |
| `omniroute doctor`      | ਸਰਵਰ ਨੂੰ ਸ਼ੁਰੂ ਕੀਤੇ ਬਿਨਾਂ ਸਥਾਨਕ ਸਿਹਤ ਜਾਂਚਾਂ ਚਲਾਓ                                 |
| `omniroute providers`   | CLI ਤੋਂ ਖੋਜੋ, ਸੂਚੀਬੱਧ ਕਰੋ, ਪ੍ਰਮਾਣਿਤ ਕਰੋ ਅਤੇ ਪ੍ਰਦਾਤਾਵਾਂ ਦੀ ਜਾਂਚ ਕਰੋ               |
| `omniroute config`      | CLI ਟੂਲ ਕੌਂਫਿਗਰੇਸ਼ਨ — ਸੂਚੀ, ਪ੍ਰਾਪਤ ਕਰੋ, ਸੈੱਟ ਕਰੋ, ਸੰਰਚਨਾ ਪ੍ਰਮਾਣਿਤ ਕਰੋ            |
| `omniroute status`      | ਔਫਲਾਈਨ ਸਥਿਤੀ ਡੈਸ਼ਬੋਰਡ — ਸੰਸਕਰਣ, DB, ਟੂਲ, ਸੰਰਚਨਾ                                  |
| `omniroute logs`        | API ਤੋਂ ਸਟ੍ਰੀਮ ਵਰਤੋਂ ਲੌਗਸ ( `--follow` ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ)                         |
| `omniroute update`      | OmniRoute ਅੱਪਡੇਟ ਦੀ ਜਾਂਚ ਕਰੋ ਜਾਂ ਲਾਗੂ ਕਰੋ                                        |
| `omniroute provider`    | ਪ੍ਰਦਾਤਾ ਕਨੈਕਸ਼ਨਾਂ ਦਾ ਪ੍ਰਬੰਧਨ ਕਰੋ — ਜੋੜੋ, ਸੂਚੀਬੱਧ ਕਰੋ, ਹਟਾਓ, ਟੈਸਟ ਕਰੋ, ਡਿਫੌਲਟ ਕਰੋ |
| `omniroute --port 3000` | canonical/API ਪੋਰਟ ਨੂੰ 3000 'ਤੇ ਸੈੱਟ ਕਰੋ                                         |
| `omniroute --mcp`       | MCP ਸਰਵਰ ਸ਼ੁਰੂ ਕਰੋ (stdio ਟ੍ਰਾਂਸਪੋਰਟ)                                            |
| `omniroute --no-open`   | ਬ੍ਰਾਊਜ਼ਰ ਨੂੰ ਆਟੋ-ਓਪਨ ਨਾ ਕਰੋ                                                      |
| `omniroute --help`      | ਮਦਦ ਦਿਖਾਓ                                                                        |

ਸਿਰਲੇਖ ਰਹਿਤ ਸੈੱਟਅੱਪ ਨੂੰ ਫਲੈਗ ਜਾਂ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ ਨਾਲ ਸਕ੍ਰਿਪਟ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ:

```bash
omniroute setup --non-interactive --password "$OMNIROUTE_PASSWORD"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY" --test-provider
```

ਡੈਸ਼ਬੋਰਡ ਖੋਲ੍ਹਣ ਤੋਂ ਬਿਨਾਂ ਸਥਾਨਕ ਡਾਇਗਨੌਸਟਿਕਸ ਚਲਾਓ:

```bash
omniroute doctor
omniroute doctor --json
omniroute doctor --no-liveness
```

ਡੈਸ਼ਬੋਰਡ ਖੋਲ੍ਹੇ ਬਿਨਾਂ SSH ਜਾਂ ਸਕ੍ਰਿਪਟਾਂ ਤੋਂ ਪ੍ਰਦਾਤਾਵਾਂ ਦਾ ਪ੍ਰਬੰਧਨ ਕਰੋ:

```bash
omniroute providers available
omniroute providers available --search openai
omniroute providers available --category api-key
omniroute providers list
omniroute providers test <id-or-name>
omniroute providers test-all
omniroute providers validate
```

## CLI ਟੂਲ ਸੰਰਚਨਾ

### 1) ਪ੍ਰਦਾਤਾਵਾਂ ਨੂੰ ਕਨੈਕਟ ਕਰੋ ਅਤੇ API ਕੁੰਜੀ ਬਣਾਓ

1. Dashboard → `Providers` ਖੋਲ੍ਹੋ ਅਤੇ ਘੱਟੋ-ਘੱਟ ਇੱਕ ਪ੍ਰਦਾਤਾ (OAuth ਜਾਂ API ਕੁੰਜੀ) ਕਨੈਕਟ ਕਰੋ।
2. Dashboard → `Endpoints` ਖੋਲ੍ਹੋ ਅਤੇ ਇੱਕ API ਕੁੰਜੀ ਬਣਾਓ।
3. (ਵਿਕਲਪਿਕ) Dashboard → `Combos` ਖੋਲ੍ਹੋ ਅਤੇ ਆਪਣੀ ਫਾਲਬੈਕ ਲੜੀ ਸੈੱਟ ਕਰੋ।

### 2) ਆਪਣੇ ਕੋਡਿੰਗ ਟੂਲ ਨੂੰ ਨਿਰਧਾਰਤ ਕਰੋ

```txt
ਮੂਲ URL: http://localhost:20128/v1
API ਕੁੰਜੀ:  [Endpoint ਪੰਨੇ ਤੋਂ ਕਾਪੀ ਕਰੋ]
ਮਾਡਲ:    if/qwen3.8-max-preview (ਜਾਂ ਕੋਈ ਵੀ ਪ੍ਰਦਾਤਾ/ਮਾਡਲ ਪ੍ਰੀਫਿਕਸ)
```

ਜੇ ਤੁਹਾਡਾ ਐਡੀਟਰ `Authorization: Bearer ...` ਨਹੀਂ ਭੇਜ ਸਕਦਾ, ਤਾਂ ਇਸ ਦੀ ਬਜਾਏ ਟੋਕਨ-ਯੁਕਤ ਅਨੁਕੂਲਤਾ ਮੂਲ ਵਰਤੋ:

```txt
ਮੂਲ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/
ਮਾਡਲ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/models
ਚੈਟ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/chat/completions
Ollama ਟੈਗ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/api/tags
```

Claude Code, Codex CLI, Cursor, Cline, OpenClaw, OpenCode ਅਤੇ OpenAI-ਅਨੁਕੂਲ SDKs ਨਾਲ ਕੰਮ ਕਰਦਾ ਹੈ।

#### `setup-*` ਨਾਲ ਸਵੈਚਾਲਿਤ ਸੰਰਚਨਾ ਕਰੋ

ਮੂਲ URL ਅਤੇ ਕੁੰਜੀ ਨੂੰ ਹੱਥੀਂ ਪੇਸਟ ਕਰਨ ਦੀ ਬਜਾਏ, OmniRoute ਨੂੰ ਲਾਈਵ ਮਾਡਲ ਕੈਟਾਲਾਗ ਤੋਂ ਹਰੇਕ ਟੂਲ ਦੀ
ਆਪਣੀ ਸੰਰਚਨਾ ਲਿਖਣ ਦਿਓ। ਹਰੇਕ ਟੂਲ ਲਈ ਇੱਕ ਕਮਾਂਡ:

```bash
omniroute setup-codex        # ~/.codex/<name>.config.toml ਪ੍ਰੋਫ਼ਾਈਲਾਂ
omniroute setup-claude       # ~/.claude/profiles/<name>/settings.json
omniroute setup-opencode     # ~/.config/opencode/opencode.json (OpenAI-ਅਨੁਕੂਲ)
omniroute setup-cline        # Cline CLI + VS Code ਐਕਸਟੈਂਸ਼ਨ ਸੈਟਿੰਗਾਂ
omniroute setup-kilo         # Kilo Code
omniroute setup-continue     # ~/.continue/config.yaml (Continue / cn)
omniroute setup-cursor       # Cursor ਦੇ ਇਨ-ਐਪ ਪੜਾਅ ਪ੍ਰਿੰਟ ਕਰਦਾ ਹੈ
omniroute setup-roo          # Roo Code ਇੰਪੋਰਟ + autoImport ਪੁਆਇੰਟਰ
omniroute setup-crush        # ~/.config/crush/crush.json
omniroute setup-zed          # ~/.config/zed/settings.json (openai_compatible)
omniroute setup-goose        # ~/.config/goose/config.yaml
omniroute setup-aider        # ~/.aider.conf.yml
omniroute setup-qwen         # ~/.qwen/settings.json + ~/.qwen/.env
```

ਹਰੇਕ ਕਮਾਂਡ ਇੱਕ ਸਥਾਨਕ ਟੂਲ ਨੂੰ ਇੱਕ **ਰਿਮੋਟ** OmniRoute ਲਈ ਸੰਰਚਿਤ ਕਰਨ ਵਾਸਤੇ `--remote <url> --api-key <key>`
ਸਵੀਕਾਰ ਕਰਦੀ ਹੈ, ਅਤੇ ਪੂਰਵ-ਝਲਕ ਲਈ `--dry-run` ਵੀ ਸਵੀਕਾਰ ਕਰਦੀ ਹੈ। ਸਹੀ env ਇੰਜੈਕਟ ਕਰਕੇ ਅਤੇ ਬਿਲਕੁਲ ਵੀ
ਸੰਰਚਨਾ ਲਿਖੇ ਬਿਨਾਂ CLI ਚਲਾਉਣ ਲਈ, ਆਮ ਲਾਂਚਰ `omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini)
ਵਰਤੋ; ਪੁਰਾਣੇ ਪ੍ਰਤੀ-ਟੂਲ ਲਾਂਚਰ `omniroute launch` (Claude Code) ਅਤੇ
`omniroute launch-codex` (Codex) ਅਜੇ ਵੀ ਉਪਲਬਧ ਹਨ।

ਪੂਰੀ ਸਾਰਣੀ ਲਈ (ਹਰੇਕ ਕਮਾਂਡ ਕੀ ਲਿਖਦੀ ਹੈ, ਹਰ ਫਲੈਗ, ਸਥਾਨਕ ਬਨਾਮ ਰਿਮੋਟ, ਮੂਲ-URL
`/v1` ਰਵਾਇਤਾਂ), **[CLI ਇੰਟੀਗ੍ਰੇਸ਼ਨਾਂ](./CLI-INTEGRATIONS.md)** ਵੇਖੋ।

ਹਰੇਕ ਟੂਲ ਦੀ ਵਿਸਤ੍ਰਿਤ ਸੰਰਚਨਾ ਲਈ (Claude Code, Codex CLI, Cursor, Cline, OpenClaw, Kilo Code, Copilot ਅਤੇ ਹੋਰ), ਸਮਰਪਿਤ **[CLI ਟੂਲ ਗਾਈਡ](../reference/CLI-TOOLS.md)** ਵੇਖੋ।

## ਪ੍ਰੋਟੋਕੋਲ ਸੈੱਟਅੱਪ (MCP + A2A)

### MCP ਸੈੱਟਅੱਪ (ਮਾਡਲ ਸੰਦਰਭ ਪ੍ਰੋਟੋਕੋਲ)

stdio ਮੋਡ ਵਿੱਚ MCP ਟ੍ਰਾਂਸਪੋਰਟ ਸ਼ੁਰੂ ਕਰੋ:

```bash
omniroute --mcp
```

ਸਿਫ਼ਾਰਸ਼ੀ ਪ੍ਰਮਾਣਿਕਤਾ ਪ੍ਰਵਾਹ:

```bash
# 1. Start MCP server
omniroute --mcp

# 2. From your MCP client, call:
omniroute_get_health        # Should return system health
omniroute_list_combos       # Should return active combos

# 3. Or run the full E2E suite:
npm run test:protocols:e2e
```

#### MCP ਕਲਾਇੰਟ ਸੰਰਚਨਾ

**Claude ਕੋਡ:**

Claude ਕੋਡ HTTP ਉੱਤੇ ਜੁੜਦਾ ਹੈ, ਜੋ ਕਿ `omniroute --mcp` (stdio) ਸ਼ੁਰੂ ਨਹੀਂ ਹੁੰਦਾ ਹੈ। HTTP ਟ੍ਰਾਂਸਪੋਰਟ ਮੂਲ ਰੂਪ ਵਿੱਚ ਬੰਦ ਹੈ: ਇਸਨੂੰ ਪਹਿਲਾਂ ਚੱਲ ਰਹੇ ਸਰਵਰ 'ਤੇ ਯੋਗ ਕਰੋ। ਜਦੋਂ ਡੈਸ਼ਬੋਰਡ ਲੌਗਇਨ ਸਮਰਥਿਤ ਹੁੰਦਾ ਹੈ, ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਤੋਂ ਬਿਨਾਂ ਇੱਕ ਬੇਨਤੀ `401` ਪ੍ਰਾਪਤ ਕਰਦੀ ਹੈ, ਇਸਲਈ ਇੱਕ API ਕੁੰਜੀ ਪਾਸ ਕਰੋ ਜਿਸ ਵਿੱਚ `mcp:connect` (ਜਾਂ `manage`); `manage`/`admin` ਤੋਂ ਬਿਨਾਂ ਇੱਕ ਕੁੰਜੀ ਨੂੰ ਵੀ ਹਰੇਕ ਟੂਲ ਦੇ ਸਕੋਪ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ ( [MCP ਸਰਵਰ → MCP ਟੂਲ ਸਕੋਪ](../frameworks/MCP-SERVER.md#mcp-tool-scopes) ਦੇਖੋ)।

```bash
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer your-key"
```

**Cursor / Cline:**

ਆਪਣੀਆਂ MCP ਸੈਟਿੰਗਾਂ ਵਿੱਚ ਸ਼ਾਮਲ ਕਰੋ (stdio, ਕੁੰਜੀ ਨਾਲ ਤਾਂ ਜੋ ਕਾਲਰ ਕੋਲ ਇੱਕ ਪ੍ਰਿੰਸੀਪਲ ਹੋਵੇ):

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"],
      "env": {
        "OMNIROUTE_API_KEY": "your-key",
        "OMNIROUTE_BASE_URL": "http://localhost:20128"
      }
    }
  }
}
```

ਜਾਂ, ਜਦੋਂ `mcpTransport` `streamable-http` ਹੋਵੇ (ਇਸ ਨੂੰ `/dashboard/mcp` ਤੇ ਸੈੱਟ ਕਰੋ ਜਾਂ `omniroute mcp enable --transport streamable-http` ਨਾਲ), ਕਲਾਇੰਟ ਦੀ ਰਿਮੋਟ MCP ਸਰਵਰ ਐਂਟਰੀ ਨੂੰ `http://localhost:20128/api/mcp/stream`'ਤੇ ਪੁਆਇੰਟ ਕਰੋ।

ਕੁੰਜੀ `Authorization: Bearer <api-key>` ਵਜੋਂ ਯਾਤਰਾ ਕਰਦੀ ਹੈ (ਰਿਮੋਟ ਮੇਜ਼ਬਾਨਾਂ ਲਈ [MCP ਸਰਵਰ → ਰਿਮੋਟ ਪਹੁੰਚ](../frameworks/MCP-SERVER.md#remote-access-manage-scope-bypass) ਵੇਖੋ; ਇੱਕ ਰਿਮੋਟ ਕੁੰਜੀ ਨੂੰ `mcp:connect` ਅਤੇ ਇਸਦੇ read/write ਸਕੋਪਾਂ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ)।

**ਪੂਰਾ MCP ਦਸਤਾਵੇਜ਼:** [MCP ਸਰਵਰ README](../../open-sse/mcp-server/README.md) — 110 ਟੂਲ, IDE ਸੰਰਚਨਾ, Python/TS/Go ਕਲਾਇੰਟਸ। ਕੰਪਰੈਸ਼ਨ CCR/dedup ਟੂਲਜ਼ (ਮਾਰਕਰ, ਪੂਰਵ-ਲੋੜਾਂ, ਪ੍ਰਤੀ-ਟੂਲ ਸਕੋਪ, ਪ੍ਰਾਪਤੀ ਪੰਨਾਬੰਦੀ, ਡਾਇਗਨੌਸਟਿਕਸ) ਲਈ ਆਪਰੇਟਰ ਸੰਦਰਭ: [ਕੰਪਰੈਸ਼ਨ ਇੰਜਣ → ਲੋੜਾਂ / ਆਪਰੇਟਰ ਗਾਈਡ](../compression/COMPRESSION_ENGINES.md#prerequisites--operator-guide-ccr--session-dedup) ।

### A2A ਸੈੱਟਅੱਪ (ਏਜੰਟ ਤੋਂ ਏਜੰਟ ਪ੍ਰੋਟੋਕੋਲ)

ਏਜੰਟ ਕਾਰਡ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ:

**ਪੂਰਾ A2A ਦਸਤਾਵੇਜ਼:** [A2A ਸਰਵਰ README](../../src/lib/a2a/README.md) — JSON-RPC 2.0, ਹੁਨਰ, ਸਟ੍ਰੀਮਿੰਗ, ਕਾਰਜ ਜੀਵਨ ਚੱਕਰ।

## ਟਾਈਮਆਉਟ ਸੰਰਚਨਾ

### ਬੁਨਿਆਦੀ ਟਾਈਮਆਉਟ

ਜ਼ਿਆਦਾਤਰ ਡਿਪਲੌਇਮੈਂਟਾਂ ਲਈ, ਤੁਹਾਨੂੰ ਸਿਰਫ਼ ਇਹਨਾਂ ਦੋ ਵੇਰੀਏਬਲਾਂ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ:

| ਵੇਰੀਏਬਲ                  | ਡਿਫੌਲਟ                          | ਉਦੇਸ਼                                                                                                                                        |
| ------------------------ | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQUEST_TIMEOUT_MS`     | `600000`                        | ਅੱਪਸਟ੍ਰੀਮ ਜਵਾਬ ਸ਼ੁਰੂ ਹੋਣ ਦੇ ਟਾਈਮਆਉਟ, ਲੁਕਵੇਂ Undici ਟਾਈਮਆਉਟਾਂ, TLS ਫਿੰਗਰਪ੍ਰਿੰਟ ਬੇਨਤੀਆਂ ਅਤੇ API ਬ੍ਰਿਜ ਬੇਨਤੀ/ਪ੍ਰੌਕਸੀ ਟਾਈਮਆਉਟਾਂ ਲਈ ਸਾਂਝੀ ਬੇਸਲਾਈਨ |
| `STREAM_IDLE_TIMEOUT_MS` | `REQUEST_TIMEOUT_MS` ਤੋਂ ਪ੍ਰਾਪਤ | OmniRoute ਵੱਲੋਂ SSE ਸਟ੍ਰੀਮ ਨੂੰ ਰੋਕਣ ਤੋਂ ਪਹਿਲਾਂ ਸਟ੍ਰੀਮਿੰਗ ਚੰਕਾਂ ਵਿਚਕਾਰ ਵੱਧ ਤੋਂ ਵੱਧ ਅੰਤਰਾਲ                                                     |

ਪਿਛਲੀ ਅਨੁਕੂਲਤਾ ਬਰਕਰਾਰ ਰੱਖੀ ਗਈ ਹੈ: ਮੌਜੂਦਾ `FETCH_TIMEOUT_MS`, `API_BRIDGE_PROXY_TIMEOUT_MS`, ਅਤੇ ਹੋਰ ਪ੍ਰਤੀ-ਲੇਅਰ ਟਾਈਮਆਉਟ ਵੇਰੀਏਬਲ ਅਜੇ ਵੀ ਕੰਮ ਕਰਦੇ ਹਨ ਅਤੇ ਸਾਂਝੀ ਬੇਸਲਾਈਨ ਨੂੰ ਓਵਰਰਾਈਡ ਕਰਦੇ ਹਨ।

### ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ ਨੋਟਸ

Claude Code-ਅਨੁਕੂਲ ਅੱਪਸਟ੍ਰੀਮਾਂ (`anthropic-compatible-cc-*`) ਲਈ, OmniRoute ਹੱਲ ਕੀਤੇ ਫੈਚ ਟਾਈਮਆਉਟ ਤੋਂ ਆਊਟਬਾਊਂਡ `X-Stainless-Timeout` ਹੈਡਰ ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ, ਤਾਂ ਜੋ ਪ੍ਰਦਾਤਾ-ਪਾਸੇ ਦੇ ਰੀਡ ਟਾਈਮਆਉਟ ਤੁਹਾਡੀ env ਸੰਰਚਨਾ ਨਾਲ ਇਕਸਾਰ ਰਹਿਣ।

ਤੀਜੀ-ਧਿਰ Claude Code-ਅਨੁਕੂਲ ਰਿਵਰਸ ਪ੍ਰੌਕਸੀਆਂ ਲਈ, OmniRoute ਡਿਫੌਲਟ `anthropic-beta` ਸੈੱਟ ਨੂੰ ਸੀਮਤ ਰੱਖਦਾ ਹੈ ਅਤੇ ਜਦੋਂ `Client Cache Control` ਨੂੰ `Auto` 'ਤੇ ਛੱਡਿਆ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਸਿਰਫ਼ ਕਲਾਇੰਟ ਵੱਲੋਂ ਦਿੱਤੇ `cache_control` ਮਾਰਕਰ ਹੀ ਅੱਗੇ ਭੇਜਦਾ ਹੈ। ਪ੍ਰਤੀ-ਕਨੈਕਸ਼ਨ "ਰਿਡੈਕਟ-ਥਿੰਕਿੰਗ ਬੀਟਾ ਸਮਰੱਥ ਕਰੋ" ਟੌਗਲ ਨੂੰ ਕੇਵਲ ਉਸ ਵੇਲੇ ਸਮਰੱਥ ਕਰੋ ਜਦੋਂ ਅੱਪਸਟ੍ਰੀਮ ਨੂੰ ਖ਼ਾਸ ਤੌਰ 'ਤੇ ਰਿਡੈਕਟ ਕੀਤੀਆਂ Claude ਥਿੰਕਿੰਗ ਸਟ੍ਰੀਮਾਂ ਦੀ ਲੋੜ ਹੋਵੇ।

### ਉੱਨਤ ਟਾਈਮਆਉਟ ਓਵਰਰਾਈਡ

| ਵੇਰੀਏਬਲ                                  | ਡਿਫੌਲਟ                                       | ਉਦੇਸ਼                                                                      |
| ---------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------- |
| `FETCH_TIMEOUT_MS`                       | `REQUEST_TIMEOUT_MS` ਤੋਂ ਪ੍ਰਾਪਤ              | ਜਵਾਬ ਦੇ ਹੈਡਰ ਆਉਣ ਤੱਕ ਵਰਤਿਆ ਜਾਣ ਵਾਲਾ ਅੱਪਸਟ੍ਰੀਮ ਜਵਾਬ-ਸ਼ੁਰੂਆਤ ਟਾਈਮਆਉਟ         |
| `FETCH_HEADERS_TIMEOUT_MS`               | `FETCH_TIMEOUT_MS` ਤੋਂ ਪ੍ਰਾਪਤ                | ਅੱਪਸਟ੍ਰੀਮ ਜਵਾਬ ਦੇ ਹੈਡਰ ਪ੍ਰਾਪਤ ਕਰਨ ਲਈ Undici ਦੀ ਸਮਾਂ-ਸੀਮਾ                   |
| `FETCH_BODY_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` ਤੋਂ ਪ੍ਰਾਪਤ                | ਅੱਪਸਟ੍ਰੀਮ ਬੌਡੀ ਚੰਕਾਂ ਵਿਚਕਾਰ Undici ਦੀ ਸਮਾਂ-ਸੀਮਾ (`0` ਇਸਨੂੰ ਅਸਮਰੱਥ ਕਰਦਾ ਹੈ) |
| `FETCH_CONNECT_TIMEOUT_MS`               | `30000`                                      | Undici TCP ਕਨੈਕਟ ਟਾਈਮਆਉਟ                                                   |
| `FETCH_KEEPALIVE_TIMEOUT_MS`             | `4000`                                       | Undici ਨਿਸ਼ਕਿਰਿਆ keep-alive ਸਾਕਟ ਟਾਈਮਆਉਟ                                   |
| `TLS_CLIENT_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` ਤੋਂ ਪ੍ਰਾਪਤ                | `wreq-js` ਰਾਹੀਂ ਕੀਤੀਆਂ TLS ਫਿੰਗਰਪ੍ਰਿੰਟ ਬੇਨਤੀਆਂ ਲਈ ਟਾਈਮਆਉਟ                  |
| `API_BRIDGE_PROXY_TIMEOUT_MS`            | `REQUEST_TIMEOUT_MS` ਜਾਂ `600000` ਤੋਂ ਪ੍ਰਾਪਤ | API ਪੋਰਟ ਤੋਂ ਡੈਸ਼ਬੋਰਡ ਪੋਰਟ ਵੱਲ `/v1` ਪ੍ਰੌਕਸੀ ਫਾਰਵਰਡਿੰਗ ਲਈ ਟਾਈਮਆਉਟ          |
| `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS`   | `max(API_BRIDGE_PROXY_TIMEOUT_MS, 300000)`   | API ਬ੍ਰਿਜ ਸਰਵਰ 'ਤੇ ਆਉਣ ਵਾਲੀ ਬੇਨਤੀ ਦਾ ਟਾਈਮਆਉਟ                               |
| `API_BRIDGE_SERVER_HEADERS_TIMEOUT_MS`   | `60000`                                      | API ਬ੍ਰਿਜ ਸਰਵਰ 'ਤੇ ਆਉਣ ਵਾਲੇ ਹੈਡਰ ਦਾ ਟਾਈਮਆਉਟ                                |
| `API_BRIDGE_SERVER_KEEPALIVE_TIMEOUT_MS` | `5000`                                       | API ਬ੍ਰਿਜ ਸਰਵਰ 'ਤੇ keep-alive ਟਾਈਮਆਉਟ                                      |
| `API_BRIDGE_SERVER_SOCKET_TIMEOUT_MS`    | `0`                                          | API ਬ੍ਰਿਜ ਸਰਵਰ 'ਤੇ ਸਾਕਟ ਨਿਸ਼ਕਿਰਿਆਤਾ ਟਾਈਮਆਉਟ (`0` ਇਸਨੂੰ ਅਸਮਰੱਥ ਕਰਦਾ ਹੈ)     |

> **ਨੋਟ:** ਸਟ੍ਰੀਮਿੰਗ ਬੇਨਤੀਆਂ ਲਈ, `FETCH_TIMEOUT_MS` ਸਿਰਫ਼ ਕਨੈਕਸ਼ਨ ਸੈੱਟਅੱਪ / ਪਹਿਲੇ ਅੱਪਸਟ੍ਰੀਮ ਜਵਾਬ ਦੀ ਉਡੀਕ ਨੂੰ ਕਵਰ ਕਰਦਾ ਹੈ। ਸਟ੍ਰੀਮ ਸਰਗਰਮ ਹੋ ਜਾਣ ਤੋਂ ਬਾਅਦ, OmniRoute ਸਿਰਫ਼ ਅਸਲ ਰੁਕਾਵਟ (`STREAM_IDLE_TIMEOUT_MS`) ਜਾਂ Undici ਬੌਡੀ ਨਿਸ਼ਕਿਰਿਆਤਾ (`FETCH_BODY_TIMEOUT_MS`) ਹੋਣ 'ਤੇ ਹੀ ਇਸਨੂੰ ਰੋਕੇਗਾ।

### ਰਿਵਰਸ ਪ੍ਰੌਕਸੀ ਅਨੁਕੂਲਤਾ

ਜੇ ਤੁਸੀਂ OmniRoute ਨੂੰ Nginx, Caddy, Cloudflare, ਜਾਂ ਕਿਸੇ ਹੋਰ ਰਿਵਰਸ ਪ੍ਰੌਕਸੀ ਦੇ ਪਿੱਛੇ ਚਲਾਉਂਦੇ ਹੋ, ਤਾਂ ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਪ੍ਰੌਕਸੀ ਟਾਈਮਆਉਟ ਵੀ ਤੁਹਾਡੇ OmniRoute ਸਟ੍ਰੀਮ/ਫੈਚ ਟਾਈਮਆਉਟਾਂ ਤੋਂ ਵੱਧ ਹੋਣ।

## Void Linux (xbps-src) ਟੈਂਪਲੇਟ

Void Linux ਉਪਭੋਗਤਾਵਾਂ ਲਈ, ਤੁਸੀਂ `xbps-src` ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਇੱਕ ਮੂਲ ਪੈਕੇਜ ਬਣਾ ਸਕਦੇ ਹੋ। ਇਸ ਬਲਾਕ ਨੂੰ `srcpkgs/omniroute/template` ਵਜੋਂ ਸੇਵ ਕਰੋ:

```bash
# Template file for 'omniroute'
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/cheaper-inference/OmniRoute"
distfiles="https://github.com/cheaper-inference/OmniRoute/archive/refs/tags/v${version}.tar.gz"
# Regenerate the checksum for each release with:
#   curl -L -o /tmp/omniroute.tar.gz "https://github.com/cheaper-inference/OmniRoute/archive/refs/tags/v${version}.tar.gz" && sha256sum /tmp/omniroute.tar.gz
checksum=PLACEHOLDER_REGENERATE_PER_RELEASE
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	NODE_ENV=development npm ci --ignore-scripts
	npm run build
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```
