ਸ਼ੇਅਰਡ ਐਗਜ਼ੀਕਿਊਟੇਬਲ ਮੈਨੀਫੈਸਟ, ਪ੍ਰਤਿਬੰਧਿਤ ਚਾਈਲਡ ਇਨਵਾਇਰਮੈਂਟ ਅਤੇ ਸਥਾਈ Gemini ਸੈੱਟਅੱਪ ਲਈ, [CLI ਲਾਂਚ ਕੰਟਰੈਕਟ](./CLI-LAUNCH-CONTRACTS.md) ਦੇਖੋ।

OmniRoute `setup-*` ਕਮਾਂਡਾਂ ਦੇ ਇੱਕ ਪਰਿਵਾਰ ਨੂੰ ਭੇਜਦਾ ਹੈ ਜੋ OmniRoute ਇਸਦੇ ਬੈਕਐਂਡ ਵਜੋਂ ਵਰਤਣ ਲਈ ਇੱਕ ਕੋਡਿੰਗ CLI (Codex, Claude ਕੋਡ, OpenCode, Cline, …) ਨੂੰ ਕੌਂਫਿਗਰ ਕਰਦਾ ਹੈ — ਇਸਲਈ ਟੂਲ ਇਸ ਨਾਲ ਗੱਲ ਕਰਦਾ ਹੈ** ਇੱਕ** ਆਟੋ-ਫਾਲਬੈਕ ਦੇ ਨਾਲ ਸਹੀ ਪ੍ਰਦਾਤਾ ਲਈ ਐਂਡਪੁਆਇੰਟ ਅਤੇ OmniRoute ਰੂਟ। ਹਰੇਕ ਕਮਾਂਡ ਨੂੰ ਪੜ੍ਹਦਾ ਹੈ** ਲਾਈਵ** ਇੱਕ ਚੱਲ ਰਹੇ OmniRoute (ਸਥਾਨਕ ਜਾਂ ਰਿਮੋਟ) ਤੋਂ ਮਾਡਲ ਕੈਟਾਲਾਗ ਅਤੇ ਟੂਲ ਦੀ ਆਪਣੀ ਸੰਰਚਨਾ ਫਾਈਲ ਨੂੰ ਲਿਖਦਾ ਹੈ** ਤੁਹਾਡਾ** ਮਸ਼ੀਨ। API ਕੁੰਜੀ ਨੂੰ ਇੱਕ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ ਦੁਆਰਾ ਹਵਾਲਾ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ ਜਿੱਥੇ ਵੀ ਟੂਲ ਇਸਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ। ਕਮਾਂਡਾਂ ਜੋ ਇੱਕ ਟੂਲ-ਲੋਕਲ ਇਨਵਾਇਰਮੈਂਟ ਫਾਈਲ ਨੂੰ ਜਾਰੀ ਰੱਖਦੀਆਂ ਹਨ ਹੇਠਾਂ ਨੋਟ ਕੀਤੀਆਂ ਗਈਆਂ ਹਨ।

ਇੱਥੇ ਇੱਕ ਆਮ ਲਾਂਚਰ — `omniroute run <target>` — ਵੀ ਹੈ ਜੋ ਬਿਨਾਂ ਕਿਸੇ ਸੰਰਚਨਾ ਦੇ, ਸਹੀ env ਟੀਕੇ ਦੇ ਨਾਲ `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen`, `gemini` ਜਾਂ `whycodes` ਨੂੰ ਪੈਦਾ ਕਰਦਾ ਹੈ। ਟਾਰਗੇਟ ਅਤੇ ਉਹਨਾਂ ਦੇ ਉਪਨਾਮ ਕੈਨੋਨੀਕਲ ਮੈਨੀਫੈਸਟ `bin/cli/cli-manifest.mjs` (`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`, `open-code`, `qwen-code`, `gemini-cli`, `why-codes|why`) ਤੋਂ ਆਉਂਦੇ ਹਨ, ਅਤੇ `omniroute completion` ਇੱਕੋ ਪ੍ਰਗਟ-ਉਤਪੰਨ ਨਿਸ਼ਾਨਾ ਸ਼ਬਦਾਂ ਦੀ ਪੇਸ਼ਕਸ਼ ਕਰਦਾ ਹੈ। ਵਿਰਾਸਤੀ ਪ੍ਰਤੀ-ਟੂਲ ਲਾਂਚਰ — `omniroute launch` (Claude ਕੋਡ) ਅਤੇ `omniroute launch-codex` (Codex) — ਉਪਲਬਧ ਰਹਿੰਦੇ ਹਨ।

ਪ੍ਰਦਾਤਾ ਆਨਬੋਰਡਿੰਗ ਉਸੇ local/remote ਸੰਦਰਭ ਤੋਂ ਉਪਲਬਧ ਹੈ। ਹੇਠਾਂ ਦਿੱਤੀਆਂ API-ਪਹਿਲੀ ਕਮਾਂਡਾਂ ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣਿਕਤਾ ਨੂੰ ਪ੍ਰਦਾਤਾ ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ ਤੋਂ ਵੱਖ ਰੱਖਦੀਆਂ ਹਨ ਅਤੇ ਕਦੇ ਵੀ ਢਾਂਚਾਗਤ ਆਉਟਪੁੱਟ ਵਿੱਚ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਪ੍ਰਿੰਟ ਨਹੀਂ ਕਰਦੀਆਂ:

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

ਸਕ੍ਰਿਪਟਾਂ ਲਈ, `--credential-stdin` ਜਾਂ `--credential-env` ਨੂੰ ਤਰਜੀਹ ਦਿਓ; `--credential` ਨਿਯੰਤਰਿਤ ਸਥਾਨਕ ਵਰਤੋਂ ਲਈ ਬਰਕਰਾਰ ਰੱਖਿਆ ਜਾਂਦਾ ਹੈ। `providers remove` ਨੂੰ ਇੱਕ ਗੈਰ-ਇੰਟਰਐਕਟਿਵ ਟਰਮੀਨਲ 'ਤੇ `--yes` ਲੋੜ ਹੁੰਦੀ ਹੈ, ਅਤੇ ਸਾਰੀਆਂ ਪੰਜ ਕਮਾਂਡਾਂ ਸਰਗਰਮ ਸੰਦਰਭ ਜਾਂ ਗਲੋਬਲ `--base-url`/`--api-key` ਵਿਕਲਪਾਂ ਦਾ ਸਨਮਾਨ ਕਰਦੀਆਂ ਹਨ।

ਪ੍ਰਦਾਤਾ ਚੋਣਕਾਰ ਅਸਪਸ਼ਟ ID ਅਗੇਤਰ, ਨਾਮ ਜਾਂ ਪ੍ਰਦਾਤਾ ਦੇ ਨਾਮ ਨੂੰ ਰੱਦ ਕਰਦੇ ਹਨ; ਜਦੋਂ ਕਈ ਕੁਨੈਕਸ਼ਨ ਮੇਲ ਖਾਂਦੇ ਹਨ ਤਾਂ ਪੂਰਾ ਕੁਨੈਕਸ਼ਨ ID ਵਰਤੋ। ਕਮਾਂਡਾਂ ਬਣਾਓ ਅਤੇ ਸੰਪਾਦਿਤ ਕਰੋ ਸੁਰੱਖਿਅਤ ਕੀਤੇ ਕਨੈਕਸ਼ਨ ਨੂੰ ਵਾਪਸ ਪੜ੍ਹੋ, ਅਤੇ ਹਟਾਉਣਾ ਪੁਸ਼ਟੀ ਕਰਦਾ ਹੈ ਕਿ ਇਹ ਹੁਣ ਪੜ੍ਹਨਯੋਗ ਨਹੀਂ ਹੈ। ਇੱਕ ਆਯਾਤ ਇੱਕ ਮੌਜੂਦਾ provider/name ਜੋੜਾ ਨੂੰ ਛੱਡ ਦਿੰਦਾ ਹੈ। ਆਯਾਤ ਐਂਟਰੀਆਂ CLI ਨੂੰ ਸਪਲਾਈ ਕੀਤੇ ਪ੍ਰਬੰਧਨ ਅੰਤਮ ਬਿੰਦੂ, ਸੰਦਰਭ ਜਾਂ ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ ਨੂੰ ਓਵਰਰਾਈਡ ਨਹੀਂ ਕਰ ਸਕਦੀਆਂ।

ਦੋ ਸਭ ਤੋਂ ਅਮੀਰ ਏਕੀਕਰਣਾਂ ਦੇ ਇੱਕ-ਵਾਰ, ਹੱਥ-ਲਿਖਤ ਅਧਾਰ ਸੈੱਟਅੱਪ ਲਈ, ਪ੍ਰਤੀ-ਟੂਲ ਡੂੰਘੇ ਡਾਈਵਜ਼ ਵੇਖੋ:

- [Claude ਕੋਡ ਸੰਰਚਨਾ](./CLAUDE-CODE-CONFIGURATION.md)
- [Codex CLI ਸੰਰਚਨਾ](./CODEX-CLI-CONFIGURATION.md)
- [ਰਿਮੋਟ ਮੋਡ](./REMOTE-MODE.md) - ਆਪਣੇ ਲੈਪਟਾਪ ਤੋਂ ਇੱਕ ਰਿਮੋਟ OmniRoute (VPS / Tailnet) ਚਲਾਓ
- [VS ਕੋਡ Copilot ਚੈਟ](./VSCODE-COPILOT.md) — OmniCopilot ਐਕਸਟੈਂਸ਼ਨ; ਇਹ ਤੁਹਾਡੇ ਲਈ ਸੰਪਾਦਕ ਦੇ ਅੰਦਰੋਂ ਇਹਨਾਂ `setup-*` ਕਮਾਂਡਾਂ ਨੂੰ ਵੀ ਚਲਾ ਸਕਦਾ ਹੈ

## ਮਾਸਟਰ ਟੇਬਲ

ਹਰ ਹੁਕਮ ਦਾ ਸਨਮਾਨ ਕਰਦਾ ਹੈ** ਸਰਗਰਮ ਸੰਦਰਭ** ( `omniroute connect` ਨਾਲ ਸੈੱਟ ਕਰੋ, [ਰਿਮੋਟ ਮੋਡ](./REMOTE-MODE.md) ਦੇਖੋ) ਜਾਂ ਸਪਸ਼ਟ `--remote <url> --api-key <key>` ਫਲੈਗ। ਹੇਠਾਂ "ਸਥਾਨਕ ਬਨਾਮ ਰਿਮੋਟ" ਦਾ ਮਤਲਬ ਹੈ: ਬਿਨਾਂ ਝੰਡੇ ਦੇ ਇਹ `http://localhost:20128` ਨੂੰ ਨਿਸ਼ਾਨਾ ਬਣਾਉਂਦਾ ਹੈ; `--remote` (ਜਾਂ ਇੱਕ ਸਰਗਰਮ ਰਿਮੋਟ ਪ੍ਰਸੰਗ) ਨਾਲ ਇਹ ਉਸ ਸਰਵਰ ਤੋਂ ਕੈਟਾਲਾਗ ਲਿਆਉਂਦਾ ਹੈ ਅਤੇ ਸੰਰਚਨਾ ਨੂੰ ਲੋਕਲ ਲਿਖਦਾ ਹੈ।

ਝੰਡੇ 'ਤੇ ਨੋਟਸ (ਕਮਾਂਡ ਸਰੋਤ ਵਿੱਚ ਪ੍ਰਮਾਣਿਤ):

- `--remote <url>` — ਇੱਕ ਰਿਮੋਟ OmniRoute ਤੋਂ ਕੈਟਾਲਾਗ ਪ੍ਰਾਪਤ ਕਰੋ ( `--port` ਅਤੇ ਕਿਰਿਆਸ਼ੀਲ ਸੰਦਰਭ ਨੂੰ ਓਵਰਰਾਈਡ ਕਰਦਾ ਹੈ)। `--api-key <key>` ਉਸ ਸਰਵਰ ਲਈ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਸਪਲਾਈ ਕਰਦਾ ਹੈ ( `OMNIROUTE_API_KEY` env var, ਜਾਂ ਸਰਗਰਮ ਸੰਦਰਭ ਦੇ ਟੋਕਨ ਲਈ ਮੂਲ)।
- `--only <patterns>` — ਕਾਮੇ ਨਾਲ ਵੱਖ ਕੀਤੇ ਸਬਸਟਰਿੰਗਜ਼; ਸਿਰਫ਼ ਮਾਡਲ IDs ਰੱਖੋ ਜੋ ਮੇਲ ਖਾਂਦਾ ਹੈ (ਜਿਵੇਂ ਕਿ `--only glm,kimi`)। `setup-codex`, `setup-claude`, `setup-opencode`, `setup-continue`, `setup-cursor`, `setup-crush`, `setup-zed`'ਤੇ ਉਪਲਬਧ ਹੈ।
- `--dry-run` — ਫਾਈਲ ਸਿਸਟਮ ਨੂੰ ਛੂਹਣ ਤੋਂ ਬਿਨਾਂ ਉਹੀ ਪ੍ਰਿੰਟ ਕਰੋ ਜੋ ਲਿਖਿਆ ਜਾਵੇਗਾ। ਹਰ `setup-*` ਕਮਾਂਡ 'ਤੇ ਉਪਲਬਧ ਹੈ** ਸਿਵਾਏ** `setup-cursor` (ਜੋ ਕਦੇ ਫਾਈਲ ਨਹੀਂ ਲਿਖਦਾ)।
- `--model <id>` — ਉਹਨਾਂ ਟੂਲਸ ਲਈ ਲੋੜੀਂਦਾ (ਜਾਂ ਇੰਟਰਐਕਟਿਵ ਤੌਰ 'ਤੇ ਚੁਣਿਆ ਗਿਆ) ਜਿਨ੍ਹਾਂ ਕੋਲ ਕੋਈ ਮਾਡਲ ਆਟੋ-ਡਿਸਕਵਰੀ ਨਹੀਂ ਹੈ: Cline, Kilo, Roo, Goose, Qwen, Aider, 5dive, WhyCodes। ਉਹ ਟੂਲ ਗੈਰ-ਇੰਟਰਐਕਟਿਵ ਰਨ ਲਈ `--yes` ਵੀ ਸਵੀਕਾਰ ਕਰਦੇ ਹਨ (ਜਿਸ ਨੂੰ ਫਿਰ `--model` ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ)। `setup-opencode` ਪੂਰਵ-ਨਿਰਧਾਰਤ ਉੱਚ-ਪੱਧਰੀ ਮਾਡਲ ਨੂੰ ਸੈੱਟ ਕਰਨ ਲਈ `--model` ਲੈਂਦਾ ਹੈ।
- `--model <id>` on `omniroute run` ਮੈਨੀਫੈਸਟ ਦੀ ਪ੍ਰਤੀ-ਨਿਸ਼ਾਨਾ ਵਾਇਰਿੰਗ (`bin/cli/cli-manifest.mjs`) ਦੀ ਪਾਲਣਾ ਕਰਦਾ ਹੈ:** ਸਹਾਇਕ** `--model openai/<id>` ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ ਅਤੇ** ਓਪਨਕੋਡ** `--model omniroute/<id>` (ਅਗੇਤਰ ਉਦੋਂ ਹੀ ਜੋੜਿਆ ਜਾਂਦਾ ਹੈ ਜਦੋਂ id ਪਹਿਲਾਂ ਹੀ ਇਸ ਨੂੰ ਨਹੀਂ ਰੱਖਦਾ);** qwen** ਅਤੇ** ਮਿਥੁਨ** ਆਈਡੀ ਸ਼ਬਦਾਵਲੀ ਪ੍ਰਾਪਤ ਕਰੋ;** ਕਲਾਉਡ** ਇਹ `ANTHROPIC_MODEL` ਦੁਆਰਾ ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ,** ਹੰਸ** `GOOSE_MODEL` ਦੁਆਰਾ,** ਕੋਡ ਕਿਉਂ** `-P omniroute -m <id>` ਦੁਆਰਾ, ਅਤੇ** ਕੋਡੈਕਸ** `-c model_providers.omniroute.*` args ਦੁਆਰਾ.**Qwen ਇਕਲੌਤਾ ਰਨ ਟੀਚਾ ਹੈ ਜਿਸ ਨੂੰ `--model` ਸਖ਼ਤ ਲੋੜ ਹੈ** - ਇਸ ਤੋਂ ਬਿਨਾਂ `omniroute run qwen` ਇੱਕ ਸਪੱਸ਼ਟ ਗਲਤੀ ਨਾਲ `2` ਤੋਂ ਬਾਹਰ ਨਿਕਲਦਾ ਹੈ।
- `--port <port>` — ਸਥਾਨਕ OmniRoute ਪੋਰਟ (ਡਿਫਾਲਟ `20128`, ਅਣਡਿੱਠ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਜਦੋਂ `--remote` ਸੈੱਟ ਹੁੰਦਾ ਹੈ)। ਸਾਰੇ `setup-*` ਅਤੇ ਦੋਵੇਂ ਲਾਂਚਰਾਂ 'ਤੇ ਮੌਜੂਦ।
- `omniroute run` ਐਗਜ਼ਿਟ ਕੋਡ: ਚਾਈਲਡ CLI ਦਾ ਆਪਣਾ ਐਗਜ਼ਿਟ ਕੋਡ ਜ਼ੁਬਾਨੀ ਤੌਰ 'ਤੇ ਪ੍ਰਚਾਰਿਆ ਜਾਂਦਾ ਹੈ; `2` = ਅਵੈਧ ਆਰਗੂਮੈਂਟ (ਅਸਮਰਥਿਤ ਟੀਚਾ, ਲੋੜੀਂਦਾ `--model` ਗੁੰਮ ਹੈ, ਕੰਟੇਨਰ ਗਾਰਡ); `127` = ਟੀਚਾ ਬਾਈਨਰੀ `PATH` ਵਿੱਚ ਨਹੀਂ ਹੈ; `130`/`143`/`129` ਜਦੋਂ ਲਾਂਚ ਨੂੰ `SIGINT`/`SIGTERM`/`SIGHUP` ਦੁਆਰਾ ਸਮਾਪਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ; `1` = ਹੋਰ ਰਨਟਾਈਮ ਲਾਂਚ ਅਸਫਲਤਾ।
- ਦੋ ਲਾਂਚਰ (`launch`, `launch-codex`) `setup-claude` / `setup-codex` ਦੁਆਰਾ ਲਿਖੇ ਪ੍ਰੋਫਾਈਲ ਨੂੰ ਚੁਣਨ ਲਈ `--profile <name>` ਸਵੀਕਾਰ ਕਰਦੇ ਹਨ, ਨਾਲ ਹੀ ਅੰਡਰਲਾਈੰਗ `claude` / `codex` ਬਾਈਨਰੀ ਲਈ ਪਾਸ-ਥਰੂ ਆਰਗਸ।

ਇੰਟਰਐਕਟਿਵ ਚੋਣਕਾਰ ਨੂੰ ਸੈੱਟਅੱਪ ਪਕਵਾਨਾਂ ਦੁਆਰਾ ਵੀ ਸਾਂਝਾ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

```bash
# Pick from the active local or remote model catalog and configure the target.
omniroute configure claude
omniroute configure opencode --provider glm
omniroute configure qwen --model qwen/qwen3.8-max-preview --yes
```

`configure` ਵਰਤਮਾਨ ਵਿੱਚ `codex`, `claude`, `opencode`, `qwen`, `aider`, `goose`, `cline`, `continue`, `kilo`, ਅਤੇ `5dive` ਲਈ ਟੈਸਟ ਕੀਤੇ ਪਕਵਾਨਾਂ ਨੂੰ ਸੌਂਪਦਾ ਹੈ। IDE-ਸਿਰਫ਼, MITM, ਅਤੇ ਸਿਰਫ਼-ਗਾਈਡ ਕੈਟਾਲਾਗ ਐਂਟਰੀਆਂ ਸਪਸ਼ਟ `setup-*`/ਮੈਨੂਅਲ ਪ੍ਰਵਾਹ ਰਹਿੰਦੀਆਂ ਹਨ ਅਤੇ ਲਾਂਚ ਹੋਣ ਯੋਗ ਟੀਚਿਆਂ ਵਜੋਂ ਪੇਸ਼ ਨਹੀਂ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ।

> `setup-opencode` ਹੈ** ਹਲਕਾ ਓਪਨਾਈ-ਅਨੁਕੂਲ** OpenCode ਏਕੀਕਰਣ. ਇੱਥੇ ਇੱਕ ਅਮੀਰ ਪਲੱਗਇਨ ਏਕੀਕਰਣ ਵੀ ਹੈ — `omniroute setup opencode` — ਜੋ `@omniroute/opencode-plugin` ਨੂੰ ਸਥਾਪਿਤ ਕਰਦਾ ਹੈ। ਉਹ ਵੱਖ-ਵੱਖ ਹੁਕਮ ਹਨ; ਦਸਤਾਵੇਜ਼ ਉੱਪਰ ਦਿੱਤੀ ਸਾਰਣੀ `setup-opencode`.
>
> ਪਲੱਗਇਨ ਦੋ ਪੈਕੇਜਾਂ ਵਿੱਚ ਆਉਂਦੀ ਹੈ, ਇੱਕ ਪ੍ਰਤੀ OpenCode ਪ੍ਰਮੁੱਖ, ਕਿਉਂਕਿ ਦੋ ਲੋਡਰ ਵੱਖ-ਵੱਖ ਐਂਟਰੀ ਪੁਆਇੰਟਾਂ ਦੀ ਉਮੀਦ ਕਰਦੇ ਹਨ: OpenCode v1 ਲਈ `@omniroute/opencode-plugin` ਅਤੇ OpenCode v2 ਲਈ `@omniroute/opencode-plugin-v2` । v2 ਪੈਕੇਜ ਨਵਾਂ ਹੈ (`0.1.0`) ਅਤੇ ਇੱਕ ਹੋਸਟ ਇਕਰਾਰਨਾਮੇ ਦੀ ਪਾਲਣਾ ਕਰਦਾ ਹੈ ਜੋ ਅਜੇ ਵੀ ਚੱਲ ਰਿਹਾ ਹੈ, ਇਸਲਈ ਇਹ ਇੱਕ ਨੂੰ ਮੰਨਣ ਦੀ ਬਜਾਏ ਕੈਟਾਲਾਗ ਡਰਾਫਟ ਵਿੱਚ ਆਕਾਰ OpenCode ਬੀਜਾਂ ਨੂੰ ਪੜ੍ਹਦਾ ਹੈ। `opencode.json` ਵਿੱਚ `plugins` ਐਂਟਰੀ ਜੋੜ ਕੇ ਇਸਨੂੰ ਸਥਾਪਿਤ ਕਰੋ; `omniroute setup opencode` ਅਜੇ ਵੀ v1 ਪੈਕੇਜ ਨੂੰ ਇੰਸਟਾਲ ਕਰਦਾ ਹੈ। ਵਿਕਲਪ ਅਤੇ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਲੁੱਕਅੱਪ ਆਰਡਰ ਪੈਕੇਜ README ਵਿੱਚ ਹਨ।

## ਸਥਾਨਕ ਵਰਤੋਂ

ਜਦੋਂ OmniRoute `localhost:20128` ਉੱਤੇ ਚੱਲ ਰਿਹਾ ਹੋਵੇ, ਤਾਂ ਆਪਣੇ ਟੂਲ ਲਈ ਸਿਰਫ਼ ਸੈੱਟਅੱਪ ਕਮਾਂਡ ਚਲਾਓ। ਕੈਟਾਲਾਗ ਸਥਾਨਕ ਸਰਵਰ ਤੋਂ ਪ੍ਰਾਪਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

```bash
# Codex: ਹਰ ਮੇਲ ਖਾਂਦੇ ਮਾਡਲ ਲਈ ~/.codex/ ਵਿੱਚ ਇੱਕ ਪ੍ਰੋਫ਼ਾਈਲ ਲਿਖੋ
omniroute setup-codex
codex --profile glm52            # ਤਿਆਰ ਕੀਤੀ ਪ੍ਰੋਫ਼ਾਈਲ ਵਰਤੋ

# Claude Code: ਹਰ ਮਾਡਲ ਲਈ ਪ੍ਰੋਫ਼ਾਈਲਾਂ ਲਿਖੋ, ਫਿਰ ਇੱਕ ਲਾਂਚ ਕਰੋ
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode: ਸਾਰੇ ਕੈਟਾਲਾਗ ਮਾਡਲਾਂ ਸਮੇਤ openai-ਅਨੁਕੂਲ ਪ੍ਰਦਾਤਾ ਲਿਖੋ
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # {env:OMNIROUTE_API_KEY} ਰਾਹੀਂ ਹਵਾਲਾ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ, ਡਿਸਕ ਉੱਤੇ ਕਦੇ ਨਹੀਂ
opencode -m omniroute/glm/glm-5.2 "..."

# ਆਟੋ-ਡਿਸਕਵਰੀ ਤੋਂ ਬਿਨਾਂ ਟੂਲਾਂ ਨੂੰ ਇੱਕ ਸਪਸ਼ਟ ਮਾਡਲ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ:
omniroute setup-aider --model glm/glm-5.2
omniroute setup-qwen --model qwen/qwen3.8-max-preview

# ਕੁਝ ਵੀ ਲਿਖੇ ਬਿਨਾਂ ਪੂਰਵਦਰਸ਼ਨ ਕਰੋ:
omniroute setup-continue --dry-run
```

ਕੋਈ ਵੀ ਕੌਂਫਿਗ ਲਿਖੇ ਬਿਨਾਂ ਲਾਂਚ ਕਰੋ (ਸਿਰਫ਼ env-ਇੰਜੈਕਸ਼ਨ):

```bash
omniroute launch                 # Claude Code → ਸਥਾਨਕ OmniRoute
omniroute launch-codex           # Codex CLI → ਸਥਾਨਕ OmniRoute
omniroute launch-codex --profile glm52
omniroute run claude --model openai/gpt-5.4
omniroute run codex --model openai/gpt-5.4 --dry-run --json
omniroute run aider --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# ਸਪਸ਼ਟ ਕਮਾਂਡ ਪਾਥ: -- ਤੋਂ ਬਾਅਦ ਆਉਣ ਵਾਲੀ ਹਰ ਚੀਜ਼ ਨੂੰ ਜਿਉਂ ਦਾ ਤਿਉਂ ਅੱਗੇ ਭੇਜੋ
omniroute run claude -- --print-system-prompt "review this diff"
```

## ਰਿਮੋਟ ਵਰਤੋਂ

ਕਿਸੇ ਵੀ ਸੈੱਟਅੱਪ ਕਮਾਂਡ ਨੂੰ `--remote` + `--api-key` ਨਾਲ ਰਿਮੋਟ OmniRoute ਵੱਲ ਨਿਰਦੇਸ਼ਿਤ ਕਰੋ। ਕੈਟਾਲਾਗ ਰਿਮੋਟ ਤੋਂ ਪ੍ਰਾਪਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ; ਕੌਂਫਿਗ ਤੁਹਾਡੀ ਸਥਾਨਕ ਮਸ਼ੀਨ ਉੱਤੇ ਲਿਖਿਆ ਜਾਂਦਾ ਹੈ।

```bash
# ਰਿਮੋਟ VPS ਉੱਤੇ OpenCode, ਸਿਰਫ਼ glm/kimi ਮਾਡਲ ਰੱਖੋ
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx \
  --only glm,kimi
opencode -m omniroute/glm/glm-5.2 "..."   # ਪਹਿਲਾਂ OMNIROUTE_API_KEY ਐਕਸਪੋਰਟ ਕਰੋ

# ਰਿਮੋਟ ਕੈਟਾਲਾਗ ਤੋਂ Codex ਪ੍ਰੋਫ਼ਾਈਲਾਂ
omniroute setup-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# ਇੱਕ CLI ਨੂੰ ਸਿੱਧਾ ਰਿਮੋਟ ਵਿਰੁੱਧ ਲਾਂਚ ਕਰੋ
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

ਹਰ ਵਾਰ `--remote`/`--api-key` ਪਾਸ ਕਰਨ ਦੀ ਬਜਾਏ, ਇੱਕ ਵਾਰ ਲੌਗ ਇਨ ਕਰੋ ਅਤੇ **ਸਰਗਰਮ ਕੌਂਟੈਕਸਟ** ਨੂੰ ਇਹ ਆਪਣੇ-ਆਪ ਮੁਹੱਈਆ ਕਰਨ ਦਿਓ:

```bash
omniroute connect 192.168.0.15        # ਇੱਕ ਸਕੋਪਡ ਟੋਕਨ ਬਣਾਉਂਦਾ ਹੈ, ਕੌਂਟੈਕਸਟ ਸਟੋਰ ਕਰਦਾ ਹੈ
omniroute setup-codex                 # ← ਹੁਣ ਰਿਮੋਟ ਕੈਟਾਲਾਗ ਵਰਤਦਾ ਹੈ
omniroute setup-opencode              # ← ਇਹੀ
omniroute launch                      # ← ਰਿਮੋਟ ਵਿਰੁੱਧ Claude Code
```

ਕੌਂਟੈਕਸਟਾਂ, ਸਕੋਪਾਂ ਅਤੇ ਟੋਕਨ ਪ੍ਰਬੰਧਨ ਲਈ [ਰਿਮੋਟ ਮੋਡ](./REMOTE-MODE.md) ਵੇਖੋ।

## 5dive ਏਜੰਟ ਫ਼ਲੀਟਾਂ

[5dive](https://5dive.ai) ਲੰਬੇ ਸਮੇਂ ਤੱਕ ਚੱਲਣ ਵਾਲੇ ਕੋਡਿੰਗ ਏਜੰਟਾਂ ਦੀ ਇੱਕ ਫ਼ਲੀਟ ਚਲਾਉਂਦਾ ਹੈ, ਜਿਸ ਵਿੱਚ ਹਰ ਏਜੰਟ ਆਪਣੇ Unix ਯੂਜ਼ਰ ਅਧੀਨ ਇੱਕ systemd ਯੂਨਿਟ ਹੁੰਦਾ ਹੈ। ਇਹ ਖੁਦ ਕੋਈ ਕੋਡਿੰਗ CLI ਨਹੀਂ ਹੈ, ਇਸ ਲਈ `omniroute run` ਦੁਆਰਾ ਲਾਂਚ ਕਰਨ ਲਈ ਕੁਝ ਵੀ ਨਹੀਂ ਹੈ — `5dive` ਇੱਕ **ਸਿਰਫ਼-ਕੌਂਫਿਗਰ** ਟਾਰਗੇਟ ਹੈ।

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

ਦੋਵੇਂ ਰੂਪ ਇੱਕ 5dive **auth ਪ੍ਰੋਫ਼ਾਈਲ** ਲਿਖਦੇ ਹਨ, ਅਤੇ ਉਸ ਪ੍ਰੋਫ਼ਾਈਲ ਨਾਲ ਬੱਝੀ ਹਰ `claude` ਸੀਟ ਫਿਰ OmniRoute ਨਾਲ ਸੰਚਾਰ ਕਰਦੀ ਹੈ। ਇਸ ਟਾਰਗੇਟ ਲਈ ਤਿੰਨ ਗੱਲਾਂ ਖ਼ਾਸ ਹਨ:

- **ਇਹ ਫ਼ਲੀਟ ਹੋਸਟ ਉੱਤੇ root ਵਜੋਂ ਚੱਲਦਾ ਹੈ।** 5dive ਦੀਆਂ ਕਾਰਵਾਈਆਂ ਸਥਾਨਕ systemd ਯੂਨਿਟਾਂ ਅਤੇ root ਦੀ ਮਲਕੀਅਤ ਵਾਲੀ ਸਟੇਟ ਡਾਇਰੈਕਟਰੀ ਉੱਤੇ ਲਾਗੂ ਹੁੰਦੀਆਂ ਹਨ; ਕੋਈ ਰਿਮੋਟ ਮੋਡ ਨਹੀਂ ਹੈ। ਜਦੋਂ ਇਹ ਪਹਿਲਾਂ ਹੀ root ਨਹੀਂ ਹੁੰਦਾ, ਤਾਂ ਰੈਸਪੀ `sudo` ਰਾਹੀਂ ਆਪਣੇ ਆਪ ਨੂੰ ਮੁੜ ਚਲਾਉਂਦੀ ਹੈ (`--no-sudo` ਇਸਨੂੰ ਬੰਦ ਕਰਦਾ ਹੈ ਅਤੇ ਇਸ ਦੀ ਬਜਾਏ ਕਮਾਂਡ ਪ੍ਰਿੰਟ ਕਰਦਾ ਹੈ)।
- **ਐਂਡਪੌਇੰਟ `https://` ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ, ਜਦੋਂ ਤੱਕ ਇਹ ਲੂਪਬੈਕ ਨਾ ਹੋਵੇ।** ਏਜੰਟ ਦੀ API ਕੁੰਜੀ ਹਰ ਬੇਨਤੀ ਵਿੱਚ ਉਸ URL ਰਾਹੀਂ ਜਾਂਦੀ ਹੈ, ਅਤੇ 5dive ਮਸ਼ੀਨ ਤੋਂ ਬਾਹਰਲੇ ਪਲੇਨਟੈਕਸਟ ਐਂਡਪੌਇੰਟ ਨੂੰ ਅਸਵੀਕਾਰ ਕਰਦਾ ਹੈ। ਇੱਕ ਨਿੱਜੀ LAN ਪਤਾ ਵੀ ਕੋਈ ਅਪਵਾਦ ਨਹੀਂ ਹੈ।
- **ਹਰ ਸੀਟ ਦਾ ਆਪਣਾ ਮਾਡਲ ਪਿਨ ਪ੍ਰੋਫ਼ਾਈਲ ਨਾਲੋਂ ਵੱਧ ਤਰਜੀਹ ਰੱਖਦਾ ਹੈ।** ਪ੍ਰੋਫ਼ਾਈਲ ਵਿੱਚ `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` ਹੁੰਦਾ ਹੈ, ਪਰ ਸਟਾਕ ਮਾਡਲ id ਨਾਲ ਅਜੇ ਵੀ ਪਿਨ ਕੀਤੀ ਸੀਟ ਆਪਣੀ ਪਹਿਲੀ ਵਾਰੀ _"There's an issue with the selected model"_ ਗਲਤੀ ਨਾਲ ਅਸਫਲ ਹੋ ਜਾਂਦੀ ਹੈ। ਸੀਟਾਂ ਨੂੰ ਵੀ ਪਿਨ ਕਰਨ ਲਈ `--agent <name>` (ਦੁਹਰਾਇਆ ਜਾ ਸਕਦਾ ਹੈ) ਪਾਸ ਕਰੋ; ਜਦੋਂ ਤੁਸੀਂ ਅਜਿਹਾ ਨਹੀਂ ਕਰਦੇ, ਤਾਂ ਰੈਸਪੀ ਕਮਾਂਡ ਪ੍ਰਿੰਟ ਕਰਦੀ ਹੈ।

API ਕੁੰਜੀ 5dive ਨੂੰ **stdin** (`--api-key=-`) ਉੱਤੇ ਦਿੱਤੀ ਜਾਂਦੀ ਹੈ, ਇਸ ਲਈ ਇਹ `ps` ਆਉਟਪੁੱਟ ਵਿੱਚ ਕਦੇ ਦਿਖਾਈ ਨਹੀਂ ਦਿੰਦੀ।

ਪ੍ਰੋਫ਼ਾਈਲ ਨੂੰ ਇੱਕ ਇਕੱਲੇ ਮਾਡਲ ਦੀ ਬਜਾਏ OmniRoute **ਕੌਂਬੋ** ਵੱਲ ਨਿਰਦੇਸ਼ਿਤ ਕਰਨ ਨਾਲ ਹੀ ਫ਼ਲੀਟ ਨੂੰ ਪ੍ਰਦਾਤਾ ਫੇਲਓਵਰ ਮਿਲਦਾ ਹੈ: [#11578](https://github.com/diegosouzapw/OmniRoute/issues/11578) ਉੱਤੇ ਦਰਜ ਕੀਤੇ ਰਨ ਵਿੱਚ ਜਦੋਂ ਮੁੱਖ ਐਂਡਪੌਇੰਟ ਵਾਰੀ ਦੇ ਵਿਚਕਾਰ ਪੂਰੀ ਤਰ੍ਹਾਂ ਬੰਦ ਹੋ ਗਿਆ, ਤਾਂ ਏਜੰਟ ਨੇ ਆਪਣੇ ਬਾਕੀ ਕਦਮ ਫ਼ਾਲਬੈਕ ਉੱਤੇ ਪੂਰੇ ਕੀਤੇ ਅਤੇ ਆਊਟੇਜ ਨੂੰ ਕਦੇ ਉਜਾਗਰ ਨਹੀਂ ਕੀਤਾ।

## ਅੱਪਡੇਟ ਦੌਰਾਨ ਮੂਲ ਡਿਪੈਂਡੈਂਸੀਆਂ ਕਾਇਮ ਰੱਖਣਾ: `--include=optional`

ਜਦੋਂ ਤੁਸੀਂ `omniroute update` ਨਾਲ ਅੱਪਡੇਟ ਕਰਦੇ ਹੋ (ਪੁਸ਼ਟੀ ਕਰਨ ਤੋਂ ਬਾਅਦ, ਜਾਂ `--apply` ਨਾਲ),
OmniRoute ਇੰਸਟਾਲੇਸ਼ਨ ਨੂੰ ਪਹਿਲਾਂ ਤੋਂ ਸ਼ਾਮਲ `--include=optional` ਨਾਲ ਚਲਾਉਂਦਾ ਹੈ:

```bash
npm install -g omniroute@latest --include=optional
```

ਇਹ ਉਹ ਫ਼ਲੈਗ **ਨਹੀਂ** ਹੈ ਜੋ ਤੁਸੀਂ `omniroute update` ਨੂੰ ਦਿੰਦੇ ਹੋ — ਅੱਪਡੇਟਰ ਇਸਨੂੰ ਹਮੇਸ਼ਾ
ਲਾਗੂ ਕਰਦਾ ਹੈ। ਇਹ ਯਕੀਨੀ ਬਣਾਉਂਦਾ ਹੈ ਕਿ `optionalDependencies` (`better-sqlite3`, `keytar`,
`tls-client`, LLMLingua SLM ਸਟੈਕ) ਅੱਪਡੇਟ ਤੋਂ ਬਾਅਦ ਵੀ ਕਾਇਮ ਰਹਿਣ, ਭਾਵੇਂ ਤੁਹਾਡੀ npm ਸੰਰਚਨਾ ਵਿੱਚ
`omit=optional` ਸੈੱਟ ਹੋਵੇ, ਜੋ ਨਹੀਂ ਤਾਂ ਮੂਲ SQLite ਡਰਾਈਵਰ ਅਤੇ OS-ਕੀਰਿੰਗ ਬਾਈਂਡਿੰਗ ਨੂੰ
ਬਿਨਾਂ ਕਿਸੇ ਚੇਤਾਵਨੀ ਦੇ ਹਟਾ ਦੇਵੇਗੀ। ਲਾਗੂ ਕੀਤੇ ਬਿਨਾਂ ਸਟੀਕ ਕਮਾਂਡ ਦੀ ਝਲਕ ਦੇਖਣ ਲਈ:

```bash
omniroute update --dry-run
# [DRY RUN] ਇਹ ਚਲਾਇਆ ਜਾਵੇਗਾ: npm install -g omniroute@latest --include=optional
```

ਹੋਰ `omniroute update` ਫ਼ਲੈਗ (ਸਰੋਤ ਵਿੱਚ ਤਸਦੀਕ ਕੀਤੇ ਗਏ): `--check` (ਜੇ
ਪੁਰਾਣਾ ਹੋਵੇ ਤਾਂ ਐਗਜ਼ਿਟ 1), `--apply` (ਪੁੱਛੇ ਬਿਨਾਂ ਇੰਸਟਾਲ ਕਰੋ), `--changelog`, `--no-backup`,
`--yes`।

## `omniroute run gemini` ਰਾਹੀਂ Google Gemini CLI

`@google/gemini-cli` 0.50.0 ਦੇ ਮੁਕਾਬਲੇ ਕਰਾਰ ਦੀ ਤਸਦੀਕ ਕੀਤੀ ਗਈ: CLI
`GOOGLE_GEMINI_BASE_URL` ਦੀ ਪਾਲਣਾ ਕਰਦਾ ਹੈ ਅਤੇ ਉਸ ਉੱਤੇ `POST /v1beta/models/<model>:generateContent`
(ਅਤੇ `:streamGenerateContent?alt=sse`) ਬੇਨਤੀਆਂ ਭੇਜਦਾ ਹੈ — ਬਿਲਕੁਲ OmniRoute ਦੇ ਮੂਲ
Gemini ਇੰਟਰਫੇਸ (`/v1beta`) ਵਾਂਗ। `omniroute run gemini` ਇਸਨੂੰ ਆਪਣੇ ਆਪ ਜੋੜਦਾ ਹੈ:

- `GOOGLE_GEMINI_BASE_URL` → ਸਰਗਰਮ OmniRoute ਬੇਸ URL (ਰੂਟ, `/v1` ਤੋਂ ਬਿਨਾਂ);
- `GEMINI_API_KEY` → ਹੱਲ ਕੀਤਾ ਗਿਆ OmniRoute ਕ੍ਰੀਡੈਂਸ਼ਲ (ਵਿਕਲਪ/env/ਕੌਂਟੈਕਸਟ);
- ਇੱਕ **ਅਸਥਾਈ ਅਤੇ ਅਲੱਗ `GEMINI_CLI_HOME`** ਜਿਸਦੀ `.gemini/settings.json`
  `gemini-api-key` ਪ੍ਰਮਾਣੀਕਰਨ ਚੁਣਦੀ ਹੈ, ਤਾਂ ਜੋ ਸਟੋਰ ਕੀਤਾ Google OAuth ਸੈਸ਼ਨ (Code Assist)
  ਕਦੇ ਵੀ OmniRoute ਵੱਲ ਨਿਰਦੇਸ਼ਿਤ ਲਾਂਚ ਨੂੰ ਓਵਰਰਾਈਡ ਨਾ ਕਰੇ — ਐਗਜ਼ਿਟ ਤੋਂ ਬਾਅਦ ਹਟਾ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ;
- **env ਸਫ਼ਾਈ**: ਚਾਈਲਡ env ਵਿੱਚੋਂ `GOOGLE_API_KEY`,
  `GOOGLE_GENAI_USE_VERTEXAI` ਅਤੇ `GOOGLE_GENAI_USE_GCA` ਹਟਾਏ ਜਾਂਦੇ ਹਨ (ਜੋ ਪ੍ਰਮਾਣੀਕਰਨ ਨੂੰ
  Vertex/Code Assist ਵੱਲ ਮੋੜ ਦੇਣਗੇ), ਅਤੇ ਵਾਧੂ ਸੁਰੱਖਿਆ ਵਜੋਂ `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key`
  ਸੈੱਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ — ਹੋਰ `run` ਟਾਰਗੇਟਾਂ ਦੇ ਆਪਣੇ ਟਕਰਾਅ ਵਾਲੇ ਵੇਰੀਏਬਲਾਂ ਨਾਲ ਵੀ ਇਹੀ
  ਵਿਵਹਾਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ;
- `--provider`/`--model` ਤੋਂ `--model <id>` ਇੰਜੈਕਸ਼ਨ।

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

Gemini ਦਾ ਵਰਕਸਪੇਸ-ਭਰੋਸਾ ਸੁਰੱਖਿਆ-ਨਿਯਮ ਹੈੱਡਲੈੱਸ ਮੋਡ ਵਿੱਚ ਵੀ ਲਾਗੂ ਰਹਿੰਦਾ ਹੈ — ਖੁਦ
`--skip-trust` ਪਾਸ ਕਰੋ (ਜਾਂ ਡਾਇਰੈਕਟਰੀ ਉੱਤੇ ਇੰਟਰਐਕਟਿਵ ਢੰਗ ਨਾਲ ਭਰੋਸਾ ਕਰੋ); ਲਾਂਚਰ
ਜਾਣ-ਬੁੱਝ ਕੇ ਇਸਨੂੰ ਬਾਈਪਾਸ ਨਹੀਂ ਕਰਦਾ। ਇਹ ਲਾਂਚਰ **ACP
ਰਜਿਸਟ੍ਰੇਸ਼ਨ** (`src/lib/acp/registry.ts`, `gemini --acp`) ਤੋਂ ਵੱਖਰਾ ਹੈ, ਜੋ
`/dashboard/acp-agents` ਲਈ ਏਜੰਟ-ਪ੍ਰੋਟੋਕੋਲ ਇੰਟੀਗ੍ਰੇਸ਼ਨ ਵਜੋਂ ਕਾਇਮ ਰਹਿੰਦਾ ਹੈ।

## ਅਸਲ ਸਮੋਕ ਸਵੀਪ (ਚੋਣਵਾਂ)

ਨਿਰਧਾਰਤ ਲਾਂਚ-ਪਲਾਨ ਰਿਗ੍ਰੈਸ਼ਨ CI ਵਿੱਚ ਚੱਲਦਾ ਹੈ (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`)। ਇੱਕ ਅਸਲ OmniRoute ਸਰਵਰ ਦੇ ਵਿਰੁੱਧ ਅਸਲ
ਬਾਈਨਰੀਆਂ ਦੀ ਪੁਸ਼ਟੀ ਕਰਨ ਲਈ, ਇੱਕ ਚੋਣਵਾਂ ਹਾਰਨੈੱਸ
`tests/integration/upstream-cli-smoke.int.test.ts` ਉੱਤੇ ਮੌਜੂਦ ਹੈ। ਇਹ ਕਦੇ ਵੀ ਆਪਣੇ-ਆਪ ਨਹੀਂ ਚੱਲਦਾ
(ਹਰੇਕ ਉਪ-ਟੈਸਟ ਉਦੋਂ ਤੱਕ ਛੱਡ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ ਜਦੋਂ ਤੱਕ `RUN_CLI_SMOKE=1` ਨਾ ਹੋਵੇ), ਕ੍ਰੀਡੈਂਸ਼ਲ ਨੂੰ env-var
ਦੇ ਨਾਮ ਰਾਹੀਂ ਪਾਸ ਕਰਦਾ ਹੈ (ਕਦੇ ਵੀ ਮੁੱਲ ਰਾਹੀਂ ਨਹੀਂ), ਕਿਸੇ ਵੀ ਰਿਕਾਰਡ ਕੀਤੇ ਆਉਟਪੁੱਟ ਵਿੱਚੋਂ ਕੁੰਜੀ-ਵਰਗੀਆਂ ਸਤਰਾਂ ਨੂੰ ਲੁਕਾਉਂਦਾ ਹੈ, ਉਹਨਾਂ
ਟਾਰਗੇਟਾਂ ਨੂੰ ਛੱਡ ਦਿੰਦਾ ਹੈ ਜਿਨ੍ਹਾਂ ਦੀ ਬਾਈਨਰੀ ਇੰਸਟਾਲ ਨਹੀਂ ਹੈ, ਅਤੇ ਅਸਫਲਤਾਵਾਂ ਨੂੰ ਸਿਰਫ਼ ਬੂਲੀਅਨ ਦੀ ਬਜਾਏ
auth / upstream / config ਵਜੋਂ ਵਰਗੀਕ੍ਰਿਤ ਕਰਦਾ ਹੈ:

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

ਚੋਣਵਾਂ: `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` ਸਵੀਪ ਨੂੰ ਸੀਮਤ ਕਰਦਾ ਹੈ;
`OMNIROUTE_SMOKE_TIMEOUT_MS` ਹਰੇਕ ਟਾਰਗੇਟ ਲਈ 120s ਟਾਈਮਆਉਟ ਨੂੰ ਓਵਰਰਾਈਡ ਕਰਦਾ ਹੈ।
