ਇੱਕ ਕਸਟਮ JSON API ਨੋਡ ਇੱਕ JSON ਕਾਰੋਬਾਰੀ ਅੰਤਮ ਬਿੰਦੂ ਨੂੰ ਜੋੜਦਾ ਹੈ ਜੋ OpenAI ਜਾਂ Anthropic ਪ੍ਰੋਟੋਕੋਲ ਨਹੀਂ ਬੋਲਦਾ ਹੈ। OmniRoute ਇੱਕ JSON ਬੇਨਤੀ ਟੈਂਪਲੇਟ ਨੂੰ ਭਰਦਾ ਹੈ, ਇਸਨੂੰ ਪੂਰੇ ਅੰਤਮ ਬਿੰਦੂ URL ਤੇ ਭੇਜਦਾ ਹੈ, ਜਵਾਬ ਮਾਰਗ ਤੋਂ ਜਵਾਬ ਪੜ੍ਹਦਾ ਹੈ ਅਤੇ ਇਸਨੂੰ ਕਲਾਇੰਟ ਦੇ ਆਪਣੇ ਫਾਰਮੈਟ (ਚੈਟ ਸੰਪੂਰਨਤਾ, ਜਵਾਬ, ਸੰਦੇਸ਼, ...) ਵਿੱਚ ਗਾਹਕ ਨੂੰ ਵਾਪਸ ਕਰਦਾ ਹੈ।

ਇਹ `apiType: "custom-json"` ਨਾਲ ਇੱਕ OpenAI- ਅਨੁਕੂਲ ਨੋਡ ਹੈ; ਇਸਦੀ id ਦਾ ਰੂਪ `openai-compatible-custom-json-<suffix>` ਹੈ। ਡੈਸ਼ਬੋਰਡ ਫਾਰਮ ਅਜੇ ਉਪਲਬਧ ਨਹੀਂ ਹੈ। ਹੇਠਾਂ ਦਿੱਤੇ ਪ੍ਰਦਾਤਾ-ਨੋਡ API ਰਾਹੀਂ ਇਹਨਾਂ ਨੋਡਾਂ ਨੂੰ ਬਣਾਓ ਅਤੇ ਸੰਪਾਦਿਤ ਕਰੋ।

## ਇੱਕ ਨੋਡ ਬਣਾਓ

`POST /api/provider-nodes` (ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣਿਕਤਾ):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` ਹੈ** ਪੂਰਾ** ਅੰਤ ਬਿੰਦੂ URL ਕੁਝ ਵੀ ਜੋੜਿਆ ਨਹੀਂ ਹੈ (ਕੋਈ `/chat/completions`, ਕੋਈ `/models` ਨਹੀਂ) ਅਤੇ, ਹੋਰ OpenAI- ਅਨੁਕੂਲ ਨੋਡਾਂ ਦੇ ਉਲਟ, ਕੋਈ ਡਿਫਾਲਟ URL ਨਹੀਂ ਹੈ। ਇਹ ਲਾਜ਼ਮੀ ਤੌਰ 'ਤੇ `http(s)` ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ, ਬਿਨਾਂ ਏਮਬੇਡ ਕੀਤੇ ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ ਜਾਂ `#fragment`, ਅਤੇ ਇਹ ਹਰੇਕ ਪ੍ਰਦਾਤਾ ਨੋਡ ਵਾਂਗ ਹੀ ਆਊਟਬਾਉਂਡ URL ਗਾਰਡ ਪਾਸ ਕਰਦਾ ਹੈ, ਜਦੋਂ ਨੋਡ ਨੂੰ ਸੁਰੱਖਿਅਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਅਤੇ ਹਰ ਬੇਨਤੀ 'ਤੇ।
- ਇੱਕ ਨੋਡ ਜੋ ਕੁਨੈਕਸ਼ਨ ਕੁੰਜੀ ਭੇਜਦਾ ਹੈ (`authType` `bearer` ਜਾਂ `api-key`, ਮੂਲ ਸਮੇਤ) ਨੂੰ `https://` ਵਰਤੋਂ ਕਰਨੀ ਚਾਹੀਦੀ ਹੈ। ਪਲੇਨ `http://` ਨੂੰ ਸਿਰਫ਼ ਲੂਪਬੈਕ ਹੋਸਟ (`localhost`, `127.0.0.0/8`, `::1`) ਜਾਂ `authType: "none"` ਨਾਲ ਸਵੀਕਾਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਜੋ ਕੋਈ ਕੁੰਜੀ ਨਹੀਂ ਭੇਜਦਾ ਹੈ। ਨਿੱਜੀ LAN ਪਤੇ (`10.x`, `172.16-31.x`, `192.168.x`) ਛੋਟ ਨਹੀਂ ਹਨ: ਉਸ ਨੈੱਟਵਰਕ 'ਤੇ ਕੋਈ ਵੀ ਕੁੰਜੀ ਨੂੰ ਪੜ੍ਹ ਸਕਦਾ ਹੈ। ਅਜਿਹੇ ਨੋਡ ਨੂੰ ਸੁਰੱਖਿਅਤ ਕਰਨਾ `400` ਨਾਲ ਫੇਲ ਹੋ ਜਾਂਦਾ ਹੈ, ਅਤੇ ਪਹਿਲਾਂ ਸਟੋਰ ਕੀਤਾ ਨੋਡ ਫੇਲ ਹੋ ਜਾਂਦਾ ਹੈ, ਹਰੇਕ ਬੇਨਤੀ 'ਤੇ ਉਸੇ ਸੰਦੇਸ਼ ਨਾਲ ਬੰਦ ਹੋ ਜਾਂਦਾ ਹੈ, ਕੋਈ ਵੀ ਬੇਨਤੀ ਭੇਜਣ ਤੋਂ ਪਹਿਲਾਂ। ਇੱਕ LAN ਉੱਤੇ ਇੱਕ ਮੁੱਖ ਅੰਤ ਬਿੰਦੂ ਲਈ, ਇਸਨੂੰ TLS ਦੇ ਪਿੱਛੇ ਰੱਖੋ (ਉਦਾਹਰਨ ਲਈ ਇੱਕ ਉਲਟਾ ਪ੍ਰੌਕਸੀ)।
- `customJson` Zod ਨਾਲ ਪ੍ਰਮਾਣਿਤ ਕੀਤਾ ਗਿਆ ਹੈ; ਅਣਜਾਣ ਕੁੰਜੀਆਂ ਨੂੰ ਰੱਦ ਕਰ ਦਿੱਤਾ ਗਿਆ ਹੈ। ਹਰ ਖੇਤਰ ਵਿਕਲਪਿਕ ਹੈ:

| ਖੇਤਰ              | ਮੁੱਲ                                        | ਡਿਫਾਲਟ                                                 |
| ----------------- | ------------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                      | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                 | `bearer`                                               |
| `authHeader`      | ਸਿਰਲੇਖ ਦਾ ਨਾਮ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ ਜਦੋਂ `api-key` | `X-API-Key`                                            |
| `requestTemplate` | JSON ਵਸਤੂ (≤ 64 KB, ਡੂੰਘਾਈ ≤ 32)            | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | ਫੀਲਡ ਪਾਥ, ਜਾਂ ਪੂਰੇ ਸਰੀਰ ਲਈ `$`              | `choices[0].message.content`                           |

- ਰਾਜ਼ ਕੁਨੈਕਸ਼ਨ ਦੀ API ਕੁੰਜੀ ਵਿੱਚ ਰਹਿੰਦਾ ਹੈ, ਕਦੇ ਟੈਂਪਲੇਟ ਵਿੱਚ ਨਹੀਂ। `bearer` `Authorization: Bearer <key>` ਭੇਜਦਾ ਹੈ; `api-key` `<authHeader>: <key>` ਭੇਜਦਾ ਹੈ। ਪ੍ਰਮਾਣੀਕਰਣ ਸਿਰਲੇਖ `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` ਜਾਂ ਇੱਕ ਹੌਪ-ਬਾਈ-ਹੋਪ ਸਿਰਲੇਖ ਨਹੀਂ ਹੋ ਸਕਦਾ ਹੈ। `none` ਨਾਲ, ਕੁਨੈਕਸ਼ਨਾਂ ਨੂੰ ਕੋਈ ਕੁੰਜੀ ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ ਹੈ।
- ਵਾਧੂ ਸਥਿਰ ਸਿਰਲੇਖ ਨੋਡ ਦੇ ਨਿਯਮਤ `customHeaders` ਵਰਤੋਂ ਕਰਦੇ ਹਨ (ਹਰ ਦੂਜੇ ਅਨੁਕੂਲ ਨੋਡ ਵਾਂਗ ਹੀ ਪ੍ਰਮਾਣਿਕਤਾ; ਪ੍ਰਮਾਣੀ ਸਿਰਲੇਖਾਂ ਦੀ ਉੱਥੇ ਇਜਾਜ਼ਤ ਨਹੀਂ ਹੈ)।

`PUT /api/provider-nodes/<id>` ਉਸੇ `customJson` ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ ਅਤੇ ਨੋਡ ਦੇ ਹਰ ਮੌਜੂਦਾ ਕੁਨੈਕਸ਼ਨ 'ਤੇ `baseUrl` ਅਤੇ ਸੰਰਚਨਾ ਨੂੰ ਦੁਬਾਰਾ ਲਿਖਦਾ ਹੈ। `customJson` ਨੂੰ ਛੱਡਣ ਨਾਲ ਸਟੋਰ ਕੀਤੀ ਸੰਰਚਨਾ ਬਣੀ ਰਹਿੰਦੀ ਹੈ; `apiType` ਨੂੰ `chat` ਜਾਂ `responses` ਵਿੱਚ ਬਦਲਣ ਨਾਲ ਇਸਨੂੰ ਨੋਡ ਅਤੇ ਇਸਦੇ ਕਨੈਕਸ਼ਨਾਂ ਤੋਂ ਹਟਾ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।

ਫਿਰ ਆਮ ਵਾਂਗ ਨੋਡ ਨਾਲ ਕਨੈਕਸ਼ਨ ਜੋੜੋ (ਨੋਡ ਆਈਡੀ ਨਾਲ `POST /api/providers` ) ਅਤੇ `<prefix>/<model>` ਦੀ ਬੇਨਤੀ ਕਰੋ, ਉਦਾਹਰਨ ਲਈ `biz/assistant-v1`। ਅੰਤਮ ਬਿੰਦੂ ਕਿਸੇ ਮਾਡਲ ਸੂਚੀ ਨੂੰ ਉਜਾਗਰ ਨਹੀਂ ਕਰਦਾ, ਇਸਲਈ ਹੱਥ ਨਾਲ ਮਾਡਲ ਆਈਡੀ ਸ਼ਾਮਲ ਕਰੋ।

## ਟੈਂਪਲੇਟਾਂ ਦੀ ਬੇਨਤੀ ਕਰੋ

ਟੈਂਪਲੇਟ ਸਾਦੇ JSON ਹਨ। ਇੱਕ ਸਤਰ ਮੁੱਲ ਵਿੱਚ `{{placeholder}}` ਮਾਰਕਰ ਹੋ ਸਕਦੇ ਹਨ; ਕੁਝ ਵੀ ਮੁਲਾਂਕਣ ਜਾਂ ਚਲਾਇਆ ਨਹੀਂ ਜਾਂਦਾ ਹੈ, ਅਤੇ ਆਬਜੈਕਟ ਕੁੰਜੀਆਂ ਨੂੰ ਕਦੇ ਵੀ ਬਦਲਿਆ ਨਹੀਂ ਜਾਂਦਾ ਹੈ।

| ਪਲੇਸਹੋਲਡਰ            | ਮੁੱਲ                                                                      |
| -------------------- | ------------------------------------------------------------------------- |
| `{{prompt}}`         | ਨਵੀਨਤਮ ਉਪਭੋਗਤਾ ਸੁਨੇਹੇ ਦਾ ਟੈਕਸਟ (ਟੈਕਸਟ ਭਾਗ ਨਵੀਆਂ ਲਾਈਨਾਂ ਨਾਲ ਜੁੜਿਆ ਹੋਇਆ ਹੈ) |
| `{{messages}}`       | OpenAI ਚੈਟ ਫਾਰਮੈਟ ਵਿੱਚ ਗੱਲਬਾਤ                                             |
| `{{model}}`          | ਬੇਨਤੀ ਕੀਤੀ ਮਾਡਲ ਆਈ.ਡੀ., ਪ੍ਰਦਾਤਾ ਅਗੇਤਰ ਤੋਂ ਬਿਨਾਂ                           |
| `{{stream}}`         | ਹਮੇਸ਼ਾ ਇੱਕ JSON ਦਸਤਾਵੇਜ਼ ਨਾਲ ਅੰਤਮ ਬਿੰਦੂ ਦੇ ਜਵਾਬ `false` —                 |
| `{{request.<path>}}` | ਅਨੁਵਾਦਿਤ (OpenAI ਚੈਟ ਫਾਰਮੈਟ) ਬੇਨਤੀ ਦਾ ਇੱਕ ਖੇਤਰ                            |

- ਇੱਕ ਮੁੱਲ ਜੋ ਬਿਲਕੁਲ ਇੱਕ ਪਲੇਸਹੋਲਡਰ ਹੈ ਆਪਣੀ JSON ਕਿਸਮ ਨੂੰ ਰੱਖਦਾ ਹੈ (`"{{messages}}"` ਇੱਕ ਐਰੇ ਬਣ ਜਾਂਦਾ ਹੈ); ਇੱਕ ਲੰਬੀ ਸਤਰ ਦੇ ਅੰਦਰ ਇੱਕ ਪਲੇਸਹੋਲਡਰ ਨੂੰ ਟੈਕਸਟ ਦੇ ਰੂਪ ਵਿੱਚ ਸ਼ਾਮਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।
- ਇੱਕ ਪਲੇਸਹੋਲਡਰ ਜੋ ਕੁਝ ਵੀ ਨਹੀਂ ਹੱਲ ਕਰਦਾ ਹੈ, ਇੱਕ ਅਧੂਰਾ ਪੇਲੋਡ ਭੇਜਣ ਦੀ ਬਜਾਏ HTTP 400 ਨਾਲ ਬੇਨਤੀ ਨੂੰ ਅਸਫਲ ਕਰਦਾ ਹੈ।
- ਮਾਰਗ ਬਿੰਦੀ ਸੰਕੇਤ ਅਤੇ ਸੰਖਿਆਤਮਕ ਸੂਚਕਾਂਕ (`data.items[0].text`) ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਹਨ। `__proto__`, `prototype` ਅਤੇ `constructor` ਕੁੰਜੀਆਂ ਅਤੇ ਮਾਰਗਾਂ ਵਿੱਚ ਰੱਦ ਕਰ ਦਿੱਤਾ ਗਿਆ ਹੈ।

## ਜਵਾਬ

`responsePath` 'ਤੇ ਮੁੱਲ ਸਹਾਇਕ ਜਵਾਬ ਬਣ ਜਾਂਦਾ ਹੈ: ਸਤਰ ਲੰਘਦੀਆਂ ਹਨ, ਹੋਰ JSON ਮੁੱਲਾਂ ਨੂੰ ਲੜੀਬੱਧ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਇੱਕ ਗੁੰਮ ਜਾਂ `null` ਫੀਲਡ, ਜਾਂ ਇੱਕ ਬਾਡੀ ਜੋ JSON ਨਹੀਂ ਹੈ, HTTP 502 ਵਾਪਸ ਕਰਦਾ ਹੈ। ਅੱਪਸਟਰੀਮ ਗਲਤੀ ਸਥਿਤੀਆਂ ਨੂੰ ਪਾਸ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਸਟ੍ਰੀਮਿੰਗ ਕਲਾਇੰਟਸ ਲਈ OmniRoute ਪੂਰੇ JSON ਜਵਾਬ ਦਾ ਇੰਤਜ਼ਾਰ ਕਰਦਾ ਹੈ ਅਤੇ ਫਿਰ ਇਸਨੂੰ ਇੱਕ ਸਮਗਰੀ ਦੇ ਹਿੱਸੇ ਅਤੇ ਫਿਨਿਸ਼ ਭਾਗ ਦੇ ਰੂਪ ਵਿੱਚ ਛੱਡਦਾ ਹੈ; ਇਹ ਟੋਕਨ ਸਟ੍ਰੀਮਿੰਗ ਨਹੀਂ ਹੈ। ਟੂਲ ਕਾਲਾਂ ਅਤੇ ਵਰਤੋਂ ਖੇਤਰ ਮੈਪ ਨਹੀਂ ਕੀਤੇ ਗਏ ਹਨ।

## ਕਦੇ ਦੁਬਾਰਾ ਨਹੀਂ ਚਲਾਇਆ ਗਿਆ

ਵਪਾਰਕ ਬੇਨਤੀ ਦੇ ਮਾੜੇ ਪ੍ਰਭਾਵ ਹੋ ਸਕਦੇ ਹਨ ਭਾਵੇਂ ਇਹ ਅਸਫਲ ਹੋ ਜਾਂਦੀ ਹੈ। OmniRoute ਇਸ ਲਈ ਇਸਨੂੰ ਇੱਕ ਵਾਰ ਭੇਜਦਾ ਹੈ:

- ਕੋਈ ਟ੍ਰਾਂਸਪੋਰਟ ਦੁਬਾਰਾ ਕੋਸ਼ਿਸ਼ ਨਹੀਂ ਅਤੇ ਕੋਈ ਰੀਡਾਇਰੈਕਟ ਨਹੀਂ;
- ਕਿਸੇ ਹੋਰ ਕਨੈਕਸ਼ਨ (ਖਾਤਾ ਫਾਲਬੈਕ) 'ਤੇ ਦੁਬਾਰਾ ਕੋਸ਼ਿਸ਼ ਨਾ ਕਰੋ — ਅਸਫਲਤਾ ਜਿਵੇਂ ਹੈ-ਉਵੇਂ ਹੀ ਵਾਪਸ ਕਰ ਦਿੱਤੀ ਜਾਂਦੀ ਹੈ ਅਤੇ ਕੁਨੈਕਸ਼ਨ ਠੰਢਾ ਨਹੀਂ ਹੁੰਦਾ;
- ਅਗਲੇ ਕੰਬੋ ਟੀਚੇ 'ਤੇ ਕੋਈ ਫਾਲਬੈਕ ਨਹੀਂ, ਭਾਵੇਂ ਖਾਲੀ ਜਾਂ ਅਸਫਲ ਜਵਾਬ ਲਈ।

ਵੱਖਰੇ ਕਲਾਇੰਟ ਬੇਨਤੀਆਂ, ਅਤੇ ਫਿਊਜ਼ਨ ਪੈਨਲ ਜੋ ਸਪੱਸ਼ਟ ਤੌਰ 'ਤੇ ਕਈ ਮਾਡਲਾਂ ਨੂੰ ਕਾਲ ਕਰਦੇ ਹਨ, ਅਜੇ ਵੀ ਅੰਤਮ ਬਿੰਦੂ ਨੂੰ ਸੁਤੰਤਰ ਤੌਰ 'ਤੇ ਬੁਲਾਉਂਦੇ ਹਨ।

## ਇੱਕ ਨੋਡ ਦੀ ਜਾਂਚ ਕਰ ਰਿਹਾ ਹੈ

ਇੱਕ ਕੁਨੈਕਸ਼ਨ ਨੂੰ ਸੰਭਾਲਣਾ, ਕੁਨੈਕਸ਼ਨ** ਟੈਸਟ** ਬਟਨ ਅਤੇ ਬੈਕਗਰਾਊਂਡ ਹੈਲਥ ਚੈਕ ਕਦੇ ਵੀ ਐਂਡਪੁਆਇੰਟ ਨੂੰ ਕਾਲ ਨਹੀਂ ਕਰਦੇ ਹਨ: ਉਹ ਸਿਰਫ ਸਟੋਰ ਕੀਤੀ ਸੰਰਚਨਾ ਨੂੰ ਪ੍ਰਮਾਣਿਤ ਕਰਦੇ ਹਨ ਅਤੇ ਕਨੈਕਸ਼ਨ ਨੂੰ ਪ੍ਰਮਾਣਿਤ ਨਹੀਂ ਹੋਣ ਦੀ ਰਿਪੋਰਟ ਕਰਦੇ ਹਨ।

`POST /api/provider-nodes/validate` ਨਾਲ `"apiType": "custom-json"` ਅਤੇ ਨੋਡ ਖੇਤਰਾਂ (`baseUrl`, `apiKey`, `customJson`, ਵਿਕਲਪਿਕ `customHeaders` ਅਤੇ `modelId`) ਬਿਲਕੁਲ ਇੱਕ ਅਸਲੀ ਬੇਨਤੀ ਭੇਜਦਾ ਹੈ, `ping` ਦੇ ਨਾਲ ਨਵੀਨਤਮ ਉਪਭੋਗਤਾ ਟੈਕਸਟ ਵਜੋਂ। ਇਹ `{ "valid": true }` ਜਾਂ ਅੱਪਸਟ੍ਰੀਮ ਸਥਿਤੀ (ਕਦੇ ਵੀ ਅੱਪਸਟ੍ਰੀਮ ਬਾਡੀ ਨਹੀਂ) ਦਾ ਜਵਾਬ ਦਿੰਦਾ ਹੈ।

## ਸਟੋਰੇਜ

ਸੰਰਚਨਾ `provider_nodes.custom_json_config_json` (ਮਾਈਗ੍ਰੇਸ਼ਨ `240_provider_node_custom_json_config.sql`) ਵਿੱਚ ਸਟੋਰ ਕੀਤੀ ਜਾਂਦੀ ਹੈ ਅਤੇ ਹਰੇਕ ਕੁਨੈਕਸ਼ਨ ਦੇ `providerSpecificData.customJson` ਵਿੱਚ ਕਾਪੀ ਕੀਤੀ ਜਾਂਦੀ ਹੈ।

ਲਾਗੂ ਕਰਨਾ: `open-sse/utils/customJson.ts` (ਪ੍ਰਮਾਣਿਕਤਾ ਅਤੇ ਟੈਂਪਲੇਟਿੰਗ), `open-sse/executors/customJson.ts` (ਐਗਜ਼ੀਕਿਊਟਰ), `open-sse/services/combo/noReplayLatch.ts` ਅਤੇ `src/sse/handlers/chat/responsePolicies.ts` (ਨੋ-ਰੀਪਲੇ)।
