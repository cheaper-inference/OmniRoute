> **TL;DR**: OmniRoute ਹਰ ਬੇਨਤੀ ਦੀ ਟੋਕਨ ਵਰਤੋਂ ਨੂੰ ਟ੍ਰੈਕ ਕਰਦਾ ਹੈ, ਲਾਗਤ ਦੀ ਗਣਨਾ ਕਰਦਾ ਹੈ, ਹਰੇਕ API ਕੁੰਜੀ ਲਈ ਕੋਟਾ ਲਾਗੂ ਕਰਦਾ ਹੈ ਅਤੇ ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਵਿਸ਼ਲੇਸ਼ਣ ਦਿਖਾਉਂਦਾ ਹੈ। ਇਹ ਗਾਈਡ ਸਮਝਾਉਂਦੀ ਹੈ ਕਿ ਇਹ ਸਭ ਕਿਵੇਂ ਕੰਮ ਕਰਦਾ ਹੈ।

**ਸਰੋਤ:**

- `open-sse/services/usage.ts` (~70KB) — ਮੁੱਖ ਵਰਤੋਂ ਟ੍ਰੈਕਿੰਗ
- `src/lib/usageAnalytics.ts` (~10KB) — ਡੈਸ਼ਬੋਰਡ ਲਈ ਏਗਰੀਗੇਸ਼ਨ
- `src/lib/db/quotaSnapshots.ts` — ਇਤਿਹਾਸਕ ਕੋਟਾ ਡਾਟਾ
- `src/lib/db/usage*.ts` — ਵਰਤੋਂ ਨਾਲ ਸੰਬੰਧਿਤ ਕਈ DB ਮੋਡੀਊਲ

## ਸੰਖੇਪ ਜਾਣਕਾਰੀ

OmniRoute ਵਿੱਚੋਂ ਲੰਘਣ ਵਾਲੀ ਹਰ ਬੇਨਤੀ ਇੱਕ **ਵਰਤੋਂ ਰਿਕਾਰਡ** ਬਣਾਉਂਦੀ ਹੈ, ਜਿਸ ਵਿੱਚ ਇਹ ਜਾਣਕਾਰੀ ਦਰਜ ਹੁੰਦੀ ਹੈ:

- **ਪਛਾਣ**: ਕਿਹੜੀ API ਕੁੰਜੀ, ਪ੍ਰਦਾਤਾ, ਮਾਡਲ ਅਤੇ ਕੌਂਬੋ
- **ਟੋਕਨ**: ਪ੍ਰੌਮਪਟ ਟੋਕਨ, ਕੰਪਲੀਸ਼ਨ ਟੋਕਨ, ਕੈਸ਼ ਕੀਤੇ ਟੋਕਨ ਅਤੇ ਕੁੱਲ
- **ਲਾਗਤ**: USD ਰਕਮ (ਕੀਮਤ-ਨਿਰਧਾਰਣ ਡਾਟੇ ਤੋਂ ਗਣਨਾ ਕੀਤੀ ਗਈ)
- **ਸਮਾਂ**: ਲੇਟੈਂਸੀ, ਸ਼ੁਰੂਆਤ/ਸਮਾਪਤੀ ਟਾਈਮਸਟੈਂਪ
- **ਸਥਿਤੀ**: ਸਫਲਤਾ, ਗਲਤੀ, ਦਰ-ਸੀਮਿਤ ਆਦਿ

ਇਨ੍ਹਾਂ ਰਿਕਾਰਡਾਂ ਨੂੰ **ਵਿਸ਼ਲੇਸ਼ਣ** ਵਿੱਚ ਏਗਰੀਗੇਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, **ਕੋਟਾ ਸਨੈਪਸ਼ਾਟਾਂ** ਵਜੋਂ ਸਥਾਈ ਤੌਰ 'ਤੇ ਸੰਭਾਲਿਆ ਜਾਂਦਾ ਹੈ ਅਤੇ **ਹਰੇਕ ਕੁੰਜੀ ਲਈ ਬਜਟ ਸੀਮਾਵਾਂ** ਲਾਗੂ ਕਰਨ ਵਾਸਤੇ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ।

```
ਬੇਨਤੀ ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    ਵਿਸ਼ਲੇਸ਼ਣ   ਕੋਟਾ    ਬਿਲਿੰਗ
                    (ਡੈਸ਼ਬੋਰਡ) (ਲਾਗੂਕਰਨ) (ਨਿਰਯਾਤ)
```

## ਕੀ ਰਿਕਾਰਡ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

`usage.ts` ਸੇਵਾ ਹਰ ਬੇਨਤੀ ਲਈ ਇੱਕ **ਵਰਤੋਂ ਇਵੈਂਟ** ਦਰਜ ਕਰਦੀ ਹੈ:

| ਖੇਤਰ               | ਕਿਸਮ    | ਸਰੋਤ                                                       |
| ------------------ | ------- | ---------------------------------------------------------- |
| `id`               | string  | ਰਿਕਾਰਡ ਕਰਨ ਵੇਲੇ ਬਣਾਇਆ ਗਿਆ UUID                             |
| `apiKeyId`         | string  | ਉਹ API ਕੁੰਜੀ ਜਿਸ ਨੇ ਬੇਨਤੀ ਸ਼ੁਰੂ ਕੀਤੀ                       |
| `provider`         | string  | ਪ੍ਰਦਾਤਾ ID (openai, anthropic, ਆਦਿ)                        |
| `model`            | string  | ਮਾਡਲ ID (gpt-5, claude-opus-4-6, ਆਦਿ)                      |
| `comboId`          | string? | ਜੇ ਕਿਸੇ ਕੰਬੋ ਰਾਹੀਂ ਰੂਟ ਕੀਤਾ ਗਿਆ ਹੋਵੇ ਤਾਂ ਕੰਬੋ ID           |
| `promptTokens`     | number  | ਅੱਪਸਟ੍ਰੀਮ ਜਵਾਬ ਤੋਂ                                         |
| `completionTokens` | number  | ਅੱਪਸਟ੍ਰੀਮ ਜਵਾਬ ਤੋਂ                                         |
| `cachedTokens`     | number  | ਕੈਸ਼ ਹਿੱਟ ਟੋਕਨ (Anthropic ਪ੍ਰੌਮਪਟ ਕੈਸ਼ਿੰਗ, ਆਦਿ)            |
| `totalTokens`      | number  | ਪ੍ਰੌਮਪਟ + ਕੰਪਲੀਸ਼ਨ                                         |
| `costUsd`          | number  | ਕੀਮਤਾਂ ਦੇ ਡਾਟੇ ਤੋਂ ਗਣਨਾ ਕੀਤੀ ਗਈ                            |
| `latencyMs`        | number  | ਬੇਨਤੀ ਦੀ ਸ਼ੁਰੂ ਤੋਂ ਅੰਤ ਤੱਕ ਦੀ ਮਿਆਦ                         |
| `status`           | enum    | `success`, `error`, `rate_limited`, `timeout`, `cancelled` |
| `errorClass`       | string? | ਜੇ ਸਥਿਤੀ != ਸਫਲਤਾ ਹੋਵੇ ਤਾਂ ਤਰੁੱਟੀ ਦੀ ਸ਼੍ਰੇਣੀ               |
| `timestamp`        | string  | ISO 8601 UTC                                               |
| `metadata`         | object  | ਪਲੱਗਇਨ ਦੁਆਰਾ ਸ਼ਾਮਲ ਕੀਤਾ ਗਿਆ ਕਸਟਮ ਡਾਟਾ                      |

### ਟੋਕਨ ਕਿੱਥੋਂ ਆਉਂਦੇ ਹਨ

ਟੋਕਨ **ਜਵਾਬ ਹੈਂਡਲਰ** ਵਿੱਚ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ ਦੇ ਜਵਾਬ ਤੋਂ ਕੱਢੇ ਜਾਂਦੇ ਹਨ:

```ts
// open-sse/handlers/chatCore.ts ਤੋਂ
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

ਜਿਹੜੇ ਪ੍ਰਦਾਤਾ ਵਰਤੋਂ ਵਾਪਸ ਨਹੀਂ ਕਰਦੇ (ਕੁਝ ਵੈੱਬ-ਕੂਕੀ ਪ੍ਰਦਾਤਾ), ਉਨ੍ਹਾਂ ਲਈ OmniRoute `~4 chars per token` ਅੰਦਾਜ਼ਨ ਨਿਯਮ ਵਰਤ ਕੇ ਟੋਕਨਾਂ ਦਾ **ਅਨੁਮਾਨ ਲਗਾਉਂਦਾ ਹੈ** (`open-sse/services/autoCombo/pipelineRouter.ts` ਵੇਖੋ)।

### ਕੈਸ਼ ਕੀਤੇ ਟੋਕਨ

OmniRoute `cached_tokens` ਨੂੰ `prompt_tokens` ਤੋਂ ਵੱਖਰੇ ਤੌਰ 'ਤੇ ਟ੍ਰੈਕ ਕਰਦਾ ਹੈ ਕਿਉਂਕਿ:

- Anthropic ਪ੍ਰੌਮਪਟ ਕੈਸ਼ਿੰਗ ਕੈਸ਼ ਕੀਤੇ ਟੋਕਨਾਂ ਲਈ ਘੱਟ ਦਰ ਲੈਂਦੀ ਹੈ (ਆਮ ਦਰ ਦਾ 10%)
- ਕੁਝ ਪ੍ਰਦਾਤਾ `cache_read_input_tokens` ਵਾਪਸ ਕਰਦੇ ਹਨ ਜਿਨ੍ਹਾਂ ਦੀ ਕੀਮਤ ਵੱਖਰੇ ਢੰਗ ਨਾਲ ਨਿਰਧਾਰਤ ਕੀਤੀ ਜਾਣੀ ਚਾਹੀਦੀ ਹੈ
- ਵਿਸ਼ਲੇਸ਼ਣ **ਕੈਸ਼ ਹਿੱਟ ਦਰ** = `cached_tokens / prompt_tokens` ਦਿਖਾ ਸਕਦਾ ਹੈ

### ਕੈਸ਼-ਰਾਈਟ ਟੀਅਰ ਦੀ ਜਾਂਚ

ਵਿਸ਼ਲੇਸ਼ਣ ਡੈਸ਼ਬੋਰਡ ਦਾ ਪ੍ਰੌਮਪਟ-ਕੈਸ਼ ਸਿਹਤ ਪੈਨਲ ਪ੍ਰਦਾਤਾ ਦੁਆਰਾ ਰਿਪੋਰਟ ਕੀਤੀਆਂ
5-ਮਿੰਟ ਅਤੇ 1-ਘੰਟੇ ਦੀਆਂ ਕੈਸ਼ ਰਾਈਟਾਂ ਵਿੱਚ ਫ਼ਰਕ ਕਰਦਾ ਹੈ। Anthropic ਦੇ
`usage.cache_creation.ephemeral_5m_input_tokens` ਅਤੇ
`usage.cache_creation.ephemeral_1h_input_tokens` ਨੂੰ ਸਟ੍ਰੀਮਿੰਗ ਅਤੇ
ਗੈਰ-ਸਟ੍ਰੀਮਿੰਗ ਵਰਤੋਂ ਅਨੁਵਾਦ ਦੌਰਾਨ ਬਰਕਰਾਰ ਰੱਖਿਆ ਜਾਂਦਾ ਹੈ ਅਤੇ ਕਾਲ-ਲੌਗ ਸਾਰਾਂ ਨਾਲ ਸਟੋਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਸੰਯੁਕਤ
ਕੈਸ਼-ਰਾਈਟ ਕੁੱਲ ਨੂੰ ਇਨ੍ਹਾਂ ਸ਼੍ਰੇਣੀਆਂ ਵਿੱਚ ਦੂਜੀ ਵਾਰ ਨਹੀਂ ਜੋੜਿਆ ਜਾਂਦਾ।

ਸਿਰਫ਼ ਸੰਯੁਕਤ ਰਾਈਟ ਕਾਊਂਟਰ ਵਾਲੀਆਂ ਕਾਲਾਂ, ਪੁਰਾਣੇ ਰਿਕਾਰਡਾਂ ਸਮੇਤ, ਦਾ ਟੀਅਰ ਅਣਜਾਣ
ਹੁੰਦਾ ਹੈ। ਅੰਸ਼ਕ ਵੇਰਵੇ ਵਿੱਚ ਨਾ-ਵੰਡਿਆ ਬਾਕੀ ਹਿੱਸਾ ਅਣਜਾਣ ਰਹਿੰਦਾ ਹੈ; ਅਵੈਧ ਜਾਂ
ਵਿਰੋਧੀ ਕਾਊਂਟਰਾਂ ਨੂੰ ਚੁੱਪਚਾਪ TTL ਦੇਣ ਦੀ ਬਜਾਏ ਚਿੰਨ੍ਹਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਬੇਨਤੀ-ਪੱਖ ਦੇ
TTL ਚਿੰਨ੍ਹ ਬਿੱਲ ਕੀਤੇ ਗਏ ਟੀਅਰ ਦਾ ਸਬੂਤ ਨਹੀਂ ਹਨ।

ਪੈਨਲ ਦਾ API-ਸਮਤੁੱਲ ਰਾਈਟ ਅਨੁਮਾਨ ਸਿਰਫ਼ ਰਿਪੋਰਟ ਕੀਤੇ, ਕੀਮਤ-ਨਿਰਧਾਰਤ ਟੀਅਰਾਂ ਨੂੰ ਸ਼ਾਮਲ ਕਰਦਾ ਹੈ,
ਪੂਰੀ ਬੇਨਤੀ ਨੂੰ ਨਹੀਂ। ਮੂਲ Claude/Anthropic ਮਾਡਲ ਕੀਮਤਾਂ ਲਈ ਇਹ 5-ਮਿੰਟ ਰਾਈਟਾਂ ਵਾਸਤੇ
ਇਨਪੁੱਟ ਦਰ ਦਾ 1.25 ਗੁਣਾ ਅਤੇ 1-ਘੰਟੇ ਰਾਈਟਾਂ ਵਾਸਤੇ ਇਨਪੁੱਟ ਦਰ ਦਾ ਦੁੱਗਣਾ ਵਰਤਦਾ ਹੈ। ਗੁੰਮ
ਕੀਮਤ ਨੂੰ ਅਣਉਪਲਬਧ ਮੰਨਿਆ ਜਾਂਦਾ ਹੈ, ਜ਼ੀਰੋ ਨਹੀਂ। ਹਰ ਨਵੀਂ ਕਾਲ ਲੌਗ ਕਰਨ ਵੇਲੇ ਕੀਮਤਾਂ ਦਰਜ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ;
ਪੁਰਾਣੇ ਰਿਕਾਰਡਾਂ ਦੀ ਕੀਮਤ ਮੁੜ ਨਹੀਂ ਨਿਰਧਾਰਤ ਕੀਤੀ ਜਾਂਦੀ। ਇਸ ਲਈ ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਖਾਤਿਆਂ ਦਾ
API-ਸਮਤੁੱਲ ਅਨੁਮਾਨ ਹੋ ਸਕਦਾ ਹੈ, ਬਿਨਾਂ ਉਸ ਰਕਮ ਨੂੰ ਨਕਦ ਖਰਚ ਜਾਂ ਸਬਸਕ੍ਰਿਪਸ਼ਨ
ਕੋਟੇ ਵਜੋਂ ਲਾਗੂ ਕੀਤੇ। ਮੌਜੂਦਾ ਕੋਟੇ, ਬਜਟ ਅਤੇ ਪ੍ਰਦਾਤਾ ਦੀ ਸਟੀਕ ਲਾਗਤ ਦੀਆਂ ਗਣਨਾਵਾਂ ਬਦਲਦੀਆਂ ਨਹੀਂ ਹਨ।

ਇਹ ਜਾਂਚਾਂ ਮੌਜੂਦਾ ਸੀਮਿਤ ਕੈਸ਼-ਸਿਹਤ ਸਾਰ ਅਤੇ ਕਾਲ-ਲੌਗ
ਰਿਟੈਂਸ਼ਨ ਵਰਤਦੀਆਂ ਹਨ। ਇਹ ਬੇਨਤੀ ਦੇ TTL ਡਿਫ਼ਾਲਟਾਂ, ਰੂਟਿੰਗ ਜਾਂ ਖਾਤੇ ਦੀ ਚੋਣ ਨੂੰ ਨਹੀਂ ਬਦਲਦੀਆਂ।
ਪ੍ਰਦਾਤਾ ਨੂੰ ਭੇਜਣ ਦੇ ਬਿੰਦੂ 'ਤੇ ਕਲਾਇੰਟ ਦੁਆਰਾ ਮੰਗੇ ਗਏ TTL ਦੇ ਮੁਕਾਬਲੇ ਪ੍ਰਭਾਵੀ ਆਊਟਗੋਇੰਗ TTL ਨੂੰ ਦਰਜ ਕਰਨਾ
ਮੁਲਤਵੀ ਕੀਤਾ ਗਿਆ ਹੈ; ਇਹ ਪੈਨਲ ਰਸੀਦ ਦੇ ਟੀਅਰ ਰਿਪੋਰਟ ਕਰਦਾ ਹੈ, ਪ੍ਰਭਾਵੀ ਆਊਟਗੋਇੰਗ TTL ਨਹੀਂ।

ਲਾਗੂਕਰਨ: `src/lib/usage/cacheWriteEstimate.ts`,
`src/lib/usage/cacheHealth.ts`, ਅਤੇ `open-sse/utils/cacheWriteUsage.ts`।

## ਲਾਗਤ ਦੀ ਗਣਨਾ

ਲਾਗਤਾਂ ਦੀ ਗਣਨਾ LiteLLM ਤੋਂ ਸਿੰਕ ਕੀਤੇ **ਕੀਮਤ ਡੇਟਾ** (`src/lib/pricingSync.ts`) ਤੋਂ ਕੀਤੀ ਜਾਂਦੀ ਹੈ:

| ਮਾਡਲ              | ਇਨਪੁੱਟ $/1M | ਆਉਟਪੁੱਟ $/1M | ਕੈਸ਼ ਕੀਤਾ $/1M |
| ----------------- | ----------- | ------------ | -------------- |
| gpt-5             | $2.50       | $10.00       | —              |
| claude-opus-4-6   | $15.00      | $75.00       | $1.50          |
| claude-sonnet-4-5 | $3.00       | $15.00       | $0.30          |
| gemini-2.5-pro    | $1.25       | $10.00       | —              |

ਲਾਗਤ ਦਾ ਫ਼ਾਰਮੂਲਾ (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **ਕੈਸ਼ ਕੀਤੇ ਟੋਕਨਾਂ ਨੂੰ ਪ੍ਰੌਂਪਟ ਵਿੱਚੋਂ ਕਿਉਂ ਘਟਾਇਆ ਜਾਂਦਾ ਹੈ?** ਕੈਸ਼ ਕੀਤੇ ਹਿੱਸੇ ਦੀ ਕੀਮਤ ਵੱਖਰੇ ਤੌਰ 'ਤੇ ਲਗਾਈ ਜਾਂਦੀ ਹੈ; ਪੂਰੇ ਪ੍ਰੌਂਪਟ ਉੱਤੇ ਇਨਪੁੱਟ ਕੀਮਤ ਲਗਾਉਣ ਨਾਲ ਗਿਣਤੀ ਵੱਧ ਹੋ ਜਾਵੇਗੀ।

### ਕੀਮਤ ਸਿੰਕ

ਕੀਮਤ ਡੇਟਾ `/api/pricing/sync` ਐਂਡਪੌਇੰਟ ਰਾਹੀਂ LiteLLM ਤੋਂ ਆਪਣੇ-ਆਪ ਸਿੰਕ ਕੀਤਾ ਜਾਂਦਾ ਹੈ (ਇਹ ਬਿਲਟ-ਇਨ cron ਟਾਸਕ ਦੁਆਰਾ ਟ੍ਰਿਗਰ ਹੁੰਦਾ ਹੈ, ਨਾ ਕਿ ਕਿਸੇ ਯੂਜ਼ਰ-ਫੇਸਿੰਗ env var ਦੁਆਰਾ):

```bash
# ਹੱਥੀਂ ਟ੍ਰਿਗਰ
curl -X POST http://localhost:20128/api/pricing/sync
```

ਜਿਨ੍ਹਾਂ ਮਾਡਲਾਂ ਲਈ ਕੀਮਤ ਡੇਟਾ ਉਪਲਬਧ ਨਹੀਂ ਹੈ, ਉਨ੍ਹਾਂ ਲਈ OmniRoute ਅੰਦਰੂਨੀ ਔਸਤ ਦਰਾਂ (LiteLLM ਦੇ ਕੀਮਤ ਡੇਟਾ ਤੋਂ ਪ੍ਰਾਪਤ) ਦੀ ਵਰਤੋਂ ਕਰਕੇ **ਲਾਗਤ ਦਾ ਅਨੁਮਾਨ ਲਗਾਉਂਦਾ ਹੈ**।

## ਕੋਟਾ ਲਾਗੂ ਕਰਨਾ

ਹਰੇਕ API ਕੁੰਜੀ ਦਾ ਕੋਟਾ ਦੋ ਥਾਵਾਂ 'ਤੇ ਲਾਗੂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

1. **ਨਰਮ ਸੀਮਾ** (`quotaWarnAt`): ਵਰਤੋਂ ਨਿਰਧਾਰਤ ਹੱਦ ਤੋਂ ਵੱਧ ਹੋਣ 'ਤੇ ਡੈਸ਼ਬੋਰਡ ਚੇਤਾਵਨੀ
2. **ਸਖ਼ਤ ਸੀਮਾ** (`quotaLimit`): ਸੀਮਾ ਤੋਂ ਵੱਧ ਹੋਣ 'ਤੇ HTTP 429 ਨਾਲ ਬੇਨਤੀ ਰੱਦ ਕੀਤੀ ਜਾਂਦੀ ਹੈ

### ਸੰਰਚਨਾ

```ts
// ਹਰੇਕ API ਕੁੰਜੀ ਲਈ
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — ਚੇਤਾਵਨੀ ਦਿਖਾਓ
  quotaLimit: 10_00,    // $10.00 — ਪੂਰੀ ਰੋਕ
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### ਲਾਗੂ ਕਰਨ ਦਾ ਪ੍ਰਵਾਹ

```
ਬੇਨਤੀ ──▶ quotaCheck()
              │
              ├── ਸੀਮਾ ਦੇ ਅੰਦਰ?  ──▶ ਆਗਿਆ ਦਿਓ
              │
              └── ਸੀਮਾ ਤੋਂ ਵੱਧ?  ──▶ 429 ਬਹੁਤ ਜ਼ਿਆਦਾ ਬੇਨਤੀਆਂ
                                   Retry-After ਹੈਡਰ ਨਾਲ
```

### ਕੋਟਾ ਸਨੈਪਸ਼ਾਟ

`quotaSnapshots` ਸਾਰਣੀ ਰੁਝਾਨ ਵਿਸ਼ਲੇਸ਼ਣ ਲਈ **ਕੋਟੇ ਦੀ ਇਤਿਹਾਸਕ ਸਥਿਤੀ** ਸੰਭਾਲਦੀ ਹੈ:

| ਖੇਤਰ | ਵੇਰਵਾ |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | ਉਹ ਕੁੰਜੀ ਜਿਸ ਦੀ ਨਿਗਰਾਨੀ ਕੀਤੀ ਜਾ ਰਹੀ ਹੈ |
| `window` | "day" | "week" | "month" |
| `used` | ਇਸ ਸਮਾਂ ਅੰਤਰਾਲ ਵਿੱਚ ਵਰਤੀ ਗਈ ਲਾਗਤ (ਸੈਂਟ) |
| `limit` | ਸੀਮਾ (ਸੈਂਟ) |
| `resetAt` | ਸਮਾਂ ਅੰਤਰਾਲ ਕਦੋਂ ਰੀਸੈੱਟ ਹੁੰਦਾ ਹੈ |
| `createdAt` | ਸਨੈਪਸ਼ਾਟ ਕਦੋਂ ਲਿਆ ਗਿਆ ਸੀ |

ਸਨੈਪਸ਼ਾਟ **ਹਰ ਉਸ ਬੇਨਤੀ 'ਤੇ** ਲਏ ਜਾਂਦੇ ਹਨ ਜਿਸ ਦੀ ਲਾਗਤ > 0 ਹੁੰਦੀ ਹੈ, ਅਤੇ ਇਹਨਾਂ ਦੀ ਵਰਤੋਂ ਇਹਨਾਂ ਕੰਮਾਂ ਲਈ ਕੀਤੀ ਜਾਂਦੀ ਹੈ:

- ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਕੋਟੇ ਦੀ ਪ੍ਰਗਤੀ ਪੱਟੀ ਦਿਖਾਉਣਾ
- 30 ਦਿਨਾਂ ਦੇ ਕੋਟਾ ਰੁਝਾਨ ਚਾਰਟ ਦਿਖਾਉਣਾ
- ਵਰਤੋਂ ਸੀਮਾ ਦੇ ਨੇੜੇ ਪਹੁੰਚਣ 'ਤੇ ਚੇਤਾਵਨੀਆਂ ਚਾਲੂ ਕਰਨਾ

## ਸੰਭਾਲ ਅਤੇ ਸਫ਼ਾਈ

ਵਰਤੋਂ ਦਾ ਡਾਟਾ ਹਰੇਕ ਬੇਨਤੀ ਨਾਲ ~1-10KB ਵਧਦਾ ਹੈ। ਵੱਡੇ ਪੈਮਾਨੇ 'ਤੇ, ਇਹ ਮਾਤਰਾ ਕਾਫ਼ੀ ਵੱਡੀ ਹੋ ਸਕਦੀ ਹੈ।

### ਸੰਭਾਲ ਦੀਆਂ ਸੈਟਿੰਗਾਂ

ਵਰਤੋਂ ਦੇ ਇਤਿਹਾਸ ਦੀ ਸੰਭਾਲ UI ਵਿੱਚ ਡਾਟਾਬੇਸ ਸੈਟਿੰਗਾਂ ਰਾਹੀਂ ਜਾਂ `/api/settings/database` ਰਾਹੀਂ ਕੌਂਫਿਗਰ ਕੀਤੀ ਜਾਂਦੀ ਹੈ।

ਮੂਲ ਰੂਪ ਵਿੱਚ, ਵਰਤੋਂ ਦਾ ਇਤਿਹਾਸ **90 ਦਿਨਾਂ** ਲਈ ਸੰਭਾਲਿਆ ਜਾਂਦਾ ਹੈ।

### ਸਫ਼ਾਈ

ਪੁਰਾਣੇ ਰਿਕਾਰਡਾਂ ਦੀ ਸਫ਼ਾਈ `src/lib/db/cleanup.ts` ਵੱਲੋਂ ਕੀਤੀ ਜਾਂਦੀ ਹੈ:

- ਬੈਕਗ੍ਰਾਊਂਡ cron ਪ੍ਰਕਿਰਿਆ ਵੱਲੋਂ ਸ਼ੁਰੂ ਕੀਤੀ ਜਾਂਦੀ ਹੈ
- `usage_history` ਵਿੱਚੋਂ ਕੌਂਫਿਗਰ ਕੀਤੀ `usageHistory` ਸੰਭਾਲ ਸੈਟਿੰਗ ਤੋਂ ਪੁਰਾਣੇ ਰਿਕਾਰਡ ਮਿਟਾਉਂਦੀ ਹੈ

### ਸਟੋਰੇਜ ਦਾ ਅੰਦਾਜ਼ਾ

| ਬੇਨਤੀ ਦਰ            | 30 ਦਿਨਾਂ ਦੀ ਸਟੋਰੇਜ | 90 ਦਿਨਾਂ ਦੀ ਸਟੋਰੇਜ |
| ------------------- | ------------------ | ------------------ |
| 100 ਬੇਨਤੀਆਂ/ਦਿਨ     | ~3MB               | ~9MB               |
| 1,000 ਬੇਨਤੀਆਂ/ਦਿਨ   | ~30MB              | ~90MB              |
| 10,000 ਬੇਨਤੀਆਂ/ਦਿਨ  | ~300MB             | ~900MB             |
| 100,000 ਬੇਨਤੀਆਂ/ਦਿਨ | ~3GB               | ~9GB               |

ਬਹੁਤ ਜ਼ਿਆਦਾ ਟ੍ਰੈਫ਼ਿਕ ਲਈ, ਇਨ੍ਹਾਂ ਬਾਰੇ ਵਿਚਾਰ ਕਰੋ:

- ਡਾਟਾਬੇਸ ਸੈਟਿੰਗਾਂ ਰਾਹੀਂ ਸੰਭਾਲ ਦੀ ਮਿਆਦ ਘਟਾਉਣਾ
- ਕੱਚੇ ਰਿਕਾਰਡਾਂ ਦੀ ਥਾਂ `aggregated_metrics` ਵਰਤਣਾ (ਸਿਰਫ਼ ਵਿਸ਼ਲੇਸ਼ਣ ਲਈ)

## ਲਾਗਤ ਅਨੁਕੂਲਨ ਲਈ ਸੁਝਾਅ

### 1. ਸਹੀ ਮਾਡਲ ਵਰਤੋ

```bash
# ਤੁਰੰਤ ਜਵਾਬ — ਸਸਤਾ + ਤੇਜ਼ ਵਰਤੋ
curl -d '{"model":"auto/fast","messages":[...]}'

# ਗੁੰਝਲਦਾਰ ਕੰਮ — ਗੁਣਵੱਤਾ ਵਰਤੋ
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. ਕੈਸ਼ਿੰਗ ਚਾਲੂ ਕਰੋ

Anthropic ਪ੍ਰੌਮਪਟ ਕੈਸ਼ਿੰਗ **ਦੁਹਰਾਏ ਗਏ ਸੰਦਰਭ 'ਤੇ 90% ਦੀ ਬਚਤ** ਕਰਦੀ ਹੈ:

```ts
// ਕੈਸ਼ਿੰਗ ਆਪਣੇ ਆਪ ਹੁੰਦੀ ਹੈ — ਬਸ ਉਹੀ ਵੱਡਾ ਸਿਸਟਮ ਪ੍ਰੌਮਪਟ ਸ਼ਾਮਲ ਕਰੋ
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // ਆਪਣੇ ਆਪ ਕੈਸ਼ ਕੀਤਾ ਜਾਵੇਗਾ
  messages: [{ role: "user", content: "..." }],
});
```

### 3. ਕੰਪ੍ਰੈਸ਼ਨ ਵਰਤੋ

RTK + Caveman ਕੰਪ੍ਰੈਸ਼ਨ **ਟੂਲਾਂ ਦੀ ਵੱਧ ਵਰਤੋਂ ਵਾਲੇ ਸੈਸ਼ਨਾਂ ਵਿੱਚ 15-95% ਦੀ ਬਚਤ** ਕਰਦੀ ਹੈ:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. ਹਰੇਕ ਕੁੰਜੀ ਲਈ ਕੋਟੇ ਸੈੱਟ ਕਰੋ

ਬੇਕਾਬੂ ਲਾਗਤਾਂ ਨੂੰ ਰੋਕਣ ਲਈ ਹਮੇਸ਼ਾ `quotaLimit` ਸੈੱਟ ਕਰੋ:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // $10/ਮਹੀਨਾ ਦੀ ਸੀਮਾ
```

### 5. ਸਭ ਤੋਂ ਵੱਧ ਵਰਤੋਂ ਕਰਨ ਵਾਲਿਆਂ ਦੀ ਜਾਂਚ ਕਰੋ

API ਕੁੰਜੀ ਅਨੁਸਾਰ ਸਮੂਹ ਬਣਾਉਣ ਅਤੇ ਲਾਗਤ ਅਨੁਸਾਰ ਕ੍ਰਮਬੱਧ ਕਰਨ ਲਈ ਡੈਸ਼ਬੋਰਡ ਜਾਂ **`/api/usage/analytics`** ਵਰਤੋ:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## ਸਮੱਸਿਆ ਨਿਵਾਰਨ

### "ਲਾਗਤ ਉਮੀਦ ਨਾਲੋਂ ਵੱਧ ਹੈ"

1. **`/api/usage/analytics?groupBy=model`** ਦੀ ਜਾਂਚ ਕਰੋ — ਮਹਿੰਗਾ ਮਾਡਲ ਲੱਭੋ
2. **`/api/usage/analytics?groupBy=apiKey`** ਦੀ ਜਾਂਚ ਕਰੋ — ਵੱਧ ਵਰਤੋਂ ਕਰਨ ਵਾਲੇ ਨੂੰ ਲੱਭੋ
3. ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਕੀਮਤਾਂ ਦਾ ਡਾਟਾ ਅੱਪ ਟੂ ਡੇਟ ਹੈ: `POST /api/pricing/sync`

### "ਰਿਕਾਰਡ ਗਾਇਬ ਹਨ"

- ਡੈਸ਼ਬੋਰਡ → ਡਾਟਾਬੇਸ → ਸਫ਼ਾਈ ਦੇ ਅਧੀਨ DB ਰਿਟੈਂਸ਼ਨ ਸੈਟਿੰਗਾਂ ਦੀ ਜਾਂਚ ਕਰੋ — ਪੁਰਾਣੇ ਰਿਕਾਰਡ ਨਿਯਮਿਤ ਸਫ਼ਾਈ ਕਾਰਜ (`src/lib/db/cleanup.ts`) ਦੁਆਰਾ ਮਿਟਾਏ ਜਾਂਦੇ ਹਨ
- `src/lib/db/usage*.ts` ਵਿੱਚ ਗਲਤੀਆਂ ਦੀ ਜਾਂਚ ਕਰੋ — DB ਵਿੱਚ ਲਿਖਣ ਦੀਆਂ ਅਸਫਲਤਾਵਾਂ ਲੌਗ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ ਪਰ ਦਿਖਾਈਆਂ ਨਹੀਂ ਜਾਂਦੀਆਂ
- ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਬੇਨਤੀ ਅਸਲ ਵਿੱਚ `chatCore` ਤੱਕ ਪਹੁੰਚੀ ਸੀ — ਕੰਬੋ ਰੂਟਿੰਗ ਦੀ ਜਾਂਚ ਕਰੋ

### "ਕੋਟਾ ਲਾਗੂ ਨਹੀਂ ਹੋ ਰਿਹਾ"

- ਕੁੰਜੀ ਦੀ `quotaLimit` ਸੈਟਿੰਗ ਦੀ ਜਾਂਚ ਕਰੋ
- ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ `quotaWindow` ਸਹੀ ਢੰਗ ਨਾਲ ਸੈੱਟ ਹੈ
- `quotaSnapshots` ਰਿਕਾਰਡ ਲੱਭੋ — ਇਹ ਹਰੇਕ ਬੇਨਤੀ 'ਤੇ ਬਣਨੇ ਚਾਹੀਦੇ ਹਨ
