`devin-cli-agentic` ਅਸਲ Claude Code ਰਨਟਾਈਮ ਨੂੰ OmniRoute ਦਾ ਸਥਾਨਕ Anthropic
Messages ਐਂਡਪੌਇੰਟ ਵਰਤਣ ਦਿੰਦਾ ਹੈ, ਜਦਕਿ ਅਧਿਕਾਰਤ Devin CLI ACP stdio ਰਾਹੀਂ ਮਾਡਲ ਜਵਾਬ
ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ। ਇਹ ਮੌਜੂਦਾ Anthropic, Claude OAuth, Claude Web, ਜਾਂ `devin-cli`
ਪ੍ਰੋਵਾਈਡਰਾਂ ਵਿੱਚ ਕੋਈ ਤਬਦੀਲੀ ਨਹੀਂ ਕਰਦਾ।

ਕਲਾਇੰਟ-ਮਲਕੀਅਤ ਵਾਲੀਆਂ ਟੂਲ ਕਾਲਾਂ ਲਈ, `devin-cli-agentic` (ਉਪਨਾਮ `dva`), ਯਾਨੀ
Claude-ਫਾਰਮੈਟ ਵਾਲੇ ਟੂਲ-ਸਮਰੱਥ ਪ੍ਰੋਵਾਈਡਰ ਰਾਹੀਂ ਰੂਟ ਕਰੋ। ਪੁਰਾਣਾ `devin-cli` (`dv`) ACP ਐਗਜ਼ਿਕਿਊਟਰ
ਕੇਵਲ-ਟੈਕਸਟ ਹੈ: ਇਹ Devin ਦਾ ਬਿਨਾਂ-ਟੂਲਾਂ ਵਾਲਾ ਸਮਰਾਈਜ਼ਰ ਚਲਾਉਂਦਾ ਹੈ ਅਤੇ ਟੂਲ ਕਾਲਾਂ ਵਾਪਸ ਨਹੀਂ ਕਰ ਸਕਦਾ।
ਇਸਦਾ ਮਾਡਲ ਮੈਟਾਡੇਟਾ ਇਸੇ ਅਨੁਸਾਰ ਚਿੰਨ੍ਹਿਤ ਕੀਤਾ ਗਿਆ ਹੈ, ਤਾਂ ਜੋ ਟੂਲ-ਲੋੜੀਂਦੀ ਕੰਬੋ ਰੂਟਿੰਗ ਇਸ ਤੋਂ ਬਚੇ।

> **ਮੌਜੂਦਾ ਸਥਿਤੀ: Claude Code `2.1.258` 'ਤੇ ਪਿੰਨ ਕੀਤਾ ਹੋਇਆ; ਆਫਲਾਈਨ ਅਤੇ ਲਾਈਵ ਪ੍ਰਮਾਣੀਕਰਨ ਆਖਰੀ ਵਾਰ
> `2.1.220` 'ਤੇ ਦਰਜ ਕੀਤਾ ਗਿਆ ਸੀ।** `2.1.220` ਪਿੰਨ ਨੇ Devin CLI
> `3000.2.17` ਅਤੇ ਮਾਡਲ `swe-1-7-lightning` ਰਾਹੀਂ ਤਿੰਨ ਅਲੱਗ-ਥਲੱਗ ਦ੍ਰਿਸ਼ ਪੂਰੇ ਕੀਤੇ; ਉਸ ਅੰਤਿਮ ਲਾਈਵ ਰਨ ਨੇ ਕਲਾਇੰਟ-ਮਲਕੀਅਤ ਵਾਲੇ `Read`,
> `Edit`, ਅਤੇ `Bash` ਟਰਨਾਂ, ਸਫਲ `npm test` ਨਤੀਜਿਆਂ, ਪ੍ਰੋਜੈਕਟ ਕਮਾਂਡ ਅਤੇ ਸਕਿੱਲ
> ਖੋਜ, ਕੇਵਲ-Devin ਰੂਟਿੰਗ, ਅਤੇ ਸਿਫ਼ਰ Claude ਈਗ੍ਰੈਸ ਨੂੰ ਸਾਬਤ ਕੀਤਾ। ਫਿਰ ਪਿੰਨ ਨੂੰ `2.1.258`
> ਤੱਕ ਵਧਾਇਆ ਗਿਆ (ਉਹ CLI ਪੀੜ੍ਹੀ ਜਿਸਦੀ OmniRoute ਦੀ Claude ਪਛਾਣ ਨਕਲ ਕਰਦੀ ਹੈ, ਅਤੇ ਪਹਿਲੀ ਲਾਈਨ ਜੋ
> Fable 5.1 ਟੀਅਰ ਨੂੰ ਮੂਲ ਰੂਪ ਵਿੱਚ ਸ਼ਾਮਲ ਕਰਦੀ ਹੈ)। ਨਵੇਂ ਪਿੰਨ 'ਤੇ ਪਿੰਨ ਕੀਤੀ ਬੇਸ ਇਮੇਜ ਵਿੱਚ ਇੰਸਟਾਲੇਸ਼ਨ ਲੇਅਰ ਅਤੇ `claude --version` ਦੀ
> ਪੁਸ਼ਟੀ ਕੀਤੀ ਗਈ ਸੀ, ਅਤੇ ਬ੍ਰਿਜ ਯੂਨਿਟ ਸੂਟ, `compose config` ਅਤੇ
> ਸਥਿਰ ਆਈਸੋਲੇਸ਼ਨ ਸਬੂਤ ਪਾਸ ਹੁੰਦੇ ਹਨ — ਪਰ ਆਫਲਾਈਨ ਮੌਕ ਦ੍ਰਿਸ਼ ਅਤੇ ਲਾਈਵ ਤਿੰਨ-ਦ੍ਰਿਸ਼
> ਸੂਟ ਨੂੰ ਹਾਲੇ ਦੁਬਾਰਾ ਨਹੀਂ ਚਲਾਇਆ ਗਿਆ। ਇਸ ਪਿੰਨ ਨਾਲ ਬ੍ਰਿਜ 'ਤੇ ਭਰੋਸਾ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਇਨ੍ਹਾਂ ਨੂੰ ਦੁਬਾਰਾ ਚਲਾਓ
> ("ਪਿੰਨ ਕੀਤੇ ਟੂਲ ਅੱਪਡੇਟ ਕਰਨਾ" ਵੇਖੋ)।

## ਆਰਕੀਟੈਕਚਰ

```text
Claude Code 2.1.258 (ਅਲੱਗ-ਥਲੱਗ ਗੈਰ-root Linux ਕੰਟੇਨਰ)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-ਫਾਰਮੈਟ, ਬਿਨਾਂ-ਪ੍ਰਮਾਣੀਕਰਨ ਵਾਲਾ ਪ੍ਰੋਵਾਈਡਰ)
  -> devin acp --agent-type summarizer (ਅਧਿਕਾਰਤ ACP stdio, ਕੋਈ Devin ਟੂਲ ਨਹੀਂ)
  -> ਸਮਰਪਿਤ devin-auth ਵਾਲਿਊਮ ਵਿੱਚ Devin ਖਾਤਾ
```

ਅਧਿਕਾਰਤ CLI ਦਾ ਡਿਫੌਲਟ ACP ਏਜੰਟ ਆਪਣੇ ਟੂਲ ਚਲਾ ਸਕਦਾ ਹੈ, ਇਸ ਲਈ ਇਹ ਬ੍ਰਿਜ
ਇਸਦੀ ਵਰਤੋਂ ਨਹੀਂ ਕਰਦਾ। ਇਹ ਨਿਸ਼ਚਿਤ `summarizer` ACP ਏਜੰਟ ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ, ਜਿਸਦੇ ਅਧਿਕਾਰਤ CLI ਮੋਡ ਵਿੱਚ ਕੋਈ ਟੂਲ ਨਹੀਂ ਹਨ, ਅਤੇ
ਸੀਰੀਅਲਾਈਜ਼ ਕੀਤੀ Anthropic ਬੇਨਤੀ ਨੂੰ ਐਗਜ਼ਿਕਿਊਸ਼ਨ ਟ੍ਰੇਸ ਵਜੋਂ ਫਰੇਮ ਕਰਦਾ ਹੈ। ਜਦੋਂ ਕਿਸੇ ਹੋਰ Claude-ਮਲਕੀਅਤ ਵਾਲੀ
ਕਾਰਵਾਈ ਦੀ ਲੋੜ ਹੋਵੇ, ਤਾਂ ਜਵਾਬ ਵਿੱਚ ਬਿਲਕੁਲ ਇੱਕ ਕਲਾਇੰਟ ਟੂਲ ਐਨਵਲਪ ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ। ਕਿਸੇ ਵੀ ACP
`tool_call` ਜਾਂ `tool_call_update` ਨੂੰ ਜਵਾਬ ਸਫਲ ਵਜੋਂ ਰਿਪੋਰਟ ਕੀਤੇ ਜਾਣ ਤੋਂ ਪਹਿਲਾਂ ਹੀ ਰੱਦ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।

`open-sse/executors/devin-agentic/serializer.ts` ਵਿੱਚ ਮੌਜੂਦ ਸੀਰੀਅਲਾਈਜ਼ਰ `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, ਅਤੇ
Claude Code ਵੱਲੋਂ ਦਿੱਤੇ ਟੂਲਾਂ ਨੂੰ ਬਰਕਰਾਰ ਰੱਖਦਾ ਹੈ। ਇਮੇਜਾਂ ਅਤੇ ਅਣਜਾਣ ਬਲਾਕਾਂ ਲਈ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਅਸਫਲਤਾ ਹੁੰਦੀ ਹੈ। ਵੱਡੇ ਟੂਲ ਨਤੀਜਿਆਂ ਵਿੱਚ
ਦਿੱਖਣਯੋਗ ਟਰੰਕੇਸ਼ਨ ਮਾਰਕਰ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ।

ਪਾਰਸਰ ਹਰ ਮਾਡਲ ਟਰਨ ਲਈ ਇੱਕ ਵੱਖਰਾ `<tool>{...}</tool>` ਐਨਵਲਪ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ। ਇਹ
ਬੇਨਤੀ ਦੀ ਟੂਲ ਸੂਚੀ ਦੇ ਮੁਕਾਬਲੇ ਨਾਮ ਦੀ ਜਾਂਚ ਕਰਦਾ ਹੈ, ਉਸ ਟੂਲ ਦੇ JSON
Schema ਅਨੁਸਾਰ ਆਰਗੂਮੈਂਟਾਂ ਦੀ ਪੁਸ਼ਟੀ ਕਰਦਾ ਹੈ, ਮਿਲੀ-ਜੁਲੀ ਵਿਆਖਿਆ/ਕਾਰਵਾਈਆਂ ਨੂੰ ਰੱਦ ਕਰਦਾ ਹੈ, ਅਤੇ ਇੱਕ ਸੀਮਿਤ ਮੁਰੰਮਤ ਦੀ ਇਜਾਜ਼ਤ ਦਿੰਦਾ ਹੈ। ਫਿਰ Claude Code
ਨਤੀਜੇ ਵਜੋਂ ਮਿਲੇ Anthropic `tool_use` ਨੂੰ ਸਥਾਨਕ ਤੌਰ 'ਤੇ ਚਲਾਉਂਦਾ ਹੈ ਅਤੇ `tool_result` ਨੂੰ OmniRoute ਰਾਹੀਂ
ਵਾਪਸ ਭੇਜਦਾ ਹੈ।

## ਆਟੋ-ਰੂਟਿੰਗ

ਜਦੋਂ ਪ੍ਰੋਵਾਈਡਰ ਬਲੌਕ ਨਹੀਂ ਹੁੰਦਾ, ਤਾਂ ਇਹ OmniRoute ਦੇ `auto/*` ਉਮੀਦਵਾਰ ਪੂਲਾਂ ਲਈ ਯੋਗ ਹੁੰਦਾ ਹੈ।
ਉਮੀਦਵਾਰ ਯੋਗਤਾ ਚੋਣ ਦੀ ਗਾਰੰਟੀ ਨਹੀਂ ਦਿੰਦੀ: ਕੰਬੋ ਦੀ ਰੂਟਿੰਗ ਰਣਨੀਤੀ (ਉਦਾਹਰਨ ਲਈ,
last-known-good) ਕਿਸੇ ਹੋਰ ਪ੍ਰੋਵਾਈਡਰ ਨੂੰ ਤਰਜੀਹ ਦੇ ਸਕਦੀ ਹੈ। ਜਦੋਂ ਤੁਸੀਂ ਚਾਹੁੰਦੇ ਹੋ ਕਿ
ਹਰ ਬੇਨਤੀ Devin ਰਾਹੀਂ ਜਾਵੇ, ਤਾਂ `dva/<model>` ਜਾਂ Devin-ਪਹਿਲਾਂ ਕੰਬੋ ਵਰਤੋ।

## ਆਈਸੋਲੇਸ਼ਨ ਅਤੇ ਖ਼ਤਰਾ ਮਾਡਲ

ਹੋਸਟ ਦੀ Claude ਇੰਸਟਾਲੇਸ਼ਨ, ਖਾਤਾ ਅਤੇ ਸੰਰਚਨਾ ਦਾਇਰੇ ਤੋਂ ਬਾਹਰ ਹਨ ਅਤੇ ਇਨ੍ਹਾਂ ਨੂੰ
ਵਰਜਿਤ ਮੰਨਿਆ ਜਾਂਦਾ ਹੈ। Compose ਸੇਵਾਵਾਂ:

- UID/GID `10001:10001` ਵਜੋਂ, ਕੇਵਲ-ਪੜ੍ਹਨਯੋਗ ਰੂਟ ਫ਼ਾਈਲ ਸਿਸਟਮ, ਹਟਾਈਆਂ ਗਈਆਂ ਸਮਰੱਥਾਵਾਂ ਅਤੇ
  `no-new-privileges` ਨਾਲ ਚੱਲਦੀਆਂ ਹਨ;
- ਇੱਕ ਨਿੱਜੀ `/home/bridge`, ਇੱਕ ਸਮਰਪਿਤ Claude ਸੰਰਚਨਾ ਵਾਲਿਊਮ, ਆਈਸੋਲੇਟ ਕੀਤਾ OmniRoute ਡਾਟਾ
  ਅਤੇ ਇੱਕ ਵੱਖਰਾ `devin-auth` ਵਾਲਿਊਮ ਵਰਤਦੀਆਂ ਹਨ;
- ਕੇਵਲ ਅਸਥਾਈ `.sandbox` ਵਰਕਸਪੇਸ/ਸਬੂਤ ਮਾਊਂਟ ਕਰਦੀਆਂ ਹਨ;
- ਹੋਸਟ ਹੋਮ, Keychain, SSH, ਕਲਾਉਡ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਜਾਂ Docker ਸਾਕਟ ਮਾਊਂਟ ਨਹੀਂ ਕਰਦੀਆਂ;
- ਸਪਸ਼ਟ ਇਨਵਾਇਰਨਮੈਂਟ ਬਣਾਉਂਦੀਆਂ ਹਨ ਅਤੇ Anthropic API/OAuth/ਰੂਟਿੰਗ ਵੇਰੀਏਬਲ ਹਟਾਉਂਦੀਆਂ ਹਨ;
- Claude Code ਇਨਫ਼ਰੈਂਸ ਨੂੰ ਕੇਵਲ ਇੱਕ ਸਿਰਫ਼-ਸਥਾਨਕ ਕੁੰਜੀ ਨਾਲ `http://omniroute:20128` ਵੱਲ ਭੇਜਦੀਆਂ ਹਨ।

ਆਫ਼ਲਾਈਨ ਪ੍ਰੋਫ਼ਾਈਲ ਇੱਕ ਅੰਦਰੂਨੀ ਨੈੱਟਵਰਕ ਵਰਤਦਾ ਹੈ। ਲਾਈਵ ਪ੍ਰੋਫ਼ਾਈਲ ਵਿੱਚ, OmniRoute ਅਧਿਕਾਰਤ
Devin ਐਂਡਪੌਇੰਟਾਂ ਤੱਕ ਕੇਵਲ `network-guard` ਰਾਹੀਂ ਪਹੁੰਚਦਾ ਹੈ; ਗ਼ੈਰ-ਸੰਬੰਧਿਤ ਮੰਜ਼ਿਲਾਂ ਨੂੰ ਅਸਵੀਕਾਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।
Claude Code ਕੋਲ ਇੱਕ ਵੱਖਰਾ ਸਾਰਾ ਈਗ੍ਰੈੱਸ ਅਸਵੀਕਾਰ ਕਰਨ ਵਾਲਾ ਗਾਰਡ ਹੈ ਅਤੇ ਇਹ `NO_PROXY` ਰਾਹੀਂ ਕੇਵਲ ਸਥਾਨਕ OmniRoute
ਸੇਵਾ ਤੱਕ ਪਹੁੰਚ ਸਕਦਾ ਹੈ। ਗਾਰਡ ਆਡਿਟ ਫ਼ਾਈਲਾਂ ਕੇਵਲ ਉਨ੍ਹਾਂ ਦੀ ਗਾਰਡ ਪ੍ਰਕਿਰਿਆ ਦੁਆਰਾ ਮਾਊਂਟ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ।
ਸਕ੍ਰਿਪਟਾਂ ਟੋਕਨ-ਰਹਿਤ ਸਬੂਤ ਐਕਸਪੋਰਟ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਫ਼ਾਈਲ ਮਲਕੀਅਤ, ਮੋਡ, ਲਿੰਕ ਗਿਣਤੀ ਅਤੇ ਹਰੇਕ ਫ਼ੈਸਲੇ ਦੀ
ਤਸਦੀਕ ਕਰਦੀਆਂ ਹਨ।

ਆਈਸੋਲੇਸ਼ਨ ਸਬੂਤ ਨੂੰ ਸੁਤੰਤਰ ਤੌਰ 'ਤੇ ਚਲਾਓ:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

ਇਹ ਟੋਪੋਲੋਜੀ, ਨਾਮਿਤ ਮਾਊਂਟਾਂ, ਗ਼ੈਰ-ਰੂਟ/ਕੇਵਲ-ਪੜ੍ਹਨਯੋਗ ਸੈਟਿੰਗਾਂ, ਸਪਸ਼ਟ ਸਥਾਨਕ ਰੂਟਿੰਗ,
ਸੰਵੇਦਨਸ਼ੀਲ ਇਨਵਾਇਰਨਮੈਂਟ ਵੇਰੀਏਬਲਾਂ ਦੀ ਗੈਰਹਾਜ਼ਰੀ, Docker ਸਾਕਟ ਦੀ ਗੈਰਹਾਜ਼ਰੀ, `api.anthropic.com`
ਅਤੇ `claude.ai` ਤੱਕ ਰੋਕੀ ਗਈ ਪਹੁੰਚ, ਕੇਵਲ-Devin ਪ੍ਰਦਾਤਾ ਚੋਣ ਅਤੇ ACP ਬੈਕਐਂਡ ਉਪਲਬਧ ਨਾ ਹੋਣ 'ਤੇ
ਸਪਸ਼ਟ ਅਸਫਲਤਾ ਨੂੰ ਪ੍ਰਮਾਣਿਤ ਕਰਦਾ ਹੈ।

## ਪਹਿਲੀ ਵਾਰ ਸੈੱਟਅੱਪ ਅਤੇ ਆਮ ਵਰਤੋਂ

ਪਿੰਨ ਕੀਤੀ ਇਮੇਜ ਬਿਲਡ ਕਰੋ:

```bash
./scripts/devin-bridge/build
```

ਕੇਵਲ ਆਈਸੋਲੇਟ ਕੀਤੇ Devin ਵਾਲਿਊਮ ਨੂੰ ਪ੍ਰਮਾਣਿਤ ਕਰੋ:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

ਲੌਗਇਨ ਕਮਾਂਡ ਰਿਮੋਟ/ਕੰਟੇਨਰ ਇਨਵਾਇਰਨਮੈਂਟਾਂ ਲਈ ਬਣਾਏ ਗਏ ਅਧਿਕਾਰਤ ਮੈਨੁਅਲ-ਟੋਕਨ ਪ੍ਰਵਾਹ ਦੀ ਵਰਤੋਂ ਕਰਦੀ ਹੈ।
ਮੁੱਲ ਸਿੱਧਾ CLI ਪ੍ਰੌਮਪਟ ਵਿੱਚ ਦਰਜ ਕੀਤਾ ਜਾਂਦਾ ਹੈ; ਇਸਨੂੰ ਪ੍ਰਕਿਰਿਆ ਆਰਗੂਮੈਂਟ ਵਜੋਂ ਪਾਸ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ,
Git ਵਿੱਚ ਨਹੀਂ ਲਿਖਿਆ ਜਾਂਦਾ ਅਤੇ ਨਾ ਹੀ ਹੋਸਟ ਤੋਂ ਕਾਪੀ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

ਆਈਸੋਲੇਟ ਕੀਤਾ Claude Code ਰਨਟਾਈਮ ਲਾਂਚ ਕਰੋ:

```bash
./scripts/devin-bridge/launch
```

`launch` ਕੰਟੇਨਰਬੱਧ Claude Code ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਆਈਸੋਲੇਸ਼ਨ, Devin ਪ੍ਰਮਾਣੀਕਰਨ ਅਤੇ ਮਾਡਲ ਖੋਜ ਦੀ
ਮੁੜ ਜਾਂਚ ਕਰਦਾ ਹੈ। ਇਹ ਕਦੇ ਵੀ ਹੋਸਟ ਦਾ Claude ਐਗਜ਼ਿਕਿਊਟੇਬਲ ਨਹੀਂ ਚਲਾਉਂਦਾ। ਮਾਡਲ ਉਪਨਾਮ
`.env.devin-bridge` ਵਿੱਚ ਸੈੱਟ ਕੀਤੇ ਜਾ ਸਕਦੇ ਹਨ; ਹਰੇਕ ਸੰਰਚਿਤ ਮੁੱਲ ਵਿੱਚ
`devin-cli-agentic/` ਪ੍ਰੀਫਿਕਸ ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ।

## ਪ੍ਰਮਾਣੀਕਰਨ ਕਮਾਂਡਾਂ

ਦੁਹਰਾਇਆ ਜਾ ਸਕਣ ਵਾਲਾ ਆਫ਼ਲਾਈਨ ਮਾਰਗ ਕਿਸੇ Devin ਖਾਤੇ ਦੀ ਲੋੜ ਨਹੀਂ ਰੱਖਦਾ ਅਤੇ ਇਸ ਵਿੱਚ ਕੋਈ ਰਨਟਾਈਮ ਇੰਟਰਨੈੱਟ ਨਹੀਂ ਹੈ:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

ਪ੍ਰਮਾਣਿਤ, ਸਵੈ-ਇੱਛਾ ਨਾਲ ਚੁਣਿਆ ਜਾਣ ਵਾਲਾ ਲਾਈਵ ਮਾਰਗ ਹੈ:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ਲਾਈਵ ਰਨਰ ACP ਸੈਸ਼ਨਾਂ ਨੂੰ ਇੱਕੋ ਵਾਰ ਵੱਡੀ ਗਿਣਤੀ ਵਿੱਚ ਖੋਲ੍ਹਣ ਤੋਂ ਬਚਣ ਲਈ ਦ੍ਰਿਸ਼ਾਂ ਵਿਚਕਾਰ ਉਡੀਕ ਕਰਦਾ ਹੈ ਅਤੇ
ਲਿਖਤੀ ਦਾਅਵਿਆਂ 'ਤੇ ਭਰੋਸਾ ਕਰਨ ਦੀ ਬਜਾਏ ਸੰਰਚਿਤ Claude ਸਟ੍ਰੀਮ ਇਵੈਂਟਾਂ ਨੂੰ ਪ੍ਰਮਾਣਿਤ ਕਰਦਾ ਹੈ। ਇਸਦੇ ਤਿੰਨ
ਦ੍ਰਿਸ਼ ਇਹ ਸਾਬਤ ਕਰਦੇ ਹਨ:

1. ਸਿੱਧੇ ਪ੍ਰੋਜੈਕਟ ਰੀਡ ਅਤੇ ਖ਼ਰਾਬੀ ਵਿਸ਼ਲੇਸ਼ਣ;
2. ਇੱਕ ਅਸਲੀ `Edit`, ਇੱਕ ਕਲਾਇੰਟ-ਮਲਕੀਅਤ ਵਾਲਾ `Bash` `npm test` ਅਤੇ ਇੱਕ ਟਰਮੀਨਲ ਨਤੀਜਾ;
3. `/bridge-check` ਦੇ ਨਾਲ `bridge-proof` ਖੋਜ, ਪ੍ਰੋਜੈਕਟ ਰੀਡ, ਇੱਕ ਹੋਰ ਸਫਲ
   ਕਲਾਇੰਟ-ਮਲਕੀਅਤ ਵਾਲਾ `npm test` ਅਤੇ ਕੋਈ ਕੰਮ ਬਕਾਇਆ ਰਹੇ ਬਿਨਾਂ ਪੂਰਾ ਹੋਣਾ।

ਅੰਤਿਮ ਗੇਟ Devin ਨੈੱਟਵਰਕ ਆਡਿਟ ਦੀ ਵੀ ਜਾਂਚ ਕਰਦਾ ਹੈ ਅਤੇ ਇਹ ਲਾਜ਼ਮੀ ਕਰਦਾ ਹੈ ਕਿ Claude ਈਗ੍ਰੈੱਸ ਆਡਿਟ
ਖ਼ਾਲੀ ਰਹੇ।

## ਪਿੰਨ ਕੀਤੇ ਟੂਲਾਂ ਨੂੰ ਅੱਪਡੇਟ ਕਰਨਾ

ਇਮੇਜ ਵਿੱਚ Node, Claude Code ਅਤੇ Devin CLI ਨੂੰ
`docker/devin-bridge/Dockerfile` ਵਿੱਚ ਪਿੰਨ ਕੀਤਾ ਗਿਆ ਹੈ। ਅੱਪਡੇਟ ਕਰਨ ਲਈ:

1. ਸਪਸ਼ਟ ਵਰਜਨ ਬਦਲੋ;
2. ਦੋਵੇਂ ਆਰਕੀਟੈਕਚਰ-ਵਿਸ਼ੇਸ਼ Devin ਆਰਕਾਈਵ ਚੈਕਸਮਾਂ ਨੂੰ ਅਧਿਕਾਰਤ
   ਆਰਟੀਫੈਕਟ ਦੇ ਮੁੱਲਾਂ ਨਾਲ ਬਦਲੋ;
3. ਮੁੜ ਬਿਲਡ ਕਰੋ ਅਤੇ ਹਰੇਕ ਆਫ਼ਲਾਈਨ ਵੈਲੀਡੇਸ਼ਨ ਕਮਾਂਡ ਚਲਾਓ;
4. ਇਮੇਜ ਦੇ ਅੰਦਰ ਵਰਜਨਾਂ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ;
5. ਪ੍ਰਮਾਣਿਤ ਤਿੰਨ-ਦ੍ਰਿਸ਼ ਲਾਈਵ ਸੂਟ ਨੂੰ ਦੁਬਾਰਾ ਚਲਾਓ।

ਕਿਸੇ ਵੀ CLI ਨੂੰ ਹੋਸਟ ਉੱਤੇ ਗਲੋਬਲੀ ਇੰਸਟਾਲ ਨਾ ਕਰੋ ਜਾਂ ਚੈਕਸਮ ਤਸਦੀਕ ਨੂੰ ਕਿਸੇ
ਗੈਰ-ਤਸਦੀਕਸ਼ੁਦਾ ਡਾਊਨਲੋਡ ਨਾਲ ਨਾ ਬਦਲੋ।

## ਸੀਮਾਵਾਂ

- ਬ੍ਰਿਜ ਸਥਿਰ, ਬਿਨਾਂ-ਟੂਲਾਂ ਵਾਲੀ `summarizer` ਭੂਮਿਕਾ ਉੱਤੇ ਨਿਰਭਰ ਕਰਦਾ ਹੈ ਕਿਉਂਕਿ Devin CLI `3000.2.17`
  ਕੋਈ ਨਿਰਪੱਖ, ਬਿਨਾਂ-ਟੂਲਾਂ ਵਾਲਾ ACP ਏਜੰਟ ਉਪਲਬਧ ਨਹੀਂ ਕਰਦਾ। ਅਡੈਪਟਰ ਸਾਰਾਂਸ਼-ਆਕਾਰ ਵਾਲੇ
  ਵਿਚਕਾਰਲੇ ਜਵਾਬਾਂ ਦੀ ਭਰਪਾਈ ਕਰਦਾ ਹੈ, ਪਰ ਇੱਕ ਸੀਮਿਤ ਮੁਰੰਮਤ ਫਿਰ ਵੀ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਅਸਫਲ ਹੋ ਸਕਦੀ ਹੈ।
- ਲਾਈਵ ACP ਕਾਲਾਂ ਅਸਥਾਈ `502`/`504` ਜਵਾਬ ਵਾਪਸ ਕਰ ਸਕਦੀਆਂ ਹਨ। ਹਾਰਨੈੱਸ ਦ੍ਰਿਸ਼ਾਂ ਵਿਚਕਾਰ ਅੰਤਰ ਰੱਖਦਾ ਹੈ;
  ਲਗਾਤਾਰ ਅਸਫਲਤਾ ਫੇਲ-ਕਲੋਜ਼ਡ ਰਹਿੰਦੀ ਹੈ ਅਤੇ ਕਦੇ ਵੀ ਕਿਸੇ ਹੋਰ ਪ੍ਰਦਾਤਾ ਨੂੰ ਨਹੀਂ ਚੁਣਦੀ।
- ACP ਕਾਂਟੈਕਸਟ ਹਰੇਕ Anthropic ਬੇਨਤੀ ਤੋਂ ਮੁੜ ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ; ਕੋਈ ਪ੍ਰੋਸੈੱਸ/ਸੈਸ਼ਨ
  ਅਫ਼ਿਨਿਟੀ ਨਹੀਂ ਹੈ।
- ਹਰ ਮਾਡਲ ਜਵਾਬ ਲਈ ਇੱਕ ਟੂਲ ਕਾਲ ਸਮਰਥਿਤ ਹੈ; ਸਮਾਂਤਰ ਕਾਲਾਂ ਰੱਦ ਕਰ ਦਿੱਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ।
- ਇਮੇਜਾਂ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਅਸਮਰਥਿਤ ਹਨ। ਵਿਜ਼ਨ, ਥਿੰਕਿੰਗ ਆਉਟਪੁੱਟ, ਐਫ਼ਰਟ ਕੰਟਰੋਲ ਅਤੇ 1M
  ਕਾਂਟੈਕਸਟ ਵਿੰਡੋ ਦਾ ਪ੍ਰਚਾਰ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ।
- SSE ਵੈਧ Anthropic ਲਾਈਫਸਾਈਕਲ ਇਵੈਂਟਾਂ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ, ਪਰ ਸੀਮਿਤ ACP ਟਰਨ ਇਕੱਠਾ ਕੀਤੇ ਜਾਣ ਤੋਂ ਬਾਅਦ
  ਨਿਕਾਸ ਕੀਤਾ ਜਾਂਦਾ ਹੈ; ACP ਚੰਕਾਂ ਨੂੰ ਕ੍ਰਮਵਾਰ ਅੱਗੇ ਨਹੀਂ ਭੇਜਿਆ ਜਾਂਦਾ।
