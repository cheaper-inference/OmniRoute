ਇਹ ਦਸਤਾਵੇਜ਼ OmniRoute ਵਿੱਚ ਸਾਰੇ CI ਗੁਣਵੱਤਾ ਗੇਟਾਂ ਲਈ ਪ੍ਰਮਾਣਿਕ ਹਵਾਲਾ ਹੈ।
ਇਹ ਹਰ ਗੇਟ ਦਾ ਵਰਣਨ ਕਰਦਾ ਹੈ, ਇਹ ਕੀ ਪ੍ਰਮਾਣਿਤ ਕਰਦਾ ਹੈ, ਇਹ ਕਿਸ CI ਜੌਬ ਵਿੱਚ ਚੱਲਦਾ ਹੈ, ਕੀ ਇਹ
ਰੈਚਟ ਬੇਸਲਾਈਨ ਜਾਂ ਪਾਸ/ਫੇਲ ਨੀਤੀ ਵਰਤਦਾ ਹੈ, ਅਤੇ ਕੀ ਇਹ ਬਿਲਡ ਨੂੰ ਰੋਕਦਾ ਹੈ ਜਾਂ ਸਿਰਫ਼ ਸਲਾਹਕਾਰੀ ਹੈ।

ਸੰਖੇਪ ਸਾਰ ਅਤੇ ਅਲਾਊਲਿਸਟ ਨੀਤੀ ਲਈ, `AGENTS.md` ਵਿੱਚ "ਗੁਣਵੱਤਾ ਗੇਟ ਅਤੇ ਰੈਚਟ" ਭਾਗ
ਦੇਖੋ। ਇਸੇ ਸਿਸਟਮ ਦੇ ਆਲੋਚਨਾਤਮਕ ਮੁਲਾਂਕਣ, ਪਰਿਪੱਕਤਾ ਵਰਗੀਕਰਨ ਅਤੇ ਟੂਲ-ਨਿਰਪੱਖ
ਪੁਨਰ-ਨਿਰਮਾਣ ਯੋਜਨਾ ਲਈ,
[ਗੁਣਵੱਤਾ ਗੇਟ ਪਲੇਬੁੱਕ](../ops/QUALITY_GATE_PLAYBOOK.md) ਦੇਖੋ।

## ਗੇਟ ਸੂਚੀ ਅਤੇ ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਪ੍ਰੋਫਾਈਲ

### ਉਮੀਦਵਾਰ ਦਾਖਲਾ

CI ਅਤੇ Quality Gates ਵਰਕਫ਼ਲੋ ਦੋਵੇਂ ਇੱਕ ਸਥਿਰ ਫ਼ੈਸਲਾ ਜਾਰੀ ਕਰਦੇ ਹਨ: `Gate / CI` ਅਤੇ
`Gate / Quality`। ਇਹਨਾਂ ਦੀ ਵਰਜ਼ਨ-ਅਧਾਰਿਤ ਦਾਖਲਾ ਨੀਤੀ ਹਰ ਅੱਪਸਟ੍ਰੀਮ ਜੌਬ ਨੂੰ ਜ਼ਰੂਰੀ ਜਾਂ
ਸਲਾਹਕਾਰ ਵਜੋਂ ਦਰਸਾਉਂਦੀ ਹੈ। ਲਾਗੂ ਹੋਣ ਵਾਲੀ ਜ਼ਰੂਰੀ ਜੌਬ ਸਫਲ ਹੋਣੀ ਲਾਜ਼ਮੀ ਹੈ: ਗੁੰਮ,
ਰੱਦ, ਛੱਡੀ ਗਈ, ਕਾਇਮ ਅਤੇ ਅਣਜਾਣ ਨਤੀਜੇ PASS ਸਥਾਪਤ ਨਹੀਂ ਕਰ ਸਕਦੇ। ਇੱਕ ਵੈਧ docs-only ਜਾਂ
catalog-only ਵਰਗੀਕਰਨ ਕਿਸੇ ਕੋਡ ਲੇਨ ਨੂੰ ਲਾਗੂ-ਰਹਿਤ ਬਣਾ ਸਕਦਾ ਹੈ;
ਇੱਕ ਡਰਾਫਟ PR ਸਵੀਕਾਰਯੋਗ ਉਮੀਦਵਾਰ ਨਹੀਂ ਹੈ। `hotfix` ਲੇਬਲ ਸਬੂਤ ਦੀ ਮਾਫ਼ੀ ਨਹੀਂ ਦਿੰਦਾ।

ਦੋਵੇਂ ਵਰਕਫ਼ਲੋ main/release ਬ੍ਰਾਂਚਾਂ ਵਿੱਚ PRs, `main` ਉੱਤੇ ਪੁਸ਼, ਮੈਨੂਅਲ ਡਿਸਪੈਚ
ਅਤੇ ਮਰਜ-ਗਰੁੱਪ ਇਵੈਂਟਸ ਨੂੰ ਕਵਰ ਕਰਦੇ ਹਨ। ਪੁਸ਼, ਡਿਸਪੈਚ ਅਤੇ ਮਰਜ-ਗਰੁੱਪ ਪੂਰੀ ਚੋਣ ਚਲਾਉਂਦੇ ਹਨ।
`release/**` ਉੱਤੇ ਪੁਸ਼ ਇਹਨਾਂ ਨੂੰ ਸ਼ੁਰੂ ਨਹੀਂ ਕਰਦੇ (2026-10-18): ਹਰ ਤਬਦੀਲੀ ਪਹਿਲਾਂ ਹੀ ਆਪਣੇ PR
ਉੱਤੇ ਮੈਟ੍ਰਿਕਸ ਚਲਾ ਚੁੱਕੀ ਹੈ ਅਤੇ ਮਰਜ ਕੀਤਾ ਸੁਮੇਲ Release-Green ਦਾ ਕੰਮ ਹੈ (`docs/ops/RUNNER_BOX.md` → ਹੋਸਟ ਕੀਤੀ ਲੇਨ)। ਫੋਰਕ
ਅਤੇ ਮਰਜ ਗਰੁੱਪ ਉਹਨਾਂ ਜੌਬਾਂ ਲਈ ਹੋਸਟ ਕੀਤੇ ਰਨਰ ਵਰਤਦੇ ਹਨ ਜੋ ਆਮ ਤੌਰ 'ਤੇ ਸੈਲਫ਼-ਹੋਸਟ ਕੀਤੇ
ਰਨਰ ਚੁਣਦੀਆਂ ਹਨ; ਰੋਲਆਉਟ ਤੋਂ ਪਹਿਲਾਂ ਕਾਫ਼ੀ ਹੋਸਟ ਕੀਤੀ ਸਮਰੱਥਾ ਦੀ ਪੁਸ਼ਟੀ ਕੀਤੀ ਜਾਣੀ ਚਾਹੀਦੀ ਹੈ।

ਹਰ JSON ਰਸੀਦ ਚੈੱਕ-ਆਉਟ ਕੀਤੇ SHA, ਵਰਕਫ਼ਲੋ ਰਨ ਅਤੇ ਅਟੈਂਪਟ ਦੀ ਪਛਾਣ ਕਰਦੀ ਹੈ।
CLI ਚੈੱਕਆਉਟ/ਇਵੈਂਟ SHA ਮਿਸਮੈਚ ਨੂੰ ਰੱਦ ਕਰ ਦਿੰਦਾ ਹੈ। ਵਰਕਫ਼ਲੋ ਟੈਸਟ ਨੀਤੀ ਮੈਂਬਰਸ਼ਿਪ ਨੂੰ
ਫ਼ੈਸਲਾ ਜੌਬ ਦੀ `needs` ਸੂਚੀ ਨਾਲ ਬੰਨ੍ਹਦੇ ਹਨ ਤਾਂ ਜੋ ਕੋਈ ਨਵੀਂ ਜਾਂ ਹਟਾਈ ਗਈ ਲੇਨ ਚੁੱਪਚਾਪ
ਗਾਇਬ ਨਾ ਹੋ ਸਕੇ। ਰਸੀਦਾਂ ਸਿਰਫ਼ ਆਪਣੇ ਵਰਕਫ਼ਲੋ ਨੂੰ ਕਵਰ ਕਰਦੀਆਂ ਹਨ, ਪ੍ਰਕਾਸ਼ਨ, ਤੈਨਾਤੀ ਜਾਂ ਕਿਸੇ
ਮੌਜੂਦਾ ਸਲਾਹਕਾਰ ਸਕੈਨਰ ਦੇ ਅੰਦਰੂਨੀ ਹਿੱਸਿਆਂ ਨੂੰ ਨਹੀਂ। ਬ੍ਰਾਂਚ ਨਿਯਮਾਂ ਵਿੱਚ ਦੋਵੇਂ ਚੈੱਕ ਨਾਮ
ਸਕ੍ਰਿਆ ਕਰਨਾ ਇੱਕ ਵੱਖਰੀ ਪ੍ਰਸ਼ਾਸਕੀ ਤਬਦੀਲੀ ਹੈ; ਇਹਨਾਂ ਜੌਬਾਂ ਨੂੰ ਜੋੜਨਾ ਆਪਣੇ ਆਪ ਵਿੱਚ ਕਿਸੇ ਬ੍ਰਾਂਚ ਦੀ ਸੁਰੱਖਿਆ ਨਹੀਂ ਕਰਦਾ।

### ਸਟੈਟਿਕ ਸਕੈਨ ਸੂਚੀ

ਵਰਜ਼ਨ-ਅਧਾਰਿਤ npm-ਅਲੀਆਸ ਸੂਚੀ ਅਤੇ ਸਟੈਟਿਕ-ਸਕੈਨ ਮੈਂਬਰਸ਼ਿਪ
`config/quality/gate-manifest.json` ਵਿੱਚ ਰਹਿੰਦੀਆਂ ਹਨ। ਸਕ੍ਰਿਪਟ ਨਾਮਾਂ ਅਤੇ ਸਹੀ ਕਮਾਂਡਾਂ ਦੀ
`package.json` ਦੇ ਵਿਰੁੱਧ ਪੁਸ਼ਟੀ ਕਰਨ ਲਈ `npm run check:gate-manifest` ਚਲਾਓ; ਜੋੜ, ਹਟਾਓ ਅਤੇ
ਕਮਾਂਡ ਡ੍ਰਿਫਟ ਸਥਾਨਕ ਹੁੱਕ ਅਤੇ CI ਵਿੱਚ ਤਬਦੀਲੀ-ਵਰਗੀਕਰਨ ਜੌਬਾਂ ਦੋਹਾਂ ਨੂੰ ਅਸਫਲ ਕਰ ਦਿੰਦੇ ਹਨ।
ਇੱਕ ਅਲੀਆਸ ਕੋਈ ਵਰਕਫ਼ਲੋ ਜੌਬ, ਮੈਟ੍ਰਿਕਸ ਇੰਸਟੈਂਸ ਜਾਂ ਟੈਸਟ ਕੇਸ ਨਹੀਂ ਹੁੰਦਾ: ਇਹਨਾਂ ਗਿਣਤੀਆਂ ਨੂੰ
ਇੱਕ-ਦੂਜੇ ਦੇ ਬਦਲ ਵਜੋਂ ਪੇਸ਼ ਨਹੀਂ ਕੀਤਾ ਜਾਣਾ ਚਾਹੀਦਾ।

ਚੁਣੇ ਅਲੀਆਸਾਂ ਨੂੰ ਚਲਾਏ ਬਿਨਾਂ ਵੇਖਣ ਲਈ `npm run quality:scan -- --list` ਜਾਂ
`npm run quality:scan:fast -- --list` ਵਰਤੋ। ਰਨਰ npm ਐਂਟਰੀਪੁਆਇੰਟ ਨੂੰ ਬੁਲਾਉਂਦਾ ਹੈ,
ਇਸ ਲਈ ਇਸਦਾ ਰਨਟਾਈਮ (ਜਿੱਥੇ ਸੰਰਚਿਤ ਹੈ ਉੱਥੇ Bun ਸਮੇਤ) ਕਾਇਮ ਰਹਿੰਦਾ ਹੈ।
ਮੈਨੀਫੈਸਟ ਉਹਨਾਂ ਪ੍ਰੋਫਾਈਲਾਂ ਤੋਂ ਬਾਹਰਲੇ ਅਲੀਆਸਾਂ ਨੂੰ ਵੱਖਰੇ ਤੌਰ 'ਤੇ ਬੁਲਾਏ ਹੋਏ ਵਜੋਂ ਦਰਜ ਕਰਦਾ ਹੈ, ਅਤੇ
ਸਿਰਫ਼-ਪੜ੍ਹਨ ਵਾਲੇ ਸਕੈਨ ਪ੍ਰੋਫਾਈਲਾਂ ਵਿੱਚ ਮੇਨਟੇਨੈਂਸ ਕਮਾਂਡਾਂ ਦੀ ਮਨਾਹੀ ਹੈ।

ਇਹ ਪ੍ਰੋਫਾਈਲ ਸਿਰਫ਼ ਸਟੈਟਿਕ ਸਕੈਨ ਨੂੰ ਕਵਰ ਕਰਦੇ ਹਨ। ਇਹ ਪ੍ਰੋਡਕਟ ਟੈਸਟਾਂ,
ਕਵਰੇਜ, ਪੈਕੇਜਿੰਗ, ਬਾਹਰੀ ਚੈੱਕਾਂ ਜਾਂ ਕਿਸੇ ਉਮੀਦਵਾਰ ਦੀ ਪੂਰੀ ਰਿਲੀਜ਼ ਸਵੀਕਾਰਤਾ ਦੀ ਪ੍ਰਮਾਣਿਕਤਾ ਨਹੀਂ ਕਰਦੇ।
ਵਰਕਫ਼ਲੋ ਦਾਖਲਾ ਜੁੜੀ ਹੋਈ `config/quality/admission-policy.json` ਅਤੇ
`scripts/quality/admission-verdict.mjs` ਵਰਤਦਾ ਹੈ। ਰਿਲੀਜ਼-ਆਬਜ਼ਰਵਰ ਪ੍ਰੋਫਾਈਲ ਵੱਖਰੇ ਰਹਿੰਦੇ ਹਨ;
ਉਹਨਾਂ ਦੇ ਲਾਗੂ ਚੈੱਕਾਂ ਅਤੇ ਰਸੀਦਾਂ ਦੀ ਸੁਤੰਤਰ ਤੌਰ 'ਤੇ ਜਾਂਚ ਕਰੋ। ਹੇਠ ਦਿੱਤੀ ਗੱਦ
ਸੂਚੀ ਇੱਕ ਹਵਾਲਾ ਹੈ, ਇਹ ਸਬੂਤ ਨਹੀਂ ਕਿ ਕੋਈ ਗੇਟ ਅਸਲ ਵਿੱਚ ਚੱਲਿਆ।

ਸਕ੍ਰਿਪਟਾਂ `scripts/check/` (ਨੀਤੀ ਗੇਟ) ਅਤੇ `scripts/quality/` (ਰੈਚਟ ਇੰਜਣ) ਅਧੀਨ ਰਹਿੰਦੀਆਂ ਹਨ।
CI ਦਾ ਸੱਚ ਦਾ ਸਰੋਤ `.github/workflows/ci.yml` ਹੈ।

### ਰਿਲੀਜ਼ PR ਫਾਸਟ-ਪਾਥ (`quality.yml`)

`.github/workflows/quality.yml` main/release PRs, `main` ਉੱਤੇ ਪੁਸ਼,
ਡਿਸਪੈਚ ਅਤੇ ਮਰਜ ਗਰੁੱਪਾਂ ਉੱਤੇ CI ਦਾ ਪੂਰਕ ਹੈ। PR ਪਾਥ-ਫਿਲਟਰ ਕੀਤੇ ਤੇਜ਼ ਚੈੱਕ ਵਰਤਦੇ ਹਨ। ਸਥਾਈ ਤੌਰ 'ਤੇ
ਬੰਦ ਕੀਤੀ ਡੁਪਲੀਕੇਟ ਬਿਲਡ ਹਟਾ ਦਿੱਤੀ ਗਈ ਸੀ; ਅਸਲ ਬਿਲਡ/ਪੈਕੇਜ/ਬੂਟ ਚੈੱਕ CI ਵਿੱਚ ਰਹਿੰਦੇ ਹਨ।

| ਜੌਬ                                              | ਦਾਇਰਾ                                                                                                                                                                                               | ਬਲੌਕਿੰਗ          |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |

#### ਭੁੱਲੇ ਸਹੋਦਰ ਟੈਸਟਾਂ ਦੀ ਰਿਪੋਰਟ

`npm run check:forgotten-sibling-tests` test-impact map ਦੇ ਪਿੱਛੇ ਮੌਜੂਦ import resolver ਨੂੰ ਮੁੜ-ਵਰਤੋਂ ਕਰਦਾ ਹੈ।
ਹਰ ਬਦਲੇ ਗਏ ਪ੍ਰੋਡਕਸ਼ਨ ਮੋਡੀਊਲ ਲਈ, ਜਦੋਂ ਉਮੀਦਵਾਰ ਟੈਸਟ pull-request diff ਵਿੱਚ ਮੌਜੂਦ ਨਹੀਂ ਹੁੰਦਾ, ਇਹ ਨਿਰਧਾਰਿਤ
`changed module/symbol -> static consumer -> candidate sibling test` ਚੇਨਾਂ ਰਿਪੋਰਟ ਕਰਦਾ ਹੈ। Markdown ਸੰਖੇਪ ਅਤੇ JSON ਨਤੀਜਾ
`forgotten-sibling-tests` ਵਰਕਫ਼ਲੋ ਆਰਟੀਫੈਕਟ ਵਜੋਂ ਰੱਖੇ ਜਾਂਦੇ ਹਨ, ਤਾਂ ਜੋ ਕਿਸੇ ਵੀ ਬਲੌਕਿੰਗ ਰੋਲਆਉਟ ਤੋਂ ਪਹਿਲਾਂ ਕੈਲੀਬ੍ਰੇਸ਼ਨ ਕੀਤੀ ਜਾ ਸਕੇ।

Barrel ਰੀ-ਐਕਸਪੋਰਟਸ ਅਤੇ ਡਾਇਨਾਮਿਕ ਇੰਪੋਰਟਸ ਸਿਰਫ਼ ਰੈਜ਼ੋਲੂਸ਼ਨ ਜਾਂਚ-ਸੂਚਨਾਵਾਂ ਹਨ; ਇਹ ਕਦੇ ਵੀ ਬਲੌਕਿੰਗ ਫਾਈਂਡਿੰਗ ਨਹੀਂ ਬਣਾਉਂਦੇ। ਸਮੀਖਿਆ ਕੀਤੇ ਅਪਵਾਦ
`config/quality/forgotten-sibling-allowlist.json` ਵਿੱਚ ਰਹਿੰਦੇ ਹਨ। ਹਰ ਐਂਟਰੀ ਵਿੱਚ consumer ਅਤੇ ਉਮੀਦਵਾਰ
ਟੈਸਟ ਦਾ ਨਾਮ, ਇੱਕ ਖ਼ਾਸ ਕਾਰਨ, ਅਤੇ GitHub issue ਜਾਂ pull request ਦਾ ਲਿੰਕ ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ। ਗਲਤ ਢਾਂਚੇ ਵਾਲੀਆਂ ਐਂਟਰੀਆਂ fail-closed ਹੁੰਦੀਆਂ
ਹਨ। ਅਪਵਾਦ ਕਿਸੇ ਮਿਟਾਏ ਗਏ ਉਮੀਦਵਾਰ ਟੈਸਟ ਜਾਂ ਅਜਿਹੇ diff ਨੂੰ ਦਬਾ ਨਹੀਂ ਸਕਦੇ ਜੋ `.skip`/`.todo` ਜੋੜਦਾ ਹੈ;
assertion ਕਮਜ਼ੋਰ ਕਰਨ ਅਤੇ ਹੋਰ masking ਦੀ ਜ਼ਿੰਮੇਵਾਰੀ ਸੁਤੰਤਰ ਤੌਰ 'ਤੇ ਬਲੌਕਿੰਗ
`check:test-masking` ਗੇਟ ਕੋਲ ਹੀ ਰਹਿੰਦੀ ਹੈ।

#### `check-ui-value-drift` — ਬਾਸੀ-ਅਨੁਵਾਦ ਗੇਟ

ਉਹ ਇਕੱਲਾ i18n ਰਿਗਰੈਸ਼ਨ ਫੜਦਾ ਹੈ ਜੋ ਹੋਰ ਗੇਟ ਢਾਂਚਾਗਤ ਤੌਰ 'ਤੇ ਨਹੀਂ ਵੇਖ ਸਕਦੇ: ਇੱਕ ਅੰਗਰੇਜ਼ੀ
ਮੁੱਲ ਮੁੜ-ਲਿਖਿਆ ਜਾਂਦਾ ਹੈ ਅਤੇ _ਪਿਛਲੇ_ ਅੰਗਰੇਜ਼ੀ ਤੋਂ ਲਏ ਗਏ ਅਨੁਵਾਦ ਪਿੱਛੇ ਰਹਿ ਜਾਂਦੇ ਹਨ, ਇਸ ਲਈ
ਗੈਰ-ਅੰਗਰੇਜ਼ੀ ਉਪਭੋਗਤਾ ਆਤਮਵਿਸ਼ਵਾਸ ਭਰੇ ਸ਼ਬਦਾਂ ਵਾਲੀ, ਹੁਣ-ਗਲਤ ਸਮੱਗਰੀ ਪੜ੍ਹਦੇ ਰਹਿੰਦੇ ਹਨ।

ਇਹ ਸੱਚਮੁੱਚ ਸ਼ਿਪ ਹੋਇਆ ਸੀ। `oauthModal.googleOAuthWarning` ਨੂੰ ਮੁੜ-ਲਿਖਿਆ ਗਿਆ ਸੀ ਜਦੋਂ Antigravity
ਲਾਗਇਨ ਹੈਲਪਰ ਆਇਆ (#5203); **43 ਵਿੱਚੋਂ 39 ਲੋਕਲਾਂ** ਵਿੱਚ ਅਜਿਹਾ ਟੈਕਸਟ ਬਣਿਆ ਰਿਹਾ ਜੋ ਓਪਰੇਟਰਾਂ ਨੂੰ
"ਪੂਰਾ URL ਕਾਪੀ ਕਰੋ ਅਤੇ ਹੇਠਾਂ ਪੇਸਟ ਕਰੋ" ਦੱਸਦਾ ਸੀ — ਇੱਕ ਅਜਿਹਾ ਫਲੋ ਜੋ ਉਸ ਪ੍ਰੋਵਾਈਡਰ ਲਈ ਪੂਰਾ ਹੋ ਹੀ
ਨਹੀਂ ਸਕਦਾ। ਇਹ #8463 ਤੱਕ ਕਿਸੇ ਦੇ ਧਿਆਨ ਨਹੀਂ ਆਇਆ ਕਿਉਂਕਿ:

- `sync-ui-keys` ਸਿਰਫ਼ ਉਹ ਕੁੰਜੀਆਂ ਭਰਦਾ ਹੈ ਜੋ **ਗੈਰਹਾਜ਼ਰ** ਹਨ, ਕਦੇ ਵੀ ਉਹ ਨਹੀਂ ਜੋ **ਬਾਸੀ** ਹਨ;
- `check-ui-keys-coverage` ਕੁੰਜੀ ਦੀ _ਮੌਜੂਦਗੀ_ ਗਿਣਦਾ ਹੈ, ਇਸ ਲਈ ਬਾਸੀ ਅਨੁਵਾਦ ਵੀ ਕਵਰ ਹੋਇਆ ਗਿਣਿਆ ਜਾਂਦਾ ਹੈ;
- `check-translation-drift` `docs/i18n/<locale>/**.md` ਦਸਤਾਵੇਜ਼ ਮਿਰਰਾਂ ਨੂੰ ਟ੍ਰੈਕ ਕਰਦਾ ਹੈ —
  ਇਹ ਕਦੇ ਵੀ `src/i18n/messages/*.json` ਨਹੀਂ ਪੜ੍ਹਦਾ। 2026-09 ਰੀ-ਸਿੰਕ ਤੋਂ ਜੌਬ
  `docs-sync-strict` ਵਿੱਚ ਰੋਕਣ ਵਾਲਾ: ਕੋਈ ਕੋਰ ਦਸਤਾਵੇਜ਼ ਸੰਪਾਦਿਤ ਕਰੋ → `npm run i18n:run -- --files=<doc>` (ਸੈਕਸ਼ਨ-ਪੱਧਰੀ, ਸਸਤਾ)।

**ਡਿਫ਼-ਅਧਾਰਿਤ, ਬੇਸਲਾਈਨ-ਸਮਰਥਿਤ ਨਹੀਂ।** ਇਹ ਮਰਜ ਬੇਸ 'ਤੇ `en.json` ਦੀ ਤੁਲਨਾ ਵਰਕਿੰਗ ਟ੍ਰੀ ਨਾਲ ਕਰਦਾ ਹੈ; ਹਰ ਕੁੰਜੀ ਲਈ ਜਿਸਦਾ ਅੰਗਰੇਜ਼ੀ ਮੁੱਲ ਬਦਲਿਆ ਹੈ, ਕੋਈ ਵੀ ਲੋਕੇਲ ਜੋ ਅਜੇ ਵੀ ਅਣਛੁਹਿਆ ਅਨੁਵਾਦ ਰੱਖ ਰਿਹਾ ਹੈ, ਪੁਰਾਣਾ ਹੈ। ਇਹ ਜਾਣਬੁੱਝ ਕੇ **ਪਹਿਲਾਂ ਤੋਂ ਮੌਜੂਦ ਕਰਜ਼ੇ ਨੂੰ ਫ੍ਰੀਜ਼ ਕਰਦਾ ਹੈ** — ਇੱਕ ਡਿਫ਼ ਇਹ ਨਹੀਂ ਦੱਸ ਸਕਦਾ ਕਿ ਲੰਬੇ ਸਮੇਂ ਤੋਂ ਮੌਜੂਦ ਅਨੁਵਾਦ ਕਿਹੜੀ ਪੁਰਾਣੀ ਅੰਗਰੇਜ਼ੀ ਤੋਂ ਆਇਆ ਸੀ, ਇਸਲਈ ਗੇਟ ਸਿਰਫ਼ ਉਸ ਚੀਜ਼ ਦੀ ਜਾਂਚ ਕਰਦਾ ਹੈ ਜਿਸ ਨੂੰ ਮੌਜੂਦਾ ਤਬਦੀਲੀ ਛੂਹਦੀ ਹੈ। ਵਿਕਲਪ (ਪ੍ਰਤੀ-ਕੁੰਜੀ ਹੈਸ਼ ਬੇਸਲਾਈਨ) ਲਈ ਇੱਕ ~600 KB ਜਨਰੇਟ ਕੀਤੀ ਫਾਈਲ ਦੀ ਲੋੜ ਹੋਵੇਗੀ, ਜੋ ਸਭ ਤੋਂ ਵੱਡੀ ਮੌਜੂਦਾ ਬੇਸਲਾਈਨ ਤੋਂ 3× ਵੱਡੀ ਹੈ, ਅਤੇ ਜੋ ਹਰ i18n PR 'ਤੇ ਬਦਲਦੀ ਰਹੇਗੀ।

ਇਸ ਨੂੰ ਪੂਰਾ ਕਰਨ ਦੇ ਦੋ ਤਰੀਕੇ:

1. ਪ੍ਰਭਾਵਿਤ ਅਨੁਵਾਦਾਂ ਨੂੰ ਅਪਡੇਟ ਕਰੋ, ਜਾਂ
2. ਉਹਨਾਂ ਨੂੰ `__MISSING__:<new english>` 'ਤੇ ਸੈੱਟ ਕਰੋ — ਫਿਰ ਰਨਟਾਈਮ ਸਹੀ ਕੀਤੀ ਅੰਗਰੇਜ਼ੀ ਪੇਸ਼ ਕਰਦਾ ਹੈ
   (`src/i18n/request.ts::deepMergeFallback`, #7258) ਅਤੇ ਕੁੰਜੀ ਅਨੁਵਾਦ ਲਈ ਕਤਾਰ ਵਿੱਚ ਲੱਗ ਜਾਂਦੀ ਹੈ।

ਜੇਕਰ ਸਟ੍ਰਿੰਗ ਦਾ **ਅਰਥ** ਬਦਲ ਗਿਆ ਹੈ, ਤਾਂ **ਕੁੰਜੀ ਦਾ ਨਾਮ ਬਦਲਣਾ** ਤਰਜੀਹ ਦਿਓ: ਇੱਕ ਨਵੀਂ ਕੁੰਜੀ ਪੁਰਾਣੇ ਅਨੁਵਾਦ ਨੂੰ ਵਿਰਾਸਤ ਵਿੱਚ ਨਹੀਂ ਲੈ ਸਕਦੀ। ਇਹੀ ਉਹ ਪੈਟਰਨ ਹੈ ਜੋ #8463 ਨੇ ਵਰਤਿਆ।

```bash
npm run i18n:check-value-drift          # ਸਖ਼ਤ (ਜੋ CI ਚਲਾਉਂਦਾ ਹੈ)
npm run i18n:check-value-drift:warn     # ਸਿਰਫ਼ ਰਿਪੋਰਟ
BASE_REF=origin/release/vX.Y.Z npm run i18n:check-value-drift
```

ਜਦੋਂ ਬੇਸ ਕੈਟਾਲਾਗ ਪੜ੍ਹਿਆ ਨਹੀਂ ਜਾ ਸਕਦਾ (ਬੇਸ ਰੈਫ਼ ਤੋਂ ਬਿਨਾਂ ਸੈਲੋ ਕਲੋਨ), ਤਾਂ `SKIP reason=base-unresolved` ਦੇ ਨਾਲ 0 ਨਾਲ ਬਾਹਰ ਨਿਕਲਦਾ ਹੈ, `check-openapi-breaking` ਦੇ ਸਮਾਨ।

`workflow_dispatch` runs, release-green sweep ਅਤੇ nightly headroom job ਕੋਲ ਕੋਈ PR base ਨਹੀਂ ਹੁੰਦਾ

## ਮਨਜ਼ੂਰਸ਼ੁਦਾ-ਸੂਚੀ ਨੀਤੀ

ਹਰ ਉਹ ਗੇਟ ਜੋ ਪਹਿਲਾਂ ਤੋਂ ਮੌਜੂਦ ਉਲੰਘਣਾਵਾਂ ਕਾਰਨ ਅਸਫਲ ਨਹੀਂ ਹੋ ਸਕਦਾ, ਇੱਕ ਸਥਿਰ ਮਨਜ਼ੂਰਸ਼ੁਦਾ-ਸੂਚੀ ਵਰਤਦਾ ਹੈ
(ਉਦਾਹਰਨ ਲਈ, `KNOWN_STALE_DOC_REFS`, `KNOWN_MISSING`, `KNOWN_RAW_SQL`)। ਨੀਤੀ ਇਹ ਹੈ:

**ਮੂਲ ਕਾਰਨ ਠੀਕ ਕਰੋ; ਮਨਜ਼ੂਰਸ਼ੁਦਾ-ਸੂਚੀ ਸਿਰਫ਼ ਉਦੋਂ ਵਰਤੋ ਜਦੋਂ ਉਲੰਘਣਾ ਪਹਿਲਾਂ ਤੋਂ ਮੌਜੂਦ ਹੋਵੇ ਅਤੇ
ਉਸੇ PR ਵਿੱਚ ਠੀਕ ਨਾ ਕੀਤੀ ਜਾ ਸਕਦੀ ਹੋਵੇ।**

ਮਨਜ਼ੂਰਸ਼ੁਦਾ-ਸੂਚੀ ਵਿੱਚ ਕੋਈ ਐਂਟਰੀ ਸ਼ਾਮਲ ਕਰਦੇ ਸਮੇਂ:

2. ਟ੍ਰੈਕਿੰਗ ਮੁੱਦੇ ਦਾ ਹਵਾਲਾ ਦਿਓ (ਉਦਾਹਰਨ ਲਈ, `// #3498 — ਪੜਾਅ 2 ਦੀ ਵਿਸ਼ੇਸ਼ਤਾ, ਹਾਲੇ ਲਾਗੂ ਨਹੀਂ ਕੀਤੀ ਗਈ`)।
3. ਉਲੰਘਣਾ ਠੀਕ ਕਰਨ ਵਾਲੇ ਉਸੇ PR ਵਿੱਚ ਐਂਟਰੀ ਹਟਾਓ — ਇੱਕ ਪੁਰਾਣੀ ਐਂਟਰੀ ਜੋ ਹੁਣ
   ਕਿਸੇ ਸਰਗਰਮ ਉਲੰਘਣਾ ਨੂੰ ਦਬਾਉਂਦੀ ਨਹੀਂ ਹੈ, ਆਪਣੇ ਆਪ ਵਿੱਚ ਇੱਕ ਖ਼ਰਾਬੀ ਹੈ (6A.3 ਪੁਰਾਣੀ-ਲਾਗੂਕਰਨ ਜਾਂਚ,

## ਨਵਾਂ ਗੇਟ ਸ਼ਾਮਲ ਕਰਨਾ

1. `scripts/check/check-<name>.mjs` (ਜਾਂ `.ts`) ਬਣਾਓ। ਨੀਤੀ ਗੇਟ 0/1 ਨਾਲ ਬੰਦ ਹੁੰਦੇ ਹਨ।
   ਰੈਚਿਟ-ਸ਼ੈਲੀ ਗੇਟ `collect-metrics.mjs` ਰਾਹੀਂ `quality-metrics.json` ਵਿੱਚ ਇੱਕ ਮਾਪਦੰਡ ਲਿਖਦੇ ਹਨ।
2. `package.json` ਵਿੱਚ `"check:<name>": "node scripts/check/check-<name>.mjs"` ਸ਼ਾਮਲ ਕਰੋ।
3. ਇਸਨੂੰ `.github/workflows/ci.yml` ਵਿੱਚ ਢੁਕਵੀਂ ਜੌਬ ਹੇਠ ਜੋੜੋ
   (ਨੀਤੀ → `lint` ਜਾਂ `docs-sync-strict`; ਰੈਚਿਟ → `quality-gate`)।
4. ਜੇ ਇਸਦੀ ਕੋਈ ਮਨਜ਼ੂਰਸ਼ੁਦਾ-ਸੂਚੀ ਹੈ, ਤਾਂ `scripts/check/lib/allowlist.mjs` ਤੋਂ
   `reportStaleEntries()` ਲਾਗੂ ਕਰੋ, ਤਾਂ ਜੋ ਪੁਰਾਣੀਆਂ ਐਂਟਰੀਆਂ ਆਪਣੇ ਆਪ ਪਛਾਣੀਆਂ ਜਾਣ।
5. ਗੇਟ ਦੀ ਪਛਾਣ ਤਰਕ ਨੂੰ ਕਵਰ ਕਰਨ ਵਾਲਾ ਇੱਕ ਟੈਸਟ `tests/unit/build/` ਵਿੱਚ ਲਿਖੋ।
6. ਇਸ ਦਸਤਾਵੇਜ਼ ਨੂੰ ਅੱਪਡੇਟ ਕਰੋ (ਸੰਬੰਧਿਤ ਜੌਬ ਸਾਰਣੀ ਵਿੱਚ ਇੱਕ ਕਤਾਰ ਸ਼ਾਮਲ ਕਰੋ)।

### ਮਰਜ / ਡੀਡੁਪ (ਮਕੈਨੀਕਲ, ਘੱਟ ਜੋਖਮ)

ਕਈ "ਸਪਸ਼ਟ" ਮਰਜਾਂ ਦੇ ਪਿੱਛੇ ਕਰਜ਼ਾ ਲੁਕਿਆ ਹੋਇਆ ਨਿਕਲਿਆ ਅਤੇ ਉਹ **ਸਿੱਧੇ ਤੌਰ 'ਤੇ ਵਰਤਣਯੋਗ ਬਦਲ ਨਹੀਂ** ਹਨ।

- **`check:docs-sync` ਦੋ ਵਾਰ ਚੱਲਦਾ ਹੈ** — `lint` ਜੌਬ ਵਿੱਚ ਵੱਖਰੇ ਤੌਰ 'ਤੇ ਅਤੇ ਮੁੜ `check:docs-all` (`docs-sync-strict`) ਅਤੇ husky pre-commit ਹੁੱਕ ਦੇ ਅੰਦਰ। ✅ **ਪੂਰਾ ਹੋਇਆ** — ਵੱਖਰਾ `lint` ਇਨਵੋਕੇਸ਼ਨ ਹਟਾਇਆ ਗਿਆ।
- **CVE ਸਕੈਨਿੰਗ** — ❌ **ਸਾਫ਼-ਸੁਥਰਾ ਮਰਜ ਨਹੀਂ ਹੈ।** `audit:deps` ਕਿਸੇ ਵੀ high/critical CVE 'ਤੇ ਹਾਰਡ-ਫੇਲ ਹੁੰਦਾ ਹੈ; `check:vuln-ratchet` (osv) ਸਿਰਫ਼ ਬੇਸਲਾਈਨ (ਇਸ ਵੇਲੇ 1 MODERATE) ਦੇ ਮੁਕਾਬਲੇ ਕਿਸੇ _ਰਿਗ੍ਰੈਸ਼ਨ_ 'ਤੇ ਫੇਲ ਹੁੰਦਾ ਹੈ। ਅਰਥ-ਵਿਹਾਰ ਵੱਖਰੇ ਹਨ — `audit:deps` ਨੂੰ ਹਟਾਉਣ ਨਾਲ ਪੂਰਨ high/critical ਗੇਟ ਖਤਮ ਹੋ ਜਾਵੇਗਾ। ਦੋਵੇਂ ਰੱਖੋ।
- **ਚੱਕਰ ਖੋਜ** — ✅ **ਪੂਰਾ ਹੋਇਆ** (#15159 G-01/G-02)। ਇੱਥੇ ਪੁਰਾਣੇ ਟੈਕਸਟ ਨੇ `check:cycles` ਨੂੰ "ਹਰਾ, ਸੰਭਾਲ ਕੇ ਚੁਣਿਆ" ਗੇਟ ਕਿਹਾ ਸੀ ਅਤੇ ਇਸਨੂੰ ਬਲੌਕਿੰਗ ਰੱਖਣ ਨੂੰ ਇਸ ਆਧਾਰ 'ਤੇ ਜਾਇਜ਼ ਠਹਿਰਾਇਆ ਸੀ ਕਿ `check:circular-deps` (dpdm) ਨੇ 91 ਚੱਕਰ ਰਿਪੋਰਟ ਕੀਤੇ ਸਨ। ਉਹ ਹਰਾ ਦਰਜਾ ਇੱਕ **ਗਲਤ ਹਰਾ ਸੰਕੇਤ** ਸੀ: `check:cycles` ਨੇ 5 ਸਬਡਾਇਰੈਕਟਰੀਆਂ (450 ਫ਼ਾਈਲਾਂ) ਸਕੈਨ ਕੀਤੀਆਂ, ਸਿਰਫ਼ ਸਥਿਰ `import|export … from` ਨਾਲ ਮੇਲ ਕੀਤਾ, ਅਤੇ ਹਰੇਕ `@/` ਅਤੇ `@omniroute/open-sse/` ਸਪੈਸੀਫਾਇਰ ਨੂੰ ਛੱਡ ਦਿੱਤਾ, ਇਸ ਲਈ ਇਹ ਉਹ dynamic-import + alias ਚੱਕਰ ਨਹੀਂ ਦੇਖ ਸਕਿਆ ਜੋ ਰਿਪੋ ਵਿੱਚ ਹਾਵੀ ਸਨ। ਠੀਕ ਕੀਤਾ ਗਿਆ: ਗੇਟ ਹੁਣ `src` + `open-sse` (5023 ਫ਼ਾਈਲਾਂ) ਵਿੱਚੋਂ ਲੰਘਦਾ ਹੈ, TypeScript AST ਤੋਂ ਸਪੈਸੀਫਾਇਰ ਇਕੱਠੇ ਕਰਦਾ ਹੈ (ਇਸ ਲਈ `import("…")` ਗਿਣਿਆ ਜਾਂਦਾ ਹੈ ਅਤੇ type-position `typeof import("…")` ਨਹੀਂ), ਅਤੇ tsconfig `paths` ਨੂੰ ਰਿਜ਼ੌਲਵ ਕਰਦਾ ਹੈ। ਇਹ 0 ਨਹੀਂ, ਸਗੋਂ **14** ਚੱਕਰ ਲੱਭਦਾ ਹੈ। ਕਿਉਂਕਿ ਪਹਿਲਾਂ ਤੋਂ ਮੌਜੂਦ 14 ਚੱਕਰਾਂ ਨੂੰ ਗੇਟ PR ਵਿੱਚ ਠੀਕ ਨਹੀਂ ਕੀਤਾ ਜਾ ਸਕਦਾ, `check:cycles` ਹੁਣ ਇੱਕ **ਰੈਚਿਟ** ਹੈ (`--ratchet`, `quality-baseline.json` ਵਿੱਚ ਸੀਮਾ `metrics.cycles.value = 14`, `direction: down`) — ਇਹ ਕਿਸੇ ਵੀ _ਰਿਗ੍ਰੈਸ਼ਨ_ ਨੂੰ ਬਲੌਕ ਕਰਦਾ ਹੈ ਅਤੇ ਗਿਣਤੀ ਸਿਰਫ਼ ਘਟ ਸਕਦੀ ਹੈ। CI `npm run check:cycles:ratchet` ਚਲਾਉਂਦਾ ਹੈ। ਘਟਾਓ ਦਾ ਕੰਮ **A-01** ਦੇ ਨਾਲ ਚੱਲੇਗਾ। `check:circular-deps` (dpdm) ਵਿਆਪਕ ਦੂਜੀ ਰਾਏ ਵਜੋਂ ਸਲਾਹਕਾਰੀ ਰਹਿੰਦਾ ਹੈ।
- **ਜਟਿਲਤਾ** — ✅ **ਪੂਰਾ ਹੋਇਆ** (`check:complexity-ratchets` / `eslint.complexity-ratchets.config.mjs`): ਇੱਕ ESLint ਵਾਕ, `ruleId` ਮੁਤਾਬਕ ਗਿਣਤੀ ਤਾਂ ਜੋ cyclomatic+max-lines ਅਤੇ cognitive ਬੇਸਲਾਈਨਾਂ ਸੁਤੰਤਰ ਰਹਿਣ; ਵੱਖਰੇ `check:complexity` / `check:cognitive-complexity` ਲੋਕਲ `--update` ਲਈ ਬਰਕਰਾਰ ਹਨ।
- **`/api` ਐਂਟੀ-ਹੈਲੂਸੀਨੇਸ਼ਨ** — ✅ **ਪੂਰਾ ਹੋਇਆ** (`check:api-docs-refs` + `scripts/check/lib/apiRoutes.mjs`): `src/app/api` ਦੀ ਇੱਕ FS ਇਨਵੈਂਟਰੀ, openapi-routes + docs-symbols ਹਾਲੇ ਵੀ ਸੁਤੰਤਰ ਤੌਰ 'ਤੇ ਰਿਪੋਰਟ ਕਰਦੇ ਹਨ; ਵੱਖਰੇ ਚੈਕ ਲੋਕਲ ਰਨਾਂ ਲਈ ਬਰਕਰਾਰ ਹਨ।

- **CI lint 'ਤੇ `typecheck:noimplicit:core`** — ✅ **lint ਜੌਬ ਤੋਂ ਹਟਾਇਆ ਗਿਆ** (ਇਹ ਸਲਾਹਕਾਰੀ `continue-on-error` ਸੀ); ਬਲੌਕਿੰਗ type ਸਤਹ `typecheck:core` + `check:type-coverage` ਹੈ। ਲੋਕਲ ਸਕ੍ਰਿਪਟ ਬਰਕਰਾਰ ਹੈ।

ਮੌਜੂਦ 42 locales ਵਿੱਚ ਅਨੁਵਾਦ ਕੀਤਾ। ਕੁਝ ਘੰਟਿਆਂ ਬਾਅਦ EU-language ਬੈਚ (#13044) ਨੇ repo ਨੂੰ 51
locales ਤੱਕ ਪਹੁੰਚਾ ਦਿੱਤਾ, ਅਤੇ ਨੌਂ ਨਵੇਂ ਆਏ locales (`el`, `et`, `ga`, `hr`, `lt`, `lv`, `mt`, `sl`,
`sr`) ਨੂੰ ਉਹ ਕੁੰਜੀਆਂ ਕਦੇ ਨਹੀਂ ਮਿਲੀਆਂ। `deepMergeFallback` ਕਿਸੇ ਗੈਰਹਾਜ਼ਰ ਕੁੰਜੀ ਦੀ ਥਾਂ ਅੰਗਰੇਜ਼ੀ
ਵਰਤਦਾ ਹੈ, ਇਸ ਲਈ ਅਸਫਲਤਾ ਦਾ ਰੂਪ ਖਾਲੀ UI ਦੀ ਬਜਾਏ ਬਿਨਾਂ ਅਨੁਵਾਦ ਵਾਲਾ UI ਸੀ — ਅਸਲ ਸਮੱਸਿਆ, ਅਤੇ
ਬਣਾਵਟ ਅਨੁਸਾਰ ਖਾਮੋਸ਼।

ਆਪਣੇ ਸੰਬੰਧਿਤ ਗੇਟ ਵਾਂਗ ਇਹ ਵੀ **diff-aware** ਹੈ, ਜੋ merge base ਉੱਤੇ ਮੌਜੂਦ ਅੰਗਰੇਜ਼ੀ ਦੀ working
tree ਨਾਲ ਤੁਲਨਾ ਕਰਦਾ ਹੈ, ਇਸ ਲਈ ਪਹਿਲਾਂ ਤੋਂ ਮੌਜੂਦ ਘਾਟਾਂ ਜਿਉਂ ਦੀਆਂ ਤਿਉਂ ਰਹਿੰਦੀਆਂ ਹਨ ਅਤੇ ਗੇਟ ਨੂੰ
ਚਾਲੂ ਕਰਨ ਲਈ ਕਿਸੇ migration ਦੀ ਲੋੜ ਨਹੀਂ ਪਈ।

**ਇੱਕ `__MISSING__:<english>` ਮਾਰਕਰ ਇਸਨੂੰ ਸੰਤੁਸ਼ਟ ਨਹੀਂ ਕਰਦਾ (2026-09-17 ਤੋਂ)।** ਪਹਿਲਾਂ ਇਹ
ਦਸਤਾਵੇਜ਼ਬੱਧ ਮੁਲਤਵੀਕਰਨ ਸੀ — runtime ਸਹੀ ਅੰਗਰੇਜ਼ੀ ਉੱਤੇ fallback ਕਰਦਾ ਹੈ — ਜਦੋਂ ਤੱਕ 2026-09-16
ਨੂੰ ਅੱਠ feature PRs ਨੇ 61 ਕੁੰਜੀਆਂ ਜੋੜ ਕੇ ਅਨੁਵਾਦ ਕਰਨ ਦੀ ਬਜਾਏ ਸਾਰੇ 65 locales ਵਿੱਚ ਮਾਰਕਰ ਨਹੀਂ
ਲਗਾ ਦਿੱਤਾ: ਇਸ ਗੇਟ ਨੇ ਹਰ ਇੱਕ ਨੂੰ ਸਵੀਕਾਰ ਕਰ ਲਿਆ, PRs ਨੂੰ ਕਿਸੇ ਚੀਜ਼ ਨੇ ਨਹੀਂ ਰੋਕਿਆ, ਅਤੇ ਫਿਰ

#### `check-vitest-exclusions` — ਰੋਕੇ ਹੋਏ ਟੈਸਟਾਂ ਦਾ ਗੇਟ

`vitest.config.ts` ਦੀ `exclude` ਸੂਚੀ ਵਿੱਚ ਮੌਜੂਦ ਫ਼ਾਈਲ ਇੱਕ ਅਜਿਹਾ ਟੈਸਟ ਹੈ ਜੋ ਚੱਲਦਾ ਨਹੀਂ, ਅਤੇ tree
ਨੂੰ ਪੜ੍ਹਨ ਵਾਲੇ ਵਿਅਕਤੀ ਨੂੰ ਇਹ coverage ਵਰਗਾ ਦਿਸਦਾ ਹੈ। ਇਸ ਟਿੱਪਣੀ ਦੇ ਪਿੱਛੇ ਬਾਹਠ ਫ਼ਾਈਲਾਂ ਇਕੱਠੀਆਂ
ਹੋ ਗਈਆਂ:
`// #8618 — ਪਹਿਲਾਂ ਤੋਂ ਮੌਜੂਦ ਅਸਫਲਤਾ; ਠੀਕ ਹੋਣ 'ਤੇ ਇਹ exclusion ਹਟਾਓ`। Issue #8618 ਨੂੰ
2026-08-11 ਨੂੰ ਬੰਦ ਕਰ ਦਿੱਤਾ ਗਿਆ ਸੀ, ਜਦਕਿ ਇਸ ਵੱਲੋਂ ਟਰੈਕ ਕੀਤੀ ਸੂਚੀ 45 entries ਤੋਂ ਵਧ ਕੇ 62 ਹੋ
ਗਈ ਸੀ, ਅਤੇ ਹਰ ਨਵੀਂ entry ਨੂੰ ਇੱਕ ਬੰਦ issue ਵੱਲ ਇਸ਼ਾਰਾ ਕਰਦੀ ਟਿੱਪਣੀ ਵਿਰਾਸਤ ਵਿੱਚ ਮਿਲੀ। ਜਦੋਂ ਅੰਤ
ਵਿੱਚ ਸੂਚੀ ਨੂੰ ਫ਼ਾਈਲ-ਦਰ-ਫ਼ਾਈਲ ਮਾਪਿਆ ਗਿਆ (#13204), ਤਾਂ **62 ਵਿੱਚੋਂ 51 ਮੌਜੂਦਾ tree ਦੇ ਵਿਰੁੱਧ
ਬਿਨਾਂ ਕਿਸੇ source ਬਦਲਾਅ ਦੇ ਪਾਸ ਹੋ ਗਈਆਂ**।

ਗੇਟ ਲਈ ਲਾਜ਼ਮੀ ਹੈ ਕਿ ਅਸਲ ਫ਼ਾਈਲ ਵਜੋਂ resolve ਹੋਣ ਵਾਲਾ ਹਰ exclusion (a) ਕਿਸੇ tracking issue ਦਾ

ਤਾਂ ਜੋ ਇੱਕ ਹੋਰ entry ਜੋੜਨਾ 60-entry array ਵਿੱਚ ਸਿਰਫ਼ ਇੱਕ ਹੋਰ ਲਾਈਨ ਬਣਨ ਦੀ ਬਜਾਏ ਇੱਕ ਸਮਰਪਿਤ ਫ਼ਾਈਲ
