| ਡੈਸਕਟਾਪ      | **Electron 41** + `electron-builder` 26.10 (`electron/` ਵਿੱਚ ਵੱਖਰਾ ਵਰਕਸਪੇਸ)                                          |
| ਟੈਸਟ         | **Node ਨੇਟਿਵ ਟੈਸਟ ਰਨਰ** (ਯੂਨਿਟ/ਇੰਟੀਗ੍ਰੇਸ਼ਨ), **Vitest** (MCP, autoCombo, ਕੈਸ਼), **Playwright** (e2e + protocols-e2e) |
| ਬਿਲਡ         | `scripts/build/build-next-isolated.mjs` ਰਾਹੀਂ Next.js standalone                                                     |
| ਲਿੰਟ/ਫਾਰਮੈਟ  | ESLint ਫਲੈਟ ਕੌਂਫਿਗ + Prettier (Husky pre-commit ਰਾਹੀਂ `lint-staged`)                                                 |
| ਮੋਡੀਊਲ ਸਿਸਟਮ | ਹਰ ਥਾਂ ESM (`"type": "module"`)                                                                                      |
| ਡੈਸ਼ਬੋਰਡ UI  | **Tailwind CSS 4** + ਵੈਂਡਰ ਕੀਤਾ **Keak CI UI Kit** (`packages/ui-kit`), Lucide ਆਇਕਨ — `DESIGN_SYSTEM.md` ਵੇਖੋ        |
| ਵਰਕਸਪੇਸ      | npm ਵਰਕਸਪੇਸ — `open-sse`, `packages/browser-pool`, `packages/ui-kit`                                                 |

ਪਾਥ ਉਪਨਾਮ (`tsconfig.json`):

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`
- `@omniroute/ui-kit` → `packages/ui-kit/src`, `@omniroute/ui-kit/*` → `packages/ui-kit/src/*`

ਡਿਫੌਲਟ HTTP ਪੋਰਟ: **`20128`** (API ਅਤੇ ਡੈਸ਼ਬੋਰਡ ਇੱਕੋ ਪ੍ਰਕਿਰਿਆ ਸਾਂਝੀ ਕਰਦੇ ਹਨ)। ਡਾਟਾ
ਡਾਇਰੈਕਟਰੀ `DATA_DIR` env var ਹੈ, ਜੋ ਡਿਫੌਲਟ ਤੌਰ 'ਤੇ `~/.omniroute/` ਹੁੰਦੀ ਹੈ।

### 3.1 `src/app/` — App Router

App Router ਦੋਵੇਂ ਡੈਸ਼ਬੋਰਡ UI ਅਤੇ ਪਬਲਿਕ/ਮੈਨੇਜਮੈਂਟ HTTP API ਨੂੰ ਐਕਸਪੋਜ਼ ਕਰਦਾ ਹੈ।
**ਕੋਈ ਗਲੋਬਲ ਮਿਡਲਵੇਅਰ ਨਹੀਂ** ਹੈ — ਇੰਟਰਸੈਪਸ਼ਨ ਹਰ ਰੂਟ ਲਈ ਵੱਖਰੇ ਤੌਰ 'ਤੇ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

`src/app/` ਹੇਠ ਉੱਪਰਲੇ-ਪੱਧਰ ਦੇ ਸੈਗਮੈਂਟ:

| ਪਾਥ                                                                           | ਮਕਸਦ                                       |
| ----------------------------------------------------------------------------- | ------------------------------------------ |
| `api/`                                                                        | ਸਾਰੇ HTTP API ਰੂਟ (ਹੇਠਾਂ ਵੰਡ ਵੇਖੋ)         |
| `a2a/`                                                                        | A2A JSON-RPC 2.0 ਐਂਡਪੌਇੰਟ (`POST /a2a`)    |
| `.well-known/agent.json/`                                                     | A2A ਏਜੰਟ ਕਾਰਡ ਡਿਸਕਵਰੀ ਦਸਤਾਵੇਜ਼             |

| `landing/`                                                                    | ਮਾਰਕੀਟਿੰਗ/ਲੈਂਡਿੰਗ ਪੇਜ                      |

| `400/`, `401/`, `403/`, `408/`, `429/`, `500/`, `502/`, `503/`                | ਸਥਿਰ ਐਰਰ ਪੇਜ                               |

#### 3.1.2a `src/app/api/services/` — ਏਮਬੈਡਡ ਸੇਵਾਵਾਂ ਦਾ ਪ੍ਰਬੰਧਨ

9Router ਅਤੇ CLIProxyAPI ਨੂੰ ਇੰਸਟਾਲ ਕਰਨ, ਸ਼ੁਰੂ ਕਰਨ, ਰੋਕਣ ਅਤੇ ਮਾਨੀਟਰ ਕਰਨ ਲਈ ਰੂਟ।
ਸਾਰੇ ਪਾਥ **LOCAL_ONLY** ਵਜੋਂ ਸ਼੍ਰੇਣੀਬੱਧ ਹਨ (ਸਿਰਫ਼ ਲੂਪਬੈਕ, ਸਖ਼ਤ ਨਿਯਮ #17) ਕਿਉਂਕਿ ਇਹ
`npm install` ਨੂੰ ਚਲਾ ਸਕਦੇ ਹਨ ਅਤੇ ਚਾਈਲਡ ਪ੍ਰੋਸੈਸ ਸਪੌਨ ਕਰ ਸਕਦੇ ਹਨ।

```
src/app/api/services/
├── 9router/
│   ├── _lib.ts             getOrInitSupervisor() helper
│   ├── install/route.ts    POST — npm install via execFile
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — npm install newer version
│   ├── rotate-key/route.ts POST — generate new API key + restart
│   ├── status/route.ts     GET  — live + DB status + version metadata
│   └── auto-start/route.ts POST — toggle auto_start flag
```

## 10. ਯੋਗਦਾਨ ਕਿਵੇਂ ਪਾਉਣਾ ਹੈ

### ਨਵਾਂ ਪ੍ਰਦਾਤਾ ਸ਼ਾਮਲ ਕਰੋ

   (`BaseExecutor` ਨੂੰ ਵਿਸਤਾਰ ਦਿਓ)।
3. ਜੇ ਇਹ OpenAI ਫਾਰਮੈਟ ਦੀ ਵਰਤੋਂ ਨਹੀਂ ਕਰਦਾ, ਤਾਂ `open-sse/translator/` ਵਿੱਚ ਇੱਕ ਅਨੁਵਾਦਕ ਸ਼ਾਮਲ ਕਰੋ।
4. ਜੇ OAuth-ਅਧਾਰਿਤ ਹੈ, ਤਾਂ `src/lib/oauth/providers/` ਅਤੇ
   `src/lib/oauth/services/` ਹੇਠ ਕਨਫਿਗ ਸ਼ਾਮਲ ਕਰੋ।
5. ਮਾਡਲਾਂ ਨੂੰ `open-sse/config/providerRegistry.ts` ਵਿੱਚ ਰਜਿਸਟਰ ਕਰੋ (ਜਾਂ
   `open-sse/config/` ਹੇਠ ਫਾਰਮੈਟ-ਵਿਸ਼ੇਸ਼ ਰਜਿਸਟਰੀ ਵਿੱਚ)।
6. `tests/unit/` ਹੇਠ ਟੈਸਟ ਲਿਖੋ।

4. ਜੇ ਕੇਵਲ ਪ੍ਰਬੰਧਨ ਲਈ ਹੈ: ਪਾਥ ਨੂੰ `src/shared/constants/publicApiRoutes.ts`
   ਵਿੱਚ ਸ਼ਾਮਲ ਕਰੋ (ਜਨਤਕ API ਸਤਹ ਲਈ ਡਿਨਾਇਲਿਸਟ)।
5. `tests/unit/` ਹੇਠ ਟੈਸਟ ਸ਼ਾਮਲ ਕਰੋ।
6. `docs/reference/API_REFERENCE.md` ਅਤੇ `docs/openapi.yaml` ਨੂੰ ਅੱਪਡੇਟ ਕਰੋ।

### ਨਵਾਂ DB ਮੋਡੀਊਲ ਸ਼ਾਮਲ ਕਰੋ

1. `src/lib/db/yourModule.ts` ਬਣਾਓ ਅਤੇ `./core.ts` ਤੋਂ `getDbInstance()` ਨੂੰ ਇੰਪੋਰਟ ਕਰੋ।
2. ਆਪਣੇ ਡੋਮੇਨ ਲਈ CRUD ਫੰਕਸ਼ਨ ਐਕਸਪੋਰਟ ਕਰੋ।
3. ਜੇ ਨਵੀਆਂ ਟੇਬਲਾਂ ਹਨ: `src/lib/db/migrations/` ਹੇਠ ਕ੍ਰਮਵਾਰ ਨੰਬਰ ਵਾਲੀ,
   ਆਈਡੈਂਪੋਟੈਂਟ ਅਤੇ ਟ੍ਰਾਂਜ਼ੈਕਸ਼ਨਲ ਮਾਈਗ੍ਰੇਸ਼ਨ ਸ਼ਾਮਲ ਕਰੋ।
4. ਇੰਪੋਰਟਰ `@/lib/db/yourModule` ਤੋਂ ਸਿੱਧੇ ਇੰਪੋਰਟ ਵਰਤਦੇ ਹਨ (ਕੋਈ ਬੈਰਲ ਨਹੀਂ — ਪੁਰਾਣੀ `localDb.ts` ਰੀ-ਐਕਸਪੋਰਟ ਪਰਤ ਹਟਾ ਦਿੱਤੀ ਗਈ ਸੀ)।
5. `tests/unit/` ਹੇਠ ਟੈਸਟ ਸ਼ਾਮਲ ਕਰੋ।

### ਨਵਾਂ MCP ਟੂਲ ਸ਼ਾਮਲ ਕਰੋ

1. `open-sse/mcp-server/tools/` ਹੇਠ ਟੂਲ ਦੀ ਪਰਿਭਾਸ਼ਾ ਸ਼ਾਮਲ ਕਰੋ (ਜਾਂ
   `open-sse/mcp-server/schemas/tools.ts` ਨੂੰ ਵਿਸਤਾਰ ਦਿਓ)।
2. `src/shared/constants/mcpScopes.ts` ਵਿੱਚ ਢੁਕਵੇਂ ਸਕੋਪ ਨਿਰਧਾਰਤ ਕਰੋ।
3. ਟੂਲ ਨੂੰ `open-sse/mcp-server/server.ts` ਵਿੱਚ ਰਜਿਸਟਰ ਕਰੋ।
4. `open-sse/mcp-server/__tests__/` ਹੇਠ ਟੈਸਟ ਸ਼ਾਮਲ ਕਰੋ।
5. [MCP-SERVER.md](../frameworks/MCP-SERVER.md) ਨੂੰ ਅੱਪਡੇਟ ਕਰੋ।

## 11. ਰਵਾਇਤਾਂ

- **ਕੋਡ ਸ਼ੈਲੀ**: 2-ਸਪੇਸ ਇੰਡੈਂਟ, ਡਬਲ ਕੋਟ, 100 ਅੱਖਰ ਚੌੜਾਈ, ਸੈਮੀਕੋਲਨ,
  `es5` ਟ੍ਰੇਲਿੰਗ ਕਾਮੇ — `lint-staged` ਰਾਹੀਂ Prettier ਦੁਆਰਾ ਲਾਗੂ ਕੀਤੇ ਜਾਂਦੇ ਹਨ।
- **ਇੰਪੋਰਟ**: ਬਾਹਰੀ → ਅੰਦਰੂਨੀ (`@/`, `@omniroute/open-sse`) → ਰਿਲੇਟਿਵ।
- **ਨਾਮਕਰਨ**: ਫਾਈਲਾਂ `camelCase` ਜਾਂ `kebab-case`, ਕੰਪੋਨੈਂਟ `PascalCase`,
  ਕਾਂਸਟੈਂਟ `UPPER_SNAKE`।
- **ESLint**: `no-eval`, `no-implied-eval`, `no-new-func` = ਹਰ ਥਾਂ `error`;
  `no-explicit-any` = `open-sse/` ਅਤੇ `tests/` ਵਿੱਚ `warn`, ਹੋਰ ਥਾਵਾਂ 'ਤੇ error।
- **TypeScript**: `strict: false` (ਵਿਰਾਸਤੀ ਰੁਖ਼)। ਕ੍ਰਾਸ-ਮੋਡੀਊਲ ਸੀਮਾਵਾਂ ਲਈ
  ਇਨਫਰੈਂਸ ਦੀ ਬਜਾਏ ਸਪਸ਼ਟ ਟਾਈਪਾਂ ਨੂੰ ਤਰਜੀਹ ਦਿਓ।
- **ਡਾਟਾਬੇਸ**: ਰੂਟਾਂ ਜਾਂ ਹੈਂਡਲਰਾਂ ਵਿੱਚ ਕਦੇ ਵੀ ਕੱਚੀ SQL ਨਾ ਲਿਖੋ — ਹਮੇਸ਼ਾ
  `src/lib/db/` ਮੋਡੀਊਲਾਂ ਰਾਹੀਂ ਜਾਓ। ਕਦੇ ਵੀ ਬੈਰਲ-ਇੰਪੋਰਟ ਨਾ ਕਰੋ — ਖਾਸ `src/lib/db/*` ਮੋਡੀਊਲ ਸਿੱਧੇ ਵਰਤੋ।
- **DB-ਐਂਟਿਟੀ ਟਾਈਪਿੰਗ (#3512)**: DB ਟੇਬਲ ਦੀ ਕਤਾਰ ਦੀ ਬਣਤਰ ਲਿਖਣ ਜਾਂ ਪੜ੍ਹਨ ਵਾਲੇ
  ਫੰਕਸ਼ਨ ਨੂੰ ਇੱਕ ਨਾਮਿਤ TS ਇੰਟਰਫੇਸ ਲੈਣਾ/ਵਾਪਸ ਕਰਨਾ ਚਾਹੀਦਾ ਹੈ, ਜੋ ਉਸ ਟੇਬਲ ਦੇ
  ਕਾਲਮਾਂ ਨੂੰ 1:1 ਦਰਸਾਉਂਦਾ ਹੋਵੇ; ਕਾਲ ਸਾਈਟ 'ਤੇ `any` ਜਾਂ ਇਨਲਾਈਨ ਬੇਨਾਮ ਟਾਈਪ ਨਹੀਂ। ਇੰਟਰਫੇਸ ਨੂੰ
  ਫੰਕਸ਼ਨ ਦੇ ਕੋਲ ਰੱਖੋ (ਉਦਾਹਰਨ ਲਈ `saveRequestUsage` ਤੋਂ ਉੱਪਰ
  `src/lib/usage/usageHistory.ts` ਵਿੱਚ `export interface UsageEntry`), ਜਦੋਂ ਵੱਖ-ਵੱਖ
  ਰਾਈਟਰ ਕਤਾਰ ਨੂੰ ਪੜਾਅਵਾਰ ਭਰਦੇ ਹਨ ਤਾਂ ਵੱਖਰੇ ਫੀਲਡਾਂ ਨੂੰ ਵਿਕਲਪਿਕ/ਨੱਲਯੋਗ
  ਰੱਖੋ, ਅਤੇ ਅਜਿਹੇ ਫੀਲਡ ਲਈ ਜਿਸ ਦੀ ਬਣਤਰ ਵੱਖ-ਵੱਖ ਕਾਲਰਾਂ ਵਿੱਚ ਬਦਲਦੀ ਹੈ,
  `any` ਦੀ ਬਜਾਏ `unknown` ਨੂੰ ਤਰਜੀਹ ਦਿਓ (ਫੀਲਡ 'ਤੇ ਦਸਤਾਵੇਜ਼ਬੱਧ, ਉਦਾਹਰਨ ਲਈ `UsageEntry.tokens`
  ਕੱਚੀ ਪ੍ਰਦਾਤਾ-ਆਕਾਰ ਵਾਲੀ ਵਰਤੋਂ ਅਤੇ ਨਾਰਮਲਾਈਜ਼ ਕੀਤੀ ਬਣਤਰ ਦੋਵੇਂ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ)। ਜਦੋਂ ਕਿਸੇ
  ਫਾਈਲ ਦੀ `any` ਗਿਣਤੀ ਇਸ ਤਰ੍ਹਾਂ ਸਿਫ਼ਰ 'ਤੇ ਪਹੁੰਚ ਜਾਵੇ, ਤਾਂ ਉਸ ਨੂੰ
  `check:any-budget:t11` ਅਲਾਊਲਿਸਟ (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`) ਵਿੱਚ ਸ਼ਾਮਲ ਕਰੋ ਤਾਂ ਜੋ ਇਹ ਪਿੱਛੇ ਨਾ ਮੁੜ ਸਕੇ। ਇਹ ਪਹਿਲੇ-ਹਿੱਸੇ ਦੀ ਰਵਾਇਤ ਹੈ —
  ਵਿਆਪਕ "ਕੋਈ ਬੇਨਾਮ `any` ਨਹੀਂ" ਸਫਾਈ ਬਾਕੀ ਕੋਡਬੇਸ ਵਿੱਚ ਦੁਹਰਾਓ ਵਾਲੇ ਢੰਗ ਨਾਲ ਕੀਤੀ ਜਾਂਦੀ ਹੈ।
- **ਗਲਤੀਆਂ**: ਖਾਸ ਐਰਰ ਟਾਈਪਾਂ ਨਾਲ try/catch ਵਰਤੋ, pino ਕਾਂਟੈਕਸਟ ਨਾਲ ਲੌਗ ਕਰੋ। SSE ਸਟ੍ਰੀਮਾਂ ਵਿੱਚ
  ਗਲਤੀਆਂ ਨੂੰ ਕਦੇ ਵੀ ਚੁੱਪਚਾਪ ਨਾ ਦਬਾਓ; ਸਫਾਈ ਲਈ abort ਸਿਗਨਲ ਵਰਤੋ।
- **ਸੁਰੱਖਿਆ**: ਕਦੇ ਵੀ `eval()` / `new Function()` / implied eval ਨਾ ਵਰਤੋ। ਸਾਰੇ
  ਇਨਪੁੱਟ Zod ਨਾਲ ਪ੍ਰਮਾਣਿਤ ਕਰੋ। ਸਟੋਰ ਕੀਤੇ ਕਰੀਡੈਂਸ਼ਲ ਐਨਕ੍ਰਿਪਟ ਕਰੋ (AES-256-GCM)।
  `src/shared/constants/upstreamHeaders.ts` ਡਿਨਾਇਲਿਸਟ ਨੂੰ
  ਸੈਨਿਟਾਈਜ਼/ਪ੍ਰਮਾਣੀਕਰਨ ਪਰਤ ਨਾਲ ਇਕਸਾਰ ਰੱਖੋ।
- **ਕਮਿਟ**: Conventional Commits — `feat(scope): subject`। ਮਨਜ਼ੂਰਸ਼ੁਦਾ ਸਕੋਪ:
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`।
- **ਬ੍ਰਾਂਚਾਂ**: ਪ੍ਰੀਫਿਕਸ `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`। ਕਦੇ ਵੀ ਸਿੱਧਾ `main` ਵਿੱਚ ਕਮਿਟ ਨਾ ਕਰੋ।
- **Husky**: pre-commit `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11` ਚਲਾਉਂਦਾ ਹੈ; pre-push `check:any-budget:t11` + `check:tracked-artifacts` ਚਲਾਉਂਦਾ ਹੈ (ਤੇਜ਼ ਗੇਟ; `test:unit` ਨੂੰ ਸ਼ਾਮਲ ਨਹੀਂ ਕਰਦਾ)।

## 12. ਸਖ਼ਤ ਨਿਯਮ (CLAUDE.md ਤੋਂ)

1. ਭੇਦ ਜਾਂ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਕਦੇ ਵੀ ਕਮਿਟ ਨਾ ਕਰੋ।
2. ਕਦੇ ਵੀ ਬੈਰਲ-ਇੰਪੋਰਟ ਨਾ ਕਰੋ — ਖ਼ਾਸ `src/lib/db/*` ਮੋਡੀਊਲਾਂ ਨੂੰ ਸਿੱਧੇ ਵਰਤੋ।
3. ਕਦੇ ਵੀ `eval()` / `new Function()` / ਅਪ੍ਰਤੱਖ eval ਨਾ ਵਰਤੋ।
4. ਕਦੇ ਵੀ ਸਿੱਧੇ `main` ਵਿੱਚ ਕਮਿਟ ਨਾ ਕਰੋ।
5. ਰੂਟਾਂ ਵਿੱਚ ਕਦੇ ਵੀ ਕੱਚੀ SQL ਨਾ ਲਿਖੋ — ਹਮੇਸ਼ਾ `src/lib/db/` ਮੋਡੀਊਲਾਂ ਰਾਹੀਂ ਜਾਓ।
6. SSE ਸਟ੍ਰੀਮਾਂ ਵਿੱਚ ਗਲਤੀਆਂ ਨੂੰ ਕਦੇ ਵੀ ਚੁੱਪਚਾਪ ਅਣਡਿੱਠਾ ਨਾ ਕਰੋ।
7. ਇਨਪੁੱਟਾਂ ਨੂੰ ਹਮੇਸ਼ਾ Zod ਸਕੀਮਾਂ ਨਾਲ ਪ੍ਰਮਾਣਿਤ ਕਰੋ।
8. ਪ੍ਰੋਡਕਸ਼ਨ ਕੋਡ ਬਦਲਦੇ ਸਮੇਂ ਹਮੇਸ਼ਾ ਟੈਸਟ ਸ਼ਾਮਲ ਕਰੋ।
9. ਕਵਰੇਜ ≥ 60% ਰਹਿਣੀ ਲਾਜ਼ਮੀ ਹੈ (ਸਟੇਟਮੈਂਟ, ਲਾਈਨਾਂ, ਫੰਕਸ਼ਨ, ਬ੍ਰਾਂਚਾਂ)।
