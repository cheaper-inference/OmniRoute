> **ਸੱਚਾਈ ਦਾ ਸਰੋਤ:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, ਅਤੇ
> `src/app/(dashboard)/dashboard/plugins/`
> **ਆਖਰੀ ਅੱਪਡੇਟ:** 2026-06-28 — v3.8.40

OmniRoute ਵਿੱਚ WordPress-ਸ਼ੈਲੀ ਦਾ ਪਲੱਗਇਨ ਸਿਸਟਮ ਸ਼ਾਮਲ ਹੈ। ਪਲੱਗਇਨ ਸਵੈ-ਨਿਰਭਰ
ਡਾਇਰੈਕਟਰੀਆਂ ਹਨ — ਹਰ ਇੱਕ ਵਿੱਚ ਇੱਕ `plugin.json` ਮੈਨੀਫੈਸਟ ਅਤੇ ਇੱਕ ਐਂਟਰੀ ਫ਼ਾਈਲ ਹੁੰਦੀ ਹੈ — ਜੋ
ਬੇਨਤੀ ਪਾਈਪਲਾਈਨ (`onRequest` / `onResponse` / `onError`) ਅਤੇ
ਲਾਈਫਸਾਈਕਲ ਇਵੈਂਟਾਂ (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`) ਨਾਲ ਜੁੜਦੀਆਂ ਹਨ।

**ਪਲੱਗਇਨ ਮਾਰਕੀਟਪਲੇਸ** ਉਸ ਸਿਸਟਮ ਦੇ ਉੱਪਰ ਬਣੀ ਖੋਜ ਪਰਤ ਹੈ। ਇਹ
ਇੰਸਟਾਲ ਕੀਤੇ ਜਾ ਸਕਣ ਵਾਲੇ ਪਲੱਗਇਨਾਂ ਦਾ ਬ੍ਰਾਊਜ਼ ਕਰਨ ਯੋਗ ਕੈਟਾਲਾਗ ਉਪਲਬਧ ਕਰਵਾਉਂਦੀ ਹੈ। ਮੂਲ ਰੂਪ ਵਿੱਚ ਕੈਟਾਲਾਗ ਇੱਕ
ਛੋਟੀ ਬਿਲਟ-ਇਨ ਸੀਡ ਰਜਿਸਟਰੀ ਹੁੰਦਾ ਹੈ; ਕੋਈ ਓਪਰੇਟਰ ਇਸਨੂੰ ਇੱਕ ਕਸਟਮ ਰਿਮੋਟ
ਰਜਿਸਟਰੀ URL ਵੱਲ ਨਿਰਦੇਸ਼ਿਤ ਕਰ ਸਕਦਾ ਹੈ, ਜਿਸ ਸਥਿਤੀ ਵਿੱਚ ਫੈਚ ਨੂੰ DNS-ਰਿਜ਼ਾਲਵਿੰਗ SSRF ਗਾਰਡ ਰਾਹੀਂ
ਸੁਰੱਖਿਅਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ([ਸੁਰੱਖਿਆ](#security) ਵੇਖੋ)।

ਹਰ ਪਲੱਗਇਨ ਰੂਟ **ਕੇਵਲ ਲੂਪਬੈਕ** ਹੈ (ਟੀਅਰ 1 — `LOCAL_ONLY`): ਪਲੱਗਇਨ ਚਾਈਲਡ ਪ੍ਰੋਸੈਸਾਂ ਵਿੱਚ
ਕੋਡ ਲੋਡ ਅਤੇ ਚਲਾਉਂਦੇ ਹਨ, ਇਸ ਲਈ ਪ੍ਰਮਾਣੀਕਰਨ ਦੀ ਪਰਵਾਹ ਕੀਤੇ ਬਿਨਾਂ ਰੂਟਾਂ ਤੱਕ
ਕਿਸੇ ਗੈਰ-ਲੂਪਬੈਕ ਮੂਲ ਤੋਂ ਪਹੁੰਚ ਨਹੀਂ ਕੀਤੀ ਜਾ ਸਕਦੀ। ਵੇਖੋ
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)।

## ਇਹ Together ਕਿਵੇਂ ਫਿੱਟ ਕਰਦਾ ਹੈ

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **ਰਜਿਸਟਰੀ ਪਰਤ** — `src/lib/plugins/marketplace.ts`: ਸੂਚੀਆਂ / ਸੂਚੀਆਂ ਦੀ ਖੋਜ ਕਰਦਾ ਹੈ, ਕਿਸੇ ਵੀ ਅਸਫਲਤਾ 'ਤੇ ਬੀਜ ਰਜਿਸਟਰੀ 'ਤੇ ਵਾਪਸ ਆਉਂਦਾ ਹੈ।
- **ਜੀਵਨ ਚੱਕਰ ਪਰਤ** — `src/lib/plugins/manager.ts` (`pluginManager` ਸਿੰਗਲਟਨ): ਸਥਾਪਿਤ ਕਰੋ, ਅਪਗ੍ਰੇਡ ਕਰੋ, ਕਿਰਿਆਸ਼ੀਲ ਕਰੋ, ਅਕਿਰਿਆਸ਼ੀਲ ਕਰੋ, ਅਣਇੰਸਟੌਲ ਕਰੋ, ਸਕੈਨ ਕਰੋ, ਸਟਾਰਟਅਪ ਲੋਡ ਕਰੋ।
- **ਮੈਨੀਫੈਸਟ ਪਰਤ** — `src/lib/plugins/manifest.ts`: `plugin.json` ਲਈ Zod ਸਕੀਮਾ + ਡਿਫਾਲਟ ਹੈ।
- **ਸਕੈਨਰ** — `src/lib/plugins/scanner.ts`: ਪਲੱਗਇਨ ਡਾਇਰੈਕਟਰੀ ਦੇ ਅਧੀਨ ਡਿਸਕ 'ਤੇ ਪਲੱਗਇਨ ਖੋਜਦਾ ਹੈ।
- **ਲੋਡਰ** — `src/lib/plugins/loader.ts`: ਹਰੇਕ ਪਲੱਗਇਨ ਨੂੰ ਇੱਕ ਵੱਖਰੀ Node.js ਚਾਈਲਡ ਪ੍ਰਕਿਰਿਆ ਵਿੱਚ ਪੈਦਾ ਕਰਦਾ ਹੈ ਅਤੇ ਦਲਾਲ IPC ਉੱਤੇ ਕਾਲਾਂ ਨੂੰ ਹੁੱਕ ਕਰਦਾ ਹੈ। ਬੱਚਾ ਸੈਂਡਬੌਕਸ ਨਹੀਂ ਹੈ (ਹੇਠਾਂ "ਪਲੱਗਇਨ ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਆਈਸੋਲੇਸ਼ਨ" ਦੇਖੋ)।

## ਮਾਰਕੀਟਪਲੇਸ ਕੈਟਾਲਾਗ

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`)
`MarketplaceEntry` ਆਬਜੈਕਟਾਂ ਦੀ ਇੱਕ ਸੂਚੀ ਵਾਪਸ ਕਰਦਾ ਹੈ:

| ਫ਼ੀਲਡ         | ਕਿਸਮ     | ਨੋਟਸ                                              |
| ------------- | -------- | ------------------------------------------------- |
| `name`        | string   | kebab-case ਪਲੱਗਇਨ ਨਾਮ                             |
| `version`     | string   | semver                                            |
| `description` | string   | ਸੰਖੇਪ ਵੇਰਵਾ                                       |
| `author`      | string   | ਲੇਖਕ / ਸੰਗਠਨ                                      |
| `license`     | string   | SPDX-ਸ਼ੈਲੀ ਲਾਇਸੈਂਸ id                             |
| `downloadUrl` | string   | ਸਰੋਤ ਡਾਊਨਲੋਡ URL (ਖਾਲੀ ਹੋ ਸਕਦਾ ਹੈ)                |
| `repository`  | string?  | ਵਿਕਲਪਿਕ ਰਿਪੋਜ਼ਟਰੀ URL                             |
| `tags`        | string[] | ਖੋਜ/ਫਿਲਟਰ ਟੈਗ                                     |
| `downloads`   | number   | ਡਾਊਨਲੋਡ ਗਿਣਤੀ                                     |
| `rating`      | number   | 0–5                                               |
| `verified`    | boolean  | ਕੀ ਐਂਟਰੀ ਨੂੰ ਤਸਦੀਕਸ਼ੁਦਾ ਵਜੋਂ ਚਿੰਨ੍ਹਿਤ ਕੀਤਾ ਗਿਆ ਹੈ |
| `lastUpdated` | string   | ISO-ਵਰਗੀ ਮਿਤੀ ਸਟ੍ਰਿੰਗ                             |

ਜਦੋਂ ਕੋਈ ਕਸਟਮ ਰਜਿਸਟਰੀ URL ਕਨਫਿਗਰ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ, ਤਾਂ ਕੈਟਾਲਾਗ ਬਿਲਟ-ਇਨ
`SEED_REGISTRY` ਹੁੰਦਾ ਹੈ (ਵਰਤਮਾਨ ਵਿੱਚ `request-logger`, `rate-limiter`, `cost-tracker`, ਅਤੇ
`theme-manager`)। ਸੀਡ ਰਜਿਸਟਰੀ ਹਮੇਸ਼ਾ ਉਪਲਬਧ ਰਹਿੰਦੀ ਹੈ — ਜੇ ਕੋਈ ਕਨਫਿਗਰ ਕੀਤੀ ਰਿਮੋਟ
ਰਜਿਸਟਰੀ ਪਹੁੰਚ ਤੋਂ ਬਾਹਰ ਹੋਵੇ, ਗੈਰ-`200` ਸਥਿਤੀ ਵਾਪਸ ਕਰੇ, ਜਾਂ ਅਣਪਛਾਤੀ
ਬਾਡੀ ਵਾਪਸ ਕਰੇ, ਤਾਂ `listMarketplacePlugins()` ਇੱਕ ਚੇਤਾਵਨੀ ਲੌਗ ਕਰਦਾ ਹੈ ਅਤੇ ਸੀਡ ਸੂਚੀ
ਵਰਤਦਾ ਹੈ।

> ਨੋਟ: ਮਾਰਕੀਟਪਲੇਸ **ਕੈਟਾਲਾਗ** (ਬ੍ਰਾਊਜ਼/ਖੋਜ) ਸ਼ੁਰੂ ਤੋਂ ਅੰਤ ਤੱਕ ਜੁੜਿਆ ਹੋਇਆ ਹੈ, ਪਰ
> ਕੈਟਾਲਾਗ ਤੋਂ ਇੱਕ-ਕਲਿੱਕ ਮਾਰਕੀਟਪਲੇਸ **ਇੰਸਟਾਲ** ਅਜੇ ਲਾਗੂ ਨਹੀਂ ਕੀਤਾ ਗਿਆ — ਕਿਸੇ ਮਾਰਕੀਟਪਲੇਸ ਐਂਟਰੀ ਉੱਤੇ
> ਡੈਸ਼ਬੋਰਡ ਦਾ "ਇੰਸਟਾਲ" ਬਟਨ ਵਰਤਮਾਨ ਵਿੱਚ "ਜਲਦੀ ਆ ਰਿਹਾ ਹੈ" ਸੂਚਨਾ ਦਿਖਾਉਂਦਾ ਹੈ।
> ਅੱਜ ਇੰਸਟਾਲੇਸ਼ਨ ਲੋਕਲ-ਪਾਥ ਇੰਸਟਾਲ ਫ਼ਲੋ (`POST /api/plugins`) ਅਤੇ ਡਿਸਕ ਉੱਤੇ ਖੋਜ
> (`POST /api/plugins/scan`) ਰਾਹੀਂ ਹੁੰਦੀ ਹੈ।

## REST API

ਸਾਰੇ ਅੰਤਮ ਬਿੰਦੂਆਂ ਲਈ ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣਿਕਤਾ (`requireManagementAuth`) ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ** ਅਤੇ** ਲੂਪਬੈਕ-ਸਿਰਫ — `/api/plugins` ਅਤੇ `/api/plugins/` `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) ਵਿੱਚ ਸੂਚੀਬੱਧ ਹਨ।

| ਅੰਤ ਬਿੰਦੂ                          | ਵਿਧੀ   | ਵਰਣਨ                                                         |
| ---------------------------------- | ------ | ------------------------------------------------------------ |
| `/api/plugins`                     | GET    | ਇੰਸਟੌਲ ਕੀਤੇ ਪਲੱਗਇਨਾਂ ਦੀ ਸੂਚੀ ਬਣਾਓ (ਵਿਕਲਪਿਕ `?status=` ਫਿਲਟਰ) |
| `/api/plugins`                     | POST   | ਪਲੱਗਇਨ ਸਰੋਤ ਡਾਇਰੈਕਟਰੀ ਤੋਂ ਇੱਕ ਪਲੱਗਇਨ ਸਥਾਪਿਤ ਕਰੋ              |
| `/api/plugins/scan`                | POST   | ਪਲੱਗਇਨ ਡਾਇਰੈਕਟਰੀ ਨੂੰ ਸਕੈਨ ਕਰੋ ਅਤੇ ਨਵੇਂ ਪਲੱਗਇਨ ਰਜਿਸਟਰ ਕਰੋ     |
| `/api/plugins/marketplace`         | GET    | ਮਾਰਕੀਟਪਲੇਸ ਕੈਟਾਲਾਗ ਐਂਟਰੀਆਂ ਦੀ ਸੂਚੀ ਬਣਾਓ                      |
| `/api/plugins/marketplace/install` | POST   | ਨਾਮ ਦੁਆਰਾ ਇੱਕ ਮਾਰਕੀਟਪਲੇਸ ਪਲੱਗਇਨ ਸਥਾਪਿਤ ਕਰੋ                   |
| `/api/plugins/[name]`              | GET    | ਸਥਾਪਿਤ ਪਲੱਗਇਨ ਵੇਰਵੇ ਪ੍ਰਾਪਤ ਕਰੋ                               |
| `/api/plugins/[name]`              | DELETE | ਇੱਕ ਪਲੱਗਇਨ ਨੂੰ ਅਣਇੰਸਟੌਲ ਕਰੋ                                  |
| `/api/plugins/[name]/activate`     | POST   | ਕਿਰਿਆਸ਼ੀਲ ਕਰੋ ( + ਰਜਿਸਟਰ ਹੁੱਕ ਲੋਡ ਕਰੋ)                       |
| `/api/plugins/[name]/deactivate`   | POST   | ਅਕਿਰਿਆਸ਼ੀਲ ਕਰੋ (ਫਾਇਰ `onDeactivate`, ਅਨਰਜਿਸਟਰ ਹੁੱਕ)          |
| `/api/plugins/[name]/config`       | GET    | ਪਲੱਗਇਨ ਸੰਰਚਨਾ + ਸੰਰਚਨਾ ਸਕੀਮਾ ਪ੍ਰਾਪਤ ਕਰੋ                      |
| `/api/plugins/[name]/config`       | PUT    | ਪਲੱਗਇਨ ਸੰਰਚਨਾ ਨੂੰ ਅੱਪਡੇਟ ਕਰੋ (ਸਕੀਮਾ ਦੇ ਵਿਰੁੱਧ ਪ੍ਰਮਾਣਿਤ)      |

`GET /api/plugins` `status` ਫਿਲਟਰ `installed` / `active` / `inactive` / `error` ਵਿੱਚੋਂ ਇੱਕ ਨੂੰ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ। ਇੱਕ ਅਵੈਧ ਮੁੱਲ `400` ਵਾਪਸ ਕਰਦਾ ਹੈ।

### ਸਥਾਪਿਤ ਪਲੱਗਇਨਾਂ ਦੀ ਸੂਚੀ ਬਣਾਓ

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### ਸਥਾਨਕ ਮਾਰਗ ਤੋਂ ਸਥਾਪਿਤ ਕਰੋ

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` ਇੱਕ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ** ਪੂਰਨ** ਇੱਕ ਡਾਇਰੈਕਟਰੀ ਲਈ ਮਾਰਗ** ਪਲੱਗਇਨ ਸਰੋਤ ਡਾਇਰੈਕਟਰੀ ਦੇ ਅੰਦਰ** : ਪਲੱਗਇਨ ਰੂਟ ਦੇ ਅੱਗੇ `plugin-sources`, ਇਸਲਈ ਮੂਲ ਰੂਪ ਵਿੱਚ `~/.omniroute/plugin-sources/`, ਜਾਂ `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` ਜਦੋਂ ਉਹ ਵੇਰੀਏਬਲ ਸੈੱਟ ਹੁੰਦਾ ਹੈ (`getPluginSourcesDir()` ਵਿੱਚ `src/lib/plugins/installSource.ts`)। ਪਹਿਲਾਂ ਉੱਥੇ ਪਲੱਗਇਨ ਨੂੰ ਕਾਪੀ ਜਾਂ ਕਲੋਨ ਕਰੋ। ਇੰਸਟਾਲੇਸ਼ਨ ਨੂੰ `400` ਨਾਲ ਅਸਵੀਕਾਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਜਦੋਂ ਪਾਥ ਵਿੱਚ `..` ਜਾਂ ਇੱਕ ਨਲ ਬਾਈਟ ਹੁੰਦਾ ਹੈ, ਉਸ ਡਾਇਰੈਕਟਰੀ ਤੋਂ ਬਾਹਰ ਹੁੰਦਾ ਹੈ, ਇੱਕ ਸਿਮਲਿੰਕ ਦੁਆਰਾ ਇਸ ਦੇ ਬਾਹਰ ਹੱਲ ਹੁੰਦਾ ਹੈ, ਇੱਕ ਸਿਮਲਿੰਕ ਰੱਖਦਾ ਹੈ ਜਿਸਦਾ ਨਿਸ਼ਾਨਾ ਇਸਦੇ ਬਾਹਰ ਹੁੰਦਾ ਹੈ, ਜਾਂ ਜਦੋਂ ਡਾਇਰੈਕਟਰੀ ਮੌਜੂਦ ਨਹੀਂ ਹੁੰਦੀ ਹੈ। ਸਰੋਤ ਡਾਇਰੈਕਟਰੀ ਵਿੱਚ ਇੱਕ ਵੈਧ `plugin.json` ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ (ਜਾਂ ਇੱਕ ਦਾ ਮਾਤਾ-ਪਿਤਾ ਹੋਣਾ)। ਸਫਲਤਾ 'ਤੇ ਜਵਾਬ ਇੰਸਟਾਲ ਪਲੱਗਇਨ ਕਤਾਰ ਦੇ ਨਾਲ `201` ਹੈ।

ਦੂਜੇ ਪਲੱਗਇਨ ਰੂਟਾਂ ਦੇ ਉਲਟ, ਇਸ ਨੂੰ ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣ ਪੱਤਰ (ਇੱਕ ਡੈਸ਼ਬੋਰਡ ਸੈਸ਼ਨ ਜਾਂ ਪ੍ਰਬੰਧਨ-ਸਕੋਪਡ API ਕੁੰਜੀ) ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ ਭਾਵੇਂ ਲੌਗਇਨ ਅਸਮਰੱਥ ਹੋਵੇ (`requireLogin=false`): ਕੋਡ ਸਥਾਪਤ ਕਰਨਾ ਕਦੇ ਵੀ ਗੁਮਨਾਮ ਕਾਰਵਾਈ ਨਹੀਂ ਹੁੰਦਾ ਹੈ। ਇਹੀ ਗੱਲ `POST /api/plugins/marketplace/install` (body `{ "name": "<plugin>" }`) 'ਤੇ ਲਾਗੂ ਹੁੰਦੀ ਹੈ।

### ਮਾਰਕੀਟਪਲੇਸ ਬ੍ਰਾਊਜ਼ ਕਰੋ

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### ਪਲੱਗਇਨ ਸੰਰਚਨਾ ਅੱਪਡੇਟ ਕਰੋ

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` `src/lib/plugins/manifest.ts` ਤੋਂ `validatePluginConfig()` ਨਾਲ ਪਲੱਗਇਨ ਦੇ `configSchema` (ਮੈਨੀਫੈਸਟ ਵਿੱਚ ਘੋਸ਼ਿਤ) ਦੇ ਵਿਰੁੱਧ ਸਰੀਰ ਨੂੰ ਪ੍ਰਮਾਣਿਤ ਕਰਦਾ ਹੈ: ਹਰ ਕੁੰਜੀ ਨੂੰ ਸਕੀਮਾ ਵਿੱਚ ਘੋਸ਼ਿਤ ਕੀਤਾ ਜਾਣਾ ਚਾਹੀਦਾ ਹੈ, ਮੁੱਲ ਘੋਸ਼ਿਤ ਕਿਸਮ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ, `number` ਖੇਤਰ `min`/`max` ਦਾ ਸਨਮਾਨ ਕਰਦੇ ਹਨ, ਅਤੇ `select` ਖੇਤਰ ਘੋਸ਼ਿਤ `enum` ਨਾਲ ਮੇਲ ਖਾਂਦੇ ਹੋਣੇ ਚਾਹੀਦੇ ਹਨ। ਕੋਈ ਵੀ ਉਲੰਘਣਾ `400` ਵਾਪਸ ਕਰਦੀ ਹੈ ਅਤੇ ਕੁਝ ਵੀ ਸਟੋਰ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਇੱਕ ਪਲੱਗਇਨ ਜੋ ਕਿਸੇ ਵੀ `configSchema` ਘੋਸ਼ਣਾ ਨਹੀਂ ਕਰਦੀ ਹੈ, ਕੋਲ ਕੋਈ ਸੰਰਚਨਾਯੋਗ ਕੁੰਜੀਆਂ ਨਹੀਂ ਹਨ, ਇਸਲਈ ਬੇਨਤੀ ਨੂੰ `400` ("ਪਲੱਗਇਨ ਕਿਸੇ ਵੀ ਸੰਰਚਨਾਯੋਗ ਕੁੰਜੀਆਂ ਦਾ ਐਲਾਨ ਨਹੀਂ ਕਰਦਾ") ਨਾਲ ਇਨਕਾਰ ਕਰ ਦਿੱਤਾ ਗਿਆ ਹੈ।

## ਸੰਰਚਨਾ

### Plugin directory

Plugins OmniRoute data directory ਦੇ ਅਧੀਨ ਰਹਿੰਦੇ ਹਨ:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (ਜਾਂ ਉਹ ਜੋ manifest.main ਦਰਸਾਉਂਦਾ ਹੈ)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ਉਸ directory ਨੂੰ
ਤਿੰਨ ਪੜਾਵਾਂ ਵਿੱਚ resolve ਕਰਦਾ ਹੈ:

1. **`OMNIROUTE_PLUGINS_DIR`**, ਜਦੋਂ ਸੈੱਟ ਹੋਵੇ — `HOME` ਦਾ ਮੁੱਲ ਭਾਵੇਂ ਜੋ ਵੀ ਹੋਵੇ, ਇਸਨੂੰ ਜਿਵੇਂ ਦਾ ਤਿਵੇਂ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ। ਇਹ
   Docker/K8s ਲਈ ਸਪਸ਼ਟ ਨਿਯੰਤਰਣ ਹੈ, ਜਿੱਥੇ plugin tree ਨੂੰ ਅਜਿਹੇ path ਉੱਤੇ bind-mount ਕੀਤਾ ਜਾਂਦਾ ਹੈ
   ਜਿਸਦਾ ਆਮ ਤੌਰ ਉੱਤੇ container ਦੀ home directory ਨਾਲ ਕੋਈ ਸੰਬੰਧ ਨਹੀਂ ਹੁੰਦਾ (#11827)।
2. `<home>/.omniroute/plugins`, ਜਿੱਥੇ `<home>` `HOME` / `USERPROFILE`
   environment variables ਤੋਂ ਆਉਂਦਾ ਹੈ।
3. `/tmp/.omniroute/plugins`, ਜਦੋਂ process ਕੋਈ home ਬਿਲਕੁਲ ਵੀ export ਨਹੀਂ ਕਰਦਾ।

resolve ਕੀਤੀ directory ਨੂੰ startup ਵੇਲੇ ਇੱਕ ਵਾਰ `scanner.dir_resolved` ਵਜੋਂ log ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਜਿਸ ਵਿੱਚ
ਵਰਤੇ ਗਏ input (`OMNIROUTE_PLUGINS_DIR`, `home`, ਜਾਂ `no-home-fallback`) ਦਾ ਨਾਮ ਹੁੰਦਾ ਹੈ — ਇਸ ਤਰ੍ਹਾਂ ਕੋਈ image
ਜੋ ਬਿਨਾਂ ਦੱਸੇ ਪੜਾਅ 3 ਉੱਤੇ ਪਹੁੰਚਦੀ ਹੈ, ਸਿਰਫ਼ ਖਾਲੀ plugin ਸੂਚੀ report ਕਰਨ ਦੀ ਬਜਾਏ ਇਸ ਬਾਰੇ ਦੱਸਦੀ ਹੈ।
`POST /api/plugins/scan` ਉੱਥੇ ਮੌਜੂਦ ਕਿਸੇ ਵੀ ਅਜਿਹੀ subdirectory ਨੂੰ ਲੱਭ ਕੇ ਰਜਿਸਟਰ ਕਰਦਾ ਹੈ ਜਿਸ ਵਿੱਚ ਇੱਕ ਵੈਧ
`plugin.json` ਹੋਵੇ; ਇਹੋ directory ਉਹ root ਵੀ ਹੈ ਜਿਸ ਵਿੱਚ
`pluginManager.install()` plugins ਨੂੰ copy ਕਰਦਾ ਹੈ, ਇਸ ਲਈ override discovery ਅਤੇ
installation ਦੋਵਾਂ ਨੂੰ ਇਕੱਠੇ ਤਬਦੀਲ ਕਰਦਾ ਹੈ।

> **`OMNIROUTE_PLUGINS_DIR`, `OMNIROUTE_PLUGIN_PATH` ਨਹੀਂ ਹੈ।** ਦੂਜੇ ਵਾਲੇ ਨੂੰ ਕੇਵਲ
> CLI command-plugin loader (`bin/cli/plugins.mjs`) ਵੱਲੋਂ `omniroute-cmd-*` npm
> packages ਲੱਭਣ ਲਈ ਪੜ੍ਹਿਆ ਜਾਂਦਾ ਹੈ, ਜੋ `omniroute` subcommands ਜੋੜਦੇ ਹਨ — ਇੱਥੇ ਵਰਣਿਤ runtime scanner ਉੱਤੇ
> ਇਸਦਾ ਕੋਈ ਪ੍ਰਭਾਵ ਨਹੀਂ ਹੈ। ਉਸ ਪੱਖ ਲਈ [PLUGINS.md](./PLUGINS.md) ਵੇਖੋ।

### ਕਸਟਮ marketplace registry URL

marketplace catalog ਦਾ source `pluginMarketplaceUrl` setting ਤੋਂ ਪੜ੍ਹਿਆ ਜਾਂਦਾ ਹੈ
(`src/lib/plugins/marketplace.ts`, `settings.pluginMarketplaceUrl` ਨੂੰ ਪੜ੍ਹਦਾ ਹੈ)। ਜਦੋਂ
ਇਸਨੂੰ ਇੱਕ `http(s)` URL ਉੱਤੇ ਸੈੱਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਤਾਂ `listMarketplacePlugins()` ਉਸ URL ਨੂੰ fetch ਕਰਦਾ ਹੈ ਅਤੇ
ਜਾਂ ਤਾਂ entries ਦੀ top-level JSON array ਜਾਂ `plugins` array ਵਾਲਾ object ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ;
string `name` ਤੋਂ ਬਿਨਾਂ entries ਨੂੰ filter ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ। ਜਦੋਂ ਇਹ ਸੈੱਟ ਨਾ ਹੋਵੇ (ਜਾਂ ਜਦੋਂ fetch
SSRF guard ਵਿੱਚ ਅਸਫਲ ਹੋ ਜਾਵੇ / ਖਰਾਬ response ਵਾਪਸ ਕਰੇ), ਤਾਂ built-in seed registry
ਵਰਤੀ ਜਾਂਦੀ ਹੈ।

dashboard ਦੀ "Marketplace" tab ਇਸ URL ਲਈ ਇੱਕ field ਦਿਖਾਉਂਦੀ ਹੈ (ਇਸਨੂੰ
`GET /api/settings` ਤੋਂ ਵਾਪਸ ਪੜ੍ਹਿਆ ਜਾਂਦਾ ਹੈ)।

> ਲਾਗੂਕਰਨ ਨੋਟ: dashboard ਦੀ "ਸੰਭਾਲੋ" ਕਾਰਵਾਈ
> `pluginMarketplaceUrl` ਨੂੰ `PATCH /api/settings` ਵੱਲ ਭੇਜਦੀ ਹੈ। ਇਹ ਲਿਖੇ ਜਾਣ ਵੇਲੇ ਇਹ
> key `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) ਵਿੱਚ ਘੋਸ਼ਿਤ ਨਹੀਂ ਹੈ, ਇਸ ਲਈ ਇਸ ਉੱਤੇ ਨਿਰਭਰ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਆਪਣੀ
> release ਵਿੱਚ persistence ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ — **read** path (`getSettings()` →
> `listMarketplacePlugins()`) settings store ਵਿੱਚ key ਮੌਜੂਦ ਹੋਣ ਤੋਂ ਬਾਅਦ ਇਸਦੀ ਪਾਲਣਾ ਕਰਦਾ ਹੈ।

## ਸੁਰੱਖਿਆ

### ਸਿਰਫ਼ ਰੂਟ ਟੀਅਰ — ਲੂਪਬੈਕ

ਪਲੱਗਇਨ ਪੈਦਾ ਕੀਤੇ ਚਾਈਲਡ ਪ੍ਰਕਿਰਿਆਵਾਂ ਵਿੱਚ ਕੋਡ ਨੂੰ ਚਲਾਉਂਦੇ ਹਨ, ਇਸਲਈ ਪੂਰੀ `/api/plugins` ਸਤਹ ਨੂੰ `LOCAL_ONLY` (ਟੀਅਰ 1) ਵਰਗੀਕ੍ਰਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਲੂਪਬੈਕ ਲਾਗੂਕਰਨ ਬਿਨਾਂ ਸ਼ਰਤ ਚੱਲਦਾ ਹੈ** ਅੱਗੇ** ਕੋਈ ਵੀ ਪ੍ਰਮਾਣਿਕਤਾ ਜਾਂਚ, ਇਸਲਈ ਇੱਕ ਲੀਕ ਹੋਇਆ ਪ੍ਰਬੰਧਨ ਟੋਕਨ ਇੱਕ ਸੁਰੰਗ ਦੇ ਉੱਪਰ ਬਾਕਸ ਤੱਕ ਪਹੁੰਚਦਾ ਹੈ, ਫਿਰ ਵੀ ਇੱਕ ਪਲੱਗਇਨ ਨੂੰ ਸਥਾਪਿਤ, ਕਿਰਿਆਸ਼ੀਲ ਜਾਂ ਅਣਇੰਸਟੌਲ ਨਹੀਂ ਕਰ ਸਕਦਾ ਹੈ। [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) ਅਤੇ ਸਖ਼ਤ ਨਿਯਮ #15 / #17 ਦੇਖੋ।

### ਮਾਰਕੀਟਪਲੇਸ ਰਜਿਸਟਰੀ SSRF ਗਾਰਡ

ਇੱਕ ਕਸਟਮ ਰਜਿਸਟਰੀ URL ਹਮਲਾਵਰ-ਪ੍ਰਭਾਵੀ ਸੰਰਚਨਾ ਹੈ, ਇਸਲਈ ਇਸਨੂੰ ਪ੍ਰਾਪਤ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ `listMarketplacePlugins()` ਇਸਨੂੰ ਦੋ ਲੇਅਰਾਂ ਰਾਹੀਂ ਚਲਾਉਂਦਾ ਹੈ:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - ਕਿਸੇ ਵੀ ਚੀਜ਼ ਨੂੰ ਰੱਦ ਕਰਦਾ ਹੈ ਜੋ `http:` / `https:` ਨਹੀਂ ਹੈ।
   - ਸ਼ਾਬਦਿਕ private/loopback/link-local/ULA ਮੇਜ਼ਬਾਨਾਂ ਨੂੰ ਰੱਦ ਕਰਦਾ ਹੈ (IPv4** ਅਤੇ** IPv6, IPv4-mapped ਸਮੇਤ ) ਕੈਨੋਨੀਕਲ `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) ਰਾਹੀਂ।
   - ਹੱਲ ਕਰਦਾ ਹੈ** ਦੋਵੇਂ** `A` ਅਤੇ `AAAA` ਰਿਕਾਰਡ ਕਰਦਾ ਹੈ ਅਤੇ ਜੇਕਰ ਰੱਦ ਕਰਦਾ ਹੈ** ਕੋਈ ਵੀ** ਹੱਲ ਕੀਤਾ ਪਤਾ ਪ੍ਰਾਈਵੇਟ — ਹੈ ਜਨਤਕ-ਹੋਸਟਨਾਮ → ਪ੍ਰਾਈਵੇਟ-ਆਈਪੀ ਬਾਈਪਾਸ ਨੂੰ ਬੰਦ ਕਰ ਰਿਹਾ ਹੈ।
   - **ਫੇਲ ਬੰਦ** : ਇੱਕ DNS ਰੈਜ਼ੋਲੂਸ਼ਨ ਅਸਫਲਤਾ URL ਨੂੰ ਰੱਦ ਕਰਦੀ ਹੈ।
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): ਪ੍ਰਾਪਤ ਕਰਨ ਦੇ ਸਮੇਂ ਅਤੇ ਸਿਰਫ਼ ਜਨਤਕ ਤੌਰ 'ਤੇ URL ਗਾਰਡ ਨੂੰ ਮੁੜ-ਲਾਗੂ ਕਰਦਾ ਹੈ** ਬਲਾਕ ਰੀਡਾਇਰੈਕਟਸ** (ਕੋਈ ਜਨਤਕ → ਪ੍ਰਾਈਵੇਟ `30x` ਧਰੁਵ ਨਹੀਂ)।

ਇੱਕ URL ਜੋ ਕਿਸੇ ਵੀ ਪਰਤ ਵਿੱਚ ਅਸਫਲ ਹੁੰਦਾ ਹੈ, ਬੇਨਤੀ ਨੂੰ ਰੱਦ ਨਹੀਂ ਕਰਦਾ — ਮਾਰਕੀਟਪਲੇਸ ਚੁੱਪਚਾਪ ਬਿਲਟ-ਇਨ ਸੀਡ ਰਜਿਸਟਰੀ ਵਿੱਚ ਵਾਪਸ ਆ ਜਾਂਦਾ ਹੈ ਅਤੇ ਇੱਕ ਚੇਤਾਵਨੀ ਲੌਗ ਕਰਦਾ ਹੈ।

> ਇਸ ਗਾਰਡ ਨੂੰ PR #3774 ਵਿੱਚ ਖਾਸ ਤੌਰ 'ਤੇ A + AAAA ਹੱਲ ਕਰਨ ਅਤੇ IPv4-only ਜਾਂਚ ਦੀ ਬਜਾਏ ਕੈਨੋਨੀਕਲ `isPrivateHost` ਵਰਤੋਂ ਕਰਨ ਲਈ ਸਖ਼ਤ ਕੀਤਾ ਗਿਆ ਸੀ।

### ਪਲੱਗਇਨ ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਆਈਸੋਲੇਸ਼ਨ

> **ਪਲੱਗਇਨ ਡਿਫੌਲਟ ਰੂਪ ਵਿੱਚ ਸੈਂਡਬਾਕਸਡ ਨਹੀਂ ਹੁੰਦੇ ਹਨ।** ਬੱਚਾ ਇੱਕ ਆਮ Node.js ਪ੍ਰਕਿਰਿਆ ਹੈ ਜੋ OmniRoute ਉਪਭੋਗਤਾ ਦੇ ਤੌਰ 'ਤੇ ਚੱਲ ਰਹੀ ਹੈ, ਜਿਸ ਵਿੱਚ ਕੋਈ VM ਸੰਦਰਭ ਅਤੇ ਕੋਈ Node.js ਅਨੁਮਤੀ ਫਲੈਗ ਨਹੀਂ ਹੈ, ਇਸਲਈ ਪਲੱਗਇਨ ਕੋਡ ਕਿਸੇ ਵੀ ਫਾਈਲ ਨੂੰ ਪੜ੍ਹ ਅਤੇ ਲਿਖ ਸਕਦਾ ਹੈ ਜੋ ਉਪਭੋਗਤਾ, ਪ੍ਰੋਗਰਾਮ ਚਲਾ ਸਕਦਾ ਹੈ ਅਤੇ ਨੈੱਟਵਰਕ ਤੱਕ ਪਹੁੰਚ ਸਕਦਾ ਹੈ। `requires.permissions` ਸਿਰਫ ਇਹ ਫੈਸਲਾ ਕਰਦਾ ਹੈ ਕਿ ਬੱਚੇ ਨੂੰ ਕਿਹੜੇ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ ਪ੍ਰਾਪਤ ਹੁੰਦੇ ਹਨ; ਹੋਰ ਅਨੁਮਤੀਆਂ ਲਾਗੂ ਨਹੀਂ ਹਨ। ਓਪਟ-ਇਨ `PLUGIN_PERMISSION_MODEL_ENABLED` ਵਿਸ਼ੇਸ਼ਤਾ ਫਲੈਗ (ਮੂਲ ਰੂਪ ਵਿੱਚ ਬੰਦ) ਉਹਨਾਂ ਅਨੁਮਤੀਆਂ ਤੋਂ ਬਣੇ Node.js ਅਨੁਮਤੀ ਮਾਡਲ ਦੇ ਅਧੀਨ ਹਰੇਕ ਪਲੱਗਇਨ ਨੂੰ ਚਲਾਉਂਦਾ ਹੈ, `network` ਨੂੰ ਛੱਡ ਕੇ, ਜਿਸਨੂੰ Node.js ਪ੍ਰਤਿਬੰਧਿਤ ਨਹੀਂ ਕਰ ਸਕਦਾ (ਵੇਖੋ [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#%E0%A8%87%E0%A8%9C%E0%A8%BE%E0%A8%9C%E0%A8%BC%E0%A8%A4-%E0%A8%B8%E0%A8%BF%E0%A8%B8%E0%A8%9F%E0%A8%AE) )। ਸਿਰਫ਼ ਉਹ ਪਲੱਗਇਨ ਸਥਾਪਤ ਕਰੋ ਜਿਨ੍ਹਾਂ 'ਤੇ ਤੁਸੀਂ ਭਰੋਸਾ ਕਰਦੇ ਹੋ। ਹੇਠਾਂ ਦਿੱਤੀ ਪ੍ਰਕਿਰਿਆ ਸੀਮਾ ਵਿੱਚ ਕਰੈਸ਼ ਅਤੇ ਹੈਂਗ ਸ਼ਾਮਲ ਹਨ; ਇਹ ਕੋਈ ਸੁਰੱਖਿਆ ਸੀਮਾ ਨਹੀਂ ਹੈ।

- **ਪ੍ਰਕਿਰਿਆ ਇਕੱਲਤਾ** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ਹਰੇਕ ਪਲੱਗਇਨ ਨੂੰ ਇੱਕ ਵੱਖਰੀ Node.js ਚਾਈਲਡ ਪ੍ਰਕਿਰਿਆ ਵਿੱਚ ਪੈਦਾ ਕਰਦਾ ਹੈ ਅਤੇ IPC ਉੱਤੇ ਸੰਚਾਰ ਕਰਦਾ ਹੈ। `SIGTERM` → `SIGKILL` ਐਸਕੇਲੇਸ਼ਨ ਦੇ ਨਾਲ ਹੁੱਕ ਕਾਲਾਂ ਦਾ ਸਮਾਂ ਸਮਾਪਤ ਹੁੰਦਾ ਹੈ।
- **Env ਅਨੁਮਤੀ ਸੂਚੀ** — ਬੱਚੇ ਨੂੰ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲਾਂ ਦਾ ਸਿਰਫ਼ ਇੱਕ ਮਨਜ਼ੂਰਸ਼ੁਦਾ ਸੈੱਟ ਪ੍ਰਾਪਤ ਹੁੰਦਾ ਹੈ; ਵਿਆਪਕ ਸੈੱਟ ਸਿਰਫ਼ ਉਦੋਂ ਹੀ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ ਜਦੋਂ ਮੈਨੀਫੈਸਟ `env` ਅਨੁਮਤੀ ਦੀ ਬੇਨਤੀ ਕਰਦਾ ਹੈ।
- **ਸਰੋਤ ਕੰਟੇਨਮੈਂਟ ਸਥਾਪਤ ਕਰੋ** — `POST /api/plugins` ਸਿਰਫ ਪਲੱਗਇਨ ਸਰੋਤਾਂ ਦੀ ਡਾਇਰੈਕਟਰੀ ਤੋਂ ਪੜ੍ਹਦਾ ਹੈ (ਦੇਖੋ "ਇੱਕ ਸਥਾਨਕ ਮਾਰਗ ਤੋਂ ਸਥਾਪਿਤ ਕਰੋ"): ਮਾਰਗ ਨੂੰ `realpath` ਨਾਲ ਕੈਨੋਨੀਕਲਾਈਜ਼ ਕੀਤਾ ਗਿਆ ਹੈ, ਉਸ ਡਾਇਰੈਕਟਰੀ ਦੇ ਅੰਦਰ ਸਖਤੀ ਨਾਲ ਰਹਿਣਾ ਚਾਹੀਦਾ ਹੈ, ਅਤੇ ਇੱਕ ਸਰੋਤ ਟ੍ਰੀ ਜੋ ਕਿ ਇੱਕ ਸਿਮਲਿੰਕ ਨੂੰ ਲੈ ਕੇ ਬਚਦਾ ਹੈ, ਕਿਸੇ ਵੀ ਚੀਜ਼ ਦੀ ਨਕਲ ਕੀਤੇ ਜਾਣ ਤੋਂ ਪਹਿਲਾਂ ਇਨਕਾਰ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।
- **ਮਾਰਗ ਦੀ ਰੋਕਥਾਮ** — install/upgrade/uninstall ਦਾਅਵਾ ਕਰਦਾ ਹੈ ਕਿ ਪਲੱਗਇਨ ਡਾਇਰੈਕਟਰੀ ਅਤੇ `manifest.main` ਹੱਲ ਕਰਦੇ ਹਨ** ਅੰਦਰ** ਕਿਸੇ ਵੀ ਕਾਪੀ ਜਾਂ ਰਿਕਰਸਿਵ ਡਿਲੀਟ ਤੋਂ ਪਹਿਲਾਂ ਪ੍ਰਬੰਧਿਤ ਪਲੱਗਇਨ ਰੂਟ (ਛੇੜਛਾੜ ਵਾਲੇ DB ਮਾਰਗਾਂ ਅਤੇ `manifest.main` ਵਿੱਚ `../` ਟ੍ਰੈਵਰਸਲ ਤੋਂ ਸੁਰੱਖਿਆ)। ਐਕਟੀਵੇਸ਼ਨ `realpath` ਦੁਆਰਾ ਸਿਮਲਿੰਕਸ ਨੂੰ ਹੱਲ ਕਰਦਾ ਹੈ ਅਤੇ ਇੱਕ ਐਂਟਰੀ ਪੁਆਇੰਟ ਲੋਡ ਕਰਨ ਤੋਂ ਇਨਕਾਰ ਕਰਦਾ ਹੈ ਜੋ ਪਲੱਗਇਨ ਡਾਇਰੈਕਟਰੀ ਤੋਂ ਬਚਦਾ ਹੈ।
- **ਵਿਕਲਪਿਕ ਇਕਸਾਰਤਾ ਪਿੰਨ** — ਇੱਕ ਮੈਨੀਫੈਸਟ ਇੱਕ `integrity` (`sha256-<base64>`, SRI ਫਾਰਮੈਟ) ਖੇਤਰ ਦਾ ਐਲਾਨ ਕਰ ਸਕਦਾ ਹੈ। ਮੌਜੂਦ ਹੋਣ 'ਤੇ, ਲੋਡਰ ਲੋਡ ਸਮੇਂ 'ਤੇ ਐਂਟਰੀ ਫਾਈਲ ਹੈਸ਼ ਦੀ ਪੁਸ਼ਟੀ ਕਰਦਾ ਹੈ ਅਤੇ ਬੇਮੇਲ ਹੋਣ 'ਤੇ ਕਿਰਿਆਸ਼ੀਲ ਕਰਨ ਤੋਂ ਇਨਕਾਰ ਕਰਦਾ ਹੈ। ਇਹ ਛੇੜਛਾੜ-ਖੋਜ ਦੀ ਚੋਣ ਹੈ,** ਨਹੀਂ** ਇੱਕ ਸੁਰੱਖਿਆ ਸੀਮਾ: ਇਹ ਸੀਮਤ ਨਹੀਂ ਕਰਦਾ ਕਿ ਇੱਕ ਲੋਡ ਕੀਤਾ ਪਲੱਗਇਨ ਕੀ ਕਰ ਸਕਦਾ ਹੈ।
- **ਹੁੱਕਾਂ ਵਿੱਚ ਕੋਈ ਕਲਾਇੰਟ ਪ੍ਰਮਾਣ ਪੱਤਰ ਨਹੀਂ ਹਨ** — `onRequest`, `onResponse` ਅਤੇ `onError` ਨੂੰ ਭੇਜੇ ਗਏ ਸੰਦਰਭ ਵਿੱਚ `authorization`, `x-api-key`, `proxy-authorization` ਅਤੇ `cookie` ਸਿਰਲੇਖਾਂ ਨੂੰ ਹਟਾ ਦਿੱਤਾ ਗਿਆ ਹੈ, ਅਤੇ API ਕੁੰਜੀ ਰਿਕਾਰਡ ਵਿੱਚ ਕੋਈ ਮੁੱਖ ਮੁੱਲ ਨਹੀਂ ਹੈ ( `src/lib/plugins/hooks.ts` ਵਿੱਚ `redactPluginContext()` )।

## ਮੈਨੀਫੈਸਟ (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) ਦੁਆਰਾ ਪ੍ਰਮਾਣਿਤ:

| ਖੇਤਰ               | ਟਾਈਪ ਕਰੋ | ਨੋਟਸ                                                                 |
| ------------------ | -------- | -------------------------------------------------------------------- |
| `name`             | ਸਤਰ      | ਲੋੜੀਂਦਾ; ਕਬਾਬ-ਕੇਸ (`^[a-z0-9-]+$`), 1–100 ਅੱਖਰ                       |
| `version`          | ਸਤਰ      | ਲੋੜੀਂਦਾ; ਸੇਮਵਰ (`MAJOR.MINOR.PATCH`)                                 |
| `description`      | ਸਤਰ?     | ≤ 500 ਅੱਖਰ                                                           |
| `author`           | ਸਤਰ?     | ≤ 200 ਅੱਖਰ                                                           |
| `license`          | ਸਤਰ?     | `MIT` ਲਈ ਡਿਫਾਲਟ                                                      |
| `main`             | ਸਤਰ?     | ਐਂਟਰੀ ਫਾਈਲ; `index.js` ਲਈ ਡਿਫਾਲਟ                                     |
| `source`           | enum?    | `local` \| `marketplace` ( `local` ਲਈ ਮੂਲ)                           |
| `tags`             | ਸਤਰ[]?   | ਖੋਜ ਟੈਗ                                                              |
| `requires`         | ਵਸਤੂ?    | `{ omniroute?, permissions[] }`                                      |
| `hooks`            | ਵਸਤੂ?    | ਬੂਲੀਅਨ ਘੋਸ਼ਣਾ ਕਰਦੇ ਹੋਏ ਕਿ ਪਲੱਗਇਨ ਨੂੰ ਕਿਸ ਹੁੱਕ ਨੂੰ ਲਾਗੂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ |
| `skills`           | ਵਸਤੂ[]?  | ਵਿਕਲਪਿਕ ਹੁਨਰ ਪਰਿਭਾਸ਼ਾਵਾਂ                                             |
| `enabledByDefault` | ਬੂਲੀਅਨ?  | ਇੰਸਟਾਲ ਕਰਨ 'ਤੇ ਆਟੋ-ਐਕਟੀਵੇਟ ਕਰੋ                                       |
| `configSchema`     | ਵਸਤੂ?    | ਸੰਰਚਨਾ ਖੇਤਰਾਂ ਦਾ ਨਕਸ਼ਾ (`string`/`number`/`boolean`/`select`)        |
| `integrity`        | ਸਤਰ?     | ਵਿਕਲਪਿਕ `sha256-<base64>` ਐਂਟਰੀ-ਫਾਈਲ ਪਿੰਨ                            |

ਇਜਾਜ਼ਤਾਂ enum `network` / `file-read` / `file-write` / `env` / `exec` ਤੋਂ ਲਈਆਂ ਗਈਆਂ ਹਨ। ਸਿਰਫ਼ `env` ਰਨਟਾਈਮ ਪ੍ਰਭਾਵ ਹੁੰਦਾ ਹੈ (ਬੱਚੇ ਲਈ ਥੋੜ੍ਹਾ ਜਿਹਾ ਵੱਡਾ ਵਾਤਾਵਰਣ-ਵੇਰੀਏਬਲ ਅਨੁਮਤੀ ਸੂਚੀ); ਬਾਕੀ ਘੋਸ਼ਣਾਵਾਂ ਹਨ ਅਤੇ ਲਾਗੂ ਨਹੀਂ ਕੀਤੀਆਂ ਗਈਆਂ ਹਨ।

## ਜੀਵਨ-ਚੱਕਰ ਪ੍ਰਵਾਹ

```
ਇੰਸਟਾਲ (POST /api/plugins, ਪਾਥ)
  → ਮੈਨਿਫੈਸਟ ਸਕੈਨ/ਪ੍ਰਮਾਣਿਤ ਕਰੋ → ਸਟੇਜਿੰਗ ਵਿੱਚ ਕਾਪੀ ਕਰੋ → ਯਕੀਨੀ ਬਣਾਓ ਕਿ main ਡਾਇਰੈਕਟਰੀ ਦੇ ਅੰਦਰ ਹੈ
  → ~/.omniroute/plugins/<name> ਵਿੱਚ ਐਟਾਮਿਕ ਰੀਨੇਮ ਕਰੋ → DB ਕਤਾਰ ਸ਼ਾਮਲ ਕਰੋ
  → onInstall ਚਲਾਓ → ਜੇ enabledByDefault ਹੈ: ਐਕਟੀਵੇਟ ਕਰੋ

ਐਕਟੀਵੇਟ (POST /api/plugins/{name}/activate)
  → realpath ਕੰਟੇਨਮੈਂਟ ਜਾਂਚ → loadPlugin() (ਚਾਇਲਡ ਪ੍ਰੋਸੈੱਸ ਸ਼ੁਰੂ ਕਰੋ)
  → ਘੋਸ਼ਿਤ ਹੁੱਕ ਰਜਿਸਟਰ ਕਰੋ → status = "active" → onActivate ਚਲਾਓ

ਡੀਐਕਟੀਵੇਟ (POST /api/plugins/{name}/deactivate)
  → onDeactivate ਚਲਾਓ (ਅਨਰਜਿਸਟਰ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ) → ਹੁੱਕ ਅਨਰਜਿਸਟਰ ਕਰੋ
  → ਚਾਇਲਡ ਪ੍ਰੋਸੈੱਸ ਸਮਾਪਤ ਕਰੋ → status = "inactive"

ਅਨਇੰਸਟਾਲ (DELETE /api/plugins/{name})
  → ਜੇ ਐਕਟਿਵ ਹੈ ਤਾਂ ਡੀਐਕਟੀਵੇਟ ਕਰੋ → onUninstall ਚਲਾਓ
  → ਕੰਟੇਨਮੈਂਟ-ਜਾਂਚ ਨਾਲ ਪਲੱਗਇਨ ਡਾਇਰੈਕਟਰੀ ਨੂੰ ਰਿਕਰਸਿਵ ਤੌਰ 'ਤੇ ਮਿਟਾਓ → DB ਕਤਾਰ ਮਿਟਾਓ
```

ਉਸ ਡਾਇਰੈਕਟਰੀ ਉੱਤੇ `install` ਨੂੰ ਮੁੜ ਚਲਾਉਣਾ, ਜਿਸ ਦਾ ਮੈਨਿਫੈਸਟ ਵਰਜਨ ਇੰਸਟਾਲ ਕੀਤੇ ਵਰਜਨ ਨਾਲੋਂ **ਸਖ਼ਤੀ ਨਾਲ
ਨਵਾਂ** ਹੈ, ਆਪਣੇ ਆਪ ਅੱਪਗ੍ਰੇਡ ਕਰਦਾ ਹੈ (ਸਾਫ਼ ਮੁੜ-ਇੰਸਟਾਲੇਸ਼ਨ; ਸੰਰਚਨਾ ਡਿਫਾਲਟ ਮੁੱਲਾਂ 'ਤੇ ਰੀਸੈੱਟ
ਹੁੰਦੀ ਹੈ)। ਸਮਾਨ ਜਾਂ ਪੁਰਾਣਾ ਵਰਜਨ ਅਸਵੀਕਾਰ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।

## ਡੈਸ਼ਬੋਰਡ

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) 'ਤੇ ਡੈਸ਼ਬੋਰਡ ਪੇਜ ਦੋ ਟੈਬਾਂ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ:

- **ਸਥਾਪਿਤ ਕੀਤਾ** — ਉਹਨਾਂ ਦੇ ਘੋਸ਼ਿਤ ਹੁੱਕਾਂ, ਇੱਕ activate/deactivate ਟੌਗਲ, ਇੱਕ ਅਣਇੰਸਟੌਲ ਬਟਨ, ਅਤੇ ਇੱਕ "ਪਲੱਗਇਨ ਲਈ ਸਕੈਨ" ਐਕਸ਼ਨ (`POST /api/plugins/scan`) ਨਾਲ ਸਥਾਪਿਤ ਪਲੱਗਇਨਾਂ ਨੂੰ ਸੂਚੀਬੱਧ ਕਰਦਾ ਹੈ।
- **ਬਾਜ਼ਾਰ** — ਕਸਟਮ ਰਜਿਸਟਰੀ URL ਨੂੰ ਸੈੱਟ ਕਰਨ ਲਈ ਇੱਕ ਖੇਤਰ ਦੇ ਨਾਲ `GET /api/plugins/marketplace` ਤੋਂ ਕੈਟਾਲਾਗ ਦਿਖਾਉਂਦਾ ਹੈ।

ਪੰਨਾ ਹਮੇਸ਼ਾ ਇੱਕ ਚੇਤਾਵਨੀ ਦਿਖਾਉਂਦਾ ਹੈ ਕਿ ਪਲੱਗਇਨ OmniRoute ਪ੍ਰਕਿਰਿਆ ਦੇ ਪੂਰੇ ਅਧਿਕਾਰਾਂ ਨਾਲ ਚੱਲਦੇ ਹਨ।

ਪ੍ਰਤੀ-ਪਲੱਗਇਨ ਸੰਰਚਨਾ ਪੰਨਾ `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) 'ਤੇ ਰਹਿੰਦਾ ਹੈ।
