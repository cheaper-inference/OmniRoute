ਵੈੱਬ ਕੂਕੀ ਪ੍ਰਦਾਤਾ OmniRoute ਨੂੰ API ਕੁੰਜੀ ਦੀ ਬਜਾਏ ਤੁਹਾਡੇ ਮੌਜੂਦਾ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਰਾਹੀਂ AI ਸੇਵਾ ਵਰਤਣ ਦਿੰਦੇ ਹਨ। ਇਹ ਉਦੋਂ ਲਾਭਦਾਇਕ ਹੁੰਦੇ ਹਨ ਜਦੋਂ ਤੁਹਾਡੇ ਕੋਲ ਪਹਿਲਾਂ ਹੀ ਕਿਸੇ ਸੇਵਾ ਦੀ ਵੈੱਬਸਾਈਟ ਰਾਹੀਂ ਪਹੁੰਚ ਹੋਵੇ ਅਤੇ ਤੁਸੀਂ ਚਾਹੁੰਦੇ ਹੋ ਕਿ OmniRoute ਉਸੇ ਪ੍ਰਮਾਣਿਤ ਸੈਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰੇ।

API-ਕੁੰਜੀ ਪ੍ਰਦਾਤਾਵਾਂ ਤੋਂ ਵੱਖਰੇ ਤੌਰ 'ਤੇ, ਵੈੱਬ ਕੂਕੀ ਪ੍ਰਦਾਤਾ ਉਹਨਾਂ ਪ੍ਰਮਾਣ-ਪੱਤਰਾਂ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਪ੍ਰਮਾਣਿਤ ਕਰਦੇ ਹਨ ਜੋ ਤੁਹਾਡਾ ਬ੍ਰਾਊਜ਼ਰ ਵੈੱਬਸਾਈਟ ਨੂੰ ਭੇਜਦਾ ਹੈ।

# ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ

> **ਮਹੱਤਵਪੂਰਨ:** ਪ੍ਰਮਾਣ-ਪੱਤਰ ਹਮੇਸ਼ਾ ਕਿਸੇ **ਲਾਈਵ ਨੈੱਟਵਰਕ ਬੇਨਤੀ** ਤੋਂ ਕਾਪੀ ਕਰੋ, ਆਪਣੇ ਬ੍ਰਾਊਜ਼ਰ ਦੇ ਕੂਕੀ ਸਟੋਰੇਜ ਤੋਂ **ਨਹੀਂ**।

ਪ੍ਰਮਾਣੀਕਰਨ ਦੀਆਂ ਬਹੁਤ ਸਾਰੀਆਂ ਸਮੱਸਿਆਵਾਂ ਗਲਤ ਥਾਂ ਤੋਂ ਕੂਕੀਆਂ ਕਾਪੀ ਕਰਨ ਕਾਰਨ ਹੁੰਦੀਆਂ ਹਨ।

## ਕੂਕੀ ਸਟੋਰੇਜ ਤੋਂ ਕਾਪੀ ਨਾ ਕਰੋ

ਜ਼ਿਆਦਾਤਰ ਬ੍ਰਾਊਜ਼ਰ ਸਟੋਰ ਕੀਤੀਆਂ ਕੂਕੀਆਂ ਨੂੰ ਇਸ ਰਾਹੀਂ ਦਿਖਾਉਂਦੇ ਹਨ:

```
ਡਿਵੈਲਪਰ ਟੂਲ
→ ਐਪਲੀਕੇਸ਼ਨ (ਜਾਂ ਸਟੋਰੇਜ)
→ ਕੂਕੀਆਂ
```

ਭਾਵੇਂ ਇਹ ਕੂਕੀਆਂ ਸਹੀ ਦਿਖਾਈ ਦੇਣ, ਪਰ ਇਹ ਹੋ ਸਕਦੀਆਂ ਹਨ:

- ਪੁਰਾਣੀਆਂ
- ਅਧੂਰੀਆਂ
- ਉਹਨਾਂ ਕੂਕੀਆਂ ਤੋਂ ਰਹਿਤ ਜੋ ਸਿਰਫ਼ ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀਆਂ ਨਾਲ ਭੇਜੀਆਂ ਜਾਂਦੀਆਂ ਹਨ

ਇਹਨਾਂ ਮੁੱਲਾਂ ਦੀ ਵਰਤੋਂ ਕਰਨ ਨਾਲ ਪ੍ਰਮਾਣੀਕਰਨ ਅਸਫਲ ਹੋ ਸਕਦਾ ਹੈ, ਭਾਵੇਂ ਇਹ ਵੈਧ ਦਿਖਾਈ ਦੇਣ।

## ਲਾਈਵ ਬੇਨਤੀ ਤੋਂ ਕਾਪੀ ਕਰੋ

ਇਸ ਦੀ ਬਜਾਏ, ਕਿਸੇ ਸਫਲ ਬੇਨਤੀ ਦੀਆਂ ਕੂਕੀਆਂ ਵਰਤੋ:

```
ਡਿਵੈਲਪਰ ਟੂਲ
→ ਨੈੱਟਵਰਕ
→ ਪੰਨੇ ਨੂੰ ਰਿਫ੍ਰੈਸ਼ ਕਰੋ
→ ਕੋਈ ਚੈਟ ਜਾਂ ਗੱਲਬਾਤ ਬੇਨਤੀ ਖੋਲ੍ਹੋ
→ ਬੇਨਤੀ ਹੈਡਰ
→ ਕੂਕੀ
```

`Cookie` ਬੇਨਤੀ ਹੈਡਰ ਵਿੱਚ ਉਹੀ ਸਟੀਕ ਪ੍ਰਮਾਣੀਕਰਨ ਜਾਣਕਾਰੀ ਹੁੰਦੀ ਹੈ ਜਿਸਦੀ ਵਰਤੋਂ ਤੁਹਾਡੇ ਬ੍ਰਾਊਜ਼ਰ ਨੇ ਸਫਲਤਾਪੂਰਵਕ ਕੀਤੀ ਸੀ।

ਜ਼ਿਆਦਾਤਰ ਵੈੱਬ ਕੂਕੀ ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ, ਇਹੀ ਉਹ ਮੁੱਲ ਹੈ ਜੋ OmniRoute ਵਿੱਚ ਪੇਸਟ ਕੀਤਾ ਜਾਣਾ ਚਾਹੀਦਾ ਹੈ।

# ਆਮ ਸੈੱਟਅੱਪ

ਜ਼ਿਆਦਾਤਰ ਵੈੱਬ ਕੂਕੀ ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ ਸੈੱਟਅੱਪ ਪ੍ਰਕਿਰਿਆ ਇੱਕੋ ਜਿਹੀ ਹੁੰਦੀ ਹੈ।

1. ਪ੍ਰਦਾਤਾ ਦੀ ਵੈੱਬਸਾਈਟ ਵਿੱਚ ਸਾਈਨ ਇਨ ਕਰੋ।
2. ਬ੍ਰਾਊਜ਼ਰ ਦੇ ਡਿਵੈਲਪਰ ਟੂਲ ਖੋਲ੍ਹੋ।
3. **ਨੈੱਟਵਰਕ** ਟੈਬ ਖੋਲ੍ਹੋ।
4. ਪੰਨੇ ਨੂੰ ਰਿਫ੍ਰੈਸ਼ ਕਰੋ।
5. ਕੋਈ ਪ੍ਰਮਾਣਿਤ ਚੈਟ ਜਾਂ ਗੱਲਬਾਤ ਬੇਨਤੀ ਖੋਲ੍ਹੋ।
6. ਲੋੜੀਂਦੇ ਪ੍ਰਮਾਣੀਕਰਨ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਕਾਪੀ ਕਰੋ।
7. OmniRoute ਖੋਲ੍ਹੋ।
8. **ਪ੍ਰਦਾਤਾ → ਪ੍ਰਦਾਤਾ ਸ਼ਾਮਲ ਕਰੋ** 'ਤੇ ਜਾਓ।
9. ਆਪਣਾ ਵੈੱਬ ਕੂਕੀ ਪ੍ਰਦਾਤਾ ਚੁਣੋ।
10. ਪ੍ਰਮਾਣ-ਪੱਤਰ ਪੇਸਟ ਕਰੋ।
11. **ਕਨੈਕਸ਼ਨ ਦੀ ਜਾਂਚ ਕਰੋ** 'ਤੇ ਕਲਿੱਕ ਕਰੋ।
12. ਪ੍ਰਦਾਤਾ ਨੂੰ ਸੇਵ ਕਰੋ।

ਲੋੜੀਂਦੇ ਸਟੀਕ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਪ੍ਰਦਾਤਾ 'ਤੇ ਨਿਰਭਰ ਕਰਦੇ ਹਨ।

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) ਇੱਕ ਮੁਫ਼ਤ ਉਪਭੋਗਤਾ ਚੈਟ ਪਲੇਟਫਾਰਮ ਹੈ, ਜਿਸ ਲਈ ਸਾਈਨ ਅੱਪ ਕਰਨ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ — ਪਹਿਲੀ ਵਾਰ ਵਿਜ਼ਿਟ ਕਰਨ 'ਤੇ ਸੈਸ਼ਨ ਗੁਮਨਾਮ ਤੌਰ 'ਤੇ ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ ਅਤੇ ਤਿੰਨ ਕੂਕੀਜ਼ ਰਾਹੀਂ ਕਾਇਮ ਰਹਿੰਦਾ ਹੈ: `uid`, `si_usr_id`, ਅਤੇ `si_ses_id`। OmniRoute ਇੱਕੋ `/api/dispatch` ਐਂਡਪੌਇੰਟ ਨੂੰ ਇੱਕੋ ਮਾਡਲ ਆਈਡੀ (`notrack-c`, ਉਪਨਾਮ `ntw`) ਰਾਹੀਂ ਪ੍ਰੌਕਸੀ ਕਰਦਾ ਹੈ।

### ਕਨੈਕਟ ਕਰਨ ਦੇ ਕਦਮ

1. ਆਪਣੇ ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ [notrack.ai](https://notrack.ai) ਖੋਲ੍ਹੋ ਅਤੇ ਗੁਮਨਾਮ ਸੈਸ਼ਨ ਕੂਕੀ ਨੂੰ ਸੈੱਟ ਹੋਣ ਦਿਓ।
2. **DevTools → Network** ਖੋਲ੍ਹੋ, ਪੰਨੇ ਨੂੰ ਰਿਫ੍ਰੈਸ਼ ਕਰੋ, ਅਤੇ ਕਿਸੇ ਵੀ `/api` ਬੇਨਤੀ 'ਤੇ ਕਲਿੱਕ ਕਰੋ।
3. **Request Headers** ਵਿੱਚੋਂ ਪੂਰਾ `Cookie` ਹੈਡਰ ਮੁੱਲ ਕਾਪੀ ਕਰੋ।
4. OmniRoute ਵਿੱਚ, **Providers → Add Provider → NoTrack Web (Free)** 'ਤੇ ਜਾਓ।
5. ਕੂਕੀ ਸਟ੍ਰਿੰਗ ਨੂੰ `apiKey` ਫੀਲਡ ਵਿੱਚ ਪੇਸਟ ਕਰੋ ਅਤੇ **Save** ਕਰੋ।

OmniRoute ਪੇਸਟ ਕੀਤੀ ਸਟ੍ਰਿੰਗ ਵਿੱਚੋਂ `uid`, `si_usr_id`, ਅਤੇ `si_ses_id` ਕੱਢਦਾ ਹੈ ਅਤੇ ਕੇਵਲ ਉਹਨਾਂ ਜੋੜਿਆਂ ਨਾਲ ਇੱਕ ਸਾਫ਼ `Cookie` ਹੈਡਰ ਮੁੜ ਬਣਾਉਂਦਾ ਹੈ — ਨਾਲ ਹੀ, ਜਦੋਂ ਮੌਜੂਦ ਹੋਵੇ, `nt_session` (ਲੌਗਇਨ ਕੀਤੇ ਖਾਤਿਆਂ ਲਈ ਸੈੱਟ ਕੀਤਾ ਗਿਆ `ntk_…` ਟੋਕਨ) ਵੀ ਸ਼ਾਮਲ ਕਰਦਾ ਹੈ। ਜੇ ਤਿੰਨਾਂ ਵਿੱਚੋਂ ਕੋਈ ਵੀ ਗੁੰਮ ਹੋਵੇ, ਤਾਂ ਕੱਚੀ ਪੇਸਟ ਕੀਤੀ ਸਟ੍ਰਿੰਗ ਨੂੰ ਬਿਨਾਂ ਬਦਲਾਅ ਅੱਗੇ ਭੇਜਿਆ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਜੋ ਆਪਰੇਟਰ ਵਿਕਲਪਕ ਬਣਤਰਾਂ ਨਾਲ ਪ੍ਰਯੋਗ ਕਰ ਸਕਣ।

### ਮਾਡਲ ਆਈਡੀਆਂ

| ਮਾਡਲ ਆਈਡੀ   | ਦਿਖਾਇਆ ਜਾਣ ਵਾਲਾ ਨਾਮ | ਨੋਟਸ                                              |
| ----------- | ------------------- | ------------------------------------------------- |
| `notrack-c` | NoTrack C           | ਡਿਫੌਲਟ — ਅੱਪਸਟ੍ਰੀਮ ਡਿਸਪੈਚ ਮਾਡਲ `C`।               |
| `C`         | NoTrack C           | `notrack-c` ਲਈ ਉਪਨਾਮ (ਕੱਚਾ ਅੱਪਸਟ੍ਰੀਮ ਡਿਸਪੈਚ ਕੋਡ)। |
| `notrack`   | NoTrack C           | `notrack-c` ਲਈ ਉਪਨਾਮ।                             |
| `ntw`       | NoTrack C           | `notrack-c` ਲਈ ਛੋਟਾ ਉਪਨਾਮ।                        |

ਸਾਰੀਆਂ ਚਾਰ ਮਾਡਲ ਆਈਡੀਆਂ ਇੱਕੋ ਅੱਪਸਟ੍ਰੀਮ ਡਿਸਪੈਚ ਮਾਡਲ (`C`) ਨਾਲ ਮੈਪ ਹੁੰਦੀਆਂ ਹਨ।

### ਬੇਨਤੀ ਵਿਕਲਪ

ਐਗਜ਼ੀਕਿਊਟਰ ਬੇਨਤੀ ਬਾਡੀ ਵਿੱਚ ਇਹ ਵਿਕਲਪਿਕ ਫੀਲਡਾਂ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ:

| ਬਾਡੀ ਫੀਲਡ             | ਡਿਫੌਲਟ  | ਉਦੇਸ਼                                                                      |
| --------------------- | ------- | -------------------------------------------------------------------------- |
| `notrack_mode`        | `usual` | ਡਿਸਪੈਚ ਮੋਡ (ਮੁਕਤ-ਰੂਪ ਸਟ੍ਰਿੰਗ; ਅੱਪਸਟ੍ਰੀਮ `usual`, … ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ)         |
| `notrack_max_turns`   | `6`     | ਜਵਾਬ ਦੇਣ ਤੋਂ ਪਹਿਲਾਂ ਅੱਪਸਟ੍ਰੀਮ ਵੱਲੋਂ ਲਏ ਜਾ ਸਕਣ ਵਾਲੇ ਅੰਦਰੂਨੀ ਟਰਨਾਂ ਦੀ ਗਿਣਤੀ। |
| `notrack_chat_id`     | `null`  | ਮੌਜੂਦਾ ਅੱਪਸਟ੍ਰੀਮ ਚੈਟ ਨੂੰ ਮੁੜ ਜਾਰੀ ਕਰੋ (ਨਵੀਂ ਚੈਟ ਲਈ ਛੱਡ ਦਿਓ)।               |
| `notrack_attachments` | `[]`    | ਅੱਪਸਟ੍ਰੀਮ ਅਟੈਚਮੈਂਟ ਡਿਸਕ੍ਰਿਪਟਰਾਂ ਦੀ ਪਾਸ-ਥਰੂ ਐਰੇ।                            |
| `notrack_regenerate`  | `false` | ਪਿਛਲੇ ਟਰਨ ਲਈ ਮੁੜ ਤਿਆਰ ਕੀਤਾ ਜਵਾਬ ਮੰਗਣ ਵਾਸਤੇ `true` ਸੈੱਟ ਕਰੋ।                |

### ਸਮਰੱਥਾਵਾਂ

- **ਸਟ੍ਰੀਮਿੰਗ ਅਤੇ ਗੈਰ-ਸਟ੍ਰੀਮਿੰਗ** ਚੈਟ ਕੰਪਲੀਸ਼ਨਾਂ।
- **ਟੂਲ ਕਾਲਿੰਗ** — ਬੇਨਤੀ 'ਤੇ `tools: [...]` ਸੈੱਟ ਕਰੋ; ਐਗਜ਼ੀਕਿਊਟਰ ਉਹਨਾਂ ਨੂੰ ਟੂਲ-ਕਾਲ ਐਨਵਲਪ ਕਾਂਟ੍ਰੈਕਟ ਵਿੱਚ ਸੀਰੀਅਲਾਈਜ਼ ਕਰਦਾ ਹੈ ਅਤੇ ਮਾਡਲ ਦੇ ਜਵਾਬਾਂ ਨੂੰ ਮੁੜ OpenAI `tool_calls` ਵਿੱਚ ਪਾਰਸ ਕਰਦਾ ਹੈ।
- **`response_format`** — `json_object` ਅਤੇ `json_schema` ਸਮਰਥਿਤ ਹਨ। ਐਗਜ਼ੀਕਿਊਟਰ ਮਾਡਲ ਦੇ ਜਵਾਬ ਵਿੱਚੋਂ ਪਹਿਲਾ JSON ਆਬਜੈਕਟ ਕੱਢਦਾ ਹੈ ਅਤੇ ਵਾਪਸ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਉਸਨੂੰ ਸਟ੍ਰਿੰਗ ਵਿੱਚ ਬਦਲਦਾ ਹੈ।
- **ਰੀਜ਼ਨਿੰਗ ਸੰਕੇਤ** — ਜਦੋਂ ਅੱਪਸਟ੍ਰੀਮ `thinking` ਇਵੈਂਟ ਭੇਜਦਾ ਹੈ, ਤਾਂ ਐਗਜ਼ੀਕਿਊਟਰ ਇੱਕ `reasoning` ਡੈਲਟਾ ਨਿਕਾਸ ਕਰਦਾ ਹੈ।

### ਸੀਮਾਵਾਂ

- ਅੱਪਸਟ੍ਰੀਮ ਗੁਮਨਾਮ ਵਰਤੋਂ ਕੋਟਿਆਂ ਨੂੰ ਲਾਗੂ ਕਰਦਾ ਹੈ — ਜਦੋਂ ਕੋਈ ਕੋਟਾ ਪਾਰ ਹੁੰਦਾ ਹੈ, ਤਾਂ ਐਗਜ਼ੀਕਿਊਟਰ ਇੱਕ ਵਰਤੋਂਕਾਰ-ਅਨੁਕੂਲ ਸੁਨੇਹੇ ਨਾਲ 429 ਦਿਖਾਉਂਦਾ ਹੈ।
- ਸਾਰੀਆਂ ਮਾਡਲ ਆਈਡੀਆਂ ਇੱਕੋ ਅੱਪਸਟ੍ਰੀਮ ਡਿਸਪੈਚ ਮਾਡਲ ਵੱਲ ਰਿਜ਼ਾਲਵ ਹੁੰਦੀਆਂ ਹਨ; ਹਰ ਮਾਡਲ ਲਈ ਵੱਖਰਾ ਸਵਿੱਚ ਉਪਲਬਧ ਨਹੀਂ ਹੈ।
- ਐਗਜ਼ੀਕਿਊਟਰ ਅੱਪਸਟ੍ਰੀਮ ਦੇ `/api/chats` ਐਂਡਪੌਇੰਟ ਨੂੰ ਕਾਲ ਨਹੀਂ ਕਰਦਾ, ਇਸ ਲਈ ਚੈਟ ਇਤਿਹਾਸ / ਸੈਸ਼ਨ ਆਪਣੇ ਆਪ ਪ੍ਰਬੰਧਿਤ ਨਹੀਂ ਹੁੰਦੇ। ਮੌਜੂਦਾ ਅੱਪਸਟ੍ਰੀਮ ਚੈਟ ਨੂੰ ਮੁੜ ਜਾਰੀ ਕਰਨ ਲਈ `notrack_chat_id` ਵਰਤੋ।

# ਵੈੱਬ ਕੂਕੀ ਪ੍ਰਦਾਤਾ ਕੀ ਕਰ ਸਕਦੇ ਹਨ ਅਤੇ ਕੀ ਨਹੀਂ ਕਰ ਸਕਦੇ

ਵੈੱਬ ਕੂਕੀ ਪ੍ਰਦਾਤਾ ਕਿਸੇ ਵੈੱਬਸਾਈਟ ਦੇ ਚੈਟ ਇੰਟਰਫੇਸ ਨੂੰ ਮੁੜ ਵਰਤਦੇ ਹਨ। ਉਹ ਅਧਿਕਾਰਤ APIs ਵਰਗੀਆਂ ਸਮਰੱਥਾਵਾਂ **ਪ੍ਰਦਾਨ ਨਹੀਂ** ਕਰਦੇ।

## ਸਮਰਥਿਤ

- ਆਪਣੇ ਮੌਜੂਦਾ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਪ੍ਰਮਾਣਿਤ ਕਰੋ
- ਆਪਣੇ ਖਾਤੇ ਰਾਹੀਂ ਉਪਲਬਧ ਮਾਡਲਾਂ ਤੱਕ ਪਹੁੰਚ ਕਰੋ
- ਚੈਟ ਜਵਾਬਾਂ ਨੂੰ ਸਟ੍ਰੀਮ ਕਰੋ
- ਕਿਸੇ API ਕੁੰਜੀ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ

## ਸਮਰਥਿਤ ਨਹੀਂ

- ਫੰਕਸ਼ਨ ਕਾਲਿੰਗ
- ਟੂਲ ਕਾਲਿੰਗ
- ਆਟੋਮੈਟਿਕ ਫ਼ਾਈਲ ਸੰਪਾਦਨ
- ਏਜੰਟ-ਅਧਾਰਿਤ IDE ਵਰਕਫ਼ਲੋ
- ਸਿਰਫ਼ API ਵਾਲੀਆਂ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ

ਇਹ ਉਮੀਦ ਕੀਤਾ ਗਿਆ ਵਿਹਾਰ ਹੈ ਅਤੇ ਇਹ ਕੋਈ **ਬੱਗ ਨਹੀਂ** ਹੈ।

ਜੇ ਤੁਹਾਨੂੰ ਟੂਲ ਚਲਾਉਣ, ਆਟੋਮੈਟਿਕ ਫ਼ਾਈਲ ਸੰਪਾਦਨ ਜਾਂ ਹੋਰ ਏਜੰਟ ਵਰਕਫ਼ਲੋ ਦੀ ਲੋੜ ਹੈ, ਤਾਂ Web Cookie ਪ੍ਰਦਾਤਾ ਦੀ ਬਜਾਏ ਇੱਕ **API-key ਪ੍ਰਦਾਤਾ** ਵਰਤੋ।

# ਪ੍ਰਮਾਣਿਕਤਾ ਸੰਬੰਧੀ ਚੇਤਾਵਨੀ

ਇੱਕ ਸਫਲ **ਕਨੈਕਸ਼ਨ ਟੈਸਟ** ਜਾਂ ਕੁਕੀ ਪ੍ਰਮਾਣਿਕਤਾ ਸਿਰਫ਼ ਇਹ ਪੁਸ਼ਟੀ ਕਰਦੀ ਹੈ ਕਿ ਦਿੱਤੇ ਗਏ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਉਮੀਦ ਕੀਤੇ ਫਾਰਮੈਟ ਵਿੱਚ ਜਾਪਦੇ ਹਨ।

Issue #7857 ਹੱਲ ਹੋਣ ਤੱਕ, ਸਫਲ ਪ੍ਰਮਾਣਿਕਤਾ ਇਸ ਗੱਲ ਦੀ **ਗਾਰੰਟੀ ਨਹੀਂ ਦਿੰਦੀ** ਕਿ ਪ੍ਰਦਾਤਾ ਸਫਲਤਾਪੂਰਵਕ ਪ੍ਰਮਾਣਿਤ ਕਰੇਗਾ।

ਜੇ ਪ੍ਰਮਾਣੀਕਰਨ ਫਿਰ ਵੀ ਅਸਫਲ ਹੁੰਦਾ ਹੈ, ਤਾਂ ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਤੁਸੀਂ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਬ੍ਰਾਊਜ਼ਰ ਦੀ ਕੁਕੀ ਸਟੋਰੇਜ ਦੀ ਬਜਾਏ ਕਿਸੇ ਸਰਗਰਮ ਨੈੱਟਵਰਕ ਬੇਨਤੀ ਤੋਂ ਕਾਪੀ ਕੀਤੇ ਸਨ।

# ਸਮੱਸਿਆ-ਨਿਪਟਾਰਾ

## ਪ੍ਰਮਾਣੀਕਰਨ ਅਸਫਲ ਹੁੰਦਾ ਹੈ

ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਇੱਥੋਂ ਕਾਪੀ ਕੀਤੇ ਗਏ ਸਨ:

```
ਨੈੱਟਵਰਕ
→ ਬੇਨਤੀ ਹੈਡਰ
→ ਕੁਕੀ
```

ਅਤੇ ਇੱਥੋਂ **ਨਹੀਂ**:

```
ਐਪਲੀਕੇਸ਼ਨ
→ ਕੁਕੀਜ਼
```

---

## ਕੁਕੀ ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ ਕੰਮ ਕਰਦੀ ਹੈ ਪਰ OmniRoute ਵਿੱਚ ਨਹੀਂ

ਕੁਝ ਪ੍ਰਦਾਤਾ ਅਜਿਹੀਆਂ ਕੁਕੀਜ਼ ਸ਼ਾਮਲ ਕਰਦੇ ਹਨ ਜੋ ਸਿਰਫ਼ ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀਆਂ ਦੌਰਾਨ ਹੀ ਭੇਜੀਆਂ ਜਾਂਦੀਆਂ ਹਨ।

ਕਿਸੇ ਗੱਲਬਾਤ ਨੂੰ ਸਫਲਤਾਪੂਰਵਕ ਖੋਲ੍ਹਣ ਤੋਂ ਬਾਅਦ ਇੱਕ ਨਵੀਂ ਨੈੱਟਵਰਕ ਬੇਨਤੀ ਤੋਂ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਮੁੜ ਕਾਪੀ ਕਰੋ।

---

## ਸੈਸ਼ਨ ਦੀ ਮਿਆਦ ਸਮਾਪਤ ਹੋ ਗਈ

Web Cookie ਪ੍ਰਦਾਤਾ ਤੁਹਾਡੇ ਮੌਜੂਦਾ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਹਨ।

ਜੇ ਤੁਹਾਡੇ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਦੀ ਮਿਆਦ ਸਮਾਪਤ ਹੋ ਜਾਂਦੀ ਹੈ ਜਾਂ ਤੁਸੀਂ ਸਾਈਨ ਆਉਟ ਕਰਦੇ ਹੋ, ਤਾਂ ਤੁਹਾਨੂੰ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲਾਂ ਦਾ ਇੱਕ ਨਵਾਂ ਸੈੱਟ ਕਾਪੀ ਕਰਨਾ ਪਵੇਗਾ। ਸਮਰਥਿਤ ਵੈੱਬ ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ ਕੁਕੀ ਨਵੀਨੀਕਰਨ ਨੂੰ ਆਟੋਮੈਟਿਕ ਕਰਨ ਵਾਸਤੇ, ਸਹਾਇਕ ਟੂਲ [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) ਵੇਖੋ।

## ਕਨੈਕਸ਼ਨ ਟੈਸਟ ਪਾਸ ਹੁੰਦਾ ਹੈ ਪਰ ਬੇਨਤੀਆਂ ਅਸਫਲ ਹੁੰਦੀਆਂ ਹਨ

Issue #7857 ਹੱਲ ਹੋਣ ਤੱਕ, ਪ੍ਰਮਾਣਿਕਤਾ ਪਾਸ ਹੋਣਾ ਇਸ ਗੱਲ ਦੀ ਗਾਰੰਟੀ ਨਹੀਂ ਦਿੰਦਾ ਕਿ ਪ੍ਰਮਾਣੀਕਰਨ ਬੇਨਤੀ ਸਫਲ ਹੋਵੇਗੀ।

ਅੱਗੇ ਸਮੱਸਿਆ-ਨਿਪਟਾਰਾ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਕਿਸੇ ਨਵੀਂ ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀ ਤੋਂ ਆਪਣੇ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਮੁੜ ਕਾਪੀ ਕਰੋ।

## ChatGPT Web `"Unsupported ChatGPT integrity dependency"` ਨਾਲ ਅਸਫਲ ਹੁੰਦਾ ਹੈ

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਠੀਕ ਹੈ — ਉਹ ਗਲਤੀ ਬ੍ਰਿਜ ਤੋਂ ਆਉਂਦੀ ਹੈ, ਸੈਸ਼ਨ ਤੋਂ ਨਹੀਂ। chatgpt.com ਹਰ ਡਿਪਲੌਇਮੈਂਟ ਲਈ ਆਪਣੇ
ਮੌਡਿਊਲ ID ਨਿਰਧਾਰਤ ਕਰਦਾ ਹੈ, ਅਤੇ ਬ੍ਰਿਜ ਪਹਿਲਾਂ ਉਸ ਵੱਲੋਂ ਇੰਸਟੈਂਸ਼ੀਏਟ ਕੀਤੇ Sentinel ਹੈਲਪਰ ਦੀ ID ਨੂੰ ਪਿੰਨ ਕਰਦਾ ਸੀ, ਇਸ ਲਈ
chatgpt.com ਦੇ ਉਸ ਰੀਬਿਲਡ ਨੇ, ਜਿਸ ਨੇ ਹੈਲਪਰ ਦਾ ਨਾਮ ਬਦਲਿਆ ਸੀ, ਕੁਕੀ ਦੇ ਵੈਧ ਰਹਿਣ ਦੇ ਬਾਵਜੂਦ ਹਰ ਵਾਰੀ ਦੀ ਕਾਰਵਾਈ ਨੂੰ ਤੋੜ ਦਿੱਤਾ। ਕਨੈਕਸ਼ਨ ਨੂੰ ਮੁੜ ਪ੍ਰਮਾਣਿਤ
ਕਰਨ ਨਾਲ ਇਹ ਠੀਕ ਨਹੀਂ ਹੋ ਸਕਦਾ।

ਉਹ ਬਿਲਡ ਜੋ ਪੇਜ ਦੇ ਆਪਣੇ ਰਨਟਾਈਮ ਰਾਹੀਂ ਮੌਡਿਊਲ ਨੂੰ ਰਿਜ਼ੌਲਵ ਕਰਦੇ ਹਨ, ਕਿਸੇ ID ਨੂੰ ਪਿੰਨ ਨਹੀਂ ਕਰਦੇ ਅਤੇ ਇਸ ਸਮੱਸਿਆ ਦਾ ਸਾਹਮਣਾ ਨਹੀਂ ਕਰਦੇ। ਜੇ ਤੁਹਾਨੂੰ ਇਹ
ਗਲਤੀ ਦਿਖਾਈ ਦਿੰਦੀ ਹੈ, ਤਾਂ OmniRoute ਨੂੰ ਅੱਪਗ੍ਰੇਡ ਕਰੋ ਅਤੇ ਕਨੈਕਸ਼ਨ ਜਾਂਚ ਮੁੜ ਚਲਾਓ।

ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ ਪੂਰੀ ਕਦਮ-ਦਰ-ਕਦਮ ਜਾਣਕਾਰੀ ਲਈ, ਵੇਖੋ:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web ਗਾਈਡ ਇੱਕ Web Cookie ਪ੍ਰਦਾਤਾ ਲਈ ਪੂਰੀ ਸੈੱਟਅੱਪ ਪ੍ਰਕਿਰਿਆ ਦਰਸਾਉਂਦੀ ਹੈ ਅਤੇ ਸੰਦਰਭ ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ ਵਜੋਂ ਕੰਮ ਕਰਦੀ ਹੈ।

# ਸਰਵੋਤਮ ਅਭਿਆਸ

- ਕਿਸੇ ਨਵੀਂ ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀ ਤੋਂ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਕਾਪੀ ਕਰੋ।
- ਪੁਰਾਣੀਆਂ ਕੁਕੀਜ਼ ਨੂੰ ਮੁੜ ਵਰਤਣ ਤੋਂ ਬਚੋ।
- Web Cookie ਪ੍ਰਦਾਤਾਵਾਂ ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਸਮੇਂ ਆਪਣੇ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਨੂੰ ਸਰਗਰਮ ਰੱਖੋ।
- ਕਾਪੀ ਕੀਤੀਆਂ ਕੁਕੀਜ਼ ਨੂੰ ਸੰਵੇਦਨਸ਼ੀਲ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਸਮਝੋ।
- ਜਦੋਂ ਤੁਹਾਨੂੰ ਫੰਕਸ਼ਨ ਕਾਲਿੰਗ ਜਾਂ ਏਜੰਟ ਵਰਕਫ਼ਲੋ ਦੀ ਲੋੜ ਹੋਵੇ, ਤਾਂ API-key ਪ੍ਰਦਾਤਾ ਵਰਤੋ।
