ਸਵੈ-ਹੋਸਟ ਕੀਤਾ ਪੂਲ **.113** ਬਾਕਸ (`tomni-proxmox-113`) ਉੱਤੇ ਚੱਲਦਾ ਹੈ। 2026-10-18 ਤੋਂ ਹਰੇਕ
OmniRoute runner ਦੀ **ਇੱਕ ਭੂਮਿਕਾ**, ਇੱਕ label, ਅਤੇ ਉਸਦੇ workload ਦੇ ਮਾਪੇ ਗਏ ਸਰੋਤਾਂ ਅਨੁਸਾਰ
ਨਿਰਧਾਰਤ memory/CPU ਬਜਟ ਹੈ। Turbopack slot ਨੂੰ build ਲਈ ਲੋੜੀਂਦੇ ਸਰੋਤ ਮਿਲਦੇ ਹਨ; ਹੋਰ slots ਨੂੰ
ਉਨ੍ਹਾਂ ਦੇ ਮਾਪੇ ਗਏ ਸਿਖਰਾਂ ਅਨੁਸਾਰ ਸਰੋਤ ਦਿੱਤੇ ਗਏ ਹਨ। ਬਾਕਸ ਕੇਵਲ ਉਦੋਂ overcommit ਹੁੰਦਾ ਹੈ ਜਦੋਂ Turbopack
build, Release-Green webpack build ਅਤੇ lint job ਇੱਕੋ ਸਮੇਂ ਚੱਲਦੇ ਹਨ; host swap (16 GB) ਇਸ ਨੂੰ
ਸੰਭਾਲ ਲੈਂਦਾ ਹੈ, ਅਤੇ ਕਿਉਂਕਿ pull-request Builds ਹੋਸਟ ਕੀਤੇ runners ਉੱਤੇ ਚੱਲਦੇ ਹਨ, Turbopack slot

(ਪਿਛਲੇ ਮੁੱਲ `override.conf.bak-20261018` ਵਜੋਂ ਰੱਖੇ ਗਏ ਹਨ) ਅਤੇ ਚੱਲਦੇ ਸਿਸਟਮ ਉੱਤੇ
`systemctl set-property --runtime … MemoryHigh=… MemoryMax=… CPUQuota=…` ਨਾਲ ਲਾਗੂ ਕੀਤੀਆਂ ਗਈਆਂ ਸਨ — ਕੋਈ restart ਨਹੀਂ ਹੋਇਆ, ਇਸ ਲਈ
ਕਿਸੇ ਵੀ ਚੱਲ ਰਹੇ job ਨੂੰ ਪ੍ਰਭਾਵਿਤ ਨਹੀਂ ਕੀਤਾ ਗਿਆ। Labels ਨੂੰ runners API ਰਾਹੀਂ ਬਦਲਿਆ ਜਾਂਦਾ ਹੈ
(`gh api -X DELETE repos/<repo>/actions/runners/<id>/labels/<label>` /
`gh api -X POST repos/<repo>/actions/runners/<id>/labels -f 'labels[]=<label>'`), ਉਹ ਵੀ ਚੱਲਦੇ ਸਿਸਟਮ ਉੱਤੇ ਹੀ।

## janitor ਇੰਸਟਾਲ ਕਰੋ (ਸਿਰਫ਼ ਇੱਕ ਵਾਰ, ਮਸ਼ੀਨ ਉੱਤੇ)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ਹਰ 30 ਮਿੰਟ ਬਾਅਦ, ਲੌਗ /var/log/runner-janitor.log ਵਿੱਚ
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` ਲੋੜੀਂਦਾ ਹੈ: janitor ਕਿਸੇ ਪਾਥ ਨੂੰ ਹਟਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਖੁੱਲ੍ਹੀਆਂ ਫ਼ਾਈਲਾਂ ਦੇ ਇੱਕ ਸਨੈਪਸ਼ਾਟ ਨਾਲ ਸਾਬਤ ਕਰਦਾ ਹੈ ਕਿ ਉਹ ਨਿਸ਼ਕਿਰਿਆ ਹੈ, ਅਤੇ ਇਸ ਟੂਲ ਤੋਂ ਬਿਨਾਂ ਇਹ ਕੁਝ ਵੀ ਨਹੀਂ ਹਟਾਉਂਦਾ ਅਤੇ ਇਸ ਬਾਰੇ ਦੱਸਦਾ ਹੈ (exit 1)। ਕੋਈ ਵੀ ਤਬਦੀਲੀ ਪਹਿਲਾਂ `--dry-run` ਨਾਲ ਅਜ਼ਮਾਓ — ਇਹ ਬਿਲਕੁਲ ਉਹੀ ਪ੍ਰਿੰਟ ਕਰਦਾ ਹੈ ਜੋ ਇਹ ਕਰੇਗਾ ਅਤੇ ਕਿਸੇ ਚੀਜ਼ ਨੂੰ ਛੂੰਹਦਾ ਨਹੀਂ।

ਹਰ ਵਾਰ ਚੱਲਣ 'ਤੇ ਇਹ ਕੀ ਕਰਦਾ ਹੈ: **tmpfs ਉੱਤੇ 3 ਘੰਟਿਆਂ** ਅਤੇ ਡਿਸਕ ਦੇ `_work/_temp` ਉੱਤੇ 24 ਘੰਟਿਆਂ ਬਾਅਦ ਸਾਡੇ ਆਪਣੇ ਬਚੇ ਹੋਏ ਆਈਟਮਾਂ (`runner-*`, `omniroute-*`, `next-build*`, `e2e-build.tar.gz`) ਨੂੰ ਸਾਫ਼ ਕਰਦਾ ਹੈ; 75 ਮਿੰਟ ਤੋਂ ਪੁਰਾਣੇ `next-build` ਨੂੰ ਖਤਮ ਕਰਦਾ ਹੈ (ਕੋਈ ਵੀ ਜੌਬ ਇੰਨਾ ਲੰਮਾ ਨਹੀਂ ਚੱਲਦਾ — 2026-08-27 ਨੂੰ GitHub ਵੱਲੋਂ ਉਸ ਦੀ ਜੌਬ ਗੁੰਮ ਐਲਾਨੇ ਜਾਣ ਤੋਂ ਬਾਅਦ ਇੱਕ 70 ਮਿੰਟ ਤੱਕ ਚੱਲਿਆ ਸੀ); ਉਨ੍ਹਾਂ runners ਦੇ 48 ਘੰਟੇ ਪੁਰਾਣੇ checkouts ਨੂੰ ਹਟਾਉਂਦਾ ਹੈ ਜਿਨ੍ਹਾਂ ਦੀ unit **ਬੰਦ** ਹੈ; ਅਤੇ ਡਿਸਕ ≥ 85 %, memory PSI `full/avg60` ≥ 10 %, ਅਤੇ `MAX_ACTIVE_RUNNERS` ਤੋਂ ਵੱਧ listeners ਹੋਣ 'ਤੇ ਚੇਤਾਵਨੀ ਦਿੰਦਾ ਹੈ (omniroute/ਹੋਰ ਦੇ ਵੇਰਵੇ ਸਮੇਤ)। Exit 1 = ਧਿਆਨ ਦੀ ਲੋੜ ਹੈ; ਲੌਗ ਪੜ੍ਹੋ।

75-ਮਿੰਟ ਵਾਲਾ ਨਿਯਮ ਉਸ build ਨੂੰ ਨਹੀਂ ਫੜਦਾ ਜਿਸ ਦੀ ਜੌਬ ਨੂੰ GitHub ਪਹਿਲਾਂ ਹੀ ਛੱਡ ਚੁੱਕਾ ਹੋਵੇ। ਜਦੋਂ `Runner.Listener` ਆਪਣੀ ਜੌਬ renew ਨਹੀਂ ਕਰ ਸਕਦਾ, ਤਾਂ `_diag/Runner_*.log` ਵਿੱਚ `POST request to …/renewjob timed out after 100 seconds` ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ, API ਆਖਰੀ ਸਫਲ renewal ਤੋਂ ਲਗਭਗ ਦਸ ਮਿੰਟ ਬਾਅਦ ਜੌਬ ਨੂੰ `completed` (ਅਸਫਲ) ਰਿਪੋਰਟ ਕਰਦਾ ਹੈ, ਅਤੇ `next-build` ਬਿਨਾਂ ਕਿਸੇ ਜੁੜੀ ਹੋਈ ਜੌਬ ਦੇ ਚੱਲਦਾ ਰਹਿੰਦਾ ਹੈ (2026-10-18: #17066 ਦਾ Build 19:43 ਵਜੇ ਅਸਫਲ ਹੋ ਗਿਆ ਸੀ ਅਤੇ ਪੰਜ ਮਿੰਟ ਬਾਅਦ ਵੀ ਉਸ ਦਾ build 40 GB ਘੇਰੀ ਬੈਠਾ ਸੀ)। ਸਭ ਤੋਂ ਨਵੇਂ `_diag/Worker_*.log` ਵਿੱਚ ref ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ, ਫਿਰ PID ਰਾਹੀਂ ਸਿਰਫ਼ build tree ਨੂੰ SIGTERM ਭੇਜੋ — `next-build`, `npm run build`, `build-next-isolated.mjs` ਅਤੇ `_work` workers। `Runner.Listener`, `RunnerService.js` ਜਾਂ `Runner.Worker` ਨੂੰ ਕਦੇ ਨਾ ਛੇੜੋ: worker ਜੌਬ ਨੂੰ cancelled ਵਜੋਂ ਰਿਪੋਰਟ ਕਰਦਾ ਹੈ ਅਤੇ listener ਆਪਣੇ ਆਪ ਮੁੜ online ਹੋ ਜਾਂਦਾ ਹੈ।

## Runner units: KillMode

Runner ਦਾ ਮੂਲ `KillMode=process`, unit ਨੂੰ ਬੰਦ ਜਾਂ restart ਕਰਨ ਵੇਲੇ `Runner.Worker → npm → next-build` ਨੂੰ ਚੱਲਦਾ ਛੱਡ ਦਿੰਦਾ ਹੈ — ਇੱਕ orphan build ਬਿਨਾਂ ਕਿਸੇ ਜੁੜੀ ਹੋਈ ਜੌਬ ਦੇ RAM ਅਤੇ CPU ਵਰਤਦਾ ਰਹਿੰਦਾ ਹੈ। ਹਰ OmniRoute unit ਵਿੱਚ `KillMode=mixed` ਵਾਲਾ ਇੱਕ drop-in (`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`) ਹੁੰਦਾ ਹੈ: ਪਹਿਲਾਂ listener ਨੂੰ SIGTERM, ਫਿਰ `TimeoutStop` ਉੱਤੇ ਪੂਰੇ cgroup ਨੂੰ SIGKILL। ਇਹ unit ਦੇ ਅਗਲੇ restart 'ਤੇ ਪ੍ਰਭਾਵੀ ਹੁੰਦਾ ਹੈ — **ਇੱਕ ਸਮੇਂ ਸਿਰਫ਼ ਇੱਕ runner ਨੂੰ, ਅਤੇ ਕੇਵਲ ਉਸ ਦੇ ਨਿਸ਼ਕਿਰਿਆ ਹੋਣ ਵੇਲੇ** restart ਕਰੋ, ਅਤੇ idle check ਤੇ restart ਨੂੰ ਇੱਕੋ command ਵਿੱਚ ਰੱਖੋ।
