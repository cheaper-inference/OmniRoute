OmniRoute ਥਿੰਕਿੰਗ-ਮੋਡ ਮਾਡਲਾਂ ਦੁਆਰਾ ਤਿਆਰ ਸਹਾਇਕ `reasoning_content` ਕੈਪਚਰ ਕਰਦਾ ਹੈ ਅਤੇ ਜਦੋਂ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ ਨੂੰ ਇਸਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ ਤਾਂ ਮਲਟੀ-ਟਰਨ ਬੇਨਤੀਆਂ 'ਤੇ ਇਸਨੂੰ ਪਾਰਦਰਸ਼ੀ ਢੰਗ ਨਾਲ ਰੀਪਲੇਅ ਕਰਦਾ ਹੈ। ਇਹ HTTP 400 ਗਲਤੀਆਂ ਨੂੰ ਖਤਮ ਕਰਦਾ ਹੈ ਜੋ ਸਖਤ ਪ੍ਰਦਾਤਾ ਉਦੋਂ ਉਠਾਉਂਦੇ ਹਨ ਜਦੋਂ ਕਿਸੇ ਕਲਾਇੰਟ ਦੇ ਗੱਲਬਾਤ ਦੇ ਇਤਿਹਾਸ ਵਿੱਚ ਪਿਛਲੀ ਵਾਰੀ ਦਾ ਤਰਕ ਗੁੰਮ ਹੁੰਦਾ ਹੈ।

## ਇਹ ਕਿਉਂ ਮੌਜੂਦ ਹੈ

ਕਈ ਸੋਚ-ਮੋਡ ਪ੍ਰਦਾਤਾ ਇੱਕ ਫਾਲੋ-ਅਪ ਮੋੜ ਨੂੰ ਰੱਦ ਕਰਦੇ ਹਨ ਜਦੋਂ ਤੱਕ ਕਿ** ਪਿਛਲੇ ਸਹਾਇਕ ਸੁਨੇਹੇ ਵਿੱਚ ਮੂਲ `reasoning_content` ਸ਼ਾਮਲ ਹੈ** . ਅੱਪਸਟ੍ਰੀਮ ਸੁਨੇਹਿਆਂ ਨਾਲ 400 ਵਾਪਸ ਕਰਦਾ ਹੈ ਜਿਵੇਂ ਕਿ:

```
Param Incorrect: The reasoning_content in the thinking mode must be passed back to the API.
```

ਪਰ ਆਮ ਕਲਾਇੰਟ (Cursor, Cline, Roo Code, OpenAI SDK) `reasoning_content` ਇਤਿਹਾਸ ਤੋਂ ਹਟਾ ਦਿੰਦੇ ਹਨ ਜੋ ਉਹ ਦੁਬਾਰਾ ਖੇਡਦੇ ਹਨ। OmniRoute ਇਸਨੂੰ ਸਰਵਰ-ਸਾਈਡ ਕੈਸ਼ ਤੋਂ ਰੀਸਟੋਰ ਕਰਦਾ ਹੈ ਤਾਂ ਜੋ ਅਪਸਟ੍ਰੀਮ ਦੁਆਰਾ ਵੇਖੀ ਗਈ ਬੇਨਤੀ ਇਕਸਾਰ ਹੋਵੇ। ਅੰਕ #1628 ਨੇ ਹਾਈਬ੍ਰਿਡ memory/SQLite ਸਥਿਰਤਾ ਪੇਸ਼ ਕੀਤੀ ਹੈ ਤਾਂ ਕਿ ਕੈਸ਼ ਬਚੇ ਰਹਿਣ ਦੀ ਪ੍ਰਕਿਰਿਆ ਨੂੰ ਮੁੜ ਚਾਲੂ ਕੀਤਾ ਜਾ ਸਕੇ।

## ਆਰਕੀਟੈਕਚਰ

```
Turn N (assistant generates):
  → response contains reasoning_content + tool_calls
  → if requiresReasoningReplay(provider, model): cacheReasoningFromAssistantMessage()
      writes (memory + DB), keyed by every tool_call.id
  → forward response to client (which may or may not retain reasoning)

Turn N+1 (client sends follow-up):
  → translator detects: requiresReasoningReplay(provider, model) === true
  → for each assistant message with tool_calls and no reasoning_content:
      lookupReasoning(toolCalls[0].id) → memory → DB
      hit  → msg.reasoning_content = cached; recordReplay()
      miss → msg.reasoning_content = "" (legacy fallback for older DeepSeek)
  → upstream sees consistent history → no 400
```

ਕੈਪਚਰ `open-sse/handlers/chatCore.ts` (ਦੋ ਸਾਈਟਾਂ, ਦੋ `cacheReasoningFromAssistantMessage` ਕਾਲ ਸਾਈਟਾਂ 'ਤੇ) ਵਿੱਚ ਹੁੰਦਾ ਹੈ। ਰੀਪਲੇਅ `open-sse/translator/index.ts` ਵਿੱਚ ਸਕੀਮਾ ਜ਼ਬਰਦਸਤੀ ਤੋਂ ਬਾਅਦ ਪਰ ਡਿਸਪੈਚ ਤੋਂ ਪਹਿਲਾਂ ਹੁੰਦਾ ਹੈ।

ਪਲੇਨ (ਗੈਰ-ਟੂਲ-ਕਾਲ) ਸਹਾਇਕ ਮੋੜਾਂ ਨੂੰ ਵੱਖਰੇ ਤਰੀਕੇ ਨਾਲ ਜੋੜਿਆ ਜਾਂਦਾ ਹੈ: `buildAssistantMessageCacheKey()` ਸੈਸ਼ਨ ਸਕੋਪ ਨੂੰ ਹਜ਼ਮ ਕਰਦਾ ਹੈ ਅਤੇ ਉਸ ਮੋੜ ਤੱਕ ਸਧਾਰਣ ਓਪਨਏਆਈ-ਫਾਰਮੈਟ ਟ੍ਰਾਂਸਕ੍ਰਿਪਟ ਨੂੰ ਹਜ਼ਮ ਕਰਦਾ ਹੈ, ਕਿਉਂਕਿ DeepSeek ਇੱਕ ਵਾਰ `tools` ਮੌਜੂਦ ਹੋਣ 'ਤੇ _Every_ ਪੂਰਵ ਮੋੜ ਦੇ ਤਰਕ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ। ਜਵਾਬਾਂ-API ਟੀਚਿਆਂ ਲਈ (ਉਦਾਹਰਨ ਲਈ `opencode-go/deepseek-v4-flash`, `/responses` ਨੂੰ ਰਾਊਟ ਕੀਤਾ ਗਿਆ) ਅੱਪਸਟ੍ਰੀਮ ਬਾਡੀ `input` ਨੂੰ ਲੈ ਕੇ ਜਾਂਦੀ ਹੈ, `messages` ਨਹੀਂ, ਇਸਲਈ `translateRequest()` (`open-sse/translator/index.ts`) ਇੱਕ ਕਾਲਬੈਕ ਵਿਕਲਪ ਦੁਆਰਾ ਹਜ਼ਮ ਕੀਤੇ ਗਏ ਪਿਵਟ ਟ੍ਰਾਂਸਕ੍ਰਿਪਟ ਦੀ ਰਿਪੋਰਟ ਕਰਦਾ ਹੈ ਅਤੇ ਕੈਪਚਰ ਸਾਈਟਾਂ ਉਸੇ ਟ੍ਰਾਂਸਕ੍ਰਿਪਟ ਨੂੰ ਹਜ਼ਮ ਕਰਦੀਆਂ ਹਨ। ਜਵਾਬਾਂ ਦਾ ਰੀਪਲੇਅ ਪਾਸ ਹਰ ਸਰੋਤ ਫਾਰਮੈਟ ਲਈ OpenAI ਪੀਵੋਟ 'ਤੇ ਚੱਲਦਾ ਹੈ, ਇਸਲਈ Anthropic ਸੁਨੇਹੇ ਕਲਾਇੰਟਸ (Claude → OpenAI → ਜਵਾਬ) ਨੂੰ ਵੀ ਰੀਪਲੇਅ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

## ਸਟੋਰੇਜ — ਹਾਈਬ੍ਰਿਡ ਮੈਮੋਰੀ + SQLite

ਹੌਟ ਪਾਥ ਕਰੈਸ਼ ਰਿਕਵਰੀ ਅਤੇ ਡੈਸ਼ਬੋਰਡ ਦਿੱਖ ਲਈ ਇੱਕ SQLite ਟੇਬਲ ਦੁਆਰਾ ਸਮਰਥਿਤ ਇੱਕ ਇਨ-ਮੈਮੋਰੀ `Map` (LRU-by-create) ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ।

| ਪਰਤ    | ਲਾਗੂ ਕਰਨਾ                                        | ਮਕਸਦ                                              |
| ------ | ------------------------------------------------ | ------------------------------------------------- |
| ਮੈਮੋਰੀ | `open-sse/services/reasoningCache.ts` ਵਿੱਚ `Map` | ਤੇਜ਼ ਲੁੱਕਅੱਪ, 200 'ਤੇ ਸਭ ਤੋਂ ਪੁਰਾਣਾ ਬੇਦਖਲ ਕਰਦਾ ਹੈ |
| DB     | `reasoning_cache` ਟੇਬਲ (`src/lib/db/`)           | ਰੀਸਟਾਰਟ, ਡਰਾਈਵ ਦੇ ਅੰਕੜਿਆਂ ਵਿੱਚ ਜਾਰੀ ਰਹਿੰਦਾ ਹੈ     |

ਲਿਖਦਾ ਦੋਨਾਂ ਨੂੰ ਜਾਂਦਾ ਹੈ। ਪੜ੍ਹਦਾ ਹੈ ਪਹਿਲਾਂ ਮੈਮੋਰੀ ਦੀ ਸਲਾਹ ਲਓ, ਫਿਰ DB ਤੇ ਵਾਪਸ ਜਾਓ (DB ਹਿੱਟਾਂ ਨੂੰ ਮੈਮੋਰੀ ਵਿੱਚ ਵਾਪਸ ਪ੍ਰਮੋਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ)। DB ਅਸਫਲਤਾਵਾਂ ਗੈਰ-ਘਾਤਕ — ਹਨ ਇਨ-ਮੈਮੋਰੀ ਕੈਸ਼ ਹੌਟ ਮਾਰਗ ਦੀ ਸੇਵਾ ਕਰਨਾ ਜਾਰੀ ਰੱਖਦਾ ਹੈ।

**ਪੂਰਵ-ਨਿਰਧਾਰਤ:**

- TTL: `2h` (`TTL_MS = 2 * 60 * 60 * 1000`)
- ਅਧਿਕਤਮ ਮੈਮੋਰੀ ਐਂਟਰੀਆਂ: `200` (`MAX_MEMORY_ENTRIES`)
- ਬੇਦਖਲੀ: ਸਭ ਤੋਂ ਪੁਰਾਣਾ `createdAt` ਪਹਿਲਾਂ

## ਡਾਟਾਬੇਸ ਸਕੀਮਾ

ਪਰਵਾਸ: `src/lib/db/migrations/033_create_reasoning_cache.sql`

```sql
CREATE TABLE IF NOT EXISTS reasoning_cache (
  tool_call_id   TEXT PRIMARY KEY,
  provider       TEXT NOT NULL,
  model          TEXT NOT NULL,
  reasoning      TEXT NOT NULL,
  char_count     INTEGER NOT NULL DEFAULT 0,
  created_at     TEXT NOT NULL DEFAULT (datetime('now')),
  expires_at     INTEGER NOT NULL
);
```

ਸੂਚਕਾਂਕ: `expires_at`, `provider`, `model`, `created_at`. `expires_at` ਨੂੰ ਯੂਨਿਕਸ ਯੁਗ ਸਕਿੰਟਾਂ ਵਜੋਂ ਸਟੋਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ; SELECT ਪਰਤ `EXPIRES_AT_EPOCH_SQL` ਦੁਆਰਾ ਵਿਰਾਸਤੀ ਟੈਕਸਟ ਮੁੱਲਾਂ ਨੂੰ ਆਮ ਬਣਾਉਂਦਾ ਹੈ।

## REST API

ਕੈਸ਼ `src/app/api/cache/reasoning/route.ts` ਦੇ ਅਧੀਨ ਦੋ ਅੰਤ ਬਿੰਦੂਆਂ ਦਾ ਪਰਦਾਫਾਸ਼ ਕਰਦਾ ਹੈ। ਦੋਵਾਂ ਨੂੰ ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣਿਕਤਾ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ (`isAuthenticated` ਤੋਂ `@/shared/utils/apiAuth`)।

| ਵਿਧੀ   | ਅੰਤ ਬਿੰਦੂ                                                 | ਵਰਣਨ                                                           |
| ------ | --------------------------------------------------------- | -------------------------------------------------------------- |
| GET    | `/api/cache/reasoning`                                    | ਅੰਕੜੇ + ਪੰਨਾ ਇੰਦਰਾਜ਼                                           |
| GET    | `/api/cache/reasoning?provider=deepseek&model=...&limit=` | ਫਿਲਟਰ ਕੀਤੀ ਸੂਚੀ (`limit` ਨੂੰ `[1, 200]` ਨਾਲ ਜੋੜਿਆ ਗਿਆ)         |

## ਕਾਰਜਕਾਰੀ ਨੋਟਸ

- **ਸਾਫ਼ ਕਰੋ:** `cleanupReasoningCache()` ਮਿਆਦ ਪੁੱਗੀਆਂ ਮੈਮੋਰੀ ਐਂਟਰੀਆਂ ਨੂੰ ਸਾਫ਼ ਕਰਦਾ ਹੈ ਅਤੇ `DELETE FROM reasoning_cache WHERE expires_at <= unixepoch('now')` ਨੂੰ ਚਲਾਉਂਦਾ ਹੈ। ਸਿਹਤ-ਜਾਂਚ ਕਰਮਚਾਰੀ ਇਸ ਨੂੰ ਸਮੇਂ-ਸਮੇਂ 'ਤੇ ਕਾਲ ਕਰਦੇ ਹਨ।
- **ਕਰੈਸ਼ ਰਿਕਵਰੀ:** ਮੁੜ-ਚਾਲੂ ਹੋਣ ਤੋਂ ਬਾਅਦ, ਮੈਮੋਰੀ ਖਾਲੀ ਹੁੰਦੀ ਹੈ ਪਰ DB ਅਜੇ ਵੀ ਮਿਆਦ ਨਾ ਹੋਣ ਵਾਲੀਆਂ ਐਂਟਰੀਆਂ ਹੁੰਦੀਆਂ ਹਨ। ਦਿੱਤੇ `tool_call_id` ਲਈ ਪਹਿਲੀ ਖੋਜ ਇੱਕ DB ਹਿੱਟ ਹੈ; ਬਾਅਦ ਦੇ ਲੁੱਕਅੱਪ ਮੈਮੋਰੀ ਹਿੱਟ ਹਨ।
- **ਕੋਈ ਤਰਕ ਨਹੀਂ, ਕੋਈ ਕੈਸ਼ ਨਹੀਂ:** `cacheReasoningFromAssistantMessage` `0` ਵਾਪਸ ਕਰਦਾ ਹੈ ਜਦੋਂ ਸਹਾਇਕ ਸੁਨੇਹੇ ਵਿੱਚ ਕੋਈ `reasoning_content` / `reasoning` ਖੇਤਰ ਨਹੀਂ ਹੈ, ਇਸਲਈ ਗੈਰ-ਸੋਚਣ ਵਾਲੇ ਜਵਾਬਾਂ ਦੀ ਕੋਈ ਕੀਮਤ ਨਹੀਂ ਹੈ।
- **ਲਿਖੋ ਵੀ ਗੇਟ ਕੀਤਾ ਗਿਆ ਹੈ:** `chatCore.ts` (ਨਾਨ-ਸਟ੍ਰੀਮਿੰਗ ਅਤੇ ਸਟ੍ਰੀਮਿੰਗ) ਵਿੱਚ ਦੋਵੇਂ ਕਾਲ ਸਾਈਟਾਂ ਸਿਰਫ `cacheReasoningFromAssistantMessage()` ਕਾਲ ਕਰਦੀਆਂ ਹਨ ਜਦੋਂ `requiresReasoningReplay(provider, model)` `true` — ਹੁੰਦਾ ਹੈ, ਜੋ ਕਿ ਰੀਡ ਸਾਈਡ ਜਾਂਚਾਂ ਦਾ ਅਨੁਮਾਨ ਹੈ। ਉਹ ਸਥਾਪਨਾਵਾਂ ਜੋ ਕਦੇ ਵੀ ਰੀਪਲੇਅ ਪ੍ਰਦਾਤਾ ਨੂੰ ਨਹੀਂ ਛੂਹਦੀਆਂ ਹਰ ਤਰਕ-ਦਾਇਕ ਜਵਾਬ 'ਤੇ ਲਿਖਤ, ਸੂਚਕਾਂਕ ਅੱਪਡੇਟ, ਅਤੇ try/catch ਲਈ ਭੁਗਤਾਨ ਕਰਨਾ ਬੰਦ ਕਰ ਦਿੰਦੀਆਂ ਹਨ।
- **ਗੈਰ-ਸਖਤ ਪ੍ਰਦਾਤਾ:** ਜਦੋਂ `requiresReasoningReplay` `false` ਹੁੰਦਾ ਹੈ ਅਤੇ ਟੀਚਾ ਫਾਰਮੈਟ OpenAI ਹੁੰਦਾ ਹੈ, ਅਨੁਵਾਦਕ** ਪੱਟੀਆਂ** ਆਊਟਗੋਇੰਗ ਸੁਨੇਹਿਆਂ ਤੋਂ ਕੋਈ ਵੀ `reasoning_content` ਖੇਤਰ — OpenAI ਚੈਟ ਸੰਪੂਰਨਤਾ ਇਸ ਨੂੰ ਸਵੀਕਾਰ ਨਹੀਂ ਕਰਦਾ ਹੈ।

## ਮਿਊਜ਼ ਅਪਾਰਦਰਸ਼ੀ-ਤਰਕ ਮਾਲਕੀ

ਮਿਊਜ਼ (`muse-code`) ਕਾਲਰ-ਬਾਊਂਡ ਓਪੇਕ ਤਰਕ (`encrypted_content`) ਵਾਪਸ ਕਰਦਾ ਹੈ। ਇਸ ਨੂੰ ਕਿਸੇ ਵੱਖਰੇ ਖਾਤੇ ਜਾਂ ਰੀਮੇਂਟ ਕੀਤੇ ਪ੍ਰਮਾਣ ਪੱਤਰ ਦੇ ਅਧੀਨ ਮੁੜ ਚਲਾਉਣਾ ਅੱਪਸਟ੍ਰੀਮ ਵਿੱਚ ਅਸਫਲ ਹੋ ਜਾਂਦਾ ਹੈ, ਇਸਲਈ ਮੂਲ OAuth ਬੇਨਤੀਆਂ ਪ੍ਰਤੀ-ਬੇਨਤੀ ਰੋਟੇਸ਼ਨ (`src/sse/services/museSessionOwnership.ts`, `src/sse/handlers/chat.ts` ਵਿੱਚ ਲਾਗੂ) ਦੀ ਬਜਾਏ ਸੈਸ਼ਨ-ਪੱਧਰ ਦੀ ਮਲਕੀਅਤ ਦੀ ਵਰਤੋਂ ਕਰਦੀਆਂ ਹਨ। ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਚੁਣੇ ਗਏ API-ਕੁੰਜੀ ਕਨੈਕਸ਼ਨ ਅਤੇ API-ਕੁੰਜੀ-ਸਿਰਫ਼ ਸੰਰਚਨਾਵਾਂ ਇਸ ਮਲਕੀਅਤ ਮੋਡ ਤੋਂ ਬਿਨਾਂ ਆਪਣੀ ਮੌਜੂਦਾ ਰੂਟਿੰਗ ਨੂੰ ਬਰਕਰਾਰ ਰੱਖਦੀਆਂ ਹਨ।

- ਹਰ ਮੋੜ 'ਤੇ ਇੱਕ ਸਥਿਰ ਸੈਸ਼ਨ ID ਸਪਲਾਈ ਕਰੋ: `x-omniroute-session-id`, `x-omniroute-session`, `x-session-id`, ਜਾਂ `x-codex-session-id`; ਵਿਕਲਪਿਕ ਤੌਰ 'ਤੇ ਸਰੀਰ ਵਿੱਚ `prompt_cache_key`, `session_id`, `conversation_id`, ਜਾਂ `metadata.session_id` ਦੀ ਵਰਤੋਂ ਕਰੋ (ਉਸ ਤਰਜੀਹ ਕ੍ਰਮ ਵਿੱਚ)। ਗੁੰਮ ਜਾਂ ਖਾਲੀ IDs ਰਿਟਰਨ 400 ਜਦੋਂ ਦੋ ਜਾਂ ਦੋ ਤੋਂ ਵੱਧ ਨੇਟਿਵ OAuth ਖਾਤੇ ਕਿਰਿਆਸ਼ੀਲ ਹੁੰਦੇ ਹਨ; ਇੱਕ ਸਿੰਗਲ OAuth ਖਾਤੇ ਨਾਲ ਘੁੰਮਾਉਣ ਲਈ ਕੁਝ ਵੀ ਨਹੀਂ ਹੈ, ਇਸਲਈ ਅਜਿਹੀ ਬੇਨਤੀ ਅਨਪਿੰਨ ਰੂਟਿੰਗ ਨੂੰ ਜਾਰੀ ਰੱਖਦੀ ਹੈ। ਦਾਇਰੇ ਵਿੱਚ ਕਾਲਰ ਦੀ OmniRoute API-key ID ਸ਼ਾਮਲ ਹੈ।
- ਕਨੈਕਸ਼ਨ ID ਦੁਆਰਾ ਆਰਡਰ ਕੀਤੇ API-ਕੁੰਜੀ ਕੁਨੈਕਸ਼ਨ ਨੀਤੀ ਦੁਆਰਾ ਅਨੁਮਤੀ ਵਾਲੇ ਸਰਗਰਮ ਮੂਲ OAuth ਖਾਤਿਆਂ ਵਿੱਚ ਤਾਜ਼ਾ ਸੁਤੰਤਰ ਸੈਸ਼ਨ ਰਾਊਂਡ-ਰੋਬਿਨ। ਰਾਊਂਡ-ਰੋਬਿਨ ਟਰਮੀਨਲ ਸਥਿਤੀ (`banned`, `expired`, `credits_exhausted`), ਜਾਂ ਬੇਨਤੀ ਕੀਤੇ ਮਾਡਲ ਲਈ ਮਾਡਲ-ਲਾਕ ਦੇ ਨਾਲ, ਕੁਨੈਕਸ਼ਨ ਕੂਲਡਾਊਨ ਵਿੱਚ ਖਾਤਿਆਂ ਨੂੰ ਛੱਡ ਦਿੰਦਾ ਹੈ; ਮਿਊਜ਼ ਅੱਪਸਟ੍ਰੀਮ ਅਸਫਲਤਾਵਾਂ ਦੂਜੇ ਪ੍ਰਦਾਤਾਵਾਂ ਵਾਂਗ ਕੂਲਡਾਊਨ ਅਤੇ ਬ੍ਰੇਕਰ ਸਟੇਟ ਨੂੰ ਰਿਕਾਰਡ ਕਰਦੀਆਂ ਹਨ। ਇੱਕ ਸਪੱਸ਼ਟ ਤੌਰ 'ਤੇ ਜ਼ਬਰਦਸਤੀ ਕਨੈਕਸ਼ਨ ਇੱਕ ਨਵੇਂ ਸੈਸ਼ਨ ਲਈ ਰਾਊਂਡ-ਰੋਬਿਨ ਨੂੰ ਬਾਈਪਾਸ ਕਰਦਾ ਹੈ ਪਰ ਮੌਜੂਦਾ ਮਾਲਕ ਨੂੰ ਓਵਰਰਾਈਡ ਨਹੀਂ ਕਰ ਸਕਦਾ ਹੈ।
- ਜਦੋਂ ਤੱਕ ਮਾਲਕ ਇੱਕ ਸਫਲ ਜਵਾਬ ਨਹੀਂ ਦਿੰਦਾ, ਇੱਕ ਸੈਸ਼ਨ ਜਿਸਦਾ ਮਾਲਕ ਅਣਉਪਲਬਧ ਹੋ ਗਿਆ ਹੈ, ਇੱਕ ਸਿਹਤਮੰਦ ਖਾਤੇ ਵਿੱਚ ਦੁਬਾਰਾ ਦਾਅਵਾ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਪਹਿਲੇ ਸਫਲ ਜਵਾਬ ਤੋਂ ਬਾਅਦ, ਸੈਸ਼ਨ ਉਦੋਂ ਤੱਕ ਉਸ ਮਾਲਕ ਨੂੰ ਪਿੰਨ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਜਦੋਂ ਤੱਕ ਇਹ 30 ਦਿਨਾਂ (`MUSE_SESSION_IDLE_TTL_MS`) ਲਈ ਨਿਸ਼ਕਿਰਿਆ ਨਹੀਂ ਹੁੰਦਾ।
- ਹਰ ਨਿਰੰਤਰਤਾ ਅਤੇ ਟੂਲ-ਨਤੀਜਿਆਂ ਦੀ ਵਾਰੀ ਸੈਸ਼ਨ ਦੇ ਮਾਲਕ ਨੂੰ ਪਿੰਨ ਕੀਤੀ ਜਾਂਦੀ ਹੈ: ਕਨੈਕਸ਼ਨ, ਖਾਤਾ ਪਛਾਣ, ਅਤੇ ਅਨੁਮਾਨ-ਪ੍ਰਮਾਣ-ਪੱਤਰ ਜਨਰੇਸ਼ਨ, ਅੱਪਸਟ੍ਰੀਮ ਕੋਸ਼ਿਸ਼ਾਂ ਤੋਂ ਪਹਿਲਾਂ ਦੁਬਾਰਾ ਜਾਂਚ ਕੀਤੀ ਜਾਂਦੀ ਹੈ, ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ-ਰਿਫਰੈਸ਼ ਮੁੜ ਕੋਸ਼ਿਸ਼ਾਂ ਸਮੇਤ। ਜਵਾਬ ਕਾਲ IDs/item ਹਵਾਲੇ ਅਤੇ ਚੈਟ ਸੰਪੂਰਨਤਾ ਟੂਲ-ਕਾਲ IDs ਉਸ ਸੈਸ਼ਨ ਅਤੇ ਪੀੜ੍ਹੀ ਲਈ ਰਿਕਾਰਡ ਕੀਤੇ ਗਏ ਹੋਣੇ ਚਾਹੀਦੇ ਹਨ।
- `muse_session_ownership` ਨੇਮਸਪੇਸ (`src/lib/db/museSessionOwnership.ts`) ਵਿੱਚ SQLite `key_value` ਰਿਕਾਰਡ ਮਾਲਕੀ ਅਤੇ ਰੋਟੇਸ਼ਨ ਕਰਸਰ ਨੂੰ ਮੁੜ-ਚਾਲੂ ਕਰਦੇ ਹਨ। ਹਰੇਕ ਦਾਅਵਾ ਅਤੇ ਪੇਸ਼ ਕੀਤਾ ਜਵਾਬ ਸੈਸ਼ਨ ਦੀ ਗਤੀਵਿਧੀ ਸਟੈਂਪ ਨੂੰ ਤਾਜ਼ਾ ਕਰਦਾ ਹੈ; `MUSE_SESSION_IDLE_TTL_MS` ਤੋਂ ਲੰਬੇ ਸਮੇਂ ਲਈ ਨਿਸ਼ਕਿਰਿਆ ਸੈਸ਼ਨ ਨੂੰ ਕੱਟਿਆ ਜਾਂਦਾ ਹੈ (ਮਾਲਕ ਪਿੰਨ, ਸਰਵਡ ਫਲੈਗ ਅਤੇ ਰਿਕਾਰਡ ਕੀਤੇ opaque/reference ਹੈਸ਼), ਵੱਧ ਤੋਂ ਵੱਧ ਹਰ 10 ਮਿੰਟਾਂ ਵਿੱਚ ਇੱਕ ਵਾਰ ਅਤੇ ਸੀਮਾਬੱਧ ਬੈਚਾਂ ਵਿੱਚ, ਇਸਲਈ ਇਸਦੇ ਇਤਿਹਾਸ ਦੀ ਇੱਕ ਬਾਅਦ ਵਿੱਚ ਰੀਪਲੇਅ ਇੱਕ ਅਣਜਾਣ ਮਾਲਕ ਵਜੋਂ ਬੰਦ ਹੋ ਜਾਂਦੀ ਹੈ। ਰਿਕਾਰਡਾਂ ਵਿੱਚ ਕਨੈਕਸ਼ਨ IDs ਅਤੇ ਖਾਤੇ ਦੀ ਪਛਾਣ, ਪ੍ਰਮਾਣ ਪੱਤਰ, ਅਪਾਰਦਰਸ਼ੀ ਸਮੱਗਰੀ, ਅਤੇ ਨਿਰੰਤਰਤਾ ਦੇ ਹਵਾਲੇ ਸ਼ਾਮਲ ਹੁੰਦੇ ਹਨ, ਨਾ ਕਿ ਭੇਦ ਜਾਂ ਗੱਲਬਾਤ ਇਤਿਹਾਸ। ਗਾਹਕਾਂ ਨੂੰ ਆਪਣਾ ਪੂਰਾ ਇਤਿਹਾਸ ਅਤੇ ਅਪਾਰਦਰਸ਼ੀ ਤਰਕ ਬਰਕਰਾਰ ਰੱਖਣਾ ਅਤੇ ਭੇਜਣਾ ਚਾਹੀਦਾ ਹੈ।
- ਅਣਜਾਣ ਜਾਂ ਵਿਦੇਸ਼ੀ ਅਪਾਰਦਰਸ਼ੀ ਤਰਕ, ਇੱਕ ਗੁੰਮ ਮਾਲਕ, ਇੱਕ ਅਣਉਪਲਬਧ ਮਾਲਕ ਖਾਤਾ, ਜਾਂ ਰਿਕਾਰਡ ਕੀਤੇ ਇਤਿਹਾਸ ਦੇ ਨਾਲ ਇੱਕ ਪੀੜ੍ਹੀ ਦੀ ਤਬਦੀਲੀ ਇੱਕ ਸਪੱਸ਼ਟ 4xx/503 — ਨਾਲ ਬੰਦ ਹੋ ਜਾਂਦੀ ਹੈ, ਕਦੇ ਵੀ ਚੁੱਪ ਕਰਾਸ-ਖਾਤਾ ਫੇਲਓਵਰ ਅਤੇ ਕਦੇ ਵੀ ਤਰਕ ਨਹੀਂ ਛੱਡਿਆ ਜਾਂਦਾ ਹੈ।
- ਇੱਕ ਰੀਮੇਂਟ ਕੀਤੀ ਸਮਾਨ-ਅਕਾਊਂਟ ਕੁੰਜੀ ਨੂੰ ਉਦੋਂ ਹੀ ਅਪਣਾਇਆ ਜਾਂਦਾ ਹੈ ਜਦੋਂ ਸੈਸ਼ਨ ਵਿੱਚ ਕੋਈ ਮੁੜ ਚਲਾਉਣਯੋਗ ਇਤਿਹਾਸ ਦਰਜ ਨਹੀਂ ਹੁੰਦਾ; ਰਿਕਾਰਡ ਕੀਤੇ ਸੈਸ਼ਨ ਤਾਜ਼ਾ ਸ਼ੁਰੂ ਹੋਣ ਤੱਕ ਬੰਦ ਹੁੰਦੇ ਰਹਿੰਦੇ ਹਨ।
- ਇੱਕ ਖਾਲੀ ਅੱਪਸਟ੍ਰੀਮ ਜਵਾਬ (`upstream_empty_response` / `empty_response`, ਕਾਲਰ ਨੂੰ ਕੁਝ ਵੀ ਨਹੀਂ ਛੱਡਿਆ ਗਿਆ) ਇੱਕੋ ਮਾਲਕ 'ਤੇ ਵੱਧ ਤੋਂ ਵੱਧ ਦੋ ਵਾਰ ਮੁੜ ਕੋਸ਼ਿਸ਼ ਕੀਤੀ ਜਾਂਦੀ ਹੈ, 0.5 s ਤੋਂ ਬਾਅਦ 1.5 s (`MUSE_EMPTY_RESPONSE_RETRY_DELAYS_MS`)। ਜੇਕਰ ਸਾਰੀਆਂ ਕੋਸ਼ਿਸ਼ਾਂ ਖਾਲੀ ਹਨ, ਤਾਂ ਅਸਲੀ 502 ਬਿਨਾਂ ਕੂਲਡਾਊਨ ਜਾਂ ਬ੍ਰੇਕਰ ਮਾਰਕਿੰਗ ਦੇ ਵਾਪਸ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ, ਇਸਲਈ ਇੱਕ ਅਸਪਸ਼ਟ ਜਵਾਬ ਕਦੇ ਵੀ ਮਾਲਕ ਨੂੰ ਲਾਕ ਨਹੀਂ ਕਰਦਾ।
- ਸਾਰੀਆਂ `muse-code` ਬੇਨਤੀਆਂ ਸਿਮੈਂਟਿਕ-ਕੈਸ਼ ਰੀਡ ਅਤੇ ਰਾਈਟਸ ਨੂੰ ਬਾਈਪਾਸ ਕਰਦੀਆਂ ਹਨ, ਜਿਸ ਵਿੱਚ ਸਟ੍ਰੀਮਿੰਗ ਰਾਈਟਸ ਸ਼ਾਮਲ ਹਨ, ਇਸਲਈ ਕੈਚਡ ਅਪਾਰਦਰਸ਼ੀ ਆਉਟਪੁੱਟ ਇੱਕ ਵੱਖਰੇ ਸੈਸ਼ਨ ਦੇ ਮਾਲਕ ਨੂੰ ਪ੍ਰਾਪਤ ਨਹੀਂ ਕਰ ਸਕਦੀ।
