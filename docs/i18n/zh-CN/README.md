> **带上您自己的提供者帐户。**这些是第三方免费套餐，而不是OmniRoute授予的代币。注册，根据提供者的要求获取凭据，然后连接您可以使用的凭据。每个提供者都有自己的限制、可用性和条款。
>
> 手动堆叠免费套餐意味着数十个SDKs、数十个速率限制，并且不清楚您还剩下什么。 OmniRoute保留 214 个可自由访问的目录行，并从 12 个具有已发布配额的池中计算实际数字，每个共享池计数一次。仅在区域身份验证（今天为ModelScope）后开放的配额被分开显示， +~落后于区域身份验证 6M，并且从未添加到实际数字中。剩下的内容显示在仪表板上（`/dashboard/free-tiers`）。

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
```

## 组合：旗舰

1. **从`auto`开始。**在兼容 OpenAI 的客户端中设置模型。 OmniRoute通过互联的提供者构建虚拟组合，并对候选人进行实时评分。
2. **保存组合以获得更多控制。**选择名称、目标列表和策略，然后使用该名称作为模型。该策略规定了首先执行哪个目标以及如何尝试其余目标。

组合会自动跨模型路由。当配额耗尽、提供者失败或模型锁定时，它会尝试下一个合格的、健康的目标。

### 零配置：只需使用`auto`

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

变体调整权重。最后已知的良好路由保留在最后一个成功的提供者处，直到它失败，然后重新评分。 `auto/fast`和`auto/cheap`表达偏好，但不保证最快或最便宜的型号。

| 型号ID              | 行为                                                                                                                                                                           |
| :------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | 平衡默认权重。                                                                                                                                                                 |
| `auto/fast`         | 有利于低延迟和提供者健康。                                                                                                                                                     |
| `auto/cheap`        | 有利于降低目录价格。                                                                                                                                                           |
| `auto/coding`       | 代码生成的质量优先权重。                                                                                                                                                       |
| `auto/smart`        | 质量优先权重，探索率为 10%（默认为 5%）。                                                                                                                                      |
| `auto/lkgp`         | 具有与`auto`相同权重的显式最后已知良好路由。                                                                                                                                   |
| `auto/subscription` | 仅使用实时验证的计划配额。当没有可用时返回HTTP 503，并避免计费回退。                                                                                                           |
| `auto/thrifty`      | 计划→无钥匙→免费→便宜→高级。当配额和冷却时间允许时，可能会达到计费模型并返回到计划。                                                                                           |
| `auto/offline`      | 有利于配额和速率限制空间。请求仍会发送给您的提供者。                                                                                                                           |
| `auto/chaos`        | 每个提供者并行一个模型，默认情况下最多五个，配置后最多十个。每个模型一次上游调用。如果顶级模型失败，则返回排名最高的回复或最后一个成功的面板回复。使用`fusion`与法官合成回复。 |

类别和可选层示例包括`auto/coding:fast`、 `auto/coding:free`、 `auto/reasoning:pro`和`auto/vision`。如果没有连接的候选者匹配，则请求返回HTTP 503 并且池保持狭窄。[自动组合指南](./docs/routing/AUTO-COMBO.md)·[订阅优先路由](./docs/routing/SUBSCRIPTION_LADDER.md)

### 或者构建您自己的：22 种路由策略

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

CLI接受 22 种策略中的 15 种。仪表板和组合API接受全部 22 个。

| 战略                | 行为                                                                                                                                        |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`              | 使用 16 因素自动组合评分器对候选人进行排名。                                                                                                |
| `cache-optimized`   | 首选可能在缓存中保存提示前缀的帐户。                                                                                                        |
| `context-optimized` | 首先尝试最大的已知上下文窗口。                                                                                                              |
| `context-relay`     | 切换帐户时保留您的订单并传递对话摘要。                                                                                                      |
| `cost-optimized`    | 按目录输入代币价格排序，未知的最后。最终请求成本可能有所不同。                                                                              |
| `expiry-first`      | 支出配额可能会过期，每小时最高剩余金额，直到首先重置。                                                                                      |
| `fill-first`        | 停留在第一个可用目标上，直到它耗尽或失败，然后继续前进。                                                                                    |
| `fusion`            | 并行询问小组并让法官综合一个答案。                                                                                                          |
| `headroom`          | 在 5 小时和每周窗口中选择最多的可用容量。                                                                                                   |

### 弹性内置：3 个独立层

故障在三个范围内进行处理，因此一种错误的模型不会导致其帐户关闭，而一种错误的帐户也不会导致其提供者关闭。

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### 如果整个提供者宕机

这**供应商断路器**在 8 (OAuth) 或 12 (API key) 次失败后打开，状态为 408、500、502、503 或 504。组合在打开时跳过该提供程序。 60秒或30秒后，一次探测请求决定是否关闭。

#### 如果一个密钥或一个帐户受到速率限制

这**连接冷却时间**仅对那个连接进行测试，从 5 s (OAuth) 或 3 s (API key) 开始进行指数退避。同一提供者的其他密钥继续提供服务。

#### 如果某一型号被拒绝

这**模型锁定**在每个模型出现 429、404 或访问拒绝后，仅阻止该连接上的该模型。同一连接上的其他模型继续提供服务。

被禁止、过期和信用不足的连接是终止状态，而不是冷却时间：它们等待您修复它们。

## 完整的CLI, MCP和A2A

> OmniRoute提供了一个命令行客户端**91个顶级命令和命令组**（754 个命令计算子命令）**MCP服务器具有 110 个工具和 33 个范围**，和一个**A2A代理有6个技能**。脚本、终端和AI代理都可以操作同一个网关。

### 真正的CLI，而不仅仅是`start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

全局`--output table|json|jsonl|csv`标志使脚本和CI可以使用相同的命令。

### 远程模式： CLI在您的笔记本电脑上， OmniRoute在服务器上

登录远程服务器一次。 CLI将其保存为**语境**，稍后的命令会针对该服务器运行，直到您切换回来。

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| 代币范围 | <img width="2000" height="0" alt="">它允许什么 |
| -------- | ---------------------------------------------- |
| `read`   | 列出并检查：模型、状态、日志、使用情况         |
| `write`  | `read` plus 配置和应用：客户端设置、密钥、配置 |
| `admin`  | `write` plus 管理：代币、提供者、服务、策略    |

裸主机获取`http://`和端口 20128；当服务器位于TLS后面时，传递完整的`https://` URL 。无论令牌是什么，可以生成进程的路由都保持仅环回。

### 连接代理

代理或您自己的代码可以通过任何这些接口驱动路由、提供程序、组合、缓存、压缩和内存。 HTTP路径由网关提供服务，默认为`http://localhost:20128`。

| 界面                    | 端点或命令                 | 用它来                                                         |
| ----------------------- | -------------------------- | -------------------------------------------------------------- |
| MCP通过 stdio           | `omniroute --mcp`          | Claude Desktop、 Cursor和其他本地MCP客户端                     |
| MCP优于 Streamable HTTP | `/api/mcp/stream`          | 远程MCP客户端：110 个工具，33 个范围，每次调用都会写入审核日志 |
| MCP优于SSE              | `/api/mcp/sse`             | 仍然使用SSE传输的客户端                                        |
| A2A发现                 | `/.well-known/agent.json`  | 代理卡：告诉其他代理OmniRoute可以做什么                        |
| A2A执行                 | `POST /a2a`                | JSON-RPC 2.0 任务，通过SSE同步或流式传输，涵盖 6 种技能        |
| REST API                | `/v1/*`                    | 兼容 OpenAI 的聊天、响应、嵌入、图像、音频和OCR                |
| 网络钩子                | `/api/webhooks`            | 发送至Slack、 Discord、 Telegram或任何具有HMAC签名的URL的事件  |
| 远程CLI                 | `omniroute connect <host>` | 使用范围访问令牌驱动远程实例                                   |

A2A六种技能是`smart-routing`、 `quota-management`、 `provider-discovery`、 `cost-analysis`、 `health-report`和`list-capabilities`。

**连接之前：**

- **MCP over HTTP开始禁用。**使用`omniroute mcp enable --transport streamable-http`或从仪表板的端点页面将其打开。一次有一个HTTP传输处于活动状态： `streamable-http`服务`/api/mcp/stream`， `sse`服务`/api/mcp/sse`。
- **A2A启动时被禁用。**在仪表板的端点页面上启用它。然后`POST /a2a`遵循与`/v1`相同的 API 密钥规则。
- **远程MCP需要合适的密钥。** `/api/mcp/*`默认只应答环回。从另一台主机，使用`manage`或`admin` （所有工具）或使用`mcp:connect`加上您需要的工具的范围发送密钥。对于没有`manage`/`admin`的键，始终强制执行工具范围。

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

默认堆叠组合运行`RTK → Caveman`。当两者作用于相同的tool/context有效负载时，节省的成本会增加：

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

代码块、 URLs、 JSON和结构化数据是**始终受到保护**由保存引擎。

> **当很少的令牌就可以达到目的时，为什么要使用很多令牌呢？**每个请求都会经过OmniRoute的压缩管道**透明地**—没有客户端变化。现在是一个**12 个可组合引擎的堆栈**按顺序运行，并根据路由组合—进行混合和匹配，该组合基于[RTK](https://github.com/rtk-ai/rtk) 、 [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +)、 [LLMLingua-2](https://github.com/microsoft/LLMLingua)和[Troglodita](https://github.com/leninejunior/troglodita) (PT-BR) 的想法。

**实例—标准模式：**

## 更多安装方法— Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest`遵循最高**发表**稳定SemVer。它不跟踪 git `main`。将`:X.Y.Z`固定为GitOps。请参阅[Docker发布通道](docs/guides/DOCKER_GUIDE.md#release-channels)。图像引脚**`OMNIROUTE_MEMORY_MB=1024`** 。对于仪表板和简单的聊天来说这已经足够了。**编码剂**（来自Claude代码的`POST /v1/responses` 、 Codex、 Grok等）需要更大的 V8 堆或两个重叠的长上下文下~ 12 GiB处的进程`FATAL ERROR`。调整堆上方容器的大小（本机缓冲区位于 V8 外部）：

| <img width="2000" height="0" alt="">工作负载 | 堆（`-e OMNIROUTE_MEMORY_MB`） | 集装箱（`--memory`） |
| -------------------------------------------- | ------------------------------ | -------------------- |
| 仪表板/轻聊                                  | `1024` （图片默认）            | ≥ 2克                |
| 编码剂一名                                   | `8192`                         | ≥ 10 克              |
| 两个并发长`/v1/responses`                    | `10240`–`12288`                | ≥ 12–16 克           |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

完整表格： [Docker指南—运行时RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents) 。

**⚡更快/更精简的安装（跳过本机构建）**

本机SQLite引擎 (`better-sqlite3`) 是一个**选修的**依赖性，因此全局安装永远不会阻止从源代码进行编译：当与您的platform/Node匹配时，它会使用预构建的二进制文件，否则会透明地回退到纯 JS 引擎（节点 22 上的`node:sqlite` +，否则捆绑的`sql.js` WASM） —不需要构建工具。

跳过安装后**本机热身**完全（CI、无头或慢速机器）。注意：这只会跳过本机SQLite预热步骤 (`scripts/postinstall.mjs`)； binary-copy/repair hook (`scripts/build/postinstall.mjs`) 仍然正常运行：

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

对于最快的安装更喜欢**PNPM** （内容寻址存储+硬链接—见上文）。对于无仪表板、无头运行时，请使用Docker `base`配置文件（上面）或[Termux 指南](docs/guides/TERMUX_GUIDE.md)。 CLI和 Web 仪表板在一个端口上由同一进程提供服务，因此目前没有单独的仅 CLI 软件包。

  <tr><td nowrap><b>协议</b></td><td>MCP (stdio / SSE / Streamable HTTP, 110 工具) + A2A v0.3 (JSON-RPC 2.0 + SSE) 与A2A v1.0 客户端兼容性</td></tr>
  <tr><td nowrap><b>流媒体</b></td><td>服务器发送的事件 (SSE) + WebSocket桥 (<code>/v1/ws</code>)</td></tr>

### 如何贡献

1. 分叉存储库
2. 分支来自**积极的**`release/vX.Y.Z`提示（不是`main`） —请参阅[分支和发布模型](docs/ops/BRANCHING_MODEL.md)
3. 创建您的功能分支（`git checkout -b feat/amazing-feature`）
4. 提交您的更改 (`git commit -m 'feat: add amazing feature'`)
5. 推送到分支（`git push origin feat/amazing-feature`）
6. 打开拉取请求**基础=即`release/vX.Y.Z`分支**

请参阅[CONTRIBUTING.md](CONTRIBUTING.md)了解详细指南。

```bash
# Create a release — npm publish happens automatically
VERSION=x.y.z
gh release create "v${VERSION}" --title "v${VERSION}" --generate-notes
```
