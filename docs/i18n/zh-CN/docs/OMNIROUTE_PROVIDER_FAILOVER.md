在做出重试决定之前对失败进行分类。

暂时性故障（例如超时、网络错误、速率限制和提供者 5xx 响应）可能会进行故障转移。耗尽的配额或信用（配额 429 或 402 要求付款）永远不会在同一提供者上重试，但会故障转移到另一提供者，其配额是单独的。认证错误、权限错误、无效请求、不可用模型、未知失败等情况不会盲目重试。

默认的跨提供者策略允许最多 3 次提供者尝试、重试速率限制和超时、配额耗尽时的故障转移，以及将管理禁用与临时电路状态分开。

## 适用地点

- **组合**根据组合自己的策略和设置在目标之间进行故障转移。
- **裸模型 ID** （无`provider/`前缀）多个活动提供者提供的服务，没有该确切名称的组合，首先发送到提供者推理选择。如果该尝试以策略故障转移的方式失败，则相同的请求将发送到提供该 ID 的下一个活动提供程序。该响应携带`x-omniroute-fallback-attempts`以及在应答之前尝试过的提供者数量。
  - 每个候补都被完全授权，就像推理选择了它一样。 API键阻止或不承认的目标将在没有上游调用的情况下被跳过，并且客户端会收到真正的上游错误，而不是对其从未命名的目标的策略拒绝。
  - 只有失败的响应才会继续：在第一个流传输的字节之后没有任何故障转移。
  - 紧急后备模型交换仅在所请求模型的每个提供者都失败后才适用。
  - 固定到连接 (`x-omniroute-connection`) 的请求将保留在该连接上。
  - 带前缀的 id (`provider/model`) 永远不会重新路由到另一个提供者。

电路状态为`closed`、 `open`和`half_open`。冷却时间安排有界探针；成功的探头会关闭电路，失败的探头会重新打开电路。
