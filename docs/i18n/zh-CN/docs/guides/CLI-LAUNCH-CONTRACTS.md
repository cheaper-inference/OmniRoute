中立的`config/cli-tools-manifest.json`合约声明规范的IDs、别名、二进制候选、设置配方、模型参数和功能。 `bin/cli/cli-manifest.mjs`中的普通 Node 适配器和`src/shared/constants/cliIntegrationManifest.ts`中的TypeScript适配器读取相同的文件。运行时、目录、配置、完成、生成器和后端注册由`tests/unit/cli/cli-manifest-drift.test.ts`一起检查。编目并不意味着可以启动或配置工具。特别是，5dive 仍然仅可配置。

## 儿童环境和生命周期

`omniroute run`、 `omniroute launch`和`omniroute launch-codex`继承OS/terminal兼容性白名单并注入所选目标的凭据。默认情况下，不继承不相关的提供程序和数据库机密。 `--inherit-env`显式恢复完整的父环境继承；仅当选定的第三方进程应接收这些值时才使用它。这是环境过滤，而不是OS沙箱：进程仍然以调用者的文件系统权限运行。

中断和终止信号被转发给子进程。启动器在删除临时配置之前等待子进程的关闭事件。 `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS`控制强制终止之前的宽限期（默认5000毫秒）。

`omniroute launch <tool>` （参见[LAUNCH.md](./LAUNCH.md) ）遵循相同的环境规则和信号转发，并添加：

- **网关自动启动。**对于本地目标，当端口上没有网关应答时，启动器会在分离的收割者进程下启动绑定到`127.0.0.1`的`omniroute serve --headless --no-open` 。每个正在运行的启动都在`DATA_DIR/launch/leases/`中持有租约（每 15 秒检测一次，45 秒后或其进程消失时失效）。一旦在空闲宽限期内没有任何租约存在，收割机就会停止它启动的网关（`OMNIROUTE_LAUNCH_IDLE_GRACE_MS`，默认 10000 毫秒）。用户启动的网关已被使用但从未停止。 `--keep-gateway`或`omniroute gateway keep`将启动器网关变成普通网关； `--no-start`恢复旧的“fail-if-down”行为。仅探测远程目标。
- **启动会议。**每次启动都会从父凭证 (`POST /api/launch/sessions`) 中创建一个短期的`olx_`会话令牌，在工具运行时对其进行检测，读取使用情况摘要并在工具退出后撤销它。该令牌是其父代令牌的严格子集：相同的权限、相同或更窄的目录、较短的生命周期，并且它不是仪表板凭证。该工具接收会话令牌，而不是父凭据，并且除非给出`--tag` ，否则请求将被标记为`launch:<tool>:<sessionId>` 。没有会话API网关会因`GatewayTooOld`失败，而不是回退到无范围启动。
- **每次启动配置。**工具配置文件被写入私有临时目录（模式 0700，前缀`omnirouter-`）并在子进程退出后删除。启动器的`SIGKILL`会留下目录；一旦此类目录超过一天， `omniroute launch --cleanup`就会将其删除。

## Gemini持久设置

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

前两个命令为选定的本地或远程服务器配置此计算机。安装程序保留不相关的JSON设置，选择Gemini API 密钥身份验证，并将端点和凭证写入私有`.gemini/.env`文件。它拒绝无效的JSON而不是覆盖它。端点URLs必须是HTTP(S)，没有嵌入的凭据、查询参数或片段。试运行打印路径，而不是凭证值。

`GEMINI_CLI_HOME`或`--gemini-home`选择持久主根。实际的`run gemini`创建并随后删除其自己的临时家。这两种模式都不会绕过Gemini的工作区信任检查。

## Codex简介

`configure codex`使用模型及其OmniRoute提供者端点编写私有`<name>.config.toml` 。凭证通过`OMNIROUTE_API_KEY`引用，从不嵌入。 launch 命令在顶级`model`键设置所选模型，而不是在`model_providers`内。

单独的配置文件是当前记录的Codex合约；当使用`codex --profile <name>`选择时，它们会覆盖用户配置。请参阅[官方配置文件参考](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles)和[OmniRoute Codex指南](./CODEX-CLI-CONFIGURATION.md)。

## 密封命令执行

通过显式`DATA_DIR`，设置`OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1`可防止启动时陷入默认用户数据目录的凭据环境。这对于孤立测试很有用。它不会禁用其他明确选择的环境文件。

## 工作目录`.env`

CLI按此顺序读取`.env`文件，第一个设置密钥的文件获胜：显式`DATA_DIR`、默认数据目录、当前工作目录，然后是包目录。 shell 变量总是获胜。

工作目录可能属于其他人（克隆的存储库、解压的存档），并且`omniroute serve`将CLI环境传递到服务器以及服务器运行的每个工具。因此`.env`可能只设置`bin/cli/utils/untrustedCwdEnv.mjs`中列出的这些键：

| 钥匙                            | 接受的值                                                 |
| ------------------------------- | -------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`、 `1`或`yes`在任何情况下，服务器视为 on 的值      |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 最多 64 个字母、数字、 `_`、 `.`、 `@`或`-`              |
| `LANGUAGE`                      | 一样，加上`:`                                            |
| `TZ`                            | 最多 64 个字母、数字、 `_`、 `+`、 `-`或`/`，不以`/`开头 |
| `NO_COLOR`, `FORCE_COLOR`       | 最多 16 个字母和数字                                     |

`REQUIRE_API_KEY`接受的每个值都会打开检查，因此文件无法自行关闭检查。但它并不决定结果：服务器在环境之前读取存储在数据库中的`REQUIRE_API_KEY`覆盖，而有关在没有API密钥的情况下侦听所有接口的启动警告仅读取环境。通过存储的`false`覆盖，工作目录`REQUIRE_API_KEY=true`使API保持打开状态并隐藏该警告。 `TZ`规则比POSIX更窄：它拒绝`.`、 `:`、 `,`和`<>`，因此必须在 shell 或`<DATA_DIR>/.env`中设置`:Area/City`形式和`EST5EDT,M3.2.0,M11.1.0`等规则。

名称必须完全匹配（大写）。任何其他行、检查失败的值以及不是普通ASCII字母、数字和`_`的名称（例如带有NUL字节或相似字母的名称）都会被跳过。 CLI打印一个警告，其中命名了它无法设置的键，并打印了一个警告，命名了它忽略的允许键，每个警告都包含要更改的内容（`TZ (expected a zone name such as Europe/Berlin)`、 `lang (write the name as LANG)`）。都不打印值。这些消息中的文件路径以及`omniroute doctor`报告的`.env`路径在包含控制字符或 bidi 字符时会被转义。当工作目录是数据目录或包目录时，此限制不适用。

`PORT`、 `API_PORT`和`DASHBOARD_PORT`不在列表中。如果没有来自更高优先级源的基本URL ， CLI会与`localhost:<PORT>`进行对话，并且无论在那里侦听的内容都会接收CLI的API密钥、上下文令牌和CLI机器令牌（`x-omniroute-cli-token`，请参阅[CLI_TOKEN.md](../security/CLI_TOKEN.md) ），本地服务器接受来自环回的管理调用。工作目录中的端口将允许该文件选择侦听器，因此请在 shell、 `<DATA_DIR>/.env`中或使用具有端口（`serve`、 `launch`、 `run`）的命令的`--port`选项设置端口。

解析器没有`export`语法。诸如`export LD_PRELOAD=...`之类的行将变量命名为`export LD_PRELOAD`；从工作目录中它会被跳过，并且在其他`.env`文件中它会设置该文字名称，但不会读取任何内容。

CLI仅将上下文的存储令牌（访问令牌或旧API密钥）与该上下文自己的来源：方案、主机和端口配对，与`URL.origin`相比。这适用于通过CLI的HTTP客户端（`--base-url`、 `OMNIROUTE_BASE_URL`、 `omniroute connect <new-url>`）发出的请求以及将基本URL和密钥写入另一个工具配置的`launch`、 `launch codex`、 `configure`和`setup-*`命令。使用`--remote`指向另一台服务器，它们使用显式`--api-key`或`OMNIROUTE_API_KEY`如果设置了），并且没有上下文令牌。比较是精确的，因此`localhost`和`127.0.0.1`，或者带有或不带有尾随点的主机，算作不同的服务器并且不会获得上下文令牌。带有 userinfo、反斜杠或空格的URL永远不会匹配，因为其他URL解析器（例如 Python 的`urllib`和`httpx`）可以从中读取不同的主机。对于CLI自身发送的请求，该检查仅涵盖方案和权限，因此路径或查询中带有空格的 id 会保留令牌。
