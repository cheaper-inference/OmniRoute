## 2026-10-18 SiliconFlow 免费模型更正（#17028）

十个已公布正数每 token 价格的 SiliconFlow 旗舰模型被错误地作为 `recurring-uncapped` 免费访问发布。这十行现已从静态目录中**移除**，该目录目前共有 **467 个条目**。SiliconFlow 不再为静态总数贡献无条件免费模型条目，也不再计为永久免费的提供者。

这**并不**意味着 SiliconFlow 没有免费模型。仅限免费模型的导入和“Free”徽章现在要求从实时提供者模型载荷中获得**明确的按模型证据**，例如显式的免费布尔标记，或输入和输出 token 价格均为零。显式的付费标志或任何正数价格均优先于乐观的免费标记。对于没有可用实时证据的模型，**不会**假定其免费；新账户的一次性额度不能证明存在周期性免费配额。如果当前提供者 API 无法提供可靠的模型级定价，请在路由之前通过提供者控制台进行确认。这一保守选择可防止仅限免费模型的导入和自动组合产生意外费用。

下方的历史提供者表格并非对实时可用性的承诺。该表格原先的 SiliconFlow 无上限／10 模型条目已被有意移除，因为它已不再代表已确认的周期性免费配额。

## 两种机制——统计与判定

OmniRoute 通过两种有意读取不同来源的机制来回答“它是否免费？”：

| 机制          | 事实来源                                                                                                                                                 | 适用界面                                                                                              |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **统计/显示** | 解析后的目录——已发布的基线目录叠加 Radar 数据源（`getRadarCatalog`）                                                                                     | 免费层总量、预算卡片、仪表板                                                                          |
| **判定**      | 仅使用已发布的目录（`open-sse/config/freeModelCatalog.data.ts` 中的 `FREE_MODEL_BUDGETS`）以及本地启发式规则（`:free` 后缀、零定价、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` 的所有使用方：模型导入、`auto/*` 路由、`GET /v1/models` 和浏览器预览 |

只要数据源可用，统计结果就可以得到改进。判定则始终基于发布制品，因此浏览器和服务器给出的答案完全一致，可离线复现，也可以在没有数据库的情况下进行测试。如果让浏览器预览读取一个来源，而服务器导入读取另一个来源，就会导致预览结果与点击后实际发生的情况不一致——这种拆分是有意保留的。

## 方法论与注意事项

- 数字是根据各提供者截至 **2026-06-17** 所记录的免费层限制，通过网络调研得出的**上限估算值**。免费层会持续变化——在依赖某个数字之前，请重新核实。
- **一条记录实际能保证什么。** 没有任何记录带有逐行置信度评级，API 也不提供此类信息——请将上面的每个数字都视为质量相同且未明确说明的估算值。以下两项事实有所不同，因为它们是人工整理的，而不是推断得出的：44 条记录带有独立记录的硬性停止限制（其中 39 条是 xKiro 行，它们共享一个每日额度），22 条记录带有提示词训练披露。仅当提供者自身的条款说明超出免费额度会拒绝请求，而不是静默开始向你收费时，才会设置 `hardStopGuaranteed`；来源会写在该条记录旁的注释中；它绝不会默认设置为 `true`，而未有人验证的记录会保持未设置。因此，缺少硬性停止标志意味着“尚未确定”，而不是“已知会向你收费”。**严格模式**（可选的 `freeAccessPolicy=strict` 路由保护）只信任带有该标志的记录；其他所有免费层都会被排除，并标记为 `no-hard-stop`（参见 `open-sse/services/autoCombo/strictZeroCostFilter.ts`）。当保护机制过滤资源池时，面向运营人员的日志会同时报告排除数量及其 `no-hard-stop` 占比。
- `estMonthlyFreeTokens` = 仅计算每月重复获得的 token。**一次性注册赠金不会重复获得**，按 0 计算。已停止提供的层级也按 0 计算。
- 每日 token 上限 → `monthly = daily × 30`。仅记录 RPD → `RPD × ~800 output tokens × 30`。仅记录 RPM/TPM（无每日上限）→ **不设上限**（见下文）。
- **可以免费访问，但未公布 token 上限**（`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`nvidia`）：这些服务受速率/并发限制。我们将其归类为 `recurring-uncapped`，并且**绝不将其相加**——将 `RPM × 24/7 × 30d` 相乘会得到一个虚构的上限（这正是我们拒绝的夸大方式）。NVIDIA 的 API 仅供试用；请参阅下方关于其 ToS 的注意事项。
- **充值解锁增益：**一次性小额充值可永久提高免费额度（OpenRouter：$10 → 每天 1000 个请求 ≈ 每月增加 24M）。该数值单独报告，不计入稳定状态的主要数字。
- **受资格条件限制的额度**（`eligibilityGate: "regional-identity"`）：只有在完成与地区绑定的身份核验后才会开放的真实重复额度（目前为中国大陆实名认证）。按照相同的资源池去重规则计入单独的数字（`gatedRecurringTokens`），绝不计入稳定状态的主要数字。运行机制（`freeType`）保持不变，因此路由也不变。
- **证据类别。**规则如下：目录中的数字必须在记录旁的 `// evidence:` 注释中注明来源——`public-page`（任何人都能阅读的提供者页面）、`api-public`（提供者的无需身份验证的端点，例如位于 router.bynara.id 的 NaraRouter 公共套餐端点），或 `console-verified <date> por <who>`（该数字只能在账户控制台内看到；注释记录查看者及查看时间，以及说明该上限存在的公共页面）。当前状态：在 2026-09-02 重新审核的五个区块带有该注释（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）；早于 2026-09-02 重新审核的记录会沿用之前的调研结果，直到被修改；任何**新增或变更**但没有证据注释的数字都是错误。目前只有 `mistral` 经过控制台验证。

## 为什么我们的数字小于其他聚合器的数字

在这一领域，大多数“每月免费 token”数字都是各模型标注额度的总和。我们的数字并非如此，这是有意为之：

- **每个共享额度池只计算一次。** Mistral 的免费套餐为每个组织提供每月 1B 的统一额度；将其列在五个模型下并不会使其变成 5B。如果按模型累加，我们自己的目录会显示为 **~7.4B**（于 2026-09-03 重新计算；此数字不受 CI 检查约束——每当目录发生变化时都应重新测算）——标题显示 **~1.47B**，因为这才是每个提供者各使用一个账户时实际可以消耗的额度。
- **每日上限会进行换算，速率限制则不会。** 有明确记录的每日 token 上限会按 `× 30` 换算；有明确记录的每日请求上限会按 `RPD × ~800 tokens × 30` 换算；如果提供者只公布每分钟请求数，则**不会**计算月度数字，并将其列为_无上限_，绝不计入总和。将速率限制按 24/7 全天候运行来相乘，正是我们拒绝采用的虚高计算方式。
- **需要通过区域身份检查才能获得的配额会单独列出**（`+~6M behind regional identity verification`），因为大多数读者无法使用这些配额。
- **注册赠送额度仅适用于首月**，并作为第二个数字报告，绝不会混入持续可用额度中。
- **该数字由 CI 强制校验。** `npm run check:docs-counts` 会根据目录重新计算总额；当此文件、README 或预算卡片中的数字与计算结果不一致时，构建会失败。

## ToS 注意事项表

> **ToS 标志仅供参考，不是路由门槛。** 标记为 `tos` 的提供者默认仍会参与路由以及组合/回退；该标志只会显示在 `/dashboard/free-tiers` 和 `/api/free-tier/summary` 中。`excludeTosAvoid` 查询参数仅影响摘要视图，不影响全局路由。判定结果位于 `open-sse/config/freeTierCatalog.ts` 中（仅供参考，不会被路由引擎读取）。

> 快速了解各提供者针对自托管、单用户个人代理的条款。`caution` = 有值得核查的个人使用或代理条款；`ambiguous` = 不明确；`ok` = 明确允许。仅供参考，不构成法律建议——由你自行决定。

## 术语表

| 术语                    | 含义                                               |
| ----------------------- | -------------------------------------------------- |
| **RPM / RPD / RPH**     | 每分钟 / 每天 / 每小时请求数                       |
| **TPM / TPD**           | 每分钟 / 每天令牌数                                |
| **Documented grant**    | 提供者公布明确的每日/月度令牌上限（可证明的预算）  |
| **Theoretical ceiling** | `rate-limit × 24/7 × 30d` — 最大值，而非授予的预算 |
| **Neuron**              | Cloudflare 计算单元（约 1 个输出令牌）             |

> 根据截至 2026-06-05 对各提供者的研究生成。重新运行研究工作流（参见 `_tasks/features-v3.8.12`）以刷新。
