`copilot-m365-web` （别名`m365copilot`）通过`m365.cloud.microsoft/chat`上经过身份验证的Microsoft 365 Copilot会话发送 OpenAI 格式的聊天请求。这是非官方的本机集成：不需要单独的代理进程或本地主机上游。提供者ID、别名和现有导入的连接保持不变。 `copilot-web`是`copilot.microsoft.com`消费者服务的不同提供者。

> **对 Web Cookie 提供者不熟悉？**
>
> 读**`docs/getting-started/WEB-COOKIE-GUIDE.md`**在遵循此特定于提供者的指南之前，请先了解一般设置过程、身份验证指南、限制和故障排除。
>
> **对于旧版导入：**该提供者的凭证是**不是饼干**。不要从`m365.cloud.microsoft`复制 cookie。凭证是WebSocket URL查询参数和路径段，两者都是从DevTools Network 选项卡读取的。

## 先决条件

- 有权访问`m365.cloud.microsoft/chat`上的Copilot的Microsoft 365 帐户
- 用于DevTools WebSocket检查的基于 Chromium 的浏览器（Chrome、Edge）
- 访问该帐户上请求的模型；可用性因租户和许可证而异

## 本机登录（工作或学校帐户）

选择**Microsoft 365 Copilot →连接**并准备登录尝试。仪表板使用PKCE的授权代码流；它不会要求您提供Microsoft密码或MFA代码。

1. 打开一个**空白浏览器选项卡**，然后打开**DevTools →网络**并启用**保存日志**。在导航到Microsoft之前执行此操作： Windows SSO可能会立即完成。
2. 复制连接对话框中显示的授权URL并在准备好的选项卡中导航到它。如果需要，请完成Microsoft的帐户选择或MFA 。
3. 在保留的网络日志中，找到对`https://login.microsoftonline.com/common/oauth2/nativeclient`的请求并复制其完整内容**请求URL** 。
4. 将URL粘贴到连接对话框中并连接。不要粘贴原始代码或最终的`wrongplace`地址栏URL：所需的回调是瞬态导航。

每次尝试将在十分钟后过期，并且只能使用一次。服务器在交换代码之前检查其状态、 PKCE验证者和重新验证目标。过期或兑换失败后，开始新的尝试。尝试无法在服务器重新启动后继续存在。

令牌使用现有的连接凭据存储和刷新路径。重新验证连接需要相同的Microsoft tenant/object身份，而不仅仅是相同的电子邮件。它保留了操作员naming/settings并替换了过时的导入凭据。原生登录适用于work/school账户；旧导入路径仍然可用于现有连接和支持的层配置。

完整回调URL是一次性凭证。切勿将其包含在屏幕截图、日志、支持消息或提交中。此流程不会在服务器上打开浏览器、检查浏览器历史记录或启动本地回调服务器。

## 凭证捕获（WebSocket方法）

1. 登录`https://m365.cloud.microsoft/chat`并开始对话。
2. 打开**DevTools →网络**。
3. 过滤依据**WS** （WebSocket）。
4. 单击 Chathub WebSocket连接。查找以`wss://substrate.office.com/m365Copilot/Chathub/`开头的URL 。
5. 从其**请求URL** ， 复制：
   - `access_token`查询参数值（短暂的JWT）。
   - `/Chathub/`之后的 Chathub 路径段（例如`<oid>@<tenant>`）。

完整的URL具有以下形式：

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. 在OmniRoute中，选择**Microsoft 365 Copilot** ，选择旧版API-key/import选项，并以以下格式粘贴凭据：

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. 点击**测试连接**和**节省**。

## 凭证捕获（HAR导入）

您可以导出DevTools HAR文件，而不是手动从WebSocket URL复制值：

1. 打开**DevTools →网络**。
2. 开始或继续Microsoft 365 Copilot对话（这会触发WebSocket连接）。
3. 在网络面板中右键单击并选择**将内容全部保存为HAR** 。
4. 在OmniRoute中，使用**导入.har文件**提供者连接对话框上的按钮。

OmniRoute扫描HAR中的 Chathub WebSocket URL，提取`access_token`和`chathubPath`，并自动填充凭据字段。 HAR导入对JWT到期进行解码并显示剩余的令牌生命周期。

> **切勿提交真正的HAR导出、访问令牌或刷新令牌。**测试和文档值必须始终是占位符。

## 令牌生命周期和刷新

`access_token`是短暂的（通常**~分钟**）。如果没有可用的刷新令牌，您必须在过期后重新捕获凭证。

### 使用`refreshToken`自动刷新

在Microsoft 365 提供者的**添加连接**或者**编辑连接**对话框，打开**高级设置→刷新令牌（可选）** 。粘贴Microsoft OAuth刷新令牌以用于`substrate.office.com/sydney`范围并保存。输入被屏蔽并且永远不会用存储的令牌预先填充。编辑时留空，保留现有token；粘贴新令牌来替换它。

当Microsoft返回 1 时，本机登录会获取刷新令牌。对于旧版导入，请使用现有的兼容Microsoft授权代码授权；该提供者不实现或承诺设备代码流。配置刷新令牌后， OmniRoute在请求之前检查`access_token` ，仅在需要刷新时刷新它。成功的刷新还会保留轮换的刷新令牌，从而避免在刷新令牌保持有效时手动重新捕获。

如果未设置`refreshToken` ，则必须在每次到期后手动重新捕获WebSocket凭证。

### 等级选择

| 等级         | 别名       | 表面                |
| ------------ | ---------- | ------------------- |
| `individual` | _（默认）_ | 消费者 M365 Copilot |
| `edu`        | `included` | 教育 M365 Copilot   |
| `enterprise` | `work`     | M365 Copilot工作版  |

将层级设置为**高级设置→ Copilot层**。本机登录不会设置它，因此工作帐户必须选择`enterprise` （别名`work`）和教育帐户`edu`，在使用记录模型IDs时也是如此：它们选择自己的语气、场景和许可证类型，但代理和调用选项仍然来自该层，并且个人默认值可能会在工作租户上失败。更改级别并不授予模型许可证。显式高级协议覆盖优先，并且仅当您知道所需的线路值时才应使用。

## 型号和路线

本机目录包括所有记录的独立IDs以及四个原始本机IDs。该目录是静态的且独立于帐户，而不是帐户权利探测：即使连接的帐户无法使用付费路由和兼容性别名，它们也会保留在列表中。模型显示标签省略了提供者名称和每个模型的可用性样板；提供者仍然存在**Microsoft 365 Copilot** 。标签标记**别名**或者**遗产**保留其现有的标识符和协议映射，不保证历史模型版本。独立代理的**从 /models 导入**说明不适用于此本机WebSocket提供者。

| 模范家庭          | 规范IDs                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| 自动的            | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |

| Claude作品        | `claude-opus`, `claude-opus-4.8`                                                                 |

还注册了`auto`、 `quick`、 `think-deeper`等别名和版本别名。现有的`copilot-m365`、 `copilot-m365-claude-opus`、 `copilot-m365-gpt-5-6-reasoning`和`copilot-m365-gpt-5-5-chat`仍然有效。记录的IDs需要提供程序前缀（`copilot-m365-web/claude-opus`或`m365copilot/claude-opus`）：许多是通用词或其他供应商的型号名称，因此裸`claude-opus`会像没有此提供程序一样保持路由。注册并不承诺Microsoft会为每个帐户提供该模型。独立的IDs遵循公共[协议目录](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts)（导出的模型到色调映射及其模型感知场景元数据）。所有原生配置文件都保留`availability: "unverified"`；包含在目录中并不是成功的帐户测试。

- 明确的模型许可拒绝返回**403** `m365_model_not_licensed`，而不是 502。路由锁定connection/model配对，使连接上的许可模型可用。
- `InvalidCopilotLicense`是帐户级许可拒绝，单独报告为`m365_account_not_licensed`。
- 每用户限制返回**第429章**`m365_throttled`并冷却连接。优先访问耗尽返回**第429章**`priority_access_exhausted`并且是模型范围的。 `OutOfCredits`与`errorCode: "ReasoningTurnExhausted"`的结果返回**第429章**相反， `reasoning_turns_exhausted` ，也是模型范围的，没有声明重置时间。据报道，一名工作租户在快速音调继续播放的同时限制了“深入思考”的音调；该范围是消费者的观察，而不是该存储库复制的内容。因此，路由还使其他已记录的 Think Deep 模型的`gpt-5.5`和`gpt-5.6`不再在该连接上旋转，以获得相同的冷却时间，并将快速音调和所有其他故障保留在其自己的模型上。保留提供的重试提示；丢失的重置不会被公布为已知的重置时间。
- Copilot安全拒绝 (`Disengaged`) 返回**400** `provider_safety_rejection`，共享提供者安全停止标签。它永远不会影响连接的健康状况，客户端SDKs不会重试 400，并且启用`PROVIDER_SAFETY_STOPS_TERMINAL`组合路由会在那里停止，而不是针对另一个目标重播请求。
- 一个连接上的请求通过现有帐户信号量进行序列化。优先选择优先级回退而不是并行面板；序列化本身并不能消除Microsoft的会话速率限制。

## 请求行为和限制

- 工具有**提示模拟**，不是本机Microsoft函数调用。工具启用的请求使用一个缓冲生成；它不会花费一代人的时间来选择工具。只有具有有效支持的参数形状的声明工具才会作为调用返回。
- 带有单个尾随示例的长结构答案将作为散文保存。这是一种启发式方法，而不是意图证明；应用程序仍然必须强制执行自己的工具权限。
- 图像输入的工作方式与 Web 客户端发送图像的方式相同。每个图像部分（`image_url`作为数据URL或公共HTTPS URL或响应`input_image`）都上传到`/m365Copilot/UploadFile`到带有聊天令牌的回合对话中，并且消息通过`ImageFile`注释指向它；文本标记了它所在的位置（`[image 1]`，...）。新的对话会上传历史记录中的每张图像，而连续的对话则仅上传新消息的图像。最多 10 个PNG、 JPEG、 GIF或WebP图像，每个图像最多 10 MiB （每个请求 40 MiB ）；格式是从字节中读取的。 HTTPS URLs通过仅限公共、DNS 固定的远程图像防护获取。上传失败导致请求失败（** 502** `m365_image_upload_failed`** 400** `m365_image_rejected`或`m365_image_invalid`);如果没有给出图像，转弯永远不会继续。其他非文本部分（音频、文件）会被明确拒绝，而不是默默丢弃。
- 后续请求将继续相同的上游会话，并且仅发送前一个回复之后的消息。它必须精确地扩展该回复：相同的连接、模型配置文件和工具集；未更改的历史记录（每条消息都有一个 sha256 链）；以及回复的工具调用 ID，或其文本（最多为空格）。任何其他内容（已编辑的历史记录、具有相同第一条消息的另一个会话、不同的回复、空闲 30 分钟或接近Copilot的 600 条消息上限的对话、没有 id 的连接）都会启动与整个历史记录的新对话。失败的回合永远不会恢复，并且在新的对话中重新发送一次无内容的`InternalError` (** 502** `m365_internal_error`如果再次失败）。延续信息保存在进程内存中：重新启动将开始新的对话。
- 每个回合都在Copilot的临时聊天 (`disableMemory=1`) 中运行：对话在运行时保留其上下文，并且永远不会出现在帐户的聊天历史记录中。因此，模型测试、测试全部和组合测试可以在不留下对话的情况下探测该提供者。
- 一个回合有 120 秒的空闲期限和有限的总期限。仅最终答案、进度过滤和取消由本机transport/composer.处理
- 基于网络的答案保留其来源。 Copilot使用私人使用控制字符标记内联引用，并将源作为`references`发送；每个标记都变成一个编号的 Markdown 链接（`[1](https://…)`，或者Copilot使用标记作为链接目标时的裸URL ），并带有匹配的`url_citation`注释（`message.annotations`，或者带有链接的块上的`delta.annotations` ）。永远不会到达的源将被丢弃，因此标记永远不会到达客户端。流式传输时，引用后的文本会等待其来源到达。
- 当模型发送Copilot的推理摘要 (`ChainOfThoughtSummary`) 时，它会作为`reasoning_content`返回，而不是作为答案的一部分。重写自身的摘要会停止流式传输而不会失败。
- 在任何内容之前，即使请求流式传输， licence/throttle失败也会保留HTTP 403/429 。内容开始后，失败是SSE错误事件，永远不会成功完成。无法用仅追加流表示的上游重写是显式流错误；非流式和缓冲工具响应保留最终文本。
- 当Copilot拒绝连接本身时，其答案如下所示：** 401** `m365_unauthorized`表示登录被拒绝或过期（再次登录），**第429章**使用`Retry-After`进行节流，否则握手失败，绝不是一般连接失败。

## 图像生成

`POST /v1/images/generations`和`model: "copilot-m365-web/m365-copilot-image"` （别名`m365copilot/m365-copilot-image`）使用Copilot的内置图像工具进行绘制，就像 Web 客户端一样。每个图像都是一个Copilot回合：它选择使用 Web 客户端的图像选项集并声明`GenerateGraphicArt`，并且图像到达指向Microsoft设计器服务上的工件的进度条目。该工件拒绝聊天令牌，因此OmniRoute从连接的刷新令牌中创建一个设计者令牌并下载字节；令牌仅发送至`designerapp.officeapps.live.com`。

- 需要本机登录连接（刷新令牌）；粘贴令牌失败**400**在任何回合结束之前。
- `n`是1-4，每回合一回合。 `size`仅控制方向（更宽、更高或方形）， Copilot从提示中读取该方向； Copilot选择渲染大小。
- 图像以内联方式返回：默认为`b64_json` ， `response_format: "url"`为数据URL 。
- 生成的图像需要少量的每日预算，与聊天无关。当它用完时，请求失败**第429章**。没有图像回答的回合会失败**502** （或者**400** /** 503**当Copilot的文本读作拒绝或容量问题时）；消息说的是哪一个。

## 安全模型

- **非官方整合。**该提供者对BizChat WebSocket协议进行逆向工程。当Microsoft更改端点时，它可能会在没有通知的情况下中断。
- `subscriptionRisk: true`标志反映集成依赖于未记录的端点。帐户限制是可能的，但尚未得到确认。
- 访问令牌是一个短暂的JWT。将其视为密码：不要提交、记录或共享它。
- 刷新令牌授予对Microsoft 365 表面的持续访问权限。像API密钥一样小心地存储它。

## 故障排除

### 认证立即失败

- Verify you copied from the **WebSocket URL**, not from an XHR/Fetch request. The credential is in the `access_token` query parameter of the Chathub WebSocket connection — not in an `Authorization: Bearer` header.
- 确保`chathubPath`包含URL路径中的完整`<oid>@<tenant>`段。

### 令牌在~ 75 分钟后过期

这是预料之中的。如果没有`refreshToken`，访问令牌是短暂的。任何一个：

- 从DevTools重新捕获凭证，或者
- 配置**高级设置→刷新令牌（可选）**在“添加”或“编辑连接”对话框中进行自动刷新。

### 测试连接通过，但聊天返回 401

对于使用以下命令创建的连接**使用Microsoft登录**，测试连接检查访问令牌的到期时间，并使用存储的刷新令牌更新过期的令牌，因此通过的测试也证明刷新令牌仍然有效。

对于粘贴的凭据，测试连接会检查凭据的形状，并且当令牌具有过期时间时，提供程序将使用的令牌尚未过期（连接的存储令牌赢得陈旧的粘贴；刷新令牌算作可更新）。过期之前被撤销的 token 仍然通过测试；聊天然后返回**401** `m365_unauthorized`.使用**使用Microsoft登录**再次，或重新获取新的凭据。

### Copilot没有出现在提供者列表中

确保`copilot-m365-web`已启用**仪表板→提供者**。默认情况下，某些层中的提供程序可能是隐藏的。
