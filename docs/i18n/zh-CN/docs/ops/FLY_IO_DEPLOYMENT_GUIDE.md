本文档介绍了在 Fly.io 上部署 OmniRoute 的实际流程，涵盖以下场景：

- 首次将当前项目部署到 Fly.io
- 发布后续代码更新
- 新项目沿用相同的部署工作流

本指南基于当前项目已经验证可用的配置。应用名称为 `omniroute`。

---

## 1. 部署目标

- 平台：Fly.io
- 部署方式：使用本地 `flyctl` 直接发布
- 运行时：使用仓库中现有的 `Dockerfile` 和 `fly.toml`
- 数据持久化：将 Fly Volume 挂载到 `/data`
- 访问地址：`https://omniroute.fly.dev/`

---

## 2. 当前项目的关键配置

已确认当前仓库中的 `fly.toml` 包含以下关键配置项：

```toml
app = 'omniroute'
primary_region = 'sin'

[[mounts]]
  source = 'data'
  destination = '/data'

[processes]
  app = 'node run-standalone.mjs'

[http_service]
  internal_port = 20128

[env]
  TZ = "Asia/Shanghai"
  HOST = "0.0.0.0"
  HOSTNAME = "0.0.0.0"
  BIND = "0.0.0.0"
```

说明：

- `app = 'omniroute'` 决定部署所面向的 Fly 应用
- `destination = '/data'` 决定持久化卷的挂载目录
- 此项目必须设置 `DATA_DIR=/data`，否则数据库和密钥将被写入容器的临时目录

## 3. 前置条件

### 3.1 安装 Fly CLI

Windows PowerShell：

```powershell
pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"
```

如果安装脚本在你的环境中执行失败，也可以手动下载 `flyctl` 二进制文件，并将其添加到 `PATH`。

### 3.2 登录 Fly 账户

```powershell
flyctl auth login
```

### 3.3 验证登录状态

```powershell
flyctl auth whoami
flyctl version
```

## 4. 首次部署当前项目

### 4.1 克隆代码并进入目录

```powershell
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
```

### 4.2 确认应用名称

打开 `fly.toml` 并确认以下配置行：

```toml
app = 'omniroute'
```

如果要部署到你自己的新应用，可以将其更改为一个全局唯一的名称，例如：

```toml
app = 'omniroute-yourname'
```

注意：

- 确保控制台中显示的应用与 `fly.toml` 中的 `app` 值一致
- 如果你之前使用过其他名称，例如 `oroute`，请勿将其与 `omniroute` 混淆

### 4.3 创建应用

如果应用尚不存在：

```powershell
flyctl apps create omniroute
```

如果你更改了应用名称，请将 `omniroute` 替换为你选择的名称。

### 4.4 首次部署

```powershell
flyctl deploy
```

## 5. 所需参数

本项目建议在Fly.io上至少配置以下参数。

### 5.1 验证参数

这些参数已在当前`omniroute`应用程序的实际部署中使用：

- `API_KEY_SECRET`
- `DATA_DIR`
- `JWT_SECRET`
- `MACHINE_ID_SALT`
- `NEXT_PUBLIC_BASE_URL`
- `OMNIROUTE_WS_BRIDGE_SECRET` （生产中需要—用于WebSocket桥接验证）
- `STORAGE_ENCRYPTION_KEY`

### 5.2 关于`INITIAL_PASSWORD`

当前项目没有设置`INITIAL_PASSWORD`因为本次部署不需要。

如果没有设置：

- 您可以在首次访问时在入门向导中创建仪表板密码。完成密码步骤：跳过该步骤将关闭仪表板登录，从而使仪表板向任何可以访问应用程序URL人开放
- Fly 的代理从非环回地址到达应用程序，因此在您提交密码后，向导会要求提供一次性引导令牌，应用程序此时会将其打印到其日志中： `flyctl logs --no-tail -a omniroute | Select-String BOOTSTRAP`。如果该行已滚出日志，请重新启动应用程序并再次提交向导以打印新令牌

要在无人值守的情况下设置密码，请在第一次访问仪表板之前添加它（保存密码后， `INITIAL_PASSWORD`将被忽略）：

- `INITIAL_PASSWORD`

## 6. 推荐参数

### 6.1 密钥配置

建议将以下变量配置为 Fly Secrets：

| 变量                         | 建议           | 说明                         |
| ---------------------------- | -------------- | ---------------------------- |
| `API_KEY_SECRET`             | 必需           | 用于生成和验证 API Key       |
| `JWT_SECRET`                 | 必需           | 用于登录会话和 JWT 签名      |
| `OMNIROUTE_WS_BRIDGE_SECRET` | 生产环境中必需 | WebSocket 桥接身份验证密钥   |
| `STORAGE_ENCRYPTION_KEY`     | 强烈建议       | 加密静态存储的敏感连接信息   |
| `MACHINE_ID_SALT`            | 建议           | 生成稳定的机器标识符         |
| `INITIAL_PASSWORD`           | 可选           | 在首次部署时设置初始后端密码 |
| OAuth/API 私有凭据           | 按需           | 外部平台身份验证配置         |

### 6.2 当前项目的建议值

| 变量                   | 建议值                      |
| ---------------------- | --------------------------- |
| `DATA_DIR`             | `/data`                     |
| `NEXT_PUBLIC_BASE_URL` | `https://omniroute.fly.dev` |

注意：

- `DATA_DIR=/data` 至关重要，并且必须与 Fly Volume 的挂载点一致
- `NEXT_PUBLIC_BASE_URL` 由调度器、前端回调及类似场景使用

### 6.3 OAuth 回调 URL 配置

如果需要在 Fly.io 部署中启用基于 OAuth 的提供者（例如 Antigravity、Gemini、Cursor），请确保以下两点：

1. **将 `NEXT_PUBLIC_BASE_URL` 设置为你的公共 HTTPS 域名**

   ```powershell
   flyctl secrets set NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev -a omniroute
   ```

   如果你使用自定义域名，请将其替换为对应的域名（例如 `https://omniroute.yourdomain.com`）。

2. **在提供者控制台中配置回调 URL**

   所有 OAuth 提供者共用唯一的回调路径 `/callback`——不存在每个提供者单独的回调路由：

   ```text
   <NEXT_PUBLIC_BASE_URL>/callback
   ```

   例如，无论是 Gemini、Antigravity、Cursor 还是 GitLab Duo：
   - `https://omniroute.fly.dev/callback`

   如果 `NEXT_PUBLIC_BASE_URL` 与在提供者处注册的回调 URL 不匹配，OAuth 流程将在浏览器重定向步骤失败。

## 7. 一条命令完成密钥设置

以下命令会生成安全的随机值，并一次性将当前项目所需的全部参数写入 Fly Secrets。

注意：

- 不包括 `INITIAL_PASSWORD`
- 适用于当前项目 `omniroute`

```powershell
$apiKeySecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$jwtSecret = [Convert]::ToHexString((1..64 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$machineIdSalt = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$storageKey = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$wsBridgeSecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()

flyctl secrets set `
  API_KEY_SECRET=$apiKeySecret `
  JWT_SECRET=$jwtSecret `
  MACHINE_ID_SALT=$machineIdSalt `
  STORAGE_ENCRYPTION_KEY=$storageKey `
  OMNIROUTE_WS_BRIDGE_SECRET=$wsBridgeSecret `
  DATA_DIR=/data `
  NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev `
  -a omniroute
```

在 Linux / macOS 上，也可以使用 `openssl rand -hex 32`：

```bash
flyctl secrets set OMNIROUTE_WS_BRIDGE_SECRET=$(openssl rand -hex 32) -a omniroute
```

注意：

- `OMNIROUTE_WS_BRIDGE_SECRET` 在生产环境中为必需项；缺少此变量将导致 WebSocket 桥接握手失败

如果还需要设置初始密码：

```powershell
flyctl secrets set INITIAL_PASSWORD=your-strong-password -a omniroute
```

## 9. 后续更新和发布

代码更新后，发布过程很简单：

```powershell
git pull
flyctl deploy
```

如果只需要更新参数而不改变代码：

```powershell
flyctl secrets set KEY=value -a omniroute
```

Fly 将自动执行机器的滚动更新。

### 9.1 跟踪上游存储库更新，同时保留 Fork 的`fly.toml`

如果当前存储库是一个分支，并且您想要从上游`https://github.com/cheaper-inference/OmniRoute`同步更新，请按照以下工作流程操作。

首先，验证您的遥控器：

```powershell
git remote -v
```

您至少应该看到：

- `origin`指向你自己的fork
- `upstream`指向原始存储库

如果没有配置`upstream` ，则添加：

```powershell
git remote add upstream https://github.com/cheaper-inference/OmniRoute.git
```

在与上游同步之前，获取最新的提交和标签：

```powershell
git fetch upstream --tags
```

检查当前版本和上游标签：

```powershell
git describe --tags --always
git show --no-patch --oneline v3.4.7
```

> 注意：当前项目版本是`v3.8.0`。下面的`v3.4.7`参考文献仅作为历史示例保留。对于实际版本，请使用`:latest`或当前版本标签（例如`:v3.8.0`）。

如果您想合并最新的上游`main`同时强制保留分支的`fly.toml`，请遵循以下工作流程：

```powershell
git merge upstream/main
git checkout HEAD~1 -- fly.toml
git add -- fly.toml
git commit -m "chore(deploy): keep fork fly.toml"
git push origin main
```

笔记：

- `git merge upstream/main`从原始存储库同步最新代码
- `git checkout HEAD~1 -- fly.toml`在合并之前恢复你的 fork 自己的`fly.toml`
- 如果上游没有修改`fly.toml`，这一步不会引入任何差异
- 如果上游确实修改了`fly.toml`，此步骤可确保您的 Fly 应用程序名称、卷安装、区域和其他特定于分叉的部署配置不会被覆盖

如果您想与特定版本标签（例如`v3.4.7`）保持一致，请首先验证该标签是否已包含在`upstream/main`中：

```powershell
git merge-base --is-ancestor v3.4.7 upstream/main
```

成功返回意味着`upstream/main`已经包含该版本；您可以简单地合并`upstream/main`。

### 9.2 上行同步后的标准发布顺序

与原始存储库同步后，请遵循以下建议的发布顺序：

1. `git fetch upstream --tags`
2. `git merge upstream/main`
3. 恢复fork的`fly.toml`
4. `git push origin main`
5. `flyctl deploy`
6. `flyctl status -a omniroute`
7. `flyctl logs --no-tail -a omniroute`

这是当前项目升级到`v3.4.7`时的实际流程（示例指的是历史版本，当前实际版本为`v3.8.0`）。

## 11. 成功标志

成功部署后，日志中应显示类似以下内容：

```text
[bootstrap] 密钥已持久化至：/data/server.env
[DB] SQLite 数据库已就绪：/data/storage.sqlite
```

以下两点至关重要：

- `/data/server.env` 表示运行时密钥已写入持久卷
- `/data/storage.sqlite` 表示数据库已写入持久卷

如果看到的是 `/app/data/...`，则说明 `DATA_DIR` 配置错误，必须立即修正。

## 12. 常见问题

### 12.1 `Secrets`页面为空

通常有两个原因：

- 您还没有运行`flyctl secrets set`
- 您正在查看不同的应用程序（例如`oroute`而不是`omniroute`）

### 12.2 `flyctl deploy`报告`app not found`

首先创建应用程序：

```powershell
flyctl apps create omniroute
```

### 12.3 `fly.toml`解析失败

检查以下内容：

- 评论是否有乱码
- TOML引用和缩进是否正确

### 12.4 数据不持久

验证以下两项：

- `fly.toml`包含`destination = '/data'`
- `DATA_DIR`设置为`/data`

### 12.5 没有`INITIAL_PASSWORD`可以运行吗？

是的。取消设置`INITIAL_PASSWORD`后，您可以在第一次访问时在入门向导中创建仪表板密码（第 5.2 节介绍一次性引导令牌和密码步骤）。

## 13. 复用于新项目

如果按照本文档部署新项目，只需修改以下内容：

1. 修改 `fly.toml` 中的 `app` 值
2. 修改 `NEXT_PUBLIC_BASE_URL`
3. 保持 `DATA_DIR=/data`
4. 重新生成 `API_KEY_SECRET`、`JWT_SECRET`、`MACHINE_ID_SALT` 和 `STORAGE_ENCRYPTION_KEY`
5. 首次部署后，验证日志是否写入 `/data`

请勿重复使用之前项目的密钥。

对于正常发布，核心命令很简单：


1. `flyctl auth login`
2. `flyctl apps create omniroute`
3. `flyctl secrets set ... -a omniroute`
4. `flyctl deploy`
