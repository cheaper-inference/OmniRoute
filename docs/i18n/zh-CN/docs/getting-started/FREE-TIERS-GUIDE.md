> **TL;DR** ：带上您自己的合格提供者帐户。 OmniRoute结合了你配置的连接；它不会发布广告中的总代币预算。免费访问可能需要注册、 API密钥、批准或付款方式。提供者限制、隐私政策和条款仍然适用。

---

## 什么是免费套餐？

许多AI提供者提供某种形式的**免费访问**。根据提供者的不同，这可能意味着无身份验证端点、定期配额、速率限制的无上限访问、注册授权、手动批准或临时促销。某些选项需要帐户、 API密钥、信用卡、 KYC或接受特定于提供者的条款。

OmniRoute**聚集体**配置连接到一个端点。您仍然需要单独注册每个需要帐户的提供者。连接这些帐户并使用`model: "auto"`在符合条件的目标之间进行路由。全新安装不能有合格的无钥匙目标；单独安装OmniRoute并不能保证聊天响应成功。

## 如何叠加免费层级

OmniRoute的神奇之处在于**堆叠免费层**。您无需依赖一个提供者，而是连接多个免费提供者，并让OmniRoute自动为每个请求选择最佳提供者。

### 示例：更广泛的免费套餐覆盖范围

连接多个提供者以减少对任何单一配额的依赖：

1. **Gemini** —定期 API 密钥配额
2. **Groq** —定期 API 密钥配额
3. **授粉**—无钥匙、限速访问
4. **LongCat** —一次性注册补助（需要KYC）

然后使用`model: "auto"`和OmniRoute将：

- 首先尝试排名最高的合格连接
- 如果其配额或运行状况检查失败→尝试下一个配置的提供程序
- 如果无密钥提供程序不可用→继续完成其余目标
- 如果没有符合条件的连接成功→返回错误；注册积分仅在有效且可用时可用

**结果**：具有自动后备—更广泛的免费套餐覆盖范围并不能保证无限容量。

## 如何连接免费提供者

### 第 1 步：打开仪表板

在浏览器中转到`http://localhost:20128` 。

### 第 2 步：前往提供者处

点击**供应商**在侧边栏中。

### 第 3 步：单击“添加提供者”

单击**+添加提供者**按钮。

### 第 4 步：选择免费提供者

浏览目录并检查每个提供者当前的`hasFree`、身份验证、配额、隐私和ToS元数据。提供者卡和[免费套餐参考](../reference/FREE_TIERS.md)区分了经常性池、 uncapped/keyless访问、注册积分、已停止的条目和高风险来源。

### 第5步：点击连接

对于`NOAUTH`提供者， OmniRoute不请求上游凭证。这并不保证上游接受第三方客户端或具有可用容量。 OAuth和 API 密钥提供者必须通过其记录的帐户流进行连接。您的客户端仍然使用在中创建的OmniRoute API密钥**仪表板→ API按键**（仅在创建时显示一次）启用路由器身份验证时。

### 第 6 步：重复

连接多个条款和隐私模型适合您的用例的提供者。

## 来自 dsh“我们的免费模型”

dsh 代理主机的[dsh-our-free-model](https://github.com/Ebony-Vinyl/dsh-our-free-model)插件到达两个上游。 OmniRoute已经为每个提供者都有一个提供者，但其中只有一个是OmniRoute中的免费路径：

| 插件通道 | 上游                                    | OmniRoute提供者             | OmniRoute免费吗？ | 如何连接                                                                 |
| -------- | --------------------------------------- | --------------------------- | ----------------- | ------------------------------------------------------------------------ |
| 千通道   | Kilo AI网关 (`api.kilo.ai/api/gateway`) | `kilo-gateway` （别名`kg`） | 是的              | API key 可选：将其留空以使用网关的空闲池                                 |
| 自由车道 | OpenCode禅 (`opencode.ai`)              | `opencode-zen`              | 不                | 来自[opencode.ai/zen](https://opencode.ai/zen)的您自己的OpenCode API密钥 |

**公斤。**将空闲池称为`kilo-gateway/<model>`或`kg/<model>`，例如`kg/kilo-auto/free` （Kilo 的免费自动路由器）或网关的`:free`模型之一。自由组旋转； `kilo-gateway`传递不在OmniRoute内置列表中的模型 ID，因此可以在目录包含模型之前调用网关今天列出的模型。 Kilo 的免费模型卡表示，上游提供者可能会记录提示并用于改进其服务，因此不要发送敏感数据。

**OpenCode.**该插件的免费通道是OpenCode的免密钥优惠。 OmniRoute不提供该优惠作为免费访问：

- 应OpenCode运营商的请求，删除了OmniRoute的无密钥OpenCode提供程序（请参阅[删除的提供程序](../reference/REMOVED_PROVIDERS.md)）。
- OpenCode的[端点文档](https://opencode.ai/v2/docs/console/models/#endpoints)将其免费聊天优惠与OpenCode自己的客户端联系起来，因此OmniRoute不会将其视为免费或将其标记为免费。

插件显示的模型 ID，例如`deepseek-v4.1-flash-free`、 `mimo-v2.6-flash-free`和`nemotron-3.5-lightning-free`，位于`opencode-zen`目录中。将`opencode-zen`与您自己的OpenCode密钥连接，以便根据您的OpenCode帐户条款使用它们。

**插件的本地端口。**该插件可以在本地 OpenAI 兼容端口（默认`18899`）上公开其模型。任何此类端点都可以添加为[自定义 OpenAI 兼容提供程序](../guides/USER_GUIDE.md#custom-openai-compatible-providers)，但OmniRoute不会安装、启动或更新插件，并且插件决定哪个上游服务于每个请求。无论哪个客户端发送请求，上述OpenCode限制都适用于OpenCode的报价。

## 正确阅读目录

- `NOAUTH`表示OmniRoute不会要求您提供提供者凭证；它不保证正常运行时间、隐私或无限容量。
- `hasFree`是发现元数据。它可以代表定期配额、无钥匙访问、注册积分、批准计划或促销。
- `recurring-uncapped`表示没有公开的代币上限；速率和并发限制仍然适用。
- 注册授权用完后，`one-time-initial`不会重复出现。
- 默认情况下，`tos: avoid`提供者被排除在自动路由之外 (`excludeTosAvoid`)。连接帐户不会绕过此过滤器。任何运营商超控都应遵循对提供者条款和帐户风险的审查。
- 标记为`discontinued`条目仍然是历史证据，不得以当前免费的方式呈现。

## OmniRoute如何让免费套餐变得更好

### 1. 自动回退

如果一个免费提供者繁忙或宕机， OmniRoute会自动尝试下一个。你不需要做任何事情。

### 2. 智能路由

OmniRoute选择了**最佳免费提供者**对于每个请求，基于：

- 速度—现在哪个提供者速度最快？
- 质量—哪个提供者最适合这项任务？
- 容量—哪家提供者还有剩余配额？

### 3. 代币节省

OmniRoute的压缩管道可以减少合格的提示和工具输出令牌。实际节省取决于内容、所选引擎、提供者会计和保真度设置；压缩不会将每个提供者配额乘以固定数量。

### 4. 多账户支持

如果提供者条款允许多个帐户或凭证， OmniRoute可以将每个连接视为单独的路由候选者。不要创建额外的帐户来逃避提供者的配额或访问策略。

## 常见问题

### “这真的是免费的吗？”

该目录记录了提供者发布的术语和项目研究，但报价可能会发生变化。使用前验证提供者的当前定价、配额、隐私政策和资格。

### “免费套餐会用完吗？”

每个提供者都可以限制速率、更改模型、暂停访问或离线。多个连接可以改善后备覆盖范围，但不能保证可用的免费路由。

### “我可以使用免费提供者进行生产吗？”

仅当提供者的SLA、数据处理、限制和条款满足您的生产要求时。关键工作负载应该受到监控、符合合同规定的后备措施。

### “有什么问题吗？”

权衡可能包括严格的限制、候补名单、 KYC、信用卡验证、提示培训、较弱的隐私、无SLA、模型流失、地理限制、超额付费或账户政策风险。 OmniRoute显示可用的元数据；您选择要启用的内容。

### “如何获得更多免费额度？”

1. 连接更多免费提供者
2. 启用适当的压缩引擎并衡量您的工作负载节省情况
3. 使用`auto/cheap`确定free/cheap提供者的优先级
4. 在不违反提供者条款的情况下添加其他允许的提供者或凭据

### “免费提供者的质量是否较差？”

未必。一些提供者通过付费途径提供相同的模型系列，但限制、延迟、隐私、可靠性和模型版本可能有所不同。使用免费提供者排名页面作为质量信号并验证所提供的实际模型。
