> **状态：** 仪表盘基于 **Keak CI UI Kit**（`@keak/cheaper-inference-ui-kit`）构建，以 vendor 方式
> 作为工作区 `packages/ui-kit` 引入（包名 `@omniroute/ui-kit`；上游快照固定在
> `packages/ui-kit/UPSTREAM.md` 中，并由 `npm run check:ui-kit-snapshot` 守护）。浅色（Light）是规范
> 主题；默认偏好为 `system`。强调色为 Keak 青柠色（`--ci-color-accent`）。Inter
> （letter-spacing 0，`--ci-letter-spacing-ui`）是 UI 字体族，Instrument Serif 仅用于大号稀疏的
> 展示性文字（`.ci-dashboard-display`），IBM Plex Mono 用于代码——全部通过
> `src/app/globals.css` 顶部的 `@fontsource/*` 导入实现自托管。每个图标都是 Lucide 字形。

## 1. 内容所在位置

- **套件（Kit）。** `packages/ui-kit/src` 是上游 `src/` 在 `packages/ui-kit/UPSTREAM.md` 中所固定提交处的逐字节副本（该文件同时记录了许可证授权）；`PATCHES.md` 列出了本地补丁（无）。它以源码形式被消费，无需构建：`next.config.mjs` 对其进行转译，`tsconfig.json` 将 `@omniroute/ui-kit` 映射到 `packages/ui-kit/src`，将 `@omniroute/ui-kit/*` 映射到 `packages/ui-kit/src/*`（`vitest.config.ts` 和 `vitest.mcp.config.ts` 携带相同的别名）。导入 kit 组件时使用其子路径（`@omniroute/ui-kit/table`、`@omniroute/ui-kit/page-header`……），绝不通过 `@omniroute/ui-kit` 的 barrel 文件导入：barrel 会把所有组件（包括日期选择器）拉进每个导入方。kit 样式表通过 `src/app/globals.css` 引入（`@import "../../packages/ui-kit/src/ci-ui.css"`）。
- **令牌（Tokens）。** `packages/ui-kit/src/ci-tokens.css` 声明了 `--ci-*` 令牌；`src/app/globals.css` 将它们桥接到旧的 OmniRoute 名称（`--color-*`、`--radius-*`、`--font-sans`/`--font-mono`、`--table-*`、`--orch-status-*`、`--color-fd-*`），因此现有的 `var(--color-*)` 读取和 Tailwind 工具类可以继续工作。新代码使用 Tailwind 工具类（`bg-surface`、`text-text-muted`、`border-border`、`text-success`、`bg-success-bg`、`bg-chart-1`……）或 kit 类——绝不使用十六进制色值（`tests/unit/design-kit-bridge.test.ts` 强制执行该桥接）。`text-primary` 通过 `--text-color-primary` 解析为 `--color-primary-ink`（浅色模式下为 lime-800，深色模式下为 lime 强调色），因此主要文本保持可读，而 `bg-primary`/`border-primary` 保留 lime 色表面。图表系列使用 `--color-chart-1` … `--color-chart-5`。
- **主题（Themes）。** `<html className="ci-theme">`（`src/app/layout.tsx`）使文档启用 kit 主题。偏好设置为 `light`、`dark` 或 `system`（`src/shared/constants/appConfig.ts` 中的 `THEME_CONFIG.defaultTheme = "system"`；`system` 遵循 `prefers-color-scheme`）。`src/store/themeStore.ts` 中的 `applyTheme()`（由 `src/app/layout.tsx` 中的内联引导脚本镜像，该脚本在水合之前运行）同时设置 `data-theme="dark"|"light"` 并切换 `<html>` 上的 `.dark` 类。kit 的深色令牌集以 `data-theme="dark"` 为键（`packages/ui-kit/src/ci-tokens.css`）；OmniRoute 自己的深色覆盖（`globals.css` 中的 `.dark` 块）和旧的 Tailwind `dark:` 工具类以 `.dark` 类为键。没有强调色预设：强调色始终来自 kit，旧版本构建中持久化的预设会在 store 加载时被丢弃。
- **组件（适配器）。** `src/shared/components/index.tsx` 保留了 OmniRoute 组件 API（相同的名称、默认导出和 props），其背后的基础组件是 kit 之上的适配器：表单（`Button`、`Input`、`Textarea`、`Checkbox`、`Select`、`Toggle`、`Badge`、`Card`）、浮层与反馈（`Modal`/`ConfirmModal`、`Tooltip`/`InfoTooltip`、`NotificationToast`、`EmptyState`、`Loading`）、结构（`Collapsible`、`CollapsibleSection`、`SegmentedControl`、`Breadcrumbs`、`Avatar`）和表格（`DataTable`、`FilterBar`、`ColumnToggle`、`FilterPills`、`PresetSlider`）。适配器通过子路径导入 kit 组件，并将旧版 props 映射到其上——例如，`Button variant="primary"` 是 kit 的 `default` 按钮（`--ci-button-primary-*`：浅色模式下为反色表面，深色模式下为强调色搭配其 `--ci-color-accent-foreground` 墨色），`danger` 是 `destructive`，`warning` 是 `outline` 加上 `.ci-button--warning` 扩展。`globals.css` 末尾（`@layer components`）的 `.ci-button--warning` 和 `.ci-badge[data-tone]` 规则是 OmniRoute 在 kit 类之上的扩展。`tests/unit/ui/adapters/*.test.tsx` 固定了每个适配器的行为。
- **外壳（Shell）。** `src/app/(dashboard)/layout.tsx` 渲染 `DashboardLayout`，后者渲染 `src/shared/components/layouts/DashboardShell.tsx`：kit 的 `SidebarProvider` / `Sidebar` / `SidebarInset`（`packages/ui-kit/src/sidebar.tsx`），OmniRoute 的导航逻辑位于 `src/shared/components/Sidebar.tsx`。指向 `#main-content` 的“跳转到内容”链接是第一个可聚焦元素。`src/shared/components/Header.tsx` 包含 kit 的 `SidebarTrigger`（外壳中唯一的侧边栏开关）、Keak 的 `ProductSwitcher` 和命令面板开启按钮；仅当 `#main-content` 内没有挂载 kit `PageHeader`（`.ci-page-header`）时，它才显示路由标题，因此带有自己 `PageHeader` 的页面只有一个 `h1`。`src/shared/components/CommandPalette.tsx` 是一个 kit `Dialog`。
- **图标（Icons）。** `<Icon name="material_name">`（`src/shared/components/Icon.tsx`）通过 `ICON_MAP`（`src/shared/constants/iconMap.ts`）将名称（页面使用的 Material Symbols 词汇）解析为 Lucide 字形。Material Symbols 字体和软件包已被移除：映射中缺失的名称会渲染一个中性占位字形（`data-icon-missing="true"`），并在生产环境之外记录控制台警告。`npm run gen:icon-map` 会打印正在使用但映射中缺失的名称（`tests/unit/icon-map-coverage.test.ts` 对任何没有 Lucide 图标的名称都会失败；`tests/unit/icon-map-object-values.test.ts` 覆盖存储在查找对象中的名称）；`scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` 将字面形式的 `<span className="material-symbols-outlined">` span 重写为 `<Icon>`。
- **品牌（Brand）。** `src/shared/components/OmniRouteLogo.tsx` 封装了 kit：默认导出 `OmniRouteLogo` 渲染 `ProductIcon product="omniroute" variant="glyph"`（内联 SVG，对 `basePath` 安全），`OmniRouteLockup` 渲染 `ProductLockup product="omniroute"`（无障碍名称为 "Keak OmniRoute"），或者对于白标运营商，渲染他们自己的 `name`/`logoSrc`。产品切换器的目标地址位于 `src/shared/constants/keakProducts.ts`（`KEAK_PRODUCT_LINKS`、`KEAK_ACTIVE_PRODUCT`）。独立页面——`src/app/login/page.tsx`、`src/app/status/page.tsx`、`src/app/maintenance/page.tsx`、`src/app/offline/page.tsx`、`src/app/not-found.tsx` 和 `src/shared/components/ErrorPageScaffold.tsx`——显示该 lockup 组合标识；`tests/unit/brand-pages-static.test.ts` 对此进行守护。

## 2. 规则

1. 只用 token，绝不使用字面值。有意保留的例外：始终为深色主题的控制台终端，以及
   `STATUS_HEX`（`src/shared/constants/statusColors.ts`）——它是 kit 状态色板解析后的 hex 镜像，供确实需要字面 hex 值的调用方使用。分类色板已不再是例外：它们通过
   `src/shared/utils/categoricalPalette.ts` 依托于 kit 的五个图表 token（`--color-chart-1..5`），路由策略则通过
   `src/app/(dashboard)/dashboard/combos/strategyPalette.ts`；ReactFlow 的边和编排画布读取感知主题的 `--orch-status-*` 变量（`src/shared/components/flow/edgeStyles.ts`）。
2. 绝不手动修改 `packages/ui-kit/src`：使用 `scripts/dev/sync-ui-kit.sh <commit>` 进行同步；
   pre-commit 关卡 `npm run check:ui-kit-snapshot`（`.husky/pre-commit`）会在任何字节与锁定的上游提交不一致时失败（当上游克隆——`UI_KIT_CLONE` 或 `_references/cheaper-inference-ui-kit`——不存在时，它会跳过并给出警告）。当 kit 缺少某些功能时，在适配器或页面中绕过它，并向上游提出需求。
3. kit 的默认文本是英文（`label = "Loading"`、`loadingLabel = "Loading table"`……）——只要 kit 组件渲染文本，就通过
   `useTranslations(...)` 传入翻译后的字符串。
4. Tailwind 工具类优先于 kit 组件类（kit 声明了
   `@layer theme, base, components, utilities`，其规则位于 `components` 层）——工具类用于间距和布局，而不是用来给 kit 组件重新着色。
5. 标题：页面和区块标题使用 `.ci-heading`（Inter 字体，无字距调整）；`.ci-dashboard-display`
   （Instrument Serif 字体）仅用于大而稀疏的展示性文本，例如错误页面的状态码。
6. `tests/unit/dashboard-kit-sweep.test.ts` 守护着 kit 的采用情况：`src/app` 和 `src/shared/components` 下不允许出现 Material 连字 span；
   在 dashboard 目录树（`src/app/(dashboard)` 和
   `src/shared/components`）中，除列出的例外（`Select` 适配器的原生分支、
   `RequestLoggerDetail`）外，不允许出现原生 `<select>`、`<textarea>` 或 `<table>`，也不允许手写的
   `role="dialog"`；其中每个原生 `<button>` 或 `<input>` 都需要一条包含
   `kit-exception:`（附原因）的注释，且注释结束位置最多在其上方 3 行；调色板色相和 `dark:` 变体只允许出现在测试列出的文件中。
7. 在提交 PR 前验证两种主题和 390 px 视口（截图）；`tests/e2e/a11y.spec.ts` 会运行
   axe。

## 3. 添加页面

1. 页面以 kit 的 `PageHeader`（`@omniroute/ui-kit/page-header`，在
   dashboard 内使用 `compact`）开头——包含标题、描述和 `actions`。这样外壳（shell）头部就会去掉它自己的标题。
2. 使用 `@/shared/components`（适配器）构建控件；在没有适配器的地方，通过子路径使用 kit
   组件（`Table`/`TableScrollArea`/`DataTableShell`、`Field`、`Alert`、`Tabs`、`RadioGroup`、
   `Slider`……）。
3. 图标：`<Icon name="…" />`。新名称要加入 `ICON_MAP`，并配上语义匹配的 Lucide
   组件；`npm run gen:icon-map` 会列出仍缺失的名称。
4. 颜色：使用语义化工具类（`text-success`、`bg-warning-bg`、`border-border`……），图表系列使用
   `var(--color-chart-N)`；不使用 hex 值，也不使用只是重复同一颜色的 `dark:` 变体。
5. 文本：所有字符串，包括传给 kit 组件的标签，都来自 `useTranslations`。新
   键要加入 `src/i18n/messages/en.json`、`pt-BR.json` 和 `vi.json`（越南语一致性测试会锁定
   每一个英文键）；其他语言由 i18n 同步填充。
6. 在提交 PR 前运行这些守护检查：`tests/unit/dashboard-kit-sweep.test.ts`、
   `tests/unit/icon-map-coverage.test.ts`、`tests/unit/icon-map-object-values.test.ts`、
   `npm run check:dashboard-typecheck`（唯一能捕获 `iconMap.ts` 中重复导入的检查）、
   `npm run check:ui-icu`，以及页面自身的测试。

## 4. 添加或修改适配器

1. 保持 `src/shared/components/index.tsx` 的公共 API 不变：相同的导出名、默认导出以及所接收的 props。在适配器内部将旧版 props 映射到 kit 上（参见 `Button.tsx`：`VARIANT_TO_KIT`、`SIZE_TO_KIT`）。
2. 通过子路径导入 kit（`@omniroute/ui-kit/<component>`）。
3. 针对 kit 缺陷的变通方案放在适配器中（如果修复的是样式，则放在 `globals.css` 的 `@layer components` 中），绝不放在 `packages/ui-kit/src` 中。
4. 添加或更新 `tests/unit/ui/adapters/<name>.test.tsx`。对于调用方众多的适配器，要比较变更前后渲染出的标记——内边距或包裹元素的变化会扩散到每个界面。

## 5. 更新 kit

`scripts/dev/sync-ui-kit.sh <commit> [clone]` 将上游该提交处的 `src/` 复制到 `packages/ui-kit/src`，并应用唯一允许的转换（去掉相对导入的 `.js` 后缀）。然后：检查 `git diff packages/ui-kit`，在两种主题下对 providers、settings、combos、usage 和 endpoint 页面做一次视觉走查，运行 `npm run check:ui-kit-snapshot` 和 `npm run test:vitest:ui`，并附上上游变更日志提交 PR。

## 6. README 图表

根目录 `README.md` 嵌入的十二张图表（`docs/diagrams/*.svg`）是将 kit 应用于静态图片的产物，它们是生成的，而非手工绘制：13 个生成器文件位于 `scripts/docs/gen-readme-*.mjs`（十二张图表加上 `gen-readme-diagrams.mjs` 驱动脚本），另有 12 个过期性测试位于 `tests/unit/docs/readme-*-svg.test.ts`，每张图表一个，每个测试都将已提交的文件与其生成器的输出逐字节比较（任务 `test-unit`）。

- **令牌。** `scripts/docs/readme-diagram-theme.mjs` 从 `packages/ui-kit/src/ci-tokens.css` 复制调色板（由 `tests/unit/docs/readme-diagram-theme.test.ts` 与该文件锚定校验），并在 kit 字体上定义文本角色——Instrument Serif 用于展示标题，Inter 用于 UI 文本，IBM Plex Mono 用于数字和代码，与 `src/app/globals.css` 为仪表盘加载的 `@fontsource` 包相同。浅色值位于 `:root`，深色值位于文件内的 `prefers-color-scheme: dark` 之后，因此每张图片在 GitHub 上都会跟随查看者的配色方案。
- **字体。** `scripts/docs/readme-fonts.mjs` 将这些 woff2 文件子集化为每张图表实际绘制的字形，并以 `@font-face` `data:` URI 的形式嵌入——这是 kit 排版进入 README 图片的唯一途径，因为 GitHub Markdown 不携带 CSS，且 camo 代理会阻止所有外部请求。这些子集仅包含拉丁字符；回退到系统字体栈的符号字形在 `SYMBOL_FALLBACKS` 中逐一放行，任何其他未覆盖的字形都会抛出错误。
- **重新生成。** `npm run docs:readme-diagrams` 按 README 顺序重写全部十二张图表，并为每个文件打印一行及其大小。单个生成器也可以独立运行（`node scripts/docs/gen-readme-<name>.mjs`；`free-tier-budget` 需要 `node --import tsx/esm`，因为它的数字来自 `open-sse/config/freeModelCatalog.ts` 中的实时目录加载器；目录变更对 CI 的影响见 `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict`）。将生成器与 SVG 一起提交。
- **验证。** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` 以 GitHub 提供图片的方式渲染文件（一个 `<img>` 标签、camo 的 `Content-Security-Policy`、`image/svg+xml`），捕获浅色和深色各一帧，并报告页面发出的外部字体请求（必须为 0）。
- **体积预算。** 每个文件低于 200 KB（每个过期性测试都会断言这一点）；500 KB 是任何 README 图片的硬性上限（SVG studio 校验器的规则）。
- **文案不变，数字以门禁为准。** 品牌重塑改变的是字体和调色板，而非文字：每个生成器将其图表的文案保存在 `*_COPY` 常量中（或从实时目录构建），它既是绘制的文本，也是字体子集化的输入。权威数字保留在 `<text>` 节点中，由 `check:docs-counts`（`scripts/check/check-docs-counts-sync.mjs`）读取；该门禁所读取图表的过期性测试还会在生成的文件上运行其校验器，因此与代码不一致的数字会导致测试失败——要修复门禁读取的数据源，绝不要改生成器中的数字。
