`devin-cli-agentic` 允许真正的 Claude Code 运行时使用 OmniRoute 的本地 Anthropic
Messages 端点，同时由官方 Devin CLI 通过 ACP stdio 提供模型响应。它
不会修改现有的 Anthropic、Claude OAuth、Claude Web 或 `devin-cli` 提供者。

对于客户端负责执行的工具调用，请通过 `devin-cli-agentic`（别名 `dva`）进行路由，它是
支持工具的 Claude 格式提供者。旧版 `devin-cli`（`dv`）ACP 执行器
仅支持文本：它运行 Devin 的无工具 summarizer，无法返回工具调用。其模型
元数据已相应标记，因此需要工具的组合路由将避开它。

> 基于 `2.1.220`。** `2.1.220` 固定版本通过 Devin CLI
> `3000.2.17` 和模型 `swe-1-7-lightning` 完成了三个相互隔离的场景；该次最终实时运行验证了客户端负责执行的 `Read`、
> `Edit` 和 `Bash` 轮次、成功的 `npm test` 结果、项目命令和技能
> 发现、仅使用 Devin 的路由，以及零 Claude 出站流量。之后，固定版本已提升至 `2.1.258`
> （即 OmniRoute 的 Claude 身份所模拟的 CLI 版本，也是首个原生提供

## 架构

```text
Claude Code 2.1.258（隔离的非 root Linux 容器）
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic（Claude 格式、无身份验证提供者）
  -> devin acp --agent-type summarizer（官方 ACP stdio，无 Devin 工具）
  -> 专用 devin-auth 卷中的 Devin 账户
```

官方 CLI 的默认 ACP 代理可以执行其自身的工具，因此此桥接器不使用
它。桥接器启动固定的 `summarizer` ACP 代理，其官方 CLI 模式不包含工具，并将
序列化后的 Anthropic 请求构造成执行轨迹。当需要另一个由 Claude 负责执行的
操作时，响应必须恰好包含一个客户端工具信封。在响应被报告为
成功之前，任何 ACP `tool_call` 或 `tool_call_update` 都会被拒绝。

`open-sse/executors/devin-agentic/serializer.ts` 中的序列化器会保留 `system`、
`text`、`tool_use`、`tool_result`、`thinking`、`redacted_thinking`、`tool_choice`，以及
Claude Code 提供的工具。图像和未知块会明确失败。大型工具结果
会使用可见的截断标记。

解析器接受每个模型轮次中一个独立的 `<tool>{...}</tool>` 信封。它会根据请求的
工具列表检查名称，依据该工具的 JSON Schema 验证参数，拒绝混合叙述/操作，
并允许一次有界修复。随后 Claude Code 会在本地执行生成的 Anthropic `tool_use`，
并通过 OmniRoute 发回 `tool_result`。

## 自动路由

当该提供者未被阻止时，它有资格进入 OmniRoute 的 `auto/*` 候选池。
具备候选资格并不保证会被选中：组合的路由策略（例如
last-known-good）可能会优先选择其他提供者。当你要求每个请求都必须通过 Devin 时，
请使用 `dva/<model>` 或 Devin 优先组合。

## 隔离与威胁模型

宿主机上的 Claude 安装、账户和配置不在适用范围内，并被视为禁止访问。Compose 服务：

- 以 UID/GID `10001:10001` 运行，使用只读根文件系统、移除 capabilities，并启用
  `no-new-privileges`；
- 使用私有的 `/home/bridge`、专用 Claude 配置卷、隔离的 OmniRoute 数据，
  以及单独的 `devin-auth` 卷；
- 仅挂载可丢弃的 `.sandbox` 工作区/证据；
- 不挂载宿主机主目录、Keychain、SSH、云凭据或 Docker socket；
- 构造显式环境并移除 Anthropic API/OAuth/路由变量；
- 仅将 Claude Code 推理请求定向到 `http://omniroute:20128`，并使用仅限本地的密钥。

离线配置使用内部网络。在实时配置中，OmniRoute 仅通过 `network-guard` 访问
Devin 官方端点；其他无关目标均被拒绝。Claude Code 使用单独的全拒绝出站防护，
并且只能通过 `NO_PROXY` 访问本地 OmniRoute 服务。防护审计文件仅挂载到对应的
防护进程。脚本会验证文件所有权、模式、链接数和每项决策，然后再导出不含令牌的证据。

独立运行隔离证明：

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

它会验证拓扑、命名挂载、非 root/只读设置、显式本地路由、敏感环境变量不存在、
Docker socket 不存在、对 `api.anthropic.com` 和 `claude.ai` 的访问被阻止、
仅选择 Devin 提供方，以及 ACP 后端不可用时明确失败。

## 首次设置和正常使用

构建固定版本的镜像：

```bash
./scripts/devin-bridge/build
```

仅对隔离的 Devin 卷进行身份验证：

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

登录命令使用面向远程/容器环境的官方手动令牌流程。该值直接输入 CLI 提示符；
不会作为进程参数传递、写入 Git，也不会从宿主机复制。

启动隔离的 Claude Code 运行时：

```bash
./scripts/devin-bridge/launch
```

`launch` 会在启动容器化 Claude Code 之前重新检查隔离状态、Devin 身份验证和模型发现。
它绝不会运行宿主机上的 Claude 可执行文件。模型别名可以在 `.env.devin-bridge` 中设置；
每个配置值都必须保留 `devin-cli-agentic/` 前缀。

## 验证命令

可复现的离线路径无需 Devin 账户，并且运行时不访问互联网：

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

经身份验证且需显式启用的实时路径为：

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

实时运行器会在不同场景之间等待，以避免突发创建 ACP 会话，并验证结构化的 Claude
流事件，而不是轻信文本声明。它的三个场景可证明：

1. 直接读取项目并分析缺陷；
2. 执行一次真实的 `Edit`、一次由客户端负责的 `Bash` `npm test`，并获得终端结果；
3. 执行 `/bridge-check` 加 `bridge-proof` 发现、读取项目、再次成功运行由客户端负责的
   `npm test`，并在没有待处理工作的情况下完成。

最终门禁还会检查 Devin 网络审计，并要求 Claude 出站审计保持为空。

## 诊断与清理

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  显示本地路由和经过清理的执行器错误。
- `.sandbox/evidence/mock-acp.jsonl` 记录确定性的模拟 ACP 操作。
- `.sandbox/evidence/claude-stream.jsonl` 记录真实的 Claude Code 离线运行。
- `.sandbox/evidence/live-*.jsonl` 记录三个已验证的在线流。
- `.sandbox/evidence/egress.jsonl` 和 `.sandbox/evidence/claude-egress.jsonl` 是经过验证且不含令牌的防护审计副本。

停止桥接器拥有的容器和网络，同时保留登录/配置卷：

```bash
./scripts/devin-bridge/clean
```

移除桥接器拥有的完整环境，包括命名卷：

```bash
./scripts/devin-bridge/clean --all
```

## 限制

- 该桥接器依赖固定的无工具 `summarizer` 角色，因为 Devin CLI `3000.2.17`
  未公开一个中立的无工具 ACP 代理。适配器会补偿摘要形式的中间响应，
  但一次有界修复仍可能明确失败。
- 在线 ACP 调用可能返回暂时性的 `502`/`504` 响应。测试工具会错开各场景的执行时间；
  持续失败时仍会采用故障关闭策略，且绝不会选择其他提供者。
- ACP 上下文会根据每个 Anthropic 请求重新构建；不存在进程/会话亲和性。
- 每个模型响应仅支持一次工具调用；并行调用会被拒绝。
- 明确不支持图像。不声明支持视觉、思考输出、投入程度控制和 1M 上下文窗口。
- SSE 使用有效的 Anthropic 生命周期事件，但会在收集完有界 ACP 轮次后发出；
  ACP 数据块不会被增量转发。
