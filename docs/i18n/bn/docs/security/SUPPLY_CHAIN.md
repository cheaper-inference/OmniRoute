OmniRoute npm + Docker আর্টিফ্যাক্ট প্রকাশ করে। এই গেটগুলি প্রোভেনেন্স, ইনভেন্টরি (SBOM) এবং CVE স্ক্যানিং প্রদান করে, যা সবই OSS এবং রিলিজ ওয়ার্কফ্লোতে সংযুক্ত।
**উপদেশ-প্রথম** অবস্থান — তারা এখন রিপোর্ট করে, প্রথম সবুজ রিলিজের পরে ব্লকিংয়ে উন্নীত করে।

| গেট                   | টুল                                            | কোথায়                        | ব্লক করে?                         | আউটপুট                                              |
| :-------------------- | :--------------------------------------------- | :---------------------------- | :-------------------------------- | :-------------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | শুধুমাত্র যদি প্রকাশ ব্যর্থ হয়   | ব্যাজ npmjs / `npm audit signatures`                |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | শুধুমাত্র যদি জেনারেশন ব্যর্থ হয় | রিলিজ অ্যাসেট + আর্টিফ্যাক্ট                        |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | উপদেশমূলক                         | CycloneDX আর্টিফ্যাক্ট                              |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | উপদেশমূলক                         | SARIF (HIGH+CRITICAL) → সিকিউরিটি ট্যাব             |
| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **ব্লকিং**                        | `exit-code: '1'` যদি ঠিক করা যায় এমন CRITICAL থাকে |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ব্লকিং**                        | `metrics.vulnCount` র্যাচেট করে (দিক: নিচে)         |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | উপদেশমূলক                         | SARIF → সিকিউরিটি + ব্যাজ                           |

ইমেজ CVE র্যাচেট `docker-publish.yml`-এ **দুটি ধাপ** ব্যবহার করে: SARIF ধাপ (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL-কে সিকিউরিটি ট্যাবে ব্লকিং ছাড়াই দৃশ্যমান রাখে; _CRITICAL গেট_ ধাপ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) একটি CRITICAL CVE-এর জন্য রিলিজ ব্যর্থ করে **যদি একটি ফিক্স উপলব্ধ থাকে**। `ignore-unfixed` একটি আপস্ট্রিম প্যাচ ছাড়া বেস-ইমেজ CVE-এর জন্য রিলিজ ব্লক করা প্রতিরোধ করে।

## ⚠️ CVE-এর পরিবর্তনশীলতা (ব্লকিং osv/Trivy গেটগুলো)

osv এবং Trivy নির্ভরতাগুলোকে এমন CVE ডেটাবেসের সঙ্গে তুলনা করে, যা **ক্রমাগত বৃদ্ধি পায়**। কোনো PR-এ **কোনো নির্ভরতা পরিবর্তন করা না হলেও**, বিদ্যমান কোনো নির্ভরতার জন্য নতুন CVE প্রকাশিত হওয়ার কারণে সেটি হঠাৎ ব্যর্থ হতে পারে (osv: পরিমাপকৃত `vulnCount` > বেসলাইন; Trivy: ইমেজে নতুন সমাধানযোগ্য CRITICAL)। **এটি ব্লকিং CVE গেটের প্রত্যাশিত পরিচালনাগত আচরণ, প্রোডাক্টের কোনো রিগ্রেশন নয়।**

নতুন প্রকাশিত CVE-এর কারণে osv বা Trivy ব্যর্থ হলে, প্রতিকার হলো:

1. **প্রভাবিত নির্ভরতার সংস্করণ বাড়ান** (অগ্রাধিকারযোগ্য) — `package.json`-এর `overrides` (পরোক্ষ নির্ভরতা) ব্যবহার করে প্যাচ করা সংস্করণে আপগ্রেড করুন অথবা প্যাচ করা বেসের ওপর ইমেজটি পুনর্নির্মাণ করুন।
2. **যদি আপস্ট্রিমে কোনো সমাধান না থাকে:**
   - **osv:** `config/quality/quality-baseline.json`-এ `metrics.vulnCount` পুনরায় বেসলাইন করুন (`npm run quality:ratchet -- --update` নিবেদিত গেটগুলোকে অন্তর্ভুক্ত করে না—একটি যৌক্তিকতার নোট + ট্র্যাকিং ইস্যুসহ মানটি হাতে সম্পাদনা করুন, `direction:down`)।
   - **Trivy:** `.trivyignore`-এ একটি এন্ট্রি যোগ করুন (প্রতি লাইনে একটি CVE-ID), সঙ্গে যৌক্তিকতার মন্তব্য + ট্র্যাকিং ইস্যু। প্যাচবিহীন CVE-গুলো ইতিমধ্যেই `ignore-unfixed: true` দ্বারা স্বয়ংক্রিয়ভাবে অন্তর্ভুক্ত হয়।

আবশ্যিক OSV এক্সিকিউশনগুলো (`check:vuln-ratchet -- --ratchet`) স্ক্যানার, রিপোর্ট বা বেসলাইন যাচাই করা না গেলে `INCOMPLETE` এবং এক্সিট কোড 2 দিয়ে ফেইল-ক্লোজড হয়। কোনো পরিমাপকৃত রিগ্রেশন হলে এক্সিট কোড 1 হয়। পরামর্শমূলক এক্সিকিউশন তবুও এক্সিট কোড 0 সহ `SKIP` রিপোর্ট করতে পারে, যা নির্ভরতাগুলো স্ক্যানে পাস করেছে—এটি প্রমাণ করে না। ব্লকিং Trivy ধাপেও একটি সফল পরিমাপ আবশ্যক: অনুপলভ্য টুল, ব্যর্থ জব এবং অনুপস্থিত ইমেজ-প্রমাণ কোনো ইমেজকে ঝুঁকিমুক্ত হিসেবে প্রত্যয়িত করতে পারে না।

## অবসরপ্রাপ্ত নির্ভরতার ঝুঁকি

পিন করা promptfoo ডেভেলপমেন্ট টুল আপগ্রেড করার পর রুট lockfile-এ আর `extract-zip` বা এটির দিকে নির্দেশকারী কোনো নির্ভরতা-সংযোগ অন্তর্ভুক্ত নেই। এর ফলে #14482-এ ট্র্যাক করা এবং আগে গ্রহণ করা `promptfoo` → `@openai/codex-security` → `extract-zip` শৃঙ্খলটি অবসরপ্রাপ্ত হয়েছে। `tests/unit/extract-zip-14482-exposure.test.ts`-এর রিগ্রেশন পরীক্ষাগুলো এটির পুনঃপ্রবর্তন প্রত্যাখ্যান করে এবং প্রোডাকশন কোড থেকে ইমপোর্ট করার ওপর নিষেধাজ্ঞা বজায় রাখে।

বর্তমান নির্ভরতা সংশোধনটি সামঞ্জস্যসংক্রান্ত override-গুলোর পরিধিও Azure identity-এর MSAL client, get-uri-এর FTP client এবং OpenCode v1 SDK-এর Zod নির্ভরতার মধ্যে সীমাবদ্ধ রাখে। Azure token সংগ্রহ এবং FTP retrieval নিয়ন্ত্রিত transport দিয়ে পরীক্ষা করা হয়; উভয় OpenCode package তাদের নিজস্ব build ও test suite চালায়। Registry advisory-এর সংখ্যা একটি নির্দিষ্ট সময়বিন্দুর পরিমাপ এবং lockfile commit করার পর পরিবর্তিত হতে পারে।
