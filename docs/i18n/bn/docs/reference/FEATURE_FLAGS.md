> ওই ফাইল থেকে তথ্য পড়ে, তাই নিচের টেবিলটি এর সঙ্গে 1:1 মিল রেখে তৈরি করা হয়েছে।

## ফিচার ফ্ল্যাগ কী

ফিচার ফ্ল্যাগ হলো একটি নামযুক্ত টগল (boolean বা enum), যার মান রানটাইমে
পরিবর্তন করে ডেটাবেসে সংরক্ষণ করা যায় এবং এর জন্য প্রসেস পুনরায় ডিপ্লয় করার
প্রয়োজন হয় না। প্রতিটি ফ্ল্যাগ একটি `FeatureFlagDefinition` দ্বারা বর্ণিত হয়,
যাতে একটি `key`, `label`, `description`, `category`, `defaultValue`, `type` এবং
একটি `requiresRestart` ইঙ্গিত থাকে।

### রেজোলিউশনের ক্রম

কোনো ফ্ল্যাগের **কার্যকর মান**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) দ্বারা নিচের
অগ্রাধিকার অনুযায়ী নির্ধারিত হয় (সর্বোচ্চ অগ্রাধিকার জয়ী হয়):

1. **DB ওভাররাইড** — `feature_flags` নেমস্পেসের অধীনে `key_value` টেবিলে
   সংরক্ষিত একটি মান (ড্যাশবোর্ড বা REST API-এর মাধ্যমে সেট করা হয়)।
2. **এনভায়রনমেন্ট ভেরিয়েবল** — `process.env[<KEY>]`, যদি সেট করা থাকে এবং খালি না হয়।
3. **সংজ্ঞার ডিফল্ট** — `featureFlagDefinitions.ts` থেকে নেওয়া `defaultValue`।

কোনো boolean ফ্ল্যাগের কার্যকর মান `"true"`, `"1"` বা `"yes"` হলে সেটিকে
**সক্রিয়** হিসেবে বিবেচনা করা হয় (`isFeatureFlagEnabled()` দেখুন)।

> [!NOTE]
> অধিকাংশ ফ্ল্যাগের জন্য [`ENVIRONMENT.md`](./ENVIRONMENT.md)-এ নথিভুক্ত
> **একই নামের** একটি সংশ্লিষ্ট এনভায়রনমেন্ট ভেরিয়েবলও রয়েছে। ফ্ল্যাগটির DB
> ওভাররাইড ওই এনভায়রনমেন্ট ভেরিয়েবলের চেয়ে অগ্রাধিকার পায়। `requiresRestart: true`
> থাকা কোনো ফ্ল্যাগ সঙ্গে সঙ্গে সংরক্ষিত হয়, তবে কেবল প্রসেস চালু হওয়ার সময়
> পুনরায় পড়া হয় — এটি টগল করলে ড্যাশবোর্ডে একটি **"সার্ভার পুনরায় চালু করুন"**
> ব্যানার প্রদর্শিত হয়।

## ফ্ল্যাগ ক্যাটালগ

৬টি বিভাগে মোট ১১৪টি ফ্ল্যাগ। **ডিফল্ট** হলো সংজ্ঞায়িত ডিফল্ট — যখন কোনো DB ওভাররাইড বা এনভায়রনমেন্ট ভেরিয়েবল উপস্থিত থাকে না, তখন ব্যবহৃত মান।

### নিরাপত্তা (১১)

| `INJECTION_GUARD_MODE`                  | enum    | `off`    | প্রম্পট ইনজেকশন গার্ড মোড। মান: `off`, `warn`, `block`, `redact`।                                                                                                                                                                                                                              |
| `PII_REDACTION_ENABLED`                 | boolean | `false`  | অনুরোধ থেকে PII রিড্যাক্ট করুন (`INPUT_SANITIZER_MODE` থেকে স্বাধীন)।                                                                                                                                                                                                                          |

| `PII_RESPONSE_SANITIZATION_MODE`        | enum    | `redact` | PII প্রতিক্রিয়া স্যানিটাইজেশনের মোড। মান: `redact`, `warn`, `block`, `off`।                                                                                                                                                                                                                   |
| `OUTBOUND_SSRF_GUARD_ENABLED`           | boolean | `true`   | লিগ্যাসি অ্যালিয়াস: এই ফ্ল্যাগের ড্যাশবোর্ড টগলে সংরক্ষিত মানটি এনভায়রনমেন্টের আগে পড়া হয়; যেকোনোটিতে `false`, `0`, `no`, বা `off` থাকলে `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`-এর মতো আউটবাউন্ড URL গার্ডের হোস্ট চেক বন্ধ হয়ে যায়।                                                    |
| `ALLOW_API_KEY_REVEAL`                  | boolean | `false`  | প্রমাণীকৃত ড্যাশবোর্ড ব্যবহারকারীদের সংরক্ষিত API কী প্রকাশ করার অনুমতি দিন, যাতে তারা শুধু মাস্ক করা মান না দেখেন।                                                                                                                                                                            |
| `AUTH_LOG_INCLUDE_ACCOUNT_ID`           | boolean | `false`  | AUTH লগ লাইনে অ্যাকাউন্টের উপসর্গ অন্তর্ভুক্ত করুন (যেমন, "Using <provider> account: abc12345...")। ডিফল্টভাবে নিষ্ক্রিয় থাকে, যাতে শেয়ারড/মাল্টি-টেন্যান্ট প্রসেস লগ থেকে অ্যাকাউন্ট শনাক্তকারী রিড্যাক্ট করা হয়। ডিবাগ মোড থেকে এটি স্বাধীন; ডিবাগ মোড পরিবর্তন করলেও এটি প্রকাশ পায় না। |
| `OMNIROUTE_OIDC_DISABLE_PASSWORD_LOGIN` | boolean | `false`  | OIDC সক্রিয় থাকলে পাসওয়ার্ড লগইন নিষ্ক্রিয় করুন, যাতে ব্যবহারকারীরা শুধু OIDC Single Sign-On-এর মাধ্যমে প্রমাণীকরণ করতে পারেন। নিষ্ক্রিয় থাকলে (ডিফল্ট), পাসওয়ার্ড লগইন এবং OIDC—উভয়ই উপলভ্য থাকে।                                                                                       |
| `API_KEY_AUDIT_CLIENT_DETAILS_ENABLED`  | boolean | `false`  | সফল API-কী মেটাডেটা এবং ডিসকভারি রিডের জন্য লেখা `api_key.auth.touch` অডিট-লগ সারিগুলোতে কলকারীর IP ঠিকানা এবং user-agent রেকর্ড করুন (#17982)। ডিফল্টভাবে বন্ধ: ওই সারিগুলোতে এখনও কোন কী ব্যবহার করা হয়েছে, কখন এবং কোন পাথে ব্যবহার করা হয়েছে তা রেকর্ড হয়, তবে IP বা user-agent নয়।    |

## ফ্ল্যাগ টগল করা

### ড্যাশবোর্ড

**Dashboard → Settings → Feature Flags**-এ যান
(`/dashboard/settings/feature-flags`)। গ্রিডটি
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
সমর্থন করে:

- কী বা বর্ণনা অনুসারে **অনুসন্ধান**, এবং বিভাগ অনুসারে **ফিল্টার** করা (এছাড়াও একটি কৃত্রিম
  **Requires Restart** ভিউ)।
- বুলিয়ান ফ্ল্যাগের জন্য একটি **টগল** এবং enum ফ্ল্যাগের জন্য একটি **ড্রপডাউন**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)।
- প্রতি ফ্ল্যাগে একটি **source badge** — `DB`, `ENV`, অথবা `DEF` — যা কার্যকর মানটি কোথা থেকে এসেছে তা দেখায়।
- একটি **Reset** বোতাম (শুধুমাত্র `DB`-সোর্সযুক্ত ফ্ল্যাগের জন্য দেখানো হয়), যা ওভাররাইড সরিয়ে দেয়, এবং নিচে একটি **Reset All Overrides** বোতাম।
- কোনো `requiresRestart` ফ্ল্যাগ পরিবর্তন করা হলে একটি **Restart Server** ব্যানার।

### REST API

সব অপারেশন একটি একক রুটের মাধ্যমে সম্পন্ন হয়:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)।
প্রতিটি মেথডের জন্য একটি প্রমাণীকৃত ড্যাশবোর্ড সেশন আবশ্যক (`401` অন্যথায়)।

#### `GET /api/settings/feature-flags`

প্রতিটি ফ্ল্যাগের কার্যকর মান, উৎস এবং একটি সারাংশ ফেরত দেয়।

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... সব 114টি ফ্ল্যাগ
  ],
  "summary": {
    "total": 114,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

একটি একক ওভাররাইড সেট বা সরান। বডি: `{ key: string; value?: string }`।
`value` বাদ দিলে ওভাররাইডটি সরানো হয় (env / default পুনরুদ্ধার করে)।

```bash
# একটি DB ওভাররাইড সেট করুন
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ওভাররাইডটি সরান ("value" ছাড়া)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

প্রতিক্রিয়ায় নতুন `effectiveValue`/`source`, `previousValue`/
`previousSource`, এবং `requiresRestart` ফেরত দেয়। অজানা কী এবং সীমার বাইরের enum
মান `400` দিয়ে প্রত্যাখ্যান করা হয়।

#### `DELETE /api/settings/feature-flags`

একসঙ্গে **সমস্ত** DB ওভাররাইড সরিয়ে দেয় এবং প্রতিটি ফ্ল্যাগকে তার env / default
মানে পুনরুদ্ধার করে। `{ cleared: <count>, message: "..." }` ফেরত দেয়।

> [!NOTE]
> `requiresRestart: true` থাকা ফ্ল্যাগগুলো কোনো প্রসেস রিলোড না হওয়া পর্যন্ত কার্যকর হয় না।
> ড্যাশবোর্ডের রিস্টার্ট ফ্লো `POST /api/restart` কল করে এবং সার্ভার পুনরায় চালু না হওয়া পর্যন্ত
> `GET /api/health/ping` পোল করে।

## জরুরি বাজেট ফলব্যাক

`OMNIROUTE_EMERGENCY_FALLBACK` (`runtime` বিভাগ, ডিফল্ট `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)-এ
জরুরি বিনামূল্যের ফলব্যাক পথ নিয়ন্ত্রণ করে। এটি সক্রিয় থাকলে, যেসব অনুরোধের
বাজেট শেষ হয়ে যায়, সেগুলো সরাসরি ব্যর্থ হওয়ার পরিবর্তে একটি বিনামূল্যের ফলব্যাক
প্রোভাইডার/মডেলে রাউট করা হয়। এই আচরণ নিষ্ক্রিয় করতে এবং বাজেট শেষ হয়ে যাওয়া
অনুরোধগুলোকে ব্যর্থ হতে দিতে ড্যাশবোর্ড টগল, একটি DB ওভাররাইড, অথবা
`OMNIROUTE_EMERGENCY_FALLBACK` এনভায়রনমেন্ট ভেরিয়েবলের মাধ্যমে এটিকে `false`
(অথবা `0`) সেট করুন। (PRs #3741 / #3752-এ ড্যাশবোর্ড টগল হিসেবে প্রদর্শিত।)

এই ফলব্যাকের মাধ্যমে পরিবেশিত প্রতিক্রিয়ায়
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` থাকে,
যাতে কোনো ক্লায়েন্ট তার অনুরোধের সঙ্গে `X-OmniRoute-Provider`-এর পার্থক্য যাচাই
না করেই বুঝতে পারে যে অনুরোধটি পুনরায় রাউট করা হয়েছিল। অন্য সব প্রতিক্রিয়ায়
এই হেডারটি অনুপস্থিত থাকে।
