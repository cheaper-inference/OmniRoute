## চ্যাট কমপ্লিশন

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### কাস্টম হেডার

| হেডার                    | দিক        | বিবরণ                                                                                                                                                                                                        |
| ------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `X-OmniRoute-No-Cache`   | রিকোয়েস্ট | ক্যাশ এড়িয়ে যেতে `true`-তে সেট করুন                                                                                                                                                                        |
| `x-omniroute-no-memory`  | রিকোয়েস্ট | এই রিকোয়েস্টের জন্য মেমরি + স্কিল ইনজেকশন এড়িয়ে যেতে `true`-তে সেট করুন (নো-ক্যাশের অনুরূপ; প্রতি-কল টোকেন/খরচের অতিরিক্ত ব্যয় এড়ায়)                                                                   |
| `X-OmniRoute-Progress`   | রিকোয়েস্ট | অগ্রগতি ইভেন্টের জন্য `true`-তে সেট করুন                                                                                                                                                                     |
| `X-Session-Id`           | রিকোয়েস্ট | এক্সটার্নাল সেশন অ্যাফিনিটির জন্য স্টিকি সেশন কী                                                                                                                                                             |
| `x_session_id`           | রিকোয়েস্ট | আন্ডারস্কোর ভ্যারিয়েন্টও গৃহীত হয় (সরাসরি HTTP)                                                                                                                                                            |
| `X-OmniRoute-Session-Id` | রিকোয়েস্ট | কলার-সরবরাহকৃত সেশন/কথোপকথন ট্যাগ (মেমরিতেও সরবরাহ করা হয়)। উপস্থিত থাকলে, প্রতি-সেশন খরচ অ্যাট্রিবিউশনের জন্য `call_logs.session_tag`-এ হুবহু সংরক্ষিত হয় (#8249) — অনুপস্থিত থাকলে কখনোই তৈরি করা হয় না |
| `Idempotency-Key`        | রিকোয়েস্ট | ডিডুপ কী (5s উইন্ডো)                                                                                                                                                                                         |
| `X-Request-Id`           | রিকোয়েস্ট | বিকল্প ডিডুপ কী                                                                                                                                                                                              |
| `x-omniroute-connection` | রিকোয়েস্ট | একটি সিঙ্গেল-মডেল রিকোয়েস্টকে তার id দিয়ে একটি প্রোভাইডার কানেকশনে (অ্যাকাউন্টে) পিন করুন — [প্রতি রিকোয়েস্টে অ্যাকাউন্ট পিনিং](#account-pinning-per-request) দেখুন                                       |
| `X-OmniRoute-Cache`      | রেসপন্স    | `HIT` অথবা `MISS` (নন-স্ট্রিমিং)                                                                                                                                                                             |
| `X-OmniRoute-Idempotent` | রেসপন্স    | ডিডুপ্লিকেট করা হলে `true`                                                                                                                                                                                   |
| `X-OmniRoute-Progress`   | রেসপন্স    | অগ্রগতি ট্র্যাকিং চালু থাকলে `enabled`                                                                                                                                                                       |
| `X-OmniRoute-Session-Id` | রেসপন্স    | OmniRoute দ্বারা ব্যবহৃত কার্যকর সেশন ID                                                                                                                                                                     |
| `X-OmniRoute-Request-Id` | রেসপন্স    | রিকোয়েস্ট কোরিলেশন id (জানা থাকলে)                                                                                                                                                                          |
| `X-OmniRoute-Version`    | রেসপন্স    | OmniRoute বিল্ড ভার্সন (সর্বদা উপস্থিত)                                                                                                                                                                      |
| `X-OmniRoute-Cost-Saved` | রেসপন্স    | HIT-এর ক্ষেত্রে ক্যাশের কারণে সাশ্রয় হওয়া USD (শুধু ক্যাশ হিট)                                                                                                                                             |
| `X-OmniRoute-Decision`   | রেসপন্স    | রাউটিং ট্রেস: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` হলো কম্বো স্ট্র্যাটেজি, অথবা নন-কম্বো রিকোয়েস্টের জন্য `single`) — সম্পন্ন হওয়া রেসপন্সে সর্বদা উপস্থিত                        |

> Nginx নোট: আপনি যদি আন্ডারস্কোরযুক্ত হেডারের ওপর নির্ভর করেন (যেমন `x_session_id`), তাহলে `underscores_in_headers on;` সক্রিয় করুন।

#### প্রতিটি অনুরোধের জন্য অ্যাকাউন্ট পিনিং

কোনো প্রোভাইডারের একাধিক সংযোগ (অ্যাকাউন্ট বা কী) থাকলে, OmniRoute সাধারণত তার
অ্যাকাউন্ট-নির্বাচন কৌশলের মাধ্যমে একটি বেছে নেয়। এর পরিবর্তে, একটি অনুরোধ
`x-omniroute-connection` হেডারের মাধ্যমে নির্দিষ্ট একটি সংযোগ পিন করতে পারে:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **আইডি কোথায় পাবেন।** ড্যাশবোর্ডে প্রোভাইডারের পৃষ্ঠা খুলুন
  (**Dashboard → Providers → <provider>**) এবং কোনো সংযোগের সারিতে থাকা `xxxxxxxx…` আইডি চিপে ক্লিক করুন
  — এতে সম্পূর্ণ সংযোগ আইডিটি কপি হবে।
- **কোন অনুরোধগুলো এটি মানে।** `/v1/chat/completions`, `/v1/messages` এবং
  `/v1/responses`-এর একক-মডেল অনুরোধ (`provider/model`)। কম্বোগুলো হেডারটি উপেক্ষা করে: এর পরিবর্তে
  প্রতিটি কম্বো ধাপের নিজস্ব সংযোগের মাধ্যমে সেই ধাপের জন্য একটি অ্যাকাউন্ট পিন করুন।
- **পিনটি কঠোর, এটি কেবল একটি পছন্দ নয়।** পিন করা সংযোগটিই একচেটিয়াভাবে ব্যবহৃত হয়। কোনো
  অনুরোধের মধ্যে ব্যর্থতা ঘটলে অ্যাকাউন্টটির কুলডাউন রেকর্ড করা হয়, কিন্তু একই প্রোভাইডারের
  অন্য কোনো সমপর্যায়ের অ্যাকাউন্টে **পরিবর্তন করা হয় না**।
- **কুলডাউন ও কোটা পিনটি মুক্ত করে।** পিন করা সংযোগটি কুলডাউনে থাকা অবস্থায়,
  কোটা নিঃশেষ হয়ে গেলে বা কোনো কোটা নীতির কারণে ব্লক হলে, পরবর্তী অনুরোধগুলো আনপিন করা ট্রাফিকের
  মতোই প্রোভাইডারের অন্যান্য সংযোগে ফলব্যাক করে।
- **অজানা বা নিষ্ক্রিয় আইডি ব্যর্থ হয়।** প্রোভাইডারের সক্রিয় পুলে নেই এমন কোনো আইডি (মুছে ফেলা,
  নিষ্ক্রিয় করা, বা অন্য প্রোভাইডারের অন্তর্ভুক্ত) কোনো যোগ্য অ্যাকাউন্ট অবশিষ্ট রাখে না, তাই অনুরোধটি
  নীরবে অন্য কোথাও রাউট হওয়ার পরিবর্তে ব্যর্থ হয়।

Claude Code `ANTHROPIC_CUSTOM_HEADERS`-এর মাধ্যমে কাস্টম হেডার পাঠায়। এটি
`~/.claude/settings.json`-এর `env` ব্লকে রাখুন, অথবা প্রতিটি প্রজেক্টের জন্য আলাদা
অ্যাকাউন্ট পিন করতে প্রজেক্ট-লেভেলের `.claude/settings.json`-এ রাখুন:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

উৎস: `src/sse/handlers/chat.ts` (হেডার পড়া), `src/sse/services/auth.ts` এবং
`src/sse/services/sessionAffinityPin.ts` (পিন মুক্ত করা এবং পুলে অনুপস্থিতির পরীক্ষা)।

> **খরচের টেলিমেট্রি হেডার:** নন-স্ট্রিমিং সফল প্রতিক্রিয়াগুলোতে `X-OmniRoute-*` খরচ-টেলিমেট্রি সেটও থাকে — `X-OmniRoute-Response-Cost` (USD, নির্দিষ্ট ১০ দশমিক স্থান; বিনামূল্যের/মূল্যবিহীন ব্যবহারের জন্য `0.0000000000`), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, এবং `X-OmniRoute-Fallback-Attempts` (শুধু > 0 হলে), সঙ্গে `X-OmniRoute-Request-Id` ও `X-OmniRoute-Version`। এগুলো চ্যাট কমপ্লিশন, `/v1/responses`, `/v1/messages`, **এবং মিডিয়া এন্ডপয়েন্টগুলোও** নির্গত করে — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations`, এবং `/v1/moderations` (খরচ সর্বদা `0`)। মূল্য উপলভ্য থাকলে প্রতিটি মোডালিটি অনুযায়ী (প্রতি-ছবি, প্রতি-সেকেন্ড, প্রতি-অক্ষর, প্রতি সার্চ-ইউনিট) মিডিয়ার খরচ গণনা করা হয়, অন্যথায় `0` (ফেইল-ওপেন)।

> **ক্যাশ-হিট খরচের অর্থ:** কোনো সেম্যান্টিক-ক্যাশ HIT-এ (`X-OmniRoute-Cache-Hit: true`) কোনো আপস্ট্রিম কল করা হয় না, তাই `X-OmniRoute-Response-Cost` হলো `0.0000000000` (হিটটি পরিবেশনের **ক্রমবর্ধমান** খরচ)। মূল/সম্ভাব্য খরচটি আলাদাভাবে `X-OmniRoute-Cost-Saved`-এ রিপোর্ট করা হয়। বিলিং গ্রাহকদের `X-OmniRoute-Response-Cost`-এর যোগফল নেওয়া উচিত (হিটের কোনো খরচ নেই); ক্যাশ অ্যানালিটিক্স `X-OmniRoute-Cost-Saved` সমষ্টিবদ্ধ করতে পারে।

## একচেটিয়া পরিচালিত সেশন লিজ

একচেটিয়া পরিচালিত সেশন লিজিং হলো একটি অপ্ট-ইন, ক্লায়েন্ট-নিরপেক্ষ রাউটিং চুক্তি: একজন সক্রিয় মালিক
একটি যোগ্য OmniRoute সংযোগ ধরে রাখে। এটি কোনো মডেল লিজ দেয় না, OAuth আবশ্যক করে না, কোনো
নির্দিষ্ট ক্লায়েন্টকে শনাক্ত করে না বা কোনো নির্দিষ্ট প্রদানকারী আবশ্যক করে না।

প্রমাণীকরণকারী API কীটির স্কোপ `lease:exclusive` এবং একটি সুস্পষ্ট, খালি নয় এমন
`allowedConnections` তালিকা থাকতে হবে। কী তৈরি এবং আংশিক আপডেটের সময় ডেটাবেস মিউটেশন সীমা
দুটি ফিল্ডকেই একসঙ্গে প্রয়োগ করে।

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

সফল অধিগ্রহণ, নবায়ন এবং মুক্তির প্রতিক্রিয়াগুলো টাইমস্ট্যাম্প, `state` এবং সঠিক ধনাত্মক
`generation` প্রকাশ করে, তবে নির্বাচিত সংযোগ বা শংসাপত্র কখনোই প্রকাশ করে না। নবায়ন এবং মুক্তির ক্ষেত্রে
JSON বডিতে generation সরবরাহ করা হয়:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

একজন সক্রিয় লিজ মালিক তার বর্তমান বাইন্ডিংয়ের জন্য গোপনীয়তা-নিরাপদ প্রদর্শন মেটাডেটা স্পষ্টভাবে অনুরোধ করতে পারে:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

এই অপ্ট-ইন স্ট্যাটাস অ্যাকশনটি একটি ডেটাবেস ট্রানজ্যাকশনের মধ্যেই অস্বচ্ছ মালিক, প্রমাণীকৃত পরিচালিত API কী এবং সঠিক
সক্রিয় generation দ্বারা সুরক্ষিত। `displayName` কেবল ছাঁটাই করা কনফিগার্ড
সংযোগের নাম; কোনো নিরাপদ কনফিগার্ড নাম না থাকলে এটি `null` হয়। OmniRoute কখনো কোনো
ইমেইল বা জেনারেট করা অ্যাকাউন্ট পরিচয় দিয়ে এটি প্রতিস্থাপন করে না। প্রদানকারীর মানটি একটি সংবেদনশীল নয় এমন প্রদর্শন লেবেল এবং কখনোই
জেনারেট করা সামঞ্জস্যপূর্ণ-প্রদানকারী শনাক্তকারী নয়। শংসাপত্র, টোকেন, কুকি, কাঁচা সংযোগ বা API
কী আইডি, মালিকের হ্যাশ, ফেন্সিং সিক্রেট এবং অভ্যন্তরীণ রাউটিং ডেটা বাদ দেওয়া হয়।

ভুল-কী, ভুল-মালিক, পুরোনো-generation, অনুপস্থিত, মেয়াদোত্তীর্ণ, মুক্ত এবং অবৈধ করা লুকআপগুলো
সংযোগ মেটাডেটা ছাড়াই একই `409 LEASE_FENCE_STALE` ত্রুটি ফেরত দেয়। যে ক্লায়েন্ট ক্যাপাসিটি-অপেক্ষা প্রতিক্রিয়া পেয়েছে, তার পরিদর্শন করার মতো কোনো সক্রিয় বাইন্ডিং নেই। রাউটিং যখন কোনো সক্রিয় লিজকে স্থানান্তর করে,
তখন একই generation বৈধ থাকে এবং স্ট্যাটাস পারমাণবিকভাবে নতুন বাইন্ডিংটি ফেরত দেয়, পুরোনোটি কখনোই নয়।
বিদ্যমান ক্লায়েন্টগুলো অপরিবর্তিত থাকে, কারণ অধিগ্রহণ, নবায়ন, মুক্তি এবং অপেক্ষার প্রতিক্রিয়াগুলো
তাদের পূর্ববর্তী কাঠামো বজায় রাখে।

এই সার্ভার চুক্তি মূল OpenAI Codex `/status` পরিবর্তন করে না। মূল Codex বর্তমানে তার
মডেল প্রদানকারী এবং অন্তর্নির্মিত প্রমাণীকরণ/অ্যাকাউন্টের অবস্থা জানায়, কিন্তু নির্বিচার কাস্টম
প্রদানকারী অ্যাকাউন্ট মেটাডেটা রেন্ডার করে না; পরবর্তী কোনো ক্লায়েন্ট ইন্টিগ্রেশনকে এই অ্যাকশনটি কল করতে হবে এবং
`connection.displayName` কীভাবে প্রদর্শন করা হবে তা নির্ধারণ করতে হবে।

এরপর প্রতিটি পরিচালিত ইনফারেন্স অনুরোধে উভয় নিয়ন্ত্রণ হেডার সরবরাহ করা হয়:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

প্রতিটি সমর্থিত আপস্ট্রিম প্রচেষ্টার ঠিক আগে সঠিক মালিক, generation, সক্রিয় সংযোগ এবং প্রমাণীকৃত API কী
ফেন্স করা হয়। অন্য কী দিয়ে মালিক এবং generation পুনরায় ব্যবহার করা ব্যর্থ হয়,
এমনকি সেই কী একই সংযোগের অনুমতি দিলেও। কাঁচা মালিকের মান সংরক্ষণ, লগ বা
অনুরোধের স্ন্যাপশটে ধরে রাখা হয় না এবং আপস্ট্রিমেও ফরওয়ার্ড করা হয় না।

সাময়িক প্রতিযোগিতার ক্ষেত্রে HTTP `429`, `Retry-After` এবং নিচের প্রতিক্রিয়া ফেরত দেওয়া হয়:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

এই প্রতিক্রিয়ার অর্থ শুধু এটুকুই যে সাধারণ যোগ্য সেটটি খালি ছিল না এবং প্রতিটি মুক্ত প্রার্থী
অন্য কোনো সক্রিয় লিজের অধীনে ছিল। অসমর্থিত মডেল/প্রদানকারী, নীতির অমিল, কুলডাউন, কোটা,
স্বাস্থ্য এবং অন্যান্য সাধারণ যোগ্যতা-সংক্রান্ত ব্যর্থতার ক্ষেত্রে বিদ্যমান OmniRoute প্রতিক্রিয়াগুলোই বহাল থাকে।

### `x-omniroute-compression`

প্রতি-অনুরোধে কম্প্রেশন পরিকল্পনা ওভাররাইড করা। এর অগ্রাধিকার সর্বোচ্চ—এটি রাউটিং-কম্বো
ওভাররাইড, সক্রিয় প্রোফাইল, স্বয়ংক্রিয় ট্রিগার এবং প্যানেলের ডিফল্টকে অগ্রাহ্য করে। মানসমূহ:

| মান           | প্রভাব                                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------------------------ |
| `off`         | এই অনুরোধের জন্য কোনো কম্প্রেশন নয়।                                                                         |
| `default`     | প্যানেল থেকে প্রাপ্ত ডিফল্ট প্রোফাইল (সক্রিয় প্রোফাইল উপেক্ষা করে)। ক্ষতিসাধনকারী ইঞ্জিনগুলো বন্ধ রাখা হয়। |
| `safe`        | শুধু ডিডুপ এবং হোয়াইটস্পেস ফোল্ডিং।                                                                         |
| `allow-lossy` | সারাংশ এবং স্টাইল পুনর্লিখনসহ এই অনুরোধের জন্য অপারেটর পরিকল্পনাটি বজায় রাখে।                               |
| `engine:<id>` | সক্রিয় থাকলে একটি একক ইঞ্জিন, যেমন `engine:rtk`। সেই ইঞ্জিনের জন্য প্রতি-অনুরোধে অপ্ট-ইন।                   |
| `<combo>`     | একটি নামযুক্ত কম্বো, যা প্রথমে নাম (কেস-ইনসেনসিটিভ) এবং তারপর আইডি অনুযায়ী মেলানো হয়।                      |

নোট:

- অজানা মানগুলো উপেক্ষা করা হয় (অনুরোধটি কখনো প্রত্যাখ্যাত হয় না); রেজোলিউশন স্বাভাবিক অপারেটর অগ্রাধিকার অনুসরণ করে।
- একাধিক কম্বোর নাম একই হলে, নির্ধারিত মিলের জন্য কম্বোর **আইডি** দিন।
- যে কম্বোর নাম `off` বা `default`, সেটিকে নাম দিয়ে নির্বাচন করা যায় না (এই কীওয়ার্ডগুলো আগে ব্যাখ্যা করা হয়); এমন কম্বোকে তার আইডি দিয়ে উল্লেখ করুন।
- মাস্টার কম্প্রেশন সুইচটি একটি কঠোর গেট: কম্প্রেশন বিশ্বব্যাপী নিষ্ক্রিয় থাকলে, এই হেডার দিয়ে তা সক্রিয় করা যায় না।

প্রয়োগ করা পরিকল্পনাটি প্রতিক্রিয়ার হেডারে প্রতিধ্বনিত হয়:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

যেখানে `<source>` হলো `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, অথবা `off`-এর যেকোনো একটি।

## এম্বেডিং

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

উপলভ্য প্রদানকারী: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI।

ক্যাটালগ আইডিগুলো হলো `provider/model` (উদাহরণ: `jina-ai/jina-embeddings-v5-omni-small`)। রেজিস্ট্রিতে থাকা শুধু Jina মডেল আইডিগুলোও (যেমন `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) সমাধান করা হয়। Jina embed/rerank/classify/segment প্রথমে ড্যাশবোর্ডের `jina-ai` শংসাপত্র ব্যবহার করে; কোনো ড্যাশবোর্ড কী না থাকলেই কেবল `JINA_AI_API_KEY` ফলব্যাক হিসেবে ব্যবহৃত হয়। `jina-reader` কার্ডটি কেবল Reader / `r.jina.ai`-এর জন্য (`POST /v1/web/fetch`) এবং কখনোই এম্বেডিং বা রির্যাঙ্ক পরিবেশন করে না।

যেসব রেজিস্ট্রি মডেল মাল্টিমোডাল সমর্থনের কথা উল্লেখ করে, সেগুলো প্রদানকারী-নিরপেক্ষ সর্বোচ্চ ৩২টি স্ট্রাকচার্ড
আইটেমও গ্রহণ করে। মিডিয়া আইটেমের ধরন হলো `text`, `image`, `audio`, `video`, এবং `document`। সেগুলোর মিডিয়া `source`
হয় `{"type":"url","url":"https://..."}`, অথবা
`{"type":"base64","data":"...","media_type":"..."}`।

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
এবং ফ্যামিলি অ্যালিয়াস `jina-ai/jina-embeddings-v5-omni` → omni-small) Jina-এর নেটিভ
EmbeddingsV5Request ডকও গ্রহণ করে এবং সেগুলো **অপরিবর্তিত অবস্থায় ফরওয়ার্ড করে** `https://api.jina.ai/v1/embeddings`-এ:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

নেটিভ `{ image | audio | video | pdf }` মান একটি সর্বজনীন HTTPS URL, একটি `data:` URI, অথবা কাঁচা
base64 হতে পারে। OmniRoute ওই অবজেক্টগুলোকে স্ট্রিংয়ে রূপান্তর করে না বা নেটিভ ইমেজ URL ফেচ করে না—Jina নিজেই
সর্বজনীন মিডিয়া সংগ্রহ করে। অতিরিক্ত Jina ফিল্ড (`task`, `normalized`, `truncate`, `embedding_type`)
ফরওয়ার্ড করা হয়। শুধু-টেক্সট Jina SKU এখনো নন-টেক্সট ডক প্রত্যাখ্যান করে।

নিরাপত্তা ও ট্রান্সপোর্টের সীমা:

- রিমোট মিডিয়া URL অবশ্যই সর্বজনীন HTTPS হতে হবে। ক্যানোনিক্যাল `{type,source:url}` আইটেমগুলো
  সার্ভার-সাইডে ফেচ করা হয় (রিডাইরেক্ট পুনরায় যাচাইকরণ, টাইমআউট, আকারের সীমা, সর্বজনীন DNS, সংযোগ পিনিং) এবং
  প্রদানকারীকে কল করার আগে ইনলাইন করা হয়। Jina-নেটিভ `{image:"https://..."}` আইটেম একই সর্বজনীন-HTTPS যাচাইয়ের
  পর অপরিবর্তিত অবস্থায় ফরওয়ার্ড করা হয়; Jina URL-টি ফেচ করে।
- ইনলাইন base64 মিডিয়া প্রতি আইটেমে ডিকোড করা অবস্থায় সর্বোচ্চ 8 MiB এবং পুরো অনুরোধজুড়ে ডিকোড করা অবস্থায় 16 MiB-এর মধ্যে সীমাবদ্ধ।

প্রদানকারী অনুবাদ (ক্যানোনিক্যাল আইটেম কখনোই অপরিবর্তিত অবস্থায় ফরওয়ার্ড করা হয় না):

- Jina মাল্টিমোডাল মডেল: প্রতিটি টপ-লেভেল আইটেম একটি মোডালিটি-কীযুক্ত অবজেক্টে পরিণত হয়
  (`text` / `image` / `audio` / `video` / `pdf`), যেখানে ইনলাইন মিডিয়ার জন্য data URI ব্যবহৃত হয়; প্রতি
  টপ-লেভেল আইটেমে একটি ভেক্টর।
- Gemini Embedding 2 ফ্যামিলি: একটি টপ-লেভেল অ্যারে `content.parts` (`text` বা `inline_data`) সহ একটি একক নেটিভ
  `models/{model}:embedContent` অনুরোধে পরিণত হয়।
- llama.cpp (`llama-cpp/<model>`, স্থানীয় সার্ভারে লোড করা যেকোনো মডেল): ক্যানোনিক্যাল `text` আইটেম
  সাধারণ স্ট্রিংয়ে পরিণত হয়, এবং `image` / `audio` / `video` প্রতিটি একটি
  `{"content": [part]}` অবজেক্টে পরিণত হয়, যেখানে ইনলাইন ডেটাসহ llama-server-এর চ্যাট কনটেন্ট পার্ট (`image_url`,
  `input_audio` এবং `wav` / `mp3` / `flac` ফরম্যাট, `input_video`) ব্যবহৃত হয়; প্রতি টপ-লেভেল আইটেমে
  একটি ভেক্টর। সার্ভারটি অবশ্যই `--embedding --mmproj …` দিয়ে চালাতে হবে; প্রজেক্টর না থাকলে এটি
  নিজেই মিডিয়া প্রত্যাখ্যান করে। `document` সমর্থিত নয়।
- স্পষ্ট মোডালিটি মেটাডেটাবিহীন অজানা/ডায়নামিক মডেলগুলো HTTP 400 সহ স্ট্রাকচার্ড ইনপুট প্রত্যাখ্যান করে।

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

অসমর্থিত মডেল/মোডালিটি সমন্বয় আইটেমটিকে জোরপূর্বক রূপান্তর না করে HTTP 400 ফেরত দেয়। লিগ্যাসি স্ট্রিং/টোকেন
অনুরোধের ইনপুট-বহির্ভূত এক্সটেনশন ফিল্ডগুলো আগের মতোই অপরিবর্তিত অবস্থায় পাস-থ্রু হয়।

```bash
# সব এম্বেডিং মডেলের তালিকা দেখুন
GET /v1/embeddings
```

## ছবি তৈরি

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

উপলভ্য প্রোভাইডারগুলোর মধ্যে রয়েছে OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (লোকাল), ComfyUI (লোকাল)।

`n`, `data[]`-এ `n`টি ছবি ফেরত দেয়। যেসব প্রোভাইডারের আপস্ট্রিম API প্রতিটি কলে একটি ছবি ফেরত দেয়
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI), তাদের জন্য আলাদা `n`টি আপস্ট্রিম কল করা হয়, যেখানে একই সময়ে সর্বোচ্চ 4টি কল চলমান থাকে। একটি
নির্দিষ্ট `seed` কলের সূচক অনুযায়ী অফসেট করা হয় (`seed`, `seed + 1`, …), ফলে ছবিগুলো ভিন্ন হলেও
পুনরুৎপাদনযোগ্য থাকে। `n`-এর সর্বোচ্চ সীমা 10। কোনো কল ব্যর্থ হলে সম্পূর্ণ অনুরোধটি
ব্যর্থ হয়। ফ্যান-আউট ফরম্যাটগুলোর তালিকা `SINGLE_IMAGE_FANOUT_FORMATS`-এ রয়েছে,
`open-sse/handlers/imageGeneration/fanOut.ts` ফাইলে।

ZenMux বিদ্যমান API-কী সংযোগ পুনরায় ব্যবহার করে এবং `zenmux/` বা `zm/` প্রিফিক্স গ্রহণ করে:

- `zenmux/openai/gpt-image-2` ZenMux-এর OpenAI Images API ব্যবহার করে। অপশনগুলোর মধ্যে রয়েছে `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background`, এবং `response_format`।
- অন্যান্য পাবলিশার, যেমন `zm/meta/muse-image-1.0`, ZenMux-এর Vertex AI `:predict`
  এন্ডপয়েন্ট ব্যবহার করে। `n`, `sampleCount`-এ; `aspect_ratio`, `aspectRatio`-তে; এবং `image_size`
  (`1K`, `2K`, `4K`), `sampleImageSize`-এ ম্যাপ হয়। পিক্সেলভিত্তিক `size` কেবল একটি অ্যাসপেক্ট রেশিও সরবরাহ করে,
  নিশ্চিত পিক্সেল ডাইমেনশন নয়। সমর্থিত রেশিও, রেজোলিউশন এবং সংখ্যা মডেলভেদে পরিবর্তিত হয়।
- `zm/inclusionai/ming-image-0.1-design` নিজস্ব ডাইমেনশন বেছে নেয়। `size`,
  `aspect_ratio`, এবং `image_size` বাদ দিন; স্পষ্টভাবে মান দিলে HTTP 400 ফেরত আসে। `output_format` দিয়ে PNG, JPEG, এবং WebP
  অনুরোধ করা যায়।

এই ইন্টিগ্রেশন টেক্সট-টু-ইমেজ জেনারেশন সমর্থন করে, রেফারেন্স-ইমেজ এডিটিং নয়। Vertex-এর
আউটপুট `data[].b64_json`-এ স্বাভাবিকীকরণ করা হয়; `response_format: "url"` একটি আপস্ট্রিম
HTTPS URL ফেরত দেয়, অথবা কেবল ছবির বাইট উপলভ্য থাকলে একটি base64 data URL ফেরত দেয়। খালি/ফিল্টার করা আউটপুট
খালি সফল প্রতিক্রিয়ার পরিবর্তে একটি ত্রুটি ফেরত দেয়। মডেলে অ্যাক্সেস ZenMux অ্যাকাউন্টের ওপর নির্ভর করে।
দেখুন [ZenMux-এর Vertex API](https://docs.zenmux.ai/api/vertexai/generate-images) এবং
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image)।

```bash
# সব ইমেজ মডেলের তালিকা দেখান
GET /v1/images/generations
```

## নথির OCR

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model` একটি `provider/model` প্রিফিক্সের মাধ্যমে OCR প্রোভাইডার নির্বাচন করে; শুধু একটি মডেল আইডি (যেমন
`mistral-ocr-latest`) দিলে সেটি তার নিবন্ধিত প্রোভাইডারে রেজলভ হয়, এবং `model` বাদ দিলে ডিফল্ট হিসেবে
Mistral (`mistral-ocr-latest`) ব্যবহৃত হয়। নিবন্ধিত প্রোভাইডারগুলো (`open-sse/config/ocrRegistry.ts`):

| প্রোভাইডার আইডি               | মডেল আইডি            | `model`-এর মান                                                | মন্তব্য                                                                                                                   |
| ----------------------------- | -------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (অথবা শুধু `mistral-ocr-latest`) | সিঙ্ক্রোনাস — একক আপস্ট্রিম কল থেকে প্রতিক্রিয়াটি সরাসরি ফেরত দেওয়া হয়।                                                |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                   | অ্যাসিঙ্ক্রোনাস আপস্ট্রিম (`analyze` + পোল) — নিচে দেখুন।                                                                 |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                       | সিঙ্ক্রোনাস, Vertex AI-এর `openapi/chat/completions` পার্টনার এন্ডপয়েন্টের মাধ্যমে — অথেন্টিকেশন/URL-এর জন্য নিচে দেখুন। |

তিনটি প্রোভাইডারই একই Mistral-আকৃতির বডিতে প্রতিক্রিয়া দেয়:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Azure Document Intelligence-এর পোল প্রবাহ

Azure Document Intelligence-এর `analyze` API অ্যাসিঙ্ক্রোনাস: প্রাথমিক অনুরোধটি বডির পরিবর্তে একটি
`Operation-Location` হেডার ফেরত দেয়, এবং ফলাফলের জন্য পোল করতে হয়। হ্যান্ডলারটি
(`open-sse/handlers/ocr.ts`) ওই URL-এ প্রতি সেকেন্ডে একবার করে সর্বোচ্চ 30 বার পোল করে, কোনো non-`ok` পোল প্রতিক্রিয়া বা
`"failed"` স্ট্যাটাস পেলে দ্রুত ব্যর্থ হয় (পোল চালিয়ে যায় না), এবং নির্ধারিত প্রচেষ্টার সীমা শেষ হওয়ার পরও
অপারেশনটি চলতে থাকলে `504` ফেরত দেয়। কলারের কাছে ফেরত দেওয়ার আগে চূড়ান্ত Azure প্রতিক্রিয়াটি
Mistral-এর ব্যবহৃত একই `pages`/`markdown` কাঠামোতে স্বাভাবিকীকরণ করা হয়, ফলে ক্লায়েন্ট কোডে
প্রোভাইডারটির জন্য বিশেষ ব্যবস্থা নেওয়ার প্রয়োজন হয় না।

### Vertex AI DeepSeek OCR-এর অথেন্টিকেশন এবং এন্ডপয়েন্ট রেজোলিউশন

`vertex-deepseek-ocr`, চ্যাট/ইমেজ ট্রাফিকের জন্য OmniRoute ইতিমধ্যে সমর্থন করে এমন একই Vertex AI অথেন্টিকেশন
(`open-sse/executors/vertex.ts`) পুনরায় ব্যবহার করে: সংযোগটির API কী হয় একটি
সার্ভিস অ্যাকাউন্ট JSON ক্রেডেনশিয়াল (যা JWT-bearer প্রবাহের মাধ্যমে স্বল্পমেয়াদি OAuth অ্যাক্সেস টোকেনে
বিনিময় করা হয়), অথবা আগে থেকেই তৈরি করা একটি OAuth অ্যাক্সেস টোকেন, যা অপরিবর্তিতভাবে ব্যবহৃত হয়। আপস্ট্রিম এন্ডপয়েন্ট URL হলো Vertex-এর
সাধারণ `openapi/chat/completions` পার্টনার এন্ডপয়েন্ট, যা সংযোগটির প্রজেক্ট এবং
রিজিয়ন থেকে তৈরি করা হয় — স্পষ্টভাবে দেওয়া `providerSpecificData.project`/`providerSpecificData.region` সর্বদা অগ্রাধিকার পায়;
অন্যথায় প্রজেক্টটি সার্ভিস অ্যাকাউন্ট JSON-এর `project_id` থেকে নির্ধারণ করা হয় এবং রিজিয়নের
ডিফল্ট মান হয় `us-central1`। উভয় রেজোলিউশনই `open-sse/handlers/ocr.ts`-এ ঘটে
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), যা
`handleOcr`-এ পাঠানোর আগে `src/app/api/v1/ocr/route.ts` ব্যবহার করে।

### মডেলের মূল্য (`pricing`)

OmniRoute যখন কোনো মডেলের মূল্য জানে, তখন একটি এন্ট্রিতে `pricing` অবজেক্ট থাকে। মূল্যটি আসে
খরচ হিসাবের জন্য ব্যবহৃত মূল্যতালিকা থেকে: বিল্ট-ইন ডিফল্ট, সিঙ্ক করা মূল্য এবং
`/api/pricing`-এর মাধ্যমে নির্ধারিত ওভাররাইড। এগুলো তালিকাভুক্ত মূল্য, তাই সাবস্ক্রিপশন প্রদানকারীরাও
প্রতি-টোকেন মূল্য দেখায়।

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| ফিল্ডসমূহ                                                       | একক                             | নোট                                                                                                                                        |
| --------------------------------------------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | প্রতি টোকেনে USD, দশমিক স্ট্রিং | OpenRouter-সামঞ্জস্যপূর্ণ, কখনোই সূচকীয় নোটেশনে নয়। ক্যাশের মূল্য থাকলেই কেবল দুটি ক্যাশ ফিল্ড দেখা যায়।                                |
| `input`, `output`, `cached`, `cache_creation`                   | প্রতি 1M টোকেনে USD, সংখ্যা     | ক্যাটালগের আগের সংস্করণগুলোর ফিল্ড, বিদ্যমান ক্লায়েন্টের জন্য রাখা হয়েছে। মূল্য সারিতে থাকলে `reasoning` এবং `long_context`-ও দেখা যায়। |

- **কম্বোসমূহে** তাদের প্রথম দৃশ্যমান টার্গেটের মূল্য থাকে। বিল্ট-ইন `auto/*` কম্বোগুলো
  অনুরোধের সময় একটি টার্গেট বেছে নেয়, তাই সেগুলোতে কোনো `pricing` থাকে না।
- **বিনামূল্যের মডেলগুলোতে** মূল্য শূন্য হলে `"0"` (এবং `0`) দেখানো হয়। কোনো মডেলের জন্য মূল্যের সারি
  না থাকলেও, ক্যাটালগ সেটিকে বিনামূল্যের হিসেবে চিহ্নিত করলে (`free: true`) অথবা বিল্ট-ইন বিনামূল্যের-মডেল
  ক্যাটালগে সেটি তালিকাভুক্ত থাকলে `"0"` দেখানো হয়।
- **অজানা মূল্য:** এন্ট্রিটিতে কোনো `pricing` কী থাকে না।
- **ক্রেডিট-ভিত্তিক মিটারিং প্রদানকারীরা** (যেমন Kiro) প্রতি টোকেনের পরিবর্তে প্রতি অনুরোধে বিল করে। তাদের
  এন্ট্রিগুলোতে আগের সংখ্যাসূচক প্রতি-1M ফিল্ডগুলো বজায় থাকে এবং কোনো প্রতি-টোকেন স্ট্রিং ফিল্ড থাকে না।
- **ভ্যারিয়েন্টগুলো** (রিজনিং-এফোর্ট আইডি, নো-থিংকিং অ্যালিয়াস, ডিসকভারি ও গেটওয়ে মিরর)
  যে মডেলে রাউট করে, সেটির মূল্য অনুলিপি করে।
- ফিল্ডগুলোতে শুধু ভিত্তিমূল্য থাকে। লং-কনটেক্সট স্তর (`long_context` সংখ্যাসূচক ফিল্ড) এবং
  সার্ভিস-টিয়ার গুণক (যেমন Codex fast বা flex) `prompt` বা
  `completion` পরিবর্তন করে না।
- Anthropic-ধাঁচের `x-api-key` এবং `anthropic-version`-সহ অনুরোধসহ প্রতিটি প্রমাণীকরণ পদ্ধতিতে
  অবজেক্টটি একই থাকে (প্রতিক্রিয়া `{ "object": "list",
"data": [...] }`-ই থাকে)। বাস্তবায়ন: `src/app/api/v1/models/catalogPricing.ts`।

### মডেল আইডির প্রিফিক্স (`?prefix=`)

বেশিরভাগ মডেল একটি **প্রদানকারী প্রিফিক্সের** অধীনে প্রকাশ করা হয়। আপনি কোন প্রিফিক্স পাবেন, তা
`MODELS_CATALOG_PREFIX_MODE` ফিচার ফ্ল্যাগ দ্বারা নিয়ন্ত্রিত হয় এবং একটি কোয়েরি প্যারামিটার দিয়ে
**প্রতি অনুরোধে** ওভাররাইড করা যায়—এটি এমন ক্লায়েন্টের জন্য উপযোগী, যারা অন্য সবার জন্য সার্ভারব্যাপী
সেটিং পরিবর্তন না করেই একটি পরিচ্ছন্ন তালিকা চায়:

```bash
GET /v1/models?prefix=alias        # প্রতি মডেলে একটি আইডি—সংক্ষিপ্ত অ্যালিয়াস প্রিফিক্স
GET /v1/models?prefix=dual         # উভয় রূপ (সার্ভারের ডিফল্ট)
GET /v1/models?prefix=canonical    # শুধু সম্পূর্ণ প্রদানকারী-আইডি প্রিফিক্স
```

| মোড         | যা নির্গত করে                                             | নোট                                                                                                                                                                                                     |
| ----------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **এবং** `claude/claude-sonnet-4-6` | **ডিফল্ট।** উভয় আইডিই একই মডেলে রাউট করে; যেসব ক্লায়েন্ট কনফিগে যেকোনো একটি রূপ হার্ডকোড করা আছে, সেগুলো যেন কাজ করতে থাকে তাই রাখা হয়েছে। এতে ক্যাটালগের আকার প্রায় দ্বিগুণ হয়।                   |
| `alias`     | `cc/claude-sonnet-4-6`                                    | প্রতি মডেলে একটি এন্ট্রি। স্বতন্ত্র অ্যালিয়াস নেই এমন প্রদানকারীরাও তাদের এন্ট্রি নির্গত করে, তাই কিছুই বাদ যায় না।                                                                                   |
| `canonical` | `claude/claude-sonnet-4-6`                                | সম্পূর্ণ প্রদানকারী-আইডি প্রিফিক্সের অধীনে প্রতি মডেলে একটি এন্ট্রি। স্বতন্ত্র অ্যালিয়াস নেই এমন প্রদানকারীরাও (যেমন `antigravity/…`, `agy/…`) এখানে তাদের একক আইডি নির্গত করে, তাই কিছুই বাদ যায় না। |

কোয়েরি প্যারামিটার ছাড়াও একটি `dual`-মোড মিরর শনাক্ত করা যায়: এতে প্রাথমিক আইডির দিকে নির্দেশকারী একটি `parent`
ফিল্ড থাকে।

যেসব ক্লায়েন্ট মডেল পিকার রেন্ডার করে, তাদের `?prefix=alias` অনুরোধ করা উচিত—[OmniCopilot VS Code এক্সটেনশন](../guides/VSCODE-COPILOT.md)
এটিই করে।

### ডিসকভারি ফিল্টার (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` অপ্ট-ইন ডিসকভারি ফিল্টার গ্রহণ করে। এগুলোর কোনোটিই না থাকলে প্রতিক্রিয়া
অপরিবর্তিত থাকে। এগুলো কলকারী ইতোমধ্যে যে ক্যাটালগ দেখতে পায় সেটিকে সংকুচিত করে (API-কী অনুমতিগুলো আগে প্রযোজ্য হয়),
এবং OpenAI-ধাঁচের `limit` / `after` পেজিংয়ের আগে কার্যকর হয়:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # তালিকাভুক্ত প্রতিটি সক্ষমতা অবশ্যই সত্য হতে হবে
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # ক্যাটালগ `type`; যেসব সারিতে এটি নেই সেগুলো `chat`
GET /v1/models?q=sonnet&limit=10                           # আইডি বা নামের সঙ্গে কেস-অসংবেদনশীল মিল
```

| প্যারামিটার   | মানসমূহ                                                                                             |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | ঋণাত্মক নয় এমন পূর্ণসংখ্যা, যা `context_length`-এর সঙ্গে তুলনা করা হয়                             |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | ১–২০০টি অক্ষর                                                                                       |

অজানা কোনো মান, অথবা ঋণাত্মক নয় এমন পূর্ণসংখ্যা নয় এমন একটি `min_context` (উদাহরণস্বরূপ `1.5`),
HTTP `400` ফেরত দেয় এবং বার্তায় বৈধ মানগুলোর তালিকা দেখানো হয়। বাস্তবায়ন:
`src/app/api/v1/models/catalogFilters.ts`।

### মডেলের সংক্ষিপ্ত তালিকা (`POST /v1/models/query`)

`POST /v1/models/query` একই ক্যাটালগ থেকে একটি সংক্ষিপ্ত, নির্ধারিত তালিকা ফেরত দেয়, যেখানে
`GET /v1/models`-এর মতো একই প্রমাণীকরণ এবং কী-প্রতি দৃশ্যমানতা প্রযোজ্য:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

প্রতিটি ক্ষেত্র ঐচ্ছিক। `capabilities` এবং `exclude` একটি অ্যারে অথবা কমা দিয়ে পৃথক করা স্ট্রিং গ্রহণ করে;
`max_output`-কে `max_output_tokens`-এর সঙ্গে তুলনা করা হয়। ফলাফল প্রথমে `owned_by`, তারপর `id` অনুসারে সাজানো হয়।
`limit`-এর ডিফল্ট মান `20` এবং `100`-এর বেশি মানকে `100`-তে সীমাবদ্ধ করা হয়। অবৈধ JSON, অজানা
ক্ষেত্র অথবা অবৈধ মান HTTP `400` ফেরত দেয়।

### স্বতন্ত্রভাবে লুকানো চ্যাট মডেল

কোনো মডেলকে তার প্রোভাইডার পৃষ্ঠায় **লুকানো** হিসেবে চিহ্নিত করা হলে সেটি ক্যাটালগ থেকে বাদ দেওয়া হয় এবং
সুস্পষ্টভাবে অনুরোধ করা হলে HTTP `404` / `model_not_found` দিয়ে প্রত্যাখ্যান করা হয়। পরীক্ষাটি সমাধানকৃত
প্রোভাইডার ও মডেল ব্যবহার করে, যার মধ্যে প্রোভাইডার উপনাম, সামঞ্জস্যপূর্ণ-প্রোভাইডার নোড প্রিফিক্স এবং
সংযোগের ডিফল্ট অন্তর্ভুক্ত রয়েছে। কোনো কম্বো লুকানো লক্ষ্যগুলো এড়িয়ে যায় এবং দৃশ্যমান সমগোত্রীয় মডেল ব্যবহার করতে পারে; যখন কোনো
কার্যকর লক্ষ্য অবশিষ্ট থাকে না, তখন এটি একই ত্রুটি কোড ফেরত দেয়। লুকানো অবস্থা সরানোর প্রভাব পরবর্তী
অনুরোধেই কার্যকর হয়। শুধু-ইমেজ দৃশ্যমানতা ওভাররাইড একই ID-সহ চ্যাট মডেলটিকে লুকায় না।

এই স্বতন্ত্র মডেল সেটিংটি
[মডেল এক্সপোজারের অনুমোদন/প্রত্যাখ্যান তালিকা](../routing/MODEL_EXPOSURE_LIST.md) থেকে পৃথক, যা সুস্পষ্ট ডিসপ্যাচ বজায় রেখে ক্যাটালগে
প্রদর্শন এবং স্বয়ংক্রিয়-রাউটিং প্রার্থীদের ফিল্টার করে। API-কী মডেল অনুমতিগুলো স্বাধীনভাবে প্রযোজ্য থাকে।
ডিফল্ট ক্যাটালগ প্রিফিক্স মোড `dual`-ই থাকে।

### নো-থিংকিং মডেল ভ্যারিয়েন্ট

থিংকিং-সক্ষম Claude মডেলগুলোর জন্য, `/v1/models` এমন একটি **নো-থিংকিং** ভ্যারিয়েন্টও প্রদর্শন করে, যার id-এর শুরুতে `claude-3-omniroute-no-thinking/` প্রিফিক্স থাকে:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

এই id নির্বাচন করলে (যেমন এমন একটি Claude Code কনফিগে, যা সব সময় একটি `thinking` ব্লক সংযুক্ত করে) রিজনিং দমন করে প্রকৃত `<provider>/<model>`-এ পুনরায় সমাধান করা হয়—`/v1/messages` পাথে `thinking:{type:"disabled"}`, অথবা `/v1/chat/completions` পাথে `reasoning`/`reasoning_effort` ক্ষেত্রগুলো বাদ দেওয়া হয়। ভ্যারিয়েন্টটি শুধু সেই Claude-পরিবারের মডেলগুলোর জন্য তালিকাভুক্ত করা হয়, যেগুলো থিংকিং সমর্থন করে **এবং** `disabled` মেনে চলে (তাই, যেমন শুধু-অ্যাডাপটিভ মডেল যেগুলো `disabled` প্রত্যাখ্যান করে, সেগুলো বাদ দেওয়া হয়)। অপারেটররা `ModelSpec.noThinkingAlias`-এর মাধ্যমে প্রতি মডেলের জন্য ভ্যারিয়েন্টটি জোরপূর্বক চালু বা বন্ধ করতে পারেন।

## ElevenLabs অডিও জেনারেশন

আপনার ElevenLabs API কী দিয়ে OmniRoute-এ একটি `elevenlabs` প্রোভাইডার সংযোগ কনফিগার করুন।
ক্লায়েন্টগুলো তাদের **OmniRoute** কী (`Authorization: Bearer $OMNIROUTE_API_KEY`) দিয়ে প্রমাণীকরণ করে;
গেটওয়ে সংরক্ষিত প্রোভাইডার কী-টি `xi-api-key` হিসেবে সরবরাহ করে। গেটওয়ের বেয়ারার টোকেন হিসেবে কখনোই ElevenLabs কী পাঠাবেন না।

| পদ্ধতি | পাথ                         | প্রতিক্রিয়া                                 | API কী এন্ডপয়েন্ট বিভাগ |
| ------ | --------------------------- | -------------------------------------------- | ------------------------ |
| POST   | `/v1/sound-generation`      | নেটিভ অডিও বাইট                              | `elevenlabs`             |
| POST   | `/v1/music`                 | নেটিভ অডিও বাইট                              | `music`                  |
| POST   | `/v1/music/stream`          | স্ট্রিমিং অডিও বাইট                          | `music`                  |
| POST   | `/v1/music/detailed`        | নেটিভ মাল্টিপার্ট অডিও এবং কম্পোজিশন প্ল্যান | `music`                  |
| POST   | `/v1/music/detailed/stream` | নেটিভ SSE মেটাডেটা এবং অডিও চাঙ্ক            | `music`                  |
| POST   | `/v1/music/plan`            | JSON কম্পোজিশন প্ল্যান                       | `music`                  |

এই এন্ডপয়েন্টগুলো বিদ্যমান `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` এবং `/v1/speech-to-text` রুটগুলোর পরিপূরক। `output_format` এবং `enable_logging`-এর মতো নেটিভ JSON ফিল্ড
ও কোয়েরি প্যারামিটার অপরিবর্তিত রাখা হয়।
`/v1/music/detailed` প্রতিক্রিয়াগুলো তাদের মাল্টিপার্ট বাউন্ডারি ধরে রাখে; এগুলোকে মাল্টিপার্ট হিসেবে পার্স করুন।
`/v1/music/detailed/stream` কম্পোজিশন মেটাডেটা এবং
SSE ইভেন্টে base64 অডিও চাঙ্কসহ `text/event-stream` ফেরত দেয়। ছয়টি রুটই CORS প্রিফ্লাইট সমর্থন করে।

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# একটি সংক্ষিপ্ত সাউন্ড ইফেক্ট। সময়কাল: 0.5 থেকে 30 সেকেন্ড।
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# সংগীতের সময়কাল মিলিসেকেন্ডে প্রকাশ করা হয়: 3000 থেকে 600000।
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

ক্রমবর্ধমান অডিও ডেলিভারির জন্য একই JSON বডির সঙ্গে `/v1/music/stream` ব্যবহার করুন। কম্পোজিশন
`prompt` অথবা `composition_plan`—ঠিক একটিকে গ্রহণ করে; `/v1/music/plan`-এর জন্য `prompt`
আবশ্যক এবং এটি ঐচ্ছিকভাবে `source_composition_plan` গ্রহণ করে। নেটিভ স্কিমাগুলো অতিরিক্ত
প্রোভাইডার ফিল্ড সংরক্ষণ করে, যাতে কম্পোজিশন-প্ল্যানের সংস্করণ এবং ফাইন-টিউনিং অপশনগুলো ElevenLabs-এ পৌঁছায়।

ইউনিফায়েড `/v1/music/generations` এন্ডপয়েন্টটি `elevenlabs/music_v1`,
`elevenlabs/music_v2` এবং `elevenlabs/music_v2_5`-ও গ্রহণ করে। একটি সক্রিয় ElevenLabs সংযোগ থাকলে,
এই মডেলগুলো মিউজিক ক্যাটালগে প্রকাশিত হয়। এই এন্ডপয়েন্টটি
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}` ফেরত দেয়। এর `duration` ফিল্ডটি
সেকেন্ডে থাকে এবং `music_length_ms`-এ ম্যাপ হয়; স্পষ্টভাবে দেওয়া `music_length_ms` অগ্রাধিকার পায়।
`instrumental`, `force_instrumental`-এ ম্যাপ হয়, যেখানে নেটিভ ফিল্ডটি অগ্রাধিকার পায়।
স্ট্রিমিংয়ের জন্য নেটিভ স্ট্রিমিং এন্ডপয়েন্ট এবং কেবল কম্পোজিশন প্ল্যান-চালিত রিকোয়েস্টের জন্য
নেটিভ কম্পোজিশন এন্ডপয়েন্ট ব্যবহার করুন।

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

আপস্ট্রিম কলের আগে এন্ডপয়েন্ট, মডেল, বাজেট এবং সংযোগের সীমাবদ্ধতা প্রয়োগ করা হয়। নেটিভ
রুটগুলো আপস্ট্রিম স্ট্যাটাস কোড এবং এরর বডি অপরিবর্তিতভাবে ফেরত দেয়, যার মধ্যে প্ল্যান
সীমাবদ্ধতার জন্য `402` এবং কোটা সীমার জন্য `429` অন্তর্ভুক্ত। উপস্থিত থাকলে `character-cost`, `song-id`, `request-id` এবং `retry-after`
হেডারগুলো সংরক্ষণ করা হয়। বিনামূল্যের ক্রেডিট ব্যালেন্স থাকলেই প্রতিটি
মিউজিক মডেল, আউটপুট ফরম্যাট বা API ফিচারে অ্যাক্সেস নিশ্চিত হয় না: প্রতিটি রিকোয়েস্টের এনটাইটেলমেন্ট ElevenLabs নির্ধারণ করে।
ইউনিফায়েড এন্ডপয়েন্টটি OmniRoute-এর স্বাভাবিকীকৃত এরর এনভেলপে এরর স্ট্যাটাস কোড সংরক্ষণ করে।

আপস্ট্রিম চুক্তি: [সাউন্ড ইফেক্ট](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[মিউজিক কম্পোজিশন](https://elevenlabs.io/docs/api-reference/music/compose) এবং
[স্ট্রিমিং মিউজিকের বিস্তারিত](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream)।

```bash
# রির্যাঙ্ক (ক্লাউড রেজিস্ট্রি প্রোভাইডার, অথবা "<prefix>/<model>" হিসেবে একটি OpenAI-সামঞ্জস্যপূর্ণ প্রোভাইডার নোড)
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Jina ক্লাসিফাই (Foundation API ক্রেডেনশিয়াল)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Jina সেগমেন্টার
POST /v1/segment     { "content": "...", "return_chunks": true }

# Jina সার্চ (s.jina.ai; প্রোভাইডার অ্যালিয়াস: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# মডারেশন
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — audio/mpeg (অথবা অনুরোধ করা ফরম্যাটের) বডি রিটার্ন করে
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS-এর জন্য একটি ভাষা এবং একটি ভয়েস প্রয়োজন: `language`-এর ডিফল্ট মান "en"; অনুপস্থিত
# ভয়েস অথবা একটি OpenAI স্টক ভয়েসের নাম (alloy, nova, …) "Adrian"-এ পরিণত হয়
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# ছবি সম্পাদনা (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# ভিডিও / মিউজিক জেনারেশন (প্রোভাইডার-প্রিফিক্সযুক্ত মডেল আইডি)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **রির্যাঙ্ক প্রোভাইডার নোড:** `POST /v1/rerank` অনুরোধটি OpenAI-সামঞ্জস্যপূর্ণ প্রোভাইডার নোডেও
> (oMLX, vLLM, Infinity, গেটওয়ের পেছনে থাকা TEI, …) রাউট করে, যেগুলোকে `<node-prefix>/<model>` হিসেবে সম্বোধন করা হয়। লুপব্যাক
> নোড (`localhost`, `127.0.0.1`, `172.16.0.0/12`) সবসময়ই ব্যবহারযোগ্য, আর অপারেটর
> `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS`-এ যেসব হোস্টনেম তালিকাভুক্ত করেন সেগুলোও ব্যবহারযোগ্য (যেমন `http://reranker:8080/v1`-এর মতো
> কোনো Docker/Compose পরিষেবার নাম; এগুলোকে সরাসরি কল করা হয়, কখনোই `HTTP(S)_PROXY` বা কোনো
> সংযোগের পিন করা প্রক্সির মাধ্যমে নয়)। অন্য যেকোনো
> হোস্টের নোড—যেমন কোনো LAN বক্স বা Tailscale পিয়ার—শুধু তখনই ব্যবহারযোগ্য হয়, যখন অপারেটর
> `RERANK_REMOTE_PROVIDER_NODES` ফিচার ফ্ল্যাগটি সক্রিয় করেন **এবং** নোডটির বেস URL প্রোভাইডারের
> আউটবাউন্ড URL নীতি (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`) পাস করে।
> মেমরি ইঞ্জিনের রির্যাঙ্ক ধাপটি লুপব্যাকের মাধ্যমে এই রুটকে কল করে,
> তাই একই নিয়ম Memory সেটিংসের `rerankProviderModel`-এর ক্ষেত্রেও প্রযোজ্য।
>
> **লোকাল সার্ভারের বিন্যাস:** নোডটিকে প্রথমে `<base>/v1/rerank`-এ এবং 404 পাওয়া গেলে `<base>/rerank`-এ
> (Infinity, TEI) কল করা হয়। আপস্ট্রিম বডিতে Cohere/OpenAI নামরীতি (`documents`,
> `return_documents`) এবং TEI নামরীতি (`texts`, `return_text`) উভয়ই থাকে, আর আপস্ট্রিম প্রতিক্রিয়াকে
> Cohere এনভেলপে স্বাভাবিকীকরণ করা হয়: TEI-এর সরাসরি `[{index, score, text}]`, হালকা গেটওয়ে থেকে পাওয়া
> `{results: [{index, score}]}` এবং Voyage-ধাঁচের `{data: [...]}`—সবই ক্লায়েন্টের কাছে
> `{results: [{index, relevance_score, document?}]}` হিসেবে ফিরে আসে, স্কোর অনুযায়ী সাজানো এবং `top_n`-এ সীমাবদ্ধ অবস্থায়।

> **প্রোভাইডার নোড আবিষ্কার:** OpenAI-সামঞ্জস্যপূর্ণ কোনো প্রোভাইডার নোডের মডেলগুলো নোড প্রিফিক্সের অধীনে `GET /v1/models`-এ
> দেখা যায়। যেসব সারিতে কোনো এন্ডপয়েন্ট মেটাডেটা থাকে না (লোকাল `/v1/models` তালিকার ক্ষেত্রে যা সাধারণ),
> সেগুলো নোডের `apiType` উত্তরাধিকারসূত্রে পায়; ফলে কোনো `embeddings` নোডের মডেলগুলো ডিফল্টভাবে চ্যাটে নির্ধারিত না হয়ে
> `type: "embedding"` হয় এবং কোনো `rerank` নোডের মডেলগুলো `type: "rerank"` হয়; তবে সিঙ্ক করা বা হাতে যোগ করা
> কোনো সারিতে সুস্পষ্ট `supportedEndpoints` থাকলে সেটিই অগ্রাধিকার পায়।

### নিবেদিত প্রোভাইডার রুটসমূহ

```bash
POST /v1/providers/{provider}/chat/completions
POST /v1/providers/{provider}/embeddings
POST /v1/providers/{provider}/images/generations
```

প্রোভাইডার প্রিফিক্স অনুপস্থিত থাকলে তা স্বয়ংক্রিয়ভাবে যোগ করা হয়। অমিল মডেলের ক্ষেত্রে `400` ফেরত আসে।

## ফাইলস API

ব্যাচ ইনপুট/আউটপুট এবং ফাইল-পারপাস আপলোডের জন্য OpenAI-সামঞ্জস্যপূর্ণ ফাইল এন্ডপয়েন্ট।

| মেথড   | পাথ                      | বিবরণ                                                                                                                     |
| ------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/files`              | একটি ফাইল আপলোড করুন (multipart: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — সর্বোচ্চ 512 MiB |
| GET    | `/v1/files`              | প্রমাণীকৃত API কী-এর ফাইলগুলোর তালিকা দেখুন                                                                               |
| GET    | `/v1/files/[id]`         | একটি ফাইলের মেটাডেটা পুনরুদ্ধার করুন                                                                                      |
| DELETE | `/v1/files/[id]`         | একটি ফাইল মুছুন                                                                                                           |
| GET    | `/v1/files/[id]/content` | অপরিবর্তিত ফাইল বডি স্ট্রিম করে ফেরত দিন                                                                                  |

**প্রমাণীকরণ:** Bearer API কী — `getApiKeyRequestScope`-এর মাধ্যমে ফাইলগুলো প্রতিটি API কী অনুযায়ী সীমাবদ্ধ। একটি কী
শুধু তার নিজস্ব ফাইল দেখতে, ডাউনলোড করতে এবং মুছতে পারে; কী ছাড়া একটি ড্যাশবোর্ড সেশন পুরো
ইনস্ট্যান্স পড়তে পারে; কোনো মালিকবিহীন ফাইল (বেনামী বা ড্যাশবোর্ড-সেশন আপলোড) প্রত্যেক
নন-সেশন কলারের জন্য অস্বীকৃত। `GET /v1/files` কোনো বেনামী কলারকে — এবং এমন কোনো প্রদত্ত কী-কে যা
সমাধান হয় না — `REQUIRE_API_KEY=false` হলেও প্রতিটি টেন্যান্টের
ফাইলের তালিকা দেখানোর পরিবর্তে `401` দিয়ে প্রত্যাখ্যান করে (GHSA-m3hp-hq9g-fpmv, GHSA-2jm2-mpx8-6523)।

## ব্যাচেস API

| মেথড   | পাথ                       | বিবরণ                                                                                                          |

**প্রমাণীকরণ:** Bearer API কী। ফাইলের মতো একই ত্রিমুখী নিয়মের অধীনে ব্যাচগুলো প্রতিটি API কী অনুযায়ী
সীমাবদ্ধ: কেবল নিজস্ব কী, ড্যাশবোর্ড সেশনের জন্য পুরো ইনস্ট্যান্স, এবং নাল-মালিকানাধীন রেকর্ড প্রত্যেক
নন-সেশন কলারের জন্য অস্বীকৃত (পুনরুদ্ধার, মুছে ফেলা, বাতিল করা এবং তৈরির সময় `input_file_id` যাচাই)।
`GET /v1/batches` কোনো বেনামী কলারকে `REQUIRE_API_KEY=false` হলেও `401` দিয়ে প্রত্যাখ্যান করে।

Web/search প্রদানকারী বিমূর্ততা (Tavily, Brave, Exa, Serper, ইত্যাদি)।

| পদ্ধতি | পথ                     | বর্ণনা                                                                                          |
| ------ | ---------------------- | ----------------------------------------------------------------------------------------------- |
| GET    | `/v1/search`           | তালিকা কনফিগার করা অনুসন্ধান প্রদানকারী + ক্ষমতা                                                |
| POST   | `/v1/search`           | একটি অনুসন্ধান ক্যোয়ারী চালান — বডি `v1SearchSchema` দ্বারা বৈধ, caching/coalescing সমর্থন করে |
| GET    | `/v1/search/analytics` | প্রতি-প্রদানকারী hit/latency/cache পরিসংখ্যান                                                   |

**প্রমাণ:** বহনকারী API কী (`extractApiKey` + `isValidApiKey`)। অনুসন্ধান নীতি `enforceApiKeyPolicy` এর মাধ্যমে প্রয়োগ করা হয়েছে।

### Exa এবং Tavily `provider_options`

Exa এবং Tavily নেমস্পেসযুক্ত ব্যাগ থেকে প্রদানকারী-নির্দিষ্ট ক্ষেত্রগুলি পড়ুন: `provider_options.exa` (বা `provider_options["exa-search"]`) এবং `provider_options.tavily` (বা `provider_options["tavily-search"]`)। শুধুমাত্র নীচের কী ফরোয়ার্ড করা হয়. প্রতিটিকে `open-sse/handlers/search/providerOptionsPassthrough.ts` এ তার নিজস্ব Zod স্কিমার বিরুদ্ধে চেক করা হয় এবং ভুল টাইপের একটি কী বাদ দেওয়া হয়। auth, base URL, `stream` এবং `outputSchema` সহ অন্য কোন কী উপেক্ষা করা হয়। অন্যান্য প্রদানকারীর দ্বারা ব্যবহৃত ফ্ল্যাট কীগুলি (`cx`, `depth`, ...) আগের মতোই কাজ করে৷

| প্রদানকারী | শীর্ষ-স্তরের ক্ষেত্র                                                                                                                                                                                                                                                                                                                                                      | নেস্টেড                                                                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa        | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (সমতল আদিম), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                                    | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` ডিফল্ট `{ text: true, highlights: true }` এর উপর একত্রিত হয়েছে |
| টাভিলি     | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                             |

জেনেরিক ক্ষেত্রগুলি সর্বদা জয়ী হয়: `query`, `max_results`, `filters` (ডোমেন), `country` এবং `search_type` থেকে প্রাপ্ত বিষয়। Exa-এ, `search_type: "news"` `category: "news"` রাখে। Tavily এছাড়াও `search_type: "finance"` (`topic: "finance"`) গ্রহণ করে।

ফায়ারক্রল অনুসন্ধান খরচ 10টি ফলাফলের সূচনা ব্লক প্রতি রেকর্ড করা হয়, $0.002 (2 ক্রেডিট) একটি ব্লক এবং প্রতি কলে কমপক্ষে একটি ব্লক ( [ফায়ারক্রল বিলিং](https://docs.firecrawl.dev/billing) ): 11টি ফলাফলের মূল্য $0.004।

জেনেরিক `time_range` এখন উভয় প্রদানকারীর কাছে পৌঁছেছে: Exa পায় `startPublishedDate` (ISO টাইমস্ট্যাম্প) এবং Tavily পায় `start_date` (`YYYY-MM-DD`)। `provider_options` এ একটি স্পষ্ট তারিখ ম্যাপ করাকে ওভাররাইড করে।

পরীক্ষার ফলাফল `id`, `highlight_scores`, `summary`, `subpages`, `entities` এবং `extras` `provider_raw` এ রাখে। Tavily ফলাফল `images` এবং `favicon` রাখা.

লিংকআপ সার্চ খরচ `depth` `fast` এবং `standard` জন্য $0.005 এবং `deep` এর জন্য $0.05 রেকর্ড করা হয়েছে ( [লিঙ্কআপ মূল্য](https://docs.linkup.so/pages/documentation/development/pricing) ), `depth` `provider_options` থেকে আসে বা সংযোগের সেটিংস থেকে।

Exa `type: "lite"` (Exa 3.0) ক্ষেত্রগুলির একটি ছোট সেট গ্রহণ করে এবং অন্য কোনও ক্ষেত্র সেট করা হলে পুরো অনুরোধটি প্রত্যাখ্যান করে। লাইটের জন্য, `additionalQueries`, `systemPrompt` এবং `text` এবং `highlights` ছাড়া প্রতিটি `contents` কী কলের আগে ড্রপ করা হয়। অপ্রচলিত `subpages`, `subpageTarget`, `highlights.numSentences` এবং `highlights.highlightsPerUrl` আর ফরওয়ার্ড করা হয় না।

কস্ট অ্যাকাউন্টিং হল ফ্ল্যাট রেজিস্ট্রি `costPerQuery`, Exa ব্যতীত, যা Exa-এর নিজস্ব মূল্য অনুসরণ করে: $0.007 প্রতি কলে `auto` (এবং লিগ্যাসি `fast`) অথবা $0.004 `lite` (এবং লিগ্যাসি `instant`), 10টি ফলাফল কভার করে; প্রতিটি পরবর্তী ফলাফলের জন্য $0.001; এবং $0.001 প্রতি ফেরত ফলাফল যখন `contents.summary` সেট করা হয়। Tavily `search_depth` `basic`, `fast` এবং `ultra-fast` এর জন্য 1 ক্রেডিট ($0.008) এবং `advanced` ( [Tavily API ক্রেডিট](https://docs.tavily.com/documentation/api-credits) ) এর জন্য 2 ক্রেডিট ($0.016) রেকর্ড করা হয়েছে। `auto_parameters: true` এর সাথে একটি কল যা Tavily অ্যাডভান্সড-এ আপগ্রেড করে তা এখনও 1 ক্রেডিটে রেকর্ড করা হয়।

## Web Fetch API

কনফিগার করা কোনো web-fetch প্রদানকারীর (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract) মাধ্যমে একটি URL থেকে কনটেন্ট এক্সট্র্যাক্ট করুন।

Parallel Extract (`parallel-search`, Parallel Search-এর একই API key) শুধু Markdown
ফেরত দেয় — অন্য যেকোনো `format`-এর ক্ষেত্রে একটি `400` ফেরত আসে — এবং কনটেন্টের সীমা 100,000 অক্ষর। যখন
লক্ষ্য পৃষ্ঠাটি নিজেই এক্সট্র্যাক্ট করা যায় না, তখন আপস্ট্রিম সেটি HTTP 200-এর মধ্যে রিপোর্ট করে;
OmniRoute সেটিকে একটি নির্দিষ্ট বার্তাসহ `422` হিসেবে প্রকাশ করে।

| মেথড | পাথ             | বিবরণ                                                                     |
| ---- | --------------- | ------------------------------------------------------------------------- |
| POST | `/v1/web/fetch` | একটি URL ফেচ/স্ক্র্যাপ করুন — বডি `v1WebFetchSchema` দ্বারা যাচাই করা হয় |

**প্রমাণীকরণ:** Bearer API key (`extractApiKey` + `isValidApiKey`)। নীতি `enforceApiKeyPolicy`-এর মাধ্যমে প্রয়োগ করা হয়।

**কোটা-সচেতন ফলব্যাক (#8297):** যখন স্পষ্টভাবে কোনো `provider` দেওয়া হয় না, তখন পুলটি
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`)
নির্দিষ্ট
অগ্রাধিকার ক্রমে (fill-first) অতিক্রম করা হয় — রেট-লিমিটেড কিন্তু কনফিগার করা কোনো প্রদানকারী অনুরোধটি
তাৎক্ষণিকভাবে বন্ধ করার পরিবর্তে এড়িয়ে যাওয়া হয়, এবং পুনরায় চেষ্টা করা যায় এমন/কোটা-সংক্রান্ত আপস্ট্রিম ব্যর্থতা
(HTTP 429 সর্বদা; Firecrawl/Tavily/TinyFish-এর কোটা-ধরনের free tier-এর ক্ষেত্রে 402/403 —
Jina Reader-এর ক্ষেত্রে নয়, এবং সাধারণ 400 bad request-এর ক্ষেত্রে কখনোই নয়) অনুরোধের সময়
পরবর্তী এখনো চেষ্টা না-করা, ক্রেডেনশিয়ালযুক্ত প্রদানকারীতে ফলব্যাক করে। পুলের প্রতিটি প্রদানকারী
শেষ হয়ে গেলে, এন্ডপয়েন্টটি আগের সাধারণ `400`-এর পরিবর্তে একটি একক `429` (`Retry-After`
হেডারসহ) ফেরত দেয়। যখন স্পষ্টভাবে কোনো `provider` চাওয়া হয়, তখন **কোনো** নীরব ফলব্যাক থাকে না — রেট-লিমিটেড বা ব্যর্থ স্পষ্ট
প্রদানকারীর নিজস্ব ত্রুটি প্রকাশিত হয় (রেট-লিমিটেড হলে `429`, অন্যথায় আপস্ট্রিম
স্ট্যাটাস)।

## WebSocket স্ট্রিমিং

```bash
GET /v1/ws?handshake=1
```

একটি WebSocket upgrade handshake যাচাই করে এবং wire protocol-এর উদাহরণ বার্তাগুলো (`request`, `cancel`) ফেরত দেয়। প্রকৃত WS frame-গুলো Next.js route table-এর বাইরে থাকা বান্ডেলকৃত WS server দ্বারা পরিচালিত হয়।

**প্রমাণীকরণ:** handshake-এর সময় Bearer API key।

### WebSocket-এর মাধ্যমে Responses API (শুধু codex)

```bash
# HTTP API-এর মতো একই host:port (ডিফল্ট 20128); সংযোগটি আপগ্রেড করুন:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (অথবা: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# প্রথম frame-টি অবশ্যই response.create হতে হবে:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

একটি Responses-API-over-WebSocket proxy **একচেটিয়াভাবে `codex`-এর সঙ্গে** (ChatGPT
backend) সংযুক্ত। এটি API/dashboard-এর একই port-এ `/v1/responses`,
`/responses`, এবং `/api/v1/responses` পাথে শোনে। প্রথম `response.create` frame-এ এটি
অভ্যন্তরীণ `codex-responses-ws` bridge-এর মাধ্যমে প্রমাণীকরণ + প্রস্তুতি সম্পন্ন করে, একটি
codex OAuth connection নির্বাচন করে এবং `wreq-js` transport-এর মাধ্যমে `wss://chatgpt.com/backend-api/codex/responses`-এ
tunnel করে। **codex নয় এমন model প্রত্যাখ্যান করা হয়** (`codex_ws_provider_required`)।
quota-share routing-এর জন্য `model: "qtSd/<group>/codex/<model>"` ব্যবহার করুন। এটি
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`-এ বাস্তবায়িত।

**প্রমাণীকরণ:** handshake-এর সময় Bearer API key। বান্ডেলকৃত HTTP server (`server-ws.mjs`)
অবশ্যই সক্রিয় entrypoint হতে হবে (`app/server-ws.mjs` বিদ্যমান থাকলে ডিফল্টভাবে এটিই সক্রিয় থাকে)।

#### Model id: সাধারণ ChatGPT id ব্যবহার করুন (`codex/` prefix ছাড়া)

OpenAI **Codex CLI**, `supports_websockets = true` হলে client-side-এ model-এর নাম যাচাই করে এবং
`codex/gpt-5.5`-এর মতো **provider-prefixed id প্রত্যাখ্যান করে**
(`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`)। **সাধারণ** id পাঠান (যেমন `gpt-5.5`)। OmniRoute-এর bridge
শুধু codex-এর জন্য, তাই upstream-এ tunnel করার আগে এটি একটি সাধারণ id-কে codex model হিসেবে পুনরায় resolve করে
(`resolveCodexWsModelInfo`) — যদিও একটি সাধারণ
`gpt-5.5` অন্যথায় HTTP-এর মাধ্যমে অন্য কোনো provider-এ route হতো।

#### OpenAI Codex CLI কনফিগার করা

`~/.codex/config.toml`-এ WebSocket
support-সহ একটি custom provider যোগ করে Codex CLI-কে OmniRoute-এর দিকে নির্দেশ করুন (বিদ্যমান config
পরিবর্তন করা এড়াতে পৃথক `CODEX_HOME` ব্যবহার করুন):

```toml
model = "gpt-5.5"                 # সাধারণ id — "codex/gpt-5.5" নয়
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # শেষে slash নয়; WS URL উদ্ভূত হয় (production-এ https/wss ব্যবহার করুন)
wire_api = "responses"                    # Feb 2026 থেকে একমাত্র সমর্থিত মান
supports_websockets = true                # Responses-over-WS transport সক্রিয় করে
env_key = "OMNIROUTE_API_KEY"             # OmniRoute API key ধারণ করে (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # একটি OmniRoute API key (REQUIRE_API_KEY=false হলে যেকোনো key)
codex exec "Responda apenas: PONG"
```

CLI, `base_url + /responses`-কে WebSocket-এ আপগ্রেড করে এবং OmniRoute সেটিকে
নির্বাচিত codex OAuth connection-এ tunnel করে। স্থানীয়
server-এর বিপরীতে end-to-end যাচাই করা হয়েছে: ChatGPT `codex.rate_limits` + `response.created` ফেরত দেয় এবং
completion stream করে।

| GET  | `/v1/quotas/check`  | নিবন্ধিত কী ইস্যু করার আগে একটি `provider` + `accountId`-এর কোটা আগাম যাচাই করে          |
| POST | `/v1/issues/report` | GitHub-এ কোটা/কী ইস্যু করার ব্যর্থতা রিপোর্ট করে (`GITHUB_ISSUES_REPO` + টোকেন প্রয়োজন) |

**প্রমাণীকরণ:** Bearer API কী (`isAuthenticated`)।

## স্ব-পরিষেবা ব্যবহার (`/api/usage/om-usage`)

যেকোনো API কী **নিজস্ব** ব্যবহার ও কোটা পড়তে পারে—কোনো ম্যানেজমেন্ট প্রমাণীকরণের প্রয়োজন নেই। কোনো
ক্লায়েন্ট (CLI, OmniCopilot প্যানেল) একজন কী-ধারককে তাঁর ব্যয় দেখাতে এই এন্ডপয়েন্ট ব্যবহার করে।

```bash
# টেক্সট ফর্ম (ঐতিহাসিক চুক্তি—টার্মিনালের জন্য প্লেইন টেক্সট)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# স্ট্রাকচার্ড ফর্ম—একটি UI যা ব্যবহার করে
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

কীটিতে অবশ্যই **`allowUsageCommand`** সক্রিয় থাকতে হবে (ডিফল্টভাবে বন্ধ—ড্যাশবোর্ডের API-কী
ম্যানেজার প্রতিটি কীর জন্য এটি টগল করে)। এটি ছাড়া এন্ডপয়েন্টটি `403` উত্তর দেয়।

`?format=json` একটি বৈষম্যসূচক কাঠামো ফেরত দেয়, যাতে কোনো কলার প্রত্যাখ্যানের ফলাফল থেকে কখনো
ডেটা ফিল্ড না পড়ে। সফল হলে:

```jsonc
{
  "allowed": true,
  // কীটি প্রতি-কী ব্যবহারসীমা (দৈনিক/সাপ্তাহিক USD) বেছে নিলেই কেবল উপস্থিত থাকে:
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // নির্বাচিত প্রোভাইডারের কোটা স্ন্যাপশট, অথবা এখনো কিছু ক্যাশে না থাকলে null:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // প্রতিটি কানেকশনের স্ন্যাপশট, যাতে একটি UI একাধিক প্রোভাইডার পাশাপাশি রেন্ডার করতে পারে:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

প্রত্যাখ্যানের ক্ষেত্রে (`401` ত্রুটিপূর্ণ কী / `403` অনুমোদিত নয়), একই রুট
`{ "allowed": false, "error": { "message": "…" } }` ফেরত দেয়—উপস্থিত কিন্তু খালি `personal`/`provider`
(কী অনুমোদিত, এখনো কিছু জানা যায়নি) প্রত্যাখ্যান থেকে আলাদা একটি অবস্থা, এবং শুধু JSON ফর্মই
এগুলোর মধ্যে পার্থক্য করে।

**প্রমাণীকরণ:** কলারের নিজস্ব Bearer API কী, যা `isValidApiKey` দিয়ে যাচাই করা হয়—এটি ম্যানেজমেন্ট
সারফেস (`/api/keys/…`) _নয়_, যা `requireManagementAuth`-এর সুরক্ষার অধীনেই থাকে।

### কাঁচা বনাম কাটঅফ-সমন্বিত কোটা শতাংশ

`/api/usage/om-usage` ব্যবহার করার সময়, কলারদের **প্লেইন-টেক্সট আউটপুট** এবং কাঠামোবদ্ধ **JSON আউটপুটে**
উপস্থাপিত শতাংশগুলোর মধ্যকার পার্থক্য লক্ষ করা উচিত:

| দিক                    | প্লেইন-টেক্সট ফরম্যাট (`/api/usage/om-usage` / `@@om-usage`)                                          | JSON ফরম্যাট (`?format=json`)                                             |
| :--------------------- | :---------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------ |
| **আউটপুট ফিল্ড**       | `NN% left` (যেমন, `20% left`)                                                                         | `provider.quotas` / `providers[].quotas`                                  |
| **পরিমাপ**             | **কাটঅফ-সমন্বিত ব্যবহারযোগ্য বরাদ্দ**: কাটঅফ থ্রেশহোল্ডের ওপরে অবশিষ্ট সক্ষমতা                        | **কাঁচা আপস্ট্রিম কোটা**: প্রোভাইডারের অসমন্বিত পরিমাপ                    |
| **কাটঅফ স্কেলিং**      | `effectiveRemainingPercent()`-এর মাধ্যমে স্কেল করা হয়, যাতে সুরক্ষিত রিজার্ভ `0% left` হিসেবে দেখায় | নেই (প্রোভাইডারের রিপোর্ট করা কাঁচা স্ন্যাপশট মান)                        |
| **থ্রেশহোল্ড ডেটা**    | প্রদর্শিত শতাংশে অন্তর্ভুক্ত                                                                          | প্রতি কানেকশনে `quotaWindowThresholds`-এ সংরক্ষিত (অথবা সার্ভারের ডিফল্ট) |
| **প্রধান ব্যবহারকারী** | ইন্টারঅ্যাকটিভ CLI, টার্মিনাল প্রম্পট, মানব অপারেটর                                                   | প্রোগ্রাম্যাটিক ইন্টিগ্রেশন, ড্যাশবোর্ড, অ্যানালিটিক্স, বিলিং ট্র্যাকার   |

#### কাটঅফ সমন্বয়ের সূত্র

OmniRoute আপস্ট্রিম নিঃশেষ হওয়া প্রতিরোধে সক্রিয় কোটা কাটঅফ সমর্থন করে (কানেকশনের
`quotaWindowThresholds`, প্রোভাইডারের ডিফল্ট বা গ্লোবাল রেজিলিয়েন্স সেটিংসের মাধ্যমে কনফিগার করা হয়)।
কোনো কোটা উইন্ডোতে একটি কাটঅফ থ্রেশহোল্ড (যেমন, `cutoff = 25%`) সক্রিয় থাকলে, টেক্সট রেন্ডারার অবশিষ্ট
বরাদ্দ এভাবে গণনা করে:

- যদি `remaining <= cutoff` হয়: `0%` ফেরত দেয়।
- যদি `remaining > cutoff` হয়: `((remaining - cutoff) / (100 - cutoff)) * 100` ফেরত দেয়।

ফরম্যাট করা টেক্সট আউটপুট এটিকে নিকটতম পূর্ণসংখ্যায় রাউন্ড করে (`Math.round(...)`)।

#### ব্যাখ্যামূলক উদাহরণ

এমন একটি প্রোভাইডার উইন্ডো বিবেচনা করুন যেখানে **60% কাঁচা ব্যবহার** (অতএব **40% কাঁচা অবশিষ্ট কোটা**) এবং
কনফিগার করা **25% অবশিষ্ট-কোটা কাটঅফ** থ্রেশহোল্ড রয়েছে:

| উপস্থাপনা                       | গণনা                                               | অবশিষ্ট |            পরোক্ষভাবে ব্যবহৃত            |
| :------------------------------ | :------------------------------------------------- | :-----: | :--------------------------------------: |
| **কাঁচা JSON (`?format=json`)** | আপস্ট্রিম স্ন্যাপশট (`quotas[window]`)             | **40%** |                 **60%**                  |
| **টেক্সট ফরম্যাট (`NN% left`)** | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (`100 - remaining` গণনা করা হলে) |

- **টেক্সটে কেন 20% অবশিষ্ট দেখায়:** অ্যাকাউন্টে অবশিষ্ট 40% প্রকৃত কোটার মধ্যে 25% কাটঅফ নীতির
  জন্য সংরক্ষিত। রাউটার এই কানেকশনে রাউটিং বন্ধ করার আগে কলারের ব্যবহারযোগ্য 75% হেডরুমের মধ্যে মাত্র
  15% অবশিষ্ট থাকে। স্কেলিং নিশ্চিত করে যে ঠিক যখন রাউটিং বন্ধ হবে, তখনই কানেকশনটি নিঃশেষ হওয়ার সংকেত
  (`0% left`) দেবে।
- **JSON কেন কাঁচা মান সংরক্ষণ করে:** JSON পেলোড সঠিক প্রোভাইডার স্ন্যাপশট (`UsageSnapshot`) ফেরত দেয়,
  যাতে বহিরাগত টুলগুলো সার্ভার-সাইড ক্ষতিকর স্কেলিং ছাড়াই প্রকৃত আপস্ট্রিম ব্যবহার এবং কানেকশন-স্তরের
  `quotaWindowThresholds` অ্যাক্সেস করতে পারে।

#### ব্যবহারকারী মাইগ্রেশন নির্দেশিকা

যদি কোনো বাহ্যিক ইন্টিগ্রেশন (যেমন কোনো এডিটর প্লাগইন বা এজেন্ট এক্সটেনশন) আগে টেক্সট
এন্ডপয়েন্ট (`NN% left`) স্ক্র্যাপ করে থাকে এবং ব্যবহৃত শতাংশ `100 - NN` হিসেবে গণনা করে থাকে, তাহলে `?format=json`-এ মাইগ্রেট করার অর্থ হলো:

- কাঁচা JSON মান পড়লে **প্রকৃত আপস্ট্রিম ব্যবহার** প্রতিফলিত হবে (উপরের উদাহরণে 60% ব্যবহৃত)।
- ইন্টিগ্রেশনটি যদি টেক্সট এন্ডপয়েন্টের ব্যবহারযোগ্য-বরাদ্দের অর্থ বজায় রাখতে চায়, তাহলে এটি সংযোগ-স্তরের ওভাররাইডের জন্য `quotaWindowThresholds` ব্যবহার করে
  ক্লায়েন্ট-সাইডে কার্যকর অবশিষ্টের সূত্রটি মূল্যায়ন করতে পারে।

## সেমান্টিক ক্যাশ

```bash
# ক্যাশের পরিসংখ্যান পান
GET /api/cache/stats

# সব ক্যাশ সাফ করুন
DELETE /api/cache/stats
```

প্রতিক্রিয়ার উদাহরণ:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### ল্যাটেন্সির প্রভাব

সেমান্টিক ক্যাশে HIT হলে প্রতিক্রিয়াটি ক্যাশ থেকে পরিবেশন করা হয় **কোনো আপস্ট্রিম
কল ছাড়াই**, তাই রিপোর্ট করা `X-OmniRoute-Response-Latency` প্রায় শূন্য
(মূল আপস্ট্রিম ল্যাটেন্সি নির্বিশেষে)। ল্যাটেন্সি-সংবেদনশীল ক্লায়েন্টগুলোর
(বেঞ্চমার্কিং, p50/p99 পর্যবেক্ষণ) `X-OmniRoute-Cache-Latency` প্রতিক্রিয়া হেডার পরীক্ষা করা উচিত:

| মান           | অর্থ                                                                          |
| ------------- | ----------------------------------------------------------------------------- |
| `synthetic`   | প্রতিক্রিয়া ক্যাশ থেকে পরিবেশিত হয়েছে; ল্যাটেন্সি প্রকৃত আপস্ট্রিম সময় নয় |
| _(অনুপস্থিত)_ | প্রকৃত আপস্ট্রিম কল থেকে পাওয়া প্রতিক্রিয়া                                  |

### প্রতি-কী ক্যাশ বাইপাস

API কীগুলো `cacheDefaultMode`-এর মাধ্যমে সেমান্টিক ক্যাশ রিড ব্যবহার না করার বিকল্প বেছে নিতে পারে:

| মান      | আচরণ                                                            |
| -------- | --------------------------------------------------------------- |
| `legacy` | স্বাভাবিক ক্যাশ আচরণ (ডিফল্ট)                                   |
| `bypass` | ক্যাশ লুকআপ সম্পূর্ণভাবে এড়িয়ে যান; সর্বদা আপস্ট্রিমে কল করুন |

কী তৈরির সময় (`POST /api/keys`) সেট করুন অথবা আপডেট করুন (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### প্রতি-অনুরোধ বাইপাস

কী-এর সেটিংস নির্বিশেষে যেকোনো অনুরোধ ক্যাশ বাইপাস করতে পারে:

```
X-OmniRoute-No-Cache: true
```

### প্রমাণীকরণ

| এন্ডপয়েন্ট                   | মেথড     | বিবরণ                                                                                                                                                                                                                                                                                  |
| ----------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api/auth/login`             | POST     | লগইন                                                                                                                                                                                                                                                                                   |

সিঙ্ক/ইমপোর্ট করা মডেলের ক্ষেত্রে, `PUT /api/provider-models` `provider`, `modelId`, এবং
`maxOutputTokenOverride` গ্রহণ করে: একটি ধনাত্মক পূর্ণসংখ্যা ম্যানুয়াল আউটপুট-টোকেন সীমা নির্ধারণ করে এবং `null`
সেটি মুছে ডিফল্ট পুনরুদ্ধার করে। `GET /api/provider-models?provider=<provider>` এই মানগুলো
`modelOutputOverrides`-এ ফেরত দেয়, যার মধ্যে কাস্টম-মডেল সারি না থাকা মডেলও অন্তর্ভুক্ত। ওভাররাইডটি
রানটাইম `max_output_tokens` সক্ষমতা ব্যবহার করে এবং মডেল পুনরায় সিঙ্ক করার পরও বজায় থাকে। OpenAI-সামঞ্জস্যপূর্ণ
প্রোভাইডার পেজ একই সম্পাদনা/মুছে ফেলার নিয়ন্ত্রণ দেয় এবং স্পষ্ট ভিশন সমর্থন থাকা মডেলগুলোকে চিহ্নিত করে।

কাস্টম Chat Completions নোডগুলো স্পষ্ট রিজনিং অপ্ট-আউটকে আপস্ট্রিম ব্যাকএন্ডের উপযোগী করে নেয়। একটি
সফল সংযোগ পরীক্ষা প্রতিটি হুবহু মডেল ID-এর জন্য স্বয়ংক্রিয়ভাবে চ্যাট-টেমপ্লেট নিয়ন্ত্রণ নির্বাচন করে,
যার `/models` এন্ট্রি একটি স্বীকৃত `owned_by` মান প্রমাণ করে: `vllm`, `sglang`, অথবা `llamacpp`।
স্বচ্ছ OpenAI-সামঞ্জস্যপূর্ণ র্যাপারগুলো একটি নেস্টেড
`openai` অবজেক্টের মধ্যে মূল মডেল এন্ট্রি সংরক্ষণ করতে পারে; শনাক্তকরণ সর্বোচ্চ তিনটি এমন এনভেলপ অনুসরণ করে। অনুপস্থিত, অজানা, অথবা
পরস্পরবিরোধী মালিকানাসহ মডেলগুলো সাধারণ OpenAI আচরণ বজায় রাখে। শনাক্তকরণ বিদ্যমান ক্যাটালগ অনুরোধ পুনরায় ব্যবহার করে,
কোনো কমপ্লিশন টোকেন তৈরি করে না এবং সংযোগ এন্ডপয়েন্ট পরিবর্তিত হলে অবৈধ হয়ে যায়।

এমন কোনো ব্যাকএন্ডে এই আচরণ স্থির করতে, যা ওই মেটাডেটা প্রকাশ করে না, বিদ্যমান আংশিক
প্রোভাইডার আপডেট API ব্যবহার করুন:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

ওই বডিটি `PUT /api/providers/<connection-id>` দিয়ে পাঠান। সেই সংযোগে, `none` মানের একটি স্পষ্ট
রিজনিং এফোর্ট `chat_template_kwargs.thinking=false` এবং
`chat_template_kwargs.enable_thinking=false` হিসেবে পাঠানো হয়। স্পষ্ট নেটিভ টেমপ্লেট মানগুলোই চূড়ান্ত কর্তৃত্ব বজায় রাখে,
যদি না কোনো সার্ভার-সাইড রিজনিং নিয়ম একটি এফোর্ট প্রয়োগ করে। সেটিংটি কেবল তখনই প্রযোজ্য, যখন একটি কাস্টম
OpenAI-সামঞ্জস্যপূর্ণ সংযোগ একটি Chat Completions বডি পাঠায়; Responses অনুরোধ এবং সাধারণ
প্রোভাইডারগুলো তাদের নেটিভ অনুরোধের কাঠামো বজায় রাখে। সাধারণ OpenAI
`reasoning_effort` পাসথ্রু বাধ্যতামূলক করতে `reasoningControl`-কে `openai`-এ সেট করুন, অথবা স্বয়ংক্রিয় শনাক্তকরণ ব্যবহার করতে এটি বাদ দিন/`null`-এ সেট করুন।

Claude Code অটো-মোড ক্লাসিফায়ার অনুরোধে কোনো স্পষ্ট রিজনিং নিয়ন্ত্রণ না থাকলে ডিফল্টভাবে নেটিভ thinking
নিষ্ক্রিয় থাকে। শনাক্তকরণ Claude-ফরম্যাট অনুরোধে ক্লাসিফায়ারের সিস্টেম মার্কার ব্যবহার করে,
মডেলের নাম বা কমপ্লিশন সীমা নয়। স্পষ্ট বডি নিয়ন্ত্রণ, সমর্থিত এফোর্ট/thinking
হেডার, রাউটিং নিয়ম এবং সমাধান করা মডেল এফোর্ট তাদের বিদ্যমান অগ্রাধিকার বজায় রাখে। উভয় ক্লাসিফায়ার
পর্যায় তাদের প্রম্পট, কমপ্লিশন সীমা, স্টপ সিকোয়েন্স এবং প্রকৃত আপস্ট্রিম অনুমতির
সিদ্ধান্ত বজায় রাখে; দ্বিতীয় পর্যায় এখনও সাধারণ টেক্সট হিসেবে তার অনুরোধকৃত দৃশ্যমান রিজনিং তৈরি করতে পারে।

| `/api/rate-limits`                | GET/POST  | প্রতি-অ্যাকাউন্ট রেট লিমিটের অবস্থা (GET), অথবা কোনো সংযোগের জন্য রেট-লিমিট সুরক্ষা চালু বা বন্ধ করুন (POST `{connectionId, enabled}`)। `rateLimitProtection`-এর সমর্থিত লেখার পাথ (`PUT /api/providers/[id]`-এর মাধ্যমে কখনো পরিবর্তন করা হয় না)। দ্রষ্টব্য: `enabled: false` সুস্পষ্ট সুরক্ষা নিষ্ক্রিয় করে, তবে কোনো সক্রিয় API-কী সংযোগকে বৈশ্বিক স্বয়ংক্রিয়-সক্রিয়করণ নিরাপত্তাব্যবস্থা (`autoEnableApiKeyProviders`) থেকে বাদ দেয় না। |
| `/api/rate-limit`                 | GET       | বৈশ্বিক রেট লিমিট কনফিগারেশন (অপ্রচলিত; `/api/rate-limits`-এর উপনাম)                                                                                                                                                                                                                                                                                                                                                                               |

> `/api/resilience/*`-এর চারটি রুটের সবগুলোর জন্যই **ম্যানেজমেন্ট অথ** (`requireManagementAuth`) প্রয়োজন। প্রোভাইডার ব্রেকার, সংযোগ কুলডাউন এবং মডেল লকআউটের পূর্ণাঙ্গ বিশ্লেষণের জন্য [স্থিতিস্থাপকতা (বর্ধিত)](#resilience-extended) দেখুন।

### সংস্করণ এবং রিলিজ চ্যানেল

```bash
GET /api/system/version
```

শুধু লুপব্যাকের জন্য ম্যানেজমেন্ট রুট (অ্যাডমিন অথ)। এটি চলমান সংস্করণ, সর্বশেষ
প্রকাশিত সংস্করণ এবং স্বয়ংক্রিয় আপডেটের অবস্থা রিটার্ন করে। `releaseChannel` এবং `channels` হলো সংযোজিত
ফিল্ড (rail 3.8.54); `channel`-এর অর্থ অপরিবর্তিত থাকে — ড্যাশবোর্ড আপডেটার যে ডিপ্লয়মেন্ট মোড
ব্যবহার করে (`npm`, `source` অথবা `docker-compose`)।

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — চলমান বিল্ডের npm চ্যানেল: `-nightly.*` সংস্করণের জন্য `nightly`,
  অন্যান্য প্রি-রিলিজের (`-rc.*`, `-beta.*`, `-alpha.*`) জন্য `next`, `channels.latest`-এর চেয়ে
  পুরোনো মেজরের কোনো স্থিতিশীল সংস্করণের জন্য `lts`, অন্যথায় `latest`। এটি
  `scripts/release/dist-tag.mjs`-এর একই নিয়ম অনুসরণ করে, যা প্রকাশের সময় npm dist-tag নির্বাচন করে।
- `channels` — `npm view omniroute dist-tags` থেকে প্রতিটি dist-tag-এর সর্বশেষ প্রকাশিত সংস্করণ (registry
  HTTP fallback), যা `latest`-এর মতো একই ১০ মিনিটের TTL দিয়ে ক্যাশ করা হয়। `latest` সর্বদা উপস্থিত থাকে
  (প্রথমে `latest` ফিল্ডে এবং তারপর `"unavailable"`-এ ফলব্যাক করে); `next`, `nightly` এবং `lts` কেবল
  সংশ্লিষ্ট dist-tag বিদ্যমান থাকলেই প্রদর্শিত হয়। একটি `Cache-Control: no-cache` অনুরোধ উভয় লুকআপই রিফ্রেশ করে।

চ্যানেল মডেলটি (`latest` = 4.0 GA পর্যন্ত v3, `next` = rc, `nightly` = `develop` বিল্ড,
`lts` = 4.0 GA-এর পরের v3 প্যাচ) `docs/ops/RELEASE_STRATEGY.md`-এ বর্ণনা করা হয়েছে।

## অডিও ট্রান্সক্রিপশন

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data
```

কনফিগার করা যেকোনো STT প্রোভাইডার ব্যবহার করে অডিও ফাইল ট্রান্সক্রাইব করুন। প্রথম পাথ
সেগমেন্ট নেটিভ প্রোভাইডার নির্বাচন করে (`openai/…`, `deepgram/…`)। অন্য কোনো
ভেন্ডরের মডেল পুনরায় এক্সপোর্ট করা গেটওয়েগুলো একটি কোয়ালিফায়েড আইডি ব্যবহার করে
(`openrouter/deepgram/nova-3`)।

**অনুরোধ:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**প্রতিক্রিয়া:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**মডেল আইডির উদাহরণ:** `openai/whisper-1` (একটি OpenAI কী প্রয়োজন),
`openrouter/deepgram/nova-3` (একটি OpenRouter কী প্রয়োজন),
`deepgram/nova-3` (একটি নেটিভ Deepgram কী প্রয়োজন)। শুধু
`deepgram/nova-3` অনুরোধটি OpenRouter ব্যবহার করে **না**।

**সমর্থিত ফরম্যাট:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`।

## টোকেনযুক্ত VS Code / হেডারবিহীন উপনাম

যখন কোনো ইন্টিগ্রেশন `Authorization` হেডার ইনজেক্ট করতে পারে না এবং বেস URL-এ API কী এম্বেড করা প্রয়োজন হয়, তখন এই উপনামগুলো ব্যবহার করুন।

```bash
# OpenAI-স্টাইল ক্যাটালগ উপনাম
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# OpenAI-স্টাইল চ্যাট উপনাম
POST /api/v1/vscode/{token}/chat/completions
POST /api/v1/vscode/{token}/responses

# Ollama-স্টাইল উপনাম
POST /api/v1/vscode/{token}/api/chat
GET /api/v1/vscode/{token}/api/tags
```

উদাহরণ:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'
```

নোট:

- টোকেনযুক্ত উপনামগুলো `/v1/*` এবং `/api/tags`-এর মতো একই হ্যান্ডলার পুনরায় ব্যবহার করে; প্রতিক্রিয়ার কাঠামো অভিন্ন থাকে।
- ক্লায়েন্ট কাস্টম হেডার সমর্থন করলে সবসময় `Authorization: Bearer ...` ব্যবহার করাই শ্রেয়।
- URL-ভিত্তিক টোকেন রিভার্স-প্রক্সি লগ, ব্রাউজার ইতিহাস এবং OmniRoute-এর বাইরের টেলিমেট্রিতে দেখা যেতে পারে। এগুলোকে ডিফল্ট প্রমাণীকরণ মোড হিসেবে নয়, বরং একটি সামঞ্জস্য বিকল্প হিসেবে বিবেচনা করুন।

## বাজেট

```bash
# সব API কী-এর বাজেট স্ট্যাটাস নিন
GET /api/usage/budget

# একটি বাজেট সেট বা আপডেট করুন
POST /api/usage/budget
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "dailyLimitUsd": 5.00,
  "weeklyLimitUsd": 30.00,
  "monthlyLimitUsd": 100.00,
  "warningThreshold": 0.8,
  "resetInterval": "monthly"
}
```

> **স্কিমা নোট** (`setBudgetSchema`): `apiKeyId` আবশ্যক; `dailyLimitUsd`, `weeklyLimitUsd`, অথবা `monthlyLimitUsd`-এর মধ্যে অন্তত একটির মান অবশ্যই শূন্যের বেশি হতে হবে। ঐচ্ছিক ফিল্ড: `warningThreshold` (0–1), `resetInterval` (`daily` | `weekly` | `monthly`), `resetTime` (`HH:MM`)। পুরোনো `{keyId, limit, period}` কাঠামোটি `400 Bad Request` প্রদান করে।

## টোকেন সীমা

প্রতি-API-কী **টোকেন** বাজেট (উপরের USD-ভিত্তিক বাজেট থেকে পৃথক)। অনুরোধের পথে ইনলাইনে প্রয়োগ করা হয়: কোনো কী-এর বর্তমান উইন্ডোর ব্যবহার তার সীমায় পৌঁছালে, অনুরোধগুলো `429 Too Many Requests` দিয়ে প্রত্যাখ্যান করা হয়। সীমা একটি নির্দিষ্ট `model`, একটি `provider`-এর জন্য নির্ধারণ করা যেতে পারে অথবা পুরো কী জুড়ে `global`ভাবে প্রয়োগ করা যেতে পারে; যখন একাধিক সীমা কোনো অনুরোধের সঙ্গে মিলে যায়, তখন সবচেয়ে কঠোর সীমাটি কার্যকর হয়।

```bash
# একটি কী-এর টোকেন সীমাগুলো তালিকাভুক্ত করুন (লাইভ উইন্ডোর ব্যবহারসহ)
GET /api/usage/token-limits?apiKeyId=key-123

# একটি টোকেন সীমা তৈরি বা হালনাগাদ করুন
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# id অনুযায়ী একটি টোকেন সীমা মুছুন
DELETE /api/usage/token-limits?id=tl-abc
```

> **স্কিমা সম্পর্কিত নোট** (`setTokenLimitSchema`): `apiKeyId` এবং `scopeType` (`model` | `provider` | `global`) আবশ্যক। `scopeType` যদি `global` না হয়, তাহলে `scopeValue` আবশ্যক (যেমন, `model` স্কোপের জন্য একটি মডেল id, `provider` স্কোপের জন্য একটি প্রোভাইডার id)। `tokenLimit` অবশ্যই একটি ধনাত্মক পূর্ণসংখ্যা হতে হবে (স্ট্রিং থেকে রূপান্তরিত)। ঐচ্ছিক: `id` (তৈরি করতে বাদ দিন, হালনাগাদ করতে প্রদান করুন), `resetInterval` (`daily` | `weekly` | `monthly`, ডিফল্ট `monthly`), `resetTime` (`HH:MM`), `enabled` (ডিফল্ট `true`)। `GET` প্রতিক্রিয়াগুলো প্রতিটি সীমায় `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, এবং `nextResetAt` যোগ করে সমৃদ্ধ করে। এটি একটি ব্যবস্থাপনা-শ্রেণির এন্ডপয়েন্ট (authz পাইপলাইন কেন্দ্রীয়ভাবে প্রমাণীকরণ প্রয়োগ করে)।

## অনুরোধ প্রক্রিয়াকরণ

1. ক্লায়েন্ট `/v1/*`-এ অনুরোধ পাঠায়
2. রুট হ্যান্ডলার `handleChat`, `handleEmbedding`, `handleAudioTranscription`, অথবা `handleImageGeneration` কল করে
3. মডেল নির্ধারণ করা হয় (সরাসরি প্রোভাইডার/মডেল অথবা অ্যালিয়াস/কম্বো)
4. অ্যাকাউন্টের উপলভ্যতা ফিল্টার করে স্থানীয় DB থেকে ক্রেডেনশিয়াল নির্বাচন করা হয়
5. চ্যাটের জন্য: `handleChatCore` সেমান্টিক/সিগনেচার ক্যাশ পরীক্ষা করে এবং কম্বোর কম্প্রেশন সেটিংস নির্ধারণ করে
6. সক্রিয় থাকলে প্রোভাইডার অনুবাদের আগে প্রোঅ্যাকটিভ কম্প্রেশন চালানো হয় (`lite`, Caveman, RTK, অথবা স্ট্যাকড)
7. প্রোভাইডার এক্সিকিউটর আপস্ট্রিম অনুরোধ পাঠায়
8. প্রতিক্রিয়া ক্লায়েন্ট ফরম্যাটে পুনরায় অনুবাদ করা হয় (চ্যাট) অথবা অপরিবর্তিতভাবে ফেরত দেওয়া হয় (এম্বেডিং/ছবি/অডিও)
9. ব্যবহার, কম্প্রেশন অ্যানালিটিক্স, এবং অনুরোধের লগ রেকর্ড করা হয়
10. কম্বোর নিয়ম অনুযায়ী ত্রুটির ক্ষেত্রে ফলব্যাক প্রয়োগ করা হয়

সম্পূর্ণ আর্কিটেকচার রেফারেন্স: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## কম্বো ব্যবস্থাপনা

উচ্চ-স্তরের রাউটিং কম্বোগুলো (`/api/combos*`-এর অধীনে ইতিমধ্যে সংক্ষেপিত) একটি মডেল id প্যাটার্ন থেকে 1:1 অনুপাতেও ম্যাপ করা যেতে পারে, যা একটি OpenAI-ধাঁচের মডেল id-কে স্বচ্ছভাবে একটি কম্বোতে পুনর্নির্দেশ করার সুযোগ দেয়।

| পদ্ধতি | পাথ                              | বিবরণ                                                                            |
| ------ | -------------------------------- | -------------------------------------------------------------------------------- |
| GET    | `/api/model-combo-mappings`      | সব মডেল→কম্বো ম্যাপিং তালিকাভুক্ত করুন                                           |
| POST   | `/api/model-combo-mappings`      | ম্যাপিং তৈরি করুন — বডি: `{pattern, comboId, priority?, enabled?, description?}` |
| GET    | `/api/model-combo-mappings/[id]` | একটি নির্দিষ্ট ম্যাপিং পুনরুদ্ধার করুন                                           |
| PUT    | `/api/model-combo-mappings/[id]` | বিদ্যমান ম্যাপিংয়ের ফিল্ডগুলো হালনাগাদ করুন                                     |
| DELETE | `/api/model-combo-mappings/[id]` | একটি ম্যাপিং অপসারণ করুন                                                         |

**প্রমাণীকরণ:** ব্যবস্থাপনা সেশন/API কী (`requireManagementAuth`)।

| POST   | `/api/webhooks`           | ওয়েবহুক তৈরি করে — বডি: `{url, events?: ["*"], secret?, description?}`       |
| GET    | `/api/webhooks/[id]`      | একটি ওয়েবহুকের তথ্য পুনরুদ্ধার করে                                           |
| PUT    | `/api/webhooks/[id]`      | url/events/secret/description আপডেট করে                                       |
| DELETE | `/api/webhooks/[id]`      | একটি ওয়েবহুক সরিয়ে দেয়                                                     |
| POST   | `/api/webhooks/[id]/test` | ওয়েবহুক URL-এ একটি পরীক্ষামূলক পেলোড পাঠায় এবং ডেলিভারি স্ট্যাটাস ফেরত দেয় |

**প্রমাণীকরণ:** ম্যানেজমেন্ট সেশন/API কী (`requireManagementAuth`)।

## নিবন্ধিত কীসমূহ (স্বয়ংক্রিয় ব্যবস্থাপনা)

দৈনিক/ঘণ্টাভিত্তিক কোটাসহ কোনো ব্যাকিং প্রোভাইডার/অ্যাকাউন্টের বিপরীতে API কী ইস্যু ও রোটেট করতে স্বয়ংক্রিয় কী ব্যবস্থাপনা সাবসিস্টেম এটি ব্যবহার করে।

| মেথড   | পাথ                                   | বিবরণ                                                                                                                                                                                                         |
| ------ | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/v1/registered-keys`             | নিবন্ধিত কীগুলোর তালিকা দেখায় (শুধু মাস্ক করা প্রিফিক্স)                                                                                                                                                     |
| POST   | `/api/v1/registered-keys`             | একটি নতুন নিবন্ধিত কী ইস্যু করে — বডি: `{name, provider?, accountId?, idempotencyKey?, expiresAt?, dailyBudget?, hourlyBudget?}`। কাঁচা কীটি **একবারই** ফেরত দেয়। কোটা প্রত্যাখ্যান করা হলে `429` ফেরত দেয়। |
| GET    | `/api/v1/registered-keys/[id]`        | একটি নিবন্ধিত কী-এর মেটাডেটা পুনরুদ্ধার করে (কাঁচা উপাদান নয়)                                                                                                                                                |
| DELETE | `/api/v1/registered-keys/[id]`        | একটি নিবন্ধিত কী বাতিল করে                                                                                                                                                                                    |
| POST   | `/api/v1/registered-keys/[id]/revoke` | সুস্পষ্ট বাতিলকরণ এন্ডপয়েন্ট (DELETE-এর মতো একই প্রভাব)                                                                                                                                                      |

**প্রমাণীকরণ:** ম্যানেজমেন্ট সেশন/API কী (`requireManagementAuth`) — `/api/keys`-এর মতো একই গার্ড: একটি ড্যাশবোর্ড সেশন, স্থানীয় CLI টোকেন, অথবা `manage`/`admin` স্কোপসহ একটি API কী; শুধু ইনফারেন্সের জন্য ব্যবহৃত API কীগুলো `403` পায়। আরও দেখুন `/v1/quotas/check` এবং `/v1/issues/report`।

## এজেন্ট প্রোটোকল

OmniRoute ব্যবহারকারীদের পক্ষ থেকে দূরবর্তীভাবে সম্পাদিত ক্লাউড এজেন্ট টাস্কসমূহ (Claude Code, Codex Cloud, OpenHands ইত্যাদি)।

| মেথড   | পাথ                           | বিবরণ                                                                                                                                             |
| ------ | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/v1/agents/tasks`        | টাস্কের তালিকা — ঐচ্ছিক `?provider=`, `?status=`, `?limit=` (1–500, ডিফল্ট 50)                                                                    |
| POST   | `/api/v1/agents/tasks`        | টাস্ক তৈরি — বডি `CreateCloudAgentTaskSchema` (`providerId`, `prompt`, `source`, `options?`) দ্বারা যাচাই করা হয়। টাস্ক এনভেলপসহ `201` ফেরত দেয় |
| DELETE | `/api/v1/agents/tasks?id=...` | একটি টাস্ক মুছে দেয়                                                                                                                              |
| GET    | `/api/v1/agents/tasks/[id]`   | টাস্ক পড়ে — কোনো `external_id` সেট থাকলে আপস্ট্রিম ক্লাউড এজেন্ট থেকে সিঙ্ক্রোনাসভাবে স্ট্যাটাস রিফ্রেশ করে                                      |
| POST   | `/api/v1/agents/tasks/[id]`   | পৃথকীকৃত অ্যাকশন: `{action: "approve"}`, `{action: "message", message}`, অথবা `{action: "cancel"}`                                                |
| DELETE | `/api/v1/agents/tasks/[id]`   | id অনুযায়ী নির্দিষ্ট একটি টাস্ক মুছে দেয়                                                                                                        |

> **প্রমাণীকরণ:** প্রতিটি মেথডে ম্যানেজমেন্ট প্রমাণীকরণ আবশ্যক (`requireCloudAgentManagementAuth`)। v3.8.0-এর আগে এগুলো প্রমাণীকরণবিহীন ছিল — ব্রেকিং পরিবর্তনটির জন্য commit `588a0333` দেখুন।

```bash
# একটি Claude Code ক্লাউড টাস্ক তৈরি করুন
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Authorization: Bearer your-management-key" \
  -H "Content-Type: application/json" \
  -d '{"providerId":"claude-code-cloud","prompt":"Fix the failing test","source":{"repo":"...","branch":"..."}}'
```

## ম্যানেজমেন্ট প্রক্সি

প্রোভাইডার, অ্যাকাউন্ট অথবা বৈশ্বিকভাবে বরাদ্দ করা যায় এমন আউটবাউন্ড HTTP(S)/SOCKS প্রক্সি।

| মেথড   | পাথ                                          | বিবরণ                                                                                                                                                               |
| ------ | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/v1/management/proxies`                 | প্রক্সির তালিকা (`?id=` দিলে একটি ফেরত দেয়; `?id=&where_used=1` দিলে অ্যাসাইনমেন্ট গ্রাফ ফেরত দেয়)                                                                |
| POST   | `/api/v1/management/proxies`                 | প্রক্সি তৈরি — বডি `createProxyRegistrySchema` দ্বারা যাচাই করা হয়                                                                                                 |
| PATCH  | `/api/v1/management/proxies`                 | প্রক্সি আপডেট — বডি `updateProxyRegistrySchema` দ্বারা যাচাই করা হয় (`id` আবশ্যক)                                                                                  |
| DELETE | `/api/v1/management/proxies?id=...&force=1`  | প্রক্সি মুছে দেয় (অ্যাসাইনমেন্ট বিচ্ছিন্ন করতে `force=1` ব্যবহার করুন)                                                                                             |
| GET    | `/api/v1/management/proxies/assignments`     | অ্যাসাইনমেন্টের তালিকা — `proxy_id`, `scope`, `scope_id` অনুযায়ী ফিল্টার করা যায়; কোনো কানেকশনের সক্রিয় প্রক্সি নির্ধারণ করতে `resolve_connection_id=<id>` পাঠান |
| PUT    | `/api/v1/management/proxies/assignments`     | বরাদ্দ করে — বডি `proxyAssignmentSchema` (`{scope, scopeId?, proxyId?}`) দ্বারা যাচাই করা হয়। ডিসপ্যাচার ক্যাশ পরিষ্কার করে                                        |
| PUT    | `/api/v1/management/proxies/bulk-assign`     | একাধিক বরাদ্দ — বডি `bulkProxyAssignmentSchema` (`{scope, scopeIds[], proxyId?}`) দ্বারা যাচাই করা হয়                                                              |
| GET    | `/api/v1/management/proxies/health?hours=24` | একটি সময়সীমায় প্রক্সির সমষ্টিগত স্বাস্থ্যতথ্য (সফল/ব্যর্থ সংখ্যা, ল্যাটেন্সি)                                                                                     |

**প্রমাণীকরণ:** প্রতিটি রুটে ম্যানেজমেন্ট সেশন/API key (`requireManagementAuth`) আবশ্যক।

> টাস্কের বিবরণে উল্লেখিত `POST /api/v1/management/proxies/[id]/assignments` এবং `POST /api/v1/management/proxies/[id]/health` উপরে দেখানো সমতল `/assignments` ও `/health` রুট দ্বারা পরিবেশিত হয় — কোডবেসে প্রতিটি id-এর জন্য আলাদা কোনো সাবরুট নেই।

## স্থিতিস্থাপকতা (বর্ধিত)

OmniRoute তিনটি স্বতন্ত্র সাময়িক-ব্যর্থতা প্রক্রিয়া প্রদান করে; নিচের ব্যবস্থাপনা এন্ডপয়েন্টগুলো অপারেটরদের এগুলোর অবস্থা পড়তে এবং ওভাররাইড করতে দেয়:

| পরিধি              | স্টেট স্টোরেজ                        | পড়ুন                                     | রিসেট / সাফ করুন                                                  |
| ------------------ | ------------------------------------ | ----------------------------------------- | ----------------------------------------------------------------- |
| প্রোভাইডার ব্রেকার | `domain_circuit_breakers` + ইন-মেমরি | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                      |
| সংযোগ কুলডাউন      | প্রোভাইডার সংযোগে `rateLimitedUntil` | `/api/rate-limits`, `/api/providers/[id]` | (অলসভাবে পুনরায় সক্রিয় হয়; প্রোভাইডার PUT-এর মাধ্যমে সাফ করুন) |
| মডেল লকআউট         | ইন-মেমরি মডেল-উপলভ্যতা রেজিস্ট্রি    | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                          |

`PATCH /api/resilience` প্রোভাইডার ব্রেকার ওভাররাইডগুলো `providerBreaker.oauth` এবং `providerBreaker.apikey`-এর অধীনে গ্রহণ করে। প্রতিটি প্রোফাইল `degradationThreshold`, `failureThreshold`, এবং `resetTimeoutMs` সমর্থন করে; একই ফিল্ডগুলো ড্যাশবোর্ড → সেটিংস → স্থিতিস্থাপকতায়ও পাওয়া যায়।

```bash
# একটি মডেল লকআউট সাফ করুন
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# প্রতিটি লকআউট মুছে ফেলুন
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

সম্পূর্ণ ধারণাগত রেফারেন্স এবং ব্রেকারের ডিফল্ট মানের জন্য দেখুন: [`CLAUDE.md`](../../CLAUDE.md) → "স্থিতিস্থাপকতার রানটাইম স্টেট" এবং [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md)।

### রেট-লিমিট কিউ ও স্বয়ংক্রিয়-সক্রিয়করণ সুরক্ষা ব্যবস্থা

- **সমর্থিত লেখার পথ**: `POST /api/rate-limits`, যার বডি `{"connectionId": "<id>", "enabled": true|false}`, একটি সংযোগের রেট-লিমিট সুরক্ষা টগল করার জন্য সমর্থিত ব্যবস্থাপনা এন্ডপয়েন্ট। `PUT /api/providers/[id]` ইচ্ছাকৃতভাবে `rateLimitProtection` পরিবর্তন বা উল্টে দেয় না (#11278)।
- **`enabled: false`-এর অর্থ**: `enabled: false` সেট করলে সংযোগটির সুস্পষ্ট সুরক্ষা সরিয়ে দেওয়া হয়, কিন্তু এটি কোনো সক্রিয় API-key সংযোগকে বৈশ্বিক স্বয়ংক্রিয়-সক্রিয়করণ সুরক্ষা ব্যবস্থা (`autoEnableApiKeyProviders = true`) থেকে বাদ দেয় **না**। `reconcileEnabledConnections`-এ (`open-sse/services/rateLimitManager.ts`), `false` এবং `undefined` সমতুল্য; সুস্পষ্ট সুরক্ষা ছাড়া সক্রিয় API-key সংযোগগুলো স্বয়ংক্রিয়-সক্রিয়করণ সুরক্ষা ব্যবস্থার অধীনে সুরক্ষিত থাকে।
- **বৈশ্বিকভাবে নিষ্ক্রিয়করণ**: রেট-লিমিট কিউ ছাড়া API-key সংযোগ চালাতে, `RATE_LIMIT_AUTO_ENABLE=false` (env) অথবা `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (সেটিংস → স্থিতিস্থাপকতা / `PATCH /api/resilience`)-এর মাধ্যমে সুরক্ষা ব্যবস্থাটি বৈশ্বিকভাবে নিষ্ক্রিয় করুন।

## MCP সার্ভার

OmniRoute-এ ৩টি ট্রান্সপোর্ট (stdio, SSE, streamable-http) এবং স্কোপযুক্ত টুলসহ একটি এমবেডেড Model Context Protocol সার্ভার অন্তর্ভুক্ত রয়েছে। নিচের ড্যাশবোর্ড এন্ডপয়েন্টগুলো স্ট্যাটাস/অডিট ডেটা পড়ে এবং HTTP ট্রান্সপোর্টগুলোকে প্রক্সি করে।

| পদ্ধতি | পাথ | বিবরণ |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | হার্টবিট, ট্রান্সপোর্ট, অনলাইন অবস্থা, সর্বশেষ কল, শীর্ষ টুল, ২৪ ঘণ্টার সাফল্যের হার |
| GET | `/api/mcp/tools` | `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints`-সহ MCP টুলের তালিকা |
| GET | `/api/mcp/sse` | SSE ট্রান্সপোর্টের জন্য SSE স্ট্রিম খুলুন (MCP নিষ্ক্রিয় থাকলে বা ট্রান্সপোর্ট না মিললে `503` ফেরত দেয়) |
| POST | `/api/mcp/sse` | SSE ট্রান্সপোর্টে JSON-RPC ফ্রেম পাঠান |
| GET | `/api/mcp/stream` | Streamable HTTP ট্রান্সপোর্টের SSE অংশ খুলুন (সার্ভার থেকে শুরু করা বার্তা) |
| POST | `/api/mcp/stream` | Streamable HTTP ট্রান্সপোর্টে JSON-RPC ফ্রেম পাঠান |
| DELETE | `/api/mcp/stream` | একটি Streamable HTTP সেশন শেষ করুন |
| GET | `/api/mcp/audit` | অডিট লগ কোয়েরি করুন — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | সমষ্টিগত অডিট পরিসংখ্যান (মোট সংখ্যা, সাফল্যের হার, গড় সময়কাল, শীর্ষ টুল) |

**প্রমাণীকরণ:** `sse`/`stream` ট্রান্সপোর্টগুলো MCP-নির্দিষ্ট প্রমাণীকরণ ব্যবস্থা অনুসরণ করে (`mcp` স্কোপসহ Bearer API কী); `status`/`tools`/`audit*` রুটগুলো ড্যাশবোর্ড থেকে পড়া যায় (ড্যাশবোর্ড হোস্টে পৌঁছানোর বাইরে অতিরিক্ত প্রমাণীকরণের প্রয়োজন নেই)।

> উভয় HTTP ট্রান্সপোর্টই `settings.mcpEnabled` এবং `settings.mcpTransport` দ্বারা নিয়ন্ত্রিত — ট্রান্সপোর্ট না মিললে `400` এবং MCP নিষ্ক্রিয় থাকলে `503` ফেরত দেয়।

## A2A সার্ভার

OmniRoute পরিদর্শন/ড্যাশবোর্ডে ব্যবহারের জন্য একটি REST র্যাপারসহ A2A (Agent-to-Agent) JSON-RPC 2.0 এন্ডপয়েন্ট প্রদান করে।

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # OMNIROUTE_API_KEY সেট করা না থাকলে ঐচ্ছিক
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

সমর্থিত মেথডসমূহ (সবগুলোই `settings.a2aEnabled` দ্বারা নিয়ন্ত্রিত):

| মেথড             | বিবরণ                                                                   |
| ---------------- | ----------------------------------------------------------------------- |
| `message/send`   | সিঙ্ক্রোনাস স্কিল এক্সিকিউশন; `{task, artifacts, metadata}` রিটার্ন করে |
| `message/stream` | একই স্কিল সেটের স্ট্রিমিং SSE এক্সিকিউশন                                |
| `tasks/get`      | `taskId` দিয়ে একটি টাস্ক ফেচ করে                                       |
| `tasks/cancel`   | `taskId` দিয়ে একটি টাস্ক বাতিল করে                                     |

বিল্ট-ইন স্কিলসমূহ: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`।

### এজেন্ট কার্ড

```bash
GET /.well-known/agent.json
```

পাবলিক A2A এজেন্ট কার্ড (নাম, বিবরণ, সক্ষমতা, স্কিল ক্যাটালগ, অথ স্কিম) রিটার্ন করে—যা সর্বজনীনভাবে 1h-এর জন্য ক্যাশ করা হয়। কোনো অথ প্রয়োজন নেই।

### REST সহায়ক

| মেথড | পাথ                          | বিবরণ                                                                                                             |
| ---- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| GET  | `/api/a2a/status`            | A2A সক্রিয় আছে কি না + টাস্কের পরিসংখ্যান + ক্যাশ করা এজেন্ট কার্ডের সারাংশ                                      |
| GET  | `/api/a2a/tasks`             | টাস্কের তালিকা—`?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST | `/api/a2a/tasks`             | (REST সহায়ক হিসেবে বাস্তবায়িত নয়—JSON-RPC `message/send` দিয়ে তৈরি করুন)                                      |
| GET  | `/api/a2a/tasks/[id]`        | একটি টাস্ক রিট্রিভ করে                                                                                            |
| POST | `/api/a2a/tasks/[id]/cancel` | একটি টাস্ক বাতিল করে                                                                                              |

**অথ:** REST সহায়কগুলো ম্যানেজমেন্ট অথ ছাড়াই চলে (ড্যাশবোর্ড থেকে পাঠযোগ্য); কনফিগার করা থাকলে JSON-RPC `/a2a` রুট Bearer `OMNIROUTE_API_KEY` ব্যবহার করে।

| GET | `/api/cloud/models/alias` | ক্লাউড সিঙ্কে প্রকাশিত মডেল অ্যালিয়াসগুলোর তালিকা দেখায় |
| GET | `/api/assess` | সর্বশেষ অ্যাসেসমেন্ট শ্রেণিবিন্যাস (প্রতি প্রোভাইডার/মডেল) পড়ে |
| POST | `/api/assess` | একটি অ্যাসেসমেন্ট চালায়—বডি: `{scope: {type:"all"}                                                   | {type:"provider", providerId} | {type:"model", modelId}, trigger?}` |
| GET | `/api/evals` | বিল্ট-ইন ইভ্যাল স্যুট + সাম্প্রতিকতম রানগুলোর তালিকা দেখায় |
| POST | `/api/evals` | একটি ইভ্যাল রান ট্রিগার করে |
| POST | `/api/evals/suites` | একটি কাস্টম ইভ্যাল স্যুট তৈরি করে—বডি `evalSuiteSaveSchema` দ্বারা যাচাই করা হয় |
| GET | `/api/evals/suites/[id]` | একটি কাস্টম ইভ্যাল স্যুট রিট্রিভ করে |

**অথ:** `/api/cloud/auth` সরাসরি একটি Bearer কী যাচাই করে এবং কেবল `manage` / `admin` স্কোপযুক্ত কীর ক্ষেত্রে প্রতিটি কানেকশনের মাস্ক করা কী ও `projectId` রিটার্ন করে; অন্যান্য `/api/cloud/*`, `/api/evals/*` এবং `/api/assess` রুটে ম্যানেজমেন্ট সেশন/API কী প্রয়োজন। `/api/assess` POST একটি ডিসক্রিমিনেটেড-ইউনিয়ন স্কোপ স্কিমাসহ `validateBody` ব্যবহার করে।

## ACP (Agent Client Protocol) ব্যবস্থাপনা

চাইল্ড প্রসেস হিসেবে। এই এন্ডপয়েন্টগুলো ACP এজেন্ট শনাক্তকরণ এবং কাস্টম এজেন্ট
নিবন্ধন পরিচালনা করে।

| মেথড   | পাথ               | বিবরণ                                                                                                                                                          |
| ------ | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/acp/agents` | ইনস্টলেশনের অবস্থা, সংস্করণ ও বাইনারিসহ সব পরিচিত CLI এজেন্টের (বিল্ট-ইন + কাস্টম) তালিকা দেখায়                                                               |
| POST   | `/api/acp/agents` | একটি কাস্টম ACP এজেন্ট নিবন্ধন বা ক্যাশ রিফ্রেশ করে — বডি: `{id, name, binary, versionCommand, providerAlias, spawnArgs, protocol}` অথবা `{action: "refresh"}` |
| DELETE | `/api/acp/agents` | একটি কাস্টম ACP এজেন্ট সরিয়ে দেয় — কোয়েরি প্যারামিটার: `?id=<agentId>`                                                                                      |

**রেসপন্সের উদাহরণ** (`GET /api/acp/agents`):

```json
{
  "agents": [
    {
      "id": "claude",
      "name": "Claude Code CLI",
      "binary": "claude",
      "version": "1.0.45",
      "installed": true,
      "protocol": "stdio",
      "providerAlias": "claude",
      "isCustom": false
    },
    {
      "id": "my-custom-cli",
      "name": "My Custom CLI",
      "installed": false,
      "protocol": "stdio",
      "providerAlias": "my-provider",
      "isCustom": true
    }
  ],
  "cacheTtlMs": 60000,
  "cacheAge": 1234
}
```

**প্রমাণীকরণ:** ম্যানেজমেন্ট সেশন (ড্যাশবোর্ডের `auth_token` কুকি) অথবা একটি
ম্যানেজমেন্ট-স্কোপড API কী প্রয়োজন।

সম্পূর্ণ বিবরণের জন্য [ACP ফ্রেমওয়ার্ক](../frameworks/ACP.md) দেখুন।

## ওয়েবহুক

ইভেন্টের জন্য ওয়েবহুক সাবস্ক্রিপশন পরিচালনা করুন।

| পদ্ধতি | পাথ                             | বিবরণ                                                                           |
| ------ | ------------------------------- | ------------------------------------------------------------------------------- |
| GET    | `/api/webhooks`                 | সব ওয়েবহুক সাবস্ক্রিপশনের তালিকা                                               |
| POST   | `/api/webhooks`                 | একটি ওয়েবহুক সাবস্ক্রিপশন তৈরি করুন — বডি: `{url, events[], secret?, active?}` |
| GET    | `/api/webhooks/[id]`            | নির্দিষ্ট একটি ওয়েবহুক সাবস্ক্রিপশন পান                                        |
| PUT    | `/api/webhooks/[id]`            | একটি ওয়েবহুক সাবস্ক্রিপশন আপডেট করুন                                           |
| DELETE | `/api/webhooks/[id]`            | একটি ওয়েবহুক সাবস্ক্রিপশন মুছুন                                                |
| GET    | `/api/webhooks/[id]/deliveries` | একটি ওয়েবহুকের ডেলিভারি ইতিহাসের তালিকা (সাফল্য/ব্যর্থতার লগ)                  |
| POST   | `/api/webhooks/[id]/test`       | একটি ওয়েবহুকে পরীক্ষামূলক ইভেন্ট পাঠান                                         |

**প্রমাণীকরণ:** ম্যানেজমেন্ট সেশন আবশ্যক।

ইভেন্টের সব ধরনের সম্পূর্ণ তালিকার জন্য [ওয়েবহুক ফ্রেমওয়ার্ক](../frameworks/WEBHOOKS.md) দেখুন।

## স্কিলস ফ্রেমওয়ার্ক

স্কিলসমূহ (এজেন্টিক এক্সটেনশন ফ্রেমওয়ার্ক) পরিচালনা করুন।

| মেথড   | পাথ                      | বিবরণ                                                                                              |
| ------ | ------------------------ | -------------------------------------------------------------------------------------------------- |
| GET    | `/api/skills`            | ইনস্টল করা সব স্কিলের তালিকা দেখুন (বিল্ট-ইন + কাস্টম)                                             |
| POST   | `/api/skills/install`    | লোকাল পাথ বা URL থেকে একটি স্কিল ইনস্টল করুন                                                       |
| DELETE | `/api/skills/[id]`       | একটি স্কিল আনইনস্টল করুন                                                                           |
| PUT    | `/api/skills/[id]`       | একটি স্কিল সক্রিয় বা নিষ্ক্রিয় করুন — বডি: `{enabled?: boolean, mode?: "on" \| "off" \| "auto"}` |
| POST   | `/api/skills/executions` | একটি স্কিল কার্যকর করুন — বডি: `{skillName, apiKeyId, input?, sessionId?}`                         |
| GET    | `/api/skills/executions` | সব স্কিলের কার্যকরকরণ ইতিহাসের তালিকা দেখুন (`?apiKeyId=` দিয়ে ফিল্টার করুন)                      |

**প্রমাণীকরণ:** ম্যানেজমেন্ট সেশন বা ম্যানেজমেন্ট-স্কোপড API কী প্রয়োজন।

সম্পূর্ণ বিবরণের জন্য [স্কিলস ফ্রেমওয়ার্ক](../frameworks/SKILLS.md) দেখুন।

## প্লাগইনসমূহ

OmniRoute প্লাগইনসমূহ (তৃতীয়-পক্ষের এক্সটেনশন) পরিচালনা করুন।

| মেথড   | পাথ                                | বিবরণ                                      |
| ------ | ---------------------------------- | ------------------------------------------ |
| GET    | `/api/plugins`                     | ইনস্টল করা প্লাগইনসমূহের তালিকা দেখুন      |
| POST   | `/api/plugins/marketplace/install` | মার্কেটপ্লেস থেকে একটি প্লাগইন ইনস্টল করুন |
| DELETE | `/api/plugins/[name]`              | একটি প্লাগইন আনইনস্টল করুন                 |
| POST   | `/api/plugins/[name]/activate`     | একটি প্লাগইন সক্রিয় করুন                  |
| POST   | `/api/plugins/[name]/deactivate`   | একটি প্লাগইন নিষ্ক্রিয় করুন               |
| GET    | `/api/plugins/[name]/config`       | প্লাগইনের কনফিগারেশন পান                   |
| PUT    | `/api/plugins/[name]/config`       | প্লাগইনের কনফিগারেশন আপডেট করুন            |

**প্রমাণীকরণ:** ম্যানেজমেন্ট সেশন প্রয়োজন।

সম্পূর্ণ বিবরণের জন্য [প্লাগইনস ফ্রেমওয়ার্ক](../frameworks/PLUGIN_SDK.md) দেখুন।

## শ্যাডো রাউটিং

প্রোভাইডারগুলোর শ্যাডো / A-B তুলনা **একটি স্বতন্ত্র REST সারফেস নয়** — এটি কম্বো রাউটিংয়ের মাধ্যমে কনফিগার করা হয় ([অটো-কম্বো](../routing/AUTO-COMBO.md) দেখুন)। প্রতি-কম্বো তুলনামূলক মেট্রিক্স `GET /api/combos/metrics` দ্বারা সরবরাহ করা হয়।

## গার্ডরেইলসমূহ

রানটাইম গার্ডরেইলসমূহ (PII শনাক্তকরণ, প্রম্পট ইনজেকশন শনাক্তকরণ, ভিশন ব্রিজিং) পরিদর্শন করুন। প্রতিটি রিকোয়েস্টে গার্ডরেইল চলে; প্রতি-কলে অপ্ট-আউট করতে `x-omniroute-disabled-guardrails` রিকোয়েস্ট হেডার ব্যবহার করুন — স্থায়ীভাবে সক্রিয়/নিষ্ক্রিয় করার কোনো সারফেস নেই।

| মেথড | পাথ                    | বিবরণ                                                                                        |
| ---- | ---------------------- | -------------------------------------------------------------------------------------------- |
| GET  | `/api/guardrails`      | নিবন্ধিত গার্ডরেইলসমূহ এবং সেগুলোর স্ট্যাটাসের তালিকা দেখুন (নাম / সক্রিয় / অগ্রাধিকার)     |
| POST | `/api/guardrails/test` | একটি নমুনা ইনপুটের ওপর প্রি-কল পাইপলাইন ড্রাই-রান করুন — বডি: `{input, disabledGuardrails?}` |

**প্রমাণীকরণ:** ম্যানেজমেন্ট সেশন প্রয়োজন।

সম্পূর্ণ বিবরণের জন্য [নিরাপত্তা > গার্ডরেইলসমূহ](../security/GUARDRAILS.md) দেখুন।

## প্রমাণীকরণ

চারটি ক্রেডেনশিয়াল শ্রেণি (ড্যাশবোর্ড সেশন, স্থানীয় CLI টোকেন, `oma_live_…` অ্যাক্সেস টোকেন, ম্যানেজমেন্ট-স্কোপড API কী) এবং ইনফারেন্স কী থেকে এগুলো কীভাবে আলাদা, তা জানতে [ম্যানেজমেন্ট প্রমাণীকরণ](../guides/MANAGEMENT-AUTH.md) দেখুন।

- ড্যাশবোর্ড রুটগুলো (`/dashboard/*`) `auth_token` কুকি ব্যবহার করে
- লগইনে সংরক্ষিত পাসওয়ার্ড হ্যাশ ব্যবহার করা হয়; ফলব্যাক হিসেবে `INITIAL_PASSWORD`
- `requireLogin` `/api/settings/require-login`-এর মাধ্যমে টগল করা যায়
- `REQUIRE_API_KEY=true` হলে `/v1/*` রুটগুলোর জন্য ঐচ্ছিকভাবে Bearer API কী প্রয়োজন হয়
- এই রেফারেন্সে "ম্যানেজমেন্ট টোকেন" / "ম্যানেজমেন্ট-স্কোপড API কী" বলতে ওই নির্দেশিকায় উল্লেখিত শ্রেণিগুলোর একটিকে বোঝায়—সংজ্ঞায়িত নয় এমন কোনো অতিরিক্ত গোপন তথ্যের ধরনকে নয়

> **ব্রেকিং পরিবর্তন (v3.8.0)** — `/api/v1/agents/tasks/*` এবং কুলডাউন ম্যানেজমেন্ট এন্ডপয়েন্টগুলোর জন্য এখন **ম্যানেজমেন্ট প্রমাণীকরণ** (ড্যাশবোর্ড `auth_token` কুকি বা একটি ম্যানেজমেন্ট-স্কোপড API কী) আবশ্যক। যেসব ক্লায়েন্ট আগে প্রমাণীকরণ ছাড়াই এই রুটগুলো কল করত, তারা `401 Unauthorized` পাবে। কমিট `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`) দেখুন।
