> **সংক্ষেপে**: OmniRoute তার **বিনামূল্যের** প্রদানকারীদের মডেলের গুণমান অনুযায়ী ক্রম নির্ধারণ করতে **Arena AI
> (LMArena-শৈলীর) ELO স্কোর** ব্যবহার করে। আপনার কাজের জন্য কোন বিনামূল্যের প্রদানকারীরা সবচেয়ে শক্তিশালী মডেল দেয় তা দেখতে
> ড্যাশবোর্ডের **বিনামূল্যের প্রদানকারীদের র্যাঙ্কিং** পৃষ্ঠা খুলুন —
> সামগ্রিকভাবে অথবা বিভাগ অনুযায়ী ফিল্টার করে (কোডিং, পর্যালোচনা, ডকুমেন্টেশন, ডিবাগিং)।

## এটা কি

OmniRoute 377 প্রদানকারীকে নিবন্ধন করে, যার মধ্যে 155টি ক্যাটালগ এন্ট্রি চিহ্নিত**free/no-auth** (no-auth, free-tier OAuth, বা free-tier API কী — দেখুন [ফ্রি টিয়ার গাইড](../getting-started/FREE-TIERS-GUIDE.md) এবং সম্পূর্ণ [ফ্রি টিয়ার ডিরেক্টরি](../reference/FREE_TIERS.md) )। ক্যাচ: বিনামূল্যে প্রদানকারীরা মডেলের গুণমানে ব্যাপকভাবে পরিবর্তিত হয়। একটি নো-অথ প্রদানকারী একটি সীমান্ত মডেল পরিবেশনকারী একটি ছোট উত্তরাধিকার মডেল পরিবেশনকারীর চেয়ে অনেক বেশি কার্যকর।

**বিনামূল্যে প্রদানকারী র্যাঙ্কিং** উত্তর "** কোন বিনামূল্যে প্রদানকারী আমাকে সেরা মডেল দেয়?** প্রতিটি বিনামূল্যে প্রদানকারীর ক্যাটালগে যোগদান করে** ক্রাউড-সোর্সড কোয়ালিটি স্কোর** থেকে** এরিনা AI লিডারবোর্ড** (মানব-অভিরুচি ELO, LMArena চ্যাটবট অঙ্গনের পিছনে একই ধারণা)। প্রদানকারীদের তারপর তাদের শক্তি দ্বারা র্যাঙ্ক করা হয়** সেরা বিনামূল্যে মডেল** .

র্যাঙ্কিং তিনটি বাস্তব উৎস থেকে গণনা করা হয়:

1. ফ্রি-প্রোভাইডার তালিকা — `NOAUTH_PROVIDERS`, প্লাস `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` এন্ট্রি পতাকাঙ্কিত `hasFree` (`src/shared/constants/providers.ts`)।
2. প্রদানকারী রেজিস্ট্রি থেকে প্রতিটি প্রদানকারীর মডেল ক্যাটালগ (`open-sse/config/providerRegistry.ts`)।
3. এরিনা ELO সিঙ্ক ইঞ্জিন (`src/lib/arenaEloSync.ts`) দ্বারা `model_intelligence` DB টেবিলে সংরক্ষিত ELO-প্রাপ্ত টাস্ক-ফিট স্কোর।

জয়েন লজিক `src/lib/freeProviderRankings.ts` তে বাস করে।

## কীভাবে অ্যাক্সেস করবেন

### ড্যাশবোর্ড পৃষ্ঠা

ড্যাশবোর্ড খুলে **খরচ → বিনামূল্যের প্রদানকারীদের র্যাঙ্কিং**-এ যান, অথবা সরাসরি এখানে নেভিগেট করুন:

```
/dashboard/free-provider-rankings
```

এই পৃষ্ঠায় (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) দেখা যায়:

- সেরা র্যাঙ্কপ্রাপ্ত বিনামূল্যের প্রদানকারীদের একটি **শীর্ষ-৩ পোডিয়াম** (🥇 🥈 🥉)।
- **র্যাঙ্ক**, **প্রদানকারী**, **শীর্ষ মডেল**,
  **স্কোর**, **গড় স্কোর**, **মডেল**, **ধরন** কলামসহ একটি পূর্ণাঙ্গ **র্যাঙ্কিং টেবিল**।
- **বিভাগ ফিল্টার বোতাম**: _সব বিভাগ_, _ডিফল্ট_, _কোডিং_, _পর্যালোচনা_,
  _ডকুমেন্টেশন_, _ডিবাগিং_।

প্রতিটি প্রদানকারীর **ধরন** ব্যাজ জানায় সেটি কীভাবে বিনামূল্যে পাওয়া যায়:

| ব্যাজ    | অর্থ                                              |
| -------- | ------------------------------------------------- |
| `NOAUTH` | সর্বদা বিনামূল্যে, কোনো পরিচয়পত্রের প্রয়োজন নেই |
| `OAUTH`  | বিনামূল্যের স্তরসহ OAuth প্রদানকারী (`hasFree`)   |
| `APIKEY` | বিনামূল্যের স্তরসহ API-কী প্রদানকারী (`hasFree`)  |

স্কোরগুলো অপরিশোধিত সংখ্যার পরিবর্তে মানুষের পাঠযোগ্য লেবেল হিসেবে দেখানো হয় (যেমন _অভিজাত_, _চমৎকার_, _খুব ভালো_,
_ভালো_, _গড়_), কারণ অন্তর্নিহিত মানটি একটি আপেক্ষিক
র্যাঙ্কিং-গুণমান, শতকরা হার নয়।

### API এন্ডপয়েন্ট

পৃষ্ঠাটি একটি সর্বজনীন রিড এন্ডপয়েন্ট দ্বারা পরিচালিত
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

কোয়েরি প্যারামিটারসমূহ (Zod দিয়ে যাচাই করা):

| প্যারামিটার | ধরন    | ডিফল্ট        | নোট                                                                                                                  |
| ----------- | ------ | ------------- | -------------------------------------------------------------------------------------------------------------------- |
| `category`  | string | (কোনোটিই নয়) | `default`, `coding`, `review`, `documentation`, `debugging`-এর যেকোনো একটি। সম্মিলিত র্যাঙ্কিংয়ের জন্য এটি বাদ দিন। |
| `limit`     | number | `50`          | `1–100` সীমার মধ্যে আবদ্ধ করা হয়।                                                                                   |

রেসপন্সের কাঠামো:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` হলো মূল Arena ELO মান; `score` হলো স্বাভাবিকীকৃত কাজের উপযোগিতা মান
(নিচে দেখুন)। স্কোরযুক্ত কোনো মডেল নেই এমন প্রদানকারীদের রেসপন্স থেকে বাদ দেওয়া হয়।

## স্কোরগুলো কীভাবে কাজ করে

### উৎস: Arena AI লিডারবোর্ড

Arena ELO সিঙ্ক ইঞ্জিন (`src/lib/arenaEloSync.ts`) Arena AI লিডারবোর্ড API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) থেকে দুটি লিডারবোর্ড — `text`
ও `code` — সংগ্রহ করে। যদি সেই API কোনো ব্যবহারযোগ্য বোর্ড না ফেরায়, তাহলে ইঞ্জিনটি
Hugging Face datasets-server-এর অফিসিয়াল `lmarena-ai/leaderboard-dataset`-এ ফলব্যাক করে
(`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` `activeSource`, `lastError` এবং
`lastFailedAt` রিপোর্ট করে। প্রতিটি লিডারবোর্ড এন্ট্রিতে
একটি মডেলের নাম, ভেন্ডর, ELO `score`, কনফিডেন্স ইন্টারভাল এবং ভোট সংখ্যা থাকে।

লিডারবোর্ড ক্যাটাগরিগুলো OmniRoute টাস্ক ক্যাটাগরিতে ম্যাপ হয়:

| Arena লিডারবোর্ড | OmniRoute টাস্ক ক্যাটাগরি                         |
| ---------------- | ------------------------------------------------- |
| `text`           | `default`, `review`, `documentation`, `debugging` |
| `code`           | `coding`                                          |

### নরমালাইজেশন (task-fit স্কোর)

কাঁচা ELO স্কোরগুলো প্রতিটি লিডারবোর্ড অনুযায়ী একটি **`[0.4, 0.98]` পরিসরের task-fit মানে** নরমালাইজ করা হয়:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

স্কোরটি কখনো `0` বা `1`-এ পৌঁছায় না, যাতে ব্যবহারকারীর ওভাররাইডের জন্য জায়গা থেকে যায়। এটিই
সেই `score` ফিল্ড যা আপনি API রেসপন্সে দেখেন এবং ড্যাশবোর্ডে যে লেবেলটি দেখানো হয়।

### কনফিডেন্স

প্রতিটি এন্ট্রি Arena ভোট সংখ্যার ভিত্তিতে একটি কনফিডেন্স লেভেল পায়:

| কনফিডেন্স | ভোট     |
| --------- | ------- |
| `high`    | ≥ 5,000 |
| `medium`  | ≥ 1,000 |
| `low`     | < 1,000 |

### সংরক্ষণ ও সতেজতা

নরমালাইজ করা এন্ট্রিগুলো `model_intelligence` DB টেবিলে
`source = "arena_elo"` সহ লেখা হয় (`src/lib/db/modelIntelligence.ts`)। এন্ট্রিগুলো **7 দিন পর
মেয়াদোত্তীর্ণ হয়ে যায়**, তাই যে প্রোভাইডার সিঙ্ক করা বন্ধ করে দেয় সে পুরনো ডেটা
পরিবেশন না করে ধীরে ধীরে তালিকা থেকে বাদ পড়ে যায়।

সিঙ্কটি **ডিফল্টভাবে চালু** থাকে:

- এটি সার্ভার চালু হওয়ার সময় একবার চলে এবং তারপর একটি পর্যায়ক্রমিক টাইমারে চলতে থাকে
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` থেকে সংযুক্ত)।
- এটি **নন-ব্লকিং এবং কখনোই ফ্যাটাল নয়** — আপস্ট্রিম ফেচ ব্যর্থ হলে OmniRoute চলতে
  থাকে এবং র্যাংকিংগুলো কেবল সর্বশেষ সঠিক ডেটা (বা একটি খালি অবস্থা) দেখায়।

দুটি এনভায়রনমেন্ট ভেরিয়েবল এটি নিয়ন্ত্রণ করে (ডকুমেন্টেশন
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)-এ):

| ভেরিয়েবল                 | ডিফল্ট        | উদ্দেশ্য                                           |
| ------------------------- | ------------- | -------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | আউটবাউন্ড সিঙ্ক থেকে বাদ পড়তে `false`-এ সেট করুন। |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | সিঙ্ক ব্যবধান, সেকেন্ডে।                           |

### ম্যানুয়াল সিঙ্ক / স্ট্যাটাস / মুছে ফেলা

অপারেটরদের জন্য, একটি অথেন্টিকেটেড ম্যানেজমেন্ট এন্ডপয়েন্ট ম্যানুয়াল নিয়ন্ত্রণ দেয়
(`src/app/api/intelligence/sync/route.ts` — ম্যানেজমেন্ট অথ প্রয়োজন):

```
GET    /api/intelligence/sync          # বর্তমান সিঙ্ক স্ট্যাটাস (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # একটি ম্যানুয়াল সিঙ্ক ট্রিগার করুন; body: { "dryRun": true } লেখা ছাড়াই প্রিভিউ করতে
DELETE /api/intelligence/sync          # সব সিঙ্ক করা arena_elo ইন্টেলিজেন্স এন্ট্রি মুছে ফেলুন
```

যদি র্যাংকিং পেজটি খালি থাকে, তাহলে একটি ম্যানুয়াল `POST /api/intelligence/sync` (বা কেবল
সার্ভার রিস্টার্ট করা) এটি পুনরায় পূরণ করে।

### লিডারবোর্ডের সাথে মডেল মিলানো

রেজিস্ট্রি মডেল ID এবং Arena মডেলের নাম সবসময় হুবহু মেলে না। র্যাংকিংটি
নমনীয় ম্যাচিং ব্যবহার করে (`src/lib/freeProviderRankings.ts`-এ `findMatchingIntelligence`):

1. নরমালাইজ করা মডেল ID-তে হুবহু মিল।
2. শেষের ভার্সন সাফিক্স বাদ দেওয়ার পর মিল (যেমন `kimi-k2.6` → `kimi-k2`)।
3. প্রিফিক্স মিল (একটি লিডারবোর্ড মডেলের নাম রেজিস্ট্রি ID-এর প্রিফিক্স)।

সিঙ্কের দিকে, পরিচিত ভেন্ডর প্রিফিক্সগুলো (`anthropic/`, `openai/`, `google/`, …)
বাদ দেওয়া হয় এবং একটি ছোট অ্যালিয়াস ম্যাপ ক্যানোনিক্যাল নামগুলোকে OmniRoute-এর
অভ্যন্তরীণভাবে ব্যবহৃত ভ্যারিয়েন্টে প্রসারিত করে, যাতে মডেলগুলো যেকোনো নামে খুঁজে পাওয়া যায়।

### কীভাবে একটি প্রোভাইডার র্যাংক করা হয়

প্রতিটি ফ্রি প্রোভাইডারের জন্য, ইঞ্জিনটি তার ক্যাটালগের প্রতিটি মডেলকে স্কোর করে, তারপর:

- **Top Model** = প্রোভাইডারের সর্বোচ্চ স্কোর করা মডেল।
- **Avg Score** = সেই প্রোভাইডারের সব স্কোর করা মডেলের গড় স্কোর।
- **Models** = প্রোভাইডারের কতগুলো মডেলের Arena স্কোর ছিল।

প্রোভাইডারগুলো প্রথমে **টপ-মডেল স্কোর** অনুযায়ী, তারপর গড় স্কোর অনুযায়ী সাজানো হয়। এটি
এমন একটি প্রোভাইডারকে পুরস্কৃত করে যা অন্তত একটি শক্তিশালী ফ্রি মডেল সরবরাহ করে।

## বিনামূল্যের প্রদানকারী বেছে নিতে এটি ব্যবহার করা

1. **সঠিক বিভাগটি বেছে নিন।** এজেন্টিক/কোড ওয়ার্কলোডের জন্য **Coding** ফিল্টার ব্যবহার করুন, অথবা
   সাধারণ চ্যাটের জন্য এটিকে **All Categories** / **Default**-এ রাখুন। একই প্রদানকারীর
   অবস্থান বিভিন্ন বিভাগে ভিন্ন হতে পারে, কারণ প্রতিটি লিডারবোর্ডে এর শীর্ষ মডেলটি আলাদা হয়।
2. **একবারেই সেটআপ করতে শীর্ষস্থানীয়গুলোকে অগ্রাধিকার দিন।** আপনি যদি শুধু একটি বা দুটি বিনামূল্যের
   প্রদানকারী সংযুক্ত করতে চান, তাহলে আপনার বিভাগের সর্বোচ্চ র্যাঙ্কেরগুলো দিয়ে শুরু করুন।
3. **Type ব্যাজ পরীক্ষা করুন।** `NOAUTH` প্রদানকারীগুলো সবচেয়ে দ্রুত সংযুক্ত করা যায় (কোনো
   পরিচয়পত্র লাগে না)। `OAUTH` / `APIKEY` বিনামূল্যের স্তরের জন্য দ্রুত সাইন-আপ করতে হয়, তবে এগুলো প্রায়ই
   আরও শক্তিশালী মডেল ব্যবহারের সুযোগ দেয়। সংযোগের ধাপগুলোর জন্য [বিনামূল্যের স্তর নির্দেশিকা](../getting-started/FREE-TIERS-GUIDE.md)
   দেখুন।
4. **একাধিক প্রদানকারী সংযুক্ত করুন এবং Auto-Combo-কে সিদ্ধান্ত নিতে দিন।** যে Arena ELO ডেটা
   এই পৃষ্ঠাটি পরিচালনা করে, সেটিই Auto-Combo স্কোরিং ইঞ্জিনের **টাস্ক-উপযোগিতা ফ্যাক্টর**-এও
   ব্যবহৃত হয় (`open-sse/services/autoCombo/taskFitness.ts`, নির্ধারণের ক্রম
   `user_override → arena_elo → models_dev_tier → static table`)। তাই শীর্ষ বিনামূল্যের প্রদানকারীগুলো সংযুক্ত করার পর
   `model: "auto"` (যেমন `auto/coding`) দিয়ে রাউটিং করলে প্রতিটি অনুরোধের জন্য
   স্বয়ংক্রিয়ভাবে উচ্চমানের বিনামূল্যের মডেলগুলোকে অগ্রাধিকার দেওয়া হবে। সম্পূর্ণ ১৬-ফ্যাক্টর স্কোরিংয়ের জন্য
   [Auto-Combo](../routing/AUTO-COMBO.md) দেখুন।
