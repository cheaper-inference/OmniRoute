শেয়ার্ড এক্সিকিউটেবল ম্যানিফেস্ট, সীমাবদ্ধ শিশু পরিবেশ এবং ক্রমাগত Gemini সেটআপের জন্য, [CLI লঞ্চ চুক্তি](./CLI-LAUNCH-CONTRACTS.md) দেখুন।

OmniRoute `setup-*` কমান্ডের একটি পরিবার পাঠায় যা একটি কোডিং CLI (Codex, Claude কোড, OpenCode, Cline, …) কনফিগার করে OmniRoute ব্যাকএন্ড — হিসাবে ব্যবহার করতে যাতে টুলটি কথা বলে** এক** অটো-ফলব্যাক সহ সঠিক প্রদানকারীর কাছে এন্ডপয়েন্ট এবং OmniRoute রুট। সেটআপ কমান্ড আপনার সক্রিয় স্থানীয় বা দূরবর্তী OmniRoute প্রসঙ্গ ব্যবহার করে এবং টুলটি কনফিগার করে** আপনার** মেশিন ক্যাটালগ ভিত্তিক রেসিপি সার্ভার থেকে মডেল আনয়ন; একক-মডেল রেসিপি `--model` গ্রহণ করে বা একটি মডেল ID এর জন্য প্রম্পট। API কী একটি এনভায়রনমেন্ট ভেরিয়েবল দ্বারা উল্লেখ করা হয় যেখানেই টুলটি সমর্থন করে। একটি টুল-লোকাল এনভায়রনমেন্ট ফাইল টিকে থাকা কমান্ডগুলি নীচে উল্লেখ করা হয়েছে।

ক্যাটালগ এবং অটোমেশন কমান্ডগুলি বিভিন্ন সরঞ্জামের সেট কভার করে:

| সারফেস                         | গণনা | এর মানে কি                                                                        |
| ------------------------------ | ---- | --------------------------------------------------------------------------------- |
| টুল ক্যাটালগ                   | 39   | নথিভুক্ত কোডিং টুল এবং এজেন্ট, ম্যানুয়াল এবং IDE ইন্টিগ্রেশন সহ                  |
| `omniroute run <target>`       | 8    | অ্যাডাপ্টারগুলি লঞ্চ করুন যা লক্ষ্যের শেষ পয়েন্ট, প্রমাণপত্র এবং মডেল সরবরাহ করে |
| `omniroute configure <target>` | 12   | ইন্টারেক্টিভ কনফিগারেশন রেসিপি `setup-*` কমান্ড দ্বারা সমর্থিত                    |
| `setup-*` আদেশ                 | 16   | guided/manual সম্পাদক সেটআপ সহ নিবন্ধিত সেটআপ কমান্ড                              |

গণনা 2026-11-17-এ [টুল ম্যানিফেস্ট](../../config/cli-tools-manifest.json) এবং [কমান্ড রেজিস্ট্রি](../../bin/cli/commands/registry.mjs) প্রতিফলিত করে। একটি ক্যাটালগ এন্ট্রি একটি লঞ্চ অ্যাডাপ্টার বোঝায় না। সম্পূর্ণ ইনভেন্টরির জন্য [CLI টুল ক্যাটালগ](../reference/CLI-TOOLS.md) দেখুন।

এছাড়াও একটি জেনেরিক লঞ্চার — `omniroute run <target>` — আছে যেটি `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen`, `gemini` বা `whycodes` সঠিক env ইনজেকশনের মাধ্যমে তৈরি করে, কোনো কনফিগারেশন না লিখেই। লক্ষ্য এবং তাদের উপনামগুলি ক্যানোনিকাল ম্যানিফেস্ট `bin/cli/cli-manifest.mjs` (`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`, `open-code`, `qwen-code`, `gemini-cli`, `why-codes|why`) থেকে এসেছে এবং `omniroute completion` একই উদ্ভূত লক্ষ্য শব্দগুলি অফার করে৷ `omniroute launch <tool>` একটি সমর্থিত কোডিং টুল শুরু করে প্রতি-লঞ্চ সেশন টোকেন এবং আপনার দ্বারা সংযুক্ত সরবরাহকারীদের থেকে তৈরি একটি মডেল তালিকা সহ, এবং যখন কোনটি না চলে তখন একটি স্থানীয় গেটওয়ে স্বয়ংক্রিয়ভাবে শুরু হয় ( [LAUNCH.md](./LAUNCH.md) দেখুন)। একটি টুলের নাম (Claude কোড) এবং `omniroute launch-codex` (Codex) — ছাড়াই — `omniroute launch` লঞ্চার পার-টুল লঞ্চারগুলি উপলব্ধ থাকে৷

একই local/remote প্রসঙ্গ থেকে সরবরাহকারী অনবোর্ডিং উপলব্ধ। নীচের API-প্রথম কমান্ডগুলি সরবরাহকারীর শংসাপত্রগুলি থেকে ব্যবস্থাপনা প্রমাণীকরণকে আলাদা রাখে এবং কাঠামোগত আউটপুটে কখনই একটি শংসাপত্র মুদ্রণ করে না:

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

স্ক্রিপ্টের জন্য, `--credential-stdin` বা `--credential-env` পছন্দ করুন; `--credential` নিয়ন্ত্রিত স্থানীয় ব্যবহারের জন্য রাখা হয়। `providers remove` জন্য একটি নন-ইন্টারেক্টিভ টার্মিনালে `--yes` প্রয়োজন এবং পাঁচটি কমান্ডই সক্রিয় প্রসঙ্গ বা গ্লোবাল `--base-url`/`--api-key` বিকল্পগুলিকে সম্মান করে।

প্রদানকারী নির্বাচকরা অস্পষ্ট ID উপসর্গ, নাম বা প্রদানকারীর নাম প্রত্যাখ্যান করে; যখন বেশ কয়েকটি সংযোগ মেলে তখন একটি সম্পূর্ণ সংযোগ ID ব্যবহার করুন। কমান্ড তৈরি করুন এবং সম্পাদনা করুন সংরক্ষিত সংযোগটি আবার পড়ুন এবং অপসারণ যাচাই করে যে এটি আর পাঠযোগ্য নয়। একটি আমদানি একটি বিদ্যমান provider/name জোড়া এড়িয়ে যায়। আমদানি করা এন্ট্রি CLI এ সরবরাহ করা ব্যবস্থাপনার শেষবিন্দু, প্রসঙ্গ বা ব্যবস্থাপনার শংসাপত্রগুলিকে ওভাররাইড করতে পারে না।

দুইটি ধনী ইন্টিগ্রেশনের এককালীন, হাতে লেখা বেস সেটআপের জন্য, প্রতি-টুল গভীর ডাইভগুলি দেখুন:

- [Claude কোড কনফিগারেশন](./CLAUDE-CODE-CONFIGURATION.md)
- [Codex CLI কনফিগারেশন](./CODEX-CLI-CONFIGURATION.md)
- [রিমোট মোড](./REMOTE-MODE.md) — আপনার ল্যাপটপ থেকে রিমোট OmniRoute (VPS / টেইলনেট) চালান
- [VS কোড Copilot চ্যাট](./VSCODE-COPILOT.md) — OmniCopilot এক্সটেনশন; এটি সম্পাদকের ভিতর থেকে আপনার জন্য এই `setup-*` কমান্ডগুলি চালাতে পারে

## মাস্টার টেবিল

প্রতিটি আদেশকে সম্মান করে** সক্রিয় প্রসঙ্গ** ( `omniroute connect` দিয়ে সেট করুন, [রিমোট মোড](./REMOTE-MODE.md) দেখুন) বা স্পষ্ট `--remote <url> --api-key <key>` পতাকা। নীচে "স্থানীয় বনাম দূরবর্তী" এর অর্থ: কোন পতাকা ছাড়াই এটি `http://localhost:20128` লক্ষ্য করে; `--remote` (অথবা একটি সক্রিয় দূরবর্তী প্রসঙ্গ) দিয়ে এটি সেই সার্ভারটিকে ব্যাকএন্ড হিসাবে কনফিগার করে এবং স্থানীয়ভাবে কনফিগার লেখে। ক্যাটালগ-ভিত্তিক রেসিপিগুলিও সেই সার্ভার থেকে মডেল আনে।

পতাকাগুলিতে নোট (কমান্ড উত্সে যাচাই করা হয়েছে):

- `--remote <url>` — একটি দূরবর্তী OmniRoute ব্যবহার করে ( `--port` এবং সক্রিয় প্রসঙ্গ ওভাররাইড করে)। `--api-key <key>` সেই সার্ভারের জন্য শংসাপত্র সরবরাহ করে ( `OMNIROUTE_API_KEY` env var-এ ডিফল্ট, বা সক্রিয় প্রসঙ্গ টোকেন)।
- `--only <patterns>` — কমা দ্বারা পৃথক করা সাবস্ট্রিং; শুধুমাত্র মডেল IDs রাখুন যা মেলে (যেমন `--only glm,kimi`)। `setup-codex`, `setup-claude`, `setup-opencode`, `setup-continue`, `setup-cursor`, `setup-crush`, `setup-zed` এ উপলব্ধ।
- `--dry-run` — মুদ্রণ ফাইল সিস্টেম স্পর্শ না করে ঠিক কি লেখা হবে। প্রতিটি `setup-*` কমান্ডে উপলব্ধ** ছাড়া** `setup-cursor` (যা কখনই একটি ফাইল লেখে না)।
- `--model <id>` — প্রয়োজন (বা ইন্টারেক্টিভভাবে বাছাই করা) এমন সরঞ্জামগুলির জন্য যার কোনো মডেল অটো-ডিসকভারি নেই: Cline, Kilo, Roo, Goose, Qwen, Gemini, Aider, 5dive, WhyCodes। এই সরঞ্জামগুলি অ-ইন্টারেক্টিভ রানের জন্য `--yes` গ্রহণ করে (যার পরে `--model` প্রয়োজন)। ডিফল্ট টপ-লেভেল মডেল সেট করতে `setup-opencode` `--model` নেয়।
- `omniroute run` এ `--model <id>` ম্যানিফেস্টের প্রতি-টার্গেট ওয়্যারিং অনুসরণ করে (`bin/cli/cli-manifest.mjs`):** সাহায্যকারী** `--model openai/<id>` পায় এবং** ওপেনকোড** `--model omniroute/<id>` (উপসর্গটি তখনই যোগ করা হয় যখন আইডিটি ইতিমধ্যে এটি বহন করে না);** qwen** এবং** মিথুন** আইডিটি মৌখিকভাবে গ্রহণ করুন;** ক্লদ** এটি `ANTHROPIC_MODEL` এর মাধ্যমে পায়,** হংস** `GOOSE_MODEL` এর মাধ্যমে,** কেন কোড** `-P omniroute -m <id>` এর মাধ্যমে, এবং** কোডেক্স** `-c model_providers.omniroute.*` args এর মাধ্যমে।**Qwen হল একমাত্র রান টার্গেট যা `--model` হার্ড-প্রয়োজন** এটি ছাড়া — `omniroute run qwen` একটি স্পষ্ট ত্রুটি সহ `2` থেকে প্রস্থান করে।
- `--port <port>` — স্থানীয় OmniRoute পোর্ট (ডিফল্ট `20128`, যখন `--remote` সেট করা হয় তখন উপেক্ষা করা হয়)। সমস্ত `setup-*` এবং উভয় লঞ্চারে উপস্থিত।
- `omniroute run` প্রস্থান কোড: শিশু CLI এর নিজস্ব প্রস্থান কোড শব্দগুচ্ছ প্রচারিত হয়; `2` = অবৈধ আর্গুমেন্ট (অসমর্থিত লক্ষ্য, অনুপস্থিত প্রয়োজনীয় `--model`, কন্টেইনার গার্ড); `127` = লক্ষ্য বাইনারি `PATH` এ নেই; `130`/`143`/`129` যখন লঞ্চটি `SIGINT`/`SIGTERM`/`SIGHUP` দ্বারা শেষ হয়; `1` = অন্যান্য রানটাইম লঞ্চ ব্যর্থতা.
- দুটি লঞ্চার (`launch`, `launch-codex`) `setup-claude` / `setup-codex` দ্বারা লিখিত একটি প্রোফাইল নির্বাচন করতে `--profile <name>` গ্রহণ করে, পাশাপাশি অন্তর্নিহিত `claude` / `codex` বাইনারির জন্য পাস-থ্রু আর্গস।

ইন্টারেক্টিভ পিকার সেটআপ রেসিপি দ্বারা শেয়ার করা হয়:

```bash
# Pick from the active local or remote model catalog and configure the target.
omniroute configure claude
omniroute configure opencode --provider glm
omniroute configure qwen --model qwen/qwen3.8-max-preview --yes
omniroute configure gemini
omniroute configure whycodes
```

`configure` বর্তমানে `codex`, `claude`, `opencode`, `qwen`, `gemini`, `aider`, `goose`, `cline`, `continue`, `kilo`, `5dive`, এবং `whycodes` এর জন্য পরীক্ষিত রেসিপিগুলিতে প্রতিনিধিত্ব করে৷ শুধুমাত্র IDE, MITM, এবং গাইড-শুধুমাত্র ক্যাটালগ এন্ট্রিগুলি স্পষ্ট `setup-*`/ম্যানুয়াল প্রবাহে থাকে এবং লঞ্চযোগ্য লক্ষ্য হিসাবে উপস্থাপিত হয় না।

> `setup-opencode` হল** লাইটওয়েট openai-সামঞ্জস্যপূর্ণ** OpenCode ইন্টিগ্রেশন। এছাড়াও একটি সমৃদ্ধ প্লাগইন ইন্টিগ্রেশন — `omniroute setup opencode` — রয়েছে যা `@omniroute/opencode-plugin` ইনস্টল করে। তারা বিভিন্ন আদেশ; উপরের টেবিলটি নথি `setup-opencode`.
>
> প্লাগইন দুটি প্যাকেজে আসে, একটি প্রতি OpenCode প্রধান, কারণ দুটি লোডার বিভিন্ন এন্ট্রিপয়েন্ট আশা করে: OpenCode v1 এর জন্য `@omniroute/opencode-plugin` এবং OpenCode v2 এর জন্য `@omniroute/opencode-plugin-v2` । v2 প্যাকেজটি নতুন (`0.1.0`) এবং একটি হোস্ট চুক্তি অনুসরণ করে যা এখনও চলমান, তাই এটি অনুমান না করে ক্যাটালগ খসড়াতে OpenCode বীজের আকৃতি পড়ে। `opencode.json` তে একটি `plugins` এন্ট্রি যোগ করে এটি ইনস্টল করুন; `omniroute setup opencode` এখনও v1 প্যাকেজ ইনস্টল করে। বিকল্প এবং শংসাপত্রের সন্ধানের অর্ডার প্যাকেজ README এ রয়েছে।

## লোকাল ব্যবহার

OmniRoute যখন `localhost:20128`-এ চলছে, তখন শুধু আপনার টুলের জন্য সেটআপ কমান্ডটি চালান।
ক্যাটালগটি লোকাল সার্ভার থেকে আনা হয়।

```bash
# Codex: মিলে যাওয়া প্রতিটি মডেলের জন্য ~/.codex/-এ একটি প্রোফাইল লিখুন
omniroute setup-codex
codex --profile glm52            # তৈরি করা একটি প্রোফাইল ব্যবহার করুন

# Claude Code: প্রতিটি মডেলের জন্য প্রোফাইল লিখুন, তারপর একটি চালু করুন
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode: ক্যাটালগের সব মডেলসহ openai-সামঞ্জস্যপূর্ণ প্রোভাইডারটি লিখুন
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # {env:OMNIROUTE_API_KEY}-এর মাধ্যমে রেফারেন্স করা হয়, কখনোই ডিস্কে নয়
opencode -m omniroute/glm/glm-5.2 "..."

# স্বয়ংক্রিয় শনাক্তকরণ ছাড়া টুলগুলোর জন্য একটি সুস্পষ্ট মডেল প্রয়োজন:
omniroute setup-aider --model glm/glm-5.2
omniroute setup-qwen --model qwen/qwen3.8-max-preview

# কিছু না লিখেই প্রিভিউ করুন:
omniroute setup-continue --dry-run
```

কোনো কনফিগ না লিখেই চালু করুন (শুধু এনভায়রনমেন্ট ইনজেকশন):

```bash
omniroute launch                 # Claude Code → লোকাল OmniRoute
omniroute launch-codex           # Codex CLI → লোকাল OmniRoute
omniroute launch-codex --profile glm52
omniroute run claude --model openai/gpt-5.4
omniroute run codex --model openai/gpt-5.4 --dry-run --json
omniroute run aider --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# সুস্পষ্ট কমান্ড পাথ: -- এর পরে যা আছে সব অপরিবর্তিতভাবে পাঠিয়ে দিন
omniroute run claude -- --print-system-prompt "review this diff"
```

## রিমোট ব্যবহার

`--remote` + `--api-key` দিয়ে যেকোনো সেটআপ কমান্ডকে একটি রিমোট OmniRoute-এর দিকে নির্দেশ করুন।
ক্যাটালগটি রিমোট থেকে আনা হয়; কনফিগটি আপনার লোকাল মেশিনে লেখা হয়।

```bash
# একটি রিমোট VPS-এর বিপরীতে OpenCode, শুধু glm/kimi মডেলগুলো রাখুন
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx \
  --only glm,kimi
opencode -m omniroute/glm/glm-5.2 "..."   # প্রথমে OMNIROUTE_API_KEY এক্সপোর্ট করুন

# একটি রিমোট ক্যাটালগ থেকে Codex প্রোফাইল
omniroute setup-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# CLI-টি সরাসরি রিমোটের বিপরীতে চালু করুন
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

প্রতিবার `--remote`/`--api-key` দেওয়ার বদলে, একবার লগ ইন করুন এবং
**সক্রিয় কনটেক্সটকে** সেগুলো স্বয়ংক্রিয়ভাবে সরবরাহ করতে দিন:

```bash
omniroute connect 192.168.0.15        # সীমিত-স্কোপের একটি টোকেন তৈরি করে, কনটেক্সট সংরক্ষণ করে
omniroute setup-codex                 # ← এখন রিমোট ক্যাটালগ ব্যবহার করে
omniroute setup-opencode              # ← একই
omniroute launch                      # ← রিমোটের বিপরীতে Claude Code
```

কনটেক্সট, স্কোপ এবং টোকেন ব্যবস্থাপনার জন্য [রিমোট মোড](./REMOTE-MODE.md) দেখুন।

## 5 ডাইভ এজেন্ট বহর

[5dive](https://5dive.ai) দীর্ঘ-চলমান কোডিং এজেন্টদের একটি বহর চালায়, প্রত্যেকটি তার নিজস্ব ইউনিক্স ব্যবহারকারীর অধীনে একটি সিস্টেমড ইউনিট। এটি নিজেই একটি কোডিং CLI নয়, তাই `omniroute run` জন্য — `5dive` চালু করার জন্য কিছুই নেই** কনফিগার-শুধুমাত্র** লক্ষ্য

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

উভয় ফর্ম এক 5 ডাইভ লিখুন** প্রমাণীকরণ প্রোফাইল** , এবং সেই প্রোফাইলের সাথে আবদ্ধ প্রতিটি `claude` আসন তারপর OmniRoute এর সাথে কথা বলে। তিনটি জিনিস এই লক্ষ্যের জন্য নির্দিষ্ট:

- **এটি রুট হিসাবে ফ্লিট হোস্টে চলে।** 5dive এর ক্রিয়া স্থানীয় সিস্টেমড ইউনিট এবং একটি রুট-মালিকানাধীন রাষ্ট্রীয় ডির এর উপর কাজ করে; কোন রিমোট মোড নেই। রেসিপিটি `sudo` মাধ্যমে পুনরায় কার্যকর হয় যখন এটি ইতিমধ্যে রুট না থাকে (`--no-sudo` এটি বন্ধ করে এবং পরিবর্তে কমান্ডটি প্রিন্ট করে)।
- **শেষ বিন্দু অবশ্যই `https://` হতে হবে যদি না এটি লুপব্যাক হয়।** এজেন্টের API কী রাইড করে যে URL প্রতিটি অনুরোধে, এবং 5dive একটি প্লেইনটেক্সট অফ-বক্স এন্ডপয়েন্ট প্রত্যাখ্যান করে। একটি ব্যক্তিগত LAN ঠিকানা একটি ব্যতিক্রম নয়।
- **প্রতিটি আসনের নিজস্ব মডেল পিন প্রোফাইলকে ছাড়িয়ে যায়।** প্রোফাইলটি `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` বহন করে, কিন্তু একটি স্টক মডেল আইডিতে পিন করা একটি সিট _"নির্বাচিত মডেলের সাথে একটি সমস্যা আছে"_ এর সাথে তার প্রথম পালা ব্যর্থ হয়৷ পাশাপাশি আসন পিন করতে `--agent <name>` (পুনরাবৃত্তিযোগ্য) পাস করুন; রেসিপি কমান্ড প্রিন্ট যখন আপনি না.

API কীটি 5 ডাইভ অনের কাছে হস্তান্তর করা হয়েছে** stdin** (`--api-key=-`), তাই এটি কখনই `ps` আউটপুটে প্রদর্শিত হয় না।

একটি OmniRoute এ প্রোফাইল নির্দেশ করে** কম্বো** একটি একক মডেলের পরিবর্তে যা ফ্লিট প্রদানকারীর ব্যর্থতা পায়: যখন প্রাথমিক এন্ডপয়েন্টটি [#11578](https://github.com/cheaper-inference/OmniRoute/issues/11578) এ রেকর্ড করা রানে হার্ড-ডাউন মিড-টার্নে চলে যায়, তখন এজেন্ট তার অবশিষ্ট ধাপগুলি ফলব্যাকে শেষ করে এবং কখনই বিভ্রাট প্রকাশ করেনি।

## আপডেটের সময় নেটিভ ডিপেন্ডেন্সি রাখা: `--include=optional`

আপনি `omniroute update` দিয়ে আপডেট করলে (নিশ্চিত করার পর অথবা `--apply` দিয়ে), OmniRoute ইনস্টল কমান্ডে আগে থেকেই `--include=optional` যুক্ত করে চালায়:

```bash
npm install -g omniroute@latest --include=optional
```

এটি **এমন কোনো ফ্ল্যাগ নয়** যা আপনাকে `omniroute update`-এ দিতে হবে — আপডেটার সর্বদা এটি প্রয়োগ করে। এটি নিশ্চিত করে যে `optionalDependencies` (`better-sqlite3`, `keytar`, `tls-client`, LLMLingua SLM স্ট্যাক) আপডেটের পরেও অক্ষত থাকে, এমনকি আপনার npm কনফিগে `omit=optional` সেট করা থাকলেও; অন্যথায় সেটি নীরবে নেটিভ SQLite ড্রাইভার এবং OS-keyring বাইন্ডিং বাদ দিত। প্রয়োগ না করে সঠিক কমান্ডটি প্রিভিউ করতে:

```bash
omniroute update --dry-run
# [DRY RUN] চালানো হতো: npm install -g omniroute@latest --include=optional
```

অন্যান্য `omniroute update` ফ্ল্যাগ (সোর্সে যাচাইকৃত): `--check` (পুরোনো হলে 1 দিয়ে এক্সিট), `--apply` (প্রম্পট না করে ইনস্টল), `--changelog`, `--no-backup`, `--yes`।

## `omniroute run gemini`-এর মাধ্যমে Google Gemini CLI

`@google/gemini-cli` 0.50.0-এর বিপরীতে কনট্র্যাক্ট যাচাই করা হয়েছে: CLI `GOOGLE_GEMINI_BASE_URL` মেনে চলে এবং এর বিপরীতে `POST /v1beta/models/<model>:generateContent` (এবং `:streamGenerateContent?alt=sse`) ইস্যু করে — যা ঠিক OmniRoute-এর নেটিভ Gemini সারফেস (`/v1beta`)। `omniroute run gemini` এটি স্বয়ংক্রিয়ভাবে সংযুক্ত করে:

- `GOOGLE_GEMINI_BASE_URL` → সক্রিয় OmniRoute বেস URL (রুট, `/v1` ছাড়া);
- `GEMINI_API_KEY` → নির্ধারিত OmniRoute ক্রেডেনশিয়াল (অপশন/env/context);
- একটি **অস্থায়ী ও বিচ্ছিন্ন `GEMINI_CLI_HOME`**, যার `.gemini/settings.json`-এ `gemini-api-key` অথ নির্বাচন করা থাকে, যাতে সংরক্ষিত Google OAuth সেশন (Code Assist) কখনো OmniRoute-নির্দেশিত লঞ্চকে ওভাররাইড না করে — এক্সিটের পর এটি সরিয়ে ফেলা হয়;
- **env পরিচ্ছন্নতা**: চাইল্ড env থেকে `GOOGLE_API_KEY`, `GOOGLE_GENAI_USE_VERTEXAI` এবং `GOOGLE_GENAI_USE_GCA` সরিয়ে ফেলা হয় (যেগুলো অথকে Vertex/Code Assist-এ রিডাইরেক্ট করত), এবং অতিরিক্ত সুরক্ষা হিসেবে `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key` সেট করা হয় — অন্যান্য `run` টার্গেটও তাদের নিজস্ব সাংঘর্ষিক ভেরিয়েবলের জন্য একই ব্যবস্থা পায়;
- `--provider`/`--model` থেকে `--model <id>` ইনজেকশন।

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

হেডলেস মোডেও Gemini-এর ওয়ার্কস্পেস-ট্রাস্ট গার্ড প্রযোজ্য থাকে — নিজে `--skip-trust` দিন (অথবা ইন্টার্যাক্টিভভাবে ডিরেক্টরিটিকে ট্রাস্ট করুন); লঞ্চারটি ইচ্ছাকৃতভাবে এটিকে বাইপাস করে না। এই লঞ্চারটি **ACP রেজিস্ট্রেশন** (`src/lib/acp/registry.ts`, `gemini --acp`) থেকে আলাদা, যা `/dashboard/acp-agents`-এর জন্য এজেন্ট-প্রোটোকল ইন্টিগ্রেশন হিসেবেই থাকে।

## বাস্তব স্মোক সুইপ (অপ্ট-ইন)

নির্ধারণযোগ্য লঞ্চ-প্ল্যান রিগ্রেশন CI-তে চলে (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`)। একটি বাস্তব OmniRoute সার্ভারের বিপরীতে বাস্তব
বাইনারিগুলো যাচাই করার জন্য, একটি অপ্ট-ইন হারনেস রয়েছে
`tests/integration/upstream-cli-smoke.int.test.ts`-এ। এটি কখনোই স্বয়ংক্রিয়ভাবে চলে না
(`RUN_CLI_SMOKE=1` না হলে প্রতিটি সাব-টেস্ট এড়িয়ে যায়), env-var-এর মাধ্যমে ক্রেডেনশিয়ালের
NAME পাঠায় (কখনোই মান নয়), রেকর্ড করা যেকোনো আউটপুট থেকে কী-সদৃশ স্ট্রিং অপসারণ করে,
যেসব টার্গেটের বাইনারি ইনস্টল করা নেই সেগুলো এড়িয়ে যায় এবং ব্যর্থতাগুলোকে শুধু একটি
বুলিয়ান হিসেবে না দেখিয়ে auth / upstream / config হিসেবে শ্রেণিবদ্ধ করে:

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

ঐচ্ছিক: `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` সুইপটিকে সীমাবদ্ধ করে;
`OMNIROUTE_SMOKE_TIMEOUT_MS` প্রতি-টার্গেটের 120s টাইমআউট ওভাররাইড করে।
