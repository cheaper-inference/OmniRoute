নিরপেক্ষ `config/cli-tools-manifest.json` চুক্তি ক্যানোনিকাল IDs, উপনাম, বাইনারি প্রার্থী, সেটআপ রেসিপি, মডেল আর্গুমেন্ট এবং ক্ষমতা ঘোষণা করে। `bin/cli/cli-manifest.mjs` এ প্লেইন নোড অ্যাডাপ্টার এবং `src/shared/constants/cliIntegrationManifest.ts` তে TypeScript অ্যাডাপ্টার একই ফাইল পড়ে। রানটাইম, ক্যাটালগ, কনফিগার, সমাপ্তি, জেনারেটর এবং ব্যাকএন্ড রেজিস্ট্রেশন `tests/unit/cli/cli-manifest-drift.test.ts` দ্বারা একসাথে চেক করা হয়। তালিকাভুক্ত হওয়ার অর্থ এই নয় যে একটি টুল চালু বা কনফিগার করা যেতে পারে। বিশেষ করে, 5 ডাইভ শুধুমাত্র কনফিগার করা যায়।

## শিশু পরিবেশ এবং জীবনচক্র

`omniroute run`, `omniroute launch` এবং `omniroute launch-codex` একটি OS/terminal সামঞ্জস্যপূর্ণ অনুমোদন তালিকার উত্তরাধিকারী হয় এবং নির্বাচিত লক্ষ্যের শংসাপত্রগুলি ইনজেকশন করে। সম্পর্কহীন প্রদানকারী এবং ডাটাবেস গোপনীয়তা ডিফল্টরূপে উত্তরাধিকারসূত্রে প্রাপ্ত হয় না। `--inherit-env` স্পষ্টভাবে সম্পূর্ণ পিতা-মাতা-পরিবেশের উত্তরাধিকার পুনরুদ্ধার করে; শুধুমাত্র এটি ব্যবহার করুন যখন নির্বাচিত তৃতীয় পক্ষের প্রক্রিয়াটি সেই মানগুলি গ্রহণ করবে। এটি এনভায়রনমেন্ট ফিল্টারিং, একটি OS স্যান্ডবক্স নয়: প্রক্রিয়াটি এখনও কলারের ফাইলসিস্টেম অনুমতির সাথে চলে।

বাধা এবং সমাপ্তির সংকেত শিশুর কাছে পাঠানো হয়। লঞ্চার অস্থায়ী কনফিগারেশন মুছে ফেলার আগে সন্তানের ঘনিষ্ঠ ইভেন্টের জন্য অপেক্ষা করে। `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` জোরপূর্বক সমাপ্তির আগে গ্রেস পিরিয়ড নিয়ন্ত্রণ করে (ডিফল্ট 5000 মিলিসেকেন্ড)।

## Gemini ক্রমাগত সেটআপ

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

প্রথম দুটি কমান্ড নির্বাচিত স্থানীয় বা দূরবর্তী সার্ভারের জন্য এই মেশিনটি কনফিগার করে। সেটআপ সম্পর্কহীন JSON সেটিংস সংরক্ষণ করে, Gemini API-কী প্রমাণীকরণ নির্বাচন করে এবং একটি ব্যক্তিগত `.gemini/.env` ফাইলে এন্ডপয়েন্ট এবং শংসাপত্র লেখে। এটি ওভাররাইট করার পরিবর্তে অবৈধ JSON প্রত্যাখ্যান করে। এন্ডপয়েন্ট URLs অবশ্যই HTTP(S) হতে হবে, এমবেডেড শংসাপত্র, ক্যোয়ারী প্যারামিটার বা টুকরা ছাড়াই। ড্রাই-রান প্রিন্ট পাথ, শংসাপত্রের মান নয়।

`GEMINI_CLI_HOME` বা `--gemini-home` স্থায়ী হোম রুট নির্বাচন করে। একটি প্রকৃত `run gemini` তৈরি করে এবং পরে তার নিজস্ব অস্থায়ী বাড়িটি সরিয়ে দেয়। কোনো মোডই Gemini এর ওয়ার্কস্পেস-ট্রাস্ট চেক বাইপাস করে না।

## Codex প্রোফাইল

`configure codex` একটি মডেল এবং এর OmniRoute প্রদানকারীর শেষ পয়েন্ট সহ একটি ব্যক্তিগত `<name>.config.toml` লেখে। শংসাপত্রগুলি `OMNIROUTE_API_KEY` এর মাধ্যমে উল্লেখ করা হয়, কখনও এম্বেড করা হয় না। লঞ্চ কমান্ড নির্বাচিত মডেলটিকে শীর্ষ-স্তরের `model` কী-তে সেট করে, `model_providers` ভিতরে নয়।

পৃথক প্রোফাইল ফাইল বর্তমান নথিভুক্ত Codex চুক্তি; `codex --profile <name>` দিয়ে নির্বাচিত হলে তারা ব্যবহারকারীর কনফিগারেশন ওভারলে করে। [অফিসিয়াল প্রোফাইল রেফারেন্স](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) এবং [OmniRoute Codex গাইড](./CODEX-CLI-CONFIGURATION.md) দেখুন।

## হারমেটিক কমান্ড এক্সিকিউশন

একটি স্পষ্ট `DATA_DIR` এর সাথে, `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` সেট করা স্টার্টআপকে ডিফল্ট ব্যবহারকারী ডেটা ডিরেক্টরির শংসাপত্রের পরিবেশে পড়তে বাধা দেয়। এটি বিচ্ছিন্ন পরীক্ষার জন্য দরকারী। এটি অন্যান্য স্পষ্টভাবে নির্বাচিত পরিবেশ ফাইল নিষ্ক্রিয় করে না।

## ওয়ার্কিং-ডিরেক্টরি `.env`

CLI এই ক্রমে `.env` ফাইলগুলি পড়ে, এবং একটি কী সেট করার জন্য প্রথম ফাইলটি জয়লাভ করে: স্পষ্ট `DATA_DIR`, ডিফল্ট ডেটা ডিরেক্টরি, বর্তমান কার্যকারী ডিরেক্টরি, তারপর প্যাকেজ ডিরেক্টরি৷ শেল ভেরিয়েবল সবসময় জয়ী হয়।

ওয়ার্কিং ডিরেক্টরি অন্য কারো (একটি ক্লোন করা সংগ্রহস্থল, একটি আনপ্যাক করা সংরক্ষণাগার) এর অন্তর্গত হতে পারে এবং `omniroute serve` সার্ভারে এবং সার্ভার চালানো প্রতিটি টুলে CLI পরিবেশ পাস করে। সুতরাং একটি `.env` সেখানে শুধুমাত্র এই কীগুলি সেট করতে পারে, `bin/cli/utils/untrustedCwdEnv.mjs` এ তালিকাভুক্ত:

| চাবি                            | গৃহীত মান                                                            |
| ------------------------------- | -------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` বা `yes` যেকোন ক্ষেত্রেই, সার্ভার যে মানগুলি বিবেচনা করে |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 64টি অক্ষর, সংখ্যা, `_`, `.`, `@` বা `-` পর্যন্ত                     |
| `LANGUAGE`                      | একই, প্লাস `:`                                                       |
| `TZ`                            | 64টি অক্ষর, সংখ্যা, `_`, `+`, `-` বা `/` পর্যন্ত, `/` দিয়ে শুরু নয় |
| `NO_COLOR`, `FORCE_COLOR`       | 16টি অক্ষর এবং সংখ্যা পর্যন্ত                                        |

প্রতিটি মান `REQUIRE_API_KEY` গ্রহণ করে চেক চালু করে, তাই ফাইলটি নিজেই চেক বন্ধ করতে পারে না। যদিও এটি ফলাফল নির্ধারণ করে না: সার্ভার পরিবেশের আগে ডাটাবেসে সংরক্ষিত একটি `REQUIRE_API_KEY` ওভাররাইড পড়ে, যখন একটি API কী ছাড়া সমস্ত ইন্টারফেসে শোনার বিষয়ে স্টার্টআপ সতর্কতা শুধুমাত্র পরিবেশকে পড়ে। `false` এর সংরক্ষিত ওভাররাইডের সাথে, একটি ওয়ার্কিং-ডিরেক্টরি `REQUIRE_API_KEY=true` API খোলা রেখে সেই সতর্কতা লুকিয়ে রাখে। `TZ` নিয়মটি POSIX চেয়ে সংকীর্ণ: এটি `.`, `:`, `,` এবং `<>` প্রত্যাখ্যান করে, তাই `:Area/City` ফর্ম এবং `EST5EDT,M3.2.0,M11.1.0` মতো নিয়মগুলি শেল বা `<DATA_DIR>/.env` তে সেট করতে হবে।

বড় ক্ষেত্রে নামগুলো হুবহু মিলতে হবে। অন্য কোনো লাইন, একটি মান যা চেক করতে ব্যর্থ হয় এবং একটি নাম যা প্লেইন ASCII অক্ষর, সংখ্যা এবং `_` নয় (উদাহরণস্বরূপ একটি NUL বাইট বা একটি চেহারার মতো অক্ষর সহ) বাদ দেওয়া হয়। CLI একটি সতর্কবাণী প্রিন্ট করে যা এটি সেট করতে পারে না এমন কীগুলির নাম দেয় এবং একটি যা এটি উপেক্ষা করা অনুমোদিত কীগুলির নাম দেয়, প্রতিটি কী পরিবর্তন করতে হবে (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`)। কোনটিই মান প্রিন্ট করে না। এই বার্তাগুলির ফাইল পাথগুলি এবং `.env` পাথ `omniroute doctor` রিপোর্টগুলি এস্কেপ করা হয় যখন এগুলিতে নিয়ন্ত্রণ বা বিড়ি অক্ষর থাকে৷ যখন কর্মরত ডিরেক্টরি ডেটা ডিরেক্টরি বা প্যাকেজ ডিরেক্টরি হয় তখন সীমাবদ্ধতা প্রযোজ্য হয় না।

`PORT`, `API_PORT` এবং `DASHBOARD_PORT` তালিকায় নেই। একটি উচ্চ-প্রধান উৎস থেকে বেস URL ছাড়া, CLI `localhost:<PORT>` এর সাথে কথা বলে এবং সেখানে যা কিছু শোনে সে CLI এর API কী, প্রসঙ্গ টোকেন এবং CLI মেশিন টোকেন (`x-omniroute-cli-token`, [CLI_TOKEN.md](../security/CLI_TOKEN.md) দেখুন), যা স্থানীয় সার্ভার loop থেকে ম্যানেজমেন্ট কলের জন্য গ্রহণ করে। ওয়ার্কিং ডাইরেক্টরি থেকে একটি পোর্ট সেই ফাইলটিকে শ্রোতাকে বেছে নিতে দেয়, তাই শেলের মধ্যে `<DATA_DIR>/.env` বা `--port` বিকল্পের সাথে একটি (`serve`, `launch`, `run`) পোর্টগুলি সেট করুন।

পার্সারের কোন `export` সিনট্যাক্স নেই। একটি লাইন যেমন `export LD_PRELOAD=...` একটি পরিবর্তনশীল `export LD_PRELOAD` নাম দেয়; ওয়ার্কিং ডিরেক্টরি থেকে এটি বাদ দেওয়া হয়, এবং অন্যান্য `.env` ফাইলগুলিতে এটি সেই আক্ষরিক নাম সেট করে, যা কিছুই পড়ে না।

CLI একটি কনটেক্সট এর সঞ্চিত টোকেন (অ্যাক্সেস টোকেন বা লিগ্যাসি API কী) শুধুমাত্র সেই প্রসঙ্গটির নিজস্ব মূলের সাথে যুক্ত করে: স্কিম, হোস্ট এবং পোর্ট, `URL.origin` এর তুলনায়। এটি CLI এর HTTP ক্লায়েন্ট (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) এবং `launch`, `launch codex`, `configure` এবং `setup-*` কমান্ডের মাধ্যমে করা অনুরোধের ক্ষেত্রে প্রযোজ্য যা অন্য টুলের কনফিগারেশনে একটি বেস URL এবং কী লিখে। `--remote` সহ অন্য সার্ভারের দিকে নির্দেশ করা হয়েছে, তারা একটি সুস্পষ্ট `--api-key` বা `OMNIROUTE_API_KEY` ব্যবহার করে যদি একটি সেট করা থাকে এবং কোন প্রসঙ্গ টোকেন নেই। তুলনাটি সঠিক, তাই `localhost` এবং `127.0.0.1`, অথবা ট্রেলিং ডট সহ এবং ছাড়া একটি হোস্ট, বিভিন্ন সার্ভার হিসাবে গণনা করুন এবং কোন প্রসঙ্গ টোকেন পাবেন না। ব্যবহারকারীর তথ্য সহ একটি URL, একটি ব্যাকস্ল্যাশ বা হোয়াইটস্পেস কখনই মেলে না, কারণ অন্যান্য URL পার্সার (উদাহরণস্বরূপ, পাইথনের `urllib` এবং `httpx`) এটি থেকে একটি ভিন্ন হোস্ট পড়তে পারে। অনুরোধের জন্য CLI নিজেই পাঠায়, সেই চেকটি শুধুমাত্র স্কিম এবং কর্তৃপক্ষকে কভার করে, তাই পাথ বা ক্যোয়ারীতে একটি স্পেস সহ একটি আইডি টোকেন রাখে।
