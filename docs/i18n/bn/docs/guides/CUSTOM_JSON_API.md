একটি কাস্টম JSON API নোড একটি JSON বিজনেস এন্ডপয়েন্টকে সংযুক্ত করে যা OpenAI বা Anthropic প্রোটোকলের সাথে কথা বলে না। OmniRoute একটি JSON অনুরোধ টেমপ্লেট পূরণ করে, এটিকে সম্পূর্ণ এন্ডপয়েন্ট URL এ পাঠায়, একটি প্রতিক্রিয়া পথ থেকে উত্তরটি পড়ে এবং ক্লায়েন্টের নিজস্ব বিন্যাসে ক্লায়েন্টকে ফেরত দেয় (চ্যাট সমাপ্তি, প্রতিক্রিয়া, বার্তা, ...)।

এটি `apiType: "custom-json"` সাথে একটি OpenAI- সামঞ্জস্যপূর্ণ নোড; এর আইডিতে `openai-compatible-custom-json-<suffix>` ফর্ম আছে। ড্যাশবোর্ড ফর্ম এখনও উপলব্ধ নয়. নীচের প্রদানকারী-নোড API এর মাধ্যমে এই নোডগুলি তৈরি করুন এবং সম্পাদনা করুন৷

## একটি নোড তৈরি করুন

`POST /api/provider-nodes` (ব্যবস্থাপনা প্রমাণীকরণ):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` হল** সম্পূর্ণ** শেষ বিন্দু URL। কিছুই সংযুক্ত করা হয় না (কোন `/chat/completions`, no `/models`) এবং অন্যান্য OpenAI- সামঞ্জস্যপূর্ণ নোডের বিপরীতে, কোন ডিফল্ট URL নেই। এটি অবশ্যই `http(s)` হতে হবে, এমবেডেড শংসাপত্র বা একটি `#fragment` ছাড়াই, এবং এটি প্রতিটি প্রদানকারী নোডের মতো একই আউটবাউন্ড URL গার্ড পাস করে, যখন নোডটি সংরক্ষণ করা হয় এবং প্রতিটি অনুরোধে উভয় ক্ষেত্রেই।
- একটি নোড যা সংযোগ কী পাঠায় (`authType` `bearer` বা `api-key`, ডিফল্ট সহ) অবশ্যই `https://` ব্যবহার করতে হবে। প্লেইন `http://` শুধুমাত্র একটি লুপব্যাক হোস্ট (`localhost`, `127.0.0.0/8`, `::1`) বা `authType: "none"` সহ গৃহীত হয়, যা কোন কী পাঠায় না। ব্যক্তিগত LAN ঠিকানাগুলি (`10.x`, `172.16-31.x`, `192.168.x`) ছাড় দেওয়া হয় না: সেই নেটওয়ার্কের যে কেউ কী পড়তে পারে৷ এই ধরনের একটি নোড সংরক্ষণ করা `400` এর সাথে ব্যর্থ হয়, এবং পূর্বে সংরক্ষিত একটি নোড একই বার্তা সহ প্রতিটি অনুরোধে বন্ধ হয়ে যায়, কোনো অনুরোধ পাঠানোর আগে। একটি LAN এ একটি কীড এন্ডপয়েন্টের জন্য, এটিকে TLS পিছনে রাখুন (উদাহরণস্বরূপ একটি বিপরীত প্রক্সি)।
- `customJson` Zod দিয়ে যাচাই করা হয়; অজানা কী প্রত্যাখ্যান করা হয়। প্রতিটি ক্ষেত্র ঐচ্ছিক:

| মাঠ               | মূল্যবোধ                                | ডিফল্ট                                                 |
| ----------------- | --------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                  | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`             | `bearer`                                               |
| `authHeader`      | হেডার নাম ব্যবহার করা হয় যখন `api-key` | `X-API-Key`                                            |
| `requestTemplate` | JSON অবজেক্ট (≤ 64 KB, গভীরতা ≤ 32)     | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | ফিল্ড পাথ, বা পুরো শরীরের জন্য `$`      | `choices[0].message.content`                           |

- গোপন সংযোগের API কীতে থাকে, কখনই টেমপ্লেটে নয়। `bearer` `Authorization: Bearer <key>` পাঠায়; `api-key` `<authHeader>: <key>` পাঠায়। প্রমাণীকরণ শিরোনামটি `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` বা একটি হপ-বাই-হপ হেডার হতে পারে না। `none` এর সাথে, সংযোগের কোন চাবির প্রয়োজন নেই।
- অতিরিক্ত স্ট্যাটিক হেডার নোডের নিয়মিত `customHeaders` ব্যবহার করে (প্রতিটি সামঞ্জস্যপূর্ণ নোডের মতো একই বৈধতা; সেখানে প্রমাণীকরণ শিরোনাম অনুমোদিত নয়)।

`PUT /api/provider-nodes/<id>` একই `customJson` গ্রহণ করে এবং নোডের প্রতিটি বিদ্যমান সংযোগে `baseUrl` এবং কনফিগার পুনর্লিখন করে। `customJson` বাদ দেওয়া সঞ্চিত কনফিগার রাখে; `apiType` কে `chat` বা `responses` স্যুইচ করা নোড এবং এর সংযোগ থেকে এটিকে সরিয়ে দেয়।

তারপর যথারীতি নোডে একটি সংযোগ যোগ করুন (নোড আইডি সহ `POST /api/providers` ) এবং `<prefix>/<model>` অনুরোধ করুন, উদাহরণস্বরূপ `biz/assistant-v1`। এন্ডপয়েন্ট কোন মডেল তালিকা প্রকাশ করে না, তাই হাত দিয়ে মডেল আইডি যোগ করুন।

## অনুরোধ টেমপ্লেট

টেমপ্লেটগুলি সরল JSON হয়। একটি স্ট্রিং মান `{{placeholder}}` মার্কার থাকতে পারে; কিছুই মূল্যায়ন বা মৃত্যুদন্ড কার্যকর করা হয় না, এবং অবজেক্ট কী কখনও প্রতিস্থাপিত হয় না।

| স্থানধারক            | মান                                                                   |
| -------------------- | --------------------------------------------------------------------- |
| `{{prompt}}`         | সর্বশেষ ব্যবহারকারীর বার্তার পাঠ্য (পাঠ্য অংশ নতুন লাইনের সাথে যুক্ত) |
| `{{messages}}`       | OpenAI চ্যাট বিন্যাসে কথোপকথন                                         |
| `{{model}}`          | অনুরোধকৃত মডেল আইডি, প্রদানকারী উপসর্গ ছাড়াই                         |
| `{{stream}}`         | সর্বদা `false` — একটি JSON নথি দিয়ে শেষ পয়েন্টের উত্তর দিন          |
| `{{request.<path>}}` | অনূদিত (OpenAI চ্যাট বিন্যাস) অনুরোধের একটি ক্ষেত্র                   |

- একটি মান যা ঠিক একটি স্থানধারক তার JSON টাইপ রাখে (`"{{messages}}"` একটি অ্যারে হয়ে যায়); একটি দীর্ঘ স্ট্রিং ভিতরে একটি স্থানধারক পাঠ্য হিসাবে সন্নিবেশ করা হয়.
- একটি স্থানধারক যা কিছুতেই সমাধান না করে একটি অসম্পূর্ণ পেলোড পাঠানোর পরিবর্তে HTTP 400 এর সাথে অনুরোধটি ব্যর্থ করে।
- পাথগুলি ডট নোটেশন এবং সাংখ্যিক সূচক (`data.items[0].text`) ব্যবহার করে। `__proto__`, `prototype` এবং `constructor` কী এবং পাথগুলিতে প্রত্যাখ্যান করা হয়েছে।

## প্রতিক্রিয়া

`responsePath` এর মান সহকারী উত্তরে পরিণত হয়: স্ট্রিংগুলি অতিক্রম করে, অন্যান্য JSON মানগুলি ক্রমিক করা হয়। একটি অনুপস্থিত বা `null` ক্ষেত্র, অথবা একটি বডি যা JSON নয়, HTTP 502 প্রদান করে। আপস্ট্রিম ত্রুটির অবস্থাগুলি পাস করা হয়। স্ট্রিমিং ক্লায়েন্টদের জন্য OmniRoute পুরো JSON প্রতিক্রিয়ার জন্য অপেক্ষা করে এবং তারপর এটিকে একটি বিষয়বস্তু খণ্ড এবং ফিনিশ খণ্ড হিসাবে নির্গত করে; এটি টোকেন স্ট্রিমিং নয়। টুল কল এবং ব্যবহার ক্ষেত্র ম্যাপ করা হয় না.

## কখনো রিপ্লে করা হয়নি

একটি ব্যবসায়িক অনুরোধ ব্যর্থ হলেও পার্শ্ব প্রতিক্রিয়া হতে পারে। OmniRoute তাই একবার এটি পাঠায়:

- কোন পরিবহন পুনঃপ্রচেষ্টা এবং কোন পুনঃনির্দেশ অনুসরণ;
- অন্য সংযোগে পুনরায় চেষ্টা করবেন না (অ্যাকাউন্ট ফলব্যাক) — ব্যর্থতা যেমন আছে-সেভাবে ফেরত দেওয়া হয় এবং সংযোগটি ঠান্ডা হয় না;
- পরবর্তী কম্বো লক্ষ্যে কোনো ফলব্যাক নয়, এমনকি একটি খালি বা ব্যর্থ উত্তরের জন্যও।

পৃথক ক্লায়েন্ট অনুরোধ, এবং ফিউশন প্যানেল যা স্পষ্টভাবে বেশ কয়েকটি মডেলকে কল করে, এখনও স্বাধীনভাবে শেষবিন্দুকে আহ্বান করে।

## একটি নোড পরীক্ষা করা হচ্ছে

একটি সংযোগ সংরক্ষণ করা হচ্ছে, সংযোগ** পরীক্ষা** বোতাম এবং ব্যাকগ্রাউন্ড হেলথ চেক কখনই এন্ডপয়েন্টে কল করে না: তারা শুধুমাত্র সঞ্চিত কনফিগারেশন যাচাই করে এবং কানেকশনটিকে যাচাইযোগ্য নয় বলে রিপোর্ট করে।

`"apiType": "custom-json"` সহ `POST /api/provider-nodes/validate` এবং নোড ক্ষেত্রগুলি (`baseUrl`, `apiKey`, `customJson`, ঐচ্ছিক `customHeaders` এবং `modelId`) ঠিক একটি বাস্তব অনুরোধ পাঠায়, সর্বশেষ ব্যবহারকারীর পাঠ্য হিসাবে `ping` সহ। এটি `{ "valid": true }` বা আপস্ট্রিম স্ট্যাটাসের উত্তর দেয় (কখনও আপস্ট্রিম বডি নয়)।

## স্টোরেজ

কনফিগারেশনটি `provider_nodes.custom_json_config_json` (মাইগ্রেশন `240_provider_node_custom_json_config.sql`) এ সংরক্ষণ করা হয় এবং প্রতিটি সংযোগের `providerSpecificData.customJson` এ কপি করা হয়।

বাস্তবায়ন: `open-sse/utils/customJson.ts` (বৈধকরণ এবং টেমপ্লেটিং), `open-sse/executors/customJson.ts` (নির্বাহক), `open-sse/services/combo/noReplayLatch.ts` এবং `src/sse/handlers/chat/responsePolicies.ts` (নো-রিপ্লে)।
