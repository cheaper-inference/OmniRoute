## 🎯 ব্যবহারের ক্ষেত্র

### ক্ষেত্র 1: "আমার Claude Pro সাবস্ক্রিপশন আছে"

**সমস্যা:** কোটা অব্যবহৃত অবস্থায় মেয়াদোত্তীর্ণ হয়ে যায়, নিবিড় কোডিংয়ের সময় রেট লিমিটে পৌঁছে যায়

```
কম্বো: "maximize-claude"
  1. cc/claude-opus-4-7        (সাবস্ক্রিপশন সম্পূর্ণভাবে ব্যবহার করুন)
  2. glm/glm-4.7               (কোটা শেষ হলে সাশ্রয়ী ব্যাকআপ)
  3. if/qwen3.8-max-preview       (জরুরি পরিস্থিতিতে বিনামূল্যের ফলব্যাক)

মাসিক খরচ: $20 (সাবস্ক্রিপশন) + ~$5 (ব্যাকআপ) = মোট $25
বনাম $20 + সীমায় পৌঁছানো = হতাশা
```

### ক্ষেত্র 2: "আমি শূন্য খরচ চাই"

**সমস্যা:** সাবস্ক্রিপশনের খরচ বহন করতে পারি না, নির্ভরযোগ্য AI কোডিং প্রয়োজন

```
কম্বো: "zero-cost"
  1. if/kimi-k2.7-code          (তালিকাভুক্ত বিনামূল্যের অ্যাক্সেস; রেট লিমিট প্রযোজ্য হতে পারে)
  2. kr/qwen3-coder-next        (Kiro-এর বিনামূল্যের ফলব্যাক)

মাসিক খরচ: $0
গুণমান: আপনার কাজের জন্য মডেল, সীমাবদ্ধতা, গোপনীয়তা এবং SLA যাচাই করুন
```

### ক্ষেত্র 3: "আমার কোনো বাধা ছাড়াই 24/7 কোডিং প্রয়োজন"

**সমস্যা:** সময়সীমা আছে, ডাউনটাইম বহন করা সম্ভব নয়

```
কম্বো: "always-on"
  1. cc/claude-opus-4-7        (সেরা গুণমান)
  2. cx/gpt-5.5                (দ্বিতীয় সাবস্ক্রিপশন)
  3. glm/glm-4.7               (সাশ্রয়ী, প্রতিদিন রিসেট হয়)
  4. minimax/MiniMax-M2.1      (সবচেয়ে সস্তা, 5 ঘণ্টায় রিসেট)
  5. if/deepseek-v4-flash       (তালিকাভুক্ত বিনামূল্যের অ্যাক্সেস; রেট লিমিট প্রযোজ্য হতে পারে)

ফলাফল: ফলব্যাকের 5টি স্তর সহনশীলতা বাড়ায়; আপস্ট্রিমের প্রাপ্যতা নিশ্চিত নয়
মাসিক খরচ: $20-200 (সাবস্ক্রিপশন) + $10-20 (ব্যাকআপ)
```

### ক্ষেত্র 4: "আমি OpenClaw-এ বিনামূল্যের AI চাই"

**সমস্যা:** মেসেজিং অ্যাপে সম্পূর্ণ বিনামূল্যের AI সহকারী প্রয়োজন

```
কম্বো: "openclaw-free"
  1. if/qwen3.8-max-preview     (তালিকাভুক্ত বিনামূল্যের অ্যাক্সেস; রেট লিমিট প্রযোজ্য হতে পারে)
  2. if/deepseek-v4-flash       (তালিকাভুক্ত বিনামূল্যের অ্যাক্সেস; রেট লিমিট প্রযোজ্য হতে পারে)
  3. if/kimi-k2.7-code          (তালিকাভুক্ত বিনামূল্যের অ্যাক্সেস; রেট লিমিট প্রযোজ্য হতে পারে)

মাসিক খরচ: $0
যেগুলোর মাধ্যমে অ্যাক্সেস করা যায়: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 🚀 ডিপ্লয়মেন্ট

### গ্লোবাল npm ইনস্টল (প্রস্তাবিত)

```bash
npm install -g omniroute

# কনফিগারেশন ডিরেক্টরি তৈরি করুন
mkdir -p ~/.omniroute

# .env ফাইল তৈরি করুন (.env.example দেখুন)
cp .env.example ~/.omniroute/.env

# সার্ভার চালু করুন
omniroute
# অথবা কাস্টম পোর্টসহ:
omniroute --port 3000
```

CLI স্বয়ংক্রিয়ভাবে `~/.omniroute/.env` অথবা `./.env` থেকে `.env` লোড করে।

### ট্রে মোড

সিস্টেম ট্রেতে OmniRoute চালু করুন:

```bash
omniroute serve --tray
```

সার্ভার ও ট্রে প্রস্তুত হওয়ার পর কমান্ডটি সমাপ্ত হয়।

টার্মিনাল ছাড়াই সার্ভারটি চলতে থাকে।

ট্রে মোড macOS, Windows এবং গ্রাফিক্যাল Linux সেশন সমর্থন করে। ট্রে মোড স্বয়ংক্রিয়ভাবে ড্যাশবোর্ড খোলে না।

নিচের কাজগুলোর জন্য ট্রে মেনু ব্যবহার করুন:

- ড্যাশবোর্ড খুলুন।
- `/dashboard/logs` খুলুন।
- স্বয়ংক্রিয়ভাবে চালু হওয়ার সেটিং পরিবর্তন করুন।
- OmniRoute বন্ধ করুন।

এই অপশনগুলোর সঙ্গে `--tray` ব্যবহার করবেন না:

- `--daemon`
- `--log`
- `--no-recovery`

এই মোডগুলোর জন্য ভিন্ন প্রক্রিয়া মালিকানা প্রয়োজন।

পরবর্তীবার মেশিনে লগইন করার সময় চালু হওয়া সক্রিয় করুন:

```bash
omniroute autostart enable
```

macOS, Windows এবং গ্রাফিক্যাল Linux সেশনে স্বয়ংক্রিয় চালু হওয়ার জন্য ট্রে মোড ব্যবহৃত হয়। হেডলেস Linux বিদ্যমান systemd ব্যবহারকারী পরিষেবা ব্যবহার করে।

লগইনের সময় চালু হওয়া নিষ্ক্রিয় করুন:

```bash
omniroute autostart disable
```

### আনইনস্টল করা

OmniRoute আর প্রয়োজন না হলে পরিচ্ছন্নভাবে অপসারণের জন্য আমরা দুটি দ্রুত স্ক্রিপ্ট প্রদান করি:

| কমান্ড                   | কাজ                                                                                            |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | সিস্টেম অ্যাপটি অপসারণ করে, তবে `~/.omniroute`-এ থাকা **আপনার DB ও কনফিগারেশনগুলো রেখে দেয়**। |
| `npm run uninstall:full` | অ্যাপটি অপসারণ করে এবং স্থায়ীভাবে **সব কনফিগারেশন, কী ও ডেটাবেস মুছে দেয়**।                  |

> দ্রষ্টব্য: এই কমান্ডগুলো চালাতে OmniRoute প্রকল্প ফোল্ডারে যান (যদি আপনি এটি ক্লোন করে থাকেন) এবং সেখান থেকে চালান। বিকল্পভাবে, গ্লোবালি ইনস্টল করা থাকলে শুধু `npm uninstall -g omniroute` চালাতে পারেন।

**অন্যান্য সামঞ্জস্যপূর্ণ প্রোভাইডার** (নির্বাচিত): `cohere`, `databricks`, `snowflake`, `together`, `vertex`, `alibaba`, `alibaba-cn`, `bedrock` (`aws-bedrock` এর মাধ্যমে), `azure-ai`, `openrouter` (পাসথ্রু ক্যাটালগ), `siliconflow`, `hyperbolic`, `huggingface`, `featherless-ai`, `cloudflare-ai`, `scaleway`, `deepinfra`, `vercel-ai-gateway`, `bazaarlink`, `friendliai`, `nous-research`, `reka`, `volcengine`, `ai21`, `gigachat`। প্রতিটি `providerRegistry.ts`-এ নিজস্ব মডেল তালিকা রক্ষণাবেক্ষণ করে এবং প্রোভাইডার `/models` এন্ডপয়েন্ট প্রকাশ করলে অটো-সিঙ্ক করা যায়।

## 🧩 উন্নত ফিচার

### কাস্টম মডেল

অ্যাপ আপডেটের জন্য অপেক্ষা না করেই যেকোনো প্রোভাইডারে যেকোনো মডেল ID যোগ করুন:

```bash
# API এর মাধ্যমে
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# তালিকা: curl http://localhost:20128/api/provider-models?provider=openai
# সরান: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

অথবা ড্যাশবোর্ড ব্যবহার করুন: **Providers → [Provider] → Custom Models**।

নোট:

- OpenRouter এবং OpenAI/Anthropic-সামঞ্জস্যপূর্ণ প্রোভাইডারগুলো শুধুমাত্র **Available Models** থেকে পরিচালিত হয়। ম্যানুয়াল অ্যাড, ইমপোর্ট এবং অটো-সিঙ্ক সবই একই available-model তালিকায় যায়, তাই ঐ প্রোভাইডারগুলোর জন্য আলাদা কোনো Custom Models সেকশন নেই।
- **Custom Models** সেকশনটি এমন প্রোভাইডারদের জন্য যারা পরিচালিত available-model ইমপোর্ট প্রদান করে না।

### কাস্টম OpenAI-সামঞ্জস্যপূর্ণ প্রোভাইডার

OpenAI API বলতে সক্ষম যেকোনো গেটওয়ে (সেলফ-হোস্টেড প্রক্সি, vLLM, বা থার্ড-পার্টি অ্যাগ্রিগেটর)
তার নিজস্ব প্রোভাইডার নোড হিসেবে যোগ করা যায়:

1. **Providers → Add OpenAI Compatible**।
2. **Name**: নোডের জন্য একটি ডিসপ্লে লেবেল।
3. **Prefix**: রাউটিং নাম। ক্লায়েন্টরা মডেলকে `<prefix>/<model>` হিসেবে কল করে, তাই
   `mygw` প্রিফিক্সওয়ালা একটি নোড `mygw/gpt-4o-mini` সার্ভ করে। আবশ্যক; কোনো ক্যারেক্টার সীমাবদ্ধতা নেই।
4. **API Type**: গেটওয়েটি যে এন্ডপয়েন্ট ফ্যামিলি সার্ভ করে (Chat Completions, Responses,
   Embeddings, অডিও, ইমেজ)।
5. **Base URL**: API রুট, `/v1` পর্যন্ত ও সহ (যেমন
   `https://gateway.example.com/v1`), সম্পূর্ণ `/chat/completions` পাথ নয়। অ-মানক পাথওয়ালা
   গেটওয়েগুলো সেগুলো **Advanced Settings**-এ সেট করে (চ্যাট পাথ, মডেল পাথ)।
6. **API Key (for Check)** ফিল্ডটি শুধুমাত্র কানেকশন পরীক্ষা করে। নোড তৈরির পর,
   সেটি খুলুন এবং রিকোয়েস্টগুলো যে কী ব্যবহার করবে তা সংরক্ষণ করতে **Add Connection** ব্যবহার করুন।

নোডটি `openai-compatible-<apiType>-<uuid>` ফর্ম্যাটের একটি অভ্যন্তরীণ id পায়; আপনাকে এটি
কখনোই টাইপ করতে হবে না, প্রিফিক্সই পাবলিক নাম।

#### সংরক্ষিত প্রিফিক্স

প্রিফিক্স কোনো বিল্ট-ইন প্রোভাইডারের id বা অ্যালিয়াস (যেমন `openai`, `cf`) হতে পারে না,
অবসরপ্রাপ্ত প্রোভাইডারের id-ও হতে পারে না। মডেল রিজলভার কাস্টম নোডের আগে বিল্ট-ইন id ও অ্যালিয়াস
পরীক্ষা করে, তাই এসব প্রিফিক্সের একটি ব্যবহারকারী নোড কখনোই ট্রাফিক পাবে না:
`<prefix>/model` বরং বিল্ট-ইন প্রোভাইডারের কাছে চলে যাবে, অথবা ঐ প্রোভাইডার অবসরপ্রাপ্ত হলে
fail closed হবে। এমন প্রিফিক্স দিয়ে নোড তৈরি বা সম্পাদনা করলে তা প্রত্যাখ্যান করা হয় এই বার্তাসহ:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

একটি স্বতন্ত্র প্রিফিক্স বেছে নিন (`mygw`, `acme-proxy`)। যদি কাস্টম নোডের রিকোয়েস্ট এমন একটি
এরর দিয়ে ব্যর্থ হয় যেখানে কোনো বিল্ট-ইন প্রোভাইডার বা তার ক্রেডেনশিয়ালের নাম উল্লেখ আছে,
তাহলে দেখুন নোডের প্রিফিক্সটি সংরক্ষিত কি না: এই নিয়ম চালু হওয়ার আগে সংরক্ষণ করা নোডগুলো
এখনো স্টোর করা আছে, কিন্তু তাদের প্রিফিক্স বিল্ট-ইন প্রোভাইডারের দিকে রুট হয়। নোডটি এডিট
করে নতুন একটি প্রিফিক্স দিন।

#### প্রতি-কানেকশন গেটওয়ে অপশন

এই কীগুলো কানেকশনের `providerSpecificData`-তে যায় (যেমন
`PUT /api/providers/{id}` এর মাধ্যমে):

- `toolNameMaxLength` (পূর্ণসংখ্যা, 1–1024) — OpenAI চ্যাট-ফর্ম্যাট সামঞ্জস্যপূর্ণ কানেকশনের জন্য
  যেগুলোর গেটওয়ে লম্বা টুল নাম প্রত্যাখ্যান করে। লম্বা নামগুলো সংক্ষিপ্ত অ্যালিয়াস হিসেবে পাঠানো হয়
  এবং রেসপন্সে পুনরুদ্ধার করা হয়।
- `quotaEndpoint` — গেটওয়ের কোটা/ক্রেডিট এন্ডপয়েন্ট, যা ড্যাশবোর্ডের কোটা স্ট্রিপ এবং
  কোটা-সচেতন রাউটিংয়ের জন্য পড়া হয়। OpenAI- ও Anthropic-সামঞ্জস্যপূর্ণ উভয় কানেকশনেই কাজ করে;
  সম্পূর্ণ স্ট্রাকচার `open-sse/services/usage/openaiCompatible.ts`-এ ডকুমেন্ট করা আছে।

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### OmniRoute পিয়ার চেইন করা

আরেকটি OmniRoute গেটওয়ে **Custom OpenAI-compatible** প্রোভাইডার হিসেবে যোগ করা যায়। পিয়ারের
`/v1` বেস URL এবং ঐ পিয়ারের ইস্যু করা একটি ডেডিকেটেড, ন্যূনতম-অধিকারভুক্ত API কী ব্যবহার করুন।

পারস্পরিক বা মাল্টি-হপ চেইনের জন্য, প্রতিটি গেটওয়েতে অপ্ট-ইন লুপ গার্ড চালু করুন:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

শুধুমাত্র স্পষ্টভাবে অনুমোদিত তালিকাভুক্ত পিয়ার URL-এ পাঠানো রিকোয়েস্টগুলোই
`X-OmniRoute-Peer-Trace` হেডার পায়। পুনরাবৃত্ত ইনস্ট্যান্স ID বা শেষ হয়ে যাওয়া হপ
বাজেট থাকলে গেটওয়ে HTTP `508 Loop Detected` দিয়ে প্রত্যাখ্যান করে; সাধারণ আপস্ট্রিম
প্রোভাইডাররা কোনো পিয়ার মেটাডেটা পায় না।

পিয়ার চেইনিং ডাটাবেস রেপ্লিকেশন বা হোস্ট ফেইলওভার নয়। প্রতিটি গেটওয়ে স্বাধীন
SQLite স্টেট, ক্যাশে, রেট কাউন্টার এবং সেশন ধরে রাখে। অ্যাক্টিভ/প্যাসিভ বা অ্যাক্টিভ/অ্যাক্টিভ
প্রাপ্যতার জন্য হেলথ-চেকড রিভার্স প্রক্সি বা ক্লায়েন্ট ফেইলওভার ব্যবহার করুন, এবং কখনোই
একটি SQLite ডাটাবেস একাধিক চলমান OmniRoute ইনস্ট্যান্সে মাউন্ট করবেন না।

### ডেডিকেটেড প্রোভাইডার রুট

মডেল যাচাইকরণসহ রিকোয়েস্ট সরাসরি নির্দিষ্ট প্রোভাইডারের কাছে রুট করুন:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

প্রোভাইডার প্রিফিক্স না থাকলে স্বয়ংক্রিয়ভাবে যোগ হয়ে যায়। মিল না থাকা মডেলগুলো `400` রিটার্ন করে।

### নেটওয়ার্ক প্রক্সি কনফিগারেশন

```bash
# গ্লোবাল প্রক্সি সেট করুন
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# প্রোভাইডার-ভিত্তিক প্রক্সি
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# প্রক্সি টেস্ট করুন
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**অগ্রাধিকার:** কী-নির্দিষ্ট → কম্বো-নির্দিষ্ট → প্রোভাইডার-নির্দিষ্ট → গ্লোবাল → এনভায়রনমেন্ট।

### মডেল ক্যাটালগ API

```bash
curl http://localhost:20128/api/models/catalog
```

প্রোভাইডার অনুযায়ী গ্রুপ করা মডেলগুলো টাইপসহ (`chat`, `embedding`, `image`) ফেরত দেয়।

### ক্লাউড সিঙ্ক

- ডিভাইসগুলোর মধ্যে প্রোভাইডার, কম্বো এবং সেটিংস সিঙ্ক করুন
- টাইমআউট + ফেইল-ফাস্ট সহ স্বয়ংক্রিয় ব্যাকগ্রাউন্ড সিঙ্ক
- প্রোডাকশনে সার্ভার-সাইড `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` ব্যবহার করাই ভালো

### Cloudflare Quick Tunnel

- Docker এবং অন্যান্য সেল্ফ-হোস্টেড ডিপ্লয়মেন্টের জন্য **ড্যাশবোর্ড → এন্ডপয়েন্টস**-এ উপলব্ধ
- একটি অস্থায়ী `https://*.trycloudflare.com` URL তৈরি করে যা আপনার বর্তমান OpenAI-সামঞ্জস্যপূর্ণ `/v1` এন্ডপয়েন্টে ফরওয়ার্ড করে
- প্রথমবার সক্ষম করলে শুধুমাত্র প্রয়োজন হলে `cloudflared` ইনস্টল হয়; পরবর্তী রিস্টার্টগুলো একই ম্যানেজড বাইনারি পুনঃব্যবহার করে
- OmniRoute বা কন্টেইনার রিস্টার্টের পর কুইক টানেলগুলো স্বয়ংক্রিয়ভাবে পুনরুদ্ধার হয় না; প্রয়োজন অনুযায়ী ড্যাশবোর্ড থেকে পুনরায় সক্ষম করুন
- টানেল URL গুলো ক্ষণস্থায়ী এবং আপনি যতবার টানেল বন্ধ/চালু করবেন ততবার পরিবর্তন হয়
- ম্যানেজড কুইক টানেলগুলো সীমাবদ্ধ কন্টেইনারে কোলাহলপূর্ণ QUIC UDP বাফার সতর্কতা এড়াতে ডিফল্টভাবে HTTP/2 ট্রান্সপোর্ট ব্যবহার করে
- ম্যানেজড ট্রান্সপোর্ট পছন্দ ওভাররাইড করতে চাইলে `CLOUDFLARED_PROTOCOL=quic` বা `auto` সেট করুন
- ম্যানেজড ডাউনলোডের পরিবর্তে পূর্ব-ইনস্টল করা `cloudflared` বাইনারি ব্যবহার করতে চাইলে `CLOUDFLARED_BIN` সেট করুন
- Cloudflare Quick Tunnel, Tailscale Funnel এবং ngrok Tunnel প্যানেলগুলো **সেটিংস → অ্যাপিয়ারেন্স**-এ দেখানো বা লুকানো যায়। কোনো প্যানেল লুকালে চলমান টানেল বন্ধ হয় না।

### LLM গেটওয়ে ইন্টেলিজেন্স (ফেজ 9)

- **সিমান্টিক ক্যাশে** — নন-স্ট্রিমিং, temperature=0 রেসপন্সগুলো স্বয়ংক্রিয়ভাবে ক্যাশে করে (`X-OmniRoute-No-Cache: true` দিয়ে বাইপাস করুন)
- **রিকোয়েস্ট আইডেমপোটেন্সি** — `Idempotency-Key` বা `X-Request-Id` হেডারের মাধ্যমে 5 সেকেন্ডের মধ্যে ডুপ্লিকেট রিকোয়েস্ট বাদ দেয়
- **প্রগ্রেস ট্র্যাকিং** — `X-OmniRoute-Progress: true` হেডারের মাধ্যমে অপ্ট-ইন SSE `event: progress` ইভেন্ট

| **টেস্ট বেঞ্চ**   | অনুবাদের সঠিকতা যাচাই করতে একাধিক ফরম্যাট কম্বিনেশনে ব্যাচ টেস্ট চালান                            |

**ব্যবহারের ক্ষেত্রে:**

- থিংকিং ট্যাগ, টুল কল এবং সিস্টেম প্রম্পট সঠিকভাবে অনুবাদ হয় কিনা যাচাই করুন
- OpenAI, Claude, Gemini এবং Responses API ফরম্যাটের মধ্যে পার্থক্য তুলনা করুন

### রাউটিং স্ট্র্যাটেজি

**ড্যাশবোর্ড → সেটিংস → রাউটিং** থেকে কনফিগার করুন। ড্যাশবোর্ডে সবচেয়ে বেশি ব্যবহৃত ছয়টি স্ট্র্যাটেজি দেখায়; কম্বো এবং অটো-রাউটার অভ্যন্তরীণভাবে আরও বিস্তৃত সেট সমর্থন করে।

**ড্যাশবোর্ড-দৃশ্যমান স্ট্র্যাটেজি (অ্যাকাউন্ট-লেভেল রাউটিং):**

| স্ট্র্যাটেজি                   | বর্ণনা                                                                                                              |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| **ফিল ফার্স্ট**                | অগ্রাধিকার ক্রমে অ্যাকাউন্ট ব্যবহার করে — প্রাইমারি অ্যাকাউন্ট অনুপলব্ধ না হওয়া পর্যন্ত সব রিকোয়েস্ট পরিচালনা করে |
| **রাউন্ড রবিন**                | কনফিগারযোগ্য স্টিকি লিমিটসহ সব অ্যাকাউন্টের মধ্যে ঘুরে ঘুরে যায় (ডিফল্ট: প্রতি অ্যাকাউন্টে 3টি কল)                 |
| **P2C (Power of Two Choices)** | 2টি র্যান্ডম অ্যাকাউন্ট বেছে নিয়ে তুলনামূলক স্বাস্থ্যকরটিতে রাউট করে — হেলথ সচেতনভাবে লোড ব্যালান্স করে            |
| **র্যান্ডম**                   | Fisher-Yates শাফল ব্যবহার করে প্রতিটি রিকোয়েস্টের জন্য র্যান্ডমভাবে একটি অ্যাকাউন্ট নির্বাচন করে                   |
| **লিস্ট ইউজড**                 | সবচেয়ে পুরনো `lastUsedAt` টাইমস্ট্যাম্পযুক্ত অ্যাকাউন্টে রাউট করে, ট্রাফিক সমানভাবে বিতরণ করে                      |
| **কস্ট অপ্টিমাইজড**            | সর্বনিম্ন অগ্রাধিকার মানের অ্যাকাউন্টে রাউট করে, সর্বনিম্ন-খরচের প্রোভাইডারদের জন্য অপ্টিমাইজ করে                   |

**অ্যাডভান্সড কম্বো এবং অটো স্ট্র্যাটেজি** (প্রতি কম্বোতে কনফিগারযোগ্য অথবা `auto/*` প্রিফিক্সের মাধ্যমে — দেখুন [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — কঠোর ক্রম, কখনো রাউন্ড-রবিন করে না
- `weighted` — প্রতি-মডেল ওজন অনুযায়ী আনুপাতিক ট্রাফিক বিভাজন
- `fill-first` — লিমিট পৌঁছানো পর্যন্ত প্রথম মডেলটিই ব্যবহার করে
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` এবং `cost-optimized`
- `auto` — সব প্রার্থীর মধ্যে স্কোর-চালিত
- `lkgp` (Last Known Good Provider) — শেষ সফল প্রোভাইডারে আটকে থাকে, তারপর রুলে ফিরে যায়
- `context-optimized` — সবচেয়ে বড় ফাঁকা কনটেক্সট উইন্ডোযুক্ত মডেল বেছে নেয়
- `context-relay` — ফলো-আপ টার্নের জন্য দীর্ঘ-কনটেক্সট মডেলগুলো চেইন করে

#### এক্সটার্নাল স্টিকি সেশন হেডার

এক্সটার্নাল সেশন অ্যাফিনিটির জন্য (উদাহরণস্বরূপ, রিভার্স প্রক্সির পেছনে থাকা Claude Code/Codex এজেন্ট), পাঠান:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id`-ও গ্রহণ করে এবং কার্যকর সেশন কী `X-OmniRoute-Session-Id`-এ ফেরত দেয়।

আপনি যদি Nginx ব্যবহার করেন এবং আন্ডারস্কোর-ফর্ম হেডার পাঠান, তাহলে সক্ষম করুন:

```nginx
underscores_in_headers on;
```

#### ওয়াইল্ডকার্ড মডেল অ্যালিয়াস

মডেলের নাম রিম্যাপ করতে ওয়াইল্ডকার্ড প্যাটার্ন তৈরি করুন:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

ওয়াইল্ডকার্ড `*` (যেকোনো অক্ষর) এবং `?` (একটি অক্ষর) সমর্থন করে।

#### ফলব্যাক চেইন

সব রিকোয়েস্টে প্রযোজ্য গ্লোবাল ফলব্যাক চেইন সংজ্ঞায়িত করুন:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### সাধারণ প্রোভাইডার কম্বিনেশন ও রাউটিং প্যাটার্ন

OmniRoute-এ একাধিক প্রোভাইডার একত্রিত করা এবং তাদের মধ্যে রাউটিং করার কিছু উদাহরণ প্যাটার্ন নিচে দেওয়া হলো:

#### 1. কোডিং এজেন্ট কম্বো: খরচ/গতি ফলব্যাক সহ উচ্চমানের রিজনিং

কোডিং এজেন্টের (OpenCode, Claude Code, Cursor, Cline) জন্য আদর্শ। প্রাথমিকভাবে ফ্রন্টিয়ার রিজনিং মডেলে রাউট করে, কোটা শেষ হয়ে গেলে বা ত্রুটি ঘটলে দ্রুত কোডিং মডেলে ফলব্যাক করে।

- **ড্যাশবোর্ড**: Combos → New Combo → Name: `agent-coding` → Strategy: `Priority`
- **মডেল**:
  1. `claude/claude-sonnet-4-6` (প্রাথমিক কোডিং এজেন্ট)
  2. `openai/gpt-4o` (সেকেন্ডারি উচ্চ-ক্ষমতার ফলব্যাক)
  3. `deepseek/deepseek-v4-flash` (উচ্চ-দক্ষ, সাশ্রয়ী ফলব্যাক)

```bash
# API এর মাধ্যমে উদাহরণ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

#### 2. ফ্রি-টিয়ার অটো ফেইলওভার কম্বো

API খরচ ছাড়াই আপটাইম সর্বোচ্চ করতে একাধিক ফ্রি-টিয়ার এবং কী-বিহীন প্রোভাইডারকে চেইন করে।

- **স্ট্র্যাটেজি**: `Least Used` অথবা `Round Robin` (কোটা জুড়ে লোড বিতরণ করে)
- **মডেল**:
  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

```bash
# CLI এর মাধ্যমে উদাহরণ
omniroute combo create free-stack \
  --models "groq/llama-3.3-70b-versatile,gemini/gemini-2.5-flash,cerebras/gpt-oss-120b" \
  --strategy round-robin
```

#### 3. মাল্টিমোডাল / ভিশন ও টেক্সট পাইপলাইন

ইমেজ আন্ডারস্ট্যান্ডিং এবং কোড জেনারেশন-ভিত্তিক ওয়ার্কফ্লোর জন্য বিশেষায়িত ভিশন মডেলকে হাই-স্পিড টেক্সট জেনারেশনের সাথে যুক্ত করা।

- **প্যাটার্ন**: একটি `Priority` কম্বো যা প্রথমে ভিশন-সক্ষম মডেলগুলো এবং সবশেষে একটি হাই-থ্রুপুট টেক্সট/কোড মডেল তালিকাভুক্ত করে।
- **মডেল**:
  1. `gemini/gemini-2.5-pro` (শক্তিশালী ইমেজ/মাল্টিমোডাল উপলব্ধি)
  2. `openai/gpt-4o` (ভারসাম্যপূর্ণ ভিশন ও টুল ব্যবহার)
  3. `deepseek/deepseek-v4-flash` (টেক্সট/কোড জেনারেশন)

### রেজিলিয়েন্স ও সার্কিট ব্রেকার

**Dashboard → Settings → Resilience** এর মাধ্যমে কনফিগার করুন।

OmniRoute পাঁচটি উপাদান নিয়ে প্রোভাইডার-স্তরের রেজিলিয়েন্স বাস্তবায়ন করে:

1. **Request Queue & Pacing** — সিস্টেম-স্তরের রিকোয়েস্ট শেপিং:
   - **Requests Per Minute (RPM)** — প্রতি অ্যাকাউন্টে প্রতি মিনিটে সর্বাধিক রিকোয়েস্ট
   - **Min Time Between Requests** — রিকোয়েস্টগুলোর মধ্যে মিলিসেকেন্ডে ন্যূনতম ব্যবধান
   - **Max Concurrent Requests** — প্রতি অ্যাকাউন্টে সর্বাধিক একসাথে চলমান রিকোয়েস্ট

2. **Connection Cooldown** — রিট্রাই-যোগ্য ব্যর্থতার পর একটি একক সংযোগের জন্য প্রতি-অথ-টাইপ কনফিগারেশন:
   - **Base Cooldown** — রিট্রাই-যোগ্য আপস্ট্রিম ব্যর্থতার জন্য ডিফল্ট কুলডাউন উইন্ডো
   - **Use Upstream Retry Hints** — প্রদান করা হলে প্রামাণিক `Retry-After` বা রিসেট হিন্ট মেনে চলে
   - **Max Backoff Steps** — বারবার ব্যর্থতার ক্ষেত্রে সর্বাধিক এক্সপোনেনশিয়াল ব্যাকঅফ স্তর

3. **Provider Circuit Breaker** — এন্ড-টু-এন্ড প্রোভাইডার ব্যর্থতা ট্র্যাক করে, কনফিগার করা সতর্কতা থ্রেশহোল্ডে প্রোভাইডারকে ডিগ্রেডেড হিসেবে চিহ্নিত করে, এবং কনফিগার করা ব্যর্থতা থ্রেশহোল্ডে পৌঁছালে ব্রেকার খুলে দেয়:
   - **Degradation Threshold** — `DEGRADED` অবস্থায় প্রবেশের আগে পরপর প্রোভাইডার ব্যর্থতার সংখ্যা
   - **Failure Threshold** — `OPEN` অবস্থায় প্রবেশের আগে পরপর প্রোভাইডার ব্যর্থতার সংখ্যা
   - **Reset Timeout** — প্রোভাইডারকে আবার পরীক্ষা করার আগের সময়ের উইন্ডো
   - **CLOSED** (সুস্থ) — রিকোয়েস্ট স্বাভাবিকভাবে প্রবাহিত হয়
   - **DEGRADED** — বর্ধিত ব্যর্থতা ট্র্যাক করা হলেও রিকোয়েস্ট প্রবাহিত হতে থাকে
   - **OPEN** — বারবার ব্যর্থতার পর প্রোভাইডার সাময়িকভাবে ব্লক করা হয়
   - **HALF_OPEN** — প্রোভাইডার পুনরুদ্ধার হয়েছে কিনা পরীক্ষা করা হচ্ছে

   সংযোগ-স্কোপড `429` রেট লিমিট **Connection Cooldown**-এই থাকে এবং প্রোভাইডার ব্রেকারের হিসাবে গণনা করা হয় না।

   প্রোভাইডার ব্রেকারের রানটাইম অবস্থা শুধুমাত্র **Dashboard → Health**-এ দেখানো হয়।

4. **Wait For Cooldown** — যদি প্রতিটি প্রার্থী সংযোগ ইতিমধ্যেই কুলডাউনে থাকে, OmniRoute সবচেয়ে আগের কুলডাউনের জন্য অপেক্ষা করতে পারে এবং একই ক্লায়েন্ট রিকোয়েস্ট স্বয়ংক্রিয়ভাবে পুনরায় চেষ্টা করতে পারে।

5. **Rate Limit Auto-Detection** — আপস্ট্রিম প্রোভাইডাররা সুস্পষ্ট অপেক্ষার উইন্ডো ফেরত দিলে, সেটিংটি সক্রিয় থাকলে সেই হিন্টগুলো স্থানীয় সংযোগ কুলডাউনকে ওভাররাইড করে।

**প্রো টিপ:** বিভ্রাটের পর লাইভ প্রোভাইডার ব্রেকার পরীক্ষা ও রিসেট করতে **Health** পৃষ্ঠাটি ব্যবহার করুন। Resilience পৃষ্ঠা শুধুমাত্র কনফিগারেশন পরিবর্তন করে।

### ডাটাবেস এক্সপোর্ট / ইমপোর্ট

**Dashboard → Settings → System & Storage**-এ ডাটাবেস ব্যাকআপ পরিচালনা করুন।

| অ্যাকশন                  | বর্ণনা                                                                                                                                                    |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Export Database**      | বর্তমান SQLite ডাটাবেসটি একটি `.sqlite` ফাইল হিসেবে ডাউনলোড করে                                                                                           |
| **Export All (.tar.gz)** | একটি সম্পূর্ণ ব্যাকআপ আর্কাইভ ডাউনলোড করে যাতে রয়েছে: ডাটাবেস, সেটিংস, কম্বো, প্রোভাইডার সংযোগ (কোনো ক্রেডেনশিয়াল ছাড়া), API কী মেটাডেটা               |
| **Import Database**      | বর্তমান ডাটাবেস প্রতিস্থাপন করতে একটি `.sqlite` ফাইল আপলোড করুন। `DISABLE_SQLITE_AUTO_BACKUP=true` না হলে ইমপোর্ট-পূর্ব ব্যাকআপ স্বয়ংক্রিয়ভাবে তৈরি হয় |

```bash
# API: ডাটাবেস এক্সপোর্ট
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: সব এক্সপোর্ট (সম্পূর্ণ আর্কাইভ)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ডাটাবেস ইমপোর্ট
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ইমপোর্ট যাচাইকরণ:** ইমপোর্ট করা ফাইলটি অখণ্ডতা (SQLite pragma চেক), প্রয়োজনীয় টেবিল (`provider_connections`, `provider_nodes`, `combos`, `api_keys`), এবং আকার (সর্বাধিক 100MB) যাচাই করা হয়।

**ব্যবহারের ক্ষেত্র:**

- মেশিনের মধ্যে OmniRoute স্থানান্তর করা
- দুর্যোগ পুনরুদ্ধারের জন্য বহিরাগত ব্যাকআপ তৈরি করা
- দলের সদস্যদের মধ্যে কনফিগারেশন শেয়ার করা (সব এক্সপোর্ট → আর্কাইভ শেয়ার)

### সেটিংস ড্যাশবোর্ড

সহজ নেভিগেশনের জন্য সেটিংস পৃষ্ঠাটি **৭টি ট্যাবে** সাজানো হয়েছে:

| ট্যাব              | বিষয়বস্তু                                                                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **সাধারণ**         | সিস্টেম স্টোরেজ টুল, ডিফল্ট আচরণ, Endpoint টানেল দৃশ্যমানতা                                                                                                        |
| **চেহারা**         | থিম নিয়ন্ত্রণ (লাইট/ডার্ক/সিস্টেম), সাইডবার দৃশ্যমানতা, Cloudflare/Tailscale/ngrok টানেল কার্ডের জন্য প্যানেল টগল                                                 |
| **AI**             | থিঙ্কিং বাজেট (passthrough / auto-strip / custom / adaptive — দেখুন [THINKING_BUDGET.md](./THINKING_BUDGET.md)), গ্লোবাল সিস্টেম প্রম্পট, প্রম্পট ক্যাশ পরিসংখ্যান |
| **নিরাপত্তা**      | লগইন/পাসওয়ার্ড সেটিংস, IP অ্যাক্সেস নিয়ন্ত্রণ, `/models`-এর জন্য API অথেন্টিকেশন, প্রোভাইডার ব্লকিং, প্রম্পট-ইনজেকশন গার্ড                                       |
| **রাউটিং**         | গ্লোবাল রাউটিং কৌশল (Fill First / Round Robin / P2C / Random / Least Used / Cost Optimized), ওয়াইল্ডকার্ড মডেল অ্যালিয়াস, ফলব্যাক চেইন, কম্বো ডিফল্ট             |
| **স্থিতিস্থাপকতা** | রিকোয়েস্ট কিউ, কানেকশন কুলডাউন, প্রোভাইডার ব্রেকার কনফিগারেশন, এবং wait-for-cooldown আচরণ                                                                         |
| **উন্নত**          | গ্লোবাল প্রক্সি কনফিগারেশন (HTTP/SOCKS5), প্রতি-প্রোভাইডার প্রক্সি ওভাররাইড                                                                                        |

সাধারণ ট্যাবে আর রিড-অনলি লগিং এবং ক্যাশ নোটগুলো ডুপ্লিকেট হয় না। ডাটাবেস রিটেনশন এবং
অপ্টিমাইজেশন সেটিংস `/api/settings/database` এর মাধ্যমে সংরক্ষিত হয়; ম্যানুয়াল ক্যাশ মুছে ফেলা
`DELETE /api/cache` ব্যবহার করে। রিকোয়েস্ট এবং প্রক্সি লগ সারির সীমা
`CALL_LOGS_TABLE_MAX_ROWS` এবং `PROXY_LOGS_TABLE_MAX_ROWS` দ্বারা নিয়ন্ত্রিত হয়।

| ------------------ | --------------------------------------------------------------------------------------------------- |
| **বাজেট**          | দৈনিক/সাপ্তাহিক/মাসিক বাজেট এবং রিয়েল-টাইম ট্র্যাকিং সহ প্রতি API কী-তে ব্যয়ের সীমা নির্ধারণ করুন |

curl http://localhost:20128/api/usage/budget

### কম্বো ব্যালেন্সিং কৌশল

**ড্যাশবোর্ড → কম্বো → তৈরি/সম্পাদনা → কৌশল**-এ প্রতি-কম্বো ব্যালেন্সিং কনফিগার করুন।

| কৌশল               | বিবরণ                                                                            |
| ------------------ | -------------------------------------------------------------------------------- |
| **Round-Robin**    | মডেলগুলোর মধ্যে ক্রমানুসারে ঘোরে                                                 |
| **Priority**       | সবসময় প্রথম মডেলটি চেষ্টা করে; শুধুমাত্র ত্রুটিতে ফলব্যাক করে                   |
| **Random**         | প্রতিটি রিকোয়েস্টের জন্য কম্বো থেকে একটি এলোমেলো মডেল বেছে নেয়                 |
| **Weighted**       | প্রতি মডেলে নির্ধারিত ওজনের ভিত্তিতে আনুপাতিকভাবে রুট করে                        |
| **Least-Used**     | সাম্প্রতিক রিকোয়েস্ট সবচেয়ে কম এমন মডেলে রুট করে (কম্বো মেট্রিক্স ব্যবহার করে) |
| **Cost-Optimized** | সবচেয়ে সস্তা উপলব্ধ মডেলে রুট করে (মূল্য টেবিল ব্যবহার করে)                     |

গ্লোবাল কম্বো ডিফল্ট **ড্যাশবোর্ড → সেটিংস → রাউটিং → কম্বো ডিফল্ট**-এ সেট করা যায়।
কম্বো টার্গেট টাইমআউট ডিফল্টরূপে বর্তমান রিকোয়েস্ট টাইমআউট উত্তরাধিকারসূত্রে পায়। কম্বো ডিফল্ট
বা একটি পৃথক কম্বোতে **টার্গেট টাইমআউট (সেকেন্ড)** শুধুমাত্র তখনই ব্যবহার করুন যখন একটি সংক্ষিপ্ত
প্রতি-টার্গেট সীমা দ্রুত ফলব্যাক ট্রিগার করা উচিত।

জিরো-ল্যাটেন্সি কম্বো অপ্টিমাইজেশন অপ্ট-ইন। এই ল্যাটেন্সি ফিচারগুলোকে ফলব্যাক টার্গেটের সাথে
প্রতিযোগিতা করা, TTFT ইতিহাসের ভিত্তিতে টার্গেট এড়িয়ে যাওয়া, বা ফলব্যাক রিকোয়েস্ট সংকুচিত করা
থেকে বিরত রাখতে **জিরো-ল্যাটেন্সি অপ্টিমাইজেশন** নিষ্ক্রিয় রাখুন; এটি সক্ষম করলে কনফিগার করা
হেজিং, ভবিষ্যদ্বাণীমূলক TTFT স্কিপ এবং সক্রিয় ফলব্যাক কম্প্রেশনকে কম টেইল ল্যাটেন্সির বিনিময়ে
রাউটিং/রিকোয়েস্ট ফিডেলিটি ত্যাগ করতে দেয়।

আপস্ট্রিম প্রোভাইডারদের কঠোর `max_tokens` / `maxOutputTokens` সীমার প্রয়োজন হলে **Reasoning টোকেন বাফার** নিষ্ক্রিয় করুন। সক্রিয় থাকলে, কম্বো রাউটিং শুধুমাত্র পরিচিত আউটপুট সীমা থাকা মডেলগুলির জন্য reasoning-মডেল হেডরুম যোগ করে এবং নিরাপদ বাফারড মান ঐ সীমা অতিক্রম করে গেলে ক্লায়েন্ট টোকেন সীমা অপরিবর্তিত রাখে। ক্লায়েন্ট সীমা যদি ইতিমধ্যেই কোনো পরিচিত সীমার উপরে থাকে, তাহলে OmniRoute আপস্ট্রিম অনুরোধ পাঠানোর আগে সেটিকে ঐ সীমায় নামিয়ে আনে।

## 🤖 স্বয়ংক্রিয় রাউটিং (শূন্য-কনফিগারেশন)

OmniRoute-এর সঙ্গে রয়েছে একটি **স্কোর-চালিত স্বয়ংক্রিয় রাউটার**, যা সংযুক্ত প্রতিটি প্রোভাইডারের মধ্য থেকে প্রতিটি অনুরোধের জন্য সেরা মডেলটি বেছে নেয় — রক্ষণাবেক্ষণের জন্য কোনো কম্বো প্রয়োজন নেই। শুধু `auto/*` প্রিফিক্সগুলোর একটি দিয়ে অনুরোধ পাঠান, আর OmniRoute তাৎক্ষণিকভাবে একটি ভার্চুয়াল কম্বো তৈরি করবে এবং ল্যাটেন্সি, খরচ, সফলতার হার, কনটেক্সটের সামঞ্জস্য, কাজটির জন্য মডেলের উপযুক্ততা, সাম্প্রতিক ব্যর্থতা, কোটা ও সার্কিট-ব্রেকারের অবস্থার ভিত্তিতে প্রার্থীদের স্কোর করবে।

| প্রিফিক্স      | যে বিষয়ের জন্য অপ্টিমাইজ করে                                                            |
| -------------- | ---------------------------------------------------------------------------------------- |
| `auto`         | ভারসাম্যপূর্ণ ডিফল্ট (ল্যাটেন্সি × খরচ × সফলতার হার)                                     |
| `auto/coding`  | কোডিংয়ের কাজ: Claude, GPT-5, GLM, Kimi, Qwen Coder ও DeepSeek কোডারকে অগ্রাধিকার দেয়   |
| `auto/cheap`   | সর্বনিম্ন $/token, বেশি ল্যাটেন্সি গ্রহণ করে                                             |
| `auto/fast`    | সর্বনিম্ন ল্যাটেন্সি, খরচ উপেক্ষা করে                                                    |
| `auto/offline` | শুধু স্থানীয় প্রোভাইডার (Ollama, vLLM, llama.cpp) — এয়ার-গ্যাপড সেটআপের জন্য উপযোগী    |
| `auto/smart`   | রিজনিংয়ের গুণমানকে সর্বোচ্চ অগ্রাধিকার দেয় (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)  |
| `auto/lkgp`    | "সর্বশেষ কার্যকর প্রোভাইডার" — সর্বশেষ সফল প্রোভাইডারে স্থির থাকে, এরপর নিয়মে ফিরে যায় |

উদাহরণ:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "এই Python ফাংশনটি রিফ্যাক্টর করুন" }],
    "stream": true
  }'
```

স্কোরিংয়ের ওয়েট কীভাবে সামঞ্জস্য করতে হয়, প্রোভাইডারকে ব্ল্যাকলিস্ট করতে হয় এবং **ড্যাশবোর্ড → স্বয়ংক্রিয় কম্বো**-তে রাউটিংয়ের সিদ্ধান্ত পরিদর্শন করতে হয়—এসবসহ স্বয়ংক্রিয় রাউটারের সম্পূর্ণ বিবরণ [AUTO-COMBO.md](../routing/AUTO-COMBO.md)-এ রয়েছে।

## 🔌 MCP ও A2A ইন্টিগ্রেশন

OmniRoute একই সঙ্গে একটি **MCP সার্ভার** (Model Context Protocol) এবং একটি **A2A সার্ভার** (Agent-to-Agent JSON-RPC 2.0)। যেকোনো MCP-সামঞ্জস্যপূর্ণ IDE বা এজেন্ট হোস্ট সরাসরি OmniRoute-এর টুল কল করতে পারে — অতিরিক্ত কোনো র্যাপারের প্রয়োজন নেই।

### MCP ট্রান্সপোর্ট

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **স্ট্রিমযোগ্য HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (যেসব IDE প্লাগইন stdio পছন্দ করে তাদের জন্য)

### Claude Desktop সংযুক্ত করুন

macOS-এ `~/Library/Application Support/Claude/claude_desktop_config.json` অথবা Windows/Linux-এ সমতুল্য ফাইলটি সম্পাদনা করুন:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCP সংযুক্ত করুন

SSE URL `http://localhost:20128/api/mcp/sse` এবং **ড্যাশবোর্ড → API কীসমূহ**-এ তৈরি করা একটি Bearer API কী ব্যবহার করুন।

### স্কোপ

MCP বর্তমানে 32টি নামযুক্ত স্কোপ নির্ধারণ করে। প্রতিটি Bearer কীকে নির্দিষ্ট স্কোপে সীমাবদ্ধ করা যায় — প্রামাণ্য স্কোপ ও টুলের তালিকার জন্য [MCP-SERVER.md](../frameworks/MCP-SERVER.md) এবং JSON-RPC স্কিমার জন্য [A2A-SERVER.md](../frameworks/A2A-SERVER.md) দেখুন।

## 💾 মেমরি সিস্টেম

OmniRoute হাইব্রিড রিট্রিভালসহ **দীর্ঘমেয়াদি কথোপকথনের মেমরি** সংরক্ষণ করে:

- অতীতের কথোপকথনের টার্নগুলোতে কীওয়ার্ড অনুসন্ধানের জন্য **SQLite FTS5**
- শব্দার্থভিত্তিক স্মরণশক্তির জন্য **Qdrant vector store** (ঐচ্ছিক)
- **স্বয়ংক্রিয় তথ্য নিষ্কাশন** — প্রতিটি সেশনের পরে সত্তা, পছন্দ এবং সিদ্ধান্তগুলো সংক্ষেপিত হয়ে `memory_facts` টেবিলে সংরক্ষিত হয়
- মেমরিগুলো প্রতি API কী এবং প্রতি সেশন অনুযায়ী সীমাবদ্ধ থাকে

**ড্যাশবোর্ড → মেমরি** থেকে মেমরি পরিচালনা করুন (অনুসন্ধান, সম্পাদনা, এক্সপোর্ট, মুছে ফেলা)। HTTP ইন্টারফেস (`/api/memory/*`) এজেন্টদের প্রোগ্রামগতভাবে তথ্য পাঠানো ও অনুসন্ধান করার সুযোগ দেয় — দেখুন [MEMORY.md](../frameworks/MEMORY.md)।

## 🔔 ওয়েবহুক

রিয়েল-টাইম পর্যবেক্ষণ ও অটোমেশনের জন্য OmniRoute ইভেন্ট সাবস্ক্রাইব করুন।

- লক্ষ্য URL এবং HMAC স্বাক্ষর গোপন কী দিয়ে **ড্যাশবোর্ড → ওয়েবহুকস**-এ একটি ওয়েবহুক তৈরি করুন
- উপলভ্য ইভেন্ট: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- যাচাইয়ের জন্য প্রতিটি পেলোডে `X-OmniRoute-Signature` (HMAC-SHA256) অন্তর্ভুক্ত থাকে
- পুনঃচেষ্টা: সূচকীয় ব্যাকঅফসহ 3 বার চেষ্টা, তারপর ডেড-লেটার কিউ

## 🛠️ প্রোগ্রামগত ব্যবস্থাপনা

**`manage` স্কোপসহ একটি Bearer কী** ব্যবহার করে HTTP-এর মাধ্যমে OmniRoute-এর প্রতিটি রিসোর্স (প্রোভাইডার, কম্বো, কী, সেটিংস) পরিচালনা করতে পারেন।

**ড্যাশবোর্ড → API কীসমূহ → নতুন কী → স্কোপ: manage** থেকে কী তৈরি করুন, তারপর:

```bash
# প্রোভাইডারগুলোর তালিকা দেখুন
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# একটি প্রোভাইডার সংযোগ যোগ করুন
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# একটি কম্বো তৈরি করুন
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API কীসমূহের তালিকা দেখুন/তৈরি করুন
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

সম্পূর্ণ এন্ডপয়েন্ট ক্যাটালগ এবং অনুরোধ/প্রতিক্রিয়া স্কিমার জন্য [API_REFERENCE.md](../reference/API_REFERENCE.md) দেখুন।

## 💻 অভ্যন্তরীণ CLI

সেটআপ, ডায়াগনস্টিকস এবং রানটাইম নিয়ন্ত্রণের জন্য OmniRoute-এর সঙ্গে একটি অভ্যন্তরীণ CLI (`omniroute …`) রয়েছে। এটি ড্যাশবোর্ডের **"CLI Tools" পৃষ্ঠা থেকে আলাদা**, যেখানে তৃতীয়-পক্ষের CLI-গুলোকে (Claude Code, Cursor, Codex, Cline, …) কনফিগার করা হয়, যাতে সেগুলো OmniRoute-এর সঙ্গে যোগাযোগ করতে পারে।

```bash
omniroute setup                    # ইন্টার্যাক্টিভ উইজার্ড (পাসওয়ার্ড, প্রোভাইডার, কম্বো)
omniroute setup --non-interactive  # CI-বান্ধব
omniroute doctor                   # স্বাস্থ্য ডায়াগনস্টিকস (ডেটা ডিরেক্টরি, DB, প্রোভাইডার, পোর্ট)
omniroute providers available      # সমর্থিত প্রোভাইডারগুলোর তালিকা দেখান
omniroute providers list           # কনফিগার করা সংযোগগুলোর তালিকা দেখান
omniroute providers test <id>      # কোনো প্রোভাইডার সংযোগের লাইভ পরীক্ষা করুন
omniroute combos list              # কম্বোগুলোর তালিকা দেখান
omniroute combos switch <name>     # ডিফল্ট কম্বো নির্ধারণ করুন
omniroute models                   # উপলভ্য মডেলগুলোর তালিকা দেখান (--json, --search)
omniroute keys add | list | remove # টার্মিনাল থেকে API কী পরিচালনা করুন
omniroute backup                   # কনফিগারেশন + DB-এর স্ন্যাপশট নিন
omniroute restore [<timestamp>]    # একটি স্ন্যাপশট থেকে পুনরুদ্ধার করুন
omniroute health                   # বিস্তারিত স্বাস্থ্যতথ্য (ব্রেকার, ক্যাশ, মেমরি)
omniroute quota                    # প্রোভাইডারের কোটা ব্যবহার
omniroute mcp status               # MCP সার্ভারের অবস্থা
omniroute a2a status               # A2A সার্ভারের অবস্থা
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok টানেল
omniroute reset-password           # অ্যাডমিন পাসওয়ার্ড রিসেট করুন
omniroute --mcp                    # stdio-এর মাধ্যমে MCP সার্ভার চালু করুন
omniroute --port 3000              # কাস্টম পোর্টে সার্ভার চালু করুন
```

পরামর্শ: অস্বাস্থ্যকর প্রোভাইডার সংযোগ সম্পর্কে সতর্কতা পেতে আপনার মনিটরিং টুলের সঙ্গে `omniroute doctor --json` ব্যবহার করুন।

## 🖥️ ডেস্কটপ অ্যাপ্লিকেশন (Electron)

OmniRoute Windows, macOS এবং Linux-এর জন্য একটি নেটিভ ডেস্কটপ অ্যাপ্লিকেশন হিসেবে উপলভ্য।

### ইনস্টলেশন

```bash
# electron ডিরেক্টরি থেকে:
cd electron
npm install

# ডেভেলপমেন্ট মোড (চলমান Next.js ডেভ সার্ভারের সঙ্গে সংযোগ করে):
npm run dev

# প্রোডাকশন মোড (স্ট্যান্ডঅ্যালোন বিল্ড ব্যবহার করে):
npm start
```

### ইনস্টলার তৈরি

```bash
cd electron
npm run build          # বর্তমান প্ল্যাটফর্ম
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg universal)
npm run build:linux    # Linux (.AppImage)
```

আউটপুট → `electron/dist-electron/`

### প্রধান বৈশিষ্ট্য

| বৈশিষ্ট্য                   | বিবরণ                                                                             |
| --------------------------- | --------------------------------------------------------------------------------- |
| **সার্ভারের প্রস্তুতি**     | উইন্ডো দেখানোর আগে সার্ভার পোল করে (ফাঁকা স্ক্রিন নয়)                            |
| **সিস্টেম ট্রে**            | ট্রেতে মিনিমাইজ করুন, পোর্ট পরিবর্তন করুন, ট্রে মেনু থেকে প্রস্থান করুন           |
| **পোর্ট ব্যবস্থাপনা**       | ট্রে থেকে সার্ভার পোর্ট পরিবর্তন করুন (সার্ভার স্বয়ংক্রিয়ভাবে পুনরায় চালু হয়) |
| **কনটেন্ট সিকিউরিটি পলিসি** | সেশন হেডারের মাধ্যমে সীমাবদ্ধ CSP                                                 |
| **একক ইনস্ট্যান্স**         | একবারে অ্যাপের কেবল একটি ইনস্ট্যান্স চলতে পারে                                    |
| **অফলাইন মোড**              | বান্ডেল করা Next.js সার্ভার ইন্টারনেট ছাড়াই কাজ করে                              |
