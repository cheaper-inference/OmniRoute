## জিরো-কনফিগ অটো-রাউটিং (`auto/` উপসর্গ)

কোন কম্বো তৈরির প্রয়োজন নেই। সরাসরি আপনার ক্লায়েন্টে `auto` বা একটি `auto/` ভেরিয়েন্ট ব্যবহার করুন।

### দ্রুত উদাহরণ

| মডেল ID             | আচরণ                                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | যোগ্য প্রদানকারী মডেল, LKGP কৌশল এবং সুষম ওজন                                                                                                     |
| `auto/coding`       | কোডিং কাজের জন্য গুণমান-প্রথম ওজন                                                                                                                 |
| `auto/fast`         | কম বিলম্বিতা এবং স্বাস্থ্যকর প্রদানকারীদের পক্ষে                                                                                                  |
| `auto/cheap`        | খরচ-সংরক্ষণকারী ওজন: কম ক্যাটালগ দামের পক্ষে; LKGP আঠালো রাখে, একটি কঠোর সস্তা-প্রথম সাজানোর নয়                                                  |
| `auto/subscription` | শুধুমাত্র পরিকল্পনা-অন্তর্ভুক্ত কোটা, যাচাইকৃত লাইভ; একটি খালি পুল HTTP 503 ফেরত দেয়, কখনও বিল করা ফলব্যাক নয়                                   |
| `auto/thrifty`      | সাবস্ক্রিপশন → চাবিহীন → বিনামূল্যে → সস্তা → প্রিমিয়াম, একবারে এক দফা; বিল করতে পারেন                                                           |
| `auto/offline`      | কোটা প্রাপ্যতা এবং প্রদানকারী স্বাস্থ্যের পক্ষে (`offline-friendly` প্যাক); অফলাইন অনুমান নয় — অনুরোধগুলি এখনও দূরবর্তী প্রদানকারীদের কাছে যায়৷ |
| `auto/smart`        | 10% এক্সপ্লোরেশন রেট সহ গুণমান-প্রথম ওজন                                                                                                          |
| `auto/lkgp`         | স্পষ্ট LKGP, ডিফল্ট `auto` মতো একই ওজন সহ                                                                                                         |
| `auto/chaos`        | প্রতি প্রদানকারী প্রতি একটি মডেল সহ সমান্তরাল প্যানেল, ডিফল্টরূপে পাঁচটি পর্যন্ত, একটি উত্তর প্রদান করে৷                                          |

ওজন ভেরিয়েন্টগুলি LKGP আঠালোতা বজায় রাখে, তাই প্রতিটি অনুরোধে সর্বনিম্ন বিলম্ব বা মূল্যের গ্যারান্টি দেওয়ার পরিবর্তে `fast` এবং `cheap` অভিরুচি প্রকাশ করে। `auto/chaos` একাধিক আপস্ট্রিম কল করে। `auto/thrifty` অর্থপ্রদানের ক্ষমতা ব্যবহার করতে পারে; পরিকল্পনা কোটায় ফিরে আসা পুনর্নবীকরণের যোগ্যতা এবং সংযোগ কুলডাউনের উপর নির্ভর করে, শুধুমাত্র রিসেট সময় নয়। [সাবস্ক্রিপশন-প্রথম রাউটিং](./SUBSCRIPTION_LADDER.md) দেখুন।

### বিভাগ × স্তর রচনা (`auto/<category>:<tier>`)

OpenRouter-শৈলী প্রত্যয় আলাদা** কি ধরনের রুট** (বিভাগ) থেকে** কিভাবে এটি অপ্টিমাইজ করা যায়** (স্তর), তাই আপনি সেগুলি অবাধে রচনা করতে পারেন (#4235 ফেজ বি, `open-sse/services/autoCombo/suffixComposition.ts`):

- **ক্যাটাগরি** : `coding` · `reasoning` · `vision` · `chat` · `multimodal`. `vision`/`multimodal` দৃষ্টি-সক্ষম মডেল রাখুন; `reasoning` reasoning/thinking মডেল রাখে। `coding` এবং `chat` একটি সক্ষমতা ফিল্টার যোগ করে না। নন-চ্যাট বিভাগগুলি যেকোনো স্তর ওভাররাইড করার আগে গুণমান-প্রথম ওজন নির্বাচন করে।
- **স্তর** (স্কোরিং ওজন / পুল ফিল্টার চয়ন করুন): `fast` (জাহাজ-দ্রুত) · `cheap` (ওরফে `floor`, খরচ-সংরক্ষণকারী) · `reliable` (সার্কিট-ব্রেকার স্বাস্থ্য + লেটেন্সি স্থিতিশীলতা) · `free` / `pro` ( — v. `classifyTier` এর মাধ্যমে মডেল স্তর দ্বারা পুল ফিল্টার করুন)। `subscription` এবং `thrifty` সংযোগ-ভিত্তিক [সাবস্ক্রিপশন](./SUBSCRIPTION_LADDER.md) মই প্রয়োগ করে।

| উদাহরণ                 | সমাধান করে                                                |
| ---------------------- | --------------------------------------------------------- |
| `auto/coding:fast`     | যোগ্য পুল, কম বিলম্বিত ওজন                                |
| `auto/coding:cheap`    | যোগ্য পুল, খরচ-সংরক্ষণকারী ওজন (ওরফে `auto/coding:floor`) |
| `auto/reasoning:pro`   | শুধুমাত্র reasoning/thinking মডেল, প্রিমিয়াম স্তর        |
| `auto/vision`          | মানের-প্রথম ওজন সহ দৃষ্টি-সক্ষম মডেল                      |
| `auto/multimodal:free` | মাল্টিমডাল-সক্ষম মডেল, শুধুমাত্র বিনামূল্যের স্তর         |

যেকোনো বৈধ `auto/<category>[:<tier>]` চাহিদা অনুযায়ী সমাধান করে; একটি কিউরেটেড উপসেট `/v1/models` এবং ড্যাশবোর্ডে বিজ্ঞাপন দেওয়া হয় ( `open-sse/services/autoCombo/builtinCatalog.ts` তে`AUTO_SUFFIX_VARIANTS` )। Category/tier ফিল্টারিং হয়** ডিফল্টরূপে ব্যর্থ-বন্ধ** : যদি কোনো যোগ্য মডেল মেলে না, ভার্চুয়াল কম্বোতে একটি খালি পুল থাকে এবং চ্যাট সমাধানকারী HTTP 503 (`src/sse/handlers/chatHelpers.ts`) প্রদান করে। ফিল্টারটি `open-sse/services/autoCombo/virtualFactory.ts` তে `narrowPoolByCategoryTier` হয়।

`OMNIROUTE_AUTO_FREE_FALLBACK_TO_FULL_POOL=true` লিগ্যাসি category/tier ফলব্যাককে সম্পূর্ণ পুলে পুনরুদ্ধার করে যখন ফিল্টার কিছুই মেলে না; এটি অনুরোধ করা স্তর বা ক্ষমতা সীমাবদ্ধতা বাতিল করতে পারে। মডেল-ফ্যামিলি ফিল্টার কখনই সেই ফলব্যাক ব্যবহার করে না এবং শুধুমাত্র সাবস্ক্রিপশন রাউটিং এর জন্য এখনও যাচাইকৃত প্ল্যান-অন্তর্ভুক্ত ক্ষমতা প্রয়োজন।

> **লাইভ মডেল বুদ্ধিমত্তা:** অটো-রাউটিং ফিটনেস লাইভ দ্বারা অবহিত করা হয়** এরিনা ELO** র্যাঙ্কিং +** models.dev** `ARENA_ELO_SYNC_ENABLED` পতাকা চালু থাকলে স্তরের ডেটা (অন্যথায় স্ট্যাটিক ফিটনেস মানচিত্রে ফিরে আসে)।

**কিভাবে ব্যবহার করবেন:**

```bash
# Any IDE or CLI tool that supports OpenAI format
Base URL: http://localhost:20128/v1
API Key:  <your-endpoint-key>

# In your code/config, set model to:
model: "auto"                 # balanced default
model: "auto/coding"          # favor coding task fit
model: "auto/fast"            # favor lower latency
model: "auto/cheap"           # favor lower catalog cost
```

**কি হয়:**

1. OmniRoute `src/sse/handlers/chat.ts` এ `auto/` উপসর্গ সনাক্ত করে
2. সব জিজ্ঞাসা** সক্রিয় প্রদানকারী সংযোগ** ডাটাবেস থেকে
3. শংসাপত্র, মডেল-দৃশ্যমানতা এবং যোগ্যতা ফিল্টার প্রয়োগ করে
4. প্রেরণের জন্য যোগ্য অ্যাকাউন্ট অনুমোদিত তালিকা রেখে উপলব্ধ মডেলগুলি থেকে যৌক্তিক provider/model প্রার্থী তৈরি করে
5. নির্মাণ করে a** ভার্চুয়াল কম্বো** ইন-মেমরি ( DB তে সংরক্ষিত নয়)
6. নির্বাচিত ভেরিয়েন্টের ওজন প্রোফাইল + LKGP কৌশল ব্যবহার করে রুট

**মূল বৈশিষ্ট্য:**

- ✅** সর্বদা চালু:** কোন টগল, কোন কম্বো তৈরি, কোন কনফিগারেশন প্রয়োজন নেই
- ✅** গতিশীল:** স্বয়ংক্রিয়ভাবে বর্তমান সংযুক্ত প্রদানকারীদের প্রতিফলিত করে
- ✅** সেশনের আঠালোতা:** LKGP নিশ্চিত করে যে শেষ সফল প্রদানকারীকে অগ্রাধিকার দেওয়া হয়েছে
- ✅** মাল্টি-অ্যাকাউন্ট সচেতন:** যৌক্তিক provider/model প্রার্থীরা যোগ্য অ্যাকাউন্ট অনুমোদিত তালিকা ধরে রাখে
- ✅** কোন সংরক্ষিত কম্বো প্রয়োজন নেই:** ভার্চুয়াল কনফিগারেশন মেমরিতে থাকে; স্বাভাবিক রাউটিং মেট্রিক্স এবং রানটাইম অবস্থা এখনও টিকে থাকতে পারে

### প্রতি-কী প্রার্থী নিয়ন্ত্রণ (#7819, লেভেল 1 + 2)

`GET /v1/auto-combo/{channel}/candidates` (`{channel}` `auto/` পরে = প্রত্যয় বা বেস চ্যানেলের আক্ষরিক `auto` ) হল একটি** শুধুমাত্র পঠনযোগ্য** এন্ডপয়েন্ট যা একটি `auto/*` চ্যানেলের বর্তমান প্রার্থীর পুলকে তালিকাভুক্ত করে যা লাইভ পৌছানোর ক্ষমতা দিয়ে সজ্জিত, বিদ্যমান স্থিতিস্থাপকতা রিডগুলিকে পুনরায় ব্যবহার করে (কখনও কাঁচা ব্রেকার `state` নয়):

- প্রদানকারী সার্কিট ব্রেকার — `getCircuitBreaker(provider).getStatus()` / `.canExecute()`
- সংযোগ কুলডাউন — `rateLimitedUntil` / `testStatus` সমাধান করা `provider_connections` সারিতে
- মডেল লকআউট — `isModelLocked(provider, connectionId, model)`

Each candidate also carries this API key's `excluded` flag. Exclusions are stored per-API-key (`auto_candidate_overrides` table, migration `128`) — OmniRoute is single-tenant with no `users` table, so `apiKeyId` is the closest real per-caller identity — and enforced at the candidate-pool chokepoint in `open-sse/services/autoCombo/virtualFactory.ts` via the pure, unit-tested `filterExcludedCandidates()` (`open-sse/services/autoCombo/candidateOverrides.ts`). The filter is **fail-open**: an unset apiKeyId/channel or a DB lookup failure both leave the pool unfiltered, so an operator with no overrides configured sees routing byte-identical to before this feature.

**একটি ফলো-আপ সমস্যা স্থগিত:** প্রতি-প্রার্থীর ওজন + সুস্পষ্ট অর্ডারিং (লেভেল 3 — বিদ্যমান weighted/priority কৌশল পাথগুলিতে ফিড করে) এবং `auto/*` চ্যানেল প্রতি একটি নির্দিষ্ট `combo.ts` কৌশল পিন করা (লেভেল 4)। ওভাররাইডগুলি প্রতি-API-কী থাকা উচিত নাকি একক-ভাড়াটে মডেলের ভিত্তিতে বিশ্বব্যাপী হওয়া উচিত সে সম্পর্কে খোলা প্রশ্নের জন্য #7819 পরিকল্পনাটি দেখুন।

**পর্দার আড়ালে:**

```txt
Request: { model: "auto/coding" }
   ↓
src/sse/handlers/chat.ts detects prefix
   ↓
createVirtualAutoCombo('coding') → candidatePool from active connections
   ↓
handleComboChat (same engine as persisted combos)
   ↓
Auto-scoring selects best provider/model per request
```

**বাস্তবায়ন ফাইল:**

| ফাইল                                                      | উদ্দেশ্য                                      |
| --------------------------------------------------------- | --------------------------------------------- |
| `open-sse/services/autoCombo/autoPrefix.ts`               | উপসর্গ পার্সার (`parseAutoPrefix`)            |
| `open-sse/services/autoCombo/virtualFactory.ts`           | ভার্চুয়াল `AutoComboConfig` অবজেক্ট তৈরি করে |
| `open-sse/services/autoCombo/providerRegistryAccessor.ts` | উপহাস প্রদানকারী রেজিস্ট্রি জন্য পরীক্ষা হুক  |

## সংরক্ষিত অটো কম্বোগুলির জন্য অ্যাকাউন্ট পছন্দগুলি৷

ইন্টেলিজেন্ট অটো এডিটর একটি ঐচ্ছিক অফার করে** অ্যাকাউন্ট পছন্দ** বিভাগ প্রতিটি সংযোগ পছন্দের, সাধারণ (ডিফল্ট), রিজার্ভ বা বাদ দেওয়া যেতে পারে। একাধিক সংযোগ একটি স্তর ভাগ করতে পারে। অটো প্রথম যোগ্য স্তরের মধ্যে নির্বাচন করে, সেখানে তার scoring/router আচরণ বজায় রাখে; ব্যর্থ প্রচেষ্টা অবশিষ্ট কংক্রিট অ্যাকাউন্টের মাধ্যমে পড়ে, রিজার্ভের আগে স্বাভাবিকের আগে পছন্দ করা হয়। বাদ দেওয়া সংযোগ এই কম্বো দ্বারা ব্যবহার করা হয় না.

সেটিংটি `config.accountPreferences` হিসাবে সংরক্ষণ করা হয়, সংযোগ ID দ্বারা কী করা হয়:

```json
{
  "accountPreferences": {
    "connection-a": "preferred",
    "connection-b": "preferred",
    "connection-c": "reserve",
    "connection-d": "excluded"
  }
}
```

একটি বাদ দেওয়া বা খালি মানচিত্র বিদ্যমান রাউটিং ধরে রাখে। পছন্দগুলি অক্ষম সংযোগগুলি সক্ষম করে না, API-কী অ্যাক্সেস দেয়, কোটা-অবরুদ্ধ প্রার্থীদের পুনরুদ্ধার করে, বা বাজেট চেকগুলিকে বাইপাস করে না৷ প্রতিটি প্রচেষ্টা তার কংক্রিট সংযোগে সীমাবদ্ধ, তাই অ্যাকাউন্ট ফলব্যাক কম্বো রাউটারের পিছনে স্তরে যেতে পারে না। বিদ্যমান সেশন অ্যাফিনিটি একটি যোগ্য অ্যাকাউন্ট ধরে রাখতে পারে; একটি নেটিভ টার্নের সাথে আবদ্ধ অ্যাকাউন্টটি বাদ দিলে নীরবে অ্যাকাউন্ট পরিবর্তন করার পরিবর্তে সেই মোড় বন্ধ হয়ে যায়।

কনফিগার করা পছন্দগুলি অ্যাকাউন্ট-সচেতন স্বয়ংক্রিয় পথ ব্যবহার করে: আনবাউন্ড প্রসঙ্গ-ক্যাশে, স্মার্ট-পাইপলাইন, বিশৃঙ্খলা এবং ছায়া শর্টকাটগুলি প্রেরণ করা হয় না। এই অনুরোধগুলির জন্য অনুমানমূলক হেজিং অক্ষম করা হয়েছে তাই রিজার্ভ অ্যাকাউন্টগুলি পছন্দেরগুলির সাথে প্রতিযোগিতা করতে পারে না। অন্যান্য কম্বো কৌশল এই সেটিং ব্যাখ্যা করে না। অটো থেকে দূরে একটি কম্বো পরিবর্তন করা পরবর্তীতে ফিরে যাওয়ার জন্য সংরক্ষিত পছন্দগুলিকে রাখে৷

## কম্বো নাম যা একটি বাস্তব মডেল আইডির সাথে মেলে

একটি কম্বো যার `name` একটি বেয়ার মডেল আইডির (যেমন `gpt-5.5` নামে একটি কম্বো) একটি** ইচ্ছাকৃত, সমর্থিত প্যাটার্ন** , একটি বাগ নয়: এটি [#6940](https://github.com/cheaper-inference/OmniRoute/issues/6940) তে নথিভুক্ত প্রতি-মডেল-আইডি প্রদানকারীর ফলব্যাকের প্রক্রিয়া। যেহেতু বেয়ার-মডেল-আইডি রেজোলিউশনের আগে কম্বো রেজোলিউশন চেক করা হয় ( `src/sse/services/model.ts` তে`getComboForModel()` ), বেয়ার আইডি `gpt-5.5` জন্য একটি অনুরোধ কম্বোর লক্ষ্যগুলির (যেমন `acme-responses/gpt-5.5`, `backup-responses/gpt-5.5`) মাধ্যমে সরাসরি একটি একক প্রদানকারী — এর পরিবর্তে রুট করা হয়, এটি [#3227-পূর্বে-#3233 জন্য পুনরায় ব্যবহার করে এবং পূর্বে তৈরি করা হয়।](https://github.com/cheaper-inference/OmniRoute/issues/3227) `tests/unit/responses-combo-resolution-3227.test.ts` এবং `tests/unit/combo-name-codex-responses-rewrite.test.ts`।

একটি কম্বো তৈরি করা বা এমন একটি নাম পরিবর্তন করা যা একটি আসল মডেল আইডিকে ছায়া দেয়৷** কখনো প্রত্যাখ্যান করেননি** — তা করলে এই নথিভুক্ত কর্মপ্রবাহ ভেঙ্গে যাবে। পরিবর্তে (#8530), `POST /api/combos` এবং `PUT /api/combos/[id]` প্রতিক্রিয়ার সাথে একটি নন-ব্লকিং `warning` ক্ষেত্র সংযুক্ত করে যখন (নতুন) নামটি একটি বাস্তব মডেল আইডির সাথে সংঘর্ষ হয়:

```json
{ "warning": { "code": "COMBO_NAME_SHADOWS_MODEL", "modelId": "gpt-5.5", "providerId": "openai" } }
```

বুট করার সময়, `scanComboModelNameCollisionsAtBoot()` (`src/instrumentation-node.ts`) একটি এক-লাইন `[STARTUP]` সতর্কবাণীও লগ করে যা একটি মডেল আইডি ছায়া করে এমন প্রতিটি বিদ্যমান কম্বোকে গণনা করে, তাই অপারেটররা যারা দুর্ঘটনাক্রমে এটিকে আঘাত করে (অবশ্যই, প্রতি #6940 এর পরিবর্তে) একটি সংকেত রয়েছে। সনাক্তকারী সাহায্যকারী `src/lib/combos/modelNameCollision.ts` তে থাকেন।

## একটি ক্লায়েন্ট থেকে একটি কাস্টম কম্বো কল করা

স্থায়ী কম্বো (সেটিংস → কম্বো) শুধুমাত্র তখনই ব্যবহৃত হয় যখন ক্লায়েন্ট কম্বো পাঠায়** সঠিক নাম** `model` ক্ষেত্রের — এ কম্বো নামের কোনো অস্পষ্ট বা আংশিক মিল নেই, এবং `auto/` উপসর্গ জড়িত নেই। রেজোলিউশন অর্ডার (`getComboForModel()` in `src/sse/services/model.ts`):

1. সঠিক কম্বো-নাম মিল (`model: "my-combo"`),
2. `combo/<name>` উপসর্গ (`model: "combo/my-combo"`),
3. মডেল → কম্বো গ্লোব ম্যাপিং (`/api/model-combo-mappings`)।

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"my-combo","messages":[{"role":"user","content":"Hello"}]}'
```

দুটি সাধারণ ক্ষতি:

- **`auto` আপনার কম্বোস ব্যবহার করে না।** `auto`/`auto/*` তার নিজস্ব শূন্য-কনফিগ প্রার্থী পুল তৈরি করে এবং শুধুমাত্র স্থায়ী কম্বোগুলির সাথে পরামর্শ করে যদি একটি কম্বোকে আক্ষরিক অর্থে `auto` (প্রস্তাবিত নয়) নাম দেওয়া হয়। একটি কম্বোর মাধ্যমে রুট করতে, এর সঠিক নাম — পাঠান `auto` নয়।
- **`openrouter/auto` একটি প্রকৃত অর্থপ্রদত্ত OpenRouter পণ্য** ("স্বয়ংক্রিয়ভাবে সেরা উপলব্ধ"), একটি OmniRoute উপনাম নয়৷ এটি OpenRouter রেজিস্ট্রির একক স্ট্যাটিক মডেল এন্ট্রি (`open-sse/config/providers/registry/openrouter/index.ts`) এবং আলাদাভাবে বিল করা হয়। সেটিংস ব্যবহার করুন → রাউটিং → লুকান প্রদত্ত মডেলগুলিকে `auto` পুল থেকে বাদ দিতে।

এই নথির মূল বিভ্রান্তির জন্য [#7992](https://github.com/cheaper-inference/OmniRoute/issues/7992) এবং [#7111](https://github.com/cheaper-inference/OmniRoute/issues/7111) দেখুন।

## এটি কীভাবে কাজ করে (স্থির অটো-কম্বোস)

অটো-কম্বো ইঞ্জিন গতিশীলভাবে provider/model প্রার্থীদের ব্যবহার করে স্কোর করে** 16টি ঘোষিত ফ্যাক্টর** ( `open-sse/services/autoCombo/scoring.ts` → `DEFAULT_WEIGHTS` তে সংজ্ঞায়িত)। ডিফল্ট ওজনের যোগফল `1.0`; কাস্টম ওজন `normalizeScoringWeights()` দ্বারা পুনর্নবীকরণ করা হয়। তিনটি কারণের ডিফল্টভাবে শূন্য ওজন থাকে: `cacheAffinity`, `resetWindowAffinity` এবং `reliability`। মোড প্যাকগুলি `reliability` কে `0.03`, বা `reliability-first` এ `0.04` দেয়; `quality` ডিফল্টরূপে `0.03` বহন করে এবং `quality-first` এ এবং অন্যান্য প্যাকে `0.02` করে। `cacheAffinity` এছাড়াও ওয়েটেড স্কোরের বাইরে প্রম্পট-ক্যাশ ডিডপ্লিকেশন গেট করে।

| `X-OmniRoute-Effort`          | `auto` (অন্যান্য মান সংরক্ষিত)                                                                                                                                                                        | অভিযোজিত চিন্তার বাজেট: যখন অনুরোধে কোনো ধরনের reasoning ফিল্ড (`reasoning_effort`, `reasoning`, `thinking`) থাকে না, তখন গেটওয়ে নির্ধারক request-shape সংকেতের ভিত্তিতে `auto`-কে `low`/`medium`/`high` হিসেবে নির্ধারণ করে (সর্বশেষ ব্যবহারকারী-বার্তার দৈর্ঘ্য, সর্বশেষ ব্যবহারকারী বার্তা পর্যন্ত কনটেক্সটের আকার, পূর্ববর্তী টুলের ফলাফল, টুল-লুপের গভীরতা)। সংকেতগুলো বর্তমান টার্নের মধ্যে সীমাবদ্ধ — সর্বশেষ ব্যবহারকারী বার্তার পরের সবকিছু উপেক্ষা করা হয় — তাই একটি টুল লুপের প্রতিটি অনুরোধ একই স্তরে নির্ধারিত হয় (প্রতি-টার্নে স্টেটলেস পিন, কোনো সেশন স্টেট নেই, লুপের মাঝখানে এমন কোনো বৃদ্ধি নেই যা আপস্ট্রিম প্রম্পট-ক্যাশ প্রিফিক্স ভেঙে দেবে)। ক্লায়েন্টের স্পষ্ট reasoning ফিল্ড সবসময় অগ্রাধিকার পায়। এটি সেই সব অনুরোধের মধ্যে সীমাবদ্ধ, যেগুলোর আপস্ট্রিম ডিসপ্যাচ OpenAI Chat Completions আকৃতিতে নির্ধারিত হয় (`targetFormat === FORMATS.OPENAI`) — `reasoning_effort` একটি OpenAI-আকৃতির ফিল্ড, তাই Claude- বা Gemini-লক্ষ্যযুক্ত অনুরোধে হেডারটি কোনো কার্যকরী পরিবর্তন আনে না (`open-sse/handlers/chatCore/adaptiveEffortWiring.ts` দেখুন)। |

```bash
# দ্রুততম প্রোফাইল বাধ্যতামূলক করুন, এই অনুরোধের সীমা $0.05 নির্ধারণ করুন এবং অতিরিক্ত ব্যয়ের পরিবর্তে কঠোরভাবে ব্লক করুন
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "X-OmniRoute-Mode: fast" \
  -H "X-OmniRoute-Budget: 0.05" \
  -H "X-OmniRoute-Budget-Fallback: strict" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hi"}]}'
```

রেজোলিউশনটি একটি বিশুদ্ধ ফাংশন (`open-sse/services/autoCombo/requestControls.ts`); নির্ধারিত
মানগুলো ইঞ্জিনের বিদ্যমান `config.modePack` / `config.budgetCap` /
`config.budgetFallback` ইনপুটে পাঠানো হয়। কোনো কম্বোর সংরক্ষিত `config.budgetFallback` ("strict" |
"cheapest") স্থায়ী নীতি নির্ধারণ করে; হেডারটি একটি একক অনুরোধের জন্য সেটি ওভাররাইড করে।

## সমস্ত রাউটিং কৌশল

### `weighted` শব্দার্থবিদ্যা

`weighted` হল a** অনুরোধ প্রতি আনুপাতিক র্যান্ডম ড্র** (`open-sse/services/combo/targetSorters.ts` → `selectWeightedTarget`), একটি সমানকারী নয়:

- প্রতিটি অনুরোধ আঁকা** এক** সম্ভাব্যতা `weight / totalWeight` সহ পদক্ষেপ; অবশিষ্ট ধাপগুলি সেই অনুরোধের জন্য ফলব্যাক চেইন হিসাবে ওজন কমানোর দ্বারা আদেশ করা হয়।
- একটি ধাপ যার ওজন `0` (বা অনুপস্থিত) হয়** কখনও আঁকা না** অন্য কোনো ধাপের ওজন > 0 — থাকলেও এটি আঁকা পদক্ষেপটি ব্যর্থ হওয়ার পরেই ফলব্যাক হিসেবে কাজ করতে পারে। শুধুমাত্র যখন** সব** ওজন 0 হয় নির্বাচন কি অভিন্ন হয়ে যায়।
- যে পদক্ষেপগুলির লক্ষ্যগুলি সমস্ত অনুপলব্ধ — প্রদানকারী সার্কিট ব্রেকার `OPEN`, সংযোগ কুলডাউন, মডেল লকআউট — ঘটার আগেই ড্র থেকে সরানো হয় (`open-sse/services/combo/targetResolution.ts`), তাই একটি একক সুস্থ পদক্ষেপ সাময়িকভাবে প্রতিটি অনুরোধ জয় করতে পারে৷
- `stickyWeightedLimit` (কম্বো কনফিগারেশন, ডিফল্ট `1` = বন্ধ) পুনরায় অঙ্কনের আগে অনেকগুলো ধারাবাহিক সাফল্যের জন্য টানা ধাপটিকে পিন করে।

কঠোর ঘূর্ণনের জন্য `round-robin` ব্যবহার করুন; `weighted` এ সমান ওজন পরিসংখ্যানগত — দেয় না কঠোর — ব্যালেন্স।

### এজেন্টিক পাইপলাইন মোড

কমপক্ষে দুটি মডেল সহ একটি `pipeline` কম্বো `config.agenticOrchestration.enabled` এর সাথে planner/executor রাউটিং বেছে নিতে পারে। প্রথম লক্ষ্য পরিকল্পনা এবং চূড়ান্ত উত্তরের মালিক; দ্বিতীয় লক্ষ্য ক্লায়েন্ট-নেটিভ টুল কল নির্গত করে। OmniRoute অনুরোধ প্রোটোকল থেকে টুল-ফলাফলের ধারাবাহিকতা সনাক্ত করে, পরিকল্পনাকারীকে জিজ্ঞাসা করে যে অন্য একটি টুল রাউন্ড প্রয়োজন কিনা, এবং গতিশীলভাবে নির্বাহক বা পরিকল্পনাকারীকে ক্লায়েন্ট-মুখী চূড়ান্ত ধাপে পরিণত করে।

ঐচ্ছিক `config.agenticOrchestration.contextCompaction` প্রতিটি পরিকল্পনাকারী বা নির্বাহক প্রেরণের আগে একটি পৃথক পেলোড বাজেট প্রয়োগ করে। এটি স্পষ্টভাবে সক্ষম করুন:

```json
{
  "enabled": true,
  "defaultMaxChars": 400000,
  "targetRatio": 0.72,
  "toolResultMaxChars": 24000,
  "modelMaxChars": { "provider/planner": 175000, "provider/executor": 300000 }
}
```

এগুলি অপারেটর দ্বারা নির্বাচিত ক্রমিক JSON অক্ষর বাজেট, টোকেন প্রসঙ্গ উইন্ডো বা গ্যারান্টিযুক্ত আপস্ট্রিম সীমা নয়। সঠিক মডেল IDs ডিফল্ট ওভাররাইড করে। থ্রেশহোল্ডের উপরে, কমপ্যাকশন অভিন্ন টুলের সংজ্ঞাগুলিকে সরিয়ে দেয়, একটি ডাইজেস্টের সাহায্যে বড় আকারের টুলের প্রমাণগুলিকে ছাঁটাই করে এবং লক্ষ্য অনুপাতের দিকে পুরানো সম্পূর্ণ ইতিহাস গোষ্ঠীগুলিকে সরিয়ে দেয়। এটি system/developer নির্দেশাবলী, সর্বশেষ ব্যবহারকারীর অনুরোধ, সমান্তরাল calls/results সহ শেষ টুল রাউন্ড এবং Gemini এর অগ্রণী রাউটিং নির্দেশনা বজায় রাখে। শীর্ষ-স্তরের নির্দেশাবলী এবং টুল সেটিংস সংরক্ষণ করা হয়। একটি বাদ চিহ্নিতকারী ইতিহাস অপসারণ রেকর্ড; এটি একটি নির্ধারক ছাঁটাই, একটি শব্দার্থিক সারাংশ নয়। যদি পিন করা প্রসঙ্গ এখনও বাজেটের চেয়ে বেশি হয়, তাহলে মডেলের সাথে যোগাযোগ করার আগে অনুরোধটি 413 ফেরত দেয়। কমপ্যাকশন নিষ্ক্রিয় বা থ্রেশহোল্ডের নীচে অনুরোধটি অপরিবর্তিত হয়ে যায়।

টুল-ফলাফলের ধারাবাহিকতায়, OmniRoute কার্যকর করা বন্ধ করে দেয় যখন পরপর দুটি সম্পূর্ণ রাউন্ড অপরিবর্তিত ফলাফল সহ একই টুল কলের পুনরাবৃত্তি করে, অথবা যখন পরপর দুটি রাউন্ডে প্রতিটি স্পষ্টভাবে চিহ্নিত ফলাফল ব্যর্থ হয়। পরিবর্তিত ফলাফল বারবার কল করার অনুমতি দেয় (উদাহরণস্বরূপ, পোলিং)। একটি নতুন ব্যবহারকারীর অনুরোধে গার্ড রিসেট করে, সমান্তরাল কলগুলিকে এক রাউন্ডে গোষ্ঠী করে এবং Anthropic, চ্যাট সমাপ্তি, প্রতিক্রিয়া এবং Gemini ইতিহাস সমর্থন করে৷ পরিকল্পনাকারী কারণটি গ্রহণ করে এবং অন্য টুল রাউন্ডের অনুরোধ করলেও চূড়ান্ত উত্তরের মালিক।

দ্বিতীয় লক্ষ্যের পরে অতিরিক্ত মডেলগুলিকে নির্বাহক ব্যাকআপের আদেশ দেওয়া হয়। একটি ব্যর্থ HTTP প্রতিক্রিয়া বা পরিবহন ব্যতিক্রম পরবর্তী নির্বাহকের কাছে অগ্রসর হয়, একই পরিকল্পনাকারীর সিদ্ধান্ত এবং স্থানীয় সরঞ্জামগুলি বহন করে কিন্তু সেই নির্বাহকের নিজস্ব পদক্ষেপের প্রম্পট এবং সমাধান করা সংযোগ। প্রথম সফল প্রতিক্রিয়া SSE স্ট্রিমিং সহ অপরিবর্তিত ফেরত দেওয়া হয়; একটি সফল স্ট্রীম শুরু হওয়ার পরে ব্যর্থতা এখানে পুনরায় চেষ্টা করা যাবে না। সমস্ত নির্বাহক ব্যর্থ হলে, শেষ ব্যর্থতা ফেরত দেওয়া হয়। ক্লায়েন্ট প্রেরন বন্ধ করে দেয়।

```json
{
  "strategy": "pipeline",
  "models": [{ "model": "provider/planner" }, { "model": "provider/executor" }],
  "config": {
    "agenticOrchestration": { "enabled": true, "maxToolRounds": 8 }
  }
}
```

নির্বাহক এক প্রতিক্রিয়ায় একাধিক স্বাধীন কল নির্গত করতে পারে। নির্ভরশীল কলগুলি পরবর্তী ক্লায়েন্ট টুল-ফলাফল মোড়তে পরিচালনা করা হয়, পরিকল্পনাকারী প্রতিটি ফলাফল পর্যালোচনা করে। `maxToolRounds` `8` এ ডিফল্ট এবং `1`–`32` গ্রহণ করে; একবার পৌঁছে গেলে, পরিকল্পনাকারীকে অবশ্যই সেরা উপলব্ধ চূড়ান্ত উত্তর তৈরি করতে হবে। অভ্যন্তরীণ পরিকল্পনাকারীর সিদ্ধান্তগুলি বাফার করা হয়, যখন নির্বাচিত ক্লায়েন্ট-মুখী প্রতিক্রিয়া মূল স্ট্রিমিং পছন্দ সংরক্ষণ করে।

### `round-robin` স্টিকি ব্যাচ এবং অ্যাকাউন্ট সম্প্রসারণ

রাউন্ড-রবিন ব্যাচ করা হয়েছে, এক-অনুরোধ-প্রতি-ধাপে নয়:

- `stickyRoundRobinLimit` (কম্বো কনফিগারেশন, তারপর `comboStickyRoundRobinLimit`, তারপর `settings.stickyRoundRobinLimit`, ডিফল্ট** 3** ) ঘূর্ণন করার আগে পরপর অনেক সাফল্যের জন্য একই লক্ষ্য রাখে। ওয়ান-রিকোয়েস্ট রোটেশনের জন্য কম্বো ওভাররাইডকে `1` এ সেট করুন। কম্বো এডিটর কার্যকর মান এবং কোন স্তর থেকে এসেছে তা দেখায়।
- `connectionAwareExpansion` (কম্বো কনফিগারেশন, তারপর সেটিংস, ডিফল্ট** মিথ্যা** ) রোটেশনের আগে প্রতিটি প্রদানকারী-স্তরের ধাপ প্রতি-অ্যাকাউন্ট লক্ষ্যে প্রসারিত করে। গ্রুপ-বি কৌশলগুলি (অগ্রাধিকার, ওজনযুক্ত, রাউন্ড-রবিন, র্যান্ডম, p2c, সর্বনিম্ন-ব্যবহৃত, খরচ-অপ্টিমাইজ করা, lkgp, ফিল-ফার্স্ট, কঠোর-এলোমেলো, প্রসঙ্গ-অপ্টিমাইজ করা, ক্যাশে-অপ্টিমাইজ করা, প্রসঙ্গ-রিলে, ফিউশন, পাইপলাইন, জেভ) একটি প্রদানকারী-স্তরের ভিউ না হওয়া পর্যন্ত। কম্বো এডিটর ইনহেরিট/চালু/বন্ধ প্রকাশ করে; inherit গ্লোবাল ডিফল্ট (বন্ধ) ব্যবহার করে।
- প্রম্পট-ক্যাশে লোকেলিটি রাউটিং (`promptCacheAffinityEnabled`, ডিফল্ট** সত্য** ) পিন করা সংযোগগুলিকে পুনরায় সাজায় যাতে ক্যাশে কীগুলি একটি অ্যাকাউন্টে থাকে৷ এটি রাউন্ড-রবিন এবং পিন-প্রতি অ্যাকাউন্ট ধাপ জুড়ে ওজনযুক্ত ঘূর্ণনের চেয়ে অগ্রাধিকার নেয়। আপনার যদি কঠোর ঘূর্ণনের প্রয়োজন হয় তবে সেটিংস → কম্বো ডিফল্টের অধীনে এটি বন্ধ করুন। প্রতি-কম্বো ওভাররাইড নেই।

একটি মডেলে মাল্টি-অ্যাকাউন্ট রোটেশনের জন্য, পছন্দ করুন** একটি গতিশীল-অ্যাকাউন্ট ধাপ** (খালি `connectionId`, পুরো পুল) স্টিকি লিমিট `1` সহ, তিন পিন করা `connectionId` s নয়। RR কাউন্টার অগ্রসর হওয়ার সময়ও একই অ্যাকাউন্টে পিনড স্টেপ প্লাস অ্যাফিনিটি কমে যায়।

## ফিউশন কৌশল

`fusion` হল একটি কৌশল যা করে** না** একটি একক লক্ষ্য বাছাই করুন। এটা প্রম্পট আউট ভক্ত** সমান্তরাল প্রতিটি প্যানেল মডেল** , তারপর একটি কনফিগারযোগ্য** বিচারক মডেল** সমস্ত প্যানেল প্রতিক্রিয়া থেকে একটি একক চূড়ান্ত উত্তর সংশ্লেষিত করে। আপস্ট্রিম `decolua/9router` থেকে পোর্টেড (OpenRouter এর ফিউশন ডিজাইন); `open-sse/services/fusion.ts` এ বাস্তবায়ন।

এটি কিভাবে কাজ করে:

0. **টুল-ভারবহন বাইপাস** — একটি অনুরোধ যা `tool_choice` সহ একটি অ-খালি `tools` অ্যারে বহন করে যা স্পষ্টভাবে `"none"` প্যানেলটিকে সম্পূর্ণভাবে এড়িয়ে যায়: এটি সরাসরি একটি একক মডেলে (কনফিগার করা বিচারক, বা `panel[0]`) `tools`/`tool_choice` অপরিবর্তিত মাধ্যমে পাস করে। প্যানেল সদস্যদের কোন টুল অ্যাক্সেস নেই এবং বিচারকের সংশ্লেষণ নির্দেশিকা টুল-কল নির্গমনকে নিরুৎসাহিত করে, তাই agentic/tool-calling ক্লায়েন্টরা সংশ্লেষিত গদ্য (#6771) এর পরিবর্তে একটি বাস্তব টুল-কল সিদ্ধান্ত পান।
1. **ফ্যান-আউট** (শুধুমাত্র অ-টুল-বহনকারী অনুরোধ) — প্রম্পটটি একবারে প্রতিটি প্যানেল মডেলে পাঠানো হয়, সরঞ্জাম ছিনিয়ে নেওয়ার সাথে জোর করে অ-স্ট্রিমিং করা হয় (বিচারককে সংশ্লেষণের জন্য সম্পূর্ণ গদ্য প্রয়োজন)।
2. **কোরাম-অনুগ্রহ সংগ্রহ** — যত তাড়াতাড়ি `minPanel` উত্তর আসে, একটি সংক্ষিপ্ত অনুগ্রহ টাইমার স্ট্র্যাগ্লারদের জন্য শুরু হয়, তারপর যা কিছু সংগ্রহ করা হয়েছিল তা নিয়ে ফিউশন এগিয়ে যায়। এটি একটি হার্ড টাইমআউট দ্বারা আবদ্ধ, প্রাচীর সময় সবচেয়ে ধীর মডেলের জরিমানা ক্যাপ.
3. **বিচারক সংশ্লেষণ** — প্যানেলের উত্তরগুলি বেনামী (`Source 1`, `Source 2`, … — তাই বিচারক পদার্থের ওজন করেন, মডেল ব্র্যান্ড নয়) এবং বিচারকের কাছে হস্তান্তর করা হয়, যা ঐকমত্য / দ্বন্দ্ব / আংশিক কভারেজ / অনন্য অন্তর্দৃষ্টি / অন্ধ দাগগুলি বিশ্লেষণ করে, তারপর লেখে** এক** প্রামাণিক উত্তর। বিচারক কল ক্লায়েন্টের আসল `stream` ফ্ল্যাগ + টুলগুলিকে রাখে, তাই স্ট্রিমিং এবং ডাউনস্ট্রিম টুল ব্যবহার এখনও কাজ করে।
4. **করুণাময় অধঃপতন** — 0 প্যানেল → `503` উত্তর দেয়; ঠিক 1 বেঁচে থাকা → যে উত্তরটি সরাসরি ফেরত দেওয়া হয়েছে (ফিউজ করার মতো কিছুই নেই); একটি একক-মডেল প্যানেল সরাসরি উত্তর দেয়।

একটি প্যানেল সদস্য একটি `combo-ref` পদক্ষেপ (`{kind: "combo-ref", comboName: "..."}`) হতে পারে যা অন্য একটি কম্বো — উল্লেখ করে এটি সমাধান করে** একটি ব্ল্যাক-বক্স প্যানেল ভয়েস** (উল্লেখিত কম্বোতে একটি সম্পূর্ণ পুনরাবৃত্ত প্রেরণ, সেই কম্বোর নিজস্ব লক্ষ্যগুলির ফ্যান-আউট নয়), একই depth/cycle সুরক্ষার সাথে অন্য প্রতিটি কম্বো-রেফ-গ্রাহক কৌশল ইতিমধ্যেই ব্যবহার করে (#6764)।

### কনফিগারেশন

কম্বোর `config` ব্লব-এ কনফিগার করা হয়েছে (কোন স্কিমা মাইগ্রেশন — নেই এটি বিদ্যমান `combos` টেবিলটি পুনরায় ব্যবহার করে):

| মাঠ                                      | টাইপ     | ডিফল্ট             | উদ্দেশ্য                                                                     |
| :--------------------------------------- | :------- | :----------------- | :--------------------------------------------------------------------------- |
| `config.judgeModel`                      | `string` | প্রথম প্যানেল মডেল | মডেল যা চূড়ান্ত উত্তর সংশ্লেষিত করে                                         |
| `config.fusionTuning.minPanel`           | `number` | `2`                | গ্রেস টাইমার শুরু হওয়ার আগে সফল উত্তর প্রয়োজন ( `[2, panelSize]` এ আটকানো) |
| `config.fusionTuning.stragglerGraceMs`   | `number` | `8000`             | কোরাম পূর্ণ হলে পিছিয়ে থাকার জন্য কতক্ষণ অপেক্ষা করতে হবে                   |
| `config.fusionTuning.panelHardTimeoutMs` | `number` | `90000`            | সম্পূর্ণ ক্যাপ তাই একটি ঝুলন্ত মডেল অনুরোধটি আটকাতে পারে না                  |

ডিফল্টগুলি `FUSION_DEFAULTS` (`open-sse/services/fusion.ts`) তে থাকে।

## ভার্চুয়াল অটো-কম্বো ফ্যাক্টরি

Auto Combo ইঞ্জিনের জন্য আগে থেকে নির্ধারিত কম্বোর প্রয়োজন হয় না। পরিবর্তে, `open-sse/services/autoCombo/virtualFactory.ts` তাৎক্ষণিকভাবে প্রার্থী তৈরি করে:

1. `getProviderConnections({ isActive: true })` থেকে তথ্য নেয় (সক্রিয় করা সব সংযোগ)
2. বৈধ ক্রেডেনশিয়াল আছে এমন সংযোগগুলো বেছে নেয় (`hasUsableOAuthToken()`-এর মাধ্যমে API key অথবা মেয়াদোত্তীর্ণ নয় এমন OAuth token)
3. মডেলের প্রাপ্যতা + মূল্য নির্ধারণের জন্য `getProviderRegistry()`-এর সঙ্গে ক্রস-রেফারেন্স করে
4. প্রতিটি `(provider, model, connection)` টিউপলের জন্য একটি `VirtualAutoComboCandidate` তৈরি করে
5. ডিসপ্যাচ টার্গেট হিসেবে `connection.defaultModel` (অথবা রেজিস্ট্রির প্রথম মডেল) বেছে নেয়
6. ১৬-ফ্যাক্টরের `scorePool()` এবং ভ্যারিয়েন্টের ওয়েট প্যাক ব্যবহার করে প্রতিটি প্রার্থীর স্কোর নির্ধারণ করে
7. `handleComboChat()`-এর জন্য ফলস্বরূপ ইন-মেমরি `AutoComboConfig` ফেরত দেয় — কখনোই DB-তে সংরক্ষণ করে না

এর অর্থ হলো, **`auto/*` সক্রিয় থাকা নতুন কোনো provider যোগ করলে প্রার্থী পুল স্বয়ংক্রিয়ভাবে প্রসারিত হয়** — ম্যানুয়ালি কম্বো সম্পাদনার প্রয়োজন নেই। প্রতিটি অনুরোধের জন্য ভার্চুয়াল কম্বো পুনর্নির্মাণ করা হয়, তাই নতুন যোগ করা বা সদ্য সুস্থ হয়ে ওঠা সংযোগগুলো তাৎক্ষণিকভাবে অন্তর্ভুক্ত হয়।

## স্বয়ংক্রিয় পুনরুদ্ধার

- **সাময়িকভাবে বাদ দেওয়া**: স্কোর < 0.2 → ৫ মিনিটের জন্য বাদ (ক্রমবর্ধমান ব্যাকঅফ, সর্বোচ্চ ৩০ মিনিট)
- **সার্কিট ব্রেকার সম্পর্কে সচেতনতা**: OPEN → স্বয়ংক্রিয়ভাবে বাদ; HALF_OPEN → প্রোব অনুরোধ
- **ইনসিডেন্ট মোড**: >৫০% OPEN → এক্সপ্লোরেশন বন্ধ করে স্থিতিশীলতা সর্বাধিক করে
- **কুলডাউন পুনরুদ্ধার**: বাদ দেওয়ার সময়সীমা শেষ হলে, প্রথম অনুরোধটি কমানো টাইমআউটসহ একটি "প্রোব" হিসেবে পাঠানো হয়

## ব্যান্ডিট এক্সপ্লোরেশন

এক্সপ্লোরেশনের জন্য ৫% অনুরোধ (কনফিগারযোগ্য) এলোমেলো provider-এ রাউট করা হয়। ইনসিডেন্ট মোডে এটি নিষ্ক্রিয় থাকে।

## API

আছে** কোন ডেডিকেটেড `POST /api/combos/auto` এন্ডপয়েন্ট নেই** — অটো-কম্বো দুটি উপায়ে ব্যবহার করা হয়:

1. **জিরো কনফিগারেশন (প্রস্তাবিত):** `model: "auto"` বা `model: "auto/<variant>"` সাথে যেকোনো চ্যাট সমাপ্তির অনুরোধ পাঠান। ভার্চুয়াল ফ্যাক্টরি প্রতি অনুরোধে কম্বো তৈরি করে — কোন অধ্যবসায়, কোন API কলের প্রয়োজন নেই।

2. **`strategy: "auto"` এর সাথে স্থায়ী কম্বো:** `POST /api/combos` মাধ্যমে একটি নিয়মিত কম্বো তৈরি করুন এবং `strategy: "auto"` প্লাস `config.auto.weights` / `config.auto.candidatePool` সেট করুন। একই স্কোরিং ইঞ্জিন ব্যবহার করা হয়; কম্বো `combos` এ সংরক্ষণ করা হয় এবং ID দ্বারা পুনরায় ব্যবহারযোগ্য।

আবিষ্কারের জন্য, `GET /api/combos/auto` প্রার্থী পুলের জানালা জুড়ে তার সমাধানকৃত প্রার্থী পুল প্লাস `context_length` / `max_output_tokens` — MAX সহ প্রতিটি বৈকল্পিক তালিকা করে। ক্লায়েন্টদের (যেমন ওপেনকোড প্লাগইন) অবশ্যই `0` এর পরিবর্তে এই মানগুলির বিজ্ঞাপন দিতে হবে: একটি শূন্য প্রসঙ্গ ওপেনকোডের স্বয়ংক্রিয় সংকোচন সম্পূর্ণরূপে নিষ্ক্রিয় করে, গেটওয়ের ইতিহাস পরিস্কার প্রসঙ্গ ধ্বংস না করা পর্যন্ত সেশনগুলিকে বাড়তে দেয়৷ MAX বিজ্ঞাপন দেওয়া নিরাপদ কারণ স্বয়ংক্রিয়-কম্বো কনটেক্সট প্রি-ফিল্টার রুট বড়-উইন্ডো প্রার্থীদের কাছে ওভারসাইজের অনুরোধ পাঠায়।

```bash
# Zero-config usage (no combo creation)
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Hello"}]}'

# Persisted auto combo via the regular combos endpoint
curl -X POST http://localhost:20128/api/combos \
  -H "Content-Type: application/json" \
  -d '{"id":"my-auto","name":"Auto Coder","strategy":"auto","config":{"auto":{"candidatePool":["anthropic","google","openai"],"weights":{"quota":0.15,"health":0.3,"costInv":0.05,"latencyInv":0.35,"taskFit":0.1,"stability":0,"tierPriority":0.05}}}}'
```

### অটো রাউটার কৌশল

স্থায়ী `strategy: "auto"` কম্বো `config.routerStrategy` (বা লিগ্যাসি `config.auto.routerStrategy`) এর মধ্যে একটিতে সেট করতে পারে:

- `rules` — ডিফল্ট ওজনযুক্ত স্কোরিং
- `score` — সর্বোচ্চ কনফিগার করা ওজনযুক্ত স্কোর নির্বাচন করে। সঠিক বন্ধন কনফিগার করা প্রার্থীর আদেশ সংরক্ষণ করে; পূর্ণ র্যাঙ্ক করা পুল থেকে বিদ্যমান `explorationRate` নমুনা।
- `cost` / `eco` — সস্তার স্বাস্থ্যকর প্রদানকারী
- নির্ভরযোগ্যতা শাস্তি সহ `latency` / `fast` — সর্বনিম্ন p95 বিলম্ব
- `sla-aware` / `sla` — প্রার্থীদের পছন্দ করে যারা p95 লেটেন্সি, ত্রুটি-হার এবং ঐচ্ছিক খরচ SLOs পূরণ করে
- `lkgp` — সর্বশেষ পরিচিত ভাল প্রদানকারী প্রথম
- `nadir` — [নাদিরের](https://getnadir.com) সিদ্ধান্তকে জিজ্ঞাসা করুন API পুলে কোন মডেলের প্রম্পট প্রয়োজন; অপ্ট-ইন, ফেইল-ওপেন টু `rules`
- `decision` — একটি কনফিগার করা সিদ্ধান্তকারীকে জিজ্ঞাসা করুন (TypeSafe সিস্টেম ওয়ান, আপনার নিজের সিদ্ধান্ত URL, বা কম্বোর নিজস্ব মডেলগুলির মধ্যে একটি) পুলের কোন মডেল অনুরোধের সাথে খাপ খায়; ডিফল্ট-অফ `COMBO_DECISION_ROUTER_ENABLED` পতাকার পিছনে, `rules` এ ব্যর্থ-ওপেন

### বিস্তারিত রাউটার কৌশল

স্বয়ংক্রিয়-কম্বো ইঞ্জিনটি 7টি প্লাগেবল প্রকাশ করে**RouterStrategy** আপনি `config.routerStrategy` (বা লিগ্যাসি `config.auto.routerStrategy`) এর মাধ্যমে অদলবদল করতে পারেন এমন বাস্তবায়ন। প্রতিটি কৌশল প্রার্থীর পুল থেকে একজন প্রদানকারীকে বেছে নেয়, একটি `RoutingContext` দেওয়া হয় (টাস্কের ধরন, tool/vision ইঙ্গিত, টোকেন অনুমান, ঐচ্ছিক SLA নীতি, ঐচ্ছিক শেষ-পরিচিত-ভাল প্রদানকারী)।

#### 1. `rules` (ডিফল্ট) — 16-ফ্যাক্টর ওয়েটেড স্কোরিং

বিদ্যমান স্কোরিং ইঞ্জিনকে মোড়ানো। `OPEN` সার্কিট-ব্রেকার প্রার্থীদের ফিল্টার করে, তারপর বর্তমান টাস্ক টাইপ এবং `getTaskFitness()` সহ `scorePool()` চালায়, শীর্ষ-স্কোরিং প্রদানকারীকে বেছে নেয়।

```ts
class RulesStrategyImpl implements RouterStrategy {
  readonly name = "rules";
  readonly description = "16-factor weighted scoring (see DEFAULT_WEIGHTS)";

  select(pool, context) {
    const eligible = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const ranked = scorePool(
      eligible.length > 0 ? eligible : pool,
      context.taskType,
      undefined,
      getTaskFitness
    );
    return { provider: ranked[0].provider /* ... */ };
  }
}
```

**কখন ব্যবহার করতে হবে** : ডিফল্ট। আপনি যখন সমস্ত সংকেত জুড়ে একটি সুষম ট্রেড-অফ চান তখন ব্যবহার করুন।

**উপনাম** : `rules` (কোনও উপনাম নেই)

---

#### 2. `cost` / `eco` — সস্তা স্বাস্থ্যকর প্রদানকারী

প্রার্থীর পুলকে `costPer1MTokens` (আরোহী) দ্বারা বাছাই করে এবং সবচেয়ে সস্তা বাছাই করে। প্রথমে `OPEN` প্রার্থীদের ফিল্টার করুন।

```ts
class CostStrategyImpl implements RouterStrategy {
  readonly name = "cost";
  readonly description = "Always selects cheapest available provider";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort((a, b) => a.costPer1MTokens - b.costPer1MTokens);
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**কখন ব্যবহার করতে হবে** : খরচ-সংবেদনশীল কাজের চাপ, ব্যাচ প্রক্রিয়াকরণ, বা ব্যাকগ্রাউন্ড কাজ।

**উপনাম** : `cost`, `eco`

#### 3. নির্ভরযোগ্যতা শাস্তি সহ `latency` / `fast` — সর্বনিম্ন p95 বিলম্ব

`p95LatencyMs + (errorRate * 1000)` দ্বারা সাজান। ত্রুটি-হার জরিমানা নিশ্চিত করে যে অবিশ্বস্ত প্রদানকারীদের নামমাত্র লেটেন্সি কম হলেও তাদের র্যাঙ্ক করা হয় কম।

```ts
class LatencyStrategyImpl implements RouterStrategy {
  readonly name = "latency";
  readonly description = "Prioritizes lowest p95 latency with reliability weighting";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort(
      (a, b) => a.p95LatencyMs + a.errorRate * 1000 - (b.p95LatencyMs + b.errorRate * 1000)
    );
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**কখন ব্যবহার করতে হবে** : লেটেন্সি-সংবেদনশীল কাজের চাপ যেমন রিয়েল-টাইম চ্যাট, স্বয়ংসম্পূর্ণ, বা ইন্টারেক্টিভ কোডিং সহকারী।

**উপনাম** : `latency`, `fast`

#### 4. `sla-aware` / `sla` — latency/error/cost SLO সম্মতি

কনফিগার করা SLO নীতি কতটা ভালোভাবে সন্তুষ্ট করে তার দ্বারা প্রতিটি প্রার্থীকে স্কোর করে:

| ফ্যাক্টর          | ওজন | সূত্র                                               |
| ----------------- | --- | --------------------------------------------------- |
| লেটেন্সি স্কোর    | 35% | `threshold / max(value, ε)`                         |
| ত্রুটি স্কোর      | 35% | `threshold / max(value, ε)`                         |
| স্বাস্থ্য স্কোর   | 15% | `1.0` (CLOSED) / `0.5` (HALF_OPEN) / `0.0` (OPEN)   |
| খরচ স্কোর         | 10% | `threshold / max(value, ε)` বা বিপরীত স্বাভাবিকীকৃত |
| স্থিতিশীলতা স্কোর | 5%  | বিপরীত স্বাভাবিক লেটেন্সি stddev                    |

যখন `hardConstraints: true`, প্রার্থীদের প্রাথমিকভাবে সাজানো হয়** লঙ্ঘনের স্কোর** (কতদূর তারা কোন SLO অতিক্রম করে), তারপর যৌগিক স্কোর দ্বারা। অন্যথায় এটি শুধুমাত্র যৌগিক স্কোর।

```ts
class SLAStrategyImpl implements RouterStrategy {
  readonly name = "sla-aware";
  readonly description =
    "Selects the provider most likely to satisfy latency, error-rate, and cost SLOs";

  select(pool, context) {
    // ... scores each candidate against policy: { targetP95Ms, maxErrorRate, maxCostPer1MTokens, hardConstraints }
  }
}
```

**SLA ক্ষেত্র** (কম্বো কনফিগারেশনে সেট করুন):

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "sla-aware",
    "slaTargetP95Ms": 1500,
    "slaMaxErrorRate": 0.05,
    "slaMaxCostPer1MTokens": 5,
    "slaHardConstraints": true
  }
}
```

**কখন ব্যবহার করতে হবে** : কঠোর বিলম্ব, ত্রুটি-হার, বা খরচ বাজেট সহ উত্পাদন কাজের চাপ।

**উপনাম** : `sla-aware`, `sla`

#### 5. `lkgp` — সর্বশেষ পরিচিত ভাল প্রদানকারী প্রথম

চেষ্টা করে** সর্বশেষ পরিচিত ভাল প্রদানকারী** (যদি সেট করা হয়) প্রথমে, তারপর `rules` কৌশলে ফিরে আসে। সেশন স্টিকিনেস — এর জন্য দরকারী একই প্রদানকারী কথোপকথনে ফলো-আপ অনুরোধগুলি পরিচালনা করে।

```ts
class LKGPStrategyImpl implements RouterStrategy {
  readonly name = "lkgp";
  readonly description = "Tries last known good provider first, then falls back to rules";

  select(pool, context) {
    if (context.lkgpEnabled === false) {
      return getStrategy("rules").select(pool, context);
    }

    if (context.lastKnownGoodProvider) {
      const candidates = pool.filter(
        (c) => c.provider === context.lastKnownGoodProvider && c.circuitBreakerState !== "OPEN"
      );
      if (candidates.length > 0) {
        return { provider: candidates[0].provider /* ... */ };
      }
    }

    // Fallback to rules strategy
    return getStrategy("rules").select(pool, context);
  }
}
```

**কখন ব্যবহার করতে হবে** : মাল্টি-টার্ন কথোপকথন যেখানে আপনি একই প্রদানকারীকে ফলো-আপ অনুরোধগুলি পরিচালনা করতে চান (যেমন, ক্যাশিং, প্রসঙ্গ ধারাবাহিকতা, বা মূল্যের ধারাবাহিকতা)।

**উপনাম** : `lkgp` (কোনও উপনাম নেই)

#### 6. নাদিরের মাধ্যমে `nadir` — প্রম্পট-সচেতন মডেল পছন্দ

উপরের প্রতিটি কৌশল প্রার্থীদের তাদের নিজস্ব টেলিমেট্রি দ্বারা স্থান দেয়; তাদের কেউ অনুরোধটি পড়ে না। `nadir` শেষ ব্যবহারকারীর পালা এবং পুলের মডেল আইডি পাঠায় [নাদিরের](https://getnadir.com) সিদ্ধান্ত API (`POST /v1/bucket`) এবং মডেলের রুট নাদির সেই মেনু থেকে নির্বাচন করে (`simple` → সবচেয়ে সস্তা সক্ষম মডেল, `complex` → দ্য ফ্রন্টিয়ার ওয়ান)। সেই মডেলটি পরিবেশনকারী সংযোগটি এখনও `rules` দ্বারা বাছাই করা হয়েছে, তাই কোটা, স্বাস্থ্য এবং খরচ কোন অ্যাকাউন্টটি নির্ধারণ করতে থাকবে।

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "nadir",
    "nadir": {
      "apiKey": "ndr_...",
      "baseUrl": "https://api.getnadir.com",
      "timeoutMs": 2000
    }
  }
}
```

`OMNIROUTE_NADIR_API_KEY` এবং `OMNIROUTE_NADIR_BASE_URL` হল দুটি স্ট্রিংয়ের জন্য env ফলব্যাক। `baseUrl` শুধুমাত্র একটি স্ব-হোস্টেড নাদিরের জন্য প্রয়োজন (একটি পিছনের `/v1` সহ্য করা হয়)। নাদিরের বেনামী স্তরে কীবিহীন কল ল্যান্ড, যা প্রতি IP হার-সীমিত। একটি কী দিয়ে ( [একটি তৈরি করুন](https://app.getnadir.com/dashboard/api-keys) ), প্রতিটি সিদ্ধান্ত আপনার নাদির ড্যাশবোর্ডে লগ করা হয়। সম্পূর্ণ সেটআপ এবং যাচাইকরণ: [getnadir.com/docs/gateway-omniroute](https://getnadir.com/docs/gateway-omniroute/) ।

বাক্স থেকে যা যায়: ব্যবহারকারীর শেষ বার্তার পাঠ্য (প্রথম 16k অক্ষর), প্রার্থীর মডেল আইডি এবং একটি `source: "omniroute"` চ্যানেল ট্যাগ। কোনো সিস্টেম প্রম্পট, ইতিহাস, টুল বা হেডার নেই।

ব্যর্থতার আচরণ হল ব্যর্থ-ওপেন: একটি টাইমআউট (ডিফল্ট 2000 ms), একটি non-2xx, একটি পৌঁছানো অযোগ্য হোস্ট, একটি বিকৃত প্রতিক্রিয়া বা পুলের বাইরে একটি নির্বাচন `rules` সিদ্ধান্তের সমাধান করে এবং কারণটি `NadirStrategy: fallback (…)` উপসর্গযুক্ত। একটি ব্যর্থ কলের পরে কৌশলটি 30 সেকেন্ডের জন্য নেটওয়ার্ককে এড়িয়ে যায়, তাই একটি বিভ্রাটের জন্য অনুরোধ প্রতি একটির পরিবর্তে প্রতি 30 সেকেন্ডে একটি টাইমআউট খরচ হয়৷ রাউটিং ইভেন্ট `strategy: "nadir"` রিপোর্ট করে যখন নাদির আসলে পছন্দ করে।

**কখন ব্যবহার করতে হবে** : একটি পুলের উপর মিশ্র-কঠিন ট্রাফিক যা মডেল স্তরগুলিকে বিস্তৃত করে (একটি ছোট, একটি মধ্য এবং একটি সীমান্ত মডেল), যেখানে সর্বদা-সীমান্ত হল আপনি যে খরচটি কাটতে চান৷

**উপনাম** : `nadir` (কোনও উপনাম নেই)

#### 7. `decision` — প্লাগযোগ্য সিদ্ধান্তকারী মডেলটি বেছে নেয়

`decision` জিজ্ঞাসা করে** সিদ্ধান্তকারী** পুলের কোন মডেলটি অনুরোধের সাথে খাপ খায়, তারপর পুলটিকে সেই মডেলে সংকুচিত করে এবং `rules` সংযোগ বাছাই করতে দেয় (কোটা, স্বাস্থ্য এবং খরচ এখনও অ্যাকাউন্ট বেছে নেয়)। যখন রাউটার নব `config` এর শীর্ষে (ড্যাশবোর্ড যা লিখে) বা `config.auto.routerStrategy` এর পাশে `config.auto.decision` বসে তখন কম্বো-এর ডিসিশন ব্লক — `config.decision` এ ডিসাইডার সেট করা হয়।

| `decider`     | কে উত্তর দেয়                                                                                                         | প্রয়োজন                                         |
| ------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `systemone`   | TypeSafe সিস্টেম ওয়ান (`POST https://api.typesafe.ai/v1/systemone`), ডিফল্ট মডেল `jev-latest`                        | একটি `typesafe` সংযোগ বা env কী                  |
| `http`        | `baseUrl` এ আপনার নিজের সিদ্ধান্ত : `wire: "systemone"` (`{baseUrl}/v1/systemone`) বা `"openai-chat"` (চ্যাট সমাপ্তি) | `baseUrl` + `model`; কী ঐচ্ছিক                   |
| `combo-model` | আপনার প্রদানকারী মডেলগুলির মধ্যে একটি, যাকে ফিউশন বিচারকের মতো প্রক্রিয়াতে বলা হয়                                   | `model` হিসাবে `provider/model` (কোনও কম্বো নেই) |

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "decision",
    "decision": {
      "decider": "http",
      "baseUrl": "https://decider.example.com",
      "wire": "openai-chat",
      "model": "qwen-small",
      "connectionId": "<stored connection id>",
      "timeoutMs": 2000,
      "minConfidence": 0.6,
      "descriptions": { "gpt-4o-mini": "Quick drafts and short answers" }
    }
  }
}
```

ক্ষেত্রগুলি (সংরক্ষণের সময় এবং আবার অনুরোধের সময় একটি কঠোর স্কিমা দ্বারা যাচাই করা হয়):

- `decider` — `systemone`, `http` বা `combo-model`।
- `model` — TypeSafe মডেল, আপনার URL এ সিদ্ধান্তের মডেল বা একটি কম্বো-মডেল কলের `provider/model` (200টি অক্ষর পর্যন্ত)।
- শুধুমাত্র `baseUrl` — `http` : একটি `http(s)` URL 500 অক্ষর পর্যন্ত, শংসাপত্র, প্রশ্ন বা খণ্ড ছাড়া। এই OmniRoute (লুপব্যাক + `PORT`) এর দিকে নির্দেশ করে একটি URL প্রত্যাখ্যান করা হয়েছে।
- শুধুমাত্র `wire` — `http` : `systemone` (ডিফল্ট) বা `openai-chat`।
- `connectionId` — সেই সঞ্চিত সংযোগ যার কী ব্যবহার করা হয় (শুধুমাত্র কলিং API কী এর অনুমোদিত সংযোগের ভিতরে)। এটি ছাড়া, `systemone` একটি `typesafe` সংযোগ পড়ে এবং প্রতিটি নেটওয়ার্ক সিদ্ধান্তকারী `OMNIROUTE_DECISION_API_KEY` এ ফিরে আসে। কোন `apiKey` ক্ষেত্র নেই: একটি কী কখনই একটি কম্বোতে সংরক্ষণ করা হয় না।
- `timeoutMs` — পূর্ণসংখ্যা, 100–5000, ডিফল্ট 2000।
- `minConfidence` — 0-1; একটি নিম্ন-আস্থার উত্তর `rules` এ ফিরে আসে (একটি সিদ্ধান্তকারী যেটি অনাস্থার রিপোর্ট করে 0 হিসাবে গণনা করে)।
- `descriptions` — 50 এন্ট্রি পর্যন্ত (300 পর্যন্ত কী, 1000 অক্ষর পর্যন্ত টেক্সট), মডেল আইডি বা `provider/model` দ্বারা কী করা হয়েছে; আনসেট এন্ট্রি একটি উৎপন্ন খরচ-র্যাঙ্ক বিবরণ পেতে.

**পতাকা।** `COMBO_DECISION_ROUTER_ENABLED` (ডিফল্ট `false`) প্রতিটি সিদ্ধান্তকারীকে গেট করে। এটি বন্ধ থাকাকালীন, একটি `decision` কম্বো কোন শংসাপত্র পড়ে না, কোন কল করে না এবং `rules` সাথে রুট করে; লগ বলছে `fallback (disabled)`. একটি সঞ্চিত কী একা এটি চালু করে না। একটি সিদ্ধান্ত ব্লক ছাড়া কম্বো সব প্রভাবিত হয় না.

**কি বাক্স ছেড়ে.** শুধুমাত্র শেষ ব্যবহারকারীর বার্তার পাঠ্য (8000 অক্ষর পর্যন্ত; chat/Claude `messages` বা প্রতিক্রিয়া `input`) এবং তাদের বিবরণ সহ মডেল আইডির মেনু। সিস্টেম প্রম্পট, প্রতিক্রিয়া `instructions`, টুলস, ইতিহাস, শিরোনাম বা অ্যাকাউন্ট ডেটা কখনই নয়। নেটওয়ার্ক কলগুলি কোনও পুনঃপ্রচার, কোনও পুনঃনির্দেশ এবং একটি 64 KB প্রতিক্রিয়া ক্যাপ ছাড়াই প্রদানকারীর আউটবাউন্ড গার্ডের মাধ্যমে যায়৷ `combo-model` কলটি 256-টোকেন বাজেট সহ নন-স্ট্রিমিং, টুল-ফ্রি, `temperature: 0`; একটি সিদ্ধান্ত কল ভিতরে শুরু একটি সিদ্ধান্ত প্রত্যাখ্যান করা হয়.

**Failure behavior** is fail-open: any failure resolves to the `rules` decision, and the reason reads `decision(<decider>): fallback (<reason>)`, with `<reason>` one of `disabled`, `not_configured`, `missing_credential`, `timeout`, `http_error`, `invalid_response`, `out_of_menu`, `refused`, `cooldown`, `network_error`, `recursion`, `low_confidence`, `single_option` or `no_user_text`. After a timeout, HTTP error or network error the endpoint is skipped for 30 s. A successful pick reads `decision(<decider>): selected <model> from <n>; confidence <c> (<rules reason>)`. No URL, key, prompt or upstream body reaches the log.

কম্বো নির্মাতা এই ক্ষেত্রগুলি দেখায় যখন রাউটার কৌশলটি `decision` হয়, স্থানধারক হিসাবে উত্পন্ন বিবরণ এবং একটি** পরীক্ষার সিদ্ধান্ত** অসংরক্ষিত সেটিংস (একই পতাকা) সহ একবার `POST /api/combos/decision-preview` কল করার বোতাম।

**কখন ব্যবহার করতে হবে** : মিশ্র-কঠিন ট্র্যাফিক যেখানে আপনি চান যে শ্রেণীটি আপনার চয়ন করা একটি শ্রেণীবিভাগের দ্বারা অনুরোধ প্রতি বাছাই করা হোক, বিশেষভাবে নাদির দ্বারা নয়।

**উপনাম** : `decision` (কোনও উপনাম নেই)

### কাস্টম রাউটার কৌশল

আপনি পাবলিক API এর মাধ্যমে আপনার নিজের `RouterStrategy` বাস্তবায়ন নিবন্ধন করতে পারেন:

```ts
import {
  registerStrategy,
  type RouterStrategy,
} from "@omniroute/open-sse/services/autoCombo/routerStrategy";

class MyCustomStrategy implements RouterStrategy {
  readonly name = "my-custom";
  readonly description = "My custom routing strategy";

  select(pool, context) {
    // Your routing logic here
    return {
      provider: pool[0].provider,
      model: pool[0].model,
      strategy: this.name,
      reason: "MyCustomStrategy: ...",
      candidatesConsidered: pool.length,
      finalScore: 1.0,
    };
  }
}

registerStrategy("my-custom", new MyCustomStrategy());
```

তারপর এটি ব্যবহার করুন:

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "my-custom"
  }
}
```

## টাস্ক উপযোগিতা

6টি টাস্কের ধরন (`coding`, `review`, `planning`, `analysis`, `debugging`, `documentation`) জুড়ে 30টিরও বেশি মডেলের স্কোর নির্ধারণ করা হয়েছে। ওয়াইল্ডকার্ড প্যাটার্ন সমর্থন করে (যেমন, `*-coder` → উচ্চ coding স্কোর)।

## অটো ভেরিয়েন্ট রিক্যাপ

`autoPrefix.ts` এ `AutoVariant` ঘোষণা করে** 7 মান** (`coding`, `fast`, `cheap`, `offline`, `smart`, `lkgp`, `chaos`)। বেয়ার `auto` সহ Together ( `variant: undefined` হিসাবে `parseAutoPrefix()` দ্বারা পরিচালিত) এবং দুটি ফ্ল্যাট স্তর `auto/subscription` এবং `auto/thrifty` ( `builtinCatalog.ts` তে`FLAT_TIER_OVERLAY_IDS` ) ওভারলে রয়েছে** 10 ফ্ল্যাট মডেল IDs** :

`auto`, `auto/coding`, `auto/fast`, `auto/cheap`, `auto/offline`, `auto/smart`, `auto/lkgp`, `auto/chaos`, `auto/subscription`, `auto/thrifty`

এর বাইরে, `auto/<category>[:<tier>]` কম্পোজিশন, মডেল-ফ্যামিলি IDs (উদাহরণস্বরূপ `auto/claude-opus`) এবং `builtinCatalog.ts` এ `auto/best-*` / `auto/pro-*` উপনামগুলিও সমাধান করে।

## Auto-Combo-তে টিয়ার কীভাবে কাজ করে

১৬-ফ্যাক্টরের স্কোরিং ফাংশনটি (`open-sse/services/autoCombo/scoring.ts`) টিয়ারের
সদস্যতাকে দুটি সংকেত হিসেবে বিবেচনা করে: `tierPriority` (0.0476) এবং `tierAffinity` (0.0476)। সম্পূর্ণ
`DEFAULT_WEIGHTS` সেটের জন্য উপরের প্রামাণ্য [স্কোরিং ফ্যাক্টর টেবিলটি](#how-it-works-persisted-auto-combos) দেখুন
— প্রতিটি প্যাকের ওভাররাইড (ship-fast/cost-saver/quality-first/
offline-friendly) "প্রতি প্যাকের ওয়েট প্রোফাইল" টেবিলে তালিকাভুক্ত রয়েছে।

শুধু টিয়ারই **Tier 1**-কে প্রথমে রাখতে বাধ্য করে না — যদি **Tier 1**-এর লেটেন্সি খারাপ হয় বা
খরচের তুলনায় গুণমান অনুকূল না হয়, তাহলে **Tier 2** জয়ী হয়। টিয়ারের ক্রম বাধ্যতামূলক করতে, কম্বো
স্ট্র্যাটেজি `priority` ব্যবহার করুন এবং টিয়ার অনুযায়ী প্রোভাইডারগুলো সাজান।

**Tier 1**-কে (সাবস্ক্রিপশন) জোরালোভাবে অগ্রাধিকার দিতে, `tierPriority`-এর ওয়েট বাড়ান:

```json
{
  "strategy": "auto",
  "config": { "auto": { "weights": { "tierPriority": 0.3, "costInv": 0.05 } } }
}
```

টিয়ারের সংজ্ঞা এবং প্রোভাইডারের শ্রেণিবিভাগের জন্য [`docs/guides/TIERS.md`](../guides/TIERS.md) দেখুন।

## পরীক্ষা এবং কভারেজ

### ডিটারমিনিস্টিক রাউটিং-সিদ্ধান্ত ম্যাট্রিক্স (`npm run test:combo:matrix`)

`tests/integration/combo-matrix/*.test.ts` রাউটিং প্রমাণ করে** সিদ্ধান্ত** পাবলিক কৌশলগুলির মধ্যে এটি একটি উপহাসিত আপস্ট্রিম সহ বাস্তব কম্বো পাইপলাইনের মাধ্যমে এন্ড-টু-এন্ড কভার করে। কভারেজ অন্তর্ভুক্ত:

- 22টি পাবলিক `ROUTING_STRATEGY_VALUES` কৌশলগুলির মধ্যে 18টি (অর্ডার করা, ওজনযুক্ত, খরচ, প্রসঙ্গ, ফিউশন, …); `quota-weighted`, `cache-optimized`, `pipeline` এবং `jev` ম্যাট্রিক্স দ্বারা প্রয়োগ করা হয় না এবং তাদের নিজস্ব ইউনিট পরীক্ষার উপর নির্ভর করে।
- `quota-share` (অভ্যন্তরীণ) এন্ড-টু-এন্ড: DRR ন্যায্যতা + স্যাচুরেশন বঞ্চিতকরণ বাস্তব `selectQuotaShareTarget` সীমের মাধ্যমে (`registerQuotaFetcher` / `setLKGP` / `__setHeadroomSaturationFetcherForTests`)।
- প্রতিটি লক্ষ্য গণনা জুড়ে`context-relay` সার্বজনীন-হ্যান্ডঅফ কভারেজ।

এই স্যুটটি CI (`test:integration` জব) `--test-concurrency=1` এবং `--test-force-exit` এর সাথে চলে তাই এটি নির্ধারক এবং লাইভ শংসাপত্রের প্রয়োজন নেই।
