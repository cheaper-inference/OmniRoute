## সংক্ষিপ্ত বিবরণ

কোটা শেয়ারিং ইঞ্জিন একই সংযোগ ব্যবহারকারী একাধিক API key-এর মধ্যে কোনো provider-এর সময়ভিত্তিক কোটা (যেমন Codex-এর
5-ঘণ্টার উইন্ডো, Kimi-এর 1500 req/h) ন্যায্যভাবে বণ্টন করে।

**এটি যে সমস্যার সমাধান করে:** OmniRoute একই upstream provider account-এর বিপরীতে অনেক API key-এর অনুরোধ প্রক্সি করে।
শেয়ারিং লজিক না থাকলে, key A থেকে আসা হঠাৎ অনুরোধের ঢল ঘণ্টাটির জন্য
provider quota শেষ করে দিতে পারে, ফলে উইন্ডো রিসেট না হওয়া পর্যন্ত key B এবং C ব্লক হয়ে থাকে।
ইঞ্জিনটি নিম্নোক্ত উপায়ে এটি প্রতিরোধ করে:

1. প্রতিটি dimension (%, requests, tokens, $) অনুযায়ী প্রতিটি key-এর rolling consumption ট্র্যাক করে।
2. একটি work-conserving fair-share algorithm প্রয়োগ করে: global pool সম্পৃক্ত না থাকা পর্যন্ত একটি key নিষ্ক্রিয়
   share থেকে ধার নিতে পারে।
3. অনুরোধটি upstream executor-এ পৌঁছানোর আগে hot path (`chatCore.ts`)-এ ফলাফলটি
   প্রয়োগ করে।

## অ্যালগরিদম: ফেয়ার-শেয়ার ওয়ার্ক-সংরক্ষণ

`src/lib/quota/fairShare.ts` এ বাস্তবায়িত হয়েছে।

### মোড

| অবস্থা                                     | মোড      | আচরণ                                                    |
| ------------------------------------------ | -------- | ------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **উদার** | কী গ্লোবাল লিমিট মাইনাস ভোক্ত-মোট পর্যন্ত ধার নিতে পারে |
| `globalUsedPercent >= saturationThreshold` | **কড়া** | পৃথক ন্যায্য ভাগ কঠোরভাবে প্রয়োগ করুন                  |

ডিফল্ট `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`)।

এই দুটি মোড ডিফল্ট ধার মোডে একটি পুল বর্ণনা করে, `saturation`। `consent` মোডে একটি পুল সবসময় কঠোর নিয়ম প্রয়োগ করে, সম্পৃক্ততা যাই হোক না কেন। [সম্মতিপ্রাপ্ত ঋণ দেখুন (প্রতি-পুলে অপ্ট-ইন)](#consented-lending-per-pool-opt-in) ।

### প্রতি-মাত্রা সিদ্ধান্ত

পুলের প্রতিটি সক্রিয় মাত্রার জন্য, ইঞ্জিন গণনা করে:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = current rolling value for this key (from QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

`percent` মাত্রার জন্য, `consumed` পরিবর্তে অ্যাট্রিবিউশন বই থেকে এসেছে ( [শতাংশ মাত্রা: প্রতি-কী অ্যাট্রিবিউশন](#percent-dimensions-per-key-attribution) দেখুন)।

তারপর:

- **`policy = hard`** : যদি `consumed > fairShareAllowed` এবং মোড কঠোর → হয়** ব্লক** .
- **`policy = soft`** : যদি `consumed > fairShareAllowed` এবং মোড কঠোর → হয়** শাস্তি দেওয়া** (কম্বোতে অগ্রাধিকার দিন; কখনই হার্ড-ব্লক)
- **`policy = burst`** : ন্যায্য ভাগ নির্বিশেষে গ্লোবাল হেডরুম বিদ্যমান থাকাকালীন অনুমতি দিন।

### ক্যাপ সম্পূর্ণ

একটি বরাদ্দের উপর `capValue` + `capUnit` হল একটি কঠিন সিলিং যা মোড বা নীতি থেকে স্বাধীন। যে কোনো মাত্রা যেখানে সবসময় `consumed >= capValue`** ব্লক** অনুরোধ একটি `percent` ক্যাপের জন্য, `consumed` হল শুধুমাত্র সেই অংশ যা কী-এর সাথে যুক্ত।

### মাল্টি-ডাইমেনশন চেক

একটি অনুরোধ ব্লক করা হয় যদি** যেকোনো** পুলের মাত্রা এটি ব্লক করবে। মাত্রাগুলি স্বাধীন — একটি 5h% ক্লান্তি সাপ্তাহিক% মাত্রাকে প্রভাবিত করে না।

### ধার করা

উদার মোডে, একটি কী যার বরাদ্দ কম-ব্যবহার করা হয় অন্য কীগুলির অ-বরাদ্দকৃত শেয়ার থেকে উদ্বৃত্ত ব্যবহার করতে পারে। সূত্রটি হল:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

যেখানে `consumedByOtherKeys = consumedTotal - consumedByThisKey`. টেটো গ্লোবাল (সেই মাত্রার জন্য পুল `limit` ) সর্বদা কঠিন সিলিং।

### সম্মত ঋণ প্রদান (প্রতি পুল অপ্ট-ইন)

প্রতিটি পুলের একটি ধার মোড আছে। `saturation` হল ডিফল্ট এবং নিয়মগুলি উপরে রাখে। `consent` মোডে একটি `hard` কী কেবলমাত্র সেই ক্ষমতার মধ্যেই তার অংশ পাস করে যা অন্যান্য কী ধার দিতে রাজি হয়। প্রশাসক প্রতিটি পুলের মোড সেট করে। প্রতিটি মূল হোল্ডার [ঋণ সম্মতির](#lending-consent) মাধ্যমে তাদের নিজস্ব সম্মতি নির্ধারণ করে।

একটি সম্মতি হল 0 থেকে 100 পর্যন্ত শতাংশ এবং যুগের মিলিসেকেন্ডে একটি ঐচ্ছিক সময়সীমা। সময়সীমা ভবিষ্যতে থাকাকালীন কী তার নিষ্ক্রিয় অংশের শতাংশ ধার দেয়।

এক মাত্রার জন্য, `L` হল কার্যকরী সীমা: পরিকল্পনার সীমা পুলের অ্যাকাউন্টের সময়। অনুরোধকারী কীটির জন্য গেট গণনা করে:

```
share_k         = w_k / 100 × L
idle_k          = max(0, share_k − consumed_k)
lent            = Σ over the other keys of lend_k / 100 × idle_k
taken           = Σ over the other keys of max(0, consumed_k − share_k)
borrowAvailable = max(0, lent − taken)
```

`w_k` হল কী-এর ওজন, অথবা প্রতিটি কী-এর জন্য `100 / n` যখন কোনও ওজন 0-এর উপরে না হয়। `lend_k` হল কী-এর সক্রিয় শতাংশ, এবং 0 এর সময়সীমা পেরিয়ে গেলে। অনুরোধকারী কী এর নিজস্ব সম্মতি কখনই গণনা করা হয় না। একটি `hard` কী প্রত্যাখ্যান করা হয় একবার যখন এর ব্যবহার তার শেয়ার প্লাস `borrowAvailable` পৌঁছায়।

যে ক্ষমতা কোন বরাদ্দ দাবি করে না (100 বিয়োগ ওজনের যোগফল) ঋণযোগ্য নয়। কোনো চাবি ধার দিতে রাজি হয়নি।

**উদাহরণ।** `L` হল 1000।

| চাবি | ওজন | শেয়ার করুন | গ্রাস করেছে | ধার দেয় |
| ---- | --- | ----------- | ----------- | -------- |
| ক    | 50  | 500         | 530         | 0%       |
| খ    | 30  | 300         | 100         | 50%      |
| গ    | 0   | 0           | 60          | 0%       |

- B তার নিষ্ক্রিয় 200 এর 50% ধার দেয়, যা 100। C ইতিমধ্যেই তার শেয়ারের উপরে 60 নিয়েছে। A 40 ধার করতে পারে।
- A-কে 530-এ পরিবেশন করা হয় এবং একবার এর ব্যবহার 540-এ পৌঁছলে তা প্রত্যাখ্যান করা হয়।
- C কিছু ব্যবহার করার আগে, A এর সাথে বা তার ভাগের নিচে, C 100 ধার নিতে পারে।
- C কিছু ব্যবহার করার আগে, A এর সাথে 530, C 70 ধার করতে পারে।

**শূন্য ওজন।** ওজন 0 সহ একটি চাবিতে 0 এর ভাগ থাকে। এটি কেবল তখনই পরিবেশন করা হয় যখন এর ব্যবহার অন্যরা ধার দেয় তার চেয়ে কম। যখন কেউ ধার দেয় না, তখন তার প্রথম অনুরোধ থেকে প্রত্যাখ্যান করা হয়।

**সময়সীমা** কোনো ব্যাকগ্রাউন্ড টাস্ক সম্মতির মেয়াদ শেষ করে না। প্রতিটি অনুরোধ তার নিজস্ব সময়ের সাথে সময়সীমার তুলনা করে এবং সেই সময়ের সমান একটি সময়সীমা পেরিয়ে গেছে। একটি সঞ্চিত সময়সীমা যা একটি সীমিত সংখ্যা নয়, অথবা একটি `Date` ধারণ করতে পারে এমন সবথেকে বড় তারিখের অতীত, পাস হিসাবে গণনা করা হয়।

**`soft` এবং `burst`.** ঋণ দেওয়া তাদের সীমাবদ্ধ করে না। একটি `soft` কী তার ভাগ অতিক্রম করার পরে বঞ্চিত হয়। পুলের রুম থাকার সময় একটি `burst` কী পাস হয়। পুলের মোট সীমাতে পৌঁছে গেলে পুলের সিলিং এখনও প্রতিটি কী প্রত্যাখ্যান করে।

**অনুরোধের পথে খরচ।** একটি `saturation` পুল আগের চেয়ে বেশি কিছু পড়ে না। একটি `consent` পুলে, একটি গণনাযোগ্য মাত্রা অন্য কীগুলিকে শুধুমাত্র একটি `hard` কী এর শেয়ারে বা তার উপরে পড়ে যখন অন্য কী ধার দেয়। এটি তখন সমান্তরালভাবে, অন্য কী প্রতি একটি পাঠ করে। একটি ব্যর্থ পড়া সেই কীটির জন্য 0 এর খরচ হিসাবে গণনা করে। একটি `percent` ডাইমেনশন কোন রিড যোগ করে না, কারণ অ্যাট্রিবিউশন বই প্রতিটি কী ধারণ করে।

**একটি পুল সম্পাদনা.** একটি সম্পাদনা কীগুলির সম্মতি রাখে যা থাকে। এটি বরাদ্দ সম্পাদনা, গ্রুপ-ব্যাপী প্রতিস্থাপন এবং `ensure` কলের জন্য ধারণ করে। একটি সরানো কী তার সম্মতি হারায়, এবং একটি কী আবার যোগ করা 0 থেকে শুরু হয়৷ অ্যাডমিন রুটগুলি প্রতিটি কীর সম্মতি ফেরত দেয় এবং এটি কখনই লিখতে পারে না৷ একটি পুলকে `saturation` এ স্যুইচ করা প্রতিটি সঞ্চিত সম্মতি রাখে, যে মোডে কোন প্রভাব নেই। পুলটিকে `consent` এ স্যুইচ করা আবার সঞ্চিত সম্মতিগুলিকে পুনরায় সক্রিয় করে যার সময়সীমা অতিক্রম করেনি। একটি কী ধারক উভয় মোডে একটি সঞ্চিত সম্মতি সাফ করতে পারে।

**আপগ্রেড হচ্ছে।** যদি `lending_percent` এবং `lending_until` কলামগুলি ইতিমধ্যেই বিদ্যমান থাকে, তবে মাইগ্রেশন শুধুমাত্র `borrow_mode` যোগ করে এবং সঞ্চিত শতাংশগুলি যেমন আছে তেমনই থাকে। প্রতিটি পুল `saturation` মোডে শুরু হয়। পুল উইজার্ডে প্রতি পুল `consent` চালু করুন। সঞ্চিত মান থেকে কিছুই অনুমান করা হয় না।

**সীমাবদ্ধতা।**

- একটি ঋণদাতা তার নিজস্ব অংশ ব্যবহার করার আগে তার সিলিং এ পুল খুঁজে পেতে পারেন. অন্যদের ধার করা ক্ষমতা পুলের মোটের দিকে গণনা করে।
- চেক অনুরোধের আগে চলে এবং কিছুই সংরক্ষণ করে না। সমকালীন অনুরোধগুলি রেকর্ড করার আগে খরচ পড়ে, তাই ধারের ক্ষমতা একবারের বেশি খরচ করা যেতে পারে, ফ্লাইটে অনুরোধের দ্বারা আবদ্ধ। `saturation` মোডের শেয়ার চেকের একই সম্পত্তি রয়েছে।

## Sliding Window Counter

`src/lib/quota/sqliteQuotaStore.ts` এবং `redisQuotaStore.ts`-এ বাস্তবায়িত।

প্রতিটি `(apiKeyId, dimensionKey)`-এর জন্য দুটি bucket:

- `curr`: বর্তমান bucket (`floor(nowMs / windowMs)`)
- `prev`: পূর্ববর্তী bucket (`curr - 1`)

কার্যকর rolling value:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**নির্ভুলতা**: প্রায় 99% নির্ভুল। Bucket-গুলোর মধ্যবর্তী সীমানায় ত্রুটি সর্বোচ্চ
window size-এর 1% (2-bucket approximation-এর অন্তর্নিহিত সীমাবদ্ধতা)।

### Concurrency

SQLite driver: প্রতিটি `(apiKeyId | dimensionKey)` key-এর জন্য in-memory mutex
read-modify-write race প্রতিরোধ করে। Pattern-টি `src/sse/services/auth.ts`-এর anti-thundering-herd অনুসরণ করে।

Redis driver: atomic increment-এর জন্য Lua EVAL script — একটি একক Redis command হিসেবে চলে।

## ড্রাইভারসমূহ

### SQLite (ডিফল্ট, 0-install)

- টেবিল: `quota_consumption` (মাইগ্রেশন `073_quota_pools.sql` / `074_quota_consumption.sql` দেখুন)।
- একক-ইনস্ট্যান্স ডিপ্লয়মেন্টের জন্য সর্বোত্তম।
- সমস্ত পার্সিস্টেন্স বিদ্যমান OmniRoute SQLite DB-তে (`DATA_DIR/storage.sqlite`) থাকে।

### Redis (ঐচ্ছিক, মাল্টি-ইনস্ট্যান্স)

- `ioredis` npm প্যাকেজ প্রয়োজন।
- কাউন্টারগুলো Redis-এ সংরক্ষিত হয়; মেটাডেটা (পুল/অ্যালোকেশন) SQLite-এই থাকে।
- যেসব মাল্টি-রেপ্লিকা ডিপ্লয়মেন্টে কাউন্টার শেয়ার করা আবশ্যক, সেগুলোর জন্য সর্বোত্তম।

### ড্রাইভার পরিবর্তন

সেটিংস UI-এর মাধ্যমে (`/dashboard/settings` → Quota Store), অথবা env vars-এর মাধ্যমে:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

env-এর তুলনায় DB সেটিং অগ্রাধিকার পায়। যদি `driver=redis` হয় কিন্তু URL অনুপস্থিত থাকে অথবা
`ioredis` ইনস্টল করা না থাকে, তাহলে ফ্যাক্টরি SQLite-এ ফিরে যায় এবং একটি সতর্কবার্তা লগ করে।

ড্রাইভার নির্বাচনের ক্রম:

1. DB সেটিং `quotaStore.driver`
2. Env `QUOTA_STORE_DRIVER`
3. ডিফল্ট: `sqlite`

## মাল্টি-ডাইমেনশন

একটি পুলের একাধিক মাত্রা থাকতে পারে। প্রতিটি মাত্রা স্বাধীন:

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // global pool ceiling for this dimension
}
```

**উদাহরণ: Codex পরিকল্পনা** (5h% + সাপ্তাহিক%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

একটি অনুরোধ অনুমোদিত হতে হবে সব মাত্রা সন্তুষ্ট করা আবশ্যক.

### শতাংশ মাত্রা: প্রতি-কী অ্যাট্রিবিউশন

একটি শতাংশ প্ল্যান প্রতি অ্যাকাউন্ট এবং প্ল্যান উইন্ডোর জন্য একটি ব্যবহারের পরিসংখ্যান রিপোর্ট করে। প্রদানকারী API কী প্রতি কোন কাউন্টার দেয় না।

এই চিত্রটিকে কীগুলির মধ্যে ভাগ করতে, প্রতিটি পুল অ্যাকাউন্ট এবং প্ল্যান উইন্ডো প্রতি একটি অ্যাট্রিবিউশন বই রাখে। `src/lib/quota/percentLedger.ts` বইয়ের নিয়ম ধারণ করে। `src/lib/quota/percentAttribution.ts` বইটিকে সংখ্যায় পরিণত করে যা প্রয়োগকারী ব্যবহার করে। ফলাফল প্রতিটি মূল রুট টোকেন থেকে নির্মিত একটি অনুমান.

#### বই নাড়া যে পড়া

অনুরোধকৃত প্ল্যান উইন্ডোর জন্য বইটি শুধুমাত্র প্রদানকারীর নিজস্ব চিত্রে চলে। এই সংযোগগুলি একটি রিপোর্ট করে:

| প্রদানকারী                         | জানালা পরিকল্পনা করুন |
| ---------------------------------- | --------------------- |
| Claude, একটি OAuth সংযোগের মাধ্যমে | `5h`, `weekly`        |
| Codex                              | `5h`, `weekly`        |

এগুলি পড়া হিসাবে গণনা করা হয় না:

- একটি প্রতিক্রিয়া প্রদানকারী ক্লায়েন্ট বাসি হিসাবে চিহ্নিত করে
- একটি Claude উইন্ডো যার শতাংশ প্রদানকারী রিপোর্ট করেনি
- অন্য উইন্ডোর চিত্র, বা জানালা জুড়ে সবচেয়ে খারাপ কেস
- হার-সীমা হেডার ফলব্যাক
- একটি ব্যর্থ পড়া

একটি API কী সহ Claude সহ অন্যান্য প্রদানকারীদের কোন বই নেই। প্রতিটি কী তাদের শতাংশ মাত্রায় 0 চার্জ করা হয়, এই পরিবর্তনের আগে।

একটি রিডিং স্যাচুরেশন সিগন্যালের 30-সেকেন্ডের ক্যাশে ভাগ করে। একটি Claude রিডিং তারিখ দেওয়া হয় যখন চিত্রটি প্রতিক্রিয়া শিরোনামে পর্যবেক্ষণ করা হয়েছিল বা ব্যবহারের শেষ পয়েন্ট থেকে পড়া হয়েছিল, যখন সেই সময়টি জানা যায়। অন্যান্য রিডিং সেই ক্যাশে এন্ট্রি কখন তৈরি করা হয়েছিল তার তারিখ অনুসারে।

#### বই কি রাখে

প্রতিটি রেকর্ড করা অনুরোধ তার টোকেন যোগ করে, একবার, প্রতি পুল, অ্যাকাউন্ট এবং কী প্রতি একটি কাউন্টারে। একটি কাউন্টার শুধুমাত্র বৃদ্ধি. বই তিনটি জিনিস রাখে:

- বেসলাইন: যখন বইটি খোলা হয়েছিল বা জানালাটি শেষবার চালু হয়েছিল তখন চিত্র
- শেষ প্রয়োগ করা চিত্র
- প্রতি কী, একই মুহুর্তে এর টোকেন কাউন্টার, এটির চিহ্ন বলা হয়

এনফোর্সমেন্ট বা ব্যবহারের রুট অ্যাট্রিবিউশন গণনা করলে বইটি আপডেট করা হয়। লেখাগুলি একটি পুনর্বিবেচনা নম্বরের উপর তুলনা এবং সেট করা হয়। একজন লেখক যে হারায় সে নতুন করে পড়ার জন্য একবার চেষ্টা করে।

#### কিভাবে একটি কী এর অংশ গণনা করা হয়

বইটি পড়ার সময় প্রতিটি কী এর অংশ গণনা করা হয়। বেসলাইনটি টোকেনগুলির অনুপাতে কীগুলির মধ্যে বিভক্ত হওয়ার পর থেকে চিত্রটির বৃদ্ধি প্রতিটি তার চিহ্ন থেকে রাউট করা হয়েছে৷

Together, এই টোকেনগুলি `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` টোকেন প্রতি চিত্রের সর্বাধিক এক বিন্দুতে ব্যাখ্যা করে (ডিফল্ট 1,000)। তারা যে বৃদ্ধি ব্যাখ্যা করে না তা বাহ্যিক। বেসলাইনটিও বাহ্যিক।

উদাহরণস্বরূপ, একটি বই 0 এ খোলে। কী A তারপর 900,000 টোকেন এবং কী B রুট 100,000 রুট করে। 60 অঙ্কে, A এর অংশ 54 পয়েন্ট এবং B এর অংশ 6।

এর কী চিহ্নের নীচে একটি কাউন্টার পুনরায় চালু হয়েছে এবং সম্পূর্ণরূপে গণনা করা হয়েছে। একটি চিহ্ন ছাড়া একটি কী, যেমন একটি কী যা একটি উইন্ডোর মাঝখানে পুলের সাথে যোগ দেয়, তার সমস্ত টোকেন গণনা করে। টোকেন পিছিয়ে থাকা একটি চিত্র একটি ত্রুটি সৃষ্টি করে যা পরবর্তী পাঠে চলে যায়। এটা জমে না।

`QUOTA_PERCENT_MIN_TOKENS_PER_POINT` প্রতিটি অ্যাট্রিবিউশনে পড়া হয়। একটি মান যা কমপক্ষে 1 এর একটি সসীম সংখ্যা নয় তা 1,000-এ ফিরে আসে।

#### কিভাবে একটি পড়া বই পরিবর্তন

প্রথম মিলিত নিয়ম প্রযোজ্য:

1. **এখনো কোনো বই নেই:** পড়া বই খুলে দেয়। এর চিত্রটি বেসলাইন এবং প্রতিটি কাউন্টার চিহ্নিত করা হয়েছে।
2. **পুরোনো পড়া:** শেষ প্রয়োগের আগে তারিখের একটি পড়া উপেক্ষা করা হয়। তাই এমন একটি রিডিং যার রিসেট সময় সঞ্চিত একের চেয়ে 30 মিনিট আগে।
3. **নতুন প্রদানকারী উইন্ডো:** একটি রিসেট সময় 30 মিনিটেরও বেশি পরে সংরক্ষিত একটি বই ঘুরিয়ে দেয়। চিত্রটি বেসলাইনে পরিণত হয় এবং প্রতিটি কাউন্টার আবার চিহ্নিত করা হয়। একটি কাউন্টার ছাড়া চাবি বই ছেড়ে.
4. **শেষ উইন্ডো:** একটি সংরক্ষিত রিসেট সময় যা পড়ার ডেটা সময়ের পরে নয় মানে উইন্ডোটি শেষ হয়ে গেছে। পড়া বইটিকে ঘুরিয়ে দেয়, তার চিত্র যাই হোক না কেন।
5. **উচ্চতর চিত্র:** শুধুমাত্র শেষ চিত্রটি চলে। বেসলাইন এবং চিহ্ন থাকে।
6. **একই চিত্র:** চিত্র, বেসলাইন এবং চিহ্ন থাকে। শুধুমাত্র একটি রিসেট সময় বই অভাব লেখা হয়.
7. **নিম্ন চিত্র:** একটি নিম্ন চিত্র যেমন প্রয়োগ করা হয় না. তিনটি জিনিস ধরে রাখলেই এটি বইটি ঘুরিয়ে দেয়। এটি শেষ প্রয়োগ করা পড়ার চেয়ে কমপক্ষে দুই মিনিট নতুন। কিছুই বলে না জানালা একই খোলা এক. এটি এক পয়েন্টের বেশি কম।

তিনটি জিনিস ধরে রাখলে উইন্ডোটিকে একই খোলা হিসাবে গণনা করা হয়। উভয় রিসেট সময় পরিচিত. তারা একে অপরের 30 মিনিটের মধ্যে রয়েছে। সঞ্চিত একটি এখনও পড়া এগিয়ে আছে. সেই জানালার ভিতরে একটি নিম্ন চিত্র কিছুই পরিবর্তন করে না।

একটি রিসেট সময় সংরক্ষণ করা হয় যখন এটি পড়ার ডেটা সময়ের আগে থাকে যা এটি বহন করে। একটি উচ্চতর চিত্র তার পড়ার রিসেট সময় সঞ্চয় করে যখন এটি ব্যবহারযোগ্য হয়, এবং অন্যথায় সঞ্চিত একটি রাখে। একটি সমান চিত্র তার পড়ার রিসেট সময় শুধুমাত্র তখনই রেকর্ড করে যখন বইটির কোনটি নেই। এটি অন্য কিছুই পরিবর্তন করে না। একটি নিম্ন চিত্র যা বই রেকর্ড চালু না কোন রিসেট সময়.

#### যখন বই ব্যবহার করা হয়

পড়ার পরে, বইটি ব্যবহার করা হয় যদি না এর সংরক্ষিত রিসেট সময় বর্তমান সময়ের পরে না হয়। সেই ক্ষেত্রে দেখা যায় যখন রিসেট করার ঠিক আগে নেওয়া একটি রিডিং, যেমন ক্যাশে থেকে দেওয়া একটি, তার ঠিক পরে পরিলক্ষিত হয়।

একটি ব্যবহারযোগ্য পড়া ছাড়া, সঞ্চিত বইটি ব্যবহার করা হয় যখন এটি এখনও বর্তমান উইন্ডোর বই হতে পারে। এটি দুটি ক্ষেত্রে ধারণ করে:

- এর রিসেট সময় জানা এবং এখনও এগিয়ে
- এটির কোন রিসেট সময় নেই, এবং শেষ পঠন যা এটিকে পরিবর্তন করেছে তা সর্বাধিক 15 মিনিটের পুরানো৷

অন্যথায় কিছুই আরোপিত হয় না, যখন কোন বই নেই। একটি বই যার সংরক্ষিত রিসেট সময় অতিবাহিত হয়েছে তা কখনই চার্জ করা হয় না।

#### এনফোর্সমেন্ট

শতাংশ মাত্রায় একটি কী এর ব্যবহার হল এর আরোপিত অংশ এবং বাহ্যিক অংশের একটি অংশ। বাহ্যিক অংশটি প্রথমে ক্ষমতা ব্যবহার করে কোন বরাদ্দ দাবি করে না (100 বিয়োগ ওজনের যোগফল)। শুধুমাত্র অতিরিক্ত ওজন দ্বারা চাবি মধ্যে ভাগ করা হয়.

যে খরচ অন্য কোনো মাত্রা জন্য চাবি ন্যায্য ভাগ সঙ্গে তুলনা করা হয়. যখন স্যাচুরেশন সিগন্যাল `QUOTA_SATURATION_THRESHOLD` (ডিফল্ট 0.5) এ পৌঁছায় তখনও কঠোর মোড শুরু হয়। প্রতিটি সংখ্যা কার্যকরী সীমা দ্বারা স্কেল করা হয়: প্রতি-অ্যাকাউন্ট সীমা পুলের অ্যাকাউন্টের সংখ্যার গুণ করে।

`capUnit: "percent"` সাথে একটি পরম ক্যাপ শুধুমাত্র কী-এর জন্য দায়ী অংশকে গণনা করে, একইভাবে স্কেল করা হয়। প্রতি-অ্যাকাউন্টের সীমা 100 এবং k অ্যাকাউন্ট নিন। N এর একটি ক্যাপ তখন পৌঁছানো হয় যখন সার্ভিং অ্যাকাউন্টের চিত্রের কী অংশ N/k পয়েন্টে পৌঁছায়। প্রতিটি অ্যাকাউন্ট তার নিজস্ব বইয়ের বিরুদ্ধে চেক করা হয়। উদাহরণস্বরূপ, দুটি অ্যাকাউন্টের সাথে, একটি অ্যাকাউন্টের চিত্রের 5 পয়েন্টে 10-এর ক্যাপ পৌঁছানো হয়।

যখন স্টোরটি পড়া যায় না, তখন কিছুই অ্যাট্রিবিউট করা হয় না এবং প্রতিটি কী সেই মাত্রায় 0 চার্জ করা হয়। যখন একটি বই লিখতে ব্যর্থ হয়, তখন সেই অ্যাট্রিবিউশনটি বইটি পড়ার মতো ব্যবহার করে। একটি ব্যর্থ টোকেন লিখলে অনুরোধের টোকেন বই থেকে বেরিয়ে যায়। এই ব্যর্থতাগুলির কোনটিই একটি অনুরোধকে ব্লক করে না।

একটি `consent` পুলে, ঋণ দেওয়ার সূত্রটি উপরে বর্ণিত হিসাবে শতাংশ মাত্রায় প্রতিটি কী-এর ব্যবহার ব্যবহার করে। যখন অন্য কী ধার দেয়, তখন বইটি একবার পড়া হয় এবং প্রতিটি কীকে দায়ী করা হয়। একটি ব্যবহারযোগ্য বই ছাড়া প্রতিটি কী 0 চার্জ করা হয়। একটি ওজন সহ একটি কী তারপর চলে যায় এবং 0 ওজনের একটি চাবি তখনই পাস হয় যখন আরেকটি কী ধার দেয়।

#### ব্যবহারের রুট

`GET /api/quota/pools/{id}/usage` একই ফাংশনের মাধ্যমে একই সংখ্যা রিপোর্ট করে। `accounts` এ প্রতি পুল সংযোগে একটি শতাংশ মাত্রার একটি এন্ট্রি রয়েছে। এর শীর্ষ-স্তরের `consumedTotal` এবং `perKey` প্রথম এন্ট্রি মিরর।

রুটটি বর্তমান পড়ার ক্ষেত্রেও প্রযোজ্য, তাই এটি অনুরোধের মতো বইটিকে অগ্রসর করতে পারে। `internal + external` `consumedTotal` থেকে আলাদা হতে পারে যখন কোন ব্যবহারযোগ্য পঠন নেই, বা যখন একটি নিম্ন চিত্র প্রয়োগ করা হয় না।

#### সঞ্চয়স্থান এবং ধারণ

দুই কোটা দোকানেই বই রাখে। SQLite তে, স্বয়ংক্রিয় ডাটাবেস ক্লিনআপ, সক্রিয় করা হলে, 60 দিনের জন্য আপডেট না হওয়া সারিগুলি সরিয়ে দেয়। Redis এ, একটি পুল সংযোগের বই এবং কাউন্টারগুলি একটি কী ভাগ করে। এটি শেষ টোকেন লেখা বা বই পরিবর্তনের 60 দিন পরে মেয়াদ শেষ হয়। একটি বই যা পরিবর্তন হয় না তা আবার লেখা হয় না, তাই কাটঅফটি দীর্ঘতম পরিকল্পনা উইন্ডোর উপরে সেট করা হয়। ম্যানুয়াল ব্যবহার-ইতিহাস রিসেট এছাড়াও SQLite এর বইগুলি সাফ করে (সীমাবদ্ধতা দেখুন)।

#### সীমাবদ্ধতা

- অ্যাকাউন্ট ফিগারের সমস্ত বৃদ্ধি যেহেতু বেসলাইন টোকেন দ্বারা বিভক্ত হয়েছে তখন থেকে রাউট করা প্রতিটি কী। সেই বৃদ্ধি কখন ঘটেছিল তা বিবেচ্য নয়।
- সুতরাং OmniRoute বাইরে ব্যবহার করা কীগুলিকে তাদের টোকেনগুলি যা অনুমতি দেয় তার জন্য চার্জ করা হয়। এর মধ্যে একটি কী এর উইন্ডোর প্রথম অনুরোধের আগে করা ব্যবহার অন্তর্ভুক্ত, যখন বইটি ইতিমধ্যে খোলা ছিল।
- উদাহরণস্বরূপ, বাইরের ব্যবহার অ্যাকাউন্ট 60 পয়েন্ট বাড়ায় যখন কোন মূল রুট নেই। একটি কী তারপর 30,000 টোকেন রুট করে এবং চিত্রটি 60.6-এ পৌঁছে।
- যদি বইটি ব্যবহার করার আগে খোলা থাকে তবে কীটির অংশটি 30 পয়েন্ট। এটি বহিরাগত ব্যবহারের 7.65 বহন করে, যার ওজন 25 এর চারটি কী রয়েছে।
- যদি বইটি ব্যবহার করার পরে খোলা হয়, তাহলে 60 পয়েন্ট বেসলাইন হয়। কীটির অংশটি 0.6 পয়েন্ট এবং এটি 15টি বাহ্যিক ব্যবহার বহন করে।
- একটি অনুরোধ বা ব্যবহারের পথ পরিদর্শন বইটি খুলে দেয়। সুতরাং এই ধরনের ব্যবহার বেসলাইন হিসাবে গণনা করা হবে কিনা তা নির্ভর করে বইটি কখন খোলা হয়েছে তার উপর।

- প্রতিটি কী সেই ব্যবহারের ওজন ভাগ দিয়ে শুরু হয়, ক্ষমতার পরে কোনো বরাদ্দ দাবি করা হয় না। 85% এ একটি অ্যাকাউন্ট এবং 20 ওজনের পাঁচটি কী, প্রতিটি তার ব্যবহৃত 20টির মধ্যে 17টি দিয়ে শুরু হয়।
- বেশ কয়েকটি অ্যাকাউন্ট সহ একটি পুলে, সার্ভিং অ্যাকাউন্টের অঙ্কটি সমষ্টি বাজেটে প্রয়োগ করা হয়। এই বই দ্বারা অপরিবর্তিত.

- উভয় ক্ষেত্রেই সঞ্চিত রিসেট সময় পাস না হওয়া পর্যন্ত বইটি তার অবস্থা রাখে। এর পরে, বইটি চার্জ করা হয় না যতক্ষণ না একটি পাঠ এটি চালু করে।
- প্রতিকার হল ম্যানুয়াল ব্যবহার-ইতিহাস রিসেট (`POST /api/settings/purge-usage-history`)। এটি SQLite ডাটাবেসে অ্যাট্রিবিউশন বই এবং তাদের টোকেন কাউন্টারগুলি সাফ করে।

- রিসেট একটি Redis কোটা দোকান স্পর্শ না. সেখানে একটি বই এর জানালা দিয়ে শেষ হয়, বা শেষ লেখার 60 দিন পরে মেয়াদ শেষ হয়।

- সেই স্বল্প সময়ের বৃদ্ধি এটিতে রাউট করা টোকেন দ্বারা বিভক্ত হয়। পরবর্তী উইন্ডোর প্রথম পড়া এটি সংশোধন করে। যখন চালু করা বইটিতে রিসেট করার সময় থাকে না, তখন সেই সংশোধনের জন্য শেষ প্রয়োগকৃত পাঠের চেয়ে কমপক্ষে দুই মিনিট নতুন একটি নিম্ন চিত্র প্রয়োজন।
- যে দৃষ্টান্তগুলি একটি Redis স্টোরের তারিখ রিডিং তাদের নিজস্ব ঘড়ির সাথে ভাগ করে, তাই সেই ঘড়িগুলিকে সিঙ্কে রাখুন৷ ঘড়ির কাঁটা পিছনে চলে এমন একটি উদাহরণের রিডিংগুলি পুরানো দেখায় এবং উপেক্ষা করা হয়।
- সঞ্চিত রিসেট সময়ের পরে যখন কোনো ব্যবহারযোগ্য রিডিং আসে না, তখন রিডিং ফিরে না আসা পর্যন্ত প্রতি-কী শতাংশ শেয়ার এবং শতাংশ ক্যাপ প্রয়োগ করা হয় না। রিসেট সময় ছাড়াই, বইটি পরিবর্তন করা শেষ পড়ার 15 মিনিট পরে এটি শুরু হয়।
- Redis স্টোরে, একজন লেখকের চেক এবং তার লেখার মধ্যে একটি বই 60 দিনের জন্য নিষ্ক্রিয় হয়ে যেতে পারে। তারপর এটি 1 এর উপরে একটি সংশোধনে পুনরায় তৈরি করা হয়, যা একটি বৈধ অবস্থা।

## পাইপলাইন ইন্টিগ্রেশন

### PRE হুক (`open-sse/handlers/chatCore.ts`)

প্রমাণীকরণ এবং নীতি পরীক্ষা করার পরে আপস্ট্রিম নির্বাহকের আগে চলে:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → getQuotaStore().peek() per dimension
      → fairShare.decideFairShare()
      → if block → return 429 (buildErrorBody, Hard Rule #12)
      → if allow + deprioritize → set quotaSoftPenalty=true on candidate
  → executor.execute()
```

**ব্যর্থ-খোলা** : যদি `enforceQuotaShare` নিক্ষেপ করে, তাহলে অনুরোধটি একটি `pino.warn` লগের মাধ্যমে অনুমোদিত হয়। এটি একটি কোটা-ইঞ্জিন বাগকে সমস্ত ট্র্যাফিক ব্লক করতে বাধা দেয়৷

**যখন ক্ষমতা ফিরে আসে।** চাবির অংশে বা পুল সিলিং-এ একটি প্রত্যাখ্যান দুটি বাক্যের একটি দিয়ে শেষ হয়, উভয় ধার মোডে:

- `percent` উইন্ডো: `. The <window> window resets at <time>.` প্রদানকারী রিপোর্ট রিসেট করার সময়।
- গণনাযোগ্য একক: `. Enough <window> usage is expected to clear by <time>.` সময় হল স্লাইডিং উইন্ডো থেকে একটি উপরের বাউন্ড, যদি কী অন্য কিছু না পাঠায়।

`<time>` হল UTC এ একটি ISO 8601 তাত্ক্ষণিক। প্রত্যাখ্যান তারপর `Retry-After` বহন করে : সেই তাৎক্ষণিক পর্যন্ত পুরো সেকেন্ড, প্লাস ওয়ান। একটি ক্লায়েন্ট যে দীর্ঘক্ষণ অপেক্ষা করে তাত্ক্ষণিক পরে সর্বাধিক এক সেকেন্ডে পুনরায় চেষ্টা করে। যখন তাৎক্ষণিক জানা যায় না, তখন প্রত্যাখ্যান বাক্য বা শিরোনাম বহন করে না। একটি পরম ক্যাপ প্রত্যাখ্যান বহন করে না. পাবলিক কোড `quota_share_blocked` থাকে।

একটি শেয়ার প্রত্যাখ্যান ভাগ করা সংযোগ স্পর্শ করে না। এটি কোন কুলডাউন সেট করে না, কোন মডেল লক এবং কোন প্রদানকারী ব্রেকার ব্যর্থতা, এবং পুলের অন্যান্য কীগুলি পরিবেশন করা হয়। যখন একটি কম্বোর প্রতিটি লক্ষ্য তার ভাগের চাবি প্রত্যাখ্যান করে, তখন কম্বো অপেক্ষা না করে 429 উত্তর দেয়। এর উত্তরটি `Retry-After` হিসাবে ইঙ্গিত বহন করে। এমবেডিং পাথ একই বাক্য দিয়ে তার প্রত্যাখ্যান শেষ করে এবং কোন `Retry-After` পাঠায় না।

### POST হুক (রেকর্ড খরচ)

একটি সফল প্রতিক্রিয়া পরে:

```
executor returns success
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → getQuotaStore().consume() per dimension
      → fail-open: errors logged as pino.warn, never propagated to client
```

**ড্রিফ্ট নোট** : যদি `consume` পোস্ট-প্রতিক্রিয়া ব্যর্থ হয়, রোলিং কাউন্টারটি কম গণনা করে। প্রদানকারীর সম্পৃক্ততা সংকেত (যেমন `anthropic-ratelimit-unified-5h-utilization`) পরবর্তী অনুরোধে বিশ্বব্যাপী অনুমান সংশোধন করে।

### কম্বো সফট পেনাল্টি (`open-sse/services/combo.ts`)

যখন `decision.deprioritize === true`:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // default 0.7
}
```

অন্যান্য সমস্ত স্কোরিং কারণের পরে জরিমানা প্রয়োগ করা হয়। এটি হার্ড-ব্লক না করে একটি স্যাচুরেটেড কী নির্বাচন করার স্বয়ংক্রিয়-কম্বো সম্ভাবনাকে হ্রাস করে।

## স্ব-সেবা কোটা API (অপ্ট-ইন)

`GET /api/v1/me/quota/{provider}` (এছাড়াও `/v1/me/quota/{provider}` এ পরিবেশিত হয়) একজন API কী ধারককে তাদের নিজস্ব কী দিয়ে পড়তে দেয়, শেয়ার করা সাবস্ক্রিপশনের কতটা তাদের এবং কী তাদের ব্লক করছে। রুটটি `src/server/selfService/quotaHandler.ts` এর উপর একটি পাতলা শেল; দৃশ্যটি `src/lib/quota/selfView.ts` দ্বারা নির্মিত এবং এর প্রতিক্রিয়া চুক্তিটি `src/shared/schemas/selfQuota.ts` (`SelfQuotaView` তে `docs/openapi.yaml`)।

### সক্ষম করা এবং প্রমাণীকরণ

- ফিচার পতাকা `QUOTA_SELF_PANEL`, ডিফল্ট `false`। এটি বন্ধ থাকাকালীন, রুটে পৌঁছানো একটি অনুরোধ 404 পায়। `REQUIRE_API_KEY=true` এর সাথে, ক্লায়েন্ট API নীতি 401 সহ একটি অনুপস্থিত বা অবৈধ কী প্রত্যাখ্যান করে রুটটি চলার আগে, পতাকা যাই হোক না কেন। কোন চাবি ছাড়া একটি অনুরোধ কিন্তু একটি সাইন ইন করা ড্যাশবোর্ড সেশন সেই নীতিটি পাস করে এবং রুটের নিজস্ব উত্তর পায়৷ পতাকাটি অন্যান্য পতাকার মত সমাধান করে (ড্যাশবোর্ড বা REST ওভাররাইড, তারপর একই নামের পরিবেশ পরিবর্তনশীল); [`FEATURE_FLAGS.md`](../reference/FEATURE_FLAGS.md) দেখুন।
- প্রতিটি পুলের ডিসপ্লে নাম এবং প্রতিটি শিডিউলের লেবেল পুলের কী হোল্ডারদের কাছে প্রশাসক যেভাবে লিখেছিলেন ঠিক সেইভাবে ফেরত দেওয়া হয়। পতাকা চালু করার আগে, পরীক্ষা করে দেখুন যে সেগুলি সেই কী হোল্ডারদের পড়ার জন্য উপযুক্ত।
- কী শুধুমাত্র শিরোনাম থেকে পড়া হয়: `Authorization: Bearer <key>` বা `x-api-key: <key>`। যখন উভয়ই পাঠানো হয়, প্রথমটি যেটি যাচাই করে তা ব্যবহার করা হয়। ক্যোয়ারী স্ট্রিং বা কুকির একটি কী উপেক্ষা করা হয়। সার্ভারের পরিবেশ কী প্রত্যাখ্যান করা হয়েছে (401)।
- কীটির জন্য `self:usage` সুযোগ প্রয়োজন (এটি ছাড়াই 403)।
- প্রদানকারীর সেগমেন্টটি ছাঁটা, ছোট আকারের এবং `^[a-z0-9][a-z0-9._-]{0,63}$` (অন্যথায় 400) এর বিরুদ্ধে চেক করা হয়, তারপর প্রদানকারী রেজিস্ট্রির মাধ্যমে সমাধান করা হয়, তাই `cc` এর মতো একটি উপনাম `claude` পুলগুলি পড়ে। `claude` এবং `anthropic` একই পুল পড়ে।

### প্রতিটি দৃশ্যমানতা কি দেখায়

| দৃশ্যমানতা      | প্রয়োজন                                                                           | ক্ষেত্র                                                                                                                                                                                                                                                           |
| --------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| নিজের শেয়ার    | `self:usage`                                                                       | `pools[]` (রেফ, নাম, প্রদানকারী, নীতি, ওজন, ক্যাপ), `dimensions[].yourShare`, `accounts[]` সহ `yourShare` ( `attributed` এবং `external` ছাড়া একটি `percent` উইন্ডোতে), `blocks`, `availableModels`, `expiresAt`, `apiBaseUrl`                                    |
| অ্যাকাউন্ট স্তর | `self:usage` + `self:account-quota`, এবং কী-এর `sharedQuotaProviders` এ প্রদানকারী | একটি `percent` উইন্ডোর `yourShare` এ `dimensions[].total`, `accounts[].dimensions[].account` এবং `accounts[].modelWindows`, `attributed` এবং `external` যোগ করে এবং সদস্যের ব্যবহার চালু সহ একটি পুলে `members` যোগ করে ( [সদস্যের ব্যবহার](#member-usage) দেখুন) |

- `sharedQuotaProviders` হল একটি প্রতি-কী সেটিং (`PUT /api/keys/[id]/self-service`): `null`, ডিফল্ট, মানে প্রতিটি প্রদানকারীর কাছে কী পৌঁছায়; `[]` মানে কোনটাই নয়। প্রতিটি পুলের `accountVisible` বলে যে এটিতে কোন দৃশ্যমানতা প্রয়োগ করা হয়েছে৷
- অ্যাকাউন্ট বার এবং মডেল উইন্ডোগুলি শুধুমাত্র সেই অ্যাকাউন্টগুলির জন্য দেখানো হয় যার সংযোগ কী ব্যবহার করতে পারে। যখন কীটিতে অনুমোদিত সংযোগের একটি তালিকা থাকে, তখন এর বাইরের একটি অ্যাকাউন্ট `account` বা `modelWindows` ছাড়াই `Account N` এন্ট্রি রাখে। একটি খালি তালিকা মানে কোন সীমাবদ্ধতা নেই, যেমন `/v1/me/status`. পুল মোট (`dimensions[].total`) সেই তালিকার উপর নির্ভর করে না।
- শুধুমাত্র `self:usage` দিয়ে দেখানো দুটি পরিসংখ্যান অন্য কী'র ব্যবহার থেকে আসে। একটি শিডিউল বাজেটের `exhausted` সেই সময়সূচীর অধীনে প্রতিটি কী ব্যবহার প্রতিফলিত করে। একটি পুলে যার ওজন সবই শূন্য, কীটির `weight` হল `100 / number of members`। উভয়ই কী এনফোর্সমেন্ট চাবিতে প্রযোজ্য।
- একটি পুল শুধুমাত্র `ref` দ্বারা চিহ্নিত করা হয়, একটি অস্বচ্ছ মান যা কলিং কী এর সাথে আবদ্ধ। এটির প্রদর্শনের নাম (`name`) অন্তর্ভুক্ত করা হয়েছে যেহেতু প্রশাসক এটি লিখেছেন৷ একটি `ref` সার্ভারের API-কী গোপন (`API_KEY_SECRET`) সহ কী এবং পুল থেকে উদ্ভূত হয়। ক্লায়েন্টদের অবশ্যই এটি চালিয়ে যাওয়া উচিত নয়: যদি সেই গোপনীয়তা ঘোরানো হয় তবে এটি পরিবর্তিত হয়।
- অ্যাকাউন্টগুলি পুল ক্রমে `Account 1`, `Account 2`, … হিসাবে তালিকাভুক্ত করা হয়েছে। কোনো পুল আইডি, সংযোগ আইডি, অ্যাকাউন্ট ই-মেইল বা অ্যাকাউন্টের নাম ফেরত দেওয়া হয় না, এবং প্রতিক্রিয়া চুক্তির স্কিমার মাধ্যমে যায়, যা এটির বাইরের যেকোনো ক্ষেত্রকে ড্রপ করে।
- গণনাযোগ্য ইউনিটগুলি (`requests`, `tokens`, `usd`) পুল বাকেট হিসাবে রিপোর্ট করা হয়েছে যে কোটা গেট প্রয়োগ করে: `limit` = প্ল্যান সীমা × পুলে অ্যাকাউন্ট, `fairShare` = ওজন / 100 × `limit` (সমান বিভক্ত যখন প্রতিটি কাউন্টার = এর নিজস্ব ওজন হয়), `consumed`, `remaining` = `fairShare` − `consumed`, 0 এ ফ্লোর করা হয়েছে।
- `blocks.schedules` কী-এর শিডিউল উইন্ডোর তালিকা করে (`open`/`closed`, `blackout` বা `outside-window`, `retryAfterSeconds`, রিজার্ভ ফ্লোর, এবং উইন্ডোর বাজেট খরচ হয়েছে কিনা); `blocks.modelCaps` তার প্রতি-মডেল প্রতি ঘন্টার ক্যাপগুলিকে খরচ সহ তালিকাভুক্ত করে।
- প্রদানকারীর প্রতিটি পুলের বাইরে একটি চাবি `pools: []` সহ 200 পায়; `availableModels` ( `qtSd/` আইডিগুলি কী `/v1/models` তে দেখে), `expiresAt` এবং `apiBaseUrl` এখনও পূর্ণ।
- `apiBaseUrl` হল `OMNIROUTE_PUBLIC_API_BASE_URL`, তারপর `OMNIROUTE_PUBLIC_BASE_URL`, অন্যথায় `null`। এটি কখনই অনুরোধের নিজস্ব উত্স নয়।

### `status` এবং `reason`

| `status`      | অর্থ                                                                                                                                                                                                                                                                                                                                                      |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ok`          | একটি বর্তমান পড়া.                                                                                                                                                                                                                                                                                                                                        |
| `stale`       | একটি ক্যাশ করা অ্যাকাউন্ট রিডিং বাসি হিসাবে চিহ্নিত করা হয়েছে, বা যার রিসেট সময় এটি পড়ার পরে কেটে গেছে৷ নম্বর রাখা হয়। একটি মডেল উইন্ডো যার রিসেট সময় পার হয়ে গেছে পুরো `modelWindows` গ্রুপ `stale` কে চিহ্নিত করে। একটি `percent` উইন্ডোর কী এর নিজস্ব ভাগের জন্য: বইটি নিশ্চিত করার জন্য গেটের ক্যাশে একটি অ্যাকাউন্ট রিডিং ছাড়াই পড়া হয়েছিল৷ |
| `unavailable` | পড়া নেই; সংখ্যাগুলি `null`, কখনও `0`। `reason` বলে কেন।                                                                                                                                                                                                                                                                                                  |

| `reason`                          | কখন                                                                                                                                              |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `store_unavailable`               | কোটা দোকান পড়া যাবে না, বা এটা অ্যাট্রিবিউশন বই পড়তে পারে না.                                                                                  |
| `percent_attribution_unavailable` | একটি `percent` উইন্ডোর কী এর নিজস্ব ভাগ: সেই অ্যাকাউন্ট এবং উইন্ডোর জন্য কোনো অ্যাট্রিবিউশন বই এখনও বিদ্যমান নেই, বা বইটি কী তালিকাভুক্ত করে না। |
| `percent_window_ended`            | একটি `percent` উইন্ডোর কী এর নিজস্ব ভাগ: বইটি একটি প্ল্যান উইন্ডোর অন্তর্গত যা শেষ হয়েছে৷                                                       |
| `account_not_used_by_key`         | একটি `percent` উইন্ডোর কী এর নিজস্ব ভাগ: অ্যাকাউন্টের সংযোগ কীটির অনুমোদিত সংযোগের বাইরে। এর বই পড়া হয় না।                                     |
| `window_not_reported`             | সেই প্ল্যান উইন্ডোর জন্য প্রদানকারী-সীমা ক্যাশে কোন রিডিং নেই।                                                                                   |
| `connection_lookup_failed`        | অ্যাকাউন্টের সংযোগ পড়া যায়নি.                                                                                                                  |
| `not_supported`                   | OmniRoute অ্যাকাউন্টের প্রদানকারীর ব্যবহারের সীমা পড়তে পারে না।                                                                                 |
| `fetch_failed`                    | কোনো ক্যাশে করা পড়া ব্যবহারযোগ্য ছিল না এবং প্রদানকারী-সীমা রিফ্রেশ ব্যর্থ হয়েছে।                                                              |
| `not_available`                   | রিডিং কোন ইউসেজ উইন্ডো বহন করে, বা অ্যাকাউন্টের কোন রিডিং নেই।                                                                                   |

যখন কোটা স্টোর পড়া যায় না, তখন `blocks` এর স্টোর-ব্যাকড ক্ষেত্রগুলি (একটি সময়সূচী বাজেটের `exhausted`, একটি মডেল ক্যাপের `consumed` এবং `reached`) `null` হয়।

### ঋণ প্রদানের সম্মতি

`PATCH /api/v1/me/quota/{provider}` একটি পুলের জন্য কলিং কী-এর নিজস্ব সম্মতি রেকর্ড করে। এটি `GET` এর পতাকা, শিরোনাম এবং প্রদানকারীর নিয়ম ব্যবহার করে। `self:usage` স্কোপ এই লেখাটিকে অনুমোদন করে, যদিও এর নামটি শুধুমাত্র পঠনযোগ্য হিসেবে পড়ে।

```json
{
  "pool": "qpr_0123456789abcdef0123456789abcdef",
  "lendingPercent": 30,
  "lendingUntil": 1893456000000
}
```

- `pool` হল `ref` সেই পুলের জন্য `GET` রিটার্ন করে।
- `lendingPercent` হল 0 থেকে 100 পর্যন্ত একটি পূর্ণসংখ্যা। 0 এর মান সম্মতি এবং এর সময়সীমা পরিষ্কার করে। `lendingPercent` 0 সহ একটি বডি উভয় মোডে গৃহীত হয়।
- `lendingUntil` ঐচ্ছিক: epoch মিলিসেকেন্ড, অথবা `null` কোনো সময়সীমা ছাড়াই। এটি অবশ্যই ভবিষ্যতে এবং সর্বাধিক 8640000000000000 হতে হবে। 1000000000000 এর নিচের একটি মান সেকেন্ড হিসাবে পড়ে এবং প্রত্যাখ্যান করা হয়।
- অন্য কোন ক্ষেত্র প্রত্যাখ্যান করা হয়. 4096 বাইটের বেশি একটি বডি প্রত্যাখ্যান করা হয়েছে। পড়া সেই আকারে থেমে যায়, তাই লম্বা শরীর কখনই পুরো ধরে রাখা যায় না।

চেকগুলি এই টেবিলের ক্রম অনুসারে চলে। প্রতিটি প্রত্যাখ্যান একটি নির্দিষ্ট বার্তা সহ স্ট্যান্ডার্ড এরর বডি ব্যবহার করে। এই চেকগুলির একটির দ্বারা প্রত্যাখ্যান কিছুই লেখে না।

| স্ট্যাটাস | বার্তা                                                                                             | কখন                                                       |
| --------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 404       | `Not found`                                                                                        | `QUOTA_SELF_PANEL` পতাকা বন্ধ.                            |
| 401       | `Valid API key required`                                                                           | কী অনুপস্থিত বা অবৈধ, অথবা সার্ভারের পরিবেশ কী।           |
| 403       | `API key lacks the self:usage scope`                                                               | মূলে `self:usage` অভাব রয়েছে।                            |
| 400       | `Invalid provider`                                                                                 | প্রদানকারী বিভাগটি অবৈধ৷                                  |
| 429       | `Too many lending changes. Retry later.`                                                           | কী তার সীমা অতিক্রম করেছে। উত্তরটি `Retry-After` বহন করে। |
| 400       | `Body must be { pool, lendingPercent, lendingUntil }. lendingPercent is an integer from 0 to 100.` | শরীর JSON নয়, খুব দীর্ঘ, বা স্কিমার সাথে মেলে না।        |
| 400       | `lendingUntil must be a Unix time in milliseconds`                                                 | সময়সীমা সেকেন্ড হিসাবে পড়া হয়.                         |
| 400       | `lendingUntil must be in the future`                                                               | সময়সীমা অনুরোধের সময় বা তার আগে।                        |
| 404       | `Pool not found`                                                                                   | `ref` এই প্রদানকারীর জন্য এই কী-এর কোনো পুলের নাম দেয়নি। |
| 403       | `Lending is not enabled for this pool`                                                             | পুলটি `saturation` মোডে এবং `lendingPercent` 0-এর উপরে।   |
| 500       | `Failed to build quota view`                                                                       | অন্য কোন ব্যর্থতা। এর কারণ সার্ভারে লগ ইন করা হয়েছে।     |

সীমা হল প্রতিটি কীর জন্য প্রতি 60 সেকেন্ডে 20টি অনুরোধ। প্রোভাইডার চেক পাস করা প্রতিটি অনুরোধ গণনা করা হয়, এমনকি একজন পরে প্রত্যাখ্যান করেছে বা যেটি কিছুই পরিবর্তন করে না। এটির নিজস্ব কাউন্টার রয়েছে, চাবির অনুরোধের হারের সীমা ছাড়াও।

একটি অনুরোধ যা সঞ্চিত সম্মতি পরিবর্তন করে একটি `quota.pool.lending.updated` অডিট রেকর্ড লিখে। এটি পুরানো এবং নতুন মানগুলির সাথে কীটির নামকরণ করে। একই বডি দুইবার প্রেরিত একবার লিখিত এবং একবার অডিট করে। সম্পূর্ণ `GET` ভিউ সহ উত্তরটি 200, লেখার পরে নির্মিত।

`GET` ভিউ নিম্নরূপ ঋণ প্রদানের প্রতিবেদন করে:

- প্রতিটি পুল `borrowMode` (`saturation` বা `consent`), এবং কী এর নিজস্ব `lendingPercent` এবং `lendingUntil` বহন করে।
- `lendingActive` শুধুমাত্র একটি `consent` পুলে `true` হয়, যার শতাংশ 0 এর উপরে থাকে এবং একটি নির্দিষ্ট সময়সীমা পৌঁছায়নি।
- একটি `consent` পুলে, প্রতিটি গণনাযোগ্য `dimensions[].yourShare` `borrowAvailable` বহন করে। এটি কি এখন তার ভাগের উপরে ব্যবহার করতে পারে, অন্যান্য কী দ্বারা ধার দেওয়া হয়েছে।
- `borrowAvailable` গেটের সূত্র ব্যবহার করে। এটি প্রতিটি অন্যান্য কী পাঠ করে, যখন কীটি তার ভাগের অধীনে থাকে। একটি `hard` কী এর জন্য যা সমান্তরালভাবে অন্যান্য কী এবং গণনাযোগ্য মাত্রা প্রতি একটি অতিরিক্ত পঠিত।
- `borrowAvailable` হল `soft` বা `burst` কী-এর জন্য `null`, এবং `null` যখন রিড ব্যর্থ হয়।
- `borrowAvailable` হল অন্য সব কীগুলির জন্য একটি চিত্র। দুটি কী এর পুলে এটি অন্য কীটির নিজস্ব চিত্র।
- `borrowAvailable` এখনও `percent` উইন্ডো বা `accounts[]` এর জন্য রিপোর্ট করা হয়নি।
- একটি `saturation` পুলে ভিউ `lendingActive: false` সাথে সঞ্চিত সম্মতি এবং `borrowAvailable` ছাড়াই রিপোর্ট করে।

### ত্রুটি

এই পথের প্রতিটি প্রতিক্রিয়া, সাফল্য বা ত্রুটি, `Cache-Control: no-store` বহন করে। একটি প্রত্যাখ্যান যা রুট চালানোর আগে ঘটে তা বহন করে না, উদাহরণস্বরূপ ক্লায়েন্ট API নীতির 401 বা IP ফিল্টারের 403। রুটের ত্রুটিগুলি একটি নির্দিষ্ট বার্তা সহ স্ট্যান্ডার্ড এরর বডি ব্যবহার করে: 400 (অবৈধ প্রদানকারী), 401 (অনুপস্থিত বা অবৈধ কী), 403 (মিসিং `self:usage`) এবং 403 (মিসিং) 403 (মিসিং) (`Failed to build quota view`) 500 যেকোন ব্যর্থতা কভার করে একবার অনুরোধটি রুটে পৌঁছালে, কী লুকআপ নিজেই সহ; এর কারণ সার্ভারে লগ করা হয়েছে এবং ফিরে আসেনি। `PATCH` এর ত্রুটিগুলি [ঋণদানের সম্মতিতে](#lending-consent) তালিকাভুক্ত করা হয়েছে।

### সীমাবদ্ধতা

- `remaining` হল কী এর ন্যায্য অংশের অংশ যা এটি ব্যবহার করেনি। এটা একটি গ্যারান্টি নয়. পুলের জায়গা থাকাকালীন একটি চাবি এখনও এটির বাইরে পরিবেশিত হতে পারে। একবার পুলের মোট `limit` এ পৌঁছালে, পুলের প্রতিটি কী প্রত্যাখ্যান করা হয়, তার নিজস্ব `remaining` যাই হোক না কেন, এবং `self:account-quota` ছাড়া একটি চাবি সেই মোট দেখতে পারে না।
- `remaining` বরাদ্দের পরম `cap` বিবেচনা করে না। এনফোর্সমেন্ট চাবিটি প্রত্যাখ্যান করে যখন ক্যাপের ইউনিটের একটি উইন্ডোতে তার নিজস্ব খরচ ক্যাপের মান পৌঁছে যায়।
- অ্যাকাউন্ট-লেভেল বার প্রদানকারী-সীমা ক্যাশে থেকে আসে এবং কয়েক মিনিটের মধ্যে প্রয়োগের সিদ্ধান্তে পিছিয়ে যেতে পারে। একটি রিডিং যার রিসেট সময় পেরিয়ে গেছে তাকে `stale` হিসাবে রিপোর্ট করা হয়।
- প্রতি-মডেল উইন্ডোজ (`modelWindows`) শুধুমাত্র সেইসব প্রদানকারীদের জন্য রিপোর্ট করা হয়েছে যাদের প্ল্যান-উইন্ডো ম্যাপিং আছে: Claude এবং Codex আজ। অন্যান্য প্রদানকারীদের জন্য `modelWindows` এখনও উপস্থিত থাকে যখন অ্যাকাউন্ট ডেটা দেখানো হয়, একটি খালি `windows` তালিকা সহ।
- একটি `percent` উইন্ডোর কী এর নিজস্ব ভাগ একটি অনুমান। এটি অ্যাট্রিবিউশন বই থেকে আসে এবং উপরে "শতাংশ মাত্রা: প্রতি-কী অ্যাট্রিবিউশন" এর অধীনে তালিকাভুক্ত প্রতিটি সীমাবদ্ধতা বহন করে৷
- `consumed` হল সংখ্যা প্রয়োগকারী ন্যায্য ভাগের সাথে তুলনা করে। এটা `attributed` প্লাস `external`, ঠিক। `attributed` হল সেই অংশ যা বইটি রাউট করা টোকেনের জন্য কী দেয়। `external` হল অ্যাকাউন্টের ব্যবহারের কী-এর অংশ যা পুলের কীগুলি অ্যাকাউন্ট করে না।
- উভয় অংশ শুধুমাত্র তখনই পাঠানো হয় যখন পুলের `accountVisible` সত্য হয়: কীটিতে `self:account-quota` আছে এবং প্রদানকারী তার `sharedQuotaProviders` এ থাকে। এটি ছাড়া একটি কী একই `status` এবং `reason` সহ `consumed` একা পায়।
- উভয় অংশ এবং তার নিজের ওজনের সাথে, একজন ধারক পুলের বাইরে যেটি পুলের চাবিতে চার্জ করা হয় তা ব্যবহার করতে পারে। অ্যাকাউন্টের স্কোপ সহ একজন ধারক ইতিমধ্যেই অ্যাকাউন্টের মোট পরিমাণ দেখেন।
- একটি কী যা উইন্ডোতে কিছুই রাউট করেনি তা এখনও `consumed` থেকে এর বাহ্যিক চার্জ পড়তে পারে, কারণ এর বৈশিষ্ট্যযুক্ত অংশটি তখন 0।
- উদাহরণস্বরূপ, একটি বই 0 এ খোলে, যার প্রতিটির ওজন 50 এ A এবং B কী আছে। কী A রুট করে 900,000 টোকেন এবং কী B 100,000। অ্যাকাউন্টটি তখন 100-এর সীমার 60%-এ পৌঁছে। তারপর `attributed` কী A-এর জন্য 54 এবং কী B-এর জন্য 6, এবং উভয়ের জন্য `external` হল 0।
- দৃষ্টিভঙ্গি বইটি পড়ে এবং কখনই তার অবস্থা লেখে না। এটি একটি বই খুলবে না, এবং এটি একটি পড়ার জন্য প্রদানকারীকে জিজ্ঞাসা করে না। Redis স্টোরের সাথে, একটি রিড পটভূমিতে স্থগিত করা সংশোধন ক্ষেত্রগুলিকে সরিয়ে দেয়, যেমন গেটের রিডগুলি করে।
- শেয়ারটি শুধুমাত্র তখনই `ok` হয় যখন গেটের ক্যাশে অ্যাকাউন্টের রিডিং থাকে। একটি ছাড়া এটি `stale`, তাই সাম্প্রতিক অনুরোধ ছাড়াই একটি পুলে এটি সম্ভবত পুরানো হিসাবে দেখায়৷
- যতক্ষণ না একটি অনুরোধ পুলের মধ্য দিয়ে যায়, শেয়ারটি অনুপলব্ধ। এই অনুরোধটি বইটি খোলে এবং সেই মুহূর্তে অ্যাকাউন্টের চিত্রটি পুলের বাইরে ব্যবহৃত হিসাবে গণনা করা হয়।
- একাধিক অ্যাকাউন্ট সহ একটি পুলে, প্রতিটি অ্যাকাউন্ট এন্ট্রি সেই অ্যাকাউন্টের নিজস্ব বই এবং একটি অ্যাকাউন্টের সীমা ব্যবহার করে। এনফোর্সমেন্ট অ্যাকাউন্টের সংখ্যা দ্বারা উভয় পক্ষের স্কেল করে, তাই অনুপাত একই।
- প্রতি-মডেল উইন্ডোতে চাবির জন্য কোন শেয়ার নেই। বইটি প্রতি-মডেলের কোনো ডেটা রাখে না।
- একটি সময়সূচীর রিজার্ভ ফ্লোরগুলি ভিউ দ্বারা মূল্যায়ন করা হয় না: একটি সময়সূচী `open` হিসাবে দেখাতে পারে যখন একটি অনুরোধ `schedule-reserve` কারণ সহ প্রত্যাখ্যান করা হয়।
- যখন একই কী এর দুটি পুল একটি সংযোগ ভাগ করে, তখন প্রয়োগকারী তাদের মধ্যে একটিকে প্রয়োগ করে এবং ভিউ উভয়েরই তালিকা করে।
- ব্যর্থ কী প্রচেষ্টার জন্য কোনো ঠিকানা-প্রতি সীমা নেই: বিপরীত প্রক্সি কলারের পিছনে একটি ঠিকানা শেয়ার করতে পারে (এটি ফরওয়ার্ড করা ক্লায়েন্ট ঠিকানাগুলি বিশ্বস্ত কিনা তার উপর নির্ভর করে), তাই একটি লকআউট প্রতিটি কী ধারকের রুটকে অস্বীকার করতে পারে। `REQUIRE_API_KEY=true` এর সাথে, রুট চলার আগে ক্লায়েন্ট API নীতি দ্বারা একটি অবৈধ কী প্রত্যাখ্যান করা হয়, এই রুটের পরিবর্তে সেই নীতির 401 বডি সহ।

### সদস্য ব্যবহার

একজন প্রশাসক কী হোল্ডারদের দেখতে দিতে পারেন কিভাবে একটি উইন্ডোর ব্যবহার পুলের সদস্যদের মধ্যে বিভক্ত হয়। বিকল্পটি হল পুলের `memberBreakdown`, ডিফল্টরূপে বন্ধ। এটি পুল উইজার্ডে বা `PATCH /api/quota/pools/{id}` এর সাথে সেট করা আছে। `GET /api/quota/pools` এবং `GET /api/quota/pools/{id}` এটা রিপোর্ট.

দৃষ্টিভঙ্গির একটি মাত্রা শুধুমাত্র তখনই `members` বহন করে যখন এই সবগুলি ধারণ করে:

- পুলের বিকল্প চালু আছে
- পুলটিতে সর্বাধিক 20টি বরাদ্দ করা কী রয়েছে এবং তাদের মধ্যে কমপক্ষে তিনটি অনুরোধ করতে পারে: সক্রিয়, প্রত্যাহার করা হয়নি, নিষিদ্ধ নয় এবং তাদের মেয়াদ শেষ হয়নি
- পুলের `accountVisible` সত্য: কীটিতে `self:account-quota` আছে এবং প্রদানকারী তার `sharedQuotaProviders` এ আছে
- একটি `percent` উইন্ডোতে, অ্যাকাউন্টের সংযোগ একটি কী ব্যবহার করতে পারে
- সেই উইন্ডোটির কীটির নিজস্ব অংশটি পড়া হয়েছিল: এর `status` `unavailable` নয়

অন্যথায় `members` অনুপস্থিত। এটি কখনই খালি তালিকা নয়।

- প্রতিটি স্লাইস `{ slot, consumed, isYou }` হয়। প্রতিক্রিয়া স্কিমা একটি স্লাইসে অন্য কোনো সম্পত্তি প্রত্যাখ্যান করে, এবং 20 টিরও বেশি স্লাইসের তালিকা। স্লাইস স্লট ক্রম তালিকাভুক্ত করা হয়.
- বরাদ্দকৃত কী প্রতি একটি স্লাইস রয়েছে, একটি কী সহ যা আর অনুরোধ করতে পারে না। কোন ব্যবহার ছাড়া একটি সদস্য একটি বাস্তব শূন্য দেখায়.
- `isYou` সত্য সহ স্লট 1 সর্বদা জিজ্ঞাসার কী। অন্যান্য স্লট নম্বরগুলি একটি কীড হ্যাশের র্যাঙ্ক। এটি `API_KEY_SECRET` দিয়ে চাবিযুক্ত এবং পুল, জিজ্ঞাসা কী এবং সদস্যকে কভার করে।
- তাই সংখ্যা ধারকদের মধ্যে লাইন আপ হয় না. এক ধারকের জন্য তারা ভিজিটের মধ্যে একই থাকে। তারা পরিবর্তন করতে পারে যখন একটি কী যোগ দেয় বা পুল ছেড়ে যায়, বা যখন সেই গোপনটি ঘোরানো হয়।
- একটি গণনাযোগ্য উইন্ডোতে একটি স্লাইস হল কোটা স্টোরের সদস্যের কাউন্টার, তার নিজস্ব `consumed` মতো একই কাউন্টার।
- একটি `percent` উইন্ডোতে একটি স্লাইস সদস্যের `attributed` অংশ, একই বই থেকে চাবির নিজস্ব ভাগ হিসাবে পড়া হয়। পুলের বাইরে তৈরি ব্যবহার কখনোই টুকরো টুকরো করে বিভক্ত হয় না। এই চার্জটি ওজন দ্বারা বিভক্ত, তাই এটি বহনকারী স্লাইসগুলি ওজন দেখাবে।
- প্রতিটি ভিউ অন্যান্য সদস্যের প্রতি একটি মান পড়ে এবং সমান্তরালে গণনাযোগ্য উইন্ডো। একটি `percent` উইন্ডোতে স্লাইসগুলির জন্য শেয়ারের নিজের পড়া বইয়ের বাইরে কোনও পড়ার খরচ নেই৷ যখন একটি মান পড়া যায় না, সেই উইন্ডোতে কোন `members` থাকে না এবং কীটির নিজস্ব শেয়ার থাকে।
- বিকল্প এবং ব্যবহারযোগ্য কীগুলির সংখ্যা প্রতি পুলে একবার পড়া হয়, এবং শুধুমাত্র একটি কী যা অ্যাকাউন্ট ডেটা দেখতে পারে। বিকল্প বা ব্যবহারযোগ্য-কী গণনার ব্যর্থ পড়া সেই পুলের জন্য বারগুলিকে বন্ধ করে দেয়। সার্ভার একটি সতর্কতা লগ করে, এবং বাকি দৃশ্য নির্মিত হয়।

বার কোন নাম বা আইডি বহন. তারা এখনও অন্যান্য সদস্যদের সম্পর্কে একটি মূল হোল্ডার জিনিস বলে:

- হোল্ডাররা এখনও তাদের মান অনুযায়ী স্লাইস মেলতে পারে।
- একটি স্থিতিশীল সংখ্যায়ন একজন ধারককে সময়ের সাথে একজন সদস্যকে অনুসরণ করতে দেয়।
- স্লাইসের সংখ্যা দেখায় যে পুলে কতগুলি কী বরাদ্দ করা হয়েছে।
- তিনটি কীর একটি পুলে, যে কেউ জানে যে একটি কী কী ব্যবহার করেছে তা বলতে পারে শেষ কীটি কী ব্যবহার করা হয়েছে।
- যখন একটি পুল তিনটি ব্যবহারযোগ্য কী নীচে নেমে যায়, বারগুলি অদৃশ্য হয়ে যায়। আগে নেওয়া ভিউগুলি এখনও দেখায় যে প্রতিটি সদস্য কী ব্যবহার করেছেন৷
- একটি গণনাযোগ্য উইন্ডোতে, পুলের মোট বিয়োগ স্লাইসগুলি এমন কীগুলির ব্যবহার দেখাতে পারে যা আর বরাদ্দ করা হয় না।
- একজন সদস্য যে একটি অ্যাকাউন্টে শূন্য দেখায় এবং অন্যটিতে ব্যবহার দেখায় কোন সদস্য কোন অ্যাকাউন্ট ব্যবহার করে তা দেখাতে পারে।
- `hard` নীতির সাথে একটি গণনাযোগ্য পুলে, একজন সদস্যের ন্যায্য ভাগে বাড়তে থাকা একটি স্লাইস সেই সদস্যের ওজনের ইঙ্গিত দেয়।

### ব্যবহার সিরিজ (`GET /api/v1/me/usage`)

`GET /api/v1/me/usage?range=<range>` (এছাড়াও `/v1/me/usage` এ পরিবেশিত হয়) কলিং কী এর নিজস্ব অনুরোধের ব্যবহার এবং খরচ ফেরত দেয়: মোট, প্রতি UTC দিনে একটি এন্ট্রি, প্রতি দিন এবং মডেল, প্রতি মডেল এবং প্রতি প্রদানকারী। এটি পতাকা, প্রমাণীকরণের নিয়ম, `self:usage` সুযোগ, `Cache-Control: no-store` এবং উপরের কোটা রুটের ত্রুটি আচরণ শেয়ার করে। `range` এর আগে কী চেক করা হয়। ত্রুটিগুলি হল 400 (`Invalid range`), 401, 403, 404 এবং 500 (`Failed to build usage`)।

- `range` হল `1d`, `7d`, `30d` (ডিফল্ট) বা `90d` এর মধ্যে একটি। অন্য কোন মান, একটি খালি মান বা পুনরাবৃত্তি করা প্যারামিটার হল একটি 400। সেটটি `90d` এ থামে একটি কলের খরচ আবদ্ধ করতে। ভিউটি শুধুমাত্র কাঁচা ব্যবহারের ইতিহাস পড়ে, কখনোই দৈনিক সারাংশ নয়, যার কোন চাবি নেই।
- সারি কলিং কী এর আইডি দ্বারা নির্বাচন করা হয়. কী নামের কলাম কখনই মেলে না এবং কী আইডি ছাড়া রেকর্ড করা সারিগুলি কখনই গণনা করা হয় না।
- একটি সিরিজ তৈরি করলে উইন্ডোতে কী এর সারিগুলির উপর পাঁচটি গ্রুপ করা প্রশ্ন চলে। নির্মিত সিরিজটি প্রতি কী এবং পরিসরে 60 সেকেন্ডের জন্য পুনরায় ব্যবহার করা হয় এবং একটি পুনঃব্যবহৃত কল কোনটিই চালায় না। এর `generatedAt` তার বয়স দেয়।
- সিরিজটি নির্মিত হলে উইন্ডোটি শেষ হয়। পরে স্ট্যাম্প করা একটি সারি, উদাহরণস্বরূপ ঘড়ির তির্যক দ্বারা, গণনা করা হয় না।
- `coverage.retentionDays` হল অপারেটরের কাঁচা ব্যবহার-ইতিহাস ধরে রাখার সেটিং (ডাটাবেস সেটিংসে`retention.usageHistory` )। `coverage.truncatedByRetention` সত্য হয় যখন অনুরোধ করা পরিসীমা সেই সেটিং থেকে দীর্ঘ হয়। এটি দুটি সংখ্যার তুলনা করে এবং সারিগুলি আসলে অনুপস্থিত কিনা তা পরীক্ষা করে না।
- কী এর নিজস্ব অনুরোধের জন্য নথিভুক্ত হিসাবে প্রদানকারীকে ফেরত দেওয়া হয়। মডেল হল এর শেষ `/` এর পরে রেকর্ড করা নাম, এবং সারিগুলি এটি দ্বারা গোষ্ঠীবদ্ধ করা হয়েছে। একটি কম্বো অনুরোধ যার প্রতিটি লক্ষ্য প্রত্যাখ্যান করা হয়েছিল তা প্রদানকারী হিসাবে রাউটিং লেবেল (কম্বো নাম, `auto` বা `combo`) এবং ক্লায়েন্টের পাঠানো মডেল স্ট্রিং সহ রেকর্ড করা হয়। অন্যান্য প্রত্যাখ্যান করা অনুরোধ, উদাহরণস্বরূপ একটি খোলা সার্কিট ব্রেকার, একটি মডেল কুলডাউন বা একটি কোটা-পার্ক করা স্কিপ, লক্ষ্য প্রদানকারী এবং মডেল রাখুন।
- গণনা এবং খরচ ছাড়াও, প্রতিক্রিয়া গড় বিলম্বতা, সাফল্যের হার এবং প্রথম এবং শেষ অনুরোধের সময় বহন করে।
- `byModel` সর্বাধিক অনুরোধ সহ 50টি প্রদানকারী-এবং-মডেল জোড়ার তালিকা করে। আরও জোড়ার সাথে এর এন্ট্রিগুলি `summary` পর্যন্ত যোগ করে না, এবং `summary.uniqueModels` প্রতিটি রেকর্ড করা মডেলের বানান গণনা করে। `byModelTruncated` তারপর সত্য, এবং একটি মডেল যার জোড়া কাটার উভয় পাশে পড়ে আংশিক মোট দেখায়।
- দুই খরচ রিপোর্ট করা হয়. `costUsd` হল বিল করা খরচ, যেমন ব্যবহার বিশ্লেষণ এটি দেখায়। ফ্ল্যাট-রেট সাবস্ক্রিপশন প্রদানকারী, যেমন Claude কোড প্ল্যান, সেখানে $0 গণনা করুন। `listPriceUsd` হল একই ব্যবহার তালিকা মূল্যে, সদস্যতা অন্তর্ভুক্ত। একটি অনুরোধ যার মডেলের কোনো মূল্য সারি নেই তার সঞ্চিত খরচ গণনা করে: প্রদানকারীর প্রতিবেদন করা একটি খরচ, অথবা অনুরোধটি রেকর্ড করার সময় গণনা করা হয়। শুধুমাত্র একটি অনুরোধ যার কোনটিই 0 গণনা করে না, কোন মার্কার ছাড়াই, তাই মোট আংশিক হতে পারে।
- প্রতিক্রিয়া চুক্তি হল `src/shared/schemas/selfUsage.ts` (`SelfUsageSeries` তে `docs/openapi.yaml`)।

### স্ব-পরিষেবা পাতা

`QUOTA_SELF_PANEL` চালু থাকলে, `/quota/{provider}` হল একটি সর্বজনীন পৃষ্ঠা। একটি কী ধারক সেখানে একটি API কী টাইপ করে এবং সেই কীটির পুল সরবরাহকারীর জন্য দেখে। প্রতিটি পুল প্রত্যেকের জন্য পুলের ব্যবহার এবং চাবির নিজস্ব ভাগ সহ, প্রতি পুল উইন্ডোতে একটি কার্ড দেখায়। পুলের প্রতিটি অ্যাকাউন্টের নিজস্ব কার্ড রয়েছে, অ্যাকাউন্টের ব্যবহার এবং কী এর ভাগ সহ। অ্যাকাউন্টের ব্যবহার তখনই দেখা যায় যখন কী অ্যাকাউন্টের ডেটা দেখতে পারে। পৃষ্ঠাটি প্রতিটি অ্যাকাউন্টের প্রতি-মডেলের সীমা এবং কীটির নিজস্ব ব্যবহারের তালিকাও করে। একটি সময়সূচী এই মুহূর্তে কী ব্লক করলে একটি বিজ্ঞপ্তি উপস্থিত হয়। একটি কার্ড কীটির প্রতি-মডেল ক্যাপকে তার ব্যবহারের সাথে তালিকাভুক্ত করে এবং পৌঁছে যাওয়াগুলি চিহ্নিত করে। `{provider}` হল একটি প্রদানকারী আইডি বা এর উপনাম (`/quota/claude`, `/quota/cc`)। একটি অজানা প্রদানকারী, এবং পতাকা বন্ধ থাকাকালীন প্রতিটি `/quota/*` পাথ, উত্তর 404. একটি কাস্টম OpenAI- বা অ্যানথ্রোপিক-সামঞ্জস্যপূর্ণ নোডের পুলগুলির কোনও পৃষ্ঠা নেই৷ API এখনও তাদের জন্য উত্তর.

পৃষ্ঠাটির কোনো সেশন নেই। কীটি শুধুমাত্র `GET /api/v1/me/quota/{provider}`, `PATCH /api/v1/me/quota/{provider}` এবং `GET /api/v1/me/usage` এর `Authorization` হেডারে পাঠানো হয়, কখনও URL তে নয়। সার্ভার গ্রহণ করে একটি কী ট্যাবের `sessionStorage` এ রাখা হয়। "এই ডিভাইসে মনে রাখুন" এর পরিবর্তে এটি `localStorage` এ রাখা হয় এবং "Forget key" উভয় থেকে এটি সরিয়ে দেয়। সার্ভার প্রত্যাখ্যান করা একটি কী স্টোরেজ থেকে সরানো হয়।

`consent` মোডে একটি পুল একটি ঋণ কার্ড দেখায়। সেখানে কী ধারক ধার দেওয়ার জন্য কীটির নিষ্ক্রিয় শেয়ারের 0 থেকে 100 পর্যন্ত পুরো শতাংশ সেট করে। সম্মতি কতক্ষণ স্থায়ী হবে তাও ধারক বেছে নেন: বন্ধ না হওয়া পর্যন্ত, 1 ঘন্টা, 8 ঘন্টা, 24 ঘন্টা, 7 দিন বা 30 দিন। একটি সময়কাল সংরক্ষণের মুহূর্ত থেকে গণনা করা হয়। একটি সময়সীমা বলবৎ থাকাকালীন, ধারক তার পরিবর্তে এটি রাখতে পারেন। যদি সেই সময়সীমা সেভ করার আগে চলে যায়, কার্ডটি কিছুই পাঠায় না এবং অন্য পছন্দের জন্য জিজ্ঞাসা করে। 0% এর সাথে কোন সময়সীমা পাঠানো হয় না। কার্ডটি তার টাইম জোন নাম দিয়ে সঞ্চিত সময়সীমা দেখায়। একটি সম্মতি যার সময়সীমা অতিক্রান্ত হয়েছে শেষ হিসাবে দেখানো হয়েছে৷

একটি `hard` কী-এর জন্য কার্ডটি তালিকা করে, প্রতি পুল উইন্ডোতে, এই মুহূর্তে অন্য কী কী কী ধার দেয়। প্রতিটি সারি একসাথে অন্যান্য সমস্ত কীগুলির জন্য একটি চিত্র। দুটি কী এর পুলে এটি অন্য কীটির নিজস্ব চিত্র। যে চিত্রটি ভিউ রিপোর্ট করে না তা উপলব্ধ নয় হিসাবে পড়া হয়, শূন্য হিসাবে নয়। একটি `soft` বা `burst` কী-এর জন্য কার্ডটি বলে যে কোনও চিত্র প্রযোজ্য নয়।

`saturation` মোডে একটি পুল যার কী শতাংশ 0-এর উপরে সঞ্চয় করে তা শুধুমাত্র প্রত্যাহার দেখায়। এটি বলে যে সঞ্চিত শতাংশের সেখানে কোন প্রভাব নেই। এর উইথড্র বাটন কোন সময়সীমা ছাড়াই 0 পাঠায়। একটি সঞ্চিত 0 সহ `saturation` মোডে একটি পুল কোন ঋণ কার্ড দেখায় না। একটি সংরক্ষণ করার পরে, একটি কার্ড যেটি ফেরত দেওয়া ভিউটির আর প্রয়োজন হয় না সেটির বার্তার সাথে থাকে যতক্ষণ না পৃষ্ঠাটির দৃশ্য আবার পরিবর্তিত হয়।

ধারক সংরক্ষণ বা প্রত্যাহার না করা পর্যন্ত কিছুই সংরক্ষিত হয় না। প্রতিটি প্রেস একটি `PATCH /api/v1/me/quota/{provider}` অনুরোধ পাঠায়, এবং একটি দ্বিতীয় প্রেস কিছুই পাঠায় না যখন প্রথমটি মুলতুবি থাকে। দেহটি দৃশ্য, শতাংশ এবং সময়সীমা থেকে পুলের অস্বচ্ছ `ref` বহন করে। উত্তর হল পুনঃনির্মিত কোটা ভিউ, এবং পৃষ্ঠাটি দ্বিতীয়বার পড়া ছাড়াই দেখায়। যখন দুটি ওভারল্যাপ সংরক্ষণ করে, পৃষ্ঠাটি শেষ উত্তরের পরে একবার কোটা পড়ে। পৃষ্ঠাটি ব্রাউজার স্টোরেজে সম্মতি রাখে না।

একটি প্রত্যাখ্যান করা পরিবর্তন কার্ডে HTTP স্ট্যাটাস থেকে নির্বাচিত একটি পাঠ্য দ্বারা ব্যাখ্যা করা হয়েছে। ত্রুটি শরীর পড়া হয় না. একটি 401 বলছে কী গ্রহণ করা হয়নি এবং কোটা পুনরায় লোড করে। একটি 403 বলছে পুল ঋণ পরিবর্তন করছে না, এবং একটি 404 বলছে পুল চলে গেছে৷ উভয়ই একটি বোতাম অফার করে যা কোটা পুনরায় লোড করে। একটি 400 বা অন্য 4xx উত্তর ধারককে শতাংশ এবং সময়সীমা পরীক্ষা করতে বলে। A 429 ধারককে অপেক্ষা করতে বলে, `Retry-After` এর সেকেন্ড সহ যখন উত্তর দেয়। একটি 5xx উত্তর, একটি 408 বা একটি নেটওয়ার্ক ব্যর্থতা বলে যে পরিবর্তনটি সংরক্ষিত নাও হতে পারে এবং টাইপ করা মানগুলি রাখে৷ চুক্তির বাইরে একটি উত্তর কোটা পুনরায় লোড করে। একটি ব্যর্থ সংরক্ষণ কী নিজে থেকে সরিয়ে দেয় না। পুনরায় লোড করার পরে যখন এটি প্রত্যাখ্যান করা হয়, তখন পৃষ্ঠাটি কোন প্রত্যাখ্যান করা পড়ার মতো কীটি সরিয়ে দেয়।

একবার একটি কী গৃহীত হলে, পৃষ্ঠাটি তিনটি ট্যাব সহ একটি "আপনার সরঞ্জাম সেট আপ করুন" কার্ডও দেখায়৷ "Claude কোড" `~/.claude/settings.json` জন্য `env` ব্লক দেয়। "শেল" `export` লাইনের মতো একই ভেরিয়েবল দেয়। "Claude Desktop" তার তৃতীয় পক্ষের অনুমান উইন্ডোর মান দেয়। মডেলগুলি হল কোটা-শেয়ার মডেলগুলি যা সেই প্রদানকারীর জন্য কী কল করতে পারে৷ যখন এই ধরনের কোন তালিকা কী সহ আসে না, ব্লকটি পরিবর্তে গেটওয়ে মডেল আবিষ্কার চালু করে। গেটওয়ে ঠিকানা হল সার্ভার রিপোর্টের সর্বজনীন API মূল (`OMNIROUTE_PUBLIC_API_BASE_URL`, তারপর `OMNIROUTE_PUBLIC_BASE_URL`)। যখন কোনটিই সেট করা হয় না, কার্ডটি একটি স্থানধারক দেখায় এবং ধারককে প্রশাসককে জিজ্ঞাসা করতে বলে৷ কী একটি স্থানধারক হিসাবে দেখানো হয়. "আমার কী অন্তর্ভুক্ত করুন" পুরো কীটিকে স্ক্রীনের পাঠ্যের মধ্যে রাখে এবং একটি অনুলিপি বোতামে যা অনুলিপি করে। বাক্সটি সাফ না হওয়া পর্যন্ত, চাবিটি ভুলে যাওয়া বা প্রতিস্থাপন করা বা পৃষ্ঠাটি অবশিষ্ট না হওয়া পর্যন্ত এটি স্থায়ী হয়। কার্ড কোনো অনুরোধ পাঠায় না এবং কোনো ফাইল ডাউনলোডের প্রস্তাব দেয় না।

একটি API চিহ্ন `stale` পড়া সম্ভবত পুরানো হিসাবে দেখানো হয়েছে৷ একটি রিডিং এটি `unavailable` চিহ্নিত করে তার কারণ সহ দেখানো হয়, কখনও শূন্য নয়।

শতকরা প্ল্যানের উপর পৃষ্ঠাটি কী এর নিজস্ব ভাগ আঁকে যখন API এটি রিপোর্ট করে। এটি বলে যে সংখ্যাটি একটি অনুমান এবং এর দুটি অংশের নাম। প্রতি-মডেল সীমা শুধুমাত্র অ্যাকাউন্ট দেখায়।

যখন একটি উইন্ডো `members` বহন করে, তখন এর কার্ডটি স্লট ক্রমে, সদস্য প্রতি একটি অংশ সহ একটি বারও দেখায়। জিজ্ঞাসা কী এর সেগমেন্ট অ্যাকসেন্ট রঙ ব্যবহার করে। অন্যান্য বিভাগগুলি থিমের চার্টের রঙগুলির মাধ্যমে চক্রাকারে চলে। একটি পাঠ্য কিংবদন্তি প্রতিটি সেগমেন্টকে তার মান সহ তালিকাভুক্ত করে, তাই কিছুই রঙের উপর নির্ভর করে না। সেগমেন্টগুলিকে `You` বা `Member N` লেবেল করা হয়, যেখানে N হল স্লট।

### পেজের জন্য ডেডিকেটেড পোর্ট

`QUOTA_PANEL_PORT` একটি দ্বিতীয় শ্রোতা খোলে যেটি শুধুমাত্র স্ব-পরিষেবা পৃষ্ঠাটি পরিবেশন করে। ভেরিয়েবল সেট না হলে এটি বন্ধ। `QUOTA_PANEL_HOST` হল আবদ্ধ ঠিকানা এবং `127.0.0.1` এর সাথে ডিফল্ট।

শ্রোতা এই পথগুলিকে প্রধান বন্দরে রিলে করে এবং প্রতিটি অন্য পথের জন্য 404 উত্তর দেয়:

| পথ                                                                       | পরিবেশন করে                      |
| ------------------------------------------------------------------------ | -------------------------------- |
| `/quota/{provider}`                                                      | পাতা                             |
| `/api/v1/me/quota/{provider}`, `/v1/me/quota/{provider}`                 | কোটা ভিউ পেজ পড়ে                |
| `/api/v1/me/usage`, `/v1/me/usage`                                       | পৃষ্ঠাটি যে ব্যবহার সিরিজটি পড়ে |
| `/_next/static/`                                                         | বিল্ডের স্ক্রিপ্ট, শৈলী এবং ফন্ট |
| `/favicon.ico`, `/favicon.svg`, `/icon-512.png`, `/apple-touch-icon.png` | আইকন                             |

`GET` এবং `HEAD` একটি বডি ছাড়া রিলে করা হয়। একটি বডির সাথে একটি অনুরোধও রিলে করা হয়: কোটা ভিউ পাথের একটি `PATCH`, যা পৃষ্ঠাটি একটি ঋণের পছন্দ সংরক্ষণ করতে পাঠায়। অন্য কোন পদ্ধতি 404 উত্তর দেয়, একটি CONNECT অনুরোধ ছাড়া, যার সংযোগ কোন উত্তর ছাড়াই বন্ধ। অন্য কোনো অনুরোধ যা একটি বডি ঘোষণা করে 404 উত্তর দেয় এবং এর সংযোগ বন্ধ হয়ে যায়। আপগ্রেডের অনুরোধ প্রত্যাখ্যান করা হয়েছে এবং তাদের সংযোগ বন্ধ করা হয়েছে। API পোর্টের মতো একটি ডট সেগমেন্ট বা একটি ফ্র্যাগমেন্ট মার্কার সহ একটি পথ প্রত্যাখ্যান করা হয়েছে। তাই মুদ্রণযোগ্য ASCII বাইরে একটি অক্ষর সহ একটি অনুরোধ লক্ষ্য। এই পোর্টের নিজস্ব চেক করার আগে, টার্গেটে একটি কাঁচা নিয়ন্ত্রণ অক্ষরকে HTTP পার্সার দ্বারা 400 উত্তর দেওয়া হয়। শিরোনামগুলিকে অনুরোধ করুন যে ফ্রেমওয়ার্কের নিজস্ব ব্যবহারের জন্য সংরক্ষণ করা হয় না রিলে করা হয়: `x-middleware-`, `x-invoke-`, `x-nextjs-`, `x-now-` বা `x-next-`, এবং নামগুলি `x-matched-path` এবং `next-resume` দিয়ে শুরু হয়৷ অনুরোধ তাদের ছাড়া রিলে হয়. ড্যাশবোর্ড, লগইন পৃষ্ঠা, ব্যবস্থাপনা API এবং অনুমান রুট এই পোর্টের মাধ্যমে পৌঁছানো যাবে না।

`PATCH` অবশ্যই `Content-Type: application/json` বহন করবে, কোন প্যারামিটার ছাড়াই বা শুধুমাত্র `charset=utf-8` সহ। এটিকে 1 থেকে 4096 পর্যন্ত একটি `Content-Length` বহন করতে হবে, প্লেইন ডিজিট হিসাবে লিখতে হবে এবং `Transfer-Encoding` নয়। একটি `PATCH` যা এই নিয়মগুলির মধ্যে একটি ভঙ্গ করে 404 উত্তর দেয়। কিছু ত্রুটিপূর্ণ দৈর্ঘ্য, যেমন একটি স্বাক্ষরিত বা একটি পুনরাবৃত্তি, এই পোর্টের নিজস্ব চেকের আগে HTTP পার্সার দ্বারা 400 উত্তর দেওয়া হয়। মূল পোর্টের সাথে যোগাযোগ করার আগে পোর্টটি ঘোষিত বাইটগুলি পড়ে এবং তাদের জন্য সর্বাধিক 5 সেকেন্ড অপেক্ষা করে। একটি বডি যা ততক্ষণে সম্পূর্ণ নয় 404 উত্তর দেয় এবং এর সংযোগ বন্ধ হয়ে যায়। সেক্ষেত্রে বা ক্লায়েন্ট প্রথমে চলে গেলে কিছুই মূল পোর্টে পৌঁছায় না। পোর্টটি একই `Content-Length` সাথে ঠিক ঘোষিত বাইট রিলে করে। তাদের পরে বাইট সংযোগের পরবর্তী অনুরোধ হিসাবে পড়া হয়. সামনে একটি TLS বিপরীত প্রক্সি অবশ্যই `Content-Length` ফরোয়ার্ড করবে এবং অনুরোধের অংশটিকে পুনরায় খণ্ডিত করা উচিত নয়। প্রধান পোর্ট `Authorization` হেডারে API কী চেক করে, যেমন `GET` এর জন্য।

404 বডি `{"error":"not_found","message":"Not found."}` হয়। একটি ব্যর্থ রিলে 502 (`api_bridge_unavailable`) বা 504 (`api_bridge_timeout`) কোন `detail` ক্ষেত্র ছাড়াই উত্তর দেয়।

শ্রোতা `QUOTA_SELF_PANEL` পড়ে না, এবং এটি পৃষ্ঠাটি চালু করে না। পতাকা বন্ধ থাকাকালীন, পৃষ্ঠা এবং এর API মূল পোর্টে 404 উত্তর দেয় এবং শ্রোতা সেই উত্তরটি রিলে করে।

ডেভেলপমেন্ট সার্ভারের অধীনে (`next dev`), পৃষ্ঠাটি এই পোর্টের মাধ্যমে ইন্টারেক্টিভ হয় না। ডেভেলপমেন্ট হট-রিলোড সকেট একটি আপগ্রেড অনুরোধ, এবং পোর্ট এটি প্রত্যাখ্যান করে। বিকাশ করার সময় প্রধান পোর্ট ব্যবহার করুন।

পোর্টটি প্লেইন HTTP পরিবেশন করে এবং পৃষ্ঠাটি API কী পাঠায়। ডিফল্ট বাঁধাই ঠিকানা রাখুন এবং এটির সামনে TLS সহ একটি বিপরীত প্রক্সি রাখুন। লুপব্যাক ব্যতীত অন্য একটি আবদ্ধ ঠিকানা এই বিজ্ঞপ্তিটি লগ করে:

```text
[Quota Panel] Bound to <host>. This port serves plain HTTP and the page sends API keys. Put a TLS reverse proxy in front of it.
```

একটি লুপব্যাক পিয়ার যেটি কোন ফরওয়ার্ডিং হেডার পাঠায় না তাকে প্রধান পোর্টে স্থানীয় হিসাবে গণ্য করা হয়। তাই একই হোস্টে একটি প্রক্সি অবশ্যই `X-Forwarded-For` পাঠাবে। একটি ব্যক্তিগত ঠিকানার একটি প্রক্সি শুধুমাত্র `OMNIROUTE_TRUST_PROXY=private` (বা `lan`) দিয়ে সেই শিরোনামের জন্য বিশ্বস্ত। অন্য কোনো পিয়ার তার সংযোগের ঠিকানা দ্বারা রিপোর্ট করা হয়, এবং এটি পাঠানো ফরওয়ার্ডিং হেডার বাদ দেওয়া হয়।

শ্রোতা এক সময়ে সর্বাধিক 256টি সংযোগ রাখে। একটি ক্লায়েন্ট অনুরোধ শিরোনাম পাঠাতে 10 সেকেন্ড এবং পুরো অনুরোধ পাঠাতে 30 সেকেন্ড আছে। একটি নিষ্ক্রিয় রাখা-জীবিত সংযোগ প্রায় 5 সেকেন্ড পরে বন্ধ হয়ে যায়৷ 60 সেকেন্ডের জন্য কোনো কার্যকলাপ ছাড়া একটি সংযোগ বন্ধ আছে। এই মান স্থির করা হয়. সামনে বিপরীত প্রক্সিতে সংযোগ এবং হারের সীমা সেট করুন। সামনে একটি বিপরীত প্রক্সি তার নিষ্ক্রিয় আপস্ট্রিম সংযোগগুলিকে 5 সেকেন্ডের কম সময় ধরে রাখতে হবে, অথবা সেগুলিকে পুনরায় ব্যবহার করবে না৷ প্রধান পোর্টের রিলে API পোর্টের আপস্ট্রিম টাইমআউট ব্যবহার করে (`API_BRIDGE_*`)।

`API_PORT` সেট না হলে শ্রোতাও শুরু হয়। `QUOTA_PANEL_PORT` 1 থেকে 65535 পর্যন্ত একটি পোর্ট হতে হবে, শুধুমাত্র সংখ্যায় লেখা। এটি অবশ্যই ড্যাশবোর্ড পোর্ট এবং API পোর্ট থেকে আলাদা হতে হবে। লাইভ WebSocket সার্ভার চালু থাকাকালীন, এটি অবশ্যই `LIVE_WS_PORT` (ডিফল্ট 20132) থেকে আলাদা হতে হবে। অন্য কোনো মান কিছুই খোলে না এবং একটি সতর্কতা লগ করে। একটি প্রত্যাখ্যান মান সম্পর্কে একটি সতর্কতা ভেরিয়েবলের নাম দেয় এবং মানের পুনরাবৃত্তি করে না। একটি পোর্ট যা ইতিমধ্যেই ব্যবহার করা হচ্ছে কিছুই খোলে না এবং এই সতর্কতাটি লগ করে:

```text
[Quota Panel] Port <port> is already in use. The quota panel port stays off.
```

`OMNIROUTE_BASE_PATH` সেটের সাথে, শ্রোতা সেই উপসর্গের অধীনে উপরের প্রতিটি পথ আশা করে। বিল্ড টাইমে এবং রান টাইমে একই `OMNIROUTE_BASE_PATH` ব্যবহার করুন। এটি একটি অগ্রণী স্ল্যাশ দিয়ে লিখুন এবং কোন ট্রেইলিং স্ল্যাশ না করে, উদাহরণস্বরূপ `/omniroute`। `/` এবং `/omniroute/` সহ আরেকটি আকৃতি, একটি সতর্কতা সহ বন্দরটি বন্ধ করে দেয়, যদিও বিল্ড সেই ফর্মগুলি গ্রহণ করে। তাই একটি বেস পাথ যার প্রথম সেগমেন্ট একটি অ্যাপ্লিকেশন রুটের নাম দেয়: `api`, `v1`, `v1beta`, `_next`, `quota`, `dashboard`, `docs`, `login`, `codex`, `responses`, `anthropic`, `openai`, `v0`, বা `connect`।

সীমাবদ্ধতা:

- এই পোর্টে`/quota/{provider}/` একটি ট্রেলিং স্ল্যাশ সহ 404 উত্তর দেয়।
- পরিষেবা কর্মী এবং ওয়েব অ্যাপ ম্যানিফেস্ট এই পোর্টে পরিবেশিত হয় না৷
- ড্যাশবোর্ডে একটি কাস্টম ফেভিকন সেট এই পোর্টে দেখানো হয় না।
- যখন অ্যাপ্লিকেশনটি বেস পাথের অধীনে চলে তখন আইকন দেখানো হয় না।
- বন্দর সরল HTTP/1.1. কথা বলে
- প্রক্রিয়া পুনরায় আরম্ভ না হওয়া পর্যন্ত ব্যর্থ হওয়া একটি বাঁধন পুনরায় চেষ্টা করা হয় না।
- শ্রোতার কোন সংযোগ বা ক্লায়েন্ট ঠিকানা প্রতি হার সীমা নেই.
- কন্টেইনার সেটআপগুলি এই বিভাগ দ্বারা আচ্ছাদিত নয়৷

## সমস্যা সমাধান

### Redis কনফিগার করা আছে, কিন্তু সংযোগ হচ্ছে না

`ioredis` ইনস্টল করা আছে কি না (`npm ls ioredis`) এবং `QUOTA_STORE_REDIS_URL`
অ্যাক্সেসযোগ্য কি না পরীক্ষা করুন। সংযোগ ব্যর্থ হলে ফ্যাক্টরি SQLite-এ ফিরে যায় (`warn`
স্তরে লগ করা হয়)।

### `peek` পুরোনো ডেটা ফেরত দেয় / ফেইল-ওপেন হয়

যদি `peek` ত্রুটি নিক্ষেপ করে, তবে `enforceQuotaShare` ফলাফলটিকে "অনুমোদন" হিসেবে বিবেচনা করে (ফেইল-ওপেন)।
মূল কারণ শনাক্ত করতে `quota:enforce` এবং `quota:factory` এন্ট্রির জন্য `pino` লগ
পরীক্ষা করুন।

### কনজাম্পশন কাউন্টারের বিচ্যুতি

প্রকৃত প্রদানকারী ব্যবহার কাউন্টারগুলোর থেকে আলাদা হলে সেটি প্রত্যাশিত — 2-বাকেট
স্লাইডিং উইন্ডোতে উইন্ডোর সীমানায় প্রায় 1% ত্রুটি থাকে এবং `consume` হলো
রেসপন্স-পরবর্তী ফায়ার-অ্যান্ড-ফরগেট অপারেশন। স্যাচুরেশন সিগন্যাল (`saturationSignals.ts`)
30s TTL সহ প্রকৃত প্রদানকারী ব্যবহার পড়ে এবং সেই অনুযায়ী `globalUsedPercent`
সমন্বয় করে।

### পুলে বার্ন রেটের জন্য "কোনো ডেটা নেই" দেখায়

## localStorage থেকে মাইগ্রেশন

`/dashboard/costs/quota-share` প্রথমবার লোড হলে, `useLocalStoragePoolMigration` হুকটি যাচাই করে:

1. `localStorage.getItem("omniroute:quota-share:pools")` খালি নয়।
2. `GET /api/quota/pools` থেকে `[]` ফেরত আসে (DB খালি)।

দুটি শর্তই সত্য হলে, এটি ব্যাচ আকারে প্রতিটি লিগ্যাসি পুল `POST /api/quota/pools`-এ পোস্ট করে,
তারপর localStorage কীটি সরিয়ে দেয়। মাইগ্রেশনটি আইডেমপোটেন্ট: শর্ত 2 পুনরায়
মাইগ্রেশন প্রতিরোধ করে।

## অভ্যন্তরীণ স্ট্র্যাটেজি শ্রেণিবিন্যাস

`quota-share` হলো একটি **শুধু-অভ্যন্তরীণ** রাউটিং স্ট্র্যাটেজি (`INTERNAL_ROUTING_STRATEGY_VALUES`,
`src/shared/constants/routingStrategies.ts`-এ)। এটি একচেটিয়াভাবে সিস্টেমের তৈরি
`qtSd/` পুল কম্বোগুলোর জন্য ব্যবহৃত হয় এবং ইচ্ছাকৃতভাবে `ROUTING_STRATEGY_VALUES` থেকে বাদ রাখা হয়েছে, যাতে এটি কখনোই
UI বা API-তে ব্যবহারকারী-নির্বাচনযোগ্য বিকল্প হিসেবে প্রদর্শিত না হয়।

## DB স্কিমার সারাংশ

মাইগ্রেশন `078`, `079` এবং `085` দ্বারা তিনটি টেবিল যোগ করা হয়েছে:

- `quota_pools` + `quota_allocations` — পুলের সংজ্ঞা এবং প্রতি-কী বরাদ্দ।
- `quota_consumption` — রোলিং 2-বালতি কাউন্টার প্রতি `(apiKeyId, dimensionKey)`.
- `provider_plans` — ম্যানুয়াল প্রোভাইডার প্ল্যান ওভাররাইড করে (মাত্রা JSON প্রতি connectionId)।

সমস্ত টেবিল idempotent `CREATE TABLE IF NOT EXISTS` মাইগ্রেশনের মাধ্যমে যোগ করা হয়েছে।

সম্মতিকৃত ঋণ তিনটি কলাম যোগ করে: `quota_allocations.lending_percent` (পূর্ণসংখ্যা, ডিফল্ট 0), `quota_allocations.lending_until` (যুগ মিলিসেকেন্ড, বা কোন সময়সীমার জন্য `NULL` ) এবং `quota_pools.borrow_mode` (ডিফল্ট `saturation`)। এর স্থানান্তর শুধুমাত্র এই কলামগুলিকে যুক্ত করে এবং কোন বিদ্যমান সারি লেখে না।

শতাংশ অ্যাট্রিবিউশন বইতে `quota_percent_ledger` (এক সারি প্রতি পুল, অ্যাকাউন্ট এবং প্ল্যান উইন্ডো) এবং `quota_percent_ledger_tokens` (পুল প্রতি একটি টোকেন কাউন্টার, অ্যাকাউন্ট এবং API কী) যোগ করা হয়েছে। `src/lib/db/quotaPercentLedger.ts` সেগুলি পড়ে এবং লেখে।
