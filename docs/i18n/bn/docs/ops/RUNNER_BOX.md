## janitor ইনস্টল করুন (একবার, মেশিনটিতে)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): প্রতি 30 মিনিটে, /var/log/runner-janitor.log-এ লগ করুন
*/30 * * * * MAX_ACTIVE_RUNNERS=8 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` আবশ্যক: কোনো পাথ সরানোর আগে janitor খোলা ফাইলগুলোর একটি স্ন্যাপশট নিয়ে
নিশ্চিত করে যে সেটি নিষ্ক্রিয়; টুলটি না থাকলে এটি কিছুই সরায় না এবং তা জানিয়ে দেয়
(exit 1)। যেকোনো পরিবর্তন প্রথমে `--dry-run` দিয়ে পরীক্ষা করুন — এটি ঠিক কী করত
তা প্রিন্ট করে এবং কিছুই পরিবর্তন করে না।

প্রতিবার চালানোর সময় এটি যা করে: আমাদের নিজস্ব অবশিষ্ট ফাইল (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) **tmpfs-এ 3 ঘণ্টা** এবং ডিস্কের
`_work/_temp`-এ 24 ঘণ্টা পর পরিষ্কার করে; 75 মিনিটের বেশি পুরোনো `next-build`
বন্ধ করে (কোনো job এত দীর্ঘ সময় চলে না — 2026-08-27 তারিখে GitHub একটি job-কে
হারিয়ে গেছে ঘোষণা করার পরও সেটি 70 মিনিট চলেছিল); যেসব runner-এর unit **stopped**,
সেগুলোর 48 ঘণ্টার পুরোনো checkout সরিয়ে দেয়; ডিস্ক ≥ 85 %, memory PSI
`full/avg60` ≥ 10 %, এবং listener-এর সংখ্যা `MAX_ACTIVE_RUNNERS`-এর চেয়ে বেশি হলে
(omniroute/other বিভাজনসহ) সতর্ক করে। Exit 1 = মনোযোগ প্রয়োজন; লগ পড়ুন।

GitHub ইতিমধ্যে ছেড়ে দিয়েছে এমন কোনো build-কে 75-মিনিটের নিয়ম শনাক্ত করে না।
`Runner.Listener` যখন তার job renew করতে পারে না, তখন `_diag/Runner_*.log`-এ
`POST request to …/renewjob timed out after 100 seconds` দেখা যায়, সর্বশেষ সফল
renewal-এর প্রায় দশ মিনিট পর API job-টিকে `completed` (failure) হিসেবে দেখায়, এবং
কোনো job সংযুক্ত না থাকা অবস্থায়ও `next-build` চলতে থাকে (2026-10-18: #17066-এর
Build 19:43-এ ব্যর্থ হয়েছিল এবং পাঁচ মিনিট পরও এর build 40 GB দখল করে রেখেছিল)।
সবচেয়ে নতুন `_diag/Worker_*.log`-এ ref নিশ্চিত করুন, তারপর PID অনুযায়ী শুধু build
tree-তে SIGTERM পাঠান — `next-build`, `npm run build`, `build-next-isolated.mjs` এবং
`_work` worker-গুলোতে। কখনোই `Runner.Listener`, `RunnerService.js` বা
`Runner.Worker` স্পর্শ করবেন না: worker job-টিকে cancelled হিসেবে রিপোর্ট করে এবং
listener নিজে থেকেই আবার online হয়ে যায়।

## Runner unit: KillMode

Runner-এর ডিফল্ট `KillMode=process` কোনো unit stop বা restart করা হলে
`Runner.Worker → npm → next-build` চালু রেখে দেয় — কোনো job সংযুক্ত না থাকা অবস্থায়
একটি orphan build RAM এবং CPU ব্যবহার করতে থাকে। প্রতিটি OmniRoute unit-এ
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
পাথে `KillMode=mixed`-সহ একটি drop-in রয়েছে: প্রথমে listener-কে SIGTERM পাঠায়,
এরপর `TimeoutStop`-এ পুরো cgroup-কে SIGKILL পাঠায়। এটি unit-এর পরবর্তী restart-এ
কার্যকর হয় — **একবারে একটি runner, এবং শুধু সেটি idle থাকলেই** restart করুন; idle
check এবং restart একই command-এ রাখুন।

  সেখানে Turbopack panic করেছিল, run 33253576569)। arm64 Docker leg-টি `ubuntu-24.04-arm`-এই থাকে।
  `docker-publish`-এর amd64, `ci.yml`-এর `Build`-এর সঙ্গে `heavy-build-main` concurrency group
  ভাগ করে (`cancel-in-progress: false`)। Docker Engine অবশ্যই `omniroute-113-5`-এ থাকতে হবে। দ্বিতীয় Turbopack
  slot 78 GB-তে আঁটে না (2 × 33–37 GB এবং box-এর বাকি অংশ); দ্বিতীয় slot কেবল
  webpack build-এর জন্যই নিরাপদ।
- **Pull-request Build-গুলো hosted-এ চলে (2026-10-18)।** `ci.yml`-এর `Build` কেবল
  `push` এবং `workflow_dispatch`-এর জন্য `omni-build`-এ পৌঁছায়; প্রতিটি `pull_request` (নিজস্ব origin বা fork) এবং `merge_group` Build
  webpack-সহ `ubuntu-latest`-এ চলে। প্রতিটি নিজস্ব-origin PR slot-এ route করায়, একটি Turbopack
  Build সেটি 29–58 min ধরে রাখত, 18টি Build সর্বোচ্চ 18 h পর্যন্ত queue-তে ছিল, এবং release line-এর নিজস্ব push Build
