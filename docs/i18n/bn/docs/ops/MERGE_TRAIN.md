## একটি রিলিজ শাখা অবতরণ

ওমনি-কিউ `release/vX.Y.Z` তে অবতরণকে নিয়ন্ত্রণ করে। একটি PR অবতরণ করার আগে ডিফল্ট শাখায় `config/merge-queue/config.json` এ শীর্ষ-স্তরের `mode` পড়ুন। [Omni-Queue](OMNI_QUEUE.md) দেখুন।

- **`shadow`** বৈধতা চালায় এবং একটি ম্যানুয়াল মার্জ অবতরণ ছেড়ে. অনুমোদিত PR এর চূড়ান্ত মাথায় `omni-queue` প্রয়োগ করুন। `npm run queue -- why <PR>` দিয়ে যোগ্যতা পরীক্ষা করুন। `npm run queue -- history --base <branch>` এ মাথার জন্য রায়ের জন্য অপেক্ষা করুন। `would-land` এ এগিয়ে যান। `culprit-found` বা `would-dequeue` এ, মার্জ ধরে রাখুন এবং কারণটি ঠিক করুন।
- **ছায়া ব্যতিক্রম।** বর্তমান বেস টিপের বিপরীতে সবুজ পূর্ণ CI সহ একটি ট্রেন পৃথক সারির রায় ছাড়াই এগিয়ে যেতে পারে। একই ব্যতিক্রম প্রযোজ্য যখন PR হেডে ইতিমধ্যেই বর্তমান বেস টিপ থাকে।
- **`live`** ল্যান্ডিং ট্রিগার করতে `omni-queue` লেবেল ব্যবহার করে। কিউ একাই PR ল্যান্ড করে। মার্জ কমান্ড এবং সারিতে সরাসরি পুশ ছেড়ে দিন।

প্রতিটি অবতরণ মালিকের অনুমোদন এবং প্রযোজ্য প্রয়োজনীয় চেক প্রয়োজন. মালিক অবতরণ করার অনুমতি দেওয়ার পরেই `omni-queue` প্রয়োগ করুন৷ সারিবদ্ধ PRs স্পর্শ করা সুরক্ষিত পাথের জন্যও সেই PR জন্য মালিকের `protected-approved` সিদ্ধান্ত প্রয়োজন।

"সক্রিয় রিলিজে সবুজ গেটস প্রয়োজন" রুলসেটের মাথায় সবুজ `Gate / CI` এবং `Gate / Quality` প্রয়োজন। লাল গেট বাইপাস করতে `--admin` ব্যবহার করবেন না। একটি রিলিজ ফ্রিজ ব্লক হিমায়িত শাখায় একত্রিত হয়। [হার্ড নিয়ম 21](HARD_RULES_DETAIL.md) দেখুন। অন্য সেশন কাজ করছে এমন টান অনুরোধে কখনই লেবেল, মার্জ বা পুশ করবেন না। [হার্ড নিয়ম 22](HARD_RULES_DETAIL.md) দেখুন।

## ট্রেন টানার অনুরোধ

1. বর্তমান রিলিজ বেস টিপে একটি ট্রেন শাখা শুরু করুন। মার্জ কমিট ব্যবহার করে সঠিক অনুমোদিত সদস্য হেড একত্রিত করুন। স্কোয়াশ এবং রিবেস এড়িয়ে তাদের প্রতিশ্রুতিবদ্ধ ইতিহাস সংরক্ষণ করুন।
2. ট্রেন শাখার জন্য একটি টান অনুরোধ খুলুন। বর্তমান বেস টিপে সেই PR এর নিজস্ব সম্পূর্ণ CI সহ যাচাই করুন। অবতরণের আগে বেস টিপ এবং অনুমোদিত সদস্য হেডগুলি পুনরায় পরীক্ষা করুন। বৈধ প্রার্থী পরিবর্তন হলে ট্রেন এবং এর CI রিফ্রেশ করুন।
3. প্রযোজ্য সারি মোডের অধীনে একটি মার্জ কমিট সহ ট্রেন PR অবতরণ করুন। লাইভ মোডে, সারির `merge-ff` ল্যান্ডিং পদ্ধতি মার্জ কমিট সংরক্ষণ করে। রিলিজ শাখা থেকে মূল সদস্য প্রধানদের কাছে পৌঁছানো যায়। GitHub সদস্য PRs মার্জ করা হিসাবে চিহ্নিত করে এবং কমিটগুলি তাদের লেখককে ধরে রাখে।

একটি সর্বজনীন উদাহরণ হল [PR #21071](https://github.com/cheaper-inference/OmniRoute/pull/21071) । এটি 18 সদস্যের PRs একত্রিত করেছে এবং 2026-11-24 তারিখে একটি মার্জ কমিটের সাথে অবতরণ করেছে।

`main` থেকে পরবর্তী রিলিজ শাখায় একটি সিঙ্ক-ব্যাকও একটি মার্জ কমিটের মাধ্যমে অবতরণ করে। পরবর্তী সিঙ্ক-ব্যাকগুলির জন্য `main` পূর্বপুরুষ সংরক্ষণ করা প্রয়োজন। [ওয়ার্কট্রি আইসোলেশন](WORKTREE_ISOLATION.md#sync-back-landings-are-merge-commits-never-squash) দেখুন।

## স্থানীয় মার্জ-ট্রেন যাচাইকারী

```bash
scripts/release/merge-train.sh [--plan] [--fast] <base-branch> <PR#> [<PR#>...]
```

যাচাইকারী বেস এবং PR হেড আনে এবং একটি নিষ্পত্তিযোগ্য ওয়ার্কট্রিতে তাদের একত্রিত করে। এটি ফলস্বরূপ গাছে একবার তার প্যারিটি স্যুট চালায়। একটি ব্যর্থ হেড আনয়ন বা মার্জ দ্বন্দ্ব PR কে বের করে দেয় এবং স্ক্রিপ্টটি অবশিষ্ট PRs সাথে চলতে থাকে।

- **`--plan`** নির্বাচিত মোডের ধাপগুলি প্রিন্ট করে এবং ওয়ার্কট্রি তৈরি না করে বা রিমোটের সাথে যোগাযোগ না করে প্রস্থান করে। দ্রুত পরিকল্পনা পরিদর্শন করতে `--fast` এর সাথে এটি একত্রিত করুন।
- **`--fast`** সাধারণ স্ট্যাটিক গেটগুলি চালায়, `tests/unit/` এবং `npm run test:vitest`এর অধীনে নির্বাচিত পরিবর্তিত `node:test` ফাইলগুলি। দ্রুত মোড ব্যবহার করার সময় জমে থাকা টিপে দিনে অন্তত একবার একটি সম্পূর্ণ স্থানীয় বৈধতা চালান।
- **সম্পূর্ণ মোড** সম্পূর্ণ-শুধু স্ট্যাটিক গেট যোগ করে এবং `npm run test:unit` এবং `npm run test:vitest` চালায়।

যদি বেস প্রোব উপলব্ধ থাকে তবে একটি ব্যর্থ স্ট্যাটিক গেট অস্পর্শিত বেসে পুনরায় চালু করা হয়। স্ক্রিপ্ট উত্তরাধিকারসূত্রে প্রাপ্ত ব্যর্থতার রিপোর্ট করে এবং চলতে থাকে যখন প্রতিটি স্বীকৃত লঙ্ঘন লাইনও ভিত্তিতে উপস্থিত হয় এবং মোট গণনা বৃদ্ধি পায় না।

| প্রস্থান করুন | অর্থ                                                                                                                                                                      |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`           | পরিকল্পনা প্রিন্ট বা স্যুট সম্পন্ন. স্যুট সারাংশ উত্তরাধিকারসূত্রে প্রাপ্ত স্ট্যাটিক ব্যর্থতা এবং নির্গত PRs তালিকাভুক্ত করে।                                             |
| `1`           | অবৈধ আর্গুমেন্ট, কোন গিট চেকআউট, ব্যর্থ প্রিফ্লাইট, বা কোন PR বোর্ডড হয়নি।                                                                                               |
| `2`           | একটি স্যুট চেক ব্যর্থ হয়েছে এবং উত্তরাধিকারসূত্রে প্রাপ্ত হিসাবে যোগ্য নয়৷ অপারেটর ব্যাচকে দ্বিখণ্ডিত করতে পারে, আপত্তিকর PR বের করে দিতে পারে এবং পুনরায় চালাতে পারে। |

একটি স্থানীয় পাস শুধুমাত্র মালিকের ডসিয়ারের জন্য ডায়াগনস্টিক প্রমাণ সরবরাহ করে। প্রতিটি অবতরণ এখনও মালিকের অনুমোদন প্রয়োজন, তার নিজস্ব প্রয়োজনীয় চেক, এবং ছায়া সারি রায় যখন প্রযোজ্য হয়.

## টিয়ারিং

- **প্রতি PR.** CI এবং পরিবর্তিত পাথের উপর ভিত্তি করে গুণমান নির্বাচন পরীক্ষা করে। কোড PRs দ্রুত মানের গেট এবং প্রভাবিত পরীক্ষা চালায়, CI তে পৃথক ইউনিট এবং Vitest কাজের সাথে।
- **প্রতি সারি প্রার্থী.** CI এবং কোয়ালিটি তার সারি রেফ-এ রচিত প্রার্থীর জন্য সম্পূর্ণ প্রোফাইল চালায়।
- **রিলিজ টিপ প্রতি.** রিলিজ-সবুজ তার পাথ ফিল্টারগুলির সাথে মেলে এমন পুশগুলিতে দ্রুত হার্ড গেট চালায়। প্রতিদিন তিনটি নির্ধারিত রান রিলিজ শাখার জন্য সম্পূর্ণ ঝাড়ু ব্যবহার করে।
- **রিলিজ প্রতি.** সম্পূর্ণ CI ম্যাট্রিক্সের মধ্যে রয়েছে E2E শার্ড, প্যাকেজ যাচাইকরণ, টারবল বুট স্মোক এবং কভারেজ চেক। [রিলিজ চেকলিস্ট](RELEASE_CHECKLIST.md) দেখুন।

## `merge-train.sh` জন্য ফ্রেশ-চেকআউট পূর্বশর্ত

ওয়ার্কট্রি তৈরি করার আগে প্রিফ্লাইট চলে। `npm ci` দিয়ে নির্ভরতা ইনস্টল করুন। নিশ্চিত করুন যে `node_modules/.bin/tsc` নির্বাহযোগ্য এবং `node_modules/node_modules` অনুপস্থিত। চেক করুন যে `node_modules/.bin/bun --version` সফল হয়েছে।

যদি Bun পোস্টইনস্টল এড়িয়ে যায়, `(cd node_modules/bun && node install.js)` চালান। প্রদানকারীর ধারাবাহিকতা এবং পরিচিত-প্রতীক চেক Bun ব্যবহার করে। যাচাইকারী একটি ব্লকিং গেট হিসাবে `npm run check:cycles:ratchet` চালায়। স্বতন্ত্র `npm run check:cycles` কমান্ড পরামর্শমূলক।
