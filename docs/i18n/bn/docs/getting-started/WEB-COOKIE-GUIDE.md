ওয়েব কুকি প্রোভাইডারগুলো OmniRoute-কে API key-এর পরিবর্তে আপনার বিদ্যমান ব্রাউজার সেশনের মাধ্যমে কোনো AI পরিষেবা ব্যবহার করতে দেয়। আপনি যখন কোনো পরিষেবার ওয়েবসাইটের মাধ্যমে ইতিমধ্যেই সেটিতে অ্যাক্সেস রাখেন এবং চান যে OmniRoute একই প্রমাণীকৃত সেশন ব্যবহার করুক, তখন এগুলো উপযোগী।

API-key প্রোভাইডারের বিপরীতে, ওয়েব কুকি প্রোভাইডারগুলো ওয়েবসাইটে আপনার ব্রাউজার পাঠানো ক্রেডেনশিয়াল ব্যবহার করে প্রমাণীকরণ করে।

# শুরু করার আগে

> **গুরুত্বপূর্ণ:** ক্রেডেনশিয়াল সবসময় একটি **সক্রিয় নেটওয়ার্ক রিকোয়েস্ট** থেকে কপি করুন, আপনার ব্রাউজারের কুকি স্টোরেজ থেকে **নয়**।

ভুল জায়গা থেকে কুকি কপি করার কারণে প্রমাণীকরণ-সংক্রান্ত অনেক সমস্যা দেখা দেয়।

## কুকি স্টোরেজ থেকে কপি করবেন না

অধিকাংশ ব্রাউজার সংরক্ষিত কুকি নিম্নলিখিত স্থানে দেখায়:

```
DevTools
→ Application (অথবা Storage)
→ Cookies
```

এই কুকিগুলো সঠিক মনে হলেও, সেগুলো হতে পারে:

- পুরোনো
- অসম্পূর্ণ
- কেবল প্রমাণীকৃত রিকোয়েস্টের সঙ্গে পাঠানো কুকিবিহীন

এই মানগুলো বৈধ মনে হলেও, সেগুলো ব্যবহার করলে প্রমাণীকরণ ব্যর্থ হতে পারে।

## একটি সক্রিয় রিকোয়েস্ট থেকে কপি করুন

এর পরিবর্তে, একটি সফল রিকোয়েস্টের কুকি ব্যবহার করুন:

```
DevTools
→ Network
→ পৃষ্ঠাটি রিফ্রেশ করুন
→ একটি চ্যাট বা কথোপকথনের রিকোয়েস্ট খুলুন
→ Request Headers
→ Cookie
```

`Cookie` রিকোয়েস্ট হেডারে সেই সুনির্দিষ্ট প্রমাণীকরণ তথ্য থাকে, যা আপনার ব্রাউজার সফলভাবে ব্যবহার করেছে।

অধিকাংশ ওয়েব কুকি প্রোভাইডারের ক্ষেত্রে, এই মানটিই OmniRoute-এ পেস্ট করা উচিত।

# সাধারণ সেটআপ

অধিকাংশ ওয়েব কুকি প্রোভাইডারের জন্য সেটআপ প্রক্রিয়া একই।

1. প্রোভাইডারের ওয়েবসাইটে সাইন ইন করুন।
2. ব্রাউজারের Developer Tools খুলুন।
3. **Network** ট্যাব খুলুন।
4. পৃষ্ঠাটি রিফ্রেশ করুন।
5. একটি প্রমাণীকৃত চ্যাট বা কথোপকথনের রিকোয়েস্ট খুলুন।
6. প্রয়োজনীয় প্রমাণীকরণ ক্রেডেনশিয়াল কপি করুন।
7. OmniRoute খুলুন।
8. **Providers → Add Provider**-এ যান।
9. আপনার ওয়েব কুকি প্রোভাইডার নির্বাচন করুন।
10. ক্রেডেনশিয়াল পেস্ট করুন।
11. **Test Connection**-এ ক্লিক করুন।
12. প্রোভাইডারটি সংরক্ষণ করুন।

ঠিক কোন ক্রেডেনশিয়াল প্রয়োজন হবে, তা প্রোভাইডারের ওপর নির্ভর করে।

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) একটি বিনামূল্যের গ্রাহক চ্যাট প্ল্যাটফর্ম, যেখানে সাইন-আপের প্রয়োজন নেই — প্রথমবার ভিজিটের সময় সেশনটি বেনামে তৈরি হয় এবং তিনটি কুকির মাধ্যমে বজায় থাকে: `uid`, `si_usr_id`, এবং `si_ses_id`। OmniRoute একটি একক মডেল আইডির (`notrack-c`, উপনাম `ntw`) মাধ্যমে একই `/api/dispatch` এন্ডপয়েন্ট প্রক্সি করে।

### সংযোগের ধাপসমূহ

1. আপনার ব্রাউজারে [notrack.ai](https://notrack.ai) খুলুন এবং বেনামি সেশন কুকিটি সেট হতে দিন।
2. **DevTools → Network** খুলুন, পৃষ্ঠাটি রিফ্রেশ করুন এবং যেকোনো `/api` অনুরোধে ক্লিক করুন।
3. **Request Headers**-এ সম্পূর্ণ `Cookie` হেডারের মান কপি করুন।
4. OmniRoute-এ **Providers → Add Provider → NoTrack Web (Free)**-এ যান।
5. কুকি স্ট্রিংটি `apiKey` ফিল্ডে পেস্ট করে **Save** করুন।

OmniRoute পেস্ট করা স্ট্রিং থেকে `uid`, `si_usr_id`, এবং `si_ses_id` বের করে এবং শুধু ওই জোড়াগুলো দিয়ে একটি পরিচ্ছন্ন `Cookie` হেডার পুনর্নির্মাণ করে — পাশাপাশি উপস্থিত থাকলে `nt_session`-ও (লগ-ইন করা অ্যাকাউন্টের জন্য সেট করা `ntk_…` টোকেন) যোগ করে। তিনটির কোনোটি অনুপস্থিত থাকলে, অপারেটররা যাতে বিকল্প বিন্যাস নিয়ে পরীক্ষা করতে পারেন, সে জন্য পেস্ট করা কাঁচা স্ট্রিংটি অপরিবর্তিত অবস্থায় ফরোয়ার্ড করা হয়।

### মডেল আইডিসমূহ

| মডেল আইডি   | প্রদর্শিত নাম | নোট                                                  |
| ----------- | ------------- | ---------------------------------------------------- |
| `notrack-c` | NoTrack C     | ডিফল্ট — আপস্ট্রিম ডিসপ্যাচ মডেল `C`।                |
| `C`         | NoTrack C     | `notrack-c`-এর উপনাম (কাঁচা আপস্ট্রিম ডিসপ্যাচ কোড)। |
| `notrack`   | NoTrack C     | `notrack-c`-এর উপনাম।                                |
| `ntw`       | NoTrack C     | `notrack-c`-এর সংক্ষিপ্ত উপনাম।                      |

চারটি মডেল আইডিই একই আপস্ট্রিম ডিসপ্যাচ মডেলে (`C`) ম্যাপ করে।

### অনুরোধের বিকল্পসমূহ

এক্সিকিউটর অনুরোধের বডিতে নিচের ঐচ্ছিক ফিল্ডগুলো গ্রহণ করে:

| বডি ফিল্ড             | ডিফল্ট  | উদ্দেশ্য                                                                |
| --------------------- | ------- | ----------------------------------------------------------------------- |
| `notrack_mode`        | `usual` | ডিসপ্যাচ মোড (মুক্ত-রূপের স্ট্রিং; আপস্ট্রিম `usual`, … গ্রহণ করে)      |
| `notrack_max_turns`   | `6`     | উত্তর দেওয়ার আগে আপস্ট্রিম সর্বোচ্চ যতটি অভ্যন্তরীণ টার্ন নিতে পারে।   |
| `notrack_chat_id`     | `null`  | বিদ্যমান আপস্ট্রিম চ্যাট পুনরায় শুরু করুন (নতুন চ্যাটের জন্য বাদ দিন)। |
| `notrack_attachments` | `[]`    | আপস্ট্রিম অ্যাটাচমেন্ট বর্ণনাকারীর পাস-থ্রু অ্যারে।                     |
| `notrack_regenerate`  | `false` | আগের টার্নের জন্য পুনরায় তৈরি করা উত্তর চাইতে `true` সেট করুন।         |

### সক্ষমতাসমূহ

- **স্ট্রিমিং এবং নন-স্ট্রিমিং** চ্যাট কমপ্লিশন।
- **টুল কলিং** — অনুরোধে `tools: [...]` সেট করুন; এক্সিকিউটর সেগুলোকে একটি টুল-কল এনভেলপ চুক্তিতে সিরিয়ালাইজ করে এবং মডেলের প্রতিক্রিয়াগুলোকে আবার OpenAI `tool_calls`-এ পার্স করে।
- **`response_format`** — `json_object` এবং `json_schema` সমর্থিত। এক্সিকিউটর মডেলের উত্তর থেকে প্রথম JSON অবজেক্টটি বের করে এবং ফেরত দেওয়ার আগে সেটিকে স্ট্রিংয়ে রূপান্তর করে।
- **রিজনিং ইঙ্গিত** — আপস্ট্রিম একটি `thinking` ইভেন্ট পাঠালে এক্সিকিউটর একটি `reasoning` ডেল্টা নির্গত করে।

### সীমাবদ্ধতাসমূহ

- আপস্ট্রিম বেনামি ব্যবহারের কোটা প্রয়োগ করে — কোটা অতিক্রম করলে এক্সিকিউটর একটি বন্ধুসুলভ বার্তাসহ 429 প্রকাশ করে।
- সব মডেল আইডি একই আপস্ট্রিম ডিসপ্যাচ মডেলে সমাধান হয়; মডেলভিত্তিক আলাদা সুইচ নেই।
- এক্সিকিউটর আপস্ট্রিমের `/api/chats` এন্ডপয়েন্ট কল করে না, তাই চ্যাট ইতিহাস / সেশন স্বয়ংক্রিয়ভাবে পরিচালিত হয় না। বিদ্যমান আপস্ট্রিম চ্যাট পুনরায় শুরু করতে `notrack_chat_id` ব্যবহার করুন।

# ওয়েব কুকি প্রোভাইডার কী করতে পারে এবং কী করতে পারে না

ওয়েব কুকি প্রোভাইডারগুলো কোনো ওয়েবসাইটের চ্যাট ইন্টারফেস পুনরায় ব্যবহার করে। এগুলো অফিসিয়াল API-এর মতো একই সক্ষমতা **প্রদান করে না**।

## সমর্থিত

- আপনার বিদ্যমান ব্রাউজার সেশন ব্যবহার করে প্রমাণীকরণ
- আপনার অ্যাকাউন্টের মাধ্যমে উপলভ্য মডেলগুলোতে অ্যাক্সেস
- চ্যাটের প্রতিক্রিয়া স্ট্রিম করা
- কোনো API কী প্রয়োজন নেই

## সমর্থিত নয়

- ফাংশন কলিং
- টুল কলিং
- স্বয়ংক্রিয় ফাইল সম্পাদনা
- এজেন্টভিত্তিক IDE ওয়ার্কফ্লো
- কেবল API-তে উপলভ্য ফিচার

এটি প্রত্যাশিত আচরণ এবং **কোনো** বাগ নয়।

আপনার যদি টুল এক্সিকিউশন, স্বয়ংক্রিয় ফাইল সম্পাদনা বা অন্যান্য এজেন্ট ওয়ার্কফ্লোর প্রয়োজন হয়, তাহলে Web Cookie প্রোভাইডারের পরিবর্তে একটি **API-key provider** ব্যবহার করুন।

# যাচাইকরণ-সংক্রান্ত সতর্কতা

একটি সফল **Test Connection** বা কুকি যাচাইকরণ শুধু নিশ্চিত করে যে সরবরাহ করা ক্রেডেনশিয়ালগুলো প্রত্যাশিত ফরম্যাটে আছে বলে মনে হচ্ছে।

Issue #7857 সমাধান না হওয়া পর্যন্ত, একটি সফল যাচাইকরণ প্রোভাইডারটি সফলভাবে প্রমাণীকরণ করবে—এমন **নিশ্চয়তা দেয় না**।

প্রমাণীকরণ তারপরও ব্যর্থ হলে, নিশ্চিত করুন যে আপনি ব্রাউজারের কুকি স্টোরেজের পরিবর্তে একটি সক্রিয় নেটওয়ার্ক রিকোয়েস্ট থেকে ক্রেডেনশিয়ালগুলো কপি করেছেন।

---

# সমস্যা সমাধান

## প্রমাণীকরণ ব্যর্থ হয়

নিশ্চিত করুন যে ক্রেডেনশিয়ালগুলো এখান থেকে কপি করা হয়েছে:

```
Network
→ Request Headers
→ Cookie
```

এবং এখান থেকে **নয়**:

```
Application
→ Cookies
```

---

## কুকি ব্রাউজারে কাজ করে, কিন্তু OmniRoute-এ করে না

কিছু প্রোভাইডার এমন কুকি অন্তর্ভুক্ত করে, যেগুলো শুধু প্রমাণীকৃত রিকোয়েস্টের সময় পাঠানো হয়।

সফলভাবে একটি কথোপকথন খোলার পর, একটি নতুন নেটওয়ার্ক রিকোয়েস্ট থেকে ক্রেডেনশিয়ালগুলো আবার কপি করুন।

---

## সেশনের মেয়াদ শেষ হয়েছে

Web Cookie প্রোভাইডারগুলো আপনার বিদ্যমান ব্রাউজার সেশন ব্যবহার করে।

আপনার ব্রাউজার সেশনের মেয়াদ শেষ হলে বা আপনি সাইন আউট করলে, আপনাকে নতুন এক সেট ক্রেডেনশিয়াল কপি করতে হবে। সমর্থিত ওয়েব প্রোভাইডারগুলোর জন্য কুকি নবায়ন স্বয়ংক্রিয় করতে, সহযোগী টুল [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) দেখুন।

## ChatGPT Web `Unsupported ChatGPT integrity dependency` ত্রুটিসহ ব্যর্থ হয়

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

ক্রেডেনশিয়ালটি ঠিক আছে—এই ত্রুটিটি ব্রিজ থেকে আসে, সেশন থেকে নয়। chatgpt.com প্রতিটি ডিপ্লয়মেন্ট অনুযায়ী এর
মডিউল আইডি নির্ধারণ করে এবং ব্রিজটি ইনস্ট্যানশিয়েট করা Sentinel হেল্পারের আইডি পিন করত; ফলে
chatgpt.com-এর কোনো রিবিল্ড হেল্পারটির নাম পরিবর্তন করলে কুকি বৈধ থাকা সত্ত্বেও প্রতিটি টার্ন ব্যর্থ হতো। সংযোগটি
পুনরায় অনুমোদন করলে এটি ঠিক হবে না।

যেসব বিল্ড পেজটির নিজস্ব রানটাইমের মাধ্যমে মডিউলটি রিজলভ করে, সেগুলো কোনো আইডি পিন করে না এবং এই সমস্যার সম্মুখীন হয় না। আপনি
ত্রুটিটি দেখলে, OmniRoute আপগ্রেড করুন এবং সংযোগ পরীক্ষা আবার চালান।

# সর্বোত্তম অনুশীলন

- একটি নতুন প্রমাণীকৃত রিকোয়েস্ট থেকে ক্রেডেনশিয়াল কপি করুন।
- পুরোনো কুকি পুনরায় ব্যবহার করা এড়িয়ে চলুন।
- Web Cookie প্রোভাইডার ব্যবহার করার সময় আপনার ব্রাউজার সেশন সক্রিয় রাখুন।
- কপি করা কুকিগুলোকে সংবেদনশীল ক্রেডেনশিয়াল হিসেবে বিবেচনা করুন।
- আপনার ফাংশন কলিং বা এজেন্ট ওয়ার্কফ্লোর প্রয়োজন হলে API-key প্রোভাইডার ব্যবহার করুন।
