## এটি কী

OmniRoute একটি **Obsidian** ভল্টের সঙ্গে **কনটেক্সট উৎস** হিসেবে সংযুক্ত হয় — এটি একটি
স্থানীয় Markdown জ্ঞানভান্ডার, যা এজেন্টরা বিল্ট-ইন MCP সার্ভারের মাধ্যমে পড়ে ও লেখে।
ইন্টিগ্রেশনটি ডেস্কটপ অ্যাপের ভেতরে চলমান **Obsidian Local REST API** কমিউনিটি প্লাগইনের
সঙ্গে যোগাযোগ করে, ফলে এজেন্টরা নোট অনুসন্ধান, ফাইল পড়া/লেখা/প্যাচ করা, ভল্টের তালিকা
দেখা, দৈনিক/সাপ্তাহিক পর্যায়ক্রমিক নোট নিয়ে কাজ করা, ট্যাগ পরিচালনা, Obsidian কমান্ড
চালানো এবং (ঐচ্ছিকভাবে) দ্বিমুখী ডেস্কটপ↔মোবাইল ভল্ট সিঙ্ক সমন্বয় করতে পারে।

ক্লায়েন্টটি (`src/lib/obsidian/api.ts`) Local REST API-কে নিম্নলিখিত সুবিধাসহ আবৃত করে:

- ক্ষণস্থায়ী `5xx` ত্রুটির জন্য **ব্যাকঅফসহ পুনঃচেষ্টা**, `AbortController`-এর মাধ্যমে
  **30-সেকেন্ডের টাইমআউট**।
- **টাইপযুক্ত ত্রুটি শ্রেণিবিন্যাস** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`।
- একটি **সহজবোধ্য "Obsidian-এ পৌঁছানো যাচ্ছে না" ইঙ্গিত**, যা সাধারণ পোর্ট-সংক্রান্ত
  ভুলটি উল্লেখ করে (HTTP-এর জন্য `27123`, MCP এন্ডপয়েন্টের `27124` **নয়**) এবং
  Tailscale-এর বিন্যাসটি দেখায়।
- ভল্ট-আপেক্ষিক **পাথ এনকোডিং**, যাতে স্পেস/স্ল্যাশযুক্ত নোটের পাথ নিরাপদ থাকে।

## সেটআপ

Obsidian token বা base URL-এর জন্য **কোনো environment variable নেই** — উভয়ই
`src/lib/db/obsidian.ts`-এর মাধ্যমে SQLite `key_value` table-এ (namespace `obsidian`)
সংরক্ষিত হয়। token-টি **সংরক্ষিত অবস্থায় encrypted** থাকে (AES-256-GCM, সঙ্গে
plaintext backward-compat fallback)। Endpoint dashboard-এর **Context Sources** tab
(`ObsidianSourceCard`) থেকে অথবা settings REST API-এর মাধ্যমে কনফিগার করুন।

> [!IMPORTANT]
> **Obsidian Local REST API** plugin অবশ্যই ইনস্টল করা এবং চালু থাকতে হবে। এর REST
> interface **HTTP `127.0.0.1:27123`**-এ শোনে (default base URL)। Port `27124`
> একটি _পৃথক_ MCP/HTTPS endpoint এবং settings route এটিকে স্পষ্টভাবে প্রত্যাখ্যান করে।
> অন্য কোনো device থেকে সংযোগ করলে `http://<tailscale-ip>:27123` ব্যবহার করুন।

### কনফিগারেশন key (SQLite `key_value`, namespace `obsidian`)

| Key               | উদ্দেশ্য                                         | Encrypted |
| ----------------- | ------------------------------------------------ | --------- |
| `api_key`         | Local REST API bearer token                      | হ্যাঁ     |
| `base_url`        | REST base URL (default `http://127.0.0.1:27123`) | না        |
| `vault_path`      | vault directory-এর absolute path (sync-এর জন্য)  | না        |
| `webdav_username` | তৈরি করা WebDAV username (vault sync)            | না        |
| `webdav_password` | তৈরি করা WebDAV password (vault sync)            | হ্যাঁ     |
| `webdav_enabled`  | WebDAV vault sync সক্রিয় কি না                  | না        |

### REST-এর মাধ্যমে কনফিগার করুন

```bash
# Local REST API token সংরক্ষণ + যাচাই করুন (POST একটি status check-এর মাধ্যমে যাচাই করে)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# সংযোগের status পরীক্ষা করুন (connected, hasToken, baseUrl, vaultPath ফেরত দেয়)
curl http://localhost:20128/api/settings/obsidian

# সংযোগ বিচ্ছিন্ন করুন (সংরক্ষিত token মুছে দেয়)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

সব method-এর জন্য dashboard authentication প্রয়োজন। `POST`, port `27124`-এর যেকোনো
URL প্রত্যাখ্যান করে এবং সংরক্ষণের আগে Local REST API status endpoint-এ call করে
token যাচাই করে।

### WebDAV vault sync

`src/app/api/settings/obsidian/webdav/route.ts` একটি ঐচ্ছিক WebDAV-backed
vault sync পরিচালনা করে (যা `src/lib/obsidianSync.ts` দ্বারা চালিত)। এটি সক্রিয় করলে
OmniRoute-কে একটি local vault directory-র দিকে নির্দেশ করা হয় এবং একটি random WebDAV
username/password pair তৈরি করা হয়:

```bash
# একটি vault directory-এর জন্য WebDAV sync সক্রিয় করুন (username/password তৈরি করে)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV sync status দেখুন (শুধু সক্রিয় থাকা অবস্থায় credentials ফেরত দেওয়া হয়)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV sync নিষ্ক্রিয় করুন (credentials + পরিচালিত .stignore মুছে দেয়)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### নিরাপত্তা ও পরিবহন

WebDAV প্রমাণীকরণ প্রতি-আইপি ব্যর্থতা ট্র্যাকিং এবং লকআউট প্রয়োগ করে (60-সেকেন্ডের উইন্ডোর মধ্যে 10টি ব্যর্থ প্রচেষ্টা `429 Too Many Requests` এবং `Retry-After` এর সাথে 5-মিনিটের লকআউট ট্রিগার করে)। যেহেতু WebDAV বেসিক প্রমাণীকরণের শংসাপত্র প্রেরণ করে, লুপব্যাকের বাইরে WebDAV এন্ডপয়েন্ট অ্যাক্সেস করার সময় TLS (অথবা একটি সুরক্ষিত টানেল যেমন Tailscale বা Cloudflare Tunnel এর উপর রাউটিং) বন্ধ করার পরামর্শ দেওয়া হয়।

### প্রতি-API-key context source (ঐচ্ছিক)

Obsidian config-কে `api_key_context_sources` table-এর মাধ্যমে **প্রতি API key অনুযায়ী**
scoped করা যায় (`src/lib/db/apiKeyContextSources.ts`)। কোনো MCP call-এ authenticated API
key id থাকলে, `getObsidianConfigForApiKey()` সেই key-এর নিজস্ব token/base-URL/vault-path-কে
অগ্রাধিকার দেয় (`source: "api_key"`); অন্যথায় global config-এ fallback করে
(`source: "global"`)।

Non-sync MCP tool-গুলো এই configuration পড়ার আগে একটি resolved caller identity চায়।
identity-বিহীন caller `Obsidian API token not configured` পায় এবং কোনো vault request
পাঠানো হয় না। HTTP caller-রা তাদের request credentials-এর মাধ্যমে resolve হয়; stdio
caller-রা `OMNIROUTE_API_KEY` বা `ROUTER_API_KEY`-এর মাধ্যমে resolve হতে পারে। কোনো
unresolved HTTP caller server-এর environment identity উত্তরাধিকারসূত্রে পেতে পারে না।
শুধু placeholder ID access অনুমোদন করে না; `env-key`-তে resolve হওয়া একটি valid
environment credential এখনও সমর্থিত। Per-key Obsidian configuration-বিহীন authenticated
key-গুলো global fallback বজায় রাখে। চারটি `obsidian_sync_*` tool তাদের পৃথক
sync-token আচরণ বজায় রাখে।

## MCP টুলস (22)

`open-sse/mcp-server/tools/obsidianTools.ts` তে সংজ্ঞায়িত। token/base-URL প্রতি কলে সমাধান করা হয় (প্রতি-API-কী প্রথমে, তারপর বিশ্বব্যাপী)। টুল যে OmniRoute আঘাত** সিঙ্ক সার্ভার** (চারটি `obsidian_sync_*` টুল) অতিরিক্তভাবে OmniRoute সেটিংসে কনফিগার করা সিঙ্ক প্রমাণীকরণ টোকেন প্রয়োজন।

| `obsidian_search_structured` | একটি JSON লজিক এক্সপ্রেশন (and/or/regex/path ফিল্টার) ব্যবহার করে অনুসন্ধান করুন।            |
| `obsidian_read_note`         | ভল্ট-রিলেটিভ পাথ দ্বারা একটি নোট পড়ুন; ঐচ্ছিকভাবে একটি নির্দিষ্ট heading/block/frontmatter. |
| `obsidian_list_vault`        | ভল্টে ফাইল এবং ডিরেক্টরি তালিকাভুক্ত করুন (এন্ট্রির গাছ)।                                    |
| `obsidian_get_document_map`  | শিরোনাম → লাইন সংখ্যার মানচিত্র হিসাবে নোটের শিরোনাম গঠন পান।                                |
| `obsidian_get_note_metadata` | সম্পূর্ণ বিষয়বস্তু ছাড়াই ফ্রন্টম্যাটার, ট্যাগ, লিঙ্ক, char/word গণনা পান।                  |
| `obsidian_get_active_file`   | Obsidian এ বর্তমানে সক্রিয় ফাইলের পাথ + বিষয়বস্তু পান।                                     |
| `obsidian_get_periodic_note` | একটি তারিখের জন্য daily/weekly/monthly পর্যায়ক্রমিক নোট পান (আজ যদি বাদ দেওয়া হয়)।        |
| `obsidian_get_tags`          | তাদের ফ্রিকোয়েন্সি সহ সমস্ত ভল্ট ট্যাগ তালিকাভুক্ত করুন।                                    |
| `obsidian_list_commands`     | উপলব্ধ Obsidian কমান্ড IDs তালিকা করুন ( `obsidian_execute_command` এর সাথে ব্যবহার করুন)।   |
| `obsidian_sync_status`       | OmniRoute সিঙ্ক সার্ভারের অবস্থা: চলমান, ভল্টের নাম, পোর্ট, আপটাইম, শেষ সিঙ্ক।               |
| `obsidian_sync_conflicts`    | অমীমাংসিত সিঙ্ক দ্বন্দ্বগুলি তালিকাভুক্ত করুন (পথ, বিরোধের পথ, সনাক্ত করা-এ)।                |

### টুল লিখুন (`write:obsidian`)

| টুল                              | বর্ণনা                                                                                       |
| -------------------------------- | -------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | প্রদত্ত মার্কডাউন সামগ্রী সহ একটি নোট তৈরি করুন বা ওভাররাইট করুন৷                            |
| `obsidian_append_note`           | একটি নোটে বিষয়বস্তু যুক্ত করুন; ঐচ্ছিকভাবে একটি নির্দিষ্ট heading/block.                    |
| `obsidian_patch_note`            | একটি শিরোনাম, ব্লক, বা ফ্রন্টম্যাটার ক্ষেত্রে অস্ত্রোপচারের মাধ্যমে append/prepend/replace । |
| `obsidian_delete_note`           | ভল্ট থেকে একটি নোট স্থায়ীভাবে মুছে দিন।                                                     |
| `obsidian_move_note`             | ভল্টের মধ্যে একটি নোট সরান বা পুনঃনামকরণ করুন।                                               |
| `obsidian_execute_command`       | একটি Obsidian কমান্ড তার ID কমান্ড দ্বারা চালান।                                             |
| `obsidian_open_file`             | Obsidian তে একটি ফাইল খুলুন (এটি বিদ্যমান না থাকলে এটি তৈরি করে)।                            |
| `obsidian_sync_trigger`          | একটি অবিলম্বে দ্বিমুখী ডেস্কটপ ↔ মোবাইল ভল্ট সিঙ্ক ট্রিগার করুন৷                             |
| `obsidian_sync_resolve_conflict` | একটি সিঙ্ক দ্বন্দ্ব সমাধান করুন: `local` (মোবাইল), `remote` (ডেস্কটপ), বা `keep-both` রাখুন। |

> [!NOTE]
> `obsidian_patch_note` লক্ষ্যগুলি `heading | block | frontmatter` এর `targetType` এবং `append | prepend | replace` এর `operation` গ্রহণ করে, একটি ঐচ্ছিক `createTargetIfMissing` সহ। চারটি `obsidian_sync_*` টুল স্থানীয় সিঙ্ক সার্ভারের সাথে কথা বলে ( ডিফল্টভাবে`http://127.0.0.1:27781` ) এবং সিঙ্ক টোকেন প্রয়োজন।

### স্কোপ

পড়ার সরঞ্জামগুলির জন্য `read:obsidian` প্রয়োজন; লেখার সরঞ্জামগুলির জন্য `write:obsidian` প্রয়োজন। এনফোর্সমেন্ট `open-sse/mcp-server/server.ts` এ `withScopeEnforcement()` দ্বারা পরিচালিত Notion — অনুরূপ, `OMNIROUTE_MCP_ENFORCE_SCOPES=true` এ গেটেড এবং HTTP/SSE কলকারীদের জন্য বাধ্য করা হয়েছে যাদের API কী-তে `manage`/`admin` নেই, `OMNIROUTE_MCP_SCOPES` বা API কী-এর স্কোপ প্রসঙ্গ থেকে প্রাপ্ত অনুমোদিত স্কোপ সহ। [MCP-SERVER.md](./MCP-SERVER.md) দেখুন।

## এন্ডপয়েন্টসমূহ

| মেথড     | পাথ                             | উদ্দেশ্য                                                     |
| -------- | ------------------------------- | ------------------------------------------------------------ |
| `GET`    | `/api/settings/obsidian`        | `{ connected, hasToken, baseUrl, vaultPath }` রিটার্ন করে।   |
| `POST`   | `/api/settings/obsidian`        | টোকেন সংরক্ষণ + যাচাই করে (`27124` পোর্ট প্রত্যাখ্যান করে)।  |
| `DELETE` | `/api/settings/obsidian`        | সংযোগ বিচ্ছিন্ন করে (সংরক্ষিত টোকেন মুছে দেয়)।              |
| `GET`    | `/api/settings/obsidian/webdav` | সক্রিয় থাকা অবস্থায় WebDAV সিঙ্কের স্থিতি + শংসাপত্র দেয়। |
| `POST`   | `/api/settings/obsidian/webdav` | একটি ভল্ট ডিরেক্টরির জন্য WebDAV সিঙ্ক সক্রিয় করে।          |
| `DELETE` | `/api/settings/obsidian/webdav` | WebDAV সিঙ্ক নিষ্ক্রিয় করে।                                 |

> এগুলো ড্যাশবোর্ড সেটিংসের রুট। ভল্টটিতে প্রবেশ করা হয় Obsidian
> Local REST API (কনফিগার করা `base_url`) এবং উপরের MCP টুলগুলোর মাধ্যমে — কোনো
> সর্বজনীন `/v1` Obsidian প্রক্সি এন্ডপয়েন্ট নেই।

## ব্যবহারের ক্ষেত্রসমূহ

- **ভল্ট-ভিত্তিক উত্তর** — প্রথমে `obsidian_search_simple` / `obsidian_search_structured`,
  এরপর `obsidian_read_note`, যাতে কোনো এজেন্ট আপনার প্রকৃত নোট থেকে উত্তর দেয়।
- **নোট লেখা / জার্নালিং** — এজেন্টের আউটপুট, সারাংশ বা দৈনিক নোট
  (`obsidian_get_periodic_note`) ভল্টে সংরক্ষণ করতে `obsidian_write_note`, `obsidian_append_note`, অথবা
  নির্দিষ্ট অংশে পরিবর্তনের জন্য `obsidian_patch_note` ব্যবহার করুন।
- **ভল্ট নেভিগেশন** — পড়া/লেখার আগে কাঠামো অন্বেষণ করতে `obsidian_list_vault`, `obsidian_get_document_map`, এবং
  `obsidian_get_tags` ব্যবহার করুন।
- **Obsidian অটোমেশন** — কোনো এজেন্ট থেকে প্লাগইন/কমান্ড পরিচালনা করতে
  `obsidian_list_commands` + `obsidian_execute_command`; UI-তে কোনো নোট দেখাতে `obsidian_open_file` ব্যবহার করুন।
- **মোবাইল সিঙ্ক** — WebDAV সিঙ্ক সক্রিয় করুন, এরপর ডেস্কটপ↔মোবাইল সমন্বয় এবং দ্বন্দ্ব সমাধান করতে
  `obsidian_sync_trigger` / `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  ব্যবহার করুন।
