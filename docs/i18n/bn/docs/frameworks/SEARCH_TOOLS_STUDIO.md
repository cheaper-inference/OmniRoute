## সংক্ষিপ্ত বিবরণ

Search Tools Studio `/dashboard/search-tools`-কে একটি সাধারণ সার্চ প্লেগ্রাউন্ড থেকে ওয়েব সার্চ, ওয়েব স্ক্র্যাপিং এবং পাশাপাশি প্রোভাইডার তুলনার সমন্বিত একটি

## ট্যাব

### অনুসন্ধান ট্যাব

বিদ্যমান `SearchForm` + `ResultsPanel` + `RerankPanel` কে একটি ট্যাবে বিকশিত করে:

- → ফলাফল জিজ্ঞাসা করুন (শিরোনাম, URL, স্নিপেট, প্রাসঙ্গিক স্কোর)।
- কনফিগার ফলকে প্রদানকারীর মেটাডেটা (খরচ, কোটা, স্থিতি)।
- পুনঃরাঙ্ক বিভাগ: একটি পুনর্বিন্যাস মডেল বাছাই করুন, ফলাফলগুলি পুনরায় সাজান, `positionDelta` দেখান।
- যখন কোন অনুসন্ধান প্রদানকারী কনফিগার করা হয় না তখন CTA সহ খালি অবস্থা।
- `SearchHistory.tsx` এর মাধ্যমে ইতিহাস অনুসন্ধান করুন।
- কল `POST /v1/search` (বিদ্যমান শেষ বিন্দু, কোন পরিবর্তন নেই)।

### স্ক্র্যাপ ট্যাব

`POST /v1/web/fetch` মাধ্যমে URL থেকে বিষয়বস্তু বের করার জন্য নতুন ট্যাব (প্ল্যান 05-এ তৈরি):

- ইনপুট: URL + পূর্ণ-পৃষ্ঠা টগল + বিন্যাস নির্বাচক (মার্কডাউন / পাঠ্য / HTML)।
- → আনয়ন → রেন্ডার `ScrapeResult.tsx` জমা দিন।
- `ScrapeResult` মার্কডাউন প্রিভিউ + raw টগল রেন্ডার করে।
- ক্যাপ: যদি প্রতিক্রিয়া শরীর >** 256 KB** , UI `(truncated, view raw)` দেখায় এবং মোনাকো মডেলে (D21) কাঁচা খোলে।
- মেটাডেটা প্যানেল: প্রদানকারী (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search), বিলম্বতা, খরচ, প্রতিক্রিয়া আকার, লিঙ্ক গণনা।
- `useScrapeFetch.ts` হুক ব্যবহার করে।

### ট্যাব তুলনা করুন

পর্যন্ত জুড়ে একই query/URL চালায়** সমান্তরালভাবে 4 প্রদানকারী** (D22):

- প্রতি প্রদানকারীর পাশাপাশি কলাম।
- মেট্রিক্স: বিলম্ব, খরচ, ফলাফল গণনা, প্রতিক্রিয়া আকার।
- অনুসন্ধানের জন্য URL ওভারল্যাপ গণনা (শেয়ার করা URLs বনাম প্রাথমিক ফলাফলের সংখ্যা)।
- প্রদানকারী প্রতি `POST /v1/search` (অনুসন্ধান) বা `POST /v1/web/fetch` (স্ক্র্যাপ) কল করে।

## প্রদানকারী ক্যাটালগ

`ProviderCatalog.tsx` `GET /api/search/providers` থেকে সম্পূর্ণ প্রদানকারীর তালিকা প্রকাশ করে (ফেচ প্রদানকারীদের অন্তর্ভুক্ত করার জন্য F4 তে প্রসারিত):

| `kind` | `"search"` (24 প্রদানকারী) বা `"fetch"` (ফায়ারক্রল, জিনা-রিডার, ট্যাভিলি-সার্চ, টিনিফিশ, নিম্বল-সার্চ, যেকোন সার্চ-সার্চ, সমান্তরাল-অনুসন্ধান, আগ্রহী-অনুসন্ধান) |

স্ট্যাটাস হল** অনুরোধের সময় প্রাপ্ত** শংসাপত্র বিদ্যমান কিনা এবং সমস্ত কী বর্তমানে কুলডাউনে আছে কিনা তা পরীক্ষা করে।

`codex-search` (Codex ওয়েব অনুসন্ধান) এর নিজস্ব কোন চাবি নেই: এটি একটি সংযুক্ত Codex (ChatGPT) অ্যাকাউন্ট পুনরায় ব্যবহার করে, তাই প্রতিটি অনুসন্ধান ChatGPT সাবস্ক্রিপশন কোটা ব্যয় করে এবং প্রায় 10-40 সেকেন্ড সময় নেয়। যখন একটি অনুরোধ এটির নাম দেয় তখন এটি চলে; স্বয়ংক্রিয় নির্বাচন `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` বৈশিষ্ট্য পতাকা প্রয়োজন (ডিফল্টরূপে বন্ধ)।

## ব্যাকএন্ড পরিবর্তন

এই বৈশিষ্ট্যটির জন্য শুধুমাত্র একটি ব্যাকএন্ড পরিবর্তন প্রয়োজন ছিল:

### বর্ধিত `GET /api/search/providers`

`src/app/api/search/providers/route.ts` প্রসারিত হয়েছে:

- অ্যারেতে প্রতিটি ফেচ প্রদানকারীকে অন্তর্ভুক্ত করুন (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`, `keenable-search`)।
- প্রতিটি আইটেমে `kind: "search" | "fetch"` যোগ করুন।
- লাইভ শংসাপত্র অবস্থা থেকে প্রাপ্ত `status: "configured" | "missing" | "rate_limited"` যোগ করুন।
- অনগ্রসর সামঞ্জস্য বজায় রাখুন — বিদ্যমান ক্ষেত্রগুলি (`id`, `name`, ইত্যাদি) অপরিবর্তিত।
