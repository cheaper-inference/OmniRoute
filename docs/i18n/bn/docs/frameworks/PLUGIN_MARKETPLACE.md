> **সত্যের উৎস:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, এবং
> `src/app/(dashboard)/dashboard/plugins/`
> **সর্বশেষ হালনাগাদ:** 2026-06-28 — v3.8.40

OmniRoute একটি WordPress-ধাঁচের প্লাগইন সিস্টেমসহ আসে। প্লাগইনগুলো স্বয়ংসম্পূর্ণ
ডিরেক্টরি — প্রতিটিতে একটি `plugin.json` ম্যানিফেস্ট এবং একটি এন্ট্রি ফাইল থাকে — যা
রিকোয়েস্ট পাইপলাইন (`onRequest` / `onResponse` / `onError`) এবং
লাইফসাইকেল ইভেন্টগুলোতে (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
হুক করে।

**Plugin Marketplace** হলো ওই সিস্টেমের ওপর নির্মিত ডিসকভারি স্তর। এটি
ইনস্টলযোগ্য প্লাগইনগুলোর একটি ব্রাউজযোগ্য ক্যাটালগ প্রকাশ করে। ডিফল্টভাবে ক্যাটালগটি
একটি ছোট বিল্ট-ইন সিড রেজিস্ট্রি; কোনো অপারেটর এটিকে একটি কাস্টম রিমোট
রেজিস্ট্রি URL-এর দিকে নির্দেশ করতে পারেন, সে ক্ষেত্রে ফেচটি DNS-রিজলভিং SSRF গার্ড
দ্বারা সুরক্ষিত করা হয় ([নিরাপত্তা](#security) দেখুন)।

প্রতিটি প্লাগইন রুট **শুধু লুপব্যাকের জন্য** (Tier 1 — `LOCAL_ONLY`): প্লাগইনগুলো
চাইল্ড প্রসেসে কোড লোড ও এক্সিকিউট করে, তাই অথ নির্বিশেষে নন-লুপব্যাক
অরিজিন থেকে রুটগুলোতে পৌঁছানো যায় না। দেখুন
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)।

## এটা কিভাবে Together ফিট করে

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **রেজিস্ট্রি স্তর** — `src/lib/plugins/marketplace.ts`: তালিকা / ক্যাটালগ অনুসন্ধান, কোনো ব্যর্থতা বীজ রেজিস্ট্রি ফিরে পড়া.
- **জীবনচক্র স্তর** — `src/lib/plugins/manager.ts` (`pluginManager` singleton): ইনস্টল, আপগ্রেড, সক্রিয়, নিষ্ক্রিয়, আনইনস্টল, স্ক্যান, স্টার্টআপ লোড।
- **ম্যানিফেস্ট স্তর** — `src/lib/plugins/manifest.ts`: `plugin.json` জন্য Zod স্কিমা + ডিফল্ট।
- **স্ক্যানার** — `src/lib/plugins/scanner.ts`: প্লাগইন ডিরেক্টরির অধীনে ডিস্কে প্লাগইনগুলি আবিষ্কার করে।
- **লোডার** — `src/lib/plugins/loader.ts`: একটি পৃথক Node.js চাইল্ড প্রক্রিয়ায় প্রতিটি প্লাগইন তৈরি করে এবং ব্রোকাররা IPC উপর কল হুক করে। শিশুটি একটি স্যান্ডবক্স নয় (নীচে "প্লাগইন এক্সিকিউশন আইসোলেশন" দেখুন)।

## মার্কেটপ্লেস ক্যাটালগ

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) `MarketplaceEntry`
অবজেক্টগুলোর একটি তালিকা ফেরত দেয়:

| ফিল্ড         | ধরন      | নোট                                     |
| ------------- | -------- | --------------------------------------- |
| `name`        | string   | kebab-case প্লাগইনের নাম                |
| `version`     | string   | semver                                  |
| `description` | string   | সংক্ষিপ্ত সারাংশ                        |
| `author`      | string   | লেখক / সংস্থা                           |
| `license`     | string   | SPDX-ধাঁচের লাইসেন্স আইডি               |
| `downloadUrl` | string   | সোর্স ডাউনলোড URL (খালি হতে পারে)       |
| `repository`  | string?  | ঐচ্ছিক রিপোজিটরি URL                    |
| `tags`        | string[] | অনুসন্ধান/ফিল্টারের ট্যাগ               |
| `downloads`   | number   | ডাউনলোডের সংখ্যা                        |
| `rating`      | number   | 0–5                                     |
| `verified`    | boolean  | এন্ট্রিটি যাচাইকৃত হিসেবে চিহ্নিত কি না |
| `lastUpdated` | string   | ISO-সদৃশ তারিখের স্ট্রিং                |

কোনো কাস্টম রেজিস্ট্রি URL কনফিগার করা না থাকলে, ক্যাটালগটি বিল্ট-ইন
`SEED_REGISTRY` (বর্তমানে `request-logger`, `rate-limiter`, `cost-tracker`, এবং
`theme-manager`) ব্যবহার করে। সিড রেজিস্ট্রি সর্বদা উপলভ্য — কনফিগার করা কোনো রিমোট
রেজিস্ট্রিতে পৌঁছানো না গেলে, সেটি নন-`200` স্ট্যাটাস ফেরত দিলে, অথবা অপরিচিত
বডি ফেরত দিলে, `listMarketplacePlugins()` একটি সতর্কতা লগ করে এবং সিড তালিকায়
ফিরে যায়।

> দ্রষ্টব্য: মার্কেটপ্লেস **ক্যাটালগ** (ব্রাউজ/অনুসন্ধান) শুরু থেকে শেষ পর্যন্ত সংযুক্ত,
> তবে ক্যাটালগ থেকে এক ক্লিকে মার্কেটপ্লেস **ইনস্টল** এখনো বাস্তবায়িত হয়নি —
> মার্কেটপ্লেস এন্ট্রিতে ড্যাশবোর্ডের "ইনস্টল" বোতামটি বর্তমানে একটি
> "শিগগিরই আসছে" বিজ্ঞপ্তি দেখায়। বর্তমানে ইনস্টলেশন লোকাল-পাথ ইনস্টল
> ফ্লো (`POST /api/plugins`) এবং অন-ডিস্ক ডিসকভারি (`POST /api/plugins/scan`)-এর
> মাধ্যমে সম্পন্ন হয়।

## REST API

সমস্ত এন্ডপয়েন্টের জন্য ব্যবস্থাপনা প্রমাণীকরণ প্রয়োজন (`requireManagementAuth`)** এবং** লুপব্যাক শুধুমাত্র — `/api/plugins` এবং `/api/plugins/` `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) এ তালিকাভুক্ত করা হয়েছে।

| শেষবিন্দু                          | পদ্ধতি | বর্ণনা                                                          |
| ---------------------------------- | ------ | --------------------------------------------------------------- |
| `/api/plugins`                     | GET    | ইনস্টল করা প্লাগইনগুলির তালিকা করুন (ঐচ্ছিক `?status=` ফিল্টার) |
| `/api/plugins`                     | POST   | প্লাগইন উত্স ডিরেক্টরি থেকে একটি প্লাগইন ইনস্টল করুন            |
| `/api/plugins/scan`                | POST   | প্লাগইন ডিরেক্টরি স্ক্যান করুন এবং নতুন প্লাগইন নিবন্ধন করুন    |
| `/api/plugins/marketplace`         | GET    | তালিকা মার্কেটপ্লেস ক্যাটালগ এন্ট্রি                            |
| `/api/plugins/marketplace/install` | POST   | নামে একটি মার্কেটপ্লেস প্লাগইন ইনস্টল করুন                      |
| `/api/plugins/[name]`              | GET    | ইনস্টল প্লাগইন বিবরণ পান                                        |
| `/api/plugins/[name]`              | DELETE | একটি প্লাগইন আনইনস্টল করুন                                      |
| `/api/plugins/[name]/activate`     | POST   | সক্রিয় করুন ( + রেজিস্টার হুক লোড করুন)                        |
| `/api/plugins/[name]/deactivate`   | POST   | নিষ্ক্রিয় (ফায়ার `onDeactivate`, আনরেজিস্টার হুক)             |
| `/api/plugins/[name]/config`       | GET    | প্লাগইন কনফিগার + কনফিগার স্কিমা পান                            |
| `/api/plugins/[name]/config`       | PUT    | প্লাগইন কনফিগার আপডেট করুন (স্কিমার বিরুদ্ধে বৈধ)               |

`GET /api/plugins` `status` ফিল্টার `installed` / `active` / `inactive` / `error` এর একটি গ্রহণ করে। একটি অবৈধ মান `400` প্রদান করে।

### ইনস্টল করা প্লাগইনগুলির তালিকা করুন

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### একটি স্থানীয় পথ থেকে ইনস্টল করুন

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` একটি হতে হবে** পরম** একটি ডিরেক্টরির পথ** প্লাগইন উত্স ডিরেক্টরির ভিতরে** : প্লাগইন রুটের পাশে `plugin-sources`, তাই ডিফল্টরূপে `~/.omniroute/plugin-sources/`, অথবা যখন ভেরিয়েবল সেট করা হয় তখন `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` ( `src/lib/plugins/installSource.ts` `getPluginSourcesDir()` । সেখানে প্রথমে প্লাগইনটি কপি বা ক্লোন করুন। যখন পাথে `..` বা একটি নাল বাইট থাকে, সেই ডিরেক্টরির বাইরে থাকে, একটি সিমলিঙ্কের মাধ্যমে এটির বাইরে সমাধান করে, একটি সিমলিংক থাকে যার লক্ষ্য এটির বাইরে থাকে, বা যখন ডিরেক্টরিটি বিদ্যমান থাকে না তখন `400` দিয়ে ইনস্টল করা প্রত্যাখ্যান করা হয়। উৎস ডিরেক্টরিতে অবশ্যই একটি বৈধ `plugin.json` থাকতে হবে (বা একজনের পিতামাতা হতে হবে)। সফল হলে প্রতিক্রিয়া ইনস্টল করা প্লাগইন সারি সহ `201` হয়।

অন্যান্য প্লাগইন রুটের বিপরীতে, এটির জন্য ম্যানেজমেন্ট শংসাপত্রের প্রয়োজন হয় (একটি ড্যাশবোর্ড সেশন বা ম্যানেজ-স্কোপড API কী) এমনকি লগইন নিষ্ক্রিয় থাকা অবস্থায়ও (`requireLogin=false`): কোড ইনস্টল করা কখনই বেনামী ক্রিয়া নয়। একই `POST /api/plugins/marketplace/install` (body `{ "name": "<plugin>" }`) এর ক্ষেত্রে প্রযোজ্য।

### মার্কেটপ্লেস ব্রাউজ করুন

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### প্লাগইন কনফিগারেশন আপডেট করুন

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` `src/lib/plugins/manifest.ts` থেকে `validatePluginConfig()` দিয়ে প্লাগইনের `configSchema` (মেনিফেস্টে ঘোষিত) এর বিরুদ্ধে বডিকে বৈধ করে : প্রতিটি কী অবশ্যই স্কিমাতে ঘোষণা করতে হবে, মান অবশ্যই ঘোষিত প্রকারের সাথে মিলতে হবে, `number` ক্ষেত্রের সম্মান `min`/`max`, এবং `select` ক্ষেত্রগুলি অবশ্যই ঘোষিত `enum` এর সাথে মিলবে। কোনো লঙ্ঘন `400` ফেরত দেয় এবং কিছুই সংরক্ষণ করা হয় না। একটি প্লাগইন যেটি কোন `configSchema` ঘোষণা করে তার কোন কনফিগারযোগ্য কী নেই, তাই অনুরোধটি `400` দিয়ে প্রত্যাখ্যান করা হয়েছে ("প্লাগইন কোন কনফিগারযোগ্য কী ঘোষণা করে না")।

## কনফিগারেশন

### Plugin directory

Plugin-গুলো OmniRoute data directory-এর অধীনে থাকে:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (অথবা manifest.main যে ফাইলকে নির্দেশ করে)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) তিনটি ধাপে ওই directory
নির্ধারণ করে:

1. **`OMNIROUTE_PLUGINS_DIR`**, সেট করা থাকলে — `HOME`-এর মান যা-ই হোক না কেন, এটি
   হুবহু ব্যবহার করা হয়। Docker/K8s-এর জন্য এটি সুস্পষ্ট নিয়ন্ত্রণব্যবস্থা, যেখানে
   plugin tree এমন একটি path-এ bind-mounted থাকে, যার সঙ্গে সাধারণত container-এর home
   directory-এর কোনো সম্পর্ক নেই (#11827)।
2. `<home>/.omniroute/plugins`, যেখানে `<home>` নেওয়া হয় `HOME` / `USERPROFILE`
   environment variable থেকে।
3. `/tmp/.omniroute/plugins`, যখন process থেকে কোনো home-ই export করা হয় না।

নির্ধারিত directory-টি startup-এর সময় একবার `scanner.dir_resolved` হিসেবে log করা
হয় এবং কোন input প্রাধান্য পেয়েছে (`OMNIROUTE_PLUGINS_DIR`, `home`, অথবা
`no-home-fallback`) তা উল্লেখ করা হয় — ফলে কোনো image নিঃশব্দে ধাপ 3-এ পৌঁছালে,
শুধু একটি খালি plugin list দেখানোর বদলে সেটি তা জানায়।
`POST /api/plugins/scan` সেখানে থাকা বৈধ `plugin.json`-সহ যেকোনো subdirectory
খুঁজে বের করে এবং সেটি নিবন্ধন করে; একই directory হলো সেই root যেখানে
`pluginManager.install()` plugin copy করে, ফলে override করলে discovery ও
installation উভয়ই একসঙ্গে স্থানান্তরিত হয়।

> **`OMNIROUTE_PLUGINS_DIR`, `OMNIROUTE_PLUGIN_PATH` নয়।** পরেরটি কেবল CLI
> command-plugin loader (`bin/cli/plugins.mjs`) পড়ে, যাতে `omniroute-cmd-*` npm
> package খুঁজে পাওয়া যায়, যেগুলো `omniroute` subcommand যোগ করে — এখানে বর্ণিত
> runtime scanner-এর ওপর এর কোনো প্রভাব নেই। ওই দিকটি সম্পর্কে জানতে
> [PLUGINS.md](./PLUGINS.md) দেখুন।

### Custom marketplace registry URL

Marketplace catalog-এর source `pluginMarketplaceUrl` setting থেকে পড়া হয়
(`src/lib/plugins/marketplace.ts`, `settings.pluginMarketplaceUrl` পড়ে)। এটি
একটি `http(s)` URL-এ সেট করা থাকলে `listMarketplacePlugins()` সেই URL fetch করে
এবং entry-এর top-level JSON array অথবা `plugins` array-সহ একটি object গ্রহণ করে;
string `name` ছাড়া entry-গুলো filter করে বাদ দেওয়া হয়। এটি সেট করা না থাকলে
(অথবা fetch SSRF guard-এ ব্যর্থ হলে / খারাপ response ফেরত দিলে), built-in seed
registry ব্যবহার করা হয়।

Dashboard-এর "Marketplace" tab-এ এই URL-এর জন্য একটি field রয়েছে (যা
`GET /api/settings` থেকে আবার পড়া হয়)।

> বাস্তবায়ন-সংক্রান্ত নোট: dashboard-এর "Save" action
> `pluginMarketplaceUrl`-কে `PATCH /api/settings`-এ পাঠায়। এই লেখা তৈরির সময়
> key-টি `updateSettingsSchema`-তে
> (`src/shared/validation/settingsSchemas.ts`) ঘোষিত নয়, তাই এর ওপর নির্ভর করার
> আগে আপনার release-এ persistence যাচাই করুন — settings store-এ key-টি উপস্থিত
> হয়ে গেলে **read** path (`getSettings()` → `listMarketplacePlugins()`) সেটি
> বিবেচনা করে।

## নিরাপত্তা

### রুট স্তর — লুপব্যাক শুধুমাত্র

প্লাগইনগুলি উদ্ভূত শিশু প্রক্রিয়াগুলিতে কোড কার্যকর করে, তাই পুরো `/api/plugins` পৃষ্ঠকে `LOCAL_ONLY` (স্তর 1) শ্রেণীবদ্ধ করা হয়। লুপব্যাক এনফোর্সমেন্ট নিঃশর্তভাবে চলে** আগে** কোনো প্রমাণীকরণ চেক, তাই একটি ফাঁস হওয়া ম্যানেজমেন্ট টোকেন একটি টানেলের উপর দিয়ে বাক্সে পৌঁছে এখনও একটি প্লাগইন ইনস্টল, সক্রিয় বা আনইনস্টল করতে পারে না। [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) এবং হার্ড রুলস #15 / #17 দেখুন।

### মার্কেটপ্লেস রেজিস্ট্রি SSRF গার্ড

একটি কাস্টম রেজিস্ট্রি URL আক্রমণকারী-প্রভাবযোগ্য কনফিগারেশন, তাই এটি আনার আগে `listMarketplacePlugins()` এটি দুটি স্তরের মাধ্যমে চালায়:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` নয় এমন কিছু প্রত্যাখ্যান করে।
   - আক্ষরিক private/loopback/link-local/ULA হোস্ট প্রত্যাখ্যান করে (IPv4** এবং** IPv6, IPv4-mapped সহ ) ক্যানোনিকাল `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) এর মাধ্যমে।
   - সমাধান করে** উভয়** `A` এবং `AAAA` রেকর্ড করে এবং যদি প্রত্যাখ্যান করে** যেকোনো** সমাধান করা ঠিকানা হল ব্যক্তিগত — পাবলিক-হোস্টনাম → প্রাইভেট-আইপি বাইপাস বন্ধ করে।
   - **ব্যর্থ বন্ধ** : একটি DNS রেজোলিউশন ব্যর্থতা URL প্রত্যাখ্যান করে।
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): আনার সময় এবং শুধুমাত্র সর্বজনীন URL গার্ড পুনরায় প্রয়োগ করে** ব্লক রিডাইরেক্ট** (কোন পাবলিক → প্রাইভেট `30x` পিভট নেই)।

একটি URL যে উভয় স্তর ব্যর্থ হয় অনুরোধ — বাতিল করে না মার্কেটপ্লেস নিঃশব্দে অন্তর্নির্মিত বীজ রেজিস্ট্রিতে ফিরে আসে এবং একটি সতর্কতা লগ করে।

> এই রক্ষকটি PR #3774 এ বিশেষভাবে A + AAAA সমাধান করার জন্য এবং একটি IPv4-only চেকের পরিবর্তে ক্যানোনিকাল `isPrivateHost` ব্যবহার করার জন্য কঠোর করা হয়েছিল।

### প্লাগইন এক্সিকিউশন আইসোলেশন

> **প্লাগইনগুলি ডিফল্টরূপে স্যান্ডবক্স করা হয় না৷** শিশুটি একটি সাধারণ Node.js প্রক্রিয়া যা OmniRoute ব্যবহারকারী হিসাবে চলছে, কোন VM প্রসঙ্গ এবং কোন Node.js অনুমতি ফ্ল্যাগ নেই, তাই প্লাগইন কোড ব্যবহারকারী যেকোন ফাইল পড়তে এবং লিখতে পারে, প্রোগ্রাম চালাতে পারে এবং নেটওয়ার্কে পৌঁছাতে পারে। `requires.permissions` শুধুমাত্র সিদ্ধান্ত নেয় শিশু কোন পরিবেশের পরিবর্তনগুলি গ্রহণ করবে; অন্যান্য অনুমতি প্রয়োগ করা হয় না. অপ্ট-ইন `PLUGIN_PERMISSION_MODEL_ENABLED` বৈশিষ্ট্য পতাকা (ডিফল্টরূপে বন্ধ) প্রতিটি প্লাগইনকে সেই অনুমতিগুলি থেকে নির্মিত Node.js অনুমতি মডেলের অধীনে চালায়, `network` ছাড়া, যা Node.js সীমাবদ্ধ করতে পারে না (দেখুন [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#%E0%A6%85%E0%A6%A8%E0%A7%81%E0%A6%AE%E0%A6%A4%E0%A6%BF-%E0%A6%B8%E0%A6%BF%E0%A6%B8%E0%A7%8D%E0%A6%9F%E0%A7%87%E0%A6%AE) )। আপনি বিশ্বাস করেন শুধুমাত্র প্লাগইন ইনস্টল করুন. নিচের প্রক্রিয়া সীমানা ক্র্যাশ এবং হ্যাং ধারণ করে; এটি একটি নিরাপত্তা সীমানা নয়।

- **প্রক্রিয়া বিচ্ছিন্নতা** — `loadPlugin()` (`src/lib/plugins/loader.ts`) একটি পৃথক Node.js চাইল্ড প্রক্রিয়ায় প্রতিটি প্লাগইন তৈরি করে এবং IPC এর মাধ্যমে যোগাযোগ করে। `SIGTERM` → `SIGKILL` বৃদ্ধির সাথে হুক কলের একটি সময়সীমা রয়েছে।
- **Env অনুমোদিত তালিকা** — শিশু শুধুমাত্র পরিবেশের পরিবর্তনশীলের একটি অনুমোদিত তালিকা পায়; বৃহত্তর সেটটি তখনই দেওয়া হয় যখন ম্যানিফেস্ট `env` অনুমতির অনুরোধ করে।
- **উৎস কন্টেনমেন্ট ইনস্টল করুন** — `POST /api/plugins` শুধুমাত্র প্লাগইন সোর্স ডিরেক্টরি থেকে পড়ে ("স্থানীয় পাথ থেকে ইনস্টল করুন" দেখুন): পাথটি `realpath` দিয়ে ক্যানোনিকালাইজ করা হয়েছে, অবশ্যই সেই ডিরেক্টরির মধ্যেই থাকতে হবে, এবং একটি সোর্স ট্রি যেটি একটি সিমলিঙ্ক বহন করে যা এটি এড়িয়ে যায় যা কিছু অনুলিপি করার আগে প্রত্যাখ্যান করা হয়।
- **পথ নিয়ন্ত্রণ** — install/upgrade/uninstall দাবি করে যে প্লাগইন ডিরেক্টরি এবং `manifest.main` সমাধান করে** ভিতরে** কোনো অনুলিপি বা পুনরাবৃত্ত মুছে ফেলার আগে পরিচালিত প্লাগইন রুট ( `manifest.main` তে DB পাথ এবং `../` ট্র্যাভারসাল থেকে রক্ষা করে)। অ্যাক্টিভেশন `realpath` এর মাধ্যমে সিমলিঙ্কগুলি সমাধান করে এবং প্লাগইন ডিরেক্টরি থেকে বেরিয়ে আসা একটি এন্ট্রি পয়েন্ট লোড করতে অস্বীকার করে।
- **ঐচ্ছিক অখণ্ডতা পিন** — একটি ম্যানিফেস্ট একটি `integrity` (`sha256-<base64>`, SRI বিন্যাস) ক্ষেত্র ঘোষণা করতে পারে। উপস্থিত হলে, লোডার লোডের সময় এন্ট্রি ফাইল হ্যাশ যাচাই করে এবং অমিল হলে সক্রিয় করতে অস্বীকার করে। এটি অপ্ট-ইন ট্যাম্পার-সনাক্তকরণ,** না** একটি নিরাপত্তা সীমানা: এটি একটি লোড করা প্লাগইন কি করতে পারে তা সীমাবদ্ধ করে না।
- **হুক মধ্যে কোন ক্লায়েন্ট শংসাপত্র** — প্রসঙ্গটি `onRequest`, `onResponse` এবং `onError` `authorization`, `x-api-key`, `proxy-authorization` এবং `cookie` শিরোনামগুলি সরানো হয়েছে, এবং API কী রেকর্ড কোন মূল মান বহন করে না (`redactPluginContext()` তে `src/lib/plugins/hooks.ts`)।

## ম্যানিফেস্ট (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) দ্বারা যাচাইকৃত :

| মাঠ                | টাইপ        | নোট                                                                  |
| ------------------ | ----------- | -------------------------------------------------------------------- |
| `name`             | স্ট্রিং     | প্রয়োজনীয়; কাবাব-কেস (`^[a-z0-9-]+$`), 1-100 অক্ষর                 |
| `version`          | স্ট্রিং     | প্রয়োজনীয়; semver (`MAJOR.MINOR.PATCH`)                            |
| `description`      | স্ট্রিং?    | ≤ 500 অক্ষর                                                          |
| `author`           | স্ট্রিং?    | ≤ 200 অক্ষর                                                          |
| `license`          | স্ট্রিং?    | `MIT` থেকে ডিফল্ট                                                    |
| `main`             | স্ট্রিং?    | এন্ট্রি ফাইল; `index.js` থেকে ডিফল্ট                                 |
| `source`           | enum?       | `local` \| `marketplace` (ডিফল্ট `local`)                            |
| `tags`             | স্ট্রিং []? | ট্যাগ অনুসন্ধান করুন                                                 |
| `requires`         | বস্তু?      | `{ omniroute?, permissions[] }`                                      |
| `hooks`            | বস্তু?      | বুলিয়ানরা ঘোষণা করছে কোন হুক প্লাগইন প্রয়োগ করে                    |
| `skills`           | বস্তু []?   | ঐচ্ছিক দক্ষতা সংজ্ঞা                                                 |
| `enabledByDefault` | বুলিয়ান?   | ইনস্টল করার সময় স্বয়ংক্রিয়ভাবে সক্রিয় করুন                       |
| `configSchema`     | বস্তু?      | কনফিগার ক্ষেত্রগুলির মানচিত্র (`string`/`number`/`boolean`/`select`) |
| `integrity`        | স্ট্রিং?    | ঐচ্ছিক `sha256-<base64>` এন্ট্রি-ফাইল পিন                            |

অনুমতি enum `network` / `file-read` / `file-write` / `env` / `exec` থেকে নেওয়া হয়। শুধুমাত্র `env` একটি রানটাইম প্রভাব রয়েছে (শিশুর জন্য একটি সামান্য বড় পরিবেশ-পরিবর্তনশীল অনুমোদিত তালিকা); অন্যগুলো ঘোষণা এবং প্রয়োগ করা হয় না।

## লাইফসাইকেল প্রবাহ

```
install (POST /api/plugins, path)
  → ম্যানিফেস্ট স্ক্যান/যাচাই → স্টেজিংয়ে কপি → main যে ডিরেক্টরির মধ্যে রয়েছে তা নিশ্চিত করা
  → ~/.omniroute/plugins/<name>-এ অ্যাটমিক রিনেম → DB সারি যোগ করা
  → onInstall চালানো → enabledByDefault হলে: সক্রিয় করা

activate (POST /api/plugins/{name}/activate)
  → realpath কনটেইনমেন্ট যাচাই → loadPlugin() (চাইল্ড প্রসেস চালু করা)
  → ঘোষিত হুক নিবন্ধন → status = "active" → onActivate চালানো

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate চালানো (নিবন্ধন বাতিলের আগে) → হুকগুলোর নিবন্ধন বাতিল
  → চাইল্ড প্রসেস বন্ধ করা → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → সক্রিয় থাকলে নিষ্ক্রিয় করা → onUninstall চালানো
  → কনটেইনমেন্ট-যাচাইকৃতভাবে প্লাগইন ডিরেক্টরি রিকার্সিভ মুছে ফেলা → DB সারি মুছে ফেলা
```

ইনস্টল করা সংস্করণের চেয়ে ম্যানিফেস্টের সংস্করণ **কঠোরভাবে
নতুন** এমন কোনো ডিরেক্টরিতে পুনরায় `install` চালালে স্বয়ংক্রিয়ভাবে আপগ্রেড হয় (পরিষ্কারভাবে পুনরায় ইনস্টল; কনফিগ ডিফল্টে রিসেট
হয়)। একই বা পুরোনো সংস্করণ প্রত্যাখ্যান করা হয়।

## ড্যাশবোর্ড

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) এ ড্যাশবোর্ড পৃষ্ঠা দুটি ট্যাব প্রদান করে:

- **ইনস্টল করা হয়েছে** — তাদের ঘোষিত হুক, একটি activate/deactivate টগল, একটি আনইনস্টল বোতাম এবং একটি "প্লাগইনগুলির জন্য স্ক্যান" অ্যাকশন (`POST /api/plugins/scan`) সহ ইনস্টল করা প্লাগইনগুলিকে তালিকাভুক্ত করে৷
- **মার্কেটপ্লেস** — কাস্টম রেজিস্ট্রি URL সেট করার জন্য একটি ক্ষেত্র সহ `GET /api/plugins/marketplace` থেকে ক্যাটালগ দেখায়।

পৃষ্ঠাটি সর্বদা একটি সতর্কতা দেখায় যে প্লাগইনগুলি OmniRoute প্রক্রিয়ার সম্পূর্ণ সুবিধার সাথে চলে।

একটি প্রতি-প্লাগইন কনফিগার পৃষ্ঠা `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) এ থাকে।
