`devin-cli-agentic` သည် တရားဝင် Devin CLI က ACP stdio မှတစ်ဆင့် model တုံ့ပြန်ချက်များကို ပေးပို့နေစဉ်၊ အမှန်တကယ် Claude Code runtime အား OmniRoute ၏ local Anthropic
Messages endpoint ကို အသုံးပြုနိုင်စေသည်။ ၎င်းသည် လက်ရှိရှိပြီးသား Anthropic၊ Claude OAuth၊ Claude Web သို့မဟုတ် `devin-cli` provider များကို
ပြင်ဆင်ခြင်းမရှိပါ။

client ပိုင် tool call များအတွက် Claude-format tool အသုံးပြုနိုင်သော provider ဖြစ်သည့်
`devin-cli-agentic` (အတိုကောက် `dva`) မှတစ်ဆင့် route လုပ်ပါ။ မူလ `devin-cli` (`dv`) ACP executor သည်
စာသားသီးသန့်သာဖြစ်သည်။ ၎င်းသည် Devin ၏ tool မပါသော summarizer ကို လုပ်ဆောင်ပြီး tool call များကို ပြန်ပေးနိုင်ခြင်းမရှိပါ။ ၎င်း၏ model
metadata ကိုလည်း ထိုအတိုင်း သတ်မှတ်ထားသောကြောင့် tool လိုအပ်သည့် combo routing က ၎င်းကို ရှောင်ရှားပါမည်။

> **လက်ရှိအခြေအနေ- Claude Code `2.1.258` တွင် pin လုပ်ထားပြီး၊ offline နှင့် live validation ကို နောက်ဆုံးမှတ်တမ်းတင်ခဲ့သည်မှာ
> `2.1.220` တွင်ဖြစ်သည်။** `2.1.220` pin သည် Devin CLI
> `3000.2.17` နှင့် model `swe-1-7-lightning` မှတစ်ဆင့် သီးခြားခွဲထားသော scenario သုံးခုကို ပြီးမြောက်စေခဲ့သည်။ ထိုနောက်ဆုံး live run က client ပိုင် `Read`၊
> `Edit` နှင့် `Bash` turn များ၊ အောင်မြင်သော `npm test` ရလဒ်များ၊ project command နှင့် skill
> ရှာဖွေတွေ့ရှိမှု၊ Devin သီးသန့် routing နှင့် Claude egress လုံးဝမရှိခြင်းတို့ကို သက်သေပြခဲ့သည်။ ထို့နောက် pin ကို `2.1.258` သို့
> မြှင့်တင်ခဲ့သည် (OmniRoute ၏ Claude identity က အယောင်ဆောင်ထားသည့် CLI generation ဖြစ်ပြီး
> Fable 5.1 tier ကို မူလအတိုင်း ပထမဆုံး ထည့်သွင်းပေးသည့် line လည်းဖြစ်သည်)။ pin အသစ်တွင် install layer နှင့် `claude --version` ကို
> pin လုပ်ထားသော base image ပေါ်၌ စစ်ဆေးအတည်ပြုခဲ့ပြီး bridge unit suite၊ `compose config` နှင့်
> static isolation proof တို့ အောင်မြင်သည် — သို့သော် offline mock scenario နှင့် live scenario သုံးခုပါ
> suite ကို ပြန်လည်မလုပ်ဆောင်ရသေးပါ။ ဤ pin ဖြင့် bridge ကို အားထားအသုံးမပြုမီ ၎င်းတို့ကို ပြန်လည်လုပ်ဆောင်ပါ
> ("Pin လုပ်ထားသော tool များကို အပ်ဒိတ်လုပ်ခြင်း" ကိုကြည့်ပါ)။

## တည်ဆောက်ပုံ

```text
Claude Code 2.1.258 (သီးခြားခွဲထားသော root မဟုတ်သည့် Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format၊ authentication မလိုသော provider)
  -> devin acp --agent-type summarizer (တရားဝင် ACP stdio၊ Devin tool မပါ)
  -> သီးသန့် devin-auth volume အတွင်းရှိ Devin account
```

တရားဝင် CLI ၏ default ACP agent သည် ၎င်း၏ကိုယ်ပိုင် tool များကို လုပ်ဆောင်နိုင်သောကြောင့် ဤ bridge က
၎င်းကို အသုံးမပြုပါ။ ယင်းအစား tool မပါသည့် တရားဝင် CLI mode ဖြစ်သော သတ်မှတ်ထားသည့် `summarizer` ACP agent ကို စတင်ပြီး
serialize လုပ်ထားသော Anthropic request ကို လုပ်ဆောင်မှုမှတ်တမ်းအဖြစ် frame လုပ်သည်။ Claude ပိုင်
လုပ်ဆောင်ချက်တစ်ခု ထပ်မံလိုအပ်ပါက တုံ့ပြန်ချက်တွင် client tool envelope တစ်ခုတည်းသာ အတိအကျ ပါဝင်ရမည်။ ACP
`tool_call` သို့မဟုတ် `tool_call_update` တစ်ခုခုကို တုံ့ပြန်ချက်အား အောင်မြင်သည်ဟု သတင်းမပို့နိုင်မီ ငြင်းပယ်ပါသည်။

`open-sse/executors/devin-agentic/serializer.ts` ရှိ serializer သည် `system`၊
`text`၊ `tool_use`၊ `tool_result`၊ `thinking`၊ `redacted_thinking`၊ `tool_choice` နှင့်
Claude Code က ပေးပို့ထားသော tool များကို မူလအတိုင်း ထိန်းသိမ်းထားသည်။ ပုံများနှင့် အမျိုးအစားမသိ block များသည် အမှားဖြင့် အတိအလင်း ရပ်တန့်စေသည်။ ကြီးမားသော tool result များတွင် မြင်နိုင်သည့် ဖြတ်တောက်ထားကြောင်း အမှတ်အသားကို အသုံးပြုသည်။

parser သည် model turn တစ်ခုစီအတွက် သီးခြား `<tool>{...}</tool>` envelope တစ်ခုကို လက်ခံသည်။ ၎င်းက
request ၏ tool list နှင့် name ကို တိုက်စစ်ပြီး၊ argument များကို ထို tool ၏ JSON
Schema နှင့်အညီ မှန်ကန်ကြောင်း စစ်ဆေးကာ narrative နှင့် action ရောနှောထားမှုကို ငြင်းပယ်ပြီး ကန့်သတ်ထားသော ပြုပြင်မှုတစ်ကြိမ်ကို ခွင့်ပြုသည်။ ထို့နောက် Claude Code က ရရှိလာသော Anthropic `tool_use` ကို local တွင် လုပ်ဆောင်ပြီး `tool_result` ကို OmniRoute မှတစ်ဆင့် ပြန်လည်ပေးပို့သည်။

## အလိုအလျောက် routing

provider သည် ပိတ်ဆို့မထားသည့်အခါ OmniRoute ၏ `auto/*` candidate pool များတွင် ရွေးချယ်ခံနိုင်သည်။
candidate အဖြစ် ရွေးချယ်ခံနိုင်ခြင်းသည် အမှန်တကယ် ရွေးချယ်ခံရမည်ဟု အာမမခံပါ။ combo ၏ routing strategy (ဥပမာ
နောက်ဆုံးအောင်မြင်ခဲ့သည့် provider ကို ဦးစားပေးခြင်း) က အခြား provider တစ်ခုကို ပိုမိုဦးစားပေးနိုင်သည်။ request တိုင်းကို
Devin မှတစ်ဆင့် ပို့ရန်လိုအပ်ပါက `dva/<model>` သို့မဟုတ် Devin-first combo ကို အသုံးပြုပါ။

## သီးခြားခွဲထားမှုနှင့် ခြိမ်းခြောက်မှုဆိုင်ရာ ပုံစံ

Host ၏ Claude ထည့်သွင်းမှု၊ အကောင့်နှင့် ဖွဲ့စည်းသတ်မှတ်မှုတို့သည် ဤသတ်မှတ်နယ်ပယ်တွင် မပါဝင်ဘဲ
အသုံးပြုခွင့်မရှိဟု သတ်မှတ်ထားသည်။ Compose ဝန်ဆောင်မှုများသည်-

- ဖတ်ရှုရန်သာဖြစ်သော root ဖိုင်စနစ်၊ ဖယ်ရှားထားသော လုပ်ဆောင်ခွင့်များနှင့်
  `no-new-privileges` တို့ကို အသုံးပြုပြီး UID/GID `10001:10001` အဖြစ် လည်ပတ်သည်။
- သီးသန့် `/home/bridge`၊ Claude ဖွဲ့စည်းသတ်မှတ်မှုအတွက် သီးခြား volume၊ ခွဲခြားထားသော OmniRoute ဒေတာ
  နှင့် သီးခြား `devin-auth` volume တို့ကို အသုံးပြုသည်။
- စွန့်ပစ်နိုင်သော `.sandbox` workspace/evidence များကိုသာ mount လုပ်သည်။
- Host home၊ Keychain၊ SSH၊ cloud အထောက်အထားများ သို့မဟုတ် Docker socket ကို mount မလုပ်ပါ။
- တိကျစွာသတ်မှတ်ထားသော environment များကို တည်ဆောက်ပြီး Anthropic API/OAuth/routing variable များကို ဖယ်ရှားသည်။
- Claude Code inference ကို စက်အတွင်းသုံး key ဖြင့် `http://omniroute:20128` သို့သာ ညွှန်ကြားသည်။

Offline profile သည် internal network ကို အသုံးပြုသည်။ Live profile တွင် OmniRoute သည်
တရားဝင် Devin endpoint များကို `network-guard` မှတစ်ဆင့်သာ ဆက်သွယ်ပြီး အခြားမသက်ဆိုင်သော destination များကို ပိတ်ပင်ထားသည်။
Claude Code တွင် သီးခြား deny-all egress guard ရှိပြီး `NO_PROXY` မှတစ်ဆင့် local OmniRoute
ဝန်ဆောင်မှုကိုသာ ဆက်သွယ်နိုင်သည်။ Guard audit ဖိုင်များကို သက်ဆိုင်ရာ guard process ကသာ mount လုပ်ထားသည်။
Script များသည် token မပါဝင်သော evidence ကို export မလုပ်မီ ဖိုင်ပိုင်ရှင်၊ mode၊ link အရေအတွက်နှင့် ဆုံးဖြတ်ချက်တိုင်းကို
စစ်ဆေးသည်။

သီးခြားခွဲထားမှု အထောက်အထားကို သီးခြားလွတ်လပ်စွာ လုပ်ဆောင်ပါ-

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

၎င်းသည် topology၊ အမည်ပေးထားသော mount များ၊ non-root/read-only ဆက်တင်များ၊ တိကျစွာသတ်မှတ်ထားသော local routing၊
အထိခိုက်မခံသော environment variable များ မရှိခြင်း၊ Docker socket မရှိခြင်း၊
`api.anthropic.com` နှင့် `claude.ai` သို့ ဝင်ရောက်မှု ပိတ်ဆို့ထားခြင်း၊ Devin-only provider ရွေးချယ်မှုနှင့်
ACP backend မရရှိနိုင်သည့်အခါ ပြတ်သားစွာ မအောင်မြင်ခြင်းတို့ကို အတည်ပြုသည်။

## ပထမအကြိမ် စီစဉ်သတ်မှတ်ခြင်းနှင့် ပုံမှန်အသုံးပြုခြင်း

သတ်မှတ်ထားသော image ကို build လုပ်ပါ-

```bash
./scripts/devin-bridge/build
```

သီးခြားခွဲထားသော Devin volume တွင်သာ စစ်မှန်ကြောင်းအတည်ပြုပါ-

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Login command သည် remote/container environment များအတွက် ရည်ရွယ်ထားသော တရားဝင် manual-token
လုပ်ငန်းစဉ်ကို အသုံးပြုသည်။ တန်ဖိုးကို CLI prompt ထဲသို့ တိုက်ရိုက်ထည့်သွင်းရပြီး process argument
အဖြစ် ပေးပို့ခြင်း၊ Git သို့ ရေးသားခြင်း သို့မဟုတ် host မှ ကူးယူခြင်း မပြုပါ။

သီးခြားခွဲထားသော Claude Code runtime ကို စတင်ပါ-

```bash
./scripts/devin-bridge/launch
```

`launch` သည် container အတွင်းရှိ Claude Code ကို မစတင်မီ သီးခြားခွဲထားမှု၊ Devin စစ်မှန်ကြောင်းအတည်ပြုမှုနှင့်
model ရှာဖွေတွေ့ရှိမှုတို့ကို ပြန်လည်စစ်ဆေးသည်။ ၎င်းသည် host ၏ Claude executable ကို မည်သည့်အခါမျှ
မလုပ်ဆောင်ပါ။ Model alias များကို `.env.devin-bridge` တွင် သတ်မှတ်နိုင်ပြီး စီစဉ်သတ်မှတ်ထားသော တန်ဖိုးတိုင်းတွင်
`devin-cli-agentic/` prefix ကို ဆက်လက်ထားရှိရမည်။

## အတည်ပြုစစ်ဆေးရေး command များ

ပြန်လည်လုပ်ဆောင်၍ တူညီသောရလဒ်ရနိုင်သည့် offline လမ်းကြောင်းသည် Devin အကောင့်မလိုအပ်သည့်အပြင် runtime Internet လည်း မရှိပါ-

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

စစ်မှန်ကြောင်းအတည်ပြုထားပြီး ရွေးချယ်အသုံးပြုရသော live လမ်းကြောင်းမှာ-

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Live runner သည် ACP session များကို တစ်ပြိုင်နက် ဆက်တိုက်မဖွင့်မိစေရန် scenario များအကြား စောင့်ဆိုင်းပြီး
စာသားဖြင့် ဖော်ပြထားသော အဆိုများကို ယုံကြည်မည့်အစား ဖွဲ့စည်းပုံကျသော Claude stream event များကို အတည်ပြုစစ်ဆေးသည်။ ၎င်း၏
scenario သုံးခုက အောက်ပါတို့ကို သက်သေပြသည်-

1. Project ကို တိုက်ရိုက်ဖတ်ရှုခြင်းနှင့် ချို့ယွင်းချက်ခွဲခြမ်းစိတ်ဖြာခြင်း၊
2. အမှန်တကယ် `Edit` တစ်ခု၊ client ပိုင် `Bash` `npm test` တစ်ခုနှင့် နောက်ဆုံးရလဒ်၊
3. `/bridge-check` နှင့် `bridge-proof` ရှာဖွေတွေ့ရှိမှု၊ project ကို ဖတ်ရှုခြင်း၊ အောင်မြင်သော အခြား
   client ပိုင် `npm test` တစ်ခုနှင့် ဆိုင်းငံ့အလုပ်မရှိဘဲ ပြီးဆုံးခြင်း။

နောက်ဆုံး gate သည် Devin network audit ကိုလည်း စစ်ဆေးပြီး Claude egress audit တွင်
မည်သည့်အရာမျှ မရှိဘဲ ဆက်လက်ဗလာဖြစ်နေရန် လိုအပ်သည်။

## ပင်ထိုးသတ်မှတ်ထားသော ကိရိယာများကို အပ်ဒိတ်လုပ်ခြင်း

Image တွင် Node၊ Claude Code နှင့် Devin CLI တို့ကို
`docker/devin-bridge/Dockerfile` ၌ ပင်ထိုးသတ်မှတ်ထားသည်။ အပ်ဒိတ်လုပ်ရန်-

1. တိကျစွာသတ်မှတ်ထားသော ဗားရှင်းများကို ပြောင်းလဲပါ။
2. Architecture တစ်မျိုးစီအလိုက် Devin archive checksum နှစ်ခုစလုံးကို တရားဝင်
   artifact အတွက် တန်ဖိုးများဖြင့် အစားထိုးပါ။
3. ပြန်လည် build လုပ်ပြီး offline validation command အားလုံးကို run ပါ။
4. Image အတွင်းရှိ ဗားရှင်းများကို အတည်ပြုပါ။
5. Authentication ပြုလုပ်ထားသော scenario သုံးခုပါ live suite ကို ပြန်လည် run ပါ။

CLI နှစ်ခုအနက် မည်သည့်တစ်ခုကိုမျှ host ပေါ်တွင် global အဖြစ် မတပ်ဆင်ပါနှင့်။ ထို့အပြင်
checksum အတည်ပြုခြင်းကို အတည်မပြုထားသော download ဖြင့် အစားမထိုးပါနှင့်။

## ပြဿနာရှာဖွေခြင်းနှင့် ရှင်းလင်းခြင်း

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  သည် local routing နှင့် အရေးကြီးအချက်အလက်များ ဖယ်ရှားထားသော executor error များကို ပြသသည်။
- `.sandbox/evidence/mock-acp.jsonl` သည် အဖြေတိကျစွာ ထပ်မံရရှိနိုင်သော mock ACP action များကို မှတ်တမ်းတင်သည်။
- `.sandbox/evidence/claude-stream.jsonl` သည် အမှန်တကယ် Claude Code offline run ကို မှတ်တမ်းတင်သည်။
- `.sandbox/evidence/live-*.jsonl` သည် အတည်ပြုပြီးသော live stream သုံးခုကို မှတ်တမ်းတင်သည်။
- `.sandbox/evidence/egress.jsonl` နှင့် `.sandbox/evidence/claude-egress.jsonl` တို့သည် အတည်ပြုပြီး
  token မပါဝင်သော guard audit မိတ္တူများဖြစ်သည်။

Login/config volume များကို ထိန်းသိမ်းထားပြီး သက်ဆိုင်ရာ container နှင့် network များကို ရပ်တန့်ရန်-

```bash
./scripts/devin-bridge/clean
```

Named volume များအပါအဝင် bridge ပိုင် environment တစ်ခုလုံးကို ဖယ်ရှားရန်-

```bash
./scripts/devin-bridge/clean --all
```

## ကန့်သတ်ချက်များ

- Devin CLI `3000.2.17` သည် tool မပါသော neutral ACP agent ကို မပံ့ပိုးသောကြောင့် bridge သည် ပုံသေ
  no-tools `summarizer` role ကို အားကိုးထားသည်။ Adapter သည် summary ပုံစံဖြစ်နေသော
  ကြားခံ response များကို ချိန်ညှိပေးသော်လည်း အကန့်အသတ်ရှိသော repair တစ်ကြိမ်သည် အတိအလင်း ကျရှုံးနိုင်သေးသည်။
- Live ACP call များသည် ယာယီ `502`/`504` response များကို ပြန်ပေးနိုင်သည်။ Harness သည် scenario များကြား
  အချိန်ခြားပေးထားသည်။ ဆက်တိုက်ကျရှုံးနေပါက fail-closed အဖြစ် ဆက်လက်ထားပြီး အခြား provider ကို လုံးဝမရွေးချယ်ပါ။
- ACP context ကို Anthropic request တစ်ခုစီမှ ပြန်လည်တည်ဆောက်သည်။ Process/session
  affinity မရှိပါ။
- Model response တစ်ခုလျှင် tool call တစ်ခုကိုသာ ပံ့ပိုးသည်။ Parallel call များကို ငြင်းပယ်သည်။
- Image များကို အတိအလင်း မပံ့ပိုးပါ။ Vision၊ thinking output၊ effort control များနှင့် 1M
  context window ကို ရရှိနိုင်သည်ဟု မကြေညာထားပါ။
- SSE သည် တရားဝင် Anthropic lifecycle event များကို အသုံးပြုသော်လည်း အကန့်အသတ်ရှိသော ACP turn ကို
  စုဆောင်းပြီးမှသာ ထုတ်လွှင့်သည်။ ACP chunk များကို ရရှိလာသည်နှင့် တစ်ပြိုင်နက် ဆက်လက်မပို့ပါ။
