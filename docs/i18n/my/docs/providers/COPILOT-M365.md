`copilot-m365-web` (alias `m365copilot`) သည် `m365.cloud.microsoft/chat` ရှိ စစ်မှန်သော Microsoft 365 Copilot စက်ရှင်မှတဆင့် OpenAI ဖော်မတ် ချတ်တောင်းဆိုမှုများကို ပေးပို့သည်။ ၎င်းသည် တရားဝင်မဟုတ်သော မူရင်းပေါင်းစပ်မှုတစ်ခုဖြစ်သည်- သီးခြား proxy လုပ်ငန်းစဉ် သို့မဟုတ် localhost အပေါ်ပိုင်း မလိုအပ်ပါ။ ပံ့ပိုးပေးသူ ID၊ နာမည်များနှင့် လက်ရှိတင်သွင်းထားသောချိတ်ဆက်မှုများသည် ပြောင်းလဲခြင်းမရှိပါ။ `copilot-web` သည် `copilot.microsoft.com` ရှိ စားသုံးသူဝန်ဆောင်မှုအတွက် မတူညီသောဝန်ဆောင်မှုပေးသူဖြစ်သည်။

> **Web Cookie ဝန်ဆောင်မှုပေးသူများထံ အသစ်လား။**
>
> ဖတ်ပါ။**`docs/getting-started/WEB-COOKIE-GUIDE.md`** ဤဝန်ဆောင်မှုပေးသူ၏ သီးခြားလမ်းညွှန်ချက်ကို မလိုက်နာမီ ယေဘူယျအားဖြင့် စနစ်ထည့်သွင်းမှုလုပ်ငန်းစဉ်အတွက်၊ အထောက်အထားစိစစ်ခြင်း လမ်းညွှန်မှု၊ ကန့်သတ်ချက်များနှင့် ပြဿနာဖြေရှင်းခြင်း
>
> **အမွေအနှစ်တင်သွင်းမှုများအတွက်-** ဤဝန်ဆောင်မှုပေးသူအတွက် အထောက်အထားမှာ** cookie မဟုတ်ပါ။** . `m365.cloud.microsoft` မှ ကွတ်ကီးများကို ကော်ပီမလုပ်ပါနှင့်။ အထောက်အထားသည် WebSocket URL query parameter နှင့် path segment တစ်ခုဖြစ်ပြီး DevTools Network တက်ဘ်မှဖတ်သည်။

## လိုအပ်ချက်များ

- `m365.cloud.microsoft/chat` တွင် Copilot သို့ဝင်ရောက်ခွင့်ရှိသော Microsoft 365 အကောင့်
- DevTools WebSocket စစ်ဆေးခြင်းအတွက် Chromium-based browser (Chrome၊ Edge)
- ထိုအကောင့်ရှိ တောင်းဆိုထားသော မော်ဒယ်သို့ ဝင်ရောက်ခွင့်၊ အိမ်ငှားနှင့် လိုင်စင်အလိုက် ရရှိနိုင်မှု ကွဲပြားသည်။

## မူရင်းအကောင့်ဝင်ခြင်း (အလုပ် သို့မဟုတ် ကျောင်းအကောင့်များ)

ရွေးပါ။**Microsoft 365 Copilot → ချိတ်ဆက်ပါ။** နှင့် လက်မှတ်ထိုးဝင်ရန် ကြိုးစားမှုကို ပြင်ဆင်ပါ။ ဒက်ရှ်ဘုတ်သည် PKCE ဖြင့် ခွင့်ပြုချက်-ကုဒ်စီးဆင်းမှုကို အသုံးပြုသည်။ သင်၏ Microsoft စကားဝှက် သို့မဟုတ် MFA ကုဒ်ကို မတောင်းပါ။

1. တစ်ခုဖွင့်ပါ။** browser တက်ဘ်အလွတ်** ထို့နောက်ဖွင့်ပါ။**DevTools → ကွန်ရက်** နှင့် enable** မှတ်တမ်းကိုထိန်းသိမ်းပါ။** . Microsoft သို့ မသွားမီ ၎င်းကို လုပ်ပါ : Windows SSO ချက်ခြင်း ပြီးသွားနိုင်သည်။
2. ချိတ်ဆက်မှု ဒိုင်ယာလော့ခ်ဖြင့် ပြသထားသော ခွင့်ပြုချက် URL ကူးယူပြီး ပြင်ဆင်ထားသည့် တဘ်တွင် ၎င်းသို့ သွားပါ။ တောင်းဆိုပါက Microsoft၏အကောင့်ရွေးချယ်မှု သို့မဟုတ် MFA ကို အပြီးသတ်ပါ။
3. ထိန်းသိမ်းထားသော ကွန်ရက်မှတ်တမ်းတွင် `https://login.microsoftonline.com/common/oauth2/nativeclient` တောင်းဆိုချက်ကို ရှာပြီး ၎င်း၏အပြည့်အစုံကို ကူးယူပါ။** URL တောင်းဆိုပါ။** .
4. ထို URL ချိတ်ဆက်မှု ဒိုင်ယာလော့ခ်ထဲသို့ ကူးထည့်ကာ ချိတ်ဆက်ပါ။ ကုဒ်ကြမ်းတစ်ခု သို့မဟုတ် နောက်ဆုံး `wrongplace` လိပ်စာဘား URL မထည့်ပါနှင့်။ လိုအပ်သော ပြန်ခေါ်မှုသည် ယာယီလမ်းညွှန်မှုတစ်ခုဖြစ်သည်။

ကြိုးစားမှုတစ်ခုစီသည် ဆယ်မိနစ်အကြာတွင် သက်တမ်းကုန်ဆုံးပြီး တစ်ကြိမ်သာ အသုံးပြုနိုင်သည်။ ကုဒ်ကိုမလဲလှယ်မီ ဆာဗာသည် ၎င်း၏အခြေအနေ၊ PKCE အတည်ပြုသူနှင့် စစ်မှန်ကြောင်းအထောက်အထားပြခြင်းပစ်မှတ်ကို စစ်ဆေးသည်။ သက်တမ်းကုန်ဆုံးပြီးနောက် သို့မဟုတ် လဲလှယ်မှုပျက်ကွက်ပြီးနောက်၊ ကြိုးစားမှုအသစ်တစ်ခု စတင်ပါ။ ကြိုးစားမှုတစ်ခုသည် ဆာဗာပြန်လည်စတင်ခြင်းကို မရှင်သန်နိုင်ပါ။

တိုကင်များသည် ရှိပြီးသားချိတ်ဆက်မှုအထောက်အထားစတိုးကိုအသုံးပြုပြီး ပြန်လည်စတင်သည့်လမ်းကြောင်းကိုအသုံးပြုသည်။ ချိတ်ဆက်မှုကို ပြန်လည် စစ်မှန်ကြောင်း အတည်ပြုခြင်းသည် တူညီသော အီးမေးလ်တစ်ခုတည်းမဟုတ်ဘဲ Microsoft tenant/object အထောက်အထား လိုအပ်ပါသည်။ ၎င်းသည် အော်ပရေတာ naming/settings ကို ထိန်းသိမ်းထားပြီး အသုံးမပြုတော့သော တင်သွင်းထားသော အထောက်အထားများကို အစားထိုးသည်။ မူရင်းအကောင့်ဝင်ခြင်းသည် work/school အကောင့်များအတွက်ဖြစ်သည်။ ရှိပြီးသားချိတ်ဆက်မှုများနှင့် ပံ့ပိုးထားသော အဆင့်ဖွဲ့စည်းပုံများအတွက် အမွေအနှစ်တင်သွင်းမှုလမ်းကြောင်းကို ဆက်လက်ရရှိနိုင်မည်ဖြစ်သည်။

URL ပြန်ခေါ်ခြင်း အပြည့်အစုံသည် တစ်ကြိမ်သာ အထောက်အထားတစ်ခုဖြစ်သည်။ ဖန်သားပြင်ဓာတ်ပုံများ၊ မှတ်တမ်းများ၊ ပံ့ပိုးပေးစာများ သို့မဟုတ် ကွန်မန့်များတွင် ၎င်းကို ဘယ်တော့မှ မထည့်ပါနှင့်။ ဤစီးဆင်းမှုသည် ဆာဗာပေါ်တွင် ဘရောက်ဆာကိုဖွင့်ထားခြင်း၊ သင့်ဘရောက်ဆာမှတ်တမ်းကို စစ်ဆေးခြင်း သို့မဟုတ် ဒေသတွင်းခေါ်ဆိုမှုပြန်ယူသည့်ဆာဗာကို စတင်ခြင်းမဟုတ်ပါ။

## အထောက်အထားဖမ်းယူမှု (WebSocket နည်းလမ်း)

1. `https://m365.cloud.microsoft/chat` တွင်ဝင်ရောက်ပြီး စကားစမြည်စတင်ပါ။
2. ဖွင့်သည်။**DevTools → ကွန်ရက်** .
3. အလိုက် စစ်ထုတ်ပါ။**WS** (WebSocket) ။
4. Chathub WebSocket connection ကို နှိပ်ပါ။ `wss://substrate.office.com/m365Copilot/Chathub/` နဲ့ အစပြုတဲ့ URL ကိုရှာပါ။
5. ၎င်း၏ထံမှ** URL တောင်းဆိုပါ။** ၊ မိတ္တူ:
   - `access_token` query ပါရာမီတာတန်ဖိုး (ခဏတာ JWT)။
   - `/Chathub/` ပြီးနောက် Chathub လမ်းကြောင်း အပိုင်း (ဥပမာ `<oid>@<tenant>`)။

URL အပြည့်အစုံတွင် ဖောင်ပါရှိသည်။

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute တွင်၊ ရွေးပါ။**Microsoft 365 Copilot** အမွေအနှစ် API-key/import ရွေးချယ်မှုကို ရွေးချယ်ပြီး အထောက်အထားကို ဖော်မတ်တွင် ကူးထည့်ပါ-

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. နှိပ်ပါ။** စမ်းသပ်ချိတ်ဆက်မှု** နှင့်** သိမ်းဆည်းပါ။** .

## အထောက်အထားဖမ်းယူခြင်း (HAR တင်သွင်းခြင်း)

WebSocket URL မှ တန်ဖိုးများကို ကိုယ်တိုင်ကူးယူမည့်အစား၊ သင်သည် DevTools HAR ဖိုင်ကို ထုတ်ယူနိုင်သည်-

1. ဖွင့်သည်။**DevTools → ကွန်ရက်** .
2. Microsoft 365 Copilot စကားဝိုင်းကို စတင်ပါ သို့မဟုတ် ဆက်လုပ်ပါ (၎င်းသည် WebSocket ချိတ်ဆက်မှုကို အစပျိုးစေသည်)။
3. Network panel တွင် right-click နှိပ်ပြီး ရွေးချယ်ပါ။** အကြောင်းအရာများဖြင့် အားလုံးကို HAR အဖြစ် သိမ်းဆည်းပါ။** .
4. OmniRoute တွင်၊ ကိုသုံးပါ။** .har ဖိုင်ကို ထည့်သွင်းပါ။** ဝန်ဆောင်မှုပေးသူချိတ်ဆက်မှု ဒိုင်ယာလော့ဂ်ပေါ်ရှိ ခလုတ်။

OmniRoute Chathub WebSocket URL အတွက် HAR စကင်န်ဖတ်ပြီး၊ `access_token` နှင့် `chathubPath` ကို ထုတ်ယူကာ အထောက်အထား အကွက်များကို အလိုအလျောက် ဖြည့်ပေးပါသည်။ HAR တင်သွင်းမှုသည် JWT သက်တမ်းကုန်ဆုံးမှုကို ကုဒ်လုပ်ပြီး ကျန်ရှိသော တိုကင်သက်တမ်းကို ပြသသည်။

> **အစစ်အမှန် HAR တင်ပို့မှု၊ ဝင်ရောက်ခွင့် တိုကင် သို့မဟုတ် တိုကင်ကို ပြန်လည်စတင်ခြင်းတို့ကို ဘယ်တော့မှ မလုပ်ပါနဲ့။** စစ်ဆေးမှုနှင့် စာရွက်စာတမ်းတန်ဖိုးများသည် အမြဲတမ်း နေရာယူထားရပါမည်။

## တိုကင်တစ်သက်တာနှင့် ပြန်လည်စတင်ပါ။

`access_token` သည် တိုတောင်းသည် (ပုံမှန်အားဖြင့်**~ 75 မိနစ်** ) အသုံးပြုနိုင်သော ပြန်လည်ဆန်းသစ်မှု တိုကင်မပါဘဲ၊ သက်တမ်းကုန်ဆုံးပြီးနောက် အထောက်အထားကို သင် ပြန်လည်ဖမ်းယူရပါမည်။

### `refreshToken` ဖြင့် အလိုအလျောက် ပြန်လည်ဆန်းသစ်ခြင်း။

Microsoft 365 ဝန်ဆောင်မှုပေးသူ၏** ချိတ်ဆက်မှုထည့်ပါ။** သို့မဟုတ်** ချိတ်ဆက်မှုကို တည်းဖြတ်ပါ။** ဒိုင်ယာလော့ခ်၊ ဖွင့်ပါ။** အဆင့်မြင့်ဆက်တင်များ → တိုကင်ပြန်လည်စတင်ခြင်း (ချန်လှပ်ထားနိုင်သည်)** . `substrate.office.com/sydney` နယ်ပယ်အတွက် Microsoft OAuth refresh တိုကင်တစ်ခုကို ကူးထည့်ကာ သိမ်းဆည်းပါ။ ထည့်သွင်းမှုကို ဖုံးကွယ်ထားပြီး သိမ်းဆည်းထားသော တိုကင်နှင့် မည်သည့်အခါမျှ ဖြည့်စွက်မထားပါ။ တည်းဖြတ်သည့်အခါ ရှိပြီးသား တိုကင်ကို သိမ်းဆည်းရန် ၎င်းကို ကွက်လပ်ထားခဲ့ပါ။ အစားထိုးရန် တိုကင်အသစ်တစ်ခုကို ကူးထည့်ပါ။

Microsoft ပြန်ပေးသောအခါ မူရင်းအကောင့်ဝင်ခြင်းသည် ပြန်လည်ဆန်းသစ်သည့်တိုကင်ကို ရရှိပါသည်။ အမွေအနှစ်တင်သွင်းမှုများအတွက်၊ ရှိပြီးသား တွဲဖက်အသုံးပြုနိုင်သော Microsoft ခွင့်ပြုချက်-ကုဒ် ထောက်ပံ့ကြေးကို အသုံးပြုပါ။ ဤဝန်ဆောင်မှုပေးသူက စက်ပစ္စည်း-ကုဒ်စီးဆင်းမှုကို အကောင်အထည်မဖော်ပါ သို့မဟုတ် ကတိပေးမည်မဟုတ်ပါ။ ပြန်လည်စတင်သည့် တိုကင်ပုံစံဖြင့်၊ OmniRoute တောင်းဆိုမှုများမပြုမီ `access_token` ကို စစ်ဆေးပြီး ပြန်လည်စတင်ရန် လိုအပ်သည့်အခါမှသာ ၎င်းကို ပြန်လည်စတင်သည်။ ပြန်လည်ဆန်းသစ်မှုအောင်မြင်ခြင်းသည် လှည့်ပတ်ထားသော ပြန်လည်ဆန်းသစ်ခြင်းတိုကင်ကို ဆက်လက်တည်ရှိနေစေပြီး ပြန်လည်ဆန်းသစ်သည့်တိုကင်သည် တရားဝင်နေချိန်တွင် လူကိုယ်တိုင် ပြန်လည်ရိုက်ကူးခြင်းကို ရှောင်ကြဉ်ပါ။

`refreshToken` မသတ်မှတ်ထားပါက၊ သက်တမ်းကုန်ဆုံးပြီးတိုင်း WebSocket အထောက်အထားကို ကိုယ်တိုင်ပြန်ရိုက်ရပါမည်။

### အဆင့်ရွေးချယ်မှု

| အဆင့်        | နာမည်များ  | အပေါ်ယံ                 |
| ------------ | ---------- | ----------------------- |
| `individual` | _(မူရင်း)_ | စားသုံးသူ M365 Copilot  |
| `edu`        | `included` | ပညာရေး M365 Copilot     |
| `enterprise` | `work`     | အလုပ်အတွက် M365 Copilot |

အဆင့်သတ်မှတ်ပါ။** အဆင့်မြင့် ဆက်တင်များ → Copilot အဆင့်** . မူရင်းအကောင့်ဝင်ခြင်းကို မသတ်မှတ်ထားသောကြောင့် အလုပ်အကောင့်တစ်ခုသည် `enterprise` (alias `work`) နှင့် ပညာရေးအကောင့် `edu` ကို မှတ်တမ်းတင်ထားသောပုံစံ IDs အသုံးပြုသည့်အခါတွင်လည်း ၎င်းတို့သည် ၎င်းတို့၏ကိုယ်ပိုင်သံစဉ်၊ ဇာတ်လမ်းနှင့် လိုင်စင်အမျိုးအစားကို ရွေးချယ်သော်လည်း အေးဂျင့်နှင့် ဖိတ်ခေါ်မှုရွေးချယ်စရာများသည် အဆင့်မှလာနေသေးပြီး တစ်ဦးချင်းစီမူလသတ်မှတ်ချက်များသည် အလုပ်ငှားရမ်းခြင်းတွင် ကျရှုံးနိုင်ပါသည်။ အဆင့်ပြောင်းလဲခြင်းသည် မော်ဒယ်လိုင်စင်ကို မပေးပေ။ ပွင့်လင်းမြင်သာသော အဆင့်မြင့်ပရိုတိုကောကို အစားထိုးမှုများသည် ဦးစားပေးဖြစ်ပြီး လိုအပ်သော ဝါယာကြိုးတန်ဖိုးများကို သိရှိမှသာ အသုံးပြုသင့်သည်။

## မော်ဒယ်များနှင့် လမ်းကြောင်းများ

မူရင်းကတ်တလောက်တွင် မှတ်တမ်းတင်ထားသော သီးခြား IDs နှင့် မူရင်းဇာတိ IDs လေးခု ပါဝင်သည်။ ကတ်တလောက်သည် တည်ငြိမ်ပြီး အကောင့်-အမှီအခိုကင်းသည်၊ အကောင့်လုပ်ပိုင်ခွင့်ဆိုင်ရာ စုံစမ်းစစ်ဆေးမှုမဟုတ်ပါ- ချိတ်ဆက်ထားသောအကောင့်သည် ၎င်းတို့ကို အသုံးမပြုနိုင်သည့်အခါတွင်ပင် အခပေးလမ်းကြောင်းများနှင့် လိုက်ဖက်ညီသော aliases များကို ဖော်ပြထားပါသည်။ မော်ဒယ်ပြသသည့် အညွှန်းများသည် ဝန်ဆောင်မှုပေးသူအမည်နှင့် မော်ဒယ်အလိုက်ရရှိနိုင်မှု ဘွိုင်လာပြားကို ချန်လှပ်ထားခြင်း၊ ဝန်ဆောင်မှုပေးသူ ကျန်ရှိနေပါသည်။**Microsoft 365 Copilot** . တံဆိပ်များ မှတ်သားထားသည်။** နာမည်များ** သို့မဟုတ်** အမွေအနှစ်** သမိုင်းဝင် မော်ဒယ်ဗားရှင်း၏ အာမခံချက် မဟုတ်ဘဲ ၎င်းတို့၏ လက်ရှိ ခွဲခြားသတ်မှတ်မှုများနှင့် ပရိုတိုကော မြေပုံများကို ထိန်းသိမ်းပါ။ သီးခြား proxy များ** / မော်ဒယ်များမှ တင်သွင်းခြင်း။** ညွှန်ကြားချက်များသည် ဤဇာတိ WebSocket ဝန်ဆောင်မှုပေးသူနှင့် မသက်ဆိုင်ပါ။

- တိကျပြတ်သားသော မော်ဒယ်လိုင်စင် ငြင်းဆိုမှု ပြန်လာပါသည်။** ၄၀၃** `m365_model_not_licensed`၊ 502 မဟုတ်ပါ။ အဆိုပါ connection/model တွဲကို လမ်းကြောင်းပိတ်စေပြီး ချိတ်ဆက်မှုတွင် လိုင်စင်ရမော်ဒယ်များကို ချန်ထားခဲ့သည်။
- `InvalidCopilotLicense` သည် `m365_account_not_licensed` အဖြစ် သီးခြားအစီရင်ခံထားသော အကောင့်အဆင့်လိုင်စင် ငြင်းဆိုမှုတစ်ခုဖြစ်သည်။
- အသုံးပြုသူတိုင်း တွန်းအားတစ်ခု ပြန်တက်လာသည်။** ၄၂၉** `m365_throttled` နှင့် ချိတ်ဆက်မှုကို အေးစေသည်။ ဦးစားပေး-ဝင်ရောက်မှု ပင်ပန်းနွမ်းနယ်မှု ပြန်ရောက်လာသည်။** ၄၂၉** `priority_access_exhausted` သည် model-scopeed ဖြစ်သည်။ `errorCode: "ReasoningTurnExhausted"` ပြန်တက်လာသော `OutOfCredits` ၏ရလဒ်** ၄၂၉** `reasoning_turns_exhausted` အစား၊ မော်ဒယ်သတ်မှတ်ထားသော၊ ပြန်လည်သတ်မှတ်ချိန်မရှိကြောင်း အရေးဆိုထားသည်။ အမြန်သံစဉ်များ ဆက်လက်ထမ်းဆောင်နေချိန်တွင် "ပို၍နက်နဲသောစဉ်းစားပါ" အသံများကို ထုပ်ရန် အလုပ်ငှားသူတစ်ဦးထံ အစီရင်ခံတင်ပြထားပါသည်။ အဆိုပါ နယ်ပယ်သည် စားသုံးသူ စောင့်ကြည့်လေ့လာခြင်းဖြစ်ပြီး၊ ဤသိုလှောင်မှုမှ ပြန်လည်ထုတ်လုပ်ထားသည့် အရာမဟုတ်ပါ။ ထို့ကြောင့် Routing သည် တူညီသော cooldown အတွက် ထိုချိတ်ဆက်မှုအပေါ် လည်ပတ်မှုမှ မှတ်တမ်းတင်ထားသော အခြား Think deeper model များကို `gpt-5.5` `gpt-5.6` ကာ Quick tones နှင့် အခြားသော ချို့ယွင်းမှုအားလုံးကို ၎င်း၏ ကိုယ်ပိုင် model တွင် ထားခဲ့သည်။ ပံ့ပိုးပေးထားသော ပြန်စမ်းကြည့်ခြင်း အရိပ်အမြွက်များကို ထိန်းသိမ်းထားသည်။ ပျောက်ဆုံးနေသော ပြန်လည်သတ်မှတ်ခြင်းကို သိရှိထားသည့် ပြန်လည်သတ်မှတ်ချိန်အဖြစ် ကြော်ငြာမထားပါ။
- Copilot ဘေးကင်းရေးငြင်းဆိုချက်တစ်ခု (`Disengaged`) ပြန်လာသည်။** ၄၀၀** `provider_safety_rejection`၊ မျှဝေပေးသူဘေးကင်းရေး-ရပ်တန့်တံဆိပ်။ ၎င်းသည် ချိတ်ဆက်မှု၏ ကျန်းမာရေးကို မည်သည့်အခါမျှ ထည့်သွင်းတွက်ချက်ခြင်းမရှိပါ၊ ကလိုင်းယင့် SDKs 400 ကို ထပ်မစမ်းပါနှင့်၊ `PROVIDER_SAFETY_STOPS_TERMINAL` ဖွင့်ထားသော ပေါင်းစပ်လမ်းကြောင်းဖြင့် အခြားပစ်မှတ်အား တောင်းဆိုမှုကို ပြန်ကစားမည့်အစား ထိုနေရာတွင် ရပ်သည်။
- ချိတ်ဆက်မှုတစ်ခုရှိ တောင်းဆိုချက်များကို လက်ရှိအကောင့် semaphore မှတဆင့် နံပါတ်စဉ်စီထားသည်။ အပြိုင်အကန့်များထက် ဦးစားပေးအလှည့်ကို ဦးစားပေးပါ။ နံပါတ်စဉ်လိုက်ခြင်းတစ်ခုတည်းသည် Microsoft၏ ပြောဆိုမှုနှုန်းကန့်သတ်ချက်များကို မဖယ်ရှားပါ။

## အပြုအမူနှင့် ကန့်သတ်ချက်များကို တောင်းဆိုပါ။

- Tools တွေဖြစ်ပါတယ်။** prompt-emulated** မူရင်း Microsoft လုပ်ဆောင်ချက်ခေါ်ဆိုမှုများ မဟုတ်ပါ။ ကိရိယာ-ဖွင့်ထားသော တောင်းဆိုချက်တစ်ခုသည် ကြားခံမျိုးဆက်တစ်ခုအား အသုံးပြုသည်။ ၎င်းသည် အခြားသော မျိုးဆက်သစ်ကိရိယာများကို ရွေးချယ်ရာတွင် အသုံးမ၀င်ပါ။ မှန်ကန်သော ပံ့ပိုးပေးထားသော အငြင်းအခုံပုံစံများပါရှိသော ကြေညာထားသော တူးလ်များကိုသာ ဖုန်းခေါ်ဆိုမှုအဖြစ် ပြန်ပို့ပေးပါသည်။
- နောက်ဆက်တွဲ ဥပမာတစ်ခုနှင့် ရှည်လျားသော ဖွဲ့စည်းတည်ဆောက်ထားသော အဖြေတစ်ခုကို စကားပြေအဖြစ် ထိန်းသိမ်းထားသည်။ ဤသည်မှာ ရည်ရွယ်ချက် သက်သေပြခြင်းမဟုတ်၊ အပလီကေးရှင်းများသည် ၎င်းတို့၏ကိုယ်ပိုင်တူးလ်ခွင့်ပြုချက်များကို ဆက်လက်ကျင့်သုံးရမည်ဖြစ်သည်။
- ပုံထည့်သွင်းခြင်းသည် ဝဘ်ကလိုင်းယင့်ပေးပို့သည့်ပုံစံအတိုင်း လုပ်ဆောင်သည်။ ပုံတစ်ပိုင်းစီ (`image_url` ဒေတာ URL သို့မဟုတ် အများသူငှာ HTTPS URL သို့မဟုတ် တုံ့ပြန်မှု `input_image`) ကို အလှည့်၏စကားပြောဆိုမှုတွင် `/m365Copilot/UploadFile` သို့ အပ်လုဒ်လုပ်ထားပြီး မက်ဆေ့ချ်သည် `ImageFile` မှတ်စာဖြင့် ၎င်းကို အမှတ်ပေးသည်။ စာသားသည် ၎င်းထိုင်သည့်နေရာကို အမှတ်အသားပြုသည် (`[image 1]`, …)။ အသစ်သော စကားဝိုင်းတစ်ခုသည် မှတ်တမ်းရှိ ပုံတိုင်းကို အပ်လုဒ်လုပ်သည်၊ ၎င်းသည် မက်ဆေ့ခ်ျအသစ်များ၏ ပုံများသာ ဆက်ရန်ဖြစ်သည်။ အများဆုံး 10 MiB တစ်ခုစီ၏ 10 PNG၊ JPEG၊ GIF သို့မဟုတ် WebP အထိ (တောင်းဆိုမှုတစ်ခုလျှင် 40 MiB ); format ကို bytes မှဖတ်သည်။ HTTPS URLs အများသူငှာ သီးသန့်၊ DNS-ပင်ထိုးထားသော အဝေးထိန်းရုပ်ပုံအစောင့်အကြပ်မှတဆင့် ရယူထားပါသည်။ အပ်လုဒ် မအောင်မြင်ပါက တောင်းဆိုမှု မအောင်မြင်ပါ (** ၅၀၂** `m365_image_upload_failed`၊** ၄၀၀** `m365_image_rejected` သို့မဟုတ် `m365_image_invalid`); ပေးထားသည့် ပုံမပါဘဲ ရှေ့သို့ ဘယ်တော့မှ မလှည့်ပါ။ စာသားမဟုတ်သော အခြားအစိတ်အပိုင်းများ (အသံ၊ ဖိုင်များ) ကို တိတ်တဆိတ် လွှတ်ချခြင်းမပြုဘဲ ပြတ်သားစွာ ပယ်ချပါသည်။
- နောက်ဆက်တွဲ တောင်းဆိုချက်တစ်ခုသည် တူညီသော အထက်စီးကြောင်း စကားဝိုင်းကို ဆက်လက်လုပ်ဆောင်ပြီး ယခင်ပြန်ကြားချက်ပြီးနောက် မက်ဆေ့ဂျ်များကိုသာ ပေးပို့ပါသည်။ ၎င်းသည် အတိအကျပြန်ကြားချက်ကို ထပ်တိုးရမည်- တူညီသောချိတ်ဆက်မှု၊ မော်ဒယ်ပရိုဖိုင်နှင့် ကိရိယာအစုံ၊ မပြောင်းလဲသောသမိုင်း (စာတိုင်းအတွက် sha256 ကွင်းဆက်တစ်ခု); နှင့် ပြန်ကြားစာ၏ တူးလ်-ခေါ်ဆိုမှု အိုင်ဒီများ သို့မဟုတ် ၎င်း၏ စာသားကို နေရာလွတ်အထိ။ အခြားမည်သည့်အရာမဆို (တည်းဖြတ်ထားသောမှတ်တမ်း၊ တူညီသောပထမမက်ဆေ့ချ်ပါသော အခြားစက်ရှင်၊ မတူညီသောပြန်ကြားချက်တစ်ခု၊ စကားဝိုင်းတွင် မိနစ် 30 ကြာ ငြိမ်သက်နေခြင်း သို့မဟုတ် Copilot၏ 600-မက်ဆေ့ချ်ထုပ်၊ id မပါဘဲ ချိတ်ဆက်မှုတစ်ခု) သည် မှတ်တမ်းတစ်ခုလုံးနှင့် အသစ်သောစကားပြောဆိုမှုတစ်ခုကို စတင်မည်ဖြစ်သည်။ မအောင်မြင်သောအလှည့်ကို ဘယ်တော့မှ ပြန်လည်စတင်မည်မဟုတ်ပါ၊ နှင့် အကြောင်းအရာ-နည်းသော `InternalError` အသစ်သောစကားဝိုင်းတွင် တစ်ကြိမ်ပြန်လည်ပေးပို့သည် (** ၅၀၂** `m365_internal_error` ထပ်ပြီး အဆင်မပြေရင်)။ ရှေ့ဆက်မှုများကို လုပ်ငန်းစဉ်မှတ်ဉာဏ်တွင် သိမ်းဆည်းထားပါသည်- ပြန်လည်စတင်ခြင်းသည် အသစ်သော စကားဝိုင်းများကို စတင်သည်။
- အလှည့်တိုင်းသည် Copilot၏ ယာယီချက်တင် (`disableMemory=1`) တွင် အလုပ်လုပ်သည် : စကားဝိုင်းသည် ၎င်းလည်ပတ်နေချိန်တွင် ၎င်း၏အကြောင်းအရာကို ထိန်းသိမ်းထားပြီး အကောင့်၏ ချတ်မှတ်တမ်းတွင် ဘယ်သောအခါမှ မပေါ်ပါ။ မော်ဒယ်စမ်းသပ်မှုများ၊ စမ်းသပ်မှုအားလုံးနှင့် ပေါင်းစပ်စမ်းသပ်မှုများသည် ထို့ကြောင့် စကားဝိုင်းများကို နောက်ကွယ်တွင် မထားခဲ့ဘဲ ဤဝန်ဆောင်မှုပေးသူကို စစ်ဆေးနိုင်သည်။
- အလှည့်တစ်ခုတွင် စက္ကန့် 120 ကြာ မလှုပ်မရှား နောက်ဆုံးရက်နှင့် အလုံးစုံ ကန့်သတ်ထားသော နောက်ဆုံးရက်ရှိသည်။ နောက်ဆုံး တစ်ခုတည်းသော အဖြေများ၊ တိုးတက်မှု စစ်ထုတ်ခြင်းနှင့် ပယ်ဖျက်ခြင်းကို မူလ transport/composer. မှ ကိုင်တွယ်ပါသည်။
- ဝဘ်အခြေခံအဖြေများသည် ၎င်းတို့၏ရင်းမြစ်များကို သိမ်းဆည်းထားသည်။ Copilot သီးသန့်အသုံးပြုမှု ထိန်းချုပ်မှု ဇာတ်ကောင်များနှင့်အတူ ကိုးကားချက်ကို အမှတ်အသားပြုပြီး အရင်းအမြစ်များကို `references` အဖြစ် ပေးပို့သည်။ အမှတ်အသားတစ်ခုစီသည် လင့်ခ်ကိုသယ်ဆောင်သော အတုံးအခဲပေါ်ရှိ `url_citation` မှတ်ချက် (`message.annotations` သို့မဟုတ် `delta.annotations` ) ဖြင့် Copilot ကို လင့်ခ်ပစ်မှတ်အဖြစ် အသုံးပြုသောအခါတွင် အမှတ်အသားတစ်ခုစီသည် နံပါတ်တပ်ထားသော Markdown လင့်ခ် (`[1](https://…)`, သို့မဟုတ် URL ) ဖြစ်လာသည်။ မရောက်ဖူးသော ရင်းမြစ်တစ်ခု ပြုတ်ကျသည်၊ ထို့ကြောင့် အမှတ်အသားများသည် သုံးစွဲသူထံ မရောက်ပါ။ တိုက်ရိုက်လွှင့်သည့်အခါ၊ ကိုးကားချက်တစ်ခုပြီးနောက် စာသားသည် ၎င်း၏ရင်းမြစ်ရောက်ရှိသည်အထိ စောင့်ပါသည်။
- Copilot၏ ကျိုးကြောင်းဆင်ခြင်ခြင်း အနှစ်ချုပ် (`ChainOfThoughtSummary`) ကို မော်ဒယ်က ပေးပို့သောအခါ၊ အဖြေ၏ တစ်စိတ်တစ်ပိုင်းအဖြစ် ဘယ်သောအခါမှ `reasoning_content` သို့ ပြန်သွားသည် ။ ကိုယ်တိုင်ပြန်ရေးသော အကျဉ်းချုပ်သည် အလှည့်အပြောင်းကို မအောင်မြင်ဘဲ ထုတ်လွှင့်ခြင်းကို ရပ်သွားစေသည်။
- မည်သည့်အကြောင်းအရာမဆိုမီ၊ licence/throttle ကျရှုံးမှုများသည် တိုက်ရိုက်ကြည့်ရှုခြင်းကို တောင်းဆိုထားသော်လည်း HTTP 403/429 ဆက်လက်ထိန်းသိမ်းထားသည်။ အကြောင်းအရာစတင်ပြီးနောက်၊ မအောင်မြင်မှုများသည် SSE အမှားဖြစ်ရပ်များဖြစ်ပြီး၊ အောင်မြင်သောပြီးဆုံးခြင်းမဟုတ်ပါ။ နောက်ဆက်တွဲ-သာ ထုတ်လွှင့်ခြင်းဖြင့် ကိုယ်စားပြုမရနိုင်သော အထက်စီးကြောင်း ပြန်လည်ရေးသားခြင်းသည် ပြတ်သားသော ထုတ်လွှင့်မှု အမှားတစ်ခုဖြစ်သည်။ ထုတ်လွှင့်ခြင်းမဟုတ်သော နှင့် ကြားခံကိရိယာ တုံ့ပြန်မှုများသည် နောက်ဆုံးစာသားကို ထိန်းသိမ်းထားသည်။
- Copilot ကိုယ်တိုင်က ချိတ်ဆက်မှုကို ငြင်းဆိုသောအခါ၊ ၎င်း၏အဖြေသည် အောက်ပါအတိုင်းဖြစ်သည်-** ၄၀၁** ငြင်းပယ်ခံရသော သို့မဟုတ် သက်တမ်းကုန်ဆုံးသွားသော လက်မှတ်ထိုးဝင်မှုအတွက် `m365_unauthorized` (ထပ်မံဝင်ရောက်ပါ)၊** ၄၂၉** အတားအဆီးအတွက် ၎င်း၏ `Retry-After` နှင့် လက်ဆွဲနှုတ်ဆက်ခြင်း ချို့ယွင်းမှုတို့နှင့်အတူ၊ ယေဘူယျချိတ်ဆက်မှု မအောင်မြင်ပါ။

## ပုံရိပ်မျိုးဆက်

`POST /v1/images/generations` နှင့် `model: "copilot-m365-web/m365-copilot-image"` (alias `m365copilot/m365-copilot-image`) သည် ဝဘ်ကလိုင်းယင့်လုပ်သကဲ့သို့ Copilot၏ built-in ပုံတူးလ်ဖြင့် ဆွဲသည်။ ပုံတစ်ပုံချင်းစီသည် Copilot အလှည့်တစ်ခုဖြစ်သည်- ၎င်းသည် ဝဘ်အသုံးပြုသူ၏ ပုံရွေးချယ်ခွင့်ကို သတ်မှတ်ပြီး `GenerateGraphicArt` ဖြင့် ရွေးချယ်ကာ Microsoft၏ ဒီဇိုင်နာဝန်ဆောင်မှုရှိ ပစ္စည်းတစ်ခုအား ညွှန်ပြသည့် တိုးတက်မှုဝင်ရောက်မှုတစ်ခုတွင် ပုံရောက်ရှိလာသည်။ ထိုရှေးဟောင်းပစ္စည်းသည် ချတ်တိုကင်ကို ငြင်းဆိုသည်၊ ထို့ကြောင့် OmniRoute ချိတ်ဆက်မှု၏ ပြန်လည်ဆန်းသစ်ထားသော တိုကင်မှ ဒီဇိုင်နာ တိုကင်ကို ထုတ်ယူပြီး ဘိုက်များကို ဒေါင်းလုဒ်လုပ်သည်။ တိုကင်ကို `designerapp.officeapps.live.com` သို့သာ ပို့ဖူးသည်။

- မူရင်းဝင်ရောက်ချိတ်ဆက်မှုတစ်ခု လိုအပ်သည် (ပြန်လည်ဆန်းသစ်သည့် တိုကင်တစ်ခု) လိုအပ်သည်။ ကူးထည့်ထားသော တိုကင်တစ်ခုနှင့် အဆင်မပြေပါ။** ၄၀၀** မည်သည့်အလှည့်မကုန်ဆုံးမီ။
- `n` သည် 1-4၊ တစ်ခုစီလှည့်သည်။ `size` သည် လမ်းညွှန်ချက်မှနေ၍ Copilot ဖတ်သည် (ပို၍ကျယ်သည်၊ ပိုမြင့်သော သို့မဟုတ် စတုရန်း) ကိုသာ ထိန်းကျောင်းသည်။ Copilot render size ကို ရွေးသည်။
- ပုံများကို inline ပြန်ပေးသည်- မူရင်းအားဖြင့် `b64_json` ၊ `response_format: "url"` အတွက် ဒေတာ URL ။
- ဖန်တီးထားသော ပုံများသည် ချတ်မှ ခွဲထွက်သော နေ့စဥ်အသုံးစရိတ် အနည်းငယ်ဖြင့် ဆွဲပါသည်။ ၎င်းကိုအသုံးပြုသောအခါ တောင်းဆိုမှုပျက်သွားပါသည်။** ၄၂၉** . ပုံမပါတဲ့ အဖြေတစ်ခုက ပျက်သွားတာ** ၅၀၂** (သို့မဟုတ်** ၄၀၀** /** ၅၀၃** Copilot၏ စာသားကို ငြင်းဆိုမှု သို့မဟုတ် စွမ်းရည်ပြဿနာတစ်ခုအဖြစ် ဖတ်သည့်အခါ၊ သတင်းစကားက ဘယ်ဟာလဲ။

## လုံခြုံရေးပုံစံ

- **တရားဝင်မဟုတ်သောပေါင်းစည်းမှု။** ဤဝန်ဆောင်မှုပေးသူသည် BizChat WebSocket ပရိုတိုကောကို ပြောင်းပြန်အင်ဂျင်နီယာများဖြစ်သည်။ Microsoft အဆုံးမှတ်ကို ပြောင်းသည့်အခါ သတိမထားမိဘဲ ပျက်သွားနိုင်သည်။
- `subscriptionRisk: true` အလံသည် ပေါင်းစည်းမှုသည် အထောက်အထားမဲ့ အဆုံးမှတ်တစ်ခုအပေါ် မှီခိုနေကြောင်း ရောင်ပြန်ဟပ်သည်။ အကောင့်ကန့်သတ်ချက်များ ဖြစ်နိုင်သော်လည်း အတည်မပြုနိုင်သေးပါ။
- ဝင်ရောက်ခွင့် တိုကင်သည် ခဏတာ JWT ဖြစ်သည်။ ၎င်းကို စကားဝှက်တစ်ခုကဲ့သို့ ဆက်ဆံပါ- ၎င်းကို ကျူးလွန်ခြင်း၊ မှတ်တမ်း သို့မဟုတ် မျှဝေခြင်း မပြုပါနှင့်။
- refresh token သည် Microsoft 365 မျက်နှာပြင်သို့ ဆက်လက်ဝင်ရောက်ခွင့်ကို ပေးသည်။ API သော့ကဲ့သို့ ဂရုတစိုက်ဖြင့် သိမ်းဆည်းပါ။

## ပြသာနာရှာဖွေရှင်းပေးခြင်း

### အထောက်အထားစိစစ်ခြင်း ချက်ချင်းပျက်ကွက်သည်။

- သင်ထံမှကူးယူကြောင်းအတည်ပြုပါ။**WebSocket URL** XHR/Fetch တောင်းဆိုချက်မှ မဟုတ်ပါ။ အထောက်အထားသည် `Authorization: Bearer` ခေါင်းစီးတွင်မဟုတ်ဘဲ Chathub WebSocket ချိတ်ဆက်မှု — ၏ `access_token` query parameter တွင်ဖြစ်သည်။
- `chathubPath` URL လမ်းကြောင်းမှ `<oid>@<tenant>` အပိုင်း အပြည့်အစုံ ပါဝင်ကြောင်း သေချာပါစေ။

### ~ 75 မိနစ်အကြာတွင် တိုကင်သည် သက်တမ်းကုန်ဆုံးသည်။

ဒါက မျှော်လင့်တယ်။ `refreshToken` မပါဘဲ၊ ဝင်ရောက်ခွင့် တိုကင်သည် သက်တမ်းတိုသည်။ တစ်ခုခု-

- DevTools မှ အထောက်အထားကို ပြန်လည်ဖမ်းယူပါ။
- စီစဉ်ပေးသည်။** အဆင့်မြင့်ဆက်တင်များ → တိုကင်ပြန်လည်စတင်ခြင်း (ချန်လှပ်ထားနိုင်သည်)** အလိုအလျောက်ပြန်လည်ဆန်းသစ်ရန်အတွက် Add သို့မဟုတ် Edit connection dialog တွင်။

### စမ်းသပ်ချိတ်ဆက်မှုအောင်မြင်သော်လည်း chat သည် 401 သို့ပြန်လာသည်။

ဖန်တီးထားတဲ့ ချိတ်ဆက်မှုတစ်ခုအတွက်ပါ။** Microsoft ဖြင့်ဝင်ရောက်ပါ။** ၊ Test Connection သည် ဝင်ရောက်ခွင့် တိုကင်၏ သက်တမ်းကုန်ဆုံးမှုကို စစ်ဆေးပြီး သိမ်းဆည်းထားသော ပြန်လည်ဆန်းသစ်သည့် တိုကင်ဖြင့် သက်တမ်းကုန်ဆုံးသွားသော တိုကင်ကို သက်တမ်းတိုးပေးသည်၊ ထို့ကြောင့် ပြီးသွားသော စမ်းသပ်မှုတစ်ခုက ပြန်လည်စတင်သည့် တိုကင်သည် အလုပ်လုပ်ဆဲဖြစ်ကြောင်း သက်သေထူပါသည်။

ကူးထည့်ထားသော အထောက်အထားအတွက်၊ Test Connection သည် အထောက်အထား၏ ပုံသဏ္ဍာန်ကို စစ်ဆေးပြီး၊ တိုကင်သည် သက်တမ်းကုန်ဆုံးသည့်အခါတွင်၊ ဝန်ဆောင်မှုပေးသူအသုံးပြုမည့် တိုကင်သည် သက်တမ်းမကုန်သေးပါ (သိမ်းဆည်းထားသော တိုကင်န်သည် ဟောင်းနွမ်းနေသော ကူးထည့်ခြင်းကို အနိုင်ရသည်၊ ပြန်လည်ဆန်းသစ်နိုင်သော တိုကင်ကို ပြန်လည်သက်တမ်းတိုးနိုင်သည်)။ သက်တမ်းမကုန်မီ ရုပ်သိမ်းထားသော တိုကင်တစ်ခုသည် စမ်းသပ်မှု အောင်မြင်ဆဲဖြစ်သည်။ chat ပြီးရင်ပြန်လာတယ်။** ၄၀၁** `m365_unauthorized` သုံးပါ။** Microsoft ဖြင့် ဝင်ရောက်ပါ။** တစ်ဖန်၊ သို့မဟုတ် အထောက်အထားအသစ်တစ်ခုကို ပြန်လည်ရိုက်ကူးပါ။

### Copilot ဝန်ဆောင်မှုပေးသူစာရင်းတွင် မပေါ်ပါ။

`copilot-m365-web` ကို ဖွင့်ထားကြောင်း သေချာပါစေ။** ဒက်ရှ်ဘုတ် → ဝန်ဆောင်မှုပေးသူများ** . အချို့သောအဆင့်များတွင် ဝန်ဆောင်မှုပေးသူကို ပုံသေအားဖြင့် ဝှက်ထားနိုင်သည်။
