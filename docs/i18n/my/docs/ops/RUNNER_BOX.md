## အိမ်စောင့်ကို တပ်ဆင်ပါ (တစ်ကြိမ်၊ သေတ္တာပေါ်တွင်)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): every 30 min, log to /var/log/runner-janitor.log
*/30 * * * * MAX_ACTIVE_RUNNERS=8 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` လိုအပ်သည်- ၎င်းကိုဖယ်ရှားခြင်းမပြုမီ အဖွင့်ဖိုင်များ၏လျှပ်တစ်ပြက်တစ်လက်နှင့် လမ်းကြောင်းတစ်ခုပျက်နေကြောင်း သက်သေပြပြီး ကိရိယာမပါဘဲ မည်သည့်အရာကိုမျှ ဖယ်ရှားမည်မဟုတ်ကြောင်း (ထွက်ပေါက် 1) မှ ပြောကြားခဲ့သည်။ `--dry-run` ဖြင့် မည်သည့်ပြောင်းလဲမှုကိုမဆို စမ်းကြည့်ပါ — သည် ၎င်းလုပ်ဆောင်ရမည့်အရာကို အတိအကျ ပရင့်ထုတ်ပြီး ဘာမှမထိပါ။

ပြေးတိုင်း ဘာလုပ်သလဲ- ပြီးနောက် ကျွန်ုပ်တို့၏ ကျန်ကြွင်းသောအရာများ (`runner-*`၊ `omniroute-*`၊ `next-build*`၊ `e2e-build.tar.gz`)**tmpfs တွင် 3 နာရီ** နှင့် `_work/_temp` disk ပေါ်တွင် 24 နာရီ ; 75 မိနစ်ထက် ပိုကြီးသော `next-build` တွင် သတိပေးပြီး ၎င်းကို ဆက်လက်လည်ပတ်စေပါသည်။ ယူနစ်ရှိသော အပြေးသမားများ၏ ၄၈ နာရီ သက်တမ်းရှိ ငွေရှင်းခြင်းများကို သုတ်သင်ခြင်း။**ရပ်သွားတယ်။** ; ဒစ်ပေါ်တွင် ≥ 85 %, မမ်မိုရီ PSI `full/avg60` ≥ 10 % နှင့် `MAX_ACTIVE_RUNNERS` ( omniroute/other ပိုင်းခြားစိတ်ဖြာမှုဖြင့်) ထက် နားဆင်သူပိုများသည်။ 1 = အာရုံစူးစိုက်မှုမှ ထွက်ရန် လိုအပ်ပါသည်။ မှတ်တမ်းကိုဖတ်ပါ။

  variable ကို ပြန်မဖွင့်ပါနှင့်။

  minutes ကြာခဲ့ပြီး disk မှ upload လုပ်ရန် 2 minutes သာ ကြာခဲ့သည်။

## လက်ခံဆောင်ရွက်ပေးထားသော lane (GitHub-hosted runners)

Repository သည် `cheaper-inference` organization ပိုင်ဖြစ်ပြီး **Team** အစီအစဉ်တွင်ရှိသည်- **တစ်ပြိုင်နက် လက်ခံဆောင်ရွက်ပေးနိုင်သော job 60 ခု** ကို organization ရှိ repository တိုင်း၊ PR စစ်ဆေးမှုတိုင်း၊ push ကြောင့် စတင်သော workflow တိုင်းနှင့် CodeQL ၏ မူလသတ်မှတ်ချက်တို့က အတူမျှဝေသုံးစွဲကြသည်။ အောက်ပါ ကိန်းဂဏန်းများကို **Pro** အစီအစဉ် (တစ်ပြိုင်နက် လက်ခံဆောင်ရွက်ပေးနိုင်သော job 40 ခု) တွင် တိုင်းတာခဲ့သည်။ 2026-10-18 ရက်တွင် `release/v3.8.52` ပေါ်၌ merge campaign တစ်ခု (~တစ်နာရီလျှင် merge 10 ခု) လုပ်ဆောင်နေစဉ် တိုင်းတာချက်အရ **24 h အတွင်း workflow run 2,500 ခု ဖန်တီးခဲ့ပြီး**၊ 6 h အတွင်း branch သို့ push 44 ကြိမ် ပြုလုပ်ခဲ့ကာ၊ PR စစ်ဆေးမှုများ နာရီပေါင်းများစွာ စောင့်ဆိုင်းနေချိန်တွင် **လက်ခံဆောင်ရွက်ပေးထားသော job 106 ခု တန်းစီနေခဲ့ပြီး** ယင်းစစ်ဆေးမှုများ မပြီးဆုံးဘဲ PR များကို merge လုပ်ခဲ့သည်။ Branch သို့ push ပြုလုပ်တိုင်း workflow ကိုးခု စတင်ခဲ့သည်-
