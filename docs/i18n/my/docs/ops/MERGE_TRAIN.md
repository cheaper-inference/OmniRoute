## လွှတ်တော်သစ်ကိုင်းပေါ် ဆင်းသက်သည်

omni-queue သည် `release/vX.Y.Z` သို့ဆင်းသက်ခြင်းကိုအုပ်ချုပ်သည်။ PR မဆင်းမီ မူရင်းဌာနခွဲတွင် `config/merge-queue/config.json` ရှိ ထိပ်တန်းအဆင့် `mode` ဖတ်ပါ။ [Omni-Queue ကို](OMNI_QUEUE.md) ကြည့်ပါ။

- **`shadow`** validation ကိုလုပ်ဆောင်ပြီး manual ပေါင်းစည်းခြင်းသို့ဆင်းသက်သည်။ ၎င်း၏နောက်ဆုံးခေါင်းတွင် အတည်ပြုထားသော PR သို့ `omni-queue` အသုံးပြုပါ။ `npm run queue -- why <PR>` ဖြင့် အရည်အချင်းပြည့်မီမှုကို စစ်ဆေးပါ။ `npm run queue -- history --base <branch>` တွင် ထိုဦးခေါင်းအတွက် စီရင်ချက်ကို စောင့်ပါ။ `would-land` တွင် ရှေ့ဆက်ပါ။ `culprit-found` သို့မဟုတ် `would-dequeue` တွင် ပေါင်းစည်းခြင်းကို ဖိထားပြီး အကြောင်းရင်းကို ပြင်ဆင်ပါ။
- **အရိပ်ခြွင်းချက်။** လက်ရှိအခြေခံထိပ်ဖျားကိုဆန့်ကျင်သည့် CI အစိမ်းရောင်အပြည့်ပါသော ရထားတစ်စီးသည် သီးခြားစီတန်းစီရင်ချက်မရှိဘဲ ဆက်လက်လုပ်ဆောင်နိုင်သည်။ PR ခေါင်းတွင် လက်ရှိအခြေခံအစွန်အဖျားပါရှိသောအခါ အလားတူခြွင်းချက် သက်ရောက်သည်။
- **`live`** ဆင်းသက်ခြင်းကို အစပျိုးရန် `omni-queue` တံဆိပ်ကို အသုံးပြုသည်။ တန်းစီခြင်းသည် PR ကို ရောက်သွားသည် ။ ပေါင်းစည်းထားသော အမိန့်များကို ချန်ထားခဲ့ကာ တန်းစီသို့ တိုက်ရိုက်တွန်းပို့ပါ။

ဆင်းသက်မှုတိုင်းသည် ပိုင်ရှင်၏ခွင့်ပြုချက်နှင့် လိုအပ်သောစစ်ဆေးမှုများ လိုအပ်သည်။ ပိုင်ရှင်မှဆင်းသက်ခွင့်ပြုပြီးနောက်မှသာ `omni-queue` အသုံးပြုပါ။ တန်းစီထားသော PRs ကိုထိသော အကာအကွယ်လမ်းကြောင်းများသည် ထို PR အတွက် ပိုင်ရှင်၏ `protected-approved` ဆုံးဖြတ်ချက်လည်း လိုအပ်ပါသည်။

"အသက်ဝင်နေသောထွက်ရှိမှုတွင် အစိမ်းရောင်တံခါးများ လိုအပ်သည်" စည်းမျဉ်းသတ်မှတ်ချက်သည် ဦးခေါင်းတွင် အစိမ်းရောင် `Gate / CI` နှင့် `Gate / Quality` လိုအပ်သည်။ အနီရောင်ဂိတ်ကို ကျော်ဖြတ်ဖို့ `--admin` ဘယ်တော့မှ မသုံးပါနဲ့။ လွှတ်လိုက်သော အအေးခဲတုံးများသည် အေးခဲနေသော အကိုင်းအခက်ထဲသို့ ပေါင်းစည်းသွားသည်။ [Hard Rule 21 ကို](HARD_RULES_DETAIL.md) ကြည့်ပါ။ အခြားစက်ရှင်တစ်ခု အလုပ်လုပ်နေသည်ဟူသော တောင်းဆိုချက်ကို အညွှန်းတပ်ခြင်း၊ ပေါင်းစည်းခြင်း သို့မဟုတ် တွန်းခြင်းသို့ ဘယ်သောအခါမှ မတွန်းလှန်ပါ။ [Hard Rule 22](HARD_RULES_DETAIL.md) ကိုကြည့်ပါ။

## ရထားဆွဲခိုင်းတယ်။

1. လက်ရှိထွက်ရှိထားသော အခြေခံအစွန်အဖျားတွင် ရထားဌာနခွဲတစ်ခု စတင်ပါ။ ပေါင်းစည်းခြင်းများကို အသုံးပြု၍ အတည်ပြုထားသော အဖွဲ့ဝင်အကြီးအကဲများကို အတိအကျ ပေါင်းစပ်ပါ။ Squash နှင့် rebase ကိုရှောင်ရှားခြင်းဖြင့် ၎င်းတို့၏ကျူးလွန်မှုသမိုင်းကို ထိန်းသိမ်းပါ။
2. ရထားဌာနခွဲအတွက် တောင်းဆိုချက်တစ်ခုဖွင့်ပါ။ အဆိုပါ PR လက်ရှိအခြေခံထိပ်ဖျားတွင် ၎င်း၏ကိုယ်ပိုင် CI အပြည့်အစုံဖြင့် အတည်ပြုပါ။ ဆင်းသက်ခြင်းမပြုမီ အခြေခံအစွန်အဖျားနှင့် အတည်ပြုထားသော အဖွဲ့ဝင်ခေါင်းများကို ပြန်လည်စစ်ဆေးပါ။ တရားဝင်လျှောက်ထားသူပြောင်းလဲသောအခါ ရထားနှင့် ၎င်း၏ CI ပြန်လည်စတင်ပါ။
3. သက်ဆိုင်သော တန်းစီမုဒ်အောက်တွင် ပေါင်းစည်းမှုဖြင့် ရထား PR မြေချပါ။ တိုက်ရိုက်မုဒ်တွင်၊ တန်းစီ၏ `merge-ff` ဆင်းသက်သည့်နည်းလမ်းသည် ပေါင်းစည်းမှုကို ထိန်းသိမ်းထားသည်။ မူလအသင်းဝင် အကြီးအကဲများသည် လွှတ် တော်ဌာနခွဲမှ ဆက်သွယ်နိုင်သည်။ GitHub သည် အဖွဲ့ဝင် PRs ပေါင်းစည်းကြောင်း အမှတ်အသားပြုပြီး ကတိကဝတ်များသည် ၎င်းတို့၏ စာရေးဆရာများကို ဆက်လက်ထိန်းသိမ်းထားသည်။

အများသူငှာ ဥပမာတစ်ခုသည် [PR #21071](https://github.com/cheaper-inference/OmniRoute/pull/21071) ဖြစ်သည်။ ၎င်းသည် အဖွဲ့ဝင် 18 ဦးကို PRs ပေါင်းစပ်ပြီး 2026-11-24 တွင် ပေါင်းစည်းရေးကတိတစ်ခုဖြင့် ဆင်းသက်ခဲ့သည်။

`main` မှ နောက်ထုတ်သည့်ဌာနခွဲသို့ ထပ်တူပြုခြင်းသည် ပေါင်းစည်းခြင်းမှတစ်ဆင့် ရောက်ရှိလာပါသည်။ နောက်ပိုင်း ထပ်တူပြုခြင်းအတွက် `main` မျိုးရိုးကို ထိန်းသိမ်းရန် လိုအပ်သည်။ [Worktree Isolation ကို](WORKTREE_ISOLATION.md#sync-back-landings-are-merge-commits-never-squash) ကြည့်ပါ။

## ဒေသခံပေါင်းစည်း-ရထား validator

```bash
scripts/release/merge-train.sh [--plan] [--fast] <base-branch> <PR#> [<PR#>...]
```

စစ်ဆေးသူသည် အခြေခံနှင့် PR ခေါင်းများကို ထုတ်ယူပြီး တစ်ခါသုံး အလုပ်ခွင်တစ်ခုတွင် ပေါင်းစပ်ထားသည်။ ၎င်းသည် ရလဒ်သစ်ပင်ပေါ်တွင် တစ်ကြိမ် ၎င်း၏ parity suite ကို လုပ်ဆောင်သည်။ မအောင်မြင်သော ဦးခေါင်းကို ဆွဲယူခြင်း သို့မဟုတ် ပေါင်းစပ်ခြင်း ပဋိပက္ခသည် PR ကို ထုတ်လိုက်ပြီး ကျန် PRs နှင့် ဇာတ်ညွှန်းကို ဆက်လက်လုပ်ဆောင်သည်။

- **`--plan`** ရွေးချယ်ထားသောမုဒ်၏ ခြေလှမ်းများကို ပရင့်ထုတ်ပြီး worktree မဖန်တီးဘဲ သို့မဟုတ် အဝေးထိန်းခလုတ်ကို မဆက်သွယ်ဘဲ ထွက်ပါ။ အမြန်အစီအစဉ်ကို စစ်ဆေးရန် ၎င်းကို `--fast` နှင့် ပေါင်းစပ်ပါ။
- **`--fast`** ဘုံအငြိမ်ဂိတ်များကို လုပ်ဆောင်သည်၊ ရွေးချယ်ထားသော ပြောင်းလဲထားသော `node:test` ဖိုင်များကို `tests/unit/` နှင့် `npm run test:vitest` အောက်တွင် လုပ်ဆောင်သည်။ အမြန်မုဒ်ကို အသုံးပြုသည့်အခါ စုဆောင်းထားသော အကြံပြုချက်တွင် အနည်းဆုံး တစ်ကြိမ် စက်တွင်းအတည်ပြုချက်ကို လုပ်ဆောင်ပါ။
- **မုဒ်အပြည့်** တစ်ခုတည်းသော တည်ငြိမ်သောတံခါးများကို ပေါင်းထည့်ပြီး `npm run test:unit` နှင့် `npm run test:vitest` ကို လုပ်ဆောင်သည်။

base probe ကိုရနိုင်လျှင် မထိရသေးသော base တွင် ပျက်ကွက်နေသော static gate ကို ပြန်ဖွင့်သည်။ ဇာတ်ညွှန်းသည် အမွေဆက်ခံထားသော ကျရှုံးမှုများကို အစီရင်ခံပြီး အသိအမှတ်ပြုထားသော ချိုးဖောက်သည့်စာကြောင်းတိုင်းသည် အခြေခံပေါ်တွင် ပေါ်လာပြီး စုစုပေါင်းအရေအတွက် တိုးမလာသည့်အခါ ဆက်လက်လုပ်ဆောင်ပါသည်။

## အဆင့်တန်း

- **PR အလိုက်** CI နှင့် Quality သည် ပြောင်းလဲထားသော လမ်းကြောင်းများအပေါ် အခြေခံ၍ စစ်ဆေးမှုများကို ရွေးချယ်ပါ။ ကုဒ် PRs CI တွင် သီးခြားယူနစ်နှင့် Vitest အလုပ်များဖြင့် လျင်မြန်သော အရည်အသွေးတံခါးများနှင့် သက်ရောက်မှုရှိသော စမ်းသပ်မှုများကို လုပ်ဆောင်သည်။
- **တန်းစီအလိုက် ကိုယ်စားလှယ်လောင်း။** CI နှင့် Quality သည် ၎င်း၏လူတန်းစာ ref တွင် ပေါင်းစပ်ထားသော ကိုယ်စားလှယ်အတွက် ပရိုဖိုင်အပြည့်အစုံကို လုပ်ဆောင်သည်။
- **ထုတ်ပြန်ချက်တစ်ခုအတွက် အကြံပြုချက်။** Release-Green သည် ၎င်း၏လမ်းကြောင်း စစ်ထုတ်မှုများနှင့် ကိုက်ညီသော အတွန်းများပေါ်တွင် လျင်မြန်သော ခက်ခဲသော တံခါးများကို လုပ်ဆောင်သည်။ တစ်ရက်လျှင် စီစဉ်ထားသော သုံးကြိမ်ပြေးခြင်းသည် ထုတ်ဝေရေးဌာနခွဲအတွက် အပြည့်အ၀ အသုံးပြုသည်။
- **ထုတ်ဝေမှုနှုန်း။** CI matrix အပြည့်အစုံတွင် E2E shards၊ package validation၊ tarball boot smoke နှင့် coverage checks များ ပါဝင်သည်။ [ဖြန့်ချိမှုစာရင်းကို](RELEASE_CHECKLIST.md) ကြည့်ပါ။

## `merge-train.sh` အတွက် အသစ်ပြန်ထုတ်ရန် လိုအပ်ချက်များ

worktrees မဖန်တီးမီ preflight သည် အလုပ်လုပ်သည်။ `npm ci` ဖြင့်မှီခိုမှုကိုထည့်သွင်းပါ။ `node_modules/.bin/tsc` ကို executable လုပ်နိုင်ပြီး `node_modules/node_modules` မရှိကြောင်း အတည်ပြုပါ။ `node_modules/.bin/bun --version` အောင်မြင်ကြောင်း စစ်ဆေးပါ။

Bun postinstall ကို ကျော်သွားပါက `(cd node_modules/bun && node install.js)` run ပါ။ ဝန်ဆောင်မှုပေးသူ၏ ညီညွတ်မှုနှင့် လူသိများသော သင်္ကေတစစ်ဆေးမှုများသည် Bun အသုံးပြုသည်။ အတည်ပြုသူသည် ပိတ်ဆို့ခြင်းတံခါးအဖြစ် `npm run check:cycles:ratchet` လုပ်ဆောင်သည်။ သီးခြား `npm run check:cycles` အမိန့်သည် အကြံပေးချက်ဖြစ်သည်။
