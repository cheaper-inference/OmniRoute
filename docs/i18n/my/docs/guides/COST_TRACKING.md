## ၎င်းသည် ဘာလဲ (နှင့် ဘာမဟုတ်သလဲ)

OmniRoute သည် token အရေအတွက်ကို model တစ်ခု၏ ဈေးနှုန်းနှုန်းထားများဖြင့် မြှောက်ခြင်းအားဖြင့်
ပြီးမြောက်သည့် တောင်းဆိုမှုတိုင်းအတွက် USD ကုန်ကျစရိတ်ကို သတ်မှတ်ပေးသည်။ ဤကိန်းဂဏန်းများကို **ကုန်ကျစရိတ်များ** dashboard၊
`omniroute cost` / `omniroute usage` CLI၊ CSV/JSON export များနှင့် API key တစ်ခုချင်းစီအလိုက် budget များတွင် အသုံးပြုသည်။

> **Dashboard ပေါ်ရှိ "ကုန်ကျစရိတ်" သည် ငွေတောင်းခံလွှာမဟုတ်ဘဲ ချွေတာမှု ခြေရာခံစနစ်တစ်ခု ဖြစ်သည်။** OmniRoute က သင့်ထံမှ မည်သည့်အခါမျှ ငွေကောက်ခံခြင်းမရှိပါ
> — ၎င်းသည် သင်ချိတ်ဆက်ထားပြီးဖြစ်သည့် provider များ (သင့်ကိုယ်ပိုင်
> subscription များ၊ အခမဲ့အဆင့်များနှင့် API key များ) ထံသို့ သင့်တောင်းဆိုမှုများကို လမ်းကြောင်းခွဲပေးခြင်းသာ ဖြစ်သည်။ အခမဲ့
> model များပေါ်တွင်သာ စုဆောင်းရရှိထားသည့် "$290 total cost" သည် အကြမ်းဖျင်းအားဖြင့် အခပေး API တစ်ခုအတွက်
> **သင် _မပေးခဲ့ရသည့်_ $290** ကို ဆိုလိုသည်။ ဤကိန်းဂဏန်းသည် တူညီသော traffic ကို ပုံမှန်ကြေညာထားသော ဈေးနှုန်းများဖြင့် အသုံးပြုခဲ့ပါက
> ကုန်ကျမည့်ပမာဏ၏ _ခန့်မှန်းချက်_ ဖြစ်သဖြင့် သင့်အသုံးပြုမှုသည် မည်သည့်နေရာတွင် အများဆုံး စုဝေးနေကြောင်းနှင့်
> ပိုမိုဈေးသက်သာသော/အခမဲ့ provider များထံ လမ်းကြောင်းခွဲပေးခြင်းကြောင့် မည်မျှ ချွေတာနိုင်ကြောင်း မြင်တွေ့နိုင်သည်။

ဤအဓိပ္ပာယ်သတ်မှတ်ချက်ကို project [README](../../README.md) တွင်လည်း တိုက်ရိုက်ဖော်ပြထားသည် ("dashboard ပေါ်ရှိ
'ကုန်ကျစရိတ်' သည် ငွေတောင်းခံလွှာမဟုတ်ဘဲ ချွေတာမှု ခြေရာခံစနစ်တစ်ခု ဖြစ်သည်")။

ဤကိန်းဂဏန်းသည် ခန့်မှန်းချက်တစ်ခု ဖြစ်သောကြောင့်-

- ၎င်းသည် model တစ်ခုချင်းစီအတွက် OmniRoute တွင်ရှိသော ဈေးနှုန်းဇယားပေါ် မူတည်သည်။ ဈေးနှုန်း
  ထည့်သွင်းထားခြင်းမရှိသည့် model သည် ကုန်ကျစရိတ် `0` အဖြစ် ပါဝင်မည် (explorer တွင် "Legacy / Free" အတန်းအဖြစ် ပြသမည်)။
- အခမဲ့အဆင့်နှင့် subscription traffic များအတွက်လည်း _ခန့်မှန်း_ ကုန်ကျစရိတ် စုဆောင်းတွက်ချက်ဆဲဖြစ်သည် — ၎င်းသည်
  သင်ချွေတာနေသည့်ပမာဏဖြစ်ပြီး ပေးရန်ရှိသည့်ပမာဏ မဟုတ်ပါ။

## ကုန်ကျစရိတ်ကို ဘယ်လို ခန့်မှန်းထားလဲ။

### စျေးနှုန်းအရင်းအမြစ်

ကုန်ကျစရိတ်များသည် [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) ရှိ ပေါင်းစပ်စျေးနှုန်းဇယားမှ လာပါသည်၊ ဤနည်းအရ (** အမြင့်ဆုံး ပထမ** ):

1. **အသုံးပြုသူအပေါ် ထပ်လောင်းသည်။** — စျေးနှုန်းများသည် ဒက်ရှ်ဘုတ်တွင် သို့မဟုတ် `PATCH /api/pricing` ( `pricing` namespace) မှတဆင့် သတ်မှတ်ထားသည်။
2. **model.dev စင့်ခ်လုပ်ခြင်း။** — စျေးနှုန်းကို `https://models.dev/api.json` ( `models_dev_pricing` namespace) မှ ရယူခဲ့သည်။
3. **LiteLLM ထပ်တူကျသည်။** — စျေးနှုန်းများသည် LiteLLM၏ အများသူငှာ `model_prices_and_context_window.json` ( `pricing_synced` namespace) မှ ရယူခဲ့သည်။
4. **Hardcoded မူရင်းများ** — နှုန်းထားများသည် [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) တွင် တင်ပို့သည်။

တူညီသော provider/model အတွက်၊ ဦးစားပေးအလွှာများမှ တန်ဖိုးများသည် အောက်အလွှာများတွင် ကိုက်ညီသည့်အကွက်များကို ထပ်ရေးသည်။ အထက်အလွှာမှ ပျက်ကွက်သော အကွက်များသည် အောက်အလွှာမှ ထွက်လာနိုင်သေးသည်။ အမှီအခိုကင်းသော စင့်ခ်အလုပ်နှစ်ခုစလုံးကို တစ်ချိန်တည်းတွင် လုပ်ဆောင်နေချိန်တွင်ပင် အမှာစာအား ပြင်ဆင်ပေးသည်။ `GET /api/pricing?includeSources=1` `pricing` နှင့် `sourceMap` ပြန်ပေးသည်၊ မော်ဒယ်အလိုက် အညွှန်းများ (`user`, `modelsDev`, `litellm`, `default`) သည် ထိုမော်ဒယ်ပါဝင်သော ဦးစားပေးအလွှာကို ခွဲခြားသတ်မှတ်သည်။

**LiteLLM ထပ်တူကျသည်။** ရွေးချယ်မှုတွင်၊ ပုံမှန်အားဖြင့် ပိတ်ထားသည်။ ၎င်း၏ပတ်ဝန်းကျင်ပြောင်းလဲမှုများ ( [`.env.example`](../../.env.example) ကြည့်ပါ) မှာ-

| Env var                 | ပုံသေ     | ရည်ရွယ်ချက်                                                                  |
| ----------------------- | --------- | ---------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | နောက်ခံ LiteLLM စျေးနှုန်းစင့်ခ်လုပ်ခြင်းကို ဖွင့်ပါ။                        |
| `PRICING_SYNC_INTERVAL` | `86400`   | စက္ကန့်ပိုင်းအတွင်း (နေ့စဉ်) စင့်ခ်လုပ်ပါ။                                   |
| `PRICING_SYNC_SOURCES`  | `litellm` | ဤစင့်ခ်အတွက်သာ အရင်းအမြစ်ရွေးချယ်မှု။ လက်ရှိတွင် `litellm` သာ ပံ့ပိုးထားသည်။ |

**model.dev စင့်ခ်လုပ်ခြင်း။** LiteLLM စင့်ခ်လုပ်ခြင်းမှ သီးခြားဖြစ်ပြီး ပုံမှန်အားဖြင့်လည်း ပိတ်ထားသည်။ ၎င်းကို ဆက်တင်များ (models.dev စင့်ခ်လုပ်ခြင်း) တွင်ဖွင့်ပါ သို့မဟုတ် ဤပြောင်းလဲမှုများကို အသုံးပြုပါ-

| Env var                    | ပုံသေ            | ရည်ရွယ်ချက်                                                                                                                                 |
| -------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(မသတ်မှတ်ရသေး)_ | သတ်မှတ်မထားသည့် ဆက်တင်များပြောင်းရန် အောက်ပါအတိုင်း၊ `1/true/on/yes` ကိုဖွင့်ပြီး `0/false/off/no` ကိုပိတ်သည် (ဆက်တင်များဖွင့်ထားသော်လည်း)။ |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`          | ပုံသေ model.dev စင့်ခ်လုပ်ချိန်သည် စက္ကန့် (နေ့စဉ်) ဖြစ်သည်။                                                                                |

`PRICING_SYNC_SOURCES` လုပ်တယ်။** မဟုတ်ဘူး** model.dev ကိုဖွင့်ပါ; ၎င်းသည် LiteLLM sync ကိုသာထိန်းချုပ်သည်။ အသုံးပြုသူ အစားထိုးမှုတစ်ခုကို ဖျက်ခြင်းသည် စင့်ခ်လုပ်ထားသော namespace ကိုလည်း မရှင်းလင်းပါ။ နောက်ရနိုင်သောစျေးနှုန်းအလွှာသည် ထိရောက်မှုဖြစ်လာသည်။ ဈေးမတန်သော မော်ဒယ်အတွက်၊ လူကိုယ်တိုင် ထပ်ရေးခြင်း မထည့်မီ စင့်ခ်ဆက်တင်များနှင့် `sourceMap` နှစ်ခုလုံးကို စစ်ဆေးပါ။

### ကုန်ကျစရိတ်ပုံသေနည်း

တိုကင်အရေအတွက်များနှင့် [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`) ရှိ တစ်သန်း-တိုကင်နှုန်းများထံမှ တောင်းဆိုမှုတစ်ခုအတွက် ကုန်ကျစရိတ်ကို တွက်ချက်ပါသည်။

- **တိုကင်များ ထည့်သွင်းပါ။** (အနှုတ် ကက်ရှ်ဖတ်ခြင်းနှင့် ကက်ရှ်ဖန်တီးခြင်းတိုကင်များ) × `input` နှုန်း။
- **Cache-read tokens** × `cached` နှုန်း (ထည့်သွင်းမှုနှုန်း) သို့ ပြန်ကျသည်။
- **ကက်ရှ်-ဖန်တီးမှုတိုကင်များ** × `cache_creation` နှုန်း (ထည့်သွင်းမှုနှုန်း) သို့ ပြန်ကျသည်။
- **အထွက်တိုကင်များ** × `output` နှုန်း။
- **ကျိုးကြောင်းဆီလျော်မှုတိုကင်များ** × `reasoning` နှုန်း (အထွက်နှုန်းသို့ ပြန်ကျသည်)။

နှုန်းထားအားလုံးကို တိုကင် 1,000,000 လျှင် USD အဖြစ် အဓိပ္ပာယ်ဖွင့်ပါသည်။ Codex "fast"/"priority" သို့မဟုတ် "flex" ဝန်ဆောင်မှုအဆင့်သည် ကုန်ကျစရိတ်မြှောက်ကိန်း (`getCodexFastCostMultiplier`) — သက်ရောက်သည် ဥပမာ- flex အား 50% တိုကင်လျှော့စျေးဖြင့် ကောက်ခံသည်** flex ငွေစု** ဒက်ရှ်ဘုတ်တွင်။

မော်ဒယ်အမည်များကို ဦးစွာပုံမှန်ပြုလုပ်သည် ( `openai/` သို့မဟုတ် `accounts/fireworks/models/` ကဲ့သို့သော ဝန်ဆောင်မှုပေးသူလမ်းကြောင်းရှေ့ဆက်များကို ဖယ်ရှားထားသည်) ထို့ကြောင့် သမိုင်းဝင်အတန်းများသည် စျေးနှုန်းနှင့် ကိုက်ညီဆဲဖြစ်သည်။

### မည်မျှသုံးစွဲသည်ကို မှတ်တမ်းတင်ထားသည်။

- တောင်းဆိုချက်တစ်ခုချင်း ကုန်ကျစရိတ်ကို တောင်းဆိုမှုပြီးစီးချိန်တွင် တွက်ချက်ပါသည်။ မျှဝေထားသော ခွဲတမ်းသုံးစွဲမှုကို [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) မှတစ်ဆင့် နောက်လာမည့် event-loop tick တွင် စီစဉ်ထားပါသည်။
- API သော့သုံးငွေကို [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (မူလ 60s flush ကြားကာလ၊ 1,000- entry ကြားခံ) ဖြင့် အသုတ်လိုက်ခွဲပြီး API သော့အသုံးပြုမှုကို ဆီးသွားပါသည်။ မှတဆင့်ကြည့်ရှုနိုင်သည်-

  | Env var                             | ပုံသေ   | ရည်ရွယ်ချက်                                                 |
  | ----------------------------------- | ------- | ----------------------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | မီလီစက္ကန့်အတွင်း ရေဆွဲချခြင်းကြားကာလ။                      |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | မရှင်းထုတ်မီ Max သည် ထည့်သွင်းမှုများကို buffed လုပ်ထားသည်။ |

ကုန်ကျစရိတ်များသည် တိကျသောပံ့ပိုးပေးသူ-အစီရင်ခံထားသည့် အခကြေးငွေ (`provider_cost_usd`) ကို ပိုမိုနှစ်သက်ကြပြီး၊ ထို့နောက် ကတ်တလောက်စျေးဖြင့် တောင်းဆိုမှုလျှပ်တစ်ပြက် (`calculated_cost_usd`)၊ ထို့နောက် လက်ရှိကက်တလောက်မှ တိုကင်ကို ပြန်လည်သတ်မှတ်ခြင်း။ ၎င်းတို့၏ တိုကင်နံပါတ်များဖြင့် သိမ်းဆည်းထားသော ကုန်ကျစရိတ်များကို ထပ်မံကောက်ခံမည်မဟုတ်ပါ။ ၎င်းတို့၏ ကတ်တလောက်စျေးနှုန်း ပြောင်းလဲသည့်အခါ အမွေအနှစ် တိုကင်သီးသန့် အတန်းများသည် ပြောင်းလဲဆဲဖြစ်သည်။

### OCR နှင့် မြှပ်နှံမှုများ

- အောင်မြင်သော `/v1/ocr` တောင်းဆိုချက်များသည် တောင်းဆိုထားသော စာမျက်နှာအပိုင်းအခြား သို့မဟုတ် ပြန်ပေးထားသော စာမျက်နှာအရာဝတ္ထုများ၏ အရေအတွက်ကို မဟုတ်ဘဲ အထက်စီးကြောင်း `usage_info.pages_processed` အသုံးပြုသည်။ ခန့်မှန်းချက်မှာ စာမျက်နှာ × `ocr_cost_per_page` ( absolute USD/page၊** မဟုတ်ဘူး** USD/million)
- စာရွက်စာတမ်း သို့မဟုတ် ဘောင်ကွက်မှတ်စာများပါသော တောင်းဆိုချက်များသည် သီးခြား `ocr_cost_per_annotated_page` အကောက်ခွန်တစ်ခု လိုအပ်သည်။ အဲဒါမရှိရင် ကုန်ကျစရိတ်ကို မသိနိုင်ပါဘူး။ သာမန် OCR အကောက်ခွန်ကို တိတ်တဆိတ် အစားထိုး၍မရပါ။
- LiteLLM စင့်ခ်သည် ၎င်း၏အထက်ပိုင်း `annotation_cost_per_page` အကွက်ကို `ocr_cost_per_annotated_page` သို့ မြေပုံဆွဲသည်၊၊ အကြွင်းမဲ့ USD/page တန်ဖိုးနှင့် တိကျသေချာသော သုညအပါအဝင် မှတ်ချက်-သီးသန့်ထည့်သွင်းမှုများကို ဆက်လက်ထိန်းသိမ်းထားသည်။ ပံ့ပိုးပေးထားသော canonical field သည် ဦးစားပေးပါသည်။ မမှန်ကန်သော နံပတ်တန်ဖိုးများကို လျစ်လျူရှုထားသည်။ အသုံးပြုသူ၏ စျေးနှုန်းကို အစားထိုးမှုများသည် ၎င်းတို့၏ ပုံမှန်ဦးစားပေးကို ဆက်လက်ထိန်းသိမ်းထားသည်။ [LiteLLM၏ OCR စျေးနှုန်းသော့များကို](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) ကြည့်ပါ။
- OCR အသုံးပြုမှုသည် စာမျက်နှာအရေအတွက်၊ ယူနစ်စျေးနှုန်း၊ တွက်ချက်ထားသော USD ကုန်ကျစရိတ်၊ API သော့နှင့် ရွေးချယ်ထားသော ချိတ်ဆက်မှုကို သိမ်းဆည်းထားသည်။ စာမျက်နှာများကို တိုကင်များအဖြစ် ဘယ်တော့မှ ကိုယ်စားမပြုပါ။ ခေါ်ဆိုမှုမှတ်တမ်းများတွင် ငွေတောင်းခံခြင်းဆိုင်ရာ မက်တာဒေတာ၊ စာရွက်စာတမ်း URLs၊ PDF bytes သို့မဟုတ် ထုတ်ယူထားသော စာသားများ ပါဝင်သည်။
- အောင်မြင်သော `/v1/embeddings` သည် တူညီသော မီလီစက္ကန့်အတွင်း ပြီးစီးသည့် သီးခြားအစီအစဥ်များအပါအဝင် ရုပ်ပိုင်းဆိုင်ရာအသုတ်တစ်ခုလျှင် အသုံးပြုမှုအတန်းတစ်ခုအား မှတ်တမ်းတင်ပါသည်။ ဝန်ဆောင်မှုပေးသူ-အစီရင်ခံထားသော အခကြေးငွေများသည် တိုကင်ခန့်မှန်းချက်များထက် သာလွန်ပါသည်။ combo wrappers များသည် အခကြေးငွေ မထည့်ပါ။
- အသုံးပြုမှုမှတ်တမ်း၊ ကုန်ကျစရိတ်ခွဲခြမ်းစိတ်ဖြာချက်၊ provider/account ပြတင်းပေါက်များ၊ API သော့သုံးငွေကန့်သတ်ချက်များ၊ တောင်းဆိုချက်-ကုန်ကျစရိတ်စာရင်းဇယားနှင့် နေ့စဉ်အသုံးပြုမှုအကျဉ်းချုပ်များတွင် ဤအခကြေးငွေများပါဝင်သည်။ No-log သော့များသည် ရင်းမြစ်စာသားကို မထိန်းသိမ်းဘဲ ကိန်းဂဏန်းစာရင်းအင်းကို ထိန်းသိမ်းထားသည်။
- အသုံးပြုမှု သို့မဟုတ် အကောက်ခွန်များ လွဲမှားခြင်းများ** မသိ** အခမဲ့မဟုတ်ပါ- တုံ့ပြန်မှုကုန်ကျစရိတ် ခေါင်းစီးကို ချန်လှပ်ထားပြီး လက်ရှိအသုံးပြုမှု မူဝါဒသည် အကန့်အသတ်ရှိသော API သော့များနှင့် သက်ဆိုင်ပါသည်။ သုညနှုန်းထားများကို အတိအလင်းသတ်မှတ်ထားသော အကျုံးဝင်သော ကုန်ကျစရိတ် သုညအသုံးပြုမှု ဆက်လက်ရှိနေပါသည်။

ဤသည်မှာ ရှေ့သို့သာ စာရင်းကိုင်ခြင်း ဖြစ်သည်။ အသုံးပြုမှုမှတ်တမ်းကို တစ်ခါမှမရေးခဲ့ဖူးသော OCR/embedding ခေါ်ဆိုမှုဟောင်းများကို ဤရွှေ့ပြောင်းခြင်းမှ ပြန်လည်တည်ဆောက်၍မရပါ။ ကတ်တလောက် ခန့်မှန်းချက်များသည် USD ခန့်မှန်းချက်ဖြစ်ပြီး ပြေစာတစ်ခုမဟုတ်ဘဲ၊ ငွေကြေးပြောင်းလဲခြင်း၊ အခွန် သို့မဟုတ် လျှော့စျေးများ မပါဝင်ပါ။

### အပြောအဆိုနှင့်ပုံရိပ်များ

- အောင်မြင်သော `/v1/audio/transcriptions`၊ `/v1/audio/speech` နှင့် ပုံ-မျိုးဆက် ကြိုးပမ်းမှုများသည် ကိန်းဂဏာန်းစာရင်းအင်းများကို မျှဝေပါသည်။ တိုက်ရိုက်နှင့် ပေါင်းစပ်ခေါ်ဆိုမှုများသည် ခေါ်ဆိုသူ၏ API သော့နှင့် ရွေးချယ်ထားသော ချိတ်ဆက်မှုကို သယ်ဆောင်သည်။ combo wrapper သည် ဒုတိယဒက်ဘစ်ကို ဘယ်သောအခါမှ မထည့်ပါ။
- ဝန်ဆောင်မှုပေးသူမှ အစီရင်ခံထားသော USD တိကျပြတ်သားသော အခကြေးငွေ လုံးဝမပါဘဲ ကတ်တလောက် ခန့်မှန်းချက်ထက် အနိုင်ရသည်။ OpenRouter၏ JSON `usage.cost` `cost_usd` သို့ ပုံမှန်ဖြစ်အောင် ပြုလုပ်သည်။ မဟုတ်ပါက၊ တိုင်းတာထားသောတိုကင်များသည် တိုကင်စျေးနှုန်းများ၊ စာသားမှတ်တမ်းစက္ကန့်များကိုအသုံးပြုသည်၊ တစ်စက္ကန့်လျှင်စျေးနှုန်းများကိုအသုံးပြုသည်၊ စကားပြောထည့်သွင်းမှုသည် ယူနီကုဒ်အက္ခရာအရေအတွက်များကိုအသုံးပြုသည်၊ စျေးနှုန်းပြားသောပုံများသည် တောင်းဆိုထားသည့် `n` မဟုတ်ဘဲ အမှန်တကယ်ပြန်ပေးသည့်နံပါတ်ကို အသုံးပြုသည်။
- Binary OpenRouter TTS တွင် JSON အသုံးပြုမှုကိုယ်ထည် မရှိပါ။ အသံပြီးသွားသည် သို့မဟုတ် ခေါ်ဆိုသူက ပယ်ဖျက်ပြီးနောက်၊ OmniRoute ၎င်း၏မျိုးဆက် ID အဆိုပါနေရာတွင် မေးမြန်းသည်။** အတူတူပါပဲ။** OpenRouter ဇာစ်မြစ်ကို ပြင်ဆင်ထားသည်။ EU တောင်းဆိုချက်သည် ကမ္ဘာလုံးဆိုင်ရာ မူလအစသို့ ဘယ်တော့မှ ပြန်မရောက်ပါ။ ၎င်းသည် အကန့်အသတ်ရှိသော၊ ဖတ်ရန်သာရှာဖွေမှုတစ်ခုဖြစ်သည်။ ပေါင်းစပ်မှုကို စာရင်းကိုင်အတွက် ထပ်၍မစမ်းပါ။ အော်ဒီယိုပြီးဆုံးပြီးနောက် ငွေတောင်းခံခြင်းမှတ်တမ်းများ ပေါ်လာနိုင်သည်- ကွန်ရက်နောက်ဆုံးရက်များအပါအဝင် 52 စက္ကန့်ခန့်အထိ နောက်ခံတွင် ပြန်လည်ရှာဖွေမှု လုပ်ဆောင်သည်။
- ၎င်းရှာဖွေနေစဉ်အတွင်း၊ အသံတုံ့ပြန်မှုတွင် `X-OmniRoute-Cost-Status: pending` ပါရှိပြီး တုံ့ပြန်မှုကုန်ကျစရိတ် ခေါင်းစီးမရှိပါ။ ၎င်း၏နောက်ဆုံးအခကြေးငွေကို အသုံးပြုမှုမှတ်တမ်း၊ ခွဲခြမ်းစိတ်ဖြာချက်များနှင့် ပြန်လည်ပေါင်းစည်းပြီးနောက် သော့လယ်ဂျာတွင် ပေါ်လာပါသည်။ မက်တာဒေတာကို မရရှိနိုင်ပါက၊ စီစဉ်သတ်မှတ်ထားသော အကောက်ခွန်လျှပ်တစ်ပြက်ဓာတ်ပုံကို အသုံးပြုသည်။ မဟုတ်ရင် ကုန်ကျစရိတ် မသိနိုင်ပါဘူး။
- စက္ကန့်များ၊ စာလုံးများနှင့် ရုပ်ပုံအရေအတွက်များသည် သီးခြားငွေပေးချေယူနစ်အကွက်များ ရှိသည်၊ မည်သည့်အခါမျှ တိုကင်နံပါတ်များ အတုမရှိပါ။ စာရင်းကိုင်ခြင်းတွင် စကားပြောစာသား၊ စာသားမှတ်တမ်း သို့မဟုတ် ပုံဘိုက်များမဟုတ်ဘဲ ဂဏန်းအသုံးပြုမှုကိုသာ ထိန်းသိမ်းထားသည်။ လက်ရှိတန်ဖိုးမဖြတ်နိုင်သော ရုပ်ပုံကင်းလွတ်ခွင့်များသည် ပြောင်းလဲခြင်းမရှိပါ- စစ်မှန်သောပျောက်ဆုံးနေသော ရုပ်ပုံအခွန်အခသည် ကန့်သတ်သော့အသစ်ကို အသစ်သော့ခတ်ထားခြင်းမဟုတ်ပါ၊ တုံ့ပြန်မှုသည် ခေါ်ဆိုခအခမဲ့ဖြစ်ကြောင်းကြေညာမည့်အစား ကုန်ကျစရိတ်ခေါင်းစီးကို ချန်လှပ်ထားသည်။ စျေးနှုန်းစတိုးဆိုင်တွင် ကျရှုံးမှုတစ်ခုသည် ပျက်ကွက်ပိတ်သိမ်းခြင်းအတွက် အသုံးပြုမှုအထောက်အထားများကို ဆက်လက်ထိန်းသိမ်းထားဆဲဖြစ်သည်။

သမိုင်းဝင် speech/image အခကြေးငွေကို တီထွင်ထားခြင်း သို့မဟုတ် ဖြည့်စွက်ထားခြင်းမရှိပါ။ ဝန်ဆောင်မှုပေးသူထံမှ ငွေတောင်းခံခြင်းသည် ငွေတောင်းခံလွှာများအတွက် ရည်ညွှန်းချက်အဖြစ် ကျန်ရှိနေသည်

## Dashboard: ကုန်ကျစရိတ် စာမျက်နှာ

**ကုန်ကျစရိတ်** စာမျက်နှာသည် `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`) တွင် ရှိသည်။
၎င်း၏ အဓိကမြင်ကွင်းမှာ **ကုန်ကျစရိတ် အနှစ်ချုပ်** တက်ဘ်
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`) ဖြစ်ပြီး
`GET /api/usage/analytics` မှ အချက်အလက်အားလုံးကို ရယူသည်။

၎င်းတွင် ပြသသည့်အရာများ-

- **အသုံးစရိတ် အကွက်များ** — _ယနေ့ (1d)_, _7d_, _30d_ နှင့် ရွေးချယ်ထားသော
  ကာလအတွက် ခန့်မှန်းအသုံးစရိတ်။ ကာလရွေးချယ်မှု- `7d`, `30d`, `90d`, `all`။
- **အဓိက မက်ထရစ်များ** — ကာလအတွင်း တောင်းဆိုမှုများ၊ လက်ရှိအသုံးပြုနေသော provider များ၊ လက်ရှိအသုံးပြုနေသော model များနှင့် တောင်းဆိုမှုတစ်ခုလျှင် ပျမ်းမျှ
  ကုန်ကျစရိတ်။
- **ကုန်ကျစရိတ် လေ့လာစိစစ်ကိရိယာ** — **provider**, **model**,
  **API key**, **account** သို့မဟုတ် **service tier** အလိုက် အုပ်စုဖွဲ့ထားပြီး စီစဉ်နိုင်/စစ်ထုတ်နိုင်သော ဇယားတစ်ခုဖြစ်ကာ ကုန်ကျစရိတ်၊ တောင်းဆိုမှုများ၊ token များ၊ တောင်းဆိုမှုတစ်ခုလျှင် ပျမ်းမျှ
  ကုန်ကျစရိတ်နှင့် စုစုပေါင်း၏ ရာခိုင်နှုန်းဝေစုတို့ ပါဝင်သည်။
- **Token အသုံးပြုမှု** — စုစုပေါင်း / input / output token များနှင့် input:output အချိုး။
- **လမ်းကြောင်းခွဲဝေမှု ထိရောက်မှု** — fallback အရေအတွက်၊ fallback နှုန်းနှင့် တောင်းဆိုထားသော model လွှမ်းခြုံမှု။
- **လစဉ် ခန့်မှန်းချက်** — မကြာသေးမီ နေ့စဉ်ပျမ်းမျှကို အခြေခံ၍ လကုန်အသုံးစရိတ်ကို ခန့်မှန်းသည်။
- **ကာလ နှိုင်းယှဉ်ချက်** — ကာလ၏ ပထမတစ်ဝက်နှင့် ဒုတိယတစ်ဝက်အကြား ပြောင်းလဲမှု ရာခိုင်နှုန်း။
- **ဇယားကွက်များ** — နေ့စဉ်ကုန်ကျစရိတ် လမ်းကြောင်း၊ provider ဝေစု (စက်ဝိုင်းပုံ)၊ ထိပ်တန်း provider များ၊ ထိပ်တန်း model များ၊ API key အလိုက် ကုန်ကျစရိတ်၊ account အလိုက် ကုန်ကျစရိတ်၊ အပတ်စဉ် အသုံးပြုမှုပုံစံနှင့် လုပ်ဆောင်မှု heatmap။
- **ထုတ်ယူခြင်း** — လက်ရှိကာလကို **CSV** သို့မဟုတ် **JSON** အဖြစ် ဒေါင်းလုဒ်လုပ်နိုင်သည် (သုညမဟုတ်သော ကုန်ကျစရိတ်ဒေတာ ရှိလာသည့်အခါ
  ခလုတ်များ ပေါ်လာသည်)။

စျေးနှုန်းသတ်မှတ်ထားသော traffic မရှိသည့်အခါ အတန်းများတွင် `$0` အစား "အဟောင်း / အခမဲ့" အညွှန်းကို ပြသပြီး
ကုန်ကျစရိတ်သက်သာမှု ခြေရာခံသည့် model ကို ထင်ဟပ်စေသည်။

### ဆက်စပ် ကုန်ကျစရိတ် စာမျက်နှာခွဲများ

ကုန်ကျစရိတ် ဧရိယာတွင် (`/dashboard/costs/` အောက်၌) အောက်ပါတို့လည်း ပါဝင်သည်-

- **စျေးနှုန်းသတ်မှတ်ခြင်း** (`/dashboard/costs/pricing`) — model တစ်ခုချင်းစီ၏ စျေးနှုန်းများကို ကြည့်ရှုပြီး အစားထိုးသတ်မှတ်နိုင်သည် (မျှဝေထားသော Pricing တက်ဘ်ကို
  ပြသသည်)။
- **ဘတ်ဂျက်** (`/dashboard/costs/budget`) — scope တစ်ခုချင်းစီအလိုက် အသုံးစရိတ်ကန့်သတ်ချက်များ သတ်မှတ်နိုင်သည် (မျှဝေထားသော
  Budget တက်ဘ်ကို ပြသသည်)။
- **Quota မျှဝေမှု** (`/dashboard/costs/quota-share`) — မျှဝေထားသော quota pool များနှင့် သုံးစွဲနှုန်း
  မြင်ကွင်းများ။

## CLI

OmniRoute ၏ CLI တွင် ကုန်ကျစရိတ်၊ အသုံးပြုမှုနှင့် ဈေးနှုန်းဆိုင်ရာ command များကို အသုံးပြုနိုင်သည် ([`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) တွင် စာရင်းသွင်းထားသည်)။

### `omniroute cost`

`/api/usage/analytics` မှ စုစည်းထားသော ကုန်ကျစရိတ်အစီရင်ခံစာ။

```bash
omniroute cost                          # နောက်ဆုံး 30 ရက်၊ provider အလိုက် အုပ်စုဖွဲ့ထားသည်
omniroute cost --period 7d              # နောက်ဆုံး 7 ရက်
omniroute cost --group-by model         # provider | model | combo | api-key | day အလိုက် အုပ်စုဖွဲ့ရန်
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ကော်လံများ- အုပ်စု၊ request အရေအတွက်၊ အဝင်/အထွက် token များ၊ ကုန်ကျစရိတ် (USD) နှင့် စုစုပေါင်း၏ ရာခိုင်နှုန်း။ နောက်ဆုံးတွင် စုစုပေါင်းစာကြောင်းကို ဖော်ပြသည် (`--quiet` သို့မဟုတ် `--output json` ဖြင့် ပိတ်ထားနိုင်သည်)။

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # provider တစ်ခုချင်းစီအလိုက် ကုန်ကျစရိတ်အကျဉ်းချုပ်
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ဘတ်ဂျက်များ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` သည် `GET /api/pricing/defaults` ကို ဖတ်ရှုသည်။ Model တစ်ခုချင်းစီ၏
> ဈေးနှုန်းများကို ပြင်ဆင်လိုပါက **Pricing** dashboard စာမျက်နှာ သို့မဟုတ် `PATCH /api/pricing` ကို အသုံးပြုပါ။

## ပြဿနာဖြေရှင်းခြင်း

- **ကုန်ကျစရိတ်အားလုံးတွင် $0 / "Legacy / Free" ဟု ဖော်ပြနေသည်။** အသုံးပြုနေသော model များအတွက် ဈေးနှုန်းထည့်သွင်းချက် မရှိပါ။
  ပြင်ပ sync ကို ဖွင့်ရန် (`PRICING_SYNC_ENABLED=true`) သတ်မှတ်ပြီး `omniroute pricing sync` ကို လုပ်ဆောင်ပါ၊ သို့မဟုတ်
  Pricing စာမျက်နှာ / `PATCH /api/pricing` မှတစ်ဆင့် ဈေးနှုန်းများကို ကိုယ်တိုင် သတ်မှတ်ပါ။
- **ယခင်က အသုံးပြုခဲ့သော model တစ်ခု၏ ဈေးနှုန်း မှားယွင်းနေသည်။** ဈေးနှုန်းကို ပြင်ဆင်ပါ (override လုပ်ခြင်း သို့မဟုတ် ပြန်လည် sync လုပ်ခြင်း) — analytics ကို ဖတ်ရှုသည့်အခါတိုင်း token အရေအတွက်များမှ ကုန်ကျစရိတ်ကို ပြန်လည်တွက်ချက်သောကြောင့် ခန့်မှန်းချက်များကို နောက်ကြောင်းပြန် အပ်ဒိတ်လုပ်ပေးသည်။
- **သုံးစွဲငွေပမာဏသည် အချိန်နှင့်တစ်ပြေးညီ မဖြစ်ဘဲ နောက်ကျနေသည်။** Key တစ်ခုချင်းစီ၏ သုံးစွဲငွေကို အစုလိုက် လုပ်ဆောင်သည်၊ ပိုမိုလတ်ဆတ်သော ကိန်းဂဏန်းများ လိုအပ်ပါက
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ကို လျှော့ချပါ။
