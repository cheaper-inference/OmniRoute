## ၎င်းသည် ဘာလဲ (နှင့် ဘာမဟုတ်သလဲ)

OmniRoute သည် token အရေအတွက်ကို model တစ်ခု၏ ဈေးနှုန်းနှုန်းထားများဖြင့် မြှောက်ခြင်းအားဖြင့်
ပြီးမြောက်သည့် တောင်းဆိုမှုတိုင်းအတွက် USD ကုန်ကျစရိတ်ကို သတ်မှတ်ပေးသည်။ ဤကိန်းဂဏန်းများကို **ကုန်ကျစရိတ်များ** dashboard၊
`omniroute cost` / `omniroute usage` CLI၊ CSV/JSON export များနှင့် API key တစ်ခုချင်းစီအလိုက် budget များတွင် အသုံးပြုသည်။

> **Dashboard ပေါ်ရှိ "ကုန်ကျစရိတ်" သည် ငွေတောင်းခံလွှာမဟုတ်ဘဲ ချွေတာမှု ခြေရာခံစနစ်တစ်ခု ဖြစ်သည်။** OmniRoute က သင့်ထံမှ မည်သည့်အခါမျှ ငွေကောက်ခံခြင်းမရှိပါ
> — ၎င်းသည် သင်ချိတ်ဆက်ထားပြီးဖြစ်သည့် provider များ (သင့်ကိုယ်ပိုင်
> subscription များ၊ အခမဲ့အဆင့်များနှင့် API key များ) ထံသို့ သင့်တောင်းဆိုမှုများကို လမ်းကြောင်းခွဲပေးခြင်းသာ ဖြစ်သည်။ အခမဲ့
> model များပေါ်တွင်သာ စုဆောင်းရရှိထားသည့် "$290 total cost" သည် အကြမ်းဖျင်းအားဖြင့် အခပေး API တစ်ခုအတွက်
> **သင် _မပေးခဲ့ရသည့်_ $290** ကို ဆိုလိုသည်။ ဤကိန်းဂဏန်းသည် တူညီသော traffic ကို ပုံမှန်ကြေညာထားသော ဈေးနှုန်းများဖြင့် အသုံးပြုခဲ့ပါက
> ကုန်ကျမည့်ပမာဏ၏ _ခန့်မှန်းချက်_ ဖြစ်သဖြင့် သင့်အသုံးပြုမှုသည် မည်သည့်နေရာတွင် အများဆုံး စုဝေးနေကြောင်းနှင့်
> ပိုမိုဈေးသက်သာသော/အခမဲ့ provider များထံ လမ်းကြောင်းခွဲပေးခြင်းကြောင့် မည်မျှ ချွေတာနိုင်ကြောင်း မြင်တွေ့နိုင်သည်။

ဤအဓိပ္ပာယ်သတ်မှတ်ချက်ကို project [README](../../README.md) တွင်လည်း တိုက်ရိုက်ဖော်ပြထားသည် ("dashboard ပေါ်ရှိ
'ကုန်ကျစရိတ်' သည် ငွေတောင်းခံလွှာမဟုတ်ဘဲ ချွေတာမှု ခြေရာခံစနစ်တစ်ခု ဖြစ်သည်")။

ဤကိန်းဂဏန်းသည် ခန့်မှန်းချက်တစ်ခု ဖြစ်သောကြောင့်-

- ၎င်းသည် model တစ်ခုချင်းစီအတွက် OmniRoute တွင်ရှိသော ဈေးနှုန်းဇယားပေါ် မူတည်သည်။ ဈေးနှုန်း
  ထည့်သွင်းထားခြင်းမရှိသည့် model သည် ကုန်ကျစရိတ် `0` အဖြစ် ပါဝင်မည် (explorer တွင် "Legacy / Free" အတန်းအဖြစ် ပြသမည်)။
- အခမဲ့အဆင့်နှင့် subscription traffic များအတွက်လည်း _ခန့်မှန်း_ ကုန်ကျစရိတ် စုဆောင်းတွက်ချက်ဆဲဖြစ်သည် — ၎င်းသည်
  သင်ချွေတာနေသည့်ပမာဏဖြစ်ပြီး ပေးရန်ရှိသည့်ပမာဏ မဟုတ်ပါ။

## ကုန်ကျစရိတ်ကို ဘယ်လို ခန့်မှန်းထားလဲ။

### စျေးနှုန်းအရင်းအမြစ်

ကုန်ကျစရိတ်များသည် [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) ရှိ ပေါင်းစပ်စျေးနှုန်းဇယားမှ လာပါသည်၊ ဤနည်းအရ (**အမြင့်ဆုံး ပထမ** ):

1. **အသုံးပြုသူအပေါ် ထပ်လောင်းသည်။** — စျေးနှုန်းများသည် ဒက်ရှ်ဘုတ်တွင် သို့မဟုတ် `PATCH /api/pricing` ( `pricing` အမည်နေရာ) မှတဆင့် သတ်မှတ်ထားသည်။
2. **model.dev စင့်ခ်လုပ်ခြင်း။** — စျေးနှုန်းကို `https://models.dev/api.json` ( `models_dev_pricing` namespace) မှ ရယူခဲ့သည်။
3. **LiteLLM စင့်ခ်လုပ်ခြင်း။** — စျေးနှုန်းများသည် LiteLLM၏ အများသူငှာ `model_prices_and_context_window.json` ( `pricing_synced` namespace ) မှ ရယူခဲ့သည်။
4. **Hardcoded မူရင်းများ** — နှုန်းထားများကို [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) တွင် တင်ပို့သည်။

တူညီသော provider/model အတွက်၊ ဦးစားပေးအလွှာများမှ တန်ဖိုးများသည် အောက်အလွှာများတွင် ကိုက်ညီသည့်အကွက်များကို ထပ်ရေးသည်။ အထက်အလွှာမှ ပျက်ကွက်သော အကွက်များသည် အောက်အလွှာမှ ထွက်လာနိုင်သေးသည်။ အမှီအခိုကင်းသော စင့်ခ်အလုပ်နှစ်ခုစလုံးကို တစ်ချိန်တည်းတွင် လုပ်ဆောင်နေချိန်တွင်ပင် အမှာစာအား ပြင်ဆင်ထားသည်။ `GET /api/pricing?includeSources=1` မော်ဒယ်အလိုက် အညွှန်းများ (`user`၊ `modelsDev`၊ `litellm`၊ `default`) မှ ထိုမော်ဒယ်ပါဝင်သော ဦးစားပေးအလွှာကို ခွဲခြားသတ်မှတ်ပေးသည့် `pricing` နှင့် `sourceMap` ကို ပြန်ပေးသည်။

**LiteLLM စင့်ခ်လုပ်ခြင်း။** ရွေးချယ်မှုတွင်၊ ပုံမှန်အားဖြင့် ပိတ်ထားသည်။ ၎င်း၏ပတ်ဝန်းကျင်ပြောင်းလဲမှုများ ( [`.env.example`](../../.env.example) ကြည့်ပါ) မှာ-

| Env var                 | ပုံသေ     | ရည်ရွယ်ချက်                                                                  |
| ----------------------- | --------- | ---------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | နောက်ခံ LiteLLM စျေးနှုန်းစင့်ခ်လုပ်ခြင်းကို ဖွင့်ပါ။                        |
| `PRICING_SYNC_INTERVAL` | `86400`   | ကြားကာလကို စက္ကန့် (နေ့စဉ်) ဖြင့် စင့်ခ်လုပ်ပါ။                              |
| `PRICING_SYNC_SOURCES`  | `litellm` | ဤစင့်ခ်အတွက်သာ အရင်းအမြစ်ရွေးချယ်မှု။ လက်ရှိတွင် `litellm` သာ ပံ့ပိုးထားသည်။ |

**model.dev စင့်ခ်လုပ်ခြင်း။** LiteLLM စင့်ခ်လုပ်ခြင်းမှ သီးခြားဖြစ်ပြီး ပုံမှန်အားဖြင့်လည်း ပိတ်ထားသည်။ ၎င်းကို ဆက်တင်များ (models.dev စင့်ခ်လုပ်ခြင်း) တွင်ဖွင့်ပါ သို့မဟုတ် ဤပြောင်းလဲမှုများကို အသုံးပြုပါ-

| Env var                    | ပုံသေ            | ရည်ရွယ်ချက်                                                                                                                                   |
| -------------------------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(မသတ်မှတ်ရသေး)_ | သတ်မှတ်မထားသည့် ဆက်တင်များပြောင်းရန် အောက်ပါအတိုင်း၊ `1/true/on/yes` ကို ဖွင့်ထားပြီး `0/false/off/no` ပိတ်သည် (ဆက်တင်များ ဖွင့်ထားသော်လည်း)။ |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`          | ပုံသေ model.dev စင့်ခ်လုပ်ချိန်သည် စက္ကန့် (နေ့စဉ်) ဖြစ်သည်။                                                                                  |

`PRICING_SYNC_SOURCES` ပြောတာပါ။**မဟုတ်ဘူး** model.dev ကိုဖွင့်ပါ; ၎င်းသည် LiteLLM ထပ်တူပြုမှုကိုသာ ထိန်းချုပ်သည်။ အသုံးပြုသူ အစားထိုးမှုတစ်ခုကို ဖျက်ခြင်းသည် စင့်ခ်လုပ်ထားသော namespace ကိုလည်း မရှင်းလင်းပါ။ နောက်ရနိုင်သောစျေးနှုန်းအလွှာသည် ထိရောက်မှုဖြစ်လာသည်။ စျေးမတန်သော မော်ဒယ်အတွက်၊ လူကိုယ်တိုင်ရေးခြင်းကို မထည့်မီ စင့်ခ်ဆက်တင်များနှင့် `sourceMap` နှစ်ခုလုံးကို စစ်ဆေးပါ။

### ကုန်ကျစရိတ်ပုံသေနည်း

[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`) တွင် တိုကင်အရေအတွက်နှင့် တစ်သန်း-တိုကင်နှုန်းများထံမှ တောင်းဆိုမှုတစ်ခုအတွက် ကုန်ကျစရိတ်ကို တွက်ချက်ပါသည်။

- **တိုကင်များ ထည့်သွင်းပါ။** (အနှုတ် ကက်ရှ်ဖတ်ခြင်းနှင့် ကက်ရှ်ဖန်တီးခြင်းတိုကင်များ) × `input` နှုန်း။
- **Cache-read tokens** × `cached` နှုန်း (ထည့်သွင်းမှုနှုန်းသို့ ပြန်ကျသည်)။
- **ကက်ရှ်-ဖန်တီးမှုတိုကင်များ** × `cache_creation` နှုန်း (ထည့်သွင်းမှုနှုန်းသို့ ပြန်ကျသည်)။
- **အထွက်တိုကင်များ** × `output` နှုန်း။
- **ကျိုးကြောင်းဆီလျော်မှုတိုကင်များ** × `reasoning` နှုန်း (အထွက်နှုန်းသို့ ပြန်ကျသည်)။

နှုန်းထားအားလုံးကို တိုကင် 1,000,000 လျှင် USD ဟု အဓိပ္ပာယ်ဖွင့်သည်။ Codex "အမြန်"/"ဦးစားပေး" သို့မဟုတ် "flex" ဝန်ဆောင်မှုအဆင့်သည် ကုန်ကျစရိတ်မြှောက်ကိန်း (`getCodexFastCostMultiplier`) — ဥပမာ- flex အား 50% တိုကင်လျှော့စျေးဖြင့် ဘီလ်ဆောင်သည်**flex ငွေစု** ဒက်ရှ်ဘုတ်တွင်။

မော်ဒယ်အမည်များကို ပထမဦးစွာ ပုံမှန်ပုံစံပြုလုပ်ထားသည် ( `openai/` သို့မဟုတ် `accounts/fireworks/models/` ကဲ့သို့သော ဝန်ဆောင်မှုပေးသူလမ်းကြောင်းရှေ့ဆက်များကို ဖယ်ရှားထားသည်) ထို့ကြောင့် သမိုင်းဝင်အတန်းများသည် စျေးနှုန်းနှင့် တူညီနေသေးသည်။

### မည်မျှသုံးစွဲသည်ကို မှတ်တမ်းတင်ထားသည်။

- တောင်းဆိုချက်တစ်ခုချင်း ကုန်ကျစရိတ်ကို တောင်းဆိုမှုပြီးစီးချိန်တွင် တွက်ချက်ပါသည်။ မျှဝေထားသော ခွဲတမ်းသုံးစွဲမှုကို [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) မှတစ်ဆင့် နောက်လာမည့် event-loop tick တွင် စီစဉ်ထားပါသည်။
- API သော့သုံးငွေကို [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (မူလ 60s flush ကြားကာလ၊ 1,000- entry ကြားခံ) ဖြင့် အတွဲလိုက်ခွဲပြီး API သော့သုံးစွဲမှုကို ဖယ်ထုတ်ထားသည်။ မှတဆင့်ကြည့်ရှုနိုင်သည်-

  | Env var                             | ပုံသေ   | ရည်ရွယ်ချက်                                                 |
  | ----------------------------------- | ------- | ----------------------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | မီလီစက္ကန့်အတွင်း ရေဆွဲချခြင်းကြားကာလ။                      |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | မရှင်းထုတ်မီ Max သည် ထည့်သွင်းမှုများကို buffed လုပ်ထားသည်။ |

ကုန်ကျစရိတ်များသည် ဝန်ဆောင်မှုပေးသူ-အစီရင်ခံထားသည့် ကုန်ကျစရိတ်အတိအကျ (`provider_cost_usd`)၊ ထို့နောက် ကတ်တလောက်စျေးနှုန်းတောင်းဆိုမှုလျှပ်တစ်ပြက် (`calculated_cost_usd`)၊ ထို့နောက် လက်ရှိကက်တလောက်မှ တိုကင်ပြန်လည်သတ်မှတ်ခြင်းကို ပိုနှစ်သက်သည်။ ၎င်းတို့၏ တိုကင်နံပါတ်များဖြင့် သိမ်းဆည်းထားသော ကုန်ကျစရိတ်များကို ထပ်မံကောက်ခံမည်မဟုတ်ပါ။ ၎င်းတို့၏ ကတ်တလောက်စျေးနှုန်း ပြောင်းလဲသည့်အခါ အမွေအနှစ် တိုကင်သီးသန့် အတန်းများသည် ပြောင်းလဲဆဲဖြစ်သည်။

### OCR နှင့် မြှပ်နှံမှုများ

- အောင်မြင်သော `/v1/ocr` တောင်းဆိုချက်များသည် အထက်စီးကြောင်း `usage_info.pages_processed` အသုံးပြုသည်၊ တောင်းဆိုထားသော စာမျက်နှာအပိုင်းအခြား သို့မဟုတ် ပြန်ပေးထားသော စာမျက်နှာအရာဝတ္ထုအရေအတွက်ကို မသုံးပါ။ ခန့်မှန်းချက်မှာ စာမျက်နှာ × `ocr_cost_per_page` (လုံးဝ USD/page၊**မဟုတ်ဘူး** USD/million)။
- စာရွက်စာတမ်း သို့မဟုတ် အကွက်မှတ်စာများပါသော တောင်းဆိုချက်များသည် သီးခြား `ocr_cost_per_annotated_page` အကောက်ခွန်တစ်ခု လိုအပ်သည်။ အဲဒါမရှိရင် ကုန်ကျစရိတ်ကို မသိနိုင်ပါဘူး။ သာမန် OCR အကောက်ခွန်ကို တိတ်တဆိတ် အစားထိုး၍မရပါ။
- LiteLLM စင့်ခ်လုပ်ခြင်းသည် ၎င်း၏အထက်ပိုင်း `annotation_cost_per_page` အကွက်ကို `ocr_cost_per_annotated_page` သို့ မြေပုံဆွဲသည်၊၊ အကြွင်းမဲ့ USD/page တန်ဖိုးနှင့် ရှင်းရှင်းလင်းလင်း သုညအပါအဝင် မှတ်ချက်-သီးသန့်ထည့်သွင်းမှုများကို ဆက်လက်ထိန်းသိမ်းထားသည်။ ပံ့ပိုးပေးထားသော canonical field သည် ဦးစားပေးပါသည်။ မမှန်ကန်သော နံပတ်တန်ဖိုးများကို လျစ်လျူရှုထားသည်။ အသုံးပြုသူ၏ စျေးနှုန်းကို အစားထိုးမှုများသည် ၎င်းတို့၏ ပုံမှန်ဦးစားပေးကို ဆက်လက်ထိန်းသိမ်းထားသည်။ [LiteLLM၏ OCR စျေးနှုန်းသော့များကို](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) ကြည့်ပါ။
- OCR အသုံးပြုမှုသည် စာမျက်နှာအရေအတွက်၊ ယူနစ်စျေးနှုန်း၊ တွက်ချက်ထားသော USD ကုန်ကျစရိတ်၊ API သော့နှင့် ရွေးချယ်ထားသော ချိတ်ဆက်မှုကို သိမ်းဆည်းထားသည်။ စာမျက်နှာများကို တိုကင်များအဖြစ် ဘယ်တော့မှ ကိုယ်စားမပြုပါ။ ခေါ်ဆိုမှုမှတ်တမ်းများတွင် URLs၊ PDF ဘိုက်များ သို့မဟုတ် ထုတ်ယူထားသော စာသားများကို စာရွက်စာတမ်းမပြဘဲ ငွေတောင်းခံခြင်းဆိုင်ရာ မက်တာဒေတာပါရှိသည်။
- အောင်မြင်သော `/v1/embeddings` သည် တူညီသောမီလီစက္ကန့်အတွင်း ပြီးစီးသည့် သီးခြားအစီအစဥ်များအပါအဝင် ရုပ်ပိုင်းဆိုင်ရာအသုတ်တစ်ခုလျှင် အသုံးပြုမှုအတန်းတစ်တန်းကို မှတ်တမ်းတင်ပါသည်။ ဝန်ဆောင်မှုပေးသူ-အစီရင်ခံထားသော အခကြေးငွေများသည် တိုကင်ခန့်မှန်းချက်များထက် သာလွန်ပါသည်။ combo wrappers များသည် အခကြေးငွေ မထည့်ပါ။
- အသုံးပြုမှုမှတ်တမ်း၊ ကုန်ကျစရိတ်ခွဲခြမ်းစိတ်ဖြာချက်၊ provider/account ပြတင်းပေါက်များ၊ API သော့အသုံးပြုမှုကန့်သတ်ချက်များ၊ တောင်းဆိုချက်-ကုန်ကျစရိတ်စာရင်းဇယားနှင့် နေ့စဥ်အသုံးပြုမှု စုစည်းမှုတွင် ဤအခကြေးငွေများ ပါဝင်သည်။ No-log သော့များသည် ရင်းမြစ်စာသားကို မထိန်းသိမ်းဘဲ ကိန်းဂဏန်းစာရင်းအင်းကို ထိန်းသိမ်းထားသည်။
- အသုံးပြုမှု သို့မဟုတ် အကောက်ခွန်များ လွဲမှားခြင်းများ**မသိ** အခမဲ့မဟုတ်ပါ- တုံ့ပြန်မှုကုန်ကျစရိတ် ခေါင်းစီးကို ချန်လှပ်ထားပြီး လက်ရှိအသုံးပြုမှု မူဝါဒသည် အကန့်အသတ်ရှိသော API သော့များနှင့် သက်ဆိုင်ပါသည်။ သုညနှုန်းထားများကို အတိအလင်းသတ်မှတ်ထားသော အကျုံးဝင်သော ကုန်ကျစရိတ် သုညအသုံးပြုမှု ဆက်လက်ရှိနေပါသည်။

ဤသည်မှာ ရှေ့သို့သာ စာရင်းကိုင်ခြင်း ဖြစ်သည်။ အသုံးပြုမှုမှတ်တမ်းကို တစ်ခါမှမရေးခဲ့ဖူးသော OCR/embedding ခေါ်ဆိုမှုဟောင်းများကို ဤရွှေ့ပြောင်းခြင်းမှ ပြန်လည်တည်ဆောက်၍မရပါ။ ကတ်တလောက် ခန့်မှန်းချက်များသည် USD ခန့်မှန်းချက်များဖြစ်သည်၊ ပြေစာတစ်ခုမဟုတ်ဘဲ၊ ငွေကြေးပြောင်းလဲခြင်း၊ အခွန် သို့မဟုတ် လျှော့စျေးများ မပါဝင်ပါ။

  ကုန်ကျစရိတ်။
- **ကုန်ကျစရိတ် လေ့လာစိစစ်ကိရိယာ** — **provider**, **model**,
  **API key**, **account** သို့မဟုတ် **service tier** အလိုက် အုပ်စုဖွဲ့ထားပြီး စီစဉ်နိုင်/စစ်ထုတ်နိုင်သော ဇယားတစ်ခုဖြစ်ကာ ကုန်ကျစရိတ်၊ တောင်းဆိုမှုများ၊ token များ၊ တောင်းဆိုမှုတစ်ခုလျှင် ပျမ်းမျှ
  ကုန်ကျစရိတ်နှင့် စုစုပေါင်း၏ ရာခိုင်နှုန်းဝေစုတို့ ပါဝင်သည်။
- **Token အသုံးပြုမှု** — စုစုပေါင်း / input / output token များနှင့် input:output အချိုး။
- **လမ်းကြောင်းခွဲဝေမှု ထိရောက်မှု** — fallback အရေအတွက်၊ fallback နှုန်းနှင့် တောင်းဆိုထားသော model လွှမ်းခြုံမှု။
- **လစဉ် ခန့်မှန်းချက်** — မကြာသေးမီ နေ့စဉ်ပျမ်းမျှကို အခြေခံ၍ လကုန်အသုံးစရိတ်ကို ခန့်မှန်းသည်။
- **ကာလ နှိုင်းယှဉ်ချက်** — ကာလ၏ ပထမတစ်ဝက်နှင့် ဒုတိယတစ်ဝက်အကြား ပြောင်းလဲမှု ရာခိုင်နှုန်း။
- **ဇယားကွက်များ** — နေ့စဉ်ကုန်ကျစရိတ် လမ်းကြောင်း၊ provider ဝေစု (စက်ဝိုင်းပုံ)၊ ထိပ်တန်း provider များ၊ ထိပ်တန်း model များ၊ API key အလိုက် ကုန်ကျစရိတ်၊ account အလိုက် ကုန်ကျစရိတ်၊ အပတ်စဉ် အသုံးပြုမှုပုံစံနှင့် လုပ်ဆောင်မှု heatmap။
- **ထုတ်ယူခြင်း** — လက်ရှိကာလကို **CSV** သို့မဟုတ် **JSON** အဖြစ် ဒေါင်းလုဒ်လုပ်နိုင်သည် (သုညမဟုတ်သော ကုန်ကျစရိတ်ဒေတာ ရှိလာသည့်အခါ
  ခလုတ်များ ပေါ်လာသည်)။

စျေးနှုန်းသတ်မှတ်ထားသော traffic မရှိသည့်အခါ အတန်းများတွင် `$0` အစား "အဟောင်း / အခမဲ့" အညွှန်းကို ပြသပြီး
ကုန်ကျစရိတ်သက်သာမှု ခြေရာခံသည့် model ကို ထင်ဟပ်စေသည်။

### ဆက်စပ် ကုန်ကျစရိတ် စာမျက်နှာခွဲများ

ကုန်ကျစရိတ် ဧရိယာတွင် (`/dashboard/costs/` အောက်၌) အောက်ပါတို့လည်း ပါဝင်သည်-

- **စျေးနှုန်းသတ်မှတ်ခြင်း** (`/dashboard/costs/pricing`) — model တစ်ခုချင်းစီ၏ စျေးနှုန်းများကို ကြည့်ရှုပြီး အစားထိုးသတ်မှတ်နိုင်သည် (မျှဝေထားသော Pricing တက်ဘ်ကို
  ပြသသည်)။
- **ဘတ်ဂျက်** (`/dashboard/costs/budget`) — scope တစ်ခုချင်းစီအလိုက် အသုံးစရိတ်ကန့်သတ်ချက်များ သတ်မှတ်နိုင်သည် (မျှဝေထားသော
  Budget တက်ဘ်ကို ပြသသည်)။
- **Quota မျှဝေမှု** (`/dashboard/costs/quota-share`) — မျှဝေထားသော quota pool များနှင့် သုံးစွဲနှုန်း
  မြင်ကွင်းများ။

## API endpoint များ

ဖော်ပြမထားပါက ဤအရာအားလုံးသည် `requireManagementAuth` မှတစ်ဆင့် management auth (loopback/JWT) လိုအပ်သည်။

### အသုံးပြုမှုနှင့် ကုန်ကျစရိတ် ခွဲခြမ်းစိတ်ဖြာမှု

| နည်းလမ်း | Endpoint                 | ရည်ရွယ်ချက်                                                                                                                                                                                                  |
| -------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET`    | `/api/usage/analytics`   | ကုန်ကျစရိတ်/အသုံးပြုမှုဆိုင်ရာ အပြည့်အစုံ ခွဲခြမ်းစိတ်ဖြာမှု- အနှစ်ချုပ်၊ နေ့စဉ်လမ်းကြောင်းနှင့် provider/model/API key/account/tier အလိုက်။ Query- `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`။ |
| `GET`    | `/api/usage/utilization` | အချိန်အလိုက် provider တစ်ခုချင်းစီ၏ quota အသုံးပြုမှု။ Query- `range` (`1h`/`24h`/`7d`/`30d`), `provider`။                                                                                                   |
| `GET`    | `/api/usage/history`     | မပြုပြင်ရသေးသော အသုံးပြုမှုမှတ်တမ်း အတန်းများ။                                                                                                                                                               |
| `GET`    | `/api/usage/call-logs`   | တောင်းဆိုမှုတစ်ခုချင်းစီ၏ call log များ (model၊ token များ၊ ကုန်ကျစရိတ်၊ ကြာချိန်၊ အခြေအနေ)။                                                                                                                 |
| `GET`    | `/api/usage/quota`       | Provider quota အခြေအနေ။                                                                                                                                                                                      |
| `GET`    | `/api/usage/proxy-logs`  | Proxy တောင်းဆိုမှု log များ။                                                                                                                                                                                 |

### ဘတ်ဂျက်များ

| နည်းလမ်း | Endpoint                 | ရည်ရွယ်ချက်                                                                                         |
| -------- | ------------------------ | --------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/usage/budget`      | API key တစ်ခုအတွက် ကုန်ကျစရိတ်အနှစ်ချုပ် + ဘတ်ဂျက်စစ်ဆေးမှု (`apiKeyId` query parameter လိုအပ်သည်)။ |
| `POST`   | `/api/usage/budget`      | API key တစ်ခုအတွက် နေ့စဉ်/အပတ်စဉ်/လစဉ် USD ကန့်သတ်ချက်များ + သတိပေးချက်အဆင့်ကို သတ်မှတ်သည်။         |
| `GET`    | `/api/usage/budget/bulk` | API key များတစ်လျှောက် ဘတ်ဂျက်အနှစ်ချုပ်များကို အစုလိုက်ရယူသည်။                                     |

> ဘတ်ဂျက် API ကို **API key** (`apiKeyId`) တစ်ခုချင်းစီအလိုက် scope သတ်မှတ်ထားသည်။
> `GET /api/usage/budget` မှ ပြန်ပေးသော ကန့်သတ်ချက်များတွင် `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> `warningThreshold` တစ်ခုနှင့် ဆက်လက်စုစည်းထားသော စုစုပေါင်းများ (`totalCostToday`, `totalCostMonth`, …) ပါဝင်သည်။

### စျေးနှုန်းသတ်မှတ်ခြင်း

| နည်းလမ်း | Endpoint                | ရည်ရွယ်ချက်                                                                                                                                                                                                                  |
| -------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | အလွှာလေးခုမှ ပေါင်းစည်းထားသော ဈေးနှုန်း (အသုံးပြုသူ၊ models.dev၊ LiteLLM၊ မူလတန်ဖိုးများ)။ `?includeSources=1` က `pricing` + `sourceMap` ကို ပြန်ပေးသည်။                                                                     |
| `PATCH`  | `/api/pricing`          | `{ provider: { model: { input, output, cached, … } } }` အတွက် စျေးနှုန်းသတ်မှတ်ချက်ကို အစားထိုးသတ်မှတ်သည်။                                                                                                                   |
| `DELETE` | `/api/pricing`          | အသုံးပြုသူ၏ ဈေးနှုန်းအစားထိုးတန်ဖိုးများကို ဖယ်ရှားပါ၊ လိုအပ်ပါက `?provider=&model=` ဖြင့် နယ်ပယ်ကန့်သတ်နိုင်သည်; တစ်ပြေးညီချိန်ညှိထားသော နှုန်းထားများ သို့မဟုတ် ပါဝင်ပြီးသား မူလတန်ဖိုးများသည် အစားထိုးသုံးရန် ကျန်ရှိသည်။ |
| `GET`    | `/api/pricing/defaults` | 1M တစ်ခုလျှင် မူလ fallback နှုန်းထားများကို ပြသသည်။                                                                                                                                                                          |
| `GET`    | `/api/pricing/models`   | Model ဖြင့် key သတ်မှတ်ထားသော စျေးနှုန်းများ။                                                                                                                                                                                |
| `POST`   | `/api/pricing/sync`     | ပြင်ပအရင်းအမြစ်များ (LiteLLM) မှ ကိုယ်တိုင် sync လုပ်ခြင်းကို စတင်သည်။                                                                                                                                                       |
| `GET`    | `/api/pricing/sync`     | လက်ရှိ sync အခြေအနေ။                                                                                                                                                                                                         |
| `DELETE` | `/api/pricing/sync`     | LiteLLM မှ တစ်ပြေးညီချိန်ညှိထားသော ဈေးနှုန်း (`pricing_synced`) ကိုသာ ရှင်းပါ; models.dev ဒေတာသည် သီးခြားဖြစ်သည်။                                                                                                            |

### ကုန်ကျစရိတ်နှင့် သက်ဆိုင်သော အခြား endpoint များ

| နည်းလမ်း | Endpoint                      | ရည်ရွယ်ချက်                                                                                        |
| -------- | ----------------------------- | -------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/free-tier/summary`      | အခမဲ့မော်ဒယ် တိုကင်စုစုပေါင်း၊ ယခုလအတွင်း အသုံးပြုပြီးသည့်ပမာဏနှင့် ကျန်ရှိသည့် အခမဲ့ခွင့်ပြုပမာဏ။ |

## CLI

OmniRoute ၏ CLI တွင် ကုန်ကျစရိတ်၊ အသုံးပြုမှုနှင့် ဈေးနှုန်းဆိုင်ရာ command များကို အသုံးပြုနိုင်သည် ([`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) တွင် စာရင်းသွင်းထားသည်)။

### `omniroute cost`

`/api/usage/analytics` မှ စုစည်းထားသော ကုန်ကျစရိတ်အစီရင်ခံစာ။

```bash
omniroute cost                          # နောက်ဆုံး 30 ရက်၊ provider အလိုက် အုပ်စုဖွဲ့ထားသည်
omniroute cost --period 7d              # နောက်ဆုံး 7 ရက်
omniroute cost --group-by model         # provider | model | combo | api-key | day အလိုက် အုပ်စုဖွဲ့ရန်
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ကော်လံများ- အုပ်စု၊ request အရေအတွက်၊ အဝင်/အထွက် token များ၊ ကုန်ကျစရိတ် (USD) နှင့် စုစုပေါင်း၏ ရာခိုင်နှုန်း။ နောက်ဆုံးတွင် စုစုပေါင်းစာကြောင်းကို ဖော်ပြသည် (`--quiet` သို့မဟုတ် `--output json` ဖြင့် ပိတ်ထားနိုင်သည်)။

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # provider တစ်ခုချင်းစီအလိုက် ကုန်ကျစရိတ်အကျဉ်းချုပ်
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ဘတ်ဂျက်များ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` သည် `GET /api/pricing/defaults` ကို ဖတ်ရှုသည်။ Model တစ်ခုချင်းစီ၏
> ဈေးနှုန်းများကို ပြင်ဆင်လိုပါက **Pricing** dashboard စာမျက်နှာ သို့မဟုတ် `PATCH /api/pricing` ကို အသုံးပြုပါ။

## ပြဿနာဖြေရှင်းခြင်း

- **ကုန်ကျစရိတ်အားလုံးတွင် $0 / "Legacy / Free" ဟု ဖော်ပြနေသည်။** အသုံးပြုနေသော model များအတွက် ဈေးနှုန်းထည့်သွင်းချက် မရှိပါ။
  ပြင်ပ sync ကို ဖွင့်ရန် (`PRICING_SYNC_ENABLED=true`) သတ်မှတ်ပြီး `omniroute pricing sync` ကို လုပ်ဆောင်ပါ၊ သို့မဟုတ်
  Pricing စာမျက်နှာ / `PATCH /api/pricing` မှတစ်ဆင့် ဈေးနှုန်းများကို ကိုယ်တိုင် သတ်မှတ်ပါ။
- **ယခင်က အသုံးပြုခဲ့သော model တစ်ခု၏ ဈေးနှုန်း မှားယွင်းနေသည်။** ဈေးနှုန်းကို ပြင်ဆင်ပါ (override လုပ်ခြင်း သို့မဟုတ် ပြန်လည် sync လုပ်ခြင်း) — analytics ကို ဖတ်ရှုသည့်အခါတိုင်း token အရေအတွက်များမှ ကုန်ကျစရိတ်ကို ပြန်လည်တွက်ချက်သောကြောင့် ခန့်မှန်းချက်များကို နောက်ကြောင်းပြန် အပ်ဒိတ်လုပ်ပေးသည်။
- **သုံးစွဲငွေပမာဏသည် အချိန်နှင့်တစ်ပြေးညီ မဖြစ်ဘဲ နောက်ကျနေသည်။** Key တစ်ခုချင်းစီ၏ သုံးစွဲငွေကို အစုလိုက် လုပ်ဆောင်သည်၊ ပိုမိုလတ်ဆတ်သော ကိန်းဂဏန်းများ လိုအပ်ပါက
