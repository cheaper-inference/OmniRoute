`@omniroute/opencode-plugin-v2` သည် သင်၏ OmniRoute ကတ်တလောက်တစ်ခုလုံး — မော်ဒယ်များ၊ combo များနှင့်
auto-combo များ — ကို ပြသမည့်အမည်များ၊ ဈေးနှုန်းများနှင့် အခမဲ့အဆင့်
သုံးစွဲခွင့်ပမာဏများနှင့်အတူ OpenCode v2 ၏ မော်ဒယ်ရွေးချယ်ကိရိယာထဲသို့ ထည့်ပေးသည်။

၎င်းသည် `@omniroute/opencode-plugin` နှင့် သီးခြား package တစ်ခုဖြစ်သည်၊ အဘယ်ကြောင့်ဆိုသော် OpenCode v1 နှင့် v2 တို့သည်
plugin များကို မတူညီသော contract များဖြင့် load လုပ်သောကြောင့်ဖြစ်သည်။ သင်၏ OpenCode major version နှင့် ကိုက်ညီသည့်တစ်ခုကို
ရွေးချယ်ပါ။ ၎င်းတို့ကြားတွင် မည်သည့်အရာမျှ မျှဝေထားခြင်းမရှိသောကြောင့် တစ်ခုကို upgrade လုပ်ခြင်းက အခြားတစ်ခုကို မည်သည့်အခါမျှ အတင်းအကျပ် upgrade မလုပ်စေပါ။

## လိုအပ်ချက်များ

- OpenCode v2။
- ချိတ်ဆက်အသုံးပြုနိုင်သော OmniRoute gateway (`http://localhost:20128` ကို မူလအဖြစ် သတ်မှတ်ထားသည်)။
- Node.js 22 သို့မဟုတ် 24။

## ထည့်သွင်းခြင်း

Plugin ကို `opencode.json` ထဲသို့ ထည့်ပါ။

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

ထို့နောက် မော်ဒယ်များသည် `omniroute/<provider>/<model>` အဖြစ် ပေါ်လာမည်။ `providerId` က ထို prefix နှင့်
OpenCode က credential ကို သိမ်းဆည်းမည့် integration ၏ id ကို သတ်မှတ်သည်။

## အထောက်အထားများ

Plugin သည် gateway key ကို အောက်ပါနေရာသုံးခုတွင် အစဉ်လိုက် ရှာဖွေသည်။

1. **OpenCode တွင် သင်ချိတ်ဆက်ထားသော credential။** Plugin သည် integration တစ်ခုကို မှတ်ပုံတင်ပေးသောကြောင့်
   OpenCode ၏ ကိုယ်ပိုင် auth flow က key ကို သိမ်းဆည်းနိုင်သည်။ `opencode.json` ထဲသို့ မည်သည့်အရာမျှ မရောက်ရှိပါ — ဤနည်းကို ဦးစားပေးပါ။
2. Project တစ်ခုချင်းစီအလိုက် override လုပ်ရန် plugin options ထဲရှိ `apiKey`။ ၎င်းက key ကို သင်
   commit လုပ်နေနိုင်သည့် file တစ်ခုထဲတွင် ထည့်သွင်းထားမည်။
3. Environment ထဲရှိ `OMNIROUTE_API_KEY`။

သုံးခုလုံး မရှိပါက ကတ်တလောက်သည် ဗလာဖြစ်နေမည်ဖြစ်ပြီး plugin က အသံတိတ် ဗလာဖြစ်နေသော ရွေးချယ်ကိရိယာတစ်ခုကို
ထားပေးမည့်အစား စတင်ချိန်တွင် တစ်ကြိမ် အသိပေးမည်။

### စီမံခန့်ခွဲမှု token သည် မတူညီသော key တစ်ခုဖြစ်သည်

Combo များ၊ provider အခြေအနေနှင့် အချက်အလက်ဖြည့်စွက်ခြင်း (ပြသမည့်အမည်များ၊ ဈေးနှုန်းများ၊ အခမဲ့အဆင့် သုံးစွဲခွင့်ပမာဏများ) ကို
gateway ၏ `/api/*` endpoint များမှ ရယူသည်။ Deployment အများစုတွင် ၎င်း endpoint များကို inference key အစား
**management** token ဖြင့် ကာကွယ်ထားသည်။

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

`managementReadToken` ကို မသတ်မှတ်ထားပါက `apiKey` ကို အစားထိုးအသုံးပြုသည်။ Gateway က ထိုအစားထိုးအသုံးပြုမှုကို
ငြင်းပယ်သည့်အခါ ကတ်တလောက်ကို ဆက်လက်ထုတ်ပြန်ပေးမည်ဖြစ်သော်လည်း ပြသမည့်အမည်များအစား မူရင်း model id များသာ ပါမည်၊ canonical
alias ထပ်တူဖယ်ရှားခြင်း မရှိ၊ ဈေးနှုန်းများ မရှိသကဲ့သို့ combo များလည်း မရှိပါ။ ထိုသို့ဖြစ်သည့်အခါ plugin က endpoint တစ်ခုစီအတွက် တစ်ကြိမ်
သတိပေးပြီး endpoint နှင့် ဆုံးရှုံးသွားသည့်အရာကို ဖော်ပြပေးသည် — ထို့ကြောင့် လုပ်ဆောင်နိုင်စွမ်းလျော့နည်းနေသော ရွေးချယ်ကိရိယာသည် မည်သည့်အခါမျှ နားမလည်နိုင်စရာ မဖြစ်ပါ။

အသုံးပြုမှုမှတ်ဉာဏ်ကို မူရင်းအတိုင်း ဖွင့်ထားသည်။ စီမံခန့်ခွဲမှု တိုကင်မပါဘဲ ၎င်းသည် ရပ်တန့်နေမည် (စတင်မှုသတိပေးချက်ကို မှတ်တမ်းတင်ထားသည်) နှင့် မည်သည့်အရာမှ ပြန်လည်ရယူမည်မဟုတ်ပါ။

## ကတ်တလောက်က ဘယ်လို ဆန်းသစ်နေလဲ။

ကတ်တလောက်ကို ပျင်းရိစွာ ထုတ်ယူပြီး `modelCacheTtlMs` အတွက် ကက်ရှ်လုပ်ထားပြီး၊ ဂိတ်ဝမှ ဆက်သွယ်၍မရသော — ပြတ်တောက်မှုသည် သင့်အား လတ်ဆတ်မှုမှလွဲ၍ ဘာမှမကုန်ကျသည့်အခါ ဒစ်ခ်လျှပ်တစ်ပြက်ရိုက်ချက်သည် နောက်ဆုံးသိရှိထားသည့် ကတ်တလောက်ကို သိမ်းဆည်းထားသည်။ မော်ဒယ်များနှင့် ပေါင်းစပ်မှုများကို ၎င်းတို့ရောက်ရှိသည်နှင့်တပြိုင်နက် ထုတ်ဝေသည်။ အလိုအလျောက်ပေါင်းစပ်မှုများ၊ ဝန်ဆောင်မှုပေးသူစာရင်းနှင့် ကြွယ်ဝမှုထပ်ဆင့်ခြင်းတို့သည် ၎င်းတို့ရောက်ရှိသည့်အခါတွင် ခေါက်သွားသောကြောင့် နှေးကွေးသောအဆုံးအချက်တစ်ခုသည် ရွေးချယ်သူတစ်ခုလုံးကို ဓားစာခံအဖြစ် မထိန်းထားနိုင်ပါ။

အမည်များသည် `Provider - Model[ (Editor)][ · budget][ (route)]` နှင့် လိုက်နာသည် : id သည် တစ်ခု (ရှေ့ဆက်မပါသော မျဥ်းစောင်းနည်း id renders) ကို သယ်ဆောင်သည့်အခါတိုင်းတွင် ဝန်ဆောင်မှုပေးသူက ပြသည်) `🆓` ဦးဆောင်မှုများကို အခမဲ့ အမှတ်အသားပြုပြီး ၎င်းတို့၏ အခမဲ့-အဆင့် ဘတ်ဂျက်သည် `· 1M tokens/month` ၏ နောက်ဆက်အဖြစ် ဆက်ရှိနေသည်၊ တိကျပြတ်သားသော `Editor: Model` `combo - <slug>` မည်၏ တည်းဖြတ်သူသည် နောက်ဆွဲကွင်းစဥ်တစ်ခုသို့ ရွှေ့သွားသည် အိုင်ကွန်။ အမည်တစ်ခုကို မျှဝေသော entry နှစ်ခုသည် route suffix — `(no-think)` — ရရှိသောကြောင့် ၎င်းတို့သည် ခွဲခြားသိမြင်နိုင်မည်ဖြစ်သည်။ `providerTag` (မူလ `true`) သည် နောက်မှလိုက်နေသော တည်းဖြတ်သူ ကွင်းပိတ်ကို ပြောင်းပေးသည်။

manual refresh command မရှိပါ။ OpenCode v2 commands များသည် callbacks များမဟုတ်ဘဲ prompt templates များဖြစ်သောကြောင့် plugin တစ်ခုမှ တစ်ခုအား ဖော်ထုတ်၍မရပါ။ ပြန်လည်ဆန်းသစ်မှုများသည် TTL ကိုလိုက်နာသည်။ ကက်တလောက် သို့မဟုတ် ထပ်ဆင့်လွှာ အမှန်တကယ် ပြောင်းလဲသွားမှသာ ပြန်လည်စတင်ရန် အိမ်ရှင်အား တစ်ကြိမ်မျှ ပြန်လည်စတင်ရန် တောင်းဆိုပါသည်။

## Gemini တွင် tool ခေါ်ယူခြင်း

Tool declarations များတွင် `$schema` သို့မဟုတ် `additionalProperties` ပါဝင်ပါက Gemini သည် request တစ်ခုလုံးကို ပယ်ချပြီး `400 INVALID_ARGUMENT` ဟု တုံ့ပြန်သည်။ Plugin သည် ဤ provider ၏ Gemini model သို့ ပို့မည့် tool schemas များမှ ထို keywords များကို ဖယ်ရှားပြီး အခြား request အားလုံးကို မပြောင်းလဲဘဲ ထားရှိသည်။ `$ref` ပါဝင်သော tool တစ်ခုကိုမူ မဖယ်ရှားဘဲ မူလအတိုင်း ဆက်လက်ပို့ပေးသည်။ အကြောင်းမှာ reference ကို ဖယ်ရှားလိုက်ပါက schema သည် "မည်သည့်အရာမဆို လက်ခံရန်" အထိ ကျယ်ပြန့်သွားမည်ဖြစ်သောကြောင့် ဖြစ်သည်။
၎င်းကို ပိတ်ရန် `"geminiSanitization": false` ဟု သတ်မှတ်ပါ။
