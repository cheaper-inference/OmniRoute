ကြားနေ `config/cli-tools-manifest.json` စာချုပ်တွင် canonical IDs၊ နာမည်တူ၊ ဒွိကိုယ် စားလှယ်များ၊ စနစ်ထည့်သွင်းမှု ချက်ပြုတ်နည်းများ၊ မော်ဒယ် အငြင်းအခုံများနှင့် စွမ်းရည်များကို ကြေငြာသည်။ `bin/cli/cli-manifest.mjs` ရှိ ရိုးရိုး Node adapter နှင့် `src/shared/constants/cliIntegrationManifest.ts` ရှိ TypeScript adapter တို့သည် တူညီသောဖိုင်ကို ဖတ်သည်။ Runtime၊ catalog၊ configure၊ completion၊ generator နှင့် backend မှတ်ပုံတင်ခြင်းကို `tests/unit/cli/cli-manifest-drift.test.ts` မှ အတူတကွ စစ်ဆေးပါသည်။ ကက်တလောက်စာရင်းသွင်းခြင်းသည် ကိရိယာတစ်ခုကို စတင်နိုင်သည် သို့မဟုတ် ပြင်ဆင်သတ်မှတ်နိုင်သည်ဟု မဆိုလိုပါ။ အထူးသဖြင့်၊ 5dive သည် configure-only ဖြစ်နေသည်။

## ကလေးပတ်ဝန်းကျင်နှင့် ဘဝသံသရာ

`omniroute run`၊ `omniroute launch` နှင့် `omniroute launch-codex` OS/terminal လိုက်ဖက်ညီသော ခွင့်ပြုစာရင်းကို အမွေဆက်ခံပြီး ရွေးချယ်ထားသော ပစ်မှတ်၏ အထောက်အထားများကို ထည့်သွင်းပါ။ မသက်ဆိုင်သော ဝန်ဆောင်မှုပေးသူနှင့် ဒေတာဘေ့စ်လျှို့ဝှက်ချက်များကို မူရင်းအတိုင်း အမွေဆက်ခံမည်မဟုတ်ပါ။ `--inherit-env` မိဘ-ပတ်ဝန်းကျင် အမွေကို အပြည့်အ၀ ပြန်လည်ရယူသည်၊ ရွေးချယ်ထားသော ပြင်ပအဖွဲ့အစည်း လုပ်ငန်းစဉ်သည် ထိုတန်ဖိုးများကို လက်ခံရရှိမှသာ ၎င်းကို အသုံးပြုပါ။ ၎င်းသည် ပတ်၀န်းကျင်ကို စစ်ထုတ်ခြင်းဖြစ်ပြီး OS sandbox မဟုတ်ဘဲ၊ လုပ်ငန်းစဉ်သည် ခေါ်ဆိုသူ၏ဖိုင်စနစ်ခွင့်ပြုချက်ဖြင့် လုပ်ဆောင်နေဆဲဖြစ်သည်။

နှောင့်ယှက်ခြင်းနှင့် ရပ်စဲခြင်း အချက်ပြမှုများကို ကလေးထံ ပေးပို့သည်။ လောင်ချာသည် ယာယီဖွဲ့စည်းပုံကို မဖယ်ရှားမီ ကလေး၏ အနီးကပ်ဖြစ်ရပ်ကို စောင့်နေသည်။ `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` အတင်းအဓမ္မရပ်စဲခြင်းမပြုမီ ကျေးဇူးတော်ကာလကို ထိန်းချုပ်သည် (မူလ 5000 မီလီစက္ကန့်)။

## Gemini ဆက်တိုက်ထည့်သွင်းခြင်း။

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

ပထမအမိန့်နှစ်ခုသည် ရွေးချယ်ထားသော စက်တွင်း သို့မဟုတ် အဝေးထိန်းဆာဗာအတွက် ဤစက်ကို စီစဉ်သတ်မှတ်ပေးသည်။ စနစ်ထည့်သွင်းခြင်းသည် မသက်ဆိုင်သော JSON ဆက်တင်များကို ထိန်းသိမ်းထားပြီး Gemini API-key auth ကို ရွေးကာ အဆုံးမှတ်နှင့် အထောက်အထားကို သီးသန့် `.gemini/.env` ဖိုင်သို့ ရေးပေးသည်။ ၎င်းသည် overwrite လုပ်မည့်အစား မမှန်ကန်သော JSON ငြင်းပယ်သည်။ အဆုံးမှတ် URLs HTTP(S) ဖြစ်ရမည်၊ ထည့်သွင်းထားသော အထောက်အထားများ၊ မေးမြန်းမှု ကန့်သတ်ချက်များ သို့မဟုတ် အပိုင်းအစများ မပါဘဲ ဖြစ်ရပါမည်။ Dry-run သည် အထောက်အထားတန်ဖိုးများမဟုတ်ဘဲ လမ်းကြောင်းများကို ပရင့်ထုတ်သည်။

`GEMINI_CLI_HOME` သို့မဟုတ် `--gemini-home` အမြဲတမ်းပင်မအမြစ်ကို ရွေးသည်။ အမှန်တကယ် `run gemini` ဖန်တီးပြီး နောက်ပိုင်းတွင် ၎င်း၏ ယာယီနေအိမ်ကို ဖယ်ရှားသည်။ မုဒ်နှစ်ခုစလုံးသည် Gemini၏ workspace-trust checks များကို ကျော်ဖြတ်မည်မဟုတ်ပါ။

## Codex ပရိုဖိုင်များ

`configure codex` မော်ဒယ်တစ်ခုနှင့် ၎င်း၏ OmniRoute ဝန်ဆောင်မှုပေးသူ အဆုံးမှတ်ဖြင့် သီးသန့် `<name>.config.toml` ရေးသားသည်။ အထောက်အထားများကို `OMNIROUTE_API_KEY` မှတဆင့် ကိုးကား၍ မည်သည့်အခါမျှ ထည့်သွင်းထားခြင်းမရှိပါ။ ပစ်လွှတ်ခြင်းအမိန့်သည် `model_providers` အတွင်းမဟုတ်ဘဲ ထိပ်တန်းအဆင့် `model` ကီးတွင် ရွေးချယ်ထားသော မော်ဒယ်ကို သတ်မှတ်သည်။

သီးခြားပရိုဖိုင်ဖိုင်များသည် လက်ရှိမှတ်တမ်းတင်ထားသော Codex စာချုပ်ဖြစ်သည်။ `codex --profile <name>` ဖြင့် ရွေးချယ်သောအခါတွင် အသုံးပြုသူ configuration ကို ထပ်ဆင့်ထားသည်။ [တရားဝင်ပရိုဖိုင်အကိုးအကား](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) နှင့် [OmniRoute Codex လမ်းညွှန်ကို](./CODEX-CLI-CONFIGURATION.md) ကြည့်ပါ။

## Hermetic အမိန့်ကို အကောင်အထည်ဖော်ခြင်း။

တိကျပြတ်သားသော `DATA_DIR` ဖြင့်၊ `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` ဆက်တင်သည် မူလအသုံးပြုသူဒေတာလမ်းညွှန်၏ အထောက်အထားပတ်ဝန်းကျင်သို့ စတင်ဝင်ရောက်ခြင်းကို တားဆီးပေးသည်။ ၎င်းသည် သီးခြားစမ်းသပ်မှုများအတွက် အသုံးဝင်သည်။ ၎င်းသည် အခြားသော အထူးတလည်ရွေးချယ်ထားသော ပတ်ဝန်းကျင်ဖိုင်များကို မပိတ်ပါ။

## အလုပ်လမ်းညွှန် `.env`

CLI ဤအစီအစဥ်တွင် `.env` ဖိုင်များကိုဖတ်ပြီး သော့တစ်ခုသတ်မှတ်ရန် ပထမဆုံးဖိုင်သည် အနိုင်ရသည်- တိကျပြတ်သားသော `DATA_DIR`၊ မူရင်းဒေတာလမ်းညွှန်၊ လက်ရှိလုပ်ဆောင်နေသည့် လမ်းညွှန်၊ ထို့နောက် ပက်ကေ့ဂျ်လမ်းညွှန်။ Shell variable များသည် အမြဲအနိုင်ရသည်။

အလုပ်လုပ်သောလမ်းညွှန်သည် အခြားသူတစ်ဦးဦး (ပုံတူကူးယူထားသော သိုလှောင်မှု၊ ထုပ်ပိုးထားသော မှတ်တမ်း) နှင့် သက်ဆိုင်နိုင်ပြီး `omniroute serve` CLI ပတ်၀န်းကျင်ကို ဆာဗာပေါ်နှင့် ဆာဗာလည်ပတ်သည့် ကိရိယာတိုင်းထံ ပေးပို့သည်။ ထို့ကြောင့် `.env` `bin/cli/utils/untrustedCwdEnv.mjs` တွင်ဖော်ပြထားသော ဤသော့များကိုသာ သတ်မှတ်နိုင်သည်။

| သော့                            | လက်ခံထားတဲ့ တန်ဖိုးများ                                                   |
| ------------------------------- | ------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`၊ `1` သို့မဟုတ် `yes` မည်သို့ပင်ဆိုစေ၊ ဆာဗာက သတ်မှတ်သည့်တန်ဖိုးများ |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 64 စာလုံး၊ ဂဏန်းများ၊ `_`၊ `.`၊ `@` သို့မဟုတ် `-` အထိ                     |
| `LANGUAGE`                      | အတူတူပါပဲ၊ အပေါင်း `:`                                                    |
| `TZ`                            | 64 လုံးအထိ၊ ဂဏန်းများ၊ `_`၊ `+`၊ `-` သို့မဟုတ် `/`၊ `/` ဖြင့်မစတင်ပါ။     |
| `NO_COLOR`, `FORCE_COLOR`       | 16 စာလုံးနှင့်ဂဏန်းများအထိ                                                |

`REQUIRE_API_KEY` တန်ဖိုးတိုင်းသည် check on ကိုလက်ခံသည်၊ ထို့ကြောင့်ဖိုင်သည် check off ကိုမပိတ်နိုင်ပါ။ ရလဒ်ကို မဆုံးဖြတ်နိုင်သော်လည်း၊ ဆာဗာသည် ပတ်ဝန်းကျင်ရှေ့၌ ဒေတာဘေ့စ်တွင် သိမ်းဆည်းထားသော `REQUIRE_API_KEY` အစားထိုးမှုကို ဖတ်ပြသော်လည်း API သော့မပါသော အင်တာဖေ့စ်အားလုံးတွင် နားထောင်ခြင်းနှင့်ပတ်သက်၍ စတင်ခြင်းသတိပေးချက်က ပတ်ဝန်းကျင်ကိုသာ ဖတ်သည်။ သိမ်းဆည်းထားသော `false`၏ အစားထိုးမှုဖြင့်၊ အလုပ်လုပ်သည့်လမ်းညွှန် `REQUIRE_API_KEY=true` API ကိုဖွင့်ပြီး ထိုသတိပေးချက်ကို ဝှက်ထားသည်။ `TZ` စည်းမျဉ်းသည် POSIX ထက် ကျဉ်းသည် - ၎င်းသည် `.`, `:`, `,` နှင့် `<>` ငြင်းပယ်သည်၊ ထို့ကြောင့် `EST5EDT,M3.2.0,M11.1.0` ကဲ့သို့သော `:Area/City` ပုံစံနှင့် စည်းမျဉ်းများကို shell သို့မဟုတ် `<DATA_DIR>/.env` တွင် သတ်မှတ်ရမည်ဖြစ်သည်။

အမည်များသည် စာလုံးကြီးဖြင့် အတိအကျ တူညီရပါမည်။ အခြားစာကြောင်းများ၊ စစ်ဆေးမှုပျက်ကွက်သည့်တန်ဖိုးနှင့် ရိုးရိုး ASCII အက္ခရာများ၊ ဂဏန်းများနှင့် `_` (ဥပမာ NUL byte သို့မဟုတ် ပုံစံတူအက္ခရာတစ်ခုပါရှိသော) အမည်ကို ကျော်သွားပါသည်။ CLI သတ်မှတ်မရနိုင်သောသော့များကို အမည်ပေးကာ လျစ်လျူရှုထားသောသော့များကို အမည်ပေးထားသည့် သတိပေးချက်တစ်ခုစီကို ပရင့်ထုတ်သည် (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`)။ တန်ဖိုးများကို ပုံနှိပ်ခြင်းလည်း မပြုပါ။ ဤမက်ဆေ့ဂျ်များရှိ ဖိုင်လမ်းကြောင်းများနှင့် `.env` လမ်းကြောင်း `omniroute doctor` အစီရင်ခံစာများသည် ၎င်းတို့တွင် ထိန်းချုပ်မှု သို့မဟုတ် bidi စာလုံးများပါရှိသည့်အခါ လွတ်မြောက်သွားမည်ဖြစ်သည်။ အလုပ်လမ်းညွှန်သည် ဒေတာလမ်းညွှန် သို့မဟုတ် ပက်ကေ့ဂျ်လမ်းညွှန်ဖြစ်သည့်အခါ ကန့်သတ်ချက်သည် သက်ရောက်မှုမရှိပါ။

`PORT`၊ `API_PORT` နှင့် `DASHBOARD_PORT` စာရင်းတွင် မပါဝင်ပါ။ ဦးစားပေး ရင်းမြစ်မှ အခြေခံ URL မပါဘဲ CLI `localhost:<PORT>` သို့ ပြောဆိုသည်၊ ၎င်းတွင် နားထောင်သည့်တိုင်းတွင် CLI's API သော့၊ ဆက်စပ် တိုကင်နှင့် CLI စက်တိုကင် (`x-omniroute-cli-token`၊ [CLI_TOKEN.md](../security/CLI_TOKEN.md) ကိုကြည့်ပါ ) တွင် ဒေသခံဆာဗာသည် စီမံခန့်ခွဲမှုခေါ်ဆိုမှုများကို loopback မှ လက်ခံရန်အတွက် လက်ခံပါသည်။ အလုပ်လုပ်သည့်လမ်းညွှန်မှ ပို့တ်တစ်ခုသည် ထိုဖိုင်အား နားဆင်သူကိုရွေးချယ်ခွင့်ပေးသည်၊ ထို့ကြောင့် တစ်ခုပါရှိသော command များ၏ shell၊ `<DATA_DIR>/.env` သို့မဟုတ် `--port` ရွေးချယ်မှုဖြင့် သတ်မှတ်ပါ (`serve`, `launch`, `run`)။

parser တွင် `export` syntax မရှိပါ။ `export LD_PRELOAD=...` ကဲ့သို့သော လိုင်းတစ်ခုသည် ပြောင်းလဲနိုင်သော `export LD_PRELOAD` အမည်ပေးသည်။ အလုပ်လုပ်သောလမ်းညွှန်မှ၎င်းကိုကျော်သွားသည်နှင့်အခြား `.env` ဖိုင်များတွင်၎င်းသည်မည်သည့်စာသားကိုမျှမဖတ်နိုင်သောထိုစာလုံးကိုသတ်မှတ်သည်။

CLI သည် ဆက်စပ်အကြောင်းအရာ၏ ကိုယ်ပိုင်ဇာစ်မြစ်- `URL.origin` နှင့် နှိုင်းယှဉ်ထားသည့် ဆက်စပ်ပစ္စည်း သိမ်းဆည်းထားသော တိုကင် (ဝင်ရောက်ခွင့် တိုကင် သို့မဟုတ် အမွေအနှစ် API ကီး) ကို တွဲပေးပါသည်။ ၎င်းသည် CLI၏ HTTP client (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) နှင့် `launch`, `launch codex`, `configure` နှင့် `setup-*` commands များနှင့် အခြား tool ၏ config တွင် အခြေခံ URL နှင့် သော့ကိုရေးပေးသော တောင်းဆိုမှုများနှင့် သက်ဆိုင်ပါသည်။ `--remote` ပါသော အခြားဆာဗာကို ညွှန်ပြပါက၊ ၎င်းတို့သည် သတ်မှတ်ထားသည့် တိကျပြတ်သားသော `--api-key` သို့မဟုတ် `OMNIROUTE_API_KEY` ကို အသုံးပြုကာ ဆက်စပ်တိုကင်မရှိပါ။ နှိုင်းယှဉ်ချက်သည် အတိအကျဖြစ်သည်၊ ထို့ကြောင့် `localhost` နှင့် `127.0.0.1`၊ သို့မဟုတ် နောက်တွင်ရှိသော အစက်ပါရှိသော လက်ခံသူသည် မတူညီသောဆာဗာများအဖြစ် ရေတွက်ပြီး ဆက်စပ်တိုကင်မယူပါ။ အသုံးပြုသူအချက်အလက်၊ backslash သို့မဟုတ် whitespace ပါသည့် URL တစ်ခုသည် အခြား URL ခွဲခြမ်းစိတ်ဖြာမှုများ (ဥပမာ Python ၏ `urllib` နှင့် `httpx`) မှ မတူညီသော host တစ်ခုကို ဖတ်နိုင်သောကြောင့် ဖြစ်သည်။ CLI က သူ့ဘာသာသူ ပေးပို့တဲ့ တောင်းဆိုမှုတွေအတွက် ချက်လက်မှတ်က scheme နဲ့ authority ကိုသာ အကျုံးဝင်တာမို့ လမ်းကြောင်း (သို့) query မှာ space ပါတဲ့ id က တိုကင်ကို သိမ်းထားပါတယ်။
