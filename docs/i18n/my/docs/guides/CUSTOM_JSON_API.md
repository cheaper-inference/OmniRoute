စိတ်ကြိုက် JSON API node သည် OpenAI သို့မဟုတ် Anthropic ပရိုတိုကောကို မပြောနိုင်သော JSON လုပ်ငန်းအဆုံးမှတ်ကို ချိတ်ဆက်သည်။ OmniRoute JSON တောင်းဆိုမှု ပုံစံပလိတ်ကို ဖြည့်ပေးကာ ပြီးပြည့်စုံသော အဆုံးမှတ် URL သို့ ပို့ပေးသည်၊ တုံ့ပြန်မှုလမ်းကြောင်းမှ ပြန်ကြားချက်ကို ဖတ်ပြီး ကလိုင်းယင့်၏ ကိုယ်ပိုင်ဖော်မတ် (ချတ်ပြီးမြောက်မှုများ၊ တုံ့ပြန်မှုများ၊ မက်ဆေ့ချ်များ၊ ...)။

၎င်းသည် `apiType: "custom-json"` နှင့် OpenAI-သဟဇာတရှိသော node တစ်ခုဖြစ်သည်။ ၎င်း၏ id တွင် `openai-compatible-custom-json-<suffix>` ပုံစံရှိသည်။ ဒက်ရှ်ဘုတ်ပုံစံကို မရရှိနိုင်သေးပါ။ အောက်ဖော်ပြပါ ဝန်ဆောင်မှုပေးသူ- node API မှတဆင့် ဤ node များကို ဖန်တီးပြီး တည်းဖြတ်ပါ။

## node တစ်ခုဖန်တီးပါ။

`POST /api/provider-nodes` (စီမံခန့်ခွဲမှု အထောက်အထား):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` သည်** ပြီးပါပြီ။** အဆုံးမှတ် URL မည်သည့်အရာကိုမျှ ထပ်မထည့်ပါ ( `/chat/completions`၊ no `/models`) နှင့် အခြားသော OpenAI-compatible node များနှင့်မတူဘဲ၊ မူရင်း URL မရှိပါ။ ၎င်းသည် `http(s)` ဖြစ်ရမည်၊ ထည့်သွင်းထားသောအထောက်အထားများ သို့မဟုတ် `#fragment` မရှိဘဲ၊ ၎င်းသည် node ကိုသိမ်းဆည်းသည့်အခါနှင့် တောင်းဆိုမှုတိုင်းတွင် ဝန်ဆောင်မှုပေးသူအားလုံးကဲ့သို့တူညီသော outbound URL guard ကိုဖြတ်သန်းသည်။
- ချိတ်ဆက်မှုကီး (`authType` `bearer` သို့မဟုတ် `api-key`၊ မူရင်းအပါအ ၀ င်) ပေးပို့သော node သည် `https://` အသုံးပြုရပါမည်။ ရိုးရိုး `http://` loopback host (`localhost`, `127.0.0.0/8`, `::1`) သို့မဟုတ် `authType: "none"` ဖြင့်သာ လက်ခံပါသည်။ သီးသန့် LAN လိပ်စာများ (`10.x`, `172.16-31.x`, `192.168.x`) များကို ကင်းလွတ်ခွင့်မပြုပါ- ထိုကွန်ရက်ရှိ မည်သူမဆို သော့ကို ဖတ်နိုင်သည်။ ထိုသို့သော node တစ်ခုကို သိမ်းဆည်းခြင်းသည် `400` ဖြင့် မအောင်မြင်ဘဲ၊ တောင်းဆိုမှုတိုင်း မပို့မီ တူညီသော မက်ဆေ့ချ်ဖြင့် တောင်းဆိုမှုတိုင်းတွင် စောစောက သိမ်းဆည်းထားသော ကုဒ်တစ်ခုသည် ပိတ်သွားပါသည်။ LAN တွင် သော့ခတ်ထားသော အဆုံးမှတ်အတွက် TLS (ဥပမာ ပြောင်းပြန်ပရောက်စီ) နောက်တွင် ထားလိုက်ပါ။
- `customJson` Zod ဖြင့် အတည်ပြုထားသည်။ အမည်မသိသော့များကို ငြင်းပယ်ထားသည်။ အကွက်တိုင်းသည် ရွေးချယ်နိုင်သည်-

| လယ်ကွင်း          | တန်ဖိုးများ                                         | ပုံသေ                                                  |
| ----------------- | --------------------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                              | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                         | `bearer`                                               |
| `authHeader`      | `api-key` တွင် ခေါင်းစီးအမည်ကို အသုံးပြုသည်။        | `X-API-Key`                                            |
| `requestTemplate` | JSON အရာဝတ္ထု (≤ 64 KB၊ အတိမ်အနက် ≤ 32)             | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | တစ်ကိုယ်လုံးအတွက် လယ်ကွင်းလမ်းကြောင်း သို့မဟုတ် `$` | `choices[0].message.content`                           |

- လျှို့ဝှက်ချက်သည် ချိတ်ဆက်မှု၏ API သော့တွင် ရှိနေသည်၊၊ ပုံစံပလိတ်တွင် ဘယ်သောအခါမှ မရှိပါ။ `bearer` ပေးပို့သည် `Authorization: Bearer <key>`; `api-key` `<authHeader>: <key>` ပို့ပေးပါတယ်။ auth header သည် `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` သို့မဟုတ် hop-by-hop header မဖြစ်ရပါ။ `none` ဖြင့် ဆက်သွယ်မှုများသည် သော့မလိုပါ။
- အပိုအငြိမ်ခေါင်းစီးများသည် node ၏ပုံမှန် `customHeaders` အသုံးပြုသည် (အခြားတွဲဖက်အသုံးပြုနိုင်သော node တိုင်းနှင့်တူညီသောအတည်ပြုချက်၊ auth headers များကိုထိုနေရာတွင်ခွင့်မပြုပါ)။

`PUT /api/provider-nodes/<id>` တူညီသော `customJson` လက်ခံပြီး node ၏လက်ရှိချိတ်ဆက်မှုတိုင်းတွင် `baseUrl` နှင့် config ကိုပြန်လည်ရေးသားသည်။ `customJson` ကို ချန်လှပ်ထားခြင်းသည် သိမ်းဆည်းထားသော config ကို ထိန်းပေးသည်။ `apiType` သို့ `chat` သို့မဟုတ် `responses` သို့ပြောင်းခြင်းသည် node နှင့် ၎င်း၏ချိတ်ဆက်မှုများမှဖယ်ရှားသည်။

ထို့နောက် ပုံမှန်အတိုင်း node သို့ ချိတ်ဆက်မှုတစ်ခုထည့်ပါ (`POST /api/providers` node id ဖြင့်) နှင့် `<prefix>/<model>` ဥပမာ `biz/assistant-v1` တောင်းဆိုပါ။ အဆုံးမှတ်သည် မော်ဒယ်စာရင်းကို မဖော်ပြသောကြောင့် မော်ဒယ်အိုင်ဒီများကို လက်ဖြင့်ထည့်ပါ။

## နမူနာပုံစံများကို တောင်းဆိုပါ။

ပုံစံများသည် ရိုးရိုး JSON ဖြစ်သည်။ စာကြောင်းတန်ဖိုးတွင် `{{placeholder}}` အမှတ်အသားများ ပါဝင်နိုင်သည်။ မည်သည့်အရာကိုမျှ အကဲဖြတ်ခြင်း သို့မဟုတ် လုပ်ဆောင်ခြင်းဖြစ်ပြီး အရာဝတ္ထုသော့များကို မည်သည့်အခါမျှ အစားထိုးခြင်းမပြုပါ။

| နေရာယူသည်။           | တန်ဖိုး                                                                                      |
| -------------------- | -------------------------------------------------------------------------------------------- |
| `{{prompt}}`         | နောက်ဆုံးအသုံးပြုသူမက်ဆေ့ခ်ျ၏ စာသား (စာသားအပိုင်းများကို လိုင်းအသစ်များဖြင့် ချိတ်ဆက်ထားသည်) |
| `{{messages}}`       | OpenAI ချတ်ဖော်မတ်ဖြင့် စကားဝိုင်း                                                           |
| `{{model}}`          | ပံ့ပိုးသူရှေ့ဆက်မပါဘဲ တောင်းဆိုထားသော မော်ဒယ်အိုင်ဒီ                                         |
| `{{stream}}`         | JSON စာရွက်စာတမ်းတစ်ခုဖြင့် အဆုံးမှတ်အဖြေကို အမြဲတမ်း `false` —                              |
| `{{request.<path>}}` | ဘာသာပြန်ဆိုချက် (OpenAI ချတ်ဖော်မတ်) တောင်းဆိုချက်၏ အကွက်တစ်ခု                               |

- တစ်နေရာတည်းတွင် အတိအကျရှိသော တန်ဖိုးသည် ၎င်း၏ JSON အမျိုးအစားကို ထိန်းထားသည် (`"{{messages}}"` array တစ်ခုဖြစ်လာသည် ) ပိုရှည်သောစာကြောင်းအတွင်း နေရာယူထားသည့်နေရာကို စာသားအဖြစ် ထည့်သွင်းထားသည်။
- မပြည့်စုံသော payload တစ်ခုကို ပေးပို့မည့်အစား HTTP 400 ဖြင့် တောင်းဆိုမှုကို ဘာမှမဖြေရှင်းနိုင်သော နေရာတစ်ခုသည် မအောင်မြင်ပါ။
- လမ်းကြောင်းများသည် အစက်အမှတ်အသားနှင့် ဂဏန်းအညွှန်းများ (`data.items[0].text`) ကို အသုံးပြုသည်။ `__proto__`၊ `prototype` နှင့် `constructor` သော့များနှင့် လမ်းကြောင်းများတွင် ငြင်းပယ်သည်။

## တုံ့ပြန်မှုများ

`responsePath` မှတန်ဖိုးသည် assistant reply ဖြစ်လာသည်- strings များဖြတ်သွားသည်၊ အခြား JSON တန်ဖိုးများကို နံပါတ်စဉ်တပ်ထားသည်။ ပျောက်ဆုံးနေသော သို့မဟုတ် `null` အကွက် သို့မဟုတ် JSON မဟုတ်သော ကိုယ်ထည်တစ်ခုသည် HTTP 502 ကို ပြန်ပေးသည်။ အထက်ရေစီးကြောင်း အမှားအယွင်း အခြေအနေများကို ဖြတ်သန်းသွားပါသည်။ တိုက်ရိုက်ကြည့်ရှုသည့်ဖောက်သည်များအတွက် OmniRoute JSON တုံ့ပြန်မှုတစ်ခုလုံးကို စောင့်မျှော်နေပြီး ၎င်းကို အကြောင်းအရာအပိုင်းတစ်ခုနှင့် ပြီးဆုံးသည့်အပိုင်းအဖြစ် ထုတ်လွှတ်သည်။ ၎င်းသည် တိုကင်လွှင့်ခြင်းမဟုတ်ပါ။ ကိရိယာခေါ်ဆိုမှုများနှင့် အသုံးပြုမှုအကွက်များကို မြေပုံမဖော်ပါ။

## ဘယ်တော့မှ ပြန်မကစားဘူး။

လုပ်ငန်းတောင်းဆိုမှုတစ်ခုသည် မအောင်မြင်သော်လည်း ဘေးထွက်ဆိုးကျိုးများ ရှိနိုင်သည်။ OmniRoute ထို့ကြောင့် တစ်ကြိမ် ပေးပို့သည် ။

- သယ်ယူပို့ဆောင်ရေး ပြန်လည်ကြိုးစားခြင်း မရှိသလို အောက်ပါအတိုင်း ပြန်ညွှန်းခြင်းမရှိပါ။
- အခြားချိတ်ဆက်မှုတွင် ထပ်၍မကြိုးစားပါနှင့် (အကောင့်ပြန်ယူခြင်း) — ပျက်ကွက်မှုသည် ယခင်အတိုင်း ပြန်ဖြစ်သွားပြီး ချိတ်ဆက်မှု အေးသွားခြင်းမရှိပါ။
- အချည်းနှီး သို့မဟုတ် မအောင်မြင်သော စာပြန်ခြင်းအတွက်ပင် နောက်တွဲပစ်မှတ်သို့ ပြန်မပြောင်းပါ။

ဖောက်သည်တောင်းဆိုချက်များနှင့် မော်ဒယ်များစွာကို ပြတ်သားစွာခေါ်ဆိုသော ပေါင်းစပ်အကန့်များသည် အဆုံးမှတ်ကို သီးခြားတောင်းဆိုနေဆဲဖြစ်သည်။

## node ကိုစမ်းသပ်ခြင်း။

ချိတ်ဆက်မှု၊ ချိတ်ဆက်မှုကို သိမ်းဆည်းခြင်း။** စမ်း** ခလုတ်နှင့် နောက်ခံကျန်းမာရေးစစ်ဆေးမှုများသည် အဆုံးမှတ်ကို ဘယ်တော့မှ မခေါ်ပါနှင့်။ ၎င်းတို့သည် သိမ်းဆည်းထားသော config ကိုသာ အတည်ပြုပြီး ချိတ်ဆက်မှုကို အတည်ပြု၍မရဟု သတင်းပို့ပါသည်။

`POST /api/provider-nodes/validate` with `"apiType": "custom-json"` and the node fields (`baseUrl`, `apiKey`, `customJson`, optional `customHeaders` and `modelId`) sends exactly one real request, with `ping` as the latest user text. It answers `{ "valid": true }` or the upstream status (never the upstream body).

## သိုလှောင်မှု

config ကို `provider_nodes.custom_json_config_json` (migration `240_provider_node_custom_json_config.sql`) တွင် သိမ်းဆည်းထားပြီး ချိတ်ဆက်မှုတစ်ခုစီ၏ `providerSpecificData.customJson` သို့ ကူးယူထားသည်။
