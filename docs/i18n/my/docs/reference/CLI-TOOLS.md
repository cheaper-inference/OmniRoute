## အလုပ်လုပ်ပုံ

```
CLI Code's / CLI Agents (အသုံးပြုမှု စီးဆင်းပုံ):
Claude / Codex / OpenCode / Cline / KiloCode / Continue / Hermes Agent / Goose / ...
           │
           ▼  (အားလုံးသည် OmniRoute သို့ ညွှန်သည်)
    http://YOUR_SERVER:20128/v1
           │
           ▼  (OmniRoute က သင့်တော်သော provider ထံ route လုပ်ပေးသည်)
    Anthropic / OpenAI / Gemini / DeepSeek / Groq / Mistral / ...

ACP Agents (ပြောင်းပြန် စတင်ပေးသည့် စီးဆင်းပုံ):
    Client request → OmniRoute → stdio/ACP မှတစ်ဆင့် CLI ကို စတင်သည် → response
```

**အကျိုးကျေးဇူးများ:**

- ကိရိယာအားလုံးကို စီမံရန် API key တစ်ခုတည်းသာ လိုအပ်ခြင်း
- dashboard တွင် CLI အားလုံး၏ ကုန်ကျစရိတ်ကို ခြေရာခံနိုင်ခြင်း
- ကိရိယာတိုင်းကို ပြန်လည် configure မလုပ်ဘဲ model ပြောင်းနိုင်ခြင်း
- Local နှင့် remote server များတွင် အလုပ်လုပ်ခြင်း (VPS, Docker, Akamai, Cloudflare Tunnel)

## `setup-*` ဖြင့် အလိုအလျောက်ပြင်ဆင်ပါ။

tool တစ်ခုစီ၏ config ကို လက်ဖြင့်ရေးရန် မလိုအပ်ပါ။ OmniRoute သည် ပံ့ပိုးထားသော CLI တစ်ခုလျှင် `setup-*` command တစ်ခုကို ပေးပို့သည်။** အသက်ရှင်** လည်ပတ်နေသည့် OmniRoute (ဒေသခံ သို့မဟုတ် အဝေးထိန်း) မှ မော်ဒယ်ကတ်တလောက်ကို သင့်စက်ပေါ်တွင် ကိရိယာ၏ ကိုယ်ပိုင် config ရေးသည်-

```bash
omniroute setup-codex        omniroute setup-claude       omniroute setup-opencode
omniroute setup-cline        omniroute setup-kilo         omniroute setup-continue
omniroute setup-cursor       omniroute setup-roo          omniroute setup-crush
omniroute setup-goose        omniroute setup-qwen         omniroute setup-aider
omniroute setup-5dive        omniroute setup-zed
omniroute setup-whycodes
```

တစ်ခုစီသည် `--remote <url> --api-key <key>` (အဝေးမှ OmniRoute နှင့် စက်တွင်းတူးလ်ကို configure လုပ်သည်)၊ `--dry-run` (စာမရေးဘဲ အစမ်းကြည့်ခြင်း) နှင့် `--port` လက်ခံသည်။ မော်ဒယ်အလိုအလျောက်ရှာဖွေမှုမရှိဘဲ ကိရိယာများ (Cline၊ Kilo ၊ Roo ၊ Goose ၊ Aider ၊ Qwen၊ 5dive ၊ WhyCodes) သည် `--model <id>` (အပြန်အလှန်လုပ်ဆောင်မှုမဟုတ်သော လုပ်ဆောင်မှုများအတွက် `--yes` ) ကို ယူသည်။ `setup-5dive` သည် `$HOME` အောက်တွင် မရေးထားသော စာရွက်တစ်ခုဖြစ်သည်- ၎င်းသည် သင်္ဘောအိမ်ရှင်တွင် အမြစ်ပိုင် auth ပရိုဖိုင်ကို ရေးသားခြင်းဖြင့် 5dive အေးဂျင့်ရေယာဉ်စုကို စီစဉ်သတ်မှတ်ပေးသောကြောင့် ၎င်းသည် `sudo` မှတဆင့် ပြန်လည်လုပ်ဆောင်ပြီး ၎င်း၏ အဝေးထိန်းမုဒ်တွင် ၎င်း၏ကိုယ်ပိုင် remote mode မရှိပါ။ မှန်ကန်သော env ထိုးသွင်းပြီး config လုံးဝမရေးထားသော CLI ဖွင့်ရန်၊ ယေဘုယျ `omniroute run <target>` launcher (claude, codex, aider, goose, opencode, qwen, gemini, whycodes — targets and aliases from `bin/cli/cli-manifest.mjs`); တူးလ်တစ်ခုစီ လောင်ချာများ `omniroute launch` (Claude ကုဒ်) နှင့် `omniroute launch-codex` (Codex) တို့သည် ကျန်ရှိနေပါသည်။ Gemini CLI သည် launch-only ဖြစ်သည်- ၎င်းသည် `omniroute run` ပစ်မှတ်တစ်ခုဖြစ်သော်လည်း `setup-*`/`configure` စာရွက်မရှိပါ။

> **ကိုးကားချက်အပြည့်အစုံ-** မာစတာဇယား — ကွန်မန်းတစ်ခုစီရေးထားသောအရာ၊ အလံတစ်ခုစီ၊ ဒေသန္တရနှင့်အဝေးထိန်း၊ နှင့် မည်သည့်ကိရိယာများသည် `/v1` နောက်ဆက်တွဲကို လိုချင်သည်—တွင် နေထိုင်သည်** [CLI ပေါင်းစည်းမှုများ](../guides/CLI-INTEGRATIONS.md)** .

### အဲဒါတွေကို ကွန်တိန်နာထဲမှာ ပြေးတယ်။

OmniRoute ကွန်တိန်နာအတွင်း လုပ်ဆောင်သည့် `setup-*` အမိန့်သည် ကွန်တိန်နာ၏ ကိုယ်ပိုင်အိမ်သို့ စာရေးသည်၊၊ မည်သည့် host CLI ကိုမျှ မဖတ်ဘဲ ကွန်တိန်နာနှင့်အတူ ပျောက်သွားသည်။ OmniRoute သည် ၎င်းကိုရှာဖွေပြီး စာရေးမည့်အစား ညွှန်ကြားချက်များဖြင့် `2` ထွက်သည်။ ရှေ့သို့ ပံ့ပိုးပေးထားသော နည်းလမ်းနှစ်ခု — — host ပေါ်တွင် CLI နှင့် `omniroute connect` ကွန်တိန်နာတွင် ထည့်သွင်းပါ သို့မဟုတ် config dirs ကို ချိတ်ပြီး `CLI_CONFIG_HOME` (ရေးဖွဲ့ `host` ပရိုဖိုင်) ကို သတ်မှတ်ပါ။ ကွန်တိန်နာ၏ကိုယ်ပိုင် CLIs သည် သင်အမှန်တကယ်ဆိုလိုသည့်အရာကို configure လုပ်သောအခါ `setup-*` command တစ်ခုစီ၊ အပေါင်း `omniroute configure` နှင့် `omniroute config set` `--allow-container-write` လက်ခံပါသည်။ `OMNIROUTE_ALLOW_CONTAINER_CONFIG_WRITE=true` ဆာဗာအတွက် အလားတူလုပ်ဆောင်သည်။ [Docker လမ်းညွှန် → host CLI ကိရိယာများ ပြင်ဆင်ခြင်းကို](../guides/DOCKER_GUIDE.md#configuring-host-cli-tools-when-omniroute-runs-in-docker) ကြည့်ပါ။

ဒက်ရှ်ဘုတ်ရဲ့** အဆုံးမှတ်ကို အသုံးပြုပါ။** (`POST /api/cli-tools/apply`) တူညီသောအစောင့်ကို တွန်းအားပေးသည်- အိမ်ရှင်အဖြေများမှ ပစ်မှတ်ကို ချည်နှောင်ထားခြင်းမပြုသော ကွန်တိန်နာတစ်ခုတွင် စာရေးပါ။**`422`** `containerEphemeralTarget: true` ဖြင့်၊ ဘေးကင်းသောအမှားစာသားနှင့် — host ချက်ပြုတ်နည်း (claude၊ codex၊ opencode၊ cline၊ kilo၊ continue) — a `hostSetupCommand` (ဥပမာ `omniroute setup-opencode`) အစား host ပေါ်တွင် run ရန်; ဘာမှ မရေးထားဘူး။ `dryRun: true` ကွန်တိန်နာမုဒ်တွင် ဆက်လက်အလုပ်လုပ်နေပြီး ဒစ်ကိုမထိဘဲ ပြန်လည်ပြင်ဆင်ထားသော + ပစ်မှတ်လမ်းကြောင်းကို ပြန်ပေးသည်။ အစမ်းကြည့်ရှုသည့်အကြောင်းအရာသည် ကူးယူရန် သို့မဟုတ် တင်သွင်းရန် အထောက်အထားရှိသော ဖွဲ့စည်းမှုတစ်ခုမဟုတ်ပါ။ မူလ tool/base URL/API key/model ထည့်သွင်းမှုများဖြင့် အသုံးပြုပါ၊ သို့မဟုတ် ညွှန်ပြထားသော လက်ခံသူဘက်ခြမ်း တပ်ဆင်မှုအမိန့်ကို အသုံးပြုပါ။ အကြိုကြည့်ရှုမှုခေါင်းစီးနှင့် စာချုပ်တောင်းဆိုမှုအတွက် [CLI ဖွဲ့စည်းမှုလုံခြုံရေးကို](../security/CLI-CONFIGURATION.md) ကြည့်ပါ။ ဤအပြုအမူသည် ရည်ရွယ်ချက်ရှိရှိနှင့် ဆုတ်ယုတ်မှုကို `tests/unit/api/cli-tools/apply-container-guard.test.ts` မှကာကွယ်သည် — အစောင့်ကိုဖယ်ရှားခြင်းဖြင့် 422 ကို ဘယ်သောအခါမှ မပြင်ပါ။

## တစ်ခုတည်းသော မှန်ကန်သည့် အရင်းအမြစ်

Entry တစ်ခုစီတွင် အောက်ပါ field များ ပါဝင်သည် (`src/shared/schemas/cliCatalog.ts` တွင် သတ်မှတ်ထားသည်)-

| Field                                           | Type                                                         | Description                                                  |
| ----------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `category`                                      | `"code" \| "agent"`                                          | Tool ပေါ်လာမည့် page                                         |

### လုပ်ဆောင်နိုင်စွမ်း အဆင့်များ (စာရင်းသွင်းထားမှု × ရှာဖွေသိရှိနိုင်မှု × ပြင်ဆင်သတ်မှတ်နိုင်မှု × စတင်အသုံးပြုနိုင်မှု)

Catalog တွင် စာရင်းသွင်းထားသော tool တိုင်းကို ရှာဖွေသိရှိနိုင်ခြင်း၊ ပြင်ဆင်သတ်မှတ်နိုင်ခြင်း သို့မဟုတ် စတင်အသုံးပြုနိုင်ခြင်း မရှိပါ။ အဆင့်တစ်ခုစီတွင်
ကြေညာသတ်မှတ်သည့် အရင်းအမြစ်တစ်ခုစီရှိပြီး drift test က ၎င်းတို့ကို တစ်ပြေးညီဖြစ်နေစေသည်-

| Tier                       | Meaning                                                                     | Declared in                                                       |
| -------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **စာရင်းသွင်းထားမှု**      | Dashboard catalog တွင် ပေါ်လာသည် (အမည်၊ vendor၊ docs၊ config type)          | `src/shared/constants/cliTools.ts` (`CLI_TOOLS`)                  |

| **ပြင်ဆင်သတ်မှတ်နိုင်မှု** | `omniroute configure <cli>` က ပံ့ပိုးသည် (setup recipe ရှိသည်)              | `bin/cli/cli-manifest.mjs` (`configure: true`)                    |

`bin/cli/cli-manifest.mjs` သည် CLI command
မျက်နှာပြင်များအတွက် တရားဝင် executable manifest ဖြစ်သည်- `run`၊ `configure` နှင့် shell-completion generator များအားလုံးသည် ၎င်းတို့၏
target စာရင်းများ၊ alias ဖြေရှင်းမှု (ဥပမာ `kilocode`/`kilo-code`/`kilo_cli` → `kilo`)
နှင့် `--model` flag ချိတ်ဆက်မှုတို့ကို ၎င်းမှ ရယူသည်။ Drift guard ဖြစ်သော
`tests/unit/cli/cli-manifest-drift.test.ts` သည် manifest၊ runtime
catalog၊ UI catalog နှင့် consumer မျက်နှာပြင်တိုင်း တစ်ပြေးညီရှိနေကြောင်း စစ်ဆေးအတည်ပြုသည် — အခြားမျက်နှာပြင်များတွင် မထည့်ဘဲ
မျက်နှာပြင်တစ်ခုတည်းတွင် target တစ်ခုထည့်ပါက တိတ်တဆိတ် ကွဲလွဲသွားမည့်အစား test suite ပျက်ကွက်မည်ဖြစ်သည်။

## 5. Batch Detection API

ကိရိယာရှာဖွေစစ်ဆေးမှုအားလုံးကို endpoint တစ်ခုတည်းမှတစ်ဆင့် စုစည်းထားသည်-

**`GET /api/cli-tools/all-statuses`**

- Auth: `requireCliToolsAuth(request)` (အခြား `/api/cli-tools/` route များနှင့် အတူတူ)
- ပြန်ပေးသည့်တန်ဖိုး- `Record<toolId, ToolBatchStatus>` (type: `src/shared/types/cliBatchStatus.ts`)
- နည်းဗျူဟာ- ကိရိယာအားလုံးအပေါ် `Promise.all` ကို အသုံးပြုပြီး ကိရိယာတစ်ခုစီအတွက် အချိန်ကန့်သတ်ချက် 5s သတ်မှတ်ထားသည်
- Cache: config file `mtime` ဖြင့် index ပြုလုပ်ထားသည့် memory အတွင်းရှိ LRU ဖြစ်သည်။ mtime ပြောင်းလဲသည့်အခါ Cache ကို ပယ်ဖျက်သည်။ Server ပြန်လည်စတင်သည့်အခါ reset လုပ်သည်။

ကိရိယာတစ်ခုစီအတွက် response ပုံစံ-

```ts
interface ToolBatchStatus {
  detection: {
    installed: boolean;
    runnable: boolean;
    version?: string;
    command?: string;
    commandPath?: string;
    reason?: string;
  };
  config: {
    status: "configured" | "not_configured" | "not_installed" | "unknown" | "other";
    endpoint?: string | null;
    lastConfiguredAt?: string | null;
  };
  error?: string; // သန့်စင်ထားပြီး stack trace များ မပါဝင်ပါ
}
```

```json
    "maxOutputTokens": 32768,
    "auth": {
      "type": "none"
    }
  }
]
```

**မှတ်ချက်များ:**

- `sk-your-omniroute-key` ကို OmniRoute တွင် ဖန်တီးထားသော API key ဖြင့် အစားထိုးပါ။

- `modelsUrl` field သည် `/api/v1/vscode/{token}/models` သို့ ညွှန်ပြသင့်သည်။
- client က စိတ်ကြိုက် header များကို ပံ့ပိုးသည့်အခါ ပုံမှန် `/v1` + Bearer header နည်းလမ်းကို ဦးစားပေးအသုံးပြုပါ။
- URL တွင် ထည့်သွင်းထားသော token များသည် လိုက်ဖက်ညီမှုအတွက် အရန်နည်းလမ်းတစ်ခုဖြစ်ပြီး editor log များ သို့မဟုတ် proxy history တွင် ပေါ်လာနိုင်သည်။

## 10. အတွင်းပိုင်း OmniRoute CLI

`omniroute` binary သည် ဆာဗာ၏ အသက်တာစက်ဝန်း၊ စနစ်ထည့်သွင်းမှု၊ ပြဿနာရှာဖွေစစ်ဆေးမှုနှင့် provider စီမံခန့်ခွဲမှုတို့အတွက် command များကို ပံ့ပိုးပေးသည်။ စတင်ဝင်ရောက်သည့်နေရာ- `bin/omniroute.mjs`။

```bash
omniroute                              # ဆာဗာကို စတင်ရန် (မူလ port 20128)
omniroute setup                        # အပြန်အလှန်တုံ့ပြန်နိုင်သော စနစ်ထည့်သွင်းမှု wizard
omniroute doctor                       # config၊ DB၊ port များနှင့် runtime ကို စစ်ဆေးရန်
omniroute providers list               # ပြင်ဆင်သတ်မှတ်ထားသော provider ချိတ်ဆက်မှုများ
omniroute providers test-all           # လက်ရှိအသုံးပြုနေသော ချိတ်ဆက်မှုတိုင်းကို စမ်းသပ်ရန်
omniroute reset-password               # admin password ကို ပြန်လည်သတ်မှတ်ရန်
omniroute logs                         # request log များကို ဆက်တိုက်ကြည့်ရှုရန်
omniroute health                       # အသေးစိတ်အခြေအနေ (breakers၊ cache၊ memory)
omniroute --version                    # version ကို ပြရန်
omniroute --help                       # command အားလုံးကို ပြရန်
```

### စနစ်ထည့်သွင်းခြင်းနှင့် အစပြုခြင်း

```bash
omniroute setup                        # အပြန်အလှန်တုံ့ပြန်နိုင်သော စနစ်ထည့်သွင်းမှု wizard
omniroute setup --non-interactive      # CI/automation mode (env var များနှင့် flag များကို ဖတ်သည်)
omniroute setup --password '<value>'   # admin password ကို တိုက်ရိုက်သတ်မှတ်ရန်
omniroute setup --add-provider \
  --provider openai \
  --api-key '<value>' \
  --test-provider                      # provider တစ်ခုကို တစ်ကြိမ်တည်းဖြင့် ထည့်သွင်းပြီး စမ်းသပ်ရန်
```

အပြန်အလှန်တုံ့ပြန်မှုမရှိသော စနစ်ထည့်သွင်းမှုအတွက် အသိအမှတ်ပြုထားသည့် environment variable များ-

| Var                 | ရည်ရွယ်ချက်                                                                      |
| ------------------- | -------------------------------------------------------------------------------- |
| `OMNIROUTE_API_KEY` | Provider API key (Commander `.env()` မှတစ်ဆင့် `--api-key` နှင့် ချိတ်ဆက်ထားသည်) |
| `DATA_DIR`          | OmniRoute data directory ကို အစားထိုးသတ်မှတ်ရန်                                  |

အခြားအပြန်အလှန်တုံ့ပြန်မှုမရှိသော input အားလုံးကို environment variable များအဖြစ်မဟုတ်ဘဲ flag များအဖြစ် ပေးပို့သည်-
`--password`, `--provider`, `--provider-name`, `--provider-base-url`, `--default-model`
(အထက်ပါ `omniroute setup` option များကို ကြည့်ပါ)။

### ပြဿနာရှာဖွေစစ်ဆေးမှု

```bash
omniroute doctor                       # config၊ DB၊ port များ၊ runtime၊ memory နှင့် liveness ကို စစ်ဆေးရန်
omniroute doctor --json                # စက်ဖြင့်ဖတ်ရှုနိုင်သော JSON
omniroute doctor --no-liveness         # HTTP health probe ကို ကျော်ရန်
omniroute doctor --host 0.0.0.0        # liveness host ကို အစားထိုးသတ်မှတ်ရန်
omniroute doctor --liveness-url <url>  # health endpoint URL အပြည့်အစုံကို အစားထိုးသတ်မှတ်ရန်
```

doctor သည် ဤစစ်ဆေးမှုများကို လုပ်ဆောင်သည်- `Config`, `Database`, `Storage/encryption`,
`Port availability`, `Node runtime`, `Native binary` (better-sqlite3),
`Memory` နှင့် `Server liveness`။ စစ်ဆေးမှုတစ်ခုခုသည် `fail` ဖြစ်ပါက non-zero ဖြင့် ထွက်သည်။

### Provider စီမံခန့်ခွဲမှု

```bash
omniroute providers available                       # OmniRoute provider catalog
omniroute providers available --search openai       # id/name/alias/category ဖြင့် catalog ကို စစ်ထုတ်ရန်
omniroute providers available --category api-key    # category ဖြင့် စစ်ထုတ်ရန် (api-key၊ oauth၊ free၊ ...)
omniroute providers available --json                # စက်ဖြင့်ဖတ်ရှုနိုင်သော JSON

omniroute providers list                            # ပြင်ဆင်သတ်မှတ်ထားသော provider ချိတ်ဆက်မှုများ
omniroute providers list --json

omniroute providers test <id|name>                  # ပြင်ဆင်သတ်မှတ်ထားသော ချိတ်ဆက်မှုတစ်ခုကို စမ်းသပ်ရန်
omniroute providers test-all                        # လက်ရှိအသုံးပြုနေသော ချိတ်ဆက်မှုတိုင်းကို စမ်းသပ်ရန်
omniroute providers validate                        # local အတွင်းသာ တည်ဆောက်ပုံဆိုင်ရာ စစ်ဆေးအတည်ပြုမှု
omniroute providers add <provider> --credential-env PROVIDER_KEY
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth <provider>                 # ရှိပြီးသား OAuth flow
omniroute providers edit <id|name> --default-model <model>
omniroute providers remove <id|name> --yes
```

`providers add/import/auth/edit/remove` သည် API ကို ဦးစားပေးအသုံးပြုသောကြောင့်
လက်ရှိ local သို့မဟုတ် remote context နှင့် အလုပ်လုပ်သည်။ Credential input အတွက်
`--credential-stdin` သို့မဟုတ် `--credential-env` ကို အသုံးပြုသင့်သည်။ `--dry-run --json` သည်
ဖုံးကွယ်ထားသော တည်ရှိမှု/ပုံသဏ္ဌာန်ကိုသာ အစီရင်ခံသည်။ `providers available` သည် OmniRoute catalog ကို ဖတ်သည်။
`providers list/test/test-all/validate` သည် ၎င်းတို့၏ local SQLite အပြုအမူကို ဆက်လက်ထိန်းသိမ်းထားပြီး
ဆာဗာ လည်ပတ်နေရန် မလိုအပ်ပါ။

စိတ်ကြိုက် OpenAI-compatible သို့မဟုတ် Anthropic-compatible node တစ်ခုအတွက် `omniroute nodes add` မှ
ပြန်ပေးသော node ID နှင့် credential များကို `omniroute keys add "$NODE_ID" --stdin` သုံး၍ ချိတ်ဆက်ပါ။
၎င်းအတွက် လည်ပတ်နေသော ဆာဗာတစ်ခုနှင့် လက်ရှိ context အတွက် management authentication လိုအပ်သည်။
CLI သည် node ကို စစ်ဆေးအတည်ပြုပြီး ၎င်း၏ endpoint setting များကို ချိတ်ဆက်မှုထဲသို့ ကူးယူပေးသည့်
`POST /api/providers` ကို အသုံးပြုသည်။ node ပျောက်ဆုံးနေခြင်း၊ authorization မအောင်မြင်ခြင်း သို့မဟုတ်
ဆာဗာ မရရှိနိုင်ခြင်းတို့ ဖြစ်ပါက local fallback credential မဖန်တီးဘဲ error ပြန်ပေးသည်။

`nodes add --base-url` သည် node endpoint ကို သတ်မှတ်ပေးသည်။ ၎င်းသည်
`OMNIROUTE_BASE_URL` ရှိ ဆာဗာလိပ်စာနှင့် သီးခြားဖြစ်သည်။ OpenAPI file များအတွက်
`omniroute openapi dump --format json --out ./openapi.json` ကို အသုံးပြုပါ။ global `--output`
သည် destination filename ကို မဟုတ်ဘဲ CLI display formatting ကို ရွေးချယ်သည်။

### ပြန်လည်ရယူခြင်းနှင့် ပြန်လည်သတ်မှတ်ခြင်း

```bash
omniroute reset-password                # admin password ကို ပြန်လည်သတ်မှတ်ရန် (ဤအမည်ဖြင့်လည်း ရသည်- omniroute-reset-password)
omniroute reset-encrypted-columns       # encrypted credential reset အတွက် သတိပေးချက် + dry-run ကို ပြရန်
omniroute reset-encrypted-columns --force  # SQLite ရှိ encrypted credential များကို အမှန်တကယ် null လုပ်ရန်
```

### Credential ထုတ်ယူခြင်း (⚠ သတိဖြင့် ကိုင်တွယ်ပါ)

```bash
omniroute auth export                                 # သတိပေးချက် + အတည်ပြုမှုအဆင့်ကို ပြရန် — DB ကို မဝင်ရောက်ပါ
omniroute auth export --force                          # ချိတ်ဆက်မှုအားလုံး၏ DECRYPTED credential များကို JSON အဖြစ် stdout သို့ ထုတ်ရန်
omniroute auth export --force --id <id>                 # ကိုက်ညီသော ချိတ်ဆက်မှုကိုသာ ထုတ်ရန်
omniroute auth export --force --format env               # OMNIROUTE_<PROVIDER>_<FIELD>=<value> လိုင်းများကို ထုတ်ရန်
omniroute auth export --force --out creds.json           # file တစ်ခုသို့ ရေးရန် (0600 permission ဖြင့် ဖန်တီးသည်)
```

`auth export` သည် **စက်တွင်းသီးသန့်** ဖြစ်သည် (SQLite ကို တိုက်ရိုက်ဖတ်ရှုခြင်းဖြစ်ပြီး HTTP route မရှိပါ)။ ထို့အပြင်
**စာသားအတိုင်း** `apiKey`/`accessToken`/`refreshToken`/`idToken` တန်ဖိုးများကို ရည်ရွယ်ချက်ရှိရှိ ဖော်ပြ/ရေးသားသည် — ၎င်းသည် ချို့ယွင်းချက်မဟုတ်ဘဲ
လုပ်ဆောင်ချက်တစ်ခုဖြစ်သည်။ `--force` မပါဘဲ database မှ မည်သည့်အရာကိုမျှ ဖတ်ရှုမည်မဟုတ်သကဲ့သို့ မည်သည့်အရာကိုမျှ စာဝှက်ဖြည်မည်မဟုတ်ပါ။ စာသားအတိုင်း တန်ဖိုးတစ်ခုခုကို မထုတ်မီ stderr တွင်
သတိပေး banner ကို အမြဲဖော်ပြသည်။ `STORAGE_ENCRYPTION_KEY` ကို
သတ်မှတ်ထားရန် လိုအပ်သည်။ စာဝှက်ဖြည်ရန် မအောင်မြင်သော field တစ်ခု (key အဟောင်း၊ ပျက်စီးနေသော ciphertext) ကို export တစ်ခုလုံး ရပ်တန့်ခြင်း သို့မဟုတ် အရင်းခံ error ကို ဖော်ထုတ်ခြင်းအစား
`<field>DecryptFailed: true` အဖြစ် အစီရင်ခံသည်။

### အခြား subcommand များ

အောက်ပါ command များသည် သီးခြားဖော်ပြထားခြင်းမရှိပါက လည်ပတ်နေသော OmniRoute server တစ်ခုရှိသည်ဟု ယူဆသည်-

```bash
omniroute status                       # လုပ်ဆောင်နေမှုအခြေအနေ အပြည့်အစုံ
omniroute logs                         # request log များကို ဆက်တိုက်ဖော်ပြရန် (--json, --search, --follow)
omniroute config list                  # စီစဉ်သတ်မှတ်ထားသော CLI tool များကို ဖော်ပြရန်

omniroute provider list                # ရရှိနိုင်သော provider များကို စာရင်းပြုစုရန် (providers list ၏ alias)
omniroute provider add                 # OmniRoute ကို tool တစ်ခုတွင် provider အဖြစ် မှတ်ပုံတင်ရန်
omniroute keys add | list | remove     # API key များကို စီမံရန်
omniroute models [provider]            # model များကို စာရင်းပြုစုရန် (--json, --search)
omniroute combo list | switch | create | delete

omniroute backup                       # config + DB ၏ snapshot ရယူရန်
omniroute restore                      # ယခင် snapshot တစ်ခုမှ ပြန်လည်ရယူရန်

omniroute health                       # အသေးစိတ် health အခြေအနေ (breaker များ၊ cache၊ memory)
omniroute quota                        # Provider quota အသုံးပြုမှု
omniroute cache                        # Cache အခြေအနေ
omniroute cache clear                  # semantic + signature cache များကို ရှင်းလင်းရန်

omniroute mcp status | restart         # MCP server အခြေအနေ / ပြန်လည်စတင်ရန်
omniroute a2a status | card            # A2A server အခြေအနေ / agent card

omniroute tunnel list | create | stop  # tunnel များကို စီမံရန် (cloudflare/tailscale/ngrok)
omniroute env show | get <k> | set <k> <v>  # env var များကို စစ်ဆေးရန် / သတ်မှတ်ရန် (ယာယီ)

omniroute test                         # Provider ချိတ်ဆက်နိုင်မှု အခြေခံစမ်းသပ်ချက်
omniroute update                       # update များ ရှိ/မရှိ စစ်ဆေးရန်
omniroute completion                   # shell completion ထုတ်လုပ်ရန်
```

## OmniRoute CLI ဖြင့် inference-key policy ကို စီမံရန်

အတည်ပြုထားသော management context ([Remote Mode](../guides/REMOTE-MODE.md) ကို ကြည့်ပါ) ကို အသုံးပြု၍
ရှိပြီးသား inference key တစ်ခုကို ၎င်း၏ ID ဖြင့် စစ်ဆေးရန် သို့မဟုတ် အပ်ဒိတ်လုပ်ရန်-

```bash
omniroute --output json keys policy show KEY_ID
omniroute keys policy set KEY_ID --unrestricted
omniroute --output json keys policy show KEY_ID
```

`--unrestricted` သည် `--model-access-mode all` ၏ alias တစ်ခုဖြစ်သည်။ ဤအပ်ဒိတ်သည်
model allowlist ကို ရှင်းလင်းသည်။ ၎င်းသည် scope များ၊ connection rule များ၊ blocked model များ၊ rate limit များ
နှင့် cost limit များကို မပြောင်းလဲဘဲ ထိန်းသိမ်းထားသောကြောင့် အခြား control များက request တစ်ခုကို ဆက်လက်ငြင်းပယ်နိုင်သည်။ အတိအလင်း
`--allowed-models ""` သတ်မှတ်ခြင်းသည်လည်း `all` ကို ရွေးချယ်သည်။ ခွင့်ပြုထားသော model မရှိသည့် restricted key အဖြစ် ဆက်ထားရန်
၎င်းကို `--model-access-mode restricted` နှင့် တွဲသုံးပါ။
ဗလာမဟုတ်သော ကော်မာဖြင့်ခွဲထားသည့် စာရင်းသည် အတိအလင်း သတ်မှတ်မထားပါက `restricted` ကို ရွေးချယ်သည်။
ဆန့်ကျင်နေသော `all` နှင့် ဗလာမဟုတ်သည့် allowlist ကို တွဲဖက်သတ်မှတ်ပါက request မပို့မီ ငြင်းပယ်ခံရမည်။

`--rate-limit 30` သည် တစ်မိနစ်လျှင် request အရေအတွက်ကို သတ်မှတ်ပြီး အခြားအချိန်
window များအတွက် rule များကို ထိန်းသိမ်းထားသည်။ `--max-cost 5` သည် အပတ်စဉ် cap ကို မပြောင်းလဲဘဲ နေ့စဉ် USD cap ကို ဖွင့်ပေးသည်။
`--max-cost 0` သည် နေ့စဉ် cap ကို ဖယ်ရှားပြီး လက်ရှိ usage-limit toggle
နှင့် အပတ်စဉ် cap ကို ထိန်းသိမ်းထားသည်။ ချန်လှပ်ထားသော policy field များသည် မပြောင်းလဲဘဲ ရှိနေမည်။ Rate ပြောင်းလဲမှုများသည်
လက်ရှိ policy ကို ဦးစွာဖတ်ရှုသည်။ key တစ်ခုတည်း၏ rate-limit array ကို တစ်ပြိုင်နက်တည်း ပြင်ဆင်ခြင်းမှ ရှောင်ကြဉ်ပါ။

Policy command များသည် အတည်ပြုထားသော `GET`/`PATCH /api/keys/{id}` ကို အသုံးပြုပြီး လက်ရှိအသုံးပြုနေသော
context နှင့် global `--api-key` option ကို လိုက်နာသည်။ JSON output တွင် policy field များသာ ပါဝင်ပြီး
သိမ်းဆည်းထားသော key သို့မဟုတ် ၎င်း၏ masked ဖော်ပြချက် မပါဝင်ပါ။ inference အတွက်သာဖြစ်သော credential သည်
management အပြောင်းအလဲများကို ခွင့်ပြုမပေးနိုင်ပါ။ 401/403 ဖြစ်ပေါ်ပါက management
credential နှင့် context ကို စစ်ဆေးရန်လိုသည်။ ၎င်းသည် local CLI-token သို့မဟုတ် salt ချို့ယွင်းမှုဖြစ်ကြောင်း အတည်မပြုပါ။
သီးခြား local authentication contract အတွက် [CLI Token](../security/CLI_TOKEN.md) ကို ကြည့်ပါ။
