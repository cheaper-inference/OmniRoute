OmniRoute ၏ လုပ်ဆောင်ပုံကို **ပြန်လည်ဖြန့်ကျက်ခြင်းမရှိဘဲ** ပြောင်းလဲပေးနိုင်သော Runtime toggles များ။
ဤနေရာတွင် ဖော်ပြထားသော flag တိုင်းကို [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts) တွင် သတ်မှတ်ထားပြီး ၎င်းသည် အမှန်တရား၏ တစ်ခုတည်းသော အရင်းအမြစ်ဖြစ်သည်။ dashboard နှင့် REST API နှစ်ခုလုံးသည် ထိုဖိုင်မှ ဖတ်ယူသောကြောင့် အောက်ပါဇယားကို ၎င်းနှင့် 1:1 ကိုက်ညီစေရန် ဖန်တီးထားပါသည်။

## Feature Flags များဆိုသည်မှာ

feature flag ဆိုသည်မှာ အမည်ပေးထားသော toggle (boolean သို့မဟုတ် enum) တစ်ခုဖြစ်ပြီး ၎င်း၏တန်ဖိုးကို runtime တွင် ပြောင်းလဲနိုင်ပြီး database တွင် သိမ်းဆည်းထားနိုင်ကာ process ကို ပြန်လည်ဖြန့်ကျက်ရန် မလိုအပ်ပါ။ flag တစ်ခုစီကို `key`, `label`, `description`, `category`, `defaultValue`, `type` နှင့် `requiresRestart` hint ပါဝင်သော `FeatureFlagDefinition` ဖြင့် ဖော်ပြထားပါသည်။

### ဖြေရှင်းမှု အစီအစဉ်

flag ၏ **ထိရောက်သောတန်ဖိုး** ကို [`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) မှ အောက်ပါဦးစားပေး (အမြင့်ဆုံးက အနိုင်ရသည်) ဖြင့် ဖြေရှင်းပေးပါသည်။

1.  **DB override** — `feature_flags` namespace အောက်ရှိ `key_value` table တွင် သိမ်းဆည်းထားသော တန်ဖိုး (dashboard သို့မဟုတ် REST API မှတစ်ဆင့် သတ်မှတ်သည်)။
2.  **Environment variable** — `process.env[<KEY>]`၊ သတ်မှတ်ထားပြီး ဗလာမဖြစ်ပါက။
3.  **Definition default** — `featureFlagDefinitions.ts` မှ `defaultValue`။

boolean flag တစ်ခု၏ ထိရောက်သောတန်ဖိုးသည် `"true"`, `"1"`, သို့မဟုတ် `"yes"` ဖြစ်ပါက ၎င်းကို **ဖွင့်ထားသည်** ဟု မှတ်ယူသည် ( `isFeatureFlagEnabled()` ကို ကြည့်ပါ)။

> [!NOTE]
> flag အများစုတွင် [`ENVIRONMENT.md`](./ENVIRONMENT.md) တွင် မှတ်တမ်းတင်ထားသော **တူညီသောအမည်** ရှိသော environment variable လည်း ရှိပါသည်။ flag ၏ DB override သည် ထို environment variable ထက် ဦးစားပေးပါသည်။ `requiresRestart: true` ပါသော flag ကို ချက်ချင်းသိမ်းဆည်းသော်လည်း process စတင်ချိန်တွင်သာ ပြန်လည်ဖတ်ရှုပါသည်။ ၎င်းကို toggle လုပ်ခြင်းဖြင့် dashboard တွင် **"Restart Server"** banner ပေါ်လာပါသည်။

ဈေးနှုန်းရှာဖွေမှုကို ဖြေလျှော့ပေးမည်မဟုတ်ပါ။ Enforcement နှင့် administrator report တို့သည်

## Flag များကို ဖွင့်/ပိတ်ခြင်း

### Dashboard

**Dashboard → Settings → Feature Flags** သို့ သွားပါ။
(`/dashboard/settings/feature-flags`)။ Grid
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
တွင် အောက်ပါလုပ်ဆောင်ချက်များကို ပံ့ပိုးထားသည်-

- Key သို့မဟုတ် ဖော်ပြချက်အလိုက် **ရှာဖွေခြင်း** နှင့် category အလိုက် **စစ်ထုတ်ခြင်း** (အပြင် synthetic
  **Requires Restart** view)။
- Boolean flag များအတွက် **toggle** နှင့် enum flag များအတွက် **dropdown**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)။
- Flag တစ်ခုစီအတွက် effective value မည်သည့်နေရာမှ ရရှိသည်ကို ပြသသည့်
  source badge — `DB`၊ `ENV` သို့မဟုတ် `DEF`။
- Override ကို ဖယ်ရှားရန် `DB`-sourced flag များအတွက်သာ ပြသသည့် **Reset**
  ခလုတ်နှင့် အောက်ခြေရှိ **Reset All Overrides** ခလုတ်။
- `requiresRestart` flag တစ်ခု ပြောင်းလဲသည့်အခါ **Restart Server** banner။

### REST API

လုပ်ဆောင်ချက်အားလုံးသည် route တစ်ခုတည်းမှတစ်ဆင့် လုပ်ဆောင်သည်-
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)။
Method တိုင်းအတွက် authenticate ပြုလုပ်ထားသော dashboard session လိုအပ်သည်
(မရှိပါက `401`)။

#### `GET /api/settings/feature-flags`

Flag တစ်ခုစီ၏ effective value၊ source နှင့် အနှစ်ချုပ်ကို ပြန်ပေးသည်။

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... flag 116 ခုလုံး
  ],
  "summary": {
    "total": 116,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Override တစ်ခုတည်းကို သတ်မှတ်ခြင်း သို့မဟုတ် ဖယ်ရှားခြင်း။ Body:
`{ key: string; value?: string }`။
`value` ကို ချန်လှပ်ထားပါက override ကို ဖယ်ရှားသည် (env / default ကို ပြန်လည်အသုံးပြုသည်)။

```bash
# DB override သတ်မှတ်ခြင်း
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Override ကို ဖယ်ရှားခြင်း ("value" မပါ)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Response တွင် အသစ်ပြောင်းလဲထားသော `effectiveValue`/`source`၊
`previousValue`/`previousSource` နှင့် `requiresRestart` တို့ကို ပြန်လည်ဖော်ပြသည်။
မသိရှိသော key များနှင့် သတ်မှတ်ထားသည့် အကန့်အသတ်အတွင်း မရှိသော enum
တန်ဖိုးများကို `400` ဖြင့် ပယ်ချသည်။

#### `DELETE /api/settings/feature-flags`

DB override အားလုံးကို တစ်ကြိမ်တည်း ဖယ်ရှားပြီး flag တိုင်းကို ၎င်း၏ env / default
တန်ဖိုးသို့ ပြန်လည်ထားသည်။ `{ cleared: <count>, message: "..." }` ကို ပြန်ပေးသည်။

> [!NOTE]
> `requiresRestart: true` ရှိသော flag များသည် process reload ပြုလုပ်ပြီးမှသာ
> အကျိုးသက်ရောက်သည်။ Dashboard ၏ restart flow သည် `POST /api/restart` ကို ခေါ်ပြီး
> server ပြန်လည်အလုပ်လုပ်သည်အထိ `GET /api/health/ping` ကို ထပ်ခါတလဲလဲ စစ်ဆေးသည်။

## အရေးပေါ် ဘတ်ဂျက် အရန်စနစ်

`OMNIROUTE_EMERGENCY_FALLBACK` (အမျိုးအစား `runtime`၊ မူလတန်ဖိုး `true`) သည်
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
ရှိ အရေးပေါ် အခမဲ့အရန်လမ်းကြောင်းကို ထိန်းချုပ်သည်။
၎င်းကို ဖွင့်ထားသည့်အခါ ဘတ်ဂျက်ကုန်သွားသော တောင်းဆိုမှုများကို ချက်ချင်း မအောင်မြင်စေဘဲ
အခမဲ့ အရန် provider/model သို့ လမ်းကြောင်းပြောင်းပေးသည်။ ဤလုပ်ဆောင်ချက်ကို ပိတ်ပြီး
ဘတ်ဂျက်ကုန်သွားသော တောင်းဆိုမှုများကို မအောင်မြင်စေရန် dashboard toggle၊ DB override
သို့မဟုတ် `OMNIROUTE_EMERGENCY_FALLBACK` environment variable မှတစ်ဆင့် ၎င်းကို
`false` (သို့မဟုတ် `0`) ဟု သတ်မှတ်ပါ။ (PRs #3741 / #3752 တွင် dashboard toggle
အဖြစ် ဖော်ပြထားသည်။)

ဤအရန်စနစ်မှ ပေးပို့သော response တွင်
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` ပါဝင်သဖြင့်
client သည် `X-OmniRoute-Provider` ကို ၎င်း၏ request နှင့် နှိုင်းယှဉ်စရာမလိုဘဲ
လမ်းကြောင်းပြောင်းထားကြောင်း သိနိုင်သည်။ အခြား response အားလုံးတွင် ဤ header မပါဝင်ပါ။
