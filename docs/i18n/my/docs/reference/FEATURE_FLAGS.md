OmniRoute ၏ လုပ်ဆောင်ပုံကို **ပြန်လည်ဖြန့်ကျက်ခြင်းမရှိဘဲ** ပြောင်းလဲပေးနိုင်သော Runtime toggles များ။
ဤနေရာတွင် ဖော်ပြထားသော flag တိုင်းကို [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts) တွင် သတ်မှတ်ထားပြီး ၎င်းသည် အမှန်တရား၏ တစ်ခုတည်းသော အရင်းအမြစ်ဖြစ်သည်။ dashboard နှင့် REST API နှစ်ခုလုံးသည် ထိုဖိုင်မှ ဖတ်ယူသောကြောင့် အောက်ပါဇယားကို ၎င်းနှင့် 1:1 ကိုက်ညီစေရန် ဖန်တီးထားပါသည်။

## Feature Flags များဆိုသည်မှာ

feature flag ဆိုသည်မှာ အမည်ပေးထားသော toggle (boolean သို့မဟုတ် enum) တစ်ခုဖြစ်ပြီး ၎င်း၏တန်ဖိုးကို runtime တွင် ပြောင်းလဲနိုင်ပြီး database တွင် သိမ်းဆည်းထားနိုင်ကာ process ကို ပြန်လည်ဖြန့်ကျက်ရန် မလိုအပ်ပါ။ flag တစ်ခုစီကို `key`, `label`, `description`, `category`, `defaultValue`, `type` နှင့် `requiresRestart` hint ပါဝင်သော `FeatureFlagDefinition` ဖြင့် ဖော်ပြထားပါသည်။

### ဖြေရှင်းမှု အစီအစဉ်

flag ၏ **ထိရောက်သောတန်ဖိုး** ကို [`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) မှ အောက်ပါဦးစားပေး (အမြင့်ဆုံးက အနိုင်ရသည်) ဖြင့် ဖြေရှင်းပေးပါသည်။

1.  **DB override** — `feature_flags` namespace အောက်ရှိ `key_value` table တွင် သိမ်းဆည်းထားသော တန်ဖိုး (dashboard သို့မဟုတ် REST API မှတစ်ဆင့် သတ်မှတ်သည်)။
2.  **Environment variable** — `process.env[<KEY>]`၊ သတ်မှတ်ထားပြီး ဗလာမဖြစ်ပါက။
3.  **Definition default** — `featureFlagDefinitions.ts` မှ `defaultValue`။

boolean flag တစ်ခု၏ ထိရောက်သောတန်ဖိုးသည် `"true"`, `"1"`, သို့မဟုတ် `"yes"` ဖြစ်ပါက ၎င်းကို **ဖွင့်ထားသည်** ဟု မှတ်ယူသည် ( `isFeatureFlagEnabled()` ကို ကြည့်ပါ)။

> [!NOTE]
> flag အများစုတွင် [`ENVIRONMENT.md`](./ENVIRONMENT.md) တွင် မှတ်တမ်းတင်ထားသော **တူညီသောအမည်** ရှိသော environment variable လည်း ရှိပါသည်။ flag ၏ DB override သည် ထို environment variable ထက် ဦးစားပေးပါသည်။ `requiresRestart: true` ပါသော flag ကို ချက်ချင်းသိမ်းဆည်းသော်လည်း process စတင်ချိန်တွင်သာ ပြန်လည်ဖတ်ရှုပါသည်။ ၎င်းကို toggle လုပ်ခြင်းဖြင့် dashboard တွင် **"Restart Server"** banner ပေါ်လာပါသည်။

| `CREDENTIAL_GATE_AUTH_DIAGNOSES_ONLY`     | ဘူလီယံ   | `false` | မကောင်းတဲ့အထောက်အထားများ (`upstream_auth_error`, `auth_missing`, `token_expired`, `token_refresh_failed`, `reauth_required`, `account_deactivated`, `auth_required`) ကက်ရှ်မအောင်မြင်သော အထောက်အထားစစ်ဆေးမှုတစ်ခုသည် ချိတ်ဆက်မှုကို ပိတ်ဆို့ထားသောကြောင့် ပေါင်းစပ်အထောက်အထားဂိတ်ကို ကျဉ်းမြောင်းစေသည်။ သယ်ယူပို့ဆောင်ရေးဆိုင်ရာ ရောဂါရှာဖွေမှုများ (`network_error`, `upstream_unavailable`, `upstream_rate_limited`) သည် အမြဲတမ်း အကျုံးမဝင်ဘဲ ဤအလံကို ပိတ်ထားသည့်တိုင် dispatch ကို မပိတ်ဆို့ပါနှင့်။ ဖွင့်ထားသောအခါတွင်၊ အခြားသော မခိုင်လုံသောရောဂါရှာဖွေမှုများ (မရေရာသောအမှားအယွင်းများ၊ ပံ့ပိုးမထားသော စုံစမ်းစစ်ဆေးမှုများနှင့် စာရိုက်မထားသော အချိန်ဇယားအမှားအယွင်းများ) ကိုလည်း ယာဉ်အသွားအလာကို ခွင့်ပြုပေးသည့် အမည်မသိအဖြစ် သတ်မှတ်သည်။ ပုံမှန်အားဖြင့် ပိတ်သည်- အခြား ကက်ရှ်လုပ်ထားသော စုံစမ်းစစ်ဆေးမှု အမှားများသည် ကက်ရှ် TTL (5 မိနစ်) အတွက် dispatch ကို ပိတ်ဆို့ဆဲဖြစ်သည်။ |

> [!NOTE]
> `INPUT_SANITIZER_BLOCK_THRESHOLD` နှင့် ၎င်း၏ အမွေအနှစ် alias `INJECTION_GUARD_BLOCK_THRESHOLD` `INJECTION_GUARD_MODE`၏ `block` မုဒ်ကို ချိန်ညှိပေးသည်၊ သို့သော် ၎င်းတို့သည် [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts) မှဖတ်သော လွင်ပြင်ပတ်ဝန်းကျင် ကိန်းရှင်များဖြစ်သည်၊ အင်္ဂါရပ်အလံများမဟုတ်ပါ- ၎င်းတို့တွင် DB ထပ်ရေးခြင်း နှင့် ဒက်ရှ်ဘုတ်ခလုတ်ဖွင့်ခြင်း မရှိပါ။ [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication) ကြည့်ပါ။

> [!NOTE]
> `Restart` ကော်လံသည် `requiresRestart: true` — ဖြင့် အလံများကို အမှတ်အသားပြုပြီး တန်ဖိုးသည် ချက်ချင်းတည်နေသော်လည်း လုပ်ငန်းစဉ် ပြန်လည်စတင်ပြီးနောက်မှသာ အကျိုးသက်ရောက်သည်။ Enum အလံများသည် ၎င်းတို့၏ခွင့်ပြုထားသောသတ်မှတ်မှုပြင်ပရှိ မည်သည့်တန်ဖိုးကိုမဆို ငြင်းပယ်သည် ( `setFeatureFlagOverride()` နှင့် REST `PUT` handler နှစ်ခုလုံးတွင် တရားဝင်အတည်ပြုထားသော ဆာဗာဘက်ခြမ်း)။

## အလံများပြောင်းခြင်း။

### ဒိုင်ခွက်

သို့သွားပါ။** ဒက်ရှ်ဘုတ် → ဆက်တင်များ → အင်္ဂါရပ် အလံများ** (`/dashboard/settings/feature-flags`) ။ ဇယားကွက် (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) သည်-

- **ရှာရန်** သော့ သို့မဟုတ် ဖော်ပြချက်အားဖြင့် လည်းကောင်း၊** ဇကာ** အမျိုးအစားအလိုက် (ပေါင်းစပ်ဓာတုပစ္စည်း** ပြန်လည်စတင်ရန် လိုအပ်သည်။** အမြင်)။
- တစ်** ပြောင်းရန်** boolean အလံများနှင့် a** ကျသည်** enum အလံများ (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`) အတွက်။
- တစ်** အရင်းအမြစ်တံဆိပ်** — `DB`၊ `ENV`၊ သို့မဟုတ် `DEF` — အလံတစ်ခုလျှင် ထိရောက်သောတန်ဖိုးသည် မည်သည့်နေရာတွင်ရှိသည်ကို ပြသသည်။
- တစ်** ပြန်လည်သတ်မှတ်ပါ။** ထပ်ရေးချရန် ခလုတ် ( `DB` -sourced အလံများအတွက်သာ ပြထားသည်)၊ နှင့် a** ဖျက်စီးမှုများအားလုံးကို ပြန်လည်သတ်မှတ်ပါ။** အောက်ခြေတွင်ခလုတ်။
- တစ်** ဆာဗာကို ပြန်လည်စတင်ပါ။** `requiresRestart` အလံကိုပြောင်းသောအခါနဖူးစည်း။

### REST API

လည်ပတ်မှုအားလုံးသည် လမ်းကြောင်းတစ်ခုမှ ဖြတ်သန်းသွားသည်- [`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts). နည်းလမ်းတိုင်းသည် စစ်မှန်ကြောင်းသက်သေပြထားသော ဒက်ရှ်ဘုတ်ဆက်ရှင် (`401` မဟုတ်လျှင်) လိုအပ်သည်။

လော့ဂ်အင်ပိတ်ထားသည် (`requireLogin=false`) ဖြင့် ကာကွယ်ထားသောအလံများမှလွဲ၍ လမ်းကြောင်းပွင့်သည်- လုံခြုံရေးအမျိုးအစားရှိ အလံတိုင်းနှင့် `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`၊ `OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS`, `MITM_DISABLE_TLS_VERIFY`, `OMNIROUTE_MCP_ENFORCE_SCOPES` နှင့် `SKILLS_SANDBOX_NETWORK_ENABLED` (`isProtectedFeatureFlag()` in `protectedFeatureFlags.ts`)။ ၎င်းတို့ထဲမှ တစ်ခုတွင် `PUT` နှင့် `DELETE` တစ်ခုတွင် DB အစားထိုးမှုတစ်ခု ပါရှိနေချိန်တွင်၊ ဒက်ရှ်ဘုတ် စက်ရှင်တစ်ခု၊ `manage` -scope API သော့၊ စာရေးစကေး သို့မဟုတ် ထို့ထက် ပိုမြင့်သော `oma_` ဝင်ရောက်ခွင့် တိုကင်တစ်ခု သို့မဟုတ် CLI တိုကင် သို့မဟုတ် စက်တွင်း-ဝန်ဆောင်မှု တိုကင်ကို လှည့်ပတ်မှ ပေးပို့ရန် လိုအပ်ပါသည်။ လမ်းကြောင်းသည် စက်ရှင် သို့မဟုတ် `manage` -scope ကီးတစ်ခုသာ လက်ခံသည့် လော့ဂ်အင်ဝင်ခြင်းထက် ကျယ်ပြန့်သည်။

#### `GET /api/settings/feature-flags`

အလံတိုင်းကို ၎င်း၏ထိရောက်သောတန်ဖိုး၊ အရင်းအမြစ်နှင့် အနှစ်ချုပ်ဖြင့် ပြန်ပေးသည်။

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 126 flags
  ],
  "summary": {
    "total": 126,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

တစ်ခုတည်းသော override ကို သတ်မှတ် သို့မဟုတ် ဖယ်ရှားပါ။ ကိုယ်ထည်- `{ key: string; value?: string }` `value` ကို ချန်လှပ်ခြင်းသည် override ကို ဖယ်ရှားသည် (env / default ကို ပြန်လည်ရယူခြင်း)။

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

တုံ့ပြန်မှုသည် `effectiveValue`/`source`၊ `previousValue`/ `previousSource` နှင့် `requiresRestart` အသစ်တို့ကို ပဲ့တင်ထပ်သည်။ အမည်မသိသော့များနှင့် ပြင်ပမှ enum တန်ဖိုးများကို `400` ဖြင့် ပယ်ချပါသည်။

#### `DELETE /api/settings/feature-flags`

ရှင်းလင်းသည်။** အားလုံး** DB သည် အလံတိုင်းကို ၎င်း၏ env / ပုံသေတန်ဖိုးသို့ ပြန်ပေးသည်။ `{ cleared: <count>, message: "..." }` ပြန်ပေးသည်။

> [!NOTE]
> လုပ်ငန်းစဉ်ပြန်လည်စတင်ပြီးနောက်တွင် `requiresRestart: true` ပါသောအလံများသည် အသက်ဝင်ပါသည်။ ဒက်ရှ်ဘုတ်၏ ပြန်လည်စတင်သည့် စီးဆင်းမှုသည် `POST /api/restart` ခေါ်ဆိုပြီး ဆာဗာကို အရန်သိမ်းသည်အထိ `GET /api/health/ping` စစ်တမ်းကောက်ယူသည်။

## အရေးပေါ် ဘတ်ဂျက် အရန်စနစ်

`OMNIROUTE_EMERGENCY_FALLBACK` (အမျိုးအစား `runtime`၊ မူလတန်ဖိုး `true`) သည်
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
ရှိ အရေးပေါ် အခမဲ့အရန်လမ်းကြောင်းကို ထိန်းချုပ်သည်။
၎င်းကို ဖွင့်ထားသည့်အခါ ဘတ်ဂျက်ကုန်သွားသော တောင်းဆိုမှုများကို ချက်ချင်း မအောင်မြင်စေဘဲ
အခမဲ့ အရန် provider/model သို့ လမ်းကြောင်းပြောင်းပေးသည်။ ဤလုပ်ဆောင်ချက်ကို ပိတ်ပြီး
ဘတ်ဂျက်ကုန်သွားသော တောင်းဆိုမှုများကို မအောင်မြင်စေရန် dashboard toggle၊ DB override
သို့မဟုတ် `OMNIROUTE_EMERGENCY_FALLBACK` environment variable မှတစ်ဆင့် ၎င်းကို
`false` (သို့မဟုတ် `0`) ဟု သတ်မှတ်ပါ။ (PRs #3741 / #3752 တွင် dashboard toggle
အဖြစ် ဖော်ပြထားသည်။)

ဤအရန်စနစ်မှ ပေးပို့သော response တွင်
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` ပါဝင်သဖြင့်
client သည် `X-OmniRoute-Provider` ကို ၎င်း၏ request နှင့် နှိုင်းယှဉ်စရာမလိုဘဲ
လမ်းကြောင်းပြောင်းထားကြောင်း သိနိုင်သည်။ အခြား response အားလုံးတွင် ဤ header မပါဝင်ပါ။
