> **အသုံးပြုသူများအတွက်**: ရိုးရှင်းသော လမ်းညွှန်ကို ရှာဖွေနေပါသလား။ အခမဲ့ AI ရယူရန် အဆင့်ဆင့်ညွှန်ကြားချက်များအတွက် [အခမဲ့အဆင့်များ လမ်းညွှန်](../getting-started/FREE-TIERS-GUIDE.md) ကို ကြည့်ပါ။

> **နောက်ဆုံး သုတေသနပြုခဲ့သည့်ရက်:** 2026-06-17 — အခမဲ့အဆင့် quota နှင့် ToS အားလုံးကို ပြန်လည်ဆန်းသစ်ထားသည့် provider တစ်ခုချင်းအလိုက် ဝဘ်သုတေသန (တရားဝင်စာရွက်စာတမ်းများ + နောက်ဆုံး 7 ရက်အတွင်း သတင်းများ၊ ဆန့်ကျင်ဘက်စိစစ်အတည်ပြုမှုပါဝင်သော agent 50 ခုဖြင့် စစ်ဆေးမှု)။ **တစ်စိတ်တစ်ပိုင်း ပြန်လည်စစ်ဆေးသည့်ရက် 2026-09-02** (`gemini`, `ollama-cloud`, `groq`, `nara`, `mistral` — အောက်ပါ ရက်စွဲပါမှတ်ချက်ကို ကြည့်ပါ)။
> **အမှန်တရားအတွက် အဓိကရင်းမြစ် (catalog):** `open-sse/config/freeModelCatalog.ts` (MODEL တစ်ခုချင်းစီအလိုက် budget များ၊ pool ထပ်နေမှုများကို ဖယ်ရှားထားသည်)။ အောက်ပါ token-budget ကိန်းဂဏန်းများသည် တိုက်ရိုက်ဝဘ်သုတေသနမှ ရရှိထားပြီး **ခန့်မှန်းခြေ** ဖြစ်သည် — [နည်းလမ်းနှင့် သတိပြုရန်အချက်များ](#methodology--caveats) ကို ကြည့်ပါ။

## TL;DR — OmniRoute သည် အခမဲ့ inference ပမာဏမည်မျှကို အမှန်တကယ် စုစည်းပေးသနည်း။

ဤကိန်းဂဏန်းများသည် catalog တစ်လျှောက်ရှိ သီးခြား third-party အကောင့်များနှင့် အရည်အချင်းပြည့်မီမှုဆိုင်ရာ သတ်မှတ်ချက်များကို ဖော်ပြသည်။ OmniRoute က ဤ budget ကို ပေးအပ်ခြင်းမဟုတ်ပါ။ လိုအပ်သော အကောင့်များ သို့မဟုတ် အထောက်အထားများကို သင်ကိုယ်တိုင် ရယူပြီး အရည်အချင်းပြည့်မီသော provider များကို ချိတ်ဆက်ကာ ၎င်းတို့၏ ကန့်သတ်ချက်များကို လိုက်နာရမည်။ အရည်အချင်းပြည့်မီသော route မရှိသည့် အသစ်ထည့်သွင်းမှုတွင် သုညအထိ ဖြစ်နိုင်ခြင်းအပါအဝင် အမှန်တကယ် အသုံးပြုနိုင်သော capacity သည် ပိုနည်းနိုင်သည်။ `tos: avoid` ဟု မှတ်သားထားသော provider များကို ပုံမှန်အားဖြင့် အလိုအလျောက် routing မှ ဖယ်ထုတ်ထားသည်။

**2026-10-08 တွင် စစ်ဆေးပြီး:** [Cerebras](https://www.cerebras.ai/pricing) သည် ငွေပေးချေမှုနည်းလမ်းတစ်ခု လိုအပ်ပြီး ရက် 30 ပြည့်လျှင် သက်တမ်းကုန်ဆုံးမည့် တစ်ကြိမ်သုံး $5 ပရိုမိုးရှင်း credit ကို ပေးသည်။ [Gemini](https://ai.google.dev/gemini-api/docs/rate-limits) သည် project/model/tier အလိုက် rate limit များကို ထုတ်ပြန်ထားသော်လည်း အရေအတွက်သတ်မှတ်ထားသော လစဉ်အဓိကကိန်းဂဏန်းတွင် ဆက်လက်မပါဝင်ပါ။

## 2026-10-18 SiliconFlow အခမဲ့ model ပြင်ဆင်ချက် (#17028)

ထုတ်ပြန်ထားသော token တစ်ခုချင်းစီအလိုက် အပေါင်းတန်ဖိုးရှိသည့် ဈေးနှုန်းများပါဝင်သော SiliconFlow ထိပ်တန်း model ဆယ်ခုကို `recurring-uncapped` အခမဲ့အသုံးပြုခွင့်အဖြစ် မှားယွင်းထည့်သွင်းဖြန့်ချိခဲ့သည်။ ထိုအတန်းဆယ်ခုကို static catalog မှ **ဖယ်ရှားပြီး** ဖြစ်သဖြင့် ယခု catalog တွင် **entry 467 ခု** ရှိသည်။ SiliconFlow သည် static စုစုပေါင်းကိန်းဂဏန်းများတွင် ခြွင်းချက်မရှိသော အခမဲ့ model အတန်း သို့မဟုတ် အမြဲတမ်းအခမဲ့ provider တစ်ခုအဖြစ် ပါဝင်ပံ့ပိုးခြင်း မရှိတော့ပါ။

ယင်းသည် SiliconFlow တွင် အခမဲ့ model လုံးဝမရှိဟု **မဆိုလိုပါ**။ အခမဲ့ model များသာ ထည့်သွင်းမှုနှင့် Free badge တို့အတွက် ယခုအခါ **တိုက်ရိုက် provider model payload မှ model တစ်ခုချင်းစီအတွက် အတည်ပြုနိုင်သော အထောက်အထား** လိုအပ်သည်။ ဥပမာ၊ အခမဲ့ဖြစ်ကြောင်း ရှင်းလင်းစွာညွှန်ပြထားသည့် boolean marker သို့မဟုတ် token ဈေးနှုန်းနှစ်ခုစလုံး သုညဖြစ်ခြင်းတို့ဖြစ်သည်။ ပေးချေရသည့် model ဖြစ်ကြောင်း ရှင်းလင်းစွာညွှန်ပြထားသော flag သို့မဟုတ် အပေါင်းတန်ဖိုးရှိသည့် ကိန်းဂဏန်းဈေးနှုန်းတစ်ခုခုသည် အခမဲ့ဖြစ်နိုင်ကြောင်း အကောင်းမြင်ဖော်ပြထားသော marker ထက် ဦးစားပေးသည်။ ရရှိနိုင်သော တိုက်ရိုက်အထောက်အထားမရှိသည့် model ကို အခမဲ့ဟု **မယူဆပါ**။ အကောင့်အသစ်အတွက် တစ်ကြိမ်သာရရှိသည့် credit သည် ထပ်တလဲလဲရရှိသော အခမဲ့ခွင့်ပြုချက်ဖြစ်ကြောင်း သက်သေမပြနိုင်ပါ။ လက်ရှိ provider API က model အဆင့်ရှိ ယုံကြည်စိတ်ချရသော ဈေးနှုန်းအချက်အလက်ကို မပေးနိုင်ပါက routing မလုပ်မီ provider console တွင် အတည်ပြုပါ။ ဤသတိထားသည့် ရွေးချယ်မှုက အခမဲ့ model များသာ ထည့်သွင်းခြင်းနှင့် အလိုအလျောက်ပေါင်းစပ်မှုများမှတစ်ဆင့် မမျှော်လင့်ထားသော ကုန်ကျစရိတ်များ ဖြစ်ပေါ်ခြင်းကို တားဆီးပေးသည်။

အောက်ပါ သမိုင်းမှတ်တမ်း provider ဇယားသည် လက်ရှိရရှိနိုင်မှုအတွက် ကတိပြုချက်မဟုတ်ပါ။ ၎င်း၏ ယခင် SiliconFlow အကန့်အသတ်မရှိ/10-model entry ကို ရည်ရွယ်ချက်ရှိရှိ မထည့်သွင်းထားခြင်းမှာ အဆိုပါ entry က အတည်ပြုပြီးဖြစ်သည့် ထပ်တလဲလဲရရှိသော အခမဲ့ခွင့်ပြုချက်ကို ကိုယ်စားမပြုတော့သောကြောင့် ဖြစ်သည်။

## နည်းစနစ်နှင့် သတိပေးချက်များ

- နံပါတ်များ** အထက်ပိုင်း ခန့်မှန်းချက်** ဝန်ဆောင်မှုပေးသူတိုင်း၏ မှတ်တမ်းတင်ထားသော အခမဲ့အဆင့် ကန့်သတ်ချက်များမှ** ၂၀၂၆-၀၆-၁၇** ဝဘ်သုတေသနဖြင့် စုစည်းထားသည်။ ကိန်းဂဏန်းတစ်ခုအပေါ်မမှီခိုမီ အခမဲ့အဆင့်များ အဆက်မပြတ် — ပြန်လည်စစ်ဆေးပါ။
- **ဝင်ခွင့်လက်မှတ်က ဘာအတွက်လဲ။** အတန်းတစ်ခုချင်းယုံကြည်မှုအဆင့်သတ်မှတ်ချက်ကို ထည့်သွင်းခြင်းမရှိပါ၊ API အထက်ဖော်ပြပါပုံတိုင်းကို တူညီသော၊ မဖော်ပြထားသော အရည်အသွေးတစ်ခုအဖြစ် အထက်ဖော်ပြပါပုံတိုင်းကို — နှင့် မဆက်ဆံပါ။ အချက်အလက်နှစ်ခုသည် ကွဲပြားသည်၊ အကြောင်းမှာ ၎င်းတို့ကို ကောက်ချက်ချမည့်အစား လက်ဖြင့် ကောက်နှုတ်ထားခြင်းဖြစ်သည်- 44 သည် သီးခြားမှတ်တမ်းတင်ထားသော hard stop (၎င်းတို့ထဲမှ 39 ခုသည် နေ့စဥ်ထောက်ပံ့ကြေးတစ်ခုစီပါဝင်သည့် xKiro အတန်း) နှင့် 21 entry သည် ချက်ခြင်းလေ့ကျင့်ကြောင်းထုတ်ဖော်ချက်ပါရှိသည်။ `hardStopGuaranteed` အခမဲ့ခွင့်ပြုငွေထက်ကျော်လွန်ပါက တောင်းဆိုချက်ကို တိတ်တဆိတ်ငွေတောင်းခံမည့်အစား ဝန်ဆောင်မှုပေးသူ၏ကိုယ်ပိုင်စည်းကမ်းချက်များဖြင့် သတ်မှတ်သည့်အခါတွင်၊ ထည့်သွင်းမှုဘေးရှိ မှတ်ချက်ရှိရင်းမြစ်နှင့်အတူ၊ ၎င်းသည် `true` တွင် မည်သည့်အခါမှ ပုံသေမဟုတ်ပါ၊ နှင့် မည်သူမျှ စစ်ဆေးမထားသော ဝင်ခွင့်သည် သတ်မှတ်မထားပါ။ ထို့ကြောင့် ပျောက်ဆုံးနေသော ရပ်တန့်နေသော အလံသည် "မတည်မငြိမ်" ဆိုသည်မှာ "သင့်ကို ငွေတောင်းခံရန် မသိခြင်း" မဟုတ်ပါ။**STRICT မုဒ်** (opt-in `freeAccessPolicy=strict` routing guard) သည် အလံကိုင်ဆောင်ထားသော အရာများကိုသာ ယုံကြည်သည်၊ အခြားအခမဲ့အဆင့်တိုင်းကို `no-hard-stop` အဖြစ် ဖယ်ထုတ်ထားသည် ( `open-sse/services/autoCombo/strictZeroCostFilter.ts` ကြည့်ပါ)။ အစောင့်သည် ရေကန်တစ်ခုကို စစ်ထုတ်သောအခါ၊ အော်ပရေတာ-မြင်ရသော မှတ်တမ်းသည် ဖယ်ထုတ်ထားသော အရေအတွက်နှင့် ၎င်း၏ `no-hard-stop` မျှဝေမှု နှစ်ခုလုံးကို အစီရင်ခံသည်။
- `estMonthlyFreeTokens` = ထပ်တလဲလဲ လစဉ် တိုကင်များသာ။** တစ်ကြိမ်သာ အကောင့်ဖွင့်ခြင်း ခရက်ဒစ်များသည် ထပ်တလဲလဲ မရှိပါ။** 0 အဖြစ် ရေတွက်ပါ။ ရပ်ဆိုင်းလိုက်သော အဆင့်များသည်လည်း 0 ဖြစ်သည်။
- နေ့စဉ်တိုကင်ထုပ် → `monthly = daily × 30`။ RPD သာလျှင် → `RPD × ~800 output tokens × 30` မှတ်တမ်းတင်ထားသည်။ RPM/TPM သာလျှင် (နေ့စဉ်ထုပ်) → မရှိပါ။** uncapped** (အောက်တွင်ကြည့်ပါ)။
- **အမြဲတမ်းအခမဲ့ဖြစ်သော်လည်း တိုကင်ထုပ်ကို မထုတ်ဝေပါ။** (`glm-cn`, `tencent`, `baidu`, `kilo-gateway`, `opencode-zen`, `gemini`, `ollama-cloud`) : ၎င်းတို့သည် အမှန်တကယ် ထပ်တလဲလဲ အခမဲ့ သုံးစွဲခွင့် ဖြစ်သည်၊ rate/concurrency-limited. ၎င်းတို့အား `recurring-uncapped` နှင့် အမျိုးအစားခွဲပါသည်။** သူတို့ကို ဘယ်တော့မှ မပေါင်းပါနဲ့။** — မြှောက်ခြင်း `RPM × 24/7 × 30d` သည် စိတ်ကူးယဉ်မျက်နှာကျက် (ကျွန်ုပ်တို့ငြင်းဆိုထားသော ငွေကြေးဖောင်းပွမှု) ကို ဖြစ်ပေါ်စေပါသည်။ ၎င်းတို့ကို စာရင်းပြုစုထားသောကြောင့် ၎င်းတို့တည်ရှိနေကြောင်း သင်သိပါသည်။
- **အပ်ငွေ-သော့ဖွင့်ခြင်း မြှင့်တင်ခြင်း-** အခမဲ့ခွဲတမ်းကို အပြီးတိုင်တိုးစေမည့် တစ်ကြိမ်သာ ငွေဖြည့်သွင်းခြင်း (OpenRouter: $10 → 1000 req/day ≈ +24M/mo)။ သီးခြားကိန်းဂဏန်းအဖြစ် အစီရင်ခံထားပြီး၊ တည်ငြိမ်သော ခေါင်းစီးသတင်းမှ လွတ်ထွက်သွားသည်။
- **အရည်အချင်းပြည့်မီမှု-ကန့်သတ်ခွဲတမ်း** (`eligibilityGate: "regional-identity"`) ဒေသအလိုက် အထောက်အထား စစ်ဆေးပြီးနောက်မှသာ ဖွင့်သည့် အမှန်တကယ် ထပ်တလဲလဲ ခွဲတမ်းတစ်ခု (ယနေ့ ပြည်မကြီး-တရုတ် အမည်ရင်း အတည်ပြုခြင်း)။ တူညီသော pool-dedupe စည်းမျဉ်းဖြင့် သီးခြားရုပ်ပုံ (`gatedRecurringTokens`) သို့ ရေတွက်ပြီး တည်ငြိမ်သော ခေါင်းစီးတွင် ဘယ်သောအခါမှ မရေတွက်ပါ။ စစ်အစိုးရ (`freeType`) သည် မပြောင်းလဲသောကြောင့် routing သည် မပြောင်းလဲပါ။
- **အထောက်အထားသင်တန်းများ။** စည်းမျဉ်း- ကတ်တလောက်ရှိ နံပါတ်တစ်ခုသည် ထည့်သွင်းမှုဘေးရှိ `// evidence:` မှတ်ချက်တွင် ၎င်း၏အရင်းအမြစ်ကို ကိုးကား၍ — `public-page` (မည်သူမဆိုဖတ်ရှုနိုင်သော ဝန်ဆောင်မှုပေးသူစာမျက်နှာ)၊ `api-public` (ဝန်ဆောင်မှုပေးသူ၏ အထောက်အထားမခိုင်လုံသောအဆုံးမှတ်၊ ဥပမာ NaraRouter၏အများပြည်သူအစီအစဥ် router.bynara.id) သို့မဟုတ် `console-verified <date> por <who>` (ကိန်းဂဏန်းသည် အကောင့်ကွန်ဆိုးလ်အတွင်းတွင်သာ မြင်နိုင်သည်)၊ မြင်သူနှင့် မှတ်ချက်များကို မှတ်တမ်းတင်သည့်အခါတွင် မှတ်ချက်များနှင့် စာမျက်နှာကို ဖုံးထားသည်ဟု ဆိုသည်။ ယနေ့အခြေအနေ- 2026-09-02 တွင် ပြန်လည်စစ်ဆေးခဲ့သော လုပ်ကွက်ငါးခု (`gemini`, `groq`, `mistral`, `ollama-cloud`, `nara`); 2026-09-02 တွင် ပြန်လည်စာရင်းစစ်ခြင်းကို ကြိုတင်လုပ်ဆောင်ထားသည့် စာရွက်စာတမ်းများကို မထိမချင်း အစောပိုင်းသုတေသနကို အမွေဆက်ခံပါသည်။ တစ်ခုခု** အသစ် သို့မဟုတ် ပြောင်းလဲထားသည်။** သက်သေမှတ်ချက်မပါဘဲ နံပါတ်သည် bug တစ်ခုဖြစ်သည်။ ယနေ့တွင် `mistral` သာလျှင် console-verified ဖြစ်သည်။

## ကျွန်ုပ်တို့၏ နံပါတ်သည် အခြား aggregator များ၏ နံပါတ်များထက် အဘယ်ကြောင့် ပိုနည်းသနည်း

ဤနယ်ပယ်ရှိ "တစ်လလျှင် အခမဲ့ token များ" ဟူသော ကိန်းဂဏန်းအများစုသည် model တစ်ခုချင်းစီ၏ label များကို ပေါင်းထားခြင်းဖြစ်သည်။ ကျွန်ုပ်တို့၏ ကိန်းဂဏန်းမှာမူ ရည်ရွယ်ချက်ရှိရှိ ထိုသို့မဟုတ်ပါ-

- **မျှဝေသုံးစွဲသည့် pool တစ်ခုစီကို တစ်ကြိမ်သာ ရေတွက်သည်။** Mistral ၏ အခမဲ့အစီအစဉ်သည် organization တစ်ခုလျှင် တစ်လ 1B သုံးစွဲခွင့်တစ်ခုဖြစ်သည်။ ၎င်းကို model ငါးခုအောက်တွင် စာရင်းသွင်းထားခြင်းကြောင့် 5B ဖြစ်မသွားပါ။ Model တစ်ခုချင်းစီအလိုက် ပေါင်းပါက ကျွန်ုပ်တို့၏ ကိုယ်ပိုင် catalog သည် **~7.4B** ဟု ပြမည် (2026-09-03 တွင် ပြန်လည်တွက်ချက်ထားသည်။ ဤကိန်းဂဏန်းကို CI ဖြင့် ထိန်းချုပ်ထားခြင်းမရှိသောကြောင့် catalog ပြောင်းလဲသည့်အခါတိုင်း ပြန်လည်တိုင်းတာပါ) — ခေါင်းစီးတွင် **~1.47B** ဟု ဖော်ပြထားခြင်းမှာ provider တစ်ခုစီ၏ account တစ်ခုက အမှန်တကယ် သုံးစွဲနိုင်သည့်ပမာဏ ဖြစ်သောကြောင့်ဖြစ်သည်။
- **နေ့စဉ်ကန့်သတ်ချက်များကို ပြောင်းလဲတွက်ချက်သော်လည်း rate များကို မတွက်ချက်ပါ။** မှတ်တမ်းတင်ဖော်ပြထားသော tokens/day ကန့်သတ်ချက်ကို `× 30` အဖြစ် ပြောင်းလဲသည်။ မှတ်တမ်းတင်ဖော်ပြထားသော requests/day ကန့်သတ်ချက်ကို `RPD × ~800 tokens × 30` အဖြစ် ပြောင်းလဲသည်။ Requests-per-minute ကိုသာ ထုတ်ပြန်သည့် provider တွင် လစဉ်ကိန်းဂဏန်း **မရှိဘဲ** _uncapped_ အဖြစ် စာရင်းသွင်းထားကာ ပေါင်းလဒ်ထဲသို့ လုံးဝမထည့်ပါ။ Rate limit ကို 24/7 ဖြင့် မြှောက်ကာ ကိန်းဂဏန်းဖောင်းပွစေခြင်းကို ကျွန်ုပ်တို့ လက်မခံပါ။
- **ဒေသအလိုက် အထောက်အထားစစ်ဆေးမှုနောက်ကွယ်ရှိ quota များကို သီးခြားဖော်ပြထားသည်** (`+~6M behind regional identity verification`)၊ အဘယ်ကြောင့်ဆိုသော် ဖတ်ရှုသူအများစုက ၎င်းတို့ကို အသုံးမပြုနိုင်သောကြောင့်ဖြစ်သည်။
- **Signup credit များသည် ပထမလအတွက်သာဖြစ်ပြီး** ပုံမှန်တည်ငြိမ်သော ကိန်းဂဏန်းထဲသို့ မရောနှောဘဲ ဒုတိယကိန်းဂဏန်းအဖြစ်သာ အစီရင်ခံထားသည်။
- **ဤကိန်းဂဏန်းကို CI ဖြင့် အတည်ပြုထိန်းချုပ်ထားသည်။** `npm run check:docs-counts` သည် catalog မှ စုစုပေါင်းများကို ပြန်လည်တွက်ချက်ပြီး ဤဖိုင်၊ README သို့မဟုတ် budget card ရှိ ကိန်းဂဏန်းများနှင့် ကွာဟလာပါက build ကို ကျရှုံးစေသည်။

## ToS အထူးဂရုပြုရန် ဇယား

> **ToS flag သည် အကြံပြုသတိပေးချက်သာဖြစ်ပြီး routing gate မဟုတ်ပါ။** `tos` ဟု အမှတ်အသားပြုထားသော provider များကို မူလအတိုင်း routing နှင့် combo/fallback တို့တွင် ထည့်သွင်းအသုံးပြုထားဆဲဖြစ်သည်။ အဆိုပါ flag ကို `/dashboard/free-tiers` နှင့် `/api/free-tier/summary` တို့တွင်သာ ဖော်ပြသည်။ `excludeTosAvoid` query parameter သည် summary view ကိုသာ သက်ရောက်ပြီး global routing ကို မသက်ရောက်ပါ။ ဆုံးဖြတ်ချက်ကို `open-sse/config/freeTierCatalog.ts` တွင် ထားရှိသည် (အချက်အလက်ပေးရန်သာဖြစ်ပြီး routing engine များက ဖတ်ရှုအသုံးပြုခြင်းမရှိပါ)။

> ကိုယ်တိုင် host လုပ်ထားသော၊ အသုံးပြုသူတစ်ဦးတည်းသုံး ကိုယ်ပိုင် proxy အတွက် provider တစ်ခုစီ၏ သတ်မှတ်ချက်များကို အမြန်ခြုံငုံဖတ်ရှုထားခြင်းဖြစ်သည်။ `caution` = စစ်ဆေးသင့်သော ကိုယ်ရေးကိုယ်တာအသုံးပြုမှု သို့မဟုတ် proxy ဆိုင်ရာ စည်းကမ်းချက်ရှိခြင်း၊ `ambiguous` = မရှင်းလင်းခြင်း၊ `ok` = အတိအလင်း ခွင့်ပြုထားခြင်း။ အချက်အလက်ပေးရန်သာဖြစ်ပြီး ဥပဒေအကြံဉာဏ်မဟုတ်ပါ — သင်ကိုယ်တိုင် ဆုံးဖြတ်ရပါမည်။

### ⚠️ သတိပြုရန် — စစ်ဆေးသင့်သော ကိုယ်ရေးကိုယ်တာအသုံးပြုမှု / proxy ဆိုင်ရာ စည်းကမ်းချက်များ (16)
