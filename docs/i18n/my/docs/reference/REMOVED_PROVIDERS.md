အချို့ဝန်ဆောင်မှုများကို OmniRoute ထဲသို့ ပေါင်းစည်းခဲ့ပြီးနောက် ၎င်းတို့ကို လည်ပတ်သူများက ဖယ်ရှားပေးရန် တောင်းဆိုခဲ့သောကြောင့် နောက်ပိုင်းတွင် ဖယ်ရှားခဲ့သည်။ ဤစာမျက်နှာသည် ထိုသို့ဖယ်ရှားမှုများ၏ အမြဲတမ်းမှတ်တမ်းဖြစ်သည်။ ၎င်း၏ တစ်ခုတည်းသော ရည်ရွယ်ချက်မှာ ထိုဝန်ဆောင်မှုများကို မတော်တဆ ပြန်လည်ထည့်သွင်းမိခြင်းမှ ကာကွယ်ရန်ဖြစ်သည်။ အဟောင်း fork တစ်ခု၊ cache လုပ်ထားသော npm tarball တစ်ခု၊ သိမ်းဆည်းထားသော issue တစ်ခု သို့မဟုတ် "provider X ကို ပြန်လည်ထည့်သွင်းရန်" တောင်းဆိုချက်တစ်ခုကို တွေ့ရှိသော ပံ့ပိုးသူအနေဖြင့် **ပြန်လည်မထည့်သွင်းရ** ဟု ဖော်ပြထားသည့် တစ်နေရာတည်းသော မှတ်တမ်းကို လိုအပ်သည်။

ဤစာမျက်နှာသည် ရပ်ဆိုင်းသွားသော သို့မဟုတ် ဆက်လက်မလုပ်ကိုင်တော့သော ဝန်ဆောင်မှုများ၏ စာရင်း **မဟုတ်ပါ**။ ထိုဝန်ဆောင်မှုများကို
[`FREE_TIERS.md`](FREE_TIERS.md) ("ဖယ်ရှားပြီး / အခမဲ့အဆင့် မရှိ") တွင် ခြေရာခံထားပြီး ဝန်ဆောင်မှု ပြန်လည်ရရှိလာပါက ပြန်လည်ထည့်သွင်းနိုင်သည်။ အောက်ပါစာရင်းဝင်များကို တောင်းဆိုချက်တွင် ဖော်ပြထားသော လည်ပတ်သူထံမှ စာဖြင့်ရေးသားထားသည့် ခွင့်ပြုချက်ရရှိမှသာ ပြန်လည်ထည့်သွင်းနိုင်ပြီး ထိုခွင့်ပြုချက်၏ လင့်ခ်ကို သက်ဆိုင်ရာစာရင်းဝင်တွင် ထည့်သွင်းထားရမည်။

## မူဝါဒ

1. **ဝန်ဆောင်မှုလည်ပတ်သူထံမှ ဖယ်ရှားရန်တောင်းဆိုချက်ကို ညှိနှိုင်းခြင်းမပြုဘဲ လိုက်နာရမည်။** OmniRoute သည်
   မည်သည့် upstream ဝန်ဆောင်မှုနှင့်မျှ ဆက်နွှယ်မှုမရှိပါ။ ဝန်ဆောင်မှုတစ်ခု၏ လည်ပတ်သူက
   ပေါင်းစည်းမှုကို ဖယ်ရှားရန် တောင်းဆိုပါက ထိုပေါင်းစည်းမှုသည် တရားဝင် API ကို အသုံးပြုထားသည်ဖြစ်စေ၊ မပြုထားသည်ဖြစ်စေ ဖယ်ရှားရမည်။
2. **"ဖယ်ရှားပြီး" ဆိုသည်မှာ OmniRoute က ထိန်းချုပ်သော မျက်နှာပြင်အားလုံးကို ဆိုလိုသည်။** Executor၊ registry entry၊ provider
   id နှင့် alias၊ model စာရင်း၊ endpoints၊ environment variables၊ icon၊ dashboard cards၊
   ထုတ်လုပ်ထားသော provider reference၊ `FREE_TIERS.md`၊ environment reference၊ README ထဲရှိ အရေအတွက်များ၊
   `llm.txt` mirrors၊ သီးသန့် tests နှင့် golden snapshots၊ code comments၊ CHANGELOG bullets
   (မှတ်တမ်းတင်ထားသော reconciliation နှင့်အတူ၊ `config/release/changelog-reconciliations.json` ကို ကြည့်ပါ)၊
   GitHub Releases notes၊ wiki နှင့် ထို provider ကို အကြောင်းအရာအဖြစ်ထားသော GitHub issues၊ discussions နှင့် pull requests အားလုံးကို ဆိုလိုသည်
   (issues နှင့် discussions များကို ဖျက်ရမည်။ GitHub တွင် pull requests များကို ဖျက်၍မရသောကြောင့် pull requests များ၏ ခေါင်းစဉ်ကို ပြောင်းလဲခြင်း၊
   ဖော်ပြချက်ကို အစားထိုးခြင်းနှင့် thread ကို lock လုပ်ခြင်းတို့ ပြုလုပ်ရမည်)။
3. **စာဖြင့်ရေးသားထားသည့် ခွင့်ပြုချက်မရှိဘဲ ဤစာမျက်နှာရှိ မည်သည့်စာရင်းဝင်ကိုမျှ ပြန်လည်မထည့်သွင်းရ။** ၎င်းတွင်
   မည်သည့် provider catalog မဆို id သို့မဟုတ် alias ကို ပြန်ထည့်ခြင်း၊ domains များကို executor ထဲသို့ ထည့်ခြင်း၊
   ၎င်းကို "ပြန်လည်ထည့်သွင်းသော" ပံ့ပိုးသူ PR ကို လက်ခံခြင်း၊ free-model catalog ထဲသို့ ထည့်ခြင်း သို့မဟုတ်
   OmniRoute မှတစ်ဆင့် ၎င်းကို ကိုယ်တိုင်ချိတ်ဆက်အသုံးပြုနိုင်သည့် နည်းလမ်းကို မှတ်တမ်းတင်ခြင်းတို့ ပါဝင်သည်။ ထိုကဲ့သို့သော PRs နှင့် issues များကို
   ဤစာမျက်နှာ၏ လင့်ခ်နှင့်အတူ ပိတ်ပါ။
4. **စာရင်းဝင်ကို အနည်းဆုံးအချက်အလက်ဖြင့်သာ ထားပါ။** ပြန်လည်ထည့်သွင်းမှုတစ်ခုကို reviewer က ခွဲခြားသိရှိရန် လိုအပ်သည့်
   identifiers၊ domains၊ dates နှင့် ဖယ်ရှားမှုကို ဆောင်ရွက်ခဲ့သော pull request ကိုသာ မှတ်တမ်းတင်ပါ။
   ပေါင်းစည်းမှု အလုပ်လုပ်ပုံကို မဖော်ပြပါနှင့်။
5. **Regression guard သည် `tests/unit/removed-providers-blocklist.test.ts` ဖြစ်သည်။** အောက်ပါ identifier သို့မဟုတ် domain တစ်ခုခုသည်
   provider catalogs၊ executor map သို့မဟုတ် provider registry sources များတွင် ပြန်လည်ပေါ်လာပါက ၎င်းသည် fail ဖြစ်မည်။
   ဤနေရာတွင် row တစ်ခုထည့်သည့် PR တစ်ခုတည်းအတွင်း identifier အသစ်များကို ထို test တွင် ထည့်ပါ။

## စာရင်းဝင်တစ်ခု ထည့်သွင်းခြင်း

ဖယ်ရှားရန် တောင်းဆိုချက်အသစ်တစ်ခု ရောက်ရှိလာသောအခါ-

1. တောင်းဆိုချက်သည် ဝန်ဆောင်မှုလည်ပတ်သူထံမှ (၎င်းတို့၏ support address သို့မဟုတ်
   ၎င်းတို့ထိန်းချုပ်သော domain မှ) လာကြောင်း အတည်ပြုပြီး message ကို သီးသန့်သိမ်းဆည်းထားပါ။
2. မူဝါဒ အချက် 2 ရှိ checklist ကို လိုက်နာ၍ ပေါင်းစည်းမှုကို ဖယ်ရှားပါ။
   keyless provider အတွက် [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) ကို ကိုးကားချက်အဖြစ် အသုံးပြုပြီး
   သိမ်းဆည်းထားသော connections များရှိသည့် API-key provider အတွက် [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) ကို အသုံးပြုပါ
   (migration တစ်ခု ထည့်ပါ)။
3. တူညီသော PR ထဲတွင် အထက်ပါဇယားသို့ row တစ်ခုနှင့် identifiers များကို
   `tests/unit/removed-providers-blocklist.test.ts` ထဲသို့ ထည့်ပါ။
4. PR ကို merge လုပ်ပြီးသည်နှင့် ဖယ်ရှားခဲ့သည့်အရာများနှင့် OmniRoute က မပြောင်းလဲနိုင်သည့်အရာများ
   (ထုတ်ဝေပြီးသား npm နှင့် Docker versions၊ git history၊ third-party forks) ကို စာရင်းပြုစု၍ လည်ပတ်သူထံ ပြန်လည်အကြောင်းကြားပါ။
