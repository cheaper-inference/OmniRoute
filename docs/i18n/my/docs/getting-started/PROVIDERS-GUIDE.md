## Provider ဆိုတာ ဘာလဲ?

Provider တစ်ခုကို **ဖုန်းဆက်သွယ်ရေးဝန်ဆောင်မှုပေးသူ** တစ်ခုကဲ့သို့ စဉ်းစားနိုင်သည်။ ဖုန်းခေါ်ဆိုရန် ဖုန်းဆက်သွယ်ရေးဝန်ဆောင်မှုပေးသူတစ်ခု လိုအပ်သကဲ့သို့ AI မော်ဒယ်များကို အသုံးပြုရန် AI provider တစ်ခု လိုအပ်သည်။ OmniRoute သည် **ဖုန်းဆက်သွယ်ရေးဝန်ဆောင်မှုပေးသူအားလုံး** နှင့် အလုပ်လုပ်နိုင်သော ဖုန်းတစ်လုံးကဲ့သို့ ဖြစ်ပြီး ၎င်းတို့အကြား အလိုအလျောက် ပြောင်းလဲအသုံးပြုနိုင်သည်။

### Provider အမျိုးအစားများ

| အမျိုးအစား     | အဓိပ္ပာယ်                            | ဥပမာများ                        | ကုန်ကျစရိတ်                     |
| -------------- | ------------------------------------ | ------------------------------- | ------------------------------- |
| **အခမဲ့**      | ငွေပေးချေရန် မလိုအပ်ပါ               | Kiro, Pollinations              | $0                              |
| **API Key**    | API key တစ်ခု လိုအပ်သည်              | OpenAI, Anthropic, Google       | အသုံးပြုမှုအလိုက် ပေးချေရသည်    |
| **OAuth**      | သင့်အကောင့်ဖြင့် ဝင်ရောက်သည်         | Claude Code, GitHub Copilot     | စာရင်းသွင်းခ                    |
| **Web Cookie** | သင့်ဘရောက်ဇာ session ကို အသုံးပြုသည် | ChatGPT Web (Codex), Gemini Web | $0 (သင့်အကောင့်ကို အသုံးပြုသည်) |

### Web Cookie Provider များ

အထွေထွေ စနစ်ထည့်သွင်းမှု လမ်းညွှန်ချက်များ၊ ကန့်သတ်ချက်များ၊ ပြဿနာဖြေရှင်းခြင်းနှင့် provider အလိုက် authentication လမ်းညွှန်ချက်များအတွက် **[WEB-COOKIE-GUIDE.md](./WEB-COOKIE-GUIDE.md)** ကို ကြည့်ပါ။

## အမြန်စတင်ခြင်း: သင်၏ ပထမဆုံး Provider ကို ချိတ်ဆက်ပါ

### ပထမဆုံးအသုံးပြုချိန်အတွက် အခမဲ့ Provider ထည့်သွင်းသတ်မှတ်ခြင်း (မလုပ်လည်းရ)

ပထမဆုံးအသုံးပြုချိန် wizard တွင် သီးခြား **အခမဲ့ Provider များကို ထည့်သွင်းသတ်မှတ်ရန်** ကတ်တစ်ခု ပါရှိသည်။ ၎င်းသည် OmniRoute ၏ စစ်မှန်ကြောင်းအတည်ပြုမှု မလိုအပ်သော Provider registry မှ လက်ရှိအသုံးပြုနိုင်သည့်
စာရင်းကို ရယူပြီး အတည်မပြုမီ Provider တစ်ခုချင်းစီကို ပြန်လည်စစ်ဆေးကာ မရွေးချယ်လိုသည်များကို ပယ်ဖျက်နိုင်စေသည်။
ပြင်ပအဖွဲ့အစည်း၏ စည်းကမ်းချက်များ၊ ကိုယ်ရေးအချက်အလက်မူဝါဒ၊ ရရှိနိုင်မှုနှင့် အသုံးပြုနှုန်းကန့်သတ်ချက်များကို ဦးစွာစစ်ဆေးနိုင်ရန် OmniRoute က Provider ၏ သတိပေးချက်နှင့် ၎င်း၏ဝဘ်ဆိုက်လင့်ခ်ကို ပြသပေးသည်။

ဤလုပ်ဆောင်ချက်သည် မဖြစ်မနေမဟုတ်ပါ။ wizard ကို အပြီးသတ်ခြင်းဖြင့် အခမဲ့ Provider ချိတ်ဆက်မှုများကို မသိမသာ ဖန်တီးမည်မဟုတ်ပါ။
မရှိသေးသော Provider များကိုသာ ဖန်တီးပြီး ရှိပြီးသား စိတ်ကြိုက်ပြင်ဆင်ထားသည့် ချိတ်ဆက်မှုများကို
မပြောင်းလဲဘဲ ထားရှိကာ ဖန်တီးပြီးသော၊ သတ်မှတ်ပြီးသားနှင့် မအောင်မြင်သော Provider များကို တစ်ခုချင်းစီ အစီရင်ခံပေးသည်။ ရလဒ်တစ်စိတ်တစ်ပိုင်းသာ အောင်မြင်ခဲ့ပါက
မအောင်မြင်ခဲ့သည့်အရာများကိုသာ ဘေးကင်းစွာ ပြန်လည်ကြိုးစားနိုင်သည်။

### ရွေးချယ်မှု A: အခမဲ့ Provider (ခရက်ဒစ်ကတ် မလိုအပ်ပါ)

1. `http://localhost:20128` ရှိ dashboard ကို ဖွင့်ပါ
2. **Provider များ** → **Provider ထည့်ရန်** သို့ သွားပါ
3. အောက်ပါ အခမဲ့ Provider များထဲမှ တစ်ခုကို ရွေးချယ်ပါ:
   - **Kiro AI** — အခမဲ့ Claude model များ (စစ်မှန်ကြောင်းအတည်ပြုမှု မလိုအပ်ပါ)
   - **Pollinations** — အခမဲ့ GPT-5၊ Claude၊ Gemini (key မလိုအပ်ပါ)
   - **LongCat** — token 10M အခမဲ့ (တစ်ကြိမ်သာ ပေးအပ်မှု၊ အကောင့် + KYC လိုအပ်သည်)
   - **Cloudflare AI** — model 50+၊ တစ်ရက်လျှင် neuron 10K
   - **MLX Gemma 26B** — စက်တွင်း Apple Silicon model (~38.5 tok/s၊ RAM ~15.9GB)
   - **MLX Qwen 3.8 27B** — စက်တွင်း Apple Silicon model (~9.1 tok/s၊ RAM ~13.1GB)
4. **ချိတ်ဆက်ရန်** ကို နှိပ်ပါ
5. ပြီးပါပြီ! ယခု အခမဲ့ AI အသုံးပြုခွင့် ရရှိပါပြီ။

### ရွေးချယ်မှု B: API Key Provider (အခပေး)

1. Provider ၏ ဝဘ်ဆိုက်မှ API key တစ်ခု ရယူပါ:
   - **OpenAI**: https://platform.openai.com/api-keys
   - **Anthropic**: https://console.anthropic.com/
   - **Google**: https://aistudio.google.com/apikey
   - **DeepSeek**: https://platform.deepseek.com/
   - **Groq**: https://console.groq.com/
2. `http://localhost:20128` ရှိ dashboard ကို ဖွင့်ပါ
3. **Provider များ** → **Provider ထည့်ရန်** သို့ သွားပါ
4. သင်၏ Provider ကို ရွေးချယ်ပါ
5. သင်၏ API key ကို ကူးထည့်ပါ
6. **ချိတ်ဆက်ရန်** ကို နှိပ်ပါ
7. ပြီးပါပြီ! ယခု ထို Provider ၏ model များကို အသုံးပြုခွင့် ရရှိပါပြီ။

### ရွေးချယ်မှု C: OAuth Provider (စာရင်းသွင်းမှု)

1. `http://localhost:20128` ရှိ dashboard ကို ဖွင့်ပါ
2. **Provider များ** → **Provider ထည့်ရန်** သို့ သွားပါ
3. သင်၏ Provider ကို ရွေးချယ်ပါ (ဥပမာ Claude Code၊ GitHub Copilot)
4. **OAuth ဖြင့် ချိတ်ဆက်ရန်** ကို နှိပ်ပါ
5. သင်၏အကောင့်ဖြင့် ဝင်ရောက်ပါ
6. ပြီးပါပြီ! ယခု သင်၏ စာရင်းသွင်းမှုတွင် ပါဝင်သော model များကို အသုံးပြုခွင့် ရရှိပါပြီ။

### ရွေးချယ်မှု D: စက်တွင်း MLX Model များ (Apple Silicon)

ပေါင်းစည်းထားသော memory ပါဝင်သည့် Apple Silicon Mac များတွင် OmniRoute သည် `mlx-lm.server` မှတစ်ဆင့် လည်ပတ်နေသော စက်တွင်း MLX model များကို ပုံမှန် OpenAI-compatible စက်တွင်း Provider များအဖြစ် ချိတ်ဆက်အသုံးပြုနိုင်သည်။

#### ကြိုတင်လိုအပ်ချက်များ

- ပေါင်းစည်းထားသော memory 24GB+ ပါဝင်သည့် **Apple Silicon Mac** (M1/M2/M3/M4) ကို အကြံပြုသည်
- **uv** package manager: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- **mlx-lm**: `uv pip install mlx-lm`

#### အမြန်စတင်ခြင်း

1. **လိုအပ်သော dependency များကို ထည့်သွင်းပါ**:

   ```bash
   # uv ကို မထည့်သွင်းရသေးပါက ထည့်သွင်းပါ
   curl -LsSf https://astral.sh/uv/install.sh | sh

   # mlx-lm ကို ထည့်သွင်းပါ
   uv pip install mlx-lm
   ```

2. **MLX server များကို ကိုယ်တိုင်စတင်ပါ** (သီးခြား terminal များတွင်):

   ```bash
   # Terminal 1: Gemma 4 26B A4B IT-QAT (port 11435)
   uv run mlx_lm.server --model mlx-community/gemma-4-26B-A4B-it-qat-q4_0-mlx-aligned --port 11435 --host 127.0.0.1

   # Terminal 2: Qwen 3.8 27B MLX Mixed (port 11436)
   uv run mlx_lm.server --model maglun/Qwen3.8-27B-MLX-Mixed-3.80bpw --port 11436 --host 127.0.0.1
   ```

3. **OmniRoute Dashboard တွင် ချိတ်ဆက်ပါ**:
   - **Provider များ** → **Provider ထည့်ရန်** သို့ သွားပါ
   - **MLX Gemma 26B** သို့မဟုတ် **MLX Qwen 3.8 27B** ကို ရွေးချယ်ပါ
   - **ချိတ်ဆက်ရန်** ကို နှိပ်ပါ (API key မလိုအပ်ပါ)

4. **OpenCode ဖြင့် အသုံးပြုပါ**:
   ```bash
   # OmniRoute ကို အသုံးပြုရန် OpenCode ကို သတ်မှတ်ပါ
   opencode config set api.base_url http://localhost:20128/v1
   opencode config set api.key <your-omniroute-api-key>

   # MLX model များကို အသုံးပြုပါ
   opencode run --model mlx-gemma/gemma-4-26b
   opencode run --model mlx-qwen/qwen3.8-27b
   ```

#### Memory စီမံခန့်ခွဲမှု

**အရေးကြီးသည်**: ပေါင်းစည်းထားသော memory 24GB ဖြင့် **အရွယ်ကြီး MLX model တစ်ခုတည်းကိုသာ တစ်ချိန်တည်းတွင် လည်ပတ်နိုင်သည်**။

- Gemma 26B: အများဆုံး memory ~15.9GB
- Qwen 3.8 27B: အများဆုံး memory ~13.1GB

၎င်းကို ကိုယ်တိုင် စီမံခန့်ခွဲရပါမည်:

- တစ်ချိန်တည်းတွင် MLX server တစ်ခုသာ လည်ပတ်ပါ၊ သို့မဟုတ်
- နှစ်ခုလုံးကို မတူညီသော စက်များပေါ်တွင် လည်ပတ်ပါ၊ သို့မဟုတ်
- တစ်ခုကို စတင်မီ အခြားတစ်ခုကို ရပ်တန့်ပါ

OmniRoute သည် MLX server process များကို အလိုအလျောက် စီမံခန့်ခွဲမပေးပါ — သင်သတ်မှတ်ထားသော OpenAI-compatible endpoint များထံ request များကို လမ်းကြောင်းပေးပို့ရုံသာ လုပ်ဆောင်သည်။

#### Tool ခေါ်ယူအသုံးပြုမှု ပံ့ပိုးခြင်း

Model နှစ်ခုလုံးသည် OpenAI-compatible tool ခေါ်ယူအသုံးပြုမှုကို ပံ့ပိုးသည်။ အောက်ပါအတိုင်း စမ်းသပ်ပါ:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mlx-gemma/gemma-4-26b",
    "messages": [{"role": "user", "content": "What is 2+2? Use the calculator tool."}],
    "tools": [{"type": "function", "function": {"name": "calculator", "description": "Calculate", "parameters": {"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]}}}]
  }'
```

## Provider အများအပြားကို အသုံးပြုခြင်း

OmniRoute သည် **provider အများအပြား** နှင့် အသုံးပြုသည့်အခါ အကောင်းဆုံး လုပ်ဆောင်နိုင်သည်။ ယင်းက သင့်အား အောက်ပါတို့ကို ပေးစွမ်းသည်-

- **အလိုအလျောက် အရန်ပြောင်းလဲအသုံးပြုခြင်း** — Provider တစ်ခု မအောင်မြင်ပါက OmniRoute သည် နောက်တစ်ခုကို စမ်းသုံးမည်
- **ကုန်ကျစရိတ် အကောင်းဆုံးဖြစ်အောင် ပြုလုပ်ခြင်း** — တောင်းဆိုမှုတစ်ခုစီအတွက် ကုန်ကျစရိတ်အနည်းဆုံး provider ကို OmniRoute က ရွေးချယ်မည်
- **မြန်နှုန်း အကောင်းဆုံးဖြစ်အောင် ပြုလုပ်ခြင်း** — တောင်းဆိုမှုတစ်ခုစီအတွက် အမြန်ဆုံး provider ကို OmniRoute က ရွေးချယ်မည်
- **အရည်အသွေး အကောင်းဆုံးဖြစ်အောင် ပြုလုပ်ခြင်း** — လုပ်ဆောင်ချက်တစ်ခုစီအတွက် အကောင်းဆုံး provider ကို OmniRoute က ရွေးချယ်မည်

### အကြံပြုထားသော စနစ်ထည့်သွင်းမှု

အကောင်းဆုံး အသုံးပြုမှုအတွေ့အကြုံရရှိရန် အနည်းဆုံး **provider 3 ခု** ကို ချိတ်ဆက်ပါ-

1. **အခမဲ့ provider တစ်ခု** (Kiro သို့မဟုတ် Pollinations) — အမြဲတမ်း အသုံးပြုနိုင်သည်
2. **မြန်ဆန်သော provider တစ်ခု** (Groq, Cerebras) — လျင်မြန်သော တုံ့ပြန်မှုများအတွက်
3. **အရည်အသွေးမြင့် provider တစ်ခု** (OpenAI, Anthropic, Google) — ရှုပ်ထွေးသော လုပ်ဆောင်ချက်များအတွက်

ထို့နောက် `model: "auto"` ကို အသုံးပြုပါ။ OmniRoute သည် တောင်းဆိုမှုတစ်ခုစီအတွက် အကောင်းဆုံးတစ်ခုကို အလိုအလျောက် ရွေးချယ်ပေးမည်။

### Qoder: အထောက်အထား ပို့ဆောင်မှုနည်းလမ်းကို ရွေးချယ်ခြင်း

Qoder သည် အထောက်အထားများ လိုအပ်သည်။ ၎င်း၏ ပို့ဆောင်မှုနည်းလမ်းနှစ်ခုတွင် လုပ်ဆောင်နိုင်စွမ်းများ မတူညီပါ။ model အမည်တစ်ခုတည်းဖြင့် သီးခြားချိတ်ဆက်မှုတစ်ခုက မည်သည့်အရာများ လုပ်ဆောင်နိုင်သည်ကို သတ်မှတ်မပေးနိုင်ပါ။

| အထောက်အထား                                  | OmniRoute ပို့ဆောင်မှုနည်းလမ်း                  | ခေါ်ယူသူ၏ tool calling                               | Streaming                                                           |
| ------------------------------------------- | ----------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------- |
| `pt-` ဖြင့် အစပြုသော PAT                    | OmniRoute host ပေါ်ရှိ local `qodercli` process | မပံ့ပိုးပါ                                           | Buffered: CLI က အဖြေအပြည့်အစုံ ပြန်ပေးပြီးမှသာ SSE ကို ထုတ်လွှတ်သည် |
| PAT မဟုတ်သော access token သို့မဟုတ် API key | DashScope OpenAI-compatible HTTP endpoint       | upstream model/key အပေါ် မူတည်၍ တိုက်ရိုက်ပေးပို့သည် | Upstream HTTP/SSE လမ်းကြောင်း                                       |

PAT အတွက် Qoder CLI ကို OmniRoute နှင့် တူညီသော host သို့မဟုတ် container ပေါ်တွင် ထည့်သွင်းပါ။ executable ကို `qodercli` အဖြစ် ရှာဖွေတွေ့ရှိနိုင်ရမည်၊ သို့မဟုတ် `CLI_QODER_BIN` ကို ၎င်း၏ executable path အဖြစ် သတ်မှတ်ပါ။ Docker host ပေါ်တွင်သာ ထည့်သွင်းထားသော CLI သည် container အတွင်း အလိုအလျောက် ရှိနေမည်မဟုတ်ပါ။ binary မရှိပါက ထည့်သွင်းခြင်း သို့မဟုတ် path သတ်မှတ်ခြင်းသို့ လမ်းညွှန်ပေးသော ရှင်းလင်းသည့် error တစ်ခု ထွက်ပေါ်မည်။

PAT chat လမ်းကြောင်းတွင် process timeout 45 စက္ကန့်ရှိသည်။ ၎င်းသည် conversation ကို prompt တစ်ခုအဖြစ် ပြောင်းလဲစုစည်းပြီး CLI ကို non-streaming print mode ဖြင့် ခေါ်ယူသည်။ `stream: true` တောင်းဆိုခြင်းသည် response envelope ကို SSE အဖြစ် ပြောင်းလဲပေးသော်လည်း upstream token များကို တစ်ဆင့်ချင်း ပို့ဆောင်ပေးခြင်း မရှိပါ။ CLI validation/model listing သည် သီးခြား timeout 20 စက္ကန့်ကို အသုံးပြုသည်။ ဤတန်ဖိုးများသည် လက်ရှိ code default များဖြစ်ပြီး dashboard မှ ပြင်ဆင်သတ်မှတ်နိုင်သော setting များ မဟုတ်ပါ။

သာမန် chat အတွက် PAT connection များကို အသုံးပြုပါ။ `tools` သို့မဟုတ် အဟောင်းပုံစံ `functions` များ ပါဝင်သည့် agent request များသည် pinned combo target များအပါအဝင် အထောက်အထားရွေးချယ်ရာတွင် PAT account များကို ဖယ်ထုတ်သည်။ Qoder account အမျိုးအစားများ ရောနှောထားသော pool တစ်ခုသည် ၎င်း၏ HTTP account ကို ရွေးချယ်နိုင်ဆဲဖြစ်သည်။ PAT executor သို့ တိုက်ရိုက်ခေါ်ဆိုမှုများသည်လည်း tool definition များကို တိတ်တဆိတ် ဖယ်ရှားမည့်အစား CLI ကို မစတင်မီ ရှင်းလင်းစွာ ပျက်ကွက်သည်။ ဤကန့်သတ်ချက်သည် API ခေါ်ယူသူက ပေးသော tool များနှင့်သာ သက်ဆိုင်ပြီး Qoder CLI ကိုယ်တိုင် အသုံးပြုနိုင်သည့် internal tool များနှင့် မသက်ဆိုင်ပါ။ HTTP key တစ်ခုရှိရုံဖြင့် model အားလုံးသည် tool များကို ပံ့ပိုးမည်ဟု အာမမခံပါ။ ပုံမှန် model capability စစ်ဆေးမှုများ ဆက်လက်သက်ရောက်သည်။

စီမံခန့်ခွဲသူက setting ငါးခုလုံးဖြစ်သော `QODER_OAUTH_AUTHORIZE_URL`, `QODER_OAUTH_TOKEN_URL`, `QODER_OAUTH_USERINFO_URL`, `QODER_OAUTH_CLIENT_ID` နှင့် `QODER_OAUTH_CLIENT_SECRET` တို့ကို သတ်မှတ်ထားမှသာ Browser OAuth ကို အသုံးပြုနိုင်သည်။ ၎င်းတို့၏ default တန်ဖိုးများသည် ဗလာဖြစ်သည်။ configuration မပြုလုပ်ရသေးသော installation တစ်ခုတွင် browser sign-in လုပ်ငန်းစဉ် အဆင်သင့်ဖြစ်နေပြီဟု ယူဆမည့်အစား ပံ့ပိုးထားသော အထောက်အထား import နည်းလမ်းကို အသုံးပြုသင့်သည်။

Implementation ကိုးကားချက်များ: [Qoder executor](../../open-sse/executors/qoder.ts),
[CLI runtime](../../open-sse/services/qoderCli.ts) နှင့်
[OAuth configuration](../../src/lib/oauth/constants/oauth.ts)။ Incremental PAT streaming နှင့် ပြင်ဆင်သတ်မှတ်နိုင်သော timeout တို့သည် သီးခြား အဆင့်မြှင့်တင်မှုများဖြစ်ပြီး ဤလုပ်ဆောင်ပုံက ၎င်းတို့ကို ပံ့ပိုးပေးမည်ဟု ကတိမပြုပါ။

## အမေးများသော မေးခွန်းများ

### "OmniRoute ကို အသုံးပြုရန် ငွေပေးချေရန် လိုအပ်ပါသလား။"

**မလိုအပ်ပါ!** OmniRoute သည် အခမဲ့ဖြစ်ပြီး open-source ဖြစ်သည်။ အခမဲ့ provider များ (Kiro, Pollinations) ကို မည်သည့်ငွေပေးချေမှုမျှ မရှိဘဲ အသုံးပြုနိုင်သည်။ အခပေး provider များကို အသုံးပြုရန် ရွေးချယ်မှသာ ငွေပေးချေရမည်ဖြစ်သည်။

### "မည်သည့် provider နှင့် စတင်သင့်ပါသလဲ။"

**Kiro AI** နှင့် စတင်ပါ — ၎င်းသည် အခမဲ့ဖြစ်ပြီး API key မလိုအပ်သည့်အပြင် Claude model များကို အသုံးပြုခွင့်ပေးသည်။ ထို့နောက် လိုအပ်သလို အခြား provider များကို ထပ်မံထည့်သွင်းပါ။

### "Provider များစွာကို တစ်ပြိုင်နက် အသုံးပြုနိုင်ပါသလား။"

**အသုံးပြုနိုင်ပါသည်!** ဒါက OmniRoute ၏ အဓိကရည်ရွယ်ချက်ပင် ဖြစ်သည်။ Provider များစွာကို ချိတ်ဆက်ပြီး request တစ်ခုချင်းစီအတွက် အကောင်းဆုံး provider ကို OmniRoute က ရွေးချယ်နိုင်ရန် `model: "auto"` ကို အသုံးပြုပါ။

### "Provider တစ်ခု အလုပ်မလုပ်တော့လျှင် ဘာဖြစ်မလဲ။"

OmniRoute သည် မအောင်မြင်သော provider များကို အလိုအလျောက် ကျော်သွားပြီး နောက်တစ်ခုကို စမ်းသပ်အသုံးပြုသည်။ သင် ဘာမျှလုပ်ရန် မလိုအပ်ပါ။

### "Provider တစ်ခုကို မည်သို့ ချိတ်ဆက်ဖြုတ်ရမလဲ။"

Providers သို့ သွားပါ → provider ကို နှိပ်ပါ → **Disconnect** ကို နှိပ်ပါ။

### "ကျွန်ုပ်၏ လက်ရှိ API key များကို အသုံးပြုနိုင်ပါသလား။"

**အသုံးပြုနိုင်ပါသည်!** OpenAI, Anthropic, Google စသည်တို့အတွက် API key များ ရှိပြီးသားဖြစ်ပါက OmniRoute တွင် အသုံးပြုနိုင်သည်။ Provider ကို ချိတ်ဆက်ချိန်တွင် ၎င်းတို့ကို paste လုပ်လိုက်ရုံသာ ဖြစ်သည်။
