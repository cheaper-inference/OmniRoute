## 1. အရာများ တည်ရှိရာနေရာ

- **Kit။** `packages/ui-kit/src` သည် `packages/ui-kit/UPSTREAM.md` တွင် pin လုပ်ထားသော commit ရှိ upstream `src/` ၏ byte-for-byte မိတ္တူဖြစ်သည် (`packages/ui-kit/UPSTREAM.md` တွင် လိုင်စင်ခွင့်ပြုချက်ကိုလည်း မှတ်တမ်းတင်ထားသည်)။ `PATCHES.md` တွင် local patch များကို စာရင်းပြုစုထားသည် (လက်ရှိ မရှိပါ)။ Build လုပ်ခြင်းမရှိဘဲ source အဖြစ် အသုံးပြုသည်။ `next.config.mjs` က ၎င်းကို transpile လုပ်ပြီး `tsconfig.json` က `@omniroute/ui-kit` → `packages/ui-kit/src` နှင့် `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` ဟု map လုပ်ထားသည် (`vitest.config.ts` နှင့် `vitest.mcp.config.ts` တို့တွင်လည်း အလားတူ alias ပါရှိသည်)။ Kit component တစ်ခုကို ၎င်း၏ subpath (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) မှတစ်ဆင့် import လုပ်ပါ။ `@omniroute/ui-kit` barrel မှတစ်ဆင့် မည်သည့်အခါမျှ import မလုပ်ပါနှင့်။ Barrel သည် component အားလုံးကို (date picker အပါအဝင်) importer တစ်ခုချင်းစီအတွင်း ထည့်သွင်းသွားသည်။ Kit stylesheet သည် `src/app/globals.css` မှတစ်ဆင့် ဝင်ရောက်သည် (`@import "../../packages/ui-kit/src/ci-styles.css"`၊ core `ci-ui.css` နှင့် pattern family အားလုံးပါဝင်သော stylesheet အပြည့်အစုံ)။
- **Token များ။** `packages/ui-kit/src/ci-tokens.css` က `--ci-*` token များကို ကြေညာထားသည်။ `src/app/globals.css` က ၎င်းတို့ကို ယခင် OmniRoute အမည်များ (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) နှင့် ချိတ်ဆက်ပေးသောကြောင့် ရှိပြီးသား `var(--color-*)` ဖတ်ရှုမှုများနှင့် Tailwind utility များ ဆက်လက်အလုပ်လုပ်သည်။ Code အသစ်များတွင် Tailwind utility များ (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) သို့မဟုတ် kit class များကို အသုံးပြုရမည်။ Hex value ကို မည်သည့်အခါမျှ မသုံးရ (`tests/unit/design-kit-bridge.test.ts` က bridge ကို စစ်ဆေးအတည်ပြုသည်)။ `text-primary` သည် `--text-color-primary` မှတစ်ဆင့် `--color-primary-ink` သို့ resolve ဖြစ်သည် (light တွင် lime-800၊ dark တွင် lime accent)။ ထို့ကြောင့် primary text ကို ဖတ်ရှုနိုင်စွမ်းရှိစေပြီး `bg-primary`/`border-primary` က lime surface ကို ဆက်လက်ထိန်းသိမ်းထားသည်။ Chart series များသည် `--color-chart-1` … `--color-chart-5` ကို အသုံးပြုသည်။
- **Theme များ။** `<html className="ci-theme">` (`src/app/layout.tsx`) က document ကို kit theme အသုံးပြုရန် သတ်မှတ်ပေးသည်။ Preference သည် `light`, `dark` သို့မဟုတ် `system` ဖြစ်သည် (`src/shared/constants/appConfig.ts` ရှိ `THEME_CONFIG.defaultTheme = "system"`၊ `system` သည် `prefers-color-scheme` ကို လိုက်နာသည်)။ `src/store/themeStore.ts` ရှိ `applyTheme()` သည် `data-theme="dark"|"light"` ကို သတ်မှတ်ပြီး `<html>` ပေါ်ရှိ `.dark` class ကို တစ်ပြိုင်နက် toggle လုပ်သည်။ Hydration မတိုင်မီ အလုပ်လုပ်သော `src/app/layout.tsx` ရှိ inline bootstrap script ကလည်း အလားတူ လုပ်ဆောင်သည်။ Kit ၏ dark token set သည် `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`) ကို အခြေခံထားသည်။ OmniRoute ၏ ကိုယ်ပိုင် dark override များ (`globals.css` ရှိ `.dark` block) နှင့် ယခင် Tailwind `dark:` utility များသည် `.dark` class ကို အခြေခံသည်။ Accent color preset များ မရှိပါ။ Accent သည် kit မှ အမြဲရရှိပြီး အဟောင်း build တစ်ခုမှ persist လုပ်ထားသော preset ရှိပါက store load လုပ်သည့်အချိန်တွင် ဖယ်ရှားသည်။
- **Component များ (adapter များ)။** `src/shared/components/index.tsx` က OmniRoute component API ကို ထိန်းသိမ်းထားသည် (တူညီသော အမည်များ၊ default export များနှင့် prop များ)။ ၎င်း၏ နောက်ကွယ်ရှိ primitive များမှာ kit ပေါ်တွင် တည်ဆောက်ထားသော adapter များဖြစ်သည်—form များ (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`)၊ overlay နှင့် feedback များ (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`)၊ ဖွဲ့စည်းပုံဆိုင်ရာ component များ (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) နှင့် table များ (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`) ဖြစ်သည်။ Adapter တစ်ခုသည် kit component ကို subpath အလိုက် import လုပ်ပြီး ယခင် prop များကို ၎င်းနှင့် သက်ဆိုင်ရာအဖြစ် map လုပ်သည်။ ဥပမာ `Button variant="primary"` သည် kit ၏ `default` button ဖြစ်သည် (`--ci-button-primary-*`—light တွင် inverse surface၊ dark တွင် ၎င်း၏ `--ci-color-accent-foreground` ink ပါသော accent)။ `danger` သည် `destructive` ဖြစ်ပြီး `warning` သည် `outline` နှင့် `.ci-button--warning` extension ပေါင်းစပ်မှုဖြစ်သည်။ `globals.css` ၏အဆုံး (`@layer components`) ရှိ `.ci-button--warning` နှင့် `.ci-badge[data-tone]` rule များသည် kit class များအပေါ် ထပ်မံဖြည့်စွက်ထားသော OmniRoute extension များဖြစ်သည်။ `tests/unit/ui/adapters/*.test.tsx` က adapter တစ်ခုချင်းစီ၏ အပြုအမူကို အတည်ပြုထိန်းသိမ်းထားသည်။
- **Shell။** `src/app/(dashboard)/layout.tsx` က `DashboardLayout` ကို render လုပ်ပြီး ၎င်းက `src/shared/components/layouts/DashboardShell.tsx` ကို render လုပ်သည်။ ထို shell တွင် kit `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`) နှင့် `src/shared/components/Sidebar.tsx` ရှိ OmniRoute ၏ navigation logic ကို အသုံးပြုထားသည်။ `#main-content` သို့ ညွှန်သော "အကြောင်းအရာသို့ ကျော်သွားရန်" link သည် focus လုပ်နိုင်သော ပထမဆုံး element ဖြစ်သည်။ `src/shared/components/Header.tsx` တွင် kit `SidebarTrigger` (shell ၏ တစ်ခုတည်းသော sidebar toggle)၊ Keak `ProductSwitcher` နှင့် command-palette opener ပါဝင်သည်။ `#main-content` အတွင်း kit `PageHeader` (`.ci-page-header`) mount မလုပ်ထားသည့်အချိန်တွင်သာ route title ကို ပြသသောကြောင့် ကိုယ်ပိုင် `PageHeader` ပါသည့် page တွင် `h1` တစ်ခုတည်းသာ ရှိသည်။ `src/shared/components/CommandPalette.tsx` သည် kit `Dialog` ဖြစ်သည်။
- **Icon များ။** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) သည် screen များက အသုံးပြုသော Material Symbols ဝေါဟာရစုမှ အမည်ကို `ICON_MAP` (`src/shared/constants/iconMap.ts`) မှတစ်ဆင့် Lucide glyph တစ်ခုသို့ resolve လုပ်သည်။ Material Symbols font နှင့် package ကို ဖယ်ရှားပြီးဖြစ်သည်။ Map တွင် မပါသော အမည်တစ်ခုသည် neutral placeholder glyph (`data-icon-missing="true"`) ကို render လုပ်ပြီး production မဟုတ်သည့်အချိန်တွင် console warning တစ်ခုကို log လုပ်သည်။ `npm run gen:icon-map` သည် အသုံးပြုနေသော်လည်း map တွင် မပါသေးသော အမည်များကို ထုတ်ပြသည် (`tests/unit/icon-map-coverage.test.ts` သည် Lucide icon မရှိသော အမည်တစ်ခုခုအတွက် fail ဖြစ်သည်။ `tests/unit/icon-map-object-values.test.ts` သည် lookup object များအတွင်း သိမ်းထားသော အမည်များကို စစ်ဆေးသည်)။ `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` သည် literal `<span className="material-symbols-outlined">` span များကို `<Icon>` အဖြစ် ပြန်ရေးသည်။

1. `src/shared/components/index.tsx` ၏ public API ကို ထိန်းသိမ်းထားပါ — export အမည်များ၊ default export များနှင့် လက်ခံသည့် props များ အတူတူဖြစ်ရမည်။ legacy props များကို adapter အတွင်းတွင် kit ပေါ်သို့ map လုပ်ပါ (`Button.tsx` ကို ကြည့်ပါ: `VARIANT_TO_KIT`,

## 5. ပစ္စည်းအစုံကို အပ်ဒိတ်လုပ်ခြင်း။

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` တွင်ထိုးထားသောဗားရှင်းကို upstream repo ၏နောက်ဆုံးထွက် `v*` tag နှင့် နှိုင်းယှဉ်ပြီး ထွက်ရှိလာသောအခါတွင် ထပ်တူကျသည့်အမိန့်ကို ပရင့်ထုတ်သည်။

နေ့စဉ် `UI Kit upstream watch` အလုပ်အသွားအလာ (`.github/workflows/ui-kit-upstream-watch.yml`) သည် တူညီသောစစ်ဆေးမှုကို လုပ်ဆောင်သည်။ ပင်နံပါတ်နောက်တွင်၊ `scripts/ci/ui-kit-sync-pr.sh` အမြင့်ဆုံး `release/vX.Y.Z` အကိုင်းအခက်နှင့် အဖွင့်တစ်ပြိုင်တည်းဖြစ်သော PR တစ်ခုကို လှိမ့်လိုက်သောကိုင်းဆက် `chore/ui-kit-sync-latest` တွင် ထားရှိထားသည်။ ၎င်းသည် ဘယ်တော့မှ ပေါင်းစပ်မည်မဟုတ်ပါ- အစုံလိုက်ထုတ်လွှတ်မှုတိုင်းသည် local VPS တွင် အမြင်အာရုံစစ်ဆေးမှု လိုအပ်နေသေးသည်။ အသစ်ထွက်ပြီး အခြားနည်းဖြင့် အထီးကျန်နေချိန်တွင် ဌာနခွဲကို ပြန်လည်တည်ဆောက်ပါသည်။ လက်ဖြင့်တွန်းထားသော ကတိကဝတ်များပါသော အဖွင့် PR ထပ်မရေးဘဲ၊ ပြုပြင်ထိန်းသိမ်းသူမှ ပိတ်ထားသော ပေါင်းစပ်မထားသော ဗားရှင်းအတွက် PR အသစ်ထွက်သည့်အချိန်အထိ ပိတ်ထားသည်။

PR ကိုဖွင့်၍မရသောအခါ (ပစ်မှတ်ထုတ်လွှတ်မှုကို အေးခဲသွားသည်၊ PR လက်ဖြင့်တွန်းထုတ်သည်၊ PR ပိတ်ထားသည်၊ သို့မဟုတ် PR တိုကင်ကိုမသတ်မှတ်ထားပါ) အလုပ်အသွားအလာသည် အဘယ်ကြောင့်ဆိုသော် ခြေရာခံခြင်းပြဿနာကို ဖွင့်ထားစေသည်။

အလုပ်အသွားအလာတွင် လျှို့ဝှက်ချက်နှစ်ခုကို အသုံးပြုသည်-

- `secrets.UI_KIT_READ_TOKEN`: သီးသန့် upstream repo အတွက် ဖတ်ရန်-သီးသန့် တိုကင်။ အလုပ်အသွားအလာကို အထက်စီးကြောင်းကို မဖတ်နိုင်သောအခါ (တိုကင်မရှိ၊ အလုပ်မလုပ်တော့သည့် သို့မဟုတ် GitHub မရနိုင်ပါ) run သည် အစိမ်းရောင်ရှိနေသော်လည်း သတိပေးချက်တစ်ခုရေးသားပြီး သီးခြားပြဿနာတစ်ခုကို ဖွင့်ထားကာ ၎င်းသည် နောက်မှပြေးပြီးသည်နှင့် ၎င်းကိုယ်တိုင်ပိတ်သွားပါက အထက်သို့ပြန်ဖတ်နိုင်သည်။
- `secrets.UI_KIT_SYNC_PR_TOKEN`: Contents and Pull Requests ဖြင့် ဝင်ရောက်ရေးသားခွင့် တောင်းဆိုချက်များပါရှိသော ဤသိုလှောင်ခန်းရှိ အနုစိတ်သော တိုကင်တစ်ခု။ မူရင်း `GITHUB_TOKEN` ဤနေရာတွင် PRs ဖန်တီး၍မရပါ၊ ၎င်းကိုဖွင့်ထားသော PR CI အစပျိုးမည်မဟုတ်ပါ။ ဤသင်္ကေတမပါဘဲ အလုပ်အသွားအလာသည် ဌာနခွဲကိုသာ တွန်းပို့သည်။

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` `src/` commit တွင် (`latest` = the newest `v*` tag) ကို `packages/ui-kit/src` သို့ ကူးယူသည်၊ ခွင့်ပြုထားသော အသွင်ပြောင်းမှုကို အသုံးပြုသည် (၎င်းသည် `.js` ၏ နောက်ဆက်တွဲကို ဆက်စပ်တင်သွင်းမှုများမှ ရုပ်သိမ်းသွားသည်) နှင့် `packages/ui-kit/package.json` နှင့် `package-lock.json` တွင် workspace ဗားရှင်းကို upstream တစ်ခုသို့ သတ်မှတ်သည်။ ထို့နောက်- `git diff packages/ui-kit` ပြန်လည်သုံးသပ်ပါ၊ ပံ့ပိုးပေးသူများ၊ ဆက်တင်များ၊ ပေါင်းစပ်မှုများ၊ အသုံးပြုမှုနှင့် အဆုံးမှတ်ကို အပြင်အဆင်နှစ်ခုလုံးတွင် ပြုလုပ်ပါ၊ `npm run check:ui-kit-snapshot` နှင့် `npm run test:vitest:ui` ကိုဖွင့်ပါ၊ နှင့် PR ကို upstream changelog ဖြင့်ဖွင့်ပါ။

## 6. README ပုံချပ်များ

အမြစ် `README.md` မြှုပ်နှံမှု (`docs/diagrams/*.svg`) ဇယား ၁၂ ခုသည် ပုံသဏ္ဍာန်တစ်ခုအတွက် အသုံးပြုထားသည့် အစုံဖြစ်ပြီး ၎င်းတို့ကို လက်ဖြင့်ရေးဆွဲခြင်းမဟုတ်ဘဲ ထုတ်ပေးသည်- `scripts/docs/gen-readme-*.mjs` တွင် ဂျင်နရေတာဖိုင် 13 ဖိုင် (12 ပုံတွဲနှင့် `gen-readme-diagrams.mjs` ဒရိုက်ဗာ) နှင့် `tests/unit/docs/readme-*-svg.test.ts` တွင် staleness စမ်းသပ်မှု 12 ခု၊ ဖိုင်တစ်ခုလျှင် တစ်ခုစီ ကတိပြုထားသည့် byte-commator ဖြင့် ၎င်း၏ပုံသေပုံတစ်ခုလျှင် တစ်ခု၊ `test-unit`)

- **တိုကင်များ။** `scripts/docs/readme-diagram-theme.mjs` `packages/ui-kit/src/ci-tokens.css` မှ palette ကိုမိတ္တူကူးသည် (ထိုဖိုင်နှင့် `tests/unit/docs/readme-diagram-theme.test.ts` ဖြင့် ပင်ထိုးထားသည်) နှင့် kit အမျိုးအစားစကေးပေါ်ရှိ စာသားအခန်းကဏ္ဍများကို သတ်မှတ်သည်- kit's weights (400/500/600, display at 500) တွင် Switzer နှင့် ကုဒ်ကဏ္ဍများ (`.cmd`, `.term`, `.term-lg`, `.mono-sm`), Mon မှလွဲ၍ အရာအားလုံးအတွက် IBM ၎င်းသည် commands၊ URLs `.mono` identifiers နှင့် terminal screens အတွက်သာဖြစ်သည် `.mono-xs` အလင်းတန်ဖိုးများသည် `:root`၊ `prefers-color-scheme: dark` နောက်ကွယ်ရှိ အမှောင်တန်ဖိုးများ ၊ ဖိုင်အတွင်းတွင် ရှိနေသည်၊ ထို့ကြောင့် ပုံတစ်ပုံချင်းစီသည် GitHub ရှိ ကြည့်ရှုသူ၏ အစီအစဉ်ကို လိုက်နာသည်။
- **ဖောင့်များ။** GitHub Markdown သည် CSS မပါရှိဘဲ camo proxy သည် ပြင်ပထုတ်ယူမှုတိုင်းကို ပိတ်ဆို့ထားသောကြောင့် kit type သည် ဖိုင်အတွင်းတွင် ရှိနေရမည်ဖြစ်သည်။ `scripts/docs/readme-outline.mjs`၊ ဂျင်နရေတာတိုင်း၏နောက်ဆုံးအဆင့်သည် Switzer ၏အခန်းကဏ္ဍများကို HarfBuzz ဖြင့်ပုံဖော်ပြီး ၎င်းတို့ကို vector မျဉ်းကြောင်းများ (`<defs>` လမ်းကြောင်းများနှင့် `<use>`) အဖြစ် မြှားများနှင့် ဂျီဩမေတြီသင်္ကေတများ Switzer သည် ၎င်း၏ကိုယ်ပိုင်မက်ထရစ်များပေါ်တွင် ရေးဆွဲခြင်းမရှိပါ။ အကြမ်းဖျင်းများ၊ ထည့်သွင်းထားသောဖောင့်ကို ဘယ်သောအခါမှ- Switzer ၏လိုင်စင် (`packages/ui-kit/src/fonts/FFL.txt`) သည် စာဖြင့်ခွင့်ပြုချက်မရှိဘဲ ဖော်မတ်ပြောင်းလဲခြင်းကိုတားမြစ်ထားပြီး vector ပုံများကိုခွင့်ပြုသောကြောင့် Switzer `@font-face` သို့မဟုတ် `data:` URI ကို ပြန်လည်မိတ်ဆက်ခြင်းမပြုပါနှင့်။ ဖိုင်တစ်ခုတွင် ကျန်ခဲ့သော ဖောင့်တစ်ခုသည် အဆိုပါ စာလုံးများမှ တည်ဆောက်ထားသည့် အစစ်အမှန်ကုဒ်စာသား (`scripts/docs/readme-fonts.mjs`) အတွက် OFL IBM Plex Mono အခွဲဖြစ်သည်။ မည်သည့် glyph သည် ပစ်ခြင်းကို မြှပ်ထား၍ မရပါ။
- **ပြန်ထုတ်ပါ။** `npm run docs:readme-diagrams` တစ်ဆယ့်နှစ်ခုလုံးကို README အမှာစာဖြင့် ပြန်လည်ရေးသားပြီး ဖိုင်တစ်ခုလျှင် စာကြောင်းတစ်ကြောင်းကို ၎င်း၏အရွယ်အစားဖြင့် ပရင့်ထုတ်သည်။ တစ်ခုတည်းသော ဂျင် `docs/architecture/QUALITY_GATES.md` → တာတစ်ခု `open-sse/config/freeModelCatalog.ts`၎င်း၏ကိုယ်ပိုင်စနစ်ဖြင့် လုပ်ဆောင်သည် (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` CI `node --import tsx/esm` `docs-sync-strict` ဂျင်နရေတာ နှင့် SVG ကို အတူတကွ ချိတ်ဆက်ပါ။
- **သက်သေ။** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` သည် ဖိုင်တစ်ခုကို GitHub ထမ်းဆောင်ပုံ ( `<img>` တဂ်၊ camo ၏ `Content-Security-Policy`၊ `image/svg+xml`) ၊ အလင်းနှင့် အမှောင်ဘောင်ကို ဖမ်းယူပြီး ပြင်ပဖောင့်တောင်းဆိုမှုများကို အစီရင်ခံသည် (၀ ဖြစ်ရပါမည်)။
- **ဘတ်ဂျက်။** ဖိုင်တစ်ခုလျှင် KB 200 အောက်တွင် (staleness test တစ်ခုစီက ၎င်းကို အခိုင်အမာဖော်ပြသည်); 500 KB သည် မည်သည့် README ပုံ ( SVG studio validator ၏ စည်းမျဉ်း) အတွက် hard cap ဖြစ်သည်။
- **မပြောင်းလဲဘဲ ကော်ပီကို ဂိတ်မှရေတွက်ပါ။** တံဆိပ်ပြောင်းထားသော အမျိုးအစားနှင့် ပျဉ်ချပ်သည် စကားလုံးများမဟုတ်ဘဲ အမျိုးအစားဖြစ်သည်- မီးစက်တစ်ခုစီသည် ၎င်း၏ပုံသေပုံ၏မိတ္တူကို `*_COPY` စဉ်ဆက်မပြတ် (သို့မဟုတ် ၎င်းကို တိုက်ရိုက်ထုတ်သည့်ကတ်တလောက်မှ တည်ဆောက်သည်) တွင် စာသားနှင့် အကြမ်းဖျဉ်းအဆင့်၏ ထည့်သွင်းချက်နှစ်ခုစလုံးကို သယ်ဆောင်သည်။ Canonical ကိန်းဂဏာန်းများသည် `<text>` node များတွင် ရှိနေသည် (တခါက မမြင်နိုင်သော၊ `fill-opacity:0`) ကို `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) ဖြင့်ဖတ်သည်။ gate reads ၏ staleness tests များသည် generated file တွင် ၎င်း၏ validators များကို run သည် ၊ ထို့ကြောင့် code မှ လွင့်မျောနေသော ကိန်းဂဏန်းသည် test — gate ဖတ်သော source ကို fix ပြီး generator ရှိ နံပါတ်ကို ဘယ်သောအခါမှ မဖြေရှင်းပါ။
