## ၁။ အရာများ တည်ရှိရာနေရာ

- **Kit။** `packages/ui-kit/src` သည် `packages/ui-kit/UPSTREAM.md` တွင် သတ်မှတ်ထားသော commit ရှိ upstream `src/` ၏ byte-for-byte မိတ္တူဖြစ်ပြီး၊ အဆိုပါဖိုင်တွင် လိုင်စင်ခွင့်ပြုချက်ကိုလည်း မှတ်တမ်းတင်ထားသည်။ `PATCHES.md` တွင် local patch များကို စာရင်းပြုစုထားသည် (မရှိပါ)။ ၎င်းကို source အဖြစ် အသုံးပြုပြီး build မလုပ်ပါ။ `next.config.mjs` က ၎င်းကို transpile လုပ်ပေးပြီး၊ `tsconfig.json` က `@omniroute/ui-kit` → `packages/ui-kit/src` နှင့် `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` အဖြစ် map လုပ်ထားသည် (`vitest.config.ts` နှင့် `vitest.mcp.config.ts` တွင်လည်း အလားတူ alias ရှိသည်)။ Kit component တစ်ခုကို ၎င်း၏ subpath (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) မှတစ်ဆင့်သာ import လုပ်ပါ။ `@omniroute/ui-kit` barrel မှတစ်ဆင့် မလုပ်ပါနှင့်။ အကြောင်းမှာ barrel သည် importer တစ်ခုချင်းစီထဲသို့ component အားလုံး (date picker အပါအဝင်) ကို ထည့်သွင်းပေးသောကြောင့် ဖြစ်သည်။ Kit stylesheet သည် `src/app/globals.css` (`@import "../../packages/ui-kit/src/ci-styles.css"`) မှတစ်ဆင့် ဝင်ရောက်သည်။ ၎င်းသည် အပြည့်အစုံသော stylesheet ဖြစ်ပြီး core `ci-ui.css` နှင့် pattern family အားလုံး ပါဝင်သည်။
- **Tokens။** `packages/ui-kit/src/ci-tokens.css` တွင် `--ci-*` token များကို ကြေညာထားသည်။ `src/app/globals.css` က ၎င်းတို့ကို legacy OmniRoute အမည်များ (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) နှင့် ချိတ်ဆက်ပေးသောကြောင့် ရှိပြီးသား `var(--color-*)` အသုံးပြုမှုများနှင့် Tailwind utility များ ဆက်လက်အလုပ်လုပ်သည်။ Code အသစ်တွင် Tailwind utility များ (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) သို့မဟုတ် kit class များကို အသုံးပြုပါ — hex value ကို မည်သည့်အခါမျှ မသုံးပါနှင့် (`tests/unit/design-kit-bridge.test.ts` က bridge ကို စစ်ဆေးအတည်ပြုသည်)။ `text-primary` သည် `--text-color-primary` မှတစ်ဆင့် `--color-primary-ink` သို့ resolve လုပ်သောကြောင့် primary text သည် ဖတ်ရှုရလွယ်ကူနေသည်။ တစ်ချိန်တည်းတွင် `bg-primary`/`border-primary` တို့က accent surface ကို ဆက်လက်ထိန်းသိမ်းထားသည်။ Editions အောက်တွင် ၎င်းသည် kit ၏ `--ci-color-accent-active` ဖြစ်ပြီး light mode တွင် deep copper `#99562f`၊ dark mode တွင် copper accent ဖြစ်သည်။ Classic အောက်တွင် light mode ၌ lime-800 နှင့် dark mode ၌ lime accent ဖြစ်သည်။ Chart series များသည် `--color-chart-1` … `--color-chart-8` ကို အသုံးပြုပြီး တစ်ခုချင်းစီတွင် text-safe `--color-chart-N-ink` နှင့် opaque `--color-chart-N-subtle` chip tint ပါရှိသည်။ ၎င်းတို့ကို kit series အစီအစဉ် (`ciChartSeriesOrder`) အတိုင်း သတ်မှတ်ထားသည်။
- **Themes။** `<html className="ci-theme">` (`src/app/layout.tsx`) သည် document ကို kit theme ထဲသို့ ဝင်ရောက်စေသည်။ Preference သည် `light`, `dark` သို့မဟုတ် `system` ဖြစ်သည် (`src/shared/constants/appConfig.ts` ရှိ `THEME_CONFIG.defaultTheme = "system"`၊ `system` သည် `prefers-color-scheme` ကို လိုက်နာသည်)။ `src/store/themeStore.ts` ရှိ `applyTheme()` (hydration မတိုင်မီ လုပ်ဆောင်ရန် `src/app/layout.tsx` ထဲတွင် inline ထည့်ထားသော `THEME_BOOT_SCRIPT` ကလည်း အလားတူလုပ်ဆောင်သည်) သည် `data-theme="dark"|"light"` ကို သတ်မှတ်ပြီး `<html>` ပေါ်ရှိ `.dark` class ကို တစ်ပြိုင်နက် toggle လုပ်သည်။ Kit ၏ dark token set သည် `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`) ကို အခြေခံထားသည်။ OmniRoute ၏ ကိုယ်ပိုင် dark override များ (`globals.css` ထဲရှိ `.dark` block) နှင့် legacy Tailwind `dark:` utility များသည် `.dark` class ကို အခြေခံထားသည်။ Accent color preset များ မရှိပါ။ Accent သည် kit ထံမှသာ အမြဲရရှိပြီး၊ ယခင် build တစ်ခုမှ သိမ်းဆည်းထားသော preset ကို store load လုပ်ချိန်တွင် ဖယ်ရှားသည်။
- **Palettes။** နှစ်မျိုးရှိပြီး နှစ်မျိုးစလုံးသည် kit မှ ဖြစ်သည် (`src/shared/constants/appearancePalette.ts`) — default ဖြစ်သော `editions` နှင့် `classic` ဖြစ်သည်။ Editions သည် `<html>` ပေါ်ရှိ kit ၏ `data-ci-appearance="editions"` attribute ဖြစ်ပြီး `ci-ui.css` က import လုပ်ထားသော `ci-editions.css` သည် ၎င်းကို `data-theme` နှင့် ပေါင်းစပ်အသုံးပြုသည်။ Classic သည် attribute မရှိခြင်း ဖြစ်သည်။ Root layout သည် attribute ကို server-render လုပ်သောကြောင့် သိမ်းဆည်းထားသော preference မရှိသူ (သို့မဟုတ် JS မရှိသူ) သည် dashboard၊ login၊ `/status`၊ error page များ၊ `/docs` နှင့် PWA အပါအဝင် surface အားလုံးတွင် Editions ကို ရရှိမည်ဖြစ်သည်။ ရွေးချယ်မှုကို `theme` store (`palette`, `setPalette()`, `applyPalette()` in `src/store/themeStore.ts`) တစ်ခုတည်းတွင် theme ဘေး၌ သိမ်းဆည်းပြီး `THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`၊ layout ၏ `<head>` ထဲတွင် inline ထည့်ထားသည်) က paint မဖြစ်မီ အသုံးချသည်။ သိမ်းဆည်းထားသော palette သည် `"classic"` ဖြစ်သည့်အခါတွင်သာ attribute ကို ဖယ်ရှားသည်။ Root layout အပြင်ဘက်ရှိ `src/app/global-error.tsx` သည်လည်း အလားတူ store မှ ရယူအသုံးချသည်။ `data-ci-appearance` ကို အခြား element တစ်ခုခုတွင် မထည့်ပါနှင့်။ Kit သည် ၎င်းကို `html:root:has([data-ci-appearance="editions"])` ဖြင့် match လုပ်သောကြောင့် descendant တစ်ခုတည်းကပင် document တစ်ခုလုံးကို ပြောင်းလဲစေမည်ဖြစ်သည်။ Editions `data-ci-editions-variant="landing"` variant သည် marketing page များအတွက် ဖြစ်ပြီး dashboard အတွက် မဟုတ်ပါ။

  Browser chrome အတွက် server သည် default ဖြစ်သော Editions ကို `viewport.themeColor` ( `prefers-color-scheme` တစ်ခုစီအတွက် tag တစ်ခု) နှင့် web manifest ထဲတွင် render လုပ်သည် — `src/shared/constants/pwaThemeColors.ts` ရှိ `PWA_THEME_COLORS` သည် Editions `--ci-color-background` (`#f3f1e9` / `#11120f`) ၏ တစ်ခုတည်းသော mirror ဖြစ်ပြီး `tests/unit/pwa-theme-colors.test.ts` က ၎င်းကို `ci-editions.css` နှင့် ချိတ်ဆက်အတည်ပြုထားသည်။ ထို့နောက် live `<meta name="theme-color">` သည် သိမ်းဆည်းထားသော palette နှင့် mode ကို လိုက်နာသည်။ `THEME_BOOT_SCRIPT` က paint မဖြစ်မီ tag များကို ပြန်ရေးပြီး theme store ၏ action များကလည်း ပြောင်းလဲမှုတိုင်းတွင် ၎င်းကို လုပ်ဆောင်သည် (`src/shared/utils/themeColorMeta.ts` ရှိ `resolveThemeColor()` / `applyThemeColor()`၊ `CLASSIC_PAGE_BACKGROUND` ကို kit ၏ `ciTokens` မှ ဖတ်ယူသည်)။ Explicit light/dark theme သတ်မှတ်ထားပါက tag အားလုံးကို ထို mode သို့ သတ်မှတ်သည်။ `system` သည် scheme တစ်ခုစီအတွက် color တစ်မျိုးစီကို ဆက်လက်ထားရှိသည်။ Manifest သည် Editions အတိုင်းပင် ရှိနေသည်။ ၎င်းကို install တစ်ကြိမ်လျှင် တစ်ကြိမ်သာ fetch လုပ်ပြီး preference မပါဝင်ပါ။ Monaco သည် probe တစ်ခု (`monacoKitTheme.ts`) မှတစ်ဆင့် ၎င်း၏ color များကို ဖတ်ယူသည်။ Editions အောက်တွင် kit သည် root မှ Editions light/dark ကို resolve လုပ်သောကြောင့် probe read လုပ်ချိန်တွင် synchronous pass တစ်ကြိမ်အတွက် root `data-theme` ကို ပြောင်းပြန်လှန်သည်။

- **Components (adapters)။** `src/shared/components/index.tsx` သည် OmniRoute component API (အမည်များ၊ default export များနှင့် props များ အတူတူ) ကို ထိန်းသိမ်းထားပြီး ၎င်းနောက်က primitive များသည် kit အပေါ်တွင် တည်ဆောက်ထားသော adapter များဖြစ်သည်။ ၎င်းတို့မှာ forms (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`)၊ overlays နှင့် feedback (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`)၊ structure (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) နှင့် tables (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`) တို့ ဖြစ်သည်။ Adapter တစ်ခုသည် kit component ကို subpath မှ import လုပ်ပြီး legacy props များကို ၎င်းပေါ်သို့ map လုပ်သည်။ ဥပမာ `Button variant="primary"` သည် kit ၏ `default` button ဖြစ်ပြီး (`--ci-button-primary-*` — light mode တွင် inverse surface၊ dark mode တွင် ၎င်း၏ `--ci-color-accent-foreground` ink ပါသော accent)၊ `danger` သည် `destructive` ဖြစ်ကာ `warning` သည် kit ၏ `warning` button ဖြစ်သည်။ `Badge` status variant များသည် kit tone များဖြစ်ပြီး `<option>` child များပါသော `Select` သည် kit ၏ `NativeSelect` ကို render လုပ်သည်။

  Adapter နှစ်ခုကို index မှ မဟုတ်ဘဲ path ဖြင့် import လုပ်သည်။ `InteractiveTableRow` (`src/shared/components/InteractiveTableRow.tsx`) သည် `onActivate` နှင့် `selected` ကို လက်ခံပြီး Tab၊ Enter နှင့် Space ကို တုံ့ပြန်သော kit `TableRow` ဖြစ်သည်။ `CodePreview` (`src/shared/components/CodePreview.tsx`) သည် copy label များကို ဘာသာပြန်ထားသည့် kit code block ဖြစ်သည်။ `tests/unit/ui/adapters/*.test.tsx` သည် adapter တစ်ခုချင်းစီ၏ အပြုအမူကို အတည်ပြုသတ်မှတ်ထားသည်။

- **Shell။** `src/app/(dashboard)/layout.tsx` သည် `DashboardLayout` ကို render လုပ်ပြီး ၎င်းက `src/shared/components/layouts/DashboardShell.tsx` ကို render လုပ်သည်။ ၎င်းတွင် kit ၏ `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`) နှင့် `src/shared/components/Sidebar.tsx` ထဲရှိ OmniRoute ၏ navigation logic ပါဝင်သည်။ `#main-content` သို့ ကျော်သွားရန် link သည် focus လုပ်နိုင်သော ပထမဆုံး element ဖြစ်သည်။ `src/shared/components/Header.tsx` တွင် kit ၏ `SidebarTrigger` (shell ၏ တစ်ခုတည်းသော sidebar toggle)၊ Keak ၏ `ProductSwitcher` နှင့် command-palette opener တို့ ပါဝင်သည်။ `#main-content` အတွင်း kit ၏ `PageHeader` (`.ci-page-header`) မတပ်ဆင်ထားသည့်အချိန်တွင်သာ route title ကို ပြသသဖြင့် ကိုယ်ပိုင် `PageHeader` ပါသော စာမျက်နှာတွင် `h1` တစ်ခုတည်းသာ ရှိသည်။ `src/shared/components/CommandPalette.tsx` သည် kit ၏ `Dialog` ဖြစ်သည်။

## 2. စည်းမျဉ်းများ

1. Literal များမဟုတ်ဘဲ Tokens များကိုသာ အသုံးပြုပါ။ ရည်ရွယ်ချက်ရှိရှိ ချန်လှပ်ထားသော ခြွင်းချက်များမှာ အမြဲတမ်းအမှောင်ဖြစ်သော console terminal နှင့်
   `STATUS_HEX` (`src/shared/constants/statusColors.ts`) တို့ဖြစ်ပြီး၊ ၎င်းသည် literal hex လိုအပ်သော caller များအတွက် kit status
   palette ၏ resolved-hex mirror ဖြစ်သည်။ Categorical palette များသည် ယခုအခါ ခြွင်းချက်မဟုတ်တော့ပါ —
   `src/shared/utils/categoricalPalette.ts` နှင့် routing strategy များအတွက်
   `src/app/(dashboard)/dashboard/combos/strategyPalette.ts` တို့မှတစ်ဆင့် kit ၏ chart token ရှစ်ခု
   (`--color-chart-1..8`, ထို့အပြင် `-ink`/`-subtle`) နှင့် kit series အစီအစဉ်အတိုင်း အသုံးပြုထားသည်။ ReactFlow edge များနှင့် orchestration
   canvas သည် theme-aware `--orch-status-*` variable များကို ဖတ်ယူသည် (`src/shared/components/flow/edgeStyles.ts`)။
2. `packages/ui-kit/src` ကို လက်ဖြင့် မပြင်ပါနှင့် — `scripts/dev/sync-ui-kit.sh <commit>` ဖြင့် sync လုပ်ပါ။ pinned upstream commit နှင့်
   byte တစ်ခုမျှ ကွာခြားပါက pre-commit gate `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) သည် အောင်မြင်မည်မဟုတ်ပါ
   (upstream clone ဖြစ်သော `UI_KIT_CLONE` သို့မဟုတ် `_references/cheaper-inference-ui-kit` မရှိပါက warning ဖြင့်
   skip လုပ်သည်)။ Kit တွင် တစ်စုံတစ်ရာ မပါရှိပါက adapter သို့မဟုတ် screen တွင် workaround လုပ်ပြီး upstream ထံ တောင်းဆိုပါ။
3. Kit text default များသည် English ဖြစ်သည် (`label = "Loading"`, `loadingLabel = "Loading table"`…) — kit component က စာသားကို render လုပ်သည့်အခါတိုင်း
   `useTranslations(...)` မှ ဘာသာပြန်ထားသော string များကို ပေးပါ။
4. Tailwind utility များသည် kit component class များထက် ဦးစားပေးသည် (kit သည်
   `@layer theme, base, components, utilities` ကို သတ်မှတ်ထားပြီး ၎င်း၏ rule များသည် `components` ထဲတွင် ရှိသည်) — kit component များ၏
   အရောင်ကို ပြန်သတ်မှတ်ရန်မဟုတ်ဘဲ spacing နှင့် layout အတွက် utility များကို အသုံးပြုပါ။ Typography သည် ခြွင်းချက်ဖြစ်သည်။
   `packages/ui-kit/src/ci-typography.css` ကို မည်သည့် layer မျှအတွင်းမဟုတ်ဘဲ import လုပ်ထားသောကြောင့် ၎င်း၏ tag rule များသည်

## 5. ပစ္စည်းအစုံကို အပ်ဒိတ်လုပ်ခြင်း။

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` တွင်ထိုးထားသောဗားရှင်းကို upstream repo ၏နောက်ဆုံးထွက် `v*` tag နှင့် နှိုင်းယှဉ်ပြီး ထွက်ရှိလာသောအခါတွင် ထပ်တူကျသည့်အမိန့်ကို ပရင့်ထုတ်သည်။

နေ့စဉ် `UI Kit upstream watch` အလုပ်အသွားအလာ (`.github/workflows/ui-kit-upstream-watch.yml`) သည် တူညီသောစစ်ဆေးမှုကို လုပ်ဆောင်သည်။ ပင်နံပါတ်နောက်တွင်၊ `scripts/ci/ui-kit-sync-pr.sh` အမြင့်ဆုံး `release/vX.Y.Z` အကိုင်းအခက်နှင့် အဖွင့်တစ်ပြိုင်တည်းဖြစ်သော PR တစ်ခုကို လှိမ့်လိုက်သောကိုင်းဆက် `chore/ui-kit-sync-latest` တွင် ထားရှိထားသည်။ ၎င်းသည် ဘယ်တော့မှ ပေါင်းစပ်မည်မဟုတ်ပါ- အစုံလိုက်ထုတ်လွှတ်မှုတိုင်းသည် local VPS တွင် အမြင်အာရုံစစ်ဆေးမှု လိုအပ်နေသေးသည်။ အသစ်ထွက်ပြီး အခြားနည်းဖြင့် အထီးကျန်နေချိန်တွင် ဌာနခွဲကို ပြန်လည်တည်ဆောက်ပါသည်။ လက်ဖြင့်တွန်းထားသော ကတိကဝတ်များပါသော အဖွင့် PR ထပ်မရေးဘဲ၊ ပြုပြင်ထိန်းသိမ်းသူမှ ပိတ်ထားသော ပေါင်းစပ်မထားသော ဗားရှင်းအတွက် PR အသစ်ထွက်သည့်အချိန်အထိ ပိတ်ထားသည်။

PR ကိုဖွင့်၍မရသောအခါ (ပစ်မှတ်ထုတ်လွှတ်မှုကို အေးခဲသွားသည်၊ PR လက်ဖြင့်တွန်းထုတ်သည်၊ PR ပိတ်ထားသည်၊ သို့မဟုတ် PR တိုကင်ကိုမသတ်မှတ်ထားပါ) အလုပ်အသွားအလာသည် အဘယ်ကြောင့်ဆိုသော် ခြေရာခံခြင်းပြဿနာကို ဖွင့်ထားစေသည်။

အလုပ်အသွားအလာတွင် လျှို့ဝှက်ချက်နှစ်ခုကို အသုံးပြုသည်-

- `secrets.UI_KIT_READ_TOKEN`: သီးသန့် upstream repo အတွက် ဖတ်ရန်-သီးသန့် တိုကင်။ အလုပ်အသွားအလာကို အထက်စီးကြောင်းကို မဖတ်နိုင်သောအခါ (တိုကင်မရှိ၊ အလုပ်မလုပ်တော့သည့် သို့မဟုတ် GitHub မရနိုင်ပါ) run သည် အစိမ်းရောင်ရှိနေသော်လည်း သတိပေးချက်တစ်ခုရေးသားပြီး သီးခြားပြဿနာတစ်ခုကို ဖွင့်ထားကာ ၎င်းသည် နောက်မှပြေးပြီးသည်နှင့် ၎င်းကိုယ်တိုင်ပိတ်သွားပါက အထက်သို့ပြန်ဖတ်နိုင်သည်။
- `secrets.UI_KIT_SYNC_PR_TOKEN`: Contents and Pull Requests ဖြင့် ဝင်ရောက်ရေးသားခွင့် တောင်းဆိုချက်များပါရှိသော ဤသိုလှောင်ခန်းရှိ အနုစိတ်သော တိုကင်တစ်ခု။ မူရင်း `GITHUB_TOKEN` ဤနေရာတွင် PRs ဖန်တီး၍မရပါ၊ ၎င်းကိုဖွင့်ထားသော PR CI အစပျိုးမည်မဟုတ်ပါ။ ဤသင်္ကေတမပါဘဲ အလုပ်အသွားအလာသည် ဌာနခွဲကိုသာ တွန်းပို့သည်။

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` `src/` commit တွင် (`latest` = the newest `v*` tag) ကို `packages/ui-kit/src` သို့ ကူးယူသည်၊ ခွင့်ပြုထားသော အသွင်ပြောင်းမှုကို အသုံးပြုသည် (၎င်းသည် `.js` ၏ နောက်ဆက်တွဲကို ဆက်စပ်တင်သွင်းမှုများမှ ရုပ်သိမ်းသွားသည်) နှင့် `packages/ui-kit/package.json` နှင့် `package-lock.json` တွင် workspace ဗားရှင်းကို upstream တစ်ခုသို့ သတ်မှတ်သည်။ ထို့နောက်- `git diff packages/ui-kit` ပြန်လည်သုံးသပ်ပါ၊ ပံ့ပိုးပေးသူများ၊ ဆက်တင်များ၊ ပေါင်းစပ်မှုများ၊ အသုံးပြုမှုနှင့် အဆုံးမှတ်ကို အပြင်အဆင်နှစ်ခုလုံးတွင် ပြုလုပ်ပါ၊ `npm run check:ui-kit-snapshot` နှင့် `npm run test:vitest:ui` ကိုဖွင့်ပါ၊ နှင့် PR ကို upstream changelog ဖြင့်ဖွင့်ပါ။

## ၆။ README ပုံကြမ်းများ

Root `README.md` တွင် ထည့်သွင်းထားသော ပုံကြမ်း ၁၂ ခု (`docs/diagrams/*.svg`) သည် static image တစ်ခုအဖြစ် အသုံးချထားသော kit ဖြစ်ပြီး လက်ဖြင့်ရေးဆွဲထားခြင်းမဟုတ်ဘဲ generate လုပ်ထားခြင်းဖြစ်သည်။ ၎င်းတို့ကို `scripts/docs/gen-readme-*.mjs` ရှိ generator ဖိုင် ၁၃ ခု (ပုံကြမ်း ၁၂ ခုနှင့် `gen-readme-diagrams.mjs` driver) နှင့် ပုံကြမ်းတစ်ခုစီအတွက် တစ်ခုစီဖြစ်သော `tests/unit/docs/readme-*-svg.test.ts` ရှိ staleness test ၁၂ ခုက ထုတ်ပေးသည်။ Test တစ်ခုစီသည် commit လုပ်ထားသောဖိုင်နှင့် ၎င်း၏ generator output ကို byte အဆင့် နှိုင်းယှဉ်စစ်ဆေးသည် (`test-unit` job)။

- **Tokens။** `scripts/docs/readme-diagram-theme.mjs` သည် Editions palette (မူလအသွင်အပြင်) ကို `packages/ui-kit/src/ci-editions.css` မှ ကူးယူသည် (`tests/unit/docs/readme-diagram-theme.test.ts` က ထိုဖိုင်နှင့် ချိတ်ဆက်စစ်ဆေးပြီး scheme နှစ်ခုလုံးရှိ surface တစ်ခုချင်းစီပေါ်ရှိ စာသားအရောင်တိုင်းအတွက် WCAG AA ကိုလည်း စစ်ဆေးသည်။ တစ်ခုတည်းသော ခြွင်းချက်မှာ light `warn` ဖြစ်ပြီး kit ၏တန်ဖိုးသည် canvas ပေါ်တွင် 4.46:1 ဖြစ်သောကြောင့် kit warning ကို 10 % မှောင်အောင် ပြုလုပ်ထားသည်)။ ထို့အပြင် kit ၏ type scale (`ci-tokens.css`) အပေါ်တွင် စာသား role များကို သတ်မှတ်သည်။ Switzer ကို kit ၏ weight များ (400/500/600၊ display အတွက် 500) နှင့် အရာအားလုံးအတွက် tracking အသုံးပြုထားပြီး၊ code role များ (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`) အတွက်မူ IBM Plex Mono ကိုသာ အသုံးပြုသည်။ ထို code role များသည် command များ၊ URL များ၊ identifier များနှင့် terminal screen များအတွက်သာ ဖြစ်သည်။
  Light တန်ဖိုးများသည် `:root` ပေါ်တွင်ရှိပြီး dark တန်ဖိုးများသည် ဖိုင်အတွင်းရှိ `prefers-color-scheme: dark` နောက်ကွယ်တွင် ရှိသည်။ ထို့ကြောင့် image တစ်ခုချင်းစီသည် GitHub ပေါ်ရှိ ကြည့်ရှုသူ၏ scheme ကို လိုက်နာသည်။
- **Fonts။** GitHub Markdown တွင် CSS မပါဝင်သည့်အပြင် camo proxy က external fetch အားလုံးကို ပိတ်ထားသောကြောင့် kit type သည် ဖိုင်အတွင်း၌ ပါဝင်သွားရမည်။ Generator တိုင်း၏ နောက်ဆုံးအဆင့်ဖြစ်သော `scripts/docs/readme-outline.mjs` သည် Switzer role များကို HarfBuzz ဖြင့် ပုံသဏ္ဌာန်ဖော်ပြီး vector outline များ (`<defs>` paths နှင့် `<use>`) အဖြစ် ဆွဲပေးသည်။ ထို့အပြင် Switzer တွင် မရှိသော arrow များနှင့် geometric symbol များကိုလည်း ၎င်း၏ metric များဖြင့် သီးခြားဆွဲပေးသည်။ Embedded font မဟုတ်ဘဲ outline များကိုသာ အသုံးပြုရမည်။ Switzer ၏ licence (`packages/ui-kit/src/fonts/FFL.txt`) သည် စာဖြင့်ခွင့်ပြုချက်မရှိဘဲ subsetting နှင့် format conversion ကို တားမြစ်ထားပြီး vector drawing များကို ခွင့်ပြုထားသောကြောင့် Switzer `@font-face` သို့မဟုတ် `data:` URI ကို ပြန်လည်မထည့်ရပါ။ ဖိုင်တစ်ခုအတွင်း ကျန်ရှိသည့် တစ်ခုတည်းသော font သည် အမှန်တကယ် code text အဖြစ် ကျန်ရှိသည့်အရာများအတွက် OFL IBM Plex Mono subset ဖြစ်ပြီး (`scripts/docs/readme-fonts.mjs`) ထိုစာလုံးများမှ build လုပ်ထားသည်။ ထည့်သွင်း၍မရသော glyph တစ်ခုခုရှိပါက error ဖြစ်ပေါ်စေသည်။
- **Regenerate။** `npm run docs:readme-diagrams` သည် README အစီအစဉ်အတိုင်း ပုံကြမ်း ၁၂ ခုလုံးကို ပြန်လည်ရေးသားပြီး ဖိုင်တစ်ခုစီအတွက် size ပါသော စာကြောင်းတစ်ကြောင်းစီကို ထုတ်ပြသည်။ Generator တစ်ခုချင်းစီကိုလည်း သီးခြား run နိုင်သည် (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` ၏ figures များသည် live catalog loader `open-sse/config/freeModelCatalog.ts` မှ ရရှိသောကြောင့် `node --import tsx/esm` လိုအပ်သည်။ Catalog ပြောင်းလဲမှု၏ CI အကျိုးဆက်ကို `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict` တွင် ကြည့်နိုင်သည်)။ Generator နှင့် SVG ကို အတူ commit လုပ်ရမည်။
  Release mode တွင် stale SVG သည် fail ဖြစ်စေသည်။ Feature PR တစ်ခုတွင် `npm run check:generated-artifacts` သည် PR က ပြင်ဆင်ထားသော SVG တစ်ခုတည်းကိုသာ စစ်ဆေးသည် (`docs/architecture/QUALITY_GATES.md` → "Generated files and derived baselines")။
- **Proof။** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` သည် GitHub က serve လုပ်သည့်ပုံစံအတိုင်း ဖိုင်တစ်ခုကို render လုပ်သည် (`<img>` tag၊ camo ၏ `Content-Security-Policy`၊ `image/svg+xml`)။ ထို့နောက် light frame နှင့် dark frame တစ်ခုစီကို capture လုပ်ပြီး page က ပြုလုပ်ခဲ့သော external font request များကို report ပြသည် (အရေအတွက် 0 ဖြစ်ရမည်)။
- **Budget။** ဖိုင်တစ်ခုစီအတွက် 200 KB အောက် ဖြစ်ရမည် (staleness test တစ်ခုစီက ၎င်းကို assert လုပ်သည်)။ README image တစ်ခုအတွက် 500 KB သည် အမြင့်ဆုံးကန့်သတ်ချက်ဖြစ်သည် (SVG studio validator ၏ rule)။
- **Copy unchanged, counts from the gate။** Rebrand ပြုလုပ်မှုသည် စာသားများကိုမဟုတ်ဘဲ type နှင့် palette ကိုသာ ပြောင်းလဲထားသည်။ Generator တစ်ခုစီတွင် ၎င်း၏ပုံကြမ်းအတွက် copy ကို `*_COPY` constant အတွင်း ထည့်ထားသည် (သို့မဟုတ် live catalog မှ တည်ဆောက်ထားသည်)။ ထို copy သည် ဆွဲသားမည့်စာသားဖြစ်သကဲ့သို့ outlining အဆင့်၏ input လည်း ဖြစ်သည်။ Canonical figure များသည် `<text>` node များအတွင်းတွင် ဆက်လက်ရှိနေသည် (outline ပြုလုပ်ပြီးနောက် မမြင်ရတော့ဘဲ `fill-opacity:0` ဖြစ်သည်)။ ထို node များကို `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) က ဖတ်ရှုသည်။ Read ကို gate လုပ်သည့် ပုံကြမ်းများ၏ staleness test များသည် generate လုပ်ထားသောဖိုင်ပေါ်တွင် ၎င်း၏ validator များကိုလည်း run သောကြောင့် figure သည် code နှင့် ကွဲလွဲသွားပါက test fail ဖြစ်မည် — Generator အတွင်းရှိ number ကို မပြင်ဘဲ gate က ဖတ်ရှုသည့် source ကိုသာ ပြင်ရမည်။
