## 1. အရာများ တည်ရှိရာနေရာ

- **Kit.** `packages/ui-kit/src` သည် `packages/ui-kit/UPSTREAM.md` (license authorization ကိုလည်း မှတ်တမ်းတင်ထားသည်) တွင် pin လုပ်ထားသော commit ရှိ upstream `src/` ၏ byte-for-byte မိတ္တူတစ်ခုဖြစ်သည်။ `PATCHES.md` တွင် local patch များ (မရှိပါ) ကို စာရင်းပြုစုထားသည်။ Build မလိုဘဲ source အနေဖြင့် သုံးစွဲသည်— `next.config.mjs` က ၎င်းကို transpile လုပ်ပေးပြီး `tsconfig.json` က `@omniroute/ui-kit` → `packages/ui-kit/src` နှင့် `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` သို့ map လုပ်ထားသည် (`vitest.config.ts` နှင့် `vitest.mcp.config.ts` တွင်လည်း alias အတိုင်း ပါဝင်သည်)။ Kit component တစ်ခုကို ၎င်း၏ subpath (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) ဖြင့် import လုပ်ပါ၊ `@omniroute/ui-kit` barrel မှတဆင့် ဘယ်သောအခါမျှ မလုပ်ပါနှင့်— barrel သည် component အားလုံး (date picker အပါအဝင်) ကို importer တိုင်းထဲသို့ ဆွဲသွင်းသည်။ Kit stylesheet သည် `src/app/globals.css` (`@import "../../packages/ui-kit/src/ci-ui.css"`) မှတဆင့် ဝင်ရောက်သည်။
- **Tokens.** `packages/ui-kit/src/ci-tokens.css` က `--ci-*` token များကို ကြေညာထားသည်။ `src/app/globals.css` က ၎င်းတို့ကို legacy OmniRoute အမည်များ (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) သို့ တံတားဆက်ပေးထားသဖြင့် လက်ရှိ `var(--color-*)` ဖတ်ရှုမှုများနှင့် Tailwind utility များ ဆက်လက်အလုပ်လုပ်နိုင်သည်။ ကုဒသစ်များသည် Tailwind utility များ (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) သို့မဟုတ် kit class များကို အသုံးပြုသည်— hex တန်ဖိုးကို ဘယ်သောအခါမျှ မသုံးပါနှင့် (`tests/unit/design-kit-bridge.test.ts` က bridge ကို enforce လုပ်ထားသည်)။ `text-primary` သည် `--text-color-primary` မှတဆင့် `--color-primary-ink` သို့ resolve ဖြစ်သည် (light mode တွင် lime-800၊ dark mode တွင် lime accent)၊ ထို့ကြောင့် `bg-primary`/`border-primary` များ lime surface ကို ဆက်လက်ထိန်းသိမ်းနေစဉ် primary text သည် ဖတ်ရလွယ်ကူနေဆဲဖြစ်သည်။ Chart series များသည် `--color-chart-1` … `--color-chart-5` ကို အသုံးပြုသည်။
- **Themes.** `<html className="ci-theme">` (`src/app/layout.tsx`) သည် document ကို kit theme ထဲသို့ opt-in လုပ်စေသည်။ Preference မှာ `light`, `dark` သို့မဟုတ် `system` ဖြစ်သည် (`src/shared/constants/appConfig.ts` ရှိ `THEME_CONFIG.defaultTheme = "system"`; `system` သည် `prefers-color-scheme` ကို လိုက်နာသည်)။ `src/store/themeStore.ts` ရှိ `applyTheme()` (`src/app/layout.tsx` ရှိ inline bootstrap script က mirror လုပ်ထားပြီး hydration မတိုင်ခင် run သည်) က `data-theme="dark"|"light"` ကို သတ်မှတ်ပြီး `<html>` ပေါ်ရှိ `.dark` class ကို အတူတကွ toggle လုပ်သည်။ Kit ၏ dark token set သည် `data-theme="dark"` ပေါ်တွင် key ချထားသည် (`packages/ui-kit/src/ci-tokens.css`)။ OmniRoute ၏ ကိုယ်ပိုင် dark override များ (`globals.css` ရှိ `.dark` block) နှင့် legacy Tailwind `dark:` utility များသည် `.dark` class ပေါ်တွင် key ချထားသည်။ Accent color preset များ မရှိပါ— accent သည် အမြဲတမ်း kit မှလာပြီး build အဟောင်းတစ်ခုမှ persist လုပ်ထားသော preset ကို store load လုပ်သောအခါ စွန့်ပစ်သည်။
- **Components (adapters).** `src/shared/components/index.tsx` သည် OmniRoute component API (အမည်များ၊ default export များနှင့် props များ အတိုင်း) ကို ထိန်းသိမ်းထားပြီး ၎င်း၏နောက်ကွယ်ရှိ primitive များသည် kit ပေါ်ရှိ adapter များဖြစ်သည်— forms (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`)၊ overlays နှင့် feedback (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`)၊ structure (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) နှင့် tables (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`)။ Adapter တစ်ခုသည် kit component ကို subpath ဖြင့် import လုပ်ပြီး legacy props များကို ၎င်းပေါ်သို့ map လုပ်သည်— ဥပမာအားဖြင့် `Button variant="primary"` သည် kit ၏ `default` button ဖြစ်သည် (`--ci-button-primary-*`: light mode တွင် inverse surface၊ dark mode တွင် ၎င်း၏ `--ci-color-accent-foreground` ink ပါသော accent)၊ `danger` သည် `destructive` ဖြစ်ပြီး `warning` သည် `outline` ပေါ် `.ci-button--warning` extension ပေါင်းထည့်ထားခြင်း ဖြစ်သည်။ `globals.css` (`@layer components`) ၏ အဆုံးရှိ `.ci-button--warning` နှင့် `.ci-badge[data-tone]` rule များသည် kit class များပေါ်ရှိ OmniRoute extension များဖြစ်သည်။ `tests/unit/ui/adapters/*.test.tsx` က adapter တစ်ခုချင်းစီကို pin လုပ်ထားသည်။
- **Shell.** `src/app/(dashboard)/layout.tsx` သည် `DashboardLayout` ကို render လုပ်ပြီး ၎င်းက `src/shared/components/layouts/DashboardShell.tsx` ကို render လုပ်သည်— kit `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`) ဖြစ်ပြီး OmniRoute ၏ navigation logic မှာ `src/shared/components/Sidebar.tsx` တွင်ရှိသည်။ `#main-content` သို့ "skip to content" link သည် ပထမဆုံး focusable element ဖြစ်သည်။ `src/shared/components/Header.tsx` တွင် kit `SidebarTrigger` (shell ၏ တစ်ခုတည်းသော sidebar toggle)၊ Keak `ProductSwitcher` နှင့် command-palette opener တို့ ပါဝင်ပြီး kit `PageHeader` (`.ci-page-header`) တစ်ခုမျှ `#main-content` အတွင်း၌ mount လုပ်မထားသေးချိန်တွင် သာ route title ကို ပြသည်။ ထို့ကြောင့် ကိုယ်ပိုင် `PageHeader` ရှိသော page တစ်ခုတွင် `h1` တစ်ခုတည်း ရှိသည်။ `src/shared/components/CommandPalette.tsx` သည် kit `Dialog` တစ်ခုဖြစ်သည်။
- **Icons.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) သည် အမည် (screen များအသုံးပြုသော Material Symbols ဝေါဟာရ) ကို `ICON_MAP` (`src/shared/constants/iconMap.ts`) မှတဆင့် Lucide glyph တစ်ခုသို့ resolve လုပ်သည်။ Material Symbols font နှင့် package များ မရှိတော့ပါ— map ထဲတွင် မပါဝင်သော အမည်တစ်ခုသည် neutral placeholder glyph (`data-icon-missing="true"`) ကို render လုပ်ပြီး production အပြင်တွင် console warning တစ်ခု log လုပ်သည်။ `npm run gen:icon-map` က map ထဲတွင် မပါဝင်သော အသုံးပြုနေသော အမည်များကို print ထုတ်ပေးသည် (`tests/unit/icon-map-coverage.test.ts` သည် Lucide icon မရှိသော အမည်တစ်ခုခုတွင် fail ဖြစ်သည်။ `tests/unit/icon-map-object-values.test.ts` သည် lookup object များတွင် သိမ်းဆည်းထားသော အမည်များကို cover လုပ်သည်)။ `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` က literal `<span className="material-symbols-outlined">` span များကို `<Icon>` သို့ ပြင်ဆင်ရေးသားပေးသည်။
- **Brand.** `src/shared/components/OmniRouteLogo.tsx` သည် kit ကို wrap လုပ်ထားသည်— default export `OmniRouteLogo` သည် `ProductIcon product="omniroute" variant="glyph"` (inline SVG၊ `basePath`-safe) ကို render လုပ်ပြီး `OmniRouteLockup` သည် `ProductLockup product="omniroute"` (accessible name "Keak OmniRoute") ကို render လုပ်သည်၊ သို့မဟုတ် white-label operator များအတွက် ၎င်းတို့ကိုယ်ပိုင် `name`/`logoSrc` ကို render လုပ်သည်။ Product-switcher ဦးတည်ရာများသည် `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`) တွင် ရှိသည်။ Standalone screen များ— `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` နှင့် `src/shared/components/ErrorPageScaffold.tsx` — သည် lockup ကို ပြသပြီး `tests/unit/brand-pages-static.test.ts` က ၎င်းကို စောင့်ကြည့်ကာကွယ်ထားသည်။

## 2. စည်းမျဉ်းများ

1. Token များသာ သုံးပါ၊ literal တန်ဖိုးများ ဘယ်တော့မှ မသုံးပါနှင့်။ ရည်ရွယ်ချက်ဖြင့် ထားရှိထားသော
   ခြွင်းချက်များမှာ- အမြဲမည်းနေသော console terminal၊ `STATUS_HEX`
   (`src/shared/constants/statusColors.ts`) မှတစ်ဆင့် ReactFlow SVG stroke များ၊ နှင့်
   အမျိုးအစားအလိုက် palette များဖြစ်သော `STRATEGY_COLORS`
   (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) နှင့်
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`)
   တို့ဖြစ်သည်။
2. `packages/ui-kit/src` ကို လက်ဖြင့် ဘယ်တော့မှ patch မလုပ်ပါနှင့်-
   `scripts/dev/sync-ui-kit.sh <commit>` ဖြင့် sync ချပါ။ pre-commit gate ဖြစ်သော
   `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) သည် pin ချထားသော upstream commit နှင့်
   ကွာခြားသော byte တစ်ခုခု ရှိလျှင် ကျရှုံးသွားမည်ဖြစ်သည် (upstream clone ဖြစ်သော
   `UI_KIT_CLONE` သို့မဟုတ် `_references/cheaper-inference-ui-kit` မရှိသောအခါ သတိပေးချက်တစ်ခုဖြင့်
   ကျော်သွားမည်)။ kit တွင် တစ်ခုခု လိုအပ်နေပါက adapter သို့မဟုတ် screen ထဲတွင်
   workaround လုပ်ပြီး upstream သို့ တောင်းဆိုပါ။
3. Kit ၏ text မူလသတ်မှတ်ချက်များသည် အင်္ဂလိပ်စာဖြစ်သည် (`label = "Loading"`,
   `loadingLabel = "Loading table"`…) — kit component တစ်ခုခုက text ကို render
   လုပ်သောအခါတိုင်း `useTranslations(...)` မှ ဘာသာပြန်ထားသော string များကို လွှဲပေးပါ။
4. Tailwind utility များက kit component class များထက် အနိုင်ရသည် (kit က
   `@layer theme, base, components, utilities` ကို ကြေညာထားပြီး ၎င်း၏ rule များသည်
   `components` ထဲတွင် ရှိသည်) — spacing နှင့် layout အတွက် utility များကို အသုံးပြုပါ၊
   kit component များ၏ အရောင်ကို ပြန်ပြောင်းရန်အတွက် မဟုတ်ပါ။
5. ခေါင်းစဉ်များ- စာမျက်နှာနှင့် အပိုင်း ခေါင်းစဉ်များအတွက် `.ci-heading` (Inter၊ tracking မရှိ)၊
   error-page status code ကဲ့သို့ ကြီးမား၍ နည်းပါးသော display text အတွက်သာ
   `.ci-dashboard-display` (Instrument Serif)။
6. `tests/unit/dashboard-kit-sweep.test.ts` က kit အသုံးပြုမှုကို ကာကွယ်စောင့်ရှောက်သည်-
   `src/app` သို့မဟုတ် `src/shared/components` အောက်တွင် Material ligature span မရှိစေရ၊
   dashboard tree (`src/app/(dashboard)` နှင့် `src/shared/components`) အတွင်းတွင်
   စာရင်းပြ ထားသော ခြွင်းချက်များ (`Select` adapter ၏ native branch၊
   `RequestLoggerDetail`) အပြင်ဘက်တွင် raw `<select>`, `<textarea>` သို့မဟုတ် `<table>`
   မရှိစေရ၊ ကိုယ်ပိုင်ပြုလုပ်ထားသော `role="dialog"` မရှိစေရ၊ ထိုနေရာရှိ raw `<button>` သို့မဟုတ်
   `<input>` တိုင်းတွင် ၎င်း၏အပေါ်ဘက် အများဆုံး ၃ စာကြောင်းအတွင်း ဆုံးသော (အကြောင်းရင်း
   ပါဝင်သော) `kit-exception:` ပါဝင်သော comment လိုအပ်သည်၊ palette hue များနှင့် `dark:`
   variant များကို test က ဖော်ပြထားသော ဖိုင်များတွင်သာ အသုံးပြုရမည်။
7. PR မတင်မီ theme နှစ်ခုလုံးနှင့် 390 px viewport ကို စစ်ဆေးပါ (screenshot များ)၊
   `tests/e2e/a11y.spec.ts` က axe ကို run သည်။

## 3. Screen အသစ်ထည့်ခြင်း

1. Kit `PageHeader` (`@omniroute/ui-kit/page-header`၊ dashboard အတွင်းတွင် `compact`) ဖြင့်
   စာမျက်နှာကို စတင်ပါ — ခေါင်းစဉ်၊ ဖော်ပြချက်နှင့် `actions`။ ထိုအခါ shell header က ၎င်း၏
   ကိုယ်ပိုင်ခေါင်းစဉ်ကို ဖယ်ထုတ်သွားမည်။
2. Control များကို `@/shared/components` (adapter များ) မှ တည်ဆောက်ပြီး adapter
   မရှိရာနေရာများတွင် subpath ဖြင့် kit component များကို အသုံးပြုပါ
   (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`,
   `Slider`…)။
3. Icon များ- `<Icon name="…" />`။ အမည်အသစ်တစ်ခုကို အဓိပ္ပာယ်အရ ကိုက်ညီသော Lucide
   component နှင့် အတူ `ICON_MAP` ထဲသို့ ထည့်ပါ၊ `npm run gen:icon-map` က လစ်နေသေးသော
   အမည်များကို စာရင်းပြ ပြပေးသည်။
4. အရောင်များ- semantic utility များ (`text-success`, `bg-warning-bg`, `border-border`…)
   နှင့် chart series များအတွက် `var(--color-chart-N)`၊ hex တန်ဖိုးများ မသုံးရ၊ အရောင်ကို
   ထပ်ခွာပြောရုံသာသော `dark:` variant များလည်း မသုံးရ။
5. စာသား- kit component များသို့ လွှဲပေးသော label များ အပါအဝင် string တိုင်းသည်
   `useTranslations` မှ လာရမည်။ key အသစ်များကို `src/i18n/messages/en.json`,
   `pt-BR.json` နှင့် `vi.json` ထဲသို့ ထည့်ပါ (Vietnamese parity test က အင်္ဂလိပ် key
   တိုင်းကို pin ချထားသည်)၊ ကျန် locale များကို i18n sync က ဖြည့်ပေးမည်။
6. PR မတင်မီ guard များကို run ပါ- `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (`iconMap.ts` ထဲတွင် ထပ်နေသော import ကို
   ဖမ်းမိနိုင်သော တစ်ခုတည်းသော စစ်ဆေးမှု), `npm run check:ui-icu`၊ နှင့် ၎င်း screen ၏
   ကိုယ်ပိုင် test များ။

## 4. Adapter ထည့်သွင်းခြင်း သို့မဟုတ် ပြောင်းလဲခြင်း

1. `src/shared/components/index.tsx` ၏ public API ကို ထိန်းသိမ်းထားပါ- export အမည်များ၊ default export
   များနှင့် လက်ခံထားသော prop များ အတူတူ ဖြစ်နေရမည်။ Legacy prop များကို adapter အတွင်းမှ kit သို့
   map လုပ်ပါ (`Button.tsx` ကို ကြည့်ပါ- `VARIANT_TO_KIT`, `SIZE_TO_KIT`)။
2. Kit ကို subpath ဖြင့် import လုပ်ပါ (`@omniroute/ui-kit/<component>`)။
3. Kit ၏ gap များအတွက် workaround များသည် adapter အတွင်းတွင် (သို့မဟုတ် ပြင်ဆင်ချက်က style
   ဖြစ်နေပါက `globals.css` ၏ `@layer components` အတွင်းတွင်) ရှိစေရမည်၊ `packages/ui-kit/src`
   အတွင်းတွင် ဘယ်တော့မှ မရှိရ။
4. `tests/unit/ui/adapters/<name>.test.tsx` ကို ထည့်သွင်းပါ သို့မဟုတ် update လုပ်ပါ။ Caller များ
   များပြားသော adapter တစ်ခုအတွက်၊ ပြောင်းလဲမှုမပြုလုပ်မီနှင့် ပြုလုပ်ပြီးနောက် render လုပ်ထားသော
   markup ကို နှိုင်းယှဉ်ပါ — padding သို့မဟုတ် wrapper ပြောင်းလဲမှုများသည် screen တိုင်းသို့
   ပျံ့နှံ့သွားသည်။

## 5. Kit ကို update လုပ်ခြင်း

`scripts/dev/sync-ui-kit.sh <commit> [clone]` သည် ထို commit ရှိ upstream `src/` ကို
`packages/ui-kit/src` အတွင်းသို့ ကူးယူပြီး ခွင့်ပြုထားသော တစ်ခုတည်းသော transformation ကို apply
လုပ်သည် (relative import များမှ `.js` suffix ကို ဖယ်ရှားပေးသည်)။ ထို့နောက်- `git diff
packages/ui-kit` ကို review လုပ်ပါ၊ theme နှစ်မျိုးလုံးတွင် providers, settings, combos, usage
နှင့် endpoint ကို visual pass ပြုလုပ်ပါ၊ `npm run check:ui-kit-snapshot` နှင့် `npm run
test:vitest:ui` ကို run ပါ၊ ပြီးလျှင် upstream changelog နှင့်အတူ PR ကို ဖွင့်ပါ။
