> `scanner.ts`, `loader.ts`), `src/app/api/plugins/` နှင့်
> `src/app/(dashboard)/dashboard/plugins/`
> **နောက်ဆုံး အပ်ဒိတ်လုပ်ထားသည့်ရက်:** 2026-06-28 — v3.8.40

OmniRoute တွင် WordPress ပုံစံ plugin စနစ်တစ်ခု ပါဝင်သည်။ Plugin များသည်
သီးခြားရပ်တည်နိုင်သော directory များဖြစ်ပြီး တစ်ခုစီတွင် `plugin.json` manifest နှင့် entry file တစ်ခုပါရှိကာ request pipeline (`onRequest` / `onResponse` / `onError`) နှင့်
lifecycle event များ (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`) ကို
ချိတ်ဆက်အသုံးပြုသည်။

**Plugin Marketplace** သည် အဆိုပါစနစ်၏ အပေါ်တွင်ရှိသော ရှာဖွေတွေ့ရှိမှု layer ဖြစ်သည်။ ၎င်းသည်
ထည့်သွင်းနိုင်သော plugin များ၏ ကြည့်ရှုရှာဖွေနိုင်သည့် catalog တစ်ခုကို ဖော်ပြပေးသည်။ မူလအတိုင်း catalog သည်
အသင့်ပါရှိသော seed registry အသေးစားတစ်ခုဖြစ်ပြီး၊ operator တစ်ဦးက ၎င်းကို စိတ်ကြိုက် remote
registry URL သို့ ညွှန်ပြနိုင်သည်။ ထိုသို့ပြုလုပ်ပါက fetch ကို DNS ဖြင့် ဖြေရှင်းစစ်ဆေးသော SSRF guard ဖြင့်
ပိုမိုလုံခြုံအောင် ပြုလုပ်ထားသည် ([လုံခြုံရေး](#security) ကို ကြည့်ပါ)။

Plugin route တိုင်းသည် **loopback-only** (Tier 1 — `LOCAL_ONLY`) ဖြစ်သည်။ Plugin များသည်
child process များအတွင်း code ကို load လုပ်ပြီး execute လုပ်သောကြောင့် auth ရှိသည်ဖြစ်စေ မရှိသည်ဖြစ်စေ
loopback မဟုတ်သော origin မှ route များကို ရောက်ရှိအသုံးပြု၍မရပါ။
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) ကို ကြည့်ပါ။

## Together ဘယ်လို လိုက်ဖက်လဲ။

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **Registry အလွှာ** — `src/lib/plugins/marketplace.ts`: စာရင်းများ / ကက်တလောက်ကိုရှာဖွေသည်၊ မည်သည့်ပျက်ကွက်မှုတွင်မျိုးစေ့မှတ်ပုံတင်ခြင်းသို့ပြန်ကျသွားသည်
- **Lifecycle အလွှာ** — `src/lib/plugins/manager.ts` (`pluginManager` singleton ) : ထည့်သွင်း၊ အဆင့်မြှင့်တင်၊ အသက်သွင်း၊ ပိတ်လိုက်၊ ဖြုတ်လိုက်၊ စကင်န်ဖတ်၊ စတင်လုပ်ဆောင်ပါ။
- **Manifest အလွှာ** — `src/lib/plugins/manifest.ts`: Zod schema + သည် `plugin.json` အတွက် ပုံသေများ။
- **စကင်နာ** — `src/lib/plugins/scanner.ts`: plugin လမ်းညွှန်အောက်ရှိ disk ပေါ်ရှိ ပလပ်အင်များကို ရှာဖွေတွေ့ရှိသည်။
- **Loader** — `src/lib/plugins/loader.ts`: သီးခြား Node.js ကလေးလုပ်ငန်းစဉ်တွင် ပလပ်အင်တစ်ခုစီကို ထုတ်ပေးပြီး ပွဲစားများက IPC ဖြင့် ဖုန်းခေါ်ဆိုမှုများကို ချိတ်သည်။ ကလေးသည် sandbox မဟုတ်ပါ။ (အောက်ပါ "Plugin execution isolation" ကိုကြည့်ပါ)။

## Marketplace Catalog

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) သည်
`MarketplaceEntry` object များ၏ စာရင်းတစ်ခုကို ပြန်ပေးသည်-

| Field         | Type     | မှတ်ချက်များ                                    |
| ------------- | -------- | ----------------------------------------------- |
| `name`        | string   | kebab-case plugin အမည်                          |
| `version`     | string   | semver                                          |
| `description` | string   | အကျဉ်းချုပ်                                     |
| `author`      | string   | ရေးသားသူ / အဖွဲ့အစည်း                           |
| `license`     | string   | SPDX ပုံစံ license id                           |
| `downloadUrl` | string   | Source download URL (ဗလာဖြစ်နိုင်သည်)           |
| `repository`  | string?  | ထည့်သွင်းရန်မလိုသော repository URL              |
| `tags`        | string[] | ရှာဖွေခြင်း/စစ်ထုတ်ခြင်းဆိုင်ရာ tag များ        |
| `downloads`   | number   | Download အရေအတွက်                               |
| `rating`      | number   | 0–5                                             |
| `verified`    | boolean  | entry ကို အတည်ပြုပြီးဟု မှတ်သားထားခြင်း ရှိမရှိ |
| `lastUpdated` | string   | ISO ပုံစံနှင့် ဆင်တူသော ရက်စွဲ string           |

စိတ်ကြိုက် registry URL ကို configure မလုပ်ထားပါက catalog သည် အသင့်ပါရှိသော
`SEED_REGISTRY` (လက်ရှိတွင် `request-logger`, `rate-limiter`, `cost-tracker` နှင့်
`theme-manager`) ဖြစ်သည်။ Seed registry ကို အမြဲတမ်း အသုံးပြုနိုင်သည် — configure လုပ်ထားသော remote
registry သို့ ဆက်သွယ်၍မရခြင်း၊ `200` မဟုတ်သော status ကို ပြန်ပေးခြင်း သို့မဟုတ် အသိအမှတ်မပြုနိုင်သော
body ကို ပြန်ပေးခြင်း ဖြစ်ပါက `listMarketplacePlugins()` သည် သတိပေးချက်တစ်ခုကို log လုပ်ပြီး seed list ကို အစားထိုးအသုံးပြုသည်။

> မှတ်ချက်- marketplace **catalog** (ကြည့်ရှုခြင်း/ရှာဖွေခြင်း) ကို အစမှအဆုံး ချိတ်ဆက်အကောင်အထည်ဖော်ထားသော်လည်း
> catalog မှ တစ်ချက်နှိပ်၍ marketplace **ထည့်သွင်းခြင်း** ကို အကောင်အထည်မဖော်ရသေးပါ — marketplace entry တစ်ခုရှိ
> dashboard ၏ "ထည့်သွင်းရန်" button သည် လက်ရှိတွင်
> "မကြာမီ ရရှိမည်" ဟူသော အသိပေးချက်ကို ပြသသည်။ ယနေ့အချိန်တွင် ထည့်သွင်းခြင်းကို local-path install
> flow (`POST /api/plugins`) နှင့် disk ပေါ်ရှိ plugin များကို ရှာဖွေဖော်ထုတ်ခြင်း (`POST /api/plugins/scan`) မှတစ်ဆင့် ပြုလုပ်ရသည်။

## REST API

အဆုံးမှတ်အားလုံးသည် စီမံခန့်ခွဲမှု အထောက်အထား (`requireManagementAuth`) လိုအပ်သည်** နှင့်** loopback-only — `/api/plugins` နှင့် `/api/plugins/` `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) တွင် ဖော်ပြထားပါသည်။

| အဆုံးမှတ်                          | နည်းလမ်း | ဖော်ပြချက်                                                                            |
| ---------------------------------- | -------- | ------------------------------------------------------------------------------------- |
| `/api/plugins`                     | GET      | ထည့်သွင်းထားသော ပလပ်အင်များကို စာရင်းပြုစုပါ (ရွေးချယ်နိုင်သော `?status=` စစ်ထုတ်မှု) |
| `/api/plugins`                     | POST     | ပလပ်အင်အရင်းအမြစ်လမ်းညွှန်မှ ပလပ်အင်တစ်ခုကို ထည့်သွင်းပါ။                             |
| `/api/plugins/scan`                | POST     | ပလပ်အင်လမ်းညွှန်ကို စကန်ဖတ်ပြီး ပလပ်အင်အသစ်များကို စာရင်းသွင်းပါ။                     |
| `/api/plugins/marketplace`         | GET      | စျေးကွက် ကတ်တလောက်ကို စာရင်းပြုစုပါ။                                                  |
| `/api/plugins/marketplace/install` | POST     | အမည်ဖြင့် စျေးကွက်ပလပ်အင်ကို ထည့်သွင်းပါ။                                             |
| `/api/plugins/[name]`              | GET      | ထည့်သွင်းထားသော ပလပ်အင်အသေးစိတ်အချက်အလက်များကို ရယူပါ။                                |
| `/api/plugins/[name]`              | DELETE   | ပလပ်အင်ကို ဖြုတ်ပါ။                                                                   |
| `/api/plugins/[name]/activate`     | POST     | အသက်သွင်းရန် ( + မှတ်ပုံတင်ချိတ်များကို တင်ပါ)                                        |
| `/api/plugins/[name]/deactivate`   | POST     | ပိတ်ပါ (မီး `onDeactivate`၊ ချိတ်ကို စာရင်းမသွင်းပါ)                                  |
| `/api/plugins/[name]/config`       | GET      | plugin config + config schema ကိုရယူပါ။                                               |
| `/api/plugins/[name]/config`       | PUT      | plugin config ကို အပ်ဒိတ်လုပ်ပါ (schema နှင့် ကိုက်ညီသည်)                             |

`GET /api/plugins` `status` စစ်ထုတ်မှုသည် `installed` / `active` / `inactive` / `error` ထဲမှ တစ်ခုကို လက်ခံသည်။ မမှန်ကန်သောတန်ဖိုးသည် `400` ပြန်ပေးသည်။

### ထည့်သွင်းထားသော ပလပ်အင်များကို စာရင်းပြုစုပါ။

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### ဒေသန္တရလမ်းကြောင်းမှ ထည့်သွင်းပါ။

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` an ဖြစ်ရမည်။** ပကတိ** လမ်းညွှန်တစ်ခုသို့လမ်းကြောင်း** plugin အရင်းအမြစ်များလမ်းညွှန်အတွင်း** ပလပ်အင် root ၏ဘေးတွင် `plugin-sources` ၊ ထို့ကြောင့် မူရင်းအားဖြင့် `~/.omniroute/plugin-sources/` သို့မဟုတ် ထိုပြောင်းလဲမှုအား သတ်မှတ်သည့်အခါ `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` (`getPluginSourcesDir()` in `src/lib/plugins/installSource.ts`)။ အဲဒီမှာ ပလပ်အင်ကို ကော်ပီကူးပါ သို့မဟုတ် ပုံတူပွားပါ။ လမ်းကြောင်းတွင် `..` သို့မဟုတ် null byte ပါ၀င်သောအခါ၊ အဆိုပါလမ်းညွှန်အပြင်ဘက်တွင်တည်ရှိသည်၊ symlink မှတဆင့်၎င်း၏အပြင်ဘက်တွင်ဖြေရှင်းသည်၊ ၎င်းအပြင်ဘက်တွင်ပစ်မှတ်ရှိသော symlink တစ်ခုပါရှိသည်၊ သို့မဟုတ် directory မရှိသည့်အခါတွင်ထည့်သွင်းမှုကို `400` ဖြင့်ငြင်းဆိုထားသည်။ ရင်းမြစ်လမ်းညွှန်တွင် မှန်ကန်သော `plugin.json` (သို့မဟုတ် တစ်ခု၏ မိဘဖြစ်ရမည်) ပါဝင်ရပါမည်။ အောင်မြင်သောအခါတွင် ထည့်သွင်းထားသော plugin အတန်းနှင့်အတူ တုံ့ပြန်မှုသည် `201` ဖြစ်သည်။

အခြားပလပ်အင်လမ်းကြောင်းများနှင့်မတူဘဲ၊ ဤတစ်ခုသည် အကောင့်ဝင်ခြင်းကိုပိတ်ထားသည့်တိုင် (`requireLogin=false`) : ကုဒ်ထည့်သွင်းခြင်းသည် အမည်မသိလုပ်ဆောင်ချက် ဘယ်တော့မှမဟုတ်သည့် စီမံခန့်ခွဲမှုဆိုင်ရာအထောက်အထား (ဒက်ရှ်ဘုတ်စက်ရှင် သို့မဟုတ် စီမံခန့်ခွဲသည့် API ကီးတစ်ခု) လိုအပ်ပါသည်။ `POST /api/plugins/marketplace/install` (body `{ "name": "<plugin>" }`) နှင့် အလားတူသည်။

### ဈေးကို လိုက်ကြည့်ပါ။

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### plugin config ကို အပ်ဒိတ်လုပ်ပါ။

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` validates the body against the plugin's `configSchema` (declared in the manifest) with `validatePluginConfig()` from `src/lib/plugins/manifest.ts`: every key must be declared in the schema, values must match the declared type, `number` fields honor `min`/`max`, and `select` fields must match the declared `enum`. Any violation returns `400` and nothing is stored. A plugin that declares no `configSchema` has no configurable keys, so the request is refused with `400` ("Plugin does not declare any configurable keys").

## ဖွဲ့စည်းသတ်မှတ်မှု

### Plugin directory

Plugin များသည် OmniRoute data directory အောက်တွင် ရှိသည်-

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (သို့မဟုတ် manifest.main က ညွှန်းဆိုသည့် မည်သည့်အရာမဆို)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) သည် အဆိုပါ directory ကို
အဆင့်သုံးဆင့်ဖြင့် သတ်မှတ်သည်-

1. **`OMNIROUTE_PLUGINS_DIR`** ကို သတ်မှတ်ထားလျှင် — `HOME` က မည်သို့ဆိုသည်ဖြစ်စေ မပြောင်းလဲဘဲ တိုက်ရိုက်အသုံးပြုသည်။ ၎င်းသည်
   plugin tree ကို container ၏ home directory နှင့် အများအားဖြင့် မသက်ဆိုင်သော path တစ်ခုတွင်
   bind-mount လုပ်ထားသည့် Docker/K8s အတွက် တိကျရှင်းလင်းသော ထိန်းချုပ်မှုဖြစ်သည် (#11827)။
2. `<home>/.omniroute/plugins`၊ ဤနေရာရှိ `<home>` ကို `HOME` / `USERPROFILE`
   environment variable များမှ ရယူသည်။
3. Process က home ကို လုံးဝ export မလုပ်ထားလျှင် `/tmp/.omniroute/plugins`။

ဆုံးဖြတ်ရရှိသော directory ကို startup တွင် `scanner.dir_resolved` အဖြစ် တစ်ကြိမ် log မှတ်တမ်းတင်ပြီး
မည်သည့် input က အနိုင်ရခဲ့သည် (`OMNIROUTE_PLUGINS_DIR`, `home`, သို့မဟုတ် `no-home-fallback`) ကို ဖော်ပြသည် — ထို့ကြောင့်
အဆင့် 3 သို့ မသိမသာ ရောက်သွားသော image တစ်ခုသည် plugin စာရင်းအလွတ်ကိုသာ အစီရင်ခံမည့်အစား
ထိုအကြောင်းကို ဖော်ပြပေးသည်။
`POST /api/plugins/scan` သည် ထိုနေရာတွင် မှန်ကန်သော
`plugin.json` ပါရှိသည့် subdirectory တစ်ခုစီကို ရှာဖွေပြီး မှတ်ပုံတင်သည်။ အလားတူ directory သည်
`pluginManager.install()` က plugin များကို ကူးယူထည့်သွင်းသည့် root လည်းဖြစ်သောကြောင့် override တစ်ခုက ရှာဖွေခြင်းနှင့်
ထည့်သွင်းခြင်းတို့ကို အတူတကွ ရွှေ့ပေးသည်။

> **`OMNIROUTE_PLUGINS_DIR` သည် `OMNIROUTE_PLUGIN_PATH` မဟုတ်ပါ။** နောက်တစ်ခုကို
> `omniroute` subcommand များ ထည့်ပေးသည့် `omniroute-cmd-*` npm
> package များကို ရှာဖွေရန် CLI command-plugin loader (`bin/cli/plugins.mjs`) ကသာ ဖတ်ရှုသည် — ဤနေရာတွင်
> ဖော်ပြထားသော runtime scanner အပေါ် မည်သည့်သက်ရောက်မှုမျှ မရှိပါ။ ထိုအပိုင်းအတွက် [PLUGINS.md](./PLUGINS.md) ကို ကြည့်ပါ။

## လုံခြုံရေး

### အဆင့် — loopback လမ်းကြောင်းသာ

ပလပ်အင်များသည် ပေါက်ဖွားလာသော ကလေးလုပ်ငန်းစဉ်များတွင် ကုဒ်ကို လုပ်ဆောင်သောကြောင့် `/api/plugins` မျက်နှာပြင်တစ်ခုလုံးကို `LOCAL_ONLY` (Tier 1) ဖြင့် ခွဲခြားထားသည်။ Loopback ကျင့်သုံးမှုသည် ခြွင်းချက်မရှိ လုပ်ဆောင်သည်။** မီ** မည်သည့် auth check မဆို၊ ထို့ကြောင့် ပေါက်ကြားနေသော စီမံခန့်ခွဲမှု တိုကင်သည် ဥမင်လိုဏ်ခေါင်းတစ်ခုပေါ်ရှိ အကွက်သို့ရောက်ရှိနေသည့် ပလပ်အင်ကို ထည့်သွင်းခြင်း၊ စတင်ခြင်း သို့မဟုတ် ဖြုတ်ခြင်းမပြုနိုင်ပါ။ [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) နှင့် Hard Rules #15 / #17 ကိုကြည့်ပါ။

### Marketplace registry SSRF အစောင့်အရှောက်

စိတ်ကြိုက် registry URL သည် တိုက်ခိုက်သူ-သြဇာလွှမ်းမိုးနိုင်သော ဖွဲ့စည်းမှုစနစ်ဖြစ်သည်၊ ထို့ကြောင့် `listMarketplacePlugins()` ကို မရယူမီ အလွှာနှစ်ဆင့်ဖြင့် လုပ်ဆောင်သည်-

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` မဟုတ်သော မည်သည့်အရာကိုမဆို ငြင်းပယ်သည်။
   - ပကတိ private/loopback/link-local/ULA hosts (IPv4** နှင့်** IPv6, IPv4-mapped အပါအဝင် ) canonical `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) မှတဆင့်။
   - ဖြေရှင်းသည်။** နှစ်ခုလုံး** `A` နှင့် `AAAA` မှတ်တမ်းများနှင့် if ကို ငြင်းပယ်သည်။** တစ်ခုခု** ဖြေရှင်းထားသော လိပ်စာသည် သီးသန့် — ဖြစ်ပြီး public-hostname → private-IP ကို ရှောင်ကွင်းပိတ်ပါသည်။
   - **ပျက်ကွက်ပိတ်** : DNS ကြည်လင်ပြတ်သားမှု ပျက်ကွက်သည် URL ကို ငြင်းပယ်သည်။
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`) : အများသူငှာ သီးသန့် URL အစောင့်ကို ထုတ်ယူသည့်အချိန်နှင့် ပြန်လည်အသုံးချသည်။** blocks များကို ပြန်ညွှန်းသည်။** (အများပြည်သူ → သီးသန့် `30x` pivot မရှိပါ။

အလွှာတစ်ခုခုမှ ပျက်ကွက်သည့် URL သည် တောင်းဆိုချက် — မဖျက်ဘဲ ဈေးသည် တပ်ဆင်ထားသော မျိုးစေ့မှတ်ပုံတင်ခြင်းသို့ တိတ်တဆိတ် ပြန်ကျသွားပြီး သတိပေးချက်ကို မှတ်တမ်းတင်ပါသည်။

> A + AAAA ဖြေရှင်းရန် ဤအစောင့်ကို PR #3774 တွင် ခိုင်မာစေပြီး IPv4-only စစ်ဆေးခြင်းအစား canonical `isPrivateHost` အသုံးပြုပါ။

### ပလပ်အင်လုပ်ဆောင်မှု သီးခြားခွဲထုတ်ခြင်း။

> **ပလပ်အင်များကို မူရင်းအတိုင်း သဲပုံးပြုလုပ်ထားခြင်းမရှိပါ။** ကလေးသည် OmniRoute အသုံးပြုသူအဖြစ် လုပ်ဆောင်နေသည့် သာမန် Node.js လုပ်ငန်းစဉ်တစ်ခုဖြစ်ပြီး VM ဆက်စပ်မှုမရှိဘဲ Node.js ခွင့်ပြုချက်အလံများမရှိသောကြောင့် ပလပ်အင်ကုဒ်သည် အသုံးပြုသူလုပ်ဆောင်နိုင်သည့် မည်သည့်ဖိုင်ကိုမဆို ဖတ်နိုင်၊ ပရိုဂရမ်များကို လုပ်ဆောင်နိုင်ပြီး ကွန်ရက်သို့ရောက်ရှိနိုင်သည်။ `requires.permissions` ကလေးလက်ခံရရှိသည့် ပတ်ဝန်းကျင်ပြောင်းလဲမှုများကိုသာ ဆုံးဖြတ်သည်၊ အခြားခွင့်ပြုချက်များကို ပြဋ္ဌာန်းထားခြင်းမရှိပါ။ ရွေးချယ်မှုတွင် `PLUGIN_PERMISSION_MODEL_ENABLED` အင်္ဂါရပ်အလံ (မူလအားဖြင့် ပိတ်သည်) သည် `network` Node.js န့်သတ်၍မရသော အဆိုပါခွင့်ပြုချက်များမှတည်ဆောက်ထားသော Node.js ခွင့်ပြုချက်ပုံစံအောက်တွင် ပလပ်အင်တစ်ခုစီကို လုပ်ဆောင်သည် ( [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#permission-system) ကြည့်ပါ)။ သင်ယုံကြည်ရသော ပလပ်အင်များကိုသာ ထည့်သွင်းပါ။ အောက်ဖော်ပြပါ လုပ်ငန်းစဉ်နယ်နိမိတ်တွင် ပျက်စီးမှုများနှင့် ကြိုးဆွဲချမှုများပါရှိသည်။ လုံခြုံရေးနယ်နိမိတ် မဟုတ်ပါ။

- **လုပ်ငန်းစဉ် အထီးကျန်** — `loadPlugin()` (`src/lib/plugins/loader.ts`) သည် သီးခြား Node.js ကလေးလုပ်ငန်းစဉ်တွင် ပလပ်အင်တစ်ခုစီကို မွေးမြူပြီး IPC နှင့် ဆက်သွယ်သည်။ Hook ခေါ်ဆိုမှုများတွင် `SIGTERM` → `SIGKILL` အရှိန်မြှင့်ခြင်းဖြင့် အချိန်ကုန်သွားပါသည်။
- **Env ခွင့်ပြုစာရင်း** — လေးသည် ခွင့်ပြုထားသော ပတ်၀န်းကျင် ပြောင်းလဲနိုင်သော အစုအဝေးတစ်ခုသာ ရရှိသည်၊ မန်နီးဖက်စ်မှ `env` ခွင့်ပြုချက်ကို တောင်းဆိုသောအခါမှသာ ပိုမိုကျယ်ပြန့်သော set ကို ခွင့်ပြုသည်။
- **အရင်းအမြစ်ထိန်းချုပ်မှုကို ထည့်သွင်းပါ။** — `POST /api/plugins` plugin ရင်းမြစ်များလမ်းညွှန်မှသာဖတ်သည် ("ဒေသခံလမ်းကြောင်းတစ်ခုမှထည့်သွင်းပါ" ကိုကြည့်ပါ- လမ်းကြောင်းကို `realpath` ဖြင့် canonicalized လုပ်ထားပြီး၊ ထိုလမ်းညွှန်အတွင်းတွင် တင်းကြပ်စွာရှိနေရမည်ဖြစ်ပြီး မည်သည့်အရာမှမကူးယူမီ ၎င်းကိုမကူးယူမီ symlink ပါရှိသည့် အရင်းအမြစ်သစ်ပင်တစ်ခု။
- **လမ်းကြောင်းထိန်း** — install/upgrade/uninstall သည် plugin directory နှင့် `manifest.main` ဖြေရှင်းကြောင်းအခိုင်အမာဆိုသည်။** အတွင်း** ကော်ပီ သို့မဟုတ် ထပ်ခါတလဲလဲ မဖျက်မီ စီမံခန့်ခွဲထားသော plugin root သည် (ဆော့ကစားထားသော DB လမ်းကြောင်းများနှင့် `manifest.main` တွင် `../` ဖြတ်သွားခြင်းကို ကာကွယ်သည်)။ အသက်သွင်းခြင်းသည် `realpath` မှတဆင့် symlinks များကိုဖြေရှင်းပြီး plugin directory ကိုလွတ်သွားသော entry point တစ်ခုကို load လုပ်ရန်ငြင်းဆိုသည်။
- **ရွေးချယ်နိုင်သော သမာဓိရှိ ပင်** — မန်နီးဖက်စ်တွင် `integrity` (`sha256-<base64>`၊ SRI ဖော်မတ်) အကွက်တစ်ခုကို ကြေညာနိုင်သည်။ လက်ရှိအချိန်တွင်၊ loader သည် load time တွင် entry file hash ကိုစစ်ဆေးပြီး မတိုက်ဆိုင်မှုတွင် စဖွင့်ရန် ငြင်းဆန်သည်။ ၎င်းသည် opt-in tamper-detection၊** မဟုတ်ဘူး** လုံခြုံရေးနယ်နိမိတ်တစ်ခု- ၎င်းသည် loaded plugin တစ်ခုလုပ်ဆောင်နိုင်သည်ကို ကန့်သတ်မထားပေ။
- **ချိတ်များတွင် သုံးစွဲသူအထောက်အထားများ မရှိပါ။** — `onRequest` သို့ ဖြတ်သွားသော စကားစပ် ၊ `onResponse` နှင့် `onError` တွင် `authorization`၊ `x-api-key`၊ `proxy-authorization` နှင့် `cookie` ခေါင်းစီးများကို ဖယ်ရှားပြီး API သော့မှတ်တမ်းသည် သော့တန်ဖိုးမရှိပါ (`redactPluginContext()` in `src/lib/plugins/hooks.ts`)။

## မန်နီးဖက်စ် (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) မှ အတည်ပြုထားသည် ။

| လယ်ကွင်း           | ရိုက်ပါ။        | မှတ်စုများ                                                    |
| ------------------ | --------------- | ------------------------------------------------------------- |
| `name`             | ကြိုးတစ်ချောင်း | လိုအပ်သည်; kebab-case (`^[a-z0-9-]+$`) 1-100 စာလုံးများ       |
| `version`          | ကြိုးတစ်ချောင်း | လိုအပ်သည်; semver (`MAJOR.MINOR.PATCH`)                       |
| `description`      | ကြိုးတစ်ချောင်း | ≤ 500 စာလုံးများ                                              |
| `author`           | ကြိုးတစ်ချောင်း | ≤ 200 စာလုံးများ                                              |
| `license`          | ကြိုးတစ်ချောင်း | ပုံသေသည် `MIT` သို့ဖြစ်သည်။                                   |
| `main`             | ကြိုးတစ်ချောင်း | ဝင်ခွင့်ဖိုင်; `index.js` ကို ပုံသေသတ်မှတ်သည်။                |
| `source`           | enum?           | `local` \| `marketplace` (မူရင်း `local` သို့ )               |
| `tags`             | string[]?       | တက်ဂ်များကို ရှာဖွေပါ။                                        |
| `requires`         | အရာဝတ္ထု?       | `{ omniroute?, permissions[] }`                               |
| `hooks`            | အရာဝတ္ထု?       | မည်သည့်ပလပ်အင်ကို ချိတ်ထားသည်ကို ဘော်လီယန်များက ကြေညာသည်။     |
| `skills`           | အရာဝတ္ထု[]?     | ရွေးချယ်နိုင်သောကျွမ်းကျင်မှု အဓိပ္ပါယ်ဖွင့်ဆိုချက်များ       |
| `enabledByDefault` | ဘူလီယံ?         | တပ်ဆင်မှုတွင် အလိုအလျောက် စဖွင့်ပါ။                           |
| `configSchema`     | အရာဝတ္ထု?       | config အကွက်များမြေပုံ (`string`/`number`/`boolean`/`select`) |
| `integrity`        | ကြိုးတစ်ချောင်း | ရွေးချယ်နိုင်သော `sha256-<base64>` entry-file pin             |

ခွင့်ပြုချက်များကို enum `network` / `file-read` / `file-write` / `env` / `exec` မှထုတ်ယူသည်။ `env` သာလျှင် runtime အကျိုးသက်ရောက်မှု (ကလေးအတွက် အနည်းငယ်ပိုကြီးသော ပတ်ဝန်းကျင်-ပြောင်းလဲနိုင်သော ခွင့်ပြုစာရင်း) အခြားအရာများသည် ကြေငြာချက်များဖြစ်ပြီး ပြဌာန်းထားခြင်းမရှိပါ။

## ဘဝစက်ဝန်း စီးဆင်းမှု

```
install (POST /api/plugins, လမ်းကြောင်း)
  → manifest ကို စကင်ဖတ်/စစ်ဆေး → staging သို့ ကူးယူ → main သည် directory အတွင်း ရှိကြောင်း အတည်ပြု
  → ~/.omniroute/plugins/<name> သို့ atomic rename ပြုလုပ် → DB row ထည့်သွင်း
  → onInstall ကို စတင်ခေါ်ယူ → enabledByDefault ဖြစ်ပါက activate ပြုလုပ်

activate (POST /api/plugins/{name}/activate)
  → realpath ပါဝင်မှု စစ်ဆေး → loadPlugin() (child process စတင်)
  → ကြေညာထားသော hooks များကို မှတ်ပုံတင် → status = "active" → onActivate ကို စတင်ခေါ်ယူ

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate ကို စတင်ခေါ်ယူ (မှတ်ပုံတင်မှု မဖြုတ်မီ) → hooks များ၏ မှတ်ပုံတင်မှုကို ဖြုတ်
  → child process ကို ရပ်တန့် → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → active ဖြစ်ပါက deactivate ပြုလုပ် → onUninstall ကို စတင်ခေါ်ယူ
  → ပါဝင်မှုကို စစ်ဆေးထားသော plugin directory ကို recursive ဖျက် → DB row ကို ဖျက်
```

ထည့်သွင်းထားသော version ထက် manifest version က **အတိအကျ ပိုသစ်သော**
directory တစ်ခုအပေါ် `install` ကို ထပ်မံလုပ်ဆောင်ပါက အလိုအလျောက် upgrade
ပြုလုပ်သည် (သန့်ရှင်းစွာ ပြန်လည်ထည့်သွင်းခြင်းဖြစ်ပြီး config များသည် default
တန်ဖိုးများသို့ ပြန်သတ်မှတ်မည်)။ တူညီသော သို့မဟုတ် ပိုဟောင်းသော version ကို ပယ်ချမည်။

## ဒိုင်ခွက်

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) ရှိ ဒက်ရှ်ဘုတ်စာမျက်နှာတွင် တက်ဘ်နှစ်ခုပါရှိသည်-

- **တပ်ဆင်ထားသည်။** — ၎င်းတို့၏ကြေငြာချိတ်များ၊ activate/deactivate ခလုတ်၊ ဖြုတ်ရန်ခလုတ်၊ နှင့် "ပလပ်အင်များအတွက် စကင်န်ဖတ်ရန်" လုပ်ဆောင်ချက် (`POST /api/plugins/scan`) တို့ဖြင့် ထည့်သွင်းထားသည့် ပလပ်အင်များကို စာရင်းပြုစုထားသည်။
- **ဈေး** — စိတ်ကြိုက် registry URL ကို သတ်မှတ်ရန် အကွက်တစ်ခုဖြင့် `GET /api/plugins/marketplace` မှ ကတ်တလောက်ကို ပြသသည်။

စာမျက်နှာသည် OmniRoute လုပ်ငန်းစဉ်၏ အခွင့်ထူးများ အပြည့်ဖြင့် ပလပ်အင်များကို လုပ်ဆောင်ကြောင်း အမြဲသတိပေးပါသည်။

per-plugin config စာမျက်နှာသည် `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) တွင်နေထိုင်သည်။
