## တက်ဘ်များ

### ရှာရန် တဘ်

ရှိပြီးသား `SearchForm` + `ResultsPanel` + `RerankPanel` ကို တဘ်တစ်ခုအဖြစ် ပြောင်းလဲလိုက်ပါ။

- Query → ရလဒ်များ (ခေါင်းစဉ်၊ URL၊ အတိုအထွာ၊ ဆက်စပ်မှုရမှတ်)။
- Config pane (ကုန်ကျစရိတ်၊ ခွဲတမ်း၊ အခြေအနေ) တွင် ပံ့ပိုးပေးသူ မက်တာဒေတာ။
- အဆင့်သတ်မှတ်ခြင်းကဏ္ဍ- အဆင့်သတ်မှတ်ခြင်း မော်ဒယ်ကို ရွေးပါ၊ ရလဒ်များကို ပြန်စီပါ၊ `positionDelta` ပြပါ။
- ရှာဖွေပေးသူများကို စီစဉ်သတ်မှတ်ထားခြင်းမရှိသောအခါ CTA ဖြင့် ဗလာဖြစ်နေသည်။
- `SearchHistory.tsx` မှတဆင့်ရှာဖွေမှုသမိုင်း။
- `POST /v1/search` (ရှိပြီးသား အဆုံးမှတ်၊ အပြောင်းအလဲမရှိ) ကိုခေါ်ဆိုပါ။

### Tab ကိုခြစ်ပါ။

`POST /v1/web/fetch` မှတစ်ဆင့် URL မှ အကြောင်းအရာကို ထုတ်ယူရန်အတွက် တဘ်အသစ် (အစီအစဉ် 05 တွင် ဖန်တီးထားသည်)

- ထည့်သွင်းမှု- URL + စာမျက်နှာပြည့် + ဖော်မတ်ရွေးချယ်မှုခလုတ် (အမှတ်အသား/စာသား/ HTML)။
- → fetch → render `ScrapeResult.tsx` တင်ပြပါ။
- `ScrapeResult` သည် markdown preview + raw toggle ကို လုပ်ဆောင်သည်။
- Cap: အကယ်၍ တုံ့ပြန်မှု body >** 256 KB** , UI `(truncated, view raw)` ပြသပြီး Monaco modal (D21) ဖြင့် အကြမ်းဖွင့်သည်။
- မက်တာဒေတာအကန့်- ဝန်ဆောင်မှုပေးသူ (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search) ၊ တုံ့ပြန်ချိန်၊ ကုန်ကျစရိတ်၊ တုံ့ပြန်မှုအရွယ်အစား၊ လင့်ခ်များအရေအတွက်။
- `useScrapeFetch.ts` ချိတ်ကို အသုံးပြုသည်။

### Tab ကို နှိုင်းယှဉ်ပါ။

တူညီသော query/URL အပေါ်သို့ ဖြတ်၍ လုပ်ဆောင်သည်။** ဝန်ဆောင်မှုပေးသူ 4 ဦး ပြိုင်တူ** (D22):

- ဝန်ဆောင်မှုပေးသူတစ်ဦးစီတွင် ဘေးချင်းကပ်ကော်လံများ။
- မက်ထရစ်များ- ကြာချိန်၊ ကုန်ကျစရိတ်၊ ရလဒ်အရေအတွက်၊ တုံ့ပြန်မှုအရွယ်အစား။
- ရှာဖွေမှုအတွက်URL ထပ်နေသောတွက်ချက်မှု (မျှဝေထားသော URLs အရေအတွက်နှင့် ကနဦးရလဒ်)။
- ဝန်ဆောင်မှုပေးသူတစ်ဦးလျှင် `POST /v1/search` (ရှာဖွေမှု) သို့မဟုတ် `POST /v1/web/fetch` (ခြစ်) ခေါ်ဆိုပါ။

| **အလိုအလျောက် (ဈေးအသက်သာဆုံး)** | ရရှိနိုင်သည့် ဈေးအသက်သာဆုံး provider ကို အလိုအလျောက် ရွေးချယ်သည်                      |

## ပံ့ပိုးသူ ကတ်တလောက်

`ProviderCatalog.tsx` `GET /api/search/providers` မှ ဝန်ဆောင်မှုပေးသူစာရင်း အပြည့်အစုံကို ထုတ်ပြသည် (F4 တွင် တိုးချဲ့ထားသော ဝန်ဆောင်မှုပေးသူများ ပါဝင်ရန်)

| `kind` | `"search"` (ဝန်ဆောင်မှုပေးသူ 24 ဦး) သို့မဟုတ် `"fetch"` (firecrawl၊ jina-reader၊ tavily-search၊ သေးငယ်သောငါး၊ သွက်လက်သောရှာဖွေမှု၊ မည်သည့်ရှာဖွေမှုမဆို၊ ပြိုင်တူရှာဖွေမှု၊ တောင့်တင်းနိုင်သောရှာဖွေမှု) |

အခြေနေက** တောင်းဆိုချိန်မှ ဆင်းသက်လာသည်။** အထောက်အထားများ ရှိမရှိ နှင့် သော့များအားလုံး လောလောဆယ် cooldown ဖြစ်နေခြင်း ရှိမရှိ စစ်ဆေးခြင်းဖြင့်။

`codex-search` (Codex ဝဘ်ရှာဖွေမှု) တွင် ၎င်း၏ကိုယ်ပိုင်သော့မရှိပါ- ၎င်းသည် ချိတ်ဆက်ထားသော Codex (ChatGPT) အကောင့်ကို ပြန်လည်အသုံးပြုသည်၊ ထို့ကြောင့် ရှာဖွေမှုတစ်ခုစီသည် ChatGPT စာရင်းသွင်းမှုခွဲတမ်းကို သုံးစွဲပြီး 10 မှ 40 စက္ကန့်ခန့် ကြာပါသည်။ တောင်းဆိုချက်တစ်ခုက ၎င်းကို အမည်ပေးသည့်အခါ လုပ်ဆောင်သည်။ အလိုအလျောက်ရွေးချယ်မှုသည် `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` အင်္ဂါရပ်အလံ (ပုံမှန်အားဖြင့် ပိတ်သည်) လိုအပ်သည်။

## နောက်ခံပြောင်းလဲမှုများ

ဤအင်္ဂါရပ်အတွက် နောက်ခံပြောင်းလဲမှုတစ်ခုသာ လိုအပ်သည်-

### တိုးချဲ့ `GET /api/search/providers`

`src/app/api/search/providers/route.ts` ကို:

- array တွင် fetch provider တိုင်း (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`, `keenable-search`) ကို ထည့်သွင်းပါ။
- ပစ္စည်းတိုင်းတွင် `kind: "search" | "fetch"` ထည့်ပါ။
- တိုက်ရိုက်အထောက်အထားအခြေအနေမှရရှိသော `status: "configured" | "missing" | "rate_limited"` ထည့်ပါ။
- နောက်ပြန်လိုက်ဖက်ညီသော — ရှိပြီးသားအကွက်များ (`id`၊ `name` စသည်တို့) ကို မပြောင်းလဲဘဲ ထိန်းသိမ်းပါ။
