## ၎င်းသည် ဘာလဲ

OmniRoute သည် **Obsidian** vault တစ်ခုကို **context source** အဖြစ် ချိတ်ဆက်ပေးသည် — ၎င်းသည်
agent များက built-in MCP server မှတစ်ဆင့် ဖတ်ရှု၊ ရေးသားနိုင်သည့် local Markdown
knowledge base တစ်ခုဖြစ်သည်။ ဤ integration သည် desktop app အတွင်း လည်ပတ်နေသော
**Obsidian Local REST API** community plugin နှင့် ဆက်သွယ်သောကြောင့် agent များသည်
မှတ်စုများကို ရှာဖွေခြင်း၊ ဖိုင်များကို ဖတ်ခြင်း/ရေးခြင်း/ပြင်ဆင်ခြင်း၊ vault စာရင်းကို ကြည့်ရှုခြင်း၊
နေ့စဉ်/အပတ်စဉ် periodic note များနှင့် လုပ်ဆောင်ခြင်း၊ tag များကို စီမံခြင်း၊ Obsidian command
များကို လုပ်ဆောင်ခြင်းနှင့် (ရွေးချယ်နိုင်သည့်အနေဖြင့်) desktop↔mobile နှစ်လမ်းသွား vault sync
ကို ညှိနှိုင်းခြင်းတို့ ပြုလုပ်နိုင်သည်။

Client (`src/lib/obsidian/api.ts`) သည် Local REST API ကို အောက်ပါလုပ်ဆောင်ချက်များဖြင့်
ထုပ်ပိုးပေးထားသည်-

- ယာယီ `5xx` အမှားများအတွက် **backoff ဖြင့် ပြန်လည်ကြိုးစားခြင်း**၊ `AbortController` မှတစ်ဆင့် **စက္ကန့် 30 timeout**။
- **Type သတ်မှတ်ထားသော error အမျိုးအစားခွဲခြားမှု** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`။
- အဖြစ်များသော port မှားယွင်းမှု (HTTP သည် `27123` တွင်ဖြစ်ပြီး `27124` ရှိ MCP endpoint
  **မဟုတ်ပါ**) နှင့် Tailscale ပုံစံကို ထောက်ပြပေးသည့် နားလည်လွယ်သော
  **"Obsidian သို့ ဆက်သွယ်၍မရပါ" အကြံပြုချက်**။
- space/slash များပါဝင်သည့် note path များကို ဘေးကင်းစေရန် vault-relative **path encoding**။

## စနစ်ထည့်သွင်းခြင်း

Obsidian token သို့မဟုတ် base URL အတွက် **environment variable မရှိပါ** — နှစ်ခုစလုံးကို
`src/lib/db/obsidian.ts` မှတစ်ဆင့် SQLite `key_value` table (namespace `obsidian`) တွင်
သိမ်းဆည်းထားသည်။ Token ကို **သိမ်းဆည်းထားစဉ် ကုဒ်ဝှက်ထားသည်** (AES-256-GCM၊
plaintext နောက်ပြန်လိုက်ဖက်ညီမှု fallback ပါဝင်သည်)။ Endpoint dashboard ၏
**Context Sources** tab (`ObsidianSourceCard`) မှဖြစ်စေ၊ settings REST API မှတစ်ဆင့်ဖြစ်စေ
စီစဉ်သတ်မှတ်ပါ။

> [!IMPORTANT]
> **Obsidian Local REST API** plugin ကို ထည့်သွင်းပြီး လည်ပတ်နေစေရမည်။ ၎င်း၏ REST
> interface သည် **HTTP `127.0.0.1:27123`** (မူလ base URL) တွင် နားထောင်သည်။ Port `27124`
> သည် _သီးခြား_ MCP/HTTPS endpoint တစ်ခုဖြစ်ပြီး settings route က အတိအလင်း ငြင်းပယ်သည်။
> အခြား device တစ်ခုမှ ချိတ်ဆက်ပါက `http://<tailscale-ip>:27123` ကို အသုံးပြုပါ။

### စီစဉ်သတ်မှတ်မှု key များ (SQLite `key_value`, namespace `obsidian`)

| Key               | ရည်ရွယ်ချက်                                     | ကုဒ်ဝှက်ထားမှု |
| ----------------- | ----------------------------------------------- | -------------- |
| `api_key`         | Local REST API bearer token                     | ဟုတ်သည်        |
| `base_url`        | REST base URL (မူလ `http://127.0.0.1:27123`)    | မဟုတ်ပါ        |
| `vault_path`      | Vault directory သို့ absolute path (sync အတွက်) | မဟုတ်ပါ        |
| `webdav_username` | ထုတ်ပေးထားသော WebDAV username (vault sync)      | မဟုတ်ပါ        |
| `webdav_password` | ထုတ်ပေးထားသော WebDAV password (vault sync)      | ဟုတ်သည်        |
| `webdav_enabled`  | WebDAV vault sync ကို ဖွင့်ထားခြင်း ရှိ၊ မရှိ   | မဟုတ်ပါ        |

### REST မှတစ်ဆင့် စီစဉ်သတ်မှတ်ခြင်း

```bash
# Local REST API token ကို သိမ်းဆည်းပြီး စစ်ဆေးပါ (POST သည် status စစ်ဆေးမှုမှတစ်ဆင့် အတည်ပြုသည်)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# ချိတ်ဆက်မှုအခြေအနေကို စစ်ဆေးပါ (connected, hasToken, baseUrl, vaultPath ကို ပြန်ပေးသည်)
curl http://localhost:20128/api/settings/obsidian

# ချိတ်ဆက်မှုဖြုတ်ပါ (သိမ်းဆည်းထားသော token ကို ရှင်းလင်းသည်)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Method အားလုံးသည် dashboard authentication လိုအပ်သည်။ `POST` သည် port `27124` ရှိ
မည်သည့် URL ကိုမဆို ငြင်းပယ်ပြီး သိမ်းဆည်းခြင်းမပြုမီ Local REST API status endpoint ကို
ခေါ်ဆိုခြင်းဖြင့် token ကို အတည်ပြုသည်။

### WebDAV vault sync

`src/app/api/settings/obsidian/webdav/route.ts` သည် ရွေးချယ်အသုံးပြုနိုင်သော WebDAV အခြေပြု
vault sync ကို စီမံသည် (`src/lib/obsidianSync.ts` က လုပ်ဆောင်ပေးသည်)။ ၎င်းကို ဖွင့်ခြင်းဖြင့်
OmniRoute ကို local vault directory တစ်ခုသို့ ညွှန်ပေးပြီး ကျပန်း WebDAV username/password
အတွဲတစ်ခုကို ထုတ်ပေးသည်-

```bash
# Vault directory တစ်ခုအတွက် WebDAV sync ကို ဖွင့်ပါ (username/password ထုတ်ပေးသည်)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV sync အခြေအနေကို ရယူပါ (ဖွင့်ထားချိန်တွင်သာ credentials ကို ပြန်ပေးသည်)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV sync ကို ပိတ်ပါ (credentials နှင့် စီမံထားသော .stignore ကို ရှင်းလင်းသည်)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### လုံခြုံရေးနှင့် သယ်ယူပို့ဆောင်ရေး

WebDAV authentication သည် per-IP ပျက်ကွက်မှုကို ခြေရာခံခြင်းနှင့် လော့ခ်ချခြင်းကို တွန်းအားပေးသည် (10 စက္ကန့် 60 ဝင်းဒိုးအတွင်း မအောင်မြင်သောကြိုးစားမှုသည် `429 Too Many Requests` နှင့် `Retry-After` ဖြင့် 5 မိနစ်ကြာ လော့ခ်ချခြင်းကို အစပျိုးစေသည်။ WebDAV အခြေခံစစ်မှန်ကြောင်းအထောက်အထားများကို ပို့လွှတ်သောကြောင့် TLS (သို့မဟုတ် Tailscale သို့မဟုတ် Cloudflare Tunnel ကဲ့သို့သော လုံခြုံသောဥမင်လိုဏ်ခေါင်းတစ်ခုပေါ်တွင် လမ်းကြောင်းပြောင်းခြင်း) ကို လှည့်ပတ်အပြင်ဘက် WebDAV အဆုံးမှတ်ကို ဝင်ရောက်သည့်အခါတွင် ပြင်းထန်စွာအကြံပြုထားသည်။

### API key တစ်ခုချင်းစီအလိုက် context source (ရွေးချယ်နိုင်သည်)

Obsidian config ကို `api_key_context_sources` table
(`src/lib/db/apiKeyContextSources.ts`) မှတစ်ဆင့် **API key တစ်ခုချင်းစီအလိုက်** သတ်မှတ်နိုင်သည်။
MCP call တစ်ခုတွင် authentication အတည်ပြုပြီးသော API key id ပါရှိသည့်အခါ
`getObsidianConfigForApiKey()` သည် ထို key ၏ ကိုယ်ပိုင် token/base-URL/vault-path
(`source: "api_key"`) ကို ဦးစားပေးပြီး၊ မရှိပါက global config (`source: "global"`) ကို
fallback အဖြစ် အသုံးပြုသည်။

Sync မဟုတ်သော MCP tool များသည် ဤ configuration ကို မဖတ်မီ ခေါ်ဆိုသူ၏ identity ကို
ဖြေရှင်းသတ်မှတ်ထားရန် လိုအပ်သည်။ Identity မရှိသော ခေါ်ဆိုသူသည်
`Obsidian API token not configured` ကို လက်ခံရရှိပြီး vault request ကို ပေးပို့မည်မဟုတ်ပါ။
HTTP ခေါ်ဆိုသူများ၏ identity ကို ၎င်းတို့၏ request credentials မှတစ်ဆင့် ဖြေရှင်းသည်။
stdio ခေါ်ဆိုသူများအတွက် `OMNIROUTE_API_KEY` သို့မဟုတ် `ROUTER_API_KEY` မှတစ်ဆင့်
ဖြေရှင်းနိုင်သည်။ Identity ကို မဖြေရှင်းနိုင်သော HTTP ခေါ်ဆိုသူသည် server ၏ environment
identity ကို ဆက်ခံအသုံးပြု၍ မရပါ။ Placeholder ID များသက်သက်ဖြင့် access ကို ခွင့်ပြုမည်
မဟုတ်ပါ။ `env-key` သို့ resolve လုပ်ပေးနိုင်သော အကျုံးဝင်သည့် environment credential ကိုမူ
ဆက်လက် ပံ့ပိုးထားသည်။ API key တစ်ခုချင်းစီအလိုက် Obsidian configuration မရှိသော
authenticated key များသည် global fallback ကို ဆက်လက်အသုံးပြုသည်။ `obsidian_sync_*`
tool လေးခုသည် ၎င်းတို့၏ သီးခြား sync-token လုပ်ဆောင်ပုံကို ဆက်လက်အသုံးပြုသည်။

## MCP ကိရိယာ (၂၂) ခု၊

`open-sse/mcp-server/tools/obsidianTools.ts` တွင်သတ်မှတ်ထားသည်။ token/base-URL ခေါ်ဆိုမှုတစ်ခုအတွက် ဖြေရှင်းပေးသည် (per-API-key ပထမ၊ ထို့နောက် ဂလိုဘယ်)။ OmniRoute ကို ထိသော ကိရိယာများ** ထပ်တူကျသောဆာဗာ** ( `obsidian_sync_*` ကိရိယာလေးခု) ထို့အပြင် OmniRoute ဆက်တင်များတွင် ပြင်ဆင်ထားသော ထပ်တူပြုမှုဆိုင်ရာ စစ်မှန်ကြောင်း တိုကင်ကို လိုအပ်သည်။

### ဖတ်ရန်ကိရိယာများ (`read:obsidian`)

| ကိရိယာ                       | ဖော်ပြချက်                                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Local REST API ဆက်သွယ်၍ စစ်မှန်ကြောင်း အတည်ပြုနိုင်ခြင်း ရှိ၊ မရှိ စစ်ဆေးပါ။                                         |
| `obsidian_search_simple`     | မှတ်စုအကြောင်းအရာ၏ စာသားအပြည့်အစုံ ရှာဖွေမှု။ ဖိုင်လမ်းကြောင်းများဖြင့် အတိုအထွာများကို ပြန်ပေးသည်။                  |
| `obsidian_search_structured` | JSON Logic expression (and/or/regex/path filters) ကို အသုံးပြု၍ ရှာဖွေပါ။                                            |
| `obsidian_read_note`         | vault-relative path ဖြင့် မှတ်စုကိုဖတ်ပါ။ သီးခြား heading/block/frontmatter. ရွေးချယ်နိုင်သည်။                       |
| `obsidian_list_vault`        | ဖိုင်များနှင့် လမ်းညွှန်များကို ခန်း (ထည့်သွင်းမှုသစ်ပင်) တွင် စာရင်းပြုစုပါ။                                        |
| `obsidian_get_document_map`  | ခေါင်းစဉ် → လိုင်းနံပါတ်များမြေပုံအဖြစ် မှတ်စု၏ ခေါင်းစီးတည်ဆောက်ပုံကို ရယူပါ။                                       |
| `obsidian_get_note_metadata` | အကြောင်းအရာအပြည့်အစုံမပါဘဲ ရှေ့မျက်နှာစာ၊ တဂ်များ၊ လင့်ခ်များ၊ char/word အရေအတွက်ကို ရယူပါ။                          |
| `obsidian_get_active_file`   | Obsidian တွင် လက်ရှိအသုံးပြုနေသော ဖိုင်၏လမ်းကြောင်း + အကြောင်းအရာကို ရယူပါ။                                          |
| `obsidian_get_periodic_note` | ရက်စွဲတစ်ခုအတွက် daily/weekly/monthly အချိန်အပိုင်းအခြားမှတ်စု (ယနေ့ချန်လှပ်ထားလျှင်) ရယူပါ။                         |
| `obsidian_get_tags`          | vault tag အားလုံးကို ၎င်းတို့၏ ကြိမ်နှုန်းများဖြင့် စာရင်းပြုစုပါ။                                                   |
| `obsidian_list_commands`     | ရနိုင်သော Obsidian အမိန့်ကို IDs ( `obsidian_execute_command` ဖြင့်သုံးပါ)။                                          |
| `obsidian_sync_status`       | OmniRoute စင့်ခ်ဆာဗာအခြေအနေ- လည်ပတ်နေသည်၊ ခန်းအမည်၊ ဆိပ်ကမ်း၊ အလုပ်ချိန်၊ နောက်ဆုံးစင့်ခ်လုပ်ခြင်း။                  |
| `obsidian_sync_conflicts`    | မဖြေရှင်းရသေးသော ထပ်တူထပ်မျှသော ပဋိပက္ခများကို စာရင်းပြုစုပါ (လမ်းကြောင်း၊ ပဋိပက္ခလမ်းကြောင်း၊ စစ်ဆေးတွေ့ရှိထားသည်)။ |

### စာရေးကိရိယာများ (`write:obsidian`)

| ကိရိယာ                           | ဖော်ပြချက်                                                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `obsidian_write_note`            | ပေးထားသော Markdown အကြောင်းအရာဖြင့် မှတ်စုတစ်ခုကို ဖန်တီးပါ သို့မဟုတ် ထပ်ရေးပါ။                              |
| `obsidian_append_note`           | အကြောင်းအရာကို မှတ်စုတစ်ခုတွင် ထပ်ထည့်ပါ။ သီးခြား heading/block. ကိုရွေးချယ်နိုင်သည်။                        |
| `obsidian_patch_note`            | ခေါင်းစီး၊ ပိတ်ဆို့ခြင်း သို့မဟုတ် ရှေ့မျက်နှာစာအကွက်တွင် append/prepend/replace ။                           |
| `obsidian_delete_note`           | မှတ်စုကို အခန်းတွင်းမှ အပြီးတိုင်ဖျက်ပါ။                                                                     |
| `obsidian_move_note`             | အခန်းအတွင်း မှတ်စုကို ရွှေ့ပါ သို့မဟုတ် အမည်ပြောင်းပါ။                                                       |
| `obsidian_execute_command`       | ၎င်း၏ command ID ဖြင့် Obsidian အမိန့်ကို လုပ်ဆောင်ပါ။                                                       |
| `obsidian_open_file`             | Obsidian တွင် ဖိုင်တစ်ခုကိုဖွင့်ပါ (၎င်းမရှိပါက ၎င်းကိုဖန်တီးပါ)။                                            |
| `obsidian_sync_trigger`          | ချက်ခြင်း နှစ်လမ်းညွန် ဒက်စတော့↔ မိုဘိုင်းလ်တဲ စင့်ခ်လုပ်ခြင်းကို အစပျိုးပါ။                                 |
| `obsidian_sync_resolve_conflict` | ထပ်တူကျသော ပဋိပက္ခကို ဖြေရှင်းပါ- `local` (မိုဘိုင်း)၊ `remote` (ဒက်စ်တော့) သို့မဟုတ် `keep-both` ကို ထားပါ။ |

> [!NOTE]
> `obsidian_patch_note` ပစ်မှတ်များသည် `heading | block | frontmatter` ၏ `targetType` နှင့် `append | prepend | replace`၏ `operation` ၊ ရွေးချယ်နိုင်သော `createTargetIfMissing` ဖြင့် လက်ခံသည်။ `obsidian_sync_*` ကိရိယာလေးခုသည် ဒေသဆိုင်ရာ ထပ်တူကျသောဆာဗာ (မူရင်းအားဖြင့်`http://127.0.0.1:27781` ) နှင့် စကားပြောပြီး ထပ်တူကျသော တိုကင်ကို လိုအပ်သည်။

### နယ်ပယ်များ

Read tools require `read:obsidian`; write tools require `write:obsidian`. Enforcement is identical to Notion — handled by `withScopeEnforcement()` in `open-sse/mcp-server/server.ts`, gated on `OMNIROUTE_MCP_ENFORCE_SCOPES=true` and forced on for HTTP/SSE callers whose API key lacks `manage`/`admin`, with allowed scopes sourced from `OMNIROUTE_MCP_SCOPES` or the API key's scope context. See [MCP-SERVER.md](./MCP-SERVER.md).

## Endpoint များ

| Method   | Path                            | ရည်ရွယ်ချက်                                                                 |
| -------- | ------------------------------- | --------------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | `{ connected, hasToken, baseUrl, vaultPath }` ကို ပြန်ပေးသည်။               |
| `POST`   | `/api/settings/obsidian`        | တိုကင်ကို သိမ်းဆည်းပြီး မှန်ကန်မှုစစ်ဆေးသည် (port `27124` ကို ငြင်းပယ်သည်)။ |
| `DELETE` | `/api/settings/obsidian`        | ချိတ်ဆက်မှုဖြုတ်သည် (သိမ်းဆည်းထားသော တိုကင်ကို ရှင်းလင်းသည်)။               |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV sync အခြေအနေ + အထောက်အထားများ (`enabled` ဖြစ်နေစဉ်)။                 |
| `POST`   | `/api/settings/obsidian/webdav` | vault directory တစ်ခုအတွက် WebDAV sync ကို ဖွင့်သည်။                        |
| `DELETE` | `/api/settings/obsidian/webdav` | WebDAV sync ကို ပိတ်သည်။                                                    |

> ဤအရာများသည် dashboard settings route များဖြစ်သည်။ vault ကိုယ်တိုင်ကို Obsidian
> Local REST API (ပြင်ဆင်သတ်မှတ်ထားသော `base_url`) နှင့် အထက်ပါ MCP tool များမှတစ်ဆင့်
> ဝင်ရောက်သည် — အများသုံး `/v1` Obsidian proxy endpoint မရှိပါ။

## အသုံးပြုမှုများ

- **Vault ကို အခြေခံသော အဖြေများ** — `obsidian_search_simple` / `obsidian_search_structured`
  ပြီးနောက် `obsidian_read_note` ကို အသုံးပြုခြင်းဖြင့် agent သည် သင့်မှတ်စုအစစ်များမှ အခြေခံ၍ အဖြေပေးနိုင်သည်။
- **မှတ်စုရေးသားခြင်း / နေ့စဉ်မှတ်တမ်းတင်ခြင်း** — agent output၊ အနှစ်ချုပ်များ သို့မဟုတ် နေ့စဉ်မှတ်စုများကို
  vault ထဲသို့ မှတ်တမ်းတင်ရန် `obsidian_write_note`၊ `obsidian_append_note` သို့မဟုတ်
  တိကျသော `obsidian_patch_note` ကို အသုံးပြုသည်
  (`obsidian_get_periodic_note`)။
- **Vault လမ်းညွှန်ရှာဖွေခြင်း** — ဖတ်ရှုခြင်း/ရေးသားခြင်းမပြုမီ ဖွဲ့စည်းပုံကို လေ့လာရန်
  `obsidian_list_vault`၊ `obsidian_get_document_map` နှင့်
  `obsidian_get_tags` ကို အသုံးပြုသည်။
- **Obsidian အလိုအလျောက်လုပ်ဆောင်မှု** — agent မှ plugin/command များကို ထိန်းချုပ်မောင်းနှင်ရန်
  `obsidian_list_commands` + `obsidian_execute_command` ကို အသုံးပြုသည်။ UI တွင် မှတ်စုတစ်ခုကို ဖော်ပြရန် `obsidian_open_file` ကို အသုံးပြုသည်။
- **မိုဘိုင်း sync** — WebDAV sync ကို ဖွင့်ပြီးနောက် desktop↔mobile အကြား ညှိနှိုင်းရန်နှင့် ပဋိပက္ခများကို ဖြေရှင်းရန်
  `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  ကို အသုံးပြုသည်။
