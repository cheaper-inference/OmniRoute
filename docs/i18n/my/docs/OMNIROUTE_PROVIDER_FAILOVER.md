ပြန်ကြိုးစားရန် ဆုံးဖြတ်ချက်များ မချမှတ်မီ ပျက်ကွက်မှုများကို အမျိုးအစားခွဲထားသည်။

အချိန်လွန်မှုများ၊ ကွန်ရက်အမှားအယွင်းများ၊ နှုန်းကန့်သတ်ချက်များနှင့် ဝန်ဆောင်မှုပေးသူ 5xx တုံ့ပြန်မှုများကဲ့သို့သော ယာယီကျရှုံးမှုများသည် ကျော်သွားနိုင်ပါသည်။ ကုန်ဆုံးသွားသော ခွဲတမ်း သို့မဟုတ် ခရက်ဒစ် (ခွဲတမ်း 429 သို့မဟုတ် 402 ပေးချေမှု လိုအပ်သည်) ကို တူညီသောဝန်ဆောင်မှုပေးသူတွင် ဘယ်သောအခါမှ ထပ်မစမ်းသော်လည်း သီးခြားခွဲတမ်းရှိသည့် အခြားတစ်ခုသို့ ပျက်ကွက်ပါသည်။ အထောက်အထားစိစစ်ခြင်းဆိုင်ရာ အမှားအယွင်းများ၊ ခွင့်ပြုချက်အမှားများ၊ မမှန်ကန်သော တောင်းဆိုမှုများ၊ မရရှိနိုင်သော မော်ဒယ်များနှင့် အမည်မသိ ပျက်ကွက်မှုများကို မျက်စိစုံမှိတ် ပြန်မစမ်းပါ။

မူရင်း ဝန်ဆောင်မှုပေးသူ မူဝါဒသည် ဝန်ဆောင်မှုပေးသူ သုံးကြိမ်အထိ ကြိုးပမ်းခွင့်၊ ထပ်ခါတလဲလဲ နှုန်းကန့်သတ်ချက်များနှင့် အချိန်ကုန်ခြင်း၊ ကုန်ခန်းနေသော ခွဲတမ်းတွင် ပျက်ကွက်ပြီး စီမံခန့်ခွဲရေးဆိုင်ရာ ပိတ်ထားမှုကို ယာယီပတ်လမ်းအခြေအနေမှ သီးခြားထားရှိပေးသည်။

## ဘယ်မှာ အကျုံးဝင်လဲ။

- **ပေါင်းစပ်မှု** combo ၏ကိုယ်ပိုင်ဗျူဟာနှင့် ဆက်တင်များအလိုက် ၎င်းတို့၏ပစ်မှတ်များကြားတွင် ကျရှုံးသည်။
- **ဗလာမော်ဒယ် အိုင်ဒီ** တက်ကြွသောဝန်ဆောင်မှုပေးသူအများအပြားဝန်ဆောင်မှုပေးသော ( `provider/` prefix မပါ)၊ ထိုအမည်အတိအကျကို ပေါင်းစပ်ခြင်းမရှိပါက ဝန်ဆောင်မှုပေးသူ၏ အနုမာနရွေးချယ်မှုများထံ ဦးစွာပေးပို့ပါသည်။ မူဝါဒကို မအောင်မြင်သည့်နည်းဖြင့် ယင်းကြိုးပမ်းမှု မအောင်မြင်ပါက၊ တူညီသော တောင်းဆိုချက်ကို id ကို ဆောင်ရွက်ပေးသည့် နောက်ထပ်တက်ကြွသောဝန်ဆောင်မှုပေးသူထံ ပေးပို့မည်ဖြစ်သည်။ တုံ့ပြန်မှုသည် အဖြေမဖြေမီ ကြိုးစားပေးသူအရေအတွက်ဖြင့် `x-omniroute-fallback-attempts` ပါ၀င်သည်။
  - အလှည့်ကျတစ်ခုစီသည် ကောက်ချက်ချထားသည့်အတိုင်း အတိအကျလုပ်ပိုင်ခွင့်ရှိသည်။ API သော့ပိတ်ဆို့ခြင်း သို့မဟုတ် ဝန်ခံခြင်းမပြုသော ပစ်မှတ်တစ်ခုသည် ရေစီးကြောင်းခေါ်ဆိုမှုမရှိဘဲ ကျော်သွားသည်၊ ဖောက်သည်သည် အမည်မဖော်ဖူးသော ပစ်မှတ်အတွက် မူဝါဒပယ်ချခြင်းမဟုတ်ဘဲ တကယ့်ရေစီးကြောင်းအမှားကို ရရှိသည်။
  - မအောင်မြင်သော တုံ့ပြန်မှုတစ်ခုသာ ဆက်သွားသည်- ပထမဆုံး streamed byte ပြီးနောက် ဘာမှ မအောင်မြင်ပါ။
  - တောင်းဆိုထားသောမော်ဒယ်၏ပံ့ပိုးပေးသူတိုင်း မအောင်မြင်ပြီးနောက်မှသာ အရေးပေါ်အခြေအနေအတွက် မော်ဒယ်လဲလှယ်မှု အကျုံးဝင်ပါသည်။
  - ချိတ်ဆက်မှု (`x-omniroute-connection`) တွင် တွဲချိတ်ထားသော တောင်းဆိုချက်သည် ၎င်းတွင် ဆက်ရှိနေပါသည်။
  - ရှေ့ပြအိုင်ဒီ (`provider/model`) ကို အခြားဝန်ဆောင်မှုပေးသူထံ ဘယ်တော့မှ ပြန်မပို့ပါ။

circuit state များသည် `closed`၊ `open` နှင့် `half_open` တို့ဖြစ်သည်။ cooldown သည် နယ်နိမိတ်သတ်မှတ်ထားသော စုံစမ်းစစ်ဆေးမှုကို အချိန်ဇယားဆွဲသည်။ အောင်မြင်သော probe သည် circuit ကိုပိတ်ပြီး မအောင်မြင်သော probe သည် ၎င်းကိုပြန်ဖွင့်သည်။
