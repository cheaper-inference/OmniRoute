Node JSON API tad-dwana jgħaqqad endpoint tan-negozju JSON li ma jitkellemx il-protokoll OpenAI jew Anthropic. OmniRoute jimla mudell ta' talba JSON, jibgħatha lill-endpoint komplut URL, jaqra r-risposta minn mogħdija tar-rispons u jirritornaha lill-klijent fil-format tal-klijent stess (Tlestija taċ-Chat, Rispons, Messaġġi, ...).

Huwa node kompatibbli ma 'OpenAI ma' `apiType: "custom-json"`; id tagħha għandha l-forma `openai-compatible-custom-json-<suffix>`. Il-formola tad-dashboard għadha mhix disponibbli. Oħloq u editja dawn in-nodi permezz tal-fornitur-node API hawn taħt.

## Oħloq node

`POST /api/provider-nodes` (management auth):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` hija l** kompluta** endpoint URL. Xejn mhu mehmuż (l-ebda `/chat/completions`, l-ebda `/models`) u, kuntrarjament għal nodi oħra kompatibbli mal-OpenAI, m'hemm l-ebda default URL. Għandu jkun `http(s)`, mingħajr kredenzjali inkorporati jew `#fragment`, u jgħaddi l-istess gwardja URL barra bħal kull nodu tal-fornitur, kemm meta n-nodu jiġi ffrankat kif ukoll fuq kull talba.
- Node li jibgħat iċ-ċavetta tal-konnessjoni (`authType` `bearer` jew `api-key`, inkluż il-default) irid juża `https://`. Plain `http://` huwa aċċettat biss għal loopback host (`localhost`, `127.0.0.0/8`, `::1`) jew ma `authType: "none"`, li ma jibgħat ebda ċavetta. L-indirizzi LAN privati (`10.x`, `172.16-31.x`, `192.168.x`) mhumiex eżenti: kull min ikun fuq dak in-netwerk jista' jaqra ċ-ċavetta. L-iffrankar ta' tali nodu jfalli `400`, u node maħżun qabel ma jagħlaq kull talba bl-istess messaġġ, qabel ma tintbagħat kwalunkwe talba. Għal endpoint keyed fuq LAN, poġġih wara TLS (per eżempju reverse proxy).
- `customJson` huwa validat bi Zod; ċwievet mhux magħrufa huma miċħuda. Kull qasam huwa fakultattiv:

| Qasam             | Valuri                                         | Default                                                |
| ----------------- | ---------------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                         | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                    | `bearer`                                               |
| `authHeader`      | isem header użat meta `api-key`                | `X-API-Key`                                            |
| `requestTemplate` | oġġett JSON (≤ 64 KB, fond ≤ 32)               | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | moghdija tal-għalqa, jew `$` għall-ġisem kollu | `choices[0].message.content`                           |

- Is-sigriet jibqa' fiċ-ċavetta API tal-konnessjoni, qatt fil-mudell. `bearer` jibgħat `Authorization: Bearer <key>`; `api-key` jibgħat `<authHeader>: <key>`. L-intestatura awth ma tistax tkun `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` jew header hop-by-hop. `none`, il-konnessjonijiet m'għandhomx bżonn ċavetta.
- L-intestaturi statiċi żejda jużaw iż `customHeaders` regolari tan-node (l-istess validazzjoni bħal kull nodu kompatibbli ieħor; l-headers tal-awtentikazzjoni mhumiex permessi hemmhekk).

`PUT /api/provider-nodes/<id>` jaċċetta l-istess `customJson` u jikteb mill-ġdid `baseUrl` u l-konfigurazzjoni fuq kull konnessjoni eżistenti tan-node. Li tħalli barra `customJson` iżżomm il-konfigurazzjoni maħżuna; li taqleb `apiType` għal `chat` jew `responses` tneħħiha min-node u l-konnessjonijiet tagħha.

Imbagħad żid konnessjoni man-node bħas-soltu (`POST /api/providers` bl-id tan-node) u titlob `<prefix>/<model>`, pereżempju `biz/assistant-v1`. L-endpoint ma jesponi l-ebda lista tal-mudelli, għalhekk żid l-ids tal-mudell bl-idejn.

## Talba mudelli

Templates huma sempliċi JSON. Valur ta' string jista' jkun fih markaturi `{{placeholder}}` ; xejn ma jiġi evalwat jew eżegwit, u ċ-ċwievet tal-oġġett qatt ma jiġu sostitwiti.

| Placeholder          | Valur                                                                          |
| -------------------- | ------------------------------------------------------------------------------ |
| `{{prompt}}`         | Test tal-aħħar messaġġ tal-utent (partijiet tat-test magħquda ma' linji ġodda) |
| `{{messages}}`       | Il-konversazzjoni f'format ta' OpenAI chat                                     |
| `{{model}}`          | L-id tal-mudell mitlub, mingħajr il-prefiss tal-fornitur                       |
| `{{stream}}`         | Dejjem `false` — l-endpoint iwieġeb b'dokument JSON wieħed                     |
| `{{request.<path>}}` | Field tar-rikjesta tradotta (OpenAI chat format).                              |

- Valur li huwa eżattament placeholder wieħed iżomm it-tip JSON tiegħu (`"{{messages}}"` isir array); placeholder ġewwa string itwal huwa mdaħħal bħala test.
- Placeholder li jsolvi xejn ma jfalli t-talba HTTP 400 minflok jibgħat payload mhux komplut.
- Il-mogħdijiet jużaw notazzjoni bil-punti u indiċi numeriċi (`data.items[0].text`). `__proto__`, `prototype` u `constructor` huma miċħuda f'ċwievet u mogħdijiet.

## Risposti

Il-valur `responsePath` jsir ir-risposta tal-assistent: is-sekwijiet jgħaddu, valuri oħra JSON jiġu serializzati. Field nieqes jew `null`, jew korp li mhuwiex JSON, jirritorna HTTP 502. L-istatus ta' żball upstream jiġu mgħoddija. Għall-klijenti tal-istreaming OmniRoute jistenna r-rispons JSON kollu u mbagħad joħroġha bħala biċċa kontenut wieħed flimkien mal-biċċa finitura; dan mhuwiex token streaming. Is-sejħiet tal-għodda u l-oqsma tal-użu mhumiex immappjati.

## Qatt replayed

Talba ta’ negozju jista’ jkollha effetti sekondarji anke meta tfalli. OmniRoute għalhekk jibgħatha darba:

- l-ebda prova mill-ġdid tat-trasport u l-ebda segwitu mill-ġdid;
- ebda retry fuq konnessjoni oħra (account fallback) — il-falliment jiġi rritornat kif inhi u l-konnessjoni ma titkessaħx;
- ebda fallback għall-mira combo li jmiss, anke għal tweġiba vojta jew falluta.

Talbiet separati tal-klijenti, u pannelli ta 'fużjoni li espliċitament isejħu diversi mudelli, xorta jinvokaw l-endpoint b'mod indipendenti.

## Ittestjar ta 'node

Iffrankar ta 'konnessjoni, il-konnessjoni** Test** kontrolli tas-saħħa tal-buttuna u l-isfond qatt ma jsejħu l-endpoint: jivvalidaw biss il-konfigurazzjoni maħżuna u jirrappurtaw il-konnessjoni bħala mhux verifikabbli.

`POST /api/provider-nodes/validate` bi `"apiType": "custom-json"` u l-oqsma tan-nodi (`baseUrl`, `apiKey`, `customJson`, `customHeaders` fakultattiv u `modelId`) jibgħat eżattament talba reali waħda, `ping` bħala l-aħħar test tal-utent. Twieġeb `{ "valid": true }` jew l-istatus upstream (qatt il-korp upstream).

## Ħażna

Il-konfigurazzjoni hija maħżuna `provider_nodes.custom_json_config_json` (migrazzjoni `240_provider_node_custom_json_config.sql`) u kkupjata f'kull konnessjoni `providerSpecificData.customJson`.

Implimentazzjoni: `open-sse/utils/customJson.ts` (validazzjoni u templating), `open-sse/executors/customJson.ts` (eżekutur), `open-sse/services/combo/noReplayLatch.ts` u `src/sse/handlers/chat/responsePolicies.ts` (no-replay).
