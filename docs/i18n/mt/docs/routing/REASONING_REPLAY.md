> **Sors tal-verità:** `src/lib/db/reasoningCache.ts`, `open-sse/services/reasoningCache.ts`** Aġġornata l-aħħar:** 2026-06-28 — v3.8.40

OmniRoute jaqbad l-assistent `reasoning_content` prodott minn mudelli tal-modalità ta' ħsieb u jerġa' jġibu b'mod trasparenti fuq talbiet b'ħafna dawriet meta l-fornitur upstream jeħtieġha. Dan jelimina l-iżbalji HTTP 400 li l-fornituri stretti jqajmu meta l-istorja tal-konversazzjoni ta 'klijent tkun nieqsa mir-raġunament tal-dawran ta' qabel.

## Għaliex Dan Jeżisti

Diversi fornituri tal-modalità ta 'ħsieb jirrifjutaw dawran ta' segwitu sakemm il-** messagg ta' l-assistent ta' qabel jinkludi `reasoning_content` originali** . L-upstream jirritorna 400 b'messaġġi bħal:

```
Param Incorrect: The reasoning_content in the thinking mode must be passed back to the API.
```

Iżda l-klijenti tipiċi (Cursor, Cline, Roo Code, OpenAI SDK) istrixxu `reasoning_content` mill-istorja li jerġgħu jilagħbu. OmniRoute jirrestawraha minn cache fuq in-naħa tas-server sabiex it-talba li tara upstream tkun konsistenti. Il-Ħruġ #1628 introduċiet il-persistenza memory/SQLite ibrida sabiex il-cache jgħix il-proċess mill-ġdid.

## Arkitettura

```
Turn N (assistant generates):
  → response contains reasoning_content + tool_calls
  → if requiresReasoningReplay(provider, model): cacheReasoningFromAssistantMessage()
      writes (memory + DB), one entry per tool_call.id within the request scope
  → forward response to client (which may or may not retain reasoning)

Turn N+1 (client sends follow-up):
  → translator detects: requiresReasoningReplay(provider, model) === true
  → for each assistant message with tool_calls and no reasoning_content:
      lookupReasoning(buildToolCallCacheKey(scope, toolCalls[0].id)) → memory → DB
      hit  → msg.reasoning_content = cached; recordReplay()
      miss → msg.reasoning_content = "" (legacy fallback for older DeepSeek)
  → upstream sees consistent history → no 400
```

Il-qbid iseħħ `open-sse/handlers/chatCore.ts` (żewġ siti, fiż-żewġ siti ta' sejħa `cacheReasoningFromAssistantMessage` ). Replay jiġri `open-sse/translator/index.ts` wara schema coercion iżda qabel id-dispaċċ.

L-entrati tas-sejħa tal-għodda huma maħżuna taħt `buildToolCallCacheKey()`, diġest tal-ambitu tat-talba u l-id tas-sejħa tal-għodda, għalhekk l-istess id użata minn ċavetta jew sessjoni API oħra ma tagħżelx l-entrata. L-ambitu ġej minn `buildReasoningCacheScope()`: iċ-ċavetta API id, flimkien maċ-ċavetta tas-sessjoni meta t-talba jkollha waħda. Il-kolonna `tool_call_id` u d-dashboard għalhekk juru dan id-diġest għal dawk l-entrati.

Id-dawriet sempliċi (mhux ta' sejħa ta' għodda) ta' l-assistenti huma mdaħħla b'mod differenti: `buildAssistantMessageCacheKey()` jiddiġerixxi l-ambitu tas-sessjoni flimkien mat-traskrizzjoni normalizzata tal-format OpenAI sa dik id-dawra, minħabba li DeepSeek jeħtieġ ir-raġunament ta' _kull_ dawra preċedenti ladarba `tools` ikun preżenti. Għall-miri Responses-API (per eżempju `opencode-go/deepseek-v4-flash`, routed to `/responses`) il-korp upstream iġorr `input`, mhux `messages`, għalhekk `translateRequest()` (`open-sse/translator/index.ts`) jirrapporta t-traskrizzjoni tal-pern li diġerit permezz ta 'għażla ta' callback u s-siti tal-qbid jiddiġerixxu dik l-istess traskrizzjoni. Il-pass ta' replay ta' Responses jimxi fuq il-pern OpenAI għal kull format tas-sors, għalhekk il-klijenti ta' Anthropic Messages (Claude → OpenAI → Responses) jerġgħu jintwerew ukoll.

## Ħażna — Hybrid Memory + SQLite

Il-mogħdija sħuna tuża `Map` fil-memorja (LRU-by-creation) appoġġjata minn tabella SQLite għall-irkupru tal-ħabta u l-viżibilità tad-dashboard.

| Saff    | Implimentazzjoni                                 | Għan                                    |
| ------- | ------------------------------------------------ | --------------------------------------- |
| Memorja | `Map` fiz- `open-sse/services/reasoningCache.ts` | Tfittxijiet veloċi, tkeċċi l-eqdem 200  |
| DB      | tabella `reasoning_cache` (`src/lib/db/`)        | Jippersisti matul restart, drives stats |

Il-kitbiet imorru għat-tnejn. Qari ikkonsulta l-memorja l-ewwel, imbagħad taqa 'lura għal DB (hits DB huma promossi lura fil-memorja). DB fallimenti mhumiex fatali — il-cache fil-memorja tkompli sservi l-passaġġ sħun.

**Defaults:**

- TTL: `2h` (`TTL_MS = 2 * 60 * 60 * 1000`)
- Daħliet massimu tal-memorja: `200` (`MAX_MEMORY_ENTRIES`)
- Żgumbrament: l-eqdem `createdAt` l-ewwel

## Skema tad-Database

Migrazzjoni: `src/lib/db/migrations/033_create_reasoning_cache.sql`

```sql
CREATE TABLE IF NOT EXISTS reasoning_cache (
  tool_call_id   TEXT PRIMARY KEY,
  provider       TEXT NOT NULL,
  model          TEXT NOT NULL,
  reasoning      TEXT NOT NULL,
  char_count     INTEGER NOT NULL DEFAULT 0,
  created_at     TEXT NOT NULL DEFAULT (datetime('now')),
  expires_at     INTEGER NOT NULL
);
```

Indiċijiet: `expires_at`, `provider`, `model`, `created_at`. `expires_at` huwa maħżun bħala sekondi epoch Unix; is-saff SELECT jinnormalizza l-valuri tat-test wirt permezz ta `EXPIRES_AT_EPOCH_SQL`.

## Noti Operattivi

- **Tindif:** `cleanupReasoningCache()` jnaddaf l-entrati tal-memorja skaduti u jmexxi `DELETE FROM reasoning_cache WHERE expires_at <= unixepoch('now')`. Il-ħaddiema tal-kontroll tas-saħħa jsejħu dan perjodikament.
- **Irkupru mill-ħabta:** Wara bidu mill-ġdid, il-memorja hija vojta iżda ż- DB għadu jżomm entrati mhux skaduti. L-ewwel tfittxija għal `tool_call_id` partikolari hija hit DB ; lookups sussegwenti huma hits memorja.
- **L-ebda raġunament, l-ebda cache:** `cacheReasoningFromAssistantMessage` jirritorna `0` meta l-messaġġ tal-assistent ma jkollu l-ebda qasam `reasoning_content` / `reasoning`, għalhekk tweġibiet li ma jaħsbux ma jiswew xejn.
- **Il-kitba hija gated ukoll:** iż-żewġ siti ta' sejħa `chatCore.ts` (non-streaming u streaming) sejħa biss `cacheReasoningFromAssistantMessage()` meta `requiresReasoningReplay(provider, model)` huwa `true` — l-istess predicat il-read side checks. Installazzjonijiet li qatt ma jmissu fornitur ta 'replay jieqfu jħallsu għall-kitba, l-aġġornament tal-indiċi, u l- try/catch fuq kull rispons li jġorr ir-raġunament.
- **Fornituri mhux stretti:** Meta `requiresReasoningReplay` huwa `false` u l-format fil-mira huwa OpenAI, it-traduttur** strixxi** kwalunkwe qasam `reasoning_content` minn messaġġi ħerġin — OpenAI Chat Completions ma jaċċettahx.

## Muse Opak-Reasoning Sjieda

Muse (`muse-code`) jirritorna raġunament opak marbut ma’ min iċempel (`encrypted_content`). Ir-replaying tagħha taħt kont differenti jew kredenzjali reminted ifalli upstream, għalhekk it-talbiet indiġeni OAuth jużaw sjieda fil-livell tas-sessjoni minflok rotazzjoni għal kull talba (`src/sse/services/museSessionOwnership.ts`, infurzat `src/sse/handlers/chat.ts`). Konnessjonijiet API-key magħżula b'mod espliċitu u konfigurazzjonijiet API-key-only iżommu r-rotot eżistenti tagħhom mingħajr din il-modalità ta' sjieda.

- Supply a stable session ID on every turn: `x-omniroute-session-id`, `x-omniroute-session`, `x-session-id`, or `x-codex-session-id`; alternattivament uża `prompt_cache_key`, `session_id`, `conversation_id`, jew `metadata.session_id` fil-korp (f'dik l-ordni ta' preċedenza). Ritorn IDs nieqes jew vojt 400 meta żewġ kontijiet OAuth indiġeni jew aktar huma attivi; b'kont OAuth wieħed m'hemm xejn li jdur għalih, għalhekk talba bħal din iżżomm ir-rotot mhux ippinjat. L-ambitu jinkludi OmniRoute API-key ID ta' min iċempel.
- Sessjonijiet indipendenti friski round-robin fuq kontijiet OAuth indiġeni attivi permessi mill-politika tal-konnessjoni API-key, ordnati minn konnessjoni ID. Round-robin taqbeż il-kontijiet b'konnessjoni cooldown, bi status terminali (`banned`, `expired`, `credits_exhausted`), jew model-locked għall-mudell mitlub; Il-fallimenti upstream ta' Muse jirreġistraw it-tkessiħ u l-istat tal-interruttur bħal fornituri oħra. Konnessjoni sfurzata b'mod espliċitu tevita round-robin għal sessjoni ġdida iżda ma tistax tegħleb sid eżistenti.
- Sakemm is-sid iservi rispons b'suċċess, sessjoni li s-sid tagħha ma jkunx disponibbli terġa' tiġi mitluba fuq kont b'saħħtu. Wara l-ewwel tweġiba b’suċċess, is-sessjoni tibqa’ mqabbda ma’ dak is-sid sakemm tkun ilha inattiva għal 30 jum (`MUSE_SESSION_IDLE_TTL_MS`).
- Kull dawra ta' kontinwazzjoni u riżultat ta' għodda tibqa' marbuta mas-sid tas-sessjoni: konnessjoni, identità tal-kont, u ġenerazzjoni ta' kredenzjali ta' inferenza, ikkontrollati mill-ġdid qabel tentattivi upstream, inklużi tentattivi mill-ġdid ta' aġġornament tal-kredenzjali. Rispons call IDs/item references u Chat Completions tool-call IDs iridu jkunu ġew irreġistrati għal dik is-sessjoni u l-ġenerazzjoni.
- SQLite `key_value` records fl-ispazju tal-isem `muse_session_ownership` (`src/lib/db/museSessionOwnership.ts`) jippersistu s-sjieda u l-cursor ta 'rotazzjoni madwar jerġa' jibda. Kull talba u tweġiba notifikata jġedded it-timbru tal-attività tas-sessjoni; sessjoni idle itwal minn `MUSE_SESSION_IDLE_TTL_MS` hija maqtugħa (pin tas-sid, bandiera moqdija u hashes opaque/reference reġistrati), l-aktar darba kull 10 minuti u f'lottijiet ilimitati, għalhekk replay aktar tard tal-istorja tagħha tonqos magħluqa bħala sid mhux magħruf. Ir-rekords fihom IDs konnessjoni u hashes tal-identità tal-kont, kredenzjali, kontenut opak, u referenzi ta 'kontinwazzjoni, mhux sigrieti jew storja ta' konversazzjoni. Il-klijenti għandhom iżommu u jibagħtu l-istorja sħiħa u r-raġunament opak tagħhom.
- Unknown or foreign opaque reasoning, a missing owner, an unavailable owner account, or a generation change with recorded history fails closed with an explicit 4xx/503 — never silent cross-account failover and never dropped reasoning.
- Ċavetta ta 'l-istess kont reminted tiġi adottata biss meta s-sessjoni ma rreġistrat l-ebda storja replayable; sessjonijiet reġistrati jibqgħu ifallu magħluqa sakemm jibdew friski.
- Rispons upstream vojt (`upstream_empty_response` / `empty_response`, xejn emess lil min iċempel) jerġa' jiġi ppruvat l-aktar darbtejn fuq l-istess sid, wara 0.5 s imbagħad 1.5 s (`MUSE_EMPTY_RESPONSE_RETRY_DELAYS_MS`). Jekk it-tentattivi kollha huma vojta, l-oriġinal 502 jintbagħat lura mingħajr cooldown jew breaker immarkar, għalhekk tweġiba flaky qatt ma jillokkja s-sid.
- It-talbiet kollha `muse-code` ta' bypass semantic-cache jaqra u jikteb, inkluż streaming jikteb, sabiex l-output opak fil-cache ma jistax jakkwista sid ta 'sessjoni differenti.
