`copilot-m365-web` (jinak `m365copilot`) odesílá požadavky na chat ve formátu OpenAI prostřednictvím ověřené relace Microsoft 365 Copilot na `m365.cloud.microsoft/chat`. Toto je neoficiální nativní integrace: není vyžadován žádný samostatný proxy proces nebo localhost upstream. Poskytovatel ID, alias a existující importovaná připojení se nezmění. `copilot-web` je jiný poskytovatel spotřebitelských služeb na `copilot.microsoft.com`.

> **Jste u poskytovatelů webových souborů cookie noví?**
>
> Číst**`docs/getting-started/WEB-COOKIE-GUIDE.md`** pro obecný proces nastavení, pokyny pro ověřování, omezení a řešení problémů, než budete postupovat podle tohoto průvodce specifického pro poskytovatele.
>
> **Pro starší importy:** Pověření pro tohoto poskytovatele je** ne cookie** . Nekopírujte soubory cookie ze `m365.cloud.microsoft`. Pověření je parametr dotazu WebSocket URL a segment cesty, obojí načtené z karty DevTools Network.

## Předpoklady

- Účet Microsoft 365 s přístupem k Copilot na `m365.cloud.microsoft/chat`
- Prohlížeč založený na Chromiu (Chrome, Edge) pro kontrolu DevTools WebSocket
- Přístup k požadovanému modelu na tomto účtu; dostupnost se liší podle nájemce a licence

## Nativní přihlášení (pracovní nebo školní účty)

Vybrat**Microsoft 365 Copilot → Připojit** a připravit pokus o přihlášení. Řídicí panel používá tok autorizačního kódu s PKCE; nepožaduje vaše heslo Microsoft ani kód MFA.

1. Otevřete a** prázdná karta prohlížeče** , poté otevřete**DevTools →** a povolit** Zachovat protokol** . Udělejte to před přechodem na Microsoft: Windows SSO může skončit okamžitě.
2. Zkopírujte autorizační URL zobrazené v dialogovém okně připojení a přejděte k němu na připravené kartě. Dokončete výběr účtu Microsoft nebo na požádání MFA.
3. V uchovaném síťovém protokolu najděte požadavek na `https://login.microsoftonline.com/common/oauth2/nativeclient` a zkopírujte jej celý** Žádost URL** .
4. Vložte URL do dialogového okna připojení a připojte se. Nevkládejte nezpracovaný kód ani poslední adresní řádek `wrongplace` URL: požadované zpětné volání je přechodná navigace.

Každý pokus vyprší po deseti minutách a lze jej použít pouze jednou. Server před výměnou kódu zkontroluje svůj stav, ověřovatel PKCE a cíl opětovné autentizace. Po vypršení platnosti nebo selhání výměny zahajte nový pokus. Pokus nemůže přežít restart serveru.

Tokeny používají existující úložiště pověření připojení a cestu aktualizace. Opětovné ověření připojení vyžaduje stejnou identitu Microsoft tenant/object, nikoli pouze stejný e-mail. Zachovává operátor naming/settings a nahrazuje zastaralé importované přihlašovací údaje. Nativní přihlášení je pro účty work/school ; starší cesta importu zůstává dostupná pro stávající připojení a podporované konfigurace vrstev.

Úplné zpětné volání URL je jednorázové pověření. Nikdy jej nezahrnujte do snímků obrazovky, protokolů, zpráv podpory nebo potvrzení. Tento postup neotevře prohlížeč na serveru, nezkontroluje historii prohlížeče ani nespustí místní server zpětného volání.

## Zachycení přihlašovacích údajů (metoda WebSocket )

1. Přihlaste se na `https://m365.cloud.microsoft/chat` a začněte konverzovat.
2. OTEVŘENO**DevTools →** .
3. Filtrovat podle**WS** (WebSocket).
4. Klikněte na připojení Chathub WebSocket. Hledejte URL začínající na `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Z jeho** Žádost URL** , kopírovat:
   - Hodnota parametru dotazu `access_token` (krátkotrvající JWT).
   - Segment cesty Chathubu za `/Chathub/` (např. `<oid>@<tenant>`).

Úplné URL má tvar:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. V OmniRoute vyberte**Microsoft 365 Copilot** , vyberte možnost starší verze API-key/import a vložte pověření ve formátu:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Klikněte** Test připojení** a** Uložit** .

## Zachycení pověření (import HAR )

Místo ručního kopírování hodnot ze souboru WebSocket URL můžete exportovat soubor DevTools HAR :

1. OTEVŘENO**DevTools →** .
2. Zahajte nebo pokračujte v konverzaci Microsoft 365 Copilot (to spustí připojení WebSocket ).
3. Klepněte pravým tlačítkem myši na panel Síť a vyberte** Uložit vše jako HAR s obsahem** .
4. V OmniRoute použijte** Importujte soubor .har** v dialogovém okně připojení poskytovatele.

OmniRoute prohledá HAR pro Chathub WebSocket URL, extrahuje `access_token` a `chathubPath` a automaticky naplní pole pověření. Import HAR dekóduje vypršení platnosti JWT a zobrazí zbývající životnost tokenu.

> **Nikdy nesvěřujte skutečný export HAR, přístupový token nebo obnovovací token.** Hodnoty testu a dokumentace musí být vždy zástupnými symboly.

## Životnost tokenu a obnovení

`access_token` je krátkodobý (obvykle**~ 75 minut** ). Bez použitelného obnovovacího tokenu musíte po vypršení platnosti znovu získat pověření.

### Automatické obnovení pomocí `refreshToken`

U poskytovatele Microsoft 365** Přidat připojení** nebo** Upravit připojení** dialog, otevřít** Pokročilá nastavení → Obnovovací token (volitelné)** . Vložte obnovovací token Microsoft OAuth pro obor `substrate.office.com/sydney` a uložte. Vstup je maskovaný a nikdy není předem vyplněn uloženým tokenem. Při úpravách ponechte toto pole prázdné, chcete-li zachovat stávající token; vložte nový token, abyste jej nahradili.

Nativní přihlášení získá obnovovací token, když Microsoft vrátí jeden. Pro starší importy použijte existující kompatibilní udělení autorizačního kódu Microsoft ; tento poskytovatel neimplementuje ani neslibuje tok kódu zařízení. S nakonfigurovaným obnovovacím tokenem OmniRoute zkontroluje `access_token` před požadavky a obnoví je pouze v případě, že potřebuje obnovit. Úspěšné obnovení také zachová otočený obnovovací token, čímž se zabrání ručnímu opětovnému zachycení, zatímco obnovovací token zůstane platný.

Pokud `refreshToken` není nastaveno, musíte po každém vypršení platnosti znovu získat pověření WebSocket ručně.

## Modely a směrování

Nativní katalog obsahuje všechny zdokumentované samostatné IDs plus čtyři původní nativní IDs. Katalog je statický a nezávislý na účtu, nejedná se o test nároku na účet: placené trasy a aliasy kompatibility zůstávají uvedeny, i když je připojený účet nemůže používat. Štítky na displeji modelu vynechávají název poskytovatele a typickou charakteristiku dostupnosti pro model; poskytovatel zůstává**Microsoft 365 Copilot** . Označeny štítky** Přezdívka** nebo** Dědictví** zachovat své stávající identifikátory a mapování protokolů, což není zárukou historické verze modelu. Samostatné proxy** Import z /models** pokyny se nevztahují na tohoto nativního poskytovatele WebSocket.

| Modelová rodina   | Kanonická IDs                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| Automatický       | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| Dřívější GPT      | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude sonet      | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude Opus       | `claude-opus`, `claude-opus-4.8`                                                                 |

Jsou také registrovány aliasy jako `auto`, `quick`, `think-deeper` a aliasy verzí. Stávající `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` a `copilot-m365-gpt-5-5-chat` zůstávají v platnosti. Dokumentované IDs potřebují předponu poskytovatele (`copilot-m365-web/claude-opus` nebo `m365copilot/claude-opus`): mnoho z nich jsou obecná slova nebo názvy modelů jiných dodavatelů, takže holé `claude-opus` pokračuje ve směrování jako bez tohoto poskytovatele. Registrace není příslibem, že Microsoft bude sloužit tomuto modelu každému účtu. Samostatný IDs se řídí veřejným [katalogem protokolů](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) (exportovaná mapa od modelu k tónu a její metadata scénáře s ohledem na model). Všechny nativní profily si zachovávají `availability: "unverified"`; zařazení do katalogu není úspěšným testem účtu.

- Výslovné vzorové odmítnutí licence se vrací** 403** `m365_model_not_licensed`, ne 502. Směrovací zámky, které se connection/model spárují, takže licencované modely na připojení zůstávají použitelné.
- `InvalidCopilotLicense` je odmítnutí licence na úrovni účtu, hlášené samostatně jako `m365_account_not_licensed`.
- Vrátí se omezení pro jednotlivé uživatele** 429** `m365_throttled` a ochlazuje připojení. Vrátí se vyčerpání prioritního přístupu** 429** `priority_access_exhausted` a je zaměřen na model. Výsledek `OutOfCredits` s návratem `errorCode: "ReasoningTurnExhausted"`** 429** místo toho `reasoning_turns_exhausted`, také v rozsahu modelu, bez nároku na čas resetování. Bylo hlášeno, že jeden nájemce práce omezil tóny „Mysli hlouběji“, zatímco rychlé tóny nadále sloužily; tento rozsah je pozorováním spotřebitelů, ne něčím, co toto úložiště reprodukovalo. Směrování proto také vyřadí z rotace ostatní zdokumentované modely Think hlubší `gpt-5.5` a `gpt-5.6` na tomto připojení pro stejný cooldown a ponechává rychlé tóny a každé další selhání na jejich vlastním modelu. Dodané rady pro opakování jsou zachovány; chybějící reset není inzerován jako známý čas resetování.
- Vrací se bezpečnostní odmítnutí Copilot (`Disengaged`).** 400** `provider_safety_rejection`, štítek bezpečnostního zastavení sdíleného poskytovatele. Nikdy se to nezapočítává do stavu připojení, klient SDKs neopakuje 400 a s povoleným `PROVIDER_SAFETY_STOPS_TERMINAL` se kombinované směrování zastaví tam, místo aby přehrál požadavek na jiný cíl.
- Požadavky na jedno připojení jsou serializovány prostřednictvím existujícího semaforu účtu. Upřednostňujte prioritní záložní před paralelními panely; samotná serializace nevylučuje limity rychlosti konverzace Microsoft.

## Požadujte chování a limity

- Nástroje jsou** promptně emulované** , nikoli nativní volání funkce Microsoft. Požadavek s povoleným nástrojem používá jednu vyrovnávací paměť; netráví další generaci výběrem nástrojů. Jako volání jsou vráceny pouze deklarované nástroje s platnými podporovanými tvary argumentů.
- Dlouhá strukturovaná odpověď s jediným koncovým příkladem je zachována jako próza. Toto je heuristika, nikoli důkaz záměru; aplikace musí stále vynucovat svá vlastní oprávnění k nástrojům.
- Zadávání obrázků funguje tak, jak jej webový klient posílá. Každá část obrázku (`image_url` jako datové URL nebo veřejné HTTPS URL nebo Responses `input_image`) je nahrána do `/m365Copilot/UploadFile` do konverzace kola s tokenem chatu a zpráva na ni ukazuje anotací `ImageFile` ; text označuje místo, kde se nacházel (`[image 1]`, …). Nová konverzace nahraje každý obrázek v historii, pokračující pouze obrázky nových zpráv. Až 10 obrázků PNG, JPEG, GIF nebo WebP o maximální velikosti 10 MiB (40 MiB na požadavek); formát se čte z bajtů. HTTPS URLs jsou načítány prostřednictvím pouze veřejné, DNS-připnuté vzdálené ochrany obrazu. Při neúspěšném nahrání se požadavek nezdaří (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` nebo `m365_image_invalid`); zatáčka nikdy nepokračuje bez obrazu, který dostala. Ostatní netextové části (audio, soubory) jsou odmítnuty explicitně, nikoli tiše odstraněny.
- Následná žádost pokračuje ve stejné konverzaci proti proudu a odesílá pouze zprávy po předchozí odpovědi. Musí přesně rozšířit tuto odpověď: stejné připojení, profil modelu a sada nástrojů; nezměněná historie (řetězec sha256 nad každou zprávou); a ID volání nástroje odpovědi nebo její text až do mezer. Cokoli jiného (upravená historie, další relace se stejnou první zprávou, jiná odpověď, konverzace nečinná po dobu 30 minut nebo blízko limitu 600 zpráv Copilot, připojení bez ID) zahájí novou konverzaci s celou historií. Neúspěšný tah není nikdy obnoven a `InternalError` bez obsahu je znovu odeslán jednou v nové konverzaci (** 502** `m365_internal_error` pokud znovu selže). Pokračování jsou uložena v paměti procesu: restart zahájí nové konverzace.
- Každé kolo probíhá v dočasném chatu Copilot(`disableMemory=1`): konverzace si během běhu zachovává svůj kontext a nikdy se neobjeví v historii chatu účtu. Modelové testy, Testovat vše a kombinované testy proto mohou tohoto poskytovatele prozkoumat, aniž by opustili konverzace.
- Zatáčka má 120sekundový nečinný termín a omezený celkový termín. Pouze konečné odpovědi, filtrování průběhu a zrušení jsou řešeny nativním transport/composer.
- Odpovědi založené na webu si uchovávají své zdroje. Copilot označí citaci vloženou pomocí řídicích znaků pro soukromé použití a odešle zdroje jako `references`; každá značka se stane očíslovaným odkazem Markdown (`[1](https://…)` nebo holé URL když Copilot použilo značku jako cíl odkazu) s odpovídající anotací `url_citation` (`message.annotations` nebo `delta.annotations` na bloku, který nese odkaz). Zdroj, který nikdy nedorazí, je zahozen, takže značky nikdy nedosáhnou klienta. Při streamování text za citací čeká, dokud nedorazí její zdroj.
- Souhrn zdůvodnění Copilot(`ChainOfThoughtSummary`), když model odešle jeden, je vrácen jako `reasoning_content`, nikdy jako součást odpovědi. Souhrn, který se sám přepíše, přestane streamovat, aniž by selhal.
- Před jakýmkoli obsahem si selhání licence/throttle zachovají HTTP 403/429 i když bylo požadováno streamování. Po spuštění obsahu jsou selhání chybové události SSE, nikdy úspěšné dokončení. Přepis proti proudu, který nemůže být reprezentován streamováním pouze s připojením, je explicitní chyba proudu; non-streaming a odezvy nástroje ve vyrovnávací paměti zachovávají konečný text.
- Když Copilot odmítne samotné připojení, jeho odpověď je hlášena tak, jak je:** 401** `m365_unauthorized` za odmítnuté přihlášení nebo přihlášení, jehož platnost vypršela (přihlaste se znovu),** 429** s jeho `Retry-After` pro omezení a selháním handshake, jinak nikdy obecným selháním připojení.

## Generování obrazu

`POST /v1/images/generations` se `model: "copilot-m365-web/m365-copilot-image"` (jinak `m365copilot/m365-copilot-image`) kreslí pomocí vestavěného nástroje pro tvorbu obrázků Copilot, stejně jako webový klient. Každý obrázek je jedním otočením Copilot : přihlásí se s nastavením a deklarací možností obrázku webového klienta `GenerateGraphicArt` a obrázek dorazí na záznam průběhu ukazující na artefakt ve službě Designer Microsoft. Tento artefakt odmítá token chatu, takže OmniRoute vyrazí token návrháře z obnovovacího tokenu připojení a stáhne bajty; token je vždy odeslán pouze `designerapp.officeapps.live.com`.

- Vyžaduje nativní přihlašovací připojení (obnovovací token); vložený token selže s** 400** předtím, než se utratí jakýkoli tah.
- `n` je 1–4, každá jedna otáčka. `size` řídí pouze orientaci (širší, vyšší nebo čtvercovou), kterou Copilot čte z výzvy; Copilot vybere velikost vykreslení.
- Obrázky jsou vráceny inline: standardně `b64_json`, data URL pro `response_format: "url"`.
- Vygenerované obrázky čerpají z malého denního rozpočtu, odděleně od chatu. Když je vyčerpán, požadavek selže s** 429** . Zatáčka, která odpovídá bez obrázku, selhává** 502** (nebo** 400** /** 503** když se text Copilot čte jako odmítnutí nebo problém s kapacitou); zpráva říká která.

## Bezpečnostní model

- **Neoficiální integrace.** Tento poskytovatel zpětně analyzuje protokol BizChat WebSocket. Může se přerušit bez upozornění, když Microsoft změní koncový bod.
- Příznak `subscriptionRisk: true` odráží, že integrace závisí na nezdokumentovaném koncovém bodu. Omezení účtu jsou možná, ale nejsou potvrzena.
- Přístupovým tokenem je krátkodobý JWT. Zacházejte s ním jako s heslem: nezadávejte, nezapisujte ani nesdílejte.
- Obnovovací token poskytuje trvalý přístup k povrchu Microsoft 365. Uchovávejte jej se stejnou péčí jako klíč API.

## Odstraňování problémů

### Ověření se okamžitě nezdaří

- Ověřte, že jste zkopírovali z**WebSocket URL** , nikoli z požadavku XHR/Fetch. Pověření je v parametru dotazu `access_token` připojení Chathub WebSocket — nikoli v záhlaví `Authorization: Bearer`.
- Ujistěte se, že `chathubPath` zahrnuje celý segment `<oid>@<tenant>` z cesty URL.

### Token vyprší po ~ 75 minutách

To se očekává. Bez `refreshToken` je přístupový token krátkodobý. Buď:

- Znovu zachyťte pověření od DevTools, popř
- Konfigurovat** Pokročilá nastavení → Obnovovací token (volitelné)** v dialogovém okně Přidat nebo Upravit připojení pro automatické obnovení.

### Test připojení projde, ale chat vrátí 401

Pro spojení vytvořené s** Přihlaste se pomocí Microsoft** Test Connection zkontroluje vypršení platnosti přístupového tokenu a obnoví token, jehož platnost vypršela, pomocí uloženého obnovovacího tokenu, takže úspěšný test také prokáže, že obnovovací token stále funguje.

U vloženého pověření Test Connection zkontroluje tvar pověření, a když token vyprší, zda nevypršela platnost tokenu, který by poskytovatel použil (uložený token připojení vyhraje zastaralé vložení; obnovovací token se počítá jako obnovitelný). Token, který je odvolán před vypršením platnosti, stále projde testem; chat se poté vrátí** 401** `m365_unauthorized`. Použití** Přihlaste se pomocí Microsoft** znovu nebo znovu získat nové pověření.

### Copilot se nezobrazuje v seznamu poskytovatelů

Ujistěte se, že `copilot-m365-web` je povoleno v** Poskytovatelé Dashboard →** . Poskytovatel může být na některých úrovních ve výchozím nastavení skrytý.
