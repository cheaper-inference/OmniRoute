## Jak to funguje

```
CLI Code's / CLI Agents (tok využití):
Claude / Codex / OpenCode / Cline / KiloCode / Continue / Hermes Agent / Goose / ...
           │
           ▼  (všechny směřují na OmniRoute)
    http://YOUR_SERVER:20128/v1
           │
           ▼  (OmniRoute směruje požadavek ke správnému poskytovateli)
    Anthropic / OpenAI / Gemini / DeepSeek / Groq / Mistral / ...

ACP Agents (obrácený tok spouštění):
    Požadavek klienta → OmniRoute → spustí CLI přes stdio/ACP → odpověď
```

**Výhody:**

- Jeden klíč API pro správu všech nástrojů
- Sledování nákladů napříč všemi CLI v řídicím panelu
- Přepínání modelů bez nutnosti znovu konfigurovat každý nástroj
- Funguje lokálně i na vzdálených serverech (VPS, Docker, Akamai, Cloudflare Tunnel)

## Automatická konfigurace pomocí `setup-*`

Konfiguraci jednotlivých nástrojů nemusíte psát ručně. OmniRoute poskytuje pro každé podporované CLI příkaz `setup-*`, který načte **aktuální** katalog modelů ze spuštěné instance OmniRoute (místní nebo vzdálené) a zapíše vlastní konfiguraci nástroje do vašeho počítače:

```bash
omniroute setup-codex        omniroute setup-claude       omniroute setup-opencode
omniroute setup-cline        omniroute setup-kilo         omniroute setup-continue
omniroute setup-cursor       omniroute setup-roo          omniroute setup-crush
omniroute setup-goose        omniroute setup-qwen         omniroute setup-aider
omniroute setup-5dive        omniroute setup-zed
```

Každý z nich podporuje `--remote <url> --api-key <key>` (konfigurace místního nástroje pro vzdálenou instanci OmniRoute), `--dry-run` (náhled bez zápisu) a `--port`. Nástroje bez automatického zjišťování modelů (Cline, Kilo, Roo, Goose, Aider, Qwen, 5dive) přijímají `--model <id>` (a `--yes` pro neinteraktivní spuštění). `setup-5dive` je jediný postup, který nezapisuje do `$HOME`: konfiguruje flotilu agentů 5dive zapsáním kořenovým uživatelem vlastněného ověřovacího profilu na hostiteli flotily, takže se znovu spustí prostřednictvím `sudo` a nemá vlastní vzdálený režim. Chcete-li spustit CLI se správně předanými proměnnými prostředí, aniž by se zapsala jakákoli konfigurace, použijte obecný spouštěč `omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini — cíle a aliasy pocházejí z `bin/cli/cli-manifest.mjs`); starší spouštěče pro jednotlivé nástroje `omniroute launch` (Claude Code) a `omniroute launch-codex` (Codex) zůstávají dostupné. Gemini CLI lze pouze spouštět: je cílem příkazu `omniroute run`, ale nemá postup `setup-*`/`configure`.

> **Kompletní reference:** hlavní tabulku — co jednotlivé příkazy zapisují, všechny příznaky, místní a vzdálený režim a které nástroje vyžadují příponu `/v1` — najdete v dokumentu
> **[Integrace CLI](../guides/CLI-INTEGRATIONS.md)**.

### Spouštění těchto příkazů uvnitř kontejneru

Příkaz `setup-*` spuštěný uvnitř kontejneru OmniRoute zapisuje do domovského adresáře samotného kontejneru, který žádné CLI na hostiteli nečte a který po zániku kontejneru zmizí. OmniRoute tuto situaci rozpozná a namísto zápisu skončí s kódem `2` a zobrazí pokyny. Existují dva podporované postupy — nainstalovat CLI na hostitele a připojit se ke kontejneru pomocí `omniroute connect`, nebo připojit konfigurační adresáře pomocí bind mountu a nastavit `CLI_CONFIG_HOME` (profil compose `host`). Každý příkaz `setup-*` a také `omniroute configure` a `omniroute config set` podporují `--allow-container-write`, pokud skutečně chcete konfigurovat CLI samotného kontejneru; stejného výsledku lze pro server dosáhnout pomocí `OMNIROUTE_ALLOW_CONTAINER_CONFIG_WRITE=true`. Viz
[Průvodce Dockerem → Konfigurace nástrojů CLI na hostiteli](../guides/DOCKER_GUIDE.md#configuring-host-cli-tools-when-omniroute-runs-in-docker).

**Koncový bod apply** řídicího panelu (`POST /api/cli-tools/apply`) vynucuje stejnou ochranu: v kontejneru požadavek na zápis, jehož cíl není připojen z hostitele pomocí bind mountu, odpoví kódem **`422`** s `containerEphemeralTarget: true`, bezpečným textem chyby a — u nástrojů s postupem pro hostitele (claude, codex, opencode, cline, kilo, continue) — také s `hostSetupCommand` (např. `omniroute setup-opencode`), který je třeba spustit na hostiteli; nic se nezapíše. `dryRun: true` funguje i nadále v režimu kontejneru a vrací redigovaný náhled a cílovou cestu, aniž by se dotkl disku. Obsah náhledu nepředstavuje konfiguraci obsahující přihlašovací údaje, kterou by bylo možné zkopírovat nebo importovat. Použijte původní vstupy nástroje, základní URL, klíče API a modelu na hostiteli nebo použijte uvedený instalační příkaz na straně hostitele. Informace o záhlaví náhledu a kontraktu požadavku najdete v dokumentu [Zabezpečení konfigurace CLI](../security/CLI-CONFIGURATION.md). Toto chování je záměrné a proti regresím je chráněno testem `tests/unit/api/cli-tools/apply-container-guard.test.ts` — chybu 422 se nikdy nepokoušejte „opravit“ odstraněním této ochrany.

## Zdroj pravdy

Sjednocený katalog se nachází v `src/shared/constants/cliTools.ts` jako `CLI_TOOLS: Record<string, CliCatalogEntry>`.

Každá položka obsahuje následující pole (definovaná v `src/shared/schemas/cliCatalog.ts`):

| Pole                                            | Typ                                                          | Popis                                                            |
| ----------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------- |
| `category`                                      | `"code" \| "agent"`                                          | Na které stránce se nástroj zobrazuje                            |
| `vendor`                                        | `string`                                                     | Původ nástroje („Anthropic“, „OSS (P. Gauthier)“)                |
| `acpSpawnable`                                  | `boolean`                                                    | Lze jej použít také jako agenta ACP (zobrazuje se odznak)        |
| `baseUrlSupport`                                | `"full" \| "partial" \| "none"`                              | Úroveň podpory vlastního koncového bodu. `"none"` = backlog MITM |
| `configType`                                    | `"env" \| "custom" \| "guide" \| "custom-builder" \| "mitm"` | Mechanismus konfigurace                                          |
| `id`, `name`, `color`, `description`, `docsUrl` | standard                                                     | Základní pole pro zobrazení                                      |

Položky s `baseUrlSupport: "none"` se na stránkách řídicího panelu **nezobrazují** — jsou evidovány v backlogu MITM pro plán 11 (viz `_tasks/features-v3.8.6/refactorpages/_orchestration/_plan11-mitm-backlog.md`).

### Úrovně schopností (katalogizovatelné × detekovatelné × konfigurovatelné × spustitelné)

Ne každý katalogizovaný nástroj lze detekovat, konfigurovat nebo spustit. Každá úroveň má jeden
deklarativní zdroj a test odchylek zajišťuje jejich vzájemný soulad:

| Úroveň                | Význam                                                                                              | Deklarováno v                                                    |
| --------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| **Katalogizovatelné** | Zobrazuje se v katalogu řídicího panelu (název, dodavatel, dokumentace, typ konfigurace)            | `src/shared/constants/cliTools.ts` (`CLI_TOOLS`)                 |
| **Detekovatelné**     | Detekce binárního souboru/konfigurace, kontroly stavu, cesty ke konfiguraci                         | `src/shared/services/cliRuntime.ts` (běhový katalog `CLI_TOOLS`) |
| **Konfigurovatelné**  | Podporováno příkazem `omniroute configure <cli>` (existuje postup nastavení)                        | `bin/cli/cli-manifest.mjs` (`configure: true`)                   |
| **Spustitelné**       | Podporováno příkazem `omniroute run <target>` (definováno předávání proměnných prostředí/argumentů) | `bin/cli/cli-manifest.mjs` (`run: true`)                         |

`bin/cli/cli-manifest.mjs` je kanonický spustitelný manifest pro rozhraní příkazů CLI:
`run`, `configure` a generátory doplňování příkazů v shellu z něj odvozují své
seznamy cílů, rozpoznávání aliasů (například `kilocode`/`kilo-code`/`kilo_cli` → `kilo`)
a zapojení příznaku `--model`. Ochrana proti odchylkám
`tests/unit/cli/cli-manifest-drift.test.ts` ověřuje, že manifest, běhový
katalog, katalog uživatelského rozhraní a všechna spotřebitelská rozhraní zůstávají synchronizovaná — přidání cíle do
jednoho rozhraní bez ostatních způsobí selhání sady testů namísto vzniku nepozorované odchylky.

## 5. API pro dávkovou detekci

Veškerá detekce nástrojů je agregována prostřednictvím jediného koncového bodu:

**`GET /api/cli-tools/all-statuses`**

- Ověřování: `requireCliToolsAuth(request)` (stejné jako u ostatních tras `/api/cli-tools/`)
- Vrací: `Record<toolId, ToolBatchStatus>` (typ: `src/shared/types/cliBatchStatus.ts`)
- Strategie: `Promise.all` nad všemi nástroji, časový limit 5 s pro každý nástroj
- Mezipaměť: LRU v paměti indexovaná podle `mtime` konfiguračního souboru. Mezipaměť se zneplatní při změně `mtime`. Při restartování serveru se resetuje.

Struktura odpovědi pro jednotlivé nástroje:

```ts
interface ToolBatchStatus {
  detection: {
    installed: boolean;
    runnable: boolean;
    version?: string;
    command?: string;
    commandPath?: string;
    reason?: string;
  };
  config: {
    status: "configured" | "not_configured" | "not_installed" | "unknown" | "other";
    endpoint?: string | null;
    lastConfiguredAt?: string | null;
  };
  error?: string; // sanitizováno, bez trasování zásobníku
}
```

## 10. Interní CLI OmniRoute

Binární soubor `omniroute` poskytuje příkazy pro správu životního cyklu serveru, nastavení, diagnostiku a správu poskytovatelů. Vstupní bod: `bin/omniroute.mjs`.

```bash
omniroute                              # Spustit server (výchozí port 20128)
omniroute setup                        # Interaktivní průvodce nastavením
omniroute doctor                       # Zkontrolovat konfiguraci, DB, porty a běhové prostředí
omniroute providers list               # Nakonfigurovaná připojení k poskytovatelům
omniroute providers test-all           # Otestovat všechna aktivní připojení
omniroute reset-password               # Obnovit heslo správce
omniroute logs                         # Průběžně zobrazovat protokoly požadavků
omniroute health                       # Podrobný stav (jističe, mezipaměť, paměť)
omniroute --version                    # Vypsat verzi
omniroute --help                       # Zobrazit všechny příkazy
```

### Nastavení a inicializace

```bash
omniroute setup                        # Interaktivní průvodce nastavením
omniroute setup --non-interactive      # Režim CI/automatizace (načítá proměnné prostředí + příznaky)
omniroute setup --password '<value>'   # Nastavit heslo správce přímo
omniroute setup --add-provider \
  --provider openai \
  --api-key '<value>' \
  --test-provider                      # Přidat a otestovat poskytovatele v jednom kroku
```

Rozpoznávané proměnné prostředí pro neinteraktivní nastavení:

| Proměnná            | Účel                                                                     |
| ------------------- | ------------------------------------------------------------------------ |
| `OMNIROUTE_API_KEY` | Klíč API poskytovatele (propojený s `--api-key` přes Commander `.env()`) |
| `DATA_DIR`          | Přepsání datového adresáře OmniRoute                                     |

Všechny ostatní neinteraktivní vstupy se předávají jako příznaky, nikoli jako proměnné prostředí:
`--password`, `--provider`, `--provider-name`, `--provider-base-url`, `--default-model`
(viz možnosti `omniroute setup` výše).

### Diagnostika

```bash
omniroute doctor                       # Zkontrolovat konfiguraci, DB, porty, běhové prostředí, paměť a dostupnost
omniroute doctor --json                # Strojově čitelný JSON
omniroute doctor --no-liveness         # Přeskočit kontrolu stavu přes HTTP
omniroute doctor --host 0.0.0.0        # Přepsat hostitele kontroly dostupnosti
omniroute doctor --liveness-url <url>  # Přepsat úplnou URL koncového bodu stavu
```

Příkaz doctor provádí tyto kontroly: `Config`, `Database`, `Storage/encryption`,
`Port availability`, `Node runtime`, `Native binary` (better-sqlite3),
`Memory` a `Server liveness`. Pokud má některá kontrola stav `fail`, skončí s nenulovým návratovým kódem.

### Správa poskytovatelů

```bash
omniroute providers available                       # Katalog poskytovatelů OmniRoute
omniroute providers available --search openai       # Filtrovat katalog podle ID/názvu/aliasu/kategorie
omniroute providers available --category api-key    # Filtrovat podle kategorie (api-key, oauth, free, ...)
omniroute providers available --json                # Strojově čitelný JSON

omniroute providers list                            # Nakonfigurovaná připojení k poskytovatelům
omniroute providers list --json

omniroute providers test <id|name>                  # Otestovat jedno nakonfigurované připojení
omniroute providers test-all                        # Otestovat všechna aktivní připojení
omniroute providers validate                        # Pouze místní strukturální ověření
omniroute providers add <provider> --credential-env PROVIDER_KEY
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth <provider>                 # Stávající tok OAuth
omniroute providers edit <id|name> --default-model <model>
omniroute providers remove <id|name> --yes
```

Příkazy `providers add/import/auth/edit/remove` primárně používají API, a proto fungují vůči
aktivnímu místnímu nebo vzdálenému kontextu. Přihlašovací údaje by měly být zadávány pomocí
`--credential-stdin` nebo `--credential-env`; `--dry-run --json` hlásí pouze
redigovanou přítomnost/strukturu. `providers available` načítá katalog OmniRoute;
`providers list/test/test-all/validate` zachovávají své místní chování nad SQLite a
nevyžadují spuštěný server.

U vlastního uzlu kompatibilního s OpenAI nebo Anthropic připojte přihlašovací údaje k
ID uzlu vrácenému příkazem `omniroute nodes add` pomocí `omniroute keys add "$NODE_ID" --stdin`.
To vyžaduje spuštěný server a ověření pro správu aktivního kontextu.
CLI používá `POST /api/providers`, který ověří uzel a zkopíruje nastavení jeho koncového bodu
do připojení. Chybějící uzel, selhání autorizace nebo nedostupný server
vrátí chybu bez vytvoření náhradních místních přihlašovacích údajů.

`nodes add --base-url` nastavuje koncový bod uzlu; liší se od adresy serveru
v `OMNIROUTE_BASE_URL`. Pro soubory OpenAPI použijte
`omniroute openapi dump --format json --out ./openapi.json`; globální příznak `--output`
vybírá formát zobrazení CLI, nikoli název cílového souboru.

### Obnova a resetování

```bash
omniroute reset-password                # Obnovit heslo správce (také: omniroute-reset-password)
omniroute reset-encrypted-columns       # Zobrazit varování + zkušební běh resetování šifrovaných přihlašovacích údajů
omniroute reset-encrypted-columns --force  # Skutečně nastavit šifrované přihlašovací údaje v SQLite na hodnotu null
```

### Export přihlašovacích údajů (⚠ zacházejte s nimi opatrně)

```bash
omniroute auth export                                 # Zobrazit varování + vyžádat potvrzení — bez přístupu k DB
omniroute auth export --force                          # Exportovat DEŠIFROVANÉ přihlašovací údaje VŠECH připojení na standardní výstup jako JSON
omniroute auth export --force --id <id>                 # Exportovat pouze odpovídající připojení
omniroute auth export --force --format env               # Vypsat řádky OMNIROUTE_<PROVIDER>_<FIELD>=<value>
omniroute auth export --force --out creds.json           # Zapsat do souboru (vytvořeného s oprávněními 0600)
```

`auth export` funguje **pouze lokálně** (přímé čtení SQLite, bez HTTP trasy) a záměrně vypisuje/ukládá
hodnoty `apiKey`/`accessToken`/`refreshToken`/`idToken` v **prostém textu** — jde o funkci, nikoli o
chybu. Bez příznaku `--force` se z databáze nic nenačte ani nedešifruje. Před vypsáním jakýchkoli
dat v prostém textu se na stderr vždy zobrazí varovný banner. Vyžaduje nastavení
`STORAGE_ENCRYPTION_KEY`. Pole, které se nepodaří dešifrovat (zastaralý klíč, poškozený šifrovaný
text), je označeno jako `<field>DecryptFailed: true`, namísto přerušení celého exportu nebo odhalení
související chyby.

## Správa zásad inferenčního klíče pomocí OmniRoute CLI

Použijte ověřený kontext správy (viz [Vzdálený režim](../guides/REMOTE-MODE.md))
ke kontrole nebo aktualizaci existujícího inferenčního klíče podle jeho ID:

```bash
omniroute --output json keys policy show KEY_ID
omniroute keys policy set KEY_ID --unrestricted
omniroute --output json keys policy show KEY_ID
```

`--unrestricted` je alias pro `--model-access-mode all`. Aktualizace vymaže
seznam povolených modelů. Zachová rozsahy oprávnění, pravidla připojení, blokované modely, limity frekvence
a nákladové limity, takže tyto ostatní řídicí mechanismy mohou požadavek i nadále zamítnout. Explicitní
`--allowed-models ""` také vybere `all`; zkombinujte jej s
`--model-access-mode restricted`, chcete-li zachovat omezený klíč bez povolených modelů.
Neprázdný seznam oddělený čárkami vybere `restricted`, pokud není výslovně uvedeno jinak.
Rozporuplná kombinace `all` s neprázdným seznamem povolených položek je odmítnuta před odesláním požadavku.

`--rate-limit 30` nastaví počet požadavků za minutu a zachová pravidla pro ostatní časová
okna. `--max-cost 5` aktivuje denní limit v USD beze změny týdenního limitu;
`--max-cost 0` odebere denní limit a zachová stávající přepínač limitu využití
a týdenní limit. Vynechaná pole zásad zůstanou beze změny. Změny limitu frekvence nejprve načtou
aktuální zásady; vyhněte se souběžným úpravám pole limitů frekvence stejného klíče.

Příkazy zásad používají ověřené `GET`/`PATCH /api/keys/{id}` a respektují aktivní
kontext a globální volbu `--api-key`. Výstup JSON obsahuje pouze pole zásad,
bez uloženého klíče nebo jeho maskované reprezentace. Přihlašovací údaj určený pouze pro inferenci
nemůže autorizovat změny správy. Odpověď 401/403 vyžaduje kontrolu přihlašovacího údaje
pro správu a kontextu; nedokládá selhání místního tokenu CLI ani soli.
Samostatnou specifikaci místního ověřování naleznete v části [Token CLI](../security/CLI_TOKEN.md).
