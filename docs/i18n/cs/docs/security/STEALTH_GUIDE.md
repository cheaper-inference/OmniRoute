OmniRoute se integruje s poskytovateli, jejichž hraniční infrastruktura aktivně vytváří otisky neoficiálních klientů (TLS JA3/JA4, pořadí hlaviček, struktura těla JSON, tokeny integrity). Tato stránka dokumentuje stealth prvky, které OmniRoute zpřístupňuje, a místa jejich implementace.

## Právní a etické upozornění

Stealth funkce existují proto, aby OmniRoute mohla fungovat jako vrstva kompatibility mezi oficiálními účty vlastněnými uživateli (Claude Code CLI, Codex, Antigravity, Cursor atd.) a jednotným API OmniRoute. **Nejsou** určeny k obcházení detekce podvodů, sdílení přihlašovacích údajů ani porušování podmínek poskytovatelů. Správci očekávají, že provozovatelé budou dodržovat podmínky upstreamových služeb, které přijali při vytváření účtů.

## Vrstva otisku TLS

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Trvalé relace `wreq-js` se vytvářejí líně pro každý rozsah účtu a přeložený proxy server. Celoprocesní
fond `TlsClient` obsahuje nejvýše 128 relací, které se vůči upstreamům za Cloudflare vydávají za
**Chrome 124 v systému macOS**. `TlsClient.fetch()` při nedostupnosti nativního běhového prostředí
bezpečně selže; volající může mimo tuto obálku explicitně vybrat záložní řešení.

- Profil relace: `browser: "chrome_124", os: "macos"`
- Překlad proxy serveru (podle priority): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (také malými písmeny)
- Časový limit: `TLS_CLIENT_TIMEOUT_MS` (dědí z `FETCH_TIMEOUT_MS`, výchozí hodnota 600000)
- Response z `wreq-js` je kompatibilní s fetch (`headers`, `text()`, `json()`, `clone()`, `body`).
- Hlídací mechanismus prvního bajtu (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656):
  `TlsClient.fetch()` se dokončí ihned po přijetí hlaviček upstreamu, takže samotný
  `TLS_CLIENT_TIMEOUT_MS` nedokáže omezit tělo, které nikdy neposkytne první bajt.
  `guardTlsFirstByte()` nechá soupeřit první `read()` těla s `TLS_FIRST_BYTE_WATCHDOG_MS`
  (výchozí hodnota `10000`, hodnota `0` jej vypne); funkční tělo zůstane nedotčeno, zatímco
  zaseknuté tělo zruší čtečku wreq a umožní stávající záložní logice TLS v `proxyFetch` přejít
  k přímému/proxy dispečeru (požadavek, který nelze bezpečně zopakovat, např. POST s tělem, se
  přesto ukončí výjimkou namísto tichého opakování).

### Přenos poskytovatelů webových cookies — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` je sdílený adaptér pro pět níže uvedených specializovaných
přenosů webových cookies. Každá tenká obálka poskytovatele vybírá profil prohlížeče/OS. Adaptér
používá jediný zavaděč běhového prostředí wreq a fond přenosů v `open-sse/utils/tlsClient.ts`,
klíčovaný podle profilu + OS + přeloženého proxy serveru, přičemž každý požadavek používá
`cookieMode: "ephemeral"`. Účty a požadavky proto sdílejí připojení na úrovni přenosu, ale nikdy
nesdílejí relaci wreq ani úložiště cookies.

| Poskytovatel | Profil        | Emulovaný OS | Zásady pro EOF streamu                 |
| ------------ | ------------- | ------------ | -------------------------------------- |
| Claude       | `chrome_146`  | Linux        | zahrnout `[DONE]`                      |
| Perplexity   | `firefox_151` | macOS        | zahrnout `event: end_of_stream`        |
| Grok         | `chrome_146`  | Linux        | vynechat `[DONE]`                      |
| Notion       | `chrome_146`  | Windows      | zahrnout `[DONE]`                      |
| LMArena      | `chrome_146`  | Windows      | bez sentinelu; zavřít při nativním EOF |

- Streamování přímo spotřebovává `ReadableStream` nativní odpovědi; nevytváří se žádný dočasný
  soubor ani pomocný proces.
- Před zpřístupněním streamu se zkontroluje až 256 počátečních bajtů. Poskytovatelé SSE ukládají
  chyby jiné než SSE do vyrovnávací paměti; Grok/LMArena mapují výzvy Cloudflare na `403` a
  mezilehlé stránky HTML na `502`.
- Časový limit nativního požadavku zůstává obalen absolutním pevným termínem v JS. Zaseknutí
  zneplatní a zavře pouze dotčený přenos profilu/OS/proxy serveru, než jej další požadavek znovu
  vytvoří.
- Priorita překladu proxy serveru je `proxyUrl` jednotlivého volání → kontext účtu/řídicího panelu
  s rozsahem požadavku → `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (včetně variant s malými písmeny).
  Chyby překladu bezpečně selžou, místo aby umožnily únik přímého připojení. LMArena záměrně
  provádí překlad vůči `arena.ai`.
- `byteResponse` vrací URL `data:` s typem obsahu bez poškození UTF-8.
- Chyby jsou `TlsClientUnavailableError` (nedostupný balíček/doplněk), `TlsClientHangError`
  (překročený termín) a `WreqTransportCapacityError` (kód chyby kapacity sdílených relací), pokud
  je všech 128 omezených slotů profilu/OS/proxy serveru aktivních nebo se zavírá.

Výše uvedená obecná relace `TlsClient` zůstává specializovaná na trvalý stav cookies založený na
prohlížeči. Obě cesty opakovaně používají jeden zavaděč modulu wreq uložený v mezipaměti a jeden
háček životního cyklu procesu; jejich fondy zůstávají oddělené, protože životnosti jejich cookies
se záměrně liší.

Profily jsou podporovány připnutým balíčkem, ale jejich skutečné přijetí systémem WAF se může měnit
nezávisle na místních smluvních testech. Před deklarováním shody s upstreamovým prohlížečem ověřte
změny otisku pomocí explicitně autorizovaného živého účtu.

## Balíček utajení Claude Code

Když je zapnutý režim `cliCompatMode`, OmniRoute upravuje odchozí požadavky Claude tak, aby byly nerozeznatelné od provozu `claude-cli`. Spolupracují na tom tři moduly:

### `claudeCodeFingerprint.ts`

Vypočítává tříznakový otisk `cc_version` vložený do fakturační hlavičky:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (pevně zakódováno; odpovídá oficiálnímu klientovi)
- Vstupy: znaky na indexech 4, 7 a 20 textu první uživatelské zprávy + řetězec verze
- Výstup: tříznakový hexadecimální prefix

### `claudeCodeCCH.ts` (hash obsahu klienta)

Kontrola integrity na straně serveru, kterou oficiální CLI Claude Code počítá prostřednictvím Bun/Zig. OmniRoute ji znovu implementuje pomocí `xxhash-wasm`:

1. Serializovat tělo se zástupným symbolem `cch=00000;`
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. Pětiznaková hexadecimální hodnota malými písmeny doplněná zleva nulami
4. Nahradit `cch=00000;` vypočítaným tokenem

Konstanty:

- Seed: `0x6e52736ac806831e`
- Vzor: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

Vkládá znak Unicode **spojovník s nulovou šířkou** (`U+200D`) za první znak „citlivých“ názvů klientů, aby je upstreamové filtry nemohly vyhledat pomocí grep. Výchozí seznam slov:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Používá se na: bloky `system`, veškerý obsah `messages[].content` a `tools[].description` / `tools[].function.description`. Operátor může seznam přepsat pomocí `setSensitiveWords()`.

### `claudeCodeCompatible.ts` — poskytovatelé `anthropic-compatible-cc-*`

Pro relé Anthropic třetích stran, která přijímají pouze provoz „skutečného Claude Code“:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- Výchozí hodnota `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- Přepínač „Enable redact-thinking beta“ pro jednotlivá připojení přidá `redact-thinking-2026-02-12`, pokud konkrétní upstream kompatibilní s CC vyžaduje proudy uvažování s redigovaným obsahem
- Přepínač „Enable summarized thinking display“ pro jednotlivá připojení ukládá `providerSpecificData.requestDefaults.summarizeThinking` a přidává `display: "summarized"` do požadavků na uvažování kompatibilních s CC, které dosud nemají nastavený režim zobrazení
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (rodina Opus/Sonnet 4.x)
- Výchozí cesta: `/v1/messages?beta=true`

Sesterské moduly ve stejném balíčku:

- `claudeCodeConstraints.ts` — pravidla pro teplotu + řízení mezipaměti
- `claudeCodeToolRemapper.ts` — přemapování názvů nástrojů
- `claudeCodeExtraRemap.ts` — dodatečná normalizace datové části

## Antigravity Stealth

Antigravity požaduje zachovat text volajícího bajt po bajtu. OmniRoute nevkládá znaky s nulovou šířkou do výzev nebo nástrojů rename/inject za účelem napodobení klienta IDE.

### `antigravityHeaderScrub.ts`

Odstraňuje nerezové značky SDK (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) před odesláním.

### Riziko ⚠️ : `ANTIGRAVITY_CREDITS=always` (hot spot pro zákaz účtu)

Trasy `ANTIGRAVITY_CREDITS=always` (spotřebované `open-sse/executors/antigravity.ts`).**každý** požádat prostřednictvím Antigravity AI Credit Overages (placené kredity Google ) namísto toho, abyste nechali věci Google bez kvóty. To je zdokumentováno jako vlastnost, ale je to tak **jediná nejběžnější zpráva o porušení smluvních podmínek, kterou vidíme** Několik — účtů Google Ultra bylo zakázáno pomocí `403 / "service disabled for ToS violation" / insufficient_quota` poté, co několik hodin běželi se `=always`.

Vymáhání proti proudu je zapnuto **Strana Google** , nic nemůže OmniRoute zabránit. Díky názvu env var a existujícím dokumentům to zní jako bezpečné tlačítko; není.

**Proč to přitahuje detekci zneužití agresivněji než použití pouze na bezplatné úrovni:**

- Trvalé automatizované výdaje na jediném účtu Google se projevují jinak než přístupy-kvóta-a-zastavení zdarma.
- Překročení kreditu nemá žádný strop, takže špatně nakonfigurovaný klient může spálit několik stovek USD během několika minut a vypadat jako přeprodej klíčů API nebo provoz botů.
- Více uživatelů OmniRoute, kteří paralelně zaznamenají přebytečné kredity ze stejného externího IP zesílí signál.

**Doporučený postoj:**

1. Ponechte výchozí `ANTIGRAVITY_CREDITS=off`, pokud provozovatel výslovně nepřijme riziko placeného úvěru a vynucení účtu. `retry` odešle normální žádost jako první a vloží kredity maximálně jednou po způsobilé kvótě 429; `always` vloží kredity na první žádost.
2. **Rozložte zatížení mezi poskytovatele pomocí funkce Auto-Combo** (`model: "auto"` nebo `kr/glm/etc` -combo) namísto nasycení jednoho účtu Antigravity.
3. **Nastavte limity RPM na připojení** na stránce úprav poskytovatele Antigravity (Dashboard Poskytovatelé → → Antigravity → omezení rychlosti připojení → ). 30–60 RPM je obhajitelná horní hranice pro trvalé používání.
4. **Používejte stabilní, operátorem řízené upstream sítě** a vyhněte se sdílení jednoho účtu mezi nesouvisejícími uživateli nebo pracovní zátěží.
5. **Pokud je zakázáno** : odvolání přes `support.google.com` → "Obnovit přístup Workspace/Account " s přesným odesláním `quota_exceeded` / `service disabled` těla odpovědi Google. Obnova není zaručena.

Referenční prostředí dokumentuje důsledky účtu a výdajů každého režimu kreditů.

#### Nejen `=always`: Antigravity OAuth směrování obecně

Pozastavení se neomezují na překročení kreditu. Zprávy z listopadu 2026 (#19223, #19266) popisují několik účtů Google pozastavených při směrování přes poskytovatele `antigravity` a `agy` (Antigravity CLI), přičemž:

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

Oba poskytovatelé se ověřují pomocí relace OAuth produktu Antigravity, což je případ, na který před přidáním připojení varuje upozornění o riziku na řídicím panelu („Tento poskytovatel používá váš oficiální produkt session/OAuth, který není autorizován pro použití proxy/router “). Žádné z výše uvedených doporučení nepovoluje toto použití; pouze snižují návštěvnost jednoho účtu.

**Autorizovaná rozhraní API pro modely Gemini.** Google nabízí programový přístup k Gemini prostřednictvím svého APIs, který OmniRoute podporuje jako běžní poskytovatelé klíčů API:

| ID poskytovatele | Název řídicího panelu     | Pověření                                                                         |
| ---------------- | ------------------------- | -------------------------------------------------------------------------------- |
| `gemini`         | Gemini (Google AI Studio) | Klíč Gemini API od Google AI Studio (k dispozici zdarma úroveň)                  |
| `vertex`         | Vertex AI                 | Servisní účet JSON, přístupový token OAuth nebo klíč Vertex Express API (Gemini) |

Tito poskytovatelé na rozdíl od relace produktu Antigravity používají problémy Google s přihlašovacími údaji pro přístup API. Neprovádějí každé použití v souladu ani neodstraňují riziko vynucení: každé se řídí svými vlastními podmínkami, které musí operátor pro jejich nasazení zkontrolovat. Například [dodatečné smluvní podmínky Gemini API](https://ai.google.dev/gemini-api/terms) povolují pouze placené služby, když jsou klienti API zpřístupněni uživatelům v Evropském hospodářském prostoru, Švýcarsku nebo Spojeném království, a obsah zaslaný do neplacených služeb lze použít ke zlepšení produktů Google. Vertex AI místo toho spadá pod podmínky Google Cloud ( [Podmínky specifické pro službu](https://cloud.google.com/terms/service-terms) ). Ceny a kvóty se řídí těmito podmínkami API spíše než předplatným Antigravity.

Operátoři, kteří se chtějí vyhnout výše popsaným pozastavením Antigravity, by měli směrovat provoz Gemini přes jednoho z těchto poskytovatelů namísto `antigravity` / `agy`, poté, co zkontrolují, zda jejich použití odpovídá podmínkám poskytovatele.

Dotykové body:

- `open-sse/executors/antigravity.ts` — čte `process.env.ANTIGRAVITY_CREDITS`
- `src/lib/oauth/providers/antigravity.ts` — pověření instalatérství
- Původní zpráva o incidentu: Diskuze [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## Registr otisků CLI — `open-sse/config/cliFingerprints.ts`

Tabulka pro jednotlivé poskytovatele, která pevně určuje **přesné** pořadí hlaviček a pořadí polí těla JSON zachycené ze záznamů mitmproxy oficiálních CLI. Aktuálně jsou registrovány: `codex`, `claude` a také profily odvozené za běhu v `providerHeaderProfiles.ts` pro `antigravity` a `github`.

```ts
interface CliFingerprint {
  headerOrder: string[]; // rozlišuje velká a malá písmena
  bodyFieldOrder: string[]; // klíče JSON nejvyšší úrovně
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Přepíná se pro každého poskytovatele prostřednictvím proměnných prostředí (viz níže). Když je tato funkce vypnutá, hlavičky a klíče těla se zobrazí v pořadí, v jakém je poskytly Node/JSON — takže je lze snadno identifikovat podle otisku.

## MITM proxy (Antigravity, Linux/macOS/Windows)

Pro CLI, jejichž binární soubory nelze přesměrovat pomocí `OPENAI_BASE_URL`, spouští OmniRoute lokální proxy ukončující TLS. Koncové body se nacházejí pod `src/app/api/cli-tools/antigravity-mitm/`.

| Metoda | Koncový bod                             | Účel                                               |
| ------ | --------------------------------------- | -------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | Stav — spuštěno, pid, dnsConfigured, certExists    |
| POST   | `/api/cli-tools/antigravity-mitm`       | Spuštění MITM (vyžaduje `apiKey` + `sudoPassword`) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | Zastavení MITM                                     |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | Výpis aliasů modelů                                |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | Uložení aliasů modelů pro nástroj                  |

Cílový zachytávaný hostitel: **`daily-cloudcode-pa.googleapis.com`** (upstream služby Antigravity).

### Sekvence spuštění (`src/mitm/manager.ts::startMitm`)

1. Vygenerování certifikátu podepsaného svým držitelem prostřednictvím `selfsigned` (RSA-2048, SHA-256, 1 rok) — `cert/generate.ts`
2. Instalace certifikátu do systémového úložiště důvěryhodných certifikátů — `cert/install.ts`
3. Přidání záznamu `127.0.0.1 daily-cloudcode-pa.googleapis.com` do souboru hosts — `dns/dnsConfig.ts`
4. Spuštění `src/mitm/server.cjs` s `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (výchozí hodnota `443`)
5. Uložení PID do `<DATA_DIR>/mitm/.mitm.pid`

### Dynamická detekce úložiště důvěryhodných certifikátů v Linuxu — `cert/install.ts`

`getLinuxCertConfig()` prochází seznam priorit a vybere první existující adresář:

| Rodina distribucí        | Adresář                                     | Příkaz pro aktualizaci   |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Název souboru certifikátu: `omniroute-mitm.crt`. Porovnání otisku prostřednictvím `getCertFingerprint()` (SHA-1 dat DER).

Funkce `updateNssDatabases()` navíc instaluje certifikát do uživatelských databází NSS, pokud je k dispozici `certutil`: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, všechny profily Firefoxu (včetně snap), pod názvem **`OmniRoute MITM Root CA`**.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** PowerShell se zvýšenými oprávněními → `certutil -addstore Root`

### Ověřování

Všechny koncové body MITM vyžadují ověření správy (`requireCliToolsAuth`). Heslo sudo se ukládá do mezipaměti v rámci modulu (nikdy v `globalThis`) a při `stopMitm()` se vymaže.

## Čištění příchozích hlaviček

OmniRoute před předáním odstraňuje příchozí hlavičky klienta, aby požadavek přijatý z Cursoru neprozradil nadřazené službě Claude hlavičku `User-Agent: Cursor/X.Y.Z`. Seznam zakázaných hlaviček najdete v `src/shared/constants/upstreamHeaders.ts`; je udržován v přesném souladu se schématy Zod a jednotkovými testy.

## Aktualizace otisků při jejich změně poskytovatelem

1. Zachyťte provoz oficiálního CLI pomocí `mitmproxy` (zachycení TLS + výpis)
2. Extrahujte JA3/JA4 a doslovné pořadí hlaviček
3. Aktualizujte odpovídající položku `CLI_FINGERPRINTS[...]`
4. Aktualizujte odpovídající výchozí hodnotu `*_USER_AGENT` v `.env.example`
5. Pokud se změnil samotný handshake TLS, aktualizujte odpovídající obalovou vrstvu poskytovatele nebo volbu `browser:` knihovny wreq-js
6. Spusťte testy TLS specifické pro daného poskytovatele a ruční ověřovací test vůči živé službě poskytovatele
7. Vydejte změnu v opravné verzi a zdokumentujte ji v `CHANGELOG.md`
