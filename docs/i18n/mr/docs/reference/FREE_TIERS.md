## TL;DR — OmniRoute प्रत्यक्षात किती मोफत इन्फरन्स एकत्रित करते?

हे आकडे संपूर्ण कॅटलॉगमधील स्वतंत्र तृतीय-पक्ष खाती आणि पात्रतेच्या अटी दर्शवतात. OmniRoute हे बजेट देत नाही: तुम्ही आवश्यक खाती किंवा क्रेडेन्शियल्स मिळवली पाहिजेत, पात्र प्रदाते जोडले पाहिजेत आणि त्यांच्या मर्यादांचे पालन केले पाहिजे. प्रत्यक्षात वापरता येणारी क्षमता कमी असू शकते—पात्र मार्ग नसलेल्या नव्या इंस्टॉलेशनवर ती शून्यही असू शकते. `tos: avoid` अशी खूण असलेले प्रदाते डीफॉल्टनुसार स्वयंचलित राउटिंगमधून वगळले जातात.

**2026-10-08 रोजी तपासले:** [Cerebras](https://www.cerebras.ai/pricing) पेमेंट पद्धत आवश्यक असलेले, 30 दिवसांनंतर कालबाह्य होणारे, एकदाच मिळणारे $5 प्रमोशनल क्रेडिट देते. [Gemini](https://ai.google.dev/gemini-api/docs/rate-limits) प्रकल्प/मॉडेल/स्तरानुसार दरमर्यादा प्रकाशित करते; मात्र ते परिमाणित मासिक मुख्य आकड्याबाहेरच राहते.

**प्रामाणिक मुख्य दावा:** _OmniRoute 34 मोफत-स्तर पूलमधून **दरमहा ~1.62B दस्तऐवजीकृत मोफत टोकन** एकत्रित करते (साइनअप क्रेडिटसह तुमच्या पहिल्या महिन्यात ~2.22B पर्यंत)—याशिवाय कायमस्वरूपी मोफत आणि मर्यादा नसलेल्या प्रदात्यांची मोठी अतिरिक्त श्रेणी उपलब्ध आहे—आणि RTK + Caveman कॉम्प्रेशनमुळे (15–95% टोकन बचत) हे बजेट आणखी जास्त काळ वापरता येते._

Guard जेव्हा pool filter करतो, तेव्हा operator ला दिसणाऱ्या log मध्ये exclusion count आणि त्यातील `no-hard-stop` वाटा दोन्ही नोंदवले जातात.

- **Deposit-unlock वाढ:** एकदाच केलेला लहान top-up, जो free quota कायमस्वरूपी वाढवतो (OpenRouter: $10 → 1000 req/day ≈ +24M/mo). स्वतंत्र आकडा म्हणून नोंदवला असून नियमित headline मधून वगळला आहे.
- **पात्रता-आधारित quotas** (`eligibilityGate: "regional-identity"`): प्रत्यक्षात पुन्हा-पुन्हा मिळणारा quota, जो region-bound identity check नंतरच खुला होतो (सध्या mainland-China real-name verification). समान pool-dedupe नियमानुसार स्वतंत्र आकड्यात (`gatedRecurringTokens`) मोजला जातो; नियमित headline मध्ये कधीही समाविष्ट केला जात नाही. व्यवस्था (`freeType`) बदलत नाही, त्यामुळे routing देखील बदलत नाही.
- **पुराव्यांचे वर्ग.** नियम असा आहे: catalog मधील एखादा आकडा त्याच्या नोंदीशेजारील `// evidence:` comment मध्ये त्याचा source उद्धृत करतो — `public-page` (कोणीही वाचू शकेल असे provider page), `api-public` (provider चे unauthenticated endpoint, उदा. router.bynara.id वरील NaraRouter चे public plans endpoint), किंवा `console-verified <date> por <who>` (आकडा फक्त account console मध्ये दिसतो; comment मध्ये तो कोणी आणि केव्हा पाहिला याची तसेच cap अस्तित्वात असल्याचे सांगणाऱ्या public page ची नोंद असते). सध्याची स्थिती: 2026-09-02 रोजी पुन्हा audit केलेल्या पाच blocks मध्ये तो आहे (`gemini`, `groq`, `mistral`, `ollama-cloud`, `nara`); 2026-09-02 च्या re-audit पूर्वीच्या नोंदींमध्ये त्या नोंदींना स्पर्श होईपर्यंत आधीचे research कायम राहते; evidence comment नसलेला कोणताही **नवीन किंवा बदललेला** आकडा हा bug आहे. सध्या फक्त `mistral` हा console-verified आहे.

## आमची संख्या इतर अॅग्रीगेटर्सच्या संख्येपेक्षा लहान का आहे

या क्षेत्रातील बहुतेक "दर महिन्याला मोफत टोकन्स" हे आकडे प्रत्येक मॉडेलच्या लेबलांची बेरीज असतात. आमचा आकडा हेतुपुरस्सर तसा नाही:

- **प्रत्येक सामायिक पूल फक्त एकदाच मोजला जातो.** Mistral च्या मोफत योजनेत प्रत्येक संस्थेसाठी दरमहा एक 1B मर्यादा आहे; ती पाच मॉडेल्सखाली सूचीबद्ध केल्याने ती 5B होत नाही. प्रत्येक मॉडेलनुसार बेरीज केल्यास, आमचाच कॅटलॉग **~7.4B** दर्शवेल (2026-09-03 रोजी पुन्हा मोजलेला; हा आकडा CI-द्वारे नियंत्रित नाही — कॅटलॉग बदलल्यावर तो पुन्हा मोजा) — मथळ्यात **~1.47B** म्हटले आहे, कारण प्रत्येक प्रदात्याचे एक खाते प्रत्यक्षात तेवढेच वापरू शकते.
- **दैनिक मर्यादांचे रूपांतर केले जाते, दरांचे नाही.** दस्तऐवजीकरण केलेली tokens/day मर्यादा `× 30` होते; दस्तऐवजीकरण केलेली requests/day मर्यादा `RPD × ~800 tokens × 30` होते; जो प्रदाता केवळ requests-per-minute प्रकाशित करतो, त्याच्यासाठी **कोणताही** मासिक आकडा दिला जात नाही आणि त्याला _अमर्यादित_ म्हणून सूचीबद्ध केले जाते, बेरीज कधीही केली जात नाही. दरमर्यादेला 24/7 ने गुणणे ही अशी फुगवणूक आहे जी आम्ही नाकारतो.
- **प्रादेशिक ओळख पडताळणीमागील कोटे स्वतंत्रपणे दाखवले जातात** (`+~6M behind regional identity verification`), कारण बहुतेक वाचक त्यांचा वापर करू शकत नाहीत.
- **साइनअप क्रेडिट्स फक्त पहिल्या महिन्यासाठी असतात** आणि ते स्थिर आकड्यात मिसळण्याऐवजी दुसरा स्वतंत्र आकडा म्हणून नोंदवले जातात.
- **हा आकडा CI-द्वारे लागू केला जातो.** `npm run check:docs-counts` कॅटलॉगमधून एकूण आकडे पुन्हा मोजते आणि ही फाइल, README किंवा बजेट कार्डमधील आकडे त्यांच्यापासून वेगळे झाल्यास बिल्ड अयशस्वी करते.
