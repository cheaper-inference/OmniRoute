`@omniroute/opencode-plugin-v2` तुमचा संपूर्ण OmniRoute कॅटलॉग — मॉडेल्स, कॉम्बोज आणि
ऑटो-कॉम्बोज — OpenCode v2 च्या मॉडेल निवडकात, प्रदर्शन नावे, किंमत आणि मोफत-स्तर
बजेटसह उपलब्ध करून देते.

हे `@omniroute/opencode-plugin` पेक्षा वेगळे पॅकेज आहे, कारण OpenCode v1 आणि v2
वेगवेगळ्या करारांद्वारे प्लगइन्स लोड करतात. तुमच्या OpenCode च्या प्रमुख आवृत्तीशी जुळणारे पॅकेज
निवडा; त्यांच्यात काहीही सामायिक नसल्यामुळे, एक अपग्रेड केल्याने दुसरे अपग्रेड करावे लागत नाही.

## आवश्यकता

- OpenCode v2.
- पोहोचण्यायोग्य OmniRoute गेटवे (डीफॉल्टनुसार `http://localhost:20128`).
- Node.js 22 किंवा 24.

## स्थापना

`opencode.json` मध्ये प्लगइन जोडा:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

त्यानंतर मॉडेल्स `omniroute/<provider>/<model>` या स्वरूपात दिसतात; `providerId` त्या उपसर्गाचे
आणि OpenCode ज्याअंतर्गत क्रेडेन्शियल साठवते त्या इंटिग्रेशनच्या आयडीचे निर्धारण करते.

## क्रेडेन्शियल्स

प्लगइन पुढील तीन ठिकाणी, याच क्रमाने, गेटवे की शोधते:

1. **तुम्ही OpenCode मध्ये जोडलेले क्रेडेन्शियल.** प्लगइन एक इंटिग्रेशन नोंदवते, त्यामुळे
   OpenCode चा स्वतःचा प्रमाणीकरण प्रवाह की साठवू शकतो. `opencode.json` मध्ये काहीही साठवले जात नाही — याला प्राधान्य द्या.
2. प्रत्येक प्रकल्पासाठी स्वतंत्र ओव्हरराइड म्हणून प्लगइन पर्यायांमधील `apiKey`. यामुळे की अशा फाइलमध्ये
   ठेवली जाते जी कदाचित तुम्ही कमिट करत असाल.
3. एन्व्हायर्नमेंटमधील `OMNIROUTE_API_KEY`.

या तिन्हींपैकी काहीही नसल्यास, कॅटलॉग रिकामा राहतो आणि मूकपणे रिकामा निवडक दाखवण्याऐवजी
प्लगइन स्टार्टअपवेळी एकदा तसे सांगते.

### व्यवस्थापन टोकन ही वेगळी की आहे

कॉम्बोज, प्रदाता आरोग्य आणि समृद्धीकरण (प्रदर्शन नावे, किंमत, मोफत-स्तर बजेट) गेटवेच्या
`/api/*` एंडपॉइंट्समधून येतात, जे बहुतांश डिप्लॉयमेंट्समध्ये इन्फरन्स कीऐवजी **व्यवस्थापन**
टोकनच्या मागे संरक्षित असतात:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

`managementReadToken` सेट न केल्यास, ते `apiKey` वापरते. गेटवेने हा पर्यायी वापर नाकारल्यास,
कॅटलॉग तरीही प्रकाशित होतो, परंतु प्रदर्शन नावांऐवजी अपरिष्कृत मॉडेल आयडी दिसतात, कॅनॉनिकल
उपनावांचे डीड्युप्लिकेशन होत नाही, किंमत उपलब्ध नसते आणि कॉम्बोजही नसतात. असे झाल्यास प्लगइन
प्रत्येक एंडपॉइंटसाठी एकदा इशारा देते आणि त्यात एंडपॉइंटचे नाव व कोणती माहिती गमावली ते नमूद करते —
त्यामुळे दर्जा कमी झालेला निवडक कधीही अनाकलनीय राहत नाही.

## कॅटलॉग ताजे कसे राहते

कॅटलॉग आळशीपणे आणला जातो आणि `modelCacheTtlMs` साठी कॅश केला जातो आणि जेव्हा गेटवे — अगम्य असतो तेव्हा डिस्क स्नॅपशॉट शेवटचा ज्ञात कॅटलॉग उपलब्ध ठेवतो आणि आउटेजमुळे तुम्हाला ताजेपणाशिवाय काहीही लागत नाही. मॉडेल आणि कॉम्बो आल्याबरोबर प्रकाशित केले जातात; ऑटो-कॉम्बोज, प्रदाता सूची आणि संवर्धन आच्छादन जेव्हा ते उतरतात तेव्हा त्यात फोल्ड होतात, त्यामुळे एक स्लो एंडपॉइंट संपूर्ण पिकरला ओलिस ठेवू शकत नाही.

नावे `Provider - Model[ (Editor)][ · budget][ (route)]` अनुसरण करतात : जेव्हा जेव्हा id मध्ये एक असतो (एक स्लॅश-लेस आयडी उपसर्गाशिवाय रेंडर होतो) तेव्हा प्रदाता दर्शविला जातो, एक अग्रगण्य `🆓` विनामूल्य नोंदी चिन्हांकित करतो आणि त्यांचे फ्री-टियर बजेट `· 1M tokens/month` प्रत्यय म्हणून राहते, स्पष्ट `Editor: Model` नावाचा संपादक अनुगामीकडे जातो आणि इतर कोष्ठक मधून नाव संपादित करतो. मुक्त चिन्हाशिवाय `combo - <slug>` म्हणून. नाव शेअर करणाऱ्या दोन नोंदींना रूट प्रत्यय — `(no-think)` — मिळतो जेणेकरून ते वेगळे राहतील. `providerTag` (डिफॉल्ट `true`) ट्रेलिंग एडिटर कंस टॉगल करते.

कोणतीही मॅन्युअल रिफ्रेश कमांड नाही: OpenCode v2 कमांड प्रॉम्प्ट टेम्पलेट्स आहेत, कॉलबॅक नाहीत, त्यामुळे प्लगइन उघड करू शकत नाही. रिफ्रेश TTL चे अनुसरण करतात; होस्टला कॅटलॉग किंवा आच्छादन प्रत्यक्षात बदलल्यावरच रीलोड करण्यास सांगितले जाते, प्रति रिफ्रेश कधीही नाही.

## Gemini वर टूल कॉलिंग

ज्या विनंतीच्या टूल घोषणांमध्ये `$schema` किंवा `additionalProperties` असतात, अशी संपूर्ण विनंती Gemini नाकारते आणि `400 INVALID_ARGUMENT` असे उत्तर देते. प्लगइन या प्रदात्याच्या Gemini मॉडेलकडे पाठवल्या जाणाऱ्या टूल स्कीमांमधून हे कीवर्ड्स काढून टाकते आणि इतर प्रत्येक विनंती जशीच्या तशी ठेवते. `$ref` असलेले टूल बदल न करता पुढे पाठवले जाते, कारण रेफरन्स काढल्यास स्कीमा "काहीही स्वीकारा" इतकी व्यापक होईल.
हे बंद करण्यासाठी `"geminiSanitization": false` सेट करा.

## समस्यानिवारण

| लक्षण                                   | कारण                                                                                                                |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| पिकर कोणतेही OmniRoute मॉडेल दाखवत नाही | कोणतीही की सोडवली नाही (स्टार्टअप चेतावणी तपासा), किंवा गेटवे अगम्य आहे                                             |
| रॉ मॉडेल आयडी, कॉम्बो नाही, किंमत नाही  | व्यवस्थापन एंडपॉईंटने टोकन — सेट `managementReadToken` नाकारले                                                      |
| लहान किंवा रिक्त `freeOnly` कॅटलॉग      | कोणतेही व्यवस्थापन टोकन किंवा नाकारलेले टोकन — होस्ट लॉगमध्ये रिफ्रेश सारांश ओळ (`unmatched-free` संख्या) वाचत नाही |
| `opencode-<id>/...` वर पिन केलेले सत्र  | v1 प्लगइन प्रकाशित `opencode-<id>`; v2 `<id>` बेअर प्रकाशित करते, म्हणून `<id>/...` अंतर्गत मॉडेल पुन्हा निवडा      |

पर्यावरण व्हेरिएबल्सने ओपनकोड सर्व्हर प्रक्रियेपर्यंत पोहोचणे आवश्यक आहे: जेव्हा होस्ट सेवा म्हणून चालतो, तेव्हा `opencode models` चालवणारा शेल आणि सर्व्हरचे वातावरण वेगळे असते, म्हणून सर्व्हर जिथे वाचतो तिथे की निर्यात करा.
