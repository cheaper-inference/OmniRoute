तटस्थ `config/cli-tools-manifest.json` करार कॅनोनिकल IDs, उपनाम, बायनरी उमेदवार, सेटअप रेसिपी, मॉडेल युक्तिवाद आणि क्षमता घोषित करतो. `bin/cli/cli-manifest.mjs` मधील प्लेन नोड अडॅप्टर आणि `src/shared/constants/cliIntegrationManifest.ts` मधील TypeScript अडॅप्टर समान फाइल वाचतात. रनटाइम, कॅटलॉग, कॉन्फिगर, पूर्णता, जनरेटर आणि बॅकएंड नोंदणी `tests/unit/cli/cli-manifest-drift.test.ts` द्वारे एकत्रितपणे तपासली जाते. कॅटलॉग असण्याचा अर्थ असा नाही की एखादे साधन लॉन्च किंवा कॉन्फिगर केले जाऊ शकते. विशेषत:, 5dive फक्त कॉन्फिगर राहते.

## बाल वातावरण आणि जीवनचक्र

`omniroute run`, `omniroute launch` आणि `omniroute launch-codex` OS/terminal सुसंगतता अनुमत यादी वारसा मिळते आणि निवडलेल्या लक्ष्याची क्रेडेन्शियल्स इंजेक्ट करतात. असंबंधित प्रदाता आणि डेटाबेस रहस्ये डीफॉल्टनुसार वारशाने मिळत नाहीत. `--inherit-env` स्पष्टपणे संपूर्ण पालक-पर्यावरण वारसा पुनर्संचयित करते; निवडलेल्या तृतीय-पक्ष प्रक्रियेने ती मूल्ये प्राप्त केली पाहिजे तेव्हाच ते वापरा. हे पर्यावरण फिल्टरिंग आहे, OS सँडबॉक्स नाही: प्रक्रिया अजूनही कॉलरच्या फाइलसिस्टम परवानग्यांसह चालते.

व्यत्यय आणि समाप्ती सिग्नल मुलाला अग्रेषित केले जातात. तात्पुरती कॉन्फिगरेशन काढून टाकण्यापूर्वी लाँचर मुलाच्या जवळच्या कार्यक्रमाची वाट पाहतो. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` सक्तीच्या समाप्तीपूर्वी वाढीव कालावधी नियंत्रित करते (डिफॉल्ट 5000 मिलीसेकंद).

## Gemini पर्सिस्टंट सेटअप

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

पहिल्या दोन कमांड्स निवडलेल्या स्थानिक किंवा रिमोट सर्व्हरसाठी हे मशीन कॉन्फिगर करतात. सेटअप असंबंधित JSON सेटिंग्ज जतन करतो, Gemini API-की प्रमाणीकरण निवडतो आणि खाजगी `.gemini/.env` फाइलवर एंडपॉइंट आणि क्रेडेन्शियल लिहितो. ते अधिलिखित करण्याऐवजी अवैध JSON नाकारते. एम्बेडेड क्रेडेंशियल, क्वेरी पॅरामीटर्स किंवा तुकड्यांशिवाय एंडपॉइंट URLs HTTP(S) असणे आवश्यक आहे. ड्राय-रन पथ मुद्रित करते, क्रेडेंशियल मूल्ये नाही.

`GEMINI_CLI_HOME` किंवा `--gemini-home` पर्सिस्टंट होम रूट निवडते. वास्तविक `run gemini` स्वतःचे तात्पुरते घर बनवते आणि नंतर काढून टाकते. कोणताही मोड Gemini च्या वर्कस्पेस-ट्रस्ट चेकला बायपास करत नाही.

## Codex प्रोफाइल

`configure codex` मॉडेल आणि त्याच्या OmniRoute प्रदाता एंडपॉइंटसह खाजगी `<name>.config.toml` लिहितो. क्रेडेन्शियल `OMNIROUTE_API_KEY` द्वारे संदर्भित केले जातात, कधीही एम्बेड केलेले नाहीत. लॉन्च कमांड निवडलेले मॉडेल `model_providers` च्या आत नसून, उच्च-स्तरीय `model` वर सेट करते.

विभक्त प्रोफाइल फाइल्स वर्तमान दस्तऐवजीकरण Codex करार आहेत; `codex --profile <name>` सह निवडल्यावर ते वापरकर्ता कॉन्फिगरेशन आच्छादित करतात. [अधिकृत प्रोफाइल संदर्भ](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) आणि [OmniRoute Codex मार्गदर्शक](./CODEX-CLI-CONFIGURATION.md) पहा.

## हर्मेटिक कमांडची अंमलबजावणी

स्पष्ट `DATA_DIR` सह, `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` सेट करणे स्टार्टअपला डीफॉल्ट वापरकर्ता डेटा निर्देशिकेच्या क्रेडेंशियल वातावरणात येण्यापासून प्रतिबंधित करते. हे वेगळ्या चाचण्यांसाठी उपयुक्त आहे. हे इतर स्पष्टपणे निवडलेल्या पर्यावरण फाइल्स अक्षम करत नाही.

## कार्य-निर्देशिका `.env`

CLI या क्रमाने `.env` फाइल्स वाचते आणि की सेट करणारी पहिली फाइल जिंकते: स्पष्ट `DATA_DIR`, डीफॉल्ट डेटा निर्देशिका, वर्तमान कार्यरत निर्देशिका, नंतर पॅकेज निर्देशिका. शेल व्हेरिएबल्स नेहमी जिंकतात.

कार्यरत डिरेक्टरी इतर कोणाचीही असू शकते (क्लोन केलेले भांडार, एक अनपॅक केलेले संग्रहण), आणि `omniroute serve` CLI वातावरण सर्व्हरवर आणि सर्व्हर चालवलेल्या प्रत्येक टूलवर पास करते. म्हणून तेथे एक `.env` फक्त या कळा सेट करू शकतो, `bin/cli/utils/untrustedCwdEnv.mjs` मध्ये सूचीबद्ध:

| की                              | स्वीकारलेली मूल्ये                                                    |
| ------------------------------- | --------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` किंवा `yes` कोणत्याही परिस्थितीत, सर्व्हर जी मूल्ये मानतो |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 64 अक्षरे, अंक, `_`, `.`, `@` किंवा `-` पर्यंत                        |
| `LANGUAGE`                      | समान, अधिक `:`                                                        |
| `TZ`                            | 64 अक्षरे, अंक, `_`, `+`, `-` किंवा `/` पर्यंत, `/` ने सुरू होत नाही  |
| `NO_COLOR`, `FORCE_COLOR`       | 16 अक्षरे आणि अंकांपर्यंत                                             |

`REQUIRE_API_KEY` स्वीकारलेले प्रत्येक मूल्य चेक चालू करते, त्यामुळे फाइल स्वतः चेक बंद करू शकत नाही. हे परिणाम ठरवत नाही, तरीही: सर्व्हर पर्यावरणापूर्वी डेटाबेसमध्ये संग्रहित `REQUIRE_API_KEY` ओव्हरराइड वाचतो, तर API की शिवाय सर्व इंटरफेसवर ऐकण्याची स्टार्टअप चेतावणी केवळ वातावरण वाचते. `false` च्या संचयित ओव्हरराइडसह, कार्यरत-डिरेक्टरी `REQUIRE_API_KEY=true` API उघडते आणि ती चेतावणी लपवते. `TZ` नियम POSIX पेक्षा संकुचित आहे: तो `.`, `:`, `,` आणि `<>` नाकारतो, म्हणून `:Area/City` फॉर्म आणि `EST5EDT,M3.2.0,M11.1.0` सारखे नियम शेलमध्ये किंवा `<DATA_DIR>/.env` मध्ये सेट करावे लागतील.

वरच्या केसमध्ये नावे तंतोतंत जुळली पाहिजेत. इतर कोणतीही ओळ, त्याची तपासणी अयशस्वी होणारे मूल्य आणि साधे ASCII अक्षरे, अंक आणि `_` नसलेले नाव (उदाहरणार्थ NUL बाइट किंवा एकसारखे अक्षर असलेले) वगळले आहे. CLI एक चेतावणी मुद्रित करते जी ती सेट करू शकत नसलेल्या की नाव देते आणि एक चेतावणी मुद्रित करते ज्याने त्याकडे दुर्लक्ष केले की परवानगी दिली आहे, प्रत्येकामध्ये काय बदलायचे आहे (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). मूल्ये छापत नाहीत. या संदेशांमधील फाईल पाथ आणि `.env` path `omniroute doctor` अहवाल, जेव्हा त्यात नियंत्रण किंवा बिडी वर्ण असतात तेव्हा ते सुटलेले असतात. जेव्हा कार्यरत निर्देशिका डेटा निर्देशिका किंवा पॅकेज निर्देशिका असते तेव्हा प्रतिबंध लागू होत नाही.

`PORT`, `API_PORT` आणि `DASHBOARD_PORT` यादीत नाहीत. उच्च-प्राधान्य स्त्रोताकडून बेस URL शिवाय, CLI `localhost:<PORT>` शी बोलतो, आणि तेथे जे काही ऐकते त्याला CLI ची API की, संदर्भ टोकन आणि CLI मशीन टोकन (`x-omniroute-cli-token`, [CLI_TOKEN.md](../security/CLI_TOKEN.md) पहा), जे स्थानिक सर्व्हर व्यवस्थापन loop कॉलसाठी स्वीकारतो. कार्यरत निर्देशिकेतील एक पोर्ट त्या फाइलला श्रोता निवडू देईल, म्हणून शेलमध्ये पोर्ट्स सेट करा, `<DATA_DIR>/.env` मध्ये किंवा `--port` पर्यायासह (`serve`, `launch`, `run`).

पार्सरमध्ये `export` सिंटॅक्स नाही. `export LD_PRELOAD=...` सारखी ओळ व्हेरिएबल `export LD_PRELOAD` नाव देते; कार्यरत निर्देशिकेतून ते वगळले जाते आणि इतर `.env` फाइल्समध्ये ते शब्दशः नाव सेट करते, जे काहीही वाचत नाही.

CLI संदर्भाचे संचयित टोकन (ऍक्सेस टोकन किंवा लेगसी API की) केवळ त्या संदर्भाच्या स्वतःच्या मूळशी जोडते: योजना, होस्ट आणि पोर्ट, `URL.origin` च्या तुलनेत. हे CLI च्या HTTP क्लायंट (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) द्वारे केलेल्या विनंत्यांना लागू होते आणि `launch`, `launch codex`, `configure` आणि `setup-*` आदेशांना लागू होते जे दुसऱ्या टूलच्या कॉन्फिगमध्ये बेस URL आणि की लिहितात. `--remote` सह दुसऱ्या सर्व्हरकडे निर्देशित केलेले, ते सेट केलेले असल्यास स्पष्ट `--api-key` किंवा `OMNIROUTE_API_KEY` वापरतात, आणि संदर्भ टोकन नाही. तुलना तंतोतंत आहे, म्हणून `localhost` आणि `127.0.0.1`, किंवा ट्रेलिंग डॉटसह आणि त्याशिवाय होस्ट, भिन्न सर्व्हर म्हणून मोजा आणि कोणताही संदर्भ टोकन मिळत नाही. वापरकर्ता माहितीसह URL, बॅकस्लॅश किंवा व्हाईटस्पेस कधीही जुळत नाही, कारण इतर URL पार्सर (उदाहरणार्थ, पायथनचे `urllib` आणि `httpx`) त्यापासून वेगळे होस्ट वाचू शकतात. विनंत्यांसाठी CLI स्वतः पाठवते, त्या चेकमध्ये फक्त योजना आणि अधिकार समाविष्ट असतात, त्यामुळे पथ किंवा क्वेरीमध्ये स्पेस असलेला आयडी टोकन ठेवतो.
