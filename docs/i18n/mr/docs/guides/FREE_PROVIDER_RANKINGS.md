> **थोडक्यात**: OmniRoute त्याच्या **विनामूल्य** प्रदात्यांना मॉडेलच्या गुणवत्तेनुसार **Arena AI
> (LMArena-शैलीतील) ELO गुणांचा** वापर करून क्रमवारी देतो. तुमच्या कामासाठी कोणते विनामूल्य प्रदाते
> सर्वात सक्षम मॉडेल्स देतात हे पाहण्यासाठी डॅशबोर्डमधील **विनामूल्य प्रदाता क्रमवारी** पृष्ठ उघडा —
> एकूण क्रमवारी किंवा श्रेणीनुसार फिल्टर केलेली क्रमवारी (कोडिंग, पुनरावलोकन, दस्तऐवजीकरण, डीबगिंग).

## हे काय आहे

OmniRoute 376 प्रदात्यांची नोंदणी करते, ज्यामध्ये **विनामूल्य/प्रमाणीकरण-विरहित** म्हणून चिन्हांकित केलेल्या 155 कॅटलॉग नोंदींचा समावेश आहे
(प्रमाणीकरण-विरहित,
विनामूल्य-स्तर OAuth किंवा विनामूल्य-स्तर API की —
[विनामूल्य स्तर मार्गदर्शिका](../getting-started/FREE-TIERS-GUIDE.md) आणि संपूर्ण
[विनामूल्य स्तर निर्देशिका](../reference/FREE_TIERS.md) पहा). पण एक अडचण आहे: विनामूल्य प्रदात्यांच्या
मॉडेल गुणवत्तेत मोठ्या प्रमाणात फरक असतो. अत्याधुनिक मॉडेल देणारा प्रमाणीकरण-विरहित प्रदाता,
लहान जुने मॉडेल देणाऱ्या प्रदात्यापेक्षा खूपच अधिक उपयुक्त असतो.

**विनामूल्य प्रदाता क्रमवारी** ही प्रत्येक विनामूल्य प्रदात्याचा कॅटलॉग
**Arena AI लीडरबोर्ड**वरील **समुदाय-स्रोतित गुणवत्ता गुणांशी** जोडून "**कोणता विनामूल्य प्रदाता मला सर्वोत्तम मॉडेल देतो?**" या प्रश्नाचे उत्तर देते
(मानवी पसंतीवर आधारित ELO, म्हणजेच LMArena
चॅटबॉट अरीनामागील तीच संकल्पना). त्यानंतर प्रदात्यांना त्यांच्या **सर्वोत्तम विनामूल्य मॉडेलच्या** क्षमतेनुसार क्रम दिला जातो.

ही क्रमवारी तीन वास्तविक स्रोतांमधून मोजली जाते:

1. विनामूल्य प्रदात्यांच्या याद्या — `NOAUTH_PROVIDERS`, तसेच `hasFree` म्हणून चिन्हांकित केलेल्या `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` नोंदी
   (`src/shared/constants/providers.ts`).
2. प्रदाता रजिस्ट्रीमधील प्रत्येक प्रदात्याचा मॉडेल कॅटलॉग
   (`open-sse/config/providerRegistry.ts`).
3. Arena ELO समक्रमण इंजिनद्वारे `model_intelligence` DB तक्त्यात साठवलेले ELO-व्युत्पन्न कार्य-अनुरूपता गुण
   (`src/lib/arenaEloSync.ts`).

जोडणीचे लॉजिक `src/lib/freeProviderRankings.ts` मध्ये आहे.

## प्रवेश कसा करावा

### डॅशबोर्ड पृष्ठ

डॅशबोर्ड उघडा आणि **खर्च → विनामूल्य प्रदाता क्रमवारी** येथे जा किंवा थेट येथे नेव्हिगेट करा:

```
/dashboard/free-provider-rankings
```

हे पृष्ठ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) पुढील गोष्टी दाखवते:

- सर्वोच्च क्रमवारीतील विनामूल्य प्रदात्यांचा **शीर्ष-3 पोडियम** (🥇 🥈 🥉).
- पुढील स्तंभांसह संपूर्ण **क्रमवारी तक्ता**: **क्रमांक**, **प्रदाता**, **सर्वोत्तम मॉडेल**,
  **गुण**, **सरासरी गुण**, **मॉडेल्स**, **प्रकार**.
- **श्रेणी फिल्टर बटणे**: _सर्व श्रेण्या_, _डीफॉल्ट_, _कोडिंग_, _पुनरावलोकन_,
  _दस्तऐवजीकरण_, _डीबगिंग_.

प्रत्येक प्रदात्याचा **प्रकार** बॅज तो कशा प्रकारे विनामूल्य आहे हे सांगतो:

| बॅज      | अर्थ                                                      |
| -------- | --------------------------------------------------------- |
| `NOAUTH` | नेहमी विनामूल्य, कोणत्याही क्रेडेन्शियल्सची आवश्यकता नाही |
| `OAUTH`  | विनामूल्य स्तर (`hasFree`) असलेला OAuth प्रदाता           |
| `APIKEY` | विनामूल्य स्तर (`hasFree`) असलेला API-की प्रदाता          |

गुण मूळ संख्यांऐवजी मानवाला सहज समजणाऱ्या लेबलांच्या स्वरूपात (उदा. _सर्वोच्च_, _उत्कृष्ट_, _अतिशय चांगले_,
_चांगले_, _सरासरी_) दाखवले जातात, कारण अंतर्निहित मूल्य ही सापेक्ष क्रमवारी गुणवत्ता आहे,
टक्केवारी नाही.

### API एंडपॉइंट

या पृष्ठाला सार्वजनिक वाचन एंडपॉइंटचा आधार आहे
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

क्वेरी पॅरामीटर्स (Zod वापरून वैध केलेले):

| पॅरामीटर   | प्रकार | डीफॉल्ट       | नोंदी                                                                                              |
| ---------- | ------ | ------------- | -------------------------------------------------------------------------------------------------- |
| `category` | string | (काहीही नाही) | `default`, `coding`, `review`, `documentation`, `debugging` यांपैकी एक. एकत्रित क्रमवारीसाठी वगळा. |
| `limit`    | number | `50`          | `1–100` या मर्यादेत सीमित केले जाते.                                                               |

प्रतिसादाची रचना:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` हे मूळ Arena ELO मूल्य आहे; `score` हे सामान्यीकृत कार्य-अनुरूपता मूल्य आहे
(खाली पाहा). गुण दिलेली मॉडेल्स नसलेले प्रदाते प्रतिसादातून वगळले जातात.

## स्कोअर कसे कार्य करतात

### स्रोत: Arena AI लीडरबोर्ड

Arena ELO सिंक इंजिन (`src/lib/arenaEloSync.ts`) Arena AI लीडरबोर्ड API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) वरून दोन लीडरबोर्ड — `text`
आणि `code` — आणते. जेव्हा ते API वापरण्यायोग्य बोर्ड देत नाही, तेव्हा इंजिन Hugging Face
datasets-server वरील अधिकृत `lmarena-ai/leaderboard-dataset` वर पर्यायी स्वरूपात जाते
(`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` `activeSource`, `lastError` आणि
`lastFailedAt` ही माहिती देते. प्रत्येक लीडरबोर्ड एंट्रीमध्ये
मॉडेलचे नाव, विक्रेता, ELO `score`, कॉन्फिडन्स इंटर्व्हल आणि मतांची संख्या असते.

लीडरबोर्ड श्रेण्या OmniRoute कार्य-श्रेणींशी जोडल्या जातात:

| Arena लीडरबोर्ड | OmniRoute कार्य-श्रेण्या                          |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### नॉर्मलायझेशन (कार्य-योग्यता स्कोअर)

कच्चे ELO स्कोअर प्रत्येक लीडरबोर्डनुसार **`[0.4, 0.98]` मधील कार्य-योग्यता मूल्यात** नॉर्मलाइज केले जातात:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

स्कोअर कधीही `0` किंवा `1` पर्यंत पोहोचत नाही, जेणेकरून वापरकर्त्याच्या ओव्हरराइडसाठी वाव राहतो. हाच तो
`score` फील्ड आहे जो तुम्हाला API प्रतिसादात दिसतो आणि डॅशबोर्डवर दाखवले जाणारे लेबल आहे.

### विश्वासार्हता (Confidence)

प्रत्येक एंट्रीला Arena मतांच्या संख्येनुसार विश्वासार्हता पातळी मिळते:

| विश्वासार्हता | मते     |
| ------------- | ------- |
| `high`        | ≥ 5,000 |
| `medium`      | ≥ 1,000 |
| `low`         | < 1,000 |

### स्टोरेज आणि अद्ययावतता

नॉर्मलाइज केलेल्या एंट्रीज `source = "arena_elo"` सह `model_intelligence` DB टेबलमध्ये
लिहिल्या जातात (`src/lib/db/modelIntelligence.ts`). एंट्रीज **7 दिवसांनंतर
कालबाह्य होतात**, म्हणून सिंक करणे थांबवलेला प्रोव्हायडर जुना डेटा देण्याऐवजी
शेवटी यादीतून वगळला जातो.

सिंक **डीफॉल्टनुसार चालू** असते:

- ती सर्व्हर स्टार्टअपवर एकदा आणि नंतर नियतकालिक टाइमरनुसार चालते
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` मधून जोडलेली).
- ती **नॉन-ब्लॉकिंग आणि कधीही घातक नसते** — जर अपस्ट्रीम फेच अयशस्वी झाले, तरी OmniRoute
  चालू राहते आणि रँकिंग्ज फक्त शेवटचा योग्य डेटा (किंवा रिकामी स्थिती) दाखवतात.

दोन एन्व्हायरनमेंट व्हेरिएबल्स ते नियंत्रित करतात (दस्तऐवजीकरण
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) मध्ये केलेले):

| व्हेरिएबल                 | डीफॉल्ट       | उद्देश                                              |
| ------------------------- | ------------- | --------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | आउटबाउंड सिंकमधून बाहेर पडण्यासाठी `false` सेट करा. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | सिंक मध्यांतर, सेकंदांमध्ये.                        |

### मॅन्युअल सिंक / स्थिती / पुसून टाकणे

ऑपरेटरसाठी, एक प्रमाणित मॅनेजमेंट एंडपॉइंट मॅन्युअल नियंत्रण देते
(`src/app/api/intelligence/sync/route.ts` — मॅनेजमेंट ऑथ आवश्यक):

```
GET    /api/intelligence/sync          # सध्याची सिंक स्थिती (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # मॅन्युअल सिंक सुरू करा; बॉडी: { "dryRun": true } लिहिल्याशिवाय पूर्वावलोकनासाठी
DELETE /api/intelligence/sync          # सर्व सिंक केलेल्या arena_elo इंटेलिजन्स एंट्रीज पुसा
```

रँकिंग्ज पेज रिकामे असल्यास, मॅन्युअल `POST /api/intelligence/sync` (किंवा फक्त
सर्व्हर रीस्टार्ट करणे) ते पुन्हा भरते.

### मॉडेल्सना लीडरबोर्डशी जुळवणे

रजिस्ट्री मॉडेल ID आणि Arena मॉडेल नावे नेहमी तंतोतंत जुळत नाहीत. रँकिंग
लवचिक जुळणी वापरते (`src/lib/freeProviderRankings.ts` मधील `findMatchingIntelligence`):

1. नॉर्मलाइज केलेल्या मॉडेल ID वर अचूक जुळणी.
2. शेवटचा व्हर्जन प्रत्यय काढून टाकल्यानंतर जुळणी (उदा. `kimi-k2.6` → `kimi-k2`).
3. उपसर्ग जुळणी (लीडरबोर्ड मॉडेल नाव हे रजिस्ट्री ID चा उपसर्ग असते).

सिंक बाजूने, ओळखीचे विक्रेता उपसर्ग (`anthropic/`, `openai/`, `google/`, …)
काढले जातात आणि एक छोटा अलियास नकाशा कॅनॉनिकल नावे OmniRoute अंतर्गत वापरत असलेल्या
रूपांमध्ये विस्तारित करतो, जेणेकरून मॉडेल्स कोणत्याही नावाने शोधता येतात.

### प्रोव्हायडरचे रँकिंग कसे होते

प्रत्येक मोफत प्रोव्हायडरसाठी, इंजिन त्याच्या कॅटलॉगमधील प्रत्येक मॉडेलला स्कोअर करते, नंतर:

- **Top Model** = प्रोव्हायडरचे सर्वाधिक स्कोअर असलेले मॉडेल.
- **Avg Score** = त्या प्रोव्हायडरच्या सर्व स्कोअर केलेल्या मॉडेल्सचा सरासरी स्कोअर.
- **Models** = प्रोव्हायडरच्या किती मॉडेल्सना Arena स्कोअर होता.

प्रोव्हायडर्स प्रथम **टॉप-मॉडेल स्कोअर**नुसार, नंतर सरासरी स्कोअरनुसार क्रमाने लावले जातात. यामुळे
किमान एक मजबूत मोफत मॉडेल देणाऱ्या प्रोव्हायडरला फायदा मिळतो.

## मोफत प्रदाते निवडण्यासाठी याचा वापर

1. **योग्य श्रेणी निवडा.** एजंटिक/कोड वर्कलोडसाठी **Coding** फिल्टर वापरा किंवा
   सामान्य चॅटसाठी **All Categories** / **Default** निवडलेले राहू द्या. प्रत्येक लीडरबोर्डनुसार
   त्याचे सर्वोत्तम मॉडेल वेगळे असल्यामुळे एकाच प्रदात्याचे स्थान विविध श्रेणींमध्ये
   वेगवेगळे असू शकते.
2. **एकदाच करावयाच्या सेटअपसाठी पोडियमवरील प्रदात्यांना प्राधान्य द्या.** तुम्हाला फक्त एक किंवा दोन मोफत
   प्रदाते जोडायचे असल्यास, तुमच्या श्रेणीतील सर्वोच्च स्थानावरील प्रदात्यांपासून सुरुवात करा.
3. **Type बॅज तपासा.** `NOAUTH` प्रदाते जोडण्यासाठी सर्वात जलद आहेत (कोणतीही
   क्रेडेन्शियल्स आवश्यक नाहीत). `OAUTH` / `APIKEY` मोफत टियरसाठी झटपट साइन-अप करावे लागते, परंतु त्यांमध्ये अनेकदा
   अधिक सक्षम मॉडेल्स उपलब्ध असतात. जोडणीच्या चरणांसाठी [मोफत टियर मार्गदर्शक](../getting-started/FREE-TIERS-GUIDE.md)
   पहा.
4. **अनेक प्रदाते जोडा आणि Auto-Combo ला निर्णय घेऊ द्या.** या पृष्ठाला चालना देणारा हाच Arena ELO डेटा
   Auto-Combo स्कोअरिंग इंजिनच्या **कार्य-योग्यता घटकासाठीही** वापरला जातो
   (`open-sse/services/autoCombo/taskFitness.ts`, निराकरण क्रम
   `user_override → arena_elo → models_dev_tier → static table`). त्यामुळे सर्वोच्च मोफत प्रदाते
   जोडल्यानंतर, `model: "auto"` (उदा. `auto/coding`) सह रूटिंग केल्यास
   प्रत्येक विनंतीसाठी उच्च-गुणवत्तेच्या मोफत मॉडेल्सना आपोआप प्राधान्य दिले जाईल. संपूर्ण 16-घटक स्कोअरिंगसाठी
   [Auto-Combo](../routing/AUTO-COMBO.md) पहा.
