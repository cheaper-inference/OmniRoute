## 🎯 वापराची प्रकरणे

### प्रकरण 1: "माझ्याकडे Claude Pro सदस्यत्व आहे"

**समस्या:** न वापरलेला कोटा कालबाह्य होतो आणि मोठ्या प्रमाणावर कोडिंग करताना दरमर्यादा लागू होतात

```
कॉम्बो: "maximize-claude"
  1. cc/claude-opus-4-7        (सदस्यत्वाचा पूर्ण वापर करा)
  2. glm/glm-4.7               (कोटा संपल्यावर स्वस्त बॅकअप)
  3. if/qwen3.8-max-preview       (आपत्कालीन मोफत पर्याय)

मासिक खर्च: $20 (सदस्यत्व) + ~$5 (बॅकअप) = एकूण $25
याउलट $20 + मर्यादा गाठणे = निराशा
```

### प्रकरण 2: "मला शून्य खर्च हवा आहे"

**समस्या:** सदस्यत्वे परवडत नाहीत, विश्वासार्ह AI कोडिंग आवश्यक आहे

```
कॉम्बो: "zero-cost"
  1. if/kimi-k2.7-code          (सूचीबद्ध मोफत प्रवेश; दरमर्यादा लागू होऊ शकतात)
  2. kr/qwen3-coder-next        (Kiro चा मोफत पर्याय)

मासिक खर्च: $0
गुणवत्ता: तुमच्या कार्यभारासाठी मॉडेल, मर्यादा, गोपनीयता आणि SLA पडताळा
```

### प्रकरण 3: "मला कोणत्याही व्यत्ययाशिवाय 24/7 कोडिंग हवे आहे"

**समस्या:** अंतिम मुदती आहेत, सेवा खंडित होणे परवडणारे नाही

```
कॉम्बो: "always-on"
  1. cc/claude-opus-4-7        (सर्वोत्तम गुणवत्ता)
  2. cx/gpt-5.5                (दुसरे सदस्यत्व)
  3. glm/glm-4.7               (स्वस्त, दररोज रीसेट होते)
  4. minimax/MiniMax-M2.1      (सर्वांत स्वस्त, 5 तासांनी रीसेट)
  5. if/deepseek-v4-flash       (सूचीबद्ध मोफत प्रवेश; दरमर्यादा लागू होऊ शकतात)

परिणाम: पर्यायांचे 5 स्तर लवचिकता वाढवतात; अपस्ट्रीम उपलब्धतेची हमी नाही
मासिक खर्च: $20-200 (सदस्यत्वे) + $10-20 (बॅकअप)
```

## 📖 प्रदाता सेटअप

CSV किंवा JSON फाइलमधून मोठ्या प्रमाणात API-की कनेक्शन्स जोडण्यासाठी, **डॅशबोर्ड → प्रदाते → फाइलमधून आयात करा** वापरा. स्तंभांचे स्थान निश्चित आहे (`provider,name,apiKey,baseUrl,priority`); `provider` हा आधीपासून व्यवस्थापित प्रदाता किंवा सुसंगत नोड म्हणून अस्तित्वात असणे आवश्यक आहे. [CSV किंवा JSON फाइलमधून प्रदाते आयात करा](../providers/CSV-IMPORT.md) पहा.

### 🔐 सदस्यता प्रदाते

#### Claude Code (Pro/Max)

```bash
डॅशबोर्ड → प्रदाते → Claude Code कनेक्ट करा
→ OAuth लॉगिन → स्वयंचलित टोकन रिफ्रेश
→ 5-तासांची + साप्ताहिक कोटा ट्रॅकिंग

मॉडेल्स:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**उपयुक्त सूचना:** जटिल कार्यांसाठी Opus आणि वेगासाठी Sonnet वापरा. OmniRoute प्रत्येक मॉडेलनुसार कोटा ट्रॅक करते!

OmniRoute होस्टवर ब्राउझर नाही? Claude Code मध्ये लॉगिन केलेल्या कोणत्याही ठिकाणी `claude setup-token` चालवा आणि एक वर्षासाठी वैध असलेले टोकन **Setup Token** टॅबमध्ये पेस्ट करा. [सेटअप टोकनसह Claude Code](../providers/CLAUDE_CODE_SETUP_TOKEN.md) पहा.

Claude आणि Claude Code-सुसंगत रूट्स Opus आणि Sonnet मॉडेल्ससाठी `max` विचार-प्रयत्न पातळी कायम ठेवतात. Haiku मॉडेल्स `max` प्रयत्न स्तर स्वीकारत नाहीत, त्यामुळे विनंती अपस्ट्रीमकडे पाठवण्यापूर्वी OmniRoute ती उच्च विचार-बजेटवर डाउनग्रेड करते.

#### OpenAI Codex (Plus/Pro)

```bash
डॅशबोर्ड → प्रदाते → Codex कनेक्ट करा
→ OAuth लॉगिन (पोर्ट 1455)
→ 5-तासांची + साप्ताहिक रीसेट

मॉडेल्स:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

### ग्लोबल npm इन्स्टॉल (शिफारस केलेले)

```bash
npm install -g omniroute

# कॉन्फिगरेशन डिरेक्टरी तयार करा
mkdir -p ~/.omniroute

# .env फाइल तयार करा (.env.example पहा)
cp .env.example ~/.omniroute/.env

# सर्व्हर सुरू करा
omniroute
# किंवा सानुकूल पोर्टसह:
omniroute --port 3000
```

CLI आपोआप `~/.omniroute/.env` किंवा `./.env` मधून `.env` लोड करते.

### ट्रे मोड

सिस्टम ट्रेमध्ये OmniRoute सुरू करा:

```bash
omniroute serve --tray
```

सर्व्हर आणि ट्रे तयार झाल्यानंतर कमांड पूर्ण होते.

टर्मिनलशिवाय सर्व्हर चालू राहतो.

ट्रे मोड macOS, Windows आणि ग्राफिकल Linux सत्रांना समर्थन देतो. ट्रे मोड डॅशबोर्ड आपोआप उघडत नाही.

पुढील क्रियांसाठी ट्रे मेनू वापरा:

- डॅशबोर्ड उघडा.
- `/dashboard/logs` उघडा.
- स्वयंचलित प्रारंभ बदला.
- OmniRoute थांबवा.

पुढील पर्यायांसोबत `--tray` वापरू नका:

- `--daemon`
- `--log`
- `--no-recovery`

या मोड्सना वेगवेगळ्या प्रक्रिया मालकीची आवश्यकता असते.

मशीनमध्ये पुढील वेळी लॉग इन करताना स्टार्टअप सक्षम करा:

```bash
omniroute autostart enable
```

macOS, Windows आणि ग्राफिकल Linux सत्रांवर स्वयंचलित प्रारंभ ट्रे मोड वापरतो. हेडलेस Linux विद्यमान systemd वापरकर्ता सेवा वापरतो.

लॉगिनवेळी स्टार्टअप अक्षम करा:

```bash
omniroute autostart disable
```

### अनइन्स्टॉल करणे

जेव्हा तुम्हाला OmniRoute ची गरज नसेल, तेव्हा पूर्णपणे काढून टाकण्यासाठी आम्ही दोन जलद स्क्रिप्ट्स पुरवतो:

| कमांड                    | कृती                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| `npm run uninstall`      | सिस्टम अॅप काढून टाकते, परंतु `~/.omniroute` मधील **तुमचा DB आणि कॉन्फिगरेशन्स जतन करते**. |
| `npm run uninstall:full` | अॅप काढून टाकते आणि **सर्व कॉन्फिगरेशन्स, की आणि डेटाबेसेस कायमचे पुसते**.                 |

> टीप: या कमांड्स चालवण्यासाठी, OmniRoute प्रकल्प फोल्डरमध्ये जा (जर तुम्ही तो क्लोन केला असेल) आणि त्या चालवा. पर्यायाने, ग्लोबलरीत्या इन्स्टॉल केले असल्यास, तुम्ही फक्त `npm uninstall -g omniroute` चालवू शकता.

```bash

version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"

system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false

do_build() {
	# node-gyp साठी लक्ष्य CPU आर्किटेक्चर निश्चित करा
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) सर्व अवलंबित्वे स्थापित करा – स्क्रिप्ट्स वगळा
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Next.js स्टँडअलोन बंडल बिल्ड करा
	npm run build

	# 3) स्टॅटिक असेट्स स्टँडअलोनमध्ये कॉपी करा
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) better-sqlite3 नेटिव्ह बाइंडिंग कंपाइल करा
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js

	# 5) कंपाइल केलेले बाइंडिंग स्टँडअलोन बंडलमध्ये ठेवा
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) आर्किटेक्चर-विशिष्ट sharp बंडल्स काढून टाका
	rm -rf .next/standalone/node_modules/@img

	# 7) Next.js स्टॅटिक विश्लेषणातून वगळलेली pino रनटाइम अवलंबित्वे कॉपी करा:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# पोस्ट-इन्स्टॉल हुकद्वारे रिकाम्या Next.js अॅप राउटर डिरेक्टरीज काढल्या जाण्यापासून प्रतिबंधित करा
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"

	vbin "${WRKDIR}/omniroute"
}

post_install() {
```

## 🧩 प्रगत वैशिष्ट्ये

### सानुकूल मॉडेल

ॲप अपडेटची वाट न पाहता कोणत्याही प्रदात्यावर कोणतेही मॉडेल ID जोडा:

```bash
# Via API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# List: curl http://localhost:20128/api/provider-models?provider=openai
# Remove: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

किंवा डॅशबोर्ड वापरा:** प्रदाता → [प्रदाता] → सानुकूल मॉडेल** .

टिपा:

- OpenRouter आणि OpenAI/Anthropic-compatible प्रदाता पासून व्यवस्थापित केले जातात** उपलब्ध मॉडेल्स** फक्त मॅन्युअल जोडा, आयात करा आणि सर्व जमीन समान उपलब्ध-मॉडेल सूचीमध्ये स्वयं-समक्रमित करा, त्यामुळे त्या प्रदात्यांसाठी कोणताही स्वतंत्र सानुकूल मॉडेल विभाग नाही.
- द** सानुकूल मॉडेल** विभाग प्रदात्यांसाठी आहे जे व्यवस्थापित उपलब्ध-मॉडेल आयात उघड करत नाहीत.

### सानुकूल OpenAI-सुसंगत प्रदाता

OpenAI API (सेल्फ-होस्टेड प्रॉक्सी, vLLM, तृतीय-पक्ष एग्रीगेटर) बोलणारा कोणताही गेटवे स्वतःचा प्रदाता नोड म्हणून जोडला जाऊ शकतो:

1. **प्रदाते → OpenAI सुसंगत जोडा** .
2. **नाव** : नोडसाठी प्रदर्शन लेबल.
3. **उपसर्ग** : राउटिंग नाव. क्लायंट मॉडेलला `<prefix>/<model>` म्हणतात, म्हणून `mygw` उपसर्ग असलेला नोड `mygw/gpt-4o-mini` सेवा देतो. आवश्यक; कोणतेही वर्ण बंधन नाही.
4. **API प्रकार** : गेटवे ज्या एंडपॉईंट कुटुंबाला सेवा देतो (चॅट पूर्णता, प्रतिसाद, एम्बेडिंग, ऑडिओ, प्रतिमा).
5. **बेस URL** : API रूट, `/v1` पर्यंत आणि त्यासह (उदाहरणार्थ `https://gateway.example.com/v1`), पूर्ण `/chat/completions` मार्ग नाही. नॉन-स्टँडर्ड पथ असलेले गेटवे त्यांना खाली सेट करतात** प्रगत सेटिंग्ज** (चॅट पथ, मॉडेल पथ).
6. द**API की (चेकसाठी)** फील्ड फक्त कनेक्शनची चाचणी घेते. नोड तयार केल्यानंतर, ते उघडा आणि वापरा** कनेक्शन जोडा** विनंत्या वापरतील ती की साठवण्यासाठी.

नोडला `openai-compatible-<apiType>-<uuid>` फॉर्मची अंतर्गत आयडी मिळते; तुम्हाला ते कधीही टाइप करण्याची गरज नाही, उपसर्ग हे सार्वजनिक नाव आहे.

#### राखीव उपसर्ग

उपसर्ग हा अंगभूत प्रदात्याचा आयडी किंवा उपनाव असू शकत नाही (उदाहरणार्थ `openai`, `cf`), किंवा सेवानिवृत्त प्रदात्याचा id असू शकत नाही. मॉडेल रिझॉल्व्हर सानुकूल नोड्सपूर्वी अंगभूत आयडी आणि उपनाम तपासतो, त्यामुळे त्या उपसर्गांपैकी एक वापरणारा नोड कधीही ट्रॅफिक प्राप्त करू शकत नाही: `<prefix>/model` त्याऐवजी अंगभूत प्रदात्याकडे जाईल, किंवा तो प्रदाता सेवानिवृत्त झाल्यास अयशस्वी होईल. अशा उपसर्गासह नोड तयार करणे किंवा संपादित करणे यासह नाकारले जाते:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

एक वेगळा उपसर्ग निवडा (`mygw`, `acme-proxy`). सानुकूल नोडच्या विनंत्या बिल्ट-इन प्रदात्याला किंवा त्याच्या क्रेडेन्शियल्सला नाव देणाऱ्या त्रुटीसह अयशस्वी झाल्यास, नोडचा उपसर्ग राखीव आहे की नाही ते तपासा: हा नियम अस्तित्वात येण्यापूर्वी जतन केलेले नोड्स अद्याप संग्रहित आहेत, परंतु अंगभूत प्रदात्याकडे त्यांचे उपसर्ग मार्ग आहेत. नोड संपादित करा आणि त्याला नवीन उपसर्ग द्या.

#### प्रति-कनेक्शन गेटवे पर्याय

या की कनेक्शनच्या `providerSpecificData` मध्ये जातात (उदाहरणार्थ `PUT /api/providers/{id}` द्वारे):

- `toolNameMaxLength` (पूर्णांक, 1–1024) — OpenAI चॅट-फॉर्मॅट सुसंगत कनेक्शनसाठी ज्यांचे गेटवे लांब साधनांची नावे नाकारतात. मोठी नावे लहान उपनाम म्हणून पाठवली जातात आणि प्रतिसादात पुनर्संचयित केली जातात.
- `quotaEndpoint` — गेटवेचा quota/credits एंडपॉइंट, डॅशबोर्ड कोटा स्ट्रिप आणि कोटा-अवेअर राउटिंगसाठी वाचा. OpenAI- आणि अँथ्रोपिक-सुसंगत कनेक्शनवर कार्य करते; पूर्ण आकार `open-sse/services/usage/openaiCompatible.ts` मध्ये दस्तऐवजीकरण केलेला आहे.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### चेनिंग OmniRoute समवयस्क

दुसरा OmniRoute गेटवे a म्हणून जोडला जाऊ शकतो** सानुकूल OpenAI-सुसंगत** प्रदाता पीअरचा `/v1` बेस URL आणि त्या पीअरने जारी केलेली समर्पित, कमीत कमी विशेषाधिकार असलेली API की वापरा.

परस्पर किंवा मल्टी-हॉप चेनसाठी, प्रत्येक गेटवेवर ऑप्ट-इन लूप गार्ड सक्षम करा:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

केवळ स्पष्टपणे परवानगी असलेल्या पीअर URL ला पाठवलेल्या विनंत्या `X-OmniRoute-Peer-Trace` शीर्षलेख प्राप्त करतात. गेटवे HTTP `508 Loop Detected` सह पुनरावृत्ती झालेल्या ID किंवा थकलेले हॉप बजेट नाकारतो; सामान्य अपस्ट्रीम प्रदाते कोणताही पीअर मेटाडेटा प्राप्त करत नाहीत.

पीअर चेनिंग हे डेटाबेस प्रतिकृती किंवा होस्ट फेलओव्हर नाही. प्रत्येक गेटवे स्वतंत्र SQLite स्थिती, कॅशे, दर काउंटर आणि सत्रे ठेवतो. active/passive किंवा active/active उपलब्धतेसाठी आरोग्य-तपासणी केलेली रिव्हर्स प्रॉक्सी किंवा क्लायंट फेलओव्हर वापरा आणि एकापेक्षा जास्त चालू असलेल्या OmniRoute उदाहरणांमध्ये कधीही एक SQLite डेटाबेस माउंट करू नका.

### क्लाउड सिंक

- डिव्हाइसेसवर प्रदाता, कॉम्बो आणि सेटिंग्ज समक्रमित करा
- टाइमआउट + फेल-फास्ट सह स्वयंचलित पार्श्वभूमी सिंक
- उत्पादनामध्ये सर्व्हर-साइड `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` ला प्राधान्य द्या

### Cloudflare जलद बोगदा

- मध्ये उपलब्ध** डॅशबोर्ड → एंडपॉइंट्स** Docker आणि इतर स्वयं-होस्ट केलेल्या उपयोजनांसाठी
- एक तात्पुरता `https://*.trycloudflare.com` URL तयार करते जो तुमच्या वर्तमान OpenAI- सुसंगत `/v1` एंडपॉइंटवर फॉरवर्ड करतो
- प्रथम जेव्हा आवश्यक असेल तेव्हाच `cloudflared` स्थापित करणे सक्षम करा; नंतर रीस्टार्ट समान व्यवस्थापित बायनरी पुन्हा वापरतात
- OmniRoute किंवा कंटेनर रीस्टार्ट केल्यानंतर जलद बोगदे स्वयं-पुनर्स्थापित होत नाहीत; जेव्हा आवश्यक असेल तेव्हा त्यांना डॅशबोर्डवरून पुन्हा-सक्षम करा
- बोगदा URLs हा क्षणिक असतो आणि प्रत्येक वेळी तुम्ही बोगदा stop/start तेव्हा बदलतो
- मर्यादित कंटेनरमध्ये गोंगाट करणारा QUIC UDP बफर चेतावणी टाळण्यासाठी HTTP/2 वाहतुकीसाठी व्यवस्थापित जलद बोगदे डीफॉल्ट
- तुम्ही व्यवस्थापित वाहतूक निवड ओव्हरराइड करू इच्छित असल्यास `CLOUDFLARED_PROTOCOL=quic` किंवा `auto` सेट करा
- व्यवस्थापित डाउनलोड ऐवजी तुम्ही पूर्वस्थापित `cloudflared` बायनरी वापरण्यास प्राधान्य दिल्यास `CLOUDFLARED_BIN` सेट करा
- Cloudflare क्विक टनेल, Tailscale फनेल आणि ngrok टनल पॅनेल दाखवले किंवा लपवले जाऊ शकतात** सेटिंग्ज → स्वरूप** . पॅनेल लपवल्याने चालू असलेला बोगदा थांबत नाही.

### LLM गेटवे इंटेलिजन्स (फेज 9)

- **सिमेंटिक कॅशे** — ऑटो-कॅशे नॉन-स्ट्रीमिंग, तापमान = 0 प्रतिसाद ( `X-OmniRoute-No-Cache: true` सह बायपास)
- **इडम्पोटेन्सीची विनंती करा** — `Idempotency-Key` किंवा `X-Request-Id` शीर्षलेख द्वारे 5s आत विनंत्या डुप्लिकेट करते
- **प्रगती ट्रॅकिंग** — `X-OmniRoute-Progress: true` हेडरद्वारे SSE `event: progress` इव्हेंट्सची निवड करा

- OpenAI, Claude, Gemini, आणि प्रतिसाद API फॉरमॅटमधील स्वरूपातील फरकांची तुलना करा

### राउटिंग धोरणे

द्वारे कॉन्फिगर करा** डॅशबोर्ड → सेटिंग्ज → राउटिंग** . डॅशबोर्ड सर्वाधिक वापरल्या जाणाऱ्या सहा धोरणांचा पर्दाफाश करतो; कॉम्बो आणि ऑटो-राउटर एका विस्तृत सेटला अंतर्गत समर्थन देतात.

**डॅशबोर्ड-दृश्यमान धोरणे (खाते-स्तर राउटिंग):**

| रणनीती                         | वर्णन                                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------ |
| **प्रथम भरा**                  | प्राधान्य क्रमाने खाती वापरते — प्राथमिक खाते अनुपलब्ध होईपर्यंत सर्व विनंत्या हाताळते           |
| **राउंड रॉबिन**                | कॉन्फिगर करण्यायोग्य स्टिकी मर्यादेसह सर्व खात्यांमधून चक्र (डीफॉल्ट: प्रति खाते 3 कॉल)          |
| **P2C (दोन पर्यायांची शक्ती)** | 2 यादृच्छिक खाती आणि निरोगी खाती निवडते — आरोग्याविषयी जागरूकता भार संतुलित करते                 |
| **यादृच्छिक**                  | Fisher-Yates shuffle वापरून प्रत्येक विनंतीसाठी यादृच्छिकपणे खाते निवडते                         |
| **कमीत कमी वापरलेले**          | ट्रॅफिक समान रीतीने वितरीत करून, सर्वात जुन्या `lastUsedAt` टाइमस्टॅम्पसह खात्याचे मार्ग         |
| **खर्च ऑप्टिमाइझ केला**        | सर्वात कमी प्राधान्य मूल्यासह खात्याचे मार्ग, सर्वात कमी किमतीच्या प्रदात्यांसाठी ऑप्टिमाइझ करणे |

**प्रगत कॉम्बो आणि ऑटो रणनीती** (प्रति कॉम्बो किंवा `auto/*` उपसर्गाद्वारे कॉन्फिगर करण्यायोग्य — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) पहा):

- `priority` — कडक ऑर्डर, कधीही राउंड-रॉबिन नाही
- `weighted` — आनुपातिक रहदारी प्रति-मॉडेल वजनानुसार विभाजित
- `fill-first` — मर्यादा येईपर्यंत पहिले मॉडेल काढून टाका
- `round-robin` / `strict-random` / `random`
- `p2c` (दोन पर्यायांची शक्ती)
- `least-used` आणि `cost-optimized`
- `auto` — सर्व उमेदवारांसाठी स्कोअर-चालित
- `lkgp` (अंतिम ज्ञात चांगला प्रदाता) — शेवटच्या यशस्वी प्रदात्याला पिन करतो, नंतर नियमांवर येतो
- `context-optimized` — सर्वात मोठ्या मुक्त संदर्भ विंडोसह मॉडेल निवडते
- `context-relay` — फॉलो-अप वळणांसाठी लांब-संदर्भ मॉडेल्स चेन

#### बाह्य चिकट सत्र शीर्षलेख

बाह्य सेशन ॲफिनिटीसाठी (उदाहरणार्थ, रिव्हर्स प्रॉक्सीच्या मागे Claude Code/Codex एजंट), पाठवा:

```http
X-Session-Id: your-session-key
```

OmniRoute देखील `x_session_id` स्वीकारते आणि `X-OmniRoute-Session-Id` मध्ये प्रभावी सत्र की परत करते.

तुम्ही Nginx वापरत असल्यास आणि अंडरस्कोर-फॉर्म हेडर पाठवत असल्यास, सक्षम करा:

```nginx
underscores_in_headers on;
```

#### वाइल्डकार्ड मॉडेल उपनाम

मॉडेलची नावे रीमॅप करण्यासाठी वाइल्डकार्ड नमुने तयार करा:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

वाइल्डकार्ड `*` (कोणतेही वर्ण) आणि `?` (एकल वर्ण) चे समर्थन करतात.

#### फॉलबॅक चेन

सर्व विनंत्यांना लागू होणाऱ्या जागतिक फॉलबॅक साखळी परिभाषित करा:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### सामान्य प्रदाता संयोजन आणि राउटिंग नमुने

OmniRoute मध्ये एकाधिक प्रदाते एकत्र करण्यासाठी आणि त्यांच्या दरम्यान राउटिंग करण्यासाठी येथे उदाहरणे आहेत:

#### 1. कोडिंग एजंट कॉम्बो: Cost/Speed फॉलबॅकसह उच्च-अंत तर्क

कोडिंग एजंट्ससाठी आदर्श (OpenCode, Claude कोड, Cursor, Cline). कोटा संपुष्टात येण्यावर किंवा त्रुटींवरील जलद कोडिंग मॉडेल्सकडे परत येत, सीमावर्ती तर्क मॉडेल्सकडे प्रारंभी मार्ग.

- **डॅशबोर्ड** : Combos → नवीन कॉम्बो → नाव: `agent-coding` → धोरण: `Priority`
- **मॉडेल्स** :
  1. `claude/claude-sonnet-4-6` (प्राथमिक कोडिंग एजंट)
  2. `openai/gpt-4o` (दुय्यम उच्च-क्षमता फॉलबॅक)
  3. `deepseek/deepseek-v4-flash` (उच्च-कार्यक्षमता, खर्च-प्रभावी फॉलबॅक)

```bash
# Example via API
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

#### 2. फ्री-टियर ऑटो फेलओव्हर कॉम्बो

API खर्चाशिवाय जास्तीत जास्त अपटाइम करण्यासाठी अनेक फ्री-टियर आणि कीलेस प्रदाते चेन करतात.

- **रणनीती** : `Least Used` किंवा `Round Robin` (कोटामध्ये लोड वितरित करते)
- **मॉडेल्स** :
  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

```bash
# Example via CLI
omniroute combo create free-stack \
  --models "groq/llama-3.3-70b-versatile,gemini/gemini-2.5-flash,cerebras/gpt-oss-120b" \
  --strategy round-robin
```

#### 3. मल्टीमोडल / व्हिजन आणि टेक्स्ट पाइपलाइन

इमेज समजणे आणि कोड जनरेशनचा समावेश असलेल्या वर्कफ्लोसाठी हाय-स्पीड टेक्स्ट जनरेशनसह विशेष व्हिजन मॉडेल्स जोडणे.

- **नमुना** : एक `Priority` कॉम्बो जो प्रथम दृष्टी-सक्षम मॉडेल्सची यादी करतो आणि उच्च-थ्रूपुट text/code मॉडेल शेवटचे.
- **मॉडेल्स** :
  1. `gemini/gemini-2.5-pro` (मजबूत image/multimodal आकलन)
  2. `openai/gpt-4o` (संतुलित दृष्टी आणि साधन वापर)
  3. `deepseek/deepseek-v4-flash` (Text/code पिढी)

### लवचिकता आणि सर्किट ब्रेकर्स

द्वारे कॉन्फिगर करा** डॅशबोर्ड → सेटिंग्ज → लवचिकता** .

OmniRoute पाच घटकांसह प्रदाता-स्तरीय लवचिकता लागू करते:

1. **रांग आणि पेसिंगची विनंती करा** — सिस्टम-स्तरीय विनंती आकार देणे:
   - **प्रति मिनिट विनंत्या (RPM)** — प्रति मिनिट प्रति खाते जास्तीत जास्त विनंत्या
   - **विनंती दरम्यान किमान वेळ** - विनंत्यांमधील किमान अंतर मिलिसेकंदांमध्ये
   - **कमाल समवर्ती विनंत्या** — प्रति खाते जास्तीत जास्त एकाचवेळी विनंत्या

2. **कनेक्शन Cooldown** — पुन्हा प्रयत्न करता येण्याजोग्या अपयशानंतर एकाच कनेक्शनसाठी प्रति-ऑथ-प्रकार कॉन्फिगरेशन:
   - **बेस कूलडाउन** — पुन्हा प्रयत्न करण्यायोग्य अपस्ट्रीम अपयशांसाठी डीफॉल्ट कूलडाउन विंडो
   - **अपस्ट्रीम पुन्हा प्रयत्न करण्याच्या सूचना वापरा** — प्रदान केल्यावर अधिकृत `Retry-After` किंवा रीसेट संकेतांचा सन्मान करतो
   - **कमाल बॅकऑफ पावले** — पुनरावृत्ती अपयशांसाठी कमाल घातांकीय बॅकऑफ पातळी

3. **प्रदाता सर्किट ब्रेकर** — एंड-टू-एंड प्रदात्याच्या अपयशांचा मागोवा ठेवते, कॉन्फिगर केलेल्या चेतावणी थ्रेशोल्डवर डिग्रेड केलेल्या प्रदात्याला चिन्हांकित करते आणि कॉन्फिगर केलेले अपयश थ्रेशोल्ड गाठल्यावर ब्रेकर उघडते:
   - **डिग्रेडेशन थ्रेशोल्ड** — `DEGRADED` मध्ये प्रवेश करण्यापूर्वी सलग प्रदाता अपयशी
   - **अपयश थ्रेशोल्ड** — `OPEN` मध्ये प्रवेश करण्यापूर्वी सलग प्रदाता अपयशी
   - **टाइमआउट रीसेट करा** — प्रदात्याची पुन्हा चाचणी होण्यापूर्वी वेळ विंडो
   - **CLOSED** (निरोगी) - विनंत्या सामान्यपणे वाहतात
   - **DEGRADED** — उंचावलेल्या अपयशांचा मागोवा घेत असतानाही विनंत्या प्रवाहित होतात
   - **OPEN** — वारंवार अपयश आल्यानंतर प्रदाता तात्पुरता अवरोधित केला जातो
   - **HALF_OPEN** - प्रदाता पुनर्प्राप्त झाला असल्यास चाचणी

   कनेक्शन-स्कॉप्ड `429` दर मर्यादा कायम राहतील** कनेक्शन Cooldown** आणि प्रदाता ब्रेकरकडे मोजू नका.

   प्रदाता ब्रेकर रनटाइम स्थिती वर दर्शविली आहे** डॅशबोर्ड → आरोग्य** फक्त

4. **Cooldown साठी प्रतीक्षा करा** — जर प्रत्येक उमेदवार कनेक्शन आधीच थंड होत असेल तर, OmniRoute लवकरात लवकर कूलडाउनची प्रतीक्षा करू शकते आणि त्याच क्लायंटच्या विनंतीवर स्वयंचलितपणे पुन्हा प्रयत्न करू शकते.

5. **रेट मर्यादा स्वयं-शोध** — जेव्हा अपस्ट्रीम प्रदाते स्पष्ट प्रतीक्षा विंडो परत करतात, तेव्हा सेटिंग सक्षम केल्यावर ते संकेत स्थानिक कनेक्शन कूलडाउन ओव्हरराइड करतात.

**प्रो टीप:** वापरा** आरोग्य** आउटेज नंतर थेट प्रदाता ब्रेकर्सची तपासणी करण्यासाठी आणि रीसेट करण्यासाठी पृष्ठ. लवचिकता पृष्ठ केवळ कॉन्फिगरेशन बदलते.

### डेटाबेस निर्यात / आयात

मध्ये डेटाबेस बॅकअप व्यवस्थापित करा** डॅशबोर्ड → सेटिंग्ज → सिस्टम आणि स्टोरेज** .

| कृती                           | वर्णन                                                                                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **डेटाबेस निर्यात करा**        | वर्तमान SQLite डेटाबेस `.sqlite` फाइल म्हणून डाउनलोड करते                                                                                         |
| **सर्व (.tar.gz) निर्यात करा** | यासह संपूर्ण बॅकअप संग्रहण डाउनलोड करते: डेटाबेस, सेटिंग्ज, कॉम्बो, प्रदाता कनेक्शन (कोणतेही क्रेडेन्शियल नाही), API की मेटाडेटा                  |
| **डेटाबेस आयात करा**           | वर्तमान डेटाबेस पुनर्स्थित करण्यासाठी `.sqlite` फाइल अपलोड करा. `DISABLE_SQLITE_AUTO_BACKUP=true` असल्याशिवाय प्री-इम्पोर्ट बॅकअप आपोआप तयार होतो |

```bash
# API: Export database
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: Export all (full archive)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: Import database
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**आयात प्रमाणीकरण:** इंपोर्ट केलेली फाइल अखंडता (SQLite pragma check), आवश्यक टेबल्स (`provider_connections`, `provider_nodes`, `combos`, `api_keys`), आणि आकार ( कमाल 100MB) साठी प्रमाणित केली आहे.

**प्रकरणे वापरा:**

- मशीन दरम्यान OmniRoute स्थलांतर करा
- आपत्ती पुनर्प्राप्तीसाठी बाह्य बॅकअप तयार करा
- कार्यसंघ सदस्यांमधील कॉन्फिगरेशन सामायिक करा (सर्व → शेअर संग्रहण निर्यात करा)

### ऑडिओ ट्रान्सक्रिप्शन

OmniRoute ओपनएआय-सुसंगत एंडपॉइंटद्वारे ऑडिओ ट्रान्सक्रिप्शनला समर्थन देते:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# Example with curl
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

`deepgram/nova-3` हा मूळ दीपग्राम मार्ग आहे आणि त्याला दीपग्राम API की आवश्यक आहे. फक्त OpenRouter कॉन्फिगर केले असल्यास, `openrouter/deepgram/nova-3` वापरा.

**स्पीच-टू-टेक्स्ट (लिप्यंतरण)** प्रदाता:

- `openai/` (कुजबुज-सुसंगत)
- `groq/` (Groq व्हिस्पर टर्बो)
- `deepgram/` (नोव्हा फॅमिली)
- `assemblyai/`
- `nvidia/` (पॅराकीट, कॅनरी)
- `huggingface/` (फुसफुसणे प्रकार)
- `qwen/`

**टेक्स्ट-टू-स्पीच (`POST /v1/audio/speech`)** प्रदाता:

- `openai/` (tts-1, tts-1-hd)

- `elevenlabs/`

### कॉम्बो बॅलन्सिंग स्ट्रॅटेजीज

मध्ये प्रति-कॉम्बो संतुलन कॉन्फिगर करा** डॅशबोर्ड → कॉम्बोस → Create/Edit → धोरण** .

| रणनीती                | वर्णन                                                           |
| --------------------- | --------------------------------------------------------------- |
| **राउंड-रॉबिन**       | मॉडेल्समधून अनुक्रमे फिरते                                      |
| **प्राधान्य**         | नेहमी पहिल्या मॉडेलचा प्रयत्न करतो; फक्त चुकल्यावरच मागे पडतो   |
| **यादृच्छिक**         | प्रत्येक विनंतीसाठी कॉम्बोमधून एक यादृच्छिक मॉडेल निवडते        |
| **भारित**             | प्रति मॉडेल नियुक्त केलेल्या वजनावर प्रमाणानुसार आधारित मार्ग   |
| **कमीत कमी वापरलेले** | सर्वात कमी विनंत्यांसह मॉडेलचे मार्ग (कॉम्बो मेट्रिक्स वापरतात) |
| **खर्च-अनुकूलित**     | स्वस्त उपलब्ध मॉडेलचे मार्ग (किंमत सारणी वापरते)                |

ग्लोबल कॉम्बो डीफॉल्ट सेट केले जाऊ शकतात** डॅशबोर्ड → सेटिंग्ज → राउटिंग → कॉम्बो डीफॉल्ट** . कॉम्बो लक्ष्य कालबाह्य वर्तमान विनंती कालबाह्य डीफॉल्टनुसार वारसा घेतात. वापरा** लक्ष्य कालबाह्य (सेकंद)** कॉम्बो डीफॉल्ट किंवा वैयक्तिक कॉम्बोवर फक्त तेव्हाच जेव्हा लहान प्रति-लक्ष्य मर्यादा जलद फॉलबॅक ट्रिगर करते.

झिरो-लेटन्सी कॉम्बो ऑप्टिमायझेशन निवडले जातात. सोडा** शून्य विलंब ऑप्टिमायझेशन** फॉलबॅक लक्ष्यांच्या रेसिंगपासून, TTFT इतिहासावर आधारित लक्ष्ये वगळण्यापासून, किंवा फॉलबॅक विनंत्या संकुचित करण्यापासून या लेटन्सी वैशिष्ट्यांना प्रतिबंधित करण्यासाठी अक्षम; हे सक्षम केल्याने कॉन्फिगर केलेले हेजिंग, प्रेडिक्टिव TTFT स्किप आणि प्रोॲक्टिव्ह फॉलबॅक कॉम्प्रेशनला लोअर टेल लेटन्सीसाठी routing/request फिडेलिटीचा व्यापार करता येतो.

अक्षम करा** तर्कसंगत टोकन बफर** जेव्हा अपस्ट्रीम प्रदात्यांना कठोर `max_tokens` / `maxOutputTokens` मर्यादा आवश्यक असतात. सक्षम केल्यावर, कॉम्बो राउटिंग केवळ ज्ञात आउटपुट कॅप असलेल्या मॉडेलसाठी तर्क-मॉडेल हेडरूम जोडते आणि सुरक्षित बफर केलेले मूल्य त्या कॅपपेक्षा जास्त असेल तेव्हा क्लायंट टोकन मर्यादा अपरिवर्तित ठेवते. जर क्लायंट मर्यादा आधीच ज्ञात कॅपच्या वर असेल, तर OmniRoute अपस्ट्रीम विनंती पाठवण्यापूर्वी त्यास त्या कॅपवर क्लॅम्प करते.

| **सक्रिय लॉकआउट्स**    | सक्रिय मॉडेल-स्कोप केलेले लॉकआउट आणि तात्पुरते बहिष्कार |
| **स्वाक्षरी कॅशे**     | डुप्लिकेशन कॅशे आकडेवारी (सक्रिय की, हिट रेट)           |
| **लेटन्सी टेलीमेट्री** | प्रति प्रदाताp50/p95/p99 विलंबता एकत्रीकरण              |

**प्रो टीप:** आरोग्य पृष्ठ दर 10 सेकंदांनी स्वयं-रिफ्रेश होते. कोणत्या पुरवठादारांना समस्या येत आहेत हे ओळखण्यासाठी सर्किट ब्रेकर कार्ड वापरा.

## 🤖 स्वयंचलित रूटिंग (शून्य-कॉन्फिगरेशन)

OmniRoute मध्ये **स्कोअर-आधारित स्वयंचलित राउटर** समाविष्ट आहे, जो प्रत्येक कनेक्ट केलेल्या प्रदात्यामधून प्रत्येक विनंतीसाठी सर्वोत्तम मॉडेल निवडतो — कोणताही कॉम्बो सांभाळण्याची गरज नाही. फक्त `auto/*` उपसर्गांपैकी एक वापरून विनंती पाठवा आणि OmniRoute तत्काळ एक आभासी कॉम्बो तयार करेल. तो विलंब, खर्च, यशाचा दर, संदर्भाची अनुरूपता, कार्यासाठी मॉडेलची योग्यता, अलीकडील अपयशे, कोटा आणि सर्किट-ब्रेकरची स्थिती यांच्या आधारे उमेदवारांना स्कोअर देतो.

| उपसर्ग         | कशासाठी अनुकूलित करतो                                                                        |
| -------------- | -------------------------------------------------------------------------------------------- |
| `auto`         | संतुलित डीफॉल्ट (विलंब × खर्च × यशाचा दर)                                                    |
| `auto/coding`  | कोडिंग कार्ये: Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek कोडरना प्राधान्य देतो          |
| `auto/cheap`   | सर्वात कमी $/token, जास्त विलंब स्वीकारतो                                                    |
| `auto/fast`    | सर्वात कमी विलंब, खर्चाकडे दुर्लक्ष करतो                                                     |
| `auto/offline` | केवळ स्थानिक प्रदाते (Ollama, vLLM, llama.cpp) — एअर-गॅप्ड सेटअपसाठी उपयुक्त                 |
| `auto/smart`   | तर्कशक्तीच्या गुणवत्तेला सर्वोच्च प्राधान्य (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)       |
| `auto/lkgp`    | "शेवटचा ज्ञात चांगला प्रदाता" — शेवटच्या यशस्वी प्रदात्यावर स्थिर राहतो, नंतर नियमांकडे वळतो |

उदाहरण:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

स्वयंचलित राउटरचे संपूर्ण वर्णन [AUTO-COMBO.md](../routing/AUTO-COMBO.md) मध्ये दिले आहे — यात स्कोअरिंगचे भार कसे समायोजित करायचे, प्रदात्यांना काळ्या यादीत कसे टाकायचे आणि **Dashboard → Auto Combo** मध्ये रूटिंगचे निर्णय कसे तपासायचे याचाही समावेश आहे.

## 🔌 MCP आणि A2A एकत्रीकरण

OmniRoute हा **MCP सर्व्हर** (Model Context Protocol) आणि **A2A सर्व्हर** (Agent-to-Agent JSON-RPC 2.0) दोन्ही आहे. कोणतेही MCP-सुसंगत IDE किंवा एजंट होस्ट OmniRoute साधनांना थेट कॉल करू शकते — कोणत्याही अतिरिक्त रॅपरची आवश्यकता नाही.

### MCP ट्रान्सपोर्ट

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **स्ट्रीम करण्यायोग्य HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (stdio ला प्राधान्य देणाऱ्या IDE प्लगइनसाठी)

### Claude Desktop कनेक्ट करा

macOS वरील `~/Library/Application Support/Claude/claude_desktop_config.json` किंवा Windows/Linux वरील समतुल्य फाइल संपादित करा:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCP कनेक्ट करा

SSE URL `http://localhost:20128/api/mcp/sse` आणि **Dashboard → API Keys** मध्ये तयार केलेली Bearer API की वापरा.

### व्याप्ती

MCP सध्या 32 नामांकित व्याप्ती परिभाषित करते. प्रत्येक Bearer की विशिष्ट व्याप्तींपुरती मर्यादित करता येते — अधिकृत व्याप्ती आणि साधन-सूचीसाठी [MCP-SERVER.md](../frameworks/MCP-SERVER.md), तसेच JSON-RPC स्कीमासाठी [A2A-SERVER.md](../frameworks/A2A-SERVER.md) पहा.

- **मार्केटप्लेस UI** — **डॅशबोर्ड → कौशल्ये** मधून कौशल्ये ब्राउझ आणि इंस्टॉल करा
- **प्रति-की स्कोप्स** — कोणत्या API की कोणती कौशल्ये वापरू शकतात हे मर्यादित करा
- **सानुकूल कौशल्ये** — `src/lib/a2a/skills/` मध्ये TypeScript फाइल ठेवा, तिची नोंदणी करा आणि ती A2A वरून त्वरित वापरण्यायोग्य होते

## 💾 मेमरी प्रणाली

OmniRoute हायब्रिड पुनर्प्राप्तीसह **दीर्घकालीन संभाषणात्मक मेमरी** कायमस्वरूपी साठवते:

- मागील संवादांमध्ये कीवर्ड शोधण्यासाठी **SQLite FTS5**
- अर्थाधारित पुनर्स्मरणासाठी **Qdrant vector store** (पर्यायी)
- **स्वयंचलित तथ्य निष्कर्षण** — प्रत्येक सत्रानंतर घटक, प्राधान्ये आणि निर्णयांचा सारांश तयार करून ते `memory_facts` टेबलमध्ये साठवले जातात
- मेमरी प्रत्येक API की आणि प्रत्येक सत्रानुसार स्वतंत्र ठेवली जाते

**डॅशबोर्ड → मेमरी** मध्ये मेमरी व्यवस्थापित करा (शोधा, संपादित करा, निर्यात करा, पूर्णपणे हटवा). HTTP इंटरफेस (`/api/memory/*`) एजंट्सना प्रोग्रामद्वारे तथ्ये पाठवण्याची आणि क्वेरी करण्याची सुविधा देतो — [MEMORY.md](../frameworks/MEMORY.md) पहा.

## 🛠️ प्रोग्रामद्वारे व्यवस्थापन

**`manage` स्कोप असलेली Bearer की** वापरून तुम्ही HTTP द्वारे प्रत्येक OmniRoute संसाधन (प्रदाते, कॉम्बोज, कीज, सेटिंग्ज) व्यवस्थापित करू शकता.

**डॅशबोर्ड → API कीज → नवीन की → स्कोप: manage** मध्ये की तयार करा, त्यानंतर:

```bash
# प्रदात्यांची सूची दाखवा
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# प्रदाता कनेक्शन जोडा
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# कॉम्बो तयार करा
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API कीजची सूची दाखवा/तयार करा
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

संपूर्ण एंडपॉइंट कॅटलॉग आणि विनंती/प्रतिसाद स्कीमांसाठी [API_REFERENCE.md](../reference/API_REFERENCE.md) पहा.

## 💻 अंतर्गत CLI

OmniRoute सेटअप, निदान आणि रनटाइम नियंत्रणासाठी अंतर्गत CLI (`omniroute …`) सह उपलब्ध होते. हे **डॅशबोर्डमधील "CLI साधने" पृष्ठापेक्षा वेगळे आहे**, जे तृतीय-पक्षीय CLI (Claude Code, Cursor, Codex, Cline, …) कॉन्फिगर करते, जेणेकरून ते OmniRoute शी संवाद साधू शकतील.

```bash
omniroute setup                    # परस्परसंवादी विझार्ड (पासवर्ड, प्रदाते, कॉम्बो)
omniroute setup --non-interactive  # CI-सुसंगत
omniroute doctor                   # आरोग्य निदान (डेटा डिरेक्टरी, DB, प्रदाते, पोर्ट)
omniroute providers available      # समर्थित प्रदात्यांची सूची
omniroute providers list           # कॉन्फिगर केलेल्या कनेक्शनची सूची
omniroute providers test <id>      # प्रदाता कनेक्शनची थेट चाचणी
omniroute combos list              # कॉम्बोंची सूची
omniroute combos switch <name>     # डीफॉल्ट कॉम्बो सेट करा
omniroute models                   # उपलब्ध मॉडेलची सूची (--json, --search)
omniroute keys add | list | remove # टर्मिनलमधून API की व्यवस्थापित करा
omniroute backup                   # कॉन्फिगरेशन + DB चा स्नॅपशॉट
omniroute restore [<timestamp>]    # स्नॅपशॉटमधून पुनर्संचयित करा
omniroute health                   # सविस्तर आरोग्य माहिती (ब्रेकर्स, कॅशे, मेमरी)
omniroute quota                    # प्रदाता कोटा वापर
omniroute mcp status               # MCP सर्व्हरची स्थिती
omniroute a2a status               # A2A सर्व्हरची स्थिती
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok टनेल
omniroute reset-password           # प्रशासकाचा पासवर्ड रीसेट करा
omniroute --mcp                    # stdio वर MCP सर्व्हर सुरू करा
omniroute --port 3000              # सानुकूल पोर्टवर सर्व्हर सुरू करा
```

टीप: प्रदाता कनेक्शन अस्वस्थ असल्यास सूचना मिळवण्यासाठी `omniroute doctor --json` आपल्या निरीक्षण साधनासोबत वापरा.
