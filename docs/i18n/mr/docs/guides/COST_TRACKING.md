OmniRoute प्रत्येक विनंतीच्या खर्चाचा अंदाज कसा लावते, त्याची नोंद कशी करते आणि त्याचा अहवाल कसा देते — तसेच
डॅशबोर्डवरील आकडा बिल नसून **बचत ट्रॅकर** का आहे.

हेही पहा: [वापरकर्ता मार्गदर्शिका](./USER_GUIDE.md) · [वैशिष्ट्यांची गॅलरी](./FEATURES.md)

## हे काय आहे (आणि काय नाही)

OmniRoute टोकनची संख्या मॉडेलच्या किंमत-दरांनी गुणून प्रत्येक पूर्णत्वासाठी प्रत्येक-विनंतीचा USD खर्च निर्धारित करते.
हे आकडे **खर्च** डॅशबोर्ड,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON निर्याती आणि प्रत्येक API कीसाठीचे बजेट यांना आधार देतात.

> **डॅशबोर्डवरील "खर्च" हा बचत ट्रॅकर आहे, बिल नाही.** OmniRoute तुमच्याकडून कधीही शुल्क आकारत नाही
> — ती तुमच्या विनंत्या तुम्ही आधीच जोडलेल्या प्रदात्यांकडे (तुमच्या स्वतःच्या
> सदस्यता, मोफत श्रेणी आणि API की) रूट करते. पूर्णपणे मोफत
> मॉडेल्सवर जमा झालेला "$290 एकूण खर्च" म्हणजे साधारणपणे **तुम्ही सशुल्क API ला न भरलेले $290**.
> समान ट्रॅफिकसाठी प्रमाणित सूची-किंमतींनुसार किती खर्च आला असता याचा हा एक _अंदाज_ आहे,
> ज्यामुळे तुमचा वापर कुठे केंद्रित आहे आणि स्वस्त/मोफत प्रदात्यांकडे रूट केल्यामुळे तुमची किती बचत होत आहे हे तुम्ही पाहू शकता.

ही मांडणी प्रकल्पाच्या [README](../../README.md) मध्ये थेट नमूद केली आहे ("डॅशबोर्डवरील
'खर्च' हा बचत ट्रॅकर आहे, बिल नाही").

हा आकडा अंदाज असल्यामुळे:

- तो प्रत्येक मॉडेलसाठी OmniRoute कडे असलेल्या किंमत-तक्त्यावर अवलंबून असतो. किंमतीची
  नोंद नसलेले मॉडेल `0` खर्चात योगदान देते (एक्सप्लोररमध्ये ते "वारसा / मोफत" पंक्ती म्हणून दिसते).
- मोफत श्रेणी आणि सदस्यता ट्रॅफिकसाठीही _अंदाजित_ खर्च जमा होतो — ती
  तुम्ही वाचवत असलेली रक्कम आहे, देय रक्कम नाही.

## खर्चाचा अंदाज कसा लावला जातो

### किंमत स्रोत

खर्च [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) मध्ये विलीन केलेल्या किंमत सारणीतून येतात, या अग्रक्रमानुसार (**सर्वोच्च प्रथम** ):

1. **वापरकर्ता अधिलिखित करतो** — किमती डॅशबोर्डमध्ये किंवा `PATCH /api/pricing` ( `pricing` नेमस्पेस) द्वारे सेट केल्या जातात.
2. **models.dev सिंक** — किंमत `https://models.dev/api.json` ( `models_dev_pricing` नेमस्पेस) वरून मिळवली.
3. **LiteLLM समक्रमण** — किमती LiteLLM च्या सार्वजनिक `model_prices_and_context_window.json` ( `pricing_synced` नेमस्पेस) वरून मिळवल्या.
4. **हार्डकोड डीफॉल्ट** — दर [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) मध्ये पाठवले.

समान provider/model साठी, उच्च-प्राधान्य स्तरावरील मूल्ये खालच्या स्तरांमध्ये जुळणारे फील्ड अधिलिखित करतात; वरच्या थरातून अनुपस्थित फील्ड अजूनही खालच्या थरातून येऊ शकतात. दोन्ही स्वतंत्र समक्रमण कार्य एकाच वेळी चालत असताना देखील क्रम निश्चित केला जातो. `GET /api/pricing?includeSources=1` `pricing` आणि `sourceMap` परत करतो, ज्यांची प्रति-मॉडेल लेबले (`user`, `modelsDev`, `litellm`, `default`) ते मॉडेल असलेले सर्वोच्च-प्राधान्य स्तर ओळखतात.

**LiteLLM समक्रमण** ऑप्ट-इन आहे, डीफॉल्टनुसार अक्षम आहे. त्याचे पर्यावरणीय चल ( [`.env.example`](../../.env.example) पहा) आहेत:

| Env var                 | डीफॉल्ट   | उद्देश                                                               |
| ----------------------- | --------- | -------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | पार्श्वभूमी LiteLLM किंमत समक्रमण सक्षम करा.                         |
| `PRICING_SYNC_INTERVAL` | `86400`   | सेकंदांमध्ये (दररोज) मध्यांतर समक्रमित करा.                          |
| `PRICING_SYNC_SOURCES`  | `litellm` | केवळ या समक्रमणासाठी स्त्रोत निवड; सध्या फक्त `litellm` समर्थित आहे. |

**models.dev सिंक** LiteLLM सिंक पासून वेगळे आहे आणि डीफॉल्टनुसार अक्षम देखील आहे. ते सेटिंग्जमध्ये सक्षम करा (models.dev sync) किंवा हे व्हेरिएबल्स वापरा:

| Env var                    | डीफॉल्ट          | उद्देश                                                                                                                                   |
| -------------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(सेट न केलेले)_ | अनसेट सेटिंग्ज टॉगलचे अनुसरण करते; `1/true/on/yes` सक्तीने चालू करते आणि `0/false/off/no` सक्तीने बंद करते (जरी सेटिंग्ज ते सक्षम करते). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`          | डीफॉल्ट models.dev संकालित अंतराल सेकंदात (दररोज).                                                                                       |

`PRICING_SYNC_SOURCES` करतो**नाही** models.dev सक्षम करा; हे फक्त LiteLLM सिंक नियंत्रित करते. वापरकर्ता ओव्हरराइड हटवण्याने सिंक केलेले नेमस्पेस साफ होत नाही; पुढील उपलब्ध किंमत स्तर प्रभावी होईल. मूल्य नसलेल्या मॉडेलसाठी, मॅन्युअल ओव्हरराइड जोडण्यापूर्वी सिंक सेटिंग्ज आणि `sourceMap` दोन्ही तपासा.

### खर्चाचे सूत्र

[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`) मधील टोकन संख्या आणि प्रति-दशलक्ष-टोकन दरांवरील विनंतीनुसार खर्चाची गणना केली जाते:

- **इनपुट टोकन** (वजा कॅशे वाचन आणि कॅशे-निर्मिती टोकन) × `input` दर.
- **कॅशे-रीड टोकन** × `cached` दर (इनपुट दरावर परत येतो).
- **कॅशे-निर्मिती टोकन** × `cache_creation` दर (इनपुट दरावर परत येतो).
- **आउटपुट टोकन** × `output` दर.
- **तर्कसंगत टोकन** × `reasoning` दर (आउटपुट दरावर परत येतो).

सर्व दरांचा प्रति 1,000,000 टोकन USD म्हणून अर्थ लावला जातो. Codex "वेगवान"/"प्राधान्य" किंवा "फ्लेक्स" सेवा श्रेणी खर्च गुणक लागू करते (`getCodexFastCostMultiplier`) — उदा. फ्लेक्सला 50% टोकन सवलतीवर बिल केले जाते, असे समोर येते**फ्लेक्स बचत** डॅशबोर्ड मध्ये.

मॉडेलची नावे प्रथम सामान्यीकृत केली जातात (प्रदाता-पथ उपसर्ग जसे की `openai/` किंवा `accounts/fireworks/models/` काढून टाकले जातात) त्यामुळे ऐतिहासिक पंक्ती अजूनही किंमतीशी जुळतात.

### खर्च कसा नोंदवला जातो

- विनंती पूर्ण झाल्यावर प्रति-विनंती खर्चाची गणना केली जाते. शेअर्ड-कोटा वापर [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) द्वारे पुढील इव्हेंट-लूप टिकवर शेड्यूल केला आहे.
- API-की खर्च [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (डिफॉल्ट 60s फ्लश इंटरव्हल, 1,000-एंट्री बफर) द्वारे बॅचमध्ये बफर आणि फ्लश केला जातो. द्वारे ट्यून करण्यायोग्य:

  | Env var                             | डीफॉल्ट | उद्देश                                     |
  | ----------------------------------- | ------- | ------------------------------------------ |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | मिलिसेकंदांमध्ये फ्लश मध्यांतर.            |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | फ्लश करण्यापूर्वी कमाल बफर केलेल्या नोंदी. |

खर्च अचूक प्रदाता-रिपोर्ट केलेले शुल्क (`provider_cost_usd`), नंतर कॅटलॉग-किंमत विनंती स्नॅपशॉट (`calculated_cost_usd`), त्यानंतर वर्तमान कॅटलॉगमधून टोकन पुनर्मूल्यांकनास प्राधान्य देतात. संचयित खर्च त्यांच्या टोकन संख्येद्वारे पुन्हा आकारले जात नाहीत. जेव्हा त्यांची कॅटलॉग किंमत बदलते तेव्हा केवळ लेगसी टोकन पंक्ती बदलतात.

### OCR आणि एम्बेडिंग

- यशस्वी `/v1/ocr` विनंत्या अपस्ट्रीम `usage_info.pages_processed` वापरतात, विनंती केलेली पृष्ठ श्रेणी किंवा परत केलेल्या पृष्ठ ऑब्जेक्टची संख्या नाही. अंदाज आहे पृष्ठे × `ocr_cost_per_page` (संपूर्ण USD/page,**नाही** USD/million).
- दस्तऐवज किंवा बाउंडिंग-बॉक्स भाष्यांसह विनंत्यांना स्वतंत्र `ocr_cost_per_annotated_page` टॅरिफ आवश्यक आहे. त्याशिवाय, खर्च अज्ञात राहतो; सामान्य OCR टॅरिफ शांतपणे बदलले जात नाही.
- LiteLLM सिंक त्याच्या अपस्ट्रीम `annotation_cost_per_page` फील्डला `ocr_cost_per_annotated_page` मध्ये मॅप करते, स्पष्ट शून्यासह परिपूर्ण USD/page मूल्य आणि केवळ भाष्य नोंदी राखून ठेवते. पुरवलेले प्रमाणिक क्षेत्र प्राधान्य घेते; अवैध उपनाव मूल्यांकडे दुर्लक्ष केले जाते. वापरकर्ता किंमत ओव्हरराइड्स त्यांचे सामान्य प्राधान्य कायम ठेवतात. [LiteLLM च्या OCR किंमत कळा](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) पहा.
- OCR वापर पृष्ठ संख्या, युनिट किंमत, गणना केलेली USD किंमत, API की आणि निवडलेले कनेक्शन संग्रहित करते. पृष्ठे कधीही टोकन म्हणून दर्शविली जात नाहीत. कॉल लॉगमध्ये बिलिंग मेटाडेटा आहे, दस्तऐवज URLs, PDF बाइट्स किंवा काढलेला मजकूर नाही.
- यशस्वी `/v1/embeddings` विनंत्या प्रत्येक भौतिक बॅचमध्ये एक वापर पंक्ती रेकॉर्ड करतात, त्याच मिलिसेकंदमध्ये पूर्ण केलेल्या वेगळ्या बॅचेससह. प्रदाता-अहवाल केलेले शुल्क टोकन अंदाजापेक्षा प्राधान्य घेतात; कॉम्बो रॅपर्स चार्ज जोडत नाहीत.
- वापर इतिहास, खर्च विश्लेषण, provider/account विंडो, API-की खर्च मर्यादा, विनंती-खर्च खाते आणि दैनिक वापर रोलअपमध्ये हे शुल्क समाविष्ट आहे. नो-लॉग की स्त्रोत मजकूर न ठेवता संख्यात्मक लेखांकन राखून ठेवतात.
- गहाळ वापर किंवा दर आहेत **अज्ञात** , विनामूल्य नाही: प्रतिसाद-किंमत शीर्षलेख वगळले आहे आणि विद्यमान अमूल्य-वापर धोरण मर्यादित API की वर लागू होते. स्पष्टपणे कॉन्फिगर केलेले शून्य दर वैध शून्य-खर्च वापर राहतील.

हे फक्त फॉरवर्ड अकाउंटिंग आहे. जुने OCR/embedding कॉल ज्याने कधीही वापर इतिहास लिहिला नाही ते या स्थलांतरातून पुन्हा तयार केले जाऊ शकत नाहीत. कॅटलॉग अंदाज हे USD अंदाज आहेत, बीजक नाही आणि चलन रूपांतरण, कर किंवा सूट समाविष्ट करत नाहीत.

## डॅशबोर्ड: खर्च पृष्ठ

**खर्च** पृष्ठ `/dashboard/costs` येथे आहे
(`src/app/(dashboard)/dashboard/costs/`).
त्याचे मुख्य दृश्य **खर्चाचा आढावा** टॅब आहे
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
जो `GET /api/usage/analytics` मधून सर्वकाही लोड करतो.

त्यामध्ये काय दिसते:

- **खर्च टाइल्स** — _आज (1d)_, _7d_, _30d_ आणि निवडलेल्या
  कालावधीसाठी अंदाजित खर्च. कालावधी निवडक: `7d`, `30d`, `90d`, `all`.
- **प्रमुख मेट्रिक्स** — कालावधीतील विनंत्या, सक्रिय प्रदाते, सक्रिय मॉडेल्स, प्रति
  विनंती सरासरी खर्च.
- **खर्च एक्सप्लोरर** — **प्रदाता**, **मॉडेल**,
  **API की**, **खाते** किंवा **सेवा स्तर** यानुसार गटबद्ध केलेले, क्रमवारी लावता/फिल्टर करता येणारे टेबल; यामध्ये खर्च, विनंत्या, टोकन्स, सरासरी
  खर्च/विनंती आणि एकूणातील वाटा % समाविष्ट असतो.
- **टोकन वापर** — एकूण / इनपुट / आउटपुट टोकन्स आणि इनपुट:आउटपुट गुणोत्तर.
- **राउटिंग कार्यक्षमता** — फॉलबॅक संख्या, फॉलबॅक दर आणि विनंती केलेल्या मॉडेलचे कव्हरेज.
- **मासिक अंदाज** — अलीकडील दैनिक सरासरीवरून महिनाअखेरीच्या खर्चाचा अंदाज लावतो.
- **कालावधी तुलना** — कालावधीच्या पहिल्या आणि दुसऱ्या अर्ध्यामधील % बदल.
- **चार्ट्स** — दैनिक खर्च कल, प्रदात्याचा वाटा (पाय), सर्वोच्च प्रदाते, सर्वोच्च मॉडेल्स, API
  कीनुसार खर्च, खात्यानुसार खर्च, साप्ताहिक वापर पॅटर्न आणि क्रियाकलाप हीटमॅप.
- **निर्यात** — सध्याचा कालावधी **CSV** किंवा **JSON** म्हणून डाउनलोड करा (शून्यापेक्षा जास्त खर्चाचा डेटा
  उपलब्ध झाल्यावर बटणे दिसतात).

किंमत निर्धारित केलेली ट्रॅफिक नसल्यास, `$0` ऐवजी पंक्ती "लेगसी / मोफत" लेबल म्हणून रेंडर होतात,
जे बचत-ट्रॅकर मॉडेल प्रतिबिंबित करते.

### संबंधित खर्च उपपृष्ठे

खर्च विभागामध्ये पुढील पृष्ठेदेखील आहेत (सर्व `/dashboard/costs/` अंतर्गत):

- **किंमत निर्धारण** (`/dashboard/costs/pricing`) — प्रति-मॉडेल किंमती पहा आणि ओव्हरराइड करा (सामायिक
  किंमत निर्धारण टॅब रेंडर करतो).
- **बजेट** (`/dashboard/costs/budget`) — प्रति-व्याप्ती खर्च मर्यादा सेट करा (सामायिक
  बजेट टॅब रेंडर करतो).
- **कोटा शेअर** (`/dashboard/costs/quota-share`) — सामायिक-कोटा पूल्स आणि वापर-दर
  दृश्ये.

आवश्यक आहे.

| `GET` | `/api/usage/utilization` | कालांतराने प्रति-प्रदाता कोटा वापर. क्वेरी: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                             |

## CLI

OmniRoute चे CLI खर्च, वापर आणि किंमत आदेश उपलब्ध करून देते (यांची नोंदणी
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) मध्ये केली आहे).

### `omniroute cost`

`/api/usage/analytics` मधून एकत्रित केलेला खर्च अहवाल.

```bash
omniroute cost                          # मागील 30d, प्रदात्यानुसार गटबद्ध
omniroute cost --period 7d              # मागील 7 दिवस
omniroute cost --group-by model         # provider | model | combo | api-key | day यानुसार गटबद्ध करा
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

स्तंभ: गट, विनंत्या, इनपुट/आउटपुट टोकन, खर्च (USD) आणि एकूण खर्चाची टक्केवारी. शेवटी
एकूण बेरजेची ओळ दर्शवली जाते (`--quiet` किंवा `--output json` वापरल्यास ती वगळली जाते).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # प्रत्येक प्रदात्याच्या खर्चाचा सारांश
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# बजेट
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`, `GET /api/pricing/defaults` मधून माहिती वाचते. त्याऐवजी स्वतंत्र मॉडेलच्या
> किंमती संपादित करण्यासाठी **Pricing** डॅशबोर्ड पृष्ठ किंवा `PATCH /api/pricing` वापरा.

## समस्यानिवारण

- **सर्व खर्च $0 / "Legacy / Free" असे दिसतात.** वापरात असलेल्या मॉडेलसाठी किंमतीची नोंद उपलब्ध नाही.
  बाह्य समक्रमण सक्षम करा (`PRICING_SYNC_ENABLED=true`) आणि `omniroute pricing sync` चालवा किंवा
  Pricing पृष्ठ / `PATCH /api/pricing` द्वारे किंमती व्यक्तिचलितपणे सेट करा.
- **ऐतिहासिक मॉडेलची किंमत चुकीची आहे.** किंमत दुरुस्त करा (अधिलिखित करा किंवा पुन्हा समक्रमित करा) — प्रत्येक वेळी विश्लेषण डेटा वाचताना
  टोकन संख्यांवरून खर्चाची पुनर्गणना केली जाते, त्यामुळे अंदाज पूर्वलक्षी प्रभावाने अद्ययावत होतात.
- **खर्चाची माहिती प्रत्यक्ष वेळेपेक्षा उशिराने दिसते.** प्रत्येक कीचा खर्च बॅचमध्ये प्रक्रिया केला जातो; अधिक अद्ययावत आकडे हवे असल्यास
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` चे मूल्य कमी करा.
