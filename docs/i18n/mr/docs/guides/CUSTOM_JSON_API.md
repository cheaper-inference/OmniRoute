सानुकूल JSON API नोड JSON बिझनेस एंडपॉइंटला जोडतो जो OpenAI किंवा Anthropic प्रोटोकॉल बोलत नाही. OmniRoute एक JSON विनंती टेम्प्लेट भरते, ते पूर्ण एंडपॉइंट URL वर पाठवते, प्रतिसाद मार्गावरून उत्तर वाचते आणि क्लायंटच्या स्वतःच्या स्वरूपात (चॅट पूर्णता, प्रतिसाद, संदेश, ...) क्लायंटला परत करते.

हे `apiType: "custom-json"` सह OpenAI- सुसंगत नोड आहे; त्याच्या id मध्ये `openai-compatible-custom-json-<suffix>` फॉर्म आहे. डॅशबोर्ड फॉर्म अद्याप उपलब्ध नाही. खालील प्रदाता-नोड API द्वारे हे नोड्स तयार करा आणि संपादित करा.

## एक नोड तयार करा

`POST /api/provider-nodes` (व्यवस्थापन प्रमाणीकरण):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` आहे** पूर्ण** एंडपॉइंट URL काहीही जोडलेले नाही ( `/chat/completions` नाही, `/models` नाही) आणि इतर OpenAI- सुसंगत नोड्सच्या विपरीत, कोणतेही डीफॉल्ट URL नाही. हे एम्बेडेड क्रेडेन्शियल किंवा `#fragment` शिवाय `http(s)` असणे आवश्यक आहे आणि ते प्रत्येक प्रदाता नोड प्रमाणेच आउटबाउंड URL गार्ड पास करते, जेव्हा नोड जतन केला जातो आणि प्रत्येक विनंतीवर दोन्ही.
- कनेक्शन की पाठवणारा नोड (`authType` `bearer` किंवा `api-key`, डीफॉल्टसह) `https://` वापरणे आवश्यक आहे. प्लेन `http://` फक्त लूपबॅक होस्टसाठी (`localhost`, `127.0.0.0/8`, `::1`) किंवा `authType: "none"` सह स्वीकारले जाते, जे कोणतीही कळ पाठवत नाही. खाजगी LAN पत्ते (`10.x`, `172.16-31.x`, `192.168.x`) मुक्त नाहीत: त्या नेटवर्कवरील कोणीही की वाचू शकते. असा नोड जतन करणे `400` सह अयशस्वी होते, आणि आधी संग्रहित नोड अयशस्वी प्रत्येक विनंतीवर समान संदेशासह, कोणतीही विनंती पाठवण्यापूर्वी बंद होते. LAN वरील कीड एंडपॉइंटसाठी, TLS च्या मागे ठेवा (उदाहरणार्थ रिव्हर्स प्रॉक्सी).
- `customJson` Zod सह प्रमाणित आहे; अज्ञात कळा नाकारल्या जातात. प्रत्येक फील्ड पर्यायी आहे:

| फील्ड             | मूल्ये                                  | डीफॉल्ट                                                |
| ----------------- | --------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                  | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`             | `bearer`                                               |
| `authHeader`      | हेडरचे नाव `api-key` तेव्हा वापरले जाते | `X-API-Key`                                            |
| `requestTemplate` | JSON ऑब्जेक्ट (≤ 64 KB, खोली ≤ 32)      | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | फील्ड पथ, किंवा संपूर्ण शरीरासाठी `$`   | `choices[0].message.content`                           |

- हे रहस्य कनेक्शनच्या API की मध्ये राहते, कधीही टेम्पलेटमध्ये नसते. `bearer` `Authorization: Bearer <key>` पाठवते; `api-key` `<authHeader>: <key>` पाठवते. प्रमाणीकरण शीर्षलेख `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` किंवा हॉप-बाय-हॉप शीर्षलेख असू शकत नाही. `none` सह, कनेक्शनला किल्लीची आवश्यकता नाही.
- अतिरिक्त स्थिर शीर्षलेख नोडचे नियमित `customHeaders` वापरतात (प्रत्येक इतर सुसंगत नोड प्रमाणेच प्रमाणीकरण; तेथे ऑथ हेडरला परवानगी नाही).

`PUT /api/provider-nodes/<id>` समान `customJson` स्वीकारतो आणि नोडच्या प्रत्येक विद्यमान कनेक्शनवर `baseUrl` आणि कॉन्फिगरेशन पुन्हा लिहितो. `customJson` वगळल्याने संग्रहित कॉन्फिगरेशन राहते; `apiType` ला `chat` किंवा `responses` स्विच केल्याने ते नोड आणि त्याच्या कनेक्शनमधून काढून टाकले जाते.

नंतर नेहमीप्रमाणे नोडला कनेक्शन जोडा (नोड आयडीसह `POST /api/providers` ) आणि `<prefix>/<model>` विनंती करा, उदाहरणार्थ `biz/assistant-v1`. एंडपॉइंट कोणतीही मॉडेल सूची उघड करत नाही, म्हणून मॉडेल आयडी हाताने जोडा.

## टेम्पलेट्सची विनंती करा

साचे साधे JSON आहेत. स्ट्रिंग मूल्यामध्ये `{{placeholder}}` मार्कर असू शकतात; काहीही मूल्यमापन किंवा कार्यान्वित केले जात नाही आणि ऑब्जेक्ट की कधीही बदलल्या जात नाहीत.

| प्लेसहोल्डर          | मूल्य                                                           |
| -------------------- | --------------------------------------------------------------- |
| `{{prompt}}`         | नवीनतम वापरकर्ता संदेशाचा मजकूर (मजकूर भाग नवीन ओळींसह जोडलेले) |
| `{{messages}}`       | OpenAI चॅट स्वरूपात संभाषण                                      |
| `{{model}}`          | विनंती केलेला मॉडेल आयडी, प्रदाता उपसर्गाशिवाय                  |
| `{{stream}}`         | नेहमी `false` — एंडपॉइंटची उत्तरे एका JSON दस्तऐवजासह द्या      |
| `{{request.<path>}}` | भाषांतरित (OpenAI चॅट स्वरूप) विनंतीचे फील्ड                    |

- अगदी एक प्लेसहोल्डर असलेले मूल्य त्याचा JSON प्रकार ठेवते (`"{{messages}}"` ॲरे बनते); लांब स्ट्रिंगमधील प्लेसहोल्डर मजकूर म्हणून घातला जातो.
- एक प्लेसहोल्डर जो काहीही निराकरण करत नाही तो अपूर्ण पेलोड पाठवण्याऐवजी HTTP 400 सह विनंती अयशस्वी करतो.
- पथ डॉट नोटेशन आणि अंकीय निर्देशांक (`data.items[0].text`) वापरतात. `__proto__`, `prototype` आणि `constructor` की आणि पथांमध्ये नाकारले जातात.

## प्रतिसाद

`responsePath` वरील मूल्य हे सहाय्यक प्रत्युत्तर बनते: स्ट्रिंग्स पास होतात, इतर JSON व्हॅल्यू अनुक्रमित केल्या जातात. गहाळ किंवा `null` फील्ड, किंवा JSON नसलेली बॉडी, HTTP 502 परत करते. अपस्ट्रीम त्रुटी स्थिती पार केल्या जातात. स्ट्रीमिंग क्लायंटसाठी OmniRoute संपूर्ण JSON प्रतिसादाची वाट पाहते आणि नंतर एक सामग्री भाग आणि फिनिश भाग म्हणून ते उत्सर्जित करते; हे टोकन स्ट्रीमिंग नाही. टूल कॉल आणि वापर फील्ड मॅप केलेले नाहीत.

## कधीही रिप्ले केले नाही

बिझनेस रिक्वेस्ट अयशस्वी झाली तरीही त्याचे दुष्परिणाम होऊ शकतात. म्हणून OmniRoute ते एकदा पाठवते:

- वाहतूक पुन्हा प्रयत्न नाही आणि कोणतेही पुनर्निर्देशन खालील नाही;
- दुसऱ्या कनेक्शनवर पुन्हा प्रयत्न करू नका (खाते फॉलबॅक) — अपयश जसे आहे तसे परत केले जाते आणि कनेक्शन थंड केले जात नाही;
- रिकाम्या किंवा अयशस्वी प्रत्युत्तरासाठीही पुढील कॉम्बो टार्गेटवर फॉलबॅक नाही.

विभक्त क्लायंट विनंत्या, आणि फ्यूजन पॅनेल जे स्पष्टपणे अनेक मॉडेल्सला कॉल करतात, तरीही स्वतंत्रपणे एंडपॉइंटची विनंती करतात.

## नोडची चाचणी करत आहे

कनेक्शन, कनेक्शन जतन करणे** चाचणी** बटण आणि बॅकग्राउंड हेल्थ चेक कधीही एंडपॉईंटला कॉल करत नाहीत: ते फक्त स्टोअर केलेल्या कॉन्फिगरेशनची पडताळणी करतात आणि कनेक्शनची पडताळणी करण्यायोग्य नसल्याचा अहवाल देतात.

`POST /api/provider-nodes/validate` सह `"apiType": "custom-json"` आणि नोड फील्ड (`baseUrl`, `apiKey`, `customJson`, पर्यायी `customHeaders` आणि `modelId`) अगदी एक वास्तविक विनंती पाठवते, `ping` नवीनतम वापरकर्ता मजकूर म्हणून. हे `{ "valid": true }` किंवा अपस्ट्रीम स्थितीचे उत्तर देते (कधीही अपस्ट्रीम बॉडी नाही).

## स्टोरेज

कॉन्फिगरेशन `provider_nodes.custom_json_config_json` (माइग्रेशन `240_provider_node_custom_json_config.sql`) मध्ये संग्रहित केले जाते आणि प्रत्येक कनेक्शनच्या `providerSpecificData.customJson` मध्ये कॉपी केले जाते.

अंमलबजावणी: `open-sse/utils/customJson.ts` (प्रमाणीकरण आणि टेम्प्लेटिंग), `open-sse/executors/customJson.ts` (एक्झिक्युटर), `open-sse/services/combo/noReplayLatch.ts` आणि `src/sse/handlers/chat/responsePolicies.ts` (नो-रीप्ले).
