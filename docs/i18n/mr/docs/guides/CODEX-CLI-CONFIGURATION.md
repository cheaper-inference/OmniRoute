OpenAI-सुसंगत बॅकएंड म्हणून OmniRoute कडे निर्देशित केलेला Codex CLI वापरण्यासाठी संपूर्ण मार्गदर्शक.

---

> **TOML हे एकमेव प्रभावी स्वरूप आहे.** आधुनिक Codex केवळ `~/.codex/config.toml`
> वाचतो (codex-cli 0.147.0 सह पडताळलेले: `codex --help` मध्ये
> `-c/--config` अधिलिखित मूल्ये "`~/.codex/config.toml` मधून लोड केली जातात" असे नमूद केले आहे). जुनी
> `~/.codex/config.yaml` फाइल लेगसी npm CLI ची होती आणि तिच्याकडे कोणतीही सूचना न देता दुर्लक्ष केले जाते.
> डॅशबोर्ड जनरेटर (`/api/cli-tools/apply`, साधन `codex`) सावधगिरीने विलीनीकरण करून TOML लिहितो —
> विद्यमान की आणि इतर प्रदाता ब्लॉक जतन केले जातात,
> API की `OMNIROUTE_API_KEY` मध्येच राहते (फाइलमध्ये कधीही नाही), आणि उरलेली लेगसी
> `config.yaml` फाइल न बदलता स्थलांतर नोंद म्हणून दर्शवली जाते.

## थेट पेस्ट करण्यासाठी तयार config.toml

`<YOUR_HOST>` आणि `<YOUR_KEY>` यांच्या जागी तुमची मूल्ये वापरा:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # प्रत्येक साधन कॉलसाठी इतिहास संचयनाची कमाल मर्यादा

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc किंवा ~/.zshrc — प्रत्यक्ष की मूल्य, config.toml मध्ये कधीही नाही
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: ChatGPT अॅपमध्ये समाविष्ट केलेला Codex

तुम्ही ChatGPT डेस्कटॉप अॅपद्वारे Codex स्थापित केला असल्यास, `codex` बायनरी
केवळ अॅप बंडलमध्ये असू शकते आणि अद्याप तुमच्या शेल `PATH` मध्ये नसू शकते. तुमच्या
शेल स्टार्टअप फाइलमध्ये रिसोर्सेस डायरेक्टरी जोडा:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

नवीन शेल उघडा आणि नंतर पडताळा:

```bash
command -v codex
codex --version
```

### प्रमाणीकरण नसलेला स्थानिक OmniRoute: प्लेसहोल्डर की पुरेशी आहे

पहिली विनंती CLI मधून बाहेर जाण्यापूर्वीच `env_key` ने निर्दिष्ट केलेले
एन्व्हायर्नमेंट व्हेरिएबल अस्तित्वात आहे की नाही, हे Codex तपासतो.
तुमच्या **स्थानिक** OmniRoute इन्स्टन्सला प्रमाणीकरणाची आवश्यकता नसल्यास,
कोणतेही रिक्त नसलेले प्लेसहोल्डर चालेल:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

तुमचा OmniRoute सर्व्हर संरक्षित किंवा दूरस्थ असल्यास त्याऐवजी खरी की वापरा.

> **सामान्य होस्ट पर्याय**
>
> | प्रवेश          | URL                           |
> | --------------- | ----------------------------- |
> | स्थानिक नेटवर्क | `http://192.168.0.1:20128/v1` |
> | Tailscale       | `http://100.x.x.x:20128/v1`   |
> | लूपबॅक          | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — ते सर्व मॉडेलसाठी का कार्य करते

Codex CLI ने फेब्रुवारी 2026 मध्ये `wire_api = "chat"` (Chat Completions) कालबाह्य केले आणि आता `wire_api = "responses"` (OpenAI Responses API) **आवश्यक** आहे. v0.138 पासून `wire_api = "chat"` सेट केल्यास स्टार्टअपच्या वेळी त्वरित क्रॅश होते.

GLM आणि Kimi यांच्यासह अनेक प्रदाते अजूनही फक्त Chat Completions एंडपॉइंट उपलब्ध करतात. DeepSeek V4 आता मूळ Responses API तसेच Anthropic-सुसंगत एंडपॉइंट उपलब्ध करतो; OmniRoute डीफॉल्टनुसार Responses वापरतो आणि प्रत्येक DeepSeek कनेक्शनला Anthropic सुसंगतता निवडण्याची अनुमती देतो.

**OmniRoute हे पारदर्शकपणे हाताळतो:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute प्रदात्याचा मूळ प्रोटोकॉल निवडतो आणि आवश्यकतेनुसार भाषांतर करतो
    → POST /responses (DeepSeek V4) किंवा /chat/completions (Mistral / GLM / Kimi / इतर)
```

OmniRoute वापरताना तुम्हाला स्वतंत्र भाषांतर प्रॉक्सीची कधीही आवश्यकता नसते. **सर्व मॉडेल `wire_api = "responses"` वापरतात** — उर्वरित सर्वकाही OmniRoute हाताळतो.

> **`wire_api` हे डीफॉल्ट आहे** — या फील्डचे डीफॉल्ट मूल्य `"responses"` आहे आणि ते `config.toml` मधून पूर्णपणे वगळता येते. हेतूचे दस्तऐवजीकरण करायचे असल्यासच ते स्पष्टपणे सेट करा.

## संदर्भ विंडो आणि संक्षेपण

### टोकन कॉन्फिगरेशन फील्ड

| फील्ड                            | वर्णन                                                                                                                                                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `model_context_window`           | सक्रिय मॉडेलसाठी एकूण टोकन मर्यादा. मॉडेलच्या घोषित मर्यादेवर सेट करा.                                                                                                                                                   |
| `model_auto_compact_token_limit` | स्वयंचलित इतिहास संक्षेपण सुरू करणारी मर्यादा. **कमाल: `model_context_window`च्या 90%** — 90% पेक्षा जास्त मूल्ये कोणतीही सूचना न देता दुर्लक्षित केली जातात.                                                            |
| `tool_output_token_limit`        | इतिहासात प्रत्येक टूल कॉलच्या आउटपुटसाठी संग्रहित केल्या जाणाऱ्या टोकनची कमाल मर्यादा. एकाच मोठ्या टूल प्रतिसादामुळे संपूर्ण विंडो भरली जाणे टाळते. **ही कमाल आउटपुट मर्यादा नाही** — ही इतिहासातील संग्रहण मर्यादा आहे. |
| `compact_prompt`                 | संक्षेपणादरम्यान वापरल्या जाणाऱ्या सिस्टम प्रॉम्प्टसाठी इनलाइन ओव्हरराइड (v0.138+).                                                                                                                                      |

> **`model_max_output_tokens` विषयी नोंद**: हे फील्ड **Codex CLI कॉन्फिग स्कीमाचा भाग नाही** (Codex Rust कोडबेसमध्ये अनुपस्थित). ते सेट केले असल्यास कोणतीही सूचना न देता दुर्लक्षित केले जाते. त्यावर अवलंबून राहू नका — इतिहासात किती टूल आउटपुट संग्रहित केले जाईल हे नियंत्रित करण्यासाठी `tool_output_token_limit` वापरा.

## तर्कशक्तीचा प्रयत्न

प्रतिसाद देण्यापूर्वी मॉडेल किती "विचार" करते हे नियंत्रित करते.

| मूल्य    | यासाठी वापरा                                      |
| -------- | ------------------------------------------------- |
| `none`   | तर्कशक्ती नाही — थेट प्रतिसाद                     |
| `low`    | किरकोळ कार्ये (नामांतर, स्वरूपन)                  |
| `medium` | निर्दिष्ट न केल्यास **सर्व्हर डीफॉल्ट**           |
| `high`   | मध्यम स्तरावरील कार्ये (रिफॅक्टरिंग, डीबग)        |
| `xhigh`  | आर्किटेक्चर, सखोल विश्लेषण, गुंतागुंतीच्या समस्या |

```bash
# प्रत्येक आवाहनासाठी ओव्हरराइड
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Desktop केवळ एन्क्रिप्ट केलेले ब्लॉब्स न दाखवता विचारांचा मजकूर रेंडर करू शकेल यासाठी तर्कशक्तीचा **सारांश** देखील सेट करा:

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # किंवा समर्थित असताना ultra
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute विचार बजेट (सर्व्हर सेटिंग)

OmniRoute होस्टवर, Codex चा प्रयत्न/सारांश अपस्ट्रीमपर्यंत पोहोचण्यासाठी **Settings → AI → Thinking Budget** हे **`passthrough`** असणे आवश्यक आहे. **`auto` मोड** सर्व क्लायंट `reasoning` / `reasoning_effort` फील्ड्स काढून टाकतो आणि Codex योग्यरीत्या कॉन्फिगर केलेले असतानाही विचार पॅनेल्स रिकामे ठेवतो.

संपूर्ण मार्गदर्शक: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

कॉम्प्रेशन आणि प्रॉम्प्ट कॅश स्वतंत्र आहेत आणि `passthrough` अंतर्गत कार्यरत राहतात.

## प्रोफाइल्स — प्रत्येक मॉडेल/वर्कफ्लोसाठी नामांकित कॉन्फिगरेशन्स

प्रोफाइल्समुळे तुम्ही एका फ्लॅगने मॉडेल + कॉन्टेक्स्ट विंडो बदलू शकता. प्रत्येक प्रोफाइल ही एक सपाट
`~/.codex/<name>.config.toml` फाइल असते, जी मूलभूत `config.toml` वर ओव्हरले केली जाते.

> **नामकरण नियम (Codex CLI v0.137+):** फाइल `~/.codex/<name>.config.toml` असली पाहिजे — **`profile-` उपसर्ग नसावा**.
> CLI `-p kimi-k27` → `~/.codex/kimi-k27.config.toml` असे निराकरण करते. फाइल न सापडल्यास, डीफॉल्ट कोणतीही सूचना न देता लागू होते.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # जलद, स्वस्त
```

## `omniroute setup-codex` वापरून प्रोफाइल आपोआप तयार करणे

तुम्ही OmniRoute हे VPS वर चालवत असल्यास, सध्या उपलब्ध असलेल्या मॉडेल कॅटलॉगवरून प्रोफाइल फाइल्स आपोआप तयार करू शकता:

```bash
# VPS वरून (पोर्ट 20128 वरील स्थानिक OmniRoute वापरते)
omniroute setup-codex

# कोणत्याही मशीनवरून — तुमच्या VPS कडे निर्देशित करा
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# फाइल्स न लिहिता पूर्वावलोकन करा
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# केवळ GLM आणि Kimi प्रोफाइल तयार करा
omniroute setup-codex --only glm,kimi

# सानुकूल डिरेक्टरीमध्ये लिहा
omniroute setup-codex --codex-home /path/to/.codex
```

हा आदेश `/v1/models` प्राप्त करतो, ज्ञात मॉडेल्ससाठी अनुकूलित प्रोफाइल वापरतो, इतर सुसंगत मजकूर मॉडेल्ससाठी कॅटलॉग मेटाडेटाचा पर्याय म्हणून वापर करतो आणि प्रत्येकासाठी `~/.codex/<name>.config.toml` लिहितो. ही प्रक्रिया आयडेम्पोटंट आहे — ती पुन्हा चालवणे सुरक्षित आहे.

मूळ `config.toml` मध्ये `model_providers.omniroute` ची व्याख्या नसल्यास, स्पष्टपणे चालवलेले
`setup-codex` निवडलेल्या स्थानिक किंवा रिमोट एंडपॉइंटचा वापर करून, तयार केलेल्या प्रत्येक ओव्हरलेमध्ये ती व्याख्या समाविष्ट करते.
मूळ फाइलमध्ये कोणताही बदल केला जात नाही. अस्तित्वात असलेली प्रोव्हायडर
व्याख्या तिच्या एंडपॉइंट आणि प्रमाणीकरण सेटिंग्जसह वारशाने घेतली जाते. मूळ TOML अवैध असल्यास,
प्रोफाइल लिहिण्यापूर्वी निर्मिती थांबते.

तुम्ही `--api-key` किंवा `OMNIROUTE_API_KEY` दिल्यास, नव्याने परिभाषित केलेला प्रोव्हायडर
`env_key = "OMNIROUTE_API_KEY"` चा संदर्भ घेतो; की स्वतः कधीही जतन केली जात नाही किंवा
पूर्वावलोकनात दाखवली जात नाही. ज्या वातावरणातून तुम्ही Codex सुरू करता, तेथे हे व्हेरिएबल सेट करा.
की न दिल्यास, प्रमाणीकरण नसलेल्या विनंत्या स्वीकारण्यासाठी कॉन्फिगर केलेल्या OmniRoute इंस्टन्ससाठी,
नवीन व्याख्येमध्ये कीची आवश्यकता नसते.

खाली वर्णन केलेले ऐच्छिक कॅटलॉग ऑटो-सिंक, ओव्हरलेमध्ये आधीपासून असलेल्या प्रोव्हायडर व्याख्या
जतन करते; मात्र ते नवीन प्रोव्हायडर सेटिंग्जचे बूटस्ट्रॅपिंग करत नाही. प्रथम स्पष्ट सेटअप किंवा
डॅशबोर्ड वापरून प्रोव्हायडर कॉन्फिगर करा. अस्तित्वात असलेल्या प्रोव्हायडर सेटिंग्ज
ड्राय-रन पूर्वावलोकनातून वगळल्या जातात, कारण त्यामध्ये ऑपरेटरद्वारे व्यवस्थापित क्रेडेन्शियल्स असू शकतात.

प्रोव्हायडर मॉडेलचे यशस्वी डिस्कव्हरी/इम्पोर्ट झाल्यानंतर सध्याचा कॅटलॉग बदलल्यास, OmniRoute याच प्रोफाइल फाइल्सना **आपोआप सिंक** देखील करू शकते. हे **ऐच्छिक असून डीफॉल्टनुसार बंद असते**: ते **CLI Code डॅशबोर्ड**मधून ("CLI प्रोफाइल ऑटो-सिंक" → Codex) सुरू करा किंवा `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` सेट करा (`CLI_ALLOW_CONFIG_WRITES` चाही आदर केला जातो, जे डीफॉल्टनुसार सुरू असते). सक्षम केल्यावर ते केवळ स्वतंत्र `~/.codex/*.config.toml` प्रोफाइल फाइल्स लिहिते; सक्रिय/डीफॉल्ट `~/.codex/config.toml`, Codex-lb सेटिंग्ज, प्रमाणीकरण किंवा प्रोव्हायडर निवड यात ते कधीही बदल करत नाही.

## `omniroute launch-codex` वापरून Codex सुरू करणे

Codex सुरू करण्यापूर्वी तुमच्या OmniRoute इंस्टन्सची आरोग्य-तपासणी करते:

# स्थानिक OmniRoute विरुद्ध सुरू करा (डीफॉल्ट पोर्ट 20128)

Codex हे दोन सर्वसाधारण मॅनिफेस्ट-आधारित प्रवेशबिंदूंचेदेखील लक्ष्य आहे

omniroute configure codex

# -c फ्लॅगद्वारे omniroute प्रदाता अंतःक्षेपित करून codex सुरू करा (कोणतेही कॉन्फिग लिहिले जात नाही)

## दीर्घकाळ चालणारी कामे

दोन OmniRoute डीफॉल्ट बहु-तास Codex CLI सत्र शांतपणे तोडफोड करू शकतात. दोन्हीपैकी एक Codex CLI सेटिंग — दोन्ही OmniRoute बाजूला राहतात. खाती पिन करणारे आणि निष्क्रिय कटऑफ अक्षम करणारे अपस्ट्रीम प्रॉक्सीमधून कॉन्फिगचे स्थलांतर करणारे वापरकर्ते अनेकदा दोन्हीवर परिणाम करतात आणि OmniRoute "दीर्घ सत्र टिकवून ठेवू शकत नाही" असा निष्कर्ष काढतात.

| लक्षण                                                                      | संभाव्य कारण                                                      | नॉब                      |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------ |
| सत्र खाते बदलत राहते / वळणांच्या दरम्यान प्रॉम्प्ट-कॅशे सातत्य गमावले जाते | सेशन ॲफिनिटी TTL `0` आहे (अक्षम)                                  | `sessionAffinityTtlMs`   |
| क्लायंट-फेसिंग प्रॉम्प्टशिवाय कनेक्शन मध्य-तर्कवादाने मरते                 | स्ट्रीम निष्क्रिय वॉचडॉग 10 मिनिटांनंतर अपस्ट्रीम भागाशिवाय उडाला | `STREAM_IDLE_TIMEOUT_MS` |

संबंधित चर्चा: [#7126](https://github.com/cheaper-inference/OmniRoute/discussions/7126) (लाँग टास्क ड्रॉप्स), [#5718](https://github.com/cheaper-inference/OmniRoute/discussions/5718) (ॲफिनिटी डीफॉल्ट का बंद आहे). ट्रॅकिंग: [#7287](https://github.com/cheaper-inference/OmniRoute/issues/7287).

### 1. सेशन ॲफिनिटी — एका खात्यावर एक संभाषण पिन करा

**डीफॉल्ट:** `sessionAffinityTtlMs = 0` (अक्षम).

**ते कुठे सेट करायचे**

- डॅशबोर्ड →** सेटिंग्ज → राउटिंग** →** सत्र आत्मीयता** →** आत्मीयता TTL (सेकंद)** (`ComboDefaultsTab`)
- किंवा `sessionAffinityTtlMs` in सह PATCH सेटिंग्ज** मिलीसेकंद** (Zod श्रेणी `0`–`86_400_000`, म्हणजे 24 तासांपर्यंत)

> कोडेक्स-केवळ `codexSessionAffinityTtlMs` वरून #7274 मध्ये पुनर्नामित केले. लेगसी की अजूनही केवळ वाचनीय उपनाव म्हणून स्वीकारली जाते; नवीन कॉन्फिगने `sessionAffinityTtlMs` वापर केला पाहिजे. आत्मीयता आता लागू होते** कोणतेही** एकदा TTL `0` वर आला की प्रदाता, फक्त Codex — नाही [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → सत्राची आत्मीयता पहा.

**० वर राहिल्यावर काय तुटते**

मल्टी-टर्न Codex संभाषणाचे प्रत्येक वळण सक्रिय कॉम्बो रणनीतीद्वारे स्वतंत्रपणे मार्गस्थ केले जाते आणि त्यावर उतरू शकते** प्रत्येक वळणावर भिन्न खाते** . ते अपस्ट्रीम सत्र / प्रॉम्प्ट-कॅशे सातत्य खंडित करते. OmniRoute फक्त Codex सत्र शीर्षलेख (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) आणि `prompt_cache_key` / `session_id` सारख्या मुख्य भागांचा सल्ला घेते जेव्हा TTL `0` ( `src/sse/services/auth.ts` मध्ये`extractSessionAffinityKey` ) पेक्षा मोठा असतो.

**बहु-तास सिंगल टास्कसाठी शिफारस केली**

TTL सेट करा** टास्कच्या अपेक्षित भिंत-घड्याळ लांबीच्या वर** (UI कमाल आहे** 86400 सेकंद** = 24 तास):

| अपेक्षित कार्य लांबी | आत्मीयता TTL (UI, सेकंद) | `sessionAffinityTtlMs` |
| -------------------- | ------------------------ | ---------------------- |
| काही तास             | `14400` (4h)             | `14400000`             |
| रात्रभर / ~ 12h      | `43200` (12h)            | `43200000`             |
| पूर्ण दिवस           | `86400` (24 तास, कमाल)   | `86400000`             |

निवड करणे जाणूनबुजून केले जाते: ॲफिनिटी अक्षम केल्याने खात्यांमध्ये लोड-बॅलन्सिंग होते; ते सक्षम केल्याने एका दीर्घ एजंट सत्रासाठी सातत्य राहते. हे मार्गदर्शक करते** नाही** लांब Codex कार्ये चालवणारे डीफॉल्ट — ऑपरेटर बदलणे आवश्यक आहे.

### 2. प्रवाह निष्क्रिय कालबाह्य — शांत तर्क वळण मारू नका

**डीफॉल्ट:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 मिनिटे). सेट केलेले नसताना ते `REQUEST_TIMEOUT_MS` कडून वारशाने मिळते; सामायिक आधाररेखा देखील 600000 आहे. [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → टाइमआउट्स पहा.

**डीफॉल्टवर काय ब्रेक होते**

एक Codex तर्क / साधन वळण जे 10 मिनिटांपेक्षा जास्त काळ शांत राहते** वास्तविक अपस्ट्रीम भाग नाही** SSE निष्क्रिय वॉचडॉग (`open-sse/utils/stream.ts`) द्वारे सक्तीने बंद केले आहे. क्लायंटला बऱ्याचदा बेअर कनेक्शन ड्रॉप — जुळणारे "कोणत्याही सूचनेशिवाय स्वयंचलितपणे थांबलेले" दिसते.

गंभीर तपशील: OmniRoute चे सिंथेटिक SSE** हृदयाचा ठोका रीसेट होत नाही** निष्क्रिय घड्याळ. फक्त एक वास्तविक अपस्ट्रीम बॉडी भाग `lastChunkTime` अद्यतनित करतो. एक शांत मॉडेल जे अजूनही “विचार” करत आहे ते वॉचडॉगच्या दृष्टिकोनातून थांबलेल्या अपस्ट्रीमसारखेच दिसते.

संबंधित Undici शरीर निष्क्रियता: `FETCH_BODY_TIMEOUT_MS` (त्याच 10-मिनिटांच्या बेसलाइनवर देखील डीफॉल्ट; `0` ते अक्षम करते). प्रवाहासाठी, `FETCH_TIMEOUT_MS` फक्त कनेक्शन सेटअप / प्रथम शीर्षलेख — कव्हर करते एकदा प्रवाह सक्रिय झाल्यानंतर, स्टॉल `STREAM_IDLE_TIMEOUT_MS` आणि `FETCH_BODY_TIMEOUT_MS` द्वारे नियंत्रित केले जातात.

**बहु-तास सिंगल टास्कसाठी शिफारस केली**

OmniRoute प्रक्रिया वातावरणात (`.env` / compose / systemd):

```bash
# Disable stream idle + body inactivity cutoffs for long reasoning turns
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

किंवा त्यांना तुम्ही अपेक्षित असलेल्या सर्वात लांब शांत अंतराच्या वर वाढवा (मूल्ये मिलीसेकंद आहेत):

```bash
# Example: allow up to 2 hours of silence between upstream chunks
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

या env vars बदलल्यानंतर OmniRoute रीस्टार्ट करा.

### कंक्रीट रेसिपी — मल्टी-अवर Codex टास्क

1. **खाते पिन करा:** डॅशबोर्ड → सेटिंग्ज → राउटिंग → सेशन ऍफिनिटी → ऍफिनिटी TTL = `43200` (12h) किंवा `86400` (24h कमाल).
2. **निष्क्रिय कटऑफ वाढवा / अक्षम करा** OmniRoute च्या वातावरणात:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. नेहमीच्या Codex `config.toml` (`wire_api = "responses"`, योग्य `base_url`, `OMNIROUTE_API_KEY`) — ठेवा या दोन वर्तनांसाठी कोडेक्स-साइड affinity/idle नॉब अस्तित्वात नाहीत.
4. OmniRoute रीस्टार्ट करा, नंतर लांब Codex टास्क सुरू करा.

### डीफॉल्ट निर्णय (#7287)

| नॉब                      | जहाज डीफॉल्ट     | या मार्गदर्शकामध्ये बदल?                                                                           |
| ------------------------ | ---------------- | -------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (बंद)        | **नाही** — ऑप्ट-इन राहते (लोड-बॅलन्सिंग विरुद्ध सातत्य; चर्चा #5718 पहा)                           |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 मि) | **नाही** सामान्य रहदारीसाठी — 10 मिनिटे शिल्लक आहे; लाँग Codex ऑपरेटर ते वाढवतात किंवा अक्षम करतात |

जागतिक स्तरावर एकतर डीफॉल्ट फ्लिप केल्याने केवळ Codex नव्हे तर प्रत्येक क्लायंटचे वर्तन बदलेल. knobs दस्तऐवजीकरण; स्पष्ट ऑपरेटर निर्णय अन्यथा सांगेपर्यंत डीफॉल्ट एकटे सोडा.

### निष्क्रिय कटांचे निदान करणे

जेव्हा निष्क्रिय वॉचडॉग फायर करतो, तेव्हा OmniRoute अशा आकाराची एक ओळ लॉग करते:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

`Idle timeout: no data from` साठी ग्रेप (किंवा कोड `stream_idle_timeout` / त्रुटी नाव `StreamIdleTimeoutError`). प्रदाता विभाग हा त्या विनंतीसाठी वापरला जाणारा OmniRoute आहे (`codex`, दुसरा प्रदाता id, किंवा `provider` अज्ञात असल्यास) — तो नेहमीच शाब्दिक स्ट्रिंग `codex` नसतो.

## समस्यानिवारण

**`Error: wire_api = "chat" is no longer supported`** तुमच्या कॉन्फिगरेशनमधून `wire_api = "chat"` काढा. `wire_api = "responses"` सेट करा किंवा फील्ड वगळा (v0.138 पासून `"responses"` वर डीफॉल्ट).

**`Error: model not found`** योग्य उपसर्गासह OmniRoute मध्ये मॉडेल अस्तित्वात असल्याचे सत्यापित करा. `omniroute models list` वापरा किंवा `/dashboard/providers/<provider>` उघडा.

**`Authentication error`** `OMNIROUTE_API_KEY` निर्यात केल्याची पुष्टी करा: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`** Codex प्रथम विनंती करण्यापूर्वी env var अस्तित्वात असल्याचे सत्यापित करते. संरक्षित सर्व्हरसाठी वास्तविक की निर्यात करा किंवा `OMNIROUTE_API_KEY=local` सारखे रिक्त नसलेले प्लेसहोल्डर जेव्हा** स्थानिक** OmniRoute उदाहरणासाठी प्रमाणीकरण आवश्यक नाही. तुम्ही `~/.bashrc` किंवा `~/.zshrc` मध्ये शेल जोडल्यास ते रीस्टार्ट करा.

**`Connection refused`** OmniRoute चालू आहे आणि `base_url` host/port तुमच्या नेटवर्कसाठी योग्य आहे याची पडताळणी करा (स्थानिक वि Tailscale vs VPS).

**संदर्भ मर्यादेजवळ सत्र क्रॅश झाले** `model_context_window` आणि `model_auto_compact_token_limit` स्पष्टपणे सेट करा. वरील संदर्भ विंडो सारणी पहा.

**कॉम्पॅक्शन खूप उशीर होतो** विंडोच्या 80-85% पर्यंत `model_auto_compact_token_limit` कमी करा. कधीही 90% च्या वर सेट करू नका.

**प्रोफाइल लोड होत नाही (`-p <name>` शांतपणे दुर्लक्षित)** फाइल `~/.codex/<name>.config.toml` वर अस्तित्वात असल्याची पुष्टी करा ( `profile-` उपसर्ग नाही). `ls ~/.codex/*.config.toml` चालवा.

**लाँग Codex टास्क मिड-रन सोडते / वळणांमध्ये खाते बदलते** [दीर्घकाळ चालणारी कार्ये](#long-running-tasks) पहा. सेशन ॲफिनिटी सक्षम करा ( टास्क लांबीच्या वर TTL ) आणि `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS` वाढवा किंवा अक्षम करा. Grep OmniRoute `Idle timeout: no data from` साठी लॉग.
