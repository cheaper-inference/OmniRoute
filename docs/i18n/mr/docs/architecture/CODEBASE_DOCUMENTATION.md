ही फाइल **आज रिपॉझिटरीमध्ये काय अस्तित्वात आहे** याचे वर्णन करते, जेणेकरून नवीन अभियंता
ट्रीमध्ये मार्गक्रमण करू शकेल, रनटाइमचे स्तर समजू शकेल आणि नवीन मॉड्यूल्स तयार न करता
कोड कुठे जोडायचा हे जाणून घेऊ शकेल.

## 1. तंत्रज्ञान संचय (Tech Stack)

| विषय            | निवड                                                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------------------------- |
| वेब फ्रेमवर्क   | **Next.js 16** (App Router, standalone आउटपुट, ग्लोबल मिडलवेअर नाही)                                                    |
| भाषा            | **TypeScript 6.0+** — लक्ष्य `ES2022`, `module: esnext`, `moduleResolution: bundler`, `strict: false`                   |
| रनटाइम          | **Node.js** `>=22.22.2 <23` किंवा `>=24.0.0 <27` (`engines` + `SUPPORTED_NODE_RANGE` द्वारे अंमलबजावणी)                 |
| डेटाबेस         | `better-sqlite3` मार्फत **SQLite** (सिंगलटन, WAL जर्नलिंग)                                                              |
| डेस्कटॉप        | **Electron 41** + `electron-builder` 26.10 (`electron/` येथे स्वतंत्र वर्कस्पेस)                                        |
| चाचण्या         | **Node native test runner** (युनिट/इंटिग्रेशन), **Vitest** (MCP, autoCombo, कॅशे), **Playwright** (e2e + protocols-e2e) |
| बिल्ड           | `scripts/build/build-next-isolated.mjs` मार्फत Next.js standalone                                                       |
| लिंट/फॉरमॅट     | ESLint flat config + Prettier (Husky pre-commit मार्फत `lint-staged`)                                                   |
| मॉड्यूल प्रणाली | सर्वत्र ESM (`"type": "module"`)                                                                                        |
| डॅशबोर्ड UI     | **Tailwind CSS 4** + वेंडर केलेले **Keak CI UI Kit** (`packages/ui-kit`), Lucide आयकन्स — `DESIGN_SYSTEM.md` पहा        |
| वर्कस्पेसेस     | npm workspaces — `open-sse`, `packages/browser-pool`, `packages/ui-kit`                                                 |

पाथ उपनाम (`tsconfig.json`):

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`
- `@omniroute/ui-kit` → `packages/ui-kit/src`, `@omniroute/ui-kit/*` → `packages/ui-kit/src/*`

डीफॉल्ट HTTP पोर्ट: **`20128`** (API आणि डॅशबोर्ड एकाच प्रोसेस शेअर करतात). डेटा
डिरेक्टरी `DATA_DIR` env व्हेरिएबलद्वारे ठरते, डीफॉल्ट `~/.omniroute/`.

### 3.1 `src/app/` — App Router

App Router डॅशबोर्ड UI आणि सार्वजनिक/व्यवस्थापन HTTP API दोन्ही उघड करतो.
येथे **कोणतेही ग्लोबल मिडलवेअर नाही** — इंटरसेप्शन प्रत्येक मार्गानुसार केले जाते.

`src/app/` खालील टॉप-लेव्हल सेगमेंट्स:

| मार्ग                                                                         | उद्देश                                      |
| ----------------------------------------------------------------------------- | ------------------------------------------- |
| `api/`                                                                        | सर्व HTTP API मार्ग (खालील विभागणी पहा)     |
| `a2a/`                                                                        | A2A JSON-RPC 2.0 एंडपॉइंट (`POST /a2a`)     |
| `.well-known/agent.json/`                                                     | A2A Agent Card डिस्कव्हरी दस्तऐवज           |
| `(dashboard)/`                                                                | डॅशबोर्ड UI (रूट ग्रुप, URL प्रीफिक्स नाही) |
| `auth/`, `login/`, `forgot-password/`, `callback/`                            | प्रमाणीकरण प्रवाह                           |
| `landing/`                                                                    | मार्केटिंग/लँडिंग पृष्ठ                     |
| `docs/`                                                                       | एम्बेडेड API डॉक्स व्यूअर                   |
| `status/`, `maintenance/`, `offline/`                                         | ऑपरेशनल पृष्ठे                              |
| `privacy/`, `terms/`                                                          | कायदेशीर पृष्ठे                             |
| `400/`, `401/`, `403/`, `408/`, `429/`, `500/`, `502/`, `503/`                | स्थिर त्रुटी पृष्ठे                         |
| `error.tsx`, `global-error.tsx`, `not-found.tsx`, `forbidden/`, `loading.tsx` | फ्रेमवर्क त्रुटी/लोडिंग बाउंडरीज            |

## 11. संकेतपद्धती

- **कोड शैली**: 2-space indent, double quotes, 100 char width, semicolons,
  `es5` trailing commas — `lint-staged` द्वारे Prettier वापरून लागू केली जाते.
- **Imports**: external → internal (`@/`, `@omniroute/open-sse`) → relative.
- **नामकरण**: files `camelCase` किंवा `kebab-case`, components `PascalCase`,
  constants `UPPER_SNAKE`.
- **ESLint**: `no-eval`, `no-implied-eval`, `no-new-func` = सर्वत्र `error`;
  `no-explicit-any` = `open-sse/` आणि `tests/` मध्ये `warn`, इतरत्र error.
- **TypeScript**: `strict: false` (वारसागत भूमिका). Cross-module सीमांसाठी
  inference ऐवजी स्पष्ट types ला प्राधान्य द्या.
- **Database**: routes किंवा handlers मध्ये कधीही raw SQL लिहू नका — नेहमी
  `src/lib/db/` modules मधूनच जा. कधीही barrel-import करू नका — विशिष्ट `src/lib/db/*` modules थेट वापरा.
- **DB-entity typing (#3512)**: DB table च्या row shape वर लिहिणारे किंवा ते
  वाचणारे function, call site वर `any` किंवा inline anonymous type न वापरता,
  त्या table च्या columns चे 1:1 प्रतिबिंब असलेले नामित TS interface स्वीकारावे/परत करावे.
  Interface हे function च्या जवळ ठेवा (उदा. `saveRequestUsage` च्या वर
  `src/lib/usage/usageHistory.ts` मध्ये `export interface UsageEntry`), विविध
  writers row क्रमाक्रमाने भरत असतील तेव्हा स्वतंत्र fields optional/nullable
  ठेवा, आणि callers नुसार shape बदलणाऱ्या field साठी `any` ऐवजी `unknown` ला
  प्राधान्य द्या (field वर दस्तऐवजीकरण केलेले, उदा. `UsageEntry.tokens`
  raw provider-shaped usage आणि normalized shape हे दोन्ही स्वीकारते). अशा
  प्रकारे file मधील `any` ची संख्या शून्यावर पोहोचल्यावर, regression टाळण्यासाठी
  ते `check:any-budget:t11` allowlist मध्ये (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`) जोडा. ही first-slice संकेतपद्धती आहे — व्यापक "anonymous `any`
  नाही" cleanup उर्वरित codebase मध्ये पुनरावृत्तीने केले जाते.
- **त्रुटी**: विशिष्ट error types सह try/catch वापरा, pino context सह log करा. SSE
  streams मधील errors कधीही शांतपणे गिळू नका; cleanup साठी abort signals वापरा.
- **सुरक्षा**: `eval()` / `new Function()` / implied eval कधीही वापरू नका. सर्व
  inputs चे Zod वापरून प्रमाणीकरण करा. संग्रहित credentials encrypt करा
  (AES-256-GCM). `src/shared/constants/upstreamHeaders.ts` denylist हे
  sanitize/validation स्तराशी सुसंगत ठेवा.
- **Commits**: Conventional Commits — `feat(scope): subject`. अनुमत scopes:
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`.
- **Branches**: prefixes `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`. `main` वर कधीही थेट commit करू नका.
- **Husky**: pre-commit मध्ये `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11` चालतात; pre-push मध्ये `check:any-budget:t11` + `check:tracked-artifacts` चालतात (जलद gates; `test:unit` वगळलेले आहे).
