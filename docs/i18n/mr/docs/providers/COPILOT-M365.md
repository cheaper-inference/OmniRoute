`copilot-m365-web` (उपनाम `m365copilot`) हे
`m365.cloud.microsoft/chat` वरील प्रमाणीकृत Microsoft 365 Copilot BizChat ब्राउझर सत्राद्वारे OpenAI-स्वरूपातील चॅट विनंत्या पाठवते. हे एक अनधिकृत एकत्रीकरण आहे.

> **Web Cookie प्रदाते वापरण्यास नवीन आहात?**
>
> या प्रदात्यासाठी विशिष्ट मार्गदर्शकाचे अनुसरण करण्यापूर्वी सर्वसाधारण सेटअप प्रक्रिया, प्रमाणीकरण मार्गदर्शन, मर्यादा आणि समस्यानिवारणासाठी **`docs/getting-started/WEB-COOKIE-GUIDE.md`** वाचा.
>
> **महत्त्वाचे:** या प्रदात्याचे क्रेडेन्शियल **कुकी नाही**. `m365.cloud.microsoft` वरून
> कुकीज कॉपी करू नका. हे क्रेडेन्शियल WebSocket URL क्वेरी
> पॅरामीटर आणि पाथ सेगमेंट आहे; दोन्ही DevTools मधील Network टॅबमधून वाचले जातात.

## पूर्वावश्यकता

- `m365.cloud.microsoft/chat` वरील BizChat मध्ये प्रवेश असलेले Microsoft 365 खाते
- DevTools मधील WebSocket तपासणीसाठी Chromium-आधारित ब्राउझर (Chrome, Edge)
- M365 Copilot परवाना (अनेक Microsoft 365 Business/Enterprise योजनांमध्ये समाविष्ट)

## क्रेडेन्शियल मिळवणे (WebSocket पद्धत)

1. `https://m365.cloud.microsoft/chat` येथे साइन इन करा आणि संभाषण सुरू करा.
2. **DevTools → Network** उघडा.
3. **WS** (WebSocket) नुसार फिल्टर करा.
4. Chathub WebSocket कनेक्शनवर क्लिक करा. खालीलप्रमाणे सुरू होणारा URL शोधा:
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. त्याच्या **Request URL** मधून पुढील गोष्टी कॉपी करा:
   - `access_token` क्वेरी पॅरामीटरचे मूल्य (अल्पकालीन JWT).
   - `/Chathub/` नंतरचा Chathub पाथ सेगमेंट (उदा. `<oid>@<tenant>`).

संपूर्ण URL चे स्वरूप असे असते:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute मध्ये **Providers → Add Provider** येथे जा, **Microsoft 365 Copilot
   (BizChat)** निवडा आणि क्रेडेन्शियल पुढील स्वरूपात पेस्ट करा:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** आणि **Save** वर क्लिक करा.

## क्रेडेन्शियल मिळवणे (HAR आयात)

WebSocket URL मधून मूल्ये व्यक्तिचलितपणे कॉपी करण्याऐवजी, तुम्ही DevTools HAR
फाइल निर्यात करू शकता:

1. **DevTools → Network** उघडा.
2. BizChat संभाषण सुरू करा किंवा पुढे सुरू ठेवा (यामुळे WebSocket कनेक्शन सक्रिय होते).
3. Network पॅनेलमध्ये उजवे-क्लिक करा आणि **Save all as HAR with content** निवडा.
4. OmniRoute मध्ये, प्रदाता कनेक्शन संवादातील **Import .har file** बटण वापरा.

OmniRoute, Chathub WebSocket URL साठी HAR स्कॅन करते, त्यातून
`access_token` आणि `chathubPath` काढते आणि क्रेडेन्शियल फील्ड आपोआप भरते.
HAR आयात JWT ची कालबाह्यता डीकोड करते आणि टोकनचा उर्वरित कालावधी दाखवते.

> **वास्तविक HAR निर्यात, ॲक्सेस टोकन किंवा रिफ्रेश टोकन कधीही कमिट करू नका.** चाचणी आणि
> दस्तऐवजीकरणातील मूल्ये नेहमी प्लेसहोल्डर असली पाहिजेत.

## टोकनची वैधता आणि रिफ्रेश

`access_token` अल्पकालीन असतो (सामान्यतः **~75 मिनिटे**). वापरण्यायोग्य रिफ्रेश
टोकनशिवाय, कालबाह्य झाल्यानंतर तुम्हाला क्रेडेन्शियल पुन्हा कॅप्चर करावे लागेल.

### `refreshToken` सह स्वयंचलित रिफ्रेश

Microsoft 365 प्रदात्याच्या **कनेक्शन जोडा** किंवा **कनेक्शन संपादित करा** संवादामध्ये,
**प्रगत सेटिंग्ज → रिफ्रेश टोकन (पर्यायी)** उघडा. `substrate.office.com/sydney` स्कोपसाठी
Microsoft OAuth रिफ्रेश टोकन पेस्ट करून जतन करा. इनपुट लपवलेले असते आणि संचयित टोकनने
ते कधीही पूर्वभरण केले जात नाही. संपादन करताना, विद्यमान टोकन ठेवण्यासाठी ते रिक्त ठेवा;
ते बदलण्यासाठी नवीन टोकन पेस्ट करा.

`substrate.office.com/sydney` स्कोपसाठी Microsoft डिव्हाइस-कोड किंवा
ऑथरायझेशन-कोड फ्लोमधून रिफ्रेश टोकन मिळवा; डॅशबोर्ड ते तुमच्यासाठी मिळवत नाही.
रिफ्रेश टोकन कॉन्फिगर केलेले असल्यास, OmniRoute विनंत्यांपूर्वी `access_token` तपासते
आणि त्याला रिफ्रेश करण्याची गरज असेल तेव्हाच रिफ्रेश करते. यशस्वी रिफ्रेशनंतर फिरवलेले
रिफ्रेश टोकन देखील जतन केले जाते, त्यामुळे रिफ्रेश टोकन वैध असेपर्यंत ते पुन्हा
हस्तचालितपणे कॅप्चर करण्याची गरज भासत नाही.

`refreshToken` सेट केलेले नसल्यास, प्रत्येक कालबाह्यतेनंतर तुम्हाला WebSocket क्रेडेन्शियल
हस्तचालितपणे पुन्हा कॅप्चर करावे लागेल.

### टियर निवड

| टियर         | उपनाव       | पृष्ठभाग                 |
| ------------ | ----------- | ------------------------ |
| `individual` | _(डीफॉल्ट)_ | ग्राहक M365 Copilot      |
| `edu`        | `included`  | शिक्षणासाठी M365 Copilot |
| `enterprise` | `work`      | कामासाठी M365 Copilot    |

टियर **प्रगत सेटिंग्ज → Copilot टियर** मध्ये सेट करा. टियरचा
BizChat रूटिंग आणि मॉडेल अॅक्सेसवर परिणाम होतो.

## सुरक्षा मॉडेल

- **अनधिकृत एकत्रीकरण.** हा प्रदाता BizChat WebSocket
  प्रोटोकॉलचे रिव्हर्स-इंजिनिअरिंग करतो. Microsoft ने एंडपॉइंट बदलल्यास तो कोणत्याही पूर्वसूचनेशिवाय काम करणे थांबवू शकतो.
- `subscriptionRisk: true` फ्लॅग हे दर्शवतो की हे एकत्रीकरण
  दस्तऐवजीकरण नसलेल्या एंडपॉइंटवर अवलंबून आहे. खात्यावर निर्बंध येण्याची शक्यता आहे, परंतु याची पुष्टी झालेली नाही.
- ॲक्सेस टोकन हे अल्पकालीन JWT आहे. त्याला पासवर्डप्रमाणे हाताळा: ते कमिट,
  लॉग किंवा शेअर करू नका.
- रिफ्रेश टोकन BizChat पृष्ठभागावर दीर्घकालीन प्रवेश प्रदान करते. ते
  API कीइतक्याच काळजीपूर्वक साठवा.

## समस्यानिवारण

### प्रमाणीकरण त्वरित अयशस्वी होते

- तुम्ही XHR/Fetch विनंतीमधून नव्हे, तर **WebSocket URL** मधून कॉपी केले आहे याची पडताळणी करा. क्रेडेन्शियल Chathub WebSocket कनेक्शनच्या `access_token` क्वेरी पॅरामीटरमध्ये असते — `Authorization: Bearer` हेडरमध्ये नाही.
- URL पथातील पूर्ण `<oid>@<tenant>` सेगमेंट `chathubPath` मध्ये समाविष्ट आहे याची खात्री करा.

### ~75 मिनिटांनंतर टोकन कालबाह्य होते

हे अपेक्षित आहे. `refreshToken` शिवाय, प्रवेश टोकन अल्पकालीन असते. यापैकी एक करा:

- DevTools मधून क्रेडेन्शियल पुन्हा कॅप्चर करा, किंवा
- स्वयंचलित रिफ्रेशसाठी Add किंवा Edit connection डायलॉगमधील **Advanced Settings → Refresh token (optional)** कॉन्फिगर करा.

### कनेक्शन चाचणी यशस्वी होते, परंतु चॅट 401 परत करते

पडताळणी आणि पहिल्या विनंतीदरम्यान टोकन कालबाह्य झालेले असू शकते. नवीन क्रेडेन्शियल पुन्हा कॅप्चर करा.

### प्रदाता सूचीमध्ये Copilot दिसत नाही

**Dashboard → Providers** मध्ये `copilot-m365-web` सक्षम असल्याची खात्री करा. काही स्तरांमध्ये प्रदाता डीफॉल्टनुसार लपवलेला असू शकतो.
