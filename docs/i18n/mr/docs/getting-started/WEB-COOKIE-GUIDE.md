Web Cookie प्रदात्यांमुळे OmniRoute ला API key ऐवजी तुमच्या विद्यमान ब्राउझर सत्राद्वारे AI सेवा वापरता येते. तुम्हाला एखाद्या सेवेच्या वेबसाइटद्वारे आधीपासून प्रवेश असेल आणि OmniRoute ने तेच प्रमाणीकृत सत्र वापरावे असे वाटत असेल, तेव्हा हे प्रदाते उपयुक्त ठरतात.

API-key प्रदात्यांपेक्षा वेगळे, Web Cookie प्रदाते तुमचा ब्राउझर वेबसाइटला पाठवत असलेली क्रेडेन्शियल्स वापरून प्रमाणीकरण करतात.

# सुरुवात करण्यापूर्वी

> **महत्त्वाचे:** क्रेडेन्शियल्स नेहमी **थेट नेटवर्क विनंतीमधून** कॉपी करा, तुमच्या ब्राउझरच्या cookie संचयनामधून **नाही**.

चुकीच्या ठिकाणाहून cookies कॉपी केल्यामुळे प्रमाणीकरणाच्या अनेक समस्या उद्भवतात.

## Cookie संचयनामधून कॉपी करू नका

बहुतेक ब्राउझर संचयित केलेले cookies पुढील ठिकाणी दाखवतात:

```
DevTools
→ Application (किंवा Storage)
→ Cookies
```

हे cookies योग्य दिसत असले, तरी ते पुढीलप्रमाणे असू शकतात:

- कालबाह्य
- अपूर्ण
- केवळ प्रमाणीकृत विनंत्यांवर पाठवले जाणारे cookies नसलेले

ही मूल्ये वैध दिसत असली, तरी त्यांचा वापर केल्यामुळे प्रमाणीकरण अयशस्वी होऊ शकते.

## थेट विनंतीमधून कॉपी करा

त्याऐवजी, यशस्वी विनंतीमधील cookies वापरा:

```
DevTools
→ Network
→ पृष्ठ रीफ्रेश करा
→ चॅट किंवा संभाषणाची विनंती उघडा
→ Request Headers
→ Cookie
```

`Cookie` विनंती हेडरमध्ये तुमच्या ब्राउझरने यशस्वीरीत्या वापरलेली अचूक प्रमाणीकरण माहिती असते.

बहुतेक Web Cookie प्रदात्यांसाठी, हेच मूल्य OmniRoute मध्ये पेस्ट केले पाहिजे.

# सामान्य सेटअप

बहुतेक Web Cookie प्रदात्यांसाठी सेटअप प्रक्रिया सारखीच असते.

1. प्रदात्याच्या वेबसाइटवर साइन इन करा.
2. ब्राउझरची Developer Tools उघडा.
3. **Network** टॅब उघडा.
4. पृष्ठ रीफ्रेश करा.
5. प्रमाणीकृत चॅट किंवा संभाषणाची विनंती उघडा.
6. आवश्यक प्रमाणीकरण क्रेडेन्शियल्स कॉपी करा.
7. OmniRoute उघडा.
8. **Providers → Add Provider** येथे जा.
9. तुमचा Web Cookie प्रदाता निवडा.
10. क्रेडेन्शियल्स पेस्ट करा.
11. **Test Connection** वर क्लिक करा.
12. प्रदाता जतन करा.

आवश्यक असलेली अचूक क्रेडेन्शियल्स प्रदात्यानुसार बदलतात.

# प्रदाता क्रेडेन्शियल स्वरूपे

वेगवेगळ्या वेबसाइट्स प्रमाणीकरणाची माहिती वेगवेगळ्या पद्धतीने संचयित करतात. काहींना केवळ cookies आवश्यक असतात, तर इतरांना अतिरिक्त headers किंवा tokens लागू शकतात.

| प्रदाता                         | क्रेडेन्शियल स्वरूप           | प्रदाता मार्गदर्शक               |
| ------------------------------- | ----------------------------- | -------------------------------- |
| Claude Web                      | संपूर्ण Cookie विनंती हेडर    | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | संपूर्ण Cookie हेडर           | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(पडताळा)_                    |                                  |
| Copilot Web                     | _(पडताळा)_                    | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(पडताळा)_                    |                                  |
| ...                             | ...                           | ...                              |

> नवीन Web Cookie प्रदाते जोडले जातात किंवा विद्यमान प्रदात्यांच्या प्रमाणीकरण आवश्यकता बदलतात, तेव्हा हे तक्ते अद्ययावत करा.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) हे नोंदणीची आवश्यकता नसलेले एक विनामूल्य ग्राहक चॅट प्लॅटफॉर्म आहे — पहिल्या भेटीवेळी सत्र अनामिकपणे तयार केले जाते आणि `uid`, `si_usr_id`, व `si_ses_id` या तीन कुकींद्वारे कायम राहते. OmniRoute एकाच मॉडेल आयडीद्वारे (`notrack-c`, उपनाव `ntw`) तोच `/api/dispatch` एंडपॉइंट प्रॉक्सी करतो.

### कनेक्ट करण्याच्या पायऱ्या

1. तुमच्या ब्राउझरमध्ये [notrack.ai](https://notrack.ai) उघडा आणि अनामिक सत्र कुकी सेट होऊ द्या.
2. **डेव्हलपर साधने → नेटवर्क** उघडा, पृष्ठ रिफ्रेश करा आणि कोणत्याही `/api` विनंतीवर क्लिक करा.
3. **विनंती शीर्षलेख** मध्ये, संपूर्ण `Cookie` शीर्षलेखाचे मूल्य कॉपी करा.
4. OmniRoute मध्ये, **प्रदाते → प्रदाता जोडा → NoTrack Web (विनामूल्य)** येथे जा.
5. कुकी स्ट्रिंग `apiKey` फील्डमध्ये पेस्ट करा आणि **जतन करा**.

OmniRoute पेस्ट केलेल्या स्ट्रिंगमधून `uid`, `si_usr_id`, आणि `si_ses_id` काढतो व केवळ त्या जोड्यांसह एक स्वच्छ `Cookie` शीर्षलेख पुन्हा तयार करतो — तसेच उपलब्ध असल्यास `nt_session` (लॉग इन केलेल्या खात्यांसाठी सेट केलेले `ntk_…` टोकन) जोडतो. या तिन्हींपैकी कोणतेही मूल्य गहाळ असल्यास, ऑपरेटरना पर्यायी स्वरूपांचे प्रयोग करता यावेत म्हणून पेस्ट केलेली मूळ स्ट्रिंग कोणताही बदल न करता फॉरवर्ड केली जाते.

### मॉडेल आयडी

| मॉडेल आयडी  | प्रदर्शित नाव | नोंदी                                             |
| ----------- | ------------- | ------------------------------------------------- |
| `notrack-c` | NoTrack C     | डीफॉल्ट — अपस्ट्रीम डिस्पॅच मॉडेल `C`.            |
| `C`         | NoTrack C     | `notrack-c` चे उपनाव (मूळ अपस्ट्रीम डिस्पॅच कोड). |
| `notrack`   | NoTrack C     | `notrack-c` चे उपनाव.                             |
| `ntw`       | NoTrack C     | `notrack-c` चे संक्षिप्त उपनाव.                   |

हे चारही मॉडेल आयडी त्याच अपस्ट्रीम डिस्पॅच मॉडेलशी (`C`) मॅप होतात.

### विनंतीचे पर्याय

एक्झिक्युटर विनंती बॉडीमध्ये ही पर्यायी फील्ड स्वीकारतो:

| बॉडी फील्ड            | डीफॉल्ट | उद्देश                                                               |
| --------------------- | ------- | -------------------------------------------------------------------- |
| `notrack_mode`        | `usual` | डिस्पॅच मोड (मुक्त-स्वरूप स्ट्रिंग; अपस्ट्रीम `usual`, … स्वीकारतो)  |
| `notrack_max_turns`   | `6`     | उत्तर देण्यापूर्वी अपस्ट्रीम घेऊ शकणाऱ्या अंतर्गत टर्नची संख्या.     |
| `notrack_chat_id`     | `null`  | विद्यमान अपस्ट्रीम चॅट पुन्हा सुरू करा (नवीन चॅटसाठी वगळा).          |
| `notrack_attachments` | `[]`    | अपस्ट्रीम संलग्नक वर्णनकांचा पास-थ्रू अॅरे.                          |
| `notrack_regenerate`  | `false` | मागील टर्नसाठी पुन्हा तयार केलेले उत्तर मागवण्यासाठी `true` सेट करा. |

### क्षमता

- **स्ट्रीमिंग आणि नॉन-स्ट्रीमिंग** चॅट पूर्णता.
- **टूल कॉलिंग** — विनंतीवर `tools: [...]` सेट करा; एक्झिक्युटर त्यांना टूल-कॉल एन्व्हलप करारामध्ये क्रमबद्ध करतो आणि मॉडेलचे प्रतिसाद पुन्हा OpenAI `tool_calls` मध्ये पार्स करतो.
- **`response_format`** — `json_object` आणि `json_schema` समर्थित आहेत. एक्झिक्युटर मॉडेलच्या उत्तरातील पहिला JSON ऑब्जेक्ट काढतो आणि तो परत करण्यापूर्वी त्याचे स्ट्रिंगमध्ये रूपांतर करतो.
- **रीझनिंग संकेत** — अपस्ट्रीमने `thinking` इव्हेंट पाठवल्यावर एक्झिक्युटर `reasoning` डेल्टा उत्सर्जित करतो.

### मर्यादा

- अपस्ट्रीम अनामिक वापरासाठी कोटा लागू करतो — तो ओलांडल्यास, एक्झिक्युटर वापरकर्ता-अनुकूल संदेशासह 429 दर्शवतो.
- सर्व मॉडेल आयडी त्याच अपस्ट्रीम डिस्पॅच मॉडेलवर रिझॉल्व्ह होतात; प्रत्येक मॉडेलसाठी स्वतंत्र स्विच नाही.
- एक्झिक्युटर अपस्ट्रीमच्या `/api/chats` एंडपॉइंटला कॉल करत नाही, त्यामुळे चॅट इतिहास / सत्रे स्वयंचलितपणे व्यवस्थापित केली जात नाहीत. विद्यमान अपस्ट्रीम चॅट पुन्हा सुरू करण्यासाठी `notrack_chat_id` वापरा.

# वेब कुकी प्रदाते काय करू शकतात आणि काय करू शकत नाहीत

वेब कुकी प्रदाते वेबसाइटचा चॅट इंटरफेस पुन्हा वापरतात. ते अधिकृत API सारख्या क्षमता **पुरवत नाहीत**.

## समर्थित

- आपल्या विद्यमान ब्राउझर सत्राचा वापर करून प्रमाणीकरण
- आपल्या खात्याद्वारे उपलब्ध असलेल्या मॉडेल्समध्ये प्रवेश
- चॅट प्रतिसादांचे स्ट्रीमिंग
- API की आवश्यक नाही

## असमर्थित

- फंक्शन कॉलिंग
- टूल कॉलिंग
- स्वयंचलित फाइल संपादन
- एजंटिक IDE कार्यप्रवाह
- केवळ API द्वारे उपलब्ध वैशिष्ट्ये

हे अपेक्षित वर्तन आहे आणि हा **बग नाही**.

आपल्याला टूल कार्यान्वयन, स्वयंचलित फाइल संपादन किंवा इतर एजंट कार्यप्रवाह आवश्यक असल्यास, Web Cookie प्रदात्याऐवजी **API-की प्रदाता** वापरा.

# प्रमाणीकरणासंबंधी मर्यादा

यशस्वी **कनेक्शन चाचणी** किंवा कुकी प्रमाणीकरण केवळ एवढेच सत्यापित करते की प्रदान केलेली क्रेडेन्शियल्स अपेक्षित स्वरूपात असल्याचे दिसते.

Issue #7857 चे निराकरण होईपर्यंत, यशस्वी प्रमाणीकरणामुळे प्रदाता यशस्वीरीत्या अधिप्रमाणित होईल याची **हमी मिळत नाही**.

अधिप्रमाणन तरीही अयशस्वी होत असल्यास, आपण क्रेडेन्शियल्स ब्राउझरच्या कुकी संचयनातून नव्हे, तर सक्रिय नेटवर्क विनंतीमधून कॉपी केली आहेत याची खात्री करा.

---

# समस्यानिवारण

## अधिप्रमाणन अयशस्वी होते

क्रेडेन्शियल्स येथून कॉपी केली आहेत याची खात्री करा:

```
Network
→ Request Headers
→ Cookie
```

आणि येथून **नाही**:

```
Application
→ Cookies
```

---

## कुकी ब्राउझरमध्ये कार्य करते, परंतु OmniRoute मध्ये नाही

काही प्रदात्यांमध्ये अशा कुकीज समाविष्ट असतात ज्या केवळ अधिप्रमाणित विनंत्यांदरम्यान पाठवल्या जातात.

संभाषण यशस्वीरीत्या उघडल्यानंतर नवीन नेटवर्क विनंतीमधून क्रेडेन्शियल्स पुन्हा कॉपी करा.

---

## सत्र कालबाह्य झाले

Web Cookie प्रदाते आपल्या विद्यमान ब्राउझर सत्राचा वापर करतात.

आपले ब्राउझर सत्र कालबाह्य झाल्यास किंवा आपण साइन आउट केल्यास, आपल्याला क्रेडेन्शियल्सचा नवीन संच कॉपी करावा लागेल. समर्थित वेब प्रदात्यांसाठी कुकी नूतनीकरण स्वयंचलित करण्यासाठी, पूरक साधन [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) पहा.

---

## कनेक्शन चाचणी उत्तीर्ण होते, परंतु विनंत्या अयशस्वी होतात

Issue #7857 चे निराकरण होईपर्यंत, प्रमाणीकरण उत्तीर्ण झाल्याने अधिप्रमाणन विनंती यशस्वी होईल याची हमी मिळत नाही.

पुढील समस्यानिवारण करण्यापूर्वी नवीन अधिप्रमाणित विनंतीमधून आपली क्रेडेन्शियल्स पुन्हा कॉपी करा.

---

## "Unsupported ChatGPT integrity dependency" त्रुटीसह ChatGPT Web अयशस्वी होते

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

क्रेडेन्शियल योग्य आहे — ती त्रुटी सत्रामुळे नव्हे, तर ब्रिजमुळे उद्भवते. chatgpt.com प्रत्येक डिप्लॉयमेंटनुसार त्याचे मॉड्यूल आयडी नियुक्त करते आणि ब्रिजने तो इन्स्टॅन्शिएट करत असलेल्या Sentinel हेल्परचा आयडी पूर्वी निश्चित केलेला असे. त्यामुळे हेल्परचे नाव बदलणाऱ्या chatgpt.com पुनर्बांधणीमुळे कुकी वैध असूनही प्रत्येक टर्न अयशस्वी झाला. कनेक्शन पुन्हा अधिकृत केल्याने ही समस्या सुटू शकत नाही.

पृष्ठाच्या स्वतःच्या रनटाइमद्वारे मॉड्यूलचे निराकरण करणाऱ्या बिल्ड्समध्ये कोणताही आयडी निश्चित केलेला नसतो आणि त्यांना ही समस्या येत नाही. आपल्याला ही त्रुटी दिसल्यास, OmniRoute अपग्रेड करा आणि कनेक्शन तपासणी पुन्हा चालवा.

# प्रदात्याचे उदाहरण

संपूर्ण प्रदाता-विशिष्ट चरण-दर-चरण मार्गदर्शनासाठी, हे पहा:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web मार्गदर्शिका Web Cookie प्रदात्यासाठी संपूर्ण सेटअप प्रक्रिया दर्शवते आणि संदर्भ अंमलबजावणी म्हणून वापरली जाते.

# सर्वोत्तम पद्धती

- नवीन अधिप्रमाणित विनंतीमधून क्रेडेन्शियल्स कॉपी करा.
- जुन्या कुकीज पुन्हा वापरणे टाळा.
- Web Cookie प्रदाते वापरताना आपले ब्राउझर सत्र सक्रिय ठेवा.
- कॉपी केलेल्या कुकीजना संवेदनशील क्रेडेन्शियल्सप्रमाणे हाताळा.
- आपल्याला फंक्शन कॉलिंग किंवा एजंट कार्यप्रवाह आवश्यक असताना API-की प्रदाते वापरा.
