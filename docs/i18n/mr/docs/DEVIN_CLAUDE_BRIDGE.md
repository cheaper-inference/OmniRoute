`devin-cli-agentic` मुळे प्रत्यक्ष Claude Code रनटाइमला OmniRoute चा स्थानिक Anthropic
Messages एंडपॉइंट वापरता येतो, तर अधिकृत Devin CLI ACP stdio वरून मॉडेल प्रतिसाद पुरवतो. हे
विद्यमान Anthropic, Claude OAuth, Claude Web किंवा `devin-cli` प्रदात्यांमध्ये बदल करत नाही.

क्लायंटच्या मालकीच्या टूल कॉल्ससाठी, Claude-स्वरूपातील टूल-सक्षम प्रदाता
`devin-cli-agentic` (उपनाम `dva`) द्वारे रूट करा. जुना `devin-cli` (`dv`) ACP एक्झिक्युटर
केवळ-मजकूर आहे: तो Devin चा टूल्स नसलेला summarizer चालवतो आणि टूल कॉल्स परत करू शकत नाही. त्याचा मॉडेल
मेटाडेटा त्यानुसार चिन्हांकित केलेला आहे, त्यामुळे टूल्स आवश्यक असलेले कॉम्बो रूटिंग त्याला टाळेल.

> **सध्याची स्थिती: Claude Code `2.1.258` वर पिन केलेले; ऑफलाइन आणि लाइव्ह प्रमाणीकरणाची शेवटची नोंद
> `2.1.220` वर झाली.** `2.1.220` पिनने Devin CLI
> `3000.2.17` आणि मॉडेल `swe-1-7-lightning` द्वारे तीन विलग परिस्थिती पूर्ण केल्या; त्या अंतिम लाइव्ह रनने क्लायंटच्या मालकीच्या `Read`,
> `Edit`, आणि `Bash` टर्न्स, यशस्वी `npm test` परिणाम, प्रकल्प कमांड आणि स्किल
> डिस्कव्हरी, केवळ-Devin रूटिंग आणि शून्य Claude इग्रेस सिद्ध केले. त्यानंतर पिन `2.1.258` पर्यंत वाढवण्यात आला
> (OmniRoute ची Claude ओळख ज्या CLI पिढीचे अनुकरण करते ती, तसेच Fable 5.1 स्तर मूळतः समाविष्ट करणारी
> पहिली आवृत्ती). नवीन पिनवर, पिन केलेल्या बेस इमेजवर इन्स्टॉल स्तर आणि `claude --version`
> सत्यापित करण्यात आले, तसेच ब्रिज युनिट संच, `compose config` आणि
> स्थिर विलगीकरण पुरावा उत्तीर्ण झाले — परंतु ऑफलाइन मॉक परिस्थिती आणि लाइव्ह तीन-परिस्थिती
> संच अद्याप पुन्हा चालवलेला नाही. या पिनसह ब्रिजवर अवलंबून राहण्यापूर्वी ते पुन्हा चालवा
> ("पिन केलेली टूल्स अपडेट करणे" पहा).

## आर्किटेक्चर

```text
Claude Code 2.1.258 (विलग non-root Linux कंटेनर)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-स्वरूप, प्रमाणीकरण नसलेला प्रदाता)
  -> devin acp --agent-type summarizer (अधिकृत ACP stdio, Devin टूल्स नाहीत)
  -> समर्पित devin-auth व्हॉल्यूममधील Devin खाते
```

अधिकृत CLI चा डीफॉल्ट ACP एजंट स्वतःची टूल्स कार्यान्वित करू शकतो, त्यामुळे हा ब्रिज त्याचा वापर
करत नाही. तो निश्चित `summarizer` ACP एजंट सुरू करतो, ज्याच्या अधिकृत CLI मोडमध्ये टूल्स नसतात, आणि
क्रमबद्ध केलेली Anthropic विनंती एक्झिक्युशन ट्रेस म्हणून फ्रेम करतो. Claude च्या मालकीची आणखी एखादी
क्रिया आवश्यक असल्यास, प्रतिसादामध्ये नेमके एक क्लायंट टूल एन्व्हलप असणे आवश्यक आहे. प्रतिसाद
यशस्वी म्हणून नोंदवण्यापूर्वी कोणताही ACP `tool_call` किंवा `tool_call_update` नाकारला जातो.

`open-sse/executors/devin-agentic/serializer.ts` मधील serializer `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, आणि
Claude Code ने पुरवलेली टूल्स जतन करतो. प्रतिमा आणि अज्ञात ब्लॉक्स स्पष्टपणे अपयशी ठरतात. मोठ्या टूल परिणामांसाठी
दृश्यमान ट्रंकेशन मार्कर वापरला जातो.

parser प्रत्येक मॉडेल टर्नमध्ये एक स्वतंत्र `<tool>{...}</tool>` एन्व्हलप स्वीकारतो. तो
विनंतीतील टूल सूचीविरुद्ध नाव तपासतो, त्या टूलच्या JSON Schema विरुद्ध आर्ग्युमेंट्सचे प्रमाणीकरण करतो,
मिश्रित वर्णन/क्रिया नाकारतो आणि एक मर्यादित दुरुस्ती अनुमत करतो. त्यानंतर Claude Code परिणामी
Anthropic `tool_use` स्थानिकरीत्या कार्यान्वित करतो आणि `tool_result` OmniRoute द्वारे परत पाठवतो.

## स्वयंचलित रूटिंग

प्रदाता ब्लॉक केलेला नसताना तो OmniRoute च्या `auto/*` उमेदवार पूल्समध्ये पात्र असतो.
उमेदवार पात्रता निवडीची हमी देत नाही: कॉम्बोची रूटिंग रणनीती (उदाहरणार्थ,
last-known-good) दुसऱ्या प्रदात्याला प्राधान्य देऊ शकते. प्रत्येक विनंती Devin द्वारेच जावी अशी
आवश्यकता असल्यास `dva/<model>` किंवा Devin-प्रथम कॉम्बो वापरा.

## विलगीकरण आणि धोका मॉडेल

होस्टवरील Claude स्थापना, खाते आणि कॉन्फिगरेशन या व्याप्तीबाहेर असून त्यांचा वापर
निषिद्ध मानला जातो. Compose सेवा:

- केवळ-वाचनीय रूट फाइलसिस्टम, काढून टाकलेल्या क्षमता आणि
  `no-new-privileges` यांसह UID/GID `10001:10001` म्हणून चालतात;
- खासगी `/home/bridge`, समर्पित Claude कॉन्फिगरेशन व्हॉल्यूम, विलग OmniRoute डेटा
  आणि स्वतंत्र `devin-auth` व्हॉल्यूम वापरतात;
- फक्त वापरानंतर टाकून देता येणारी `.sandbox` कार्यक्षेत्रे/पुरावे माउंट करतात;
- होस्टचे होम, Keychain, SSH, क्लाउड क्रेडेन्शियल्स किंवा Docker socket माउंट करत नाहीत;
- स्पष्टपणे परिभाषित केलेली वातावरणे तयार करतात आणि Anthropic API/OAuth/रूटिंग व्हेरिएबल्स काढून टाकतात;
- केवळ स्थानिक-वापरापुरत्या कीसह Claude Code चे इन्फरन्स फक्त `http://omniroute:20128` कडे निर्देशित करतात.

ऑफलाइन प्रोफाइल अंतर्गत नेटवर्क वापरते. लाइव्ह प्रोफाइलमध्ये, OmniRoute अधिकृत Devin
एंडपॉइंट्सपर्यंत फक्त `network-guard` द्वारे पोहोचते; असंबंधित गंतव्यस्थाने नाकारली जातात.
Claude Code साठी स्वतंत्र सर्व-निर्गमन-निषेध गार्ड आहे आणि ते `NO_PROXY` द्वारे फक्त स्थानिक OmniRoute
सेवेपर्यंत पोहोचू शकते. गार्ड ऑडिट फाइल्स फक्त त्यांच्या संबंधित गार्ड प्रक्रियेद्वारे माउंट केल्या जातात.
टोकनविरहित पुरावा निर्यात करण्यापूर्वी स्क्रिप्ट्स फाइलची मालकी, मोड, लिंक संख्या आणि प्रत्येक निर्णय
पडताळतात.

विलगीकरणाचा पुरावा स्वतंत्रपणे चालवा:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

हे टोपोलॉजी, नामांकित माउंट्स, नॉन-रूट/केवळ-वाचनीय सेटिंग्ज, स्पष्ट स्थानिक रूटिंग,
संवेदनशील पर्यावरणीय व्हेरिएबल्सचा अभाव, Docker socket चा अभाव, `api.anthropic.com` आणि
`claude.ai` वरील अवरोधित प्रवेश, फक्त Devin प्रदात्याची निवड आणि ACP बॅकएंड अनुपलब्ध असताना
स्पष्ट अपयश यांची पडताळणी करते.

## प्रथमच सेटअप आणि सामान्य वापर

पिन केलेली इमेज बिल्ड करा:

```bash
./scripts/devin-bridge/build
```

फक्त विलग केलेले Devin व्हॉल्यूम प्रमाणीकृत करा:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

लॉगिन कमांड रिमोट/कंटेनर वातावरणांसाठी असलेला अधिकृत मॅन्युअल-टोकन प्रवाह वापरते.
मूल्य थेट CLI प्रॉम्प्टमध्ये प्रविष्ट केले जाते; ते प्रोसेस आर्ग्युमेंट म्हणून पाठवले जात नाही,
Git मध्ये लिहिले जात नाही किंवा होस्टवरून कॉपी केले जात नाही.

विलग केलेले Claude Code रनटाइम सुरू करा:

```bash
./scripts/devin-bridge/launch
```

कंटेनरमध्ये चालणारे Claude Code सुरू करण्यापूर्वी `launch` विलगीकरण, Devin प्रमाणीकरण आणि
मॉडेल शोध पुन्हा तपासते. ते होस्टवरील Claude एक्झिक्युटेबल कधीही चालवत नाही. मॉडेल उपनावे
`.env.devin-bridge` मध्ये सेट करता येतात; कॉन्फिगर केलेल्या प्रत्येक मूल्याने
`devin-cli-agentic/` हा उपसर्ग कायम ठेवला पाहिजे.

## पडताळणी कमांड्स

पुनरुत्पादनीय ऑफलाइन मार्गासाठी Devin खात्याची आवश्यकता नसते आणि रनटाइमदरम्यान इंटरनेटची गरज नसते:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

प्रमाणीकृत आणि स्पष्टपणे निवडता येणारा लाइव्ह मार्ग असा आहे:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ACP सत्रे एकाच वेळी मोठ्या संख्येने उघडली जाऊ नयेत म्हणून लाइव्ह रनर प्रत्येक परिस्थितीदरम्यान
थांबतो आणि मजकूररूपी दाव्यांवर विश्वास ठेवण्याऐवजी संरचित Claude स्ट्रीम इव्हेंट्सची पडताळणी करतो.
त्याच्या तीन परिस्थिती पुढील गोष्टी सिद्ध करतात:

1. प्रकल्पाचे थेट वाचन आणि दोष विश्लेषण;
2. प्रत्यक्ष `Edit`, क्लायंटच्या मालकीचे `Bash` `npm test` आणि अंतिम निकाल;
3. `/bridge-check` तसेच `bridge-proof` शोध, प्रकल्पाचे वाचन, क्लायंटच्या मालकीचे आणखी एक यशस्वी
   `npm test` आणि कोणतेही प्रलंबित काम न ठेवता पूर्णता.

अंतिम गेट Devin नेटवर्क ऑडिटही तपासते आणि Claude निर्गमन ऑडिट रिकामे राहणे आवश्यक ठरवते.

## पिन केलेली साधने अद्ययावत करणे

इमेजमध्ये Node, Claude Code आणि Devin CLI यांच्या आवृत्त्या
`docker/devin-bridge/Dockerfile` मध्ये पिन केल्या आहेत. अद्ययावत करण्यासाठी:

1. स्पष्टपणे नमूद केलेल्या आवृत्त्या बदला;
2. दोन्ही आर्किटेक्चर-विशिष्ट Devin संग्रहणांचे चेकसम अधिकृत
   आर्टिफॅक्टच्या मूल्यांनी बदला;
3. इमेज पुन्हा बिल्ड करा आणि प्रत्येक ऑफलाइन प्रमाणीकरण कमांड चालवा;
4. इमेजमधील आवृत्त्यांची पुष्टी करा;
5. प्रमाणीकरण केलेला तीन-परिदृश्यांचा लाईव्ह संच पुन्हा चालवा.

होस्टवर कोणतेही CLI जागतिक स्तरावर इंस्टॉल करू नका किंवा चेकसम पडताळणीच्या जागी
पडताळणी न केलेले डाउनलोड वापरू नका.

## निदान आणि साफसफाई

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  स्थानिक राउटिंग आणि संवेदनशील माहिती काढून टाकलेल्या एक्झिक्युटर त्रुटी दाखवते.
- `.sandbox/evidence/mock-acp.jsonl` मध्ये निर्धारक मॉक ACP कृती नोंदवल्या जातात.
- `.sandbox/evidence/claude-stream.jsonl` मध्ये प्रत्यक्ष Claude Code ऑफलाइन रन नोंदवला जातो.
- `.sandbox/evidence/live-*.jsonl` मध्ये प्रमाणीकरण केलेले तीन लाईव्ह प्रवाह नोंदवले जातात.
- `.sandbox/evidence/egress.jsonl` आणि `.sandbox/evidence/claude-egress.jsonl` या गार्ड ऑडिटच्या
  प्रमाणीकरण केलेल्या, टोकन-मुक्त प्रती आहेत.

लॉगिन/कॉन्फिग व्हॉल्यूम जतन करून ब्रिजच्या मालकीचे कंटेनर आणि नेटवर्क थांबवा:

```bash
./scripts/devin-bridge/clean
```

नामांकित व्हॉल्यूमसह ब्रिजच्या मालकीचे संपूर्ण वातावरण काढून टाका:

```bash
./scripts/devin-bridge/clean --all
```

## मर्यादा

- ब्रिज निश्चित, साधने नसलेल्या `summarizer` भूमिकेवर अवलंबून आहे, कारण Devin CLI `3000.2.17`
  तटस्थ, साधने नसलेला ACP एजंट उपलब्ध करत नाही. अॅडॅप्टर सारांशाच्या स्वरूपातील
  मध्यवर्ती प्रतिसादांची भरपाई करतो, परंतु एक मर्यादित दुरुस्ती तरीही स्पष्टपणे अपयशी ठरू शकते.
- लाईव्ह ACP कॉल तात्पुरते `502`/`504` प्रतिसाद देऊ शकतात. हार्नेस परिदृश्यांमध्ये अंतर ठेवतो;
  सातत्यपूर्ण अपयश झाल्यास प्रक्रिया बंद स्थितीत अपयशी ठरते आणि दुसरा प्रदाता कधीही निवडत नाही.
- प्रत्येक Anthropic विनंतीमधून ACP संदर्भ पुन्हा तयार केला जातो; कोणतीही प्रक्रिया/सत्र
  संलग्नता नाही.
- प्रत्येक मॉडेल प्रतिसादासाठी एका टूल कॉलला समर्थन आहे; समांतर कॉल नाकारले जातात.
- इमेजना स्पष्टपणे समर्थन नाही. दृक्-क्षमता, विचार आउटपुट, प्रयत्न नियंत्रणे आणि 1M
  संदर्भ विंडो उपलब्ध म्हणून जाहीर केली जात नाही.
- SSE वैध Anthropic जीवनचक्र इव्हेंट वापरते, परंतु मर्यादित ACP टर्न संकलित झाल्यानंतरच
  ते उत्सर्जित केले जातात; ACP चंक्स वाढीव पद्धतीने पुढे पाठवले जात नाहीत.
