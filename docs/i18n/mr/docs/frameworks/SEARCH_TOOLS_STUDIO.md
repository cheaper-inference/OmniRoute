## आढावा

Search Tools Studio हे `/dashboard/search-tools` चे रूपांतर एका मूलभूत शोध प्लेग्राउंडमधून वेब शोध, वेब स्क्रॅपिंग आणि प्रदात्यांची शेजारी-शेजारी तुलना एकत्रित करणाऱ्या तीन-टॅब Studio मध्ये करते.

```
┌ Search Tools ──────────────────────────────────────────────────────────┐
│ [🔍 शोध] [📄 स्क्रॅप] [⚖ तुलना]                 142ms · $0.001  </>    │
│ ⓘ [मोडॅलिटीज मार्गदर्शक]                                               │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {सक्रिय टॅबमधील सामग्री}               │ ─ कॉन्फिगरेशन              │
│                                          │ प्रदाता [स्वयं ∨]           │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (फेच)        │
│                                          │ प्रकार [वेब | बातम्या]      │
│                                          │ पूर्ण पृष्ठ [ ] (स्क्रॅप)   │
│                                          │ स्वरूप [md|text|html]       │
│                                          │ रीरँक मॉडेल [∨]             │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## टॅब

### टॅब शोधा

विद्यमान `SearchForm` + `ResultsPanel` + `RerankPanel` टॅबमध्ये विकसित करते:

- → परिणाम क्वेरी करा (शीर्षक, URL, स्निपेट, प्रासंगिकता स्कोअर).
- कॉन्फिग उपखंडातील प्रदाता मेटाडेटा (किंमत, कोटा, स्थिती).
- विभाग पुन्हा रँक करा: पुन्हा रँक मॉडेल निवडा, परिणाम पुन्हा क्रमाने लावा, `positionDelta` दर्शवा.
- कोणतेही शोध प्रदाता कॉन्फिगर केलेले नसताना CTA सह रिक्त स्थिती.
- `SearchHistory.tsx` द्वारे इतिहास शोधा.
- कॉल `POST /v1/search` (विद्यमान एंडपॉइंट, कोणतेही बदल नाहीत).

### स्क्रॅप टॅब

URL मधून `POST /v1/web/fetch` द्वारे सामग्री काढण्यासाठी नवीन टॅब (योजना 05 मध्ये तयार केला):

- इनपुट: URL + पूर्ण-पृष्ठ टॉगल + स्वरूप निवडकर्ता (मार्कडाउन / मजकूर / HTML).
- → आणणे → रेंडर `ScrapeResult.tsx` सबमिट करा.
- `ScrapeResult` मार्कडाउन पूर्वावलोकन + रॉ टॉगल प्रस्तुत करते.
- कॅप: जर प्रतिसाद शरीर >** 256 KB** , UI `(truncated, view raw)` दाखवते आणि मोनॅको मॉडेल (D21) मध्ये रॉ उघडते.
- मेटाडेटा पॅनेल: प्रदाता (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search), विलंबता, खर्च, प्रतिसाद आकार, दुवे संख्या.
- `useScrapeFetch.ts` हुक वापरते.

### टॅबची तुलना करा

पर्यंत समान query/URL चालवते** समांतर 4 प्रदाता** (डी२२):

- प्रति प्रदाता शेजारी-बाय-साइड स्तंभ.
- मेट्रिक्स: विलंबता, खर्च, परिणाम संख्या, प्रतिसाद आकार.
- शोधासाठीURL ओव्हरलॅप गणना (शेअर केलेल्या URLs वि प्रारंभिक निकालाची संख्या).
- प्रति प्रदाता `POST /v1/search` (शोध) किंवा `POST /v1/web/fetch` (स्क्रॅप) कॉल करते.

## कॉन्फिगरेशन पेन (सामायिक)

`SearchToolsConfigPane.tsx` — नेहमी दृश्यमान, संकुचित करता येण्याजोगा.

| फील्ड       | नोंदी                                                                    |
| ----------- | ------------------------------------------------------------------------ |
| प्रदाता     | स्थिती बॅजसह ड्रॉपडाउन (कॉन्फिगर केलेला / अनुपलब्ध / दर-मर्यादित)        |
| प्रकार      | `web` किंवा `news` (फक्त शोधासाठी)                                       |
| पूर्ण पृष्ठ | स्क्रॅपसाठी टॉगल — संपूर्ण पृष्ठ विरुद्ध प्रथम दृश्यमान सामग्री फेच करतो |
| स्वरूप      | `markdown`, `text`, किंवा `html` (फक्त स्क्रॅपसाठी)                      |
| रीरँक मॉडेल | शोधानंतरच्या रीरँकिंगसाठी पर्यायी मॉडेल                                  |
| इतिहास      | संकुचित करता येण्याजोगा शोध इतिहास विभाग                                 |

## SearchConceptCard

`SearchConceptCard.tsx` — नेहमी दृश्यमान असलेले, संकुचित करता येणारे अकॉर्डियन. हे पुढील गोष्टी स्पष्ट करते:

| संकल्पना                  | एका ओळीत वर्णन                                                   |
| ------------------------- | ---------------------------------------------------------------- |
| **शोध**                   | वेब परिणामांची सूची मिळवते (शीर्षक, URL, स्निपेट, सुसंगतता गुण)  |
| **स्क्रेप**               | URL मधील संपूर्ण मजकूर काढते (markdown, मजकूर किंवा HTML)        |
| **तुलना**                 | तीच क्वेरी N प्रदात्यांमध्ये शेजारी-शेजारी चालवते                |
| **पुनर्क्रमांकन**         | क्वेरीची सुसंगतता सुधारण्यासाठी LLM द्वारे परिणामांचा क्रम बदलते |
| **स्वयं (सर्वात स्वस्त)** | उपलब्ध असलेला सर्वात स्वस्त प्रदाता स्वयंचलितपणे निवडते          |

## प्रदाता कॅटलॉग

`ProviderCatalog.tsx` `GET /api/search/providers` कडून संपूर्ण प्रदाता सूची उघड करते (प्रदात्य आणण्यासाठी F4 मध्ये विस्तारित):

| `kind` | `"search"` (24 प्रदाता) किंवा `"fetch"` (फायरक्रॉल, जिना-रीडर, टॅविली-सर्च, टिनीफिश, चपळ-शोध, कोणताही शोध-शोध, समांतर-शोध, उत्सुक-शोध) |

स्थिती आहे** विनंती वेळी व्युत्पन्न** क्रेडेन्शियल्स अस्तित्वात आहेत की नाही आणि सर्व की सध्या कूलडाउनमध्ये आहेत की नाही हे तपासून.

`codex-search` (Codex वेब शोध) ची स्वतःची कोणतीही की नाही: ते कनेक्ट केलेले Codex (ChatGPT) खाते पुन्हा वापरते, म्हणून प्रत्येक शोध ChatGPT सदस्यता कोटा खर्च करतो आणि सुमारे 10-40 सेकंद घेतो. जेव्हा एखादी विनंती त्यास नाव देते तेव्हा ते चालते; स्वयंचलित निवडीसाठी `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` वैशिष्ट्य ध्वज आवश्यक आहे (डीफॉल्टनुसार बंद).

`ExportCodeModal` (Playground Studio मधून आयात केलेले) + `codeExport.ts`, `/v1/search` आणि `/v1/web/fetch` या दोन्ही कॉलसाठी
curl / Python / TypeScript स्निपेट्स व्युत्पन्न करतात.

## बॅकएंड बदल

या वैशिष्ट्यासाठी फक्त एक बॅकएंड बदल आवश्यक होता:

### विस्तारित `GET /api/search/providers`

`src/app/api/search/providers/route.ts` पर्यंत विस्तारित करण्यात आले:

- प्रत्येक आणणे प्रदाता (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`, `keenable-search`) ॲरेमध्ये समाविष्ट करा.
- प्रत्येक आयटममध्ये `kind: "search" | "fetch"` जोडा.
- लाइव्ह क्रेडेंशियल स्थितीतून मिळवलेले `status: "configured" | "missing" | "rate_limited"` जोडा.
- — विद्यमान फील्ड (`id`, `name`, इ.) अपरिवर्तित असलेली बॅकवर्ड सुसंगतता राखा.
