> **सत्याचा अधिकृत स्रोत:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, आणि
> `src/app/(dashboard)/dashboard/plugins/`
> **शेवटचे अद्यतन:** 2026-06-28 — v3.8.40

OmniRoute मध्ये WordPress-शैलीची प्लगइन प्रणाली समाविष्ट आहे. प्लगइन म्हणजे स्वतंत्र
डिरेक्टरी असतात — प्रत्येकामध्ये एक `plugin.json` मॅनिफेस्ट आणि एक एंट्री फाइल असते — ज्या
विनंती पाइपलाइनमध्ये (`onRequest` / `onResponse` / `onError`) आणि
जीवनचक्र इव्हेंटमध्ये (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
हुक होतात.

**Plugin Marketplace** हा त्या प्रणालीवरील शोध स्तर आहे. तो इन्स्टॉल करता येणाऱ्या
प्लगइनचा ब्राउझ करण्यायोग्य कॅटलॉग उपलब्ध करतो. डीफॉल्टनुसार कॅटलॉग ही एक
लहान, अंगभूत सीड रजिस्ट्री असते; ऑपरेटर त्यासाठी सानुकूल रिमोट
रजिस्ट्री URL निर्दिष्ट करू शकतो, अशा परिस्थितीत फेच DNS-रिझॉल्व्हिंग SSRF गार्डद्वारे
अधिक सुरक्षित केले जाते ([सुरक्षा](#security) पहा).

प्रत्येक प्लगइन रूट **केवळ लूपबॅकसाठी** (Tier 1 — `LOCAL_ONLY`) उपलब्ध असतो: प्लगइन
चाइल्ड प्रोसेसमध्ये कोड लोड आणि कार्यान्वित करतात, त्यामुळे प्रमाणीकरण असले तरीही
नॉन-लूपबॅक उगमावरून हे रूट उपलब्ध नसतात.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) पहा.

## हे Together कसे बसते

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **नोंदणी स्तर** — `src/lib/plugins/marketplace.ts`: सूची / कॅटलॉग शोधते, कोणत्याही अपयशावर बियाणे नोंदणीकडे परत येते.
- **जीवनचक्र स्तर** — `src/lib/plugins/manager.ts` (`pluginManager` सिंगलटन): स्थापित करा, अपग्रेड करा, सक्रिय करा, निष्क्रिय करा, अनइंस्टॉल करा, स्कॅन करा, स्टार्टअप लोड करा.
- **मॅनिफेस्ट लेयर** — `src/lib/plugins/manifest.ts`: `plugin.json` साठी Zod स्कीमा + डीफॉल्ट्स.
- **स्कॅनर** — `src/lib/plugins/scanner.ts`: प्लगइन डिरेक्टरी अंतर्गत डिस्कवर प्लगइन शोधते.
- **लोडर** — `src/lib/plugins/loader.ts`: प्रत्येक प्लगइन वेगळ्या Node.js चाइल्ड प्रक्रियेमध्ये तयार करतो आणि दलाल IPC वर कॉल करतात. मूल सँडबॉक्स नाही (खालील "प्लगइन एक्झिक्युशन आयसोलेशन" पहा).

## मार्केटप्लेस कॅटलॉग

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) हे
`MarketplaceEntry` ऑब्जेक्टची सूची परत करते:

| फील्ड         | प्रकार   | नोंदी                                  |
| ------------- | -------- | -------------------------------------- |
| `name`        | string   | kebab-case प्लगइन नाव                  |
| `version`     | string   | semver                                 |
| `description` | string   | संक्षिप्त सारांश                       |
| `author`      | string   | लेखक / संस्था                          |
| `license`     | string   | SPDX-शैलीचा परवाना आयडी                |
| `downloadUrl` | string   | स्रोत डाउनलोड URL (रिकामा असू शकतो)    |
| `repository`  | string?  | पर्यायी रिपॉझिटरी URL                  |
| `tags`        | string[] | शोध/फिल्टर टॅग                         |
| `downloads`   | number   | डाउनलोड संख्या                         |
| `rating`      | number   | 0–5                                    |
| `verified`    | boolean  | नोंद सत्यापित म्हणून चिन्हांकित आहे का |
| `lastUpdated` | string   | ISO-सदृश दिनांक स्ट्रिंग               |

कोणताही सानुकूल रजिस्ट्री URL कॉन्फिगर केलेला नसल्यास, कॅटलॉग म्हणून अंगभूत
`SEED_REGISTRY` वापरली जाते (सध्या `request-logger`, `rate-limiter`, `cost-tracker`, आणि
`theme-manager`). सीड रजिस्ट्री नेहमी उपलब्ध असते — कॉन्फिगर केलेली रिमोट
रजिस्ट्री उपलब्ध नसल्यास, नॉन-`200` स्थिती परत केल्यास किंवा अपरिचित
बॉडी परत केल्यास, `listMarketplacePlugins()` एक इशारा लॉग करते आणि सीड सूचीचा वापर करते.

> टीप: मार्केटप्लेस **कॅटलॉग** (ब्राउझ/शोध) सुरुवातीपासून शेवटपर्यंत जोडलेला आहे, परंतु
> कॅटलॉगमधून एका क्लिकमध्ये मार्केटप्लेस **इन्स्टॉल** करण्याची सुविधा अद्याप लागू केलेली नाही —
> मार्केटप्लेस नोंदीवरील डॅशबोर्डचे "इन्स्टॉल" बटण सध्या
> "लवकरच उपलब्ध" अशी सूचना दाखवते. सध्या इन्स्टॉलेशन स्थानिक-पाथ इन्स्टॉल
> प्रवाहाद्वारे (`POST /api/plugins`) आणि डिस्कवरील शोधाद्वारे (`POST /api/plugins/scan`) केले जाते.

## REST API

सर्व एंडपॉइंट्सना व्यवस्थापन प्रमाणीकरण आवश्यक आहे (`requireManagementAuth`)** आणि** लूपबॅक-केवळ — `/api/plugins` आणि `/api/plugins/` `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) मध्ये सूचीबद्ध आहेत.

| शेवटचा बिंदू                     | पद्धत  | वर्णन                                                    |
| -------------------------------- | ------ | -------------------------------------------------------- |
| `/api/plugins`                   | GET    | स्थापित प्लगइनची यादी करा (पर्यायी `?status=` फिल्टर)    |
| `/api/plugins`                   | POST   | प्लगइन स्त्रोत निर्देशिकेतून प्लगइन स्थापित करा          |
| `/api/plugins/scan`              | POST   | प्लगइन निर्देशिका स्कॅन करा आणि नवीन प्लगइनची नोंदणी करा |
| `/api/plugins/marketplace`       | GET    | मार्केटप्लेस कॅटलॉग नोंदी सूचीबद्ध करा                   |
| `/api/plugins/[name]`            | GET    | स्थापित प्लगइन तपशील मिळवा                               |
| `/api/plugins/[name]`            | DELETE | प्लगइन विस्थापित करा                                     |
| `/api/plugins/[name]/activate`   | POST   | सक्रिय करा ( + रजिस्टर हुक लोड करा)                      |
| `/api/plugins/[name]/deactivate` | POST   | निष्क्रिय करा (फायर `onDeactivate`, अननोंदणी हुक)        |
| `/api/plugins/[name]/config`     | GET    | प्लगइन कॉन्फिगरेशन + कॉन्फिगरेशन स्कीमा मिळवा            |
| `/api/plugins/[name]/config`     | PUT    | प्लगइन कॉन्फिगरेशन अपडेट करा (स्कीमा विरुद्ध प्रमाणित)   |

`GET /api/plugins` `status` फिल्टर `installed` / `active` / `inactive` / `error` पैकी एक स्वीकारतो. अवैध मूल्य `400` मिळवते.

### स्थापित प्लगइन सूचीबद्ध करा

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### स्थानिक मार्गावरून स्थापित करा

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` असणे आवश्यक आहे** निरपेक्ष** निर्देशिकेचा मार्ग** प्लगइन स्त्रोत निर्देशिकेत** : प्लगइन रूटच्या पुढे `plugin-sources`, त्यामुळे डीफॉल्टनुसार `~/.omniroute/plugin-sources/`, किंवा जेव्हा ते व्हेरिएबल सेट केले जाते तेव्हा `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` (`getPluginSourcesDir()` मध्ये `src/lib/plugins/installSource.ts`). तेथे प्रथम प्लगइन कॉपी किंवा क्लोन करा. जेव्हा पथमध्ये `..` किंवा नल बाइट असते, त्या डिरेक्टरीच्या बाहेर असते, सिमलिंकद्वारे त्याचे निराकरण होते, सिमलिंक असते ज्याचे लक्ष्य त्याच्या बाहेर असते किंवा निर्देशिका अस्तित्वात नसते तेव्हा `400` सह इंस्टॉलेशन नाकारले जाते. स्त्रोत निर्देशिकेमध्ये वैध `plugin.json` (किंवा एकाचे पालक असणे) असणे आवश्यक आहे. यशस्वीतेवर प्रतिसाद स्थापित प्लगइन पंक्तीसह `201` आहे.

इतर प्लगइन मार्गांच्या विपरीत, लॉगिन अक्षम केलेले असतानाही यासाठी व्यवस्थापन क्रेडेन्शियल (डॅशबोर्ड सत्र किंवा व्यवस्थापित-स्कोप्ड API की) आवश्यक आहे (`requireLogin=false`): कोड स्थापित करणे ही कधीही निनावी क्रिया नसते.

### मार्केटप्लेस ब्राउझ करा

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### प्लगइन कॉन्फिगरेशन अपडेट करा

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` प्लगइनच्या `configSchema` (मॅनिफेस्टमध्ये घोषित) विरुद्ध प्रत्येक प्रदान केलेले मूल्य प्रमाणित करते: `number` फील्ड्स `min`/`max`, `select` फील्ड घोषित `enum` शी जुळणे आवश्यक आहे. स्कीमामध्ये नसलेल्या की याद्वारे अनुमत आहेत.

## कॉन्फिगरेशन

### प्लगइन डिरेक्टरी

प्लगइन्स OmniRoute डेटा डिरेक्टरीखाली असतात:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (किंवा manifest.main ज्याकडे निर्देश करते ती फाइल)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ही डिरेक्टरी
तीन टप्प्यांत निर्धारित करते:

1. **`OMNIROUTE_PLUGINS_DIR`**, सेट केलेले असल्यास — `HOME` चे मूल्य काहीही असले तरी जसेच्या तसे वापरले जाते. Docker/K8s साठी
   हे स्पष्ट नियंत्रण आहे, जिथे प्लगइन ट्री अशा पाथवर बाइंड-माउंट केलेला असतो
   ज्याचा सामान्यतः कंटेनरच्या होम डिरेक्टरीशी काहीही संबंध नसतो (#11827).
2. `<home>/.omniroute/plugins`, जिथे `<home>` हे `HOME` / `USERPROFILE`
   पर्यावरण चलांमधून घेतले जाते.
3. `/tmp/.omniroute/plugins`, जेव्हा प्रक्रियेकडून कोणतीही होम डिरेक्टरी एक्सपोर्ट केली जात नाही.

निर्धारित डिरेक्टरी स्टार्टअपवेळी `scanner.dir_resolved` म्हणून एकदा लॉग केली जाते आणि
निवडलेले इनपुट (`OMNIROUTE_PLUGINS_DIR`, `home`, किंवा `no-home-fallback`) नमूद केले जाते — त्यामुळे एखादी इमेज
नकळत तिसऱ्या टप्प्यावर पोहोचल्यास, केवळ रिकामी प्लगइन यादी नोंदवण्याऐवजी तसे स्पष्टपणे सांगितले जाते.
`POST /api/plugins/scan` तेथील वैध `plugin.json` असलेली प्रत्येक सबडिरेक्टरी शोधून
तिची नोंदणी करते; हीच डिरेक्टरी `pluginManager.install()` प्लगइन्स कॉपी करण्यासाठी
रूट म्हणून वापरते, त्यामुळे ओव्हरराइड केल्यास शोध आणि स्थापना दोन्ही एकत्र स्थलांतरित होतात.

> **`OMNIROUTE_PLUGINS_DIR` हे `OMNIROUTE_PLUGIN_PATH` नाही.** नंतरचे मूल्य फक्त
> CLI कमांड-प्लगइन लोडर (`bin/cli/plugins.mjs`) द्वारे `omniroute` उपकमांड्स जोडणारी
> `omniroute-cmd-*` npm पॅकेजेस शोधण्यासाठी वाचले जाते — येथे वर्णन केलेल्या रनटाइम स्कॅनरवर
> त्याचा कोणताही परिणाम होत नाही. त्या भागासाठी [PLUGINS.md](./PLUGINS.md) पहा.

### सानुकूल मार्केटप्लेस रजिस्ट्री URL

मार्केटप्लेस कॅटलॉगचा स्रोत `pluginMarketplaceUrl` सेटिंगमधून वाचला जातो
(`src/lib/plugins/marketplace.ts` हे `settings.pluginMarketplaceUrl` वाचते). ते
`http(s)` URL वर सेट केलेले असल्यास, `listMarketplacePlugins()` त्या URL वरून डेटा आणते आणि
एकतर नोंदींचा शीर्ष-स्तरीय JSON अॅरे किंवा `plugins` अॅरे असलेला ऑब्जेक्ट स्वीकारते;
स्ट्रिंग `name` नसलेल्या नोंदी फिल्टर केल्या जातात. हे सेट केलेले नसल्यास (किंवा फेच
SSRF संरक्षकामुळे अयशस्वी झाल्यास / खराब प्रतिसाद मिळाल्यास), अंगभूत सीड रजिस्ट्री
वापरली जाते.

डॅशबोर्डवरील "Marketplace" टॅब या URL साठी एक फील्ड उपलब्ध करून देतो (जे
`GET /api/settings` मधून पुन्हा वाचले जाते).

> अंमलबजावणीविषयक टीप: डॅशबोर्डवरील "Save" क्रिया
> `pluginMarketplaceUrl` हे `PATCH /api/settings` कडे पाठवते. हे लिहित असताना ही
> की `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) मध्ये घोषित केलेली नाही, त्यामुळे तिच्यावर अवलंबून राहण्यापूर्वी
> तुमच्या रिलीजमध्ये ती कायम राहते का ते तपासा — सेटिंग्ज
> स्टोअरमध्ये की उपलब्ध झाल्यानंतर **वाचन** पाथ (`getSettings()` →
> `listMarketplacePlugins()`) तिचे पालन करतो.

## सुरक्षा

### फक्त रूट टियर — लूपबॅक

प्लगइन्स जन्मलेल्या चाइल्ड प्रक्रियेमध्ये कोड कार्यान्वित करतात, म्हणून संपूर्ण `/api/plugins` पृष्ठभागाचे वर्गीकरण `LOCAL_ONLY` (टियर 1) केले जाते. लूपबॅक अंमलबजावणी बिनशर्त चालते** आधी** कोणतीही प्रमाणीकरण तपासणी, त्यामुळे बोगद्यावरील बॉक्सपर्यंत पोहोचणारे लीक केलेले व्यवस्थापन टोकन अद्याप प्लगइन स्थापित, सक्रिय किंवा विस्थापित करू शकत नाही. [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) आणि कठोर नियम #15 / #17 पहा.

### मार्केटप्लेस नोंदणी SSRF गार्ड

सानुकूल रेजिस्ट्री URL हे आक्रमणकर्ते-प्रभावी कॉन्फिगरेशन आहे, म्हणून ते आणण्यापूर्वी `listMarketplacePlugins()` ते दोन स्तरांमधून चालवते:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` नसलेली कोणतीही गोष्ट नाकारते.
   - शाब्दिक private/loopback/link-local/ULA होस्ट नाकारतो (IPv4** आणि** IPv6, IPv4-mapped सह ) कॅनॉनिकल `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) द्वारे.
   - निराकरण करते** दोन्ही** `A` आणि `AAAA` रेकॉर्ड करते आणि असल्यास नाकारते** कोणतेही** निराकरण केलेला पत्ता खाजगी — आहे सार्वजनिक-होस्टनाव → खाजगी-आयपी बायपास बंद करत आहे.
   - **अयशस्वी बंद** : एक DNS ठराव अयशस्वी झाल्याने URL नाकारतो.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): आणण्याच्या वेळी फक्त सार्वजनिक URL गार्ड पुन्हा लागू करते आणि** ब्लॉक पुनर्निर्देशन** (सार्वजनिक → खाजगी `30x` पिव्होट नाही).

एकही थर अयशस्वी होणारा URL विनंती रद्द करत नाही — मार्केटप्लेस शांतपणे अंगभूत सीड रेजिस्ट्रीकडे परत येते आणि एक चेतावणी लॉग करते.

> हे गार्ड PR #3774 मध्ये विशेषतः A + AAAA निराकरण करण्यासाठी आणि IPv4-only चेक ऐवजी कॅनॉनिकल `isPrivateHost` वापरण्यासाठी कठोर केले गेले.

### प्लगइन अंमलबजावणी अलगाव

> **प्लगइन सँडबॉक्स केलेले नाहीत.** मूल ही OmniRoute वापरकर्ता म्हणून चालणारी एक सामान्य Node.js प्रक्रिया आहे, ज्यामध्ये कोणतेही VM संदर्भ आणि कोणतेही Node.js परवानगी ध्वज नाहीत, त्यामुळे प्लगइन कोड वापरकर्ता कोणतीही फाईल वाचू आणि लिहू शकतो, प्रोग्राम चालवू शकतो आणि नेटवर्कपर्यंत पोहोचू शकतो. `requires.permissions` फक्त ठरवते की मुलाला कोणते पर्यावरण व्हेरिएबल्स मिळतील; इतर परवानग्या लागू केल्या जात नाहीत. फक्त तुमचा विश्वास असलेले प्लगइन स्थापित करा. खालील प्रक्रिया सीमा क्रॅश आणि हँग समाविष्टीत आहे; ही सुरक्षा सीमा नाही.

- **प्रक्रिया अलगाव** — `loadPlugin()` (`src/lib/plugins/loader.ts`) प्रत्येक प्लगइनला वेगळ्या Node.js चाइल्ड प्रक्रियेमध्ये तयार करते आणि IPC वर संप्रेषण करते. `SIGTERM` → `SIGKILL` एस्केलेशनसह हुक कॉल्सची कालबाह्यता असते.
- **Env परवानगी यादी** — मुलाला पर्यावरण व्हेरिएबल्सचा फक्त एक अनुमत संच प्राप्त होतो; जेव्हा मॅनिफेस्टने `env` परवानगीची विनंती केली तेव्हाच विस्तृत संच मंजूर केला जातो.
- **स्त्रोत प्रतिबंध स्थापित करा** — `POST /api/plugins` फक्त प्लगइन स्त्रोत निर्देशिकेतून वाचतो ("स्थानिक मार्गावरून स्थापित करा" पहा): पथ `realpath` सह कॅनॉनिकल केलेला आहे, त्या निर्देशिकेत काटेकोरपणे राहणे आवश्यक आहे, आणि एक सिमलिंक असलेले स्त्रोत ट्री जे सुटते ते काहीही कॉपी करण्यापूर्वी नाकारले जाते.
- **मार्ग प्रतिबंध** — install/upgrade/uninstall ठामपणे सांगतात की प्लगइन निर्देशिका आणि `manifest.main` निराकरण करतात** आत** कोणतीही कॉपी किंवा रिकर्सिव डिलीट करण्यापूर्वी व्यवस्थापित प्लगइन रूट (छेडछाड केलेल्या DB पथ आणि `manifest.main` मधील `../` ट्रॅव्हर्सल विरुद्ध रक्षक). सक्रियकरण `realpath` द्वारे सिमलिंक्सचे निराकरण करते आणि प्लगइन निर्देशिकेतून बाहेर पडणारा एंट्री पॉइंट लोड करण्यास नकार देते.
- **पर्यायी अखंडता पिन** — मॅनिफेस्ट एक `integrity` (`sha256-<base64>`, SRI स्वरूप) फील्ड घोषित करू शकते. उपस्थित असताना, लोडर लोडच्या वेळी एंट्री फाइल हॅशची पडताळणी करतो आणि जुळत नसल्यास सक्रिय करण्यास नकार देतो. हे छेडछाड-शोध निवडणे आहे,** नाही** सुरक्षा सीमा: लोड केलेले प्लगइन काय करू शकते यावर ते मर्यादित करत नाही.
- **हुकमध्ये क्लायंट क्रेडेन्शियल नाहीत** — संदर्भ `onRequest`, `onResponse` आणि `onError` ला दिलेला `authorization`, `x-api-key`, `proxy-authorization` आणि `cookie` शीर्षलेख काढून टाकला आहे आणि API की रेकॉर्डमध्ये कोणतेही मुख्य मूल्य नाही ( `src/lib/plugins/hooks.ts` मध्ये`redactPluginContext()` ).

## जीवनचक्र प्रवाह

```
install (POST /api/plugins, path)
  → मॅनिफेस्ट स्कॅन/प्रमाणित करा → स्टेजिंगमध्ये कॉपी करा → main निर्देशिकेच्या आत असल्याची खात्री करा
  → ~/.omniroute/plugins/<name> मध्ये अणुस्तरीय rename करा → DB पंक्ती समाविष्ट करा
  → onInstall ट्रिगर करा → enabledByDefault असल्यास: activate

activate (POST /api/plugins/{name}/activate)
  → realpath अंतर्भाव तपासणी → loadPlugin() (चाइल्ड प्रोसेस सुरू करा)
  → घोषित hooks नोंदणीकृत करा → status = "active" → onActivate ट्रिगर करा

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate ट्रिगर करा (नोंदणी रद्द करण्यापूर्वी) → hooks ची नोंदणी रद्द करा
  → चाइल्ड प्रोसेस समाप्त करा → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → सक्रिय असल्यास deactivate करा → onUninstall ट्रिगर करा
  → अंतर्भाव-तपासणीसह प्लगइन निर्देशिका पुनरावर्तीपणे हटवा → DB पंक्ती हटवा
```

ज्या निर्देशिकेतील मॅनिफेस्ट आवृत्ती स्थापित आवृत्तीपेक्षा **निश्चितपणे
नवीन** आहे, तिच्यावर `install` पुन्हा चालवल्यास स्वयंचलित अपग्रेड होते (स्वच्छ पुनर्स्थापना; कॉन्फिगरेशन
डीफॉल्ट मूल्यांवर रीसेट होते). समान किंवा जुनी आवृत्ती नाकारली जाते.

## डॅशबोर्ड

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) वरील डॅशबोर्ड पृष्ठ दोन टॅब प्रदान करते:

- **स्थापित केले** — स्थापित प्लगइन्स त्यांच्या घोषित हुकसह, एक activate/deactivate टॉगल, एक अनइंस्टॉल बटण आणि "प्लगइनसाठी स्कॅन" क्रिया (`POST /api/plugins/scan`) सह सूचीबद्ध करते.
- **बाजारपेठ** — कस्टम रेजिस्ट्री URL सेट करण्यासाठी फील्डसह `GET /api/plugins/marketplace` मधील कॅटलॉग दाखवते.

पृष्ठ नेहमी चेतावणी दर्शवते की प्लगइन्स OmniRoute प्रक्रियेच्या पूर्ण विशेषाधिकारांसह चालतात.

प्रति-प्लगइन कॉन्फिगरेशन पृष्ठ `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) वर राहतात.
