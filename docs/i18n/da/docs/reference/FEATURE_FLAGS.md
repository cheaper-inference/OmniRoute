> Runtimekontakter, der ændrer OmniRoutes adfærd **uden en ny udrulning**.
> Alle flag, der er angivet her, er defineret i
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — den eneste autoritative kilde. Både dashboardet og REST API'et læser fra
> denne fil, så tabellen nedenfor genereres, så den matcher den 1:1.

---

## Hvad feature flags er

Et feature flag er en navngivet kontakt (boolean eller enum), hvis værdi kan ændres
under kørsel og gemmes i databasen, uden at processen skal udrulles igen. Hvert
flag beskrives af en `FeatureFlagDefinition` med en `key`, `label`,
`description`, `category`, `defaultValue`, `type` og en `requiresRestart`-angivelse.

### Evalueringsrækkefølge

Et flags **effektive værdi** bestemmes af
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) med følgende
prioritet (højeste vinder):

1. **DB-tilsidesættelse** — en værdi, der er gemt i tabellen `key_value` under
   navnerummet `feature_flags` (angivet via dashboardet eller REST API'et).
2. **Miljøvariabel** — `process.env[<KEY>]`, hvis den er angivet og ikke er tom.
3. **Definitionens standardværdi** — `defaultValue` fra `featureFlagDefinitions.ts`.

Et boolean-flag betragtes som **aktiveret**, når dets effektive værdi er `"true"`,
`"1"` eller `"yes"` (se `isFeatureFlagEnabled()`).

> [!NOTE]
> De fleste flag har også en tilsvarende miljøvariabel med **samme navn**,
> som er dokumenteret i [`ENVIRONMENT.md`](./ENVIRONMENT.md). Flagets
> DB-tilsidesættelse har højere prioritet end denne miljøvariabel. Et flag med
> `requiresRestart: true` gemmes med det samme, men genindlæses først, når
> processen startes — hvis det skiftes, vises banneret **"Genstart server"** i dashboardet.

## Skift flag

### Dashboard

Gå til **Dashboard → Indstillinger → Funktionsflag**
(`/dashboard/settings/feature-flags`). Gitteret
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
understøtter:

- **Søgning** efter nøgle eller beskrivelse og **filtrering** efter kategori (samt en syntetisk visning af
  **Kræver genstart**).
- En **skifteknap** til booleske flag og en **rullemenu** til enum-flag
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Et **kildebadge** pr. flag — `DB`, `ENV` eller `DEF` — der viser, hvor den effektive værdi kommer fra.
- En **Nulstil**-knap (vises kun for flag med kilden `DB`) til at fjerne tilsidesættelsen samt en **Nulstil alle tilsidesættelser**-knap nederst.
- Et **Genstart server**-banner, når et `requiresRestart`-flag ændres.

### REST API

Alle handlinger går gennem en enkelt route:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Alle metoder kræver en godkendt dashboardsession (`401` ellers).

#### `GET /api/settings/feature-flags`

Returnerer alle flag med deres effektive værdi, kilde og en oversigt.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... alle 119 flag
  ],
  "summary": {
    "total": 119,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Angiv eller fjern en enkelt tilsidesættelse. Body: `{ key: string; value?: string }`.
Hvis `value` udelades, fjernes tilsidesættelsen (og miljøvariablen/standardværdien gendannes).

```bash
# Angiv en DB-tilsidesættelse
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Fjern tilsidesættelsen (ingen "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Svaret gentager den nye `effectiveValue`/`source`, den
`previousValue`/`previousSource` og `requiresRestart`. Ukendte nøgler og enumværdier uden for det tilladte område afvises med `400`.

#### `DELETE /api/settings/feature-flags`

Rydder alle DB-tilsidesættelser på én gang og gendanner alle flag til deres miljøvariabel-/standardværdi. Returnerer `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Flag med `requiresRestart: true` træder først i kraft efter en genindlæsning af processen.
> Dashboardets genstartsflow kalder `POST /api/restart` og foretager derefter forespørgsler til
> `GET /api/health/ping`, indtil serveren er tilgængelig igen.

## Nødreserve ved opbrugt budget

`OMNIROUTE_EMERGENCY_FALLBACK` (kategori `runtime`, standardværdi `true`) styrer
nødmekanismen med en gratis reserveløsning i
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Når den er aktiveret, dirigeres anmodninger, der har opbrugt deres budget, til en
gratis reserveudbyder/-model i stedet for at mislykkes med det samme. Indstil den
til `false` (eller `0`) — via kontakten i dashboardet, en DB-tilsidesættelse eller
miljøvariablen `OMNIROUTE_EMERGENCY_FALLBACK` — for at deaktivere denne adfærd og
lade anmodninger med opbrugt budget mislykkes. (Tilgængelig som en kontakt i
dashboardet i PR'er #3741 / #3752.)

Et svar, der leveres via denne reserveløsning, indeholder
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, så en
klient kan se, at anmodningen blev omdirigeret, uden at sammenligne
`X-OmniRoute-Provider` med sin anmodning. Headeren er ikke til stede i noget andet
svar.
