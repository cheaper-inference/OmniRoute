## Oversigt

Search Tools Studio omdanner `/dashboard/search-tools` fra et grundlæggende søgetestmiljø til et
Studio med tre faner, der samler websøgning, webscraping og sideordnet sammenligning af udbydere.

```
┌ Søgeværktøjer ─────────────────────────────────────────────────────────┐
│ [🔍 Søg] [📄 Scrap] [⚖ Sammenlign]              142ms · $0.001  </>    │
│ ⓘ [Guide til modaliteter]                                               │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {indhold i aktiv fane}                  │ ─ Konfiguration             │
│                                          │ Udbyder [auto ∨]            │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (hentning)   │
│                                          │ Type   [web | nyheder]      │
│                                          │ Fuld side [ ] (scraping)    │
│                                          │ Format [md|tekst|html]      │
│                                          │ Rerank-model [∨]            │
└──────────────────────────────────────────┴─────────────────────────────┘
```

---

## Faner

### Søg-fane

Videreudvikler den eksisterende `SearchForm` + `ResultsPanel` + `RerankPanel` til en fane:

- Forespørgsel → resultater (titel, URL, uddrag, relevansscore).
- Provider-metadata i konfigurationsruden (pris, kvote, status).
- Genrangeringssektion: vælg en genrangeringsmodel, omarranger resultaterne, vis `positionDelta`.
- Tom tilstand med CTA, når ingen søgeproviders er konfigureret.
- Søgehistorik via `SearchHistory.tsx`.
- Kalder `POST /v1/search` (eksisterende endpoint, ingen ændringer).

### Scrape-fane

Ny fane til udtrækning af indhold fra en URL via `POST /v1/web/fetch` (oprettet i plan 05):

- Input: URL + indstilling for hele siden + formatvælger (markdown / tekst / HTML).
- Indsend → hent → gengiv `ScrapeResult.tsx`.
- `ScrapeResult` gengiver en markdown-forhåndsvisning + skift til rådata.
- Grænse: Hvis svarindholdet er større end **256 KB**, viser brugerfladen `(afkortet, vis rådata)` og åbner rådata i en Monaco-modal (D21).
- Metadatapanel: provider (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search), latenstid, pris, svarstørrelse, antal links.
- Bruger hooket `useScrapeFetch.ts`.

### Sammenlign-fane

Kører den samme forespørgsel/URL parallelt hos op til **4 providers** (D22):

- Kolonner side om side for hver provider.
- Målinger: latenstid, pris, antal resultater, svarstørrelse.
- Beregning af URL-overlap for søgning (antal delte URL'er sammenlignet med det oprindelige resultat).
- Kalder `POST /v1/search` (søgning) eller `POST /v1/web/fetch` (scraping) for hver provider.

## Konfigurationsrude (fælles)

`SearchToolsConfigPane.tsx` — altid synlig, kan foldes sammen.

| Felt         | Bemærkninger                                                                    |
| ------------ | ------------------------------------------------------------------------------- |
| Udbyder      | Rullemenu med statusbadge (konfigureret / mangler / hastighedsbegrænset)        |
| Type         | `web` eller `news` (kun søgning)                                                |
| Fuld side    | Skifteknap til scraping — henter hele siden frem for det første synlige indhold |
| Format       | `markdown`, `text` eller `html` (kun scraping)                                  |
| Rerank-model | Valgfri model til reranking efter søgning                                       |
| Historik     | Sammenfoldelig sektion med søgehistorik                                         |

---

## SearchConceptCard

`SearchConceptCard.tsx` — altid synlig harmonika, der kan foldes sammen. Forklarer:

| Koncept             | Kort beskrivelse                                                             |
| ------------------- | ---------------------------------------------------------------------------- |
| **Søgning**         | Henter en liste over webresultater (titel, URL, uddrag, relevansscore)       |
| **Scraping**        | Udtrækker hele indholdet fra en URL (markdown, tekst eller HTML)             |
| **Sammenligning**   | Kører den samme forespørgsel i N udbydere side om side                       |
| **Genrangering**    | Omarrangerer resultater via LLM for at forbedre relevansen for forespørgslen |
| **Auto (billigst)** | Vælger automatisk den billigste tilgængelige udbyder                         |

## Udbyderkatalog

`ProviderCatalog.tsx` viser den fulde liste over udbydere fra `GET /api/search/providers`
(udvidet i F4 til at inkludere fetch-udbydere):

| `kind` | `"search"` (20 udbydere) eller `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search, parallel-search) |

Statussen **udledes på anmodningstidspunktet** ved at kontrollere, om legitimationsoplysninger findes, og om
alle nøgler aktuelt er i nedkølingsperioden.

## Eksportér kode

`ExportCodeModal` (importeret fra Playground Studio) + `codeExport.ts` genererer
curl-/Python-/TypeScript-kodestykker til både `/v1/search`- og `/v1/web/fetch`-kald.
Pladsholderen for API-nøglen er altid `$OMNIROUTE_API_KEY` (D11, deles med Playground Studio).

## Backendændringer

Kun én backendændring var nødvendig for denne funktion:

### Udvidet `GET /api/search/providers`

`src/app/api/search/providers/route.ts` blev udvidet til at:

- Inkludere alle fetch-udbydere (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`) i arrayet.
- Tilføje `kind: "search" | "fetch"` til hvert element.
- Tilføje `status: "configured" | "missing" | "rate_limited"` afledt af den aktuelle legitimationsstatus.
- Opretholde bagudkompatibilitet — eksisterende felter (`id`, `name` osv.) er uændrede.

## Fejlfinding

| Symptom                                          | Årsag                                         | Løsning                                                                                               |
| ------------------------------------------------ | --------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Scrape-fanen viser "slutpunkt ikke tilgængeligt" | `/v1/web/fetch` er ikke tilsluttet            | Kontrollér, at plan 05 er flettet; kontrollér, at `src/app/api/v1/web/fetch/route.ts` findes          |
| Udbyderkataloget viser alle som "mangler"        | Legitimationsoplysninger er ikke konfigureret | Tilføj legitimationsoplysninger i `/dashboard/providers`                                              |
| Scrape-indholdet er afkortet                     | Svar > grænsen på 256 KB                      | Forventet adfærd (D21). Brug knappen "vis rådata" for at se hele indholdet                            |
| Sammenlign-fanen viser kun 2 udbydere            | Hastighedsbegrænsning er aktiv                | To eller flere udbydere kan være i nedkølingsperiode — kontrollér udbyderstatus i konfigurationsruden |
| "Størrelse" vises som en rå nøgle i tabellen     | Manglende i18n-nøgle                          | Kontrollér, at `search.size` findes i lokalitetsfilen; genopbyg i18n                                  |
