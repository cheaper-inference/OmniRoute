`@omniroute/opencode-plugin-v2` gør hele dit OmniRoute-katalog — modeller, kombinationer og
automatiske kombinationer — tilgængeligt i OpenCode v2's modelvælger med visningsnavne, priser og
budgetter for gratisniveauet.

Det er en separat pakke fra `@omniroute/opencode-plugin`, fordi OpenCode v1 og v2 indlæser
plugins via forskellige kontrakter. Vælg den, der matcher din primære OpenCode-version; intet
deles mellem dem, så en opgradering af den ene aldrig fremtvinger en opgradering af den anden.

## Krav

- OpenCode v2.
- En tilgængelig OmniRoute-gateway (`http://localhost:20128` som standard).
- Node.js 22 eller 24.

## Installation

Føj pluginet til `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Modeller vises derefter som `omniroute/<provider>/<model>`; `providerId` bestemmer dette præfiks og
id'et for den integration, som OpenCode gemmer legitimationsoplysningerne under.

## Legitimationsoplysninger

Pluginet leder efter en gateway-nøgle tre steder i denne rækkefølge:

1. **De legitimationsoplysninger, du tilsluttede i OpenCode.** Pluginet registrerer en integration, så
   OpenCodes eget godkendelsesflow kan gemme nøglen. Intet ender i `opencode.json` — foretræk dette.
2. `apiKey` i pluginindstillingerne til en projektspecifik tilsidesættelse. Det placerer nøglen i en fil, som du
   muligvis føjer til versionsstyring.
3. `OMNIROUTE_API_KEY` i miljøet.

Hvis ingen af de tre er angivet, er kataloget tomt, og pluginet oplyser dette én gang ved opstart i stedet for
at efterlade dig med en tom modelvælger uden nogen meddelelse.

### Administrationstokenet er en anden nøgle

Kombinationer, udbyderstatus og berigelse (visningsnavne, priser og budgetter for gratisniveauet) kommer fra
gatewayens `/api/*`-endpoints, som de fleste installationer beskytter med et **administrations**token
i stedet for inferensnøglen:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<administrationens læsetoken>"
}
```

Hvis `managementReadToken` ikke er angivet, bruges `apiKey` som reserve. Når en gateway afviser denne reserveløsning,
udgives kataloget stadig, men med rå model-id'er i stedet for visningsnavne, uden deduplikering af kanoniske
aliaser, uden priser og uden kombinationer. Pluginet advarer én gang pr. endpoint, når dette sker,
og angiver endpointet samt det, der gik tabt — så en begrænset modelvælger aldrig er et mysterium.

## Indstillinger

| Nøgle                            | Standard                                                        | Bemærkninger                                                                                                                              |
| -------------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                                   | Udbyder-id, integrations-id og det præfiks, som modeller vises under                                                                      |
| `baseURL`                        | påkrævet                                                        | Gateway-rod, kun `http(s)`; suffikset `/v1` tilføjes, hvor det er nødvendigt                                                              |
| `apiKey`                         | tilknyttet legitimationsoplysning, derefter `OMNIROUTE_API_KEY` | Chatnøgle til `/v1/*`                                                                                                                     |
| `managementReadToken`            | bruger `apiKey` som reserve                                     | Nøgle til `/api/*` — normalt **ikke** den samme                                                                                           |
| `displayName`                    | `"OmniRoute"`                                                   | Udbydernavn i vælgeren                                                                                                                    |
| `timeoutMs`                      | `10000`                                                         | Timeout pr. slutpunkt for fetch (automatiske kombinationer bruger 5 sek.)                                                                 |
| `modelCacheTtlMs`                | `300000`                                                        | TTL for katalogcache; et snapshot på disken fremskynder kolde starter                                                                     |
| `timeouts`                       | bruger `timeoutMs` som reserve                                  | Tidsbudgetter pr. slutpunkt i ms: `models`, `combos`, `autoCombos`, `enrichment`                                                          |
| `enrichment`                     | `true`                                                          | Hent navne, priser og budgetter for gratisniveauet                                                                                        |
| `providerTag`                    | `true`                                                          | Sæt navnet på den upstream-udbyder, som der routes til, foran visningsnavnet                                                              |
| `usableOnly`                     | `false`                                                         | Behold kun udbydere, som gatewayen rapporterer som klargjorte                                                                             |
| `combosSource`                   | `"api"`                                                         | `"models"` springer `/api/combos` over og publicerer kombinationsrækkerne fra `/v1/models`; filtre på medlemsniveau beholder `"api"`      |
| `showcasePerOwner`               | `10`                                                            | Poster i standardvisningen, der beholdes pr. udbyder                                                                                      |
| `freshPerOwner`                  | `10`                                                            | Nye poster i standardvisningen, der beholdes pr. udbyder                                                                                  |
| `freshWindowDays`                | `90`                                                            | Friskhedsperiode i dage for grenen med nye poster                                                                                         |
| `usageMemory`                    | `true`                                                          | Gendan statisk fravalgte poster, der er navngivet i brugsanalyse for 30 dage (kræver et administrationstoken)                             |
| `visibleModels` / `hiddenModels` | `[]`                                                            | Tilladelseslister med eksakte match eller suffiksmatch; afvisning har forrang; `*` publicerer hele kataloget (andre filtre gælder stadig) |
| `geminiSanitization`             | `true`                                                          | Fjern de JSON-Schema-nøgleord, som Gemini afviser, fra værktøjsskemaer (værktøjer med `$ref` videresendes uændret)                        |
| `apiFormat.allowAnthropic`       | `false`                                                         | Send tilladte id'er gennem Anthropic API-blokken                                                                                          |
| `apiFormat.anthropicModels`      | `[]`                                                            | Fuldstændige model-id'er, der sendes til Anthropic                                                                                        |
| `logLevel` / `startupDebug`      | `warn` / `false`                                                | Loggerens detaljeringsgrad                                                                                                                |

Brugshukommelse er aktiveret som standard. Uden et administrationstoken forbliver den inaktiv
(en opstartsmeddelelse logges), og intet gendannes.

## Sådan holdes kataloget opdateret

Kataloget hentes efter behov og caches i `modelCacheTtlMs`, og et snapshot på disken holder det
senest kendte katalog tilgængeligt, når gatewayen ikke kan nås — et nedbrud koster dig kun
aktualitet. Modeller og kombinationer udgives, så snart de ankommer; automatiske kombinationer,
udbyderlisten og berigelseslaget indarbejdes, når de ankommer, så ét langsomt endpoint ikke kan
holde hele vælgeren som gidsel.

Navnene indeholder det, gatewayen ved: den upstream-udbyder, som en model routes til, en `[Free]`-markør
og det budget, der følger med — så to forbindelser, der sælger den samme model, fortsat kan
skelnes fra hinanden. Slå præfikset fra med `"providerTag": false`.

Der findes ingen manuel opdateringskommando: OpenCode v2-kommandoer er promptskabeloner, ikke callbacks,
så et plugin kan ikke eksponere en sådan. Opdateringer følger TTL'en; værten anmodes kun om at genindlæse,
når kataloget eller laget faktisk er ændret, aldrig én gang pr. opdatering.

## Værktøjskald på Gemini

Gemini afviser en hel anmodning, hvis værktøjsdeklarationer indeholder `$schema` eller
`additionalProperties`, med svaret `400 INVALID_ARGUMENT`. Pluginet fjerner disse nøgleord fra
værktøjsskemaer, der er beregnet til en Gemini-model fra denne udbyder, og lader alle andre anmodninger være urørte.
Et værktøj, der indeholder en `$ref`, videresendes urørt i stedet for at blive renset, da fjernelse af
referencen ville udvide skemaet til at "acceptere hvad som helst".
Indstil `"geminiSanitization": false` for at slå det fra.

## Fejlfinding

| Symptom                                           | Årsag                                                                                                                          |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Modelvælgeren viser ingen OmniRoute-model         | Ingen nøgle blev fundet (kontrollér opstartsadvarslen), eller gatewayen kan ikke nås                                           |
| Rå model-id'er, ingen kombinationer, ingen priser | Administrationsendepunkterne afviste tokenet — indstil `managementReadToken`                                                   |
| Kort eller tomt `freeOnly`-katalog                | Intet administrationstoken eller et afvist token — læs oversigtslinjen for opdateringen (`unmatched-free`-antal) i værtsloggen |
| En session fastgjort til `opencode-<id>/…`        | v1-pluginet publicerede `opencode-<id>`; v2 publicerer kun `<id>`, så vælg modellen igen under `<id>/…`                        |

Miljøvariabler skal nå opencode-serverprocessen: Når værten
kører som en tjeneste, er den shell, der kører `opencode models`, og serverens
miljø forskellige, så eksportér nøglen dér, hvor serveren læser den.
