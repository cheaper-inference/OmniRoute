## Gratis poletter om måneden: ~ 11.3B som andre tæller · ~ 90M Real

</div>

> **~ 11.3B gratis tokens / måned**<br/> <sub> talte som andre kataloger tæller: hver række lagt sammen, afsluttede tilbud inkluderet </sub>
>
> **~ 90M ægte i dag**<br/> <sub> hver delt kvote tælles én gang: hvad du faktisk kan bruge </sub>
>
> **Alt her er gratis. Ingen betalingsmur.**<br/> ★ [Kan du lide det? Stjerne os på GitHub](https://github.com/cheaper-inference/OmniRoute)

Andre kataloger opkræver fra US$ 19 om året til US$ 49 for livslang adgang til live data. Her er alt gratis. <sub> Priser tjekket den 2026-11-18.</sub>

<sub>Katalog senest revideret 23-11-2026. [Hvordan vi tæller →](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **Medbring dine egne udbyderkonti.** Disse er tredjeparts gratis niveauer, ikke et symbolsk tilskud fra OmniRoute. Tilmeld dig, få legitimationsoplysninger, hvor en udbyder beder om dem, og tilslut dem, du kan bruge. Hver udbyder sætter sine egne grænser, tilgængelighed og vilkår.
>
> At stable gratis niveauer i hånden betyder snesevis af SDKs, snesevis af satsgrænser og ingen klar idé om, hvad du har tilbage. OmniRoute beholder 214 katalogrækker med fri adgang og beregner det reelle tal ud fra 12 puljer med en offentliggjort kvote, hver delt pulje tælles én gang. Kvoter, der kun åbner efter en regional identitetskontrol (i dag, ModelScope), vises adskilt, +~ 6M bag regional identitetsbekræftelse og føjes aldrig til det reelle tal. Det, der er tilbage, vises på instrumentbrættet (`/dashboard/free-tiers`).

The bar shows where the real figure comes from, one segment per pool. Signup credits and free providers without a token cap are listed apart and never added to it. Live used and remaining tokens on /dashboard/free-tiers."/>

>
> <sub> kataloget sidst revideret den 23-11-2026. Figurerne bevæger sig begge veje. En udbyder afslutter et gratis niveau, og det reelle antal falder. En ny lander og den klatrer. Vi udgiver, hvad kataloget beregner, aldrig en afrundet best case.</sub>

## Installer, tilslut en udbyder, og rul derefter gennem ét slutpunkt

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

## Combos: flagskibet

1. **Start med `auto`.** Indstil modellen i din OpenAI-kompatible klient. OmniRoute bygger en virtuel combo fra tilsluttede udbydere og scorer kandidater live.
2. **Gem en kombination for mere kontrol.** Vælg et navn, en målliste og en strategi, og brug derefter det navn som model. Strategien angiver, hvilket mål der går først, og hvordan resten prøves.

En kombination ruter automatisk på tværs af modeller. Ved kvoteopbrug, udbyderfejl eller modellockout forsøger den det næste kvalificerede, sunde mål.

### Zero-config: brug bare `auto`

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

Varianter tuner vægtene. Sidst kendte-god routing forbliver hos den sidste succesfulde udbyder, indtil den mislykkes, og scorer derefter igen. `auto/fast` og `auto/cheap` udtrykker præferencer uden at garantere den hurtigste eller billigste model.

| Model ID            | Opførsel                                                                                                                                                                                                                                                                          |
| :------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Balancerede standardvægte.                                                                                                                                                                                                                                                        |
| `auto/fast`         | Foretrækker lav latenstid og udbyderens sundhed.                                                                                                                                                                                                                                  |
| `auto/cheap`        | Går ind for lavere katalogpriser.                                                                                                                                                                                                                                                 |
| `auto/coding`       | Kvalitets-første vægte til kodegenerering.                                                                                                                                                                                                                                        |
| `auto/smart`        | Kvalitets-første vægte med 10% udforskning (standard 5%).                                                                                                                                                                                                                         |
| `auto/lkgp`         | Eksplicit sidst kendte gode routing med samme vægte som `auto`.                                                                                                                                                                                                                   |
| `auto/subscription` | Bruger kun liveverificeret plankvote. Returnerer HTTP 503, når ingen er tilgængelig, og undgår faktureret fallback.                                                                                                                                                               |
| `auto/thrifty`      | Planlæg → nøglefri → gratis → billig → premium. Kan nå fakturerede modeller og returnerer til planen, når kvote og nedkøling tillader det.                                                                                                                                        |
| `auto/offline`      | Går ind for kvote- og satsgrænser. Anmodninger går stadig til dine udbydere.                                                                                                                                                                                                      |
| `auto/chaos`        | Én model pr. udbyder parallelt, op til fem som standard eller ti, når den er konfigureret. Ét upstream-opkald pr. model. Returnerer det toprangerede svar eller det sidste vellykkede panelsvar, hvis topmodellen mislykkes. Brug `fusion` til at syntetisere svar med en dommer. |

Eksempler på kategori og valgfrit niveau inkluderer `auto/coding:fast`, `auto/coding:free`, `auto/reasoning:pro` og `auto/vision`. Hvis ingen tilsluttet kandidat matcher, returnerer anmodningen HTTP 503, og puljen forbliver smal. [Auto-Combo guide](./docs/routing/AUTO-COMBO.md) · [Abonnement-første rute](./docs/routing/SUBSCRIPTION_LADDER.md)

### Eller byg din egen: 22 routingstrategier

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

CLI accepterer 15 af 22 strategier. Dashboardet og kombinationerne API accepterer alle 22.

| Strategi            | Opførsel                                                                                                                                                                                                                   |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Rangkandidater lever med 16-faktor Auto-Combo-scoreren.                                                                                                                                                                    |
| `cache-optimized`   | Foretrækker den konto, der sandsynligvis vil have promptpræfikset i cachen.                                                                                                                                                |
| `context-optimized` | Prøv først det største kendte kontekstvindue.                                                                                                                                                                              |
| `context-relay`     | Behold din ordre, og send en samtaleoversigt, når du skifter konto.                                                                                                                                                        |
| `cost-optimized`    | Sorter efter katalog input-token pris, ukendte sidst. Den endelige anmodningspris kan variere.                                                                                                                             |
| `expiry-first`      | Brug kvoten, der sandsynligvis udløber, højeste rest pr. time, indtil nulstillingen først.                                                                                                                                 |
| `fill-first`        | Bliv på det første tilgængelige mål, indtil det løber tør eller fejler, og fortsæt derefter.                                                                                                                               |
| `fusion`            | Forespørg et panel parallelt, og få en dommer til at syntetisere ét svar.                                                                                                                                                  |
| `headroom`          | Vælg den mest ledige kapacitet på tværs af 5-timers og ugentlige vinduer.                                                                                                                                                  |
| `jev`               | TypeSafe Jev vælger, hvilke poster på din rangerede liste, der kører. Slå `COMBO_JEV_STRATEGY_ENABLED` til for at sende et uddrag pr. anmodning og bruge betalte TypeSafe -opkald. Når den er slået fra, gælder din ordre. |
| `least-used`        | Vælg målet med færrest registrerede anmodninger i denne kombination.                                                                                                                                                       |
| `lkgp`              | Prøv den sidste succesfulde udbyder først, ellers behold din ordre.                                                                                                                                                        |
| `p2c`               | Prøv to mål, og vælg efter succesrate og latenstid.                                                                                                                                                                        |
| `pipeline`          | Før hvert trins output ind i det næste mål i rækkefølge og returner kun det endelige svar.                                                                                                                                 |
| `priority`          | Prøv mål i din ordre. Session klæbrighed bevarer det.                                                                                                                                                                      |
| `quota-weighted`    | Spring over opbrugte konti og træk efter resterende kvote og last under flyvningen.                                                                                                                                        |
| `random`            | Bland for hver anmodning. Det samme første mål kan gentages.                                                                                                                                                               |
| `reset-aware`       | Giv den resterende kvote og tid til at nulstille på tværs af sessions- og ugentlige vinduer.                                                                                                                               |
| `reset-window`      | Prøv den konto, hvis kvotevindue nulstilles hurtigst.                                                                                                                                                                      |
| `round-robin`       | Roter i rækkefølge, tre succeser pr. mål som standard.                                                                                                                                                                     |
| `strict-random`     | Deal fra et blandet dæk, så hvert mål fører én gang før gentagelser.                                                                                                                                                       |
| `weighted`          | Tegn et første mål efter vægt og behold resten som fallbacks. Opdelingen er statistisk. Brug `round-robin` til streng rotation.                                                                                            |

Kvotestrategier bruger live data, hvor udbydere rapporterer det, inklusive 5-timers og ugentlige abonnementsvinduer. `fusion` og `pipeline` foretager flere upstream-opkald pr. anmodning.

16-faktorscoreren bruger kvote, sundhed, omkostninger, latens, opgavetilpasning, stabilitet, niveauprioritet, niveauaffinitet, specificitetsmatch, kontekstaffinitet, cache-affinitet, sessionstilgængelighed, nulstil-vinduesaffinitet, forbindelsestæthed, kvalitet og pålidelighed. Vægten varierer efter profil. Cache-affinitet, nulstil-vindue-affinitet og pålidelighed har som standard nul vægt. [Scorefaktorer](./docs/routing/AUTO-COMBO.md#how-it-works-persisted-auto-combos)

### Resiliens er indbygget i: 3 uafhængige lag

Fejl håndteres i tre omfang, så én dårlig model fjerner ikke sin konto, og én dårlig konto fjerner ikke sin udbyder.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Hvis en hel udbyder er nede

De** udbyder afbryder** åbner efter 8 (OAuth) eller 12 (API nøgle) fejl med status 408, 500, 502, 503 eller 504. Kombinationer springer den udbyder over, mens den er åben. Efter 60 s eller 30 s, beslutter en probeanmodning, om den lukker.

#### Hvis én nøgle eller konto er satsbegrænset

De** nedkøling af forbindelsen** bænke kun den forbindelse, med eksponentiel backoff fra 5 s (OAuth) eller 3 s (API key). Andre nøgler for samme udbyder bliver ved med at tjene.

#### Hvis én model nægtes

De** model lockout** blokerer kun den model på den forbindelse efter en per-model 429, 404 eller adgangsnægtelse. Andre modeller på samme forbindelse bliver ved med at tjene.

Forbudte, udløbne og ikke-kreditforbindelser er terminaltilstande, ikke nedkøling: de venter på, at du løser dem.

## Fuld CLI, MCP og A2A

> OmniRoute sender en kommandolinjeklient med** 91 kommandoer og kommandogrupper på øverste niveau** (754 kommandoer, der tæller underkommandoer), en**MCP server med 110 værktøjer og 33 scopes** , og en**A2A agent med 6 færdigheder** . Scripts, terminaler og AI -agenter kan alle betjene den samme gateway.

### En rigtig CLI, ikke kun `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

Det globale `--output table|json|jsonl|csv` flag gør de samme kommandoer anvendelige fra scripts og CI.

### Fjerntilstand: CLI på din bærbare computer, OmniRoute på en server

Log ind én gang på en ekstern server. CLI gemmer den som en** sammenhæng** , og senere kommandoer kører mod den server, indtil du skifter tilbage.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Token-omfang | <img width="2000" height="0" alt=""> Hvad det tillader              |
| ------------ | ------------------------------------------------------------------- |
| `read`       | Liste og inspicere: modeller, status, logfiler, brug                |
| `write`      | `read` plus konfigurere og anvende: klientopsætning, nøgler, config |
| `admin`      | `write` plus administrere: tokens, udbydere, tjenester, politik     |

En bar vært får `http://` og port 20128; videregive en fuld `https://` URL når serveren sidder bag TLS. Ruter, der kan afføde processer, forbliver kun loopback, uanset tokenet.

### Tilslut en agent

En agent eller din egen kode kan drive routing, udbydere, kombinationer, cache, komprimering og hukommelse gennem enhver af disse grænseflader. HTTP stier betjenes af gatewayen, som standard ved `http://localhost:20128`.

| Interface               | Slutpunkt eller kommando   | Brug det til                                                                          |
| ----------------------- | -------------------------- | ------------------------------------------------------------------------------------- |
| MCP over stdio          | `omniroute --mcp`          | Claude Desktop, Cursor og andre lokale MCP klienter                                   |
| MCP over Streambar HTTP | `/api/mcp/stream`          | Remote MCP klienter: 110 værktøjer, 33 scopes, hvert kald skrevet til revisionsloggen |
| MCP over SSE            | `/api/mcp/sse`             | Kunder, der stadig bruger SSE transporten                                             |
| A2A opdagelse           | `/.well-known/agent.json`  | Agentkort: fortæller andre agenter, hvad OmniRoute kan gøre                           |
| A2A udførelse           | `POST /a2a`                | JSON-RPC 2.0 opgaver, synkrone eller streamet over SSE, på tværs af 6 færdigheder     |
| REST API                | `/v1/*`                    | OpenAI-kompatibel chat, svar, indlejringer, billeder, lyd og OCR                      |
| Webhooks                | `/api/webhooks`            | Begivenheder til Slack, Discord, Telegram eller enhver URL med HMAC -signering        |
| Fjernbetjening CLI      | `omniroute connect <host>` | Kør en fjernforekomst med scoped adgangstokens                                        |

De seks A2A -færdigheder er `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` og `list-capabilities`.

**Før du opretter forbindelse:**

- **MCP over HTTP starter deaktiveret.** Tænd det med `omniroute mcp enable --transport streamable-http` eller fra dashboardets Endpoints-side. Én HTTP -transport er aktiv ad gangen: `streamable-http` tjener `/api/mcp/stream`, `sse` tjener `/api/mcp/sse`.
- **A2A starter deaktiveret.** Aktiver det på dashboardets Endpoints-side. `POST /a2a` følger derefter de samme API-nøgleregler som `/v1`.
- **Remote MCP har brug for en passende nøgle.** `/api/mcp/*` svarer kun loopback som standard. Fra en anden vært, send en nøgle med `manage` eller `admin` (alle værktøjer), eller med `mcp:connect` plus omfanget af de værktøjer, du har brug for. For nøgler uden `manage`/`admin` håndhæves værktøjsomfang altid.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

## Spar 15–95 % tokens — automatisk

### Sådan fungerer det — pipeline, arkitektur og besparelser matematik

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

Standard stablet combo kører `RTK → Caveman`. Når begge virker på den samme tool/context nyttelast, spares sammensætning:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Kodeblokke, URLs, JSON og strukturerede data er** altid beskyttet** af konserveringsmotoren.

> **Hvorfor bruge mange tokens, når få tokens gør tricket?** Hver anmodning passerer gennem OmniRoute kompressionspipeline** gennemsigtigt** — ingen klientændringer. Det er nu en** stak af 12 komponerbare motorer** der kører i rækkefølge og mix & match pr routing combo — bygger på ideer fra [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) og [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

| Indstilling | Valgmuligheder                                                                                                                                                                          |

| Mode        | `floor` kan eskalere den valgte plan, så den passer til kontekstvinduet. `replace-autotrigger` bruger budgettet til automatisk eskalering. `off` beholder token-tærsklens auto-trigger. |

## Flere installationsmetoder — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` følger den højeste** offentliggjort** stabil SemVer. Den sporer ikke git `main`. Pin `:X.Y.Z` til GitOps. Se [Docker Release Channels](docs/guides/DOCKER_GUIDE.md#release-channels).Billedets stifter**`OMNIROUTE_MEMORY_MB=1024`** . Det er nok til instrumentbrættet og en let snak.** Kodningsmidler** (`POST /v1/responses` fra Claude Code, Codex, Grok, …) har brug for en meget større V8-heap eller processen `FATAL ERROR` s ved ~ 12 GiB under to overlappende lange sammenhænge. Størrelse på beholderen over bunken (native buffere sidder uden for V8):

| <img width="2000" height="0" alt=""> Arbejdsbyrde | Heap (`-e OMNIROUTE_MEMORY_MB`) | Container (`--memory`) |
| ------------------------------------------------- | ------------------------------- | ---------------------- |
| Dashboard / let chat                              | `1024` (standardbillede)        | ≥ 2 g                  |
| Én kodningsagent                                  | `8192`                          | ≥ 10 g                 |
| To samtidige lange `/v1/responses`                | `10240`–`12288`                 | ≥ 12-16 g              |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Fuld tabel: [Docker Guide — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Pre-release Docker kanal:** `diegosouzapw/omniroute:next` og `diegosouzapw/omniroute:next-web` følger den nuværende standard `release/v*` -gren. Disse mutable tags er kun beregnet til at teste ikke-udgivne rettelser og er** ikke understøttet til produktion** . Se [Docker udgivelseskanaler](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

Standard `bun install` og global installation (`bun install -g omniroute`) understøttes via Bun runtime detektion:

- **Indbygget `bun:sqlite`** : OmniRoute bruger Bun's indbyggede `bun:sqlite` -driver, når den kører under Bun, falder tilbage til `better-sqlite3` på Node.js eller `sql.js`.
- **Automatisk Webpack bundler valg i dev** : Udvikling (`bun run dev`) registrerer automatisk Bun og deaktiverer Turbopack til fordel for Webpack for at forhindre native V8-bindingsinkompatibiliteter. Produktionsbyg (`bun run build`) følger `OMNIROUTE_USE_TURBOPACK` nøjagtigt som på Node: Turbopack som standard, `OMNIROUTE_USE_TURBOPACK=0` for at bygge med Webpack (`Dockerfile.bun` udsætter det som en `--build-arg`).
- **Dedikeret Bun Dockerfile** : Flertrins `Dockerfile.bun` til native Bun -produktionsinstallationer (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ Hurtigere / slankere installation (spring over den oprindelige build)**

Den oprindelige SQLite motor (`better-sqlite3`) er en** valgfri** afhængighed, så en global installation blokerer aldrig for kompilering fra kilden: den bruger en forudbygget binær, når en matcher din platform/Node, og falder ellers transparent tilbage til en ren-JS-motor (`node:sqlite` på Node 22 +, ellers den medfølgende `sql.js` WASM) — kræves ingen byggeværktøjer.

For at springe over efterinstallationen** indfødt opvarmning** helt (CI, hovedløse eller langsomme maskiner). Bemærk: dette springer kun det oprindelige SQLite -opvarmningstrin over (`scripts/postinstall.mjs`); binary-copy/repair krogen (`scripts/build/postinstall.mjs`) kører stadig normalt:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

For de hurtigste installationer foretrækkes** pnpm** (indholdsadresseret butik + hard links — se ovenfor). Brug Docker `base` profilen (ovenfor) eller [Termux-guiden](docs/guides/TERMUX_GUIDE.md) for en dashboard-fri, hovedløs køretid. CLI og web-dashboardet betjenes af den samme proces på én port, så der er ingen separat CLI-only-pakke i dag.

## Anerkendelser

OmniRoute står på skuldrene af giganter. Det startede som en gaffel af** [9 router](https://github.com/decolua/9router)** og en TypeScript port af Go-projektet** [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)** — og derfra var hvert undersystem nedenfor inspireret af et open source-projekt, der kom der først. Hver af dem formede et betonstykke af OmniRoute. Dette er vores tak til dem alle. 🙏

> Antallet af ⭐ stjerner bekræftet fra GitHub's REST API den 16. november 2026 — go give disse projekter en stjerne. Optællinger er et nøjagtigt dateret øjebliksbillede og vil naturligvis ændre sig. GrokBridge returnerede HTTP 404 på den dato; dens tilskrivning bevares.
