## 🎯 Các trường hợp sử dụng

### Trường hợp 1: "Tôi có gói đăng ký Claude Pro"

**Vấn đề:** Hạn mức hết hạn khi chưa sử dụng, bị giới hạn tốc độ trong lúc lập trình cường độ cao

```
Combo: "maximize-claude"
  1. cc/claude-opus-4-7        (tận dụng tối đa gói đăng ký)
  2. glm/glm-4.7               (phương án dự phòng giá rẻ khi hết hạn mức)
  3. if/qwen3.8-max-preview       (phương án dự phòng khẩn cấp miễn phí)

Chi phí hằng tháng: $20 (gói đăng ký) + ~$5 (dự phòng) = tổng cộng $25
so với $20 + chạm giới hạn = bực bội
```

### Trường hợp 2: "Tôi muốn chi phí bằng không"

**Vấn đề:** Không đủ khả năng chi trả cho các gói đăng ký, cần AI lập trình đáng tin cậy

```
Combo: "zero-cost"
  1. if/kimi-k2.7-code          (được liệt kê là có quyền truy cập miễn phí; có thể áp dụng giới hạn tốc độ)
  2. kr/qwen3-coder-next        (phương án dự phòng Kiro miễn phí)

Chi phí hằng tháng: $0
Chất lượng: hãy xác minh mô hình, giới hạn, quyền riêng tư và SLA cho khối lượng công việc của bạn
```

### Trường hợp 3: "Tôi cần lập trình 24/7, không bị gián đoạn"

**Vấn đề:** Có thời hạn gấp, không thể chấp nhận thời gian ngừng hoạt động

```
Combo: "always-on"
  1. cc/claude-opus-4-7        (chất lượng tốt nhất)
  2. cx/gpt-5.5                (gói đăng ký thứ hai)
  3. glm/glm-4.7               (giá rẻ, đặt lại hằng ngày)
  4. minimax/MiniMax-M2.1      (rẻ nhất, đặt lại sau 5 giờ)
  5. if/deepseek-v4-flash       (được liệt kê là có quyền truy cập miễn phí; có thể áp dụng giới hạn tốc độ)

Kết quả: 5 lớp dự phòng giúp tăng khả năng phục hồi; tính khả dụng của dịch vụ đầu nguồn không được đảm bảo
Chi phí hằng tháng: $20-200 (gói đăng ký) + $10-20 (dự phòng)
```

### Trường hợp 4: "Tôi muốn AI MIỄN PHÍ trong OpenClaw"

**Vấn đề:** Cần trợ lý AI trong các ứng dụng nhắn tin, hoàn toàn miễn phí

```
Combo: "openclaw-free"

  2. if/deepseek-v4-flash       (được liệt kê là có quyền truy cập miễn phí; có thể áp dụng giới hạn tốc độ)
  3. if/kimi-k2.7-code          (được liệt kê là có quyền truy cập miễn phí; có thể áp dụng giới hạn tốc độ)

Truy cập qua: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 Thiết lập nhà cung cấp

Để thêm hàng loạt kết nối khóa API từ tệp CSV hoặc JSON, hãy sử dụng **Bảng điều khiển → Nhà cung cấp → Nhập từ tệp**. Các cột được xác định theo vị trí (`provider,name,apiKey,baseUrl,priority`); `provider` phải tồn tại sẵn dưới dạng nhà cung cấp được quản lý hoặc một nút tương thích. Xem [Nhập nhà cung cấp từ tệp CSV hoặc JSON](../providers/CSV-IMPORT.md).

### 🔐 Nhà cung cấp theo gói đăng ký

#### Claude Code (Pro/Max)

```bash
Bảng điều khiển → Nhà cung cấp → Kết nối Claude Code
→ Đăng nhập OAuth → Tự động làm mới token
→ Theo dõi hạn mức 5 giờ + hàng tuần

Mô hình:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**Mẹo chuyên nghiệp:** Dùng Opus cho các tác vụ phức tạp, Sonnet khi cần tốc độ. OmniRoute theo dõi hạn mức theo từng mô hình!

Không có trình duyệt trên máy chủ OmniRoute? Chạy `claude setup-token` ở bất kỳ đâu đã đăng nhập Claude Code và dán token có thời hạn một năm vào tab **Setup Token**. Xem [Claude Code với setup token](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

Các tuyến Claude và tương thích với Claude Code duy trì mức nỗ lực suy luận `max` cho các mô hình Opus và Sonnet. Các mô hình Haiku không chấp nhận mức nỗ lực `max`, vì vậy OmniRoute sẽ hạ yêu cầu đó xuống ngân sách suy luận cao trước khi gửi đến dịch vụ thượng nguồn.

### 💰 Nhà cung cấp giá rẻ

#### GLM-4.7 (Đặt lại hàng ngày, $0.6/1M)

1. Đăng ký: [Zhipu AI](https://open.bigmodel.cn)
2. Lấy khóa API từ Coding Plan
3. Bảng điều khiển → Thêm khóa API: Nhà cung cấp: `glm`, Khóa API: `your-key`

**Sử dụng:** `glm/glm-4.7` — **Mẹo chuyên nghiệp:** Coding Plan cung cấp hạn mức gấp 3 lần với chi phí bằng 1/7! Đặt lại hàng ngày lúc 10:00 sáng.

#### MiniMax M2.1 (Đặt lại sau 5 giờ, $0.20/1M)

1. Đăng ký: [MiniMax](https://www.minimax.io)
2. Lấy khóa API → Bảng điều khiển → Thêm khóa API

**Sử dụng:** `minimax/MiniMax-M2.1` — **Mẹo chuyên nghiệp:** Lựa chọn rẻ nhất cho ngữ cảnh dài (1M token)!

#### Kimi K2 (Cố định $9/tháng)

1. Đăng ký gói: [Moonshot AI](https://platform.kimi.ai?aff=omniroute)
2. Lấy khóa API → Bảng điều khiển → Thêm khóa API

**Sử dụng:** `kimi/kimi-k2.5` — **Mẹo chuyên nghiệp:** Mức cố định $9/tháng cho 10M token = chi phí thực tế $0.90/1M!

#### Baidu Qianfan / ERNIE

## 🚀 Triển khai

### Cài đặt npm toàn cục (Khuyến nghị)

```bash
npm install -g omniroute

# Tạo thư mục cấu hình
mkdir -p ~/.omniroute

# Tạo tệp .env (xem .env.example)
cp .env.example ~/.omniroute/.env

# Khởi động máy chủ
omniroute
# Hoặc với cổng tùy chỉnh:
omniroute --port 3000
```

CLI tự động tải `.env` từ `~/.omniroute/.env` hoặc `./.env`.

### Chế độ khay hệ thống

Khởi động OmniRoute trong khay hệ thống:

```bash
omniroute serve --tray
```

Lệnh sẽ kết thúc sau khi máy chủ và khay hệ thống sẵn sàng.

Máy chủ tiếp tục chạy mà không cần cửa sổ dòng lệnh.

Chế độ khay hệ thống hỗ trợ macOS, Windows và các phiên Linux có giao diện đồ họa. Chế độ khay hệ thống không tự động mở bảng điều khiển.

Sử dụng menu khay hệ thống cho các thao tác sau:

- Mở bảng điều khiển.
- Mở `/dashboard/logs`.
- Thay đổi chế độ tự động khởi động.
- Dừng OmniRoute.

Không kết hợp `--tray` với các tùy chọn sau:

- `--daemon`
- `--log`
- `--no-recovery`

Các chế độ này yêu cầu quyền sở hữu tiến trình khác nhau.

Bật khởi động cùng hệ thống vào lần đăng nhập máy tính tiếp theo:

```bash
omniroute autostart enable
```

Tính năng tự động khởi động sử dụng chế độ khay hệ thống trên macOS, Windows và các phiên Linux có giao diện đồ họa. Linux không có giao diện đồ họa sử dụng dịch vụ người dùng systemd hiện có.

Tắt khởi động cùng hệ thống khi đăng nhập:

```bash
omniroute autostart disable
```

### Gỡ cài đặt

Khi không còn cần OmniRoute, chúng tôi cung cấp hai tập lệnh nhanh để gỡ bỏ sạch sẽ:

| Lệnh                     | Hành động                                                                                           |
| ------------------------ | --------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | Gỡ ứng dụng khỏi hệ thống nhưng **giữ lại cơ sở dữ liệu và cấu hình của bạn** trong `~/.omniroute`. |
| `npm run uninstall:full` | Gỡ ứng dụng VÀ **xóa vĩnh viễn tất cả cấu hình, khóa và cơ sở dữ liệu**.                            |

> Lưu ý: Để chạy các lệnh này, hãy chuyển đến thư mục dự án OmniRoute (nếu bạn đã sao chép kho lưu trữ) rồi chạy chúng. Ngoài ra, nếu đã cài đặt toàn cục, bạn chỉ cần chạy `npm uninstall -g omniroute`.

### Void Linux (xbps-src)

Người dùng Void Linux có thể đóng gói và cài đặt OmniRoute theo cách nguyên bản bằng framework biên dịch chéo `xbps-src`. Quy trình này tự động hóa việc xây dựng bản độc lập Node.js cùng với các liên kết native `better-sqlite3` bắt buộc.

```bash
# Tệp template cho 'omniroute'
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"

export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# Xác định kiến trúc CPU đích cho node-gyp
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) Cài đặt tất cả dependency – bỏ qua script
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Xây dựng gói độc lập Next.js
	npm run build

	# 3) Sao chép tài nguyên tĩnh vào gói độc lập
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) Biên dịch liên kết native better-sqlite3
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) Đặt liên kết đã biên dịch vào gói độc lập
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) Xóa các gói sharp dành riêng cho từng kiến trúc
	rm -rf .next/standalone/node_modules/@img

	# 7) Sao chép các dependency runtime của pino bị quá trình phân tích tĩnh Next.js bỏ sót:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# Ngăn hook sau cài đặt xóa các thư mục app router Next.js trống
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

### Biến môi trường

| Biến                                    | Mặc định                             | Mô tả                                                                                                                              |
| --------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `JWT_SECRET`                            | `omniroute-default-secret-change-me` | Khóa bí mật dùng để ký JWT (**phải thay đổi trong môi trường production**)                                                         |
| `INITIAL_PASSWORD`                      | `CHANGEME`                           | Mật khẩu đăng nhập lần đầu                                                                                                         |
| `DATA_DIR`                              | `~/.omniroute`                       | Thư mục dữ liệu (cơ sở dữ liệu, mức sử dụng, nhật ký)                                                                              |
| `PORT`                                  | mặc định của framework               | Cổng dịch vụ (`20128` trong các ví dụ)                                                                                             |
| `HOSTNAME`                              | mặc định của framework               | Máy chủ để liên kết (Docker mặc định là `0.0.0.0`)                                                                                 |

| `API_KEY_SECRET`                        | `endpoint-proxy-api-key-secret`      | Khóa bí mật HMAC dành cho các khóa API được tạo                                                                                    |
| `REQUIRE_API_KEY`                       | `false`                              | Bắt buộc sử dụng khóa API Bearer trên `/v1/*`                                                                                      |
| `ALLOW_API_KEY_REVEAL`                  | `false`                              | Cho phép người dùng bảng điều khiển đã xác thực xem toàn bộ giá trị khóa API được lưu trữ khi có yêu cầu                           |

### Provider tùy chỉnh tương thích OpenAI

Bất kỳ gateway nào sử dụng OpenAI API (proxy tự host, vLLM, một bên tổng hợp bên thứ ba)
đều có thể được thêm như một provider node riêng:

1. **Providers → Add OpenAI Compatible**.
2. **Name**: nhãn hiển thị cho node.
3. **Prefix**: tên dùng để định tuyến. Client gọi model theo dạng `<prefix>/<model>`, nên node có
   prefix `mygw` sẽ phục vụ `mygw/gpt-4o-mini`. Bắt buộc; không giới hạn ký tự.
4. **API Type**: nhóm endpoint mà gateway phục vụ (Chat Completions, Responses,
   Embeddings, audio, hình ảnh).
5. **Base URL**: gốc của API, bao gồm cả phần `/v1` (ví dụ
   `https://gateway.example.com/v1`), không phải đường dẫn đầy đủ `/chat/completions`. Các gateway có
   đường dẫn không chuẩn sẽ thiết lập chúng trong **Advanced Settings** (chat path, models path).
6. Trường **API Key (for Check)** chỉ dùng để kiểm tra kết nối. Sau khi tạo node,
   hãy mở node đó và dùng **Add Connection** để lưu key mà các request sẽ sử dụng.

Node sẽ được gán một id nội bộ dạng `openai-compatible-<apiType>-<uuid>`; bạn không bao giờ
cần nhập id này, prefix chính là tên công khai.

#### Prefix bị dành riêng

Prefix không được trùng id hoặc alias của một provider tích hợp sẵn (ví dụ `openai`, `cf`), cũng
không được trùng id của một provider đã ngừng hỗ trợ. Trình phân giải model kiểm tra id và alias
tích hợp sẵn trước các node tùy chỉnh, nên node dùng một trong các prefix đó sẽ không bao giờ nhận
được traffic: `<prefix>/model` sẽ được chuyển đến provider tích hợp sẵn, hoặc bị fail closed nếu
provider đó đã ngừng hỗ trợ. Việc tạo hoặc chỉnh sửa node với prefix như vậy sẽ bị từ chối với thông báo:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

Hãy chọn một prefix khác biệt (`mygw`, `acme-proxy`). Nếu request đến node tùy chỉnh thất bại với
lỗi nhắc đến một provider tích hợp sẵn hoặc credential của provider đó, hãy kiểm tra xem prefix của
node có bị dành riêng không: các node được lưu trước khi quy tắc này tồn tại vẫn được giữ lại,
nhưng prefix của chúng sẽ định tuyến sang provider tích hợp sẵn. Hãy chỉnh sửa node và đặt prefix mới.

#### Tùy chọn gateway theo từng kết nối

Các key này nằm trong `providerSpecificData` của một kết nối (ví dụ qua
`PUT /api/providers/{id}`):

- `toolNameMaxLength` (số nguyên, 1–1024) — dành cho các kết nối tương thích định dạng chat
  của OpenAI khi gateway từ chối tên tool quá dài. Các tên dài hơn sẽ được gửi dưới dạng alias ngắn
  và được khôi phục lại trong response.
- `quotaEndpoint` — endpoint quota/credits của gateway, được đọc để hiển thị dải quota trên dashboard
  và phục vụ định tuyến theo quota. Hoạt động trên cả kết nối tương thích OpenAI lẫn Anthropic;
  cấu trúc đầy đủ được mô tả trong `open-sse/services/usage/openaiCompatible.ts`.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### Kết nối chuỗi các peer OmniRoute

Một gateway OmniRoute khác có thể được thêm như một provider **Custom OpenAI-compatible**. Hãy dùng
base URL `/v1` của peer và một API key riêng, có quyền tối thiểu do peer đó cấp.

Với các chuỗi hai chiều hoặc nhiều hop, hãy bật cơ chế chống vòng lặp (opt-in) trên mọi gateway:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

Chỉ các request gửi đến URL peer được liệt kê rõ ràng trong allowlist mới nhận header
`X-OmniRoute-Peer-Trace`. Gateway sẽ từ chối một instance ID bị lặp hoặc hạn mức hop đã cạn
với HTTP `508 Loop Detected`; các provider upstream thông thường không nhận bất kỳ metadata peer nào.

Kết nối chuỗi peer không phải là replication cơ sở dữ liệu hay failover host. Mỗi gateway giữ
trạng thái SQLite, cache, bộ đếm rate limit và session độc lập. Hãy dùng reverse proxy có
health-check hoặc failover phía client để đạt độ sẵn sàng active/passive hoặc active/active, và
tuyệt đối không mount một cơ sở dữ liệu SQLite vào nhiều instance OmniRoute đang chạy.

### Chiến lược Định tuyến

Cấu hình qua **Dashboard → Settings → Routing**. Dashboard hiển thị sáu chiến lược được dùng nhiều nhất; các combo và auto-router bên trong hỗ trợ một tập lớn hơn.

**Các chiến lược hiển thị trên Dashboard (định tuyến cấp tài khoản):**

| Chiến lược                     | Mô tả                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| **Fill First**                 | Dùng các tài khoản theo thứ tự ưu tiên — tài khoản chính xử lý mọi request cho đến khi không khả dụng        |
| **Round Robin**                | Luân phiên qua tất cả tài khoản với giới hạn sticky có thể cấu hình (mặc định: 3 lần gọi mỗi tài khoản)      |
| **P2C (Power of Two Choices)** | Chọn ngẫu nhiên 2 tài khoản và định tuyến tới tài khoản khỏe hơn — cân bằng tải dựa trên tình trạng sức khỏe |
| **Random**                     | Chọn ngẫu nhiên một tài khoản cho mỗi request bằng thuật toán xáo trộn Fisher-Yates                          |
| **Least Used**                 | Định tuyến tới tài khoản có timestamp `lastUsedAt` cũ nhất, phân phối lưu lượng đều nhau                     |
| **Cost Optimized**             | Định tuyến tới tài khoản có giá trị priority thấp nhất, tối ưu cho các provider chi phí thấp nhất            |

**Các chiến lược combo và auto nâng cao** (có thể cấu hình theo từng combo hoặc qua tiền tố `auto/*` — xem [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — thứ tự nghiêm ngặt, không bao giờ round-robin
- `weighted` — chia lưu lượng theo tỷ lệ dựa trên trọng số của từng model
- `fill-first` — dồn hết vào model đầu tiên cho đến khi chạm giới hạn
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` và `cost-optimized`
- `auto` — định tuyến dựa trên điểm số trên tất cả ứng viên
- `lkgp` (Last Known Good Provider) — ghim vào provider thành công gần nhất, sau đó quay về các quy tắc
- `context-optimized` — chọn model có cửa sổ ngữ cảnh trống lớn nhất
- `context-relay` — nối chuỗi các model ngữ cảnh dài cho các lượt tiếp theo

Để gắn kết session từ bên ngoài (ví dụ, các agent Claude Code/Codex phía sau reverse proxy), hãy gửi:

```http
X-Session-Id: your-session-key
```

OmniRoute cũng chấp nhận `x_session_id` và trả về khóa session hiệu lực trong `X-OmniRoute-Session-Id`.

Nếu bạn dùng Nginx và gửi các header dạng gạch dưới, hãy bật:

```nginx
underscores_in_headers on;
```

#### Alias Model Wildcard

Tạo các mẫu wildcard để ánh xạ lại tên model:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

Wildcard hỗ trợ `*` (bất kỳ ký tự nào) và `?` (một ký tự).

#### Chuỗi Fallback

Định nghĩa các chuỗi fallback toàn cục áp dụng cho mọi request:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### Khả năng phục hồi & Circuit Breaker

Cấu hình qua **Dashboard → Settings → Resilience**.

OmniRoute triển khai khả năng phục hồi ở cấp nhà cung cấp với năm thành phần:

1. **Request Queue & Pacing** — Định hình yêu cầu ở cấp hệ thống:
   - **Requests Per Minute (RPM)** — Số yêu cầu tối đa mỗi phút cho mỗi tài khoản
   - **Min Time Between Requests** — Khoảng cách tối thiểu (tính bằng mili giây) giữa các yêu cầu
   - **Max Concurrent Requests** — Số yêu cầu đồng thời tối đa cho mỗi tài khoản

2. **Connection Cooldown** — Cấu hình theo từng loại xác thực cho một kết nối riêng lẻ sau các lỗi có thể thử lại:
   - **Base Cooldown** — Khoảng thời gian cooldown mặc định cho các lỗi upstream có thể thử lại
   - **Use Upstream Retry Hints** — Tuân theo các gợi ý `Retry-After` hoặc gợi ý reset có thẩm quyền khi được cung cấp
   - **Max Backoff Steps** — Mức backoff lũy thừa tối đa cho các lỗi lặp lại

3. **Provider Circuit Breaker** — Theo dõi lỗi nhà cung cấp toàn trình, đánh dấu nhà cung cấp bị suy giảm khi đạt ngưỡng cảnh báo đã cấu hình, và mở breaker khi đạt ngưỡng lỗi đã cấu hình:
   - **Degradation Threshold** — Số lỗi nhà cung cấp liên tiếp trước khi chuyển sang `DEGRADED`
   - **Failure Threshold** — Số lỗi nhà cung cấp liên tiếp trước khi chuyển sang `OPEN`
   - **Reset Timeout** — Khoảng thời gian trước khi nhà cung cấp được kiểm tra lại
   - **CLOSED** (Khỏe mạnh) — Các yêu cầu được đi qua bình thường
   - **DEGRADED** — Các yêu cầu vẫn được đi qua trong khi các lỗi gia tăng được theo dõi
   - **OPEN** — Nhà cung cấp tạm thời bị chặn sau các lỗi lặp lại
   - **HALF_OPEN** — Đang kiểm tra xem nhà cung cấp đã phục hồi hay chưa

   Các giới hạn tốc độ `429` ở phạm vi kết nối vẫn nằm trong **Connection Cooldown** và không được tính vào breaker của nhà cung cấp.

   Trạng thái runtime của provider breaker chỉ được hiển thị tại **Dashboard → Health**.

4. **Wait For Cooldown** — Nếu mọi kết nối khả dụng đều đang trong thời gian cooldown, OmniRoute có thể chờ thời điểm cooldown sớm nhất và tự động thử lại cùng một yêu cầu của client.

5. **Rate Limit Auto-Detection** — Khi các nhà cung cấp upstream trả về khoảng thời gian chờ rõ ràng, các gợi ý đó sẽ ghi đè cooldown kết nối cục bộ khi cài đặt này được bật.

**Mẹo:** Sử dụng trang **Health** để kiểm tra và đặt lại các provider breaker đang hoạt động sau sự cố ngừng hoạt động. Trang Resilience chỉ thay đổi cấu hình.

### Chiến lược Cân bằng Combo

Cấu hình cân bằng cho từng combo trong **Dashboard → Combos → Create/Edit → Strategy**.

| Chiến lược         | Mô tả                                                                    |
| ------------------ | ------------------------------------------------------------------------ |
| **Round-Robin**    | Xoay vòng qua các model một cách tuần tự                                 |
| **Priority**       | Luôn thử model đầu tiên; chỉ fallback khi gặp lỗi                        |
| **Random**         | Chọn ngẫu nhiên một model trong combo cho mỗi request                    |
| **Weighted**       | Định tuyến theo tỷ lệ dựa trên trọng số được gán cho từng model          |
| **Least-Used**     | Định tuyến đến model có ít request gần đây nhất (dùng metrics của combo) |
| **Cost-Optimized** | Định tuyến đến model khả dụng rẻ nhất (dùng bảng giá)                    |

Các giá trị mặc định combo toàn cục có thể được thiết lập trong **Dashboard → Settings → Routing → Combo Defaults**.
Timeout của target combo mặc định kế thừa timeout của request hiện tại. Chỉ sử dụng **Target timeout
(seconds)** trong combo defaults hoặc trên một combo riêng lẻ khi bạn muốn giới hạn ngắn hơn cho từng
target nhằm kích hoạt fallback nhanh hơn.

Các tối ưu hóa zero-latency của combo là opt-in (phải chủ động bật). Hãy để **Zero-latency optimizations**
ở trạng thái tắt để ngăn các tính năng độ trễ này chạy đua với các target fallback, bỏ qua target
dựa trên lịch sử TTFT, hoặc nén các request fallback; khi bật, các cơ chế hedging đã cấu hình,
bỏ qua theo dự đoán TTFT và nén fallback chủ động sẽ được áp dụng — đánh đổi độ trung thực của
định tuyến/request để đạt độ trễ đuôi (tail latency) thấp hơn.

Tắt **Reasoning token buffer** khi các nhà cung cấp upstream yêu cầu giới hạn nghiêm ngặt đối với
`max_tokens` / `maxOutputTokens`. Khi được bật, combo routing chỉ bổ sung khoảng dự phòng
cho mô hình reasoning đối với những mô hình có mức giới hạn đầu ra đã biết, và giữ nguyên giới hạn
token của client khi giá trị đệm an toàn sẽ vượt quá mức giới hạn đó. Nếu giới hạn của client đã
cao hơn một mức giới hạn đã biết, OmniRoute sẽ kẹp (clamp) giá trị đó xuống đúng mức giới hạn trước khi gửi yêu cầu tới upstream.

Truy cập qua **Dashboard → Health**. Tổng quan sức khỏe hệ thống theo thời gian thực với 6 thẻ:

## 🤖 Tự động định tuyến (Không cần cấu hình)

OmniRoute tích hợp sẵn một **bộ tự động định tuyến dựa trên điểm số**, giúp chọn mô hình tốt nhất cho từng yêu cầu trên tất cả các nhà cung cấp đã kết nối — không cần duy trì tổ hợp nào. Chỉ cần gửi yêu cầu với một trong các tiền tố `auto/*`, OmniRoute sẽ tự động tạo một tổ hợp ảo, chấm điểm các ứng viên dựa trên độ trễ, chi phí, tỷ lệ thành công, mức độ phù hợp với ngữ cảnh, mức độ phù hợp của mô hình với tác vụ, các lỗi gần đây, hạn ngạch và trạng thái bộ ngắt mạch.

| Tiền tố        | Tiêu chí tối ưu hóa                                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| `auto`         | Mặc định cân bằng (độ trễ × chi phí × tỷ lệ thành công)                                                      |
| `auto/coding`  | Tác vụ lập trình: ưu tiên Claude, GPT-5, GLM, Kimi, Qwen Coder, các mô hình lập trình DeepSeek               |
| `auto/cheap`   | Chi phí $/token thấp nhất, chấp nhận độ trễ cao hơn                                                          |
| `auto/fast`    | Độ trễ thấp nhất, bỏ qua chi phí                                                                             |
| `auto/offline` | Chỉ dùng nhà cung cấp cục bộ (Ollama, vLLM, llama.cpp) — hữu ích cho các hệ thống cách ly mạng               |
| `auto/smart`   | Ưu tiên chất lượng suy luận (Opus, GPT-5 xhigh, R1, suy luận GLM 5.1)                                        |
| `auto/lkgp`    | "Nhà cung cấp tốt gần nhất" — cố định vào nhà cung cấp thành công gần nhất, sau đó dự phòng theo các quy tắc |

Ví dụ:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Tái cấu trúc hàm Python này" }],
    "stream": true
  }'
```

Bộ tự động định tuyến được mô tả đầy đủ trong [AUTO-COMBO.md](../routing/AUTO-COMBO.md) — bao gồm cách điều chỉnh trọng số chấm điểm, đưa nhà cung cấp vào danh sách đen và kiểm tra các quyết định định tuyến trong **Bảng điều khiển → Tổ hợp tự động**.

## 🔌 Tích hợp MCP & A2A

OmniRoute vừa là một **máy chủ MCP** (Giao thức Ngữ cảnh Mô hình), vừa là một **máy chủ A2A** (JSON-RPC 2.0 từ tác nhân đến tác nhân). Mọi IDE hoặc máy chủ tác nhân tương thích với MCP đều có thể gọi trực tiếp các công cụ OmniRoute — không cần lớp bao bọc bổ sung.

### Các phương thức truyền tải MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP có thể phát luồng**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (dành cho các plugin IDE ưu tiên stdio)

### Kết nối Claude Desktop

Chỉnh sửa `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) hoặc tệp tương đương trên Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Kết nối Cursor / Continue / VS Code MCP

Sử dụng URL SSE `http://localhost:20128/api/mcp/sse` và khóa API Bearer được tạo trong **Bảng điều khiển → Khóa API**.

### Phạm vi

MCP hiện định nghĩa 32 phạm vi có tên. Mỗi khóa Bearer có thể được giới hạn ở các phạm vi cụ thể — xem [MCP-SERVER.md](../frameworks/MCP-SERVER.md) để biết danh sách phạm vi và công cụ chính thức, cũng như [A2A-SERVER.md](../frameworks/A2A-SERVER.md) để biết lược đồ JSON-RPC.

## 💾 Hệ thống bộ nhớ

OmniRoute lưu trữ **bộ nhớ hội thoại dài hạn** bằng cơ chế truy xuất kết hợp:

## 🔔 Webhook

Đăng ký nhận các sự kiện OmniRoute để giám sát và tự động hóa theo thời gian thực.

- Tạo webhook trong **Dashboard → Webhooks** với URL đích và khóa bí mật ký HMAC
- Các sự kiện khả dụng: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- Mỗi payload đều bao gồm `X-OmniRoute-Signature` (HMAC-SHA256) để xác minh
- Thử lại: 3 lần với thời gian chờ tăng theo cấp số nhân, sau đó chuyển vào hàng đợi thư lỗi

Schema đầy đủ có trong [WEBHOOKS.md](../frameworks/WEBHOOKS.md).

## 🛠️ Quản lý theo chương trình

Bạn có thể quản lý mọi tài nguyên OmniRoute (nhà cung cấp, combo, khóa, cài đặt) qua HTTP bằng **khóa Bearer có phạm vi `manage`**.

Tạo khóa trong **Dashboard → API Keys → New Key → Scope: manage**, sau đó:

```bash
# Liệt kê các nhà cung cấp
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Thêm kết nối nhà cung cấp
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Tạo combo
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Liệt kê/tạo API key
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

Xem [API_REFERENCE.md](../reference/API_REFERENCE.md) để biết danh mục endpoint đầy đủ cùng các schema yêu cầu/phản hồi.

## 💻 CLI nội bộ

OmniRoute cung cấp một CLI nội bộ (`omniroute …`) để thiết lập, chẩn đoán và kiểm soát thời gian chạy. CLI này **tách biệt với trang "Công cụ CLI" trong bảng điều khiển**, nơi cấu hình các CLI của bên thứ ba (Claude Code, Cursor, Codex, Cline, …) để chúng có thể giao tiếp với OmniRoute.

```bash
omniroute setup                    # Trình hướng dẫn tương tác (mật khẩu, nhà cung cấp, tổ hợp)
omniroute setup --non-interactive  # Phù hợp với CI
omniroute doctor                   # Chẩn đoán tình trạng (thư mục dữ liệu, DB, nhà cung cấp, cổng)
omniroute providers available      # Liệt kê các nhà cung cấp được hỗ trợ
omniroute providers list           # Liệt kê các kết nối đã cấu hình
omniroute providers test <id>      # Kiểm tra trực tiếp kết nối với nhà cung cấp
omniroute combos list              # Liệt kê các tổ hợp
omniroute combos switch <name>     # Đặt tổ hợp mặc định
omniroute models                   # Liệt kê các mô hình khả dụng (--json, --search)
omniroute keys add | list | remove # Quản lý khóa API từ terminal
omniroute backup                   # Tạo bản chụp nhanh cấu hình + DB
omniroute restore [<timestamp>]    # Khôi phục từ bản chụp nhanh
omniroute health                   # Tình trạng chi tiết (bộ ngắt mạch, bộ nhớ đệm, bộ nhớ)
omniroute quota                    # Mức sử dụng hạn ngạch của nhà cung cấp
omniroute mcp status               # Trạng thái máy chủ MCP
omniroute a2a status               # Trạng thái máy chủ A2A
omniroute tunnel list|create|stop  # Đường hầm Cloudflare/Tailscale/ngrok
omniroute reset-password           # Đặt lại mật khẩu quản trị viên
omniroute --mcp                    # Khởi động máy chủ MCP qua stdio
omniroute --port 3000              # Khởi động máy chủ trên một cổng tùy chỉnh
```

Mẹo: kết hợp `omniroute doctor --json` với công cụ giám sát của bạn để cảnh báo khi kết nối với nhà cung cấp gặp sự cố.

## 🖥️ Ứng dụng máy tính (Electron)

OmniRoute có sẵn dưới dạng ứng dụng máy tính gốc dành cho Windows, macOS và Linux.

### Cài đặt

```bash
# Từ thư mục electron:
cd electron
npm install

# Chế độ phát triển (kết nối với máy chủ phát triển Next.js đang chạy):
npm run dev

# Chế độ sản xuất (sử dụng bản dựng độc lập):
npm start
```

### Tạo bộ cài đặt

```bash
cd electron
npm run build          # Nền tảng hiện tại
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg universal)
npm run build:linux    # Linux (.AppImage)
```

Đầu ra → `electron/dist-electron/`

### Các tính năng chính

| Tính năng                       | Mô tả                                                               |
| ------------------------------- | ------------------------------------------------------------------- |
| **Mức độ sẵn sàng của máy chủ** | Thăm dò máy chủ trước khi hiển thị cửa sổ (không có màn hình trống) |
| **Khay hệ thống**               | Thu nhỏ vào khay, thay đổi cổng, thoát từ menu khay                 |
| **Quản lý cổng**                | Thay đổi cổng máy chủ từ khay (tự động khởi động lại máy chủ)       |
| **Chính sách bảo mật nội dung** | CSP hạn chế thông qua các tiêu đề phiên                             |
| **Một phiên bản duy nhất**      | Mỗi lần chỉ có thể chạy một phiên bản ứng dụng                      |
| **Chế độ ngoại tuyến**          | Máy chủ Next.js đi kèm hoạt động mà không cần internet              |

### Biến môi trường

| Biến                  | Mặc định | Mô tả                                   |
| --------------------- | -------- | --------------------------------------- |
| `OMNIROUTE_PORT`      | `20128`  | Cổng máy chủ                            |
| `OMNIROUTE_MEMORY_MB` | `512`    | Giới hạn heap của Node.js (64–16384 MB) |
