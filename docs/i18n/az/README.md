## Ayda Pulsuz Tokenlər: ~ 11.3B, digərlərinin sayına görə · ~ 90M Real

</div>

> **~ 11.3B pulsuz tokenlər / ay**<br/> <sub> digər kataloqların sayıldığını hesabladı: hər sıra əlavə edildi, bitən təkliflər </sub> daxil edildi
>
> **~ 90M real bu gün**<br/> <sub> hər paylaşılan kvota bir dəfə sayılır:</sub> əslində nə istifadə edə bilərsiniz
>
> **Burada hər şey pulsuzdur. Ödəniş divarı yoxdur.**<br/> ★ [Bəyəndinizmi? Bizi GitHub-də ulduzlayın](https://github.com/cheaper-inference/OmniRoute)

Digər kataloqlar canlı məlumatlara ömür boyu daxil olmaq üçün ildə US dollardan US 49 dollara qədər ödəniş alır. Burada hər şey pulsuzdur. <sub> Qiymətlər 2026-11-18 tarixində yoxlanılıb.</sub>

<sub>Kataloq sonuncu dəfə 23.11.2026 tarixində yoxlanılıb. [Necə → sayırıq](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **Öz provayder hesablarınızı gətirin.** Bunlar üçüncü tərəfin pulsuz səviyyələridir, OmniRoute dan əlamət qrantı deyil. Qeydiyyatdan keçin, provayderin tələb etdiyi etimadnamələri əldə edin və istifadə edə biləcəyiniz məlumatları birləşdirin. Hər bir provayder öz məhdudiyyətlərini, mövcudluğunu və şərtlərini təyin edir.
>
> Pulsuz pillələri əl ilə yığmaq onlarla SDKs, onlarla tarif limiti və qalanlarınız haqqında aydın təsəvvürün olmaması deməkdir. OmniRoute pulsuz girişi olan 214 kataloq sıralarını saxlayır və dərc edilmiş kvota ilə 12 hovuzdan real rəqəmi hesablayır, hər bir paylaşılan hovuz bir dəfə hesablanır. Yalnız regional şəxsiyyət yoxlanışından sonra açılan kvotalar (bu gün ModelScope) ayrı göstərilir, +~ 6M regional identifikasiyanın arxasındadır və əsl rəqəmə heç vaxt əlavə edilmir. Qalanlar tablosunda görünür (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute free-tier budget card. Free tokens a month: ~11.3B as others count · ~90M real. The bar shows where the real figure comes from, one segment per pool. Signup credits and free providers without a token cap are listed apart and never added to it. Live used and remaining tokens on /dashboard/free-tiers."/>

> Canlı `/dashboard/free-tiers` səhifəsinin animasiyalı xülasəsi. Hər bir rəqəm necə hesablanır:** [docs/reference/FREE_TIERS.md#necə-sayırıq](docs/reference/FREE_TIERS.md#how-we-count)** .
>
> <sub> Kataloq sonuncu dəfə 23.11.2026 tarixində yoxlanılıb. Rəqəmlər hər iki istiqamətdə hərəkət edir. Provayder pulsuz səviyyəni bitirir və real rəqəm azalır. Yenisi enir və dırmaşır. Biz kataloqun hesabladığını dərc edirik, heç vaxt yuvarlaqlaşdırılmış ən yaxşı hal deyil.</sub>

## Quraşdırın, provayderi birləşdirin, sonra bir son nöqtədən keçin

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

## Kombolar: flaqman

1. **`auto` ilə başlayın.** Modeli OpenAI uyğun müştərinizdə qurun. OmniRoute əlaqəli provayderlərdən virtual kombin qurur və canlı olaraq namizədləri qiymətləndirir.
2. **Daha çox nəzarət üçün kombini saxlayın.** Ad, hədəf siyahısı və strategiya seçin, sonra həmin addan model kimi istifadə edin. Strategiya hansı hədəfin birinci olacağını və qalanların necə sınaqdan keçiriləcəyini təyin edir.

Kombo avtomatik olaraq modellər arasında marşrutlar. Kvota tükəndikdə, provayderin uğursuzluğunda və ya model blokadasında o, növbəti uyğun, sağlam hədəfi sınayır.

### Sıfır konfiqurasiya: sadəcə `auto` istifadə edin

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

### Dayanıqlılıq qurulur: 3 müstəqil təbəqə

Uğursuzluqlar üç miqyasda idarə olunur, beləliklə, bir pis model öz hesabını, bir pis hesab isə provayderini ləğv etmir.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Bütün provayder işləmirsə

The** provayderin dövrə açarı** 408, 500, 502, 503 və ya 504 statuslu 8 (OAuth) və ya 12 (API açarı) uğursuzluqdan sonra açılır. Kombolar açıq olduqda həmin provayderi keçir. 60 və ya 30 saniyədən sonra bir zond sorğusu onun bağlanıb-bağlanmamasına qərar verir.

#### Bir açar və ya hesab dərəcəsi məhduddursa

The** əlaqənin soyuması** 5 s (OAuth) və ya 3 s (API düyməsi ) eksponensial geriləmə ilə yalnız bu əlaqəni oturur. Eyni provayder üçün digər açarlar xidmət etməyə davam edir.

#### Bir modeldən imtina edilərsə

The** model kilidi** hər model 429, 404 və ya girişin rədd edilməsindən sonra həmin əlaqədə yalnız həmin modeli bloklayır. Eyni əlaqədə olan digər modellər xidmət etməyə davam edir.

Qadağan edilmiş, vaxtı keçmiş və krediti bitmiş bağlantılar soyuma deyil, terminal vəziyyətləridir: onlar sizin onları düzəltməyinizi gözləyirlər.

Modality Bridge, qoşulmuş Radar kataloqu, OmniConductor donanmasının nümayəndə heyəti və iş masası proqramını işləyən serverə qoşmaq üçün dəstək. [Buraxılış qeydləri](https://github.com/cheaper-inference/OmniRoute/releases/tag/v3.8.50).

Bütün dəyişikliklər üçün [CHANGELOG.md](CHANGELOG.md) və planlaşdırılan işlər üçün [ROADMAP.md](ROADMAP.md) baxın.

## Uyğun CLIs və Kodlaşdırma Agentləri

İdarə paneli kataloqu siyahıları** 39 inteqrasiya** (28 kodlaşdırma aləti və 11 agent). CLI manifestinə `omniroute run` ilə işə salınan Gemini CLI və yalnız aşkarlaya biləcəyi dörd alət əlavə edilir. Onların hamısından,** 8** `omniroute run` ilə işə salın,** 12** `omniroute configure` ilə qurmaq olar və** 16** xüsusi `setup-*` əmri var. İstədiyinizə uyğun olan yolu seçin.

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"
omniroute setup-whycodes && omniroute run whycodes --model glm/glm-5.2

# Or pick provider and model interactively and write the tool's own config:
omniroute configure codex   # also: claude opencode qwen aider goose gemini whycodes cline continue kilo 5dive
```

Hər bir əmr aktiv uzaq konteksti (`omniroute connect <host>`) qiymətləndirir. `--dry-run` heç bir işlətmədən dəqiq env və args çap edir və `--api-key-env NAME` açarı qabıq tarixçənizdən kənarda saxlayır. Qwen Code və Gemini CLI çıxışda silinən müvəqqəti evdə işləyir. WhyCodes öz provayderini yalnız `config.toml` dan oxuyur, ona görə də `run whycodes` dən əvvəl bir dəfə `setup-whycodes` işə salın. → [CLI İnteqrasiyaları](docs/guides/CLI-INTEGRATIONS.md)

## Tam CLI, MCP və A2A

> OmniRoute komanda xətti müştərisini göndərir** 91 yüksək səviyyəli əmrlər və komanda qrupları** (alt əmrləri sayan 754 əmr), an** 110 alət və 33 əhatə dairəsi olan MCP server** , və bir** 6 bacarıqlı A2A agenti** . Skriptlər, terminallar və AI agentləri hamısı eyni şlüzlə işləyə bilər.

### Əsl CLI, sadəcə `start` deyil

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

Qlobal `--output table|json|jsonl|csv` bayrağı eyni əmrləri skriptlərdən və CI dən istifadə edilə bilən edir.

### Uzaqdan idarəetmə rejimi: laptopda CLI, serverdə OmniRoute

Uzaq serverə bir dəfə daxil olun. CLI onu bir kimi saxlayır** kontekst** , və sonrakı əmrlər siz geriyə keçənə qədər həmin serverə qarşı işləyir.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Token əhatə dairəsi | <img width="2000" height="0" alt=""> Nə imkan verir                                         |
| ------------------- | ------------------------------------------------------------------------------------------- |
| `read`              | Siyahıya salın və yoxlayın: modellər, statuslar, qeydlər, istifadə                          |
| `write`             | `read` plus konfiqurasiya edin və tətbiq edin: müştəri quraşdırması, açarlar, konfiqurasiya |
| `admin`             | `write` plus idarə edin: ayələr, provayderlər, xidmətlər, siyasət                           |

Çılpaq host `http://` və port 20128 alır; server TLS arxasında oturanda tam `https://` URL keçir. Prosesləri inkişaf etdirə bilən marşrutlar, işarədən asılı olmayaraq yalnız geri dönmə ilə qalır.

### Agenti birləşdirin

Agent və ya öz kodunuz bu interfeyslərdən hər hansı biri vasitəsilə marşrutlaşdırma, provayderlər, kombinasiyalar, keş, sıxılma və yaddaş idarə edə bilər. HTTP yolları `http://localhost:20128`-də standart olaraq şlüz tərəfindən xidmət edilir.

| İnterfeys                          | Son nöqtə və ya əmr        | üçün istifadə edin                                                                     |
| ---------------------------------- | -------------------------- | -------------------------------------------------------------------------------------- |
| stdio üzərindən MCP                | `omniroute --mcp`          | Claude Desktop, Cursor və digər yerli MCP müştəriləri                                  |

| A2A kəşfi                          | `/.well-known/agent.json`  | Agent Kartı: digər agentlərə OmniRoute nə edə biləcəyini bildirir                      |
| A2A icrası                         | `POST /a2a`                | 6 bacarıq üzrə sinxron və ya SSE üzərindən yayımlanan JSON-RPC 2.0 tapşırıqları        |
| REST API                           | `/v1/*`                    | OpenAI-a uyğun söhbət, Cavablar, daxiletmələr, şəkillər, audio və OCR                  |
| Veb kancalar                       | `/api/webhooks`            | Slack, Discord, Telegram və ya HMAC imzası ilə hər hansı URL üçün hadisələr            |
| Uzaqdan CLI                        | `omniroute connect <host>` | Genişlənmiş giriş nişanları ilə uzaq bir nümunəni idarə edin                           |

Altı A2A bacarığı `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` və `list-capabilities` dir .

**Qoşulmazdan əvvəl:**

- **MCP over HTTP deaktiv başlayır.** Onu `omniroute mcp enable --transport streamable-http` ilə və ya tablosunun Son nöqtələr səhifəsindən yandırın. Bir HTTP nəqli eyni anda aktivdir: `streamable-http` `/api/mcp/stream`, `sse` `/api/mcp/sse` xidmət edir.
- **A2A əlil başlayır.** Bunu tablosunun Endpoints səhifəsində aktivləşdirin. `POST /a2a` daha sonra `/v1` ilə eyni API açarı qaydalarına əməl edir.
- **Uzaqdan MCP uyğun açara ehtiyac duyur.** `/api/mcp/*` defolt olaraq yalnız geri dönməyə cavab verir. Başqa hostdan `manage` və ya `admin` (bütün alətlər) və ya `mcp:connect` plus sizə lazım olan alətlərin əhatə dairəsi ilə açar göndərin. `manage`/`admin` olmayan düymələr üçün alət dairələri həmişə tətbiq edilir.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

### Necə işləyir — boru kəməri, memarlıq və qənaət riyaziyyatı

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

Defolt yığılmış kombo `RTK → Caveman` işləyir. Hər ikisi eyni tool/context yükü ilə hərəkət etdikdə qənaət mürəkkəbləşir:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Kod blokları, URLs, JSON və strukturlaşdırılmış məlumatlardır** həmişə qorunur** qoruyucu mühərrik tərəfindən.

## Daha çox quraşdırma metodları — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` ən yüksək olanı izləyir** nəşr edilmişdir** sabit SemVer. git `main` izləmir. GitOps üçün `:X.Y.Z` bağlayın. [Docker Buraxılış Kanallarına](docs/guides/DOCKER_GUIDE.md#release-channels) baxın. Şəkil sancaqları**`OMNIROUTE_MEMORY_MB=1024`** . Bu, tablosuna və yüngül söhbət üçün kifayətdir.** Kodlaşdırma agentləri** ( Claude Kodundan `POST /v1/responses`, Codex, Grok, …) iki üst-üstə düşən uzun kontekstdə ~ 12 GiB -də daha böyük V8 yığını və ya `FATAL ERROR` s prosesi lazımdır. Konteyneri yığının üstündən ölçün (doğma buferlər V8 xaricində oturur):

| <img width="2000" height="0" alt=""> İş Yükü | Yığın (`-e OMNIROUTE_MEMORY_MB`) | Konteyner (`--memory`) |
| -------------------------------------------- | -------------------------------- | ---------------------- |
| İdarə paneli / işıqlı söhbət                 | `1024` (defolt şəkil)            | ≥ 2 q                  |
| Bir kodlaşdırma agenti                       | `8192`                           | ≥ 10 q                 |
| İki eyni vaxtda uzun `/v1/responses`         | `10240`–`12288`                  | ≥ 12-16 q              |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Tam cədvəl: [Docker Guide — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Yayımdan əvvəl Docker kanalı:** `diegosouzapw/omniroute:next` və `diegosouzapw/omniroute:next-web` cari standart `release/v*` filialını izləyir. Bu dəyişkən teqlər yalnız buraxılmamış düzəlişləri sınamaq üçün nəzərdə tutulub** istehsal üçün dəstəklənmir** . [Docker Buraxılış Kanallarına](docs/guides/DOCKER_GUIDE.md#release-channels) baxın.

**🥟 Bun**

Standart `bun install` və qlobal quraşdırma (`bun install -g omniroute`) Bun iş vaxtının aşkarlanması vasitəsilə dəstəklənir:

- **Quraşdırılmış `bun:sqlite`** : OmniRoute Bun altında işləyərkən, Node.js və ya `sql.js` da `better-sqlite3` -ə qayıdarkən Bun-nin daxili `bun:sqlite` sürücüsündən istifadə edir.
- **Dev-də avtomatik Webpack bundler seçimi** : İnkişaf (`bun run dev`) avtomatik olaraq Bun aşkarlayır və yerli V8 bağlama uyğunsuzluqlarının qarşısını almaq üçün Webpack lehinə Turbopack söndürür. İstehsal quruluşları (`bun run build`) tam olaraq Node-da olduğu kimi `OMNIROUTE_USE_TURBOPACK` izləyir: Turbopack defolt olaraq, Webpack ilə qurmaq üçün `OMNIROUTE_USE_TURBOPACK=0` (`Dockerfile.bun` onu `--build-arg` kimi göstərir).
- **Xüsusi Bun Dockerfile** : Doğma Bun istehsal yerləşdirmələri üçün çox mərhələli `Dockerfile.bun` (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ Daha sürətli / daha incə quraşdırma (doğma quruluşu atlayın)**

The native SQLite engine (`better-sqlite3`) is an **optional** dependency, so a global install never blocks on compiling from source: it uses a prebuilt binary when one matches your platform/Node, and otherwise falls back transparently to a pure-JS engine (`node:sqlite` on Node 22+, else the bundled `sql.js` WASM) — no build tools required.

Quraşdırmadan sonra keçmək üçün** yerli istiləşmə** tamamilə (CI, başsız və ya yavaş maşınlar). Qeyd: bu, yalnız yerli SQLite isinmə addımını keçir (`scripts/postinstall.mjs`); binary-copy/repair çəngəl (`scripts/build/postinstall.mjs`) hələ də normal işləyir:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

Ən sürətli quraşdırmalar üçün üstünlük verilir** pnpm** (məzmun ünvanlı mağaza + hard links — yuxarıda bax). Panelsiz, başsız işləmə müddəti üçün Docker `base` profilindən (yuxarıda) və ya [Termux bələdçisindən](docs/guides/TERMUX_GUIDE.md) istifadə edin. CLI və veb tablosuna eyni proses bir portda xidmət göstərir, ona görə də bu gün yalnız CLI üçün ayrıca paket yoxdur.
