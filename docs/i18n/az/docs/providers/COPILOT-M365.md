`copilot-m365-web` (`m365copilot` aliası) OpenAI formatlı çat sorğularını
`m365.cloud.microsoft/chat` ünvanındakı autentifikasiya edilmiş Microsoft 365 Copilot BizChat brauzer sessiyası vasitəsilə göndərir. Bu, qeyri-rəsmi inteqrasiyadır.

> **Web Cookie provayderlərindən ilk dəfə istifadə edirsiniz?**
>
> Bu provayderə aid təlimata keçməzdən əvvəl ümumi quraşdırma prosesi, autentifikasiya üzrə tövsiyələr, məhdudiyyətlər və problemlərin aradan qaldırılması haqqında məlumat üçün **`docs/getting-started/WEB-COOKIE-GUIDE.md`** sənədini oxuyun.
>
> **Vacib:** Bu provayder üçün giriş məlumatı **cookie deyil**. Cookie-ləri
> `m365.cloud.microsoft` saytından köçürməyin. Giriş məlumatı WebSocket URL sorğu
> parametrindən və yol seqmentindən ibarətdir; hər ikisi DevTools-un Network tabından əldə edilir.

## İlkin tələblər

- `m365.cloud.microsoft/chat` ünvanında BizChat-a çıxışı olan Microsoft 365 hesabı
- DevTools-da WebSocket-i yoxlamaq üçün Chromium əsaslı brauzer (Chrome, Edge)
- M365 Copilot lisenziyası (bir çox Microsoft 365 Business/Enterprise planına daxildir)

## Giriş məlumatının əldə edilməsi (WebSocket üsulu)

1. `https://m365.cloud.microsoft/chat` ünvanında hesabınıza daxil olun və söhbət başladın.
2. **DevTools → Network** bölməsini açın.
3. **WS** (WebSocket) üzrə filtrləyin.
4. Chathub WebSocket bağlantısına klikləyin. Aşağıdakı ilə başlayan URL-i tapın:
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Onun **Request URL** dəyərindən aşağıdakıları köçürün:
   - `access_token` sorğu parametrinin dəyəri (qısamüddətli JWT).
   - `/Chathub/` hissəsindən sonrakı Chathub yol seqmenti (məsələn, `<oid>@<tenant>`).

Tam URL aşağıdakı formadadır:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute-da **Providers → Add Provider** bölməsinə keçin, **Microsoft 365 Copilot
   (BizChat)** seçin və giriş məlumatını aşağıdakı formatda yerləşdirin:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** və sonra **Save** düyməsinə klikləyin.

## Giriş məlumatının əldə edilməsi (HAR idxalı)

Dəyərləri WebSocket URL-dən əl ilə köçürmək əvəzinə, DevTools HAR
faylını ixrac edə bilərsiniz:

1. **DevTools → Network** bölməsini açın.
2. BizChat söhbətini başladın və ya davam etdirin (bu, WebSocket bağlantısını işə salır).
3. Network panelində sağ klikləyin və **Save all as HAR with content** seçin.
4. OmniRoute-da provayder bağlantısı dialoqundakı **Import .har file** düyməsindən istifadə edin.

OmniRoute HAR faylında Chathub WebSocket URL-ni axtarır, `access_token` və
`chathubPath` dəyərlərini çıxarır və giriş məlumatı sahələrini avtomatik doldurur.
HAR idxalı JWT-nin bitmə vaxtını deşifrə edir və tokenin qalan etibarlılıq müddətini göstərir.

> **Heç vaxt real HAR ixracını, giriş tokenini və ya yeniləmə tokenini repozitoriyaya əlavə etməyin.** Test və
> sənədləşdirmə dəyərləri həmişə yer tutucular olmalıdır.

## Tokenin istifadə müddəti və yenilənməsi

`access_token` qısa müddətlidir (adətən **~75 dəqiqə**). İstifadə edilə bilən yeniləmə
tokeni olmadan, müddət bitdikdən sonra kredensialı yenidən əldə etməlisiniz.

### `refreshToken` ilə avtomatik yeniləmə

Microsoft 365 provayderinin **Add connection** və ya **Edit connection** dialoqunda
**Advanced Settings → Refresh token (optional)** bölməsini açın. `substrate.office.com/sydney`
scope-u üçün Microsoft OAuth yeniləmə tokenini yapışdırın və yadda saxlayın. Daxiletmə sahəsi
maskalanır və saxlanılmış token heç vaxt əvvəlcədən doldurulmur. Redaktə edərkən mövcud tokeni
saxlamaq üçün sahəni boş buraxın; onu əvəz etmək üçün yeni token yapışdırın.

Yeniləmə tokenini `substrate.office.com/sydney` scope-u ilə Microsoft device-code və ya
authorization-code axınından əldə edin; idarə paneli bunu sizin üçün əldə etmir.
Yeniləmə tokeni konfiqurasiya edildikdə, OmniRoute sorğulardan əvvəl `access_token`-i yoxlayır
və yalnız yenilənməsi lazım olduqda onu yeniləyir. Uğurlu yeniləmə həmçinin dəyişdirilmiş
yeniləmə tokenini saxlayır; beləliklə, yeniləmə tokeni etibarlı qaldığı müddətdə onu əl ilə
yenidən əldə etməyə ehtiyac qalmır.

`refreshToken` təyin edilməyibsə, hər müddət bitməsindən sonra WebSocket kredensialını əl ilə
yenidən əldə etməlisiniz.

### Səviyyə seçimi

| Səviyyə      | Ləqəb       | Səth                    |
| ------------ | ----------- | ----------------------- |
| `individual` | _(default)_ | İstehlakçı M365 Copilot |
| `edu`        | `included`  | Təhsil M365 Copilot     |
| `enterprise` | `work`      | İş üçün M365 Copilot    |

Səviyyəni **Advanced Settings → Copilot tier** bölməsində təyin edin. Səviyyə
BizChat marşrutlaşdırmasına və modelə girişə təsir edir.

## Təhlükəsizlik modeli

- **Qeyri-rəsmi inteqrasiya.** Bu provayder BizChat WebSocket
  protokolunu əks mühəndislik yolu ilə tətbiq edir. Microsoft son nöqtəni dəyişdikdə, inteqrasiya xəbərdarlıq edilmədən işləməyə bilər.
- `subscriptionRisk: true` bayrağı inteqrasiyanın sənədləşdirilməmiş son nöqtəyə
  əsaslandığını göstərir. Hesab məhdudiyyətləri mümkündür, lakin təsdiqlənməyib.
- Giriş tokeni qısamüddətli JWT-dir. Onunla parol kimi davranın: repozitoriyaya əlavə etməyin,
  jurnala yazmayın və paylaşmayın.
- Yeniləmə tokeni BizChat interfeysinə uzunmüddətli giriş imkanı verir. Onu
  API açarı ilə eyni ehtiyatla saxlayın.

## Problemlərin aradan qaldırılması

### Autentifikasiya dərhal uğursuz olur

- XHR/Fetch sorğusundan deyil, **WebSocket URL**-dən kopyaladığınızı yoxlayın. Kimlik məlumatı Chathub WebSocket bağlantısının `access_token` sorğu parametrində yerləşir — `Authorization: Bearer` başlığında deyil.
- `chathubPath`-ə URL yolundakı tam `<oid>@<tenant>` seqmentinin daxil olduğundan əmin olun.

### Token ~75 dəqiqədən sonra vaxtını başa vurur

Bu gözlənilən haldır. `refreshToken` olmadan giriş tokeninin istifadə müddəti qısadır. Aşağıdakılardan birini edin:

- Kimlik məlumatını DevTools-dan yenidən əldə edin, yaxud
- Avtomatik yeniləmə üçün bağlantının əlavə edilməsi və ya redaktəsi dialoqunda **Qabaqcıl parametrlər → Yeniləmə tokeni (istəyə bağlı)** seçimini konfiqurasiya edin.

### Bağlantını sınaqdan keçirmə uğurludur, lakin söhbət 401 qaytarır

Token doğrulama ilə ilk sorğu arasında vaxtını başa vurmuş ola bilər. Təzə kimlik məlumatını yenidən əldə edin.

### Copilot provayderlər siyahısında görünmür

`copilot-m365-web`-in **İdarə paneli → Provayderlər** bölməsində aktiv olduğundan əmin olun. Bəzi tariflərdə provayder standart olaraq gizlədilə bilər.
