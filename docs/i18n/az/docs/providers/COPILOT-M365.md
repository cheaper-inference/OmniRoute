`copilot-m365-web` (ləqəb `m365copilot`) `m365.cloud.microsoft/chat`-də təsdiqlənmiş Microsoft 365 Copilot sessiyası vasitəsilə OpenAI formatlı söhbət sorğuları göndərir. Bu qeyri-rəsmi yerli inteqrasiyadır: ayrıca proksi prosesi və ya yuxarı axın localhost tələb olunmur. Provayder ID, ləqəb və mövcud idxal edilmiş bağlantılar dəyişməzdir. `copilot-web` `copilot.microsoft.com`-da istehlakçı xidməti üçün fərqli bir provayderdir.

> **Web Cookie təminatçılarında yenisiniz?**
>
> Oxuyun**`docs/getting-started/WEB-COOKIE-GUIDE.md`** bu provayder üçün xüsusi təlimata əməl etməzdən əvvəl ümumi quraşdırma prosesi, autentifikasiya təlimatı, məhdudiyyətlər və problemlərin aradan qaldırılması üçün.
>
> **Köhnə idxal üçün:** Bu provayder üçün etimadnamədir** peçenye deyil** . `m365.cloud.microsoft` dan kukiləri kopyalamayın. Etibarnamə WebSocket URL sorğu parametri və yol seqmentidir, hər ikisi DevTools Şəbəkə nişanından oxunur.

## İlkin şərtlər

- `m365.cloud.microsoft/chat`-də Copilot -ə çıxışı olan Microsoft 365 hesabı
- DevTools WebSocket yoxlaması üçün Chromium əsaslı brauzer (Chrome, Edge).
- Həmin hesabda tələb olunan modelə giriş; mövcudluq icarəçiyə və lisenziyaya görə dəyişir

## Doğma giriş (iş və ya məktəb hesabları)

seçin**Microsoft 365 Copilot → qoşun** və daxil olmaq cəhdi hazırlayın. İdarə paneli PKCE ilə avtorizasiya kodu axınından istifadə edir; Microsoft parolunuzu və ya MFA kodunuzu tələb etmir.

1. Açıq a** boş brauzer nişanı** , sonra açın**DevTools → şəbəkəsi** və aktivləşdirin** Girişi qoruyun** . Microsoft-ə keçməzdən əvvəl bunu edin: Windows SSO dərhal bitə bilər.
2. Bağlantı dialoqunda göstərilən URL icazəsini kopyalayın və hazırlanmış tabda ona keçin. Microsoft-nin hesab seçimini və ya tələb olunarsa MFA tamamlayın.
3. Qorunan Şəbəkə jurnalında `https://login.microsoftonline.com/common/oauth2/nativeclient` sorğusunu tapın və onun tam surətini kopyalayın** URL tələb edin** .
4. Həmin URL əlaqə dialoquna yapışdırın və qoşulun. Xam kodu və ya son `wrongplace` ünvan çubuğunu yapışdırmayın URL: tələb olunan geri zəng müvəqqəti naviqasiyadır.

Hər cəhd on dəqiqədən sonra başa çatır və yalnız bir dəfə istifadə edilə bilər. Server kodu mübadilə etməzdən əvvəl vəziyyətini, PKCE doğrulayıcısını və yenidən doğrulama hədəfini yoxlayır. Müddəti bitdikdən və ya mübadilə uğursuzluğundan sonra yeni cəhdə başlayın. Bir cəhd serverin yenidən başlamasından sağ çıxa bilməz.

Tokenlər mövcud əlaqə etimadnaməsi anbarından və yeniləmə yolundan istifadə edir. Bağlantının yenidən təsdiqlənməsi yalnız eyni e-poçt deyil, eyni Microsoft tenant/object identifikasiyası tələb edir. O, naming/settings operatorunu qoruyur və köhnəlmiş idxal edilmiş etimadnamələri əvəz edir. Doğma giriş work/school hesabları üçündür; köhnə idxal yolu mövcud əlaqələr və dəstəklənən səviyyə konfiqurasiyaları üçün əlçatan olaraq qalır.

Tam geri çağırış URL birdəfəlik etimadnamədir. Heç vaxt onu ekran görüntülərinə, qeydlərə, dəstək mesajlarına və ya öhdəliklərə daxil etməyin. Bu axın serverdə brauzer açmır, brauzerinizin tarixçəsini yoxlayır və ya yerli geri çağırış serverini işə salmır.

## Etibarnamənin tutulması (WebSocket üsulu)

1. `https://m365.cloud.microsoft/chat` -da daxil olun və söhbətə başlayın.
2. Açıq**DevTools → şəbəkəsi** .
3. Filtr edin**WS** (WebSocket).
4. Chathub WebSocket bağlantısına klikləyin. `wss://substrate.office.com/m365Copilot/Chathub/` ilə başlayan URL axtarın.
5. Ondan** URL tələb edin** , surəti:
   - `access_token` sorğu parametri dəyəri (qısamüddətli JWT).
   - `/Chathub/` sonra Chathub yolu seqmenti (məsələn, `<oid>@<tenant>`).

Tam URL formasına malikdir:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute da seçin**Microsoft 365 Copilot** , köhnə API-key/import seçimini seçin və etimadnaməni formatda yapışdırın:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. klikləyin** Test Bağlantısı** və** Saxla** .

## Etibarnamənin tutulması (HAR idxalı)

WebSocket URL dən dəyərləri əl ilə kopyalamaq əvəzinə, siz DevTools HAR faylını ixrac edə bilərsiniz:

1. Açıq**DevTools → şəbəkəsi** .
2. Microsoft 365 Copilot söhbətinə başlayın və ya davam etdirin (bu, WebSocket bağlantısını işə salır).
3. Şəbəkə panelində sağ klikləyin və seçin** Hamısını məzmunu ilə HAR olaraq qeyd edin** .
4. OmniRoute-da istifadə edin** .har faylını idxal edin** provayder bağlantısı dialoqunda düymə.

OmniRoute Chathub WebSocket URL üçün HAR skan edir, `access_token` və `chathubPath` ni çıxarır və etimadnamə sahələrini avtomatik doldurur. HAR idxalı JWT müddətini deşifrə edir və tokenin qalan ömrünü göstərir.

> **Heç vaxt real HAR ixracı, giriş nişanı və ya yenilənmə nişanı etməyin.** Test və sənədləşdirmə dəyərləri həmişə yer tutucu olmalıdır.

## Token ömrü və yeniləmə

`access_token` qısamüddətlidir (adətən**~ 75 dəqiqə** ). İstifadəyə yararlı yeniləmə nişanı olmadan, müddəti bitdikdən sonra etimadnaməsini yenidən ələ keçirməlisiniz.

### `refreshToken` ilə avtomatik yeniləmə

Microsoft 365 provayderində** Bağlantı əlavə edin** və ya** Bağlantını redaktə edin** dialoq, açın** Qabaqcıl Parametrlər → Yeniləmə nişanı (isteğe bağlı)** . `substrate.office.com/sydney` əhatə dairəsi üçün Microsoft OAuth yeniləmə nişanı yapışdırın və yadda saxlayın. Giriş maskalanır və heç vaxt saxlanılan nişanla doldurulmur. Redaktə edərkən, mövcud nişanı saxlamaq üçün onu boş buraxın; onu əvəz etmək üçün yeni nişan yapışdırın.

Doğma giriş Microsoft birini qaytardıqda yeniləmə nişanını əldə edir. Köhnə idxal üçün mövcud uyğun Microsoft icazə kodu qrantından istifadə edin; bu provayder cihaz kodu axını həyata keçirmir və ya söz vermir. Konfiqurasiya edilmiş yeniləmə nişanı ilə OmniRoute sorğulardan əvvəl `access_token` yoxlayır və onu yalnız yeniləməyə ehtiyac duyduqda təzələyir. Uğurlu yeniləmə, həmçinin fırlanan yeniləmə nişanını davam etdirir, təzələmə nişanı etibarlı qalarkən əl ilə təkrar tutmaqdan qaçır.

Əgər `refreshToken` təyin edilməyibsə, hər müddət bitdikdən sonra WebSocket etimadnaməsini əl ilə yenidən götürməlisiniz.

## Modellər və marşrutlaşdırma

Doğma kataloqa bütün sənədləşdirilmiş müstəqil IDs və dörd orijinal yerli IDs daxildir. Kataloq statikdir və hesabdan müstəqildir, hesab hüququnun yoxlanışı deyil: ödənişli marşrutlar və uyğunluq ləqəbləri qoşulmuş hesab onlardan istifadə edə bilmədikdə belə siyahıda qalır. Modelin ekran etiketləri provayderin adını və hər model üçün əlçatanlıq lövhəsini buraxır; provayder qalır**Microsoft 365 Copilot** . Etiketlər qeyd olunur** ləqəb** və ya** Miras** onların mövcud identifikatorlarını və protokol xəritələrini saxlayırlar, tarixi model versiyasının zəmanəti deyil. Bağımsız proxy-lər** /modellərdən idxal edin** təlimatlar bu yerli WebSocket provayderinə şamil edilmir.

| Model ailə        | Kanonik IDs                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| Avtomatik         | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| Əvvəllər GPT      | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude Sonnet     | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude Opus       | `claude-opus`, `claude-opus-4.8`                                                                 |

`auto`, `quick`, `think-deeper` kimi ləqəblər və versiya ləqəbləri də qeydə alınıb. Mövcud `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` və `copilot-m365-gpt-5-5-chat` qüvvədə qalır. Sənədləşdirilmiş IDs provayder prefiksinə (`copilot-m365-web/claude-opus` və ya `m365copilot/claude-opus`) ehtiyac duyur: bir çoxları ümumi sözlər və ya digər təchizatçıların model adlarıdır, ona görə də çılpaq `claude-opus` bu provayder olmadan olduğu kimi marşrutlaşdırmağa davam edir. Qeydiyyat Microsoft bu modeli hər hesaba xidmət edəcəyi vəd deyil. Müstəqil IDs ictimai [protokol kataloqunu](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) izləyir (eksport edilmiş modeldən tona xəritə və onun modeldən xəbərdar ssenari metadatası). Bütün yerli profillər `availability: "unverified"` saxlayır; kataloqa daxil edilməsi uğurlu hesab testi deyil.

- Açıq-aydın model lisenziyasının imtinası qaytarılır** 403** `m365_model_not_licensed`, 502 deyil. Marşrutlaşdırma connection/model cütlüyünü kilidləyir və lisenziyalı modelləri əlaqədə istifadə edilə bilər.
- `InvalidCopilotLicense`, `m365_account_not_licensed` kimi ayrıca bildirilən hesab səviyyəsində lisenziyadan imtinadır.
- Hər istifadəçi üçün tənzimləyici qayıdır** 429** `m365_throttled` və əlaqəni soyuyur. Prioritetli giriş tükənməsi qayıdır** 429** `priority_access_exhausted` və model əhatəlidir. `errorCode: "ReasoningTurnExhausted"` ilə `OutOfCredits` nəticəsi** 429** `reasoning_turns_exhausted` əvəzinə, həmçinin model əhatəlidir, sıfırlama vaxtı tələb olunmur. Sürətli tonlar xidmət etməyə davam edərkən, bir iş kirayəçisinin "Daha dərin düşün" tonlarını bağlaması bildirildi; bu əhatə dairəsi bu deponun təkrar istehsal etdiyi bir şey deyil, istehlakçı müşahidəsidir. Marşrutlaşdırma buna görə də eyni soyutma müddəti üçün `gpt-5.5` və `gpt-5.6` -nin digər sənədləşdirilmiş daha dərin düşün modellərini həmin əlaqədə fırlanmadan çıxarır və Sürətli tonları və hər bir uğursuzluğu öz modelində buraxır. Təchiz edilmiş təkrar cəhd göstərişləri saxlanılır; itkin sıfırlama məlum sıfırlama vaxtı kimi elan edilmir.
- Copilot təhlükəsizlik rəddi (`Disengaged`) qaytarılır** 400** `provider_safety_rejection`, paylaşılan provayderin təhlükəsizlik-stop etiketi. Bu, heç vaxt əlaqənin sağlamlığı ilə hesablaşmır, müştəri SDKs 400-ü təkrar sınamır və `PROVIDER_SAFETY_STOPS_TERMINAL` aktivləşdirildikdə, sorğunu başqa hədəfə qarşı təkrar oxutmaq əvəzinə orada dayanır.
- Bir əlaqə üzrə sorğular mövcud hesab semaforu vasitəsilə seriallaşdırılır. Paralel panellərə deyil, prioritet geriyə üstünlük verin; Təkcə seriallaşdırma Microsoft-nın danışıq sürəti məhdudiyyətlərini aradan qaldırmır.

## Davranış və məhdudiyyətlər tələb edin

- Alətlər var** tez təqlid edilmişdir** , yerli Microsoft funksiyası çağırışları deyil. Alətin aktivləşdirdiyi sorğu bir tamponlanmış nəsildən istifadə edir; alətləri seçmək üçün başqa nəsil sərf etmir. Yalnız etibarlı dəstəklənən arqument formaları ilə elan edilmiş alətlər çağırış kimi qaytarılır.
- Tək arxada qalan nümunə ilə uzun strukturlaşdırılmış cavab nəsr kimi saxlanılır. Bu, niyyətin sübutu deyil, evristikdir; tətbiqlər hələ də öz alət icazələrini tətbiq etməlidir.
- Şəkil daxiletməsi veb müştərinin onu göndərdiyi şəkildə işləyir. Hər bir şəkil hissəsi (`image_url` data URL və ya ictimai HTTPS URL və ya Cavablar `input_image`) söhbət nişanı ilə növbənin söhbətinə `/m365Copilot/UploadFile` -ə yüklənir və mesaj `ImageFile` annotasiyası ilə onu göstərir; mətn onun oturduğu yeri qeyd edir (`[image 1]`, …). Təzə söhbət tarixdəki hər şəkli, davamı isə yalnız yeni mesajların şəkillərini yükləyir. Hər biri ən çox 10 MiB olan 10 PNG, JPEG, GIF və ya WebP şəkilləri (hər sorğu üçün 40 MiB ); format baytlardan oxunur. HTTPS URLs yalnız ictimai, DNS ilə bağlanmış uzaqdan görüntü qoruyucusu vasitəsilə əldə edilir. Uğursuz yükləmə sorğunu yerinə yetirmir (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` və ya `m365_image_invalid`); bir növbə ona verilmiş bir şəkil olmadan heç vaxt irəli getmir. Digər qeyri-mətn hissələri (audio, fayllar) açıq şəkildə rədd edilir, səssizcə atılmır.
- Növbəti sorğu eyni yuxarı söhbəti davam etdirir və yalnız əvvəlki cavabdan sonra mesajlar göndərir. O, həmin cavabı dəqiq şəkildə genişləndirməlidir: eyni əlaqə, model profili və alət dəsti; dəyişməmiş tarix (hər mesaj üzərində bir sha256 zənciri); və cavabın alət çağırışı idləri və ya onun mətni boşluğa qədər. Başqa hər şey (redaktə edilmiş tarixçə, eyni ilk mesajla başqa sessiya, fərqli cavab, 30 dəqiqə ərzində boş qalan söhbət və ya Copilot-nın 600 mesaj limitinə yaxın, id-siz əlaqə) bütün tarixçə ilə təzə söhbətə başlayır. Uğursuz dönüş heç vaxt bərpa edilmir və məzmunsuz `InternalError` təzə söhbətdə bir dəfə yenidən göndərilir (** 502** `m365_internal_error` yenidən uğursuz olarsa). Davamlar proses yaddaşında saxlanılır: yenidən başlatma təzə söhbətlərə başlayır.
- Hər növbə Copilot-nın müvəqqəti söhbətində (`disableMemory=1`) keçir: söhbət davam edərkən kontekstini saxlayır və heç vaxt hesabın söhbət tarixçəsində görünmür. Model testləri, Hamısını Test edin və birləşmiş testlər buna görə də söhbətləri geridə qoymadan bu provayderi yoxlaya bilər.
- Bir növbənin 120 saniyəlik boş qalma müddəti və məhdud ümumi son tarix var. Yalnız son cavablar, tərəqqinin filtrasiyası və ləğvi yerli transport/composer. tərəfindən idarə olunur
- Veb əsaslı cavablar öz mənbələrini saxlayır. Copilot xüsusi istifadə nəzarət simvolları ilə daxil edilmiş sitatı qeyd edir və mənbələri `references` kimi göndərir; hər bir marker uyğun `url_citation` annotasiyası (`message.annotations` və ya linki daşıyan hissədə `delta.annotations` ) ilə nömrələnmiş Markdown linkinə (`[1](https://…)` və ya Copilot markeri keçid hədəfi kimi istifadə etdikdə çılpaq URL ) çevrilir. Heç vaxt gəlməyən bir mənbə atılır, buna görə də markerlər heç vaxt müştəriyə çatmır. Yayım zamanı sitatdan sonrakı mətn onun mənbəyi gələnə qədər gözləyir.
- Copilot-nın əsaslandırma xülasəsi (`ChainOfThoughtSummary`), model birini göndərdikdə, heç vaxt cavabın bir hissəsi kimi deyil, `reasoning_content` olaraq qaytarılır. Özünü yenidən yazan xülasə növbəni itirmədən yayımı dayandırır.
- İstənilən məzmundan əvvəl, licence/throttle uğursuzluqları hətta axın tələb olunduqda da HTTP 403/429 saxlayır. Məzmun başladıqdan sonra uğursuzluqlar SSE səhv hadisələridir, heç vaxt uğurlu bitməz. Yalnız əlavə axını ilə təmsil edilə bilməyən yuxarı axının yenidən yazılması açıq axın xətasıdır; axın etməyən və buferləşdirilmiş alət cavabları yekun mətni saxlayır.
- Copilot əlaqənin özündən imtina etdikdə onun cavabı olduğu kimi bildirilir:** 401** rədd edilmiş və ya vaxtı keçmiş giriş üçün `m365_unauthorized` (yenidən daxil olun),** 429** tənzimləmə üçün `Retry-After` və əl sıxma uğursuzluğu ilə, əks halda heç vaxt ümumi əlaqə nasazlığı olmaz.

## Şəkil generasiyası

`model: "copilot-m365-web/m365-copilot-image"` (ləqəb `m365copilot/m365-copilot-image`) ilə `POST /v1/images/generations`, veb müştərinin etdiyi kimi Copilot-nin daxili şəkil aləti ilə çəkir. Hər bir şəkil bir Copilot növbəsidir: o, veb müştərinin şəkil seçiminə qoşulur və `GenerateGraphicArt` elan edir və şəkil Microsoft-nin Dizayner xidmətindəki artefaktı göstərən tərəqqi girişində gəlir. Həmin artefakt söhbət işarəsindən imtina edir, ona görə də OmniRoute əlaqənin yeniləmə nişanından Dizayner işarəsini çıxarır və baytları yükləyir; token yalnız `designerapp.officeapps.live.com` yə göndərilir.

- Doğma giriş bağlantısı lazımdır (təzələmə nişanı); yapışdırılmış işarə ilə uğursuz olur** 400** hər hansı bir növbə sərf edilməzdən əvvəl.
- `n` 1-4, hər biri bir döngədir. `size` yalnız oriyentasiyanı idarə edir (daha geniş, daha uzun və ya kvadrat), Copilot əmrdən oxuyur; Copilot render ölçüsünü seçir.
- Şəkillər inline qaytarılır: defolt olaraq `b64_json`, `response_format: "url"` üçün URL datası.
- Yaradılmış şəkillər söhbətdən ayrı, kiçik bir gündəlik büdcə ilə çəkilir. İstifadə edildikdə sorğu uğursuz olur** 429** . Şəkilsiz cavab verən dönüş uğursuz olur** 502** (və ya** 400** /** 503** Copilot mətni imtina və ya qabiliyyət problemi kimi oxunduqda); mesajda deyilir ki.

## Təhlükəsizlik modeli

- **Qeyri-rəsmi inteqrasiya.** Bu provayder BizChat WebSocket protokolunu tərs mühəndisləşdirir. Microsoft son nöqtəni dəyişdikdə xəbərdarlıq etmədən pozula bilər.
- `subscriptionRisk: true` bayrağı inteqrasiyanın sənədsiz son nöqtəyə əsaslandığını əks etdirir. Hesab məhdudiyyətləri mümkündür, lakin təsdiqlənmir.
- Giriş nişanı qısamüddətli JWT. Onu parol kimi qəbul edin: onu qəbul etməyin, daxil etməyin və ya paylaşmayın.
- Yeniləmə nişanı Microsoft 365 səthinə davamlı giriş imkanı verir. Onu API açarı ilə eyni qayğı ilə saxlayın.

## Problemlərin aradan qaldırılması

### Doğrulama dərhal uğursuz olur

- -dən kopyaladığınızı təsdiqləyin**WebSocket URL** , XHR/Fetch sorğusundan deyil. Etibarnamə Chathub WebSocket bağlantısının `access_token` sorğu parametrindədir — `Authorization: Bearer` başlığında deyil.
- `chathubPath` URL yolundan tam `<oid>@<tenant>` seqmentini ehtiva etdiyinə əmin olun.

### Token ~ 75 dəqiqədən sonra başa çatır

Bu gözlənilir. `refreshToken` olmadan, giriş nişanı qısa ömürlüdür. Ya:

- DevTools-dan etimadnaməni yenidən götürün və ya
- Konfiqurasiya edin** Qabaqcıl Parametrlər → Yeniləmə nişanı (isteğe bağlı)** avtomatik yeniləmə üçün əlaqə əlavə et və ya redaktə et dialoq qutusunda.

### Test Bağlantısı keçdi, lakin söhbət 401 qaytarır

ilə yaradılmış əlaqə üçün** Microsoft ilə daxil olun** , Test Bağlantısı giriş nişanının istifadə müddətini yoxlayır və saxlanmış yeniləmə nişanı ilə vaxtı keçmiş nişanı yeniləyir, beləliklə, keçən test də yeniləmə nişanının hələ də işlədiyini sübut edir.

Yapışdırılmış etimadnaməsi üçün Test Bağlantısı etimadnamənin formasını yoxlayır və nişanın müddəti bitdikdə, provayderin istifadə edəcəyi nişanın müddətinin bitmədiyini yoxlayır (bağlantıda saxlanılan token köhnəlmiş pastanı qazanır; təzələmə nişanı yenilənə bilən sayılır). Müddəti bitməzdən əvvəl ləğv edilmiş token hələ də sınaqdan keçir; söhbət sonra qayıdır** 401** `m365_unauthorized`. istifadə edin** Microsoft ilə daxil olun** yenidən və ya təzə etimadnaməsini yenidən ələ keçirin.

### Copilot provayder siyahısında görünmür

`copilot-m365-web` aktiv olduğundan əmin olun** Dashboard → Provayderləri** . Provayder bəzi səviyyələrdə defolt olaraq gizlənə bilər.
