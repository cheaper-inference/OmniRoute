> **Qısa xülasə**: `open-sse/` OmniRoute daxilində hər bir LLM sorğusunu işlədən əsas axın mühərrikidir. Burada sorğu konveyerini, icraçıları, xidmətləri, MCP serverini və tərcümə qatını həyata keçirən təxminən 1,400 fayl var. Bu təlimat hissələrin bir-biri ilə necə əlaqəli olduğunu izah edir.

**Mənbə:** `open-sse/` (iş sahəsi paketi, test olmayan təxminən 1,440 `.ts` faylı)

---

## Niyə ayrıca iş sahəsi paketi?

`open-sse/` bir neçə səbəbə görə OmniRoute monoreposunda **müstəqil iş sahəsidir**:

1. **Təkrar istifadə imkanı** — `open-sse`, npm-də `@omniroute/open-sse` kimi dərc edilir, buna görə digər layihələr ondan müstəqil şəkildə istifadə edə bilər
2. **Aydın sərhədlər** — axın mühərriki OmniRoute-a xas UI/DB qatından ayrılıb
3. **Performans** — mühərrikin Next.js asılılıqları yoxdur, bu da CLI/serverless kontekstlərində daha sürətli soyuq başlanğıca imkan verir
4. **Versiyalaşdırma** — `open-sse` öz buraxılış qrafikinə uyğun olaraq buraxıla bilər

```json
// package.json
"workspaces": ["open-sse"]
```

## Sorğu konveyeri

Hər LLM sorğusu **5 mərhələli konveyerdən** keçir:

```
                              ┌──────────────────┐
   HTTP sorğusu               │  1. MARŞRUTLAŞDIR│   kombinasiyanın həlli, model seçimi
   (Next.js marşrutu)          └────────┬─────────┘
                                       │
                                       ▼
                              ┌──────────────────┐
                              │  2. TƏRCÜMƏ ET   │   format çevrilməsi (OpenAI ↔ Claude ↔ Gemini)
                              └────────┬─────────┘
                                       │
                                       ▼
                              ┌──────────────────┐
                              │  3. İCRA ET      │   provayder icraçısı, HTTP, təkrar cəhd, qoruyucu
                              └────────┬─────────┘
                                       │
                                       ▼
                              ┌──────────────────┐
                              │  4. AXINLA ÖTÜR  │   SSE transformasiyası, əks təzyiq
                              └────────┬─────────┘
                                       │
                                       ▼
                              ┌──────────────────┐
                              │  5. QEYDƏ AL     │   istifadə izlənməsi, çağırış jurnalı, xəta təsnifatı
                              └────────┬─────────┘
                                       │
                                       ▼
                              HTTP cavabı (SSE və ya JSON)
```

### Mərhələ 1: Marşrutlaşdırma (services/combo.ts)

**Giriş nöqtəsi**: `services/combo.ts` daxilindəki `handleComboChat()`

Sorğunu konkret `(provider, model, account, credentials)` kortejinədək həll edir:

- Kombinasiyanı ID üzrə axtarır (və ya `auto/*` modelləri üçün virtual kombinasiya yaradır)
- Marşrutlaşdırma strategiyasını tətbiq edir (prioritet, çəkili, növbəli və s.)
- Sağlam olmayan provayderləri filtrdən keçirir (dövrə qoruyucusu)
- Növbəti uyğun hədəfi seçir

`auto/*` modelləri üçün bu mərhələ həmçinin:

- **16 amilli qiymətləndirmə** alqoritmini işə salır (`services/autoCombo/`)
- Sağlamlıq, xərc, gecikmə və digər amillərə əsasən `provider+model` cütünü seçir

### Mərhələ 2: Tərcümə (translator/)

Mənbə formatı (məsələn, OpenAI) hədəf formatından (məsələn, Claude) fərqlənirsə, sorğu **tərcümə edilir**:

- Sistem promptu → sistem mesajı
- Alət tərifləri → provayderə xas alət formatı
- Mühakimə/düşünmə parametrləri → provayderə xas ekvivalentlər
- Mesaj rollarının normallaşdırılması (OpenAI olmayan sistemlər üçün `developer` → `system`)

`translator/index.ts` aşağıdakıları təqdim edir:

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### Mərhələ 3: İcra (executors/)

**Giriş nöqtəsi**: `getExecutor(providerId).execute(request, options)`

Bütün provayderlər `getExecutor()` fabrikinin ehtiyat variantı vasitəsilə `DefaultExecutor`-dan (`executors/default.ts`) istifadə edir. İcraçı:

- Yuxarı axın URL-ni yaradır (`buildUrl()`)
- Provayderə xas başlıqları əlavə edir (`buildHeaders()`)
- Sorğu gövdəsini çevirir (`transformRequest()`)
- HTTP sorğusunu təkrar cəhd və eksponensial gecikmə ilə göndərir
- Lazım olduqda autentifikasiya məlumatlarını yeniləyir (OAuth provayderləri)

Bütün icraçılar aşağıdakıları təmin edən `BaseExecutor`-u (`executors/base.ts`, 1170 kod sətri) genişləndirir:

- Ümumi təkrar cəhd məntiqi
- Proksi inteqrasiyası
- Dövrə qoruyucusu inteqrasiyası
- İstifadənin qeydə alınması üçün qarmaqlar

### Mərhələ 4: Axın (utils/stream.ts)

Axınla ötürülən cavablar üçün icraçı **ReadableStream** qaytarır. Emalçı:

- SSE transformasiyasından keçirir (`createSSETransformStreamWithLogger`)
- Ölü bağlantıları aşkar etmək üçün heartbeat pingləri tətbiq edir
- Müştəri bağlantısının kəsilməsini düzgün şəkildə idarə edir (`pipeWithDisconnect`)
- Axınla ötürülməyən müştərilər üçün SSE → JSON çevrilməsini həyata keçirir

Axınla ötürülməyən cavablar üçün icraçı dəyişdirilmədən ötürülən, təhlil edilmiş JSON obyekti qaytarır.

### Mərhələ 5: Qeydəalma (services/usage.ts)

Cavabdan sonra (uğurlu və ya uğursuz olmasından asılı olmayaraq) istifadə qeydə alınır:

- Cavabdan `prompt_tokens`, `completion_tokens`, `cached_tokens`
- Qiymət məlumatları əsasında hesablanan `cost_usd`
- Uğursuz olduqda `latency_ms`, `status`, `error_class`
- `usage_history` cədvəlində saxlanılır

Çağırış jurnalı artefaktları (aktivləşdirilibsə) `${DATA_DIR}/call_logs/` qovluğuna yazılır.

## Açar Fayllar Dərin Dalış

### chatCore.ts (5977 sətir)

The** əsas sorğu işləyicisi** . Ölçüsünə baxmayaraq, aydın bir quruluşa malikdir:

```ts
// Pseudo-structure of chatCore.ts
export async function handleChat(request: NextRequest) {
  // 1. Auth + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. Body validation
  const body = await parseRequestBody(request);

  // 3. Format detection + translation
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. Combo routing
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // Continue to next target
    }
  }

  // 5. Emergency fallback
  return await emergencyFallback(body);
}
```

Bir nəhəng funksiya olmasına baxmayaraq, o, təşkil edilmişdir** şərh bölmələri** 5 mərhələli boru kəmərinin xəritəsi.

// services/combo.ts
export async function handleComboChat(body, comboId): Promise<ChatResult> {
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      return await handleSingleModel(target, body);

### base.ts (1170 LOC)

The** mücərrəd icraçı** ki, hər bir icraçı sinfi (birbaşa və ya `DefaultExecutor` və digər alt siniflər vasitəsilə) genişlənir. Tərkibində:

- `buildUrl()` — defolt URL konstruksiyası (alt siniflər xüsusi üçün ləğv edilir)
- `buildHeaders()` — defolt başlıqları (auth, məzmun növü)
- `transformRequest()` — defolt olaraq keçid
- `execute()` — retry/backoff/breaker ilə əsas HTTP loop

```ts
// open-sse/executors/default.ts
export class DefaultExecutor extends BaseExecutor {
  // Handles all OpenAI/Anthropic-compatible providers
  // Providers register configurations (URL, auth, headers) but share executor logic
}
```

Provayderə xas davranış (auth başlıqları, əsas URL, versiya başlıqları) ayrıca icraçı sinifləri deyil, provayder reyestri vasitəsilə konfiqurasiya edilir.

````

## İcraçılar (150 modul)

Provayder üçün əsasən bir fayl. İcraçı siniflərin hamısı `BaseExecutor` genişləndirir və fərqli olanları ləğv edir; digər modullar provayderə görə köməkçilərdir (alət sxemləri, fetch/TTS adapterləri, quirk işləyiciləri).

### Ümumi Nümunələr

Provayderlər konfiqurasiya edilmiş icraçını qaytaran `getExecutor(providerId)` vasitəsilə həll edilir. OpenAI/Anthropic-compatible provayderləri `DefaultExecutor` (`executors/default.ts`) istifadə edir. Provayderə xas davranış (əsas URL, auth başlıqları, API versiyası) `open-sse/config/providers/`-də konfiqurasiya edilir, sorğunun əsas çevrilmələri isə `open-sse/translator/`-da idarə olunur.

**Xüsusi URL** provayder konfiqurasiyası vasitəsilə təyin edilir:

```ts
// Provider config in open-sse/config/providers/
export default {
  id: "together",
  baseURL: "https://api.together.xyz/v1/chat/completions",
}
````

**Fərdi auth** provayder reyestrinin auth konfiqurasiyası (API açarı, OAuth, başlıq profilləri) vasitəsilə idarə olunur.

**Xüsusi sorğu orqanı** transformasiyalar (məsələn, `system` `messages` dən ayıran Anthropic ) `open-sse/translator/`-də hər provayder üçün qeydə alınır.

````

### The Executor Factory

`executors/index.ts` exports `getExecutor(providerId)`:

```ts
import { getExecutor } from "@omniroute/open-sse/executors";

const executor = getExecutor("anthropic");
const result = await executor.execute({
  model: "claude-sonnet-4-5",
  messages: [...],
});
````

Qətnamə `ExecutorRegistry` (`executors/registry.ts`) üzərindən keçir: hər bir ixtisaslaşdırılmış icraçı `executors/index.ts` nin daxili cədvəlində elan edilir və modulun yüklənməsi zamanı `registerExecutor(alias, instance)` vasitəsilə qeydə alınır; `getExecutor()` reyestrlə məsləhətləşir və xüsusi giriş olmadan istənilən provayder üçün yadda saxlanılan `DefaultExecutor` -ə qayıdır. Tam ləqəb → icraçı xəritələşdirilməsi qızıl test `tests/unit/executor-map-golden.test.ts` ilə xarakterizə olunur.

## Tərcüməçilər

**3 format** arasında tərcümə edir: OpenAI, Anthropic, Gemini və həmçinin yeni Responses API.

### Tərcümə nə zaman baş verir

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
  body = translateRequest(body, sourceFormat, targetFormat);
}
```

Ümumi tərcümələr:

- `OpenAI → Anthropic`: ayrıca `system` sahəsi, `x-api-key` başlığı
- `OpenAI → Gemini`: `messages` əvəzinə `contents`, `systemInstruction`
- `OpenAI → Responses API`: `input` massivi, `previous_response_id` vəziyyəti

### Emal edilən kənar hallar

- `developer` rolu → OpenAI-dan fərqli sistemlər üçün `system`
- `system` rolu → GLM/ERNIE üçün ilk istifadəçi mesajına birləşdirilir
- `json_schema` → Gemini-nin `responseMimeType` + `responseSchema` formatı
- `tools` → provayderə xas alət formatı
- Düşünmə parametrləri (o1, Claude) → provayderə xas ekvivalentlər

## MCP Serveri

`open-sse/mcp-server/` **Model Context Protocol** serverini reallaşdırır:

- **110 alət** (provayderlərin idarə edilməsi, kombinasiyalar, yaddaş, keş, sıxılma, proksi, bacarıqlar, oyunlaşdırma, plaginlər, Notion, Obsidian, lokal korpus)
- **3 nəqliyyat üsulu**: stdio, SSE, Streamable HTTP
- Dəqiq səviyyəli avtorizasiya üçün **33 icazə sahəsi**

### Alətlərin qeydiyyatı

Alətlər `open-sse/mcp-server/tools/` daxilində müstəqil fayllar kimi qeydiyyatdan keçirilir; hər biri ad, sxem, emal funksiyası və icazə sahəsini ixrac edir:

```ts
// open-sse/mcp-server/tools/getHealth.ts
import { z } from "zod";
export default {
  name: "omniroute_get_health",
  description: "Get system health snapshot",
  scope: "read:health",
  inputSchema: z.object({}),
  handler: async (_args, ctx) => {
    return await getSystemHealth();
  },
};
```

### Nəqliyyat üsulları

```ts
// stdio (CLI istifadəsi)
startMcpStdio(server);

// SSE (HTTP əsaslı axın)
startMcpSse(server, port);

// Streamable HTTP (müasir MCP)
startMcpStreamable(server, port);
```

### Avtorizasiya

Hər alət çağırışı icazə sahəsi yoxlamalarından keçir (`open-sse/mcp-server/auth/`):

```ts
if (!hasScope(apiKey, "providers:read")) {
  throw new Error("Insufficient scope");
}
```

## Transformatorlar

`open-sse/transformer/` **Chat Completions** və **Responses API** formatları arasında çevirmə aparır.

### Niyə ayrıca transformator?

Responses API, OpenAI-ın **vəziyyət saxlayan söhbətlərə** (`previous_response_id`) malik yeni formatıdır. Müştəri Responses sorğusu göndərdikdə OmniRoute:

1. Daxildə Responses → Chat Completions çevrilməsini həyata keçirir
2. Sorğunu provayderə (Chat Completions dəstəkləyən istənilən provayderə) göndərir
3. Cavabı yenidən Responses formatına çevirir
4. Çevrilmiş cavabı axın şəklində müştəriyə göndərir

Transformator (`transformer/responsesTransformer.ts`) aşağıdakıları təmin edir:

```ts
createResponsesApiTransformStream(): TransformStream
```

Bu, aşağıdakıları emal edir:

- `response.output_item.added` hadisələri
- `response.output_text.delta` hadisələri
- `response.completed` hadisəsi
- Alət çağırışlarının uyğunlaşdırılması (`function_call` ↔ `tool_calls`)

## Anti-Patternlər

❌ **`combo.ts` daxilində sinxron DB çağırışları** — əvvəlcədən hesablayın və keşləyin
❌ **İşləyicilərdə təkrar cəhd məntiqi** — dayanıqlılıq xidmətindəki `retry()` funksiyasından istifadə edin
❌ **Provayder konfiqurasiyasına birbaşa giriş** — `providerRegistry` getter-lərindən istifadə edin
❌ **Sərt kodlaşdırılmış ehtiyat keçid zəncirləri** — `modelFamilyFallback.ts` daxilində müəyyən edin
❌ **Paralel sorğular arasında vəziyyət dəyişiklikləri** — yalnız sorğu miqyaslı kontekstdən istifadə edin

## Yeni Komponentin Əlavə Edilməsi

### Yeni Xidmətin Əlavə Edilməsi

1. Məhdud və konkret məsuliyyət daşıyan `open-sse/services/[serviceName].ts` yaradın
2. Əsas işləyici funksiyanı və bütün sabitləri ixrac edin
3. `tests/unit/services/[serviceName].test.mjs` daxilində vahid testlər əlavə edin
4. Marşrutlaşdırma ilə əlaqəlidirsə, `handlers/chatCore.ts` daxilində sorğu emalı ardıcıllığına inteqrasiya edin
5. Xidmət hədəf seçiminə təsir edirsə, `combo.ts` daxilində marşrutlaşdırma məntiqini yeniləyin
6. Bu faylda sənədləşdirin

### Yeni İcraedicinin Əlavə Edilməsi

1. `BaseExecutor` sinfini genişləndirən `open-sse/executors/[provider].ts` yaradın
2. `config/providerRegistry.ts` daxilində qeydiyyatdan keçirin
3. `executors/index.ts` fabrik funksiyasına əlavə edin
4. İcraedici üçün vahid testlər əlavə edin
5. `docs/architecture/ARCHITECTURE.md` daxilində sənədləşdirin

### Yeni MCP Alətinin Əlavə Edilməsi

1. `open-sse/mcp-server/tools/[category]Tools.ts` faylını yaradın və ya yeniləyin
2. Girişlər üçün Zod sxemini müəyyən edin
3. Aləti `mcp-server/index.ts` daxilində qeydiyyatdan keçirin
4. `mcp-server/auth/` daxilindəki əhatə matrisi bölməsinə əlavə edin
5. Vahid testlər əlavə edin
