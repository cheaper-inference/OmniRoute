`@omniroute/opencode-plugin-v2` bütün OmniRoute kataloqunuzu — modelləri, kombinasiyaları və
avtomatik kombinasiyaları — görünən adlar, qiymətlər və pulsuz səviyyə
limitləri ilə birlikdə OpenCode v2-nin model seçicisinə əlavə edir.

Bu, `@omniroute/opencode-plugin` paketindən ayrı paketdir, çünki OpenCode v1 və v2
plaginləri fərqli müqavilələr vasitəsilə yükləyir. OpenCode-un əsas versiyasına uyğun olanı
seçin; onlar arasında heç nə paylaşılmadığı üçün birini yeniləmək heç vaxt digərini yeniləməyə
məcbur etmir.

## Tələblər

- OpenCode v2.
- Əlçatan OmniRoute şlüzü (standart olaraq `http://localhost:20128`).
- Node.js 22 və ya 24.

## Quraşdırma

Plagini `opencode.json` faylına əlavə edin:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Bundan sonra modellər `omniroute/<provider>/<model>` formasında görünür; `providerId` həmin
prefiksi və OpenCode-un giriş məlumatını saxladığı inteqrasiya identifikatorunu müəyyən edir.

## Giriş məlumatları

Plagin şlüz açarını aşağıdakı üç yerdə, bu ardıcıllıqla axtarır:

1. **OpenCode-da qoşduğunuz giriş məlumatı.** Plagin inteqrasiya qeydiyyatdan keçirdiyi üçün
   OpenCode-un öz autentifikasiya prosesi açarı saxlaya bilər. `opencode.json` faylına heç nə
   yazılmır — buna üstünlük verin.
2. Layihəyə məxsus əvəzləmə üçün plagin seçimlərindəki `apiKey`. Bu, açarı repozitoriyaya
   daxil edə biləcəyiniz bir faylda saxlayır.
3. Mühitdəki `OMNIROUTE_API_KEY`.

Bu üçündən heç biri olmadıqda kataloq boş olur və plagin sizi səssizcə boş seçici ilə
baş-başa qoymaq əvəzinə başlanğıcda bunu bir dəfə bildirir.

### İdarəetmə tokeni fərqli açardır

Kombinasiyalar, provayderin vəziyyəti və zənginləşdirmə (görünən adlar, qiymətlər və pulsuz
səviyyə limitləri) şlüzün `/api/*` son nöqtələrindən əldə edilir. Əksər yerləşdirmələr bu son
nöqtələri inferensiya açarı əvəzinə **idarəetmə** tokeni ilə qoruyur:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

`managementReadToken` təyin edilmədikdə `apiKey` istifadə olunur. Şlüz bu alternativi rədd
etdikdə kataloq yenə də yayımlanır, lakin görünən adların əvəzinə xam model identifikatorları
ilə, kanonik alias təkrarsızlaşdırması, qiymətlər və kombinasiyalar olmadan təqdim edilir.
Bu baş verdikdə plagin hər son nöqtə üçün bir dəfə xəbərdarlıq edir, son nöqtənin adını və
nələrin itirildiyini göstərir — beləliklə, məhdud işləyən seçicinin səbəbi heç vaxt müəmmalı
qalmır.

## Kataloq necə təzə qalır

Kataloq tənbəlliklə gətirilir və `modelCacheTtlMs` üçün yaddaşda saxlanılır və — əlçatmaz olduqda disk snapshotı sonuncu məlum kataloqu mövcud saxlayır. Modellər və kombinlər gələn kimi dərc olunur; avtomatik kombinasiyalar, provayder siyahısı və zənginləşdirmə üst-üstə düşən zaman qatlanır, beləliklə, bir yavaş son nöqtə bütün seçicini girov saxlaya bilməz.

Adlar `Provider - Model[ (Editor)][ · budget][ (route)]` sonra gəlir: id bir daşıyanda provayder göstərilir (çirksiz id prefikssiz göstərilir), aparıcı `🆓` pulsuz girişləri qeyd edir və onların pulsuz səviyyəli büdcəsi `· 1M tokens/month` şəkilçisi kimi qalır, açıq `Editor: Model` adının redaktoru arxadakı mötərizələrə keçdikdə və başqa adlar təxmin edilmədən (redaktor yoxdur) göstərilir. pulsuz `combo - <slug>`. Bir adı paylaşan iki giriş — `(no-think)` — marşrut şəkilçisi alır ki, onlar fərqlənə bilsinlər. `providerTag` (defolt `true`) arxadakı redaktor mötərizəsini dəyişdirir.

Əl ilə yeniləmə əmri yoxdur: OpenCode v2 əmrləri geri çağırışlar deyil, operativ şablonlardır, ona görə də plagin birini ifşa edə bilməz. Yeniləmələr TTL ə uyğundur; hostdan yalnız kataloq və ya üst-üstə düşmə faktiki olaraq dəyişdikdə yenidən yükləməsi xahiş olunur, hər yeniləmədə heç vaxt.

## Gemini-də alət çağırışı

Gemini, alət bəyanlarında `$schema` və ya `additionalProperties` olan bütöv sorğunu rədd edərək `400 INVALID_ARGUMENT` cavabını verir. Plagin bu açar sözləri həmin provayderin Gemini modelinə göndərilən alət sxemlərindən çıxarır və bütün digər sorğulara toxunmur. `$ref` ehtiva edən alət dəyişdirilmədən ötürülür, çünki istinadın silinməsi sxemi «hər şeyi qəbul et» səviyyəsinə qədər genişləndirərdi.
Bunu söndürmək üçün `"geminiSanitization": false` təyin edin.

## Problemlərin aradan qaldırılması

| Simptom                                                        | Səbəb                                                                                                                         |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Seçici OmniRoute modelini göstərmir                            | Heç bir açar həll edilmədi (başlanğıc xəbərdarlığını yoxlayın) və ya şluz əlçatmazdır                                         |
| Xam model identifikatorları, kombinasiya yoxdur, qiymət yoxdur | Rəhbərliyin son nöqtələri — set `managementReadToken` tokenindən imtina etdi                                                  |
| Qısa və ya boş `freeOnly` kataloqu                             | Heç bir idarəetmə nişanı və ya imtina edilmiş nişan — host jurnalında yeniləmə xülasə xəttini (`unmatched-free` sayı) oxumadı |
| Seans `opencode-<id>/...`-ya bağlandı                          | v1 plaqini `opencode-<id>` nəşr etdi; v2 `<id>` çılpaq dərc edir, ona görə də `<id>/...` altında modeli yenidən seçin         |

Ətraf mühit dəyişənləri opencode server prosesinə çatmalıdır: host bir xidmət kimi işlədikdə, `opencode models` işləyən qabıq və server mühiti fərqlidir, ona görə də açarı serverin oxuduğu yerə ixrac edin.
