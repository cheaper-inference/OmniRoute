Fərdi JSON API nodu OpenAI və ya Anthropic protokolunu danışmayan JSON biznes son nöqtəsini birləşdirir. OmniRoute JSON sorğu şablonunu doldurur, onu tam son nöqtəyə göndərir URL, cavab yolundan cavabı oxuyur və müştərinin öz formatında (Söhbət Tamamlamaları, Cavablar, Mesajlar, ...) müştəriyə qaytarır.

Bu, `apiType: "custom-json"` ilə OpenAI-a uyğun qovşaqdır; onun id-si `openai-compatible-custom-json-<suffix>` formasına malikdir. İdarə paneli forması hələ mövcud deyil. Aşağıdakı API provayder node vasitəsilə bu qovşaqları yaradın və redaktə edin.

## Bir node yaradın

`POST /api/provider-nodes` (idarəetmə auth):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` edir** tam** son nöqtə URL. Heç bir şey əlavə edilmir ( `/chat/completions` yoxdur, `/models` yoxdur) və digər OpenAI uyğun qovşaqlardan fərqli olaraq, standart URL yoxdur. O, daxil edilmiş etimadnamələri və ya `#fragment` olmadan `http(s)` olmalıdır və o, həm node saxlandıqda, həm də hər sorğuda hər bir provayder qovşağı ilə eyni gedən URL qoruyucusundan keçir.
- Bağlantı açarını göndərən qovşaq (`authType` `bearer` və ya `api-key`, standart daxil olmaqla) `https://` istifadə etməlidir. Düz `http://` yalnız geri dönmə hostu üçün (`localhost`, `127.0.0.0/8`, `::1`) və ya heç bir açar göndərməyən `authType: "none"` ilə qəbul edilir. Şəxsi LAN ünvanları (`10.x`, `172.16-31.x`, `192.168.x`) istisna deyil: həmin şəbəkədəki hər kəs açarı oxuya bilər. Belə bir qovşağın saxlanması `400` ilə uğursuz olur və əvvəllər saxlanılan node hər hansı sorğu göndərilməzdən əvvəl eyni mesajla hər sorğuda bağlanır. LAN-da açarlı son nöqtə üçün onu TLS arxasına qoyun (məsələn, əks proxy).
- `customJson` Zod ilə təsdiqlənir; naməlum açarlar rədd edilir. Hər sahə isteğe bağlıdır:

| Sahə              | Dəyərlər                                    | Defolt                                                 |
| ----------------- | ------------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                      | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                 | `bearer`                                               |
| `authHeader`      | `api-key` zamanı istifadə olunan başlıq adı | `X-API-Key`                                            |
| `requestTemplate` | JSON obyekti (≤ 64 KB, dərinlik ≤ 32)       | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | sahə yolu və ya bütün bədən üçün `$`        | `choices[0].message.content`                           |

- Sirr əlaqənin API açarında qalır, heç vaxt şablonda deyil. `bearer` `Authorization: Bearer <key>` göndərir; `api-key` `<authHeader>: <key>` göndərir. Doğrulama başlığı `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` və ya hop-by-hop başlığı ola bilməz. `none` ilə bağlantılar açara ehtiyac duymur.
- Əlavə statik başlıqlar qovşağın adi `customHeaders` istifadə edir (hər digər uyğun qovşaqla eyni yoxlama; orada auth başlıqlarına icazə verilmir).

`PUT /api/provider-nodes/<id>` eyni `customJson` qəbul edir və qovşağın hər bir mövcud əlaqəsində `baseUrl` və konfiqurasiyanı yenidən yazır. `customJson` buraxılması saxlanılan konfiqurasiyanı saxlayır; `apiType` `chat` və ya `responses` ə keçməsi onu qovşaqdan və onun birləşmələrindən çıxarır.

Sonra düyünə həmişə olduğu kimi bir əlaqə əlavə edin ( node id ilə `POST /api/providers` ) və sorğu `<prefix>/<model>`, məsələn `biz/assistant-v1`. Son nöqtə heç bir model siyahısını göstərmir, ona görə də model identifikatorlarını əl ilə əlavə edin.

## Şablonları tələb edin

Şablonlar sadə JSON. Sətir dəyəri `{{placeholder}}` markerlərini ehtiva edə bilər; heç bir şey qiymətləndirilmir və ya icra edilmir və obyekt açarları heç vaxt əvəz olunmur.

| Yer tutucu           | Dəyər                                                                            |
| -------------------- | -------------------------------------------------------------------------------- |
| `{{prompt}}`         | Ən son istifadəçi mesajının mətni (yeni sətirlərlə birləşdirilən mətn hissələri) |
| `{{messages}}`       | Söhbət OpenAI chat formatında                                                    |
| `{{model}}`          | Tələb olunan model id, provayder prefiksi olmadan                                |
| `{{stream}}`         | Həmişə `false` — son nöqtə bir JSON sənədi ilə cavab verir                       |
| `{{request.<path>}}` | Tərcümə edilmiş (OpenAI chat formatı) sorğunun sahəsi                            |

- Tam bir yertutan olan dəyər JSON tipini saxlayır (`"{{messages}}"` massiv olur); daha uzun sətir daxilində yer tutucu mətn kimi daxil edilir.
- Heç bir nəticə verməyən yertutan natamam yük göndərmək əvəzinə HTTP 400 ilə sorğunu yerinə yetirmir.
- Yollar nöqtə qeydindən və rəqəmsal indekslərdən (`data.items[0].text`) istifadə edir. `__proto__`, `prototype` və `constructor` açarlarda və yollarda rədd edilir.

## Cavablar

`responsePath` -dakı dəyər köməkçi cavab olur: sətirlər keçir, digər JSON dəyərləri seriallaşdırılır. Çatışmayan və ya `null` sahəsi və ya JSON olmayan gövdə HTTP 502-ni qaytarır. Upstream xəta statusları ötürülür. Axın müştəriləri üçün OmniRoute bütün JSON cavabını gözləyir və sonra onu bir məzmun yığını üstəgəl bitiş parçası kimi yayır; bu token axını deyil. Alət zəngləri və istifadə sahələri xəritələnmir.

## Heç vaxt təkrarlanmadı

Biznes sorğusu uğursuz olsa belə yan təsirləri ola bilər. OmniRoute buna görə də onu bir dəfə göndərir:

- nəqliyyatın təkrar cəhdi və izləmə yönləndirməsi yoxdur;
- başqa bir əlaqədə təkrar cəhd yoxdur (hesabın geri qaytarılması) — uğursuzluq olduğu kimi qaytarılır və əlaqə soyudulmur;
- hətta boş və ya uğursuz cavab üçün belə növbəti kombinasiya hədəfinə geri dönüş yoxdur.

Ayrı-ayrı müştəri sorğuları və bir neçə modeli açıq şəkildə çağıran birləşmə panelləri hələ də son nöqtəni müstəqil olaraq çağırır.

## Bir node sınaqdan keçirilir

Əlaqənin, əlaqənin saxlanması** Test** düymə və fon sağlamlığı yoxlamaları heç vaxt son nöqtəni çağırmır: onlar yalnız saxlanılan konfiqurasiyanı təsdiqləyir və əlaqəni yoxlanıla bilməyən kimi bildirirlər.

`"apiType": "custom-json"` və qovşaq sahələri (`baseUrl`, `apiKey`, `customJson`, isteğe bağlı `customHeaders` və `modelId`) olan `POST /api/provider-nodes/validate` ən son istifadəçi mətni kimi `ping` ilə tam olaraq bir real sorğu göndərir. O, `{ "valid": true }` və ya yuxarı axın statusuna cavab verir (heç vaxt yuxarı orqan deyil).

## Saxlama

Konfiqurasiya `provider_nodes.custom_json_config_json` -da (miqrasiya `240_provider_node_custom_json_config.sql`) saxlanılır və hər bir əlaqənin `providerSpecificData.customJson` ə kopyalanır.

İcra: `open-sse/utils/customJson.ts` (təsdiqləmə və şablonlaşdırma), `open-sse/executors/customJson.ts` (icraçı), `open-sse/services/combo/noReplayLatch.ts` və `src/sse/handlers/chat/responsePolicies.ts` (təkrarsız).
