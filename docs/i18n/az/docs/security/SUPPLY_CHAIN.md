OmniRoute npm + Docker artefaktlarını dərc edir. Bu qapılar mənşə, inventar (SBOM) və CVE skanlamasını təmin edir, hamısı Açıq Mənbədir (OSS), buraxılış iş axınlarına inteqrasiya olunmuşdur. **Məsləhət-əsaslı** yanaşma — onlar indi hesabat verir, ilk uğurlu buraxılışdan sonra bloklama səviyyəsinə yüksəldilir.

| Qapı                | Alət                                           | Harada                        | Bloklayır?                       | Çıxış                                         |
| ------------------- | ---------------------------------------------- | ----------------------------- | -------------------------------- | --------------------------------------------- |
| SLSA mənşəyi (npm)  | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | yalnız dərc uğursuz olarsa       | badge npmjs / `npm audit signatures`          |
| SBOM npm            | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | yalnız generasiya uğursuz olarsa | Release asset + artifact                      |
| SBOM image          | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | məsləhət xarakterli              | CycloneDX artifact                            |
| Trivy CVE (SARIF)   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | məsləhət xarakterli              | SARIF (HIGH+CRITICAL) → Security tab          |
| Trivy CRITICAL qapı | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **bloklayıcı**                   | `exit-code: '1'` on fixable CRITICAL          |
| osv vulnCount       | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **bloklayıcı**                   | ratchets `metrics.vulnCount` (direction:down) |
| OpenSSF Scorecard   | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | məsləhət xarakterli              | SARIF → Security + badge                      |

Şəkil CVE ratçeti `docker-publish.yml` faylında **iki addımdan** istifadə edir: SARIF addımı (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL səviyyələrini Təhlükəsizlik tabında bloklamadan görünən saxlayır; _KRİTİK qapı_ addımı (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) **mövcud düzəlişi olan** KRİTİK CVE-də buraxılışı uğursuz edir. `ignore-unfixed` yuxarı axın yaması olmayan əsas şəkil CVE-si üçün buraxılışın bloklanmasının qarşısını alır.

## ⚠️ CVE dəyişkənliyi (bloklayıcı osv/Trivy keçidləri)

osv və Trivy asılılıqları **davamlı olaraq genişlənən** CVE verilənlər bazaları ilə müqayisə edir. **Heç bir asılılığa toxunmayan** PR mövcud asılılıqda yeni CVE açıqlandığı üçün qəfildən uğursuz ola bilər (osv: ölçülən `vulnCount` > ilkin göstərici; Trivy: obrazda aradan qaldırıla bilən yeni CRITICAL boşluq). **Bu, məhsul reqressiyası deyil, bloklayıcı CVE keçidinin GÖZLƏNİLƏN əməliyyat davranışıdır.**

Yeni açıqlanmış CVE səbəbindən osv və ya Trivy uğursuz olduqda həll yolu belədir:

1. **Təsirə məruz qalan asılılığın versiyasını artırın** (üstünlük verilən variant) — `package.json` faylındakı `overrides` vasitəsilə düzəliş edilmiş versiyaya yüksəldin (tranzitiv asılılıqlar üçün) və ya obrazı düzəliş edilmiş baza əsasında yenidən yaradın.
2. **Əgər təmir mümkün deyilsə:** ölçülmüş tapıntını saxlamaq və təsirə məruz qalan asılılığı və ya təsviri izləmək. Uğursuz namizədin keçidini təmin etmək üçün zəifliyin baza səviyyəsini yüksəltməyin. Trivy's `ignore-unfixed: true` artıq yuxarı yama olmadan görüntü zəifliklərini istisna edir. İstənilən istisna nəzərdən keçirilmiş zəiflik ID, dəqiq paket yolu, istifadə müddəti və siyasətdə izləmə problemi tələb edir; uğursuz taramanın avtomatik nəticəsi deyil.

Tələb olunan OSV icraları (`check:vuln-ratchet -- --ratchet`) skaner, hesabat və ya ilkin göstərici doğrulana bilmədikdə `INCOMPLETE` statusu və 2 çıxış kodu ilə qapalı şəkildə uğursuz olur. Ölçülmüş reqressiya 1 çıxış kodu ilə nəticələnir. Məsləhət xarakterli icra yenə də 0 çıxış kodu ilə `SKIP` bildirə bilər, lakin bu, asılılıqların skandan uğurla keçdiyini təsdiqləmir. Bloklayıcı Trivy addımı da uğurlu ölçmə tələb edir: əlçatan olmayan alətlər, uğursuz tapşırıqlar və çatışmayan obraz sübutları obrazın təmiz olduğunu təsdiqləyə bilməz.

## Şəkil skan siyasəti

Cari `.trivyignore.yaml` zəiflik istisnalarını ehtiva etmir. `npm run check:trivy-ignore-policy` yerli skan profillərində, CI və Keyfiyyətdə strukturlaşdırılmış siyasəti təsdiqləyir. Naməlum IDs, daha geniş yollar, dublikat girişlər və vaxtı keçmiş istisnalar rədd edilir; köhnə `.trivyignore` köçürülmüş skanlara giriş deyil.

Docker `github.workflow_sha` -dən siyasət alətlərini və quruluşla eyni mənbə seçicisi ilə şəkil mənbəyi siyasətini yoxlayır. Siyasət seçicisi uyğun olmayan əhatə dairələrini rədd edir və hər iki Trivy skanı üçün bir fayl hazırlayır. Strukturlaşdırılmış siyasəti olmayan tarixi mənbə heç bir istisna qəbul etmir. Hər iki skan Trivy `v0.70.0` ni bağlayır. Siyasət doğrulaması konfiqurasiyanın ardıcıllığını sübut edir; şəkil hələ də uğurlu skan tələb edir.

## Təqaüdə çıxmış asılılıq riski

Saxlanmış promptfoo inkişaf alətini təkmilləşdirdikdən sonra kök kilid faylı artıq `extract-zip` və ya ondan asılılıq kənarını ehtiva etmir. Bu, #14482 də izlənilən əvvəllər qəbul edilmiş `promptfoo` → `@openai/codex-security` → `extract-zip` zəncirini ləğv edir. `tests/unit/extract-zip-14482-exposure.test.ts` də reqressiya yoxlamaları onun yenidən tətbiqini rədd edir və istehsal kodundan idxal qadağanını saxlayır.

Cari asılılıq təmiri həmçinin Azure şəxsiyyətinin MSAL müştərisi və get-uri-nin FTP müştərisi ilə uyğunluğu ləğv edir. Azure tokeninin əldə edilməsi və FTP axtarışı idarə olunan nəqliyyatlarla sınaqdan keçirilir; hər iki OpenCode paketi öz qurma və sınaq paketlərini idarə edir. Reyestr məsləhət sayları müəyyən bir zamanda ölçmələrdir və kilid faylı bağlandıqdan sonra dəyişə bilər.
