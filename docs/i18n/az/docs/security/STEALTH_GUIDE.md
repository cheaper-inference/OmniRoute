## Hüquqi və Etik Bildiriş

Gizlilik funksiyaları OmniRoute-un istifadəçiyə məxsus rəsmi hesablar (Claude Code CLI, Codex, Antigravity, Cursor və s.) ilə OmniRoute-un vahid API-si arasında uyğunluq qatı kimi fəaliyyət göstərə bilməsi üçün mövcuddur. Onlar fırıldaqçılığın aşkarlanmasından yayınmaq, giriş məlumatlarını paylaşmaq və ya provayderin Xidmət Şərtlərini pozmaq üçün **nəzərdə tutulmayıb**. Dəstəkləyicilər operatorlardan hesabları yaradarkən qəbul etdikləri yuxarı axın xidmətlərinin Xidmət Şərtlərinə riayət etmələrini gözləyirlər.

## TLS Barmaq İzi Qatı

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Davamlı `wreq-js` sessiyaları hər hesab əhatə dairəsi və müəyyən edilmiş proksi üçün tənbəl şəkildə yaradılır. Proses miqyaslı `TlsClient`, Cloudflare arxasındakı yuxarı axın xidmətləri üçün **macOS-da Chrome 124** kimi görünən ən çox 128 sessiyanı hovuzda saxlayır. Yerli icra mühiti əlçatan olmadıqda `TlsClient.fetch()` təhlükəsiz şəkildə uğursuz olur; çağıran tərəf bu örtükdən kənarda ehtiyat variantı açıq şəkildə seçə bilər.

- Sessiya profili: `browser: "chrome_124", os: "macos"`
- Proksinin müəyyən edilməsi (prioritet): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (həmçinin kiçik hərfli variantlar)
- Taymaut: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS` parametrindən miras alınır, standart olaraq 600000)
- `wreq-js` Response fetch ilə uyğundur (`headers`, `text()`, `json()`, `clone()`, `body`).
- İlk bayt nəzarətçisi (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`
  yuxarı axın başlıqları daxil olan kimi tamamlanır, buna görə yalnız `TLS_CLIENT_TIMEOUT_MS` ilk baytı heç vaxt təqdim etməyən gövdəni məhdudlaşdıra bilməz. `guardTlsFirstByte()` gövdənin ilk `read()` əməliyyatı ilə `TLS_FIRST_BYTE_WATCHDOG_MS` müddətini (standart `10000`, `0` onu deaktiv edir) yarışdırır; sağlam gövdəyə təsir edilmir, ilişib qalmış gövdə isə wreq oxuyucusunu ləğv edir və `proxyFetch` funksiyasının mövcud TLS ehtiyat məntiqinin birbaşa/proksi dispetçerinə keçməsinə imkan verir (təkrar icrası təhlükəsiz olmayan sorğu, məsələn, gövdəli POST sorğusu, səssizcə yenidən cəhd edilmək əvəzinə yenə də xəta yaradır).

### Veb-kuki provayderi nəqli — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` aşağıdakı beş ixtisaslaşdırılmış veb-kuki nəqli üçün ortaq adapterdir. Hər bir yüngül provayder örtüyü brauzer/ƏS profilini seçir. Adapter `open-sse/utils/tlsClient.ts` faylındakı, profil + ƏS + müəyyən edilmiş proksiyə görə açarlandırılan vahid wreq icra mühiti yükləyicisindən və nəqliyyat hovuzundan istifadə edir, hər sorğu isə `cookieMode: "ephemeral"` parametrindən istifadə edir. Buna görə hesablar və sorğular nəqliyyat səviyyəli bağlantıları paylaşır, lakin heç vaxt wreq sessiyasını və ya kuki anbarını paylaşmır.

| Provayder  | Profil        | Emulyasiya edilən ƏS | Axın EOF siyasəti                          |
| ---------- | ------------- | -------------------- | ------------------------------------------ |
| Claude     | `chrome_146`  | Linux                | `[DONE]` daxil edilir                      |
| Perplexity | `firefox_151` | macOS                | `event: end_of_stream` daxil edilir        |
| Grok       | `chrome_146`  | Linux                | `[DONE]` xaric edilir                      |
| Notion     | `chrome_146`  | Windows              | `[DONE]` daxil edilir                      |
| LMArena    | `chrome_146`  | Windows              | sentinel yoxdur; yerli EOF zamanı bağlanır |

- Axın emalı yerli cavabın `ReadableStream` obyektini birbaşa istehlak edir; müvəqqəti fayl və ya köməkçi proses yaradılmır.
- Axın təqdim edilməzdən əvvəl ilkin 256 bayta qədər məlumat yoxlanılır. SSE provayderləri SSE olmayan xətaları buferləşdirir; Grok/LMArena Cloudflare yoxlamalarını `403`, HTML aralıq səhifələrini isə `502` ilə uyğunlaşdırır.
- Yerli sorğu taymautu mütləq JS sərt son müddəti ilə əhatələnməyə davam edir. İlişmə yalnız təsirlənmiş profil/ƏS/proksi nəqliyyatını etibarsız edir və bağlayır; növbəti sorğudan əvvəl həmin nəqliyyat yenidən yaradılır.
- Proksinin müəyyən edilməsi prioriteti hər çağırış üzrə `proxyUrl` → sorğu əhatəli hesab/idarəetmə paneli konteksti → `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (kiçik hərfli variantlar daxil olmaqla) şəklindədir. Müəyyənetmə xətaları birbaşa bağlantının sızmasına yol vermək əvəzinə təhlükəsiz şəkildə uğursuz olur. LMArena qəsdən `arena.ai` ünvanına əsasən müəyyənetmə aparır.
- `byteResponse` UTF-8 korlanması olmadan məzmun tipi göstərilmiş `data:` URL qaytarır.
- Xətalar bütün 128 məhdud profil/ƏS/proksi yuvası aktiv və ya bağlanmaqda olduqda `TlsClientUnavailableError` (paket/əlavə əlçatan deyil), `TlsClientHangError` (son müddət keçilib) və `WreqTransportCapacityError` (ortaq sessiya tutumu xəta kodu) olur.

Yuxarıdakı ümumi `TlsClient` sessiyası brauzer tərəfindən dəstəklənən davamlı kuki vəziyyəti üçün ixtisaslaşdırılmış olaraq qalır. Hər iki yol bir keşlənmiş wreq modul yükləyicisindən və prosesin həyat dövrü qarmağından təkrar istifadə edir; kukilərinin istifadə müddətləri qəsdən fərqli olduğuna görə hovuzları ayrı qalır.

Profillər sabitlənmiş paket tərəfindən dəstəklənir, lakin real WAF qəbulu yerli müqavilə testlərindən asılı olmayaraq dəyişə bilər. Yuxarı axın brauzeri ilə uyğunluq iddia etməzdən əvvəl barmaq izi dəyişikliklərini açıq şəkildə icazə verilmiş canlı hesabla yoxlayın.

## Claude Code Gizlilik Paketi

`cliCompatMode` aktiv olduqda, OmniRoute gedən Claude sorğularını `claude-cli` trafiki ilə fərqləndirilməsi mümkün olmayacaq şəkildə yenidən formalaşdırır. Üç modul birlikdə işləyir:

### `claudeCodeFingerprint.ts`

Faktura başlığına yerləşdirilən 3 simvolluq `cc_version` rəqəmsal izini hesablayır:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (sərt şəkildə kodlaşdırılıb; rəsmi müştəri ilə uyğun gəlir)
- Girişlər: ilk istifadəçi mesajının mətnində 4, 7 və 20 indekslərindəki simvollar + versiya sətri
- Çıxış: 3 simvolluq onaltılıq prefiks

### `claudeCodeCCH.ts` (Müştəri Məzmun Heşi)

Rəsmi Claude Code CLI-nin Bun/Zig vasitəsilə hesabladığı server tərəfli bütövlük yoxlaması. OmniRoute bunu `xxhash-wasm` ilə yenidən həyata keçirir:

1. Gövdəni `cch=00000;` yer tutucusu ilə seriallaşdırın
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. Sıfırlarla tamamlanmış 5 simvolluq kiçik hərfli onaltılıq dəyər
4. `cch=00000;` hissəsini hesablanmış tokenlə əvəz edin

Sabitlər:

- İlkin dəyər: `0x6e52736ac806831e`
- Nümunə: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

Yuxarı axın filtrlərinin onları `grep` ilə tapa bilməməsi üçün "həssas" müştəri adlarının ilk simvolundan sonra Unicode **sıfır enli birləşdirici** (`U+200D`) əlavə edir. Standart söz siyahısı:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Bunlara tətbiq olunur: `system` blokları, bütün `messages[].content` məzmunları və `tools[].description` / `tools[].function.description`. Operator tərəfindən `setSensitiveWords()` vasitəsilə dəyişdirilə bilər.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` provayderləri

Yalnız "real Claude Code" trafikini qəbul edən üçüncü tərəf Anthropic releləri üçün:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- Standart olaraq `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- Hər bağlantı üzrə "Redaktə edilmiş düşünmə beta-versiyasını aktivləşdir" keçidi, CC Compatible yuxarı axını xüsusi olaraq redaktə edilmiş düşünmə axınlarını tələb etdikdə `redact-thinking-2026-02-12` əlavə edir
- Hər bağlantı üzrə "Xülasələşdirilmiş düşünmə ekranını aktivləşdir" keçidi `providerSpecificData.requestDefaults.summarizeThinking` dəyərini saxlayır və ekran rejimi əvvəlcədən təyin edilməmiş CC Compatible düşünmə sorğularına `display: "summarized"` əlavə edir
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x ailəsi)
- Standart yol: `/v1/messages?beta=true`

Eyni paketdəki əlaqəli modullar:

- `claudeCodeConstraints.ts` — temperatur + keşə nəzarət qaydaları
- `claudeCodeToolRemapper.ts` — alət adlarının yenidən xəritələnməsi
- `claudeCodeExtraRemap.ts` — əlavə faydalı yükün normallaşdırılması

## Antigravity Gizli

Antigravity sorğuları zəng edənin mətnini bayt-bayt saxlayır. OmniRoute IDE müştərisini təqlid etmək üçün göstərişlərə və ya rename/inject alətlərinə sıfır enli simvollar daxil etmir.

### `antigravityHeaderScrub.ts`

Yönləndirmədən əvvəl Paslanmayan SDK markerlərini (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) zolaqlar.

### ⚠️ Riski: `ANTIGRAVITY_CREDITS=always` (hesab qadağası qaynar nöqtə)

`ANTIGRAVITY_CREDITS=always` ( `open-sse/executors/antigravity.ts` tərəfindən istehlak olunur) marşrutları **hər** Google-nin pulsuz səviyyəli kvota qapısı işlərinə icazə vermək əvəzinə Antigravity AI Kredit Ödənişləri (ödənilmiş Google kreditləri) vasitəsilə tələb edin. Bu xüsusiyyət kimi sənədləşdirilmişdir, lakin belədir **gördüyümüz yeganə ən ümumi ToS pozuntusu hesabatı** `=always` ilə bir neçə saat işlədikdən sonra Google — hesabı `403 / "service disabled for ToS violation" / insufficient_quota` ilə qadağan edildi.

Upstream icrası aktivdir **Google tərəfi** , OmniRoute heç bir şeyin qarşısını ala bilməz. Env var adı və mövcud sənədlər onu çevirmək üçün təhlükəsiz düymə kimi səsləyir; bu deyil.

**Niyə bu, sui-istifadənin aşkarlanmasını yalnız pulsuz səviyyəli istifadədən daha aqressiv şəkildə çəkir:**

- Tək bir Google hesabına davamlı avtomatlaşdırılmış xərcləmə pulsuz səviyyəli hit-kvota-və-stoplardan fərqli olaraq qeyd olunur.
- Kredit həddən artıq faiz dərəcələrinin tavanı yoxdur, ona görə də səhv konfiqurasiya edilmiş müştəri dəqiqələr ərzində bir neçə yüz USD dan keçə bilər və API açarının yenidən satışı və ya bot trafiki kimi görünə bilər.
- Eyni xarici IP dən paralel olaraq həddindən artıq kreditləri vuran çoxsaylı OmniRoute istifadəçiləri siqnalı birləşdirir.

**Tövsiyə olunan duruş:**

1. Operator ödənişli kredit və hesabın icrası riskini açıq şəkildə qəbul etmədikdə, standart `ANTIGRAVITY_CREDITS=off` saxlayın. `retry` əvvəlcə normal sorğunu göndərir və uyğun kvota 429-dan sonra ən çox bir dəfə kreditlər daxil edir; `always` ilk sorğuda kreditlər daxil edir.
2. **Auto-Combo vasitəsilə yükü provayderlər arasında paylayın** (`model: "auto"` və ya `kr/glm/etc` -combo) tək bir Antigravity hesabını doyurmaq əvəzinə.
3. **Hər bağlantı üçün RPM limitlərini təyin edin** Antigravity provayderinin redaktə səhifəsində (Dashboard → Providers → Antigravity → əlaqə → tarif həddi). 30-60 RPM davamlı istifadə üçün müdafiə edilə bilən yuxarı hədddir.
4. **Stabil, operator tərəfindən idarə olunan yuxarı şəbəkədən istifadə edin** və əlaqəsi olmayan istifadəçilər və ya iş yükləri arasında bir hesabı paylaşmaqdan çəkinin.
5. **Qadağan olunarsa** : `support.google.com` → vasitəsilə müraciət " Workspace/Account girişini bərpa edin" `quota_exceeded` / `service disabled` cavab orqanı Google göndərildi. Bərpaya zəmanət verilmir.

Ətraf mühit arayışı hər bir kredit rejiminin hesabını və xərcləmə nəticələrini sənədləşdirir.

#### Yalnız `=always` deyil: ümumiyyətlə Antigravity OAuth marşrutu

Dayandırılmalar kreditin həddindən artıq olması ilə məhdudlaşmır. 2026-cı ilin noyabr ayında (#19223, #19266) hesabatlar `antigravity` və `agy` (Antigravity CLI) provayderləri vasitəsilə marşrutlaşdırarkən dayandırılmış bir neçə Google hesabını təsvir edir:

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

Hər iki provayder Antigravity məhsulu OAuth seansı ilə autentifikasiya edir, bu halda idarə panelinin risk bildirişi ("Bu provayder proxy/router istifadəsi üçün icazə verilməyən rəsmi məhsulunuz session/OAuth istifadə edir") əlaqə əlavə edilməzdən əvvəl xəbərdarlıq edir. Yuxarıdakı tövsiyələrin heç biri bu istifadəyə icazə vermir; onlar yalnız bir hesabın nə qədər trafik daşıdığını azaldır.

**Gemini modelləri üçün səlahiyyətli API interfeysləri.** Google, OmniRoute adi API açarı təminatçıları kimi dəstəklədiyi APIs vasitəsilə Gemini -yə proqramlı giriş təklif edir:

| Provayder id | İdarə paneli adı          | Etibarnamə                                                                     |
| ------------ | ------------------------- | ------------------------------------------------------------------------------ |
| `gemini`     | Gemini (Google AI Studio) | Google AI Studio-dan Gemini API açarı (pulsuz səviyyə mövcuddur)               |
| `vertex`     | Vertex AI                 | Xidmət Hesabı JSON, OAuth giriş nişanı və ya Vertex Express API açarı (Gemini) |

Bu provayderlər Antigravity məhsul sessiyasından fərqli olaraq API girişi üçün etimadnamələrdən Google məsələlərindən istifadə edirlər. Onlar hər istifadəni tələblərə uyğunlaşdırmır və ya icra riskini aradan qaldırmır: hər biri operatorun onların yerləşdirilməsini yoxlamalı olduğu öz şərtləri ilə idarə olunur. Məsələn, [Gemini API Əlavə Xidmət Şərtləri](https://ai.google.dev/gemini-api/terms) API müştəriləri Avropa İqtisadi Bölgəsində, İsveçrədə və ya Birləşmiş Krallıqda istifadəçilər üçün əlçatan olduqda və Ödənişsiz Xidmətlərə göndərilən məzmun Google məhsullarını təkmilləşdirmək üçün istifadə olunarsa, yalnız Ödənişli Xidmətlərə icazə verir. Vertex AI əvəzinə Google Cloud şərtlərinə aiddir ( [Xidmətə Xüsusi Şərtlər](https://cloud.google.com/terms/service-terms) ). Qiymətlər və kvotalar Antigravity abunəliyinə deyil, həmin API şərtlərinə uyğundur.

Yuxarıda təsvir edilən Antigravity dayandırılmalarından qaçmaq istəyən operatorlar onların istifadəsinin provayderin şərtlərinə uyğun olduğunu yoxladıqdan sonra Gemini trafikini `antigravity` / `agy` əvəzinə bu provayderlərdən biri vasitəsilə yönləndirməlidirlər.

Toxunma nöqtələri:

- `open-sse/executors/antigravity.ts` — `process.env.ANTIGRAVITY_CREDITS` oxuyur
- `src/lib/oauth/providers/antigravity.ts` — etimadnaməsi santexnika
- Orijinal hadisə hesabatı: [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183) müzakirəsi

## CLI Barmaq İzi Reyestri — `open-sse/config/cliFingerprints.ts`

Rəsmi CLI-lərin mitmproxy izləmələrindən götürülmüş **dəqiq** başlıq sıralamasını və JSON gövdəsindəki sahələrin sıralamasını sabitləyən, hər provayder üçün ayrıca cədvəl. Hazırda qeydiyyatdan keçənlər: `codex`, `claude`, həmçinin `antigravity` və `github` üçün `providerHeaderProfiles.ts` daxilində icra zamanı yaradılan profillər.

```ts
interface CliFingerprint {
  headerOrder: string[]; // böyük-kiçik hərfə həssasdır
  bodyFieldOrder: string[]; // üst səviyyəli JSON açarları
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Env vasitəsilə hər provayder üçün ayrıca aktivləşdirin və ya deaktivləşdirin (aşağıya baxın). Deaktiv olduqda başlıqlar/gövdə açarları Node/JSON tərəfindən verilən istənilən sırada görünür — barmaq izinin müəyyənləşdirilməsini asanlaşdırır.

## MITM Proksisi (Antigravity, Linux/macOS/Windows)

Binar faylları `OPENAI_BASE_URL` vasitəsilə yönləndirilə bilməyən CLI-lər üçün OmniRoute lokal TLS sonlandırıcı proksi işlədir. Son nöqtələr `src/app/api/cli-tools/antigravity-mitm/` altında yerləşir.

| Metod  | Son nöqtə                               | Məqsəd                                                    |
| ------ | --------------------------------------- | --------------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | Status — işləmə vəziyyəti, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM-i başladın (`apiKey` + `sudoPassword` tələb olunur)  |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM-i dayandırın                                         |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | Model aliaslarını siyahıya alın                           |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | Alət üçün model aliaslarını yadda saxlayın                |

Hədəf tutulan host: **`daily-cloudcode-pa.googleapis.com`** (Antigravity-nin yuxarı axın xidməti).

### Başlatma ardıcıllığı (`src/mitm/manager.ts::startMitm`)

1. `selfsigned` vasitəsilə özü imzalanmış sertifikat yaradın (RSA-2048, SHA-256, 1 il) — `cert/generate.ts`
2. Sertifikatı sistemin etibarlı sertifikatlar anbarına quraşdırın — `cert/install.ts`
3. Hosts qeydi əlavə edin: `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (standart olaraq `443`) ilə `src/mitm/server.cjs` prosesini başladın
5. PID-i `<DATA_DIR>/mitm/.mitm.pid` ünvanında saxlayın

### Linux-da etibarlı sertifikat anbarının dinamik aşkarlanması — `cert/install.ts`

`getLinuxCertConfig()` prioritet siyahısını nəzərdən keçirir və mövcud olan ilk qovluğu seçir:

| Distributiv ailəsi       | Qovluq                                      | Yeniləmə əmri            |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Sertifikat faylının adı: `omniroute-mitm.crt`. Barmaq izi uyğunluğu `getCertFingerprint()` vasitəsilə yoxlanılır (DER-in SHA-1 heşi).

Əlavə olaraq, `certutil` mövcud olduqda `updateNssDatabases()` sertifikatı istifadəçiyə aid NSS verilənlər bazalarına quraşdırır: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, bütün Firefox profilləri (snap daxil olmaqla); ləqəb isə **`OmniRoute MITM Root CA`** olur.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** yüksəldilmiş səlahiyyətli PowerShell → `certutil -addstore Root`

### Autentifikasiya

Bütün MITM son nöqtələri idarəetmə autentifikasiyası (`requireCliToolsAuth`) tələb edir. Sudo parolu modul əhatə dairəsində keşlənir (heç vaxt `globalThis` daxilində deyil) və `stopMitm()` çağırıldıqda təmizlənir.

## Provayder Barmaq İzini Dəyişdikdə Yeniləmə

1. Rəsmi CLI trafikini `mitmproxy` ilə tutun (TLS-in ələ keçirilməsi + dump)
2. JA3/JA4 məlumatlarını və başlıqların hərfi sırasını çıxarın
3. Müvafiq `CLI_FINGERPRINTS[...]` qeydini yeniləyin
4. `.env.example` faylındakı uyğun `*_USER_AGENT` standart dəyərinin versiyasını artırın
5. TLS əl sıxışmasının özü dəyişibsə, müvafiq provayder örtüyünü və ya wreq-js `browser:` seçimini yeniləyin
6. Provayderə xas TLS testlərini və canlı provayderə qarşı əl ilə canary testini işə salın
7. Düzəliş buraxılışı kimi yayımlayın; `CHANGELOG.md` faylında sənədləşdirin
