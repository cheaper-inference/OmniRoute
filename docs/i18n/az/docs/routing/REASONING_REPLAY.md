> **Həqiqətin mənbəyi:** `src/lib/db/reasoningCache.ts`, `open-sse/services/reasoningCache.ts`** Son yeniləmə:** 28-06-2026 — v3.8.40

OmniRoute düşünmə rejimi modelləri tərəfindən hazırlanmış köməkçi `reasoning_content` çəkir və yuxarı axın provayderi tələb etdikdə, çoxdövrəli sorğularda onu şəffaf şəkildə təkrarlayır. Bu, müştərinin söhbət tarixçəsində əvvəlki növbənin əsaslandırmasını əldən verdiyi zaman ciddi provayderlərin qaldırdığı HTTP 400 səhvlərini aradan qaldırır.

## Bu Niyə Mövcuddur

Bir neçə düşünmə rejimi təminatçıları təqib növbəsini rədd edirlər** əvvəlki köməkçi mesajına orijinal `reasoning_content` daxildir** . Upstream aşağıdakı kimi mesajlarla 400 qaytarır:

```
Param Incorrect: The reasoning_content in the thinking mode must be passed back to the API.
```

Lakin tipik müştərilər (Cursor, Cline, Roo Code, OpenAI SDK) `reasoning_content` təkrar oynatdıqları tarixdən silirlər. OmniRoute onu server tərəfindəki keşdən bərpa edir ki, yuxarı axının gördüyü sorğu ardıcıl olsun. #1628-ci buraxılış hibrid memory/SQLite əzmkarlığını təqdim etdi, beləliklə keş prosesin yenidən başlaması zamanı sağ qalsın.

## Memarlıq

```
Turn N (assistant generates):
  → response contains reasoning_content + tool_calls
  → if requiresReasoningReplay(provider, model): cacheReasoningFromAssistantMessage()
      writes (memory + DB), one entry per tool_call.id within the request scope
  → forward response to client (which may or may not retain reasoning)

Turn N+1 (client sends follow-up):
  → translator detects: requiresReasoningReplay(provider, model) === true
  → for each assistant message with tool_calls and no reasoning_content:
      lookupReasoning(buildToolCallCacheKey(scope, toolCalls[0].id)) → memory → DB
      hit  → msg.reasoning_content = cached; recordReplay()
      miss → msg.reasoning_content = "" (legacy fallback for older DeepSeek)
  → upstream sees consistent history → no 400
```

Çəkmə `open-sse/handlers/chatCore.ts` -da baş verir (iki sayt, iki `cacheReasoningFromAssistantMessage` zəng saytında). Təkrarlama `open-sse/translator/index.ts` də sxem məcburiyyətindən sonra, lakin göndərilmədən əvvəl baş verir.

Alət-zəng qeydləri `buildToolCallCacheKey()` altında saxlanılır, sorğunun əhatə dairəsi və alət çağırışı id-si, ona görə də başqa API açarı və ya sessiyası tərəfindən istifadə edilən eyni id girişi seçmir. Əhatə dairəsi `buildReasoningCacheScope()` dən gəlir: API açar identifikatoru, üstəgəl sorğuda bir seans açarı. Buna görə də `tool_call_id` sütunu və tablosunda həmin qeydlər üçün bu həzm göstərilir.

Sadə (alətdən istifadə etməyən) köməkçi növbələri fərqli şəkildə düymələnir: `buildAssistantMessageCacheKey()` sessiyanın əhatə dairəsini üstəgəl bu növbəyə qədər normallaşdırılmış OpenAI formatlı transkripti həzm edir, çünki DeepSeek mövcud olduqdan sonra `tools` əvvəlki _her_ növbənin əsaslandırılmasını tələb edir. Responses-API hədəfləri üçün (məsələn, `opencode-go/deepseek-v4-flash`, `/responses`-yə yönləndirilmiş) yuxarı orqan `messages` deyil, `input` daşıyır, ona görə də `translateRequest()` (`open-sse/translator/index.ts`) geri çağırış seçimi vasitəsilə həzm etdiyi pivot transkriptini bildirir və tutma saytları həmin transkripti həzm edir. Cavabları təkrar oxutma keçidi hər mənbə formatı üçün OpenAI pivotu üzərində işləyir, ona görə də Anthropic Mesaj müştəriləri (Claude → OpenAI → Cavabları) da təkrar oxunur.

## Saxlama — Hibrid Yaddaş + SQLite

İsti yol qəzanın bərpası və tablosunun görünməsi üçün SQLite cədvəli ilə dəstəklənən yaddaşdaxili `Map` (LRU-by-creation) istifadə edir.

| Qat    | İcra                                           | Məqsəd                                                    |
| ------ | ---------------------------------------------- | --------------------------------------------------------- |
| Yaddaş | `Map` in `open-sse/services/reasoningCache.ts` | Sürətli axtarışlar, ən qədimi 200-də çıxarılır            |
| DB     | `reasoning_cache` cədvəli (`src/lib/db/`)      | Yenidən başlatmalarda davam edir, statistikanı idarə edir |

Yazılar hər ikisinə gedir. Oxuyanlar əvvəlcə yaddaşla məsləhətləşir, sonra DB -ya qayıdır (DB hitləri yaddaşa qaytarılır). DB uğursuzluqları ölümcül deyil — yaddaşdaxili keş isti yola xidmət etməyə davam edir.

**Defoltlar:**

- TTL: `2h` (`TTL_MS = 2 * 60 * 60 * 1000`)
- Maksimum yaddaş qeydləri: `200` (`MAX_MEMORY_ENTRIES`)
- Evdən çıxarma: ən qədim `createdAt` əvvəlcə

## Verilənlər bazası sxemi

Miqrasiya: `src/lib/db/migrations/033_create_reasoning_cache.sql`

```sql
CREATE TABLE IF NOT EXISTS reasoning_cache (
  tool_call_id   TEXT PRIMARY KEY,
  provider       TEXT NOT NULL,
  model          TEXT NOT NULL,
  reasoning      TEXT NOT NULL,
  char_count     INTEGER NOT NULL DEFAULT 0,
  created_at     TEXT NOT NULL DEFAULT (datetime('now')),
  expires_at     INTEGER NOT NULL
);
```

İndekslər: `expires_at`, `provider`, `model`, `created_at`. `expires_at` Unix epoch saniyələri kimi saxlanılır; SELECT təbəqəsi `EXPIRES_AT_EPOCH_SQL` vasitəsilə köhnə mətn dəyərlərini normallaşdırır.

`requiresReasoningReplay(provider, model)` `true` qaytardıqda təkrar oxutma aktiv edilir. Funksiya `open-sse/services/reasoningCache.ts`-də iki siyahı yoxlayır.

**Provayder IDs (dəqiq uyğunluq, böyük hərflərə həssas deyil):**

- `deepinfra`
- `sambanova`
- `fireworks`
- `together`
- `kimi-coding`

- `xiaomi-mimo`

- `/deepseek-reasoner/i`
- `/deepseek-chat/i`
- `/deepseek[-/]?v4[-.]flash/i` və `/deepseek[-/]?v4[-.]pro/i` (V4 Flash / Pro, isteğe bağlı `-free` şəkilçisi)

Yeni ciddi provider/model əlavə etmək bu siyahılardan birinə əlavə etmək və təkrar inyeksiyanı təsdiq edən vahid testi yazmaq deməkdir. PR təsviri dəyişikliyə səbəb olan dəqiq yuxarı 400 sətrini göstərməlidir.

## Əməliyyat qeydləri

- **Təmizləmə:** `cleanupReasoningCache()` vaxtı keçmiş yaddaş qeydlərini təmizləyir və `DELETE FROM reasoning_cache WHERE expires_at <= unixepoch('now')` işə salır. Səhiyyə işçiləri bunu vaxtaşırı çağırırlar.
- **Qəza bərpası:** Yenidən başladıqdan sonra yaddaş boşdur, lakin DB hələ də vaxtı bitməmiş qeydləri saxlayır. Verilmiş `tool_call_id` üçün ilk axtarış DB hitdir; sonrakı axtarışlar yaddaş hitləridir.
- **Heç bir əsaslandırma, keş yoxdur:** `cacheReasoningFromAssistantMessage` köməkçi mesajda `reasoning_content` / `reasoning` sahəsi olmadıqda `0` qaytarır, ona görə də qeyri-düşüncə cavabları heç bir xərc tələb etmir.
- **Write is gated too:** both call sites in `chatCore.ts` (non-streaming and streaming) only call `cacheReasoningFromAssistantMessage()` when `requiresReasoningReplay(provider, model)` is `true` — the same predicate the read side checks. Installs that never touch a replay provider stop paying for the write, the index update, and the try/catch on every reasoning-bearing response.
- **Qeyri-ciddi provayderlər:** `requiresReasoningReplay` `false` və hədəf format OpenAI olduqda, tərcüməçi** zolaqlar** gedən mesajlardan hər hansı `reasoning_content` sahəsi — OpenAI Chat Completions onu qəbul etmir.

## Muse Opaque-Reasoning Sahibliyi

Muse (`muse-code`) zəng edənə bağlı qeyri-şəffaf əsaslandırmanı (`encrypted_content`) qaytarır. Onu fərqli hesab və ya xatırladılmış etimadnamə ilə təkrar oxutma yuxarıda uğursuz olur, buna görə də yerli OAuth sorğuları hər sorğu fırlanması əvəzinə sessiya səviyyəli sahiblikdən istifadə edir (`src/sse/services/museSessionOwnership.ts`, `src/sse/handlers/chat.ts` ilə tətbiq edilir). Açıq şəkildə seçilmiş API açarı əlaqələri və yalnız API açarı konfiqurasiyaları bu sahiblik rejimi olmadan mövcud marşrutlaşdırmalarını saxlayır.

- Hər növbədə sabit seans ID təmin edin: `x-omniroute-session-id`, `x-omniroute-session`, `x-session-id`, və ya `x-codex-session-id`; alternativ olaraq bədəndə `prompt_cache_key`, `session_id`, `conversation_id` və ya `metadata.session_id` istifadə edin (bu üstünlük sırasında). İki və ya daha çox yerli OAuth hesabı aktiv olduqda çatışmayan və ya boş IDs 400 qaytarır; tək bir OAuth hesabı ilə fırlanma üçün heç bir şey yoxdur, buna görə də belə bir sorğu bağlanmamış marşrutlaşdırma saxlayır. Əhatə dairəsinə zəng edənin OmniRoute API açarı ID daxildir.
- API açarı qoşulma siyasəti ilə icazə verilən, ID bağlantısı ilə sifariş edilən aktiv yerli OAuth hesabları üzrə yeni müstəqil sessiyalar. Raund-robin, terminal statusu (`banned`, `expired`, `credits_exhausted`) olan və ya tələb olunan model üçün model kilidli olan əlaqənin soyudulma müddətində hesabları ötür; Muse upstream uğursuzluqları digər provayderlər kimi soyutma müddətini və pozucu vəziyyətini qeyd edir. Açıqca məcburi əlaqə yeni sessiya üçün dövriyyədən yan keçir, lakin mövcud sahibi ləğv edə bilməz.
- Sahib uğurlu cavab verənə qədər, sahibi əlçatan olmayan sessiya sağlam hesaba yenidən iddia edilir. İlk uğurlu cavabdan sonra sessiya 30 gün boş qalana qədər həmin sahibə bağlanmış qalır (`MUSE_SESSION_IDLE_TTL_MS`).
- Hər bir davam və alət-nəticə növbəsi sessiya sahibinə bağlanır: əlaqə, hesab identifikasiyası və etimadnamənin yenilənməsi cəhdləri daxil olmaqla, yuxarı axını cəhdlərindən əvvəl yenidən yoxlanılır. Cavablar çağırış IDs/item istinadları və Çat Tamamlamaları aləti-zəngi IDs həmin sessiya və nəsil üçün qeydə alınmış olmalıdır.
- `muse_session_ownership` ad məkanında (`src/lib/db/museSessionOwnership.ts`)SQLite `key_value` qeydləri sahibliyi və fırlanma kursorunu yenidən işə salmaqda davam edir. Hər bir iddia və təqdim edilmiş cavab sessiyanın fəaliyyət möhürünü təzələyir; `MUSE_SESSION_IDLE_TTL_MS` -dən daha uzun boş sessiya kəsilir (sahibi pin, təqdim edilmiş bayraq və qeydə alınmış opaque/reference heşləri), ən çoxu hər 10 dəqiqədə bir dəfə və məhdud qruplarla, ona görə də onun tarixinin sonrakı təkrarı naməlum sahib kimi bağlana bilmir. Qeydlər sirr və ya söhbət tarixçəsini deyil, əlaqə IDs və hesab şəxsiyyətinin heşlərini, etimadnamələri, qeyri-şəffaf məzmunu və davam istinadlarını ehtiva edir. Müştərilər tam tarixlərini və qeyri-şəffaf əsaslandırmalarını saxlamalı və göndərməlidirlər.
- Naməlum və ya xarici qeyri-şəffaf mülahizə, itkin sahib, əlçatmaz sahib hesabı və ya qeydə alınmış tarixçəsi olan nəsil dəyişikliyi açıq 4xx/503 — heç vaxt səssiz hesablar arası uğursuzluqla bağlanır və heç vaxt əsaslandırmadan imtina edir.
- Xatırlatılmış eyni hesab açarı yalnız sessiya təkrar oynatılan tarixçə qeydə alınmadıqda qəbul edilir; qeydə alınmış seanslar təzə başlayana qədər qapalı qalır.
- Boş yuxarı cavab cavabı (`upstream_empty_response` / `empty_response`, zəng edənə heç nə verilmir) eyni sahibdə ən çox iki dəfə, 0,5 s, sonra 1,5 s (`MUSE_EMPTY_RESPONSE_RETRY_DELAYS_MS`) sonra təkrar sınanır. Bütün cəhdlər boşdursa, orijinal 502 soyuducu və ya kəsici işarəsi olmadan qaytarılır, beləliklə, ləpələnmiş cavab heç vaxt sahibini kilidləmir.
- Bütün `muse-code` sorğuları axın yazıları da daxil olmaqla semantik keş oxunuşlarını və yazılarını yan keçir, buna görə də keşlənmiş qeyri-şəffaf çıxış başqa sessiya sahibini əldə edə bilməz.
