## İcmal

Kvota Paylaşma Mühərriki provayderin vaxta əsaslanan kvotasını (məsələn, Codex
üçün 5 saatlıq pəncərə, Kimi üçün 1500 sorğu/saat) eyni bağlantını paylaşan
çoxsaylı API açarları arasında ədalətli şəkildə bölüşdürür.

**Həll etdiyi problem:** OmniRoute çoxsaylı API açarlarının sorğularını eyni yuxarı
axın provayder hesabına proksiləyir. Paylaşma məntiqi olmadıqda, A açarından gələn
sorğu sıçrayışı provayderin saatlıq kvotasını tükədə bilər və pəncərə sıfırlanana
qədər B və C açarlarını bloklanmış vəziyyətdə qoya bilər. Mühərrik bunun qarşısını
aşağıdakı üsullarla alır:

1. Hər açarın hər ölçü üzrə sürüşən istehlakını (%, sorğular, tokenlər, $) izləyir.
2. İşi qoruyan ədalətli paylaşma alqoritmini tətbiq edir: qlobal hovuz doyma həddinə
   çatmadığı müddətdə açar boş qalan paylardan istifadə edə bilər.
3. Sorğu yuxarı axın icraçısına çatmazdan əvvəl nəticəni sürətli icra yolunda
   (`chatCore.ts`) tətbiq edir.

## Alqoritm: Fair-Share Work-Conserving

`src/lib/quota/fairShare.ts`-da həyata keçirilir.

### Rejimlər

| Vəziyyət                                   | Rejim         | Davranış                                                                   |
| ------------------------------------------ | ------------- | -------------------------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **Səxavətli** | Açar, ümumi istehlak miqdarını çıxmaqla qlobal limitə qədər borc ala bilər |
| `globalUsedPercent >= saturationThreshold` | **sərt**      | Fərdi ədalətli payı ciddi şəkildə tətbiq edin                              |

Defolt `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`).

Bu iki rejim standart borc rejimində hovuzu təsvir edir, `saturation`. `consent` rejimində olan hovuz doyma dərəcəsindən asılı olmayaraq həmişə ciddi qaydaları tətbiq edir. Baxın [Razılaşdırılmış kreditləşmə (hər bir hovuza qoşulma)](#consented-lending-per-pool-opt-in).

### Ölçüyə görə qərar

Hovuzdakı hər bir aktiv ölçü üçün mühərrik hesablayır:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = current rolling value for this key (from QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

`percent` ölçüləri üçün `consumed` əvəzinə atribusiya kitabından gəlir ( [faiz ölçüləri: hər açar üçün atribusiyaya](#percent-dimensions-per-key-attribution) baxın).

Sonra:

- **`policy = hard`** : `consumed > fairShareAllowed` və rejim ciddi → olarsa** blok** .
- **`policy = soft`** : `consumed > fairShareAllowed` və rejim ciddi → olarsa** cəzalandırmaq** (komboda prioritetləşdirin; heç vaxt sərt bloklama).
- **`policy = burst`** : ədalətli paydan asılı olmayaraq qlobal boşluq mövcud olarkən icazə verin.

### Mütləq qapaq

`capValue` + `capUnit` bölgüsü rejim və ya siyasətdən asılı olmayan sərt tavandır. `consumed >= capValue` həmişə olduğu hər hansı bir ölçü** bloklar** sorğu. `percent` qapağı üçün `consumed` yalnız açara aid edilən hissədir.

### Çoxölçülü yoxlama

Əgər sorğu bloklanır** hər hansı** hovuzun ölçüsü onu maneə törədir. Ölçülər müstəqildir — 5h% tükənmə həftəlik% ölçüyə təsir etmir.

### Borc alma

Səxavətli rejimdə, ayrılması az istehlak edilən açar digər açarların bölüşdürülməmiş paylarından artıqlığı istifadə edə bilər. Formula belədir:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

harada `consumedByOtherKeys = consumedTotal - consumedByThisKey`. Teto qlobal (bu ölçü üçün hovuz `limit` ) həmişə sərt tavandır.

### Razılaşdırılmış kreditləşmə (hər bir hovuza qoşulma)

Hər hovuzun bir borc rejimi var. `saturation` defoltdur və yuxarıdakı qaydaları saxlayır. `consent` rejimində `hard` açarı öz payını yalnız digər açarların borc verməyə razılaşdığı imkan daxilində keçir. Administrator hər hovuzun rejimini təyin edir. Hər bir açar sahibi [Kredit razılığı](#lending-consent) vasitəsilə öz razılığını təyin edir.

Razılıq 0-dan 100-ə qədər olan faizdir və epox millisaniyələrində isteğe bağlı son tarixdir. Açar, son tarix gələcəkdə olduğu halda, onun boş payının bu faizini borc verir.

Bir ölçü üçün `L` effektiv hədddir: plan limiti hovuzdakı hesabları dəfələrlə əhatə edir. Qapı tələb olunan açar üçün hesablayır:

```
share_k         = w_k / 100 × L
idle_k          = max(0, share_k − consumed_k)
lent            = Σ over the other keys of lend_k / 100 × idle_k
taken           = Σ over the other keys of max(0, consumed_k − share_k)
borrowAvailable = max(0, lent − taken)
```

`w_k` açarın çəkisidir və ya heç bir çəki 0-dan yuxarı olmadıqda hər açar üçün `100 / n` `lend_k` açarın aktiv faizidir və son tarix keçdikdən sonra 0-dır. Sorğu edən açarın öz razılığı heç vaxt nəzərə alınmır. İstehlak payına və `borrowAvailable` çatdıqda `hard` açarı rədd edilir.

Heç bir ayırma iddiası olmayan tutum (100 minus çəkilərin cəmi) borc verilə bilməz. Heç bir açar onu borc verməyə razı olmadı.

**Misal.** `L` 1000-dir.

| Açar | Çəki | Paylaşın | İstehlak olunur | Borc verir |
| ---- | ---- | -------- | --------------- | ---------- |
| A    | 50   | 500      | 530             | 0%         |
| B    | 30   | 300      | 100             | 50%        |
| C    | 0    | 0        | 60              | 0%         |

- B boş qalan 200-ün 50%-ni borc verir, bu da 100-dür. C artıq öz payından 60-ı yuxarı götürmüşdür. A 40 borc ala bilər.
- A 530-da verilir və istehlakı 540-a çatdıqda imtina edilir.
- C hər hansı bir şeyi istifadə etməzdən əvvəl, A payında və ya onun altında olmaqla, C 100 borc ala bilərdi.
- C hər hansı bir şeyi istifadə etməzdən əvvəl, A 530-da, C 70 borc ala bilərdi.

**Sıfır çəki.** Çəkisi 0 olan açarın payı 0-dır. O, yalnız istehlakı başqalarının verdiyindən aşağı olduqda xidmət göstərir. Heç kim borc vermədikdə, ilk tələbindən imtina edilir.

**Son tarixlər.** Heç bir fon tapşırığının razılıq müddəti bitmir. Hər bir sorğu son tarixi öz vaxtı ilə müqayisə edir və həmin vaxta bərabər olan son tarix keçib. Sonlu sayda olmayan və ya `Date` saxlaya biləcəyi ən böyük tarixdən keçmiş saxlanılan son tarix keçilmiş sayılır.

**`soft` və `burst`.** Kredit vermək onları məhdudlaşdırmır. Bir `soft` açarı payını keçdikdən sonra prioritetləşdirilir. Hovuzda otaq olduqda `burst` açarı keçir. Hovuz tavanı hövzənin ümumi miqdarı həddinə çatdıqdan sonra hələ də hər açardan imtina edir.

**Müraciət yolunda xərc.** Bir `saturation` hovuzu əvvəlkindən daha çox oxumur. `consent` hovuzunda hesablana bilən ölçü digər açarları yalnız öz payında və ya ondan yuxarı olan `hard` açarı üçün oxuyur, digər açar isə borc verir. Sonra paralel olaraq digər açar üçün bir oxunuş edir. Uğursuz oxunuş həmin açar üçün 0 istehlakı kimi sayılır. `percent` ölçüsü heç bir oxunma əlavə etmir, çünki atribusiya kitabı hər bir açarı saxlayır.

**Hovuzun redaktəsi.** Redaktə qalan düymələrin razılığını saxlayır. Bu, ayırma redaktələri, qrup miqyasında dəyişdirmələr və `ensure` zəngləri üçün aiddir. Silinmiş açar razılığını itirir və yenidən əlavə edilmiş açar 0-dan başlayır. Admin marşrutları hər açarın razılığını qaytarır və heç vaxt onu yazmır. Hovuzun yenidən `saturation` ə dəyişdirilməsi hər saxlanmış razılığı saxlayır, bu rejimdə heç bir təsiri yoxdur. Hovuzun yenidən `consent` ə dəyişdirilməsi son tarixi keçməmiş saxlanılan razılıqları yenidən aktivləşdirir. Açar sahibi hər iki rejimdə saxlanan razılığı silə bilər.

**Təkmilləşdirilir.** `lending_percent` və `lending_until` sütunları artıq mövcuddursa, miqrasiya yalnız `borrow_mode` əlavə edir və saxlanılan faizlər olduğu kimi qalır. Hər hovuz `saturation` rejimində başlayır. Hovuz sehrbazında hər hovuz üçün `consent` yandırın. Saxlanılan dəyərlərdən heç nə çıxarılmır.

**Məhdudiyyətlər.**

- Kreditor öz payından istifadə etməzdən əvvəl hovuzu tavanında tapa bilər. Başqalarının borc götürdüyü tutum hovuzun ümumi həcminə hesablanır.
- Çek sorğudan əvvəl işləyir və heç nə saxlamır. Paralel sorğular hər hansı biri qeydə alınmazdan əvvəl istehlakı oxuyur, ona görə də borc tutumu uçuş zamanı sorğularla məhdudlaşaraq bir dəfədən çox xərclənə bilər. `saturation` rejiminin pay çeki eyni xüsusiyyətə malikdir.

## Sürüşən pəncərə sayğacı

`src/lib/quota/sqliteQuotaStore.ts` və `redisQuotaStore.ts` fayllarında həyata keçirilib.

Hər `(apiKeyId, dimensionKey)` üçün iki seqment:

- `curr`: cari seqment (`floor(nowMs / windowMs)`)
- `prev`: əvvəlki seqment (`curr - 1`)

Effektiv sürüşən dəyər:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**Dəqiqlik**: təxminən 99% dəqiqdir. Xəta seqmentlər arasındakı sərhəddə pəncərə
ölçüsünün ən çoxu 1%-ni təşkil edir (2 seqmentli aproksimasiyaya xasdır).

### Paralel icra

SQLite drayveri: hər `(apiKeyId | dimensionKey)` açarı üçün yaddaşdaxili mutex
oxu-dəyiş-yaz yarış vəziyyətinin qarşısını alır. Nümunə `src/sse/services/auth.ts`
faylındakı izdihamlı paralel sorğulara qarşı yanaşmanı təkrarlayır.

Redis drayveri: atomik artırma üçün Lua EVAL skripti — vahid Redis əmri kimi icra olunur.

## Drayverlər

### SQLite (standart, quraşdırma tələb etmir)

- Cədvəl: `quota_consumption` (`073_quota_pools.sql` / `074_quota_consumption.sql` miqrasiyalarına baxın).
- Tək instanslı yerləşdirmələr üçün ən uyğundur.
- Bütün davamlı məlumatlar mövcud OmniRoute SQLite verilənlər bazasında (`DATA_DIR/storage.sqlite`) saxlanılır.

### Redis (istəyə bağlı, çox instanslı)

- `ioredis` npm paketini tələb edir.
- Sayğaclar Redis-də saxlanılır; metaməlumatlar (hovuzlar/ayırmalar) isə SQLite-da qalır.
- Sayğacların paylaşılmalı olduğu çox replikalı yerləşdirmələr üçün ən uyğundur.

### Drayverlərin dəyişdirilməsi

Parametrlər interfeysi (`/dashboard/settings` → Quota Store) və ya mühit dəyişənləri vasitəsilə:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

Verilənlər bazasındakı parametr mühit dəyişənindən daha yüksək prioritetə malikdir. Əgər `driver=redis` olsa, lakin URL mövcud olmasa və ya
`ioredis` quraşdırılmasa, fabrika SQLite-a geri keçir və xəbərdarlıq qeydə alır.

Drayverin seçim ardıcıllığı:

1. Verilənlər bazası parametri `quotaStore.driver`
2. Mühit dəyişəni `QUOTA_STORE_DRIVER`
3. Standart: `sqlite`

## Çoxölçülü

Hovuzun bir neçə ölçüsü ola bilər. Hər ölçü müstəqildir:

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // global pool ceiling for this dimension
}
```

**Misal: Codex planı** (5h% + həftəlik%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

Sorğu icazə veriləcək bütün ölçüləri təmin etməlidir.

### Faiz ölçüləri: hər açar üçün atribut

Faiz planı hesab və plan pəncərəsi üçün bir istifadə rəqəmini bildirir. Provayder hər API açarı üçün sayğac vermir.

Bu rəqəmi açarlar arasında bölmək üçün hər bir hovuz hər hesab və plan pəncərəsi üçün atribut kitabçasını saxlayır. `src/lib/quota/percentLedger.ts` kitabın qaydalarına riayət edir. `src/lib/quota/percentAttribution.ts` kitabı mühafizə orqanlarının istifadə etdiyi nömrələrə çevirir. Nəticə, hər bir əsas marşrut üzrə ayələr əsasında qurulmuş bir təxmindir.

#### Kitabı hərəkətə gətirən mütaliələr

Kitab tələb olunan plan pəncərəsi üçün yalnız provayderin öz rəqəmi üzərində hərəkət edir. Bu əlaqələr bir hesabat verir:

| Provayder                           | Pəncərələri planlaşdırın |
| ----------------------------------- | ------------------------ |
| Claude, OAuth bağlantısı vasitəsilə | `5h`, `weekly`           |
| Codex                               | `5h`, `weekly`           |

Bunlar oxuma sayılmır:

- provayder müştərisinin köhnə kimi qeyd etdiyi cavab
- provayderin faizini bildirmədiyi Claude pəncərəsi
- başqa bir pəncərənin fiquru və ya pəncərələr arasında ən pis vəziyyət
- dərəcə limiti başlığının geri qaytarılması
- uğursuz oxu

API açarı olan Claude daxil olmaqla digər provayderlərin kitabları yoxdur. Bu dəyişiklikdən əvvəl olduğu kimi, hər bir düymə onların faiz ölçülərinə görə 0 yüklənir.

Oxuma doyma siqnalının 30 saniyəlik yaddaşını paylaşır. Claude oxunuşu, rəqəmin cavab başlıqlarında müşahidə edildiyi və ya istifadənin son nöqtəsindən oxunduğu zaman, o vaxt məlum olduqda tarixlənir. Digər oxunuşlar həmin keş girişinin qurulduğu vaxta görə tarixlənir.

#### Kitab nə saxlayır

Hər bir qeydə alınmış sorğu öz nişanlarını hər hovuza, hesaba və açara bir dəfə əlavə edir. Bir sayğac yalnız böyüyür. Kitab üç şeyi özündə saxlayır:

- əsas xətt: kitabın açıldığı və ya pəncərənin sonuncu dəfə çevrildiyi rəqəm
- son tətbiq olunan rəqəm
- hər bir açar, onun işarə sayğacı eyni anda işarəsi adlanır

Tətbiq və ya istifadə marşrutu atribusiyanı hesabladıqda kitab yenilənir. Yazılar təftiş nömrəsinə görə müqayisə edilir və təyin edilir. Yeni oxuduğunda bir dəfə təkrar cəhdini itirən yazıçı.

#### Açar hissəsinin necə hesablanması

Kitab oxunarkən hər bir açarın hissəsi hesablanır. Əsas xəttdən bəri rəqəmin artımı hər biri öz işarəsindən bəri yönləndirilən tokenlərə nisbətdə açarlar arasında bölünür.

Together, bu tokenlər `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` tokenləri üçün rəqəmin ən çox bir nöqtəsini izah edir (defolt 1,000). Onların izah etmədikləri artım xaricidir. Baza da xaricidir.

Məsələn, kitab 0-da açılır. Açar A sonra 900.000 tokeni, B açarı isə 100.000-ni istiqamətləndirir. 60 rəqəmində A hissəsi 54 nöqtə, B hissəsi isə 6-dır.

Açar işarəsindən aşağı olan sayğac yenidən başladı və tam olaraq sayılır. Pəncərənin ortasında hovuza qoşulan açar kimi nişanı olmayan açar bütün işarələrini sayar. Tokenləri geridə qoyan rəqəm növbəti oxunuşda yox olan xətaya səbəb olur. O, yığılmır.

`QUOTA_PERCENT_MIN_TOKENS_PER_POINT` hər atributda oxunur. Ən azı 1 olan sonlu sayda olmayan dəyər 1000-ə düşür.

#### Oxumaq kitabı necə dəyişir

İlk uyğunluq qaydası tətbiq olunur:

1. **Hələ kitab yoxdur:** oxu kitabı açır. Onun rəqəmi əsasdır və hər sayğac qeyd olunur.
2. **Köhnə oxu:** sonuncu tətbiq ediləndən əvvəl tarixli oxunuş nəzərə alınmır. Sıfırlama vaxtı saxlanan vaxtdan 30 dəqiqə əvvəl olan oxunuş da belədir.
3. **Yeni provayder pəncərəsi:** saxlanandan 30 dəqiqədən çox gec sıfırlama vaxtı kitabı çevirir. Rəqəm bazaya çevrilir və hər sayğac yenidən qeyd olunur. Sayğac olmayan açarlar kitabı tərk edir.
4. **Bitmiş pəncərə:** oxunan məlumat vaxtından sonra olmayan saxlanılan sıfırlama vaxtı pəncərənin bitdiyini bildirir. Oxumaq, şəkli nə olursa olsun, kitabı çevirir.
5. **Daha yüksək rəqəm:** yalnız sonuncu rəqəm hərəkət edir. Əsas xətt və işarələr qalır.
6. **Eyni rəqəm:** rəqəm, əsas xətt və işarələr qalır. Yalnız kitabda olmayan bir sıfırlama vaxtı yazılır.
7. **Aşağı rəqəm:** daha aşağı rəqəm heç vaxt belə tətbiq edilmir. Kitabı yalnız üç şey tutduqda çevirir. Son tətbiq olunan oxunuşdan ən azı iki dəqiqə yenidir. Heç bir şey pəncərənin eyni açıq olduğunu söyləmir. Bir nöqtədən çox aşağıdır.

Üç şey tutduqda pəncərə eyni açıq pəncərə kimi sayılır. Hər iki sıfırlama vaxtı məlumdur. Onlar bir-birindən 30 dəqiqəlik məsafədədirlər. Saxlanılan hələ oxunuşdan qabaqdadır. Pəncərənin içindəki aşağı rəqəm heç nəyi dəyişmir.

Sıfırlama vaxtı yalnız onu daşıyan oxunuşun məlumat vaxtından əvvəl olduğu halda saxlanılır. Daha yüksək rəqəm istifadəyə yararlı olduqda onun oxunuşunun sıfırlama vaxtını saxlayır, əks halda isə saxlanılan rəqəmi saxlayır. Bərabər rəqəm yalnız kitabda heç bir şey olmadıqda oxunma vaxtını qeyd edir. Başqa heç nəyi dəyişmir. Kitabı çevirməyən aşağı rəqəm heç bir sıfırlama vaxtını qeyd etmir.

#### Kitabdan istifadə edildikdə

Oxuduqdan sonra, onun saxlanmış sıfırlama vaxtı cari vaxtdan sonra deyilsə, kitab istifadə olunur. Bu vəziyyət sıfırlamadan dərhal əvvəl götürülmüş bir oxunuş, məsələn, keşdən xidmət edilən kimi, ondan dərhal sonra müşahidə edildikdə yaranır.

İstifadəyə yararlı oxu olmadan, saxlanılan kitab yalnız cari pəncərənin kitabı ola bildiyi halda istifadə olunur. Bu iki halda olur:

- onun sıfırlama vaxtı məlumdur və hələ qabaqdadır
- onun sıfırlama vaxtı yoxdur və onu dəyişdirən son oxunuş ən çoxu 15 dəqiqə köhnədir

Əks halda heç bir şey kitab olmayanda olduğu kimi aid edilmir. Saxlanmış sıfırlama vaxtı keçmiş kitabdan heç vaxt ödəniş tutulmur.

#### İcra

Açarın faiz ölçüsü üzrə istehlakı onun aid edilən hissəsi və xarici hissənin payıdır. Xarici hissə əvvəlcə heç bir ayırma iddiası olmayan tutumdan istifadə edir (çəkilərin cəmindən 100 minus). Yalnız artıqlıq çəki ilə açarlar arasında bölüşdürülür.

Bu istehlak hər hansı digər ölçüdə olduğu kimi açarın ədalətli payı ilə müqayisə edilir. Doyma siqnalı `QUOTA_SATURATION_THRESHOLD` çatdıqda ciddi rejim hələ də başlayır (standart 0.5). Hər bir nömrə effektiv limitlə ölçülür: hər hesab limiti hovuzdakı hesabların sayına bərabərdir.

`capUnit: "percent"` ilə mütləq qapaq yalnız eyni şəkildə miqyaslanmış açara aid edilən hissəni hesablayır. Hesab başına 100 və k hesab limiti götürün. Xidmət hesabının rəqəminin açar hissəsi N/k nöqtələrinə çatdıqda N həddi çatır. Hər bir hesab öz kitabı ilə yoxlanılır. Məsələn, iki hesabla bir hesabın rəqəminin 5 nöqtəsində 10 həddi çatır.

Mağaza oxuna bilmədikdə, heç bir şey aid edilmir və hər bir açar həmin ölçüdə 0 hesablanır. Bir kitab yazısı uğursuz olduqda, bu atribusiya kitabı oxunduğu kimi istifadə edir. Uğursuz bir işarə yazısı həmin sorğunun nişanlarını kitabdan çıxarır. Bu uğursuzluqların heç biri sorğunu blok etmir.

`consent` hovuzunda, borc vermə düsturu yuxarıda təsvir olunduğu kimi faiz ölçüsü üzrə hər bir açarın istehlakından istifadə edir. Başqa bir açar borc verəndə kitab bir dəfə oxunur və hər açara aid edilir. İstifadəyə yararlı kitab olmadan hər açar 0 ilə doldurulur. Çəkisi olan açar daha sonra keçir, çəkisi 0 olan açar isə yalnız başqa açar verilən zaman keçir.

#### İstifadə marşrutu

`GET /api/quota/pools/{id}/usage` eyni funksiya vasitəsilə eyni nömrələri bildirir. Faiz ölçüsü `accounts`-də hər hovuz bağlantısı üçün bir girişə malikdir. Onun yüksək səviyyəli `consumedTotal` və `perKey` ilk girişi əks etdirir.

Marşrut cari oxunu da tətbiq edir, ona görə də kitabı sorğu kimi irəliləyə bilər. `internal + external` istifadə edilə bilən oxu olmadıqda və ya daha aşağı rəqəm tətbiq edilmədikdə `consumedTotal` dən fərqlənə bilər.

#### Saxlama və saxlama

Hər iki kvota mağazası kitabı saxlayır. SQLite-da verilənlər bazasının avtomatik təmizlənməsi aktiv olduqda, 60 gün ərzində yenilənməmiş sətirləri silir. Redis də hovuz bağlantısının kitabları və sayğacları bir açarı paylaşır. Son işarənin yazılması və ya kitab dəyişdirilməsindən 60 gün sonra müddəti başa çatır. Dəyişməyən kitab yenidən yazılmır, buna görə də kəsmə ən uzun plan pəncərəsinin üstündə qurulur. Əl ilə istifadə tarixçəsinin sıfırlanması SQLite -dəki kitabları da təmizləyir (Məhdudiyyətlərə baxın).

#### Məhdudiyyətlər

- Əsas xətt o vaxtdan bəri yönləndirilən hər bir açarın işarələri ilə bölündüyündən bəri hesab rəqəminin bütün artımı. Bu artımın nə vaxt baş verməsinin əhəmiyyəti yoxdur.
- Beləliklə, OmniRoute xaricində edilən istifadə, açarların tokenlərinin icazə verdiyi qədər tutulur. Buraya kitab artıq açıq olan zaman açarın ilk pəncərə sorğusundan əvvəl edilən istifadə daxildir.
- Məsələn, xaricdən istifadə əsas marşrutlar olmadığı halda hesabı 60 xal artırır. Açar daha sonra 30.000 tokeni istiqamətləndirir və rəqəm 60.6-ya çatır.
- Əgər kitab bu istifadədən əvvəl açıq idisə, açar hissəsi 30 baldır. O, həmçinin çəkisi 25 olan dörd açarla 7,65 xarici istifadəyə malikdir.
- Əgər kitab bu istifadədən sonra açılıbsa, 60 bal əsasdır. Açar hissəsi 0,6 baldır və 15 xarici istifadəni daşıyır.
- Bir sorğu və ya istifadə marşrutuna səfər kitabı açır. Beləliklə, bu cür istifadənin əsas kimi sayılması kitabın nə vaxt açılmasından asılıdır.
- Standart mərtəbə ilə, kənar istifadə zamanı 60.000 tokeni yönləndirən bir açar hesabı 60 xal artırır, bütün 60-ı öz hissəsi kimi alır.
- Döşəmə 50.000 ilə, öz hissəsi 1,2 baldır. Digər 58.8 xaricidir və hər hansı xarici istifadə kimi çəki ilə doldurulur.
- `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` planınızda bir balın dəyərinə yaxın qoyun. Xarici istifadəyə hovuzdan kənar açarlardan eyni hesabdakı trafik daxildir.
- Hər rejimdə faiz həddi tətbiq olunur. Hesab doyma həddindən çox aşağı olduğu halda qapalı açardan imtina edilə bilər.
- Pəncərədə əvvəllər xarici istifadə üçün 10 və 12 nöqtədən ibarət bir qapaq götürün. 20.000 tokeni yönləndirən açar 12,4% hesabla rədd edilir.
- Bölmə, token həcminə görə təxmindir. Sorğu onun tez bildirişləri və tamamlama nişanları kimi sayılır. Keş endirimləri və model qiymətləri bu sayı dəyişmir.
- 200 statusu ilə bitməyən sorğu heç bir nişanı qeyd etmir. Nümunələr müştərinin kəsdiyi axın və istifadə bitdikdən sonra yuxarı axın xətasıdır.
- Belə bir sorğunun səbəb olduğu istifadə, tokenləri qeyd edən açarlara, tokenlərinin icazə verdiyi qədər tutulur. Qalanları xaricidir. Geri çəkilmir. Heç bir token istifadə edilmədiyini bildirən cavab heç bir nişanı da qeyd etmir.
- Davam edən sorğunun istifadəsi bütün sorğu üçün başqa aktiv açarın hissəsində göstərilə bilər. Yalnız sorğu 200 statusu ilə başa çatdıqda geri qayıdır.
- Kitab açılanda artıq hesabda istifadə xarici hesab olunur. Bu, təkmilləşdirmə, yeni hovuz və yeni hesabı əhatə edir. İlk oxunmadan əvvəl yeni pəncərədə istifadə də xarici sayılır.
- Hər bir açar, heç bir ayırma iddiası olmayan tutumdan sonra həmin istifadənin çəki payı ilə başlayır. 85%-lik bir hesab və çəkisi 20 olan beş açarla hər biri istifadə olunan 20 açardan 17-si ilə başlayır.
- Bir neçə hesabı olan hovuzda xidmət hesabının rəqəmi cəmlənmiş büdcəyə tətbiq edilir. Bu, kitaba görə dəyişməzdir.
- Provayderin açıq elan etdiyi pəncərənin içərisində daha aşağı rəqəm tətbiq edilmir. 30 dəqiqədən çox geri çəkilən sıfırlama vaxtı köhnə oxunma kimi qəbul edilir.
- Hər iki halda kitab saxlanmış sıfırlama vaxtı keçənə qədər öz vəziyyətini saxlayır. Bundan sonra, bir oxu çevrilənə qədər kitab yüklənmir.
- Çözüm əl ilə istifadə tarixinin sıfırlanmasıdır (`POST /api/settings/purge-usage-history`). O SQLite verilənlər bazasında atribusiya kitablarını və onların token sayğaclarını təmizləyir.
- `all` dövrü hər kitabı və sayğacı təmizləyir. Qısa bir müddət əvvəlcə onun daxilində yazılmamış kitabları təmizləyir. Daha sonra onun daxilində yazılmamış sayğacları təmizləyir, ancaq heç bir kitab qalmayan hovuz bağlantısı üçün. Saxlanılan kitab hələ də hər açarı öz sayğacının qarşısında qeyd edir.
- Fiquru yerindən tərpənməyən kitab yenidən yazılmır, ona görə də daha qısa müddət cari pəncərənin kitabını da təmizləyə bilər. Növbəti oxunuşda cari rəqəmlə təzə kitab açılır.
- Sıfırlama Redis kvota mağazasına toxunmur. Orada kitab pəncərəsi ilə bitir və ya son yazısından 60 gün sonra başa çatır.
- Provayder sıfırlama vaxtı göndərmədikdə, iki oxunuş arasında köhnə rəqəmin üstündən sıfırlanan və yenidən doldurulan bir pəncərə daha yüksək rəqəm kimi görünür. Kitab köhnə baza və işarələri saxlayır.
- Oxumalar yerli saatla tarixlənir. O, provayderdən irəli getdikdə və ya mənbə sıfırlama vaxtını bir az erkən bildirdikdə, kitab bu fərqi erkən əldə edə bilər.
- Bu qısa aralıqdakı artım, ona yönəldilmiş nişanlar tərəfindən bölünür. Növbəti pəncərənin ilk oxunuşu onu düzəldir. Çevirilmiş kitabda sıfırlama vaxtı olmadıqda, bu düzəliş son tətbiq olunan oxunuşdan ən azı iki dəqiqə daha aşağı rəqəm tələb edir.
- Bir Redis mağazasında tarix oxunuşlarını öz saatları ilə paylaşan nümunələr, bu saatları sinxronlaşdırın. Saatı geridə qalan nümunənin oxunuşları daha köhnə görünür və nəzərə alınmır.
- Saxlanılan sıfırlama vaxtından sonra istifadə edilə bilən oxunuş gəlmədikdə, oxunuş qaytarılana qədər hər açar üzrə faiz payları və faiz hədləri tətbiq edilmir. Sıfırlama vaxtı olmadan, bu, kitabı dəyişdirən son oxunuşdan 15 dəqiqə sonra başlayır.
- Redis mağazasında 60 gün ərzində boş qalan kitab yazıçının çeki ilə onun yazılması arasında başa çata bilər. Daha sonra 1-dən yuxarı olan təftişdə yenidən yaradılır, bu etibarlı vəziyyətdir.

## Boru Kəmərinin İnteqrasiyası

### PRE çəngəl (`open-sse/handlers/chatCore.ts`)

Təsdiqləmə və siyasət yoxlamalarından sonra yuxarı axın icraçısından əvvəl işləyir:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → getQuotaStore().peek() per dimension
      → fairShare.decideFairShare()
      → if block → return 429 (buildErrorBody, Hard Rule #12)
      → if allow + deprioritize → set quotaSoftPenalty=true on candidate
  → executor.execute()
```

**Uğursuz-açıq** : `enforceQuotaShare` atırsa, sorğuya `pino.warn` log ilə icazə verilir. Bu, kvota mühərriki səhvinin bütün trafiki bloklamasına mane olur.

**Tutum geri qayıdanda.** Açar payından və ya hovuz tavanında imtina hər iki borc rejimində iki cümlədən biri ilə başa çatır:

- `percent` pəncərəsi: `. The <window> window resets at <time>.` Vaxt provayderin hesabatlarının sıfırlanmasıdır.
- Sayılan vahid: `. Enough <window> usage is expected to clear by <time>.` Əgər açar başqa heç nə göndərmirsə, vaxt sürüşmə pəncərəsindən yuxarı hədddir.

`<time>` UTC də ISO 8601 anidir. Bundan sonra imtina `Retry-After` ifadəsini daşıyır: həmin an qədər bütün saniyə, üstəgəl bir. Bu qədər uzun müddət gözləyən müştəri anidən ən çox bir saniyə sonra yenidən cəhd edir. Ani bilinmədikdə, imtina nə cümləni, nə də başlığı ehtiva edir. Mütləq məhdudiyyətdən imtina heç birini daşımır. İctimai kod `quota_share_blocked` qalır.

Paylaşımdan imtina paylaşılan əlaqəyə toxunmur. O, soyutma müddətini, model kilidini və provayder açarının nasazlığını təyin etmir və hovuzun digər açarları xidmətə davam edir. Kombonun hər hədəfi öz payı üçün açardan imtina etdikdə, kombo gözləmədən 429 cavabını verir. Onun cavabı `Retry-After` kimi işarə daşıyır. Yerləşdirmə yolu öz imtinasını eyni cümlə ilə bitirir və `Retry-After` göndərmir.

### POST çəngəl (rekord istehlak)

Uğurlu cavabdan sonra:

```
executor returns success
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → getQuotaStore().consume() per dimension
      → fail-open: errors logged as pino.warn, never propagated to client
```

**Drift qeydi** : `consume` post-cavabda uğursuz olarsa, yuvarlanan sayğac az sayılır. Provayderdən gələn doyma siqnalı (məsələn, `anthropic-ratelimit-unified-5h-utilization`) növbəti sorğuda qlobal qiymətləndirməni düzəldir.

### Kombo yumşaq penalti (`open-sse/services/combo.ts`)

Zaman `decision.deprioritize === true`:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // default 0.7
}
```

Bütün digər xal faktorlarından sonra cəza tətbiq edilir. Doymuş açarı çətin blok etmədən seçmək üçün avtomatik birləşmə ehtimalını azaldır.

## Self-Xidmət Kvota API (qoşulmaq)

`GET /api/v1/me/quota/{provider}` (həmçinin `/v1/me/quota/{provider}`-də xidmət göstərir) API açar sahibinə öz açarı ilə paylaşılan abunəliyin nə qədərinin onlara aid olduğunu və onlara nəyin mane olduğunu oxumağa imkan verir. Marşrut `src/server/selfService/quotaHandler.ts` üzərində nazik bir qabıqdır; görünüş `src/lib/quota/selfView.ts` tərəfindən qurulur və onun cavab müqaviləsi `src/shared/schemas/selfQuota.ts` dir (`SelfQuotaView` in `docs/openapi.yaml`).

### Aktivləşdirmə və autentifikasiya

- Xüsusiyyət bayrağı `QUOTA_SELF_PANEL`, standart `false`. O, söndürüldükdə, marşruta çatan sorğu 404 alır. `REQUIRE_API_KEY=true` ilə müştəri API siyasəti bayraqdan asılı olmayaraq marşrut işə düşməzdən əvvəl 401 ilə çatışmayan və ya etibarsız açardan imtina edir. Açarı olmayan sorğu, lakin daxil edilmiş idarə paneli sessiyası həmin siyasəti keçir və marşrutun öz cavabını alır. Bayraq bütün digər bayraqlar kimi həll olunur (iş paneli və ya REST ləğvi, sonra eyni adlı mühit dəyişəni); bax [`FEATURE_FLAGS.md`](../reference/FEATURE_FLAGS.md).
- Hər bir hovuzun görünən adı və hər bir cədvəlin etiketi idarəçinin yazdığı kimi hovuzun əsas sahiblərinə qaytarılır. Bayrağı yandırmazdan əvvəl onların həmin açar sahibləri tərəfindən oxunmaq üçün uyğun olub olmadığını yoxlayın.
- Açar yalnız başlıqlardan oxunur: `Authorization: Bearer <key>` və ya `x-api-key: <key>`. Hər ikisi göndərildikdə, ilk təsdiq edən istifadə olunur. Sorğu sətirindəki açar və ya kuki nəzərə alınmır. Serverin mühit açarı rədd edildi (401).
- Açar `self:usage` əhatə dairəsinə ehtiyac duyur (onsuz 403).
- Provayder seqmenti kəsilir, kiçik hərflərlə yazılır və `^[a-z0-9][a-z0-9._-]{0,63}$` ilə yoxlanılır (əks halda 400), sonra provayder reyestrində həll edilir, beləliklə, `cc` kimi ləqəb `claude` hovuzlarını oxuyur. `claude` və `anthropic` eyni hovuzları oxuyur.

### Hər bir görünüş nəyi göstərir

| Görünüş         | Tələb edir                                                                         | Sahələr                                                                                                                                                                                                                                             |
| --------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Öz payı         | `self:usage`                                                                       | `pools[]` (ref, ad, provayder, siyasət, çəki, cap), `dimensions[].yourShare`, `accounts[]` ilə `yourShare` ( `attributed` və `external` olmayan `percent` pəncərəsində), `blocks`, `availableModels`, `expiresAt`, `apiBaseUrl`                     |
| Hesab səviyyəsi | `self:usage` + `self:account-quota`, və açarın `sharedQuotaProviders`-də provayder | `percent` pəncərəsinin `yourShare` `dimensions[].total`, `accounts[].dimensions[].account` və `accounts[].modelWindows`, `attributed` və `external` və üzv istifadəsi aktiv olan hovuzda `members` əlavə edir ( [Üzvün istifadəsi](#member-usage) ) |

- `sharedQuotaProviders` hər düymə parametridir (`PUT /api/keys/[id]/self-service`): `null`, standart, açarın çatdığı hər bir provayder deməkdir; `[]` heç biri deməkdir. Hər bir hovuzun `accountVisible` ona hansı görmə qabiliyyətinin tətbiq olunduğunu bildirir.
- Hesab panelləri və model pəncərələri yalnız açarın əlaqəsindən istifadə edə biləcəyi hesablar üçün göstərilir. Açarda icazə verilən bağlantıların siyahısı olduqda, ondan kənarda olan hesab `Account N` girişini `account` və ya `modelWindows` olmadan saxlayır. Boş siyahı `/v1/me/status` üçün olduğu kimi heç bir məhdudiyyət demək deyil. Hovuzun cəmi (`dimensions[].total`) həmin siyahıdan asılı deyil.
- Təkcə `self:usage` ilə göstərilən iki rəqəm digər açarların istifadəsindən gəlir. Cədvəl büdcəsinin `exhausted` həmin cədvəl üzrə hər bir açarın istehlakını əks etdirir. Çəkisi sıfır olan hovuzda açarın `weight` `100 / number of members` dir. Hər ikisi icranın açara aid olduğu şeydir.
- Hovuz yalnız `ref` ilə müəyyən edilir, zəng açarına bağlı qeyri-şəffaf dəyər. Onun displey adı (`name`) administratorun yazdığı kimi daxil edilir. `ref` açardan və serverin API açar sirri olan hovuzdan (`API_KEY_SECRET`) əldə edilir. Müştərilər bunu israr etməməlidirlər: o sirr çevrildikdə dəyişir.
- Hesablar hovuz qaydasında `Account 1`, `Account 2`, … kimi verilmişdir. Heç bir hovuz identifikatoru, əlaqə id-si, hesabın e-poçtu və ya hesab adı qaytarılmır və cavab ondan kənar hər hansı sahəni buraxan müqavilə sxemindən keçir.
- Sayılan vahidlər (`requests`, `tokens`, `usd`) kvota qapısının tətbiq etdiyi hovuz qabı kimi bildirilir: hovuzdakı `limit` = plan limiti × hesabları, `fairShare` = çəkisi / 100 × `limit` (hər çəki 0 olduqda bərabər bölünür = `consumed` `remaining` = `fairShare` − `consumed` da döşəmə.
- `blocks.schedules` açarın cədvəl pəncərələrini sadalayır (`open`/`closed`, `blackout` və ya `outside-window`, `retryAfterSeconds`, ehtiyat mərtəbələr və pəncərənin büdcəsinin sərf olunub-olunmaması); `blocks.modelCaps` hər model üçün saatlıq hədləri istehlakla sadalayır.
- Provayderin hər hovuzundan kənar bir açar `pools: []` ilə 200 alır; `availableModels` (açarın `/v1/models`-də gördüyü `qtSd/` identifikatorları), `expiresAt` və `apiBaseUrl` hələ də doldurulur.
- `apiBaseUrl` `OMNIROUTE_PUBLIC_API_BASE_URL`, sonra `OMNIROUTE_PUBLIC_BASE_URL`, başqa `null`. Bu heç vaxt sorğunun öz mənşəyi deyil.

### Kredit razılığı

`PATCH /api/v1/me/quota/{provider}` bir hovuz üçün zəng edən açarın öz razılığını qeyd edir. O `GET` nin bayrağı, başlıqları və provayder qaydalarından istifadə edir. `self:usage` əhatə dairəsi bu bir yazmağa icazə verir, baxmayaraq ki, adı yalnız oxumaq üçün oxunur.

```json
{
  "pool": "qpr_0123456789abcdef0123456789abcdef",
  "lendingPercent": 30,
  "lendingUntil": 1893456000000
}
```

- `pool` `GET` nin həmin hovuz üçün qaytardığı `ref` dir.
- `lendingPercent` 0-dan 100-ə qədər olan tam ədəddir. 0 dəyəri razılığı və onun son tarixini təmizləyir. `lendingPercent` 0 olan bədən hər iki rejimdə qəbul edilir.
- `lendingUntil` isteğe bağlıdır: epox millisaniyələri və ya son tarix üçün `null`. Gələcəkdə və ən çoxu 8640000000000000 olmalıdır. 100000000000-dan aşağı dəyər saniyə kimi oxunur və rədd edilir.
- Hər hansı digər sahə rədd edilir. 4096 baytdan uzun bir bədəndən imtina edilir. Oxuma bu ölçüdə dayanır, buna görə daha uzun bir bədən heç vaxt bütöv tutulmur.

Yoxlamalar bu cədvəlin ardıcıllığı ilə aparılır. Hər bir imtina sabit bir mesajla standart səhv orqanından istifadə edir. Bu çeklərdən birinin imtinası heç nə yazmır.

| Vəziyyət | Mesaj                                                                                              | Nə vaxt                                                              |
| -------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 404      | `Not found`                                                                                        | `QUOTA_SELF_PANEL` bayrağı sönür.                                    |
| 401      | `Valid API key required`                                                                           | Açar yoxdur və ya etibarsızdır və ya serverin mühit açarıdır.        |
| 403      | `API key lacks the self:usage scope`                                                               | Açarda `self:usage` yoxdur.                                          |
| 400      | `Invalid provider`                                                                                 | Provayder seqmenti yanlışdır.                                        |
| 429      | `Too many lending changes. Retry later.`                                                           | Açar limitini keçdi. Cavab `Retry-After` daşıyır.                    |
| 400      | `Body must be { pool, lendingPercent, lendingUntil }. lendingPercent is an integer from 0 to 100.` | Bədən JSON deyil, çox uzundur və ya sxemə uyğun gəlmir.              |
| 400      | `lendingUntil must be a Unix time in milliseconds`                                                 | Son tarix saniyə kimi oxunur.                                        |
| 400      | `lendingUntil must be in the future`                                                               | Son tarix sorğu vaxtında və ya ondan əvvəldir.                       |
| 404      | `Pool not found`                                                                                   | `ref` bu provayder üçün bu açarın heç bir hovuzunu adlandırmır.      |
| 403      | `Lending is not enabled for this pool`                                                             | Hovuz `saturation` rejimindədir və `lendingPercent` 0-dan yuxarıdır. |
| 500      | `Failed to build quota view`                                                                       | Hər hansı digər uğursuzluq. Onun səbəbi serverdə qeyd olunur.        |

Limit hər açar üçün 60 saniyədə 20 sorğudur. Provayder yoxlanışından keçən hər bir sorğu, hətta sonradan rədd edilmiş və ya heç nəyi dəyişdirməyən bir sorğu sayılır. Açarın sorğu sürəti limitindən başqa onun öz sayğacı var.

Saxlanılan razılığı dəyişdirən sorğu bir `quota.pool.lending.updated` audit qeydini yazır. Açarı köhnə və yeni dəyərlərlə adlandırır. İki dəfə göndərilən eyni qurum bir dəfə yazır, bir dəfə yoxlayır. Cavab yazdıqdan sonra qurulan tam `GET` görünüşü ilə 200-dür.

`GET` view kreditləşməni aşağıdakı kimi bildirir:

- Hər hovuzda `borrowMode` (`saturation` və ya `consent`) və açarın öz `lendingPercent` və `lendingUntil` var.
- `lendingActive` yalnız `consent` hovuzunda `true` dir, faiz 0-dan yuxarıdır və son tarix çatmayıb.
- `consent` hovuzunda hər bir hesablana bilən `dimensions[].yourShare` `borrowAvailable` daşıyır. Bu, açarın digər açarların verdiyi paydan yuxarı istifadə edə biləcəyi şeydir.
- `borrowAvailable` qapının düsturundan istifadə edir. Açar öz payının altında olarkən hər bir digər açarı oxuyur. Paralel olaraq digər açar və hesablana bilən ölçü üçün əlavə bir oxu olan `hard` açarı üçün.
- `borrowAvailable` `soft` və ya `burst` açarı üçün `null`, oxumaq uğursuz olduqda isə `null`.
- `borrowAvailable` bütün digər açarlar üçün bir rəqəmdir. İki düymədən ibarət hovuzda o, digər açarın öz rəqəmidir.
- `borrowAvailable` hələ `percent` windows və ya `accounts[]` -də bildirilməyib.
- `saturation` hovuzunda görünüş `lendingActive: false` ilə saxlanılan razılığı bildirir və `borrowAvailable` yoxdur.

### Səhvlər

Bu marşrutun hər cavabı, uğur və ya səhv, `Cache-Control: no-store` daşıyır. Marşrut işə düşməzdən əvvəl baş verən imtina onu daşımır, məsələn, müştəri API siyasətinin 401 və ya IP filtrinin 403. Marşrutun xətaları sabit bir mesajla standart xəta əsasını istifadə edir: 400 (etibarsız provayder), 401 (çatışmayan və ya etibarsız açar), 403 ( `self:usage`), zq405 (flag 40d) və `Failed to build quota view`). Sorğu marşruta çatdıqdan sonra 500 istənilən uğursuzluğu, o cümlədən açar axtarışını əhatə edir; onun səbəbi serverə daxil olub və heç vaxt geri qaytarılmayıb. `PATCH` səhvləri [Kredit razılığında](#lending-consent) verilmişdir.

### Məhdudiyyətlər

- `remaining` açarın ədalətli payının istifadə etmədiyi hissəsidir. Bu zəmanət deyil. Hovuzda yer olduqda, açar hələ də ondan kənarda verilə bilər. Hovuzun cəmi `limit` çatdıqda, öz `remaining` asılı olmayaraq, hovuzun hər bir açarı rədd edilir və `self:account-quota` olmayan açar bu cəmi görə bilməz.
- `remaining` bölgüsünün mütləq `cap` nəzərə almır. Qapaq blokunun pəncərəsindəki öz istehlakı qapağın dəyərinə çatdıqdan sonra icra orqanı açardan imtina edir.
- Hesab səviyyəli bar provayder limitləri keşindən gəlir və icra qərarını bir neçə dəqiqə gecikdirə bilər. Sıfırlama vaxtı keçmiş oxu `stale` olaraq bildirilir.
- Hər model pəncərələri (`modelWindows`) yalnız plan-pəncərə xəritəsi olan provayderlər üçün bildirilir: bu gün Claude və Codex. Digər provayderlər üçün boş `windows` siyahısı ilə hesab məlumatları göstərildikdə `modelWindows` hələ də mövcuddur.
- `percent` pəncərəsində açarın öz payı təxmindir. O, atribusiya kitabından gəlir və yuxarıda "Faiz ölçüləri: hər açar üçün atribusiya" altında sadalanan bütün məhdudiyyətləri daşıyır.
- `consumed` icranın ədalətli payla müqayisə etdiyi rəqəmdir. Bu `attributed` plus `external`, dəqiqdir. `attributed` kitabın yönləndirdiyi tokenlər üçün açarı verdiyi hissədir. `external` hovuzun açarlarının nəzərə almadığı hesabın istifadəsinin açar hissəsidir.
- Hər iki hissə yalnız hovuzun `accountVisible` doğru olduqda göndərilir: açar `self:account-quota` malikdir və provayder `sharedQuotaProviders` dədir. Onsuz bir açar eyni `status` və `reason` ilə tək `consumed` alır.
- Hər iki hissə və öz çəkisi ilə, sahibi hovuzun açarlarına yüklənən hovuzdan kənarda istifadəni işləyə bilər. Hesabın əhatə dairəsi olan sahibi artıq hesabın cəmini görür.
- Pəncərədə heç nəyi yönləndirməyən açar hələ də öz xarici yükünü `consumed` dan oxuya bilər, çünki onun aid hissəsi 0-dır.
- Məsələn, kitab 0-da açılır, A və B düymələri hər birinin çəkisi 50-dir. Açar A 900.000 tokeni və B açarı 100.000-ni istiqamətləndirir. Bundan sonra hesab 100 limitinin 60%-nə çatır. Sonra `attributed` A açarı üçün 54, B açarı üçün 6, hər ikisi üçün `external` 0-dır.
- Görünüş kitabı oxuyur və heç vaxt vəziyyətini yazmaz. Kitabı açmır və heç vaxt provayderdən oxumağı tələb etmir. Redis mağazası ilə oxuma, qapının oxuduqları kimi arxa planda əvəz edilmiş təftiş sahələrini silir.
- Paylaşım yalnız qapının keşində hesabın oxunuşunu saxladığı halda `ok` olur. Biri olmadan bu `stale` dir, buna görə də son sorğusu olmayan hovuzda o, köhnəlmiş kimi göstərir.
- Sorğu hovuzdan keçənə qədər paylaşım əlçatan deyil. Bu sorğu kitabı açır və o an hesabın rəqəmi hovuzdan kənar istifadə kimi sayılır.
- Bir neçə hesabı olan hovuzda hər hesab girişi həmin hesabın öz kitabından və bir hesabın limitindən istifadə edir. İcra hər iki tərəfi hesabların sayına görə ölçür, buna görə də nisbət eynidir.
- Hər model pəncərələri açar üçün heç bir pay daşımır. Kitab hər bir model məlumatını saxlamır.
- Cədvəlin ehtiyat mərtəbələri görünüşə görə qiymətləndirilmir: sorğu `schedule-reserve` səbəbi ilə rədd edilərkən cədvəl `open` kimi göstərilə bilər.
- Eyni açarın iki hovuzu əlaqəni paylaşdıqda, icra onlardan birini tətbiq edir və görünüş hər ikisini siyahıya alır.
- Uğursuz açar cəhdləri üçün ünvan üzrə heç bir məhdudiyyət yoxdur: əks proksi arxasında zəng edənlər bir ünvanı paylaşa bilər (bu yönləndirilmiş müştəri ünvanlarının etibarlı olub-olmamasından asılıdır), beləliklə, bloklama hər açar sahibinə marşrutu rədd edə bilər. `REQUIRE_API_KEY=true` ilə etibarsız açar müştəri API siyasəti tərəfindən marşrut işə düşməzdən əvvəl rədd edilir, bu marşrutun əvəzinə həmin siyasətin 401 gövdəsi ilə.

### Üzv istifadəsi

İdarəçi açar sahiblərinə pəncərədən istifadənin hovuzun üzvləri arasında necə bölündüyünü görməyə icazə verə bilər. Seçim hovuzun `memberBreakdown`, defolt olaraq söndürülür. O, hovuz sehrbazında və ya `PATCH /api/quota/pools/{id}` ilə qurulub. `GET /api/quota/pools` və `GET /api/quota/pools/{id}` bunu bildirir.

Görünüşün ölçüsü yalnız bütün bunlar olduqda `members` daşıyır:

- hovuz seçimi aktivdir
- hovuzda ən çox 20 ayrılmış açar var və onlardan ən azı üçü sorğu verə bilər: aktiv, ləğv edilməmiş, qadağan edilməmiş və müddəti bitməmiş
- hovuzun `accountVisible` doğrudur: açar `self:account-quota` malikdir və provayder öz `sharedQuotaProviders` dədir
- `percent` pəncərəsində hesabın əlaqəsi açarın istifadə edə biləcəyi biridir
- açarın həmin pəncərənin öz payı oxundu: onun `status` `unavailable` deyil

Əks halda `members` yoxdur. Bu heç vaxt boş siyahı deyil.

- Hər dilim `{ slot, consumed, isYou }`. Cavab sxemi bir dilimdəki hər hansı digər xüsusiyyəti və 20-dən çox dilimin siyahısını rədd edir. Dilimlər yuva sırasına görə sıralanır.
- Artıq sorğu verə bilməyən açar da daxil olmaqla, hər ayrılmış açar üçün bir dilim var. İstifadəsi olmayan üzv real sıfırı göstərir.
- Yuva 1 həmişə sorğu açarıdır, `isYou` true ilə. Digər yuva nömrələri açarlı hashın dərəcələridir. O, `API_KEY_SECRET` ilə açar və hovuzu, sorğu açarını və üzvü əhatə edir.
- Beləliklə, nömrələr sahiblər arasında düzülmür. Bir sahibi üçün onlar səfərlər arasında eyni qalırlar. Açar hovuza qoşulduqda və ya ayrıldıqda və ya bu sirr fırlananda dəyişə bilər.
- Sayılan pəncərədə bir dilim kvota mağazasındakı üzvün sayğacıdır, öz `consumed` ilə eyni sayğacdır.
- `percent` pəncərəsində bir dilim açarın öz payı kimi oxunan eyni kitabdan üzvün `attributed` hissəsidir. Hovuzdan kənarda edilən istifadə heç vaxt dilimlərə bölünmür. Bu yük çəkiyə bölünür, ona görə də onu daşıyan dilimlər çəkiləri göstərəcək.
- Hər bir görünüş paralel olaraq digər üzv və hesablana bilən pəncərə üçün bir dəyər oxuyur. Bir `percent` pəncərəsində dilimlər, payın oxuduğu kitabdan çox oxunmur. Bir dəyəri oxumaq mümkün olmadıqda, həmin pəncərədə `members` yoxdur və açarın öz payı qalır.
- Seçim və istifadə edilə bilən açarların sayı hər hovuzda bir dəfə oxunur və yalnız hesab məlumatlarını görə bilən açar üçün. Seçim və ya istifadə edilə bilən açarların sayının uğursuz oxunması həmin hovuz üçün çubuqları söndürür. Server bir xəbərdarlıq qeyd edir və görünüşün qalan hissəsi qurulur.

Barlar heç bir ad və ya id daşımır. Onlar hələ də əsas sahibinə digər üzvlər haqqında məlumat verirlər:

- Sahiblər yenə də dilimləri öz dəyərlərinə görə uyğunlaşdıra bilərlər.
- Sabit nömrələmə sahibinə zamanla bir üzvü izləməyə imkan verir.
- Dilimlərin sayı hovuzda neçə açarın ayrıldığını göstərir.
- Üç açardan ibarət bir hovuzda, hansı açarın istifadə edildiyini bilən biri sonuncu açarın nədən istifadə etdiyini deyə bilər.
- Hovuz üç istifadə edilə bilən düymənin altına düşəndə barlar yox olur. Əvvəllər çəkilmiş baxışlar hələ də hər bir üzvün nədən istifadə etdiyini göstərir.
- Hesablana bilən pəncərədə, hovuzun cəmindən dilimlər çıxılmaqla, artıq ayrılmış düymələrin istifadəsini göstərə bilər.
- Bir hesabda sıfır göstərən və digər hesabda istifadə edən üzv hansı üzvün hansı hesabdan istifadə etdiyini göstərə bilər.
- `hard` siyasəti ilə hesablana bilən hovuzda üzvün ədalətli payında böyüməyi dayandıran dilim həmin üzvün çəkisinə işarə edir.

### İstifadə seriyası (`GET /api/v1/me/usage`)

`GET /api/v1/me/usage?range=<range>` (həmçinin `/v1/me/usage` ünvanında xidmət göstərir) zəng edən açarın öz sorğularının istifadəsini və qiymətini qaytarır: cəmi, UTC gündə bir giriş, gün və model, hər model və provayder üçün. O, bayrağı, autentifikasiya qaydalarını, `self:usage` əhatə dairəsini, `Cache-Control: no-store` və yuxarıdakı kvota marşrutunun xəta davranışını paylaşır. Açar `range` dən əvvəl yoxlanılır. Səhvlər 400 (`Invalid range`), 401, 403, 404 və 500 (`Failed to build usage`).

- `range` `1d`, `7d`, `30d` (standart) və ya `90d` dən biridir. Hər hansı digər dəyər, boş dəyər və ya təkrarlanan parametr 400-dür. Zəngin qiymətini bağlamaq üçün dəstə `90d` -də dayanır. Görünüş yalnız xam istifadə tarixini oxuyur, heç bir açar daşımayan gündəlik xülasələri oxuyur.
- Sətirlər zəng edən açarın identifikatoru ilə seçilir. Açar adı sütunu heç vaxt uyğun gəlmir və açar identifikatoru olmadan qeydə alınan sətirlər heç vaxt sayılmır.
- Silsilənin qurulması pəncərədəki açarın sətirləri üzərində beş qruplaşdırılmış sorğu həyata keçirir. Quraşdırılmış seriya hər açar və diapazon üçün 60 saniyə ərzində təkrar istifadə olunur və təkrar istifadə edilən zəng heç birini işlətmir. Onun `generatedAt` yaşını verir.
- Seriya qurulduqda pəncərə bitir. Daha sonra möhürlənmiş cərgə, məsələn, saatın əyilməsi ilə, sayılmır.
- `coverage.retentionDays` operatorun xam istifadə tarixini saxlama parametridir ( verilənlər bazası parametrlərində `retention.usageHistory` ). `coverage.truncatedByRetention` tələb olunan diapazon həmin parametrdən uzun olduqda doğrudur. O, iki rəqəmi müqayisə edir və sətirlərin həqiqətən əskik olub olmadığını yoxlayır.
- Provayder açarın öz sorğuları üçün qeyd edildiyi kimi qaytarılır. Model son `/` dan sonra qeydə alınmış addır və sətirlər ona görə qruplaşdırılır. Hər hədəfi rədd edilmiş birləşmiş sorğu provayder kimi marşrutlaşdırma etiketi (kombo adı, `auto` və ya `combo`) və müştərinin göndərdiyi model sətri ilə qeyd olunur. Digər rədd edilmiş sorğular, məsələn, açıq elektrik açarı, modelin soyudulması və ya kvota park edilmiş skip tərəfindən hədəf provayderi və modeli saxlayın.
- Hesablamalar və xərclərdən başqa, cavab orta gecikməni, müvəffəqiyyət dərəcələrini və ilk və son sorğunun vaxtlarını ehtiva edir.
- `byModel` ən çox sorğu alan 50 provayder və model cütünü sadalayır. Daha çox cütlərlə onun girişləri `summary` ə qədər əlavə edilmir və `summary.uniqueModels` hər qeydə alınmış model yazısını hesablayır. `byModelTruncated` onda doğrudur və cütləri kəsimin hər iki tərəfinə düşən model qismən cəmi göstərir.
- İki xərc bildirildi. `costUsd`, istifadə analitikasının göstərdiyi kimi, hesablanmış xərcdir. Claude Code planı kimi sabit tarifli abunə təminatçıları orada $0 hesab edirlər. `listPriceUsd`, abunəliklər daxil olmaqla siyahı qiymətinə görə eyni istifadədir. Modelində qiymət sırası olmayan sorğu onun saxlanmış dəyərini hesablayır: provayderin bildirdiyi xərc və ya sorğu qeydə alındıqda hesablanmış xərc. Yalnız heç biri 0 sayılmayan sorğu, heç bir marker olmadan, cəmi qismən ola bilər.
- Cavab müqaviləsi `src/shared/schemas/selfUsage.ts` (`SelfUsageSeries` -də `docs/openapi.yaml`).

### Özünə xidmət səhifəsi

`QUOTA_SELF_PANEL` açıq olduqda, `/quota/{provider}` ictimai səhifədir. Açar sahibi orada API açarını yazır və həmin açarın provayder üçün hovuzlarını görür. Hər hovuz hovuzun hər kəs üçün istifadəsi və açarın öz payı ilə hər hovuz pəncərəsi üçün bir kart göstərir. Hovuzun hər hesabında hesabın istifadəsi və açar payı olan öz kartları var. Hesabın istifadəsi yalnız açar hesab məlumatlarını görə bildikdə görünür. Səhifədə həmçinin hər bir hesabın model üzrə limitləri və açarın öz istifadəsi göstərilir. Cədvəl açarı hazırda bloklayanda bildiriş görünür. Kartda açarın hər bir model qapağı onun istifadəsi ilə sadalanır və əldə edilənləri qeyd edir. `{provider}` provayder id və ya onun ləqəbidir (`/quota/claude`, `/quota/cc`). Naməlum provayder və bayraq söndürüldükdə hər `/quota/*` yolu 404-ə cavab verin. Xüsusi OpenAI və ya Antropik uyğun qovşaqdakı hovuzların səhifəsi yoxdur. API hələ də onlar üçün cavab verir.

Səhifənin sessiyası yoxdur. Açar yalnız `GET /api/v1/me/quota/{provider}`, `PATCH /api/v1/me/quota/{provider}` və `GET /api/v1/me/usage` nin `Authorization` başlığında göndərilir , heç vaxt URL deyil . Serverin qəbul etdiyi açar tabın `sessionStorage`-də saxlanılır. "Bu cihazda yadda saxla" ilə əvəzinə `localStorage` -də saxlanılır və "Unutma açarı" onu hər ikisindən silir. Serverin rədd etdiyi açar yaddaşdan silinir.

`consent` rejimində hovuz kredit kartını göstərir. Orada açar sahibi borc vermək üçün açarın boş payının 0-dan 100-ə qədər tam faizini təyin edir. Sahibi razılığın nə qədər davam edəcəyini də seçir: söndürülənə qədər, 1 saat, 8 saat, 24 saat, 7 gün və ya 30 gün. Müddət saxlama anından sayılır. Son tarix qüvvədə olsa da, sahibi onu saxlaya bilər. Əgər bu son tarix Saxlamadan əvvəl keçərsə, kart heç nə göndərmir və başqa seçim tələb edir. 0% ilə heç bir son tarix göndərilmir. Kartda saxlanmış son tarixi öz saat qurşağı ilə göstərir. Son müddəti keçmiş razılıq bitmiş kimi göstərilir.

Bir `hard` açarı üçün kart hər hovuz pəncərəsinə görə hazırda açara hansı digər açarların verdiyini də sadalayır. Hər bir sıra bütün digər düymələr üçün bir rəqəmdir. İki düymədən ibarət hovuzda o, digər açarın öz rəqəmidir. Görünüşün bildirmədiyi rəqəm sıfır olaraq deyil, mövcud deyil kimi oxunur. `soft` və ya `burst` açarı üçün kart heç bir rəqəmin tətbiq olunmadığını bildirir.

Açarında 0-dan yuxarı faizi saxlayan `saturation` rejimində hovuz yalnız çəkilməni göstərir. Orada qeyd olunur ki, saxlanılan faizin orada heç bir təsiri yoxdur. Onun Geri çəkmə düyməsi son tarix olmadan 0 göndərir. Saxlanılan 0 ilə `saturation` rejimində olan hovuz heç bir kredit kartı göstərmir. Yaddaşdan sonra, geri qaytarılan görünüşün ehtiyac duymadığı kart, səhifənin görünüşü yenidən dəyişənə qədər mesajı ilə birlikdə qalır.

Saxlayan Saxla və ya Çıxarış düyməsini sıxana qədər heç nə yadda saxlanmır. Hər bir mətbuat bir `PATCH /api/v1/me/quota/{provider}` sorğusu göndərir və birincisi gözlənilən halda ikinci basma heç nə göndərmir. Bədən hovuzun qeyri-şəffaf `ref` görünüşdən, faizdən və son tarixdən daşıyır. Cavab yenidən qurulmuş kvota görünüşüdür və səhifə onu ikinci oxunmadan göstərir. İki saxlama üst-üstə düşdükdə, səhifə sonuncu cavabdan sonra kvotanı bir dəfə oxuyur. Səhifə razılığı brauzer yaddaşında saxlamır.

İmtina edilən dəyişiklik kartda HTTP statusundan seçilmiş mətnlə izah olunur. Səhv mətni oxunmur. 401 açarın qəbul edilmədiyini deyir və kvotanı yenidən yükləyir. 403 hovuzun kredit dəyişiklikləri qəbul etmədiyini, 404 isə hovuzun getdiyini deyir. Hər ikisi kvotanı yenidən yükləyən düymə təklif edir. 400 və ya başqa 4xx cavabı sahibindən faizi və son tarixi yoxlamağı xahiş edir. A 429, cavabı verəndə `Retry-After` saniyələri ilə sahibindən gözləməyi xahiş edir. 5xx cavabı, 408 və ya şəbəkə nasazlığı dəyişikliyin saxlanıla bilməyəcəyini bildirir və yazılmış dəyərləri saxlayır. Müqavilədən kənar cavab kvotanı yenidən yükləyir. Uğursuz saxlama açarı öz-özünə silmir. Yenidən yükləmədən imtina edildikdə, səhifə hər hansı imtina edilmiş oxunuşda olduğu kimi açarı çıxarır.

Açar qəbul edildikdən sonra səhifədə üç nişanlı "Alətlərinizi qurun" kartı da göstərilir. "Claude Kodu" `~/.claude/settings.json` üçün `env` blokunu verir. "Shell" `export` sətirləri ilə eyni dəyişənləri verir. "Claude Desktop" üçüncü tərəfin çıxarış pəncərəsi üçün dəyərləri verir. Modellər, açarın həmin provayder üçün çağıra biləcəyi kvota payı modelləridir. Açarla birlikdə belə bir siyahı olmadıqda, blok əvəzində şlüz modelinin kəşfini işə salır. Şlüz ünvanı serverin hesabat verdiyi ictimai API mənşəlidir (`OMNIROUTE_PUBLIC_API_BASE_URL`, sonra `OMNIROUTE_PUBLIC_BASE_URL`). Heç biri təyin edilmədikdə, kart yer tutucunu göstərir və sahibinə administratordan xahiş etməyi bildirir. Açar yer tutucu kimi göstərilir. "Açarımı daxil et" bütün açarı ekrandakı mətnə və surət düyməsinin kopyaladığı yerə qoyur. Bu, qutu təmizlənənə, açar unudulana və ya dəyişdirilənə və ya səhifə qalana qədər davam edir. Kart heç bir sorğu göndərmir və fayl yükləməsini təklif etmir.

API işarələrinin oxunması `stale` ehtimal ki, köhnəlmiş kimi göstərilir. Onun `unavailable` işarələdiyi oxu heç vaxt sıfır kimi deyil, səbəbi ilə göstərilir.

Faiz planlarında API bunu bildirdikdə səhifə açarın öz payını çəkir. Bu rəqəmin təxmini olduğunu deyir və onun iki hissəsini adlandırır. Hər model limitləri yalnız hesabı göstərir.

Pəncərə `members` daşıdıqda, onun kartında hər bir üzvə bir seqment olan bir çubuq yuva sırası ilə göstərilir. Sorğu düyməsinin seqmenti vurğu rəngindən istifadə edir. Digər seqmentlər mövzunun qrafik rəngləri arasında dövr edir. Mətn əfsanəsi hər seqmenti dəyəri ilə sadalayır, buna görə də heç bir şey rəngdən asılı deyil. Seqmentlər `You` və ya `Member N` ilə etiketlənir, burada N yuvadır.

### Səhifə üçün xüsusi port

`QUOTA_PANEL_PORT` yalnız özünəxidmət səhifəsinə xidmət edən ikinci dinləyicini açır. Dəyişən təyin edilmədikcə söndürülür. `QUOTA_PANEL_HOST` bağlama ünvanıdır və defolt olaraq `127.0.0.1`.

Dinləyici bu yolları əsas porta ötürür və bütün digər yollar üçün 404-ə cavab verir:

| Yol                                                                      | xidmət edir                                  |
| ------------------------------------------------------------------------ | -------------------------------------------- |
| `/quota/{provider}`                                                      | Səhifə                                       |
| `/api/v1/me/quota/{provider}`, `/v1/me/quota/{provider}`                 | Səhifənin oxunduğu kvota görünüşü            |
| `/api/v1/me/usage`, `/v1/me/usage`                                       | Səhifənin oxuduğu istifadə seriyası          |
| `/_next/static/`                                                         | Quruluşun skriptləri, üslubları və şriftləri |
| `/favicon.ico`, `/favicon.svg`, `/icon-512.png`, `/apple-touch-icon.png` | Nişanlar                                     |

`GET` və `HEAD` gövdəsiz ötürülür. Gövdə ilə bir sorğu da ötürülür: kredit seçimini saxlamaq üçün səhifənin göndərdiyi kvota görünüş yolunun `PATCH`. Bağlantısı cavabsız bağlanan CONNECT sorğusu istisna olmaqla, hər hansı digər üsul 404-ə cavab verir. Bədəni elan edən hər hansı digər sorğu 404-ə cavab verir və onun əlaqəsi bağlanır. Təkmilləşdirmə sorğuları rədd edilir və onların əlaqəsi bağlanır. API portunda olduğu kimi nöqtə seqmenti və ya fraqment markeri olan yoldan imtina edilir. Çap edilə bilən ASCII xaricində simvolu olan sorğu hədəfi də belədir. Hədəfdəki xam nəzarət simvoluna bu portun öz yoxlanışından əvvəl HTTP analizatoru tərəfindən 400 cavab verilir. Çərçivənin öz istifadəsi üçün ehtiyatlarının ötürülməməsi üçün başlıqları tələb edin: `x-middleware-`, `x-invoke-`, `x-nextjs-`, `x-now-` və ya `x-next-` ilə başlayan adlar və `x-matched-path` və `next-resume` adları. Sorğu onlar olmadan ötürülür. Tablosuna, giriş səhifəsinə, idarəetmə API və nəticə çıxarma marşrutlarına bu port vasitəsilə daxil olmaq mümkün deyil.

`PATCH` heç bir parametr olmadan və ya yalnız `charset=utf-8` ilə `Content-Type: application/json` daşımalıdır. O, 1-dən 4096-a qədər bir `Content-Length` daşımalı, düz rəqəmlərlə yazılmalı və `Transfer-Encoding` olmamalıdır. Bu qaydalardan birini pozan `PATCH` 404-ə cavab verir. İmzalanmış və ya təkrarlanan kimi bəzi düzgün olmayan uzunluqlara bu portun öz yoxlamasından əvvəl HTTP analizatoru tərəfindən 400 cavab verilir. Port elan edilmiş baytları əsas portla əlaqə saxlamazdan əvvəl oxuyur və onları ən çox 5 saniyə gözləyir. O vaxta qədər tamamlanmayan cisim 404-ə cavab verir və onun əlaqəsi bağlanır. Bu halda və ya müştəri əvvəlcə ayrıldıqda heç nə əsas limana çatmır. Port eyni `Content-Length` ilə elan edilmiş baytları ötürür. Onlardan sonrakı baytlar əlaqədə növbəti sorğu kimi oxunur. Qabaqda olan TLS reverse proksi `Content-Length` yönləndirməli və sorğunun əsas hissəsini yenidən bölməməlidir. Əsas port, `GET` üçün olduğu kimi, `Authorization` başlığında API düyməsini yoxlayır.

404 bədəni `{"error":"not_found","message":"Not found."}`. Uğursuz rele `detail` sahəsi olmadan 502 (`api_bridge_unavailable`) və ya 504 (`api_bridge_timeout`) cavab verir.

Dinləyici `QUOTA_SELF_PANEL` oxumur və səhifəni açmır. Bayraq sönük olduqda, səhifə və onun API əsas portda 404-ə cavab verir və dinləyici bu cavabı ötürür.

İnkişaf serverində (`next dev`) səhifə bu port vasitəsilə interaktiv olmur. İnkişaf isti yenidən yükləmə yuvası təkmilləşdirmə sorğusudur və port bunu rədd edir. İnkişaf edərkən əsas portdan istifadə edin.

Liman sadə HTTP xidmət edir və səhifə API açarlarını göndərir. Defolt bağlama ünvanını saxlayın və qarşısına TLS ilə əks proxy qoyun. Geri dönmədən başqa bağlama ünvanı bu bildirişi qeyd edir:

```text
[Quota Panel] Bound to <host>. This port serves plain HTTP and the page sends API keys. Put a TLS reverse proxy in front of it.
```

Heç bir yönləndirmə başlığı göndərməyən geri döngə əsas portda yerli sayılır. Beləliklə, eyni hostda bir proxy `X-Forwarded-For` göndərməlidir. Şəxsi ünvandakı proksi həmin başlıq üçün yalnız `OMNIROUTE_TRUST_PROXY=private` (və ya `lan`) ilə etibarlıdır. İstənilən digər həmyaşıd onun əlaqə ünvanı ilə bildirilir və göndərdiyi yönləndirmə başlıqları atılır.

Dinləyici eyni anda ən çox 256 əlaqə saxlayır. Müştərinin sorğu başlıqlarını göndərmək üçün 10 saniyəsi və bütün sorğunu göndərmək üçün 30 saniyəsi var. Boş vəziyyətdə saxlanılan əlaqə təxminən 5 saniyədən sonra bağlanır. 60 saniyə ərzində fəaliyyəti olmayan əlaqə bağlanır. Bu dəyərlər sabitdir. Qarşıdakı əks proksidə də əlaqə və sürət limitlərini təyin edin. Qarşıdakı tərs proksi öz boş axın bağlantılarını 5 saniyədən az saxlamalı və ya təkrar istifadə etməməlidir. Əsas porta rele API portunun yuxarı axın zaman aşımlarından istifadə edir (`API_BRIDGE_*`).

Dinləyici də `API_PORT` təyin olunmayanda başlayır. `QUOTA_PANEL_PORT` yalnız rəqəmlərlə yazılmış 1-dən 65535-ə qədər port olmalıdır. O, tablosunun portundan və API portundan fərqli olmalıdır. Canlı WebSocket serveri aktiv olduqda, o, həmçinin `LIVE_WS_PORT` dən fərqli olmalıdır (defolt 20132). Hər hansı digər dəyər heç nə açmır və xəbərdarlıq qeyd edir. İmtina edilmiş dəyər haqqında xəbərdarlıq dəyişənə ad verir və dəyəri təkrarlamır. Artıq istifadə olunan port heç nə açmır və bu xəbərdarlığı qeyd edir:

```text
[Quota Panel] Port <port> is already in use. The quota panel port stays off.
```

`OMNIROUTE_BASE_PATH` dəsti ilə dinləyici yuxarıdakı hər yolu həmin prefiksin altında gözləyir. Quraşdırma və işləmə zamanı eyni `OMNIROUTE_BASE_PATH` istifadə edin. Onu baş kəsiklə yazın və arxada olan kəsik işarəsi olmadan yazın, məsələn `/omniroute`. Digər forma, o cümlədən `/` və `/omniroute/`, konstruksiya həmin formaları qəbul etsə də, xəbərdarlıqla portu tərk edir. İlk seqmenti tətbiq marşrutunu adlandıran əsas yol da belədir: `api`, `v1`, `v1beta`, `_next`, `quota`, `dashboard`, `docs`, `login`, `codex`, `responses`, `anthropic`, `openai`, `v0` və ya `connect`, istənilən halda.

Məhdudiyyətlər:

- Ardında kəsik işarəsi olan `/quota/{provider}/` bu portda 404-ə cavab verir.
- Xidmət işçisi və veb tətbiq manifestinə bu portda xidmət göstərilmir.
- İdarə panelində quraşdırılmış fərdi favikon bu portda göstərilmir.
- Tətbiq əsas yol altında işləyərkən nişanlar göstərilmir.
- Liman sadə HTTP/1.1. dilində danışır
- Uğursuz olan bağlama proses yenidən başlayana qədər təkrar sınaqdan keçirilmir.
- Dinləyicinin hər bir müştəri ünvanı üçün əlaqə və ya tarif limiti yoxdur.
- Konteyner quraşdırmaları bu bölmədə əhatə olunmur.

## Problemlərin aradan qaldırılması

### Redis konfiqurasiya edilib, lakin qoşulmur

`ioredis` paketinin quraşdırıldığını (`npm ls ioredis`) və `QUOTA_STORE_REDIS_URL`
ünvanının əlçatan olduğunu yoxlayın. Bağlantı uğursuz olarsa, fabrika SQLite-a
geri keçir (hadisə `warn` səviyyəsində jurnala yazılır).

### `peek` köhnəlmiş nəticə qaytarır / açıq rejimdə uğursuz olur

`peek` xəta verərsə, `enforceQuotaShare` nəticəni «icazə ver» kimi qəbul edir (uğursuzluq zamanı açıq rejim).
Əsas səbəbi müəyyən etmək üçün `pino` jurnallarında `quota:enforce` və
`quota:factory` qeydlərini yoxlayın.

### İstehlak sayğacında yayınma

Provayderin faktiki istifadəsi sayğaclardan fərqlənirsə, bu gözləniləndir —
2-seqmentli sürüşən pəncərənin sərhədlərində təxminən 1% xəta olur və `consume`
cavabdan sonra nəticə gözlənilmədən icra edilir. Doyma siqnalı (`saturationSignals.ts`)
30 saniyəlik TTL ilə provayderin faktiki istifadə səviyyəsini oxuyur və
`globalUsedPercent` dəyərini müvafiq olaraq tənzimləyir.

### Hovuz sərfiyyat sürəti üçün «məlumat yoxdur» göstərir

`computeBurnRate` ən azı 2 tarixi nümunə tələb edir. Əvvəlki `consume`
çağırışları olmayan yeni hovuzlar `tokensPerSecond: 0` və `timeToExhaustionMs: null`
göstərəcək.

## localStorage-dan miqrasiya

`/dashboard/costs/quota-share` ilk dəfə yükləndikdə `useLocalStoragePoolMigration` hook-u aşağıdakıları yoxlayır:

1. `localStorage.getItem("omniroute:quota-share:pools")` boş deyil.
2. `GET /api/quota/pools` sorğusu `[]` qaytarır (DB boşdur).

Hər iki şərt doğru olarsa, hər bir köhnə hovuz paket şəklində `POST /api/quota/pools` ünvanına göndərilir, sonra isə localStorage açarı silinir. Miqrasiya idempotentdir: 2-ci şərt təkrar miqrasiyanın qarşısını alır.

## DB sxeminin xülasəsi

`078`, `079` və `085` miqrasiyaları ilə əlavə edilmiş üç cədvəl:

- `quota_pools` + `quota_allocations` — hovuz tərifləri və hər açar üçün ayırmalar.
- `quota_consumption` — `(apiKeyId, dimensionKey)` başına yuvarlanan 2 vedrəli sayğaclar .
- `provider_plans` — manual provayder planını ləğv edir ( connectionId üçün ölçülər JSON ).

Bütün cədvəllər idempotent `CREATE TABLE IF NOT EXISTS` miqrasiyaları vasitəsilə əlavə edildi.

Razılaşdırılmış kreditləşmə üç sütun əlavə edir: `quota_allocations.lending_percent` (tam, defolt 0), `quota_allocations.lending_until` (epox millisaniyələri və ya son tarix üçün `NULL` ) və `quota_pools.borrow_mode` (defolt `saturation`). Onun miqrasiyası yalnız bu sütunları əlavə edir və mövcud sətir yazmır.

Faiz atribusiya kitabı `quota_percent_ledger` (hovuz üçün bir sıra, hesab və plan pəncərəsi) və `quota_percent_ledger_tokens` (hər hovuz, hesab və API açarı üçün bir işarə sayğacı) əlavə edir. `src/lib/db/quotaPercentLedger.ts` onları oxuyur və yazır.
