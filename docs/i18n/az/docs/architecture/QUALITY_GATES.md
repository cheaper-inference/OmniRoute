## Gate inventar və icra profilləri

### Namizəd qəbulu

CI və Quality Gates iş axınlarının hər biri sabit qərar verir: `Gate / CI` və `Gate / Quality`. Onların versiyalı qəbul siyasəti tələb olunan və ya məsləhət kimi hər bir yuxarı işi sadalayır. Müvafiq tələb olunan iş uğur qazanmalıdır: çatışmayan, ləğv edilmiş, atlanmış, gözlənilən və naməlum nəticələr PASS qura bilməz. Etibarlı yalnız sənədlər və ya yalnız kataloq üçün təsnifat kod zolağının qeyri-mümkün olmasına səbəb ola bilər; PR layihəsi qəbul edilmiş namizəd deyil. `hotfix` etiketi sübutdan imtina etmir.

Hər iki iş axını PRs main/release filiallarına əhatə edir, `main`-ə itələyir, əl ilə göndərmə və qrup hadisələrini birləşdirir. Tam seçimi itələyin, göndərin və birləşdirin. `release/**` -yə təkanlar onları işə salmır (10-18-2026): hər bir dəyişiklik artıq öz PR də matrisi işlətdi və birləşdirilən birləşmə Release-Green-in işidir (`docs/ops/RUNNER_BOX.md` → Hosted zolaq). Çəngəllər və birləşmə qrupları, əks halda öz-özünə yerləşdirilən qaçışçıları seçən işlər üçün yerləşdirilən qaçışçılardan istifadə edir; buraxılışdan əvvəl kifayət qədər yerləşdirilmiş tutum yoxlanılmalıdır.

Adi bir PR sürətli seçimi idarə edir. Qəbul siyasətinin `full-code` və `full-code-e2e` zolaqları (E2E, inteqrasiya, paket artefaktı, Electron tüstüsü, Bun SQLite, ekosistem və protokol müştəriləri) yalnız Mergify növbə qaralamasında və ya tam icrada işləyir: `gh workflow run ci.yml --ref <branch>`.

Hər bir JSON qəbzi yoxlanılmış SHA, iş axını və cəhdi müəyyən edir. CLI checkout/event SHA uyğunsuzluğunu rədd edir. İş axını testləri siyasət üzvlüyünü hökm işinin `needs` siyahısına bağlayır ki, yeni və ya çıxarılan zolaq səssizcə yoxa çıxmasın. Qəbzlər nəşr, yerləşdirmə və ya mövcud məsləhət skanerinin daxili hissələrini deyil, öz iş axınını əhatə edir. Filial qaydalarında hər iki çek adının aktivləşdirilməsi ayrıca inzibati dəyişiklikdir; Bu işləri əlavə etmək özü bir şöbəni qorumur.

### Növbəni birləşdirin

`queue` etiketi Birləşdirmə növbəsinə (`.mergify.yml`) PR göndərir. Mergify `mergify/merge-queue/` filialında qaralama PR açır, CI orada tam seçimi işə salır və `Gate / CI`, `Gate / Quality` və `Merge integrity (changelog + generated skills)` keçəndə orijinal PR birləşir.

Mergify öz növbəsinin xülasəsini qaralamanın təsvirinə yazır və digər proqramlar da onu redaktə edə bilər. Belə qaralamada `pull_request` `edited` hadisəsi özünün paralellik qrupunu (`-queue-edit-<run_id>`) götürür, ona görə də o, qaralamanın real qaçışını ləğv edə bilməz və o, qapını və matrisi atlar. Yalnız `Merge integrity` hələ də işləyir. Atlanan qapı işi fərqli çek adı daşıyır, çünki Mergify atlanmış `Gate / CI` uğursuz çek kimi oxuyur və PR sıradan çıxarır.

Dequeue sonra, bir təkan həmişə PR requeue deyil. Bu barədə `@mergifyio queue` şərh edin.

### Qəbul reduktorunda saxlanılan sübut

`scripts/quality/validate-release-acceptance.mjs` təchiz edilmiş planı və onun təzahürlərini azaldır; planın tam buraxılış boru kəmərini əhatə etdiyini müəyyən etmir. Onun hesabatları açıq şəkildə `releaseAcceptance: false` təyin edir, hətta bu plan `VERIFIED` olduqda belə. `release-acceptance.yml` iş axını hələ də real quruluş, paket, açılış və ya tanıtım qəbzləri deyil, kölgə qurğularından istifadə edir.

CLI saxlanılan sübutları yoxlamaq üçün `--evidence-root` tələb edir. Fayllar `<evidence-root>/<artifact_id>/<member>` kimi həll edilir və SHA-256 kimi hashed olunur. Sübutsuz PASS qeydi, itkin və ya dəyişdirilmiş fayl, təhlükəli yol və ya simvolik əlaqə yoxlamanın qarşısını alır. Çatışmayan fayllar boş uğurlu qeydlərə bərabər deyil. Mövcud SHA/run/attempt çekləri müstəqil olaraq qalır: uyğun baytlar köhnə qəbzi xilas edə bilməz. Fayl bütövlüyü icranın həqiqiliyinə və ya artefaktın təşviqinə sübut deyil.

### Statik skan edilmiş inventar

Versiyalaşdırılmış npm-ləqəbli inventar və statik-skan üzvlüyü `config/quality/gate-manifest.json`-da yaşayır. Skript adlarını və `package.json` qarşı dəqiq əmrləri təsdiqləmək üçün `npm run check:gate-manifest` işə salın; əlavələr, silinmələr və komanda sürüşməsi həm yerli çəngəl, həm də CI-də dəyişiklik təsnifatı işlərini uğursuz edir. Ləqəb iş axını işi, matris nümunəsi və ya sınaq işi deyil: bu saylar bir-birini əvəz edə bilən kimi təqdim edilməməlidir.

Seçilmiş ləqəbləri icra etmədən yoxlamaq üçün `npm run quality:scan -- --list` və ya `npm run quality:scan:fast -- --list` istifadə edin. Qaçışçı npm giriş nöqtəsini çağırır, ona görə də onun işləmə vaxtı (konfiqurasiya edilmiş Bun daxil olmaqla) saxlanılır. Manifest həmin profillərdən kənar ləqəbləri ayrıca çağırılmış kimi qeyd edir və baxım əmrləri yalnız oxumaq üçün skan profillərində qadağandır.

Bu profillər yalnız statik taramanı əhatə edir. Onlar məhsul testlərini, əhatə dairəsini, qablaşdırmanı, xarici yoxlamaları və ya namizədin tam buraxılış qəbulunu təsdiq etmir. İş axınının qəbulu əlaqəli `config/quality/admission-policy.json` və `scripts/quality/admission-verdict.mjs` istifadə edir. Buraxılış-müşahidəçi profilləri ayrı qalır; onların müvafiq çek və qəbzlərini müstəqil şəkildə yoxlayın. Tam müşahidəçinin statik əmrləri `audit:deps`, mutasiya testi seçimi və tərcümə yoxlamaları daxil olmaqla `config/quality/release-green-static-profile.json`-də elan edilir. Yükləyici package.json və modelləşdirilmiş CI/Quality bəyannamələrinə qarşı npm əmrlərini təsdiq edir; o, arqument kimi qabıq işarələrini yerinə yetirmək əvəzinə drifti rədd edir. Tələb olunan skaner SKIP/INCOMPLETE çıxışı PASS qura bilmir. Profil öz xarici istisnalarını qeyd edir və yerləşdirilən əhatə dairəsini, sınaq matrislərini, paket və ya yerləşdirmə sübutlarını əvəz etmir. Aşağıdakı nəsr inventar bir istinaddır, bir qapının həqiqətən qaçdığını sübut etmir.

Skriptlər `scripts/check/` (siyasət qapıları) və `scripts/quality/` (ratchet engine) altında yaşayır. Həqiqətin CI mənbəyi `.github/workflows/ci.yml` dir.

### PR sürətli yolunu buraxın (`quality.yml`)

`.github/workflows/quality.yml` main/release PRs üzərində CI tamamlayır, `main` yə itələyir, qrupları göndərir və birləşdirir. PRs yol filtrli sürətli yoxlamalardan istifadə edir. Daimi əlil olan dublikat quruluş silindi; real build/package/boot çekləri CI-da qalır. Vahid dəsti və vitest yalnız CI də işləyir (`Unit Tests (N/8)` və `Vitest`).

| İş                                               | Əhatə dairəsi                                                                                                                                 | Bloklama                         |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `Docs Gates (fast-path)`                         | Docs/code PRs; API docs refs və docs-all                                                                                                      | Bəli                             |
| `Fast Quality Gates`                             | PRs kodu; statik yoxlamalar, tip yoxlanışı, tablosuna tip yoxlanışı, təsirə məruz qalmış vahid testləri, unudulmuş qardaş testləri (məsləhət) |
| `No new ESLint warnings`                         | PRs kodu; supressions-xəbərdar lint qoruyucu                                                                                                  | Bəli, çəngəllər də daxil olmaqla |
| `Merge integrity (changelog + generated skills)` | Qaralama olmayan PRs; dəyişiklik jurnalı və yaradılan bacarıq sinxronizasiyası                                                                | Bəli, çəngəllər də daxil olmaqla |

#### Unudulmuş qardaş testləri hesabatı

`npm run check:forgotten-sibling-tests` `Fast Quality Gates` -nin məsləhət addımı kimi işləyir və test-təsir xəritəsinin arxasında idxal həlledicisini təkrar istifadə edir. Hər dəyişdirilmiş istehsal modulu üçün, namizəd testi çəkilmə tələbi fərqində olmadıqda, deterministik `changed module/symbol -> static consumer -> candidate sibling test` zəncirləri haqqında məlumat verir. Markdown xülasəsi və JSON nəticəsi hər hansı bloklama yayımından əvvəl kalibrləmə üçün `forgotten-sibling-tests` iş axını artefaktı kimi saxlanılır.

Barelin təkrar ixracı və dinamik idxalı yalnız həlledici diaqnostikadır; onlar heç vaxt bloklayan tapıntı yaratmırlar. Nəzərdən keçirilmiş istisnalar `config/quality/forgotten-sibling-allowlist.json`-da yaşayır. Hər bir giriş istehlakçı və namizəd testini adlandırmalı, konkret əsaslandırma verməli və GitHub məsələsini əlaqələndirməlidir və ya sorğunu çəkməlidir. Səhv tərtib edilmiş girişlər bağlana bilmir. İstisnalar silinmiş namizəd testini və ya `.skip`/`.todo` əlavə edən fərqi sıxışdıra bilməz; iddianın zəifləməsi və digər maskalanma müstəqil şəkildə bloklanan `check:test-masking` qapısına məxsus olaraq qalır.

#### Tərcümə güzgüləri əldə edilmiş fayllardır (PR rejimi və buraxılış rejimi)

PR xüsusiyyəti yalnız ingilis mənbələrini redaktə edir. `docs/i18n/<locale>/**` güzgüləri (66 `llm.txt` nüsxəsi və tərcümə edilmiş `CHANGELOG.md` faylları daxil olmaqla) və `.i18n-state.json` tərcümə dalğası (`docs/i18n-*` / `chore/i18n-*` filialları, planlaşdırılan `i18n-mirror-refresh.yml`) və buraxılış (`npm run release:sync-changelog-i18n`) ilə bir addımda yenidən yazılır. Buna görə də güzgü qapıları iki rejimdə işləyir, `scripts/check/lib/gateMode.mjs` (`--mode=pr|release`, sonra `OMNIROUTE_GATE_MODE`, sonra Fəaliyyət hadisəsi; yerli qaçış `release`):

- `check:docs-sync` — buraxılış rejimi hər yoxlamanı həyata keçirir. PR rejimi package.json/OpenAPI versiyasını, kök CHANGELOG başlıqlarını və əvəz edilmiş sənədlərin qoruyucusunu saxlayır və `llm.txt` güzgü nüsxələri və tərcümə edilmiş CHANGELOG bölmələri üçün `SKIP reason=pr-mode` çap edir — əgər PR güzgülər yazmazsa: `docs/i18n/**` ailəsinin yazıçısı kimi elan edilən baş `config/quality/derived-paths/*.json` həm, həm də yoxlanılır, diff bazası həll edilir, öz fərqi `docs/i18n/<locale>/llm.txt` və ya `CHANGELOG.md` redaktə edən dəyişiklik ciddi şəkildə yoxlayır. Fərq bazası depth-1 yoxlamasında ( `docs-sync-strict` işi) həll edilmir, buna görə də PR rejimi bazaya ehtiyacı olmayan bir yoxlamanı da həyata keçirir: hər `llm.txt` güzgü mövcud olmalı, `---` ayırıcısını saxlamalı və ya kök gövdəsini, ya da əksər güzgülərin paylaşdığı bədəni daşımalıdır. Köçürülən bir baza bütün güzgüləri eyni dərəcədə köhnəlir və keçir; bir güzgüyə əl ilə düzəliş uğursuz olur. Tərcümə edilmiş `CHANGELOG.md` fayllarında depth-1 PR yoxlamasında belə bir yoxlama yoxdur.
- Pre-commit çəngəl `check-docs-sync.mjs --mode=pr` işləyir: bir öhdəlik onun etdiyinə görə qiymətləndirilir. Bayraq olmadan yerli qaçış buraxılış rejimidir və `llm.txt` kökünü redaktə edən birləşdirilmiş PR dalğa qaçana qədər həmin bazada hər bir sonrakı öhdəliyi bloklayardı. Eyni qayda Husky çəngəlinin işlədiyi rejimdən xəbərdar olan istənilən qapı üçün də keçərlidir: qarmaq `--mode=pr` keçir və ciddi hökm buraxılış rejimində işləyir (buraxılış PR, `main`-ə itələyir, sadə yerli qaçış).
- Güzgü məzmun vahidi testləri (`tests/_helpers/mirrorFreshness.ts`: `cycle-docs-mirror-contract`, `resilience-pre-dispatch-docs-mirrors`, `cli-env-quality-docs-mirrors`, `docs/*-locales`) — buraxılış rejimi hər bir dili təsdiqləyir. PR rejimi yalnız `.i18n-state.json` (bütün fayl hashı və ya test sancaqları bölməsinin qeydə alınmış bölmə hashı) uyğun olaraq ingilis mənbəsi ilə cari olan güzgüləri təsdiqləyir və bir səbəblə köhnə olanları atlayır. `target_hash` mənşəyinin yoxlanılması hər iki rejimdə hər bir yerli üçün çalışır. Təravət `## ` bölməsinə görədir, vahid `run-translation.mjs` hashes; uzun bölmə (bu faylın qapısı inventarının təxminən yarısıdır) onda hər hansı redaktənin həmin güzgüləri köhnəlməsi və onların PR rejiminin təsdiqləmələri növbəti dalğaya qədər keçməsi deməkdir. İngilis mənbəsində artıq olmayan lövbər bütün fayl müqayisəsinə qayıdır.
- `i18n translation drift` — PRs haqqında məsləhət, təkanda ciddi, gecə və buraxılış kəsilib, ona görə də köhnəlmiş güzgü buraxılışda göndərilə bilməz.

`scripts/i18n/sync-llm-mirrors.mjs` (həmçinin `syncLlmMirrors()` kimi ixrac olunur, `--dry-run` ilə) `llm.txt` güzgülərini yenidən yazır; buraxılış yeniləməsi, tərcümə dalğası və planlaşdırılan `i18n-mirror-refresh.yml` onu işə salır (yeniləmə quru işləmə ilə köhnəlmiş `llm.txt` güzgülərini aşkar edir, çünki sürüşmə hesabatı onları siyahıya salmır və onları `check:docs-all` əvvəl sinxronlaşdırır).

`docs/diagrams/` altında on iki README SVGs yaradılır (`scripts/docs/gen-readme-<name>.mjs`; `npm run docs:readme-diagrams` onların hamısını bərpa edir). Hər birinin bayt-müqayisə vahid testi (`tests/unit/docs/readme-*-svg.test.ts`, iş `test-unit`) var ki, bu da qəbul edilmiş fayl buraxılış rejimində köhnəldikdə uğursuz olur; PR-da `check:generated-artifacts` SVG mühakimə edir və PR redaktə edir və bazanın sürüşməsi buraxılış yeniləməsinə buraxılır (bax: [Yaradılmış fayllar və əldə edilmiş əsas xətlər](#generated-files-and-derived-baselines-written-at-release) ) — və `check:docs-counts` `<text>` qovşaqlarından kanonik nömrələri oxuyur — buna görə də kontur addımı hər bir faylda təsvir olunan `<text>` saxlayır. SVG kanonik-rəqəm yoxlaması `SVG_DIAGRAM_FILES` (`scripts/check/check-docs-counts-sync.mjs`) -da sadalanan faylları oxuyur: `docs/diagrams/readme-hero.svg`, `free-tier-budget.svg`, `promise-pillars.svg`, `comparison-table.svg`, `cli-terminal.svg`, `tier-cascade.svg`, plus `public/images/tier-flow-dark.svg` və `tier-flow-light.svg`; free-forever, kataloqa giriş, təkrarlanan hovuz və skorinq faktorları iddiaları da `promise-pillars.svg`, `free-tier-budget.svg` və `strategies-grid.svg` oxunur. Bu generatorların çəkdiyi saylar (provayder cəmi, MCP alətləri, marşrutlaşdırma strategiyaları, pulsuz əbədi provayderlər, …) literallardan deyil, `docs/reference/derived-facts.json` vasitəsilə `scripts/docs/readmeFacts.mjs` vasitəsilə əldə edilən snapshot faktlarından gəlir, ona görə də hər hansı filialda diaqramın bərpası təhvil verilmiş faylı təkrarlayır. `free-tier-budget.svg` eyni snapshotdan öz cərgələrini çəkir (`code.freeTierBudget`, kataloq xülasəsi faktların araşdırılması qeydləri), beləliklə, `FREE_MODEL_BUDGETS` -ə dəyişiklik CI qırmızıya çevirmək əvəzinə növbəti yeniləmədə karta çatır.

### Əldə edilmiş dəyərlər: `pr` və `release` qapısı rejimləri

PR xüsusiyyəti heç vaxt bazanın vəziyyətindən asılı olan dəyəri yazmır: provayder, miqrasiya, MCP aləti və strategiya sayları, README SVG nömrələri, faktların anlıq görüntüsü. Bir addım onların hamısını yenidən hesablayır, `npm run release:refresh-derived`, buraxılış və gecəlik əldə edilən-yeniləmə PR tərəfindən idarə olunur. Beləliklə** buraxılışlar arasında baza dizayna görə canlı kodun arxasındadır** , və bir bacı provayderi əlavə etdikdən sonra ağacı canlı kodla müqayisə edən qapı və ya test hər PR -də qırmızı olacaq. Əldə edilmiş dəyərləri mühakimə edən qapılar `scripts/check/lib/gateMode.mjs` ilə həll edilən iki rejimdən birində işləyir (ilk matç qalib gəlir):

1. komanda xəttində `--mode=pr|release` ;
2. `OMNIROUTE_GATE_MODE` mühit dəyişəni (`pr` və ya `release`);
3. avtomatik, GitHub Actions hadisəsindən: başı `release/v*` olmayan `pull_request`, `merge_group` və ya `omni-queue/**` → `pr`-ə təkan; qalan hər şey (push, cədvəl, göndərmə, buraxılış PR `release/v* → main`, istənilən yerli qaçış) → `release`.

Hansı `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) hər rejimdə uğursuz olur:

| Rejim     | Uğursuz                                                                                                                                                                                                                                                                                                                                                                                                                                            | Canlı faktlara ehtiyacı var |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| `release` | Hər yoxlama, ağacdan toplanmış faktlara qarşı ciddi bərabərlik (qapının həmişə olduğu davranış): köhnəlmiş say, versiya, əhatə dairəsi və ya SVG nömrəsi STRICT sürüşməsidir.                                                                                                                                                                                                                                                                      | Bəli                        |
| `pr`      | Yalnız dəyişikliyin etdiyi eyni iddia çıxarıcıları ilə PR bazası ilə fərqlənirdi: (1) həmin çek və fayl üçün bazada mövcud olmayan idarə olunan dəyər ("PR idarə olunan nömrəni redaktə etdi — xətti əsas mətnə bərpa etdi"); (2) bazanın daşınması və başın itirilməsi tələb olunan iddia. Heç bir fakta ehtiyacı olmayan məzmun invariantları buraxılış rejimində olduğu kimi işləyir; yalnız buraxılış yoxlamaları siyahıya alınır və buraxılır | yox                         |

Agent-təlimat faylları daşıyır** yox** ümumiyyətlə törəmə sayma: `AGENTS.md`, `llm.txt` (və onun `docs/i18n/*/llm.txt` nüsxələri), bs `AGENTS.md` çəngəl, `open-sse/services/AGENTS.md`, `src/shared/constants/agentSkills.ts`, `skills/README.md` və hər `skills/*/SKILL.md` mənbəyə işarə edir (məsələn `src/shared/constants/routingStrategies.ts`-də `ROUTING_STRATEGY_VALUES` ) və əvəzinə `npm run facts`. "Heç bir əldə edilmiş sayma (agent-təlimat faylı ...)" invariantı hər iki rejimdə orada (provayderlər, köçürmələr, MCP alətləri və əhatə dairələri, marşrutlaşdırma strategiyaları, xal faktorları, rejim paketləri) hesablamanı uğursuz edir, buna görə buraxılış yeniləməsi heç vaxt təlimat faylını yenidən yazmağa ehtiyac duymur.

`pr` rejimində yazıçı bölmələri idarə olunan dəyərləri redaktə edə bilər: `chore/derived-*` (gecə yeniləməsi PR), `release/v*` və tərcümə dalğaları `docs/i18n-*` və `chore/i18n-*` (`scripts/check/lib/derivedClaimsDiff.mjs`). Növbə qrupları (`merge_group`, Qaralamaları birləşdirin, `omni-queue/**`) yenidən mühakimə olunmur: onlar artıq qiymətləndirilmiş qapını bir-bir PRs.

Çıxış kodları: `0` clean · `1` STRICT drift (və ya soft drift with `--strict`) və ya idarə olunan dəyər pozuntusu · `2` infrastrukturu — kod faktları toplana bilmədi (tsx probu uğursuz oldu və ya vaxtı bitdi; timeout `OMNIROUTE_FACTS_TIMEOUT_MS`, default 6000 msq və ya CI) PR əsasını həll etmək mümkün olmadı. Çıxış 2 heç vaxt sənədləşmədə fikir ayrılığı deyil: işi yenidən icra edin və ya mühiti düzəldin.

Hər rejimin işlədiyi yer:

| Harada                                                                                                                     | Rejim                                                                                                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Xüsusiyyət PR — `ci.yml` işi `docs-sync-strict`, `quality.yml` addımı "Sənədlərin dəqiqliyi"                               | `pr` (avtomatik); iş bazanı `BASE_SHA` kimi keçir və `fetch-depth: 2` ilə yoxlayır                                                                                                                          |
| `merge_group`, `omni-queue/**` namizədləri, birləşmə qatarının tam siyahısı                                                | `pr`                                                                                                                                                                                                        |
| PR (`release/v* → main`), itələmə, planlaşdırılmış və əl ilə qaçışları buraxın                                             | `release`                                                                                                                                                                                                   |
| Buraxılış-Yaşıl (`scripts/quality/validate-release-green.mjs`)                                                             | HARD elementləri `OMNIROUTE_GATE_MODE=pr` ilə işləyir ("baza pozuldu?"); DRIFT elementi `derived-refresh` `npm run release:refresh-derived -- --check` işləyir (ciddi görünüş, heç vaxt əsas-qırmızı açmır) |
| Buraxılış (`/generate-release` mərhələləri 0a və 1; bacarıq naqilləri ayrıca sahibi tərəfindən təsdiqlənmiş dəyişiklikdir) | `npm run release:refresh-derived` törəmə faylları yazır; buraxılış PR-nin öz yoxlamaları sonra `release` rejimində işləyir                                                                                  |
| `nightly-derived-refresh.yml` (gündəlik, ən yüksək `release/vX.Y.Z`, buraxılış-dondurulma altında atlandı)                 | `npm run release:refresh-derived -- --profile=nightly`; diff-də ONE PR `chore/derived-refresh` dən açıq saxlayır; heç vaxt birləşmir                                                                        |

Bunun arxasındakı əmrlər:

- `npm run facts` hər törəmə ədədi JSON (`scripts/release/facts.mjs`) kimi çap edir. `--key=code.mcpTools` bir dəyəri çap edir, `--snapshot` canlı ağacın yerinə yerinə yetirilən snapshotı oxuyur. Faktları toplamaq mümkün olmadıqda 2-dən çıxın.
- `npm run release:refresh-derived` (`scripts/release/refresh-derived.mjs`) əldə edilmiş faylları bir keçiddə bu ardıcıllıqla ( `--only=` üçün addım identifikatorları) yenidən hesablayır: `provider-reference` (`docs/reference/PROVIDER_REFERENCE.md`), `facts` (snapshot), `numbers` (sayım qapısının yenidən yazma planı sənədlərə tətbiq edilir, sonra onların `docs/i18n/` güzgülərinə köçürülür, generasiya `SKILL.md`), `readme-diagrams`), `skills` (ağac `syncE2eTimings` göndərənə qədər atlanır), `e2e-timings` (quru gavalı açarları `en.json` `ui-keys` və `--rewritten-since=<ref>` — default `origin/main` — ilə son buraxılışdan bəri yenidən yazılmış ingilis dəyərləri yenidən növbəyə salınır), `llm-mirrors` və `verify-generated` (yazıldıqdan sonra, `check:generated-artifacts` və `check:agent-skills-sync` buraxılış rejimində `--only` kənara çıxdıqda aa keçməlidirz; `--check` ; çıxış 2). `changelog` addımı daxil olmaqdır (`--with-changelog`, yalnız buraxılış profili). `--profile=nightly` heç vaxt versiya iddiasına toxunmur. `-- --check` ilə o, heç nə yazmır və hər hansı bir fayl dəyişdikdə və ya idarə olunan dəyər əl ilə redaktəyə ehtiyac olduqda (hər ikisini siyahıya alır) 1-dən çıxır; infrastruktur nasazlığı ilə bağlı 2-ci çıxış. `--json` nəticəni JSON kimi çap edir.
- `docs/reference/derived-facts.json` son yeniləmədə istifadə edilən faktların şəklidir. Yalnız yeniləmə onu yazır. README SVG generatorları onu oxuyur və PR-vaxt vahidi testləri onunla bağlı sənədləri və yaradılan faylları — heç vaxt canlı kodla müqayisə edir. Paketin tək canlı müqayisəsi `tests/unit/check-docs-counts-sync.test.ts`-də "buraxılış yeniləməsi dövrü bağlayır": canlı faktlarla yaddaşda tətbiq edilən yeniləmənin yenidən yazma planı hesabat vermədiyi heç bir STRICT drift qoymur və yenidən planlaşdırma heç nəyi dəyişmir.

Yerli olaraq çoxaltmaq üçün (yerli iş defolt olaraq `release`):

```bash
npm run check:docs-counts                                       # release: strict, live facts
node scripts/check/check-docs-counts-sync.mjs --mode=pr          # what a feature PR is judged on
OMNIROUTE_GATE_MODE=pr BASE_REF="origin/release/v$(node -p "require('./package.json').version")" npm run check:docs-counts
npm run release:refresh-derived -- --check                       # what the release would rewrite
```

Həll edilə bilən baza olmadan ( `BASE_SHA`/`BASE_REF` yoxdur, yerli `origin/release/v<version>` yoxdur) yerli `pr` qaçışı xəbərdarlıq çap edir və uğursuzluq əvəzinə fərqi atlayır.

**İki rejim (2026-11-13 tarixindən).** PR funksiyası `en.json` (və `bin/cli/locales/en.json`) dilinə düymələri əlavə edir və ya yenidən yazır və başqa heç bir dilə toxunmur; `check:pr-derived-paths` (iş `pr-test-policy`, ailə `config/quality/derived-paths/translation.json`) PR funksiyasını yerinə yetirmir. Digər yerlilər hər buraxılışda bir dəfə `release:refresh-derived` ilə `syncUiKeys()` çağıran `scripts/i18n/sync-ui-keys.mjs` ilə tamamlanır (çatışmayan düymələri əlavə edin, atılanları kəsin, yenidən yazılmış ingilis dilinin tərcümələrini `rewrittenSinceRef` ilə qeyd edin, tərcümə edin) və ya tərcümə dalğası ilə. Qapılar rejimi `scripts/check/lib/gateMode.mjs`-dən oxuyur: `pr` rejimində (xüsusiyyət PRs, `merge_group`, `omni-queue/**`) yuxarıdakı buraxma rejimi qapıları `SKIP reason=pr-mode` çap edir və 0-dan çıxış edir; `release` rejimində (buraxılış PR, `main`-a itələyir, `workflow_dispatch`, yerli qaçışlar) onlar əvvəlki kimi sərtdirlər və PR buraxılışında fərqdən xəbərdar olanlar `BASE_REF=origin/main` alırlar, ona görə də onlar dövrün əlavə edildiyi və ya yenidən yazıldığı hər düyməni mühakimə edirlər. `--mode=pr` ilə yerli olaraq xüsusiyyət-PR qərarını nəzərdən keçirin.

Hələ də `pr` rejimində yerli kataloqları dəyişən PR (tərcümə dalğası, buraxılış yeniləməsi, yalnız tərcümə üçün düzəliş) atılmır: `check-key-completeness` dəyişdirildiyi hər bir kataloqu birləşmə bazasındakı (`scripts/i18n/lib/touched-catalogs.mjs`) eyni kataloqla mühakimə edir və bir açarda uğursuz olur, kataloq itirilir, `en.json` açarı yoxdur, mətnə çevrilmiş realz və ya mətnə çevrilir. artıq PR toxunmadığı bir ingilis simlinin `__MISSING__:` placeholders/tags interpolyasiya etmir. PR də yeni bir kataloq bütün `en.json` açar dəstini daşımalıdır. Bu, PR toxunduğu kataloqlar üçün nisbət və CLI-paritet qapılarının nə görəcəyini əhatə edir.

Yerli bərabərlik vahidi testləri (`cli-i18n-catalog`, `i18n-pt-br`, `i18n-vi-completeness`, `i18n-placeholder-parity`) `tests/_helpers/localeParityMode.ts` vasitəsilə eyni rejimləri izləyir: `pr` rejimində onlar açar-paritet təsdiqlərini atlayır və birləşmə bazasından bəri ingilis dili dəyişmiş açarların yer tutucu paritetini yeniləməyə buraxırlar (vahid test işini oxuya bilməyəndə hər düymə). Həmin köməkçidir** yalnız** sanksiya edilmiş rejim-şərti atlama: `check:test-masking` `.skip(` və `{ skip: true }` hesablayır, lakin onun qaytardığı hesablanmış `{ skip: "<reason>" }` deyil, ona görə də `tests/unit/locale-parity-mode.test.ts` ondan istifadə etməyə icazə verilən testlərin siyahısını bağlayır — birinin əlavə edilməsi həmin siyahıya nəzərdən keçirilmiş redaktədir.

#### `check-ui-value-drift` — köhnəlmiş-tərcümə qapısı

Digər qapıların struktur olaraq görə bilmədiyi bir i18n reqressiyasını tutur: İngilis dəyəri yenidən yazılır və _əvvəlki_ İngilis dilindən alınan tərcümələr geridə qalır, beləliklə qeyri-ingilis istifadəçilər əminliklə yazılmış, indi səhv olan surəti oxumağa davam edirlər.

Bu real olaraq göndərildi. Antigravity giriş köməkçisi yerə endikdə `oauthModal.googleOAuthWarning` yenidən yazılmışdır (#5203);** 43 yerdən 39-u** operatorlara "tam URL kopyalayın və aşağıya yapışdırın" deyən mətni saxladı ki, bu provayder üçün tamamlana bilməyən bir —. #8463 ə qədər diqqətdən kənarda qaldı, çünki:

- `sync-ui-keys` yalnız olan açarları doldurur** yox** , heç vaxt olanlar** köhnəlmiş** ;
- `check-ui-keys-coverage` açarı _presence_ hesablayır, buna görə də köhnə tərcümə əhatə olunduğu kimi qiymətləndirir;
- `check-translation-drift` `docs/i18n/<locale>/**.md` sənədlərinin güzgülərini izləyir — heç vaxt `src/i18n/messages/*.json` oxumur. Bu `docs-sync-strict` işində işləyir: PRs üzrə məsləhət, təkanla bağlı ciddi və gecə; tərcümə dalğası PR xüsusiyyətini deyil, güzgüləri təzələyir.

**Fərqlilikdən xəbərdardır, bazaya əsaslanmır.** Birləşmə bazasında `en.json` işləyən ağacla müqayisə edir; İngilis dili dəyəri dəyişən hər bir açar üçün hələ də toxunulmamış tərcüməsi olan hər hansı bir dil köhnəlmişdir. Bu qəsdən** əvvəllər mövcud olan borcları dondurur** — a diff uzun müddət davam edən tərcümənin hansı köhnə ingilis dilindən gəldiyini aşkar edə bilməz, buna görə də qapı yalnız cari dəyişikliyin nəyə toxunduğunu mühakimə edir. Alternativ (hər açar hash bazası) ~ 600 KB yaradılan fayla başa gələcək, 3 × ən böyük mövcud baza, hər i18n PR də çalınır.

Onu qane etməyin iki yolu:

1. təsirə məruz qalan tərcümələri yeniləyin və ya
2. onları iş vaxtını `__MISSING__:<new english>` — olaraq təyin edin, sonra düzəldilmiş ingilis dilini (`src/i18n/request.ts::deepMergeFallback`, #7258) və tərcümə üçün əsas növbələrə xidmət edir.

Əgər simli** məna** dəyişdirmək, üstünlük vermək** açarın adının dəyişdirilməsi** : yeni açar köhnə tərcüməni miras ala bilməz. Bu istifadə edilən #8463 nümunəsidir.

```bash
npm run i18n:check-value-drift          # strict (what CI runs)
npm run i18n:check-value-drift:warn     # report only
BASE_REF=origin/release/vX.Y.Z npm run i18n:check-value-drift
```

Əsas kataloqu oxumaq mümkün olmadıqda (əsas ref olmadan dayaz klon), `check-openapi-breaking` aynası ilə 0-dan `SKIP reason=base-unresolved` ilə çıxır. Əsl təkmilləşdirmədən sonra baza xəttini yeniləmək üçün:

```bash

git add quality-baseline.json
```

`--update` bayrağı cari ölçülmüş dəyərləri `quality-baseline.json`-ə yazır. PR (`pr` qapı rejimi) funksiyasında o, təkmilləşdirməni məlumat kimi çap edir və ötürür; reqressiya hər iki rejimdə uğursuz olur. Sürət fazası zamanı hər yerdə məsləhətdir (`_policy.requireTighten: false`). [Yaradılmış fayllar və əldə edilmiş əsaslara](#generated-files-and-derived-baselines-written-at-release) baxın.

### CodeQL ratchet: kadansı və əl ilə tətiyi təzələyin

`check:codeql-ratchet` oxuyur** repo vəziyyəti, PR başına deyil cədvəl üzrə yenilənmiş —.** `gh api repos/diegosouzapw/OmniRoute/code-scanning/default-setup` `state: configured`, `schedule: weekly`: GitHub defolt quraşdırma skanını bildirir, hər təkan təhlili deyil. Nəticə: FIXES xəbərdarlıq edən PR birləşdirildikdən sonra, ratchet növbəti planlaşdırılan skan — işə düşənə qədər köhnə, daha yüksək sayı oxumağa davam edir, beləliklə, skan başa çatana qədər hər açıq PR, o cümlədən PR-in öz təqibləri ilə bağlı reqressiya haqqında məlumat verir.

**Əl ilə yeniləmə** : `gh workflow run codeql.yml --ref release/vX.Y.Z` təhlili yenidən həyata keçirir və bir neçə dəqiqə ərzində xəbərdarlıqları yenidən dərc edir. Əvvəlcə `.github/workflows/codeql.yml` oxuyun — onun başlığı `workflow_dispatch` -only olduğunu izah edir** çünki o, GitHub-in "standart quraşdırma" ilə ziddiyyət təşkil edir** (`CodeQL analyses from advanced configurations cannot be processed when the default setup is enabled`). `push`/`pull_request`/ `schedule` tetikleyicilərinin bərpası tələb edir** ilk növbədə sahibinin hərəkəti** : Parametrlər → Kod təhlükəsizliyi → CodeQL: Defolt → Qabaqcıl. Bu keçid olmadan `schedule:` trigger əlavə etməyin — bu, yalnız uğursuz qaçışlar yaradacaq.

**Say azaldıqdan sonra əsas xətti sıxın** — `node scripts/check/check-codeql-ratchet.mjs --update` yeni ölçülmüş sayını `quality-baseline.json` → `metrics.codeqlAlerts.value`-ə yazır, beləliklə, ratchet səssizcə köhnə tavana qədər reqressiyaya icazə vermir. İşlənmiş nümunə (2026-09-02/03): PR #12502 sabit 7 real xəbərdarlıq (13 → 6 ölçülən açıq); PR #12530 dondurulmuş baza xəttini 11 → 6 ilə uyğunlaşdırdı; Qalan 6-sı daha sonra 0-a qədər hər bir xəbərdarlıq əsaslandırması ilə işdən çıxarıldı.

**İşdən çıxarılmalar operatorun çağırışıdır (Hard Rule #14)** — işdən çıxarılma şərhində texniki əsaslandırmanı qeyd etmədən CodeQL xəbərdarlığını heç vaxt rədd etmir: yuxarı axın-protokol tələbi üçün `won't fix`, sınaq qurğusu üçün `used in tests`, sanitarlaşdırıcı üçün `false positive` CodeQL görə bilmir (presedent: `docs/security/ERROR_SANITIZATION.md`).

## Ratchet azalmalarının qeydə alınması — aşağı istiqamət (#8584)

Ratchet yalnız yarı-avtomatikdir və avtomatik olan hissə yanlış hissədir. Həddin **artırılması**
on saniyə çəkən əl ilə JSON redaktəsidir və qırmızı PR-ın blokdan çıxarılmasının ən sürətli yoludur.
Həddin **azaldılması** üçün isə kimsə `--update` icra etməli və nəticəni commit etməlidir — və
`bank-ratchet-shrinks` tapşırığı tətbiq edilənədək heç bir iş axını bunu icra etmirdi. Ölçülmüş nəticə
(2026-07-25): artıq yeni fayllar üçün 800 sətirlik həddə və ya ondan aşağı olan 18 dondurulmuş fayl, ən pis
halda 132× (`src/shared/validation/schemas.ts`, 2,523 həddi daşıyan 19 sətir);
mürəkkəblik tavanı təxminən 37 baza yeniləmə qeydi ərzində `1794 → 2169` yüksəlib və cəmi bir
azalma (−1) olub; “növbəti dövrdə `--update` vasitəsilə sərtləşdirin” ifadəsi 31 dəfə yazılıb və
yalnız bir dəfə yerinə yetirilib. Onu doğuran koddan daha uzunömürlü olan hədd, tamamlanmış hər bir
parçalanmanı faylı növbəti dəfə redaktə edən şəxs üçün səssizcə böyümə güzəştinə çevirir.

`nightly-release-green.yml` → **`bank-ratchet-shrinks`** tapşırığı bu dövrəni bağlayır:

|          |                                                                                                                              |
| -------- | ---------------------------------------------------------------------------------------------------------------------------- |
| İşləyir  | `schedule` (gündə 3×) + `workflow_dispatch` — məqsədli şəkildə `push` **deyil**                                              |
| Ölçür    | ən yüksək `release/vX.Y.Z`, `release-green` ilə eyni həll və inyeksiya qoruması                                              |
| Yazır    | `check:file-size --update` və `check:complexity-ratchets --update` (hər ikisi konstruksiyaya görə yalnız azalma tətbiq edir) |
| Yoxlayır | `npm run check:ratchet-bank` (`scripts/quality/verify-ratchet-bank.mjs`)                                                     |
| Göndərir | buraxılış budağına qarşı həmişə aktual olan bir PR — məcburi yenilənir, heç vaxt spam edilmir                                |

Qeydəalma hər `push` üzrə deyil, paketləşdirilmiş şəkildə aparılır, çünki gecikmə tələbi yoxdur (azalmanın
8 saat ərzində qeydə alınması kifayətdir), hər birləşdirmə üzrə icra isə birləşdirmə kampaniyaları zamanı
PR budağını təkrar-təkrar quracaq və hər dəfə tam ESLint keçidinin xərcini ödəyəcəkdi. Aşkarlama `push`
üzərində qalır (`release-green`); yalnız qeydəalma paketləşdirilir.

### Təhlükəsizlik yoxlayıcısı

Tapşırıq baza səviyyələrinə nəzarətsiz şəkildə yazır, buna görə bunu məqbul edən

## İcazə Siyahısı Siyasəti

Əvvəlki pozuntulara görə uğursuz ola bilməyən hər bir qapı dondurulmuş icazə siyahısından istifadə edir (məsələn, `KNOWN_STALE_DOC_REFS`, `KNOWN_MISSING`, `KNOWN_RAW_SQL`). Siyasət belədir:

**Kök səbəbi aradan qaldırın; icazəli siyahıdan yalnız pozuntu əvvəlcədən mövcud olduqda və eyni PR-da düzəldilə bilməyəndə istifadə edin.**

İcazə verilən siyahıya giriş əlavə edərkən:

1. Əsaslandırma ilə bir şərh əlavə edin.
2. İzləmə probleminə istinad edin (məsələn, `// #3498 — Phase 2 feature, not yet implemented`).
3. Pozuntu aradan qaldıran eyni PR -dakı girişi silin — artıq aktiv pozuntunu aradan qaldırmayan köhnə girişin özü bir qüsurdur (6A.3 köhnəlmə tətbiqi həyata keçirildikdən sonra yetim icazəli siyahı girişində keçidi uğursuz edəcək).

Et** yox** testlərin daha sürətli keçməsi üçün icazələr siyahısına daxil olanları əlavə edin. Artan icazə siyahısı olan yaşıl qapı yanlış keyfiyyət hissidir.

### PR-da bir qapı uğursuz olduqda

1. **Qapı çıxışını diqqətlə oxuyun** — hansı faylın və ya simvolun qaydanı pozduğunu dəqiq deyir.
2. **Pozuntu düzəldin** — əksər qapılar kod düzgün olan kimi keçən deterministik fayl sistemi yoxlamalarıdır.
3. **Əgər pozuntu əvvəldən baş veribsə** (yəni, siz bunu təqdim etməmisiniz, lakin qapı indi onu əhatə edir): əsaslandırma şərhi və izləmə problemi ilə icazə siyahısına giriş əlavə edin.
4. **Qapı cırcırdırsa** (əhatə dairəsi, ESLint xəbərdarlıqları, təkrarlama, mürəkkəblik): dəyişikliyiniz metrikanı daha da pisləşdirdi. Əsas problemi həll edin və ya dəyişiklik qəsdəndirsə və metrik deqradasiya məqbuldursa (nadir hallarda) `npm run quality:ratchet -- --update` işə salın —, lakin bunun səbəbini PR təsvirində sənədləşdirin.
5. **Məsləhət qapıları** (`continue-on-error: true`) məlumat xarakterli — dir, birləşməni bloklamır, lakin CI xülasəsində görünür. Onları hər halda düzəldin.

`scripts/i18n/check-key-completeness.mjs` (`npm run i18n:check-keys`, iş `i18n-ui-coverage`). Hər `src/i18n/messages/<locale>.json` nin yarpaq açar dəstini `en.json` ilə müqayisə edir və açarın nə vaxt əlavə olunmasından asılı olmayaraq, hər hansı olmayan və ya əlavə yarpaqda uğursuz olur. `__MISSING__:` yer tutucuları indiki kimi sayılır (onların məzmunu nisbət qapısının işidir). Bu, iki diff-based/percentage qapısının mütləq tamamlayıcısıdır: `check-ui-keys-coverage` hər bir yerli üçün 80% mərtəbə tətbiq edir ( ~ 13.000-dən 43-ü olmayan düymə hələ də 99.7% oxunur) və `check-new-key-coverage` yalnız PR `en.json` a əlavə etdiyi düymələri mühakimə edir. Şöbənin kəsildiyi günün `en.json` -dən yerli qrup yaradılır və baza açarları əlavə etməyə davam edərkən günlərlə tərcümə olunur; toplu PR özü heç bir açar əlavə etmir, buna görə də 1-ci qrup (#13044) doqquz yerli dildə 43 düymə, 2-ci qrup (#13660) səkkizdə 10 düymə qısa olduqda (2026-09-15) hər iki bacı səssiz qaldı. Qırmızı rəngi `node scripts/i18n/sync-ui-keys.mjs --locale=<codes> --translate-markers` ilə düzəldin; `extra` yarpağı mənbənin onu atması deməkdir — `sync-ui-keys` onu buraxır (`--prune-extra`, standart). `--warn` xəbər verir. `--catalog=cli` eyni müqayisəni `bin/cli/locales` (`npm run i18n:check-keys:cli`) üzərində aparır; hər iki addım `i18n-ui-coverage` işdə yaşayır. Mütləq yoxlama yalnız buraxılış rejimidir: PR funksiyası `SKIP reason=pr-mode` görür və düzəliş buraxılış yeniləməsində və ya tərcümə dalğasında işləyir, heç vaxt PR funksiyasında deyil; Yerli kataloqları dəyişdirən PR onların hər birini birləşmə bazasına qarşı mühakimə etdi ( `i18n-ui-coverage` işi altında "İki rejim" bölməsinə baxın).

#### `check-new-key-coverage` — yeni açar i18n qapısı

`check-ui-value-drift` bacısı. Bu bir İngilis dəyərini tutur** yenidən yazılmışdır** onun tərcümələri geridə qalarkən; bu bir ingilis açarını tutur** əlavə etdi** bəzi yerlilər bunu heç vaxt qəbul etməsə də.

`check-ui-keys-coverage` bu sinfi görə bilmir: o, hər bir dil üçün faiz dərəcəsini tətbiq edir və ~ 13,000-dən on bir yox düyməsi əhatə dairəsini 99,9% təşkil edir. Hər dil üzrə faiz "bu xüsusiyyət tərcümə edilməmiş şəkildə göndərilmiş" — ifadə edə bilməz.

Kodlaşdırdığı hadisə: Orkestrasiya Canvasının 3-cü Fazası on bir açarını o zaman mövcud olan 42 yerli dilə tərcümə etdi. Saatlar sonra Aİ-dilli paket (#13044) repo 51 yerə apardı və doqquz yeni gələn (`el`, `et`, `ga`, `hr`, `lt`, `lv`, `mt`, `sl`, `sr`) onları heç vaxt qəbul etmədi. `deepMergeFallback` ingilis dilini olmayan açarı əvəz edir, ona görə də uğursuzluq rejimi boş UI — real deyil, tərcümə olunmamış UI idi və konstruksiyaya görə səssiz idi.

Qardaşı kimidir** fərqindən xəbərdar** , birləşmə bazasında ingilis dilini işləyən ağacla müqayisə edərək, əvvəlcədən mövcud boşluqlar donmuş qalır və qapının işə salınması üçün miqrasiya tələb olunmur.

**`__MISSING__:<english>` markeri onu qane etmir (2026-09-17 tarixindən).** Əvvəllər sənədləşdirilmiş təxirə salınmış — idi, səkkiz funksiya PRs 2026-09-16 tarixində 61 açar əlavə edənə və tərcümə etmək əvəzinə markeri bütün 65 dilə möhürləyənə qədər iş vaxtı ingiliscə — düzəltmək üçün geri düşür: bu darvaza hər birini qəbul etdi, heç bir şey PRs maneə törətmədi və hər kəs translate nisbəti uğursuz oldu. (pt-BR 3,2 % > 2,5 % + 0,5). Marker indi olmayan tərcümə kimi qiymətləndirilir. Buraxılış rejimi yalnız 11-13-2026-cı il tarixindən etibarən: PR funksiyası `SKIP reason=pr-mode` görür və buraxılış PR (`BASE_REF=origin/main`) zamanı qapı dövrə əlavə edilmiş hər düyməni mühakimə edir. #### `check-vitest-exclusions` — park edilmiş sınaq qapısı

`vitest.config.ts`-nın `exclude` siyahısındakı fayl işləməyən bir testdir və ağacı oxuyan hər kəs üçün əhatə kimi görünür. Şərhin arxasında toplanmış altmış iki fayl `// #8618 — pre-existing failure; remove this exclusion when fixed`. Məsələ #8618 11-08-2026-cı il tarixində bağlandı, izlədiyi siyahı 45 girişdən 62-yə yüksəldi, hər yenisi ölü məsələyə işarə edən şərhi miras aldı. Siyahı nəhayət fayl üzrə ölçüləndə (#13204),** 62-dən 51-i mənbə dəyişikliyi olmadan cari ağaca qarşı keçdi** .

Qapı (a) izləmə problemini adlandırmaq və (b) ölçülmüş statusu ilə `config/quality/vitest-exclusions.json` -da görünmək üçün real faylı həll edən hər bir istisna tələb edir, ona görə də birinin əlavə edilməsi 60 girişli massivdə daha bir sətir deyil, xüsusi faylda nəzərdən keçirilə bilən fərqdir. O ~ 10 dəqiqəyə başa gələn və dövri işə aid olan xaric edilmiş — testlərini qəsdən təkrar etmir; inventarların hər birinin sonuncu ölçüldüyü zaman qeydləri.
