> **Vəziyyət:** panel üzərində qurulmuşdur **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), bu depoya iş sahəsi kimi daxil edilmişdir `packages/ui-kit` (`@omniroute/ui-kit`; yuxarı axın şəkli `packages/ui-kit/UPSTREAM.md` -də bərkidilir və `npm run check:ui-kit-snapshot` tərəfindən qorunur). İşıq kanonik mövzudur; standart üstünlük `system`. Defolt palitrası dəstin palitrasıdır **Editions** görünüş (isti kağız neytralları və mis vurğu `#e5ac82`, `packages/ui-kit/src/ci-editions.css`); Parametrlər → Görünüş → Rəng palitrası təklif edir **Classic** , əhəng vurğusu ilə dəstin əsas nişanları. Switzer UI və displey mətni (`--ci-font-ui`; `--ci-font-display` və `--ci-font-mono` ona həll) üçün əsas ailədir, kitin özü (`packages/ui-kit/src/ci-fonts.css`, `ci-tokens.css` tərəfindən idxal olunur ) tərəfindən yerləşdirilir. Hər ikona Lucide qlifidir.
>
> Inter Switzer də çatışmayan qliflər üçün ehtiyatdır; `--font-mono` sistem monospace yığınına xəritələr `--ci-font-code`.
>
> `src/app/globals.css` hər simvol forması üçün ayrıca şrift seçir. `Switzer` də olmayan simvol forması üçün o, istifadə edir: Kiril, Yunan və Vyetnam üçün `Inter` və yalnız `html[dir="rtl"]` altında ərəb yazısı üçün `Vazirmatn`.

`src/app/globals.css`:

```css
:root,
.ci-theme {
  --ci-font-ui:
    "Switzer", "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif;
  --ci-font-code: ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace;
  --font-mono: var(--ci-font-code);
}
```

## 1. Əşyaların yaşadığı yer

- **Kit.** `packages/ui-kit/src` `packages/ui-kit/UPSTREAM.md` -də bağlanmış öhdəliyin yuxarı axını `src/` -nin bayt-bayt surətidir (o, həmçinin lisenziya icazəsini qeyd edir); `PATCHES.md` yerli yamaları siyahıya alır. O, heç bir quruluş olmadan mənbə kimi istehlak olunur: `next.config.mjs` onu köçürür və `tsconfig.json` `@omniroute/ui-kit` → `packages/ui-kit/src` və `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` xəritələrini yaradır (`vitest.config.ts` və `vitest.mcp.config.ts` eyni ləqəbi daşıyır). Kit komponentini heç vaxt `@omniroute/ui-kit` çəlləkindən keçməyin (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) alt yolu ilə idxal edin: barel hər bir komponenti (tarix seçici daxil olmaqla) hər bir idxalçıya çəkir. Dəstin üslub cədvəli `src/app/globals.css` vasitəsilə daxil olur (`@import "../../packages/ui-kit/src/ci-styles.css"`, tam vərəq: əsas `ci-ui.css` və hər bir naxış ailəsi).
- **Tokenlər.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` tokenlərini elan edir; `src/app/globals.css` onları köhnə OmniRoute adlarına (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) körpü edir, beləliklə, mövcud `var(--color-*)` oxuyur və Tailwind utilitləri işləməyə davam edir. Yeni kod Tailwind utilitlərindən (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) və ya dəst siniflərindən — heç vaxt hex dəyərindən istifadə edir (`tests/unit/design-kit-bridge.test.ts` körpünü tətbiq edir). `text-primary` `--text-color-primary` vasitəsilə `--color-primary-ink` həll edir, beləliklə, `bg-primary`/`border-primary` vurğu səthini saxlayarkən əsas mətn oxunaqlı qalır: Editions altında bu dəstin `--ci-color-accent-active` sidir (işıqda dərin mis `#99562f`, qaranlıqda mis vurğu); altında Classic, işıqda lime-800 və qaranlıqda əhəng vurğusu. Diaqram seriyası `--color-chart-1` istifadə edir … `--color-chart-8`, hər biri mətn üçün təhlükəsiz `--color-chart-N-ink` və qeyri-şəffaf `--color-chart-N-subtle` çip rəngi ilə dəst seriyası qaydasında təyin olunur (`ciChartSeriesOrder`).
- **Mövzular.** `<html className="ci-theme">` (`src/app/layout.tsx`) sənədi dəst mövzusuna daxil edir. Üstünlük `light`, `dark` və ya `system` ( `src/shared/constants/appConfig.ts`-də `THEME_CONFIG.defaultTheme = "system"` ; `system` `prefers-color-scheme` dən sonra ). `src/store/themeStore.ts` -da `applyTheme()` ( `THEME_BOOT_SCRIPT` ilə əks olunur, nəmlənmədən əvvəl işləyən `src/app/layout.tsx` də daxil edilir) `data-theme="dark"|"light"` təyin edir və `<html>` -də `.dark` sinfini birlikdə dəyişdirir. Kitin qaranlıq nişan dəsti `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`) üzərində qurulub; OmniRoute-in öz qaranlıq ləğvetmələri ( `globals.css`-da `.dark` bloku) və `.dark` sinfində köhnə Tailwind `dark:` utilitləri açarı. Vurğu rənginin ilkin təyinləri yoxdur: vurğu həmişə dəstdən gəlir və mağaza yükləndikdə köhnə quruluşdan davamlı əvvəlcədən qurulur.
- **Palitralar.** İki, hər ikisi dəstdən (`src/shared/constants/appearancePalette.ts`): `editions`, standart və `classic`. Editions, `<html>`-də kitin `data-ci-appearance="editions"` atributudur və `ci-editions.css` ( `ci-ui.css` tərəfindən idxal olunur) `data-theme` ilə birləşir; Classic atributun yoxluğudur. Kök layout server-atributu göstərir, beləliklə, heç bir şey saxlanılmayan (və ya heç bir JS olmayan) ziyarətçi hər — tablosunda, girişdə, `/status`, səhv səhifələrində, `/docs` və PWA də Editions əldə edir. Seçim eyni `theme` mağazasındakı (`palette`, `setPalette()`, `applyPalette()` ) mövzunun yanında saxlanılır və `src/store/themeStore.ts`(`src/shared/utils/themeBootScript.ts`, tərtibatın `THEME_BOOT_SCRIPT` `<head>` ə daxil edilmiş ) tərəfindən boyadan əvvəl tətbiq edilir , bu atributu yalnız saxlanılan palitra `"classic"` olduqda silir ; `src/app/global-error.tsx`, kök layout xaricində, onu eyni mağazadan tətbiq edir. `data-ci-appearance` başqa elementə qoymayın: dəst onu `html:root:has([data-ci-appearance="editions"])` ilə uyğunlaşdırır, ona görə də bir nəsil bütün sənədi dəyişəcək. Editions `data-ci-editions-variant="landing"` variantı idarə paneli üçün deyil, marketinq səhifələri üçündür. Brauzer xromu: server defolt Editions `viewport.themeColor` də (hər `prefers-color-scheme` üçün bir teq) və `tests/unit/pwa-theme-colors.test.ts` tərəfindən `ci-editions.css` a bərkidilmiş Editions `--ci-color-background` -nin (`#f3f1e9` / `#11120f`) bir güzgüsü olan `src/shared/constants/pwaThemeColors.ts` də veb manifest — `PWA_THEME_COLORS` təqdim edir. Canlı `<meta name="theme-color">` daha sonra saxlanılan palitra və rejimi izləyir: `THEME_BOOT_SCRIPT` boyadan əvvəl etiketləri yenidən yazır və mövzu mağazasının hərəkətləri bunu hər dəyişiklikdə edir ( `src/shared/utils/themeColorMeta.ts`-da `resolveThemeColor()` / `applyThemeColor()`, `CLASSIC_PAGE_BACKGROUND` dəstin `ciTokens`-dən oxunması ilə). Açıq light/dark mövzusu hər bir teqi həmin rejimə təyin edir; `system` hər sxemdə bir rəng saxlayır. Manifest Editions olaraq qalır: üstünlük verilmədən hər quraşdırmada bir dəfə alınır. Monako rənglərini zonddan oxuyur (`monacoKitTheme.ts`); Editions altında zond bir sinxron keçid üçün kök `data-theme` çevirir, çünki dəst Editions light/dark kökdən həll edir.
- **Komponentlər (adapterlər).** `src/shared/components/index.tsx` OmniRoute komponentini API (eyni adlar, defolt ixrac və rekvizitlər) saxlayır və onun arxasındakı primitivlər dəst üzərindəki adapterlərdir: formalar (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), üst-üstə düşmələr və əks əlaqə (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`/ `NotificationToast`/ `EmptyState`, `Loading`), struktur (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) və cədvəllər (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). Adapter dəst komponentini alt yol ilə idxal edir və ona köhnə rekvizitləri xəritələşdirir — məsələn, `Button variant="primary"` dəst `default` düyməsidir (`--ci-button-primary-*`: işıqda tərs səth, qaranlıqda `--ci-color-accent-foreground` mürəkkəbi ilə vurğu), `danger` `destructive` və `warning` dəst `warning` düyməsidir. `Badge` status variantları dəst tonlarıdır və `<option>` uşaqları olan `Select` `NativeSelect` dəstini təqdim edir. `tests/unit/ui/adapters/*.test.tsx` hər bir adapteri bağlayın.
- **Shell.** `src/app/(dashboard)/layout.tsx`, `src/shared/components/layouts/DashboardShell.tsx` göstərən `DashboardLayout` göstərir: `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`) dəsti, OmniRoute-nin `src/shared/components/Sidebar.tsx`-də naviqasiya məntiqi ilə. `#main-content` -ə "məzmuna keçmək" bağlantısı diqqəti cəlb edən ilk elementdir. `src/shared/components/Header.tsx` `SidebarTrigger` dəstini (qabığın yeganə yan panel keçidi), Keak `ProductSwitcher` və komanda palitrası açıcısını saxlayır; o, yalnız `#main-content` daxilində heç bir dəst `PageHeader` (`.ci-page-header`) quraşdırılmadıqda marşrutun başlığını göstərir, ona görə də öz `PageHeader` malik səhifədə tək `h1` var. `src/shared/components/CommandPalette.tsx` `Dialog` dəstidir.
- **Nişanlar.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) adı (ekranların istifadə etdiyi Material Simvol lüğəti) `ICON_MAP` (`src/shared/constants/iconMap.ts`) vasitəsilə Lucide qlifinə həll edir. Material Symbols şrifti və paketi yox oldu: xəritədə çatışmayan ad neytral yer tutan qlifi (`data-icon-missing="true"`) göstərir və istehsaldan kənar konsol xəbərdarlığını qeyd edir. `npm run gen:icon-map` xəritədə əskik olan istifadə olunan adları çap edir (`tests/unit/icon-map-coverage.test.ts` Lucide işarəsi olmayan istənilən adda uğursuz olur; `tests/unit/icon-map-object-values.test.ts` axtarış obyektlərində saxlanılan adları əhatə edir); `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` hərfi `<span className="material-symbols-outlined">` əhatəsini `<Icon>`-ə yenidən yazır.
- **Brend.** `src/shared/components/OmniRouteLogo.tsx` dəsti əhatə edir: defolt ixrac `OmniRouteLogo` `ProductIcon product="omniroute" variant="glyph"` (daxili SVG, `basePath` -safe) və `OmniRouteLockup` `ProductLockup product="omniroute"` (əlçatan ad "Keak OmniRoute") və ya ağ etiketli operatorlar üçün öz `name`/`logoSrc` göstərir. Məhsul dəyişdirici təyinatları `src/shared/constants/keakProducts.ts` -də (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`) yaşayır. Müstəqil ekranlar — `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` və `src/shared/components/ErrorPageScaffold.tsx` — kilidi göstərir; `tests/unit/brand-pages-static.test.ts` onu qoruyur.

## 2. Qaydalar

1. Tokens, heç vaxt hərfi deyil. İstisnalar məqsədyönlü şəkildə saxlanılır: həmişə qaranlıq olan konsol terminalı və `STATUS_HEX` (`src/shared/constants/statusColors.ts`), hərfi hex ehtiyacı olan zəng edənlər üçün kit status palitrasının həll edilmiş hex güzgüsü. Kateqoriyalı palitralar artıq istisna deyil: onlar dəstin səkkiz diaqram nişanı (`--color-chart-1..8`, plus `-ink`/`-subtle`), `src/shared/utils/categoricalPalette.ts` vasitəsilə dəstin seriyası sırası ilə və marşrutlaşdırma strategiyaları üçün `src/app/(dashboard)/dashboard/combos/strategyPalette.ts`; ReactFlow kənarları və orkestrasiya kətan mövzudan xəbərdar `--orch-status-*` dəyişənlərini (`src/shared/components/flow/edgeStyles.ts`) oxuyur.
2. Heç vaxt `packages/ui-kit/src` əl ilə yamaq etməyin: `scripts/dev/sync-ui-kit.sh <commit>` ilə sinxronizasiya edin; əvvəlcədən icra qapısı `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) bərkidilmiş yuxarı commitdən fərqlənən hər hansı baytda uğursuz olur (yuxarı axın klonu, `UI_KIT_CLONE` və ya `_references/cheaper-inference-ui-kit` olmadıqda, xəbərdarlıqla ötürülür). Dəstdə bir şey çatışmırsa, adapterdə və ya ekranda onun ətrafında işləyin və onu yuxarıdan soruşun.
3. Kit mətninin defoltları ingiliscədir (`label = "Loading"`, `loadingLabel = "Loading table"`…) — kit komponenti mətni hər dəfə təqdim etdikdə `useTranslations(...)` dən tərcümə edilmiş sətirləri keçir.
4. Tailwind utilitləri dəst komponent sinifləri üzərində qalib gəlir (kit `@layer theme, base, components, utilities` elan edir və onun qaydaları `components`-də yaşayır) — dəst komponentlərini yenidən rəngləndirmək üçün deyil, boşluqlar və yerləşdirmə üçün utilitlərdən istifadə edir.
5. Başlıqlar: səhifə və bölmə başlıqları üçün `.ci-heading` ; `.ci-dashboard-display` yalnız səhv səhifəsi status kodu kimi böyük, seyrək ekran mətni üçün. Hər ikisi Switzer istifadə edir.
6. `tests/unit/dashboard-kit-sweep.test.ts` kitin qəbulunu qoruyur: `src/app` və ya `src/shared/components` altında heç bir Material ligature span; tablosuna ağacda (`src/app/(dashboard)` və `src/shared/components`) heç bir xam `<select>`, `<textarea>` və ya `<table>` və sadalanan istisnalar xaricində əl ilə yuvarlanan `role="dialog"` yoxdur ( `Select` adapterinin yerli filialı, `RequestLoggerDetail`); orada hər xam `<button>` və ya `<input>` yuxarıda ən çox 3 sətirlə bitən `kit-exception:` (səbəbi ilə) olan şərhə ehtiyac duyur; palitra çalarları və `dark:` variantları yalnız testin sadaladığı fayllarda.
7. PR dan əvvəl həm mövzuları, həm də 390 px görüntü pəncərəsini yoxlayın (skrinşotlar); `tests/e2e/a11y.spec.ts` balta işlədir.

## 3. Ekran əlavə etmək

1. Səhifəni kit `PageHeader` ilə açın (`@omniroute/ui-kit/page-header`, dashboard daxilində `compact`) —
   başlıq, təsvir və `actions`. Sonra shell başlığı öz başlığını atır.
2. İdarəetmə elementlərini `@/shared/components`-dən (adapterlər) qurun və adapter olmadıqda kit
   komponentlərindən alt-yol ilə istifadə edin (`Table`/`TableScrollArea`/`DataTableShell`, `Field`,
   `Alert`, `Tabs`, `RadioGroup`, `Slider`…).
3. İkonlar: `<Icon name="…" />`. Yeni ad semantik cəhətdən uyğun Lucide komponenti ilə `ICON_MAP`-ə əlavə
   edilir; `npm run gen:icon-map` hələ də çatışmayan adları siyahılayır.
4. Rənglər: semantik utility-lər (`text-success`, `bg-warning-bg`, `border-border`…) və qrafik seriyaları
   üçün `var(--color-chart-N)`; hex dəyərlər və yalnız rəngi təkrarlayan `dark:` variantları yoxdur.
5. Mətn: kit komponentlərinə ötürdüyünüz etiketlər daxil olmaqla hər sətir `useTranslations`-dan gəlir. Yeni
   açarlar `src/i18n/messages/en.json`, `pt-BR.json` və `vi.json`-a əlavə edilir (Vyetnam paritet testi
   hər ingilis açarını sabitləyir); digər lokallar i18n sinxronizasiyası ilə doldurulur.
6. PR-dan əvvəl qoruyucuları işə salın: `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (`iconMap.ts`-də təkrarlanmış import-u tutan yeganə yoxlama),
   `npm run check:ui-icu` və ekranın öz testləri.

## 4. Adapter əlavə etmək və ya dəyişdirmək

1. `src/shared/components/index.tsx` faylının publik API-sini saxlayın: eyni export adları, default export-lar və qəbul edilən prop-lar. Köhnə prop-ları adapter daxilində kit-ə uyğunlaşdırın (bax: `Button.tsx`: `VARIANT_TO_KIT`, `SIZE_TO_KIT`).
2. Kit-i subpath ilə import edin (`@omniroute/ui-kit/<component>`).
3. Kit boşluqları üçün müvəqqəti həllər adapter-də (və ya düzəliş stil olduqda `globals.css` faylında `@layer components` içərisində) yerləşir, heç vaxt `packages/ui-kit/src`-də yox.
4. `tests/unit/ui/adapters/<name>.test.tsx` əlavə edin və ya yeniləyin. Çox sayda çağırıcısı olan adapter üçün dəyişiklikdən əvvəl və sonra render olunmuş markup-u müqayisə edin — padding və ya wrapper dəyişiklikləri bütün ekranlara yayılır.

## 5. Kit-in yenilənməsi

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` də bərkidilmiş versiyanı yuxarı repo-nun ən yeni `v*` teqi ilə müqayisə edir və buraxılış bitdikdə sinxronizasiya əmrini çap edir.

Gündəlik `UI Kit upstream watch` iş axını (`.github/workflows/ui-kit-upstream-watch.yml`) eyni yoxlamanı həyata keçirir. Sancaq arxada olarkən, `scripts/ci/ui-kit-sync-pr.sh` `chore/ui-kit-sync-latest` yuvarlanan budaqda ən yüksək `release/vX.Y.Z` budağına qarşı bir sinxronizasiya PR açıq saxlayır. O, heç vaxt birləşmir: hər dəst buraxılışı hələ də yerli VPS üzərində vizual yoxlamaya ehtiyac duyur. Daha yeni buraxılış çıxdıqda filial yenidən qurulur və əks halda tək qalır. Əl ilə itələnən açıq PR üzərinə yazılmır və qoruyucunun bağlandığı, birləşdirilməmiş versiya üçün PR daha yeni buraxılışa qədər bağlı qalır.

Heç bir PR açılmadıqda (hədəf buraxılış dondurulduqda, PR əl ilə itələdi, PR bağlandı və ya heç bir PR nişanı təyin olunmadı) iş axını səbəbini bildirən bir izləmə məsələsini açıq saxlayır.

İş prosesi iki sirrdən istifadə edir:

- `secrets.UI_KIT_READ_TOKEN`: şəxsi yuxarı repo üçün yalnız oxuna bilən işarədir. Yuxarı yoxlama məlumatları oxuya bilmədikdə (token yoxdur, işləməyi dayandırmış işarə və ya GitHub əlçatmaz), o, `unknown` xəbər verir və `0` kodu ilə çıxır. İş axını xəbərdarlıq yazır və bir ayrı izləmə məsələsini açıq saxlamağa çalışır; daha sonrakı uğurlu qaçış, giriş qayıtdıqdan sonra onu bağlayır. GitHub məsələsinin uğursuzluğu API işi uğursuz edir.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: Məzmun və Çəkmə sorğuları yazma girişi olan bu depoda incə dənəli işarədir. Bu iş axını yalnız xüsusi nişan konfiqurasiya edildikdə sinxronizasiya PRs açır və ya yeniləyir; onsuz iş axını filialı itələyir və heç bir PR açılmadığını bildirir.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` həmin öhdəçilikdə yuxarı axın `src/` (`latest` = ən yeni `v*` teq) `packages/ui-kit/src`-ə kopyalayır, tək icazə verilən transformasiyanı tətbiq edir (nisbi idxaldan `.js` şəkilçisini çıxarır) və iş sahəsinin `packages/ui-kit/package.json` və `package-lock.json` versiyasını yuxarı axına təyin edir. Sonra: `git diff packages/ui-kit` nəzərdən keçirin, hər iki mövzuda provayderlər, parametrlər, kombinasiyalar, istifadə və son nöqtə haqqında vizual keçid edin, `npm run check:ui-kit-snapshot` və `npm run test:vitest:ui` işə salın və yuxarı axın dəyişiklik jurnalı ilə PR açın.

## 6. README diaqramları

Kök `README.md` faylının daxil etdiyi on iki diaqram (`docs/diagrams/*.svg`) statik təsvirə tətbiq edilmiş kitdir və onlar əl ilə çəkilmir, generasiya edilir: `scripts/docs/gen-readme-*.mjs` daxilində 13 generator faylı (on iki diaqram və `gen-readme-diagrams.mjs` drayveri) və `tests/unit/docs/readme-*-svg.test.ts` daxilində hər diaqram üçün bir olmaqla 12 köhnəlmə testi var; hər biri repozitoriyaya daxil edilmiş faylı öz generatorunun çıxışı ilə bayt-bayt müqayisə edir (`test-unit` tapşırığı).

- **Tokenlər.** `scripts/docs/readme-diagram-theme.mjs` Editions palitrasını (standart görünüşü) `packages/ui-kit/src/ci-editions.css` faylından köçürür (`tests/unit/docs/readme-diagram-theme.test.ts` vasitəsilə həmin fayla sabitlənib; bu test, həmçinin hər iki sxemdə hər səth üzərində bütün mətn rəngləri üçün WCAG AA uyğunluğunu yoxlayır; yeganə istisna açıq sxemdəki `warn` rəngidir — kitdəki dəyər kətan üzərində 4.46:1 olduğuna görə kit xəbərdarlıq rəngi 10 % tündləşdirilib) və kitin şrift ölçüsü şkalasında (`ci-tokens.css`) mətn rollarını müəyyənləşdirir: hər şey üçün kitin çəkilərində (400/500/600, başlıq üçün 500) və hərf aralığında Switzer; yalnız kod rolları (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`) istisnadır — onlar IBM Plex Mono istifadə edir və yalnız əmrlər, URL-lər, identifikatorlar və terminal ekranları üçündür.
  Açıq sxemin dəyərləri fayl daxilində `:root` üzərində, tünd sxemin dəyərləri isə `prefers-color-scheme: dark` arxasında yerləşir; beləliklə, hər təsvir GitHub-da baxanın sxeminə uyğunlaşır.
- **Şriftlər.** GitHub Markdown heç bir CSS daşımır və camo proksisi bütün xarici sorğuları bloklayır, buna görə də kitin şrifti faylın daxilində daşınmalıdır. Hər generatorun son addımı olan `scripts/docs/readme-outline.mjs`, Switzer rollarını HarfBuzz ilə formalaşdırır və onları vektor konturları (`<defs>` yolları və `<use>`) kimi çəkir; Switzer-də olmayan oxlar və həndəsi simvollar isə onun öz metrikalarına əsasən çəkilir. Yalnız konturlardan istifadə edilir, daxil edilmiş şriftdən heç vaxt istifadə edilmir: Switzer lisenziyası (`packages/ui-kit/src/fonts/FFL.txt`) yazılı razılıq olmadan alt dəst yaratmağı və format çevirməsini qadağan edir, lakin vektor təsvirlərinə icazə verir; buna görə də Switzer `@font-face` və ya `data:` URI-sini yenidən əlavə etməyin. Faylda qalan yeganə şrift real kod mətni kimi saxlanılan hissələr üçün OFL lisenziyalı IBM Plex Mono alt dəstidir (`scripts/docs/readme-fonts.mjs`) və həmin simvollardan yaradılır; daxil edə bilmədiyi istənilən qlif xəta yaradır.
- **Yenidən generasiya.** `npm run docs:readme-diagrams` on iki diaqramın hamısını README sırası ilə yenidən yazır və hər fayl üçün ölçüsü ilə birlikdə bir sətir çap edir. Ayrı-ayrı generatorlar da müstəqil şəkildə işlədilə bilər (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` üçün `node --import tsx/esm` tələb olunur, çünki onun göstəriciləri `open-sse/config/freeModelCatalog.ts` daxilindəki canlı kataloq yükləyicisindən gəlir; kataloq dəyişikliyinin CI nəticəsi `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict` bölməsində göstərilib). Generatoru və SVG-ni birlikdə kommit edin.
- **Sübut.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` faylı yerli sınaqda təsvir edir (`<img>` teqi, məhdudlaşdırıcı `Content-Security-Policy` və `image/svg+xml` cavabı), açıq və tünd bir kadr çəkir və səhifənin xarici şrift sorğularını bildirir; onların sayı 0 olmalıdır.

- **Ölçü limiti.** Hər fayl 200 KB-dan kiçik olmalıdır (hər köhnəlmə testi bunu yoxlayır); 500 KB istənilən README təsviri üçün sərt yuxarı həddir (SVG studio validatorunun qaydası).
- **Ortaq mətn, saylar gate-dən.** hər bir generator öz diaqramının surətini `*_COPY` sabitində daşıyır (yaxud onu canlı kataloqdan qurur), bu həm çəkilmiş mətn, həm də kontur addımının daxil edilməsidir. Kanonik fiqurlar `<text>` qovşaqlarında qalır (bir dəfə qeyd olunduqdan sonra görünməz, `fill-opacity:0`), `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) tərəfindən oxunur; qapının oxuduğu diaqramların köhnəlmə testləri də yaradılan faylda öz təsdiqləyicilərini işə salır, buna görə də koddan kənara çıxan rəqəm testdən keçmir — qapının oxuduğu mənbəni düzəldir, generatordakı nömrəni heç vaxt.
