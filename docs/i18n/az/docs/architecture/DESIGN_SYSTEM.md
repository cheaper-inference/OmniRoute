## 1. Əşyaların yaşadığı yer

- **Kit.** `packages/ui-kit/src` `packages/ui-kit/UPSTREAM.md` bərkidilmiş icraatda yuxarı axın `src/` -nin bayt-bayt surətidir (o, həmçinin lisenziya icazəsini qeyd edir); `PATCHES.md` yerli yamaları siyahıya alır (heç biri). O, heç bir quruluş olmadan mənbə kimi istehlak olunur: `next.config.mjs` onu köçürür və `tsconfig.json` xəritələri `@omniroute/ui-kit` → `packages/ui-kit/src` və `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` (`vitest.config.ts` və `vitest.mcp.config.ts` eyni ləqəbi daşıyır). Kit komponentini heç vaxt `@omniroute/ui-kit` çəlləkindən keçməyərək, alt yolu (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) ilə idxal edin: barel hər bir komponenti (tarix seçici daxil olmaqla) hər bir idxalçıya çəkir. Dəstin üslub cədvəli `src/app/globals.css` vasitəsilə daxil olur (`@import "../../packages/ui-kit/src/ci-styles.css"`, tam vərəq: əsas `ci-ui.css` plus hər model ailəsi).
- **Tokenlər.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` tokenlərini elan edir; `src/app/globals.css` onları köhnə OmniRoute adlarına (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) körpü edir, buna görə də mövcud `var(--color-*)` oxuyur və Tailwind utilitləri işləməyə davam edir. Yeni kod Tailwind utilitlərindən (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) və ya dəst siniflərindən — heç vaxt hex dəyərindən istifadə edir (`tests/unit/design-kit-bridge.test.ts` körpünü tətbiq edir). `text-primary` `--text-color-primary` vasitəsilə `--color-primary-ink` -ə həll edir, buna görə də `bg-primary`/`border-primary` vurğu səthini saxlayarkən əsas mətn oxunaqlı qalır: Nəşrlər altında bu dəstin `--ci-color-accent-active` dir (işıqda dərin mis `#99562f`, qaranlıqda mis vurğu); Klassik altında, işıqda lime-800 və qaranlıqda əhəng vurğusu. Diaqram seriyası `--color-chart-1` … `--color-chart-8` istifadə edir, hər biri mətn üçün təhlükəsiz `--color-chart-N-ink` və qeyri-şəffaf `--color-chart-N-subtle` çip rəngi ilə dəst seriyası sırası ilə təyin olunur (`ciChartSeriesOrder`).
- **Mövzular.** `<html className="ci-theme ci-scrollbars">` (`src/app/layout.tsx`) sənədi dəst mövzusuna və dəstin sürüşdürmə çubuqlarına daxil edir (`--ci-scrollbar-*` nişanları; `globals.css` özünəməxsus sürüşmə çubuğu qaydası yoxdur və element Chromium və Safari-də dəstin üslubunu aşağı salacaq `scrollbar-width` və ya `scrollbar-color` təyin etməməlidir; `tests/unit/design-kit-bridge.test.ts` hər ikisini qoruyur). Üstünlük `light`, `dark` və ya `system` (`THEME_CONFIG.defaultTheme = "system"` -də `src/shared/constants/appConfig.ts`; `system` `prefers-color-scheme` izləyir). `src/store/themeStore.ts` -də `applyTheme()` ( `THEME_BOOT_SCRIPT` ilə əks olunur, nəmlənmədən əvvəl işləyən `src/app/layout.tsx` ilə daxil edilir) `data-theme="dark"|"light"` təyin edir və `<html>` -da `.dark` sinfini birlikdə dəyişdirir. Kitin tünd işarə dəsti `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`) ilə bağlıdır; OmniRoute-in öz qaranlıq ləğvetmələri ( `globals.css` dəki `.dark` bloku) və `.dark` sinfində köhnə Tailwind `dark:` utilitləri açarı. Vurğu rənginin ilkin təyinləri yoxdur: vurğu həmişə dəstdən gəlir və mağaza yükləndikdə köhnə quruluşdan davamlı əvvəlcədən qurulur.
- **Palitralar.** İki, hər ikisi dəstdən (`src/shared/constants/appearancePalette.ts`): `editions`, default və `classic`. Nəşrlər dəstin `<html>` üzərindəki `data-ci-appearance="editions"` atributudur və `ci-editions.css` ( `ci-ui.css` tərəfindən idxal olunur) `data-theme` ilə birləşir; Klassik atributun yoxluğudur. Kök layout server-atributu göstərir, beləliklə, heç nə saxlanmayan (və ya JS olmayan) ziyarətçi hər bir səthdə — tablosunda, girişdə, `/status`, səhv səhifələrində, `/docs` və PWA də Nəşrlər əldə edir. Seçim eyni `theme` mağazasındakı mövzunun yanında saxlanılır ( `src/store/themeStore.ts`-da `palette`, `setPalette()`, `applyPalette()` ) və `THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`, tərtibatın `<head>` na daxil edilmiş) ilə rənglənmədən əvvəl tətbiq edilir, bu atributu yalnız saxlanılan palitra `"classic"` olduqda silir; `src/app/global-error.tsx`, kök düzümü xaricində onu eyni mağazadan tətbiq edir. Heç bir başqa elementə `data-ci-appearance` qoymayın: dəst ona `html:root:has([data-ci-appearance="editions"])` ilə uyğun gəlir, ona görə də bir nəsil bütün sənədi dəyişəcək. Editions `data-ci-editions-variant="landing"` variantı idarə paneli üçün deyil, marketinq səhifələri üçündür. Brauzer xromu: server standart Nəşrləri `viewport.themeColor` (hər `prefers-color-scheme` üçün bir teq) və veb manifest — `PWA_THEME_COLORS` `src/shared/constants/pwaThemeColors.ts`-də, `tests/unit/pwa-theme-colors.test.ts` tərəfindən `ci-editions.css` -ə bərkidilmiş Nəşrlərin bir güzgüsü `--ci-color-background` (`#f3f1e9` / `#11120f`) təqdim edir. Canlı `<meta name="theme-color">` daha sonra saxlanılan palitraya və rejimi izləyir: `THEME_BOOT_SCRIPT` boyadan əvvəl teqləri yenidən yazır və mövzu mağazasının hərəkətləri bunu hər dəyişiklikdə edir (`resolveThemeColor()` / `applyThemeColor()` `src/shared/utils/themeColorMeta.ts`-da, `CLASSIC_PAGE_BACKGROUND` dəstin `ciTokens`-dan oxunması ilə). Açıq light/dark mövzusu hər bir teqi həmin rejimə qoyur; `system` hər sxem üçün bir rəng saxlayır. Manifest Nəşrlər olaraq qalır: üstünlük verilmədən hər quraşdırmada bir dəfə alınır. Monako öz rənglərini zonddan oxuyur (`monacoKitTheme.ts`); Nəşrlər altında zond oxunuşu bir sinxron keçid üçün `data-theme` kökünü çevirir, çünki dəst Nəşrlər light/dark kökdən həll edir.
- **Komponentlər (adapterlər).** `src/shared/components/index.tsx` OmniRoute komponentini API (eyni adlar, defolt ixraclar və rekvizitlər) saxlayır və onun arxasındakı primitivlər dəst üzərindəki adapterlərdir: formalar (`Button`, `Input` `Loading` `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`),`Modal`/ əks `ConfirmModal` `Tooltip`,`InfoTooltip`, `NotificationToast`, `EmptyState`), struktur (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) və cədvəllər (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). Adapter dəst komponentini alt yol ilə idxal edir və köhnə rekvizitləri onun üzərinə qoyur — məsələn `Button variant="primary"` dəsti `default` düyməsidir (`--ci-button-primary-*`: işıqda tərs səth, qaranlıqda `--ci-color-accent-foreground` mürəkkəbi ilə vurğu), `danger` `destructive` `warning` `warning` kit düyməsidir. `Badge` status variantları dəst tonlarıdır və `<option>` uşaqları olan `Select` dəsti `NativeSelect` göstərir. Bir adapter indeksdən deyil, marşrutla idxal olunur: `CodePreview` (`src/shared/components/CodePreview.tsx`), kopiya etiketləri tərcümə edilmiş dəst kod bloku. Tıklana bilən cədvəl sırasının adapteri yoxdur: bu, `onActivate` və `selected` olan `TableRow` dəstidir. `tests/unit/ui/adapters/*.test.tsx` pin hər adapter.
- **Shell.** `src/app/(dashboard)/layout.tsx` qabığı `KitLabelsProvider` də (hər ekran üçün bir dəfə təyin olunan mətnlər dəsti: cədvəlin davamlı sürüşdürmə çubuğunu adlandıran tərcümə edilmiş cümlə) bükən `DashboardLayout` göstərir və `src/shared/components/layouts/DashboardShell.tsx` göstərir: `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), naviqasiya girişi ilə OmniRoute' `src/shared/components/Sidebar.tsx`. `#main-content` a "məzmuna keçmək" bağlantısı diqqəti cəlb edən ilk elementdir. `src/shared/components/Header.tsx` dəsti `SidebarTrigger` (qabığın yeganə yan panel keçidi), Keak `ProductSwitcher` və komanda palitrası açıcısını saxlayır; o, yalnız `#main-content` daxilində heç bir `PageHeader` (`.ci-page-header`) dəsti quraşdırılmadıqda marşrutun başlığını göstərir, ona görə də öz `PageHeader` olan səhifədə tək `h1` olur. `src/shared/components/CommandPalette.tsx` `Dialog` dəstidir.
- **Nişanlar.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) adı (ekranların istifadə etdiyi Material Simvol lüğəti) `ICON_MAP` (`src/shared/constants/iconMap.ts`) vasitəsilə Lucide qlifinə həll edir. Material Symbols şrifti və paketi yox oldu: xəritədə olmayan ad neytral yertutan qlifi (`data-icon-missing="true"`) göstərir və istehsaldan kənar konsol xəbərdarlığını qeyd edir. `npm run gen:icon-map` xəritədə əskik olan istifadə olunan adları çap edir (`tests/unit/icon-map-coverage.test.ts` Lucide işarəsi olmayan hər hansı adda uğursuz olur; `tests/unit/icon-map-object-values.test.ts` axtarış obyektlərində saxlanılan adları əhatə edir); `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` hərfi `<span className="material-symbols-outlined">` spanlarını `<Icon>`-a yenidən yazır.
- **Brend.** `src/shared/components/OmniRouteLogo.tsx` dəsti əhatə edir: defolt ixrac `OmniRouteLogo` `ProductIcon product="omniroute" variant="glyph"` (daxili SVG, `basePath` -safe) və `OmniRouteLockup` `ProductLockup product="omniroute"` (əlçatan ad "Keak OmniRoute") və ya ağ etiketli operatorlar üçün öz `name`/`logoSrc` göstərir. Məhsul dəyişdirici təyinatları `src/shared/constants/keakProducts.ts` -də yaşayır (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`). Müstəqil ekranlar — `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` və `src/shared/components/ErrorPageScaffold.tsx` — kilidləməni göstərir; `tests/unit/brand-pages-static.test.ts` onu qoruyur.

## 2. Qaydalar

1. Tokens, heç vaxt hərfi deyil. İstisnalar məqsədyönlü şəkildə saxlanılır: həmişə qaranlıq olan konsol terminalı və `STATUS_HEX` (`src/shared/constants/statusColors.ts`), hərfi hex ehtiyacı olan zəng edənlər üçün kit status palitrasının həll edilmiş hex güzgüsü. Kateqoriyalı palitralar artıq istisna deyil: onlar dəstin səkkiz diaqram nişanı (`--color-chart-1..8`, plus `-ink`/`-subtle`), `src/shared/utils/categoricalPalette.ts` vasitəsilə dəstin seriyası sırası ilə və marşrutlaşdırma strategiyaları üçün `src/app/(dashboard)/dashboard/combos/strategyPalette.ts`; ReactFlow kənarları və orkestrasiya kətan mövzudan xəbərdar olan `--orch-status-*` dəyişənlərini (`src/shared/components/flow/edgeStyles.ts`) oxuyur.
2. Heç vaxt `packages/ui-kit/src` əl ilə yamaq etməyin: `scripts/dev/sync-ui-kit.sh <commit>` ilə sinxronizasiya edin; əvvəlcədən icra qapısı `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) bərkidilmiş yuxarı commitdən fərqlənən hər hansı baytda uğursuz olur (yuxarı axın klonu, `UI_KIT_CLONE` və ya `_references/cheaper-inference-ui-kit` olmadıqda, xəbərdarlıqla ötürülür). Kitdə bir şey çatışmırsa, adapterdə və ya ekranda onun ətrafında işləyin və onu yuxarıdan soruşun.
3. Kit mətninin defoltları ingiliscədir (`label = "Loading"`, `loadingLabel = "Loading table"`…) — kit komponenti mətni hər dəfə təqdim etdikdə `useTranslations(...)` dən tərcümə edilmiş sətirləri keçir.
4. Tailwind utilitləri dəst komponent sinifləri üzərində qalib gəlir (kit `@layer theme, base, components, utilities` elan edir və onun qaydaları `components`-də yaşayır) — dəst komponentlərini yenidən rəngləndirmək üçün deyil, boşluqlar və yerləşdirmə üçün utilitlərdən istifadə edir. Tipoqrafiya istisnadır: `packages/ui-kit/src/ci-typography.css` istənilən təbəqədən kənara idxal edilir, ona görə də onun etiketi defolt olaraq utilitləri döyür. Çəki, `tracking-*` və `leading-*` siniflərinin `h1`-a heç bir təsiri yoxdur –`h6`, çəki və `tracking-*` cədvəl xanalarında, çəki isə düymələrdə yoxdur (`tests/unit/dead-typography-classes.test.ts` onları orada rədd edir); `font-mono` `th`, `td`, `button`, `input` və `textarea` üzərində heç bir təsiri yoxdur . Ölçü, rəng və `uppercase` utilitləri hələ də tətbiq olunur. Defolt teqlərin iki çıxışı var və heç biri utiliti çəki və ya izləmə təyin etmək üsuluna çevirmir:
   - Kit tipli sinif daşıyan element teq standartları tərəfindən atlanır, beləliklə sinif istənilən teqdə eyni oxuyur. Rol sinifləri (`type-heading`, `type-body`, `type-reading`, `type-control`, `type-data`, `type-caption`) da qatsızdır, ona görə də kommunal xidmətlər hələ də onların yanında itirirlər. `ci-eyebrow` bir `components` qaydasıdır: `<h3 className="ci-eyebrow">` indi qaş tipini alır və onun üzərində faydalı proqram tətbiq olunur (mühafizəçi onu işarələmir), lakin qaşın öz `data-size` və `data-weight` üstünlük verir. `ci-heading` çıxış deyil: defolt başlıq hələ də tətbiq olunur.

## 4. Adapter əlavə etmək və ya dəyişdirmək

1. `src/shared/components/index.tsx` faylının publik API-sini saxlayın: eyni export adları, default export-lar və qəbul edilən prop-lar. Köhnə prop-ları adapter daxilində kit-ə uyğunlaşdırın (bax: `Button.tsx`: `VARIANT_TO_KIT`, `SIZE_TO_KIT`).
2. Kit-i subpath ilə import edin (`@omniroute/ui-kit/<component>`).
3. Kit boşluqları üçün müvəqqəti həllər adapter-də (və ya düzəliş stil olduqda `globals.css` faylında `@layer components` içərisində) yerləşir, heç vaxt `packages/ui-kit/src`-də yox.

## 5. Kitin yenilənməsi

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` də bərkidilmiş versiyanı yuxarı repo-nun ən yeni `v*` teqi ilə müqayisə edir və buraxılış bitdikdə sinxronizasiya əmrini çap edir.

Gündəlik `UI Kit upstream watch` iş axını (`.github/workflows/ui-kit-upstream-watch.yml`) eyni yoxlamanı həyata keçirir. Sancaq arxada olarkən, `scripts/ci/ui-kit-sync-pr.sh` `chore/ui-kit-sync-latest` yuvarlanan budaqda ən yüksək `release/vX.Y.Z` budağına qarşı bir sinxronizasiya PR açıq saxlayır. O, heç vaxt birləşmir: hər dəst buraxılışı hələ də yerli VPS üzərində vizual yoxlamaya ehtiyac duyur. Daha yeni buraxılış çıxdıqda filial yenidən qurulur və əks halda tək qalır. Əl ilə itələnən açıq PR üzərinə yazılmır və qoruyucunun bağlandığı, birləşdirilməmiş versiya üçün PR daha yeni buraxılışa qədər bağlı qalır.

Heç bir PR açılmadıqda (hədəf buraxılış dondurulduqda, PR əl ilə itələdi, PR bağlandı və ya heç bir PR nişanı təyin olunmadı) iş axını səbəbini bildirən bir izləmə məsələsini açıq saxlayır.

İş prosesi iki sirrdən istifadə edir:

- `secrets.UI_KIT_READ_TOKEN`: şəxsi yuxarı repo üçün yalnız oxuna bilən işarədir. İş axını yuxarı axını oxuya bilmədikdə (token yoxdur, işləməyi dayandıran işarə və ya GitHub əlçatmazdır) qaçış yaşıl qalır, lakin xəbərdarlıq yazır və bir ayrı məsələni açıq saxlayır, bu da sonrakı qaçış yuxarı axını təkrar oxuya bildikdə özünü bağlayır.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: Məzmun və Çəkmə sorğuları yazma girişi olan bu depoda incə dənəli işarədir. Defolt `GITHUB_TOKEN` burada PRs yarada bilməz və onun açdığı PR CI işə salmaz. Bu işarə olmadan iş axını yalnız filialı itələyir.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` həmin öhdəçilikdə yuxarı axın `src/` (`latest` = ən yeni `v*` teq) `packages/ui-kit/src`-ə kopyalayır, tək icazə verilən transformasiyanı tətbiq edir (nisbi idxaldan `.js` şəkilçisini çıxarır) və iş sahəsinin `packages/ui-kit/package.json` və `package-lock.json` versiyasını yuxarı axına təyin edir. Sonra: `git diff packages/ui-kit` nəzərdən keçirin, hər iki mövzuda provayderlər, parametrlər, kombinasiyalar, istifadə və son nöqtə haqqında vizual keçid edin, `npm run check:ui-kit-snapshot` və `npm run test:vitest:ui` işə salın və yuxarı axın dəyişiklik jurnalı ilə PR açın.

## 6. README diaqramları

Kök `README.md` faylının daxil etdiyi on iki diaqram (`docs/diagrams/*.svg`) statik təsvirə tətbiq olunan kitin nümunələridir və əl ilə çəkilmir: `scripts/docs/gen-readme-*.mjs` daxilindəki 13 generator faylı (on iki diaqram və `gen-readme-diagrams.mjs` drayveri) və diaqram başına bir olmaqla `tests/unit/docs/readme-*-svg.test.ts` daxilindəki 12 köhnəlmə testi commit edilmiş faylı generatorunun çıxışı ilə bayt-bayt müqayisə edir (`test-unit` işi).

- **Tokenlər.** `scripts/docs/readme-diagram-theme.mjs` Editions palitrasını (standart görünüşü) `packages/ui-kit/src/ci-editions.css` faylından köçürür (`tests/unit/docs/readme-diagram-theme.test.ts` həmin fayla uyğunluğu yoxlayır və hər iki sxemdə hər səthdəki bütün mətn rəngləri üçün WCAG AA uyğunluğunu da yoxlayır; yeganə istisna açıq rejimdəki `warn` rəngidir — kitin dəyəri kətanda 4.46:1 olduğuna görə 10 % tündləşdirilmiş kit xəbərdarlıq rəngidir) və kitin tip miqyasında (`ci-tokens.css`) mətn rollarını müəyyənləşdirir: bütün elementlər üçün kitin çəkilərində (400/500/600, display üçün 500) və hərflərarası intervalda Switzer, yalnız əmrlər, URL-lər, identifikatorlar və terminal ekranları üçün nəzərdə tutulan kod rolları (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`) üçün isə IBM Plex Mono.
  Açıq rejim dəyərləri faylın daxilində `:root` üzərində, tünd rejim dəyərləri isə `prefers-color-scheme: dark` arxasında yerləşir; beləliklə hər təsvir GitHub-da baxanın sxemini izləyir.
- **Şriftlər.** GitHub Markdown CSS daşımır və camo proksisi bütün xarici sorğuları bloklayır, buna görə kitin tip məlumatı faylın daxilində olmalıdır. Hər generatorun son addımı olan `scripts/docs/readme-outline.mjs`, Switzer rollarını HarfBuzz ilə formalaşdırır və onları vektor konturları (`<defs>` yolları və `<use>`) kimi çəkir; Switzer-də olmayan oxlar və həndəsi simvollar da öz metrikləri əsasında çəkilir. Daxil edilmiş şrift yox, konturlar: Switzer lisenziyası (`packages/ui-kit/src/fonts/FFL.txt`) yazılı razılıq olmadan alt çoxluq yaratmağı və format çevirməsini qadağan edir, vektor təsvirlərinə isə icazə verir; buna görə Switzer `@font-face` və ya `data:` URI-ni yenidən əlavə etməyin. Faylda qalan yeganə şrift real kod mətni olaraq saxlanılan hissə üçün OFL IBM Plex Mono alt çoxluğudur (`scripts/docs/readme-fonts.mjs`); daxil edə bilmədiyi hər hansı qlif xəta yaradır.
- **Yenidən yaradın.** `npm run docs:readme-diagrams` bütün on iki diaqramı README sırası ilə yenidən yazır və hər fayl üçün ölçüsü ilə birlikdə bir sətir çap edir. Ayrı-ayrı generator da müstəqil işlədilə bilər (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` canlı kataloq yükləyicisindən (`open-sse/config/freeModelCatalog.ts`) gəldiyi üçün `node --import tsx/esm` tələb edir; kataloq dəyişikliyinin CI nəticəsi `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict` bölməsində göstərilib). Generatoru və SVG-ni birlikdə commit edin.
  Release rejimində köhnəlmiş SVG xətaya səbəb olur; xüsusiyyət PR-ında `npm run check:generated-artifacts` yalnız PR-ın redaktə etdiyi SVG-ni qiymətləndirir (`docs/architecture/QUALITY_GATES.md` → "Generated files and derived baselines").
