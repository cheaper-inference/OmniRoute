## 1. Əşyalar harada yerləşir

- **Dəst.** `packages/ui-kit/src`, `packages/ui-kit/UPSTREAM.md` faylında sabitlənmiş kommitdəki yuxarı mənbənin
  `src/` qovluğunun bayt-bayt surətidir (həmin faylda lisenziya icazəsi də qeyd olunur); `PATCHES.md` yerli
  yamaqları sadalayır (heç biri yoxdur). O, yığma olmadan mənbə kimi istifadə edilir: `next.config.mjs` onu
  transpilasiya edir, `tsconfig.json` isə `@omniroute/ui-kit` → `packages/ui-kit/src` və `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` uyğunlaşdırmalarını müəyyənləşdirir (`vitest.config.ts` və `vitest.mcp.config.ts` eyni
  aliası daşıyır). Dəst komponentini həmişə öz alt yolundan (`@omniroute/ui-kit/table`,
  `@omniroute/ui-kit/page-header`…) idxal edin, heç vaxt `@omniroute/ui-kit` barrel ixracı vasitəsilə idxal
  etməyin: barrel hər komponenti (tarix seçici daxil olmaqla) hər idxalçıya daxil edir. Dəstin üslub cədvəli
  `src/app/globals.css` vasitəsilə daxil edilir
  (`@import "../../packages/ui-kit/src/ci-styles.css"`, tam cədvəl: əsas `ci-ui.css` və bütün nümunə ailələri).
- **Tokenlər.** `packages/ui-kit/src/ci-tokens.css`, `--ci-*` tokenlərini elan edir; `src/app/globals.css`
  onları köhnə OmniRoute adları ilə (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`) əlaqələndirir, beləliklə mövcud `var(--color-*)` oxunuşları
  və Tailwind utilitləri işləməyə davam edir. Yeni kod Tailwind utilitlərindən (`bg-surface`,
  `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) və ya dəst
  siniflərindən istifadə edir — heç vaxt hex dəyərindən istifadə etmir
  (`tests/unit/design-kit-bridge.test.ts` bu əlaqəni məcburi edir). `text-primary`,
  `--text-color-primary` vasitəsilə `--color-primary-ink` dəyərinə çevrilir, buna görə əsas mətn oxunaqlı
  qalır, `bg-primary`/`border-primary` isə vurğu səthini qoruyur: Editions rejimində bu, dəstin
  `--ci-color-accent-active` dəyəridir (işıqlı rejimdə tünd mis rəngli `#99562f`, qaranlıq rejimdə mis
  vurğu); Classic rejimində isə işıqlı rejimdə lime-800, qaranlıq rejimdə laym vurğudur. Diaqram sıraları
  `--color-chart-1` … `--color-chart-8` istifadə edir; hər birinin mətn üçün təhlükəsiz
  `--color-chart-N-ink` və qeyri-şəffaf `--color-chart-N-subtle` çip çaları var və bunlar dəstin sıra
  ardıcıllığına (`ciChartSeriesOrder`) uyğun təyin edilir.
- **Mövzular.** `<html className="ci-theme">` (`src/app/layout.tsx`) sənədi dəst mövzusuna qoşur.
  Seçim `light`, `dark` və ya `system` ola bilər (`src/shared/constants/appConfig.ts` daxilində
  `THEME_CONFIG.defaultTheme = "system"`; `system`, `prefers-color-scheme` parametrini izləyir).
  `src/store/themeStore.ts` daxilindəki `applyTheme()` (hidratasiya başlamazdan əvvəl işləyən və
  `src/app/layout.tsx` daxilində sətirdaxili yerləşdirilən `THEME_BOOT_SCRIPT` tərəfindən təkrarlanır)
  `data-theme="dark"|"light"` atributunu təyin edir və eyni anda `<html>` elementində `.dark` sinfini
  aktivləşdirir və ya deaktivləşdirir. Dəstin qaranlıq tokenlər dəsti `data-theme="dark"` əsasında seçilir
  (`packages/ui-kit/src/ci-tokens.css`); OmniRoute-un öz qaranlıq rejim əvəzləmələri (`globals.css`
  daxilindəki `.dark` bloku) və köhnə Tailwind `dark:` utilitləri `.dark` sinfinə əsaslanır. Vurğu rəngi
  üçün əvvəlcədən təyin edilmiş seçimlər yoxdur: vurğu həmişə dəstdən gəlir və köhnə yığmadan saxlanılmış
  seçim anbar yüklənərkən silinir.
- **Palitralar.** Hər ikisi dəstdən gələn iki palitra var (`src/shared/constants/appearancePalette.ts`):
  standart `editions` və `classic`. Editions, `<html>` elementində dəstin `data-ci-appearance="editions"`
  atributudur və `ci-editions.css` (`ci-ui.css` tərəfindən idxal olunur) onu `data-theme` ilə birləşdirir;
  Classic isə bu atributun olmamasıdır. Kök tərtibat atributu serverdə render edir, buna görə heç nə
  saxlamamış (və ya JS-i olmayan) ziyarətçi bütün səthlərdə — idarə panelində, giriş səhifəsində,
  `/status`, xəta səhifələrində, `/docs` və PWA-da — Editions əldə edir. Seçim mövzu ilə yanaşı eyni
  `theme` anbarında saxlanılır (`src/store/themeStore.ts` daxilində `palette`, `setPalette()`,
  `applyPalette()`) və tərtibatın `<head>` hissəsində sətirdaxili yerləşdirilən `THEME_BOOT_SCRIPT`
  (`src/shared/utils/themeBootScript.ts`) tərəfindən ilk rəngləmədən əvvəl tətbiq edilir; o, atributu
  yalnız saxlanmış palitra `"classic"` olduqda silir. Kök tərtibatdan kənarda olan
  `src/app/global-error.tsx` bunu eyni anbardan tətbiq edir. `data-ci-appearance` atributunu başqa heç bir
  elementə yerləşdirməyin: dəst onu `html:root:has([data-ci-appearance="editions"])` ilə uyğunlaşdırır,
  buna görə bir alt element bütün sənədi dəyişər. Editions üçün
  `data-ci-editions-variant="landing"` variantı idarə paneli üçün deyil, marketinq səhifələri üçündür.
  Brauzer xromu: server standart Editions dəyərini `viewport.themeColor` daxilində (hər
  `prefers-color-scheme` üçün bir teq) və veb manifestdə render edir —
  `src/shared/constants/pwaThemeColors.ts` daxilindəki `PWA_THEME_COLORS`, Editions
  `--ci-color-background` dəyərinin (`#f3f1e9` / `#11120f`) yeganə surətidir və
  `tests/unit/pwa-theme-colors.test.ts` tərəfindən `ci-editions.css` faylına sabitlənib. Bundan sonra
  canlı `<meta name="theme-color">` saxlanmış palitra və rejimi izləyir: `THEME_BOOT_SCRIPT` ilk
  rəngləmədən əvvəl teqləri yenidən yazır, mövzu anbarının əməliyyatları isə bunu hər dəyişiklikdə edir
  (`src/shared/utils/themeColorMeta.ts` daxilində `resolveThemeColor()` / `applyThemeColor()`; burada
  `CLASSIC_PAGE_BACKGROUND` dəstin `ciTokens` dəyərindən oxunur). Açıq şəkildə seçilmiş işıqlı/qaranlıq
  mövzu bütün teqləri həmin rejimə təyin edir; `system` isə hər sxem üçün bir rəng saxlayır. Manifest
  Editions olaraq qalır: o, seçim olmadan hər quraşdırma üçün bir dəfə əldə edilir. Monaco rənglərini
  sınaq elementindən oxuyur (`monacoKitTheme.ts`); Editions rejimində sınaq oxunuşu bir sinxron keçid
  üçün kök `data-theme` dəyərini dəyişir, çünki dəst Editions işıqlı/qaranlıq rejimini kök elementdən
  müəyyənləşdirir.
- **Komponentlər (adapterlər).** `src/shared/components/index.tsx` OmniRoute komponent API-sini (eyni
  adlar, standart ixraclar və proplar) qoruyur və onun arxasındakı primitivlər dəst üzərində qurulmuş
  adapterlərdir: formalar (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`),
  üst qatlar və geribildirim (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`,
  `EmptyState`, `Loading`), struktur (`Collapsible`, `CollapsibleSection`, `SegmentedControl`,
  `Breadcrumbs`, `Avatar`) və cədvəllər (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`,
  `PresetSlider`). Adapter dəst komponentini alt yolundan idxal edir və köhnə propları ona uyğunlaşdırır
  — məsələn, `Button variant="primary"` dəstin `default` düyməsidir (`--ci-button-primary-*`: işıqlı
  rejimdə əks səth, qaranlıq rejimdə isə öz `--ci-color-accent-foreground` mətn rənginə malik vurğu),
  `danger` dəyəri `destructive`, `warning` isə dəstin `warning` düyməsidir. `Badge` status variantları
  dəstin tonlarıdır və `<option>` alt elementləri olan `Select`, dəstin `NativeSelect` komponentini
  render edir.
  İki adapter indeksdən deyil, yol ilə idxal edilir: `InteractiveTableRow`
  (`src/shared/components/InteractiveTableRow.tsx`) — `onActivate` və `selected` qəbul edən, Tab, Enter
  və Space düymələrinə cavab verən dəst `TableRow` komponenti — və `CodePreview`
  (`src/shared/components/CodePreview.tsx`) — köçürmə etiketləri tərcümə edilmiş dəst kod bloku.
  `tests/unit/ui/adapters/*.test.tsx` hər adapteri sabitləyir.
- **Shell.** `src/app/(dashboard)/layout.tsx` `DashboardLayout`-u render edir, o isə `src/shared/components/layouts/DashboardShell.tsx` faylını render edir: `packages/ui-kit/src/sidebar.tsx` daxilindəki kit `SidebarProvider` / `Sidebar` /
  `SidebarInset`; OmniRoute-un naviqasiya məntiqi isə `src/shared/components/Sidebar.tsx` faylındadır. `#main-content`-ə keçid verən “məzmun bölməsinə keç” linki fokuslana bilən ilk elementdir. `src/shared/components/Header.tsx` kit `SidebarTrigger`-ı (shell-in yeganə sidebar keçidi), Keak `ProductSwitcher`-ını və komanda palitrasını açan düyməni ehtiva edir; o, marşrut başlığını yalnız `#main-content` daxilində heç bir kit `PageHeader` (`.ci-page-header`) mount edilmədikdə göstərir, buna görə öz `PageHeader`-ına malik səhifədə yalnız bir `h1` olur. `src/shared/components/CommandPalette.tsx` kit `Dialog`-udur.
- **İkonlar.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) adı `ICON_MAP` (`src/shared/constants/iconMap.ts`) vasitəsilə ekranların istifadə etdiyi Material Symbols lüğətindən götürərək Lucide qlifinə uyğunlaşdırır. Material Symbols şrifti və paketi artıq mövcud deyil: xəritədə olmayan ad neytral əvəzedici qlif (`data-icon-missing="true"`) göstərir və production mühiti xaricində konsola xəbərdarlıq yazır. `npm run gen:icon-map` xəritədə çatışmayan və istifadədə olan adları çap edir (`tests/unit/icon-map-coverage.test.ts` Lucide ikonu olmayan istənilən adda uğursuz olur; `tests/unit/icon-map-object-values.test.ts` axtarış obyektlərində saxlanılan adları yoxlayır); `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` literal `<span className="material-symbols-outlined">` elementlərini `<Icon>` elementlərinə yenidən yazır.
- **Brend.** `src/shared/components/OmniRouteLogo.tsx` kit-i əhatə edir: standart export `OmniRouteLogo` `ProductIcon product="omniroute" variant="glyph"` (inline SVG, `basePath`-ə təhlükəsiz) render edir, `OmniRouteLockup` isə `ProductLockup product="omniroute"` (əlçatan adı “Keak OmniRoute”) və ya white-label operatorları üçün onların öz `name`/`logoSrc` dəyərlərini render edir. Məhsul dəyişdiricisinin təyinatları `src/shared/constants/keakProducts.ts` faylında (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`) yerləşir. Müstəqil ekranlar — `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` və `src/shared/components/ErrorPageScaffold.tsx` — lockup-ı göstərir; `tests/unit/brand-pages-static.test.ts` bunu qoruyur.

## 2. Qaydalar

1. Heç vaxt literal dəyərlərdən deyil, tokenlərdən istifadə edin. Qəsdən saxlanılan istisnalar: həmişə tünd olan konsol terminalı və
   `STATUS_HEX` (`src/shared/constants/statusColors.ts`), literal hex dəyərinə ehtiyacı olan çağıranlar üçün kit status
   palitrasının həll edilmiş hex əksi. Kateqorik palitralar artıq istisna deyil:
   onlar kit-in səkkiz diaqram tokenindən (`--color-chart-1..8`, həmçinin `-ink`/`-subtle`), kit seriyalarının sırası ilə,
   `src/shared/utils/categoricalPalette.ts` və marşrutlaşdırma strategiyaları üçün
   `src/app/(dashboard)/dashboard/combos/strategyPalette.ts` vasitəsilə istifadə edir; ReactFlow kənarları və orkestrasiya
   kətanı mövzuya uyğun `--orch-status-*` dəyişənlərini oxuyur (`src/shared/components/flow/edgeStyles.ts`).
2. `packages/ui-kit/src` qovluğuna heç vaxt əl ilə düzəliş etməyin: `scripts/dev/sync-ui-kit.sh <commit>` ilə sinxronlaşdırın; `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) pre-commit yoxlaması sabitlənmiş upstream commit-dən fərqlənən istənilən baytda uğursuz olur (upstream klonu,
   `UI_KIT_CLONE` və ya `_references/cheaper-inference-ui-kit` olmadıqda xəbərdarlıqla ötürülür). Kit-də nəsə yoxdursa,
   bunu adapter və ya ekran səviyyəsində həll edin və upstream-dən əlavə edilməsini istəyin.
3. Kit mətnlərinin defolt dəyərləri ingiliscədir (`label = "Loading"`, `loadingLabel = "Loading table"`…) — kit komponenti mətn göstərdikdə `useTranslations(...)`-dən tərcümə edilmiş sətirləri ötürün.
4. Tailwind utility-ləri kit komponentlərinin siniflərindən üstündür (`kit`, `@layer theme, base, components, utilities` elan edir və qaydaları `components` daxilində yerləşir) — aralıq və yerləşdirmə üçün utility-lərdən istifadə edin, kit komponentlərinin rəngini dəyişmək üçün yox. Tipoqrafiya istisnadır:
   `packages/ui-kit/src/ci-typography.css` hər hansı layer xaricində import edilir, buna görə onun teq qaydaları utility-lərdən üstündür. `h1`–`h6` elementlərində çəki, `tracking-*` və `leading-*` siniflərinin heç bir təsiri yoxdur, cədvəl xanalarında çəki və `tracking-*` siniflərinin, düymələrdə isə çəki sinfinin təsiri yoxdur
   (`tests/unit/dead-typography-classes.test.ts` bunları həmin yerlərdə rədd edir); `font-mono`-nun
   `th`, `td`, `button`, `input` və `textarea` üzərində təsiri yoxdur. Ölçü, rəng və `uppercase` utility-ləri isə tətbiq olunur.

## 5. Kitin yenilənməsi

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` də bərkidilmiş versiyanı yuxarı repo-nun ən yeni `v*` teqi ilə müqayisə edir və buraxılış bitdikdə sinxronizasiya əmrini çap edir.

Gündəlik `UI Kit upstream watch` iş axını (`.github/workflows/ui-kit-upstream-watch.yml`) eyni yoxlamanı həyata keçirir. Sancaq arxada olarkən, `scripts/ci/ui-kit-sync-pr.sh` `chore/ui-kit-sync-latest` yuvarlanan budaqda ən yüksək `release/vX.Y.Z` budağına qarşı bir sinxronizasiya PR açıq saxlayır. O, heç vaxt birləşmir: hər dəst buraxılışı hələ də yerli VPS üzərində vizual yoxlamaya ehtiyac duyur. Daha yeni buraxılış çıxdıqda filial yenidən qurulur və əks halda tək qalır. Əl ilə itələnən açıq PR üzərinə yazılmır və qoruyucunun bağlandığı, birləşdirilməmiş versiya üçün PR daha yeni buraxılışa qədər bağlı qalır.

Heç bir PR açılmadıqda (hədəf buraxılış dondurulduqda, PR əl ilə itələdi, PR bağlandı və ya heç bir PR nişanı təyin olunmadı) iş axını səbəbini bildirən bir izləmə məsələsini açıq saxlayır.

İş prosesi iki sirrdən istifadə edir:

- `secrets.UI_KIT_READ_TOKEN`: şəxsi yuxarı repo üçün yalnız oxuna bilən işarədir. İş axını yuxarı axını oxuya bilmədikdə (token yoxdur, işləməyi dayandıran işarə və ya GitHub əlçatmazdır) qaçış yaşıl qalır, lakin xəbərdarlıq yazır və bir ayrı məsələni açıq saxlayır, bu da sonrakı qaçış yuxarı axını təkrar oxuya bildikdə özünü bağlayır.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: Məzmun və Çəkmə sorğuları yazma girişi olan bu depoda incə dənəli işarədir. Defolt `GITHUB_TOKEN` burada PRs yarada bilməz və onun açdığı PR CI işə salmaz. Bu işarə olmadan iş axını yalnız filialı itələyir.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` həmin öhdəçilikdə yuxarı axın `src/` (`latest` = ən yeni `v*` teq) `packages/ui-kit/src`-ə kopyalayır, tək icazə verilən transformasiyanı tətbiq edir (nisbi idxaldan `.js` şəkilçisini çıxarır) və iş sahəsinin `packages/ui-kit/package.json` və `package-lock.json` versiyasını yuxarı axına təyin edir. Sonra: `git diff packages/ui-kit` nəzərdən keçirin, hər iki mövzuda provayderlər, parametrlər, kombinasiyalar, istifadə və son nöqtə haqqında vizual keçid edin, `npm run check:ui-kit-snapshot` və `npm run test:vitest:ui` işə salın və yuxarı axın dəyişiklik jurnalı ilə PR açın.

## 6. README diaqramları

Kök `README.md` faylının daxil etdiyi on iki diaqram (`docs/diagrams/*.svg`) statik təsvirə tətbiq olunan kitin nümunələridir və əl ilə çəkilmir: `scripts/docs/gen-readme-*.mjs` daxilindəki 13 generator faylı (on iki diaqram və `gen-readme-diagrams.mjs` drayveri) və diaqram başına bir olmaqla `tests/unit/docs/readme-*-svg.test.ts` daxilindəki 12 köhnəlmə testi commit edilmiş faylı generatorunun çıxışı ilə bayt-bayt müqayisə edir (`test-unit` işi).

- **Tokenlər.** `scripts/docs/readme-diagram-theme.mjs` Editions palitrasını (standart görünüşü) `packages/ui-kit/src/ci-editions.css` faylından köçürür (`tests/unit/docs/readme-diagram-theme.test.ts` həmin fayla uyğunluğu yoxlayır və hər iki sxemdə hər səthdəki bütün mətn rəngləri üçün WCAG AA uyğunluğunu da yoxlayır; yeganə istisna açıq rejimdəki `warn` rəngidir — kitin dəyəri kətanda 4.46:1 olduğuna görə 10 % tündləşdirilmiş kit xəbərdarlıq rəngidir) və kitin tip miqyasında (`ci-tokens.css`) mətn rollarını müəyyənləşdirir: bütün elementlər üçün kitin çəkilərində (400/500/600, display üçün 500) və hərflərarası intervalda Switzer, yalnız əmrlər, URL-lər, identifikatorlar və terminal ekranları üçün nəzərdə tutulan kod rolları (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`) üçün isə IBM Plex Mono.
  Açıq rejim dəyərləri faylın daxilində `:root` üzərində, tünd rejim dəyərləri isə `prefers-color-scheme: dark` arxasında yerləşir; beləliklə hər təsvir GitHub-da baxanın sxemini izləyir.
- **Şriftlər.** GitHub Markdown CSS daşımır və camo proksisi bütün xarici sorğuları bloklayır, buna görə kitin tip məlumatı faylın daxilində olmalıdır. Hər generatorun son addımı olan `scripts/docs/readme-outline.mjs`, Switzer rollarını HarfBuzz ilə formalaşdırır və onları vektor konturları (`<defs>` yolları və `<use>`) kimi çəkir; Switzer-də olmayan oxlar və həndəsi simvollar da öz metrikləri əsasında çəkilir. Daxil edilmiş şrift yox, konturlar: Switzer lisenziyası (`packages/ui-kit/src/fonts/FFL.txt`) yazılı razılıq olmadan alt çoxluq yaratmağı və format çevirməsini qadağan edir, vektor təsvirlərinə isə icazə verir; buna görə Switzer `@font-face` və ya `data:` URI-ni yenidən əlavə etməyin. Faylda qalan yeganə şrift real kod mətni olaraq saxlanılan hissə üçün OFL IBM Plex Mono alt çoxluğudur (`scripts/docs/readme-fonts.mjs`); daxil edə bilmədiyi hər hansı qlif xəta yaradır.
- **Yenidən yaradın.** `npm run docs:readme-diagrams` bütün on iki diaqramı README sırası ilə yenidən yazır və hər fayl üçün ölçüsü ilə birlikdə bir sətir çap edir. Ayrı-ayrı generator da müstəqil işlədilə bilər (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` canlı kataloq yükləyicisindən (`open-sse/config/freeModelCatalog.ts`) gəldiyi üçün `node --import tsx/esm` tələb edir; kataloq dəyişikliyinin CI nəticəsi `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict` bölməsində göstərilib). Generatoru və SVG-ni birlikdə commit edin.
  Release rejimində köhnəlmiş SVG xətaya səbəb olur; xüsusiyyət PR-ında `npm run check:generated-artifacts` yalnız PR-ın redaktə etdiyi SVG-ni qiymətləndirir (`docs/architecture/QUALITY_GATES.md` → "Generated files and derived baselines").
- **Yoxlama.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` faylı GitHub-un onu təqdim etdiyi şəkildə (`<img>` teqi, camo-nun `Content-Security-Policy` siyasəti, `image/svg+xml`) render edir, açıq və tünd kadrları çəkir və səhifənin etdiyi xarici şrift sorğularını bildirir (sayı 0 olmalıdır).
- **Büdcə.** Hər fayl üçün 200 KB-dan az (hər köhnəlmə testi bunu təsdiqləyir); 500 KB istənilən README təsviri üçün sərt həddir (SVG studio validatorunun qaydası).
- **Dəyişmədən köçürün, sayları qapıdan götürün.** Rebrend sözləri deyil, tipi və palitranı dəyişdi: hər generator diaqramının mətnini həm çəkilən mətn, həm də konturlaşdırma addımının girişi olan `*_COPY` sabitində saxlayır (və ya onu canlı kataloqdan qurur). Kanonik göstəricilər `<text>` qovşaqlarında saxlanılır (konturlaşdırıldıqdan sonra görünməz olur, `fill-opacity:0`) və `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) tərəfindən oxunur; qapı oxunuşlarını həyata keçirən diaqramların köhnəlmə testləri yaradılmış faylda onun validatorlarını da işlədir, buna görə koddan uzaqlaşan göstərici testi uğursuz edir — generatordakı rəqəmi heç vaxt düzəltməyin, qapının oxuduğu mənbəni düzəldin.
