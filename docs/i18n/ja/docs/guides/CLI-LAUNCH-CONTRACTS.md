中立`config/cli-tools-manifest.json`コントラクトは、正規のIDs、エイリアス、バイナリ候補、セットアップ レシピ、モデルの引数および機能を宣言します。 `bin/cli/cli-manifest.mjs`のプレーン ノード アダプタと`src/shared/constants/cliIntegrationManifest.ts`のTypeScriptアダプタは同じファイルを読み取ります。ランタイム、カタログ、構成、完了、ジェネレーター、およびバックエンドの登録は、 `tests/unit/cli/cli-manifest-drift.test.ts`によって一緒にチェックされます。カタログ化されたからといって、ツールを起動したり構成したりできるわけではありません。特に、5dive は設定のみのままです。

## 子どもの環境とライフサイクル

`omniroute run`、 `omniroute launch`および`omniroute launch-codex` 、 OS/terminal互換性ホワイトリストを継承し、選択されたターゲットの資格情報を挿入します。関連のないプロバイダーとデータベースのシークレットは、デフォルトでは継承されません。 `--inherit-env` 、完全な親環境の継承を明示的に復元します。選択したサードパーティ プロセスがそれらの値を受け取る必要がある場合にのみ使用してください。これは環境フィルタリングであり、 OSサンドボックスではありません。プロセスは呼び出し元のファイルシステム権限で引き続き実行されます。

割り込み信号と終了信号は子に転送されます。ランチャーは、一時的な構成を削除する前に、子の close イベントを待ちます。 `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` 、強制終了までの猶予期間 (デフォルトは 5000 ミリ秒) を制御します。

## Gemini永続セットアップ

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

最初の 2 つのコマンドは、選択したローカル サーバーまたはリモート サーバー用にこのマシンを構成します。セットアップでは、無関係なJSON設定が保存され、 Gemini API キー認証が選択され、エンドポイントと資格情報がプライベート`.gemini/.env`ファイルに書き込まれます。無効なJSONを上書きするのではなく、拒否します。エンドポイントURLs 、埋め込み資格情報、クエリ パラメーター、またはフラグメントのないHTTP(S) である必要があります。ドライランでは、資格情報の値ではなく、パスが出力されます。

`GEMINI_CLI_HOME`または`--gemini-home`永続的なホーム ルートを選択します。実際の`run gemini` 、独自の一時ホームを作成し、後で削除します。どちらのモードもGeminiの workspace-trust チェックをバイパスしません。

## Codexプロファイル

`configure codex` 、モデルとそのOmniRouteプロバイダー エンドポイントを使用してプライベート`<name>.config.toml`を書き込みます。資格情報は`OMNIROUTE_API_KEY`を通じて参照され、埋め込まれることはありません。 launch コマンドは、選択したモデルを`model_providers`内ではなく、最上位の`model`キーに設定します。

個別のプロファイル ファイルは、現在の文書化されたCodex契約です。 `codex --profile <name>`で選択すると、ユーザー構成をオーバーレイします。[公式プロファイルのリファレンス](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles)と[OmniRoute Codexガイド](./CODEX-CLI-CONFIGURATION.md)を参照してください。

## 密閉コマンドの実行

明示的な`DATA_DIR`を使用して`OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1`を設定すると、起動時にデフォルトのユーザー データ ディレクトリの資格情報環境に落ちてしまうことを防ぎます。これは、個別のテストに役立ちます。明示的に選択された他の環境ファイルは無効になりません。

## 作業ディレクトリ`.env`

CLI 、明示的な`DATA_DIR`、デフォルトのデータ ディレクトリ、現在の作業ディレクトリ、パッケージ ディレクトリの順に`.env`ファイルを読み取り、キーを設定した最初のファイルが優先されます。シェル変数が常に優先されます。

作業ディレクトリは他の人 (複製されたリポジトリ、解凍されたアーカイブ) に属している可能性があり、 `omniroute serve` CLI環境をサーバーとサーバーが実行するすべてのツールに渡します。したがって、 `.env`では、 `bin/cli/utils/untrustedCwdEnv.mjs`にリストされている次のキーのみを設定できます。

| 鍵                              | 受け入れられる値                                                      |
| ------------------------------- | --------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`、 `1`または`yes`のいずれの場合でも、サーバーが値として扱う     |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 最大 64 文字の文字、数字、 `_`、 `.`、 `@`または`-`                   |
| `LANGUAGE`                      | 同じ、プラス`:`                                                       |
| `TZ`                            | 最大 64 文字の文字、数字、 `_`、 `+`、 `-`または`/`、 `/`で始まらない |
| `NO_COLOR`, `FORCE_COLOR`       | 最大 16 文字の文字と数字                                              |

`REQUIRE_API_KEY`が受け入れる値はすべてチェックをオンにするため、ファイル自体がチェックをオフにすることはできません。ただし、結果は決まりません。サーバーは環境の前にデータベースに保存されている`REQUIRE_API_KEY`オーバーライドを読み取りますが、 APIキーなしですべてのインターフェイスをリッスンすることに関する起動警告は環境のみを読み取ります。 `false`のオーバーライドを保存すると、作業ディレクトリ`REQUIRE_API_KEY=true` APIを開いたままにし、警告を非表示にします。 `TZ`ルールはPOSIXよりも範囲が狭く、 `.`、 `:`、 `,`および`<>`拒否するため、 `:Area/City`形式と`EST5EDT,M3.2.0,M11.1.0`などのルールをシェルまたは`<DATA_DIR>/.env`で設定する必要があります。

名前は大文字で正確に一致する必要があります。他の行、チェックに失敗した値、およびプレーンなASCII文字、数字、および`_`ではない名前 (たとえばNULバイトまたは類似文字を含むもの) はスキップされます。 CLI 、設定できないキーの名前を示す 1 つの警告と、無視された許可されたキーの名前を示す警告を 1 つ出力し、それぞれ変更内容 (`TZ (expected a zone name such as Europe/Berlin)`、 `lang (write the name as LANG)`) を示します。どちらも値を出力しません。これらのメッセージ内のファイル パス、および`omniroute doctor`がレポートする`.env`パスには、制御文字または Bidi 文字が含まれている場合はエスケープされます。作業ディレクトリがデータ ディレクトリまたはパッケージ ディレクトリである場合、この制限は適用されません。

`PORT`、 `API_PORT`および`DASHBOARD_PORT`はリストにありません。優先順位の高いソースからのベースURLがなければ、 CLI `localhost:<PORT>`と通信し、そこでリッスンするものはすべてCLIのAPIキー、コンテキスト トークン、およびCLIマシン トークン (`x-omniroute-cli-token`、 [CLI_TOKEN.md](../security/CLI_TOKEN.md)を参照) を受け取ります。ローカル サーバーはこれをループバックからの管理呼び出しとして受け入れます。作業ディレクトリからのポートにより、そのファイルがリスナーを選択できるようになるため、シェル内、 `<DATA_DIR>/.env`内、またはポートを持つコマンドの`--port`オプション (`serve`、 `launch`、 `run`) を使用してポートを設定します。

パーサーには`export`構文がありません。 `export LD_PRELOAD=...`などの行は、変数`export LD_PRELOAD`に名前を付けます。作業ディレクトリからはスキップされ、他の`.env`ファイルではそのリテラル名が設定され、何も読み取られません。

CLI 、コンテキストに保存されているトークン (アクセス トークンまたはレガシーAPIキー) を、 `URL.origin`と比較して、そのコンテキスト自体のオリジン (スキーム、ホスト、ポート) とのみペアリングします。これは、 CLIのHTTPクライアント (`--base-url`、 `OMNIROUTE_BASE_URL`、 `omniroute connect <new-url>`) を通じて行われたリクエストと、ベースURLとキーを別のツールの構成に書き込む`launch`、 `launch codex`、 `configure`および`setup-*`コマンドに適用されます。 `--remote`で別のサーバーを指す場合、明示的な`--api-key`または`OMNIROUTE_API_KEY`が設定されている場合はそれを使用し、コンテキスト トークンは使用しません。比較は正確であるため、 `localhost`と`127.0.0.1`、または末尾にドットがあるホストとないホストは異なるサーバーとしてカウントされ、コンテキスト トークンは取得されません。ユーザー情報、バックスラッシュ、または空白を含むURL決して一致しません。これは、他のURLパーサー (Python の`urllib`や`httpx`など) が異なるホストを読み取ることができるためです。 CLI自体が送信するリクエストの場合、そのチェックはスキームと権限のみをカバーするため、パスまたはクエリ内のスペースを含む ID によってトークンが保持されます。
