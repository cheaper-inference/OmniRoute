> **要約**: プロバイダーとは、AI サービス（OpenAI、Anthropic、Google など）への接続です。OmniRoute を使用するには、少なくとも 1 つのプロバイダーが必要です。

---

## プロバイダーとは？

プロバイダーは、**携帯電話会社**のようなものだと考えてください。電話をかけるのに携帯電話会社が必要なのと同様に、AIモデルを使用するにはAIプロバイダーが必要です。OmniRouteは、**すべての携帯電話会社**に対応する携帯電話のようなもので、プロバイダーを自動的に切り替えられます。

### プロバイダーの種類

| 種類           | 概要                     | 例                              | 料金                   |
| -------------- | ------------------------ | ------------------------------- | ---------------------- |
| **無料**       | 支払い不要               | Kiro, Pollinations              | $0                     |
| **APIキー**    | APIキーが必要            | OpenAI, Anthropic, Google       | 使用量に応じた従量課金 |
| **OAuth**      | アカウントでログイン     | Claude Code, GitHub Copilot     | サブスクリプション     |
| **Web Cookie** | ブラウザセッションを使用 | ChatGPT Web (Codex), Gemini Web | $0（アカウントを使用） |

### Web Cookieプロバイダー

一般的なセットアップ手順、制限事項、トラブルシューティング、およびプロバイダー固有の認証ガイダンスについては、**[WEB-COOKIE-GUIDE.md](./WEB-COOKIE-GUIDE.md)**を参照してください。

## クイックスタート：最初のプロバイダーに接続する

### 任意の初回無料プロバイダー設定

初回実行ウィザードには、明示的な **無料プロバイダーを設定** カードが表示されます。OmniRoute の認証不要プロバイダーレジストリから現在利用可能な一覧を取得し、確定する前に各プロバイダーを確認して選択を解除できます。OmniRoute にはプロバイダーの注意事項とそのサイトへのリンクが表示されるため、サードパーティの利用規約、プライバシー、可用性、レート制限を事前に確認できます。

この操作は任意です。ウィザードを完了しても、無料プロバイダーへの接続が自動的に作成されることはありません。まだ追加されていないプロバイダーのみが作成され、既存のカスタマイズ済み接続は変更されません。また、作成済み、設定済み、失敗したプロバイダーが個別に報告されます。一部のみ成功した場合は、失敗したものだけを安全に再試行できます。

### オプション A：無料プロバイダー（クレジットカード不要）

1. `http://localhost:20128` でダッシュボードを開きます
2. **プロバイダー** → **プロバイダーを追加** に移動します
3. 次の無料プロバイダーから1つを選択します：
   - **Kiro AI** — 無料の Claude モデル（認証不要）
   - **Pollinations** — 無料の GPT-5、Claude、Gemini（キー不要）
   - **LongCat** — 1,000万トークンを無料で利用可能（1回限りの付与、アカウントと KYC が必要）
   - **Cloudflare AI** — 50以上のモデル、1日あたり10Kニューロン
   - **MLX Gemma 26B** — ローカル Apple Silicon モデル（約38.5 tok/s、約15.9GB RAM）
   - **MLX Qwen 3.8 27B** — ローカル Apple Silicon モデル（約9.1 tok/s、約13.1GB RAM）
4. **接続** をクリックします
5. 完了です！無料で AI を利用できるようになりました。

### オプション B：API キープロバイダー（有料）

1. プロバイダーのウェブサイトから API キーを取得します：
   - **OpenAI**: https://platform.openai.com/api-keys
   - **Anthropic**: https://console.anthropic.com/
   - **Google**: https://aistudio.google.com/apikey
   - **DeepSeek**: https://platform.deepseek.com/
   - **Groq**: https://console.groq.com/
2. `http://localhost:20128` でダッシュボードを開きます
3. **プロバイダー** → **プロバイダーを追加** に移動します
4. プロバイダーを選択します
5. API キーを貼り付けます
6. **接続** をクリックします
7. 完了です！そのプロバイダーのモデルを利用できるようになりました。

### オプション C：OAuth プロバイダー（サブスクリプション）

1. `http://localhost:20128` でダッシュボードを開きます
2. **プロバイダー** → **プロバイダーを追加** に移動します
3. プロバイダー（Claude Code、GitHub Copilot など）を選択します
4. **OAuth で接続** をクリックします
5. アカウントでログインします
6. 完了です！サブスクリプション対象モデルを利用できるようになりました。

### オプション D：ローカル MLX モデル（Apple Silicon）

ユニファイドメモリを搭載した Apple Silicon Mac では、OmniRoute は `mlx-lm.server` 経由で実行されるローカル MLX モデルを、通常の OpenAI 互換ローカルプロバイダーとして接続できます。

#### 前提条件

- **Apple Silicon Mac**（M1/M2/M3/M4）。24GB以上のユニファイドメモリを推奨
- **uv** パッケージマネージャー：`curl -LsSf https://astral.sh/uv/install.sh | sh`
- **mlx-lm**：`uv pip install mlx-lm`

#### クイックスタート

1. **依存関係をインストールします**：

   ```bash
   # まだインストールされていない場合は uv をインストール
   curl -LsSf https://astral.sh/uv/install.sh | sh

   # mlx-lm をインストール
   uv pip install mlx-lm
   ```

2. **MLX サーバーを手動で起動します**（別々のターミナルで）：

   ```bash
   # ターミナル1：Gemma 4 26B A4B IT-QAT（ポート11435）
   uv run mlx_lm.server --model mlx-community/gemma-4-26B-A4B-it-qat-q4_0-mlx-aligned --port 11435 --host 127.0.0.1

   # ターミナル2：Qwen 3.8 27B MLX Mixed（ポート11436）
   uv run mlx_lm.server --model maglun/Qwen3.8-27B-MLX-Mixed-3.80bpw --port 11436 --host 127.0.0.1
   ```

3. **OmniRoute ダッシュボードで接続します**：
   - **プロバイダー** → **プロバイダーを追加** に移動します
   - **MLX Gemma 26B** または **MLX Qwen 3.8 27B** を選択します
   - **接続** をクリックします（API キー不要）

4. **OpenCode で使用します**：
   ```bash
   # OmniRoute を使用するように OpenCode を設定
   opencode config set api.base_url http://localhost:20128/v1
   opencode config set api.key <your-omniroute-api-key>

   # MLX モデルを使用
   opencode run --model mlx-gemma/gemma-4-26b
   opencode run --model mlx-qwen/qwen3.8-27b
   ```

#### メモリ管理

**重要**：24GBのユニファイドメモリでは、**一度に実行できる大規模 MLX モデルは1つだけです**。

- Gemma 26B：ピークメモリ約15.9GB
- Qwen 3.8 27B：ピークメモリ約13.1GB

これは手動で管理する必要があります：

- 一度に1つの MLX サーバーのみを実行する、または
- それぞれを別のマシンで実行する、または
- 一方を停止してからもう一方を起動する

OmniRoute は MLX サーバープロセスを自動的に管理しません。設定した OpenAI 互換エンドポイントへリクエストをルーティングするだけです。

#### ツール呼び出しのサポート

どちらのモデルも OpenAI 互換のツール呼び出しをサポートしています。以下でテストできます：

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mlx-gemma/gemma-4-26b",
    "messages": [{"role": "user", "content": "What is 2+2? Use the calculator tool."}],
    "tools": [{"type": "function", "function": {"name": "calculator", "description": "Calculate", "parameters": {"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]}}}]
  }'
```

#### トラブルシューティング

| 問題                     | 解決方法                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------- |
| サーバーが起動しない     | `uv run mlx_lm.server --help` を確認し、モデル ID が正しいことを確認してください                        |
| メモリ不足               | 1つのモデルだけが実行されていることを確認し、他のアプリを終了してアクティビティモニタを確認してください |
| 接続が拒否される         | サーバーが正しいポート（11435/11436）で実行されていることを確認してください                             |
| 応答が遅い               | 最初のリクエストではモデルがメモリに読み込まれます（約30～60秒）。それ以降のリクエストは高速です        |
| ツール呼び出しが失敗する | モデルがツールをサポートしていることを確認し、OmniRoute のログで変換エラーを確認してください            |

## プロバイダーへの接続方法（ステップごと）

### ステップ1：ダッシュボードを開く

ブラウザーで`http://localhost:20128`にアクセスします。

サイドバーの**プロバイダー**をクリックします。

## 複数プロバイダーの使用

OmniRoute は、**複数のプロバイダー**を使用することで最大限に活用できます。これにより、次のメリットが得られます。

- **自動フォールバック** — 1つのプロバイダーで障害が発生した場合、OmniRoute は次のプロバイダーを試します
- **コスト最適化** — OmniRoute はリクエストごとに最も安価なプロバイダーを選択します
- **速度最適化** — OmniRoute はリクエストごとに最も高速なプロバイダーを選択します
- **品質最適化** — OmniRoute はタスクごとに最適なプロバイダーを選択します

### 推奨設定

最適な利用環境を実現するために、少なくとも**3つのプロバイダー**に接続してください。

1. **無料プロバイダーを1つ**（Kiro または Pollinations）— 常に利用可能
2. **高速プロバイダーを1つ**（Groq、Cerebras）— 迅速な応答向け
3. **高品質プロバイダーを1つ**（OpenAI、Anthropic、Google）— 複雑なタスク向け

その後、`model: "auto"` を使用すると、OmniRoute が各リクエストに最適なプロバイダーを自動的に選択します。

### Qoder: 認証情報の転送方式を選択

Qoderには認証情報が必要です。2つの転送方式はそれぞれ機能が異なるため、モデル名
だけでは、特定の接続で何ができるかを判別できません。

| 認証情報                               | OmniRouteの転送方式                           | 呼び出し元によるツール呼び出し                     | ストリーミング                                               |
| -------------------------------------- | --------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------ |
| `pt-`で始まるPAT                       | OmniRouteホスト上のローカル`qodercli`プロセス | 非対応                                             | バッファリング方式: CLIが完全な応答を返した後にのみSSEを送信 |
| PAT以外のアクセストークンまたはAPIキー | DashScopeのOpenAI互換HTTPエンドポイント       | アップストリームのモデル／キーに応じてそのまま転送 | アップストリームのHTTP/SSE経路                               |

PATを使用する場合は、OmniRouteと同じホストまたはコンテナにQoder CLIをインストールしてください。実行ファイルは
`qodercli`として検出可能である必要があります。あるいは、`CLI_QODER_BIN`に実行ファイルのパスを設定してください。Dockerホスト
にのみインストールされたCLIは、コンテナ内で自動的に利用可能にはなりません。バイナリが見つからない
場合は、インストールまたはパス設定を案内する明示的なエラーが発生します。

PATチャット経路には45秒のプロセスタイムアウトがあります。会話を1つの
プロンプトにフラット化し、非ストリーミングの出力モードでCLIを呼び出します。`stream: true`を指定すると
レスポンスのエンベロープはSSEに変わりますが、アップストリームからトークンが逐次配信されるわけではありません。
CLIの検証／モデル一覧取得には、別途20秒のタイムアウトが使用されます。これらは現在のコード上の
デフォルト値であり、ダッシュボードで設定可能な項目ではありません。

PAT接続は通常のチャットに使用してください。`tools`または従来の`functions`を含むエージェントリクエストでは、
固定されたコンボターゲットを含め、認証情報の選択時にPATアカウントが除外されます。Qoderの混在
プールでは、引き続きHTTPアカウントを選択できます。PAT実行機能を直接呼び出した場合も、ツール定義を黙って破棄
するのではなく、CLIを起動する前に明示的に失敗します。この制限が対象とするのはAPI呼び出し元が指定したツールであり、Qoder
CLI自体が内部で使用する可能性のあるツールではありません。HTTPキーを使用しても、すべてのモデルがツールをサポートするとは限りません。通常の
モデル機能チェックは引き続き適用されます。

ブラウザOAuthは、管理者が以下の5つの設定をすべて構成した場合にのみ利用できます:
`QODER_OAUTH_AUTHORIZE_URL`、`QODER_OAUTH_TOKEN_URL`、`QODER_OAUTH_USERINFO_URL`、
`QODER_OAUTH_CLIENT_ID`、`QODER_OAUTH_CLIENT_SECRET`。これらのデフォルト値は空です。未構成の
環境では、ブラウザのサインインフローが利用可能だと想定せず、サポートされている認証情報のインポート方法を使用してください。

実装リファレンス: [Qoder実行機能](../../open-sse/executors/qoder.ts)、
[CLIランタイム](../../open-sse/services/qoderCli.ts)、および
[OAuth設定](../../src/lib/oauth/constants/oauth.ts)。PATの逐次ストリーミング
と構成可能なタイムアウトは個別の拡張機能であり、この動作はそれらを保証するものではありません。

## よくある質問

### 「OmniRouteを使用するには料金がかかりますか？」

**いいえ！** OmniRouteは無料のオープンソースです。無料のプロバイダー（Kiro、Pollinations）を利用すれば、料金は一切かかりません。有料プロバイダーを選択した場合にのみ料金が発生します。

### 「最初にどのプロバイダーを使えばよいですか？」

まずは**Kiro AI**から始めましょう。無料でAPIキーが不要なうえ、Claudeモデルを利用できます。その後、必要に応じてプロバイダーを追加してください。

### 「複数のプロバイダーを同時に使用できますか？」

**はい！** それこそがOmniRouteの目的です。複数のプロバイダーを接続し、`model: "auto"`を使用すると、リクエストごとにOmniRouteが最適なプロバイダーを選択します。

### 「プロバイダーが停止した場合はどうなりますか？」

OmniRouteは障害が発生したプロバイダーを自動的にスキップし、次のプロバイダーを試します。ユーザーが何かする必要はありません。

### 「プロバイダーとの接続を解除するにはどうすればよいですか？」

Providers → プロバイダーをクリック → **Disconnect**をクリックしてください。

### 「既存のAPIキーを使用できますか？」

**はい！** OpenAI、Anthropic、GoogleなどのAPIキーをすでにお持ちの場合は、OmniRouteで使用できます。プロバイダーに接続するときに貼り付けるだけです。
