失敗は、再試行の決定が行われる前に分類されます。

タイムアウト、ネットワーク エラー、レート制限、プロバイダー 5xx 応答などの一時的な障害がフェイルオーバーする可能性があります。使い果たしたクォータまたはクレジット (クォータ 429 または 402 Payment Required) は、同じプロバイダーで再試行されることはありませんが、クォータが別の別のプロバイダーにフェイルオーバーします。認証エラー、権限エラー、無効なリクエスト、使用できないモデル、および不明なエラーが盲目的に再試行されることはありません。

デフォルトのクロスプロバイダー ポリシーでは、プロバイダーの試行を最大 3 回許可し、レート制限とタイムアウトを再試行し、クォータを使い果たした場合にフェールオーバーし、管理上の無効化を一時的な回線状態から切り離します。

## 適用される場所

- **コンボ**コンボ独自の戦略と設定に従って、ターゲット間でフェイルオーバーします。
- **裸のモデル ID**いくつかのアクティブなプロバイダーがサービスを提供する ( `provider/`プレフィックスなし) が、その正確な名前のコンボなしで、最初にプロバイダー推論ピックに送信されます。ポリシーがフェイルオーバーする形でその試みが失敗した場合、同じリクエストがその ID を提供する次のアクティブなプロバイダーに送信されます。応答には、応答したプロバイダーの前に試行されたプロバイダーの数を示す`x-omniroute-fallback-attempts`が含まれます。
  - それぞれの代替案は、あたかも推論によって選択されたかのように正確に認可されます。 APIキーがブロックするターゲット、または許可しないターゲットは、アップストリーム呼び出しなしでスキップされ、クライアントは、名前を付けなかったターゲットに対するポリシー拒否ではなく、実際のアップストリーム エラーを受け取ります。
  - 失敗した応答のみが続行されます。最初のストリーミング バイトの後は何もフェイルオーバーされません。
  - 緊急フォールバック モデル スワップは、要求されたモデルのすべてのプロバイダーに障害が発生した後にのみ適用されます。
  - 接続 (`x-omniroute-connection`) に固定されたリクエストは接続上に残ります。
  - 接頭辞付きの ID (`provider/model`) が別のプロバイダーに再ルーティングされることはありません。

回路状態は`closed`、 `open`、および`half_open`です。クールダウンでは、制限付きプローブをスケジュールします。プローブが成功すると回線が閉じられ、プローブが失敗すると再び回線が開きます。
