> **ステータス:** このダッシュボードは **Keak CI UI Kit**（`@keak/cheaper-inference-ui-kit`）を基盤として構築されており、
> ワークスペース `packages/ui-kit`（`@omniroute/ui-kit`）としてベンダー化されています（上流スナップショットは
> `packages/ui-kit/UPSTREAM.md` に固定され、`npm run check:ui-kit-snapshot` によって保護されています）。ライトが正規の
> テーマであり、デフォルトの設定は `system` です。アクセントカラーは Keak ライム（`--ci-color-accent`）です。Inter
> （letter-spacing 0、`--ci-letter-spacing-ui`）が UI のフォントファミリーで、Instrument Serif は大きく疎な
> ディスプレイテキスト（`.ci-dashboard-display`）のみに、IBM Plex Mono はコードに使用され、これらはすべて
> `src/app/globals.css` の先頭にある `@fontsource/*` インポートを通じてセルフホストされています。アイコンはすべて Lucide グリフです。

## 1. どこに何があるか

- **キット。** `packages/ui-kit/src` は、`packages/ui-kit/UPSTREAM.md` でピン留めされたコミット時点のアップストリーム `src/` のバイト単位で完全に同一のコピーである（同ファイルにはライセンスの認可も記録されている）。`PATCHES.md` にはローカルパッチが列挙されている（なし）。ビルドを挟まずソースとして利用され、`next.config.mjs` がこれをトランスパイルし、`tsconfig.json` が `@omniroute/ui-kit` → `packages/ui-kit/src`、`@omniroute/ui-kit/*` → `packages/ui-kit/src/*` にマップする（`vitest.config.ts` と `vitest.mcp.config.ts` も同じエイリアスを持つ）。キットコンポーネントはサブパス（`@omniroute/ui-kit/table`、`@omniroute/ui-kit/page-header`…）でインポートし、`@omniroute/ui-kit` バレル経由では決してインポートしない。バレルは（デートピッカーを含む）すべてのコンポーネントを各インポーターに引き込んでしまうためである。キットのスタイルシートは `src/app/globals.css` から読み込まれる（`@import "../../packages/ui-kit/src/ci-ui.css"`）。
- **トークン。** `packages/ui-kit/src/ci-tokens.css` が `--ci-*` トークンを宣言し、`src/app/globals.css` がそれらをレガシーな OmniRoute の名前（`--color-*`、`--radius-*`、`--font-sans`/`--font-mono`、`--table-*`、`--orch-status-*`、`--color-fd-*`）にブリッジする。これにより、既存の `var(--color-*)` の参照と Tailwind ユーティリティが動作し続ける。新しいコードは Tailwind ユーティリティ（`bg-surface`、`text-text-muted`、`border-border`、`text-success`、`bg-success-bg`、`bg-chart-1`…）またはキットクラスを使用し、16進数値は決して使わない（`tests/unit/design-kit-bridge.test.ts` がこのブリッジを強制する）。`text-primary` は `--text-color-primary` を経由して `--color-primary-ink` に解決される（ライトモードでは lime-800、ダークモードではライムアクセント）。そのため、`bg-primary`/`border-primary` がライム色のサーフェスを維持しつつ、プライマリテキストの可読性も保たれる。チャート系列は `--color-chart-1` … `--color-chart-5` を使用する。
- **テーマ。** `<html className="ci-theme">`（`src/app/layout.tsx`）がドキュメントをキットテーマにオプトインする。設定値は `light`、`dark`、`system` のいずれかであり（`src/shared/constants/appConfig.ts` の `THEME_CONFIG.defaultTheme = "system"`。`system` は `prefers-color-scheme` に従う）、`src/store/themeStore.ts` の `applyTheme()`（`src/app/layout.tsx` 内のインラインブートストラップスクリプトにミラーされており、ハイドレーション前に実行される）が、`data-theme="dark"|"light"` の設定と `<html>` 上の `.dark` クラスの切り替えを同時に行う。キットのダークトークンセットは `data-theme="dark"` をキーとする（`packages/ui-kit/src/ci-tokens.css`）。OmniRoute 独自のダーク上書き（`globals.css` の `.dark` ブロック）とレガシーな Tailwind の `dark:` ユーティリティは `.dark` クラスをキーとする。アクセントカラーのプリセットは存在しない。アクセントは常にキットから取得され、古いビルドで永続化されたプリセットはストアの読み込み時に破棄される。
- **コンポーネント（アダプター）。** `src/shared/components/index.tsx` は OmniRoute のコンポーネント API（同じ名前、デフォルトエクスポート、props）を維持し、その背後にあるプリミティブはキットの上に構築されたアダプターである：フォーム（`Button`、`Input`、`Textarea`、`Checkbox`、`Select`、`Toggle`、`Badge`、`Card`）、オーバーレイとフィードバック（`Modal`/`ConfirmModal`、`Tooltip`/`InfoTooltip`、`NotificationToast`、`EmptyState`、`Loading`）、構造（`Collapsible`、`CollapsibleSection`、`SegmentedControl`、`Breadcrumbs`、`Avatar`）、テーブル（`DataTable`、`FilterBar`、`ColumnToggle`、`FilterPills`、`PresetSlider`）。アダプターはキットコンポーネントをサブパスでインポートし、レガシー props をそれにマッピングする。例えば、`Button variant="primary"` はキットの `default` ボタンであり（`--ci-button-primary-*`：ライトモードでは反転サーフェス、ダークモードではアクセント色とその `--ci-color-accent-foreground` インク）、`danger` は `destructive`、`warning` は `outline` に `.ci-button--warning` 拡張を加えたものである。`globals.css` 末尾（`@layer components`）の `.ci-button--warning` と `.ci-badge[data-tone]` のルールは、キットクラスの上に追加された OmniRoute の拡張である。`tests/unit/ui/adapters/*.test.tsx` が各アダプターをピン留めする。
- **シェル。** `src/app/(dashboard)/layout.tsx` は `DashboardLayout` をレンダリングし、それが `src/shared/components/layouts/DashboardShell.tsx` をレンダリングする。キットの `SidebarProvider` / `Sidebar` / `SidebarInset`（`packages/ui-kit/src/sidebar.tsx`）を使用し、OmniRoute のナビゲーションロジックは `src/shared/components/Sidebar.tsx` にある。`#main-content` への「コンテンツへスキップ」リンクが最初のフォーカス可能要素である。`src/shared/components/Header.tsx` には、キットの `SidebarTrigger`（シェル内で唯一のサイドバートグル）、Keak の `ProductSwitcher`、コマンドパレットの起動ボタンが配置されている。キットの `PageHeader`（`.ci-page-header`）が `#main-content` 内にマウントされていない間だけルートタイトルを表示するため、独自の `PageHeader` を持つページでは `h1` が1つになる。`src/shared/components/CommandPalette.tsx` はキットの `Dialog` である。
- **アイコン。** `<Icon name="material_name">`（`src/shared/components/Icon.tsx`）は、（画面で使用される Material Symbols の語彙の）名前を `ICON_MAP`（`src/shared/constants/iconMap.ts`）を通じて Lucide グリフに解決する。Material Symbols のフォントとパッケージは削除されている。マップに存在しない名前は中立的なプレースホルダーグリフ（`data-icon-missing="true"`）をレンダリングし、本番環境以外ではコンソール警告を出力する。`npm run gen:icon-map` は使用中だがマップに存在しない名前を出力する（`tests/unit/icon-map-coverage.test.ts` は Lucide アイコンがない名前があると失敗し、`tests/unit/icon-map-object-values.test.ts` はルックアップオブジェクトに格納された名前をカバーする）。`scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` はリテラルな `<span className="material-symbols-outlined">` スパンを `<Icon>` に書き換える。
- **ブランド。** `src/shared/components/OmniRouteLogo.tsx` はキットをラップする。デフォルトエクスポートの `OmniRouteLogo` は `ProductIcon product="omniroute" variant="glyph"`（インライン SVG、`basePath` 対応）をレンダリングし、`OmniRouteLockup` は `ProductLockup product="omniroute"`（アクセシブルな名前は "Keak OmniRoute"）をレンダリングする。ホワイトラベル事業者の場合は独自の `name`/`logoSrc` をレンダリングする。プロダクトスイッチャーの遷移先は `src/shared/constants/keakProducts.ts`（`KEAK_PRODUCT_LINKS`、`KEAK_ACTIVE_PRODUCT`）にある。スタンドアロン画面 —— `src/app/login/page.tsx`、`src/app/status/page.tsx`、`src/app/maintenance/page.tsx`、`src/app/offline/page.tsx`、`src/app/not-found.tsx`、`src/shared/components/ErrorPageScaffold.tsx` —— はロックアップを表示し、`tests/unit/brand-pages-static.test.ts` がこれを保護する。

## 2. ルール

1. トークンのみを使い、リテラルは使わないこと。意図的に残されている例外: 常にダーク表示のコンソールターミナル、
   `STATUS_HEX` (`src/shared/constants/statusColors.ts`) 経由の ReactFlow SVG ストローク、およびカテゴリカルパレットの
   `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) と
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`)。
2. `packages/ui-kit/src` を手作業でパッチしないこと: `scripts/dev/sync-ui-kit.sh <commit>` で同期する。
   pre-commit ゲートの `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) は、ピン留めされたアップストリームコミットと
   1 バイトでも異なる箇所があれば失敗する (アップストリームのクローン `UI_KIT_CLONE` または
   `_references/cheaper-inference-ui-kit` が存在しない場合は、警告を出してスキップする)。キットに足りないものがある場合は、
   アダプターまたは画面側で回避し、アップストリームに要望を出すこと。
3. キットのテキストのデフォルトは英語 (`label = "Loading"`, `loadingLabel = "Loading table"`…) —
   キットコンポーネントがテキストをレンダリングするときは、必ず `useTranslations(...)` から翻訳済みの文字列を渡すこと。
4. Tailwind ユーティリティはキットコンポーネントのクラスより優先される (キットは
   `@layer theme, base, components, utilities` を宣言しており、そのルールは `components` に置かれている) —
   ユーティリティはスペーシングとレイアウトのために使い、キットコンポーネントの色変更には使わないこと。
5. 見出し: ページやセクションのタイトルには `.ci-heading` (Inter、トラッキングなし) を使う。
   `.ci-dashboard-display` (Instrument Serif) は、エラーページのステータスコードのような大きくてまばらなディスプレイテキストにのみ使う。
6. `tests/unit/dashboard-kit-sweep.test.ts` がキット採用をガードしている: `src/app` や `src/shared/components` 配下に
   Material リガチャの span を置かないこと。ダッシュボードツリー (`src/app/(dashboard)` と
   `src/shared/components`) では、生の `<select>`、`<textarea>`、`<table>` を使わず、列挙された例外
   (`Select` アダプターのネイティブ分岐、`RequestLoggerDetail`) 以外で独自実装の `role="dialog"` を使わないこと。
   これらの場所にある生の `<button>` や `<input>` にはすべて、`kit-exception:` を含むコメント (理由を添えたもの) を
   最大でもその 3 行上までに付ける必要がある。パレットの色相と `dark:` バリアントは、テストに列挙されたファイル内でのみ使用すること。
7. PR の前に両方のテーマと 390 px のビューポートを確認すること (スクリーンショット)。`tests/e2e/a11y.spec.ts` が
   axe を実行する。

## 3. 画面の追加

1. ページはキットの `PageHeader` (`@omniroute/ui-kit/page-header`、ダッシュボード内では `compact`) で始める —
   タイトル、説明、`actions` を指定する。これによりシェルヘッダーは自身のタイトルを表示しなくなる。
2. コントロールは `@/shared/components` (アダプター) から組み立て、アダプターが存在しない場所ではサブパス指定で
   キットコンポーネント (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`,
   `Slider`…) を使う。
3. アイコン: `<Icon name="…" />`。新しい名前は、意味的に対応する Lucide コンポーネントとともに `ICON_MAP` に追加する。
   `npm run gen:icon-map` でまだ不足している名前を一覧できる。
4. 色: セマンティックユーティリティ (`text-success`, `bg-warning-bg`, `border-border`…) を使い、チャート系列には
   `var(--color-chart-N)` を使う。16 進数値や、色を繰り返すだけの `dark:` バリアントは使わないこと。
5. テキスト: キットコンポーネントに渡すラベルを含め、すべての文字列は `useTranslations` から取得する。新しいキーは
   `src/i18n/messages/en.json`、`pt-BR.json`、`vi.json` に追加する (ベトナム語のパリティテストがすべての英語キーを
   ピン留めしている)。他のロケールは i18n 同期によって補完される。
6. PR の前にガードを実行する: `tests/unit/dashboard-kit-sweep.test.ts`、
   `tests/unit/icon-map-coverage.test.ts`、`tests/unit/icon-map-object-values.test.ts`、
   `npm run check:dashboard-typecheck` (`iconMap.ts` の重複インポートを検出できる唯一のチェック)、
   `npm run check:ui-icu`、およびその画面固有のテスト。

## 4. アダプターの追加または変更

1. `src/shared/components/index.tsx` の公開 API を維持すること: エクスポート名、デフォルトエクスポート、受け入れる props を同一に保つ。レガシー props はアダプター内でキットの props にマッピングする（`Button.tsx` の `VARIANT_TO_KIT`、`SIZE_TO_KIT` を参照）。
2. キットはサブパスでインポートする（`@omniroute/ui-kit/<component>`）。
3. キットの不足部分に対する回避策はアダプター内に置く（修正がスタイルの場合は `globals.css` の `@layer components` 内）。`packages/ui-kit/src` には決して置かない。
4. `tests/unit/ui/adapters/<name>.test.tsx` を追加または更新する。多数の呼び出し元を持つアダプターの場合、変更前後でレンダリングされるマークアップを比較すること — padding やラッパーの変更はすべての画面に波及する。

## 5. キットの更新

`scripts/dev/sync-ui-kit.sh <commit> [clone]` は、指定コミット時点の上流の `src/` を `packages/ui-kit/src` にコピーし、許可された唯一の変換（相対インポートから `.js` サフィックスを除去する）を適用する。その後: `git diff packages/ui-kit` を確認し、providers、settings、combos、usage、endpoint を両テーマで目視確認し、`npm run check:ui-kit-snapshot` と `npm run test:vitest:ui` を実行して、上流の変更履歴を添えて PR を作成する。
