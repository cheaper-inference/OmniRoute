`copilot-m365-web`（エイリアス `m365copilot`）は、認証済みの Microsoft 365 Copilot セッションを介して、
`m365.cloud.microsoft/chat` に OpenAI 形式のチャットリクエストを送信します。これは非公式のネイティブ統合です。別個のプロキシプロセスや localhost のアップストリームは必要ありません。
プロバイダー ID、エイリアス、既存のインポート済み接続に変更はありません。`copilot-web` は、`copilot.microsoft.com` のコンシューマーサービス向けの別のプロバイダーです。

> **Web Cookie プロバイダーを初めて利用しますか？**
>
> このプロバイダー固有のガイドに従う前に、一般的なセットアップ手順、認証に関するガイダンス、制限事項、トラブルシューティングについて、**`docs/getting-started/WEB-COOKIE-GUIDE.md`** をお読みください。
>
> **レガシーインポートの場合:** このプロバイダーの認証情報は**Cookie ではありません**。`m365.cloud.microsoft` から Cookie をコピーしないでください。認証情報は、DevTools の Network タブから読み取る WebSocket URL のクエリパラメーターとパスセグメントです。

## 前提条件

- `m365.cloud.microsoft/chat` の Copilot にアクセスできる Microsoft 365 アカウント
- DevTools で WebSocket を検査するための Chromium ベースのブラウザー（Chrome、Edge）
- そのアカウントで要求されたモデルにアクセスできること。利用可否はテナントとライセンスによって異なります

## ネイティブ サインイン（職場または学校のアカウント）

**Microsoft 365 Copilot → Connect** を選択し、サインインを試行する準備をします。ダッシュボードでは
PKCE を使用した認証コードフローが使われます。Microsoft のパスワードや MFA コードの入力は求められません。

1. **空白のブラウザータブ**を開き、**DevTools → Network** を開いて **Preserve log** を有効にします。
   Microsoft に移動する前にこれを行ってください。Windows SSO はすぐに完了する場合があります。
2. 接続ダイアログに表示された認証 URL をコピーし、準備したタブでその URL に移動します。
   要求された場合は、Microsoft のアカウント選択または MFA を完了します。
3. 保持された Network ログで、
   `https://login.microsoftonline.com/common/oauth2/nativeclient` へのリクエストを見つけ、その完全な **Request URL** をコピーします。
4. その URL を接続ダイアログに貼り付けて接続します。未加工のコードや、最終的な
   `wrongplace` のアドレスバー URL は貼り付けないでください。必要なコールバックは一時的なナビゲーションです。

各試行の有効期限は 10 分で、1 回しか使用できません。サーバーは、コードを交換する前に
その state、PKCE verifier、再認証対象を検証します。有効期限切れまたは交換の失敗後は、新しい試行を開始してください。
試行はサーバーの再起動後まで存続しません。

トークンには既存の接続資格情報ストアと更新パスが使用されます。接続を再認証するには、単に同じメールアドレスであるだけでなく、
同じ Microsoft テナント／オブジェクト ID が必要です。オペレーターの名前や設定は維持され、古くなったインポート済みの資格情報は置き換えられます。ネイティブ サインインは職場または学校のアカウント用です。既存の接続とサポート対象の階層構成では、従来のインポートパスも引き続き利用できます。

完全なコールバック URL は一度しか使用できない資格情報です。スクリーンショット、ログ、サポートメッセージ、コミットには決して含めないでください。このフローでは、サーバー上でブラウザーを開いたり、ブラウザーの履歴を調べたり、ローカルのコールバックサーバーを起動したりすることはありません。

## 認証情報の取得（WebSocket メソッド）

1. `https://m365.cloud.microsoft/chat` にサインインし、会話を開始します。
2. **DevTools → ネットワーク**を開きます。
3. **WS**（WebSocket）でフィルターします。
4. Chathub WebSocket 接続をクリックします。
   `wss://substrate.office.com/m365Copilot/Chathub/` で始まる URL を探します。
5. その **Request URL** から、以下をコピーします。
   - `access_token` クエリパラメーターの値（短期間のみ有効な JWT）。
   - `/Chathub/` の後にある Chathub パスセグメント（例: `<oid>@<tenant>`）。

完全な URL は次の形式です。

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute で **Microsoft 365 Copilot** を選択し、従来の API キー/インポートオプションを選択して、次の形式で認証情報を貼り付けます。

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **接続をテスト**をクリックして、**保存**します。

## 認証情報の取得（HAR インポート）

WebSocket URL から値を手動でコピーする代わりに、DevTools の HAR
ファイルをエクスポートできます。

1. **DevTools → Network** を開きます。
2. Microsoft 365 Copilot の会話を開始または続行します（これにより WebSocket 接続がトリガーされます）。
3. Network パネル内を右クリックし、**Save all as HAR with content** を選択します。
4. OmniRoute で、プロバイダー接続ダイアログの **Import .har file** ボタンを使用します。

OmniRoute は HAR 内から Chathub WebSocket URL を検索し、
`access_token` と `chathubPath` を抽出して、認証情報フィールドに自動入力します。HAR
のインポートでは JWT の有効期限をデコードし、トークンの残り有効期間を表示します。

> **実際の HAR エクスポート、アクセストークン、またはリフレッシュトークンを決してコミットしないでください。** テストおよびドキュメントの値には、必ずプレースホルダーを使用してください。

## トークンの有効期間と更新

`access_token` の有効期間は短く（通常 **約75分**）、有効なリフレッシュ
トークンがない場合は、有効期限が切れた後に認証情報を再取得する必要があります。

### `refreshToken` による自動更新

Microsoft 365 プロバイダーの **接続を追加** または **接続を編集** ダイアログで、
**詳細設定 → リフレッシュトークン（オプション）** を開きます。`substrate.office.com/sydney`
スコープ用の Microsoft OAuth リフレッシュトークンを貼り付けて保存します。入力値はマスクされ、
保存済みのトークンが事前入力されることはありません。編集時に空欄のままにすると既存のトークンが保持され、
新しいトークンを貼り付けると置き換えられます。

ネイティブサインインでは、Microsoft がリフレッシュトークンを返した場合にそれを取得します。レガシーインポートでは、
既存の互換性のある Microsoft 認証コードグラントを使用してください。このプロバイダーはデバイスコードフローを
実装しておらず、提供することも保証していません。
リフレッシュトークンを設定すると、OmniRoute はリクエスト前に `access_token` を確認し、更新が必要な場合にのみ更新します。
更新が成功するとローテーションされたリフレッシュトークンも保存されるため、リフレッシュトークンが有効である限り手動での
再取得は不要です。

`refreshToken` が設定されていない場合は、有効期限が切れるたびに WebSocket 認証情報を手動で
再取得する必要があります。

### ティアの選択

| ティア       | エイリアス     | 対象                            |
| ------------ | -------------- | ------------------------------- |
| `individual` | _(デフォルト)_ | コンシューマー向け M365 Copilot |
| `edu`        | `included`     | 教育機関向け M365 Copilot       |
| `enterprise` | `work`         | 業務向け M365 Copilot           |

**詳細設定 → Copilot ティア** でティアを設定します。ネイティブサインインではこれが設定されないため、
職場アカウントでは `enterprise`（エイリアス `work`）を、教育機関のアカウントでは `edu` を選択する必要があります。
これはドキュメントに記載されたモデル ID を使用する場合も同様です。モデル ID はそれぞれ独自のトーン、シナリオ、
ライセンスタイプを選択しますが、エージェントと呼び出しオプションは引き続きティアから取得され、個人向けのデフォルト値では
職場のテナントで失敗する可能性があります。ティアを変更してもモデルライセンスは付与されません。明示的な高度なプロトコルのオーバーライドが
優先されるため、必要なワイヤー値を把握している場合にのみ使用してください。

## モデルとルーティング

ネイティブカタログには、文書化されたすべてのスタンドアロン ID と、4 つの元のネイティブ ID が含まれます。
カタログは静的でアカウントに依存せず、アカウントの権限を確認するものではありません。接続されたアカウントで利用できない場合でも、有料ルート
および互換性エイリアスは引き続き一覧に表示されます。モデルの表示ラベルからはプロバイダー名とモデルごとの利用可能性に関する定型文が省略されます。プロバイダーは
引き続き **Microsoft 365 Copilot** です。**Alias** または **Legacy** のラベルが付いたものは、既存の
識別子とプロトコルマッピングを保持しますが、過去のモデルバージョンであることを保証するものではありません。スタンドアロンプロキシの
**Import from /models** に関する手順は、このネイティブ WebSocket プロバイダーには適用されません。

| モデルファミリー  | 正規 ID                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| 自動              | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| 以前の GPT        | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude Sonnet     | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude Opus       | `claude-opus`, `claude-opus-4.8`                                                                 |

`auto`、`quick`、`think-deeper`、バージョンエイリアスなどのエイリアスも登録されます。
既存の `copilot-m365`、`copilot-m365-claude-opus`、
`copilot-m365-gpt-5-6-reasoning`、`copilot-m365-gpt-5-5-chat` は引き続き有効です。
文書化された ID にはプロバイダープレフィックス（`copilot-m365-web/claude-opus` または
`m365copilot/claude-opus`）が必要です。多くは一般的な単語や他ベンダーのモデル名であるため、プレフィックスなしの
`claude-opus` は、このプロバイダーがない場合と同じようにルーティングされます。
登録は、Microsoft がすべてのアカウントにそのモデルを提供することを約束するものではありません。
スタンドアロン ID は、公開されている[プロトコルカタログ](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts)
（エクスポートされたモデルからトーンへのマップと、モデルを考慮したシナリオメタデータ）に従います。すべてのネイティブプロファイルには
`availability: "unverified"` が保持されます。カタログに含まれていることは、アカウントでの利用成功テストを意味しません。

- 明示的なモデルライセンス拒否は、502 ではなく **403** `m365_model_not_licensed` を返します。
  ルーティングはその接続とモデルの組み合わせをロックし、接続上のライセンス済みモデルは引き続き利用可能にします。
- `InvalidCopilotLicense` はアカウントレベルのライセンス拒否であり、`m365_account_not_licensed` として個別に報告されます。
- ユーザー単位のスロットリングは **429** `m365_throttled` を返し、接続をクールダウンさせます。
  優先アクセスの使い切りは **429** `priority_access_exhausted` を返し、モデル単位で適用されます。
  `errorCode: "ReasoningTurnExhausted"` を伴う `OutOfCredits` の結果は、代わりに **429**
  `reasoning_turns_exhausted` を返します。これもモデル単位で適用され、リセット時刻は主張されません。これは、
  Quick トーンでは提供が継続される一方で、「Think deeper」トーンに上限を設けるために、ある職場テナントで報告されたものです。この範囲は利用者による観測であり、このリポジトリが再現したものではありません。
  そのためルーティングでは、同じクールダウン期間中、その接続上で `gpt-5.5` と
  `gpt-5.6` の他の文書化された Think deeper モデルもローテーションから除外し、Quick トーンと、それ以外のすべての障害は各モデルに固有の状態として残します。
  提供された再試行ヒントは保持されます。リセット情報がない場合、既知のリセット時刻としては通知されません。
- Copilot の安全性による拒否（`Disengaged`）は **400** `provider_safety_rejection` を返します。これは
  共有プロバイダー安全停止ラベルです。接続の健全性には一切影響せず、クライアント SDK は 400 を再試行しません。また、
  `PROVIDER_SAFETY_STOPS_TERMINAL` を有効にしたコンボルーティングでは、別のターゲットに対してリクエストを再実行せず、その時点で停止します。
- 1 つの接続上のリクエストは、既存のアカウントセマフォを通じて直列化されます。並列パネルではなく、優先フォールバックを推奨します。
  直列化だけでは、Microsoft の会話レート制限を解消できません。

## リクエストの動作と制限

- ツールは **プロンプトでエミュレートされたもの**であり、ネイティブの Microsoft 関数呼び出しではありません。ツール対応のリクエストでは、1 回のバッファリングされた生成が使用され、ツールを選択するために別の生成が行われることはありません。有効なサポート対象の引数形式を持つ、宣言済みのツールのみが呼び出しとして返されます。
- 単一の末尾の例を含む長い構造化された回答は、本文として保持されます。これはヒューリスティックであり、意図の証明ではありません。アプリケーション側で独自のツール権限を引き続き適用する必要があります。
- 画像入力は、Web クライアントから送信される方法で機能します。各画像パート（データ URL または公開 HTTPS URL としての `image_url`、または Responses の `input_image`）は、チャットトークンを使用して `/m365Copilot/UploadFile` にアップロードされ、ターンの会話に追加されます。メッセージでは `ImageFile` アノテーションによってその画像が参照され、テキストには画像が置かれていた位置（`[image 1]`、…）が示されます。新しい会話では履歴内のすべての画像がアップロードされ、継続中の会話では新しいメッセージの画像のみがアップロードされます。1 リクエストあたり、最大 10 MiB の PNG、JPEG、GIF、または WebP 画像を最大 10 枚（合計 40 MiB）使用できます。形式はバイト列から読み取られます。HTTPS URL は、公開アクセスのみを許可し、DNS を固定するリモート画像ガードを介して取得されます。アップロードに失敗した場合、リクエストも失敗します（**502** `m365_image_upload_failed`、**400** `m365_image_rejected` または `m365_image_invalid`）。与えられた画像なしでターンが先に進むことはありません。その他のテキスト以外のパート（音声、ファイル）は、黙って破棄されるのではなく、明示的に拒否されます。
- フォローアップリクエストは同じアップストリーム会話を継続し、前回の応答以降のメッセージのみを送信します。継続するには、その応答を正確に拡張する必要があります。つまり、同じ接続、モデルプロファイル、ツールセット、すべてのメッセージに対する sha256 チェーンが一致する変更されていない履歴、そして応答のツール呼び出し ID、または空白までのテキストが必要です。それ以外（編集された履歴、同じ最初のメッセージを持つ別のセッション、異なる応答、30 分間アイドル状態の会話、Copilot の 600 メッセージ上限に近い会話、ID のない接続）の場合は、履歴全体を含む新しい会話が開始されます。失敗したターンが再開されることはありません。また、内容のない `InternalError` は新しい会話で 1 回再送されます（再度失敗した場合は **502** `m365_internal_error`）。継続情報はプロセスメモリ内に保持されるため、再起動すると新しい会話が開始されます。
- すべてのターンは Copilot の一時チャット（`disableMemory=1`）で実行されます。会話は実行中のコンテキストを保持しますが、アカウントのチャット履歴には一切表示されません。そのため、モデルテスト、すべてのテスト、コンボテストでは、会話を残さずにこのプロバイダーを検証できます。
- 各ターンには 120 秒のアイドル期限と、制限された全体期限があります。最終回答のみの応答、進行状況のフィルタリング、キャンセルは、ネイティブのトランスポート／コンポーザーによって処理されます。
- Web に基づく回答では、ソースが保持されます。Copilot はプライベート用途の制御文字を使用して引用をインラインで示し、ソースを `references` として送信します。各マーカーは、対応する `url_citation` アノテーション（`message.annotations`、またはリンクを含むチャンク上の `delta.annotations`）を持つ番号付き Markdown リンク（`[1](https://…)`、または Copilot がマーカーをリンク先として使用した場合は URL のみ）になります。ソースが到着しない場合は破棄されるため、マーカーがクライアントに届くことはありません。ストリーミング中は、ソースが到着するまで引用の後のテキストは待機します。
- Copilot の推論概要（`ChainOfThoughtSummary`）がモデルから送信された場合、その概要は `reasoning_content` として返され、回答の一部になることはありません。概要が書き換えられた場合、ターンを失敗させずにストリーミングを停止します。
- コンテンツが始まる前のライセンス／スロットルエラーでは、ストリーミングが要求されている場合でも HTTP 403/429 が維持されます。コンテンツの送信開始後に発生したエラーは SSE エベントとして通知され、成功した終了にはなりません。追加のみのストリーミングでは表現できないアップストリームでの書き換えは、明示的なストリームエラーになります。非ストリーミングおよびバッファリングされたツール応答では、最終テキストが維持されます。
- Copilot 自体が接続を拒否した場合、その応答はそのまま報告されます。拒否または期限切れのサインイン（再度サインインしてください）では **401** `m365_unauthorized`、スロットリングでは `Retry-After` を伴う **429**、それ以外ではハンドシェイク失敗となり、一般的な接続失敗として扱われることはありません。

## 画像生成

`POST /v1/images/generations` with `model: "copilot-m365-web/m365-copilot-image"` (alias
`m365copilot/m365-copilot-image`) は、Web クライアントと同様に、Copilot 組み込みの画像ツールを使用して描画します。各画像は 1 回の Copilot ターンとして処理されます。Web クライアントの画像オプションセットを使用してオプトインし、`GenerateGraphicArt` を宣言します。画像は、Microsoft の Designer サービス上のアーティファクトを指す進行状況エントリとして届きます。そのアーティファクトはチャットトークンを受け付けないため、OmniRoute は接続のリフレッシュトークンから Designer トークンを発行してバイト列をダウンロードします。このトークンが送信されるのは `designerapp.officeapps.live.com` だけです。

- ネイティブのサインイン接続（リフレッシュトークン）が必要です。貼り付けたトークンでは、ターンを消費する前に **400** で失敗します。
- `n` は 1～4 で、画像 1 枚につき 1 ターンです。`size` は向き（横長、縦長、正方形）だけを誘導し、Copilot がプロンプトから読み取ります。レンダリングサイズは Copilot が選択します。
- 画像はインラインで返されます。デフォルトでは `b64_json`、`response_format: "url"` の場合はデータ URL です。
- 生成画像はチャットとは別の、少量の日次予算を消費します。使い切るとリクエストは **429** で失敗します。画像なしで応答するターンは **502** で失敗します（Copilot のテキストが拒否または容量の問題を示す場合は **400** / **503**）。メッセージにはその理由が示されます。

## セキュリティモデル

- **非公式の統合。** このプロバイダーは BizChat WebSocket
  プロトコルをリバースエンジニアリングしています。Microsoft がエンドポイントを変更すると、予告なく動作しなくなる可能性があります。
- `subscriptionRisk: true` フラグは、この統合が文書化されていないエンドポイントに依存していることを示します。アカウント制限が発生する可能性はありますが、確認はされていません。
- アクセストークンは短期間のみ有効な JWT です。パスワードと同様に扱い、コミット、ログ出力、共有を行わないでください。
- リフレッシュトークンは Microsoft 365 のサービス群への継続的なアクセスを許可します。API キーと同じように慎重に保管してください。

## トラブルシューティング

### 認証が直ちに失敗する

- **WebSocket URL** からコピーしたことを確認してください。XHR/Fetch リクエストからではありません。資格情報は Chathub WebSocket 接続の `access_token` クエリパラメーターに含まれており、`Authorization: Bearer` ヘッダーには含まれていません。
- `chathubPath` に、URL パスに含まれる完全な `<oid>@<tenant>` セグメントが含まれていることを確認してください。

### トークンが約 75 分後に期限切れになる

これは想定される動作です。`refreshToken` がない場合、アクセストークンの有効期間は短くなります。次のいずれかを行ってください。

- DevTools から資格情報を再取得する、または
- 接続の追加または編集ダイアログで、**Advanced Settings → Refresh token (optional)** を設定して自動更新を有効にする。

### 接続テストは成功するが、チャットで 401 が返される

**Sign in with Microsoft** で作成した接続の場合、接続テストではアクセストークンの有効期限を確認し、保存されているリフレッシュトークンを使用して期限切れのトークンを更新します。そのため、テストが成功すれば、リフレッシュトークンも引き続き機能していることが確認できます。

貼り付けた資格情報の場合、接続テストでは資格情報の形式を確認し、トークンに有効期限が含まれている場合は、プロバイダーが使用するトークンが期限切れになっていないことを確認します（接続に保存されているトークンが古い貼り付け値より優先され、リフレッシュトークンがある場合は更新可能とみなされます）。有効期限前に失効したトークンはテストに合格しますが、チャットでは **401** `m365_unauthorized` が返されます。再度 **Sign in with Microsoft** を使用するか、新しい資格情報を再取得してください。

### プロバイダー一覧に Copilot が表示されない

`copilot-m365-web` が **Dashboard → Providers** で有効になっていることを確認してください。一部のティアでは、プロバイダーがデフォルトで非表示になっている場合があります。
