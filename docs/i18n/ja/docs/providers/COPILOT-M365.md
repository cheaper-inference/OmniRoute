`copilot-m365-web`（エイリアス `m365copilot`）は、`m365.cloud.microsoft/chat` で認証済みの Microsoft 365 Copilot BizChat ブラウザーセッションを通じて、OpenAI 形式のチャットリクエストを送信します。これは非公式の連携です。

> **Web Cookie プロバイダーを初めて使用しますか？**
>
> このプロバイダー固有のガイドに進む前に、一般的なセットアップ手順、認証に関するガイダンス、制限事項、トラブルシューティングについて **`docs/getting-started/WEB-COOKIE-GUIDE.md`** をお読みください。
>
> **重要：** このプロバイダーの認証情報は **Cookie ではありません**。`m365.cloud.microsoft` から Cookie をコピーしないでください。認証情報は WebSocket URL のクエリパラメーターとパスセグメントであり、どちらも DevTools の Network タブから取得します。

## 前提条件

- `m365.cloud.microsoft/chat` の BizChat にアクセスできる Microsoft 365 アカウント
- DevTools で WebSocket を検査するための Chromium ベースのブラウザー（Chrome、Edge）
- M365 Copilot ライセンス（多くの Microsoft 365 Business/Enterprise プランに含まれています）

## 認証情報の取得（WebSocket 方式）

1. `https://m365.cloud.microsoft/chat` にサインインし、会話を開始します。
2. **DevTools → Network** を開きます。
3. **WS**（WebSocket）でフィルタリングします。
4. Chathub WebSocket 接続をクリックします。`wss://substrate.office.com/m365Copilot/Chathub/` で始まる URL を探します。
5. その **Request URL** から、以下をコピーします。
   - `access_token` クエリパラメーターの値（有効期間の短い JWT）。
   - `/Chathub/` の後にある Chathub パスセグメント（例：`<oid>@<tenant>`）。

完全な URL は次の形式です。

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute で **Providers → Add Provider** に移動し、**Microsoft 365 Copilot
   (BizChat)** を選択して、次の形式で認証情報を貼り付けます。

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection**、続いて **Save** をクリックします。

## 認証情報の取得（HAR インポート）

WebSocket URL から値を手動でコピーする代わりに、DevTools の HAR ファイルをエクスポートできます。

1. **DevTools → Network** を開きます。
2. BizChat の会話を開始または続行します（これにより WebSocket 接続が開始されます）。
3. Network パネル内を右クリックし、**Save all as HAR with content** を選択します。
4. OmniRoute のプロバイダー接続ダイアログで、**Import .har file** ボタンを使用します。

OmniRoute は HAR 内で Chathub WebSocket URL を検索し、`access_token` と `chathubPath` を抽出して、認証情報フィールドへ自動的に入力します。HAR インポートでは JWT の有効期限がデコードされ、トークンの残り有効期間が表示されます。

> **実際の HAR エクスポート、アクセストークン、リフレッシュトークンは絶対にコミットしないでください。** テストおよびドキュメント内の値には、必ずプレースホルダーを使用してください。

## トークンの有効期間と更新

`access_token` は短期間のみ有効です（通常 **約 75 分**）。使用可能なリフレッシュ
トークンがない場合、有効期限が切れるたびに認証情報を再取得する必要があります。

### `refreshToken` による自動更新

Microsoft 365 プロバイダーの **接続を追加** または **接続を編集** ダイアログで、
**詳細設定 → リフレッシュトークン（任意）** を開きます。`substrate.office.com/sydney`
スコープ用の Microsoft OAuth リフレッシュトークンを貼り付けて保存します。入力値はマスクされ、
保存済みのトークンが事前入力されることはありません。編集時に既存のトークンを保持するには空欄のままにし、
新しいトークンを貼り付けると置き換えられます。

`substrate.office.com/sydney` をスコープに指定した Microsoft のデバイスコードまたは認証コードフローから
リフレッシュトークンを取得してください。ダッシュボードが自動的に取得することはありません。
リフレッシュトークンを設定すると、OmniRoute はリクエスト前に `access_token` を確認し、
更新が必要な場合にのみ更新します。更新が成功すると、ローテーションされたリフレッシュトークンも
保存されるため、リフレッシュトークンが有効である間は手動で再取得する必要がありません。

`refreshToken` が設定されていない場合、有効期限が切れるたびに WebSocket 認証情報を
手動で再取得する必要があります。

### 階層の選択

| 階層         | エイリアス     | サーフェス                      |
| ------------ | -------------- | ------------------------------- |
| `individual` | _(デフォルト)_ | コンシューマー向け M365 Copilot |
| `edu`        | `included`     | 教育機関向け M365 Copilot       |
| `enterprise` | `work`         | 職場向け M365 Copilot           |

階層は **詳細設定 → Copilot の階層** で設定します。この階層は
BizChat のルーティングとモデルへのアクセスに影響します。

## セキュリティモデル

- **非公式の統合。** このプロバイダーは BizChat WebSocket
  プロトコルをリバースエンジニアリングしています。Microsoft がエンドポイントを変更すると、予告なく動作しなくなる可能性があります。
- `subscriptionRisk: true` フラグは、この統合が文書化されていない
  エンドポイントに依存していることを示します。アカウントが制限される可能性はありますが、確認はされていません。
- アクセストークンは有効期間の短い JWT です。パスワードと同様に扱い、コミット、
  ログへの記録、共有を行わないでください。
- リフレッシュトークンは、BizChat サービスへの長期的なアクセスを許可します。
  API キーと同様に慎重に保管してください。

## トラブルシューティング

### 認証が直ちに失敗する

- **WebSocket URL** からコピーしたことを確認してください。XHR/Fetch リクエストからではありません。認証情報は Chathub WebSocket 接続の `access_token` クエリパラメーターにあり、`Authorization: Bearer` ヘッダーにはありません。
- `chathubPath` に、URL パスの完全な `<oid>@<tenant>` セグメントが含まれていることを確認してください。

### トークンが約 75 分後に期限切れになる

これは想定された動作です。`refreshToken` がない場合、アクセストークンの有効期間は短くなります。次のいずれかを行ってください。

- DevTools で認証情報を再取得する、または
- 接続の追加または編集ダイアログで、**詳細設定 → Refresh token（オプション）** を設定して自動更新を有効にする。

### 接続テストは成功するが、チャットで 401 が返される

検証から最初のリクエストまでの間に、トークンの有効期限が切れた可能性があります。新しい認証情報を再取得してください。

### プロバイダー一覧に Copilot が表示されない

**ダッシュボード → プロバイダー** で `copilot-m365-web` が有効になっていることを確認してください。一部のティアでは、プロバイダーがデフォルトで非表示になっている場合があります。
