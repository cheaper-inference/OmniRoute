## TL;DR — OmniRoute が実際に集約する無料推論の総量はどれくらいか？

これらの数値は、カタログ全体における個別のサードパーティアカウントと利用資格条件を示しています。OmniRoute がこの予算を付与するわけではありません。必要なアカウントまたは認証情報を取得し、利用資格のあるプロバイダーを接続し、それぞれの制限を遵守する必要があります。実際に利用可能な容量はこれより少なくなる場合があり、利用資格のあるルートがない新規インストールではゼロになることもあります。`tos: avoid` とマークされたプロバイダーは、デフォルトでは自動ルーティングから除外されます。

**確認日 2026-10-08:** [Cerebras](https://www.cerebras.ai/pricing) は、支払い方法の登録が必要で、30日後に期限切れとなる一度限りの $5 プロモーションクレジットを提供しています。[Gemini](https://ai.google.dev/gemini-api/docs/rate-limits) はプロジェクト、モデル、ティアごとのレート制限を公開していますが、定量化した月間の主要値には含めていません。

## 2026-10-18 SiliconFlow無料モデルの修正（#17028）

公開されているトークン単価が正の値であるSiliconFlowの主力モデル10件が、誤って
`recurring-uncapped`の無料アクセスとして提供されていました。この10行は静的
カタログから**削除**され、現在は**467エントリ**になっています。SiliconFlowは静的集計において、
無条件の無料モデル行にも、恒久無料プロバイダーにも含まれなくなりました。

これは、SiliconFlowに無料モデルがないという意味では**ありません**。無料モデル限定インポートとFreeバッジでは、
明示的な無料を示すブール値、または入力・出力双方のトークン価格がゼロであることなど、
**プロバイダーのライブモデルペイロードから得られる、モデルごとの肯定的な証拠**が必要になりました。明示的な有料フラグや、
正の数値価格は、楽観的な無料マーカーよりも優先されます。利用可能なライブ証拠が
存在しないモデルは、無料とは**見なされません**。新規アカウント向けの1回限りのクレジットは、
継続的な無料付与を証明するものではありません。現在のプロバイダーAPIから信頼できる
モデルレベルの価格情報を取得できない場合は、ルーティング前にプロバイダーのコンソールで確認してください。この保守的な
判断により、無料モデル限定インポートや自動組み合わせを通じた予期しない課金を防止します。

以下の過去のプロバイダーテーブルは、現在の利用可能性を保証するものではありません。以前の
SiliconFlowの上限なし／10モデルのエントリは、確立された継続的な無料付与を
表さなくなったため、意図的に削除されています。

## 2026-10-15 Bytez と Nous の修正

[Bytez の課金](https://docs.bytez.com/model-api/docs/billing)では、Free プランのオープンモデルが 7B パラメータまでに制限されています。70B および 72B のエントリは、購入したクレジットによるロック解除が必要なため削除されました。Mistral-7B は引き続き `recurring-credit` です。クレジットは 4 週間ごとに更新されますが、課金は推論秒単位であり、トークン枠は公開されていません。トークン数が 0 なのは、サポートされていない 100 万トークンという推定値を置き換え、数量が不明であることを表すためです。無料クレジットがゼロという意味ではありません。Nous の変更については、以下のプロバイダーノートで詳しく説明します。

## 2 つの方式 — 集計と判定

OmniRoute は、意図的に異なるソースを参照する 2 つの方式で「無料か？」という問いに答えます。

| 方式            | 信頼できる情報源                                                                                                                                                         | 対象                                                                                                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| **集計 / 表示** | 解決済みカタログ — 配布されるベースラインに Radar フィード（`getRadarCatalog`）を重ねたもの                                                                              | 無料枠の合計、予算カード、ダッシュボード                                                                                             |

## 方法論と注意事項

- 数値は、各プロバイダーが文書化している無料ティアの上限に基づく**上限見積もり**であり、**2026-06-17**時点でウェブ調査によって収集したものです。無料ティアは常に変更されるため、数値を前提にする前に再確認してください。
- **各エントリが実際に裏付けるもの。** 行ごとの信頼度評価を持つエントリはなく、APIもそのような情報を提供しません。上記の数値はすべて、同じ明示されていない品質の推定値として扱ってください。手作業でキュレーションされているため、推測によるものとは異なる事実が2つあります。44件のエントリには、独立して文書化されたハードストップがあり、そのうち39件は、すべて同じ日次上限を共有する xKiro の行です。また、22件のエントリにはプロンプト学習に関する開示があります。`hardStopGuaranteed` は、無料枠を超過した場合に、黙って課金を開始するのではなくリクエストを拒否するとプロバイダー自身の規約に記載されている場合にのみ設定され、出典はエントリの隣のコメントに記載されます。デフォルトで `true` に設定されることはなく、誰も検証していないエントリは未設定のままです。したがって、ハードストップフラグがないことは「未確立」を意味し、「課金されることがわかっている」という意味ではありません。**STRICT モード**（オプトインの `freeAccessPolicy=strict` ルーティングガード）は、このフラグを持つエントリのみを信頼します。それ以外の無料ティアは `no-hard-stop` として除外されます（`open-sse/services/autoCombo/strictZeroCostFilter.ts` を参照）。ガードがプールをフィルタリングすると、オペレーター向けログには除外数と、そのうち `no-hard-stop` が占める割合の両方が出力されます。
- `estMonthlyFreeTokens` は、継続的に利用できる月間トークンのみを表します。**一度限りのサインアップクレジットは繰り返し発生しない**ため、0として数えます。終了したティアも0です。
- 日次トークン上限 → `monthly = daily × 30`。RPD のみが文書化されている場合 → `RPD × ~800 output tokens × 30`。RPM/TPM のみ（日次上限なし）の場合 → **上限なし**（下記参照）。
- **無料アクセスはあるが、公開されたトークン上限がないもの**（`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`nvidia`）：これらはレートまたは同時実行数によって制限されます。`recurring-uncapped` に分類し、**決して合計しません**。`RPM × 24/7 × 30d` を掛けると、架空の上限値になってしまうためです（このような水増しは採用しません）。NVIDIA の API は試用利用のみです。下記の ToS に関する注意事項を参照してください。
- **デポジットによるロック解除ブースト：** 一度限りの少額チャージによって無料割当量が恒久的に増加します（OpenRouter：10ドル → 1日あたり1000リクエスト ≈ 月間+24M）。別の数値として報告し、定常的な見出しの数値からは除外します。
- **利用資格によってゲートされる割当量**（`eligibilityGate: "regional-identity"`）：地域に紐づく本人確認（現在は中国本土の実名認証）の完了後にのみ有効になる、実際の継続的な割当量です。別の数値（`gatedRecurringTokens`）に、同じプール重複排除ルールで加算し、定常的な見出しの数値には決して含めません。制度（`freeType`）は変わらないため、ルーティングは変わりません。
- **証拠の分類。** ルールは次のとおりです。カタログ内の数値は、エントリの隣にある `// evidence:` コメントで出典を示します。`public-page`（誰でも閲覧できるプロバイダーのページ）、`api-public`（プロバイダーの未認証エンドポイント。例：router.bynara.id にある NaraRouter の公開プランエンドポイント）、または `console-verified <date> por <who>`（数値はアカウントコンソール内でのみ表示されるもので、コメントには、それをいつ誰が確認したかと、上限の存在を示す公開ページが記録されます）。現在の状態は次のとおりです。2026-09-02 に再監査された5つのブロック（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）にはこの情報があります。2026-09-02 の再監査より前のエントリは、更新されるまで以前の調査結果を引き継ぎます。**新規または変更された**数値に証拠コメントがない場合はバグです。現在、コンソールで検証されているのは `mistral` のみです。

## 当社の数値が他のアグリゲーターより小さい理由

この分野で見られる「1 か月あたりの無料トークン」の数値の多くは、モデルごとに表示された値を合算したものです。当社では、意図的にそのような計算をしていません。

- **各共有プールは 1 回だけ計上します。** Mistral の無料プランは、組織ごとに月間 1B の単一枠として提供されています。これを 5 つのモデルに記載しても、5B になるわけではありません。モデルごとに合算すると、当社自身のカタログでも **~7.4B**（2026-09-03 に再計算。この数値は CI で検証されないため、カタログが変更されるたびに再測定してください）となりますが、見出しでは **~1.47B** としています。これは、各プロバイダーで 1 アカウントずつ使用した場合に実際に消費できる量だからです。
- **日次上限は換算しますが、レート制限は換算しません。** 文書化された 1 日あたりのトークン上限は `× 30`、文書化された 1 日あたりのリクエスト上限は `RPD × ~800 tokens × 30` として換算します。1 分あたりのリクエスト数のみを公開しているプロバイダーには月間値を設定せず、_上限なし_ と記載し、合算には含めません。レート制限を 24 時間 365 日稼働として乗算するような水増しは行いません。
- **地域別の本人確認が必要なクォータは別枠で表示します**（`+~6M behind regional identity verification`）。ほとんどの読者が利用できないためです。
- **サインアップクレジットは初月限定**であるため、定常的な数値には混ぜず、2 つ目の数値として報告します。
- **この数値は CI によって検証されます。** `npm run check:docs-counts` はカタログから合計を再計算し、このファイル、README、または予算カードの数値にずれがある場合はビルドを失敗させます。

## 用語集

| 用語                   | 意味                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------- |
| **RPM / RPD / RPH**    | 1 分あたり / 1 日あたり / 1 時間あたりのリクエスト数                                   |
| **TPM / TPD**          | 1 分あたり / 1 日あたりのトークン数                                                    |
| **文書化された付与枠** | プロバイダーが 1 日 / 1 か月あたりのトークン上限を明示していること（根拠を示せる予算） |
| **理論上の上限**       | `rate-limit × 24/7 × 30d` — 付与された予算ではなく、最大値                             |
| **Neuron**             | Cloudflare のコンピューティング単位（出力トークン約 1 個）                             |

> 2026-06-05 にプロバイダーごとの調査から生成。更新するには、調査ワークフロー（`_tasks/features-v3.8.12` を参照）を再実行してください。
