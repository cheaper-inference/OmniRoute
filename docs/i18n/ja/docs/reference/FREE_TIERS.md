## TL;DR — OmniRouteが実際に集約する無料推論量はどれくらいか？

これらの数値は、カタログ全体にわたる個別のサードパーティアカウントと利用資格条件を示しています。OmniRoute自体がこの予算を付与するわけではありません。必要なアカウントまたは認証情報を取得し、対象プロバイダーに接続して、それぞれの制限を遵守する必要があります。実際に利用できる容量はこれより少ない場合があり、対象ルートがない新規インストールではゼロになることもあります。`tos: avoid`と記載されたプロバイダーは、デフォルトでは自動ルーティングから除外されます。

**2026-10-08確認済み:** [Cerebras](https://www.cerebras.ai/pricing)は、支払い方法の登録が必要で30日後に期限切れとなる、1回限りの$5プロモーションクレジットを提供しています。[Gemini](https://ai.google.dev/gemini-api/docs/rate-limits)はプロジェクト/モデル/ティア別のレート制限を公開していますが、月間の主要集計値には引き続き含まれていません。

**正直な主要値:** _OmniRouteは、34個の無料枠プールから**月間約1.62Bの文書化された無料トークン**（サインアップクレジットを含む初月は最大約2.22B）を集約します。さらに、恒久無料かつ上限なしのプロバイダーが多数存在し、RTK + Caveman圧縮（15～95%のトークン節約）によって利用可能量をさらに伸ばせます。_

>
> **v3.8.42でさらに約1.37Bへ修正：** `longcat`の無料プレビュー終了後、150M/月の継続付与から、サインアップ時に一度だけ付与される10Mクレジットへ再分類されました。同じく実態に即した基準によるものであり、誤って削除されたプロバイダーはありません。
>
> **Felo Web廃止後の2026-08-26に更新：** Felo Webは、GPL由来の出自およびライセンスが保留中である間、対象外としています。この時点で、ソースではプールキーが38個と報告されていました。プール数は動的に算出され、CIで検証されています（上記の数値が`computeFreeModelTotals()`からずれると、`check:docs-counts`がビルドを失敗させます）。

> **2026-09-02に各プロバイダー自身のページを基に再監査**（出典：`open-sse/config/freeModelCatalog.data.ts`内で、再監査された各エントリの横にある`// evidence:`コメント）：`gemini`と`ollama-cloud`はトークン数を公開しなくなりました（Googleは2025-12-23にモデル別の無料枠表を削除し、OllamaのFreeプランは「スターター使用クレジット」とされています）。そのため、現在は**上限なし**として掲載し、合計には一切算入していません（−80M）。`groq`には、**モデルごと**に200K TPDの上限が5つあります（各6M、+15M）。廃止された3つのIDは削除されました。`nara`は7M/日の単一バケットです（+60M、210M）。`mistral`の1Bはアカウントコンソールでのみ確認できます。方法論の_Evidence classes_を参照してください。

## 2026-10-18 SiliconFlow無料モデルの修正（#17028）

公開されているトークン単価が正の値であるSiliconFlowの主力モデル10件が、誤って
`recurring-uncapped`の無料アクセスとして提供されていました。この10行は静的
カタログから**削除**され、現在は**467エントリ**になっています。SiliconFlowは静的集計において、
無条件の無料モデル行にも、恒久無料プロバイダーにも含まれなくなりました。

これは、SiliconFlowに無料モデルがないという意味では**ありません**。無料モデル限定インポートとFreeバッジでは、
明示的な無料を示すブール値、または入力・出力双方のトークン価格がゼロであることなど、
**プロバイダーのライブモデルペイロードから得られる、モデルごとの肯定的な証拠**が必要になりました。明示的な有料フラグや、
正の数値価格は、楽観的な無料マーカーよりも優先されます。利用可能なライブ証拠が
存在しないモデルは、無料とは**見なされません**。新規アカウント向けの1回限りのクレジットは、
継続的な無料付与を証明するものではありません。現在のプロバイダーAPIから信頼できる
モデルレベルの価格情報を取得できない場合は、ルーティング前にプロバイダーのコンソールで確認してください。この保守的な
判断により、無料モデル限定インポートや自動組み合わせを通じた予期しない課金を防止します。

以下の過去のプロバイダーテーブルは、現在の利用可能性を保証するものではありません。以前の
SiliconFlowの上限なし／10モデルのエントリは、確立された継続的な無料付与を
表さなくなったため、意図的に削除されています。

## 2026-10-15 Bytez と Nous の修正

[Bytez の課金](https://docs.bytez.com/model-api/docs/billing)では、Free プランのオープンモデルが 7B パラメータまでに制限されています。70B および 72B のエントリは、購入したクレジットによるロック解除が必要なため削除されました。Mistral-7B は引き続き `recurring-credit` です。クレジットは 4 週間ごとに更新されますが、課金は推論秒単位であり、トークン枠は公開されていません。トークン数が 0 なのは、サポートされていない 100 万トークンという推定値を置き換え、数量が不明であることを表すためです。無料クレジットがゼロという意味ではありません。Nous の変更については、以下のプロバイダーノートで詳しく説明します。

## 2 つの方式 — 集計と判定

OmniRoute は、意図的に異なるソースを参照する 2 つの方式で「無料か？」という問いに答えます。

| 方式            | 信頼できる情報源                                                                                                                                                         | 対象                                                                                                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| **集計 / 表示** | 解決済みカタログ — 配布されるベースラインに Radar フィード（`getRadarCatalog`）を重ねたもの                                                                              | 無料枠の合計、予算カード、ダッシュボード                                                                                             |
| **判定**        | 配布カタログのみ（`open-sse/config/freeModelCatalog.data.ts` の `FREE_MODEL_BUDGETS`）とローカルヒューリスティック（`:free` サフィックス、ゼロ価格、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` のすべての利用箇所：モデルのインポート、`auto/*` ルーティング、`GET /v1/models`、ブラウザプレビュー |

フィードが利用可能になるたびに、集計は改善できます。一方、判定はリリース成果物に固定されるため、ブラウザとサーバーで結果が一致し、オフラインでも再現可能で、データベースなしでテストできます。ブラウザプレビューとサーバー側のインポートが異なるソースを参照すると、プレビューの内容とクリック時の実際の動作が一致しなくなります。この分離は意図的に維持されています。

## 方法論と注意事項

- 数値は、ウェブ調査によって収集した、**2026-06-17** 時点で各プロバイダーが文書化している無料枠上限に基づく**上限推定値**です。無料枠は常に変更されるため、数値を利用する前に再確認してください。
- **各エントリが実際に保証する内容。** エントリごとの信頼度評価はなく、API からも提供されません。上記のすべての数値は、明示されていない同一水準の推定値として扱ってください。ただし、推測ではなく手動で管理されているため、次の 2 点は異なります。44 件のエントリには独立して文書化されたハードストップがあり（そのうち 39 件は xKiro の行で、すべて同じ 1 日あたりの枠を共有しています）、12 件のエントリにはプロンプトをトレーニングに利用する旨の開示があります。`hardStopGuaranteed` が設定されるのは、無料枠を超過した際に暗黙的に課金を開始するのではなく、リクエストを拒否するとプロバイダー自身の規約に記載されており、その出典がエントリ横のコメントに示されている場合のみです。デフォルトで `true` に設定されることはなく、誰も検証していないエントリでは未設定のままです。したがって、ハードストップフラグがないことは「確認されていない」という意味であり、「課金されることが判明している」という意味ではありません。**STRICT モード**（オプトインの `freeAccessPolicy=strict` ルーティングガード）は、このフラグを持つエントリのみを信頼します。それ以外の無料枠はすべて `no-hard-stop` として除外されます（`open-sse/services/autoCombo/strictZeroCostFilter.ts` を参照）。ガードがプールをフィルタリングすると、オペレーター向けのログに除外数と、そのうち `no-hard-stop` が占める割合の両方が記録されます。
- `estMonthlyFreeTokens` = 毎月繰り返し付与されるトークンのみ。**サインアップ時に一度だけ付与されるクレジットは繰り返し付与されない**ため、0 として数えます。廃止された枠も 0 です。
- 1 日あたりのトークン上限 → `monthly = daily × 30`。RPD のみが文書化されている場合 → `RPD × 約 800 出力トークン × 30`。RPM/TPM のみで 1 日あたりの上限がない場合 → **上限なし**（以下を参照）。
- **永続的に無料だが、公開されたトークン上限がないもの**（`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：これらは、レートまたは同時実行数に制限のある、実在する継続的な無料アクセスです。これらは `recurring-uncapped` に分類し、**合計には決して含めません**。`RPM × 24/7 × 30d` を計算すると、現実離れした上限値になってしまうためです（このような水増しは採用しません）。利用可能であることが分かるよう、一覧には掲載しています。
- **デポジットによるロック解除の増加分：** 少額を一度だけ入金することで、無料枠が恒久的に増加するものです（OpenRouter：$10 → 1000 リクエスト/日 ≈ +2400 万/月）。これは別の数値として報告し、継続的な主要合計には含めません。
- **利用資格によって制限される割り当て**（`eligibilityGate: "regional-identity"`）：地域に紐づく本人確認（現時点では中国本土の実名認証）を行った後にのみ利用可能になる、実在する継続的な割り当てです。同じプール重複排除ルールで別の数値（`gatedRecurringTokens`）として集計し、継続的な主要合計には含めません。方式（`freeType`）は変わらないため、ルーティングも変わりません。
- **証拠の分類。** ルール：カタログ内の数値は、そのエントリの横にある `// evidence:` コメントで出典を示します。分類は、`public-page`（誰でも閲覧できるプロバイダーのページ）、`api-public`（プロバイダーの認証不要エンドポイント。例：router.bynara.id にある NaraRouter の公開プランエンドポイント）、または `console-verified <date> por <who>`（数値がアカウントコンソール内でのみ確認可能であり、コメントには確認者と確認日、および上限の存在を記載した公開ページが記録されます）です。現時点では、2026-09-02 に再監査された 5 つのブロック（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）にこの情報があります。2026-09-02 の再監査より前から存在するエントリは、更新されるまで以前の調査結果を引き継ぎます。証拠コメントのない**新規または変更された**数値はバグです。現時点で console-verified なのは `mistral` のみです。

## 当社の数値が他のアグリゲーターより小さい理由

この分野で見られる「1 か月あたりの無料トークン」の数値の多くは、モデルごとに表示された値を合算したものです。当社では、意図的にそのような計算をしていません。

- **各共有プールは 1 回だけ計上します。** Mistral の無料プランは、組織ごとに月間 1B の単一枠として提供されています。これを 5 つのモデルに記載しても、5B になるわけではありません。モデルごとに合算すると、当社自身のカタログでも **~7.4B**（2026-09-03 に再計算。この数値は CI で検証されないため、カタログが変更されるたびに再測定してください）となりますが、見出しでは **~1.47B** としています。これは、各プロバイダーで 1 アカウントずつ使用した場合に実際に消費できる量だからです。
- **日次上限は換算しますが、レート制限は換算しません。** 文書化された 1 日あたりのトークン上限は `× 30`、文書化された 1 日あたりのリクエスト上限は `RPD × ~800 tokens × 30` として換算します。1 分あたりのリクエスト数のみを公開しているプロバイダーには月間値を設定せず、_上限なし_ と記載し、合算には含めません。レート制限を 24 時間 365 日稼働として乗算するような水増しは行いません。
- **地域別の本人確認が必要なクォータは別枠で表示します**（`+~6M behind regional identity verification`）。ほとんどの読者が利用できないためです。
- **サインアップクレジットは初月限定**であるため、定常的な数値には混ぜず、2 つ目の数値として報告します。
- **この数値は CI によって検証されます。** `npm run check:docs-counts` はカタログから合計を再計算し、このファイル、README、または予算カードの数値にずれがある場合はビルドを失敗させます。

## 用語集

| 用語                   | 意味                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------- |
| **RPM / RPD / RPH**    | 1分 / 1日 / 1時間あたりのリクエスト数                                                     |
| **TPM / TPD**          | 1分 / 1日あたりのトークン数                                                               |
| **明示された割り当て** | プロバイダーが明示的な1日 / 1か月あたりのトークン上限を公開していること（根拠のある予算） |
| **理論上の上限**       | `レート制限 × 24/7 × 30日` — 割り当てられた予算ではなく、最大値                           |
| **Neuron**             | Cloudflareのコンピューティング単位（約1出力トークン）                                     |
