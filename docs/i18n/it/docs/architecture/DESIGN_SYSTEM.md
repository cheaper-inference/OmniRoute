> **Stato:** la dashboard è costruita sul **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), incluso
> come vendored nel workspace `packages/ui-kit` (`@omniroute/ui-kit`; lo snapshot upstream è fissato in
> `packages/ui-kit/UPSTREAM.md` e protetto da `npm run check:ui-kit-snapshot`). Light è il tema
> canonico; la preferenza predefinita è `system`. L'accento è il lime Keak (`--ci-color-accent`). Inter
> (letter-spacing 0, `--ci-letter-spacing-ui`) è la famiglia tipografica dell'interfaccia, Instrument
> Serif solo per testo display grande e sparso (`.ci-dashboard-display`), IBM Plex Mono per il codice —
> tutti self-hosted tramite gli import `@fontsource/*` in cima a `src/app/globals.css`. Ogni icona è un
> glifo Lucide.

## 1. Dove si trovano le cose

- **Kit.** `packages/ui-kit/src` è una copia byte per byte del `src/` upstream al commit fissato in
  `packages/ui-kit/UPSTREAM.md` (che registra anche l'autorizzazione della licenza); `PATCHES.md` elenca
  le patch locali (nessuna). Viene consumato come sorgente, senza build: `next.config.mjs` lo transpila e
  `tsconfig.json` mappa `@omniroute/ui-kit` → `packages/ui-kit/src` e `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` (`vitest.config.ts` e `vitest.mcp.config.ts` riportano lo stesso alias). Importa
  un componente del kit tramite il suo subpath (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…),
  mai attraverso il barrel `@omniroute/ui-kit`: il barrel trascina tutti i componenti (incluso il date picker)
  in ogni modulo che lo importa. Il foglio di stile del kit viene incluso tramite `src/app/globals.css`
  (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **Token.** `packages/ui-kit/src/ci-tokens.css` dichiara i token `--ci-*`; `src/app/globals.css`
  li collega ai nomi legacy di OmniRoute (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`), così le letture esistenti di `var(--color-*)` e le
  utility Tailwind continuano a funzionare. Il nuovo codice usa le utility Tailwind (`bg-surface`,
  `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) o le classi del kit —
  mai un valore esadecimale (`tests/unit/design-kit-bridge.test.ts` impone il bridge). `text-primary`
  risolve a `--color-primary-ink` tramite `--text-color-primary` (lime-800 in chiaro, l'accento lime in
  scuro), così il testo primario resta leggibile mentre `bg-primary`/`border-primary` mantengono la
  superficie lime. Le serie dei grafici usano `--color-chart-1` … `--color-chart-5`.
- **Temi.** `<html className="ci-theme">` (`src/app/layout.tsx`) attiva il tema del kit per il documento.
  La preferenza è `light`, `dark` o `system` (`THEME_CONFIG.defaultTheme = "system"` in
  `src/shared/constants/appConfig.ts`; `system` segue `prefers-color-scheme`). `applyTheme()` in
  `src/store/themeStore.ts` (rispecchiata dallo script di bootstrap inline in `src/app/layout.tsx`, che
  viene eseguito prima dell'idratazione) imposta `data-theme="dark"|"light"` e attiva/disattiva la classe
  `.dark` su `<html>` in modo sincronizzato. Il set di token scuri del kit è legato a `data-theme="dark"`
  (`packages/ui-kit/src/ci-tokens.css`); gli override scuri propri di OmniRoute (il blocco `.dark` in
  `globals.css`) e le utility Tailwind legacy `dark:` si basano sulla classe `.dark`. Non esistono preset
  di colore per l'accento: l'accento proviene sempre dal kit, e un preset persistito da una build precedente
  viene scartato al caricamento dello store.
- **Componenti (adattatori).** `src/shared/components/index.tsx` mantiene l'API dei componenti di OmniRoute
  (stessi nomi, export di default e props), e le primitive sottostanti sono adattatori sopra il kit: form
  (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), overlay e feedback
  (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`),
  struttura (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) e tabelle
  (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). Un adattatore importa il
  componente del kit tramite subpath e mappa le props legacy su di esso — per esempio
  `Button variant="primary"` è il pulsante `default` del kit (`--ci-button-primary-*`: la superficie
  inversa in chiaro, l'accento con il suo inchiostro `--ci-color-accent-foreground` in scuro), `danger` è
  `destructive`, e `warning` è `outline` più l'estensione `.ci-button--warning`. Le regole
  `.ci-button--warning` e `.ci-badge[data-tone]` alla fine di `globals.css` (`@layer components`) sono
  estensioni di OmniRoute sopra le classi del kit. `tests/unit/ui/adapters/*.test.tsx` fissa ogni adattatore.
- **Shell.** `src/app/(dashboard)/layout.tsx` renderizza `DashboardLayout`, che renderizza
  `src/shared/components/layouts/DashboardShell.tsx`: i componenti del kit `SidebarProvider` / `Sidebar` /
  `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), con la logica di navigazione di OmniRoute in
  `src/shared/components/Sidebar.tsx`. Un link "salta al contenuto" verso `#main-content` è il primo
  elemento focalizzabile. `src/shared/components/Header.tsx` contiene il `SidebarTrigger` del kit (l'unico
  toggle della sidebar della shell), il `ProductSwitcher` di Keak e il pulsante di apertura della command
  palette; mostra il titolo della route solo quando nessun `PageHeader` del kit (`.ci-page-header`) è
  montato dentro `#main-content`, così una pagina con il proprio `PageHeader` ha un singolo `h1`.
  `src/shared/components/CommandPalette.tsx` è un `Dialog` del kit.
- **Icone.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) risolve il nome (il
  vocabolario Material Symbols usato dalle schermate) tramite `ICON_MAP`
  (`src/shared/constants/iconMap.ts`) in un glifo Lucide. Il font e il pacchetto Material Symbols sono
  stati rimossi: un nome assente dalla mappa renderizza un glifo segnaposto neutro
  (`data-icon-missing="true"`) e registra un avviso in console fuori dalla produzione.
  `npm run gen:icon-map` stampa i nomi in uso che mancano dalla mappa
  (`tests/unit/icon-map-coverage.test.ts` fallisce per qualsiasi nome senza un'icona Lucide;
  `tests/unit/icon-map-object-values.test.ts` copre i nomi memorizzati negli oggetti di lookup);
  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` riscrive gli span letterali
  `<span className="material-symbols-outlined">` in `<Icon>`.
- **Brand.** `src/shared/components/OmniRouteLogo.tsx` fa da wrapper attorno al kit: l'export di default
  `OmniRouteLogo` renderizza `ProductIcon product="omniroute" variant="glyph"` (SVG inline, sicuro rispetto
  a `basePath`) e `OmniRouteLockup` renderizza `ProductLockup product="omniroute"` (nome accessibile "Keak
  OmniRoute") oppure, per gli operatori white-label, il proprio `name`/`logoSrc`. Le destinazioni del
  product switcher si trovano in `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`,
  `KEAK_ACTIVE_PRODUCT`). Le schermate standalone — `src/app/login/page.tsx`, `src/app/status/page.tsx`,
  `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` e
  `src/shared/components/ErrorPageScaffold.tsx` — mostrano il lockup;
  `tests/unit/brand-pages-static.test.ts` lo protegge.

## 2. Regole

1. Token, mai valori letterali. Eccezioni mantenute di proposito: il terminale della console sempre
   scuro, i tratti SVG di ReactFlow tramite `STATUS_HEX` (`src/shared/constants/statusColors.ts`) e le
   palette categoriche `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) e
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`).
2. Non correggere mai manualmente `packages/ui-kit/src`: sincronizza con `scripts/dev/sync-ui-kit.sh <commit>`; il
   gate di pre-commit `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) fallisce su qualsiasi byte che
   differisca dal commit upstream fissato (viene saltato con un avviso quando il clone upstream,
   `UI_KIT_CLONE` oppure `_references/cheaper-inference-ui-kit`, è assente). Quando il kit non offre qualcosa,
   aggiralo nell'adapter o nella schermata e richiedilo a monte.
3. I testi predefiniti del kit sono in inglese (`label = "Loading"`, `loadingLabel = "Loading table"`…) — passa le
   stringhe tradotte da `useTranslations(...)` ogni volta che un componente del kit rende del testo.
4. Le utility Tailwind hanno la precedenza sulle classi dei componenti del kit (il kit dichiara
   `@layer theme, base, components, utilities` e le sue regole vivono in `components`) — usa le utility per
   spaziatura e layout, non per ricolorare i componenti del kit.
5. Titoli: `.ci-heading` (Inter, senza tracking) per i titoli di pagina e di sezione; `.ci-dashboard-display`
   (Instrument Serif) solo per testo display grande e rado, come il codice di stato della pagina di errore.
6. `tests/unit/dashboard-kit-sweep.test.ts` presidia l'adozione del kit: nessuno span con ligature Material sotto
   `src/app` o `src/shared/components`; nell'albero della dashboard (`src/app/(dashboard)` e
   `src/shared/components`) nessun `<select>`, `<textarea>` o `<table>` grezzo e nessun
   `role="dialog"` fatto a mano al di fuori delle eccezioni elencate (il ramo nativo dell'adapter `Select`,
   `RequestLoggerDetail`); ogni `<button>` o `<input>` grezzo lì presente richiede un commento contenente
   `kit-exception:` (con il motivo) che termini al massimo 3 righe sopra di esso; tonalità di palette e varianti
   `dark:` solo nei file elencati dal test.
7. Verifica entrambi i temi e il viewport da 390 px prima di una PR (screenshot); `tests/e2e/a11y.spec.ts` esegue
   axe.

## 3. Aggiungere una schermata

1. Apri la pagina con il `PageHeader` del kit (`@omniroute/ui-kit/page-header`, `compact` all'interno della
   dashboard) — titolo, descrizione e `actions`. L'header della shell rinuncia quindi al proprio titolo.
2. Costruisci i controlli a partire da `@/shared/components` (gli adapter) e usa i componenti del kit tramite
   sottopercorso dove non esiste un adapter (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`,
   `RadioGroup`, `Slider`…).
3. Icone: `<Icon name="…" />`. Un nuovo nome va inserito in `ICON_MAP` con il componente Lucide semanticamente
   corrispondente; `npm run gen:icon-map` elenca i nomi ancora mancanti.
4. Colori: utility semantiche (`text-success`, `bg-warning-bg`, `border-border`…) e
   `var(--color-chart-N)` per le serie dei grafici; nessun valore esadecimale e nessuna variante `dark:` che si
   limiti a ripetere un colore.
5. Testo: ogni stringa, incluse le etichette che passi ai componenti del kit, proviene da `useTranslations`. Le
   nuove chiavi vanno in `src/i18n/messages/en.json`, `pt-BR.json` e `vi.json` (il test di parità vietnamita
   fissa ogni chiave inglese); le altre localizzazioni vengono compilate dalla sincronizzazione i18n.
6. Esegui i controlli prima della PR: `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (l'unico controllo che intercetta un import duplicato in `iconMap.ts`),
   `npm run check:ui-icu` e i test specifici della schermata.

## 4. Aggiungere o modificare un adapter

1. Mantieni l'API pubblica di `src/shared/components/index.tsx`: stessi nomi di export, default export e
   prop accettate. Mappa le prop legacy sul kit all'interno dell'adapter (vedi `Button.tsx`: `VARIANT_TO_KIT`,
   `SIZE_TO_KIT`).
2. Importa il kit tramite subpath (`@omniroute/ui-kit/<component>`).
3. I workaround per le lacune del kit risiedono nell'adapter (o in `globals.css` `@layer components` quando la
   correzione è uno stile), mai in `packages/ui-kit/src`.
4. Aggiungi o aggiorna `tests/unit/ui/adapters/<name>.test.tsx`. Per un adapter con molti chiamanti, confronta
   il markup renderizzato prima e dopo la modifica — le modifiche a padding o wrapper si propagano a ogni schermata.

## 5. Aggiornare il kit

`scripts/dev/sync-ui-kit.sh <commit> [clone]` copia l'`src/` upstream a quel commit in
`packages/ui-kit/src` e applica l'unica trasformazione consentita (rimuove il suffisso `.js` dagli
import relativi). Poi: rivedi `git diff packages/ui-kit`, fai un controllo visivo su providers, settings, combos,
usage ed endpoint in entrambi i temi, esegui `npm run check:ui-kit-snapshot` e `npm run test:vitest:ui`, e
apri la PR con il changelog upstream.
