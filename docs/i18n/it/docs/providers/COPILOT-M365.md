`copilot-m365-web` (alias `m365copilot`) invia richieste di chat in formato OpenAI tramite una sessione Microsoft 365 Copilot autenticata su `m365.cloud.microsoft/chat`. Si tratta di un'integrazione nativa non ufficiale: non è richiesto alcun processo proxy separato o localhost upstream. Il provider ID, l'alias e le connessioni importate esistenti rimangono invariati. `copilot-web` è un fornitore diverso per il servizio al consumatore su `copilot.microsoft.com`.

> **Nuovo per i fornitori di cookie Web?**
>
> Leggere**`docs/getting-started/WEB-COOKIE-GUIDE.md`** per il processo di configurazione generale, le indicazioni per l'autenticazione, le limitazioni e la risoluzione dei problemi prima di seguire questa guida specifica del provider.
>
> **Per le importazioni precedenti:** La credenziale per questo fornitore è** non un biscotto** . Non copiare i cookie da `m365.cloud.microsoft`. La credenziale è un parametro di query WebSocket URL e un segmento di percorso, entrambi letti dalla scheda Rete DevTools.

## Prerequisiti

- Un account Microsoft 365 con accesso a Copilot su `m365.cloud.microsoft/chat`
- Un browser basato su Chromium (Chrome, Edge) per l'ispezione DevTools WebSocket
- Accesso al modello richiesto su quell'account; la disponibilità varia in base al locatario e alla licenza

## Accesso nativo (account aziendali o scolastici)

Scegliere**Microsoft 365 Copilot → Connetti** e preparare un tentativo di accesso. La dashboard utilizza un flusso di codice di autorizzazione con PKCE; non richiede la password Microsoft o il codice MFA.

1. Apri un** scheda del browser vuota** , quindi aprire**DevTools → Rete** e abilitare** Conserva registro** . Fallo prima di passare a Microsoft: Windows SSO potrebbe terminare immediatamente.
2. Copia l'autorizzazione URL mostrata dalla finestra di dialogo di connessione e raggiungila nella scheda preparata. Completa la selezione dell'account Microsoft o MFA se richiesto.
3. Nel registro di rete conservato, trova la richiesta a `https://login.microsoftonline.com/common/oauth2/nativeclient` e copiala per intero** Richiedi URL** .
4. Incolla URL nella finestra di dialogo di connessione e connettiti. Non incollare un codice grezzo o la barra degli indirizzi `wrongplace` finale URL: la richiamata richiesta è una navigazione temporanea.

Ogni tentativo scade dopo dieci minuti e può essere utilizzato una sola volta. Il server controlla il suo stato, il verificatore PKCE e il target di riautenticazione prima di scambiare il codice. Dopo la scadenza o un errore di scambio, avviare un nuovo tentativo. Un tentativo non può sopravvivere al riavvio del server.

I token utilizzano l'archivio credenziali di connessione esistente e il percorso di aggiornamento. La riautenticazione di una connessione richiede la stessa identità Microsoft tenant/object, non semplicemente la stessa email. Conserva l'operatore naming/settings e sostituisce le credenziali importate obsolete. L'accesso nativo è per gli account work/school ; il percorso di importazione legacy rimane disponibile per le connessioni esistenti e le configurazioni di livello supportate.

La richiamata completa URL è una credenziale utilizzabile una sola volta. Non includerlo mai in screenshot, log, messaggi di supporto o commit. Questo flusso non apre un browser sul server, non controlla la cronologia del browser né avvia un server di richiamata locale.

## Cattura credenziali (metodo WebSocket )

1. Accedi a `https://m365.cloud.microsoft/chat` e inizia una conversazione.
2. Aprire**DevTools → Rete** .
3. Filtra per**WS** (WebSocket).
4. Fare clic sulla connessione Chathub WebSocket. Cerca uno URL che inizi con `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Dal suo** Richiedi URL** , copia:
   - Il valore del parametro di query `access_token` (uno JWT di breve durata).
   - Il segmento del percorso Chathub dopo `/Chathub/` (ad esempio `<oid>@<tenant>`).

La URL completa ha la forma:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. In OmniRoute, seleziona**Microsoft 365 Copilot** , scegli l'opzione legacy API-key/import e incolla la credenziale nel formato:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Clic** Prova connessione** E** Salva** .

## Cattura credenziali (importazione HAR )

Invece di copiare manualmente i valori da URLWebSocket puoi esportare un file DevTools HAR :

1. Aprire**DevTools → Rete** .
2. Avvia o continua una conversazione Microsoft 365 Copilot (questo attiva la connessione WebSocket ).
3. Fare clic con il tasto destro nel pannello Rete e selezionare** Salva tutto come HAR con contenuto** .
4. In OmniRoute, usa il file** Importa il file .har** pulsante nella finestra di dialogo di connessione del provider.

OmniRoute esegue la scansione di HAR per Chathub WebSocket URL, estrae `access_token` e `chathubPath` e popola automaticamente i campi delle credenziali. L'importazione HAR decodifica la scadenza JWT e mostra la durata rimanente del token.

> **Non eseguire mai il commit di un'esportazione HAR reale, di un token di accesso o di un token di aggiornamento.** I valori di test e documentazione devono sempre essere segnaposto.

## Durata e aggiornamento del token

La `access_token` è di breve durata (tipicamente**~ 75 minuti** ). Senza un token di aggiornamento utilizzabile, è necessario acquisire nuovamente la credenziale dopo la scadenza.

### Aggiornamento automatico con `refreshToken`

Nel fornitore Microsoft 365** Aggiungi connessione** O** Modifica connessione** finestra di dialogo, aprire** Impostazioni avanzate → Aggiorna token (opzionale)** . Incolla un token di aggiornamento Microsoft OAuth per l'ambito `substrate.office.com/sydney` e salva. L'input è mascherato e non è mai precompilato con il token archiviato. Durante la modifica, lascialo vuoto per mantenere il token esistente; incolla un nuovo token per sostituirlo.

L'accesso nativo acquisisce il token di aggiornamento quando Microsoft ne restituisce uno. Per le importazioni legacy, utilizzare una concessione del codice di autorizzazione Microsoft compatibile esistente; questo fornitore non implementa né promette un flusso di codice dispositivo. Con un token di aggiornamento configurato, OmniRoute controlla `access_token` prima delle richieste e lo aggiorna solo quando è necessario aggiornarlo. Un aggiornamento riuscito mantiene inoltre il token di aggiornamento ruotato, evitando la nuova acquisizione manuale mentre il token di aggiornamento rimane valido.

Se `refreshToken` non è impostato, è necessario acquisire nuovamente le credenziali WebSocket manualmente dopo ogni scadenza.

È stato riferito che un inquilino di lavoro ha limitato i toni "Pensa più profondamente" mentre i toni rapidi continuavano a essere pubblicati; tale ambito è un'osservazione del consumatore, non qualcosa che questo repository ha riprodotto. Il routing quindi porta fuori rotazione anche gli altri modelli documentati Think Deep di `gpt-5.5` e `gpt-5.6` su quella connessione per lo stesso tempo di recupero e lascia i toni rapidi e ogni altro errore sul proprio modello. I suggerimenti per i nuovi tentativi forniti vengono conservati; un ripristino mancante non viene pubblicizzato come tempo di ripristino noto.
- Ritorna un rifiuto di sicurezza Copilot (`Disengaged`).** 400** `provider_safety_rejection`, l'etichetta di sosta di sicurezza del fornitore condiviso. Non conta mai per l'integrità della connessione, il client SDKs non riprova un 400 e con `PROVIDER_SAFETY_STOPS_TERMINAL` abilitato il routing combinato si ferma lì invece di riprodurre la richiesta contro un'altra destinazione.
- Le richieste su una connessione vengono serializzate tramite il semaforo dell'account esistente. Preferire il fallback prioritario piuttosto che i pannelli paralleli; la serializzazione da sola non elimina i limiti della velocità di conversazione di Microsoft.

## Richiedere comportamenti e limiti

- Gli strumenti sono** emulato dal prompt** , non chiamate di funzione Microsoft native. Una richiesta abilitata allo strumento utilizza una generazione bufferizzata; non passa un'altra generazione a selezionare gli strumenti. Solo gli strumenti dichiarati con forme di argomento supportate valide vengono restituiti come chiamate.
- Una risposta lunga e strutturata con un unico esempio finale viene conservata come prosa. Questa è un'euristica, non una prova di intenti; le applicazioni devono comunque applicare le proprie autorizzazioni per lo strumento.
- L'input dell'immagine funziona nel modo in cui lo invia il client Web. Ogni parte dell'immagine (`image_url` come URL di dati o HTTPS URL pubblica o `input_image` di risposta ) viene caricata su `/m365Copilot/UploadFile` nella conversazione del turno con il token della chat e il messaggio la punta con un'annotazione `ImageFile` ; il testo indica dove si trovava (`[image 1]`, ...). Una nuova conversazione carica tutte le immagini nella cronologia, una continua solo le immagini dei nuovi messaggi. Fino a 10 immagini PNG, JPEG, GIF o WebP da massimo 10 MiB ciascuna (40 MiB per richiesta); il formato viene letto dai byte. HTTPS URLs vengono recuperati tramite la protezione dell'immagine remota bloccata solo dal DNS. Un caricamento non riuscito non soddisfa la richiesta (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` o `m365_image_invalid`); una svolta non va mai avanti senza che gli sia stata data un'immagine. Altre parti non testuali (audio, file) vengono rifiutate esplicitamente, non eliminate silenziosamente.
- Una richiesta di follow-up continua la stessa conversazione a monte e invia solo i messaggi dopo la risposta precedente. Deve estendere esattamente quella risposta: stessa connessione, profilo del modello e set di strumenti; una cronologia invariata (una catena sha256 su ogni messaggio); e gli ID di chiamata dello strumento della risposta o il suo testo fino agli spazi bianchi. Qualsiasi altra cosa (una cronologia modificata, un'altra sessione con lo stesso primo messaggio, una risposta diversa, una conversazione inattiva per 30 minuti o vicina al limite di 600 messaggi di Copilot, una connessione senza ID) avvia una nuova conversazione con l'intera cronologia. Una svolta fallita non viene mai ripresa e uno `InternalError` senza contenuto viene inviato nuovamente una volta in una nuova conversazione (** 502** `m365_internal_error` se fallisce di nuovo). Le continuazioni vengono mantenute nella memoria del processo: un riavvio avvia nuove conversazioni.
- Ogni turno viene eseguito nella chat temporanea di Copilot(`disableMemory=1`): la conversazione mantiene il suo contesto mentre viene eseguita e non appare mai nella cronologia chat dell'account. I test modello, Test All e test combinati possono quindi sondare questo fornitore senza lasciare indietro le conversazioni.
- Un turno ha una scadenza inattiva di 120 secondi e una scadenza complessiva delimitata. Le risposte finali, il filtraggio dell'avanzamento e l'annullamento sono gestiti dal transport/composer. nativo
- Le risposte basate sul Web mantengono le loro fonti. Copilot contrassegna una citazione in linea con caratteri di controllo per uso privato e invia le fonti come `references`; ogni marcatore diventa un collegamento Markdown numerato (`[1](https://…)`, o il semplice URL quando Copilot utilizzava il marcatore come destinazione del collegamento) con un'annotazione `url_citation` corrispondente (`message.annotations` o `delta.annotations` sul pezzo che trasporta il collegamento). Una fonte che non arriva mai viene eliminata, quindi i marcatori non raggiungono mai il client. Durante lo streaming, il testo dopo una citazione attende finché non arriva la sua fonte.
- Il riepilogo del ragionamento di Copilot(`ChainOfThoughtSummary`), quando il modello ne invia uno, viene restituito come `reasoning_content`, mai come parte della risposta. Una sintesi che si riscrive ferma lo streaming senza fallire la svolta.
- Prima di qualsiasi contenuto, gli errori licence/throttle mantengono HTTP 403/429 anche quando è stato richiesto lo streaming. Dopo l'avvio del contenuto, gli errori sono eventi di errore SSE e mai un completamento riuscito. Una riscrittura upstream che non può essere rappresentata dallo streaming di sola aggiunta è un errore di flusso esplicito; le risposte dello strumento non in streaming e memorizzate nel buffer mantengono il testo finale.
- Quando Copilot rifiuta la connessione stessa, la sua risposta viene riportata così com'è:** 401** `m365_unauthorized` per un accesso rifiutato o scaduto (accedi di nuovo),** 429** con il suo `Retry-After` per la limitazione e altrimenti un errore di handshake, mai un errore di connessione generico.

## Generazione di immagini

`POST /v1/images/generations` con `model: "copilot-m365-web/m365-copilot-image"` (alias `m365copilot/m365-copilot-image`) disegna con lo strumento di immagine integrato di Copilot, come fa il client web. Ogni immagine è un turno Copilot : si attiva con i set di opzioni dell'immagine del client Web e dichiara `GenerateGraphicArt` e l'immagine arriva su una voce di avanzamento che punta a un artefatto sul servizio Designer di Microsoft. Quell'artefatto rifiuta il token della chat, quindi OmniRoute conia un token Designer dal token di aggiornamento della connessione e scarica i byte; il token viene inviato sempre e solo a `designerapp.officeapps.live.com`.

- Richiede una connessione di accesso nativa (un token di aggiornamento); un token incollato fallisce** 400** prima che venga speso qualsiasi turno.
- `n` è 1–4, un turno ciascuno. `size` controlla solo l'orientamento (più largo, più alto o quadrato), che Copilot legge dal prompt; Copilot sceglie la dimensione di rendering.
- Le immagini vengono restituite in linea: `b64_json` per impostazione predefinita, un dato URL per `response_format: "url"`.
- Le immagini generate utilizzano un piccolo budget giornaliero, separato dalla chat. Quando è esaurito, la richiesta fallisce** 429** . Una svolta che risponde senza un'immagine fallisce** 502** (O** 400** /** 503** quando il testo di Copilot si legge come rifiuto o problema di capacità); il messaggio dice quale.

## Modello di sicurezza

- **Integrazione non ufficiale.** Questo provider esegue il reverse engineering del protocollo BizChat WebSocket. Potrebbe rompersi senza preavviso quando Microsoft cambia l'endpoint.
- Il flag `subscriptionRisk: true` riflette che l'integrazione si basa su un endpoint non documentato. Le restrizioni sull'account sono possibili ma non confermate.
- Il token di accesso è uno JWT di breve durata. Trattalo come una password: non impegnarlo, registrarlo o condividerlo.
- Il token di aggiornamento garantisce l'accesso continuo alla superficie Microsoft 365. Conservatela con la stessa cura di una chiave API.

## Risoluzione dei problemi

### L'autenticazione fallisce immediatamente

- Verify you copied from the **WebSocket URL**, not from an XHR/Fetch request. The credential is in the `access_token` query parameter of the Chathub WebSocket connection — not in an `Authorization: Bearer` header.
- Assicurati che `chathubPath` includa l'intero segmento `<oid>@<tenant>` dal percorso URL.

### Il token scade dopo ~ 75 minuti

Questo è previsto. Senza `refreshToken` il token di accesso ha vita breve. O:

- Acquisisci nuovamente le credenziali da DevTools, o
- Configura** Impostazioni avanzate → Aggiorna token (opzionale)** nella finestra di dialogo Aggiungi o modifica connessione per l'aggiornamento automatico.

### Il test della connessione viene superato ma la chat restituisce 401

Per una connessione creata con** Accedi con Microsoft** , Test Connection controlla la scadenza del token di accesso e rinnova un token scaduto con il token di aggiornamento archiviato, quindi un test superato dimostra anche che il token di aggiornamento funziona ancora.

Per una credenziale incollata, Test Connection controlla la forma della credenziale e, quando il token ha una scadenza, che il token che il provider utilizzerà non sia scaduto (il token archiviato della connessione vince un incolla obsoleto; un token di aggiornamento conta come rinnovabile). Un token revocato prima della scadenza supera comunque il test; chat poi ritorna** 401** `m365_unauthorized`. Utilizzo** Accedi con Microsoft** nuovamente o acquisire nuovamente una nuova credenziale.

### Copilot non appare nell'elenco dei fornitori

Assicurati che `copilot-m365-web` sia abilitato** Fornitori → del dashboard** . Il provider potrebbe essere nascosto per impostazione predefinita in alcuni livelli.
