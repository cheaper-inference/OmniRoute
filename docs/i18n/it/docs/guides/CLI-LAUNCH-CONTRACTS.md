Il contratto `config/cli-tools-manifest.json` neutro dichiara IDs canonico, alias, candidati binari, ricette di installazione, argomenti e capacità del modello. Il semplice adattatore Node in `bin/cli/cli-manifest.mjs` e l'adattatore TypeScript in `src/shared/constants/cliIntegrationManifest.ts` leggono lo stesso file. Runtime, catalogo, configurazione, completamento, generatori e registrazione del backend vengono controllati insieme da `tests/unit/cli/cli-manifest-drift.test.ts`. Essere catalogato non significa che uno strumento possa essere lanciato o configurato. In particolare, 5dive rimane di sola configurazione.

## Ambiente e ciclo di vita del bambino

`omniroute run`, `omniroute launch` e `omniroute launch-codex` ereditano una lista consentita di compatibilità OS/terminal e iniettano le credenziali della destinazione selezionata. I segreti del database e del provider non correlati non vengono ereditati per impostazione predefinita. `--inherit-env` ripristina esplicitamente l'eredità completa dell'ambiente genitore; utilizzarlo solo quando il processo di terze parti selezionato deve ricevere tali valori. Si tratta di un filtraggio dell'ambiente, non di un sandbox OS : il processo viene comunque eseguito con le autorizzazioni del filesystem del chiamante.

I segnali di interruzione e terminazione vengono inoltrati al bambino. Il programma di avvio attende l'evento di chiusura del bambino prima di rimuovere la configurazione temporanea. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` controlla il periodo di grazia prima della terminazione forzata (predefinito 5000 millisecondi).

## Gemini configurazione persistente

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

I primi due comandi configurano questa macchina per il server locale o remoto selezionato. Il programma di installazione conserva le impostazioni JSON non correlate, seleziona l'autenticazione della chiave API Gemini e scrive l'endpoint e le credenziali in un file `.gemini/.env` privato. Rifiuta JSON non valido anziché sovrascriverlo. L'endpoint URLs deve essere HTTP(S), senza credenziali incorporate, parametri di query o frammenti. L'esecuzione di prova stampa i percorsi, non i valori delle credenziali.

`GEMINI_CLI_HOME` o `--gemini-home` seleziona la radice home persistente. Un vero e proprio `run gemini` crea e successivamente rimuove la propria sede temporanea. Nessuna delle due modalità ignora i controlli di attendibilità dello spazio di lavoro di Gemini.

## profili Codex

`configure codex` scrive uno `<name>.config.toml` privato con un modello e il relativo endpoint del provider OmniRoute. Si fa riferimento alle credenziali tramite `OMNIROUTE_API_KEY`, mai incorporate. Il comando launch imposta il modello selezionato sul tasto `model` di livello superiore, non all'interno `model_providers`.

File di profilo separati costituiscono l'attuale contratto Codex documentato; si sovrappongono alla configurazione dell'utente quando selezionati con `codex --profile <name>`. Vedi [il riferimento del profilo ufficiale](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) e [la guida OmniRoute Codex](./CODEX-CLI-CONFIGURATION.md).

## Esecuzione ermetica dei comandi

Con un `DATA_DIR` esplicito, l'impostazione `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` impedisce che l'avvio ricada nell'ambiente delle credenziali della directory dei dati utente predefinita. Ciò è utile per i test isolati. Non disabilita altri file di ambiente selezionati esplicitamente.

## Directory di lavoro `.env`

CLI legge i file `.env` in questo ordine e vince il primo file che imposta una chiave: l'esplicito `DATA_DIR`, la directory dei dati predefinita, la directory di lavoro corrente, quindi la directory del pacchetto. Le variabili di shell vincono sempre.

La directory di lavoro può appartenere a qualcun altro (un repository clonato, un archivio decompresso) e `omniroute serve` passa l'ambiente CLI al server e ad ogni strumento eseguito dal server. Quindi uno `.env` può impostare solo queste chiavi, elencate in `bin/cli/utils/untrustedCwdEnv.mjs`:

| Chiave                          | Valori accettati                                                               |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `REQUIRE_API_KEY`               | `true`, `1` o `yes` in ogni caso, i valori che il server considera come attivi |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | fino a 64 lettere, cifre, `_`, `.`, `@` o `-`                                  |
| `LANGUAGE`                      | lo stesso, più `:`                                                             |
| `TZ`                            | fino a 64 lettere, cifre, `_`, `+`, `-` o `/`, che non iniziano con `/`        |
| `NO_COLOR`, `FORCE_COLOR`       | fino a 16 lettere e cifre                                                      |

Ogni valore accettato `REQUIRE_API_KEY` attiva il controllo, quindi il file non può disattivare il controllo da solo. Tuttavia, non decide il risultato: il server legge un override `REQUIRE_API_KEY` memorizzato nel database prima dell'ambiente, mentre l'avviso di avvio sull'ascolto su tutte le interfacce senza una chiave API legge solo l'ambiente. Con un override memorizzato di `false`, una directory di lavoro `REQUIRE_API_KEY=true` lascia API aperto e nasconde l'avviso. La regola `TZ` è più ristretta di POSIX: rifiuta `.`, `:`, `,` e `<>`, quindi la forma `:Area/City` e le regole come `EST5EDT,M3.2.0,M11.1.0` devono essere impostate nella shell o in `<DATA_DIR>/.env`.

I nomi devono corrispondere esattamente, in maiuscolo. Qualsiasi altra riga, un valore che non supera il controllo e un nome che non sia composto da semplici lettere ASCII, cifre e `_` (ad esempio uno con un byte NUL o una lettera simile) vengono saltati. CLI stampa un avviso che nomina le chiavi che non può impostare e uno che nomina le chiavi consentite che ha ignorato, ciascuno con cosa modificare (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Nessuno dei due stampa i valori. I percorsi dei file in questi messaggi e il percorso `.env` riportato da `omniroute doctor` vengono sottoposti a escape quando contengono caratteri di controllo o bidi. La restrizione non si applica quando la directory di lavoro è la directory dei dati o la directory del pacchetto.

`PORT`, `API_PORT` e `DASHBOARD_PORT` non sono nell'elenco. Senza una base URL da una fonte con precedenza più elevata, CLI comunica con `localhost:<PORT>` e qualunque cosa sia in ascolto riceve la chiave API di CLI, il token di contesto e il token della macchina CLI (`x-omniroute-cli-token`, vedere [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), che il server locale accetta per le chiamate di gestione dal loopback. Una porta dalla directory di lavoro consentirebbe a quel file di scegliere il listener, quindi imposta le porte nella shell, in `<DATA_DIR>/.env` o con l'opzione `--port` dei comandi che ne hanno una (`serve`, `launch`, `run`).

Il parser non ha sintassi `export`. Una riga come `export LD_PRELOAD=...` nomina una variabile `export LD_PRELOAD`; dalla directory di lavoro viene saltato e in altri file `.env` imposta quel nome letterale, che nulla legge.

CLI accoppia il token memorizzato di un contesto (token di accesso o chiave API legacy) solo con l'origine propria di quel contesto: schema, host e porta, rispetto a `URL.origin`. Questo si applica alle richieste effettuate tramite il client HTTP di CLI(`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) e ai comandi `launch`, `launch codex`, `configure` e `setup-*` che scrivono una base URL e una chiave nella configurazione di un altro strumento. Puntati su un altro server con `--remote`, utilizzano uno `--api-key` o `OMNIROUTE_API_KEY` esplicito se impostato e nessun token di contesto. Il confronto è esatto, quindi `localhost` e `127.0.0.1`, o un host con e senza punto finale, contano come server diversi e non ottengono alcun token di contesto. Uno URL con userinfo, una barra rovesciata o uno spazio bianco non corrisponde mai, perché altri parser URL ( `urllib` e `httpx` di Python, ad esempio) possono leggere un host diverso da esso. Per le richieste che CLI invia da solo, il controllo copre solo lo schema e l'autorità, quindi un ID con uno spazio nel percorso o nella query mantiene il token.
