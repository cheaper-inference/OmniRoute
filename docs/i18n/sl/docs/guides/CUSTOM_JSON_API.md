Vozlišče JSON API po meri povezuje poslovno končno točko JSON, ki ne govori protokola OpenAI ali Anthropic. OmniRoute izpolni predlogo zahteve JSON, jo pošlje na celotno končno točko URL, prebere odgovor s poti odgovora in ga vrne odjemalcu v odjemalčevem lastnem formatu (zaključki klepeta, odgovori, sporočila, ...).

Je vozlišče, združljivo z OpenAI, z `apiType: "custom-json"`; njegov ID ima obliko `openai-compatible-custom-json-<suffix>`. Obrazec nadzorne plošče še ni na voljo. Ustvarite in uredite ta vozlišča prek spodnjega vozlišča ponudnika API.

## Ustvarite vozlišče

`POST /api/provider-nodes` (avtor upravljanja):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` je** popolna** končna točka URL. Nič ni pripeto (ni `/chat/completions`, ne `/models`) in za razliko od drugih vozlišč, združljivih z OpenAI, ni privzetega URL. Biti mora `http(s)`, brez vdelanih poverilnic ali `#fragment`, in mora prepustiti isto izhodno zaščito URL kot vsako vozlišče ponudnika, tako ko je vozlišče shranjeno kot pri vsaki zahtevi.
- Vozlišče, ki pošlje povezovalni ključ (`authType` `bearer` ali `api-key`, vključno s privzetim), mora uporabljati `https://`. Navadni `http://` je sprejet samo za gostitelja s povratno zanko (`localhost`, `127.0.0.0/8`, `::1`) ali z `authType: "none"`, ki ne pošilja ključa. Zasebni naslovi LAN (`10.x`, `172.16-31.x`, `192.168.x`) niso izvzeti: kdorkoli v tem omrežju bi lahko prebral ključ. Shranjevanje takega vozlišča ne uspe z `400`, prej shranjeno vozlišče pa se ne zapre ob vsaki zahtevi z istim sporočilom, preden je katera koli zahteva poslana. Za ključno končno točko na LAN jo postavite za TLS (na primer obratni proxy).
- `customJson` je potrjen z Zod; neznani ključi so zavrnjeni. Vsako polje ni obvezno:

| Polje             | Vrednote                             | Privzeto                                               |
| ----------------- | ------------------------------------ | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`               | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`          | `bearer`                                               |
| `authHeader`      | ime glave, uporabljeno pri `api-key` | `X-API-Key`                                            |
| `requestTemplate` | objekt JSON (≤ 64 KB, globina ≤ 32)  | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | poljska pot ali `$` za celotno telo  | `choices[0].message.content`                           |

- Skrivnost ostane v ključu API povezave, nikoli v predlogi. `bearer` pošlje `Authorization: Bearer <key>`; `api-key` pošlje `<authHeader>: <key>`. Auth glava ne more biti `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` ali hop-by-hop glava. Z `none` povezave ne potrebujejo ključa.
- Dodatne statične glave uporabljajo običajni `customHeaders` vozlišča (enako preverjanje veljavnosti kot vsako drugo združljivo vozlišče; glave za preverjanje avtorizacije tam niso dovoljene).

`PUT /api/provider-nodes/<id>` sprejme isti `customJson` in prepiše `baseUrl` in konfiguracijo na vsako obstoječo povezavo vozlišča. Če izpustite `customJson` ohranite shranjeno konfiguracijo; preklop `apiType` na `chat` ali `responses` ga odstrani iz vozlišča in njegovih povezav.

Nato dodajte povezavo do vozlišča kot običajno (`POST /api/providers` z ID-jem vozlišča) in zahtevajte `<prefix>/<model>`, na primer `biz/assistant-v1`. Končna točka ne razkrije nobenega seznama modelov, zato ID-je modelov dodajte ročno.

## Zahtevajte predloge

Predloge so navadne JSON. Vrednost niza lahko vsebuje oznake `{{placeholder}}` ; nič se ne ovrednoti ali izvede in ključi objektov niso nikoli zamenjani.

| Placeholder          | Vrednost                                                                          |
| -------------------- | --------------------------------------------------------------------------------- |
| `{{prompt}}`         | Besedilo zadnjega uporabniškega sporočila (deli besedila povezani z novo vrstico) |
| `{{messages}}`       | Pogovor v obliki klepeta OpenAI                                                   |
| `{{model}}`          | ID zahtevanega modela brez predpone ponudnika                                     |
| `{{stream}}`         | Vedno `false` — končna točka odgovori z enim dokumentom JSON                      |
| `{{request.<path>}}` | Polje prevedene (OpenAI chat format) zahteve                                      |

- Vrednost, ki je točno en ogradni znak, ohrani svoj tip JSON (`"{{messages}}"` postane niz); ograda znotraj daljšega niza je vstavljena kot besedilo.
- Oznaka mesta, ki se razreši na nič, zavrne zahtevo z HTTP 400 namesto pošiljanja nepopolnega koristnega tovora.
- Poti uporabljajo zapis s pikami in številske indekse (`data.items[0].text`). `__proto__`, `prototype` in `constructor` so zavrnjeni v ključih in poteh.

## Odzivi

Vrednost pri `responsePath` postane odgovor pomočnika: nizi gredo skozi, druge vrednosti JSON so serializirane. Manjkajoče polje ali polje `null` ali telo, ki ni JSON, vrne HTTP 502. Stanja napak navzgor so posredovana. Za pretočne odjemalce OmniRoute čaka na celoten odgovor JSON in ga nato odda kot en kos vsebine in končni kos; to ni pretakanje žetonov. Klici orodij in polja uporabe niso preslikani.

## Nikoli ponovno predvajano

Poslovna zahteva ima lahko stranske učinke, tudi če je neuspešna. OmniRoute ga torej pošlje enkrat:

- brez ponovnega poskusa prenosa in brez preusmeritve;
- ni ponovnega poskusa na drugi povezavi (nadomestni račun) — napaka je vrnjena takšna kot je in povezava ni ohlajena;
- brez povratka na naslednji kombinirani cilj, tudi za prazen ali neuspešen odgovor.

Ločene zahteve odjemalcev in fuzijske plošče, ki izrecno kličejo več modelov, še vedno kličejo končno točko neodvisno.

## Testiranje vozlišča

Shranjevanje povezave, povezave** Test** preverjanje stanja gumba in ozadja nikoli ne pokliče končne točke: potrdi le shranjeno konfiguracijo in poroča, da povezave ni mogoče preveriti.

`POST /api/provider-nodes/validate` z `"apiType": "custom-json"` in polji vozlišča (`baseUrl`, `apiKey`, `customJson`, izbirno `customHeaders` in `modelId`) pošlje natanko eno pravo zahtevo z `ping` kot najnovejšim uporabniškim besedilom. Odgovarja `{ "valid": true }` ali stanje navzgor (nikoli na telo navzgor).

## Shranjevanje

Konfiguracija je shranjena v `provider_nodes.custom_json_config_json` (migracija `240_provider_node_custom_json_config.sql`) in kopirana v `providerSpecificData.customJson` vsake povezave.

Implementacija: `open-sse/utils/customJson.ts` (validacija in predloga), `open-sse/executors/customJson.ts` (izvajalec), `open-sse/services/combo/noReplayLatch.ts` in `src/sse/handlers/chat/responsePolicies.ts` (brez ponovnega predvajanja).
