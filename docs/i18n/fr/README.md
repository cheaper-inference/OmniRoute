## Jetons gratuits par mois : ~ 11,3 milliards comme les autres comptent · ~ 90 millions de réels

</div>

> **~ 11,3 milliards de jetons gratuits / mois**<br/> <sub> comptait comme les autres catalogues comptent : chaque ligne s'additionnait, les offres terminées incluaient </sub>
>
> **~ 90 millions réels aujourd'hui**<br/> <sub> chaque quota partagé compte une fois : ce que vous pouvez réellement utiliser </sub>
>
> **Ici, tout est gratuit. Pas de paywall.**<br/> ★ [Vous aimez ça ? Mettez-nous en vedette sur GitHub](https://github.com/cheaper-inference/OmniRoute)

D'autres catalogues facturent entre 19 $ US par an et 49 $ US pour un accès à vie aux données en direct. Ici, tout est gratuit. <sub> Prix vérifiés le 2026-11-18.</sub>

<sub>Catalogue vérifié pour la dernière fois le 2026-11-23. [Comment nous comptons →](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **Apportez vos propres comptes de fournisseur.** Il s'agit de niveaux gratuits tiers, et non d'un jeton accordé par OmniRoute. Inscrivez-vous, obtenez les informations d'identification là où un fournisseur les demande et connectez celles que vous pouvez utiliser. Chaque fournisseur fixe ses propres limites, disponibilités et conditions.
>
> Empiler manuellement des niveaux gratuits signifie des dizaines de SDKs, des dizaines de limites de taux et aucune idée claire de ce qu'il vous reste. OmniRoute conserve 214 lignes de catalogue en accès libre et calcule le chiffre réel à partir de 12 pools avec un quota publié, chaque pool partagé étant compté une fois. Les quotas qui ne s'ouvrent qu'après un contrôle d'identité régional (aujourd'hui ModelScope) sont indiqués à part, +~ 6M derrière le contrôle d'identité régional, et ne sont jamais ajoutés au chiffre réel. Ce qui reste apparaît sur le tableau de bord (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute free-tier budget card. Free tokens a month: ~11.3B as others count · ~90M real. Up to ~153M in your first month with one-time signup credits. 12 pools with a published quota and 214 catalog rows with free access behind one endpoint, catalog audited 2026-11-23. The bar shows where the real figure comes from, one segment per pool. Signup credits and free providers without a token cap are listed apart and never added to it. Live used and remaining tokens on /dashboard/free-tiers."/>

> Résumé animé de la page `/dashboard/free-tiers` en direct. Comment chaque chiffre est compté :** [docs/reference/FREE_TIERS.md#comment-on-compte](docs/reference/FREE_TIERS.md#how-we-count)** .
>
> Catalogue <sub> audité pour la dernière fois le 2026-11-23. Les chiffres évoluent dans les deux sens. Un fournisseur met fin à un niveau gratuit et le nombre réel diminue. Un nouveau atterrit et il grimpe. Nous publions ce que le catalogue calcule, jamais un meilleur cas arrondi.</sub>

## Installez, connectez un fournisseur, puis acheminez via un point de terminaison

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

## Les combos : le produit phare

1. **Commencez par `auto`.** Définissez le modèle dans votre client compatible OpenAI. OmniRoute crée un combo virtuel à partir de fournisseurs connectés et note les candidats en direct.
2. **Enregistrez un combo pour plus de contrôle.** Choisissez un nom, une liste de cibles et une stratégie, puis utilisez ce nom comme modèle. La stratégie définit quelle cible sera ciblée en premier et comment les autres seront tentées.

Un combo effectue automatiquement un itinéraire à travers les modèles. En cas d'épuisement du quota, de défaillance du fournisseur ou de verrouillage du modèle, il essaie la prochaine cible éligible et saine.

### Zéro configuration : utilisez simplement `auto`

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

Les variantes ajustent les poids. Le dernier routage connu reste chez le dernier fournisseur réussi jusqu'à ce qu'il échoue, puis il est réinitialisé. `auto/fast` et `auto/cheap` expriment leurs préférences sans garantir le modèle le plus rapide ou le moins cher.

| Modèle ID           | Comportement                                                                                                                                                                                                                                                                                            |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`              | Pondérations par défaut équilibrées.                                                                                                                                                                                                                                                                    |
| `auto/fast`         | Favorise une faible latence et la santé du fournisseur.                                                                                                                                                                                                                                                 |
| `auto/cheap`        | Favorise des prix catalogue plus bas.                                                                                                                                                                                                                                                                   |
| `auto/coding`       | Pondérations axées sur la qualité pour la génération de code.                                                                                                                                                                                                                                           |
| `auto/smart`        | Pondérations de qualité supérieure avec 10 % d'exploration (par défaut 5 %).                                                                                                                                                                                                                            |
| `auto/lkgp`         | Routage explicite du dernier bon connu avec les mêmes poids que `auto`.                                                                                                                                                                                                                                 |
| `auto/subscription` | Utilise uniquement le quota du plan vérifié en direct. Renvoie HTTP 503 lorsqu'aucun n'est disponible et évite le repli facturé.                                                                                                                                                                        |
| `auto/thrifty`      | Plan → sans clé → gratuit → pas cher → premium. Peut atteindre les modèles facturés et revenir au plan lorsque le quota et le temps de recharge le permettent.                                                                                                                                          |
| `auto/offline`      | Favorise la marge de quota et de limite de débit. Les demandes sont toujours adressées à vos fournisseurs.                                                                                                                                                                                              |
| `auto/chaos`        | Un modèle par fournisseur en parallèle, jusqu'à cinq par défaut ou dix une fois configuré. Un appel en amont par modèle. Renvoie la réponse la mieux classée ou la dernière réponse réussie du panneau si le modèle haut de gamme échoue. Utilisez `fusion` pour synthétiser les réponses avec un juge. |

Les exemples de catégories et de niveaux facultatifs incluent `auto/coding:fast`, `auto/coding:free`, `auto/reasoning:pro` et `auto/vision`. Si aucun candidat connecté ne correspond, la requête renvoie HTTP 503 et le pool reste étroit. [Guide Auto-Combo](./docs/routing/AUTO-COMBO.md) · [Routage basé sur l'abonnement](./docs/routing/SUBSCRIPTION_LADDER.md)

### Ou créez la vôtre : 22 stratégies de routage

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

Le CLI accepte 15 des 22 stratégies. Le tableau de bord et les combos API acceptent les 22.

| Stratégie           | Comportement                                                                                                                                                                                                                    |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`              | Classez les candidats en direct avec le marqueur Auto-Combo à 16 facteurs.                                                                                                                                                      |
| `cache-optimized`   | Préférez le compte susceptible de contenir le préfixe d'invite en cache.                                                                                                                                                        |
| `context-optimized` | Essayez d'abord la plus grande fenêtre contextuelle connue.                                                                                                                                                                     |
| `context-relay`     | Conservez votre commande et transmettez un résumé de la conversation lors du changement de compte.                                                                                                                              |
| `cost-optimized`    | Trier par prix du jeton d'entrée du catalogue, les inconnues en dernier. Le coût final de la demande peut différer.                                                                                                             |
| `expiry-first`      | Quota de dépenses susceptible d'expirer, maximum restant par heure jusqu'à la première réinitialisation.                                                                                                                        |
| `fill-first`        | Restez sur la première cible disponible jusqu'à ce qu'elle soit épuisée ou échoue, puis continuez.                                                                                                                              |
| `fusion`            | Interrogez un panel en parallèle et demandez à un juge de synthétiser une réponse.                                                                                                                                              |
| `headroom`          | Choisissez la capacité la plus libre sur des fenêtres de 5 heures et hebdomadaires.                                                                                                                                             |
| `jev`               | TypeSafe Jev choisit les entrées de votre liste de classement. Activez `COMBO_JEV_STRATEGY_ENABLED` pour envoyer un extrait par demande et utilisez les appels TypeSafe payants. Une fois désactivé, votre commande s'applique. |
| `least-used`        | Choisissez la cible avec le moins de requêtes enregistrées dans ce combo.                                                                                                                                                       |
| `lkgp`              | Essayez d'abord le dernier fournisseur retenu, sinon conservez votre commande.                                                                                                                                                  |
| `p2c`               | Échantillonnez deux cibles et choisissez en fonction du taux de réussite et de la latence.                                                                                                                                      |
| `pipeline`          | Introduisez le résultat de chaque étape dans la cible suivante dans l'ordre et renvoyez uniquement la réponse finale.                                                                                                           |
| `priority`          | Essayez les cibles dans votre commande. La viscosité de la session le préserve.                                                                                                                                                 |
| `quota-weighted`    | Évitez les comptes épuisés et dessinez en fonction du quota restant et de la charge en vol.                                                                                                                                     |
| `random`            | Mélangez pour chaque demande. La même première cible peut se répéter.                                                                                                                                                           |
| `reset-aware`       | Notez le quota restant et le temps de réinitialisation au cours des sessions et des fenêtres hebdomadaires.                                                                                                                     |
| `reset-window`      | Essayez le compte dont la fenêtre de quota se réinitialise le plus tôt.                                                                                                                                                         |
| `round-robin`       | Rotation dans l'ordre, trois réussites par cible par défaut.                                                                                                                                                                    |
| `strict-random`     | Distribuez à partir d'un jeu mélangé afin que chaque cible mène une fois avant les répétitions.                                                                                                                                 |
| `weighted`          | Dessinez une première cible en poids et conservez le reste comme solution de repli. La répartition est statistique. Utilisez `round-robin` pour une rotation stricte.                                                           |

Les stratégies de quota utilisent des données en direct là où les fournisseurs les signalent, y compris des fenêtres d'abonnement de 5 heures et hebdomadaires. `fusion` et `pipeline` effectuent plusieurs appels en amont par requête.

L'évaluateur à 16 facteurs utilise le quota, l'état de santé, le coût, la latence, l'adéquation des tâches, la stabilité, la priorité de niveau, l'affinité de niveau, la correspondance de spécificité, l'affinité de contexte, l'affinité de cache, la disponibilité de session, l'affinité de réinitialisation de fenêtre, la densité de connexion, la qualité et la fiabilité. Les poids varient selon le profil. L'affinité du cache, l'affinité de la fenêtre de réinitialisation et la fiabilité n'ont aucun poids par défaut. [Facteurs de notation](./docs/routing/AUTO-COMBO.md#how-it-works-persisted-auto-combos)

### La résilience est intégrée : 3 couches indépendantes

Les échecs sont traités à trois niveaux, donc un mauvais modèle ne supprime pas son compte, et un mauvais compte ne supprime pas son fournisseur.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Si un fournisseur entier est en panne

Le** disjoncteur du fournisseur** s'ouvre après 8 (OAuth) ou 12 (API key) échecs avec le statut 408, 500, 502, 503 ou 504. Les combos ignorent ce fournisseur lorsqu'il est ouvert. Après 60 s ou 30 s, une requête de sonde décide si elle se ferme.

#### Si une clé ou un compte est limité en débit

Le** temps de recharge de connexion** bancs uniquement cette connexion, avec un recul exponentiel de 5 s (OAuth) ou 3 s ( clé API ). D'autres clés du même fournisseur continuent à être utilisées.

#### Si un modèle est refusé

Le** verrouillage du modèle** bloque uniquement ce modèle sur cette connexion après un 429, 404 par modèle ou un refus d'accès. D'autres modèles sur la même connexion continuent de servir.

Les connexions interdites, expirées et sans crédit sont des états terminaux, pas des temps de recharge : elles attendent que vous les corrigiez.

## CLI complet, MCP et A2A

> OmniRoute livre un client en ligne de commande avec** 91 commandes et groupes de commandes de niveau supérieur** (754 commandes en comptant les sous-commandes), un** serveur MCP avec 110 outils et 33 scopes** , et un** agent A2A avec 6 compétences** . Les scripts, les terminaux et les agents AI peuvent tous exploiter la même passerelle.

### Un vrai CLI, pas seulement `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

L'indicateur global `--output table|json|jsonl|csv` rend les mêmes commandes utilisables à partir des scripts et CI.

### Mode distant : le CLI sur votre portable, OmniRoute sur un serveur

Connectez-vous une fois à un serveur distant. Le CLI l'enregistre en tant que** contexte** , et les commandes ultérieures s'exécutent sur ce serveur jusqu'à ce que vous reveniez en arrière.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Portée du jeton | <img width="2000" height="0" alt=""> Ce que ça permet                              |
| --------------- | ---------------------------------------------------------------------------------- |
| `read`          | Répertorier et inspecter : modèles, statut, journaux, utilisation                  |
| `write`         | `read` plus configurer et appliquer : configuration du client, clés, configuration |
| `admin`         | `write` plus manage : jetons, fournisseurs, services, politique                    |

### Connecter un agent

Un agent, ou votre propre code, peut piloter le routage, les fournisseurs, les combos, le cache, la compression et la mémoire via n'importe laquelle de ces interfaces. Les chemins HTTP sont desservis par la passerelle, par défaut à `http://localhost:20128`.

| Interface               | Point de terminaison ou commande | Utilisez-le pour                                                                           |
| ----------------------- | -------------------------------- | ------------------------------------------------------------------------------------------ |
| MCP sur stdio           | `omniroute --mcp`                | Claude Desktop, Cursor et autres clients MCP locaux                                        |
| MCP sur HTTP diffusable | `/api/mcp/stream`                | Clients MCP distants : 110 outils, 33 étendues, chaque appel écrit dans le journal d'audit |
| MCP sur SSE             | `/api/mcp/sse`                   | Clients qui utilisent encore le transport SSE                                              |
| découverte A2A          | `/.well-known/agent.json`        | Carte d'agent : indique aux autres agents ce que OmniRoute peut faire                      |
| exécution A2A           | `POST /a2a`                      | Tâches JSON-RPC 2.0, synchrones ou diffusées sur SSE, sur 6 compétences                    |
| REST API                | `/v1/*`                          | Chat compatible OpenAI, réponses, intégrations, images, audio et OCR                       |
| Webhooks                | `/api/webhooks`                  | Événements sur Slack, Discord, Telegram ou n'importe quel URL avec signature HMAC          |
| CLI à distance          | `omniroute connect <host>`       | Piloter une instance distante avec des jetons d'accès étendus                              |

Les six compétences A2A sont `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` et `list-capabilities`.

**Avant de vous connecter :**

- **MCP sur HTTP démarre désactivé.** Activez-le avec `omniroute mcp enable --transport streamable-http` ou depuis la page Endpoints du tableau de bord. Un transport HTTP est actif à la fois : `streamable-http` sert `/api/mcp/stream`, `sse` sert `/api/mcp/sse`.
- **A2A démarre désactivé.** Activez-le sur la page Points de terminaison du tableau de bord. `POST /a2a` suit alors les mêmes règles de clé API que `/v1`.
- **MCP distant a besoin d’une clé appropriée.** `/api/mcp/*` répond uniquement au bouclage par défaut. Depuis un autre hôte, envoyez une clé avec `manage` ou `admin` (tous les outils), ou avec `mcp:connect` plus les étendues des outils dont vous avez besoin. Pour les clés sans `manage`/`admin`, les portées des outils sont toujours appliquées.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

## Économisez automatiquement 15 à 95 % de jetons —

### Comment ça marche : pipeline —, architecture et calcul des économies

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

Le combo empilé par défaut s'exécute `RTK → Caveman`. Lorsque les deux agissent sur la même charge utile tool/context, les économies s'accumulent :

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Les blocs de code, URLs, JSON et les données structurées sont** toujours protégé** par le moteur de préservation.

> **Pourquoi utiliser beaucoup de jetons alors que peu de jetons suffisent ?** Chaque requête passe par le pipeline de compression de OmniRoute** de manière transparente** — aucun changement de client. C'est maintenant un** pile de 12 moteurs composables** qui fonctionnent dans l'ordre et mélangent et correspondent par combo de routage — en s'appuyant sur les idées de [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) et [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

#### Styles de sortie

| Style                                          | <img width="2000" height="0" alt=""> Qu'est-ce que ça fait                                  |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Prose laconique                                | Coupe les remplissages et les haies tout en préservant les détails techniques.              |
| Moins de code                                  | Demande la plus petite modification fonctionnelle et réutilise le code existant.            |
| Queue de cheval (développeur senior paresseux) | Vérifie ce qui peut être réutilisé ou supprimé et demande une solution à la cause première. |
| J'ai ADHD (l'action d'abord)                   | Commence par l'action, numérote les étapes et termine par une prochaine étape concrète.     |
| CJK laconique (文言)                           | Utilise un chinois classique concis. Disponible pour `zh`.                                  |

Chaque style a des intensités `lite`, `full` et `ultra`. Ajoutez un style avec une entrée dans le registre des styles de sortie.

#### Budget contextuel adaptatif

| Paramètre | Possibilités                                                                                                                                                                                                                 |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Politique | `reserve-output` (par défaut) réserve un espace pour la réponse et une marge de sécurité. `percentage` utilise une part de la fenêtre contextuelle. `absolute` définit une cible de jeton fixe.                              |
| Mode      | `floor` peut faire évoluer le plan sélectionné pour l'adapter à la fenêtre contextuelle. `replace-autotrigger` utilise le budget pour l'escalade automatique. `off` conserve le déclenchement automatique du seuil de jeton. |

#### Où la compression est décidée

| Commande | Source <img width="2000" height="0" alt="">                                |
| -------- | -------------------------------------------------------------------------- |
| 1        | En-tête de requête `x-omniroute-compression` reconnu                       |
| 2        | Remplacement de la combinaison de routage                                  |
| 3        | Profil nommé actif                                                         |
| 4        | Budget contextuel adaptatif ou déclenchement automatique du seuil de jeton |
| 5        | Valeur par défaut du panneau de compression                                |
| 6        | Désactivé lorsqu'aucun forfait ne s'applique                               |

Le commutateur de compression global est prioritaire sur cette table. L'en-tête de réponse `X-OmniRoute-Compression` indique `<mode>; source=<source>`.

## Plus de méthodes d'installation — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` suit le plus haut** publié** SemVer stable. Il ne suit pas git `main`. Épinglez `:X.Y.Z` pour GitOps. Voir [les canaux de version Docker](docs/guides/DOCKER_GUIDE.md#release-channels). Les épingles d'image**`OMNIROUTE_MEMORY_MB=1024`** . C'est suffisant pour le tableau de bord et une conversation légère.** Agents de codage** (`POST /v1/responses` de Claude Code, Codex, Grok, …) nécessite un tas V8 beaucoup plus grand ou le processus `FATAL ERROR` s à ~ 12 GiB sous deux contextes longs qui se chevauchent. Dimensionnez le conteneur au-dessus du tas (les tampons natifs se trouvent en dehors de V8) :

| Charge de travail <img width="2000" height="0" alt=""> | Tas (`-e OMNIROUTE_MEMORY_MB`) | Conteneur (`--memory`) |
| ------------------------------------------------------ | ------------------------------ | ---------------------- |
| Tableau de bord / chat léger                           | `1024` (image par défaut)      | ≥ 2 g                  |
| Un agent de codage                                     | `8192`                         | ≥ 10 g                 |
| Deux `/v1/responses` longs simultanés                  | `10240`–`12288`                | ≥ 12 à 16 g            |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Tableau complet : [Docker Guide — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Chaîne Docker en avant-première :** `diegosouzapw/omniroute:next` et `diegosouzapw/omniroute:next-web` suivent la branche `release/v*` par défaut actuelle. Ces balises mutables sont uniquement destinées à tester des correctifs non publiés et sont** non pris en charge pour la production** . Voir [Canaux de version Docker](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

`bun install` standard et l'installation globale (`bun install -g omniroute`) sont pris en charge via la détection du runtime Bun :

- **`bun:sqlite` intégré** : OmniRoute utilise le pilote `bun:sqlite` intégré de Bun lors de l'exécution sous Bun, en revenant à `better-sqlite3` sur Node.js ou `sql.js`.
- **Sélection automatique du bundle Webpack en développement** : Development (`bun run dev`) détecte automatiquement Bun et désactive Turbopack en faveur de Webpack pour éviter les incompatibilités de liaison natives V8. Les builds de production (`bun run build`) suivent `OMNIROUTE_USE_TURBOPACK` exactement comme sur Node : Turbopack par défaut, `OMNIROUTE_USE_TURBOPACK=0` à construire avec Webpack (`Dockerfile.bun` l'expose en tant que `--build-arg`).
- **Dockerfile Bun dédié** : `Dockerfile.bun` en plusieurs étapes pour les déploiements de production natifs Bun (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ Installation plus rapide/plus simple (ignorer la version native)**

Le moteur natif SQLite (`better-sqlite3`) est un** facultatif** dépendance, donc une installation globale ne bloque jamais la compilation à partir des sources : elle utilise un binaire prédéfini lorsqu'il correspond à votre platform/Node, et sinon, revient de manière transparente à un moteur pure-JS (`node:sqlite` sur le nœud 22 +, sinon le `sql.js` WASM fourni ) — aucun outil de construction n'est requis.

Pour ignorer la post-installation** échauffement natif** entièrement (machines CI, sans tête ou lentes). Remarque : cela ignore uniquement l'étape de préchauffage native SQLite (`scripts/postinstall.mjs`); le hook binary-copy/repair (`scripts/build/postinstall.mjs`) fonctionne toujours normalement :

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

Pour les installations les plus rapides, préférez** pnpm** (liens durs + du magasin adressé au contenu — voir ci-dessus). Pour un environnement d'exécution sans tableau de bord et sans tête, utilisez le profil Docker `base` (ci-dessus) ou le [guide Termux](docs/guides/TERMUX_GUIDE.md). Le CLI et le tableau de bord Web sont servis par le même processus sur un seul port, il n'existe donc pas aujourd'hui de package CLI uniquement distinct.

### Comment contribuer

1. Forker le référentiel
2. Branche du** actif** `release/vX.Y.Z` tip (pas `main`) — voir [Modèle de branchement et de version](docs/ops/BRANCHING_MODEL.md)
3. Créez votre branche de fonctionnalités (`git checkout -b feat/amazing-feature`)
4. Validez vos modifications (`git commit -m 'feat: add amazing feature'`)
5. Pousser vers la branche (`git push origin feat/amazing-feature`)
6. Ouvrez une Pull Request avec** base = cette branche `release/vX.Y.Z`**

Voir [CONTRIBUTING.md](CONTRIBUTING.md) pour des directives détaillées.

### Publication d'une nouvelle version

```bash
# Create a release — npm publish happens automatically
VERSION=x.y.z
gh release create "v${VERSION}" --title "v${VERSION}" --generate-notes
```

## Remerciements

OmniRoute se tient sur les épaules de géants.
