> **Statut :** le tableau de bord est construit sur le **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), vendorisé
> sous forme de workspace `packages/ui-kit` (`@omniroute/ui-kit` ; le snapshot amont est épinglé dans
> `packages/ui-kit/UPSTREAM.md` et protégé par `npm run check:ui-kit-snapshot`). Le thème clair est le thème
> canonique ; la préférence par défaut est `system`. L'accent est le lime Keak (`--ci-color-accent`). Inter
> (interlettrage 0, `--ci-letter-spacing-ui`) est la famille typographique de l'interface, Instrument Serif
> uniquement pour les grands textes d'affichage occasionnels (`.ci-dashboard-display`), IBM Plex Mono pour le
> code — toutes auto-hébergées via les imports `@fontsource/*` en haut de `src/app/globals.css`. Chaque icône
> est un glyphe Lucide.

## 1. Où se trouvent les choses

- **Kit.** `packages/ui-kit/src` est une copie octet par octet du `src/` amont au commit épinglé dans
  `packages/ui-kit/UPSTREAM.md` (qui consigne aussi l'autorisation de licence) ; `PATCHES.md` liste les
  correctifs locaux (aucun). Il est consommé en tant que source, sans compilation : `next.config.mjs` le
  transpile, et `tsconfig.json` fait correspondre `@omniroute/ui-kit` → `packages/ui-kit/src` et
  `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` (`vitest.config.ts` et `vitest.mcp.config.ts` portent le
  même alias). Importez un composant du kit par son sous-chemin (`@omniroute/ui-kit/table`,
  `@omniroute/ui-kit/page-header`…), jamais via le barrel `@omniroute/ui-kit` : le barrel tire tous les
  composants (y compris le sélecteur de date) dans chaque importateur. La feuille de style du kit entre par
  `src/app/globals.css` (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **Jetons.** `packages/ui-kit/src/ci-tokens.css` déclare les jetons `--ci-*` ; `src/app/globals.css` fait
  le pont entre eux et les anciens noms OmniRoute (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`), de sorte que les lectures `var(--color-*)` existantes et
  les utilitaires Tailwind continuent de fonctionner. Le nouveau code utilise les utilitaires Tailwind
  (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) ou les
  classes du kit — jamais de valeur hexadécimale (`tests/unit/design-kit-bridge.test.ts` impose ce pont).
  `text-primary` se résout en `--color-primary-ink` via `--text-color-primary` (lime-800 en clair, l'accent
  lime en sombre), de sorte que le texte primaire reste lisible tandis que `bg-primary`/`border-primary`
  conservent la surface lime. Les séries de graphiques utilisent `--color-chart-1` … `--color-chart-5`.
- **Thèmes.** `<html className="ci-theme">` (`src/app/layout.tsx`) inscrit le document au thème du kit.
  La préférence est `light`, `dark` ou `system` (`THEME_CONFIG.defaultTheme = "system"` dans
  `src/shared/constants/appConfig.ts` ; `system` suit `prefers-color-scheme`). `applyTheme()` dans
  `src/store/themeStore.ts` (mis en miroir par le script d'amorçage en ligne de `src/app/layout.tsx`, qui
  s'exécute avant l'hydratation) définit `data-theme="dark"|"light"` et bascule la classe `.dark` sur
  `<html>` en même temps. L'ensemble de jetons sombres du kit est indexé sur `data-theme="dark"`
  (`packages/ui-kit/src/ci-tokens.css`) ; les surcharges sombres propres à OmniRoute (le bloc `.dark` dans
  `globals.css`) et les anciens utilitaires Tailwind `dark:` s'indexent sur la classe `.dark`. Il n'existe
  aucun préréglage de couleur d'accentuation : l'accent vient toujours du kit, et un préréglage persisté
  issu d'une build plus ancienne est abandonné au chargement du store.
- **Composants (adaptateurs).** `src/shared/components/index.tsx` conserve l'API des composants OmniRoute
  (mêmes noms, exports par défaut et props), et les primitives sous-jacentes sont des adaptateurs au-dessus
  du kit : formulaires (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`),
  superpositions et retours (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`,
  `EmptyState`, `Loading`), structure (`Collapsible`, `CollapsibleSection`, `SegmentedControl`,
  `Breadcrumbs`, `Avatar`) et tableaux (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`,
  `PresetSlider`). Un adaptateur importe le composant du kit par son sous-chemin et y fait correspondre les
  props héritées — par exemple `Button variant="primary"` correspond au bouton `default` du kit
  (`--ci-button-primary-*` : la surface inversée en clair, l'accent avec son encre
  `--ci-color-accent-foreground` en sombre), `danger` correspond à `destructive`, et `warning` à `outline`
  plus l'extension `.ci-button--warning`. Les règles `.ci-button--warning` et `.ci-badge[data-tone]` à la
  fin de `globals.css` (`@layer components`) sont des extensions OmniRoute par-dessus les classes du kit.
  `tests/unit/ui/adapters/*.test.tsx` verrouille chaque adaptateur.
- **Shell.** `src/app/(dashboard)/layout.tsx` rend `DashboardLayout`, qui rend
  `src/shared/components/layouts/DashboardShell.tsx` : le `SidebarProvider` / `Sidebar` / `SidebarInset`
  du kit (`packages/ui-kit/src/sidebar.tsx`), avec la logique de navigation d'OmniRoute dans
  `src/shared/components/Sidebar.tsx`. Un lien « Aller au contenu » vers `#main-content` est le premier
  élément focalisable. `src/shared/components/Header.tsx` contient le `SidebarTrigger` du kit (le seul
  bouton de bascule de la barre latérale du shell), le `ProductSwitcher` Keak et le déclencheur de la
  palette de commandes ; il n'affiche le titre de la route que tant qu'aucun `PageHeader` du kit
  (`.ci-page-header`) n'est monté dans `#main-content`, de sorte qu'une page dotée de son propre
  `PageHeader` n'a qu'un seul `h1`. `src/shared/components/CommandPalette.tsx` est un `Dialog` du kit.
- **Icônes.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) résout le nom (le
  vocabulaire Material Symbols qu'utilisent les écrans) via `ICON_MAP`
  (`src/shared/constants/iconMap.ts`) en un glyphe Lucide. La police et le paquet Material Symbols ont
  disparu : un nom absent de la table produit un glyphe de substitution neutre
  (`data-icon-missing="true"`) et consigne un avertissement dans la console hors production.
  `npm run gen:icon-map` affiche les noms utilisés qui manquent dans la table
  (`tests/unit/icon-map-coverage.test.ts` échoue dès qu'un nom n'a pas d'icône Lucide ;
  `tests/unit/icon-map-object-values.test.ts` couvre les noms stockés dans des objets de correspondance) ;
  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` réécrit les balises littérales
  `<span className="material-symbols-outlined">` en `<Icon>`.
- **Marque.** `src/shared/components/OmniRouteLogo.tsx` encapsule le kit : l'export par défaut
  `OmniRouteLogo` rend `ProductIcon product="omniroute" variant="glyph"` (SVG en ligne, compatible avec
  `basePath`) et `OmniRouteLockup` rend `ProductLockup product="omniroute"` (nom accessible
  « Keak OmniRoute ») ou, pour les opérateurs en marque blanche, leurs propres `name`/`logoSrc`. Les
  destinations du sélecteur de produits résident dans `src/shared/constants/keakProducts.ts`
  (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`). Les écrans autonomes — `src/app/login/page.tsx`,
  `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`,
  `src/app/not-found.tsx` et `src/shared/components/ErrorPageScaffold.tsx` — affichent le lockup ;
  `tests/unit/brand-pages-static.test.ts` le garantit.

## 2. Règles

1. Des tokens, jamais de littéraux. Exceptions conservées volontairement : le terminal de console
   toujours sombre, les contours SVG ReactFlow via `STATUS_HEX` (`src/shared/constants/statusColors.ts`),
   et les palettes catégorielles `STRATEGY_COLORS`
   (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) et `LAYER_COLORS`
   (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`).
2. Ne jamais patcher `packages/ui-kit/src` à la main : synchronisez avec
   `scripts/dev/sync-ui-kit.sh <commit>` ; le garde-fou pre-commit `npm run check:ui-kit-snapshot`
   (`.husky/pre-commit`) échoue sur tout octet qui diffère du commit amont épinglé (il est ignoré avec
   un avertissement lorsque le clone amont, `UI_KIT_CLONE` ou `_references/cheaper-inference-ui-kit`,
   est absent). Lorsque le kit ne propose pas quelque chose, contournez le manque dans l'adaptateur ou
   l'écran et demandez-le en amont.
3. Les textes par défaut du kit sont en anglais (`label = "Loading"`, `loadingLabel = "Loading table"`…) —
   passez des chaînes traduites depuis `useTranslations(...)` chaque fois qu'un composant du kit affiche
   du texte.
4. Les utilitaires Tailwind l'emportent sur les classes des composants du kit (le kit déclare
   `@layer theme, base, components, utilities` et ses règles vivent dans `components`) — utilisez les
   utilitaires pour l'espacement et la mise en page, pas pour recolorer les composants du kit.
5. Titres : `.ci-heading` (Inter, sans interlettrage) pour les titres de page et de section ;
   `.ci-dashboard-display` (Instrument Serif) uniquement pour les grands textes d'affichage espacés,
   comme le code de statut de la page d'erreur.
6. `tests/unit/dashboard-kit-sweep.test.ts` protège l'adoption du kit : aucun span de ligature Material
   sous `src/app` ou `src/shared/components` ; dans l'arborescence du dashboard (`src/app/(dashboard)` et
   `src/shared/components`), aucun `<select>`, `<textarea>` ou `<table>` brut et aucun `role="dialog"`
   fait main en dehors des exceptions listées (la branche native de l'adaptateur `Select`,
   `RequestLoggerDetail`) ; chaque `<button>` ou `<input>` brut nécessite un commentaire contenant
   `kit-exception:` (avec la raison) se terminant au plus 3 lignes au-dessus ; les teintes de palette et
   les variantes `dark:` uniquement dans les fichiers listés par le test.
7. Vérifiez les deux thèmes et la fenêtre de 390 px avant une PR (captures d'écran) ;
   `tests/e2e/a11y.spec.ts` exécute axe.

## 3. Ajouter un écran

1. Ouvrez la page avec le `PageHeader` du kit (`@omniroute/ui-kit/page-header`, `compact` dans le
   dashboard) — titre, description et `actions`. L'en-tête du shell abandonne alors son propre titre.
2. Construisez les contrôles à partir de `@/shared/components` (les adaptateurs) et utilisez les
   composants du kit par sous-chemin lorsqu'aucun adaptateur n'existe
   (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`, `Slider`…).
3. Icônes : `<Icon name="…" />`. Un nouveau nom va dans `ICON_MAP` avec le composant Lucide
   correspondant sémantiquement ; `npm run gen:icon-map` liste les noms encore manquants.
4. Couleurs : utilitaires sémantiques (`text-success`, `bg-warning-bg`, `border-border`…) et
   `var(--color-chart-N)` pour les séries de graphiques ; aucune valeur hexadécimale et aucune variante
   `dark:` qui ne fait que répéter une couleur.
5. Texte : chaque chaîne, y compris les libellés que vous passez aux composants du kit, provient de
   `useTranslations`. Les nouvelles clés vont dans `src/i18n/messages/en.json`, `pt-BR.json` et
   `vi.json` (le test de parité vietnamien épingle chaque clé anglaise) ; les autres locales sont
   remplies par la synchronisation i18n.
6. Exécutez les garde-fous avant la PR : `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (la seule vérification qui détecte un import dupliqué dans
   `iconMap.ts`), `npm run check:ui-icu`, et les tests propres à l'écran.

## 4. Ajouter ou modifier un adaptateur

1. Conserver l'API publique de `src/shared/components/index.tsx` : mêmes noms d'export, exports par défaut et
   props acceptées. Faire correspondre les props héritées vers le kit dans l'adaptateur (voir `Button.tsx` : `VARIANT_TO_KIT`,
   `SIZE_TO_KIT`).
2. Importer le kit par sous-chemin (`@omniroute/ui-kit/<component>`).
3. Les solutions de contournement pour les lacunes du kit vivent dans l'adaptateur (ou dans `globals.css` `@layer components` quand le correctif est
   un style), jamais dans `packages/ui-kit/src`.
4. Ajouter ou mettre à jour `tests/unit/ui/adapters/<name>.test.tsx`. Pour un adaptateur avec de nombreux appelants, comparer le
   balisage rendu avant et après la modification — les changements de padding ou de wrapper se propagent à chaque écran.

## 5. Mettre à jour le kit

`scripts/dev/sync-ui-kit.sh <commit> [clone]` copie le `src/` amont à ce commit dans
`packages/ui-kit/src` et applique l'unique transformation autorisée (elle supprime le suffixe `.js` des
imports relatifs). Ensuite : examiner `git diff packages/ui-kit`, faire une passe visuelle sur les providers, settings, combos,
usage et endpoint dans les deux thèmes, exécuter `npm run check:ui-kit-snapshot` et `npm run test:vitest:ui`, puis
ouvrir la PR avec le changelog amont.
