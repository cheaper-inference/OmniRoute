> des outils et la configuration des portées se trouvent dans `open-sse/mcp-server/server.ts`.

## Présentation

OmniRoute se connecte à un coffre **Obsidian** en tant que **source de contexte** — une
base de connaissances Markdown locale que les agents lisent et modifient au moyen du
serveur MCP intégré. L’intégration communique avec l’extension communautaire
**Obsidian Local REST API** exécutée dans l’application de bureau, ce qui permet aux
agents de rechercher des notes, de lire/écrire/corriger des fichiers, de parcourir le
coffre, de travailler avec des notes périodiques quotidiennes/hebdomadaires, de gérer
les étiquettes, d’exécuter des commandes Obsidian et, éventuellement, de coordonner
une synchronisation bidirectionnelle du coffre entre ordinateur et appareil mobile.

Le client (`src/lib/obsidian/api.ts`) encapsule la Local REST API avec :

- **Nouvelle tentative avec délai progressif** pour les erreurs transitoires `5xx` et
  **délai d’expiration de 30 secondes** via `AbortController`.
- **Classification typée des erreurs** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Une **indication claire en cas d’impossibilité de joindre Obsidian**, qui signale
  l’erreur de port courante (HTTP sur `27123`, **et non** le point de terminaison MCP
  sur `27124`) ainsi que le format Tailscale.
- **Encodage des chemins** relatifs au coffre afin de gérer de façon sûre les chemins
  de notes contenant des espaces ou des barres obliques.

## Configuration

Il n’existe **aucune variable d’environnement** pour le jeton Obsidian ou l’URL de base — les deux sont
stockés dans la table SQLite `key_value` (espace de noms `obsidian`) via
`src/lib/db/obsidian.ts`. Le jeton est **chiffré au repos** (AES-256-GCM, avec
un mécanisme de repli rétrocompatible en texte clair). Effectuez la configuration depuis l’onglet **Sources de contexte** du
tableau de bord Endpoint (`ObsidianSourceCard`), ou via l’API REST des paramètres.

> [!IMPORTANT]
> Le plugin **Obsidian Local REST API** doit être installé et en cours d’exécution. Son interface REST
> écoute sur **HTTP `127.0.0.1:27123`** (l’URL de base par défaut). Le port `27124`
> est un point de terminaison MCP/HTTPS _distinct_ et est explicitement rejeté par la route des paramètres.
> Si vous vous connectez depuis un autre appareil, utilisez `http://<tailscale-ip>:27123`.

### Clés de configuration (SQLite `key_value`, espace de noms `obsidian`)

| Clé               | Rôle                                                                 | Chiffré |
| ----------------- | -------------------------------------------------------------------- | ------- |
| `api_key`         | Jeton bearer de l’API REST locale                                    | oui     |
| `base_url`        | URL de base REST (par défaut `http://127.0.0.1:27123`)               | non     |
| `vault_path`      | Chemin absolu vers le répertoire du coffre (pour la synchronisation) | non     |
| `webdav_username` | Nom d’utilisateur WebDAV généré (synchronisation du coffre)          | non     |
| `webdav_password` | Mot de passe WebDAV généré (synchronisation du coffre)               | oui     |
| `webdav_enabled`  | Indique si la synchronisation WebDAV du coffre est activée           | non     |

### Configuration via REST

```bash
# Enregistrer et valider le jeton de l’API REST locale (POST effectue la validation via une vérification d’état)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Vérifier l’état de la connexion (renvoie connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Se déconnecter (efface le jeton stocké)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Toutes les méthodes nécessitent une authentification au tableau de bord. `POST` rejette toute URL utilisant le port `27124`
et valide le jeton en appelant le point de terminaison d’état de l’API REST locale avant de le conserver.

### Synchronisation WebDAV du coffre

`src/app/api/settings/obsidian/webdav/route.ts` gère une synchronisation facultative du
coffre basée sur WebDAV (pilotée par `src/lib/obsidianSync.ts`). Son activation fait pointer OmniRoute vers un
répertoire de coffre local et génère une paire aléatoire de nom d’utilisateur et de mot de passe WebDAV :

```bash
# Activer la synchronisation WebDAV pour un répertoire de coffre (génère un nom d’utilisateur et un mot de passe)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Obtenir l’état de la synchronisation WebDAV (les identifiants ne sont renvoyés que lorsqu’elle est activée)
curl http://localhost:20128/api/settings/obsidian/webdav

# Désactiver la synchronisation WebDAV (efface les identifiants et le fichier .stignore géré)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Sécurité et transports

L'authentification WebDAV applique le suivi des échecs et le verrouillage par IP (10 tentatives infructueuses dans une fenêtre de 60 secondes déclenchent un verrouillage de 5 minutes avec `429 Too Many Requests` et `Retry-After`). Étant donné que WebDAV transmet les informations d'authentification de base, il est fortement recommandé de mettre fin à TLS (ou au routage via un tunnel sécurisé tel que Tailscale ou Cloudflare Tunnel) lors de l'accès au point de terminaison WebDAV en dehors du bouclage.

### Source de contexte par clé d’API (facultatif)

La configuration Obsidian peut être définie **par clé d’API** via la table `api_key_context_sources`
(`src/lib/db/apiKeyContextSources.ts`). Lorsqu’un appel MCP contient un identifiant de clé d’API
authentifié, `getObsidianConfigForApiKey()` utilise en priorité le jeton, l’URL de base et le chemin du coffre propres à cette clé
(`source: "api_key"`) et, à défaut, utilise la configuration globale (`source: "global"`).

Les outils MCP autres que ceux de synchronisation nécessitent une identité d’appelant résolue avant de lire cette configuration.
Un appelant sans identité reçoit `Obsidian API token not configured`, et aucune requête
n’est envoyée au coffre. L’identité des appelants HTTP est résolue à partir des identifiants de leur requête ; celle des appelants stdio
peut être résolue via `OMNIROUTE_API_KEY` ou `ROUTER_API_KEY`. Un appelant HTTP non résolu
ne peut pas hériter de l’identité d’environnement du serveur. Les identifiants d’espace réservé seuls n’autorisent pas
l’accès ; un identifiant d’environnement valide qui se résout en `env-key` reste pris en charge.
Les clés authentifiées sans configuration Obsidian propre à la clé conservent le mécanisme de repli vers la configuration globale.
Les quatre outils `obsidian_sync_*` conservent leur comportement distinct relatif au jeton de synchronisation.

## outils MCP (22)

Défini dans `open-sse/mcp-server/tools/obsidianTools.ts`. Les token/base-URL sont résolus par appel (par clé API d'abord, puis globalement). Des outils qui frappent le OmniRoute** serveur de synchronisation** (les quatre outils `obsidian_sync_*` ) nécessitent en outre le jeton d'authentification de synchronisation configuré dans les paramètres OmniRoute.

### Lire les outils (`read:obsidian`)

| Outil                        | Description                                                                                                                             |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Vérifiez si le REST API local est accessible et authentifié.                                                                            |
| `obsidian_search_simple`     | Recherche en texte intégral du contenu des notes ; renvoie des extraits avec les chemins de fichiers.                                   |
| `obsidian_search_structured` | Recherchez à l'aide d'une expression logique JSON (filtres and/or/regex/path ).                                                         |
| `obsidian_read_note`         | Lire une note par chemin relatif au coffre-fort ; en option un heading/block/frontmatter. spécifique                                    |
| `obsidian_list_vault`        | Liste les fichiers et répertoires dans le coffre-fort (arborescence des entrées).                                                       |
| `obsidian_get_document_map`  | Obtenez la structure des titres de la note sous forme de carte des titres → des numéros de ligne.                                       |
| `obsidian_get_note_metadata` | Obtenez des éléments de présentation, des balises, des liens, le nombre char/word sans le contenu complet.                              |
| `obsidian_get_active_file`   | Obtenez le chemin + du contenu du fichier actuellement actif dans Obsidian.                                                             |
| `obsidian_get_periodic_note` | Obtenez la note périodique daily/weekly/monthly pour une date (aujourd'hui si omise).                                                   |
| `obsidian_get_tags`          | Répertoriez toutes les balises de coffre-fort avec leurs fréquences.                                                                    |
| `obsidian_list_commands`     | Liste la commande Obsidian disponible IDs (à utiliser avec `obsidian_execute_command`).                                                 |
| `obsidian_sync_status`       | État du serveur de synchronisation OmniRoute : en cours d'exécution, nom du coffre-fort, port, disponibilité, dernière synchronisation. |
| `obsidian_sync_conflicts`    | Répertoriez les conflits de synchronisation non résolus (chemin, chemin de conflit, détecté à).                                         |

### Outils d'écriture (`write:obsidian`)

| Outil                            | Description                                                                                                          |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Créez ou écrasez une note avec un contenu Markdown donné.                                                            |
| `obsidian_append_note`           | Ajouter du contenu à une note ; éventuellement à un heading/block. spécifique                                        |
| `obsidian_patch_note`            | Chirurgicalement, append/prepend/replace dans un champ d'en-tête, de bloc ou de frontmatter.                         |
| `obsidian_delete_note`           | Supprimez définitivement une note du coffre-fort.                                                                    |
| `obsidian_move_note`             | Déplacez ou renommez une note dans le coffre-fort.                                                                   |
| `obsidian_execute_command`       | Exécutez une commande Obsidian par sa commande ID.                                                                   |
| `obsidian_open_file`             | Ouvrez un fichier dans Obsidian (le crée s'il n'existe pas).                                                         |
| `obsidian_sync_trigger`          | Déclenchez une synchronisation bidirectionnelle immédiate du coffre-fort mobile ↔ sur le bureau.                     |
| `obsidian_sync_resolve_conflict` | Résolvez un conflit de synchronisation : conservez `local` (mobile), `remote` (ordinateur de bureau) ou `keep-both`. |

> [!NOTE]
> Les cibles `obsidian_patch_note` acceptent `targetType` de `heading | block | frontmatter` et `operation` de `append | prepend | replace`, avec un `createTargetIfMissing` facultatif. Les quatre outils `obsidian_sync_*` communiquent avec le serveur de synchronisation local (`http://127.0.0.1:27781` par défaut) et nécessitent le jeton de synchronisation.

### Portées

Les outils de lecture nécessitent `read:obsidian`; les outils d'écriture nécessitent `write:obsidian`. L'application est identique à Notion — géré par `withScopeEnforcement()` dans `open-sse/mcp-server/server.ts`, bloqué sur `OMNIROUTE_MCP_ENFORCE_SCOPES=true` et forcé pour les appelants HTTP/SSE dont la clé API manque `manage`/`admin`, avec des portées autorisées provenant de `OMNIROUTE_MCP_SCOPES` ou du contexte de portée de la clé API. Voir [MCP-SERVER.md](./MCP-SERVER.md).

## Points de terminaison

| Méthode  | Chemin                          | Objectif                                                        |
| -------- | ------------------------------- | --------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Renvoie `{ connected, hasToken, baseUrl, vaultPath }`.          |
| `POST`   | `/api/settings/obsidian`        | Enregistre et valide le jeton (rejette le port `27124`).        |
| `DELETE` | `/api/settings/obsidian`        | Déconnecte (supprime le jeton enregistré).                      |
| `GET`    | `/api/settings/obsidian/webdav` | État de la synchronisation WebDAV et identifiants (si activée). |
| `POST`   | `/api/settings/obsidian/webdav` | Active la synchronisation WebDAV pour un répertoire de coffre.  |
| `DELETE` | `/api/settings/obsidian/webdav` | Désactive la synchronisation WebDAV.                            |

> Il s'agit des routes de configuration du tableau de bord. Le coffre lui-même est accessible via l'API
> REST locale d'Obsidian (la `base_url` configurée) et via les outils MCP ci-dessus — il n'existe
> aucun point de terminaison proxy Obsidian `/v1` public.

## Cas d'utilisation

- **Réponses fondées sur le coffre** — `obsidian_search_simple` / `obsidian_search_structured`
  puis `obsidian_read_note`, afin qu'un agent réponde à partir de vos véritables notes.
- **Rédaction de notes / tenue d'un journal** — `obsidian_write_note`, `obsidian_append_note` ou
  la commande précise `obsidian_patch_note` pour consigner les résultats d'un agent, des résumés ou des notes quotidiennes
  (`obsidian_get_periodic_note`) dans le coffre.
- **Navigation dans le coffre** — `obsidian_list_vault`, `obsidian_get_document_map` et
  `obsidian_get_tags` pour explorer la structure avant toute lecture ou écriture.
- **Automatisation d'Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` pour
  piloter les plugins/commandes depuis un agent ; `obsidian_open_file` pour afficher une note dans l'interface utilisateur.
- **Synchronisation mobile** — activez la synchronisation WebDAV, puis utilisez `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  pour coordonner la synchronisation ordinateur↔mobile et résoudre les conflits.
