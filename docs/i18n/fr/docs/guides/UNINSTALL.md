Ce guide explique comment supprimer proprement OmniRoute de votre système.

## Rétablir la configuration du client

Le programme de désinstallation arrête le processus OmniRoute géré par PM2, le cas échéant, et laisse la configuration client en place. Les clients qui pointent toujours vers OmniRoute perdent leur connexion une fois celle-ci arrêtée. La suppression complète supprime également le répertoire de données, `~/.omniroute` par défaut, ainsi que ses sauvegardes de configuration client.

### 1. Utilisez le tableau de bord pendant que OmniRoute est en cours d'exécution

Ouvrir** Code CLI** (`/dashboard/cli-code`) dans le tableau de bord et recherchez le** Code Claude** carte.** Appliquer** écrit dans le fichier de paramètres Claude Code de l'hôte OmniRoute, `~/.claude/settings.json` par défaut. Si vous disposez d'une sauvegarde avant d'appliquer les paramètres OmniRoute, ouvrez** Sauvegardes** et restaurez-le. Sinon, sélectionnez** Réinitialiser** pour supprimer les paramètres de passerelle de `env`. Appliquez et réinitialisez d'abord la sauvegarde du fichier existant. Les sauvegardes sont stockées sous `<DATA_DIR>/backups`.

Si `CLI_ALLOW_CONFIG_WRITES=false` ou le tableau de bord n'est pas disponible, rétablissez le fichier manuellement. Si OmniRoute s'exécute dans Docker et que le client s'exécute sur l'hôte, annulez la configuration de l'hôte. Les fichiers dans un conteneur home non monté n'ont aucun effet sur le client hôte.

### 2. Annuler manuellement les modifications restantes

Pour Claude Code, vérifiez `~/.claude/settings.json`, le `settings.json` dans `CLAUDE_CONFIG_DIR` s'il est défini et le `.claude/settings.json` du projet. Reset supprime les clés suivantes de `env`. Supprimez les valeurs que vous avez ajoutées pour OmniRoute ou restaurez vos valeurs précédentes.

- `"ANTHROPIC_BASE_URL"`, `"ANTHROPIC_AUTH_TOKEN"` et `"ANTHROPIC_API_KEY"`
- `"ANTHROPIC_DEFAULT_OPUS_MODEL"`, `"ANTHROPIC_DEFAULT_SONNET_MODEL"` et `"ANTHROPIC_DEFAULT_HAIKU_MODEL"`
- `"API_TIMEOUT_MS"`

La réinitialisation laisse `ANTHROPIC_MODEL` dans `env` et les paramètres `model` et `apiKeyHelper` de niveau supérieur en place. Supprimez ou restaurez-les manuellement s'ils sélectionnent un modèle ou des informations d'identification OmniRoute. Arrêtez d'utiliser tout profil OmniRoute créé par `omniroute setup-claude` sous `~/.claude/profiles/<name>/` ou rétablissez son `settings.json`. La commande setup écrit le profil sans modifier le fichier de paramètres par défaut ni enregistrer de jeton. Supprimez ou restaurez les exportations correspondantes dans les fichiers de démarrage de votre shell et effacez les anciennes valeurs du shell actuel. `omniroute launch` et `omniroute run claude` définissent la passerelle URL et le jeton pour le processus enfant uniquement.

Pour Codex, restaurez le fournisseur et le modèle précédents dans `~/.codex/config.toml` s'il contient `model_provider = "omniroute"`. Supprimez `[model_providers.omniroute]` s'il a été ajouté pour cette passerelle. Restaurez ou supprimez `openai_base_url` pointe vers OmniRoute. Pour les clients compatibles OpenAI, restaurez ou effacez `OPENAI_BASE_URL` partout où vous le définissez pour OmniRoute.

### 3. Vérifiez que le client fonctionne avec OmniRoute arrêté

Vérifiez les paramètres par défaut du code Claude et l'environnement shell actuel.

```bash
grep -n ANTHROPIC ~/.claude/settings.json
env | grep ANTHROPIC
```

Aucune des deux vérifications ne doit montrer `ANTHROPIC_BASE_URL` pointant vers OmniRoute. Si vous utilisez un profil ou des paramètres de projet, vérifiez également ces fichiers. Avec OmniRoute arrêté et votre authentification habituelle restaurée, exécutez directement Claude Code.

```bash
claude -p "say hello"
```

Claude Code doit répondre en utilisant la configuration restaurée. Si elle pointe toujours vers la passerelle arrêtée, la requête échoue avec une erreur de connexion.

## Désinstallation rapide (v3.6.2 +)

> [Rétablissez d'abord la configuration du client](#revert-client-configuration) pendant que OmniRoute est toujours en cours d'exécution.

OmniRoute fournit deux scripts intégrés pour une suppression propre :

### Conservez vos données

```bash
npm run uninstall
```

Cela supprime l'application OmniRoute mais** conserves** votre base de données, vos configurations, vos clés API et les paramètres de votre fournisseur dans `~/.omniroute/`. Utilisez-le si vous envisagez de réinstaller plus tard et souhaitez conserver votre configuration.

### Suppression complète

```bash
npm run uninstall:full
```

Cela supprime l'application** et efface définitivement** toutes les données :

- Base de données (`storage.sqlite`)
- Configurations du fournisseur et clés API
- Fichiers de sauvegarde
- Fichiers journaux
- Tous les fichiers du répertoire `~/.omniroute/`

> ⚠️** Avertissement:** `npm run uninstall:full` est irréversible. Toutes les connexions de votre fournisseur, combos, clés API et historique d'utilisation seront définitivement supprimés.

## Désinstallation manuelle

> [Rétablissez d'abord la configuration du client](#revert-client-configuration) pendant que OmniRoute est toujours en cours d'exécution.

### Installation globale NPM

```bash
# Remove the global package
npm uninstall -g omniroute

# (Optional) Remove data directory
rm -rf ~/.omniroute
```

### Installation globale de pnpm

```bash
pnpm uninstall -g omniroute
rm -rf ~/.omniroute
```

### Docker

```bash
# Stop and remove the container
docker stop omniroute
docker rm omniroute

# Remove the volume (deletes all data)
docker volume rm omniroute-data

# (Optional) Remove the image
docker rmi cheaperinference/omniroute:latest
# Older installs pulled the legacy name:
docker rmi diegosouzapw/omniroute:latest
```

### Docker Composer

```bash
# Stop and remove containers
docker compose down

# Also remove volumes (deletes all data)
docker compose down -v
```

### Application de bureau Electron

**Windows:**

- Ouvrir `Settings → Apps → OmniRoute → Uninstall`
- Ou exécutez le programme de désinstallation NSIS à partir du répertoire d'installation

**macOS:**

- Faites glisser `OmniRoute.app` de `/Applications` vers la corbeille
- Supprimer des données : `rm -rf ~/Library/Application Support/omniroute`

**Linux:**

- Supprimez le fichier AppImage
- Supprimer des données : `rm -rf ~/.omniroute`

### Installation source (clone git)

```bash
# Remove the cloned directory
rm -rf /path/to/omniroute

# (Optional) Remove data directory
rm -rf ~/.omniroute
```

## Répertoires de données

Par défaut, OmniRoute stocke les données aux emplacements suivants :

| Plateforme     | Chemin par défaut             | Remplacement                               |
| -------------- | ----------------------------- | ------------------------------------------ |
| Linux          | `~/.omniroute/`               | Variable d’environnement `DATA_DIR`        |
| macOS          | `~/.omniroute/`               | Variable d’environnement `DATA_DIR`        |
| Windows        | `%APPDATA%/omniroute/`        | Variable d’environnement `DATA_DIR`        |
| Docker         | `/app/data/` (volume monté)   | Variable d’environnement `DATA_DIR`        |
| Compatible XDG | `$XDG_CONFIG_HOME/omniroute/` | Variable d’environnement `XDG_CONFIG_HOME` |

### Fichiers du répertoire de données

| Fichier/Répertoire   | Description                                                               |
| -------------------- | ------------------------------------------------------------------------- |
| `storage.sqlite`     | Base de données principale (fournisseurs, combinaisons, paramètres, clés) |
| `storage.sqlite-wal` | Journal d’écriture anticipée SQLite (temporaire)                          |
| `storage.sqlite-shm` | Mémoire partagée SQLite (temporaire)                                      |
| `call_logs/`         | Archives des charges utiles des requêtes                                  |
| `backups/`           | Sauvegardes automatiques de la base de données                            |
| `log.txt`            | Journal des requêtes hérité (facultatif)                                  |

## Vérifier la suppression complète

Après la désinstallation, vérifiez qu’il ne reste aucun fichier :

```bash
# Vérifier le package npm global
npm list -g omniroute 2>/dev/null

# Vérifier le répertoire de données
ls -la ~/.omniroute/ 2>/dev/null

# Vérifier les processus en cours d’exécution
pgrep -f omniroute
```

Si un processus est toujours en cours d’exécution, arrêtez-le :

```bash
pkill -f omniroute
```
