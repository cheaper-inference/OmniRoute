`devin-cli-agentic` permet à l’environnement d’exécution réel de Claude Code d’utiliser le
point de terminaison Messages Anthropic local d’OmniRoute, tandis que le CLI Devin officiel
fournit les réponses du modèle via ACP stdio. Il ne modifie pas les fournisseurs Anthropic,
Claude OAuth, Claude Web ou `devin-cli` existants.

Pour les appels d’outils gérés par le client, effectuez le routage via `devin-cli-agentic`
(alias `dva`), le fournisseur compatible avec les outils au format Claude. L’ancien exécuteur
ACP `devin-cli` (`dv`) ne prend en charge que le texte : il exécute le synthétiseur sans outils
de Devin et ne peut pas renvoyer d’appels d’outils. Les métadonnées de son modèle sont
marquées en conséquence afin que le routage combiné nécessitant des outils l’évite.

> **État actuel : Claude Code `2.1.258` épinglé ; dernière validation hors ligne et en direct
> enregistrée avec `2.1.220`.** L’épinglage sur `2.1.220` a permis d’exécuter trois scénarios
> isolés via Devin CLI `3000.2.17` et le modèle `swe-1-7-lightning` ; cette dernière exécution
> en direct a validé les tours `Read`, `Edit` et `Bash` gérés par le client, la réussite de
> `npm test`, la découverte des commandes et des compétences du projet, un routage
> exclusivement via Devin et l’absence totale de trafic sortant vers Claude. L’épinglage a
> ensuite été relevé à `2.1.258` (la génération du CLI dont OmniRoute usurpe l’identité Claude,
> et la première version qui inclut nativement le niveau Fable 5.1). Avec le nouvel épinglage,
> la couche d’installation et `claude --version` ont été vérifiées sur l’image de base épinglée,
> et la suite de tests unitaires du pont, `compose config` ainsi que la preuve statique
> d’isolation réussissent — mais le scénario simulé hors ligne et la suite en direct de trois
> scénarios n’ont pas encore été réexécutés. Réexécutez-les (voir « Mise à jour des outils
> épinglés ») avant d’utiliser le pont avec cet épinglage.

## Architecture

```text
Claude Code 2.1.258 (conteneur Linux non-root isolé)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (fournisseur au format Claude, sans authentification)
  -> devin acp --agent-type summarizer (ACP stdio officiel, sans outils Devin)
  -> compte Devin dans le volume devin-auth dédié
```

L’agent ACP par défaut du CLI officiel peut exécuter ses propres outils ; ce pont ne
l’utilise donc pas. Il démarre l’agent ACP fixe `summarizer`, dont le mode CLI officiel ne
dispose d’aucun outil, et encapsule la requête Anthropic sérialisée sous forme de trace
d’exécution. Lorsqu’une autre action gérée par Claude est nécessaire, la réponse doit
contenir exactement une enveloppe d’outil client. Tout événement ACP `tool_call` ou
`tool_call_update` est rejeté avant qu’une réponse puisse être signalée comme réussie.

Le sérialiseur situé dans `open-sse/executors/devin-agentic/serializer.ts` préserve `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` ainsi que
les outils fournis par Claude Code. Les images et les blocs inconnus provoquent explicitement
un échec. Les résultats d’outils volumineux utilisent un marqueur de troncature visible.

L’analyseur accepte une seule enveloppe autonome `<tool>{...}</tool>` par tour du modèle. Il
vérifie le nom par rapport à la liste d’outils de la requête, valide les arguments selon le
schéma JSON de cet outil, rejette les réponses mêlant texte narratif et actions, et autorise
une seule tentative de correction limitée. Claude Code exécute ensuite localement le
`tool_use` Anthropic obtenu et renvoie le `tool_result` via OmniRoute.

## Routage automatique

Le fournisseur est admissible dans les groupes de candidats `auto/*` d’OmniRoute lorsqu’il
n’est pas bloqué. L’admissibilité comme candidat ne garantit pas sa sélection : la stratégie
de routage de la combinaison (par exemple, le dernier fournisseur fonctionnel connu) peut en
privilégier un autre. Utilisez `dva/<model>` ou une combinaison donnant la priorité à Devin
lorsque vous exigez que chaque requête passe par Devin.

## Isolation et modèle de menace

L’installation, le compte et la configuration Claude de l’hôte sont hors périmètre et considérés comme
interdits. Les services Compose :

- s’exécutent avec l’UID/GID `10001:10001`, un système de fichiers racine en lecture seule, des capacités supprimées et
  `no-new-privileges` ;
- utilisent un répertoire `/home/bridge` privé, un volume de configuration Claude dédié, des données OmniRoute isolées
  et un volume `devin-auth` distinct ;
- montent uniquement des espaces de travail et des preuves `.sandbox` jetables ;
- ne montent ni le répertoire personnel de l’hôte, ni Keychain, ni les identifiants SSH ou cloud, ni le socket Docker ;
- construisent des environnements explicites et suppriment les variables d’API, d’OAuth et de routage d’Anthropic ;
- dirigent les inférences de Claude Code uniquement vers `http://omniroute:20128` avec une clé exclusivement locale.

Le profil hors ligne utilise un réseau interne. Dans le profil actif, OmniRoute accède aux
points de terminaison Devin officiels uniquement via `network-guard` ; les destinations sans rapport sont refusées.
Claude Code dispose d’une protection de sortie distincte qui interdit tout trafic et ne peut accéder qu’au service OmniRoute
local via `NO_PROXY`. Les fichiers d’audit des protections sont montés uniquement par leur processus de protection. Les
scripts vérifient la propriété, le mode et le nombre de liens des fichiers, ainsi que chaque décision, avant d’exporter
des preuves sans jeton.

Exécutez la preuve d’isolation de manière indépendante :

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Elle valide la topologie, les montages nommés, les paramètres d’exécution non-root et en lecture seule, le routage local explicite,
l’absence de variables d’environnement sensibles, l’absence du socket Docker, le blocage de l’accès à
`api.anthropic.com` et `claude.ai`, la sélection exclusive du fournisseur Devin et l’échec explicite lorsque
le backend ACP est indisponible.

## Configuration initiale et utilisation normale

Construisez l’image épinglée :

```bash
./scripts/devin-bridge/build
```

Authentifiez uniquement le volume Devin isolé :

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

La commande de connexion utilise le flux officiel par jeton manuel destiné aux environnements
distants ou conteneurisés. La valeur est saisie directement dans l’invite de la CLI ; elle n’est ni transmise comme
argument de processus, ni écrite dans Git, ni copiée depuis l’hôte.

Lancez l’environnement d’exécution Claude Code isolé :

```bash
./scripts/devin-bridge/launch
```

`launch` revérifie l’isolation, l’authentification Devin et la découverte des modèles avant de démarrer
Claude Code dans le conteneur. Il n’exécute jamais l’exécutable Claude de l’hôte. Les alias de modèles peuvent être
définis dans `.env.devin-bridge` ; chaque valeur configurée doit conserver le
préfixe `devin-cli-agentic/`.

## Commandes de validation

Le parcours hors ligne reproductible ne nécessite aucun compte Devin et ne dispose d’aucun accès à Internet pendant l’exécution :

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Le parcours actif authentifié et facultatif est :

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Le programme d’exécution actif attend entre les scénarios afin d’éviter d’ouvrir des sessions ACP en rafale et
valide les événements structurés du flux Claude au lieu de se fier à des affirmations textuelles. Ses trois
scénarios démontrent :

1. la lecture directe du projet et l’analyse des défauts ;
2. une véritable opération `Edit`, une commande `Bash` `npm test` contrôlée par le client et un résultat final ;
3. la découverte de `/bridge-check` et de `bridge-proof`, la lecture du projet, une autre exécution réussie de
   `npm test` contrôlée par le client et l’achèvement sans travail en attente.

La vérification finale contrôle également l’audit réseau de Devin et exige que l’audit des sorties réseau de Claude
reste vide.

## Mise à jour des outils épinglés

L’image épingle Node, Claude Code et Devin CLI dans
`docker/devin-bridge/Dockerfile`. Pour effectuer une mise à jour :

1. modifiez les versions explicites ;
2. remplacez les sommes de contrôle de l’archive Devin propres à chacune des deux architectures par les valeurs de l’artefact
   officiel ;
3. reconstruisez l’image et exécutez toutes les commandes de validation hors ligne ;
4. confirmez les versions dans l’image ;
5. réexécutez la suite authentifiée en conditions réelles comportant trois scénarios.

N’installez aucun des deux CLI globalement sur l’hôte et ne remplacez pas la vérification des sommes de contrôle par un
téléchargement non vérifié.

## Diagnostic et nettoyage

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  affiche le routage local et les erreurs assainies de l’exécuteur.
- `.sandbox/evidence/mock-acp.jsonl` enregistre les actions ACP simulées et déterministes.
- `.sandbox/evidence/claude-stream.jsonl` enregistre l’exécution hors ligne réelle de Claude Code.
- `.sandbox/evidence/live-*.jsonl` enregistre les trois flux en conditions réelles validés.
- `.sandbox/evidence/egress.jsonl` et `.sandbox/evidence/claude-egress.jsonl` sont des copies validées,
  dépourvues de jetons, des audits de contrôle des sorties réseau.

Arrêtez les conteneurs et les réseaux détenus tout en préservant les volumes de connexion/configuration :

```bash
./scripts/devin-bridge/clean
```

Supprimez l’intégralité de l’environnement détenu par le pont, y compris les volumes nommés :

```bash
./scripts/devin-bridge/clean --all
```

## Limites

- Le pont repose sur le rôle `summarizer` fixe sans outils, car Devin CLI `3000.2.17`
  n’expose pas d’agent ACP neutre sans outils. L’adaptateur compense les réponses intermédiaires
  prenant la forme de résumés, mais une unique tentative de réparation bornée peut néanmoins échouer explicitement.
- Les appels ACP en conditions réelles peuvent renvoyer des réponses transitoires `502`/`504`. Le banc de test espace les scénarios ;
  un échec persistant entraîne toujours un arrêt sécurisé et ne sélectionne jamais un autre fournisseur.
- Le contexte ACP est reconstruit à partir de chaque requête Anthropic ; il n’existe aucune affinité de processus/session.
- Un seul appel d’outil est pris en charge par réponse du modèle ; les appels parallèles sont rejetés.
- Les images sont explicitement non prises en charge. La vision, la sortie du raisonnement, les contrôles d’effort et une fenêtre
  de contexte de 1M ne sont pas annoncés.
- SSE utilise des événements de cycle de vie Anthropic valides, mais ceux-ci sont émis après la collecte du tour ACP borné ;
  les fragments ACP ne sont pas transmis de manière incrémentielle.
