`copilot-m365-web` (alias `m365copilot`) envoie des demandes de discussion au format OpenAI via une session Microsoft 365 Copilot authentifiée sur `m365.cloud.microsoft/chat`. Il s'agit d'une intégration native non officielle : aucun processus proxy distinct ni localhost en amont n'est requis. Le fournisseur ID, l'alias et les connexions importées existantes sont inchangés. `copilot-web` est un fournisseur différent pour le service consommateur chez `copilot.microsoft.com`.

> **Vous êtes nouveau sur les fournisseurs de cookies Web ?**
>
> Lire**`docs/getting-started/WEB-COOKIE-GUIDE.md`** pour le processus de configuration général, les conseils d’authentification, les limitations et le dépannage avant de suivre ce guide spécifique au fournisseur.
>
> **Pour les anciennes importations :** Les informations d'identification de ce fournisseur sont** pas un cookie** . Ne copiez pas les cookies de `m365.cloud.microsoft`. Les informations d'identification sont un paramètre de requête WebSocket URL et un segment de chemin, tous deux lus à partir de l'onglet Réseau DevTools.

## Conditions préalables

- Un compte Microsoft 365 avec accès à Copilot chez `m365.cloud.microsoft/chat`
- Un navigateur basé sur Chromium (Chrome, Edge) pour l'inspection DevTools WebSocket
- Accès au modèle demandé sur ce compte ; la disponibilité varie selon le locataire et la licence

## Connexion native (comptes professionnels ou scolaires)

Choisir**Microsoft 365 Copilot → Connecter** et préparez une tentative de connexion. Le tableau de bord utilise un flux de code d'autorisation avec PKCE; il ne vous demande pas votre mot de passe Microsoft ou votre code MFA.

1. Ouvrir un** onglet de navigateur vide** , puis ouvrez**DevTools → Réseau** et activer** Conserver le journal** . Faites ceci avant de naviguer vers Microsoft: Windows SSO peut se terminer immédiatement.
2. Copiez l'autorisation URL affichée par la boîte de dialogue de connexion et accédez-y dans cet onglet préparé. Complétez la sélection du compte Microsoft ou MFA si demandé.
3. Dans le journal réseau conservé, recherchez la requête adressée à `https://login.microsoftonline.com/common/oauth2/nativeclient` et copiez-la dans son intégralité.** Demander URL** .
4. Collez ce URL dans la boîte de dialogue de connexion et connectez-vous. Ne collez pas de code brut ou la barre d'adresse `wrongplace` finale URL: le rappel requis est une navigation transitoire.

Chaque tentative expire après dix minutes et ne peut être utilisée qu'une seule fois. Le serveur vérifie son état, son vérificateur PKCE et sa cible de réauthentification avant d'échanger le code. Après expiration ou échec d’échange, recommencez une nouvelle tentative. Une tentative ne peut pas survivre à un redémarrage du serveur.

Les jetons utilisent le magasin d’informations d’identification de connexion existant et le chemin d’actualisation. La réauthentification d'une connexion nécessite la même identité Microsoft tenant/object, pas simplement le même e-mail. Il préserve l'opérateur naming/settings et remplace les informations d'identification importées obsolètes. La connexion native est destinée aux comptes work/school ; le chemin d'importation hérité reste disponible pour les connexions existantes et les configurations de niveau prises en charge.

Le rappel complet URL est un identifiant unique. Ne l'incluez jamais dans les captures d'écran, les journaux, les messages d'assistance ou les commits. Ce flux n'ouvre pas de navigateur sur le serveur, n'inspecte pas l'historique de votre navigateur et ne démarre pas de serveur de rappel local.

## Capture d'informations d'identification (méthode WebSocket )

1. Connectez-vous à `https://m365.cloud.microsoft/chat` et démarrez une conversation.
2. Ouvrir**DevTools → Réseau** .
3. Filtrer par**WS** (WebSocket).
4. Cliquez sur la connexion Chathub WebSocket. Recherchez un URL commençant par `wss://substrate.office.com/m365Copilot/Chathub/`.
5. De son** Demander URL** , copie :
   - La valeur du paramètre de requête `access_token` (un JWT de courte durée).
   - Le segment du chemin Chathub après `/Chathub/` (par exemple `<oid>@<tenant>`).

Le URL complet a la forme :

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Dans OmniRoute, sélectionnez**Microsoft 365 Copilot** , choisissez l'option API-key/import héritée et collez les informations d'identification au format :

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Cliquez** Tester la connexion** et** Sauvegarder** .

## Capture d'informations d'identification (importation HAR )

Au lieu de copier manuellement les valeurs du WebSocket URL, vous pouvez exporter un fichier DevTools HAR :

1. Ouvrir**DevTools → Réseau** .
2. Démarrez ou poursuivez une conversation Microsoft 365 Copilot (cela déclenche la connexion WebSocket ).
3. Cliquez avec le bouton droit dans le panneau Réseau et sélectionnez** Enregistrez tout au format HAR avec le contenu** .
4. Dans OmniRoute, utilisez le** Importer un fichier .har** dans la boîte de dialogue de connexion au fournisseur.

OmniRoute analyse le HAR à la recherche du Chathub WebSocket URL, extrait le `access_token` et `chathubPath` et remplit automatiquement les champs d'informations d'identification. L'importation HAR décode l'expiration JWT et affiche la durée de vie restante du jeton.

> **Ne commettez jamais une véritable exportation HAR, un jeton d'accès ou un jeton d'actualisation.** Les valeurs de test et de documentation doivent toujours être des espaces réservés.

## Durée de vie et actualisation du jeton

Le `access_token` est de courte durée (généralement**~ 75 minutes** ). Sans jeton d’actualisation utilisable, vous devez capturer à nouveau les informations d’identification après expiration.

### Actualisation automatique avec `refreshToken`

Chez le fournisseur Microsoft 365** Ajouter une connexion** ou** Modifier la connexion** boîte de dialogue, ouvrir** Paramètres avancés Jeton d'actualisation → (facultatif)** . Collez un jeton d'actualisation Microsoft OAuth pour la portée `substrate.office.com/sydney` et enregistrez. L'entrée est masquée et jamais pré-remplie avec le jeton stocké. Lors de la modification, laissez-le vide pour conserver le jeton existant ; collez un nouveau jeton pour le remplacer.

La connexion native acquiert le jeton d'actualisation lorsque Microsoft en renvoie un. Pour les importations existantes, utilisez une autorisation de code d'autorisation Microsoft compatible existante ; ce fournisseur n'implémente ni ne promet de flux de code de périphérique. Avec un jeton d'actualisation configuré, OmniRoute vérifie le `access_token` avant les requêtes et l'actualise uniquement lorsqu'il a besoin d'être actualisé. Une actualisation réussie conserve également le jeton d’actualisation pivoté, évitant ainsi une nouvelle capture manuelle pendant que le jeton d’actualisation reste valide.

Si `refreshToken` n'est pas défini, vous devez capturer à nouveau les informations d'identification WebSocket manuellement après chaque expiration.

| `edu`        | `included` | Éducation M365 Copilot       |

Définir le niveau dans** Paramètres avancés niveau → Copilot** . ## Modèles et routage

Le catalogue natif comprend tous IDs autonomes documentés ainsi que les quatre IDs natifs originaux. Le catalogue est statique et indépendant du compte, il ne s'agit pas d'une vérification des droits d'accès au compte : les itinéraires payants et les alias de compatibilité restent répertoriés même lorsqu'un compte connecté ne peut pas les utiliser. Les étiquettes d’affichage du modèle omettent le nom du fournisseur et la disponibilité standard par modèle ; le fournisseur reste**Microsoft 365 Copilot** . Etiquettes marquées** Alias** ou** Héritage** conserver leurs identifiants et mappages de protocoles existants, ce qui ne constitue pas une garantie d'une version historique du modèle. Les proxy autonomes** Importer depuis /models** les instructions ne s'appliquent pas à ce fournisseur WebSocket natif.

| Famille modèle    | IDs canonique                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| Automatique       | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| Plus tôt GPT      | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude Sonnet     | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude Opus       | `claude-opus`, `claude-opus-4.8`                                                                 |

Des alias tels que `auto`, `quick`, `think-deeper` et des alias de version sont également enregistrés. Les `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` et `copilot-m365-gpt-5-5-chat` existants restent valables. Le IDs documenté a besoin du préfixe du fournisseur (`copilot-m365-web/claude-opus` ou `m365copilot/claude-opus`) : beaucoup sont des mots génériques ou des noms de modèles d'autres fournisseurs, donc un `claude-opus` nu continue de router comme il le fait sans ce fournisseur. L'inscription ne constitue pas une promesse que Microsoft servira ce modèle à chaque compte. Le IDs autonome suit le [catalogue de protocoles](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) publics (la carte modèle-tonalité exportée et ses métadonnées de scénario sensibles au modèle). Tous les profils natifs conservent `availability: "unverified"`; l'inclusion dans le catalogue n'est pas un test de compte réussi.

- Un modèle explicite de refus de licence revient** 403** `m365_model_not_licensed`, pas 502. Le routage verrouille cette paire connection/model, laissant les modèles sous licence sur la connexion utilisables.
- `InvalidCopilotLicense` est un refus de licence au niveau du compte, signalé séparément sous la forme `m365_account_not_licensed`.
- Un régulateur par utilisateur revient** 429** `m365_throttled` et refroidit la connexion. Retours d’épuisement de l’accès prioritaire** 429** `priority_access_exhausted` et est limité au modèle. Un résultat de `OutOfCredits` avec `errorCode: "ReasoningTurnExhausted"` renvoie** 429** `reasoning_turns_exhausted` à la place, également à l'échelle du modèle, sans temps de réinitialisation revendiqué. Il a été signalé qu'un locataire de travail plafonnait les tonalités « Réfléchissez plus profondément » pendant que les tonalités rapides continuaient à fonctionner ; cette portée est une observation du consommateur, et non quelque chose que ce référentiel a reproduit. Le routage retire donc également les autres modèles Think Deeper documentés de `gpt-5.5` et `gpt-5.6` hors rotation sur cette connexion pendant le même temps de recharge, et laisse les tonalités rapides et tous les autres échecs sur son propre modèle. Les conseils de nouvelle tentative fournis sont conservés ; une réinitialisation manquante n'est pas annoncée comme une heure de réinitialisation connue.
- Un refus de sécurité Copilot (`Disengaged`) revient** 400** `provider_safety_rejection`, l'étiquette d'arrêt de sécurité partagée du fournisseur. Cela ne compte jamais dans l'état de la connexion, le client SDKs ne réessaye pas un 400, et avec `PROVIDER_SAFETY_STOPS_TERMINAL` activé, le routage combo s'arrête là au lieu de rejouer la requête sur une autre cible.
- Les requêtes sur une connexion sont sérialisées via le sémaphore du compte existant. Préférez le repli prioritaire plutôt que les panneaux parallèles ; la sérialisation à elle seule n'élimine pas les limites de taux de conversation de Microsoft.

## Comportement et limites des requêtes

- Les outils sont** émulé par invite** , pas les appels de fonction Microsoft natifs. Une requête activée par un outil utilise une génération mise en mémoire tampon ; il ne passe pas une autre génération à sélectionner des outils. Seuls les outils déclarés avec des formes d'arguments prises en charge valides sont renvoyés sous forme d'appels.
- Une longue réponse structurée avec un seul exemple final est conservée sous forme de prose. Il s’agit d’une heuristique, pas d’une preuve d’intention ; les applications doivent toujours appliquer leurs propres autorisations d’outils.
- La saisie d'image fonctionne de la même manière que le client Web l'envoie. Chaque partie d'image (`image_url` en tant que data URL ou public HTTPS URL, ou Responses `input_image`) est téléchargée sur `/m365Copilot/UploadFile` dans la conversation du tour avec le jeton de discussion, et le message la pointe avec une annotation `ImageFile` ; le texte indique où il se trouve (`[image 1]`,…). Une nouvelle conversation télécharge toutes les images de l'historique, une conversation continue uniquement les images des nouveaux messages. Jusqu'à 10 images PNG, JPEG, GIF ou WebP d'au plus 10 MiB chacune (40 MiB par requête) ; le format est lu à partir des octets. HTTPS URLs sont récupérés via le garde d'image distant épinglé DNS public uniquement. Un téléchargement échoué fait échouer la demande (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` ou `m365_image_invalid`); un tour ne se déroule jamais sans une image qui lui a été donnée. Les autres parties non textuelles (audio, fichiers) sont rejetées explicitement et non silencieusement.
- Une demande de suivi poursuit la même conversation en amont et envoie uniquement les messages après la réponse précédente. Il doit étendre cette réponse exactement : même connexion, même profil de modèle et même ensemble d'outils ; un historique inchangé (une chaîne sha256 sur chaque message) ; et les identifiants d'appel d'outil de la réponse, ou son texte jusqu'aux espaces. Tout le reste (un historique modifié, une autre session avec le même premier message, une réponse différente, une conversation inactive pendant 30 minutes ou proche de la limite de 600 messages de Copilot, une connexion sans identifiant) démarre une nouvelle conversation avec tout l'historique. Un tour raté n'est jamais repris et un `InternalError` sans contenu est renvoyé une fois dans une nouvelle conversation (** 502** `m365_internal_error` s'il échoue à nouveau). Les continuations sont conservées dans la mémoire du processus : un redémarrage démarre de nouvelles conversations.
- Chaque tour s'exécute dans le chat temporaire de Copilot(`disableMemory=1`) : la conversation conserve son contexte pendant son exécution et n'apparaît jamais dans l'historique des discussions du compte. Les tests sur modèle, les tests Test All et les tests combinés peuvent donc sonder ce fournisseur sans laisser de côté les conversations.
- Un tour a un délai d'inactivité de 120 secondes et un délai global limité. Les réponses finales uniquement, le filtrage de la progression et l'annulation sont gérés par le transport/composer. natif
- Les réponses basées sur le Web conservent leurs sources. Copilot marque une citation en ligne avec des caractères de contrôle à usage privé et envoie les sources sous la forme `references`; chaque marqueur devient un lien Markdown numéroté (`[1](https://…)`, ou le URL nu lorsque Copilot a utilisé le marqueur comme cible de lien) avec une annotation `url_citation` correspondante (`message.annotations`, ou `delta.annotations` sur le morceau qui porte le lien). Une source qui n'arrive jamais est supprimée, de sorte que les marqueurs n'atteignent jamais le client. Lors de la diffusion en continu, le texte après une citation attend que sa source arrive.
- Le résumé du raisonnement de Copilot(`ChainOfThoughtSummary`), lorsque le modèle en envoie un, est renvoyé sous la forme `reasoning_content`, jamais dans le cadre de la réponse. Un résumé qui se réécrit arrête le streaming sans échouer au tour.
- Avant tout contenu, les échecs licence/throttle conservent HTTP 403/429 même lorsque le streaming a été demandé. Une fois le contenu démarré, les échecs sont des événements d'erreur SSE, jamais une fin réussie. Une réécriture en amont qui ne peut pas être représentée par un streaming en ajout uniquement est une erreur de flux explicite ; les réponses des outils sans streaming et mises en mémoire tampon conservent le texte final.
- Lorsque Copilot refuse lui-même la connexion, sa réponse est rapportée telle quelle :** 401** `m365_unauthorized` pour une connexion refusée ou expirée (reconnectez-vous),** 429** avec son `Retry-After` pour la limitation, et un échec de prise de contact sinon, jamais d'échec de connexion générique.

## Génération d'images

`POST /v1/images/generations` avec `model: "copilot-m365-web/m365-copilot-image"` (alias `m365copilot/m365-copilot-image`) dessine avec l'outil d'image intégré de Copilot, comme le fait le client Web. Chaque image correspond à un tour Copilot : elle s'inscrit avec les ensembles d'options d'image du client Web et déclare `GenerateGraphicArt`, et l'image arrive sur une entrée de progression pointant vers un artefact sur le service Designer de Microsoft. Cet artefact refuse le jeton de discussion, donc OmniRoute crée un jeton Designer à partir du jeton d'actualisation de la connexion et télécharge les octets ; le jeton n'est envoyé qu'à `designerapp.officeapps.live.com`.

- Nécessite une connexion de connexion native (un jeton d’actualisation) ; un jeton collé échoue avec** 400** avant qu'un tour ne soit dépensé.
- `n` vaut 1 à 4, un tour chacun. `size` contrôle uniquement l'orientation (plus large, plus haute ou carrée), que Copilot lit à partir de l'invite ; Copilot choisit la taille du rendu.
- Les images sont renvoyées en ligne : `b64_json` par défaut, une donnée URL pour `response_format: "url"`.
- Les images générées nécessitent un petit budget quotidien, distinct du chat. Lorsqu'il est épuisé, la requête échoue avec** 429** . Un tour qui répond sans image échoue avec** 502** (ou** 400** /** 503** lorsque le texte de Copilot se lit comme un refus ou un problème de capacité) ; le message dit lequel.

## Modèle de sécurité

- **Intégration non officielle.** Ce fournisseur effectue une rétro-ingénierie du protocole BizChat WebSocket. Il peut se briser sans préavis lorsque Microsoft modifie le point de terminaison.
- L'indicateur `subscriptionRisk: true` indique que l'intégration repose sur un point de terminaison non documenté. Des restrictions de compte sont possibles mais non confirmées.
- Le jeton d'accès est un JWT de courte durée. Traitez-le comme un mot de passe : ne le validez pas, ne l'enregistrez pas et ne le partagez pas.
- Le jeton d'actualisation accorde un accès continu à la surface Microsoft 365. Conservez-la avec le même soin qu'une clé API.

## Dépannage

### L'authentification échoue immédiatement

- Vérifiez que vous avez copié à partir du**WebSocket URL** , pas à partir d'une requête XHR/Fetch. Les informations d'identification se trouvent dans le paramètre de requête `access_token` de la connexion Chathub WebSocket — et non dans un en-tête `Authorization: Bearer`.
- Assurez-vous que le `chathubPath` inclut le segment `<oid>@<tenant>` complet du chemin URL.

### Le jeton expire après ~ 75 minutes

Ceci est attendu. Sans `refreshToken`, le jeton d'accès est de courte durée. Soit:

- Récupérez à nouveau les informations d'identification à partir de DevTools, ou
- Configurer** Paramètres avancés → Jeton d'actualisation (facultatif)** dans la boîte de dialogue Ajouter ou Modifier une connexion pour une actualisation automatique.

### Test de connexion réussit mais le chat renvoie 401

Pour une connexion créée avec** Connectez-vous avec Microsoft** , Test Connection vérifie l'expiration du jeton d'accès et renouvelle un jeton expiré avec le jeton d'actualisation stocké, de sorte qu'un test réussi prouve également que le jeton d'actualisation fonctionne toujours.

Pour un identifiant collé, Test Connection vérifie la forme de l'identifiant et, lorsque le jeton arrive à expiration, que le jeton que le fournisseur utiliserait n'a pas expiré (le jeton stocké dans la connexion remporte une pâte périmée ; un jeton d'actualisation est considéré comme renouvelable). Un jeton révoqué avant son expiration réussit quand même le test ; le chat revient puis** 401** `m365_unauthorized`. Utiliser** Connectez-vous avec Microsoft** à nouveau, ou récupérez un nouvel identifiant.

### Copilot n'apparaît pas dans la liste des fournisseurs

Assurez-vous `copilot-m365-web` est activé dans** Fournisseurs de tableaux de bord →** . Le fournisseur peut être masqué par défaut dans certains niveaux.
