> Futásidejű kapcsolók, amelyek **újratelepítés nélkül** módosítják az OmniRoute viselkedését.
> Az itt felsorolt összes jelző definíciója a
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> fájlban található — ez az egyetlen hiteles forrás. Az irányítópult és a REST API egyaránt
> ebből a fájlból olvas, ezért az alábbi táblázat úgy készül, hogy 1:1 arányban megfeleljen neki.

---

## Mik azok a funkciójelzők?

A funkciójelző egy névvel ellátott kapcsoló (logikai vagy felsorolási típusú), amelynek értéke
futásidőben módosítható és az adatbázisban tartósan tárolható, a folyamat újratelepítése nélkül.
Minden jelzőt egy `FeatureFlagDefinition` ír le, amely rendelkezik `key`, `label`,
`description`, `category`, `defaultValue`, `type` mezőkkel és egy `requiresRestart` jelzéssel.

### Feloldási sorrend

Egy jelző **tényleges értékét** a
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) oldja fel a következő
prioritási sorrendben (a magasabb prioritású érvényesül):

1. **Adatbázis-felülírás** — a `key_value` táblában, a `feature_flags`
   névtér alatt tárolt érték (az irányítópulton vagy a REST API-n keresztül beállítva).
2. **Környezeti változó** — `process.env[<KEY>]`, ha be van állítva és nem üres.
3. **A definíció alapértelmezése** — a `featureFlagDefinitions.ts` fájlban megadott `defaultValue`.

Egy logikai jelző akkor tekinthető **engedélyezettnek**, ha tényleges értéke `"true"`,
`"1"` vagy `"yes"` (lásd: `isFeatureFlagEnabled()`).

> [!NOTE]
> A legtöbb jelzőhöz tartozik egy **azonos nevű** környezeti változó is,
> amelynek dokumentációja az [`ENVIRONMENT.md`](./ENVIRONMENT.md) fájlban található. A jelző adatbázisban
> megadott felülírása elsőbbséget élvez ezzel a környezeti változóval szemben. A
> `requiresRestart: true` beállítású jelző azonnal tartósan mentésre kerül, de csak a folyamat
> indulásakor olvassa be újra a rendszer — az ilyen jelző átkapcsolásakor egy
> **„Kiszolgáló újraindítása”** szalag jelenik meg az irányítópulton.

## Jelzők kapcsolgatása

### Irányítópult

Navigáljon ide: **Irányítópult → Beállítások → Funkciójelzők**
(`/dashboard/settings/feature-flags`). A rács
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) támogatja:

- **Keresés** kulcs vagy leírás alapján, valamint **szűrés** kategória szerint (továbbá egy szintetikus
  **Újraindítást igényel** nézetet).
- Logikai jelzők esetén egy **kapcsolót**, felsorolt értékű jelzők esetén pedig egy **legördülő menüt**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Jelzőnként egy **forrásjelvényt** — `DB`, `ENV` vagy `DEF` — amely megmutatja, honnan származik a tényleges érték.
- Egy **Visszaállítás** gombot (csak `DB` forrású jelzőknél jelenik meg) a felülbírálás eltávolításához, valamint alul egy
  **Összes felülbírálás visszaállítása** gombot.
- Egy **Szerver újraindítása** szalagot, amikor egy `requiresRestart` jelző értéke megváltozik.

### REST API

Minden művelet egyetlen útvonalon keresztül történik:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Minden metódus hitelesített irányítópult-munkamenetet igényel (egyébként `401` választ ad).

#### `GET /api/settings/feature-flags`

Minden jelzőt visszaad a tényleges értékével, forrásával és egy összesítéssel együtt.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "API-kulcs megkövetelése",
      "description": "API-kulcs megkövetelése minden beérkező kéréshez",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... mind a 116 jelző
  ],
  "summary": {
    "total": 116,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Egyetlen felülbírálás beállítása vagy eltávolítása. Törzs: `{ key: string; value?: string }`.
A `value` elhagyása eltávolítja a felülbírálást (visszaállítva a környezeti / alapértelmezett értéket).

```bash
# DB-felülbírálás beállítása
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# A felülbírálás eltávolítása ("value" nélkül)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

A válasz tartalmazza az új `effectiveValue`/`source`, a `previousValue`/
`previousSource` és a `requiresRestart` értékét. Az ismeretlen kulcsokat és a megengedett tartományon kívüli felsorolt
értékeket a rendszer `400` válasszal elutasítja.

#### `DELETE /api/settings/feature-flags`

Egyszerre törli az összes DB-felülbírálást, és minden jelzőt visszaállít a környezeti / alapértelmezett
értékére. A visszaadott érték: `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> A `requiresRestart: true` jelzők csak a folyamat újratöltése után lépnek érvénybe.
> Az irányítópult újraindítási folyamata meghívja a `POST /api/restart` végpontot, majd lekérdezi a
> `GET /api/health/ping` végpontot, amíg a szerver ismét elérhetővé nem válik.

## Vészhelyzeti költségkeret-tartalék

Az `OMNIROUTE_EMERGENCY_FALLBACK` (kategória: `runtime`, alapértelmezés: `true`) vezérli a vészhelyzeti ingyenes tartalék útvonalat az [`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts) fájlban. Ha engedélyezve van, a költségkeretüket kimerítő kérések teljes meghiúsulás helyett egy ingyenes tartalék szolgáltatóhoz/modellhez lesznek irányítva. Állítsa `false` (vagy `0`) értékre — az irányítópult kapcsolóján, egy adatbázis-felülbíráláson vagy az `OMNIROUTE_EMERGENCY_FALLBACK` környezeti változón keresztül — a működés letiltásához és a költségkeretüket kimerítő kérések meghiúsulásának engedélyezéséhez. (Az irányítópult kapcsolójaként a #3741 / #3752 PR-ekben jelent meg.)

Az ezen tartalék útvonalon kiszolgált válasz tartalmazza az `X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` fejlécet, így a kliens anélkül állapíthatja meg, hogy a kérés át lett irányítva, hogy össze kellene hasonlítania az `X-OmniRoute-Provider` értékét a saját kérésével. A fejléc minden más válaszból hiányzik.
