A `copilot-m365-web` (alias: `m365copilot`) OpenAI-formátumú csevegési kéréseket küld egy
hitelesített Microsoft 365 Copilot BizChat böngésző-munkameneten keresztül a
`m365.cloud.microsoft/chat` címen. Ez egy nem hivatalos integráció.

> **Még nem használt Web Cookie-szolgáltatókat?**
>
> A szolgáltatóspecifikus útmutató követése előtt olvassa el a **`docs/getting-started/WEB-COOKIE-GUIDE.md`** dokumentumot az általános beállítási folyamatról, a hitelesítési útmutatásról, a korlátozásokról és a hibaelhárításról.
>
> **Fontos:** Ennél a szolgáltatónál a hitelesítő adat **nem cookie**. Ne másoljon
> cookie-kat a `m365.cloud.microsoft` oldalról. A hitelesítő adat egy WebSocket URL lekérdezési
> paraméteréből és útvonalszegmenséből áll; mindkettő a DevTools Network lapján olvasható ki.

## Előfeltételek

- BizChat-hozzáféréssel rendelkező Microsoft 365-fiók a `m365.cloud.microsoft/chat` címen
- Chromium-alapú böngésző (Chrome, Edge) a WebSocket-kapcsolatok DevToolsban történő vizsgálatához
- M365 Copilot-licenc (számos Microsoft 365 Business/Enterprise csomag tartalmazza)

## Hitelesítő adatok rögzítése (WebSocket-módszer)

1. Jelentkezzen be a `https://m365.cloud.microsoft/chat` címen, és indítson beszélgetést.
2. Nyissa meg a **DevTools → Network** lapot.
3. Szűrjön a **WS** (WebSocket) értékre.
4. Kattintson a Chathub WebSocket-kapcsolatra. Keressen egy olyan URL-t, amely a következővel kezdődik:
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. A **Request URL** értékéből másolja ki:
   - Az `access_token` lekérdezési paraméter értékét (egy rövid élettartamú JWT-t).
   - A `/Chathub/` utáni Chathub-útvonalszegmenst (például `<oid>@<tenant>`).

A teljes URL formátuma:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Az OmniRoute-ban lépjen a **Providers → Add Provider** menüpontra, válassza a **Microsoft 365 Copilot
   (BizChat)** lehetőséget, majd illessze be a hitelesítő adatot a következő formátumban:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Kattintson a **Test Connection**, majd a **Save** gombra.

## Hitelesítő adatok rögzítése (HAR-importálás)

Ahelyett, hogy manuálisan másolná ki az értékeket a WebSocket URL-jéből, exportálhat egy DevTools HAR-fájlt:

1. Nyissa meg a **DevTools → Network** lapot.
2. Indítson el vagy folytasson egy BizChat-beszélgetést (ez létrehozza a WebSocket-kapcsolatot).
3. Kattintson jobb gombbal a Network panelen, majd válassza a **Save all as HAR with content** lehetőséget.
4. Az OmniRoute szolgáltatói kapcsolat párbeszédpanelén használja az **Import .har file** gombot.

Az OmniRoute megkeresi a HAR-fájlban a Chathub WebSocket URL-jét, kinyeri az
`access_token` és `chathubPath` értékeket, majd automatikusan kitölti a hitelesítőadat-mezőket. A
HAR-importálás dekódolja a JWT lejárati idejét, és megjeleníti a token hátralévő élettartamát.

> **Soha ne véglegesítsen valódi HAR-exportot, hozzáférési tokent vagy frissítési tokent a verziókövető rendszerben.** A tesztelési és
> dokumentációs értékeknek mindig helyőrzőknek kell lenniük.

## Token élettartama és frissítése

Az `access_token` rövid élettartamú (jellemzően **~75 perc**). Használható refresh token
nélkül a lejárat után újra le kell kérnie a hitelesítő adatot.

### Automatikus frissítés a `refreshToken` használatával

A Microsoft 365-szolgáltató **Kapcsolat hozzáadása** vagy **Kapcsolat szerkesztése** párbeszédpanelén nyissa meg a
**Speciális beállítások → Refresh token (nem kötelező)** lehetőséget. Illesszen be egy Microsoft OAuth refresh tokent a
`substrate.office.com/sydney` hatókörhöz, majd mentse. A beviteli mező maszkolt, és a tárolt token soha nem jelenik meg előre kitöltve. Szerkesztéskor hagyja üresen a mezőt a meglévő token megtartásához;
új token beillesztésével lecserélheti azt.

A refresh tokent egy `substrate.office.com/sydney` hatókörre beállított Microsoft eszközkód- vagy engedélykód-alapú folyamatból szerezze be; az irányítópult nem szerzi be Ön helyett.
Beállított refresh token esetén az OmniRoute a kérések előtt ellenőrzi az `access_token` értékét,
és csak akkor frissíti, amikor szükséges. A sikeres frissítés a rotált refresh tokent is menti,
így nincs szükség manuális újralekérésre, amíg a refresh token érvényes marad.

Ha a `refreshToken` nincs beállítva, minden lejárat után manuálisan újra le kell kérnie a WebSocket hitelesítő adatát.

### Szint kiválasztása

| Szint        | Alias               | Felület                |
| ------------ | ------------------- | ---------------------- |
| `individual` | _(alapértelmezett)_ | Consumer M365 Copilot  |
| `edu`        | `included`          | Education M365 Copilot |
| `enterprise` | `work`              | M365 Copilot for Work  |

A szintet a **Speciális beállítások → Copilot-szint** alatt állíthatja be. A szint hatással van
a BizChat-útválasztásra és a modellhozzáférésre.

## Biztonsági modell

- **Nem hivatalos integráció.** Ez a szolgáltató visszafejtett módon használja a BizChat WebSocket-protokollját. Előzetes értesítés nélkül működésképtelenné válhat, ha a Microsoft módosítja a végpontot.
- A `subscriptionRisk: true` jelző azt tükrözi, hogy az integráció nem dokumentált végpontra támaszkodik. A fiók korlátozása lehetséges, de nem megerősített.
- A hozzáférési token egy rövid élettartamú JWT. Kezelje jelszóként: ne véglegesítse verziókezelőben, ne naplózza és ne ossza meg.
- A frissítési token hosszú távú hozzáférést biztosít a BizChat felületéhez. Ugyanolyan gondosan tárolja, mint egy API-kulcsot.

## Hibaelhárítás

### A hitelesítés azonnal meghiúsul

- Ellenőrizze, hogy a **WebSocket URL**-ből másolt-e, nem pedig egy XHR/Fetch-kérésből. A hitelesítő adat a Chathub WebSocket-kapcsolatának `access_token` lekérdezési paraméterében található — nem egy `Authorization: Bearer` fejlécben.
- Győződjön meg arról, hogy a `chathubPath` tartalmazza az URL elérési útjából származó teljes `<oid>@<tenant>` szegmenst.

### A token körülbelül 75 perc után lejár

Ez várható. `refreshToken` nélkül a hozzáférési token rövid élettartamú. Vagy:

- Rögzítse újra a hitelesítő adatot a DevToolsból, vagy
- Állítsa be a **Speciális beállítások → Frissítési token (opcionális)** lehetőséget a Kapcsolat hozzáadása vagy szerkesztése párbeszédpanelen az automatikus frissítéshez.

### A kapcsolat tesztelése sikeres, de a csevegés 401-es hibát ad vissza

Lehetséges, hogy a token az ellenőrzés és az első kérés között lejárt. Rögzítsen újra egy friss hitelesítő adatot.

### A Copilot nem jelenik meg a szolgáltatók listájában

Győződjön meg arról, hogy a `copilot-m365-web` engedélyezve van az **Irányítópult → Szolgáltatók** menüpontban. Egyes csomagszinteken a szolgáltató alapértelmezés szerint rejtve lehet.
