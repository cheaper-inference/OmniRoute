Az `@omniroute/opencode-plugin-v2` a teljes OmniRoute-katalógust — modelleket, kombókat és
automatikus kombókat — elérhetővé teszi az OpenCode v2 modellválasztójában, megjelenítési nevekkel,
árakkal és ingyenes keretekkel együtt.

Ez az `@omniroute/opencode-plugin` csomagtól különálló csomag, mivel az OpenCode v1 és v2 eltérő
szerződések alapján tölti be a bővítményeket. Válaszd az OpenCode főverziódhoz illőt; semmit sem
osztanak meg egymással, így az egyik frissítése soha nem kényszeríti ki a másikét.

## Követelmények

- OpenCode v2.
- Egy elérhető OmniRoute-átjáró (alapértelmezés szerint `http://localhost:20128`).
- Node.js 22 vagy 24.

## Telepítés

Add hozzá a bővítményt az `opencode.json` fájlhoz:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

A modellek ezután `omniroute/<provider>/<model>` formában jelennek meg; a `providerId` határozza meg
ezt az előtagot, valamint annak az integrációnak az azonosítóját, amely alatt az OpenCode tárolja a hitelesítő adatot.

## Hitelesítő adatok

A bővítmény három helyen keresi az átjáró kulcsát, a következő sorrendben:

1. **Az OpenCode-ban csatlakoztatott hitelesítő adat.** A bővítmény regisztrál egy integrációt, így
   az OpenCode saját hitelesítési folyamata tárolhatja a kulcsot. Semmi sem kerül az `opencode.json`
   fájlba — ezt a megoldást részesítsd előnyben.
2. A bővítmény beállításaiban megadott `apiKey`, projektenkénti felülbíráláshoz. Ez a kulcsot egy
   olyan fájlba helyezi, amelyet esetleg verziókezelőbe küldesz.
3. A környezetben megadott `OMNIROUTE_API_KEY`.

Ha egyik sincs megadva, a katalógus üres lesz, és a bővítmény erről egyszer értesít induláskor,
ahelyett, hogy minden jelzés nélkül üres modellválasztót hagyna.

### A felügyeleti token egy másik kulcs

A kombók, a szolgáltatók állapota és a bővített adatok (megjelenítési nevek, árak, ingyenes keretek)
az átjáró `/api/*` végpontjairól származnak, amelyeket a legtöbb telepítés a következtetési kulcs
helyett egy **felügyeleti** tokennel véd:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<felügyeleti olvasási token>"
}
```

Ha nincs beállítva, a `managementReadToken` az `apiKey` értékére vált vissza. Amikor egy átjáró
elutasítja ezt a tartalék megoldást, a katalógus továbbra is közzétételre kerül, de a megjelenítési
nevek helyett nyers modellazonosítókkal, kanonikus aliasok deduplikálása, árak és kombók nélkül.
Ilyenkor a bővítmény végpontonként egyszer figyelmeztet, megnevezve a végpontot és azt, hogy milyen
adatok vesztek el — így a korlátozott modellválasztó oka sosem marad rejtély.

## Beállítások

| Kulcs                            | Alapértelmezett                                           | Megjegyzések                                                                                                                                        |
| -------------------------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                             | A szolgáltató azonosítója, az integráció azonosítója és a modellek megjelenítési előtagja                                                           |
| `baseURL`                        | kötelező                                                  | Az átjáró gyökér-URL-je, csak `http(s)`; a `/v1` utótag szükség szerint automatikusan hozzáadódik                                                   |
| `apiKey`                         | csatlakoztatott hitelesítő adat, majd `OMNIROUTE_API_KEY` | Csevegési kulcs a `/v1/*` végpontokhoz                                                                                                              |
| `managementReadToken`            | visszaáll az `apiKey` értékére                            | Kulcs az `/api/*` végpontokhoz — általában **nem** ugyanaz                                                                                          |
| `displayName`                    | `"OmniRoute"`                                             | A szolgáltató neve a választóban                                                                                                                    |
| `timeoutMs`                      | `10000`                                                   | Végpontonkénti lekérési időkorlát (az automatikus kombinációknál 5 másodperc)                                                                       |
| `modelCacheTtlMs`                | `300000`                                                  | A katalógus-gyorsítótár TTL-je; egy lemezen tárolt pillanatkép felgyorsítja a hidegindításokat                                                      |
| `timeouts`                       | visszaáll a `timeoutMs` értékére                          | Végpontonkénti időkeretek ezredmásodpercben: `models`, `combos`, `autoCombos`, `enrichment`                                                         |
| `enrichment`                     | `true`                                                    | Nevek, árak és ingyenes csomaghoz tartozó keretek lekérése                                                                                          |
| `providerTag`                    | `true`                                                    | A megjelenítési név elé illeszti annak a felsőbb szintű szolgáltatónak a nevét, amelyhez az útvonal vezet                                           |
| `usableOnly`                     | `false`                                                   | Csak azokat a szolgáltatókat tartja meg, amelyeket az átjáró kiépítettként jelent                                                                   |
| `combosSource`                   | `"api"`                                                   | A `"models"` kihagyja az `/api/combos` végpontot, és közzéteszi a `/v1/models` kombinációs sorait; a tagszintű szűrők megtartják az `"api"` értéket |
| `showcasePerOwner`               | `10`                                                      | Szolgáltatónként megtartott bejegyzések száma az alapértelmezett nézetben                                                                           |
| `freshPerOwner`                  | `10`                                                      | Szolgáltatónként megtartott friss bejegyzések száma az alapértelmezett nézetben                                                                     |
| `freshWindowDays`                | `90`                                                      | A friss ághoz tartozó frissességi időablak napokban                                                                                                 |
| `usageMemory`                    | `true`                                                    | Visszaállítja a statikusan elvetett azon bejegyzéseket, amelyeket a 30 napos használati elemzés megnevez (felügyeleti token szükséges)              |
| `visibleModels` / `hiddenModels` | `[]`                                                      | Pontos vagy utótagalapú engedélyezési listák; a tiltás elsőbbséget élvez; a `*` közzéteszi a teljes katalógust (a többi szűrő továbbra is érvényes) |
| `geminiSanitization`             | `true`                                                    | Eltávolítja az eszközsémákból a Gemini által elutasított JSON-Schema-kulcsszavakat (a `$ref`-eszközök változatlanul továbbítódnak)                  |
| `apiFormat.allowAnthropic`       | `false`                                                   | Az engedélyezési listán szereplő azonosítókat az Anthropic API-blokkon keresztül irányítja                                                          |
| `apiFormat.anthropicModels`      | `[]`                                                      | Az Anthropichoz irányított teljes modellazonosítók                                                                                                  |
| `logLevel` / `startupDebug`      | `warn` / `false`                                          | A naplózás részletessége                                                                                                                            |

A használati memória alapértelmezés szerint be van kapcsolva. Felügyeleti token nélkül inaktív marad
(a rendszer indításkor naplóz egy értesítést), és semmi sem kerül visszaállításra.

## Hogyan marad naprakész a katalógus

A katalógus lusta betöltéssel kérődik le, és `modelCacheTtlMs` ideig gyorsítótárazódik, egy lemezen tárolt pillanatkép pedig elérhetővé teszi az utoljára ismert katalógust, amikor az átjáró nem érhető el — egy kiesés így csak a frissességet érinti. A modellek és kombinációk érkezésük után azonnal közzétételre kerülnek; az automatikus kombinációk, a szolgáltatók listája és a kiegészítő réteg akkor épülnek be, amikor megérkeznek, így egy lassú végpont nem tarthatja fel a teljes választót.

A nevek tartalmazzák az átjáró által ismert információkat: azt a felsőbb szintű szolgáltatót, amelyhez egy modell továbbításra kerül, egy `[Free]` jelölést és a hozzá tartozó keretet — így az ugyanazt a modellt kínáló két kapcsolat megkülönböztethető marad. Az előtag a `"providerTag": false` beállítással kapcsolható ki.

Nincs kézi frissítési parancs: az OpenCode v2 parancsai prompt-sablonok, nem visszahívások, ezért egy bővítmény nem tehet közzé ilyen parancsot. A frissítések a TTL-t követik; a rendszer csak akkor kéri a gazdafolyamatot az újratöltésre, ha a katalógus vagy a kiegészítő réteg ténylegesen megváltozott, és soha nem minden egyes frissítéskor.

## Eszközhívás a Geminiben

A Gemini elutasít minden olyan teljes kérést, amelynek eszközdeklarációi `$schema` vagy `additionalProperties` elemet tartalmaznak, és `400 INVALID_ARGUMENT` választ ad. A bővítmény eltávolítja ezeket a kulcsszavakat az e szolgáltató Gemini-modelljének szánt eszközsémákból, miközben minden más kérést változatlanul hagy. A `$ref` elemet tartalmazó eszköz módosítás nélkül kerül továbbításra, mivel a hivatkozás eltávolítása „bármit elfogadóvá” tágítaná a sémát.
A kikapcsolásához állítsa be a `"geminiSanitization": false` értéket.

## Hibaelhárítás

| Tünet                                                         | Ok                                                                                                                                                                |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A választó nem jelenít meg OmniRoute-modellt                  | Nem sikerült kulcsot feloldani (ellenőrizze az indítási figyelmeztetést), vagy az átjáró nem érhető el                                                            |
| Nyers modellazonosítók, nincsenek kombinációk, nincsenek árak | A felügyeleti végpontok elutasították a tokent — állítsa be a `managementReadToken` értékét                                                                       |
| Rövid vagy üres `freeOnly` katalógus                          | Nincs felügyeleti token, vagy a tokent elutasították — olvassa el a frissítési összegző sort (`unmatched-free` darabszám) a gazdagép naplójában                   |
| Egy munkamenet az `opencode-<id>/…` elemhez van rögzítve      | A v1 beépülő modul az `opencode-<id>` azonosítót tette közzé; a v2 csak a nyers `<id>` azonosítót teszi közzé, ezért válassza ki újra a modellt az `<id>/…` alatt |

A környezeti változóknak el kell jutniuk az opencode kiszolgálófolyamatához: amikor a gazdagép
szolgáltatásként fut, az `opencode models` parancsot futtató parancsértelmező és a kiszolgáló
környezete eltér, ezért ott exportálja a kulcsot, ahonnan a kiszolgáló beolvassa.
