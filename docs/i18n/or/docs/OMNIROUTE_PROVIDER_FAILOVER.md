ପୁନର୍ବାର ନିଷ୍ପତ୍ତି ନେବା ପୂର୍ବରୁ ବିଫଳତା ବର୍ଗୀକୃତ ହୋଇଛି।

କ୍ଷଣସ୍ଥାୟୀ ବିଫଳତା ଯେପରିକି ସମୟ ସମାପ୍ତ, ନେଟୱର୍କ ତ୍ରୁଟି, ହାର ସୀମା, ଏବଂ ପ୍ରଦାନକାରୀ 5xx ପ୍ରତିକ୍ରିୟା ସମାପ୍ତ ହୋଇପାରେ। କ୍ଳାନ୍ତ କୋଟା କିମ୍ବା କ୍ରେଡିଟ୍ (ଏକ କୋଟା 429, କିମ୍ବା 402 ଦେୟ ଆବଶ୍ୟକ) ସମାନ ପ୍ରଦାନକାରୀଙ୍କ ଉପରେ କେବେବି ପୁନ ry ଚେଷ୍ଟା କରାଯାଏ ନାହିଁ କିନ୍ତୁ ଅନ୍ୟ ଜଣକୁ ବିଫଳ ହୁଏ, ଯାହାର କୋଟା ଅଲଗା ଅଟେ। ପ୍ରାମାଣିକିକରଣ ତ୍ରୁଟି, ଅନୁମତି ତ୍ରୁଟି, ଅବ alid ଧ ଅନୁରୋଧ, ଅନୁପଲବ୍ଧ ମଡେଲ, ଏବଂ ଅଜ୍ଞାତ ବିଫଳତା ଅନ୍ଧ ଭାବରେ ପୁନ ry ଚେଷ୍ଟା କରାଯାଏ ନାହିଁ।

ଡିଫଲ୍ଟ କ୍ରସ୍-ପ୍ରଦାନକାରୀ ନୀତି ତିନୋଟି ପ୍ରଦାନକାରୀ ପ୍ରୟାସକୁ ଅନୁମତି ଦେଇଥାଏ, ହାର ସୀମା ଏବଂ ସମୟ ସମାପ୍ତ କରେ, କ୍ଳାନ୍ତ କୋଟା ଉପରେ ବିଫଳ ହୁଏ, ଏବଂ ପ୍ରଶାସନିକ ଅକ୍ଷମତାକୁ ଅସ୍ଥାୟୀ ସର୍କିଟ୍ ସ୍ଥିତିରୁ ପୃଥକ ରଖେ।

## ଯେଉଁଠାରେ ଏହା ପ୍ରଯୁଜ୍ୟ।

- **କମ୍ବୋସ୍।** କମ୍ବୋ ର ନିଜସ୍ୱ ରଣନୀତି ଏବଂ ସେଟିଙ୍ଗ୍ ଅନୁଯାୟୀ ସେମାନଙ୍କ ଟାର୍ଗେଟ୍ ମଧ୍ୟରେ ବିଫଳ ହୁଅନ୍ତୁ।
- **ଏକ ଖାଲି ମଡେଲ୍ id।** (କ z ଣସି `provider/` ଉପସର୍ଗ ନାହିଁ) ଯାହା ଅନେକ ସକ୍ରିୟ ପ୍ରଦାନକାରୀ ସେବା କରନ୍ତି, ସେହି ସଠିକ ନାମର କମ୍ବୋ ସହିତ, ପ୍ରଥମେ ପ୍ରଦାନକାରୀ ଇନଫେରେନ୍ସ ପିକ୍ସକୁ ପଠାଯାଏ। ଯଦି ସେହି ପ୍ରୟାସ ନୀତି ବିଫଳ ହେବା ପରି ଭାବରେ ବିଫଳ ହୁଏ, ସମାନ ଅନୁରୋଧ ପରବର୍ତ୍ତୀ ସକ୍ରିୟ ପ୍ରଦାନକାରୀଙ୍କୁ ପଠାଯାଏ ଯାହା id କୁ ସେବା କରେ। ପ୍ରତିକ୍ରିୟା `x-omniroute-fallback-attempts` ବହନ କରେ ଯାହା ଉତ୍ତର ଦେଇଥିବା ପୂର୍ବରୁ ପ୍ରଦାନକାରୀଙ୍କ ସଂଖ୍ୟା ସହିତ।
  - ପ୍ରତ୍ୟେକ ବିକଳ୍ପ ସଠିକ୍ ଭାବରେ ସ୍ authorized ୀକୃତପ୍ରାପ୍ତ ଯେପରି ଇନଫେରେନ୍ସ ଏହାକୁ ଉଠାଇ ନେଇଛି। ଏକ ଲକ୍ଷ୍ୟ API କି ବ୍ଲକଗୁଡିକ କିମ୍ବା ସ୍ୱୀକାର କରେ ନାହିଁ ଅପଷ୍ଟ୍ରିମ କଲ୍ ବିନା ଏଡ଼ାଇ ଦିଆଯାଏ, ଏବଂ ଗ୍ରାହକ ପ୍ରକୃତ ଅପଷ୍ଟ୍ରିମ ତ୍ରୁଟି ପାଇଥାଏ, ଯାହା ଏକ ନାମ ପାଇଁ ଏକ ନୀତି ପ୍ରତ୍ୟାଖ୍ୟାନ ନୁହେଁ।
  - କେବଳ ଏକ ବିଫଳ ପ୍ରତିକ୍ରିୟା ଆଗକୁ ବ: େ: ପ୍ରଥମ ଷ୍ଟ୍ରିମ୍ ବାଇଟ୍ ପରେ କିଛି ବିଫଳ ହୁଏ ନାହିଁ।
  - ଅନୁରୋଧ କରାଯାଇଥିବା ମଡେଲର ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀ ବିଫଳ ହେବା ପରେ ଜରୁରୀକାଳୀନ ଫଲବ୍ୟାକ୍ ମଡେଲ୍ ସ୍ ap ାପ୍ ପ୍ରଯୁଜ୍ୟ।
  - ଏକ ସଂଯୋଗ (`x-omniroute-connection`) ରେ ପିନ୍ ହୋଇଥିବା ଏକ ଅନୁରୋଧ ଏହା ଉପରେ ରହିଥାଏ।
  - ଏକ ଉପସର୍ଗିତ id (`provider/model`) ଅନ୍ୟ ପ୍ରଦାନକାରୀଙ୍କୁ କେବେବି ମାର୍ଗଦର୍ଶନ କରାଯାଏ ନାହିଁ।

ସର୍କିଟ୍ ଅବସ୍ଥା ହେଉଛି `closed`, `open`, ଏବଂ `half_open`। ଏକ କୁଲଡାଉନ୍ ଏକ ସୀମାବଦ୍ଧ ଅନୁସନ୍ଧାନ କାର୍ଯ୍ୟସୂଚୀ କରେ; ଏକ ସଫଳ ଅନୁସନ୍ଧାନ ସର୍କିଟ୍କୁ ବନ୍ଦ କରିଥାଏ ଏବଂ ଏକ ବିଫଳ ଅନୁସନ୍ଧାନ ଏହାକୁ ପୁନ op ଖୋଲିଥାଏ।
