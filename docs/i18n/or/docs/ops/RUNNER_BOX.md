## ଜାନିଟର୍କୁ ଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ (କେବଳ ଥରେ, ମେସିନ୍ରେ)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ପ୍ରତି 30 ମିନିଟ୍ରେ, /var/log/runner-janitor.log ରେ ଲଗ୍ କରନ୍ତୁ
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` ଆବଶ୍ୟକ: ଜାନିଟର୍ କୌଣସି ପଥକୁ ଅପସାରଣ କରିବା ପୂର୍ବରୁ ଖୋଲା
ଫାଇଲ୍ଗୁଡ଼ିକର ଗୋଟିଏ ସ୍ନାପସଟ୍ ନେଇ ତାହା ନିଷ୍କ୍ରିୟ ବୋଲି ପ୍ରମାଣ କରେ, ଏବଂ ଏହି ଟୁଲ୍ ନଥିଲେ ଏହା କିଛି
ଅପସାରଣ କରେନାହିଁ ଓ ସେହି କଥା ଜଣାଏ
(exit 1)। କୌଣସି ପରିବର୍ତ୍ତନକୁ ପ୍ରଥମେ `--dry-run` ସହିତ ପରୀକ୍ଷା କରନ୍ତୁ — ଏହା ଠିକ୍ କ’ଣ
କରିବ ତାହା ପ୍ରିଣ୍ଟ କରେ ଏବଂ କିଛି ସ୍ପର୍ଶ କରେନାହିଁ।

ପ୍ରତ୍ୟେକ ଥର ଚାଲିବାବେଳେ ଏହା ଯାହା କରେ: **tmpfsରେ 3 ଘଣ୍ଟା** ଏବଂ ଡିସ୍କର
`_work/_temp`ରେ 24 ଘଣ୍ଟା ପରେ ଆମର ନିଜସ୍ୱ ଅବଶିଷ୍ଟଗୁଡ଼ିକୁ (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) ସଫା କରେ; 75 ମିନିଟ୍ରୁ ପୁରୁଣା `next-build`କୁ ବନ୍ଦ କରେ (କୌଣସି ଜବ୍ ଏତେ ସମୟ ଚାଲେନାହିଁ —
2026-08-27ରେ GitHub ତାହାର ଜବ୍କୁ ହଜିଯାଇଛି ବୋଲି ଘୋଷଣା କରିବା ପରେ ଗୋଟିଏ ଜବ୍ 70 ମିନିଟ୍ ଚାଲିଥିଲା);
ଯେଉଁ runnerର unit **ବନ୍ଦ** ଅଛି, ସେଗୁଡ଼ିକର 48 ଘଣ୍ଟା ପୁରୁଣା
checkoutକୁ ହଟାଏ; ଡିସ୍କ ≥ 85 %, memory PSI
`full/avg60` ≥ 10 %, ଏବଂ `MAX_ACTIVE_RUNNERS` ଠାରୁ ଅଧିକ listener ଥିଲେ ସତର୍କ କରେ (omniroute/ଅନ୍ୟ
ବିଭାଜନ ସହିତ)। Exit 1 = ଧ୍ୟାନ ଦେବା ଆବଶ୍ୟକ; ଲଗ୍ ପଢ଼ନ୍ତୁ।

GitHub ପୂର୍ବରୁ ପରିତ୍ୟାଗ କରିସାରିଥିବା ଜବ୍ର buildକୁ 75 ମିନିଟ୍ର ନିୟମ ଧରିପାରେନାହିଁ। ଯେତେବେଳେ
`Runner.Listener` ତାହାର ଜବ୍କୁ renew କରିପାରେନାହିଁ, `_diag/Runner_*.log`ରେ
`POST request to …/renewjob timed out after 100 seconds` ଦେଖାଯାଏ, ଶେଷ ସଫଳ renewalର ପ୍ରାୟ ଦଶ ମିନିଟ୍ ପରେ API ଜବ୍କୁ `completed`
(failure) ବୋଲି ରିପୋର୍ଟ କରେ, ଏବଂ କୌଣସି ଜବ୍ ସଂଲଗ୍ନ ନଥାଇ `next-build` ଚାଲୁ ରହେ
(2026-10-18: #17066ର Build 19:43ରେ ବିଫଳ ହୋଇଥିଲା ଏବଂ ପାଞ୍ଚ ମିନିଟ୍ ପରେ ମଧ୍ୟ ତାହାର build
40 GB ଧରି ରଖିଥିଲା)। ସବୁଠାରୁ ନୂଆ `_diag/Worker_*.log`ରେ ref ନିଶ୍ଚିତ କରନ୍ତୁ, ତା’ପରେ
PID ଅନୁଯାୟୀ କେବଳ build treeକୁ SIGTERM ପଠାନ୍ତୁ — `next-build`, `npm run build`, `build-next-isolated.mjs` ଏବଂ
`_work` workerଗୁଡ଼ିକ। `Runner.Listener`, `RunnerService.js` କିମ୍ବା `Runner.Worker`କୁ କେବେ ମଧ୍ୟ ସ୍ପର୍ଶ କରନ୍ତୁ ନାହିଁ:

## Runner unitଗୁଡ଼ିକ: KillMode

Runnerର ଡିଫଲ୍ଟ `KillMode=process`, କୌଣସି unit ବନ୍ଦ କିମ୍ବା restart ହେଲେ
`Runner.Worker → npm → next-build`କୁ ଚାଲୁ ଛାଡ଼ିଦିଏ — ସଂଲଗ୍ନ ଜବ୍ ନଥିବା ଏକ orphan build RAM ଏବଂ
CPU ବ୍ୟବହାର କରିଚାଲେ। ପ୍ରତ୍ୟେକ OmniRoute unitରେ
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
ପଥରେ `KillMode=mixed` ସହିତ ଗୋଟିଏ drop-in ରହେ: ପ୍ରଥମେ listenerକୁ SIGTERM, ତା’ପରେ
`TimeoutStop`ରେ ସମ୍ପୂର୍ଣ୍ଣ cgroupକୁ SIGKILL। Unitର ପରବର୍ତ୍ତୀ restartରେ ଏହା କାର୍ଯ୍ୟକାରୀ ହୁଏ — **ଗୋଟିଏ ସମୟରେ
କେବଳ ଗୋଟିଏ runnerକୁ, ଏବଂ ତାହା ନିଷ୍କ୍ରିୟ ଥିବାବେଳେ ମାତ୍ର** restart କରନ୍ତୁ, idle check ଏବଂ restartକୁ ସମାନ commandରେ ରଖନ୍ତୁ।
