## ଇନ୍ଷ୍ଟଲେସନ୍

OmniRoute MCP ଅନ୍ତର୍ନିର୍ମିତ। ଏହାକୁ ଏପରି ଆରମ୍ଭ କରନ୍ତୁ:

```bash
omniroute --mcp
```

କିମ୍ବା open-sse ଟ୍ରାନ୍ସପୋର୍ଟ ମାଧ୍ୟମରେ:

```bash
# HTTP ଷ୍ଟ୍ରିମ୍ଯୋଗ୍ୟ ଟ୍ରାନ୍ସପୋର୍ଟ (ପୋର୍ଟ 20130)
omniroute --dev  # MCP /mcp ଏଣ୍ଡପଏଣ୍ଟ୍ରେ ସ୍ୱୟଂଚାଳିତ ଭାବେ ଆରମ୍ଭ ହୁଏ
```

HTTP ଟ୍ରାନ୍ସପୋର୍ଟଗୁଡ଼ିକ (`sse` / `streamable-http`, ଡ୍ୟାସ୍ବୋର୍ଡ ସର୍ଭର୍ ଦ୍ୱାରା ଇନ୍-ପ୍ରୋସେସ୍ ପରିବେଷିତ) ଡିଫଲ୍ଟ ଭାବେ
ବନ୍ଦ ଥାଏ ଏବଂ ପୂର୍ବରୁ କେବଳ `/dashboard/mcp` ପୃଷ୍ଠାରୁ ଟଗଲ୍ କରାଯାଇପାରୁଥିଲା। v3.8.51 ଠାରୁ
CLIରେ ମଧ୍ୟ ସମାନ ସୁବିଧା ରହିଛି:

```bash
omniroute mcp status                                  # ସକ୍ଷମ/ଅନ୍ଲାଇନ୍, ଟ୍ରାନ୍ସପୋର୍ଟ, ଟୁଲ୍ ସଂଖ୍ୟା
omniroute mcp enable [--transport stdio|sse|streamable-http]
omniroute mcp disable
omniroute mcp restart                                 # ସକ୍ରିୟ sse/streamable-http ସେସନ୍ଗୁଡ଼ିକୁ ରିସେଟ୍ କରେ
```

`mcp enable`/`mcp disable`, ଡ୍ୟାସ୍ବୋର୍ଡ `/api/settings` ମାଧ୍ୟମରେ ଟଗଲ୍ କରୁଥିବା ସେହି `mcpEnabled` (ଏବଂ ଇଚ୍ଛାଧୀନ ଭାବେ `mcpTransport`) ସେଟିଂକୁ
PATCH କରେ। `mcp restart`, `POST /api/mcp/restart`କୁ କଲ୍ କରେ: ଏହା ସକ୍ରିୟ
`sse`/`streamable-http` ସେସନ୍ଗୁଡ଼ିକୁ ବନ୍ଦ କରେ, ଯାହାଦ୍ୱାରା ପରବର୍ତ୍ତୀ ଅନୁରୋଧ ସଫା ଭାବେ ପୁନଃ-ଆରମ୍ଭ ହୁଏ; MCP ଅକ୍ଷମ ଥିଲେ
`409` ଏବଂ `stdio` ଟ୍ରାନ୍ସପୋର୍ଟ ପାଇଁ `501` ଫେରାଏ (stdio କ୍ଲାଏଣ୍ଟଗୁଡ଼ିକ ନିଜସ୍ୱ
ସବ୍ପ୍ରୋସେସ୍ ପରିଚାଳନା କରନ୍ତି — ପୁନଃଚାଳୁ କରିବା ପାଇଁ କୌଣସି ଇନ୍-ପ୍ରୋସେସ୍ ହ୍ୟାଣ୍ଡଲ୍ ନାହିଁ)।

## ଟ୍ରାନ୍ସପୋର୍ଟଗୁଡ଼ିକ

MCP ସର୍ଭର୍ ତିନୋଟି ଟ୍ରାନ୍ସପୋର୍ଟ ଉପଲବ୍ଧ କରାଏ, ଯାହା ସବୁ ସମାନ `createMcpServer()` ଫ୍ୟାକ୍ଟରି ଦ୍ୱାରା ସମର୍ଥିତ:

| ଟ୍ରାନ୍ସପୋର୍ଟ      | କେଉଁଠାରେ                                         | କେତେବେଳେ ବ୍ୟବହାର କରିବେ                                        |
| :---------------- | :----------------------------------------------- | :------------------------------------------------------------ |
| `stdio`           | `open-sse/mcp-server/server.ts`                  | IDE ଇଣ୍ଟିଗ୍ରେସନ୍ଗୁଡ଼ିକ (Claude Desktop, Cursor ଇତ୍ୟାଦି)       |
| `sse`             | `httpTransport` ମାଧ୍ୟମରେ `POST/GET /api/mcp/sse` | ଇଭେଣ୍ଟ ଷ୍ଟ୍ରିମ୍ ଆବଶ୍ୟକ କରୁଥିବା ବ୍ରାଉଜର୍/ଏଜେଣ୍ଟ କ୍ଲାଏଣ୍ଟଗୁଡ଼ିକ |
| `streamable-http` | `POST/GET/DELETE /api/mcp/stream`                | ମଲ୍ଟି-ସେସନ୍ HTTP କ୍ଲାଏଣ୍ଟଗୁଡ଼ିକ (`mcp-session-id` ହେଡର୍)      |

ସକ୍ରିୟ HTTP ଟ୍ରାନ୍ସପୋର୍ଟ (`sse` କିମ୍ବା `streamable-http`) `mcpTransport` ସେଟିଂ ଦ୍ୱାରା ଚୟନ କରାଯାଏ। ଟ୍ରାନ୍ସପୋର୍ଟ ପରିବର୍ତ୍ତନ କଲେ ଅନ୍ୟ ଟ୍ରାନ୍ସପୋର୍ଟରେ ଥିବା ବିଦ୍ୟମାନ ସେସନ୍ଗୁଡ଼ିକ ବନ୍ଦ ହୋଇଯାଏ।

### ରିମୋଟ୍ ଆକ୍ସେସ୍ (manage-scope ବାଇପାସ୍)

`/api/mcp/*`, LOCAL_ONLY ସ୍ତରରେ ଅଛି (`src/server/authz/routeGuard.ts`) — ଡିଫଲ୍ଟ ଭାବେ କେବଳ ଲୁପ୍ବ୍ୟାକ୍ ହୋଷ୍ଟଗୁଡ଼ିକ (`localhost`, `127.0.0.1`, `::1`) ଏହାକୁ ଆକ୍ସେସ୍ କରିପାରନ୍ତି। v3.8.2 ଠାରୁ, ଯଦି ନନ୍-ଲୁପ୍ବ୍ୟାକ୍ କ୍ଲାଏଣ୍ଟଗୁଡ଼ିକ ଏପରି ଏକ `Authorization: Bearer <api-key>` ପ୍ରଦାନ କରନ୍ତି ଯାହାର କୀ ପାଖରେ `manage` ସ୍କୋପ୍ ଅଛି, ତେବେ ସେମାନେ ସଂଯୋଗ କରିପାରିବେ। ଟନେଲ୍, ରିଭର୍ସ ପ୍ରକ୍ସି କିମ୍ବା ସାର୍ବଜନୀନ ହୋଷ୍ଟନେମ୍ ମାଧ୍ୟମରେ ରିମୋଟ୍ MCP ସର୍ଭର୍କୁ ଆକ୍ସେସ୍ କରିବାର ଏହା ହେଉଛି ଏକମାତ୍ର ଉପାୟ।

```bash
# manage ସ୍କୋପ୍ ପ୍ରଦାନ କରନ୍ତୁ: ଡ୍ୟାସ୍ବୋର୍ଡର API Keys ପୃଷ୍ଠା ଖୋଲି କୀରେ
# "Management Access" ଟଗଲ୍ କରନ୍ତୁ, କିମ୍ବା ସୃଷ୍ଟି କରିବା ସମୟରେ POST scopes:["manage"] ବ୍ୟବହାର କରନ୍ତୁ।

# ତା’ପରେ ଏକ ରିମୋଟ୍ MCP କ୍ଲାଏଣ୍ଟରୁ ସଂଯୋଗ କରନ୍ତୁ:
curl -i \
  -H "Host: your-public-host.example" \
  -H "Authorization: Bearer sk-…" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"my-client","version":"0"}}}' \
  https://your-public-host.example/api/mcp/stream
```

`manage` ନଥିବା କୀ (କିମ୍ବା Bearer ନଥିଲେ) `403 LOCAL_ONLY` ଫେରାଏ। ସହୋଦର ପ୍ରିଫିକ୍ସ `/api/cli-tools/runtime/*`କୁ ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ ବାଇପାସ୍ କରାଯାଇପାରିବ ନାହିଁ — [ରୁଟ୍ ଗାର୍ଡ ସ୍ତରଗୁଡ଼ିକ — Manage-scope ବ୍ୟତିକ୍ରମ](../security/ROUTE_GUARD_TIERS.md#manage-scope-carve-out) ଦେଖନ୍ତୁ।

### Origin ଯାଞ୍ଚ

ପ୍ରମାଣୀକରଣ ପରେ `/api/mcp/*` କୁ ଯାଉଥିବା ପ୍ରତ୍ୟେକ ଅନୁରୋଧର — ଟ୍ରାନ୍ସପୋର୍ଟ ଏବଂ `status`, `tools`, `audit`, `restart` ପରି ପରିଚାଳନା ରୁଟ — `Origin` ହେଡର ଯାଞ୍ଚ କରାଯାଏ, କଲର ଯିଏ ବି ହୁଅନ୍ତୁ (API କି, CLI ଟୋକେନ, ଡ୍ୟାସବୋର୍ଡ ସେସନ, କିମ୍ବା ଲଗଇନ ବନ୍ଦ ଥିବାବେଳେ ଅଜ୍ଞାତ loopback)। ଏହା MCP Streamable HTTP ନିର୍ଦ୍ଦିଷ୍ଟକରଣ ଆବଶ୍ୟକ କରୁଥିବା DNS rebinding ସୁରକ୍ଷା।

- **`Origin` ହେଡର ନାହିଁ** → ଅନୁମତି ଅଛି। OmniRoute CLI, SDK ଏବଂ IDE କ୍ଲାଏଣ୍ଟ ଏହାକୁ ପଠାନ୍ତି ନାହିଁ।
- **ଅନୁମୋଦିତ `Origin`** → ଯେକୌଣସି ପୋର୍ଟରେ `localhost` / `127.0.0.1` / `[::1]`, କିମ୍ବା OmniRoute ର ନିଜସ୍ୱ ସାର୍ବଜନୀନ origin: `OMNIROUTE_PUBLIC_BASE_URL` / `NEXT_PUBLIC_BASE_URL` / `NEXT_PUBLIC_APP_URL`, ବିଶ୍ୱସ୍ତ ରିଭର୍ସ ପ୍ରକ୍ସି ଦ୍ୱାରା ଫରୱାର୍ଡ ହୋଇଥିବା origin (`OMNIROUTE_TRUST_PROXY`, କେବଳ base URL ସେଟ ହୋଇନଥିଲେ), କିମ୍ବା ସିଧାସଳଖ ପ୍ରବେଶ କରାଯାଇଥିବା loopback/LAN IP ହୋଷ୍ଟ। କେବଳ `Host` ହେଡର କେବେ ବି କୌଣସି origin କୁ ବିଶ୍ୱସ୍ତ କରେ ନାହିଁ।
- **`null` ସମେତ ଅନ୍ୟ କୌଣସି `Origin`** → JSON-RPC ତ୍ରୁଟି ବଡି ସହିତ `403`: `id: null`, `error.code: -32000`, `error.data.code: "INVALID_ORIGIN"`। ବୈଧ CSRF ଟୋକେନ ଦେଖାଉଥିବା ଡ୍ୟାସବୋର୍ଡ ସେସନ, ଅନ୍ୟ ଡ୍ୟାସବୋର୍ଡ ଲେଖା ପରି, ଏବେ ବି ଗ୍ରହଣ କରାଯାଏ।

ରିଭର୍ସ ପ୍ରକ୍ସି ପଛରେ ପରିବେଷିତ ବ୍ରାଉଜର MCP କ୍ଲାଏଣ୍ଟ ପାଇଁ `OMNIROUTE_PUBLIC_BASE_URL` ଆବଶ୍ୟକ; ଅନ୍ୟ origins ପାଇଁ କୌଣସି ଅନୁମତି-ତାଲିକା ନାହିଁ। CORS ପ୍ରିଫ୍ଲାଇଟ (`OPTIONS`) ର Origin ଯାଞ୍ଚ ହୁଏ ନାହିଁ; ତା ପରବର୍ତ୍ତୀ ଅନୁରୋଧର ହୁଏ।

CCR ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ କେବଳ ଇନ୍-ମେମୋରିରେ ରହେ ଏବଂ ପୁନଃଚାଳନ ପରେ ଅଦୃଶ୍ୟ ହୋଇଯାଏ। ପ୍ରତ୍ୟେକ ବ୍ଲକ୍ 2 MiB, ପ୍ରତ୍ୟେକ
ପ୍ରିନ୍ସିପାଲ୍ 16 MiB ଏବଂ ଗ୍ଲୋବାଲ୍ ଷ୍ଟୋର୍ 64 MiB ପର୍ଯ୍ୟନ୍ତ ସୀମିତ। ଏଣ୍ଟ୍ରିଗୁଡ଼ିକର ଡିଫଲ୍ଟ TTL 24 ଘଣ୍ଟା (ସର୍ବାଧିକ
ସାତ ଦିନ)। ସମ୍ପୂର୍ଣ୍ଣ MCP ପୁନରୁଦ୍ଧାର 256 KiB ପର୍ଯ୍ୟନ୍ତ ସୀମିତ; ବଡ଼ ବ୍ଲକ୍ଗୁଡ଼ିକ ରେଞ୍ଜ୍ଡ୍ ଏବଂ
grep ମୋଡ୍ ମାଧ୍ୟମରେ ଉପଲବ୍ଧ ରହେ। ସଂରକ୍ଷଣ, ପୁନରୁଦ୍ଧାର, ତାଲିକାକରଣ, ନିରୀକ୍ଷଣ, ବିଲୋପ ଏବଂ ପରିସଂଖ୍ୟାନ
ପ୍ରମାଣୀକୃତ API-key ପ୍ରିନ୍ସିପାଲ୍ ଅନୁଯାୟୀ ପୃଥକ ରଖାଯାଏ। ଅଡିଟ୍ ରେକର୍ଡ୍ଗୁଡ଼ିକରେ ହ୍ୟାସ୍ ଏବଂ ଆକାର ମେଟାଡାଟା ରହେ, ବିଷୟବସ୍ତୁ କେବେ ମଧ୍ୟ ନୁହେଁ।

`omniroute_compression_status`, `analytics.mcpDescriptionCompression` ଅଧୀନରେ MCP ବର୍ଣ୍ଣନା ସଙ୍କୋଚନକୁ ପୃଥକ ଭାବରେ ରିପୋର୍ଟ କରେ।
ସେହି ମୂଲ୍ୟଗୁଡ଼ିକ MCP ତାଲିକାଭୁକ୍ତ-ଯୋଗ୍ୟ ବର୍ଣ୍ଣନାଗୁଡ଼ିକ (`tools`, `prompts`, `resources`, ଏବଂ `resourceTemplates`) ପାଇଁ ମେଟାଡାଟା-ଆକାରର ଆକଳନ; ସେଗୁଡ଼ିକ ପ୍ରଦାନକାରୀଙ୍କ ବ୍ୟବହାର ରସିଦ ନୁହେଁ ଏବଂ `source: "mcp_metadata_estimate"` ସହିତ ଚିହ୍ନିତ ହୋଇଛି।

### MCP ଆକ୍ସେସିବିଲିଟି ଟ୍ରି ଫିଲ୍ଟର୍ (v3.8.0)

ଉପରୋକ୍ତ ସଙ୍କୋଚନ ଟୁଲ୍ଗୁଡ଼ିକଠାରୁ ପୃଥକ ଭାବରେ, OmniRoute ଏକ ନିଷ୍ପାଦନ-ପରବର୍ତ୍ତୀ ଫିଲ୍ଟର୍ ଅନ୍ତର୍ଭୁକ୍ତ କରେ, ଯାହା MCP ବ୍ରାଉଜର୍/ଆକ୍ସେସିବିଲିଟି ଟୁଲ୍ଗୁଡ଼ିକର **ଟୁଲ୍ ଫଳାଫଳଗୁଡ଼ିକୁ** ଏଜେଣ୍ଟଙ୍କୁ ଫେରାଇବା ପୂର୍ବରୁ ସଙ୍କୋଚନ କରେ। ଏହି ଫିଲ୍ଟର୍ ନିଜେ ଏକ ଟୁଲ୍ ନୁହେଁ — ବିସ୍ତୃତ ଆକ୍ସେସିବିଲିଟି-ଟ୍ରି କିମ୍ବା ବ୍ରାଉଜର୍-ସ୍ନାପ୍ଶଟ୍ ପାଠ୍ୟ (≥2000 ଅକ୍ଷର) ଧାରଣ କରୁଥିବା ଯେକୌଣସି ଟୁଲ୍ ଫଳାଫଳ ଉପରେ ଏହା ସ୍ୱଚ୍ଛ ଭାବରେ ଚାଲେ।

ମୁଖ୍ୟ ଆଚରଣଗୁଡ଼ିକ:

- କ୍ରମାଗତ ଭାବରେ ପୁନରାବୃତ୍ତ ହେଉଥିବା ≥30ଟି ସମସ୍ତରୀୟ ଲାଇନ୍କୁ ଆରମ୍ଭ + ଶେଷ ସାରାଂଶରେ ସଙ୍କୁଚିତ କରେ
- Playwright/କମ୍ପ୍ୟୁଟର୍-ବ୍ୟବହାର ପାଇଁ ଆବଶ୍ୟକ `[ref=eXX]` ଆଙ୍କର୍ଗୁଡ଼ିକୁ ସଂରକ୍ଷିତ ରଖେ
- ଅତ୍ୟଧିକ ବଡ଼ ପାଠ୍ୟକୁ (>50,000 ଅକ୍ଷର) ଏକ ନେଭିଗେସନ୍ ସଙ୍କେତ ସହିତ କଠୋର ଭାବରେ ଛୋଟ କରେ
- ପ୍ରତ୍ୟାଶିତ ସଞ୍ଚୟ: ବ୍ରାଉଜର୍ ସ୍ନାପ୍ଶଟ୍ ପେଲୋଡ୍ଗୁଡ଼ିକରେ **60–80%**

ବିନ୍ୟାସ: ଗ୍ଲୋବାଲ୍ ସେଟିଂସ୍ରେ `compression.mcpAccessibility` (ମାଇଗ୍ରେସନ୍ 056)।
କାର୍ଯ୍ୟାନ୍ୱୟନ: `open-sse/services/compression/engines/mcpAccessibility/`।
ସମ୍ପୂର୍ଣ୍ଣ ଡକ୍ୟୁମେଣ୍ଟେସନ୍: [ସଙ୍କୋଚନ ଇଞ୍ଜିନ୍ଗୁଡ଼ିକ — MCP ଆକ୍ସେସିବିଲିଟି ଟ୍ରି ଫିଲ୍ଟର୍](../compression/COMPRESSION_ENGINES.md#mcp-accessibility-tree-filter)।

## ସମ୍ବନ୍ଧିତ ଫ୍ରେମ୍ୱର୍କଗୁଡ଼ିକ (v3.8.0)

ଉପରୋକ୍ତ MCP ଟୁଲ୍ ଇନ୍ଭେଣ୍ଟରି (110ଟି ଅନନ୍ୟ ଟୁଲ୍, `countUniqueMcpTools()` ଦ୍ୱାରା ଗଣନା କରାଯାଇଛି) ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ
ରନ୍ଟାଇମ୍ ରାଉଟିଂ/କ୍ୟାଶ୍/କମ୍ପ୍ରେସନ୍/ମେମୋରି/ସ୍କିଲ୍/ପ୍ରକ୍ସି/କଣ୍ଟେକ୍ସ୍ଟ-ସୋର୍ସ ଅପରେସନ୍ଗୁଡ଼ିକ ମଧ୍ୟରେ ସୀମିତ। v3.8.0-ରେ MCP ସର୍ଭର୍ ସହିତ ଦୁଇଟି ସମୀପବର୍ତ୍ତୀ
ଫ୍ରେମ୍ୱର୍କ ମଧ୍ୟ ପ୍ରଦାନ କରାଯାଏ ଏବଂ ସେଗୁଡ଼ିକୁ ପୃଥକ ଭାବେ ଡକ୍ୟୁମେଣ୍ଟ କରାଯାଇଛି:

### Cloud Agents

Cloud Agents ହେଉଛନ୍ତି ଆଉଟ୍-ଅଫ୍-ପ୍ରୋସେସ୍ AI କୋଡିଂ ଏଜେଣ୍ଟ (codex-cloud, cursor-cloud, devin, jules), ଯେଉଁମାନେ LLM ପ୍ରଦାତାମାନଙ୍କ ପାଇଁ ବ୍ୟବହୃତ ସମାନ ସଂଯୋଗ ମଡେଲ୍ ମାଧ୍ୟମରେ
OmniRoute ସହିତ ସଂଯୁକ୍ତ। ସେମାନଙ୍କୁ ସେମାନଙ୍କର ନିଜସ୍ୱ REST ସର୍ଫେସ୍ (`/api/v1/agents/*`) ମାଧ୍ୟମରେ ଉପଲବ୍ଧ କରାଯାଏ ଏବଂ ସେମାନେ MCP ଟୁଲ୍ କ୍ୟାଟାଲଗ୍ର ଅଂଶ **ନୁହଁନ୍ତି**
— ଏକ Cloud Agent-କୁ କଲ୍ କରିବା ଦ୍ୱାରା କୌଣସି MCP ସ୍କୋପ୍ ବ୍ୟବହୃତ ହୁଏ ନାହିଁ।

- କାର୍ଯ୍ୟାନ୍ୱୟନ: `src/lib/cloudAgent/` (`registry.ts`, `agents/codex.ts`, `agents/cursor.ts`, `agents/devin.ts`, `agents/jules.ts`)।
- ଲାଇଫ୍ସାଇକେଲ୍: `createTask`, `getStatus`, `approvePlan`, `sendMessage`, `listSources`।
- ଡକ୍ୟୁମେଣ୍ଟେସନ୍: [docs/frameworks/CLOUD_AGENT.md](./CLOUD_AGENT.md)।

### Guardrails

Guardrails ହେଉଛି ପୂର୍ବ/ପରବର୍ତ୍ତୀ-ନିଷ୍ପାଦନ ଫିଲ୍ଟର୍ (vision-bridge, pii-masker, prompt-injection),
ଯାହା ଚାଟ୍ ପାଇପ୍ଲାଇନ୍ ଭିତରେ ପ୍ରୟୋଗ କରାଯାଏ। MCP ଟୁଲ୍/ରୁଟ୍ ସ୍ତରରେ ପହଞ୍ଚିବା ପୂର୍ବରୁ ସେଗୁଡ଼ିକ ଚାଲେ
ଏବଂ ଅଡିଟ୍ ପାଇପ୍ଲାଇନ୍କୁ ସଂରଚିତ ଉଲ୍ଲଂଘନ ସୂଚନା ପଠାଏ; ସେଗୁଡ଼ିକୁ MCP ଟୁଲ୍ ଭାବେ ଆହ୍ୱାନ କରାଯାଏ ନାହିଁ।

- କାର୍ଯ୍ୟାନ୍ୱୟନ: `src/lib/guardrails/`।
- ଡକ୍ୟୁମେଣ୍ଟେସନ୍: [docs/security/GUARDRAILS.md](../security/GUARDRAILS.md)।

ଅବରୋଧ କରାଯାଇଥିବା ପରି ଦେଖାଯାଉଥିବା ଏକ MCP କଲ୍କୁ ଡିବଗ୍ କରିବା ସମୟରେ, MCP ଅଡିଟ୍ ଲଗ୍
(`scope_denied:*` ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ) ଏବଂ guardrails ଅଡିଟ୍ ଟ୍ରେଲ୍—ଉଭୟ ଯାଞ୍ଚ କରନ୍ତୁ—କୌଣସି ଅନୁରୋଧ MCP ସ୍କୋପ୍ ଏନ୍ଫୋର୍ସମେଣ୍ଟ ସ୍ତରରେ ପହଞ୍ଚିବା **ପୂର୍ବରୁ**
ଏକ guardrail ଦ୍ୱାରା ପ୍ରତ୍ୟାଖ୍ୟାନ ହୋଇପାରେ।

## ପ୍ରାମାଣୀକରଣ ଓ ସ୍କୋପ୍‌ସ

MCP ଟୁଲ କଲ କର୍ତ୍ତାରେ ଥିବା ସ୍କୋପ୍ ଷ୍ଟ୍ରିଙ୍ଗ ପଢ଼େ। ଏହି ଚେକଟି ତିନୋଟି ସ୍ୱତନ୍ତ୍ର ନେମସ୍ପେସ ମଧ୍ୟର ଏକଟି। ଗୋଟିଏ ଚେକର୍ ପାସ ହେବା ଅନ୍ୟଥିଗୁଡ଼ିକ ଚେକର୍‌ଗୁଡ଼ିକ ପାସ ହେବା ସମାନ ନୁହେଁ। ନିୟମଗୁଡ଼ିକ [ତିନୋଟି ସ୍କୋପ୍ ନେମସ୍ପେସ](#three-scope-namespaces) ରେ ଦେଇଛାନ୍ତି। ଟୁଲ କାଟଲଗ ହେଉଛି [MCP ଟୁଲ ସ୍କୋପ୍‌ସ](#mcp-tool-scopes)।

#### API-key ସ୍କୋପ୍‌ସ

ଗୋଟିଏ `api_keys.scopes` ଅରେ ଦୁଇଟି କାମ ଆସିଠାଏ। ସେଗୁଡ଼ିକ ଭିନ୍ନ ଫଙ୍କସନ ବ୍ୟବହାର କରେ।

**ମ୍ୟାନେଜମେଣ୍ଟ REST.** `manage` ଓ `admin` ହେଉଛନ୍ତି `MANAGEMENT_API_KEY_SCOPES` ର ସଦସ୍ୟ (`src/shared/constants/managementScopes.ts`)। `hasManageScope` ହେଉଛି ସେଇ key ପାଇଁ ମ୍ୟାନେଜମେଣ୍ଟ ରାଉଟଗୁଡ଼ିକ ଅନୁମତି ଦେଇଥିବା କଣ। ସେଗୁଡ଼ିକ ରାଉଟରେ `admin` ମ୍ୟାନେଜମେଣ୍ଟ-ସମର୍ଥନ କରିପାରେ। ଏଠାରେ `admin` ଶବ୍ଦଟି ଆକ୍ସେସ-ଟ୍କେନ ର୍ୟାଙ୍କ ନୁହେଁ ଏବଂ ଏହା MCP ଟୁଲ ସ୍କୋପ୍‌ସରେ ବିସ୍ତାର ହୁଏ ନାହିଁ।

**ଯୋଗାତମକ ଷ୍ଟ୍ରିଙ୍ଗ.** ପ୍ରତ୍ୟେକଟି ଏକ ନିର୍ଦିଷ୍ଟ ସଦସ୍ୟପତ୍ର ପରୀକ୍ଷା, ଏବଂ ପ୍ରତ୍ୟେକଟି `MANAGEMENT_API_KEY_SCOPES` ର ବାହାରେ ରହେ।

#### ମେଚିଙ୍ଗ

କାଟଲଗ ହେଉଛି [MCP ଟୁଲ ସ୍କୋପ୍‌ସ](#mcp-tool-scopes) ଅଧୀନର ଟେବଲ। `src/shared/constants/mcpScopes.ts` ର `MCP_SCOPE_LIST` କୁ ସେହି କାଟଲଗ ଭାବେ ମନ କରନ୍ତୁ ନାହିଁ: ଏହା ମୂଳ typed subset। ପରବର୍ତ୍ତୀ ଟୁଲଗୁଡ଼ିକ ଏହିର ପାଖରେ ଅନ୍ୟ ସ୍କୋପ୍ ଘୋଷଣା କରେ (`read:notion`, `read:skills`, `read:local-corpus`, ଏବଂ ଟେବଲର ବାକୀ ଅଂଶ)।

`open-sse/mcp-server/scopeEnforcement.ts` ର `evaluateToolScopes` ସମସ୍ତେ ଆବଶ୍ୟକ ସ୍କୋପ୍ କୌଣସି ପ୍ରଦତ୍ତ ସ୍କୋପ୍ ସହିତ ମେଳ ଖାଇଲେ କଲ ଅନୁମତି ଦେଇଥାଏ:

- `*` ସମସ୍ତେ ଆବଶ୍ୟକ ସ୍କୋପ୍ ସହିତ ମେଳ ଖାଏ।
- `*` ରେ ଶେଷ ହେଇଥିବା ପ୍ରଦତ୍ତ ସ୍କୋପ୍, ସ୍ଟାର ପୂର୍ବର ପ୍ରେଫିକ୍ସ ଦିଅନ୍ତା ଆରମ୍ଭ ହେଇଥିବା ଆବଶ୍ୟକ ସ୍କୋପ୍ ସହିତ ମେଳ ଖାଏ। `read:*` ହେଉଛି `read:compression` ସହିତ ମେଳ ଖାଏ।
- ଅନ୍ୟ ପ୍ରତ୍ୟେକ ପ୍ରଦତ୍ତ ସ୍କୋପ୍ କେବଳ ସମାନ ଆବଶ୍ୟକ ଷ୍ଟ୍ରିଙ୍ଗ ସହିତ ମେଳ ଖାଏ।

`["manage"]` ଥିବା scopes ଯଣ୍ଡ key ପାଇଁ `read:compression` କ୍ଷେତ୍ରେ `scopeMatches` ବିଫଳ ହୁଏ। ସେହି କଲ ଏହିଗୁଡ଼ିକ ମାତ୍ର ପ୍ରଦତ୍ତ ଷ୍ଟ୍ରିଙ୍ଗ ହେଇଥିବା ସମୟରେ `admin`, `mcp:connect`, `read`, ଏବଂ `write` ପାଇଁଓ ବିଫଳ ହୁଏ। ଅନ୍ତିମ `*` ବାହାରେ MCP ଟୁଲ ସ୍କୋପ୍‌ସ ମଧ୍ୟରେ କୌଣସି ପାଇରାର୍କି ନାହିଁ।

`OMNIROUTE_MCP_ENFORCE_SCOPES=true` ନୁହେଁ (ଡିଫଲ୍ଟ `false`) ଏନଫୋର୍ସମେଣ୍ଟ ବନ୍ଦ ରହେ। ଏହା ବନ୍ଦ ଥିବା ବେଳେ `evaluateToolScopes` କଲ ଅନୁମତି ଦେଇ କାଟଲଗ ବିପସ କରେ। ଏହା ଚାଲୁ ଥିବା ବେଳେ HTTP, Bearer key ର `api_keys.scopes` କୁ `authInfo` ଭାବେ ବ୍ୟବହାର କରେ ([Per-key HTTP scope binding](#per-key-http-scope-binding-7895) ଦେଖନ୍ତୁ)। କୌଣସି key scope ନିଷ୍ପତ୍ତି ନହେଁ ଥିବା ବେଳେ ପ୍ରଦତ୍ତ ସେଟ, MCP `_meta` କୁ (କେବଳ HTTP/SSE କର୍ତ୍ତାର୍ଥୀ HTTP auth context ରେ ସମ୍ମାନ ହୁଏ; stdio କର୍ତ୍ତାର୍ଥୀ `_meta` ଅନ୍ତର୍ଭୁକ୍ତ ହୁଏ କାରଣ କ୍ଲାଏଣ୍ଟ ଏହା ନିୟନ୍ତ୍ରଣ କରେ ଏବଂ ଏହା କର୍ତ୍ତାପରିଛି ପରିଚୟ ଆଇଡେଣ୍ଟିଟି ଅନ୍ତର୍ଭୁକ୍ତ କରେ), ତାପରେ `OMNIROUTE_MCP_SCOPES` କୁ ଯାଏ।

#### ଆକ୍ସେସ-ଟ୍କେନ ସ୍କୋପ୍‌ସ

`oma_live_…` ଟୋକେନ (`src/lib/accessTokens/scopes.ts`) `read`, `write`, କିମ୍ବା `admin` ବହନ କରେ। `scopeSatisfies` ଏକ ର୍ୟାଙ୍କ: `admin` ହେଉଛି `write` ଓ `read` ଦୁଇଟିକୁ ଆବରଣ କରେ, ଏବଂ `write` ହେଉଛି `read` କୁ ଆବରଣ କରେ। ଅଜଣା ସ୍କୋପ୍ କିଛିମ୍ ଅବରଣ କରେ ନାହିଁ।

`evaluateAccessTokenAuth` (`src/server/authz/accessTokenAuth.ts`) ସେହି ର୍ୟାଙ୍କକୁ `inferRequiredScope` (`src/server/authz/accessScopes.ts`) ସହିତ ତୁଳନା କରେ:

- `GET`, `HEAD`, ଏବଂ `OPTIONS` ପାଇଁ `read` ଆବଶ୍ୟକ।
- ଅନ୍ୟ ସବୁ ମେଥଡ ପାଇଁ `write` ଆବଶ୍ୟକ।
- `ADMIN_SCOPE_PREFIXES` ମଧ୍ୟର ଥିବା ପାଥଗୁଡ଼ିକ ପ୍ରତ୍ୟେକ method ପାଇଁ `admin` ଆବଶ୍ୟକ। `/api/mcp`
  ସେଇ ତାଲିକାରେ ଅଛି, ତେଣୁ ଏକଟି `write` access token ବାକୀ ଭଲେ MCP HTTP
  surface କୁହି ପକାରି ପାରିବ ନାହିଁ।
- `ADMIN_MUTATION_PREFIXES` ମଧ୍ୟର ଥିବା ପାଥଗୁଡ଼ିକ କେବଳ mutation ପାଇଁ `admin` ଆବଶ୍ୟକ।
- `ADMIN_MUTATION_EXACT_PATHS` (`/api/settings`,
  `/api/settings/require-login`) ମଧ୍ୟର ଥିବା ପାଥଗୁଡ଼ିକ କେବଳ mutation ପାଇଁ ଏବଂ କେବଳ ସେଇ ନିର୍ଦ୍ଦିଷ୍ଟ ପାଥରେ `admin` ଆବଶ୍ୟକ — ଅନ୍ୟ `/api/settings/*` sub-route ଗୁଡ଼ିକ `write` ରଖେ।

`PATCH /api/keys/{id}` ଏକଟି mutation ଏବଂ ସେଇ admin ତାଲିକାରେ ନାହିଁ, ତେଣୁ ଏକଟି
`read` token ପୁରେ 403 ପ୍ରାପ୍ତ କରେ
`Access token scope 'read' is insufficient; 'write' required.`
ଏକଟି `write` କିମ୍ବା `admin` access token ସେଇ route କୁହି ସନ୍ତୁଷ୍ଟ କରେ। ଏକଟି dashboard JWT, loopback
CLI machine-id token, ଏବଂ `manage` କିମ୍ବା `admin` ଥିବା API key ଅନ୍ୟ branch ନିଅନ୍ତି ଏବଂ ଏହି rank
ଦ୍ୱାରା ସମାହିତ ହୁଏନାହିଁ।

`/api/mcp` ପାଇଁ `scopeSatisfies` କୁହି ପାସ ହେବା access token କେବଳ management gate ଅତିକ୍ରମ
କରିଛି। Tool call ଗୁଡ଼ିକ ଏପରି ଆପଣ API-key scope ବିପରୀତ `scopeMatches` ଚଲାଇଥାନ୍ତି। Access-token rank ଏ
`scopeMatches` ର ଏକଟି input ନୁହେଁ।

### `mcp:connect` — narrow route capability (#7895)

non-loopback ଥିରୁ HTTP/SSE MCP transport (`/api/mcp/*`) କୁ ପହଞ୍ଚାଇବା ପାଇଁ `/api/mcp/` LOCAL_ONLY carve-out ଆବଶ୍ୟକ (`docs/security/ROUTE_GUARD_TIERS.md` ଦେଖନ୍ତୁ)। ପୂର୍ବରୁ ଏହି carve-out କେବଳ full `manage`/`admin`-scope API key ଗ୍ରହଣ କରୁଥିଲ — ଯେ caller କେବଳ MCP ସହିତ କଥାବାରୁ ଚାହେ, ସେହି ପାଇଁ ଅତ୍ୟଧିକ ବିସ୍ତୃତ। `src/shared/constants/managementScopes.ts` ଏପରିଁ ଏପରିଁ `MCP_CONNECT_SCOPE = "mcp:connect"` export କରୁଛି: ଏହି ହେଉଛି additive, narrow scope (`SELF_USAGE_SCOPE` ପରି ଏକାନ୍ତ precedent) ଯାହା କେବଳ `src/server/authz/policies/management.ts` ରେ `/api/mcp/` bypass କୁ ଅଧିକାର ଦେଇଦେ — ଏହା ଅନ୍ୟ management-route access କୌଣସି ଅନୁମତି ଦେଇନଥାଏ ଏବଂ ଇଚ୍ଛାସୂତଭାବେ `MANAGEMENT_API_KEY_SCOPES` ରେ ବାହାର ରଖାଯାଇଛି। `manage`/`admin` ଧାରଣ କରୁଥିବା key ଆଉ ଅପରିବର୍ତ୍ତନ carve-out ଅପରିବର୍ତ୍ତନଭାବେ ପାସ ହୁଏ; `mcp:connect` ହେଉଛି remote MCP-only caller ପାଇଁ ନିମ୍ନ-ପ୍ରାଧିକାର (lower-privilege) ବିକଳ୍ପ, ଯାହା `hasMcpConnectOrManageScope()` ଦ୍ୱାରା check ହୁଏ।

### Per-key HTTP scope binding (#7895)

HTTP/SSE ରେ, `open-sse/mcp-server/httpTransport.ts` ଏପରିଁ caller's real `api_keys.scopes` କୁ `resolveMcpCallerAuthInfo()` (`open-sse/mcp-server/httpAuthContext.ts`) ଦ୍ୱାରା resolve କରେ ଏବଂ ତାହା MCP SDK's `transport.handleRequest(req, { authInfo })` କୁ pass କରେ, ଫଲସ୍ୱାରେ ପ୍ରତ୍ୟେକ tool call ଯେଉଁଥିବା `extra.authInfo.scopes` ସେହି ମୂଲ Bearer key ର own scopes କୁ ପ୍ରତିଭିମିତ କରେ। `scopeEnforcement.ts` ର `resolveCallerScopeContext()` ଇତିମଧ୍ୟରେ `_meta` ଏବଂ `OMNIROUTE_MCP_SCOPES` env fallback କୁ ଛାଡ଼ି `authInfo` କୁ ଅଗ୍ରାଧିକାର ଦେଇଥିଲ — ଏହା କେବଳ ସେହି ପ୍ରଥମ, ସର୍ବୋଚ୍ଚ ପ୍ରାଧିକାର ଥିବା source କୁ ପୂରଣ କରେ, ଯାହା HTTP ରେ ପୂର୍ବରୁ ଖାଲୀ ରହିଥିଲ। ଯେଉଁଥିବା କୌଣସି API key resolve ହୁଏନାହିଁ (header ନାହିଁ, key ଅବୈଧ), ସେହି ସମ୍ପର୍କେ `authInfo` `undefined` ରହେ ଏବଂ resolution ଅପରିବର୍ତ୍ତନ ହୋଇଥିବା `meta`/env chain ଦିଗରେ ପଡ଼େ। stdio ରେ per-caller identity ନାହିଁ (`mcpCallerIdentity.ts` ଦେଖନ୍ତୁ) ଏବଂ ଏହା per-key binding ଦ୍ୱାରା ପ୍ରଭାବିତ ହୁଏନାହିଁ — ଏହା `_meta` ପଦକ୍ଷେପ ଏଡ଼ାଇଦେ (`_meta` କେବଳ HTTP auth context ଭିତରେ ସମମାନ ହୁଏ, #15159) ଏବଂ କେବଳ `OMNIROUTE_MCP_SCOPES` env key ରୁ resolve କରେ।

**narrow-scoped HTTP/SSE caller ଙ୍କ ପାଇଁ `OMNIROUTE_MCP_ENFORCE_SCOPES` ଉପରେ ବିଜ୍ଞାନମାନ ଥିବା ବାଇର enforcement ଜାରୀ ହୁଏ।** `OMNIROUTE_MCP_ENFORCE_SCOPES` ର default `false` ହେବା କେବଳ local/stdio single-operator flow ପାଇଁ ସୁରକ୍ଷିତ, ଯେଉଁଥିବା ସେଠାରେ scope କରିବା ପାଇଁ କୌଣସି per-caller identity ନାହିଁ। `open-sse/mcp-server/server.ts::withScopeEnforcement()` per-tool scope enforcement କୁ ଅବିସରତ ଭାବେ on କରେ (`scopeEnforcement.ts` ର `shouldForceScopeEnforcement()`) ଯେଉଁଥିବା `resolveCallerScopeContext()` `source === "authInfo"` resolve କରିଛି (ଅର୍ଥାଁ, ପ୍ରକୃତ HTTP Authorization header, HTTP/SSE-only) ଏବଂ ସେହି key ରେ full `manage`/`admin` scope ନାହିଁ। ଏହା ଏହି ଫାଦ କାଢ଼େ, ଯେଉଁଥିବା କେବଳ narrow `mcp:connect` bypass scope ଧାରଣ କରୁଥିବା key — ଉପରେ ଦସ୍ତାବିକଭାବେ `/api/mcp/` LOCAL_ONLY carve-out ଛାଡ଼ି ଅନ୍ୟଥିବା କିଛି ନାହିଁ ବୋଲି ଦସ୍ତାବିକଭାବେ ଲେଖାଯାଇଛି — ଅନ୍ୟଥିବା ପାଇଁ operator ଯେତେବେଳେ remote/non-loopback MCP access ଚାଲୁ କଲେ, କେବଳ କାରଣ `OMNIROUTE_MCP_ENFORCE_SCOPES` default ଭାବେ `false` ଥିବା ସେ ସମସ୍ତ MCP tool invoke କରିପାରନ୍ତା। HTTP ରେ full `manage`/`admin` key ଏବଂ ସମସ୍ତ stdio/local caller ଗୁଡ଼ିକ ବର୍ତ୍ତମାନ `OMNIROUTE_MCP_ENFORCE_SCOPES`-gated behavior ଅପରିବର୍ତ୍ତନ ରଖେ।

## ବର୍ଣ୍ଣନା ସଙ୍କୋଚନ

କ୍ଲାଏଣ୍ଟମାନଙ୍କୁ ପ୍ରକାଶିତ ମେଟାଡାଟାର ପରିମାଣ (ଏବଂ ତେଣୁ ପ୍ରମ୍ପ୍ଟ ପ୍ରସଙ୍ଗ ଖର୍ଚ୍ଚ) ହ୍ରାସ କରିବା ପାଇଁ MCP ଟୁଲ୍, ପ୍ରମ୍ପ୍ଟ ଏବଂ ରିସୋର୍ସ ରେଜିଷ୍ଟ୍ରିଗୁଡ଼ିକ ପଞ୍ଜୀକରଣ/ତାଲିକାକରଣ ସମୟରେ ବର୍ଣ୍ଣନାଗୁଡ଼ିକୁ ସଙ୍କୋଚିତ କରିପାରନ୍ତି। କାର୍ଯ୍ୟାନ୍ୱୟନଟି `open-sse/mcp-server/descriptionCompressor.ts`ରେ ରହିଛି ଏବଂ `createMcpServer()` ଭିତରେ `compressMcpRegistryMetadata` ମାଧ୍ୟମରେ MCP ସର୍ଭର ସହିତ ସଂଯୋଜିତ ହୋଇଛି।

- ସଙ୍କୋଚନଟି ସଂରକ୍ଷିତ-ବ୍ଲକ୍ ନିଷ୍କାସନ (କୋଡ୍ ସ୍ପାନ୍, ଫେନ୍ସ୍ଡ୍ ବ୍ଲକ୍ ଇତ୍ୟାଦି) ସହିତ Caveman ନିୟମାବଳୀ (`getRulesForContext("all", "full")`) ବ୍ୟବହାର କରି ବର୍ଣ୍ଣନା ପାଠ୍ୟ ଉପରେ ଚାଲେ, ଯାହାଦ୍ୱାରା ଗଠନାତ୍ମକ ବିଷୟବସ୍ତୁ ପରିବର୍ତ୍ତିତ ହୁଏ ନାହିଁ।
- `key_value` ସେଟିଂସ୍ ଟେବୁଲ୍ରେ ଥିବା `compression.mcpDescriptionCompressionEnabled` ମୂଲ୍ୟ ମାଧ୍ୟମରେ ପ୍ରତ୍ୟେକ ଡିପ୍ଲୟମେଣ୍ଟ ପାଇଁ ଟଗଲ୍ କରନ୍ତୁ (ଡିଫଲ୍ଟ: ସକ୍ଷମ) — UIରେ **ବିଶ୍ଳେଷଣ → MCP ବର୍ଣ୍ଣନା ସଙ୍କୋଚନ** ଭାବରେ ଉପଲବ୍ଧ।
- `OMNIROUTE_MCP_COMPRESS_DESCRIPTIONS=false` କିମ୍ବା `OMNIROUTE_MCP_DESCRIPTION_COMPRESSION=false` ମଧ୍ୟରୁ ଯେକୌଣସି ଗୋଟିଏ ମାଧ୍ୟମରେ ସମଗ୍ର ପ୍ରକ୍ରିୟା ପାଇଁ ଟଗଲ୍ କରନ୍ତୁ।
- ବାସ୍ତବ-ସମୟ ପରିସଂଖ୍ୟାନଗୁଡ଼ିକ `analytics.mcpDescriptionCompression` ଅଧୀନରେ `omniroute_compression_status` ମାଧ୍ୟମରେ ପ୍ରଦର୍ଶିତ ହୁଏ ଏବଂ ପ୍ରକୃତ ପ୍ରଦାନକାରୀ ବ୍ୟବହାର ରସିଦରୁ ପୃଥକ କରିବା ପାଇଁ `source: "mcp_metadata_estimate"` ଟ୍ୟାଗ୍ ଯୋଡ଼ାଯାଏ।

## ଟୁଲ୍ କାର୍ଡିନାଲିଟି ହ୍ରାସ (F4.3)

ବର୍ଣ୍ଣନା ସଂକୋଚନ ପ୍ରତ୍ୟେକ ଟୁଲ୍ର ମେଟାଡାଟାକୁ ସଙ୍କୁଚିତ କରେ; **ଟୁଲ୍-କାର୍ଡିନାଲିଟି ହ୍ରାସ** ଘୋଷଣା କରାଯାଉଥିବା ଟୁଲ୍ର _ସଂଖ୍ୟା_ ହ୍ରାସ କରି ଏହାକୁ ଆଉ ଗୋଟିଏ ପାଦ ଆଗକୁ ନେଇଯାଏ। `tools/list` ମ୍ୟାନିଫେଷ୍ଟରେ କମ୍ ଟୁଲ୍ର ବିଜ୍ଞାପନ କରିବା ଫଳରେ ଟୁଲ୍ କ୍ୟାଟାଲଗ୍ ପାଇଁ କ୍ଲାଏଣ୍ଟର ମଡେଲ୍କୁ ଦେବାକୁ ପଡ଼ୁଥିବା ପ୍ରତି-ଅନୁରୋଧ ଟୋକନ୍ ଖର୍ଚ୍ଚ ("layer 5" ସଂକୋଚନ) କମିଯାଏ। ଏହାର ରୂପାୟଣ `open-sse/mcp-server/toolCardinality.ts` ଭିତରେ ଥିବା ଏକ ବିଶୁଦ୍ଧ, ଅବସ୍ଥାବିହୀନ ଫିଲ୍ଟର୍ (`reduceToolManifest`), ଯାହାକୁ `createMcpServer()` (`open-sse/mcp-server/server.ts`) ଭିତରେ ଥିବା ପଞ୍ଜୀକରଣ ଲୁପ୍ ସହ ସଂଯୋଗ କରାଯାଇଛି।

**ଇଚ୍ଛାଧୀନ, ଡିଫଲ୍ଟ ଭାବେ ବନ୍ଦ।** ଦୁଇଟି ପରିବେଶ ଭେରିଏବଲ୍ରୁ ଅତି କମରେ ଗୋଟିଏ ସେଟ୍ ହୋଇଥିଲେ ହିଁ ଫିଲ୍ଟର୍ ଚାଲେ; କୌଣସିଟି ସେଟ୍ ହୋଇନଥିଲେ, ସମସ୍ତ 110ଟି ଟୁଲ୍ ଅପରିବର୍ତ୍ତିତ ଭାବେ ଘୋଷଣା କରାଯାଏ।

| ଭେରିଏବଲ୍         | ମୋଡ୍                                                                                            |
| :--------------- | :---------------------------------------------------------------------------------------------- |
| `MCP_TOOL_DENY`  | ବ୍ଲାକ୍ଲିଷ୍ଟ — କମା ଦ୍ୱାରା ପୃଥକ କରାଯାଇଥିବା ଟୁଲ୍ ନାମ, ଯାହାକୁ ସର୍ବଦା `tools/list`ରୁ ବାଦ ଦିଆଯାଏ      |
| `MCP_TOOL_ALLOW` | ଅନୁମତି-ତାଲିକା — କମା ଦ୍ୱାରା ପୃଥକ କରାଯାଇଥିବା ଟୁଲ୍ ନାମ; କେବଳ ଏଗୁଡ଼ିକ ରହିଥାଏ, ଅନ୍ୟ ସବୁକୁ ବାଦ ଦିଆଯାଏ |

`deny`, `allow` ଅପେକ୍ଷା ଅଗ୍ରାଧିକାର ପାଏ। ନାମଗୁଡ଼ିକ କମା ଦ୍ୱାରା ପୃଥକ କରାଯାଏ, ଚାରିପାଖର ଖାଲି ସ୍ଥାନ କାଟି ଦିଆଯାଏ ଏବଂ ଖାଲି ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ ଅଣଦେଖା କରାଯାଏ। ଉଦାହରଣ:

```bash
# କ୍ୟାଟାଲଗ୍ରୁ ଦୁଇଟି ଟୁଲ୍ ବାଦ ଦିଅନ୍ତୁ
MCP_TOOL_DENY="omniroute_get_health,omniroute_list_combos" omniroute --mcp

# କେବଳ ରାଉଟିଂ + କୋଟା ଟୁଲ୍ଗୁଡ଼ିକୁ ଘୋଷଣା କରନ୍ତୁ (ଅନୁମତି-ତାଲିକା ମୋଡ୍)
MCP_TOOL_ALLOW="omniroute_route_request,omniroute_check_quota" omniroute --mcp
```

**ଫିଲ୍ଟର୍ ହୋଇଥିବା ଟୁଲ୍ଗୁଡ଼ିକ କିପରି ଅପସାରଣ କରାଯାଏ:** ପଞ୍ଜୀକରଣ ସର୍ବଦା ସଫଳ ହୁଏ; ପ୍ରୋଫାଇଲ୍ ପ୍ରତ୍ୟାଖ୍ୟାନ କରୁଥିବା ଟୁଲ୍କୁ ପରେ MCP SDK ହ୍ୟାଣ୍ଡଲ୍ରେ `.disable()` କରାଯାଏ, ତେଣୁ ଏହା କେବେବି `tools/list`ରେ ଦେଖାଯାଏ ନାହିଁ, କିନ୍ତୁ ୱାୟାରିଂ ଅକ୍ଷୁଣ୍ଣ ରହେ (ସ୍ୱଚ୍ଛ ସକ୍ଷମ/ଅକ୍ଷମ କରଣ, ପୁନଃ-ପଞ୍ଜୀକରଣ ନାହିଁ)। ପ୍ରୋଫାଇଲ୍ ପାର୍ସର୍ ହେଉଛି `readMcpToolProfileFromEnv(process.env)`, ଯାହା ଉଭୟ ଭେରିଏବଲ୍ ଖାଲି ଥିଲେ `null` (କୌଣସି ଫିଲ୍ଟରିଂ ନାହିଁ) ଫେରାଏ।

`reduceToolManifest` ପଛରେ ଥିବା ଅଧିକ ସମୃଦ୍ଧ `ToolProfile` ଗଠନ ସ୍କୋପ୍-ଇଣ୍ଟରସେକ୍ସନ୍ ଫିଲ୍ଟରିଂ (`allowScopes`, `read:*`-ଶୈଳୀର ୱାଇଲ୍ଡକାର୍ଡ ମେଳ ସହିତ) ଏବଂ ଏକ ନିର୍ଦ୍ଧାରିତ `maxTools` ସୀମାକୁ ମଧ୍ୟ ସମର୍ଥନ କରେ, କିନ୍ତୁ ଏହି ଦୁଇଟି ନିୟନ୍ତ୍ରଣ ପାଇଁ ପଞ୍ଜୀକରଣ ସମୟରେ ସମ୍ପୂର୍ଣ୍ଣ ମ୍ୟାନିଫେଷ୍ଟ ଆବଶ୍ୟକ ଏବଂ ଆଜି ପରିବେଶ ଭେରିଏବଲ୍ଗୁଡ଼ିକ ମାଧ୍ୟମରେ ଏଗୁଡ଼ିକୁ ପ୍ରକାଶ କରାଯାଇ **ନାହିଁ** (ଏକ `tools/list`-ସ୍ତରୀୟ ହୁକ୍ ହେଉଛି ଟ୍ରାକ୍ କରାଯାଇଥିବା ପରବର୍ତ୍ତୀ କାର୍ଯ୍ୟ)। ହ୍ରାସ ପୂର୍ବରୁ ଏବଂ ପରେ ମ୍ୟାନିଫେଷ୍ଟ ଟୋକନ୍ ଖର୍ଚ୍ଚ ତୁଳନା କରିବା ପାଇଁ `estimateManifestTokens()` ଉପଲବ୍ଧ।

## ରନ୍ଟାଇମ୍ ହାର୍ଟବିଟ୍

stdio ଟ୍ରାନ୍ସପୋର୍ଟ ପ୍ରତି 5 ସେକେଣ୍ଡରେ `${DATA_DIR}/runtime/mcp-heartbeat.json`ରେ ସକ୍ରିୟତା ଅବସ୍ଥା ସଂରକ୍ଷଣ କରେ। ଡ୍ୟାସ୍ବୋର୍ଡ (`/api/mcp/status`) `online` ନିର୍ଣ୍ଣୟ କରିବା ପାଇଁ ଏହି ଫାଇଲ୍ ସହିତ PIDର ସକ୍ରିୟତା ଅବସ୍ଥା ପଢ଼େ। ଏହା ପରିବର୍ତ୍ତେ HTTP ଟ୍ରାନ୍ସପୋର୍ଟଗୁଡ଼ିକ ଇନ୍-ପ୍ରୋସେସ୍ `getMcpHttpStatus()`ରୁ ଅବସ୍ଥା ରିପୋର୍ଟ କରନ୍ତି (କୌଣସି ଫାଇଲ୍ ଲେଖା ନାହିଁ)।

ହାର୍ଟବିଟ୍ ସ୍ନାପ୍ଶଟ୍ରେ ଏଗୁଡ଼ିକ ରହିଥାଏ:

```json
{
  "pid": 12345,
  "startedAt": "2026-05-13T12:34:56.000Z",
  "lastHeartbeatAt": "2026-05-13T12:35:01.000Z",
  "version": "1.8.1",
  "transport": "stdio",
  "scopesEnforced": false,
  "allowedScopes": [],
  "toolCount": 110
}
```

## ଅଡିଟ୍ ଲଗିଂ

ପ୍ରତ୍ୟେକ ଟୁଲ୍ କଲ୍କୁ `open-sse/mcp-server/audit.ts` ଦ୍ୱାରା SQLite `mcp_tool_audit` ଟେବୁଲ୍ରେ ଲଗ୍ କରାଯାଏ:

- ଟୁଲ୍ ନାମ, ଆର୍ଗୁମେଣ୍ଟ୍ଗୁଡ଼ିକ (ପ୍ରତି-ଟୁଲ୍ `auditLevel` ଅନୁଯାୟୀ ହ୍ୟାଶ୍ କରାଯାଇଥିବା/ସଂକ୍ଷିପ୍ତ କରାଯାଇଥିବା), ଫଳାଫଳ
- ମିଲିସେକେଣ୍ଡରେ ଅବଧି, ସଫଳତା/ବିଫଳତା ଫ୍ଲାଗ୍, ତ୍ରୁଟି ବାର୍ତ୍ତା (ଯେତେବେଳେ ପ୍ରଯୁଜ୍ୟ)
- API କି ହ୍ୟାଶ୍, ଟାଇମ୍ଷ୍ଟାମ୍ପ
- ସ୍କୋପ୍ ପ୍ରତ୍ୟାଖ୍ୟାନଗୁଡ଼ିକୁ ଅନୁପସ୍ଥିତ ସ୍କୋପ୍ ତାଲିକା ସହିତ `scope_denied:<reason>` ଭାବେ ଲଗ୍ କରାଯାଏ

ସାମ୍ପ୍ରତିକ କଲ୍ଗୁଡ଼ିକ ଯାଞ୍ଚ କରିବା ପାଇଁ ଡ୍ୟାସ୍ବୋର୍ଡ କିମ୍ବା `/api/mcp/audit` ଏବଂ `/api/mcp/audit/stats` REST ଏଣ୍ଡପଏଣ୍ଟ୍ଗୁଡ଼ିକ ବ୍ୟବହାର କରନ୍ତୁ।
