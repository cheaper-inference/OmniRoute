Traffic Inspector ହେଉଛି OmniRouteର ଅନ୍ତର୍ନିହିତ HTTPS ଟ୍ରାଫିକ୍ ଡିବଗର୍ — Charles Proxy / mitmweb / HTTP Toolkit ପରି ଏକ ଟୁଲ୍, ଯାହା **LLM-ସଚେତନ** ଏବଂ **ଏଜେଣ୍ଟ-ସଚେତନ**। ଏହା `/dashboard/tools/traffic-inspector`ରେ ଉପଲବ୍ଧ ଏବଂ ଏକସଙ୍ଗେ ସର୍ବାଧିକ 5ଟି କ୍ୟାପଚର୍ ଉତ୍ସରୁ ଲାଇଭ୍ ଟ୍ରାଫିକ୍ ଗ୍ରହଣ କରେ।

**ଡ୍ୟାସବୋର୍ଡ ଅବସ୍ଥାନ:** `/dashboard/tools/traffic-inspector`
**ସାଇଡ୍ବାର୍ ଗ୍ରୁପ୍:** Tools (AgentBridge ପରେ)
**ଏହା ମଧ୍ୟ ଦେଖନ୍ତୁ:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge ହେଉଛି କ୍ୟାପଚର୍ ମୋଡ୍ 1।

### ଗୋଟିଏ ଅନୁଚ୍ଛେଦରେ ଆର୍କିଟେକ୍ଚର୍

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) ହେଉଛି ଏକ ଅଂଶୀଦାର ଇନ୍-ମେମୋରି ରିଙ୍ଗ୍ ବଫର୍ (ଡିଫଲ୍ଟ ଭାବେ 1000ଟି ଏଣ୍ଟ୍ରି, `INSPECTOR_BUFFER_SIZE` ମାଧ୍ୟମରେ ବିନ୍ୟାସଯୋଗ୍ୟ)। ସମସ୍ତ କ୍ୟାପଚର୍ ଉତ୍ସ `push()` ମାଧ୍ୟମରେ ଏଥିରେ ଲେଖନ୍ତି। ବଫର୍ଟି `kindDetector.ts` ବ୍ୟବହାର କରି ପ୍ରତ୍ୟେକ ଏଣ୍ଟ୍ରିକୁ ବର୍ଗୀକୃତ କରେ (ଏହା ଏକ LLM ଅନୁରୋଧ କି ନାହିଁ ନିର୍ଣ୍ଣୟ କରେ), ଏକ `contextKey` (ସିଷ୍ଟମ୍ ପ୍ରମ୍ପ୍ଟର SHA-256 ଫିଙ୍ଗରପ୍ରିଣ୍ଟ) ଗଣନା କରେ ଏବଂ `globalTrafficBuffer.subscribe()` ମାଧ୍ୟମରେ ସମସ୍ତ WebSocket ସବ୍ସ୍କ୍ରାଇବର୍ଙ୍କୁ ପ୍ରସାରଣ କରେ। ଡ୍ୟାସବୋର୍ଡଟି `GET /api/tools/traffic-inspector/ws` ମାଧ୍ୟମରେ ସଂଯୋଗ କରେ ଏବଂ ସଂଯୋଗ ସମୟରେ ଏକ ସ୍ନାପ୍ଶଟ୍ ଗ୍ରହଣ କରେ, ଯାହା ପରେ `new`/`update`/`clear` ଇଭେଣ୍ଟଗୁଡ଼ିକ ଆସେ।

## §2 କ୍ୟାପ୍ଚର୍ ମୋଡ୍ଗୁଡ଼ିକ

Traffic Inspector **5ଟି ଏକକାଳୀନ କ୍ୟାପ୍ଚର୍ ଉତ୍ସ** ସମର୍ଥନ କରେ। ପ୍ରତ୍ୟେକଟିକୁ ସ୍ୱାଧୀନ ଭାବରେ ଟୋଗଲ୍ କରାଯାଇପାରେ। ପ୍ରତ୍ୟେକ `InterceptedRequest` (`src/mitm/inspector/types.ts`)ରେ ଥିବା `source` ଫିଲ୍ଡଟି `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"`, କିମ୍ବା `"tproxy"` ମଧ୍ୟରୁ ଗୋଟିଏ।

### ମୋଡ୍ 1 — AgentBridge (ଡିଫଲ୍ଟ, ସର୍ବଦା ସକ୍ରିୟ)

**ଉତ୍ସ:** AgentBridge ହ୍ୟାଣ୍ଡଲର୍ଗୁଡ଼ିକ (`src/mitm/handlers/base.ts`)
**ପ୍ରଣାଳୀ:** `MitmHandlerBase`ରେ ଥିବା ପ୍ରତ୍ୟେକ `intercept()` କଲ୍ ଫରୱାର୍ଡ କରିବା ପୂର୍ବରୁ `hookBufferStart()`କୁ ଏବଂ ସମାପ୍ତି ସମୟରେ `hookBufferUpdate()`କୁ କଲ୍ କରେ। କୌଣସି ଅତିରିକ୍ତ ବିନ୍ୟାସ ଆବଶ୍ୟକ ନାହିଁ — AgentBridge ଚାଲୁ ହେବା ମାତ୍ରେ ଏହା କାମ କରେ।
**ପରିସର:** AgentBridgeରେ ବିନ୍ୟାସିତ 9ଟି IDE ଏଜେଣ୍ଟ
**ଟିପ୍ପଣୀ:** `InterceptedRequest`ରେ `source` ଫିଲ୍ଡ = `"agent-bridge"`

### ମୋଡ୍ 2 — କଷ୍ଟମ୍ ହୋଷ୍ଟଗୁଡ଼ିକ (DNS ପୁନଃନିର୍ଦ୍ଦେଶନ)

**ଉତ୍ସ:** ବ୍ୟବହାରକାରୀ-ନିର୍ଦ୍ଧାରିତ ହୋଷ୍ଟ ତାଲିକା (`inspector_custom_hosts` ଟେବୁଲ୍)
**ପ୍ରଣାଳୀ:** UI ମାଧ୍ୟମରେ ଏକ ହୋଷ୍ଟ ଯୋଡ଼ିଲେ `/etc/hosts`ରେ `127.0.0.1 <host>` ଯୋଡ଼ାଯାଏ (sudo ଆବଶ୍ୟକ)। ବିଦ୍ୟମାନ AgentBridge MITM ସର୍ଭର୍ (ପୋର୍ଟ 443) ନୂଆ ହୋଷ୍ଟ ପାଇଁ ଡାଇନାମିକ୍ ଭାବରେ ଏକ SNI ସର୍ଟିଫିକେଟ୍ ସୃଷ୍ଟି କରେ।
**ପରିସର:** ଯୋଡ଼ାଯାଇଥିବା ହୋଷ୍ଟ ବ୍ୟବହାର କରୁଥିବା ଯେକୌଣସି ଆପ୍ଲିକେସନ୍ — ଆପ୍ ବିନ୍ୟାସରେ କୌଣସି ପରିବର୍ତ୍ତନ ଆବଶ୍ୟକ ନାହିଁ
**ଟିପ୍ପଣୀ:** `source` = `"custom-host"`

ବ୍ୟବହାରର ଉଦାହରଣଗୁଡ଼ିକ:

- Python ସ୍କ୍ରିପ୍ଟଗୁଡ଼ିକରୁ `api.openai.com` ନିରୀକ୍ଷଣ କରନ୍ତୁ
- `my-internal-llm.company.com` ଡିବଗ୍ କରନ୍ତୁ
- ସମାନ ନେଟୱର୍କରେ ଥିବା ମୋବାଇଲ୍ ଡିଭାଇସ୍ଗୁଡ଼ିକରୁ ଟ୍ରାଫିକ୍ କ୍ୟାପ୍ଚର୍ କରନ୍ତୁ (ARP ସ୍ପୁଫିଂ ମାଧ୍ୟମରେ — ଉନ୍ନତ)

### ମୋଡ୍ 3 — HTTP_PROXY ଲିସନର୍ (ପୋର୍ଟ 8080)

**ଉତ୍ସ:** `HTTP_PROXY`/`HTTPS_PROXY` ପରିବେଶ ଭେରିଏବଲ୍ଗୁଡ଼ିକ ବ୍ୟବହାର କରୁଥିବା ଆପ୍ଲିକେସନ୍ଗୁଡ଼ିକ
**ପ୍ରଣାଳୀ:** ପୋର୍ଟ 8080ରେ ଏକ ଦ୍ୱିତୀୟ ଲିସନର୍ (`src/mitm/inspector/httpProxyServer.ts`), ଯାହା ଏକ ମାନକ ସ୍ପଷ୍ଟ HTTP/HTTPS ପ୍ରକ୍ସି ଭାବେ କାର୍ଯ୍ୟ କରେ। `CONNECT` ଟନେଲ୍ଗୁଡ଼ିକ (HTTPS) ଏବଂ ସିଧାସଳଖ HTTP ଅନୁରୋଧଗୁଡ଼ିକୁ ଗ୍ରହଣ କରେ।
**ପରିସର:** `HTTP_PROXY` ପରିବେଶ ଭେରିଏବଲ୍କୁ ସମ୍ମାନ କରୁଥିବା ଯେକୌଣସି ଆପ୍ଲିକେସନ୍ — କୌଣସି DNS ପରିବର୍ତ୍ତନ ନାହିଁ, sudo ଆବଶ୍ୟକ ନାହିଁ
**ଟିପ୍ପଣୀ:** `source` = `"http-proxy"`

```bash
# ଗୋଟିଏ କମାଣ୍ଡ ପାଇଁ ଦ୍ରୁତ କ୍ୟାପ୍ଚର୍:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# ଏକ shell ସେସନ୍ରେ ସ୍ଥାୟୀ କ୍ୟାପ୍ଚର୍:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS ସୀମାବଦ୍ଧତା:** HTTPS ଏକ ସାଧାରଣ `CONNECT` ଟନେଲ୍ ମାଧ୍ୟମରେ ଯାଏ: ଲିସନର୍ ଏନ୍କ୍ରିପ୍ଟ ହୋଇଥିବା ବାଇଟ୍ଗୁଡ଼ିକୁ ଅପରିବର୍ତ୍ତିତ ଭାବରେ ରିଲେ କରେ ଏବଂ କେବଳ ମେଟାଡାଟା (ହୋଷ୍ଟ, ପୋର୍ଟ, ସମୟ) ରେକର୍ଡ କରେ। ଏହା କେବେବି HTTPS ଡିକ୍ରିପ୍ଟ କରେ ନାହିଁ, ଏବଂ ଏହି ମୋଡ୍ ପାଇଁ ଡିକ୍ରିପ୍ସନ୍ ସକ୍ରିୟ କରୁଥିବା କୌଣସି ସେଟିଂ ନାହିଁ। HTTPS ବଡିଗୁଡ଼ିକୁ କ୍ୟାପ୍ଚର୍ କରିବା ପାଇଁ, ହୋଷ୍ଟକୁ ମୋଡ୍ 1 (AgentBridge), ମୋଡ୍ 2 (କଷ୍ଟମ୍ ହୋଷ୍ଟଗୁଡ଼ିକ) କିମ୍ବା ମୋଡ୍ 5 (TPROXY ଡିକ୍ରିପ୍ଟ) ମାଧ୍ୟମରେ ରୁଟ୍ କରନ୍ତୁ।

**ପୋର୍ଟ ଦ୍ୱନ୍ଦ୍ୱ:** ପୋର୍ଟ 8080 ବ୍ୟବହାରରେ ଥିଲେ, AgentBridge ଏକ ସଂରଚିତ ତ୍ରୁଟି ସହିତ 409 ଫେରାଏ। `INSPECTOR_HTTP_PROXY_PORT` ପରିବେଶ ଭେରିଏବଲ୍ ମାଧ୍ୟମରେ ପୋର୍ଟ ପରିବର୍ତ୍ତନ କରନ୍ତୁ।

### ମୋଡ୍ 4 — ସିଷ୍ଟମ୍-ବ୍ୟାପୀ ପ୍ରକ୍ସି (ଉନ୍ନତ, ଇଚ୍ଛାଧୀନ)

**ଉତ୍ସ:** OS-ସ୍ତରୀୟ ପ୍ରକ୍ସି ସେଟିଂସ୍ (ମେସିନ୍ରେ ଥିବା ସମସ୍ତ ଆପ୍ରେ ପ୍ରଯୁଜ୍ୟ)
**ପ୍ରଣାଳୀ:** ସମସ୍ତ HTTP/HTTPS ଟ୍ରାଫିକ୍କୁ HTTP_PROXY ଲିସନର୍ ମାଧ୍ୟମରେ ପୁନଃନିର୍ଦ୍ଦେଶିତ କରିବା ପାଇଁ OS APIଗୁଡ଼ିକ ବ୍ୟବହାର କରେ:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **ପରିସର:** ସିଷ୍ଟମ୍ ପ୍ରକ୍ସି ସେଟିଂସ୍କୁ ସମ୍ମାନ କରୁଥିବା ମେସିନ୍ର ପ୍ରତ୍ୟେକ ଆପ୍ଲିକେସନ୍
  **ଟିପ୍ପଣୀ:** `source` = `"system-proxy"`

**ସୁରକ୍ଷା ପ୍ରଣାଳୀଗୁଡ଼ିକ:**

- ସ୍ୱୟଂଚାଳିତ ଭାବେ ଅକ୍ଷମ କରିବାର ଟାଇମର୍ (ଡିଫଲ୍ଟ 30 ମିନିଟ୍, `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` ମାଧ୍ୟମରେ ବିନ୍ୟାସଯୋଗ୍ୟ)
- ପୂର୍ବ ସିଷ୍ଟମ୍ ପ୍ରକ୍ସି ସ୍ଥିତି DBରେ ସଞ୍ଚୟ ହୁଏ ଏବଂ ପ୍ରତ୍ୟାବର୍ତ୍ତନ ସମୟରେ ପୁନଃସ୍ଥାପିତ ହୁଏ
- ଏହା ସକ୍ରିୟ ଥିବାବେଳେ ବ୍ୟବହାରକାରୀ ଅନ୍ୟତ୍ର ନାଭିଗେଟ୍ କଲେ ଡ୍ୟାସ୍ବୋର୍ଡ "ସିଷ୍ଟମ୍ ପ୍ରକ୍ସି ପ୍ରତ୍ୟାବର୍ତ୍ତନ କରାଯାଉଛି" ପ୍ରମ୍ପ୍ଟ ଦେଖାଏ
- UI `⚠ ଉନ୍ନତ` ବ୍ୟାଜ୍ + ସ୍ପଷ୍ଟ ନିଶ୍ଚିତକରଣ ଚେକ୍ବକ୍ସ ଦେଖାଏ

### ମୋଡ୍ 5 — TPROXY ସ୍ୱଚ୍ଛ ଡିକ୍ରିପ୍ଟ (Linux, root, ଇଚ୍ଛାଧୀନ)

**ଉତ୍ସ:** Kernel TPROXY + ପଲିସି ରାଉଟିଂ (`src/mitm/tproxy/`)
**ପ୍ରଣାଳୀ:** `mangle OUTPUT`ରେ ଏକ ଲକ୍ଷ୍ୟ ପୋର୍ଟକୁ (ଡିଫଲ୍ଟ `443`) ଯାଉଥିବା ନୂଆ ସ୍ଥାନୀୟ ଆଉଟ୍ବାଉଣ୍ଡ TCP ସଂଯୋଗଗୁଡ଼ିକୁ ଚିହ୍ନିତ କରେ, ଏକ `ip rule` ଚିହ୍ନିତ ପ୍ୟାକେଟ୍ଗୁଡ଼ିକୁ ସ୍ଥାନୀୟ ଡେଲିଭରିକୁ ପୁନଃରୁଟ୍ କରେ, ଏବଂ `mangle PREROUTING`ର `TPROXY` ଟାର୍ଗେଟ୍ ସେଗୁଡ଼ିକୁ ଏକ ସ୍ୱଚ୍ଛ (**IP_TRANSPARENT**) ଲିସନର୍କୁ (ଡିଫଲ୍ଟ ପୋର୍ଟ `8443`) ହସ୍ତାନ୍ତର କରେ। ଲିସନର୍ ଏକ ଡାଇନାମିକ୍ CA ଦ୍ୱାରା **ଚାହିଦା ଅନୁସାରେ ପ୍ରତ୍ୟେକ SNI ହୋଷ୍ଟନାମ ପାଇଁ** ଜାରି କରାଯାଇଥିବା ଲିଫ୍ ସର୍ଟିଫିକେଟ୍ ସହିତ TLS ସମାପ୍ତ କରେ, ଡିକ୍ରିପ୍ଟ ହୋଇଥିବା ବିନିମୟକୁ କ୍ୟାପ୍ଚର୍ କରେ, ଏବଂ ଅନୁରୋଧକୁ ପୁନଃଏନ୍କ୍ରିପ୍ଟ କରି ମୂଳ ଗନ୍ତବ୍ୟସ୍ଥଳକୁ ଫରୱାର୍ଡ କରେ।
**ପରିସର:** ଲକ୍ଷ୍ୟ ପୋର୍ଟରେ **ଯେକୌଣସି** ଗନ୍ତବ୍ୟ ହୋଷ୍ଟ — କୌଣସି `/etc/hosts` ସ୍ପୁଫ୍ ନାହିଁ, `HTTP_PROXY` ପରିବେଶ ଭେରିଏବଲ୍ ନାହିଁ, ସିଷ୍ଟମ୍-ବ୍ୟାପୀ ପ୍ରକ୍ସି ପରିବର୍ତ୍ତନ ନାହିଁ। ଇଣ୍ଟରସେପ୍ଟ କରାଯାଇଥିବା ପ୍ରୋସେସ୍ରେ କୌଣସି ବିନ୍ୟାସ ପରିବର୍ତ୍ତନ ଆବଶ୍ୟକ ନାହିଁ, କିନ୍ତୁ ଏହା ଡାଇନାମିକ୍ CAକୁ ବିଶ୍ୱାସ କରିବା ଆବଶ୍ୟକ।
**ଟିପ୍ପଣୀ:** `source` = `"tproxy"`

**ଆବଶ୍ୟକତାଗୁଡ଼ିକ:** କେବଳ Linux (**IP_TRANSPARENT** କେବଳ Linuxରେ ଉପଲବ୍ଧ), **CAP_NET_ADMIN** କ୍ଷମତା (root), ଏବଂ ଏକ ନେଟିଭ୍ N-API ଆଡ୍ଅନ୍ ଯାହାକୁ C ଟୁଲ୍ଚେନ୍ ସହିତ ବିଲ୍ଡ କରିବା ଆବଶ୍ୟକ (`npm run build:native:tproxy`)। ଏଗୁଡ଼ିକ ଅନୁପଲବ୍ଧ ଥିଲେ, "TPROXY ଡିକ୍ରିପ୍ଟ ପାଇଁ Linux + root + ନେଟିଭ୍ ଆଡ୍ଅନ୍ ଆବଶ୍ୟକ" ଟୁଲ୍ଟିପ୍ ସହିତ ଡ୍ୟାସ୍ବୋର୍ଡ ଟୋଗଲ୍ ଅକ୍ଷମ ରହେ। ଫାୟାରୱାଲ୍ ନିୟମଗୁଡ଼ିକ ଟ୍ରାଞ୍ଜାକ୍ସନାଲ୍ ଭାବରେ ଲାଗୁ/ପ୍ରତ୍ୟାବର୍ତ୍ତନ କରାଯାଏ (ଏକ କ୍ରାସ୍ କେବେବି କୌଣସି `mangle` ନିୟମକୁ ଛାଡ଼ି ଯାଏ ନାହିଁ) ଏବଂ ରିବୁଟ୍ ସମୟରେ ସଫା ହୁଏ। ଏକ SO_MARK-ଆଧାରିତ ଆଣ୍ଟି-ଲୁପ୍ ପ୍ରକ୍ସିର ନିଜସ୍ୱ ପୁନଃଏନ୍କ୍ରିପ୍ଟ ହୋଇଥିବା ଫରୱାର୍ଡକୁ ପୁନର୍ବାର ଇଣ୍ଟରସେପ୍ଟ ହେବାରୁ ରୋକେ।

ଏହା ନିଜସ୍ୱ ଉତ୍ସର୍ଗୀକୃତ ଅପରେଟର୍ ଗାଇଡ୍ ସହିତ ଏକ ବ୍ୟାପକ ସବ୍ସିଷ୍ଟମ୍ — ସମ୍ପୂର୍ଣ୍ଣ ଫାୟାରୱାଲ୍ ପ୍ରକ୍ରିୟା, ପ୍ରତ୍ୟେକ-SNI ଡାଇନାମିକ୍ CA + ଟ୍ରଷ୍ଟ-ଷ୍ଟୋର୍ ଇନ୍ଷ୍ଟଲର୍, କେବଳ-ସ୍ଥାନୀୟ ରୁଟ୍, ଆଣ୍ଟି-ଲୁପ୍ ବିବରଣୀ ଏବଂ ବିନ୍ୟାସ ସ୍କିମା ପାଇଁ `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs`ରେ କମ୍ପାଇଲ୍ କରାଯାଇନାହିଁ) ଦେଖନ୍ତୁ। ଟୋଗଲ୍ଟି `GET / POST / DELETE /api/tools/agent-bridge/tproxy` ଦ୍ୱାରା ପରିଚାଳିତ ହୁଏ (ଟିପ୍ପଣୀ: ରୁଟ୍ଟି Traffic Inspector ପ୍ରିଫିକ୍ସ ଅଧୀନରେ ନୁହେଁ, AgentBridge ପ୍ରିଫିକ୍ସ ଅଧୀନରେ ରହିଛି)।

- **ଅଳସ ଭାବେ ବଡି ଲୋଡ୍**: କେବଳ ଚୟନିତ ଅନୁରୋଧର ବଡିକୁ ବିବରଣୀ ଟ୍ୟାବ୍ଗୁଡ଼ିକରେ ପ୍ରସ୍ତୁତ କରାଯାଏ (1000 × 1MB ବଡି ରେଣ୍ଡର୍ କରିବାରୁ ରକ୍ଷା କରେ)

## §4 LLM-ସଚେତନ ବୈଶିଷ୍ଟ୍ୟଗୁଡ଼ିକ

### 4.1 ପ୍ରକାର ନିର୍ଣ୍ଣାୟକ (`src/mitm/inspector/kindDetector.ts`)

4ଟି ସଙ୍କେତ ବ୍ୟବହାର କରି ପ୍ରତ୍ୟେକ ଅନୁରୋଧକୁ `"llm"`, `"app"`, କିମ୍ବା `"unknown"` ଭାବରେ ବର୍ଗୀକୃତ କରେ:

1. **ହୋଷ୍ଟ ରେଜିଷ୍ଟ୍ରି** — ~18ଟି ଜଣାଶୁଣା LLM API ହୋଷ୍ଟନାମ (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot, ଇତ୍ୟାଦି)
2. **ପଥ ପ୍ୟାଟର୍ନଗୁଡ଼ିକ** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses`, ଇତ୍ୟାଦି
3. **ବଡି ଆକୃତି** — `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input` ଫିଲ୍ଡଗୁଡ଼ିକୁ ଚିହ୍ନଟ କରେ
4. **ୟୁଜର-ଏଜେଣ୍ଟ ସୂଚନା** — UA ଷ୍ଟ୍ରିଙ୍ଗରେ `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor`

Mode 2 ମାଧ୍ୟମରେ ଯୋଡ଼ାଯାଇଥିବା କଷ୍ଟମ୍ ହୋଷ୍ଟଗୁଡ଼ିକ ଫର୍ମ ଇନପୁଟରୁ ସେମାନଙ୍କର `kind` ଉତ୍ତରାଧିକାରରେ ପାଆନ୍ତି (ଡିଫଲ୍ଟ ହେଉଛି `"custom"`)।

### 4.2 SSE ମର୍ଜର୍ (`src/mitm/inspector/sseMerger.ts`)

**ସ୍ୱାଧୀନ କ୍ଲିନ୍-ରୁମ୍ କାର୍ଯ୍ୟାନ୍ୱୟନ।** ଇଭେଣ୍ଟ ପାର୍ସିଂ
[WHATWG server-sent events ଆଲଗୋରିଦମ୍](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)
ଅନୁସରଣ କରେ, ଯେତେବେଳେ ପୁନର୍ଗଠନ ସାର୍ବଜନୀନ [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming), ଏବଂ
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
ଷ୍ଟ୍ରିମିଂ ସ୍କିମାଗୁଡ଼ିକୁ ଅନୁସରଣ କରେ।

କଞ୍ଚା SSE ଡେଲ୍ଟା ଇଭେଣ୍ଟଗୁଡ଼ିକରୁ ଅନ୍ତିମ ଆସିଷ୍ଟାଣ୍ଟ ସନ୍ଦେଶକୁ ପୁନର୍ଗଠନ କରେ:

- **Anthropic**: ଇଣ୍ଡେକ୍ସ ଅନୁସାରେ `content_block_delta` ସଞ୍ଚୟ କରେ; `text_delta`, `input_json_delta` (ଟୁଲ୍ କଲ୍), `thinking_delta` ପରିଚାଳନା କରେ
- **OpenAI**: Chat Completions ପସନ୍ଦ/ଟୁଲ୍ କଲ୍ ଏବଂ Responses API ଆଉଟପୁଟ୍ ଆଇଟମଗୁଡ଼ିକୁ
  ଇଣ୍ଡେକ୍ସ ଅନୁସାରେ ସଞ୍ଚୟ କରେ
- **Gemini**: `candidates[i].content.parts` ସଞ୍ଚୟ କରେ
- **Unknown**: କଞ୍ଚା ଇଭେଣ୍ଟଗୁଡ଼ିକୁ ଅପରିବର୍ତ୍ତିତ ଭାବରେ ଫେରାଏ

Response ଟ୍ୟାବ୍ ଏକ ଟୋଗଲ୍ ଦେଖାଏ: **"କଞ୍ଚା ଇଭେଣ୍ଟ ↔ ମର୍ଜ୍ ହୋଇଥିବା"**।

### 4.3 ବାର୍ତ୍ତାଳାପ ନର୍ମାଲାଇଜର୍ (`src/mitm/inspector/conversationNormalizer.ts`)

**ସ୍ୱାଧୀନ କ୍ଲିନ୍-ରୁମ୍ କାର୍ଯ୍ୟାନ୍ୱୟନ।** ନର୍ମାଲାଇଜେସନ୍ ସ୍ଥାନୀୟ ବ୍ଲାକ୍-ବକ୍ସ
ଚୁକ୍ତି ଏବଂ ସାର୍ବଜନୀନ OpenAI, Anthropic, ଓ Gemini ସନ୍ଦେଶ ସ୍କିମାଗୁଡ଼ିକ ଦ୍ୱାରା ପରିଭାଷିତ; କୌଣସି ଅପ୍ଷ୍ଟ୍ରିମ୍
କାର୍ଯ୍ୟାନ୍ୱୟନ ଉତ୍ସ ବ୍ୟବହୃତ ହୋଇନାହିଁ।

ରେଣ୍ଡରିଂ ପୂର୍ବରୁ OpenAI, Anthropic, ଏବଂ Gemini ସନ୍ଦେଶ ଫର୍ମାଟଗୁଡ଼ିକୁ ଗୋଟିଏ `NormalizedConversation`ରେ ରୂପାନ୍ତର କରେ:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // ଅନୁରୋଧ ବଡିରୁ messages / contents / prompt
  response: NormalizedTurn[]; // ଆସିଷ୍ଟାଣ୍ଟ ପ୍ରତିକ୍ରିୟା (sseMerger ମାଧ୍ୟମରେ ମର୍ଜ୍ ହୋଇଥିବା)
  contextKey: string | null; // SHA-256 ସିଷ୍ଟମ୍-ପ୍ରମ୍ପ୍ଟ ଫିଙ୍ଗରପ୍ରିଣ୍ଟ
}
```

ବ୍ଲକ୍ ପ୍ରକାରଗୁଡ଼ିକ: `text`, `tool_use`, `tool_result`। ପ୍ରଦାନକାରୀ ନିର୍ବିଶେଷରେ Conversation ଟ୍ୟାବ୍ ଏହି ଆକୃତି ବ୍ୟବହାର କରେ।

### 4.4 କଣ୍ଟେକ୍ସ୍ଟ କି ରଙ୍ଗକରଣ (`src/mitm/inspector/contextKey.ts`)

- ସିଷ୍ଟମ୍ ପ୍ରମ୍ପ୍ଟର `SHA-256` ଗଣନା କରେ (ପ୍ରଥମ `role:system` ସନ୍ଦେଶ, କିମ୍ବା `system` ଫିଲ୍ଡ, କିମ୍ବା Gemini `systemInstruction`)
- ଏକ 12-ଅକ୍ଷରର ହେକ୍ସ ପ୍ରିଫିକ୍ସ (`"a3f9c2..."`) ଫେରାଏ
- ସାମ୍ନା ପାର୍ଶ୍ୱ ବାର୍ ପାଇଁ ଫ୍ରଣ୍ଟଏଣ୍ଡ କିକୁ ଏକ ନିର୍ଦ୍ଧାରିତ HSL ରଙ୍ଗ ସହିତ ମ୍ୟାପ୍ କରେ
- **ଫିଲ୍ଟର୍ "ସମାନ କଣ୍ଟେକ୍ସ୍ଟ"**: `ctx #a3f` ଚିପ୍ରେ କ୍ଲିକ୍ କଲେ କେବଳ ସମାନ ଫିଙ୍ଗରପ୍ରିଣ୍ଟ ଥିବା ଅନୁରୋଧଗୁଡ଼ିକୁ ଦେଖାଇବା ପାଇଁ ଏକ ଫିଲ୍ଟର୍ ଯୋଡ଼ାଯାଏ

ଏହା ସମାନ ଏଜେଣ୍ଟ ସେସନ୍ରେ ଚାଲୁଥିବା ଭିନ୍ନ "ବ୍ୟକ୍ତିତ୍ୱ" କିମ୍ବା କାର୍ଯ୍ୟଗୁଡ଼ିକୁ ଦୃଶ୍ୟତଃ ଅଲଗା କରିବା ସହଜ କରେ।

### 4.5 LLM ମେଟାଡାଟା ନିଷ୍କାସନ

LLM ଅନୁରୋଧଗୁଡ଼ିକ ପାଇଁ, LLM Details ଟ୍ୟାବ୍ ନିମ୍ନଲିଖିତଗୁଡ଼ିକୁ ନିଷ୍କାସନ କରେ:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // ଅନୁରୋଧ ବଡି କିମ୍ବା ପ୍ରତିକ୍ରିୟାରୁ
  messages: number; // ଟର୍ନ ସଂଖ୍ୟା
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // SSE ପ୍ରତିକ୍ରିୟା ହେଲେ true
  mappedTo: string | null; // x-omniroute-mapped ହେଡର୍
  costEstimateUsd: number | null; // OmniRoute ମୂଲ୍ୟ ଆଧାରରେ ଆନୁମାନିକ ଖର୍ଚ୍ଚ
}
```

### 4.6 ସଜୀବ ଇନ୍-ଫ୍ଲାଇଟ୍ ଅନୁରୋଧ ଫିଲ୍ଟର୍

ଅନୁରୋଧର `status` ଫିଲ୍ଡ ହେଉଛି `number | "in-flight" | "error"` — ଅନୁରୋଧ ଆରମ୍ଭ ହେବା ମାତ୍ରେ ଏକ ଏଣ୍ଟ୍ରିକୁ
`"in-flight"` ଭାବରେ ପୁଶ୍ କରାଯାଏ ଏବଂ ପ୍ରତିକ୍ରିୟା (କିମ୍ବା ତ୍ରୁଟି) ଆସିଲେ **ସେହି ସ୍ଥାନରେ ଅପଡେଟ୍ କରାଯାଏ**।
ଟୁଲ୍ବାର୍ର **"Live"** ଟୋଗଲ୍
(`liveOnly`, i18n କି `trafficInspector.liveOnly`) ତାଲିକାକୁ ସେହି ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ମଧ୍ୟରେ ସୀମିତ କରେ
ଯାହାର `status === "in-flight"`, ଫଳରେ ଆପଣ ଖୋଲା ସଂଯୋଗଗୁଡ଼ିକୁ ବାସ୍ତବ ସମୟରେ ଦେଖିପାରିବେ।

ଫିଲ୍ଟର୍ଟି
`src/lib/inspector/matchesTrafficFilter.ts`ରେ ଥିବା ଏକ ଶୁଦ୍ଧ କ୍ଲାଏଣ୍ଟ-ସାଇଡ୍ ପ୍ରେଡିକେଟ୍:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

ଟୋଗଲ୍ ସ୍ଥିତି `useTrafficFilters`ରେ (ଇନ୍ସ୍ପେକ୍ଟର୍ ଡ୍ୟାସ୍ବୋର୍ଡ ହୁକ୍ଗୁଡ଼ିକ) ରହେ ଏବଂ
ଅନ୍ୟ ଫିଲ୍ଟର୍ଗୁଡ଼ିକ (ପ୍ରୋଫାଇଲ୍, ହୋଷ୍ଟ, ଏଜେଣ୍ଟ, ଉତ୍ସ, ସ୍ଥିତି, କଣ୍ଟେକ୍ସ୍ଟ) ସହିତ ମିଶି କାମ କରେ।

### 4.7 ପ୍ରକ୍ରିୟା ଆଟ୍ରିବ୍ୟୁସନ୍ (Linux)

Linuxରେ, ପ୍ରତ୍ୟେକ ଇଣ୍ଟରସେପ୍ଟ କରାଯାଇଥିବା ଅନୁରୋଧକୁ **ଉତ୍ପତ୍ତିକାରୀ ସ୍ଥାନୀୟ
ପ୍ରକ୍ରିୟା** ସହିତ ଯୋଡ଼ାଯାଇପାରିବ। `InterceptedRequest`ରେ ଦୁଇଟି ଇଚ୍ଛାଧୀନ ଫିଲ୍ଡ ଯୋଡ଼ାଯାଇଛି:

```ts
pid?: number;          // ଉତ୍ପତ୍ତିକାରୀ ପ୍ରକ୍ରିୟା ID (କେବଳ Linux)
processName?: string;  // ଉତ୍ପତ୍ତିକାରୀ ପ୍ରକ୍ରିୟା ନାମ (କେବଳ Linux)
```

`src/mitm/inspector/processAttribution.ts` ସଂଯୋଗର _କ୍ଲାଏଣ୍ଟ_
ଅସ୍ଥାୟୀ ପୋର୍ଟକୁ ନିମ୍ନ ପଦ୍ଧତିରେ ଏକ PID + ନାମ ସହିତ ମ୍ୟାପ୍ କରେ:

1. ପୋର୍ଟ ପାଇଁ ସକେଟ୍ inode ଖୋଜିବାକୁ `/proc/net/tcp` ଏବଂ `/proc/net/tcp6` ପଢ଼େ
   (`parseProcNetTcpForInode`, ଏକ ଶୁଦ୍ଧ ଫିକ୍ସଚର୍-ପରୀକ୍ଷଣଯୋଗ୍ୟ ପାର୍ସର୍)।
2. `socket:[<inode>]` ପ୍ରତି ଏକ ସିମ୍ଲିଙ୍କ ପାଇଁ `/proc/<pid>/fd/` ସ୍କାନ୍ କରେ।
3. `/proc/<pid>/comm`ରୁ ପ୍ରକ୍ରିୟା ନାମ ପଢ଼େ।

ଏକ 1-ସେକେଣ୍ଡ TTL କ୍ୟାଶ୍ ଲୋଡ୍ ଅଧୀନରେ procfs ସ୍କାନ୍ ଖର୍ଚ୍ଚକୁ ସୀମିତ କରେ। ଆଟ୍ରିବ୍ୟୁସନ୍
**ସର୍ବୋତ୍ତମ-ପ୍ରୟାସ ଭିତ୍ତିକ** — ଯେକୌଣସି ବିଫଳତା `null`ରେ ସମାଧାନ ହୁଏ ଏବଂ କ୍ୟାପ୍ଚର୍କୁ କେବେ ଅବରୋଧ କରେନାହିଁ।
macOS/Windowsରେ ଫଙ୍କସନ୍ଟି `null` ଫେରାଏ (ଷ୍ଟବ୍; `lsof`/`GetExtendedTcpTable`
ସମର୍ଥନ ଏକ ପରବର୍ତ୍ତୀ କାର୍ଯ୍ୟ)।

## §5 ସେସନ୍ଗୁଡ଼ିକ

### 5.1 ଏକ ସେସନ୍ ରେକର୍ଡ କରିବା

1. ଟୁଲ୍ବାର୍ରେ **"● ସେସନ୍ ରେକର୍ଡ କରନ୍ତୁ"** କ୍ଲିକ୍ କରନ୍ତୁ → ଏକ ନାମ ଦିଅନ୍ତୁ (ଇଚ୍ଛାଧୀନ)
2. ଲାଇଭ୍ ଟେଲ୍ ସ୍ୱାଭାବିକ ଭାବରେ ଜାରି ରହେ; ଏକ ଲାଲ୍ ସ୍ପନ୍ଦିତ ସୂଚକ `◉ REC · <name> · 00:42 · 23ଟି ଅନୁରୋଧ` ଦେଖାଏ
3. **"⏹ ବନ୍ଦ କରନ୍ତୁ"** କ୍ଲିକ୍ କରନ୍ତୁ → ସେସନ୍ ସ୍ନାପ୍ଶଟ୍ଟି `inspector_sessions` + `inspector_session_requests`ରେ ସଞ୍ଚୟ ହୁଏ

### 5.2 ଏକ ରେକର୍ଡ ହୋଇଥିବା ସେସନ୍ ଦେଖିବା

ଟୁଲ୍ବାର୍ରେ ଥିବା **ସେସନ୍ଗୁଡ଼ିକ** ଡ୍ରପ୍ଡାଉନ୍ ସଞ୍ଚିତ ସେସନ୍ଗୁଡ଼ିକୁ ତାଲିକାଭୁକ୍ତ କରେ। ଗୋଟିଏ ଚୟନ କଲେ:

- ସେସନ୍ର ସ୍ନାପ୍ଶଟ୍ (ସ୍ଥିରୀକୃତ ଅବସ୍ଥା) ଲୋଡ୍ ହୁଏ
- ଏକ ବ୍ୟାନର୍ ଦେଖାଏ: `ରେକର୍ଡ ହୋଇଥିବା ସେସନ୍ "<name>" ଦେଖୁଛନ୍ତି — [ଲାଇଭ୍କୁ ଫେରନ୍ତୁ]`
- Recharts ସମାହାରଗୁଡ଼ିକ ସହିତ ପରିସଂଖ୍ୟାନ ଟ୍ୟାବ୍ ଉପଲବ୍ଧ ହୁଏ

### 5.3 ରପ୍ତାନି ଫର୍ମାଟ୍ଗୁଡ଼ିକ

ପ୍ରତ୍ୟେକ ସେସନ୍କୁ ଏହି ଫର୍ମାଟ୍ଗୁଡ଼ିକରେ ରପ୍ତାନି କରାଯାଇପାରେ:

| ଫର୍ମାଟ୍                    | ବ୍ୟବହାର                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------- |
| **HAR** (HTTP Archive 1.2) | Chrome DevTools, Charles, Fiddler ସହିତ ସୁସଙ୍ଗତ — ଅଫ୍ଲାଇନ୍ ବିଶ୍ଳେଷଣ ପାଇଁ ଆମଦାନି କରନ୍ତୁ |
| **JSONL**                  | ପ୍ରତି ଧାଡ଼ିରେ ଗୋଟିଏ `InterceptedRequest` — `llm-interceptor` ଫର୍ମାଟ୍ ସହିତ ସୁସଙ୍ଗତ     |

`GET /api/tools/traffic-inspector/sessions/{id}/export.har` କିମ୍ବା ସେସନ୍ଗୁଡ଼ିକ ଡ୍ରପ୍ଡାଉନ୍ରେ ଥିବା ⬇ ବଟନ୍ ମାଧ୍ୟମରେ ରପ୍ତାନି କରନ୍ତୁ।

### ଜଣାଶୁଣା ସୀମାବଦ୍ଧତାଗୁଡ଼ିକ

- **ସିଷ୍ଟମ୍-ବ୍ୟାପୀ ପ୍ରକ୍ସି ମୋଡ୍** VPN କ୍ଲାଏଣ୍ଟ ଏବଂ SSO ସମେତ ମେସିନ୍ର ସମସ୍ତ ଆପ୍ଲିକେସନ୍କୁ ପ୍ରଭାବିତ କରେ। ସର୍ବଦା ସ୍ୱୟଂଚାଳିତ-ନିଷ୍କ୍ରିୟକରଣ ଟାଇମର୍ ସହିତ ବ୍ୟବହାର କରନ୍ତୁ। ସହଭାଗୀ ମେସିନ୍ଗୁଡ଼ିକରେ ଏହା ବ୍ୟବହାର କରନ୍ତୁ ନାହିଁ।
- **CONNECT ଟନେଲ୍ HTTPS**: Mode 3 (HTTP_PROXY) HTTPS ଗନ୍ତବ୍ୟସ୍ଥଳ ପାଇଁ କେବଳ ଟନେଲ୍ ମେଟାଡାଟା କ୍ୟାପ୍ଚର୍ କରେ ଏବଂ ସେଗୁଡ଼ିକୁ କେବେ ମଧ୍ୟ ଡିକ୍ରିପ୍ଟ କରେ ନାହିଁ। ଏହା ଉଦ୍ଦେଶ୍ୟମୂଳକ — ଡିକ୍ରିପ୍ଟ କରିବା ପାଇଁ ପ୍ରତ୍ୟେକ କ୍ଲାଏଣ୍ଟକୁ ଏକ MITM ସାର୍ଟିଫିକେଟ୍ ଉପରେ ଭରସା କରିବାକୁ ପଡ଼ିବ, ତେଣୁ ଲିସନର୍ HTTPSକୁ ଏଣ୍ଡ-ଟୁ-ଏଣ୍ଡ ଏନ୍କ୍ରିପ୍ଟେଡ୍ ରଖେ। HTTPS ବଡି ଆବଶ୍ୟକ ହେଲେ AgentBridge, Custom Hosts କିମ୍ବା TPROXY ଡିକ୍ରିପ୍ସନ୍ ବ୍ୟବହାର କରନ୍ତୁ।
- **କିଛି କମ୍ପୋନେଣ୍ଟରେ ହାର୍ଡକୋଡ୍ କରାଯାଇଥିବା ଷ୍ଟ୍ରିଙ୍ଗ୍**: କିଛି UI କମ୍ପୋନେଣ୍ଟରେ (F7/F8) ଅଳ୍ପସଂଖ୍ୟକ ହାର୍ଡକୋଡ୍ ଷ୍ଟ୍ରିଙ୍ଗ୍ ଅଛି, ଯାହା ଏପର୍ଯ୍ୟନ୍ତ i18n କୀ ଦ୍ୱାରା ଅନ୍ତର୍ଭୁକ୍ତ ହୋଇନାହିଁ। ଏଗୁଡ଼ିକୁ i18n ଗ୍ୟାପ୍ ରିପୋର୍ଟରେ ଜଣାଶୁଣା ସୀମାବଦ୍ଧତା ଭାବେ ଡକ୍ୟୁମେଣ୍ଟ କରାଯାଇଛି; ପରବର୍ତ୍ତୀ ପର୍ଯ୍ୟାୟରେ ସେଗୁଡ଼ିକୁ ମାଇଗ୍ରେଟ୍ କରାଯିବ। ପ୍ରଭାବିତ ଷ୍ଟ୍ରିଙ୍ଗ୍ଗୁଡ଼ିକ ହେଉଛି UI ସଜାଣି ଲେବଲ୍, ଯାହାର କାର୍ଯ୍ୟକ୍ଷମ ବ୍ୟବହାର ପାଇଁ ଅନୁବାଦ ଆବଶ୍ୟକ ନାହିଁ।

## §7 ସମସ୍ୟା ସମାଧାନ

### WebSocket ସଂଯୋଗ ବିଚ୍ଛିନ୍ନତା

ଲାଇଭ୍ ଟେଲ୍ରେ "ସଂଯୋଗ ବିଚ୍ଛିନ୍ନ" ଦେଖାଗଲେ:

1. ସର୍ଭର୍ ଏବେ ମଧ୍ୟ ଚାଲୁଛି କି ଯାଞ୍ଚ କରନ୍ତୁ: `GET /api/tools/traffic-inspector/capture-modes`
2. ପୃଷ୍ଠାଟି ପୁନଃଲୋଡ୍ କରନ୍ତୁ — WebSocket ପୁନଃସଂଯୋଗ କରି ଏକ ନୂତନ ସ୍ନାପ୍ଶଟ୍ ଗ୍ରହଣ କରେ
3. ସର୍ଭର୍ ପୁନଃଆରମ୍ଭ ହୋଇଥିଲେ, ଇନ୍-ମେମୋରି ବଫର୍ ସଫା ହୋଇଯାଇଛି — କୌଣସି ସେସନ୍ ରେକର୍ଡ କରାଯାଇନଥିଲେ ପୁରୁଣା ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ଆଉ ଉପଲବ୍ଧ ନାହିଁ

### ପୋର୍ଟ 8080 ଦ୍ୱନ୍ଦ୍ୱ

HTTP_PROXY ମୋଡ୍ ଆରମ୍ଭ ହେବାରେ ବିଫଳ ହେଲେ:

```bash
lsof -i :8080    # ପ୍ରକ୍ରିୟାଟି ଖୋଜନ୍ତୁ
```

ପୋର୍ଟ ପରିବର୍ତ୍ତନ କରନ୍ତୁ:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### ସିଷ୍ଟମ୍ ପ୍ରକ୍ସି ପୂର୍ବାବସ୍ଥାକୁ ଫେରିନାହିଁ

ସିଷ୍ଟମ୍-ବ୍ୟାପୀ ପ୍ରକ୍ସି ମୋଡ୍ ସକ୍ରିୟ ଥିବାବେଳେ OmniRoute କ୍ରାସ୍ ହେଲେ:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

DB ସ୍ଥିତିରୁ ପ୍ରକ୍ସି ସକ୍ରିୟ ଥିବା ଚିହ୍ନଟ ହେଲେ, ପରବର୍ତ୍ତୀ ଥର ଲୋଡ୍ ସମୟରେ ଡ୍ୟାସ୍ବୋର୍ଡ "ସିଷ୍ଟମ୍ ପ୍ରକ୍ସିକୁ ପୂର୍ବାବସ୍ଥାକୁ ଫେରାନ୍ତୁ" ବିକଳ୍ପ ମଧ୍ୟ ପ୍ରଦାନ କରିବ।

### ବଫର୍ ପୂର୍ଣ୍ଣ

ବଫର୍ `INSPECTOR_BUFFER_SIZE` (ଡିଫଲ୍ଟ 1000) ରେ ପହଞ୍ଚିଲେ, ନୂତନ ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ସବୁଠାରୁ ପୁରୁଣା ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ ବାହାର କରିଦିଏ। ଯଦି ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ ଅନୁରୋଧଗୁଡ଼ିକ ହଜିଯାଉଛି:

- `INSPECTOR_BUFFER_SIZE` ବୃଦ୍ଧି କରନ୍ତୁ (ଉଦାହରଣ ସ୍ୱରୂପ, 5000) — ଏହା ଅଧିକ ସମୟ ଧରି ତଥ୍ୟ ରଖିବା ପାଇଁ ଅଧିକ ମେମୋରି ବ୍ୟବହାର କରେ
- ସମ୍ପର୍କିତ ସମୟସୀମାକୁ DB ରେ ସ୍ଥାୟୀ ଭାବେ ରଖିବା ପାଇଁ ଏକ ସେସନ୍ ରେକର୍ଡ କରନ୍ତୁ
