OmniRoute ଏକ WordPress-ଶୈଳୀର ପ୍ଲଗଇନ୍ ସିଷ୍ଟମ୍ ସହିତ ଆସେ। ପ୍ଲଗଇନ୍ଗୁଡ଼ିକ ସ୍ୱୟଂ-ସମ୍ପୂର୍ଣ୍ଣ
ଡିରେକ୍ଟୋରୀ — ପ୍ରତ୍ୟେକରେ ଏକ `plugin.json` ମାନିଫେଷ୍ଟ ଏବଂ ଏକ ଏଣ୍ଟ୍ରି ଫାଇଲ୍ ଥାଏ — ଯାହା
ଅନୁରୋଧ ପାଇପଲାଇନ୍ (`onRequest` / `onResponse` / `onError`) ଏବଂ
ଜୀବନଚକ୍ର ଇଭେଣ୍ଟଗୁଡ଼ିକ (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`) ସହିତ ହୁକ୍ ହୁଏ।

**ପ୍ଲଗଇନ୍ ମାର୍କେଟପ୍ଲେସ୍** ହେଉଛି ସେହି ସିଷ୍ଟମ୍ ଉପରେ ଥିବା ଆବିଷ୍କାର ସ୍ତର। ଏହା
ଇନ୍ଷ୍ଟଲ୍ କରିହେବା ପ୍ଲଗଇନ୍ଗୁଡ଼ିକର ଏକ ବ୍ରାଉଜ୍ଯୋଗ୍ୟ କ୍ୟାଟାଲଗ୍ ପ୍ରଦର୍ଶନ କରେ। ଡିଫଲ୍ଟ ଭାବରେ କ୍ୟାଟାଲଗ୍ଟି
ଏକ ଛୋଟ ବିଲ୍ଟ-ଇନ୍ ସିଡ୍ ରେଜିଷ୍ଟ୍ରି ଅଟେ; ଜଣେ ଅପରେଟର୍ ଏହାକୁ ଏକ କଷ୍ଟମ୍ ରିମୋଟ୍
ରେଜିଷ୍ଟ୍ରି URL ଦିଗରେ ନିର୍ଦ୍ଦେଶ କରିପାରିବେ, ଯେଉଁ କ୍ଷେତ୍ରରେ ଫେଚ୍କୁ ଏକ DNS-ରିଜଲ୍ଭିଂ SSRF ଗାର୍ଡ ଦ୍ୱାରା
ସୁଦୃଢ଼ କରାଯାଏ ([ସୁରକ୍ଷା](#security) ଦେଖନ୍ତୁ)।

ପ୍ରତ୍ୟେକ ପ୍ଲଗଇନ୍ ରୁଟ୍ **କେବଳ ଲୁପ୍ବ୍ୟାକ୍ ପାଇଁ** (ଟିୟର୍ 1 — `LOCAL_ONLY`): ପ୍ଲଗଇନ୍ଗୁଡ଼ିକ ଚାଇଲ୍ଡ ପ୍ରୋସେସ୍ରେ
କୋଡ୍ ଲୋଡ୍ ଏବଂ ନିଷ୍ପାଦନ କରନ୍ତି, ତେଣୁ ପ୍ରମାଣୀକରଣ ନିର୍ବିଶେଷରେ ଏହି ରୁଟ୍ଗୁଡ଼ିକୁ
ଏକ ନନ୍-ଲୁପ୍ବ୍ୟାକ୍ ଅରିଜିନ୍ରୁ ପହଞ୍ଚିହେବ ନାହିଁ। ଦେଖନ୍ତୁ
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)।

## ଏହା Together କିପରି ଫିଟ୍ କରେ।

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **ରେଜିଷ୍ଟ୍ରି ସ୍ତର।** — `src/lib/plugins/marketplace.ts`: କ catalog ଣସି ବିଫଳତା ଉପରେ ମଞ୍ଜି ରେଜିଷ୍ଟ୍ରିକୁ ଖସି, ତାଲିକା / ସନ୍ଧାନ କରେ।
- **ଜୀବନଚକ୍ର ସ୍ତର।** — `src/lib/plugins/manager.ts` (`pluginManager` singleton): ସଂସ୍ଥାପନ, ନବୀକରଣ, ସକ୍ରିୟ, ନିଷ୍କ୍ରିୟ, ଅସଂସ୍ଥାପନ, ସ୍କାନ୍, ଷ୍ଟାର୍ଟଅପ୍ ଲୋଡ୍।
- **ପ୍ରକାଶିତ ସ୍ତର।** — `src/lib/plugins/manifest.ts`: `plugin.json` ପାଇଁ Zod ସ୍କିମା + ଡିଫଲ୍ଟ।
- **ସ୍କାନର୍** — `src/lib/plugins/scanner.ts`: ପ୍ଲଗଇନ୍ ଡିରେକ୍ଟୋରୀ ଅନ୍ତର୍ଗତ ଡିସ୍କରେ ପ୍ଲଗଇନ୍ ଆବିଷ୍କାର କରେ।
- **ଲୋଡର୍** — `src/lib/plugins/loader.ts`: ପ୍ରତ୍ୟେକ ପ୍ଲଗଇନକୁ ଏକ ଅଲଗା Node.js ଶିଶୁ ପ୍ରକ୍ରିୟାରେ ବ aw ାଇଥାଏ ଏବଂ ଦଲାଲମାନେ IPC ଉପରେ ହୁକ୍ କଲ୍ କରନ୍ତି। ପିଲାଟି ଏକ ବାଲୁକା ବାକ୍ସ ନୁହେଁ (ନିମ୍ନରେ "ପ୍ଲଗଇନ୍ ଏକଜେକ୍ୟୁସନ ବିଚ୍ଛିନ୍ନତା" ଦେଖନ୍ତୁ)।

## ମାର୍କେଟପ୍ଲେସ୍ କ୍ୟାଟାଲଗ୍

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) `MarketplaceEntry`
ଅବଜେକ୍ଟଗୁଡ଼ିକର ଏକ ତାଲିକା ଫେରାଏ:

| ଫିଲ୍ଡ         | ପ୍ରକାର   | ଟିପ୍ପଣୀ                                  |
| ------------- | -------- | ---------------------------------------- |
| `name`        | string   | kebab-case ପ୍ଲଗଇନ୍ ନାମ                   |
| `version`     | string   | semver                                   |
| `description` | string   | ସଂକ୍ଷିପ୍ତ ସାରାଂଶ                         |
| `author`      | string   | ଲେଖକ / ସଂଗଠନ                             |
| `license`     | string   | SPDX-ଶୈଳୀର ଲାଇସେନ୍ସ id                   |
| `downloadUrl` | string   | ଉତ୍ସ ଡାଉନ୍ଲୋଡ୍ URL (ଖାଲି ହୋଇପାରେ)        |
| `repository`  | string?  | ଇଚ୍ଛାଧୀନ ରିପୋଜିଟୋରୀ URL                  |
| `tags`        | string[] | ସନ୍ଧାନ/ଫିଲ୍ଟର୍ ଟ୍ୟାଗ୍ଗୁଡ଼ିକ              |
| `downloads`   | number   | ଡାଉନ୍ଲୋଡ୍ ସଂଖ୍ୟା                         |
| `rating`      | number   | 0–5                                      |
| `verified`    | boolean  | ଏଣ୍ଟ୍ରିଟି ଯାଞ୍ଚକୃତ ଭାବେ ଚିହ୍ନିତ କି ନାହିଁ |
| `lastUpdated` | string   | ISO-ସଦୃଶ ତାରିଖ ଷ୍ଟ୍ରିଙ୍ଗ୍                |

ଯେତେବେଳେ କୌଣସି କଷ୍ଟମ୍ ରେଜିଷ୍ଟ୍ରି URL କନଫିଗର୍ ହୋଇନଥାଏ, କ୍ୟାଟାଲଗ୍ଟି ହେଉଛି ବିଲ୍ଟ-ଇନ୍
`SEED_REGISTRY` (ବର୍ତ୍ତମାନ `request-logger`, `rate-limiter`, `cost-tracker`, ଏବଂ
`theme-manager`)। ସିଡ୍ ରେଜିଷ୍ଟ୍ରି ସର୍ବଦା ଉପଲବ୍ଧ — ଯଦି ଏକ କନଫିଗର୍ ହୋଇଥିବା ରିମୋଟ୍
ରେଜିଷ୍ଟ୍ରିକୁ ପହଞ୍ଚିହେବ ନାହିଁ, ଏକ ନନ୍-`200` ଷ୍ଟାଟସ୍ ଫେରାଏ, କିମ୍ବା ଏକ ଅପରିଚିତ
ବଡି ଫେରାଏ, `listMarketplacePlugins()` ଏକ ଚେତାବନୀ ଲଗ୍ କରେ ଏବଂ ସିଡ୍ ତାଲିକାକୁ ଫଲ୍ବ୍ୟାକ୍ କରେ।

> ଟିପ୍ପଣୀ: ମାର୍କେଟପ୍ଲେସ୍ **କ୍ୟାଟାଲଗ୍** (ବ୍ରାଉଜ୍/ସନ୍ଧାନ) ଆରମ୍ଭରୁ ଶେଷ ପର୍ଯ୍ୟନ୍ତ ସଂଯୋଜିତ ହୋଇଛି, କିନ୍ତୁ
> କ୍ୟାଟାଲଗ୍ରୁ ଏକ-କ୍ଲିକ୍ ମାର୍କେଟପ୍ଲେସ୍ **ଇନ୍ଷ୍ଟଲ୍** ଏପର୍ଯ୍ୟନ୍ତ କାର୍ଯ୍ୟକାରୀ କରାଯାଇନାହିଁ —
> ଏକ ମାର୍କେଟପ୍ଲେସ୍ ଏଣ୍ଟ୍ରିରେ ଥିବା ଡ୍ୟାସ୍ବୋର୍ଡର "ଇନ୍ଷ୍ଟଲ୍" ବଟନ୍ ବର୍ତ୍ତମାନ ଏକ
> "ଶୀଘ୍ର ଆସୁଛି" ସୂଚନା ଦେଖାଏ। ବର୍ତ୍ତମାନ ଇନ୍ଷ୍ଟଲେସନ୍ ସ୍ଥାନୀୟ-ପାଥ୍ ଇନ୍ଷ୍ଟଲ୍
> ପ୍ରବାହ (`POST /api/plugins`) ଏବଂ ଅନ୍-ଡିସ୍କ ଆବିଷ୍କାର (`POST /api/plugins/scan`) ମାଧ୍ୟମରେ ହୁଏ।

## REST API

ସମସ୍ତ ଏଣ୍ଡପଏଣ୍ଟଗୁଡିକ ମ୍ୟାନେଜମେଣ୍ଟ auth (`requireManagementAuth`) ଆବଶ୍ୟକ କରେ।** ଏବଂ** କେବଳ ଲୁପବ୍ୟାକ୍-କେବଳ — `/api/plugins` ଏବଂ `/api/plugins/` `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) ରେ ତାଲିକାଭୁକ୍ତ।

| ଶେଷ ପଏଣ୍ଟ।                         | ପଦ୍ଧତି | ବର୍ଣ୍ଣନା                                                                    |
| ---------------------------------- | ------ | --------------------------------------------------------------------------- |
| `/api/plugins`                     | GET    | ସଂସ୍ଥାପିତ ପ୍ଲଗଇନଗୁଡ଼ିକର ତାଲିକା (ଇଚ୍ଛାଧୀନ `?status=` ଫିଲ୍ଟର)                 |

### ଏକ ସ୍ଥାନୀୟ ପଥରୁ ସଂସ୍ଥାପନ କରନ୍ତୁ।

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` ନିଶ୍ଚିତ ଭାବରେ ଏକ ହେବ।** ସଂପୂର୍ଣ୍ଣ** ଏକ ଡିରେକ୍ଟୋରୀକୁ ପଥ** ପ୍ଲଗଇନ୍ ଉତ୍ସ ଡିରେକ୍ଟୋରୀ ଭିତରେ।** : ପ୍ଲଗଇନ୍ ରୁଟ୍ ପାଖରେ `plugin-sources`, ତେଣୁ ଡିଫଲ୍ଟ ଭାବରେ `~/.omniroute/plugin-sources/`, କିମ୍ବା ଯେତେବେଳେ ସେହି ଭେରିଏବଲ୍ ସେଟ୍ ହୁଏ `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` ( `src/lib/plugins/installSource.ts` ରେ`getPluginSourcesDir()` )। ପ୍ରଥମେ ସେଠାରେ ପ୍ଲଗଇନକୁ କପି କିମ୍ବା କ୍ଲୋନ କରନ୍ତୁ। ଯେତେବେଳେ `400` କିମ୍ବା ଏକ ନଲ୍ ବାଇଟ୍ ଧାରଣ କରେ, ସେହି ଡିରେକ୍ଟୋରୀ ବାହାରେ ରହିଥାଏ, ଏକ ସିମ୍ଲିଙ୍କ ମାଧ୍ୟମରେ ଏହାର ସମାଧାନ କରେ, ଏକ ସିମଲିଙ୍କ ଧାରଣ କରେ ଯାହାର ଲକ୍ଷ୍ୟ ଏହା ବାହାରେ, କିମ୍ବା ଯେତେବେଳେ ଡିରେକ୍ଟୋରୀ ନଥାଏ `..` ଉତ୍ସ ଡିରେକ୍ଟୋରୀ ନିଶ୍ଚିତ ଭାବରେ ଏକ ବ valid `plugin.json` ଧାରଣ କରିବ (କିମ୍ବା ଗୋଟିଏର ପିତାମାତା ହେବା ଉଚିତ)। ସଫଳତା ଉପରେ ସଂସ୍ଥାପିତ ପ୍ଲଗଇନ୍ ଧାଡି ସହିତ ପ୍ରତିକ୍ରିୟା ହେଉଛି `201`।

ଅନ୍ୟ ପ୍ଲଗଇନ୍ ରୁଟ୍ ପରି, ଏହା ଏକ ପରିଚାଳନା ପ୍ରମାଣପତ୍ର ଆବଶ୍ୟକ କରେ (ଏକ ଡ୍ୟାସବୋର୍ଡ ଅଧିବେଶନ କିମ୍ବା ଏକ ପରିଚାଳନା-ସ୍କୋପିଡ୍ API କି) ଯେତେବେଳେ ଲଗଇନ୍ ଅକ୍ଷମ ହୋଇଥାଏ (`requireLogin=false`): କୋଡ୍ ସଂସ୍ଥାପନ କରିବା କଦାପି ଅଜ୍ଞାତ କାର୍ଯ୍ୟ ନୁହେଁ। `POST /api/plugins/marketplace/install` (ଶରୀର `{ "name": "<plugin>" }`) ପାଇଁ ମଧ୍ୟ ସମାନ ପ୍ରଯୁଜ୍ୟ।

### ପ୍ଲଗଇନ୍ ବିନ୍ୟାସ ଅଦ୍ୟତନ କରନ୍ତୁ।

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` ପ୍ଲଗଇନ୍ର `configSchema` ( `src/lib/plugins/manifest.ts` `validatePluginConfig()` ଶରୀରକୁ ବ ates ଧ କରେ: ପ୍ରତ୍ୟେକ ଚାବି ଯୋଜନାରେ ଘୋଷିତ ହେବା ଆବଶ୍ୟକ, ମୂଲ୍ୟଗୁଡିକ ଘୋଷିତ ପ୍ରକାର ସହିତ ମେଳ ହେବା ଉଚିତ, `number` କ୍ଷେତ୍ର ସମ୍ମାନ `min`/`max`, ଏବଂ `select` କ୍ଷେତ୍ର ଘୋଷିତ `enum` ସହିତ ମେଳ ହେବା ଜରୁରୀ। ଯେକ Any ଣସି ଉଲ୍ଲଂଘନ `400` ଫେରସ୍ତ କରେ ଏବଂ କିଛି ଗଚ୍ଛିତ ହୁଏ ନାହିଁ। କ z ଣସି `configSchema` ଘୋଷଣା କରୁଥିବା ଏକ ପ୍ଲଗଇନ୍ରେ କ config ଣସି ବିନ୍ୟାସଯୋଗ୍ୟ ଚାବି ନାହିଁ, ତେଣୁ `400` ସହିତ ଅନୁରୋଧକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଇଛି ("ପ୍ଲଗଇନ୍ କ any ଣସି ବିନ୍ୟାସଯୋଗ୍ୟ ଚାବି ଘୋଷଣା କରେ ନାହିଁ")।

## ବିନ୍ୟାସ

### Plugin directory

Plugin ଗୁଡ଼ିକ OmniRoute data directory ଅଧୀନରେ ରହେ:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (କିମ୍ବା manifest.main ଯାହାକୁ ସୂଚାଏ)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ସେହି directory କୁ
ତିନୋଟି ପଦକ୍ଷେପରେ resolve କରେ:

1. **`OMNIROUTE_PLUGINS_DIR`**, ସେଟ୍ ହୋଇଥିଲେ — `HOME` ଯାହା କହୁଥାଉ ନା କାହିଁକି, ଏହାକୁ ଅବିକଳ ଭାବରେ ବ୍ୟବହାର କରାଯାଏ। ଏହା
   Docker/K8s ପାଇଁ ସ୍ପଷ୍ଟ ନିୟନ୍ତ୍ରଣ, ଯେଉଁଠାରେ plugin tree କୁ ଏମିତି ଏକ path ରେ bind-mount କରାଯାଏ
   ଯାହାର ସାଧାରଣତଃ container ର home directory ସହିତ କୌଣସି ସମ୍ପର୍କ ନଥାଏ (#11827)।
2. `<home>/.omniroute/plugins`, ଯେଉଁଠାରେ `<home>` ଟି `HOME` / `USERPROFILE`
   environment variable ରୁ ଆସେ।
3. `/tmp/.omniroute/plugins`, ଯେତେବେଳେ process କୌଣସି home export କରେ ନାହିଁ।

resolve ହୋଇଥିବା directory କୁ startup ସମୟରେ `scanner.dir_resolved` ଭାବରେ ଥରେ log କରାଯାଏ, ଏବଂ
କେଉଁ input ଚୟନ ହେଲା (`OMNIROUTE_PLUGINS_DIR`, `home`, କିମ୍ବା `no-home-fallback`) ତାହା ଉଲ୍ଲେଖ କରାଯାଏ — ତେଣୁ ଏକ image
ନିରବରେ ପଦକ୍ଷେପ 3 ରେ ପହଞ୍ଚିଲେ, କେବଳ ଏକ ଖାଲି plugin ତାଲିକା ରିପୋର୍ଟ କରିବା ପରିବର୍ତ୍ତେ ତାହା ଜଣାଇଦିଏ।
`POST /api/plugins/scan` ସେଠାରେ ଏକ ବୈଧ
`plugin.json` ଥିବା ଯେକୌଣସି subdirectory କୁ ଖୋଜି ପଞ୍ଜୀକୃତ କରେ; ସେହି directory ଟି ମଧ୍ୟ ସେହି root ଯେଉଁଠାକୁ
`pluginManager.install()` plugin ଗୁଡ଼ିକୁ copy କରେ, ତେଣୁ ଏକ override discovery ଏବଂ
installation ଉଭୟକୁ ଏକାସାଙ୍ଗରେ ସ୍ଥାନାନ୍ତର କରେ।

> **`OMNIROUTE_PLUGINS_DIR`, `OMNIROUTE_PLUGIN_PATH` ନୁହେଁ।** ପରବର୍ତ୍ତୀଟିକୁ କେବଳ
> CLI command-plugin loader (`bin/cli/plugins.mjs`) ଦ୍ୱାରା `omniroute` subcommand ଯୋଡ଼ୁଥିବା `omniroute-cmd-*` npm
> package ଖୋଜିବା ପାଇଁ ପଢ଼ାଯାଏ — ଏଠାରେ ବର୍ଣ୍ଣିତ runtime scanner ଉପରେ ଏହାର କୌଣସି ପ୍ରଭାବ ନାହିଁ।
> ସେହି ପକ୍ଷ ପାଇଁ [PLUGINS.md](./PLUGINS.md) ଦେଖନ୍ତୁ।

### Custom marketplace registry URL

marketplace catalog ର source କୁ `pluginMarketplaceUrl` setting ରୁ ପଢ଼ାଯାଏ
(`src/lib/plugins/marketplace.ts` ରେ `settings.pluginMarketplaceUrl` ପଢ଼ାଯାଏ)। ଏହାକୁ
ଏକ `http(s)` URL ରେ ସେଟ୍ କରାଗଲେ, `listMarketplacePlugins()` ସେହି URL କୁ fetch କରେ ଏବଂ
entry ଗୁଡ଼ିକର ଏକ top-level JSON array କିମ୍ବା ଏକ `plugins` array ଥିବା object କୁ ଗ୍ରହଣ କରେ;
string `name` ନଥିବା entry ଗୁଡ଼ିକୁ filter କରି ବାହାର କରାଯାଏ। ସେଟ୍ ହୋଇନଥିଲେ (କିମ୍ବା fetch
SSRF guard ରେ ବିଫଳ ହେଲେ / ଏକ ଖରାପ response ଫେରାଇଲେ), built-in seed registry
ବ୍ୟବହାର କରାଯାଏ।

dashboard ର "Marketplace" tab ଏହି URL ପାଇଁ ଏକ field ପ୍ରଦର୍ଶନ କରେ (`GET /api/settings` ରୁ
ପୁନଃ ପଢ଼ାଯାଏ)।

> କାର୍ଯ୍ୟାନ୍ୱୟନ ଟିପ୍ପଣୀ: dashboard ର "Save" action
> `pluginMarketplaceUrl` କୁ `PATCH /api/settings` ନିକଟକୁ ପଠାଏ। ଲେଖାଯିବା ସମୟରେ ଏହି
> key ଟି `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) ରେ ଘୋଷିତ ହୋଇନାହିଁ, ତେଣୁ ଏହା ଉପରେ ନିର୍ଭର କରିବା ପୂର୍ବରୁ ଆପଣଙ୍କ
> release ରେ persistence ଯାଞ୍ଚ କରନ୍ତୁ — settings
> store ରେ key ଟି ଉପସ୍ଥିତ ହୋଇଗଲେ **read** path (`getSettings()` →
> `listMarketplacePlugins()`) ଏହାକୁ ସମ୍ମାନ କରେ।

### କେବଳ ମାର୍ଗ ସ୍ତର — ଲୁପବ୍ୟାକ୍।

ପ୍ଲଗଇନ୍ଗୁଡ଼ିକ ସ୍ପାଉଡ୍ ଶିଶୁ ପ୍ରକ୍ରିୟାରେ କୋଡ୍ ଏକଜେକ୍ୟୁଟ୍ କରନ୍ତି, ତେଣୁ ସମଗ୍ର `/api/plugins` ପୃଷ୍ଠକୁ `LOCAL_ONLY` (ଟାୟାର୍ 1) ଶ୍ରେଣୀଭୁକ୍ତ କରାଯାଏ। ଲୁପବ୍ୟାକ୍ କାର୍ଯ୍ୟକାରିତା ବିନା ସର୍ତ୍ତରେ ଚାଲିଥାଏ।** ପୂର୍ବରୁ** ଯେକ any ଣସି auth ଯାଞ୍ଚ, ତେଣୁ ଏକ ଟନେଲ ଉପରେ ବାକ୍ସରେ ପହଞ୍ଚୁଥିବା ଏକ ଲିକ୍ ମ୍ୟାନେଜମେଣ୍ଟ ଟୋକେନ୍ ଏକ ପ୍ଲଗଇନ୍ ସଂସ୍ଥାପନ, ସକ୍ରିୟ କିମ୍ବା ସଂସ୍ଥାପନ କରିପାରିବ ନାହିଁ। [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) ଏବଂ ହାର୍ଡ ନିୟମ #15 / #17 ଦେଖନ୍ତୁ।

### ମାର୍କେଟପ୍ଲେସ୍ ରେଜିଷ୍ଟ୍ରି SSRF ଗାର୍ଡ।

ଏକ କଷ୍ଟମ୍ ରେଜିଷ୍ଟ୍ରି URL ହେଉଛି ଆକ୍ରମଣକାରୀ-ପ୍ରଭାବଶାଳୀ ସଂରଚନା, ତେଣୁ ଏହାକୁ ଆଣିବା ପୂର୍ବରୁ `listMarketplacePlugins()` ଏହାକୁ ଦୁଇଟି ସ୍ତର ଦେଇ ଚଲାଇଥାଏ:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` ନୁହେଁ ଯେକ anything ଣସି ଜିନିଷକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ।
   - ଆକ୍ଷରିକ private/loopback/link-local/ULA ହୋଷ୍ଟଗୁଡ଼ିକୁ (IPv4 ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ।** ଏବଂ** IPv6, IPv4-mapped ଅନ୍ତର୍ଭୂକ୍ତ କରି) କାନୋନିକାଲ୍ `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) ମାଧ୍ୟମରେ।
   - ସମାଧାନ କରେ।** ଉଭୟ** `A` ଏବଂ `AAAA` ରେକର୍ଡ କରେ ଏବଂ ଯଦି ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ।** ଯେକ any ଣସି** ସମାଧାନ ହୋଇଥିବା ଠିକଣା ହେଉଛି ବ୍ୟକ୍ତିଗତ — ସର୍ବସାଧାରଣ-ହୋଷ୍ଟନାମ → ବ୍ୟକ୍ତିଗତ- IP ବାଇପାସ୍ ବନ୍ଦ କରିବା।
   - **ବିଫଳ ବନ୍ଦ।** : ଏକ DNS ରେଜୋଲୁସନ ବିଫଳତା URL କୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ।
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): ଆଣିବା ସମୟରେ ସର୍ବସାଧାରଣ-କେବଳ URL ଗାର୍ଡକୁ ପୁନ-ପ୍ରୟୋଗ କରେ ଏବଂ।** ପୁନ ir ନିର୍ଦ୍ଦେଶକୁ ଅବରୋଧ କରେ।** (କ public ଣସି ସାର୍ବଜନୀନ → ବ୍ୟକ୍ତିଗତ `30x` pivot ନାହିଁ)।

ଏକ URL ଯାହା ଉଭୟ ସ୍ତରରେ ବିଫଳ ହୁଏ — ଅନୁରୋଧକୁ ପରିତ୍ୟାଗ କରେ ନାହିଁ ମାର୍କେଟପ୍ଲେସ୍ ଚୁପଚାପ୍ ବିଲ୍ଟ-ଇନ୍ ବିହନ ରେଜିଷ୍ଟ୍ରିକୁ ଫେରିଯାଏ ଏବଂ ଏକ ଚେତାବନୀ ଲଗ୍ କରେ।

> ଏହି ରାକ୍ଷୀ PR #3774 ରେ ବିଶେଷ ଭାବରେ A + AAAA ସମାଧାନ କରିବା ଏବଂ IPv4-only ଯାଞ୍ଚ ପରିବର୍ତ୍ତେ କାନୋନିକାଲ୍ `isPrivateHost` ବ୍ୟବହାର କରିବା ପାଇଁ କଠିନ କରାଯାଇଥିଲା।

### ପ୍ଲଗଇନ୍ ଏକଜେକ୍ୟୁଶନ୍ ବିଚ୍ଛିନ୍ନତା।

> **ଡିଫଲ୍ଟ ଭାବରେ ପ୍ଲଗଇନଗୁଡିକ ବାଲୁକା ବାକ୍ସ ନୁହେଁ।** ପିଲାଟି ହେଉଛି OmniRoute ବ୍ୟବହାରକାରୀ ଭାବରେ ଚାଲୁଥିବା ଏକ ସାଧାରଣ Node.js ପ୍ରକ୍ରିୟା, ଏଥିରେ VM ପ୍ରସଙ୍ଗ ନାହିଁ ଏବଂ Node.js ଅନୁମତି ପତାକା ନାହିଁ, ତେଣୁ ପ୍ଲଗଇନ୍ କୋଡ୍ ଯେକ file ଣସି ଫାଇଲ ପ read ିପାରେ ଏବଂ ଲେଖିପାରେ ଯାହା ଉପଭୋକ୍ତା, ପ୍ରୋଗ୍ରାମ ଚଳାଇ ପାରିବେ ଏବଂ ନେଟୱାର୍କରେ ପହଞ୍ଚି ପାରିବେ। `requires.permissions` କେବଳ ସ୍ଥିର କରେ ପିଲା କେଉଁ ପରିବେଶ ଭେରିଏବଲ୍ ଗ୍ରହଣ କରେ; ଅନ୍ୟ ଅନୁମତିଗୁଡିକ ବାଧ୍ୟତାମୂଳକ ନୁହେଁ। ଅପ୍ଟ-ଇନ୍ `PLUGIN_PERMISSION_MODEL_ENABLED` feature ଶିଷ୍ଟ୍ୟ ଫ୍ଲାଗ୍ (ଡିଫଲ୍ଟ ଭାବରେ ଅଫ୍) ସେହି ଅନୁମତିଗୁଡ଼ିକରୁ ନିର୍ମିତ Node.js ଅନୁମତି ମଡେଲ ଅନ୍ତର୍ଗତ ପ୍ରତ୍ୟେକ ପ୍ଲଗଇନ୍ ଚଲାଇଥାଏ, `network` ବ୍ୟତୀତ, ଯାହାକି Node.js ପ୍ରତିବନ୍ଧକ କରିପାରିବ ନାହିଁ ( [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#%E0%AC%85%E0%AC%A8%E0%AD%81%E0%AC%AE%E0%AC%A4%E0%AC%BF-%E0%AC%AC%E0%AD%8D%E0%AD%9F%E0%AC%AC%E0%AC%B8%E0%AD%8D%E0%AC%A5%E0%AC%BE) ଦେଖନ୍ତୁ)। ଆପଣ ବିଶ୍ trust ାସ କରୁଥିବା କେବଳ ପ୍ଲଗଇନ୍ ସଂସ୍ଥାପନ କରନ୍ତୁ। ନିମ୍ନରେ ପ୍ରକ୍ରିୟା ସୀମା କ୍ରାସ୍ ଏବଂ ହ୍ୟାଙ୍ଗ୍ ଧାରଣ କରେ; ଏହା ଏକ ସୁରକ୍ଷା ସୀମା ନୁହେଁ।

- **ବିଚ୍ଛିନ୍ନ ପ୍ରକ୍ରିୟା।** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ପ୍ରତ୍ୟେକ ପ୍ଲଗଇନକୁ ଏକ ପୃଥକ Node.js ଶିଶୁ ପ୍ରକ୍ରିୟାରେ ସ୍ପାଉନ୍ କରେ ଏବଂ IPC ଉପରେ ଯୋଗାଯୋଗ କରେ। `SIGTERM` → `SIGKILL` ଏସ୍କାଲେସନ୍ ସହିତ ହୁକ୍ କଲଗୁଡିକର ଏକ ସମୟ ସମାପ୍ତ ଅଛି।
- **Env ଅନୁମତି ତାଲିକା।** — ପିଲାଟି କେବଳ ପରିବେଶ ଭେରିଏବଲ୍ସର ଏକ ଅନୁମତିପ୍ରାପ୍ତ ତାଲିକା ଗ୍ରହଣ କରେ। ବିସ୍ତୃତ ସେଟ୍ କେବଳ ମଞ୍ଜୁର ହୁଏ ଯେତେବେଳେ `env` ଅନୁମତି ମାଗେ।
- **ଉତ୍ସ ଧାରଣ ସଂସ୍ଥାପନ କରନ୍ତୁ।** — `POST /api/plugins` କେବଳ ପ୍ଲଗଇନ୍ ଉତ୍ସ ଡିରେକ୍ଟୋରୀରୁ ପ read ଼ିଥାଏ (“ଏକ ସ୍ଥାନୀୟ ପଥରୁ ସଂସ୍ଥାପନ” କୁ ଦେଖନ୍ତୁ): ପଥଟି `realpath` ସହିତ କାନୋନିକାଲ୍ ହୋଇଛି, ନିଶ୍ଚିତ ଭାବରେ ସେହି ଡିରେକ୍ଟୋରୀ ଭିତରେ ରହିବା ଆବଶ୍ୟକ, ଏବଂ ଏକ ସିମ୍ଲିଙ୍କ୍ ନେଇଥିବା ଏକ ଉତ୍ସ ଗଛ ଯାହାକି କପି ହେବା ପୂର୍ବରୁ ଏହାକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଇଥାଏ।
- **ପଥ ଧାରଣ** — install/upgrade/uninstall ନିଶ୍ଚିତ କରେ ଯେ ପ୍ଲଗଇନ୍ ଡିରେକ୍ଟୋରୀ ଏବଂ `manifest.main` ସମାଧାନ କରେ।** ଭିତରେ** ଯେକ copy ଣସି କପି କିମ୍ବା ପୁନରାବୃତ୍ତି ବିଲୋପ ପୂର୍ବରୁ ପରିଚାଳିତ ପ୍ଲଗଇନ୍ ରୁଟ୍ ( `manifest.main` ରେ tqered DB ପଥ ଏବଂ `../` ଟ୍ରାଭର୍ସାଲ୍ ବିରୁଦ୍ଧରେ ରାକ୍ଷୀ)। ଆକ୍ଟିଭେସନ୍ `realpath` ମାଧ୍ୟମରେ ସିମଲିଙ୍କ୍କୁ ସମାଧାନ କରେ ଏବଂ ପ୍ଲଗଇନ୍ ଡିରେକ୍ଟୋରୀରୁ ରକ୍ଷା ପାଇଥିବା ଏକ ଏଣ୍ଟ୍ରି ପଏଣ୍ଟ ଲୋଡ୍ କରିବାକୁ ମନା କରେ।
- **ବ tion କଳ୍ପିକ ଅଖଣ୍ଡତା ପିନ୍।** — ଏକ ମନିଫେଷ୍ଟ୍ ଏକ `integrity` (`sha256-<base64>`, SRI ଫର୍ମାଟ୍) କ୍ଷେତ୍ର ଘୋଷଣା କରିପାରେ। ଉପସ୍ଥିତ ଥିବାବେଳେ, ଲୋଡର୍ ଲୋଡ୍ ସମୟରେ ଏଣ୍ଟ୍ରି ଫାଇଲ୍ ହ୍ୟାସ୍ ଯାଞ୍ଚ କରେ ଏବଂ ମେଳ ଖାଇବାରେ ସକ୍ରିୟ ହେବାକୁ ମନା କରେ। ଏହା ଅପ୍ଟ-ଇନ୍ ଟ୍ୟାମ୍ପର-ଚିହ୍ନଟ,** ନୁହେଁ।** ଏକ ସୁରକ୍ଷା ସୀମା: ଏକ ଲୋଡ୍ ପ୍ଲଗଇନ୍ କ’ଣ କରିପାରିବ ତାହା ସୀମିତ କରେ ନାହିଁ।
- **ହୁକ୍ ରେ କ client ଣସି ଗ୍ରାହକ ପରିଚୟପତ୍ର ନାହିଁ।** — ପ୍ରସଙ୍ଗ `onRequest` କୁ ପଠାଗଲା, `onResponse` ଏବଂ `onError` `authorization`, `x-api-key`, `proxy-authorization` ଏବଂ `cookie` ହେଡର୍ ଅପସାରିତ ହୋଇଛି, ଏବଂ API କି ରେକର୍ଡ କ key ଣସି ମୁଖ୍ୟ ମୂଲ୍ୟ ଧାରଣ କରେ ନାହିଁ ( `src/lib/plugins/hooks.ts` ରେ`redactPluginContext()` )।

| `integrity`        | ଷ୍ଟ୍ରିଙ୍ଗ୍?   | ବ z କଳ୍ପିକ `sha256-<base64>` ଏଣ୍ଟ୍ରି-ଫାଇଲ୍ ପିନ୍।                      |

Enum `network` / `file-read` / `file-write` / `env` / `exec` ରୁ ଅନୁମତି ଅଙ୍କିତ। କେବଳ `env` ଚାଲିବା ସମୟ ପ୍ରଭାବ ଅଛି (ପିଲାଙ୍କ ପାଇଁ ଟିକିଏ ବଡ଼ ପରିବେଶ-ପରିବର୍ତ୍ତନଶୀଳ ଅନୁମତି ତାଲିକା); ଅନ୍ୟମାନେ ଘୋଷଣାନାମା ଏବଂ ବାଧ୍ୟତାମୂଳକ ନୁହେଁ।

## ଜୀବନଚକ୍ର ପ୍ରବାହ

```
install (POST /api/plugins, ପଥ)
  → manifest ସ୍କାନ୍/ବୈଧତା ଯାଞ୍ଚ → stagingକୁ କପି → main ଡିରେକ୍ଟୋରୀ ଭିତରେ ଥିବା ସୁନିଶ୍ଚିତ କରନ୍ତୁ
  → ପରମାଣବିକ ଭାବେ ~/.omniroute/plugins/<name>କୁ ନାମ ପରିବର୍ତ୍ତନ → DB ଧାଡ଼ି ଯୋଡ଼ନ୍ତୁ
  → onInstall ଚାଲୁ କରନ୍ତୁ → enabledByDefault ହେଲେ: ସକ୍ରିୟ କରନ୍ତୁ

activate (POST /api/plugins/{name}/activate)
  → realpath ସୀମାବଦ୍ଧତା ଯାଞ୍ଚ → loadPlugin() (child process ଆରମ୍ଭ କରନ୍ତୁ)
  → ଘୋଷିତ hooks ପଞ୍ଜୀକରଣ କରନ୍ତୁ → status = "active" → onActivate ଚାଲୁ କରନ୍ତୁ

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate ଚାଲୁ କରନ୍ତୁ (ପଞ୍ଜୀକରଣ ରଦ୍ଦ କରିବା ପୂର୍ବରୁ) → hooksର ପଞ୍ଜୀକରଣ ରଦ୍ଦ କରନ୍ତୁ
  → child process ବନ୍ଦ କରନ୍ତୁ → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → ସକ୍ରିୟ ଥିଲେ deactivate କରନ୍ତୁ → onUninstall ଚାଲୁ କରନ୍ତୁ
  → ସୀମାବଦ୍ଧତା-ଯାଞ୍ଚ ସହିତ plugin ଡିରେକ୍ଟୋରୀକୁ ପୁନରାବର୍ତ୍ତୀ ଭାବେ ଅପସାରଣ କରନ୍ତୁ → DB ଧାଡ଼ି ବିଲୋପ କରନ୍ତୁ
```

ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିବା ସଂସ୍କରଣଠାରୁ ଯେଉଁ ଡିରେକ୍ଟୋରୀର manifest ସଂସ୍କରଣ **କଠୋର ଭାବେ
ନୂତନ**, ସେହି ଡିରେକ୍ଟୋରୀ ଉପରେ `install` ପୁଣି ଚଲାଇଲେ ସ୍ୱୟଂଚାଳିତ ଭାବେ ଅପଗ୍ରେଡ୍ ହୁଏ (ସ୍ୱଚ୍ଛ ପୁନଃ-ଇନ୍ଷ୍ଟଲ୍; config
ଡିଫଲ୍ଟ ମୂଲ୍ୟକୁ ପୁନଃସେଟ୍ ହୁଏ)। ସମାନ କିମ୍ବା ପୁରୁଣା ସଂସ୍କରଣ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ।

## ଡ୍ୟାସବୋର୍ଡ।

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) ରେ ଥିବା ଡ୍ୟାସବୋର୍ଡ ପୃଷ୍ଠା ଦୁଇଟି ଟ୍ୟାବ୍ ପ୍ରଦାନ କରେ:

- **ସଂସ୍ଥାପିତ।** — ସେମାନଙ୍କର ଘୋଷିତ ହୁକ୍, ଏକ activate/deactivate ଟୋଗଲ୍, ଏକ ଅସଂସ୍ଥାପନ ବଟନ୍ ଏବଂ “ପ୍ଲଗଇନ୍ ପାଇଁ ସ୍କାନ୍” କାର୍ଯ୍ୟ (`POST /api/plugins/scan`) ସହିତ ସଂସ୍ଥାପିତ ପ୍ଲଗଇନଗୁଡ଼ିକୁ ତାଲିକାଭୁକ୍ତ କରେ।
- **ମାର୍କେଟପ୍ଲେସ୍।** — କଷ୍ଟମ୍ ରେଜିଷ୍ଟ୍ରି URL ସେଟ୍ କରିବାକୁ ଏକ ଫିଲ୍ଡ ସହିତ `GET /api/plugins/marketplace` ରୁ କାଟାଲଗ୍ ଦେଖାଏ।

ପୃଷ୍ଠା ସର୍ବଦା ଏକ ଚେତାବନୀ ଦେଖାଏ ଯେ OmniRoute ପ୍ରକ୍ରିୟାର ପୂର୍ଣ୍ଣ ଅଧିକାର ସହିତ ପ୍ଲଗଇନ୍ ଚାଲିଥାଏ।

ଏକ ପ୍ଲଗଇନ୍ ବିନ୍ୟାସ ପୃଷ୍ଠା `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) ରେ ରୁହେ।
