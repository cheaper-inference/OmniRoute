AgentBridge ହେଉଛି OmniRouteର MITM (Man-in-the-Middle) ପ୍ରକ୍ସି, ଯାହା IDE AI ଏଜେଣ୍ଟଗୁଡ଼ିକର HTTPS ଟ୍ରାଫିକ୍କୁ ଅବରୋଧ କରି OmniRouteର ଏକୀକୃତ ରାଉଟିଂ ଇଞ୍ଜିନ୍ ମାଧ୍ୟମରେ ପୁନଃରାଉଟ୍ କରେ। ଏହା **10ଟି IDE ଏଜେଣ୍ଟ** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code, ଏବଂ Trae (ଅନୁସନ୍ଧାନାଧୀନ) — କୁ ସମର୍ଥନ କରେ, ଯାହା OmniRouteକୁ ବଜାରରେ AI କୋଡିଂ ସହାୟକମାନଙ୍କ ପାଇଁ ସର୍ବାଧିକ ବ୍ୟାପକ କଭରେଜ୍ ଥିବା MITM ପ୍ରକ୍ସି କରିଥାଏ।

**ଡ୍ୟାସବୋର୍ଡ ଅବସ୍ଥାନ:** `/dashboard/tools/agent-bridge`
**ସାଇଡ୍ବାର୍ ଗୋଷ୍ଠୀ:** ଟୁଲ୍ଗୁଡ଼ିକ (Cloud Agents ପରେ)
**ଏହା ମଧ୍ୟ ଦେଖନ୍ତୁ:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — ଅବରୋଧ କରାଯାଇଥିବା ସମସ୍ତ ଟ୍ରାଫିକ୍କୁ ରିୟଲ୍-ଟାଇମ୍ରେ ନିରୀକ୍ଷଣ କରନ୍ତୁ; `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs`ରେ କମ୍ପାଇଲ୍ ହୋଇନାହିଁ) — `/api/tools/agent-bridge/tproxy` ରୁଟ୍ ଦ୍ୱାରା ପରିଚାଳିତ Linux TPROXY ସ୍ୱଚ୍ଛ-ଡିକ୍ରିପ୍ଟ କ୍ୟାପ୍ଚର୍ ମୋଡ୍।

## §1 ସାରାଂଶ

### AgentBridge କ'ଣ?

ଯେତେବେଳେ ଏକ IDE ଏଜେଣ୍ଟ (ଯେପରିକି GitHub Copilot, Cursor, Claude Code) କୌଣସି API କଲ୍ କରେ, ଏହା ସିଧାସଳଖ ଅପଷ୍ଟ୍ରିମ୍ AI ପ୍ରୋଭାଇଡର (OpenAI, Anthropic ଇତ୍ୟାଦି) ସହିତ ସଂଯୋଗ କରେ। AgentBridge ସେହି ସଂଯୋଗକୁ TLS ସ୍ତରରେ ସ୍ୱଚ୍ଛ ଭାବରେ ଅଟକାଇଥାଏ — କୌଣସି ଏଜେଣ୍ଟ କନଫିଗରେସନ୍ ପରିବର୍ତ୍ତନ ଆବଶ୍ୟକ ନ କରି — ଏବଂ ଅନୁରୋଧକୁ OmniRoute ମାଧ୍ୟମରେ ପୁନର୍ଲେଖନ କରିଥାଏ।

ଏହାର ଅର୍ଥ ଆପଣ କରିପାରିବେ:

- **ଯେକୌଣସି ଏଜେଣ୍ଟକୁ ଯେକୌଣସି ପ୍ରୋଭାଇଡରକୁ ପୁନଃନିର୍ଦ୍ଦେଶ କରନ୍ତୁ**: Copilot OpenAI ସହ କଥା ହେଉଛି କି? ଏହାକୁ Anthropic Claude, Gemini କିମ୍ବା OmniRoute ର 375 ପ୍ରୋଭାଇଡର ମଧ୍ୟରୁ ଯେକୌଣସିକୁ ପୁନଃନିର୍ଦ୍ଦେଶ କରନ୍ତୁ।
- **ମଡେଲ୍ ମ୍ୟାପିଂ ପ୍ରୟୋଗ କରନ୍ତୁ**: `gemini-3-flash` → `claude-sonnet-4.7` ହ୍ୟାଣ୍ଡଲର ସ୍ତରରେ ସ୍ୱଚ୍ଛ ଭାବରେ।
- **ସମସ୍ତ ଏଜେଣ୍ଟ ଟ୍ରାଫିକ୍ ଦେଖନ୍ତୁ**: ପ୍ରତ୍ୟେକ ଅଟକାଯାଇଥିବା ଅନୁରୋଧ [ଟ୍ରାଫିକ୍ ଇନ୍ସପେକ୍ଟର](./TRAFFIC_INSPECTOR.md)କୁ ପ୍ରକାଶିତ ହୁଏ।
- **OmniRoute ସ୍ଥିରତା ପ୍ରୟୋଗ କରନ୍ତୁ**: କମ୍ବୋ ରାଉଟିଂ, ସର୍କିଟ ବ୍ରେକର, ଫଲବ୍ୟାକ ଏବଂ ଖର୍ଚ୍ଚ ଟ୍ରାକିଂ IDE ଏଜେଣ୍ଟ ଟ୍ରାଫିକ୍ ପାଇଁ ମଧ୍ୟ କାମ କରେ।

## §2 ସ୍ଥାପତ୍ୟ

### 2.1 ଉପାଦାନଗୁଡ଼ିକର ସାରାଂଶ

```
IDE ଏଜେଣ୍ଟ (VS Code / Cursor / ଇତ୍ୟାଦି)
    │  HTTPS (ପୋର୍ଟ 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS ପୁନଃନିର୍ଦ୍ଦେଶନ
    │
    ▼
src/mitm/server.cjs  (ପୋର୍ଟ 443, CJS ଚାଇଲ୍ଡ ପ୍ରକ୍ରିୟା)
    │  Host ହେଡର୍ SNI ଦ୍ୱାରା ଲକ୍ଷ୍ୟ ନିର୍ଦ୍ଧାରଣ କରେ
    │  AgentBridge CA ଦ୍ୱାରା ସ୍ୱାକ୍ଷରିତ ପ୍ରତି-SNI TLS ପ୍ରମାଣପତ୍ର ସୃଷ୍ଟି କରେ
    ├── ବାଇପାସ୍ ତାଲିକା ସହ ମେଳ? → TCP ପାସ୍ଥ୍ରୁ (ଡିକ୍ରିପ୍ସନ୍ ନାହିଁ)
    ├── ଲକ୍ଷ୍ୟ ସହ ମେଳ? → fetch → OmniRoute ରାଉଟର୍ (ପୋର୍ଟ 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── ଅନୁରୋଧର ବଡି/ହେଡର୍ଗୁଡ଼ିକରେ maskSecrets()
    │               ├── TrafficBuffer.push() — Traffic Inspectorକୁ ପ୍ରକାଶ କରେ
    │               └── fetchRouter() → /v1/chat/completions
    └── କୌଣସି ମେଳ ନାହିଁ? → TCP ପାସ୍ଥ୍ରୁ (ଡିକ୍ରିପ୍ସନ୍ ନାହିଁ)
```

### 2.2 MITM ସର୍ଭର୍ (`src/mitm/server.cjs`)

ମୂଳ MITM ସର୍ଭର୍ଟି ଏକ Node.js CJS ଚାଇଲ୍ଡ ପ୍ରକ୍ରିୟା ଭାବରେ ଚାଲେ (ବିଦ୍ୟମାନ CJS କୋଡ୍ବେସ୍କୁ ପୁନଃଲିଖନ କରିବାରୁ ରକ୍ଷା ପାଇବା ପାଇଁ)। ଏହା:

- ପୋର୍ଟ 443ରେ ଶୁଣେ (`authbind`/`setcap` କିମ୍ବା ବିଶେଷାଧିକାର ଆବଶ୍ୟକ)
- OSରୁ CONNECT ଟନେଲ୍ଗୁଡ଼ିକ ଗ୍ରହଣ କରେ (`/etc/hosts` DNS ପୁନଃନିର୍ଦ୍ଦେଶନ ମାଧ୍ୟମରେ)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) ଦ୍ୱାରା ସ୍ୱାକ୍ଷରିତ ପ୍ରତି-SNI TLS ପ୍ରମାଣପତ୍ର ସୃଷ୍ଟି କରେ
- `targets/index.ts` ରେଜିଷ୍ଟ୍ରି ମାଧ୍ୟମରେ Host ହେଡର୍ ଅନୁସାରେ ଲକ୍ଷ୍ୟ ଏଜେଣ୍ଟ ନିର୍ଦ୍ଧାରଣ କରେ
- HTTP ମାଧ୍ୟମରେ `http://127.0.0.1:20128`କୁ TypeScript ହ୍ୟାଣ୍ଡଲର୍ ସ୍ତରକୁ ପ୍ରେରଣ କରେ

`TARGET_HOSTS`, `DATA_DIR/mitm/targets.json`ରୁ ଲୋଡ୍ ହୁଏ (ବୁଟ୍ ସମୟରେ `targets/index.ts` ଦ୍ୱାରା ଲିଖିତ), ଯାହା CJS ସର୍ଭର୍କୁ ପୁନଃଚାଳନ ନକରି ଡାଇନାମିକ୍ ଅପଡେଟ୍କୁ ସମ୍ଭବ କରେ।

> **ରୁଟ୍-CA ମଡେଲ୍ (#6684)।** ଉପରେ ଥିବା ଏକ CA ଦ୍ୱାରା ସ୍ୱାକ୍ଷରିତ ପ୍ରତି-SNI-ପ୍ରମାଣପତ୍ର ବିବରଣୀ
> ହେଉଛି #6684ରେ ଯୋଡ଼ାଯାଇଥିବା ସ୍ଥାୟୀ ରୁଟ୍-CA ମଡେଲ୍ (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, `src/mitm/tproxy/dynamicCert.ts`ରେ TPROXY ପାଇଁ
> ପୂର୍ବରୁ ପ୍ରମାଣିତ CA/ଲିଫ୍ କ୍ରିପ୍ଟୋକୁ ପୁନଃବ୍ୟବହାର କରି) — ଏହା ଅପେକ୍ଷାକୃତ ପୁରୁଣା
> ଏକକ ସ୍ଥିର ସ୍ୱ-ସ୍ୱାକ୍ଷରିତ ଲିଫ୍କୁ (`src/mitm/cert/generate.ts`, ଯାହା ଏବେ ମଧ୍ୟ
> କେବଳ antigravity ହୋଷ୍ଟଗୁଡ଼ିକ ପର୍ଯ୍ୟନ୍ତ ସୀମିତ) ପ୍ରତିସ୍ଥାପନ କରେ, ଯାହାକୁ ଡିସ୍କରେ ଥିବା
> ଏକ ସାଧାରଣ `server.crt`/`server.key` ଯୁଗଳ ସୂଚାଇଥାଏ। **ମାଇଗ୍ରେସନ୍ ଆଚରଣ**: ଏକ ନୂତନ
> ଇନ୍ଷ୍ଟଲେସନ୍ (ପୂର୍ବରୁ `server.crt` ନଥିବା) ସ୍ୱୟଂଚାଳିତ ଭାବରେ ରୁଟ୍-CA ମଡେଲ୍ ପାଏ; ପୁରୁଣା
> ସ୍ଥିର ଲିଫ୍କୁ ପୂର୍ବରୁ ବିଶ୍ୱସ୍ତ କରିଥିବା ଏକ ଇନ୍ଷ୍ଟଲେସନ୍, ଅପରେଟର୍
> `MITM_ROOT_CA_ENABLED=true` ସେଟ୍ କରି ବ୍ରିଜ୍ଟିକୁ ପୁନଃଚାଳନ ନକରିବା ପର୍ଯ୍ୟନ୍ତ ତାହାକୁ
> ବ୍ୟବହାର କରିଚାଲେ (`src/mitm/cert/migration.ts` ହେଉଛି ଶୁଦ୍ଧ ନିଷ୍ପତ୍ତି ଫଙ୍କସନ୍ — **ଯେକୌଣସି**
> ହୋଷ୍ଟ ପାଇଁ ଏକ ଲିଫ୍କୁ ସ୍ୱାକ୍ଷର କରିପାରୁଥିବା ବିଶ୍ୱସ୍ତ MITM CA, ପୁରୁଣା ସ୍ଥିର-SAN ଲିଫ୍ଠାରୁ
> ବାସ୍ତବରେ ଅଧିକ ଶକ୍ତିଶାଳୀ, ତେଣୁ ପୂର୍ବରୁ ବିଶ୍ୱସ୍ତ ଇନ୍ଷ୍ଟଲେସନ୍ ପାଇଁ ଏହି ପରିବର୍ତ୍ତନ କେବେବି
> ନିରବରେ ହୁଏ ନାହିଁ)। CA ପ୍ରମାଣପତ୍ରଟି ପୁରୁଣା ଲିଫ୍ ବ୍ୟବହାର କରୁଥିବା ସେହି
> `omniroute-mitm.crt` ଟ୍ରଷ୍ଟ-ଷ୍ଟୋର୍ ସ୍ଲଟ୍ରେ ଇନ୍ଷ୍ଟଲ୍ ହୁଏ
> (`cert/install.ts::installCaCert`) — ଦ୍ୱୈତ-ବିଶ୍ୱାସ ସଫେଇର ଆବଶ୍ୟକତା ନାହିଁ।

### 2.3 ହ୍ୟାଣ୍ଡଲର୍ ବେସ୍ (`src/mitm/handlers/base.ts`)

ସମସ୍ତ ଏଜେଣ୍ଟ ହ୍ୟାଣ୍ଡଲର୍ `MitmHandlerBase`କୁ ବିସ୍ତାର କରନ୍ତି:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // ସୁରକ୍ଷିତ ସହାୟକଗୁଡ଼ିକ: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

ପ୍ରତ୍ୟେକ ହ୍ୟାଣ୍ଡଲର୍ ପ୍ରକ୍ସି କରିବା ପୂର୍ବରୁ `hookBufferStart()` ଏବଂ ସମାପ୍ତ ହେଲେ `hookBufferUpdate()`କୁ କଲ୍ କରେ। ଏଗୁଡ଼ିକ `InterceptedRequest` ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ `globalTrafficBuffer` ଭିତରକୁ ପୁଶ୍ କରେ ([Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4 ଦେଖନ୍ତୁ)।

### 2.4 ଲକ୍ଷ୍ୟ ରେଜିଷ୍ଟ୍ରି (`src/mitm/targets/`)

ପ୍ରତ୍ୟେକ ଏଜେଣ୍ଟର ଏକ ଘୋଷଣାତ୍ମକ ଲକ୍ଷ୍ୟ ଫାଇଲ୍ ଅଛି:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

ରେଜିଷ୍ଟ୍ରିଟି (`targets/index.ts`) `ALL_TARGETS` ଏକ୍ସପୋର୍ଟ କରେ ଏବଂ ବୁଟ୍ ସମୟରେ `DATA_DIR/mitm/targets.json` ନିର୍ଗତ କରେ।

### 2.5 ପାସ୍ଥ୍ରୁ ଏବଂ ବାଇପାସ୍ ତାଲିକା (`src/mitm/passthrough.ts`)

**ବାଇପାସ୍ ତାଲିକା** (ପ୍ରଥମେ ଯାଞ୍ଚ କରାଯାଏ, ଲକ୍ଷ୍ୟ ମେଳ ଉପରେ ପ୍ରାଧାନ୍ୟ ସହିତ):

- ଡିଫଲ୍ଟ ପ୍ୟାଟର୍ନ୍ଗୁଡ଼ିକ: ବ୍ୟାଙ୍କିଂ ହୋଷ୍ଟ, `.gov.`, OAuth/SSO ପ୍ରଦାନକାରୀ (Okta, Auth0), ଇତ୍ୟାଦି।
- ବ୍ୟବହାରକାରୀ ପ୍ୟାଟର୍ନ୍ଗୁଡ଼ିକ: DB ଟେବୁଲ୍ `agent_bridge_bypass`ରେ ସଞ୍ଚିତ
- ବାଇପାସ୍ ହୋଇଥିବା ହୋଷ୍ଟଗୁଡ଼ିକ ଏକ ସ୍ୱଚ୍ଛ TCP ଟନେଲ୍ ପାଆନ୍ତି — TLSକୁ **କେବେବି ଡିକ୍ରିପ୍ଟ କରାଯାଏ ନାହିଁ**

**ପାସ୍ଥ୍ରୁ ଡିଫଲ୍ଟ** (କୌଣସି ଲକ୍ଷ୍ୟ ମେଳ ନାହିଁ ଏବଂ ବାଇପାସ୍ରେ ନାହିଁ):

- ଏକ TCP ଟନେଲ୍ ମଧ୍ୟ ପାଏ — ସଂଯୋଗଗୁଡ଼ିକ କେବେବି ବିଚ୍ଛିନ୍ନ ହୁଏ ନାହିଁ
- AgentBridgeକୁ ସାଧାରଣ ସିଷ୍ଟମ୍ HTTPS ଟ୍ରାଫିକ୍ରେ ବାଧା ସୃଷ୍ଟି କରିବାରୁ ରୋକେ

ରାଉଟିଂ ପ୍ରାଧାନ୍ୟ:

```
ବାଇପାସ୍ ତାଲିକା → ଲକ୍ଷ୍ୟ ମେଳ → ପାସ୍ଥ୍ରୁ
```

### 2.6 ଅପ୍ଷ୍ଟ୍ରିମ୍ CA ପ୍ରମାଣପତ୍ର (`src/mitm/upstreamTrust.ts`)

ଏକ କଷ୍ଟମ୍ CA ଥିବା କର୍ପୋରେଟ୍ ନେଟ୍ୱର୍କ ପରିବେଶ ପାଇଁ:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

ସେଟ୍ କରାଗଲେ, ଏହା ଅତିରିକ୍ତ CA ପ୍ରମାଣପତ୍ର ସହିତ `undici`ର ଗ୍ଲୋବାଲ୍ ଡିସ୍ପ୍ୟାଚର୍କୁ ବିନ୍ୟାସ କରେ, ଯାହା AgentBridgeକୁ କର୍ପୋରେଟ୍ TLS ଟର୍ମିନେସନ୍ ପ୍ରକ୍ସି ମାଧ୍ୟମରେ ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରଦାନକାରୀଙ୍କ ପାଖକୁ ପହଞ୍ଚିବାରେ ସକ୍ଷମ କରେ।

### 2.7 ଗୁପ୍ତ ତଥ୍ୟ ମାସ୍କିଂ (`src/mitm/maskSecrets.ts`)

ସ୍ୱାଧୀନ କ୍ଲିନ୍-ରୁମ୍ ସ୍କାନର୍ଟି ଅନୁରୋଧ ବଡି ଏବଂ କ୍ରେଡେନ୍ସିଆଲ୍ ହେଡର୍ଗୁଡ଼ିକ
Traffic Inspector ବଫର୍ କିମ୍ବା କୌଣସି ଲଗ୍ରେ ପ୍ରବେଶ କରିବା **ପୂର୍ବରୁ** ପ୍ରୟୋଗ କରାଯାଏ। ଏହା ଗୋଟିଏ ରୈଖିକ ପାସ୍ ସମ୍ପାଦନ କରେ:

- `sk-` / `ak-` / `pk-` ପ୍ରିଫିକ୍ସ ଥିବା ଟୋକେନ୍ଗୁଡ଼ିକ (OpenAI/Anthropic-ଶୈଳୀ)
- RFC 6750 `Authorization: Bearer <token>` କ୍ରେଡେନ୍ସିଆଲ୍ଗୁଡ଼ିକ, ସମ୍ପୂର୍ଣ୍ଣ-ଟୋକେନ୍ ପ୍ରାଧାନ୍ୟ ସହିତ
- ସାଧାରଣ ଦୀର୍ଘ ଅସ୍ୱଚ୍ଛ ଟୋକେନ୍ଗୁଡ଼ିକ (≥40 ଅକ୍ଷର), ଡଟ୍ଯୁକ୍ତ ଏବଂ ପ୍ୟାଡ୍ କରାଯାଇଥିବା ରୂପ ସମେତ

`sanitizeHeaders()` ରଖାଯାଇଥିବା ନାମଗୁଡ଼ିକୁ ଲୋଅର୍କେସ୍ କରେ, ଆରେ ମୂଲ୍ୟଗୁଡ଼ିକୁ ନିର୍ଦ୍ଧାରିତ ଭାବରେ ଯୋଡ଼େ, ସାଧାରଣ ହପ୍-ବାଇ-ହପ୍/ଫ୍ରେମିଂ ଡିନାଇଲିଷ୍ଟକୁ ବାଦ୍ ଦିଏ (ପ୍ରକ୍ସି ପ୍ରାମାଣିକରଣ ସମେତ), `cookie` ଏବଂ `set-cookie`କୁ ସମ୍ପୂର୍ଣ୍ଣ ଭାବରେ ଗୋପନ କରେ, ଏବଂ କ୍ରେଡେନ୍ସିଆଲ୍ ମୂଲ୍ୟଗୁଡ଼ିକୁ ସ୍କାନର୍କୁ ନ୍ୟସ୍ତ କରେ।

### 3.2 ସାର୍ଟିଫିକେଟ୍କୁ ବିଶ୍ୱସ୍ତ କରନ୍ତୁ

IDEଗୁଡ଼ିକ MITM ସଂଯୋଗକୁ ଗ୍ରହଣ କରିବା ପୂର୍ବରୁ AgentBridge CA ସାର୍ଟିଫିକେଟ୍କୁ OS ଦ୍ୱାରା ବିଶ୍ୱସ୍ତ କରାଯିବା ଆବଶ୍ୟକ।

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

କିମ୍ବା ଡ୍ୟାସବୋର୍ଡରେ ଥିବା "Trust Cert" ବଟନ୍ ବ୍ୟବହାର କରନ୍ତୁ (ଆବଶ୍ୟକ ହେଲେ sudo ପ୍ରମ୍ପ୍ଟ ସହିତ, ଆପଣଙ୍କ OS ପାଇଁ ଉପଯୁକ୍ତ କମାଣ୍ଡ ଚଲାଏ)।

#### Electron-ଆଧାରିତ IDEଗୁଡ଼ିକ OS ଟ୍ରଷ୍ଟ ଷ୍ଟୋର୍କୁ ଅଣଦେଖା କରନ୍ତି (`NODE_EXTRA_CA_CERTS`)

କିଛି IDE — ବିଶେଷତଃ **Antigravity IDE**, ଏବଂ ଅନ୍ୟ Electron / VS Code-ରୁ ଉତ୍ପନ୍ନ ଆପ୍ଗୁଡ଼ିକ — ନିଜସ୍ୱ Node.js ରନ୍ଟାଇମ୍
ସହିତ ଆସନ୍ତି, ଯାହା ଆଉଟ୍ବାଉଣ୍ଡ `fetch`/HTTPS ପାଇଁ **OS ଟ୍ରଷ୍ଟ ଷ୍ଟୋର୍କୁ ବ୍ୟବହାର କରେ ନାହିଁ**।
OS/NSS ସ୍ତରରେ CA କୁ ବିଶ୍ୱସ୍ତ କରିବା IDEର ନେଟିଭ୍ **ବ୍ୟାକେଣ୍ଡ**
(ଉଦାହରଣ ସ୍ୱରୂପ, OS CA ବଣ୍ଡଲ୍ ବ୍ୟବହାର କରୁଥିବା ଏକ Go ଲାଙ୍ଗୁଏଜ୍ ସର୍ଭର୍) ପାଇଁ ଯଥେଷ୍ଟ, କିନ୍ତୁ **Electron ଫ୍ରଣ୍ଟଏଣ୍ଡ**ରେ
ତଥାପି TLS ବିଫଳ ହେବ — MITM ଲଗ୍ରେ ବ୍ୟାକେଣ୍ଡର ବୁଟ୍ଷ୍ଟ୍ରାପ୍ କଲ୍ଗୁଡ଼ିକ `200` ଫେରାଉଥିବା ସତ୍ତ୍ୱେ, ଆପ୍ଟି _ଲଗ୍ ଆଉଟ୍ ହୋଇଥିବା_ କିମ୍ବା
ଏକ _"ସଂଯୋଗ ତ୍ରୁଟି"_ ଦେଖାଉଥିବା ଭାବେ ଏହା ପ୍ରକାଶ ପାଏ। ଦୁଇଟି ପଦକ୍ଷେପ
ଆବଶ୍ୟକ, ଏବଂ ଉଭୟ ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ:

1. ରନ୍ଟାଇମ୍କୁ ସ୍ପଷ୍ଟ ଭାବରେ CA ଦିଗରେ ନିର୍ଦ୍ଦେଶ କରନ୍ତୁ:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **ସେହି shell ରୁ IDE ଆରମ୍ଭ କରନ୍ତୁ।** ଡେସ୍କଟପ୍ ଆଇକନ୍ / Dock / Start menu ରୁ ଏହାକୁ ଆରମ୍ଭ କଲେ
   shell exports ଇନ୍ହେରିଟ୍ ହୁଏ **ନାହିଁ**, ଏବଂ `~/.config/environment.d/*.conf` କେବଳ
   ଏକ ନୂତନ ଗ୍ରାଫିକାଲ୍ ଲଗଇନ୍ ପରେ ଲାଗୁ ହୁଏ। ପ୍ରଥମେ IDE କୁ ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ବନ୍ଦ କରନ୍ତୁ — Electronର singleton lock ଫଳରେ ଦ୍ୱିତୀୟ
   ଲଞ୍ଚ କେବଳ ପୂର୍ବରୁ ଚାଲୁଥିବା ପ୍ରୋସେସ୍କୁ ଫୋକସ୍ କରେ ଏବଂ ନୂତନ environment କୁ ଅଣଦେଖା କରାଯାଏ।

ଉପରୋକ୍ତ OS-trust + NSS ପଦକ୍ଷେପ ତଥାପି ଆବଶ୍ୟକ (କିଛି auth
ପ୍ରବାହ ଦ୍ୱାରା ବ୍ୟବହୃତ Chromium ନେଟୱର୍କ ଷ୍ଟାକ୍ ପ୍ରତି-ଉପଯୋଗକର୍ତ୍ତା NSS ଷ୍ଟୋର୍କୁ ପଢ଼େ, ଏବଂ `*.googleapis.com` ପାଇଁ ଏହାର ନିଜସ୍ୱ ଷ୍ଟାଟିକ୍ ପିନ୍ ଅଛି, ଯାହାକୁ
ଏକ ସ୍ଥାନୀୟ ଭାବେ ବିଶ୍ୱସ୍ତ CA ଓଭର୍ରାଇଡ୍ କରେ)। ଏହା ସହିତ Node `fetch` ପଥକୁ `NODE_EXTRA_CA_CERTS` କଭର୍ କରେ।

### 3.3 DNS ରାଉଟିଂ

ଆପଣ ଇଣ୍ଟରସେପ୍ଟ କରିବାକୁ ଚାହୁଁଥିବା ପ୍ରତ୍ୟେକ ଏଜେଣ୍ଟ ପାଇଁ, ଏହାର API ହୋଷ୍ଟ(ଗୁଡ଼ିକ) `127.0.0.1` କୁ ରିଜଲ୍ଭ ହେବା ଆବଶ୍ୟକ। Setup Wizardରେ ଏକ ଏଜେଣ୍ଟ ପାଇଁ DNS ଟଗଲ୍ କରିବାବେଳେ AgentBridge ସ୍ୱୟଂଚାଳିତ ଭାବେ `/etc/hosts` ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ ପରିଚାଳନା କରେ।

GitHub Copilot ପାଇଁ `/etc/hosts` ଏଣ୍ଟ୍ରିର ଉଦାହରଣ:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 ମଡେଲ୍ ମ୍ୟାପିଂ

ସୋର୍ସ → ଟାର୍ଗେଟ୍ ମ୍ୟାପିଂ ନିର୍ଦ୍ଧାରଣ କରିବା ପାଇଁ ପ୍ରତ୍ୟେକ ଏଜେଣ୍ଟ କାର୍ଡରେ ଥିବା Model Mapping Table ବ୍ୟବହାର କରନ୍ତୁ:

| ସୋର୍ସ ମଡେଲ୍ (ଏଜେଣ୍ଟର ନେଟିଭ୍) | ଟାର୍ଗେଟ୍ ମଡେଲ୍ (OmniRoute) |
| ---------------------------- | -------------------------- |
| `gpt-4o`                     | `claude-sonnet-4.7`        |
| `*` (ୱାଇଲ୍ଡକାର୍ଡ)            | `claude-haiku-4.7`         |

ୱାଇଲ୍ଡକାର୍ଡ `*` ଯେକୌଣସି ଅଚିହ୍ନା ମଡେଲ୍କୁ ନିର୍ଦ୍ଦିଷ୍ଟ ଟାର୍ଗେଟ୍ରେ ମ୍ୟାପ୍ କରେ। `agent_bridge_mappings` ଟେବୁଲ୍ରେ ସ୍ଥାୟୀ ଭାବେ ସଂରକ୍ଷିତ ହୁଏ।

> **ପରାମର୍ଶ — ଏଜେଣ୍ଟର ପ୍ରକୃତ model IDଗୁଡ଼ିକୁ ଖୋଜନ୍ତୁ।** ଏକ IDE ଏପରି model ନାମ ପଠାଇପାରେ ଯାହା
> ଏହାର UI labelଗୁଡ଼ିକଠାରୁ ଭିନ୍ନ ଏବଂ ପ୍ରମୁଖ versionଗୁଡ଼ିକ ମଧ୍ୟରେ ପରିବର୍ତ୍ତିତ ହୁଏ। ଉଦାହରଣ ସ୍ୱରୂପ **Antigravity 2**
> ନେଟୱର୍କ ମାଧ୍ୟମରେ `gemini-3.1-pro-low`, `gemini-pro-agent`, ଏବଂ `gemini-3.1-flash-lite` ପଠାଏ — ପୁରୁଣା
> docsରେ ଦେଖାଯାଇଥିବା `gemini-2.5-pro` ନୁହେଁ। କୌଣସି matching mapping ବିନ୍ୟାସ ନ କରି ଗୋଟିଏ chat ପଠାନ୍ତୁ: MITM
> ସଠିକ୍ incoming `model:`କୁ log କରେ ଏବଂ requestଟିକୁ ପଠାଇଦିଏ। ସେହି literal valueକୁ map କରନ୍ତୁ, ତା’ପରେ
> ପରବର୍ତ୍ତୀ requestକୁ intercept କରାଯାଇ ଆପଣଙ୍କ targetକୁ route କରାଯିବ।

### 3.5 ବିପଦ ସୂଚନା

AgentBridge ସେହି credentials (OAuth tokens, API keys)କୁ intercept କରେ, ଯାହା IDE upstream providersଙ୍କ ସହ authenticate କରିବା ପାଇଁ ବ୍ୟବହାର କରେ। ଏଗୁଡ଼ିକୁ **logging ପୂର୍ବରୁ mask କରାଯାଏ** (§2.7 ଦେଖନ୍ତୁ), କିନ୍ତୁ OmniRouteର MITM layer ପାଇଁ ଦୃଶ୍ୟମାନ ରହେ। ପ୍ରତ୍ୟେକ agentର ପ୍ରଥମ activation ଏକ dismiss କରାଯାଇପାରୁଥିବା ବିପଦ ସୂଚନା modal ଦେଖାଏ।

### 3.6 ରକ୍ଷଣାବେକ୍ଷଣ ଏବଂ ଡାଏଗ୍ନୋଷ୍ଟିକ୍ସ

Dashboard ଏକ **ରକ୍ଷଣାବେକ୍ଷଣ ଏବଂ ଡାଏଗ୍ନୋଷ୍ଟିକ୍ସ** card (`AgentBridgeMaintenanceCard`, `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`ରେ) ପ୍ରଦର୍ଶନ କରେ, ଯାହା ପୂର୍ବରୁ UI ନଥିବା operational MITM routesଗୁଡ଼ିକୁ ଉପଲବ୍ଧ କରାଏ। ଏହାର subtitle: _"capture pipelineର self-test କରନ୍ତୁ, ରହିଯାଇଥିବା system stateକୁ ପୂର୍ବାବସ୍ଥାକୁ ଫେରାନ୍ତୁ, ଏବଂ ନିଜ setupକୁ machineଗୁଡ଼ିକ ମଧ୍ୟରେ ସ୍ଥାନାନ୍ତର କରନ୍ତୁ।"_ Cardର client helpersଗୁଡ଼ିକ `src/lib/inspector/agentBridgeMaintenanceApi.ts`ରେ ଅଛି।

| ବଟନ୍                     | Route                                  | ଏହା କ’ଣ କରେ                                                                                                                                                                                          |
| ------------------------ | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ନିଦାନ କରନ୍ତୁ**         | `GET /api/tools/agent-bridge/diagnose` | capture-pipeline self-test ଚଲାଏ ଏବଂ ପ୍ରତ୍ୟେକ check ପାଇଁ ଏକ report ଦେଖାଏ (✓/✗ + remediation hint)।                                                                                                    |
| **ମରାମତି କରନ୍ତୁ**        | `POST /api/tools/agent-bridge/repair`  | crash କିମ୍ବା SIGKILL ପରେ ରହିଯାଇଥିବା orphaned MITM system state (DNS spoof entries, root CA, system proxy)କୁ ପୂର୍ବାବସ୍ଥାକୁ ଫେରାଏ। Idempotent — state ସଫା ଥିଲେ "ମରାମତି କରିବାକୁ କିଛି ନାହିଁ" report କରେ। |
| **CA ହଟାନ୍ତୁ**           | `DELETE /api/tools/agent-bridge/cert`  | OS trust storeରୁ MITM root CAକୁ untrust କରି ହଟାଏ (ସ୍ପଷ୍ଟ, idempotent)। CA ବର୍ତ୍ତମାନ trusted ଥିଲେ ମାତ୍ର ଦେଖାଯାଏ; ଏକ inline "CA ହଟାଇବେ?" confirmation ଆବଶ୍ୟକ କରେ।                                      |
| **config export କରନ୍ତୁ** | `GET /api/tools/agent-bridge/config`   | portable config JSON download କରେ (§3.7 ଦେଖନ୍ତୁ)।                                                                                                                                                    |
| **config import କରନ୍ତୁ** | `POST /api/tools/agent-bridge/config`  | ପୂର୍ବରୁ export କରାଯାଇଥିବା config JSON upload କରେ (§3.7 ଦେଖନ୍ତୁ)।                                                                                                                                     |

ପ୍ରତ୍ୟେକ agent cardର ନିଜସ୍ୱ **Default ପୁନଃସ୍ଥାପନ କରନ୍ତୁ** ବଟନ୍ (`POST
/api/tools/agent-bridge/agents/{id}/reset`) ମଧ୍ୟ ଅଛି — ଏକ one-click, ପ୍ରତ୍ୟେକ agent ପାଇଁ undo, ଯାହା କେବଳ ସେହି
agentର hostsଗୁଡ଼ିକୁ un-spoof କରେ, ତାହାର ସଂରକ୍ଷିତ model mappings ସଫା କରେ, ଏବଂ ତାହାର `dns_enabled`/`setup_completed`
state reset କରେ, ଫଳରେ IDE ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ restart ହେବା ପରେ ପୁଣିଥରେ ପ୍ରକୃତ upstream ସହ ଯୋଗାଯୋଗ କରେ। ଏହା
shared MITM server କିମ୍ବା root CAକୁ ପରିବର୍ତ୍ତନ କରେ **ନାହିଁ** (ଅନ୍ୟ agents ଏବେ ମଧ୍ୟ ସେଗୁଡ଼ିକ ଉପରେ ନିର୍ଭର କରିପାରନ୍ତି) — ସେଗୁଡ଼ିକ ଉପରୋକ୍ତ
Server Card ଏବଂ **CA ହଟାନ୍ତୁ** action ମାଧ୍ୟମରେ ଉପଲବ୍ଧ ରହେ। Windowsରେ ଏହା best-effort ଭାବେ
`ipconfig /flushdns` ମଧ୍ୟ ଚଲାଏ, କାରଣ Windows DNS Client hosts-file entriesକୁ cache କରେ ଏବଂ ଏହା ବିନା
ନୂତନ ଭାବେ ହଟାଯାଇଥିବା spoofକୁ ଛାଡ଼ିବ ନାହିଁ।

**ଡାଏଗ୍ନୋଷ୍ଟିକ୍ସ checks** (`src/mitm/inspector/diagnostics.ts`ରେ `summarizeDiagnostics()`)। Routeଟି ପ୍ରତ୍ୟେକ ପାଇଁ effectful probe ଚଲାଏ ଏବଂ booleansଗୁଡ଼ିକୁ pure summarizerରେ ପ୍ରଦାନ କରେ; ଗୋଟିଏ `healthy` verdict ସହ ପ୍ରତ୍ୟେକ failure ପାଇଁ ଏକ hint ଫେରାଯାଏ:

| Check ନାମ          | ଏହା କ’ଣ ଯାଞ୍ଚ କରେ                                         | ବିଫଳତା ସମୟରେ hint                                                                                                                                                                  |
| ------------------ | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | MITM server process ସକ୍ରିୟ ଅଛି                            | "MITM server ଚାଲୁନାହିଁ। AgentBridge tabରୁ ଏହାକୁ ଆରମ୍ଭ କରନ୍ତୁ।"                                                                                                                     |
| `server-reachable` | MITM server ଏହାର portରେ connections ଗ୍ରହଣ କରେ (TCP probe) | "MITM server ଏହାର portରେ connections ଗ୍ରହଣ କରୁନାହିଁ। portଟି ଖାଲି ଅଛି ଏବଂ ତାହାକୁ bind କରିବା ପାଇଁ ଆପଣଙ୍କ ପାଖରେ privileges ଅଛି କି ଯାଞ୍ଚ କରନ୍ତୁ।"                                      |
| `cert-exists`      | MITM certificateଟି diskରେ generate କରାଯାଇଛି               | "ଏପର୍ଯ୍ୟନ୍ତ କୌଣସି MITM certificate generate କରାଯାଇନାହିଁ। AgentBridge tabରୁ ଗୋଟିଏ generate କରନ୍ତୁ।"                                                                                 |
| `cert-trusted`     | MITM root CAଟି OS trust storeରେ ଅଛି                       | "MITM root CAକୁ OS store trust କରୁନାହିଁ, ତେଣୁ TLS interception ବିଫଳ ହେବ। AgentBridge tabରୁ certificateଟିକୁ trust କରନ୍ତୁ।"                                                          |
| `dns-configured`   | Target hostnamesଗୁଡ଼ିକୁ `/etc/hosts`ରେ spoof କରାଯାଇଛି     | "Target hostnamesଗୁଡ଼ିକୁ /etc/hostsରେ spoof କରାଯାଇନାହିଁ, ତେଣୁ traffic କେବେ ମଧ୍ୟ proxy ପର୍ଯ୍ୟନ୍ତ ପହଞ୍ଚେ ନାହିଁ। ଆପଣ capture କରିବାକୁ ଚାହୁଁଥିବା agent(ଗୁଡ଼ିକ) ପାଇଁ DNS enable କରନ୍ତୁ।" |

**Orphaned-state banner:** pageଟି crash ପରେ ରହିଯାଇଥିବା state (DNS spoof / CA / system proxy) detect କଲେ, cardଟି ଏକ amber banner ଦେଖାଏ — _"ଏକ ପୂର୍ବ session system state ଛାଡ଼ିଯାଇଛି (DNS spoof, CA, କିମ୍ବା system proxy)। ଏହାକୁ ସଫା କରିବା ପାଇଁ ମରାମତି ଚଲାନ୍ତୁ।"_ — ଏବଂ **ମରାମତି କରନ୍ତୁ** ବଟନ୍କୁ highlight କରେ। `Repair` ହେଉଛି ProxyBridgeର `--cleanup` flagର application-layer ସମତୁଲ୍ୟ (ଏହା `src/mitm/manager.ts`ର `repairMitm()`କୁ delegate କରେ)।

> ପୁନଃପୁନି sudo ପ୍ରମ୍ପ୍ଟ ଏଡ଼ାଇବା ପାଇଁ stop/start ମଧ୍ୟରେ MITM root CA ଇନଷ୍ଟଲ୍ ହୋଇ ରହେ
> (mitmproxy/Charles ଭଳି ସମାନ ଆଚରଣ), ତେଣୁ ଏହାକୁ ହଟାଇବା stop ସମୟରେ ସ୍ୱୟଂଚାଳିତ ଭାବେ
> ଘଟୁଥିବା କିଛି ନୁହେଁ, ବରଂ ଏକ ସ୍ପଷ୍ଟ **CA ହଟାନ୍ତୁ** କାର୍ଯ୍ୟ।

### 3.7 ପୋର୍ଟେବଲ୍ କନଫିଗ୍ ଇମ୍ପୋର୍ଟ/ଏକ୍ସପୋର୍ଟ

AgentBridge **ଅପରେଟର୍ଙ୍କ ଦ୍ୱାରା ସମନ୍ୱୟଯୋଗ୍ୟ** ଅବସ୍ଥାକୁ ଏକ ସଂସ୍କରଣଯୁକ୍ତ JSON ବ୍ଲବ୍ରେ ସିରିଆଲାଇଜ୍ କରିପାରେ, ଯାହାଦ୍ୱାରା ଗୋଟିଏ ସେଟଅପ୍କୁ ଏକାଧିକ ମେସିନ୍ରେ ପୁନଃସୃଷ୍ଟି କରାଯାଇପାରିବ। ସିରିଆଲାଇଜର୍ ହେଉଛି `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), ଯାହା `AgentBridgeConfigSchema` ଦ୍ୱାରା ବୈଧୀକୃତ।

ଏକ୍ସପୋର୍ଟରେ ଠିକ୍ ତିନୋଟି ଅଂଶ ଅନ୍ତର୍ଭୁକ୍ତ (ବିଲ୍ଟ-ଇନ୍ ଡିଫଲ୍ଟଗୁଡ଼ିକୁ ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ **ଏକ୍ସପୋର୍ଟ କରାଯାଏ ନାହିଁ**, ତେଣୁ ଇମ୍ପୋର୍ଟ କରିବା ସେଗୁଡ଼ିକୁ କେବେହେଲେ ନକଲ କରେ ନାହିଁ କିମ୍ବା ସେଗୁଡ଼ିକ ସହିତ ଦ୍ୱନ୍ଦ୍ୱ ସୃଷ୍ଟି କରେ ନାହିଁ):

| ଫିଲ୍ଡ            | ଉତ୍ସ                                                             | ଟିପ୍ପଣୀ                                                                 |
| ---------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `bypassPatterns` | ବ୍ୟବହାରକାରୀ-ନିର୍ଦ୍ଧାରିତ ବାଇପାସ୍ ପ୍ୟାଟର୍ନ (`agent_bridge_bypass`) | ଡିଫଲ୍ଟ bank/gov/okta ପ୍ୟାଟର୍ନଗୁଡ଼ିକ ବାଦ ଦିଆଯାଏ                          |
| `customHosts`    | Traffic Inspector କଷ୍ଟମ୍ ହୋଷ୍ଟ (`inspector_custom_hosts`)        | ପ୍ରତ୍ୟେକଟି: `{ host, kind: "llm"\|"app"\|"custom", label? }`            |
| `agentMappings`  | ପ୍ରତି-ଏଜେଣ୍ଟ ମଡେଲ୍ ମ୍ୟାପିଂ (`agent_bridge_mappings`)             | ମ୍ୟାପିଂ ଥିବା ପ୍ରତ୍ୟେକ ଏଜେଣ୍ଟ ପାଇଁ `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**ଇମ୍ପୋର୍ଟ ଆଚରଣ** (`POST /api/tools/agent-bridge/config`): ବାଇପାସ୍ ପ୍ୟାଟର୍ନ ଏବଂ ପ୍ରତି-ଏଜେଣ୍ଟ ମ୍ୟାପିଂଗୁଡ଼ିକ **ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ପ୍ରତିସ୍ଥାପିତ ହୁଏ**; କଷ୍ଟମ୍ ହୋଷ୍ଟଗୁଡ଼ିକୁ **ଆଇଡେମ୍ପୋଟେଣ୍ଟ ଭାବେ** ଯୋଡ଼ାଯାଏ (`INSERT OR IGNORE`)। ପ୍ରତ୍ୟେକରୁ କେତୋଟି ପ୍ରୟୋଗ କରାଗଲା, ପ୍ରତିକ୍ରିୟାରେ ତାହା ଦର୍ଶାଯାଏ:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

କନଫିଗ୍ରେ ଯାହା **ନାହିଁ**: ସର୍ଭର୍ ଚାଲୁଥିବା ଅବସ୍ଥା, ସର୍ଟିଫିକେଟ୍ ପଥ, ପ୍ରତି-ଏଜେଣ୍ଟ DNS ଅବସ୍ଥା, ଅପ୍ଷ୍ଟ୍ରିମ୍ CA ପଥ, ଏବଂ TPROXY ସେଟିଂସ୍ — ଏଗୁଡ଼ିକ ହେଉଛି ହୋଷ୍ଟ/ରନ୍ଟାଇମ୍ ଅବସ୍ଥା, ପୋର୍ଟେବଲ୍ ପସନ୍ଦ ନୁହେଁ।

### ସେଟ୍ଅପ୍ ୱିଜାର୍ଡ ପଦକ୍ଷେପଗୁଡ଼ିକ (ପ୍ରତି ଏଜେଣ୍ଟ)

### ସମ୍ବେଦନଶୀଳ ହୋଷ୍ଟଗୁଡ଼ିକ ପାଇଁ ବାଇପାସ୍ ତାଲିକା

ବାଇପାସ୍ ତାଲିକା ନିଶ୍ଚିତ କରେ ଯେ ଆର୍ଥିକ ସଂସ୍ଥା, OAuth/SSO ପ୍ରଦାନକାରୀ ଏବଂ ଅନ୍ୟାନ୍ୟ ସମ୍ବେଦନଶୀଳ ହୋଷ୍ଟଗୁଡ଼ିକୁ **କେବେବି ଡିକ୍ରିପ୍ଟ କରାଯାଏ ନାହିଁ**। ସେମାନଙ୍କର TLS ଟ୍ରାଫିକ୍ ଏକ ସ୍ୱଚ୍ଛ TCP ଟନେଲ୍ ଭାବରେ ପାର ହୁଏ — OmniRoute କେବେବି ପ୍ଲେନ୍ଟେକ୍ସଟ୍ ଦେଖେ ନାହିଁ।

ଡିଫଲ୍ଟ ବାଇପାସ୍ ପ୍ୟାଟର୍ନଗୁଡ଼ିକରେ ଅନ୍ତର୍ଭୁକ୍ତ:

- `*.bank.*`, `*.gov.*` (ଆର୍ଥିକ/ସରକାରୀ)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/ପରିଚୟ)
- `*.apple.com`, `*.icloud.com` (Apple ସିଷ୍ଟମ୍ ସେବାଗୁଡ଼ିକ)

ବ୍ୟବହାରକାରୀଙ୍କ ଦ୍ୱାରା ଯୋଡ଼ାଯାଇଥିବା ବାଇପାସ୍ ପ୍ୟାଟର୍ନଗୁଡ଼ିକ `agent_bridge_bypass` ସାରଣୀରେ ସଂରକ୍ଷିତ ହୁଏ ଏବଂ ଅନ୍ୟ ସବୁକିଛି ଉପରେ ପ୍ରାଥମ୍ୟ ପାଏ।

### ଗୁପ୍ତ ତଥ୍ୟ ମାସ୍କିଂ

`src/mitm/maskSecrets.ts`ରୁ `maskSecrets()` ପ୍ରୟୋଗ କରାଯାଏ:

- `TrafficBuffer.push()` ପୂର୍ବରୁ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ବଡି ଉପରେ
- ଲଗିଂ କିମ୍ବା ବ୍ରଡକାଷ୍ଟିଂ ପୂର୍ବରୁ ପ୍ରତ୍ୟେକ ହେଡର୍ ଉପରେ

ପ୍ୟାଟର୍ନଗୁଡ଼ିକ: `sk-`/`ak-`/`pk-` ପ୍ରିଫିକ୍ସ ଟୋକେନ୍, `Bearer` ଟୋକେନ୍ ଏବଂ ≥40 ଅକ୍ଷର ବିଶିଷ୍ଟ ଜେନେରିକ୍ ଟୋକେନ୍।

### ଅପ୍ଷ୍ଟ୍ରିମ୍ CA ସାର୍ଟିଫିକେଟ୍

ଯେତେବେଳେ `AGENTBRIDGE_UPSTREAM_CA_CERT` ସେଟ୍ କରାଯାଏ, ଷ୍ଟାର୍ଟଅପ୍ ସମୟରେ ଫାଇଲ୍ଟି ପଢ଼ାଯାଏ। ଯଦି ପଥଟି ବିଦ୍ୟମାନ ଥାଏ କିନ୍ତୁ ଫାଇଲ୍ଟି ପଠନଯୋଗ୍ୟ ନୁହେଁ, AgentBridge ଏକ ସ୍ପଷ୍ଟ ତ୍ରୁଟି ଲଗ୍ କରେ ଏବଂ ଆରମ୍ଭ ହେବାକୁ ମନା କରେ (କର୍ପୋରେଟ୍ ପରିବେଶରେ ନିରବ TLS ବିଫଳତାକୁ ପ୍ରତିରୋଧ କରେ)।

### ଜଣାଶୁଣା ସୀମାବଦ୍ଧତାଗୁଡ଼ିକ

- **ପୋର୍ଟ 443 ପାଇଁ ବିଶେଷାଧିକାର ଆବଶ୍ୟକ**: Linuxରେ, AgentBridgeକୁ Node ବାଇନାରି ଉପରେ `setcap 'cap_net_bind_service=+ep'` ଆବଶ୍ୟକ, କିମ୍ବା `authbind` ମାଧ୍ୟମରେ ଚଲାନ୍ତୁ। ସେଟ୍ଅପ୍ ୱିଜାର୍ଡ OS-ନିର୍ଦ୍ଦିଷ୍ଟ ନିର୍ଦ୍ଦେଶାବଳୀ ପ୍ରଦର୍ଶନ କରେ।
- **IDE ପୁନଃଚାଳନ ଆବଶ୍ୟକ**: DNS ପୁନଃନିର୍ଦ୍ଦେଶନ ପରେ, ନୂଆ ହୋଷ୍ଟ ରିଜୋଲ୍ୟୁସନ୍ କାର୍ଯ୍ୟକାରୀ ହେବା ପାଇଁ IDEକୁ ପୁନଃଚାଳନ କରିବା ଆବଶ୍ୟକ।
- **ହାର୍ଡକୋଡ୍ କରାଯାଇଥିବା OAuth ଟୋକେନ୍**: କିଛି ଏଜେଣ୍ଟ (Kiro, Antigravity) OAuth ରିଫ୍ରେଶ୍ ଟୋକେନ୍ଗୁଡ଼ିକୁ ସ୍ଥାନୀୟ ଭାବରେ ସଂରକ୍ଷଣ କରନ୍ତି। ଏଗୁଡ଼ିକ AgentBridge ପାଇଁ ସ୍ୱଚ୍ଛ — ଏହା ପ୍ରତ୍ୟେକ ଅନୁରୋଧରେ Bearer ଟୋକେନ୍ ଦେଖେ, ଯାହାକୁ ଲଗିଂ ପୂର୍ବରୁ ମାସ୍କ କରାଯାଏ।
- **Electron ଫ୍ରଣ୍ଟଏଣ୍ଡଗୁଡ଼ିକୁ `NODE_EXTRA_CA_CERTS` ଆବଶ୍ୟକ**: ଯେଉଁ IDEଗୁଡ଼ିକର ଫ୍ରଣ୍ଟଏଣ୍ଡ ଏକ ବଣ୍ଡଲ୍କୃତ Node/Electron ରନ୍ଟାଇମ୍ରେ ଚାଲେ, ସେଗୁଡ଼ିକ OS/NSS ଟ୍ରଷ୍ଟ ଷ୍ଟୋର୍କୁ ଅଣଦେଖା କରେ ଏବଂ `NODE_EXTRA_CA_CERTS` ସେଟ୍ ଥିବା ଏକ ଶେଲ୍ରୁ ଆରମ୍ଭ କରାଯିବା ଆବଶ୍ୟକ (§3.2 ଦେଖନ୍ତୁ)। ଏହା ନଥିବାବେଳେ ଲକ୍ଷଣ: IDE ବ୍ୟାକ୍ଏଣ୍ଡ ପ୍ରମାଣୀକୃତ ହୁଏ (MITM `200`ଗୁଡ଼ିକ ଦେଖାଏ), କିନ୍ତୁ UI ଲଗ୍ଆଉଟ୍ ଅବସ୍ଥାରେ ରହେ।
- **ସମାନ IDEର ଏକାଧିକ ଇନ୍ଷ୍ଟଲେସନ୍ ସ୍ୱାଧୀନ ଅଟେ**: ଏକ ସିଷ୍ଟମ୍ ଇନ୍ଷ୍ଟଲେସନ୍ (ଉଦାହରଣ ସ୍ୱରୂପ `/usr/share/antigravity/antigravity`) ଏବଂ ଏକ ବ୍ୟବହାରକାରୀ-ସ୍ଥାନୀୟ "Full" ଇନ୍ଷ୍ଟଲେସନ୍ (ଉଦାହରଣ ସ୍ୱରୂପ `~/AntigravityIDE_Full/antigravity-ide`) ନିଜସ୍ୱ ରନ୍ଟାଇମ୍ ସହିତ ପୃଥକ ପ୍ରକ୍ରିୟା — ପ୍ରତ୍ୟେକକୁ CA ଇଞ୍ଜେକ୍ଟ କରି ପୁନଃଚାଳୁ କରିବା ଆବଶ୍ୟକ। ପୁନଃଚାଳୁ କରିବା ପୂର୍ବରୁ ଏହାର ବାଇନାରି ପଥ ଦ୍ୱାରା କେଉଁଟି ଚାଲୁଛି ତାହା ଚିହ୍ନଟ କରନ୍ତୁ।
- **ପରିଚୟ ରାଉଟ୍ କରାଯାଇଥିବା ମଡେଲ୍ ଦ୍ୱାରା ନୁହେଁ, ଏଜେଣ୍ଟର ସିଷ୍ଟମ୍ ପ୍ରମ୍ପ୍ଟ ଦ୍ୱାରା ସେଟ୍ ହୁଏ**: ଯେତେବେଳେ ଆପଣ ଏକ ଏଜେଣ୍ଟର ମଡେଲ୍କୁ ଏକ ଭିନ୍ନ ପ୍ରଦାନକାରୀ ସହିତ ପୁନଃମ୍ୟାପ୍ କରନ୍ତି, ଉତ୍ତରଟି ତଥାପି ଏଜେଣ୍ଟର ମୂଳ ପରିଚୟ ଦାବି କରେ (ଉଦାହରଣ ସ୍ୱରୂପ Antigravity ଉତ୍ତର ଦିଏ "ମୁଁ Gemini ଦ୍ୱାରା ପରିଚାଳିତ") କାରଣ IDE ତାହାକୁ ସିଷ୍ଟମ୍ ପ୍ରମ୍ପ୍ଟରେ ଇଞ୍ଜେକ୍ଟ କରେ। ମଡେଲ୍କୁ ଏହା କିଏ ବୋଲି ପଚାରିବା ପରିବର୍ତ୍ତେ `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`)ରେ ପ୍ରକୃତ ବ୍ୟାକ୍ଏଣ୍ଡକୁ ନିଶ୍ଚିତ କରନ୍ତୁ।

## §6 ସମସ୍ୟା ସମାଧାନ

### ପୋର୍ଟ 443 ବିରୋଧ

ଯଦି ଅନ୍ୟ କୌଣସି ପ୍ରକ୍ରିୟା ପୂର୍ବରୁ ପୋର୍ଟ 443ରେ ଶୁଣୁଛି (ୱେବ୍ ସର୍ଭର୍, VPN, ଇତ୍ୟାଦି):

```bash
lsof -i :443          # ପ୍ରକ୍ରିୟାଟି ଖୋଜନ୍ତୁ
sudo fuser -k 443/tcp  # ବଳପୂର୍ବକ ବନ୍ଦ କରନ୍ତୁ (ସତର୍କତାର ସହ ବ୍ୟବହାର କରନ୍ତୁ)
```

ବିକଳ୍ପ ଭାବେ, AgentBridge ସେଟିଂସ୍ରେ ଏକ ଅଣ-ବିଶେଷାଧିକୃତ ପୋର୍ଟ ବିନ୍ୟାସ କରନ୍ତୁ ଏବଂ `iptables` / `pf` ପୁନଃନିର୍ଦ୍ଦେଶ ନିୟମ ସେଟ୍ ଅପ୍ କରନ୍ତୁ।

### ସାର୍ଟିଫିକେଟ୍ ବିଶ୍ୱସ୍ତ ନୁହେଁ

AgentBridge ଆରମ୍ଭ କରିବା ପରେ ଯଦି IDE TLS ତ୍ରୁଟି ଦେଖାଏ:

1. ସାର୍ଟିଫିକେଟ୍ଟି ଇନ୍ଷ୍ଟଲ୍ ହୋଇଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) କିମ୍ବା `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. କେତେକ ଆପ୍ ନିଜସ୍ୱ ବିଶ୍ୱାସ ଭଣ୍ଡାର ବଜାୟ ରଖନ୍ତି (Firefox, Linuxରେ Chrome)। "Trust Cert" ପୁଣି ଚଲାନ୍ତୁ ଏବଂ NSS/Firefox-ନିର୍ଦ୍ଦିଷ୍ଟ ସାର୍ଟିଫିକେଟ୍ ଭଣ୍ଡାର ଯାଞ୍ଚ କରନ୍ତୁ।
3. ବିଶ୍ୱସ୍ତ କରିବା ପରେ IDE ପୁନଃଆରମ୍ଭ କରନ୍ତୁ — ଚାଲୁଥିବା TLS ସେସନ୍ଗୁଡ଼ିକ ପୁରୁଣା ବିଶ୍ୱାସ ସ୍ଥିତି ବ୍ୟବହାର କରନ୍ତି।

### ବିଶ୍ୱସ୍ତ CA ଥିବା ସତ୍ତ୍ୱେ IDEରୁ ଲଗ୍ ଆଉଟ୍ / "ସଂଯୋଗ ତ୍ରୁଟି"

ଲକ୍ଷଣ: DNS ପୁନଃନିର୍ଦ୍ଦେଶ କରିବା ଏବଂ CAକୁ ବିଶ୍ୱସ୍ତ କରିବା ପରେ, Electron-ଆଧାରିତ IDE (ଯଥା Antigravity)
**ଲଗ୍ ଆଉଟ୍ ହୋଇଥିବା** ଅବସ୍ଥାରେ ଖୋଲେ କିମ୍ବା ଏକ ପ୍ରମାଣୀକରଣ/ସଂଯୋଗ ତ୍ରୁଟି ଦେଖାଏ, ଯଦିଓ MITM ଲଗ୍ରେ
ବୁଟ୍ଷ୍ଟ୍ରାପ୍ କଲ୍ଗୁଡ଼ିକ (`loadCodeAssist`, `fetchAvailableModels`, …) `200` ଫେରାଉଥିବା ଦେଖାଯାଏ।

କାରଣ: IDEର **ବଣ୍ଡଲ୍ କରାଯାଇଥିବା Node/Electron ରନ୍ଟାଇମ୍ OS ବିଶ୍ୱାସ ଭଣ୍ଡାରକୁ ଅଣଦେଖା କରେ**। ନେଟିଭ୍
ବ୍ୟାକ୍ଏଣ୍ଡ୍ (ଏକ Go ଭାଷା ସର୍ଭର୍) OS CAକୁ ବିଶ୍ୱାସ କରେ ଏବଂ ପ୍ରମାଣୀକରଣ କରେ, କିନ୍ତୁ Electron ଫ୍ରଣ୍ଟ୍ଏଣ୍ଡ୍
ତାହା କରେ ନାହିଁ — ତେଣୁ UI ନିଜକୁ ଅଫ୍ଲାଇନ୍ ବୋଲି ଧରେ।

ସମାଧାନ (ଉଭୟ ପଦକ୍ଷେପ): `NODE_EXTRA_CA_CERTS=<ca.crt>` ଏକ୍ସପୋର୍ଟ କରନ୍ତୁ **ଏବଂ ସେହି
ସେଲ୍ରୁ IDEକୁ ପୁନଃଚାଲୁ କରନ୍ତୁ**, ଡେସ୍କଟପ୍ ଆଇକନ୍ରୁ ନୁହେଁ। ପ୍ରଥମେ IDEକୁ ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ବନ୍ଦ କରନ୍ତୁ — Electronର ସିଙ୍ଗଲ୍ଟନ୍ ଲକ୍ର ଅର୍ଥ ହେଉଛି
ଦ୍ୱିତୀୟ ଲଞ୍ଚ୍ କେବଳ ପୂର୍ବରୁ ଚାଲୁଥିବା ପ୍ରକ୍ରିୟାକୁ ଫୋକସ୍ କରେ ଏବଂ ନୂଆ ପରିବେଶକୁ ଅଣଦେଖା କରାଯାଏ। §3.2 ଦେଖନ୍ତୁ।
ଏହା ଏକ ଖୋଲା ଅପ୍ଷ୍ଟ୍ରିମ୍ ରିପୋର୍ଟ ସହ ମେଳ ଖାଏ, ଯେଉଁଠାରେ ଏକ ସ୍ୱତନ୍ତ୍ର ଏଜେଣ୍ଟ MITM ମାଧ୍ୟମରେ କାମ କରେ, କିନ୍ତୁ IDE
ପ୍ରକାରଟି ସେହି ସେଟ୍ଅପ୍ରେ ବିଫଳ ହୁଏ।

### DNS ପ୍ରସାରିତ ହୋଇନାହିଁ

`/etc/hosts` ଅଦ୍ୟତନ ହୋଇଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS କ୍ୟାଶ୍ ସଫା କରନ୍ତୁ:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE ଚିହ୍ନଟ ହୋଇନାହିଁ

ସ୍ୱୟଂଚାଳିତ ଚିହ୍ନଟ ସାଧାରଣ ଇନ୍ଷ୍ଟଲେସନ୍ ପଥଗୁଡ଼ିକ ବ୍ୟବହାର କରେ। IDE ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିଲେ ମଧ୍ୟ ଯଦି ଚିହ୍ନଟ ବିଫଳ ହୁଏ:

- IDE ବାଇନାରିଟି ଏକ ଅଣ-ମାନକ ଅବସ୍ଥାନରେ ଅଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ
- Setup Wizard ତଥାପି କାମ କରେ — ଚିହ୍ନଟ ବିଫଳତାର ଅର୍ଥ କେବଳ ଏତିକି ଯେ ବ୍ୟାଜ୍ରେ ଇନ୍ଷ୍ଟଲ୍ ପଥ ଦେଖାଯିବ ନାହିଁ

### ହ୍ୟାଣ୍ଡଲର୍ ତ୍ରୁଟି (ଅପ୍ଷ୍ଟ୍ରିମ୍ ଫେଚ୍ ବିଫଳ)

ଯଦି AgentBridge ଇଣ୍ଟରସେପ୍ଟ କରେ କିନ୍ତୁ ସମସ୍ତ ଅନୁରୋଧ ବିଫଳ ହୁଏ:

## §8 ରୋଡ୍ମ୍ୟାପ୍

### Trae ଅନୁସନ୍ଧାନ

Trae ଏକ ଅପେକ୍ଷାକୃତ ନୂତନ AI କୋଡିଂ ସହାୟକ। ଏକ ହ୍ୟାଣ୍ଡଲର୍ କାର୍ଯ୍ୟକାରୀ କରିବା ପୂର୍ବରୁ:

1. VS Code / JetBrains ମାର୍କେଟ୍ପ୍ଲେସ୍ରେ କିମ୍ବା ଏକ ସ୍ୱତନ୍ତ୍ର ଆପ୍ ଭାବେ ବାଇନାରୀ/ଏକ୍ସଟେନ୍ସନ୍କୁ ଚିହ୍ନଟ କରନ୍ତୁ
2. API ହୋଷ୍ଟ ଏବଂ ଏଣ୍ଡପଏଣ୍ଟର ଗଠନ ଆବିଷ୍କାର କରିବା ପାଇଁ mitmproxy ସହିତ ଟ୍ରାଫିକ୍ କ୍ୟାପ୍ଚର୍ କରନ୍ତୁ
3. ପ୍ରମାଣୀକରଣ ପ୍ରଣାଳୀ ନିର୍ଦ୍ଧାରଣ କରନ୍ତୁ
4. TOS ଏବଂ API ଆବିଷ୍କାରଯୋଗ୍ୟତା ଆଧାରରେ ଆଗକୁ ବଢ଼ିବା/ନ ବଢ଼ିବାର ମୂଲ୍ୟାଙ୍କନ କରନ୍ତୁ

ଅନୁସନ୍ଧାନ ସମ୍ପୂର୍ଣ୍ଣ ହେବା ପର୍ଯ୍ୟନ୍ତ, ଡ୍ୟାସ୍ବୋର୍ଡରେ ଥିବା Trae କାର୍ଡ ଏକ "ଅନୁସନ୍ଧାନାଧୀନ" ବ୍ୟାଜ୍ ସହିତ ଏକ "କାର୍ଯ୍ୟକ୍ଷମତା ରିପୋର୍ଟ କରନ୍ତୁ" ଲିଙ୍କ୍ ଦେଖାଏ। `src/mitm/handlers/trae.ts` ରେ ଥିବା ହ୍ୟାଣ୍ଡଲର୍ ଷ୍ଟବ୍ ଏକ ସଂରଚିତ `ଏପର୍ଯ୍ୟନ୍ତ କାର୍ଯ୍ୟକାରୀ ହୋଇନାହିଁ` ତ୍ରୁଟି ଉତ୍ଥାପନ କରେ।
