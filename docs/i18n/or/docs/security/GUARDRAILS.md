> **ପ୍ରାମାଣିକ ଉତ୍ସ:** `src/lib/guardrails/`
> **ଶେଷ ଅଦ୍ୟତନ:** 2026-10-17 — v3.8.52 ([କଭରେଜ୍ ଏବଂ ସୀମାଗୁଡ଼ିକ](#coverage-and-limits) ଯୋଡ଼ାଗଲା:
> hooks ଗୁଡ଼ିକ କେଉଁ route ଏବଂ response path ଗୁଡ଼ିକୁ ପହଞ୍ଚନ୍ତି, ମିଶ୍ରିତ disable headers (#16412), ବାଧ୍ୟତାମୂଳକ ସୀମା ଭାବରେ injection
> block mode (#16413), ଏବଂ post-call ପୂର୍ବରୁ କେଉଁଟି ଗୋଟିଏ response ଦେଖେ)

Guardrails ଗୁଡ଼ିକ OmniRoute ଏବଂ upstream provider ମାନଙ୍କ ମଧ୍ୟରେ ଥିବା ସୀମାରେ ସୁରକ୍ଷା, ନୀତି ଏବଂ ବିଷୟବସ୍ତୁ ରୂପାନ୍ତରଣ ଲାଗୁ କରନ୍ତି। ପ୍ରତ୍ୟେକ guardrail request payload (`preCall`) ଏବଂ upstream response (`postCall`) ଯାଞ୍ଚ କରିପାରେ (ଏବଂ ଇଚ୍ଛାନୁସାରେ ପ୍ରତ୍ୟାଖ୍ୟାନ, ରୂପାନ୍ତର କିମ୍ବା annotate କରିପାରେ)।

ଏହି ବ୍ୟବସ୍ଥା **fail-open** ଅଟେ: ଯଦି ଗୋଟିଏ guardrail ଚାଲିବା ସମୟରେ error ପକାଏ, registry ସେହି error ରେକର୍ଡ କରେ ଏବଂ request ବିଫଳ ନକରି ପରବର୍ତ୍ତୀ guardrail ସହିତ ଆଗକୁ ବଢ଼େ। Blocking ଏକ ସ୍ପଷ୍ଟ ନିଷ୍ପତ୍ତି (`block: true`), କେବେବି ଦୁର୍ଘଟଣା ନୁହେଁ। ଏକମାତ୍ର ବ୍ୟତିକ୍ରମ ହେଉଛି abort ହୋଇଥିବା request: ଯେତେବେଳେ caller ର `signal` abort ହୁଏ, error ପକାଉଥିବା guardrail skip ହେବା ପରିବର୍ତ୍ତେ hook run କୁ reject କରେ।

hooks ଗୁଡ଼ିକ ପ୍ରତ୍ୟେକ route କିମ୍ବା ପ୍ରତ୍ୟେକ response ରେ ଚାଲନ୍ତି **ନାହିଁ**। ଗୋଟିଏ guardrail କୁ ସୁରକ୍ଷା ନିୟନ୍ତ୍ରଣ ଭାବରେ ବ୍ୟବହାର କରିବା ପୂର୍ବରୁ [କଭରେଜ୍ ଏବଂ ସୀମାଗୁଡ଼ିକ](#coverage-and-limits) ପଢ଼ନ୍ତୁ।

### ଭିଜନ୍ ବ୍ରିଜ୍ (`visionBridge.ts`) — ମୋଡାଲିଟି ବ୍ରିଜ୍ PR-1

GLM 5.3 ଆଧାର ମଡେଲ ଏବଂ `glm-5.3-{low,high,max}` ସ୍ପଷ୍ଟ `supportsVision:false` registry/spec ମେଟାଡାଟା ଅଛି। GLM 5.3 ଫ୍ଲାସ ପ୍ରକାରଗୁଡ଼ିକ ଦେଶୀ-ଦର୍ଶନ ମଡେଲ ହୋଇ ରହିଥାଏ। Claude କୋଡ୍ ର `/v1/messages` ମାର୍ଗ ଅଂଶୀଦାରିତ `handleChat` ପ୍ରି-କଲ୍ ଗାର୍ଡେଲ୍ ଚେନରେ ପ୍ରବେଶ କରେ।** ପୂର୍ବରୁ** କ୍ଲୋଡ୍-ଟୁ- OpenAI ଅନୁବାଦ; nested `Read` ଟୁଲ୍-ଫଳାଫଳ ପ୍ରତିଛବିଗୁଡ଼ିକୁ ବର୍ଣ୍ଣନା କରାଯିବା କିମ୍ବା ନିୟନ୍ତ୍ରଣ କରିବା ପୂର୍ବରୁ ସେହି ଅନୁବାଦ ସେମାନଙ୍କୁ OpenAI `image_url` ବିଷୟବସ୍ତୁ (#17069) କୁ ଉଠାଇବା ପୂର୍ବରୁ।

ଲକ୍ଷ୍ୟ ରଖାଯାଇଥିବା ପ୍ରତିଛବି ଧାରଣ ଅନୁରୋଧକୁ ବାଧା ଦେଇଥାଏ।** ଅଣ-ଦର୍ଶନ ମଡେଲଗୁଡିକ।** ଏବଂ ସମଗ୍ର ଅନୁରୋଧକୁ ଏକ ଦର୍ଶନ-ସକ୍ଷମ ମଡେଲକୁ ପୁନ er ମାର୍ଗ କରେ କିମ୍ବା ଅପଷ୍ଟ୍ରିମ୍ କଲ୍ ପୂର୍ବରୁ ଏକ ବିନ୍ୟାସଯୋଗ୍ୟ ଭିଜନ୍ ମଡେଲ୍ ଦ୍ୱାରା ଉତ୍ପାଦିତ ପାଠ୍ୟ ବର୍ଣ୍ଣନା ସହିତ ପ୍ରତିଛବି ଅଂଶଗୁଡ଼ିକୁ ବଦଳାଇଥାଏ। ଏହା କେବଳ ଟେକ୍ସଟ୍ ପ୍ରଦାନକାରୀଙ୍କୁ ସ୍ୱଚ୍ଛ ଭାବରେ ମଲ୍ଟିମୋଡାଲ୍ ପେଲୋଡ୍ ପରିଚାଳନା କରିବାକୁ ଦିଏ।

ପ୍ରବାହ:

1. ଯଦି ଟାର୍ଗେଟ୍ ମଡେଲ୍ ପୂର୍ବରୁ ଦର୍ଶନକୁ ସମର୍ଥନ କରେ (ଯଦି ଏହା ବାଧ୍ୟତାମୂଳକ ବ୍ରିଜ୍ ତାଲିକାରେ `isVisionBridgeForcedModel` ରେ ଦେଖାଯାଏ ନାହିଁ) ଛାଡିଦିଅ।
2. `extractImageParts(messages)` (`visionBridgeHelpers.ts`) ମାଧ୍ୟମରେ ପ୍ରତିଛବି ଅଂଶଗୁଡିକ ବାହାର କରନ୍ତୁ, ଯାହାକି ପ୍ରତିନିଧିତ୍ୱ କରେ।** ୟୁନିଫାଏଡ୍ ମିଡିଆ ଡିଟେକ୍ଟର।** `open-sse/utils/mediaParts.ts` `detectMediaParts()` — ଏକକ ଉତ୍ସ କମ୍ବୋ ସୁସଙ୍ଗତତା ଫିଲ୍ଟର୍ ସହିତ ଅଂଶୀଦାର। `replaceImageParts` ଆକୃତିଗୁଡିକ ପାଇଁ ଏକ୍ସଟ୍ରାକସନ୍ ଅନୁମତି ପ୍ରାପ୍ତ ହୋଇଛି (ଏକ୍ସଟ୍ରାକ୍ଟ ↔ ବଦଳ ଚୁକ୍ତି): OpenAI `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"`, ଏବଂ Responses API `input_image`। Claude କୋଡ୍ `tool_result.content` ଏବଂ ରେସପନ୍ସ ଟୁଲ୍ ଆଉଟପୁଟ୍ ଭିତରେ ବାନ୍ଧିଥିବା ପ୍ରତିଛବିଗୁଡିକ ମେଳ କରିବା ମଧ୍ୟ ସେମାନଙ୍କର ମୂଳ ପଥରେ ବାହାର କରାଯାଇଥାଏ। ସୂଚକ-କେବଳ ଆକୃତିଗୁଡ଼ିକ କମ୍ବୋ-ଫିଲ୍ଟର ସାମଗ୍ରୀ ଏବଂ ବାହାର କରାଯାଇ ନାହିଁ। ଯଦି କେହି ନ ପାଇଲେ ଛାଡିଦିଅ।
3. `resolveVisionBridgeRuntimeSettings()` (`src/shared/constants/modalityBridgeDefaults.ts`) ମାଧ୍ୟମରେ ଚାଲିବା ସମୟ ବିନ୍ୟାସ ସମାଧାନ କରନ୍ତୁ: ନୂତନ `modalityBridge*` ସେଟିଂସମୂହ କୀ ଜିତେ; ପୁରୁଣା `visionBridge*` କିଗୁଡ଼ିକ ଗୋଟିଏ ହୋଇ ରହିଥାଏ।** ଗୋଟିଏ ଚକ୍ରର ପତନ।** (ରୋଲବ୍ୟାକ୍ ୱିଣ୍ଡୋ)। ବ୍ରିଜ୍ ଅକ୍ଷମ ହେଲେ କ media ଣସି ମିଡିଆ ଟ୍ରାଭର୍ସାଲ୍ ପୂର୍ବରୁ ଛାଡିଦିଅ।
4. ମୋଡ୍ ଚୟନକର୍ତ୍ତା (`modalityBridgeVisionMode`, ନିମ୍ନରେ ସାରଣୀ ଦେଖନ୍ତୁ) ମାର୍ଗଦର୍ଶନ ବନାମ ବର୍ଣ୍ଣନା କରେ। ରେରୁଟ୍ `modifiedPayload` କେବଳ `model` ଅଦଳବଦଳ ସହିତ ମେଟା `{ rerouted, fromModel, toModel, imagesKept }` ସହିତ ରିଟର୍ନ କରେ।
5. ପଥ ବର୍ଣ୍ଣନା କରନ୍ତୁ: `maxImages` ରେ କ୍ୟାପ୍ ପ୍ରତିଛବିଗୁଡିକ, ଟାସ୍କ-ସଚେତନ ପ୍ରମ୍ପ୍ଟ ରଚନା କରନ୍ତୁ, ବର୍ଣ୍ଣନା କ୍ୟାଶେ ସହିତ ପରାମର୍ଶ କରନ୍ତୁ, ଦର୍ଶନ ମଡେଲକୁ ଡାକନ୍ତୁ।** ସମାନ୍ତରାଳ ଭାବରେ।** (`Promise.allSettled`), ଏବଂ `[Image N]: <description>` ପାଠ୍ୟ ଅଂଶଗୁଡ଼ିକୁ ସେମାନଙ୍କ ସ୍ଥାନରେ ଇଞ୍ଜେକ୍ସନ ଦିଅନ୍ତୁ। ଏକ ବିଫଳ ବର୍ଣ୍ଣନା `null` ଅମଳ କରେ: କଞ୍ଚା ପ୍ରତିଛବି unknown/vision-capable ଲକ୍ଷ୍ୟ (#4012) ପାଇଁ ସଂରକ୍ଷିତ, କିନ୍ତୁ a** ନିଶ୍ଚିତ ପାଠ୍ୟ-ପ୍ରତ୍ୟକ୍ଷ ଲକ୍ଷ୍ୟ।** କିମ୍ବା ଶୂନ-ଭିଜନ୍ କମ୍ବୋ ପ୍ରତ୍ୟେକ ଅନାବଶ୍ୟକ ପ୍ରତିଛବି ପାଇଁ ଏକ ସ୍ପଷ୍ଟ `(unavailable — no vision-capable provider connected)` ଟେକ୍ସଟ୍ ଷ୍ଟବ୍ ପାଇଥାଏ, ଆଂଶିକ ବିଫଳତା ଏବଂ ବର୍ଣ୍ଣନା-କଲ୍ କ୍ୟାପ୍ (#17069) ବାହାରେ ଥିବା ପ୍ରତିଛବିଗୁଡ଼ିକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରି। ବିଦ୍ୟମାନ ସମସ୍ତ ବିଫଳ କମ୍ବୋ ଫଲବ୍ୟାକ୍ ବର୍ଣ୍ଣନା କରେ (#8430)।
6. `modifiedPayload` + ମେଟା (`imagesProcessed`, `descriptions`, `processingTimeMs`, `visionModel`) ଫେରସ୍ତ କରନ୍ତୁ।

#### API- କି ପରିସର (`visionBridgeKeyScope.ts`)

ଯେତେବେଳେ କଲର୍ ର API କି `allowedConnections`, କୋଟା ପୁଲ୍ (`allowedQuotas`) କିମ୍ବା ମଡେଲଗୁଡିକ (`allowedModels` / `blockedModels` / `modelAccessMode: "restricted"` / `disableNonPublicModels`) କୁ ପ୍ରତିବନ୍ଧିତ କରେ, ସେତେବେଳେ ବ୍ରିଜ୍ କେବଳ ମାର୍ଗଦର୍ଶନ କରେ ଏବଂ ଚାବି ବ୍ୟବହାର କରୁଥିବା ସଂଯୋଗଗୁଡ଼ିକରେ ଚାବି ବ୍ୟବହାର କରୁଥିବା ମଡେଲଗୁଡ଼ିକୁ ବର୍ଣ୍ଣନା କରେ। ବର୍ଣ୍ଣନା କଲ୍ ତାପରେ ସର୍ବଦା `x-omniroute-self-loop-key-id` ହେଡର୍ ସହିତ OmniRoute ସେଲ୍ଫ୍-ଲୁପ୍ ଦେଇ ଯାଏ, ତେଣୁ ଗ୍ରହଣ କରୁଥିବା ଚାଟ୍ ଅନୁରୋଧ ସେହି ଚାବିର ସଂଯୋଗ ଏବଂ ମଡେଲ୍ ନୀତିକୁ ପୁନର୍ବାର କାର୍ଯ୍ୟକାରୀ କରେ। `enforceApiKeyPolicy()` ସେହି ହେଡର୍ କୁ କେବଳ ସେଲ୍-ଲୁପ୍ ଧାରକ ସହିତ ସମ୍ମାନିତ କରେ, ତେଣୁ ଏହା କେବଳ ସଂକୀର୍ଣ୍ଣ ପ୍ରବେଶ କରିପାରିବ, ଏବଂ ଏକ id ଯାହା ସମାଧାନ କରେ ନାହିଁ ପ୍ରତ୍ୟାଖ୍ୟାନ।

ଯଦି ଚାବି ପାଇଁ କ vision ଣସି ଦର୍ଶନ ମଡେଲ ଅନୁମତିପ୍ରାପ୍ତ ନୁହେଁ, a** ନିଶ୍ଚିତ ପାଠ୍ୟ-ଲକ୍ଷ୍ୟ।** ଏକ ଅକ୍ଷମ ଅପଷ୍ଟ୍ରିମ୍ (#17069) କୁ ଇମେଜ୍ ବାଇଟ୍ ପଠାଇବା ପରିବର୍ତ୍ତେ ଏକ ସ୍ୱଚ୍ଛ HTTP 400 ସହିତ ସ୍ଥାନୀୟ ଭାବରେ ପ୍ରତିଛବି ଅନୁରୋଧକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। ଅଜ୍ unknown ାତ କିମ୍ବା ଦେଶୀ ଦର୍ଶନ କ୍ଷମତା ଥିବା ଲକ୍ଷ୍ୟଗୁଡ଼ିକ ପାଇଁ, ବର୍ଣ୍ଣନା ପଥ ଏହାର ପୂର୍ବ ବିଫଳ-ଖୋଲା ଆଚରଣ (ମେଟା `{ skipped: true, reason: "no_permitted_vision_model" }`) ରଖେ। ଏକ ଚାବି ବିନା ଅନୁରୋଧ, ଏବଂ ଏହି ପ୍ରତିବନ୍ଧକ ବିନା ଚାବିଗୁଡ଼ିକ ପୂର୍ବ ପରି ଆଚରଣ କରେ।

#### କାର୍ଯ୍ୟ-ସଚେତନ ବର୍ଣ୍ଣନା ପ୍ରମ୍ପ୍ଟ (`modalityBridgeVisionTaskAware`)

ଡିଫଲ୍ଟ।** ସତ** । `composeVisionPrompt()` (`visionBridgeHelpers.ts`) ଟେକ୍ସଟ୍ କୁ ଯୋଡିଥାଏ।** ଶେଷ ବ୍ୟବହାରକାରୀ ବାର୍ତ୍ତା।** (500 ଅକ୍ଷରରୁ ଛୋଟ) ବେସକୁ ପ୍ରମ୍ପ୍ଟ ବର୍ଣ୍ଣନା କରେ, ଉପଭୋକ୍ତା ପ୍ରକୃତରେ ଯାହା ପଚାରିଥିଲେ (କୋଡେକ୍ସ-ଭିଜନ-ପ୍ରକ୍ସି ପ୍ୟାଟର୍) ଆଡକୁ ବର୍ଣ୍ଣନା ପରିଚାଳନା କରନ୍ତି ଏବଂ ଦୃଶ୍ୟମାନ ପାଠ୍ୟକୁ ଟ୍ରାନ୍ସକ୍ରିପସନ୍ କରିବାକୁ ଭିଜନ୍ ମଡେଲକୁ କୁହନ୍ତି। — ଫ୍ଲାଗ୍ ଅଫ୍ କିମ୍ବା କ user ଣସି ଉପଭୋକ୍ତା ପାଠ୍ୟ — ସହିତ ବେସ୍ ପ୍ରମ୍ପ୍ଟ ଅପରିବର୍ତ୍ତିତ ଭାବରେ ବ୍ୟବହୃତ ହୁଏ।

ସ୍ self- ଲୁପ୍ ର ନିଜସ୍ୱ OpenAI- ସୁସଙ୍ଗତ ଅନୁରୋଧ ( `visionBridgeHelpers.ts` ରେ`callVisionModelSingle()` ) ସର୍ବଦା `image_url.detail: "high"` — ବିନା ସର୍ତ୍ତରେ ଅନୁରୋଧ କରେ, ପ୍ରତ୍ୟେକ caller/provider ପାଇଁ, କ client ଣସି କ୍ଲାଏଣ୍ଟ ସିଗନାଲରେ ଗେଟ୍ ହୋଇନଥାଏ। ନିମ୍ନ-ସବିଶେଷ ନମୁନାକରଣ ଏହି ପ୍ରମ୍ପ୍ଟ ମାଗୁଥିବା ପାଠ୍ୟ-ଟ୍ରାନ୍ସକ୍ରିପସନ୍ କାର୍ଯ୍ୟ ପାଇଁ OCR ସଠିକତାକୁ ଖରାପ କରିଥାଏ, ତେଣୁ ବର୍ଣ୍ଣନାକାରୀ କଲ୍ ନିଜେ ସର୍ବଦା ଉଚ୍ଚ ବିବରଣୀ ପାଇଁ ପଚାରିଥାଏ ଯାହା ମୂଳ ଇନବାଉଣ୍ଡ ଅନୁରୋଧ ବ୍ୟବହୃତ ହୋଇଛି। ଏହା କେବଳ ଆଭ୍ୟନ୍ତରୀଣ ବର୍ଣ୍ଣନା ଅନୁରୋଧ ଶରୀରକୁ ପ୍ରଭାବିତ କରେ; ପ୍ରାଥମିକ ଅନୁରୋଧ — ଉପରେ OmniRoute କିପରି କଲରର ନିଜସ୍ୱ `image_url.detail` ଅଗ୍ରଗତି କରେ ତାହା ପରିବର୍ତ୍ତନ କରେ ନାହିଁ ଯାହା ଡିଫଲ୍ଟ ପୃଥକ ଭାବରେ ପ୍ରୟୋଗ ହୁଏ, ଏବଂ କେବଳ OpenCode କ୍ଲାଏଣ୍ଟମାନଙ୍କ ପାଇଁ, `defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`) ରେ। ବର୍ଣ୍ଣନା ସେଲ୍-ଲୁପ୍ ର Anthropic ତାର-ଫର୍ମାଟ୍ ଶାଖାର କ `detail` କ୍ଷେତ୍ର ନାହିଁ ଏବଂ ଉଭୟ ଡିଫଲ୍ଟ ଦ୍ୱାରା ପ୍ରଭାବିତ ନୁହେଁ।

`0` (ଡିଫଲ୍ଟ) ଅର୍ଥ।** କ cap ଣସି କ୍ୟାପ୍ ନାହିଁ।** — `callVisionModel()` returned ାରା ଫେରସ୍ତ ହୋଇଥିବା ବର୍ଣ୍ଣନା ବିଦ୍ୟମାନ ଆଚରଣକୁ ସଂରକ୍ଷଣ କରି ଅଣମୋଡିଫାଏଡ୍ ମାଧ୍ୟମରେ ପାସ୍ ହୋଇଛି। 100-50000 ପରିସରର ଯେକ Any ଣସି ମୂଲ୍ୟ `[Image N]: <description>` ( `src/lib/guardrails/visionBridge.ts` ରେ`VisionBridgeGuardrail.preCall()` ) ଭାବରେ ବିଭାଜିତ ହେବା ପୂର୍ବରୁ `…` ସଫିକ୍ସ ସହିତ ବର୍ଣ୍ଣନାକୁ ଛୋଟ କରିଥାଏ। ସବିଶେଷ-ଭାରୀ OCR କାର୍ଯ୍ୟଗୁଡ଼ିକ ପାଇଁ ଏହାକୁ ଉଠାନ୍ତୁ ଯେଉଁଠାରେ ଡାଉନ୍ଷ୍ଟ୍ରିମ୍ ମଡେଲ୍ ପୂର୍ଣ୍ଣ ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ଆବଶ୍ୟକ କରେ। ଚାଟି ଭିଜନ ମଡେଲଗୁଡିକରେ ଏହାକୁ ଟୋକେନ୍ ବ୍ୟବହାରରେ କମ୍ କରନ୍ତୁ। ଡ୍ୟାସବୋର୍ଡ ଫିଲ୍ଡ ଭିଜନ୍ ଟ୍ୟାବ୍ର ଆଡଭାନ୍ସ ପ୍ୟାନେଲ୍ ( `ModalityBridgeVisionTab.tsx` ରେ`modality-bridge-max-chars` ) ରେ ବାସ କରେ ଏବଂ 1 ରୁ 99 ମଧ୍ୟରେ 100 ମହଲା ପର୍ଯ୍ୟନ୍ତ ଯେକ any ଣସି ମୂଲ୍ୟକୁ ବନ୍ଦ କରିଦିଏ ଯେତେବେଳେ ଏକ ସ୍ପଷ୍ଟ `0` ଅସ୍ପୃଶ୍ୟ — `0` ନିଜ ଅଧିକାରରେ (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`) ଏକ ବ valid Zod ମୂଲ୍ୟ ଅଟେ, କେବଳ “ସେଟ୍” ଡିଫଲ୍ଟ ନୁହେଁ।

#### କ୍ୟାଚ୍ (`modalityBridge/bridgeCache.ts`) ବର୍ଣ୍ଣନା କର।

ଫଳାଫଳକୁ ବର୍ଣ୍ଣନା କରିବା ପାଇଁ ଇନ-ମେମୋରୀ LRU + TTL କ୍ୟାଶେ, ଅଂଶୀଦାର ପ୍ରକ୍ରିୟା-ପ୍ରଶସ୍ତ। ଦ length ର୍ଘ୍ୟ-ଉପସର୍ଗ ଫ୍ରେମ୍ ସହିତ କୀ = `sha256(imageRef + composedPrompt + configuredBridgeModel)` (କ field ଣସି କ୍ଷେତ୍ର-ସୀମା ଧକ୍କା ନାହିଁ)। ମଡେଲ୍ ଉପାଦାନ ହେଉଛି** ବିନ୍ୟାସିତ** ବ୍ରିଜ୍ ମଡେଲ୍, ପ୍ରକୃତରେ — `callVisionModel` ଉତ୍ତର ଦେଇଥିବା ମଡେଲ୍ ଆଭ୍ୟନ୍ତରୀଣ ଭାବରେ ପଛକୁ ଫେରିପାରେ, ଏବଂ ପ୍ରତି ପ୍ରୟାସରେ ଚାବି କ୍ୟାଚ୍ ଖଣ୍ଡ ଖଣ୍ଡ କରିଦେବ। ବିଫଳ ବର୍ଣ୍ଣନା କଦାପି କ୍ୟାଚ୍ ହୋଇନଥାଏ। ସେଟିଂସମୂହ:

| ଚାବି                            | ଡିଫଲ୍ଟ। | ପରିସର   |
| ------------------------------- | ------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`  | —       |
| `modalityBridgeCacheTtlMinutes` | `60`    | 1–1440  |

#### ସୁଦୂର ପ୍ରତିଛବି ସାଧାରଣକରଣ (ସେଲ୍-ଲୁପ୍ describe/base64 ଫେଚ୍)

ଯେତେବେଳେ ସେତୁ ଆଣେ a** ସୁଦୂର** ପ୍ରତିଛବି ନିଜେ — Anthropic ସ୍ୱୟଂ କଲ୍ ଏବଂ କ୍ଲାଉଡ୍-ତାର-ଫର୍ମାଟ୍ ବେସ୍ 64 ରୂପାନ୍ତର (`ensureBase64ImagesForClaudeWire`) କୁ ବର୍ଣ୍ଣନା କରେ, ଉଭୟ `fetchRemoteImageAsDataUri()` ମାଧ୍ୟମରେ `visionBridgeHelpers.ts` — ରେ ଫଳାଫଳ ତଥ୍ୟ URI ଦର୍ଶନ-ମଡେଲ ଅନୁରୋଧରେ ଏମ୍ବେଡ୍ ହେବା ପୂର୍ବରୁ `normalizeDataUri()` (`open-sse/utils/imageNormalize.ts`) ମାଧ୍ୟମରେ ପଠାଯାଇଥାଏ। ଓଭରସାଇଜ୍ ହୋଇଥିବା ପ୍ରତିଛବିଗୁଡ଼ିକ a କୁ ଡାଉନସ୍କାଲ୍ ହୋଇଛି।** 2048px ଲମ୍ବା ଧାର।** (ରିଜାଇଜ୍ କ୍ୟାପ୍ OpenAI/Anthropic ସହିତ ମେଳ ହେବା ପୂର୍ବରୁ ସର୍ଭର-ସାଇଡ୍ ପ୍ରୟୋଗ କରେ), ଯାହା ଭିଜନ୍ ମଡେଲ୍ ଯାହା ଦେଖେ ତାହା ପରିବର୍ତ୍ତନ ନକରି bytes/latency ଅପଲୋଡ୍ କାଟେ। ଆକାର ପରିବର୍ତ୍ତନ `sharp` ବ୍ୟବହାର କରେ, ଗତିଶୀଳ ଆମଦାନୀ ମାଧ୍ୟମରେ ଲୋଡ୍: ଏକ ପ୍ଲାଟଫର୍ମରେ ଯେଉଁଠାରେ ଏହାର ଦେଶୀ ବାଇନାରୀ ଲୋଡ୍ କରିବାରେ ବିଫଳ ହୁଏ, `normalizeDataUri()`** କଦାପି ଫୋପାଡେ ନାହିଁ।** — ଏହା ମୂଳ ବାଇଟ୍ ର ଏକ ପଥକୁ ଫେରିଯାଏ, ତେଣୁ describe/base64-conversion ପଥ ସର୍ବଦା କାର୍ଯ୍ୟ କରିଥାଏ। ଅଣ-ପ୍ରତିଛବି ବାଇଟ୍ (ଏକ ଫେଚ୍ ଯାହା ଏକ ଡିକୋଡେବଲ୍ ଇମେଜ୍ ଫେରସ୍ତ କରିନଥିଲା) ମଧ୍ୟ ଅସ୍ପୃଶ୍ୟ ମାଧ୍ୟମରେ ପାସ୍ ହୁଏ। ଏହି ସ୍ ization ାଭାବିକତା ବ୍ରିଜ୍ ନିଜସ୍ call- କଲ୍ — ପାଇଁ ଚିତ୍ରଗୁଡ଼ିକ ପାଇଁ ସ୍କୋପ୍ ହୋଇଛି, ଏହା କଲରଙ୍କ କଞ୍ଚା ପାସ୍ଟ୍ରୋ ପେଲୋଡ୍ ଉପରେ କଦାପି ପ୍ରୟୋଗ କରାଯାଏ ନାହିଁ, କେବଳ ଅପ୍ଟ-ଇନ୍-ମ୍ୟୁଟେସନ୍ ନୀତି (ହାର୍ଡ ନିୟମ #20) ସହିତ ସମାନ।

#### ସେଟିଙ୍ଗ୍ ସ୍କିମା + ସ୍ଥାନାନ୍ତରଣ।

ନୂତନ `modalityBridge*` କିଗୁଡ଼ିକ `updateSettingsSchema` (`src/shared/validation/settingsSchemas.ts`) ରେ Zod- ବ valid ଧ ହୋଇଛି: `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCache*` ତ୍ରି, ଏବଂ ଅଡିଓ ବ୍ରିଜ୍ ଦ୍ୱାରା ବ୍ୟବହୃତ `modalityBridgeAudio*` ଗୋଷ୍ଠୀ। ସ୍ଥାନାନ୍ତରଣ `141_modality_bridge_settings.sql` ବିଦ୍ୟମାନ ପୁରୁଣା `visionBridge*` ମୂଲ୍ୟଗୁଡ଼ିକୁ ମେଳ ଖାଉଥିବା ନୂତନ କିଗୁଡ଼ିକରେ ନକଲ କରିଥାଏ (idempotent, କେବେବି ଅପରେଟର୍-ସେଟ୍ `modalityBridge*` ମୂଲ୍ୟକୁ ଓଭର୍ ରାଇଟ୍ କରେ ନାହିଁ); ଉତ୍ତରାଧିକାରୀ ଚାବିଗୁଡ଼ିକ ଗୋଟିଏ ପ୍ରକାଶନ ଚକ୍ର ପାଇଁ ଏକ ପଠନ ଫଲବ୍ୟାକ୍ ଭାବରେ ଗ୍ରହଣୀୟ।

#### ସ୍ୱଚ୍ଛତା ହେଡର୍ + ପରିସଂଖ୍ୟାନ।

ବର୍ଣ୍ଣନା-ରୂପାନ୍ତରିତ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` ବହନ କରେ ( `modalityBridge/bridgeStats.ts` ରେ `buildModalityBridgeHeader()` ଦ୍ୱାରା ନିର୍ମିତ, `src/sse/handlers/chatHelpers.ts` ରେ `withModalityBridgeHeader()` ଦ୍ୱାରା ଷ୍ଟାମ୍ପ୍)। ମାର୍ଗଦର୍ଶନ ଅନୁରୋଧ ପ୍ରାପ୍ତ ହୁଏ।** ନା** ହେଡର୍ — ପେଲୋଡ୍ ଅସ୍ପୃଶ୍ୟ ଥିଲା ଏବଂ ମଡେଲ୍ ଅଦଳବଦଳ ପ୍ରତିକ୍ରିୟା ଶରୀରର `model` କ୍ଷେତ୍ରରେ ଦୃଶ୍ୟମାନ ହୋଇସାରିଛି।

`GET /api/modality-bridge/stats` (ମ୍ୟାନେଜମେଣ୍ଟ auth, `GET /api/settings` ସହିତ ସମାନ ସ୍ତର) `vision`, `audio`, ଏବଂ `video` ପାଇଁ ଇନ-ମେମୋରୀ ପ୍ରତି-ମୋଡାଲିଟି କାଉଣ୍ଟର `{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs, latencySamples, averageLatencyMs, lastUsedAt }` ଫେରସ୍ତ କରେ। `averageLatencyMs` `latencySamples` ବ୍ୟବହାର କରେ, ସମସ୍ତ ପ୍ରୟାସ ନୁହେଁ, ଏହାର ନାମ ଭାବରେ; ସମୟ ବିନା ଏକ ଅପରେସନ୍ ଏକ ଶୂନ-ମିଲିସେକେଣ୍ଡ ନମୁନା ତିଆରି କରେ ନାହିଁ। ସଫଳ ରୂପାନ୍ତର ପାଇଁ `bridged` ପଛୁଆ-ସୁସଙ୍ଗତ ଛଦ୍ମନାମ ହୋଇ ରହିଥାଏ; ବିଫଳ ପ୍ରୟାସ ଏହାକୁ ବୃଦ୍ଧି କରେ ନାହିଁ। ଡିଜାଇନ୍ (ଟେଲିମେଟ୍ରି, ଆକାଉଣ୍ଟିଂ ନୁହେଁ) ଦ୍ୱାରା ପ୍ରକ୍ରିୟା ପୁନ rest ଆରମ୍ଭରେ କାଉଣ୍ଟରଗୁଡ଼ିକ ପୁନ res ସେଟ୍ ହୁଏ।

#### ଡ୍ୟାସବୋର୍ଡ ବିନ୍ୟାସ

ଉତ୍ସର୍ଗୀକୃତ ଡ୍ୟାସବୋର୍ଡ ପୃଷ୍ଠା ହେଉଛି `/dashboard/settings/modality-bridge`। ଏହାର URL- ଠିକଣା ଯୋଗ୍ୟ `Vision`, `Audio`, ଏବଂ `Video` ଟ୍ୟାବଗୁଡ଼ିକ `tab` ମୂଲ୍ୟ ପରିବର୍ତ୍ତନ କରିବା ସମୟରେ ଜିଜ୍ଞାସା ପାରାମିଟରଗୁଡ଼ିକୁ ସଂରକ୍ଷଣ କରିଥାଏ। ଭିଜନ୍ ଟ୍ୟାବ୍ ସାମର୍ଥ୍ୟ, ମୋଡ୍, ମଡେଲ୍ ଚୟନ (ସ୍ୱୟଂଚାଳିତ ଡିଫଲ୍ଟ ଅନ୍ତର୍ଭୂକ୍ତ କରି), ଟାସ୍କ-ସଚେତନ ପ୍ରମ୍ପ୍ଟିଙ୍ଗ୍, ଉନ୍ନତ timeout/image/description-length/cache ସୀମା, ଚାଲିବା ସମୟ କାଉଣ୍ଟର ଏବଂ ଏକ ଜଗୁଆଳି ନମୁନା ଅନୁରୋଧକୁ ପ୍ରକାଶ କରେ। ଅଡିଓ ଟ୍ୟାବ୍ ମଧ୍ୟ ଲାଇଭ୍: ଏହା ସାମର୍ଥ୍ୟ, ଅଟୋ, timeout/max-clip ସୀମା, ଅଡିଓ କାଉଣ୍ଟର ଏବଂ ଏକ `input_audio` ନମୁନା ପରୀକ୍ଷଣ ସହିତ ଏକ STT- କେବଳ ମଡେଲ୍ ପିକର୍ ପ୍ରକାଶ କରେ। ଭିଡିଓ ଟ୍ୟାବ୍ କାର୍ଯ୍ୟକ୍ଷମ: ଏହା FFmpeg/ffprobe ରନ୍ଟାଇମ୍ ଷ୍ଟେଟ୍ — କୁ ଚାରୋଟି ସ୍ପଷ୍ଟ UI ରାଜ୍ୟ ମଧ୍ୟରୁ ଗୋଟିଏ (`unknown` ଯେତେବେଳେ ଯାତାୟାତ ଉଡ଼ାଣରେ ଅଛି କିମ୍ବା ସଂପୂର୍ଣ୍ଣ ହୋଇପାରିବ ନାହିଁ, `restricted` ଏକ ଅଣ-ଲୁପବ୍ୟାକ୍ ଡ୍ୟାସବୋର୍ଡ ହୋଷ୍ଟରେ ଯେଉଁଠାରେ ଅନୁସନ୍ଧାନ କ୍ଲାଏଣ୍ଟ ପାର୍ଶ୍ୱକୁ ଛାଡିଦିଆଯାଏ, `unavailable` ଥରେ ଯାଞ୍ଚ କରାଯାଇଥାଏ ଏବଂ ନିଖୋଜ ହୋଇଯାଏ, କିମ୍ବା FFmpeg/ffprobe ଭିଡ଼ିଓ ମଡେଲଗୁଡିକ `available` ସ୍ଥିର କରିଥାଏ, — ସ୍ଥିର କରିଥାଏ enable/model/frame/video/timeout

AI ସେଟିଙ୍ଗ୍ ଅନ୍ତର୍ଗତ ପୂର୍ବ ଭିଜନ୍ ବ୍ରିଜ୍ କାର୍ଡ ହେଉଛି ନୂତନ ପୃଷ୍ଠା ସହିତ ଏକ ସୁସଙ୍ଗତତା ଲିଙ୍କ୍। ଏହା ଆଉ ଫର୍ମର ଦ୍ୱିତୀୟ କପି ର ମାଲିକାନା ନୁହେଁ। ମିଡିଆ ପ୍ରଦାନକାରୀମାନେ ବିଦ୍ୟମାନ ସ୍ପିଚ୍-ଟୁ-ଟେକ୍ସଟ୍ ଖେଳ ପଡିଆକୁ ଅପସାରଣ ନକରି ଇମେଜ୍-ଟୁ-ଟେକ୍ସଟ୍ ଏବଂ ସ୍ପିଚ୍-ଟୁ-ଟେକ୍ସଟ୍ ୱାର୍କଫ୍ଲୋକୁ ସଂପୃକ୍ତ ମୋଡାଲିଟି ବ୍ରିଜ୍ ଟ୍ୟାବଗୁଡ଼ିକ ସହିତ ଲିଙ୍କ କରନ୍ତି।

**ସେଲ୍ଫ୍ ଲୁପ୍ ଆଡମିଶନ ବାଇପାସ୍:** ଯେତେବେଳେ OmniRoute ର ନିଜସ୍ୱ `/v1` ସେଲ୍-ଲୁପ୍ (ଅଣ-ମାନକ ପ୍ରଦାନକାରୀ ମଡେଲ୍) ମାଧ୍ୟମରେ କଲ୍ ରୁଟ୍ ବର୍ଣ୍ଣନା କରେ, ସବ୍-ଅନୁରୋଧ `x-omniroute-admission-bypass: internal` ପଠାଏ ଏବଂ ସମାଧାନ ହୋଇଥିବା ସେଲ୍-ଲୁପ୍ ପ୍ରମାଣପତ୍ର — ସ୍ଥାନୀୟ ମୋଡ୍ ରେ ସ୍ଥାନୀୟ `sk_omniroute` ସେଣ୍ଟିନେଲ ସହିତ ପ୍ରାମାଣିକୃତ ହୁଏ, କିମ୍ବା ଅପରେଟର-ବିନ୍ୟାସିତ `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` env କି (#1350) ତେଣୁ `REQUIRE_API_KEY=true` ନିୟୋଜନଗୁଡ଼ିକ ବର୍ଣ୍ଣନା କଲ୍ ଚଲାଇପାରେ। ବାଇପାସ୍ କେବଳ ସେହି ସଠିକ ପ୍ରମାଣପତ୍ର ପାଇଁ ସମ୍ମାନିତ, ତେଣୁ ବାହ୍ୟ ଗ୍ରାହକମାନେ ଆଡମିଶନ ଛାଡିବାକୁ ହେଡର୍ ବ୍ୟବହାର କରିପାରିବେ ନାହିଁ।

ପୁରୁଣା ଡିଫଲ୍ଟ `src/shared/constants/visionBridgeDefaults.ts` ରେ ରୁହନ୍ତି; ନୂତନ mode/task-aware/cache ଡିଫଲ୍ଟ ଏବଂ ସେଟିଂସମୂହ ସମାଧାନକାରୀ `src/shared/constants/modalityBridgeDefaults.ts` ରେ ଲାଇଭ୍। ରାକ୍ଷୀ ଏକ `deps` କନଷ୍ଟ୍ରକ୍ଟର ବିକଳ୍ପକୁ ଉନ୍ମୋଚନ କରେ ତେଣୁ ପରୀକ୍ଷଣ ନକଲି `getSettings` ଏବଂ `callVisionModel` ପ୍ରୟୋଗକୁ ଇଞ୍ଜେକ୍ସନ ଦେଇପାରେ।

### ଅଡିଓ ବ୍ରିଜ୍ (`audioBridge.ts`) — ମୋଡାଲିଟି ବ୍ରିଜ୍ PR-3

ଅଡିଓ-ଭାରୀ ଚାଟ୍ ଅନୁରୋଧକୁ ସେମାନେ ଏକ ଲକ୍ଷ୍ୟସ୍ଥଳରେ ପହଞ୍ଚିବା ପୂର୍ବରୁ ବାଧା ଦିଅନ୍ତି ଯାହା ଅଡିଓ ଇନପୁଟ୍ ଗ୍ରହଣ କରିବାକୁ ଜଣା ନାହିଁ। ଏହା କଦାପି ଚାଟ୍ ଅନୁରୋଧକୁ ପୁନ er ମାର୍ଗ କରେ ନାହିଁ: ଅଡିଓ ଅଂଶଗୁଡିକ ବିଦ୍ୟମାନ OpenAI- ସୁସଙ୍ଗତ ମଲ୍ଟିପାର୍ଟ ଏଣ୍ଡପଏଣ୍ଟ ମାଧ୍ୟମରେ ଟ୍ରାନ୍ସକ୍ରିପ୍ସିତ ହୋଇଛି ଏବଂ ମନୋନୀତ ଚାଟ୍ ମଡେଲ୍ ପାଠ୍ୟ ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ସହିତ ଜାରି ରହିଛି।

ପ୍ରବାହ:

1. `getResolvedModelCapabilities()` ମାଧ୍ୟମରେ `supportsAudio` ସମାଧାନ କରନ୍ତୁ। ସ୍ପଷ୍ଟ ପ୍ରଦାନକାରୀ-ରେଜିଷ୍ଟ୍ରି ମେଟାଡାଟା ଜିତେ, ତାପରେ ଷ୍ଟାଟିକ୍ ମଡେଲ୍ ମେଟାଡାଟା, ତାପରେ `modalities_input` ସିଙ୍କ୍ ହେଲା। `audio` ବିନା ଘୋଷିତ ଇନପୁଟ୍ ତାଲିକା ହେଉଛି `false`; କ ability ଣସି ସାମର୍ଥ୍ୟ ପ୍ରମାଣ `null` ରୁହେ ନାହିଁ। ଉଭୟ `false` ଏବଂ `null` ରକ୍ଷଣଶୀଳ ସେତୁକୁ ସକ୍ରିୟ କରୁଥିବାବେଳେ `true` ଏହାକୁ ବାଇପାସ୍ କରିଥାଏ।
2. `modalityBridgeAudio*` ସେଟିଂସମୂହର ସମାଧାନ କରନ୍ତୁ ଏବଂ ଅଂଶୀଦାରିତ `detectMediaParts()` ଡିଟେକ୍ଟର ମାଧ୍ୟମରେ ପ୍ରତ୍ୟେକ ସନ୍ଦେଶରୁ ବିଭାଜିତ ଶୀର୍ଷ ସ୍ତରୀୟ ଅଡିଓ ଅଂଶଗୁଡିକ ବାହାର କରନ୍ତୁ। ସମର୍ଥିତ ତାର ଆକୃତିଗୁଡ଼ିକ ହେଉଛି OpenAI `input_audio`, `audio_url`, ଏବଂ `source.media_type: "audio/*"`। ନେଷ୍ଟେଡ୍ ଅଡିଓ ରାଉଟିଙ୍ଗ୍ ପାଇଁ ଚିହ୍ନଟ ହୁଏ କିନ୍ତୁ ବିଭାଜନ ପଥ ଦ୍ୱାରା ଅପସାରିତ ହୁଏ ନାହିଁ। କାର୍ଯ୍ୟ `modalityBridgeAudioMaxClips` ଦ୍ୱାରା କ୍ୟାପ୍ ହୋଇଛି; ପରବର୍ତ୍ତୀ ଅଂଶଗୁଡିକ ଅସ୍ପୃଶ୍ୟ ରହିଥାଏ।
3. ଏକ ବିନ୍ୟାସିତ `provider/model` ସମ୍ମାନ ଦିଅନ୍ତୁ, କିମ୍ବା `selectAudioBridgeModel()` `AUDIO_TRANSCRIPTION_PROVIDERS` ସ୍ଥିର କାଟାଲଗ୍ କ୍ରମରେ ଚାଲିବାକୁ ଦିଅନ୍ତୁ ଏବଂ ଏକ ବ୍ୟବହାରଯୋଗ୍ୟ ସକ୍ରିୟ ପ୍ରଦାନକାରୀ ପ୍ରମାଣପତ୍ର ସହିତ ପ୍ରଥମ ମଡେଲ୍ ଚୟନ କରନ୍ତୁ।
4. `callAudioTranscription()` base64/data-URI ଅଡିଓକୁ ଏକ ମଲ୍ଟିପାର୍ଟ `file` ରେ ରୂପାନ୍ତର କରିଥାଏ, କିମ୍ବା DNS ପିନିଙ୍ଗ ଏବଂ 25 MB ବନ୍ଧା ସହିତ ସର୍ବସାଧାରଣ-କେବଳ ଆଉଟବାଉଣ୍ଡ ଗାର୍ଡ ମାଧ୍ୟମରେ ଏକ ସୁଦୂର `audio_url` ଡାଉନଲୋଡ୍ କରେ। ଏହା ପରେ POSTs ଫାଇଲ୍ ଏବଂ `resolveSelfLoopBearer()` ସହିତ ପ୍ରାମାଣିକୃତ ସ୍ଥାନୀୟ `/v1/audio/transcriptions` ସେଲ୍ଫ-ଲୁପ୍ କୁ ମନୋନୀତ ମଡେଲ୍। ବିଦ୍ୟମାନ ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ରୁଟ୍ ସାଧାରଣ ପରିଚୟ ସନ୍ଧାନ, cooldown/rate-limit ହ୍ୟାଣ୍ଡଲିଂ ଏବଂ ପ୍ରଦାନକାରୀ ପଠାଇବା କାର୍ଯ୍ୟ କରିଥାଏ।
5. ସଫଳ କଲ୍ ସେମାନଙ୍କର ଅଂଶଗୁଡ଼ିକୁ `[Audio N]: <transcript>` ସହିତ ବଦଳାଇଥାଏ। `Promise.allSettled` ସହିତ କଲ୍ ଚାଲିଥାଏ: ଏକ ବ୍ୟକ୍ତିଗତ ବିଫଳତା ସେହି ମୂଳ ଅଡିଓ ଅଂଶ (#4012 ଚୁକ୍ତି) ସଂରକ୍ଷଣ କରେ। ଯଦି ପ୍ରତ୍ୟେକ କଲ୍ ବିଫଳ ହୁଏ ଏବଂ ଲକ୍ଷ୍ୟ `supportsAudio === false` ପ୍ରମାଣିତ ହୁଏ, ଅଂଶଗୁଡ଼ିକ `[Audio N]: (unavailable — no STT provider connected)` ହୋଇଯାଏ (#8430 ଚୁକ୍ତି)। ଏକ ଅଜ୍ଞାତ ଲକ୍ଷ୍ୟ (`null`) ପାଇଁ, ଏକ ବିଫଳତା ଫଳାଫଳ ଅସ୍ପୃଶ୍ୟ ରହିଥାଏ। କ us ଣସି ବ୍ୟବହାରଯୋଗ୍ୟ STT ପ୍ରମାଣପତ୍ର ସହିତ ଏକ ପ୍ରମାଣିତ ପାଠ୍ୟ-ଲକ୍ଷ୍ୟ କେବଳ ନେଟୱର୍କ କଲ୍ ପ୍ରଦାନ ନକରି ସମାନ ସ୍ପଷ୍ଟ ଷ୍ଟବ୍ ଗ୍ରହଣ କରେ।

ସଫଳ ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ପ୍ରକ୍ରିୟା-ମୋଡାଲିଟି ବ୍ରିଜ୍ LRU/TTL କ୍ୟାଚ୍ ବ୍ୟବହାର କରେ। ଚାବି ଅଡିଓ ରେଫରେନ୍ସ, ସ୍ଥିର `audio-transcription` ଅପରେସନ୍ ଲେବଲ୍ ଏବଂ ମନୋନୀତ STT ମଡେଲକୁ ଏକତ୍ର କରେ। ବିଫଳତା କଦାପି କ୍ୟାଚ୍ ହୋଇନଥାଏ। ଅଡିଓ ଅଂଶୀଦାର `bridged`, `cacheHits`, `failures`, ଏବଂ `lastUsedAt` କାଉଣ୍ଟରଗୁଡ଼ିକୁ ଅଦ୍ୟତନ କରିବାକୁ ଚେଷ୍ଟା କରେ। ପରିବର୍ତ୍ତିତ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ `x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ବହନ କରେ; ଅସ୍ପୃଶ୍ୟ ଅନୁରୋଧଗୁଡିକ ଏକ ଅଡିଓ ବ୍ରିଜ୍ ସେଗମେଣ୍ଟ୍ ଗ୍ରହଣ କରେ ନାହିଁ।

### ଭିଡିଓ ବ୍ରିଜ୍ (`videoBridge.ts`, `videoBridgePipeline.ts`)

ଜଣାଶୁଣା ଦେଶୀ ଭିଡିଓ ସମର୍ଥନ ବିନା ଏକ ଲକ୍ଷ୍ୟ ପୂର୍ବରୁ ଚାଟ୍ ସମାପ୍ତି `messages` ଏବଂ Responses API `input` ରେ ଶୀର୍ଷ ସ୍ତରୀୟ ଭିଡିଓ ଅଂଶଗୁଡ଼ିକୁ ବାଧା ଦେଇଥାଏ। ସମର୍ଥିତ ଆକୃତିଗୁଡ଼ିକ ହେଉଛି `input_video`, `video_url`, `video_source`, HTTPS URLs, ଏବଂ `data:video/*;base64,...` ଡାଟା URIs। ପାଠ୍ୟରେ ସରଳ ଫାଇଲନାମଗୁଡିକ ଭିଡିଓ ଭାବରେ ଗ୍ରହଣ କରାଯାଏ ନାହିଁ।

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) ଅନୁରୋଧ ଟ୍ରାଭର୍ସାଲ୍, capability/policy ଯାଞ୍ଚ, ପ୍ରତି ଅନୁରୋଧ ଏଗ୍ରିଗେସନ୍ ଏବଂ ପ୍ରତିକ୍ରିୟା ପେଲୋଡ୍ ର ମାଲିକ। ପ୍ରତି-ଭିଡିଓ କାର୍ଯ୍ୟ — ଅଧିଗ୍ରହଣ, ସମ୍ପୂର୍ଣ୍ଣ ଫଳାଫଳ କ୍ୟାଚ୍, ଏକ ଫ୍ରେମ୍ କ୍ରମକୁ ବର୍ଣ୍ଣନା କରେ (ଯାହା କ any ଣସି କଲର୍ ଘୋଷିତ ଅଡିଓ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟକୁ ଫ୍ୟୁଜ୍ କରେ), ଏବଂ ପ୍ରତି ପ୍ରୟାସ metrics/abort/cleanup — `videoBridgePipeline.ts` ରେ `processVideoPart` ପଛରେ ଲୁକ୍କାୟିତ, `preCall` ର ଲୁପ୍ ଭିତରେ ପ୍ରତି ଭିଡିଓ ଅଂଶକୁ ଥରେ କୁହାଯାଏ। ସେହି ମଡ୍ୟୁଲ୍ ସ୍ପଷ୍ଟ ପୋର୍ଟ ସୀମା `VideoMediaBrokerPort` (ବାଇଟ୍ ହାସଲ କରିବା ଏବଂ ନମୁନା ଫ୍ରେମ୍ ବାହାର କରିବା), `VideoAudioTranscriptionPort` (ନମୁନା କ୍ୟାପ୍ସନ୍ ସହିତ ଏକ କଲର୍ ଘୋଷିତ ଅଡିଓ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟକୁ ଫ୍ୟୁଜ୍ କରିବା) ଏବଂ `VideoDrilldownPort` (ପୁରୁଣା କଞ୍ଚା-ଷ୍ଟୋର ଆକୃତି) କୁ ମଧ୍ୟ ବ୍ୟାଖ୍ୟା କରେ। ଉତ୍ପାଦନ STT ଏବଂ ଫ୍ରେମ୍ ଧାରଣ `createVideoSttAdapter` ଏବଂ `createVideoDrilldownAdapter` ମାଧ୍ୟମରେ ବର୍ଣ୍ଣନାକାରୀ ପୋର୍ଟ ଚାରିପାଖରେ ରଚନା କରାଯାଇଛି। ଶେଷଟି ଅଂଶୀଦାରୀ ଅସ୍ପଷ୍ଟ-ହ୍ୟାଣ୍ଡଲ୍ ଲାଇଫ୍ ସାଇକେଲ୍ ବ୍ୟବହାର କରେ।

ସାର୍ବଜନୀନ `/v1` ଅନୁରୋଧ ପଥ କେବେବି ଏକ ସବ୍-ପ୍ରୋସେସ୍ ଆମଦାନି କରେ ନାହିଁ କିମ୍ବା ଆହ୍ୱାନ କରେ ନାହିଁ। ସୁଦୂର ଭିଡିଓଗୁଡିକ 50 MiB ବନ୍ଧନରେ ଡାଉନଲୋଡ୍ ହୋଇଛି; ଇନଲାଇନ୍ ବେସ୍ 64 ଭିଡିଓଗୁଡିକରେ ଏକ ରକ୍ଷଣଶୀଳ 36 MiB ଡିକୋଡେଡ୍ ପ୍ରତି ଭିଡିଓ କ୍ୟାପ୍ ଅଛି ତେଣୁ model/messages/framing ଏନଭଲପ୍ ସର୍ବସାଧାରଣ JSON ଅନୁରୋଧ 50 MiB ଭିତରେ ରହିପାରିବ। ଆବଣ୍ଟନ ପୂର୍ବରୁ ଇନଲାଇନ ଲମ୍ବ ଏବଂ ଡିକୋଡେଡ୍ ଆକାରର ଆକଳନ ଯାଞ୍ଚ କରାଯାଏ। HTTPS ପ୍ରାରମ୍ଭିକ ରିମୋଟ URL ଏବଂ ପ୍ରତ୍ୟେକ ପୁନ ir ନିର୍ଦ୍ଦେଶରେ ଆବଶ୍ୟକ, DNS ପିନିଙ୍ଗ ସହିତ ବିଦ୍ୟମାନ ଜନସାଧାରଣ-କେବଳ ଆଉଟବାଉଣ୍ଡ ଗାର୍ଡ ବ୍ୟବହାର କରି। ବାଇଟ୍ ତା’ପରେ ସଠିକ୍ ଆଭ୍ୟନ୍ତରୀଣ `POST /api/modality-bridge/video/extract` ଦଲାଲ୍ ସୀମା ଅତିକ୍ରମ କରେ। ସେହି ମାର୍ଗଟି ଉଭୟ `LOCAL_ONLY` ଏବଂ `SPAWN_CAPABLE` ଅଟେ, କେବଳ ପ୍ରତି-ପ୍ରକ୍ରିୟା ପ୍ରାମାଣିକୃତ, ବିଶ୍ୱସ୍ତ-ଲୁପବ୍ୟାକ୍ ଅନୁରୋଧ ଗ୍ରହଣ କରେ, ଏବଂ URL, ଫାଇଲ୍ ସିଷ୍ଟମ୍ ପଥ, ଏକଜେକ୍ୟୁଟେବଲ୍, କିମ୍ବା ଆର୍ଗୁମେଣ୍ଟ ତାଲିକା ଗ୍ରହଣ କରେ ନାହିଁ। API ଶରୀର ଆକାରର ପାଇପଲାଇନ ଏବଂ ହ୍ୟାଣ୍ଡେଲର ବର୍ଦ୍ଧିତ ଶରୀର ପାଠକ ସ୍ ently ାଧୀନ ଭାବରେ ଏକ 50 MiB ଦଲାଲ ଇନପୁଟ୍ କ୍ୟାପ୍ ବାଧ୍ୟତାମୂଳକ କରେ। ଏହାର ସୀମାବଦ୍ଧ ଧାଡି ଏକ ସମୟରେ ଗୋଟିଏ ନିଷ୍କାସନ ଚଲାଇଥାଏ, ଚାରୋଟି ବିଚାରାଧୀନ କାର୍ଯ୍ୟକୁ ଅନୁମତି ଦିଏ, ଏବଂ 100 MiB ରେ ଇନପୁଟ୍ ବିଚାରାଧୀନ କ୍ୟାପ୍।

ଅର୍ଥଗତ କ୍ୟାପସନ୍ ଫୋକସ୍ ହେଉଛି ଏକ ପୃଥକ, ସ୍ପଷ୍ଟ ସେଟିଂ। ଡିଫଲ୍ଟ `full` ବିଶ୍ଳେଷଣ ମୋଡ୍ ବିଦ୍ୟମାନ ଫ୍ରେମ୍ ପ୍ରମ୍ପ୍ଟକୁ ସଂରକ୍ଷଣ କରେ ଏବଂ କ୍ୟାପସନ୍ ମଡେଲକୁ ଅନୁରୋଧ ପାଠ୍ୟକୁ କେବେବି ଅଗ୍ରଗାମୀ କରେ ନାହିଁ। `focused` ମୋଡ୍ ରେ, ବ୍ରିଜ୍ କେବଳ ସମାନ ଚାଟ୍ କିମ୍ବା ରେସପନ୍ସ କଣ୍ଟେନରରୁ ସର୍ବଶେଷ ଖାଲି ବ୍ୟବହାରକାରୀ-ଲେଖକ `text`/`input_text` ପ read େ, ଏହାକୁ NFC ରେ ସ୍ izes ାଭାବିକ କରେ, କଣ୍ଟ୍ରୋଲ୍ ବର୍ଣ୍ଣ ଏବଂ ହ୍ ites ାଇଟସ୍ପେସ୍କୁ ଭାଙ୍ଗି ଦିଏ ଏବଂ ଏହାକୁ 500 ୟୁନିକୋଡ୍ କୋଡ୍ ପଏଣ୍ଟରେ ସୀମିତ କରେ। ଏକ ଖାଲି ଫଳାଫଳ ସଠିକ୍ `full` ପ୍ରମ୍ପ୍ଟକୁ ଫେରିଯାଏ। ଏକ ବ୍ୟବହାରଯୋଗ୍ୟ ସୂଚନା ଏକ ଉତ୍ସର୍ଗୀକୃତ ଅବିଶ୍ୱାସୀ-ଉପଭୋକ୍ତା-ପ୍ରସଙ୍ଗ ବ୍ଲକରେ JSON ଭାବରେ କ୍ରମିକ ହୋଇଛି ଏବଂ କେବଳ ପର୍ଯ୍ୟବେକ୍ଷଣଯୋଗ୍ୟ ବିବରଣୀକୁ ପ୍ରାଥମିକତା ଦେଇପାରେ। ମିଡିଆରେ ଦୃଶ୍ୟମାନ କିମ୍ବା ଶ୍ରବଣଯୋଗ୍ୟ ନିମ୍ନଲିଖିତ ନିର୍ଦ୍ଦେଶଗୁଡ଼ିକ ବିରୁଦ୍ଧରେ ଏହା ପୃଥକ ଚେତାବନୀକୁ ନବଲିଖନ କରିପାରିବ ନାହିଁ। ପାଠ୍ୟ ଧ୍ୟାନ କେବେବି `start`/`end` କୁ ସଂକ୍ରମିତ କରେ ନାହିଁ କିମ୍ବା ସାମୟିକ ନମୁନାକୁ ପରିବର୍ତ୍ତନ କରେ ନାହିଁ।

#### FU-07 ଗଠନମୂଳକ ବିଭାଗ ପ୍ରମାଣ।

`segment_aware` ପୂର୍ବରୁ ବ valid ଧ ହୋଇଥିବା ସ୍ଥାନୀୟ ଭିଡିଓ ଷ୍ଟ୍ରିମ୍ ଉପରେ ଗୋଟିଏ ସୀମିତ ପ୍ରି-ଆନାଲିସିସ୍ ପାସ୍ ବ୍ୟବହାର କରେ। ସ୍ଥିର ଫିଲ୍ଟର ଶୃଙ୍ଖଳା ପ୍ରଥମେ ସର୍ବାଧିକ 320 ପିକ୍ସେଲ ଚଉଡା, ଦୃଶ୍ୟ ପରିବର୍ତ୍ତନ ଏବଂ ଫ୍ରିଜ୍ ବ୍ୟବଧାନ ଚିହ୍ନଟ କରେ, ତାପରେ ଅସ୍ପଷ୍ଟ, ହାରାହାରି ଲୁମା, ଏବଂ spatial/temporal ସୂଚନା ପାଇଁ ସେକେଣ୍ଡରେ 1 ଫ୍ରେମରେ ନମୁନା। ପାସ୍ 600 ଷ୍ଟ୍ରକଚରାଲ୍ ନମୁନା, ଗୋଟିଏ FFmpeg/filter ଥ୍ରେଡ୍, ସମାନ `file` -only ପ୍ରୋଟୋକଲ୍ ଏବଂ କଣ୍ଟେନର ଅନୁମତି ତାଲିକା, 1 MiB ପ୍ରକ୍ରିୟା-ଆଉଟପୁଟ୍ ସୀମିତ, ଏବଂ ଦଲାଲର ଅଂଶୀଦାରିତ abort/deadline. ଭିତରେ ପ୍ରାୟ 30 ସେକେଣ୍ଡରେ ଏହା ଅନୁରୋଧରୁ କ command ଣସି ନିର୍ଦ୍ଦେଶ, ଫିଲ୍ଟର, ପଥ, କିମ୍ବା URL ଗ୍ରହଣ କରେ ନାହିଁ।

ଗଠନମୂଳକ ମୂଲ୍ୟଗୁଡ଼ିକ ହେଉଛି ନିର୍ଣ୍ଣୟକାରୀ ନମୁନା ପ୍ରମାଣ, ଅର୍ଥଗତ ଭିଡିଓ ବୁ understanding ାମଣା ନୁହେଁ। ସେମାନେ ବିଷୟ, କାର୍ଯ୍ୟ, କ୍ୟାପସନ୍, ବକ୍ତବ୍ୟ, କିମ୍ବା ଉପଭୋକ୍ତା ଉଦ୍ଦେଶ୍ୟ ବିଷୟରେ ଅନୁମାନ କରନ୍ତି ନାହିଁ। ଦୃଶ୍ୟ ଏବଂ ଫ୍ରିଜ୍ ସୀମା ଗଠନ କରେ; ଫ୍ରିଜ୍ କଭରେଜ୍, ଅସ୍ପଷ୍ଟ, ଏକ୍ସପୋଜର୍, ସ୍ଥାନିକ ବିବରଣୀ, ଏବଂ ସାମୟିକ ପରିବର୍ତ୍ତନ କେବଳ ବିଦ୍ୟମାନ 1-16 ଫ୍ରେମ୍ ବଜେଟ୍ କିପରି ଆବଣ୍ଟିତ ହୁଏ ତାହା ପ୍ରଭାବିତ କରେ। ଏକ ଫ୍ରିଜ୍ ସେଗମେଣ୍ଟ୍ ଗୋଟିଏ ଫ୍ରେମ୍ରେ କ୍ୟାପ୍ ହୋଇଥିବାବେଳେ ଅବଶିଷ୍ଟ ଫ୍ରିଜ୍ ସେଗମେଣ୍ଟଗୁଡିକ ଅବଶିଷ୍ଟ ବଜେଟ୍ ପାଇଁ ପ୍ରତିଦ୍ୱନ୍ଦ୍ୱିତା କରନ୍ତି। ଯେତେବେଳେ ସୀମା ଫ୍ରେମ୍ ଅତିକ୍ରମ କରେ, ୟୁନିଫର୍ମ ଟାଇମଲାଇନ୍ କଭରେଜ୍ ରଖାଯାଏ ତେଣୁ ଶୀଘ୍ର ଶୀଘ୍ର କଟ୍ ଏକ ଲମ୍ବା ଟ୍ରେଲିଂ ସେଗମେଣ୍ଟ ଲୁଚାଇ ପାରିବ ନାହିଁ। ଏକ ଫ୍ରିଜ୍ ସୀମାର 1 ସେକେଣ୍ଡ୍ ବିଶ୍ଳେଷଣ ରିଜୋଲ୍ୟୁସନ୍ ମଧ୍ୟରେ ଦୃଶ୍ୟ ସୀମା ଏକତ୍ରିତ।

ସଂଗ୍ରହକାରୀମାନେ ମେମୋରୀରେ ପ୍ରତିକ୍ରିୟା ସ୍କୋର କରିବା ଉଚିତ ଏବଂ `responseDigest` ପ୍ଲସ୍ ମେଟ୍ରିକ୍ସ ଏବଂ ପର୍ଯ୍ୟବେକ୍ଷଣ ବନ୍ଧନଗୁଡ଼ିକୁ ସଂରକ୍ଷଣ କରିବା ଉଚିତ, କଦାପି ପ୍ରତିକ୍ରିୟା ପାଠ୍ୟ। ଗ୍ରାହକ ମଧ୍ୟ ପୁରୁଣା କଞ୍ଚା ପର୍ଯ୍ୟବେକ୍ଷଣ ପ read ନ୍ତି କିନ୍ତୁ ସେହି ପାଠ୍ୟକୁ କେବେବି ଏହାର ରିପୋର୍ଟରେ କପି କରନ୍ତି ନାହିଁ। ପ୍ରତ୍ୟେକ ପର୍ଯ୍ୟବେକ୍ଷଣ ପାଇଁ `responseDigest` କିମ୍ବା `rawResponseText` ମଧ୍ୟରୁ ଗୋଟିଏ ଗ୍ରହଣୀୟ। ସଂସ୍କରଣଯୋଗ୍ୟ ଅନୁମତି ତାଲିକା ଏକ ଅକ୍ଷୟ `hold` ଡିଫଲ୍ଟ ସହିତ ଖାଲି ରହିଥାଏ। ଏକ ଯୋଗ୍ୟ ପ୍ରବେଶ ଏହାର ପ୍ରମାଣ ରେଫରେନ୍ସ, ନୀତି, ମଡେଲ୍ ସଂଶୋଧନ, ସଠିକ୍ ପ୍ରାର୍ଥୀ SHA, ମନିଫେଷ୍ଟ୍ ହଜମ ଏବଂ ଦୁଇଟି ଭିନ୍ନ ରନ୍ IDs ଆବଶ୍ୟକ କରେ। ବିବାଦୀୟ ପ୍ରସଙ୍ଗଗୁଡିକ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଇଛି। ଏହି ମେଟାଡାଟା ହେଉଛି ଏକ ଅଡିଟ୍ ଚୁକ୍ତି, ଏକ ପ୍ରମାଣ ନୁହେଁ ଯେ ଏକ ରେଫରେନ୍ସ ଫାଇଲ୍ ପ୍ରକୃତ ମାପ ଧାରଣ କରିଥାଏ। କ any ଣସି ଏଣ୍ଟ୍ରି ଯୋଡିବା ପୂର୍ବରୁ ପ୍ରକୃତ ରସିଦ ସମୀକ୍ଷା କରନ୍ତୁ। ମ୍ୟାନେଜମେଣ୍ଟ ପରିସଂଖ୍ୟାନ ଏଣ୍ଡପଏଣ୍ଟ ଏବଂ ଭିଡିଓ ଡ୍ୟାସବୋର୍ଡ ରକ୍ଷଣଶୀଳ ପ୍ରସ୍ତୁତିକୁ ପ୍ରକାଶ କରେ। ଏକ ବିନ୍ୟାସିତ ମଡେଲ ଛଦ୍ମନାମ କେବଳ ଏହାର ସଂଶୋଧନ କିମ୍ବା ଚାଲୁଥିବା ପ୍ରାର୍ଥୀ SHA ପ୍ରତିଷ୍ଠା କରେ ନାହିଁ, ତେଣୁ ବର୍ତ୍ତମାନର ଡ୍ୟାସବୋର୍ଡ ଅନ୍ୟ ନିଷ୍ପାଦନ ପ୍ରସଙ୍ଗରୁ ଯୋଗ୍ୟତାକୁ ପୁନ using ବ୍ୟବହାର କରିବା ପରିବର୍ତ୍ତେ `HOLD` ରିପୋର୍ଟ କରେ। ସ୍ପଷ୍ଟ ପରୀକ୍ଷାମୂଳକ ଚୟନ ପଦୋନ୍ନତି ଠାରୁ ଅଲଗା ରହିଥାଏ; କ default ଣସି ଡିଫଲ୍ଟ ସ୍ୱୟଂଚାଳିତ ଭାବରେ ପରିବର୍ତ୍ତିତ ହୁଏ ନାହିଁ।

କଲର୍ମାନେ ଏକ ସମର୍ଥିତ ଭିଡିଓ ଅଂଶରେ ଏକ ବ al କଳ୍ପିକ `transcript.cues` ଆରେ ସଂଲଗ୍ନ କରିପାରନ୍ତି ଯେତେବେଳେ ସେମାନେ ପୂର୍ବରୁ ସଜ୍ଜିତ ପାଠ୍ୟ ଧାରଣ କରନ୍ତି। ପ୍ରତ୍ୟେକ କ୍ୟୁ ନିଶ୍ଚିତ ଭାବରେ `text`, ଯାଞ୍ଚ ସମୟ ମଧ୍ୟରେ ଏକ ସୀମିତ `start`/`end` ବ୍ୟବଧାନ, ଏବଂ ଏକ ଧଳା ତାଲିକାଭୁକ୍ତ `source` (`client`, `embedded`, କିମ୍ବା `audio-bridge`) ବହନ କରିବା ଆବଶ୍ୟକ। `confidence` `1` କୁ ଡିଫଲ୍ଟ କରେ ଏବଂ `0` ଏବଂ `1` ମଧ୍ୟରେ ରହିବା ଜରୁରୀ। ପ୍ରକୃତ ନକଲ ସୂତ୍ରଗୁଡ଼ିକ ଭୁଶୁଡି ପଡିଛି। OmniRoute ଏହି ମେଟାଡାଟା ଠାରୁ କଦାପି ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ଆରମ୍ଭ କରେ ନାହିଁ: ବ valid ଧ ବ c ଶିଷ୍ଟ୍ୟଗୁଡିକ ଉତ୍ସ, ଆତ୍ମବିଶ୍ୱାସ ଏବଂ ବ୍ୟବଧାନ ସହିତ ବର୍ଣ୍ଣିତ ଫଳାଫଳରେ କପି କରାଯାଇଥାଏ, ଏବଂ ଫ୍ରେମ୍ କ୍ୟାପସନ୍ ସହିତ ଅବିଶ୍ୱାସନୀୟ ପର୍ଯ୍ୟବେକ୍ଷଣ ଭାବରେ ଉପସ୍ଥାପିତ ହୁଏ। କ୍ୟାପସନ୍ ଷ୍ଟ୍ରିମ୍ରେ ମିଶ୍ରିତ ହେବା ପରିବର୍ତ୍ତେ ଅବ val ଧ, ବାହାରେ, କିମ୍ବା ପ୍ରୋଭାନ୍ସମୁକ୍ତ ପାଠ୍ୟ ପ୍ରତ୍ୟାଖ୍ୟାନ। ଉଭୟ ଅନୁରୋଧ-ଶରୀର ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ଚ୍ୟାନେଲଗୁଡ଼ିକ `client` କୁ ଯୋଗାଇ ଦିଆଯାଇଥିବା ପ୍ରୋଭାନ୍ସକୁ ସ୍ ize ାଭାବିକ `embedded` କିମ୍ବା `audio-bridge` ଲେବଲ୍ ଅନ୍ତର୍ଭୁକ୍ତ କରେ। କେବଳ ଏକ ସର୍ଭର-ମାଲିକାନା ଆଡାପ୍ଟର ସେହି ବିଶ୍ୱସ୍ତ ଲେବଲ୍ଗୁଡ଼ିକୁ କେବଳ କୋଡ୍- `trustedSource` ଆର୍ଗୁମେଣ୍ଟ ମାଧ୍ୟମରେ ନ୍ୟସ୍ତ କରିପାରିବ। ଏକ ଅନୁରୋଧ JSON କ୍ଷେତ୍ର ସେହି ଯୁକ୍ତିରେ ପହଞ୍ଚିପାରିବ ନାହିଁ। ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ପାଠ୍ୟ ଅବିଶ୍ୱାସନୀୟ ମିଡିଆ-ଉତ୍ପାଦିତ ବିଷୟବସ୍ତୁ ହୋଇ ରହିଥାଏ, ଏହାର ପ୍ରମାଣକୁ ଖାତିର ନକରି, ଏବଂ କଦାପି ପ୍ରାଧିକରଣ ନିର୍ଣ୍ଣୟ କରିବା ଉଚିତ୍ ନୁହେଁ।

ଏକ ଉନ୍ନତ କଲର୍ ସମାନ ଭିଡିଓ ପାଇଁ ଏକ `audioTranscript` ଟ୍ରାକ୍ ପ୍ରଦାନ କରିପାରନ୍ତି। ଏହାକୁ କ୍ଲାଏଣ୍ଟ-ପ୍ରଦାନ କରାଯାଇଥିବା ପାଠ୍ୟ ଭାବରେ ଗ୍ରହଣ କରାଯାଏ, ସର୍ଭର ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ର ପ୍ରମାଣ ନୁହେଁ। ଫ୍ୟୁଜନ୍ ସିମ୍ ଏକ ସମୟସୀମା ଅଧୀନରେ ଭିଜୁଆଲ୍ ଏବଂ ଅଡିଓ ପର୍ଯ୍ୟବେକ୍ଷଣଗୁଡିକ ଚଲାଇଥାଏ ଏବଂ ସିଗନାଲ୍ ପରିତ୍ୟାଗ କରେ, ସେମାନଙ୍କୁ ଏକ ସାଧାରଣ ଟାଇମଲାଇନ୍ରେ ଅର୍ଡର କରେ, ସଠିକ୍ ନକଲଗୁଡିକ ଭାଙ୍ଗିଯାଏ ଏବଂ କେବଳ ଗୋଟିଏ ପାର୍ଶ୍ୱ ସଫଳ ହେଲେ ଆଂଶିକ ଫଳାଫଳ ରିପୋର୍ଟ କରେ। ଏକ ଅବ alid ଧ `audioTranscript` ସେହି ଆଂଶିକ ଫଳାଫଳ — କୁ ଭିଜୁଆଲ୍ ବର୍ଣ୍ଣନାକୁ ରଖେ ଏବଂ ଅଡିଓ ଶାଖା ପୁରା ଭିଡିଓ ବିଫଳ ହେବା ପରିବର୍ତ୍ତେ ଏକ ସାନିଟାଇଜଡ୍ ବିଫଳତା କୋଡ୍ — ରେକର୍ଡ କରେ। ଶାଖା ପ୍ରତି ଉପଲବ୍ଧତା, ଆଂଶିକ ପତାକା, ଏବଂ ସାନିଟାଇଜଡ୍ ବିଫଳତା ସଂକେତଗୁଡିକ ବର୍ଣ୍ଣିତ ଫଳାଫଳରେ, ରାକ୍ଷୀ ମେଟାଡାଟା (`audioFusionRuns`/`audioFusionPartials`/ `audioFusionFailureCodes`), ଫଳାଫଳ-କ୍ୟାଚ୍ ମେଟାଡାଟା ଏବଂ ବ୍ରିଜ୍ ଫ୍ୟୁଜନ୍ କାଉଣ୍ଟରରେ ସଂରକ୍ଷିତ। ଡିଫଲ୍ଟ ଭିଡିଓ ବ୍ରିଜ୍ ପଥ ବାଣୀ-ଟୁ-ଟେକ୍ସଟ୍ କିମ୍ବା ଦ୍ୱିତୀୟ ମିଡିଆ କପି ଡାଉନଲୋଡ୍ କରେ ନାହିଁ; ସେହି ସ୍ପଷ୍ଟ ଟ୍ରାକ ବିନା, ଏହା କେବଳ ଭିଡିଓ-ରହିଥାଏ।

ଅତିରିକ୍ତ ରଖାଯାଇଥିବା ନକଲଗୁଡ଼ିକ ସମାନ ପର୍ଯ୍ୟବେକ୍ଷଣ-ଅନୁରୋଧ ସଙ୍କେତ ବ୍ୟବହାର କରନ୍ତି। କଞ୍ଚା ପ୍ରି-ଗାର୍ଡେଲ୍ କ୍ଲାଏଣ୍ଟ-ଅନୁରୋଧ ସ୍ନାପସଟ୍, ମେମୋରୀ ବିଚାରାଧୀନ ଅନୁରୋଧ, ଏବଂ ଶୀଘ୍ର ପ୍ରତ୍ୟାଖ୍ୟାନ-ଅନୁରୋଧ ଲଗ୍ ଗଠନମୂଳକ ଭାବରେ ଭିଡିଓ ଅଂଶରେ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ଫିଲ୍ଡଗୁଡ଼ିକୁ ବଦଳାଇଥାଏ। ପାଇପଲାଇନ ପର୍ଯ୍ୟାୟ ଦ୍ synt ାରା ସିନ୍ଥାଇଜ୍ ହୋଇଥିବା ଷ୍ଟ୍ରିଙ୍ଗ୍ ପ୍ରମ୍ପ୍ଟ ଏବଂ ସ୍ଥିର-ଅନୁରୋଧ-ବଡି ସିଙ୍କରେ ପ୍ରସଙ୍ଗ ହ୍ୟାଣ୍ଡଅଫ୍ ରିଡାକ୍ଟ କରାଯାଇଥାଏ। ସ୍ଥିର ହୋଇଥିବା `video_content_removed` ମାର୍କର, ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବରେ ପରିତ୍ୟାଗ ହୋଇଥିବା ପାଠ୍ୟକୁ ପୁନ str ନିର୍ମାଣ କରିବା ପରିବର୍ତ୍ତେ `previous_response_id` ଜାରିକୁ ବନ୍ଦ କରିବାରେ ବିଫଳ କରିଥାଏ। ଯଦି ଏକ ପର୍ଯ୍ୟବେକ୍ଷଣ କରାଯାଇଥିବା ଅନୁରୋଧ ଲଗିଂ କରିବା ପୂର୍ବରୁ ଏହାର ପ୍ରତି-ଅଂଶ ରିଡାକସନ ଛାୟା ହରାଇଥାଏ, କିମ୍ବା ପରବର୍ତ୍ତୀ ଅନୁରୋଧ ପରିବର୍ତ୍ତନ ପରେ ଅନେକ ଭିଡିଓ ଛାୟା ମଧ୍ୟରୁ ଗୋଟିଏ ମଧ୍ୟ ମେଳ କରିବାରେ ବିଫଳ ହୁଏ, ତେବେ ଆଂଶିକ ରିଡାକ୍ଟ ହୋଇଥିବା ଟ୍ରାନ୍ସକ୍ରିପଟ ରଖିବା ପରିବର୍ତ୍ତେ ରଖାଯାଇଥିବା ଅନୁରୋଧ ସଂସ୍ଥା ସଂପୂର୍ଣ୍ଣ ଭାବରେ ବାଦ ଦିଆଯାଇଛି।

ଏକ ନିରୀକ୍ଷଣ ଅନୁରୋଧ ପାଇଁ, ଏକ ମଡେଲ୍ ପ୍ରତିକ୍ରିୟା ହୁଏତ ଏକ ସଂରଚନା କ୍ୟୁ ସୀମା ବିନା ଟ୍ରାନ୍ସକ୍ରିପ୍ଟର ଯେକ portion ଣସି ଅଂଶକୁ ଉଦ୍ଧୃତ କରିପାରେ। ଏହାର ସ୍ଥାୟୀ କଲ୍-ଲଗ୍ `responseBody` ତେଣୁ ଏକ ବର୍ଜନ ମାର୍କର୍ ଦ୍ୱାରା ପ୍ରତିସ୍ଥାପିତ ହୁଏ। ବିସ୍ତୃତ ପାଇପଲାଇନ କଳାକୃତି (ଯାହାକି upstream/client ଶରୀର ଏବଂ ଷ୍ଟ୍ରିମ୍ ଅଂଶ ଅନ୍ତର୍ଭୂକ୍ତ କରିପାରିବ) ରଖାଯାଏ ନାହିଁ। ସେମାଣ୍ଟିକ୍, ଅପାରଗତା, ଏବଂ ଯୁକ୍ତିଯୁକ୍ତ-ରିପ୍ଲେ କ୍ୟାଚ୍ ବାଇପାସ୍ ସେହି ଅନୁରୋଧ ପାଇଁ ପ s ିଥାଏ ଏବଂ ଲେଖେ। ପ୍ରଦାନକାରୀ ଅନୁରୋଧ ଏବଂ କ୍ଲାଏଣ୍ଟ-ଦୃଶ୍ୟମାନ ପ୍ରତିକ୍ରିୟା ଅପରିବର୍ତ୍ତିତ ରହିଥାଏ। ବିସ୍ତୃତ କଳାକୃତି ଛାଡି ଦିଆଯିବା ପରେ ଅସ୍ଥାୟୀ ବଫରରୁ ପ୍ରାରମ୍ଭିକ ରକ୍ଷକ ବାଇଟ୍ ନିଷ୍କାସିତ ହୁଏ। Kiro ର ବିକୃତ EventStream ଚେତାବନୀ କେବଳ ପେଲୋଡ୍ ବାଇଟ୍ ଗଣନା ରିପୋର୍ଟ କରେ, ଏହାର ବିଷୟବସ୍ତୁ କିମ୍ବା JSON ପାର୍ସରର କଞ୍ଚା ତ୍ରୁଟି। ଏହା ଦାବି କରେ ନାହିଁ ଯେ ପ୍ରତ୍ୟେକ ଅବିଭକ୍ତ provider/plugin ଡାଇଗ୍ନୋଷ୍ଟିକ୍ ଅଡିଟ୍ କରାଯାଇଛି; ବ୍ୟାପକ ସଂରକ୍ଷିତ-ସିଙ୍କ୍ ସୁଇପ୍ #11658 ରେ ଟ୍ରାକ୍ ହୋଇଛି।

ଆଭ୍ୟନ୍ତରୀଣ `/api/modality-bridge/video/drilldown` ଜୀବନଚକ୍ର ଏକ ଅଲଗା, loopback/token-authenticated କ୍ୟାଚ୍ ସବଷ୍ଟ୍ରେଟ୍। ପ୍ରତ୍ୟେକ ଅପରେସନ୍ ମଧ୍ୟ ଏକ କାନୋନିକାଲ୍ ଅପାକ୍ ପ୍ରିନ୍ସିପାଲ୍ ID ଆବଶ୍ୟକ କରେ। ଏକ ପ୍ରଡକ୍ସନ୍ କଲର୍ ସକ୍ଷମ ହେବା ପୂର୍ବରୁ, ଏହା ନିଶ୍ଚିତ ଭାବରେ ପ୍ରାମାଣିକ ଭିକାରୀଙ୍କ ଠାରୁ ID ପାଇବା ଉଚିତ ଏବଂ କ୍ଲାଏଣ୍ଟ-ମନୋନୀତ ମୂଲ୍ୟକୁ କେବେବି ପଠାଇବା ଉଚିତ ନୁହେଁ। କ୍ୟାଚ୍ କିଗୁଡ଼ିକ ସେହି ପ୍ରିନ୍ସିପାଲ୍ କୁ କାନୋନିକାଲ୍ ଅଧିବେଶନ ଏବଂ ଭିଡିଓ-ରେଫରେନ୍ସ IDs ସହିତ ବାନ୍ଧେ, କେବଳ ସେମାନଙ୍କର SHA-256-derived କିଗୁଡ଼ିକୁ ସଂରକ୍ଷଣ କରେ, ଏବଂ ସମାନ ପ୍ରିନ୍ସିପାଲକୁ ଉଭୟ ପଠନ ଏବଂ ବିଲୋପକୁ ପରିସର କରେ। କ୍ୟାଶେ ପ୍ରତି ପ୍ରବେଶ ପାଇଁ ସର୍ବାଧିକ 16 ଟି JPEG ଫ୍ରେମ୍ ଗଚ୍ଛିତ କରେ, ସେମାନଙ୍କୁ ଦଶ ମିନିଟ୍ ପରେ ସମାପ୍ତ କରେ, ଏବଂ ସୀମିତ `start`/`end` ପ s ଼ିବା କିମ୍ବା ସ୍ପଷ୍ଟ ଅଧିବେଶନ ବିଲୋପକୁ ସମର୍ଥନ କରେ।

ପ୍ରତ୍ୟେକ ପ୍ରିନ୍ସିପାଲ୍ 16 ଏଣ୍ଟ୍ରି ଏବଂ 64 MiB କାନୋନିକାଲ୍ JPEG ଡାଟା ମଧ୍ୟରେ ସୀମିତ। ସେହି ସୀମା ଗ୍ଲୋବାଲ୍ 64-entry/256 MiB ଛାତରୁ ସ୍ are ାଧୀନ: ମୂଖ୍ୟ କୋଟା ଚାପ କେବଳ ବିଶ୍ global ର LRU ଉଚ୍ଛେଦକୁ ବିଚାର କରିବା ପୂର୍ବରୁ ପ୍ରିନ୍ସିପାଲ୍ଙ୍କ ସର୍ବନିମ୍ନ-ବ୍ୟବହୃତ ପ୍ରବିଷ୍ଟଗୁଡ଼ିକୁ ବାହାର କରିଥାଏ। କ୍ୟାଚ୍ କାର୍ଯ୍ୟକଳାପ ଉପରେ ଉଭୟ ମୂଖ୍ୟ ଏବଂ ବିଶ୍ global ସ୍ତରୀୟ ଆକାଉଣ୍ଟିଂରୁ ମିଆଦ ପୂର୍ଣ୍ଣ ଏଣ୍ଟ୍ରିଗୁଡିକ ସ୍ୱିପ୍ ହୋଇଥିବାବେଳେ ବାତିଲ୍ ଏବଂ ବ valid ଧତା ବିଫଳତା ଆଂଶିକ ବଦଳାଇବ ନାହିଁ।

- **`preCall`** ପେଲୋଡ୍ କ୍ଲୋନ୍ କରେ, `system`, `messages`, `input`, ଏବଂ `prompt` (ସାଧା ଷ୍ଟ୍ରିଙ୍ଗ୍ ଆଇଟମ୍ ଅନ୍ତର୍ଭୂକ୍ତ କରି) ଚାଲିଥାଏ, ଏବଂ `processPII()` ( `@/shared/utils/inputSanitizer` ରୁ) ଷ୍ଟ୍ରିଙ୍ଗ୍ `content`/`text` ଫିଲ୍ଡରେ ପ୍ରୟୋଗ କରେ। ଯେତେବେଳେ `PII_REDACTION_ENABLED=true`, ଚିହ୍ନିତ PII ଆଉଟବାଉଣ୍ଡ ପେଲୋଡ୍ ରେ ରିଡାକ୍ଟ ହୁଏ। ଏହା `INPUT_SANITIZER_MODE` ଠାରୁ ସ୍ is ାଧୀନ (ଯାହା କେବଳ ପ୍ରମ୍ପ୍ଟ-ଇଞ୍ଜେକ୍ସନ୍ ନୀତି ନିୟନ୍ତ୍ରଣ କରେ)। ଯେତେବେଳେ ରେଡକ୍ସନ୍ ବନ୍ଦ ହୋଇଯାଏ, କଲ୍ ରେକର୍ଡ ଚିହ୍ନଟ ବିଷୟବସ୍ତୁ ପୁନ rew ଲିଖନ ନକରି ଗଣନା କରିଥାଏ।
- **`postCall`** ପ୍ରତିକ୍ରିୟାକୁ ଗଭୀର-କ୍ଲୋନ, `sanitizePIIResponse()` ଏବଂ ରେସପନ୍ସ- API- ଆକୃତି ମାସ୍କର୍ ଚଲାଇଥାଏ (`maskResponsesOutput` — `output_text` ଏବଂ `output[].content[].text` କୁ ଆବୃତ କରେ)। ଯଦି କ red ଣସି ରିଡାକସନ ହୁଏ, ପରିବର୍ତ୍ତିତ ପ୍ରତିକ୍ରିୟା ମୂଳକୁ ବଦଳାଇଥାଏ।

ରାକ୍ଷୀ କଦାପି ଅବରୋଧ କରେ ନାହିଁ; ଏହା କେବଳ ଟିପ୍ପଣୀ (`meta.detections`, `meta.redacted`) କିମ୍ବା ପୁନ r ଲିଖନ କରେ।

**ଓଲଟା ଭାଲ୍ଟ (`PII_REVERSIBLE_VAULT_ENABLED`, ଡିଫଲ୍ଟ `false`)।** ଯେତେବେଳେ ଉଭୟ `PII_REDACTION_ENABLED` ଏବଂ `PII_REVERSIBLE_VAULT_ENABLED` ଅନ୍ ଅଛି (DB > env > ଡିଫଲ୍ଟ, ପ୍ରତି ଅନୁରୋଧ ଥରେ ପ read ନ୍ତୁ), `handleChat` କ୍ଲାଏଣ୍ଟ ଅନୁରୋଧ (`src/lib/pii/requestTokenVaultScope.ts`) ପ୍ରତି ଗୋଟିଏ ଭାଲ୍ଟ ଖୋଲିଥାଏ ଏବଂ ଏହାକୁ `GuardrailContext.tokenVault` ଭାବରେ ପ୍ରି-କଲ୍ ପାସ୍ କୁ ପଠାଇଥାଏ। ମାସ୍କର୍ ବିଲ୍ଟ-ଇନ୍, ବ valid ଧ (GDPR/POPIA) ଏବଂ କଷ୍ଟମ୍ ନିୟମ ପାଇଁ `[EMAIL_REDACTED]` ପରିବର୍ତ୍ତେ `<<PII_EMAIL_QWERTYUI_1>>` ପରି ସରୋଗେଟ୍ ଟୋକେନ୍ ଲେଖେ। ନନ୍ସ ହେଉଛି ଅନୁରୋଧ ପାଇଁ 8 ଟି ଅନିୟମିତ ଅକ୍ଷର ଅକ୍ଷର, ଏବଂ ସମାନ ମୂଲ୍ୟ ଅନୁରୋଧ ମଧ୍ୟରେ ସମାନ ଟୋକେନ୍ ପାଇଥାଏ। କେବଳ ମାସ୍କର ମିନିଟ୍ସ: ପ୍ରମ୍ପ୍ଟ-ଇଞ୍ଜେକ୍ସନ୍ ଗାର୍ଡ ଏବଂ `/api/guardrails/test` ବିନା ଭାଲ୍ଟରେ ଚାଲିଥାଏ ଏବଂ ସ୍ଥାନଧାରୀମାନଙ୍କୁ ରଖେ।

- ପ୍ରଦାନକାରୀ, ପ୍ରତ୍ୟେକ କମ୍ବୋ ଲେଗ୍, ପୁନ ry ଚେଷ୍ଟା, ଫ୍ୟୁଜନ୍ ପ୍ୟାନେଲ୍ ସଦସ୍ୟ ଏବଂ ଫ୍ୟୁଜନ୍ ଜଜ୍ କେବଳ ଟୋକେନ୍ ଦେଖନ୍ତି। `handleChat` ଛାଡିଥିବା 2xx ପ୍ରତିକ୍ରିୟାରେ ଟୋକେନ୍ ଗୁଡିକ ଥରେ ପୁନ restored ସ୍ଥାପିତ ହୁଏ: ପାର୍ସଡ୍ SSE ଉପରେ ପ୍ରତି କ୍ଷେତ୍ର (ଇଭେଣ୍ଟଗୁଡିକ ମଧ୍ୟରେ ଏକ ଟୋକେନ୍ ବିଭାଜନ ଏପର୍ଯ୍ୟନ୍ତ ସମାଧାନ ହୁଏ; ଟୁଲ୍-କଲ୍ ଆର୍ଗୁମେଣ୍ଟସ୍ JSON- ପଳାୟନ) କିମ୍ବା ଏକ JSON ଶରୀରରେ ପ୍ରତି କ୍ଷେତ୍ର, ପୁନ omp ଗଣିତ `Content-Length` ସହିତ। ବିଷୟବସ୍ତୁ ଏବଂ ଯୁକ୍ତିଯୁକ୍ତ ପାଠ୍ୟ ଏବଂ ଟୁଲ୍-କଲ୍ ଆର୍ଗୁମେଣ୍ଟସ୍ ପୁନରୁଦ୍ଧାର ହୋଇଛି। ତ୍ରୁଟି ସଂସ୍ଥା (4xx/5xx) ଟୋକେନ୍ ରଖେ।
- ବିଫଳତା ବ୍ୟକ୍ତିଗତ ରହେ: ଯଦି ମେଣ୍ଟିଂ ବିଫଳ ହୁଏ କିମ୍ବା ଭାଲ୍ଟ ଏକ ମୂଲ୍ୟ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ (1000 ଏଣ୍ଟ୍ରି, ମୂଲ୍ୟ ପ୍ରତି 256 ଅକ୍ଷର, ସମୁଦାୟ 64 KB ), ସ୍ଥାନଧାରୀ ଏହା ବଦଳରେ ଲେଖାଯାଏ; ଏକ ଟୋକନ୍ ଭାଲ୍ଟ ସମାଧାନ କରିପାରିବ ନାହିଁ, କିମ୍ବା ପୁନ restore ସ୍ଥାପନ ଯାହା ବିଫଳ ହୁଏ, ଆକ୍ଷରିକ ରହିଥାଏ ଏବଂ କେବଳ ଏକ ଗଣନା ଲଗ୍ ହୋଇଯାଏ। ଭାଲ୍ଟରେ କ tim ଣସି ଟାଇମର୍ ନାହିଁ ଏବଂ କ global ଣସି ବିଶ୍ୱସ୍ତରୀୟ ରାଜ୍ୟ ନାହିଁ; ଯେତେବେଳେ ପ୍ରତିକ୍ରିୟା ଷ୍ଟ୍ରିମ୍ ସମାପ୍ତ ହୁଏ, ବାତିଲ୍ ହୁଏ କିମ୍ବା ତ୍ରୁଟି ହୁଏ, ଏହା ସଫା ହୋଇଯାଏ।
- ଯେତେବେଳେ ଏକ ଅନୁରୋଧ ମେଣ୍ଟ ଟୋକେନ୍, ମେମୋରୀ ନିଷ୍କାସନ, idempotency ସେଭ୍ ଏବଂ ଉଭୟ ଅର୍ଥଗତ-କ୍ୟାଚ୍ ଲେଖାକୁ ଏଡ଼ାଇ ଦିଆଯାଏ, କାରଣ ପରବର୍ତ୍ତୀ ଅନୁରୋଧ ସେହି ଟୋକେନ୍ଗୁଡ଼ିକୁ ସମାଧାନ କରିପାରିବ ନାହିଁ। କଲ୍ ଲଗରେ ପ୍ରଦାନକାରୀ ଅନୁରୋଧ ଏବଂ ପ୍ରତିକ୍ରିୟା ଟୋକେନ୍ ବହନ କରେ; ଲଗ୍ ହୋଇଥିବା କ୍ଲାଏଣ୍ଟ ଅନୁରୋଧ ସଂସ୍ଥା ସାଧା ରିଡାକସନ ପରି କଞ୍ଚା କ୍ଲାଏଣ୍ଟ ଇନପୁଟ୍ ଅଟେ।
- ଟୋକେନଗୁଡିକ ପ୍ରତି-ଅନୁରୋଧ ରାଣ୍ଡମ ନନ୍ସ ବ୍ୟବହାର କରନ୍ତି, ତେଣୁ ପ୍ରମ୍ପ୍ଟ ପ୍ରିଫିକ୍ସ ପ୍ରତ୍ୟେକ ଟର୍ନରେ ପରିବର୍ତ୍ତନ ହୁଏ: ପ୍ରଦାନକାରୀ-ସାଇଡ୍ ପ୍ରମ୍ପ୍ଟ କ୍ୟାଚିଂ ମାସ୍କେଡ୍ ଟର୍ନ୍ ପାଇଁ ହିଟ୍ ହୁଏ ନାହିଁ, ଏବଂ ପରବର୍ତ୍ତୀ ଟର୍ଣ୍ଣରେ ଫେରି ଆସୁଥିବା ଏକ ଟୋକେନ୍ (ଉଦାହରଣ ସ୍ୱରୂପ `previous_response_id` ମାଧ୍ୟମରେ) ଏକ ପୁରୁଣା ଅନୁରୋଧର ଅଟେ ଏବଂ ଆକ୍ଷରିକ ଭାବରେ ରହିଥାଏ।

#### ପ୍ରତି ପ୍ରକାର ଚୟନ, କଷ୍ଟମ୍ s ାଞ୍ଚା ଏବଂ ଚିହ୍ନଟ କାଉଣ୍ଟର।

**ଡ୍ୟାସବୋର୍ଡ → ସେଟିଂସମୂହ → ସୁରକ୍ଷା → PII ମାସ୍କିଂ।** _ ଯାହା_ ମାସ୍କ ହୋଇଛି ତାହା ବାଛେ। ଏହା ମାସ୍କିଂକୁ ସୁଇଚ୍ କରେ ନାହିଁ: ତାହା ଏପର୍ଯ୍ୟନ୍ତ `PII_REDACTION_ENABLED` (ଅନୁରୋଧ) ଏବଂ `PII_RESPONSE_SANITIZATION` (ପ୍ରତିକ୍ରିୟା + SSE), ଉଭୟ ଡିଫଲ୍ଟ ଭାବରେ ବନ୍ଦ।

- **ପ୍ରତି ପ୍ରକାର ଚୟନ।** — ବିଲ୍ଟ-ଇନ୍ ଗୁଡିକ `src/shared/constants/piiTypes.ts` (`PII_BUILTIN_TYPES`) ରେ ତାଲିକାଭୁକ୍ତ। ଅସନ୍ତୁଷ୍ଟ ଅର୍ଥ ପ୍ରତ୍ୟେକ ପ୍ରକାର (ଏହି ସେଟିଂ ପୂର୍ବରୁ ଆଚରଣ)। ଅନୁରୋଧ ଇଞ୍ଜିନ୍ ର `ssn_us` ପ୍ୟାଟର୍ ମାନଚିତ୍ର `ssn` କୁ। ଟେମ୍ପଲେଟ୍ (ସର୍ବନିମ୍ନ, ମାନକ, ଆର୍ଥିକ, ବ୍ରାଜିଲ୍, USA, GDPR, POPIA, ପୂର୍ଣ୍ଣ) କେବଳ UI ରେ ଚେକ୍ ବକ୍ସଗୁଡିକ ପୂରଣ କରେ।
- **GDPR ଏବଂ POPIA ପରିଚାୟକ।** — ବାରଟି ବିଲ୍ଟ-ଇନ୍ ID ଗୁଡିକ EU ଏବଂ ଦକ୍ଷିଣ ଆଫ୍ରିକାର ବ୍ୟକ୍ତିଗତ ପରିଚାୟକ (ନିମ୍ନରେ ସାରଣୀ) କୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ। ସେମାନଙ୍କର ରେଜେକ୍ସ, ବ valid ଧତାକାରୀ ଏବଂ ପ୍ରାଧିକରଣ ଟ୍ୟାଗଗୁଡ଼ିକ ଗୋଟିଏ ଟେବୁଲ୍, `src/shared/utils/piiPatterns.ts` ରେ ବାସ କରନ୍ତି, ଯାହା ଉଭୟ ପ୍ରତିକ୍ରିୟା ସାନିଟାଇଜର୍ (`src/lib/piiSanitizer.ts`) ଏବଂ ଅନୁରୋଧ ମାସ୍କର୍ (`src/shared/utils/inputSanitizer.ts`) ଖାଇଥାଏ। ଯେତେବେଳେ ଏକ ବ match ଧତା ଏହାକୁ ଗ୍ରହଣ କରେ ସେତେବେଳେ ଏକ ମ୍ୟାଚ୍ ରିଡାକ୍ଟ ହୁଏ। ଅଙ୍କଗୁଡିକର ଖାଲି ଚାଲିବା କଦାପି ଯଥେଷ୍ଟ ନୁହେଁ। ଏକ ଅପରେଟର୍ ଯିଏ ଏହି ଆଇଡିଗୁଡିକ ବିଦ୍ୟମାନ ହେବା ପୂର୍ବରୁ ଏକ ସଂକୀର୍ଣ୍ଣ ଚୟନକୁ ସଂରକ୍ଷଣ କରିଥିଲା, ନୂତନ ଆଇଡିଗୁଡିକ ଟିକ୍ ନହେବା ପର୍ଯ୍ୟନ୍ତ ଏହାର ଆଚରଣକୁ ରଖେ।
- **କଷ୍ଟମ୍ s ାଞ୍ଚା।** — ପର୍ଯ୍ୟନ୍ତ 20 ରେଜେକ୍ସ କିମ୍ବା ୱାଇଲ୍ଡକାର୍ଡ s ାଞ୍ଚା (`*` = ପର୍ଯ୍ୟନ୍ତ 64 ଅଣ-ଧଳା ସ୍ଥାନ ବର୍ଣ୍ଣ, `?` = ଗୋଟିଏ)। ମ୍ୟାଚ୍ ଗୁଡିକ `[CUSTOM_REDACTED]` ହୋଇଯାଏ। ପ୍ରତ୍ୟେକ ପ୍ୟାଟର୍ `compilePiiCustomPattern()` (`src/shared/utils/piiCustomPatterns.ts`) ଦେଇ ଗତି କରେ: ସର୍ବାଧିକ 500 ଅକ୍ଷର, ଫ୍ଲାଗ୍ `g i m s u` ରେ ସୀମିତ, ସଂକଳନ କରିବା ଆବଶ୍ୟକ, ନିଶ୍ଚିତ ଭାବରେ `safe-regex` (ବିପର୍ଯ୍ୟସ୍ତ ବ୍ୟାକଟ୍ରାକିଂ) ପାସ୍ କରିବା ଉଚିତ, ଏବଂ ଏକ ଖାଲି ଷ୍ଟ୍ରିଙ୍ଗ କିମ୍ବା ରିଡାକସନ ପ୍ଲେସହୋଲ୍ଡର ସହିତ ମେଳ ଖାଇବା ଉଚିତ ନୁହେଁ। ବିଫଳ ହୋଇଥିବା ଏକ pattern ାଞ୍ଚା ସଞ୍ଚୟ ହେବା ସମୟରେ ଏବଂ ପରୀକ୍ଷଣ ସମୟରେ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ, ଏବଂ ଏକ ସଂରକ୍ଷିତ ଧାଡି ଯାହା ବିଫଳ ହୁଏ ତାହା ସଂକଳନ ପରିବର୍ତ୍ତେ ଚାଲିବା ସମୟରେ ଛାଡି ଦିଆଯାଏ। ମାସ୍କିଂ ଚାଲିଥିବାବେଳେ କଷ୍ଟମ୍ s ାଞ୍ଚାଗୁଡ଼ିକ କେବଳ ଚାଲିଥାଏ।
- **ଚିହ୍ନଟ କାଉଣ୍ଟର** — ପ୍ରତି ପ୍ରକାର ଗଣନା (କଦାପି ମେଳ ଖାଉଥିବା ମୂଲ୍ୟଗୁଡିକ), ସ୍ମୃତିରେ ରଖାଯାଇଥାଏ ଏବଂ ପୁନ art ଆରମ୍ଭ (`src/lib/pii/piiDetectionStats.ts`) ରେ ପୁନ et ସେଟ୍ କରେ। ମାସ୍କିଂ ଚାଲିଥିବାବେଳେ ସେମାନେ କେବଳ ବୃଦ୍ଧି ପାଆନ୍ତି।

| ମୋଡ୍                 | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                         | `warn`  | ଇଞ୍ଜେକ୍ସନ୍ ନୀତି: `block`, `warn`, କିମ୍ବା `log`। (`redact` ବ୍ୟାକ୍-ସୁସଙ୍ଗତ ପାଇଁ ଗ୍ରହଣୀୟ କିନ୍ତୁ କରେ।** ନୁହେଁ** ଷ୍ଟ୍ରିପ୍ ଇଞ୍ଜେକ୍ସନ୍ ପାଠ୍ୟ; ଅନୁରୋଧ PII ପୁନ r ଲିଖନ `PII_REDACTION_ENABLED` ଦ୍ୱାରା ନିୟନ୍ତ୍ରିତ।) |
| ସୀମାକୁ ଅବରୋଧ କରନ୍ତୁ। | `blockThreshold` ବିକଳ୍ପ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (ଛଦ୍ମନାମ `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`  | ଅବରୋଧ କରିବାକୁ ସର୍ବନିମ୍ନ ଗମ୍ଭୀରତା। ଡିଫଲ୍ଟରେ ମଧ୍ୟମ କେବଳ ପାଳନ କରାଯାଏ।                                                                                                                                       |

**ମୋଡ୍ ପ୍ରାଥମିକତା।** (`getMode`): କଲର୍ `options.mode` → `INJECTION_GUARD_MODE`**DB feature ଶିଷ୍ଟ୍ୟ-ଫ୍ଲାଗ୍ ନବଲିଖନ କରନ୍ତୁ।** (ଡ୍ୟାସବୋର୍ଡ → ସେଟିଂସମୂହ → ature ଶିଷ୍ଟ୍ୟ ପତାକା) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env → `warn`। ଏକ ଡ୍ୟାସବୋର୍ଡ ଓଭରବାଇଡ୍ ତେଣୁ env vars ଉପରେ ଜିତେ, ତେଣୁ ଫିଚର୍ ଫ୍ଲାଗ୍ UI ଚାଲୁଥିବା ଗାର୍ଡ ଲାଇଭ୍କୁ ନିୟନ୍ତ୍ରଣ କରେ (ପୁନ rest ଆରମ୍ଭ ନାହିଁ)। DB ପ read ଼ିବା ବିଫଳ-ନିରାପଦ: ଯଦି ଏହା ତ୍ରୁଟି ହୁଏ, ରାକ୍ଷୀ env- ଆଧାରିତ ଆଚରଣକୁ ଫେରିଯାଏ, ଏବଂ ଯେତେବେଳେ କ over ଣସି ଓଭରବ୍ରିଡ୍ ସେଟ୍ ଆଚରଣ କେବଳ env- ରେଜୋଲୁସନ ସହିତ ସମାନ ନୁହେଁ।

ଚିହ୍ନଟ ଉତ୍ସ:

1. `@/shared/utils/inputSanitizer` ରୁ`sanitizeRequest()` (ପାଇପଲାଇନର ଅନ୍ୟ ସ୍ଥାନରେ ବ୍ୟବହୃତ ଅଂଶୀଦାର ଡିଟେକ୍ଟର ସେଟ୍)।
2. ବିଲ୍ଟ-ଇନ୍ `DEFAULT_GUARD_PATTERNS` (ସମ୍ପ୍ରତି `system_override_inline` ଏବଂ `markdown_system_block`, ଉଭୟ `high` ଗମ୍ଭୀରତା)।
3. ଇଚ୍ଛାଧୀନ `customPatterns` କନଷ୍ଟ୍ରକ୍ଟର୍ ଅପ୍ସନ୍ (ଷ୍ଟ୍ରିଙ୍ଗ୍, ରେଜେକ୍ସ, କିମ୍ବା `{ name, pattern, severity }` ରେକର୍ଡ) ମାଧ୍ୟମରେ ପାସ୍ କଲା।

ଯେତେବେଳେ `mode === "block"`** ଏବଂ** ଅତିକମରେ ଗୋଟିଏ ଚିହ୍ନଟ ଗମ୍ଭୀରତା ସୀମାକୁ ପୂରଣ କରେ, `preCall` `{ block: true, message: "Request rejected: suspicious content detected" }` ଫେରସ୍ତ କରେ। `warn`/`log` ମୋଡରେ ଗାର୍ଡେୟାର ଲଗ୍ କିନ୍ତୁ କଲ୍ କୁ ଅନୁମତି ଦିଏ। ଅଂଶୀଦାର ହେଲପର `evaluatePromptInjection()` ମଧ୍ୟ କଲ୍ କରୁଥିବା ବ୍ୟକ୍ତିଙ୍କ ପାଇଁ ରପ୍ତାନି ହୁଏ ଯାହା ରେଜିଷ୍ଟ୍ରି ଦେଇ ନ ଯାଇ ପ୍ରମ୍ପ୍ଟର ମୂଲ୍ୟାଙ୍କନ କରିବା ଆବଶ୍ୟକ କରେ।

**ସ୍କାନ୍ ବନ୍ଧା (v3.8.20):** ଡିଟେକ୍ଟର କେବଳ ଯାଞ୍ଚ କରେ।** ପ୍ରଥମ 16 KB** `src/shared/utils/inputSanitizer.ts` ରେ ଯୋଗ ହୋଇଥିବା ପ୍ରମ୍ପ୍ଟ ଟେକ୍ସଟ୍ — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ବାଇଟ୍)। ପ୍ୟାଟର୍ ଲୁପ୍ ଚଲାଇବା ପୂର୍ବରୁ ଉଭୟ `detectInjection()` ଏବଂ `evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` ଇଞ୍ଜେକ୍ସନ୍ ନିର୍ଦ୍ଦେଶନାମା ଏକ ଇନପୁଟ୍ ର ଶୀର୍ଷରେ ବସିଥାଏ, ତେଣୁ ଚିହ୍ନଟକୁ ଦୁର୍ବଳ ନକରି #3932-ଶହ-କେବି ପେଲୋଡ୍ ଉପରେ ଏହି କ୍ୟାପ୍ସ ରେଜେକ୍ସ CPU/GC #4041

### ପରିଚୟ ମାସ୍କର୍ (`credentialMasker.ts`)

ଚାଲିଥାଏ।** ଉଭୟ** ପର୍ଯ୍ୟାୟ, ଡିଫଲ୍ଟ ଶୃଙ୍ଖଳରେ ଶେଷ (ପ୍ରାଥମିକତା `95`)। ଆଉଟବାଉଣ୍ଡ ପେଲୋଡ୍ (ମେସେଜ୍ ବିଷୟବସ୍ତୁ, ଟୁଲ୍-କଲ୍ ଆର୍ଗୁମେଣ୍ଟସ୍, ଟୁଲ୍ ଫଳାଫଳ) ରୁ ଜଣାଶୁଣା API- କି / ଗୁପ୍ତ-ଟୋକନ୍ s ାଞ୍ଚାଗୁଡ଼ିକୁ ପୁନ Red ପ୍ରତିକ୍ରିୟା କରେ।** ଏବଂ** ପ୍ରଦାନକାରୀ ପ୍ରତିକ୍ରିୟା, ତେଣୁ ଏକ ପ୍ରମ୍ପ୍ଟରେ ପେଷ୍ଟ ହୋଇଥିବା ଏକ ପରିଚୟପତ୍ର (କିମ୍ବା ଏକ ଉପକରଣ ଫଳାଫଳ ଦ୍ୱାରା ଇକୋଡ୍) ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରଦାନକାରୀଙ୍କୁ କିମ୍ବା କ୍ଲାଏଣ୍ଟକୁ ଫେରି ନଥାଏ।

- **କେବଳ ଅପ୍ଟ-ଇନ୍।** , PII ରେଡାକସନ ସହିତ ସମାନ ସମ୍ମିଳନୀ (ହାର୍ଡ ନିୟମ #20-adjacent): `settings.credentialRedactionEnabled === true` ନହେବା ପର୍ଯ୍ୟନ୍ତ ଅକ୍ଷମ।** କିମ୍ବା** `CREDENTIAL_REDACTION_ENABLED=true` ଏହା ବନ୍ଦ ହେବା ସହିତ, ରାକ୍ଷୀ ହେଉଛି ଏକ ନୋ-ଅପ୍ — ଯାହା କେବେବି ଅବରୋଧ କରେ ନାହିଁ ଏବଂ ପୁନ rew ଲିଖନ କରେ ନାହିଁ।

## ମୂଳ ଚୁକ୍ତି (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true ହେଲେ ଚେନ୍ short-circuit ହୁଏ
  message?: string; // ଅବରୋଧ କରିବା ବେଳେ ଦେଖାଯାଏ
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // ଅନୁରୋଧକୁ ପୁନର୍ଲେଖନ କରିବା ପାଇଁ preCall ଦ୍ୱାରା ଫେରାଯାଏ
  modifiedResponse?: TValue; // ପ୍ରତିକ୍ରିୟାକୁ ପୁନର୍ଲେଖନ କରିବା ପାଇଁ postCall ଦ୍ୱାରା ଫେରାଯାଏ
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ଗୋଟିଏ ଗାର୍ଡ଼ରେଲ୍ `void`, `{}`, କିମ୍ବା
`{ block: false }` ଫେରାଇ "କୌଣସି ପରିବର୍ତ୍ତନ ନାହିଁ" ବୋଲି ସଙ୍କେତ ଦିଏ।
`modifiedPayload`/`modifiedResponse` ଫେରାଇଲେ, ଡାଉନଷ୍ଟ୍ରିମ୍ ଗାର୍ଡ଼ରେଲ୍ ମାନଙ୍କ ପାଇଁ ଚେନ୍
ମାଧ୍ୟମରେ ପ୍ରବାହିତ ହେଉଥିବା ମୂଲ୍ୟ ବଦଳିଯାଏ।
`signal?: AbortSignal` କଲର୍ର ଲାଇଫସାଇକଲକୁ ଗାର୍ଡ଼ରେଲ୍ ମାନଙ୍କ ଭିତରକୁ ବହନ କରେ। ଅନୁରୋଧ abort ହେଉଛି ଇଚ୍ଛାକୃତ fail-open ବ୍ୟତିକ୍ରମ: ମିଡ଼ିଆ ବ୍ରିଜ୍ ଗୁଡ଼ିକ କାମ ବନ୍ଦ କରନ୍ତି ଏବଂ ଏହାକୁ ସମର୍ଥନ କରୁନଥିବା ଜଣାଶୁଣା ଟାର୍ଗେଟକୁ raw ମିଡ଼ିଆ ପୁନଃସ୍ଥାପନ ନକରି cleanup କରନ୍ତି।

## ରେଜିଷ୍ଟ୍ରୀ (`registry.ts`)

singleton `guardrailRegistry` ନିମ୍ନଲିଖିତଗୁଡ଼ିକୁ ଉନ୍ମୋଚନ କରେ:

- `register(guardrail)` — ଗୋଟିଏ ଗାର୍ଡ଼ରେଲ୍ ଯୋଡ଼େ (କିମ୍ବା normalized ନାମ ଅନୁସାରେ
  ବଦଳାଏ) ଏବଂ ଆରୋହୀ `priority` ଅନୁସାରେ ପୁନଃ-ସଜାଏ।
- `clear()` / `list()` — ପ୍ରଶାସନିକ ସହାୟକ।
- `runPreCallHooks(payload, context)` — ସକ୍ରିୟ ଗାର୍ଡ଼ରେଲ୍ ମାନଙ୍କୁ ପୁନରାବୃତ୍ତି କରେ,
  payload କୁ `modifiedPayload` ମାଧ୍ୟମରେ ପର୍ଯ୍ୟାୟକ୍ରମେ ପଠାଏ, ଏବଂ ପ୍ରଥମ `block: true` ପାଇଲେ ଅଟକିଯାଏ।
- `runPostCallHooks(response, context)` — ପ୍ରତିକ୍ରିୟା ପାର୍ଶ୍ୱରେ ସମାନ ପ୍ରବାହ।
- `resetGuardrailsForTests({ registerDefaults })` — ଅବସ୍ଥା ସଫା କରେ ଏବଂ ପରିଷ୍କାର
  ଟେଷ୍ଟ isolation ପାଇଁ ଇଚ୍ଛାନୁସାରେ ଡିଫଲ୍ଟ ଗୁଡ଼ିକୁ ପୁନଃ-ପଞ୍ଜୀକରଣ କରେ।

ଉଭୟ runner `{ blocked, payload|response, results, guardrail?, message? }`
ଫେରାନ୍ତି, ଯେଉଁଠାରେ `results` ହେଉଛି `GuardrailExecutionResult` ରେକର୍ଡଗୁଡ଼ିକର ଏକ array
ଯାହା ପ୍ରତ୍ୟେକ ଗାର୍ଡ଼ରେଲ୍ ପାଇଁ `blocked`, `skipped`, `modified`, `error`, ଏବଂ `meta`
ଫିଲ୍ଡ୍ ଧାରଣ କରେ, ଯାହା ଟ୍ରେସିଂ ପାଇଁ ଉପଯୋଗୀ।

ପାଞ୍ଚଟି ଚ୍ୟାନେଲ୍ ଅଛି, ସେଗୁଡ଼ିକ ଏହି କ୍ରମରେ ପଢ଼ାଯାଏ ଏବଂ ଗୋଟିଏ ତାଲିକାରେ ମିଶାଯାଏ
(ଡୁପ୍ଲିକେଟ୍ ହଟାଇବା ବେଳେ ପ୍ରଥମ ଉପସ୍ଥିତି ବିଜୟୀ ହୁଏ):

1. `apiKeyInfo.disabledGuardrails`
2. ଅନୁରୋଧ body `disabledGuardrails` (ଶୀର୍ଷ-ସ୍ତରୀୟ)
3. ଅନୁରୋଧ body `metadata.disabledGuardrails` (କେବଳ ଯେତେବେଳେ `metadata` ଗୋଟିଏ object)

## ନିଷ୍ପାଦନ ଆଦେଶ

`src/sse/handlers/chat.ts` ଏବଂ `open-sse/handlers/chatCore.ts` ଦେଇ ପ୍ରବାହିତ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ ( [କଭରେଜ୍ ଏବଂ ସୀମା](#coverage-and-limits) ଅନ୍ତର୍ଗତ ତାଲିକାଭୁକ୍ତ ଚାଟ୍-ପରିବାର ମାର୍ଗ):

1. `resolveDisabledGuardrails(...)` API କି, ଶରୀର, ଏବଂ ହେଡର୍ ରୁ ସ୍କିପ୍ ତାଲିକା ନିର୍ମାଣ କରେ।
2. ପ୍ରାଥମିକତା କ୍ରମରେ`guardrailRegistry.runPreCallHooks(body, ctx)` ରାକ୍ଷୀ ଚଲାଇଥାଏ:
   - ଅକ୍ଷମ ରାକ୍ଷୀଗୁଡିକ `skipped` ଭାବରେ ରେକର୍ଡ କରାଯାଇଛି।
   - ପ୍ରତ୍ୟେକ ରାକ୍ଷୀଙ୍କ `preCall` `modifiedPayload` ମାଧ୍ୟମରେ ପେଲୋଡ୍ ପୁନ rew ଲିଖନ କରିପାରେ।
   - ପ୍ରଥମ `block: true` ସର୍ଟ ସର୍କିଟ୍ ଶୃଙ୍ଖଳା ଏବଂ ହ୍ୟାଣ୍ଡେଲର୍ ଏକ ରାକ୍ଷୀ ପ୍ରତ୍ୟାଖ୍ୟାନ ପ୍ରତିକ୍ରିୟା ଫେରସ୍ତ କରେ।
3. (ସମ୍ଭାବ୍ୟ ପୁନ rew ଲିଖିତ) ପେଲୋଡ୍ ଲୋ କମ୍ବୋ ରାଉଟିଙ୍ଗ୍ ଏବଂ ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରେରଣରେ ପ୍ରବାହିତ ହୁଏ।
4. **କେବଳ ଷ୍ଟ୍ରିମିଂ ନୁହେଁ:** ପ୍ରତିକ୍ରିୟା ଏକତ୍ର ହେବା ପରେ, `guardrailRegistry.runPostCallHooks(...)` ପ୍ରତିକ୍ରିୟାରେ ସମାନ ଶୃଙ୍ଖଳା ଚଲାଇଥାଏ। `block: true` ଏଠାରେ ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରତିକ୍ରିୟାକୁ ଡ୍ରପ୍ କରେ ଏବଂ HTTP 400 ରିଟର୍ନ କରେ। ଷ୍ଟ୍ରିମିଡ୍ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ ଏହି ପଦକ୍ଷେପକୁ ସଂପୂର୍ଣ୍ଣ ଛାଡିଦିଅ।
5. **କେବଳ ଓଲଟା ଭାଲ୍ଟ:** ଯେତେବେଳେ ଅନୁରୋଧ ମେଣ୍ଟ ଟୋକେନ୍, `handleChat` ସେମାନଙ୍କୁ 2xx ପ୍ରତିକ୍ରିୟାରେ ପୁନ ores ସ୍ଥାପିତ କରେ, କଲ୍-ପୋଷ୍ଟ ହୁକ୍ ଏବଂ ଷ୍ଟ୍ରିମିଂ PII ରୂପାନ୍ତର ପରେ, ତେଣୁ `PII_RESPONSE_SANITIZATION` ଟୋକେନ୍ ଏବଂ ମଡେଲ୍-ଉତ୍ପାଦିତ PII ଦେଖେ, କଦାପି ପୁନ restored ସ୍ଥାପିତ ମୂଳ ନୁହେଁ।

ଫୋପାଡିଥିବା ରାକ୍ଷୀ `error: <message>` ସହିତ ରେକର୍ଡ ହୋଇଛି ଏବଂ `logger.warn` ମାଧ୍ୟମରେ ଲଗ୍ ହୋଇଛି, କିନ୍ତୁ ଶୃଙ୍ଖଳା ଦ୍ୱାରା ଡିଜାଇନ୍ ଦ୍ୱାରା — ବିଫଳ-ଖୋଲା ଚାଲିଛି।

### ଯାହା ଆଚ୍ଛାଦିତ ନୁହେଁ।

- **ମିଡିଆ, ଏମ୍ବେଡିଂ ଏବଂ ଡାଟା ରୁଟ୍।** (`/v1/images/*`, `/v1/embeddings`, `/v1/audio/*`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/rerank`, `/v1/search`, `/v1/moderations`) କଦାପି ରେଜିଷ୍ଟ୍ରିରେ ପହଞ୍ଚେ ନାହିଁ। ସେଠାରେ କ z ଣସି PII ମାସ୍କିଂ, ପରିଚୟ ମାସ୍କିଂ କିମ୍ବା ମୋଡାଲୀ ବ୍ରିଜ୍ ଚାଲୁ ନାହିଁ। ସେମାନଙ୍କର ଏକମାତ୍ର ଯାଞ୍ଚ ହେଉଛି ଉତ୍ତରାଧିକାରୀ ଇଞ୍ଜେକ୍ସନ୍-ଗାର୍ଡ ମିଡିଲୱେର୍।
- **ଷ୍ଟ୍ରିମିଡ୍ ପ୍ରତିକ୍ରିୟା।** କ post ଣସି ପୋଷ୍ଟ କଲ୍ ଗାର୍ଡେଲ୍ ପାଆନ୍ତୁ ନାହିଁ: `pii-masker` କିମ୍ବା `credential-masker` ପୋଷ୍ଟ-କଲ ନାହିଁ, ଏବଂ କଲ୍-ପୋଷ୍ଟ ବ୍ଲକ୍ ନାହିଁ। କେବଳ ଷ୍ଟ୍ରିମିଂ PII ଟ୍ରାନ୍ସଫର୍ମ ପ୍ରଯୁଜ୍ୟ (ଯେତେବେଳେ `PII_RESPONSE_SANITIZATION` ଅନ୍ ଅଛି)। ଏକ ଷ୍ଟ୍ରିମିଡ୍ ପ୍ରତିକ୍ରିୟାରେ ଏକ ପରିଚୟପତ୍ର ପୁନ red ପ୍ରତିଫଳିତ ହୁଏ ନାହିଁ।
- **ଚ୍ୟାନେଲ ବନାମ ମିଡିଲୱେର୍ (ଡିଜାଇନ୍ ଦ୍ୱାରା) ଅକ୍ଷମ କରନ୍ତୁ:** ମିଡିଲୱେର୍ କ call ଣସି କଲର୍-ନିୟନ୍ତ୍ରିତ ଅକ୍ଷମ ତାଲିକା ପାସ୍ ନକରି `evaluatePromptInjection()` କୁ ନିଜର କଲ୍ ସହିତ ପ୍ରମ୍ପ୍ଟ ଇଞ୍ଜେକ୍ସନ୍ ମୂଲ୍ୟାଙ୍କନ କରେ। `block` ମୋଡ୍ ହେଉଛି ଏକ ବାଧ୍ୟତାମୂଳକ ସୀମା ଯାହା ଚାଟର୍-ନିୟନ୍ତ୍ରିତ ଅକ୍ଷମଗୁଡିକ ବାଇପାସ୍ କରିପାରିବ ନାହିଁ, ଚାଟ୍-ପରିବାର ମାର୍ଗ ( [#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413) ) କୁ ଅନ୍ତର୍ଭୁକ୍ତ କରି। `prompt-injection` ଅକ୍ଷମ କରିବା କେବଳ ରେଜିଷ୍ଟ୍ରି ଗାର୍ଡେଲକୁ ଛାଡିଦିଏ।

### କଲ୍ ପରେ କ’ଣ ପ୍ରତିକ୍ରିୟା ଦେଖେ।

ଅଣ-ଷ୍ଟ୍ରିମିଂ ପଥରେ କ୍ରମ ହେଉଛି: ମେମୋରୀ ନିଷ୍କାସନ → ବିଲ୍ଟ-ଇନ୍ ଟୁଲ୍ ଏକଜେକ୍ୟୁଶନ୍ → ପୋଷ୍ଟ-କଲ୍ ଗାର୍ଡେୟାର୍ → ପୋଷ୍ଟ-କଲ୍ ବ୍ଲକ୍ ଏକ୍ଜିଟ୍ → ସେମାଣ୍ଟିକ୍-କ୍ୟାଚ୍ ଷ୍ଟୋର୍।

- **ସ୍ମୃତି ନିଷ୍କାସନ** ଏବଂ** ସାଧନ ନିଷ୍ପାଦନ** କଲ୍-ପୋଷ୍ଟ ଗାର୍ଡେଲ୍ ଏହାକୁ ପୁନ r ଲିଖନ କିମ୍ବା ଅବରୋଧ କରିବା ପୂର୍ବରୁ ପ୍ରତିକ୍ରିୟା ଦେଖନ୍ତୁ। [#16401](https://github.com/diegosouzapw/OmniRoute/pull/16401) ପରଠାରୁ, `PII_RESPONSE_SANITIZATION` ଅନ୍ ଥିବାବେଳେ (ଉଭୟ ଷ୍ଟ୍ରିମିଂ ଏବଂ ଅଣ-ଷ୍ଟ୍ରିମିଂ) ମେମୋରୀ ନିଷ୍କାସନ `sanitizePII` ମାଧ୍ୟମରେ ବାହାର କରାଯାଇଥିବା ପାଠ୍ୟକୁ ଚଲାଇଥାଏ, କିନ୍ତୁ ଏକ ପ୍ରତିକ୍ରିୟା ଯାହା ପରବର୍ତ୍ତୀ ବ୍ଲକଗୁଡିକ ସ୍ମୃତି ଏବଂ ଉପକରଣଗୁଡ଼ିକୁ ପ୍ରଦାନ କରାଯାଇଥାଏ।
- **ଅର୍ଥଗତ କ୍ୟାଚ୍।** ପୋଷ୍ଟ-କଲ ପରେ ପ୍ରତିକ୍ରିୟା ଗଚ୍ଛିତ କରେ, ତେଣୁ ଏହା ପୁନ r ଲିଖିତ ପ୍ରତିକ୍ରିୟାକୁ ସଂରକ୍ଷଣ କରେ, ଏବଂ ଏକ ଅବରୋଧିତ ପ୍ରତିକ୍ରିୟା କେବେବି କ୍ୟାଚ୍ ହୋଇନଥାଏ। API କି ପାଇଁ କ୍ୟାଚ୍ ଏଣ୍ଟ୍ରିଗୁଡିକ କିଡ୍ ହୋଇଛି।

## କଷ୍ଟମ୍ ଗାର୍ଡରେଲ୍

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ପଦକ୍ଷେପଗୁଡ଼ିକ:

1. `BaseGuardrail` କୁ ବିସ୍ତାର କରୁଥିବା `src/lib/guardrails/myGuardrail.ts` ସୃଷ୍ଟି କରନ୍ତୁ।
2. `preCall` ଏବଂ/କିମ୍ବା `postCall` କାର୍ଯ୍ୟାନ୍ୱୟ କରନ୍ତୁ।
3. import ସମୟରେ ପଞ୍ଜୀକରଣ କରନ୍ତୁ (`registerDefaultGuardrails` ରୁ push କରି) କିମ୍ବା runtime ରେ `guardrailRegistry.register(...)` କଲ୍ କରନ୍ତୁ — registry ସମାନ normalized ନାମ ଥିବା ଯେକୌଣସି ପୂର୍ବତନ ଗାର୍ଡରେଲ୍ କୁ ବଦଳାଇ ଦିଏ।
4. `tests/unit/` ଅଧୀନରେ ଟେଷ୍ଟ ଯୋଡ଼ନ୍ତୁ (ବିଦ୍ୟମାନ ଉଦାହରଣ:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`)।

## ଟେଷ୍ଟିଂ

ଜ୍ଞାତ ଅବସ୍ଥାରୁ ଆରମ୍ଭ କରିବା ପାଇଁ ଟେଷ୍ଟଗୁଡ଼ିକ ମଧ୍ୟରେ `resetGuardrailsForTests()` ବ୍ୟବହାର କରନ୍ତୁ। ଖାଲି registry ସହ ଆରମ୍ଭ କରି କେବଳ ଟେଷ୍ଟ ଅଧୀନରେ ଥିବା ଗାର୍ଡରେଲ୍ଗୁଡ଼ିକୁ ପଞ୍ଜୀକରଣ କରିବା ପାଇଁ `{ registerDefaults: false }` ପାସ୍ କରନ୍ତୁ। Vision Bridge dependency injection ଗ୍ରହଣ କରେ (`deps.getSettings`, `deps.callVisionModel`); Audio Bridge settings, capabilities, STT ମଡେଲ ଚୟନ, credential ଯାଞ୍ଚ ଏବଂ transcription ପାଇଁ ସମତୁଲ୍ୟ seams ପ୍ରଦାନ କରେ। ତେଣୁ ଟେଷ୍ଟଗୁଡ଼ିକ DB କିମ୍ବା network ପ୍ରବେଶ ବିନା ଉଭୟ ପ୍ରବାହକୁ ପରୀକ୍ଷା କରିପାରିବେ।

## Injection-guard ରୁଟ୍ କଭରେଜ୍ ଏବଂ red-team (Phase 8 · Block D)

Injection-guard (`createInjectionGuard` / `withInjectionGuard`) ଉପଯୋଗକର୍ତ୍ତା prompts ଗ୍ରହଣ କରୁଥିବା ସମସ୍ତ routes କୁ କଭର କରେ। ଏହା `INJECTION_GUARD_MODE` କୁ ସମ୍ମାନ କରେ (default `warn` = କେବଳ log; `block` = HTTP 400 `SECURITY_001` ଫେରାଏ)।

| ପ୍ରକାର             | Routes                                                                                                                                               | ଡିଫଲ୍ଟ ମୋଡ୍ |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| ଟେକ୍ସ୍ଟ (ବିଦ୍ୟମାନ) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn        |
| ଜେନେରେଟିଭ୍         | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn        |
| ଡାଟା               | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn        |

Text extraction (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` କୁ କଭର କରେ।

**Red-team (nightly, `nightly-llm-security.yml`):** promptfoo ଯାଞ୍ଚ କରେ ଯେ `INJECTION_GUARD_MODE=block` ରେ ପ୍ରତ୍ୟେକ route OWASP-LLM corpus କୁ block କରେ; garak probes ଚଲାଏ (secret ନଥିଲେ skip କରେ)। ସାମଞ୍ଜସ୍ୟ ପାଇଁ `moderations` ମଧ୍ୟ ଅନ୍ତର୍ଭୁକ୍ତ କରାଯାଇଛି। Block mode ଏକ ବାଧ୍ୟତାମୂଳକ ସୀମା: `evaluatePromptInjection()` middleware ଦ୍ୱାରା ଦିଆଯାଇଥିବା per-request disable ତାଲିକାକୁ ଅଗ୍ରାହ୍ୟ କରେ, ତେଣୁ `disabledGuardrails` କୌଣସି route କୁ ଏଥିରୁ **ଛାଡ଼** ଦିଏ ନାହିଁ ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413))।

Nightly workflow (`.github/workflows/nightly-llm-security.yml`, cron + manual dispatch) ର ଦୁଇଟି job ଅଛି:

- **`promptfoo-guard` (blocking)** — `INJECTION_GUARD_MODE=block` ସହ `promptfoo eval -c promptfooconfig.yaml` ଚଲାଏ। ପ୍ରତ୍ୟେକ adversarial case (ଯେପରିକି "ପୂର୍ବବର୍ତ୍ତୀ ସମସ୍ତ ନିର୍ଦ୍ଦେଶକୁ ଅଣଦେଖା କର…", DAN-ଶୈଳୀ jailbreaks) assert କରେ ଯେ ପ୍ରତିକ୍ରିୟାରେ `error.code === "SECURITY_001"` ରହେ, ଅର୍ଥାତ୍ guard ପ୍ରକୃତରେ ଅନୁରୋଧକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରିଛି।
- **`garak` (advisory)** — ସ୍ଥାନୀୟ OmniRoute instance (`http://localhost:20128/v1`) ବିରୁଦ୍ଧରେ garak `--probes promptinject,dan,leakreplay` ଚଲାଏ। ଏହା ଏକ provider secret (`PROMPTFOO_PROVIDER_KEY`) ଉପରେ gated; gracefully skip କରେ ଏବଂ ଏଥିରେ `|| true` suffix ଥାଏ, ତେଣୁ CI ବିଫଳ ନକରି ରିପୋର୍ଟ କରେ।

Guard helper (`createInjectionGuard` / `withInjectionGuard`) ର coverage ପ୍ରତ୍ୟେକ prompt-bearing `/v1` route କୁ ବ୍ୟାପେ; `src/shared/utils/inputSanitizer.ts` ରେ ଥିବା `extractMessageContents()` ଦ୍ୱାରା `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ରୁ prompt text ନିଆଯାଏ।
