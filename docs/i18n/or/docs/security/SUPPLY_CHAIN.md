OmniRoute npm + Docker ଆର୍ଟିଫ୍ୟାକ୍ଟ ପ୍ରକାଶ କରେ। ଏହି ଗେଟ୍ଗୁଡ଼ିକ ପ୍ରୋଭେନାନ୍ସ, ଇନଭେଣ୍ଟୋରୀ (SBOM) ଏବଂ CVE ସ୍କାନିଂ ପ୍ରଦାନ କରନ୍ତି, ଯାହା ସମସ୍ତ OSS ଅଟେ ଏବଂ ରିଲିଜ୍ ୱାର୍କଫ୍ଲୋରେ ସଂଯୁକ୍ତ ହୋଇଛି।
**ପରାମର୍ଶ-ପ୍ରଥମ** ଆଭିମୁଖ୍ୟ — ସେମାନେ ବର୍ତ୍ତମାନ ରିପୋର୍ଟ କରନ୍ତି, ପ୍ରଥମ ସବୁଜ ରିଲିଜ୍ ପରେ ବ୍ଲକିଂକୁ ପ୍ରୋତ୍ସାହିତ କରନ୍ତି।

| ଗେଟ୍                  | ଟୁଲ୍                                           | କେଉଁଠାରେ                      | ବ୍ଲକ୍ କରେ କି?             | ଆଉଟପୁଟ୍                                      |
| --------------------- | ---------------------------------------------- | ----------------------------- | ------------------------- | -------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | କେବଳ ଯଦି ପ୍ରକାଶନ ବିଫଳ ହୁଏ | ବ୍ୟାଜ୍ npmjs / `npm audit signatures`        |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | କେବଳ ଯଦି ଉତ୍ପାଦନ ବିଫଳ ହୁଏ | ରିଲିଜ୍ ଆସେଟ୍ + ଆର୍ଟିଫ୍ୟାକ୍ଟ                  |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | ପରାମର୍ଶ                   | CycloneDX ଆର୍ଟିଫ୍ୟାକ୍ଟ                       |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | ପରାମର୍ଶ                   | SARIF (HIGH+CRITICAL) → ସୁରକ୍ଷା ଟ୍ୟାବ୍       |
| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **ବ୍ଲକିଂ**                | ସୁଧାର ଯୋଗ୍ୟ CRITICAL ଉପରେ `exit-code: '1'`   |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ବ୍ଲକିଂ**                | `metrics.vulnCount` କୁ ରାଚେଟ୍ କରେ (ଦିଗ:ତଳକୁ) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | ପରାମର୍ଶ                   | SARIF → ସୁରକ୍ଷା + ବ୍ୟାଜ୍                     |

ଇମେଜ୍ CVE ରାଚେଟ୍ `docker-publish.yml` ରେ **ଦୁଇଟି ପଦକ୍ଷେପ** ବ୍ୟବହାର କରେ: SARIF ପଦକ୍ଷେପ (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL କୁ ସୁରକ୍ଷା ଟ୍ୟାବ୍ ରେ ବ୍ଲକ୍ ନକରି ଦୃଶ୍ୟମାନ ରଖେ; _CRITICAL ଗେଟ୍_ ପଦକ୍ଷେପ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) ଏକ CRITICAL CVE **ସହିତ ଏକ ଉପଲବ୍ଧ ସୁଧାର** ଉପରେ ରିଲିଜ୍ କୁ ବିଫଳ କରେ। `ignore-unfixed` ଏକ ଅପଷ୍ଟ୍ରିମ୍ ପ୍ୟାଚ୍ ବିନା ଏକ ବେସ୍-ଇମେଜ୍ CVE ପାଇଁ ରିଲିଜ୍ କୁ ବ୍ଲକ୍ କରିବାରୁ ରୋକିଥାଏ।

## ⚠️ CVE ଭିନ୍ନତା (osv/Trivy ଗେଟ୍ଗୁଡ଼ିକୁ ଅବରୋଧ କରୁଛି)

osv ଏବଂ Trivy ନିର୍ଭରତାଗୁଡ଼ିକୁ **ନିରନ୍ତର ବୃଦ୍ଧି ପାଉଥିବା** CVE ଡାଟାବେସ୍ଗୁଡ଼ିକ ସହ ତୁଳନା କରନ୍ତି। ଏକ PR
ଯାହା **କୌଣସି ନିର୍ଭରତାକୁ ପରିବର୍ତ୍ତନ କରେ ନାହିଁ**, ତାହା ହଠାତ୍ ବିଫଳ ହୋଇପାରେ, କାରଣ ଏକ ବିଦ୍ୟମାନ ନିର୍ଭରତାରେ
ଏକ ନୂତନ CVE ପ୍ରକାଶିତ ହୋଇଛି (osv: ମାପାଯାଇଥିବା `vulnCount` > ବେସ୍ଲାଇନ୍; Trivy: ଇମେଜ୍ରେ ଏକ ନୂତନ
ସମାଧାନଯୋଗ୍ୟ CRITICAL)। **ଏହା ଏକ ଅବରୋଧକାରୀ CVE ଗେଟ୍ର ଆଶାକରାଯାଉଥିବା ପରିଚାଳନାଗତ ଆଚରଣ,
ଉତ୍ପାଦର ରିଗ୍ରେସନ୍ ନୁହେଁ।**

ନୂତନ ଭାବେ ପ୍ରକାଶିତ CVE କାରଣରୁ osv କିମ୍ବା Trivy ବିଫଳ ହେଲେ, ପ୍ରତିକାର ହେଉଛି:

1. **ପ୍ରଭାବିତ ନିର୍ଭରତାର ସଂସ୍କରଣ ବୃଦ୍ଧି କରନ୍ତୁ** (ଅଧିକ ପସନ୍ଦଯୋଗ୍ୟ) — `package.json`
   `overrides` (ପରୋକ୍ଷ ନିର୍ଭରତାଗୁଡ଼ିକ) ମାଧ୍ୟମରେ ପ୍ୟାଚ୍ ହୋଇଥିବା ସଂସ୍କରଣକୁ ଅପ୍ଗ୍ରେଡ୍ କରନ୍ତୁ କିମ୍ବା ଏକ ପ୍ୟାଚ୍ ହୋଇଥିବା ବେସ୍ରେ ଇମେଜ୍ଟିକୁ ପୁନଃନିର୍ମାଣ କରନ୍ତୁ।
2. **ଯଦି କୌଣସି ଅପ୍ଷ୍ଟ୍ରିମ୍ ସମାଧାନ ନାହିଁ:**
   - **osv:** `config/quality/quality-baseline.json` ମଧ୍ୟରେ `metrics.vulnCount`କୁ ପୁନଃ-ବେସ୍ଲାଇନ୍ କରନ୍ତୁ
     (`npm run quality:ratchet -- --update` ଉତ୍ସର୍ଗୀକୃତ ଗେଟ୍ଗୁଡ଼ିକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ ନାହିଁ — ଯଥାର୍ଥତା ସୂଚକ ଟିପ୍ପଣୀ + ଟ୍ରାକିଂ ଇସ୍ୟୁ ସହିତ
     ମୂଲ୍ୟଟିକୁ ହାତରେ ସମ୍ପାଦନା କରନ୍ତୁ, `direction:down`)।
   - **Trivy:** ଯଥାର୍ଥତା ସୂଚକ ମନ୍ତବ୍ୟ + ଟ୍ରାକିଂ ଇସ୍ୟୁ ସହିତ `.trivyignore`ରେ ଏକ ଏଣ୍ଟ୍ରି ଯୋଡ଼ନ୍ତୁ
     (ପ୍ରତ୍ୟେକ ଧାଡ଼ିରେ CVE-ID)। `ignore-unfixed: true` ପ୍ୟାଚ୍ ନଥିବା CVEଗୁଡ଼ିକୁ ପୂର୍ବରୁ
     ସ୍ୱୟଂଚାଳିତ ଭାବରେ ଅନ୍ତର୍ଭୁକ୍ତ କରେ।

ଆବଶ୍ୟକ OSV ନିଷ୍ପାଦନଗୁଡ଼ିକ (`check:vuln-ratchet -- --ratchet`) ସ୍କାନର୍, ରିପୋର୍ଟ କିମ୍ବା ବେସ୍ଲାଇନ୍କୁ ବୈଧ କରାଯାଇ ନପାରିଲେ
`INCOMPLETE` ସହିତ ଫେଲ୍-କ୍ଲୋଜ୍ ହୁଏ ଏବଂ 2 କୋଡ୍ ସହିତ ପ୍ରସ୍ଥାନ କରେ।
ମାପାଯାଇଥିବା ରିଗ୍ରେସନ୍ 1 କୋଡ୍ ସହିତ ପ୍ରସ୍ଥାନ କରେ। ପରାମର୍ଶମୂଳକ ନିଷ୍ପାଦନ ତଥାପି `SKIP` ରିପୋର୍ଟ କରି
0 କୋଡ୍ ସହିତ ପ୍ରସ୍ଥାନ କରିପାରେ, ଯାହା ନିର୍ଭରତାଗୁଡ଼ିକ ସ୍କାନ୍ରେ ପାସ୍ କରିଥିଲେ ବୋଲି ପ୍ରମାଣ କରେ ନାହିଁ। ଅବରୋଧକାରୀ
Trivy ପଦକ୍ଷେପ ପାଇଁ ମଧ୍ୟ ଏକ ସଫଳ ମାପ ଆବଶ୍ୟକ: ଅନୁପଲବ୍ଧ ଟୁଲ୍, ବିଫଳ ଜବ୍
ଏବଂ ନିଖୋଜ ଇମେଜ୍ ପ୍ରମାଣ କୌଣସି ଇମେଜ୍କୁ ତ୍ରୁଟିମୁକ୍ତ ବୋଲି ପ୍ରମାଣିତ କରିପାରିବ ନାହିଁ।

## ବ୍ୟବହାରରୁ ଅବସରପ୍ରାପ୍ତ ନିର୍ଭରତାର ବିପଦ

ପିନ୍ କରାଯାଇଥିବା promptfoo ବିକାଶ ଉପକରଣକୁ ଅପ୍ଗ୍ରେଡ୍ କରିବା ପରେ ରୁଟ୍ ଲକ୍ଫାଇଲ୍ରେ ଆଉ `extract-zip` କିମ୍ବା ଏହା ପ୍ରତି କୌଣସି ନିର୍ଭରତା ଏଜ୍ ଅନ୍ତର୍ଭୁକ୍ତ ନାହିଁ।
ଏହା #14482 ରେ ଟ୍ରାକ୍ କରାଯାଇଥିବା, ପୂର୍ବରୁ ଗ୍ରହଣ କରାଯାଇଥିବା
`promptfoo` → `@openai/codex-security` → `extract-zip` ଶୃଙ୍ଖଳକୁ ବ୍ୟବହାରରୁ ଅବସର ଦେଉଛି।
`tests/unit/extract-zip-14482-exposure.test.ts` ରେ ଥିବା ରିଗ୍ରେସନ୍ ଯାଞ୍ଚଗୁଡ଼ିକ ଏହାର
ପୁନଃପ୍ରବେଶକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ ଏବଂ ପ୍ରଡକ୍ସନ୍ କୋଡ୍ରୁ ଇମ୍ପୋର୍ଟ ଉପରେ ଥିବା ନିଷେଧକୁ ବଜାୟ ରଖେ।
