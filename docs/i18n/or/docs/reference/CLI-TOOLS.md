## ଏହା କିପରି କାମ କରେ

```
CLI କୋଡ୍ଗୁଡ଼ିକ / CLI ଏଜେଣ୍ଟ୍ଗୁଡ଼ିକ (ବ୍ୟବହାର ପ୍ରବାହ):
Claude / Codex / OpenCode / Cline / KiloCode / Continue / Hermes Agent / Goose / ...
           │
           ▼  (ସମସ୍ତେ OmniRoute ଆଡ଼କୁ ନିର୍ଦ୍ଦେଶ କରନ୍ତି)
    http://YOUR_SERVER:20128/v1
           │
           ▼  (OmniRoute ସଠିକ୍ ପ୍ରଦାନକାରୀଙ୍କୁ ରୁଟ୍ କରେ)
    Anthropic / OpenAI / Gemini / DeepSeek / Groq / Mistral / ...

ACP ଏଜେଣ୍ଟ୍ଗୁଡ଼ିକ (ବିପରୀତ ଆରମ୍ଭ ପ୍ରବାହ):
    କ୍ଲାଏଣ୍ଟ ଅନୁରୋଧ → OmniRoute → stdio/ACP ମାଧ୍ୟମରେ CLI ଆରମ୍ଭ କରେ → ପ୍ରତିକ୍ରିୟା
```

**ଲାଭଗୁଡ଼ିକ:**

- ସମସ୍ତ ଟୁଲ୍ ପରିଚାଳନା ପାଇଁ ଗୋଟିଏ API କୀ
- ଡ୍ୟାଶବୋର୍ଡରେ ସମସ୍ତ CLI ପାଇଁ ଖର୍ଚ୍ଚ ଟ୍ରାକିଂ
- ପ୍ରତ୍ୟେକ ଟୁଲ୍କୁ ପୁନଃବିନ୍ୟାସ ନକରି ମଡେଲ୍ ପରିବର୍ତ୍ତନ
- ସ୍ଥାନୀୟ ଏବଂ ରିମୋଟ୍ ସର୍ଭର୍ଗୁଡ଼ିକରେ କାମ କରେ (VPS, Docker, Akamai, Cloudflare Tunnel)

## `setup-*` ସହିତ ସ୍ୱୟଂଚାଳିତ ଭାବେ କନଫିଗର୍ କରନ୍ତୁ

ଆପଣଙ୍କୁ ପ୍ରତ୍ୟେକ ଟୁଲ୍ର କନଫିଗ୍ ହାତରେ ଲେଖିବାକୁ ପଡ଼ିବ ନାହିଁ। OmniRoute ପ୍ରତ୍ୟେକ ସମର୍ଥିତ CLI ପାଇଁ ଏକ `setup-*`
କମାଣ୍ଡ ପ୍ରଦାନ କରେ, ଯାହା ଚାଲୁଥିବା OmniRoute (ସ୍ଥାନୀୟ କିମ୍ବା ରିମୋଟ୍)ରୁ **ଲାଇଭ୍** ମଡେଲ୍ କ୍ୟାଟାଲଗ୍ ପଢ଼େ
ଏବଂ ଆପଣଙ୍କ ମେସିନ୍ରେ ଟୁଲ୍ର ନିଜସ୍ୱ କନଫିଗ୍ ଲେଖେ:

```bash
omniroute setup-codex        omniroute setup-claude       omniroute setup-opencode
omniroute setup-cline        omniroute setup-kilo         omniroute setup-continue
omniroute setup-cursor       omniroute setup-roo          omniroute setup-crush
omniroute setup-goose        omniroute setup-qwen         omniroute setup-aider
omniroute setup-5dive        omniroute setup-zed
```

ପ୍ରତ୍ୟେକ କମାଣ୍ଡ `--remote <url> --api-key <key>` (ଏକ ରିମୋଟ୍ OmniRoute ବିପକ୍ଷରେ ସ୍ଥାନୀୟ ଟୁଲ୍କୁ
କନଫିଗର୍ କରିବା), `--dry-run` (କିଛି ନ ଲେଖି ପୂର୍ବାବଲୋକନ କରିବା), ଏବଂ `--port` ଗ୍ରହଣ କରେ। ମଡେଲ୍
ସ୍ୱୟଂ-ଆବିଷ୍କାର ସୁବିଧା ନଥିବା ଟୁଲ୍ଗୁଡ଼ିକ (Cline, Kilo, Roo, Goose, Aider, Qwen, 5dive)
`--model <id>` (ଏବଂ ଅଣ-ଇଣ୍ଟରାକ୍ଟିଭ୍ ରନ୍ ପାଇଁ `--yes`) ଗ୍ରହଣ କରେ। `setup-5dive` ହେଉଛି ଏକମାତ୍ର
ରେସିପି, ଯାହା `$HOME` ଅଧୀନରେ ଲେଖେ ନାହିଁ: ଏହା ଫ୍ଲିଟ୍ ହୋଷ୍ଟରେ root-ମାଲିକାନାର ଏକ ଅଥ୍ ପ୍ରୋଫାଇଲ୍
ଲେଖି 5dive ଏଜେଣ୍ଟ ଫ୍ଲିଟ୍କୁ କନଫିଗର୍ କରେ, ତେଣୁ ଏହା `sudo` ମାଧ୍ୟମରେ ନିଜକୁ ପୁନଃ-ନିଷ୍ପାଦନ କରେ
ଏବଂ ଏହାର ନିଜସ୍ୱ କୌଣସି ରିମୋଟ୍ ମୋଡ୍ ନାହିଁ। ଉପଯୁକ୍ତ env ଇଞ୍ଜେକ୍ଟ କରି ଏବଂ ଆଦୌ କୌଣସି କନଫିଗ୍ ନ ଲେଖି ଏକ CLI
ଚାଲୁ କରିବାକୁ, ସାଧାରଣ `omniroute run <target>` ଲଞ୍ଚର୍ ବ୍ୟବହାର କରନ୍ତୁ (claude, codex, aider, goose, opencode, qwen,
gemini — ଟାର୍ଗେଟ୍ ଏବଂ ଉପନାମଗୁଡ଼ିକ `bin/cli/cli-manifest.mjs`ରୁ ଆସେ); ପୁରୁଣା
ପ୍ରତି-ଟୁଲ୍ ଲଞ୍ଚର୍ `omniroute launch` (Claude Code) ଏବଂ `omniroute launch-codex`
(Codex) ଏବେ ମଧ୍ୟ ଉପଲବ୍ଧ ଅଛି। Gemini CLI କେବଳ ଲଞ୍ଚ ପାଇଁ: ଏହା ଏକ `omniroute run`
ଟାର୍ଗେଟ୍, କିନ୍ତୁ ଏହାର କୌଣସି `setup-*`/`configure` ରେସିପି ନାହିଁ।

> **ସମ୍ପୂର୍ଣ୍ଣ ସନ୍ଦର୍ଭ:** ମୁଖ୍ୟ ସାରଣୀ — ପ୍ରତ୍ୟେକ କମାଣ୍ଡ କ’ଣ ଲେଖେ, ପ୍ରତ୍ୟେକ ଫ୍ଲାଗ୍,
> ସ୍ଥାନୀୟ ବନାମ ରିମୋଟ୍, ଏବଂ କେଉଁ ଟୁଲ୍କୁ `/v1` ସଫିକ୍ସ ଆବଶ୍ୟକ — ଏଠାରେ ଉପଲବ୍ଧ:
> **[CLI ଇଣ୍ଟିଗ୍ରେସନ୍ଗୁଡ଼ିକ](../guides/CLI-INTEGRATIONS.md)**।

### ଏଗୁଡ଼ିକୁ ଏକ କଣ୍ଟେନର୍ ଭିତରେ ଚଲାଇବା

OmniRoute କଣ୍ଟେନର୍ ଭିତରେ ନିଷ୍ପାଦିତ ଏକ `setup-*` କମାଣ୍ଡ କଣ୍ଟେନର୍ର ନିଜସ୍ୱ homeରେ ଲେଖେ,
ଯାହାକୁ କୌଣସି ହୋଷ୍ଟ CLI ପଢ଼େ ନାହିଁ ଏବଂ ଯାହା କଣ୍ଟେନର୍ ସହିତ ଅଦୃଶ୍ୟ ହୋଇଯାଏ।
OmniRoute ଏହା ଚିହ୍ନଟ କରେ ଏବଂ କିଛି ଲେଖିବା ପରିବର୍ତ୍ତେ ନିର୍ଦ୍ଦେଶନା ସହିତ `2` କୋଡ୍ରେ ପ୍ରସ୍ଥାନ କରେ।
ଆଗକୁ ବଢ଼ିବାର ଦୁଇଟି ସମର୍ଥିତ ଉପାୟ ଅଛି — ହୋଷ୍ଟରେ CLI ଇନ୍ଷ୍ଟଲ୍ କରି କଣ୍ଟେନର୍କୁ
`omniroute connect` କରନ୍ତୁ, କିମ୍ବା କନଫିଗ୍ ଡିରେକ୍ଟୋରୀଗୁଡ଼ିକୁ bind-mount କରି
`CLI_CONFIG_HOME` (compose `host` ପ୍ରୋଫାଇଲ୍) ସେଟ୍ କରନ୍ତୁ। ପ୍ରତ୍ୟେକ `setup-*` କମାଣ୍ଡ ସହିତ
`omniroute configure` ଏବଂ `omniroute config set` ମଧ୍ୟ
`--allow-container-write` ଗ୍ରହଣ କରେ, ଯେତେବେଳେ କଣ୍ଟେନର୍ର ନିଜସ୍ୱ CLIଗୁଡ଼ିକୁ କନଫିଗର୍ କରିବା ହିଁ ଆପଣଙ୍କର
ପ୍ରକୃତ ଉଦ୍ଦେଶ୍ୟ; ସର୍ଭର୍ ପାଇଁ `OMNIROUTE_ALLOW_CONTAINER_CONFIG_WRITE=true` ମଧ୍ୟ ସମାନ କାମ କରେ।
[Docker ଗାଇଡ୍ → ହୋଷ୍ଟ CLI ଟୁଲ୍ଗୁଡ଼ିକୁ କନଫିଗର୍ କରିବା](../guides/DOCKER_GUIDE.md#configuring-host-cli-tools-when-omniroute-runs-in-docker) ଦେଖନ୍ତୁ।

ଡ୍ୟାସ୍ବୋର୍ଡର **ପ୍ରୟୋଗ ଏଣ୍ଡପଏଣ୍ଟ** (`POST /api/cli-tools/apply`) ସମାନ
ସୁରକ୍ଷା ନିୟମ ଲାଗୁ କରେ: ଏକ କଣ୍ଟେନର୍ରେ, ଯେଉଁ ରାଇଟ୍ର ଟାର୍ଗେଟ୍ ହୋଷ୍ଟରୁ bind-mount ହୋଇନାହିଁ,
ତାହା **`422`** ସହିତ `containerEphemeralTarget: true`, ସୁରକ୍ଷିତ ତ୍ରୁଟି
ପାଠ୍ୟ ଏବଂ — ହୋଷ୍ଟ ରେସିପି ଥିବା ଟୁଲ୍ଗୁଡ଼ିକ ପାଇଁ (claude, codex, opencode, cline,

ସମସ୍ତ ଟୁଲ୍ ଚିହ୍ନଟ ଗୋଟିଏ ଏଣ୍ଡପଏଣ୍ଟ ମାଧ୍ୟମରେ ସମାହାର କରାଯାଏ:

**`GET /api/cli-tools/all-statuses`**

- ପ୍ରମାଣୀକରଣ: `requireCliToolsAuth(request)` (ଅନ୍ୟ `/api/cli-tools/` ରୁଟ୍ଗୁଡ଼ିକ ସହିତ ସମାନ)
- ଫେରାଏ: `Record<toolId, ToolBatchStatus>` (ଟାଇପ୍: `src/shared/types/cliBatchStatus.ts`)
- କୌଶଳ: ସମସ୍ତ ଟୁଲ୍ ଉପରେ `Promise.all`, ପ୍ରତ୍ୟେକ ଟୁଲ୍ ପାଇଁ 5s ଟାଇମ୍ଆଉଟ୍
- କ୍ୟାଶ୍: କନଫିଗ୍ ଫାଇଲ୍ `mtime` ଦ୍ୱାରା ସୂଚୀବଦ୍ଧ ଇନ୍-ମେମୋରି LRU। mtime ପରିବର୍ତ୍ତନ ହେଲେ କ୍ୟାଶ୍ ଅବୈଧ ହୁଏ। ସର୍ଭର୍ ପୁନଃଆରମ୍ଭ ହେଲେ ରିସେଟ୍ ହୁଏ।

ପ୍ରତ୍ୟେକ ଟୁଲ୍ ପାଇଁ ପ୍ରତିକ୍ରିୟାର ଗଠନ:

```ts
interface ToolBatchStatus {
  detection: {
    installed: boolean;
    runnable: boolean;
    version?: string;
    command?: string;
    commandPath?: string;
    reason?: string;
  };
  config: {
    status: "configured" | "not_configured" | "not_installed" | "unknown" | "other";
    endpoint?: string | null;
    lastConfiguredAt?: string | null;
  };
  error?: string; // ପରିଷ୍କୃତ, କୌଣସି ଷ୍ଟାକ୍ ଟ୍ରେସ୍ ନାହିଁ
}
```

#### VS Code Insiders (`chatLanguageModels.json`)

VS Code Insiders କଷ୍ଟମ୍ endpoint modelଗୁଡ଼ିକ ପାଇଁ କନ୍ଫିଗର୍ ହୋଇଥିଲେ ଏବଂ ଆପଣ OmniRouteକୁ କୌଣସି କଷ୍ଟମ୍ header field ବିନା କାର୍ଯ୍ୟ କରାଇବାକୁ ଚାହୁଁଥିଲେ, ଏହା ବ୍ୟବହାର କରନ୍ତୁ।

**ସୁପାରିଶ କରାଯାଇଥିବା ଅବସ୍ଥାନ:**

- Linux: `~/.config/Code - Insiders/User/chatLanguageModels.json`
- Windows: `%APPDATA%/Code - Insiders/User/chatLanguageModels.json`

**ଟୋକେନ୍ଯୁକ୍ତ OmniRoute ଉପନାମ ବ୍ୟବହାର କରି ଉଦାହରଣ:**

```json
[
  {
    "vendor": "customendpoint",
    "id": "auto",
    "name": "OmniRoute Auto",
    "family": "gpt-4",
    "version": "1.0.0",
    "url": "http://localhost:20128/api/v1/vscode/sk-your-omniroute-key/chat/completions",
    "modelsUrl": "http://localhost:20128/api/v1/vscode/sk-your-omniroute-key/models",
    "requestFormat": "openai-chat-completions",
    "contextWindow": 256000,
    "maxOutputTokens": 32768,
    "auth": {
      "type": "none"
    }
  }
]
```

**ଟିପ୍ପଣୀ:**

- `sk-your-omniroute-key`କୁ OmniRouteରେ ସୃଷ୍ଟି କରାଯାଇଥିବା ଏକ API କୀ ସହିତ ବଦଳାନ୍ତୁ।
- `url` ଫିଲ୍ଡଟି `/api/v1/vscode/{token}/chat/completions`କୁ ସୂଚିତ କରିବା ଉଚିତ।
- `modelsUrl` ଫିଲ୍ଡଟି `/api/v1/vscode/{token}/models`କୁ ସୂଚିତ କରିବା ଉଚିତ।
- କ୍ଲାଏଣ୍ଟ କଷ୍ଟମ୍ ହେଡର୍କୁ ସମର୍ଥନ କରୁଥିଲେ, ସାଧାରଣ `/v1` + Bearer ହେଡର୍ ପ୍ରବାହକୁ ପ୍ରାଧାନ୍ୟ ଦିଅନ୍ତୁ।
- URLରେ ସନ୍ନିବେଶିତ ଟୋକେନ୍ଗୁଡ଼ିକ ଏକ ସୁସଙ୍ଗତତା ବିକଳ୍ପ ଏବଂ ଏଡିଟର୍ ଲଗ୍ କିମ୍ବା ପ୍ରକ୍ସି ଇତିହାସରେ ଦୃଶ୍ୟମାନ ହୋଇପାରେ।

## 10. ଆଭ୍ୟନ୍ତରୀଣ OmniRoute CLI

`omniroute` ବାଇନାରୀ ସର୍ଭର ଜୀବନଚକ୍ର, ସେଟ୍ଅପ୍, ନିଦାନ ଏବଂ ପ୍ରଦାତା ପରିଚାଳନା ପାଇଁ କମାଣ୍ଡ୍ଗୁଡ଼ିକ ପ୍ରଦାନ କରେ। ପ୍ରବେଶ ବିନ୍ଦୁ: `bin/omniroute.mjs`।

```bash
omniroute                              # ସର୍ଭର ଆରମ୍ଭ କରନ୍ତୁ (ଡିଫଲ୍ଟ ପୋର୍ଟ 20128)
omniroute setup                        # ଇଣ୍ଟରାକ୍ଟିଭ୍ ସେଟ୍ଅପ୍ ୱିଜାର୍ଡ
omniroute doctor                       # କନଫିଗ୍, DB, ପୋର୍ଟ ଏବଂ ରନ୍ଟାଇମ୍ ଯାଞ୍ଚ କରନ୍ତୁ
omniroute providers list               # କନଫିଗର୍ କରାଯାଇଥିବା ପ୍ରଦାତା ସଂଯୋଗଗୁଡ଼ିକ
omniroute providers test-all           # ପ୍ରତ୍ୟେକ ସକ୍ରିୟ ସଂଯୋଗ ପରୀକ୍ଷା କରନ୍ତୁ
omniroute reset-password               # ଆଡ୍ମିନ୍ ପାସ୍ୱାର୍ଡ ରିସେଟ୍ କରନ୍ତୁ
omniroute logs                         # ଅନୁରୋଧ ଲଗ୍ଗୁଡ଼ିକ ଷ୍ଟ୍ରିମ୍ କରନ୍ତୁ
omniroute health                       # ବିସ୍ତୃତ ସ୍ୱାସ୍ଥ୍ୟ ସ୍ଥିତି (ବ୍ରେକର୍, କ୍ୟାଶ୍, ମେମୋରି)
omniroute --version                    # ସଂସ୍କରଣ ପ୍ରିଣ୍ଟ୍ କରନ୍ତୁ
omniroute --help                       # ସମସ୍ତ କମାଣ୍ଡ୍ ଦେଖାନ୍ତୁ
```

### ସେଟ୍ଅପ୍ ଏବଂ ପ୍ରାରମ୍ଭୀକରଣ

```bash
omniroute setup                        # ଇଣ୍ଟରାକ୍ଟିଭ୍ ସେଟ୍ଅପ୍ ୱିଜାର୍ଡ
omniroute setup --non-interactive      # CI/ସ୍ୱୟଂଚାଳନ ମୋଡ୍ (env vars + flags ପଢ଼େ)
omniroute setup --password '<value>'   # ଆଡ୍ମିନ୍ ପାସ୍ୱାର୍ଡ ସିଧାସଳଖ ସେଟ୍ କରନ୍ତୁ
omniroute setup --add-provider \
  --provider openai \
  --api-key '<value>' \
  --test-provider                      # ଏକାଥରେ ପ୍ରଦାତା ଯୋଡ଼ନ୍ତୁ ଏବଂ ପରୀକ୍ଷା କରନ୍ତୁ
```

ନନ୍-ଇଣ୍ଟରାକ୍ଟିଭ୍ ସେଟ୍ଅପ୍ ପାଇଁ ସ୍ୱୀକୃତ ପରିବେଶ ଭେରିଏବଲ୍ଗୁଡ଼ିକ:

| ଭେରିଏବଲ୍            | ଉଦ୍ଦେଶ୍ୟ                                                              |
| ------------------- | --------------------------------------------------------------------- |
| `OMNIROUTE_API_KEY` | ପ୍ରଦାତା API କୀ (Commander `.env()` ମାଧ୍ୟମରେ `--api-key` ସହିତ ବାନ୍ଧିତ) |
| `DATA_DIR`          | OmniRoute ଡାଟା ଡିରେକ୍ଟୋରିକୁ ଓଭର୍ରାଇଡ୍ କରେ                             |

ଅନ୍ୟ ସମସ୍ତ ନନ୍-ଇଣ୍ଟରାକ୍ଟିଭ୍ ଇନ୍ପୁଟ୍ ପରିବେଶ ଭେରିଏବଲ୍ ଭାବରେ ନୁହେଁ, ଫ୍ଲାଗ୍ ଭାବରେ ପାସ୍ କରାଯାଏ:
`--password`, `--provider`, `--provider-name`, `--provider-base-url`, `--default-model`
(ଉପରେ ଥିବା `omniroute setup` ବିକଳ୍ପଗୁଡ଼ିକ ଦେଖନ୍ତୁ)।

### ନିଦାନ

```bash
omniroute doctor                       # କନଫିଗ୍, DB, ପୋର୍ଟ, ରନ୍ଟାଇମ୍, ମେମୋରି ଏବଂ ସଜୀବତା ଯାଞ୍ଚ କରନ୍ତୁ
omniroute doctor --json                # ମେସିନ୍-ପଠନଯୋଗ୍ୟ JSON
omniroute doctor --no-liveness         # HTTP ସ୍ୱାସ୍ଥ୍ୟ ଯାଞ୍ଚକୁ ଏଡ଼ାଇ ଯାଆନ୍ତୁ
omniroute doctor --host 0.0.0.0        # ସଜୀବତା ହୋଷ୍ଟକୁ ଓଭର୍ରାଇଡ୍ କରନ୍ତୁ
omniroute doctor --liveness-url <url>  # ସମ୍ପୂର୍ଣ୍ଣ ସ୍ୱାସ୍ଥ୍ୟ ଏଣ୍ଡପଏଣ୍ଟ୍ URL ଓଭର୍ରାଇଡ୍
```

doctor ଏହି ଯାଞ୍ଚଗୁଡ଼ିକ ଚଲାଏ: `Config`, `Database`, `Storage/encryption`,
`Port availability`, `Node runtime`, `Native binary` (better-sqlite3),
`Memory`, ଏବଂ `Server liveness`। କୌଣସି ଯାଞ୍ଚ `fail` ହେଲେ ଏହା ଏକ ଅଣ-ଶୂନ୍ୟ କୋଡ୍ ସହିତ ପ୍ରସ୍ଥାନ କରେ।

### ପ୍ରଦାତା ପରିଚାଳନା

```bash
omniroute providers available                       # OmniRoute ପ୍ରଦାତା କ୍ୟାଟାଲଗ୍
omniroute providers available --search openai       # id/name/alias/category ଅନୁଯାୟୀ କ୍ୟାଟାଲଗ୍ ଫିଲ୍ଟର୍ କରନ୍ତୁ
omniroute providers available --category api-key    # ଶ୍ରେଣୀ ଅନୁଯାୟୀ ଫିଲ୍ଟର୍ କରନ୍ତୁ (api-key, oauth, free, ...)
omniroute providers available --json                # ମେସିନ୍-ପଠନଯୋଗ୍ୟ JSON

omniroute providers list                            # କନଫିଗର୍ କରାଯାଇଥିବା ପ୍ରଦାତା ସଂଯୋଗଗୁଡ଼ିକ
omniroute providers list --json

omniroute providers test <id|name>                  # ଗୋଟିଏ କନଫିଗର୍ କରାଯାଇଥିବା ସଂଯୋଗ ପରୀକ୍ଷା କରନ୍ତୁ
omniroute providers test-all                        # ପ୍ରତ୍ୟେକ ସକ୍ରିୟ ସଂଯୋଗ ପରୀକ୍ଷା କରନ୍ତୁ
omniroute providers validate                        # କେବଳ-ଲୋକାଲ୍ ଗଠନାତ୍ମକ ବୈଧତା ଯାଞ୍ଚ
omniroute providers add <provider> --credential-env PROVIDER_KEY
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth <provider>                 # ବିଦ୍ୟମାନ OAuth ପ୍ରବାହ
omniroute providers edit <id|name> --default-model <model>
omniroute providers remove <id|name> --yes
```

`providers add/import/auth/edit/remove` API-ପ୍ରଥମ ଅଟେ ଏବଂ ସେଥିପାଇଁ
ସକ୍ରିୟ ଲୋକାଲ୍ କିମ୍ବା ରିମୋଟ୍ କଣ୍ଟେକ୍ସ୍ଟ ବିପରୀତରେ କାମ କରେ। କ୍ରେଡେନ୍ସିଆଲ୍ ଇନ୍ପୁଟ୍ ପାଇଁ
`--credential-stdin` କିମ୍ବା `--credential-env` ବ୍ୟବହାର କରିବା ଉଚିତ; `--dry-run --json` କେବଳ
ଗୋପନୀୟ କରାଯାଇଥିବା ଉପସ୍ଥିତି/ଆକୃତି ରିପୋର୍ଟ କରେ। `providers available` OmniRoute କ୍ୟାଟାଲଗ୍ ପଢ଼େ;
`providers list/test/test-all/validate` ସେମାନଙ୍କର ଲୋକାଲ୍ SQLite ଆଚରଣ ବଜାୟ ରଖେ ଏବଂ
ସର୍ଭର ଚାଲୁଥିବା ଆବଶ୍ୟକ କରେ ନାହିଁ।

ଏକ କଷ୍ଟମ୍ OpenAI-ସୁସଙ୍ଗତ କିମ୍ବା Anthropic-ସୁସଙ୍ଗତ ନୋଡ୍ ପାଇଁ, `omniroute nodes add` ଦ୍ୱାରା ଫେରସ୍ତ ହୋଇଥିବା
ନୋଡ୍ ID ସହିତ କ୍ରେଡେନ୍ସିଆଲ୍ ଯୋଡ଼ନ୍ତୁ, ଏଥିପାଇଁ `omniroute keys add "$NODE_ID" --stdin` ବ୍ୟବହାର କରନ୍ତୁ।
ଏଥିପାଇଁ ସକ୍ରିୟ କଣ୍ଟେକ୍ସ୍ଟରେ ଏକ ଚାଲୁଥିବା ସର୍ଭର ଏବଂ ପରିଚାଳନା ପ୍ରମାଣୀକରଣ ଆବଶ୍ୟକ।
CLI `POST /api/providers` ବ୍ୟବହାର କରେ, ଯାହା ନୋଡ୍କୁ ବୈଧ କରେ ଏବଂ ଏହାର ଏଣ୍ଡପଏଣ୍ଟ୍
ସେଟିଂସ୍କୁ ସଂଯୋଗରେ କପି କରେ। ନୋଡ୍ ଅନୁପସ୍ଥିତି, ଅନୁମୋଦନ ବିଫଳତା କିମ୍ବା ଅନୁପଲବ୍ଧ
ସର୍ଭର କୌଣସି ଲୋକାଲ୍ ଫଲ୍ବ୍ୟାକ୍ କ୍ରେଡେନ୍ସିଆଲ୍ ସୃଷ୍ଟି ନକରି ଏକ ତ୍ରୁଟି ଫେରାଏ।

`nodes add --base-url` ନୋଡ୍ ଏଣ୍ଡପଏଣ୍ଟ୍ ସେଟ୍ କରେ; ଏହା `OMNIROUTE_BASE_URL` ମଧ୍ୟରେ ଥିବା ସର୍ଭର ଠିକଣାଠାରୁ
ଭିନ୍ନ। OpenAPI ଫାଇଲ୍ଗୁଡ଼ିକ ପାଇଁ,
`omniroute openapi dump --format json --out ./openapi.json` ବ୍ୟବହାର କରନ୍ତୁ; ଗ୍ଲୋବାଲ୍ `--output`
ଏକ ଗନ୍ତବ୍ୟ ଫାଇଲ୍ନାମ ନୁହେଁ, CLI ପ୍ରଦର୍ଶନ ଫର୍ମାଟିଂ ଚୟନ କରେ।

### ପୁନରୁଦ୍ଧାର ଏବଂ ରିସେଟ୍

```bash
omniroute reset-password                # ଆଡ୍ମିନ୍ ପାସ୍ୱାର୍ଡ ରିସେଟ୍ କରନ୍ତୁ (ଏହା ମଧ୍ୟ: omniroute-reset-password)
omniroute reset-encrypted-columns       # ଏନ୍କ୍ରିପ୍ଟ୍ କରାଯାଇଥିବା କ୍ରେଡେନ୍ସିଆଲ୍ ରିସେଟ୍ ପାଇଁ ଚେତାବନୀ + ଡ୍ରାଏ-ରନ୍ ଦେଖାନ୍ତୁ
omniroute reset-encrypted-columns --force  # SQLite ରେ ଏନ୍କ୍ରିପ୍ଟ୍ କରାଯାଇଥିବା କ୍ରେଡେନ୍ସିଆଲ୍ଗୁଡ଼ିକୁ ପ୍ରକୃତରେ null କରନ୍ତୁ
```

### କ୍ରେଡେନ୍ସିଆଲ୍ ରପ୍ତାନି (⚠ ସତର୍କତାର ସହିତ ପରିଚାଳନା କରନ୍ତୁ)

```bash
omniroute auth export                                 # ଚେତାବନୀ + ନିଶ୍ଚିତକରଣ ଗେଟ୍ ଦେଖାନ୍ତୁ — କୌଣସି DB ଆକ୍ସେସ୍ ନାହିଁ
omniroute auth export --force                          # ସମସ୍ତ ସଂଯୋଗର ଡିକ୍ରିପ୍ଟ୍ କରାଯାଇଥିବା କ୍ରେଡେନ୍ସିଆଲ୍ଗୁଡ଼ିକୁ JSON ଭାବେ stdout କୁ ରପ୍ତାନି କରନ୍ତୁ
omniroute auth export --force --id <id>                 # କେବଳ ମେଳ ଖାଉଥିବା ସଂଯୋଗକୁ ରପ୍ତାନି କରନ୍ତୁ
omniroute auth export --force --format env               # OMNIROUTE_<PROVIDER>_<FIELD>=<value> ଧାଡ଼ିଗୁଡ଼ିକ ନିର୍ଗତ କରନ୍ତୁ
omniroute auth export --force --out creds.json           # ଏକ ଫାଇଲ୍କୁ ଲେଖନ୍ତୁ (0600 ଅନୁମତି ସହିତ ସୃଷ୍ଟି କରାଯାଇଛି)
```

`auth export` **କେବଳ-ଲୋକାଲ୍** ଅଟେ (ସିଧାସଳଖ SQLite ପଠନ, କୌଣସି HTTP ରୁଟ୍ ନାହିଁ) ଏବଂ ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ
**ପ୍ଲେନ୍ଟେକ୍ସଟ୍** `apiKey`/`accessToken`/`refreshToken`/`idToken` ମୂଲ୍ୟଗୁଡ଼ିକୁ ପ୍ରିଣ୍ଟ୍/ଲେଖେ — ଏହା ହିଁ ବୈଶିଷ୍ଟ୍ୟ, କୌଣସି
ବଗ୍ ନୁହେଁ। `--force` ବିନା ଡାଟାବେସ୍ରୁ କିଛି ପଢ଼ାଯାଏ ନାହିଁ ଏବଂ କିଛି ଡିକ୍ରିପ୍ଟ୍ କରାଯାଏ ନାହିଁ। କୌଣସି ପ୍ଲେନ୍ଟେକ୍ସଟ୍ ନିର୍ଗତ ହେବା ପୂର୍ବରୁ ସର୍ବଦା stderr-ରେ
ଏକ ସତର୍କତା ବ୍ୟାନର୍ ପ୍ରିଣ୍ଟ୍ ହୁଏ। `STORAGE_ENCRYPTION_KEY` ସେଟ୍ ହୋଇଥିବା ଆବଶ୍ୟକ।
ଡିକ୍ରିପ୍ଟ୍ ହେବାରେ ବିଫଳ ହେଉଥିବା ଫିଲ୍ଡ୍କୁ (ପୁରୁଣା କୀ, ଦୂଷିତ ସାଇଫର୍ଟେକ୍ସଟ୍) ସମଗ୍ର ଏକ୍ସପୋର୍ଟ୍ ବାତିଲ୍ କରିବା କିମ୍ବା ଅନ୍ତର୍ନିହିତ ତ୍ରୁଟିକୁ ପ୍ରକାଶ କରିବା ପରିବର୍ତ୍ତେ
`<field>DecryptFailed: true` ଭାବେ ରିପୋର୍ଟ୍ କରାଯାଏ।

### ଅନ୍ୟାନ୍ୟ ସବ୍କମାଣ୍ଡ୍

ଅନ୍ୟଥା ଉଲ୍ଲେଖ ନଥିଲେ, ଏଗୁଡ଼ିକ ଏକ ଚାଲୁଥିବା OmniRoute ସର୍ଭର୍ ଅଛି ବୋଲି ଧରିନିଏ:

```bash
omniroute status                       # ବିସ୍ତୃତ ରନ୍ଟାଇମ୍ ସ୍ଥିତି
omniroute logs                         # ଅନୁରୋଧ ଲଗ୍ଗୁଡ଼ିକୁ ଷ୍ଟ୍ରିମ୍ କରନ୍ତୁ (--json, --search, --follow)
omniroute config list                  # ବିନ୍ୟାସିତ CLI ଟୁଲ୍ଗୁଡ଼ିକୁ ପ୍ରଦର୍ଶନ କରନ୍ତୁ

omniroute provider list                # ଉପଲବ୍ଧ ପ୍ରଦାତାମାନଙ୍କୁ ତାଲିକାଭୁକ୍ତ କରନ୍ତୁ (providers list-ର ଉପନାମ)
omniroute provider add                 # ଏକ ଟୁଲ୍ରେ OmniRoute-କୁ ପ୍ରଦାତା ଭାବେ ପଞ୍ଜୀକୃତ କରନ୍ତୁ
omniroute keys add | list | remove     # API କୀଗୁଡ଼ିକୁ ପରିଚାଳନା କରନ୍ତୁ
omniroute models [provider]            # ମଡେଲ୍ଗୁଡ଼ିକୁ ତାଲିକାଭୁକ୍ତ କରନ୍ତୁ (--json, --search)
omniroute combo list | switch | create | delete

omniroute backup                       # ବିନ୍ୟାସ + DB-ର ସ୍ନାପ୍ସଟ୍ ନିଅନ୍ତୁ
omniroute restore                      # ପୂର୍ବ ସ୍ନାପ୍ସଟ୍ରୁ ପୁନଃସ୍ଥାପନ କରନ୍ତୁ

omniroute health                       # ବିସ୍ତୃତ ସ୍ୱାସ୍ଥ୍ୟ ସ୍ଥିତି (ବ୍ରେକର୍, କ୍ୟାଶ୍, ମେମୋରି)
omniroute quota                        # ପ୍ରଦାତା କୋଟା ବ୍ୟବହାର
omniroute cache                        # କ୍ୟାଶ୍ ସ୍ଥିତି
omniroute cache clear                  # ସେମାଣ୍ଟିକ୍ + ସିଗ୍ନେଚର୍ କ୍ୟାଶ୍ଗୁଡ଼ିକୁ ସଫା କରନ୍ତୁ

omniroute mcp status | restart         # MCP ସର୍ଭର୍ ସ୍ଥିତି / ପୁନଃଚାଳନ
omniroute a2a status | card            # A2A ସର୍ଭର୍ ସ୍ଥିତି / ଏଜେଣ୍ଟ୍ କାର୍ଡ୍

omniroute tunnel list | create | stop  # ଟନେଲ୍ଗୁଡ଼ିକୁ ପରିଚାଳନା କରନ୍ତୁ (cloudflare/tailscale/ngrok)
omniroute env show | get <k> | set <k> <v>  # ପରିବେଶ ଭେରିଏବଲ୍ଗୁଡ଼ିକୁ ଯାଞ୍ଚ / ସେଟ୍ କରନ୍ତୁ (ଅସ୍ଥାୟୀ)

omniroute test                         # ପ୍ରଦାତା ସଂଯୋଗର ସ୍ମୋକ୍ ଟେଷ୍ଟ୍
omniroute update                       # ଅପଡେଟ୍ ଯାଞ୍ଚ କରନ୍ତୁ
omniroute completion                   # ଶେଲ୍ କମ୍ପ୍ଲିସନ୍ ସୃଷ୍ଟି କରନ୍ତୁ
```

## OmniRoute CLI ଦ୍ୱାରା ଇନ୍ଫରେନ୍ସ-କୀ ନୀତି ପରିଚାଳନା କରନ୍ତୁ

ଏକ ପ୍ରମାଣିତ ପରିଚାଳନା କଣ୍ଟେକ୍ସ୍ଟ ବ୍ୟବହାର କରନ୍ତୁ ([ରିମୋଟ୍ ମୋଡ୍](../guides/REMOTE-MODE.md) ଦେଖନ୍ତୁ)
ଯାହାଦ୍ୱାରା ଏକ ବିଦ୍ୟମାନ ଇନ୍ଫରେନ୍ସ କୀକୁ ତାହାର ID ଦ୍ୱାରା ଯାଞ୍ଚ କିମ୍ବା ଅପଡେଟ୍ କରିପାରିବେ:

```bash
omniroute --output json keys policy show KEY_ID
omniroute keys policy set KEY_ID --unrestricted
omniroute --output json keys policy show KEY_ID
```

`--unrestricted` ହେଉଛି `--model-access-mode all`ର ଏକ ଉପନାମ। ଅପଡେଟ୍ଟି
ମଡେଲ୍ ଅନୁମତି-ତାଲିକାକୁ ସଫା କରେ। ଏହା ସ୍କୋପ୍, ସଂଯୋଗ ନିୟମ, ଅବରୋଧିତ ମଡେଲ୍, ହାର ସୀମା
ଏବଂ ଖର୍ଚ୍ଚ ସୀମାଗୁଡ଼ିକୁ ଅପରିବର୍ତ୍ତିତ ରଖେ, ତେଣୁ ସେହି ଅନ୍ୟ ନିୟନ୍ତ୍ରଣଗୁଡ଼ିକ ଏବେ ମଧ୍ୟ ଏକ ଅନୁରୋଧକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରିପାରନ୍ତି। ଏକ ସ୍ପଷ୍ଟ
`--allowed-models ""` ମଧ୍ୟ `all` ବାଛେ; କୌଣସି ଅନୁମୋଦିତ ମଡେଲ୍ ନଥିବା ଏକ ସୀମିତ କୀ ରଖିବା ପାଇଁ ଏହାକୁ
`--model-access-mode restricted` ସହ ମିଶାନ୍ତୁ।
ଏକ ଅଣ-ଖାଲି କମା-ପୃଥକ ତାଲିକା, ସ୍ପଷ୍ଟ ଭାବରେ ଅନ୍ୟ କିଛି ଉଲ୍ଲେଖ ନହୋଇଥିଲେ, `restricted` ବାଛେ।
ବିରୋଧାଭାସୀ `all` ସହ ଏକ ଅଣ-ଖାଲି ଅନୁମତି-ତାଲିକା ଥିଲେ, ଅନୁରୋଧ ପଠାଇବା ପୂର୍ବରୁ ଏହାକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ।

`--rate-limit 30` ପ୍ରତି ମିନିଟ୍ରେ ଅନୁରୋଧ ସଂଖ୍ୟା ସେଟ୍ କରେ ଏବଂ ଅନ୍ୟ ସମୟ
ଅବଧିଗୁଡ଼ିକ ପାଇଁ ନିୟମଗୁଡ଼ିକୁ ଅପରିବର୍ତ୍ତିତ ରଖେ। `--max-cost 5` ସାପ୍ତାହିକ ସୀମାକୁ ପରିବର୍ତ୍ତନ ନକରି ଦୈନିକ USD ସୀମାକୁ ସକ୍ଷମ କରେ;
`--max-cost 0` ଦୈନିକ ସୀମାକୁ ହଟାଏ ଏବଂ ବିଦ୍ୟମାନ ବ୍ୟବହାର-ସୀମା ଟଗଲ୍
ଓ ସାପ୍ତାହିକ ସୀମାକୁ ଅପରିବର୍ତ୍ତିତ ରଖେ। ଛାଡ଼ି ଦିଆଯାଇଥିବା ନୀତି ଫିଲ୍ଡଗୁଡ଼ିକ ଅପରିବର୍ତ୍ତିତ ରହେ। ହାର ପରିବର୍ତ୍ତନ ପ୍ରଥମେ
ବର୍ତ୍ତମାନର ନୀତିକୁ ପଢ଼େ; ସେହି ଏକ କୀର ହାର-ସୀମା ଆରେରେ ଏକାସାଙ୍ଗେ ସମ୍ପାଦନା କରିବାରୁ ବିରତ ରୁହନ୍ତୁ।

ନୀତି କମାଣ୍ଡଗୁଡ଼ିକ ପ୍ରମାଣିତ `GET`/`PATCH /api/keys/{id}` ବ୍ୟବହାର କରନ୍ତି ଏବଂ ସକ୍ରିୟ
କଣ୍ଟେକ୍ସ୍ଟ ଓ ଗ୍ଲୋବାଲ୍ `--api-key` ବିକଳ୍ପକୁ ସମ୍ମାନ କରନ୍ତି। JSON ଆଉଟ୍ପୁଟ୍ରେ କେବଳ ନୀତି ଫିଲ୍ଡଗୁଡ଼ିକ ଥାଏ,
ସଂରକ୍ଷିତ କୀ କିମ୍ବା ତାହାର ମାସ୍କ୍ କରାଯାଇଥିବା ରୂପ ବିନା। କେବଳ ଇନ୍ଫରେନ୍ସ ପାଇଁ ଥିବା କ୍ରେଡେନ୍ସିଆଲ୍
ପରିଚାଳନା ପରିବର୍ତ୍ତନକୁ ଅନୁମୋଦନ କରିପାରିବ ନାହିଁ। 401/403 ହେଲେ ପରିଚାଳନା
କ୍ରେଡେନ୍ସିଆଲ୍ ଓ କଣ୍ଟେକ୍ସ୍ଟ ଯାଞ୍ଚ କରିବା ଆବଶ୍ୟକ; ଏହା ସ୍ଥାନୀୟ CLI-ଟୋକେନ୍ କିମ୍ବା ସଲ୍ଟ ବିଫଳତାକୁ ପ୍ରମାଣିତ କରେ ନାହିଁ।
ପୃଥକ ସ୍ଥାନୀୟ ପ୍ରମାଣୀକରଣ ଚୁକ୍ତି ପାଇଁ [CLI ଟୋକେନ୍](../security/CLI_TOKEN.md) ଦେଖନ୍ତୁ।
