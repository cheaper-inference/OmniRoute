## ଏହା କାହିଁକି ଅଛି \|

ଅନେକ ଚିନ୍ତାଧାରା-ମୋଡ୍ ପ୍ରଦାନକାରୀ ଏକ ଅନୁସରଣ ଟର୍ନକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରନ୍ତି \|** ପୂର୍ବ ସହାୟକ ବାର୍ତ୍ତା ମୂଳ `reasoning_content` ଅନ୍ତର୍ଭୁକ୍ତ କରେ \|** । ଅପଷ୍ଟ୍ରିମ୍ 400 ସହିତ ବାର୍ତ୍ତା ସହିତ 400 ରିଟର୍ନ କରେ:

```
Param Incorrect: The reasoning_content in the thinking mode must be passed back to the API.
```

କିନ୍ତୁ ସାଧାରଣ ଗ୍ରାହକ (Cursor, Cline, Roo Code, OpenAI SDK) ଷ୍ଟ୍ରିପ୍ `reasoning_content` ସେମାନେ ରିପ୍ଲେ କରୁଥିବା ଇତିହାସରୁ \| OmniRoute ଏହାକୁ ଏକ ସର୍ଭର-ସାଇଡ୍ କ୍ୟାଶେରୁ ପୁନ ores ସ୍ଥାପନ କରେ ତେଣୁ ଅପଷ୍ଟ୍ରିମ୍ ଦେଖୁଥିବା ଅନୁରୋଧ ସ୍ଥିର ଅଟେ \| ଇସୁ # #1628 ହାଇବ୍ରିଡ୍ memory/SQLite ସ୍ଥିରତାକୁ ପ୍ରବର୍ତ୍ତାଇଲା ତେଣୁ କ୍ୟାଚ୍ ବଞ୍ଚିଥାଏ ପ୍ରକ୍ରିୟା ପୁନ art ଆରମ୍ଭ ହୁଏ \|

## ସ୍ଥାପତ୍ୟ

```
Turn N (assistant generates):
  → response contains reasoning_content + tool_calls
  → if requiresReasoningReplay(provider, model): cacheReasoningFromAssistantMessage()
      writes (memory + DB), one entry per tool_call.id within the request scope
  → forward response to client (which may or may not retain reasoning)

Turn N+1 (client sends follow-up):
  → translator detects: requiresReasoningReplay(provider, model) === true
  → for each assistant message with tool_calls and no reasoning_content:
      lookupReasoning(buildToolCallCacheKey(scope, toolCalls[0].id)) → memory → DB
      hit  → msg.reasoning_content = cached; recordReplay()
      miss → msg.reasoning_content = "" (legacy fallback for older DeepSeek)
  → upstream sees consistent history → no 400
```

`open-sse/handlers/chatCore.ts` ରେ କ୍ୟାପଚର ହୁଏ (ଦୁଇଟି ସାଇଟ୍, ଦୁଇଟି `cacheReasoningFromAssistantMessage` କଲ୍ ସାଇଟରେ)। ସ୍କିମା ବାଧ୍ୟତାମୂଳକ ପରେ `open-sse/translator/index.ts` ରେ ରିପ୍ଲେ ହୁଏ କିନ୍ତୁ ପଠାଇବା ପୂର୍ବରୁ।

ଟୁଲ୍-କଲ୍ ଏଣ୍ଟ୍ରିଗୁଡିକ `buildToolCallCacheKey()` ଅଧୀନରେ ଗଚ୍ଛିତ ହୋଇଛି, ଅନୁରୋଧ ପରିସରର ଏକ ହଜମ ଏବଂ ଟୁଲ୍ କଲ୍ id, ତେଣୁ ଅନ୍ୟ API କି କିମ୍ବା ଅଧିବେଶନ ଦ୍ୱାରା ବ୍ୟବହୃତ ସମାନ id ପ୍ରବେଶକୁ ଚୟନ କରେ ନାହିଁ। ପରିସର `buildReasoningCacheScope()` ରୁ ଆସିଥାଏ: API କି id, ଏବଂ ଅନୁରୋଧଟି ଥିବାବେଳେ ଅଧିବେଶନ ଚାବି। `tool_call_id` ସ୍ତମ୍ଭ ଏବଂ ଡ୍ୟାସବୋର୍ଡ ତେଣୁ ସେହି ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ପାଇଁ ଏହି ହଜମକୁ ଦର୍ଶାଏ।

ସାଧା (ଅଣ-ଟୁଲ୍-କଲ୍) ସହାୟକ ଟର୍ନଗୁଡିକ ଭିନ୍ନ ଭାବରେ ଚାବି ଦିଆଯାଏ: `buildAssistantMessageCacheKey()` ଅଧିବେଶନ ପରିସରକୁ ହଜମ କରେ ଏବଂ ସେହି ଟର୍ନ୍ ପର୍ଯ୍ୟନ୍ତ ସ୍ ized ାଭାବିକ OpenAI- ଫର୍ମାଟ୍ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ, କାରଣ DeepSeek ଉପସ୍ଥିତ ହେବା ପରେ `tools` _ ପ୍ରତ୍ୟେକ_ ପୂର୍ବ ଟର୍ନର କାରଣ ଆବଶ୍ୟକ କରେ। ରେସପନ୍ସ- API ଟାର୍ଗେଟ୍ ପାଇଁ (ଉଦାହରଣ ସ୍ୱରୂପ `opencode-go/deepseek-v4-flash`, `/responses` ରୁଟ୍) ଅପଷ୍ଟ୍ରିମ୍ ଶରୀର `input` ବହନ କରେ, `messages` ନୁହେଁ, ତେଣୁ `translateRequest()` (`open-sse/translator/index.ts`) ଏକ କଲବ୍ୟାକ୍ ଅପ୍ସନ୍ ମାଧ୍ୟମରେ ହଜମ ହୋଇଥିବା ପିଭଟ୍ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟକୁ ରିପୋର୍ଟ କରେ ଏବଂ କ୍ୟାପଚର ସାଇଟଗୁଡ଼ିକ ସେହି ସମାନ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟକୁ ହଜମ କରେ। ପ୍ରତ୍ୟେକ ଉତ୍ସ ଫର୍ମାଟ୍ ପାଇଁ OpenAI pivot ରେ ରେସପନ୍ସ ରିପ୍ଲେ ପାସ୍ ଚାଲିଥାଏ, ତେଣୁ Anthropic ମେସେଜ୍ କ୍ଲାଏଣ୍ଟ (Claude → OpenAI → Responses) ମଧ୍ୟ ପୁନ play ଚିତ୍ରିତ ହୁଏ।

## ଷ୍ଟୋରେଜ୍ — ହାଇବ୍ରିଡ୍ ମେମୋରୀ + SQLite

ହଟ୍ ପଥ କ୍ରାସ୍ ପୁନରୁଦ୍ଧାର ଏବଂ ଡ୍ୟାସବୋର୍ଡ ଦୃଶ୍ୟମାନତା ପାଇଁ SQLite ଟେବୁଲ୍ ଦ୍ୱାରା ସମର୍ଥିତ ଏକ ଇନ-ମେମୋରୀ `Map` (LRU-by-creation) ବ୍ୟବହାର କରେ।

| ସ୍ତର   | କାର୍ଯ୍ୟାନ୍ୱୟନ                                 | ଉଦ୍ଦେଶ୍ୟ                                     |
| ------ | --------------------------------------------- | -------------------------------------------- |
| ସ୍ମୃତି | `open-sse/services/reasoningCache.ts` ରେ`Map` | ଦ୍ରୁତ ସନ୍ଧାନ, 200 ରେ ପୁରାତନକୁ ବାହାର କରିଦିଏ।  |
| DB     | `reasoning_cache` ଟେବୁଲ୍ (`src/lib/db/`)      | ପୁନ rest ଆରମ୍ଭ, ଷ୍ଟାଟସ୍ ଡ୍ରାଇଭ୍ ଉପରେ ରହିଥାଏ। |

ଲେଖା ଉଭୟକୁ ଯାଏ। ପ୍ରଥମେ ମେମୋରୀ ପରାମର୍ଶ ପ Read ନ୍ତୁ, ତାପରେ DB କୁ ଫେରିଯାଅ (DB ହିଟ୍ ସ୍ମୃତିକୁ ପୁନ oted ପ୍ରୋତ୍ସାହିତ ହୁଏ)। DB ବିଫଳତା ସାଂଘାତିକ ନୁହେଁ — ଇନ-ମେମୋରୀ କ୍ୟାଶେ ଗରମ ପଥରେ ସେବା ଜାରି ରଖିଛି।

**ଡିଫଲ୍ଟ:**

- TTL: `2h` (`TTL_MS = 2 * 60 * 60 * 1000`)
- ସର୍ବାଧିକ ସ୍ମୃତି ଭରଣଗୁଡ଼ିକ: `200` (`MAX_MEMORY_ENTRIES`)
- ବହିଷ୍କାର: ସର୍ବପ୍ରଥମ `createdAt`।

## ଡାଟାବେସ୍ ସ୍କିମା \|

CREATE TABLE IF NOT EXISTS reasoning_cache (
  tool_call_id   TEXT PRIMARY KEY,
  provider       TEXT NOT NULL,
  model          TEXT NOT NULL,
  reasoning      TEXT NOT NULL,
  char_count     INTEGER NOT NULL DEFAULT 0,

## ଅପରେସନ୍ ଟିପ୍ପଣୀ \|

- **ପରିଷ୍କାର:** `cleanupReasoningCache()` ପୂର୍ଣ୍ଣ ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ ଶୁଦ୍ଧ କରେ ଏବଂ `DELETE FROM reasoning_cache WHERE expires_at <= unixepoch('now')` ଚଲାଇଥାଏ \| ସ୍ୱାସ୍ଥ୍ୟ-ଯାଞ୍ଚ କର୍ମଚାରୀମାନେ ଏହାକୁ ପର୍ଯ୍ୟାୟକ୍ରମେ ଡାକନ୍ତି \|
- **ଦୁର୍ଘଟଣା ପୁନରୁଦ୍ଧାର:** ପୁନ rest ଆରମ୍ଭ ପରେ, ମେମୋରୀ ଖାଲି ଅଛି କିନ୍ତୁ DB ଏପର୍ଯ୍ୟନ୍ତ ଅପ୍ରତ୍ୟାଶିତ ପ୍ରବିଷ୍ଟଗୁଡ଼ିକୁ ଧରିଥାଏ \| ପ୍ରଦତ୍ତ `tool_call_id` ପାଇଁ ପ୍ରଥମ ସନ୍ଧାନ ହେଉଛି DB ହିଟ୍; ପରବର୍ତ୍ତୀ ସନ୍ଧାନଗୁଡ଼ିକ ହେଉଛି ସ୍ମୃତି ହିଟ୍ \|
- **କ reason ଣସି କାରଣ ନାହିଁ, କ୍ୟାଚ୍ ନାହିଁ:** `cacheReasoningFromAssistantMessage` `0` ଫେରସ୍ତ କରେ ଯେତେବେଳେ ସହାୟକ ସନ୍ଦେଶର କ z ଣସି `reasoning_content` / `reasoning` କ୍ଷେତ୍ର ନଥାଏ, ତେଣୁ ଚିନ୍ତା ନକରି ପ୍ରତିକ୍ରିୟା କିଛି ଖର୍ଚ୍ଚ କରେ ନାହିଁ \|
- **ଲେଖିବା ମଧ୍ୟ ଗେଟ୍ ହୋଇଛି:** `chatCore.ts` ରେ ଉଭୟ କଲ୍ ସାଇଟ୍ (ଅଣ-ଷ୍ଟ୍ରିମିଂ ଏବଂ ଷ୍ଟ୍ରିମିଂ) କେବଳ `cacheReasoningFromAssistantMessage()` କଲ୍ କରେ ଯେତେବେଳେ `requiresReasoningReplay(provider, model)` `true` — ସମାନ ପ read ଼ୁଥିବା ପାର୍ଶ୍ୱ ଯାଞ୍ଚକୁ ପୂର୍ବାନୁମାନ କରେ \| ସଂସ୍ଥାଗୁଡ଼ିକ ଯାହା କ a ଣସି ରିପ୍ଲେ ପ୍ରଦାନକାରୀଙ୍କୁ ସ୍ପର୍ଶ କରେ ନାହିଁ, ପ୍ରତ୍ୟେକ ଯୁକ୍ତିଯୁକ୍ତ ପ୍ରତିକ୍ରିୟାରେ ଲେଖା, ସୂଚକାଙ୍କ ଅଦ୍ୟତନ, ଏବଂ try/catch ପାଇଁ ଦେୟ ବନ୍ଦ କରିଦିଏ \|
- **ଅଣ-କଠୋର ପ୍ରଦାନକାରୀ:** ଯେତେବେଳେ `requiresReasoningReplay` ହେଉଛି `false` ଏବଂ ଟାର୍ଗେଟ୍ ଫର୍ମାଟ୍ ହେଉଛି OpenAI, ଅନୁବାଦକ \|** ରେଖା** ବାହାରକୁ ଯାଉଥିବା ସନ୍ଦେଶଗୁଡ଼ିକରୁ ଯେକ z ଣସି `reasoning_content` କ୍ଷେତ୍ର — OpenAI ଚାଟ୍ ସମାପ୍ତି ଏହାକୁ ଗ୍ରହଣ କରେ ନାହିଁ \|

## ମ୍ୟୁଜ୍ ଅପାକ୍-ଯୁକ୍ତିଯୁକ୍ତ ମାଲିକାନା \|

ମ୍ୟୁଜ୍ (`muse-code`) କଲର୍-ବାନ୍ଧୁଥିବା ଅସ୍ପଷ୍ଟ ଯୁକ୍ତି (`encrypted_content`) ଫେରସ୍ତ କରେ \| ଏହାକୁ ଏକ ଭିନ୍ନ ଆକାଉଣ୍ଟ୍ କିମ୍ବା ରିମାଇଟେଡ୍ ପ୍ରମାଣପତ୍ର ଅଧୀନରେ ରିପ୍ଲାଏ କରିବା ଅପଷ୍ଟ୍ରିମ୍ରେ ବିଫଳ ହୁଏ, ତେଣୁ ଦେଶୀ OAuth ଅନୁରୋଧଗୁଡ଼ିକ ପ୍ରତି ଅନୁରୋଧ ଘୂର୍ଣ୍ଣନ ପରିବର୍ତ୍ତେ ଅଧିବେଶନ ସ୍ତରର ମାଲିକାନା ବ୍ୟବହାର କରନ୍ତି (`src/sse/services/museSessionOwnership.ts`, `src/sse/handlers/chat.ts` ରେ ବାଧ୍ୟତାମୂଳକ) \| ସ୍ପଷ୍ଟ ଭାବରେ ମନୋନୀତ API- କି ସଂଯୋଗ ଏବଂ API- କି-କେବଳ ସଂରଚନାଗୁଡ଼ିକ ଏହି ମାଲିକାନା ମୋଡ୍ ବିନା ସେମାନଙ୍କର ବିଦ୍ୟମାନ ମାର୍ଗକୁ ବଜାୟ ରଖନ୍ତି \|

- ପ୍ରତ୍ୟେକ ପର୍ଯ୍ୟାୟରେ ଏକ ସ୍ଥିର ଅଧିବେଶନ ID ଯୋଗାନ୍ତୁ: `x-omniroute-session-id`, `x-omniroute-session`, `x-session-id`, କିମ୍ବା `x-codex-session-id`; ବ ly କଳ୍ପିକ ଭାବରେ ଶରୀରରେ `prompt_cache_key`, `session_id`, `conversation_id`, କିମ୍ବା `metadata.session_id` ବ୍ୟବହାର କରନ୍ତୁ (ସେହି ପ୍ରାଧାନ୍ୟ କ୍ରମରେ) \| ଦୁଇଟି କିମ୍ବା ଅଧିକ ଦେଶୀ OAuth ଖାତା ସକ୍ରିୟ ଥିବାବେଳେ ନିଖୋଜ କିମ୍ବା ଖାଲି IDs 400 ଫେରସ୍ତ; ଗୋଟିଏ OAuth ଆକାଉଣ୍ଟ୍ ସହିତ ଘୂର୍ଣ୍ଣନ କରିବାକୁ କିଛି ନାହିଁ, ତେଣୁ ଏହିପରି ଏକ ଅନୁରୋଧ ଅନ୍-ପେନ୍ ରାଉଟିଙ୍ଗ୍ ରଖେ \| ପରିସର କଲ୍ ର OmniRoute API-key ID ଅନ୍ତର୍ଭୁକ୍ତ କରେ \|
- ସକ୍ରିୟ ଦେଶୀ OAuth ଆକାଉଣ୍ଟଗୁଡିକ ମଧ୍ୟରେ ସତେଜ ସ୍ independent ାଧୀନ ଅଧିବେଶନଗୁଡିକ ରାଉଣ୍ଡ-ରୋବିନ୍, API- କି ସଂଯୋଗ ନୀତି ଦ୍ୱାରା ଅନୁମତିପ୍ରାପ୍ତ, ID ଦ୍ୱାରା ନିର୍ଦ୍ଦେଶିତ \| ଟର୍ମିନାଲ୍ ସ୍ଥିତି (`banned`, `expired`, `credits_exhausted`) ସହିତ, କିମ୍ବା ଅନୁରୋଧ କରାଯାଇଥିବା ମଡେଲ୍ ପାଇଁ ମଡେଲ୍-ଲକ୍ ସହିତ ରାଉଣ୍ଡ-ରୋବିନ୍ ସଂଯୋଗ କୁଲଡାଉନ୍ ରେ ଖାତା ଛାଡିଦିଏ \| ମ୍ୟୁଜ୍ ଅପଷ୍ଟ୍ରିମ୍ ବିଫଳତା ଅନ୍ୟ ପ୍ରଦାନକାରୀଙ୍କ ପରି କୁଲଡାଉନ୍ ଏବଂ ବ୍ରେକର୍ ଷ୍ଟେଟ୍ ରେକର୍ଡ କରେ \| ଏକ ନୂତନ ଅଧିବେଶନ ପାଇଁ ଏକ ସ୍ପଷ୍ଟ ଭାବରେ ବାଧ୍ୟତାମୂଳକ ସଂଯୋଗ ରାଉଣ୍ଡ-ରୋବିନକୁ ଅତିକ୍ରମ କରେ କିନ୍ତୁ ଏକ ବିଦ୍ୟମାନ ମାଲିକକୁ ନବଲିଖନ କରିପାରିବ ନାହିଁ \|
- ଯେପର୍ଯ୍ୟନ୍ତ ମାଲିକ ଏକ ସଫଳ ପ୍ରତିକ୍ରିୟା ପ୍ରଦାନ ନକରନ୍ତି, ଏକ ଅଧିବେଶନ ଯାହାର ମାଲିକ ଉପଲବ୍ଧ ହୋଇନାହାଁନ୍ତି ଏକ ସୁସ୍ଥ ଆକାଉଣ୍ଟରେ ପୁନ claimed ଦାବି କରାଯାଏ \| ପ୍ରଥମ ସଫଳ ପ୍ରତିକ୍ରିୟା ପରେ, ଅଧିବେଶନ ସେହି ମାଲିକଙ୍କ ନିକଟରେ 30 ଦିନ ପର୍ଯ୍ୟନ୍ତ (`MUSE_SESSION_IDLE_TTL_MS`) ନିଷ୍କ୍ରିୟ ନହେବା ପର୍ଯ୍ୟନ୍ତ ରହିଥାଏ \|
- ପ୍ରତ୍ୟେକ ଜାରି ଏବଂ ଉପକରଣ-ଫଳାଫଳ ଟର୍ନ ଅଧିବେଶନ ମାଲିକଙ୍କ ନିକଟରେ ରହିଥାଏ: ସଂଯୋଗ, ଆକାଉଣ୍ଟ୍ ପରିଚୟ, ଏବଂ ଇନ୍ଫେରେନ୍ସ-କ୍ରେଡେନସିଆଲ୍ ପି generation ଼ି, ଅପଷ୍ଟ୍ରିମ୍ ଚେଷ୍ଟା ପୂର୍ବରୁ ପୁନର୍ବାର ଯାଞ୍ଚ କରାଯାଇଥାଏ, ପ୍ରମାଣପତ୍ର-ସତେଜ ପୁନ ries ଚେଷ୍ଟା ସହିତ \| ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ କଲ୍ IDs/item ରେଫରେନ୍ସ ଏବଂ ଚାଟ୍ ସମାପ୍ତି ଟୁଲ୍-କଲ୍ IDs ନିଶ୍ଚିତ ଭାବରେ ସେହି ଅଧିବେଶନ ଏବଂ ପି generation ଼ି ପାଇଁ ରେକର୍ଡ ହୋଇଥିବ \|
