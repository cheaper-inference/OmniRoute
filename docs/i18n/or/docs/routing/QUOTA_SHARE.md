## ସାରାଂଶ

କୋଟା ସହଭାଗୀକରଣ ଇଞ୍ଜିନ୍ ସମାନ ସଂଯୋଗ ସହଭାଗ କରୁଥିବା ଏକାଧିକ API କୀ ମଧ୍ୟରେ ପ୍ରଦାତାଙ୍କ ସମୟ-ଆଧାରିତ କୋଟାକୁ (ଯଥା Codex
5-ଘଣ୍ଟିଆ ୱିଣ୍ଡୋ, Kimi 1500 ଅନୁରୋଧ/ଘଣ୍ଟା) ନ୍ୟାୟସଙ୍ଗତ ଭାବରେ ବଣ୍ଟନ କରେ।

**ଏହା ସମାଧାନ କରୁଥିବା ସମସ୍ୟା:** OmniRoute ସମାନ ଅପ୍ଷ୍ଟ୍ରିମ୍
ପ୍ରଦାତା ଆକାଉଣ୍ଟ ବିପରୀତରେ ଅନେକ API କୀକୁ ପ୍ରକ୍ସି କରେ। ସହଭାଗୀକରଣ ଲଜିକ୍ ବିନା, କୀ A-ରୁ ହଠାତ୍ ଅଧିକ ଅନୁରୋଧ ସେହି
ଘଣ୍ଟା ପାଇଁ ପ୍ରଦାତା କୋଟାକୁ ସମ୍ପୂର୍ଣ୍ଣ ଶେଷ କରିପାରେ, ଫଳରେ ୱିଣ୍ଡୋ ରିସେଟ୍ ହେବା ପର୍ଯ୍ୟନ୍ତ କୀ B ଏବଂ C ଅବରୋଧିତ ରହିବ।
ଇଞ୍ଜିନ୍ ନିମ୍ନ ପ୍ରକାରେ ଏହାକୁ ପ୍ରତିରୋଧ କରେ:

1. ପ୍ରତ୍ୟେକ ଡାଇମେନ୍ସନ୍ (%, ଅନୁରୋଧ, ଟୋକନ୍, $) ପାଇଁ ପ୍ରତ୍ୟେକ କୀର ରୋଲିଂ ବ୍ୟବହାର ଟ୍ରାକ୍ କରିବା।
2. ଏକ କାର୍ଯ୍ୟ-ସଂରକ୍ଷକ ନ୍ୟାୟସଙ୍ଗତ-ହିସ୍ସା ଆଲଗୋରିଦମ୍ ପ୍ରୟୋଗ କରିବା: ଗ୍ଲୋବାଲ୍ ପୁଲ୍ ସାଚୁରେଟ୍ ହୋଇନଥିବାବେଳେ ଗୋଟିଏ କୀ ନିଷ୍କ୍ରିୟ
   ହିସ୍ସାରୁ ଧାର ନେଇପାରିବ।
3. ଅନୁରୋଧଟି ଅପ୍ଷ୍ଟ୍ରିମ୍ ଏକ୍ସିକ୍ୟୁଟର୍ ପାଖରେ ପହଞ୍ଚିବା ପୂର୍ବରୁ ହଟ୍ ପାଥ୍ (`chatCore.ts`) ମଧ୍ୟରେ ଫଳାଫଳକୁ
   ଲାଗୁ କରିବା।

## ଆଲଗୋରିଦମ: ମେଳା-ଅଂଶୀଦାର କାର୍ଯ୍ୟ-ସଂରକ୍ଷଣ।

`src/lib/quota/fairShare.ts` ରେ କାର୍ଯ୍ୟକାରୀ

### ମୋଡ୍

| ଅବସ୍ଥା                                     | ମୋଡ୍      | ଆଚରଣ                                                                 |
| ------------------------------------------ | --------- | -------------------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **ଉଦାର**  | ଚାବି ସର୍ବଭାରତୀୟ ସୀମା ମାଇନସ୍ ଖର୍ଚ୍ଚ-ସମୁଦାୟ ପର୍ଯ୍ୟନ୍ତ orrow ଣ କରିପାରେ। |
| `globalUsedPercent >= saturationThreshold` | **କଠୋର।** | ବ୍ୟକ୍ତିଗତ ନ୍ୟାୟ ଅଂଶକୁ କଠୋର ଭାବରେ କାର୍ଯ୍ୟକାରୀ କରନ୍ତୁ।                 |

ଡିଫଲ୍ଟ `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`)।

ଏହି ଦୁଇଟି ମୋଡ୍ ଡିଫଲ୍ଟ orrow ଣ ମୋଡ୍, `saturation` ରେ ଏକ ପୁଲ୍ ବର୍ଣ୍ଣନା କରେ। `consent` ମୋଡ୍ ରେ ଥିବା ଏକ ପୁଲ୍ ସର୍ବଦା କଠୋର ନିୟମ ପ୍ରୟୋଗ କରେ, ଯାହା ବି ପରିପୂର୍ଣ୍ଣତା। [ସମ୍ମତି ଦିଆଯାଇଥିବା ending ଣ ଦେଖନ୍ତୁ (ପ୍ରତି ପୁଲ୍ ଅପ୍ଟ-ଇନ୍)](#consented-lending-per-pool-opt-in)।

### ପରିମାପ ନିଷ୍ପତ୍ତି।

ପୁଲରେ ଥିବା ପ୍ରତ୍ୟେକ ସକ୍ରିୟ ଆକାର ପାଇଁ, ଇଞ୍ଜିନ୍ ଗଣନା କରେ:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = current rolling value for this key (from QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

`percent` ପରିମାପ ପାଇଁ, `consumed` ଏହା ପରିବର୍ତ୍ତେ ଗୁଣବତ୍ତା ପୁସ୍ତକରୁ ଆସିଥାଏ ( [ଶତ ପ୍ରତିଶତ ପରିମାପ: ପ୍ରତି-କି ଗୁଣଧର୍ମ](#percent-dimensions-per-key-attribution) )।

ତା’ପରେ:

- **`policy = hard`** : ଯଦି `consumed > fairShareAllowed` ଏବଂ ମୋଡ୍ କଠୋର → ଅଟେ।** ବ୍ଲକ** ।
- **`policy = soft`** : ଯଦି `consumed > fairShareAllowed` ଏବଂ ମୋଡ୍ କଠୋର → ଅଟେ।** ଦଣ୍ଡ ଦିଅ।** (କମ୍ବୋରେ ବଞ୍ଚିତ କରନ୍ତୁ; କଦାପି ହାର୍ଡ-ବ୍ଲକ୍ କରନ୍ତୁ ନାହିଁ)।
- **`policy = burst`** : ଗ୍ଲୋବାଲ୍ ହେଡରୁମ୍ ବିଦ୍ୟମାନ ଥିବାବେଳେ ନିର୍ବିଶେଷରେ ଅନୁମତି ଦିଅନ୍ତୁ।

### କ୍ୟାପ୍ ସଂପୂର୍ଣ୍ଣ।

`capValue` + `capUnit` ଏକ ଆବଣ୍ଟନରେ ମୋଡ୍ କିମ୍ବା ପଲିସି ଠାରୁ ନିରପେକ୍ଷ ଏକ କଠିନ ଛାତ। ଯେକ Any ଣସି ପରିମାଣ ଯେଉଁଠାରେ `consumed >= capValue` ସର୍ବଦା।** ବ୍ଲକଗୁଡିକ** ଅନୁରୋଧ ଏକ `percent` କ୍ୟାପ୍ ପାଇଁ, `consumed` କେବଳ ଚାବି ପାଇଁ ଦାୟୀ ଅଂଶ।

### ମଲ୍ଟି-ଡାଇମେନ୍ସନ୍ ଯାଞ୍ଚ।

ଯଦି ଏକ ଅନୁରୋଧ ଅବରୋଧିତ ହୋଇଛି।** ଯେକ any ଣସି** ପୁଷ୍କରିଣୀର ପରିମାଣ ଏହାକୁ ଅବରୋଧ କରିବ। ପରିମାପ ସ୍ independent ାଧୀନ — ଏକ 5h% କ୍ଲାନ୍ତ ସାପ୍ତାହିକ% ଆକାରକୁ ପ୍ରଭାବିତ କରେ ନାହିଁ।

### Orr ଣ

ଉଦାର ମୋଡ୍ ରେ, ଏକ ଚାବି ଯାହାର ଆବଣ୍ଟନ କମ୍ ଖର୍ଚ୍ଚ ହୁଏ, ଅନ୍ୟ ଚାବିର ଅବଣ୍ଟିତ ଅଂଶରୁ ସରପ୍ଲସ୍ ବ୍ୟବହାର କରିପାରିବ। ସୂତ୍ର ହେଉଛି:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

ଯେଉଁଠାରେ `consumedByOtherKeys = consumedTotal - consumedByThisKey` ଟେଟୋ ଗ୍ଲୋବାଲ୍ (ସେହି ପରିମାଣ ପାଇଁ ପୁଲ୍ `limit` ) ସର୍ବଦା କଠିନ ଛାତ।

### ସହମତ ending ଣ (ପ୍ରତି ପୁଲ୍ ଅପ୍ଟ-ଇନ୍)

ପ୍ରତ୍ୟେକ ପୁଲରେ ଏକ orrow ଣ ମୋଡ୍ ଅଛି। `saturation` ହେଉଛି ଡିଫଲ୍ଟ ଏବଂ ଉପରୋକ୍ତ ନିୟମଗୁଡିକ ରଖେ। `consent` ମୋଡ୍ ରେ ଏକ `hard` କି ଏହାର ଅଂଶକୁ କେବଳ କ୍ଷମତା ମଧ୍ୟରେ ପାସ୍ କରେ ଯାହା ଅନ୍ୟ କିଗୁଡ଼ିକ end ଣ ଦେବାକୁ ରାଜି ହୋଇଥିଲା। ବ୍ୟବସ୍ଥାପକ ପ୍ରତ୍ୟେକ ପୁଲ୍ର ମୋଡ୍ ସେଟ୍ କରନ୍ତି। ପ୍ରତ୍ୟେକ କି ଧାରକ [ending ଣ ପ୍ରଦାନ ସମ୍ମତି](#lending-consent) ମାଧ୍ୟମରେ ନିଜର ସମ୍ମତି ସେଟ୍ କରନ୍ତି।

ଏକ ସମ୍ମତି ହେଉଛି 0 ରୁ 100 ପ୍ରତିଶତ ଏବଂ ଯୁଗ ମିଲିସେକେଣ୍ଡରେ ଏକ ଇଚ୍ଛାଧୀନ ସମୟସୀମା। ଭବିଷ୍ୟତରେ ସମୟସୀମା ଥିବାବେଳେ ଚାବି ଏହାର ନିଷ୍କ୍ରିୟ ଅଂଶର ଶତକଡ଼ା ends ଣ ଦେଇଥାଏ।

ଗୋଟିଏ ପରିମାପ ପାଇଁ, `L` ହେଉଛି ପ୍ରଭାବଶାଳୀ ସୀମା: ଯୋଜନା ପୁଲରେ ଥିବା ଆକାଉଣ୍ଟଗୁଡିକର ସମୟ ସୀମା। ଅନୁରୋଧକାରୀ ଚାବି ପାଇଁ ଗେଟ୍ ଗଣନା କରେ:

```
share_k         = w_k / 100 × L
idle_k          = max(0, share_k − consumed_k)
lent            = Σ over the other keys of lend_k / 100 × idle_k
taken           = Σ over the other keys of max(0, consumed_k − share_k)
borrowAvailable = max(0, lent − taken)
```

`w_k` ହେଉଛି ଚାବିର ଓଜନ, କିମ୍ବା ପ୍ରତ୍ୟେକ ଚାବି ପାଇଁ `100 / n` ଯେତେବେଳେ କ weight ଣସି ଓଜନ 0 ରୁ ଅଧିକ ନଥାଏ। `lend_k` ହେଉଛି ଚାବିର ସକ୍ରିୟ ଶତକଡା, ଏବଂ ଏହାର ସମୟସୀମା ଅତିକ୍ରମ କରିସାରିବା ପରେ 0। ଅନୁରୋଧ କରୁଥିବା ଚାବିର ନିଜସ୍ୱ ସମ୍ମତି କଦାପି ଗଣନା କରେ ନାହିଁ। ଏହାର ବ୍ୟବହାର ଏହାର ଅଂଶ ଏବଂ `borrowAvailable` ପହଞ୍ଚିବା ପରେ ଏକ `hard` ଚାବିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ।

କ୍ଷମତା ଯାହା କ alloc ଣସି ଆବଣ୍ଟନ ଦାବି (100 ମାଇନସ୍ ଓଜନର ରାଶି) lend ଣଯୋଗ୍ୟ ନୁହେଁ। କ key ଣସି ଚାବି ଏହାକୁ end ଣ ଦେବାକୁ ରାଜି ହେଲା ନାହିଁ।

**`soft` ଏବଂ `burst`** End ଣ ଦେବା ସେମାନଙ୍କୁ ସୀମିତ କରେ ନାହିଁ। ଏକ `soft` ଚାବି ଏହାର ଅଂଶକୁ ଅତିକ୍ରମ କରି ଥରେ ବଞ୍ଚିତ ହୋଇଛି। ପୁଲରେ କୋଠରୀ ଥିବାବେଳେ ଏକ `burst` ଚାବି ପାସ୍ କରେ। ପୁଲ୍ର ସମୁଦାୟ ଏହାର ସୀମାରେ ପହଞ୍ଚିବା ପରେ ପୁଲ୍ ଛାତ ପ୍ରତ୍ୟେକ ଚାବିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ।

**ଅନୁରୋଧ ପଥରେ ମୂଲ୍ୟ** ଏକ `saturation` ପୁଲ୍ ପୂର୍ବ ଅପେକ୍ଷା ଆଉ କିଛି ପ read େ ନାହିଁ। ଏକ `consent` ପୁଲରେ, ଏକ ଗଣନା ଯୋଗ୍ୟ ଡାଇମେନ୍ସନ୍ ଅନ୍ୟ କିଗୁଡ଼ିକୁ କେବଳ `hard` କି ପାଇଁ ଏହାର ଅଂଶରେ କିମ୍ବା ତା’ଠାରୁ ଅଧିକ ପ read ଼ୁଥିବାବେଳେ ଅନ୍ୟ ଏକ ଚାବି ends ଣ ଦେଇଥାଏ। ଏହା ପରେ ସମାନ୍ତରାଳ ଭାବରେ ଅନ୍ୟ ଚାବି ପ୍ରତି ଗୋଟିଏ ପ read ଼ାଏ। ଏକ ବିଫଳ ପ read ା ସେହି ଚାବି ପାଇଁ 0 ର ବ୍ୟବହାର ଭାବରେ ଗଣନା କରେ। ଏକ `percent` ଡାଇମେନ୍ସନ୍ କ read ଣସି ପ read ଼ା ଯୋଗ କରେ ନାହିଁ, କାରଣ ଆଟ୍ରିବ୍ୟୁସନ୍ ବୁକ୍ ପ୍ରତ୍ୟେକ ଚାବି ଧାରଣ କରେ।

**ଏକ ପୁଲ୍ ଏଡିଟ୍ କରିବା।** ଏକ ସଂପାଦନ ଚାବିଗୁଡ଼ିକର ସମ୍ମତି ରଖେ। ଏହା ଆବଣ୍ଟନ ଏଡିଟ୍, ଗ୍ରୁପ୍-ୱାଇଡ୍ ରିପ୍ଲେସମେଣ୍ଟ ଏବଂ `ensure` କଲ୍ ପାଇଁ ଧାରଣ କରେ। ଏକ ଅପସାରିତ ଚାବି ଏହାର ସମ୍ମତି ହରାଇଥାଏ, ଏବଂ ଏକ ଚାବି ଯୋଗ ହୋଇଥିବା 0 ରୁ ଆରମ୍ଭ ହୁଏ। ଆଡମିନି ରୁଟ୍ ପ୍ରତ୍ୟେକ ଚାବିର ସମ୍ମତି ଫେରାଇଥାଏ ଏବଂ ଏହାକୁ କେବେବି ଲେଖେ ନାହିଁ। ଏକ ପୁଲକୁ `saturation` କୁ ବଦଳାଇବା ପ୍ରତ୍ୟେକ ଗଚ୍ଛିତ ସମ୍ମତି ରଖେ, ଯାହାର ସେହି ଧାରାରେ କ effect ଣସି ପ୍ରଭାବ ପଡ଼େ ନାହିଁ। ପୁଲ୍ କୁ `consent` କୁ ସୁଇଚ୍ କରିବା ଦ୍ୱାରା ସଂରକ୍ଷିତ ସମ୍ମତି ପୁନ re ସକ୍ରିୟ ହୁଏ ଯାହାର ସମୟସୀମା ଅତିକ୍ରମ କରିନାହିଁ। ଏକ କି ଧାରକ ଉଭୟ ମୋଡରେ ସଂରକ୍ଷିତ ସମ୍ମତି ସଫା କରିପାରିବ।

**ନବୀକରଣ** ଯଦି `lending_percent` ଏବଂ `lending_until` ସ୍ତମ୍ଭଗୁଡିକ ପୂର୍ବରୁ ବିଦ୍ୟମାନ ଅଛି, ସ୍ଥାନାନ୍ତରଣ କେବଳ `borrow_mode` ଯୋଗ କରିଥାଏ, ଏବଂ ସଂରକ୍ଷିତ ଶତକଡ଼ା ସେପରି ରହିଥାଏ। ପ୍ରତ୍ୟେକ ପୁଲ୍ `saturation` ମୋଡ୍ ରେ ଆରମ୍ଭ ହୁଏ। ପୁଲ୍ ୱିଜାର୍ଡରେ ପ୍ରତି ପୁଲ୍ ଉପରେ `consent` ଟର୍ନ୍ କରନ୍ତୁ। ଗଚ୍ଛିତ ମୂଲ୍ୟଗୁଡ଼ିକରୁ କିଛି ଅନୁମାନ କରାଯାଏ ନାହିଁ।

## ସ୍ଲାଇଡିଂ ୱିଣ୍ଡୋ କାଉଣ୍ଟର୍

`src/lib/quota/sqliteQuotaStore.ts` ଏବଂ `redisQuotaStore.ts` ମଧ୍ୟରେ କାର୍ଯ୍ୟକାରୀ କରାଯାଇଛି।

ପ୍ରତ୍ୟେକ `(apiKeyId, dimensionKey)` ପାଇଁ ଦୁଇଟି ବକେଟ୍:

- `curr`: ବର୍ତ୍ତମାନର ବକେଟ୍ (`floor(nowMs / windowMs)`)
- `prev`: ପୂର୍ବବର୍ତ୍ତୀ ବକେଟ୍ (`curr - 1`)

ପ୍ରଭାବଶାଳୀ ରୋଲିଂ ମୂଲ୍ୟ:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**ସଠିକତା**: ~99% ସଠିକ୍। ବକେଟ୍ଗୁଡ଼ିକ ମଧ୍ୟର ସୀମାରେ ତ୍ରୁଟି ସର୍ବାଧିକ ୱିଣ୍ଡୋ ଆକାରର 1% ଅଟେ
(2-ବକେଟ୍ ଆନୁମାନିକତାର ଅନ୍ତର୍ନିହିତ ସୀମା)।

### ସମକାଳୀନତା

SQLite ଡ୍ରାଇଭର୍: ପ୍ରତ୍ୟେକ `(apiKeyId | dimensionKey)` କୀ ପାଇଁ ଇନ୍-ମେମୋରି ମ୍ୟୁଟେକ୍ସ
ରିଡ୍-ମଡିଫାଇ-ରାଇଟ୍ ରେସ୍କୁ ପ୍ରତିରୋଧ କରେ। ପ୍ୟାଟର୍ନଟି `src/sse/services/auth.ts`-ର ଆଣ୍ଟି-ଥଣ୍ଡରିଂ-ହର୍ଡ ପ୍ୟାଟର୍ନକୁ ଅନୁସରଣ କରେ।

Redis ଡ୍ରାଇଭର୍: ଆଟମିକ୍ ଇନ୍କ୍ରିମେଣ୍ଟ ପାଇଁ Lua EVAL ସ୍କ୍ରିପ୍ଟ — ଏହା ଗୋଟିଏ Redis କମାଣ୍ଡ୍ ଭାବରେ ଚାଲେ।

ତିନୋଟି ଜିନିଷ ଧରିବାବେଳେ ୱିଣ୍ଡୋ ସମାନ ଖୋଲା ପରି ଗଣନା କରେ। ଉଭୟ ପୁନ et ସେଟ୍ ସମୟ ଜଣାଶୁଣା। ସେମାନେ ପରସ୍ପରର 30 ମିନିଟ୍ ମଧ୍ୟରେ ଅଛନ୍ତି। ଗଚ୍ଛିତ ଗୋଟିଏ ପ reading ଼ିବା ଆଗରେ ଅଛି। ସେହି ୱିଣ୍ଡୋ ଭିତରେ ଏକ ନିମ୍ନ ଚିତ୍ର କିଛି ପରିବର୍ତ୍ତନ କରେ ନାହିଁ।

ଏକ ପୁନ res ସେଟ୍ ସମୟ କେବଳ ଗଚ୍ଛିତ ହୁଏ ଯେତେବେଳେ ଏହା ପ reading ଼ିବାର ତଥ୍ୟ ସମୟଠାରୁ ଆଗରେ ଥାଏ। ଏକ ଉଚ୍ଚ ଚିତ୍ର ଏହାର ପ reading ଼ିବାର ପୁନ et ସେଟ୍ ସମୟ ଗଚ୍ଛିତ କରେ ଯେତେବେଳେ ସେହିଟି ବ୍ୟବହାରଯୋଗ୍ୟ, ଏବଂ ସଂରକ୍ଷିତକୁ ଅନ୍ୟଥା ରଖେ। ଏକ ସମାନ ଚିତ୍ର ଏହାର ପ reading ଼ିବାର ପୁନ et ସେଟ୍ ସମୟକୁ ରେକର୍ଡ କରେ ଯେତେବେଳେ ବହିଟି ନଥାଏ। ଏହା ଅନ୍ୟ କିଛି ପରିବର୍ତ୍ତନ କରେ ନାହିଁ। ଏକ ନିମ୍ନ ଚିତ୍ର ଯାହା ବୁକ୍ ଟର୍ନ କରେ ନାହିଁ କ res ଣସି ପୁନ et ସେଟ୍ ସମୟ ରେକର୍ଡ କରେ।

#### ଯେତେବେଳେ ବହି ବ୍ୟବହାର କରାଯାଏ।

ଏକ ପ reading ଼ିବା ପରେ, ବହିଟି ବ୍ୟବହୃତ ହୁଏ ଯଦି ଏହାର ସଂରକ୍ଷିତ ପୁନ et ସେଟ୍ ସମୟ ସାମ୍ପ୍ରତିକ ସମୟ ପରେ ନଥାଏ। ସେହି ପରିସ୍ଥିତି ଉପୁଜେ ଯେତେବେଳେ ପୁନ et ସେଟ୍ ପୂର୍ବରୁ ନିଆଯାଇଥିବା ଏକ ପଠନ, ଯେପରିକି କ୍ୟାଚ୍ ରୁ ପରିବେଷଣ କରାଯାଏ, ଏହାର ଠିକ୍ ପରେ ପାଳନ କରାଯାଏ।

ଏକ ବ୍ୟବହାରଯୋଗ୍ୟ ପଠନ ବିନା, ଗଚ୍ଛିତ ପୁସ୍ତକ କେବଳ ବ୍ୟବହୃତ ହୁଏ ଯେତେବେଳେ ଏହା ବର୍ତ୍ତମାନର ୱିଣ୍ଡୋର ବୁକ୍ ହୋଇପାରେ। ତାହା ଦୁଇଟି କ୍ଷେତ୍ରରେ ଧାରଣ କରେ:

- ଏହାର ପୁନ et ସେଟ୍ ସମୟ ଜଣାଶୁଣା ଏବଂ ଆଗକୁ ଅଛି।
- ଏହାର କ res ଣସି ପୁନ et ସେଟ୍ ସମୟ ନାହିଁ, ଏବଂ ଶେଷ ପ reading ା ଯାହା ଏହାକୁ ବଦଳାଇଲା ତାହା ପ୍ରାୟ 15 ମିନିଟ୍ ପୁରୁଣା।

ନଚେତ୍ କିଛି ବହି ଦିଆଯାଇନଥାଏ, ଯେପରି କ book ଣସି ବହି ନାହିଁ। ଏକ ବହି ଯାହାର ଗଚ୍ଛିତ ପୁନ res ସେଟ୍ ସମୟ ଅତିକ୍ରମ କରିସାରିଛି।

#### ନିୟମ

ଏକ ଶତକଡା ଏକ ଚାବିର ବ୍ୟବହାର ହେଉଛି ଏହାର ଗୁଣବତ୍ତା ଅଂଶ ଏବଂ ବାହ୍ୟ ଅଂଶର ଏକ ଅଂଶ। ବାହ୍ୟ ଅଂଶ ପ୍ରଥମେ କ୍ଷମତା ବ୍ୟବହାର କରେ କ no ଣସି ଆବଣ୍ଟନ ଦାବି (ଓଜନର ରାଶି 100 ମାଇନସ୍)। କେବଳ ଓଜନ ଓଜନ ଦ୍ୱାରା ଚାବିଗୁଡ଼ିକ ମଧ୍ୟରେ ଅଂଶୀଦାର ହୁଏ।

ସେହି ବ୍ୟବହାରକୁ ଅନ୍ୟ କ dim ଣସି ପରିମାପ ପରି ଚାବିର ଯଥାର୍ଥ ଅଂଶ ସହିତ ତୁଳନା କରାଯାଏ। କଠିନ ମୋଡ୍ ଏପର୍ଯ୍ୟନ୍ତ ଆରମ୍ଭ ହୁଏ ଯେତେବେଳେ ସାଚୁଚରେସନ୍ ସିଗ୍ନାଲ୍ `QUOTA_SATURATION_THRESHOLD` (ଡିଫଲ୍ଟ 0.5। 0.5) ରେ ପହଞ୍ଚେ। ପ୍ରତ୍ୟେକ ସଂଖ୍ୟା ପ୍ରଭାବଶାଳୀ ସୀମା ଦ୍ sc ାରା ମାପ କରାଯାଇଥାଏ: ପ୍ରତି ଖାତା ସୀମା ପୁଲରେ ଖାତା ସଂଖ୍ୟାଠାରୁ ଅଧିକ।

`capUnit: "percent"` ସହିତ ଏକ ସଂପୂର୍ଣ୍ଣ କ୍ୟାପ୍ କେବଳ ଚାବି ପାଇଁ ଦିଆଯାଇଥିବା ଅଂଶକୁ ଗଣନା କରେ, ସମାନ ଭାବରେ ମାପକାଠି। 100 ଏବଂ k ଖାତାର ପ୍ରତି ଆକାଉଣ୍ଟ ସୀମା ନିଅ। N ର ଏକ କ୍ୟାପ୍ ସେତେବେଳେ ପହଞ୍ଚେ ଯେତେବେଳେ ସର୍ଭିସିଂ ଆକାଉଣ୍ଟର ଚିତ୍ରର ଅଂଶର ଅଂଶ N/k ପଏଣ୍ଟରେ ପହଞ୍ଚେ। ପ୍ରତ୍ୟେକ ଖାତା ନିଜସ୍ୱ ପୁସ୍ତକ ବିରୁଦ୍ଧରେ ଯାଞ୍ଚ କରାଯାଏ। ଉଦାହରଣ ସ୍ୱରୂପ, ଦୁଇଟି ଆକାଉଣ୍ଟ୍ ସହିତ, 10 ର ଏକ କ୍ୟାପ୍ ଗୋଟିଏ ଖାତାର ଚିତ୍ରର 5 ପଏଣ୍ଟରେ ପହଞ୍ଚିଥାଏ।

ଯେତେବେଳେ ଷ୍ଟୋର ପ read ିହେବ ନାହିଁ, କ nothing ଣସି ଜିନିଷକୁ ଦାୟୀ କରାଯାଇ ନାହିଁ ଏବଂ ପ୍ରତ୍ୟେକ ଚାବି ସେହି ଆକାରରେ 0 ଚାର୍ଜ କରାଯାଏ। ଯେତେବେଳେ ଏକ ବହି ଲେଖିବା ବିଫଳ ହୁଏ, ସେହି ଗୁଣଟି ପୁସ୍ତକକୁ ପ as ଼ିବା ପରି ବ୍ୟବହାର କରେ। ଏକ ବିଫଳ ଟୋକନ୍ ଲେଖିବା ପତ୍ର ଯାହା ଅନୁରୋଧର ଟୋକେନ୍ଗୁଡ଼ିକୁ ବହିରୁ ବାହାର କରିଦିଏ। ଏହି ବିଫଳତା ମଧ୍ୟରୁ କ a ଣସି ଏକ ଅନୁରୋଧକୁ ଅବରୋଧ କରେ ନାହିଁ।

ଏକ `consent` ପୁଲରେ, ending ଣ ସୂତ୍ର ଉପରୋକ୍ତ ବର୍ଣ୍ଣନା ଅନୁଯାୟୀ ଶତକଡ଼ା ଆକାରରେ ପ୍ରତ୍ୟେକ ଚାବିର ବ୍ୟବହାରକୁ ବ୍ୟବହାର କରିଥାଏ। ଯେତେବେଳେ ଅନ୍ୟ ଏକ ଚାବି ends ଣ ଦିଏ, ବହିଟି ଥରେ ପ read ଼ାଯାଏ ଏବଂ ପ୍ରତ୍ୟେକ ଚାବି ପାଇଁ ଦାୟୀ। ଏକ ବ୍ୟବହାର ଯୋଗ୍ୟ ପୁସ୍ତକ ବିନା ପ୍ରତ୍ୟେକ ଚାବି 0 ଚାର୍ଜ କରାଯାଏ। ଓଜନ ବିଶିଷ୍ଟ ଏକ ଚାବି ତାପରେ ପାସ୍ ହୁଏ, ଏବଂ ଓଜନ 0 ସହିତ ଏକ ଚାବି କେବଳ ଯେତେବେଳେ ଅନ୍ୟ ଏକ ଚାବି ends ଣ ଦିଏ।

#### ବ୍ୟବହାର ମାର୍ଗ

`GET /api/quota/pools/{id}/usage` ସମାନ ଫଙ୍କସନ୍ ମାଧ୍ୟମରେ ସମାନ ସଂଖ୍ୟା ରିପୋର୍ଟ କରେ। `accounts` ରେ ପୁଲ୍ ସଂଯୋଗ ପାଇଁ ଏକ ଶତକଡା ଡାଇମେନ୍ସନ୍ ଅଛି। ଏହାର ଶୀର୍ଷ ସ୍ତରୀୟ `consumedTotal` ଏବଂ `perKey` ପ୍ରଥମ ପ୍ରବେଶକୁ ଦର୍ପଣ କରେ।

ମାର୍ଗଟି ବର୍ତ୍ତମାନର ପଠନକୁ ମଧ୍ୟ ପ୍ରୟୋଗ କରେ, ତେଣୁ ଏହା ଏକ ଅନୁରୋଧ ପରି ପୁସ୍ତକକୁ ଆଗକୁ ବ .ାଇପାରେ। ଯେତେବେଳେ କ us ଣସି ବ୍ୟବହାରଯୋଗ୍ୟ ପ reading ଼ା ନଥାଏ, କିମ୍ବା ଯେତେବେଳେ ଏକ ନିମ୍ନ ଚିତ୍ର ପ୍ରୟୋଗ କରାଯାଏ ନାହିଁ, `internal + external` `consumedTotal` ଠାରୁ ଭିନ୍ନ ହୋଇପାରେ।

#### ସଂରକ୍ଷଣ ଏବଂ ଧାରଣ

ଉଭୟ କୋଟା ଷ୍ଟୋର୍ଗୁଡ଼ିକ ପୁସ୍ତକ ରଖନ୍ତି। SQLite ରେ, ସ୍ୱୟଂଚାଳିତ ଡାଟାବେସ୍ କ୍ଲିନଅପ୍, ଯେତେବେଳେ ସକ୍ଷମ ହୁଏ, 60 ଦିନ ପାଇଁ ଅପଡେଟ୍ ହୋଇନଥିବା ଧାଡିଗୁଡ଼ିକୁ ଅପସାରଣ କରିଥାଏ। Redis ରେ, ପୁଲ୍ ସଂଯୋଗର ବହି ଏବଂ କାଉଣ୍ଟରଗୁଡ଼ିକ ଗୋଟିଏ ଚାବି ଅଂଶୀଦାର କରନ୍ତି। ଏହାର ଶେଷ ଟୋକନ୍ ଲେଖିବା କିମ୍ବା ପୁସ୍ତକ ପରିବର୍ତ୍ତନର 60 ଦିନ ପରେ ଏହା ସମାପ୍ତ ହୁଏ। ଏକ ପୁସ୍ତକ ଯାହା ପରିବର୍ତ୍ତନ ହୁଏ ନାହିଁ ତାହା ପୁନ r ଲିଖିତ ନୁହେଁ, ତେଣୁ କଟଅଫ୍ ଦୀର୍ଘତମ ଯୋଜନା ୱିଣ୍ଡୋ ଉପରେ ସେଟ୍ ହୋଇଛି। ମାନୁଆଲ୍ ବ୍ୟବହାର-ଇତିହାସ ପୁନ et ସେଟ୍ ମଧ୍ୟ SQLite ରେ ଥିବା ପୁସ୍ତକଗୁଡ଼ିକୁ ସଫା କରେ (ସୀମିତତା ଦେଖନ୍ତୁ)।

## ପାଇପଲାଇନ ଏକୀକରଣ

### PRE ହୁକ୍ (`open-sse/handlers/chatCore.ts`)

Auth ଏବଂ ନୀତି ଯାଞ୍ଚ ପରେ ଅପଷ୍ଟ୍ରିମ୍ ଏକଜିକ୍ୟୁଟରଙ୍କ ଆଗରେ ଚାଲିଥାଏ:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → getQuotaStore().peek() per dimension
      → fairShare.decideFairShare()
      → if block → return 429 (buildErrorBody, Hard Rule #12)
      → if allow + deprioritize → set quotaSoftPenalty=true on candidate
  → executor.execute()
```

**ବିଫଳ-ଖୋଲା।** : ଯଦି `enforceQuotaShare` ଫୋପାଡେ, ଏକ `pino.warn` ଲଗ୍ ମାଧ୍ୟମରେ ଅନୁରୋଧ ଅନୁମତିପ୍ରାପ୍ତ। ଏହା ଏକ କୋଟା-ଇଞ୍ଜିନ୍ ବଗ୍ କୁ ସମସ୍ତ ଟ୍ରାଫିକ୍ ଅବରୋଧ କରିବାରେ ରୋକିଥାଏ।

**ଯେତେବେଳେ କ୍ଷମତା ଫେରି ଆସେ।** ଚାବିର ଅଂଶରେ କିମ୍ବା ପୁଲ୍ ଛାତରେ ଏକ ପ୍ରତ୍ୟାଖ୍ୟାନ, ଉଭୟ orrow ଣ ମୋଡ୍ ରେ ଦୁଇଟି ବାକ୍ୟ ମଧ୍ୟରୁ ଗୋଟିଏ ସହିତ ଶେଷ ହୁଏ:

- `percent` ୱିଣ୍ଡୋ: `. The <window> window resets at <time>.` ପ୍ରଦାନକାରୀ ରିପୋର୍ଟଗୁଡିକର ପୁନ et ସେଟ୍ ସମୟ ଅଟେ।
- ଗଣନା ଯୋଗ୍ୟ ୟୁନିଟ୍: `. Enough <window> usage is expected to clear by <time>.` ସମୟ ହେଉଛି ସ୍ଲାଇଡିଂ ୱିଣ୍ଡୋରୁ ଏକ ଉପର ସୀମା, ଯଦି ଚାବି ଅନ୍ୟ କିଛି ପଠାଏ ନାହିଁ।

`<time>` ହେଉଛି UTC ରେ ଏକ ISO 8601 ତତକ୍ଷଣାତ୍। ପ୍ରତ୍ୟାଖ୍ୟାନ ତା’ପରେ `Retry-After` ବହନ କରେ: ସେହି ତତକ୍ଷଣାତ୍ ପୁରା ସେକେଣ୍ଡ୍, ଏବଂ ଗୋଟିଏ। ଏକ କ୍ଲାଏଣ୍ଟ ଯାହା ଅପେକ୍ଷା କରେ, ତତକ୍ଷଣାତ୍ ପ୍ରାୟ ଏକ ସେକେଣ୍ଡରେ ପୁନର୍ବାର ଚେଷ୍ଟା କରେ। ଯେତେବେଳେ ତତକ୍ଷଣାତ୍ ଜଣା ନଥାଏ, ପ୍ରତ୍ୟାଖ୍ୟାନ ନା ବାକ୍ୟ କିମ୍ବା ହେଡର୍ ବହନ କରେ। ଏକ ସଂପୂର୍ଣ୍ଣ କ୍ୟାପ୍ ପ୍ରତ୍ୟାଖ୍ୟାନ ମଧ୍ୟ ବହନ କରେ ନାହିଁ। ସର୍ବସାଧାରଣ କୋଡ୍ `quota_share_blocked` ରୁହେ।

ଏକ ଅଂଶୀଦାର ପ୍ରତ୍ୟାଖ୍ୟାନ ଅଂଶୀଦାର ସଂଯୋଗକୁ ସ୍ପର୍ଶ କରେ ନାହିଁ। ଏହା କ co ଣସି କୁଲଡାଉନ୍, କ model ଣସି ମଡେଲ୍ ଲକ୍ ଏବଂ କ prov ଣସି ପ୍ରଦାନକାରୀ ବ୍ରେକର୍ ବିଫଳତା ସେଟ୍ କରେ ନାହିଁ, ଏବଂ ପୁଲ୍ର ଅନ୍ୟ ଚାବିଗୁଡ଼ିକ ପରିବେଷଣ କରାଯାଏ। ଯେତେବେଳେ କମ୍ବୋ ର ପ୍ରତ୍ୟେକ ଟାର୍ଗେଟ୍ ଏହାର ଅଂଶ ପାଇଁ ଚାବିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ, କମ୍ବୋ ଅପେକ୍ଷା ନକରି 429 ର ଉତ୍ତର ଦେଇଥାଏ। ଏହାର ଉତ୍ତର `Retry-After` ଭାବରେ ସୂଚାଇଥାଏ। ଏମ୍ବେଡିଂ ପଥ ସମାନ ବାକ୍ୟ ସହିତ ଏହାର ପ୍ରତ୍ୟାଖ୍ୟାନକୁ ସମାପ୍ତ କରେ ଏବଂ `Retry-After` ପଠାଏ ନାହିଁ।

### POST ହୁକ୍ (ରେକର୍ଡ ବ୍ୟବହାର)

ଏକ ସଫଳ ପ୍ରତିକ୍ରିୟା ପରେ:

```
executor returns success
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → getQuotaStore().consume() per dimension
      → fail-open: errors logged as pino.warn, never propagated to client
```

**ଡ୍ରାଇଫ୍ ନୋଟ୍।** : ଯଦି `consume` ପରବର୍ତ୍ତୀ ପ୍ରତିକ୍ରିୟାରେ ବିଫଳ ହୁଏ, ଗାଡ଼ି କାଉଣ୍ଟର ଅଣ୍ଡର-କାଉଣ୍ଟ୍। ପ୍ରଦାନକାରୀଙ୍କ ଠାରୁ ସାଚୁଚରେସନ୍ ସିଗ୍ନାଲ୍ (ଯଥା `anthropic-ratelimit-unified-5h-utilization`) ପରବର୍ତ୍ତୀ ଅନୁରୋଧରେ ବିଶ୍ global ର ଆକଳନକୁ ସଂଶୋଧନ କରେ।

### କମ୍ବୋ ସଫ୍ଟ ପେନାଲ୍ଟି (`open-sse/services/combo.ts`)

ଯେତେବେଳେ `decision.deprioritize === true`:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // default 0.7
}
```

ଅନ୍ୟ ସମସ୍ତ ସ୍କୋରିଂ ଫ୍ୟାକ୍ଟର୍ ପରେ ପେନାଲ୍ଟି ପ୍ରୟୋଗ କରାଯାଏ। ଏହା ହାର୍ଡ-ବ୍ଲକ୍ ନକରି ଏକ ସନ୍ତୁଳିତ ଚାବି ବାଛିବାର ଅଟୋ-କମ୍ବୋ ସମ୍ଭାବନାକୁ ହ୍ରାସ କରେ।

## ସ୍ Service ୟଂ ସେବା କୋଟା API (ଅପ୍ଟ-ଇନ୍)

`GET /api/v1/me/quota/{provider}` ( `/v1/me/quota/{provider}` ରେ ମଧ୍ୟ ପରିବେଷିତ) ଏକ API କି ଧାରକକୁ ନିଜ ଚାବି ସହିତ ପ shared ଼ିବାକୁ ଦେଇଥାଏ, କେତେ ଅଂଶୀଦାରୀ ସଦସ୍ୟତା ସେମାନଙ୍କର ଏବଂ ସେମାନଙ୍କୁ ଅବରୋଧ କରୁଛି। ମାର୍ଗଟି `src/server/selfService/quotaHandler.ts` ଉପରେ ଏକ ପତଳା ଶେଲ୍; ଦୃଶ୍ୟ `src/lib/quota/selfView.ts` ଦ୍ୱାରା ନିର୍ମିତ ଏବଂ ଏହାର ପ୍ରତିକ୍ରିୟା ଚୁକ୍ତି ହେଉଛି `src/shared/schemas/selfQuota.ts` (`SelfQuotaView` ରେ `docs/openapi.yaml`)।

### ସକ୍ଷମ ଏବଂ ପ୍ରାମାଣିକିକରଣ।

- ବ flag ଶିଷ୍ଟ୍ୟ ଫ୍ଲାଗ୍ `QUOTA_SELF_PANEL`, ଡିଫଲ୍ଟ `false`। ଏହା ବନ୍ଦ ଥିବାବେଳେ, ଏକ ଅନୁରୋଧ ଯାହା ମାର୍ଗରେ ପହଞ୍ଚେ 404 ପାଇଥାଏ। `REQUIRE_API_KEY=true` ସହିତ, କ୍ଲାଏଣ୍ଟ API ନୀତି 401 ସହିତ ଏକ ନିଖୋଜ କିମ୍ବା ଅବ alid ଧ ଚାବିକୁ ମନା କରିଦିଏ, ପତାକା ଯାହା ବି ହେଉ। କ key ଣସି ଚାବି ନଥିବା ଏକ ଅନୁରୋଧ କିନ୍ତୁ ଏକ ସାଇନ୍-ଇନ୍ ଡ୍ୟାସବୋର୍ଡ ଅଧିବେଶନ ସେହି ନୀତି ପାସ୍ କରେ ଏବଂ ମାର୍ଗର ନିଜସ୍ୱ ଉତ୍ତର ପାଇଥାଏ। ପତାକା ଅନ୍ୟ ସମସ୍ତ ପତାକା ପରି ସମାଧାନ କରେ (ଡ୍ୟାସବୋର୍ଡ କିମ୍ବା REST ଓଭରବ୍ରିଡ୍, ତାପରେ ସମାନ ନାମର ପରିବେଶ ଭେରିଏବଲ୍); [`FEATURE_FLAGS.md`](../reference/FEATURE_FLAGS.md) ଦେଖନ୍ତୁ।
- ପ୍ରତ୍ୟେକ ପୁଲ୍ର ପ୍ରଦର୍ଶନ ନାମ ଏବଂ ପ୍ରତ୍ୟେକ କାର୍ଯ୍ୟସୂଚୀର ଲେବଲ୍ ଠିକ୍ ଭାବରେ ପ୍ରଶାସକ ଲେଖିଥିବା ପରି ପୁଲ୍ର ମୁଖ୍ୟ ଧାରକମାନଙ୍କୁ ଫେରସ୍ତ କରାଯାଇଥାଏ। ପତାକା ଅନ୍ କରିବା ପୂର୍ବରୁ, ଯାଞ୍ଚ କରନ୍ତୁ ଯେ ସେଗୁଡ଼ିକ ସେହି ପ୍ରମୁଖ ଧାରକମାନଙ୍କ ଦ୍ୱାରା ପ read ିବାକୁ ଫିଟ୍।
- ଚାବି କେବଳ ହେଡର୍ ରୁ ପ read ାଯାଏ: `Authorization: Bearer <key>` କିମ୍ବା `x-api-key: <key>`। ଯେତେବେଳେ ଉଭୟ ପଠାଯାଏ, ପ୍ରଥମଟି ବ valid ଧତା ବ୍ୟବହୃତ ହୁଏ। ଜିଜ୍ଞାସା ଷ୍ଟ୍ରିଙ୍ଗ୍ କିମ୍ବା କୁକିରେ ଥିବା ଏକ ଚାବିକୁ ଅଣଦେଖା କରାଯାଏ। ସର୍ଭରର ପରିବେଶ ଚାବିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଇଛି (401)।
- ଚାବି `self:usage` ପରିସର ଆବଶ୍ୟକ କରେ (ଏହା ବିନା 403)।
- ପ୍ରଦାନକାରୀ ବିଭାଗକୁ ଛେଦନ କରାଯାଇଛି, ଲୋ-କେଜେଡ୍ ଏବଂ `^[a-z0-9][a-z0-9._-]{0,63}$` (400 ଅନ୍ୟଥା) ବିରୁଦ୍ଧରେ ଯାଞ୍ଚ କରାଯାଇଥାଏ, ତାପରେ ପ୍ରଦାନକାରୀ ରେଜିଷ୍ଟ୍ରି ମାଧ୍ୟମରେ ସମାଧାନ କରାଯାଇଥାଏ, ତେଣୁ `cc` ପରି ଏକ ଛଦ୍ମନାମ `claude` ପୁଲ୍ ପ read ିଥାଏ। `claude` ଏବଂ `anthropic` ସମାନ ପୁଷ୍କରିଣୀ ପ read ନ୍ତି।

### ସମ୍ମତି ending ଣ

`PATCH /api/v1/me/quota/{provider}` ଗୋଟିଏ ପୁଲ୍ ପାଇଁ କଲିଂ କି ର ନିଜସ୍ୱ ସମ୍ମତି ରେକର୍ଡ କରେ। ଏହା `GET` ର ପତାକା, ହେଡର୍ ଏବଂ ପ୍ରଦାନକାରୀ ନିୟମ ବ୍ୟବହାର କରେ। `self:usage` ପରିସର ଏହି ଲେଖାକୁ ଅନୁମତି ଦିଏ, ଯଦିଓ ଏହାର ନାମ କେବଳ ପଠନୀୟ ଭାବରେ ପ read େ।

```json
{
  "pool": "qpr_0123456789abcdef0123456789abcdef",
  "lendingPercent": 30,
  "lendingUntil": 1893456000000
}
```

- `pool` ହେଉଛି `ref` ସେହି ପୁଲ୍ ପାଇଁ `GET` ରିଟର୍ନ।
- `lendingPercent` ହେଉଛି 0 ରୁ 100 ପର୍ଯ୍ୟନ୍ତ ଏକ ପୂର୍ଣ୍ଣ ସଂଖ୍ୟା। 0 ର ମୂଲ୍ୟ ସମ୍ମତି ଏବଂ ଏହାର ସମୟସୀମା ସଫା କରେ। `lendingPercent` 0 ସହିତ ଏକ ଶରୀର ଉଭୟ ମୋଡରେ ଗ୍ରହଣୀୟ।
- `lendingUntil` ବ al କଳ୍ପିକ: ଯୁଗ ମିଲିସେକେଣ୍ଡ, କିମ୍ବା କ dead ଣସି ସମୟସୀମା ପାଇଁ `null`। ଏହା ନିଶ୍ଚିତ ଭାବରେ ଭବିଷ୍ୟତରେ ଏବଂ ସର୍ବାଧିକ 8640000000000000 ହେବା ଆବଶ୍ୟକ। 100000000000 ତଳେ ଥିବା ମୂଲ୍ୟ ସେକେଣ୍ଡ୍ ଭାବରେ ପ read ଼େ ଏବଂ ଏହାକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ।

| 403    | `Lending is not enabled for this pool`                                                             | ପୁଲ୍ `saturation` ମୋଡ୍ ରେ ଅଛି ଏବଂ `lendingPercent` 0 ଉପରେ ଅଛି।     |
| 500    | `Failed to build quota view`                                                                       | ଅନ୍ୟ କ failure ଣସି ବିଫଳତା। ଏହାର କାରଣ ସର୍ଭରରେ ଲଗ୍ ହୋଇଛି।            |

ପ୍ରତ୍ୟେକ ଚାବି ପାଇଁ ସୀମା ହେଉଛି 60 ସେକେଣ୍ଡରେ 20 ଅନୁରୋଧ। ପ୍ରଦାନକାରୀ ଚେକ୍ ଗଣନାକୁ ପାସ୍ କରୁଥିବା ପ୍ରତ୍ୟେକ ଅନୁରୋଧ, ଏପରିକି ଗୋଟିଏ ପରେ ମନା କରିଦେଲା କିମ୍ବା କିଛି ପରିବର୍ତ୍ତନ କରେ ନାହିଁ। ଚାବିର ଅନୁରୋଧ ହାର ସୀମା ବ୍ୟତୀତ ଏହାର ନିଜସ୍ୱ କାଉଣ୍ଟର ଅଛି।

ସଂରକ୍ଷିତ ସମ୍ମତି ପରିବର୍ତ୍ତନ କରୁଥିବା ଏକ ଅନୁରୋଧ ଗୋଟିଏ `quota.pool.lending.updated` ଅଡିଟ୍ ରେକର୍ଡ ଲେଖେ। ଏହା ପୁରୁଣା ଏବଂ ନୂତନ ମୂଲ୍ୟ ସହିତ ଚାବିକୁ ନାମିତ କରେ। ପଠାଯାଇଥିବା ସମାନ ଶରୀର ଦୁଇଥର ଲେଖେ ଏବଂ ଥରେ ଅଡିଟ୍ କରେ। ଉତ୍ତରଟି ସମ୍ପୂର୍ଣ୍ଣ `GET` ଦୃଶ୍ୟ ସହିତ 200, ଲେଖା ପରେ ନିର୍ମିତ।

`GET` ଦୃଶ୍ୟ ନିମ୍ନଲିଖିତ ଭାବରେ ending ଣ ପ୍ରଦାନ ରିପୋର୍ଟ କରେ:

- ପ୍ରତ୍ୟେକ ପୁଲ୍ `borrowMode` (`saturation` କିମ୍ବା `consent`), ଏବଂ ଚାବିର ନିଜସ୍ୱ `lendingPercent` ଏବଂ `lendingUntil` ବହନ କରେ।
- `lendingActive` କେବଳ `true` `consent` ଅଛି, ଶତକଡା 0 ରୁ ଅଧିକ ଏବଂ ଏକ ସମୟସୀମା ପହଞ୍ଚି ନାହିଁ।
- ଏକ `consent` ପୁଲରେ, ପ୍ରତ୍ୟେକ ଗଣନାଯୋଗ୍ୟ `dimensions[].yourShare` `borrowAvailable` ବହନ କରେ। ଅନ୍ୟ ଚାବି ଦ୍ୱାରା ent ଣ ଦିଆଯାଇଥିବା ଚାବି ବର୍ତ୍ତମାନ ଏହାର ଅଂଶ ଉପରେ ବ୍ୟବହାର କରିପାରିବ।
- `borrowAvailable` ଗେଟର ସୂତ୍ର ବ୍ୟବହାର କରେ। ଚାବି ଏହାର ଅଂଶରେ ଥିବାବେଳେ ଏହା ଅନ୍ୟ ସମସ୍ତ ଚାବି ପ read େ। ଏକ `hard` କି ପାଇଁ ସମାନ୍ତରାଳ ଭାବରେ ଅନ୍ୟ ଚାବି ଏବଂ ଗଣନା ଯୋଗ୍ୟ ପରିମାଣ ପାଇଁ ଗୋଟିଏ ଅତିରିକ୍ତ ପ read ା।
- `borrowAvailable` ହେଉଛି `soft` କିମ୍ବା `burst` କି ପାଇଁ `null`, ଏବଂ ଏକ ପଠନ ବିଫଳ ହେଲେ `null`।
- `borrowAvailable` ଅନ୍ୟ ସମସ୍ତ କିଗୁଡ଼ିକ ପାଇଁ ଏକ ଚିତ୍ର। ଦୁଇଟି ଚାବିର ପୁଲରେ ଏହା ଅନ୍ୟ ଚାବିର ନିଜସ୍ୱ ଚିତ୍ର।
- `borrowAvailable` `percent` କିମ୍ବା `accounts[]` ରେ ଏପର୍ଯ୍ୟନ୍ତ ରିପୋର୍ଟ ହୋଇନାହିଁ।
- ଏକ `saturation` ପୁଲରେ ଦୃଶ୍ୟ `lendingActive: false` ସହିତ ସଂରକ୍ଷିତ ସମ୍ମତି ରିପୋର୍ଟ କରେ ଏବଂ `borrowAvailable` ନାହିଁ।

### ତ୍ରୁଟି।

ଏହି ମାର୍ଗର ପ୍ରତ୍ୟେକ ପ୍ରତିକ୍ରିୟା, ସଫଳତା କିମ୍ବା ତ୍ରୁଟି, `Cache-Control: no-store` ବହନ କରେ। ମାର୍ଗ ଚାଲିବା ପୂର୍ବରୁ ଘଟିଥିବା ଏକ ପ୍ରତ୍ୟାଖ୍ୟାନ ଏହାକୁ ବହନ କରେ ନାହିଁ, ଉଦାହରଣ ସ୍ୱରୂପ କ୍ଲାଏଣ୍ଟ API ପଲିସିର 401 କିମ୍ବା IP ଫିଲ୍ଟରର 403। ମାର୍ଗର ତ୍ରୁଟିଗୁଡ଼ିକ ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ ବାର୍ତ୍ତା ସହିତ ମାନକ ତ୍ରୁଟି ଶରୀରକୁ ବ୍ୟବହାର କରିଥାଏ: 400 (ଅବ alid ଧ ପ୍ରଦାନକାରୀ), 401 (ନିଖୋଜ କିମ୍ବା ଅବ alid ଧ ଚାବି), 403 (ନିଖୋଜ `self:usage`), 404 (ଫ୍ଲାଗ୍ ଅଫ୍) ଏବଂ 500 (`Failed to build quota view`)। 500 ଅନୁରୋଧଟି ମାର୍ଗରେ ପହଞ୍ଚିବା ପରେ ଯେକ any ଣସି ବିଫଳତାକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ, ଚାବି ନିଜେ ନିଜେ ଅନ୍ତର୍ଭୁକ୍ତ କରେ। ଏହାର କାରଣ ସର୍ଭରରେ ଲଗ୍ ହୋଇଛି ଏବଂ ଆଉ ଫେରିନାହିଁ। `PATCH` ର ତ୍ରୁଟିଗୁଡ଼ିକ [ending ଣ ସମ୍ମତିରେ](#lending-consent) ତାଲିକାଭୁକ୍ତ।

### ସୀମା

- `remaining` ହେଉଛି ଚାବିର ନ୍ୟାୟଯୁକ୍ତ ଅଂଶ ଯାହା ଏହା ବ୍ୟବହାର କରିନାହିଁ। ଏହା ଏକ ଗ୍ୟାରେଣ୍ଟି ନୁହେଁ। ପୁଷ୍କରିଣୀର କୋଠରୀ ଥିବାବେଳେ ଏକ ଚାବି ତଥାପି ଏହା ବାହାରେ ପରିବେଷଣ କରାଯାଇପାରେ। ଥରେ ପୁଲ୍ର ସମୁଦାୟ `limit` ପହଞ୍ଚିବା ପରେ ପୁଲ୍ର ପ୍ରତ୍ୟେକ ଚାବି ପ୍ରତ୍ୟାଖ୍ୟାନ ହୁଏ, ଏହାର ନିଜସ୍ୱ `remaining` ଯାହା ବି ହେଉ, ଏବଂ `self:account-quota` ବିନା ଏକ ଚାବି ସେହି ସମୁଦାୟକୁ ଦେଖିପାରିବ ନାହିଁ।
- `remaining` ଆବଣ୍ଟନର ସଂପୂର୍ଣ୍ଣ `cap` କୁ ଗ୍ରହଣ କରେ ନାହିଁ। କ୍ୟାପ୍ ୟୁନିଟ୍ ର ଏକ ୱିଣ୍ଡୋରେ ଏହାର ବ୍ୟବହାର କ୍ୟାପ୍ ମୂଲ୍ୟରେ ପହଞ୍ଚିବା ପରେ ଏନଫୋର୍ସମେଣ୍ଟ ଚାବିକୁ ମନା କରେ।
- ଆକାଉଣ୍ଟ୍-ଲେଭଲ୍ ବାର୍ ପ୍ରଦାନକାରୀ-ସୀମା କ୍ୟାଶେରୁ ଆସିଥାଏ ଏବଂ କିଛି ମିନିଟ୍ ପର୍ଯ୍ୟନ୍ତ କାର୍ଯ୍ୟକାରୀ ନିଷ୍ପତ୍ତିକୁ ପଛରେ ପକାଇପାରେ। ଏକ ପଠନ ଯାହାର ପୁନ et ସେଟ୍ ସମୟ ଅତିବାହିତ ହୋଇଛି `stale` ଭାବରେ ରିପୋର୍ଟ କରାଯାଇଛି।
- ପ୍ରତି-ମଡେଲ୍ ୱିଣ୍ଡୋ (`modelWindows`) କେବଳ ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ ରିପୋର୍ଟ କରାଯାଇଛି ଯେଉଁମାନଙ୍କର ପ୍ଲାନ୍-ୱିଣ୍ଡୋ ମ୍ୟାପିଙ୍ଗ୍ ଅଛି: ଆଜି Claude ଏବଂ Codex। ଅନ୍ୟ ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ `modelWindows` ଏକ ଖାଲି `windows` ତାଲିକା ସହିତ ଖାତା ତଥ୍ୟ ଦେଖାଯିବାବେଳେ ଉପସ୍ଥିତ ଥାଏ।
- `percent` ୱିଣ୍ଡୋର ଚାବିର ନିଜସ୍ୱ ଅଂଶ ହେଉଛି ଏକ ଆକଳନ। ଏହା ଆଟ୍ରିବ୍ୟୁସନ୍ ବୁକ୍ ରୁ ଆସିଥାଏ ଏବଂ ଉପରୋକ୍ତ “ଶତକଡା ensions ାଞ୍ଚା: ପ୍ରତି କି-ଆଟ୍ରିବ୍ୟୁସନ୍” ଅନ୍ତର୍ଗତ ତାଲିକାଭୁକ୍ତ ପ୍ରତ୍ୟେକ ସୀମିତତାକୁ ବହନ କରେ।
- `consumed` ହେଉଛି ନମ୍ୱର ପ୍ରୟୋଗ ହେଉଛି ଯଥାର୍ଥ ଅଂଶ ସହିତ ତୁଳନା କରେ। ଏହା `attributed` plus `external` ଅଟେ। `attributed` ହେଉଛି ସେହି ଅଂଶ ଯାହାକି ବହିଟି ଟୋକେନ୍ ପାଇଁ ଚାବି ଦେଇଥାଏ। `external` ହେଉଛି ଖାତାର ବ୍ୟବହାରର ଚାବିର ଅଂଶ ଯାହା ପୁଲ୍ର ଚାବିଗୁଡ଼ିକ ହିସାବ କରେ ନାହିଁ।
- ପୁଲ୍ର `accountVisible` ସତ ହେଲେ ଉଭୟ ଅଂଶ ପଠାଯାଏ: ଚାବିର `self:account-quota` ଅଛି ଏବଂ ପ୍ରଦାନକାରୀ ଏହାର `sharedQuotaProviders` ରେ ଅଛି। ଏହା ବିନା ଏକ ଚାବି `consumed` ଏକାକୀ ପାଇଥାଏ, ସମାନ `status` ଏବଂ `reason` ସହିତ।
- ଉଭୟ ଅଂଶ ଏବଂ ଏହାର ଓଜନ ସହିତ, ଜଣେ ଧାରକ ପୁଲ୍ର ଚାବି ଉପରେ ଚାର୍ଜ ହୋଇଥିବା ପୁଲ୍ ବାହାରେ ନିର୍ମିତ ବ୍ୟବହାରକୁ ବାହାର କରିପାରିବ। ଆକାଉଣ୍ଟ୍ ପରିସର ସହିତ ଏକ ଧାରକ ପୂର୍ବରୁ ଆକାଉଣ୍ଟ୍ ସମୁଦାୟ ଦେଖନ୍ତି।
- ୱିଣ୍ଡୋରେ କିଛି ଚଲାଇ ନଥିବା ଏକ ଚାବି ଏପର୍ଯ୍ୟନ୍ତ `consumed` ରୁ ଏହାର ବାହ୍ୟ ଚାର୍ଜ ପ read ିପାରେ, କାରଣ ଏହାର ଗୁଣବତ୍ତା ଅଂଶ 0 ଅଟେ।

- ଧାରକମାନେ ତଥାପି ସେମାନଙ୍କର ମୂଲ୍ୟ ଅନୁଯାୟୀ ସ୍ଲାଇସ୍ ସହିତ ମେଳ କରିପାରିବେ।
- ଏକ ସ୍ଥିର ସଂଖ୍ୟାକରଣ ଏକ ଧାରକକୁ ସମୟ ସହିତ ଜଣେ ସଦସ୍ୟଙ୍କୁ ଅନୁସରଣ କରିବାକୁ ଦିଏ।
- କଦଳୀ ସଂଖ୍ୟା ଦର୍ଶାଏ ଯେ ପୁଲରେ କେତେ ଚାବି ଆବଣ୍ଟିତ ହୋଇଛି।
- ତିନୋଟି ଚାବିର ପୁଲରେ, ଯିଏ ଜାଣେ କେଉଁ ଚାବି ବ୍ୟବହୃତ ହୋଇଛି ଶେଷ ଚାବି କ’ଣ ବ୍ୟବହୃତ ହୋଇଛି ତାହା କହିପାରେ।
- ଯେତେବେଳେ ଏକ ପୁଲ୍ ତିନୋଟି ବ୍ୟବହାର ଯୋଗ୍ୟ ଚାବି ତଳେ ପଡ଼େ, ବାରଗୁଡ଼ିକ ଅଦୃଶ୍ୟ ହୋଇଯାଏ। ପୂର୍ବରୁ ନିଆଯାଇଥିବା ଦୃଶ୍ୟଗୁଡ଼ିକ ତଥାପି ପ୍ରତ୍ୟେକ ସଦସ୍ୟ କ’ଣ ବ୍ୟବହାର କରିଥିଲେ ତାହା ଦର୍ଶାଏ।
- ଏକ ଗଣନାଯୋଗ୍ୟ ୱିଣ୍ଡୋରେ, ପୁଲ୍ ସମୁଦାୟ ମାଇନସ୍ ସ୍ଲାଇସ୍ ଚାବିର ବ୍ୟବହାର ଦେଖାଇପାରେ ଯାହା ଆଉ ବଣ୍ଟନ ହୋଇନାହିଁ।
- ଜଣେ ସଦସ୍ୟ ଯିଏ ଗୋଟିଏ ଆକାଉଣ୍ଟରେ ଶୂନ ଦେଖାଏ ଏବଂ ଅନ୍ୟଟିରେ ବ୍ୟବହାର କରେ କେଉଁ ସଦସ୍ୟ କେଉଁ ଆକାଉଣ୍ଟ ବ୍ୟବହାର କରେ ତାହା ଦର୍ଶାଇପାରେ।
- `hard` ନୀତି ସହିତ ଏକ ଗଣନାଯୋଗ୍ୟ ପୁଲରେ, ଏକ ସ୍ଲାଇସ୍ ଯାହା ସଦସ୍ୟଙ୍କ ମେଳାରେ ବ growing ିବା ବନ୍ଦ କରିଦିଏ ସେହି ସଦସ୍ୟଙ୍କ ଓଜନକୁ ସୂଚାଇଥାଏ।

### ବ୍ୟବହାର ସିରିଜ୍ (`GET /api/v1/me/usage`)

`GET /api/v1/me/usage?range=<range>` ( `/v1/me/usage` ରେ ମଧ୍ୟ ପରିବେଷିତ) କଲିଂ କି ର ନିଜସ୍ୱ ଅନୁରୋଧର ବ୍ୟବହାର ଏବଂ ମୂଲ୍ୟ ଫେରସ୍ତ କରେ: ସମୁଦାୟ, UTC ଦିନ ପ୍ରତି ଗୋଟିଏ ପ୍ରବେଶ, ଦିନ ଏବଂ ମଡେଲ, ପ୍ରତି ମଡେଲ ଏବଂ ପ୍ରତି ପ୍ରଦାନକାରୀ। ଏହା ପତାକା, ପ୍ରାମାଣିକିକରଣ ନିୟମ, `self:usage` ପରିସର, `Cache-Control: no-store` ଏବଂ ଉପରୋକ୍ତ କୋଟା ମାର୍ଗର ତ୍ରୁଟି ଆଚରଣ ଅଂଶୀଦାର କରେ। `range` ପୂର୍ବରୁ ଚାବି ଯାଞ୍ଚ କରାଯାଇଥାଏ। ତ୍ରୁଟିଗୁଡିକ ହେଉଛି 400 (`Invalid range`), 401, 403, 404 ଏବଂ 500 (`Failed to build usage`)।

- `range` ହେଉଛି `1d`, `7d`, `30d` (ଡିଫଲ୍ଟ) କିମ୍ବା `90d` ମଧ୍ୟରୁ ଗୋଟିଏ। ଅନ୍ୟ କ value ଣସି ମୂଲ୍ୟ, ଏକ ଖାଲି ମୂଲ୍ୟ କିମ୍ବା ବାରମ୍ବାର ପାରାମିଟର ହେଉଛି 400। କଲ୍ ର ମୂଲ୍ୟ ବାନ୍ଧିବା ପାଇଁ ସେଟ୍ `90d` ରେ ଅଟକିଯାଏ। ଦୃଶ୍ୟ କେବଳ କଞ୍ଚା ବ୍ୟବହାର ଇତିହାସ ପ read େ, କଦାପି ଦ daily ନିକ ସାରାଂଶ, ଯାହା କ key ଣସି ଚାବି ବହନ କରେ ନାହିଁ।
- ଧାଡିଗୁଡିକ କଲିଂ କି ର id ଦ୍ୱାରା ଚୟନ କରାଯାଇଛି। ଚାବି ନାମ ସ୍ତମ୍ଭ କଦାପି ମେଳ ହୁଏ ନାହିଁ, ଏବଂ ଏକ କି id ବିନା ରେକର୍ଡ ହୋଇଥିବା ଧାଡିଗୁଡିକ କଦାପି ଗଣନା କରାଯାଏ ନାହିଁ।
- ୱିଣ୍ଡୋରେ ଚାବିର ଧାଡି ଉପରେ ଏକ ସିରିଜ୍ ନିର୍ମାଣ ପାଞ୍ଚଟି ଗୋଷ୍ଠୀଗତ ପ୍ରଶ୍ନଗୁଡିକ ଚଲାଇଥାଏ। ନିର୍ମିତ ସିରିଜ୍ କି ଏବଂ ପରିସର ପ୍ରତି 60 ସେକେଣ୍ଡ ପାଇଁ ପୁନ used ବ୍ୟବହୃତ ହୁଏ, ଏବଂ ପୁନ used ବ୍ୟବହୃତ କଲ୍ କ runs ଣସି ଚଲାଏ ନାହିଁ। ଏହାର `generatedAt` ଏହାର ବୟସ ଦେଇଥାଏ।
- ସିରିଜ୍ ନିର୍ମାଣ ହେବା ପରେ ୱିଣ୍ଡୋ ଶେଷ ହୁଏ। ପରେ ଷ୍ଟାମ୍ପ୍ ହୋଇଥିବା ଏକ ଧାଡି, ଉଦାହରଣ ସ୍ୱରୂପ ଘଣ୍ଟା ସ୍କେ ଦ୍ୱାରା ଗଣନା କରାଯାଏ ନାହିଁ।
- `coverage.retentionDays` ହେଉଛି ଅପରେଟରର କଞ୍ଚା ବ୍ୟବହାର-ଇତିହାସ ଧାରଣ ସେଟିଂ (ଡାଟାବେସ୍ ସେଟିଂସମୂହରେ`retention.usageHistory` )। `coverage.truncatedByRetention` ସତ ଯେତେବେଳେ ଅନୁରୋଧ କରାଯାଇଥିବା ପରିସର ସେହି ସେଟିଂଠାରୁ ଲମ୍ବା ଅଟେ। ଏହା ଦୁଇଟି ସଂଖ୍ୟାକୁ ତୁଳନା କରେ ଏବଂ ଧାଡିଗୁଡ଼ିକ ପ୍ରକୃତରେ ଅନୁପସ୍ଥିତ ଅଛି କି ନାହିଁ ଯାଞ୍ଚ କରେ ନାହିଁ।
- ଚାବିର ନିଜସ୍ୱ ଅନୁରୋଧ ପାଇଁ ରେକର୍ଡ କରାଯାଇଥିବା ପରି ପ୍ରଦାନକାରୀ ଫେରସ୍ତ କରାଯାଇଥାଏ। ମଡେଲ୍ ହେଉଛି ଏହାର ଶେଷ `/` ପରେ ରେକର୍ଡ ହୋଇଥିବା ନାମ, ଏବଂ ଧାଡିଗୁଡ଼ିକ ଏହା ଦ୍ୱାରା ଗ୍ରୁପ୍ ହୋଇଛି। ଏକ କମ୍ବୋ ଅନୁରୋଧ ଯାହାର ପ୍ରତ୍ୟେକ ଲକ୍ଷ୍ୟକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଇଥିଲା ପ୍ରଦାନକାରୀ (କମ୍ବୋ ନାମ, `auto` କିମ୍ବା `combo`) ଏବଂ କ୍ଲାଏଣ୍ଟ ପଠାଇଥିବା ମଡେଲ ଷ୍ଟ୍ରିଙ୍ଗ ଭାବରେ ରାଉଟିଙ୍ଗ ଲେବଲ୍ ସହିତ ରେକର୍ଡ କରାଯାଇଛି। ଅନ୍ୟାନ୍ୟ ମନା କରାଯାଇଥିବା ଅନୁରୋଧ, ଉଦାହରଣ ସ୍ୱରୂପ ଏକ ଓପନ୍ ସର୍କିଟ୍ ବ୍ରେକର୍, ଏକ ମଡେଲ୍ କୁଲଡାଉନ୍ କିମ୍ବା କୋଟା-ପାର୍କ ସ୍କିପ୍ ଦ୍ୱାରା, ଲକ୍ଷ୍ୟ ପ୍ରଦାନକାରୀ ଏବଂ ମଡେଲ୍ ରଖ।
- ଗଣନା ଏବଂ ଖର୍ଚ୍ଚ ବ୍ୟତୀତ, ପ୍ରତିକ୍ରିୟା ହାରାହାରି ବିଳମ୍ବତା, ସଫଳତା ହାର ଏବଂ ପ୍ରଥମ ଏବଂ ଶେଷ ଅନୁରୋଧର ସମୟ ବହନ କରେ।
- `byModel` ସର୍ବାଧିକ ଅନୁରୋଧ ସହିତ 50 ପ୍ରଦାନକାରୀ-ଏବଂ-ମଡେଲ ଯୋଡି ତାଲିକାଭୁକ୍ତ କରେ। ଅଧିକ ଯୋଡି ସହିତ ଏହାର ଏଣ୍ଟ୍ରିଗୁଡିକ `summary` ପର୍ଯ୍ୟନ୍ତ ଯୋଡେ ନାହିଁ, ଏବଂ `summary.uniqueModels` ପ୍ରତ୍ୟେକ ରେକର୍ଡ ହୋଇଥିବା ମଡେଲ ବନାନକୁ ଗଣନା କରେ। `byModelTruncated` ତାପରେ ସତ ଅଟେ, ଏବଂ ଏକ ମଡେଲ୍ ଯାହାର ଯୋଡି କଟର ଉଭୟ ପାର୍ଶ୍ୱରେ ପଡ଼େ ଆଂଶିକ ସମୁଦାୟ ଦେଖାଏ।
- ଦୁଇଟି ଖର୍ଚ୍ଚ ରିପୋର୍ଟ କରାଯାଇଛି। `costUsd` ହେଉଛି ବିଲ୍ ମୂଲ୍ୟ, ଯେହେତୁ ବ୍ୟବହାର ଆନାଲିଟିକ୍ସ ଏହାକୁ ଦର୍ଶାଏ। ଫ୍ଲାଟ-ରେଟ୍ ସବସ୍କ୍ରିପସନ୍ ପ୍ରଦାନକାରୀ, ଯେପରିକି Claude କୋଡ୍ ଯୋଜନା, ସେଠାରେ $ 0 ଗଣନା କରନ୍ତୁ। `listPriceUsd` ତାଲିକା ମୂଲ୍ୟରେ ସମାନ ବ୍ୟବହାର, ସଦସ୍ୟତା ଅନ୍ତର୍ଭୁକ୍ତ। ଏକ ଅନୁରୋଧ ଯାହାର ମଡେଲର କ price ଣସି ମୂଲ୍ୟ ଧାଡି ଏହାର ଗଚ୍ଛିତ ମୂଲ୍ୟ ଗଣନା କରେ: ପ୍ରଦାନକାରୀ ରିପୋର୍ଟ କରିଥିବା ମୂଲ୍ୟ, କିମ୍ବା ଅନୁରୋଧ ରେକର୍ଡ ହେବା ସମୟରେ ଗଣନା କରାଯାଏ। କେବଳ ଏକ ଅନୁରୋଧ 0 ସହିତ ଗଣନା କରେ ନାହିଁ, କ mark ଣସି ମାର୍କର୍ ସହିତ ନାହିଁ, ତେଣୁ ସମୁଦାୟ ଆଂଶିକ ହୋଇପାରେ।
- ପ୍ରତିକ୍ରିୟା ଚୁକ୍ତି ହେଉଛି `src/shared/schemas/selfUsage.ts` ( `docs/openapi.yaml` ରେ`SelfUsageSeries` )।

### ଆତ୍ମ ସେବା ପୃଷ୍ଠା।

`QUOTA_SELF_PANEL` ସହିତ, `/quota/{provider}` ଏକ ସାର୍ବଜନୀନ ପୃଷ୍ଠା। ଏକ କି ଧାରକ ସେଠାରେ ଏକ API କି ଟାଇପ୍ କରେ ଏବଂ ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ ସେହି ଚାବିର ପୁଲଗୁଡ଼ିକୁ ଦେଖେ। ପ୍ରତ୍ୟେକ ପୁଲ୍ ପୁଲ୍ ୱିଣ୍ଡୋ ପ୍ରତି ଗୋଟିଏ କାର୍ଡ ଦେଖାଏ, ସମସ୍ତଙ୍କ ପାଇଁ ପୁଲ୍ ବ୍ୟବହାର ଏବଂ ଚାବିର ନିଜସ୍ୱ ଅଂଶ। ପୁଲ୍ର ପ୍ରତ୍ୟେକ ଖାତାର ନିଜସ୍ୱ କାର୍ଡ ଅଛି, ଖାତାର ବ୍ୟବହାର ଏବଂ ଚାବିର ଅଂଶ ସହିତ। ଖାତାର ବ୍ୟବହାର କେବଳ ଦୃଶ୍ୟମାନ ହୁଏ ଯେତେବେଳେ ଚାବି ଆକାଉଣ୍ଟ ତଥ୍ୟ ଦେଖିପାରେ। ପୃଷ୍ଠାଟି ପ୍ରତ୍ୟେକ ଖାତାର ପ୍ରତି-ମଡେଲ ସୀମା ଏବଂ ଚାବିର ନିଜସ୍ୱ ବ୍ୟବହାର ତାଲିକାଭୁକ୍ତ କରେ। ଯେତେବେଳେ ଏକ କାର୍ଯ୍ୟସୂଚୀ ଚାବିକୁ ଅବରୋଧ କରେ ଏକ ବିଜ୍ଞପ୍ତି ଦେଖାଯାଏ। ଏକ କାର୍ଡ ଏହାର ବ୍ୟବହାର ସହିତ ଚାବିର ପ୍ରତି-ମଡେଲ୍ କ୍ୟାପ୍ ତାଲିକାଭୁକ୍ତ କରେ ଏବଂ ପହଞ୍ଚିଥିବା ଚିହ୍ନଗୁଡ଼ିକୁ ଚିହ୍ନିତ କରେ। `{provider}` ହେଉଛି ଏକ ପ୍ରଦାନକାରୀ id କିମ୍ବା ଏହାର ଛଦ୍ମନାମ (`/quota/claude`, `/quota/cc`)। ଏକ ଅଜ୍ଞାତ ପ୍ରଦାନକାରୀ, ଏବଂ ପତାକା ବନ୍ଦ ଥିବାବେଳେ ପ୍ରତ୍ୟେକ `/quota/*` ପଥ, 404 ର ଉତ୍ତର ଦିଅ। ଏକ କଷ୍ଟମ୍ OpenAI- କିମ୍ବା ଆନ୍ଥ୍ରୋପିକ୍-ସୁସଙ୍ଗତ ନୋଡରେ ଥିବା ପୁଲଗୁଡ଼ିକର କ page ଣସି ପୃଷ୍ଠା ନାହିଁ। API ତଥାପି ସେମାନଙ୍କ ପାଇଁ ଉତ୍ତର ଦେଇଥାଏ।

ପୃଷ୍ଠାର କ session ଣସି ଅଧିବେଶନ ନାହିଁ। ଚାବି କେବଳ `GET /api/v1/me/quota/{provider}`, `PATCH /api/v1/me/quota/{provider}` ଏବଂ `GET /api/v1/me/usage` ର `Authorization` ହେଡର୍ ରେ ପଠାଯାଏ, କେବେବି URL ରେ ନୁହେଁ। ସର୍ଭର ଗ୍ରହଣ କରୁଥିବା ଏକ ଚାବିକୁ ଟ୍ୟାବ୍ ର `sessionStorage` ରେ ରଖାଯାଏ। "ଏହି ଡିଭାଇସରେ ମନେରଖ" ସହିତ ଏହା `localStorage` ରେ ରଖାଯାଏ, ଏବଂ "କି ଭୁଲିଯାଅ" ଏହାକୁ ଉଭୟରୁ ଅପସାରଣ କରେ। ସର୍ଭର ପ୍ରତ୍ୟାଖ୍ୟାନ କରୁଥିବା ଏକ ଚାବି ସଂରକ୍ଷଣ ସ୍ଥାନରୁ ଅପସାରିତ ହୋଇଛି।

`consent` ମୋଡରେ ଥିବା ଏକ ପୁଲ୍ ଏକ ending ଣ କାର୍ଡ ଦେଖାଏ। ସେଠାରେ କି ଧାରକ le ଣ ଦେବା ପାଇଁ ଚାବିର ନିଷ୍କ୍ରିୟ ଅଂଶର 0 ରୁ 100 ପର୍ଯ୍ୟନ୍ତ ସମ୍ପୂର୍ଣ୍ଣ ଶତକଡ଼ା ସେଟ୍ କରେ। ସମ୍ମତି କେତେ ଦିନ ପର୍ଯ୍ୟନ୍ତ ରହିଥାଏ, ଧାରକ ମଧ୍ୟ ବାଛିଥାଏ: ବନ୍ଦ ନହେବା ପର୍ଯ୍ୟନ୍ତ, 1 ଘଣ୍ଟା, 8 ଘଣ୍ଟା, 24 ଘଣ୍ଟା, 7 ଦିନ କିମ୍ବା 30 ଦିନ। ସଞ୍ଚୟ କ୍ଷଣରୁ ଏକ ଅବଧି ଗଣନା କରାଯାଏ। ଏକ ସମୟସୀମା ବଳବତ୍ତର ଥିବାବେଳେ ଧାରକ ଏହାକୁ ବଦଳରେ ରଖିପାରିବେ। ଯଦି ସେଭ୍ ପୂର୍ବରୁ ସେହି ସମୟସୀମା ପାସ୍ ହୁଏ, କାର୍ଡ କିଛି ପଠାଏ ନାହିଁ ଏବଂ ଅନ୍ୟ ପସନ୍ଦ ମାଗେ। 0% ସହିତ କ dead ଣସି ସମୟସୀମା ପଠାଯାଏ ନାହିଁ। କାର୍ଡ ଏହାର ଟାଇମ୍ ଜୋନ୍ ନାମିତ ସହିତ ସଂରକ୍ଷିତ ସମୟସୀମା ଦେଖାଏ। ଏକ ସମ୍ମତି ଯାହାର ସମୟସୀମା ଅତିକ୍ରମ କରିସାରିଛି।

ଏକ `hard` କି ପାଇଁ କାର୍ଡ ମଧ୍ୟ ପୁଲ୍ ୱିଣ୍ଡୋରେ ତାଲିକାଭୁକ୍ତ କରେ, ଅନ୍ୟ କିଗୁଡ଼ିକ ବର୍ତ୍ତମାନ ଚାବିକୁ end ଣ ଦେଇଥାଏ। ପ୍ରତ୍ୟେକ ଧାଡି ଏକତ୍ର ଅନ୍ୟ ସମସ୍ତ ଚାବି ପାଇଁ ଗୋଟିଏ ଚିତ୍ର। ଦୁଇଟି ଚାବିର ପୁଲରେ ଏହା ଅନ୍ୟ ଚାବିର ନିଜସ୍ୱ ଚିତ୍ର। ଏକ ଚିତ୍ର ଦୃଶ୍ୟ ରିପୋର୍ଟ କରେ ନାହିଁ ଯେପରି ଉପଲବ୍ଧ ନୁହେଁ, ଶୂନ୍ୟ ନୁହେଁ। `soft` କିମ୍ବା `burst` କି ପାଇଁ କାର୍ଡ କହେ ଯେ କ figure ଣସି ଚିତ୍ର ପ୍ରଯୁଜ୍ୟ ନୁହେଁ।

`saturation` ମୋଡରେ ଥିବା ଏକ ପୁଲ୍ ଯାହାର ଚାବି 0 ରୁ ଅଧିକ ଶତକଡ଼ା ଗଚ୍ଛିତ କରେ କେବଳ ପ୍ରତ୍ୟାହାର ଦେଖାଏ। ଏଥିରେ କୁହାଯାଇଛି ଯେ ଗଚ୍ଛିତ ଶତକଡା କ no ଣସି ପ୍ରଭାବ ନାହିଁ। ଏହାର ପ୍ରତ୍ୟାହାର ବଟନ୍ କ dead ଣସି ସମୟସୀମା ବିନା 0 ପଠାଏ। ସଂରକ୍ଷିତ 0 ସହିତ `saturation` ମୋଡରେ ଥିବା ଏକ ପୁଲ୍ କ ending ଣସି ending ଣ କାର୍ଡ ଦେଖାଏ ନାହିଁ। ଏକ ସେଭ୍ ପରେ, ଏକ କାର୍ଡ ଯାହା ରିଟର୍ନ ଭ୍ୟୁ ଆଉ ପେଜ୍ ର ଦୃଶ୍ୟ ପରିବର୍ତ୍ତନ ନହେବା ପର୍ଯ୍ୟନ୍ତ ଏହାର ମେସେଜ୍ ସହିତ ରହିଥାଏ।

ଧାରକ ସେଭ୍ କିମ୍ବା ପ୍ରତ୍ୟାହାର ନକରିବା ପର୍ଯ୍ୟନ୍ତ କିଛି ସଞ୍ଚୟ ହୁଏ ନାହିଁ। ପ୍ରତ୍ୟେକ ପ୍ରେସ୍ ଗୋଟିଏ `PATCH /api/v1/me/quota/{provider}` ଅନୁରୋଧ ପଠାଏ, ଏବଂ ଦ୍ୱିତୀୟ ପ୍ରେସ୍ କିଛି ବି ପଠାଏ ନାହିଁ ଯେତେବେଳେ ପ୍ରଥମଟି ବିଚାରାଧୀନ ଅଛି। ଶରୀର ଦୃଶ୍ୟ, ଶତକଡ଼ା ଏବଂ ସମୟସୀମା ଠାରୁ ପୁଲ୍ର ଅସ୍ପଷ୍ଟ `ref` ବହନ କରେ। ଏହାର ଉତ୍ତର ହେଉଛି ପୁନ ilt ନିର୍ମାଣ କୋଟା ଦୃଶ୍ୟ, ଏବଂ ପୃଷ୍ଠାଟି ଏହାକୁ ଦ୍ୱିତୀୟ ପ read ଼ିବା ସହିତ ଦେଖାଏ। ଯେତେବେଳେ ଦୁଇଟି ଓଭରଲପ୍ ସେଭ୍ କରେ, ପୃଷ୍ଠାଟି ଶେଷ ଉତ୍ତର ପରେ ଥରେ କୋଟା ପ read େ। ପୃଷ୍ଠା ବ୍ରାଉଜର୍ ଷ୍ଟୋରେଜ୍ ରେ ସମ୍ମତି ରଖେ ନାହିଁ।

HTTP ସ୍ଥିତିରୁ ବାଛିଥିବା ପାଠ୍ୟ ଦ୍ୱାରା କାର୍ଡରେ ଏକ ପ୍ରତ୍ୟାଖ୍ୟାନ ପରିବର୍ତ୍ତନ ବ୍ୟାଖ୍ୟା କରାଯାଇଛି। ତ୍ରୁଟି ଶରୀର ପ read ାଯାଏ ନାହିଁ। ଏକ 401 କହୁଛି ଚାବି ଗ୍ରହଣ କରାଯାଇ ନାହିଁ ଏବଂ କୋଟାକୁ ପୁନ o ଲୋଡ୍ କରେ। ଏକ 403 କହୁଛି ପୁଲ୍ ending ଣ ପରିବର୍ତ୍ତନ ନେଉନାହିଁ ଏବଂ 404 ଟି ପୁଲ୍ ଚାଲିଯାଇଛି ବୋଲି କହିଛି। ଉଭୟ ଏକ ବଟନ୍ ପ୍ରଦାନ କରନ୍ତି ଯାହା କୋଟାକୁ ପୁନ o ଲୋଡ୍ କରେ। ଏକ 400 କିମ୍ବା ଅନ୍ୟ 4xx ଉତ୍ତର ଧାରକକୁ ଶତକଡ଼ା ଏବଂ ସମୟସୀମା ଯାଞ୍ଚ କରିବାକୁ କହିଥାଏ। ଏକ 429 ଧାରକକୁ ଅପେକ୍ଷା କରିବାକୁ କହିଥାଏ, ଯେତେବେଳେ ଉତ୍ତର ସେମାନଙ୍କୁ `Retry-After` ର ସେକେଣ୍ଡ ସହିତ। ଏକ 5xx ଉତ୍ତର, 408 କିମ୍ବା ଏକ ନେଟୱାର୍କ ବିଫଳତା କହୁଛି ପରିବର୍ତ୍ତନ ହୁଏତ ସଞ୍ଚୟ ହୋଇନଥାଇପାରେ ଏବଂ ଟାଇପ୍ ହୋଇଥିବା ମୂଲ୍ୟଗୁଡ଼ିକୁ ରଖିବ। ଚୁକ୍ତିନାମା ବାହାରେ ଏକ ଉତ୍ତର କୋଟା ପୁନ o ଲୋଡ୍ କରେ। ଏକ ବିଫଳ ସଞ୍ଚୟ ଚାବିକୁ ନିଜେ ଅପସାରଣ କରେ ନାହିଁ। ଯେତେବେଳେ ଏହାକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯିବା ପରେ ପୁନ o ଲୋଡ୍ ହୁଏ, ପୃଷ୍ଠାଟି ଯେକ any ଣସି ମନା କରାଯାଇଥିବା ପ read ଼ିବା ପରି ଚାବିକୁ ଅପସାରଣ କରିଥାଏ।

ଥରେ ଏକ ଚାବି ଗ୍ରହଣ ହେବା ପରେ, ପୃଷ୍ଠାଟି ତିନୋଟି ଟ୍ୟାବ୍ ସହିତ ଏକ “ତୁମର ଉପକରଣ ସେଟ୍ ଅପ୍” କାର୍ଡ ଦେଖାଏ। "Claude କୋଡ୍" `~/.claude/settings.json` ପାଇଁ `env` ବ୍ଲକ ଦେଇଥାଏ। "ସେଲ୍" `export` ରେଖା ପରି ସମାନ ଭେରିଏବଲ୍ ଦେଇଥାଏ। "Claude ଡେସ୍କଟପ୍" ଏହାର ତୃତୀୟ-ପକ୍ଷ ଇନଫେରେନ୍ସ ୱିଣ୍ଡୋ ପାଇଁ ମୂଲ୍ୟ ଦେଇଥାଏ। ମଡେଲଗୁଡିକ ହେଉଛି କୋଟା-ସେୟାର ମଡେଲଗୁଡିକ ସେହି ପ୍ରଦାନକାରୀ ପାଇଁ କଲ୍ କରିପାରେ। ଯେତେବେଳେ ଚାବି ସହିତ ସେପରି କ list ଣସି ତାଲିକା ଆସେ ନାହିଁ, ବ୍ଲକ୍ ଏହା ବଦଳରେ ଗେଟୱେ ମଡେଲ ଆବିଷ୍କାରକୁ ଟର୍ନ୍ କରେ। ଗେଟୱେ ଠିକଣା ହେଉଛି ସର୍ଭର ରିପୋର୍ଟଗୁଡିକ (`OMNIROUTE_PUBLIC_API_BASE_URL`, ତାପରେ `OMNIROUTE_PUBLIC_BASE_URL`) ସର୍ବସାଧାରଣ API ଉତ୍ପତ୍ତି। ଯେତେବେଳେ ଉଭୟ ସେଟ୍ ହୋଇନଥାଏ, କାର୍ଡ ଏକ ପ୍ଲେସହୋଲ୍ଡର୍ ଦେଖାଏ ଏବଂ ଧାରକକୁ ବ୍ୟବସ୍ଥାପକଙ୍କୁ ପଚାରିବାକୁ କହିଥାଏ। ଚାବି ଏକ ସ୍ଥାନଧାରୀ ଭାବରେ ଦର୍ଶାଯାଇଛି। "ମୋ ଚାବି ଅନ୍ତର୍ଭୂକ୍ତ କର" ପୁରା ଚାବିକୁ ସ୍କ୍ରିନରେ ଟେକ୍ସଟ୍ ରେ ରଖେ ଏବଂ କେଉଁ କପି ବଟନ୍ କପି କରେ। ବାକ୍ସ ସଫା ନହେବା ପର୍ଯ୍ୟନ୍ତ, ଚାବି ଭୁଲିଯାଏ କିମ୍ବା ବଦଳାଯାଏ, କିମ୍ବା ପୃଷ୍ଠାଟି ନହେବା ପର୍ଯ୍ୟନ୍ତ ତାହା ରହିଥାଏ। କାର୍ଡ କ request ଣସି ଅନୁରୋଧ ପଠାଏ ନାହିଁ ଏବଂ କ file ଣସି ଫାଇଲ୍ ଡାଉନଲୋଡ୍ କରେ ନାହିଁ।

API ମାର୍କ `stale` ପ reading ଼ିବା ସମ୍ଭବତ out ପୁରୁଣା ବୋଲି ଦର୍ଶାଯାଇଛି। `unavailable` ଚିହ୍ନିତ ଏକ ପଠନ ଏହାର କାରଣ ସହିତ ଦେଖାଯାଏ, କେବେ ଶୂନ୍ୟ ନୁହେଁ।

ଶତକଡ଼ା ଯୋଜନା ଉପରେ API ରିପୋର୍ଟ କଲାବେଳେ ପୃଷ୍ଠା ଚାବିର ନିଜସ୍ୱ ଅଂଶ ଆଙ୍କିଥାଏ। ଏଥିରେ କୁହାଯାଇଛି ଯେ ସଂଖ୍ୟା ହେଉଛି ଏକ ଆକଳନ ଏବଂ ଏହାର ଦୁଇଟି ଅଂଶର ନାମକରଣ କରେ। ପ୍ରତି ମଡେଲ୍ ସୀମା କେବଳ ଖାତା ଦେଖାଏ।

ଯେତେବେଳେ ଏକ ୱିଣ୍ଡୋ `members` ବହନ କରେ, ଏହାର କାର୍ଡ ସ୍ଲଟ୍ କ୍ରମରେ ପ୍ରତ୍ୟେକ ସଦସ୍ୟଙ୍କ ପାଇଁ ଗୋଟିଏ ସେଗମେଣ୍ଟ୍ ସହିତ ଏକ ବାର୍ ଦେଖାଏ। ପଚାରୁଥିବା ଚାବିର ବିଭାଗ ଉଚ୍ଚାରଣ ରଙ୍ଗ ବ୍ୟବହାର କରେ। ଥିମର ଚାର୍ଟ ରଙ୍ଗ ମାଧ୍ୟମରେ ଅନ୍ୟ ବିଭାଗଗୁଡିକ ଚକ୍ର। ଏକ ପାଠ୍ୟ କିମ୍ବଦନ୍ତୀ ଏହାର ମୂଲ୍ୟ ସହିତ ପ୍ରତ୍ୟେକ ବିଭାଗକୁ ତାଲିକାଭୁକ୍ତ କରେ, ତେଣୁ ରଙ୍ଗ ଉପରେ କିଛି ନିର୍ଭର କରେ ନାହିଁ। ବିଭାଗଗୁଡିକ `You` କିମ୍ବା `Member N` ଲେବଲ୍ ହୋଇଛି, ଯେଉଁଠାରେ N ହେଉଛି ସ୍ଲଟ୍।

### ପୃଷ୍ଠା ପାଇଁ ଉତ୍ସର୍ଗୀକୃତ ପୋର୍ଟ।

`QUOTA_PANEL_PORT` ଦ୍ୱିତୀୟ ଶ୍ରୋତା ଖୋଲିବ ଯାହା କେବଳ ସ୍ୱୟଂ ସେବା ପୃଷ୍ଠାକୁ ସେବା କରେ। ଭେରିଏବଲ୍ ସେଟ୍ ନହେବା ପର୍ଯ୍ୟନ୍ତ ଏହା ବନ୍ଦ ଅଛି। `QUOTA_PANEL_HOST` ହେଉଛି ବନ୍ଧନ ଠିକଣା ଏବଂ `127.0.0.1` କୁ ଡିଫଲ୍ଟ।

ଶ୍ରୋତା ଏହି ପଥଗୁଡ଼ିକୁ ମୁଖ୍ୟ ବନ୍ଦରକୁ ପଠାନ୍ତି ଏବଂ ଅନ୍ୟାନ୍ୟ ପଥ ପାଇଁ 404 ର ଉତ୍ତର ଦିଅନ୍ତି:

| ପଥ                                                                       | ସେବା କରେ।                             |
| ------------------------------------------------------------------------ | ------------------------------------- |
| `/quota/{provider}`                                                      | ପୃଷ୍ଠା।                               |
| `/api/v1/me/quota/{provider}`, `/v1/me/quota/{provider}`                 | ପୃଷ୍ଠା ପ read ଼ୁଥିବା କୋଟା ଦୃଶ୍ୟ।      |
| `/api/v1/me/usage`, `/v1/me/usage`                                       | ପେଜ୍ ବ୍ୟବହାର ସିରିଜ୍।                  |
| `/_next/static/`                                                         | ବିଲ୍ଡର ସ୍କ୍ରିପ୍ଟ, ଶ yles ଳୀ ଏବଂ ଫଣ୍ଟ। |

`GET` ଏବଂ `HEAD` ଶରୀର ବିନା ରିଲେ। ଏକ ଶରୀର ସହିତ ଗୋଟିଏ ଅନୁରୋଧ ମଧ୍ୟ ରିଲିଜ୍ ହୋଇଛି: କୋଟା ଭ୍ୟୁ ପଥର ଏକ `PATCH`, ଯାହା ଏକ ending ଣ ପସନ୍ଦ ସଞ୍ଚୟ କରିବାକୁ ପୃଷ୍ଠା ପଠାଏ। CONNECT ଅନୁରୋଧ ବ୍ୟତୀତ ଅନ୍ୟ କ method ଣସି ପଦ୍ଧତି 404 ର ଉତ୍ତର ଦେଇଥାଏ, ଯାହାର ସଂଯୋଗ ବିନା ଉତ୍ତର ସହିତ ବନ୍ଦ। ଅନ୍ୟ କ request ଣସି ଅନୁରୋଧ ଯାହା ଏକ ଶରୀର ଘୋଷଣା କରେ 404 ଏବଂ ଏହାର ସଂଯୋଗ ବନ୍ଦ। ଅପଗ୍ରେଡ୍ ଅନୁରୋଧଗୁଡିକ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଇଛି ଏବଂ ସେମାନଙ୍କର ସଂଯୋଗ ବନ୍ଦ ଅଛି। API ପୋର୍ଟ ପରି ଏକ ଡଟ୍ ସେଗମେଣ୍ଟ୍ କିମ୍ବା ଏକ ଖଣ୍ଡ ମାର୍କର୍ ସହିତ ଏକ ପଥ ପ୍ରତ୍ୟାଖ୍ୟାନ। ପ୍ରିଣ୍ଟେବଲ୍ ASCII ବାହାରେ ଏକ ଅକ୍ଷର ସହିତ ଏକ ଅନୁରୋଧ ଲକ୍ଷ୍ୟ। ଟାର୍ଗେଟରେ ଥିବା ଏକ କଞ୍ଚା ନିୟନ୍ତ୍ରଣ ଚରିତ୍ରକୁ ଏହି ପୋର୍ଟର ନିଜସ୍ୱ ଯାଞ୍ଚ ପୂର୍ବରୁ HTTP ପାର୍ସର୍ ଦ୍ୱାରା 400 ଉତ୍ତର ଦିଆଯାଇଛି। ହେଡର୍ସକୁ ଅନୁରୋଧ ଯେ ଏହାର ନିଜସ୍ୱ ବ୍ୟବହାର ପାଇଁ framework ା framework ୍ଚା ଭଣ୍ଡାରଗୁଡ଼ିକ ରିଲିଜ୍ ହୋଇନାହିଁ: `x-middleware-`, `x-invoke-`, `x-nextjs-`, `x-now-` କିମ୍ବା `x-next-` ସହିତ ଆରମ୍ଭ ହେଉଥିବା ନାମ, ଏବଂ `x-matched-path` ଏବଂ `next-resume` ନାମଗୁଡ଼ିକ। ସେଗୁଡିକ ବିନା ଅନୁରୋଧ ରିଲେ। ଏହି ପୋର୍ଟ ମାଧ୍ୟମରେ ଡ୍ୟାସବୋର୍ଡ, ଲଗଇନ୍ ପେଜ୍, ମ୍ୟାନେଜମେଣ୍ଟ API ଏବଂ ଇନଫେରେନ୍ସ ରୁଟ୍ ପହଞ୍ଚିପାରିବ ନାହିଁ।

କ q ଣସି ପାରାମିଟର କିମ୍ବା କେବଳ `charset=utf-8` ସହିତ `PATCH` ନିଶ୍ଚିତ ଭାବରେ `Content-Type: application/json` ବହନ କରିବ। ଏହା ନିଶ୍ଚିତ ଭାବରେ 1 ରୁ 4096 ପର୍ଯ୍ୟନ୍ତ ଗୋଟିଏ `Content-Length` ବହନ କରିବ, ସାଧା ସଂଖ୍ୟା ଭାବରେ ଲିଖିତ, ଏବଂ `Transfer-Encoding` ନାହିଁ। ଏକ `PATCH` ଯାହା ଏହି ନିୟମଗୁଡିକ ମଧ୍ୟରୁ HTTP ଭାଙ୍ଗିଥାଏ 404 ର ଉତ୍ତର ଦେଇଥାଏ। ପୋର୍ଟ ମୁଖ୍ୟ ପୋର୍ଟ ସହିତ ଯୋଗାଯୋଗ କରିବା ପୂର୍ବରୁ ଘୋଷିତ ବାଇଟ୍ ପ read ିଥାଏ ଏବଂ ସେମାନଙ୍କ ପାଇଁ ସର୍ବାଧିକ 5 ସେକେଣ୍ଡ ଅପେକ୍ଷା କରିଥାଏ। ଏକ ଶରୀର ଯାହା ପରେ ସଂପୂର୍ଣ୍ଣ ହୋଇନଥାଏ 404 ର ଉତ୍ତର ଦେଇଥାଏ ଏବଂ ଏହାର ସଂଯୋଗ ବନ୍ଦ ହୋଇଯାଏ। ସେହି କ୍ଷେତ୍ରରେ, କିମ୍ବା ଯେତେବେଳେ ଗ୍ରାହକ ପ୍ରଥମେ ଚାଲିଯାଆନ୍ତି, କିଛି ମୁଖ୍ୟ ପୋର୍ଟରେ ପହଞ୍ଚେ ନାହିଁ। ସମାନ `Content-Length` ସହିତ ବନ୍ଦର ଘୋଷିତ ବାଇଟ୍କୁ ଠିକ୍ ଭାବରେ ରିଲ୍ କରେ। ସେମାନଙ୍କ ପରେ ବାଇଟ୍ ସଂଯୋଗର ପରବର୍ତ୍ତୀ ଅନୁରୋଧ ଭାବରେ ପ read ାଯାଏ। ସାମ୍ନାରେ ଏକ TLS ଓଲଟା ପ୍ରକ୍ସି ନିଶ୍ଚିତ ଭାବରେ `Content-Length` ଅଗ୍ରଗାମୀ କରିବ ଏବଂ ଅନୁରୋଧ ଶରୀରକୁ ପୁନ ch ଖଣ୍ଡ କରିବା ଉଚିତ୍ ନୁହେଁ। ମୁଖ୍ୟ ପୋର୍ଟ, `Authorization` ହେଡର୍ ରେ API କି ଯାଞ୍ଚ କରେ, ଯେପରି `GET` ପାଇଁ।

404 ଶରୀର ହେଉଛି `{"error":"not_found","message":"Not found."}`। ଏକ ବିଫଳ ରିଲେ ଉତ୍ତରଗୁଡିକ 502 (`api_bridge_unavailable`) କିମ୍ବା 504 (`api_bridge_timeout`) ବିନା `detail` କ୍ଷେତ୍ର ସହିତ ଉତ୍ତର ଦେଇଥାଏ।

ଶ୍ରୋତା `QUOTA_SELF_PANEL` ପ read ନ୍ତି ନାହିଁ, ଏବଂ ଏହା ପୃଷ୍ଠା ଟର୍ନ୍ ଅନ୍ କରେ ନାହିଁ। ପତାକା ବନ୍ଦ ଥିବାବେଳେ, ପୃଷ୍ଠା ଏବଂ ଏହାର API ମୁଖ୍ୟ ପୋର୍ଟରେ 404 ଉତ୍ତର ଦେଇଥାଏ, ଏବଂ ଶ୍ରୋତା ସେହି ଉତ୍ତରକୁ ରିଲେ କରନ୍ତି।

ବିକାଶ ସର୍ଭର (`next dev`) ଅଧୀନରେ, ଏହି ପୋର୍ଟ ମାଧ୍ୟମରେ ପୃଷ୍ଠା ଇଣ୍ଟରାକ୍ଟିଭ୍ ହୋଇନଥାଏ। ବିକାଶ ହଟ-ପୁନ o ଲୋଡ୍ ସକେଟ୍ ହେଉଛି ଏକ ଅପଗ୍ରେଡ୍ ଅନୁରୋଧ, ଏବଂ ପୋର୍ଟ ଏହାକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। ବିକାଶ ସମୟରେ ମୁଖ୍ୟ ପୋର୍ଟ ବ୍ୟବହାର କରନ୍ତୁ।

ପୋର୍ଟ ସାଧା HTTP ସେବା କରେ ଏବଂ ପୃଷ୍ଠା API କି ପଠାଏ। ଡିଫଲ୍ଟ ବାଇଣ୍ଡ ଠିକଣା ରଖନ୍ତୁ ଏବଂ ଏହା ଆଗରେ TLS ସହିତ ଏକ ଓଲଟା ପ୍ରକ୍ସି ରଖନ୍ତୁ। ଲୁପ୍ ବ୍ୟାକ୍ ବ୍ୟତୀତ ଏକ ବନ୍ଧନ ଠିକଣା ଏହି ବିଜ୍ notice ପ୍ତି ଲଗ୍ କରେ:

```text
[Quota Panel] Bound to <host>. This port serves plain HTTP and the page sends API keys. Put a TLS reverse proxy in front of it.
```

ଏକ ଲୁପ୍ ବ୍ୟାକ୍ ସାଥୀ ଯାହା କ forward ଣସି ଅଗ୍ରଗାମୀ ହେଡର୍ ପଠାଏ ନାହିଁ, ମୁଖ୍ୟ ବନ୍ଦରରେ ସ୍ଥାନୀୟ ଭାବରେ ଗଣନା କରେ। ତେଣୁ ସମାନ ହୋଷ୍ଟରେ ଥିବା ଏକ ପ୍ରକ୍ସି ନିଶ୍ଚିତ ଭାବରେ `X-Forwarded-For` ପଠାଇବ। ଏକ ବ୍ୟକ୍ତିଗତ ଠିକଣାରେ ଥିବା ଏକ ପ୍ରକ୍ସି ସେହି ହେଡର୍ ପାଇଁ କେବଳ `OMNIROUTE_TRUST_PROXY=private` (କିମ୍ବା `lan`) ସହିତ ବିଶ୍ୱାସ କରାଯାଏ। ଅନ୍ୟ କ pe ଣସି ସାଥୀ ଏହାର ସଂଯୋଗର ଠିକଣା ଦ୍ୱାରା ରିପୋର୍ଟ କରାଯାଇଥାଏ, ଏବଂ ଏହା ପଠାଯାଇଥିବା ଅଗ୍ରଗାମୀ ହେଡର୍ ଗୁଡିକ ଡ୍ରପ୍ ହୋଇଯାଏ।

ଶ୍ରୋତା ଏକ ସମୟରେ ସର୍ବାଧିକ 256 ସଂଯୋଗ ଧାରଣ କରନ୍ତି। ଅନୁରୋଧ ହେଡର୍ ପଠାଇବାକୁ ଜଣେ ଗ୍ରାହକଙ୍କ ପାଖରେ 10 ସେକେଣ୍ଡ ଏବଂ ପୁରା ଅନୁରୋଧ ପଠାଇବାକୁ 30 ସେକେଣ୍ଡ ଅଛି। ଏକ ନିଷ୍କ୍ରିୟ ରଖାଯାଇଥିବା ଜୀବନ୍ତ ସଂଯୋଗ ପ୍ରାୟ 5 ସେକେଣ୍ଡ ପରେ ବନ୍ଦ ହୋଇଯାଏ। 60 ସେକେଣ୍ଡ ପାଇଁ କ activity ଣସି କାର୍ଯ୍ୟକଳାପ ସହିତ ଏକ ସଂଯୋଗ ବନ୍ଦ ଅଛି। ଏହି ମୂଲ୍ୟଗୁଡ଼ିକ ସ୍ଥିର ହୋଇଛି। ସାମ୍ନାରେ ଓଲଟା ପ୍ରକ୍ସି ଉପରେ ସଂଯୋଗ ଏବଂ ହାର ସୀମା ସେଟ୍ କରନ୍ତୁ। ସାମ୍ନାରେ ଏକ ଓଲଟା ପ୍ରକ୍ସି ଏହାର ନିଷ୍କ୍ରିୟ ଅପଷ୍ଟ୍ରିମ୍ ସଂଯୋଗକୁ 5 ସେକେଣ୍ଡରୁ କମ୍ ରଖିବା ଉଚିତ, କିମ୍ବା ପୁନ use ବ୍ୟବହାର ନକରିବା। ମୁଖ୍ୟ ପୋର୍ଟକୁ ରିଲେ API ପୋର୍ଟ (`API_BRIDGE_*`) ର ଅପଷ୍ଟ୍ରିମ୍ ଟାଇମଆଉଟ୍ ବ୍ୟବହାର କରେ।

`API_PORT` ସେଟ୍ ହୋଇନଥିବା ବେଳେ ଶ୍ରୋତା ମଧ୍ୟ ଆରମ୍ଭ ହୁଏ। `QUOTA_PANEL_PORT` ନିଶ୍ଚିତ ଭାବରେ 1 ରୁ 65535 ପର୍ଯ୍ୟନ୍ତ ଏକ ପୋର୍ଟ ହେବା ଆବଶ୍ୟକ, କେବଳ ଅଙ୍କରେ ଲେଖାଯାଇଛି। ଏହା ଡ୍ୟାସବୋର୍ଡ ପୋର୍ଟ ଏବଂ API ପୋର୍ଟ ଠାରୁ ଭିନ୍ନ ହେବା ଜରୁରୀ। ଲାଇଭ୍ WebSocket ସର୍ଭର ଚାଲୁଥିବାବେଳେ, ଏହା ମଧ୍ୟ `LIVE_WS_PORT` (ଡିଫଲ୍ଟ 20132) ଠାରୁ ଭିନ୍ନ ହେବା ଜରୁରୀ। ଅନ୍ୟ କ value ଣସି ମୂଲ୍ୟ କିଛି ଖୋଲିବ ନାହିଁ ଏବଂ ଏକ ଚେତାବନୀ ଲଗ୍ କରେ। ଏକ ପ୍ରତ୍ୟାଖ୍ୟାନ ମୂଲ୍ୟ ବିଷୟରେ ଏକ ଚେତାବନୀ ଭେରିଏବଲ୍ ନାମ କରେ ଏବଂ ମୂଲ୍ୟ ପୁନରାବୃତ୍ତି କରେ ନାହିଁ। ପୂର୍ବରୁ ବ୍ୟବହାର ହେଉଥିବା ଏକ ପୋର୍ଟ କିଛି ଖୋଲିବ ନାହିଁ ଏବଂ ଏହି ଚେତାବନୀକୁ ଲଗ୍ କରେ:

```text
[Quota Panel] Port <port> is already in use. The quota panel port stays off.
```

`OMNIROUTE_BASE_PATH` ସେଟ୍ ସହିତ, ଶ୍ରୋତା ସେହି ଉପସର୍ଗ ତଳେ ଉପରୋକ୍ତ ପ୍ରତ୍ୟେକ ପଥ ଆଶା କରନ୍ତି। ନିର୍ମାଣ ସମୟରେ ଏବଂ ଚାଲିବା ସମୟରେ ସମାନ `OMNIROUTE_BASE_PATH` ବ୍ୟବହାର କରନ୍ତୁ। ଏହାକୁ ଏକ ଅଗ୍ରଣୀ ସ୍ଲାସ୍ ସହିତ ଲେଖନ୍ତୁ ଏବଂ କ trail ଣସି ଟ୍ରେଲିଂ ସ୍ଲାଶ୍ ନାହିଁ, ଉଦାହରଣ ସ୍ୱରୂପ `/omniroute`। `/` ଏବଂ `/omniroute/` ସହିତ ଅନ୍ୟ ଏକ ଆକୃତି, ଏକ ଚେତାବନୀ ସହିତ ବନ୍ଦରକୁ ଛାଡିଦିଏ, ଯଦିଓ ବିଲ୍ଡ ସେହି ଫର୍ମଗୁଡ଼ିକୁ ଗ୍ରହଣ କରେ। ସେହିପରି ଏକ ଆଧାର ପଥ ଯାହାର ପ୍ରଥମ ସେଗମେଣ୍ଟ ଏକ ପ୍ରୟୋଗ ମାର୍ଗର ନାମ ଦେଇଥାଏ: `api`, `v1`, `v1beta`, `_next`, `quota`, `dashboard`, `docs`, `login`, `codex`, `responses`, `anthropic`, `openai`, `v0` କିମ୍ବା `connect`, ଯେକ case ଣସି କ୍ଷେତ୍ରରେ।

ସୀମା:

## DB ସ୍କିମା ସାରାଂଶ

`078`, `079` ଏବଂ `085` ସ୍ଥାନାନ୍ତରଣ ଦ୍ୱାରା ତିନୋଟି ସାରଣୀ ଯୋଗ କରାଯାଇଛି:

- `quota_consumption` — `(apiKeyId, dimensionKey)` ପ୍ରତି 2-ବାଲ୍ଟି କାଉଣ୍ଟର ଗଡ଼ୁଛି।
- `provider_plans` — ମାନୁଆଲ୍ ପ୍ରଦାନକାରୀ ଯୋଜନା ଓଭରବ୍ରିଡ୍ କରେ ( JSON ପ୍ରତି ପରିମାଣ connectionId)।

ସମସ୍ତ ଟେବୁଲ୍ idempotent `CREATE TABLE IF NOT EXISTS` ସ୍ଥାନାନ୍ତରଣ ମାଧ୍ୟମରେ ଯୋଗ କରାଯାଇଛି।

ସମ୍ମତି ଦିଆଯାଇଥିବା ending ଣ ତିନୋଟି ସ୍ତମ୍ଭ ଯୋଗ କରେ: `quota_allocations.lending_percent` (ପୂର୍ଣ୍ଣ ସଂଖ୍ୟା, ଡିଫଲ୍ଟ 0), `quota_allocations.lending_until` (ଯୁଗ ମିଲିସେକେଣ୍ଡ, କିମ୍ବା କ dead ଣସି ସମୟସୀମା ପାଇଁ `NULL` ) ଏବଂ `quota_pools.borrow_mode` (ଡିଫଲ୍ଟ `saturation`)। ଏହାର ସ୍ଥାନାନ୍ତରଣ କେବଳ ଏହି ସ୍ତମ୍ଭଗୁଡ଼ିକୁ ଯୋଡିଥାଏ ଏବଂ କ existing ଣସି ବିଦ୍ୟମାନ ଧାଡି ଲେଖେ ନାହିଁ।

ଶତକଡ଼ା ଆଟ୍ରିବ୍ୟୁସନ୍ ବୁକ୍ `quota_percent_ledger` (ପୁଲ୍ ପ୍ରତି ଗୋଟିଏ ଧାଡି, ଆକାଉଣ୍ଟ୍ ଏବଂ ପ୍ଲାନ୍ ୱିଣ୍ଡୋ) ଏବଂ `quota_percent_ledger_tokens` (ପୁଲ୍ ପ୍ରତି ଗୋଟିଏ ଟୋକେନ୍ କାଉଣ୍ଟର, ଆକାଉଣ୍ଟ୍ ଏବଂ API କି) ଯୋଗ କରିଥାଏ। `src/lib/db/quotaPercentLedger.ts` ସେଗୁଡିକ ପ read ଼େ ଏବଂ ଲେଖେ।
