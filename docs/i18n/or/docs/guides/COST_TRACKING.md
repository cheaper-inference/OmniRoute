## ଏହା କ’ଣ (ଏବଂ କ’ଣ ନୁହେଁ)

OmniRoute ଟୋକନ୍ ସଂଖ୍ୟାକୁ ଏକ ମଡେଲ୍ର ମୂଲ୍ୟ ହାର ସହିତ ଗୁଣ କରି ପ୍ରତ୍ୟେକ ସମାପ୍ତି ପାଇଁ ଅନୁରୋଧ-ପିଛା USD ଖର୍ଚ୍ଚ ନିର୍ଦ୍ଧାରଣ କରେ। ଏହି ସଂଖ୍ୟାଗୁଡ଼ିକ **ଖର୍ଚ୍ଚ** ଡ୍ୟାଶବୋର୍ଡ,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON ରପ୍ତାନି ଏବଂ ପ୍ରତି-API-key ବଜେଟ୍କୁ ପରିଚାଳିତ କରେ।

> **ଡ୍ୟାଶବୋର୍ଡର "ଖର୍ଚ୍ଚ" ଏକ ସଞ୍ଚୟ ଟ୍ରାକର୍, ବିଲ୍ ନୁହେଁ।** OmniRoute କେବେବି ଆପଣଙ୍କଠାରୁ ଶୁଳ୍କ ନିଏ ନାହିଁ
> — ଏହା ଆପଣଙ୍କ ଅନୁରୋଧଗୁଡ଼ିକୁ ଆପଣ ପୂର୍ବରୁ ସଂଯୋଗ କରିଥିବା ପ୍ରଦାନକାରୀଙ୍କ ପାଖକୁ ରୁଟ୍ କରେ (ଆପଣଙ୍କ ନିଜସ୍ୱ
> ସବ୍ସ୍କ୍ରିପ୍ସନ୍, ମାଗଣା ସ୍ତର ଏବଂ API keyଗୁଡ଼ିକ)। ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ମାଗଣା
> ମଡେଲ୍ଗୁଡ଼ିକରେ ସଞ୍ଚିତ "$290 total cost"ର ଅର୍ଥ ହେଉଛି ପ୍ରାୟ **$290 ଯାହା ଆପଣ ଏକ ଦେୟ APIକୁ ଦେଇ _ନାହାନ୍ତି_**। ଏହି ଅଙ୍କଟି ସମାନ ଟ୍ରାଫିକ୍ର ମାନକ ତାଲିକା ମୂଲ୍ୟ ଅନୁସାରେ ସମ୍ଭାବ୍ୟ ଖର୍ଚ୍ଚର ଏକ _ଆକଳନ_,
> ଯାହାଦ୍ୱାରା ଆପଣଙ୍କ ବ୍ୟବହାର କେଉଁଠି କେନ୍ଦ୍ରୀଭୂତ ଏବଂ ଶସ୍ତା/ମାଗଣା ପ୍ରଦାନକାରୀଙ୍କୁ ରୁଟ୍ କରିବା ଦ୍ୱାରା ଆପଣ କେତେ ସଞ୍ଚୟ କରୁଛନ୍ତି ତାହା ଦେଖିପାରିବେ।

ଏହି ବ୍ୟାଖ୍ୟା ପ୍ରକଳ୍ପର [README](../../README.md)ରେ ସିଧାସଳଖ ଭାବେ ଉଲ୍ଲେଖ କରାଯାଇଛି ("ଡ୍ୟାଶବୋର୍ଡର
'ଖର୍ଚ୍ଚ' ଏକ ସଞ୍ଚୟ ଟ୍ରାକର୍, ବିଲ୍ ନୁହେଁ")।

ସଂଖ୍ୟାଟି ଏକ ଆକଳନ ହୋଇଥିବାରୁ:

- ଏହା ପ୍ରତ୍ୟେକ ମଡେଲ୍ ପାଇଁ OmniRoute ପାଖରେ ଥିବା ମୂଲ୍ୟ ତାଲିକା ଉପରେ ନିର୍ଭର କରେ। ମୂଲ୍ୟ
  ଏଣ୍ଟ୍ରି ନଥିବା ମଡେଲ୍ `0` ଖର୍ଚ୍ଚ ଯୋଗ କରେ (ଏହା ଏକ୍ସପ୍ଲୋରର୍ରେ "ପୁରୁଣା / ମାଗଣା" ଧାଡ଼ି ଭାବେ ଦେଖାଯାଏ)।
- ମାଗଣା-ସ୍ତର ଏବଂ ସବ୍ସ୍କ୍ରିପ୍ସନ୍ ଟ୍ରାଫିକ୍ରେ ମଧ୍ୟ ଏକ _ଆନୁମାନିକ_ ଖର୍ଚ୍ଚ ସଞ୍ଚିତ ହୁଏ — ଏହା
  ଆପଣ ସଞ୍ଚୟ କରୁଥିବା ରାଶି, ଦେୟ ରାଶି ନୁହେଁ।

## ଖର୍ଚ୍ଚ କିପରି ଆକଳନ କରାଯାଏ।

### ମୂଲ୍ୟ ଉତ୍ସ

ମୂଲ୍ୟଗୁଡିକ [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) ରେ ମିଶ୍ରିତ ମୂଲ୍ୟ ସାରଣୀରୁ ଆସିଥାଏ, ଏହି କ୍ରମରେ (**ସର୍ବୋଚ୍ଚ ପ୍ରଥମ** ):

1. **ଉପଯୋଗକର୍ତ୍ତା ନବଲିଖନ କରନ୍ତି।** — ମୂଲ୍ୟ ଡ୍ୟାସବୋର୍ଡରେ କିମ୍ବା `PATCH /api/pricing` ( `pricing` ନାମ ସ୍ଥାନ) ମାଧ୍ୟମରେ ସେଟ୍ ହୋଇଛି।
2. **models.dev ସିଙ୍କ୍।** — ମୂଲ୍ୟ `https://models.dev/api.json` ( `models_dev_pricing` ନାମ ସ୍ଥାନ) ରୁ ଅଣାଯାଇଥିଲା।
3. **LiteLLM ସିଙ୍କ୍।** — ମୂଲ୍ୟ LiteLLM ର ସର୍ବସାଧାରଣ `model_prices_and_context_window.json` ( `pricing_synced` ନାମ ସ୍ଥାନ) ରୁ ଅଣାଯାଇଥିଲା।
4. **ହାର୍ଡକୋଡ୍ ଡିଫଲ୍ଟ।** [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) ରେ — ହାର ପଠାଯାଇଛି।

ସମାନ provider/model ପାଇଁ, ଉଚ୍ଚ-ପ୍ରାଥମିକ ସ୍ତରରୁ ମୂଲ୍ୟଗୁଡ଼ିକ ନିମ୍ନ ସ୍ତରରେ ମେଳ ଖାଉଥିବା କ୍ଷେତ୍ରଗୁଡ଼ିକୁ ନବଲିଖନ କରେ। ଏକ ଉପର ସ୍ତରରୁ ଅନୁପସ୍ଥିତ କ୍ଷେତ୍ରଗୁଡିକ ଏକ ନିମ୍ନ ସ୍ତରରୁ ଆସିପାରେ। ଉଭୟ ସ୍ independent ାଧୀନ ସିଙ୍କ କାର୍ଯ୍ୟ ଏକ ସମୟରେ ଚାଲୁଥିଲେ ମଧ୍ୟ କ୍ରମ ସ୍ଥିର ହୋଇଛି। `GET /api/pricing?includeSources=1` `pricing` ଏବଂ `sourceMap` ଫେରସ୍ତ କରେ, ଯାହାର ପ୍ରତି-ମଡେଲ୍ ଲେବଲ୍ (`user`, `modelsDev`, `litellm`, `default`) ସେହି ମଡେଲ୍ ଧାରଣ କରିଥିବା ସର୍ବୋଚ୍ଚ-ପ୍ରାଥମିକ ସ୍ତର ଚିହ୍ନଟ କରେ।

**LiteLLM ସିଙ୍କ୍।** ଡିଫଲ୍ଟ ଭାବରେ ଅପ୍ଟ-ଇନ୍ ଅଟେ। ଏହାର ପରିବେଶ ଭେରିଏବଲ୍ ( [`.env.example`](../../.env.example) ଦେଖନ୍ତୁ) ହେଉଛି:

| Env var                 | ଡିଫଲ୍ଟ।   | ଉଦ୍ଦେଶ୍ୟ                                                       |
| ----------------------- | --------- | -------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | ପୃଷ୍ଠଭୂମି LiteLLM ମୂଲ୍ୟ ସିଙ୍କ୍ ସକ୍ଷମ କରନ୍ତୁ।                   |
| `PRICING_SYNC_INTERVAL` | `86400`   | ସେକେଣ୍ଡରେ ବ୍ୟବଧାନ (ଦ daily ନିକ)।                               |
| `PRICING_SYNC_SOURCES`  | `litellm` | କେବଳ ଏହି ସିଙ୍କ ପାଇଁ ଉତ୍ସ ଚୟନ; ସମ୍ପ୍ରତି କେବଳ `litellm` ସମର୍ଥିତ। |

**models.dev ସିଙ୍କ୍।** LiteLLM ସିଙ୍କ ଠାରୁ ଅଲଗା ଏବଂ ଡିଫଲ୍ଟ ଭାବରେ ଅକ୍ଷମ ଅଟେ। ଏହାକୁ ସେଟିଂସମୂହରେ ସକ୍ଷମ କରନ୍ତୁ (models.dev sync) କିମ୍ବା ଏହି ଭେରିଏବଲ୍ ବ୍ୟବହାର କରନ୍ତୁ:

| Env var                    | ଡିଫଲ୍ଟ।    | ଉଦ୍ଦେଶ୍ୟ                                                                                                               |
| -------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _ (ସେଟ୍) _ | ସେଟିଂସମୂହ ଟୋଗଲ୍ ଅନୁସରଣ କରନ୍ତୁ; `1/true/on/yes` ଫୋର୍ସ ଏବଂ `0/false/off/no` ଫୋର୍ସ ବନ୍ଦ (ଯଦିଓ ସେଟିଂସମୂହ ଏହାକୁ ସକ୍ଷମ କରେ)। |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`    | ଡିଫଲ୍ଟ ମଡେଲଗୁଡିକ .dev ସେକେଣ୍ଡରେ ବ୍ୟବଧାନ (ଦ daily ନିକ)।                                                                 |

`PRICING_SYNC_SOURCES` କରେ।**ନୁହେଁ** models.dev ସକ୍ଷମ କରନ୍ତୁ; ଏହା କେବଳ LiteLLM ସିଙ୍କ୍କୁ ନିୟନ୍ତ୍ରଣ କରେ। ଏକ ୟୁଜର୍ ଓଭରବାଇଡ୍ ଡିଲିଟ୍ କରିବା ସିଙ୍କ୍ ହୋଇଥିବା ନାମ ସ୍ପେସ୍ ସଫା କରେ ନାହିଁ। ପରବର୍ତ୍ତୀ ଉପଲବ୍ଧ ମୂଲ୍ୟ ସ୍ତର ପ୍ରଭାବଶାଳୀ ହୁଏ। ଏକ ମୂଲ୍ୟହୀନ ମଡେଲ୍ ପାଇଁ, ଏକ ମାନୁଆଲ୍ ଓଭରବ୍ରିଡ୍ ଯୋଡିବା ପୂର୍ବରୁ ଉଭୟ ସିଙ୍କ ସେଟିଂସମୂହ ଏବଂ `sourceMap` ଯାଞ୍ଚ କରନ୍ତୁ।

### ମୂଲ୍ୟ ସୂତ୍ର

ଟୋକେନ୍ ଗଣନା ଏବଂ [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`) ରେ ପ୍ରତି ମିଲିୟନ୍ ଟୋକେନ୍ ହାରରୁ ଅନୁରୋଧ ଅନୁଯାୟୀ ମୂଲ୍ୟ ଗଣନା କରାଯାଏ:

- **ଇନପୁଟ୍ ଟୋକେନ୍।** (ମାଇନସ୍ କ୍ୟାଚ୍ ପ read ଼େ ଏବଂ କ୍ୟାଚ୍-ସୃଷ୍ଟି ଟୋକେନ୍) × `input` ହାର।
- **କ୍ୟାଚ୍-ପ read ଼ୁଥିବା ଟୋକେନ୍।** × `cached` ହାର (ଇନପୁଟ୍ ହାରକୁ ଫେରିଯାଏ)।
- **କ୍ୟାଚ୍-ସୃଷ୍ଟି ଟୋକେନ୍।** × `cache_creation` ହାର (ଇନପୁଟ୍ ହାରକୁ ଫେରିଯାଏ)।
- **ଆଉଟପୁଟ୍ ଟୋକେନ୍।** × `output` ହାର।
- **ଟୋକେନ୍ଗୁଡ଼ିକର କାରଣ** × `reasoning` ହାର (ଆଉଟପୁଟ୍ ହାରକୁ ଫେରିଯାଏ)।

ସମସ୍ତ ହାରକୁ 1,000,000 ଟୋକେନ୍ ପ୍ରତି USD ଭାବରେ ବ୍ୟାଖ୍ୟା କରାଯାଇଛି। ଏକ Codex "ଦ୍ରୁତ" / "ପ୍ରାଥମିକତା" କିମ୍ବା "ଫ୍ଲେକ୍ସ" ସେବା ସ୍ତର ଏକ ମୂଲ୍ୟ ଗୁଣକର୍ତ୍ତା (`getCodexFastCostMultiplier`) ପ୍ରୟୋଗ କରେ — ଯଥା ଫ୍ଲେକ୍ସ 50% ଟୋକେନ୍ ରିହାତିରେ ବିଲ୍ ହୋଇଛି, ଯେପରି ଏହା ସାମ୍ନାକୁ ଆସିଛି।**ଫ୍ଲେକ୍ସ ସଞ୍ଚୟ।** ଡ୍ୟାସବୋର୍ଡରେ।

ପ୍ରଥମେ ମଡେଲ୍ ନାମଗୁଡିକ ସ୍ ized ାଭାବିକ ହୋଇଛି (ପ୍ରଦାନକାରୀ-ପଥ ଉପସର୍ଗ ଯେପରିକି `openai/` କିମ୍ବା `accounts/fireworks/models/` ଛଡ଼ାଯାଇଛି) ତେଣୁ historical ତିହାସିକ ଧାଡିଗୁଡ଼ିକ ଏକ ମୂଲ୍ୟ ସହିତ ମେଳ ଖାଉଛି।

### କିପରି ଖର୍ଚ୍ଚ ରେକର୍ଡ ହୋଇଛି।

- ଅନୁରୋଧ ସମାପ୍ତି ସମୟରେ ପ୍ରତି-ଅନୁରୋଧ ମୂଲ୍ୟ ଗଣନା କରାଯାଏ। [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) ମାଧ୍ୟମରେ ପରବର୍ତ୍ତୀ ଇଭେଣ୍ଟ-ଲୁପ୍ ଟିକ୍ ରେ ଅଂଶୀଦାର-କୋଟା ବ୍ୟବହାର ଧାର୍ଯ୍ୟ କରାଯାଇଛି।
- API- କି ଖର୍ଚ୍ଚକୁ [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (ଡିଫଲ୍ଟ s ୦ ଦଶକର ଫ୍ଲାଶ୍ ବ୍ୟବଧାନ, 1,000-ପ୍ରବେଶ ବଫର୍) ଦ୍ୱାରା ବ୍ୟାଚ୍ ଏବଂ ଫ୍ଲାଶ୍ କରାଯାଏ। ମାଧ୍ୟମରେ ଟ୍ୟୁନେବଲ୍:

  | Env var                             | ଡିଫଲ୍ଟ। | ଉଦ୍ଦେଶ୍ୟ                                    |
  | ----------------------------------- | ------- | ------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | ମିଲିସେକେଣ୍ଡରେ ଫ୍ଲାସ୍ ବ୍ୟବଧାନ।               |

ମୂଲ୍ୟଗୁଡିକ ଏକ ସଠିକ୍ ପ୍ରଦାନକାରୀ-ରିପୋର୍ଟ ହୋଇଥିବା ଚାର୍ଜ (`provider_cost_usd`) କୁ ପସନ୍ଦ କରେ, ତାପରେ ଏକ କାଟାଲଗ୍-ମୂଲ୍ୟର ଅନୁରୋଧ ସ୍ନାପସଟ୍ (`calculated_cost_usd`), ତାପରେ ସାମ୍ପ୍ରତିକ କାଟାଲଗ୍ ରୁ ଟୋକେନ୍ ପୁନ icing ପ୍ରକାଶ। ଗଚ୍ଛିତ ଖର୍ଚ୍ଚ ସେମାନଙ୍କ ଟୋକେନ୍ ଗଣନା ମାଧ୍ୟମରେ ପୁନର୍ବାର ଚାର୍ଜ କରାଯାଏ ନାହିଁ। ପୁରୁଣା ଟୋକେନ୍-କେବଳ ଧାଡିଗୁଡ଼ିକ ଯେତେବେଳେ ସେମାନଙ୍କର କାଟାଲଗ୍ ମୂଲ୍ୟ ପରିବର୍ତ୍ତନ ହୁଏ ସେତେବେଳେ ପରିବର୍ତ୍ତନ ହୁଏ।

### OCR ଏବଂ ଏମ୍ବେଡିଂ।

- ସଫଳ `/v1/ocr` ଅନୁରୋଧ ଅପଷ୍ଟ୍ରିମ `usage_info.pages_processed` ବ୍ୟବହାର କରେ, ଅନୁରୋଧ କରାଯାଇଥିବା ପୃଷ୍ଠା ପରିସର କିମ୍ବା ଫେରସ୍ତ ପୃଷ୍ଠା ବସ୍ତୁର ସଂଖ୍ୟା ନୁହେଁ। ଆକଳନ ହେଉଛି ପୃଷ୍ଠାଗୁଡ଼ିକ × `ocr_cost_per_page` (ସଂପୂର୍ଣ୍ଣ USD/page,**ନୁହେଁ** USD/million)।
- ଡକ୍ୟୁମେଣ୍ଟ୍ କିମ୍ବା ବନ୍ଧନ-ବାକ୍ସ ଟିପ୍ପଣୀ ସହିତ ଅନୁରୋଧଗୁଡିକ ଏକ ପୃଥକ `ocr_cost_per_annotated_page` ଶୁଳ୍କ ଆବଶ୍ୟକ କରେ। ଏହା ବିନା, ମୂଲ୍ୟ ଅଜ୍ଞାତ ହୋଇ ରହିଥାଏ; ସାଧାରଣ OCR ଶୁଳ୍କ ଚୁପଚାପ୍ ବଦଳାଯାଏ ନାହିଁ।
- LiteLLM ସିଙ୍କ ଏହାର ଅପଷ୍ଟ୍ରିମ `annotation_cost_per_page` କ୍ଷେତ୍ରକୁ `ocr_cost_per_annotated_page` ରେ ମାନଚିତ୍ର କରେ, ସଂପୂର୍ଣ୍ଣ USD/page ମୂଲ୍ୟ ଏବଂ ସ୍ପଷ୍ଟୀକରଣ ଶୂନକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରି କେବଳ ଟିପ୍ପଣୀ-ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ ବଜାୟ ରଖେ। ଏକ ଯୋଗାଇ ଦିଆଯାଇଥିବା କାନୋନିକାଲ୍ କ୍ଷେତ୍ର ପ୍ରାଧାନ୍ୟ ଦେଇଥାଏ; ଅବ alid ଧ ଛଦ୍ମନାମ ମୂଲ୍ୟକୁ ଅଣଦେଖା କରାଯାଏ। ଉପଭୋକ୍ତା ମୂଲ୍ୟ ନିର୍ଧାରଣ ସେମାନଙ୍କର ସାଧାରଣ ପ୍ରାଥମିକତା ବଜାୟ ରଖେ। [LiteLLM ର OCR ମୂଲ୍ୟ କୀ](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) ଦେଖନ୍ତୁ।
- OCR ବ୍ୟବହାର ପୃଷ୍ଠା ଗଣନା, ଏକକ ମୂଲ୍ୟ, ଗଣିତ USD ମୂଲ୍ୟ, API କି ଏବଂ ମନୋନୀତ ସଂଯୋଗକୁ ସଂରକ୍ଷଣ କରେ। ପୃଷ୍ଠାଗୁଡ଼ିକ କେବେବି ଟୋକେନ୍ ଭାବରେ ଉପସ୍ଥାପିତ ହୁଏ ନାହିଁ। କଲ୍ ଲଗ୍ ବିଲିଂ ମେଟାଡାଟା ଧାରଣ କରିଥାଏ, URLs, PDF ବାଇଟ୍ କିମ୍ବା ବାହାର କରାଯାଇଥିବା ପାଠ୍ୟକୁ ଡକ୍ୟୁମେଣ୍ଟ୍ କରେ ନାହିଁ।
- ସଫଳ `/v1/embeddings` ଅନୁରୋଧଗୁଡିକ ସମାନ ମିଲିସେକେଣ୍ଡରେ ସମାପ୍ତ ହୋଇଥିବା ପୃଥକ ବ୍ୟାଚ୍ ଅନ୍ତର୍ଭୂକ୍ତ କରି ଶାରୀରିକ ବ୍ୟାଚ୍ ପ୍ରତି ଗୋଟିଏ ବ୍ୟବହାର ଧାଡି ରେକର୍ଡ କରେ। ପ୍ରଦାନକାରୀ-ରିପୋର୍ଟ ଚାର୍ଜଗୁଡିକ ଟୋକେନ୍ ଆକଳନ ଉପରେ ପ୍ରାଧାନ୍ୟ ଦେଇଥାଏ; କମ୍ବୋ ରାପର୍ଗୁଡ଼ିକ ଏକ ଚାର୍ଜ ଯୋଗ କରନ୍ତି ନାହିଁ।
- ବ୍ୟବହାର ଇତିହାସ, ଖର୍ଚ୍ଚ ଆନାଲିଟିକ୍ସ, provider/account ୱିଣ୍ଡୋ, API- କି ଖର୍ଚ୍ଚ ସୀମା, ଅନୁରୋଧ-ମୂଲ୍ୟ ଲିଜର୍ ଏବଂ ଦ daily ନିକ ବ୍ୟବହାର ରୋଲଅପ୍ ଏହି ଚାର୍ଜଗୁଡ଼ିକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ। ନୋ-ଲଗ୍ କିଗୁଡ଼ିକ ଉତ୍ସ ପାଠ୍ୟକୁ ନ ରଖି ସାଂଖ୍ୟିକ ହିସାବ ରଖେ।
- ନିଖୋଜ ବ୍ୟବହାର କିମ୍ବା ଶୁଳ୍କ ହେଉଛି।**ଅଜ୍ଞାତ** , ମାଗଣା ନୁହେଁ: ପ୍ରତିକ୍ରିୟା-ମୂଲ୍ୟ ହେଡର୍ ବାଦ ଦିଆଯାଇଛି, ଏବଂ ବିଦ୍ୟମାନ ମୂଲ୍ୟହୀନ ବ୍ୟବହାର ନୀତି ସୀମିତ API କିଗୁଡ଼ିକ ପାଇଁ ପ୍ରଯୁଜ୍ୟ। ସ୍ପଷ୍ଟ ଭାବରେ ବିନ୍ୟାସିତ ଶୂନ ହାର ବ valid ଧ ଶୂନ-ମୂଲ୍ୟ ବ୍ୟବହାର ରହିଥାଏ।

ଏହା କେବଳ ଅଗ୍ରଗାମୀ ହିସାବ। ପୁରୁଣା OCR/embedding କଲ୍ ଯାହା ବ୍ୟବହାର ଇତିହାସ ଲେଖି ନାହିଁ ଏହି ସ୍ଥାନାନ୍ତରଣରୁ ପୁନ str ନିର୍ମାଣ ହୋଇପାରିବ ନାହିଁ। କାଟାଲଗ୍ ଆକଳନ ହେଉଛି USD ଆକଳନ, ଏକ ଇନଭଏସ୍ ନୁହେଁ, ଏବଂ ମୁଦ୍ରା ରୂପାନ୍ତର, ଟିକସ କିମ୍ବା ରିହାତି ଅନ୍ତର୍ଭୂକ୍ତ କରେ ନାହିଁ।

- ପ୍ରଦାନକାରୀ-ରିପୋର୍ଟ ହୋଇଥିବା USD ଏକ କାଟାଲଗ୍ ଆକଳନ ଉପରେ ଜିତିଥାଏ, ଏକ ସ୍ପଷ୍ଟ ଶୂନ ଚାର୍ଜକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରି। OpenRouter ର JSON `usage.cost` `cost_usd` କୁ ସ୍ୱାଭାବିକ ହୋଇଛି। ଅନ୍ୟଥା, ମାପାଯାଇଥିବା ଟୋକେନ୍ଗୁଡ଼ିକ ଟୋକେନ୍ ମୂଲ୍ୟ ବ୍ୟବହାର କରେ, ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ସେକେଣ୍ଡ୍ ପ୍ରତି ସେକେଣ୍ଡ୍ ମୂଲ୍ୟ ବ୍ୟବହାର କରେ, ବକ୍ତବ୍ୟ ଇନପୁଟ୍ ୟୁନିକୋଡ୍ ବର୍ଣ୍ଣ ଗଣନା ବ୍ୟବହାର କରେ, ଏବଂ ଫ୍ଲାଟ-ମୂଲ୍ୟ ଚିତ୍ରଗୁଡ଼ିକ ପ୍ରକୃତରେ ଫେରିଥିବା ସଂଖ୍ୟାକୁ ବ୍ୟବହାର କରେ, ଅନୁରୋଧ କରାଯାଇଥିବା `n` ନୁହେଁ।
- ବାଇନାରୀ OpenRouter TTS କ JSON ବ୍ୟବହାର ଶରୀର ନାହିଁ। ଅଡିଓ ସମାପ୍ତ ହେବା ପରେ କିମ୍ବା କଲର୍ ବାତିଲ୍ ହେବା ପରେ, OmniRoute ଏହାର ପି generation ଼ି ID ପଚାରିଥାଏ।**ସମାନ** OpenRouter ଉତ୍ପତ୍ତି ବିନ୍ୟାସିତ। ଏକ EU ଅନୁରୋଧ କଦାପି ବିଶ୍ global ର ମୂଳ ସ୍ଥାନକୁ ଫେରିବ ନାହିଁ। ଏହା ଏକ ସୀମିତ, କେବଳ ପଠନୀୟ ସନ୍ଧାନ; ହିସାବ ପାଇଁ ସିନ୍ଥେସିସ୍ ପୁନ ret ଚେଷ୍ଟା କରାଯାଏ ନାହିଁ। ଅଡିଓ ସମାପ୍ତ ହେବା ପରେ ବିଲିଂ ରେକର୍ଡଗୁଡିକ ଦୃଶ୍ୟମାନ ହୋଇପାରେ: ନେଟୱାର୍କର ସମୟସୀମା ଅନ୍ତର୍ଭୂକ୍ତ କରି ପ୍ରାୟ 52 ସେକେଣ୍ଡ ପର୍ଯ୍ୟନ୍ତ ବ୍ୟାକଗ୍ରାଉଣ୍ଡରେ ଲୁକ୍ଅପ୍ ପୁନ ries ଚେଷ୍ଟା ଚାଲିଥାଏ।
- ସେହି ସନ୍ଧାନ ସମୟରେ, ଅଡିଓ ପ୍ରତିକ୍ରିୟାରେ `X-OmniRoute-Cost-Status: pending` ଅଛି ଏବଂ କ response ଣସି ପ୍ରତିକ୍ରିୟା-ମୂଲ୍ୟ ହେଡର୍ ନାହିଁ। ଏହାର ଅନ୍ତିମ ଚାର୍ଜ ବ୍ୟବହାର ଇତିହାସ, ଆନାଲିଟିକ୍ସ ଏବଂ ପୁନ iliation ସମନ୍ୱୟ ପରେ କି ଲିଜରରେ ଦେଖାଯାଏ। ଯଦି ମେଟାଡାଟା ଉପଲବ୍ଧ ନାହିଁ, ଏକ ବିନ୍ୟାସିତ ଶୁଳ୍କ ସ୍ନାପସଟ୍ ବ୍ୟବହୃତ ହୁଏ। ଅନ୍ୟଥା ମୂଲ୍ୟ ଅଜ୍ଞାତ ରହିଥାଏ।
- ସେକେଣ୍ଡ, ଅକ୍ଷର ଏବଂ ପ୍ରତିଛବି ଗଣନାରେ ଅଲଗା ବିଲିଂ-ୟୁନିଟ୍ ଫିଲ୍ଡ ଅଛି, କଦାପି ନକଲି ଟୋକେନ୍ ଗଣନା। ଆକାଉଣ୍ଟିଂ କେବଳ ସାଂଖ୍ୟିକ ବ୍ୟବହାର ବଜାୟ ରଖେ, ବକ୍ତବ୍ୟ ପାଠ୍ୟ, ଟ୍ରାନ୍ସକ୍ରିପସନ୍ କିମ୍ବା ଇମେଜ୍ ବାଇଟ୍ ନୁହେଁ। ବିଦ୍ୟମାନ ମୂଲ୍ୟହୀନ-ପ୍ରତିଛବି ଛାଡଗୁଡିକ ଅପରିବର୍ତ୍ତିତ: ଏକ ପ୍ରକୃତ ଅନୁପସ୍ଥିତ ପ୍ରତିଛବି ଶୁଳ୍କ ଏକ ସୀମିତ ଚାବିକୁ ଲକ୍ କରେ ନାହିଁ, ଏବଂ ପ୍ରତିକ୍ରିୟା କଲ୍ ମୁକ୍ତ ଘୋଷଣା କରିବା ପରିବର୍ତ୍ତେ ମୂଲ୍ୟ ହେଡର୍ ଛାଡିଦିଏ। ଏକ ମୂଲ୍ୟ ଷ୍ଟୋର ବିଫଳତା ବିଫଳ-ବନ୍ଦ କାର୍ଯ୍ୟକାରିତା ପାଇଁ ବ୍ୟବହାର ପ୍ରମାଣକୁ ବଜାୟ ରଖିଛି।

କ historical ଣସି historical ତିହାସିକ speech/image ଚାର୍ଜ ଉଦ୍ଭାବନ କିମ୍ବା ବ୍ୟାକଫିଲ୍ ହୋଇନାହିଁ। ପ୍ରଦାନକାରୀ ବିଲିଂ ଇନଭଏସ୍ ଏବଂ କଲ୍ ପାଇଁ ରେଫରେନ୍ସ ହୋଇ ରହିଥାଏ ଯାହାର ଚାର୍ଜ ରିପୋର୍ଟ ହୋଇନଥିଲା।

## ଡ୍ୟାଶବୋର୍ଡ: ଖର୍ଚ୍ଚ ପୃଷ୍ଠା

  ଅନୁରୋଧର ହାରାହାରି ଖର୍ଚ୍ଚ ଏବଂ ମୋଟର ଅଂଶ % ରହିଛି।

- **ଅବଧି ତୁଳନା** — ଅବଧିର ପ୍ରଥମ ଏବଂ ଦ୍ୱିତୀୟ ଅର୍ଦ୍ଧ ମଧ୍ୟରେ % ପରିବର୍ତ୍ତନ।
- **ଚାର୍ଟଗୁଡ଼ିକ** — ଦୈନିକ ଖର୍ଚ୍ଚ ଧାରା, ପ୍ରଦାନକାରୀଙ୍କ ଅଂଶ (ପାଇ), ଶୀର୍ଷ ପ୍ରଦାନକାରୀ, ଶୀର୍ଷ ମଡେଲ୍, API କୀ
  ଅନୁଯାୟୀ ଖର୍ଚ୍ଚ, ଆକାଉଣ୍ଟ ଅନୁଯାୟୀ ଖର୍ଚ୍ଚ, ସାପ୍ତାହିକ ବ୍ୟବହାର ପ୍ୟାଟର୍ନ ଏବଂ ଏକ କାର୍ଯ୍ୟକଳାପ ହିଟ୍ମ୍ୟାପ୍।

## CLI

OmniRouteର CLI ଖର୍ଚ୍ଚ, ବ୍ୟବହାର ଏବଂ ମୂଲ୍ୟ ନିର୍ଦ୍ଧାରଣ କମାଣ୍ଡଗୁଡ଼ିକୁ ଉପଲବ୍ଧ କରାଏ ([`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)ରେ ପଞ୍ଜୀକୃତ)।

### `omniroute cost`

`/api/usage/analytics`ରୁ ସଂଗୃହୀତ ଏକ ଖର୍ଚ୍ଚ ରିପୋର୍ଟ।

```bash
omniroute cost                          # ଗତ 30d, provider ଅନୁଯାୟୀ ଗୋଷ୍ଠୀଭୁକ୍ତ
omniroute cost --period 7d              # ଗତ 7 ଦିନ
omniroute cost --group-by model         # provider | model | combo | api-key | day ଅନୁଯାୟୀ ଗୋଷ୍ଠୀଭୁକ୍ତ କରନ୍ତୁ
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ସ୍ତମ୍ଭଗୁଡ଼ିକ: ଗୋଷ୍ଠୀ, ଅନୁରୋଧ, ଇନପୁଟ୍/ଆଉଟପୁଟ୍ ଟୋକେନ୍, ଖର୍ଚ୍ଚ (USD), ଏବଂ ମୋଟର ପ୍ରତିଶତ। ଶେଷରେ ଏକ ସର୍ବମୋଟ ପଙ୍କ୍ତି
ମୁଦ୍ରିତ ହୁଏ (`--quiet` କିମ୍ବା `--output json` ଦ୍ୱାରା ଏହାକୁ ଲୁଚାଯାଏ)।

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ପ୍ରତି-provider ଖର୍ଚ୍ଚ ସାରାଂଶ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ବଜେଟ୍ଗୁଡ଼ିକ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`, `GET /api/pricing/defaults`ରୁ ପଢ଼େ। ଏହା ପରିବର୍ତ୍ତେ ପୃଥକ୍ model
> ମୂଲ୍ୟଗୁଡ଼ିକ ସମ୍ପାଦନ କରିବା ପାଇଁ, **Pricing** ଡ୍ୟାସ୍ବୋର୍ଡ ପୃଷ୍ଠା କିମ୍ବା `PATCH /api/pricing` ବ୍ୟବହାର କରନ୍ତୁ।

## ସମସ୍ୟା ସମାଧାନ

- **ସମସ୍ତ ଖର୍ଚ୍ଚ $0 / "Legacy / Free" ଦର୍ଶାଏ।** ବ୍ୟବହୃତ modelଗୁଡ଼ିକ ପାଇଁ କୌଣସି ମୂଲ୍ୟ ଏଣ୍ଟ୍ରି ନାହିଁ।
  ବାହ୍ୟ ସିଙ୍କ୍ ସକ୍ଷମ କରନ୍ତୁ (`PRICING_SYNC_ENABLED=true`) ଏବଂ `omniroute pricing sync` ଚଲାନ୍ତୁ, କିମ୍ବା
  Pricing ପୃଷ୍ଠା / `PATCH /api/pricing` ମାଧ୍ୟମରେ ମାନୁଆଲ୍ ଭାବେ ମୂଲ୍ୟ ସେଟ୍ କରନ୍ତୁ।
- **ଏକ ଐତିହାସିକ modelର ମୂଲ୍ୟ ଭୁଲ୍ ଅଛି।** ମୂଲ୍ୟ ସଂଶୋଧନ କରନ୍ତୁ (ଓଭରରାଇଡ୍ କିମ୍ବା ପୁନଃ-ସିଙ୍କ୍ କରନ୍ତୁ) — ପ୍ରତ୍ୟେକ analytics ରିଡ୍ରେ ଟୋକେନ୍ ସଂଖ୍ୟାରୁ ଖର୍ଚ୍ଚ
  ପୁନଃଗଣନା କରାଯାଏ, ତେଣୁ ଆନୁମାନିକ ମୂଲ୍ୟଗୁଡ଼ିକ ପୂର୍ବବ୍ୟାପୀ ଭାବରେ ଅପଡେଟ୍ ହୁଏ।
- **ବ୍ୟୟ ବାସ୍ତବ ସମୟଠାରୁ ପଛରେ ରହେ।** ପ୍ରତି-key ବ୍ୟୟ ବ୍ୟାଚ୍ ଆକାରରେ ପ୍ରକ୍ରିୟାକରଣ ହୁଏ; ଅଧିକ ସଦ୍ୟତମ ସଂଖ୍ୟା ଆବଶ୍ୟକ ହେଲେ
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS`ର ମୂଲ୍ୟ କମାନ୍ତୁ।
