## ଏହା କ’ଣ (ଏବଂ କ’ଣ ନୁହେଁ)

OmniRoute ଟୋକନ୍ ସଂଖ୍ୟାକୁ ଏକ ମଡେଲ୍ର ମୂଲ୍ୟ ହାର ସହିତ ଗୁଣ କରି ପ୍ରତ୍ୟେକ ସମାପ୍ତି ପାଇଁ ଅନୁରୋଧ-ପିଛା USD ଖର୍ଚ୍ଚ ନିର୍ଦ୍ଧାରଣ କରେ। ଏହି ସଂଖ୍ୟାଗୁଡ଼ିକ **ଖର୍ଚ୍ଚ** ଡ୍ୟାଶବୋର୍ଡ,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON ରପ୍ତାନି ଏବଂ ପ୍ରତି-API-key ବଜେଟ୍କୁ ପରିଚାଳିତ କରେ।

> **ଡ୍ୟାଶବୋର୍ଡର "ଖର୍ଚ୍ଚ" ଏକ ସଞ୍ଚୟ ଟ୍ରାକର୍, ବିଲ୍ ନୁହେଁ।** OmniRoute କେବେବି ଆପଣଙ୍କଠାରୁ ଶୁଳ୍କ ନିଏ ନାହିଁ
> — ଏହା ଆପଣଙ୍କ ଅନୁରୋଧଗୁଡ଼ିକୁ ଆପଣ ପୂର୍ବରୁ ସଂଯୋଗ କରିଥିବା ପ୍ରଦାନକାରୀଙ୍କ ପାଖକୁ ରୁଟ୍ କରେ (ଆପଣଙ୍କ ନିଜସ୍ୱ
> ସବ୍ସ୍କ୍ରିପ୍ସନ୍, ମାଗଣା ସ୍ତର ଏବଂ API keyଗୁଡ଼ିକ)। ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ମାଗଣା
> ମଡେଲ୍ଗୁଡ଼ିକରେ ସଞ୍ଚିତ "$290 total cost"ର ଅର୍ଥ ହେଉଛି ପ୍ରାୟ **$290 ଯାହା ଆପଣ ଏକ ଦେୟ APIକୁ ଦେଇ _ନାହାନ୍ତି_**। ଏହି ଅଙ୍କଟି ସମାନ ଟ୍ରାଫିକ୍ର ମାନକ ତାଲିକା ମୂଲ୍ୟ ଅନୁସାରେ ସମ୍ଭାବ୍ୟ ଖର୍ଚ୍ଚର ଏକ _ଆକଳନ_,
> ଯାହାଦ୍ୱାରା ଆପଣଙ୍କ ବ୍ୟବହାର କେଉଁଠି କେନ୍ଦ୍ରୀଭୂତ ଏବଂ ଶସ୍ତା/ମାଗଣା ପ୍ରଦାନକାରୀଙ୍କୁ ରୁଟ୍ କରିବା ଦ୍ୱାରା ଆପଣ କେତେ ସଞ୍ଚୟ କରୁଛନ୍ତି ତାହା ଦେଖିପାରିବେ।

ଏହି ବ୍ୟାଖ୍ୟା ପ୍ରକଳ୍ପର [README](../../README.md)ରେ ସିଧାସଳଖ ଭାବେ ଉଲ୍ଲେଖ କରାଯାଇଛି ("ଡ୍ୟାଶବୋର୍ଡର
'ଖର୍ଚ୍ଚ' ଏକ ସଞ୍ଚୟ ଟ୍ରାକର୍, ବିଲ୍ ନୁହେଁ")।

ସଂଖ୍ୟାଟି ଏକ ଆକଳନ ହୋଇଥିବାରୁ:

- ଏହା ପ୍ରତ୍ୟେକ ମଡେଲ୍ ପାଇଁ OmniRoute ପାଖରେ ଥିବା ମୂଲ୍ୟ ତାଲିକା ଉପରେ ନିର୍ଭର କରେ। ମୂଲ୍ୟ
  ଏଣ୍ଟ୍ରି ନଥିବା ମଡେଲ୍ `0` ଖର୍ଚ୍ଚ ଯୋଗ କରେ (ଏହା ଏକ୍ସପ୍ଲୋରର୍ରେ "ପୁରୁଣା / ମାଗଣା" ଧାଡ଼ି ଭାବେ ଦେଖାଯାଏ)।
- ମାଗଣା-ସ୍ତର ଏବଂ ସବ୍ସ୍କ୍ରିପ୍ସନ୍ ଟ୍ରାଫିକ୍ରେ ମଧ୍ୟ ଏକ _ଆନୁମାନିକ_ ଖର୍ଚ୍ଚ ସଞ୍ଚିତ ହୁଏ — ଏହା
  ଆପଣ ସଞ୍ଚୟ କରୁଥିବା ରାଶି, ଦେୟ ରାଶି ନୁହେଁ।

## ଖର୍ଚ୍ଚ କିପରି ଆକଳନ କରାଯାଏ \|

### ମୂଲ୍ୟ ଉତ୍ସ

[`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) ରେ ମିଶ୍ରିତ ମୂଲ୍ୟ ସାରଣୀରୁ ମୂଲ୍ୟ, ଏହି କ୍ରମରେ (** ସର୍ବୋଚ୍ଚ ପ୍ରଥମ** ):

1. **ଉପଯୋଗକର୍ତ୍ତା ନବଲିଖନ କରନ୍ତି \|** — ମୂଲ୍ୟ ଡ୍ୟାସବୋର୍ଡରେ କିମ୍ବା `PATCH /api/pricing` ( `pricing` ନାମ ସ୍ଥାନ) ମାଧ୍ୟମରେ ସେଟ୍ ହୋଇଛି \|
2. **models.dev ସିଙ୍କ୍ \|** — ମୂଲ୍ୟ `https://models.dev/api.json` ( `models_dev_pricing` ନାମ ସ୍ଥାନ) ରୁ ଅଣାଯାଇଛି \|
3. **LiteLLM ସିଙ୍କ୍** — ମୂଲ୍ୟ LiteLLM ର ସର୍ବସାଧାରଣ `model_prices_and_context_window.json` ( `pricing_synced` ନାମ ସ୍ଥାନ) ରୁ ଅଣାଯାଇଛି \|
4. **ହାର୍ଡକୋଡ୍ ଡିଫଲ୍ଟ \|** — ହାର [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) ରେ ପଠାଯାଇଛି \|

ସମାନ provider/model ପାଇଁ, ଉଚ୍ଚ-ପ୍ରାଥମିକ ସ୍ତରରୁ ମୂଲ୍ୟଗୁଡ଼ିକ ନିମ୍ନ ସ୍ତରରେ ମେଳ ଖାଉଥିବା କ୍ଷେତ୍ରଗୁଡ଼ିକୁ ନବଲିଖନ କରେ \| ଏକ ଉପର ସ୍ତରରୁ ଅନୁପସ୍ଥିତ କ୍ଷେତ୍ରଗୁଡିକ ଏକ ନିମ୍ନ ସ୍ତରରୁ ଆସିପାରେ \| ଉଭୟ ସ୍ independent ାଧୀନ ସିଙ୍କ କାର୍ଯ୍ୟ ଏକ ସମୟରେ ଚାଲୁଥିଲେ ମଧ୍ୟ କ୍ରମ ସ୍ଥିର ହୋଇଛି \| `GET /api/pricing?includeSources=1` `pricing` ଏବଂ `sourceMap` ରିଟର୍ନ କରେ, ଯାହାର ପ୍ରତି-ମଡେଲ୍ ଲେବଲ୍ (`user`, `modelsDev`, `litellm`, `default`) ସେହି ମଡେଲ୍ ଧାରଣ କରିଥିବା ସର୍ବୋଚ୍ଚ-ପ୍ରାଥମିକ ସ୍ତର ଚିହ୍ନଟ କରେ \|

**LiteLLM ସିଙ୍କ୍** ଡିଫଲ୍ଟ ଭାବରେ ଅପ୍ଟ-ଇନ୍ ଅଟେ \| ଏହାର ପରିବେଶ ଭେରିଏବଲ୍ ( [`.env.example`](../../.env.example) ଦେଖନ୍ତୁ) ହେଉଛି:

| Env var                 | ଡିଫଲ୍ଟ \| | ଉଦ୍ଦେଶ୍ୟ                                                         |
| ----------------------- | --------- | ---------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | ବ୍ୟାକଗ୍ରାଉଣ୍ଡ୍ LiteLLM ମୂଲ୍ୟ ସିଙ୍କ୍ ସକ୍ଷମ କରନ୍ତୁ \|              |
| `PRICING_SYNC_INTERVAL` | `86400`   | ସେକେଣ୍ଡରେ ବ୍ୟବଧାନ (ଦ daily ନିକ) \|                               |
| `PRICING_SYNC_SOURCES`  | `litellm` | କେବଳ ଏହି ସିଙ୍କ ପାଇଁ ଉତ୍ସ ଚୟନ; ସମ୍ପ୍ରତି କେବଳ `litellm` ସମର୍ଥିତ \| |

**models.dev ସିଙ୍କ୍ \|** LiteLLM ସିଙ୍କ ଠାରୁ ଅଲଗା ଏବଂ ଡିଫଲ୍ଟ ଭାବରେ ଅକ୍ଷମ ଅଟେ \| ଏହାକୁ ସେଟିଂସମୂହରେ ସକ୍ଷମ କରନ୍ତୁ (models.dev sync) କିମ୍ବା ଏହି ଭେରିଏବଲ୍ ବ୍ୟବହାର କରନ୍ତୁ:

| Env var                    | ଡିଫଲ୍ଟ \|  | ଉଦ୍ଦେଶ୍ୟ                                                                                                                    |
| -------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _ (ସେଟ୍) _ | ସେଟିଂସମୂହ ଟୋଗଲ୍ ଅନୁସରଣ କରନ୍ତୁ; `1/true/on/yes` ଫୋର୍ସ ଅନ୍ ଏବଂ `0/false/off/no` ଫୋର୍ସ ଅଫ୍ (ଯଦିଓ ସେଟିଂସମୂହ ଏହାକୁ ସକ୍ଷମ କରେ) \| |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`    | ଡିଫଲ୍ଟ ମଡେଲଗୁଡିକ .dev ସେକେଣ୍ଡରେ ବ୍ୟବଧାନ (ଦ daily ନିକ) \|                                                                    |

## ଡ୍ୟାଶବୋର୍ଡ: ଖର୍ଚ୍ଚ ପୃଷ୍ଠା

**ଖର୍ଚ୍ଚ** ପୃଷ୍ଠାଟି `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`)ରେ ରହିଛି।
ଏହାର ମୁଖ୍ୟ ଦୃଶ୍ୟ ହେଉଛି **ଖର୍ଚ୍ଚ ସାରାଂଶ** ଟ୍ୟାବ୍

ଏହା ଯାହା ଦେଖାଏ:

- **ଖର୍ଚ୍ଚ ଟାଇଲ୍ଗୁଡ଼ିକ** — _ଆଜି (1d)_, _7d_, _30d_ ଏବଂ ଚୟନିତ
  ଅବଧି ପାଇଁ ଆନୁମାନିକ ଖର୍ଚ୍ଚ। ଅବଧି ଚୟନକାରୀ: `7d`, `30d`, `90d`, `all`।
- **ମୁଖ୍ୟ ମେଟ୍ରିକ୍ସ** — ଅବଧି ମଧ୍ୟରେ ଅନୁରୋଧ, ସକ୍ରିୟ ପ୍ରଦାନକାରୀ, ସକ୍ରିୟ ମଡେଲ୍, ପ୍ରତି
  ଅନୁରୋଧର ହାରାହାରି ଖର୍ଚ୍ଚ।
- **ଖର୍ଚ୍ଚ ଏକ୍ସପ୍ଲୋରର୍** — **ପ୍ରଦାନକାରୀ**, **ମଡେଲ୍**,
  **API କୀ**, **ଆକାଉଣ୍ଟ**, କିମ୍ବା **ସେବା ସ୍ତର** ଅନୁଯାୟୀ ଗୋଷ୍ଠୀଭୁକ୍ତ ଏକ କ୍ରମବଦ୍ଧ/ଫିଲ୍ଟର୍ଯୋଗ୍ୟ ଟେବୁଲ୍, ଯେଉଁଥିରେ ଖର୍ଚ୍ଚ, ଅନୁରୋଧ, ଟୋକେନ୍, ପ୍ରତି
  ଅନୁରୋଧର ହାରାହାରି ଖର୍ଚ୍ଚ ଏବଂ ମୋଟର ଅଂଶ % ରହିଛି।
- **ଟୋକେନ୍ ବ୍ୟବହାର** — ମୋଟ / ଇନ୍ପୁଟ୍ / ଆଉଟ୍ପୁଟ୍ ଟୋକେନ୍ ଏବଂ ଇନ୍ପୁଟ୍:ଆଉଟ୍ପୁଟ୍ ଅନୁପାତ।
- **ରାଉଟିଂ ଦକ୍ଷତା** — ଫଲ୍ବ୍ୟାକ୍ ସଂଖ୍ୟା, ଫଲ୍ବ୍ୟାକ୍ ହାର ଏବଂ ଅନୁରୋଧ କରାଯାଇଥିବା ମଡେଲ୍ର କଭରେଜ୍।
- **ମାସିକ ପୂର୍ବାନୁମାନ** — ସାମ୍ପ୍ରତିକ ଦୈନିକ ହାରାହାରିରୁ ମାସ-ଶେଷ ଖର୍ଚ୍ଚର ଆକଳନ କରେ।
- **ଅବଧି ତୁଳନା** — ଅବଧିର ପ୍ରଥମ ଏବଂ ଦ୍ୱିତୀୟ ଅର୍ଦ୍ଧ ମଧ୍ୟରେ % ପରିବର୍ତ୍ତନ।
- **ଚାର୍ଟଗୁଡ଼ିକ** — ଦୈନିକ ଖର୍ଚ୍ଚ ଧାରା, ପ୍ରଦାନକାରୀଙ୍କ ଅଂଶ (ପାଇ), ଶୀର୍ଷ ପ୍ରଦାନକାରୀ, ଶୀର୍ଷ ମଡେଲ୍, API କୀ
  ଅନୁଯାୟୀ ଖର୍ଚ୍ଚ, ଆକାଉଣ୍ଟ ଅନୁଯାୟୀ ଖର୍ଚ୍ଚ, ସାପ୍ତାହିକ ବ୍ୟବହାର ପ୍ୟାଟର୍ନ ଏବଂ ଏକ କାର୍ଯ୍ୟକଳାପ ହିଟ୍ମ୍ୟାପ୍।
- **ରପ୍ତାନି** — ବର୍ତ୍ତମାନର ଅବଧିକୁ **CSV** କିମ୍ବା **JSON** ଭାବରେ ଡାଉନଲୋଡ୍ କରନ୍ତୁ (ଶୂନ୍ୟରୁ ଅଧିକ ଖର୍ଚ୍ଚ ତଥ୍ୟ
  ଥିଲେ ବଟନ୍ଗୁଡ଼ିକ ଦେଖାଯାଏ)।

ମୂଲ୍ୟ ନିର୍ଦ୍ଧାରିତ ଟ୍ରାଫିକ୍ ନଥିଲେ, ଧାଡ଼ିଗୁଡ଼ିକ `$0` ପରିବର୍ତ୍ତେ "ପୁରୁଣା / ମାଗଣା" ଲେବଲ୍ ଭାବରେ ଦେଖାଯାଏ,

## CLI

OmniRouteର CLI ଖର୍ଚ୍ଚ, ବ୍ୟବହାର ଏବଂ ମୂଲ୍ୟ ନିର୍ଦ୍ଧାରଣ କମାଣ୍ଡଗୁଡ଼ିକୁ ଉପଲବ୍ଧ କରାଏ ([`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)ରେ ପଞ୍ଜୀକୃତ)।

### `omniroute cost`

`/api/usage/analytics`ରୁ ସଂଗୃହୀତ ଏକ ଖର୍ଚ୍ଚ ରିପୋର୍ଟ।

```bash
omniroute cost                          # ଗତ 30d, provider ଅନୁଯାୟୀ ଗୋଷ୍ଠୀଭୁକ୍ତ
omniroute cost --period 7d              # ଗତ 7 ଦିନ
omniroute cost --group-by model         # provider | model | combo | api-key | day ଅନୁଯାୟୀ ଗୋଷ୍ଠୀଭୁକ୍ତ କରନ୍ତୁ
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ସ୍ତମ୍ଭଗୁଡ଼ିକ: ଗୋଷ୍ଠୀ, ଅନୁରୋଧ, ଇନପୁଟ୍/ଆଉଟପୁଟ୍ ଟୋକେନ୍, ଖର୍ଚ୍ଚ (USD), ଏବଂ ମୋଟର ପ୍ରତିଶତ। ଶେଷରେ ଏକ ସର୍ବମୋଟ ପଙ୍କ୍ତି
ମୁଦ୍ରିତ ହୁଏ (`--quiet` କିମ୍ବା `--output json` ଦ୍ୱାରା ଏହାକୁ ଲୁଚାଯାଏ)।

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ପ୍ରତି-provider ଖର୍ଚ୍ଚ ସାରାଂଶ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ବଜେଟ୍ଗୁଡ଼ିକ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`, `GET /api/pricing/defaults`ରୁ ପଢ଼େ। ଏହା ପରିବର୍ତ୍ତେ ପୃଥକ୍ model
> ମୂଲ୍ୟଗୁଡ଼ିକ ସମ୍ପାଦନ କରିବା ପାଇଁ, **Pricing** ଡ୍ୟାସ୍ବୋର୍ଡ ପୃଷ୍ଠା କିମ୍ବା `PATCH /api/pricing` ବ୍ୟବହାର କରନ୍ତୁ।

## ସମସ୍ୟା ସମାଧାନ

- **ସମସ୍ତ ଖର୍ଚ୍ଚ $0 / "Legacy / Free" ଦର୍ଶାଏ।** ବ୍ୟବହୃତ modelଗୁଡ଼ିକ ପାଇଁ କୌଣସି ମୂଲ୍ୟ ଏଣ୍ଟ୍ରି ନାହିଁ।
  ବାହ୍ୟ ସିଙ୍କ୍ ସକ୍ଷମ କରନ୍ତୁ (`PRICING_SYNC_ENABLED=true`) ଏବଂ `omniroute pricing sync` ଚଲାନ୍ତୁ, କିମ୍ବା
  Pricing ପୃଷ୍ଠା / `PATCH /api/pricing` ମାଧ୍ୟମରେ ମାନୁଆଲ୍ ଭାବେ ମୂଲ୍ୟ ସେଟ୍ କରନ୍ତୁ।
- **ଏକ ଐତିହାସିକ modelର ମୂଲ୍ୟ ଭୁଲ୍ ଅଛି।** ମୂଲ୍ୟ ସଂଶୋଧନ କରନ୍ତୁ (ଓଭରରାଇଡ୍ କିମ୍ବା ପୁନଃ-ସିଙ୍କ୍ କରନ୍ତୁ) — ପ୍ରତ୍ୟେକ analytics ରିଡ୍ରେ ଟୋକେନ୍ ସଂଖ୍ୟାରୁ ଖର୍ଚ୍ଚ
  ପୁନଃଗଣନା କରାଯାଏ, ତେଣୁ ଆନୁମାନିକ ମୂଲ୍ୟଗୁଡ଼ିକ ପୂର୍ବବ୍ୟାପୀ ଭାବରେ ଅପଡେଟ୍ ହୁଏ।
- **ବ୍ୟୟ ବାସ୍ତବ ସମୟଠାରୁ ପଛରେ ରହେ।** ପ୍ରତି-key ବ୍ୟୟ ବ୍ୟାଚ୍ ଆକାରରେ ପ୍ରକ୍ରିୟାକରଣ ହୁଏ; ଅଧିକ ସଦ୍ୟତମ ସଂଖ୍ୟା ଆବଶ୍ୟକ ହେଲେ
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS`ର ମୂଲ୍ୟ କମାନ୍ତୁ।
