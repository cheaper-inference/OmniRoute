ନିରପେକ୍ଷ `config/cli-tools-manifest.json` ଚୁକ୍ତି କାନୋନିକାଲ୍ IDs, ଛଦ୍ମନାମ, ବାଇନାରୀ ପ୍ରାର୍ଥୀ, ସେଟଅପ୍ ରେସିପି, ମଡେଲ୍ ଆର୍ଗୁମେଣ୍ଟସ୍ ଏବଂ ସାମର୍ଥ୍ୟ ଘୋଷଣା କରେ। `bin/cli/cli-manifest.mjs` ରେ ସାଧା ନୋଡ୍ ଆଡାପ୍ଟର ଏବଂ `src/shared/constants/cliIntegrationManifest.ts` ରେ TypeScript ଆଡାପ୍ଟର ସମାନ ଫାଇଲ ପ read ନ୍ତି। ଚାଲିବା ସମୟ, କାଟାଲଗ୍, ବିନ୍ୟାସ, ସମାପ୍ତି, ଜେନେରେଟର ଏବଂ ବ୍ୟାକେଣ୍ଡ ପଞ୍ଜୀକରଣ `tests/unit/cli/cli-manifest-drift.test.ts` ଦ୍ୱାରା ଏକତ୍ର ଯାଞ୍ଚ କରାଯାଏ। କାଟାଲଗ୍ ହେବା ଏହାର ଅର୍ଥ ନୁହେଁ ଯେ ଏକ ସାଧନ ଲଞ୍ଚ କିମ୍ବା ବିନ୍ୟାସ ହୋଇପାରିବ। ବିଶେଷ ଭାବରେ, 5dive କେବଳ ବିନ୍ୟାସିତ ରହିଥାଏ।

## ଶିଶୁ ପରିବେଶ ଏବଂ ଜୀବନଚକ୍ର।

`omniroute run`, `omniroute launch` ଏବଂ `omniroute launch-codex` ଏକ OS/terminal ସୁସଙ୍ଗତ ଅନୁମତି ତାଲିକା ଉତ୍ତରାଧିକାରୀ ଏବଂ ମନୋନୀତ ଲକ୍ଷ୍ୟର ପରିଚୟପତ୍ର ଇଞ୍ଜେକ୍ସନ ଦିଅନ୍ତୁ। ଅବିଭକ୍ତ ପ୍ରଦାନକାରୀ ଏବଂ ଡାଟାବେସ୍ ରହସ୍ୟ ଡିଫଲ୍ଟ ଭାବରେ ଉତ୍ତରାଧିକାରୀ ନୁହେଁ। `--inherit-env` ସ୍ପଷ୍ଟ ଭାବରେ ପୂର୍ଣ୍ଣ ପିତାମାତା-ପରିବେଶ ଉତ୍ତରାଧିକାରୀ ପୁନରୁଦ୍ଧାର କରେ; ଯେତେବେଳେ ମନୋନୀତ ତୃତୀୟ-ପକ୍ଷ ପ୍ରକ୍ରିୟା ସେହି ମୂଲ୍ୟଗୁଡ଼ିକୁ ଗ୍ରହଣ କରିବା ଉଚିତ ସେତେବେଳେ କେବଳ ଏହାକୁ ବ୍ୟବହାର କରନ୍ତୁ। ଏହା ହେଉଛି ପରିବେଶ ଫିଲ୍ଟରିଂ, OS ସ୍ୟାଣ୍ଡବକ୍ସ ନୁହେଁ: ପ୍ରକ୍ରିୟା ଏପର୍ଯ୍ୟନ୍ତ କଲରଙ୍କ ଫାଇଲତନ୍ତ୍ର ଅନୁମତି ସହିତ ଚାଲିଥାଏ।

ବାଧା ଏବଂ ସମାପ୍ତି ସଙ୍କେତଗୁଡିକ ପିଲାଙ୍କ ନିକଟକୁ ପଠାଯାଏ। ଅସ୍ଥାୟୀ ବିନ୍ୟାସ ଅପସାରଣ କରିବା ପୂର୍ବରୁ ଲଞ୍ଚର୍ ଶିଶୁର ଘନିଷ୍ଠ ଘଟଣାକୁ ଅପେକ୍ଷା କରିଥାଏ। `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` ବାଧ୍ୟତାମୂଳକ ସମାପ୍ତି ପୂର୍ବରୁ ଅନୁଗ୍ରହ ଅବଧି ନିୟନ୍ତ୍ରଣ କରେ (ଡିଫଲ୍ଟ 5000 ମିଲିସେକେଣ୍ଡ)।

## Gemini ସ୍ଥାୟୀ ସେଟଅପ୍।

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

ପ୍ରଥମ ଦୁଇଟି ନିର୍ଦ୍ଦେଶ ଏହି ମେସିନକୁ ମନୋନୀତ ସ୍ଥାନୀୟ କିମ୍ବା ସୁଦୂର ସର୍ଭର ପାଇଁ ବିନ୍ୟାସ କରିଥାଏ। ସେଟଅପ୍ ଅବିଭକ୍ତ JSON ସେଟିଂସମୂହକୁ ସଂରକ୍ଷଣ କରେ, Gemini API- କି auth କୁ ବାଛେ ଏବଂ ଏକ ବ୍ୟକ୍ତିଗତ `.gemini/.env` ଫାଇଲରେ ଶେଷ ପଏଣ୍ଟ ଏବଂ ପରିଚୟପତ୍ର ଲେଖେ। ଏହା ଓଭର୍ ରାଇଟ୍ କରିବା ପରିବର୍ତ୍ତେ ଅବ alid ଧ JSON ମନା କରେ। ଏଣ୍ଡପଏଣ୍ଟ URLs ନିଶ୍ଚିତ ଭାବରେ HTTP(S) ହେବା ଆବଶ୍ୟକ, ଏମ୍ବେଡ୍ ହୋଇଥିବା ପରିଚୟପତ୍ର, ଜିଜ୍ଞାସା ପାରାମିଟର କିମ୍ବା ଖଣ୍ଡଗୁଡ଼ିକ ବିନା। ଶୁଖିଲା ଚାଲୁଥିବା ପଥଗୁଡ଼ିକ, ପରିଚୟ ମୂଲ୍ୟ ନୁହେଁ।

`GEMINI_CLI_HOME` କିମ୍ବା `--gemini-home` ସ୍ଥାୟୀ ଗୃହ ମୂଳକୁ ବାଛିଥାଏ। ଏକ ପ୍ରକୃତ `run gemini` ନିଜର ଅସ୍ଥାୟୀ ଘର ସୃଷ୍ଟି କରେ ଏବଂ ପରେ ଅପସାରଣ କରେ। କ mode ଣସି ମୋଡ୍ Gemini ର କାର୍ଯ୍ୟକ୍ଷେତ୍ର-ଟ୍ରଷ୍ଟ ଯାଞ୍ଚକୁ ବାଇପାସ୍ କରେ ନାହିଁ।

## Codex ପ୍ରୋଫାଇଲ୍।

`configure codex` ଏକ ମଡେଲ୍ ଏବଂ ଏହାର OmniRoute ପ୍ରଦାନକାରୀ ଶେଷ ପଏଣ୍ଟ ସହିତ ଏକ ବ୍ୟକ୍ତିଗତ `<name>.config.toml` ଲେଖେ। ପ୍ରମାଣପତ୍ରଗୁଡ଼ିକ `OMNIROUTE_API_KEY` ମାଧ୍ୟମରେ ସୂଚିତ ହୋଇଛି, କେବେବି ଏମ୍ବେଡ୍ ହୋଇନାହିଁ। ଲଞ୍ଚ କମାଣ୍ଡ `model_providers` ଭିତରେ ନୁହେଁ, ଶୀର୍ଷ ସ୍ତରର `model` କିରେ ମନୋନୀତ ମଡେଲକୁ ସେଟ୍ କରେ।

ପୃଥକ ପ୍ରୋଫାଇଲ୍ ଫାଇଲଗୁଡ଼ିକ ହେଉଛି ସାମ୍ପ୍ରତିକ ଡକ୍ୟୁମେଣ୍ଟ୍ ହୋଇଥିବା Codex ଚୁକ୍ତି; `codex --profile <name>` ସହିତ ସିଲେକ୍ଟ ହେବାବେଳେ ସେମାନେ ୟୁଜର୍ କନଫିଗରେନ୍ସକୁ ଆଚ୍ଛାଦନ କରନ୍ତି। [ଅଫିସିଆଲ୍ ପ୍ରୋଫାଇଲ୍ ରେଫରେନ୍ସ](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) ଏବଂ [OmniRoute Codex ଗାଇଡ୍](./CODEX-CLI-CONFIGURATION.md) ଦେଖନ୍ତୁ।

## ହର୍ମେଟିକ୍ କମାଣ୍ଡ୍ ଏକଜେକ୍ୟୁଶନ୍।

ଏକ ସ୍ପଷ୍ଟ `DATA_DIR` ସହିତ, `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` ସେଟିଂ ଷ୍ଟାର୍ଟଅପ୍ କୁ ଡିଫଲ୍ଟ ୟୁଜର୍ ଡାଟା ଡିରେକ୍ଟୋରୀର ପରିଚୟ ପରିବେଶକୁ ଖସିଯିବାକୁ ରୋକିଥାଏ। ପୃଥକ ପରୀକ୍ଷଣ ପାଇଁ ଏହା ଉପଯୋଗୀ। ଏହା ଅନ୍ୟ ସ୍ପଷ୍ଟ ଭାବରେ ମନୋନୀତ ପରିବେଶ ଫାଇଲଗୁଡ଼ିକୁ ଅକ୍ଷମ କରେ ନାହିଁ।

## ୱାର୍କିଂ-ଡିରେକ୍ଟୋରୀ `.env`

CLI ଏହି କ୍ରମରେ `.env` ଫାଇଲଗୁଡ଼ିକୁ ପ read ଼େ, ଏବଂ ଏକ ଚାବି ସେଟ୍ କରିବାକୁ ପ୍ରଥମ ଫାଇଲ୍: ସ୍ପଷ୍ଟ `DATA_DIR`, ଡିଫଲ୍ଟ ଡାଟା ଡିରେକ୍ଟୋରୀ, ସାମ୍ପ୍ରତିକ କାର୍ଯ୍ୟ ଡିରେକ୍ଟୋରୀ, ତାପରେ ପ୍ୟାକେଜ୍ ଡିରେକ୍ଟୋରୀ। ସେଲ୍ ଭେରିଏବଲ୍ ସବୁବେଳେ ଜିତେ।

ୱାର୍କିଂ ଡିରେକ୍ଟୋରୀ ଅନ୍ୟ କାହାର ହୋଇପାରେ (ଏକ କ୍ଲୋନେଡ୍ ରେପୋଜିଟୋରୀ, ଏକ ପ୍ୟାକ୍ ହୋଇନଥିବା ଅଭିଲେଖ), ଏବଂ `omniroute serve` CLI ପରିବେଶକୁ ସର୍ଭରକୁ ଏବଂ ସର୍ଭର ଚାଲୁଥିବା ପ୍ରତ୍ୟେକ ଉପକରଣକୁ ପଠାଇଥାଏ। ତେଣୁ ସେଠାରେ ଏକ `.env` କେବଳ ଏହି କିଗୁଡ଼ିକୁ ସେଟ୍ କରିପାରେ, `bin/cli/utils/untrustedCwdEnv.mjs` ରେ ତାଲିକାଭୁକ୍ତ:

| ଚାବି                            | ଗ୍ରହଣ କରାଯାଇଥିବା ମୂଲ୍ୟଗୁଡ଼ିକ                                              |
| ------------------------------- | ------------------------------------------------------------------------- |

| `NO_COLOR`, `FORCE_COLOR`       | 16 ଟି ଅକ୍ଷର ଏବଂ ସଂଖ୍ୟା ପର୍ଯ୍ୟନ୍ତ।                                         |

`REQUIRE_API_KEY` ଗ୍ରହଣ କରୁଥିବା ପ୍ରତ୍ୟେକ ମୂଲ୍ୟ ଚେକ୍ ଅନ୍ କରେ, ତେଣୁ ଫାଇଲ୍ ଚେକ୍ ଅଫ୍ କରିପାରିବ ନାହିଁ। ଏହା ଫଳାଫଳ ସ୍ଥିର କରେ ନାହିଁ, ଯଦିଓ: ସର୍ଭର ପରିବେଶ ପୂର୍ବରୁ ଡାଟାବେସରେ ଗଚ୍ଛିତ ଏକ `REQUIRE_API_KEY` ଓଭରବ୍ରିଡ୍ ପ read ଼ିଥାଏ, ଯେତେବେଳେ API ଚାବି ବିନା ସମସ୍ତ ଇଣ୍ଟରଫେସରେ ଶୁଣିବା ବିଷୟରେ ଷ୍ଟାର୍ଟଅପ୍ ଚେତାବନୀ କେବଳ ପରିବେଶ ପ read େ। `false` ର ଏକ ଗଚ୍ଛିତ ଓଭରଡାଇଡ୍ ସହିତ, ଏକ ୱର୍କିଂ-ଡିରେକ୍ଟୋରୀ `REQUIRE_API_KEY=true` API କୁ ଖୋଲା ଛାଡି ସେହି ଚେତାବନୀକୁ ଲୁଚାଇଥାଏ। `TZ` ନିୟମ POSIX ଠାରୁ ସଂକୀର୍ଣ୍ଣ: ଏହା `.`, `:`, `,` ଏବଂ `<>` କୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ, ତେଣୁ `:Area/City` ଫର୍ମ ଏବଂ `EST5EDT,M3.2.0,M11.1.0` ପରି ନିୟମ ଶେଲରେ କିମ୍ବା `<DATA_DIR>/.env` ରେ ସେଟ୍ ହେବା ଆବଶ୍ୟକ।

ଉପର କ୍ଷେତ୍ରରେ ନାମଗୁଡିକ ନିଶ୍ଚିତ ଭାବରେ ମେଳ ହେବା ଜରୁରୀ। ଅନ୍ୟ କ line ଣସି ଧାଡ଼ି, ଏକ ମୂଲ୍ୟ ଯାହା ଏହାର ଯା check ୍ଚରେ ବିଫଳ ହୁଏ, ଏବଂ ଏକ ନାମ ଯାହା ସରଳ ASCII ଅକ୍ଷର, ଅଙ୍କ ଏବଂ `_` ନୁହେଁ (ଉଦାହରଣ ସ୍ୱରୂପ ଗୋଟିଏ NUL ବାଇଟ୍ କିମ୍ବା ଏକ ସମାନ ଅକ୍ଷର)। CLI ଗୋଟିଏ ଚେତାବନୀକୁ ମୁଦ୍ରଣ କରେ ଯାହା ଚାବିଗୁଡ଼ିକୁ ସେଟ୍ କରିପାରିବ ନାହିଁ ଏବଂ ଗୋଟିଏ ନାମ ଯାହା ଏହାକୁ ଅଣଦେଖା କରିବାକୁ ଅନୁମତି ଦେଇଥାଏ, ପ୍ରତ୍ୟେକଟି କଣ ପରିବର୍ତ୍ତନ ହେବ (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`) ସହିତ। ନା ଭାଲ୍ୟୁ ପ୍ରିଣ୍ଟ୍ କରେ। ଏହି ସନ୍ଦେଶଗୁଡ଼ିକରେ ଫାଇଲ୍ ପଥ, ଏବଂ `.env` ପଥ `omniroute doctor` ରିପୋର୍ଟଗୁଡିକ, ଯେତେବେଳେ ସେମାନେ ନିୟନ୍ତ୍ରଣ କିମ୍ବା ବିଡି ଅକ୍ଷର ଧାରଣ କରନ୍ତି, ସେତେବେଳେ ପଳାଇଯାଆନ୍ତି। ୱାର୍କିଂ ଡିରେକ୍ଟୋରୀ ହେଉଛି ଡାଟା ଡିରେକ୍ଟୋରୀ କିମ୍ବା ପ୍ୟାକେଜ୍ ଡିରେକ୍ଟୋରୀ।

`PORT`, `API_PORT` ଏବଂ `DASHBOARD_PORT` ତାଲିକାରେ ନାହିଁ। ଏକ ଉଚ୍ଚ ପ୍ରାଥମିକ ଉତ୍ସରୁ ଆଧାର URL ବିନା, CLI `localhost:<PORT>` ସହିତ କଥାବାର୍ତ୍ତା କରେ, ଏବଂ ସେଠାରେ ଯାହା ଶୁଣେ CLI ର API କି, ପ୍ରସଙ୍ଗ ଟୋକେନ୍ ଏବଂ CLI ମେସିନ୍ ଟୋକେନ୍ (`x-omniroute-cli-token`, [CLI_TOKEN.md](../security/CLI_TOKEN.md) ଦେଖନ୍ତୁ), ଯାହାକି ସ୍ଥାନୀୟ ସର୍ଭର ଲୁପବ୍ୟାକ୍ ରୁ ପରିଚାଳନା କଲ୍ ପାଇଁ ଗ୍ରହଣ କରେ। ୱାର୍କିଂ ଡିରେକ୍ଟୋରୀରୁ ଏକ ପୋର୍ଟ ସେହି ଫାଇଲକୁ ଶ୍ରୋତା ବାଛିବା ପାଇଁ ଅନୁମତି ଦେବ, ତେଣୁ ଶେଲରେ ଥିବା ପୋର୍ଟଗୁଡ଼ିକୁ `<DATA_DIR>/.env` ରେ କିମ୍ବା `--port` ଅପ୍ସନ୍ ସହିତ ଗୋଟିଏ (`serve`, `launch`, `run`) ସେଟ୍ କରନ୍ତୁ।

ପାର୍ସରର `export` ବାକ୍ୟବିନ୍ୟାସ ନାହିଁ। `export LD_PRELOAD=...` ପରି ଏକ ରେଖା ଏକ ଭେରିଏବଲ୍ `export LD_PRELOAD` ନାମ କରେ। ୱାର୍କିଂ ଡିରେକ୍ଟୋରୀରୁ ଏହାକୁ ଏଡ଼ାଇ ଦିଆଯାଏ, ଏବଂ ଅନ୍ୟ `.env` ଫାଇଲଗୁଡ଼ିକରେ ଏହା ସେହି ଆକ୍ଷରିକ ନାମ ସେଟ୍ କରେ, ଯାହା କିଛି ପ read େ ନାହିଁ।

CLI ଏକ ପ୍ରସଙ୍ଗର ସଂରକ୍ଷିତ ଟୋକନ୍ (ଆକ୍ସେସ୍ ଟୋକେନ୍ କିମ୍ବା ପୁରୁଣା API କି) କେବଳ ସେହି ପ୍ରସଙ୍ଗର ନିଜସ୍ୱ ଉତ୍ପତ୍ତି ସହିତ ଯୋଡିଥାଏ: `URL.origin` ତୁଳନାରେ ସ୍କିମ୍, ହୋଷ୍ଟ ଏବଂ ପୋର୍ଟ। ଏହା CLI ର HTTP କ୍ଲାଏଣ୍ଟ (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) ଏବଂ `launch`, `launch codex`, `configure` ଏବଂ `setup-*` ନିର୍ଦ୍ଦେଶଗୁଡ଼ିକ ଦ୍ୱାରା କରାଯାଇଥିବା ଅନୁରୋଧଗୁଡ଼ିକ ପାଇଁ ପ୍ରଯୁଜ୍ୟ ଯାହାକି ଅନ୍ୟ ଏକ ଉପକରଣର ବିନ୍ୟାସରେ ଏକ ଆଧାର URL ଏବଂ କି ଲେଖେ। `--remote` ସହିତ ଅନ୍ୟ ଏକ ସର୍ଭରରେ ସୂଚିତ, ଯଦି ସେଟ ହୁଏ, ତେବେ ସେମାନେ ଏକ ସ୍ପଷ୍ଟ `--api-key` କିମ୍ବା `OMNIROUTE_API_KEY` ବ୍ୟବହାର କରନ୍ତି, ଏବଂ କ context ଣସି ପ୍ରସଙ୍ଗ ଟୋକନ୍ ନାହିଁ। ତୁଳନାତ୍ମକ ସଠିକ୍, ତେଣୁ `localhost` ଏବଂ `127.0.0.1`, କିମ୍ବା ଏକ ହୋଷ୍ଟ ବିନା ଟ୍ରେଲିଂ ଡଟ୍ ସହିତ, ବିଭିନ୍ନ ସର୍ଭର ଭାବରେ ଗଣନା କରନ୍ତୁ ଏବଂ କ context ଣସି ପ୍ରସଙ୍ଗ ଟୋକେନ୍ ପାଇବେ ନାହିଁ। ୟୁଜର୍ନଫୋ ସହିତ ଏକ URL, ଏକ ବ୍ୟାକ୍ ସ୍ଲାସ୍ କିମ୍ବା ହ୍ ites ାଇଟସ୍ପେସ୍ କେବେବି ମେଳ ହୁଏ ନାହିଁ, କାରଣ ଅନ୍ୟ URL ପାର୍ସର୍ (ଉଦାହରଣ ସ୍ୱରୂପ Python ର `urllib` ଏବଂ `httpx`) ଏହାଠାରୁ ଏକ ଭିନ୍ନ ହୋଷ୍ଟ ପ read ିପାରେ। ଅନୁରୋଧ ପାଇଁ CLI ନିଜକୁ ପଠାଏ, ସେହି ଚେକ୍ କେବଳ ସ୍କିମ୍ ଏବଂ ପ୍ରାଧିକରଣକୁ ଆବୃତ କରେ, ତେଣୁ ପଥ କିମ୍ବା ଜିଜ୍ଞାସାରେ ଏକ ସ୍ପେସ୍ ଥିବା ଏକ id ଟୋକେନ୍ ରଖେ।
