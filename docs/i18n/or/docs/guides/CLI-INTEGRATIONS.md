ସାଧାରଣ executable manifest, ସୀମିତ child environment ଏବଂ ସ୍ଥାୟୀ
Gemini setup ପାଇଁ, [CLI launch contracts](./CLI-LAUNCH-CONTRACTS.md) ଦେଖନ୍ତୁ।

OmniRoute ଏକାଧିକ `setup-*` command ପ୍ରଦାନ କରେ, ଯେଉଁଗୁଡ଼ିକ ଏକ coding
CLI (Codex, Claude Code, OpenCode, Cline, …)କୁ OmniRoute-କୁ ଏହାର backend ଭାବେ ବ୍ୟବହାର କରିବା ପାଇଁ configure କରେ — ଫଳରେ
toolଟି **ଗୋଟିଏ** endpoint ସହିତ ଯୋଗାଯୋଗ କରେ ଏବଂ OmniRoute auto-fallback ସହିତ ଉପଯୁକ୍ତ providerକୁ
route କରେ। ପ୍ରତ୍ୟେକ command ଚାଲୁଥିବା OmniRoute (local କିମ୍ବା remote)ରୁ **live** model catalog ପଢ଼େ
ଏବଂ **ଆପଣଙ୍କ**
machineରେ toolର ନିଜସ୍ୱ config file ଲେଖେ। Toolଟି ଯେଉଁଠାରେ ଏହାକୁ support କରେ, ସେଠାରେ API keyକୁ ଏକ environment variable ଦ୍ୱାରା reference କରାଯାଏ। ଯେଉଁ commandଗୁଡ଼ିକ tool-local environment fileକୁ ସ୍ଥାୟୀ ଭାବେ ସଂରକ୍ଷଣ କରେ, ସେଗୁଡ଼ିକ ନିମ୍ନରେ ଉଲ୍ଲେଖ କରାଯାଇଛି।

ଏକ ସାଧାରଣ launcher ମଧ୍ୟ ଅଛି — `omniroute run <target>` — ଯାହା
କୌଣସି config ନ ଲେଖି, ଠିକ୍ env inject କରି
`claude`, `codex`, `aider`, `goose`, `opencode`, `qwen` କିମ୍ବା `gemini`କୁ ଚାଲୁ କରେ। Target ଏବଂ ସେଗୁଡ଼ିକର
alias canonical manifest `bin/cli/cli-manifest.mjs`ରୁ ଆସେ
(`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`,
`open-code`, `qwen-code`, `gemini-cli`), ଏବଂ `omniroute completion` ସେହି
manifestରୁ ପ୍ରାପ୍ତ target ଶବ୍ଦଗୁଡ଼ିକୁ ମଧ୍ୟ ପ୍ରଦାନ କରେ। ପୁରୁଣା ପ୍ରତ୍ୟେକ-tool launcher —
`omniroute launch` (Claude Code) ଏବଂ `omniroute launch-codex` (Codex) — ଏବେ ମଧ୍ୟ
ଉପଲବ୍ଧ ଅଛି।

ସେହି local/remote contextରୁ provider onboarding ଉପଲବ୍ଧ। ନିମ୍ନରେ ଥିବା
API-first commandଗୁଡ଼ିକ management authenticationକୁ provider
credentialରୁ ପୃଥକ୍ ରଖେ ଏବଂ structured outputରେ କେବେବି credential print କରେ ନାହିଁ:

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

Script ପାଇଁ `--credential-stdin` କିମ୍ବା `--credential-env`କୁ ପ୍ରାଧାନ୍ୟ ଦିଅନ୍ତୁ; ନିୟନ୍ତ୍ରିତ local ବ୍ୟବହାର ପାଇଁ `--credential`
ରଖାଯାଇଛି। ଏକ non-interactive terminalରେ `providers remove` ପାଇଁ `--yes` ଆବଶ୍ୟକ,
ଏବଂ ସମସ୍ତ ପାଞ୍ଚଟି command ସକ୍ରିୟ context କିମ୍ବା global
`--base-url`/`--api-key` optionକୁ ମାନିଥାଏ।

Provider selectorଗୁଡ଼ିକ ଅସ୍ପଷ୍ଟ ID prefix, name କିମ୍ବା provider nameକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ; ଏକାଧିକ connection match କଲେ
ସମ୍ପୂର୍ଣ୍ଣ connection ID ବ୍ୟବହାର କରନ୍ତୁ। Create ଏବଂ edit commandଗୁଡ଼ିକ
ସଂରକ୍ଷିତ connectionକୁ ପୁଣି ପଢ଼େ, ଏବଂ removal ଏହା ଆଉ ପଠନୀୟ ନୁହେଁ ବୋଲି ଯାଞ୍ଚ କରେ।
ଏକ import ପୂର୍ବରୁ ଥିବା provider/name ଯୁଗଳକୁ skip କରେ। Import କରାଯାଇଥିବା entryଗୁଡ଼ିକ CLIକୁ ଯୋଗାଇ ଦିଆଯାଇଥିବା
management endpoint, context କିମ୍ବା management credentialକୁ override କରିପାରିବ ନାହିଁ।

ଦୁଇଟି ସବୁଠାରୁ ସମୃଦ୍ଧ integrationର ଏକକାଳୀନ, ହାତରେ ଲେଖାଯାଇଥିବା base setup ପାଇଁ
ପ୍ରତ୍ୟେକ toolର ବିସ୍ତୃତ ମାର୍ଗଦର୍ଶିକା ଦେଖନ୍ତୁ:

- [Claude Code configuration](./CLAUDE-CODE-CONFIGURATION.md)
- [Codex CLI configuration](./CODEX-CLI-CONFIGURATION.md)
- [Remote Mode](./REMOTE-MODE.md) — ଆପଣଙ୍କ laptopରୁ ଏକ remote OmniRoute (VPS / Tailnet) ପରିଚାଳନା କରନ୍ତୁ
- [VS Code Copilot Chat](./VSCODE-COPILOT.md) — OmniCopilot extension; ଏହା editor ଭିତରୁ ଆପଣଙ୍କ ପାଇଁ ଏହି
  `setup-*` commandଗୁଡ଼ିକୁ ମଧ୍ୟ ଚଲାଇପାରେ

## ମାଷ୍ଟର ଟେବୁଲ୍

ପ୍ରତ୍ୟେକ କମାଣ୍ଡ **ସକ୍ରିୟ କଣ୍ଟେକ୍ସ୍ଟ**କୁ ଅନୁସରଣ କରେ (`omniroute connect` ଦ୍ୱାରା ସେଟ୍ କରାଯାଏ, [ରିମୋଟ୍ ମୋଡ୍](./REMOTE-MODE.md) ଦେଖନ୍ତୁ) କିମ୍ବା ସ୍ପଷ୍ଟ `--remote <url> --api-key <key>` ଫ୍ଲାଗ୍ଗୁଡ଼ିକୁ ଅନୁସରଣ କରେ।
ନିମ୍ନରେ ଥିବା "ଲୋକାଲ୍ ବନାମ ରିମୋଟ୍"ର ଅର୍ଥ ହେଉଛି: କୌଣସି ଫ୍ଲାଗ୍ ନଥିଲେ ଏହା `http://localhost:20128`କୁ ଲକ୍ଷ୍ୟ କରେ;
`--remote` ସହିତ (କିମ୍ବା ଏକ ସକ୍ରିୟ ରିମୋଟ୍ କଣ୍ଟେକ୍ସ୍ଟ ସହିତ) ଏହା ସେହି ସର୍ଭରରୁ କ୍ୟାଟାଲଗ୍ ଆଣେ ଏବଂ କନଫିଗ୍କୁ ଲୋକାଲ୍ ଭାବରେ ଲେଖେ।

ଫ୍ଲାଗ୍ଗୁଡ଼ିକ ସମ୍ପର୍କିତ ଟିପ୍ପଣୀ (କମାଣ୍ଡ୍ ଉତ୍ସରେ ଯାଞ୍ଚ କରାଯାଇଛି):

- `--remote <url>` — ଏକ ରିମୋଟ୍ OmniRouteରୁ କ୍ୟାଟାଲଗ୍ ଆଣେ (`--port`
  ଏବଂ ସକ୍ରିୟ କଣ୍ଟେକ୍ସ୍ଟକୁ ଓଭରରାଇଡ୍ କରେ)। `--api-key <key>` ସେହି
  ସର୍ଭର ପାଇଁ ପରିଚୟପତ୍ର ଯୋଗାଏ (ଡିଫଲ୍ଟ ଭାବେ `OMNIROUTE_API_KEY` env var, କିମ୍ବା ସକ୍ରିୟ କଣ୍ଟେକ୍ସ୍ଟର ଟୋକନ୍)।
- `--only <patterns>` — କମା ଦ୍ୱାରା ପୃଥକ୍ ସବ୍ଷ୍ଟ୍ରିଙ୍ଗ୍ଗୁଡ଼ିକ; କେବଳ ମେଳ ଖାଉଥିବା model IDଗୁଡ଼ିକୁ
  ରଖେ (ଯଥା `--only glm,kimi`)। `setup-codex`, `setup-claude`,
  `setup-opencode`, `setup-continue`, `setup-cursor`, `setup-crush`, `setup-zed`ରେ ଉପଲବ୍ଧ।
- `--dry-run` — ଫାଇଲ୍ସିଷ୍ଟମ୍କୁ ସ୍ପର୍ଶ ନକରି ଠିକ୍ କ’ଣ ଲେଖାଯିବ ତାହା ପ୍ରିଣ୍ଟ୍ କରେ।
  `setup-cursor` **ବ୍ୟତୀତ** ପ୍ରତ୍ୟେକ `setup-*` କମାଣ୍ଡ୍ରେ ଉପଲବ୍ଧ
  (ଯାହା କେବେ ମଧ୍ୟ କୌଣସି ଫାଇଲ୍ ଲେଖେ ନାହିଁ)।
- `--model <id>` — ଯେଉଁ ଟୁଲ୍ଗୁଡ଼ିକରେ model ସ୍ୱୟଂ-ଆବିଷ୍କାର ନାହିଁ,
  ସେଗୁଡ଼ିକ ପାଇଁ ଏହା ଆବଶ୍ୟକ (କିମ୍ବା ଇଣ୍ଟରାକ୍ଟିଭ୍ ଭାବେ ବଛାଯାଏ): Cline, Kilo, Roo, Goose, Qwen, Aider, 5dive। ସେହି ଟୁଲ୍ଗୁଡ଼ିକ
  ଅଣ-ଇଣ୍ଟରାକ୍ଟିଭ୍ ରନ୍ ପାଇଁ `--yes` ମଧ୍ୟ ଗ୍ରହଣ କରନ୍ତି (ଯେଉଁ କ୍ଷେତ୍ରରେ `--model` ଆବଶ୍ୟକ)।
  ଡିଫଲ୍ଟ ଶୀର୍ଷ-ସ୍ତରୀୟ model ସେଟ୍ କରିବାକୁ `setup-opencode`, `--model` ଗ୍ରହଣ କରେ।
- `omniroute run`ରେ `--model <id>` ମ୍ୟାନିଫେଷ୍ଟର ପ୍ରତି-target ୱାୟାରିଂ
  (`bin/cli/cli-manifest.mjs`) ଅନୁସରଣ କରେ: **aider** `--model openai/<id>` ଏବଂ
  **opencode** `--model omniroute/<id>` ପାଏ (idରେ ପୂର୍ବରୁ ପ୍ରିଫିକ୍ସ ନଥିଲେ ମାତ୍ର
  ତାହା ଯୋଡ଼ାଯାଏ); **qwen** ଏବଂ **gemini** idକୁ ଅବିକଳ ଭାବେ ପାଆନ୍ତି;
  **claude** ଏହାକୁ `ANTHROPIC_MODEL` ମାଧ୍ୟମରେ, **goose** `GOOSE_MODEL` ମାଧ୍ୟମରେ ଏବଂ
  **codex** `-c model_providers.omniroute.*` args ମାଧ୍ୟମରେ ପାଏ। **Qwen ହେଉଛି ଏକମାତ୍ର run
  target ଯାହା ପାଇଁ `--model` କଠୋର ଭାବେ ଆବଶ୍ୟକ** — ଏହା ବିନା `omniroute run qwen`
  ଚଲାଇଲେ ଏକ ସ୍ପଷ୍ଟ ତ୍ରୁଟି ସହିତ `2`ରେ ପ୍ରସ୍ଥାନ କରେ।
- `--port <port>` — ସ୍ଥାନୀୟ OmniRoute ପୋର୍ଟ୍ (ଡିଫଲ୍ଟ `20128`, `--remote`
  ସେଟ୍ ଥିଲେ ଅଣଦେଖା କରାଯାଏ)। ସମସ୍ତ `setup-*` ଏବଂ ଉଭୟ ଲଞ୍ଚର୍ରେ ଉପସ୍ଥିତ।
- `omniroute run` ପ୍ରସ୍ଥାନ କୋଡ୍ଗୁଡ଼ିକ: ଚାଇଲ୍ଡ୍ CLIର ନିଜସ୍ୱ ପ୍ରସ୍ଥାନ କୋଡ୍
  ଅବିକଳ ଭାବେ ପ୍ରସାରିତ ହୁଏ; `2` = ଅବୈଧ ଆର୍ଗୁମେଣ୍ଟ୍ (ଅସମର୍ଥିତ target, ଆବଶ୍ୟକ
  `--model` ଅନୁପସ୍ଥିତ, କଣ୍ଟେନର୍ ଗାର୍ଡ୍); `127` = target ବାଇନାରି `PATH`ରେ ନାହିଁ;
  `SIGINT`/`SIGTERM`/`SIGHUP` ଦ୍ୱାରା ଲଞ୍ଚ୍ ସମାପ୍ତ ହେଲେ `130`/`143`/`129`;
  `1` = ଅନ୍ୟାନ୍ୟ ରନ୍ଟାଇମ୍ ଲଞ୍ଚ୍ ବିଫଳତା।
- ଦୁଇଟି ଲଞ୍ଚର୍ (`launch`, `launch-codex`) `setup-claude` / `setup-codex` ଦ୍ୱାରା ଲିଖିତ
  ପ୍ରୋଫାଇଲ୍ ବାଛିବା ପାଇଁ `--profile <name>` ଗ୍ରହଣ କରନ୍ତି, ଏବଂ ଅନ୍ତର୍ନିହିତ
  `claude` / `codex` ବାଇନାରି ପାଇଁ ପାସ୍-ଥ୍ରୁ args ମଧ୍ୟ ଗ୍ରହଣ କରନ୍ତି।

ଇଣ୍ଟରାକ୍ଟିଭ୍ ପିକର୍ଟି setup ରେସିପିଗୁଡ଼ିକ ଦ୍ୱାରା ମଧ୍ୟ ସାଧାରଣ ଭାବେ ବ୍ୟବହୃତ ହୁଏ:

## ସ୍ଥାନୀୟ ବ୍ୟବହାର

`localhost:20128` ରେ OmniRoute ଚାଲୁଥିବାବେଳେ, ଆପଣଙ୍କ ଟୁଲ୍ ପାଇଁ ସେଟଅପ୍ କମାଣ୍ଡ୍ ଚଲାନ୍ତୁ। କାଟାଲଗ୍ ସ୍ଥାନୀୟ ସର୍ଭରରୁ ଫେଚ୍ କରାଯାଏ।

```bash
# Codex: ପ୍ରତ୍ୟେକ ମିଳିଥିବା ମଡେଲ୍ ପାଇଁ ~/.codex/ ରେ ଏକ ପ୍ରୋଫାଇଲ୍ ଲେଖନ୍ତୁ
omniroute setup-codex
codex --profile glm52            # ଏକ ଉତ୍ପନ୍ନ ପ୍ରୋଫାଇଲ୍ ବ୍ୟବହାର କରନ୍ତୁ

# Claude Code: ପ୍ରତି-ମଡେଲ୍ ପ୍ରୋଫାଇଲ୍ ଲେଖନ୍ତୁ, ତାପରେ ଗୋଟିଏ ଲଞ୍ଚ୍ କରନ୍ତୁ
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode: ସମସ୍ତ କାଟାଲଗ୍ ମଡେଲ୍ ସହିତ openai-ସୁସଙ୍ଗତ ପ୍ରଦାନକାରୀ ଲେଖନ୍ତୁ
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # {env:OMNIROUTE_API_KEY} ମାଧ୍ୟମରେ ସନ୍ଦର୍ଭିତ, କେବେବି ଡିସ୍କରେ ନୁହେଁ
opencode -m omniroute/glm/glm-5.2 "..."

# ସ୍ୱୟଂ-ଆବିଷ୍କାର ବିନା ଟୁଲ୍ସକୁ ଏକ ସ୍ପଷ୍ଟ ମଡେଲ୍ ଆବଶ୍ୟକ:
omniroute setup-aider --model glm/glm-5.2
omniroute setup-qwen --model qwen/qwen3.8-max-preview

# କିଛି ନ ଲେଖି ପୂର୍ବାବଲୋକନ କରନ୍ତୁ:
omniroute setup-continue --dry-run
```

କୌଣସି କନଫିଗ୍ ନ ଲେଖି ଲଞ୍ଚ୍ କରନ୍ତୁ (କେବଳ env-injection):

```bash

omniroute launch-codex           # Codex CLI → local OmniRoute
omniroute launch-codex --profile glm52

omniroute run codex --model openai/gpt-5.4 --dry-run --json
omniroute run aider --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen --model glm/glm-5.2 -- -p "reply OK"
```

## ଦୂରବର୍ତ୍ତୀ ବ୍ୟବହାର

`--remote` + `--api-key` ସହିତ ଯେକୌଣସି ସେଟଅପ୍ କମାଣ୍ଡକୁ ଏକ ଦୂରବର୍ତ୍ତୀ OmniRoute ଆଡ଼କୁ ନିର୍ଦ୍ଦେଶ କରନ୍ତୁ। କ୍ୟାଟାଲଗ୍ ଦୂରବର୍ତ୍ତୀ ସ୍ଥାନରୁ ଆଣାଯାଏ; କନଫିଗରେସନ୍ ଆପଣଙ୍କ ସ୍ଥାନୀୟ ମେସିନ୍ ରେ ଲେଖାଯାଏ।

```bash
# OpenCode against a remote VPS, keep only glm/kimi models
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx \
  --only glm,kimi
opencode -m omniroute/glm/glm-5.2 "..."   # export OMNIROUTE_API_KEY first

# Codex profiles from a remote catalog
omniroute setup-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Launch a CLI straight against the remote
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

ପ୍ରତ୍ୟେକ ଥର `--remote`/`--api-key` ପାସ୍ କରିବା ପରିବର୍ତ୍ତେ, ଏକଥର ଲଗ୍ ଇନ୍ କରନ୍ତୁ ଏବଂ **ସକ୍ରିୟ ପ୍ରସଙ୍ଗ**କୁ ସ୍ୱୟଂଚାଳିତ ଭାବରେ ସେଗୁଡିକ ଯୋଗାଇବାକୁ ଦିଅନ୍ତୁ:

```bash
omniroute connect 192.168.0.15        # mints a scoped token, stores the context
omniroute setup-codex                 # ← now uses the remote catalog
omniroute setup-opencode              # ← same
omniroute launch                      # ← Claude Code against the remote
```

ପ୍ରସଙ୍ଗ, ସ୍କୋପ୍ ଏବଂ ଟୋକେନ୍ ପରିଚାଳନା ପାଇଁ [ଦୂରବର୍ତ୍ତୀ ମୋଡ୍](./REMOTE-MODE.md) ଦେଖନ୍ତୁ।

## 5dive ଏଜେଣ୍ଟ ଫ୍ଲିଟ୍ସ

[5dive](https://5dive.ai) ଦୀର୍ଘ ସମୟ ଚାଲୁଥିବା କୋଡିଂ ଏଜେଣ୍ଟଗୁଡିକର ଏକ ଫ୍ଲିଟ୍ ଚଲାଏ, ପ୍ରତ୍ୟେକ ଏଜେଣ୍ଟ ନିଜ ୟୁନିକ୍ସ ବ୍ୟବହାରକାରୀ ଅଧୀନରେ ଏକ systemd ୟୁନିଟ୍। ଏହା ନିଜେ ଏକ କୋଡିଂ CLI ନୁହେଁ, ତେଣୁ `omniroute run` ଦ୍ୱାରା ଲଞ୍ଚ୍ କରିବାକୁ କିଛି ନାହିଁ - `5dive` ଏକ **କେବଳ କନଫିଗର୍** ଲକ୍ଷ୍ୟ।

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

ଉଭୟ ଫର୍ମ ଏକ 5dive **ପ୍ରମାଣୀକରଣ ପ୍ରୋଫାଇଲ୍** ଲେଖେ, ଏବଂ ସେହି ପ୍ରୋଫାଇଲ୍ ସହ ବାନ୍ଧା ହୋଇଥିବା ପ୍ରତ୍ୟେକ `claude` ସିଟ୍ ତା'ପରେ OmniRoute ସହ କଥା ହୁଏ। ଏହି ଲକ୍ଷ୍ୟ ପାଇଁ ତିନିଟି ନିର୍ଦ୍ଦିଷ୍ଟ ଅଟେ:

- **ଏହା ଫ୍ଲିଟ୍ ହୋଷ୍ଟରେ, root ଭାବରେ ଚାଲେ।** 5dive ର କ୍ରିୟାଗୁଡିକ ସ୍ଥାନୀୟ systemd ୟୁନିଟ୍ ଏବଂ ଏକ root ମାଲିକାନାରେ ଥିବା ଅବସ୍ଥା ଡିରେକ୍ଟୋରୀ ଉପରେ କାର୍ଯ୍ୟ କରେ; କୌଣସି ଦୂରବର୍ତ୍ତୀ ମୋଡ୍ ନାହିଁ। ଯେତେବେଳେ ଏହା ଇତିମଧ୍ୟରେ root ନୁହେଁ, ରେସିପି `sudo` ମାଧ୍ୟମରେ ପୁନଃ-ଏକ୍ସେକ୍ କରେ (`--no-sudo` ଏହାକୁ ବନ୍ଦ କରେ ଏବଂ କମାଣ୍ଡ ପ୍ରିଣ୍ଟ୍ କରେ)।
- **ଏଣ୍ଡପୋଇଣ୍ଟ `https://` ହେବା ଆବଶ୍ୟକ ଯଦି ଏହା loopback ନୁହେଁ।** ଏଜେଣ୍ଟର API କୀ ପ୍ରତ୍ୟେକ ଅନୁରୋଧରେ ସେହି URL ଉପରେ ଯାତ୍ରା କରେ, ଏବଂ 5dive ପ୍ଲେନଟେକ୍ସ୍ଟ off-box ଏଣ୍ଡପୋଇଣ୍ଟ ଅସ୍ୱୀକାର କରେ। ଏକ ବ୍ୟକ୍ତିଗତ LAN ଠିକଣା ସେଥିରେ ବ୍ୟତିକ୍ରମ ନୁହେଁ।
- **ପ୍ରତ୍ୟେକ ସିଟ୍ର ନିଜ ମଡେଲ୍ ପିନ୍ ପ୍ରୋଫାଇଲ୍ ଅପେକ୍ଷା ଶ୍ରେଷ୍ଠ।** ପ୍ରୋଫାଇଲ୍ `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` ବହନ କରେ, କିନ୍ତୁ ଏକ ସିଟ୍ ଯଦି ଏକ ଷ୍ଟକ୍ ମଡେଲ୍ id ସହ ପିନ୍ ହୋଇଥାଏ ତେବେ ଏହାର ପ୍ରଥମ ଟର୍ନ୍ _"There's an issue with the selected model"_ ସହ ବିଫଳ ହୁଏ। ସିଟ୍ଗୁଡିକୁ ମଧ୍ୟ ପିନ୍ କରିବାକୁ `--agent <name>` (ପୁନରାବୃତ୍ତିଯୋଗ୍ୟ) ପାସ୍ କରନ୍ତୁ; ଯେତେବେଳେ ଆପଣ ଏହା ନ କରନ୍ତି, ରେସିପି କମାଣ୍ଡ ପ୍ରିଣ୍ଟ୍ କରେ।

API କୀ 5dive କୁ **stdin** (`--api-key=-`) ମାଧ୍ୟମରେ ଦିଆଯାଏ, ତେଣୁ ଏହା କେବେ `ps` ଆଉଟପୁଟ୍ ରେ ଦେଖାଯାଏ ନାହିଁ।

ପ୍ରୋଫାଇଲ୍ କୁ ଏକ ଏକକ ମଡେଲ୍ ପରିବର୍ତ୍ତେ ଏକ OmniRoute **କମ୍ବୋ** ଆଡ଼କୁ ନିର୍ଦ୍ଦେଶ କରିବା ହିଁ ଫ୍ଲିଟ୍ ପ୍ରଦାତା ଫେଲୋଭର୍ ପ୍ରାପ୍ତ କରାଏ: ଯେତେବେଳେ [#11578](https://github.com/diegosouzapw/OmniRoute/issues/11578) ରେ ରେକର୍ଡ୍ ହୋଇଥିବା ରନ୍ ରେ ପ୍ରାଥମିକ ଏଣ୍ଡପୋଇଣ୍ଟ ଟର୍ନ୍ ମଧ୍ୟରେ ହାର୍ଡ-ଡାଉନ୍ ଗଲା, ଏଜେଣ୍ଟ ଫେଲବ୍ୟାକ୍ ଉପରେ ତା'ର ବାକି ପଦକ୍ଷେପ ସମାପ୍ତ କଲା ଏବଂ ସମସ୍ୟାକୁ କଦାପି ପ୍ରକାଶ କଲା ନାହିଁ।

## ଅଦ୍ୟତନ ସମୟରେ ସ୍ୱଦେଶୀ ନିର୍ଭରତା ରଖିବା: `--include=optional`

ଯେତେବେଳେ ଆପଣ `omniroute update` ସାହାଯ୍ୟରେ ଅଦ୍ୟତନ କରନ୍ତି (ନିଶ୍ଚିତ ହେବା ପରେ, କିମ୍ବା `--apply` ସହିତ), OmniRoute `--include=optional` ବେକଡ୍ ଇନ୍ କରି ଇନ୍ଷ୍ଟଲ୍ ଚଳାଏ:

```bash
npm install -g omniroute@latest --include=optional
```

ଏହା **ନୁହେଁ** ଆପଣ `omniroute update` କୁ ଦିଅନ୍ତି ସେହି ଫ୍ଲାଗ୍ — ଏହା ସର୍ବଦା ଅଦ୍ୟତନକାରୀ ଦ୍ୱାରା ପ୍ରୟୋଗ ହୁଏ। ଏହା `optionalDependencies` (`better-sqlite3`, `keytar`, `tls-client`, LLMLingua SLM ଷ୍ଟ୍ୟାକ୍) କୁ ଅଦ୍ୟତନ ପରେ ମଧ୍ୟ ଜୀବିତ ରଖେ ଯଦି ଆପଣଙ୍କ npm କନ୍ଫିଗ୍ ରେ `omit=optional` ସେଟ୍ ଅଛି, ଯାହା ଅନ୍ୟଥା ନିରୁତ୍ସାହରେ ସ୍ୱଦେଶୀ SQLite ଡ୍ରାଇଭର୍ ଏବଂ OS-keyring ବାଇଣ୍ଡିଂ କୁ ଛାଡି ଦିଏ। ବାସ୍ତବିକ ନକଲି କମାଣ୍ଡ ପୂର୍ବାବଲୋକନ କରିବା ପାଇଁ:

```bash
omniroute update --dry-run
# [DRY RUN] Would run: npm install -g omniroute@latest --include=optional
```

ଅନ୍ୟାନ୍ୟ `omniroute update` ଫ୍ଲାଗ୍ (ସୋର୍ସରେ ଯାଞ୍ଚ କରାଯାଇଛି): `--check` (ପୁରୁଣା ଥିଲେ exit 1), `--apply` (ପ୍ରମ୍ପ୍ଟ୍ ନକରି ଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ), `--changelog`, `--no-backup`, `--yes`।

## `omniroute run gemini` ମାଧ୍ୟମରେ Google Gemini CLI

`@google/gemini-cli` 0.50.0 ସାଙ୍ଗରେ ଯାଞ୍ଚ କରାଯାଇଥିବା ଚୁକ୍ତି: CLI `GOOGLE_GEMINI_BASE_URL` କୁ ସମ୍ମାନ ଦିଏ ଏବଂ ତାହା ବିରୁଦ୍ଧରେ `POST /v1beta/models/<model>:generateContent` (ଏବଂ `:streamGenerateContent?alt=sse`) ଜାରି କରେ — ସମ୍ପୂର୍ଣ୍ଣ ରୂପେ OmniRoute ର ସ୍ୱଦେଶୀ Gemini ସର୍ଫେସ୍ (`/v1beta`)। `omniroute run gemini` ସ୍ୱୟଂଚାଳିତ ଭାବରେ ସେହି ଯୋଡ଼େ:

- `GOOGLE_GEMINI_BASE_URL` → ସକ୍ରିୟ OmniRoute ମୂଳ URL (ମୂଳ, `/v1` ନାହିଁ);
- `GEMINI_API_KEY` → ସମାଧାନ ହୋଇଥିବା OmniRoute ପ୍ରମାଣପତ୍ର (ବିକଳ୍ପ/env/context);
- ଏକ **ଅସ୍ଥାୟୀ ଏକାକୀ `GEMINI_CLI_HOME`** ଯାହାର `.gemini/settings.json` `gemini-api-key` ଅଧିକାର ବାଛେ, ଯେପରିକି ସଂରକ୍ଷିତ Google OAuth ସେସନ୍ (Code Assist) କଦାପି OmniRoute-ନିର୍ଦ୍ଦେଶିତ ଲଞ୍ଚକୁ ଓଭରାଇଡ୍ ନକରେ — ବାହାରିବା ପରେ ହଟାଯାଏ;
- **env ସ୍ୱଚ୍ଛତା**: ପୁତ୍ର env ରୁ `GOOGLE_API_KEY`, `GOOGLE_GENAI_USE_VERTEXAI` ଏବଂ `GOOGLE_GENAI_USE_GCA` ସଫା କରାଯାଏ (ଯାହା Vertex/Code Assist କୁ ଅଧିକାର ରିଡାଇରେକ୍ଟ କରିବ), ଏବଂ `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key` ଏକ ବେଲ୍ଟ-ଏଣ୍ଡ-ସୁସ୍ପେନ୍ଡର୍ ଫଲ୍ବ୍ୟାକ୍ ଭାବରେ ସେଟ୍ ହୁଏ — ଅନ୍ୟ `run` ଟାର୍ଗେଟ୍ ମାନେ ସେମାନଙ୍କ ନିଜ ଦ୍ୱନ୍ଦ୍ୱପୂର୍ଣ୍ଣ ଭେରିଆବଲ୍ ପାଇଁ ସମାନ ଚିକିତ୍ସା ପାଆନ୍ତି;
- `--provider`/`--model` ରୁ `--model <id>` ଇଞ୍ଜେକ୍ସନ୍।

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

ହେଡଲେସ୍ ମୋଡରେ Gemini ର ୱାର୍କସ୍ପେସ୍-ଟ୍ରଷ୍ଟ ଗାର୍ଡ୍ ଏପରି ମଧ୍ୟ ପ୍ରୟୋଗ ହୁଏ — ସ୍ୱୟଂ `--skip-trust` ପାସ୍ କରନ୍ତୁ (କିମ୍ବା ଇଣ୍ଟରାକ୍ଟିଭଲି ଡାଇରେକ୍ଟୋରୀକୁ ବିଶ୍ୱାସ କରନ୍ତୁ); ଲଞ୍ଚର ସେ ଜାଣିଶୁଣି ଏହାକୁ ବାଇପାସ୍ କରେ ନାହିଁ। ଏହି ଲଞ୍ଚର **ACP ପଞ୍ଜୀକରଣ** (`src/lib/acp/registry.ts`, `gemini --acp`) ଠାରୁ ଭିନ୍ନ, ଯାହା `/dashboard/acp-agents` ପାଇଁ ଏଜେଣ୍ଟ-ପ୍ରୋଟୋକଲ ଇଣ୍ଟଗ୍ରେସନ୍ ହୋଇ ରହେ।

## ପ୍ରକୃତ ଧୂଆଁ ସ୍ୱିପ (ବିକଳ୍ପ)

CI ରେ ନିଶ୍ଚିତ ଲଞ୍ଚ-ଯୋଜନା ପ୍ରତିଗମନ ରନ୍ (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`)। ପ୍ରକୃତ ବାଇନାରୀଗୁଡିକୁ ପ୍ରକୃତ
OmniRoute ସର୍ଭର ସହ ଯାଞ୍ଚ କରିବା ପାଇଁ, ଏକ ବିକଳ୍ପ ହାର୍ନେସ୍ ଅଛି
`tests/integration/upstream-cli-smoke.int.test.ts` ରେ। ଏହା ସ୍ୱୟଂଚାଳିତ ଭାବେ କଦାପି ଚାଲେ ନାହିଁ
(ପ୍ରତ୍ୟେକ ଉପ-ପରୀକ୍ଷଣ `RUN_CLI_SMOKE=1` ନଥିଲେ ଛାଡ଼ି ଦିଏ), ସାଖ୍ୟାତାକୁ ଏନଭାର୍ଯ୍ୟ ଭେରିଏବଲ୍ NAME
ଦ୍ୱାରା ପାସ୍ କରେ (ମୂଲ୍ୟ ଦ୍ୱାରା କଦାପି ନୁହେଁ), ଯେକୌଣସି ରେକର୍ଡ୍ ଆଉଟପୁଟ୍ ରୁ କୀ-ଆକାରର ଷ୍ଟ୍ରିଙ୍ଗ୍ ଲୁଚାଏ,
ଯେଉଁ ଟାର୍ଗେଟ୍ ର ବାଇନାରୀ ଇନ୍ଷ୍ଟଲ୍ ହୋଇ ନାହିଁ ସେଗୁଡିକୁ ଛାଡ଼ି ଦିଏ, ଏବଂ ବିଫଳତାଗୁଡିକୁ
auth / upstream / config ଭାବେ ଶ୍ରେଣୀଭୁକ୍ତ କରେ ଏକ ଖାଲି ବୁଲିଆନ୍ ପରିବର୍ତ୍ତେ:

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

ବିକଳ୍ପ: `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` ସ୍ୱିପ୍ କୁ ସୀମିତ କରେ;
`OMNIROUTE_SMOKE_TIMEOUT_MS` ପ୍ରତି-ଟାର୍ଗେଟ୍ 120s ସମୟସୀମାକୁ ଓଭରରାଇଡ୍ କରେ।
