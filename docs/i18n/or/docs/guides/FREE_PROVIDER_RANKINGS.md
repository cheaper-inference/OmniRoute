> **TL;DR**: OmniRoute ଏହାର **ମାଗଣା** ପ୍ରଦାନକାରୀମାନଙ୍କୁ ମଡେଲ୍ର ଗୁଣବତ୍ତା ଅନୁସାରେ **Arena AI
> (LMArena-ଶୈଳୀ) ELO ସ୍କୋର୍** ବ୍ୟବହାର କରି ରାଙ୍କ୍ କରେ। ଆପଣଙ୍କ କାର୍ଯ୍ୟ ପାଇଁ କେଉଁ ମାଗଣା ପ୍ରଦାନକାରୀ ସବୁଠାରୁ ଶକ୍ତିଶାଳୀ ମଡେଲ୍ ପ୍ରଦାନ କରନ୍ତି ତାହା ଦେଖିବାକୁ
> ଡ୍ୟାସ୍ବୋର୍ଡ୍ରେ **Free Provider Rankings** ପୃଷ୍ଠା ଖୋଲନ୍ତୁ —
> ସାମଗ୍ରିକ ଭାବରେ କିମ୍ବା ବର୍ଗ ଅନୁସାରେ ଫିଲ୍ଟର୍ କରି (କୋଡିଂ, ସମୀକ୍ଷା, ଡକ୍ୟୁମେଣ୍ଟେସନ୍, ଡିବଗିଂ)।

## ଏହା କ’ଣ

OmniRoute 376ଟି ପ୍ରଦାନକାରୀଙ୍କୁ ପଞ୍ଜୀକୃତ କରେ, ଯେଉଁଥିରେ **ମାଗଣା/ପ୍ରମାଣୀକରଣ-ବିହୀନ** ଭାବେ ଚିହ୍ନିତ 155ଟି କ୍ୟାଟାଲଗ୍ ଏଣ୍ଟ୍ରି ଅନ୍ତର୍ଭୁକ୍ତ
(ପ୍ରମାଣୀକରଣ-ବିହୀନ,
ମାଗଣା-ସ୍ତର OAuth, କିମ୍ବା ମାଗଣା-ସ୍ତର API କୀ —
[ମାଗଣା ସ୍ତର ଗାଇଡ୍](../getting-started/FREE-TIERS-GUIDE.md) ଏବଂ ସମ୍ପୂର୍ଣ୍ଣ
[ମାଗଣା ସ୍ତର ଡିରେକ୍ଟୋରୀ](../reference/FREE_TIERS.md) ଦେଖନ୍ତୁ)। କିନ୍ତୁ ସମସ୍ୟା ହେଉଛି: ମାଗଣା ପ୍ରଦାନକାରୀମାନଙ୍କର ମଡେଲ୍ ଗୁଣବତ୍ତାରେ
ବ୍ୟାପକ ଭିନ୍ନତା ରହିଛି। ଏକ ଅତ୍ୟାଧୁନିକ ମଡେଲ୍ ପ୍ରଦାନ କରୁଥିବା ପ୍ରମାଣୀକରଣ-ବିହୀନ ପ୍ରଦାନକାରୀ,
ଏକ ଛୋଟ ପୁରୁଣା ମଡେଲ୍ ପ୍ରଦାନ କରୁଥିବା ପ୍ରଦାନକାରୀ ତୁଳନାରେ ଅଧିକ ଉପଯୋଗୀ।

**ମାଗଣା ପ୍ରଦାନକାରୀ ମାନ୍ୟତା** ପ୍ରତ୍ୟେକ ମାଗଣା ପ୍ରଦାନକାରୀଙ୍କ କ୍ୟାଟାଲଗ୍କୁ
**Arena AI ଲିଡରବୋର୍ଡ**ରୁ ପ୍ରାପ୍ତ **ସମୂହ-ଉତ୍ସ ଗୁଣବତ୍ତା ସ୍କୋର୍** ସହିତ ଯୋଡ଼ି "**କେଉଁ ମାଗଣା ପ୍ରଦାନକାରୀ ମୋତେ ସର୍ବୋତ୍ତମ ମଡେଲ୍ ଦିଅନ୍ତି?**" ପ୍ରଶ୍ନର ଉତ୍ତର ଦିଏ
(ମାନବ-ପସନ୍ଦ ELO, LMArena
ଚାଟ୍ବଟ୍ ଆରେନାର ଅନ୍ତର୍ନିହିତ ଧାରଣା ସହ ସମାନ)। ତା’ପରେ ପ୍ରଦାନକାରୀମାନଙ୍କୁ ସେମାନଙ୍କର **ସର୍ବୋତ୍ତମ ମାଗଣା ମଡେଲ୍**ର କ୍ଷମତା ଅନୁସାରେ ମାନ୍ୟତା ଦିଆଯାଏ।

ଏହି ମାନ୍ୟତା ତିନୋଟି ବାସ୍ତବ ଉତ୍ସରୁ ଗଣନା କରାଯାଏ:

1. ମାଗଣା-ପ୍ରଦାନକାରୀ ତାଲିକାଗୁଡ଼ିକ — `NOAUTH_PROVIDERS`, ଏବଂ `hasFree` ଭାବେ ଚିହ୍ନିତ `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ
   (`src/shared/constants/providers.ts`)।
2. ପ୍ରଦାନକାରୀ ରେଜିଷ୍ଟ୍ରିରୁ ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀଙ୍କ ମଡେଲ୍ କ୍ୟାଟାଲଗ୍
   (`open-sse/config/providerRegistry.ts`)।
3. Arena ELO ସିଙ୍କ୍ ଇଞ୍ଜିନ୍ (`src/lib/arenaEloSync.ts`) ଦ୍ୱାରା `model_intelligence` DB ଟେବୁଲ୍ରେ ସଂରକ୍ଷିତ
   ELO-ଉତ୍ପନ୍ନ କାର୍ଯ୍ୟ-ଉପଯୁକ୍ତତା ସ୍କୋର୍।

ଯୋଡ଼ାଣି ତର୍କ `src/lib/freeProviderRankings.ts`ରେ ରହିଛି।

## କିପରି ପ୍ରବେଶ କରିବେ

### ଡ୍ୟାସ୍ବୋର୍ଡ୍ ପୃଷ୍ଠା

ଡ୍ୟାସ୍ବୋର୍ଡ୍ ଖୋଲି **Costs → Free Provider Rankings**-କୁ ଯାଆନ୍ତୁ, କିମ୍ବା ସିଧାସଳଖ ଏଠାକୁ ନେଭିଗେଟ୍ କରନ୍ତୁ:

```
/dashboard/free-provider-rankings
```

ଏହି ପୃଷ୍ଠା (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) ଦେଖାଏ:

- ସର୍ବୋତ୍ତମ ରାଙ୍କ୍ ପାଇଥିବା ମାଗଣା ପ୍ରଦାନକାରୀମାନଙ୍କର ଏକ **ଶୀର୍ଷ-3 ପୋଡିୟମ୍** (🥇 🥈 🥉)।
- ଏହି ସ୍ତମ୍ଭଗୁଡ଼ିକ ସହିତ ଏକ ସମ୍ପୂର୍ଣ୍ଣ **ରାଙ୍କିଂ ଟେବୁଲ୍**: **ରାଙ୍କ୍**, **ପ୍ରଦାନକାରୀ**, **ଶୀର୍ଷ ମଡେଲ୍**,
  **ସ୍କୋର୍**, **ହାରାହାରି ସ୍କୋର୍**, **ମଡେଲ୍ଗୁଡ଼ିକ**, **ପ୍ରକାର**।
- **ବର୍ଗ ଫିଲ୍ଟର୍ ବଟନ୍ଗୁଡ଼ିକ**: _ସମସ୍ତ ବର୍ଗ_, _ଡିଫଲ୍ଟ_, _କୋଡିଂ_, _ସମୀକ୍ଷା_,
  _ଡକ୍ୟୁମେଣ୍ଟେସନ୍_, _ଡିବଗିଂ_।

ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀଙ୍କ **ପ୍ରକାର** ବ୍ୟାଜ୍ ଏହା କିପରି ମାଗଣା ତାହା ଜଣାଏ:

| ବ୍ୟାଜ୍   | ଅର୍ଥ                                               |
| -------- | -------------------------------------------------- |
| `NOAUTH` | ସର୍ବଦା ମାଗଣା, କୌଣସି ପ୍ରମାଣପତ୍ର ଆବଶ୍ୟକ ନାହିଁ        |
| `OAUTH`  | ଏକ ମାଗଣା ଟିୟର୍ (`hasFree`) ଥିବା OAuth ପ୍ରଦାନକାରୀ   |
| `APIKEY` | ଏକ ମାଗଣା ଟିୟର୍ (`hasFree`) ଥିବା API-key ପ୍ରଦାନକାରୀ |

ସ୍କୋର୍ଗୁଡ଼ିକ କଞ୍ଚା ସଂଖ୍ୟା ବଦଳରେ ମଣିଷ ପାଇଁ ସହଜବୋଧ୍ୟ ଲେବଲ୍ (ଯେପରିକି _ଶ୍ରେଷ୍ଠ_, _ଅତ୍ୟୁତ୍ତମ_, _ବହୁତ ଭଲ_,
_ଭଲ_, _ହାରାହାରି_) ଭାବେ ଦେଖାଯାଏ, କାରଣ ଅନ୍ତର୍ନିହିତ ମୂଲ୍ୟଟି ଏକ ଆପେକ୍ଷିକ
ରାଙ୍କିଂ ଗୁଣବତ୍ତା, ଶତକଡ଼ା ନୁହେଁ।

### API ଏଣ୍ଡପଏଣ୍ଟ୍

ଏହି ପୃଷ୍ଠାଟି ଏକ ସାର୍ବଜନୀନ ରିଡ୍ ଏଣ୍ଡପଏଣ୍ଟ୍
(`src/app/api/free-provider-rankings/route.ts`) ଦ୍ୱାରା ସମର୍ଥିତ:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

କ୍ୱେରି ପାରାମିଟର୍ଗୁଡ଼ିକ (Zod ସହିତ ବୈଧୀକୃତ):

| ପାରାମିଟର୍  | ପ୍ରକାର | ଡିଫଲ୍ଟ       | ଟିପ୍ପଣୀ                                                                                                             |
| ---------- | ------ | ------------ | ------------------------------------------------------------------------------------------------------------------- |
| `category` | string | (କିଛି ନାହିଁ) | `default`, `coding`, `review`, `documentation`, `debugging` ମଧ୍ୟରୁ ଗୋଟିଏ। ସଂଯୁକ୍ତ ରାଙ୍କିଂ ପାଇଁ ଏହାକୁ ଛାଡ଼ି ଦିଅନ୍ତୁ। |
| `limit`    | number | `50`         | `1–100` ପରିସର ମଧ୍ୟରେ ସୀମିତ।                                                                                         |

ପ୍ରତିକ୍ରିୟାର ଗଠନ:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` ହେଉଛି ମୂଳ Arena ELO ମୂଲ୍ୟ; `score` ହେଉଛି ସାମାନ୍ୟୀକୃତ ଟାସ୍କ୍-ଫିଟ୍ ମୂଲ୍ୟ
(ନିମ୍ନରେ ଦେଖନ୍ତୁ)। କୌଣସି ସ୍କୋର୍ ହୋଇଥିବା ମଡେଲ୍ ନଥିବା ପ୍ରଦାନକାରୀମାନଙ୍କୁ ପ୍ରତିକ୍ରିୟାରୁ ବାଦ ଦିଆଯାଏ।

## ସ୍କୋରଗୁଡ଼ିକ କିପରି କାମ କରନ୍ତି

### ଉତ୍ସ: Arena AI ଲିଡରବୋର୍ଡ

Arena ELO ସିଙ୍କ ଇଞ୍ଜିନ (`src/lib/arenaEloSync.ts`) Arena AI ଲିଡରବୋର୍ଡ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) ରୁ ଦୁଇଟି ଲିଡରବୋର୍ଡ — `text`
ଏବଂ `code` — ଆଣିଥାଏ। ଯେତେବେଳେ ସେହି API କୌଣସି ବ୍ୟବହାରଯୋଗ୍ୟ ବୋର୍ଡ ଫେରାଇ ନଥାଏ, ଇଞ୍ଜିନ
Hugging Face datasets-server ଉପରେ ଥିବା ଅଫିସିଆଲ୍ `lmarena-ai/leaderboard-dataset` କୁ
ଫଲବ୍ୟାକ୍ କରିଥାଏ (`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` `activeSource`, `lastError` ଏବଂ
`lastFailedAt` ରିପୋର୍ଟ କରିଥାଏ। ପ୍ରତ୍ୟେକ ଲିଡରବୋର୍ଡ ଏଣ୍ଟ୍ରି ଏକ ମଡେଲ ନାମ, ଭେଣ୍ଡର, ELO `score`,
କନଫିଡେନ୍ସ ଇଣ୍ଟରଭାଲ୍ ଏବଂ ଭୋଟ୍ ସଂଖ୍ୟା ବହନ କରିଥାଏ।

ଲିଡରବୋର୍ଡ ବର୍ଗଗୁଡ଼ିକ OmniRoute ଟାସ୍କ୍ ବର୍ଗଗୁଡ଼ିକ ସହ ମ୍ୟାପ୍ ହୋଇଥାଆନ୍ତି:

| Arena ଲିଡରବୋର୍ଡ | OmniRoute ଟାସ୍କ୍ ବର୍ଗଗୁଡ଼ିକ                       |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### ନର୍ମାଲାଇଜେସନ୍ (task-fit ସ୍କୋର)

ମୌଳିକ ELO ସ୍କୋରଗୁଡ଼ିକ ପ୍ରତି ଲିଡରବୋର୍ଡରେ **`[0.4, 0.98]` ଭିତରେ ଏକ task-fit ମୂଲ୍ୟ** କୁ
ନର୍ମାଲାଇଜ୍ ହୋଇଥାଆନ୍ତି:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

ସ୍କୋର କେବେବି `0` କିମ୍ବା `1` ଛୁଏଁ ନାହିଁ, ଯାହା ଉପଭୋକ୍ତା ଓଭରରାଇଡ୍ ପାଇଁ ଅବକାଶ ଛାଡ଼ିଥାଏ। ଏହା
ହେଉଛି ସେହି `score` ଫିଲ୍ଡ ଯାହା ଆପଣ API ରେସପନ୍ସରେ ଦେଖନ୍ତି ଏବଂ ଡ୍ୟାସବୋର୍ଡରେ ଦେଖାଯାଉଥିବା
ଲେବଲ୍ ମଧ୍ୟ ଅଟେ।

### କନଫିଡେନ୍ସ

ପ୍ରତ୍ୟେକ ଏଣ୍ଟ୍ରି Arena ଭୋଟ୍ ସଂଖ୍ୟା ଆଧାରରେ ଏକ କନଫିଡେନ୍ସ ସ୍ତର ପାଇଥାଏ:

| କନଫିଡେନ୍ସ | ଭୋଟ୍    |
| --------- | ------- |
| `high`    | ≥ 5,000 |
| `medium`  | ≥ 1,000 |
| `low`     | < 1,000 |

### ଷ୍ଟୋରେଜ୍ ଏବଂ ସତେଜତା

ନର୍ମାଲାଇଜ୍ ହୋଇଥିବା ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ `source = "arena_elo"` ସହ `model_intelligence` DB
ଟେବୁଲକୁ ଲେଖାଯାଇଥାଏ (`src/lib/db/modelIntelligence.ts`)। ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ **7 ଦିନ ପରେ ସମାପ୍ତ
ହୋଇଯାଆନ୍ତି**, ତେଣୁ ସିଙ୍କ ବନ୍ଦ କରିଦେଉଥିବା ପ୍ରୋଭାଇଡର ପୁରୁଣା ଡାଟା ଦେଖାଇବା ବଦଳରେ ଧିରେ ଧିରେ
ବାଦ୍ ପଡ଼ିଯାଇଥାଏ।

ସିଙ୍କ **ଡିଫଲ୍ଟରୂପେ ଚାଲୁ** ଥାଏ:

- ଏହା ସର୍ଭର ଷ୍ଟାର୍ଟଅପ୍ ସମୟରେ ଥରେ ଚାଲିଥାଏ ଏବଂ ତାପରେ ଏକ ପର୍ଯ୍ୟାୟକ୍ରମିକ ଟାଇମରରେ ଚାଲିଥାଏ
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` ରୁ ୱାୟାର୍ ହୋଇଛି)।
- ଏହା **ନନ-ବ୍ଲକିଂ ଏବଂ କେବେବି ଫାଟାଲ୍ ନୁହେଁ** — ଯଦି ଅପଷ୍ଟ୍ରିମ୍ ଫେଚ୍ ବିଫଳ ହୁଏ, OmniRoute
  ଚାଲୁ ରହିଥାଏ ଏବଂ ର୍ୟାଙ୍କିଂଗୁଡ଼ିକ କେବଳ ଶେଷ ଭଲ ଡାଟା (କିମ୍ବା ଏକ ଖାଲି ଅବସ୍ଥା) ଦେଖାଇଥାଏ।

ଦୁଇଟି ଏନଭାଇରନମେଣ୍ଟ ଭେରିଏବଲ୍ ଏହାକୁ ନିୟନ୍ତ୍ରଣ କରିଥାଆନ୍ତି ([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) ରେ ଡକ୍ୟୁମେଣ୍ଟ୍ ହୋଇଛି):

| ଭେରିଏବଲ୍                  | ଡିଫଲ୍ଟ୍       | ଉଦ୍ଦେଶ୍ୟ                                              |
| ------------------------- | ------------- | ----------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | ଆଉଟବାଉଣ୍ଡ୍ ସିଙ୍କରୁ ଦୂରେଇ ରହିବାକୁ `false` ସେଟ୍ କରନ୍ତୁ। |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | ସିଙ୍କ ବ୍ୟବଧାନ, ସେକେଣ୍ଡରେ।                             |

### ମାନୁଆଲ୍ ସିଙ୍କ / ସ୍ଥିତି / ସଫା କରିବା

ଅପରେଟରମାନଙ୍କ ପାଇଁ, ଏକ ପ୍ରମାଣିତ ମ୍ୟାନେଜମେଣ୍ଟ ଏଣ୍ଡପଏଣ୍ଟ ମାନୁଆଲ୍ ନିୟନ୍ତ୍ରଣ ଉପଲବ୍ଧ କରାଇଥାଏ
(`src/app/api/intelligence/sync/route.ts` — ମ୍ୟାନେଜମେଣ୍ଟ ଅଥ୍ ଆବଶ୍ୟକ):

```
GET    /api/intelligence/sync          # ବର୍ତ୍ତମାନର ସିଙ୍କ ସ୍ଥିତି (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # ମାନୁଆଲ୍ ସିଙ୍କ ଟ୍ରିଗର କରନ୍ତୁ; body: { "dryRun": true } ଲେଖା ନ କରି ପୂର୍ବାବଲୋକନ କରିବା ପାଇଁ
DELETE /api/intelligence/sync          # ସମସ୍ତ ସିଙ୍କ ହୋଇଥିବା arena_elo ଇଣ୍ଟେଲିଜେନ୍ସ ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ ସଫା କରନ୍ତୁ
```

ଯଦି ର୍ୟାଙ୍କିଂ ପୃଷ୍ଠା ଖାଲି ଥାଏ, ଏକ ମାନୁଆଲ୍ `POST /api/intelligence/sync` (କିମ୍ବା କେବଳ
ସର୍ଭରକୁ ପୁନଃଆରମ୍ଭ କରିବା) ଏହାକୁ ପୁଣି ଭର୍ତ୍ତି କରିଦିଏ।

### ଲିଡରବୋର୍ଡ ସହ ମଡେଲଗୁଡ଼ିକୁ ମେଳ କରିବା

ରେଜିଷ୍ଟ୍ରି ମଡେଲ ID ଏବଂ Arena ମଡେଲ ନାମ ସବୁବେଳେ ଠିକ୍ ଭାବରେ ମେଳ ଖାଆନ୍ତି ନାହିଁ। ର୍ୟାଙ୍କିଂ
ଫ୍ଲେକ୍ସିବଲ୍ ମ୍ୟାଚିଂ ବ୍ୟବହାର କରିଥାଏ (`src/lib/freeProviderRankings.ts` ରେ
`findMatchingIntelligence`):

1. ନର୍ମାଲାଇଜ୍ ହୋଇଥିବା ମଡେଲ ID ଉପରେ ସଠିକ୍ ମେଳ।
2. ଶେଷାନ୍ତ ଭର୍ସନ୍ ସଫିକ୍ସ କାଢ଼ିଦେଲା ପରେ ମେଳ (ଉଦା. `kimi-k2.6` → `kimi-k2`)।
3. ପ୍ରିଫିକ୍ସ ମେଳ (ଏକ ଲିଡରବୋର୍ଡ ମଡେଲ ନାମ ରେଜିଷ୍ଟ୍ରି ID ର ପ୍ରିଫିକ୍ସ ଅଟେ)।

ସିଙ୍କ ପାର୍ଶ୍ୱରେ, ଜଣା ଭେଣ୍ଡର ପ୍ରିଫିକ୍ସଗୁଡ଼ିକ (`anthropic/`, `openai/`, `google/`, …) କାଢ଼ି
ଦିଆଯାଇଥାଏ ଏବଂ ଏକ ଛୋଟ ଆଲିୟାସ୍ ମ୍ୟାପ୍ କାନୋନିକାଲ୍ ନାମଗୁଡ଼ିକୁ OmniRoute ଆଭ୍ୟନ୍ତରୀଣ ଭାବରେ
ବ୍ୟବହାର କରୁଥିବା ଭେରିଆଣ୍ଟଗୁଡ଼ିକରେ ବିସ୍ତାର କରିଥାଏ, ଯାହାଦ୍ୱାରା ମଡେଲଗୁଡ଼ିକ ଯେକୌଣସି ନାମ ଅଧୀନରେ
ଖୋଜି ହୋଇପାରନ୍ତି।

### ଏକ ପ୍ରୋଭାଇଡର କିପରି ର୍ୟାଙ୍କ୍ ହୁଏ

ପ୍ରତ୍ୟେକ ମାଗଣା ପ୍ରୋଭାଇଡର ପାଇଁ, ଇଞ୍ଜିନ ତାହାର କାଟାଲଗ୍ ରେ ଥିବା ପ୍ରତ୍ୟେକ ମଡେଲକୁ ସ୍କୋର କରିଥାଏ,
ତାପରେ:

- **ଶୀର୍ଷ ମଡେଲ** = ପ୍ରୋଭାଇଡରର ସର୍ବାଧିକ ସ୍କୋର କରୁଥିବା ମଡେଲ।
- **ହାରାହାରି ସ୍କୋର** = ସେହି ପ୍ରୋଭାଇଡରର ସମସ୍ତ ସ୍କୋର ହୋଇଥିବା ମଡେଲଗୁଡ଼ିକର ହାରାହାରି ସ୍କୋର।
- **ମଡେଲଗୁଡ଼ିକ** = ପ୍ରୋଭାଇଡରର କେତେଗୁଡ଼ିଏ ମଡେଲର Arena ସ୍କୋର ଥିଲା।

ପ୍ରୋଭାଇଡରଗୁଡ଼ିକ ପ୍ରଥମେ **ଶୀର୍ଷ-ମଡେଲ ସ୍କୋର** ଅନୁଯାୟୀ, ତାପରେ ହାରାହାରି ସ୍କୋର ଅନୁଯାୟୀ
ସଜାଯାଆନ୍ତି। ଏହା ସେହି ପ୍ରୋଭାଇଡରକୁ ପୁରସ୍କୃତ କରିଥାଏ ଯିଏ ଅତିକମରେ ଗୋଟିଏ ଶକ୍ତିଶାଳୀ ମାଗଣା ମଡେଲ
ଉପଲବ୍ଧ କରାଇଥାଏ।

## ମାଗଣା ପ୍ରଦାତା ବାଛିବା ପାଇଁ ଏହାର ବ୍ୟବହାର

1. **ସଠିକ୍ ବର୍ଗ ବାଛନ୍ତୁ।** ଏଜେଣ୍ଟ-ଆଧାରିତ/କୋଡ୍ ୱାର୍କଲୋଡ୍ ପାଇଁ **Coding** ଫିଲ୍ଟର୍ ବ୍ୟବହାର କରନ୍ତୁ, କିମ୍ବା
   ସାଧାରଣ ଚାଟ୍ ପାଇଁ ଏହାକୁ **All Categories** / **Default**ରେ ରଖନ୍ତୁ। ପ୍ରତ୍ୟେକ ଲିଡର୍ବୋର୍ଡରେ ଏକ ପ୍ରଦାତାର ଶ୍ରେଷ୍ଠ ମଡେଲ୍ ଭିନ୍ନ ହୋଇଥିବାରୁ,
   ସେହି ପ୍ରଦାତା ବିଭିନ୍ନ ବର୍ଗରେ ଭିନ୍ନ ସ୍ଥାନ ପାଇପାରେ।
2. **ଏକକ-ସେଟ୍ଅପ୍ ପାଇଁ ଶୀର୍ଷ ସ୍ଥାନଗୁଡ଼ିକୁ ପ୍ରାଧାନ୍ୟ ଦିଅନ୍ତୁ।** ଯଦି ଆପଣ କେବଳ ଗୋଟିଏ କିମ୍ବା ଦୁଇଟି ମାଗଣା
   ପ୍ରଦାତାଙ୍କୁ ସଂଯୋଗ କରିବାକୁ ଚାହାନ୍ତି, ତେବେ ନିଜ ବର୍ଗରେ ସର୍ବୋଚ୍ଚ ମାନ୍ୟତାପ୍ରାପ୍ତ ପ୍ରଦାତାଙ୍କଠାରୁ ଆରମ୍ଭ କରନ୍ତୁ।
3. **Type ବ୍ୟାଜ୍ ଯାଞ୍ଚ କରନ୍ତୁ।** `NOAUTH` ପ୍ରଦାତାମାନଙ୍କୁ ସବୁଠାରୁ ଶୀଘ୍ର ସଂଯୋଗ କରାଯାଇପାରେ (କୌଣସି
   ପରିଚୟପତ୍ର ଆବଶ୍ୟକ ନାହିଁ)। `OAUTH` / `APIKEY` ମାଗଣା ସ୍ତରଗୁଡ଼ିକ ପାଇଁ ଶୀଘ୍ର ସାଇନ୍-ଅପ୍ ଆବଶ୍ୟକ, କିନ୍ତୁ ସେଗୁଡ଼ିକ ପ୍ରାୟତଃ
   ଅଧିକ ଶକ୍ତିଶାଳୀ ମଡେଲ୍ ଉପଲବ୍ଧ କରାନ୍ତି। ସଂଯୋଗ ପଦକ୍ଷେପ ପାଇଁ
   [ମାଗଣା ସ୍ତର ମାର୍ଗଦର୍ଶିକା](../getting-started/FREE-TIERS-GUIDE.md) ଦେଖନ୍ତୁ।
4. **ଏକାଧିକ ପ୍ରଦାତାଙ୍କୁ ସଂଯୋଗ କରନ୍ତୁ ଏବଂ Auto-Comboକୁ ନିଷ୍ପତ୍ତି ନେବାକୁ ଦିଅନ୍ତୁ।** ଏହି ପୃଷ୍ଠାକୁ ପରିଚାଳିତ କରୁଥିବା ସମାନ Arena ELO ଡାଟା
   Auto-Combo ସ୍କୋରିଂ ଇଞ୍ଜିନ୍ର **କାର୍ଯ୍ୟ-ଉପଯୋଗିତା ଗୁଣକ**କୁ ମଧ୍ୟ ଯୋଗାଇଥାଏ
   (`open-sse/services/autoCombo/taskFitness.ts`, ସମାଧାନ କ୍ରମ
   `user_override → arena_elo → models_dev_tier → static table`)। ତେଣୁ ଆପଣ ଶୀର୍ଷ ମାଗଣା ପ୍ରଦାତାଙ୍କୁ ସଂଯୋଗ କରିବା ପରେ,
   `model: "auto"` (ଯଥା `auto/coding`) ସହିତ ରାଉଟିଂ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ
   ଉଚ୍ଚ-ଗୁଣବତ୍ତାର ମାଗଣା ମଡେଲ୍ଗୁଡ଼ିକୁ ସ୍ୱୟଂଚାଳିତ ଭାବେ ପ୍ରାଧାନ୍ୟ ଦେବ। ସମ୍ପୂର୍ଣ୍ଣ 16-ଗୁଣକ ସ୍କୋରିଂ ପାଇଁ
   [Auto-Combo](../routing/AUTO-COMBO.md) ଦେଖନ୍ତୁ।
