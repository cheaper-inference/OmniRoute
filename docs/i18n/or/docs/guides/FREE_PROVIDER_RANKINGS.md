> (LMArena-ଶୈଳୀ) ELO ସ୍କୋର୍** ବ୍ୟବହାର କରି ରାଙ୍କ୍ କରେ। ଆପଣଙ୍କ କାର୍ଯ୍ୟ ପାଇଁ କେଉଁ ମାଗଣା ପ୍ରଦାନକାରୀ ସବୁଠାରୁ ଶକ୍ତିଶାଳୀ ମଡେଲ୍ ପ୍ରଦାନ କରନ୍ତି ତାହା ଦେଖିବାକୁ
> ଡ୍ୟାସ୍ବୋର୍ଡ୍ରେ **Free Provider Rankings** ପୃଷ୍ଠା ଖୋଲନ୍ତୁ —
> ସାମଗ୍ରିକ ଭାବରେ କିମ୍ବା ବର୍ଗ ଅନୁସାରେ ଫିଲ୍ଟର୍ କରି (କୋଡିଂ, ସମୀକ୍ଷା, ଡକ୍ୟୁମେଣ୍ଟେସନ୍, ଡିବଗିଂ)।

## ଏହା କଣ

OmniRoute 377 ପ୍ରଦାନକାରୀଙ୍କୁ ପଞ୍ଜିକରଣ କରେ, ଚିହ୍ନିତ 155 କାଟାଲଗ୍ ଏଣ୍ଟ୍ରିଗୁଡିକ ଅନ୍ତର୍ଭୁକ୍ତ କରେ \|**free/no-auth** (no-auth, free-tier OAuth, କିମ୍ବା free-tier API key - [ମାଗଣା ଟାୟାର୍ ଗାଇଡ୍](../getting-started/FREE-TIERS-GUIDE.md) ଏବଂ ସମ୍ପୂର୍ଣ୍ଣ [ମାଗଣା ଟାୟାର୍ ଡିରେକ୍ଟୋରୀ](../reference/FREE_TIERS.md) ଦେଖନ୍ତୁ) \| ଧର: ମାଗଣା ପ୍ରଦାନକାରୀମାନେ ମଡେଲ ଗୁଣରେ ଭିନ୍ନ ଭିନ୍ନ ଅଟନ୍ତି \| ଏକ ସୀମାନ୍ତ ମଡେଲକୁ ସେବା କରୁଥିବା ଏକ ନୋ-ଅଥ୍ ପ୍ରଦାନକାରୀ ଏକ ଛୋଟ ଉତ୍ତରାଧିକାରୀ ମଡେଲ୍ ସେବା କରିବା ଅପେକ୍ଷା ଅଧିକ ଉପଯୋଗୀ \|

**ମାଗଣା ପ୍ରଦାନକାରୀ ମାନ୍ୟତା \|** ଉତ୍ତର "** କେଉଁ ମାଗଣା ପ୍ରଦାନକାରୀ ମୋତେ ସର୍ବୋତ୍ତମ ମଡେଲ୍ ଦିଅନ୍ତି?** ପ୍ରତ୍ୟେକ ମାଗଣା ପ୍ରଦାନକାରୀଙ୍କ କାଟାଲଗ୍ ସହିତ ଯୋଗଦାନ କରି \|** ଭିଡ଼-ସୋର୍ସଡ୍ ଗୁଣାତ୍ମକ ସ୍କୋର \|** ରୁ** ଆରେନା AI ଲିଡବୋର୍ଡ \|** (ମାନବ-ପସନ୍ଦ ELO, LMArena ଚାଟବଟ୍ ମ ena ଦାନ ପଛରେ ସମାନ ଧାରଣା) \| ପ୍ରଦାନକାରୀମାନେ ତା’ପରେ ସେମାନଙ୍କର ଶକ୍ତି ଦ୍ୱାରା ସ୍ଥାନିତ ହୁଅନ୍ତି \|** ସର୍ବୋତ୍ତମ ମାଗଣା ମଡେଲ୍ \|** ।

ତିନୋଟି ପ୍ରକୃତ ଉତ୍ସରୁ ରାଙ୍କିଙ୍ଗ୍ ଗଣନା କରାଯାଇଛି:

1. ମାଗଣା-ପ୍ରଦାନକାରୀ ତାଲିକା - `NOAUTH_PROVIDERS`, ଏବଂ `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ଫ୍ଲାଗ୍ ହୋଇଥିବା `hasFree` (`src/shared/constants/providers.ts`) \|
2. ପ୍ରଦାନକାରୀ ରେଜିଷ୍ଟ୍ରି (`open-sse/config/providerRegistry.ts`) ରୁ ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀଙ୍କ ମଡେଲ୍ କାଟାଲଗ୍ \|
3. ଆର୍ନା ELO ସିଙ୍କ୍ ଇ engine ୍ଜିନ୍ (`src/lib/arenaEloSync.ts`) ଦ୍ୱାରା `model_intelligence` DB ଟେବୁଲରେ ସଂରକ୍ଷିତ ELO- ପ୍ରାପ୍ତ ଟାସ୍କ-ଫିଟ୍ ସ୍କୋର \|

ଯୋଗଦାନ ତର୍କ `src/lib/freeProviderRankings.ts` ରେ ରୁହେ \|

## କିପରି ପ୍ରବେଶ କରିବେ

### ଡ୍ୟାସ୍ବୋର୍ଡ୍ ପୃଷ୍ଠା

ଡ୍ୟାସ୍ବୋର୍ଡ୍ ଖୋଲି **Costs → Free Provider Rankings**-କୁ ଯାଆନ୍ତୁ, କିମ୍ବା ସିଧାସଳଖ ଏଠାକୁ ନେଭିଗେଟ୍ କରନ୍ତୁ:

```
/dashboard/free-provider-rankings
```

ଏହି ପୃଷ୍ଠା (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) ଦେଖାଏ:

- ସର୍ବୋତ୍ତମ ରାଙ୍କ୍ ପାଇଥିବା ମାଗଣା ପ୍ରଦାନକାରୀମାନଙ୍କର ଏକ **ଶୀର୍ଷ-3 ପୋଡିୟମ୍** (🥇 🥈 🥉)।
- ଏହି ସ୍ତମ୍ଭଗୁଡ଼ିକ ସହିତ ଏକ ସମ୍ପୂର୍ଣ୍ଣ **ରାଙ୍କିଂ ଟେବୁଲ୍**: **ରାଙ୍କ୍**, **ପ୍ରଦାନକାରୀ**, **ଶୀର୍ଷ ମଡେଲ୍**,
  **ସ୍କୋର୍**, **ହାରାହାରି ସ୍କୋର୍**, **ମଡେଲ୍ଗୁଡ଼ିକ**, **ପ୍ରକାର**।
- **ବର୍ଗ ଫିଲ୍ଟର୍ ବଟନ୍ଗୁଡ଼ିକ**: _ସମସ୍ତ ବର୍ଗ_, _ଡିଫଲ୍ଟ_, _କୋଡିଂ_, _ସମୀକ୍ଷା_,
  _ଡକ୍ୟୁମେଣ୍ଟେସନ୍_, _ଡିବଗିଂ_।

ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀଙ୍କ **ପ୍ରକାର** ବ୍ୟାଜ୍ ଏହା କିପରି ମାଗଣା ତାହା ଜଣାଏ:

| ବ୍ୟାଜ୍   | ଅର୍ଥ                                               |
| -------- | -------------------------------------------------- |
| `NOAUTH` | ସର୍ବଦା ମାଗଣା, କୌଣସି ପ୍ରମାଣପତ୍ର ଆବଶ୍ୟକ ନାହିଁ        |
| `OAUTH`  | ଏକ ମାଗଣା ଟିୟର୍ (`hasFree`) ଥିବା OAuth ପ୍ରଦାନକାରୀ   |
| `APIKEY` | ଏକ ମାଗଣା ଟିୟର୍ (`hasFree`) ଥିବା API-key ପ୍ରଦାନକାରୀ |

ସ୍କୋର୍ଗୁଡ଼ିକ କଞ୍ଚା ସଂଖ୍ୟା ବଦଳରେ ମଣିଷ ପାଇଁ ସହଜବୋଧ୍ୟ ଲେବଲ୍ (ଯେପରିକି _ଶ୍ରେଷ୍ଠ_, _ଅତ୍ୟୁତ୍ତମ_, _ବହୁତ ଭଲ_,
_ଭଲ_, _ହାରାହାରି_) ଭାବେ ଦେଖାଯାଏ, କାରଣ ଅନ୍ତର୍ନିହିତ ମୂଲ୍ୟଟି ଏକ ଆପେକ୍ଷିକ
ରାଙ୍କିଂ ଗୁଣବତ୍ତା, ଶତକଡ଼ା ନୁହେଁ।

### API ଏଣ୍ଡପଏଣ୍ଟ୍

ଏହି ପୃଷ୍ଠାଟି ଏକ ସାର୍ବଜନୀନ ରିଡ୍ ଏଣ୍ଡପଏଣ୍ଟ୍
(`src/app/api/free-provider-rankings/route.ts`) ଦ୍ୱାରା ସମର୍ଥିତ:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

କ୍ୱେରି ପାରାମିଟର୍ଗୁଡ଼ିକ (Zod ସହିତ ବୈଧୀକୃତ):

| ପାରାମିଟର୍  | ପ୍ରକାର | ଡିଫଲ୍ଟ       | ଟିପ୍ପଣୀ                                                                                                             |
| ---------- | ------ | ------------ | ------------------------------------------------------------------------------------------------------------------- |
| `category` | string | (କିଛି ନାହିଁ) | `default`, `coding`, `review`, `documentation`, `debugging` ମଧ୍ୟରୁ ଗୋଟିଏ। ସଂଯୁକ୍ତ ରାଙ୍କିଂ ପାଇଁ ଏହାକୁ ଛାଡ଼ି ଦିଅନ୍ତୁ। |
| `limit`    | number | `50`         | `1–100` ପରିସର ମଧ୍ୟରେ ସୀମିତ।                                                                                         |

ପ୍ରତିକ୍ରିୟାର ଗଠନ:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` ହେଉଛି ମୂଳ Arena ELO ମୂଲ୍ୟ; `score` ହେଉଛି ସାମାନ୍ୟୀକୃତ ଟାସ୍କ୍-ଫିଟ୍ ମୂଲ୍ୟ
(ନିମ୍ନରେ ଦେଖନ୍ତୁ)। କୌଣସି ସ୍କୋର୍ ହୋଇଥିବା ମଡେଲ୍ ନଥିବା ପ୍ରଦାନକାରୀମାନଙ୍କୁ ପ୍ରତିକ୍ରିୟାରୁ ବାଦ ଦିଆଯାଏ।

### ଉତ୍ସ: Arena AI leaderboard

Arena ELO sync engine (`src/lib/arenaEloSync.ts`) Arena AI leaderboard API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) ରୁ ଦୁଇଟି leaderboard — `text`
ଏବଂ `code` — ଆଣିଥାଏ। ଯେତେବେଳେ ସେହି API କୌଣସି ବ୍ୟବହାରଯୋଗ୍ୟ board ଫେରାଏ ନାହିଁ, engine ଟି
Hugging Face datasets-server ଉପରେ ଥିବା ଅଫିସିଆଲ `lmarena-ai/leaderboard-dataset` ଆଡ଼କୁ ଯାଏ
(`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` `activeSource`, `lastError` ଏବଂ
`lastFailedAt` ରିପୋର୍ଟ କରେ। ପ୍ରତ୍ୟେକ leaderboard entry ଏକ model ନାମ, vendor, ELO `score`,
confidence interval, ଏବଂ vote ଗଣନା ବହନ କରେ।

Leaderboard ବର୍ଗଗୁଡ଼ିକ OmniRoute କାର୍ଯ୍ୟ ବର୍ଗଗୁଡ଼ିକ ସହ ମ୍ୟାପ୍ ହୁଏ:

| Arena leaderboard | OmniRoute କାର୍ଯ୍ୟ ବର୍ଗ                            |
| ----------------- | ------------------------------------------------- |
| `text`            | `default`, `review`, `documentation`, `debugging` |
| `code`            | `coding`                                          |

### Normalization (task-fit ସ୍କୋର)

ମୂଳ ELO ସ୍କୋରଗୁଡ଼ିକ ପ୍ରତି leaderboard ରେ **`[0.4, 0.98]` ମଧ୍ୟରେ ଏକ task-fit ମୂଲ୍ୟ** କୁ normalize ହୁଏ:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

ସ୍କୋର କେବେ `0` କିମ୍ବା `1` ଛୁଏଁ ନାହିଁ, ଯାହା user override ପାଇଁ ଅବକାଶ ଛାଡ଼ିଥାଏ। ଏହା ହେଉଛି
ସେହି `score` field ଯାହା ଆପଣ API response ରେ ଦେଖନ୍ତି ଏବଂ dashboard ରେ ଦେଖାଯାଉଥିବା label।

### ବିଶ୍ବାସନୀୟତା (Confidence)

ପ୍ରତ୍ୟେକ entry Arena vote ଗଣନା ଆଧାରରେ ଏକ confidence ସ୍ତର ପାଏ:

| ବିଶ୍ବାସନୀୟତା | ଭୋଟ୍    |
| ------------ | ------- |
| `high`       | ≥ 5,000 |
| `medium`     | ≥ 1,000 |
| `low`        | < 1,000 |

### ସଂରକ୍ଷଣ ଏବଂ ସତେଜତା

Normalize ହୋଇଥିବା entry ଗୁଡ଼ିକ `source = "arena_elo"` ସହିତ `model_intelligence` DB ଟେବୁଲ୍ କୁ
ଲେଖାଯାଏ (`src/lib/db/modelIntelligence.ts`)। Entry ଗୁଡ଼ିକ **7 ଦିନ ପରେ ମିଆଦ ପୂରଣ କରେ**,
ତେଣୁ ଯେଉଁ provider sync ବନ୍ଦ କରିଦିଏ, ସେ ପୁରୁଣା ତଥ୍ୟ ପରିବେଷଣ ନକରି ଧୀରେ ଧୀରେ ତାଲିକାରୁ ବାହାରିଯାଏ।

Sync **ଡିଫଲ୍ଟ ରୂପେ ଚାଲୁ** ଥାଏ:

- ଏହା ସର୍ଭର ଆରମ୍ଭ ବେଳେ ଥରେ ଚାଲେ ଏବଂ ତାପରେ ଏକ ଆବ୍ତ୍ତିକ timer ରେ ଚାଲେ
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` ରୁ wired)।
- ଏହା **non-blocking ଏବଂ କେବେବି fatal ନୁହେଁ** — ଯଦି upstream fetch ବିଫଳ ହୁଏ, OmniRoute
  ଚାଲୁ ରହେ ଏବଂ ranking ଗୁଡ଼ିକ କେବଳ ଶେଷ ଭଲ ତଥ୍ୟ (କିମ୍ବା ଖାଲି ଅବସ୍ଥା) ଦେଖାଏ।

ଦୁଇଟି environment variable ଏହାକୁ ନିୟନ୍ତ୍ରଣ କରେ ([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) ରେ ଦଲିଲକୃତ):

| Variable                  | Default       | ଉଦ୍ଦେଶ୍ୟ                                            |
| ------------------------- | ------------- | --------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | outbound sync ରୁ ବାହାରିବା ପାଇଁ `false` ସେଟ୍ କରନ୍ତୁ। |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | Sync ବ୍ୟବଧାନ, ସେକେଣ୍ଡରେ।                            |

### ମାନୁଆଲ sync / ସ୍ଥିତି / ସଫା କରିବା

Operator ମାନଙ୍କ ପାଇଁ, ଏକ ପ୍ରମାଣିତ management endpoint ମାନୁଆଲ ନିୟନ୍ତ୍ରଣ ପ୍ରଦାନ କରେ
(`src/app/api/intelligence/sync/route.ts` — management auth ଆବଶ୍ୟକ):

```
GET    /api/intelligence/sync          # ବର୍ତ୍ତମାନର sync ସ୍ଥିତି (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # ମାନୁଆଲ sync ଆରମ୍ଭ କରନ୍ତୁ; body: { "dryRun": true } ଲେଖା ନକରି preview ଦେଖିବା ପାଇଁ
DELETE /api/intelligence/sync          # sync ହୋଇଥିବା ସମସ୍ତ arena_elo intelligence entry ସଫା କରନ୍ତୁ
```

ଯଦି ranking ପୃଷ୍ଠା ଖାଲି ଥାଏ, ଏକ ମାନୁଆଲ `POST /api/intelligence/sync` (କିମ୍ବା କେବଳ
ସର୍ଭରକୁ ପୁନରାରମ୍ଭ କରିବା) ଏହାକୁ ପୁଣି ପୂରଣ କରେ।

### Model ଗୁଡ଼ିକୁ leaderboard ସହ ମେଳ କରିବା

Registry model ID ଗୁଡ଼ିକ ଏବଂ Arena model ନାମଗୁଡ଼ିକ ସର୍ବଦା ଠିକ୍ ମେଳ ଖାଏ ନାହିଁ। Ranking ଟି
ନମନୀୟ matching ବ୍ୟବହାର କରେ (`src/lib/freeProviderRankings.ts` ରେ
`findMatchingIntelligence`):

1. Normalize ହୋଇଥିବା model ID ଉପରେ ସଠିକ୍ ମେଳ।
2. ଶେଷରେ ଥିବା version suffix କାଢ଼ିବା ପରେ ମେଳ (ଯେପରି `kimi-k2.6` → `kimi-k2`)।
3. Prefix ମେଳ (leaderboard model ନାମଟି registry ID ର ଏକ prefix)।

Sync ପାର୍ଶ୍ୱରେ, ଜଣାଶୁଣା vendor prefix ଗୁଡ଼ିକ (`anthropic/`, `openai/`, `google/`, …) କାଢ଼ି
ଦିଆଯାଏ ଏବଂ ଏକ ଛୋଟ alias map ଆଦର୍ଶ ନାମଗୁଡ଼ିକୁ OmniRoute ଆଭ୍ୟନ୍ତରୀଣ ଭାବେ ବ୍ୟବହାର କରୁଥିବା
variant ଗୁଡ଼ିକୁ ବିସ୍ତାର କରେ, ଯାହାଫଳରେ model ଗୁଡ଼ିକ ଯେକୌଣସି ନାମରେ ମଧ୍ୟ ଖୋଜିହୁଏ।

### Provider କିପରି rank ହୁଏ

ପ୍ରତ୍ୟେକ ମାଗଣା provider ପାଇଁ, engine ତା'ର catalog ର ପ୍ରତ୍ୟେକ model କୁ ସ୍କୋର କରେ, ତାପରେ:

- **Top Model** = provider ର ସର୍ବାଧିକ ସ୍କୋର କରୁଥିବା model।
- **Avg Score** = ସେହି provider ର ସ୍କୋର ହୋଇଥିବା ସମସ୍ତ model ର ହାରାହାରି ସ୍କୋର।
- **Models** = provider ର କେତୋଟି model ର Arena ସ୍କୋର ଥିଲା।

Provider ଗୁଡ଼ିକ ପ୍ରଥମେ **top-model ସ୍କୋର** ଅନୁଯାୟୀ, ତାପରେ ହାରାହାରି ସ୍କୋର ଅନୁଯାୟୀ ସଜାଯାନ୍ତି। ଏହା
ସେହି provider କୁ ପୁରସ୍କୃତ କରେ ଯିଏ ଅତିକମରେ ଗୋଟିଏ ଶକ୍ତିଶାଳୀ ମାଗଣା model ପ୍ରଦାନ କରେ।

## ମାଗଣା ପ୍ରଦାତା ବାଛିବା ପାଇଁ ଏହାର ବ୍ୟବହାର

1. **ସଠିକ୍ ବର୍ଗ ବାଛନ୍ତୁ।** ଏଜେଣ୍ଟ-ଆଧାରିତ/କୋଡ୍ ୱାର୍କଲୋଡ୍ ପାଇଁ **Coding** ଫିଲ୍ଟର୍ ବ୍ୟବହାର କରନ୍ତୁ, କିମ୍ବା
   ସାଧାରଣ ଚାଟ୍ ପାଇଁ ଏହାକୁ **All Categories** / **Default**ରେ ରଖନ୍ତୁ। ପ୍ରତ୍ୟେକ ଲିଡର୍ବୋର୍ଡରେ ଏକ ପ୍ରଦାତାର ଶ୍ରେଷ୍ଠ ମଡେଲ୍ ଭିନ୍ନ ହୋଇଥିବାରୁ,
   ସେହି ପ୍ରଦାତା ବିଭିନ୍ନ ବର୍ଗରେ ଭିନ୍ନ ସ୍ଥାନ ପାଇପାରେ।
2. **ଏକକ-ସେଟ୍ଅପ୍ ପାଇଁ ଶୀର୍ଷ ସ୍ଥାନଗୁଡ଼ିକୁ ପ୍ରାଧାନ୍ୟ ଦିଅନ୍ତୁ।** ଯଦି ଆପଣ କେବଳ ଗୋଟିଏ କିମ୍ବା ଦୁଇଟି ମାଗଣା
   ପ୍ରଦାତାଙ୍କୁ ସଂଯୋଗ କରିବାକୁ ଚାହାନ୍ତି, ତେବେ ନିଜ ବର୍ଗରେ ସର୍ବୋଚ୍ଚ ମାନ୍ୟତାପ୍ରାପ୍ତ ପ୍ରଦାତାଙ୍କଠାରୁ ଆରମ୍ଭ କରନ୍ତୁ।
3. **Type ବ୍ୟାଜ୍ ଯାଞ୍ଚ କରନ୍ତୁ।** `NOAUTH` ପ୍ରଦାତାମାନଙ୍କୁ ସବୁଠାରୁ ଶୀଘ୍ର ସଂଯୋଗ କରାଯାଇପାରେ (କୌଣସି
   ପରିଚୟପତ୍ର ଆବଶ୍ୟକ ନାହିଁ)। `OAUTH` / `APIKEY` ମାଗଣା ସ୍ତରଗୁଡ଼ିକ ପାଇଁ ଶୀଘ୍ର ସାଇନ୍-ଅପ୍ ଆବଶ୍ୟକ, କିନ୍ତୁ ସେଗୁଡ଼ିକ ପ୍ରାୟତଃ
   ଅଧିକ ଶକ୍ତିଶାଳୀ ମଡେଲ୍ ଉପଲବ୍ଧ କରାନ୍ତି। ସଂଯୋଗ ପଦକ୍ଷେପ ପାଇଁ
   [ମାଗଣା ସ୍ତର ମାର୍ଗଦର୍ଶିକା](../getting-started/FREE-TIERS-GUIDE.md) ଦେଖନ୍ତୁ।
4. **ଏକାଧିକ ପ୍ରଦାତାଙ୍କୁ ସଂଯୋଗ କରନ୍ତୁ ଏବଂ Auto-Comboକୁ ନିଷ୍ପତ୍ତି ନେବାକୁ ଦିଅନ୍ତୁ।** ଏହି ପୃଷ୍ଠାକୁ ପରିଚାଳିତ କରୁଥିବା ସମାନ Arena ELO ଡାଟା
   Auto-Combo ସ୍କୋରିଂ ଇଞ୍ଜିନ୍ର **କାର୍ଯ୍ୟ-ଉପଯୋଗିତା ଗୁଣକ**କୁ ମଧ୍ୟ ଯୋଗାଇଥାଏ
   (`open-sse/services/autoCombo/taskFitness.ts`, ସମାଧାନ କ୍ରମ
   `user_override → arena_elo → models_dev_tier → static table`)। ତେଣୁ ଆପଣ ଶୀର୍ଷ ମାଗଣା ପ୍ରଦାତାଙ୍କୁ ସଂଯୋଗ କରିବା ପରେ,
   `model: "auto"` (ଯଥା `auto/coding`) ସହିତ ରାଉଟିଂ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ
   ଉଚ୍ଚ-ଗୁଣବତ୍ତାର ମାଗଣା ମଡେଲ୍ଗୁଡ଼ିକୁ ସ୍ୱୟଂଚାଳିତ ଭାବେ ପ୍ରାଧାନ୍ୟ ଦେବ। ସମ୍ପୂର୍ଣ୍ଣ 16-ଗୁଣକ ସ୍କୋରିଂ ପାଇଁ
   [Auto-Combo](../routing/AUTO-COMBO.md) ଦେଖନ୍ତୁ।
