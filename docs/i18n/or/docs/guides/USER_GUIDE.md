## 🎯 ବ୍ୟବହାର ପରିସ୍ଥିତି

### ପରିସ୍ଥିତି 1: "ମୋ ପାଖରେ Claude Pro ସବସ୍କ୍ରିପ୍ସନ୍ ଅଛି"

**ସମସ୍ୟା:** କୋଟା ବ୍ୟବହାର ନ ହୋଇ ସମାପ୍ତ ହୁଏ, ଅଧିକ କୋଡିଂ ସମୟରେ ରେଟ୍ ଲିମିଟ୍ ଲାଗେ

```
କମ୍ବୋ: "maximize-claude"
  1. cc/claude-opus-4-7        (ସବସ୍କ୍ରିପ୍ସନ୍‌କୁ ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ବ୍ୟବହାର କରନ୍ତୁ)
  2. glm/glm-4.7               (କୋଟା ସରିଗଲେ ଶସ୍ତା ବ୍ୟାକଅପ୍)
  3. if/qwen3.8-max-preview       (ମାଗଣା ଜରୁରୀକାଳୀନ ଫଲ୍‌ବ୍ୟାକ୍)

ମାସିକ ଖର୍ଚ୍ଚ: $20 (ସବସ୍କ୍ରିପ୍ସନ୍) + ~$5 (ବ୍ୟାକଅପ୍) = ମୋଟ $25
ତୁଳନାରେ $20 + ସୀମାରେ ପହଞ୍ଚିବା = ହତାଶା
```

### ପରିସ୍ଥିତି 2: "ମୁଁ ଶୂନ୍ୟ ଖର୍ଚ୍ଚ ଚାହୁଁଛି"

**ସମସ୍ୟା:** ସବସ୍କ୍ରିପ୍ସନ୍ କିଣିବାକୁ ସକ୍ଷମ ନୁହେଁ, ନିର୍ଭରଯୋଗ୍ୟ AI କୋଡିଂ ଆବଶ୍ୟକ

```
କମ୍ବୋ: "zero-cost"
  1. if/kimi-k2.7-code          (ତାଲିକାଭୁକ୍ତ ମାଗଣା ଆକ୍ସେସ୍; ରେଟ୍ ଲିମିଟ୍ ପ୍ରଯୁଜ୍ୟ ହୋଇପାରେ)
  2. kr/qwen3-coder-next        (Kiro ମାଗଣା ଫଲ୍‌ବ୍ୟାକ୍)

ମାସିକ ଖର୍ଚ୍ଚ: $0
```

### ଟ୍ରେ ମୋଡ୍

ସିଷ୍ଟମ୍ ଟ୍ରେରେ OmniRoute ଆରମ୍ଭ କରନ୍ତୁ:

```bash
omniroute serve --tray
```

ସର୍ଭର ଏବଂ ଟ୍ରେ ପ୍ରସ୍ତୁତ ହେବା ପରେ କମାଣ୍ଡଟି ଫେରିଆସେ।

ଟର୍ମିନାଲ୍ ବିନା ସର୍ଭର ଚାଲୁ ରହେ।

ଟ୍ରେ ମୋଡ୍ macOS, Windows ଏବଂ ଗ୍ରାଫିକାଲ୍ Linux ସେସନ୍‌ଗୁଡ଼ିକୁ ସମର୍ଥନ କରେ। ଟ୍ରେ ମୋଡ୍ ସ୍ୱୟଂଚାଳିତ ଭାବରେ ଡ୍ୟାଶବୋର୍ଡ ଖୋଲେ ନାହିଁ।

ଏହି କାର୍ଯ୍ୟଗୁଡ଼ିକ ପାଇଁ ଟ୍ରେ ମେନୁ ବ୍ୟବହାର କରନ୍ତୁ:

- ଡ୍ୟାଶବୋର୍ଡ ଖୋଲନ୍ତୁ।
- `/dashboard/logs` ଖୋଲନ୍ତୁ।
- ସ୍ୱୟଂଚାଳିତ ଆରମ୍ଭ ପରିବର୍ତ୍ତନ କରନ୍ତୁ।
- OmniRoute ବନ୍ଦ କରନ୍ତୁ।

ଏହି ବିକଳ୍ପଗୁଡ଼ିକ ସହିତ `--tray`କୁ ଏକାଠି ବ୍ୟବହାର କରନ୍ତୁ ନାହିଁ:

- `--daemon`
- `--log`
- `--no-recovery`

ଏହି ମୋଡ୍‌ଗୁଡ଼ିକ ପାଇଁ ଭିନ୍ନ ପ୍ରକ୍ରିୟା ମାଲିକାନା ଆବଶ୍ୟକ।

ପରବର୍ତ୍ତୀ ମେସିନ୍ ଲଗ୍‌ଇନ୍ ସମୟରେ ଷ୍ଟାର୍ଟଅପ୍ ସକ୍ଷମ କରନ୍ତୁ:

```bash
omniroute autostart enable
```

ସ୍ୱୟଂଚାଳିତ ଆରମ୍ଭ macOS, Windows ଏବଂ ଗ୍ରାଫିକାଲ୍ Linux ସେସନ୍‌ଗୁଡ଼ିକରେ ଟ୍ରେ ମୋଡ୍ ବ୍ୟବହାର କରେ। ହେଡ୍‌ଲେସ୍ Linux ବିଦ୍ୟମାନ systemd ବ୍ୟବହାରକାରୀ ସେବା ବ୍ୟବହାର କରେ।

ଲଗ୍‌ଇନ୍ ସମୟରେ ଷ୍ଟାର୍ଟଅପ୍ ଅକ୍ଷମ କରନ୍ତୁ:


**ମଡେଲ ID ଗୁଡ଼ିକ ଉପରେ ଟିପ୍ପଣୀ:** OmniRoute ପ୍ରୋଭାଇଡର-ନେଟିଭ୍ ID ଗୁଡ଼ିକ ବ୍ୟବହାର କରେ (`claude-opus-4-8`, `gpt-5.5`, `glm-5.1`, `MiniMax-M2.7`, `kimi-k2.5`, `grok-4.20-0309-reasoning`) । କିଛି ID ରେ ବିନ୍ଦୁଯୁକ୍ତ ସଂସ୍କରଣ ରହିଛି କାରଣ ଅପଷ୍ଟ୍ରିମ୍ API ସେଗୁଡ଼ିକୁ ସେହିପରି ଆଶା କରେ । ଯଦି କୌଣସି ମଡେଲ ଉପରେ ତାଲିକାଭୁକ୍ତ ହୋଇନାହିଁ, ତେବେ ଉପଲବ୍ଧତା ନିଶ୍ଚିତ କରିବା ପାଇଁ `omniroute models --search <term>` ଚଲାନ୍ତୁ କିମ୍ବା `GET /api/models/catalog` କୁ ହିଟ୍ କରନ୍ତୁ ।

## 🧩 ଉନ୍ନତ ବୈଶିଷ୍ଟ୍ୟଗୁଡ଼ିକ

### କଷ୍ଟମ୍ ମଡେଲ୍ଗୁଡ଼ିକ

ଆପ୍ ଅପଡେଟ୍ ପାଇଁ ଅପେକ୍ଷା ନକରି ଯେକୌଣସି ପ୍ରୋଭାଇଡରରେ ଯେକୌଣସି ମଡେଲ୍ ID ଯୋଡ଼ନ୍ତୁ:

```bash
# API ମାଧ୍ୟମରେ
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# ତାଲିକା: curl http://localhost:20128/api/provider-models?provider=openai
# ଅପସାରଣ: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

କିମ୍ବା ଡ୍ୟାସବୋର୍ଡ ବ୍ୟବହାର କରନ୍ତୁ: **Providers → [Provider] → Custom Models**।

ଟିପ୍ପଣୀ:

- OpenRouter ଏବଂ OpenAI/Anthropic-ସୁସଙ୍ଗତ ପ୍ରୋଭାଇଡର୍ମାନେ କେବଳ **Available Models** ରୁ ପରିଚାଳିତ ହୁଅନ୍ତି। ମାନୁଆଲ୍ ଯୋଡ଼, ଆମଦାନୀ (import) ଏବଂ ଅଟୋ-ସିଙ୍କ — ସବୁ ସେହି ଏକା ଉପଲବ୍ଧ-ମଡେଲ୍ ତାଲିକାରେ ପହଞ୍ଚାନ୍ତି, ତେଣୁ ସେହି ପ୍ରୋଭାଇଡର୍ମାନଙ୍କ ପାଇଁ କୌଣସି ପୃଥକ Custom Models ବିଭାଗ ନାହିଁ।
- **Custom Models** ବିଭାଗଟି ସେହି ପ୍ରୋଭାଇଡର୍ମାନଙ୍କ ପାଇଁ ଉଦ୍ଦିଷ୍ଟ ଯେଉଁମାନେ ପରିଚାଳିତ ଉପଲବ୍ଧ-ମଡେଲ୍ ଆମଦାନୀ ପ୍ରଦାନ କରନ୍ତି ନାହିଁ।

### କଷ୍ଟମ୍ OpenAI-ସୁସଙ୍ଗତ ପ୍ରୋଭାଇଡର୍ଗୁଡ଼ିକ

OpenAI API କଥା ହେଉଥିବା ଯେକୌଣସି ଗେଟୱେ (ଏକ ସ୍ୱ-ହୋଷ୍ଟ କରାଯାଇଥିବା ପ୍ରକ୍ସୀ, vLLM, କିମ୍ବା କୌଣସି ତୃତୀୟ-ପକ୍ଷ ଏଗ୍ରିଗେଟର୍)
ନିଜସ୍ୱ ପ୍ରୋଭାଇଡର ନୋଡ୍ ଭାବରେ ଯୋଡ଼ା ଯାଇପାରେ:

1. **Providers → Add OpenAI Compatible**।
2. **Name**: ନୋଡ୍ ପାଇଁ ଏକ ପ୍ରଦର୍ଶନ ଲେବଲ୍।
3. **Prefix**: ରାଉଟିଂ ନାମ। କ୍ଲାଏଣ୍ଟମାନେ ମଡେଲ୍ଗୁଡ଼ିକୁ `<prefix>/<model>` ଭାବରେ ଡାକନ୍ତି, ତେଣୁ `mygw`
   ଉପସର୍ଗ ଥିବା ଏକ ନୋଡ୍ `mygw/gpt-4o-mini` ସେବା ଦେଇଥାଏ। ଆବଶ୍ୟକ; କୌଣସି ଅକ୍ଷର ପ୍ରତିବନ୍ଧକ ନାହିଁ।
4. **API Type**: ଗେଟୱେ ଯେଉଁ ଏଣ୍ଡପଏଣ୍ଟ ପରିବାର ପ୍ରଦାନ କରେ (Chat Completions, Responses,
   Embeddings, ଅଡିଓ, ଛବି)।
5. **Base URL**: API ମୂଳ, `/v1` ପର୍ଯ୍ୟନ୍ତ ଏବଂ ସହିତ (ଉଦାହରଣସ୍ୱରୂପ
   `https://gateway.example.com/v1`), ସମ୍ପୂର୍ଣ୍ଣ `/chat/completions` ପଥ ନୁହେଁ। ଅପ୍ରମାଣିତ
   (non-standard) ପଥ ଥିବା ଗେଟୱେଗୁଡ଼ିକ ସେଗୁଡ଼ିକୁ **Advanced Settings** ଅଧୀନରେ ସେଟ୍ କରନ୍ତି (chat path, models path)।
6. **API Key (for Check)** କ୍ଷେତ୍ର କେବଳ ସଂଯୋଗକୁ ପରୀକ୍ଷା କରେ। ନୋଡ୍ ତିଆରି କରିବା ପରେ,
   ଏହାକୁ ଖୋଲନ୍ତୁ ଏବଂ ଅନୁରୋଧଗୁଡ଼ିକ ବ୍ୟବହାର କରିବାକୁ ଥିବା କି (key) ସଂରକ୍ଷଣ କରିବା ପାଇଁ **Add Connection** ବ୍ୟବହାର କରନ୍ତୁ।

ନୋଡ୍କୁ `openai-compatible-<apiType>-<uuid>` ଆକାରର ଏକ ଆଭ୍ୟନ୍ତରୀଣ id ମିଳେ; ଆପଣଙ୍କୁ ଏହାକୁ କେବେବି
ଟାଇପ୍ କରିବାକୁ ପଡ଼ିବ ନାହିଁ, ଉପସର୍ଗ (prefix) ହିଁ ସାର୍ବଜନୀନ ନାମ।

#### ସଂରକ୍ଷିତ ଉପସର୍ଗଗୁଡ଼ିକ

ଏକ ଉପସର୍ଗ କୌଣସି ଅନ୍ତର୍ନିର୍ମିତ (built-in) ପ୍ରୋଭାଇଡରର id କିମ୍ବା ଉପନାମ (alias) (ଉଦାହରଣସ୍ୱରୂପ `openai`, `cf`) ହୋଇପାରିବ ନାହିଁ,
କିମ୍ବା ଅବସରିତ (retired) ପ୍ରୋଭାଇଡରର id ବି ହୋଇପାରିବ ନାହିଁ। ମଡେଲ୍ ରିଜଲଭର୍ କଷ୍ଟମ୍ ନୋଡ୍ଗୁଡ଼ିକ ପୂର୍ବରୁ ଅନ୍ତର୍ନିର୍ମିତ
id ଏବଂ ଉପନାମଗୁଡ଼ିକୁ ଯାଞ୍ଚ କରେ, ତେଣୁ ସେହି ଉପସର୍ଗଗୁଡ଼ିକ ମଧ୍ୟରୁ ଗୋଟିଏ ବ୍ୟବହାର କରୁଥିବା ନୋଡ୍ କେବେବି ଟ୍ରାଫିକ୍
ପାଇବ ନାହିଁ: `<prefix>/model` ଅନ୍ତର୍ନିର୍ମିତ ପ୍ରୋଭାଇଡରକୁ ଚାଲିଯିବ, କିମ୍ବା ସେହି ପ୍ରୋଭାଇଡର
ଅବସରିତ ହୋଇଥିଲେ fail closed ହେବ। ଏପରି ଉପସର୍ଗ ସହିତ ନୋଡ୍ ତିଆରି କିମ୍ବା ସମ୍ପାଦନ କରିବା ନିମ୍ନଲିଖିତ ତ୍ରୁଟି ସହିତ ପ୍ରତ୍ୟାଖ୍ୟାତ ହୁଏ:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

ଏକ ସ୍ୱତନ୍ତ୍ର ଉପସର୍ଗ ବାଛନ୍ତୁ (`mygw`, `acme-proxy`)। ଯଦି କଷ୍ଟମ୍ ନୋଡ୍କୁ ଯାଉଥିବା ଅନୁରୋଧଗୁଡ଼ିକ
କୌଣସି ଅନ୍ତର୍ନିର୍ମିତ ପ୍ରୋଭାଇଡର କିମ୍ବା ତା'ର କ୍ରେଡେନସିଆଲ୍ର ନାମ ନେଉଥିବା ତ୍ରୁଟି ସହିତ ବିଫଳ ହୁଏ, ତେବେ ନୋଡ୍ର ଉପସର୍ଗ
ସଂରକ୍ଷିତ କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ: ଏହି ନିୟମ ଆସିବା ପୂର୍ବରୁ ସଂରକ୍ଷଣ କରାଯାଇଥିବା ନୋଡ୍ଗୁଡ଼ିକ ଏବେବି ସଂରକ୍ଷିତ ଅଛି,
କିନ୍ତୁ ସେମାନଙ୍କ ଉପସର୍ଗ ଅନ୍ତର୍ନିର୍ମିତ ପ୍ରୋଭାଇଡରକୁ ରାଉଟ୍ ହୁଏ। ନୋଡ୍କୁ ସମ୍ପାଦନ କରନ୍ତୁ ଏବଂ ଏହାକୁ ଏକ ନୂତନ ଉପସର୍ଗ ଦିଅନ୍ତୁ।

#### ପ୍ରତି-ସଂଯୋଗ ଗେଟୱେ ବିକଳ୍ପଗୁଡ଼ିକ

ଏହି କି (keys) ଗୁଡ଼ିକ ସଂଯୋଗର `providerSpecificData` ରେ ଯାଏ (ଉଦାହରଣସ୍ୱରୂପ
`PUT /api/providers/{id}` ମାଧ୍ୟମରେ):

- `toolNameMaxLength` (ପୂର୍ଣ୍ଣାଙ୍କ, 1–1024) — OpenAI chat-ଫର୍ମାଟ୍ ସୁସଙ୍ଗତ ସଂଯୋଗଗୁଡ଼ିକ ପାଇଁ ଯାହାଙ୍କ
  ଗେଟୱେ ଲମ୍ବା ଟୁଲ୍ ନାମଗୁଡ଼ିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। ଲମ୍ବା ନାମଗୁଡ଼ିକ ଛୋଟ ଉପନାମ ଭାବରେ ପଠାଯାଏ ଏବଂ
  ପ୍ରତିକ୍ରିୟାରେ ପୁନର୍ସ୍ଥାପିତ ହୁଏ।
- `quotaEndpoint` — ଗେଟୱେର କୋଟା/କ୍ରେଡିଟ୍ ଏଣ୍ଡପଏଣ୍ଟ, ଯାହା ଡ୍ୟାସବୋର୍ଡ କୋଟା ଷ୍ଟ୍ରିପ୍ ଏବଂ
  କୋଟା-ସଚେତନ ରାଉଟିଂ ପାଇଁ ପଢ଼ାଯାଏ। OpenAI- ଏବଂ Anthropic-ସୁସଙ୍ଗତ ଉଭୟ ସଂଯୋଗରେ କାମ କରେ; ସମ୍ପୂର୍ଣ୍ଣ ଆକୃତି
  `open-sse/services/usage/openaiCompatible.ts` ରେ ଦଲିଲକୃତ।

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### OmniRoute ପିଅର୍ଗୁଡ଼ିକୁ ଶୃଙ୍ଖଳିତ କରିବା

ଅନ୍ୟ ଏକ OmniRoute ଗେଟୱେକୁ **Custom OpenAI-compatible** ପ୍ରୋଭାଇଡର ଭାବରେ ଯୋଡ଼ା ଯାଇପାରେ। ପିଅର୍ର
`/v1` ବେସ୍ URL ଏବଂ ସେହି ପିଅର୍ ଦ୍ୱାରା ଜାରି କରାଯାଇଥିବା ଏକ ଉତ୍ସର୍ଗୀକୃତ, ସର୍ବନିମ୍ନ-ଅଧିକାର (least-privilege) API କି ବ୍ୟବହାର କରନ୍ତୁ।

ପରସ୍ପର (reciprocal) କିମ୍ବା ମଲ୍ଟି-ହପ୍ ଶୃଙ୍ଖଳା ପାଇଁ, ପ୍ରତ୍ୟେକ ଗେଟୱେରେ ଅପ୍ଟ-ଇନ୍ ଲୁପ୍ ଗାର୍ଡ୍ ସକ୍ଷମ କରନ୍ତୁ:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

କେବଳ ସ୍ପଷ୍ଟ ଭାବରେ allowlist କରାଯାଇଥିବା ପିଅର୍ URL କୁ ପଠାଯାଇଥିବା ଅନୁରୋଧଗୁଡ଼ିକ
`X-OmniRoute-Peer-Trace` ହେଡର୍ ପାଆନ୍ତି। ଗୋଟିଏ ଗେଟୱେ ପୁନରାବୃତ ଇନଷ୍ଟାନ୍ସ ID କିମ୍ବା ସମାପ୍ତ ହପ୍
ବଜେଟ୍କୁ HTTP `508 Loop Detected` ସହିତ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ; ସାଧାରଣ ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରୋଭାଇଡର୍ମାନେ କୌଣସି ପିଅର୍ ମେଟାଡାଟା ପାଆନ୍ତି ନାହିଁ।

ପିଅର୍ ଶୃଙ୍ଖଳନ ଡାଟାବେସ୍ ରେପ୍ଲିକେସନ୍ କିମ୍ବା ହୋଷ୍ଟ ଫେଲଓଭର୍ ନୁହେଁ। ପ୍ରତ୍ୟେକ ଗେଟୱେ ସ୍ୱତନ୍ତ୍ର
SQLite ସ୍ଥିତି, କ୍ୟାଶେ, ରେଟ୍ କାଉଣ୍ଟର୍ ଏବଂ ସେସନ୍ ରଖେ। active/passive କିମ୍ବା active/active
ଉପଲବ୍ଧତା ପାଇଁ ହେଲ୍ଥ-ଚେକ୍ କରାଯାଇଥିବା ରିଭର୍ସ ପ୍ରକ୍ସୀ କିମ୍ବା କ୍ଲାଏଣ୍ଟ ଫେଲଓଭର୍ ବ୍ୟବହାର କରନ୍ତୁ, ଏବଂ ଗୋଟିଏ SQLite ଡାଟାବେସ୍କୁ
କେବେବି ଏକାଧିକ ଚାଲୁଥିବା OmniRoute ଇନଷ୍ଟାନ୍ସରେ ମାଉଣ୍ଟ କରନ୍ତୁ ନାହିଁ।

### ଉତ୍ସର୍ଗୀକୃତ ପ୍ରୋଭାଇଡର ରାଉଟ୍ଗୁଡ଼ିକ

ମଡେଲ୍ ବୈଧତା (validation) ସହିତ ଅନୁରୋଧଗୁଡ଼ିକୁ ସିଧାସଳଖ ନିର୍ଦ୍ଦିଷ୍ଟ ପ୍ରୋଭାଇଡରକୁ ରାଉଟ୍ କରନ୍ତୁ:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

ପ୍ରୋଭାଇଡର ଉପସର୍ଗ ନଥିଲେ ସ୍ୱୟଂଚାଳିତ ଭାବରେ ଯୋଡ଼ା ଯାଏ। ମେଳ ନଖାଉଥିବା ମଡେଲ୍ଗୁଡ଼ିକ `400` ଫେରାଇଥାଏ।

### ନେଟୱାର୍କ ପ୍ରକ୍ସୀ ବିନ୍ୟାସ

```bash
# ଗ୍ଲୋବାଲ୍ ପ୍ରକ୍ସୀ ସେଟ୍ କରନ୍ତୁ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# ପ୍ରତି-ପ୍ରୋଭାଇଡର ପ୍ରକ୍ସୀ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# ପ୍ରକ୍ସୀ ପରୀକ୍ଷା କରନ୍ତୁ
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**ଅଗ୍ରାଧିକାର:** କି-ନିର୍ଦ୍ଦିଷ୍ଟ → କମ୍ବୋ-ନିର୍ଦ୍ଦିଷ୍ଟ → ପ୍ରୋଭାଇଡର-ନିର୍ଦ୍ଦିଷ୍ଟ → ଗ୍ଲୋବାଲ → ଏନଭାଇରନମେଣ୍ଟ।

### କ୍ଲାଉଡ୍ ସିଙ୍କ୍

- ଡିଭାଇସଗୁଡ଼ିକ ମଧ୍ୟରେ ପ୍ରୋଭାଇଡର, କମ୍ବୋ ଏବଂ ସେଟିଂସଗୁଡ଼ିକୁ ସିଙ୍କ୍ କରନ୍ତୁ
- ଟାଇମଆଉଟ୍ + fail-fast ସହିତ ସ୍ୱୟଂଚାଳିତ ବ୍ୟାକଗ୍ରାଉଣ୍ଡ ସିଙ୍କ୍
- ପ୍ରଡକ୍ସନରେ ସର୍ଭର-ସାଇଡ୍ `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` କୁ ପ୍ରାଥମିକତା ଦିଅନ୍ତୁ

### Cloudflare Quick Tunnel

- Docker ଏବଂ ଅନ୍ୟାନ୍ୟ ସେଲ୍ଫ-ହୋଷ୍ଟେଡ୍ ଡିପ୍ଲୟମେଣ୍ଟଗୁଡ଼ିକ ପାଇଁ **ଡ୍ୟାସବୋର୍ଡ → ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକ** ରେ ଉପଲବ୍ଧ
- ଏକ ଅସ୍ଥାୟୀ `https://*.trycloudflare.com` URL ସୃଷ୍ଟି କରେ ଯାହା ଆପଣଙ୍କ ବର୍ତ୍ତମାନର OpenAI-ସୁସଂଗତ `/v1` ଏଣ୍ଡପଏଣ୍ଟକୁ ଫରୱାର୍ଡ କରେ
- ପ୍ରଥମଥର ସକ୍ଷମ କଲାବେଳେ କେବଳ ଆବଶ୍ୟକ ସମୟରେ `cloudflared` ଇନଷ୍ଟଲ୍ କରେ; ପରବର୍ତ୍ତୀ ରିଷ୍ଟାର୍ଟଗୁଡ଼ିକ ସେହି ପରିଚାଳିତ ବାଇନାରୀକୁ ପୁନର୍ବ୍ୟବହାର କରେ
- OmniRoute କିମ୍ବା କଣ୍ଟେନର ରିଷ୍ଟାର୍ଟ ପରେ Quick Tunnelଗୁଡ଼ିକ ସ୍ୱୟଂଚାଳିତ ଭାବେ ପୁନରୁଦ୍ଧାର ହୁଅନ୍ତି ନାହିଁ; ଆବଶ୍ୟକ ସମୟରେ ଡ୍ୟାସବୋର୍ଡରୁ ସେଗୁଡ଼ିକୁ ପୁଣି ସକ୍ଷମ କରନ୍ତୁ
- ଟନେଲ URLଗୁଡ଼ିକ କ୍ଷଣସ୍ଥାୟୀ ଏବଂ ଆପଣ ଟନେଲକୁ ବନ୍ଦ/ଆରମ୍ଭ କରିବା ପ୍ରତ୍ୟେକ ଥର ପରିବର୍ତ୍ତିତ ହୁଏ
- ପରିଚାଳିତ Quick Tunnelଗୁଡ଼ିକ ସୀମିତ କଣ୍ଟେନରଗୁଡ଼ିକରେ କୋଳାହଳପୂର୍ଣ୍ଣ QUIC UDP ବଫର ଚେତାବନୀଗୁଡ଼ିକୁ ଏଡ଼ାଇବା ପାଇଁ ଡିଫଲ୍ଟ ଭାବେ HTTP/2 ଟ୍ରାନ୍ସପୋର୍ଟ ବ୍ୟବହାର କରନ୍ତି
- ଯଦି ଆପଣ ପରିଚାଳିତ ଟ୍ରାନ୍ସପୋର୍ଟ ପସନ୍ଦକୁ ଓଭରରାଇଡ୍ କରିବାକୁ ଚାହୁଁଛନ୍ତି ତେବେ `CLOUDFLARED_PROTOCOL=quic` କିମ୍ବା `auto` ସେଟ୍ କରନ୍ତୁ
- ଯଦି ଆପଣ ପରିଚାଳିତ ଡାଉନଲୋଡ୍ ପରିବର୍ତ୍ତେ ପୂର୍ବ-ଇନଷ୍ଟଲ୍ ହୋଇଥିବା `cloudflared` ବାଇନାରୀ ବ୍ୟବହାର କରିବାକୁ ପସନ୍ଦ କରନ୍ତି ତେବେ `CLOUDFLARED_BIN` ସେଟ୍ କରନ୍ତୁ
- Cloudflare Quick Tunnel, Tailscale Funnel ଏବଂ ngrok Tunnel ପ୍ୟାନେଲଗୁଡ଼ିକୁ **ସେଟିଂସ → ରୂପରେଖ** ରେ ଦେଖାଯାଇ କିମ୍ବା ଲୁଚାଯାଇ ପାରିବ। ପ୍ୟାନେଲ ଲୁଚାଇବା ଚାଲୁଥିବା ଟନେଲକୁ ବନ୍ଦ କରେ ନାହିଁ।

### LLM ଗେଟୱେ ଇଣ୍ଟେଲିଜେନ୍ସ (ପର୍ଯ୍ୟାୟ 9)

- **ସିମାଣ୍ଟିକ କ୍ୟାଶ୍** — ନନ୍-ଷ୍ଟ୍ରିମିଂ, temperature=0 ରେସପନ୍ସଗୁଡ଼ିକୁ ସ୍ୱୟଂଚାଳିତ ଭାବେ କ୍ୟାଶ୍ କରେ (`X-OmniRoute-No-Cache: true` ସହିତ ବାଇପାସ୍ କରନ୍ତୁ)
- **ରିକ୍ୱେଷ୍ଟ ଆଇଡେମପୋଟେନ୍ସି** — `Idempotency-Key` କିମ୍ବା `X-Request-Id` ହେଡର ମାଧ୍ୟମରେ 5s ମଧ୍ୟରେ ରିକ୍ୱେଷ୍ଟଗୁଡ଼ିକୁ ଡିଡୁପ୍ଲିକେଟ୍ କରେ
- **ପ୍ରଗତି ଟ୍ରାକିଂ** — `X-OmniRoute-Progress: true` ହେଡର ମାଧ୍ୟମରେ ଅପ୍ଟ-ଇନ୍ SSE `event: progress` ଇଭେଣ୍ଟଗୁଡ଼ିକ

### ରାଉଟିଂ ରଣନୀତିଗୁଡ଼ିକ

**ଡ୍ୟାସବୋର୍ଡ → ସେଟିଂସ → ରାଉଟିଂ** ମାଧ୍ୟମରେ କନଫିଗର୍ କରନ୍ତୁ। ଡ୍ୟାସବୋର୍ଡ ଛଅଟି ସର୍ବାଧିକ ବ୍ୟବହୃତ ରଣନୀତି ପ୍ରଦାନ କରେ; କମ୍ବୋ ଏବଂ ଅଟୋ-ରାଉଟର ଅଭ୍ୟନ୍ତରୀଣ ଭାବେ ଅଧିକ ବିସ୍ତୃତ ସେଟ୍ ସମର୍ଥନ କରନ୍ତି।

**ଉନ୍ନତ କମ୍ବୋ ଏବଂ ଅଟୋ ରଣନୀତିଗୁଡ଼ିକ** (ପ୍ରତି କମ୍ବୋ କିମ୍ବା `auto/*` ପ୍ରିଫିକ୍ସ ମାଧ୍ୟମରେ କନଫିଗର୍ ଯୋଗ୍ୟ — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ଦେଖନ୍ତୁ):

- `priority` — କଠୋର କ୍ରମ, କେବେ ରାଉଣ୍ଡ-ରବିନ୍ କରେ ନାହିଁ
- `weighted` — ପ୍ରତି-ମଡେଲ ୱେଟ୍ ଅନୁଯାୟୀ ଆନୁପାତିକ ଟ୍ରାଫିକ୍ ବିଭାଜନ
- `fill-first` — ସୀମା ପହଞ୍ଚିବା ପର୍ଯ୍ୟନ୍ତ ପ୍ରଥମ ମଡେଲକୁ ବ୍ୟବହାର କରେ
- `round-robin` / `strict-random` / `random`
- `p2c` (ଦୁଇଟି ପସନ୍ଦର ଶକ୍ତି)
- `least-used` ଏବଂ `cost-optimized`
- `auto` — ସମସ୍ତ ପ୍ରାର୍ଥୀ ମଧ୍ୟରେ ସ୍କୋର-ଚାଳିତ
- `lkgp` (ଶେଷ ଜଣା ଭଲ ପ୍ରୋଭାଇଡର) — ଶେଷ ସଫଳ ପ୍ରୋଭାଇଡର ସହିତ ଲାଗି ରହେ, ତାପରେ ନିୟମଗୁଡ଼ିକୁ ଫଲବ୍ୟାକ କରେ
- `context-optimized` — ସବୁଠାରୁ ବଡ଼ ମୁକ୍ତ କଣ୍ଟେକ୍ସ୍ଟ ୱିଣ୍ଡୋ ଥିବା ମଡେଲ ବାଛେ
- `context-relay` — ଫଲୋ-ଅପ୍ ଟର୍ନଗୁଡ଼ିକ ପାଇଁ ଦୀର୍ଘ-କଣ୍ଟେକ୍ସ୍ଟ ମଡେଲଗୁଡ଼ିକୁ ଶୃଙ୍ଖଳିତ କରେ

#### ବାହ୍ୟ ଷ୍ଟିକି ସେସନ୍ ହେଡର

ବାହ୍ୟ ସେସନ୍ ଆଫିନିଟି ପାଇଁ (ଉଦାହରଣ ସ୍ୱରୂପ, ରିଭର୍ସ ପ୍ରକ୍ସି ପଛରେ ଥିବା Claude Code/Codex ଏଜେଣ୍ଟଗୁଡ଼ିକ), ପଠାନ୍ତୁ:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id` ମଧ୍ୟ ଗ୍ରହଣ କରେ ଏବଂ ପ୍ରଭାବଶାଳୀ ସେସନ୍ କି `X-OmniRoute-Session-Id` ରେ ଫେରସ୍ତ କରେ।

ଯଦି ଆପଣ Nginx ବ୍ୟବହାର କରନ୍ତି ଏବଂ ଅଣ୍ଡରସ୍କୋର-ଫର୍ମ ହେଡର ପଠାନ୍ତି, ତେବେ ସକ୍ଷମ କରନ୍ତୁ:

```nginx
underscores_in_headers on;
```

#### ୱାଇଲ୍ଡକାର୍ଡ ମଡେଲ ଉପନାମ

ମଡେଲ ନାମଗୁଡ଼ିକୁ ରିମ୍ୟାପ୍ କରିବା ପାଇଁ ୱାଇଲ୍ଡକାର୍ଡ ପ୍ୟାଟର୍ନ ସୃଷ୍ଟି କରନ୍ତୁ:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

ୱାଇଲ୍ଡକାର୍ଡଗୁଡ଼ିକ `*` (ଯେକୌଣସି ଅକ୍ଷର) ଏବଂ `?` (ଗୋଟିଏ ଅକ୍ଷର) ସମର୍ଥନ କରନ୍ତି।

#### ଫଲବ୍ୟାକ ଶୃଙ୍ଖଳା

ସମସ୍ତ ରିକ୍ୱେଷ୍ଟରେ ଲାଗୁ ହେଉଥିବା ଗ୍ଲୋବାଲ ଫଲବ୍ୟାକ ଶୃଙ୍ଖଳାଗୁଡ଼ିକ ସଂଜ୍ଞାୟିତ କରନ୍ତୁ:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### ସାଧାରଣ ପ୍ରୋଭାଇଡର କମ୍ବିନେସନ ଏବଂ ରାଉଟିଂ ପ୍ୟାଟର୍ନଗୁଡ଼ିକ

OmniRoute ରେ ଏକାଧିକ ପ୍ରୋଭାଇଡରଙ୍କୁ ମିଶାଇବା ଏବଂ ସେମାନଙ୍କ ମଧ୍ୟରେ ରାଉଟିଂ କରିବା ପାଇଁ ଏଠାରେ କିଛି ଉଦାହରଣ ପ୍ୟାଟର୍ନ ଦିଆଯାଇଛି:

#### 1. କୋଡିଂ ଏଜେଣ୍ଟ କମ୍ବୋ: ଖର୍ଚ୍ଚ/ଗତି ଫଲବ୍ୟାକ୍ ସହିତ ଉଚ୍ଚ-ସ୍ତରୀୟ ରିଜନିଂ

କୋଡିଂ ଏଜେଣ୍ଟମାନଙ୍କ (OpenCode, Claude Code, Cursor, Cline) ପାଇଁ ଉପଯୁକ୍ତ। ଆରମ୍ଭରେ ଅଗ୍ରଣୀ ରିଜନିଂ ମଡେଲମାନଙ୍କୁ ରାଉଟ୍ କରେ, କୋଟା ସମାପ୍ତ କିମ୍ବା ତ୍ରୁଟି ସମୟରେ ଦ୍ରୁତ କୋଡିଂ ମଡେଲମାନଙ୍କୁ ଫଲବ୍ୟାକ୍ କରେ।

- **ଡ୍ୟାସବୋର୍ଡ**: କମ୍ବୋ → ନୂତନ କମ୍ବୋ → ନାମ: `agent-coding` → ରଣନୀତି: `Priority`
- **ମଡେଲଗୁଡ଼ିକ**:
  1. `claude/claude-sonnet-4-6` (ପ୍ରାଥମିକ କୋଡିଂ ଏଜେଣ୍ଟ)
  2. `openai/gpt-4o` (ଦ୍ୱିତୀୟ ଉଚ୍ଚ-କ୍ଷମତା ଫଲବ୍ୟାକ୍)
  3. `deepseek/deepseek-v4-flash` (ଉଚ୍ଚ-ଦକ୍ଷତା, ଖର୍ଚ୍ଚ-ସାଶ୍ରୟୀ ଫଲବ୍ୟାକ୍)

```bash
# API ମାଧ୍ୟମରେ ଉଦାହରଣ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

#### 2. ଫ୍ରି-ଟାୟର ଅଟୋ ଫେଲଓଭର କମ୍ବୋ

API ଖର୍ଚ୍ଚ ବିନା ଅପଟାଇମକୁ ସର୍ବାଧିକ କରିବା ପାଇଁ ଏକାଧିକ ଫ୍ରି-ଟାୟର ଏବଂ କି-ବିହୀନ ପ୍ରୋଭାଇଡରମାନଙ୍କୁ ଶୃଙ୍ଖଳିତ କରେ।

- **ରଣନୀତି**: `Least Used` କିମ୍ବା `Round Robin` (କୋଟାଗୁଡ଼ିକ ମଧ୍ୟରେ ଲୋଡ୍ ବଣ୍ଟନ କରେ)
- **ମଡେଲଗୁଡ଼ିକ**:
  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

```bash
# CLI ମାଧ୍ୟମରେ ଉଦାହରଣ
omniroute combo create free-stack \
```

#### 3. ମଲ୍ଟିମୋଡାଲ / ଭିଜନ ଓ ଟେକ୍ସଟ ପାଇପଲାଇନ

ପ୍ରତିଛବି ବୁଝାମଣା ଏବଂ କୋଡ ଜେନରେସନ ଜଡ଼ିତ ବର୍କଫ୍ଲୋ ପାଇଁ ବିଶେଷଜ୍ଞ ଭିଜନ ମଡେଲମାନଙ୍କୁ ଉଚ୍ଚ-ଗତି ଟେକ୍ସଟ ଜେନରେସନ ସହିତ ଯୋଡ଼ିବା।

- **ମଡେଲଗୁଡ଼ିକ**:
  1. `gemini/gemini-2.5-pro` (ଶକ୍ତିଶାଳୀ ପ୍ରତିଛବି/ମଲ୍ଟିମୋଡାଲ ବୁଝାମଣା)
  2. `openai/gpt-4o` (ସନ୍ତୁଳିତ ଭିଜନ ଏବଂ ଟୁଲ୍ ବ୍ୟବହାର)

### ରେଜିଲିଏନ୍ସ ଓ ସର୍କିଟ ବ୍ରେକର

**ଡ୍ୟାସବୋର୍ଡ → ସେଟିଂସ୍ → ରେଜିଲିଏନ୍ସ** ମାଧ୍ୟମରେ କନଫିଗର୍ କରନ୍ତୁ।

OmniRoute ପାଞ୍ଚଟି ଉପାଦାନ ସହିତ ପ୍ରୋଭାଇଡର-ସ୍ତରୀୟ ରେଜିଲିଏନ୍ସ କାର୍ଯ୍ୟକାରୀ କରେ:

1. **ରିକ୍ୱେଷ୍ଟ କ୍ୟୁ ଓ ପେସିଂ** — ସିଷ୍ଟମ-ସ୍ତରୀୟ ରିକ୍ୱେଷ୍ଟ ଆକାର ପ୍ରଦାନ:
   - **ପ୍ରତି ମିନିଟରେ ରିକ୍ୱେଷ୍ଟ (RPM)** — ପ୍ରତି ଆକାଉଣ୍ଟ ପାଇଁ ପ୍ରତି ମିନିଟରେ ସର୍ବାଧିକ ରିକ୍ୱେଷ୍ଟ
   - **ରିକ୍ୱେଷ୍ଟ ମଧ୍ୟରେ ସର୍ବନିମ୍ନ ସମୟ** — ରିକ୍ୱେଷ୍ଟଗୁଡ଼ିକ ମଧ୍ୟରେ ମିଲିସେକେଣ୍ଡରେ ସର୍ବନିମ୍ନ ବ୍ୟବଧାନ
   - **ସର୍ବାଧିକ ସମକାଲୀନ ରିକ୍ୱେଷ୍ଟ** — ପ୍ରତି ଆକାଉଣ୍ଟ ପାଇଁ ସର୍ବାଧିକ ଏକାକାଳୀନ ରିକ୍ୱେଷ୍ଟ

2. **କନେକସନ କୁଲଡାଉନ** — ପୁନଃଚେଷ୍ଟା ଯୋଗ୍ୟ ବିଫଳତା ପରେ ଏକକ କନେକସନ ପାଇଁ ପ୍ରତି-ପ୍ରମାଣୀକରଣ-ପ୍ରକାର କନଫିଗରେସନ:
   - **ବେସ କୁଲଡାଉନ** — ପୁନଃଚେଷ୍ଟା ଯୋଗ୍ୟ ଅପଷ୍ଟ୍ରିମ ବିଫଳତା ପାଇଁ ଡିଫଲ୍ଟ କୁଲଡାଉନ ସମୟସୀମା
   - **ଅପଷ୍ଟ୍ରିମ ରିଟ୍ରାଏ ସଙ୍କେତ ବ୍ୟବହାର କରନ୍ତୁ** — ପ୍ରଦାନ କରାଯିଲେ ଅଧିକୃତ `Retry-After` କିମ୍ବା ରିସେଟ ସଙ୍କେତକୁ ସମ୍ମାନ କରେ
   - **ସର୍ବାଧିକ ବ୍ୟାକଅଫ ପଦକ୍ଷେପ** — ବାରମ୍ବାର ବିଫଳତା ପାଇଁ ସର୍ବାଧିକ ଘାତାଙ୍କୀୟ ବ୍ୟାକଅଫ ସ୍ତର

3. **ପ୍ରୋଭାଇଡର ସର୍କିଟ ବ୍ରେକର** — ଶେଷରୁ-ଶେଷ ପ୍ରୋଭାଇଡର ବିଫଳତାଗୁଡ଼ିକୁ ଟ୍ରାକ୍ କରେ, କନଫିଗର୍ କରାଯାଇଥିବା ଚେତାବନୀ ସୀମାରେ ପ୍ରୋଭାଇଡରକୁ ଅବକ୍ଷୟିତ ଭାବେ ଚିହ୍ନଟ କରେ, ଏବଂ କନଫିଗର୍ କରାଯାଇଥିବା ବିଫଳତା ସୀମାରେ ପହଞ୍ଚିଲେ ବ୍ରେକର ଖୋଲେ:
   - **ଅବକ୍ଷୟ ସୀମା** — `DEGRADED` ଅବସ୍ଥାରେ ପ୍ରବେଶ ପୂର୍ବରୁ କ୍ରମାଗତ ପ୍ରୋଭାଇଡର ବିଫଳତା
   - **ବିଫଳତା ସୀମା** — `OPEN` ଅବସ୍ଥାରେ ପ୍ରବେଶ ପୂର୍ବରୁ କ୍ରମାଗତ ପ୍ରୋଭାଇଡର ବିଫଳତା
   - **ରିସେଟ ଟାଇମଆଉଟ** — ପ୍ରୋଭାଇଡରକୁ ପୁଣି ପରୀକ୍ଷା କରିବା ପୂର୍ବରୁ ସମୟସୀମା
   - **CLOSED** (ସୁସ୍ଥ) — ରିକ୍ୱେଷ୍ଟଗୁଡ଼ିକ ସାଧାରଣ ଭାବେ ପ୍ରବାହିତ ହୁଏ
   - **DEGRADED** — ବଢ଼ିଥିବା ବିଫଳତାଗୁଡ଼ିକ ଟ୍ରାକ୍ ହେଉଥିବା ବେଳେ ମଧ୍ୟ ରିକ୍ୱେଷ୍ଟଗୁଡ଼ିକ ପ୍ରବାହିତ ହୁଏ
   - **OPEN** — ବାରମ୍ବାର ବିଫଳତା ପରେ ପ୍ରୋଭାଇଡର ଅସ୍ଥାୟୀ ଭାବେ ଅବରୋଧିତ ହୁଏ
   - **HALF_OPEN** — ପ୍ରୋଭାଇଡର ପୁନରୁଦ୍ଧାର ହୋଇଛି କି ନାହିଁ ପରୀକ୍ଷା କରୁଛି

   କନେକସନ-ସ୍ତରୀୟ `429` ରେଟ ଲିମିଟ **କନେକସନ କୁଲଡାଉନ** ରେ ରହେ ଏବଂ ପ୍ରୋଭାଇଡର ବ୍ରେକର ଗଣନାରେ ଗଣାଯାଏ ନାହିଁ।

   ପ୍ରୋଭାଇଡର ବ୍ରେକର ରନଟାଇମ ଅବସ୍ଥା କେବଳ **ଡ୍ୟାସବୋର୍ଡ → ହେଲ୍ଥ** ରେ ଦେଖାଯାଏ।

4. **କୁଲଡାଉନ ପାଇଁ ଅପେକ୍ଷା କରନ୍ତୁ** — ଯଦି ପ୍ରତ୍ୟେକ ସମ୍ଭାବ୍ୟ କନେକସନ ପୂର୍ବରୁ କୁଲଡାଉନ ଅବସ୍ଥାରେ ଅଛି, OmniRoute ସବୁଠାରୁ ଶୀଘ୍ର କୁଲଡାଉନ ପାଇଁ ଅପେକ୍ଷା କରି ସେହି କ୍ଲାଏଣ୍ଟ ରିକ୍ୱେଷ୍ଟକୁ ସ୍ୱୟଂଚାଳିତ ଭାବେ ପୁନଃଚେଷ୍ଟା କରିପାରେ।

5. **ରେଟ ଲିମିଟ ଅଟୋ-ଡିଟେକସନ** — ଯେତେବେଳେ ଅପଷ୍ଟ୍ରିମ ପ୍ରୋଭାଇଡରମାନେ ସ୍ପଷ୍ଟ ଅପେକ୍ଷା ସମୟସୀମା ଫେରାଇଥାନ୍ତି, ସେଟିଂ ସକ୍ଷମ ଥିଲେ ସେହି ସଙ୍କେତଗୁଡ଼ିକ ସ୍ଥାନୀୟ କନେକସନ କୁଲଡାଉନକୁ ଅତିକ୍ରମ କରେ।

**ପ୍ରୋ ଟିପ:** ବିଭ୍ରାଟ ପରେ ଲାଇଭ ପ୍ରୋଭାଇଡର ବ୍ରେକରଗୁଡ଼ିକୁ ଯାଞ୍ଚ ଏବଂ ରିସେଟ କରିବା ପାଇଁ **ହେଲ୍ଥ** ପୃଷ୍ଠା ବ୍ୟବହାର କରନ୍ତୁ। ରେଜିଲିଏନ୍ସ ପୃଷ୍ଠା କେବଳ କନଫିଗରେସନ ପରିବର୍ତ୍ତନ କରେ।

### ଡାଟାବେସ ଏକ୍ସପୋର୍ଟ / ଇମ୍ପୋର୍ଟ

**ଡ୍ୟାସବୋର୍ଡ → ସେଟିଂସ୍ → ସିଷ୍ଟମ ଓ ଷ୍ଟୋରେଜ** ରେ ଡାଟାବେସ ବ୍ୟାକଅପ ପରିଚାଳନା କରନ୍ତୁ।

| କାର୍ଯ୍ୟ                       | ବିବରଣୀ                                                                                                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ଡାଟାବେସ ଏକ୍ସପୋର୍ଟ**         | ବର୍ତ୍ତମାନର SQLite ଡାଟାବେସକୁ `.sqlite` ଫାଇଲ ଭାବେ ଡାଉନଲୋଡ୍ କରେ                                                                                                     |
| **ସମସ୍ତ ଏକ୍ସପୋର୍ଟ (.tar.gz)** | ଏକ ସମ୍ପୂର୍ଣ୍ଣ ବ୍ୟାକଅପ ଆର୍କାଇଭ ଡାଉନଲୋଡ୍ କରେ ଯେଉଁଥିରେ ରହିଛି: ଡାଟାବେସ, ସେଟିଂସ୍, କମ୍ବୋ, ପ୍ରୋଭାଇଡର କନେକସନ (କ୍ରେଡେନସିଆଲ ବିନା), API କି ମେଟାଡେଟା                         |
| **ଡାଟାବେସ ଇମ୍ପୋର୍ଟ**          | ବର୍ତ୍ତମାନର ଡାଟାବେସକୁ ବଦଳାଇବା ପାଇଁ ଏକ `.sqlite` ଫାଇଲ ଅପଲୋଡ୍ କରନ୍ତୁ। `DISABLE_SQLITE_AUTO_BACKUP=true` ନ ଥିଲେ ଏକ ପୂର୍ବ-ଇମ୍ପୋର୍ଟ ବ୍ୟାକଅପ ସ୍ୱୟଂଚାଳିତ ଭାବେ ସୃଷ୍ଟି ହୁଏ |

```bash
# API: ଡାଟାବେସ ଏକ୍ସପୋର୍ଟ
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: ସମସ୍ତ ଏକ୍ସପୋର୍ଟ (ସମ୍ପୂର୍ଣ୍ଣ ଆର୍କାଇଭ)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ଡାଟାବେସ ଇମ୍ପୋର୍ଟ
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ଇମ୍ପୋର୍ଟ ବୈଧତା:** ଇମ୍ପୋର୍ଟ କରାଯାଇଥିବା ଫାଇଲକୁ ଅଖଣ୍ଡତା (SQLite pragma ଯାଞ୍ଚ), ଆବଶ୍ୟକ ଟେବୁଲ (`provider_connections`, `provider_nodes`, `combos`, `api_keys`), ଏବଂ ଆକାର (ସର୍ବାଧିକ 100MB) ପାଇଁ ବୈଧ କରାଯାଏ।

**ବ୍ୟବହାର କ୍ଷେତ୍ର:**

- ମେସିନଗୁଡ଼ିକ ମଧ୍ୟରେ OmniRoute ସ୍ଥାନାନ୍ତର କରନ୍ତୁ
- ବିପର୍ଯ୍ୟୟ ପୁନରୁଦ୍ଧାର ପାଇଁ ବାହ୍ୟ ବ୍ୟାକଅପ ସୃଷ୍ଟି କରନ୍ତୁ
- ଦଳ ସଦସ୍ୟମାନଙ୍କ ମଧ୍ୟରେ କନଫିଗରେସନ ଅଂଶୀଦାର କରନ୍ତୁ (ସମସ୍ତ ଏକ୍ସପୋର୍ଟ → ଆର୍କାଇଭ ଅଂଶୀଦାର କରନ୍ତୁ)

### କମ୍ବୋ ବାଲାନ୍ସିଂ ଷ୍ଟ୍ରାଟେଜି

**ଡ୍ୟାସବୋର୍ଡ → କମ୍ବୋ → ସୃଷ୍ଟି/ସମ୍ପାଦନା → ଷ୍ଟ୍ରାଟେଜି** ରେ ପ୍ରତି-କମ୍ବୋ ବାଲାନ୍ସିଂ କନଫିଗର କରନ୍ତୁ।

| ଷ୍ଟ୍ରାଟେଜି         | ବର୍ଣ୍ଣନା                                                                          |
| ------------------ | --------------------------------------------------------------------------------- |
| **Round-Robin**    | ମଡେଲଗୁଡ଼ିକ ମଧ୍ୟରେ କ୍ରମାନ୍ୱୟରେ ଘୂର୍ଣ୍ଣନ କରେ                                        |
| **Priority**       | ସର୍ବଦା ପ୍ରଥମ ମଡେଲ ଚେଷ୍ଟା କରେ; କେବଳ ତ୍ରୁଟି ହେଲେ ଫଲବ୍ୟାକ କରେ                        |
| **Random**         | ପ୍ରତ୍ୟେକ ରିକୱେଷ୍ଟ ପାଇଁ କମ୍ବୋରୁ ଏକ ଯାଦୃଚ୍ଛିକ ମଡେଲ ବାଛେ                             |
| **Weighted**       | ପ୍ରତି ମଡେଲ ପାଇଁ ନିର୍ଦ୍ଧାରିତ ଓଜନ ଆଧାରରେ ଆନୁପାତିକ ଭାବେ ରାଉଟ କରେ                     |
| **Least-Used**     | ସବୁଠାରୁ କମ ସାମ୍ପ୍ରତିକ ରିକୱେଷ୍ଟ ଥିବା ମଡେଲକୁ ରାଉଟ କରେ (କମ୍ବୋ ମେଟ୍ରିକ୍ସ ବ୍ୟବହାର କରେ) |
| **Cost-Optimized** | ସବୁଠାରୁ ଶସ୍ତା ଉପଲବ୍ଧ ମଡେଲକୁ ରାଉଟ କରେ (ମୂଲ୍ୟ ଟେବୁଲ ବ୍ୟବହାର କରେ)                    |

ଗ୍ଲୋବାଲ କମ୍ବୋ ଡିଫଲ୍ଟ **ଡ୍ୟାସବୋର୍ଡ → ସେଟିଂସ → ରାଉଟିଂ → କମ୍ବୋ ଡିଫଲ୍ଟ** ରେ ସେଟ କରାଯାଇପାରିବ।
କମ୍ବୋ ଟାର୍ଗେଟ ଟାଇମଆଉଟ ଡିଫଲ୍ଟ ଭାବରେ ବର୍ତ୍ତମାନର ରିକୱେଷ୍ଟ ଟାଇମଆଉଟରୁ ଉତ୍ତରାଧିକାର ପାଏ। ଯେତେବେଳେ ଛୋଟ
ପ୍ରତି-ଟାର୍ଗେଟ ସୀମା ଶୀଘ୍ର ଫଲବ୍ୟାକ ଟ୍ରିଗର କରିବା ଉଚିତ, ସେତେବେଳେ କେବଳ କମ୍ବୋ ଡିଫଲ୍ଟ କିମ୍ବା ପୃଥକ କମ୍ବୋରେ
**ଟାର୍ଗେଟ ଟାଇମଆଉଟ (ସେକେଣ୍ଡ)** ବ୍ୟବହାର କରନ୍ତୁ।

ଜିରୋ-ଲେଟେନ୍ସି କମ୍ବୋ ଅପ୍ଟିମାଇଜେସନ ଅପ୍ଟ-ଇନ ଅଟେ। **ଜିରୋ-ଲେଟେନ୍ସି ଅପ୍ଟିମାଇଜେସନ**କୁ ଅକ୍ଷମ ରଖନ୍ତୁ,
ଯାହା ଦ୍ୱାରା ଏହି ଲେଟେନ୍ସି ବୈଶିଷ୍ଟ୍ୟଗୁଡ଼ିକ ଫଲବ୍ୟାକ ଟାର୍ଗେଟ ସହିତ ପ୍ରତିଦ୍ୱନ୍ଦ୍ୱିତା କରିବ, TTFT ଇତିହାସ
ଆଧାରରେ ଟାର୍ଗେଟ ଏଡ଼ାଇବ, କିମ୍ବା ଫଲବ୍ୟାକ ରିକୱେଷ୍ଟକୁ ସଂକୁଚିତ କରିବ ନାହିଁ; ଏହାକୁ ସକ୍ଷମ କଲେ କନଫିଗର କରାଯାଇଥିବା
ହେଜିଂ, ପୂର୍ବାନୁମାନମୂଳକ TTFT ସ୍କିପ ଏବଂ ସକ୍ରିୟ ଫଲବ୍ୟାକ ସଂକୋଚନ, କମ୍ ଟେଲ ଲେଟେନ୍ସି ହାସଲ ପାଇଁ
ରାଉଟିଂ/ରିକୱେଷ୍ଟ ସଠିକତାକୁ ବଦଳାଇବାକୁ ଅନୁମତି ଦିଏ।

ଯେତେବେଳେ ଅପଷ୍ଟ୍ରିମ ପ୍ରୋଭାଇଡରମାନେ କଠୋର `max_tokens` / `maxOutputTokens` ସୀମା ଆବଶ୍ୟକ କରନ୍ତି, ସେତେବେଳେ **ରିଜନିଂ ଟୋକନ ବଫର** ଅକ୍ଷମ କରନ୍ତୁ। ସକ୍ଷମ କରାଯାଇଥିଲେ, କମ୍ବୋ ରାଉଟିଂ କେବଳ ଜଣାଶୁଣା ଆଉଟପୁଟ ସୀମା ଥିବା ମଡେଲଗୁଡ଼ିକ ପାଇଁ ରିଜନିଂ-ମଡେଲ ହେଡରୁମ୍ ଯୋଡ଼ିଥାଏ ଏବଂ ସୁରକ୍ଷିତ ବଫର ମୂଲ୍ୟ ସେହି ସୀମାକୁ ଅତିକ୍ରମ କରିବାକୁ ଯାଉଥିବା ସ୍ଥିତିରେ କ୍ଲାଏଣ୍ଟ ଟୋକନ ସୀମାକୁ ଅପରିବର୍ତ୍ତିତ ଛାଡ଼ିଦିଏ। ଯଦି କ୍ଲାଏଣ୍ଟ ସୀମା ପୂର୍ବରୁ ହିଁ କୌଣସି ଜଣାଶୁଣା ସୀମାଠାରୁ ଅଧିକ ଥାଏ, ତେବେ OmniRoute ଅପଷ୍ଟ୍ରିମ ଅନୁରୋଧ ପଠାଇବା ପୂର୍ବରୁ ଏହାକୁ ସେହି ସୀମା ପର୍ଯ୍ୟନ୍ତ କମ୍ କରିଦିଏ।

| `auto/offline` | କେବଳ ସ୍ଥାନୀୟ ପ୍ରଦାନକାରୀ (Ollama, vLLM, llama.cpp) — ଏୟାର୍-ଗ୍ୟାପ୍ଡ ସେଟଅପ୍ ପାଇଁ ଉପଯୋଗୀ           |
| `auto/smart`   | ଯୁକ୍ତିକରଣ ଗୁଣବତ୍ତାକୁ ପ୍ରଥମ ପ୍ରାଥମିକତା (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)               |
| `auto/lkgp`    | "ଶେଷ ଜଣାଶୁଣା ଭଲ ପ୍ରଦାନକାରୀ" — ଶେଷ ସଫଳ ପ୍ରଦାନକାରୀକୁ ପିନ୍ କରେ, ତା’ପରେ ନିୟମଗୁଡ଼ିକୁ ଫଲ୍‌ବ୍ୟାକ୍ କରେ |

## 🔌 MCP ଏବଂ A2A ଏକୀକରଣ

OmniRoute ଉଭୟ ଏକ **MCP ସର୍ଭର୍** (Model Context Protocol) ଏବଂ ଏକ **A2A ସର୍ଭର୍** (Agent-to-Agent JSON-RPC 2.0) ଅଟେ। ଯେକୌଣସି MCP-ସୁସଙ୍ଗତ IDE କିମ୍ବା ଏଜେଣ୍ଟ ହୋଷ୍ଟ ସିଧାସଳଖ OmniRoute ଟୁଲ୍‌ଗୁଡ଼ିକୁ କଲ୍ କରିପାରିବ — କୌଣସି ଅତିରିକ୍ତ ରାପର୍ ଆବଶ୍ୟକ ନାହିଁ।

### MCP ପରିବହନ

- **ଷ୍ଟ୍ରିମ୍‌ଯୋଗ୍ୟ HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (stdioକୁ ପସନ୍ଦ କରୁଥିବା IDE ପ୍ଲଗଇନ୍‌ଗୁଡ଼ିକ ପାଇଁ)

## 💾 ମେମୋରି ସିଷ୍ଟମ୍

OmniRoute ହାଇବ୍ରିଡ୍ ପୁନରୁଦ୍ଧାର ସହିତ **ଦୀର୍ଘକାଳୀନ କଥୋପକଥନ ମେମୋରି**କୁ ସ୍ଥାୟୀ ଭାବରେ ସଂରକ୍ଷଣ କରେ:

- **ସ୍ୱୟଂଚାଳିତ ତଥ୍ୟ ନିଷ୍କାସନ** — ପ୍ରତ୍ୟେକ ସେସନ୍ ପରେ ଏଣ୍ଟିଟି, ପସନ୍ଦ ଏବଂ ନିଷ୍ପତ୍ତିଗୁଡ଼ିକର ସାରାଂଶ ପ୍ରସ୍ତୁତ କରାଯାଇ `memory_facts` ଟେବୁଲ୍‌ରେ ସଂରକ୍ଷଣ କରାଯାଏ
- ମେମୋରିଗୁଡ଼ିକ ପ୍ରତ୍ୟେକ API କୀ ଏବଂ ପ୍ରତ୍ୟେକ ସେସନ୍ ଅନୁଯାୟୀ ସ୍କୋପ୍ କରାଯାଏ

## 🛠️ ପ୍ରୋଗ୍ରାମାଟିକ୍ ପରିଚାଳନା

ଆପଣ **`manage` ସ୍କୋପ୍ ଥିବା Bearer କୀ** ବ୍ୟବହାର କରି HTTP ମାଧ୍ୟମରେ ପ୍ରତ୍ୟେକ OmniRoute ରିସୋର୍ସ (ପ୍ରଦାତା, କମ୍ବୋ, କୀ, ସେଟିଂସ୍) ପରିଚାଳନା କରିପାରିବେ।

**Dashboard → API Keys → New Key → Scope: manage**ରେ କୀ ସୃଷ୍ଟି କରନ୍ତୁ, ତା’ପରେ:

```bash
# ପ୍ରଦାତାମାନଙ୍କର ତାଲିକା ଦେଖାନ୍ତୁ
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# ଏକ ପ୍ରଦାତା ସଂଯୋଗ ଯୋଗ କରନ୍ତୁ
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# ଏକ କମ୍ବୋ ସୃଷ୍ଟି କରନ୍ତୁ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API କୀଗୁଡ଼ିକର ତାଲିକା ଦେଖାନ୍ତୁ/ସୃଷ୍ଟି କରନ୍ତୁ
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

ସମ୍ପୂର୍ଣ୍ଣ ଏଣ୍ଡପଏଣ୍ଟ କ୍ୟାଟାଲଗ୍ ଏବଂ ଅନୁରୋଧ/ପ୍ରତିକ୍ରିୟା ସ୍କିମା ପାଇଁ [API_REFERENCE.md](../reference/API_REFERENCE.md) ଦେଖନ୍ତୁ।

## 💻 ଆଭ୍ୟନ୍ତରୀଣ CLI

ସେଟଅପ୍, ନିଦାନ ଏବଂ ରନ୍‌ଟାଇମ୍ ନିୟନ୍ତ୍ରଣ ପାଇଁ OmniRoute ଏକ ଆଭ୍ୟନ୍ତରୀଣ CLI (`omniroute …`) ସହିତ ଆସେ। ଏହା **ଡ୍ୟାସ୍‌ବୋର୍ଡରେ ଥିବା "CLI ଟୁଲ୍ସ" ପୃଷ୍ଠାଠାରୁ ଅଲଗା**, ଯାହା ତୃତୀୟ-ପକ୍ଷ CLIଗୁଡ଼ିକୁ (Claude Code, Cursor, Codex, Cline, …) ବିନ୍ୟାସ କରେ, ଯାହାଦ୍ୱାରା ସେଗୁଡ଼ିକ OmniRoute ସହିତ ଯୋଗାଯୋଗ କରିପାରିବେ।

```bash
omniroute setup                    # ଇଣ୍ଟରାକ୍ଟିଭ୍ ୱିଜାର୍ଡ (ପାସ୍‌ୱାର୍ଡ, ପ୍ରଦାନକାରୀ, କମ୍ବୋ)
omniroute setup --non-interactive  # CI-ଅନୁକୂଳ
omniroute doctor                   # ସ୍ୱାସ୍ଥ୍ୟ ନିଦାନ (ଡାଟା ଡିରେକ୍ଟୋରୀ, DB, ପ୍ରଦାନକାରୀ, ପୋର୍ଟ)
omniroute providers available      # ସମର୍ଥିତ ପ୍ରଦାନକାରୀଗୁଡ଼ିକର ତାଲିକା
omniroute providers list           # ବିନ୍ୟାସିତ ସଂଯୋଗଗୁଡ଼ିକର ତାଲିକା
omniroute providers test <id>      # ଏକ ପ୍ରଦାନକାରୀ ସଂଯୋଗର ଲାଇଭ୍ ପରୀକ୍ଷା
omniroute combos list              # କମ୍ବୋଗୁଡ଼ିକର ତାଲିକା
omniroute combos switch <name>     # ଡିଫଲ୍ଟ କମ୍ବୋ ସେଟ୍ କରନ୍ତୁ
omniroute models                   # ଉପଲବ୍ଧ ମଡେଲ୍‌ଗୁଡ଼ିକର ତାଲିକା (--json, --search)
omniroute keys add | list | remove # ଟର୍ମିନାଲ୍‌ରୁ API କୀଗୁଡ଼ିକ ପରିଚାଳନା କରନ୍ତୁ
omniroute backup                   # ବିନ୍ୟାସ + DBର ସ୍ନାପ୍‌ଶଟ୍
omniroute restore [<timestamp>]    # ଏକ ସ୍ନାପ୍‌ଶଟ୍‌ରୁ ପୁନରୁଦ୍ଧାର କରନ୍ତୁ
omniroute health                   # ବିସ୍ତୃତ ସ୍ୱାସ୍ଥ୍ୟ ସୂଚନା (ବ୍ରେକର୍, କ୍ୟାଶ୍, ମେମୋରୀ)
omniroute quota                    # ପ୍ରଦାନକାରୀ କୋଟା ବ୍ୟବହାର
omniroute mcp status               # MCP ସର୍ଭର ସ୍ଥିତି
omniroute a2a status               # A2A ସର୍ଭର ସ୍ଥିତି
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok ଟନେଲ୍‌ଗୁଡ଼ିକ
omniroute reset-password           # ଆଡ୍‌ମିନ୍ ପାସ୍‌ୱାର୍ଡ ରିସେଟ୍ କରନ୍ତୁ
omniroute --mcp                    # stdio ମାଧ୍ୟମରେ MCP ସର୍ଭର ଆରମ୍ଭ କରନ୍ତୁ
omniroute --port 3000              # ଏକ କଷ୍ଟମ୍ ପୋର୍ଟରେ ସର୍ଭର ଆରମ୍ଭ କରନ୍ତୁ
```

ପରାମର୍ଶ: ଅସ୍ୱାସ୍ଥ୍ୟକର ପ୍ରଦାନକାରୀ ସଂଯୋଗଗୁଡ଼ିକ ବିଷୟରେ ସତର୍କତା ପାଇବାକୁ ଆପଣଙ୍କ ନିରୀକ୍ଷଣ ଟୁଲ୍ ସହିତ `omniroute doctor --json` ବ୍ୟବହାର କରନ୍ତୁ।

## 🖥️ ଡେସ୍କଟପ୍ ଆପ୍ଲିକେସନ୍ (Electron)

OmniRoute Windows, macOS ଏବଂ Linux ପାଇଁ ଏକ ନେଟିଭ୍ ଡେସ୍କଟପ୍ ଆପ୍ଲିକେସନ୍ ଭାବେ ଉପଲବ୍ଧ।

### ସଂସ୍ଥାପନ

```bash
# electron ଡିରେକ୍ଟୋରୀରୁ:
cd electron
npm install

# ଡେଭଲପ୍‌ମେଣ୍ଟ ମୋଡ୍ (ଚାଲୁଥିବା Next.js ଡେଭ୍ ସର୍ଭର ସହିତ ସଂଯୋଗ କରେ):
npm run dev

# ପ୍ରଡକ୍ସନ୍ ମୋଡ୍ (ସ୍ୱତନ୍ତ୍ର ବିଲ୍ଡ ବ୍ୟବହାର କରେ):
npm start
```

### ଇନ୍‌ଷ୍ଟଲର୍ ନିର୍ମାଣ

```bash
cd electron
npm run build          # ବର୍ତ୍ତମାନର ପ୍ଲାଟଫର୍ମ
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg ୟୁନିଭର୍ସାଲ୍)
npm run build:linux    # Linux (.AppImage)
```

ଆଉଟ୍‌ପୁଟ୍ → `electron/dist-electron/`
