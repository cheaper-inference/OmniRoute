> **TL;DR**: OmniRoute ପ୍ରତ୍ୟେକ ଅନୁରୋଧର ଟୋକନ୍ ବ୍ୟବହାରକୁ ଟ୍ରାକ୍ କରେ, ଖର୍ଚ୍ଚ ଗଣନା କରେ, ପ୍ରତି-API-key କୋଟା ଲାଗୁ କରେ ଏବଂ ଡ୍ୟାସବୋର୍ଡରେ ବିଶ୍ଳେଷଣ ତଥ୍ୟ ପ୍ରଦର୍ଶନ କରେ। ଏହି ମାର୍ଗଦର୍ଶିକାରେ ଏସବୁ କିପରି କାମ କରେ ତାହା ବ୍ୟାଖ୍ୟା କରାଯାଇଛି।

**ଉତ୍ସଗୁଡ଼ିକ:**

- `open-sse/services/usage.ts` (~70KB) — ମୁଖ୍ୟ ବ୍ୟବହାର ଟ୍ରାକିଂ
- `src/lib/usageAnalytics.ts` (~10KB) — ଡ୍ୟାସବୋର୍ଡ ପାଇଁ ସମାହାର
- `src/lib/db/quotaSnapshots.ts` — ଐତିହାସିକ କୋଟା ତଥ୍ୟ
- `src/lib/db/usage*.ts` — ବ୍ୟବହାର-ସମ୍ବନ୍ଧୀୟ ଏକାଧିକ DB ମଡ୍ୟୁଲ୍

## ସାରାଂଶ

OmniRoute ମାଧ୍ୟମରେ ପ୍ରବାହିତ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ଏକ **ବ୍ୟବହାର ରେକର୍ଡ** ସୃଷ୍ଟି କରେ, ଯେଉଁଥିରେ ନିମ୍ନଲିଖିତ ତଥ୍ୟ ସଂଗୃହୀତ ହୁଏ:

- **ପରିଚୟ**: କେଉଁ API key, ପ୍ରଦାତା, ମଡେଲ୍, କମ୍ବୋ
- **ଟୋକନ୍ଗୁଡ଼ିକ**: ପ୍ରମ୍ପ୍ଟ ଟୋକନ୍, ସମାପ୍ତି ଟୋକନ୍, କ୍ୟାଶ୍ ହୋଇଥିବା ଟୋକନ୍, ସର୍ବମୋଟ
- **ଖର୍ଚ୍ଚ**: USD ପରିମାଣ (ମୂଲ୍ୟ ତଥ୍ୟରୁ ଗଣନା କରାଯାଇଥାଏ)
- **ସମୟ**: ବିଳମ୍ବତା, ଆରମ୍ଭ/ଶେଷ ଟାଇମ୍ଷ୍ଟାମ୍ପ
- **ସ୍ଥିତି**: ସଫଳତା, ତ୍ରୁଟି, ହାର-ସୀମିତ ଇତ୍ୟାଦି

ଏହି ରେକର୍ଡଗୁଡ଼ିକୁ **ବିଶ୍ଳେଷଣ ତଥ୍ୟ** ଭାବରେ ସମାହାର କରାଯାଏ, **କୋଟା ସ୍ନାପ୍ଶଟ୍** ଭାବରେ ସ୍ଥାୟୀ ଭାବେ ସଂରକ୍ଷଣ କରାଯାଏ ଏବଂ **ପ୍ରତି-key ବଜେଟ୍ ସୀମା** ଲାଗୁ କରିବାରେ ବ୍ୟବହୃତ ହୁଏ।

```
ଅନୁରୋଧ ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    ବିଶ୍ଳେଷଣ   କୋଟା    ବିଲିଂ
                    (ଡ୍ୟାସବୋର୍ଡ) (ଲାଗୁ) (ରପ୍ତାନି)
```

## କ’ଣ ରେକର୍ଡ କରାଯାଏ

`usage.ts` ସେବା ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ ଏକ **ବ୍ୟବହାର ଘଟଣା** ରେକର୍ଡ କରେ:

| କ୍ଷେତ୍ର            | ପ୍ରକାର      | ଉତ୍ସ                                                       |
| ------------------ | ----------- | ---------------------------------------------------------- |
| `id`               | ଷ୍ଟ୍ରିଙ୍ଗ୍  | ରେକର୍ଡ କରିବା ସମୟରେ ସୃଷ୍ଟି ହୋଇଥିବା UUID                     |
| `apiKeyId`         | ଷ୍ଟ୍ରିଙ୍ଗ୍  | ଅନୁରୋଧ ଆରମ୍ଭ କରିଥିବା API କୀ                                |
| `provider`         | ଷ୍ଟ୍ରିଙ୍ଗ୍  | ପ୍ରଦାନକାରୀ ID (openai, anthropic, ଇତ୍ୟାଦି)                 |
| `model`            | ଷ୍ଟ୍ରିଙ୍ଗ୍  | ମଡେଲ୍ ID (gpt-5, claude-opus-4-6, ଇତ୍ୟାଦି)                 |
| `comboId`          | ଷ୍ଟ୍ରିଙ୍ଗ୍? | କମ୍ବୋ ମାଧ୍ୟମରେ ରାଉଟ୍ ହୋଇଥିଲେ କମ୍ବୋ ID                      |
| `promptTokens`     | ସଂଖ୍ୟା      | ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରତିକ୍ରିୟାରୁ                                   |
| `completionTokens` | ସଂଖ୍ୟା      | ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରତିକ୍ରିୟାରୁ                                   |
| `cachedTokens`     | ସଂଖ୍ୟା      | କ୍ୟାଶ୍ ହିଟ୍ ଟୋକେନ୍ (Anthropic ପ୍ରମ୍ପ୍ଟ କ୍ୟାଶିଂ, ଇତ୍ୟାଦି)   |
| `totalTokens`      | ସଂଖ୍ୟା      | ପ୍ରମ୍ପ୍ଟ + କମ୍ପ୍ଲିସନ୍                                      |
| `costUsd`          | ସଂଖ୍ୟା      | ମୂଲ୍ୟ ତଥ୍ୟରୁ ଗଣନା କରାଯାଇଥିବା                               |
| `latencyMs`        | ସଂଖ୍ୟା      | ଅନୁରୋଧର ଆରମ୍ଭରୁ ଶେଷ ପର୍ଯ୍ୟନ୍ତ ଅବଧି                         |
| `status`           | ଏନମ୍        | `success`, `error`, `rate_limited`, `timeout`, `cancelled` |
| `errorClass`       | ଷ୍ଟ୍ରିଙ୍ଗ୍? | ସ୍ଥିତି ସଫଳ ନ ହେଲେ ତ୍ରୁଟି ଶ୍ରେଣୀ                            |
| `timestamp`        | ଷ୍ଟ୍ରିଙ୍ଗ୍  | ISO 8601 UTC                                               |
| `metadata`         | ଅବଜେକ୍ଟ     | ପ୍ଲଗଇନ୍ ଦ୍ୱାରା ଯୋଡ଼ାଯାଇଥିବା କଷ୍ଟମ୍ ତଥ୍ୟ                    |

### ଟୋକେନ୍ କେଉଁଠୁ ଆସେ

**ପ୍ରତିକ୍ରିୟା ହ୍ୟାଣ୍ଡଲର୍** ଭିତରେ ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରଦାନକାରୀଙ୍କ ପ୍ରତିକ୍ରିୟାରୁ ଟୋକେନ୍ ବାହାର କରାଯାଏ:

```ts
// open-sse/handlers/chatCore.ts ରୁ
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

ବ୍ୟବହାର ତଥ୍ୟ ଫେରାଉନଥିବା ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ (କିଛି ୱେବ୍-କୁକି ପ୍ରଦାନକାରୀ), OmniRoute ଏକ `~4 chars per token` ଆନୁମାନିକ ନିୟମ ବ୍ୟବହାର କରି ଟୋକେନ୍ **ଆକଳନ** କରେ (`open-sse/services/autoCombo/pipelineRouter.ts` ଦେଖନ୍ତୁ)।

### କ୍ୟାଶ୍ ହୋଇଥିବା ଟୋକେନ୍

OmniRoute `cached_tokens` କୁ `prompt_tokens` ଠାରୁ ପୃଥକ ଭାବରେ ଟ୍ରାକ୍ କରେ, କାରଣ:

- Anthropic ପ୍ରମ୍ପ୍ଟ କ୍ୟାଶିଂ କ୍ୟାଶ୍ ହୋଇଥିବା ଟୋକେନ୍ ପାଇଁ କମ୍ ଦରରେ ଶୁଳ୍କ ନିଏ (ସାଧାରଣ ଦରର 10%)
- କିଛି ପ୍ରଦାନକାରୀ `cache_read_input_tokens` ଫେରାନ୍ତି, ଯାହା ପାଇଁ ଭିନ୍ନ ମୂଲ୍ୟ ନିର୍ଦ୍ଧାରଣ ହେବା ଉଚିତ
- ଆନାଲିଟିକ୍ସ **କ୍ୟାଶ୍ ହିଟ୍ ହାର** = `cached_tokens / prompt_tokens` ଦେଖାଇପାରେ

### କ୍ୟାଶ୍-ରାଇଟ୍ ସ୍ତର ନିଦାନ

ଆନାଲିଟିକ୍ସ ଡ୍ୟାଶବୋର୍ଡର ପ୍ରମ୍ପ୍ଟ-କ୍ୟାଶ୍ ସ୍ୱାସ୍ଥ୍ୟ ପ୍ୟାନେଲ୍ ପ୍ରଦାନକାରୀଙ୍କ ଦ୍ୱାରା ରିପୋର୍ଟ କରାଯାଇଥିବା
5-ମିନିଟ୍ ଏବଂ 1-ଘଣ୍ଟା କ୍ୟାଶ୍ ରାଇଟ୍ ମଧ୍ୟରେ ପାର୍ଥକ୍ୟ କରେ। Anthropic ର
`usage.cache_creation.ephemeral_5m_input_tokens` ଏବଂ
`usage.cache_creation.ephemeral_1h_input_tokens` କୁ ଷ୍ଟ୍ରିମିଂ ଏବଂ
ଅଣ-ଷ୍ଟ୍ରିମିଂ ବ୍ୟବହାର ରୂପାନ୍ତରଣ ସମୟରେ ବଜାୟ ରଖାଯାଏ ଏବଂ କଲ୍-ଲଗ୍ ସାରାଂଶ ସହିତ ସଂରକ୍ଷଣ କରାଯାଏ। ମିଳିତ
କ୍ୟାଶ୍-ରାଇଟ୍ ମୋଟକୁ ସେହି ବର୍ଗଗୁଡ଼ିକରେ ଦ୍ୱିତୀୟ ଥର ଯୋଡ଼ାଯାଏ ନାହିଁ।

ପୁରୁଣା ରେକର୍ଡ ସମେତ, କେବଳ ଏକ ମିଳିତ ରାଇଟ୍ କାଉଣ୍ଟର୍ ଥିବା କଲ୍‌ଗୁଡ଼ିକର ସ୍ତର
ଅଜଣା ରହେ। ଆଂଶିକ ବିଭାଜନରେ ଆବଣ୍ଟନ ହୋଇନଥିବା ଅବଶିଷ୍ଟ ଅଂଶ ଅଜଣା ରହେ; ଅବୈଧ କିମ୍ବା
ପରସ୍ପର ବିରୋଧୀ କାଉଣ୍ଟର୍‌ଗୁଡ଼ିକୁ ନିରବରେ ଏକ TTL ଆବଣ୍ଟନ କରିବା ପରିବର୍ତ୍ତେ ଚିହ୍ନଟ କରାଯାଏ। ଅନୁରୋଧ-ପାର୍ଶ୍ୱର
TTL ଚିହ୍ନଗୁଡ଼ିକ ବିଲ୍ କରାଯାଇଥିବା ସ୍ତରର ପ୍ରମାଣ ନୁହେଁ।

ପ୍ୟାନେଲ୍‌ର API-ସମତୁଲ୍ୟ ରାଇଟ୍ ଆକଳନ କେବଳ ରିପୋର୍ଟ ହୋଇଥିବା, ମୂଲ୍ୟ ନିର୍ଦ୍ଧାରିତ ସ୍ତରଗୁଡ଼ିକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ,
ସମ୍ପୂର୍ଣ୍ଣ ଅନୁରୋଧକୁ ନୁହେଁ। ନେଟିଭ୍ Claude/Anthropic ମଡେଲ୍ ମୂଲ୍ୟ ନିର୍ଦ୍ଧାରଣ ପାଇଁ ଏହା
5-ମିନିଟ୍ ରାଇଟ୍ ପାଇଁ ଇନପୁଟ୍ ଦରର 1.25 ଗୁଣ ଏବଂ 1-ଘଣ୍ଟା ରାଇଟ୍ ପାଇଁ ଇନପୁଟ୍ ଦରର ଦୁଇ ଗୁଣ ବ୍ୟବହାର କରେ। ମୂଲ୍ୟ
ନଥିଲେ ତାହା ଅନୁପଲବ୍ଧ, ଶୂନ ନୁହେଁ। ପ୍ରତ୍ୟେକ ନୂଆ କଲ୍ ଲଗ୍ ହେବା ସମୟରେ ମୂଲ୍ୟ ରେକର୍ଡ କରାଯାଏ;
ପୁରୁଣା ରେକର୍ଡଗୁଡ଼ିକର ମୂଲ୍ୟ ପୁନଃ ନିର୍ଦ୍ଧାରଣ କରାଯାଏ ନାହିଁ। ତେଣୁ ସବସ୍କ୍ରିପ୍ସନ୍ ଆକାଉଣ୍ଟଗୁଡ଼ିକର
API-ସମତୁଲ୍ୟ ଆକଳନ ଥାଇପାରେ, କିନ୍ତୁ ସେହି ପରିମାଣର ନଗଦ ଖର୍ଚ୍ଚ କିମ୍ବା ସବସ୍କ୍ରିପ୍ସନ୍
କୋଟା ବ୍ୟବହାର ହୋଇନପାରେ। ବିଦ୍ୟମାନ କୋଟା, ବଜେଟ୍ ଏବଂ ପ୍ରଦାନକାରୀଙ୍କ ସଠିକ୍ ଖର୍ଚ୍ଚ ଗଣନା ଅପରିବର୍ତ୍ତିତ ରହେ।

ଏହି ନିଦାନଗୁଡ଼ିକ ବିଦ୍ୟମାନ ସୀମିତ କ୍ୟାଶ୍-ସ୍ୱାସ୍ଥ୍ୟ ସାରାଂଶ ଏବଂ କଲ୍-ଲଗ୍
ସଂରକ୍ଷଣ ବ୍ୟବସ୍ଥା ବ୍ୟବହାର କରନ୍ତି। ଏଗୁଡ଼ିକ ଅନୁରୋଧର ଡିଫଲ୍ଟ TTL, ରାଉଟିଂ କିମ୍ବା ଆକାଉଣ୍ଟ ଚୟନକୁ ପରିବର୍ତ୍ତନ କରନ୍ତି ନାହିଁ।
ପ୍ରଦାନକାରୀଙ୍କୁ ପଠାଇବା ସୀମାରେ କ୍ଲାଏଣ୍ଟ ଅନୁରୋଧ କରିଥିବା TTL ଏବଂ ପ୍ରକୃତରେ ବାହାରକୁ ପଠାଯାଉଥିବା TTL ରେକର୍ଡ କରିବା
ସ୍ଥଗିତ ରହିଛି; ଏହି ପ୍ୟାନେଲ୍ ପ୍ରାପ୍ତି ରସିଦରେ ଥିବା ସ୍ତରଗୁଡ଼ିକୁ ରିପୋର୍ଟ କରେ, ପ୍ରକୃତ ବହିର୍ଗାମୀ TTL କୁ ନୁହେଁ।

କାର୍ଯ୍ୟାନ୍ୱୟନ: `src/lib/usage/cacheWriteEstimate.ts`,
`src/lib/usage/cacheHealth.ts`, ଏବଂ `open-sse/utils/cacheWriteUsage.ts`।

| ----------------- | ------------ | ------------- | ------------- |
| gpt-5             | $2.50        | $10.00        | —             |
| claude-opus-4-6   | $15.00       | $75.00        | $1.50         |
| claude-sonnet-4-5 | $3.00        | $15.00        | $0.30         |

ଖର୍ଚ୍ଚ ସୂତ୍ର (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **ପ୍ରମ୍ପ୍ଟ୍ରୁ କ୍ୟାଶ୍ଡ୍ ଅଂଶକୁ କାହିଁକି ବିୟୋଗ କରାଯାଏ?** କ୍ୟାଶ୍ଡ୍ ଅଂଶର ମୂଲ୍ୟ ପୃଥକ୍ ଭାବେ ଗଣନା କରାଯାଏ; ସମ୍ପୂର୍ଣ୍ଣ ପ୍ରମ୍ପ୍ଟ୍ ଉପରେ ଇନ୍ପୁଟ୍ ମୂଲ୍ୟ ଲାଗୁ କଲେ ଅତିରିକ୍ତ ଗଣନା ହେବ।

### ମୂଲ୍ୟ ସିଙ୍କ୍

````ts
## କୋଟା ପ୍ରବର୍ତ୍ତନ

ପ୍ରତ୍ୟେକ API କୀର କୋଟା ଦୁଇଟି ସ୍ଥାନରେ ପ୍ରବର୍ତ୍ତନ କରାଯାଏ:

1. **ନମନୀୟ ସୀମା** (`quotaWarnAt`): ବ୍ୟବହାର ନିର୍ଦ୍ଧାରିତ ସୀମା ଅତିକ୍ରମ କଲେ ଡ୍ୟାଶବୋର୍ଡରେ ଚେତାବନୀ
2. **କଠୋର ସୀମା** (`quotaLimit`): ସୀମା ଅତିକ୍ରମ କଲେ HTTP 429 ସହିତ ଅନୁରୋଧ ପ୍ରତ୍ୟାଖ୍ୟାନ

### ବିନ୍ୟାସ

```ts
// ପ୍ରତ୍ୟେକ API କୀ ପାଇଁ
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — ଚେତାବନୀ ଦେଖାନ୍ତୁ
  quotaLimit: 10_00,    // $10.00 — ସମ୍ପୂର୍ଣ୍ଣ ବନ୍ଦ
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### ପ୍ରବର୍ତ୍ତନ ପ୍ରବାହ

```
Request ──▶ quotaCheck()
              │
              ├── Within limit?  ──▶ allow
              │
              └── Over limit?  ──▶ 429 Too Many Requests
                                   with Retry-After header
```

### କୋଟା ସ୍ନାପଶଟ୍

ପ୍ରବଣତା ବିଶ୍ଳେଷଣ ପାଇଁ `quotaSnapshots` ସାରଣୀ **ଐତିହାସିକ କୋଟା ସ୍ଥିତି** ସଂରକ୍ଷଣ କରେ:

| ଫିଲ୍ଡ | ବିବରଣୀ |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | ଟ୍ରାକ୍ କରାଯାଉଥିବା କୀ |
| `window` | "day" | "week" | "month" |
| `used` | ଏହି ସମୟସୀମାରେ ବ୍ୟବହୃତ ଖର୍ଚ୍ଚ (ସେଣ୍ଟ୍) |
| `limit` | ସୀମା (ସେଣ୍ଟ୍) |
| `resetAt` | ସମୟସୀମା କେବେ ପୁନଃସେଟ୍ ହୁଏ |
| `createdAt` | ସ୍ନାପଶଟ୍ କେବେ ନିଆଯାଇଥିଲା |

ଖର୍ଚ୍ଚ > 0 ହେଉଥିବା **ପ୍ରତ୍ୟେକ ଅନୁରୋଧରେ** ସ୍ନାପଶଟ୍ ନିଆଯାଏ, ଏବଂ ଏଗୁଡ଼ିକୁ ନିମ୍ନ କାର୍ଯ୍ୟରେ ବ୍ୟବହାର କରାଯାଏ:

- ଡ୍ୟାଶବୋର୍ଡରେ କୋଟା ପ୍ରଗତି ବାର୍ ପ୍ରଦର୍ଶନ କରିବା
- 30-ଦିନିଆ କୋଟା ପ୍ରବଣତା ଚାର୍ଟ ଦେଖାଇବା
- ବ୍ୟବହାର ସୀମାର ନିକଟତର ହେଲେ ସତର୍କ ସୂଚନା ସକ୍ରିୟ କରିବା

## REST API

### ବ୍ୟବହାର ରେକର୍ଡଗୁଡ଼ିକର ତାଲିକା ଦେଖନ୍ତୁ

```bash
GET /api/usage?range=7d&limit=100
GET /api/usage?apiKeyId=key-123&range=30d
GET /api/usage?provider=openai&range=1d
```

ପ୍ରତିକ୍ରିୟା:

```json
{
  "records": [
    {
      "id": "uuid",
      "apiKeyId": "key-123",
      "provider": "openai",
      "model": "gpt-5",
      "promptTokens": 1234,
      "completionTokens": 567,
      "totalTokens": 1801,
      "costUsd": 0.005,
      "latencyMs": 1234,
      "status": "success",
      "timestamp": "2026-06-08T12:00:00Z"
    }
  ],
  "total": 1234,
  "nextCursor": "..."
}
```

### ବିଶ୍ଳେଷଣ ସାରାଂଶ ପାଆନ୍ତୁ

```bash
GET /api/usage/analytics?range=7d&groupBy=model
```

ପ୍ରତିକ୍ରିୟା:

```json

    { "date": "2026-06-02", "cost": 2.0, "requests": 1000 }
```

### ବ୍ୟବହାର ବିଶ୍ଳେଷଣ ପାଇଁ କ୍ୱେରି କରନ୍ତୁ

ବ୍ୟବହାର ତଥ୍ୟକୁ ସିଧାସଳଖ REST ରପ୍ତାନି ଏଣ୍ଡପଏଣ୍ଟ ମାଧ୍ୟମରେ ନୁହେଁ, ବରଂ ଡ୍ୟାସବୋର୍ଡ କିମ୍ବା MCP ଟୁଲ୍ ମାଧ୍ୟମରେ ଆକ୍ସେସ୍ କରାଯାଏ। ଉପଲବ୍ଧ ବିଶ୍ଳେଷଣ:

- **`/api/usage/analytics`** — ସମଷ୍ଟିକୃତ ବ୍ୟବହାର ମାପକ (ମଡେଲ୍, ପ୍ରଦାନକାରୀ, କି ଅନୁସାରେ ଗୋଷ୍ଠୀଭୁକ୍ତ)
- **`/api/usage/quota`** — ପ୍ରତ୍ୟେକ API କି ପାଇଁ ବର୍ତ୍ତମାନର କୋଟା ସ୍ଥିତି
- **`/api/usage/history`** — ଅନୁରୋଧ ଇତିହାସ ଲଗ୍

## MCP ଟୁଲ୍

ଦୁଇଟି MCP ଟୁଲ୍ ଏଜେଣ୍ଟମାନଙ୍କୁ ବ୍ୟବହାର ତଥ୍ୟ ଉପଲବ୍ଧ କରାଏ (`open-sse/mcp-server/tools/` ଦେଖନ୍ତୁ):

| ଟୁଲ୍                    | ବିବରଣୀ                                                      |
| ----------------------- | ----------------------------------------------------------- |
| `omniroute_cost_report` | ନିର୍ଦ୍ଦିଷ୍ଟ ଅବଧି ପାଇଁ ପ୍ରତ୍ୟେକ କିର ଖର୍ଚ୍ଚ ରିପୋର୍ଟ ତିଆରି କରେ |
| `omniroute_check_quota` | ଏକ API କି ପାଇଁ ବର୍ତ୍ତମାନର କୋଟା ସ୍ଥିତି ଫେରାଏ                 |

ଏଜେଣ୍ଟ ଆହ୍ୱାନର ଉଦାହରଣ:

```json
{
  "tool": "omniroute_cost_report",
  "args": { "period": "week" }
}
```

## ସଂରକ୍ଷଣ ଅବଧି ଏବଂ ସଫେଇ

ପ୍ରତ୍ୟେକ ଅନୁରୋଧରେ ବ୍ୟବହାର ତଥ୍ୟ ~1-10KB ବୃଦ୍ଧି ପାଏ। ବୃହତ୍ ପରିମାଣରେ ଏହା ଉଲ୍ଲେଖନୀୟ ହୋଇପାରେ।

### ସଂରକ୍ଷଣ ଅବଧି ସେଟିଂସ୍

ବ୍ୟବହାର ଇତିହାସର ସଂରକ୍ଷଣ ଅବଧି UI ର ଡାଟାବେସ୍ ସେଟିଂସ୍ ମାଧ୍ୟମରେ କିମ୍ବା `/api/settings/database` ମାଧ୍ୟମରେ ବିନ୍ୟାସ କରାଯାଏ।

ଡିଫଲ୍ଟ ଭାବରେ, ବ୍ୟବହାର ଇତିହାସ **90 ଦିନ** ପର୍ଯ୍ୟନ୍ତ ରଖାଯାଏ।

### ସଫେଇ

ପୁରୁଣା ରେକର୍ଡଗୁଡ଼ିକୁ `src/lib/db/cleanup.ts` ଦ୍ୱାରା ସଫା କରାଯାଏ:

- ପୃଷ୍ଠଭୂମି cron ପ୍ରକ୍ରିୟା ଦ୍ୱାରା ଆରମ୍ଭ କରାଯାଏ
- ବିନ୍ୟାସିତ `usageHistory` ସଂରକ୍ଷଣ ଅବଧି ସେଟିଂଠାରୁ ପୁରୁଣା ରେକର୍ଡଗୁଡ଼ିକୁ `usage_history` ରୁ ବିଲୋପ କରେ

### ଷ୍ଟୋରେଜ୍ ଆକଳନ

| ଅନୁରୋଧ ହାର         | 30-ଦିନର ଷ୍ଟୋରେଜ୍ | 90-ଦିନର ଷ୍ଟୋରେଜ୍ |
| ------------------ | ---------------- | ---------------- |
| 100 ଅନୁରୋଧ/ଦିନ     | ~3MB             | ~9MB             |
| 1,000 ଅନୁରୋଧ/ଦିନ   | ~30MB            | ~90MB            |
| 10,000 ଅନୁରୋଧ/ଦିନ  | ~300MB           | ~900MB           |
| 100,000 ଅନୁରୋଧ/ଦିନ | ~3GB             | ~9GB             |

ଅତ୍ୟଧିକ ଟ୍ରାଫିକ୍ ପାଇଁ, ନିମ୍ନଲିଖିତ ବିଷୟଗୁଡ଼ିକ ବିଚାର କରନ୍ତୁ:

- ଡାଟାବେସ୍ ସେଟିଂସ୍ ମାଧ୍ୟମରେ ସଂରକ୍ଷଣ ଅବଧି କମାଇବା
- ମୂଳ ରେକର୍ଡ ବଦଳରେ `aggregated_metrics` ବ୍ୟବହାର କରିବା (କେବଳ ବିଶ୍ଳେଷଣ ପାଇଁ)

## ଖର୍ଚ୍ଚ ଅନୁକୂଳନ ପରାମର୍ଶ

### 1. ସଠିକ୍ ମଡେଲ୍ ବ୍ୟବହାର କରନ୍ତୁ

```bash
# ଶୀଘ୍ର ଉତ୍ତର — ଶସ୍ତା + ଦ୍ରୁତ ବ୍ୟବହାର କରନ୍ତୁ
curl -d '{"model":"auto/fast","messages":[...]}'

# ଜଟିଳ କାର୍ଯ୍ୟ — ଗୁଣବତ୍ତା ବ୍ୟବହାର କରନ୍ତୁ
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. କ୍ୟାଶିଂ ସକ୍ରିୟ କରନ୍ତୁ

Anthropic ପ୍ରମ୍ପ୍ଟ କ୍ୟାଶିଂ **ପୁନରାବୃତ୍ତ ପ୍ରସଙ୍ଗରେ 90% ସଞ୍ଚୟ କରେ**:

```ts
// କ୍ୟାଶିଂ ସ୍ୱୟଂଚାଳିତ — କେବଳ ସମାନ ବୃହତ୍ ସିଷ୍ଟମ୍ ପ୍ରମ୍ପ୍ଟ ଅନ୍ତର୍ଭୁକ୍ତ କରନ୍ତୁ
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // ସ୍ୱୟଂଚାଳିତ ଭାବେ କ୍ୟାଶ୍ ହେବ
  messages: [{ role: "user", content: "..." }],
});
```

### 3. ସଙ୍କୋଚନ ବ୍ୟବହାର କରନ୍ତୁ

RTK + Caveman ସଙ୍କୋଚନ **ଅଧିକ ଟୁଲ୍ ବ୍ୟବହୃତ ହେଉଥିବା ସେସନ୍‌ରେ 15-95% ସଞ୍ଚୟ କରେ**:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. ପ୍ରତ୍ୟେକ କୀ ପାଇଁ କୋଟା ସ୍ଥିର କରନ୍ତୁ

ଅନିୟନ୍ତ୍ରିତ ଖର୍ଚ୍ଚ ରୋକିବା ପାଇଁ ସର୍ବଦା `quotaLimit` ସ୍ଥିର କରନ୍ତୁ:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // $10/ମାସ ସୀମା
```

### 5. ସର୍ବାଧିକ ବ୍ୟବହାରକାରୀଙ୍କ ଅଡିଟ୍ କରନ୍ତୁ

API କୀ ଅନୁଯାୟୀ ଗୋଷ୍ଠୀଭୁକ୍ତ କରିବା ଏବଂ ଖର୍ଚ୍ଚ ଅନୁଯାୟୀ ସଜାଇବା ପାଇଁ ଡ୍ୟାଶବୋର୍ଡ କିମ୍ବା **`/api/usage/analytics`** ବ୍ୟବହାର କରନ୍ତୁ:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## ସମସ୍ୟା ନିରାକରଣ

### "ଖର୍ଚ୍ଚ ଆଶାଠାରୁ ଅଧିକ"

1. **`/api/usage/analytics?groupBy=model`** ଯାଞ୍ଚ କରନ୍ତୁ — ଅଧିକ ଖର୍ଚ୍ଚବହୁଳ ମଡେଲ୍ ଖୋଜନ୍ତୁ
2. **`/api/usage/analytics?groupBy=apiKey`** ଯାଞ୍ଚ କରନ୍ତୁ — ଅଧିକ ବ୍ୟବହାରକାରୀଙ୍କୁ ଖୋଜନ୍ତୁ
3. ମୂଲ୍ୟ ତଥ୍ୟ ଅଦ୍ୟତନ ଅଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ: `POST /api/pricing/sync`

### "ରେକର୍ଡ ମିଳୁନାହିଁ"

- ଡ୍ୟାଶବୋର୍ଡ → ଡାଟାବେସ୍ → ସଫେଇ ଅଧୀନରେ DB ସଂରକ୍ଷଣ ସେଟିଂସ୍ ଯାଞ୍ଚ କରନ୍ତୁ — ପୁରୁଣା ରେକର୍ଡଗୁଡ଼ିକ ପର୍ଯ୍ୟାୟକ୍ରମିକ ସଫେଇ କାର୍ଯ୍ୟ (`src/lib/db/cleanup.ts`) ଦ୍ୱାରା ବିଲୋପ କରାଯାଏ
- `src/lib/db/usage*.ts` ରେ ତ୍ରୁଟି ଯାଞ୍ଚ କରନ୍ତୁ — DB ଲେଖନ ବିଫଳତା ଲଗ୍ କରାଯାଏ କିନ୍ତୁ ପ୍ରଦର୍ଶିତ ହୁଏ ନାହିଁ
- ଅନୁରୋଧ ପ୍ରକୃତରେ `chatCore` ପାଖରେ ପହଞ୍ଚିଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ — କମ୍ବୋ ରାଉଟିଂ ଯାଞ୍ଚ କରନ୍ତୁ

### "କୋଟା ଲାଗୁ ହେଉନାହିଁ"

- କୀର `quotaLimit` ସେଟିଂ ଯାଞ୍ଚ କରନ୍ତୁ
- `quotaWindow` ସଠିକ୍ ଭାବେ ସ୍ଥିର ହୋଇଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ
- `quotaSnapshots` ରେକର୍ଡଗୁଡ଼ିକ ଖୋଜନ୍ତୁ — ପ୍ରତ୍ୟେକ ଅନୁରୋଧରେ ସେଗୁଡ଼ିକ ସୃଷ୍ଟି ହେବା ଉଚିତ
