ଏକ କଷ୍ଟମ୍ JSON API ନୋଡ୍ ଏକ JSON ବ୍ୟବସାୟ ଶେଷ ପଏଣ୍ଟକୁ ସଂଯୋଗ କରେ ଯାହା OpenAI କିମ୍ବା Anthropic ପ୍ରୋଟୋକଲ୍ କହି ନଥାଏ। OmniRoute ଏକ JSON ଅନୁରୋଧ ଟେମ୍ପଲେଟ୍ ପୁରଣ କରେ, ଏହାକୁ ସଂପୂର୍ଣ୍ଣ ଏଣ୍ଡପଏଣ୍ଟ URL କୁ ପଠାଏ, ଏକ ପ୍ରତିକ୍ରିୟା ପଥରୁ ଉତ୍ତର ପ read ଼ି ଗ୍ରାହକଙ୍କ ନିଜ ଫର୍ମାଟରେ କ୍ଲାଏଣ୍ଟକୁ ଫେରାଇଥାଏ (ଚାଟ୍ ସମାପ୍ତି, ପ୍ରତିକ୍ରିୟା, ବାର୍ତ୍ତା, ...)।

ଏହା `apiType: "custom-json"` ସହିତ ଏକ OpenAI- ସୁସଙ୍ଗତ ନୋଡ୍। ଏହାର id ରେ `openai-compatible-custom-json-<suffix>` ଫର୍ମ ଅଛି। ଡ୍ୟାସବୋର୍ଡ ଫର୍ମ ଏପର୍ଯ୍ୟନ୍ତ ଉପଲବ୍ଧ ନାହିଁ। ନିମ୍ନରେ ପ୍ରଦାନକାରୀ-ନୋଡ୍ API ମାଧ୍ୟମରେ ଏହି ନୋଡଗୁଡିକ ସୃଷ୍ଟି ଏବଂ ସଂପାଦନ କରନ୍ତୁ।

## ଏକ ନୋଡ୍ ସୃଷ୍ଟି କରନ୍ତୁ।

`POST /api/provider-nodes` (ପରିଚାଳନା auth):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` ହେଉଛି** ସଂପୂର୍ଣ୍ଣ** ଶେଷ ପଏଣ୍ଟ URL କିଛି ଯୋଡା ଯାଇନାହିଁ ( `/chat/completions` ନାହିଁ, `/models` ନାହିଁ) ଏବଂ, ଅନ୍ୟ OpenAI- ସୁସଙ୍ଗତ ନୋଡଗୁଡିକ ପରି, କ default ଣସି URL ନାହିଁ। ଏହା ନିଶ୍ଚିତ ଭାବରେ `http(s)` ହେବା ଆବଶ୍ୟକ, ଏମ୍ବେଡ୍ ହୋଇଥିବା ପ୍ରମାଣପତ୍ର କିମ୍ବା `#fragment` ବିନା, ଏବଂ ଏହା ସମାନ ଆଉଟବାଉଣ୍ଡ୍ URL ଗାର୍ଡକୁ ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀ ନୋଡ୍ ପରି ପାସ୍ କରିଥାଏ, ଯେତେବେଳେ ନୋଡ୍ ସେଭ୍ ହୁଏ ଏବଂ ପ୍ରତ୍ୟେକ ଅନୁରୋଧରେ।
- ଏକ ନୋଡ୍ ଯାହା ସଂଯୋଗ କୀ ପଠାଏ (`authType` `bearer` କିମ୍ବା `api-key`, ଡିଫଲ୍ଟ ଅନ୍ତର୍ଭୂକ୍ତ କରି) ନିଶ୍ଚିତ ଭାବରେ `https://` ବ୍ୟବହାର କରିବା ଉଚିତ। ସାଧା `http://` କେବଳ ଏକ ଲୁପ୍ ବ୍ୟାକ୍ ହୋଷ୍ଟ (`localhost`, `127.0.0.0/8`, `::1`) କିମ୍ବା `authType: "none"` ସହିତ ଗ୍ରହଣ କରାଯାଏ, ଯାହା କ key ଣସି ଚାବି ପଠାଏ ନାହିଁ। ବ୍ୟକ୍ତିଗତ LAN ଠିକଣାଗୁଡ଼ିକ (`10.x`, `172.16-31.x`, `192.168.x`) ଛାଡ ନୁହେଁ: ସେହି ନେଟୱାର୍କରେ କେହି ଚାବି ପ read ିପାରନ୍ତି। ଏହିପରି ଏକ ନୋଡ୍ ସଞ୍ଚୟ କରିବା `400` ସହିତ ବିଫଳ ହୁଏ, ଏବଂ ପୂର୍ବରୁ ସଂରକ୍ଷିତ ଏକ ନୋଡ୍ ସମାନ ଅନୁରୋଧ ସହିତ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ଉପରେ ବନ୍ଦ ହୋଇଯାଏ, ଯେକ request ଣସି ଅନୁରୋଧ ପଠାଯିବା ପୂର୍ବରୁ। ଏକ LAN ଉପରେ ଏକ କିଡ୍ ଶେଷ ପଏଣ୍ଟ ପାଇଁ, ଏହାକୁ TLS ପଛରେ ରଖନ୍ତୁ (ଉଦାହରଣ ସ୍ୱରୂପ ଏକ ଓଲଟା ପ୍ରକ୍ସି)।
- `customJson` Zod ସହିତ ବ valid ଧ ହୋଇଛି; ଅଜ୍ଞାତ ଚାବିଗୁଡିକ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଇଛି। ପ୍ରତ୍ୟେକ କ୍ଷେତ୍ର ବ al କଳ୍ପିକ:

| କ୍ଷେତ୍ର           | ମୂଲ୍ୟଗୁଡ଼ିକ                            | ଡିଫଲ୍ଟ।                                                |
| ----------------- | -------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                 | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`            | `bearer`                                               |
| `authHeader`      | `api-key` ଯେତେବେଳେ ବ୍ୟବହୃତ ହେଡର୍ ନାମ।  | `X-API-Key`                                            |
| `requestTemplate` | JSON ବସ୍ତୁ (≤ 64 KB, ଗଭୀରତା ≤ 32)      | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | କ୍ଷେତ୍ର ପଥ, କିମ୍ବା ସମଗ୍ର ଶରୀର ପାଇଁ `$` | `choices[0].message.content`                           |

- ରହସ୍ୟ ସଂଯୋଗର API କିରେ ରହିଥାଏ, ଟେମ୍ପଲେଟରେ କେବେବି ନୁହେଁ। `bearer` `Authorization: Bearer <key>` ପଠାଏ; `api-key` `<authHeader>: <key>` ପଠାଏ। Auth ହେଡର୍ `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` କିମ୍ବା ଏକ ହପ୍-ବାଇ-ହୋପ୍ ହେଡର୍ ହୋଇପାରିବ ନାହିଁ। `none` ସହିତ, ସଂଯୋଗଗୁଡ଼ିକର କ key ଣସି ଆବଶ୍ୟକତା ନାହିଁ।
- ଅତିରିକ୍ତ ଷ୍ଟାଟିକ୍ ହେଡର୍ଗୁଡ଼ିକ ନୋଡର ନିୟମିତ `customHeaders` ବ୍ୟବହାର କରନ୍ତି (ଅନ୍ୟ ସମସ୍ତ ସୁସଙ୍ଗତ ନୋଡ ପରି ସମାନ ବ valid ଧତା; ସେଠାରେ auth ହେଡର୍ ଗୁଡିକ ଅନୁମତିପ୍ରାପ୍ତ ନୁହେଁ)।

`PUT /api/provider-nodes/<id>` ସମାନ `customJson` ଗ୍ରହଣ କରେ ଏବଂ ନୋଡର ପ୍ରତ୍ୟେକ ବିଦ୍ୟମାନ ସଂଯୋଗରେ `baseUrl` ଏବଂ ବିନ୍ୟାସକୁ ପୁନ r ଲିଖନ କରେ। `customJson` ଛାଡିବା ଗଚ୍ଛିତ ବିନ୍ୟାସକୁ ରଖେ; `apiType` କୁ `chat` କିମ୍ବା `responses` ବଦଳାଇବା ଏହାକୁ ନୋଡ ଏବଂ ଏହାର ସଂଯୋଗରୁ ବାହାର କରିଥାଏ।

ତା’ପରେ ପୂର୍ବପରି ନୋଡ ସହିତ ଏକ ସଂଯୋଗ ଯୋଡନ୍ତୁ (ନୋଡ id ସହିତ `POST /api/providers` ) ଏବଂ `<prefix>/<model>` ଅନୁରୋଧ, ଉଦାହରଣ ସ୍ୱରୂପ `biz/assistant-v1`। ଶେଷ ପଏଣ୍ଟ କ model ଣସି ମଡେଲ ତାଲିକା ପ୍ରକାଶ କରେ ନାହିଁ, ତେଣୁ ହାତରେ ମଡେଲ id କୁ ଯୋଡନ୍ତୁ।

## ଟେମ୍ପଲେଟ୍ ଅନୁରୋଧ।

ଟେମ୍ପଲେଟ୍ ଗୁଡିକ ସାଧା JSON। ଏକ ଷ୍ଟ୍ରିଙ୍ଗ୍ ମୂଲ୍ୟ `{{placeholder}}` ମାର୍କର୍ ଧାରଣ କରିପାରେ। କ nothing ଣସି ଜିନିଷର ମୂଲ୍ୟାଙ୍କନ କିମ୍ବା ନିଷ୍ପାଦନ କରାଯାଏ ନାହିଁ, ଏବଂ ବସ୍ତୁ ଚାବିଗୁଡ଼ିକ କେବେବି ବଦଳାଯାଏ ନାହିଁ।

| ସ୍ଥାନଧାରୀ            | ମୂଲ୍ୟ                                                                           |
| -------------------- | ------------------------------------------------------------------------------- |
| `{{prompt}}`         | ଅତ୍ୟାଧୁନିକ ଉପଭୋକ୍ତା ବାର୍ତ୍ତାର ପାଠ୍ୟ (ପାଠ୍ୟ ଅଂଶଗୁଡ଼ିକ ନୂତନ ରେଖା ସହିତ ଯୋଡି ହୋଇଛି) |
| `{{messages}}`       | OpenAI ଚାଟ୍ ଫର୍ମାଟରେ ବାର୍ତ୍ତାଳାପ।                                               |
| `{{model}}`          | ପ୍ରଦାନକାରୀ ଉପସର୍ଗ ବିନା ଅନୁରୋଧ କରାଯାଇଥିବା ମଡେଲ id।                               |
| `{{stream}}`         | ସର୍ବଦା `false` — ଗୋଟିଏ JSON ଡକ୍ୟୁମେଣ୍ଟ ସହିତ ଶେଷ ପଏଣ୍ଟ ଉତ୍ତରଗୁଡିକ।               |
| `{{request.<path>}}` | ଅନୁବାଦିତ (OpenAI ଚାଟ୍ ଫର୍ମାଟ୍) ଅନୁରୋଧର ଏକ କ୍ଷେତ୍ର।                              |

- ଏକ ମୂଲ୍ୟ ଯାହା ଠିକ୍ ଗୋଟିଏ ସ୍ଥାନଧାରୀ ଏହାର JSON ପ୍ରକାର ରଖେ (`"{{messages}}"` ଏକ ଆରେ ହୋଇଯାଏ); ଏକ ଲମ୍ବା ଷ୍ଟ୍ରିଙ୍ଗ୍ ଭିତରେ ଏକ ପ୍ଲେସହୋଲ୍ଡର୍ ଟେକ୍ସଟ୍ ଭାବରେ ଇନ୍ସର୍ଟ ହୁଏ।
- ଏକ ପ୍ଲେସହୋଲ୍ଡର୍ ଯାହା କିଛି ସମାଧାନ କରେ ନାହିଁ ଏକ ଅସମ୍ପୂର୍ଣ୍ଣ ପେଲୋଡ୍ ପଠାଇବା ପରିବର୍ତ୍ତେ HTTP 400 ସହିତ ଅନୁରୋଧକୁ ବିଫଳ କରେ।
- ପଥଗୁଡିକ ଡଟ୍ ନୋଟେସନ୍ ଏବଂ ସାଂଖ୍ୟିକ ସୂଚକାଙ୍କ (`data.items[0].text`) ବ୍ୟବହାର କରେ। `__proto__`, `prototype` ଏବଂ `constructor` କି ଏବଂ ପଥରେ ପ୍ରତ୍ୟାଖ୍ୟାନ।

## ପ୍ରତିକ୍ରିୟା

`responsePath` ରେ ଥିବା ମୂଲ୍ୟ ସହାୟକ ଉତ୍ତରରେ ପରିଣତ ହୁଏ: ଷ୍ଟ୍ରିଙ୍ଗଗୁଡ଼ିକ ଅତିକ୍ରମ କରେ, ଅନ୍ୟ JSON ମୂଲ୍ୟଗୁଡ଼ିକ କ୍ରମିକ ହୋଇଯାଏ। ଏକ ନିଖୋଜ କିମ୍ବା `null` କ୍ଷେତ୍ର, କିମ୍ବା ଏକ ଶରୀର ଯାହା JSON ନୁହେଁ, HTTP 502 ଫେରସ୍ତ କରେ। ଅପଷ୍ଟ୍ରିମ ତ୍ରୁଟି ସ୍ଥିତି ଦେଇ ଗତି କରେ। ଷ୍ଟ୍ରିମିଂ କ୍ଲାଏଣ୍ଟମାନଙ୍କ ପାଇଁ OmniRoute ସମଗ୍ର JSON ପ୍ରତିକ୍ରିୟାକୁ ଅପେକ୍ଷା କରିଥାଏ ଏବଂ ତାପରେ ଏହାକୁ ଏକ ବିଷୟବସ୍ତୁ ଖଣ୍ଡ ଏବଂ ଫିନିଶ୍ ଖଣ୍ଡ ଭାବରେ ନିର୍ଗତ କରେ। ଏହା ଟୋକନ୍ ଷ୍ଟ୍ରିମିଂ ନୁହେଁ। ଟୁଲ୍ କଲ୍ ଏବଂ ବ୍ୟବହାର କ୍ଷେତ୍ରଗୁଡିକ ମ୍ୟାପ୍ ହୋଇନାହିଁ।

## କଦାପି ରିପ୍ଲାଏ କରନ୍ତୁ ନାହିଁ।

ଏକ ବ୍ୟବସାୟ ଅନୁରୋଧ ବିଫଳ ହେଲେ ମଧ୍ୟ ପାର୍ଶ୍ୱ ପ୍ରତିକ୍ରିୟା ହୋଇପାରେ। OmniRoute ତେଣୁ ଏହାକୁ ଥରେ ପଠାଏ:

- କ transport ଣସି ପରିବହନ ପୁନ ry ଚେଷ୍ଟା ଏବଂ ନିମ୍ନଲିଖିତ ପୁନ ir ନିର୍ଦ୍ଦେଶ ନାହିଁ;
- ଅନ୍ୟ କ connection ଣସି ସଂଯୋଗରେ ପୁନ ret ଚେଷ୍ଟା କରନ୍ତୁ ନାହିଁ (ଆକାଉଣ୍ଟ୍ ଫଲବ୍ୟାକ୍) — ବିଫଳତା ପୂର୍ବପରି ଫେରସ୍ତ ହୋଇଛି ଏବଂ ସଂଯୋଗ ଥଣ୍ଡା ହୋଇନାହିଁ;
- ପରବର୍ତ୍ତୀ କମ୍ବୋ ଟାର୍ଗେଟରେ କ fall ଣସି ଫଲବ୍ୟାକ୍ ନାହିଁ, ଖାଲି କିମ୍ବା ବିଫଳ ଉତ୍ତର ପାଇଁ ମଧ୍ୟ।

ପୃଥକ କ୍ଲାଏଣ୍ଟ ଅନୁରୋଧ, ଏବଂ ଫ୍ୟୁଜନ୍ ପ୍ୟାନେଲ ଯାହା ସ୍ପଷ୍ଟ ଭାବରେ ଅନେକ ମଡେଲକୁ ଡାକେ, ତଥାପି ସ୍ end ାଧୀନ ଭାବରେ ଶେଷ ପଏଣ୍ଟକୁ ଆହ୍ .ାନ କରେ।

## ଏକ ନୋଡ୍ ପରୀକ୍ଷା କରିବା।

ଏକ ସଂଯୋଗ ସଞ୍ଚୟ, ସଂଯୋଗ।** ପରୀକ୍ଷା** ବଟନ୍ ଏବଂ ବ୍ୟାକଗ୍ରାଉଣ୍ଡ୍ ସ୍ୱାସ୍ଥ୍ୟ ଯା check ୍ଚ କେବେ ବି ଶେଷ ପଏଣ୍ଟକୁ କଲ୍ କରେ ନାହିଁ: ସେମାନେ କେବଳ ସଂରକ୍ଷିତ ବିନ୍ୟାସକୁ ବ valid ଧ କରନ୍ତି ଏବଂ ସଂଯୋଗକୁ ଯା if ୍ଚଯୋଗ୍ୟ ନୁହେଁ ବୋଲି ରିପୋର୍ଟ କରନ୍ତି।

`POST /api/provider-nodes/validate` ସହିତ `"apiType": "custom-json"` ଏବଂ ନୋଡ ଫିଲ୍ଡଗୁଡିକ (`baseUrl`, `apiKey`, `customJson`, ଇଚ୍ଛାଧୀନ `customHeaders` ଏବଂ `modelId`) ଏକ ପ୍ରକୃତ ଅନୁରୋଧ ପଠାଏ, `ping` ସହିତ ସର୍ବଶେଷ ଉପଭୋକ୍ତା ପାଠ୍ୟ ଭାବରେ। ଏହା `{ "valid": true }` କିମ୍ବା ଅପଷ୍ଟ୍ରିମ୍ ସ୍ଥିତିର ଉତ୍ତର ଦେଇଥାଏ (କଦାପି ଅପଷ୍ଟ୍ରିମ୍ ବଡି)।

## ଭଣ୍ଡାର

ବିନ୍ୟାସ `provider_nodes.custom_json_config_json` (ସ୍ଥାନାନ୍ତରଣ `240_provider_node_custom_json_config.sql`) ରେ ଗଚ୍ଛିତ ହୋଇଛି ଏବଂ ପ୍ରତ୍ୟେକ ସଂଯୋଗର `providerSpecificData.customJson` ରେ କପି କରାଯାଇଛି।
