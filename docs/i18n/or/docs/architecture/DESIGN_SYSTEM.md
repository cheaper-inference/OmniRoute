> workspace `packages/ui-kit` (`@omniroute/ui-kit`) ଭାବେ vendored କରାଯାଇଛି; upstream snapshot-ଟି

> theme; ଡିଫଲ୍ଟ ପସନ୍ଦ ହେଉଛି `system`। ଡିଫଲ୍ଟ palette ହେଉଛି kitର **Editions** appearance

> Appearance → Color paletteରେ **Classic** ଉପଲବ୍ଧ, ଯାହା lime accent ସହିତ kitର base tokens ବ୍ୟବହାର କରେ। UI, display ଏବଂ code text ପାଇଁ Switzer
> ହେଉଛି ଏକମାତ୍ର family (`--ci-font-ui`; `--ci-font-display` ଏବଂ
> `--ci-font-mono` ଏହାକୁ resolve କରେ), ଯାହା kit ଦ୍ୱାରା ନିଜେ self-host କରାଯାଇଛି (`packages/ui-kit/src/ci-fonts.css`,

> ପ୍ରତ୍ୟେକ icon ହେଉଛି ଏକ Lucide glyph।

## ଯେଉଁଠାରେ ଜିନିଷ ବାସ କରେ।

- **କିଟ୍** `packages/ui-kit/src` ହେଉଛି `packages/ui-kit/UPSTREAM.md` ରେ ପିନ୍ ହୋଇଥିବା ପ୍ରତିଶ୍ରୁତିରେ ଅପଷ୍ଟ୍ରିମ୍ `src/` ର ଏକ ବାଇଟ୍-ଫର୍-ବାଇଟ୍ କପି (ଯାହା ଲାଇସେନ୍ସ ପ୍ରାଧିକରଣକୁ ମଧ୍ୟ ରେକର୍ଡ କରେ); `PATCHES.md` ସ୍ଥାନୀୟ ପ୍ୟାଚ୍ ତାଲିକାଭୁକ୍ତ କରେ (କିଛି ନୁହେଁ)। ଏହା ବିନା ଉତ୍ସ ସହିତ ଉତ୍ସ ଭାବରେ ଖର୍ଚ୍ଚ ହୁଏ: `next.config.mjs` ଏହାକୁ ଟ୍ରାନ୍ସପାଇଲ କରେ, ଏବଂ `tsconfig.json` ମାନଚିତ୍ର `@omniroute/ui-kit` → `packages/ui-kit/src` ଏବଂ `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` (`vitest.config.ts` ଏବଂ `vitest.mcp.config.ts` ସମାନ ଛଦ୍ମନାମ ବହନ କରେ)। ଏହାର ଉପପଥ (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) ଦ୍ a ାରା ଏକ କିଟ୍ ଉପାଦାନ ଆମଦାନୀ କରନ୍ତୁ, `@omniroute/ui-kit` ବ୍ୟାରେଲ୍ ମାଧ୍ୟମରେ କେବେବି ନୁହେଁ: ବ୍ୟାରେଲ୍ ପ୍ରତ୍ୟେକ ଆମଦାନୀକାରୀଙ୍କ ମଧ୍ୟରେ ପ୍ରତ୍ୟେକ ଉପାଦାନ (ତାରିଖ ଚୟନକର୍ତ୍ତା ଅନ୍ତର୍ଭୂକ୍ତ କରି) ଟାଣେ। କିଟ୍ ଷ୍ଟାଇଲସିଟ୍ `src/app/globals.css` (`@import "../../packages/ui-kit/src/ci-styles.css"`, ସଂପୂର୍ଣ୍ଣ ସିଟ୍: କୋର `ci-ui.css` ପ୍ଲସ୍ ପ୍ରତ୍ୟେକ ପ୍ୟାଟର୍ ପରିବାର) ମାଧ୍ୟମରେ ପ୍ରବେଶ କରେ।
- **ଟୋକେନ୍।** `packages/ui-kit/src/ci-tokens.css` `--ci-*` ଟୋକେନ୍ ଘୋଷଣା କରେ; `src/app/globals.css` OmniRoute `--color-*` `--radius-*` `--font-sans` `--font-mono` `--table-*` `--orch-status-*` `--color-fd-*` `var(--color-*)` Tailwind ନୂତନ କୋଡ୍ Tailwind ଉପଯୋଗିତାକୁ ବ୍ୟବହାର କରିଥାଏ (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) କିମ୍ବା କିଟ୍ କ୍ଲାସ୍ — କଦାପି ହେକ୍ସ ମୂଲ୍ୟ (`tests/unit/design-kit-bridge.test.ts` ସେତୁକୁ କାର୍ଯ୍ୟକାରୀ କରେ)। `text-primary` `--text-color-primary` ମାଧ୍ୟମରେ `--color-primary-ink` କୁ ସମାଧାନ କରେ, ତେଣୁ `bg-primary`/`border-primary` ଉଚ୍ଚାରଣ ପୃଷ୍ଠକୁ ରଖିବାବେଳେ ପ୍ରାଥମିକ ପାଠ୍ୟ ପଠନୀୟ ରହିଥାଏ: ସଂସ୍କରଣ ଅଧୀନରେ ଏହା କିଟ୍ ର `--ci-color-accent-active` (ଆଲୋକରେ ଗଭୀର ତମ୍ବା `#99562f`, ଅନ୍ଧାରରେ ତମ୍ବା ଉଚ୍ଚାରଣ); କ୍ଲାସିକ୍ ଅଧୀନରେ, ଆଲୋକରେ lime-800 ଏବଂ ଅନ୍ଧାରରେ ଚୂନ ଉଚ୍ଚାରଣ। ଚାର୍ଟ ସିରିଜ୍ `--color-chart-1` … `--color-chart-8` ବ୍ୟବହାର କରେ, ପ୍ରତ୍ୟେକଟି ଏକ ପାଠ୍ୟ-ସୁରକ୍ଷିତ `--color-chart-N-ink` ଏବଂ ଏକ ଅସ୍ପଷ୍ଟ `--color-chart-N-subtle` ଚିପ୍ ଟିଣ୍ଟ, କିଟ୍ ସିରିଜ୍ କ୍ରମରେ (`ciChartSeriesOrder`) ନ୍ୟସ୍ତ।
- **ଥିମ୍ସ** `<html className="ci-theme ci-scrollbars">` (`src/app/layout.tsx`) ଡକ୍ୟୁମେଣ୍ଟକୁ କିଟ୍ ଥିମ୍ ଏବଂ କିଟ୍ ସ୍କ୍ରୋଲବାର୍ (`--ci-scrollbar-*` ଟୋକେନ୍; `globals.css` ନିଜସ୍ୱ ସ୍କ୍ରୋଲ୍ ବାର୍ ନିୟମ ନାହିଁ, ଏବଂ ଏକ ଉପାଦାନ `scrollbar-width` କିମ୍ବା `scrollbar-color` ସେଟ୍ କରିବା ଉଚିତ୍ ନୁହେଁ, ଯାହା କି କ୍ରୋମିୟମ୍ ଏବଂ ସଫାରିରେ କିଟ୍ ଷ୍ଟାଇଲ୍ ପକାଇବ; `tests/unit/design-kit-bridge.test.ts` ରାକ୍ଷୀ ଉଭୟ)। ପସନ୍ଦ ହେଉଛି `light`, `dark` କିମ୍ବା `system` ( `src/shared/constants/appConfig.ts` ରେ`THEME_CONFIG.defaultTheme = "system"` ; `system` `prefers-color-scheme` ଅନୁସରଣ କରେ)। `src/store/themeStore.ts` ରେ `applyTheme()` ( `THEME_BOOT_SCRIPT` ଦ୍ୱାରା ପ୍ରତିବିମ୍ବିତ, `src/app/layout.tsx` ରେ ଅନ୍ତର୍ଭୁକ୍ତ, ଯାହା ହାଇଡ୍ରେସନ୍ ପୂର୍ବରୁ ଚାଲିଥାଏ) `data-theme="dark"|"light"` ସେଟ୍ କରେ ଏବଂ `.dark` ଶ୍ରେଣୀକୁ `<html>` ରେ ଟୋଗଲ୍ କରେ। କିଟ୍ ର ଡାର୍କ ଟୋକନ୍ ସେଟ୍ `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`) ରେ କିଡ୍ ହୋଇଛି। OmniRoute ର ନିଜସ୍ୱ ଗା dark ଼ ଓଭରବ୍ରିଡ୍ ( `globals.css` ରେ `.dark` ବ୍ଲକ) ଏବଂ `.dark` ଶ୍ରେଣୀରେ ଉତ୍ତରାଧିକାରୀ Tailwind `dark:` ଉପଯୋଗୀତା ଚାବି। କ accent ଣସି ଉଚ୍ଚାରଣ ରଙ୍ଗ ପ୍ରିସେଟ୍ ନାହିଁ: ଉଚ୍ଚାରଣ ସର୍ବଦା କିଟ୍ ରୁ ଆସିଥାଏ, ଏବଂ ଷ୍ଟୋର ଲୋଡ୍ ହେବାବେଳେ ଏକ ପୁରୁଣା ବିଲ୍ଡରୁ ଏକ ସ୍ଥାୟୀ ପ୍ରିସେଟ୍ ଡ୍ରପ୍ ହୋଇଯାଏ।
- **ପ୍ୟାଲେଟ୍।** ଦୁଇଟି, କିଟ୍ (`src/shared/constants/appearancePalette.ts`) ରୁ ଉଭୟ: `editions`, ଡିଫଲ୍ଟ, ଏବଂ `classic`। ସଂସ୍କରଣଗୁଡ଼ିକ ହେଉଛି `<html>` ଉପରେ କିଟ୍ ର `data-ci-appearance="editions"` ଗୁଣ, ଯାହାକି `ci-editions.css` ( `ci-ui.css` ଦ୍ୱାରା ଆମଦାନୀ) `data-theme` ସହିତ ମିଳିତ ହୁଏ। କ୍ଲାସିକ୍ ହେଉଛି ଗୁଣର ଅନୁପସ୍ଥିତି। ରୁଟ୍ ଲେଆଉଟ୍ ସର୍ଭର ଗୁଣବତ୍ତା ପ୍ରଦାନ କରେ, ତେଣୁ କିଛି ପରିଦର୍ଶକ ସଂରକ୍ଷିତ (କିମ୍ବା JS ନାହିଁ) ପ୍ରତ୍ୟେକ ପୃଷ୍ଠରେ — ଡ୍ୟାସବୋର୍ଡ, ଲଗଇନ୍, `/status`, ତ୍ରୁଟି ପୃଷ୍ଠା, `/docs` ଏବଂ PWA ରେ ସଂସ୍କରଣ ପାଇଥାଏ। ସମାନ `theme` ଷ୍ଟୋର୍ରେ (`palette`, `setPalette()`, `src/store/themeStore.ts` ରେ `applyPalette()` ) ଥିମ୍ ପାଖରେ ପସନ୍ଦ ସ୍ଥିର ରହିଥାଏ ଏବଂ `THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`, ଲେଆଉଟ୍ `<head>` ରେ ଅନ୍ତର୍ଭୂକ୍ତ) ଦ୍ୱାରା ରଙ୍ଗ ପୂର୍ବରୁ ପ୍ରୟୋଗ କରାଯାଏ, ଯାହା ସଂରକ୍ଷିତ ପ୍ୟାଲେଟ୍ `"classic"` Tailwind ଉପଯୋଗୀତା କିଟ୍ ଉପାଦାନ ଶ୍ରେଣୀଗୁଡ଼ିକ ଉପରେ ଜିତେ (କିଟ୍ `@layer theme, base, components, utilities` ଘୋଷଣା କରେ ଏବଂ ଏହାର ନିୟମ `components` ରେ ବାସ କରେ) — ବ୍ୟବଧାନ ଏବଂ ଲେଆଉଟ୍ ପାଇଁ ଉପଯୋଗିତା ବ୍ୟବହାର କରେ, କିଟ୍ ଉପାଦାନଗୁଡ଼ିକୁ ପୁନ color ରଙ୍ଗ କରିବା ପାଇଁ ନୁହେଁ। ଟାଇପୋଗ୍ରାଫି ହେଉଛି ଏହାର ବ୍ୟତିକ୍ରମ: `packages/ui-kit/src/ci-typography.css` ଯେକ layer ଣସି ସ୍ତର ବାହାରେ ଆମଦାନୀ ହୁଏ, ତେଣୁ ଏହାର ଟ୍ୟାଗ୍ ଡିଫଲ୍ଟ ୟୁଟିଲିଟିଗୁଡ଼ିକୁ ବିଟ୍ କରେ। ଓଜନ, `tracking-*` ଏବଂ `leading-*` ଶ୍ରେଣୀର `h1` ଉପରେ କ effect ଣସି ପ୍ରଭାବ ନାହିଁ -`h6`, ଓଜନ ଏବଂ `tracking-*` ଟେବୁଲ୍ କୋଷଗୁଡ଼ିକ ଉପରେ କ, ଣସି ପ୍ରଭାବ ନାହିଁ, ଏବଂ ବଟନ୍ ଉପରେ ଓଜନ ନାହିଁ (`tests/unit/dead-typography-classes.test.ts` ସେଗୁଡ଼ିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ); `th`, `td`, `button`, `input` ଏବଂ `textarea` ଉପରେ `font-mono` କ effect ଣସି ପ୍ରଭାବ ନାହିଁ। ଆକାର, ରଙ୍ଗ ଏବଂ `uppercase` ଉପଯୋଗିତା ତଥାପି ପ୍ରଯୁଜ୍ୟ। ଟ୍ୟାଗ୍ ଡିଫଲ୍ଟଗୁଡିକର ଦୁଇଟି ପ୍ରସ୍ଥାନ ଅଛି, ଏବଂ ଓଜନ ସେଟ୍ କରିବା କିମ୍ବା ଟ୍ରାକିଂ କରିବା ପାଇଁ ଏକ ଉପଯୋଗୀତା ମଧ୍ୟ କରେ ନାହିଁ:
   - ଏକ ଉପାଦାନ ଯାହା କିଟ୍ ପ୍ରକାର ଶ୍ରେଣୀ ବହନ କରେ ଟ୍ୟାଗ୍ ଡିଫଲ୍ଟ ଦ୍ୱାରା ଏଡ଼ାଇ ଦିଆଯାଏ, ତେଣୁ କ୍ଲାସ୍ ଯେକ any ଣସି ଟ୍ୟାଗରେ ସମାନ ପ read େ। ରୋଲ୍ କ୍ଲାସ୍ (`type-heading`, `type-body`, `type-reading`, `type-control`, `type-data`, `type-caption`) ମଧ୍ୟ ଅନାବଶ୍ୟକ, ତେଣୁ ଉପଯୋଗିତା ତଥାପି ସେମାନଙ୍କ ପାଖରେ ହଜିଯାଏ। `ci-eyebrow` ହେଉଛି ଏକ `components` ନିୟମ: `<h3 className="ci-eyebrow">` ବର୍ତ୍ତମାନ ଆଖିର ପ୍ରକାର ପାଇଥାଏ, ଏବଂ ଏଥିରେ ଏକ ଉପଯୋଗିତା ପ୍ରୟୋଗ ହୁଏ (ରାକ୍ଷୀ ଏହାକୁ ଫ୍ଲାଗ୍ କରନ୍ତି ନାହିଁ), କିନ୍ତୁ ଆଖିର ନିଜସ୍ୱ `data-size` ଏବଂ `data-weight` ପସନ୍ଦ କରନ୍ତି। `ci-heading` ଏକ ପ୍ରସ୍ଥାନ ନୁହେଁ: ହେଡିଙ୍ଗ୍ ଡିଫଲ୍ଟ ଏପର୍ଯ୍ୟନ୍ତ ପ୍ରଯୁଜ୍ୟ।
   - ଏକ କଣ୍ଟେନରରେ`data-ci-type-roles="layered"` ହୋଷ୍ଟ ଉପଯୋଗିତା ତଳେ, ତଳେ ଥିବା ପ୍ରତ୍ୟେକ ଜିନିଷର ଟ୍ୟାଗ୍ ଡିଫଲ୍ଟକୁ `@layer utilities.ci-type-roles` କୁ ଘୁ moves ୍ଚାଇଦିଏ। ଡ୍ୟାସବୋର୍ଡ ଏହାକୁ ସେଟ୍ କରେ ନାହିଁ: ଏହା ସେଟିଂ କରିବା ଦ୍ every ାରା ଏହା ପ୍ରତ୍ୟେକ ଓଜନ, ଟ୍ରାକିଂ ଏବଂ ଅଗ୍ରଣୀ ଉପଯୋଗିତାକୁ ଥରେ କାର୍ଯ୍ୟକାରୀ କରେ, ତେଣୁ ଏହା ଏହି ନିୟମ ଆବଶ୍ୟକ କରେ ଏବଂ ସମାନ ପରିବର୍ତ୍ତନରେ ସମୀକ୍ଷା ହୋଇଥିବା ରାକ୍ଷୀ (ଗୁଣଟି `src/` ଅଧୀନରେ ଦେଖାଯିବାବେଳେ ରାକ୍ଷୀ ବିଫଳ ହୁଏ)।

## 3. ଏକ ସ୍କ୍ରିନ୍ ଯୋଡ଼ିବା

1. କିଟ୍ `PageHeader` (`@omniroute/ui-kit/page-header`, ଡ୍ୟାସବୋର୍ଡ ଭିତରେ `compact`) ସହିତ ପୃଷ୍ଠା ଖୋଲନ୍ତୁ — ଶୀର୍ଷକ, ବର୍ଣ୍ଣନା ଏବଂ `actions`। ଏହାପରେ shell header ନିଜର ଶୀର୍ଷକକୁ ହଟାଇଦିଏ, ଏବଂ 1024 px ଠାରୁ କମ୍ ହେଲେ ଏହା ଲୁଚିଯାଏ, ତେଣୁ `PageHeader` ବିନା ଥିବା ଏକ route ରେ ଫୋନ୍ରେ କୌଣସି ଶୀର୍ଷକ ଦେଖାଯାଏ ନାହିଁ
   (`tests/unit/dashboard-page-header-coverage.test.ts`)। ଯେଉଁ path segment ର ନିଜସ୍ୱ କୌଣସି page ନାହିଁ, ତାହା `ROUTE_PREFIXES_WITHOUT_PAGE` ରେ
   `src/shared/utils/breadcrumbTrail.ts` ଭିତରକୁ ଯାଏ, ତେଣୁ ଏହାର crumb ଏକ dead link ନହୋଇ
   ଟେକ୍ସଟ୍ ହୁଏ (`tests/unit/breadcrumb-trail-routes.test.ts`)।
2. `@/shared/components` (adapters) ରୁ controls ତିଆରି କରନ୍ତୁ ଏବଂ ଯେଉଁଠାରେ adapter ନାହିଁ ସେଠାରେ subpath ଦ୍ୱାରା kit components ବ୍ୟବହାର କରନ୍ତୁ (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`,
   `Slider`…)।

4. `tests/unit/ui/adapters/<name>.test.tsx` ଯୋଡ଼ନ୍ତୁ କିମ୍ବା ଅଦ୍ୟତନ କରନ୍ତୁ । ଅନେକ caller ଥିବା ଆଡାପ୍ଟର ପାଇଁ, ପରିବର୍ତ୍ତନ ପୂର୍ବରୁ ଏବଂ ପରେ ରେଣ୍ଡର୍ ହୋଇଥିବା ମାର୍କଅପ୍ ତୁଳନା କରନ୍ତୁ — padding କିମ୍ବା wrapper ପରିବର୍ତ୍ତନ ପ୍ରତ୍ୟେକ ସ୍କ୍ରିନ୍କୁ ବ୍ୟାପିଯାଏ ।
