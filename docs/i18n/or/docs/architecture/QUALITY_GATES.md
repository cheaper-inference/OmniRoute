ପରିପକ୍ୱତା ବର୍ଗୀକରଣ ଏବଂ ଟୁଲ୍-ନିରପେକ୍ଷ ପ୍ରତିରୂପଣ ଯୋଜନା ପାଇଁ,

## ଗେଟ୍ ଭଣ୍ଡାର ଏବଂ ନିଷ୍ପାଦନ ପ୍ରୋଫାଇଲ୍।

### ପ୍ରାର୍ଥୀ ଆଡମିଶନ।

CI ଏବଂ କ୍ୱାଲିଟି ଗେଟ୍ସ ୱାର୍କଫ୍ଲୋ ପ୍ରତ୍ୟେକ ଏକ ସ୍ଥିର ରାୟ ନିର୍ଗତ କରେ: `Gate / CI` ଏବଂ `Gate / Quality`। ସେମାନଙ୍କର ସଂସ୍କରଣ ଆଡମିଶନ ନୀତି ପ୍ରତ୍ୟେକ ଅପଷ୍ଟ୍ରିମ କାର୍ଯ୍ୟକୁ ଆବଶ୍ୟକ କିମ୍ବା ପରାମର୍ଶଦାତା ଭାବରେ ଗଣନା କରେ। ଏକ ପ୍ରଯୁଜ୍ୟ ଆବଶ୍ୟକୀୟ କାର୍ଯ୍ୟ ନିଶ୍ଚିତ ଭାବରେ ସଫଳ ହେବ: ନିଖୋଜ, ବାତିଲ୍, ଛାଡି, ବିଚାରାଧୀନ ଏବଂ ଅଜ୍ଞାତ ଫଳାଫଳ PASS ପ୍ରତିଷ୍ଠା କରିପାରିବ ନାହିଁ। କେବଳ ଏକ ବ valid ଧ ଡକସ୍ କିମ୍ବା କାଟାଲଗ୍-କେବଳ ବର୍ଗୀକରଣ ଏକ କୋଡ୍ ଗାଡ଼ି ଅନୁପଯୁକ୍ତ କରିପାରେ। ଏକ ଡ୍ରାଫ୍ଟ PR ଏକ ଗ୍ରହଣୀୟ ପ୍ରାର୍ଥୀ ନୁହେଁ। ଏକ `hotfix` ଲେବଲ୍ ପ୍ରମାଣ ଛାଡ କରେ ନାହିଁ।

ଉଭୟ ୱାର୍କଫ୍ଲୋ PRs main/release ଶାଖାରେ ଆବୃତ କରେ, `main` କୁ ଠେଲିଥାଏ, ମାନୁଆଲ୍ ପଠାଇବା ଏବଂ ମିଶ୍ରଣ-ଗୋଷ୍ଠୀ ଇଭେଣ୍ଟଗୁଡିକ। ପୁସ୍, ପଠାଇବା ଏବଂ ମିଶ୍ରଣ-ଗୋଷ୍ଠୀ ପୂର୍ଣ୍ଣ ଚୟନ ଚଲାନ୍ତୁ। `release/**` କୁ ଠେଲିବା ସେଗୁଡିକ ଆରମ୍ଭ କରେ ନାହିଁ (2026-10-18): ପ୍ରତ୍ୟେକ ପରିବର୍ତ୍ତନ ଏହାର PR ରେ ମ୍ୟାଟ୍ରିକ୍ସ ଚଲାଇସାରିଛି ଏବଂ ମିଶ୍ରିତ ମିଶ୍ରଣ ହେଉଛି ରିଲିଜ୍-ଗ୍ରୀନ୍ ର କାର୍ଯ୍ୟ (`docs/ops/RUNNER_BOX.md` → ହୋଷ୍ଟେଡ୍ ଲେନ୍)। ଫର୍କସ୍ ଏବଂ ମିଶ୍ରଣ ଗୋଷ୍ଠୀଗୁଡିକ ଚାକିରି ପାଇଁ ହୋଷ୍ଟ ରନର୍ସ ବ୍ୟବହାର କରନ୍ତି ଯାହା ଅନ୍ୟଥା ସ୍ୱ-ହୋଷ୍ଟ ରନର୍ସ ଚୟନ କରେ। ଯଥେଷ୍ଟ ହୋଷ୍ଟ କ୍ଷମତା ରୋଲଆଉଟ୍ ପୂର୍ବରୁ ଯାଞ୍ଚ ହେବା ଜରୁରୀ।

ଏକ ସାଧାରଣ PR ଦ୍ରୁତ ଚୟନ ଚଲାଇଥାଏ। ଆଡମିଶନ ପଲିସିର `full-code` ଏବଂ `full-code-e2e` ଗାଡ଼ି (E2E, ଇଣ୍ଟିଗ୍ରେସନ୍, ପ୍ୟାକେଜ୍ ଆର୍ଟିଫାକ୍ଟ, Electron ଧୂଆଁ, Bun SQLite, ଇକୋସିଷ୍ଟମ୍ ଏବଂ ପ୍ରୋଟୋକଲ୍ କ୍ଲାଏଣ୍ଟ) କେବଳ ଏକ ମର୍ଜିଫ୍ କ୍ୟୁ ଡ୍ରାଫ୍ଟରେ କିମ୍ବା ସମ୍ପୂର୍ଣ୍ଣ ଚାଲିବାରେ ଚାଲିଥାଏ: `gh workflow run ci.yml --ref <branch>`।

ପ୍ରତ୍ୟେକ JSON ରସିଦ ଚେକ୍ ଆଉଟ୍ SHA, ୱାର୍କଫ୍ଲୋ ଚଲାଇବା ଏବଂ ପ୍ରୟାସକୁ ଚିହ୍ନଟ କରେ। CLI ଏକ checkout/event SHA ଅସଙ୍ଗତିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। ୱାର୍କଫ୍ଲୋ ପରୀକ୍ଷଣ ନୀତି ସଦସ୍ୟତାକୁ ବିଚାରର `needs` ତାଲିକାରେ ବାନ୍ଧେ ତେଣୁ ଏକ ନୂତନ କିମ୍ବା ଅପସାରିତ ଗାଡ଼ି ଚୁପଚାପ୍ ଅଦୃଶ୍ୟ ହୋଇପାରିବ ନାହିଁ। ରସିଦଗୁଡ଼ିକ ସେମାନଙ୍କର ନିଜସ୍ୱ କାର୍ଯ୍ୟ ପ୍ରବାହକୁ ଆବୃତ୍ତି କରେ, ପ୍ରକାଶନ, ନିୟୋଜନ କିମ୍ବା ଏକ ବିଦ୍ୟମାନ ପରାମର୍ଶଦାତା ସ୍କାନରର ଆଭ୍ୟନ୍ତରୀଣ ନୁହେଁ। ଶାଖା ନିୟମରେ ଉଭୟ ଚେକ୍ ନାମକୁ ସକ୍ରିୟ କରିବା ଏକ ପୃଥକ ପ୍ରଶାସନିକ ପରିବର୍ତ୍ତନ; ଏହି ଚାକିରିଗୁଡିକ ଯୋଡିବା ନିଜେ ଏକ ଶାଖା ରକ୍ଷା କରେ ନାହିଁ।

### ଧାଡ଼ି ମିଶ୍ରଣ କରନ୍ତୁ।

> **2026-11-19: Mergify ମିଶ୍ରଣ ଧାଡ଼ିକୁ ଅବସର ଦିଆଯାଇଛି** (ମାଲିକଙ୍କ ନିଷ୍ପତ୍ତି)। `.mergify.yml` ଆଉ କୌଣସି ଧାଡ଼ି ପରିଭାଷିତ କରେ ନାହିଁ ଏବଂ ପୁଲ୍ ଅନୁରୋଧକୁ ମିଶ୍ରଣ ବା ପୁନଃଲେଖନ କରୁଥିବା Mergify ନିର୍ଦ୍ଦେଶଗୁଡ଼ିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। omni-queue live ମୋଡ୍‌ରେ ଚାଲୁ ହେବା ପର୍ଯ୍ୟନ୍ତ, ରିଲିଜ୍ ଶାଖାର ପୁଲ୍ ଅନୁରୋଧଗୁଡ଼ିକ ରିପୋଜିଟୋରୀର “Require green gates on the active release” ନିୟମସମୂହ (`Gate / CI` + `Gate / Quality`) ଅଧୀନରେ ହାତରେ ମିଶ୍ରଣ କରାଯାଏ। ତା’ପରେ ସେଗୁଡ଼ିକ omni-queue ମାଧ୍ୟମରେ ମିଶ୍ରଣ ହୁଏ ([OMNI_QUEUE.md](../ops/OMNI_QUEUE.md))। ନିମ୍ନରେ ବର୍ଣ୍ଣିତ Mergify ଡ୍ରାଫ୍ଟର ୱାର୍କଫ୍ଲୋ ନିୟନ୍ତ୍ରଣ ଏବେ ମଧ୍ୟ `ci.yml` ଓ `quality.yml` ରେ ରହିଛି, କିନ୍ତୁ ଆଉ କୌଣସି Mergify ଡ୍ରାଫ୍ଟ ଖୋଲାଯାଏ ନାହିଁ।

`queue` ଲେବଲ୍ ମିଶ୍ରଣ କ୍ରମ (`.mergify.yml`) କୁ ଏକ PR ପଠାଏ। ମିଶ୍ରଣ ଏକ `mergify/merge-queue/` ଶାଖାରେ PR ଏକ ଡ୍ରାଫ୍ଟ ଖୋଲିଥାଏ, CI ସେଠାରେ ପୂର୍ଣ୍ଣ ଚୟନ ଚଲାଇଥାଏ, ଏବଂ `Gate / CI`, `Gate / Quality` ଏବଂ `Merge integrity (changelog + generated skills)` ପାସ୍ କଲାବେଳେ ମୂଳ PR ମିଶ୍ରଣ ହୁଏ।

ମିଶ୍ରଣ ଏହାର କ୍ରମ ସାରାଂଶକୁ ଡ୍ରାଫ୍ଟର ବର୍ଣ୍ଣନାରେ ଲେଖେ, ଏବଂ ଅନ୍ୟାନ୍ୟ ଆପ୍ ମଧ୍ୟ ଏହାକୁ ସଂପାଦନ କରିପାରନ୍ତି। ଏହିପରି ଏକ ଡ୍ରାଫ୍ଟ ଉପରେ ଏକ `pull_request` `edited` ଇଭେଣ୍ଟ ନିଜସ୍ୱ ସମନ୍ୱୟ ଗୋଷ୍ଠୀ (`-queue-edit-<run_id>`) ନେଇଥାଏ ତେଣୁ ଏହା ଡ୍ରାଫ୍ଟର ପ୍ରକୃତ ରନ୍ ବାତିଲ୍ କରିପାରିବ ନାହିଁ, ଏବଂ ଏହା ଗେଟ୍ ଏବଂ ମ୍ୟାଟ୍ରିକ୍ସକୁ ଛାଡିଦିଏ। କେବଳ `Merge integrity` ଚାଲିଥାଏ। ସ୍କିପ୍ ହୋଇଥିବା ଗେଟ୍ କାର୍ଯ୍ୟ ଏକ ଭିନ୍ନ ଚେକ୍ ନାମ ବହନ କରେ, କାରଣ ମର୍ଜିଫ୍ ଏକ ସ୍କିପ୍ ହୋଇଥିବା `Gate / CI` ଏକ ବିଫଳ ଚେକ୍ ଭାବରେ ପ read ିଥାଏ ଏବଂ PR କୁ ଡିସ୍କ କରିଥାଏ।

ଏକ ଡେକ୍ ପରେ, ଏକ ପୁସ୍ ସର୍ବଦା PR ଆବଶ୍ୟକ କରେ ନାହିଁ। ଏହା ଉପରେ `@mergifyio queue` ମନ୍ତବ୍ୟ ଦିଅନ୍ତୁ।

### ଗ୍ରହଣ ରିଡ୍ୟୁଟରରେ ପ୍ରମାଣ ରଖାଯାଇଛି।

`scripts/quality/validate-release-acceptance.mjs` ଏକ ଯୋଗାଣ ଯୋଜନା ଏବଂ ଏହାର ପ୍ରକାଶନକୁ ହ୍ରାସ କରେ; ଏହା ସ୍ଥିର କରେ ନାହିଁ ଯେ ଯୋଜନାଟି ସମ୍ପୂର୍ଣ୍ଣ ରିଲିଜ୍ ପାଇପଲାଇନକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ। ଏହାର ରିପୋର୍ଟଗୁଡିକ ସ୍ପଷ୍ଟ ଭାବରେ `releaseAcceptance: false` ସେଟ୍ କରେ, ଯଦିଓ ସେହି ଯୋଜନା `VERIFIED` ଅଟେ। `release-acceptance.yml` ୱାର୍କଫ୍ଲୋ ତଥାପି ଛାୟା ଫିକ୍ଚର୍ ବ୍ୟବହାର କରେ, ପ୍ରକୃତ ନିର୍ମାଣ, ପ୍ୟାକେଜ୍, ବୁଟ୍ କିମ୍ବା ପଦୋନ୍ନତି ରସିଦ ନୁହେଁ।

ସଂରକ୍ଷିତ ପ୍ରମାଣ ଯାଞ୍ଚ କରିବାକୁ CLI `--evidence-root` ଆବଶ୍ୟକ କରେ। ଫାଇଲଗୁଡିକ `<evidence-root>/<artifact_id>/<member>` ଭାବରେ ସମାଧାନ ହୋଇଛି ଏବଂ SHA-256 ପରି ହ୍ୟାସ୍ ହୋଇଛି। ପ୍ରମାଣ ବିନା ଏକ PASS ରେକର୍ଡ, ଏକ ନିଖୋଜ କିମ୍ବା ପରିବର୍ତ୍ତିତ ଫାଇଲ, ଏକ ଅସୁରକ୍ଷିତ ପଥ କିମ୍ବା ଏକ ସିମ୍ଲିଙ୍କ ଯାଞ୍ଚକୁ ରୋକିଥାଏ। ନିଖୋଜ ଫାଇଲଗୁଡ଼ିକ ଖାଲି ସଫଳ ଲଗ ସହିତ ସମାନ ନୁହେଁ। ବିଦ୍ୟମାନ SHA/run/attempt ଯାଞ୍ଚଗୁଡିକ ସ୍ independent ାଧୀନ ରହିଥାଏ: ମେଳ ଖାଉଥିବା ବାଇଟ୍ ଏକ ପୁରୁଣା ରସିଦକୁ ଉଦ୍ଧାର କରିପାରିବ ନାହିଁ। ଫାଇଲ୍ ଅଖଣ୍ଡତା ଏକଜେକ୍ୟୁସନ ପ୍ରାମାଣିକତା କିମ୍ବା କଳାକୃତି ପଦୋନ୍ନତିର ପ୍ରମାଣ ନୁହେଁ।

### ଷ୍ଟାଟିକ୍ ସ୍କାନ୍ ଭଣ୍ଡାର।

ସଂସ୍କରଣ npm-alias inventary ଏବଂ static-scan ସଦସ୍ୟତା `config/quality/gate-manifest.json` ରେ ରୁହନ୍ତି। ସ୍କ୍ରିପ୍ଟ ନାମ ଏବଂ `package.json` ବିରୁଦ୍ଧରେ ସଠିକ୍ ନିର୍ଦ୍ଦେଶକୁ ବ valid ଧ କରିବାକୁ `npm run check:gate-manifest` ଚଲାନ୍ତୁ; ଯୋଗ, ଅପସାରଣ ଏବଂ ନିର୍ଦ୍ଦେଶ ଡ୍ରାଇଫ୍ ଉଭୟ ସ୍ଥାନୀୟ ହୁକ୍ ଏବଂ CI ରେ ପରିବର୍ତ୍ତନ-ବର୍ଗୀକରଣ କାର୍ଯ୍ୟ ବିଫଳ ହୁଏ। ଏକ ଛଦ୍ମନାମ ଏକ କାର୍ଯ୍ୟଧାରା କାର୍ଯ୍ୟ ନୁହେଁ, ମ୍ୟାଟ୍ରିକ୍ସ ଉଦାହରଣ କିମ୍ବା ପରୀକ୍ଷଣ ମାମଲା: ଏହି ଗଣନାଗୁଡ଼ିକ ଅଦଳବଦଳ ଭାବରେ ଉପସ୍ଥାପିତ ହେବା ଉଚିତ ନୁହେଁ।

ସେଗୁଡ଼ିକୁ କାର୍ଯ୍ୟକାରୀ ନକରି ମନୋନୀତ ଛଦ୍ମନାମ ଯାଞ୍ଚ କରିବାକୁ `npm run quality:scan -- --list` କିମ୍ବା `npm run quality:scan:fast -- --list` ବ୍ୟବହାର କରନ୍ତୁ। ରନର୍ npm ଏଣ୍ଟ୍ରିପଏଣ୍ଟକୁ ଆହ୍ .ାନ କରେ, ତେଣୁ ଏହାର ଚାଲିବା ସମୟ ( Bun ଅନ୍ତର୍ଭୂକ୍ତ କରି ଯେଉଁଠାରେ ବିନ୍ୟାସିତ) ସଂରକ୍ଷିତ। ସେହି ପ୍ରୋଫାଇଲଗୁଡିକ ବାହାରେ ପ୍ରକାଶିତ ରେକର୍ଡ ଛଦ୍ମନାମଗୁଡିକ ପୃଥକ ଭାବରେ ଆହ୍ as ାନିତ, ଏବଂ କେବଳ ପଠନୀୟ ସ୍କାନ ପ୍ରୋଫାଇଲରେ ରକ୍ଷଣାବେକ୍ଷଣ ନିର୍ଦ୍ଦେଶଗୁଡ଼ିକ ନିଷେଧ।

ଏହି ପ୍ରୋଫାଇଲଗୁଡ଼ିକ କେବଳ ଷ୍ଟାଟିକ୍ ସ୍କାନ୍ କୁ ଆବୃତ କରେ। ସେମାନେ ଉତ୍ପାଦ ପରୀକ୍ଷା, କଭରେଜ, ପ୍ୟାକେଜିଂ, ବାହ୍ୟ ଯା s ୍ଚ କିମ୍ବା ଜଣେ ପ୍ରାର୍ଥୀଙ୍କ ପୂର୍ଣ୍ଣ ପ୍ରକାଶନ ଗ୍ରହଣକୁ ପ୍ରମାଣ କରନ୍ତି ନାହିଁ। ୱାର୍କଫ୍ଲୋ ଆଡମିଶନ ସଂଯୁକ୍ତ `config/quality/admission-policy.json` ଏବଂ `scripts/quality/admission-verdict.mjs` ବ୍ୟବହାର କରେ। ରିଲିଜ୍-ପର୍ଯ୍ୟବେକ୍ଷକ ପ୍ରୋଫାଇଲ୍ ଅଲଗା ରହିଥାଏ; ନିରପେକ୍ଷ ଭାବରେ ସେମାନଙ୍କର ପ୍ରଯୁଜ୍ୟ ଯାଞ୍ଚ ଏବଂ ରସିଦ ଯାଞ୍ଚ କରନ୍ତୁ। `audit:deps`, mutation-test ଚୟନ ଏବଂ ଅନୁବାଦ ଯାଞ୍ଚ ସହିତ `config/quality/release-green-static-profile.json` ରେ ପୂର୍ଣ୍ଣ ପର୍ଯ୍ୟବେକ୍ଷକଙ୍କ ଷ୍ଟାଟିକ୍ କମାଣ୍ଡ ଘୋଷିତ ହୋଇଛି। ଲୋଡର୍ package.json ଏବଂ ମଡେଲ ହୋଇଥିବା CI/Quality ଘୋଷଣାନାମା ବିରୁଦ୍ଧରେ npm ନିର୍ଦ୍ଦେଶଗୁଡ଼ିକୁ ବ valid ଧ କରେ। ଏହା ଆର୍ଗୁମେଣ୍ଟସ୍ ଭାବରେ ସେଲ୍ ଟୋକେନ୍ ଏକଜେକ୍ୟୁଟ୍ କରିବା ପରିବର୍ତ୍ତେ ଡ୍ରିଫ୍ଟକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। ଆବଶ୍ୟକ ସ୍କାନର୍ SKIP/INCOMPLETE ଆଉଟପୁଟ୍ PASS ପ୍ରତିଷ୍ଠା କରିପାରିବ ନାହିଁ। ପ୍ରୋଫାଇଲ୍ ଏହାର ବାହ୍ୟ ବହିଷ୍କାରକୁ ରେକର୍ଡ କରେ ଏବଂ ହୋଷ୍ଟ କଭରେଜ୍, ଟେଷ୍ଟ ମ୍ୟାଟ୍ରିକ୍ସ, ପ୍ୟାକେଜ୍ କିମ୍ବା ନିୟୋଜନ ପ୍ରମାଣକୁ ସ୍ଥାନାନ୍ତର କରେ ନାହିଁ। ନିମ୍ନରେ ଥିବା ଗଦ୍ୟ ତାଲିକା ହେଉଛି ଏକ ରେଫରେନ୍ସ, ଏକ ଗେଟ୍ ପ୍ରକୃତରେ ଚାଲିଥିବାର ପ୍ରମାଣ ନୁହେଁ।

ସ୍କ୍ରିପ୍ଟଗୁଡ଼ିକ `scripts/check/` (ପଲିସି ଗେଟ୍) ଏବଂ `scripts/quality/` (ରାଞ୍ଚେଟ୍ ଇଞ୍ଜିନ୍) ଅଧୀନରେ ବାସ କରେ। ସତ୍ୟର CI ଉତ୍ସ ହେଉଛି `.github/workflows/ci.yml`।

#### ଭୁଲିଯାଇଥିବା ସହୋଦର ଟେଷ୍ଟ ରିପୋର୍ଟ

`npm run check:forgotten-sibling-tests` `Fast Quality Gates` ର ଏକ ପରାମର୍ଶଦାତା ପଦକ୍ଷେପ ଭାବରେ ଚାଲିଥାଏ ଏବଂ ପରୀକ୍ଷା-ପ୍ରଭାବ ମାନଚିତ୍ର ପଛରେ ଆମଦାନୀ ସମାଧାନକାରୀକୁ ପୁନ uses ବ୍ୟବହାର କରେ। ପ୍ରତ୍ୟେକ ପରିବର୍ତ୍ତିତ ଉତ୍ପାଦନ ମଡ୍ୟୁଲ୍ ପାଇଁ, ଏହା ନିର୍ଣ୍ଣୟକାରୀ `changed module/symbol -> static consumer -> candidate sibling test` ଶୃଙ୍ଖଳା ରିପୋର୍ଟ କରେ ଯେତେବେଳେ ପ୍ରାର୍ଥୀ ପରୀକ୍ଷା ପଲ୍-ଅନୁରୋଧ ଭିନ୍ନରୁ ଅନୁପସ୍ଥିତ ଥାଏ। ମାର୍କଡାଉନ୍ ସାରାଂଶ ଏବଂ JSON ଫଳାଫଳ କ any ଣସି ଅବରୋଧ ରୋଲଆଉଟ୍ ପୂର୍ବରୁ କାଲିବ୍ରେସନ୍ ପାଇଁ `forgotten-sibling-tests` ୱାର୍କଫ୍ଲୋ ଆର୍ଟିଫାକ୍ଟ ଭାବରେ ରଖାଯାଇଛି।

ବ୍ୟାରେଲ୍ ପୁନ - ରପ୍ତାନି ଏବଂ ଗତିଶୀଳ ଆମଦାନୀ କେବଳ ରେଜୋଲୁସନ ଡାଇଗ୍ନୋଷ୍ଟିକ୍ ଅଟେ; ସେମାନେ କଦାପି ଏକ ଅବରୋଧକାରୀ ସନ୍ଧାନ ସୃଷ୍ଟି କରନ୍ତି ନାହିଁ। ସମୀକ୍ଷା ହୋଇଥିବା ବ୍ୟତିକ୍ରମଗୁଡ଼ିକ `config/quality/forgotten-sibling-allowlist.json` ରେ ରୁହନ୍ତି। ପ୍ରତ୍ୟେକ ଏଣ୍ଟ୍ରି ନିଶ୍ଚିତ ଭାବରେ ଗ୍ରାହକ ଏବଂ ପ୍ରାର୍ଥୀ ପରୀକ୍ଷଣର ନାମ ଦେବା, ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ ଯୁକ୍ତିଯୁକ୍ତତା ପ୍ରଦାନ କରିବା, ଏବଂ ଏକ GitHub ଇସୁ ଲିଙ୍କ୍ କରିବା କିମ୍ବା ଅନୁରୋଧ ଟାଣିବା। ବିକୃତ ଏଣ୍ଟ୍ରିଗୁଡିକ ବନ୍ଦ ହୋଇଗଲା। ବ୍ୟତିକ୍ରମଗୁଡିକ ଏକ ବିଲୋପିତ ପ୍ରାର୍ଥୀ ପରୀକ୍ଷା କିମ୍ବା `.skip`/`.todo` ଯୋଗ କରୁଥିବା ଏକ ଭିନ୍ନତାକୁ ଦମନ କରିପାରିବ ନାହିଁ। ଧାରଣା ଦୁର୍ବଳ ହେବା ଏବଂ ଅନ୍ୟାନ୍ୟ ମାସ୍କିଂ ସ୍ z ାଧୀନ ଭାବରେ `check:test-masking` ଗେଟକୁ ଅବରୋଧ କରିଥାଏ।

#### ଦୁଇଟି ଟାଇପ୍ ଚେକ୍ ପ୍ରୋଗ୍ରାମ୍ ଭିନ୍ନ ଭାବରେ ଉତ୍ତର ଦିଅନ୍ତି।

`typecheck:core` ଏବଂ `check:build-typecheck` ବିଭିନ୍ନ ବିକଳ୍ପ ଅଧୀନରେ ବିଭିନ୍ନ ପ୍ରୋଗ୍ରାମ୍ ସଂକଳନ କରନ୍ତି, ଏବଂ ସମାନ ଫାଇଲ୍ ଗୋଟିଏରେ ସଫା ହୋଇପାରେ ଏବଂ ଅନ୍ୟଟିରେ ତ୍ରୁଟି ପୂର୍ଣ୍ଣ ହୋଇପାରେ।

`tsconfig.build.json` `"strict": false` ସେଟ୍ କରେ, ତେଣୁ `noImplicitAny` ବନ୍ଦ ଅଛି। କୋର୍ କନଫିଗ୍ ଏକ କଠିନ 27-ଫାଇଲ୍ ଅନୁମତି ତାଲିକାକୁ କଠିନ ବିକଳ୍ପ ସହିତ ସଂକଳନ କରେ ଏବଂ ପ୍ରତ୍ୟେକ ଏଣ୍ଟ୍ରିର ଆମଦାନୀ ଗ୍ରାଫ୍ ଅନୁସରଣ କରେ, ତେଣୁ ବିଲ୍ଡ ପ୍ରୋଗ୍ରାମରେ କେବେବି ଦେଖାଯାଉଥିବା ଫାଇଲଗୁଡ଼ିକ ସେଠାରେ ଯାଞ୍ଚ କରାଯାଇଥାଏ।

ଏକ ଫାଇଲ୍ ଟାଇପ୍ ହୋଇଛି କି ନାହିଁ ବିଚାର କରିବାବେଳେ ଏହାର ପରିଣାମ ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ:** `check:build-typecheck` ଅଧୀନରେ ଶୂନ୍ୟ ନିଦାନ ଶୂନ୍ୟ ନୁହେଁ।** । 26 ଫାଇଲରୁ `@ts-nocheck` ଛଡ଼ାଇବା ସେମାନଙ୍କ ମଧ୍ୟରୁ 23 ଟି ବିଲ୍ଡ ପ୍ରୋଗ୍ରାମରେ ସଫା ଦେଖାଇଲା। ସେମାନଙ୍କ ମଧ୍ୟରୁ ଷୋହଳଟି ପ୍ରାୟ 120 ଅନ୍ତର୍ନିହିତ - କ any ଣସି ତ୍ରୁଟିରେ ଦେଖାଗଲା। ଏକ ଫାଇଲ୍ ସଫା କରିବା ପୂର୍ବରୁ ଉଭୟ ଯାଞ୍ଚ କରନ୍ତୁ।

- `check:docs-sync` — ରିଲିଜ୍ ମୋଡ୍ ପ୍ରତ୍ୟେକ ଚେକ୍ ଚଲାଇଥାଏ। PR package.json/OpenAPI CHANGELOG `SKIP reason=pr-mode` `llm.txt` CHANGELOG — PR `docs/i18n/**` `config/quality/derived-paths/*.json` `docs/i18n/<locale>/llm.txt` `CHANGELOG.md` ଡିଫ୍ ବେସ୍ ଏକ depth-1 ଚେକଆଉଟ୍ ( `docs-sync-strict` ଚାକିରି) ରେ ସମାଧାନ ହୁଏ ନାହିଁ, ତେଣୁ PR ମୋଡ୍ ମଧ୍ୟ ଗୋଟିଏ ଚେକ୍ ଚଲାଇଥାଏ ଯାହା କ base ଣସି ଆଧାର ଆବଶ୍ୟକ କରେ ନାହିଁ: ପ୍ରତ୍ୟେକ `llm.txt` ଦର୍ପଣ ନିଶ୍ଚିତ ଭାବରେ ବିଦ୍ୟମାନ ରହିବା ଆବଶ୍ୟକ, ଏହାର `---` ବିଛିନ୍ନକାରୀ ରଖିବା ଏବଂ ମୂଳ ଶରୀର କିମ୍ବା ଶରୀରର ଅଧିକାଂଶ ଦର୍ପଣ ଅଂଶ ବହନ କରିଥାଏ। ଏକ ବେସ୍ ଯାହା ଘୁଞ୍ଚିଗଲା ସମସ୍ତ ଦର୍ପଣକୁ ସମାନ ଭାବରେ ଷ୍ଟାଲ୍ ଏବଂ ପାସ୍ କରେ। ଗୋଟିଏ ଦର୍ପଣରେ ଏକ ହାତ ସଂପାଦନ ବିଫଳ ହୁଏ। ଅନୁବାଦିତ `CHANGELOG.md` ଫାଇଲଗୁଡ଼ିକରେ depth-1 PR ଚେକଆଉଟ୍ ରେ ସେପରି କ check ଣସି ଯାଞ୍ଚ ନାହିଁ।
- ପ୍ରି-କମ୍ୟୁଟ୍ ହୁକ୍ `check-docs-sync.mjs --mode=pr` ଚଲାଇଥାଏ: ଏକ ପ୍ରତିବଦ୍ଧତା ଯାହା କରେ ତାହା ଉପରେ ବିଚାର କରାଯାଏ। ଫ୍ଲାଗ୍ ବିନା ଏକ ସ୍ଥାନୀୟ ରନ୍ ହେଉଛି ରିଲିଜ୍ ମୋଡ୍, ଏବଂ ଗୋଟିଏ ମିଶ୍ରିତ PR ଯାହା ମୂଳ `llm.txt` ଏଡିଟ୍ କରେ, ତରଙ୍ଗ ଚାଲିବା ପର୍ଯ୍ୟନ୍ତ ସେହି ଆଧାରରେ ପ୍ରତିଟି ପ୍ରତିବଦ୍ଧତାକୁ ଅବରୋଧ କରିବ। ସମାନ ନିୟମ ଯେକ any ଣସି ମୋଡ୍-ସଚେତନ ଗେଟ୍ ପାଇଁ ଏକ ହସ୍କି ହୁକ୍ ଚଲାଇଥାଏ: ହୁକ୍ `--mode=pr` ପାସ୍ କରେ, ଏବଂ କଠୋର ନିଷ୍ପତ୍ତି ରିଲିଜ୍-ମୋଡ୍ ରନ୍ ସହିତ ରହିଥାଏ (ରିଲିଜ୍ PR, `main` କୁ ଠେଲିଥାଏ, ଏକ ସାଧା ଲୋକାଲ୍ ରନ୍)।
- ଦର୍ପଣ-ବିଷୟବସ୍ତୁ ୟୁନିଟ୍ ପରୀକ୍ଷା (`tests/_helpers/mirrorFreshness.ts`: `cycle-docs-mirror-contract`, `resilience-pre-dispatch-docs-mirrors`, `cli-env-quality-docs-mirrors`, `docs/*-locales`) — ରିଲିଜ୍ ମୋଡ୍ ପ୍ରତ୍ୟେକ ଲୋକାଲ୍ କୁ ଦର୍ଶାଏ। PR ମୋଡ୍ କେବଳ ଦର୍ପଣଗୁଡ଼ିକୁ ସୂଚିତ କରେ ଯାହା `.i18n-state.json` ଅନୁଯାୟୀ ଇଂରାଜୀ ଉତ୍ସ ସହିତ ସାମ୍ପ୍ରତିକ ଅଟେ (ପୁରା ଫାଇଲ୍ ହ୍ୟାସ୍, କିମ୍ବା ପରୀକ୍ଷଣ ପିନର ବିଭାଗର ରେକର୍ଡ ହୋଇଥିବା ବିଭାଗ ହ୍ୟାସ୍) ଏବଂ ଏକ କାରଣ ସହିତ ଷ୍ଟଲ୍ଗୁଡ଼ିକୁ ଛାଡିଦିଏ। `target_hash` ପ୍ରୋଭାନ୍ସ ଯାଞ୍ଚ ଉଭୟ ମୋଡରେ ପ୍ରତ୍ୟେକ ଲୋକାଲ୍ ପାଇଁ ଚାଲିଥାଏ। ସତେଜତା ହେଉଛି `## ` ବିଭାଗ, ୟୁନିଟ୍ `run-translation.mjs` ହ୍ୟାସ୍; ଏକ ଲମ୍ବା ବିଭାଗ (ଏହି ଫାଇଲର ଗେଟ୍ ଇନଭେଣ୍ଟୋରୀ ଏହାର ଅଧା ଅଟେ) ଅର୍ଥାତ୍ ଏଥିରେ ଥିବା ଯେକ edit ଣସି ସମ୍ପାଦନା ସେହି ଦର୍ପଣଗୁଡ଼ିକୁ ଅକାମୀ କରିଦିଏ, ଏବଂ ସେମାନଙ୍କର PR- ମୋଡ୍ ଧାରଣା ପରବର୍ତ୍ତୀ ତରଙ୍ଗ ପର୍ଯ୍ୟନ୍ତ ଛାଡିଦିଏ। ଏକ ଆଙ୍କର୍ ଇଂରାଜୀ ଉତ୍ସ ଆଉ ଧାରଣ କରେ ନାହିଁ ପୁରା ଫାଇଲ୍ ତୁଳନାରେ।

### ପ୍ରାପ୍ତ ମୂଲ୍ୟଗୁଡିକ: `pr` ଏବଂ `release` ଗେଟ୍ ମୋଡ୍।

ଏକ ବ feature ଶିଷ୍ଟ୍ୟ PR କଦାପି ମୂଲ୍ୟ ଲେଖେ ନାହିଁ ଯାହା ଏହାର ଆଧାର ସ୍ଥିତି ଉପରେ ନିର୍ଭର କରେ: ପ୍ରଦାନକାରୀ, ସ୍ଥାନାନ୍ତରଣ, MCP- ଉପକରଣ ଏବଂ ରଣନୀତି ଗଣନା, README SVG ସଂଖ୍ୟା, ତଥ୍ୟ ସ୍ନାପସଟ୍। ଗୋଟିଏ ପଦାଙ୍କ, `npm run release:refresh-derived`, ରିଲିଜ୍ ଦ୍ୱାରା ପରିଚାଳିତ ଏବଂ ରାତ୍ରିରେ ପ୍ରାପ୍ତ-ସତେଜ PR ଦ୍ୱାରା ପୁନ rec ଗଣନା କରେ। ତେଣୁ।** ଡିଜାଇନ୍ ଦ୍ୱାରା ଲାଇଭ୍ କୋଡ୍ ପଛରେ ଆଧାର ରିଲିଜ୍ ମଧ୍ୟରେ।** , ଏବଂ ଏକ ଗେଟ୍ କିମ୍ବା ପରୀକ୍ଷଣ ଯାହା ଗଛକୁ ଲାଇଭ୍ କୋଡ୍ ସହିତ ତୁଳନା କରେ, ପ୍ରତ୍ୟେକ ଭାଇଭଉଣୀ ଏକ ପ୍ରଦାନକାରୀ ଯୋଗ କରିବା ପରେ ପ୍ରତ୍ୟେକ PR ରେ ଲାଲ ହୋଇଯିବ। ମୂଲ୍ୟଗୁଡିକ ବିଚାର କରୁଥିବା ଫାଟକ ତେଣୁ ଦୁଇଟି ମୋଡ୍ ମଧ୍ୟରୁ ଗୋଟିଏରେ ଚାଲିଥାଏ, `scripts/check/lib/gateMode.mjs` ଦ୍ୱାରା ସମାଧାନ ହୋଇଥିଲା (ପ୍ରଥମ ମ୍ୟାଚ୍ ଜିତେ):

1. `--mode=pr|release` କମାଣ୍ଡ୍ ଲାଇନ୍ ରେ;
2. `OMNIROUTE_GATE_MODE` ପରିବେଶ ଭେରିଏବଲ୍ (`pr` କିମ୍ବା `release`);
3. ସ୍ୱୟଂଚାଳିତ, GitHub କ୍ରିୟା ଇଭେଣ୍ଟରୁ: ଏକ `pull_request` ଯାହାର ମୁଣ୍ଡ `release/v*` ନୁହେଁ, ଏକ `merge_group`, କିମ୍ବା `omni-queue/**` → `pr` କୁ ଠେଲିବା; ଅନ୍ୟ ସବୁକିଛି (ପୁସ୍, କାର୍ଯ୍ୟସୂଚୀ, ପଠାଇବା, ପ୍ରକାଶନ PR `release/v* → main`, ଯେକ local ଣସି ସ୍ଥାନୀୟ ଚାଲିବା) → `release`।

#### `check-ui-value-drift` — ଷ୍ଟଲ୍-ଅନୁବାଦ ଗେଟ୍।

ଗୋଟିଏ i18n ରିଗ୍ରେସନ୍ ଧରାଯାଏ ଅନ୍ୟ ଫାଟକଗୁଡିକ ଗଠନମୂଳକ ଭାବରେ ଦେଖିପାରିବ ନାହିଁ: ଏକ ଇଂରାଜୀ ମୂଲ୍ୟ ପୁନ r ଲିଖିତ ଏବଂ _ ପୂର୍ବ_ ଇଂରାଜୀରୁ ଅନୁବାଦଗୁଡ଼ିକ ପଛରେ ରହିଥାଏ, ତେଣୁ ଅଣ-ଇଂରାଜୀ ବ୍ୟବହାରକାରୀମାନେ ଆତ୍ମବିଶ୍ୱାସୀ ଶବ୍ଦ, ବର୍ତ୍ତମାନ ଭୁଲ କପି ପ reading ଼ନ୍ତି।

ଏହା ବାସ୍ତବ ପାଇଁ ପଠାଗଲା। ଆଣ୍ଟିଗ୍ରାଭିଟି ଲଗଇନ୍ ହେଲପର ଅବତରଣ କଲାବେଳେ `oauthModal.googleOAuthWarning` ପୁନ r ଲିଖିତ ହେଲା (#5203);** 43 ଟି ଲୋକାଲ୍ ମଧ୍ୟରୁ 39।** ଅପରେଟର୍ମାନଙ୍କୁ "ସମ୍ପୂର୍ଣ୍ଣ URL କପି କରନ୍ତୁ ଏବଂ ଏହାକୁ ତଳେ ଲେପନ କରନ୍ତୁ" — ଏକ ପ୍ରବାହ ଯାହା ସେହି ପ୍ରଦାନକାରୀ ପାଇଁ ସଂପୂର୍ଣ୍ଣ ହୋଇପାରିବ ନାହିଁ ବୋଲି କହି ରଖେ। #8463 ପର୍ଯ୍ୟନ୍ତ ଏହା ଅଜ୍ଞାତ ହୋଇଗଲା କାରଣ:

**ଡିଫ୍-ସଚେତନ, ବେସ୍ ଲାଇନ୍-ସମର୍ଥିତ ନୁହେଁ।** ଏହା କାର୍ଯ୍ୟ ବୃକ୍ଷ ସହିତ ମିଶ୍ରଣ ଆଧାରରେ `en.json` ତୁଳନା କରେ; ପ୍ରତ୍ୟେକ ଚାବି ପାଇଁ ଯାହାର ଇଂରାଜୀ ମୂଲ୍ୟ ବଦଳିଛି, ଯେକ any ଣସି ଲୋକାଲ୍ ଏପର୍ଯ୍ୟନ୍ତ ଏକ ଅସ୍ପୃଶ୍ୟ ଅନୁବାଦ ଧରିଛି। ଏହା ଜାଣିଶୁଣି।** ପୂର୍ବ debt ଣକୁ ଫ୍ରିଜ୍ କରେ।** — a diff କେଉଁ ପୁରୁଣା ଇଂରାଜୀ ଦୀର୍ଘ ଦିନର ଅନୁବାଦରୁ ଆସିଛି ତାହା ପ୍ରକାଶ କରିପାରିବ ନାହିଁ, ତେଣୁ ବର୍ତ୍ତମାନର ପରିବର୍ତ୍ତନ କ’ଣ ସ୍ପର୍ଶ କରେ ତାହା ଗେଟ୍ ବିଚାର କରେ। ବିକଳ୍ପ (ପ୍ରତି କି-ହ୍ୟାସ୍ ବେସ୍ ଲାଇନ୍) ଏକ ~ 600 KB ଉତ୍ପାଦିତ ଫାଇଲ୍, 3 × ସର୍ବ ବୃହତ ବିଦ୍ୟମାନ ବେସ୍ ଲାଇନ୍, ପ୍ରତ୍ୟେକ i18n PR ଉପରେ ଘୁଞ୍ଚିବ।

3. **ଯଦି ଉଲ୍ଲଂଘନଟି ପୂର୍ବରୁ ଥିଲା** (ଅର୍ଥାତ୍, ଆପଣ ଏହାକୁ ଯୋଡ଼ିନଥିଲେ କିନ୍ତୁ ଗେଟ୍ ବର୍ତ୍ତମାନ ଏହାକୁ ଆବୃତ କରୁଛି): ଯୁକ୍ତିସହ ଏକ ମନ୍ତବ୍ୟ ଏବଂ ଟ୍ରାକିଂ ଇସ୍ୟୁ ସହିତ ଏକ ଅନୁମୋଦିତ ତାଲିକା ଏଣ୍ଟ୍ରି ଯୋଡ଼ନ୍ତୁ।
4. **ଯଦି ଗେଟ୍ଟି ଏକ ରାଚେଟ୍** (କଭରେଜ୍, ESLint ସତର୍କତା, ଡୁପ୍ଲିକେସନ୍, ଜଟିଳତା): ଆପଣଙ୍କ ପରିବର୍ତ୍ତନ ମେଟ୍ରିକ୍କୁ ଅଧିକ ଖରାପ କରିଛି। ମୂଳ ସମସ୍ୟା ସମାଧାନ କରନ୍ତୁ, କିମ୍ବା (ବିରଳ କ୍ଷେତ୍ରରେ) ପରିବର୍ତ୍ତନଟି ଉଦ୍ଦେଶ୍ୟମୂଳକ ଏବଂ ମେଟ୍ରିକ୍ର ଅବନତି ଗ୍ରହଣଯୋଗ୍ୟ ହେଲେ `npm run quality:ratchet -- --update` ଚଲାନ୍ତୁ — କିନ୍ତୁ PR ବର୍ଣ୍ଣନାରେ ଏହାର କାରଣ ଲେଖନ୍ତୁ।
5. **ପରାମର୍ଶମୂଳକ ଗେଟ୍ଗୁଡ଼ିକ** (`continue-on-error: true`) ସୂଚନାମୂଳକ — ସେଗୁଡ଼ିକ ମର୍ଜ୍କୁ ଅଟକାଇନଥାଏ କିନ୍ତୁ CI ସାରାଂଶରେ ଦେଖାଯାଏ। ତଥାପି ସେଗୁଡ଼ିକୁ ସମାଧାନ କରନ୍ତୁ।

### ମର୍ଜ / ଡିଡ୍ୟୁପ୍ (ଯାନ୍ତ୍ରିକ, କମ୍ ଝୁମ୍ପ)

ପ୍ରତ୍ୟେକ ପ୍ରାର୍ଥୀକୁ 2026-06-17 ରେ ଲାଇଭ୍ ଗେଟ୍ ଅବସ୍ଥା ବିରୋଧରେ ଯାଞ୍ଚ କରାଯାଇଥିଲା (ଭରସା କରନ୍ତୁ, କିନ୍ତୁ ଯାଞ୍ଚ କରନ୍ତୁ);
କିଛି "ସ୍ପଷ୍ଟ" ମର୍ଜ ମଧ୍ୟରେ ଲୁକାଇଥିବା ଋଣ ମିଳିଲା ଏବଂ ସେଗୁଡ଼ିକ **ସଫା ଡ୍ରପ୍-ଇନ୍ ନୁହେଁ**।

- **`check:docs-sync` ଦୁଇଥର ଚାଲେ** — `lint` ଜବ୍ରେ ସ୍ୱତନ୍ତ୍ର ଭାବେ ଏବଂ ପୁଣି `check:docs-all` (`docs-sync-strict`) ଭିତରେ ଓ husky ପ୍ରି-କମିଟ୍ ହୁକ୍ରେ। ✅ **ସମ୍ପନ୍ନ** — ସ୍ୱତନ୍ତ୍ର `lint` ଇନଭୋକେସନ୍ ହଟାଯାଇଛି।
- **CVE ସ୍କାନିଂ** — ❌ **ସଫା ମର୍ଜ ନୁହେଁ।** `audit:deps` ସମସ୍ତ ପାଞ୍ଚଟି ଲକଫାଇଲ୍ରେ ଗୁରୁତର ଆଡଭାଇଜରୀ ଏବଂ ଅସମ୍ପୂର୍ଣ୍ଣ ଅଡିଟ୍କୁ ବ୍ଲକ୍ କରେ, ଯେତେବେଳେ ବର୍ତ୍ତମାନର ନୀତି ଅନୁସାରେ ଉଚ୍ଚ-ସ୍ତରୀୟ ଆଡଭାଇଜରୀଗୁଡ଼ିକୁ ସତର୍କତା ଭାବେ ରିପୋର୍ଟ କରେ; `check:vuln-ratchet` (osv) କେବଳ ଚେକ୍-ଇନ୍ ହୋଇଥିବା ବେସଲାଇନ୍ ବିରୋଧରେ _ରିଗ୍ରେସନ୍_ ହେଲେ ବିଫଳ ହୁଏ ଏବଂ ଆବଶ୍ୟକ ସମୟରେ ମାପ ଅନୁପସ୍ଥିତିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। ଅର୍ଥ ଭିନ୍ନ — `audit:deps` ହଟାଇଲେ ନିରପେକ୍ଷ ଗୁରୁତର ଗେଟ୍ ଏବଂ ସ୍ୱତନ୍ତ୍ର ପ୍ୟାକେଜ୍ ଅଡିଟ୍ ରସିଦଗୁଡ଼ିକ ହରାଇଯିବ। ଉଭୟକୁ ରଖନ୍ତୁ।
