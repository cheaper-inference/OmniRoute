ଏହି ଡକ୍ୟୁମେଣ୍ଟଟି OmniRoute ର ସମସ୍ତ CI ଗୁଣବତ୍ତା ଗେଟ୍ ପାଇଁ ପ୍ରାମାଣିକ ସନ୍ଦର୍ଭ।
ଏହା ପ୍ରତ୍ୟେକ ଗେଟ୍, ଏହା କ’ଣ ଯାଞ୍ଚ କରେ, କେଉଁ CI ଜବ୍ରେ ଏହା ଚାଲେ, ଏହା
ଏକ ରାଚେଟ୍ ବେସ୍ଲାଇନ୍ କିମ୍ବା ଏକ ପାସ୍/ଫେଲ୍ ନୀତି ବ୍ୟବହାର କରେ କି ନାହିଁ, ଏବଂ ଏହା ବିଲ୍ଡ୍କୁ ଅବରୋଧ କରେ କିମ୍ବା କେବଳ ପରାମର୍ଶମୂଳକ—ତାହା ବର୍ଣ୍ଣନା କରେ।

"ଗୁଣବତ୍ତା ଗେଟ୍ ଏବଂ ରାଚେଟ୍" ବିଭାଗ ଦେଖନ୍ତୁ। ସେହି ସିଷ୍ଟମ୍ର ସମାଲୋଚନାମୂଳକ ମୂଲ୍ୟାଙ୍କନ,
ପରିପକ୍ୱତା ବର୍ଗୀକରଣ ଏବଂ ଟୁଲ୍-ନିରପେକ୍ଷ ପ୍ରତିରୂପଣ ଯୋଜନା ପାଇଁ,
[ଗୁଣବତ୍ତା ଗେଟ୍ ପ୍ଲେବୁକ୍](../ops/QUALITY_GATE_PLAYBOOK.md) ଦେଖନ୍ତୁ।

## ଗେଟ୍ ଇନଭେଣ୍ଟରି ଏବଂ ଏକ୍ସିକ୍ୟୁସନ୍ ପ୍ରୋଫାଇଲ୍

### ପ୍ରାର୍ଥୀ ଗ୍ରହଣ

CI ଏବଂ Quality Gates କାର୍ଯ୍ୟପ୍ରବାହଗୁଡ଼ିକ ପ୍ରତ୍ୟେକ ଏକ ସ୍ଥିର ନିର୍ଣ୍ଣୟ ପ୍ରକାଶ କରନ୍ତି: `Gate / CI` ଏବଂ
`Gate / Quality`। ସେମାନଙ୍କର ସଂସ୍କରଣଯୁକ୍ତ ଗ୍ରହଣ ନୀତି ପ୍ରତ୍ୟେକ ଅପଷ୍ଟ୍ରିମ୍ କାର୍ଯ୍ୟକୁ
ଆବଶ୍ୟକ କିମ୍ବା ପରାମର୍ଶଦାତା ଭାବରେ ଗଣନା କରେ। ଏକ ପ୍ରଯୁଜ୍ୟ ଆବଶ୍ୟକ କାର୍ଯ୍ୟ ସଫଳ ହେବା ଆବଶ୍ୟକ: ହଜିଯାଇଥିବା,
ବାତିଲ୍ ହୋଇଥିବା, ଏଡ଼ାଇଯାଇଥିବା, ବିଚାରାଧୀନ ଏବଂ ଅଜଣାତ ଫଳାଫଳ PASS ସ୍ଥାପନ କରିପାରିବେ ନାହିଁ। ଏକ ବୈଧ
docs-only କିମ୍ବା catalog-only ଶ୍ରେଣୀବିଭାଗ ଏକ କୋଡ୍ ଲେନ୍କୁ ଅପ୍ରଯୁଜ୍ୟ କରିପାରେ;
ଏକ ଡ୍ରାଫ୍ଟ PR ଗ୍ରହଣଯୋଗ୍ୟ ପ୍ରାର୍ଥୀ ନୁହେଁ। `hotfix` ଲେବଲ୍ ପ୍ରମାଣକୁ ଛଡ଼ାଇ ଦିଏ ନାହିଁ।

ଉଭୟ କାର୍ଯ୍ୟପ୍ରବାହ main/release ଶାଖାଗୁଡ଼ିକୁ ଯାଉଥିବା PR ଗୁଡ଼ିକ, `main` କୁ ପୁସ୍, ମାନୁଆଲ୍ ଡିସ୍ପାଚ୍
ଏବଂ ମର୍ଜ୍-ଗ୍ରୁପ୍ ଘଟଣାଗୁଡ଼ିକୁ କଭର୍ କରନ୍ତି। ପୁସ୍, ଡିସ୍ପାଚ୍ ଏବଂ ମର୍ଜ୍-ଗ୍ରୁପ୍ ସମ୍ପୂର୍ଣ୍ଣ ଚୟନ ଚଲାନ୍ତି।
`release/**` କୁ ପୁସ୍ ସେଗୁଡ଼ିକୁ ଆରମ୍ଭ କରେ ନାହିଁ (2026-10-18): ପ୍ରତ୍ୟେକ ପରିବର୍ତ୍ତନ ନିଜର PR ରେ ମ୍ୟାଟ୍ରିକ୍ସ ଚଲାଇ ସାରିଛି
ଏବଂ ମିଶ୍ରିତ ସଂଯୋଜନା Release-Green ର କାର୍ଯ୍ୟ ଅଟେ (`docs/ops/RUNNER_BOX.md` → ହୋଷ୍ଟେଡ୍ ଲେନ୍)। ଫର୍କ୍
ଏବଂ ମର୍ଜ୍ ଗ୍ରୁପଗୁଡ଼ିକ ସେହି କାର୍ଯ୍ୟଗୁଡ଼ିକ ପାଇଁ ହୋଷ୍ଟେଡ୍ ରନର୍ ବ୍ୟବହାର କରନ୍ତି ଯାହା ଅନ୍ୟଥା ସେଲ୍ଫ-ହୋଷ୍ଟେଡ୍
ରନର୍ ଚୟନ କରନ୍ତି; ରୋଲଆଉଟ୍ ପୂର୍ବରୁ ଯଥେଷ୍ଟ ହୋଷ୍ଟେଡ୍ କ୍ଷମତା ଯାଞ୍ଚ କରାଯିବା ଆବଶ୍ୟକ।

ପ୍ରତ୍ୟେକ JSON ରସିଦ ଚେକ-ଆଉଟ୍ ହୋଇଥିବା SHA, କାର୍ଯ୍ୟପ୍ରବାହ ରନ୍ ଏବଂ ପ୍ରୟାସକୁ ଚିହ୍ନଟ କରେ।
CLI ଚେକଆଉଟ୍/ଇଭେଣ୍ଟ SHA ମେଳ ନହେଲେ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। କାର୍ଯ୍ୟପ୍ରବାହ ପରୀକ୍ଷାଗୁଡ଼ିକ ନୀତି ସଦସ୍ୟତାକୁ
ନିର୍ଣ୍ଣୟ କାର୍ଯ୍ୟର `needs` ତାଲିକା ସହ ବାନ୍ଧନ୍ତି ଯାହା ଫଳରେ ଏକ ନୂତନ କିମ୍ବା ଅପସାରିତ ଲେନ୍ ନୀରବରେ ଅଦୃଶ୍ୟ ହୋଇପାରିବ ନାହିଁ।
ରସିଦଗୁଡ଼ିକ ନିଜର କାର୍ଯ୍ୟପ୍ରବାହକୁ କଭର୍ କରନ୍ତି, ପ୍ରକାଶନ, ଡିପ୍ଲୟମେଣ୍ଟ କିମ୍ବା ବିଦ୍ୟମାନ
ପରାମର୍ଶଦାତା ସ୍କାନରର ଆଭ୍ୟନ୍ତରୀଣ ବିଷୟକୁ ନୁହେଁ। ଶାଖା ନିୟମରେ ଉଭୟ ଚେକ୍ ନାମ ସକ୍ରିୟ କରିବା ଏକ
ପୃଥକ ପ୍ରଶାସନିକ ପରିବର୍ତ୍ତନ; ଏହି କାର୍ଯ୍ୟଗୁଡ଼ିକୁ ଯୋଡ଼ିବା ନିଜେ ଏକ ଶାଖାକୁ ସୁରକ୍ଷା ଦିଏ ନାହିଁ।

### ଷ୍ଟାଟିକ୍ ସ୍କାନ୍ ଇନଭେଣ୍ଟରି

ସଂସ୍କରଣଯୁକ୍ତ npm-ଏଲିଆସ୍ ଇନଭେଣ୍ଟରି ଏବଂ ଷ୍ଟାଟିକ୍-ସ୍କାନ୍ ସଦସ୍ୟତା
`config/quality/gate-manifest.json` ରେ ରହେ। `package.json` ବିପରୀତରେ
ସ୍କ୍ରିପ୍ଟ ନାମ ଏବଂ ସଠିକ୍ କମାଣ୍ଡଗୁଡ଼ିକୁ ବୈଧ କରିବା ପାଇଁ `npm run check:gate-manifest` ଚଲାନ୍ତୁ; ଯୋଗ, ଅପସାରଣ ଏବଂ
କମାଣ୍ଡ ଡ୍ରିଫ୍ଟ ସ୍ଥାନୀୟ ହୁକ୍ ଏବଂ CI ର ପରିବର୍ତ୍ତନ-ଶ୍ରେଣୀବିଭାଗ କାର୍ଯ୍ୟ ଉଭୟକୁ ବିଫଳ କରେ।
ଏକ ଏଲିଆସ୍ କାର୍ଯ୍ୟପ୍ରବାହ କାର୍ଯ୍ୟ, ମ୍ୟାଟ୍ରିକ୍ସ ଇନଷ୍ଟାନ୍ସ କିମ୍ବା ଟେଷ୍ଟ କେସ୍ ନୁହେଁ: ଏହି ଗଣନାଗୁଡ଼ିକୁ
ପରସ୍ପର ବଦଳାଯାଇପାରିବା ଭାବରେ ଉପସ୍ଥାପନ କରାଯିବା ଉଚିତ୍ ନୁହେଁ।

ଚୟନିତ ଏଲିଆସଗୁଡ଼ିକୁ ଚଲାଇବା ବିନା ଯାଞ୍ଚ କରିବା ପାଇଁ `npm run quality:scan -- --list` କିମ୍ବା `npm run quality:scan:fast -- --list`
ବ୍ୟବହାର କରନ୍ତୁ। ରନର୍ npm ଏଣ୍ଟ୍ରିପଏଣ୍ଟ ଆହ୍ୱାନ କରେ, ତେଣୁ ଏହାର ରନଟାଇମ୍ (ଯେଉଁଠାରେ କନଫିଗର କରାଯାଇଛି Bun ସହିତ) ସଂରକ୍ଷିତ ରହେ।
ମ୍ୟାନିଫେଷ୍ଟ ସେହି ପ୍ରୋଫାଇଲଗୁଡ଼ିକ ବାହାରେ ଥିବା ଏଲିଆସଗୁଡ଼ିକୁ ପୃଥକ ଭାବରେ ଆହ୍ୱାନ ହୋଇଥିବା ଭାବରେ ରେକର୍ଡ କରେ, ଏବଂ
ରୀଡ୍-ଓନଲି ସ୍କାନ୍ ପ୍ରୋଫାଇଲରେ ରକ୍ଷଣାବେକ୍ଷଣ କମାଣ୍ଡଗୁଡ଼ିକ ନିଷିଦ୍ଧ।

ଏହି ପ୍ରୋଫାଇଲଗୁଡ଼ିକ କେବଳ ଷ୍ଟାଟିକ୍ ସ୍କାନକୁ କଭର୍ କରନ୍ତି। ସେଗୁଡ଼ିକ ପ୍ରୋଡକ୍ଟ ପରୀକ୍ଷା,
କଭରେଜ୍, ପ୍ୟାକେଜିଂ, ବାହ୍ୟ ଯାଞ୍ଚ କିମ୍ବା ପ୍ରାର୍ଥୀର ସମ୍ପୂର୍ଣ୍ଣ ରିଲିଜ୍ ଗ୍ରହଣକୁ ପ୍ରମାଣିତ କରନ୍ତି ନାହିଁ।
କାର୍ଯ୍ୟପ୍ରବାହ ଗ୍ରହଣ ଲିଙ୍କ୍ ହୋଇଥିବା `config/quality/admission-policy.json` ଏବଂ

#### ଭୁଲିଯାଇଥିବା ସିବ୍ଲିଂ ପରୀକ୍ଷା ରିପୋର୍ଟ

`npm run check:forgotten-sibling-tests` ଟେଷ୍ଟ-ଇମ୍ପାକ୍ଟ ମ୍ୟାପ୍ ପଛରେ ଥିବା ଇମ୍ପୋର୍ଟ ରିଜଲଭରକୁ ପୁନଃବ୍ୟବହାର କରେ।
ପ୍ରତ୍ୟେକ ପରିବର୍ତ୍ତିତ ପ୍ରଡକ୍ସନ୍ ମଡ୍ୟୁଲ୍ ପାଇଁ, ଯେତେବେଳେ କ୍ୟାଣ୍ଡିଡେଟ୍ ଟେଷ୍ଟ ପୁଲ୍-ରିକ୍ୱେଷ୍ଟ ଡିଫ୍ରେ ନ ଥାଏ, ଏହା ନିର୍ଣ୍ଣୟାତ୍ମକ
`changed module/symbol -> static consumer -> candidate sibling test` ଚେନ୍ ରିପୋର୍ଟ କରେ। Markdown ସାରାଂଶ ଏବଂ JSON ଫଳାଫଳ, କୌଣସି ବ୍ଲକିଂ ରୋଲ୍ଆଉଟ୍ ପୂର୍ବରୁ କ୍ୟାଲିବ୍ରେସନ୍ ପାଇଁ
`forgotten-sibling-tests` ୱାର୍କଫ୍ଲୋ ଆର୍ଟିଫାକ୍ଟ ଭାବରେ ସଂରକ୍ଷିତ ରହେ।

Barrel ରି-ଏକ୍ସପୋର୍ଟ ଏବଂ ଡାଏନାମିକ୍ ଇମ୍ପୋର୍ଟଗୁଡ଼ିକ କେବଳ ରିଜଲ୍ୟୁସନ୍ ଡାୟାଗ୍ନୋଷ୍ଟିକ୍ସ; ସେଗୁଡ଼ିକ କେବେ ବି ବ୍ଲକିଂ ଫାଇଣ୍ଡିଂ ସୃଷ୍ଟି କରନ୍ତି ନାହିଁ। ସମୀକ୍ଷିତ ଅପବାଦଗୁଡ଼ିକ
`config/quality/forgotten-sibling-allowlist.json` ରେ ରହେ। ପ୍ରତ୍ୟେକ ଏଣ୍ଟ୍ରି କଞ୍ଜ୍ୟୁମର୍ ଏବଂ କ୍ୟାଣ୍ଡିଡେଟ୍
ଟେଷ୍ଟର ନାମ ଦେବା ଆବଶ୍ୟକ, ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ କାରଣ ଦର୍ଶାଇବା ଆବଶ୍ୟକ, ଏବଂ ଗୋଟିଏ GitHub ଇସ୍ୟୁ କିମ୍ବା ପୁଲ୍ ରିକ୍ୱେଷ୍ଟ ଲିଙ୍କ୍ କରିବା ଆବଶ୍ୟକ। ତ୍ରୁଟିପୂର୍ଣ୍ଣ ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ଫେଲ୍ କ୍ଲୋଜ୍ଡ୍ ହୁଅନ୍ତି। ଅପବାଦଗୁଡ଼ିକ ଡିଲିଟ୍ ହୋଇଥିବା କ୍ୟାଣ୍ଡିଡେଟ୍ ଟେଷ୍ଟ କିମ୍ବା `.skip`/`.todo` ଯୋଡ଼ୁଥିବା ଡିଫ୍କୁ ଦବାଇ ପାରିବ ନାହିଁ;
ଆସର୍ସନ୍ ଦୁର୍ବଳତା ଏବଂ ଅନ୍ୟାନ୍ୟ ମାସ୍କିଂ ସ୍ୱାଧୀନ ଭାବରେ ବ୍ଲକିଂ କରୁଥିବା
`check:test-masking` ଗେଟ୍ ଅଧୀନରେ ରହେ।

#### `check-ui-value-drift` — ପୁରୁଣା-ଅନୁବାଦ ଗେଟ୍

ଏହା ସେହି ଏକମାତ୍ର i18n ରିଗ୍ରେସନ୍କୁ ଧରେ ଯାହାକୁ ଅନ୍ୟ ଗେଟ୍ଗୁଡ଼ିକ ଗଠନାତ୍ମକ ଭାବରେ ଦେଖିପାରିବେ ନାହିଁ: ଗୋଟିଏ
ଇଂରାଜୀ ମୂଲ୍ୟ ପୁନଃଲେଖା ହୁଏ ଏବଂ _ପୂର୍ବବର୍ତ୍ତୀ_ ଇଂରାଜୀରୁ ଉଦ୍ଭୂତ ଅନୁବାଦଗୁଡ଼ିକ ପଛରେ ରହିଯାଆନ୍ତି, ତେଣୁ
ଅଣ-ଇଂରାଜୀ ବ୍ୟବହାରକାରୀମାନେ ଆତ୍ମବିଶ୍ୱାସପୂର୍ଣ୍ଣ ଶବ୍ଦରେ ଲେଖାଯାଇଥିବା, ବର୍ତ୍ତମାନ-ଭୁଲ୍ କପି ପଢ଼ିବାକୁ ଜାରି ରଖନ୍ତି।

ଏହା ପ୍ରକୃତରେ ରିଲିଜ୍ ହୋଇଥିଲା। `oauthModal.googleOAuthWarning` କୁ ପୁନଃଲେଖା କରାଯାଇଥିଲା ଯେତେବେଳେ
Antigravity ଲଗଇନ୍ ହେଲ୍ପର୍ ଆସିଥିଲା (#5203); **43 ଟି ଲୋକେଲ୍ ମଧ୍ୟରୁ 39 ଟି** ଅପରେଟରମାନଙ୍କୁ "ସମ୍ପୂର୍ଣ୍ଣ URL
କପି କରନ୍ତୁ ଏବଂ ତଳେ ପେଷ୍ଟ୍ କରନ୍ତୁ" ବୋଲି କହୁଥିବା ଟେକ୍ସ୍ଟ ରଖିଥିଲେ — ଏକ ପ୍ରବାହ ଯାହା ସେହି ପ୍ରୋଭାଇଡର୍ ପାଇଁ
ସମ୍ପୂର୍ଣ୍ଣ ହୋଇପାରିବ ନାହିଁ। #8463 ପର୍ଯ୍ୟନ୍ତ ଏହା ଅଦେଖା ରହିଥିଲା କାରଣ:

- `sync-ui-keys` କେବଳ **ଅନୁପସ୍ଥିତ** ଥିବା କି'ଗୁଡ଼ିକୁ ବ୍ୟାକଫିଲ୍ କରେ, **ପୁରାତନ (stale)** ଥିବା କି'ଗୁଡ଼ିକୁ କେବେ ନୁହେଁ;
- `check-ui-keys-coverage` କି'ର _ଉପସ୍ଥିତି_ ଗଣେ, ତେଣୁ ଗୋଟିଏ ପୁରାତନ ଅନୁବାଦ କଭର୍ ହୋଇଥିବା ଭାବରେ ସ୍କୋର କରେ;
- `check-translation-drift` `docs/i18n/<locale>/**.md` ଡକ୍ୟୁମେଣ୍ଟେସନ୍ ମିରର୍ଗୁଡ଼ିକୁ ଟ୍ରାକ୍ କରେ —
  ଏହା କେବେ `src/i18n/messages/*.json` ପଢ଼େ ନାହିଁ। 2026-09 ପୁନଃ-ସିଙ୍କ ପରଠାରୁ `docs-sync-strict` ଜବ୍ରେ
  ବ୍ଲକିଂ: ଗୋଟିଏ କୋର୍ ଡକ୍ ସମ୍ପାଦନ କରନ୍ତୁ → `npm run i18n:run -- --files=<doc>` (ସେକ୍ସନ୍-ସ୍ତରୀୟ, ସସ୍ତା)।

**Diff-ସଚେତନ, baseline-ଆଧାରିତ ନୁହେଁ।** ଏହା ମର୍ଜ୍ ବେସ୍ରେ ଥିବା `en.json` କୁ ୱାର୍କିଂ ଟ୍ରୀ ସହିତ ତୁଳନା କରେ;
ଯେଉଁ ପ୍ରତ୍ୟେକ କି'ର ଇଂରାଜୀ ମୂଲ୍ୟ ପରିବର୍ତ୍ତନ ହୋଇଛି, ଗୋଟିଏ ଅସ୍ପର୍ଶୀତ ଅନୁବାଦ ଧାରଣ କରିଥିବା ଯେକୌଣସି ଲୋକେଲ୍
ପୁରାତନ। ଏହା ଇଚ୍ଛାକୃତ ଭାବରେ **ପୂର୍ବ-ବିଦ୍ୟମାନ ଋଣକୁ ସ୍ଥିର କରେ** — ଗୋଟିଏ diff ଦର୍ଶାଇପାରିବ ନାହିଁ ଯେ ଗୋଟିଏ
ଦୀର୍ଘକାଳୀନ ଅନୁବାଦ କେଉଁ ପୁରୁଣା ଇଂରାଜୀରୁ ଆସିଥିଲା, ତେଣୁ ଗେଟ୍ କେବଳ ବର୍ତ୍ତମାନର ପରିବର୍ତ୍ତନ ଯାହାକୁ ସ୍ପର୍ଶ କରେ
ତାହାକୁ ବିଚାର କରେ। ବିକଳ୍ପ (ପ୍ରତି-କି' ହ୍ୟାସ୍ baseline) ଏକ ~600 KB ଜେନେରେଟ୍ ହୋଇଥିବା ଫାଇଲ୍ ଖର୍ଚ୍ଚ କରିବ,
ସବୁଠାରୁ ବଡ଼ ବିଦ୍ୟମାନ baseline ର 3×, ଯାହା ପ୍ରତ୍ୟେକ i18n PR ରେ ପରିବର୍ତ୍ତିତ ହେବ।

ଏହାକୁ ସନ୍ତୁଷ୍ଟ କରିବାର ଦୁଇଟି ଉପାୟ:

1. ପ୍ରଭାବିତ ଅନୁବାଦଗୁଡ଼ିକୁ ଅପଡେଟ୍ କରନ୍ତୁ, କିମ୍ବା
2. ସେଗୁଡ଼ିକୁ `__MISSING__:<new english>` ରେ ସେଟ୍ କରନ୍ତୁ — ରନ୍ଟାଇମ୍ ତାପରେ ସଂଶୋଧିତ ଇଂରାଜୀ ପରିବେଷଣ କରେ
   (`src/i18n/request.ts::deepMergeFallback`, #7258) ଏବଂ କି' ଅନୁବାଦ ପାଇଁ କ୍ୟୁରେ ରହେ।

ଯଦି ଷ୍ଟ୍ରିଂର **ଅର୍ଥ** ପରିବର୍ତ୍ତନ ହୋଇଛି, **କି'ର ନାମ ପରିବର୍ତ୍ତନ କରିବାକୁ** ପ୍ରାଥମିକତା ଦିଅନ୍ତୁ: ଗୋଟିଏ ନୂତନ
କି' ପୁରାତନ ଅନୁବାଦ ଉତ୍ତରାଧିକାରରେ ପାଇପାରିବ ନାହିଁ। #8463 ସେହି ପ୍ୟାଟର୍ଣ୍ଣ ବ୍ୟବହାର କରିଥିଲା।


### CodeQL ରାଚେଟ୍: ରିଫ୍ରେଶ୍ ଅନ୍ତରାଳ ଏବଂ ମାନୁଆଲ୍ ଟ୍ରିଗର୍

`check:codeql-ratchet` **ରିପୋ ଅବସ୍ଥା ପଢ଼େ, ଯାହା ଏକ ସୂଚୀ ଅନୁସାରେ ରିଫ୍ରେଶ୍ ହୁଏ — ପ୍ରତ୍ୟେକ PR ପାଇଁ ନୁହେଁ।**
`gh api repos/diegosouzapw/OmniRoute/code-scanning/default-setup` ରିପୋର୍ଟ କରେ
`state: configured`, `schedule: weekly`: ଏହା GitHubର ଡିଫଲ୍ଟ-ସେଟଅପ୍ ସ୍କାନ୍, ପ୍ରତ୍ୟେକ ପୁସ୍ ପାଇଁ
ବିଶ୍ଳେଷଣ ନୁହେଁ। ପରିଣାମ: ଆଲର୍ଟଗୁଡ଼ିକୁ ଠିକ୍ କରୁଥିବା ଏକ PR ମର୍ଜ ହେବା ପରେ, ପରବର୍ତ୍ତୀ ନିର୍ଦ୍ଧାରିତ
ସ୍କାନ୍ ଚାଲିବା ପର୍ଯ୍ୟନ୍ତ ରାଚେଟ୍ ପୁରୁଣା, ଅଧିକ ସଂଖ୍ୟା ପଢ଼ିବା ଜାରି ରଖେ — ତେଣୁ ସ୍କାନ୍ ଅଦ୍ୟତନ ହେବା
ପର୍ଯ୍ୟନ୍ତ ଏହା ପ୍ରତ୍ୟେକ ଖୋଲା PRରେ, ଠିକ୍ କରୁଥିବା PRର ନିଜସ୍ୱ ଫଲୋ-ଅପ୍ଗୁଡ଼ିକ ସମେତ, ଅବନତି ରିପୋର୍ଟ କରେ।

**ମାନୁଆଲ୍ ରିଫ୍ରେଶ୍**: `gh workflow run codeql.yml --ref release/vX.Y.Z` ବିଶ୍ଳେଷଣକୁ
ପୁନଃ ଚଳାଏ ଏବଂ କିଛି ମିନିଟ୍ ମଧ୍ୟରେ ଆଲର୍ଟଗୁଡ଼ିକୁ ପୁନଃ ପ୍ରକାଶ କରେ। ପ୍ରଥମେ `.github/workflows/codeql.yml`

GitHubର "default setup" ସହିତ ଦ୍ୱନ୍ଦ୍ୱ କରେ** (`CodeQL analyses from advanced configurations cannot be
processed when the default setup is enabled`)। `push`/`pull_request`/
`schedule` ଟ୍ରିଗର୍ଗୁଡ଼ିକୁ ପୁନଃସ୍ଥାପନ କରିବା ପାଇଁ ପ୍ରଥମେ ଏକ **ମାଲିକଙ୍କ କାର୍ଯ୍ୟ** ଆବଶ୍ୟକ: Settings → Code security →
CodeQL: Default → Advanced। ସେହି ସ୍ୱିଚ୍ ବିନା `schedule:` ଟ୍ରିଗର୍ ଯୋଡ଼ନ୍ତୁ ନାହିଁ — ଏହା
କେବଳ ବିଫଳ ରନ୍ଗୁଡ଼ିକ ସୃଷ୍ଟି କରିବ।

   ଅବନତି ଗ୍ରହଣଯୋଗ୍ୟ ହେଲେ `npm run quality:ratchet -- --update` ଚଲାନ୍ତୁ — କିନ୍ତୁ PR ବିବରଣୀରେ ଏହାର କାରଣ ଲିପିବଦ୍ଧ କରନ୍ତୁ।
5. **ପରାମର୍ଶମୂଳକ ଗେଟ୍ଗୁଡ଼ିକ** (`continue-on-error: true`) କେବଳ ସୂଚନାମୂଳକ — ସେଗୁଡ଼ିକ ମର୍ଜ୍କୁ ଅବରୋଧ
   କରେନାହିଁ, କିନ୍ତୁ CI ସାରାଂଶରେ ଦେଖାଯାଏ। ତଥାପି ସେଗୁଡ଼ିକୁ ସମାଧାନ କରନ୍ତୁ।

### ମର୍ଜ / ଡିଡ୍ୟୁପ୍ (ଯାନ୍ତ୍ରିକ, କମ୍ ବିପଦ)

ପ୍ରତ୍ୟେକ ପ୍ରାର୍ଥୀକୁ 2026-06-17 ରେ ସକ୍ରିୟ ଗେଟ୍ ସ୍ଥିତି ସହିତ ଯାଞ୍ଚ କରାଯାଇଥିଲା (ବିଶ୍ୱାସ କରନ୍ତୁ, କିନ୍ତୁ ଯାଞ୍ଚ ମଧ୍ୟ କରନ୍ତୁ);
ଅନେକ "ସ୍ପଷ୍ଟ" ମର୍ଜ ଋଣ ଲୁଚାଇ ରଖିଥିବା ଜଣାପଡ଼ିଲା ଏବଂ ସେଗୁଡ଼ିକ **ସିଧାସଳଖ ପ୍ରତିସ୍ଥାପନଯୋଗ୍ୟ ନୁହେଁ**।

- **`check:docs-sync` ଦୁଇଥର ଚାଲେ** — `lint` ଜବ୍ରେ ସ୍ୱତନ୍ତ୍ର ଭାବେ ଏବଂ ପୁଣି `check:docs-all` (`docs-sync-strict`) ଭିତରେ ଓ husky pre-commit hook ରେ। ✅ **ସମ୍ପୂର୍ଣ୍ଣ** — ସ୍ୱତନ୍ତ୍ର `lint` ଆହ୍ୱାନ ହଟାଯାଇଛି।
- **CVE ସ୍କାନିଂ** — ❌ **ଏକ ସ୍ୱଚ୍ଛ ମର୍ଜ ନୁହେଁ।** ଯେକୌଣସି high/critical CVE ଥିଲେ `audit:deps` ନିଶ୍ଚିତ ଭାବେ ବିଫଳ ହୁଏ; `check:vuln-ratchet` (osv) କେବଳ ବେସ୍ଲାଇନ୍ ତୁଳନାରେ ଏକ _ଅବନତି_ ହେଲେ ବିଫଳ ହୁଏ (ବର୍ତ୍ତମାନ 1 MODERATE)। ଅର୍ଥବିଜ୍ଞାନ ଭିନ୍ନ — `audit:deps` ବାଦ ଦେଲେ ସମ୍ପୂର୍ଣ୍ଣ high/critical ଗେଟ୍ ହରାଇଯିବ। ଉଭୟକୁ ରଖନ୍ତୁ।
- **ଚକ୍ର ଚିହ୍ନଟ** — ✅ **ସମ୍ପୂର୍ଣ୍ଣ** (#15159 G-01/G-02)। ଏଠାରେ ଥିବା ପୁରୁଣା ପାଠ୍ୟ `check:cycles` କୁ "ସବୁଜ, ସୁବ୍ୟବସ୍ଥିତ" ଗେଟ୍ ବୋଲି କହିଥିଲା ଏବଂ `check:circular-deps` (dpdm) 91ଟି ଚକ୍ର ରିପୋର୍ଟ କରିଥିବାରୁ ଏହାକୁ ବ୍ଲକିଂ ଭାବେ ରଖିବା ଯୁକ୍ତିସଙ୍ଗତ ବୋଲି ଦର୍ଶାଇଥିଲା। ସେହି ସବୁଜ ସ୍ଥିତି ଏକ **ଭୁଲ ସବୁଜ** ଥିଲା: `check:cycles` 5ଟି ସବ୍ଡିରେକ୍ଟୋରୀ (450ଟି ଫାଇଲ୍) ସ୍କାନ୍ କରୁଥିଲା, କେବଳ ସ୍ଥିର `import|export … from` ସହିତ ମେଳ କରୁଥିଲା, ଏବଂ ପ୍ରତ୍ୟେକ `@/` ଓ `@omniroute/open-sse/` ସ୍ପେସିଫାୟର୍କୁ ବାଦ ଦେଉଥିଲା, ତେଣୁ ରିପୋଜିଟୋରୀରେ ପ୍ରାଧାନ୍ୟ ରଖିଥିବା ଡାଇନାମିକ୍-import + alias ଚକ୍ରଗୁଡ଼ିକୁ ଏହା ଦେଖିପାରୁ ନଥିଲା। ସମାଧାନ କରାଯାଇଛି: ଗେଟ୍ଟି ବର୍ତ୍ତମାନ `src` + `open-sse` (5023ଟି ଫାଇଲ୍) ପରିକ୍ରମା କରେ, TypeScript AST ରୁ ସ୍ପେସିଫାୟର୍ଗୁଡ଼ିକ ସଂଗ୍ରହ କରେ (ଫଳରେ `import("…")` ଗଣାଯାଏ ଏବଂ type-position `typeof import("…")` ଗଣାଯାଏ ନାହିଁ), ଏବଂ tsconfig `paths` ସମାଧାନ କରେ। ଏହା 0 ନୁହେଁ, **14**ଟି ଚକ୍ର ଚିହ୍ନଟ କରେ। ଏକ ଗେଟ୍ PR ରେ ପୂର୍ବରୁ ଥିବା 14ଟି ଚକ୍ର ସମାଧାନ କରାଯାଇପାରିବ ନାହିଁ ବୋଲି, `check:cycles` ବର୍ତ୍ତମାନ ଏକ **ରାଚେଟ୍** (`--ratchet`, `quality-baseline.json` ରେ ସୀମା `metrics.cycles.value = 14`, `direction: down`) — ଏହା ଯେକୌଣସି _ଅବନତି_କୁ ଅବରୋଧ କରେ ଏବଂ ଗଣନା କେବଳ କମିପାରେ। CI `npm run check:cycles:ratchet` ଚଲାଏ। କ୍ରମଶଃ ହ୍ରାସ **A-01** ସହିତ ଚାଲିବ। ବ୍ୟାପକ ଦ୍ୱିତୀୟ ମତାମତ ଭାବେ `check:circular-deps` (dpdm) ପରାମର୍ଶମୂଳକ ରହିବ।
