## ଗେଟ୍ ଇନଭେଣ୍ଟରି ଏବଂ ଏକ୍ଜିକ୍ୟୁସନ୍ ପ୍ରୋଫାଇଲ୍

### ପ୍ରାର୍ଥୀ ଗ୍ରହଣ

CI ଏବଂ Quality Gates ୱର୍କଫ୍ଲୋ ପ୍ରତ୍ୟେକଟି ଏକ ସ୍ଥିର ନିଷ୍ପତ୍ତି ଉତ୍ପାଦନ କରେ: `Gate / CI` ଏବଂ
`Gate / Quality`। ସେମାନଙ୍କର ସଂସ୍କରଣ-ନିୟନ୍ତ୍ରିତ ଗ୍ରହଣ ନୀତି ପ୍ରତ୍ୟେକ ଅପ୍ଷ୍ଟ୍ରିମ୍ ଜବ୍କୁ ଆବଶ୍ୟକ କିମ୍ବା ପରାମର୍ଶମୂଳକ ଭାବେ ତାଲିକାଭୁକ୍ତ କରେ। ପ୍ରୟୋଜ୍ୟ ଆବଶ୍ୟକ ଜବ୍ ସଫଳ ହେବା ଦରକାର: ଅନୁପସ୍ଥିତ, ବାତିଲ, ସ୍କିପ୍, ପେଣ୍ଡିଂ ଏବଂ ଅଜଣା ଫଳାଫଳ PASS ସ୍ଥାପନ କରିପାରେ ନାହିଁ। ବୈଧ docs-only କିମ୍ବା catalog-only ବର୍ଗୀକରଣ ଏକ କୋଡ୍ ଲେନ୍କୁ ପ୍ରୟୋଜ୍ୟ ନୁହେଁ ବୋଲି ଗଣନା କରାଇପାରେ; ଏକ draft PR ଗ୍ରହଣଯୋଗ୍ୟ ପ୍ରାର୍ଥୀ ନୁହେଁ। ଏକ `hotfix` ଲେବଲ୍ ପ୍ରମାଣକୁ ଛାଡ଼ ଦେଉନାହିଁ।

ଉଭୟ ୱର୍କଫ୍ଲୋ main/release ବ୍ରାଞ୍ଚକୁ ଯାଉଥିବା PR, `main` କୁ push, ମାନୁଆଲ୍ dispatch
ଏବଂ merge-group ଇଭେଣ୍ଟକୁ କଭର୍ କରେ। Push, dispatch ଏବଂ merge-group ପୂର୍ଣ୍ଣ ଚୟନ ଚଲାଏ। `release/**` କୁ
push ଏଗୁଡ଼ିକୁ ଆରମ୍ଭ କରେ ନାହିଁ (2026-10-18): ପ୍ରତ୍ୟେକ ପରିବର୍ତ୍ତନ ଏହାର PR ଉପରେ matrix ଚଲାଇସାରିଛି
ଏବଂ ମର୍ଜ୍ ହୋଇଥିବା ସଂଯୋଜନ Release-Green ର କାମ (`docs/ops/RUNNER_BOX.md` → Hosted lane)।
ଫର୍କ ଏବଂ merge group ଗୁଡ଼ିକ ସେହି ଜବ୍ଗୁଡ଼ିକ ପାଇଁ hosted runner ବ୍ୟବହାର କରେ ଯେଉଁଗୁଡ଼ିକ
ଅନ୍ୟଥା self-hosted runner ଚୟନ କରନ୍ତି; rollout ପୂର୍ବରୁ ପର୍ଯ୍ୟାପ୍ତ hosted କ୍ଷମତା ଯାଞ୍ଚ କରିବା ଆବଶ୍ୟକ।

ପ୍ରତ୍ୟେକ JSON ରସିଦ୍ ଯାଞ୍ଚ କରାଯାଇଥିବା SHA, ୱର୍କଫ୍ଲୋ run ଏବଂ attempt ଚିହ୍ନଟ କରେ।
CLI checkout/event SHA ଅମେଳକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। ୱର୍କଫ୍ଲୋ ପରୀକ୍ଷାଗୁଡ଼ିକ ନୀତି ସଦସ୍ୟତାକୁ verdict ଜବ୍ର
`needs` ତାଲିକା ସହିତ ବାନ୍ଧିଥାଏ, ଯାହାଦ୍ୱାରା ଏକ ନୂତନ କିମ୍ବା ଅପସାରିତ ଲେନ୍ ନିରବରେ ଅଦୃଶ୍ୟ ହୋଇପାରେ ନାହିଁ। ରସିଦଗୁଡ଼ିକ ସେମାନଙ୍କର ନିଜ ୱର୍କଫ୍ଲୋକୁ କଭର୍ କରେ, ପ୍ରକାଶନ, deployment କିମ୍ବା ଏକ ବିଦ୍ୟମାନ advisory scanner ର ଆଭ୍ୟନ୍ତରୀଣ କାର୍ଯ୍ୟକୁ ନୁହେଁ। ବ୍ରାଞ୍ଚ ନିୟମରେ ଉଭୟ check ନାମ ସକ୍ରିୟ କରିବା ଏକ ପୃଥକ ପ୍ରଶାସନିକ ପରିବର୍ତ୍ତନ; ଏହି ଜବ୍ଗୁଡ଼ିକୁ ଯୋଡ଼ିବା ନିଜେ କୌଣସି ବ୍ରାଞ୍ଚକୁ ସୁରକ୍ଷା ଦେଉନାହିଁ।

### ସ୍ଥିର ସ୍କାନ୍ ଇନଭେଣ୍ଟରି

ସଂସ୍କରଣ-ନିୟନ୍ତ୍ରିତ npm-alias ଇନଭେଣ୍ଟରି ଏବଂ static-scan ସଦସ୍ୟତା
`config/quality/gate-manifest.json` ରେ ରହେ। `package.json` ବିରୋଧରେ ସ୍କ୍ରିପ୍ଟ ନାମ ଏବଂ ନିଖୁତ କମାଣ୍ଡ ଯାଞ୍ଚ କରିବା ପାଇଁ `npm run check:gate-manifest` ଚଲାନ୍ତୁ; ଯୋଗ, ଅପସାରଣ ଏବଂ କମାଣ୍ଡର ପରିବର୍ତ୍ତନ local hook ଏବଂ CI ର change-classification ଜବ୍ ଉଭୟରେ ବିଫଳ ହୁଏ। ଏକ alias ୱର୍କଫ୍ଲୋ ଜବ୍, matrix instance କିମ୍ବା test case ନୁହେଁ: ଏହି ଗଣନାଗୁଡ଼ିକୁ ପରସ୍ପର ବଦଳାଯୋଗ୍ୟ ଭାବେ ପ୍ରଦର୍ଶନ କରାଯିବା ଉଚିତ୍ ନୁହେଁ।

ଚୟନିତ alias ଗୁଡ଼ିକୁ execute ନକରି ଯାଞ୍ଚ କରିବା ପାଇଁ `npm run quality:scan -- --list` କିମ୍ବା `npm run quality:scan:fast -- --list`
ବ୍ୟବହାର କରନ୍ତୁ। Runner npm entrypoint କୁ ଆହ୍ୱାନ କରେ, ତେଣୁ ଏହାର runtime (ସଂରଚିତ ଥିଲେ Bun ସହିତ) ଅବିକୃତ ରହେ।
Manifest ସେହି profiles ବାହାରର alias ଗୁଡ଼ିକୁ ପୃଥକ ଭାବେ ଆହ୍ୱାନ କରାଯାଉଥିବା ଭାବେ ରେକର୍ଡ କରେ, ଏବଂ read-only scan profile ଗୁଡ଼ିକରେ maintenance command ନିଷିଦ୍ଧ।

ଏହି profile ଗୁଡ଼ିକ କେବଳ static scan କୁ କଭର୍ କରେ। ଏଗୁଡ଼ିକ product test, coverage, packaging, external check କିମ୍ବା ପ୍ରାର୍ଥୀର ସମ୍ପୂର୍ଣ୍ଣ release acceptance କୁ ପ୍ରମାଣିତ କରେ ନାହିଁ। ୱର୍କଫ୍ଲୋ admission ସଂଯୁକ୍ତ `config/quality/admission-policy.json` ଏବଂ `scripts/quality/admission-verdict.mjs` ବ୍ୟବହାର କରେ। Release-observer profile ଗୁଡ଼ିକ ପୃଥକ ରହେ; ସେମାନଙ୍କର ପ୍ରୟୋଜ୍ୟ check ଏବଂ receipt ଗୁଡ଼ିକୁ ସ୍ୱାଧୀନ ଭାବେ ଯାଞ୍ଚ କରନ୍ତୁ। ତଳର prose inventory ଏକ ସନ୍ଦର୍ଭ, କୌଣସି gate ପ୍ରକୃତରେ ଚାଲିଥିବାର ପ୍ରମାଣ ନୁହେଁ।

ସ୍କ୍ରିପ୍ଟଗୁଡ଼ିକ policy gate ପାଇଁ `scripts/check/` ଏବଂ ratchet engine ପାଇଁ `scripts/quality/` ଅଧୀନରେ ରହେ।
CI ର ପ୍ରାମାଣିକ ଉତ୍ସ ହେଉଛି `.github/workflows/ci.yml`।

### Release PR fast-path (`quality.yml`)

`.github/workflows/quality.yml` main/release PR, `main` କୁ push,
dispatch ଏବଂ merge group ରେ CI କୁ ପୂରକ କରେ। PR ଗୁଡ଼ିକ path-filtered fast check ବ୍ୟବହାର କରେ।
ସ୍ଥାୟୀ ଭାବେ disabled duplicate build ଅପସାରଣ କରାଯାଇଛି; ପ୍ରକୃତ build/package/boot check ଗୁଡ଼ିକ CI ରେ ରହିଛି।

| ଜବ୍                                              | ପରିସର                                                                                                                                                                                                             | ବ୍ଲକିଂ          |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| `Docs Gates (fast-path)`                         | Docs/code PR; API docs refs ଏବଂ docs-all                                                                                                                                                                          | ହଁ              |
| `Fast Quality Gates`                             | Code PR; static check, typecheck, dashboard typecheck, impacted unit test                                                                                                                                         | ହଁ              |
| `Forgotten sibling tests`                        | Code PR; static consumer ଏବଂ candidate sibling test ପର୍ଯ୍ୟନ୍ତ trace କରାଯାଇଥିବା changed module; barrel ଏବଂ dynamic-import path ଗୁଡ଼ିକୁ referenced allowlist exception ସହିତ advisory diagnostic ଭାବେ ରିପୋର୍ଟ କରାଯାଏ | **ପରାମର୍ଶମୂଳକ** |
| `Vitest (fast-path)`                             | Code PR; fast vitest suite                                                                                                                                                                                        | ହଁ              |
| `Unit Tests fast-path`                           | Code PR; 4-shard unit suite                                                                                                                                                                                       | ହଁ              |

#### Forgotten sibling tests ରିପୋର୍ଟ

`npm run check:forgotten-sibling-tests` ପରୀକ୍ଷା-ପ୍ରଭାବ ମାନଚିତ୍ର ପଛରେ ଥିବା ଆମଦାନି ରିଜଲ୍ଭର୍କୁ ପୁନଃବ୍ୟବହାର କରେ।

#### `check-ui-value-drift` — ପୁରୁଣା-ଅନୁବାଦ ଗେଟ୍

ଅନ୍ୟ ଗେଟ୍ଗୁଡ଼ିକ ଯାହାକୁ ଗଠନାତ୍ମକ ଭାବେ ଦେଖିପାରନ୍ତି ନାହିଁ, ସେହି ଗୋଟିଏ i18n regression-କୁ ଧରିଥାଏ: ଗୋଟିଏ ଇଂରାଜୀ ମୂଲ୍ୟ
ପୁନଃଲେଖା ହୁଏ ଏବଂ _ପୂର୍ବର_ ଇଂରାଜୀରୁ ଉତ୍ପନ୍ନ ଅନୁବାଦଗୁଡ଼ିକ ପଛରେ ରହିଯାଆନ୍ତି, ତେଣୁ
ଅଇଂରାଜୀ ବ୍ୟବହାରକାରୀମାନେ ଆତ୍ମବିଶ୍ୱାସଜନକ ଭାବରେ ଲେଖାଯାଇଥିବା, କିନ୍ତୁ ବର୍ତ୍ତମାନ ଭୁଲ୍ ଥିବା କପି ପଢ଼ିଚାଲନ୍ତି।

ଏହା ପ୍ରକୃତରେ ଶିପ୍ ହୋଇଥିଲା। Antigravity
ଲଗଇନ୍ ସହାୟକ ଆସିବା ସମୟରେ `oauthModal.googleOAuthWarning` ପୁନଃଲେଖା ହୋଇଥିଲା (#5203); **43ଟି ଲୋକେଲ୍ରୁ 39ଟି** ଅପରେଟରମାନଙ୍କୁ "ସମ୍ପୂର୍ଣ୍ଣ URL କପି କରି ତଳେ ପେଷ୍ଟ କରନ୍ତୁ" ବୋଲି କହୁଥିବା ପାଠ୍ୟ ରଖିଥିଲେ — ଏହି ପ୍ରବାହ ସେହି ପ୍ରୋଭାଇଡର୍ ପାଇଁ ସମାପ୍ତ ହୋଇପାରେ ନାହିଁ। #8463 ପର୍ଯ୍ୟନ୍ତ ଏହା ଅଦୃଶ୍ୟ ରହିଲା, କାରଣ:

- `sync-ui-keys` କେବଳ **ଅନୁପସ୍ଥିତ** କୀଗୁଡ଼ିକୁ ପଛରୁ ଯୋଡ଼େ, **stale** କୀଗୁଡ଼ିକୁ କେବେ ନୁହେଁ;
- `check-ui-keys-coverage` କୀ _ଉପସ୍ଥିତି_ ଗଣନା କରେ, ତେଣୁ ଗୋଟିଏ stale ଅନୁବାଦ ମଧ୍ୟ କଭର୍ ହୋଇଥିବା ବୋଲି ଗଣାଯାଏ;
- `check-translation-drift` `docs/i18n/<locale>/**.md` ଡକ୍ୟୁମେଣ୍ଟେସନ୍ ମିରର୍ଗୁଡ଼ିକୁ ଟ୍ରାକ୍ କରେ —
  ଏହା `src/i18n/messages/*.json` କେବେ ପଢ଼େ ନାହିଁ। 2026-09 ରି-ସିଙ୍କ୍ ପରଠାରୁ `docs-sync-strict` ଜବ୍ରେ ବ୍ଲକ୍ କରୁଛି: ଏକ କୋର୍ ଡକ୍କୁ ସମ୍ପାଦନ କରନ୍ତୁ → `npm run i18n:run -- --files=<doc>` (ସେକ୍ସନ୍-ସ୍ତରୀୟ, ସସ୍ତା)।

**Diff-aware, baseline-backed ନୁହେଁ।** ଏହା merge base-ରେ ଥିବା `en.json` ସହିତ
working tree-ର ତୁଳନା କରେ; ଯେକୌଣସି କୀର ଇଂରାଜୀ ମୂଲ୍ୟ ବଦଳିଥିଲେ, ଏପର୍ଯ୍ୟନ୍ତ
ଅସ୍ପୃଶ୍ୟ ଅନୁବାଦ ରଖିଥିବା ଯେକୌଣସି ଲୋକେଲ୍ stale ଅଟେ। ଏହା ଉଦ୍ଦେଶ୍ୟପୂର୍ବକ **ପୂର୍ବରୁ ଥିବା ଋଣକୁ ଫ୍ରିଜ୍ କରେ** — ଦୀର୍ଘଦିନର ଅନୁବାଦ କେଉଁ ପୁରୁଣା ଇଂରାଜୀରୁ ଆସିଥିଲା, ଏକ diff ତାହା ପ୍ରକାଶ କରିପାରେ ନାହିଁ, ତେଣୁ ଗେଟ୍ କେବଳ ବର୍ତ୍ତମାନର ପରିବର୍ତ୍ତନ ଯାହାକୁ ସ୍ପର୍ଶ କରୁଛି ତାହାକୁ ମାତ୍ର ମୂଲ୍ୟାୟନ କରେ। ବିକଳ୍ପଟି (ପ୍ରତ୍ୟେକ କୀ ପାଇଁ ଏକ hash baseline) ପାଇଁ ପ୍ରାୟ 600 KB-ର ଏକ generated file ଦରକାର ହେବ, ଯାହା ବର୍ତ୍ତମାନର ସବୁଠାରୁ ବଡ଼ baseline ଠାରୁ 3× ବଡ଼ ଏବଂ ପ୍ରତ୍ୟେକ i18n PR-ରେ ପରିବର୍ତ୍ତନ ଆଣିବ।

ଏହାକୁ ପୂରଣ କରିବାର ଦୁଇଟି ଉପାୟ:

1. ପ୍ରଭାବିତ ଅନୁବାଦଗୁଡ଼ିକୁ ଅଦ୍ୟତନ କରନ୍ତୁ, କିମ୍ବା
2. ସେଗୁଡ଼ିକୁ `__MISSING__:<new english>` କରନ୍ତୁ — runtime ତାହାପରେ ସଂଶୋଧିତ ଇଂରାଜୀ ପ୍ରଦାନ କରିବ
   (`src/i18n/request.ts::deepMergeFallback`, #7258) ଏବଂ କୀଟି ଅନୁବାଦ ପାଇଁ କ୍ୟୁରେ ଯିବ।

ଯଦି string-ର **ଅର୍ଥ** ବଦଳିଛି, ତେବେ **କୀର ନାମ ବଦଳାଇବାକୁ** ପସନ୍ଦ କରନ୍ତୁ: ଏକ ନୂତନ କୀ stale ଅନୁବାଦ ଉତ୍ତରାଧିକାରରେ ପାଇପାରେ ନାହିଁ। #8463 ରେ ବ୍ୟବହୃତ ପ୍ୟାଟର୍ନ୍ ଏହା ହିଁ ଥିଲା।

```bash
npm run i18n:check-value-drift          # strict (what CI runs)
npm run i18n:check-value-drift:warn     # report only
BASE_REF=origin/release/vX.Y.Z npm run i18n:check-value-drift
```

(ଯଥା, `KNOWN_STALE_DOC_REFS`, `KNOWN_MISSING`, `KNOWN_RAW_SQL`)। ନୀତିଟି ହେଉଛି:

**ମୂଳ କାରଣଟି ସମାଧାନ କରନ୍ତୁ; ଉଲ୍ଲଂଘନଟି ପୂର୍ବରୁ ଥିଲେ ଏବଂ ସେହି PRରେ
ସମାଧାନ କରାଯାଇପାରୁ ନଥିଲେ ମାତ୍ର ଅନୁମୋଦିତ-ତାଲିକା ବ୍ୟବହାର କରନ୍ତୁ।**

ଏକ ଅନୁମୋଦିତ-ତାଲିକାରେ ଏଣ୍ଟ୍ରି ଯୋଡ଼ିବାବେଳେ:

2. ଟ୍ରାକିଂ ଇସ୍ୟୁକୁ ଉଲ୍ଲେଖ କରନ୍ତୁ (ଯଥା, `// #3498 — ପର୍ଯ୍ୟାୟ 2 ବୈଶିଷ୍ଟ୍ୟ, ଏପର୍ଯ୍ୟନ୍ତ କାର୍ଯ୍ୟକାରୀ କରାଯାଇନାହିଁ`)।
3. ଉଲ୍ଲଂଘନଟି ସମାଧାନ କରୁଥିବା ସେହି PRରେ ଏଣ୍ଟ୍ରିଟି ହଟାନ୍ତୁ — ଆଉ କୌଣସି ସକ୍ରିୟ ଉଲ୍ଲଂଘନକୁ
   ଦମନ କରୁ ନଥିବା ଏକ ଅଚଳ ଏଣ୍ଟ୍ରି ନିଜେ ଏକ ତ୍ରୁଟି (କାର୍ଯ୍ୟକାରୀ ହେବା ପରେ 6A.3 ଅଚଳ-ପ୍ରବର୍ତ୍ତନ
   ଏକ ଅନାଥ ଅନୁମୋଦିତ-ତାଲିକା ଏଣ୍ଟ୍ରି ପାଇଁ ଗେଟ୍କୁ ବିଫଳ କରିବ)।

ପରୀକ୍ଷାଗୁଡ଼ିକୁ ଶୀଘ୍ର ପାସ୍ କରାଇବା ପାଇଁ ଅନୁମୋଦିତ-ତାଲିକା ଏଣ୍ଟ୍ରି ଯୋଡ଼ନ୍ତୁ **ନାହିଁ**। ବଢ଼ୁଥିବା

1. **ଗେଟ୍ର ଆଉଟପୁଟ୍ ଯତ୍ନର ସହ ପଢ଼ନ୍ତୁ** — କେଉଁ ଫାଇଲ୍ କିମ୍ବା ସିମ୍ବଲ୍ ନିୟମଟି ଉଲ୍ଲଂଘନ କରିଛି, ଏହା ଆପଣଙ୍କୁ ଠିକ୍ ଭାବରେ କହିଥାଏ।

   ସଠିକ୍ ହେବାମାତ୍ରେ ପାସ୍ ହୋଇଯାଏ।
3. **ଯଦି ଉଲ୍ଲଂଘନଟି ପୂର୍ବରୁ ଥିଲା** (ଅର୍ଥାତ୍, ଆପଣ ଏହାକୁ ସୃଷ୍ଟି କରିନାହାନ୍ତି, କିନ୍ତୁ ଗେଟ୍ ବର୍ତ୍ତମାନ
   ଏହାକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରୁଛି): ଯଥାର୍ଥତାର ମନ୍ତବ୍ୟ ଏବଂ ଏକ ଟ୍ରାକିଂ ଇସ୍ୟୁ ସହିତ ଏକ ଅନୁମୋଦିତ-ତାଲିକା ଏଣ୍ଟ୍ରି ଯୋଡ଼ନ୍ତୁ।

   ଆପଣଙ୍କ ପରିବର୍ତ୍ତନ ମେଟ୍ରିକ୍କୁ ଆହୁରି ଖରାପ କରିଛି। ଅନ୍ତର୍ନିହିତ ସମସ୍ୟାଟି ସମାଧାନ କରନ୍ତୁ, କିମ୍ବା (କ୍ୱଚିତ୍) ପରିବର୍ତ୍ତନଟି ଉଦ୍ଦେଶ୍ୟମୂଳକ ଏବଂ ମେଟ୍ରିକ୍ର
   ଅବନତି ଗ୍ରହଣଯୋଗ୍ୟ ହେଲେ `npm run quality:ratchet -- --update` ଚଲାନ୍ତୁ — କିନ୍ତୁ PR ବିବରଣୀରେ ଏହାର କାରଣ ଲିପିବଦ୍ଧ କରନ୍ତୁ।

   କରେନାହିଁ, କିନ୍ତୁ CI ସାରାଂଶରେ ଦେଖାଯାଏ। ତଥାପି ସେଗୁଡ଼ିକୁ ସମାଧାନ କରନ୍ତୁ।

### ମର୍ଜ / ଡିଡ୍ୟୁପ୍ (ଯାନ୍ତ୍ରିକ, କମ୍ ବିପଦ)

ପ୍ରତ୍ୟେକ ପ୍ରାର୍ଥୀକୁ 2026-06-17 ରେ ସକ୍ରିୟ ଗେଟ୍ ସ୍ଥିତି ସହିତ ଯାଞ୍ଚ କରାଯାଇଥିଲା (ବିଶ୍ୱାସ କରନ୍ତୁ, କିନ୍ତୁ ଯାଞ୍ଚ ମଧ୍ୟ କରନ୍ତୁ);
ଅନେକ "ସ୍ପଷ୍ଟ" ମର୍ଜ ଋଣ ଲୁଚାଇ ରଖିଥିବା ଜଣାପଡ଼ିଲା ଏବଂ ସେଗୁଡ଼ିକ **ସିଧାସଳଖ ପ୍ରତିସ୍ଥାପନଯୋଗ୍ୟ ନୁହେଁ**।

- **`check:docs-sync` ଦୁଇଥର ଚାଲେ** — `lint` ଜବ୍ରେ ସ୍ୱତନ୍ତ୍ର ଭାବେ ଏବଂ ପୁଣି `check:docs-all` (`docs-sync-strict`) ଭିତରେ ଓ husky pre-commit hook ରେ। ✅ **ସମ୍ପୂର୍ଣ୍ଣ** — ସ୍ୱତନ୍ତ୍ର `lint` ଆହ୍ୱାନ ହଟାଯାଇଛି।
- **CVE ସ୍କାନିଂ** — ❌ **ଏକ ସ୍ୱଚ୍ଛ ମର୍ଜ ନୁହେଁ।** ଯେକୌଣସି high/critical CVE ଥିଲେ `audit:deps` ନିଶ୍ଚିତ ଭାବେ ବିଫଳ ହୁଏ; `check:vuln-ratchet` (osv) କେବଳ ବେସ୍ଲାଇନ୍ ତୁଳନାରେ ଏକ _ଅବନତି_ ହେଲେ ବିଫଳ ହୁଏ (ବର୍ତ୍ତମାନ 1 MODERATE)। ଅର୍ଥବିଜ୍ଞାନ ଭିନ୍ନ — `audit:deps` ବାଦ ଦେଲେ ସମ୍ପୂର୍ଣ୍ଣ high/critical ଗେଟ୍ ହରାଇଯିବ। ଉଭୟକୁ ରଖନ୍ତୁ।
- **ଚକ୍ର ଚିହ୍ନଟ** — ✅ **ସମ୍ପୂର୍ଣ୍ଣ** (#15159 G-01/G-02)। ଏଠାରେ ଥିବା ପୁରୁଣା ପାଠ୍ୟ `check:cycles` କୁ "ସବୁଜ, ସୁବ୍ୟବସ୍ଥିତ" ଗେଟ୍ ବୋଲି କହିଥିଲା ଏବଂ `check:circular-deps` (dpdm) 91ଟି ଚକ୍ର ରିପୋର୍ଟ କରିଥିବାରୁ ଏହାକୁ ବ୍ଲକିଂ ଭାବେ ରଖିବା ଯୁକ୍ତିସଙ୍ଗତ ବୋଲି ଦର୍ଶାଇଥିଲା। ସେହି ସବୁଜ ସ୍ଥିତି ଏକ **ଭୁଲ ସବୁଜ** ଥିଲା: `check:cycles` 5ଟି ସବ୍ଡିରେକ୍ଟୋରୀ (450ଟି ଫାଇଲ୍) ସ୍କାନ୍ କରୁଥିଲା, କେବଳ ସ୍ଥିର `import|export … from` ସହିତ ମେଳ କରୁଥିଲା, ଏବଂ ପ୍ରତ୍ୟେକ `@/` ଓ `@omniroute/open-sse/` ସ୍ପେସିଫାୟର୍କୁ ବାଦ ଦେଉଥିଲା, ତେଣୁ ରିପୋଜିଟୋରୀରେ ପ୍ରାଧାନ୍ୟ ରଖିଥିବା ଡାଇନାମିକ୍-import + alias ଚକ୍ରଗୁଡ଼ିକୁ ଏହା ଦେଖିପାରୁ ନଥିଲା। ସମାଧାନ କରାଯାଇଛି: ଗେଟ୍ଟି ବର୍ତ୍ତମାନ `src` + `open-sse` (5023ଟି ଫାଇଲ୍) ପରିକ୍ରମା କରେ, TypeScript AST ରୁ ସ୍ପେସିଫାୟର୍ଗୁଡ଼ିକ ସଂଗ୍ରହ କରେ (ଫଳରେ `import("…")` ଗଣାଯାଏ ଏବଂ type-position `typeof import("…")` ଗଣାଯାଏ ନାହିଁ), ଏବଂ tsconfig `paths` ସମାଧାନ କରେ। ଏହା 0 ନୁହେଁ, **14**ଟି ଚକ୍ର ଚିହ୍ନଟ କରେ। ଏକ ଗେଟ୍ PR ରେ ପୂର୍ବରୁ ଥିବା 14ଟି ଚକ୍ର ସମାଧାନ କରାଯାଇପାରିବ ନାହିଁ ବୋଲି, `check:cycles` ବର୍ତ୍ତମାନ ଏକ **ରାଚେଟ୍** (`--ratchet`, `quality-baseline.json` ରେ ସୀମା `metrics.cycles.value = 14`, `direction: down`) — ଏହା ଯେକୌଣସି _ଅବନତି_କୁ ଅବରୋଧ କରେ ଏବଂ ଗଣନା କେବଳ କମିପାରେ। CI `npm run check:cycles:ratchet` ଚଲାଏ। କ୍ରମଶଃ ହ୍ରାସ **A-01** ସହିତ ଚାଲିବ। ବ୍ୟାପକ ଦ୍ୱିତୀୟ ମତାମତ ଭାବେ `check:circular-deps` (dpdm) ପରାମର୍ଶମୂଳକ ରହିବ।
