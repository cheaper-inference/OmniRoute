ଏହି ଡକ୍ୟୁମେଣ୍ଟଟି OmniRoute ର ସମସ୍ତ CI ଗୁଣବତ୍ତା ଗେଟ୍ ପାଇଁ ପ୍ରାମାଣିକ ସନ୍ଦର୍ଭ।
ଏହା ପ୍ରତ୍ୟେକ ଗେଟ୍, ଏହା କ’ଣ ଯାଞ୍ଚ କରେ, କେଉଁ CI ଜବ୍ରେ ଏହା ଚାଲେ, ଏହା
ଏକ ରାଚେଟ୍ ବେସ୍ଲାଇନ୍ କିମ୍ବା ଏକ ପାସ୍/ଫେଲ୍ ନୀତି ବ୍ୟବହାର କରେ କି ନାହିଁ, ଏବଂ ଏହା ବିଲ୍ଡ୍କୁ ଅବରୋଧ କରେ କିମ୍ବା କେବଳ ପରାମର୍ଶମୂଳକ—ତାହା ବର୍ଣ୍ଣନା କରେ।

ଏକ ସଂକ୍ଷିପ୍ତ ସାରାଂଶ ଏବଂ ଅନୁମତି-ତାଲିକା ନୀତି ପାଇଁ, `AGENTS.md` ରେ ଥିବା
"ଗୁଣବତ୍ତା ଗେଟ୍ ଏବଂ ରାଚେଟ୍" ବିଭାଗ ଦେଖନ୍ତୁ। ସେହି ସିଷ୍ଟମ୍ର ସମାଲୋଚନାମୂଳକ ମୂଲ୍ୟାଙ୍କନ,
ପରିପକ୍ୱତା ବର୍ଗୀକରଣ ଏବଂ ଟୁଲ୍-ନିରପେକ୍ଷ ପ୍ରତିରୂପଣ ଯୋଜନା ପାଇଁ,
[ଗୁଣବତ୍ତା ଗେଟ୍ ପ୍ଲେବୁକ୍](../ops/QUALITY_GATE_PLAYBOOK.md) ଦେଖନ୍ତୁ।

## ଗେଟ୍ ଇନଭେଣ୍ଟରି ଏବଂ ଏକ୍ସିକ୍ୟୁସନ୍ ପ୍ରୋଫାଇଲ୍

### ପ୍ରାର୍ଥୀ ଭର୍ତ୍ତି

CI ଏବଂ Quality Gates ୱର୍କଫ୍ଲୋ ପ୍ରତ୍ୟେକଟି ଏକ ସ୍ଥିର ନିଷ୍ପତ୍ତି ପ୍ରକାଶ କରେ: `Gate / CI` ଏବଂ
`Gate / Quality`। ସେମାନଙ୍କର ସଂସ୍କରଣ-ନିୟନ୍ତ୍ରିତ ଭର୍ତ୍ତି ନୀତି ପ୍ରତ୍ୟେକ upstream job କୁ
ଆବଶ୍ୟକ କିମ୍ବା ପରାମର୍ଶାତ୍ମକ ଭାବେ ତାଲିକାଭୁକ୍ତ କରେ। ପ୍ରୟୋଜ୍ୟ ଆବଶ୍ୟକ job ସଫଳ ହେବା ଦରକାର:
ଅନୁପସ୍ଥିତ, ବାତିଲ, skip ହୋଇଥିବା, ଅପେକ୍ଷାରତ ଏବଂ ଅଜଣା ଫଳାଫଳ PASS ସ୍ଥାପନ କରିପାରେ ନାହିଁ। ଏକ ବୈଧ
docs-only କିମ୍ବା catalog-only ଶ୍ରେଣୀକରଣ ଏକ code lane କୁ ପ୍ରଯୋଜ୍ୟ ନୁହେଁ ବୋଲି ଦର୍ଶାଇପାରେ;
draft PR ଗ୍ରହଣଯୋଗ୍ୟ ପ୍ରାର୍ଥୀ ନୁହେଁ। ଏକ `hotfix` ଲେବଲ୍ ପ୍ରମାଣକୁ ଛାଡ଼ ଦିଏ ନାହିଁ।

ଉଭୟ ୱର୍କଫ୍ଲୋ main/release ବ୍ରାଞ୍ଚକୁ ଯାଉଥିବା PR, `main` କୁ push, manual dispatch
ଏବଂ merge-group ଇଭେଣ୍ଟକୁ ଆବୃତ କରେ। Push, dispatch ଏବଂ merge-group ସମ୍ପୂର୍ଣ୍ଣ selection ଚଲାଏ। `release/**` କୁ
push ଏଗୁଡ଼ିକୁ ଆରମ୍ଭ କରେ ନାହିଁ (2026-10-18): ପ୍ରତ୍ୟେକ ପରିବର୍ତ୍ତନ ତାହାର PR ଉପରେ matrix ଚଲାଇସାରିଛି
ଏବଂ merged combination ହେଉଛି Release-Green ର କାମ (`docs/ops/RUNNER_BOX.md` → Hosted lane)।
Fork ଏବଂ merge group ଗୁଡ଼ିକ ସେହି job ପାଇଁ hosted runner ବ୍ୟବହାର କରେ ଯେଉଁଗୁଡ଼ିକ ଅନ୍ୟଥା self-hosted
runner ବାଛନ୍ତି; rollout ପୂର୍ବରୁ ପର୍ଯ୍ୟାପ୍ତ hosted capacity ଯାଞ୍ଚ କରିବା ଦରକାର।

ପ୍ରତ୍ୟେକ JSON receipt ଯାଞ୍ଚ କରାଯାଇଥିବା checkout SHA, workflow run ଏବଂ attempt ଚିହ୍ନଟ କରେ।
CLI checkout/event SHA mismatch ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। Workflow tests verdict job ର `needs` ତାଲିକା ସହିତ policy
membership କୁ ବାନ୍ଧେ, ଯାହାଦ୍ୱାରା ନୂଆ କିମ୍ବା ଅପସାରିତ lane ନିରବରେ ଅଦୃଶ୍ୟ ହୋଇପାରେ ନାହିଁ। Receipt ଗୁଡ଼ିକ
ନିଜ workflow କୁ ଆବୃତ କରେ, publication, deployment କିମ୍ବା ଏକ ବିଦ୍ୟମାନ advisory scanner ର ଆଭ୍ୟନ୍ତରୀଣ
ଅଂଶଗୁଡ଼ିକୁ ନୁହେଁ। Branch rules ରେ ଉଭୟ check name ସକ୍ରିୟ କରିବା ଏକ ପୃଥକ ପ୍ରଶାସନିକ ପରିବର୍ତ୍ତନ;
ଏହି job ଗୁଡ଼ିକୁ ଯୋଡ଼ିବା ନିଜେ କୌଣସି branch କୁ ସୁରକ୍ଷିତ କରେ ନାହିଁ।

### ସ୍ଥିର ସ୍କାନ୍ ଇନଭେଣ୍ଟରି

ସଂସ୍କରଣ-ନିୟନ୍ତ୍ରିତ npm-alias ଇନଭେଣ୍ଟରି ଏବଂ static-scan membership
`config/quality/gate-manifest.json` ରେ ରହେ। `npm run check:gate-manifest` ଚଲାଇ
`package.json` ବିରୋଧରେ script name ଏବଂ ସଠିକ୍ command ଗୁଡ଼ିକୁ ବୈଧତା ଯାଞ୍ଚ କରନ୍ତୁ; ଯୋଗ, ଅପସାରଣ ଏବଂ
command drift ଉଭୟ local hook ଏବଂ CI ର change-classification job ଗୁଡ଼ିକୁ ବିଫଳ କରେ।
ଏକ alias କୌଣସି workflow job, matrix instance କିମ୍ବା test case ନୁହେଁ: ଏହି ଗଣନାଗୁଡ଼ିକୁ
ପରସ୍ପର ବଦଳଯୋଗ୍ୟ ଭାବେ ପ୍ରଦର୍ଶନ କରିବା ଉଚିତ୍ ନୁହେଁ।

ଚୟନିତ alias ଗୁଡ଼ିକୁ ଚଲାଇବା ବିନା ଯାଞ୍ଚ କରିବା ପାଇଁ `npm run quality:scan -- --list` କିମ୍ବା
`npm run quality:scan:fast -- --list` ବ୍ୟବହାର କରନ୍ତୁ। Runner npm entrypoint କୁ ଆହ୍ୱାନ କରେ, ତେଣୁ ଏହାର
runtime (configured ଥିଲେ Bun ସମେତ) ଅବିକୃତ ରହେ। Manifest ସେହି profile ବାହାରର alias ଗୁଡ଼ିକୁ
ପୃଥକ ଭାବେ ଆହ୍ୱାନ କରାଯାଉଥିବା ବୋଲି ରେକର୍ଡ କରେ, ଏବଂ read-only scan profile ଗୁଡ଼ିକରେ
maintenance command ନିଷିଦ୍ଧ।

ଏହି profile ଗୁଡ଼ିକ କେବଳ static scan କୁ ଆବୃତ କରେ। ସେଗୁଡ଼ିକ product test, coverage, packaging,
external check କିମ୍ବା ପ୍ରାର୍ଥୀର ସମ୍ପୂର୍ଣ୍ଣ release acceptance କୁ ପ୍ରମାଣିତ କରେ ନାହିଁ।
Workflow admission ସଂଯୁକ୍ତ `config/quality/admission-policy.json` ଏବଂ
`scripts/quality/admission-verdict.mjs` ବ୍ୟବହାର କରେ। Release-observer profile ଗୁଡ଼ିକ ପୃଥକ ରହେ;
ସେମାନଙ୍କର ପ୍ରଯୋଜ୍ୟ check ଏବଂ receipt ଗୁଡ଼ିକୁ ସ୍ୱାଧୀନ ଭାବେ ଯାଞ୍ଚ କରନ୍ତୁ। ତଳେ ଥିବା
prose inventory ଏକ reference, କୌଣସି gate ପ୍ରକୃତରେ ଚାଲିଥିଲା ବୋଲି ପ୍ରମାଣ ନୁହେଁ।

Script ଗୁଡ଼ିକ `scripts/check/` (policy gate) ଏବଂ `scripts/quality/` (ratchet engine) ଅଧୀନରେ ରହେ।
CI ର source of truth ହେଉଛି `.github/workflows/ci.yml`।

### Release PR fast-path (`quality.yml`)

`.github/workflows/quality.yml` main/release PR, `main` କୁ push,
dispatch ଏବଂ merge group ସମୟରେ CI କୁ ପୂରକ କରେ। PR ଗୁଡ଼ିକ path-filtered fast check ବ୍ୟବହାର କରେ।
ସ୍ଥାୟୀ ଭାବେ ନିଷ୍କ୍ରିୟ duplicate build ଅପସାରଣ କରାଯାଇଛି; ପ୍ରକୃତ build/package/boot check ଗୁଡ଼ିକ
CI ରେ ରହିଛି।

| Job                                              | Scope                                                                                                                                                                                                             | Blocking         |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| `Docs Gates (fast-path)`                         | Docs/code PR; API docs refs ଏବଂ docs-all                                                                                                                                                                          | ହଁ               |
| `Fast Quality Gates`                             | Code PR; static check, typecheck, dashboard typecheck, impacted unit test                                                                                                                                         | ହଁ               |
| `Forgotten sibling tests`                        | Code PR; static consumer ଏବଂ candidate sibling test ପର୍ଯ୍ୟନ୍ତ trace କରାଯାଇଥିବା changed module; barrel ଏବଂ dynamic-import path ଗୁଡ଼ିକୁ advisory diagnostic ଭାବେ report କରାଯାଏ, referenced allowlist exception ସହିତ | **ପରାମର୍ଶାତ୍ମକ** |
| `Vitest (fast-path)`                             | Code PR; fast vitest suite                                                                                                                                                                                        | ହଁ               |
| `Unit Tests fast-path`                           | Code PR; 4-shard unit suite                                                                                                                                                                                       | ହଁ               |
| `No new ESLint warnings`                         | Code PR; suppression-aware lint guard                                                                                                                                                                             | ହଁ, fork ସମେତ    |
| `Merge integrity (changelog + generated skills)` | Non-draft PR; changelog ଏବଂ generated skill sync                                                                                                                                                                  | ହଁ, fork ସମେତ    |

#### Forgotten sibling tests report

`npm run check:forgotten-sibling-tests` ପରୀକ୍ଷା-ପ୍ରଭାବ ମାନଚିତ୍ର ପଛରେ ଥିବା ଆମଦାନି ରିଜଲ୍ଭର୍କୁ ପୁନଃବ୍ୟବହାର କରେ।
ପରିବର୍ତ୍ତିତ ପ୍ରତ୍ୟେକ ଉତ୍ପାଦନ ମଡ୍ୟୁଲ୍ ପାଇଁ, ପ୍ରାର୍ଥୀ
ପରୀକ୍ଷା pull-request diff ରେ ନଥିଲେ, ଏହା ନିର୍ଦ୍ଧାରଣାତ୍ମକ
`changed module/symbol -> static consumer -> candidate sibling test` ଶୃଙ୍ଖଳାଗୁଡ଼ିକୁ ରିପୋର୍ଟ କରେ। ସଂରେଖଣ ପୂର୍ବରୁ
Markdown ସାରାଂଶ ଏବଂ JSON ଫଳାଫଳକୁ `forgotten-sibling-tests` workflow artifact ଭାବେ

#### `check-ui-value-drift` — stale-translation gate

ଅନ୍ୟ ଗେଟ୍ଗୁଡ଼ିକ ଗଠନାତ୍ମକ ଭାବେ ଯାହା ଦେଖିପାରେ ନାହିଁ, ସେହି ଗୋଟିଏ i18n regression-କୁ ଧରେ: ଗୋଟିଏ ଇଂରାଜୀ ମୂଲ୍ୟ ପୁନଃଲିଖିତ ହୁଏ ଏବଂ _ପୂର୍ବତନ_ ଇଂରାଜୀରୁ ଉତ୍ପନ୍ନ ଅନୁବାଦଗୁଡ଼ିକ ପଛରେ ରହିଯାଏ, ତେଣୁ ଅଣ-ଇଂରାଜୀ ବ୍ୟବହାରକାରୀମାନେ ନିଶ୍ଚିତ ଶୁଣାଯାଉଥିବା, କିନ୍ତୁ ଏବେ ଭୁଲ ହୋଇଥିବା ଟେକ୍ସଟ୍ ପଢ଼ିଚାଲନ୍ତି।

ଏହା ପ୍ରକୃତରେ ରିଲିଜ୍ ହୋଇଥିଲା। Antigravity
ଲଗଇନ୍ ହେଲ୍ପର୍ ଯୋଡ଼ାଯିବା ସମୟରେ `oauthModal.googleOAuthWarning` ପୁନଃଲିଖିତ ହୋଇଥିଲା (#5203); **43ଟି ଲୋକେଲ୍ରୁ 39ଟି** ଅପରେଟରମାନଙ୍କୁ "ସମ୍ପୂର୍ଣ୍ଣ URL କପି କରି ତଳେ ପେଷ୍ଟ କରନ୍ତୁ" ବୋଲି କହୁଥିବା ଟେକ୍ସଟ୍ ରଖିଥିଲେ — ଏହି ପ୍ରୋଭାଇଡର୍ ପାଇଁ ଯାହା କେବେ ସମ୍ପୂର୍ଣ୍ଣ ହୋଇପାରେ ନାହିଁ। #8463 ପର୍ଯ୍ୟନ୍ତ ଏହା ଅଜଣା ରହିଥିଲା, କାରଣ:

- `sync-ui-keys` କେବଳ **ଅନୁପସ୍ଥିତ** କି-ଗୁଡ଼ିକୁ ପଛରୁ ଯୋଡ଼େ, **stale** କି-ଗୁଡ଼ିକୁ କେବେ ନୁହେଁ;
- `check-ui-keys-coverage` କି-ର _ଉପସ୍ଥିତି_ ଗଣନା କରେ, ତେଣୁ ଗୋଟିଏ stale ଅନୁବାଦ ମଧ୍ୟ covered ଭାବେ ଗଣାଯାଏ;
- `check-translation-drift` `docs/i18n/<locale>/**.md` ଡକ୍ୟୁମେଣ୍ଟେସନ୍ ମିରର୍ଗୁଡ଼ିକୁ ଟ୍ରାକ୍ କରେ —
  ଏହା `src/i18n/messages/*.json` କେବେ ପଢ଼େ ନାହିଁ। 2026-09 ରି-ସିଙ୍କ୍ଠାରୁ `docs-sync-strict` ଜବ୍ରେ ବ୍ଲକିଂ: ଗୋଟିଏ କୋର୍ ଡକ୍ୟୁମେଣ୍ଟ୍ ସମ୍ପାଦନ କରନ୍ତୁ → `npm run i18n:run -- --files=<doc>` (ସେକ୍ସନ୍-ସ୍ତରୀୟ, ଅଳ୍ପ ଖର୍ଚ୍ଚ)।

**Diff-aware, baseline-backed ନୁହେଁ।** ଏହା merge base-ର `en.json` ସହିତ working tree-କୁ ତୁଳନା କରେ; ଯେକୌଣସି କି ପାଇଁ ଇଂରାଜୀ ମୂଲ୍ୟ ବଦଳିଥିଲେ, ଏବଂ ଯେକୌଣସି ଲୋକେଲ୍ ଏପର୍ଯ୍ୟନ୍ତ ଅସ୍ପର୍ଶିତ ଅନୁବାଦ ରଖିଥିଲେ, ସେହି ଅନୁବାଦ stale ଅଟେ। ଏହା ଇଚ୍ଛାକୃତ ଭାବରେ **ପୂର୍ବରୁ ଥିବା ଋଣକୁ ସ୍ଥିର କରେ** — ଦୀର୍ଘଦିନ ଧରି ରହିଥିବା ଅନୁବାଦ କେଉଁ ପୁରୁଣା ଇଂରାଜୀରୁ ଆସିଛି, ଏକ diff ତାହା ପ୍ରକାଶ କରିପାରେ ନାହିଁ, ତେଣୁ ଗେଟ୍ କେବଳ ବର୍ତ୍ତମାନର ପରିବର୍ତ୍ତନ ଯାହାକୁ ସ୍ପର୍ଶ କରୁଛି ତାହାକୁ ମାତ୍ର ମୂଲ୍ୟାୟନ କରେ। ବିକଳ୍ପଟି (ପ୍ରତି-କି hash baseline) ପାଇଁ ପ୍ରାୟ 600 KB-ର ଏକ generated file ଲାଗିଥାନ୍ତା, ଯାହା ସବୁଠାରୁ ବଡ଼ ବର୍ତ୍ତମାନର baseline ଠାରୁ 3× ବଡ଼ ଏବଂ ପ୍ରତ୍ୟେକ i18n PR-ରେ ପୁନଃପୁନି ପରିବର୍ତ୍ତିତ ହୋଇଥାନ୍ତା।

ଏହା ପୂରଣ କରିବାର ଦୁଇଟି ଉପାୟ:

1. ପ୍ରଭାବିତ ଅନୁବାଦଗୁଡ଼ିକୁ ଅଦ୍ୟତନ କରନ୍ତୁ, କିମ୍ବା
2. ସେଗୁଡ଼ିକୁ `__MISSING__:<new english>` ରେ ସେଟ୍ କରନ୍ତୁ — runtime ତାହାପରେ ସଂଶୋଧିତ ଇଂରାଜୀ ପ୍ରଦାନ କରେ
   (`src/i18n/request.ts::deepMergeFallback`, #7258) ଏବଂ କି-ଟି ଅନୁବାଦ ପାଇଁ queue ହୁଏ।

ଯଦି ଷ୍ଟ୍ରିଙ୍ଗ୍ର **ଅର୍ଥ** ବଦଳିଛି, ତେବେ **କି-ର ନାମ ବଦଳାଇବାକୁ** ପସନ୍ଦ କରନ୍ତୁ: ଏକ ନୂଆ କି stale ଅନୁବାଦ ଉତ୍ତରାଧିକାରରେ ପାଇପାରେ ନାହିଁ। #8463 ରେ ବ୍ୟବହୃତ ପ୍ୟାଟର୍ନ୍ ଏହିଥିଲା।

### CodeQL ରାଚେଟ୍: ରିଫ୍ରେଶ୍ ଅନ୍ତରାଳ ଏବଂ ମାନୁଆଲ୍ ଟ୍ରିଗର୍

`check:codeql-ratchet` **ରିପୋ ଅବସ୍ଥା ପଢ଼େ, ଯାହା ଏକ ସୂଚୀ ଅନୁସାରେ ରିଫ୍ରେଶ୍ ହୁଏ — ପ୍ରତ୍ୟେକ PR ପାଇଁ ନୁହେଁ।**
`gh api repos/diegosouzapw/OmniRoute/code-scanning/default-setup` ରିପୋର୍ଟ କରେ
`state: configured`, `schedule: weekly`: ଏହା GitHubର ଡିଫଲ୍ଟ-ସେଟଅପ୍ ସ୍କାନ୍, ପ୍ରତ୍ୟେକ ପୁସ୍ ପାଇଁ
ବିଶ୍ଳେଷଣ ନୁହେଁ। ପରିଣାମ: ଆଲର୍ଟଗୁଡ଼ିକୁ ଠିକ୍ କରୁଥିବା ଏକ PR ମର୍ଜ ହେବା ପରେ, ପରବର୍ତ୍ତୀ ନିର୍ଦ୍ଧାରିତ
ସ୍କାନ୍ ଚାଲିବା ପର୍ଯ୍ୟନ୍ତ ରାଚେଟ୍ ପୁରୁଣା, ଅଧିକ ସଂଖ୍ୟା ପଢ଼ିବା ଜାରି ରଖେ — ତେଣୁ ସ୍କାନ୍ ଅଦ୍ୟତନ ହେବା
ପର୍ଯ୍ୟନ୍ତ ଏହା ପ୍ରତ୍ୟେକ ଖୋଲା PRରେ, ଠିକ୍ କରୁଥିବା PRର ନିଜସ୍ୱ ଫଲୋ-ଅପ୍ଗୁଡ଼ିକ ସମେତ, ଅବନତି ରିପୋର୍ଟ କରେ।

**ମାନୁଆଲ୍ ରିଫ୍ରେଶ୍**: `gh workflow run codeql.yml --ref release/vX.Y.Z` ବିଶ୍ଳେଷଣକୁ
ପୁନଃ ଚଳାଏ ଏବଂ କିଛି ମିନିଟ୍ ମଧ୍ୟରେ ଆଲର୍ଟଗୁଡ଼ିକୁ ପୁନଃ ପ୍ରକାଶ କରେ। ପ୍ରଥମେ `.github/workflows/codeql.yml`

GitHubର "default setup" ସହିତ ଦ୍ୱନ୍ଦ୍ୱ କରେ** (`CodeQL analyses from advanced configurations cannot be
processed when the default setup is enabled`)। `push`/`pull_request`/
`schedule` ଟ୍ରିଗର୍ଗୁଡ଼ିକୁ ପୁନଃସ୍ଥାପନ କରିବା ପାଇଁ ପ୍ରଥମେ ଏକ **ମାଲିକଙ୍କ କାର୍ଯ୍ୟ** ଆବଶ୍ୟକ: Settings → Code security →
CodeQL: Default → Advanced। ସେହି ସ୍ୱିଚ୍ ବିନା `schedule:` ଟ୍ରିଗର୍ ଯୋଡ଼ନ୍ତୁ ନାହିଁ — ଏହା
କେବଳ ବିଫଳ ରନ୍ଗୁଡ଼ିକ ସୃଷ୍ଟି କରିବ।

   ଅବନତି ଗ୍ରହଣଯୋଗ୍ୟ ହେଲେ `npm run quality:ratchet -- --update` ଚଲାନ୍ତୁ — କିନ୍ତୁ PR ବିବରଣୀରେ ଏହାର କାରଣ ଲିପିବଦ୍ଧ କରନ୍ତୁ।
5. **ପରାମର୍ଶମୂଳକ ଗେଟ୍ଗୁଡ଼ିକ** (`continue-on-error: true`) କେବଳ ସୂଚନାମୂଳକ — ସେଗୁଡ଼ିକ ମର୍ଜ୍କୁ ଅବରୋଧ
   କରେନାହିଁ, କିନ୍ତୁ CI ସାରାଂଶରେ ଦେଖାଯାଏ। ତଥାପି ସେଗୁଡ଼ିକୁ ସମାଧାନ କରନ୍ତୁ।

### ମର୍ଜ / ଡିଡ୍ୟୁପ୍ (ଯାନ୍ତ୍ରିକ, କମ୍ ବିପଦ)

ପ୍ରତ୍ୟେକ ପ୍ରାର୍ଥୀକୁ 2026-06-17 ରେ ସକ୍ରିୟ ଗେଟ୍ ସ୍ଥିତି ସହିତ ଯାଞ୍ଚ କରାଯାଇଥିଲା (ବିଶ୍ୱାସ କରନ୍ତୁ, କିନ୍ତୁ ଯାଞ୍ଚ ମଧ୍ୟ କରନ୍ତୁ);
ଅନେକ "ସ୍ପଷ୍ଟ" ମର୍ଜ ଋଣ ଲୁଚାଇ ରଖିଥିବା ଜଣାପଡ଼ିଲା ଏବଂ ସେଗୁଡ଼ିକ **ସିଧାସଳଖ ପ୍ରତିସ୍ଥାପନଯୋଗ୍ୟ ନୁହେଁ**।

- **`check:docs-sync` ଦୁଇଥର ଚାଲେ** — `lint` ଜବ୍ରେ ସ୍ୱତନ୍ତ୍ର ଭାବେ ଏବଂ ପୁଣି `check:docs-all` (`docs-sync-strict`) ଭିତରେ ଓ husky pre-commit hook ରେ। ✅ **ସମ୍ପୂର୍ଣ୍ଣ** — ସ୍ୱତନ୍ତ୍ର `lint` ଆହ୍ୱାନ ହଟାଯାଇଛି।
- **CVE ସ୍କାନିଂ** — ❌ **ଏକ ସ୍ୱଚ୍ଛ ମର୍ଜ ନୁହେଁ।** ଯେକୌଣସି high/critical CVE ଥିଲେ `audit:deps` ନିଶ୍ଚିତ ଭାବେ ବିଫଳ ହୁଏ; `check:vuln-ratchet` (osv) କେବଳ ବେସ୍ଲାଇନ୍ ତୁଳନାରେ ଏକ _ଅବନତି_ ହେଲେ ବିଫଳ ହୁଏ (ବର୍ତ୍ତମାନ 1 MODERATE)। ଅର୍ଥବିଜ୍ଞାନ ଭିନ୍ନ — `audit:deps` ବାଦ ଦେଲେ ସମ୍ପୂର୍ଣ୍ଣ high/critical ଗେଟ୍ ହରାଇଯିବ। ଉଭୟକୁ ରଖନ୍ତୁ।
- **ଚକ୍ର ଚିହ୍ନଟ** — ✅ **ସମ୍ପୂର୍ଣ୍ଣ** (#15159 G-01/G-02)। ଏଠାରେ ଥିବା ପୁରୁଣା ପାଠ୍ୟ `check:cycles` କୁ "ସବୁଜ, ସୁବ୍ୟବସ୍ଥିତ" ଗେଟ୍ ବୋଲି କହିଥିଲା ଏବଂ `check:circular-deps` (dpdm) 91ଟି ଚକ୍ର ରିପୋର୍ଟ କରିଥିବାରୁ ଏହାକୁ ବ୍ଲକିଂ ଭାବେ ରଖିବା ଯୁକ୍ତିସଙ୍ଗତ ବୋଲି ଦର୍ଶାଇଥିଲା। ସେହି ସବୁଜ ସ୍ଥିତି ଏକ **ଭୁଲ ସବୁଜ** ଥିଲା: `check:cycles` 5ଟି ସବ୍ଡିରେକ୍ଟୋରୀ (450ଟି ଫାଇଲ୍) ସ୍କାନ୍ କରୁଥିଲା, କେବଳ ସ୍ଥିର `import|export … from` ସହିତ ମେଳ କରୁଥିଲା, ଏବଂ ପ୍ରତ୍ୟେକ `@/` ଓ `@omniroute/open-sse/` ସ୍ପେସିଫାୟର୍କୁ ବାଦ ଦେଉଥିଲା, ତେଣୁ ରିପୋଜିଟୋରୀରେ ପ୍ରାଧାନ୍ୟ ରଖିଥିବା ଡାଇନାମିକ୍-import + alias ଚକ୍ରଗୁଡ଼ିକୁ ଏହା ଦେଖିପାରୁ ନଥିଲା। ସମାଧାନ କରାଯାଇଛି: ଗେଟ୍ଟି ବର୍ତ୍ତମାନ `src` + `open-sse` (5023ଟି ଫାଇଲ୍) ପରିକ୍ରମା କରେ, TypeScript AST ରୁ ସ୍ପେସିଫାୟର୍ଗୁଡ଼ିକ ସଂଗ୍ରହ କରେ (ଫଳରେ `import("…")` ଗଣାଯାଏ ଏବଂ type-position `typeof import("…")` ଗଣାଯାଏ ନାହିଁ), ଏବଂ tsconfig `paths` ସମାଧାନ କରେ। ଏହା 0 ନୁହେଁ, **14**ଟି ଚକ୍ର ଚିହ୍ନଟ କରେ। ଏକ ଗେଟ୍ PR ରେ ପୂର୍ବରୁ ଥିବା 14ଟି ଚକ୍ର ସମାଧାନ କରାଯାଇପାରିବ ନାହିଁ ବୋଲି, `check:cycles` ବର୍ତ୍ତମାନ ଏକ **ରାଚେଟ୍** (`--ratchet`, `quality-baseline.json` ରେ ସୀମା `metrics.cycles.value = 14`, `direction: down`) — ଏହା ଯେକୌଣସି _ଅବନତି_କୁ ଅବରୋଧ କରେ ଏବଂ ଗଣନା କେବଳ କମିପାରେ। CI `npm run check:cycles:ratchet` ଚଲାଏ। କ୍ରମଶଃ ହ୍ରାସ **A-01** ସହିତ ଚାଲିବ। ବ୍ୟାପକ ଦ୍ୱିତୀୟ ମତାମତ ଭାବେ `check:circular-deps` (dpdm) ପରାମର୍ଶମୂଳକ ରହିବ।
