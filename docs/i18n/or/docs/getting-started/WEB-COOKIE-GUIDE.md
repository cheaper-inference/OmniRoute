ୱେବ୍ କୁକି ପ୍ରଦାନକାରୀମାନେ OmniRouteକୁ API କି ବଦଳରେ ଆପଣଙ୍କ ବର୍ତ୍ତମାନର ବ୍ରାଉଜର୍ ସେସନ୍ ମାଧ୍ୟମରେ ଏକ AI ସେବା ବ୍ୟବହାର କରିବାକୁ ଦିଅନ୍ତି। ଯେତେବେଳେ ଆପଣଙ୍କ ପାଖରେ ଏକ ସେବାର ୱେବସାଇଟ୍ ମାଧ୍ୟମରେ ପୂର୍ବରୁ ପ୍ରବେଶାଧିକାର ଥାଏ ଏବଂ OmniRoute ସେହି ପ୍ରମାଣୀକୃତ ସେସନ୍କୁ ବ୍ୟବହାର କରୁ ବୋଲି ଚାହାନ୍ତି, ସେତେବେଳେ ସେଗୁଡ଼ିକ ଉପଯୋଗୀ ହୋଇଥାଏ।

API-କି ପ୍ରଦାନକାରୀଙ୍କ ବିପରୀତ, ୱେବ୍ କୁକି ପ୍ରଦାନକାରୀମାନେ ଆପଣଙ୍କ ବ୍ରାଉଜର୍ ୱେବସାଇଟ୍କୁ ପଠାଉଥିବା ପ୍ରମାଣପତ୍ର ବ୍ୟବହାର କରି ପ୍ରମାଣୀକରଣ କରନ୍ତି।

# ଆରମ୍ଭ କରିବା ପୂର୍ବରୁ

> **ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ:** ପ୍ରମାଣପତ୍ରଗୁଡ଼ିକୁ ସର୍ବଦା ଏକ **ସକ୍ରିୟ ନେଟୱର୍କ ଅନୁରୋଧ**ରୁ କପି କରନ୍ତୁ, ଆପଣଙ୍କ ବ୍ରାଉଜର୍ର କୁକି ଷ୍ଟୋରେଜ୍ରୁ **ନୁହେଁ**।

ଭୁଲ ସ୍ଥାନରୁ କୁକି କପି କରିବା କାରଣରୁ ଅନେକ ପ୍ରମାଣୀକରଣ ସମସ୍ୟା ସୃଷ୍ଟି ହୁଏ।

## କୁକି ଷ୍ଟୋରେଜ୍ରୁ କପି କରନ୍ତୁ ନାହିଁ

ଅଧିକାଂଶ ବ୍ରାଉଜର୍ ନିମ୍ନଲିଖିତ ସ୍ଥାନରେ ସଞ୍ଚିତ କୁକିଗୁଡ଼ିକୁ ପ୍ରଦର୍ଶନ କରନ୍ତି:

```
DevTools
→ Application (କିମ୍ବା Storage)
→ Cookies
```

ଏହି କୁକିଗୁଡ଼ିକ ଠିକ୍ ଦେଖାଯାଉଥିଲେ ମଧ୍ୟ, ସେଗୁଡ଼ିକ ହୋଇପାରେ:

- ପୁରୁଣା
- ଅସମ୍ପୂର୍ଣ୍ଣ
- କେବଳ ପ୍ରମାଣୀକୃତ ଅନୁରୋଧରେ ପଠାଯାଉଥିବା କୁକିଗୁଡ଼ିକ ନଥିବା

ଏହି ମୂଲ୍ୟଗୁଡ଼ିକ ବୈଧ ଦେଖାଯାଉଥିଲେ ମଧ୍ୟ, ସେଗୁଡ଼ିକୁ ବ୍ୟବହାର କଲେ ପ୍ରମାଣୀକରଣ ବିଫଳ ହୋଇପାରେ।

## ଏକ ସକ୍ରିୟ ଅନୁରୋଧରୁ କପି କରନ୍ତୁ

ଏହା ବଦଳରେ, ଏକ ସଫଳ ଅନୁରୋଧରୁ କୁକିଗୁଡ଼ିକୁ ବ୍ୟବହାର କରନ୍ତୁ:

```
DevTools
→ Network
→ ପୃଷ୍ଠାକୁ ରିଫ୍ରେଶ୍ କରନ୍ତୁ
→ ଏକ ଚାଟ୍ କିମ୍ବା ବାର୍ତ୍ତାଳାପ ଅନୁରୋଧ ଖୋଲନ୍ତୁ
→ Request Headers
→ Cookie
```

`Cookie` ଅନୁରୋଧ ହେଡର୍ରେ ଆପଣଙ୍କ ବ୍ରାଉଜର୍ ସଫଳତାର ସହ ବ୍ୟବହାର କରିଥିବା ସଠିକ୍ ପ୍ରମାଣୀକରଣ ସୂଚନା ରହିଥାଏ।

ଅଧିକାଂଶ ୱେବ୍ କୁକି ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ, OmniRouteରେ ଏହି ମୂଲ୍ୟକୁ ପେଷ୍ଟ କରିବା ଉଚିତ।

# ସାଧାରଣ ସେଟଅପ୍

ଅଧିକାଂଶ ୱେବ୍ କୁକି ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ ସେଟଅପ୍ ପ୍ରକ୍ରିୟା ସମାନ ଅଟେ।

1. ପ୍ରଦାନକାରୀଙ୍କ ୱେବସାଇଟ୍ରେ ସାଇନ୍ ଇନ୍ କରନ୍ତୁ।
2. ବ୍ରାଉଜର୍ର ବିକାଶକାରୀ ଉପକରଣ ଖୋଲନ୍ତୁ।
3. **Network** ଟ୍ୟାବ୍ ଖୋଲନ୍ତୁ।
4. ପୃଷ୍ଠାକୁ ରିଫ୍ରେଶ୍ କରନ୍ତୁ।
5. ଏକ ପ୍ରମାଣୀକୃତ ଚାଟ୍ କିମ୍ବା ବାର୍ତ୍ତାଳାପ ଅନୁରୋଧ ଖୋଲନ୍ତୁ।
6. ଆବଶ୍ୟକ ପ୍ରମାଣୀକରଣ ପ୍ରମାଣପତ୍ରଗୁଡ଼ିକୁ କପି କରନ୍ତୁ।
7. OmniRoute ଖୋଲନ୍ତୁ।
8. **ପ୍ରଦାନକାରୀ → ପ୍ରଦାନକାରୀ ଯୋଡ଼ନ୍ତୁ**କୁ ଯାଆନ୍ତୁ।
9. ଆପଣଙ୍କ ୱେବ୍ କୁକି ପ୍ରଦାନକାରୀକୁ ଚୟନ କରନ୍ତୁ।
10. ପ୍ରମାଣପତ୍ରଗୁଡ଼ିକୁ ପେଷ୍ଟ କରନ୍ତୁ।
11. **ସଂଯୋଗ ପରୀକ୍ଷା କରନ୍ତୁ**ରେ କ୍ଲିକ୍ କରନ୍ତୁ।
12. ପ୍ରଦାନକାରୀକୁ ସଞ୍ଚୟ କରନ୍ତୁ।

ଆବଶ୍ୟକ ସଠିକ୍ ପ୍ରମାଣପତ୍ରଗୁଡ଼ିକ ପ୍ରଦାନକାରୀ ଉପରେ ନିର୍ଭର କରେ।

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) ହେଉଛି ଏକ ମାଗଣା ଉପଭୋକ୍ତା ଚାଟ୍ ପ୍ଲାଟଫର୍ମ, ଯେଉଁଥିରେ ସାଇନ୍ ଅପ୍ କରିବା ଆବଶ୍ୟକ ନାହିଁ — ପ୍ରଥମ ଥର ପରିଦର୍ଶନ ସମୟରେ ସେସନ୍ ଅଜ୍ଞାତ ଭାବରେ ସୃଷ୍ଟି ହୁଏ ଏବଂ ତିନୋଟି କୁକି ମାଧ୍ୟମରେ ସ୍ଥାୟୀ ରହେ: `uid`, `si_usr_id`, ଏବଂ `si_ses_id`। OmniRoute ଗୋଟିଏ ମାତ୍ର ମଡେଲ୍ ଆଇଡି (`notrack-c`, ଉପନାମ `ntw`) ମାଧ୍ୟମରେ ସମାନ `/api/dispatch` ଏଣ୍ଡପଏଣ୍ଟକୁ ପ୍ରକ୍ସି କରେ।

### ସଂଯୋଗ କରିବାର ପଦକ୍ଷେପ

1. ଆପଣଙ୍କ ବ୍ରାଉଜର୍ରେ [notrack.ai](https://notrack.ai) ଖୋଲନ୍ତୁ ଏବଂ ଅଜ୍ଞାତ ସେସନ୍ କୁକି ସେଟ୍ ହେବାକୁ ଦିଅନ୍ତୁ।
2. **ଡେଭ୍ଟୁଲ୍ସ → ନେଟୱର୍କ** ଖୋଲନ୍ତୁ, ପୃଷ୍ଠାକୁ ରିଫ୍ରେଶ୍ କରନ୍ତୁ ଏବଂ ଯେକୌଣସି `/api` ଅନୁରୋଧ ଉପରେ କ୍ଲିକ୍ କରନ୍ତୁ।
3. **ଅନୁରୋଧ ହେଡର୍ଗୁଡ଼ିକ**ରେ, ସମ୍ପୂର୍ଣ୍ଣ `Cookie` ହେଡର୍ ମୂଲ୍ୟକୁ କପି କରନ୍ତୁ।
4. OmniRouteରେ, **ପ୍ରଦାନକାରୀ → ପ୍ରଦାନକାରୀ ଯୋଡ଼ନ୍ତୁ → NoTrack Web (ମାଗଣା)**କୁ ଯାଆନ୍ତୁ।
5. କୁକି ଷ୍ଟ୍ରିଙ୍ଗ୍କୁ `apiKey` ଫିଲ୍ଡରେ ପେଷ୍ଟ୍ କରି **ସେଭ୍** କରନ୍ତୁ।

OmniRoute ପେଷ୍ଟ୍ କରାଯାଇଥିବା ଷ୍ଟ୍ରିଙ୍ଗ୍ରୁ `uid`, `si_usr_id`, ଏବଂ `si_ses_id` ବାହାର କରେ ଏବଂ କେବଳ ସେହି ଯୋଡ଼ିଗୁଡ଼ିକ ସହିତ ଏକ ସ୍ୱଚ୍ଛ `Cookie` ହେଡର୍ ପୁନଃନିର୍ମାଣ କରେ — ଏଥିସହିତ, ଉପଲବ୍ଧ ଥିଲେ `nt_session` (ଲଗ୍-ଇନ୍ ହୋଇଥିବା ଆକାଉଣ୍ଟଗୁଡ଼ିକ ପାଇଁ ସେଟ୍ କରାଯାଇଥିବା `ntk_…` ଟୋକନ୍) ମଧ୍ୟ ଯୋଡ଼ାଯାଏ। ଏହି ତିନୋଟି ମଧ୍ୟରୁ କୌଣସିଟି ନଥିଲେ, ଅପରେଟର୍ମାନେ ବିକଳ୍ପ ଗଠନ ସହିତ ପରୀକ୍ଷା କରିପାରିବା ପାଇଁ ପେଷ୍ଟ୍ କରାଯାଇଥିବା ମୂଳ ଷ୍ଟ୍ରିଙ୍ଗ୍କୁ କୌଣସି ପରିବର୍ତ୍ତନ ବିନା ଫରୱାର୍ଡ କରାଯାଏ।

### କ୍ଷମତାଗୁଡ଼ିକ

- **ଷ୍ଟ୍ରିମିଂ ଏବଂ ନନ୍-ଷ୍ଟ୍ରିମିଂ** ଚାଟ୍ ସମ୍ପୂର୍ଣ୍ଣତା।
- **ଟୁଲ୍ କଲିଂ** — ଅନୁରୋଧରେ `tools: [...]` ସେଟ୍ କରନ୍ତୁ; ନିଷ୍ପାଦକ ସେଗୁଡ଼ିକୁ ଏକ ଟୁଲ୍-କଲ୍ ଏନଭେଲପ୍ ଚୁକ୍ତିରେ ସିରିଆଲାଇଜ୍ କରେ ଏବଂ ମଡେଲ୍ର ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକୁ ପାର୍ସ କରି ପୁଣି OpenAI `tool_calls`ରେ ପରିଣତ କରେ।
- **`response_format`** — `json_object` ଏବଂ `json_schema` ସମର୍ଥିତ। ନିଷ୍ପାଦକ ମଡେଲ୍ର ଉତ୍ତରରୁ ପ୍ରଥମ JSON ଅବଜେକ୍ଟକୁ ବାହାର କରେ ଏବଂ ଫେରାଇବା ପୂର୍ବରୁ ତାହାକୁ ଷ୍ଟ୍ରିଙ୍ଗ୍ରେ ପରିଣତ କରେ।
- **ରିଜନିଂ ସଙ୍କେତ** — ଅପସ୍ଟ୍ରିମ୍ ଏକ `thinking` ଇଭେଣ୍ଟ ପଠାଇଲେ, ନିଷ୍ପାଦକ ଏକ `reasoning` ଡେଲ୍ଟା ନିର୍ଗତ କରେ।

### ସୀମାବଦ୍ଧତାଗୁଡ଼ିକ

- ଅପସ୍ଟ୍ରିମ୍ ଅଜ୍ଞାତ ବ୍ୟବହାର କୋଟା ଲାଗୁ କରେ — ଏହି ସୀମା ଅତିକ୍ରମ ହେଲେ, ନିଷ୍ପାଦକ ଏକ ବ୍ୟବହାରକାରୀ-ଅନୁକୂଳ ସନ୍ଦେଶ ସହିତ 429 ପ୍ରଦର୍ଶନ କରେ।
- ସମସ୍ତ ମଡେଲ୍ ଆଇଡି ସମାନ ଅପସ୍ଟ୍ରିମ୍ ଡିସ୍ପାଚ୍ ମଡେଲ୍କୁ ନିର୍ଦ୍ଦେଶ କରେ; ପ୍ରତ୍ୟେକ ମଡେଲ୍ ପାଇଁ ଅଲଗା ସ୍ୱିଚ୍ ନାହିଁ।
- ନିଷ୍ପାଦକ ଅପସ୍ଟ୍ରିମ୍ର `/api/chats` ଏଣ୍ଡପଏଣ୍ଟକୁ କଲ୍ କରେ ନାହିଁ, ତେଣୁ ଚାଟ୍ ଇତିହାସ / ସେସନ୍ଗୁଡ଼ିକ ସ୍ୱୟଂଚାଳିତ ଭାବେ ପରିଚାଳିତ ହୁଏ ନାହିଁ। ଏକ ବିଦ୍ୟମାନ ଅପସ୍ଟ୍ରିମ୍ ଚାଟ୍ ପୁନଃଆରମ୍ଭ କରିବାକୁ `notrack_chat_id` ବ୍ୟବହାର କରନ୍ତୁ।

# ୱେବ୍ କୁକି ପ୍ରଦାନକାରୀମାନେ କ’ଣ କରିପାରନ୍ତି ଏବଂ କ’ଣ କରିପାରନ୍ତି ନାହିଁ

ୱେବ୍ କୁକି ପ୍ରଦାନକାରୀମାନେ ଏକ ୱେବସାଇଟ୍ର ଚାଟ୍ ଇଣ୍ଟରଫେସ୍କୁ ପୁନଃବ୍ୟବହାର କରନ୍ତି। ସେମାନେ ଆଧିକାରିକ APIଗୁଡ଼ିକ ପରି ସମାନ କ୍ଷମତା **ପ୍ରଦାନ କରନ୍ତି ନାହିଁ**।

## ସମର୍ଥିତ

- ଆପଣଙ୍କ ବର୍ତ୍ତମାନର ବ୍ରାଉଜର୍ ସେସନ୍ ବ୍ୟବହାର କରି ପ୍ରାମାଣିକରଣ କରନ୍ତୁ
- ଆପଣଙ୍କ ଆକାଉଣ୍ଟ ମାଧ୍ୟମରେ ଉପଲବ୍ଧ ମଡେଲ୍ଗୁଡ଼ିକୁ ଆକ୍ସେସ୍ କରନ୍ତୁ
- ଚାଟ୍ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକୁ ଷ୍ଟ୍ରିମ୍ କରନ୍ତୁ
- API କୀ ଆବଶ୍ୟକ ନାହିଁ

## ସମର୍ଥିତ ନୁହେଁ

- ଫଙ୍କସନ୍ କଲିଂ
- ଟୁଲ୍ କଲିଂ
- ସ୍ୱୟଂଚାଳିତ ଫାଇଲ୍ ସମ୍ପାଦନା
- ଏଜେଣ୍ଟିକ୍ IDE କାର୍ଯ୍ୟପ୍ରବାହ
- କେବଳ APIରେ ଉପଲବ୍ଧ ବୈଶିଷ୍ଟ୍ୟଗୁଡ଼ିକ

ଏହା ଆଶାକରାଯାଇଥିବା ଆଚରଣ ଏବଂ ଏହା **କୌଣସି** ବଗ୍ ନୁହେଁ।

ଯଦି ଆପଣଙ୍କୁ ଟୁଲ୍ ନିଷ୍ପାଦନ, ସ୍ୱୟଂଚାଳିତ ଫାଇଲ୍ ସମ୍ପାଦନା କିମ୍ବା ଅନ୍ୟ ଏଜେଣ୍ଟ କାର୍ଯ୍ୟପ୍ରବାହ ଆବଶ୍ୟକ ହୁଏ, ତେବେ Web Cookie ପ୍ରଦାନକାରୀ ପରିବର୍ତ୍ତେ ଏକ **API-key provider** ବ୍ୟବହାର କରନ୍ତୁ।

ଏକ ସଫଳ **Test Connection** କିମ୍ବା କୁକି ବୈଧତା ଯାଞ୍ଚ କେବଳ ଏତିକି ନିଶ୍ଚିତ କରେ ଯେ ଦିଆଯାଇଥିବା ପରିଚୟପତ୍ରଗୁଡ଼ିକ ଆଶାକରାଯାଇଥିବା ଫର୍ମାଟ୍ରେ ଥିବା ପରି ଦେଖାଯାଉଛି।

Issue #7857 ସମାଧାନ ନହେବା ପର୍ଯ୍ୟନ୍ତ, ଏକ ସଫଳ ବୈଧତା ଯାଞ୍ଚ ପ୍ରଦାନକାରୀ ସଫଳତାର ସହ ପ୍ରାମାଣିକରଣ କରିବେ ବୋଲି **ନିଶ୍ଚିତ କରେ ନାହିଁ**।

ଯଦି ପ୍ରାମାଣିକରଣ ତଥାପି ବିଫଳ ହୁଏ, ତେବେ ଯାଞ୍ଚ କରନ୍ତୁ ଯେ ଆପଣ ପରିଚୟପତ୍ରଗୁଡ଼ିକୁ ବ୍ରାଉଜର୍ କୁକି ଷ୍ଟୋରେଜ୍ ପରିବର୍ତ୍ତେ ଏକ ସକ୍ରିୟ ନେଟୱର୍କ ଅନୁରୋଧରୁ କପି କରିଛନ୍ତି।

# ସମସ୍ୟା ସମାଧାନ

## ପ୍ରାମାଣିକରଣ ବିଫଳ ହେଉଛି

ଯାଞ୍ଚ କରନ୍ତୁ ଯେ ପରିଚୟପତ୍ରଗୁଡ଼ିକ ଏଠାରୁ କପି କରାଯାଇଥିଲା:

```
ନେଟୱର୍କ
→ ଅନୁରୋଧ ହେଡର୍ଗୁଡ଼ିକ
→ କୁକି
```

ଏବଂ ଏଠାରୁ **ନୁହେଁ**:

```
ଆପ୍ଲିକେସନ୍
→ କୁକିଗୁଡ଼ିକ
```

## ସେସନ୍ର ଅବଧି ସମାପ୍ତ ହୋଇଛି

Web Cookie ପ୍ରଦାନକାରୀମାନେ ଆପଣଙ୍କ ବର୍ତ୍ତମାନର ବ୍ରାଉଜର୍ ସେସନ୍ ବ୍ୟବହାର କରନ୍ତି।

ଯଦି ଆପଣଙ୍କ ବ୍ରାଉଜର୍ ସେସନ୍ର ଅବଧି ସମାପ୍ତ ହୁଏ କିମ୍ବା ଆପଣ ସାଇନ୍ ଆଉଟ୍ କରନ୍ତି, ତେବେ ଆପଣଙ୍କୁ ଏକ ନୂତନ ପରିଚୟପତ୍ର ସେଟ୍ କପି କରିବାକୁ ପଡ଼ିବ। ସମର୍ଥିତ ୱେବ୍ ପ୍ରଦାନକାରୀମାନଙ୍କ ପାଇଁ କୁକି ନବୀକରଣ ସ୍ୱୟଂଚାଳିତ କରିବାକୁ, ସହାୟକ ଟୁଲ୍ [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) ଦେଖନ୍ତୁ।

## "Unsupported ChatGPT integrity dependency" ସହିତ ChatGPT Web ବିଫଳ ହେଉଛି

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

ପରିଚୟପତ୍ରଟି ଠିକ୍ ଅଛି — ସେହି ତ୍ରୁଟିଟି ସେସନ୍ରୁ ନୁହେଁ, ବ୍ରିଜ୍ରୁ ଆସୁଛି। chatgpt.com ପ୍ରତ୍ୟେକ ଡିପ୍ଲୟମେଣ୍ଟ ପାଇଁ ଏହାର
ମଡ୍ୟୁଲ୍ IDଗୁଡ଼ିକ ନିର୍ଦ୍ଧାରଣ କରେ, ଏବଂ ବ୍ରିଜ୍ ପୂର୍ବରୁ ଏହା ଇନ୍ଷ୍ଟାନ୍ସିଏଟ୍ କରୁଥିବା Sentinel ସହାୟକର IDକୁ ପିନ୍ କରୁଥିଲା, ତେଣୁ
ସହାୟକର ନାମ ପରିବର୍ତ୍ତନ କରିଥିବା ଏକ chatgpt.com ପୁନଃବିଲ୍ଡ କୁକି ବୈଧ ଥିବା ସତ୍ତ୍ୱେ ପ୍ରତ୍ୟେକ ଟର୍ନ୍କୁ ଭାଙ୍ଗି ଦେଇଥିଲା। ସଂଯୋଗକୁ ପୁନଃପ୍ରାଧିକୃତ କରିବା
ଦ୍ୱାରା ଏହାକୁ ଠିକ୍ କରାଯାଇପାରିବ ନାହିଁ।

ପୃଷ୍ଠାର ନିଜସ୍ୱ ରନ୍ଟାଇମ୍ ମାଧ୍ୟମରେ ମଡ୍ୟୁଲ୍କୁ ସମାଧାନ କରୁଥିବା ବିଲ୍ଡଗୁଡ଼ିକ କୌଣସି ID ପିନ୍ କରନ୍ତି ନାହିଁ ଏବଂ ଏହି ସମସ୍ୟାର ସମ୍ମୁଖୀନ ହୁଅନ୍ତି ନାହିଁ। ଯଦି ଆପଣ
ଏହି ତ୍ରୁଟି ଦେଖନ୍ତି, OmniRoute ଅପ୍ଗ୍ରେଡ୍ କରନ୍ତୁ ଏବଂ ସଂଯୋଗ ଯାଞ୍ଚ ପୁଣି ଚଲାନ୍ତୁ।

# ସର୍ବୋତ୍ତମ ଅଭ୍ୟାସ

- ଏକ ନୂତନ ପ୍ରାମାଣିକୃତ ଅନୁରୋଧରୁ ପରିଚୟପତ୍ରଗୁଡ଼ିକୁ କପି କରନ୍ତୁ।
- ପୁରୁଣା କୁକିଗୁଡ଼ିକୁ ପୁନଃବ୍ୟବହାର କରିବାରୁ ବିରତ ରୁହନ୍ତୁ।
- Web Cookie ପ୍ରଦାନକାରୀ ବ୍ୟବହାର କରିବା ସମୟରେ ଆପଣଙ୍କ ବ୍ରାଉଜର୍ ସେସନ୍କୁ ସକ୍ରିୟ ରଖନ୍ତୁ।
- କପି କରାଯାଇଥିବା କୁକିଗୁଡ଼ିକୁ ସମ୍ବେଦନଶୀଳ ପରିଚୟପତ୍ର ଭାବେ ବିବେଚନା କରନ୍ତୁ।
- ଯେତେବେଳେ ଆପଣଙ୍କୁ ଫଙ୍କସନ୍ କଲିଂ କିମ୍ବା ଏଜେଣ୍ଟ କାର୍ଯ୍ୟପ୍ରବାହ ଆବଶ୍ୟକ ହୁଏ, API-key ପ୍ରଦାନକାରୀ ବ୍ୟବହାର କରନ୍ତୁ।
