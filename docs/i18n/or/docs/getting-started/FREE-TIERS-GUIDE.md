> **TL;DR** : ଆପଣଙ୍କର ନିଜର ଯୋଗ୍ୟ ପ୍ରଦାନକାରୀ ଖାତା ଆଣନ୍ତୁ। OmniRoute ଆପଣ ବିନ୍ୟାସ କରୁଥିବା ସଂଯୋଗଗୁଡ଼ିକୁ ଏକତ୍ର କରିଥାଏ; ଏହା ବିଜ୍ଞାପନିତ ଏଗ୍ରିଗେଟ୍ ଟୋକେନ୍ ବଜେଟ୍ ପ୍ରଦାନ କରେ ନାହିଁ। ମାଗଣା ପ୍ରବେଶ ସାଇନଅପ୍, ଏକ API କି, ଅନୁମୋଦନ କିମ୍ବା ଏକ ଦେୟ ପଦ୍ଧତି ଆବଶ୍ୟକ କରିପାରିବ। ପ୍ରଦାନକାରୀ ସୀମା, ଗୋପନୀୟତା ନୀତି, ଏବଂ ସର୍ତ୍ତାବଳୀ ଏପର୍ଯ୍ୟନ୍ତ ପ୍ରଯୁଜ୍ୟ।

## ମାଗଣା ସ୍ତରଗୁଡିକ କ’ଣ?

ଅନେକ AI ପ୍ରଦାନକାରୀ କିଛି ଫର୍ମ ପ୍ରଦାନ କରନ୍ତି।** ମାଗଣା ପ୍ରବେଶ** । ପ୍ରଦାନକାରୀ ଉପରେ ନିର୍ଭର କରି, ଏହାର ଅର୍ଥ ଏକ ନୋ-ଏଥ୍ ଏଣ୍ଡପଏଣ୍ଟ, ବାରମ୍ବାର କୋଟା, ହାର-ସୀମିତ ଅନ୍-କ୍ୟାପ୍ ଆକ୍ସେସ୍, ଏକ ସାଇନ୍ ଅପ୍ ଅନୁଦାନ, ମାନୁଆଲ୍ ଅନୁମୋଦନ କିମ୍ବା ଏକ ଅସ୍ଥାୟୀ ପଦୋନ୍ନତି ହୋଇପାରେ। କିଛି ବିକଳ୍ପ ଏକ ଆକାଉଣ୍ଟ୍, API କି, କ୍ରେଡିଟ୍ କାର୍ଡ, KYC, କିମ୍ବା ପ୍ରଦାନକାରୀ-ନିର୍ଦ୍ଦିଷ୍ଟ ସର୍ତ୍ତାବଳୀ ଗ୍ରହଣ କରିବା ଆବଶ୍ୟକ କରେ।

OmniRoute** ଏଗ୍ରିଗେଟ୍ସ** ଗୋଟିଏ ଶେଷ ପଏଣ୍ଟରେ ସଂଯୋଗଗୁଡ଼ିକୁ ବିନ୍ୟାସ କରାଯାଇଛି। ଆପଣ ତଥାପି ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ ପୃଥକ ଭାବରେ ସାଇନ୍ ଅପ୍ କରନ୍ତି ଯାହା ଏକ ଆକାଉଣ୍ଟ୍ ଆବଶ୍ୟକ କରେ। ସେହି ଖାତାଗୁଡ଼ିକୁ ସଂଯୋଗ କରନ୍ତୁ ଏବଂ ଯୋଗ୍ୟ ଲକ୍ଷ୍ୟଗୁଡିକ ମଧ୍ୟରେ ମାର୍ଗ କରିବାକୁ `model: "auto"` ବ୍ୟବହାର କରନ୍ତୁ। ଏକ ନୂତନ ସଂସ୍ଥାପନରେ କ able ଣସି ଯୋଗ୍ୟ ଚାବିହୀନ ଲକ୍ଷ୍ୟ ରହିପାରିବ ନାହିଁ; କେବଳ OmniRoute ସଂସ୍ଥାପନ କରିବା ଏକ ସଫଳ ଚାଟ୍ ପ୍ରତିକ୍ରିୟାକୁ ଗ୍ୟାରେଣ୍ଟି ଦିଏ ନାହିଁ।

## ମାଗଣା ସ୍ତରଗୁଡିକ କିପରି ଷ୍ଟକ୍ କରିବେ।

କାଟାଲଗ୍ ବ୍ରାଉଜ୍ କରନ୍ତୁ ଏବଂ ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀଙ୍କ ସାମ୍ପ୍ରତିକ `hasFree`, auth, କୋଟା, ଗୋପନୀୟତା, ଏବଂ ToS ମେଟାଡାଟା ଯାଞ୍ଚ କରନ୍ତୁ। ପ୍ରଦାନକାରୀ କାର୍ଡ ଏବଂ [ମାଗଣା ଟାୟାର ରେଫରେନ୍ସ](../reference/FREE_TIERS.md) ବାରମ୍ବାର ପୁଲ, uncapped/keyless ଆକ୍ସେସ୍, ସାଇନ୍ ଅପ୍ କ୍ରେଡିଟ୍, ବନ୍ଦ ହୋଇଥିବା ଏଣ୍ଟ୍ରି ଏବଂ ଅଧିକ ବିପଦ ଉତ୍ସକୁ ପୃଥକ କରେ।

### ପଦାଙ୍କ 5: ସଂଯୋଗ କ୍ଲିକ୍ କରନ୍ତୁ।

ଏକ `NOAUTH` ପ୍ରଦାନକାରୀ ପାଇଁ, OmniRoute ଏକ ଅପଷ୍ଟ୍ରିମ ପରିଚୟ ପତ୍ର ଅନୁରୋଧ କରେ ନାହିଁ। ଏହା ଗ୍ୟାରେଣ୍ଟି ଦିଏ ନାହିଁ ଯେ ଅପଷ୍ଟ୍ରିମ୍ ତୃତୀୟ-ପକ୍ଷ ଗ୍ରାହକମାନଙ୍କୁ ଗ୍ରହଣ କରେ କିମ୍ବା ଉପଲବ୍ଧ କ୍ଷମତା ଅଛି। OAuth ଏବଂ API- କି ପ୍ରଦାନକାରୀ ନିଶ୍ଚିତ ଭାବରେ ସେମାନଙ୍କର ଡକ୍ୟୁମେଣ୍ଟ୍ ଆକାଉଣ୍ଟ୍ ଫ୍ଲୋ ମାଧ୍ୟମରେ ସଂଯୁକ୍ତ ହେବା ଆବଶ୍ୟକ। ଆପଣଙ୍କର କ୍ଲାଏଣ୍ଟ ଏପର୍ଯ୍ୟନ୍ତ ସୃଷ୍ଟି ହୋଇଥିବା ଏକ OmniRoute API କି ବ୍ୟବହାର କରେ।** ଡ୍ୟାସବୋର୍ଡ → API କିଗୁଡ଼ିକ।** (ସୃଷ୍ଟିରେ କେବଳ ଥରେ ଦେଖାଯାଏ) ଯେତେବେଳେ ରାଉଟର ପ୍ରାମାଣିକିକରଣ ସକ୍ଷମ ହୁଏ।

**OpenCode** ପ୍ଲଗଇନ୍ ର ମାଗଣା ଗାଡ଼ି ହେଉଛି OpenCode ର କି-ମୁକ୍ତ ଅଫର୍। OmniRoute ମାଗଣା ଅଫର୍ ଭାବରେ ସେହି ଅଫର୍ ପ୍ରଦାନ କରେ ନାହିଁ:

- OmniRoute ର ଚାବିହୀନ OpenCode ପ୍ରଦାନକାରୀ OpenCode ର ଅପରେଟରଙ୍କ ଅନୁରୋଧ କ୍ରମେ ଅପସାରିତ ହୋଇଛି ( [ଅପସାରଣକାରୀ ପ୍ରଦାନକାରୀଙ୍କୁ](../reference/REMOVED_PROVIDERS.md) ଦେଖନ୍ତୁ)।
- OpenCode ର [ଏଣ୍ଡପଏଣ୍ଟ ଡକ୍ୟୁମେଣ୍ଟେସନ୍](https://opencode.ai/v2/docs/console/models/#endpoints) ଏହାର ମାଗଣା ଚାଟ୍ ଅଫର୍ OpenCode ର ନିଜ କ୍ଲାଏଣ୍ଟ ସହିତ ବାନ୍ଧିଥାଏ, ତେଣୁ OmniRoute ସେଗୁଡ଼ିକୁ ମାଗଣା ଭାବରେ ଗଣନା କରେ ନାହିଁ କିମ୍ବା ବ୍ୟାଜ୍ କରେ ନାହିଁ।

ମଡେଲ୍ id ପ୍ଲଗଇନ୍ ଶୋ, ଯେପରିକି `deepseek-v4.1-flash-free`, `mimo-v2.6-flash-free` ଏବଂ `nemotron-3.5-lightning-free`, `opencode-zen` କାଟାଲଗ୍ ରେ ଅଛି। `opencode-zen` ଆପଣଙ୍କର OpenCode କି ସହିତ ଆପଣଙ୍କର OpenCode ଆକାଉଣ୍ଟ୍ ସର୍ତ୍ତାବଳୀରେ ବ୍ୟବହାର କରିବାକୁ ସଂଯୋଗ କରନ୍ତୁ।

**ପ୍ଲଗଇନ୍ ର ସ୍ଥାନୀୟ ପୋର୍ଟ।** ପ୍ଲଗଇନ୍ ଏହାର ମଡେଲଗୁଡିକୁ ଏକ ସ୍ଥାନୀୟ OpenAI- ସୁସଙ୍ଗତ ପୋର୍ଟ (ଡିଫଲ୍ଟ `18899`) ରେ ପ୍ରକାଶ କରିପାରିବ। ଯେକ Any ଣସି ଏଣ୍ଡପଏଣ୍ଟକୁ [କଷ୍ଟମ୍ OpenAI- ସୁସଙ୍ଗତ ପ୍ରଦାନକାରୀ](../guides/USER_GUIDE.md#custom-openai-compatible-providers) ଭାବରେ ଯୋଗ କରାଯାଇପାରିବ, କିନ୍ତୁ OmniRoute ପ୍ଲଗଇନ୍ ସଂସ୍ଥାପନ, ଆରମ୍ଭ କିମ୍ବା ଅଦ୍ୟତନ କରେ ନାହିଁ, ଏବଂ ପ୍ଲଗଇନ୍ ସ୍ଥିର କରେ କେଉଁ ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରତ୍ୟେକ ଅନୁରୋଧକୁ ସେବା କରେ। ଉପରୋକ୍ତ OpenCode ପ୍ରତିବନ୍ଧକ OpenCode ର ଅଫର୍ ପାଇଁ ପ୍ରଯୁଜ୍ୟ ଯାହାକି ଗ୍ରାହକ ଅନୁରୋଧ ପଠାନ୍ତି।

## ସଠିକ୍ ଭାବରେ କାଟାଲଗ୍ ପ Reading ିବା।

- `NOAUTH` ଅର୍ଥ ହେଉଛି OmniRoute ଆପଣଙ୍କୁ ଏକ ପ୍ରଦାନକାରୀ ପ୍ରମାଣପତ୍ର ମାଗେ ନାହିଁ; ଏହା ଅପଟାଇମ୍, ଗୋପନୀୟତା, କିମ୍ବା ଅସୀମିତ କ୍ଷମତାର ଗ୍ୟାରେଣ୍ଟି ଦିଏ ନାହିଁ।
- `hasFree` ହେଉଛି ଆବିଷ୍କାର ମେଟାଡାଟା। ଏହା ଏକ ବାରମ୍ବାର କୋଟା, ଚାବିହୀନ ପ୍ରବେଶ, ସାଇନ୍ ଅପ୍ କ୍ରେଡିଟ୍, ଅନୁମୋଦନ ପ୍ରୋଗ୍ରାମ, କିମ୍ବା ପଦୋନ୍ନତିକୁ ପ୍ରତିନିଧିତ୍ୱ କରିପାରିବ।
- `recurring-uncapped` ଅର୍ଥ କ published ଣସି ପ୍ରକାଶିତ ଟୋକନ୍ ଛାତ ଉପଲବ୍ଧ ନଥିଲା; ହାର ଏବଂ ସମାନତା ସୀମା ଏପର୍ଯ୍ୟନ୍ତ ପ୍ରଯୁଜ୍ୟ।
- ସାଇନ୍ ଅପ୍ ଅନୁଦାନ ଖାଇବା ପରେ`one-time-initial` ପୁନରାବୃତ୍ତି ହୁଏ ନାହିଁ।
- `tos: avoid` ପ୍ରଦାନକାରୀମାନେ ଡିଫଲ୍ଟ ଭାବରେ (`excludeTosAvoid`) ସ୍ୱୟଂଚାଳିତ ରାଉଟିଙ୍ଗରୁ ବାଦ ପଡିଛନ୍ତି। ଏକ ଆକାଉଣ୍ଟ୍ ସଂଯୋଗ କରିବା ଏହି ଫିଲ୍ଟରକୁ ବାଇପାସ୍ କରେ ନାହିଁ। ଯେକ Any ଣସି ଅପରେଟର୍ ନବଲିଖନକାରୀ ପ୍ରଦାନକାରୀ ସର୍ତ୍ତାବଳୀ ଏବଂ ଆକାଉଣ୍ଟ୍ ବିପଦର ସମୀକ୍ଷା କରିବା ଉଚିତ୍।
- `discontinued` ଚିହ୍ନିତ ଏଣ୍ଟ୍ରିଗୁଡିକ historical ତିହାସିକ ପ୍ରମାଣ ହୋଇ ରହିଥାଏ ଏବଂ ବର୍ତ୍ତମାନ ମୁକ୍ତ ଭାବରେ ଉପସ୍ଥାପିତ ହେବା ଉଚିତ୍ ନୁହେଁ।

## OmniRoute କିପରି ମାଗଣା ସ୍ତରଗୁଡିକ ଉନ୍ନତ କରେ।

### ସ୍ୱୟଂଚାଳିତ ଫଲବ୍ୟାକ୍।

ଯଦି ଗୋଟିଏ ମାଗଣା ପ୍ରଦାନକାରୀ ବ୍ୟସ୍ତ କିମ୍ବା ତଳ, OmniRoute ସ୍ୱୟଂଚାଳିତ ଭାବରେ ପରବର୍ତ୍ତୀକୁ ଚେଷ୍ଟା କରେ। ତୁମେ କିଛି କରିବା ଆବଶ୍ୟକ ନାହିଁ।

### ସ୍ମାର୍ଟ ରାଉଟିଙ୍ଗ୍।

OmniRoute ବାଛିଥାଏ।** ସର୍ବୋତ୍ତମ ମାଗଣା ପ୍ରଦାନକାରୀ।** ଉପରେ ଆଧାରିତ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ:

- ଗତି — ବର୍ତ୍ତମାନ କେଉଁ ପ୍ରଦାନକାରୀ ଦ୍ରୁତତମ?
- ଗୁଣବତ୍ତା — ଏହି କାର୍ଯ୍ୟ ପାଇଁ କେଉଁ ପ୍ରଦାନକାରୀ ସର୍ବୋତ୍ତମ?
- କ୍ଷମତା — କେଉଁ ପ୍ରଦାନକାରୀଙ୍କର କୋଟା ବାକି ଅଛି?

### 3 ଟୋକେନ୍ ସଞ୍ଚୟ।

OmniRoute ର ସଙ୍କୋଚନ ପାଇପଲାଇନ ଯୋଗ୍ୟ ପ୍ରମ୍ପ୍ଟ ଏବଂ ଟୁଲ୍-ଆଉଟପୁଟ୍ ଟୋକେନ୍ ହ୍ରାସ କରିପାରିବ। ପ୍ରକୃତ ସଞ୍ଚୟ ବିଷୟବସ୍ତୁ, ମନୋନୀତ ଇଞ୍ଜିନ୍, ପ୍ରଦାନକାରୀ ଆକାଉଣ୍ଟିଂ, ଏବଂ ବିଶ୍ୱସ୍ତତା ସେଟିଂ ଉପରେ ନିର୍ଭର କରେ। ସଙ୍କୋଚନ ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀ କୋଟାକୁ ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ ପରିମାଣରେ ଗୁଣନ କରେ ନାହିଁ।

### ମଲ୍ଟି ଆକାଉଣ୍ଟ୍ ସମର୍ଥନ।

ଯଦି ପ୍ରଦାନକାରୀ ସର୍ତ୍ତାବଳୀ ଏକାଧିକ ଆକାଉଣ୍ଟ୍ କିମ୍ବା ପରିଚୟପତ୍ରକୁ ଅନୁମତି ଦିଏ, OmniRoute ପ୍ରତ୍ୟେକ ସଂଯୋଗକୁ ଏକ ପୃଥକ ରାଉଟିଙ୍ଗ୍ ପ୍ରାର୍ଥୀ ଭାବରେ ବ୍ୟବହାର କରିପାରିବ। ଏକ ପ୍ରଦାନକାରୀଙ୍କ କୋଟା କିମ୍ବା ଆକ୍ସେସ୍ ପଲିସିରୁ ବଞ୍ଚିବା ପାଇଁ ଅତିରିକ୍ତ ଆକାଉଣ୍ଟ୍ ସୃଷ୍ଟି କରନ୍ତୁ ନାହିଁ।

## ସାଧାରଣ ପ୍ରଶ୍ନ।

### ଏହା ପ୍ରକୃତରେ ମାଗଣା କି?

କାଟାଲଗ୍ ରେକର୍ଡ ପ୍ରଦାନକାରୀ-ପ୍ରକାଶିତ ସର୍ତ୍ତାବଳୀ ଏବଂ ପ୍ରକଳ୍ପ ଅନୁସନ୍ଧାନ, କିନ୍ତୁ ଅଫରଗୁଡିକ ପରିବର୍ତ୍ତନ ହୋଇପାରେ। ପ୍ରଦାନକାରୀଙ୍କ ବର୍ତ୍ତମାନର ମୂଲ୍ୟ, କୋଟା, ଗୋପନୀୟତା ନୀତି, ଏବଂ ବ୍ୟବହାର ପୂର୍ବରୁ ଯୋଗ୍ୟତା ଯାଞ୍ଚ କରନ୍ତୁ।

### ମାଗଣା ପର୍ଯ୍ୟାୟ ଶେଷ ହେବ କି?

ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀ ହାର-ସୀମା, ମଡେଲ ପରିବର୍ତ୍ତନ କରିପାରିବେ, ପ୍ରବେଶ ସ୍ଥଗିତ କରିପାରିବେ କିମ୍ବା ଅଫଲାଇନରେ ଯାଇପାରିବେ। ଏକାଧିକ ସଂଯୋଗଗୁଡ଼ିକ ଫଲବ୍ୟାକ୍ କଭରେଜକୁ ଉନ୍ନତ କରିଥାଏ କିନ୍ତୁ ଏକ ଉପଲବ୍ଧ ମାଗଣା ମାର୍ଗକୁ ଗ୍ୟାରେଣ୍ଟି ଦିଏ ନାହିଁ।

### ମୁଁ ଉତ୍ପାଦନ ପାଇଁ ମାଗଣା ପ୍ରଦାନକାରୀ ବ୍ୟବହାର କରିପାରିବି କି?

କେବଳ ଯଦି ପ୍ରଦାନକାରୀଙ୍କ SLA, ଡାଟା ନିୟନ୍ତ୍ରଣ, ସୀମା, ଏବଂ ସର୍ତ୍ତାବଳୀ ଆପଣଙ୍କ ଉତ୍ପାଦନ ଆବଶ୍ୟକତା ପୂରଣ କରେ। ଗୁରୁତ୍ work ପୂର୍ଣ୍ଣ କାର୍ଯ୍ୟଭାର ଉପରେ ନଜର ରଖିବା ଉଚିତ୍, ଚୁକ୍ତିଭିତ୍ତିକ ଉପଯୁକ୍ତ ଫଲବ୍ୟାକ୍।

### "ଧରିବା କଣ?"

ଟ୍ରେଡ୍ ଅଫ୍ ଗୁଡିକରେ କଠୋର ସୀମା, ୱେଟଲିଷ୍ଟ, KYC, କ୍ରେଡିଟ୍-କାର୍ଡ ଯାଞ୍ଚ, ପ୍ରମ୍ପ୍ଟ ଉପରେ ତାଲିମ, ଦୁର୍ବଳ ଗୋପନୀୟତା, କ z ଣସି SLA, ମଡେଲ୍ ଚର୍ନ୍, ଭ ographic ଗୋଳିକ ପ୍ରତିବନ୍ଧକ, ପେଡ୍ ଓଭର, କିମ୍ବା ଆକାଉଣ୍ଟ-ପଲିସି ବିପଦ ଅନ୍ତର୍ଭୁକ୍ତ ହୋଇପାରେ। OmniRoute ଉପଲବ୍ଧ ମେଟାଡାଟା ପୃଷ୍ଠଗୁଡ଼ିକ; ଆପଣ କ’ଣ ସକ୍ଷମ କରିବେ ତାହା ବାଛନ୍ତୁ।

### ମୁଁ କିପରି ଅଧିକ ମାଗଣା କୋଟା ପାଇବି?

1. ଅଧିକ ମାଗଣା ପ୍ରଦାନକାରୀଙ୍କୁ ସଂଯୋଗ କରନ୍ତୁ।
2. ଉପଯୁକ୍ତ ସଙ୍କୋଚନ ଇଞ୍ଜିନ୍ ସକ୍ଷମ କରନ୍ତୁ ଏବଂ ଆପଣଙ୍କର କାର୍ଯ୍ୟଭାର ପାଇଁ ସଞ୍ଚୟ ମାପନ୍ତୁ।
3. free/cheap ପ୍ରଦାନକାରୀଙ୍କୁ ପ୍ରାଥମିକତା ଦେବା ପାଇଁ `auto/cheap` ବ୍ୟବହାର କରନ୍ତୁ।
4. ପ୍ରଦାନକାରୀ ସର୍ତ୍ତାବଳୀ ଉଲ୍ଲଂଘନ ନକରି ଅତିରିକ୍ତ ଅନୁମତି ପ୍ରାପ୍ତ ପ୍ରଦାନକାରୀ କିମ୍ବା ପରିଚୟପତ୍ର ଯୋଡନ୍ତୁ।

### ମାଗଣା ପ୍ରଦାନକାରୀଙ୍କର ଖରାପ ଗୁଣ ଅଛି କି?

ଅବଶ୍ୟ ନୁହେଁ। କେତେକ ପ୍ରଦାନକାରୀ ଦେୟଯୁକ୍ତ ମାର୍ଗ ମାଧ୍ୟମରେ ଉପଲବ୍ଧ ସମାନ ମଡେଲ ପରିବାରକୁ ପ୍ରକାଶ କରନ୍ତି, କିନ୍ତୁ ସୀମା, ବିଳମ୍ବ, ଗୋପନୀୟତା, ନିର୍ଭରଯୋଗ୍ୟତା, ଏବଂ ମଡେଲ ସଂସ୍କରଣ ଭିନ୍ନ ହୋଇପାରେ। ମାଗଣା ପ୍ରଦାନକାରୀ ର୍ୟାଙ୍କିଙ୍ଗ୍ ପୃଷ୍ଠାକୁ ଏକ ଗୁଣାତ୍ମକ ସଙ୍କେତ ଭାବରେ ବ୍ୟବହାର କରନ୍ତୁ ଏବଂ ପରିବେଷିତ ପ୍ରକୃତ ମଡେଲ୍ ଯାଞ୍ଚ କରନ୍ତୁ।
