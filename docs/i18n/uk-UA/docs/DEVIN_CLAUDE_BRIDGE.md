`devin-cli-agentic` дає змогу справжньому середовищу виконання Claude Code використовувати локальну
кінцеву точку Anthropic Messages від OmniRoute, тоді як офіційний Devin CLI надає відповіді моделі через ACP stdio. Він
не змінює наявні провайдери Anthropic, Claude OAuth, Claude Web або `devin-cli`.

Для викликів інструментів, якими керує клієнт, маршрутизуйте через `devin-cli-agentic` (псевдонім `dva`) —
провайдер із підтримкою інструментів у форматі Claude. Застарілий виконавець ACP `devin-cli` (`dv`)
підтримує лише текст: він запускає підсумовувач Devin без інструментів і не може повертати виклики інструментів. Його
метадані моделі позначено відповідним чином, тож комбінована маршрутизація, що вимагає інструментів, уникатиме його.

> **Поточний стан: закріплено Claude Code `2.1.258`; офлайн- і онлайн-перевірку востаннє зафіксовано
> на `2.1.220`.** Закріплена версія `2.1.220` успішно пройшла три ізольовані сценарії через Devin CLI
> `3000.2.17` і модель `swe-1-7-lightning`; цей фінальний онлайн-запуск підтвердив керовані клієнтом виклики `Read`,
> `Edit` і `Bash`, успішні результати `npm test`, виявлення команд і навичок проєкту,
> маршрутизацію виключно через Devin і нульовий вихідний трафік до Claude. Після цього закріплену версію було підвищено до `2.1.258`
> (покоління CLI, за яке видає себе ідентичність Claude в OmniRoute, і перша версія, що нативно постачається
> з рівнем Fable 5.1). На новій закріпленій версії було перевірено шар установлення та `claude --version`
> у закріпленому базовому образі, а набір модульних тестів мосту, `compose config` і
> статичне підтвердження ізоляції проходять успішно — однак офлайн-сценарій із макетом і онлайн-набір із трьох сценаріїв
> ще не запускалися повторно. Запустіть їх повторно (див. «Оновлення закріплених інструментів»), перш ніж покладатися на
> міст із цією закріпленою версією.

## Архітектура

```text
Claude Code 2.1.258 (ізольований Linux-контейнер без прав root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (формат Claude, провайдер без автентифікації)
  -> devin acp --agent-type summarizer (офіційний ACP stdio, без інструментів Devin)
  -> обліковий запис Devin у виділеному томі devin-auth
```

Стандартний ACP-агент офіційного CLI може виконувати власні інструменти, тому цей міст
його не використовує. Він запускає фіксованого ACP-агента `summarizer`, офіційний режим CLI якого не має інструментів, і
оформлює серіалізований запит Anthropic як трасу виконання. Коли потрібна інша дія, якою керує Claude,
відповідь має містити рівно одну клієнтську оболонку інструмента. Будь-які ACP
`tool_call` або `tool_call_update` відхиляються до того, як відповідь може бути позначена як
успішна.

Серіалізатор у `open-sse/executors/devin-agentic/serializer.ts` зберігає `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` та
інструменти, надані Claude Code. Зображення й невідомі блоки спричиняють явну помилку. Великі результати інструментів
містять видимий маркер обрізання.

Парсер приймає одну окрему оболонку `<tool>{...}</tool>` на кожен хід моделі. Він перевіряє
назву за списком інструментів у запиті, перевіряє аргументи за JSON Schema цього інструмента,
відхиляє змішування описового тексту та дій і допускає одну обмежену спробу виправлення. Потім Claude Code
локально виконує отриманий Anthropic `tool_use` і надсилає `tool_result` назад через
OmniRoute.

## Автоматична маршрутизація

Провайдер може входити до пулів кандидатів `auto/*` в OmniRoute, якщо його не заблоковано.
Допустимість кандидата не гарантує його вибір: стратегія маршрутизації комбінації (наприклад,
останній відомий робочий варіант) може віддати перевагу іншому провайдеру. Використовуйте `dva/<model>` або комбінацію з
пріоритетом Devin, якщо потрібно, щоб кожен запит проходив через Devin.

## Ізоляція та модель загроз

Встановлення, обліковий запис і конфігурація Claude на хості не входять до області розгляду та вважаються
забороненими. Сервіси Compose:

- працюють із UID/GID `10001:10001`, файловою системою кореневого рівня лише для читання, скинутими можливостями та
  `no-new-privileges`;
- використовують приватний `/home/bridge`, окремий том конфігурації Claude, ізольовані дані OmniRoute
  та окремий том `devin-auth`;
- монтують лише одноразові робочі простори/докази `.sandbox`;
- не монтують домашній каталог хоста, Keychain, облікові дані SSH і хмарних сервісів або сокет Docker;
- створюють явні середовища та видаляють змінні API/OAuth/маршрутизації Anthropic;
- спрямовують інференс Claude Code лише до `http://omniroute:20128` із ключем, призначеним лише для локального використання.

Офлайн-профіль використовує внутрішню мережу. У робочому профілі OmniRoute отримує доступ до
офіційних кінцевих точок Devin лише через `network-guard`; доступ до інших адрес заборонено.
Claude Code має окремий захист вихідного трафіку з повною забороною та може звертатися лише до локального сервісу OmniRoute
через `NO_PROXY`. Файли аудиту захисту монтуються лише відповідним процесом захисту.
Скрипти перевіряють власника файлу, режим, кількість посилань і кожне рішення перед експортом
доказів без токенів.

Запустіть перевірку ізоляції окремо:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Вона перевіряє топологію, іменовані монтування, налаштування запуску не від імені root і лише для читання, явну локальну маршрутизацію,
відсутність чутливих змінних середовища, відсутність сокета Docker, блокування доступу до
`api.anthropic.com` і `claude.ai`, вибір лише постачальника Devin та явне завершення з помилкою, коли
бекенд ACP недоступний.

## Початкове налаштування та звичайне використання

Зберіть закріплений образ:

```bash
./scripts/devin-bridge/build
```

Автентифікуйте лише ізольований том Devin:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Команда входу використовує офіційний процес із ручним токеном, призначений для віддалених/контейнерних
середовищ. Значення вводиться безпосередньо в запит CLI; воно не передається як
аргумент процесу, не записується в Git і не копіюється з хоста.

Запустіть ізольоване середовище виконання Claude Code:

```bash
./scripts/devin-bridge/launch
```

`launch` повторно перевіряє ізоляцію, автентифікацію Devin і виявлення моделей перед запуском
контейнеризованого Claude Code. Він ніколи не запускає виконуваний файл Claude із хоста. Псевдоніми моделей можна
встановити в `.env.devin-bridge`; кожне налаштоване значення має зберігати
префікс `devin-cli-agentic/`.

## Команди перевірки

Відтворюваний офлайн-сценарій не потребує облікового запису Devin і не використовує Інтернет під час виконання:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Робочий сценарій із автентифікацією, який запускається за явною згодою:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Засіб запуску робить паузи між сценаріями, щоб уникнути одночасного відкриття великої кількості сеансів ACP, і
перевіряє структуровані потокові події Claude замість того, щоб покладатися на текстові твердження. Його три
сценарії підтверджують:

1. безпосереднє читання проєкту й аналіз дефектів;
2. справжнє `Edit`, належне клієнту виконання `Bash` `npm test` і кінцевий результат;
3. `/bridge-check` разом із виявленням `bridge-proof`, читання проєкту, ще одне успішне
   належне клієнту виконання `npm test` і завершення без незакінченої роботи.

Фінальна контрольна перевірка також перевіряє аудит мережі Devin і вимагає, щоб аудит вихідного трафіку Claude
залишався порожнім.

## Оновлення закріплених інструментів

Образ закріплює версії Node, Claude Code і Devin CLI у
`docker/devin-bridge/Dockerfile`. Щоб оновити:

1. змініть явно вказані версії;
2. замініть контрольні суми архіву Devin для обох архітектур значеннями офіційного
   артефакту;
3. повторно зберіть образ і виконайте всі команди офлайн-перевірки;
4. підтвердьте версії всередині образу;
5. повторно запустіть автентифікований набір із трьох сценаріїв у реальному середовищі.

Не встановлюйте жоден із CLI глобально на хості та не замінюйте перевірку контрольної суми
неперевіреним завантаженням.

## Діагностика та очищення

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  показує локальну маршрутизацію та очищені від чутливих даних помилки виконавця.
- `.sandbox/evidence/mock-acp.jsonl` містить записи детермінованих дій макета ACP.
- `.sandbox/evidence/claude-stream.jsonl` містить записи реального офлайн-запуску Claude Code.
- `.sandbox/evidence/live-*.jsonl` містить записи трьох перевірених потоків у реальному середовищі.
- `.sandbox/evidence/egress.jsonl` і `.sandbox/evidence/claude-egress.jsonl` є перевіреними
  копіями аудитів захисту без токенів.

Зупиніть належні мосту контейнери та мережі, зберігши томи входу/config:

```bash
./scripts/devin-bridge/clean
```

Видаліть усе середовище, що належить мосту, включно з іменованими томами:

```bash
./scripts/devin-bridge/clean --all
```

## Обмеження

- Міст використовує фіксовану роль `summarizer` без інструментів, оскільки Devin CLI `3000.2.17`
  не надає нейтрального ACP-агента без інструментів. Адаптер компенсує проміжні відповіді,
  сформовані як підсумки, але одна обмежена спроба виправлення все одно може завершитися явною помилкою.
- Виклики ACP у реальному середовищі можуть повертати тимчасові відповіді `502`/`504`. Засіб тестування
  розділяє сценарії часовими інтервалами; у разі постійного збою система залишається закритою для відмов
  і ніколи не вибирає іншого постачальника.
- Контекст ACP відновлюється з кожного запиту Anthropic; прив’язка до процесу/сеансу
  відсутня.
- Для кожної відповіді моделі підтримується один виклик інструмента; паралельні виклики відхиляються.
- Зображення явно не підтримуються. Підтримка зору, виведення процесу міркування, керування зусиллями
  та контекстне вікно на 1M не заявлені.
- SSE використовує коректні події життєвого циклу Anthropic, але надсилається після завершення збору
  обмеженого ходу ACP; фрагменти ACP не пересилаються поступово.
