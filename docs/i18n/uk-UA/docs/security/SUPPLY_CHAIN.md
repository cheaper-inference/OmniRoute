OmniRoute публікує артефакти npm + Docker. Ці шлюзи забезпечують походження, інвентаризацію (SBOM) та сканування CVE, все це є відкритим вихідним кодом (OSS) і інтегровано в робочі процеси випуску.
**Консультативний підхід** — вони повідомляють зараз, а після першого успішного випуску підвищують до блокування.

| Шлюз                  | Інструмент                                     | Де                            | Блокує?                          | Вивід                                         |
| :-------------------- | :--------------------------------------------- | :---------------------------- | :------------------------------- | :-------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | лише якщо публікація не вдається | badge npmjs / `npm audit signatures`          |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | лише якщо генерація не вдається  | Релізний ресурс + артефакт                    |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | консультативний                  | Артефакт CycloneDX                            |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | консультативний                  | SARIF (ВИСОКИЙ+КРИТИЧНИЙ) → вкладка Безпека   |
| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **блокує**                       | `exit-code: '1'` при виправному КРИТИЧНОМУ    |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **блокує**                       | збільшує `metrics.vulnCount` (напрямок: вниз) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | консультативний                  | SARIF → Безпека + значок                      |

Механізм CVE для образів використовує **два кроки** у `docker-publish.yml`: крок SARIF (`HIGH,CRITICAL`, `exit-code: 0`) зберігає ВИСОКІ+КРИТИЧНІ вразливості видимими на вкладці Безпека без блокування; крок _CRITICAL gate_ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) призводить до збою випуску при КРИТИЧНІЙ CVE **з доступним виправленням**. `ignore-unfixed` запобігає блокуванню випуску для CVE базового образу без виправлення від постачальника.

## ⚠️ Варіативність CVE (блокує перевірки osv/Trivy)

osv і Trivy порівнюють залежності з базами даних CVE, які **постійно зростають**. PR,
який **не змінює жодних залежностей**, може раптово отримати червоний статус через
оприлюднення нового CVE в наявній залежності (osv: виміряне значення `vulnCount` >
базового рівня; Trivy: нова вразливість рівня CRITICAL із доступним виправленням
в образі). **Це ОЧІКУВАНА робоча поведінка блокувального шлюзу CVE, а не регресія
продукту.**

Якщо osv або Trivy отримує червоний статус через нещодавно оприлюднений CVE,
потрібно:

1. **Оновити відповідну залежність** (бажано) — перейти на виправлену версію через
   `package.json` `overrides` (для транзитивних залежностей) або повторно зібрати
   образ на основі виправленого базового образу.
2. **Якщо виправлення від розробників ще немає:**
   - **osv:** повторно встановити базове значення `metrics.vulnCount` у
     `config/quality/quality-baseline.json` (`npm run quality:ratchet -- --update`
     не охоплює спеціалізовані шлюзи — відредагуйте значення вручну,
     `direction:down`), додавши примітку з обґрунтуванням і посилання на задачу
     для відстеження.
   - **Trivy:** додати запис до `.trivyignore` (по одному CVE-ID на рядок),
     додавши коментар з обґрунтуванням і посилання на задачу для відстеження.
     `ignore-unfixed: true` уже автоматично охоплює CVE без доступних виправлень.

Обов’язкові запуски OSV (`check:vuln-ratchet -- --ratchet`) завершуються із
заборонним результатом `INCOMPLETE` і кодом виходу 2, якщо не вдається перевірити
сканер, звіт або базовий рівень. Виміряна регресія завершується з кодом виходу 1.
Рекомендаційний запуск усе ще може повідомити `SKIP` із кодом виходу 0, але це не
підтверджує, що залежності пройшли сканування. Блокувальний етап Trivy також
вимагає успішного вимірювання: недоступні інструменти, невдалі завдання та
відсутність підтверджень щодо образу не дають змоги засвідчити, що образ не
містить вразливостей.

## Ризик застарілої залежності

Кореневий lockfile більше не містить `extract-zip` або ребра залежності до нього після
оновлення закріпленої версії інструмента розробки promptfoo. Це усуває раніше прийнятий
ланцюжок `promptfoo` → `@openai/codex-security` → `extract-zip`, що відстежувався в #14482.
Регресійні перевірки в `tests/unit/extract-zip-14482-exposure.test.ts` запобігають його
повторному додаванню та зберігають заборону на імпортування з продуктивного коду.

Поточне виправлення залежностей також обмежує перевизначення сумісності клієнтом MSAL
служби ідентифікації Azure, FTP-клієнтом get-uri та залежністю Zod SDK OpenCode v1. Отримання
токенів Azure і завантаження через FTP тестуються з контрольованими транспортами; обидва
пакети OpenCode запускають власні набори збирання й тестування. Кількість рекомендацій
щодо безпеки в реєстрі є показником на певний момент часу та може змінитися після
фіксації lockfile.
