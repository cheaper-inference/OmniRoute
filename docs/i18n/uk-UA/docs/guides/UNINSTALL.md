## Повернути конфігурацію клієнта

Програма видалення зупиняє процес OmniRoute, керований PM2, якщо він присутній, і залишає конфігурацію клієнта на місці. Клієнти, які все ще вказують на OmniRoute втрачають з’єднання після його припинення. Повне видалення також видаляє каталог даних, `~/.omniroute` за замовчуванням, разом із резервними копіями конфігурації клієнта.

### 1. Використовуйте інформаційну панель під час роботи OmniRoute

ВІДЧИНЕНО** Код CLI** (`/dashboard/cli-code`) на інформаційній панелі та знайдіть** Код Claude** картку.** Застосувати** записує файл налаштувань коду Claude хоста OmniRoute, `~/.claude/settings.json` за замовчуванням. Якщо у вас є резервна копія до застосування налаштувань OmniRoute, відкрийте** Резервні копії** і відновити його. В іншому випадку виберіть** Скинути** щоб видалити налаштування шлюзу з `env`. Спершу застосуйте та скиньте резервну копію наявного файлу. Резервні копії зберігаються в `<DATA_DIR>/backups`.

Якщо `CLI_ALLOW_CONFIG_WRITES=false` або інформаційна панель недоступні, поверніть файл вручну. Якщо OmniRoute працює в Docker, а клієнт працює на хості, скасуйте конфігурацію хоста. Файли в розмонтованому домашньому контейнері не впливають на хост-клієнт.

### 2. Скасуйте решту змін вручну

Для коду Claude перевірте `~/.claude/settings.json`, `settings.json` у `CLAUDE_CONFIG_DIR` якщо встановлено, та `.claude/settings.json` проекту. Reset видаляє наступні ключі з `env`. Видаліть значення, які ви додали для OmniRoute або відновіть попередні значення.

- `"ANTHROPIC_BASE_URL"`, `"ANTHROPIC_AUTH_TOKEN"` і `"ANTHROPIC_API_KEY"`
- `"ANTHROPIC_DEFAULT_OPUS_MODEL"`, `"ANTHROPIC_DEFAULT_SONNET_MODEL"` і `"ANTHROPIC_DEFAULT_HAIKU_MODEL"`
- `"API_TIMEOUT_MS"`

Reset залишає `ANTHROPIC_MODEL` в `env` і налаштування верхнього рівня `model` і `apiKeyHelper` на місці. Видаліть або відновіть їх вручну, якщо вони вибрали модель OmniRoute або облікові дані. Припиніть використання будь-якого профілю OmniRoute, створеного `omniroute setup-claude` під `~/.claude/profiles/<name>/`, або поверніть його `settings.json`. Команда setup записує профіль без зміни файлу параметрів за замовчуванням або збереження маркера. Видаліть або відновіть відповідні експорти у файлах запуску оболонки та очистіть старі значення з поточної оболонки. `omniroute launch` і `omniroute run claude` встановлюють шлюз URL і маркер лише для дочірнього процесу.

Для Codex відновіть попередній постачальник і модель у `~/.codex/config.toml`, якщо він містить `model_provider = "omniroute"`. Видаліть `[model_providers.omniroute]` якщо він був доданий для цього шлюзу. Відновіть або видаліть `openai_base_url` якщо він вказує на OmniRoute. Для OpenAI-сумісних клієнтів відновіть або очистіть `OPENAI_BASE_URL` там, де ви встановили його для OmniRoute.

### 3. Переконайтеся, що клієнт працює з зупиненою OmniRoute

Перевірте налаштування коду Claude за замовчуванням і поточне середовище оболонки.

```bash
grep -n ANTHROPIC ~/.claude/settings.json
env | grep ANTHROPIC
```

Жодна перевірка не повинна показувати, `ANTHROPIC_BASE_URL` вказує на OmniRoute. Якщо ви використовуєте налаштування профілю або проекту, перевірте також ці файли. Коли OmniRoute зупинено та відновлено вашу звичайну автентифікацію, запустіть код Claude безпосередньо.

```bash
claude -p "say hello"
```

Код Claude має відповідати, використовуючи відновлену конфігурацію. Якщо він усе ще вказує на зупинений шлюз, запит завершується помилкою підключення.

## Швидке видалення (v3.6.2 +)

> Спочатку [відновіть конфігурацію клієнта](#revert-client-configuration), поки OmniRoute все ще працює.

OmniRoute надає два вбудовані сценарії для чистого видалення:

### Зберігайте свої дані

```bash
npm run uninstall
```

Це видаляє програму OmniRoute але** консерви** ваша база даних, конфігурації, ключі API і налаштування провайдера в `~/.omniroute/`. Використовуйте це, якщо плануєте перевстановити пізніше та хочете зберегти налаштування.

### Повне видалення

```bash
npm run uninstall:full
```

Це видаляє програму** і остаточно стирає** всі дані:

- База даних (`storage.sqlite`)
- Конфігурації провайдера та ключі API
- Резервне копіювання файлів
- Файли журналів
- Усі файли в каталозі `~/.omniroute/`

> ⚠️** УВАГА:** `npm run uninstall:full` необоротний. Усі ваші з’єднання з провайдерами, комбінації, ключі API та історію використання буде остаточно видалено.

## Ручне видалення

> Спочатку [відновіть конфігурацію клієнта](#revert-client-configuration), поки OmniRoute все ще працює.

### Глобальна інсталяція NPM

```bash
# Remove the global package
npm uninstall -g omniroute

# (Optional) Remove data directory
rm -rf ~/.omniroute
```

### Глобальна інсталяція pnpm

```bash
pnpm uninstall -g omniroute
rm -rf ~/.omniroute
```

### Docker

```bash
# Stop and remove the container
docker stop omniroute
docker rm omniroute

# Remove the volume (deletes all data)
docker volume rm omniroute-data

# (Optional) Remove the image
docker rmi cheaperinference/omniroute:latest
# Older installs pulled the legacy name:
docker rmi diegosouzapw/omniroute:latest
```

### Docker Створити

```bash
# Stop and remove containers
docker compose down

# Also remove volumes (deletes all data)
docker compose down -v
```

### Додаток Electron для робочого столу

**Windows:**

- Відкрийте `Settings → Apps → OmniRoute → Uninstall`
- Або запустіть програму видалення NSIS з каталогу встановлення

**macOS:**

- Перетягніть `OmniRoute.app` із `/Applications` у кошик
- Видалити дані: `rm -rf ~/Library/Application Support/omniroute`

**Linux:**

- Видаліть файл AppImage
- Видалити дані: `rm -rf ~/.omniroute`

### Встановлення вихідного коду (git clone)

```bash
# Remove the cloned directory
rm -rf /path/to/omniroute

# (Optional) Remove data directory
rm -rf ~/.omniroute
```

## Каталоги даних

За замовчуванням OmniRoute зберігає дані в таких розташуваннях:

| Платформа     | Шлях за замовчуванням          | Перевизначення                      |
| ------------- | ------------------------------ | ----------------------------------- |
| Linux         | `~/.omniroute/`                | змінна середовища `DATA_DIR`        |
| macOS         | `~/.omniroute/`                | змінна середовища `DATA_DIR`        |
| Windows       | `%APPDATA%/omniroute/`         | змінна середовища `DATA_DIR`        |
| Docker        | `/app/data/` (підключений том) | змінна середовища `DATA_DIR`        |
| Сумісні з XDG | `$XDG_CONFIG_HOME/omniroute/`  | змінна середовища `XDG_CONFIG_HOME` |

### Файли в каталозі даних

| Файл/каталог         | Опис                                                             |
| -------------------- | ---------------------------------------------------------------- |
| `storage.sqlite`     | Основна база даних (провайдери, комбінації, налаштування, ключі) |
| `storage.sqlite-wal` | Журнал випереджального запису SQLite (тимчасовий)                |
| `storage.sqlite-shm` | Спільна пам’ять SQLite (тимчасова)                               |
| `call_logs/`         | Архіви вмісту запитів                                            |
| `backups/`           | Автоматичні резервні копії бази даних                            |
| `log.txt`            | Застарілий журнал запитів (необов’язково)                        |

## Перевірка повного видалення

Після видалення переконайтеся, що жодних файлів не залишилося:

```bash
# Перевірка глобального пакета npm
npm list -g omniroute 2>/dev/null

# Перевірка каталогу даних
ls -la ~/.omniroute/ 2>/dev/null

# Перевірка запущених процесів
pgrep -f omniroute
```

Якщо якийсь процес усе ще запущено, зупиніть його:

```bash
pkill -f omniroute
```
