> **Коротко**: OmniRoute ранжує своїх **безкоштовних** провайдерів за якістю моделей, використовуючи **ELO-оцінки Arena AI
> (у стилі LMArena)**. Відкрийте сторінку **Рейтинг безкоштовних провайдерів** на
> панелі керування, щоб дізнатися, які безкоштовні провайдери пропонують найпотужніші моделі для вашого завдання —
> загалом або з фільтрацією за категоріями (програмування, перевірка, документація, налагодження).

---

## Що це таке

OmniRoute реєструє 376 провайдерів, зокрема 155 записів каталогу, позначених як **free/no-auth** (без автентифікації, безкоштовний тариф OAuth або безкоштовний тариф із API-ключем — див. [Посібник із безкоштовних тарифів](../getting-started/FREE-TIERS-GUIDE.md) та повний [каталог безкоштовних тарифів](../reference/FREE_TIERS.md)). Підвох у тому, що якість моделей у безкоштовних провайдерів надзвичайно різниться. Провайдер без автентифікації, який надає доступ до прогресивної моделі, набагато корисніший за того, що пропонує малу застарілу модель.

**Free Provider Rankings** відповідає на питання «**який безкоштовний провайдер дає мені найкращу модель?**», поєднуючи каталог кожного безкоштовного провайдера з **оцінками якості, зібраними спільнотою**, із **таблиці лідерів Arena AI** (ELO на основі людських уподобань — та сама ідея, що лежить в основі чат-арени LMArena). Далі провайдери ранжуються за силою своєї **найкращої безкоштовної моделі**.

Рейтинг обчислюється з трьох реальних джерел:

1. Списки безкоштовних провайдерів — `NOAUTH_PROVIDERS`, а також записи `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS`, позначені прапорцем `hasFree`
   (`src/shared/constants/providers.ts`).
2. Каталог моделей кожного провайдера з реєстру провайдерів
   (`open-sse/config/providerRegistry.ts`).
3. Оцінки відповідності завданням, отримані з ELO, які зберігаються в таблиці БД
   `model_intelligence` рушієм синхронізації Arena ELO (`src/lib/arenaEloSync.ts`).

Логіка об'єднання міститься в `src/lib/freeProviderRankings.ts`.

## Як отримати доступ

### Сторінка панелі керування

Відкрийте панель керування та перейдіть до розділу **Витрати → Рейтинг безкоштовних провайдерів** або відкрийте безпосередньо:

```
/dashboard/free-provider-rankings
```

На сторінці (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) відображаються:

- **Подіум із трьома лідерами** (🥇 🥈 🥉) серед безкоштовних провайдерів із найвищим рейтингом.
- Повна **таблиця рейтингу** зі стовпцями: **Місце**, **Провайдер**, **Найкраща модель**,
  **Оцінка**, **Середня оцінка**, **Моделі**, **Тип**.
- **Кнопки фільтрації за категоріями**: _Усі категорії_, _За замовчуванням_, _Програмування_, _Перевірка_,
  _Документація_, _Налагодження_.

Позначка **Тип** кожного провайдера вказує, у який спосіб він надається безкоштовно:

| Позначка | Значення                                              |
| -------- | ----------------------------------------------------- |
| `NOAUTH` | Завжди безкоштовно, облікові дані не потрібні         |
| `OAUTH`  | OAuth-провайдер із безкоштовним рівнем (`hasFree`)    |
| `APIKEY` | Провайдер API-ключа з безкоштовним рівнем (`hasFree`) |

Оцінки відображаються як зрозумілі людині позначення (наприклад, _Елітна_, _Відмінна_, _Дуже добра_,
_Добра_, _Середня_), а не як необроблені числа, оскільки базове значення є відносною
оцінкою якості в рейтингу, а не відсотком.

### Кінцева точка API

Сторінка використовує загальнодоступну кінцеву точку для читання
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

Параметри запиту (перевіряються за допомогою Zod):

| Параметр   | Тип    | Значення за замовчуванням | Примітки                                                                                                            |
| ---------- | ------ | ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `category` | string | (немає)                   | Одне зі значень: `default`, `coding`, `review`, `documentation`, `debugging`. Не вказуйте для об’єднаного рейтингу. |
| `limit`    | number | `50`                      | Обмежується діапазоном `1–100`.                                                                                     |

Структура відповіді:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` — це початкове значення Arena ELO; `score` — нормалізоване значення відповідності завданню
(див. нижче). Провайдери, які не мають оцінених моделей, не включаються до відповіді.

## Як обчислюються оцінки

### Джерело: таблиця лідерів Arena AI

Рушій синхронізації Arena ELO (`src/lib/arenaEloSync.ts`) отримує дві таблиці лідерів — `text`
та `code` — з API таблиці лідерів Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). Коли цей API не повертає
придатної таблиці, рушій перемикається на офіційний набір даних `lmarena-ai/leaderboard-dataset`
на сервері датасетів Hugging Face (`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` повертає `activeSource`, `lastError` та
`lastFailedAt`. Кожен запис таблиці лідерів містить назву моделі, постачальника, оцінку ELO
`score`, довірчий інтервал і кількість голосів.

Категорії таблиці лідерів відповідають категоріям завдань OmniRoute:

| Таблиця лідерів Arena | Категорії завдань OmniRoute                       |
| --------------------- | ------------------------------------------------- |
| `text`                | `default`, `review`, `documentation`, `debugging` |
| `code`                | `coding`                                          |

### Нормалізація (оцінка відповідності завданню)

Сирі значення ELO нормалізуються в межах кожної таблиці лідерів у **значення відповідності
завданню в діапазоні `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

Оцінка ніколи не досягає `0` або `1`, залишаючи запас для перевизначень користувача. Це поле
`score`, яке ви бачите у відповіді API, і підпис, що відображається на інформаційній панелі.

### Рівень довіри

Кожен запис отримує рівень довіри залежно від кількості голосів на Arena:

| Рівень довіри | Голоси  |
| ------------- | ------- |
| `high`        | ≥ 5,000 |
| `medium`      | ≥ 1,000 |
| `low`         | < 1,000 |

### Зберігання та актуальність

Нормалізовані записи записуються до таблиці БД `model_intelligence` зі значенням
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). Записи **застарівають через
7 днів**, тож постачальник, який припиняє синхронізацію, зрештою випадає з рейтингу, а не
продовжує показувати застарілі дані.

Синхронізація **увімкнена за замовчуванням**:

- Вона запускається один раз під час старту сервера, а далі — за періодичним таймером
  (`src/lib/arenaEloSync.ts`, підключено з `src/instrumentation-node.ts`).
- Вона **неблокувальна і ніколи не є фатальною** — якщо запит до зовнішнього джерела
  завершується невдачею, OmniRoute продовжує працювати, а рейтинги просто показують останні
  коректні дані (або порожній стан).

Дві змінні середовища керують нею (описані в
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| Змінна                    | Типове значення  | Призначення                                                     |
| ------------------------- | ---------------- | --------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`           | Установіть `false`, щоб відмовитися від вихідної синхронізації. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24 год) | Інтервал синхронізації в секундах.                              |

### Ручна синхронізація / статус / очищення

Для операторів доступний автентифікований керувальний ендпоінт із ручним керуванням
(`src/app/api/intelligence/sync/route.ts` — потребує автентифікації керування):

```
GET    /api/intelligence/sync          # поточний статус синхронізації (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # запустити синхронізацію вручну; тіло: { "dryRun": true } для попереднього перегляду без запису
DELETE /api/intelligence/sync          # очистити всі синхронізовані аналітичні записи arena_elo
```

Якщо сторінка рейтингів порожня, ручний виклик `POST /api/intelligence/sync` (або простий
перезапуск сервера) знову її заповнить.

### Зіставлення моделей із таблицею лідерів

Ідентифікатори моделей у реєстрі та назви моделей на Arena не завжди збігаються точно. Рейтинг
використовує гнучке зіставлення (`findMatchingIntelligence` у `src/lib/freeProviderRankings.ts`):

1. Точний збіг за нормалізованим ідентифікатором моделі.
2. Збіг після відсікання кінцевого суфікса версії (наприклад, `kimi-k2.6` → `kimi-k2`).
3. Префіксний збіг (назва моделі з таблиці лідерів є префіксом ідентифікатора в реєстрі).

На боці синхронізації відомі префікси постачальників (`anthropic/`, `openai/`, `google/`, …)
відсікаються, а невелика таблиця псевдонімів розгортає канонічні назви у варіанти, які OmniRoute
використовує внутрішньо, — тож моделі можна знайти під будь-якою назвою.

### Як визначається рейтинг постачальника

Для кожного безкоштовного постачальника рушій оцінює кожну модель у його каталозі, а потім:

- **Top Model** (найкраща модель) = модель постачальника з найвищою оцінкою.
- **Avg Score** (середня оцінка) = середнє значення оцінок усіх оцінених моделей цього постачальника.
- **Models** (моделі) = скільки моделей постачальника мають оцінку Arena.

Постачальники сортуються спочатку за **оцінкою найкращої моделі**, потім — за середньою оцінкою.
Це заохочує постачальника, який пропонує принаймні одну потужну безкоштовну модель.

## Використання для вибору безкоштовних провайдерів

1. **Виберіть правильну категорію.** Використовуйте фільтр **Coding** для агентних завдань і завдань із кодом або
   залиште **All Categories** / **Default** для загального спілкування. Один і той самий провайдер може
   мати різні позиції в різних категоріях, оскільки його найкраща модель відрізняється залежно від таблиці лідерів.
2. **Для налаштувань з одним провайдером віддавайте перевагу призерам.** Якщо ви хочете підключити лише одного або двох безкоштовних
   провайдерів, почніть із тих, що посідають найвищі місця у вашій категорії.
3. **Перевірте позначку Type.** Провайдери `NOAUTH` підключаються найшвидше (без
   облікових даних). Безкоштовні рівні `OAUTH` / `APIKEY` потребують швидкої реєстрації, але часто надають доступ до
   потужніших моделей. Інструкції з підключення див. у [Посібнику з безкоштовних рівнів](../getting-started/FREE-TIERS-GUIDE.md).
4. **Підключіть кілька провайдерів і дозвольте Auto-Combo зробити вибір.** Ті самі дані Arena ELO, на основі яких працює
   ця сторінка, також використовуються для **коефіцієнта відповідності завданню** механізму оцінювання Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`, порядок визначення:
   `user_override → arena_elo → models_dev_tier → static table`). Тож після підключення
   найкращих безкоштовних провайдерів маршрутизація з `model: "auto"` (наприклад, `auto/coding`) буде
   автоматично віддавати перевагу якіснішим безкоштовним моделям для кожного запиту. Повний опис оцінювання за 16 факторами див. у
   [Auto-Combo](../routing/AUTO-COMBO.md).
