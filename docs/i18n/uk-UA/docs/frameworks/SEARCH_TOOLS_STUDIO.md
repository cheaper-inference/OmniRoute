## Огляд

Search Tools Studio перетворює `/dashboard/search-tools` із базового середовища для експериментів із пошуком на
Studio із трьома вкладками, що об’єднує вебпошук, вебскрапінг і паралельне порівняння провайдерів.

```
┌ Інструменти пошуку ────────────────────────────────────────────────────┐
│ [🔍 Пошук] [📄 Скрапінг] [⚖ Порівняння]         142ms · $0.001  </>    │
│ ⓘ [Посібник із модальностей]                                           │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {вміст активної вкладки}                │ ─ Конфігурація              │
│                                          │ Провайдер [авто ∨]          │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (отримання)  │
│                                          │ Тип   [веб | новини]        │
│                                          │ Повна сторінка [ ] (скрапінг)│
│                                          │ Формат [md|текст|html]      │
│                                          │ Модель реранжування [∨]     │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## Вкладки

### Вкладка пошуку

Розвиває існуючий `SearchForm` + `ResultsPanel` + `RerankPanel` у вкладку:

- Результати запиту → (заголовок, URL, фрагмент, оцінка релевантності).
- Метадані постачальника на панелі конфігурації (вартість, квота, статус).
- Розділ зміни рейтингу: виберіть модель зміни рейтингу, змініть порядок результатів, покажіть `positionDelta`.
- Порожній стан із CTA якщо пошукові провайдери не налаштовано.
- Історія пошуку через `SearchHistory.tsx`.
- Виклики `POST /v1/search` (існуюча кінцева точка, без змін).

### Вкладка скребка

Нова вкладка для отримання вмісту з URL через `POST /v1/web/fetch` (створено в плані 05):

- Вхід: URL + повносторінковий перемикач селектор формату + (markdown / text / HTML).
- Надіслати → fetch → render `ScrapeResult.tsx`.
- `ScrapeResult` відтворює попередній перегляд уцінки + raw перемикач.
- Шапка: якщо тіло відповіді >** 256 KB** , UI показує `(truncated, view raw)` і відкриває raw у модальному режимі Monaco (D21).
- Панель метаданих: провайдер (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search), затримка, вартість, розмір відповіді, кількість посилань.
- Використовує гачок `useScrapeFetch.ts`.

### Порівняти табл

Запускає той самий query/URL до** 4 провайдера паралельно** (D22):

- Пліч-о-пліч стовпці для кожного постачальника.
- Метрики: затримка, вартість, кількість результатів, розмір відповіді.
- Розрахунок перекриття URL для пошуку (кількість спільних URLs порівняно з початковим результатом).
- Виклики `POST /v1/search` (пошук) або `POST /v1/web/fetch` (скрейп) для кожного провайдера.

## Панель конфігурації (спільна)

`SearchToolsConfigPane.tsx` — завжди видима, її можна згорнути.

| Поле                | Примітки                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------- |
| Провайдер           | Розкривний список зі значком статусу (налаштовано / відсутній / обмежено частоту запитів) |
| Тип                 | `web` або `news` (лише для пошуку)                                                        |
| Повна сторінка      | Перемикач для скрапінгу — отримує всю сторінку замість першого видимого вмісту            |
| Формат              | `markdown`, `text` або `html` (лише для скрапінгу)                                        |
| Модель реранжування | Необов’язкова модель для реранжування після пошуку                                        |
| Історія             | Згортаний розділ історії пошуку                                                           |

## SearchConceptCard

`SearchConceptCard.tsx` — завжди видимий згортний акордеон. Пояснює:

| Концепція             | Короткий опис                                                                   |
| --------------------- | ------------------------------------------------------------------------------- |
| **Пошук**             | Отримує список вебрезультатів (заголовок, URL, фрагмент, оцінка релевантності)  |
| **Скрапінг**          | Витягує повний вміст URL (markdown, текст або HTML)                             |
| **Порівняння**        | Виконує той самий запит у N провайдерів паралельно                              |
| **Переранжування**    | Змінює порядок результатів за допомогою LLM для підвищення релевантності запиту |
| **Авто (найдешевше)** | Автоматично вибирає найдешевшого доступного провайдера                          |

## Каталог постачальників

`ProviderCatalog.tsx` відкриває повний список провайдерів із `GET /api/search/providers` (розширений у F4, щоб включити провайдери вибірки):

| `kind` | `"search"` (24 провайдери) або `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search, parallel-search, keenable-search) |

Статус є** отримано під час запиту** перевіривши, чи існують облікові дані та чи всі ключі наразі перезаряджаються.

`codex-search` ( веб-пошук Codex ) не має власного ключа: він повторно використовує підключений обліковий запис Codex (ChatGPT), тому кожен пошук витрачає квоту підписки ChatGPT і займає приблизно 10–40 с. Він запускається, коли запит називає його; для автоматичного вибору потрібен прапор функції `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` (за умовчанням вимкнено).

## Експорт коду

`ExportCodeModal` (імпортований із Playground Studio) + `codeExport.ts` генерують
фрагменти curl / Python / TypeScript для викликів `/v1/search` і `/v1/web/fetch`.
Заповнювач ключа API — завжди `$OMNIROUTE_API_KEY` (D11, спільний із Playground Studio).

## Зміни серверної частини

Для цієї функції була потрібна лише одна зміна серверної частини:

### Розширений `GET /api/search/providers`

`src/app/api/search/providers/route.ts` було розширено до:

- Включіть кожного постачальника вибірки (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`, `keenable-search`) до масиву.
- Додайте `kind: "search" | "fetch"` до кожного елемента.
- Додайте `status: "configured" | "missing" | "rate_limited"` отриманий із поточного стану облікових даних.
- Зберігати зворотну сумісність — наявних полів (`id`, `name` тощо) без змін.

## Усунення несправностей

| Симптом                                                 | Причина                                     | Виправлення                                                                                                      |
| ------------------------------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| На вкладці Scrape відображається «endpoint недоступний» | `/v1/web/fetch` не підключено               | Переконайтеся, що план 05 об’єднано; перевірте наявність `src/app/api/v1/web/fetch/route.ts`                     |
| У каталозі провайдерів усі позначені як «відсутні»      | Облікові дані не налаштовано                | Додайте облікові дані в `/dashboard/providers`                                                                   |
| Вміст Scrape обрізано                                   | Розмір відповіді перевищує обмеження 256 КБ | Очікувана поведінка (D21). Скористайтеся кнопкою «переглянути необроблені дані», щоб побачити повний вміст       |
| На вкладці Compare відображаються лише 2 провайдери     | Активне обмеження частоти запитів           | Два або більше провайдерів можуть перебувати в режимі очікування — перевірте статус провайдерів на панелі Config |
| «Size» відображається в таблиці як необроблений ключ    | Відсутній ключ i18n                         | Переконайтеся, що `search.size` існує у файлі локалі; перебудуйте i18n                                           |
