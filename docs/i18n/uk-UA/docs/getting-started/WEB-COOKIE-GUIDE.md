Провайдери Web Cookie дають змогу OmniRoute використовувати сервіс ШІ через наявний сеанс браузера замість ключа API. Вони корисні, якщо ви вже маєте доступ до сервісу через його вебсайт і хочете, щоб OmniRoute використовував той самий автентифікований сеанс.

На відміну від провайдерів із ключем API, провайдери Web Cookie виконують автентифікацію за допомогою облікових даних, які ваш браузер надсилає вебсайту.

---

# Перш ніж почати

> **Важливо:** Завжди копіюйте облікові дані з **активного мережевого запиту**, а **не** зі сховища файлів cookie вашого браузера.

Багато проблем з автентифікацією виникають через копіювання файлів cookie з неправильного місця.

## Не копіюйте зі сховища файлів cookie

Більшість браузерів надають доступ до збережених файлів cookie через:

```
Інструменти розробника
→ Програма (або Сховище)
→ Файли cookie
```

Хоча ці файли cookie можуть виглядати правильними, вони можуть бути:

- застарілими
- неповними
- без файлів cookie, які надсилаються лише з автентифікованими запитами

Використання цих значень може спричинити помилки автентифікації, навіть якщо вони здаються дійсними.

## Копіюйте з активного запиту

Натомість використовуйте файли cookie з успішного запиту:

```
Інструменти розробника
→ Мережа
→ Оновіть сторінку
→ Відкрийте запит чату або розмови
→ Заголовки запиту
→ Cookie
```

Заголовок запиту `Cookie` містить точні автентифікаційні дані, які ваш браузер успішно використав.

Для більшості провайдерів Web Cookie саме це значення потрібно вставити в OmniRoute.

# Загальне налаштування

Процес налаштування однаковий для більшості провайдерів Web Cookie.

1. Увійдіть на вебсайт провайдера.
2. Відкрийте інструменти розробника браузера.
3. Відкрийте вкладку **Мережа**.
4. Оновіть сторінку.
5. Відкрийте автентифікований запит чату або розмови.
6. Скопіюйте необхідні облікові дані для автентифікації.
7. Відкрийте OmniRoute.
8. Перейдіть до **Провайдери → Додати провайдера**.
9. Виберіть свого провайдера Web Cookie.
10. Вставте облікові дані.
11. Натисніть **Перевірити з’єднання**.
12. Збережіть провайдера.

Точні необхідні облікові дані залежать від провайдера.

# Формати облікових даних провайдерів

Різні вебсайти зберігають автентифікаційні дані по-різному. Деяким потрібні лише файли cookie, тоді як іншим можуть знадобитися додаткові заголовки або токени.

| Провайдер                       | Формат облікових даних         | Посібник із провайдера           |
| ------------------------------- | ------------------------------ | -------------------------------- |
| Claude Web                      | Повний заголовок запиту Cookie | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | Повний заголовок Cookie        | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(перевірити)_                 |                                  |
| Copilot Web                     | _(перевірити)_                 | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath  | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(перевірити)_                 |                                  |
| ...                             | ...                            | ...                              |

> Оновлюйте цю таблицю, коли додаються нові провайдери Web Cookie або змінюються вимоги до автентифікації наявних провайдерів.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) — це безкоштовна споживча чат-платформа, яка не потребує реєстрації: сеанс створюється анонімно під час першого відвідування та зберігається за допомогою трьох файлів cookie: `uid`, `si_usr_id` і `si_ses_id`. OmniRoute проксіює ту саму кінцеву точку `/api/dispatch` через єдиний ідентифікатор моделі (`notrack-c`, псевдонім `ntw`).

### Кроки для підключення

1. Відкрийте [notrack.ai](https://notrack.ai) у браузері та дочекайтеся встановлення файлу cookie анонімного сеансу.
2. Відкрийте **Інструменти розробника → Мережа**, оновіть сторінку та натисніть будь-який запит `/api`.
3. У розділі **Заголовки запиту** скопіюйте повне значення заголовка `Cookie`.
4. В OmniRoute перейдіть до **Провайдери → Додати провайдера → NoTrack Web (безкоштовно)**.
5. Вставте рядок cookie в поле `apiKey` і натисніть **Зберегти**.

OmniRoute витягує `uid`, `si_usr_id` і `si_ses_id` із вставленого рядка та повторно формує чистий заголовок `Cookie`, що містить лише ці пари, а також `nt_session` (токен `ntk_…`, установлений для облікових записів, у які виконано вхід), якщо він наявний. Якщо будь-яке з трьох значень відсутнє, вставлений необроблений рядок пересилається без змін, щоб оператори могли експериментувати з альтернативними форматами.

### Ідентифікатори моделей

| Ідентифікатор моделі | Відображувана назва | Примітки                                                                |
| -------------------- | ------------------- | ----------------------------------------------------------------------- |
| `notrack-c`          | NoTrack C           | За замовчуванням — висхідна модель диспетчеризації `C`.                 |
| `C`                  | NoTrack C           | Псевдонім для `notrack-c` (необроблений висхідний код диспетчеризації). |
| `notrack`            | NoTrack C           | Псевдонім для `notrack-c`.                                              |
| `ntw`                | NoTrack C           | Короткий псевдонім для `notrack-c`.                                     |

Усі чотири ідентифікатори моделей відповідають одній і тій самій висхідній моделі диспетчеризації (`C`).

### Параметри запиту

Виконавець приймає такі необов’язкові поля в тілі запиту:

| Поле тіла             | Значення за замовчуванням | Призначення                                                                            |
| --------------------- | ------------------------- | -------------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`                   | Режим диспетчеризації (довільний рядок; висхідний сервіс приймає `usual`, …)           |
| `notrack_max_turns`   | `6`                       | Кількість внутрішніх кроків, які висхідний сервіс може виконати перед відповіддю.      |
| `notrack_chat_id`     | `null`                    | Відновлення наявного висхідного чату (не вказуйте для нового чату).                    |
| `notrack_attachments` | `[]`                      | Наскрізний масив дескрипторів вкладень висхідного сервісу.                             |
| `notrack_regenerate`  | `false`                   | Установіть `true`, щоб запитати повторно згенеровану відповідь для попереднього кроку. |

### Можливості

- **Потокові та непотокові** завершення чату.
- **Виклик інструментів** — установіть `tools: [...]` у запиті; виконавець серіалізує їх у контракт конверта виклику інструмента та перетворює відповіді моделі назад у `tool_calls` OpenAI.
- **`response_format`** — підтримуються `json_object` і `json_schema`. Виконавець витягує перший об’єкт JSON із відповіді моделі та перетворює його на рядок перед поверненням.
- **Підказка щодо міркувань** — виконавець генерує дельту `reasoning`, коли висхідний сервіс надсилає подію `thinking`.

### Обмеження

- Висхідний сервіс застосовує квоти анонімного використання — у разі їх перевищення виконавець повертає помилку 429 зі зрозумілим повідомленням.
- Усі ідентифікатори моделей відповідають одній висхідній моделі диспетчеризації; перемикання між моделями відсутнє.
- Виконавець не викликає кінцеву точку `/api/chats` висхідного сервісу, тому історія чатів і сеанси не керуються автоматично. Використовуйте `notrack_chat_id`, щоб відновити наявний висхідний чат.

# Що можуть і чого не можуть робити провайдери Web Cookie

Провайдери Web Cookie повторно використовують чат-інтерфейс вебсайту. Вони **не** надають таких самих можливостей, як офіційні API.

## Підтримується

- Автентифікація за допомогою наявного сеансу браузера
- Доступ до моделей, доступних через ваш обліковий запис
- Потокове передавання відповідей чату
- Ключ API не потрібен

## Не підтримується

- Виклик функцій
- Виклик інструментів
- Автоматичне редагування файлів
- Агентні робочі процеси IDE
- Функції, доступні лише через API

Це очікувана поведінка й **не** помилка.

Якщо вам потрібні виконання інструментів, автоматичне редагування файлів або інші агентні робочі процеси, використовуйте **провайдера з ключем API** замість провайдера Web Cookie.

# Застереження щодо перевірки

Успішна **перевірка з’єднання** або перевірка файлів cookie лише підтверджує, що надані облікові дані мають очікуваний формат.

До вирішення проблеми #7857 успішна перевірка **не гарантує**, що провайдер зможе успішно виконати автентифікацію.

Якщо автентифікація все одно завершується невдало, переконайтеся, що ви скопіювали облікові дані з активного мережевого запиту, а не зі сховища файлів cookie браузера.

---

# Усунення несправностей

## Помилка автентифікації

Переконайтеся, що облікові дані скопійовано з:

```
Network
→ Request Headers
→ Cookie
```

а **не** з:

```
Application
→ Cookies
```

---

## Файл cookie працює у браузері, але не в OmniRoute

Деякі провайдери додають файли cookie, які надсилаються лише під час автентифікованих запитів.

Повторно скопіюйте облікові дані зі свіжого мережевого запиту після успішного відкриття розмови.

---

## Термін дії сеансу завершився

Провайдери Web Cookie використовують ваш наявний сеанс браузера.

Якщо термін дії сеансу браузера завершиться або ви вийдете з облікового запису, необхідно скопіювати новий набір облікових даних. Щоб автоматизувати оновлення файлів cookie для підтримуваних вебпровайдерів, скористайтеся супутнім інструментом [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md).

---

## Перевірка з’єднання проходить успішно, але запити завершуються невдало

До вирішення проблеми #7857 успішне проходження перевірки не гарантує, що запит автентифікації буде успішним.

Перш ніж продовжувати усунення несправностей, повторно скопіюйте облікові дані зі свіжого автентифікованого запиту.

---

## ChatGPT Web завершується з помилкою "Unsupported ChatGPT integrity dependency"

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

З обліковими даними все гаразд — ця помилка походить від мосту, а не від сеансу. chatgpt.com призначає свої
ідентифікатори модулів для кожного розгортання, а міст раніше фіксував ідентифікатор допоміжного модуля Sentinel, екземпляр якого він створює, тому
повторне збирання chatgpt.com, під час якого допоміжний модуль було перейменовано, порушувало кожен запит, хоча файл cookie залишався дійсним. Повторна авторизація
з’єднання не може це виправити.

Збірки, які визначають модуль через власне середовище виконання сторінки, не фіксують жодного ідентифікатора й не стикаються з цією проблемою. Якщо ви бачите цю
помилку, оновіть OmniRoute й повторно запустіть перевірку з’єднання.

# Рекомендації

- Копіюйте облікові дані зі свіжого автентифікованого запиту.
- Не використовуйте старі файли cookie повторно.
- Підтримуйте сеанс браузера активним під час використання провайдерів Web Cookie.
- Вважайте скопійовані файли cookie конфіденційними обліковими даними.
- Використовуйте провайдерів із ключем API, коли вам потрібні виклики функцій або агентні робочі процеси.
