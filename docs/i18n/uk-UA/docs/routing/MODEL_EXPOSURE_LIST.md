> Увімкнення, вимкнено за замовчуванням (`modelVisibilityAllowlist`/`modelVisibilityDenylist` обидва порожні, залишаючи каталог `/v1/models` AND кожен байт пулу кандидатів `auto/*` ідентичним). Побратим `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`) для операторів, яким потрібен підбірний список моделей з причин, не пов’язаних із вартістю.

## Чому це існує

`hidePaidModels` відповідає "ця модель безкоштовна?" і `hideAutoCombos` відповідає "чи потрібно взагалі рекламувати віртуальні ідентифікатори `auto/*` ?" — також не дозволяє оператору керувати довільною підмножиною моделей (наприклад, представляти саме ті моделі, які повинен бачити даний клієнт Claude Code / OpenCode, незалежно від ціни). #11481 додає це як два незалежні параметри масиву рядків.

## Налаштування

| ключ                       | Тип        | За замовчуванням | Сенс                                                                            |
| -------------------------- | ---------- | ---------------- | ------------------------------------------------------------------------------- |
| `modelVisibilityDenylist`  | `string[]` | `[]`             | Записи, що відповідають кандидату, приховують його від пулу catalog/candidate.  |
| `modelVisibilityAllowlist` | `string[]` | `[]`             | Якщо не порожні, записи ONLY що відповідають кандидату, залишаються відкритими. |

Обидва приймають до 500 записів до 200 символів кожен (перевірено Zod у `src/shared/validation/settingsSchemas.ts`). Запис:

- точний ідентифікатор каталогу — `"gpt-4o"` (ідентифікатор голої моделі) або `"openai/gpt-4o"` (префікс постачальника), або
- глобальний шаблон з використанням `*`/`?` — наприклад, `"openai/gpt-4*"` або `"anthropic/*"` — розв’язаний через той самий спільний збіг `globToRegex()` (`src/shared/utils/globPattern.ts`), який уже використовується комбінованими відображеннями `ModelRoutingSection` для кожної моделі та `freeModels.ts::matchesOnlyPaidModels`.

Пріоритет: спочатку перевіряється список заборонених (заборонений запис завжди приховано, навіть якщо він також відповідає білому списку); коли білий список не порожній, виживають лише ті записи, які йому відповідають.

## Дві задушливі точки, а не одна

Урок із #6512 (фільтр каталогу `hidePaidModels` -only усе ще дозволяє `auto/*` направляти платну модель, оскільки пул комбінованих кандидатів було створено незалежно) тут ідентично застосовується. Збігний предикат `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`) викликається з BOTH:

- `src/app/api/v1/models/catalog.ts` — сам список `/v1/models`, з тими самими 5 контрольними точками для кожного джерела `shouldHidePaid()` уже пропускає (статичний `PROVIDER_MODELS`, синхронізовані рядки провайдера, спеціальні рядки, рядки з псевдонімами, керовані резервні рядки).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — викликається з `virtualFactory.ts::buildPreparedPool` відразу після еквівалентного виклику `filterPaidOnlyCandidates()`, тому заборонену модель також ніколи не можна вибрати в пул кандидатів `auto/*`.

## Що таке фільтр NOT

Дзеркалює існуючу поведінку `hideAutoCombos`: надіслано ідентифікатор моделі** явно** (не через `auto/*` і не виявлено через список каталогу) ніколи не блокується під час відправки — фільтрується лише членство advertisement/candidate-pool. Це не залежить від `hidePaidModels`; Оператор може знадобитися кураторський набір з причин, які не мають нічого спільного з вартістю, тому обидва параметри складаються як незалежні фільтри AND-ed, так само, як і існуюча композиція з кількома прапорцями в `catalog.ts`.

Експорт налаштувань (`GET /api/settings/export-json`) включає обидва масиви дослівно, як і будь-яке інше поле налаштувань — на відміну від фільтра експорту комбінованих кроків `hidePaidModels`, тут немає ризику повторної гідратації: заборонений ідентифікатор, вбудований в експортований крок комбінованого, є власним явним вибором маршрутизації оператора, а не тим, що межі експорту потрібно видалити.

## Комбінований список (`exposeCombosOnly`)

Окреме логічне значення, а також опція та `false` за замовчуванням для розгортань, де комбо є загальнодоступною поверхнею моделі, а постачальники є лише серверними. Коли це `true`, публічний список (`GET /v1/models`, `GET /v1` та інші маршрути виявлення `/v1` побудовані на `getUnifiedModelsResponse()`) зберігає лише рядки з комбінаціями `owned_by: "combo"`: користувача та вбудованими комбінаціями `auto/*` (якщо тільки `hideAutoCombos` не приховує їх). Він використовує той самий тест рядка, що й `catalogScope: "combos"` для кожного ключа, а власні фільтри allow/deny/scope ключа все ще застосовуються зверху.

Увімкніть його** Параметри → Маршрутизація → Моделі API список** , або з `PATCH /api/settings {"exposeCombosOnly": true}`.

Як і списки вище, він змінює лише рекламу:

- явний ідентифікатор `provider/model` все ще надсилається, і `GET /v1/models/{id}` все ще вирішує його;
- каталог приладової панелі (`GET /api/models/catalog`, який використовується для вибору моделей) не звужений;
- він не відображається в пулах кандидатів `auto/*`, тому комбо `auto/*` зберігають свій повний пул.
