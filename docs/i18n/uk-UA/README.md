## Безкоштовні токени на місяць: ~ 11,3 млрд. на рахунок інших · ~ 90 млн реальних

</div>

> **~ 11,3 млрд безкоштовних токенів на місяць**<br/> <sub> рахував так само, як інші каталоги: кожен рядок додано, завершені пропозиції включено </sub>
>
> **~ 90M реальний сьогодні**<br/> <sub> кожна спільна квота враховується один раз: що насправді можна використовувати </sub>
>
> **Тут все безкоштовно. Без платного доступу.**<br/> ★ [Подобається? Зіркою нас на GitHub](https://github.com/cheaper-inference/OmniRoute)

Інші каталоги стягують від US 19 доларів на рік до US 49 доларів за довічний доступ до живих даних. Тут все безкоштовно. <sub> Ціни перевірено 2026-11-18.</sub>

<sub>Остання перевірка каталогу 2026-11-23. [Як ми розраховуємо →](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **Принесіть власні облікові записи постачальника.** Це сторонні безкоштовні рівні, а не символічний грант від OmniRoute. Зареєструйтеся, отримайте облікові дані там, де їх просить провайдер, і підключіть ті, які ви можете використовувати. Кожен провайдер встановлює власні обмеження, доступність і умови.
>
> Складання безкоштовних рівнів вручну означає десятки SDKs, десятки обмежень на швидкість і відсутність чіткого уявлення про те, що у вас залишилося. OmniRoute зберігає 214 рядків каталогу з вільним доступом і обчислює реальну цифру з 12 пулів з опублікованою квотою, кожен спільний пул враховується один раз. Квоти, які відкриваються лише після перевірки регіональної ідентифікації (сьогодні, ModelScope), відображаються окремо, +~ 6M після перевірки регіональної ідентифікації та ніколи не додаються до реальної цифри. Те, що залишилося, відображається на приладовій панелі (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute free-tier budget card. Free tokens a month: ~11.3B as others count · ~90M real. Up to ~153M in your first month with one-time signup credits. 12 pools with a published quota and 214 catalog rows with free access behind one endpoint, catalog audited 2026-11-23. The bar shows where the real figure comes from, one segment per pool. Signup credits and free providers without a token cap are listed apart and never added to it. Live used and remaining tokens on /dashboard/free-tiers."/>

>
> Остання перевірка каталогу <sub>: 23 листопада 2026 року. Фігури рухаються в обидві сторони. Постачальник закінчує безкоштовний рівень, і реальне число падає. Новий приземляється і лізе. Ми публікуємо те, що обчислює каталог, ніколи не найкращий випадок.</sub>

## Встановіть, підключіть постачальника, а потім маршрут через одну кінцеву точку

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>`auto` потрібен відповідний маршрут. Нова інсталяція може не мати придатних цілей без ключа, а постачальник без ключа може відхилити сторонніх клієнтів. Постачальники з позначкою `tos: avoid`, включаючи Kiro, за замовчуванням виключаються з автоматичної маршрутизації; підключення облікового запису не замінює це налаштування. Перш ніж вибрати постачальника, перегляньте [Посібник із безкоштовних рівнів](docs/getting-started/FREE-TIERS-GUIDE.md).</sub>

<sub>Скопіюйте та вставте сценарії швидкого запуску для** Python, Node.js, PHP і cURL** : [`examples/quickstart/`](examples/quickstart/). Покрокова версія: [Швидкий старт](#quick-start).</sub>

## Комбо: флагман

1. **Почніть із `auto`.** Встановіть модель у вашому OpenAI-сумісному клієнті. OmniRoute створює віртуальне комбо з підключених провайдерів і оцінює кандидатів наживо.
2. **Збережіть комбо для більшого контролю.** Виберіть назву, цільовий список і стратегію, а потім використовуйте це ім’я як модель. Стратегія встановлює, яка ціль буде першою та як випробувати решту.

Комбінація автоматично маршрутизує між моделями. У разі вичерпання квоти, збою постачальника або блокування моделі він намагається виконати наступну відповідну, справну ціль.

### Без конфігурації: просто використовуйте `auto`

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

Варіанти налаштування ваги. Маршрутизація «Останній відомий-справний» залишається з останнім успішним постачальником, доки він не вийде, а потім повторно оцінюється. `auto/fast` та `auto/cheap` виражають переваги, не гарантуючи найшвидшу чи найдешевшу модель.

| Модель ID           | Поведінка                                                                                                                                                                                                                                                                                                               |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Збалансовані ваги за замовчуванням.                                                                                                                                                                                                                                                                                     |
| `auto/fast`         | Сприяє низькій затримці та працездатності постачальника.                                                                                                                                                                                                                                                                |
| `auto/cheap`        | Надає перевагу нижчим цінам за каталогом.                                                                                                                                                                                                                                                                               |
| `auto/coding`       | Вагові показники якості для генерації коду.                                                                                                                                                                                                                                                                             |
| `auto/smart`        | Вагові ваги першочергово якості з 10% дослідження (за замовчуванням 5%).                                                                                                                                                                                                                                                |
| `auto/lkgp`         | Явна маршрутизація останнього відомого успішного з такими ж вагами, як і `auto`.                                                                                                                                                                                                                                        |
| `auto/subscription` | Використовує лише перевірену квоту плану. Повертає HTTP 503, якщо жоден з них недоступний, і уникає виставлення рахунків.                                                                                                                                                                                               |
| `auto/thrifty`      | Плануйте → keyless → free → cheap → premium. Запити все ще надходять до ваших провайдерів.                                                                                                                                                                                                                         |

### Або створіть власну: 22 стратегії маршрутизації

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

CLI приймає 15 із 22 стратегій. Приладова панель і комбо API приймають усі 22.

| Стратегія           | Поведінка                                                                                                                                                                                                                                |
| :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Ранг кандидатів у прямому ефірі за допомогою 16-факторного автокомбінатора.                                                                                                                                                              |
| `cache-optimized`   | Надайте перевагу обліковому запису, який, імовірно, зберігає префікс підказки в кеші.                                                                                                                                                    |
| `context-optimized` | Спробуйте спочатку найбільше відоме контекстне вікно.                                                                                                                                                                                    |
| `context-relay`     | Зберігайте своє замовлення та передайте зведення розмови під час зміни облікового запису.                                                                                                                                                |
| `cost-optimized`    | Сортувати за ціною вхідного токена каталогу, останні невідомі. Кінцева вартість запиту може відрізнятися.                                                                                                                                |
| `expiry-first`      | Квота витрат, імовірно, закінчиться, найвищий залишок на годину до початку скидання.                                                                                                                                                     |
| `fill-first`        | Залишайтеся на першій доступній цілі, доки вона не закінчиться або не зазнає невдачі, а потім рухайтеся далі.                                                                                                                            |
| `fusion`            | Запитуйте групу паралельно, а суддя синтезує одну відповідь.                                                                                                                                                                             |
| `headroom`          | Виберіть найбільшу вільну ємність у 5-годинному та тижневому вікнах.                                                                                                                                                                     |
| `jev`               | TypeSafe Jev вибирає, які записи у вашому рейтинговому списку працюватимуть. Увімкніть `COMBO_JEV_STRATEGY_ENABLED`, щоб надсилати уривок за запитом і використовувати платні дзвінки TypeSafe. Якщо його вимкнено, ваше замовлення діє. |
| `least-used`        | Виберіть ціль із найменшою кількістю записаних запитів у цій комбінації.                                                                                                                                                                 |
| `lkgp`              | Спершу спробуйте останнього успішного постачальника, інакше збережіть своє замовлення.                                                                                                                                                   |
| `p2c`               | Зробіть вибірку з двох цілей і оберіть за рівнем успіху та затримкою.                                                                                                                                                                    |
| `pipeline`          | Передавати результати кожного кроку в наступну ціль у послідовності та повертати лише остаточну відповідь.                                                                                                                               |
| `priority`          | Спробуйте цілі у своєму порядку. Сеансова липкість зберігає його.                                                                                                                                                                        |
| `quota-weighted`    | Пропустіть вичерпані облікові записи та використовуйте залишкову квоту та бортове навантаження.                                                                                                                                          |
| `random`            | Перемішайте для кожного запиту. Та сама перша ціль може повторюватися.                                                                                                                                                                   |
| `reset-aware`       | Оцініть квоту, що залишилася, і час для скидання в вікнах сесії та тижня.                                                                                                                                                                |
| `reset-window`      | Спробуйте обліковий запис, вікно квоти якого скидається найшвидше.                                                                                                                                                                       |
| `round-robin`       | Обертайтеся по порядку, три успіхи на ціль за умовчанням.                                                                                                                                                                                |
| `strict-random`     | Роздайте з перемішаної колоди, щоб кожна ціль лідирувала один раз перед повторенням.                                                                                                                                                     |

Стратегії квотування використовують дані в реальному часі, про які повідомляють постачальники, включаючи 5-годинний і тижневий вікна підписки. `fusion` і `pipeline` здійснюють кілька вихідних викликів на запит.

16-факторний оцінювач використовує квоту, працездатність, вартість, затримку, відповідність завданням, стабільність, пріоритет рівня, спорідненість рівня, відповідність специфічності, спорідненість контексту, спорідненість кешу, доступність сеансу, спорідненість вікна скидання, щільність з’єднання, якість і надійність. Вага залежить від профілю. Спорідненість кешу, схожість вікна скидання та надійність за замовчуванням мають нульову вагу. ### Стійкість вбудована: 3 незалежні шари

Помилки обробляються в трьох областях, тому одна погана модель не знімає свій обліковий запис, а один поганий обліковий запис не знімає свого постачальника.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Якщо весь провайдер не працює

The** автоматичний вимикач провайдера** відкривається після 8 (OAuth) або 12 (ключ API ) помилок зі статусом 408, 500, 502, 503 або 504. Комбінації пропускають цей провайдер, поки він відкритий. Через 60 с або 30 с один запит зонду вирішує, чи він закривається.

#### Якщо один ключ або обліковий запис має обмеження по швидкості

The** час відновлення з'єднання** перевіряє лише це з’єднання з експоненціальним відстрочкою від 5 с (OAuth) або 3 с (ключ API ). Інші ключі для того самого постачальника продовжують працювати.

#### При відмові від однієї моделі

The** блокування моделі** блокує лише цю модель у цьому з’єднанні після помилок 429, 404 для кожної моделі або відмови в доступі. Інші моделі на тому ж з’єднанні продовжують працювати.

Заборонені, прострочені та безкредитні підключення є термінальними станами, а не перезарядкою: вони чекають, поки ви їх виправите.

## OmniRoute радар

Radar — це активна, підписана копія безкоштовного каталогу вище, і вона безкоштовна для всіх. Немає платного доступу та періоду очікування. Він доступний лише для реєстрації та отримання. Клієнт OmniRoute нічого не надсилає до Radar: жодних підказок, трафіку, конфігурації провайдера чи використання телеметрії.

Наведені вище номери взято з каталогу, який постачається разом із цим випуском. Радар може показувати нові дані між випусками. Щотижня додаються нові безкоштовні пропозиції та акції. Спостерігайте за зростанням реального числа на радарі.

### OmniCopilot: OmniRoute у рідному чаті Copilot коду VS

> Ні нової бічної панелі, ні нового чату UI. Кожна модель чату, яку обслуговує OmniRoute відображається в** засіб вибору моделі чату Copilot який ви вже використовуєте** , і режим агента Copilot, виклик інструментів, сервери MCP та спеціальні інструкції продовжують працювати на обраній вами моделі.

встановити**OmniCopilot** , запустіть сервер OmniRoute (розширення за замовчуванням — `http://localhost:20128`), а потім відкрийте Copilot Chat → вибір моделі →** Керувати моделями…** →**OmniRoute** і відзначте потрібні моделі. ## Повний CLI, MCP і A2A

> OmniRoute постачає клієнт командного рядка** 91 команда верхнього рівня та група команд** (754 команди враховуючи підкоманди), an** сервер MCP зі 110 інструментами та 33 областями** , і ан** агент A2A з 6 навичками** . Сценарії, термінали та агенти AI можуть працювати з одним шлюзом.

### Справжній CLI, а не просто `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

Глобальний прапор `--output table|json|jsonl|csv` дозволяє використовувати ті самі команди зі сценаріїв і CI.

### Віддалений режим: CLI на вашому ноутбуці, OmniRoute на сервері

Увійдіть один раз на віддалений сервер. CLI зберігає його як a** контекст** , а пізніші команди виконуються на цьому сервері, доки ви не перейдете назад.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Сфера дії маркера | <img width="2000" height="0" alt=""> Що це дозволяє                               |
| ----------------- | --------------------------------------------------------------------------------- |
| `read`            | Перерахуйте та перевірте: моделі, статус, журнали, використання                   |
| `write`           | `read` plus налаштувати та застосувати: налаштування клієнта, ключі, конфігурація |
| `admin`           | `write` plus керує: токенами, провайдерами, послугами, політикою                  |

Голий хост отримує `http://` та порт 20128; передати повний `https://` URL, коли сервер знаходиться позаду TLS. Маршрути, які можуть породжувати процеси, залишаються лише петлевими, незалежно від маркера.

### Підключіть агента

Агент або ваш власний код може керувати маршрутизацією, постачальниками, комбо, кеш-пам’яттю, стисненням і пам’яттю через будь-який із цих інтерфейсів. Шляхи HTTP обслуговуються шлюзом за замовчуванням у `http://localhost:20128`.

| Інтерфейс               | Кінцева точка або команда  | Використовуйте його для                                                                        |
| ----------------------- | -------------------------- | ---------------------------------------------------------------------------------------------- |
| MCP через stdio         | `omniroute --mcp`          | Claude Desktop, Cursor та інші локальні клієнти MCP                                            |
| MCP над Streamable HTTP | `/api/mcp/stream`          | Віддалені клієнти MCP : 110 інструментів, 33 області, кожен виклик записується в журнал аудиту |
| MCP над SSE             | `/api/mcp/sse`             | Клієнти, які все ще користуються транспортом SSE                                               |
| відкриття A2A           | `/.well-known/agent.json`  | Картка агента: повідомляє іншим агентам, що може робити OmniRoute                              |
| виконання A2A           | `POST /a2a`                | Завдання JSON-RPC 2.0, синхронні або потокові через SSE, для 6 навичок                         |
| REST API                | `/v1/*`                    | Чат, сумісний з OpenAI, відповіді, вставки, зображення, аудіо та OCR                           |
| Вебхуки                 | `/api/webhooks`            | Події для Slack, Discord, Telegram або будь-якого URL із підписом HMAC                         |
| Віддалений CLI          | `omniroute connect <host>` | Керуйте віддаленим екземпляром за допомогою маркерів обмеженого доступу                        |

Шість навичок A2A : `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` і `list-capabilities`.

**Перед підключенням:**

- **MCP поверх HTTP запускається вимкнено.** Увімкніть його за допомогою `omniroute mcp enable --transport streamable-http` або на сторінці кінцевих точок інформаційної панелі. Одночасно активний один транспорт HTTP : `streamable-http` обслуговує `/api/mcp/stream`, `sse` обслуговує `/api/mcp/sse`.
- **A2A запускається вимкнено.** Увімкніть його на сторінці кінцевих точок інформаційної панелі. тоді `POST /a2a` дотримується тих самих правил ключа API, що й `/v1`.
- **Remote MCP потребує відповідного ключа.** `/api/mcp/*` за замовчуванням відповідає лише на loopback. З іншого хосту надішліть ключ за допомогою `manage` або `admin` (усі інструменти) або за допомогою `mcp:connect` плюс обсяги інструментів, які вам потрібні. Для ключів без `manage`/`admin` області інструментів завжди застосовуються.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

## Заощаджуйте 15–95% токенів — автоматично

### Як це працює, конвеєр —, архітектура та математика заощаджень

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

За замовчуванням стекова комбінована програма запускає `RTK → Caveman`. Коли обидва діють на те саме корисне навантаження tool/context, економія складається:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Блоки коду, URLs, JSON і структуровані дані** завжди захищений** двигуном збереження.

> **Навіщо використовувати багато токенів, коли кілька токенів справляються?** Кожен запит проходить через конвеєр стиснення OmniRoute** прозоро** — без змін клієнта. Тепер це a** стек з 12 компонованих двигунів** які працюють у порядку та змішують і підбирають для комбо маршрутизації — спираючись на ідеї з [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) і [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

## Інші методи встановлення — Docker, джерело, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` слідує за найвищим** опубліковано** стабільний SemVer. Він не відстежує git `main`. Закріпити `:X.Y.Z` для GitOps. Дивіться [канали випуску Docker](docs/guides/DOCKER_GUIDE.md#release-channels). Закріплення зображення**`OMNIROUTE_MEMORY_MB=1024`** . Цього достатньо для приладової панелі та легкого чату.** Агенти кодування** (`POST /v1/responses` з коду Claude, Codex, Grok, …) потрібна набагато більша купа V8 або процес `FATAL ERROR` з ~ 12 GiB у двох довгих контекстах, що перекриваються. Розмір контейнера вище купи (власні буфери знаходяться за межами V8):

| робоче навантаження <img width="2000" height="0" alt=""> | Купа (`-e OMNIROUTE_MEMORY_MB`)      | Контейнер (`--memory`) |
| -------------------------------------------------------- | ------------------------------------ | ---------------------- |
| Інформаційна панель / легкий чат                         | `1024` (зображення за замовчуванням) | ≥ 2 г                  |
| Один агент кодування                                     | `8192`                               | ≥ 10 г                 |
| Два одночасних довгих `/v1/responses`                    | `10240`–`12288`                      | ≥ 12–16 г              |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Повна таблиця: [Docker Guide — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Попередній випуск каналу Docker :** `diegosouzapw/omniroute:next` і `diegosouzapw/omniroute:next-web` дотримуються поточної гілки `release/v*` за замовчуванням. Ці змінні теги призначені лише для тестування неопублікованих виправлень** не підтримується для виробництва** . Перегляньте [канали випуску Docker](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

Стандартний `bun install` та глобальна інсталяція (`bun install -g omniroute`) підтримуються через виявлення часу виконання Bun :

- **Вбудований `bun:sqlite`** : OmniRoute використовує вбудований драйвер `bun:sqlite` Bun під час роботи в Bun, повертаючись до `better-sqlite3` на Node.js або `sql.js`.
- **Автоматичний вибір збірника Webpack у розробнику** : Розробка (`bun run dev`) автоматично виявляє Bun і вимикає Turbopack на користь Webpack, щоб запобігти несумісності зв’язування рідного V8. Виробничі збірки (`bun run build`) слідують за `OMNIROUTE_USE_TURBOPACK` точно так само, як і на Node: Turbopack за замовчуванням, `OMNIROUTE_USE_TURBOPACK=0` для створення з Webpack (`Dockerfile.bun` представляє його як `--build-arg`).
- **Виділений Bun Dockerfile** : Багатоетапний `Dockerfile.bun` для власного розгортання виробництва Bun (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ Швидше/простіше встановлення (пропустіть нативну збірку)**

Власний механізм SQLite (`better-sqlite3`) — це an** необов'язковий** залежність, тому глобальна інсталяція ніколи не блокує компіляцію з вихідного коду: вона використовує попередньо зібраний двійковий файл, коли він відповідає вашому platform/Node, а в іншому випадку повертається прозоро до чистого механізму JS (`node:sqlite` на Node 22 +, інакше в комплекті `sql.js` WASM) — не потрібні інструменти для збирання.

Щоб пропустити постінсталяцію** рідна розминка** повністю (CI, безголові або повільні машини). Примітка: це лише пропускає рідний етап розминки SQLite (`scripts/postinstall.mjs`); хук binary-copy/repair (`scripts/build/postinstall.mjs`) все ще працює нормально:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

Для найшвидшого встановлення віддайте перевагу** pnpm** (жорсткі посилання на магазин + з адресою вмісту — див. вище). Для роботи без інформаційної панелі без голови використовуйте профіль Docker `base` (вище) або [посібник Termux](docs/guides/TERMUX_GUIDE.md). CLI і веб-панель обслуговуються одним і тим же процесом на одному порту, тому сьогодні немає окремого пакета лише для CLI.

## Подяки

OmniRoute стоїть на плечах велетнів. Це почалося як розгалуження** [9роутер](https://github.com/decolua/9router)** і порт TypeScript проекту Go** [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)** — і звідти кожна підсистема нижче була натхненна проектом з відкритим кодом, який потрапив туди першим. Кожен утворив бетонний шматок OmniRoute. Це наша вдячність усім їм. 🙏

> кількість зірок ⭐ підтверджено з GitHubREST API 16 листопада 2026 р. — позначте ці проекти зірочками. Підрахунки є точним датованим знімком і, природно, змінюватимуться. GrokBridge повернув HTTP 404 у цю дату; його атрибуція зберігається.
