> **Katayuan:** ang dashboard ay binuo sa **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), na na-vendored
> bilang workspace na `packages/ui-kit` (`@omniroute/ui-kit`; ang upstream snapshot ay naka-pin sa
> `packages/ui-kit/UPSTREAM.md` at binabantayan ng `npm run check:ui-kit-snapshot`). Ang Light ang canonical
> na tema; ang default na kagustuhan ay `system`. Ang accent ay Keak lime (`--ci-color-accent`). Ang Inter
> (letter-spacing 0, `--ci-letter-spacing-ui`) ang UI family, ang Instrument Serif ay para lamang sa malalaki at sparse
> na display text (`.ci-dashboard-display`), at ang IBM Plex Mono para sa code — lahat ay self-hosted sa pamamagitan ng
> mga `@fontsource/*` import sa itaas ng `src/app/globals.css`. Ang bawat icon ay isang Lucide glyph.

## 1. Kung saan matatagpuan ang mga bagay

- **Kit.** Ang `packages/ui-kit/src` ay isang byte-for-byte na kopya ng upstream `src/` sa commit na naka-pin sa
  `packages/ui-kit/UPSTREAM.md` (na nagtatala rin ng awtorisasyon ng lisensya); ang `PATCHES.md` ay naglilista ng mga
  lokal na patch (wala). Kinokonsumo ito bilang source, nang walang build: ang `next.config.mjs` ang nagta-transpile
  nito, at ang `tsconfig.json` ay nag-ma-map ng `@omniroute/ui-kit` → `packages/ui-kit/src` at `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` (ang `vitest.config.ts` at `vitest.mcp.config.ts` ay may parehong alias). Mag-import ng kit
  component gamit ang subpath nito (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), hindi kailanman sa
  pamamagitan ng `@omniroute/ui-kit` barrel: hinihila ng barrel ang bawat component (kabilang ang date picker)
  papasok sa bawat importer. Ang kit stylesheet ay pumapasok sa pamamagitan ng `src/app/globals.css`
  (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **Mga token.** Ang `packages/ui-kit/src/ci-tokens.css` ang nag-deklara ng mga `--ci-*` token; ang
  `src/app/globals.css` ay nagba-bridge ng mga ito sa mga legacy na pangalan ng OmniRoute (`--color-*`, `--radius-*`,
  `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`), kaya patuloy na gumagana ang mga
  umiiral na pagbasa ng `var(--color-*)` at mga Tailwind utility. Ang bagong code ay gumagamit ng mga Tailwind
  utility (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) o mga kit
  class — hindi kailanman ng hex value (ang `tests/unit/design-kit-bridge.test.ts` ang nag-e-enforce ng bridge). Ang
  `text-primary` ay nagre-resolve sa `--color-primary-ink` sa pamamagitan ng `--text-color-primary` (lime-800 sa
  light, ang lime accent sa dark), kaya ang primary text ay nananatiling nababasa habang pinapanatili ng
  `bg-primary`/`border-primary` ang lime surface. Ang mga chart series ay gumagamit ng `--color-chart-1` …
  `--color-chart-5`.
- **Mga tema.** Ang `<html className="ci-theme">` (`src/app/layout.tsx`) ay nag-o-opt-in ng document sa kit theme.
  Ang preference ay `light`, `dark` o `system` (`THEME_CONFIG.defaultTheme = "system"` sa
  `src/shared/constants/appConfig.ts`; ang `system` ay sumusunod sa `prefers-color-scheme`). Ang `applyTheme()` sa
  `src/store/themeStore.ts` (na minime-mirror ng inline bootstrap script sa `src/app/layout.tsx`, na tumatakbo bago
  ang hydration) ay nagse-set ng `data-theme="dark"|"light"` at nagta-toggle ng `.dark` class sa `<html>` nang
  magkasama. Ang dark token set ng kit ay naka-key sa `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`); ang
  sariling mga dark override ng OmniRoute (ang `.dark` block sa `globals.css`) at ang mga legacy Tailwind `dark:`
  utility ay naka-key sa `.dark` class. Walang mga accent color preset: ang accent ay laging nagmumula sa kit, at ang
  naka-persist na preset mula sa mas lumang build ay itinatapon kapag nag-load ang store.
- **Mga component (mga adapter).** Pinapanatili ng `src/shared/components/index.tsx` ang OmniRoute component API
  (mga parehong pangalan, default exports at props), at ang mga primitive sa likod nito ay mga adapter sa ibabaw ng
  kit: mga form (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), mga overlay at
  feedback (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`),
  istruktura (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) at mga table
  (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). Ang isang adapter ay nag-i-import ng kit
  component gamit ang subpath at nag-ma-map ng mga legacy prop dito — halimbawa, ang `Button variant="primary"` ay
  ang kit `default` button (`--ci-button-primary-*`: ang inverse surface sa light, ang accent kasama ang
  `--ci-color-accent-foreground` ink nito sa dark), ang `danger` ay `destructive`, at ang `warning` ay `outline`
  kasama ang `.ci-button--warning` extension. Ang mga rule na `.ci-button--warning` at `.ci-badge[data-tone]` sa dulo
  ng `globals.css` (`@layer components`) ay mga extension ng OmniRoute sa ibabaw ng mga kit class. Ang
  `tests/unit/ui/adapters/*.test.tsx` ang nagpi-pin ng bawat adapter.
- **Shell.** Ang `src/app/(dashboard)/layout.tsx` ay nagre-render ng `DashboardLayout`, na nagre-render ng
  `src/shared/components/layouts/DashboardShell.tsx`: ang kit `SidebarProvider` / `Sidebar` / `SidebarInset`
  (`packages/ui-kit/src/sidebar.tsx`), kasama ang navigation logic ng OmniRoute sa
  `src/shared/components/Sidebar.tsx`. Ang isang "skip to content" na link papunta sa `#main-content` ang unang
  focusable na elemento. Ang `src/shared/components/Header.tsx` ang may hawak ng kit `SidebarTrigger` (ang tanging
  sidebar toggle ng shell), ng Keak `ProductSwitcher` at ng nagbubukas ng command palette; ipinapakita nito ang route
  title lamang habang walang kit `PageHeader` (`.ci-page-header`) na naka-mount sa loob ng `#main-content`, kaya ang
  isang page na may sariling `PageHeader` ay may iisang `h1`. Ang `src/shared/components/CommandPalette.tsx` ay isang
  kit `Dialog`.
- **Mga icon.** Ang `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) ay nagre-resolve ng pangalan
  (ang Material Symbols vocabulary na ginagamit ng mga screen) sa pamamagitan ng `ICON_MAP`
  (`src/shared/constants/iconMap.ts`) papunta sa isang Lucide glyph. Wala na ang Material Symbols font at package:
  ang isang pangalang wala sa map ay nagre-render ng neutral na placeholder glyph (`data-icon-missing="true"`) at
  naglo-log ng console warning sa labas ng production. Ang `npm run gen:icon-map` ay nagpi-print ng mga pangalang
  ginagamit na wala sa map (ang `tests/unit/icon-map-coverage.test.ts` ay nagfa-fail sa anumang pangalan na walang
  Lucide icon; ang `tests/unit/icon-map-object-values.test.ts` ay sumasaklaw sa mga pangalang naka-store sa mga
  lookup object); ang `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` ay nagra-rewrite ng mga
  literal na `<span className="material-symbols-outlined">` span papunta sa `<Icon>`.
- **Brand.** Ang `src/shared/components/OmniRouteLogo.tsx` ay nagwa-wrap ng kit: ang default export na
  `OmniRouteLogo` ay nagre-render ng `ProductIcon product="omniroute" variant="glyph"` (inline SVG, ligtas sa
  `basePath`) at ang `OmniRouteLockup` ay nagre-render ng `ProductLockup product="omniroute"` (accessible name na
  "Keak OmniRoute") o, para sa mga white-label operator, ang kanilang sariling `name`/`logoSrc`. Ang mga destination
  ng product-switcher ay matatagpuan sa `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`,
  `KEAK_ACTIVE_PRODUCT`). Ang mga standalone na screen — `src/app/login/page.tsx`, `src/app/status/page.tsx`,
  `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` at
  `src/shared/components/ErrorPageScaffold.tsx` — ay nagpapakita ng lockup; ang
  `tests/unit/brand-pages-static.test.ts` ang nagbabantay dito.

## 2. Mga Tuntunin

1. Mga token, hindi kailanman mga literal. Mga eksepsyon na sinadyang panatilihin: ang laging-dark na console terminal, mga ReactFlow SVG stroke sa pamamagitan ng `STATUS_HEX` (`src/shared/constants/statusColors.ts`), at ang mga categorical palette na
   `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) at
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`).
2. Huwag kailanman i-patch nang manu-mano ang `packages/ui-kit/src`: i-sync gamit ang `scripts/dev/sync-ui-kit.sh <commit>`; ang pre-commit gate na `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) ay nabibigo sa anumang byte na
   naiiba sa naka-pin na upstream commit (nilalaktawan nito na may babala kapag wala ang upstream clone,
   `UI_KIT_CLONE` o `_references/cheaper-inference-ui-kit`). Kapag may kulang sa kit,
   gumawa ng paraan sa adapter o sa screen at humingi nito sa upstream.
3. Ang mga default na teksto ng kit ay English (`label = "Loading"`, `loadingLabel = "Loading table"`…) — magpasa ng mga isinaling
   string mula sa `useTranslations(...)` tuwing may nagre-render na teksto ang isang kit component.
4. Ang mga Tailwind utility ang nananaig sa mga kit component class (idinedeklara ng kit ang
   `@layer theme, base, components, utilities` at ang mga panuntunan nito ay nasa `components`) — gamitin ang mga utility para sa
   spacing at layout, hindi para muling kulayan ang mga kit component.
5. Mga heading: `.ci-heading` (Inter, walang tracking) para sa mga titulo ng page at seksyon; `.ci-dashboard-display`
   (Instrument Serif) para lamang sa malalaki, madalang na display text tulad ng status code ng error page.
6. Binabantayan ng `tests/unit/dashboard-kit-sweep.test.ts` ang kit adoption: walang Material ligature span sa ilalim ng
   `src/app` o `src/shared/components`; sa dashboard tree (`src/app/(dashboard)` at
   `src/shared/components`) walang hilaw na `<select>`, `<textarea>` o `<table>` at walang sariling-gawang
   `role="dialog"` sa labas ng mga nakalistang eksepsyon (ang native branch ng `Select` adapter,
   `RequestLoggerDetail`); bawat hilaw na `<button>` o `<input>` doon ay kailangan ng komentong naglalaman ng
   `kit-exception:` (kasama ang dahilan) na nagtatapos nang hindi hihigit sa 3 linya sa itaas nito; mga palette hue at `dark:` variant
   ay sa mga file lamang na inililista ng test.
7. I-verify ang dalawang tema at ang 390 px viewport bago ang PR (mga screenshot); pinapatakbo ng `tests/e2e/a11y.spec.ts`
   ang axe.

## 3. Pagdaragdag ng screen

1. Buksan ang page gamit ang kit `PageHeader` (`@omniroute/ui-kit/page-header`, `compact` sa loob ng
   dashboard) — titulo, deskripsyon at `actions`. Pagkatapos ay inaalis ng shell header ang sarili nitong titulo.
2. Bumuo ng mga control mula sa `@/shared/components` (mga adapter) at gumamit ng mga kit component ayon sa subpath kung saan walang
   adapter (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`,
   `Slider`…).
3. Mga icon: `<Icon name="…" />`. Ang bagong pangalan ay pumapasok sa `ICON_MAP` kasama ang katumbas na Lucide
   component sa semantika; ililista ng `npm run gen:icon-map` ang mga pangalang kulang pa.
4. Mga kulay: mga semantic utility (`text-success`, `bg-warning-bg`, `border-border`…) at
   `var(--color-chart-N)` para sa mga chart series; walang mga hex value at walang mga `dark:` variant na umuulit lamang ng kulay.
5. Teksto: bawat string, kabilang ang mga label na ipinapasa mo sa mga kit component, ay nagmumula sa `useTranslations`. Ang mga bagong
   key ay pumapasok sa `src/i18n/messages/en.json`, `pt-BR.json` at `vi.json` (ini-pin ng Vietnamese parity test ang
   bawat English key); ang ibang mga locale ay pinupunan ng i18n sync.
6. Patakbuhin ang mga guard bago ang PR: `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (ang tanging check na nakakahuli ng dinobleng import sa `iconMap.ts`),
   `npm run check:ui-icu`, at ang sariling mga test ng screen.

## 4. Pagdaragdag o pagbabago ng adapter

1. Panatilihin ang public API ng `src/shared/components/index.tsx`: parehong mga pangalan ng export, default exports, at mga tinatanggap na props. I-map ang mga legacy props papunta sa kit sa loob ng adapter (tingnan ang `Button.tsx`: `VARIANT_TO_KIT`, `SIZE_TO_KIT`).
2. I-import ang kit gamit ang subpath (`@omniroute/ui-kit/<component>`).
3. Ang mga workaround para sa mga kakulangan ng kit ay naroroon sa adapter (o sa `globals.css` `@layer components` kapag ang ayos ay isang style), hindi kailanman sa `packages/ui-kit/src`.
4. Magdagdag o mag-update ng `tests/unit/ui/adapters/<name>.test.tsx`. Para sa isang adapter na may maraming caller, ihambing ang rendered markup bago at pagkatapos ng pagbabago — ang mga pagbabago sa padding o wrapper ay kumakalat sa bawat screen.

## 5. Pag-update ng kit

Ang `scripts/dev/sync-ui-kit.sh <commit> [clone]` ay nagkokopya ng upstream `src/` sa commit na iyon papunta sa `packages/ui-kit/src` at nag-a-apply ng iisang pinapayagang transformation (inaalis nito ang `.js` suffix mula sa mga relative import). Pagkatapos: suriin ang `git diff packages/ui-kit`, gumawa ng visual pass sa mga provider, settings, combos, usage at endpoint sa parehong tema, patakbuhin ang `npm run check:ui-kit-snapshot` at `npm run test:vitest:ui`, at buksan ang PR kasama ang upstream changelog.
