`copilot-m365-web` (alias `m365copilot`) ay nagpapadala ng mga kahilingan sa chat na format ng OpenAI sa pamamagitan ng napatotohanang Microsoft 365 Copilot session sa `m365.cloud.microsoft/chat`. Ito ay isang hindi opisyal na katutubong pagsasama: walang hiwalay na proseso ng proxy o localhost upstream na kinakailangan. Ang provider na ID, alias at mga kasalukuyang na-import na koneksyon ay hindi nagbabago. `copilot-web` ay ibang provider para sa serbisyo ng consumer sa `copilot.microsoft.com`.

> **Bago sa mga provider ng Web Cookie?**
>
> Basahin**`docs/getting-started/WEB-COOKIE-GUIDE.md`** para sa pangkalahatang proseso ng pag-setup, gabay sa pagpapatotoo, mga limitasyon, at pag-troubleshoot bago sundin ang gabay na ito na partikular sa provider.
>
> **Para sa mga legacy na pag-import:** Ang kredensyal para sa provider na ito ay** hindi cookie** . Huwag kumopya ng cookies mula sa `m365.cloud.microsoft`. Ang kredensyal ay isang WebSocket URL query parameter at path segment, parehong nabasa mula sa DevTools Network tab.

## Mga kinakailangan

- Isang Microsoft 365 account na may access sa Copilot sa `m365.cloud.microsoft/chat`
- Isang browser na nakabatay sa Chromium (Chrome, Edge) para sa inspeksyon DevTools WebSocket
- Access sa hiniling na modelo sa account na iyon; ang kakayahang magamit ay nag-iiba ayon sa nangungupahan at lisensya

## Native sign-in (mga account sa trabaho o paaralan)

Pumili**Microsoft 365 Copilot → Connect** at maghanda ng pagtatangkang mag-sign in. Gumagamit ang dashboard ng authorization-code flow na may PKCE; hindi nito hinihingi ang iyong Microsoft password o MFA code.

1. Buksan a** blangkong tab ng browser** , pagkatapos ay buksan**DevTools → Network** at paganahin** Panatilihin ang log** . Gawin ito bago mag-navigate sa Microsoft: Windows SSO ay maaaring matapos kaagad.
2. Kopyahin ang URL ng awtorisasyon na ipinapakita ng dialog ng koneksyon at mag-navigate dito sa inihandang tab na iyon. Kumpletuhin ang pagpili ng account ng Microsoft o MFA kung hiniling.
3. Sa napreserbang Network log, hanapin ang kahilingan sa `https://login.microsoftonline.com/common/oauth2/nativeclient` at kopyahin nang buo** Humiling URL** .
4. I-paste ang URL na iyon sa dialog ng koneksyon at kumonekta. Huwag mag-paste ng raw code o ang panghuling `wrongplace` address-bar URL: ang kinakailangang callback ay isang lumilipas na nabigasyon.

Ang bawat pagsubok ay mag-e-expire pagkatapos ng sampung minuto at magagamit nang isang beses lamang. Sinusuri ng server ang estado nito, PKCE verifier at target na muling pagpapatotoo bago palitan ang code. Pagkatapos ng pag-expire o pagkabigo sa palitan, magsimula ng bagong pagsubok. Ang isang pagtatangka ay hindi makakaligtas sa isang pag-restart ng server.

Ginagamit ng mga token ang kasalukuyang tindahan ng kredensyal ng koneksyon at landas ng pag-refresh. Ang muling pagpapatunay ng isang koneksyon ay nangangailangan ng parehong Microsoft tenant/object na pagkakakilanlan, hindi lamang ang parehong email. Pinapanatili nito ang operator naming/settings at pinapalitan ang mga hindi na ginagamit na imported na kredensyal. Ang katutubong pag-sign-in ay para sa mga work/school account; ang legacy na landas sa pag-import ay nananatiling available para sa mga kasalukuyang koneksyon at suportadong tier configuration.

Ang buong callback URL ay isang beses na kredensyal. Huwag kailanman isama ito sa mga screenshot, log, mensahe ng suporta o commit. Ang daloy na ito ay hindi nagbubukas ng browser sa server, sinisiyasat ang kasaysayan ng iyong browser, o nagsimula ng lokal na callback server.

## Pagkuha ng kredensyal (WebSocket method)

1. Mag-sign in sa `https://m365.cloud.microsoft/chat` at magsimula ng pag-uusap.
2. Bukas**DevTools → Network** .
3. I-filter ayon sa**WS** (WebSocket).
4. I-click ang Chathub WebSocket na koneksyon. Maghanap ng URL na nagsisimula sa `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Mula nito** Humiling URL** , kopyahin:
   - Ang halaga ng parameter ng query `access_token` (isang panandaliang JWT).
   - Ang segment ng path ng Chathub pagkatapos `/Chathub/` (hal. `<oid>@<tenant>`).

Ang buong URL ay may anyo:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Sa OmniRoute, piliin**Microsoft 365 Copilot** , piliin ang legacy API-key/import na opsyon, at i-paste ang kredensyal sa format:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. I-click** Subukan ang Koneksyon** at** I-save** .

## Pagkuha ng kredensyal (HAR import)

Sa halip na manu-manong kopyahin ang mga halaga mula sa WebSocket URL, maaari kang mag-export ng DevTools HAR file:

1. Bukas**DevTools → Network** .
2. Magsimula o magpatuloy ng Microsoft 365 Copilot na pag-uusap (ito ay nagti-trigger ng WebSocket na koneksyon).
3. Mag-right-click sa panel ng Network at piliin** I-save ang lahat bilang HAR na may nilalaman** .
4. Sa OmniRoute, gamitin ang** Mag-import ng .har file** button sa dialog ng koneksyon ng provider.

Ini-scan ng OmniRoute ang HAR para sa Chathub WebSocket URL, kinukuha ang `access_token` at `chathubPath`, at awtomatikong i-populate ang mga field ng kredensyal. Ang HAR import ay nagde-decode ng JWT expiry at ipinapakita ang natitirang token habang-buhay.

> **Huwag kailanman gumawa ng totoong HAR export, access token, o refresh token.** Ang mga halaga ng pagsubok at dokumentasyon ay dapat palaging mga placeholder.

## Token habang buhay at i-refresh

Ang `access_token` ay panandalian (karaniwang**~ 75 minuto** ). Kung walang magagamit na refresh token, dapat mong kunin muli ang kredensyal pagkatapos mag-expire.

### Awtomatikong pag-refresh gamit ang `refreshToken`

Sa Microsoft 365 provider's** Magdagdag ng koneksyon** o** I-edit ang koneksyon** dialog, bukas** Mga Advanced na Setting → Refresh token (opsyonal)** . Mag-paste ng Microsoft OAuth refresh token para sa `substrate.office.com/sydney` scope at i-save. Ang input ay naka-mask at hindi kailanman napuno ng nakaimbak na token. Kapag nag-e-edit, iwanan itong blangko upang panatilihin ang umiiral na token; mag-paste ng bagong token para palitan ito.

Nakukuha ng native na pag-sign-in ang refresh token kapag nagbalik ng isa Microsoft. Para sa mga legacy na pag-import, gumamit ng kasalukuyang katugmang Microsoft authorization-code grant; ang provider na ito ay hindi nagpapatupad o nangangako ng daloy ng device-code. Sa isang refresh token na na-configure, sinusuri ng OmniRoute ang `access_token` bago humiling at nire-refresh lang ito kapag kailangan nitong i-refresh. Ang isang matagumpay na pag-refresh ay nagpapatuloy din sa rotated refresh token, na iniiwasan ang manu-manong muling pagkuha habang ang refresh token ay nananatiling wasto.

Kung hindi nakatakda `refreshToken`, dapat mong kunin muli ang kredensyal WebSocket nang manu-mano pagkatapos ng bawat pag-expire.

### Pagpili ng tier

| Tier         | alyas       | Ibabaw                       |
| ------------ | ----------- | ---------------------------- |
| `individual` | _(default)_ | Consumer M365 Copilot        |
| `edu`        | `included`  | Edukasyon M365 Copilot       |
| `enterprise` | `work`      | M365 Copilot para sa Trabaho |

Itakda ang tier sa** Mga Advanced na Setting → Copilot tier** . Hindi ito itinatakda ng native na pag-sign-in, kaya dapat piliin ng isang account sa trabaho `enterprise` (alias `work`) at isang education account `edu`, gayundin kapag gumagamit ng dokumentadong modelong IDs: pinipili ng mga iyon ang kanilang sariling tono, sitwasyon at uri ng lisensya, ngunit ang ahente at mga opsyon sa invocation ay nagmumula pa rin sa tier, at maaaring mabigo ang mga indibidwal na default sa isang nangungupahan sa trabaho. Ang pagpapalit ng tier ay hindi nagbibigay ng lisensya ng modelo. Ang mga tahasang advanced na pag-override sa protocol ay mauuna at dapat lang gamitin kapag alam mo ang mga kinakailangang halaga ng wire.

## Mga modelo at pagruruta

Kasama sa native catalog ang lahat ng nakadokumentong standalone IDs kasama ang apat na orihinal na native IDs. Ang catalog ay static at account-independent, hindi isang account entitlement probe: ang mga bayad na ruta at mga alyas sa compatibility ay nananatiling nakalista kahit na hindi magagamit ng isang konektadong account ang mga ito. Inalis ng mga label ng display ng modelo ang pangalan ng provider at boilerplate ng availability sa bawat modelo; nananatili ang provider**Microsoft 365 Copilot** . Minarkahan ang mga label** alyas** o** Legacy** panatilihin ang kanilang mga kasalukuyang identifier at protocol mapping, hindi isang garantiya ng isang makasaysayang bersyon ng modelo. Ang mga standalone na proxy** Mag-import mula sa /models** hindi nalalapat ang mga tagubilin sa katutubong tagapagbigay WebSocket na ito.

| Modelong pamilya  | Canonical IDs                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| Awtomatiko        | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| Kanina pa GPT     | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude Soneto     | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude Opus       | `claude-opus`, `claude-opus-4.8`                                                                 |

Ang mga alias gaya ng `auto`, `quick`, `think-deeper`, at mga bersyon na alias ay nakarehistro din. Ang umiiral na `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` at `copilot-m365-gpt-5-5-chat` ay nananatiling wasto. Ang dokumentadong IDs ay nangangailangan ng prefix ng provider (`copilot-m365-web/claude-opus` o `m365copilot/claude-opus`): marami ang mga generic na salita o mga pangalan ng modelo ng iba pang mga vendor, kaya ang isang hubad `claude-opus` ay patuloy na nagruruta tulad ng ginagawa nito nang wala ang provider na ito. Ang pagpaparehistro ay hindi isang pangako na ihahatid ng Microsoft ang modelong iyon sa bawat account. Ang standalone IDs ay sumusunod sa public [protocol catalog](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) (ang na-export na model-to-tone na mapa at ang metadata ng senaryo na may kamalayan sa modelo nito). Ang lahat ng katutubong profile ay nagpapanatili `availability: "unverified"`; Ang pagsasama sa catalog ay hindi isang matagumpay na pagsubok sa account.

- Nagbabalik ang isang tahasang pagtanggi sa lisensya ng modelo** 403** `m365_model_not_licensed`, hindi 502. Nila-lock ng pagruruta ang pares na iyon connection/model, na iniiwan ang mga lisensyadong modelo sa koneksyon na magagamit.
- `InvalidCopilotLicense` ay isang pagtanggi sa lisensya sa antas ng account, na iniulat nang hiwalay bilang `m365_account_not_licensed`.
- Nagbabalik ang bawat user throttle** 429** `m365_throttled` at pinapalamig ang koneksyon. Nagbabalik ang priority-access exhaustion** 429** `priority_access_exhausted` at nasasakupan ng modelo. Isang resulta ng `OutOfCredits` na may `errorCode: "ReasoningTurnExhausted"` ay bumabalik** 429** `reasoning_turns_exhausted` sa halip, nasasakupan din ng modelo, na walang na-claim na oras ng pag-reset. Iniulat sa isang nangungupahan sa trabaho na i-cap ang "Think deeper" tones habang ang Quick tones ay patuloy na nagsisilbi; ang saklaw na iyon ay isang pagmamasid ng consumer, hindi isang bagay na ginawa ng repositoryong ito. Samakatuwid, inaalis din ng pagruruta ang iba pang nakadokumentong Think deeper models ng `gpt-5.5` at `gpt-5.6` mula sa pag-ikot sa koneksyon na iyon para sa parehong cooldown, at iniiwan ang mga Quick tone at bawat iba pang pagkabigo sa sarili nitong modelo. Ang mga ibinigay na pahiwatig sa muling pagsubok ay pinapanatili; ang nawawalang pag-reset ay hindi ina-advertise bilang isang kilalang oras ng pag-reset.
- Nagbabalik ang isang Copilot safety refusal (`Disengaged`).** 400** `provider_safety_rejection`, ang nakabahaging label ng paghinto ng kaligtasan ng provider. Ito ay hindi kailanman binibilang laban sa kalusugan ng koneksyon, client SDKs ay hindi muling subukan ang isang 400, at kapag `PROVIDER_SAFETY_STOPS_TERMINAL` pinagana ang combo routing hihinto doon sa halip na i-replay ang kahilingan laban sa isa pang target.
- Ang mga kahilingan sa isang koneksyon ay naka-serialize sa pamamagitan ng umiiral nang account semaphore. Mas gusto ang priority fallback kaysa sa mga parallel na panel; Ang serialization lang ay hindi nag-aalis ng mga limitasyon sa rate ng pag-uusap ni Microsoft.

## Humiling ng pag-uugali at mga limitasyon

- Ang mga kasangkapan ay** maagap-emulated** , hindi katutubong Microsoft function na tawag. Gumagamit ng isang naka-buffer na henerasyon ang isang kahilingang pinagana ng tool; hindi ito gumugugol ng isa pang henerasyon sa pagpili ng mga kasangkapan. Tanging ang mga ipinahayag na tool na may wastong suportadong mga hugis ng argumento ang ibinabalik bilang mga tawag.
- Ang isang mahabang structured na sagot na may isang solong trailing na halimbawa ay pinapanatili bilang prosa. Ito ay isang heuristic, hindi patunay ng layunin; dapat pa ring ipatupad ng mga application ang sarili nilang mga pahintulot sa tool.
- Gumagana ang pag-input ng larawan sa paraan ng pagpapadala nito ng web client. Ang bawat bahagi ng larawan (`image_url` bilang isang data URL o isang pampublikong HTTPS URL, o isang Mga Tugon `input_image`) ay ina-upload sa `/m365Copilot/UploadFile` sa pag-uusap ng turn kasama ang token ng chat, at itinuturo ito ng mensahe gamit ang isang `ImageFile` annotation; ang teksto ay nagmamarka kung saan ito nakaupo (`[image 1]`, …). Ang isang bagong pag-uusap ay nag-a-upload ng bawat larawan sa kasaysayan, ang isang patuloy na larawan lamang ng mga bagong mensahe. Hanggang 10 PNG, JPEG, GIF o WebP na mga larawan ng hindi hihigit sa 10 MiB bawat isa (40 MiB bawat kahilingan); ang format ay binabasa mula sa mga byte. HTTPS URLs ay kinukuha sa pamamagitan ng pampublikong-lamang, naka-pin na DNS na remote na image guard. Ang isang nabigong pag-upload ay nabigo ang kahilingan (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` o `m365_image_invalid`); hindi magpapatuloy ang isang pagliko nang walang ibinigay na imahe. Ang iba pang bahaging hindi teksto (audio, mga file) ay tahasang tinatanggihan, hindi tahimik na ibinabagsak.
- Ang isang follow-up na kahilingan ay nagpapatuloy sa parehong upstream na pag-uusap at nagpapadala lamang ng mga mensahe pagkatapos ng nakaraang tugon. Dapat nitong pahabain nang eksakto ang tugon na iyon: parehong koneksyon, profile ng modelo at set ng tool; isang hindi nabagong kasaysayan (isang sha256 chain sa bawat mensahe); at ang mga tool-call id ng tugon, o ang text nito hanggang sa whitespace. Anumang iba pa (isang na-edit na kasaysayan, isa pang session na may parehong unang mensahe, ibang tugon, isang pag-uusap na walang ginagawa sa loob ng 30 minuto o malapit sa 600-mensahe cap ni Copilot, isang koneksyon na walang id) ay magsisimula ng bagong pag-uusap sa buong kasaysayan. Ang isang nabigong pagliko ay hindi na ipagpatuloy, at ang isang walang nilalamang `InternalError` ay muling ipinapadala nang isang beses sa isang bagong pag-uusap (** 502** `m365_internal_error` kung nabigo muli). Ang mga pagpapatuloy ay pinananatili sa memorya ng proseso: ang pag-restart ay magsisimula ng mga bagong pag-uusap.
- Ang bawat pagliko ay tumatakbo sa pansamantalang chat ni Copilot(`disableMemory=1`): pinapanatili ng pag-uusap ang konteksto nito habang tumatakbo ito at hindi kailanman lumalabas sa kasaysayan ng chat ng account. Ang mga pagsubok sa modelo, Pagsubok sa Lahat at mga combo test ay maaaring samakatuwid ay suriin ang provider na ito nang hindi umaalis sa mga pag-uusap.
- Ang isang pagliko ay may 120-segundong idle na deadline at may hangganan na pangkalahatang deadline. Ang mga panghuling sagot, pag-filter ng pag-usad at pagkansela ay pinangangasiwaan ng katutubong transport/composer.
- Pinapanatili ng mga sagot na batay sa web ang kanilang mga mapagkukunan. minarkahan Copilot ang isang pagsipi na inline na may pribadong paggamit na mga control character at ipinapadala ang mga source bilang `references`; bawat marker ay nagiging isang may bilang na Markdown link (`[1](https://…)`, o ang bare URL kapag ginamit Copilot ang marker bilang target ng link) na may katugmang `url_citation` annotation (`message.annotations`, o `delta.annotations` sa chunk na nagdadala ng link). Ang isang mapagkukunan na hindi dumarating ay ibinabagsak, kaya ang mga marker ay hindi naabot ang kliyente. Kapag nagsi-stream, maghihintay ang text pagkatapos ng isang pagsipi hanggang sa dumating ang pinagmulan nito.
- Ang buod ng pangangatwiran ni Copilot(`ChainOfThoughtSummary`), kapag nagpadala ang modelo ng isa, ay ibinalik bilang `reasoning_content`, hindi kailanman bilang bahagi ng sagot. Ang isang buod na nagre-rewrite mismo ay humihinto sa pag-stream nang hindi nabibigo ang pagliko.
- Bago ang anumang nilalaman, ang mga pagkabigo licence/throttle ay nagpapanatili HTTP 403/429 kahit na hiniling ang streaming. Pagkatapos magsimula ng nilalaman, ang mga pagkabigo ay SSE error na kaganapan, hindi kailanman isang matagumpay na pagtatapos. Ang upstream rewrite na hindi maaaring katawanin ng append-only streaming ay isang tahasang error sa stream; hindi-streaming at buffered tool na mga tugon ay nagpapanatili ng huling teksto.
- Kapag tinanggihan Copilot ang koneksyon mismo, ang sagot nito ay iniulat bilang ito ay:** 401** `m365_unauthorized` para sa isang tinanggihan o nag-expire na pag-sign-in (mag-sign in muli),** 429** kasama ang `Retry-After` nito para sa throttling, at isang pagkabigo sa pagkakamay kung hindi man, hindi kailanman isang generic na pagkabigo ng koneksyon.

## Pagbuo ng imahe

`POST /v1/images/generations` na may `model: "copilot-m365-web/m365-copilot-image"` (alias `m365copilot/m365-copilot-image`) ay gumuhit gamit ang built-in na tool ng imahe ng Copilot, gaya ng ginagawa ng web client. Ang bawat larawan ay isang Copilot turn: nag-o-opt in ito sa mga set ng opsyon sa imahe ng web client at nagdedeklara `GenerateGraphicArt`, at ang larawan ay dumating sa isang progress entry na tumuturo sa isang artifact sa serbisyo ng Designer ng Microsoft. Tinatanggihan ng artifact na iyon ang token ng chat, kaya nag-mint OmniRoute ng isang Designer token mula sa refresh token ng koneksyon at dina-download ang mga byte; ang token ay ipinadala lamang sa `designerapp.officeapps.live.com`.

- Kailangan ng katutubong koneksyon sa pag-sign-in (isang refresh token); nabigo ang isang naka-paste na token** 400** bago gumastos ng anumang pagliko.
- `n` ay 1–4, tig-isang liko. `size` ay pinamamahalaan lamang ang oryentasyon (mas malawak, mas mataas o parisukat), na binabasa ng Copilot mula sa prompt; Pinipili Copilot ang laki ng pag-render.
- Ibinalik ang mga larawan nang inline: `b64_json` bilang default, isang data URL para sa `response_format: "url"`.
- Ang mga nabuong larawan ay gumuhit sa maliit na pang-araw-araw na badyet, na hiwalay sa chat. Kapag ito ay naubos ang kahilingan ay nabigo sa** 429** . Nabigo ang isang pagliko na sumasagot nang walang larawan** 502** (o** 400** /** 503** kapag ang teksto ni Copilot ay nagbabasa bilang isang pagtanggi o isang problema sa kapasidad); sinasabi ng mensahe kung alin.

## Modelo ng seguridad

- **Hindi opisyal na pagsasama.** Ang provider na ito ay nagre-reverse-engineer ng BizChat WebSocket protocol. Maaari itong masira nang walang abiso kapag binago ng Microsoft ang endpoint.
- Ang `subscriptionRisk: true` flag ay sumasalamin na ang integration ay umaasa sa isang undocumented endpoint. Posible ang mga paghihigpit sa account ngunit hindi nakumpirma.
- Ang access token ay isang panandaliang JWT. Tratuhin ito bilang isang password: huwag i-commit, i-log, o ibahagi ito.
- Ang refresh token ay nagbibigay ng patuloy na access sa Microsoft 365 surface. Itabi ito nang may parehong pangangalaga tulad ng isang API key.

## Pag-troubleshoot

### Nabigo kaagad ang pagpapatotoo

- I-verify na kinopya mo mula sa**WebSocket URL** , hindi mula sa isang kahilingan XHR/Fetch. Ang kredensyal ay nasa `access_token` query parameter ng Chathub WebSocket connection — wala sa isang `Authorization: Bearer` header.
- Tiyaking kasama sa `chathubPath` ang buong `<oid>@<tenant>` segment mula sa URL path.

### Mag-e-expire ang token pagkatapos ~ 75 minuto

Ito ay inaasahan. Kung walang `refreshToken`, ang access token ay panandalian. alinman sa:

- Kunin muli ang kredensyal mula sa DevTools, o
- I-configure** Mga Advanced na Setting → Refresh token (opsyonal)** sa dialog na Magdagdag o Mag-edit ng koneksyon para sa awtomatikong pag-refresh.

### Ang Test Connection ay pumasa ngunit ang chat ay nagbabalik ng 401

Para sa isang koneksyon na ginawa sa** Mag-sign in gamit ang Microsoft** , Sinusuri ng Test Connection ang pag-expire ng access token at nire-renew ang isang nag-expire na token gamit ang nakaimbak na refresh token, kaya pinatutunayan din ng isang pumasa na pagsubok na gumagana pa rin ang refresh token.

Para sa naka-paste na kredensyal, sinusuri ng Test Connection ang hugis ng kredensyal at, kapag nag-expire ang token, na ang token na gagamitin ng provider ay hindi pa nag-expire (ang nakaimbak na token ng koneksyon ay mananalo ng stale paste; ang isang refresh token ay mabibilang na renewable). Ang isang token na binawi bago ito mag-expire ay pumasa pa rin sa pagsubok; chat tapos bumalik** 401** `m365_unauthorized`. Gamitin** Mag-sign in gamit ang Microsoft** muli, o muling kumuha ng bagong kredensyal.

### Hindi lumalabas Copilot sa listahan ng provider

Tiyaking naka-enable `copilot-m365-web`** Mga Provider ng Dashboard →** . Maaaring nakatago ang provider bilang default sa ilang tier.
