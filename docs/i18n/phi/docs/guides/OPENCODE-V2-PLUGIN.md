Inilalagay ng `@omniroute/opencode-plugin-v2` ang buong catalog ng OmniRoute mo — mga model, combo, at
auto-combo — sa model picker ng OpenCode v2, kasama ang mga display name, presyo, at badyet
para sa free tier.

Hiwalay itong package sa `@omniroute/opencode-plugin` dahil magkaiba ang mga contract na ginagamit ng OpenCode v1 at v2 sa pag-load
ng mga plugin. Piliin ang tumutugma sa major version ng OpenCode mo; walang
pinagsasaluhan ang dalawa, kaya hindi kailanman mapipilit ng pag-upgrade sa isa ang pag-upgrade sa kabila.

## Mga Kinakailangan

- OpenCode v2.
- Isang naaabot na OmniRoute gateway (`http://localhost:20128` bilang default).
- Node.js 22 o 24.

## Pag-install

Idagdag ang plugin sa `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Pagkatapos, lalabas ang mga model bilang `omniroute/<provider>/<model>`; ang `providerId` ang tumutukoy sa prefix na iyon at
sa id ng integration kung saan iniimbak ng OpenCode ang credential.

## Mga Credential

Hinahanap ng plugin ang gateway key sa tatlong lugar, sa ganitong pagkakasunod-sunod:

1. **Ang credential na ikinonekta mo sa OpenCode.** Nagrerehistro ang plugin ng isang integration, kaya
   maaaring iimbak ng sariling auth flow ng OpenCode ang key. Walang inilalagay sa `opencode.json` — ito ang mas mainam.
2. `apiKey` sa mga option ng plugin, para sa override na para sa bawat project. Inilalagay nito ang key sa isang file na
   maaaring kino-commit mo.
3. `OMNIROUTE_API_KEY` sa environment.

Kapag wala ang tatlo, walang laman ang catalog at minsang ipapaalam ito ng plugin sa startup sa halip na
hayaan kang magkaroon ng tahimik na walang-lamang picker.

### Ibang key ang management token

Ang mga combo, kalagayan ng provider, at enrichment (mga display name, presyo, at badyet para sa free tier) ay nagmumula sa
mga endpoint na `/api/*` ng gateway, na sa karamihan ng deployment ay protektado ng **management** token
sa halip na inference key:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

Kapag hindi itinakda, gagamitin ng `managementReadToken` ang `apiKey` bilang fallback. Kapag tinanggihan ng gateway ang fallback na iyon,
ilalathala pa rin ang catalog, ngunit may mga raw model id sa halip na mga display name, walang pag-aalis ng duplicate batay sa canonical
alias, walang presyo, at walang mga combo. Minsang magbibigay ng babala ang plugin para sa bawat endpoint kapag nangyari iyon,
na binabanggit ang endpoint at kung ano ang nawala — kaya hindi magiging palaisipan ang isang degraded na picker.

## Paano nananatiling sariwa ang catalog

Ang catalog ay kinukuha nang tamad at naka-cache para sa `modelCacheTtlMs`, at ang isang disk snapshot ay nagpapanatili sa huling kilalang catalog na available kapag ang gateway ay hindi maabot — ang isang outage ay walang halaga kundi pagiging bago. Ang mga modelo at combo ay nai-publish sa sandaling dumating ang mga ito; Ang mga auto-combos, ang listahan ng provider at ang enrichment overlay ay natitiklop kapag lumapag ang mga ito, kaya ang isang mabagal na endpoint ay hindi ma-hostage ang buong picker.

Ang mga pangalan ay sumusunod `Provider - Model[ (Editor)][ · budget][ (route)]`: ang provider ay ipinapakita sa tuwing ang id ay may dalang isa (isang slash-less na id ay nagre-render nang walang prefix), ang isang nangungunang `🆓` ay nagmamarka ng mga libreng entry at ang kanilang libreng-tier na badyet ay nananatili bilang isang `· 1M tokens/month` suffix, ang editor ng isang tahasang `Editor: Model` na pangalan ay lilipat sa isang trailing parenthesis (walang editor ang hinuhulaan mula sa iba pang mga pangalan), at `combo - <slug>` combos mula sa iba pang pangalan Ang dalawang entry na nagbabahagi ng pangalan ay nakakakuha ng suffix ng ruta — `(no-think)` — upang manatiling nakikilala ang mga ito. `providerTag` (default `true`) i-toggle ang trailing editor parenthesis.

Walang manu-manong utos sa pag-refresh: ang mga OpenCode v2 na utos ay mga prompt na template, hindi mga callback, kaya hindi maaaring ilantad ng isang plugin ang isa. Ang mga pag-refresh ay sumusunod sa TTL; ang host ay hinihiling na mag-reload lamang kapag ang catalog o ang overlay ay aktwal na nagbago, hindi kailanman isang beses sa bawat pag-refresh.

## Pagtawag sa tool sa Gemini

Tinatanggihan ng Gemini ang isang buong request kapag may `$schema` o
`additionalProperties` ang mga deklarasyon ng tool nito, at tumutugon ito ng `400 INVALID_ARGUMENT`. Inaalis ng plugin ang mga keyword na iyon mula sa
mga tool schema na nakalaan para sa isang Gemini model ng provider na ito at hindi nito binabago ang lahat ng iba pang request.
Ang isang tool na may `$ref` ay ipinapasa nang hindi binabago sa halip na alisin ito, dahil ang pag-aalis sa
reference ay magpapalawak sa schema upang "tanggapin ang kahit ano".
Itakda ang `"geminiSanitization": false` upang i-off ito.

## Pag-troubleshoot

| Sintomas                                          | Dahilan                                                                                                                                     |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Walang ipinapakitang OmniRoute model ang Picker   | Walang nalutas na key (tingnan ang babala sa pagsisimula), o hindi maabot ang gateway                                                       |
| Raw model id, walang combos, walang pricing       | Tinanggihan ng mga endpoint ng pamamahala ang token — set `managementReadToken`                                                             |
| Maikli o walang laman `freeOnly` catalog          | Walang token ng pamamahala o tinanggihang token — ang nagbasa ng linya ng buod ng pag-refresh ( bilang ng `unmatched-free` ) sa log ng host |
| Isang session ang naka-pin sa `opencode-<id>/...` | Inilathala ng v1 plugin ang `opencode-<id>`; Ini-publish ng v2 `<id>` bare, kaya muling piliin ang modelo sa ilalim `<id>/...`              |

Ang mga variable ng kapaligiran ay dapat maabot ang proseso ng opencode server: kapag ang host ay tumatakbo bilang isang serbisyo, ang shell na nagpapatakbo `opencode models` at ang kapaligiran ng server ay iba, kaya i-export ang key kung saan ito binabasa ng server.
