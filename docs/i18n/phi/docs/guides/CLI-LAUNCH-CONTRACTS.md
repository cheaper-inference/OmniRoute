Ang neutral na kontrata `config/cli-tools-manifest.json` ay nagdedeklara ng canonical IDs, mga alias, binary na kandidato, mga recipe sa pag-setup, mga argumento ng modelo at mga kakayahan. Ang plain Node adapter sa `bin/cli/cli-manifest.mjs` at ang TypeScript adapter sa `src/shared/constants/cliIntegrationManifest.ts` ay nagbabasa ng parehong file. Ang runtime, catalog, configure, completion, generators at backend registration ay sama-samang sinusuri ng `tests/unit/cli/cli-manifest-drift.test.ts`. Ang pagiging cataloged ay hindi nangangahulugan na ang isang tool ay maaaring ilunsad o i-configure. Sa partikular, ang 5dive ay nananatiling naka-configure lamang.

## Kapaligiran ng bata at siklo ng buhay

`omniroute run`, `omniroute launch` at `omniroute launch-codex` ay nagmamana ng OS/terminal compatibility allowlist at nag-inject ng mga kredensyal ng napiling target. Ang hindi nauugnay na mga lihim ng provider at database ay hindi minana bilang default. tahasang ibinabalik `--inherit-env` ang buong pamana ng parent-environment; gamitin lamang ito kapag ang napiling proseso ng third-party ay dapat tumanggap ng mga halagang iyon. Ito ay pag-filter ng kapaligiran, hindi isang OS sandbox: tumatakbo pa rin ang proseso sa mga pahintulot ng filesystem ng tumatawag.

Ang mga signal ng interrupt at termination ay ipinapasa sa bata. Hinihintay ng launcher ang malapit na kaganapan ng bata bago alisin ang pansamantalang configuration. Kinokontrol ng `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` ang palugit bago ang sapilitang pagwawakas (default na 5000 millisecond).

## Gemini persistent setup

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

Kino-configure ng unang dalawang command ang makinang ito para sa napiling lokal o malayong server. Pinapanatili ng setup ang hindi nauugnay na mga setting JSON, pinipili ang Gemini API-key na auth, at isinusulat ang endpoint at kredensyal sa isang pribadong `.gemini/.env` file. Tinatanggihan nito ang di-wastong JSON sa halip na i-overwrite ito. Ang endpoint URLs ay dapat na HTTP(S), nang walang naka-embed na mga kredensyal, mga parameter ng query o mga fragment. Mga path ng pag-print ng dry-run, hindi mga halaga ng kredensyal.

Pinipili ng `GEMINI_CLI_HOME` o `--gemini-home` ang persistent home root. Ang isang aktwal `run gemini` ay lumilikha at sa ibang pagkakataon ay nag-aalis ng sarili nitong pansamantalang tahanan. Wala sa alinmang mode ang lumalampas sa mga tseke ng workspace-trust ng Gemini.

## mga profile Codex

Nagsusulat `configure codex` ng pribadong `<name>.config.toml` na may modelo at endpoint ng provider OmniRoute nito. Ang mga kredensyal ay nire-reference sa pamamagitan ng `OMNIROUTE_API_KEY`, hindi kailanman naka-embed. Itinatakda ng launch command ang napiling modelo sa pinakamataas na antas `model` key, hindi sa loob `model_providers`.

Ang mga hiwalay na profile file ay ang kasalukuyang nakadokumentong kontrata Codex ; overlay nila ang configuration ng user kapag pinili gamit ang `codex --profile <name>`. Tingnan [ang opisyal na sanggunian sa profile](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) at [ang OmniRoute Codex na gabay](./CODEX-CLI-CONFIGURATION.md).

## Hermetic command execution

Sa isang tahasang `DATA_DIR`, pinipigilan ng pagtatakda ng `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` ang startup na mapunta sa kredensyal na kapaligiran ng default na direktoryo ng data ng user. Ito ay kapaki-pakinabang para sa mga nakahiwalay na pagsubok. Hindi nito pinapagana ang iba pang tahasang napiling mga file sa kapaligiran.

## Working-directory `.env`

Ang CLI ay nagbabasa ng mga `.env` na file sa ganitong pagkakasunud-sunod, at ang unang file na magtakda ng isang susi ay mananalo: ang tahasang `DATA_DIR`, ang default na direktoryo ng data, ang kasalukuyang gumaganang direktoryo, pagkatapos ay ang direktoryo ng package. Palaging panalo ang mga variable ng shell.

Ang gumaganang direktoryo ay maaaring pag-aari ng ibang tao (isang naka-clone na repositoryo, isang naka-unpack na archive), at ipinapasa ng `omniroute serve` ang CLI environment sa server at sa bawat tool na pinapatakbo ng server. Kaya ang isang `.env` doon ay maaaring magtakda lamang ng mga key na ito, na nakalista sa `bin/cli/utils/untrustedCwdEnv.mjs`:

| Susi                            | Mga tinatanggap na halaga                                                              |
| ------------------------------- | -------------------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` o `yes` sa anumang kaso, ang mga halaga na itinuturing ng server bilang on |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | hanggang 64 na letra, digit, `_`, `.`, `@` o `-`                                       |
| `LANGUAGE`                      | pareho, plus `:`                                                                       |
| `TZ`                            | hanggang 64 na letra, digit, `_`, `+`, `-` o `/`, hindi nagsisimula sa `/`             |
| `NO_COLOR`, `FORCE_COLOR`       | hanggang 16 na letra at digit                                                          |

Ino-on ng bawat value na tinatanggap `REQUIRE_API_KEY` ang check, kaya hindi maaaring i-off mismo ng file ang check. Ito ay hindi nagpapasya sa resulta, bagaman: ang server ay nagbabasa ng isang `REQUIRE_API_KEY` override na naka-imbak sa database bago ang kapaligiran, habang ang babala sa startup tungkol sa pakikinig sa lahat ng mga interface na walang API key ay nagbabasa lamang ng kapaligiran. Sa isang nakaimbak na override ng `false`, iniiwan ng gumaganang-direktoryo `REQUIRE_API_KEY=true` ang API na bukas at itinatago ang babalang iyon. Ang panuntunang `TZ` ay mas makitid kaysa sa POSIX: tinatanggihan nito `.`, `:`, `,` at `<>`, kaya kailangang itakda ang `:Area/City` form at mga panuntunan tulad ng `EST5EDT,M3.2.0,M11.1.0` sa shell o sa `<DATA_DIR>/.env`.

Ang mga pangalan ay dapat na eksaktong tumutugma, sa malaking titik. Nilaktawan ang anumang iba pang linya, isang value na nabigo sa pagsusuri nito, at isang pangalan na hindi plain ASCII na mga letra, digit at `_` (halimbawa, isa na may NUL byte o kamukhang-kamukha). Ang CLI ay nagpi-print ng isang babala na nagpapangalan sa mga susi na hindi nito maaaring itakda at isa na nagpapangalan sa mga pinahihintulutang key na binalewala nito, bawat isa ay may kung ano ang babaguhin (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Hindi rin nagpi-print ng mga halaga. Ang mga path ng file sa mga mensaheng ito, at ang mga ulat ng `.env` path `omniroute doctor`, ay tinatakasan kapag naglalaman ang mga ito ng control o bidi na mga character. Ang paghihigpit ay hindi nalalapat kapag ang gumaganang direktoryo ay ang direktoryo ng data o ang direktoryo ng pakete.

`PORT`, `API_PORT` at `DASHBOARD_PORT` ay wala sa listahan. Kung walang base URL mula sa mas mataas na pinagmumulan na pinagmumulan, ang CLI ay nakikipag-usap sa `localhost:<PORT>`, at anuman ang nakikinig doon ay nakakatanggap ng API key ng CLI, ang context token at ang CLI machine token (`x-omniroute-cli-token`, tingnan [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), na tinatanggap ng lokal na server para sa mga tawag sa pamamahala mula sa loopback. Ang isang port mula sa gumaganang direktoryo ay hahayaan ang file na iyon na pumili ng tagapakinig, kaya itakda ang mga port sa shell, sa `<DATA_DIR>/.env` o sa `--port` na opsyon ng mga command na mayroong isa (`serve`, `launch`, `run`).

Ang parser ay walang `export` syntax. Ang isang linya tulad ng `export LD_PRELOAD=...` ay nagpapangalan ng variable `export LD_PRELOAD`; mula sa gumaganang direktoryo ito ay nilaktawan, at sa iba pang mga `.env` file ay itinatakda nito ang literal na pangalan, na walang nababasa.

Ipinapares lang ng CLI ang nakaimbak na token ng konteksto (token ng access o legacy API key) sa sariling pinagmulan ng kontekstong iyon: scheme, host at port, kumpara bilang `URL.origin`. Nalalapat ito sa mga kahilingang ginawa sa pamamagitan ng CLI client ng HTTP (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) at sa `launch`, `launch codex`, `configure` at `setup-*` command na nagsusulat ng base URL at key sa config ng isa pang tool. Itinuro sa isa pang server na may `--remote`, gumagamit sila ng tahasang `--api-key` o `OMNIROUTE_API_KEY` kung nakatakda ang isa, at walang context token. Eksakto ang paghahambing, kaya `localhost` at `127.0.0.1`, o isang host na may at walang sumusunod na tuldok, ay binibilang bilang magkaibang mga server at hindi nakakakuha ng context token. Ang isang URL na may userinfo, isang backslash o whitespace ay hindi kailanman tumutugma, dahil ang ibang URL parser (halimbawa, `urllib` at `httpx` ng Python) ay makakabasa ng ibang host mula rito. Para sa mga kahilingan na ipinapadala mismo ng CLI, ang tseke na iyon ay sumasaklaw lamang sa scheme at awtoridad, kaya pinapanatili ng isang id na may puwang sa landas o query ang token.
