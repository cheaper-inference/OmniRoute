> Mga runtime toggle na nagbabago sa gawi ng OmniRoute **nang hindi muling nagde-deploy**.
> Ang bawat flag na nakalista rito ay tinukoy sa
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — ang nag-iisang pinagmumulan ng katotohanan. Parehong nagbabasa ang dashboard at ang REST API mula sa
> file na iyon, kaya ang talahanayan sa ibaba ay binuo upang tumugma rito nang 1:1.

---

## Ano ang Mga Feature Flag

Ang feature flag ay isang may-pangalang toggle (boolean o enum) na maaaring baguhin ang value
habang tumatakbo at i-persist sa database, nang hindi kinakailangang muling i-deploy ang proseso. Ang bawat
flag ay inilalarawan ng isang `FeatureFlagDefinition` na may `key`, `label`,
`description`, `category`, `defaultValue`, `type`, at isang `requiresRestart` na pahiwatig.

### Pagkakasunod-sunod ng Pag-resolve

Ang **effective value** ng isang flag ay nire-resolve ng
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ayon sa sumusunod na
pagkakasunod-sunod ng prayoridad (pinakamataas ang mananaig):

1. **DB override** — isang value na nakaimbak sa talahanayang `key_value` sa ilalim ng
   namespace na `feature_flags` (itinakda sa pamamagitan ng dashboard o REST API).
2. **Environment variable** — `process.env[<KEY>]`, kung nakatakda at hindi walang laman.
3. **Default ng definition** — ang `defaultValue` mula sa `featureFlagDefinitions.ts`.

Itinuturing na **enabled** ang isang boolean flag kapag ang effective value nito ay `"true"`,
`"1"`, o `"yes"` (tingnan ang `isFeatureFlagEnabled()`).

> [!NOTE]
> Karamihan sa mga flag ay mayroon ding katugmang environment variable na may **parehong pangalan**
> na nakadokumento sa [`ENVIRONMENT.md`](./ENVIRONMENT.md). Mas inuuna ang DB override ng flag
> kaysa sa environment variable na iyon. Ang isang flag na may
> `requiresRestart: true` ay agad na pini-persist ngunit muli lamang binabasa sa pagsisimula ng proseso
> — ang pag-toggle rito ay nagpapakita ng banner na **"I-restart ang Server"** sa dashboard.

Ang mga diagnosis ng transportasyon (`network_error`, `upstream_unavailable`, `upstream_rate_limited`) ay palaging nananatiling walang tiyak na paniniwala at hindi hinaharangan ang pagpapadala, kahit na naka-off ang flag na ito. Kapag naka-enable, ang iba pang mga hindi tiyak na pagsusuri (mga hindi maliwanag na error, hindi sinusuportahang mga pagsisiyasat at hindi na-type na mga error sa scheduler) ay ituturing ding hindi alam, na nagpapahintulot sa trapiko. Naka-off bilang default: hinaharangan pa rin ng iba pang mga naka-cache na probe error ang pagpapadala para sa cache TTL (5 minuto). |

> [!NOTE]
> `INPUT_SANITIZER_BLOCK_THRESHOLD` at ang legacy na alyas `INJECTION_GUARD_BLOCK_THRESHOLD` ay ibagay ang `block` mode ng `INJECTION_GUARD_MODE`, ngunit ang mga ito ay mga simpleng variable ng kapaligiran na binabasa ng [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts), hindi nagtatampok ng mga flag: wala silang DB override at walang dashboard toggle. Tingnan ang [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication).

> [!NOTE]
> Ang `Restart` column ay minarkahan ang mga flag na may `requiresRestart: true` — ang value ay nananatili kaagad ngunit magkakabisa lamang pagkatapos mag-reload ang proseso. Ang mga flag ng Enum ay tinatanggihan ang anumang halaga sa labas ng kanilang pinapayagang hanay (na-validate ang server-side sa parehong `setFeatureFlagOverride()` at ang REST `PUT` handler).

## Toggling Flags

### Dashboard

Mag-navigate sa** Dashboard → Mga Setting → Mga Flag ng Feature** (`/dashboard/settings/feature-flags`). Sinusuportahan ng grid (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) ang:

- **Maghanap** sa pamamagitan ng susi o paglalarawan, at** salain** ayon sa kategorya (kasama ang isang synthetic** Nangangailangan ng I-restart** view).
- A** magpalipat-lipat** para sa mga boolean flag at a** dropdown** para sa mga flag ng enum (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- A** badge ng pinagmulan** bawat flag — `DB`, `ENV`, o `DEF` — na nagpapakita kung saan nanggaling ang epektibong halaga.
- A** I-reset** button (ipinapakita lamang para sa `DB` -sourced flag) upang i-drop ang override, at a** I-reset ang Lahat ng Pag-override** button sa ibaba.
- A** I-restart ang Server** banner kapag binago ang isang `requiresRestart` flag.

### REST API

Ang lahat ng mga operasyon ay dumadaan sa iisang ruta: [`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts). Ang bawat pamamaraan ay nangangailangan ng isang napatotohanan na sesyon ng dashboard (`401` kung hindi man).

Kapag hindi pinagana ang pag-log in (`requireLogin=false`) ang ruta ay bukas, maliban sa mga protektadong flag: bawat bandila sa kategoryang Seguridad kasama ang `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`, `OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS`, `MITM_DISABLE_TLS_VERIFY`, `OMNIROUTE_MCP_ENFORCE_SCOPES` at `SKILLS_SANDBOX_NETWORK_ENABLED` (`isProtectedFeatureFlag()` sa `protectedFeatureFlags.ts`). Ang isang `PUT` sa isa sa mga ito, at isang `DELETE` habang ang isa sa mga ito ay may DB override, kailangan pa rin ng isang dashboard session, isang `manage` -scope API key, isang `oma_` access token na may write scope o mas mataas, o ang CLI token o internal-service token na ipinadala mula sa loopback. Ang hanay na iyon ay mas malawak kaysa sa pag-log in, kung saan ang ruta ay tumatanggap lamang ng isang session o isang `manage` -scope key.

#### `GET /api/settings/feature-flags`

Ibinabalik ang bawat flag kasama ang epektibong halaga, pinagmulan, at isang buod.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 126 flags
  ],
  "summary": {
    "total": 126,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Magtakda o mag-alis ng isang override. Katawan: `{ key: string; value?: string }`. Ang pagtanggal sa `value` ay nag-aalis ng override (nagpapanumbalik ng env / default).

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Ang tugon ay umaalingawngaw sa bagong `effectiveValue`/`source`, ang `previousValue`/ `previousSource`, at `requiresRestart`. Ang mga hindi kilalang key at out-of-range na mga halaga ng enum ay tinanggihan ng `400`.

#### `DELETE /api/settings/feature-flags`

Nililinis** lahat** sabay-sabay na nag-o-override ang DB, nire-restore ang bawat flag sa env / default na value nito. Ibinabalik ang `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Ang mga flag na may `requiresRestart: true` ay magkakabisa lamang pagkatapos ng proseso ng pag-reload. Ang restart flow ng dashboard ay tumatawag `POST /api/restart` at pagkatapos ay nag-poll ng `GET /api/health/ping` hanggang sa ma-back up ang server.

## Pang-emergency na Fallback sa Badyet

Kinokontrol ng `OMNIROUTE_EMERGENCY_FALLBACK` (kategoryang `runtime`, default na `true`) ang
pang-emergency na libreng fallback path sa
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Kapag naka-enable, ang mga request na nakaubos ng kanilang badyet ay niruruta sa isang libreng fallback na
provider/model sa halip na tuluyang mabigo. Itakda ito sa `false` (o `0`) — sa pamamagitan ng
toggle sa dashboard, isang override sa DB, o ng `OMNIROUTE_EMERGENCY_FALLBACK`
environment variable — upang i-disable ang gawi at hayaang mabigo ang mga request na
nakaubos ng badyet. (Inilantad bilang toggle sa dashboard sa mga PR #3741 / #3752.)

Ang tugon na ibinigay ng fallback na ito ay may
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, upang
malaman ng client na muli itong niruta nang hindi inihahambing ang `X-OmniRoute-Provider` sa
request nito. Wala ang header na ito sa lahat ng iba pang tugon.
