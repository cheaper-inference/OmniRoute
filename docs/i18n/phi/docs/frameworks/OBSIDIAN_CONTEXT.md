## Ano ito

Kumokonekta ang OmniRoute sa isang **Obsidian** vault bilang **pinagmumulan ng konteksto** — isang lokal na
Markdown knowledge base na binabasa at sinusulatan ng mga agent sa pamamagitan ng built-in na MCP server. Ang
integration ay nakikipag-ugnayan sa **Obsidian Local REST API** community plugin na tumatakbo sa loob ng
desktop app, kaya maaaring maghanap ang mga agent sa mga note, magbasa/magsulat/mag-patch ng mga file, ilista ang vault, gumawa
sa mga pang-araw-araw/panglingguhang periodic note, mamahala ng mga tag, magpatakbo ng mga Obsidian command, at (opsyonal)
mag-coordinate ng bidirectional na desktop↔mobile vault sync.

Binabalot ng client (`src/lib/obsidian/api.ts`) ang Local REST API gamit ang:

- **Muling pagsubok na may backoff** para sa pansamantalang `5xx`, **30-segundong timeout** sa pamamagitan ng `AbortController`.
- **Typed na pag-uuri ng error** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Isang **madaling maunawaang pahiwatig na "hindi maabot ang Obsidian"** na binibigyang-diin ang karaniwang pagkakamali sa port
  (HTTP sa `27123`, **hindi** ang MCP endpoint sa `27124`) at ang anyo para sa Tailscale.
- **Path encoding** na relative sa vault upang maging ligtas ang mga path ng note na may mga space/slash.

## Setup

meron** walang environment variable** para sa Obsidian token o base URL — pareho ay nakaimbak sa SQLite `key_value` table (namespace `obsidian`) sa pamamagitan ng `src/lib/db/obsidian.ts`. Ang token ay** naka-encrypt sa pahinga** (AES-256-GCM, na may plaintext na backward-compat fallback). I-configure mula sa** Mga Pinagmumulan ng Konteksto** tab ng Endpoint dashboard (`ObsidianSourceCard`), o sa pamamagitan ng mga setting REST API.

> [!IMPORTANT]
> Ang**Obsidian Lokal REST API** dapat na naka-install at tumatakbo ang plugin. Nakikinig ang REST interface nito**HTTP `127.0.0.1:27123`** (ang default na base URL). Ang port `27124` ay isang _separate_ MCP/HTTPS endpoint at tahasang tinatanggihan ng ruta ng mga setting. Kung kumokonekta mula sa ibang device, gamitin `http://<tailscale-ip>:27123`.

### Mga susi sa pagsasaayos (SQLite `key_value`, namespace `obsidian`)

| Susi              | Layunin                                                   | Naka-encrypt |
| ----------------- | --------------------------------------------------------- | ------------ |
| `api_key`         | Lokal na REST API bearer token                            | oo           |
| `base_url`        | REST base URL (default `http://127.0.0.1:27123`)          | hindi        |
| `vault_path`      | Ganap na landas sa direktoryo ng vault (para sa pag-sync) | hindi        |
| `webdav_username` | Binuo na WebDAV username (vault sync)                     | hindi        |
| `webdav_password` | Binuo na WebDAV password (vault sync)                     | oo           |
| `webdav_enabled`  | Kung pinagana ang WebDAV vault sync                       | hindi        |

### I-configure sa pamamagitan ng REST

```bash
# Save + validate the Local REST API token (POST validates via a status check)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Check connection status (returns connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Disconnect (clears the stored token)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Ang lahat ng mga pamamaraan ay nangangailangan ng pagpapatunay ng dashboard. `POST` ay tinatanggihan ang anumang URL sa port `27124` at pinapatunayan ang token sa pamamagitan ng pagtawag sa Lokal REST API status endpoint bago magpatuloy.

### WebDAV vault sync

`src/app/api/settings/obsidian/webdav/route.ts` ay namamahala ng isang opsyonal na WebDAV-backed vault sync (na hinimok ng `src/lib/obsidianSync.ts`). Ang pagpapagana nito ay tumuturo ng OmniRoute sa isang lokal na direktoryo ng vault at nagbibigay ng random na pares WebDAV username/password :

```bash
# Enable WebDAV sync for a vault directory (mints username/password)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Get WebDAV sync status (credentials returned only while enabled)
curl http://localhost:20128/api/settings/obsidian/webdav

# Disable WebDAV sync (clears credentials + managed .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Seguridad at Transportasyon

WebDAV authentication ay nagpapatupad ng per-IP failure tracking at lockout (10 nabigong pagtatangka sa loob ng 60 segundong window ay nagti-trigger ng 5 minutong lockout na may `429 Too Many Requests` at `Retry-After`). Dahil nagpapadala ang WebDAV ng mga pangunahing kredensyal sa pagpapatotoo, ang pagwawakas ng TLS (o pagruruta sa isang secure na tunnel gaya ng Tailscale o Cloudflare Tunnel) ay lubos na inirerekomenda kapag ina-access ang WebDAV endpoint sa labas ng loopback.

### Per-API-key context source (opsyonal)

Obsidian config ay maaaring saklaw** bawat API key** sa pamamagitan ng `api_key_context_sources` table (`src/lib/db/apiKeyContextSources.ts`). Kapag ang isang MCP na tawag ay nagdadala ng napatunayang API key id, mas gusto ng `getObsidianConfigForApiKey()` ang sariling token/base-URL/vault-path (`source: "api_key"`) ng key na iyon at kung hindi man ay bumabalik sa pandaigdigang config (`source: "global"`).

Ang mga tool na hindi naka-sync MCP ay nangangailangan ng nalutas na pagkakakilanlan ng tumatawag bago basahin ang configuration na ito. Ang isang tumatawag na walang pagkakakilanlan ay tumatanggap `Obsidian API token not configured`, at walang kahilingan sa vault na ipinadala. Ang mga tumatawag HTTP ay nalutas sa pamamagitan ng kanilang mga kredensyal sa kahilingan; Ang mga tumatawag sa stdio ay maaaring malutas sa pamamagitan ng `OMNIROUTE_API_KEY` o `ROUTER_API_KEY`. Ang isang hindi nalutas HTTP na tumatawag ay hindi maaaring magmana ng pagkakakilanlan sa kapaligiran ng server. Ang placeholder IDs lamang ay hindi nagpapahintulot ng pag-access; nananatiling suportado ang isang wastong kredensyal sa kapaligiran na lumalabas sa `env-key`. Ang mga na-authenticate na key na walang per-key Obsidian configuration ay nagpapanatili ng pandaigdigang fallback. Pinapanatili ng apat na `obsidian_sync_*` tool ang kanilang hiwalay na pag-uugali ng sync-token.

## MCP tools (22)

Tinukoy sa `open-sse/mcp-server/tools/obsidianTools.ts`. Ang token/base-URL ay naresolba sa bawat tawag (per-API-key muna, pagkatapos ay global). Mga tool na tumama sa OmniRoute** sync server** (ang apat `obsidian_sync_*` tool) ay nangangailangan din ng sync auth token na na-configure sa mga setting OmniRoute.

### Magbasa ng mga tool (`read:obsidian`)

| Tool                         | Paglalarawan                                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Suriin kung ang Lokal REST API ay naaabot at napatotohanan.                                                    |
| `obsidian_search_simple`     | Full-text na paghahanap ng nilalaman ng tala; nagbabalik ng mga snippet na may mga path ng file.               |
| `obsidian_search_structured` | Maghanap gamit ang JSON Logic expression ( mga filter and/or/regex/path ).                                     |
| `obsidian_read_note`         | Magbasa ng tala sa pamamagitan ng vault-relative path; opsyonal na isang partikular heading/block/frontmatter. |
| `obsidian_list_vault`        | Maglista ng mga file at direktoryo sa vault (puno ng mga entry).                                               |
| `obsidian_get_document_map`  | Kunin ang istraktura ng heading ng tala bilang isang mapa ng mga heading → line number.                        |
| `obsidian_get_note_metadata` | Kumuha ng frontmatter, mga tag, link, bilang ng char/word nang wala ang buong nilalaman.                       |
| `obsidian_get_active_file`   | Kunin ang path + na nilalaman ng kasalukuyang aktibong file sa Obsidian.                                       |
| `obsidian_get_periodic_note` | Kunin ang daily/weekly/monthly periodic note para sa isang petsa (ngayon kung aalisin).                        |
| `obsidian_get_tags`          | Ilista ang lahat ng mga tag ng vault sa kanilang mga frequency.                                                |
| `obsidian_list_commands`     | Ilista ang magagamit na Obsidian command IDs (gamitin kasama ang `obsidian_execute_command`).                  |
| `obsidian_sync_status`       | OmniRoute sync server status: tumatakbo, pangalan ng vault, port, uptime, huling pag-sync.                     |
| `obsidian_sync_conflicts`    | Maglista ng mga hindi naresolbang salungatan sa pag-sync (path, conflict path, detected-at).                   |

### Mga tool sa pagsulat (`write:obsidian`)

| Tool                             | Paglalarawan                                                                                               |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Gumawa o mag-overwrite ng tala na may ibinigay na Markdown na content.                                     |
| `obsidian_append_note`           | Magdagdag ng nilalaman sa isang tala; opsyonal sa isang partikular heading/block.                          |
| `obsidian_patch_note`            | Surgically append/prepend/replace sa isang heading, block, o frontmatter field.                            |
| `obsidian_delete_note`           | Permanenteng tanggalin ang isang tala mula sa vault.                                                       |
| `obsidian_move_note`             | Ilipat o palitan ang pangalan ng tala sa loob ng vault.                                                    |
| `obsidian_execute_command`       | Magsagawa ng Obsidian command sa pamamagitan ng utos nito ID.                                              |
| `obsidian_open_file`             | Magbukas ng file sa Obsidian (gumawa ito kung wala ito).                                                   |
| `obsidian_sync_trigger`          | Mag-trigger ng agarang bidirectional desktop ↔ mobile vault sync.                                          |
| `obsidian_sync_resolve_conflict` | Lutasin ang isang salungatan sa pag-sync: panatilihin `local` (mobile), `remote` (desktop), o `keep-both`. |

> [!NOTE]
> tumatanggap ang mga `obsidian_patch_note` target ng `targetType` ng `heading | block | frontmatter` at `operation` ng `append | prepend | replace`, na may opsyonal na `createTargetIfMissing`. Ang apat na `obsidian_sync_*` tool ay nakikipag-usap sa lokal na sync server (`http://127.0.0.1:27781` bilang default) at nangangailangan ng sync token.

### Saklaw

Ang mga tool sa pagbabasa ay nangangailangan ng `read:obsidian`; ang mga tool sa pagsulat ay nangangailangan ng `write:obsidian`. Ang pagpapatupad ay kapareho ng Notion — na pinangangasiwaan ng `withScopeEnforcement()` sa `open-sse/mcp-server/server.ts`, naka-gate sa `OMNIROUTE_MCP_ENFORCE_SCOPES=true` at pinilit na naka-on para sa mga HTTP/SSE na tumatawag na ang API key ay walang `manage`/`admin`, na may mga pinapayagang saklaw na nagmula sa `OMNIROUTE_MCP_SCOPES` o sa konteksto ng saklaw ng API key. Tingnan ang [MCP-SERVER.md](./MCP-SERVER.md).

## Mga Endpoint

| Paraan   | Path                            | Layunin                                                             |
| -------- | ------------------------------- | ------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Ibalik ang `{ connected, hasToken, baseUrl, vaultPath }`.           |
| `POST`   | `/api/settings/obsidian`        | I-save at i-validate ang token (tinatanggihan ang port na `27124`). |
| `DELETE` | `/api/settings/obsidian`        | Idiskonekta (burahin ang nakaimbak na token).                       |
| `GET`    | `/api/settings/obsidian/webdav` | Status ng WebDAV sync at mga kredensyal (habang naka-enable).       |
| `POST`   | `/api/settings/obsidian/webdav` | I-enable ang WebDAV sync para sa isang vault directory.             |
| `DELETE` | `/api/settings/obsidian/webdav` | I-disable ang WebDAV sync.                                          |

> Ang mga ito ay mga route ng mga setting ng dashboard. Naa-access ang vault mismo sa pamamagitan ng Obsidian
> Local REST API (ang naka-configure na `base_url`) at sa pamamagitan ng mga MCP tool sa itaas — walang
> pampublikong `/v1` Obsidian proxy endpoint.

## Mga sitwasyon ng paggamit

- **Mga sagot na nakabatay sa vault** — `obsidian_search_simple` / `obsidian_search_structured`
  pagkatapos ay `obsidian_read_note` upang sumagot ang isang agent batay sa iyong mga aktuwal na tala.
- **Pagsulat ng tala / pag-journal** — `obsidian_write_note`, `obsidian_append_note`, o
  ang eksaktong `obsidian_patch_note` upang i-log sa vault ang output ng agent, mga buod, o mga pang-araw-araw na tala
  (`obsidian_get_periodic_note`).
- **Pag-navigate sa vault** — `obsidian_list_vault`, `obsidian_get_document_map`, at
  `obsidian_get_tags` upang galugarin ang istruktura bago magbasa/magsulat.
- **Pag-automate ng Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` upang
  patakbuhin ang mga plugin/command mula sa isang agent; `obsidian_open_file` upang ipakita ang isang tala sa UI.
- **Pag-sync sa mobile** — i-enable ang WebDAV sync, pagkatapos ay gamitin ang `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  upang i-coordinate ang desktop↔mobile at lutasin ang mga conflict.
