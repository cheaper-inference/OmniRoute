Hinahayaan ng `devin-cli-agentic` ang tunay na Claude Code runtime na gamitin ang lokal na Anthropic
Messages endpoint ng OmniRoute habang ibinibigay ng opisyal na Devin CLI ang mga tugon ng modelo sa
pamamagitan ng ACP stdio. Hindi nito binabago ang mga kasalukuyang Anthropic, Claude OAuth, Claude Web,
o `devin-cli` provider.

Para sa mga tool call na pagmamay-ari ng client, mag-route sa pamamagitan ng `devin-cli-agentic` (alias na `dva`),
ang provider na may format na Claude at sumusuporta sa mga tool. Text-only ang legacy na `devin-cli` (`dv`)
ACP executor: pinapatakbo nito ang no-tools summarizer ng Devin at hindi ito makapagbabalik ng mga tool call.
Minarkahan nang naaayon ang metadata ng modelo nito upang iwasan ito ng combo routing na nangangailangan ng tool.

> **Kasalukuyang katayuan: naka-pin sa Claude Code `2.1.258`; huling naitala ang offline at live na
> validation sa `2.1.220`.** Nakumpleto ng `2.1.220` pin ang tatlong nakahiwalay na scenario sa pamamagitan
> ng Devin CLI `3000.2.17` at modelong `swe-1-7-lightning`; pinatunayan ng huling live run na iyon ang mga
> client-owned na `Read`, `Edit`, at `Bash` turn, matagumpay na mga resulta ng `npm test`, pagtuklas ng
> project command at skill, Devin-only routing, at zero Claude egress. Pagkatapos ay itinaas ang pin sa
> `2.1.258` (ang henerasyon ng CLI na ginagaya ng Claude identity ng OmniRoute, at ang unang linya na
> native na naglalaman ng Fable 5.1 tier). Sa bagong pin, na-verify ang installation layer at
> `claude --version` sa naka-pin na base image, at pumapasa ang bridge unit suite, `compose config`, at
> static isolation proof — ngunit hindi pa muling pinapatakbo ang offline mock scenario at ang live na
> three-scenario suite. Muling patakbuhin ang mga ito (tingnan ang "Pag-update ng mga naka-pin na tool")
> bago umasa sa bridge gamit ang pin na ito.

## Arkitektura

```text
Claude Code 2.1.258 (nakahiwalay na non-root Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format, no-auth provider)
  -> devin acp --agent-type summarizer (opisyal na ACP stdio, walang Devin tools)
  -> Devin account sa nakalaang devin-auth volume
```

Maaaring magpatakbo ang default na ACP agent ng opisyal na CLI ng sarili nitong mga tool, kaya hindi ito
ginagamit ng bridge na ito. Sinisimulan nito ang nakapirming `summarizer` ACP agent, na walang mga tool sa
opisyal na CLI mode nito, at binabalangkas ang serialized na Anthropic request bilang isang execution trace.
Kapag kailangan ng isa pang action na pagmamay-ari ng Claude, dapat maglaman ang tugon ng eksaktong isang
client tool envelope. Tinatanggihan ang anumang ACP `tool_call` o `tool_call_update` bago maiulat na
matagumpay ang isang tugon.

Pinapanatili ng serializer sa `open-sse/executors/devin-agentic/serializer.ts` ang `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, at ang
mga tool na ibinigay ng Claude Code. Tahasang nagdudulot ng failure ang mga image at hindi kilalang block.
Gumagamit ang malalaking tool result ng nakikitang truncation marker.

Tumatanggap ang parser ng isang hiwalay na `<tool>{...}</tool>` envelope sa bawat model turn. Sinusuri
nito ang pangalan laban sa listahan ng mga tool ng request, vina-validate ang mga argument laban sa JSON
Schema ng tool na iyon, tinatanggihan ang pinaghalong narrative/action, at nagpapahintulot ng isang bounded
repair. Pagkatapos, lokal na pinapatakbo ng Claude Code ang resultang Anthropic `tool_use` at ipinadadala
pabalik ang `tool_result` sa pamamagitan ng OmniRoute.

## Awtomatikong pag-route

Kwalipikado ang provider sa mga `auto/*` candidate pool ng OmniRoute kapag hindi ito naka-block.
Hindi ginagarantiya ng pagiging kwalipikado bilang candidate ang pagpili: maaaring piliin ng routing strategy
ng combo (halimbawa, last-known-good) ang ibang provider. Gamitin ang `dva/<model>` o isang Devin-first combo
kapag kailangan mong dumaan sa Devin ang bawat request.

## Paghihiwalay at modelo ng banta

Hindi saklaw at itinuturing na ipinagbabawal ang installation, account, at configuration ng Claude sa host. Ang mga serbisyo ng Compose ay:

- tumatakbo bilang UID/GID `10001:10001`, na may read-only na root filesystem, mga inalis na capability, at
  `no-new-privileges`;
- gumagamit ng pribadong `/home/bridge`, nakalaang Claude config volume, nakahiwalay na data ng OmniRoute,
  at hiwalay na `devin-auth` volume;
- nagma-mount lamang ng mga disposable na `.sandbox` workspace/ebidensya;
- hindi nagma-mount ng host home, Keychain, mga credential ng SSH at cloud, o Docker socket;
- bumubuo ng mga tahasang environment at nag-aalis ng mga variable ng Anthropic API/OAuth/routing;
- nagdidirekta ng inference ng Claude Code sa `http://omniroute:20128` lamang gamit ang local-only na key.

Gumagamit ang offline profile ng internal na network. Sa live profile, naaabot lamang ng OmniRoute ang mga
opisyal na endpoint ng Devin sa pamamagitan ng `network-guard`; tinatanggihan ang mga hindi kaugnay na destinasyon.
May hiwalay na deny-all egress guard ang Claude Code at maaabot lamang nito ang lokal na serbisyo ng OmniRoute
sa pamamagitan ng `NO_PROXY`. Ang mga audit file ng guard ay mino-mount lamang ng kani-kanilang proseso ng guard. Bine-verify ng
mga script ang pagmamay-ari ng file, mode, bilang ng link, at bawat desisyon bago mag-export ng
ebidensyang walang token.

Patakbuhin nang hiwalay ang patunay ng paghihiwalay:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Bine-validate nito ang topology, mga pinangalanang mount, mga setting na non-root/read-only, tahasang lokal na routing,
kawalan ng mga sensitibong environment variable, kawalan ng Docker socket, naka-block na access sa
`api.anthropic.com` at `claude.ai`, pagpili lamang sa Devin bilang provider, at tahasang pagkabigo kapag
hindi available ang ACP backend.

## Paunang pag-setup at normal na paggamit

I-build ang naka-pin na image:

```bash
./scripts/devin-bridge/build
```

I-authenticate lamang ang nakahiwalay na Devin volume:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Ginagamit ng login command ang opisyal na manual-token flow na inilaan para sa mga remote/container
environment. Direktang inilalagay ang value sa CLI prompt; hindi ito ipinapasa bilang
process argument, isinusulat sa Git, o kinokopya mula sa host.

Ilunsad ang nakahiwalay na Claude Code runtime:

```bash
./scripts/devin-bridge/launch
```

Muling sinusuri ng `launch` ang paghihiwalay, authentication ng Devin, at pagtuklas ng modelo bago simulan ang
naka-container na Claude Code. Hindi nito kailanman pinapatakbo ang Claude executable ng host. Maaaring
itakda ang mga alias ng modelo sa `.env.devin-bridge`; dapat panatilihin ng bawat naka-configure na value ang
prefix na `devin-cli-agentic/`.

## Mga command sa validation

Hindi nangangailangan ng Devin account at walang runtime Internet ang reproducible na offline path:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Ang authenticated na opt-in live path ay:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Naghihintay ang live runner sa pagitan ng mga scenario upang maiwasang magbukas ng magkakasunod na ACP session at
bine-validate nito ang mga structured na Claude stream event sa halip na magtiwala sa mga textual na pahayag. Pinatutunayan ng tatlong
scenario nito ang:

1. direktang pagbasa sa proyekto at pagsusuri ng depekto;
2. isang tunay na `Edit`, isang `Bash` `npm test` na pagmamay-ari ng client, at isang terminal na resulta;
3. pagtuklas sa `/bridge-check` at `bridge-proof`, mga pagbasa sa proyekto, isa pang matagumpay na
   `npm test` na pagmamay-ari ng client, at pagkumpleto nang walang nakabinbing gawain.

Sinusuri rin ng panghuling gate ang network audit ng Devin at iniaatas na manatiling
walang laman ang egress audit ng Claude.

## Pag-update ng mga naka-pin na tool

Naka-pin sa image ang Node, Claude Code, at Devin CLI sa
`docker/devin-bridge/Dockerfile`. Upang mag-update:

1. baguhin ang mga tahasang tinukoy na bersyon;
2. palitan ang parehong checksum ng Devin archive na partikular sa arkitektura gamit ang mga halaga para sa opisyal na artifact;
3. muling i-build at patakbuhin ang bawat offline na validation command;
4. kumpirmahin ang mga bersyon sa loob ng image;
5. muling patakbuhin ang authenticated na live suite na may tatlong scenario.

Huwag i-install nang global ang alinmang CLI sa host o palitan ang checksum verification ng
hindi na-verify na download.

## Diagnosis at paglilinis

- Ipinapakita ng `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  ang lokal na routing at mga na-sanitize na error ng executor.
- Itinatala ng `.sandbox/evidence/mock-acp.jsonl` ang mga deterministic na mock ACP action.
- Itinatala ng `.sandbox/evidence/claude-stream.jsonl` ang totoong offline na pagpapatakbo ng Claude Code.
- Itinatala ng `.sandbox/evidence/live-*.jsonl` ang tatlong na-validate na live stream.
- Ang `.sandbox/evidence/egress.jsonl` at `.sandbox/evidence/claude-egress.jsonl` ay mga na-validate
  at token-free na kopya ng mga guard audit.

Ihinto ang mga pag-aari nitong container at network habang pinapanatili ang mga volume ng login/config:

```bash
./scripts/devin-bridge/clean
```

Alisin ang kumpletong environment na pag-aari ng bridge, kabilang ang mga pinangalanang volume:

```bash
./scripts/devin-bridge/clean --all
```

## Mga limitasyon

- Umaasa ang bridge sa nakapirming no-tools na role na `summarizer` dahil hindi
  naglalantad ang Devin CLI `3000.2.17` ng neutral na no-tools ACP agent. Binabawi ng adapter
  ang mga intermediate response na kahugis ng summary, ngunit maaari pa ring tahasang mabigo ang isang
  limitadong repair.
- Maaaring magbalik ang mga live ACP call ng pansamantalang `502`/`504` na response. Nilalagyan ng harness ng pagitan ang mga scenario;
  ang patuloy na pagkabigo ay nananatiling fail-closed at hindi kailanman pumipili ng ibang provider.
- Muling binubuo ang ACP context mula sa bawat Anthropic request; walang affinity sa process/session.
- Isang tool call ang sinusuportahan sa bawat model response; tinatanggihan ang mga parallel call.
- Tahasang hindi sinusuportahan ang mga image. Hindi ina-advertise ang vision, thinking output, effort control, at 1M
  context window.
- Gumagamit ang SSE ng mga wastong Anthropic lifecycle event ngunit inilalabas lamang matapos
  makolekta ang limitadong ACP turn; hindi ipinapasa nang incremental ang mga ACP chunk.
