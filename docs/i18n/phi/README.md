## Libreng Token sa isang Buwan: ~ 11.3B bilang Bilang ng Iba · ~ 90M Real

</div>

> **~ 11.3B libreng token / buwan** Binibilang ng <br/> <sub> ang paraan ng pagbibilang ng iba pang mga katalogo: bawat row ay idinagdag, ang mga natapos na alok ay kasama ang </sub>
>
> **~ 90M real ngayon**<br/> <sub> bawat nakabahaging quota ay binilang ng isang beses: kung ano talaga ang magagamit mo </sub>
>
> **Lahat dito ay libre. Walang paywall.**<br/> ★ [Gusto ito? Lagyan kami ng star sa GitHub](https://github.com/cheaper-inference/OmniRoute)

Ang ibang mga katalogo ay naniningil mula US$19 sa isang taon hanggang US$49 para sa panghabambuhay na pag-access sa live na data. Dito libre ang lahat. <sub> Sinuri ang mga presyo noong 2026-11-18.</sub>

<sub>Huling na-audit ang Catalog noong 2026-11-23. [Paano namin binibilang →](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **Dalhin ang iyong sariling provider account.** Ito ay mga third-party na libreng tier, hindi isang token grant mula sa OmniRoute. Mag-sign up, kumuha ng mga kredensyal kung saan hinihiling ng isang provider ang mga ito, at ikonekta ang mga magagamit mo. Ang bawat provider ay nagtatakda ng sarili nitong mga limitasyon, kakayahang magamit at mga tuntunin.
>
> Ang pag-stack ng mga libreng tier sa pamamagitan ng kamay ay nangangahulugan ng dose-dosenang SDKs, dose-dosenang mga limitasyon sa rate at walang malinaw na ideya kung ano ang natitira mo. OmniRoute ay nagpapanatili ng 214 na mga hilera ng catalog na may libreng pag-access at kinakalkula ang tunay na bilang mula sa 12 pool na may naka-publish na quota, ang bawat shared pool ay binibilang nang isang beses. Ang mga quota na nagbubukas lamang pagkatapos ng pagsusuri sa pagkakakilanlan ng rehiyon (ngayon, ModelScope) ay ipinapakita nang magkahiwalay, +~ 6M sa likod ng pag-verify ng pagkakakilanlan ng rehiyon, at hindi kailanman idinagdag sa tunay na pigura. Ang natitira ay lumalabas sa dashboard (`/dashboard/free-tiers`).

>

Isang bago ang dumapo at ito ay umaakyat. Ini-publish namin kung ano ang kino-compute ng catalog, hindi kailanman isang round-up na pinakamahusay na kaso.</sub>

## I-install, ikonekta ang isang provider, pagkatapos ay ruta sa isang endpoint

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>`auto` ay nangangailangan ng isang karapat-dapat na ruta. Ang isang bagong pag-install ay maaaring walang karapat-dapat na keyless na mga target, at ang isang keyless provider ay maaaring tanggihan ang mga third-party na kliyente. Ang mga provider na may markang `tos: avoid`, kabilang Kiro, ay hindi kasama sa awtomatikong pagruruta bilang default; ang pagkonekta sa isang account ay hindi override ang setting na iyon. Tingnan ang [Free Tiers Guide](docs/getting-started/FREE-TIERS-GUIDE.md) bago pumili ng provider.</sub>

## Combo: ang punong barko

1. **Magsimula sa `auto`.** Itakda ang modelo sa iyong OpenAI-compatible na kliyente. OmniRoute ay bubuo ng isang virtual na combo mula sa mga konektadong provider at nag-score ng mga kandidato nang live.
2. **Mag-save ng combo para sa higit pang kontrol.** Pumili ng pangalan, listahan ng target at diskarte, pagkatapos ay gamitin ang pangalang iyon bilang modelo. Itinatakda ng diskarte kung aling target ang mauuna at kung paano sinusubukan ang iba.

Awtomatikong isang combo na ruta sa mga modelo. Sa pagkaubos ng quota, pagkabigo ng provider o pag-lock ng modelo, sinusubukan nito ang susunod na karapat-dapat, malusog na target.

### Zero-config: gamitin lang `auto`

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

Ang mga variant ay nagtutugma sa mga timbang. Ang huling-kilalang mahusay na pagruruta ay nananatili sa huling matagumpay na provider hanggang sa mabigo ito, pagkatapos ay mag-rescores. `auto/fast` at `auto/cheap` ay nagpapahayag ng mga kagustuhan nang hindi ginagarantiyahan ang pinakamabilis o pinakamurang modelo.

| Model ID            | Pag-uugali                                                                                                                                                                                                                                                                                                                                        |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`              | Mga balanseng default na timbang.                                                                                                                                                                                                                                                                                                                 |
| `auto/fast`         | Pinapaboran ang mababang latency at kalusugan ng provider.                                                                                                                                                                                                                                                                                        |
| `auto/cheap`        | Pinapaboran ang mas mababang presyo ng catalog.                                                                                                                                                                                                                                                                                                   |
| `auto/coding`       | Pang-kalidad na mga timbang para sa pagbuo ng code.                                                                                                                                                                                                                                                                                               |
| `auto/smart`        | Mga timbang na una sa kalidad na may 10% paggalugad (default 5%).                                                                                                                                                                                                                                                                                 |
| `auto/lkgp`         | Ang tahasang huling-kilalang mahusay na pagruruta na may parehong mga timbang gaya ng `auto`.                                                                                                                                                                                                                                                     |
| `auto/subscription` | Gumagamit lang ng live-verify na quota ng plano. Ibinabalik ang HTTP 503 kapag walang available at iniiwasan ang nasingil na fallback.                                                                                                                                                                                                            |
| `auto/thrifty`      | Magplano → keyless → libreng → murang → premium. Maaaring umabot sa mga sinisingil na modelo at bumalik sa plano kapag pinapayagan ang quota at cooldown.                                                                                                                                                                                         |
| `auto/offline`      | Pinapaboran ang quota at rate-limit headroom. Napupunta pa rin ang mga kahilingan sa iyong mga provider.                                                                                                                                                                                                                                          |
| `auto/chaos`        | Isang modelo sa bawat provider nang magkatulad, hanggang lima bilang default o sampu kapag na-configure. Isang upstream na tawag sa bawat modelo. Ibinabalik ang pinakamataas na ranggo na tugon o ang huling matagumpay na tugon sa panel kung nabigo ang nangungunang modelo. Gamitin `fusion` para mag-synthesize ng mga tugon sa isang judge. |

Kasama sa mga halimbawa ng kategorya at opsyonal na tier ang `auto/coding:fast`, `auto/coding:free`, `auto/reasoning:pro` at `auto/vision`. Kung walang katugmang kandidatong konektado, ibabalik ng kahilingan HTTP 503 at mananatiling makitid ang pool. [Gabay sa Auto-Combo](./docs/routing/AUTO-COMBO.md) · [Pagruruta sa una sa subscription](./docs/routing/SUBSCRIPTION_LADDER.md)

### O bumuo ng sarili mong: 22 diskarte sa pagruruta

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

Tumatanggap ang CLI ng 15 sa 22 na diskarte. Tinatanggap ng dashboard at combos API ang lahat ng 22.

| Diskarte            | Pag-uugali                                                                                                                                                                                                                                                  |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Live ang mga kandidato sa ranggo kasama ang 16-factor Auto-Combo scorer.                                                                                                                                                                                    |
| `cache-optimized`   | Mas gusto ang account na malamang na hawakan ang prompt prefix sa cache.                                                                                                                                                                                    |
| `context-optimized` | Subukan muna ang pinakamalaking kilalang window ng konteksto.                                                                                                                                                                                               |
| `context-relay`     | Panatilihin ang iyong order at magpasa ng buod ng pag-uusap kapag lumipat ng account.                                                                                                                                                                       |
| `cost-optimized`    | Pagbukud-bukurin ayon sa catalog input-token na presyo, hindi alam ang huling. Maaaring mag-iba ang halaga ng huling kahilingan.                                                                                                                            |
| `expiry-first`      | Paggastos ng quota na malamang na mag-expire, pinakamataas na natitira bawat oras hanggang sa i-reset muna.                                                                                                                                                 |
| `fill-first`        | Manatili sa unang available na target hanggang sa maubos o mabigo ito, pagkatapos ay magpatuloy.                                                                                                                                                            |

Ang 16-factor scorer ay gumagamit ng quota, kalusugan, gastos, latency, task fit, stability, tier priority, tier affinity, specificity match, context affinity, cache affinity, availability ng session, reset-window affinity, density ng koneksyon, kalidad at pagiging maaasahan. ### Ang katatagan ay binuo sa: 3 independiyenteng mga layer

Ang mga pagkabigo ay pinangangasiwaan sa tatlong saklaw, kaya hindi inaalis ng isang masamang modelo ang account nito, at hindi tinatanggal ng isang masamang account ang provider nito.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Kung ang isang buong provider ay down

Ang** tagapagbigay ng circuit breaker** magbubukas pagkatapos ng 8 (OAuth) o 12 (API key) na pagkabigo na may status na 408, 500, 502, 503 o 504. Ang mga combo ay laktawan ang provider na iyon habang ito ay bukas. Pagkatapos ng 60 s o 30 s, isang kahilingan sa pagsisiyasat ang magpapasya kung magsasara ito.

#### Kung ang isang susi o account ay limitado sa rate

Ang** cooldown ng koneksyon** benches lamang ang koneksyon na iyon, na may exponential backoff mula 5 s (OAuth) o 3 s (API key). Ang iba pang mga susi para sa parehong provider ay patuloy na nagsisilbi.

#### Kung ang isang modelo ay tinanggihan

Ang** lockout ng modelo** hinaharangan lang ang modelong iyon sa koneksyong iyon pagkatapos ng bawat modelong 429, 404 o pagtanggi sa pag-access. Ang iba pang mga modelo sa parehong koneksyon ay patuloy na nagsisilbi.

Ang mga naka-ban, nag-expire at wala sa kredito na koneksyon ay mga terminal state, hindi mga cooldown: naghihintay sila na ayusin mo ang mga ito.

## Buong CLI, MCP at A2A

> Nagpapadala OmniRoute ng command-line client na may** 91 pinakamataas na antas ng command at command group** (754 na utos na nagbibilang ng mga subcommand), isang**MCP server na may 110 tool at 33 saklaw** , at isang**A2A agent na may 6 na kasanayan** . Ang mga script, terminal at AI agent ay maaaring magpatakbo ng parehong gateway.

### Isang tunay CLI, hindi lang `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

Ginagawa ng global `--output table|json|jsonl|csv` flag na magagamit ang parehong mga command mula sa mga script at CI.

### Remote mode: ang CLI sa iyong laptop, OmniRoute sa isang server

Mag-log in nang isang beses sa isang malayuang server. Ini-save ito ng CLI bilang a** konteksto** , at ang mga command sa ibang pagkakataon ay tumatakbo laban sa server na iyon hanggang sa bumalik ka.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Saklaw ng token | <img width="2000" height="0" alt=""> Ano ang pinapayagan nito         |
| --------------- | --------------------------------------------------------------------- |
| `read`          | Ilista at siyasatin: mga modelo, katayuan, mga tala, paggamit         |
| `write`         | `read` plus i-configure at ilapat: setup ng kliyente, mga key, config |
| `admin`         | `write` plus pamahalaan: mga token, provider, serbisyo, patakaran     |

Ang isang hubad na host ay nakakakuha `http://` at port 20128; ipasa ang isang buong `https://` URL kapag ang server ay nakaupo sa likod TLS. Ang mga ruta na maaaring magbunga ng mga proseso ay mananatiling loopback-only, anuman ang token.

### Ikonekta ang isang ahente

Ang isang ahente, o ang iyong sariling code, ay maaaring humimok ng pagruruta, mga provider, combos, cache, compression at memory sa pamamagitan ng alinman sa mga interface na ito. Ang mga HTTP path ay inihahatid ng gateway, bilang default sa `http://localhost:20128`.

| Interface                        | Endpoint o utos            | Gamitin ito para sa                                                              |
| -------------------------------- | -------------------------- | -------------------------------------------------------------------------------- |
| MCP sa stdio                     | `omniroute --mcp`          | Claude Desktop, Cursor at iba pang lokal na kliyente MCP                         |
| MCP sa ibabaw ng Streamable HTTP | `/api/mcp/stream`          | Mga remote MCP client: 110 tool, 33 scope, bawat tawag na nakasulat sa audit log |
| MCP sa SSE                       | `/api/mcp/sse`             | Mga kliyente na gumagamit pa rin ng SSE transport                                |
| A2A pagtuklas                    | `/.well-known/agent.json`  | Agent Card: nagsasabi sa ibang mga ahente kung ano ang magagawa OmniRoute        |
| A2A pagpapatupad                 | `POST /a2a`                | JSON-RPC 2.0 na mga gawain, kasabay o na-stream sa SSE, sa 6 na kasanayan        |
| REST API                         | `/v1/*`                    | OpenAI-compatible na chat, Mga tugon, pag-embed, larawan, audio at OCR           |
| Mga Webhook                      | `/api/webhooks`            | Mga kaganapan sa Slack, Discord, Telegram, o anumang URL na may HMAC signing     |
| Malayong CLI                     | `omniroute connect <host>` | Magmaneho ng malayong instance na may mga saklaw na token ng access              |

Ang anim na kasanayan A2A ay `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` at `list-capabilities`.

**Bago ka kumonekta:**

- **MCP over HTTP ay nagsisimulang hindi pinagana.** I-on ito gamit ang `omniroute mcp enable --transport streamable-http` o mula sa pahina ng Mga Endpoint ng dashboard. Isang HTTP transport ang aktibo sa isang pagkakataon: `streamable-http` serves `/api/mcp/stream`, `sse` serves `/api/mcp/sse`.
- **Nagsisimulang hindi pinagana A2A.** Paganahin ito sa pahina ng Mga Endpoint ng dashboard. Sinusunod ng `POST /a2a` ang parehong mga panuntunan sa API-key gaya ng `/v1`.
- **Ang remote MCP ay nangangailangan ng angkop na susi.** loopback lang ang sinasagot ng `/api/mcp/*` bilang default. Mula sa isa pang host, magpadala ng key na may `manage` o `admin` (lahat ng tool), o may `mcp:connect` kasama ang mga saklaw ng mga tool na kailangan mo. Para sa mga key na walang `manage`/`admin`, palaging ipinapatupad ang mga saklaw ng tool.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

## Makatipid ng 15–95% Token — Awtomatikong

### Paano ito gumagana — pipeline, architecture at savings math

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

Ang default na stacked combo ay tumatakbo `RTK → Caveman`. Kapag parehong kumilos sa parehong tool/context payload, savings compound:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Ang mga bloke ng code, URLs, JSON at structured na data ay** laging protektado** sa pamamagitan ng preservation engine.

> **Bakit gagamit ng maraming token kapag kakaunti ang token na gumagawa ng trick?** Ang bawat kahilingan ay dumadaan sa compression pipeline ni OmniRoute** malinaw** — walang pagbabago sa kliyente. Ngayon ay a** stack ng 12 composable engine** na tumatakbo sa pagkakasunud-sunod at paghahalo at pagtutugma bawat pagruruta combo — pagbuo sa mga ideya mula sa [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua), at [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

### Higit pa sa mga istilo ng output — ng engine, ang adaptive na dial at kontrol sa bawat kahilingan

Hugis ang tugon, i-target ang window ng konteksto ng modelo, o pumili ng compression plan bawat kahilingan.

#### Mga istilo ng output

| Estilo                            | <img width="2000" height="0" alt=""> Ano ang ginagawa nito                                              |
| --------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Terse prosa                       | Pinuputol ang filler at hedging habang pinapanatili ang teknikal na detalye.                            |
| Mas kaunting code                 | Humihingi ng pinakamaliit na pagbabagong gumagana at muling ginagamit ang umiiral na code.              |
| Nakapusod (tamad na senior dev)   | Sinusuri kung ano ang maaaring magamit muli o alisin at humihingi ng pag-aayos sa ugat.                 |
| Mayroon akong ADHD (action-first) | Nangunguna sa aksyon, binibilang ang mga hakbang at nagtatapos sa isang kongkretong susunod na hakbang. |
| Terse CJK (文言)                  | Gumagamit ng maigsi na klasikal na Tsino. Available para sa `zh`.                                       |

Ang bawat istilo ay may `lite`, `full` at `ultra` intensity. Magdagdag ng istilo na may entry sa output style registry.

#### Aangkop na badyet sa konteksto

| Setting   | Mga pagpipilian                                                                                                                                                                                                             |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Patakaran | `reserve-output` (default) ay naglalaan ng puwang para sa tugon at isang margin sa kaligtasan. Gumagamit `percentage` ng bahagi ng window ng konteksto. Nagtatakda `absolute` ng nakapirming token na target.               |
| Mode      | `floor` maaaring palakihin ang napiling plano upang umangkop sa window ng konteksto. Ginagamit ng `replace-autotrigger` ang badyet para sa awtomatikong pagdami. Pinapanatili ng `off` ang auto-trigger ng token-threshold. |

#### Kung saan napagpasyahan ang compression

| Umorder | <img width="2000" height="0" alt=""> Pinagmulan                   |
| ------- | ----------------------------------------------------------------- |
| 1       | Kinikilalang header ng kahilingan sa `x-omniroute-compression`    |
| 2       | Override sa combo ng pagruruta                                    |
| 3       | Aktibong pinangalanang profile                                    |
| 4       | Adaptive na badyet sa konteksto o token-threshold na auto-trigger |
| 5       | Default ng compression panel                                      |
| 6       | Off kapag walang planong nalalapat                                |

Ang global compression switch ay mas priyoridad kaysa sa talahanayang ito. Ang `X-OmniRoute-Compression` response header ay nag-uulat ng `<mode>; source=<source>`.

[Gabay sa compression](docs/compression/COMPRESSION_GUIDE.md) · [RTK compression](docs/compression/RTK_COMPRESSION.md) · [Mga compression engine](docs/compression/COMPRESSION_ENGINES.md)

Inihahambing ng opt-in eval harness (`npm run eval:compression`) ang katapatan ng tugon at pagtitipid ng token sa isang nakapirming corpus.

## Higit pang mga paraan ng pag-install — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Sinusundan ng `:latest` ang pinakamataas** inilathala** matatag SemVer. Hindi nito sinusubaybayan ang git `main`. I-pin `:X.Y.Z` para sa GitOps. Tingnan ang [Docker Release Channels](docs/guides/DOCKER_GUIDE.md#release-channels).Naka-pin ang larawan**`OMNIROUTE_MEMORY_MB=1024`** . Sapat na iyon para sa dashboard at isang magaan na chat.** Mga ahente ng coding** (`POST /v1/responses` mula sa Claude Code, Codex, Grok, …) ay nangangailangan ng mas malaking V8 heap o ang prosesong `FATAL ERROR` s sa ~ 12 GiB sa ilalim ng dalawang magkakapatong na mahabang konteksto. Sukatin ang lalagyan sa itaas ng heap (ang mga katutubong buffer ay nasa labas ng V8):

| <img width="2000" height="0" alt=""> Workload   | Bunton (`-e OMNIROUTE_MEMORY_MB`) | Lalagyan (`--memory`) |
| ----------------------------------------------- | --------------------------------- | --------------------- |
| Dashboard / magaan na chat                      | `1024` (default ng larawan)       | ≥ 2 g                 |
| Isang coding agent                              | `8192`                            | ≥ 10 g                |
| Dalawang magkasabay na mahabang `/v1/responses` | `10240`–`12288`                   | ≥ 12–16 g             |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Buong talahanayan: [Docker Guide — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Pre-release Docker channel:** Sinusundan ng `diegosouzapw/omniroute:next` at `diegosouzapw/omniroute:next-web` ang kasalukuyang default na sangay `release/v*`. Ang mga nababagong tag na ito ay inilaan lamang para sa pagsubok ng mga hindi pa nailalabas na pag-aayos at** hindi suportado para sa produksyon** . Tingnan ang [Docker Release Channels](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

Ang karaniwang `bun install` at pandaigdigang pag-install (`bun install -g omniroute`) ay sinusuportahan sa pamamagitan ng Bun runtime detection:

- **Built-in na `bun:sqlite`** : Ginagamit OmniRoute ang built-in `bun:sqlite` driver Bun kapag tumatakbo sa ilalim Bun, bumabalik sa `better-sqlite3` sa Node.js o `sql.js`.
- **Awtomatikong pagpili ng bundler ng Webpack sa dev** : Awtomatikong nade-detect ng development (`bun run dev`) Bun at hindi pinapagana Turbopack na pabor sa Webpack upang maiwasan ang mga hindi pagkakatugma ng katutubong V8. Ang mga production build (`bun run build`) ay sumusunod sa `OMNIROUTE_USE_TURBOPACK` nang eksakto tulad ng sa Node: Turbopack bilang default, `OMNIROUTE_USE_TURBOPACK=0` upang bumuo gamit ang Webpack (`Dockerfile.bun` ay inilalantad ito bilang isang `--build-arg`).
- **Nakalaang Bun Dockerfile** : Multi-stage `Dockerfile.bun` para sa mga native Bun production deployment (`docker build -f Dockerfile.bun -t omniroute:bun .`).

**⚡ Mas mabilis / mas payat na pag-install (laktawan ang katutubong build)**

Ang katutubong SQLite engine (`better-sqlite3`) ay isang** opsyonal** dependency, kaya ang isang pandaigdigang pag-install ay hindi kailanman humaharang sa pag-compile mula sa pinagmulan: ito ay gumagamit ng isang prebuilt na binary kapag ang isa ay tumugma sa iyong platform/Node, at kung hindi man ay malinaw na bumabalik sa isang pure-JS engine (`node:sqlite` sa Node 22 +, kung hindi ang bundled `sql.js` WASM) — walang mga tool sa build na kinakailangan.

Upang laktawan ang post-install** katutubong warm-up** ganap (CI, walang ulo, o mabagal na makina). Tandaan: nilalaktawan lang nito ang katutubong SQLite warm-up step (`scripts/postinstall.mjs`); ang binary-copy/repair hook (`scripts/build/postinstall.mjs`) ay tumatakbo nang normal:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

Para sa pinakamabilis na pag-install mas gusto** pnpm** (content-addressed store + hard link — tingnan sa itaas). Para sa walang dashboard, walang ulo na runtime gamitin ang Docker `base` profile (sa itaas) o ang [Termux guide](docs/guides/TERMUX_GUIDE.md). Ang CLI at ang web dashboard ay inihahatid ng parehong proseso sa isang port, kaya walang hiwalay na CLI-only na package ngayon.

### Paano Mag-ambag

1. I-fork ang repository
2. Sangay mula sa** aktibo** `release/vX.Y.Z` tip (hindi `main`) — tingnan [ang Branching & Release Model](docs/ops/BRANCHING_MODEL.md)
3. Lumikha ng iyong sangay ng tampok (`git checkout -b feat/amazing-feature`)
4. Ibigay ang iyong mga pagbabago (`git commit -m 'feat: add amazing feature'`)
5. Itulak sa sangay (`git push origin feat/amazing-feature`)
6. Magbukas ng Pull Request gamit ang** base = na `release/vX.Y.Z` branch**

Tingnan ang [CONTRIBUTING.md](CONTRIBUTING.md) para sa mga detalyadong alituntunin.

### Naglalabas ng Bagong Bersyon

```bash
# Create a release — npm publish happens automatically
VERSION=x.y.z
gh release create "v${VERSION}" --title "v${VERSION}" --generate-notes
```
