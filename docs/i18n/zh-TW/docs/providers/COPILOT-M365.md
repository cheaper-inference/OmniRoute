`copilot-m365-web` （別名`m365copilot`）透過`m365.cloud.microsoft/chat`上經過驗證的Microsoft 365 Copilot會話發送 OpenAI 格式的聊天請求。這是非官方的本機整合：不需要單獨的代理程式或本地主機上游。提供者ID、別名和現有導入的連線保持不變。 `copilot-web`是`copilot.microsoft.com`消費者服務的不同提供者。

> **對 Web Cookie 提供者不熟悉？**
>
> 讀**`docs/getting-started/WEB-COOKIE-GUIDE.md`**在遵循此特定於提供者的指南之前，請先了解一般設定流程、身分驗證指南、限制和故障排除。
>
> **對於舊版導入：**該提供者的憑證是**不是餅乾**。不要從`m365.cloud.microsoft`複製 cookie。憑證是WebSocket URL查詢參數和路徑段，兩者都是從DevTools Network 標籤讀取的。

## 先決條件

- 有權存取`m365.cloud.microsoft/chat`上的Copilot的Microsoft 365 帳戶
- 用於DevTools WebSocket檢查的基於 Chromium 的瀏覽器（Chrome、Edge）
- 存取該帳戶上請求的模型；可用性因租戶和許可證而異

## 本機登入（工作或學校帳戶）

選擇**Microsoft 365 Copilot →連接**並準備登入嘗試。儀表板使用PKCE的授權代碼流；它不會要求您提供Microsoft密碼或MFA代碼。

1. 打開一個**空白瀏覽器標籤**，然後打開**DevTools →網絡**並啟用**保存日誌**。在導航到Microsoft之前執行此操作： Windows SSO可能會立即完成。
2. 複製連線對話方塊中顯示的授權URL並在準備好的標籤中導覽到它。如果需要，請完成Microsoft的帳戶選擇或MFA 。
3. 在保留的網誌中，找到對`https://login.microsoftonline.com/common/oauth2/nativeclient`的請求並複製其完整內容**請求URL** 。
4. 將URL貼到連接對話框中並連接。不要貼上原始程式碼或最終的`wrongplace`網址列URL：所需的回調是瞬態導覽。

每次嘗試將在十分鐘後過期，並且只能使用一次。伺服器在交換程式碼之前檢查其狀態、 PKCE驗證者和重新驗證目標。過期或兌換失敗後，開始新的嘗試。嘗試無法在伺服器重新啟動後繼續存在。

令牌使用現有的連線憑證儲存和刷新路徑。重新驗證連線需要相同的Microsoft tenant/object身份，而不僅僅是相同的電子郵件。它保留了操作員naming/settings並取代了過時的導入憑證。原生登入適用於work/school帳戶；舊導入路徑仍可用於現有連線和支援的層配置。

完整回呼URL是一次性憑證。切勿將其包含在螢幕截圖、日誌、支援訊息或提交中。此流程不會在伺服器上開啟瀏覽器、檢查瀏覽器歷史記錄或啟動本機回呼伺服器。

## 憑證捕獲（WebSocket方法）

1. 登入`https://m365.cloud.microsoft/chat`並開始對話。
2. 打開**DevTools →網絡**。
3. 過濾依據**WS** （WebSocket）。
4. 點選 Chathub WebSocket連接。尋找以`wss://substrate.office.com/m365Copilot/Chathub/`開頭的URL 。
5. 從其**請求URL** ， 複製：
   - `access_token`查詢參數值（短暫的JWT）。
   - `/Chathub/`之後的 Chathub 路徑段（例如`<oid>@<tenant>`）。

完整的URL具有以下形式：

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. 在OmniRoute中，選擇**Microsoft 365 Copilot** ，選擇舊版API-key/import選項，並以以下格式貼上憑證：

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. 點選**測試連接**和**節省**。

## 憑證捕獲（HAR導入）

您可以匯出DevTools HAR文件，而不是手動從WebSocket URL複製值：

1. 打開**DevTools →網絡**。
2. 開始或繼續Microsoft 365 Copilot對話（這會觸發WebSocket連線）。
3. 在網路面板中右鍵並選擇**將內容全部儲存為HAR** 。
4. 在OmniRoute中，使用**導入.har文件**提供者連線對話方塊上的按鈕。

OmniRoute掃描HAR中的 Chathub WebSocket URL，提取`access_token`和`chathubPath`，並自動填入憑證欄位。 HAR導入對JWT到期進行解碼並顯示剩餘的令牌生命週期。

> **切勿提交真正的HAR匯出、存取令牌或刷新令牌。**測試和文件值必須始終是佔位符。

## 令牌生命週期和刷新

`access_token`是短暫的（通常**~分鐘**）。如果沒有可用的刷新令牌，您必須在過期後重新擷取憑證。

### 使用`refreshToken`自動刷新

在Microsoft 365 提供者的**新增連接**或者**編輯連接**對話框，打開**進階設定→刷新令牌（可選）** 。貼上Microsoft OAuth刷新令牌以用於`substrate.office.com/sydney`範圍並保存。輸入被屏蔽並且永遠不會用儲存的令牌預先填充。編輯時留空，保留現有token；貼上新令牌來替換它。

當Microsoft回傳 1 時，本機登入會取得刷新令牌。對於舊版導入，請使用現有的相容Microsoft授權代碼授權；該提供者不實現或承諾設備代碼流。配置刷新令牌後， OmniRoute在請求之前檢查`access_token` ，僅在需要刷新時刷新它。成功的刷新還會保留輪換的刷新令牌，從而避免在刷新令牌保持有效時手動重新捕獲。

如果未設定`refreshToken` ，則必須在每次到期後手動重新擷取WebSocket憑證。

### 等級選擇

| 等級         | 別名       | 表面                |
| ------------ | ---------- | ------------------- |
| `individual` | _(預設)_   | 消費者 M365 Copilot |
| `edu`        | `included` | 教育 M365 Copilot   |
| `enterprise` | `work`     | M365 Copilot工作版  |

將層級設定為**進階設定→ Copilot層**。本機登入不會設定它，因此工作帳戶必須選擇`enterprise` （別名`work`）和教育帳戶`edu`，在使用記錄模型IDs時也是如此：它們選擇自己的語氣、場景和許可證類型，但代理和呼叫選項仍然來自該層，並且個人預設值可能會在工作租戶上失敗。更改等級並不授予模型許可證。顯式高級協定覆蓋優先，並且僅當您知道所需的線路值時才應使用。

## 型號和路線

本機目錄包括所有記錄的獨立IDs以及四個原始本機IDs。該目錄是靜態的且獨立於帳戶，而不是帳戶權利探測：即使連接的帳戶無法使用付費路由和相容性別名，它們也會保留在清單中。模型顯示標籤省略了提供者名稱和每個模型的可用性樣板；提供者仍然存在**Microsoft 365 Copilot** 。標籤標記**別名**或者**遺產**保留其現有的識別碼和協定映射，不保證歷史模型版本。獨立代理的**從 /models 導入**說明不適用於此本機WebSocket提供者。

| 模範家庭          | 規範IDs                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| 自動的            | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| 早前的GPT         | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude            | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude作品        | `claude-opus`, `claude-opus-4.8`                                                                 |

也註冊了`auto`、 `quick`、 `think-deeper`等別名和版本別名。現有的`copilot-m365`、 `copilot-m365-claude-opus`、 `copilot-m365-gpt-5-6-reasoning`和`copilot-m365-gpt-5-5-chat`仍然有效。記錄的IDs需要提供程式前綴（`copilot-m365-web/claude-opus`或`m365copilot/claude-opus`）：許多是通用字或其他提供者的型號名稱，因此裸`claude-opus`會像沒有此提供者一樣保持路由。註冊並不承諾Microsoft會為每個帳戶提供該模型。獨立的IDs遵循公共[協議目錄](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts)（導出的模型到色調映射及其模型感知場景元資料）。所有原生設定檔都保留`availability: "unverified"`；包含在目錄中並不是成功的帳戶測試。

- 明確的模型許可拒絕返回**403** `m365_model_not_licensed`，而不是 502。路由鎖定connection/model配對，使連線上的授權模型可用。
- `InvalidCopilotLicense`是帳戶級許可拒絕，單獨報告為`m365_account_not_licensed`。
- 每用戶限制返回**第429章**`m365_throttled`並冷卻連接。優先訪問耗盡返回**第429章**`priority_access_exhausted`且是模型範圍的。 `OutOfCredits`與`errorCode: "ReasoningTurnExhausted"`的結果返回**第429章**相反， `reasoning_turns_exhausted` ，也是模型範圍的，沒有聲明重置時間。據報導，一名工作租戶在快速音調繼續播放的同時限制了“深入思考”的音調；該範圍是消費者的觀察，而不是該存儲庫複製的內容。因此，路由也使其他已記錄的 Think Deep 模型的`gpt-5.5`和`gpt-5.6`不再在該連接上旋轉，以獲得相同的冷卻時間，並將快速音調和所有其他故障保留在自己的模型上。保留提供的重試提示；遺失的重置不會被公佈為已知的重置時間。
- Copilot安全拒絕 (`Disengaged`) 返回**400** `provider_safety_rejection`，共享提供者安全停止標籤。它永遠不會影響連線的健康狀況，客戶端SDKs不會重試 400，啟用`PROVIDER_SAFETY_STOPS_TERMINAL`組合路由會在那裡停止，而不是針對另一個目標重播請求。
- 一個連線上的請求透過現有帳戶信號量進行序列化。優先選擇優先順序回退而不是並行面板；序列化本身並不能消除Microsoft的會話速率限制。

## 請求行為和限制

- 工具有**提示模擬**，不是本機Microsoft函數呼叫。工具啟用的請求使用一個緩衝產生；它不會花費一代人的時間來選擇工具。只有具有有效支援的參數形狀的聲明工具才會作為呼叫傳回。
- 帶有單一尾隨範例的長結構答案將作為散文保存。這是一種啟發式方法，而不是意圖證明；應用程式仍然必須強制執行自己的工具權限。
- 影像輸入的工作方式與 Web 用戶端發送影像的方式相同。每個圖像部分（`image_url`作為資料URL或公共HTTPS URL或回應`input_image`）都上傳到`/m365Copilot/UploadFile`到帶有聊天令牌的回合對話中，並且訊息透過`ImageFile`註釋指向它；文字標記了它所在的位置（`[image 1]`，...）。新的對話會上傳歷史記錄中的每張圖像，而連續的對話則僅上傳新訊息的圖像。最多 10 個PNG、 JPEG、 GIF或WebP映像，每個影像最多 10 MiB （每個請求 40 MiB ）；格式是從位元組讀取的。 HTTPS URLs透過僅限公共、DNS 固定的遠端影像防護來取得。上傳失敗導致請求失敗（** 502** `m365_image_upload_failed`** 400** `m365_image_rejected`或`m365_image_invalid`);如果沒有給出圖像，轉彎永遠不會繼續。其他非文字部分（音訊、檔案）會被明確拒絕，而不是默默丟棄。
- 後續請求將繼續相同的上游會話，並且僅發送前一個回復之後的訊息。它必須精確地擴展該回應：相同的連接、模型設定檔和工具集；未更改的歷史記錄（每個訊息都有一個 sha256 鏈）；以及回應的工具呼叫 ID，或其文字（最多為空格）。任何其他內容（已編輯的歷史記錄、具有相同第一則訊息的另一個會話、不同的回應、空閒 30 分鐘或接近Copilot的 600 條訊息上限的對話、沒有 id 的連接）都會啟動與整個歷史記錄的新對話。失敗的回合永遠不會恢復，並且在新的對話中重新發送一次無內容的`InternalError` (** 502** `m365_internal_error`如果再次失敗）。延續資訊保存在進程記憶體中：重新啟動將開始新的對話。
- 每個回合都在Copilot的臨時聊天 (`disableMemory=1`) 中運行：對話在運行時保留其上下文，並且永遠不會出現在帳戶的聊天歷史記錄中。因此，模型測試、測試全部和組合測試可以在不留下對話的情況下探測該提供者。
- 一個回合有 120 秒的空閒期限和有限的總期限。僅最終答案、進度過濾和取消由本機transport/composer.處理
- 基於網路的答案保留其來源。 Copilot使用私人使用控製字元標記內聯引用，並將來源作為`references`發送；每個標記都變成一個編號的 Markdown 連結（`[1](https://…)`，或Copilot使用標記作為連結目標時的裸URL ），並帶有匹配的`url_citation`註釋（`message.annotations`，或帶有連結的區塊上的`delta.annotations` ）。永遠不會到達的來源將被丟棄，因此標記永遠不會到達客戶端。串流傳輸時，引用後的文字會等待其來源到達。
- 當模型發送Copilot的推理摘要 (`ChainOfThoughtSummary`) 時，它會作為`reasoning_content`返回，而不是作為答案的一部分。重寫自身的摘要會停止串流而不會失敗。
- 在任何內容之前，即使請求串流傳輸， licence/throttle失敗也會保留HTTP 403/429 。內容開始後，失敗是SSE錯誤事件，永遠不會成功完成。無法用僅追加流表示的上游重寫是顯式流錯誤；非流式和緩衝工具回應保留最終文字。
- 當Copilot拒絕連線本身時，其答案如下：** 401** `m365_unauthorized`表示登入被拒絕或過期（再次登入），**第429章**使用`Retry-After`進行節流，否則握手失敗，絕非一般連線失敗。

## 影像生成

`POST /v1/images/generations`和`model: "copilot-m365-web/m365-copilot-image"` （別名`m365copilot/m365-copilot-image`）使用Copilot的內建影像工具進行繪製，就像 Web 用戶端一樣。每個圖像都是一個Copilot回合：它選擇使用 Web 用戶端的圖像選項集並聲明`GenerateGraphicArt`，並且圖像到達指向Microsoft設計器服務上的工件的進度條目。該工件拒絕聊天令牌，因此OmniRoute從連接的刷新令牌中建立一個設計者令牌並下載位元組；令牌僅發送至`designerapp.officeapps.live.com`。

- 需要本機登入連線（刷新令牌）；貼上令牌失敗**400**在任何回合結束之前。
- `n`是1-4，每回合一回合。 `size`僅控制方向（更寬、更高或方形）， Copilot從提示中讀取該方向； Copilot選擇渲染大小。
- 影像以內聯方式傳回：預設為`b64_json` ， `response_format: "url"`為資料URL 。
- 生成的圖像需要少量的每日預算，與聊天無關。當它用完時，請求失敗**第429章**。沒有圖像回答的回合會失敗**502** （或者**400** /** 503**當Copilot的文字讀作拒絕或容量問題時）；訊息說的是哪一個。

## 安全模型

- **非官方整合。**該提供者對BizChat WebSocket協定進行逆向工程。當Microsoft更改端點時，它可能會在沒有通知的情況下中斷。
- `subscriptionRisk: true`標誌反映整合依賴於未記錄的端點。帳戶限制是可能的，但尚未得到確認。
- 訪問令牌是一個短暫的JWT。將其視為密碼：不要提交、記錄或共享它。
- 刷新令牌授予對Microsoft 365 表面的持續存取權限。像API密鑰一樣小心地儲存它。

## 故障排除

### 認證立即失敗

- Verify you copied from the **WebSocket URL**, not from an XHR/Fetch request. The credential is in the `access_token` query parameter of the Chathub WebSocket connection — not in an `Authorization: Bearer` header.
- 確保`chathubPath`包含URL路徑中的完整`<oid>@<tenant>`段。

### 令牌在~ 75 分鐘後過期

這是預料之中的。如果沒有`refreshToken`，訪問令牌是短暫的。任何一個：

- 從DevTools重新捕捉憑證，或者
- 配置**進階設定→刷新令牌（可選）**在「新增」或「編輯連線」對話方塊中進行自動刷新。

### 測試連線通過，但聊天回傳 401

對於使用以下命令建立的連接**使用Microsoft登入**，測試連線檢查存取令牌的到期時間，並使用儲存的刷新令牌更新過期的令牌，因此通過的測試也證明刷新令牌仍然有效。

對於貼上的憑證，測試連接會檢查憑證的形狀，並且當令牌具有過期時間時，提供程式將使用的令牌尚未過期（連接的儲存令牌贏得陳舊的貼上；刷新令牌算作可更新）。過期之前被撤銷的 token 仍然通過測試；聊天然後返回**401** `m365_unauthorized`.使用**使用Microsoft登入**再次，或重新取得新的憑證。

### Copilot沒有出現在提供者清單中

確保`copilot-m365-web`已啟用**儀表板→提供者**。預設情況下，某些層中的提供者可能是隱藏的。
