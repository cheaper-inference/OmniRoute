> **狀態：** 儀表板以 **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`) 建置，並以工作區
> `packages/ui-kit` (`@omniroute/ui-kit`) 的形式內建於專案中；上游快照固定記錄於
> `packages/ui-kit/UPSTREAM.md`，並由 `npm run check:ui-kit-snapshot` 驗證。淺色是標準
> 主題；預設偏好設定為 `system`。強調色為 Keak 萊姆綠 (`--ci-color-accent`)。Inter
> （字距為 0，`--ci-letter-spacing-ui`）是 UI 字型，Instrument Serif 僅用於大型、疏朗的
> 展示文字 (`.ci-dashboard-display`)，IBM Plex Mono 則用於程式碼——所有字型皆透過
> `src/app/globals.css` 頂端的 `@fontsource/*` 匯入自行託管。所有圖示皆為 Lucide 字形。

## 1. 內容所在位置

- **套件。** `packages/ui-kit/src` 是上游 `src/` 在
  `packages/ui-kit/UPSTREAM.md` 所釘選提交的逐位元組副本（該檔案亦記錄授權許可）；`PATCHES.md` 列出本機
  修補程式（目前沒有）。它會直接以原始碼形式使用，不需建置：`next.config.mjs` 會轉譯它，而
  `tsconfig.json` 將 `@omniroute/ui-kit` → `packages/ui-kit/src`，並將 `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*`（`vitest.config.ts` 與 `vitest.mcp.config.ts` 也包含相同別名）。請透過子路徑匯入
  套件元件（`@omniroute/ui-kit/table`、`@omniroute/ui-kit/page-header`……），絕不要透過
  `@omniroute/ui-kit` 彙總入口匯入：該彙總入口會將所有元件（包括日期選擇器）帶入每個匯入端。
  套件樣式表透過 `src/app/globals.css` 載入
  （`@import "../../packages/ui-kit/src/ci-ui.css"`）。
- **權杖。** `packages/ui-kit/src/ci-tokens.css` 宣告 `--ci-*` 權杖；`src/app/globals.css`
  會將它們橋接至舊版 OmniRoute 名稱（`--color-*`、`--radius-*`、`--font-sans`/`--font-mono`、
  `--table-*`、`--orch-status-*`、`--color-fd-*`），讓現有的 `var(--color-*)` 讀取方式與 Tailwind
  工具類別能繼續運作。新程式碼使用 Tailwind 工具類別（`bg-surface`、`text-text-muted`、
  `border-border`、`text-success`、`bg-success-bg`、`bg-chart-1`……）或套件類別，絕不使用十六進位色彩值
  （`tests/unit/design-kit-bridge.test.ts` 會強制檢查此橋接）。`text-primary` 透過
  `--text-color-primary` 解析為 `--color-primary-ink`（淺色模式為 lime-800，深色模式為萊姆強調色），因此
  主要文字能維持可讀性，而 `bg-primary`/`border-primary` 則保留萊姆色表面。圖表數列使用
  `--color-chart-1` … `--color-chart-5`。
- **主題。** `<html className="ci-theme">`（`src/app/layout.tsx`）讓文件啟用套件主題。
  偏好設定可以是 `light`、`dark` 或 `system`（`src/shared/constants/appConfig.ts` 中的
  `THEME_CONFIG.defaultTheme = "system"`；`system` 會遵循 `prefers-color-scheme`）。位於
  `src/store/themeStore.ts` 的 `applyTheme()`（在 `src/app/layout.tsx` 中由會在水合前執行的內嵌啟動指令碼
  對應實作）會設定 `data-theme="dark"|"light"`，並同步切換 `<html>` 上的 `.dark` 類別。
  套件的深色權杖集合以 `data-theme="dark"` 為依據（`packages/ui-kit/src/ci-tokens.css`）；
  OmniRoute 自身的深色覆寫（`globals.css` 中的 `.dark` 區塊）與舊版 Tailwind `dark:`
  工具類別則以 `.dark` 類別為依據。這裡沒有強調色預設集：強調色一律來自套件，而較舊建置版本所保存的
  預設集會在儲存區載入時遭到捨棄。
- **元件（轉接器）。** `src/shared/components/index.tsx` 保留 OmniRoute 元件 API（相同的
  名稱、預設匯出與屬性），而其背後的基礎元件則是套件的轉接器：表單
  （`Button`、`Input`、`Textarea`、`Checkbox`、`Select`、`Toggle`、`Badge`、`Card`）、覆蓋層與回饋
  （`Modal`/`ConfirmModal`、`Tooltip`/`InfoTooltip`、`NotificationToast`、`EmptyState`、`Loading`）、
  結構（`Collapsible`、`CollapsibleSection`、`SegmentedControl`、`Breadcrumbs`、`Avatar`）以及表格
  （`DataTable`、`FilterBar`、`ColumnToggle`、`FilterPills`、`PresetSlider`）。轉接器會透過子路徑匯入套件
  元件，並將舊版屬性對應至該元件——例如 `Button variant="primary"` 是套件的 `default` 按鈕
  （`--ci-button-primary-*`：淺色模式下使用反向表面，深色模式下則使用強調色及其
  `--ci-color-accent-foreground` 前景色），`danger` 是 `destructive`，而 `warning` 則是 `outline` 加上
  `.ci-button--warning` 擴充。`globals.css` 結尾（`@layer components`）的
  `.ci-button--warning` 與 `.ci-badge[data-tone]` 規則，是建構於套件類別之上的 OmniRoute 擴充。
  `tests/unit/ui/adapters/*.test.tsx` 會固定驗證各個轉接器。
- **殼層。** `src/app/(dashboard)/layout.tsx` 會轉譯 `DashboardLayout`，後者再轉譯
  `src/shared/components/layouts/DashboardShell.tsx`：其中使用套件的 `SidebarProvider` / `Sidebar` /
  `SidebarInset`（`packages/ui-kit/src/sidebar.tsx`），並由
  `src/shared/components/Sidebar.tsx` 提供 OmniRoute 的導覽邏輯。指向 `#main-content` 的「跳至內容」
  連結是第一個可取得焦點的元素。`src/shared/components/Header.tsx` 包含套件的 `SidebarTrigger`
  （殼層唯一的側邊欄切換控制項）、Keak `ProductSwitcher` 與命令面板開啟器；只有在
  `#main-content` 內未掛載套件 `PageHeader`（`.ci-page-header`）時，它才會顯示路由標題，因此具有自有
  `PageHeader` 的頁面只會有一個 `h1`。`src/shared/components/CommandPalette.tsx` 是套件的 `Dialog`。
- **圖示。** `<Icon name="material_name">`（`src/shared/components/Icon.tsx`）會透過
  `ICON_MAP`（`src/shared/constants/iconMap.ts`），將名稱（畫面所使用的 Material Symbols 詞彙）解析為
  Lucide 圖像。Material Symbols 字型與套件已移除：對應表中缺少的名稱會轉譯為中性預留位置圖像
  （`data-icon-missing="true"`），並在非正式環境中記錄主控台警告。
  `npm run gen:icon-map` 會列印目前正在使用但對應表中缺少的名稱
  （`tests/unit/icon-map-coverage.test.ts` 會在任何名稱沒有 Lucide 圖示時失敗；
  `tests/unit/icon-map-object-values.test.ts` 涵蓋儲存在查找物件中的名稱）；
  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` 會將常值
  `<span className="material-symbols-outlined">` span 改寫為 `<Icon>`。
- **品牌。** `src/shared/components/OmniRouteLogo.tsx` 封裝套件：預設匯出 `OmniRouteLogo`
  會轉譯 `ProductIcon product="omniroute" variant="glyph"`（內嵌 SVG，與 `basePath` 相容），而
  `OmniRouteLockup` 會轉譯 `ProductLockup product="omniroute"`（無障礙名稱為「Keak OmniRoute」），或為
  白標營運商轉譯其自有的 `name`/`logoSrc`。產品切換器目的地位於
  `src/shared/constants/keakProducts.ts`（`KEAK_PRODUCT_LINKS`、`KEAK_ACTIVE_PRODUCT`）。獨立畫面——
  `src/app/login/page.tsx`、`src/app/status/page.tsx`、`src/app/maintenance/page.tsx`、
  `src/app/offline/page.tsx`、`src/app/not-found.tsx` 與 `src/shared/components/ErrorPageScaffold.tsx`
  ——會顯示品牌鎖定標誌；`tests/unit/brand-pages-static.test.ts` 會加以保護。

## 2. 規則

1. 使用設計權杖，絕不使用字面值。刻意保留的例外：固定為深色的主控台終端、透過 `STATUS_HEX` (`src/shared/constants/statusColors.ts`) 設定的 ReactFlow SVG
   筆畫，以及分類調色盤
   `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) 和
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`)。
2. 絕不手動修補 `packages/ui-kit/src`：請使用 `scripts/dev/sync-ui-kit.sh <commit>` 同步；若有任何位元組
   與固定的上游提交不同，預先提交閘門 `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) 就會失敗
   （若上游複製版本 `UI_KIT_CLONE` 或 `_references/cheaper-inference-ui-kit` 不存在，則會顯示警告並
   略過）。當套件缺少某項功能時，請在轉接器或畫面中採取替代作法，並向上游提出需求。
3. 套件的文字預設值為英文（`label = "Loading"`、`loadingLabel = "Loading table"`……）——每當套件元件
   轉譯文字時，請傳入來自 `useTranslations(...)` 的翻譯字串。
4. Tailwind 公用類別的優先順序高於套件元件類別（套件宣告
   `@layer theme, base, components, utilities`，而其規則位於 `components`）——請使用公用類別處理
   間距與版面配置，不要用它們重新設定套件元件的顏色。
5. 標題：頁面與區段標題使用 `.ci-heading`（Inter，無字距調整）；`.ci-dashboard-display`
   （Instrument Serif）僅用於大型、稀疏的展示文字，例如錯誤頁面的狀態碼。
6. `tests/unit/dashboard-kit-sweep.test.ts` 會守護套件的採用情況：`src/app` 或
   `src/shared/components` 下不得有 Material 連字 span；儀表板樹狀目錄（`src/app/(dashboard)` 和
   `src/shared/components`）中不得有原始 `<select>`、`<textarea>` 或 `<table>`，也不得在列出的
   例外之外自行實作 `role="dialog"`（例外包括 `Select` 轉接器的原生分支、
   `RequestLoggerDetail`）；其中每個原始 `<button>` 或 `<input>` 的上方至多 3 行內，都必須有一則
   包含 `kit-exception:`（以及原因）的註解；調色盤色相與 `dark:` 變體只能出現在測試列出的檔案中。
7. PR 前請驗證兩種主題與 390 px 視窗寬度（附螢幕擷取畫面）；`tests/e2e/a11y.spec.ts` 會執行
   axe。

## 3. 新增畫面

1. 使用套件的 `PageHeader` (`@omniroute/ui-kit/page-header`) 開啟頁面（在儀表板內使用 `compact`）
   ——包含標題、描述和 `actions`。如此一來，外殼頁首便不再顯示自己的標題。
2. 使用 `@/shared/components`（轉接器）建構控制項；若沒有轉接器，則透過子路徑使用套件元件
   （`Table`/`TableScrollArea`/`DataTableShell`、`Field`、`Alert`、`Tabs`、`RadioGroup`、
   `Slider`……）。
3. 圖示：`<Icon name="…" />`。新的名稱需連同語意相符的 Lucide 元件加入 `ICON_MAP`；
   `npm run gen:icon-map` 會列出仍缺少的名稱。
4. 顏色：使用語意化公用類別（`text-success`、`bg-warning-bg`、`border-border`……），圖表數列則使用
   `var(--color-chart-N)`；不得使用十六進位值，也不得使用只重複顏色的 `dark:` 變體。
5. 文字：每個字串，包括傳給套件元件的標籤，都必須來自 `useTranslations`。新鍵必須加入
   `src/i18n/messages/en.json`、`pt-BR.json` 和 `vi.json`（越南文一致性測試會固定檢查每個英文鍵）；
   其他語言地區則由 i18n 同步補齊。
6. PR 前請執行防護檢查：`tests/unit/dashboard-kit-sweep.test.ts`、
   `tests/unit/icon-map-coverage.test.ts`、`tests/unit/icon-map-object-values.test.ts`、
   `npm run check:dashboard-typecheck`（這是唯一能捕捉 `iconMap.ts` 中重複匯入的檢查）、
   `npm run check:ui-icu`，以及該畫面本身的測試。

## 4. 新增或變更轉接器

1. 保持 `src/shared/components/index.tsx` 的公開 API 不變：使用相同的匯出名稱、預設匯出及
   可接受的 props。在轉接器內將舊版 props 對應至套件（請參閱 `Button.tsx`：`VARIANT_TO_KIT`、
   `SIZE_TO_KIT`）。
2. 透過子路徑匯入套件（`@omniroute/ui-kit/<component>`）。
3. 套件缺漏功能的因應措施應放在轉接器內（若修正項目屬於樣式，則放在 `globals.css` 的 `@layer components` 中），
   絕不可放在 `packages/ui-kit/src` 中。
4. 新增或更新 `tests/unit/ui/adapters/<name>.test.tsx`。對於有許多呼叫端的轉接器，請比較變更前後
   轉譯出的標記——內距或包裝器的變更會影響每個畫面。

## 5. 更新套件

`scripts/dev/sync-ui-kit.sh <commit> [clone]` 會將該提交中的上游 `src/` 複製到
`packages/ui-kit/src`，並套用唯一允許的轉換（移除相對匯入中的 `.js` 副檔名）。接著：檢閱 `git diff packages/ui-kit`、在兩種主題下對供應器、設定、組合、
用量及端點進行視覺檢查、執行 `npm run check:ui-kit-snapshot` 和 `npm run test:vitest:ui`，並
附上上游變更日誌建立 PR。
