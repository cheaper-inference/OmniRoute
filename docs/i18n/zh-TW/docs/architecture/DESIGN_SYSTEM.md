> **狀態：** 儀表板建構於 **Keak CI UI Kit**(`@keak/cheaper-inference-ui-kit`)之上,並以 vendor 方式
> 納入為 workspace `packages/ui-kit`(`@omniroute/ui-kit`;上游快照固定於
> `packages/ui-kit/UPSTREAM.md`,並由 `npm run check:ui-kit-snapshot` 把關)。淺色為標準
> 主題;預設偏好為 `system`。強調色為 Keak 萊姆綠(`--ci-color-accent`)。Inter
> (letter-spacing 0,`--ci-letter-spacing-ui`)為 UI 字體家族,Instrument Serif 僅用於
> 大型且稀疏的展示文字(`.ci-dashboard-display`),IBM Plex Mono 用於程式碼 —— 全部透過
> `src/app/globals.css` 頂端的 `@fontsource/*` 匯入自行託管。每個圖示皆為 Lucide 字形。

## 1. 各項內容的位置

- **套件（Kit）。** `packages/ui-kit/src` 是上游 `src/` 在 `packages/ui-kit/UPSTREAM.md` 所釘選 commit 的逐位元組複本（該檔案同時記錄授權許可）；`PATCHES.md` 列出本地修補（無）。它以原始碼形式直接使用，無需建置：`next.config.mjs` 負責轉譯，且 `tsconfig.json` 將 `@omniroute/ui-kit` 對應至 `packages/ui-kit/src`、將 `@omniroute/ui-kit/*` 對應至 `packages/ui-kit/src/*`（`vitest.config.ts` 與 `vitest.mcp.config.ts` 帶有相同別名）。匯入套件元件時一律使用其子路徑（`@omniroute/ui-kit/table`、`@omniroute/ui-kit/page-header`…），切勿透過 `@omniroute/ui-kit` 的 barrel：barrel 會將所有元件（包括日期選擇器）拉進每一個匯入者。套件樣式表經由 `src/app/globals.css` 引入（`@import "../../packages/ui-kit/src/ci-ui.css"`）。
- **設計代符（Tokens）。** `packages/ui-kit/src/ci-tokens.css` 宣告 `--ci-*` 代符；`src/app/globals.css` 將其橋接至舊版 OmniRoute 名稱（`--color-*`、`--radius-*`、`--font-sans`/`--font-mono`、`--table-*`、`--orch-status-*`、`--color-fd-*`），因此現有的 `var(--color-*)` 讀取與 Tailwind 工具類別可繼續運作。新程式碼使用 Tailwind 工具類別（`bg-surface`、`text-text-muted`、`border-border`、`text-success`、`bg-success-bg`、`bg-chart-1`…）或套件類別——絕不使用十六進位色值（`tests/unit/design-kit-bridge.test.ts` 會強制檢查此橋接）。`text-primary` 透過 `--text-color-primary` 解析為 `--color-primary-ink`（淺色模式為 lime-800，深色模式為 lime 強調色），因此主要文字保持可讀，而 `bg-primary`/`border-primary` 仍維持 lime 底色。圖表系列使用 `--color-chart-1` … `--color-chart-5`。
- **主題（Themes）。** `<html className="ci-theme">`（`src/app/layout.tsx`）讓文件啟用套件主題。偏好設定為 `light`、`dark` 或 `system`（`src/shared/constants/appConfig.ts` 中的 `THEME_CONFIG.defaultTheme = "system"`；`system` 會跟隨 `prefers-color-scheme`）。`src/store/themeStore.ts` 中的 `applyTheme()`（由 `src/app/layout.tsx` 內的內嵌啟動腳本鏡像執行，該腳本在 hydration 之前運行）會同時設定 `data-theme="dark"|"light"` 並切換 `<html>` 上的 `.dark` 類別。套件的深色代符組以 `data-theme="dark"` 為判斷依據（`packages/ui-kit/src/ci-tokens.css`）；OmniRoute 自己的深色覆寫（`globals.css` 中的 `.dark` 區塊）與舊版 Tailwind `dark:` 工具類別則以 `.dark` 類別為依據。沒有強調色預設組合：強調色一律來自套件，而舊版建置所保存的預設值會在 store 載入時被捨棄。
- **元件（轉接器）。** `src/shared/components/index.tsx` 維持 OmniRoute 元件 API（相同名稱、預設匯出與 props），其背後的基礎元件皆為套件之上的轉接器：表單（`Button`、`Input`、`Textarea`、`Checkbox`、`Select`、`Toggle`、`Badge`、`Card`）、覆層與回饋（`Modal`/`ConfirmModal`、`Tooltip`/`InfoTooltip`、`NotificationToast`、`EmptyState`、`Loading`）、結構（`Collapsible`、`CollapsibleSection`、`SegmentedControl`、`Breadcrumbs`、`Avatar`）與表格（`DataTable`、`FilterBar`、`ColumnToggle`、`FilterPills`、`PresetSlider`）。轉接器以子路徑匯入套件元件，並將舊版 props 對應到該元件上——例如 `Button variant="primary"` 對應套件的 `default` 按鈕（`--ci-button-primary-*`：淺色模式為反色底色，深色模式為強調色搭配其 `--ci-color-accent-foreground` 前景色），`danger` 對應 `destructive`，而 `warning` 則是 `outline` 加上 `.ci-button--warning` 擴充。`globals.css` 結尾（`@layer components`）的 `.ci-button--warning` 與 `.ci-badge[data-tone]` 規則，是 OmniRoute 在套件類別之上的擴充。`tests/unit/ui/adapters/*.test.tsx` 逐一鎖定每個轉接器的行為。
- **外殼（Shell）。** `src/app/(dashboard)/layout.tsx` 渲染 `DashboardLayout`，後者再渲染 `src/shared/components/layouts/DashboardShell.tsx`：套件的 `SidebarProvider` / `Sidebar` / `SidebarInset`（`packages/ui-kit/src/sidebar.tsx`），並搭配 `src/shared/components/Sidebar.tsx` 中的 OmniRoute 導覽邏輯。指向 `#main-content` 的「跳至內容」連結是第一個可聚焦的元素。`src/shared/components/Header.tsx` 持有套件的 `SidebarTrigger`（外殼中唯一的側邊欄切換鈕）、Keak 的 `ProductSwitcher` 與命令面板開啟鈕；僅當 `#main-content` 內未掛載套件 `PageHeader`（`.ci-page-header`）時才顯示路由標題，因此自帶 `PageHeader` 的頁面只會有一個 `h1`。`src/shared/components/CommandPalette.tsx` 是套件的 `Dialog`。
- **圖示。** `<Icon name="material_name">`（`src/shared/components/Icon.tsx`）透過 `ICON_MAP`（`src/shared/constants/iconMap.ts`）將名稱（各畫面使用的 Material Symbols 詞彙）解析為 Lucide 字形。Material Symbols 字型與套件皆已移除：對應表中找不到的名稱會渲染為中性的佔位字形（`data-icon-missing="true"`），並在非正式環境輸出主控台警告。`npm run gen:icon-map` 會列出使用中但不在對應表內的名稱（`tests/unit/icon-map-coverage.test.ts` 對任何沒有 Lucide 圖示的名稱都會判定失敗；`tests/unit/icon-map-object-values.test.ts` 涵蓋存放在查詢物件中的名稱）；`scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` 會將字面寫死的 `<span className="material-symbols-outlined">` span 改寫為 `<Icon>`。
- **品牌。** `src/shared/components/OmniRouteLogo.tsx` 包裝套件：預設匯出的 `OmniRouteLogo` 渲染 `ProductIcon product="omniroute" variant="glyph"`（內嵌 SVG，可安全搭配 `basePath`），而 `OmniRouteLockup` 渲染 `ProductLockup product="omniroute"`（無障礙名稱為「Keak OmniRoute」），或針對白牌營運商渲染其自訂的 `name`/`logoSrc`。產品切換器的連結目的地定義於 `src/shared/constants/keakProducts.ts`（`KEAK_PRODUCT_LINKS`、`KEAK_ACTIVE_PRODUCT`）。獨立畫面——`src/app/login/page.tsx`、`src/app/status/page.tsx`、`src/app/maintenance/page.tsx`、`src/app/offline/page.tsx`、`src/app/not-found.tsx` 與 `src/shared/components/ErrorPageScaffold.tsx`——會顯示 lockup；`tests/unit/brand-pages-static.test.ts` 負責把關。

## 2. 規則

1. 使用 Token，絕不使用字面值。以下為刻意保留的例外：永遠深色的主控台終端機、透過 `STATUS_HEX`
   （`src/shared/constants/statusColors.ts`）設定的 ReactFlow SVG 描邊，以及類別色盤
   `STRATEGY_COLORS`（`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`）與
   `LAYER_COLORS`（`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`）。
2. 絕不手動修改 `packages/ui-kit/src`：以 `scripts/dev/sync-ui-kit.sh <commit>` 同步；
   pre-commit 關卡 `npm run check:ui-kit-snapshot`（`.husky/pre-commit`）會在任何與釘選上游
   commit 不同的位元組上失敗（若上游複本 `UI_KIT_CLONE` 或
   `_references/cheaper-inference-ui-kit` 不存在，則發出警告並略過）。當套件缺少某項功能時，
   請在 adapter 或畫面中變通處理，並向上游提出需求。
3. 套件的文字預設為英文（`label = "Loading"`、`loadingLabel = "Loading table"`……）——
   每當套件元件渲染文字時，請從 `useTranslations(...)` 傳入翻譯後的字串。
4. Tailwind 工具類別優先於套件元件類別（套件宣告了
   `@layer theme, base, components, utilities`，其規則位於 `components` 層）——
   請以工具類別處理間距與版面配置，而非用來重新為套件元件上色。
5. 標題：頁面與區段標題使用 `.ci-heading`（Inter，無字距調整）；
   `.ci-dashboard-display`（Instrument Serif）僅用於大型、稀疏的展示文字，
   例如錯誤頁面的狀態碼。
6. `tests/unit/dashboard-kit-sweep.test.ts` 負責把關套件的採用：`src/app` 與
   `src/shared/components` 底下不得出現 Material 連字 span；在 dashboard 樹
   （`src/app/(dashboard)` 與 `src/shared/components`）內，除了列出的例外
   （`Select` adapter 的原生分支、`RequestLoggerDetail`），不得使用原生 `<select>`、
   `<textarea>` 或 `<table>`，也不得手刻 `role="dialog"`；該處每個原生 `<button>`
   或 `<input>` 都必須有一則包含 `kit-exception:`（附原因）的註解，且註解結尾最多
   在其上方 3 行；色盤色相與 `dark:` 變體僅限測試所列的檔案。
7. 提交 PR 前，驗證兩種主題與 390 px 可視區域（截圖）；`tests/e2e/a11y.spec.ts` 會執行 axe。

## 3. 新增畫面

1. 頁面以套件的 `PageHeader`（`@omniroute/ui-kit/page-header`，dashboard 內使用 `compact`）
   開頭——標題、描述與 `actions`。外殼標頭便不再顯示自己的標題。
2. 控制項以 `@/shared/components`（即 adapter）建構；沒有 adapter 的地方，以子路徑
   使用套件元件（`Table`/`TableScrollArea`/`DataTableShell`、`Field`、`Alert`、`Tabs`、
   `RadioGroup`、`Slider`……）。
3. 圖示：`<Icon name="…" />`。新名稱加入 `ICON_MAP`，並對應語意相符的 Lucide 元件；
   `npm run gen:icon-map` 會列出仍缺少的名稱。
4. 顏色：語意工具類別（`text-success`、`bg-warning-bg`、`border-border`……）與圖表系列
   專用的 `var(--color-chart-N)`；不使用十六進位色碼，也不使用只是重複同一顏色的 `dark:` 變體。
5. 文字：所有字串，包括傳給套件元件的標籤，都來自 `useTranslations`。新 key 加入
   `src/i18n/messages/en.json`、`pt-BR.json` 與 `vi.json`（越南語一致性測試會鎖定
   每個英文 key）；其餘語系由 i18n 同步填入。
6. 提交 PR 前執行各項把關：`tests/unit/dashboard-kit-sweep.test.ts`、
   `tests/unit/icon-map-coverage.test.ts`、`tests/unit/icon-map-object-values.test.ts`、
   `npm run check:dashboard-typecheck`（唯一能抓出 `iconMap.ts` 中重複 import 的檢查）、
   `npm run check:ui-icu`，以及該畫面本身的測試。

## 4. 新增或變更適配器

1. 保持 `src/shared/components/index.tsx` 的公開 API 不變:相同的匯出名稱、預設匯出及接受的 props。在適配器內將舊版 props 對應至 kit(參見 `Button.tsx`:`VARIANT_TO_KIT`、`SIZE_TO_KIT`)。
2. 透過子路徑匯入 kit(`@omniroute/ui-kit/<component>`)。
3. 針對 kit 缺口的變通方案應放在適配器中(若修正屬於樣式,則放在 `globals.css` 的 `@layer components`),絕不放在 `packages/ui-kit/src`。
4. 新增或更新 `tests/unit/ui/adapters/<name>.test.tsx`。對於有許多呼叫方的適配器,請比較變更前後所渲染的標記——padding 或 wrapper 的變更會擴散到每個畫面。

## 5. 更新 kit

`scripts/dev/sync-ui-kit.sh <commit> [clone]` 會將該 commit 的上游 `src/` 複製到 `packages/ui-kit/src`,並套用唯一允許的轉換(移除相對匯入的 `.js` 後綴)。接著:檢閱 `git diff packages/ui-kit`,在兩種主題下對 providers、settings、combos、usage 及 endpoint 進行視覺檢查,執行 `npm run check:ui-kit-snapshot` 與 `npm run test:vitest:ui`,並附上上游變更日誌開啟 PR。
