> **狀態：**儀表板建構於 **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`) 之上，並以工作區
> `packages/ui-kit` (`@omniroute/ui-kit`) 的形式納入版本控制（上游快照固定於
> `packages/ui-kit/UPSTREAM.md`，並由 `npm run check:ui-kit-snapshot` 檢查）。淺色是標準
> 主題；預設偏好設定為 `system`。預設調色盤採用套件的 **Editions** 外觀
> （暖色紙張中性色與銅色強調色 `#e5ac82`，`packages/ui-kit/src/ci-editions.css`）；設定 →
> 外觀 → 調色盤提供**經典**選項，使用套件的基礎權杖與萊姆色強調色。Switzer 是
> UI、展示與程式碼文字共用的唯一字型家族（`--ci-font-ui`；`--ci-font-display` 與
> `--ci-font-mono` 均解析為此字型），並由套件本身自行託管（`packages/ui-kit/src/ci-fonts.css`，
> 由 `ci-tokens.css` 匯入）。Switzer 缺少的文字系統會逐字形回退（`src/app/globals.css`）：
> 西里爾字母、希臘字母與越南文使用 Inter，而阿拉伯文字僅在 `html[dir="rtl"]` 下使用 Vazirmatn。
> 每個圖示皆為 Lucide 字形。

## 1. 事物存在的地方

- **成套工具。** `packages/ui-kit/src`是`packages/ui-kit/UPSTREAM.md`中固定的提交處上游`src/`的逐字節副本（也記錄許可證授權）； `PATCHES.md`列出本地補丁（無）。它作為源使用，無需構建： `next.config.mjs`對其進行轉譯， `tsconfig.json`映射`@omniroute/ui-kit` → `packages/ui-kit/src`和`@omniroute/ui-kit/*` → `packages/ui-kit/src/*` （`vitest.config.ts`和`vitest.mcp.config.ts`具有相同的別名）。透過其子路徑（`@omniroute/ui-kit/table`、 `@omniroute/ui-kit/page-header`...）導入套件元件，而不是透過`@omniroute/ui-kit`桶：桶將每個元件（包括日期選擇器）拉入每個導入器。套件樣式表透過`src/app/globals.css` （`@import "../../packages/ui-kit/src/ci-styles.css"`，完整的表：核心`ci-ui.css`加上每個模式系列）進入。
- **代幣。** `packages/ui-kit/src/ci-tokens.css`聲明`--ci-*`代幣； `src/app/globals.css`將它們橋接到舊的OmniRoute名稱（`--color-*`、 `--radius-*`、 `--font-sans`/`--font-mono`、 `--table-*`、 `--orch-status-*`、 `--color-fd-*`），因此現有的`var(--color-*)`讀取和Tailwind實用程式繼續工作。新程式碼使用Tailwind實用程式（`bg-surface`、 `text-text-muted`、 `border-border`、 `text-success`、 `bg-success-bg`、 `bg-chart-1`…）或套件類別—從不使用十六進位值（`tests/unit/design-kit-bridge.test.ts`強制橋接）。 `text-primary`透過`--text-color-primary`解析為`--color-primary-ink` ，因此主要文字保持可讀，而`bg-primary`/`border-primary`保留重音表面：在版本下，它是套件的`--ci-color-accent-active` （淺色深銅`#99562f` ，深色銅重音）；在經典下， lime-800在淺色下，石灰口音在深色下。圖表系列使用`--color-chart-1` … `--color-chart-8`，每個都有一個文字安全的`--color-chart-N-ink`和一個不透明的`--color-chart-N-subtle`晶片色調，按套件系列順序（`ciChartSeriesOrder`）分配。
- **主題。** `<html className="ci-theme">` (`src/app/layout.tsx`) 將文件選擇為套件主題。優選的是`light`、 `dark`或`system` （`THEME_CONFIG.defaultTheme = "system"`位於`src/shared/constants/appConfig.ts`中； `system`跟隨`prefers-color-scheme`）。 `src/store/themeStore.ts`中的`applyTheme()` （由`THEME_BOOT_SCRIPT`鏡像，內聯在`src/app/layout.tsx`中，在水合之前運行）設定`data-theme="dark"|"light"`並一起切換`<html>`上的`.dark`類別。此套件的暗令牌集以`data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`) 為密鑰； OmniRoute自己的暗覆蓋（ `globals.css`中的`.dark`塊）和`.dark`類別上的舊Tailwind `dark:`實用程式鍵。沒有強調色預設：強調色始終來自套件，並且在商店加載時會刪除舊版本中保留的預設。
- **調色板。**兩個，均來自套件 (`src/shared/constants/appearancePalette.ts`)：預設值`editions`和`classic`。 Editions 是`<html>`上套件的`data-ci-appearance="editions"`屬性， `ci-editions.css` （由`ci-ui.css`導入）與`data-theme`組合；經典就是該屬性的缺失。根佈局伺服器渲染屬性，因此沒有儲存任何內容（或沒有JS）的訪客在每個表面—儀表板、登入、 `/status`、錯誤頁面、 `/docs`和PWA上獲得版本。該選擇將保留在同一個`theme`存儲中的主題旁邊（`palette`、 `setPalette()`、 `src/store/themeStore.ts`中的`applyPalette()` ），並在`THEME_BOOT_SCRIPT`繪製之前應用（`src/shared/utils/themeBootScript.ts`，內聯在佈局的`<head>`中），僅當存儲的調色板為`"classic"`時才會刪除該屬性； `src/app/global-error.tsx`位於同一佈局它時才會刪除該屬性；不要將`data-ci-appearance`放在任何其他元素上：該套件將其與`html:root:has([data-ci-appearance="editions"])`匹配，因此一個後代將切換整個文件。 Editions `data-ci-editions-variant="landing"`變體適用於行銷頁面，而不是儀表板。瀏覽器 chrome：伺服器在`viewport.themeColor`中呈現預設版本（每個`prefers-color-scheme`一個標籤），並在`src/shared/constants/pwaThemeColors.ts`中呈現 Web 清單— `PWA_THEME_COLORS` ，這是版本`--ci-color-background` (`#f3f1e9` / `#11120f`) 的一個鏡像，由`tests/unit/pwa-theme-colors.test.ts`固定到`ci-editions.css` 。然後，即時`<meta name="theme-color">`遵循儲存的調色板和模式： `THEME_BOOT_SCRIPT`在繪製之前重寫標籤，主題商店的操作在每次變更時執行此操作（ `src/shared/utils/themeColorMeta.ts`中的`resolveThemeColor()` / `applyThemeColor()` ，其中`CLASSIC_PAGE_BACKGROUND`從套件的`ciTokens`讀取）。明確的light/dark主題將每個標籤設定為該模式； `system`為每個方案保留一種顏色。清單保留版本：每次安裝都會取得一次，沒有首選項。摩納哥從探針（`monacoKitTheme.ts`）讀取顏色；在版本下，探針讀取會翻轉一次同步傳遞的根`data-theme` ，因為該套件從根解析版本light/dark 。
- **組件（適配器）。** `src/shared/components/index.tsx`保留OmniRoute元件API （相同的名稱、預設導出和 props），其背後的原語是套件上的適配器`InfoTooltip`表單（`Button`、 `Input`、 `Textarea`、 `Checkbox`、 `Select`、 `Toggle`、 `Badge`、 `Card`）、覆蓋和`DataTable`（`Modal` `ConfirmModal`），結構（`Collapsible`、 `NotificationToast`、 `CollapsibleSection`、 `SegmentedControl`、 `Loading` `Avatar`和表（ `Breadcrumbs`、 `FilterBar`、 `ColumnToggle` `EmptyState` `FilterPills`、 `PresetSlider`） `Tooltip`適配器透過`warning`路徑導入 kit 元件，並將舊版 props 映射到它—上，例如`Button variant="primary"`是 kit `default`按鈕（`--ci-button-primary-*`：亮色下的反面，暗色下帶有`--ci-color-accent-foreground`墨水的重音）， `danger` ， `destructive`是 kit `warning` 。 `Badge`狀態變體是套件音調，帶有`<option>`子項的`Select`呈現套件`NativeSelect`。兩個適配器透過路徑導入，而不是從索引導入： `InteractiveTableRow` (`src/shared/components/InteractiveTableRow.tsx`)，一個工具包`TableRow` ，它接受`onActivate`和`selected`並回答 Tab、Enter 和 Space，以及`CodePreview` (`src/shared/components/CodePreview.tsx`)，工具包代碼區塊及其複製標籤已翻譯。 `tests/unit/ui/adapters/*.test.tsx`固定每個轉接器。
- **殼。** `src/app/(dashboard)/layout.tsx`呈現`DashboardLayout`，後者呈現`src/shared/components/layouts/DashboardShell.tsx`：套件`SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`)， OmniRoute的導航邏輯位於`src/shared/components/Sidebar.tsx`。指向`#main-content` 「跳到內容」連結是第一個可聚焦元素。 `src/shared/components/Header.tsx`包含`SidebarTrigger`套件（shell 唯一的側邊欄切換開關）、Keak `ProductSwitcher`和命令面板開啟器；它僅在`#main-content`內沒有安裝套件`PageHeader` (`.ci-page-header`) 時顯示路由標題，因此具有自己的`PageHeader`頁面有一個`h1`。 `src/shared/components/CommandPalette.tsx`是`Dialog`一個套件。
- **圖示.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) 透過`ICON_MAP` (`src/shared/constants/iconMap.ts`) 將名稱（螢幕使用的材質符號詞彙表）解析為 Lucide 字形。材質符號字體和套件消失了：地圖中缺少的名稱會呈現中性佔位符字形 (`data-icon-missing="true"`) 並在生產之外記錄控制台警告。 `npm run gen:icon-map`列印地圖中缺少的正在使用的名稱（`tests/unit/icon-map-coverage.test.ts`在沒有 Lucide 圖示的任何名稱上失敗； `tests/unit/icon-map-object-values.test.ts`涵蓋儲存在尋找物件中的名稱）； `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]`將文字`<span className="material-symbols-outlined">` spans 重寫為`<Icon>`。
- **品牌。** `src/shared/components/OmniRouteLogo.tsx`包裝套件：預設導出`OmniRouteLogo`呈現`ProductIcon product="omniroute" variant="glyph"` （內聯SVG、 `basePath` -safe）， `OmniRouteLockup`呈現`ProductLockup product="omniroute"` （可訪問名稱“Keak OmniRoute”），或者，對於白標籤運營商，他們自己的`name`/`logoSrc`。產品切換器目標位於`src/shared/constants/keakProducts.ts` （`KEAK_PRODUCT_LINKS`、 `KEAK_ACTIVE_PRODUCT`）。獨立螢幕— `src/app/login/page.tsx`、 `src/app/status/page.tsx`、 `src/app/maintenance/page.tsx`、 `src/app/offline/page.tsx`、 `src/app/not-found.tsx`和`src/shared/components/ErrorPageScaffold.tsx` —顯示鎖定； `tests/unit/brand-pages-static.test.ts`守護著它。

## 2. 規則

1. 令牌，絕不是字面意思。刻意保留的例外：始終黑暗的控制台終端和`STATUS_HEX` (`src/shared/constants/statusColors.ts`)，工具包狀態調色板的解析十六進位鏡像，供需要文字十六進制的呼叫者使用。分類調色板不再例外：它們依賴套件的八個圖表標記（`--color-chart-1..8`，加上`-ink`/`-subtle`），按照套件系列順序，透過`src/shared/utils/categoricalPalette.ts` ，以及用於路由策略的`src/app/(dashboard)/dashboard/combos/strategyPalette.ts`； ReactFlow邊緣和編排畫布讀取主題感知`--orch-status-*`變數 (`src/shared/components/flow/edgeStyles.ts`)。
2. 切勿手動修補`packages/ui-kit/src` ：與`scripts/dev/sync-ui-kit.sh <commit>`同步；預先提交門`npm run check:ui-kit-snapshot` (`.husky/pre-commit`) 在與固定的上游提交不同的任何位元組上失敗（當上游克隆`UI_KIT_CLONE`或`_references/cheaper-inference-ui-kit`不存在時，它會跳過並發出警告）。當套件缺少某些內容時，請在適配器或螢幕中解決它並向上游詢問。
3. 套件文字預設為英文（`label = "Loading"`、 `loadingLabel = "Loading table"`...） 每當套件元件呈現文字時， —都會傳遞來自`useTranslations(...)`的翻譯字串。
4. Tailwind實用程式勝過套件元件類別（套件宣告`@layer theme, base, components, utilities`及其規則位於`components`） —使用公用程式進行間距和佈局，而不是重新著色套件元件。排版是個例外： `packages/ui-kit/src/ci-typography.css`是在任何層之外導入的，因此它的標籤規則擊敗了實用程式。 Weight、 `tracking-*`和`leading-*`類別對`h1`沒有影響 –`h6`、weight 和`tracking-*`對表格單元格沒有影響，而weight 對按鈕沒有影響（`tests/unit/dead-typography-classes.test.ts`在那裡拒絕它們）； `font-mono`對`th`、 `td`、 `button`、 `input`和`textarea`沒有影響。尺寸、顏色和`uppercase`實用程式仍然適用。
5. 標題： `.ci-heading`用於頁面和章節標題； `.ci-dashboard-display`僅適用於大而稀疏的顯示文本，例如錯誤頁面狀態代碼。兩者都使用瑞士語。
6. `tests/unit/dashboard-kit-sweep.test.ts`保護套件採用： `src/app`或`src/shared/components`下沒有材料結紮跨度；在儀表板樹（`src/app/(dashboard)`和`src/shared/components`）中，沒有原始`<select>`、 `<textarea>`或`<table>` ，並且在列出的例外之外沒有手工製作的`role="dialog"` （ `Select`的本機分支具有`dark:` `RequestLoggerDetail` `kit-exception:` `<button>` `<input>`測試列出的文件中。
7. 在PR之前驗證兩個主題和 390 px 視口（螢幕截圖）； `tests/e2e/a11y.spec.ts`運行斧頭。
8. 顏色實用程式必須在`src/app/globals.css`中命名`@theme`區塊的標記：不存在的名稱（`text-text`、 `bg-bg-muted`、 `text-danger`...）不會產生CSS且元素保留繼承的顏色（`tests/unit/theme-color-classes.test.ts`）。沒有`card`類別：使用`Card`適配器 (`tests/unit/no-bare-card-class.test.ts`)。圖表顏色中的文字使用`text-chart-N-ink`； `text-chart-N`用於圖示和筆畫 (`tests/unit/chart-ink-for-text.test.ts`)。半透明顏色是使用`color-mix`建構的，而不是透過將十六進位 alpha 附加到可能是`var()` (`tests/unit/color-alpha-concatenation.test.ts`) 的值來建構。
9. 表：每個套件`Table`在繪製持久滾動條（`tests/unit/kit-tables-have-accessible-name.test.ts`）時都會傳遞`scrollLabel`（其滾動區域的名稱）和`scrollbarLabel` 。可點擊的行是帶有`onActivate` `InteractiveTableRow` ，而不是`<TableRow onClick>` (`tests/unit/table-row-click-needs-keyboard.test.ts`)。卡片內或任何邊框框內的表格會使用`containerClassName="rounded-none border-0"` (`tests/unit/datatable-not-framed-inside-card.test.ts`) 刪除自己的框架。
10. 顯示金額的條是套件`Progress`，或當套件條無法繪製它時（`tests/unit/progress-bars-have-semantics.test.ts`），則帶有帶有名稱和值的`role="progressbar"` 。選單、彈出視窗和工具提示來自套件（`Popover`、 `SearchableSelect`、 `Tooltip`適配器），而不是來自本地狀態（`tests/unit/hand-positioned-overlays.test.ts`）開啟的絕對定位面板。
11. 在`Input`適配器上`className`樣式化欄位包裝器；用於控制的類別位於`inputClassName` (`tests/unit/input-adapter-classname-destination.test.ts`) 中。

## 3.添加螢幕

## 5. 更新套件

`npm run check:ui-kit-upstream`將`packages/ui-kit/UPSTREAM.md`中固定的版本與上游儲存庫的最新`v*`標籤進行比較，並在發佈時列印同步命令。

每日`UI Kit upstream watch`工作流程 (`.github/workflows/ui-kit-upstream-watch.yml`) 執行相同的檢查。當 pin 位於後面時， `scripts/ci/ui-kit-sync-pr.sh`會在滾動分支`chore/ui-kit-sync-latest`上針對最高`release/vX.Y.Z`分支保持一個同步PR開啟。它永遠不會合併：每個套件版本仍然需要對本地VPS進行目視檢查。當新版本發佈時，分支會被重建，否則就不會發生。手動提交的開放PR不會被覆蓋，並且維護者關閉未合併的版本的PR將保持關閉狀態，直到新版本發布。

當無法開啟PR時（目標版本被凍結、 PR已手動提交、 PR已關閉或未設定PR令牌），工作流程會保持一個追蹤問題處於開啟狀態，並說明原因。

這個工作流程使用兩個秘密：

- `secrets.UI_KIT_READ_TOKEN`：私有上游儲存庫的唯讀令牌。當工作流程無法讀取上游（沒有令牌、令牌停止工作或GitHub無法存取）時，運行將保持綠色，但會寫入一條警告並保持一個單獨的問題處於開啟狀態，一旦稍後的運行可以再次讀取上游，該問題就會自行關閉。
- `secrets.UI_KIT_SYNC_PR_TOKEN`：此儲存庫上的細粒度令牌，具有內容和拉取請求寫入權限。預設的`GITHUB_TOKEN`不能在這裡建立PRs ，而且它開啟的PR不會觸發CI。如果沒有此令牌，工作流程只會推送分支。

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]`將該提交處的上游`src/` （`latest` =最新的`v*`標記）複製到`packages/ui-kit/src`中，應用單一允許的轉換（它從相對導入中刪除`.js`後綴），並將`packages/ui-kit/package.json`和`package-lock.json`中的工作區版本設定為上游版本。然後：檢視`git diff packages/ui-kit`，對兩個主題中的提供者、設定、組合、用法和端點進行視覺化傳遞，運行`npm run check:ui-kit-snapshot`和`npm run test:vitest:ui`，並使用上游變更日誌開啟PR 。

## README圖

根`README.md`嵌入的 12 個圖表 (`docs/diagrams/*.svg`) 是應用於靜態圖像的套件，它們是生成的，而不是手工繪製的： `scripts/docs/gen-readme-*.mjs`上的 13 個生成器檔案（12 個圖表加上`gen-readme-diagrams.mjs`驅動程式）和`tests/unit/docs/readme-*-svg.test.ts`上的 12 個過時測試，每個圖表一個，每個位元組將提交的檔案與其生成器的輸出作業（ `test-unit`）。

- **代幣。** `scripts/docs/readme-diagram-theme.mjs`從`packages/ui-kit/src/ci-editions.css`複製版本調色板（預設外觀）（由`tests/unit/docs/readme-diagram-theme.test.ts`固定在該檔案上，它還會檢查WCAG AA兩種方案中每個表面上的每種文字顏色；一個例外，淺`warn`，是套件警告變暗 10 %，因為套件在畫布上的值為 4.46:1），並在字體的比例上定義：`ci-tokens.css` 400/500/600，顯示為 500）並追蹤所有內容，但代碼角色（`.cmd`、 `.term`、 `.term-lg`、 `.mono`、 `.mono-sm`、 `.mono-xs`）除外，它們是IBM Plex Mono，僅適用於命令、 URLs、識別碼和終端螢幕。檔案內的亮值位於`:root`上，暗值位於`prefers-color-scheme: dark`後面，因此每個影像都遵循檢視者在GitHub上的方案。
- **字體。** GitHub Markdown 不攜帶CSS ，且迷彩代理會阻止每個外部獲取，因此套件類型必須在文件內傳輸。 `scripts/docs/readme-outline.mjs`是每個生成器的最後一步，它使用HarfBuzz來塑造 Switzer 角色，並將它們繪製為向量輪廓（`<defs>`路徑和`<use>`），並使用 Switzer 缺乏的根據其自己的度量繪製的箭頭和幾何符號。輪廓，絕不是嵌入字體：Switzer 的許可證 (`packages/ui-kit/src/fonts/FFL.txt`) 禁止在未經書面同意的情況下進行子集化和格式轉換，並允許向量圖形，因此不要重新引入 Switzer `@font-face`或`data:` URI。文件中留下的一種字體是OFL IBM Plex Mono 子集，用於保留真實代碼文字 (`scripts/docs/readme-fonts.mjs`)，由這些字元建構；任何不能嵌入的字形都會拋出異常。
- **再生。** `npm run docs:readme-diagrams`按README順序重寫所有 12 個文件，並為每個文件列印一行及其大小。單一生成器也可以獨立運作（`node scripts/docs/gen-readme-<name>.mjs`； `free-tier-budget`需要`node --import tsx/esm`因為它的資料來自`open-sse/config/freeModelCatalog.ts`中的即時目錄載入器；目錄變更的CI結果位於`docs/architecture/QUALITY_GATES.md` → `docs-sync-strict`中）。將生成器和SVG一起提交。過時的SVG在發布模式下失敗；在功能PR中， `npm run check:generated-artifacts`僅判斷PR編輯的SVG （`docs/architecture/QUALITY_GATES.md` → “生成的文件和派生基線”）。
- **證明。** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>`以GitHub服務的方式渲染檔案（ `<img>`標籤、camo 的`Content-Security-Policy`、 `image/svg+xml`），捕捉淺色和深色框架並報告頁面發出的外部字體請求（必須為 0）。
- **預算。**每個檔案低於 200 個KB （每個過時測試都斷言這一點）； 500 KB是任何README鏡像的硬上限（ SVG studio 驗證器的規則）。
- **複製不變，從門開始計數。**品牌重塑改變了類型和調色板，而不是單字：每個生成器在`*_COPY`常數中攜帶其圖表的副本（或從實時目錄構建它），該常數既是繪製的文本也是大綱步驟的輸入。規範圖形保留在`<text>`節點中（輪廓一旦勾勒就不可見， `fill-opacity:0`），由`check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) 讀取；門讀取的圖表的陳舊性測試也在生成的文件上運行其驗證器，因此與代碼漂移的數字無法通過測試—修復門讀取的源，而不是生成器中的數字。
