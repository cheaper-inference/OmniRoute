中立的`config/cli-tools-manifest.json`合約聲明規範的IDs、別名、二進位候選、設定配方、模型參數和功能。 `bin/cli/cli-manifest.mjs`中的普通 Node 適配器和`src/shared/constants/cliIntegrationManifest.ts`中的TypeScript適配器讀取相同的檔案。運行時、目錄、配置、完成、產生器和後端註冊由`tests/unit/cli/cli-manifest-drift.test.ts`一起檢查。編目並不意味著可以啟動或配置工具。特別是，5dive 仍然僅可設定。

## 兒童環境與生命週期

`omniroute run`、 `omniroute launch`和`omniroute launch-codex`繼承OS/terminal相容性白名單並注入所選目標的憑證。預設情況下，不繼承不相關的提供者和資料庫機密。 `--inherit-env`明確恢復完整的父環境繼承；僅當選定的第三方程序應接收這些值時才使用它。這是環境過濾，而不是OS沙箱：進程仍然以呼叫者的檔案系統權限運作。

中斷和終止訊號被轉發給子程序。啟動器在刪除臨時配置之前等待子進程的關閉事件。 `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS`控制強制終止之前的寬限期（預設5000毫秒）。

`omniroute launch <tool>` （參見[LAUNCH.md](./LAUNCH.md) ）遵循相同的環境規則和訊號轉發，並添加：

- **網關自動啟動。**對於本機目標，當連接埠上沒有閘道應答時，啟動器會在分離的收割者程序下啟動綁定到`127.0.0.1`的`omniroute serve --headless --no-open` 。每個正在運行的啟動都在`DATA_DIR/launch/leases/`中持有租約（每 15 秒檢測一次，45 秒後或其進程消失時失效）。一旦在空閒寬限期內沒有任何租約存在，收割機就會停止它啟動的網關（`OMNIROUTE_LAUNCH_IDLE_GRACE_MS`，預設為 10000 毫秒）。用戶啟動的網關已被使用但從未停止。 `--keep-gateway`或`omniroute gateway keep`將啟動器閘道變成普通網關； `--no-start`恢復舊的「fail-if-down」行為。僅探測遠程目標。
- **啟動會議。**每次啟動都會從父憑證 (`POST /api/launch/sessions`) 中建立一個短期的`olx_`會話令牌，在工具運行時對其進行檢測，讀取使用情況摘要並在工具退出後撤銷它。該令牌是其父代令牌的嚴格子集：相同的權限、相同或更窄的目錄、較短的生命週期，並且它不是儀表板憑證。此工具接收會話令牌，而不是父憑證，除非給予`--tag` ，否則請求將被標記為`launch:<tool>:<sessionId>` 。沒有會話API網關會因`GatewayTooOld`失敗，而不是回退到無範圍啟動。
- **每次啟動配置。**工具設定檔寫入私有暫存目錄（模式 0700，前綴`omnirouter-`）並在子程序退出後刪除。啟動器的`SIGKILL`會留下目錄；一旦此類目錄超過一天， `omniroute launch --cleanup`就會將其刪除。

## Gemini持久設置

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

前兩個指令為選定的本機或遠端伺服器設定此電腦。安裝程式保留不相關的JSON設置，選擇Gemini API 金鑰驗證，並將端點和憑證寫入私有`.gemini/.env`檔案。它拒絕無效的JSON而不是覆蓋它。端點URLs必須是HTTP(S)，沒有嵌入的憑證、查詢參數或片段。試運行列印路徑，而不是憑證值。

`GEMINI_CLI_HOME`或`--gemini-home`選擇持久主根。實際的`run gemini`創建並隨後刪除自己的臨時家。這兩種模式都不會繞過Gemini的工作區信任檢查。

## Codex簡介

`configure codex`使用模型及其OmniRoute提供者端點來寫私有`<name>.config.toml` 。憑證透過`OMNIROUTE_API_KEY`引用，從不嵌入。 launch 指令在頂級`model`鍵設定所選模型，而不是在`model_providers`內。

單獨的設定檔是目前記錄的Codex合約；當使用`codex --profile <name>`選擇時，它們會覆蓋使用者配置。請參閱[官方設定檔參考](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles)和[OmniRoute Codex指南](./CODEX-CLI-CONFIGURATION.md)。

## 密封命令執行

透過明確`DATA_DIR`，設定`OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1`可防止啟動時陷入預設使用者資料目錄的憑證環境。這對於孤立測試很有用。它不會停用其他明確選擇的環境文件。

## 工作目錄`.env`

CLI依此順序讀取`.env`文件，第一個設定金鑰的檔案獲勝：顯式`DATA_DIR`、預設資料目錄、目前工作目錄，然後是套件目錄。 shell 變數總是獲勝。

工作目錄可能屬於其他人（克隆的儲存庫、解壓縮的存檔），並且`omniroute serve`將CLI環境傳遞到伺服器以及伺服器運行的每個工具。因此`.env`可能只設定`bin/cli/utils/untrustedCwdEnv.mjs`中列出的這些鍵：

| 鑰匙                            | 接受的值                                                 |
| ------------------------------- | -------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`、 `1`或`yes`在任何情況下，伺服器視為 on 的值      |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 最多 64 個字母、數字、 `_`、 `.`、 `@`或`-`              |
| `LANGUAGE`                      | 一樣，加上`:`                                            |
| `TZ`                            | 最多 64 個字母、數字、 `_`、 `+`、 `-`或`/`，不以`/`開頭 |
| `NO_COLOR`, `FORCE_COLOR`       | 最多 16 個字母和數字                                     |

`REQUIRE_API_KEY`接受的每個值都會開啟檢查，因此檔案無法自行關閉檢查。但它並沒有決定結果：伺服器在環境之前讀取儲存在資料庫中的`REQUIRE_API_KEY`覆蓋，而有關在沒有API密鑰的情況下偵聽所有介面的啟動警告僅讀取環境。透過儲存的`false`覆蓋，工作目錄`REQUIRE_API_KEY=true`使API保持開啟並隱藏該警告。 `TZ`規則比POSIX更窄：它拒絕`.`、 `:`、 `,`和`<>`，因此必須在 shell 或`<DATA_DIR>/.env`中設定`:Area/City`形式和`EST5EDT,M3.2.0,M11.1.0`等規則。

名稱必須完全符合（大寫）。任何其他行、檢查失敗的值以及不是普通ASCII字母、數字和`_`的名稱（例如帶有NUL位元組或相似字母的名稱）都會被跳過。 CLI列印一個警告，其中命名了它無法設定的鍵，並列印了一個警告，命名了它忽略的允許鍵，每個警告都包含要更改的內容（`TZ (expected a zone name such as Europe/Berlin)`、 `lang (write the name as LANG)`）。都不列印值。這些訊息中的檔案路徑以及`omniroute doctor`報告的`.env`路徑在包含控製字元或 bidi 字元時會被轉義。當工作目錄是資料目錄或套件目錄時，此限制不適用。

`PORT`、 `API_PORT`和`DASHBOARD_PORT`不在列表中。如果沒有來自更高優先權來源的基本URL ， CLI會與`localhost:<PORT>`進行對話，並且無論在那裡偵聽的內容都會接收CLI的API密鑰、上下文令牌和CLI機器令牌（`x-omniroute-cli-token`，請參閱[CLI_TOKEN.md](../security/CLI_TOKEN.md) ），本地伺服器接受來自環回的管理呼叫。工作目錄中的連接埠將允許該檔案選擇偵聽器，因此請在 shell、 `<DATA_DIR>/.env`中或使用具有連接埠（`serve`、 `launch`、 `run`）的命令的`--port`選項設定連接埠。

解析器沒有`export`語法。諸如`export LD_PRELOAD=...`之類的行將變數命名為`export LD_PRELOAD`；從工作目錄中它會被跳過，並且在其他`.env`檔案中它會設定該文字名稱，但不會讀取任何內容。

CLI僅將上下文的儲存令牌（存取權杖或舊API金鑰）與該上下文自己的來源：方案、主機和連接埠配對，與`URL.origin`相比。這適用於透過CLI的HTTP客戶端（`--base-url`、 `OMNIROUTE_BASE_URL`、 `omniroute connect <new-url>`）發出的請求以及將基本URL和金鑰寫入另一個工具配置的`launch`、 `launch codex`、 `configure`和`setup-*`指令。使用`--remote`指向另一台伺服器，它們使用明確`--api-key`或`OMNIROUTE_API_KEY`如果設定了），並且沒有上下文令牌。比較是精確的，因此`localhost`和`127.0.0.1`，或者有或沒有尾隨點的主機，算作不同的伺服器並且不會獲得上下文令牌。具有 userinfo、反斜線或空格的URL永遠不會匹配，因為其他URL解析器（例如 Python 的`urllib`和`httpx`）可以從中讀取不同的主機。對於CLI本身發送的請求，該檢查僅涵蓋方案和權限，因此路徑或查詢中帶有空格的 id 會保留令牌。
