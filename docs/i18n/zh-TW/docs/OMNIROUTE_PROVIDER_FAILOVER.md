在做出重試決定之前對失敗進行分類。

暫時性故障（例如逾時、網路錯誤、速率限制和提供者 5xx 回應）可能會進行故障轉移。耗盡的配額或信用（配額 429 或 402 要求付款）永遠不會在同一提供者上重試，但會故障轉移到另一提供者，其配額是單獨的。認證錯誤、權限錯誤、無效請求、不可用模型、未知失敗等情況不會盲目重試。

預設的跨提供者策略允許最多 3 次提供者嘗試、重試速率限制和逾時、配額耗盡時的故障轉移，以及將管理停用與臨時電路狀態分開。

## 適用地點

- **組合**根據組合自己的策略和設定在目標之間進行故障轉移。
- **裸模型 ID** （無`provider/`前綴）多個活動提供者提供的服務，沒有該確切名稱的組合，首先發送到提供者推理選擇。如果該嘗試以策略故障轉移的方式失敗，則相同的請求將傳送至提供該 ID 的下一個活動提供者。此回應攜帶`x-omniroute-fallback-attempts`以及在應答之前嘗試過的提供者數量。
  - 每個候補都被完全授權，就像推理選擇了它一樣。 API鍵阻止或不承認的目標將在沒有上游呼叫的情況下被跳過，並且客戶端會收到真正的上游錯誤，而不是對其從未命名的目標的策略拒絕。
  - 只有失敗的回應才會繼續：在第一個串流傳輸的位元組之後沒有任何故障轉移。
  - 緊急後備模型交換僅在所請求模型的每個提供者都失敗後才適用。
  - 固定到連線 (`x-omniroute-connection`) 的請求將保留在該連線上。
  - 帶有前綴的 id (`provider/model`) 永遠不會重新路由到另一個提供者。

電路狀態為`closed`、 `open`和`half_open`。冷卻時間安排有界探針；成功的探頭會關閉電路，失敗的探頭會重新開啟電路。
