## 2026-10-18 SiliconFlow 免費模型修正（#17028）

十個已公布正數每 token 價格的 SiliconFlow 旗艦模型，被錯誤地以 `recurring-uncapped` 免費存取形式發布。這十列現已從靜態目錄中**移除**，目錄目前共有 **467 個項目**。SiliconFlow 不再為靜態總數貢獻任何無條件免費模型項目或永久免費提供者。

這**不**代表 SiliconFlow 沒有免費模型。僅免費匯入功能與「免費」徽章現在要求**即時提供者模型承載資料提供每個模型的正面證據**，例如明確的免費布林標記，或輸入與輸出 token 價格皆為零。明確的付費標記或任何正數價格，優先於樂觀的免費標記。若模型沒有可用的即時證據，則**不會**被假定為免費；新帳戶的一次性額度無法證明存在週期性免費配額。若目前的提供者 API 無法提供可靠的模型層級定價，請先在提供者主控台中確認，再進行路由。這項保守選擇可避免透過僅免費匯入與自動組合而產生意外費用。

下方的歷史提供者表格並非即時可用性的承諾。先前的 SiliconFlow 無上限／10 模型項目已刻意移除，因為它不再代表已確認的週期性免費配額。

## 2026-10-15 Bytez 與 Nous 修正

[Bytez 計費](https://docs.bytez.com/model-api/docs/billing)將其免費方案的
開放模型限制在 7B 參數以內。70B 與 72B 的項目需要購買點數才能
解鎖，因此已移除。Mistral-7B 仍屬於 `recurring-credit`：點數
每四週更新一次，但費用按推論秒數計算，且未公布 token
額度。其 token 計數器設為零，以表示數量未知，取代不受支援的 1M-token
估算；這不代表免費點數為零。Nous 的變更詳述於下方的提供者備註中。

## 兩種機制——計數與判定

OmniRoute 透過兩種刻意讀取
不同來源的機制回答「它是否免費？」：

| 機制           | 事實來源                                                                                                                                                 | 適用介面                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **計數／顯示** | 解析後的目錄——已發布的基準資料疊加 Radar 資料來源（`getRadarCatalog`）                                                                                   | 免費層級總量、預算卡片、儀表板                                                                           |
| **判定**       | 僅限已發布的目錄（`open-sse/config/freeModelCatalog.data.ts` 中的 `FREE_MODEL_BUDGETS`），加上本機啟發式規則（`:free` 後綴、零定價、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` 的所有使用端：模型匯入、`auto/*` 路由、`GET /v1/models`，以及瀏覽器預覽 |

只要資料來源可用，計數即可隨之改善。判定則維持使用
發布成品，因此瀏覽器與伺服器上的答案完全一致，
可離線重現，也能在沒有資料庫的情況下測試。若讓瀏覽器
預覽讀取一個來源，而伺服器匯入讀取另一個來源，預覽結果就會
與點擊後實際發生的行為不一致——這種區分是
刻意保留的。

## 方法論和注意事項

- 數字是**上限估計**從每個提供者記錄的免費套餐限制開始**2026-06-17** ，由網路研究收集。免費等級不斷變化， —在依賴數字之前重新驗證。
- **條目實際上證明了什麼。**沒有條目帶有每行的置信度評級，且API不服務—將上面的每個數字視為對相同的未聲明品質的估計。有兩個事實是不同的，因為它們是手工策劃的而不是推斷的：44 個條目帶有獨立記錄的硬停止（其中 39 個是xKiro行，它們共享一份每日津貼），22 個條目帶有提示培訓披露。僅當提供者自己的條款規定超過免費限額會拒絕請求而不是默默地開始向您收費時才設置`hardStopGuaranteed` ，來源位於條目旁邊的評論中；它永遠不會預設為`true`，並且沒有人驗證的條目保持未設定狀態。因此，缺少硬停止標誌意味著“未建立”，而不是“已知會向您收費”。**STRICT模式**（選擇加入的`freeAccessPolicy=strict`路由防護）僅信任帶有該標誌的條目；所有其他免費套餐均被排除為`no-hard-stop` （請參閱`open-sse/services/autoCombo/strictZeroCostFilter.ts`）。當防護過濾池時，操作員可見的日誌會報告排除計數及其`no-hard-stop`份額。
- `estMonthlyFreeTokens` =僅每月循環代幣。**一次性註冊積分不會重複出現**計為 0。停產的等級也是 0。
- 每日代幣上限→ `monthly = daily × 30`。只有RPD記錄了→ `RPD × ~800 output tokens × 30`。僅限RPM/TPM （無每日上限） →**不封頂的**（見下文）。
- **免費訪問，但沒有公佈代幣上限**(`glm-cn`, `tencent`, `baidu`, `kilo-gateway`, `opencode-zen`, `gemini`, `nvidia`)：這些是rate/concurrency-limited.我們將它們分類為`recurring-uncapped`和**永遠不要對它們求和**—乘以`RPM × 24/7 × 30d`將產生幻想上限（我們拒絕的通貨膨脹）。 NVIDIA的API僅供試用；請參閱下面的ToS警告。
- **存款解鎖提升：**一次性小額充值，永久提高免費配額（OpenRouter： $10 → 1000 req/day ≈ +24M/mo）。作為單獨的數字進行報道，不出現在穩定的標題中。
- **資格限製配額**(`eligibilityGate: "regional-identity"`)：真正的經常性額度，只有在區域內的身份檢查（今天中國大陸實名認證）後才開放。使用相同的池重複資料刪除規則將其計入單獨的數字 (`gatedRecurringTokens`)，而不計入穩定的標題。制度（`freeType`）不變，因此路由也不變。
- **證據類。**規則：目錄中的數字在條目`// evidence:` — `public-page`任何人都可以閱讀的提供者頁面）、 `api-public` （提供者的未經身份驗證的端點，例如NaraRouter位於 router.bynara.id 的公共計劃端點）或`console-verified <date> por <who>` （該圖僅在帳戶控制台內可見；評論今天的狀態：2026-09-02 重新審查的五個區塊（`gemini`、 `groq`、 `mistral`、 `ollama-cloud`、 `nara`）；2026 年 9 月 2 日重新審核之前的條目繼承了早期的研究，直到它們被觸及；任何**新的或改變的**沒有證據註釋的數字是一個錯誤。目前只有`mistral`經過控制台驗證。

## 為什麼我們的數量比其他聚合商少

該領域的大多數「每月免費代幣」數字都是每個模型標籤的總和。我們的目的不是故意的：

- **每個共享池都被計數一次。** Mistral的免費計劃是每個組織獲得一份1B/month津貼；將其列為五種型號並不意味著它是 5B。根據模型總結，我們自己的目錄將顯示為**~ 7.4B** （2026-09-03重新計算；這個數字不是CI門控的—只要目錄改變就重新測量） —標題說**~ 1.47B**因為這是每個提供者的一個帳戶實際上可以花費的金額。
- **每日上限已轉換，但費率未轉換。**記錄在案的tokens/day上限變為`× 30`；記錄在案的requests/day上限變為`RPD × ~800 tokens × 30`；每分鐘僅發布請求的提供者**不**每月的數字並被列為_uncapped_，從未求和。將利率限制乘以24/7就是我們拒絕的通貨膨脹。
- **區域身份檢查背後的配額是分開顯示的**(`+~6M behind regional identity verification`)，因為大多數讀者無法使用它們。
- **註冊積分僅限第一個月**並作為第二個數字報告，從未混合到穩定數字中。
- **該數字由CI強制執行。**當此檔案、 README或預算卡偏離目錄時， `npm run check:docs-counts`會重新計算目錄中的總計，並導致建置失敗。

## 詞彙表

| 術語                    | 含義                                                          |
| ----------------------- | ------------------------------------------------------------- |
| **RPM / RPD / RPH**     | 每分鐘 / 每日 / 每小時的請求數                                |
| **TPM / TPD**           | 每分鐘 / 每日的 Token 數                                      |
| **Documented grant**    | 提供者公布明確的每日／每月 Token 上限（可作為合理依據的預算） |
| **Theoretical ceiling** | `rate-limit × 24/7 × 30d` — 理論最大值，而非獲准的預算        |
| **Neuron**              | Cloudflare 運算單位（約等於 1 個輸出 Token）                  |

> 根據 2026-06-05 針對各提供者的研究產生。若要更新，請重新執行研究工作流程（請參閱 `_tasks/features-v3.8.12`）。
