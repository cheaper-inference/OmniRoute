## TL;DR — OmniRoute 實際彙整了多少免費推論額度？

這些數據描述目錄中不同第三方帳戶及其資格條件。OmniRoute 不會提供這些額度：您必須取得所需帳戶或憑證、連線至符合資格的提供者，並遵守其限制。實際可用容量可能更低；在全新安裝且沒有符合資格的路由時，甚至可能為零。標記為 `tos: avoid` 的提供者預設不會納入自動路由。

**查核日期：2026-10-08：** [Cerebras](https://www.cerebras.ai/pricing) 提供一次性 $5 促銷額度，必須提供付款方式，並會在 30 天後到期。[Gemini](https://ai.google.dev/gemini-api/docs/rate-limits) 公布了專案／模型／方案層級的速率限制；其仍未納入量化的每月主要數字。

## 2026-10-18 SiliconFlow 免費模型修正（#17028）

十個已公布正數每 token 價格的 SiliconFlow 旗艦模型，被錯誤地以 `recurring-uncapped` 免費存取形式發布。這十列現已從靜態目錄中**移除**，目錄目前共有 **467 個項目**。SiliconFlow 不再為靜態總數貢獻任何無條件免費模型項目或永久免費提供者。

這**不**代表 SiliconFlow 沒有免費模型。僅免費匯入功能與「免費」徽章現在要求**即時提供者模型承載資料提供每個模型的正面證據**，例如明確的免費布林標記，或輸入與輸出 token 價格皆為零。明確的付費標記或任何正數價格，優先於樂觀的免費標記。若模型沒有可用的即時證據，則**不會**被假定為免費；新帳戶的一次性額度無法證明存在週期性免費配額。若目前的提供者 API 無法提供可靠的模型層級定價，請先在提供者主控台中確認，再進行路由。這項保守選擇可避免透過僅免費匯入與自動組合而產生意外費用。

下方的歷史提供者表格並非即時可用性的承諾。先前的 SiliconFlow 無上限／10 模型項目已刻意移除，因為它不再代表已確認的週期性免費配額。

## 2026-10-15 Bytez 與 Nous 修正

[Bytez 計費](https://docs.bytez.com/model-api/docs/billing)將其免費方案的
開放模型限制在 7B 參數以內。70B 與 72B 的項目需要購買點數才能
解鎖，因此已移除。Mistral-7B 仍屬於 `recurring-credit`：點數
每四週更新一次，但費用按推論秒數計算，且未公布 token
額度。其 token 計數器設為零，以表示數量未知，取代不受支援的 1M-token
估算；這不代表免費點數為零。Nous 的變更詳述於下方的提供者備註中。

## 兩種機制——計數與判定

OmniRoute 透過兩種刻意讀取
不同來源的機制回答「它是否免費？」：

| 機制           | 事實來源                                                                                                                                                 | 適用介面                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **計數／顯示** | 解析後的目錄——已發布的基準資料疊加 Radar 資料來源（`getRadarCatalog`）                                                                                   | 免費層級總量、預算卡片、儀表板                                                                           |
| **判定**       | 僅限已發布的目錄（`open-sse/config/freeModelCatalog.data.ts` 中的 `FREE_MODEL_BUDGETS`），加上本機啟發式規則（`:free` 後綴、零定價、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` 的所有使用端：模型匯入、`auto/*` 路由、`GET /v1/models`，以及瀏覽器預覽 |

只要資料來源可用，計數即可隨之改善。判定則維持使用
發布成品，因此瀏覽器與伺服器上的答案完全一致，
可離線重現，也能在沒有資料庫的情況下測試。若讓瀏覽器
預覽讀取一個來源，而伺服器匯入讀取另一個來源，預覽結果就會
與點擊後實際發生的行為不一致——這種區分是
刻意保留的。

## 方法與注意事項

- 數字是根據各提供者截至 **2026-06-17** 所記載的免費層級限制，透過網路研究彙整而成的**上限估算值**。免費層級經常變動——依賴任何數字前請重新驗證。
- **每個項目實際保證的內容。** 所有項目都沒有逐列信心評級，API 也不提供——請將上述每個數字視為品質相同但未明示的估算值。有兩項事實不同，因為它們是人工整理而非推斷所得：44 個項目具有獨立記載的硬性停止機制（其中 39 個是 xKiro 項目，它們共用同一每日額度），另有 20 個項目帶有提示詞訓練揭露。只有在提供者自身條款表明超出免費額度時會拒絕請求，而非在未提示的情況下開始計費，才會設定 `hardStopGuaranteed`，且來源會寫在項目旁的註解中；其值絕不會預設為 `true`，未經任何人驗證的項目會維持未設定。因此，缺少硬性停止標記代表「尚未確認」，而非「已知會向你收費」。**STRICT 模式**（選用的 `freeAccessPolicy=strict` 路由防護）只信任帶有該標記的項目；其他所有免費層級都會以 `no-hard-stop` 為由排除（請參閱 `open-sse/services/autoCombo/strictZeroCostFilter.ts`）。防護機制篩選集區時，操作人員可見的日誌會同時回報排除數量，以及其中 `no-hard-stop` 所占的比例。
- `estMonthlyFreeTokens` = 僅計算每月週期性 token。**一次性註冊點數不會重複發放**，因此計為 0。已終止的層級也計為 0。
- 每日 token 上限 → `monthly = daily × 30`。若僅記載 RPD → `RPD × ~800 output tokens × 30`。若僅有 RPM/TPM（沒有每日上限）→ **無上限**（見下文）。
- **永久免費，但未公布 token 上限**（`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：這些是確實存在且週期性提供的免費存取，但受到速率／並行限制。我們將它們分類為 `recurring-uncapped`，並且**絕不將其加總**——以 `RPM × 24/7 × 30d` 相乘會產生不切實際的上限（這正是我們拒絕的膨脹計算方式）。列出它們是為了讓你知道這些方案確實存在。
- **儲值解鎖加成：** 一次性的小額儲值，可永久提高免費配額（OpenRouter：$10 → 1000 req/day ≈ +24M/mo）。此數字會分開回報，不納入穩定額度的主要數字。
- **資格限制配額**（`eligibilityGate: "regional-identity"`）：這是確實存在的週期性配額，但只有在完成地區綁定的身分驗證後才會開放（目前為中國大陸實名驗證）。使用相同的集區去重規則計入獨立數字（`gatedRecurringTokens`），絕不納入穩定額度的主要數字。機制（`freeType`）維持不變，因此路由也不變。
- **證據類別。** 規則如下：目錄中的數字會在項目旁的 `// evidence:` 註解中引用來源——`public-page`（任何人都能閱讀的提供者頁面）、`api-public`（提供者無需驗證的端點，例如 NaraRouter 位於 router.bynara.id 的公開方案端點），或 `console-verified <date> por <who>`（該數字只能在帳戶主控台內查看；註解會記錄查看者與日期，以及說明此上限存在的公開頁面）。目前狀態：於 2026-09-02 重新稽核的五個區塊都已帶有此註解（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）；早於 2026-09-02 重新稽核的項目，在更新前會沿用先前的研究結果；任何**新增或變更**但沒有證據註解的數字都屬於錯誤。目前只有 `mistral` 經主控台驗證。

## 為什麼我們的數字比其他彙整平台小

在這個領域，大多數「每月免費 token」數字都是各模型標示額度的加總。我們刻意不這麼做：

- **每個共享額度池只計算一次。** Mistral 的免費方案是每個組織每月共用 1B 額度；把它列在五個模型下並不會讓它變成 5B。若按模型加總，我們自己的目錄數字會是 **~7.4B**（於 2026-09-03 重新計算；此數字不受 CI 檢查管控——每當目錄變更時請重新測量）——標題所列的是 **~1.47B**，因為這才是每個提供者各一個帳號實際可使用的總量。
- **每日上限會換算，速率限制則不會。** 文件明載的每日 token 上限會以 `× 30` 換算；文件明載的每日請求上限會以 `RPD × ~800 tokens × 30` 換算；如果提供者只公布每分鐘請求數，則**不會**提供每月數字，而是列為_無上限_，且絕不納入加總。我們拒絕以全天候 24/7 的方式乘算速率限制來灌水。
- **需要通過地區身分驗證才能取得的配額會另行列出**（`+~6M，需通過地區身分驗證`），因為大多數讀者無法使用這些配額。
- **註冊贈送額度僅適用於第一個月**，並會以第二個數字另行呈現，絕不與穩定持續的額度混合計算。
- **此數字由 CI 強制驗證。** `npm run check:docs-counts` 會根據目錄重新計算總額；當本檔案、README 或預算卡片中的數字與計算結果不一致時，建置就會失敗。

## 詞彙表

| 術語                    | 含義                                                          |
| ----------------------- | ------------------------------------------------------------- |
| **RPM / RPD / RPH**     | 每分鐘 / 每日 / 每小時的請求數                                |
| **TPM / TPD**           | 每分鐘 / 每日的 Token 數                                      |
| **Documented grant**    | 提供者公布明確的每日／每月 Token 上限（可作為合理依據的預算） |
| **Theoretical ceiling** | `rate-limit × 24/7 × 30d` — 理論最大值，而非獲准的預算        |
| **Neuron**              | Cloudflare 運算單位（約等於 1 個輸出 Token）                  |
