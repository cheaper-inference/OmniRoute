## Me Ya Sa Ake da Kunshin Workspace Na Daban?

`open-sse/` **workspace mai zaman kansa** ne a cikin monorepo na OmniRoute saboda dalilai da dama:

1. **Sake amfani** — ana wallafa `open-sse` a matsayin `@omniroute/open-sse` a npm, don haka sauran ayyuka za su iya amfani da shi da kansu
2. **Iyakoki masu tsabta** — an ware injin watsa bayanai daga matakin UI/DB na musamman ga OmniRoute
3. **Aiki mai sauri** — injin ba shi da dogaro da Next.js, wanda ke ba da damar farawa cikin sauri a mahallin CLI/serverless
4. **Sarrafa sigogi** — `open-sse` zai iya fitar da sabbin sigogi bisa jadawalinsa

```json
// package.json
"workspaces": ["open-sse"]
```

## Bututun Buƙata

Kowace buƙatar LLM tana bi ta cikin **bututu mai matakai 5**:

```
                              ┌──────────────┐
   Buƙatar HTTP                │  1. HANYA    │   warware combo, zaɓen model
   (hanyar Next.js)            └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  2. FASSARA  │   sauya tsari (OpenAI ↔ Claude ↔ Gemini)
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  3. AIWATAR  │   mai aiwatar da mai samarwa, HTTP, sake gwadawa, breaker
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  4. WATSA    │   sauya SSE, backpressure
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  5. RIKODA   │   bin sawun amfani, rajistar kira, rarraba kurakurai
                              └──────┬───────┘
                                     │
                                     ▼
                              Amsar HTTP (SSE ko JSON)
```

### Mataki na 1: Hanya (services/combo.ts)

**Wurin shiga**: `handleComboChat()` a cikin `services/combo.ts`

Yana warware buƙatar zuwa takamaiman tuple na `(provider, model, account, credentials)`:

- Nemo combo ta ID (ko gina combo na kama-da-wane don models na `auto/*`)
- Aiwatar da dabarar zaɓen hanya (fifiko, weighted, round-robin, da sauransu)
- Tace masu samarwa marasa lafiya (circuit breaker)
- Zaɓi manufa mai aiki ta gaba

Ga models na `auto/*`, wannan matakin kuma yana:

- Gudanar da tsarin **ƙididdiga mai dalilai 16** (`services/autoCombo/`)
- Zaɓar tagwayen `provider+model` bisa lafiya, farashi, latency, da sauransu

### Mataki na 2: Fassara (translator/)

Idan tsarin tushe (misali, OpenAI) ya bambanta da tsarin manufa (misali, Claude), ana **fassara** buƙatar:

- System prompt → system message
- Ma'anar kayan aiki → tsarin kayan aiki na musamman ga mai samarwa
- Sigogin reasoning/thinking → makamantansu na musamman ga mai samarwa
- Daidaita matsayin saƙo (`developer` → `system` ga waɗanda ba OpenAI ba)

`translator/index.ts` yana samar da:

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### Mataki na 3: Aiwatar (executors/)

**Wurin shiga**: `getExecutor(providerId).execute(request, options)`

Dukkan masu samarwa suna amfani da `DefaultExecutor` (`executors/default.ts`) ta hanyar madadin masana'antar `getExecutor()`. Mai aiwatarwar yana:

- Gina URL na upstream (`buildUrl()`)
- Ƙara headers na musamman ga mai samarwa (`buildHeaders()`)
- Sauya jikin buƙatar (`transformRequest()`)
- Aika buƙatar HTTP tare da sake gwadawa + exponential backoff
- Gudanar da sabunta auth idan ana buƙata (masu samarwa na OAuth)

Dukkan masu aiwatarwa suna faɗaɗa `BaseExecutor` (`executors/base.ts`, layukan lamba 1170), wanda ke samar da:

- Dabarar sake gwadawa ta gama-gari
- Haɗin proxy
- Haɗin circuit breaker
- Hooks na rikodin amfani

### Mataki na 4: Watsawa (utils/stream.ts)

Don amsoshin da ake watsawa, mai aiwatarwar yana dawo da **ReadableStream**. Mai sarrafa buƙatar yana:

- Tura bayanai ta hanyar sauyin SSE (`createSSETransformStreamWithLogger`)
- Aiwatar da saƙonnin heartbeat don gano haɗin da ya mutu
- Gudanar da yankewar haɗin abokin ciniki cikin tsari (`pipeWithDisconnect`)
- Sauya SSE → JSON ga abokan ciniki marasa amfani da watsawa

Don amsoshin da ba a watsa su ba, mai aiwatarwar yana dawo da parsed JSON object wanda ake miƙawa ba tare da canji ba.

### Mataki na 5: Rikodi (services/usage.ts)

Bayan amsa (nasara ko gazawa), ana adana bayanan amfani:

- `prompt_tokens`, `completion_tokens`, `cached_tokens` daga amsar
- `cost_usd` da aka ƙididdige daga bayanan farashi
- `latency_ms`, `status`, `error_class` idan an gaza
- Ana adanawa a teburin `usage_history`

Ana rubuta fayilolin rajistar kira (idan an kunna su) zuwa `${DATA_DIR}/call_logs/`.

## Key Files Deep-Dive

### chatCore.ts (5977 Lines)

The** babban mai kula da buƙatun** . Duk da girmansa, yana da tsayayyen tsari:

```ts
// Pseudo-structure of chatCore.ts
export async function handleChat(request: NextRequest) {
  // 1. Auth + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. Body validation
  const body = await parseRequestBody(request);

  // 3. Format detection + translation
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. Combo routing
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // Continue to next target
    }
  }

  // 5. Emergency fallback
  return await emergencyFallback(body);
}
```

Duk da kasancewar babban aiki ɗaya, an tsara shi cikin** sharhi sassan** wannan taswirar zuwa bututun mai mataki 5.

## Masu zartarwa (Modules 150)

Galibi fayil ɗaya kowane mai bayarwa. Azuzuwan masu zartarwa duk sun shimfiɗa `BaseExecutor` kuma sun soke abin da ya bambanta; sauran nau'ikan su ne mataimakan masu ba da kyauta (tsarin tsara kayan aiki, adaftar fetch/TTS, masu sarrafa quirk).

### Samfuran gama gari

Ana warware masu samarwa ta hanyar `getExecutor(providerId)`, wanda ke dawo da mai zartarwa da aka saita. masu samar da OpenAI/Anthropic-compatible suna amfani da `DefaultExecutor` (`executors/default.ts`). Halaye na musamman na mai bayarwa (tushe URL, masu rubutun auth, sigar API ) an saita su a cikin `open-sse/config/providers/`, yayin da ake sarrafa canjin jiki a `open-sse/translator/`.

**Custom URL** an saita ta ta hanyar daidaitawar mai bada:

```ts
// Provider config in open-sse/config/providers/
export default {
  id: "together",
  baseURL: "https://api.together.xyz/v1/chat/completions",
}
````

**Takaddun shaida** ana sarrafa ta ta hanyar daidaitawa na rijistar mai bayarwa (maɓallin API, OAuth, bayanan bayanan kai).

**Jikin buƙatar na al'ada** canje-canje (misali, Anthropic keɓance `system` daga `messages`) an yi rajista ga kowane mai bayarwa a cikin `open-sse/translator/`.

````

### The Executor Factory

`executors/index.ts` exports `getExecutor(providerId)`:

```ts
import { getExecutor } from "@omniroute/open-sse/executors";

const executor = getExecutor("anthropic");
const result = await executor.execute({
  model: "claude-sonnet-4-5",
  messages: [...],
});
````

ƙudirin yana tafiya ta cikin `ExecutorRegistry` (`executors/registry.ts`): kowane ƙwararren mai zartarwa ana ayyana shi a cikin ginanniyar tebur na `executors/index.ts` kuma an yi rajista ta `registerExecutor(alias, instance)` a nauyin kaya; `getExecutor()` ya tuntubi wurin yin rajista kuma ya koma zuwa ga abin da aka haddace `DefaultExecutor` ga kowane mai bayarwa ba tare da shigarwa na musamman ba. Cikakken wanda aka fi sani da → mai aiwatar da taswirar yana siffanta gwajin zinare `tests/unit/executor-map-golden.test.ts`.

## Masu Fassara

Fassara tsakanin **tsare-tsare 3**: OpenAI, Anthropic, Gemini, tare da sabon Responses API.

### Lokacin da Fassara ke Faruwa

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
  body = translateRequest(body, sourceFormat, targetFormat);
}
```

Fassarorin da aka fi amfani da su:

- `OpenAI → Anthropic`: keɓantaccen filin `system`, kanun `x-api-key`
- `OpenAI → Gemini`: `contents` maimakon `messages`, `systemInstruction`
- `OpenAI → Responses API`: jerin `input`, yanayin `previous_response_id`

### Abubuwan Musamman da Aka Sarrafa

- Matsayin `developer` → `system` ga waɗanda ba OpenAI ba
- Matsayin `system` → ana haɗa shi cikin saƙon mai amfani na farko don GLM/ERNIE
- `json_schema` → `responseMimeType` + `responseSchema` na Gemini
- `tools` → tsarin kayan aiki na musamman ga mai samarwa
- Sigogin tunani (o1, Claude) → makamantansu na musamman ga mai samarwa

## Sabar MCP

`open-sse/mcp-server/` yana aiwatar da sabar **Model Context Protocol**:

- **kayan aiki 110** (sarrafa masu samarwa, haɗe-haɗe, ma’adanar tunawa, cache, matsewa, proxy, ƙwarewa, mayar da abubuwa wasa, plugins, Notion, Obsidian, ma’ajiyar bayanai ta cikin gida)
- **hanyoyin sufuri 3**: stdio, SSE, Streamable HTTP
- **scopes 33** don cikakken sarrafa izini

### Rijistar Kayan Aiki

Ana rijistar kayan aiki a matsayin fayiloli masu zaman kansu a cikin `open-sse/mcp-server/tools/`, inda kowannensu ke fitar da suna, schema, handler, da scope:

```ts
// open-sse/mcp-server/tools/getHealth.ts
import { z } from "zod";
export default {
  name: "omniroute_get_health",
  description: "Samo taƙaitaccen bayanin lafiyar tsarin",
  scope: "read:health",
  inputSchema: z.object({}),
  handler: async (_args, ctx) => {
    return await getSystemHealth();
  },
};
```

### Hanyoyin Sufuri

```ts
// stdio (amfani da CLI)
startMcpStdio(server);

// SSE (yaɗawa bisa HTTP)
startMcpSse(server, port);

// Streamable HTTP (MCP na zamani)
startMcpStreamable(server, port);
```

### Ba da Izini

Kowane kiran kayan aiki yana bi ta binciken scope (`open-sse/mcp-server/auth/`):

```ts
if (!hasScope(apiKey, "providers:read")) {
  throw new Error("Izinin scope bai isa ba");
}
```

## Masu Sauya Tsari

`open-sse/transformer/` yana sauyawa tsakanin tsare-tsaren **Chat Completions** da **Responses API**.

### Me Ya Sa Ake Buƙatar Wani Mai Sauya Tsari Na Daban?

Responses API shi ne sabon tsarin OpenAI mai **tattaunawa da ake riƙe yanayinta** (`previous_response_id`). Lokacin da abokin hulɗa ya aika buƙatar Responses, OmniRoute:

1. Yana sauya Responses → Chat Completions a ciki
2. Yana aikawa ga mai samarwa (duk wani mai samarwa da ke goyon bayan Chat Completions)
3. Yana mayar da amsar zuwa tsarin Responses
4. Yana yaɗa amsar da aka sauya zuwa ga abokin hulɗa

Mai sauya tsarin (`transformer/responsesTransformer.ts`) yana samar da:

```ts
createResponsesApiTransformStream(): TransformStream
```

Wannan yana sarrafa:

- Abubuwan da suka faru na `response.output_item.added`
- Abubuwan da suka faru na `response.output_text.delta`
- Abin da ya faru na `response.completed`
- Daidaita kiran kayan aiki (`function_call` ↔ `tool_calls`)

## Ƙa'idodin Aiki

Injin bayar da hanya yana da tsauraran iyakokin aiki:

| Aiki                                                    | Manufa | Ma'auni                          |
| ------------------------------------------------------- | ------ | -------------------------------- |
| Warware combo                                           | <10ms  | Ga maƙasudai 50                  |
| Duba iyakar ƙima                                        | <1ms   | Bokitin token na cikin ƙwaƙwalwa |
| Komawa ga dangin model                                  | <5ms   | Ma'anonin dangi da aka cache     |
| Tura buƙata zuwa hanya                                  | <2ms   | Hanya mai yawan amfani           |
| **Babu blocking I/O a hanyar routing mai yawan amfani** | —      | Duk async                        |

## Hanyoyin da Ba Su Dace Ba

❌ **Kiran DB na synchronous a cikin `combo.ts`** — yi lissafi tun da wuri kuma a cache
❌ **Dabarar sake gwadawa a cikin handlers** — yi amfani da `retry()` daga resilience service
❌ **Samun damar config na provider kai tsaye** — yi amfani da getters na `providerRegistry`
❌ **Jerin fallback da aka rubuta kai tsaye** — ayyana a cikin `modelFamilyFallback.ts`
❌ **Sauya state a tsakanin buƙatu masu gudana lokaci guda** — yi amfani da context na kowace buƙata kawai

## Ƙara Sabon Bangare

### Ƙara Sabon Service

1. Ƙirƙiri `open-sse/services/[serviceName].ts` mai takamaiman nauyi
2. Fitar da babban handler function da duk wasu constants
3. Ƙara unit tests a cikin `tests/unit/services/[serviceName].test.mjs`
4. Haɗa shi cikin request pipeline a `handlers/chatCore.ts` (idan yana da alaƙa da routing)
5. Sabunta routing logic a cikin `combo.ts` idan service ɗin yana shafar zaɓin target
6. Yi bayani a cikin wannan fayil

### Ƙara Sabon Executor

1. Ƙirƙiri `open-sse/executors/[provider].ts` wanda ke faɗaɗa `BaseExecutor`
2. Yi rajista a cikin `config/providerRegistry.ts`
3. Ƙara shi zuwa factory na `executors/index.ts`
4. Ƙara unit tests don executor
5. Yi bayani a cikin `docs/architecture/ARCHITECTURE.md`

### Ƙara Sabon MCP Tool

1. Ƙirƙiri ko sabunta `open-sse/mcp-server/tools/[category]Tools.ts`
2. Ayyana Zod schema don inputs
3. Yi rajistar tool a cikin `mcp-server/index.ts`
4. Ƙara shi zuwa scope matrix a cikin `mcp-server/auth/`
5. Ƙara unit tests
