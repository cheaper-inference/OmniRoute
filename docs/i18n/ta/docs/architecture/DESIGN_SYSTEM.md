## 1. எது எங்கே உள்ளது

- **கிட்.** `packages/ui-kit/src` என்பது, `packages/ui-kit/UPSTREAM.md`-இல் பின் செய்யப்பட்ட கமிட்டில் உள்ள அப்ஸ்ட்ரீம் `src/`-இன் பைட்டுக்குப் பைட் நகல் (அந்த கோப்பு உரிம அங்கீகாரத்தையும் பதிவு செய்கிறது); `PATCHES.md` உள்ளூர் பேட்ச்களைப் பட்டியலிடுகிறது (எதுவும் இல்லை). இது பில்ட் இல்லாமல் சோர்சாகவே பயன்படுத்தப்படுகிறது: `next.config.mjs` அதை டிரான்ஸ்பைல் செய்கிறது, `tsconfig.json` `@omniroute/ui-kit` → `packages/ui-kit/src` எனவும் `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` எனவும் மேப் செய்கிறது (`vitest.config.ts` மற்றும் `vitest.mcp.config.ts` அதே ஏலியஸைக் கொண்டுள்ளன). ஒரு கிட் காம்போனென்ட்டை அதன் சப்பாத் மூலம் இம்போர்ட் செய்யுங்கள் (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), `@omniroute/ui-kit` பேரல் வழியாக ஒருபோதும் இம்போர்ட் செய்ய வேண்டாம்: பேரல் ஒவ்வொரு காம்போனென்ட்டையும் (டேட் பிக்கர் உட்பட) ஒவ்வொரு இம்போர்ட்டருக்குள்ளும் இழுத்துவிடும். கிட் ஸ்டைல்ஷீட் `src/app/globals.css` வழியாக நுழைகிறது (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **டோக்கன்கள்.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` டோக்கன்களை அறிவிக்கிறது; `src/app/globals.css` அவற்றை பழைய OmniRoute பெயர்களுடன் (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) பிரிட்ஜ் செய்கிறது, ஆகவே தற்போதுள்ள `var(--color-*)` வாசிப்புகளும் Tailwind யூட்டிலிட்டிகளும் தொடர்ந்து செயல்படும். புதிய கோடு Tailwind யூட்டிலிட்டிகளை (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) அல்லது கிட் கிளாஸ்களைப் பயன்படுத்துகிறது — ஒருபோதும் ஹெக்ஸ் மதிப்பை அல்ல (`tests/unit/design-kit-bridge.test.ts` இந்த பிரிட்ஜை உறுதி செய்கிறது). `text-primary` என்பது `--text-color-primary` வழியாக `--color-primary-ink`-ஐத் தீர்க்கிறது (லைட்டில் lime-800, டார்க்கில் lime ஆக்சென்ட்), ஆகவே `bg-primary`/`border-primary` lime சர்ஃபேஸைத் தக்கவைத்திருக்கும்போதும் பிரைமரி டெக்ஸ்ட் படிக்கக்கூடியதாக இருக்கிறது. சார்ட் சீரிஸ்கள் `--color-chart-1` … `--color-chart-5`-ஐப் பயன்படுத்துகின்றன.
- **தீம்கள்.** `<html className="ci-theme">` (`src/app/layout.tsx`) டாகுமென்ட்டை கிட் தீமில் சேர்க்கிறது. விருப்பம் `light`, `dark` அல்லது `system` (`src/shared/constants/appConfig.ts`-இல் `THEME_CONFIG.defaultTheme = "system"`; `system` என்பது `prefers-color-scheme`-ஐப் பின்பற்றுகிறது). `src/store/themeStore.ts`-இல் உள்ள `applyTheme()` (ஹைட்ரேஷனுக்கு முன் இயங்கும், `src/app/layout.tsx`-இல் உள்ள இன்லைன் பூட்ஸ்டிராப் ஸ்கிரிப்டால் மிரர் செய்யப்பட்டது) `data-theme="dark"|"light"`-ஐ அமைத்து, `<html>`-இல் `.dark` கிளாஸையும் ஒன்றாக டோகிள் செய்கிறது. கிட்டின் டார்க் டோக்கன் தொகுப்பு `data-theme="dark"`-ஐ அடிப்படையாகக் கொண்டது (`packages/ui-kit/src/ci-tokens.css`); OmniRoute-இன் சொந்த டார்க் ஓவர்ரைடுகள் (`globals.css`-இல் உள்ள `.dark` பிளாக்) மற்றும் பழைய Tailwind `dark:` யூட்டிலிட்டிகள் `.dark` கிளாஸை அடிப்படையாகக் கொண்டவை. ஆக்சென்ட் நிற ப்ரீசெட்டுகள் எதுவும் இல்லை: ஆக்சென்ட் எப்போதும் கிட்டிலிருந்தே வருகிறது, மேலும் பழைய பில்டிலிருந்து நிலைத்திருந்த ப்ரீசெட், ஸ்டோர் ஏற்றப்படும்போது கைவிடப்படுகிறது.
- **காம்போனென்ட்கள் (அடாப்டர்கள்).** `src/shared/components/index.tsx` OmniRoute காம்போனென்ட் API-ஐத் தக்கவைக்கிறது (அதே பெயர்கள், டிஃபால்ட் எக்ஸ்போர்ட்டுகள் மற்றும் ப்ராப்ஸ்), அதற்குப் பின்னால் உள்ள பிரிமிட்டிவ்கள் கிட் மீதான அடாப்டர்கள்: ஃபார்ம்கள் (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), ஓவர்லேக்கள் மற்றும் ஃபீட்பேக் (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`), ஸ்ட்ரக்சர் (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) மற்றும் டேபிள்கள் (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). ஒரு அடாப்டர் கிட் காம்போனென்ட்டை சப்பாத் மூலம் இம்போர்ட் செய்து, பழைய ப்ராப்ஸை அதன் மீது மேப் செய்கிறது — உதாரணமாக `Button variant="primary"` என்பது கிட்டின் `default` பட்டன் (`--ci-button-primary-*`: லைட்டில் இன்வர்ஸ் சர்ஃபேஸ், டார்க்கில் அதன் `--ci-color-accent-foreground` இங்குடன் ஆக்சென்ட்), `danger` என்பது `destructive`, மேலும் `warning` என்பது `outline` மற்றும் `.ci-button--warning` எக்ஸ்டென்ஷன். `globals.css`-இன் இறுதியில் உள்ள `.ci-button--warning` மற்றும் `.ci-badge[data-tone]` ரூல்கள் (`@layer components`) கிட் கிளாஸ்களின் மீதான OmniRoute எக்ஸ்டென்ஷன்கள். `tests/unit/ui/adapters/*.test.tsx` ஒவ்வொரு அடாப்டரையும் பின் செய்கிறது.
- **ஷெல்.** `src/app/(dashboard)/layout.tsx` `DashboardLayout`-ஐ ரெண்டர் செய்கிறது, அது `src/shared/components/layouts/DashboardShell.tsx`-ஐ ரெண்டர் செய்கிறது: கிட் `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), OmniRoute-இன் நேவிகேஷன் லாஜிக் `src/shared/components/Sidebar.tsx`-இல் உள்ளது. `#main-content`-க்கான "skip to content" (உள்ளடக்கத்திற்குச் செல்) இணைப்பு முதல் ஃபோகஸ் செய்யக்கூடிய உறுப்பு. `src/shared/components/Header.tsx` கிட் `SidebarTrigger`-ஐ (ஷெல்லின் ஒரே சைட்பார் டோகிள்), Keak `ProductSwitcher`-ஐ மற்றும் கமாண்ட்-பேலட் ஓப்பனரைக் கொண்டுள்ளது; `#main-content`-க்குள் கிட் `PageHeader` (`.ci-page-header`) மவுண்ட் செய்யப்படாதபோது மட்டுமே அது ரூட் தலைப்பைக் காட்டுகிறது, ஆகவே தனது சொந்த `PageHeader` கொண்ட பேஜில் ஒரே ஒரு `h1` மட்டுமே இருக்கும். `src/shared/components/CommandPalette.tsx` ஒரு கிட் `Dialog`.
- **ஐக்கான்கள்.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) பெயரை (ஸ்கிரீன்கள் பயன்படுத்தும் Material Symbols சொற்களஞ்சியம்) `ICON_MAP` (`src/shared/constants/iconMap.ts`) வழியாக ஒரு Lucide கிளிஃபாகத் தீர்க்கிறது. Material Symbols ஃபான்ட்டும் பேக்கேஜும் நீக்கப்பட்டுவிட்டன: மேப்பில் இல்லாத ஒரு பெயர் நியூட்ரல் ப்ளேஸ்ஹோல்டர் கிளிஃபை (`data-icon-missing="true"`) ரெண்டர் செய்து, ப்ரொடக்ஷனுக்கு வெளியே கன்சோல் எச்சரிக்கையை லாக் செய்கிறது. `npm run gen:icon-map` பயன்பாட்டில் உள்ள, மேப்பில் இல்லாத பெயர்களை அச்சிடுகிறது (Lucide ஐக்கான் இல்லாத எந்தப் பெயரிலும் `tests/unit/icon-map-coverage.test.ts` தோல்வியடையும்; லுக்கப் ஆப்ஜெக்ட்டுகளில் சேமிக்கப்பட்ட பெயர்களை `tests/unit/icon-map-object-values.test.ts` உள்ளடக்குகிறது); `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` லிட்டரல் `<span className="material-symbols-outlined">` ஸ்பேன்களை `<Icon>`-ஆக மீளெழுதுகிறது.
- **பிராண்ட்.** `src/shared/components/OmniRouteLogo.tsx` கிட்டை ரேப் செய்கிறது: டிஃபால்ட் எக்ஸ்போர்ட் `OmniRouteLogo` என்பது `ProductIcon product="omniroute" variant="glyph"`-ஐ ரெண்டர் செய்கிறது (இன்லைன் SVG, `basePath`-பாதுகாப்பானது), `OmniRouteLockup` என்பது `ProductLockup product="omniroute"`-ஐ ரெண்டர் செய்கிறது (அணுகல்திறன் பெயர் "Keak OmniRoute") அல்லது, ஒயிட்-லேபிள் ஆபரேட்டர்களுக்கு, அவர்களது சொந்த `name`/`logoSrc`. ப்ராடக்ட்-ஸ்விட்சர் இலக்குகள் `src/shared/constants/keakProducts.ts`-இல் உள்ளன (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`). தனித்த ஸ்கிரீன்கள் — `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` மற்றும் `src/shared/components/ErrorPageScaffold.tsx` — லாக்கப்பைக் காட்டுகின்றன; `tests/unit/brand-pages-static.test.ts` அதைப் பாதுகாக்கிறது.

## 2. விதிகள்

1. டோக்கன்கள் மட்டுமே, லிட்டரல்கள் அல்ல. வேண்டுமென்றே வைக்கப்பட்ட விதிவிலக்குகள்: எப்போதும் இருண்ட console terminal,
   `STATUS_HEX` (`src/shared/constants/statusColors.ts`) வழியான ReactFlow SVG
   strokes, மற்றும் வகைப்படுத்தப்பட்ட palettes ஆன
   `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) மற்றும்
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`).
2. `packages/ui-kit/src`-ஐ கைமுறையாக patch செய்ய வேண்டாம்: `scripts/dev/sync-ui-kit.sh <commit>` மூலம் ஒத்திசைக்கவும்; pin செய்யப்பட்ட upstream commit-லிருந்து மாறுபடும் எந்த byte-லும்
   pre-commit gate ஆன `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) தோல்வியடையும் (upstream clone ஆனது
   `UI_KIT_CLONE` அல்லது `_references/cheaper-inference-ui-kit` இல்லையென்றால், அது எச்சரிக்கையுடன் தவிர்க்கப்படும்). kit-ல் ஏதேனும் இல்லையென்றால்,
   adapter-ல் அல்லது screen-ல் அதை சமாளித்து, upstream-ஐ அதற்காக கேளுங்கள்.
3. Kit-ன் உரை இயல்புநிலைகள் ஆங்கிலத்தில் உள்ளன (`label = "Loading"`, `loadingLabel = "Loading table"`…) — kit component உரையை வழங்கும் போதெல்லாம்
   `useTranslations(...)`-லிருந்து மொழிபெயர்க்கப்பட்ட strings-ஐ அனுப்பவும்.
4. Tailwind utilities kit component class-களை விட மேலானவை (kit
   `@layer theme, base, components, utilities` என அறிவிக்கிறது, அதன் விதிகள் `components`-ல் உள்ளன) — spacing மற்றும் layout-க்கு utilities-ஐப் பயன்படுத்தவும், kit component-களை மீண்டும் நிறமூட்டுவதற்கு அல்ல.
5. தலைப்புகள்: பக்கம் மற்றும் பிரிவு தலைப்புகளுக்கு `.ci-heading` (Inter, tracking இல்லாமல்); error-page status code போன்ற பெரிய, அரிதான display உரைக்கு மட்டும் `.ci-dashboard-display`
   (Instrument Serif).
6. `tests/unit/dashboard-kit-sweep.test.ts` kit ஏற்றுக்கொள்ளலை காக்கிறது:
   `src/app` அல்லது `src/shared/components`-ன் கீழ் Material ligature span இருக்கக் கூடாது; dashboard tree-ல் (`src/app/(dashboard)` மற்றும்
   `src/shared/components`) raw `<select>`, `<textarea>` அல்லது `<table>` இருக்கக் கூடாது மற்றும் பட்டியலிடப்பட்ட விதிவிலக்குகளுக்கு வெளியே கைமுறையாக உருவாக்கப்பட்ட
   `role="dialog"` இருக்கக் கூடாது (`Select` adapter-ன் native கிளை,
   `RequestLoggerDetail`); அங்குள்ள ஒவ்வொரு raw `<button>` அல்லது `<input>`-க்கும் அதிகபட்சம் 3 வரிகளுக்குள் முடியும் வகையில், அதற்கு மேலே
   `kit-exception:` (காரணத்துடன்) என்ற கருத்து தேவை; palette நிறங்கள் மற்றும் `dark:` variants

7. PR-க்கு முன் இரண்டு theme-களையும் 390 px viewport-ஐயும் சரிபார்க்கவும் (screenshots); `tests/e2e/a11y.spec.ts` axe-ஐ இயக்குகிறது.

## 3. திரை சேர்த்தல்

1. பக்கத்தை kit `PageHeader`-உடன் திறக்கவும் (`@omniroute/ui-kit/page-header`, dashboard-க்குள்
   `compact`) — தலைப்பு, விளக்கம் மற்றும் `actions`. பின்னர் shell header தனது சொந்த தலைப்பை கைவிடும்.
2. Controls-ஐ `@/shared/components`-லிருந்து (adapter-கள்) உருவாக்கவும், adapter இல்லாத இடங்களில் subpath மூலம் kit component-களைப் பயன்படுத்தவும்
   (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`,
   `Slider`…).
3. Icons: `<Icon name="…" />`. புதிய பெயர் `ICON_MAP`-ல் அர்த்தத்திற்கு பொருந்தும் Lucide
   component-உடன் சேரும்; இன்னும் விடுபட்ட பெயர்களை `npm run gen:icon-map` பட்டியலிடும்.
4. நிறங்கள்: semantic utilities (`text-success`, `bg-warning-bg`, `border-border`…) மற்றும்
   chart தொடர்களுக்கு `var(--color-chart-N)`; hex மதிப்புகள் இல்லை, மற்றும் நிறத்தை மட்டும் மீண்டும் செய்யும் `dark:` variants இல்லை.
5. உரை: kit component-களுக்கு அனுப்பும் labels உட்பட ஒவ்வொரு string-ம் `useTranslations`-லிருந்து வரும். புதிய
   key-கள் `src/i18n/messages/en.json`, `pt-BR.json` மற்றும் `vi.json`-ல் சேரும் (Vietnamese parity test
   ஒவ்வொரு ஆங்கில key-ஐயும் pin செய்கிறது); மற்ற locale-கள் i18n sync மூலம் நிரப்பப்படும்.
6. PR-க்கு முன் காவலர்களை இயக்கவும்: `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (`iconMap.ts`-ல் நகல் import-ஐ பிடிக்கும் ஒரே சரிபார்ப்பு),
   `npm run check:ui-icu`, மற்றும் அந்தத் திரையின் சொந்த test-கள்.

## 4. அடாப்டரைச் சேர்த்தல் அல்லது மாற்றுதல்

1. `src/shared/components/index.tsx`-இன் பொது API-ஐ அப்படியே வைத்திருங்கள்: அதே export பெயர்கள், default export-கள் மற்றும்
   ஏற்றுக்கொள்ளப்படும் props. லெகசி props-ஐ அடாப்டருக்குள் kit-க்கு மேப் செய்யுங்கள் (`Button.tsx`-ஐப் பார்க்கவும்: `VARIANT_TO_KIT`,
   `SIZE_TO_KIT`).
2. kit-ஐ subpath மூலம் import செய்யுங்கள் (`@omniroute/ui-kit/<component>`).
3. kit குறைகளுக்கான தற்காலிக தீர்வுகள் அடாப்டரில் இருக்க வேண்டும் (அல்லது தீர்வு ஒரு style ஆக இருந்தால் `globals.css`
   `@layer components`-இல்), ஒருபோதும் `packages/ui-kit/src`-இல் அல்ல.
4. `tests/unit/ui/adapters/<name>.test.tsx`-ஐச் சேர்க்கவும் அல்லது புதுப்பிக்கவும். பல அழைப்பாளர்களைக் கொண்ட அடாப்டருக்கு,
   மாற்றத்திற்கு முன்னும் பின்னும் ரெண்டர் செய்யப்பட்ட markup-ஐ ஒப்பிடுங்கள் — padding அல்லது wrapper மாற்றங்கள் ஒவ்வொரு திரைக்கும் பரவும்.

## 5. Kit-ஐப் புதுப்பித்தல்

`scripts/dev/sync-ui-kit.sh <commit> [clone]` அந்த commit-இல் உள்ள upstream `src/`-ஐ
`packages/ui-kit/src`-க்கு நகலெடுத்து, அனுமதிக்கப்பட்ட ஒரே மாற்றத்தைச் செய்கிறது (இது
relative import-களிலிருந்து `.js` பின்னொட்டை நீக்குகிறது). பின்னர்: `git diff packages/ui-kit`-ஐ மதிப்பாய்வு செய்யுங்கள், இரண்டு theme-களிலும் providers, settings, combos,
usage மற்றும் endpoint-ஐ காட்சி ரீதியாகச் சரிபார்க்கவும், `npm run check:ui-kit-snapshot` மற்றும் `npm run test:vitest:ui`-ஐ இயக்கவும், மேலும்
upstream changelog-உடன் PR-ஐத் திறக்கவும்.
