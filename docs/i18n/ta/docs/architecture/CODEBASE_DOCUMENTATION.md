## 1. தொழில்நுட்ப அடுக்கு

| அம்சம்          | தேர்வு                                                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| வலை கட்டமைப்பு  | **Next.js 16** (App Router, தனித்தியங்கும் வெளியீடு, உலகளாவிய middleware இல்லை)                                               |
| மொழி            | **TypeScript 6.0+** — இலக்கு `ES2022`, `module: esnext`, `moduleResolution: bundler`, `strict: false`                         |
| இயக்கச் சூழல்   | **Node.js** `>=22.22.2 <23` அல்லது `>=24.0.0 <27` (`engines` + `SUPPORTED_NODE_RANGE` மூலம் கட்டாயப்படுத்தப்படுகிறது)         |
| தரவுத்தளம்      | `better-sqlite3` வழியான **SQLite** (singleton, WAL journaling)                                                                |
| டெஸ்க்டாப்      | **Electron 41** + `electron-builder` 26.10 (`electron/` இல் தனியான பணியிடம்)                                                  |
| சோதனைகள்        | **Node இயல்புநிலை சோதனை இயக்கி** (unit/integration), **Vitest** (MCP, autoCombo, cache), **Playwright** (e2e + protocols-e2e) |
| கட்டமைப்பு      | `scripts/build/build-next-isolated.mjs` வழியாக Next.js standalone                                                             |
| Lint/வடிவமைப்பு | ESLint flat config + Prettier (Husky pre-commit வழியாக `lint-staged`)                                                         |
| தொகுதி அமைப்பு  | எல்லா இடங்களிலும் ESM (`"type": "module"`)                                                                                    |
| Dashboard UI    | **Tailwind CSS 4** + உள்ளடக்கப்பட்ட **Keak CI UI Kit** (`packages/ui-kit`), Lucide icons — `DESIGN_SYSTEM.md` ஐப் பார்க்கவும் |
| பணியிடங்கள்     | npm பணியிடங்கள் — `open-sse`, `packages/browser-pool`, `packages/ui-kit`                                                      |

பாதை மாற்றுப்பெயர்கள் (`tsconfig.json`):

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`
- `@omniroute/ui-kit` → `packages/ui-kit/src`, `@omniroute/ui-kit/*` → `packages/ui-kit/src/*`

இயல்புநிலை HTTP port: **`20128`** (API மற்றும் dashboard ஒரே process-ஐப் பகிர்கின்றன). தரவு
அடைவு `DATA_DIR` env var ஆகும்; அதன் இயல்புநிலை `~/.omniroute/`.

### 3.1 `src/app/` — ஆப் ரூட்டர்

ஆப் ரூட்டர் டாஷ்போர்டு UI மற்றும் public/management HTTP API இரண்டையும் வெளிப்படுத்துகிறது. உள்ளது** உலகளாவிய மிடில்வேர் இல்லை** — குறுக்கீடு ஒவ்வொரு வழியிலும் செய்யப்படுகிறது.

`src/app/` இன் கீழ் உயர்மட்ட பிரிவுகள்:

| பாதை                                                                          | நோக்கம்                                                    |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `api/`                                                                        | அனைத்து HTTP API வழிகளும் (கீழே உள்ள பிரிவைப் பார்க்கவும்) |

#### 3.1.2a `src/app/api/services/` — உட்பொதிக்கப்பட்ட சேவைகள் மேலாண்மை

9Router மற்றும் CLIProxyAPI ஐ நிறுவுதல், தொடங்குதல், நிறுத்துதல் மற்றும் கண்காணிப்பதற்கான வழிகள். அனைத்து பாதைகளும் வகைப்படுத்தப்பட்டுள்ளன**LOCAL_ONLY** (லூப்பேக் மட்டும், ஹார்ட் ரூல் #17) ஏனெனில் அவர்கள் `npm install` செயல்படுத்தலாம் மற்றும் குழந்தை செயல்முறைகளை உருவாக்கலாம்.

### 3.3 `src/domain/` — டொமைன் அடுக்கு

டொமைன் சேவைகள் மற்றும் மதிப்பீட்டு ஒப்பந்தங்கள். சில தொகுதிகள் நேரடி கோரிக்கை பாதையால் அழைக்கப்படுகின்றன; மற்றவை தனித்த ஒப்பந்தங்களாகவே இருக்கின்றன. இந்த முழு கோப்பகமும் I/O இல்லாதது அல்லது ஒவ்வொரு தொகுதியையும் மாற்றுவது உற்பத்தி ரூட்டிங் பாதிக்கிறது என்று கருத வேண்டாம்.

## 10. பங்களிப்பது எப்படி

### புதிய provider-ஐச் சேர்த்தல்

1. `src/shared/constants/providers.ts`-இல் பதிவுசெய்யவும் (ஏற்றப்படும்போது Zod மூலம் சரிபார்க்கப்படும்).
2. தனிப்பயன் தர்க்கம் தேவைப்பட்டால் `open-sse/executors/`-இல் executor ஒன்றைச் சேர்க்கவும்
   (`BaseExecutor`-ஐ நீட்டிக்கவும்).
3. அது OpenAI வடிவமைப்பைப் பயன்படுத்தவில்லை என்றால் `open-sse/translator/`-இல் translator ஒன்றைச் சேர்க்கவும்.
4. OAuth அடிப்படையிலானது என்றால், `src/lib/oauth/providers/` மற்றும்
   `src/lib/oauth/services/` ஆகியவற்றின் கீழ் config-ஐச் சேர்க்கவும்.
5. `open-sse/config/providerRegistry.ts`-இல் (அல்லது `open-sse/config/`-இன் கீழுள்ள வடிவமைப்புக்குரிய
   registry-இல்) models-ஐப் பதிவுசெய்யவும்.
6. `tests/unit/`-இன் கீழ் சோதனைகளை எழுதவும்.

### புதிய API route-ஐச் சேர்த்தல்

1. `src/app/api/your-route/route.ts`-ஐ உருவாக்கவும்.
2. இந்த முறையைப் பின்பற்றவும்: CORS → Zod body சரிபார்ப்பு → அங்கீகாரம் → handler-க்கு ஒப்படைத்தல்.
3. புதிய request வடிவம் என்றால்: `src/shared/validation/schemas.ts`-இல் Zod schema-ஐச் சேர்க்கவும்.
4. நிர்வாகத்திற்கு மட்டும் என்றால்: `src/shared/constants/publicApiRoutes.ts`-இல் path-ஐச் சேர்க்கவும்
   (பொது API பரப்பிற்கான denylist).
5. `tests/unit/`-இன் கீழ் சோதனைகளைச் சேர்க்கவும்.
6. `docs/reference/API_REFERENCE.md` மற்றும் `docs/openapi.yaml` ஆகியவற்றைப் புதுப்பிக்கவும்.

### புதிய DB module-ஐச் சேர்த்தல்

1. `src/lib/db/yourModule.ts`-ஐ உருவாக்கி, `./core.ts`-இலிருந்து `getDbInstance()`-ஐ import செய்யவும்.
2. உங்கள் domain-க்கான CRUD செயல்பாடுகளை export செய்யவும்.
3. புதிய tables இருந்தால்: `src/lib/db/migrations/`-இன் கீழ், வரிசையாக எண்ணிடப்பட்ட,
   idempotent மற்றும் transactional migration ஒன்றைச் சேர்க்கவும்.
4. Import செய்பவர்கள் `@/lib/db/yourModule`-இலிருந்து நேரடி imports-ஐப் பயன்படுத்த வேண்டும் (barrel வேண்டாம் — பழைய `localDb.ts` re-export அடுக்கு அகற்றப்பட்டது).
5. `tests/unit/`-இன் கீழ் சோதனைகளைச் சேர்க்கவும்.

### புதிய MCP tool-ஐச் சேர்த்தல்

1. `open-sse/mcp-server/tools/`-இன் கீழ் tool வரையறையைச் சேர்க்கவும் (அல்லது
   `open-sse/mcp-server/schemas/tools.ts`-ஐ நீட்டிக்கவும்).
2. `src/shared/constants/mcpScopes.ts`-இல் பொருத்தமான scope(களை) ஒதுக்கவும்.

## 11. மரபுகள்

- **Code பாணி**: 2-space indent, double quotes, 100 எழுத்து அகலம், semicolons,
  `es5` trailing commas — `lint-staged` வழியாக Prettier இதைச் செயல்படுத்துகிறது.
- **Imports**: வெளிப்புறம் → உட்புறம் (`@/`, `@omniroute/open-sse`) → தொடர்புடையது.
- **பெயரிடல்**: கோப்புகள் `camelCase` அல்லது `kebab-case`, components `PascalCase`,
  constants `UPPER_SNAKE`.
- **ESLint**: `no-eval`, `no-implied-eval`, `no-new-func` = எல்லா இடங்களிலும் `error`;
  `no-explicit-any` = `open-sse/` மற்றும் `tests/`-இல் `warn`, மற்ற இடங்களில் error.
- **TypeScript**: `strict: false` (மரபுவழி நிலைப்பாடு). Modules இடையிலான எல்லைகளில்
  inference-ஐவிட வெளிப்படையான types-ஐ முன்னுரிமைப்படுத்தவும்.
- **Database**: routes அல்லது handlers-இல் ஒருபோதும் raw SQL எழுத வேண்டாம் — எப்போதும்
  `src/lib/db/` modules வழியாகச் செல்லவும். Barrel-import செய்ய வேண்டாம் — குறிப்பிட்ட `src/lib/db/*` modules-ஐ நேரடியாகப் பயன்படுத்தவும்.
- **DB-entity typing (#3512)**: DB table-இன் row வடிவத்தை எழுதும் அல்லது படிக்கும்
  function, அந்த table-இன் columns-ஐ 1:1 முறையில் பிரதிபலிக்கும் பெயரிடப்பட்ட TS interface-ஐ
  ஏற்க/திருப்பியளிக்க வேண்டும்; call site-இல் `any` அல்லது inline anonymous type-ஐப் பயன்படுத்தக் கூடாது. அந்த
  interface-ஐ function-க்கு அருகில் அமைக்கவும் (எ.கா. `src/lib/usage/usageHistory.ts`-இல்
  `saveRequestUsage`-க்கு மேலே `export interface UsageEntry`); வெவ்வேறு writers row-ஐ
  படிப்படியாக நிரப்பும்போது தனிப்பட்ட fields-ஐ optional/nullable ஆக வைத்திருக்கவும்;
  callers-க்கு இடையே வடிவம் மாறுபடும் field-க்கு `any`-ஐவிட `unknown`-ஐ முன்னுரிமைப்படுத்தவும்
  (field-இல் இதை ஆவணப்படுத்தவும்; எ.கா. `UsageEntry.tokens`, raw provider வடிவிலான usage
  மற்றும் normalized வடிவம் இரண்டையும் ஏற்கிறது). இவ்வாறு ஒரு கோப்பின் `any` எண்ணிக்கை பூஜ்ஜியத்தை
  அடைந்ததும், பின்னடைவு ஏற்படாதபடி அதை `check:any-budget:t11` allowlist-இல்
  (`scripts/check/check-t11-any-budget.mjs`, `maxAny: 0`) சேர்க்கவும். இது first-slice
  மரபாகும் — பரந்த "anonymous `any` வேண்டாம்" தூய்மைப்படுத்தல், மீதமுள்ள codebase முழுவதும்
  படிப்படியாக மேற்கொள்ளப்படுகிறது.
- **பிழைகள்**: குறிப்பிட்ட error types உடன் try/catch-ஐப் பயன்படுத்தி, pino context உடன் பதிவு செய்யவும். SSE streams-இல்
  பிழைகளை ஒருபோதும் அமைதியாகப் புறக்கணிக்க வேண்டாம்; cleanup-க்கு abort signals-ஐப் பயன்படுத்தவும்.
- **பாதுகாப்பு**: `eval()` / `new Function()` / implied eval-ஐ ஒருபோதும் பயன்படுத்த வேண்டாம். அனைத்து
  inputs-ஐயும் Zod மூலம் சரிபார்க்கவும். சேமிக்கப்பட்ட credentials-ஐ encrypt செய்யவும் (AES-256-GCM).
  `src/shared/constants/upstreamHeaders.ts` denylist-ஐ sanitize/validation
  அடுக்குடன் ஒத்திசைவாக வைத்திருக்கவும்.
- **Commits**: Conventional Commits — `feat(scope): subject`. அனுமதிக்கப்பட்ட scopes:
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`.
- **Branches**: prefixes `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`. `main`-க்கு ஒருபோதும் நேரடியாக commit செய்ய வேண்டாம்.
- **Husky**: pre-commit, `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11` ஆகியவற்றை இயக்கும்; pre-push, `check:any-budget:t11` + `check:tracked-artifacts` ஆகியவற்றை இயக்கும் (வேகமான gates; `test:unit` விலக்கப்பட்டுள்ளது).

## 12. கடுமையான விதிகள் (CLAUDE.md இலிருந்து)

1. ரகசியங்கள் அல்லது நற்சான்றுகளை ஒருபோதும் commit செய்ய வேண்டாம்.
2. barrel-import-ஐ ஒருபோதும் பயன்படுத்த வேண்டாம் — குறிப்பிட்ட `src/lib/db/*` தொகுதிகளை நேரடியாகப் பயன்படுத்தவும்.
3. `eval()` / `new Function()` / மறைமுக eval-ஐ ஒருபோதும் பயன்படுத்த வேண்டாம்.
4. `main`-க்கு ஒருபோதும் நேரடியாக commit செய்ய வேண்டாம்.
5. routes-இல் நேரடி SQL-ஐ ஒருபோதும் எழுத வேண்டாம் — எப்போதும் `src/lib/db/` தொகுதிகள் வழியாகச் செல்லவும்.
6. SSE streams-இல் பிழைகளை எந்த அறிவிப்புமின்றி ஒருபோதும் புறக்கணிக்க வேண்டாம்.
7. உள்ளீடுகளை எப்போதும் Zod schemas மூலம் சரிபார்க்கவும்.
8. production code-ஐ மாற்றும்போது எப்போதும் சோதனைகளைச் சேர்க்கவும்.
9. coverage ≥ 60% ஆகத் தொடர்ந்து இருக்க வேண்டும் (statements, lines, functions, branches).
