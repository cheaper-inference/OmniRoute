`devin-cli-agentic`, உண்மையான Claude Code இயக்கநேரத்தை OmniRoute-இன் உள்ளூர் Anthropic
Messages முனைப்புள்ளியைப் பயன்படுத்த அனுமதிக்கிறது; அதே நேரத்தில் அதிகாரப்பூர்வ Devin CLI, ACP stdio வழியாக மாதிரி பதில்களை வழங்குகிறது. இது
ஏற்கெனவே உள்ள Anthropic, Claude OAuth, Claude Web அல்லது `devin-cli` வழங்குநர்களை மாற்றாது.

கிளையன்ட் கட்டுப்பாட்டிலுள்ள கருவி அழைப்புகளுக்கு, Claude வடிவிலான கருவி ஆதரவு வழங்குநரான
`devin-cli-agentic` (மாற்றுப்பெயர் `dva`) வழியாக வழிச்செலுத்தவும். மரபுவழி `devin-cli` (`dv`) ACP செயலாக்கி
உரை மட்டும் ஆதரிக்கிறது: அது Devin-இன் கருவிகள் இல்லாத சுருக்கியை இயக்குவதால் கருவி அழைப்புகளைத் திருப்பித் தர முடியாது. அதன் மாதிரி
மெட்டாதரவு அதற்கேற்ப குறிக்கப்பட்டுள்ளது; எனவே கருவிகள் தேவைப்படும் சேர்க்கை வழிச்செலுத்தல் அதைத் தவிர்க்கும்.

> **தற்போதைய நிலை: Claude Code `2.1.258`-க்கு நிலைநிறுத்தப்பட்டுள்ளது; ஆஃப்லைன் மற்றும் நேரடி சரிபார்ப்பு கடைசியாக
> `2.1.220`-இல் பதிவுசெய்யப்பட்டது.** `2.1.220` நிலைநிறுத்தம், Devin CLI
> `3000.2.17` மற்றும் `swe-1-7-lightning` மாதிரி வழியாக மூன்று தனிமைப்படுத்தப்பட்ட சூழ்நிலைகளை நிறைவுசெய்தது; அந்த இறுதி நேரடி இயக்கம் கிளையன்ட் கட்டுப்பாட்டிலுள்ள `Read`,
> `Edit` மற்றும் `Bash` சுற்றுகள், வெற்றிகரமான `npm test` முடிவுகள், திட்டக் கட்டளை மற்றும் திறன்
> கண்டறிதல், Devin-க்கு மட்டும் உரிய வழிச்செலுத்தல் மற்றும் Claude-க்கு வெளிச்செல்லும் போக்குவரத்து ஏதுமில்லை என்பதை நிரூபித்தது. பின்னர் நிலைநிறுத்தம் `2.1.258`-க்கு உயர்த்தப்பட்டது
> (இது OmniRoute-இன் Claude அடையாளம் ஆள்மாறாட்டம் செய்யும் CLI தலைமுறை மற்றும்
> Fable 5.1 அடுக்கை இயல்பாகவே வழங்கும் முதல் வெளியீட்டு வரிசை). புதிய நிலைநிறுத்தத்தில், நிலைநிறுத்தப்பட்ட அடிப்படை படிமத்தில் நிறுவல் அடுக்கு மற்றும் `claude --version`
> சரிபார்க்கப்பட்டன; மேலும் பிரிட்ஜ் அலகுச் சோதனைத் தொகுப்பு, `compose config` மற்றும்
> நிலையான தனிமைப்படுத்தல் நிரூபணம் வெற்றிபெறுகின்றன — ஆனால் ஆஃப்லைன் மாதிரிச் சூழ்நிலையும் நேரடி மூன்று-சூழ்நிலை
> தொகுப்பும் இன்னும் மீண்டும் இயக்கப்படவில்லை. இந்த நிலைநிறுத்தத்துடன் பிரிட்ஜை நம்பிப் பயன்படுத்துவதற்கு முன் அவற்றை மீண்டும் இயக்கவும்
> ("நிலைநிறுத்தப்பட்ட கருவிகளைப் புதுப்பித்தல்" என்பதைப் பார்க்கவும்).

## கட்டமைப்பு

```text
Claude Code 2.1.258 (தனிமைப்படுத்தப்பட்ட root அல்லாத Linux கொள்கலன்)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude வடிவம், அங்கீகாரம் தேவையற்ற வழங்குநர்)
  -> devin acp --agent-type summarizer (அதிகாரப்பூர்வ ACP stdio, Devin கருவிகள் இல்லை)
  -> பிரத்யேக devin-auth தொகுதியில் உள்ள Devin கணக்கு
```

அதிகாரப்பூர்வ CLI-இன் இயல்புநிலை ACP முகவர் அதன் சொந்தக் கருவிகளை இயக்க முடியும்; எனவே இந்தப் பிரிட்ஜ்
அதைப் பயன்படுத்துவதில்லை. இது கருவிகள் இல்லாத அதிகாரப்பூர்வ CLI பயன்முறையைக் கொண்ட நிலையான `summarizer` ACP முகவரைத் தொடங்கி,
தொடராக்கப்பட்ட Anthropic கோரிக்கையை ஒரு செயலாக்கத் தடமாகக் கட்டமைக்கிறது. Claude கட்டுப்பாட்டிலுள்ள மற்றொரு
செயல் தேவைப்படும்போது, பதிலில் சரியாக ஒரு கிளையன்ட் கருவி உறை இருக்க வேண்டும். ஒரு பதிலை
வெற்றிகரமானதாக அறிவிப்பதற்கு முன், எந்த ACP `tool_call` அல்லது `tool_call_update`-உம் நிராகரிக்கப்படும்.

`open-sse/executors/devin-agentic/serializer.ts`-இல் உள்ள தொடராக்கி, `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` மற்றும்
Claude Code வழங்கும் கருவிகளைப் பாதுகாக்கிறது. படங்கள் மற்றும் அறியப்படாத தொகுதிகள் வெளிப்படையாகத் தோல்வியடையும். பெரிய கருவி முடிவுகள்
காணக்கூடிய துண்டிப்பு அடையாளத்தைப் பயன்படுத்துகின்றன.

ஒவ்வொரு மாதிரிச் சுற்றிலும் தனித்துள்ள ஒரு `<tool>{...}</tool>` உறையைப் பாகுபடுத்தி ஏற்கிறது. அது
கோரிக்கையின் கருவிப் பட்டியலுடன் பெயரைச் சரிபார்க்கிறது, அந்தக் கருவியின் JSON
Schema-க்கு எதிராக மதிப்புருக்களைச் சரிபார்க்கிறது, விவரிப்பும் செயல்களும் கலந்த பதில்களை நிராகரிக்கிறது மற்றும் வரம்புக்குட்பட்ட ஒரு திருத்தத்தை அனுமதிக்கிறது. பின்னர் Claude Code
விளைவான Anthropic `tool_use`-ஐ உள்ளூரில் இயக்கி, `tool_result`-ஐ OmniRoute வழியாகத் திருப்பி
அனுப்புகிறது.

## தானியங்கி வழிச்செலுத்தல்

தடுக்கப்படாதபோது, இந்த வழங்குநர் OmniRoute-இன் `auto/*` வேட்பாளர் தொகுப்புகளில் தகுதிபெறும்.
வேட்பாளர் தகுதி தேர்வை உறுதிசெய்யாது: சேர்க்கையின் வழிச்செலுத்தல் உத்தி (எடுத்துக்காட்டாக,
கடைசியாக வெற்றிபெற்றது) வேறொரு வழங்குநரை விரும்பக்கூடும். ஒவ்வொரு கோரிக்கையும் Devin வழியாகச் செல்ல வேண்டும் எனில்,
`dva/<model>` அல்லது Devin-க்கு முன்னுரிமை அளிக்கும் சேர்க்கையைப் பயன்படுத்தவும்.

## தனிமைப்படுத்தல் மற்றும் அச்சுறுத்தல் மாதிரி

ஹோஸ்டின் Claude நிறுவல், கணக்கு மற்றும் உள்ளமைவு ஆகியவை வரம்பிற்கு அப்பாற்பட்டவையாகவும்
தடைசெய்யப்பட்டவையாகவும் கருதப்படுகின்றன. Compose சேவைகள்:

- UID/GID `10001:10001` ஆக, வாசிப்பதற்கு மட்டும் அனுமதிக்கப்பட்ட ரூட் கோப்பு முறைமை, நீக்கப்பட்ட திறன்கள் மற்றும்
  `no-new-privileges` உடன் இயங்குகின்றன;
- தனிப்பட்ட `/home/bridge`, பிரத்யேக Claude உள்ளமைவு வால்யூம், தனிமைப்படுத்தப்பட்ட OmniRoute தரவு
  மற்றும் தனியான `devin-auth` வால்யூமைப் பயன்படுத்துகின்றன;
- தற்காலிகமான `.sandbox` பணியிடங்கள்/சான்றுகளை மட்டுமே மவுண்ட் செய்கின்றன;
- ஹோஸ்ட் ஹோம், Keychain, SSH, கிளவுட் நற்சான்றுகள் அல்லது Docker சாக்கெட்டை மவுண்ட் செய்வதில்லை;
- வெளிப்படையான சூழல்களை உருவாக்கி, Anthropic API/OAuth/ரூட்டிங் மாறிகளை அகற்றுகின்றன;
- Claude Code அனுமானத்தை உள்ளூர் விசையுடன் `http://omniroute:20128` என்பதற்கு மட்டுமே வழிநடத்துகின்றன.

ஆஃப்லைன் சுயவிவரம் ஓர் உள் நெட்வொர்க்கைப் பயன்படுத்துகிறது. நேரடி சுயவிவரத்தில், OmniRoute அதிகாரப்பூர்வ
Devin முனைப்புள்ளிகளை `network-guard` வழியாக மட்டுமே அணுகுகிறது; தொடர்பில்லாத இலக்குகள் மறுக்கப்படுகின்றன.
Claude Code-க்கு தனியான அனைத்து வெளிச்செல்லும் போக்குவரத்தையும் மறுக்கும் காவல் உள்ளது; மேலும் அது `NO_PROXY`
வழியாக உள்ளூர் OmniRoute சேவையை மட்டுமே அணுக முடியும். காவல் தணிக்கைக் கோப்புகள் அவற்றிற்குரிய காவல் செயல்முறையால்
மட்டுமே மவுண்ட் செய்யப்படுகின்றன. டோக்கன் இல்லாத சான்றுகளை ஏற்றுமதி செய்வதற்கு முன், ஸ்கிரிப்ட்கள் கோப்பின் உரிமை,
பயன்முறை, இணைப்பு எண்ணிக்கை மற்றும் ஒவ்வொரு முடிவையும் சரிபார்க்கின்றன.

தனிமைப்படுத்தல் நிரூபணத்தைத் தனித்தனியாக இயக்கவும்:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

இது இடவியல், பெயரிடப்பட்ட மவுண்ட்கள், ரூட் அல்லாத/வாசிப்பதற்கு மட்டும் அனுமதிக்கப்பட்ட அமைப்புகள், வெளிப்படையான உள்ளூர் ரூட்டிங்,
உணர்திறன் மிக்க சூழல் மாறிகள் இல்லாமை, Docker சாக்கெட் இல்லாமை, `api.anthropic.com` மற்றும் `claude.ai`
ஆகியவற்றிற்கான அணுகல் தடுக்கப்பட்டிருப்பது, Devin-மட்டும் வழங்குநர் தேர்வு மற்றும் ACP பின்தளம் கிடைக்காதபோது
வெளிப்படையான தோல்வி ஆகியவற்றைச் சரிபார்க்கிறது.

## முதல்முறை அமைப்பும் இயல்பான பயன்பாடும்

நிலைப்படுத்தப்பட்ட இமேஜை உருவாக்கவும்:

```bash
./scripts/devin-bridge/build
```

தனிமைப்படுத்தப்பட்ட Devin வால்யூமை மட்டும் அங்கீகரிக்கவும்:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

உள்நுழைவு கட்டளை, தொலைநிலை/கன்டெய்னர் சூழல்களுக்காக வடிவமைக்கப்பட்ட அதிகாரப்பூர்வ கைமுறை-டோக்கன்
செயல்முறையைப் பயன்படுத்துகிறது. மதிப்பு நேரடியாக CLI உள்ளீட்டில் இடப்படுகிறது; அது செயல்முறை வாதமாக
அனுப்பப்படுவதோ, Git-இல் எழுதப்படுவதோ அல்லது ஹோஸ்டிலிருந்து நகலெடுக்கப்படுவதோ இல்லை.

தனிமைப்படுத்தப்பட்ட Claude Code இயக்கநேரத்தைத் தொடங்கவும்:

```bash
./scripts/devin-bridge/launch
```

கன்டெய்னராக்கப்பட்ட Claude Code-ஐத் தொடங்குவதற்கு முன், `launch` தனிமைப்படுத்தல், Devin அங்கீகாரம்
மற்றும் மாதிரிக் கண்டறிதல் ஆகியவற்றை மீண்டும் சரிபார்க்கிறது. இது ஹோஸ்டின் Claude இயக்கக்கூடிய கோப்பை ஒருபோதும்
இயக்காது. மாதிரி மாற்றுப்பெயர்களை `.env.devin-bridge`-இல் அமைக்கலாம்; உள்ளமைக்கப்பட்ட ஒவ்வொரு மதிப்பும்
`devin-cli-agentic/` முன்னொட்டைக் கொண்டிருக்க வேண்டும்.

## சரிபார்ப்புக் கட்டளைகள்

மீண்டும் உருவாக்கக்கூடிய ஆஃப்லைன் பாதைக்கு Devin கணக்கு தேவையில்லை; மேலும் அதற்கு இயக்கநேர இணைய அணுகலும் இல்லை:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

அங்கீகரிக்கப்பட்ட, விருப்பத்தேர்வு அடிப்படையிலான நேரடிப் பாதை:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ACP அமர்வுகளை ஒரே நேரத்தில் அதிக எண்ணிக்கையில் திறப்பதைத் தவிர்க்க, நேரடி இயக்கி நிகழ்வுகளுக்கு இடையில் காத்திருந்து,
உரை வடிவ உரிமைகோரல்களை நம்புவதற்குப் பதிலாக கட்டமைக்கப்பட்ட Claude ஸ்ட்ரீம் நிகழ்வுகளைச் சரிபார்க்கிறது. அதன் மூன்று
நிகழ்வுகள் பின்வருவனவற்றை நிரூபிக்கின்றன:

1. நேரடி திட்ட வாசிப்புகளும் குறைபாடு பகுப்பாய்வும்;
2. உண்மையான `Edit`, கிளையன்ட் உரிமையுள்ள `Bash` `npm test` மற்றும் ஒரு இறுதி முடிவு;
3. `/bridge-check` மற்றும் `bridge-proof` கண்டறிதல், திட்ட வாசிப்புகள், கிளையன்ட் உரிமையுள்ள மற்றொரு வெற்றிகரமான
   `npm test` மற்றும் நிலுவைப் பணி எதுவுமின்றி நிறைவு செய்தல்.

இறுதித் தடுப்புச் சோதனை Devin நெட்வொர்க் தணிக்கையையும் சரிபார்த்து, Claude வெளிச்செல்லும் போக்குவரத்துத் தணிக்கை
காலியாகவே இருக்க வேண்டும் எனக் கோருகிறது.

## பின் செய்யப்பட்ட கருவிகளைப் புதுப்பித்தல்

இந்த image, Node, Claude Code மற்றும் Devin CLI ஆகியவற்றை
`docker/devin-bridge/Dockerfile`-இல் பின் செய்கிறது. புதுப்பிக்க:

1. வெளிப்படையாகக் குறிப்பிடப்பட்ட பதிப்புகளை மாற்றவும்;
2. architecture-க்கு உரிய இரு Devin archive checksum-களையும் அதிகாரப்பூர்வ
   artifact-க்கான மதிப்புகளால் மாற்றவும்;
3. மீண்டும் build செய்து, ஒவ்வொரு offline validation command-ஐயும் இயக்கவும்;
4. image-க்குள் உள்ள பதிப்புகளை உறுதிப்படுத்தவும்;
5. அங்கீகரிக்கப்பட்ட மூன்று-scenario live suite-ஐ மீண்டும் இயக்கவும்.

இரு CLI-களில் எதையும் host-இல் global-ஆக நிறுவவோ, checksum சரிபார்ப்பைச்
சரிபார்க்கப்படாத download-ஆல் மாற்றவோ வேண்டாம்.

## கண்டறிதலும் சுத்தப்படுத்தலும்

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  உள்ளூர் routing மற்றும் சுத்திகரிக்கப்பட்ட executor பிழைகளைக் காட்டுகிறது.
- `.sandbox/evidence/mock-acp.jsonl` தீர்மானகரமான mock ACP செயல்களைப் பதிவுசெய்கிறது.
- `.sandbox/evidence/claude-stream.jsonl` உண்மையான Claude Code offline இயக்கத்தைப் பதிவுசெய்கிறது.
- `.sandbox/evidence/live-*.jsonl` சரிபார்க்கப்பட்ட மூன்று live stream-களைப் பதிவுசெய்கிறது.
- `.sandbox/evidence/egress.jsonl` மற்றும் `.sandbox/evidence/claude-egress.jsonl` ஆகியவை guard audit-களின்
  சரிபார்க்கப்பட்ட, token இல்லாத நகல்கள்.

login/config volume-களைப் பாதுகாத்தபடி, சொந்தமான container-களையும் network-களையும் நிறுத்தவும்:

```bash
./scripts/devin-bridge/clean
```

பெயரிடப்பட்ட volume-கள் உட்பட, bridge-க்குச் சொந்தமான முழுச் சூழலையும் அகற்றவும்:

```bash
./scripts/devin-bridge/clean --all
```

## வரம்புகள்

- Devin CLI `3000.2.17`, நடுநிலையான, tools இல்லாத ACP agent-ஐ வழங்காததால், bridge நிலையான no-tools `summarizer` role-ஐச் சார்ந்துள்ளது. சுருக்க வடிவிலான
  இடைநிலை response-களை adapter ஈடுசெய்கிறது; ஆனால் வரம்பிடப்பட்ட ஒரு repair முயற்சி இன்னும் வெளிப்படையாகத் தோல்வியடையக்கூடும்.
- Live ACP call-கள் தற்காலிக `502`/`504` response-களைத் தரக்கூடும். harness, scenario-களுக்கு
  இடையே இடைவெளி விடுகிறது; தொடர்ச்சியான தோல்வி fail-closed நிலையிலேயே இருக்கும், வேறொரு provider-ஐ ஒருபோதும் தேர்ந்தெடுக்காது.
- ஒவ்வொரு Anthropic request-இலிருந்தும் ACP context மறுகட்டமைக்கப்படுகிறது; process/session
  affinity எதுவும் இல்லை.
- ஒவ்வொரு model response-க்கும் ஒரு tool call மட்டுமே ஆதரிக்கப்படுகிறது; இணையான call-கள் நிராகரிக்கப்படுகின்றன.
- image-கள் வெளிப்படையாக ஆதரிக்கப்படவில்லை. Vision, thinking output, effort control-கள் மற்றும் 1M
  context window ஆகியவை விளம்பரப்படுத்தப்படவில்லை.
- SSE செல்லுபடியாகும் Anthropic lifecycle event-களைப் பயன்படுத்துகிறது; ஆனால் வரம்பிடப்பட்ட ACP turn
  சேகரிக்கப்பட்ட பின்னரே அவை வெளியிடப்படுகின்றன; ACP chunk-கள் படிப்படியாக forward செய்யப்படுவதில்லை.
