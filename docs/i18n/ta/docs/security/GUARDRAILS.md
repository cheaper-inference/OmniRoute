> ஹுக்குகள் எந்த ரூட்டுகள் மற்றும் ரெஸ்பான்ஸ் பாதைகளை அடைகின்றன, ஒன்றிணைக்கப்பட்ட டிசேபிள் ஹெடர்கள் (#16412), கட்டாய
> எல்லையாக இன்ஜெக்ஷன் பிளாக் மோட் (#16413), மற்றும் post-call-க்கு முன் ரெஸ்பான்ஸை எது பார்க்கிறது)

Guardrail-கள் OmniRoute-க்கும் அப்ஸ்ட்ரீம் புரொவைடர்களுக்கும் இடையிலான எல்லையில்
பாதுகாப்பு, பாலிசி மற்றும் கண்டென்ட் டிரான்ஸ்ஃபார்மேஷன்களை நடைமுறைப்படுத்துகின்றன. ஒவ்வொரு
guardrail-மும் ரிக்வெஸ்ட் பேலோடுகளை (`preCall`) மற்றும் அப்ஸ்ட்ரீம் ரெஸ்பான்ஸ்களை (`postCall`)
ஆய்வு செய்யலாம் (மற்றும் விரும்பினால் நிராகரிக்கலாம், டிரான்ஸ்ஃபார்ம் செய்யலாம், அல்லது குறிப்பிடலாம்).

இந்த சிஸ்டம் **fail-open**: ஒரு guardrail இயங்கும்போது throw செய்தால், registry
அந்த எர்ரை பதிவு செய்து, ரிக்வெஸ்டை தோல்வியடையச் செய்யாமல் அடுத்த guardrail-லுடன்
தொடரும். பிளாக் செய்வது ஒரு வெளிப்படையான முடிவு (`block: true`), ஒருபோதும் விபத்து அல்ல.
ஒரே விதிவிலக்கு நிறுத்தப்பட்ட (aborted) ரிக்வெஸ்ட்: காலரின் `signal` abort
செய்யப்பட்டால், throw செய்யும் guardrail தவிர்க்கப்படாமல் ஹுக் ரன்னை reject செய்யும்.

இந்த ஹுக்குகள் ஒவ்வொரு ரூட்டிலும் அல்லது ஒவ்வொரு ரெஸ்பான்ஸிலும் இயங்காது.
ஒரு guardrail-ஐ செக்யூரிட்டி கன்ட்ரோலாக நம்புவதற்கு முன்
[கவரேஜ் மற்றும் வரம்புகள்](#coverage-and-limits)-ஐ படியுங்கள்.

### பார்வை பாலம் (`visionBridge.ts`) — மாடலிட்டி பாலம் PR-1

GLM 5.3 அடிப்படை மாதிரி மற்றும் `glm-5.3-{low,high,max}` வெளிப்படையான `supportsVision:false` registry/spec மெட்டாடேட்டாவைக் கொண்டுள்ளன. GLM 5.3 ஃப்ளாஷ் மாறுபாடுகள் நேட்டிவ்-விஷன் மாடல்களாகவே இருக்கின்றன. Claude குறியீட்டின் `/v1/messages` பாதை பகிரப்பட்ட `handleChat` முன் அழைப்பு பாதுகாப்பு சங்கிலியில் நுழைகிறது** முன்** Claude-to-OpenAI மொழிபெயர்ப்பு; உள்ளமைக்கப்பட்ட `Read` கருவி-முடிவு படங்கள் விவரிக்கப்பட வேண்டும் அல்லது அவற்றை மொழிபெயர்ப்பு OpenAI `image_url` உள்ளடக்கத்திற்கு (#17069) உயர்த்தும் முன் கையாள வேண்டும்.

இலக்காகக் கொண்ட படத்தைத் தாங்கும் கோரிக்கைகளை இடைமறிக்கும்** பார்வையற்ற மாதிரிகள்** மற்றும் முழு கோரிக்கையையும் பார்வை திறன் கொண்ட மாதிரிக்கு மாற்றுகிறது அல்லது அப்ஸ்ட்ரீம் அழைப்புக்கு முன் உள்ளமைக்கக்கூடிய பார்வை மாதிரியால் உருவாக்கப்பட்ட உரை விளக்கங்களுடன் பட பகுதிகளை மாற்றுகிறது. இது உரை-மட்டும் வழங்குநர்களை மல்டிமாடல் பேலோடுகளை வெளிப்படையாகக் கையாள அனுமதிக்கிறது.

ஓட்டம்:

1. இலக்கு மாதிரி ஏற்கனவே பார்வையை ஆதரிக்கிறது என்றால் தவிர்க்கவும் (அது கட்டாயம்-பிரிட்ஜ் பட்டியலில் தோன்றும் வரை `isVisionBridgeForcedModel`).
2. `extractImageParts(messages)` (`visionBridgeHelpers.ts`) வழியாக படப் பகுதிகளை பிரித்தெடுக்கவும், இது க்கு பிரதிநிதித்துவம் அளிக்கிறது** ஒருங்கிணைந்த மீடியா டிடெக்டர்** `open-sse/utils/mediaParts.ts` — இல் `detectMediaParts()`, காம்போ இணக்கத்தன்மை வடிகட்டியுடன் பகிரப்பட்ட உண்மையின் ஒற்றை ஆதாரம். பிரித்தெடுத்தல் `replaceImageParts` வடிவங்களுக்குப் பட்டியலிடப்பட்டுள்ளது (சாறு↔ ஒப்பந்தத்தை மாற்றுகிறது): OpenAI `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"`, மற்றும் பதில்கள் API `input_image`. Claude கோட் `tool_result.content` மற்றும் ரெஸ்பான்ஸ் டூல் அவுட்புட்டுகளுக்குள் உள்ள பொருத்தப்பட்ட படங்கள் பிரித்தெடுக்கப்பட்டு அவற்றின் அசல் பாதையில் மாற்றப்படுகின்றன; காட்டி-மட்டும் வடிவங்கள் சேர்க்கை வடிகட்டி பொருள் மற்றும் பிரித்தெடுக்கப்படவில்லை. எதுவும் கிடைக்கவில்லை என்றால் தவிர்க்கவும்.
3. `resolveVisionBridgeRuntimeSettings()` (`src/shared/constants/modalityBridgeDefaults.ts`) வழியாக இயக்க நேர கட்டமைப்பைத் தீர்க்கவும்: புதிய `modalityBridge*` அமைப்புகள் விசைகள் வெற்றி; மரபு `visionBridge*` விசைகள் எஞ்சியுள்ளன** ஒரு சுழற்சி பின்னடைவு** (திரும்பச் சாளரம்). பாலம் முடக்கப்பட்டிருக்கும் போது எந்த மீடியா டிராவஸலுக்கு முன்பும் தவிர்க்கவும்.
4. பயன்முறை தேர்வி (`modalityBridgeVisionMode`, கீழே உள்ள அட்டவணையைப் பார்க்கவும்) மறுமார்க்கத்திற்கு எதிராக விவரிக்கிறது. மாற்றியமைக்கப்பட்ட `model`, மேலும் மெட்டா `{ rerouted, fromModel, toModel, imagesKept }` உடன் `modifiedPayload` திருப்பி அனுப்புகிறது.
5. பாதையை விவரிக்கவும்: `maxImages` இல் படங்களை தொப்பி, பணி-விழிப்புணர்வு வரியில் உருவாக்கவும், விவரிக்கும் தற்காலிக சேமிப்பைப் பார்க்கவும், பார்வை மாதிரியை அழைக்கவும்** இணையாக** (`Promise.allSettled`), மற்றும் `[Image N]: <description>` உரை பகுதிகளை அவற்றின் இடத்தில் செலுத்தவும். ஒரு தோல்வி விவரிப்பு விளைச்சல் `null`: மூலப் படம் unknown/vision-capable இலக்குகளுக்காக (#4012) பாதுகாக்கப்படுகிறது, ஆனால் a** உறுதிப்படுத்தப்பட்ட உரை-மட்டும் நேரடி இலக்கு** அல்லது zero-vision காம்போ ஒவ்வொரு விவரிக்கப்படாத படத்திற்கும் ஒரு வெளிப்படையான `(unavailable — no vision-capable provider connected)` உரை ஸ்டப்பைப் பெறுகிறது, இதில் பகுதி தோல்விகள் மற்றும் விவரிப்பு-அழைப்பு தொப்பிக்கு அப்பாற்பட்ட படங்கள் (#17069) அடங்கும். தற்போதுள்ள அனைத்து-தோல்வி காம்போ விவரிப்பு ஃபால்பேக் இடத்தில் உள்ளது (#8430).
6. `modifiedPayload` + மெட்டாவைத் திரும்பு (`imagesProcessed`, `descriptions`, `processingTimeMs`, `visionModel`).

| `reroute`  |            | வழித்தடத்தை கட்டாயப்படுத்தவும்: வைத்திருக்கும் நற்சான்றிதழ்-மாடல் காவலர் புறக்கணிக்கப்படுகிறது. மறுவழி -** இலக்கு** நற்சான்றிதழ் காவலர் இன்னும் பயன்படுத்தக்கூடிய பார்வை இலக்கு இல்லாதபோது — பயன்படுத்துகிறது, ஒரு உரை மட்டுமே இலக்குக்கு மூலப் படங்களை விவரிப்பது அல்லது அனுப்புவதை விட தெளிவான பிழையுடன் பாலம் தடுக்கிறது. |

கட்டாய முறைகள் ஷார்ட் சர்க்யூட்** முன்** ஆட்டோ ஹூரிஸ்டிக் இயங்குகிறது; `auto` நடத்தை pre-PR-1 guardrail ஐப் போலவே பைட் ஆகும்.

#### API-விசை நோக்கம் (`visionBridgeKeyScope.ts`)

அழைப்பவரின் API விசையானது `allowedConnections`, கோட்டா குளங்கள் (`allowedQuotas`) அல்லது மாதிரிகள் (`allowedModels` / `blockedModels` / `modelAccessMode: "restricted"` / `disableNonPublicModels`) ஆகியவற்றைக் கட்டுப்படுத்தும் போது, பிரிட்ஜ் மாற்று வழியைத் தேர்ந்தெடுத்து, விசை பயன்படுத்தக்கூடிய இணைப்புகளில் பயன்படுத்தக்கூடிய மாதிரிகளை மட்டுமே விவரிக்கிறது. விவரிக்கும் அழைப்பு எப்போதுமே `x-omniroute-self-loop-key-id` தலைப்புடன் OmniRoute சுய-லூப் வழியாகச் செல்லும், எனவே பெறும் அரட்டை கோரிக்கையானது அந்த விசையின் இணைப்பு மற்றும் மாதிரிக் கொள்கையை மீண்டும் செயல்படுத்துகிறது. `enforceApiKeyPolicy()` ஆனது செல்ஃப்-லூப் பேயரருடன் மட்டுமே தலைப்புக்கு மதிப்பளிக்கிறது, எனவே அது அணுகலைக் குறைக்கும், மேலும் தீர்க்கப்படாத ஐடி நிராகரிக்கப்படும்.

விசைக்கு பார்வை மாதிரி அனுமதிக்கப்படாவிட்டால், a** உறுதிப்படுத்தப்பட்ட உரை மட்டுமே இலக்கு** படக் கோரிக்கையை உள்ளூரில் உள்ள ஒரு தெளிவான HTTP 400 உடன் நிராகரிக்கிறது, அதற்குப் பதிலாக பட பைட்டுகளை திறனற்ற அப்ஸ்ட்ரீமுக்கு (#17069) அனுப்புகிறது. தெரியாத அல்லது சொந்த பார்வை திறன் கொண்ட இலக்குகளுக்கு, விவரிக்கும் பாதை அதன் முந்தைய தோல்வி-திறந்த நடத்தையை (மெட்டா `{ skipped: true, reason: "no_permitted_vision_model" }`) தக்க வைத்துக் கொள்கிறது. விசை இல்லாத கோரிக்கைகள் மற்றும் இந்த கட்டுப்பாடுகள் இல்லாத விசைகள் முன்பு போலவே செயல்படும்.

#### Task-aware விவரிக்கும் வரியில் (`modalityBridgeVisionTaskAware`)

இயல்புநிலை** உண்மை** . `composeVisionPrompt()` (`visionBridgeHelpers.ts`) இன் உரையைச் சேர்க்கிறது** கடைசி பயனர் செய்தி** (500 எழுத்துக்களாக துண்டிக்கப்பட்டது) அடிப்படை விவரிக்கும் ப்ராம்ட், பயனர் உண்மையில் என்ன கேட்டார் (கோடெக்ஸ்-விஷன்-ப்ராக்ஸி பேட்டர்ன்) மற்றும் பார்வை மாதிரியை காணக்கூடிய உரையை டிரான்ஸ்கிரிப்ட் செய்யும்படி கேட்கிறது. ஃபிளாக் ஆஃப் — அல்லது பயனர் உரை — இல்லாவிட்டாலும் அடிப்படை வரியில் மாறாமல் பயன்படுத்தப்படுகிறது.

சுய-லூப்பின் சொந்த OpenAI-இணக்கமான கோரிக்கையை விவரிக்கிறது ( `visionBridgeHelpers.ts` இல்`callVisionModelSingle()` ) எப்போதும் `image_url.detail: "high"` — ஐ நிபந்தனையின்றி, ஒவ்வொரு caller/provider க்கும், எந்த கிளையன்ட் சிக்னலிலும் இணைக்கப்படவில்லை. இந்த ப்ராம்ட் கேட்கும் டெக்ஸ்ட்-டிரான்ஸ்கிரிப்ஷன் பணிக்கான OCR துல்லியத்தை குறைந்த-விவர மாதிரியானது குறைக்கிறது, எனவே அசல் உள்வரும் கோரிக்கை எந்த அளவு விவரங்களைப் பயன்படுத்தினாலும் விவரிக்கும் அழைப்பே எப்போதும் அதிக விவரங்களைக் கேட்கும். இது உள் விவரக் கோரிக்கை அமைப்பை மட்டுமே பாதிக்கிறது; முதன்மை கோரிக்கை — இல் OmniRoute அழைப்பவரின் சொந்த `image_url.detail` எவ்வாறு அனுப்புகிறது என்பதை இது மாற்றாது, இயல்புநிலை தனித்தனியாகப் பயன்படுத்தப்படும், மேலும் `defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`) இல் கண்டறியப்பட்ட OpenCode கிளையன்ட்களுக்கு மட்டுமே. விவரிக்கும் சுய-லூப்பின் Anthropic வயர்-வடிவ கிளையில் `detail` புலம் இல்லை மற்றும் இயல்புநிலையால் பாதிக்கப்படாது.

#### வெளியீட்டு தொப்பியை விவரிக்கவும் (`modalityBridgeVisionMaxChars`)

| முக்கிய                        | இயல்புநிலை | வரம்பு               |
| ------------------------------ | ---------- | -------------------- |
| `modalityBridgeVisionMaxChars` | `0`        | `0` அல்லது 100-50000 |

`0` (இயல்புநிலை) என்றால்** தொப்பி இல்லை** — `callVisionModel()` ஆல் வழங்கப்படும் விளக்கம் மாற்றப்படாமல் அனுப்பப்பட்டு, ஏற்கனவே உள்ள நடத்தையைப் பாதுகாக்கிறது. 100–50000 வரம்பில் உள்ள எந்த மதிப்பும் `[Image N]: <description>` ( `src/lib/guardrails/visionBridge.ts` இல்`VisionBridgeGuardrail.preCall()` ) எனப் பிரிப்பதற்கு முன், `…` பின்னொட்டுடன் விளக்கத்தைத் துண்டிக்கிறது. டவுன்ஸ்ட்ரீம் மாடலுக்கு முழு டிரான்ஸ்கிரிப்ஷன் தேவைப்படும் விவரம்-கடுமையான OCR பணிகளுக்கு இதை உயர்த்தவும்; சாட்டி விஷன் மாடல்களில் கட்டுப்பட்ட டோக்கன் பயன்பாட்டிற்கு அதை குறைக்கவும். டாஷ்போர்டு புலமானது விஷன் டேப்பின்`z.union([z.literal(0), z.number().int().min(100).max(50000)])` பேனலில் ( `ModalityBridgeVisionTab.tsx` இல்`modality-bridge-max-chars` ) வாழ்கிறது மற்றும் 100 தளம் வரை `0` முதல் — `0` உள்ள Zod மதிப்பையும் க்ளாம்ப் செய்கிறது.

#### தற்காலிக சேமிப்பை விவரிக்கவும் (`modalityBridge/bridgeCache.ts`)

இன்-மெமரி LRU + TTL கேச் வெளியீடுகளை விவரிக்க, செயல்முறை முழுவதும் பகிரப்பட்டது. முக்கிய = `sha256(imageRef + composedPrompt + configuredBridgeModel)` நீளம்-முன்னொட்டு ஃப்ரேமிங் (புலம்-எல்லை மோதல்கள் இல்லை). மாதிரி கூறு உள்ளது** கட்டமைக்கப்பட்டது** பிரிட்ஜ் மாடல், உண்மையில் — `callVisionModel` பதிலளித்த மாதிரி அல்ல, உள்நாட்டில் பின்வாங்கலாம், மேலும் ஒவ்வொரு முயற்சிக்கும் கீயிங் தற்காலிக சேமிப்பை துண்டாக்கும். தோல்வியுற்ற விவரிப்புகள் ஒருபோதும் தற்காலிகமாக சேமிக்கப்படாது. அமைப்புகள்:

| முக்கிய                         | இயல்புநிலை | வரம்பு  |
| ------------------------------- | ---------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`     | —       |
| `modalityBridgeCacheTtlMinutes` | `60`       | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`      | 10–5000 |

#### ரிமோட் படத்தை இயல்பாக்குதல் (சுய-லூப் describe/base64 பெறுதல்)

பாலம் எடுக்கும் போது ஒரு** தொலைவில்** படமே — Anthropic சுய அழைப்பு மற்றும் claude-wire-format base64 மாற்றத்தை (`ensureBase64ImagesForClaudeWire`) விவரிக்கிறது, `visionBridgeHelpers.ts` — இல் `fetchRemoteImageAsDataUri()` வழியாக URI விளைவான தரவு `normalizeDataUri()` (`open-sse/utils/imageNormalize.ts`) வழியாக பார்வை மாதிரி கோரிக்கையில் உட்பொதிக்கப்படுவதற்கு முன் அனுப்பப்படுகிறது. பெரிதாக்கப்பட்ட படங்கள் a ஆக குறைக்கப்படுகின்றன** 2048px நீண்ட விளிம்பு** (ரிசைஸ் கேப் OpenAI/Anthropic உடன் பொருந்துகிறது, ஏற்கனவே சர்வர்-பக்கம் பொருந்தும்), இது பார்வை மாதிரி என்ன பார்க்கிறது என்பதை மாற்றாமல் பதிவேற்ற bytes/latency குறைக்கிறது. மறுஅளவிடுதல் டைனமிக் இறக்குமதி மூலம் ஏற்றப்படும் `sharp` பயன்படுத்துகிறது: அதன் நேட்டிவ் பைனரி ஏற்றத் தவறினால், `normalizeDataUri()`** ஒருபோதும் வீசுவதில்லை** — ஆனது அசல் பைட்டுகளின் ஒரு வழியாக மீண்டும் விழுகிறது, எனவே describe/base64-conversion பாதை எப்போதும் வேலை செய்து கொண்டே இருக்கும். படம் அல்லாத பைட்டுகள் (டிகோட் செய்யக்கூடிய படத்தை திரும்பப் பெறாத ஒரு பெறுதல்) தீண்டப்படாமல் அனுப்பப்படுகின்றன. இந்த இயல்பாக்கம், பிரிட்ஜ் அதன் சொந்த சுய-அழைப்பு — க்காகப் பெறப்படும் படங்களுக்குப் பயன்படுத்தப்படுகிறது, இது அழைப்பாளரின் ரா பாஸ்த்ரூ பேலோடில் ஒருபோதும் பயன்படுத்தப்படாது, தேர்வு-ஒன்லி பிறழ்வுக் கொள்கையுடன் (ஹார்ட் ரூல் #20) இணங்குகிறது.

#### அமைப்புகள் ஸ்கீமா + இடம்பெயர்வு

புதிய `modalityBridge*` விசைகள் `updateSettingsSchema` (`src/shared/validation/settingsSchemas.ts`) இல் Zod-சரிபார்க்கப்பட்டவை: `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCache*` ட்ரையோ மற்றும் ஆடியோ பிரிட்ஜ் பயன்படுத்தும் `modalityBridgeAudio*` குழு. இடம்பெயர்வு `141_modality_bridge_settings.sql` ஏற்கனவே உள்ள மரபு `visionBridge*` மதிப்புகளை பொருந்தும் புதிய விசைகளுக்கு நகலெடுக்கிறது (ஐடெம்போடென்ட், ஆபரேட்டர்-செட் `modalityBridge*` மதிப்பை மேலெழுதுவதில்லை); ஒரு வெளியீட்டு சுழற்சிக்கான ரீட் ஃபால்பேக்காக மரபு விசைகள் ஏற்றுக்கொள்ளப்படுகின்றன.

#### வெளிப்படைத்தன்மை தலைப்பு + புள்ளிவிவரங்கள்

விவரிக்க-மாற்றப்பட்ட பதில்கள் `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` வைக் கொண்டு செல்கின்றன ( `modalityBridge/bridgeStats.ts` இல் `buildModalityBridgeHeader()` ஆல் கட்டப்பட்டது, `src/sse/handlers/chatHelpers.ts` இல் `withModalityBridgeHeader()` ஆல் முத்திரையிடப்பட்டது). வழிமாற்றப்பட்ட கோரிக்கைகள் கிடைக்கும்** இல்லை** ஹெடர் — பேலோட் தொடப்படவில்லை மற்றும் மாடல் ஸ்வாப் ஏற்கனவே பதில் உடலின் `model` புலத்தில் தெரியும்.

`GET /api/modality-bridge/stats` (மேலாண்மை அங்கீகாரம், `GET /api/settings` இன் அதே அடுக்கு) `vision`, `audio`, மற்றும் `video` க்கான இன்-மெமரி பெர்-மாடலிட்டி கவுண்டர்கள் `{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs, latencySamples, averageLatencyMs, lastUsedAt }` வழங்குகிறது. `averageLatencyMs` `latencySamples` பயன்படுத்துகிறது, எல்லா முயற்சிகளும் அல்ல, அதன் வகுப்பாக; நேரம் இல்லாத ஒரு செயல்பாடு பூஜ்ஜிய-மில்லிசெகண்ட் மாதிரியை உருவாக்காது. வெற்றிகரமான மாற்றங்களுக்கு `bridged` பின்தங்கிய-இணக்கமான மாற்றுப்பெயராக உள்ளது; தோல்வியுற்ற முயற்சிகள் அதை அதிகரிக்காது. வடிவமைப்பின் மூலம் செயல்முறை மறுதொடக்கம் செய்யும்போது கவுண்டர்கள் மீட்டமைக்கப்படுகின்றன (டெலிமெட்ரி, கணக்கியல் அல்ல).

#### டாஷ்போர்டு உள்ளமைவு

The dedicated dashboard page is `/dashboard/settings/modality-bridge`. Its URL-addressable `Vision`, `Audio`, and `Video` tabs preserve query parameters while switching the `tab` value. The Vision tab exposes enablement, mode, model selection (including the automatic default), task-aware prompting, advanced timeout/image/description-length/cache limits, runtime counters, and a guarded sample request. The Audio tab is also live: it exposes enablement, an STT-only model picker with Auto, timeout/max-clip limits, audio counters, and an `input_audio` sample test. The Video tab is functional: it reports the FFmpeg/ffprobe runtime state — one of four explicit UI states (`unknown` while the probe is in flight or could not complete, `restricted` on a non-loopback dashboard host where the probe is skipped client-side, `unavailable` once probed and confirmed missing, or `available` with the FFmpeg/ffprobe versions) — persists enable/model/frame/video/timeout limits, filters the model picker to vision-capable models, and exposes video counters.

AI அமைப்புகளின் கீழ் உள்ள முன்னாள் விஷன் பிரிட்ஜ் கார்டு புதிய பக்கத்திற்கான பொருந்தக்கூடிய இணைப்பாகும்; படிவத்தின் இரண்டாவது நகலை இனி அது வைத்திருக்காது. மீடியா வழங்குநர்கள் இமேஜ்-டு-டெக்ஸ்ட் மற்றும் ஸ்பீச்-டு-டெக்ஸ்ட் பணிப்பாய்வுகளை ஏற்கனவே உள்ள ஸ்பீச்-டு-டெக்ஸ்ட் விளையாட்டு மைதானத்தை அகற்றாமல், தொடர்புடைய மாடலிட்டி பிரிட்ஜ் தாவல்களுடன் இணைக்கின்றனர்.

**சுய-லூப் சேர்க்கை பைபாஸ்:** OmniRoute இன் சொந்த `/v1` சுய-லூப் (தரமற்ற வழங்குநர் மாதிரி) மூலம் அழைப்பு வழிகளை விவரிக்கும் போது, துணை வேண்டுகோள் `x-omniroute-admission-bypass: internal` அனுப்புகிறது மற்றும் தீர்க்கப்பட்ட சுய-லூப் நற்சான்றிதழ் — உடன் உள்ளூர் `sk_omniroute` செண்டினல் உள்ளூர் பயன்முறையில் அல்லது ஆபரேட்டர்-கட்டமைக்கப்பட்ட `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` (#1350) மூலம் அங்கீகரிக்கப்படுகிறது. `REQUIRE_API_KEY=true` இன்னும் விவரிக்கும் அழைப்பை இயக்கலாம். பைபாஸ் சரியான சான்றுகளுக்கு மட்டுமே மதிப்பளிக்கப்படுகிறது, எனவே வெளிப்புற வாடிக்கையாளர்கள் சேர்க்கையைத் தவிர்க்க தலைப்பைப் பயன்படுத்த முடியாது.

மரபு இயல்புநிலைகள் `src/shared/constants/visionBridgeDefaults.ts` இல் வாழ்கின்றன; புதிய mode/task-aware/cache இயல்புநிலைகள் மற்றும் அமைப்புகள் தீர்வு `src/shared/constants/modalityBridgeDefaults.ts` இல் நேரடி. கார்ட்ரெயில் ஒரு `deps` கன்ஸ்ட்ரக்டர் விருப்பத்தை வெளிப்படுத்துகிறது, எனவே சோதனைகள் போலி `getSettings` மற்றும் `callVisionModel` செயலாக்கங்களைச் செலுத்தலாம்.

### ஆடியோ பிரிட்ஜ் (`audioBridge.ts`) — மாடலிட்டி பாலம் PR-3

ஆடியோ உள்ளீட்டை ஏற்கத் தெரியாத இலக்கை அடையும் முன், ஆடியோ தாங்கி அரட்டை கோரிக்கைகளை இடைமறிக்கும். இது அரட்டைக் கோரிக்கையை ஒருபோதும் மாற்றாது: ஏற்கனவே உள்ள OpenAI-இணக்கமான மல்டிபார்ட் எண்ட்பாயிண்ட் மூலம் ஆடியோ பாகங்கள் படியெடுக்கப்படும் மற்றும் தேர்ந்தெடுக்கப்பட்ட அரட்டை மாதிரி உரை டிரான்ஸ்கிரிப்ட்களுடன் தொடர்கிறது.

ஓட்டம்:

1. `supportsAudio` `getResolvedModelCapabilities()` மூலம் தீர்க்கவும். வெளிப்படையான வழங்குநர்-பதிவு மெட்டாடேட்டா வெற்றிகள், பின்னர் நிலையான மாதிரி மெட்டாடேட்டா, பின்னர் ஒத்திசைக்கப்பட்ட `modalities_input`. `audio` இல்லாமல் அறிவிக்கப்பட்ட உள்ளீடு பட்டியல் `false` ஆகும்; `null` எந்த திறன் ஆதாரமும் இல்லை. `false` மற்றும் `null` இரண்டும் பழமைவாத பாலத்தை செயல்படுத்துகிறது, அதே நேரத்தில் `true` அதை கடந்து செல்கிறது.
2. பகிரப்பட்ட `detectMediaParts()` டிடெக்டர் மூலம் `modalityBridgeAudio*` அமைப்புகளைத் தீர்த்து, ஒவ்வொரு செய்தியிலிருந்தும் பிளவுபடுத்தக்கூடிய உயர்மட்ட ஆடியோ பகுதிகளைப் பிரித்தெடுக்கவும். ஆதரிக்கப்படும் கம்பி வடிவங்கள் OpenAI `input_audio`, `audio_url` மற்றும் `source.media_type: "audio/*"` ஆகும். உள்ளமைக்கப்பட்ட ஆடியோ ரூட்டிங்க்காக கண்டறியப்பட்டது ஆனால் ஸ்ப்லைஸ் பாதையால் அகற்றப்படவில்லை. வேலை `modalityBridgeAudioMaxClips` ஆல் மூடப்பட்டுள்ளது; பிந்தைய பகுதிகள் தீண்டப்படாமல் இருக்கும்.
3. கட்டமைக்கப்பட்ட `provider/model` மதிக்கவும் அல்லது நிலையான அட்டவணை வரிசையில் `selectAudioBridgeModel()` `AUDIO_TRANSCRIPTION_PROVIDERS` மற்றும் பயன்படுத்தக்கூடிய செயலில் உள்ள வழங்குநர் நற்சான்றிதழுடன் முதல் மாதிரியைத் தேர்ந்தெடுக்கவும்.
4. `callAudioTranscription()` base64/data-URI ஆடியோவை மல்டிபார்ட் `file` ஆக மாற்றுகிறது அல்லது ரிமோட் `audio_url` DNS பின்னிங் மற்றும் 25 MB பிணைப்புடன் பொது வெளியில் செல்லும் காவலர் மூலம் பதிவிறக்குகிறது. இது `resolveSelfLoopBearer()` உடன் அங்கீகரிக்கப்பட்ட உள்ளூர் `/v1/audio/transcriptions` சுய-லூப்பிற்கு கோப்பு மற்றும் தேர்ந்தெடுக்கப்பட்ட மாதிரியை POSTs. தற்போதுள்ள டிரான்ஸ்கிரிப்ஷன் பாதையானது சாதாரண நற்சான்றிதழ் தேடுதல், cooldown/rate-limit கையாளுதல் மற்றும் வழங்குநர் அனுப்புதல் ஆகியவற்றைச் செய்கிறது.
5. வெற்றிகரமான அழைப்புகள் அவற்றின் பகுதிகளை `[Audio N]: <transcript>` உடன் மாற்றும். `Promise.allSettled` உடன் இயங்கும் அழைப்புகள் : ஒரு தனிப்பட்ட தோல்வி அந்த அசல் ஆடியோ பகுதியை (#4012 ஒப்பந்தம்) பாதுகாக்கிறது. ஒவ்வொரு அழைப்பும் தோல்வியுற்றால் மற்றும் இலக்கு `supportsAudio === false` நிரூபிக்கப்பட்டால், பகுதிகள் `[Audio N]: (unavailable — no STT provider connected)` (#8430 ஒப்பந்தம்) ஆக மாறும். அறியப்படாத இலக்குக்கு (`null`), அனைத்து தோல்வி முடிவும் தொடப்படாமல் இருக்கும். பயன்படுத்தக்கூடிய STT நற்சான்றிதழ் இல்லாத ஒரு நிரூபிக்கப்பட்ட உரை-மட்டும் இலக்கானது பிணைய அழைப்பை வழங்காமல் அதே வெளிப்படையான ஸ்டப்பைப் பெறுகிறது.

வெற்றிகரமான டிரான்ஸ்கிரிப்டுகள் செயல்முறை அளவிலான மாடலிட்டி பிரிட்ஜ் LRU/TTL தற்காலிக சேமிப்பைப் பயன்படுத்துகின்றன. விசையானது ஆடியோ குறிப்பு, நிலையான `audio-transcription` செயல்பாட்டு லேபிள் மற்றும் தேர்ந்தெடுக்கப்பட்ட STT மாதிரி ஆகியவற்றை ஒருங்கிணைக்கிறது; தோல்விகள் எப்போதும் சேமிக்கப்படுவதில்லை. பகிரப்பட்ட `bridged`, `cacheHits`, `failures`, மற்றும் `lastUsedAt` கவுண்டர்களை ஆடியோ முயற்சிகள் புதுப்பிக்கும். மாற்றப்பட்ட பதில்கள் `x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ஐக் கொண்டு செல்கின்றன; தொடப்படாத கோரிக்கைகள் ஆடியோ பிரிட்ஜ் பிரிவைப் பெறாது.

இயக்க நேர அமைப்புகள் DB-ஆதரவு மற்றும் Zod-சரிபார்க்கப்பட்டவை:

| முக்கிய                       | இயல்புநிலை | வரம்பு              |
| ----------------------------- | ---------- | ------------------- |
| `modalityBridgeAudioEnabled`  | `true`     | —                   |
| `modalityBridgeAudioModel`    | `""`       | ஆட்டோ அல்லது STT ID |
| `modalityBridgeAudioTimeout`  | `60000`    | 1000–300000         |
| `modalityBridgeAudioMaxClips` | `3`        | 1–10                |

பகிரப்பட்ட கேச் `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes` மற்றும் `modalityBridgeCacheMaxEntries` ஆல் கட்டுப்படுத்தப்படுகிறது.

### வீடியோ பாலம் (`videoBridge.ts`, `videoBridgePipeline.ts`)

நேட்டிவ் வீடியோ ஆதரவு இல்லாத இலக்கை அழைக்கும் முன், அரட்டை நிறைவுகள் `messages` மற்றும் பதில்கள் API `input` இல் உள்ள உயர்நிலை வீடியோ பகுதிகளை இடைமறிக்கும். ஆதரிக்கப்படும் வடிவங்கள் `input_video`, `video_url`, `video_source`, HTTPS URLs மற்றும் `data:video/*;base64,...` தரவு URIs. உரையில் உள்ள எளிய கோப்பு பெயர்கள் வீடியோவாக கருதப்படுவதில்லை.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) க்கு சொந்தமானது கோரிக்கை டிராவர்சல், capability/policy காசோலை, ஒரு கோரிக்கை ஒருங்கிணைப்பு மற்றும் பதில் பேலோட். ஒரு வீடியோ வேலை — கையகப்படுத்தல், முழு முடிவு கேச், ஒரு பிரேம் வரிசையை விவரிக்கிறது (எந்தவொரு அழைப்பாளரால் அறிவிக்கப்பட்ட ஆடியோ டிரான்ஸ்கிரிப்ட்டையும் இணைக்கிறது), மற்றும் ஒவ்வொரு முயற்சிக்கும் metrics/abort/cleanup — `videoBridgePipeline.ts` இல் `processVideoPart` க்கு பின்னால் மறைக்கப்படுகிறது, `preCall` இன் லூப்பில் உள்ள வீடியோ பகுதிக்கு ஒரு முறை அழைக்கப்படுகிறது. அந்த தொகுதியானது வெளிப்படையான போர்ட் எல்லைகளான `VideoMediaBrokerPort` (பைட்டுகளைப் பெறுதல் மற்றும் மாதிரி பிரேம்களைப் பிரித்தெடுத்தல்), `VideoAudioTranscriptionPort` (அழைப்பாளர் அறிவித்த ஆடியோ டிரான்ஸ்கிரிப்டை மாதிரி தலைப்புகளுடன் இணைத்தல்) மற்றும் `VideoDrilldownPort` (மரபு மூல-கடை வடிவம்) ஆகியவற்றையும் வரையறுக்கிறது. உற்பத்தி STT மற்றும் சட்டத் தக்கவைப்பு ஆகியவை `createVideoSttAdapter` மற்றும் `createVideoDrilldownAdapter` மூலம் விவரிக்கும் போர்ட்டைச் சுற்றி உருவாக்கப்படுகின்றன; பிந்தையது பகிரப்பட்ட ஒளிபுகா-கைப்பிடி வாழ்க்கைச் சுழற்சியைப் பயன்படுத்துகிறது.

பொது `/v1` கோரிக்கை பாதை ஒருபோதும் ஒரு துணை செயல்முறையை இறக்குமதி செய்யாது அல்லது செயல்படுத்தாது. ரிமோட் வீடியோக்கள் 50 MiB எல்லைக்குள் பதிவிறக்கம் செய்யப்படுகின்றன; இன்லைன் பேஸ்64 வீடியோக்கள் கன்சர்வேடிவ் 36 MiB டிகோட் செய்யப்பட்ட ஒரு வீடியோ தொப்பியைக் கொண்டுள்ளன, எனவே model/messages/framing உறை பொது JSON கோரிக்கை அனுமதி வரம்பு 50 MiB க்குள் இருக்கும். இன்லைன் நீளம் மற்றும் டிகோட் செய்யப்பட்ட அளவு மதிப்பீடுகள் ஒதுக்கப்படுவதற்கு முன் சரிபார்க்கப்படும். ஆரம்ப ரிமோட் URL மற்றும் ஒவ்வொரு வழிமாற்றுக்கும் HTTPS தேவைப்படுகிறது, DNS பின்னிங்குடன் இருக்கும் பொது-மட்டும் வெளிச்செல்லும் காவலரைப் பயன்படுத்தி. பைட்டுகள் பின்னர் சரியான உள் `POST /api/modality-bridge/video/extract` தரகர் எல்லையை கடக்கும். அந்த வழி `LOCAL_ONLY` மற்றும் `SPAWN_CAPABLE` ஆகிய இரண்டும் ஆகும், ஒரு செயல்முறைக்கு அங்கீகரிக்கப்பட்ட, நம்பகமான லூப்பேக் கோரிக்கையை மட்டுமே ஏற்கும், மேலும் URL, கோப்பு முறைமை பாதை, இயங்கக்கூடிய அல்லது வாதப் பட்டியலை ஒருபோதும் ஏற்காது. API உடல் அளவு பைப்லைன் மற்றும் கையாளுபவரின் அதிகரிக்கும் உடல் ரீடர் ஆகியவை 50 MiB தரகர் உள்ளீட்டு தொப்பியை சுயாதீனமாக செயல்படுத்துகின்றன. அதன் எல்லைக்குட்பட்ட வரிசை ஒரு நேரத்தில் ஒரு பிரித்தெடுத்தலை இயக்குகிறது, நான்கு நிலுவையிலுள்ள வேலைகளை அனுமதிக்கிறது மற்றும் 100 MiB இல் நிலுவையிலுள்ள உள்ளீடுகளை வழங்குகிறது.

தரகரின் உள்ளே, `ffprobe` ஒரு தனிப்பட்ட உள்ளூர் கோப்பைப் படிக்கிறது; நிலையான வடிவமைப்பு அனுமதிப்பட்டியலில் பிளேலிஸ்ட் மற்றும் மேனிஃபெஸ்ட் வடிவங்கள் இல்லை. அனுமதிக்கப்பட்ட MOV-குடும்ப கொள்கலன்களுக்கு, வெளிப்புற MOV தரவு குறிப்புகள் இயல்பாகவே முடக்கப்பட்டிருக்கும், மேலும் நிலையான கட்டளை அவற்றைத் தேர்வு செய்யாது. `ffprobe` மற்றும் `ffmpeg` இரண்டும் `file` -only நெறிமுறை அனுமதிப்பட்டியல், ஒரு நூல், நிலையான வாத வரிசைகள், ஷெல் இல்லை மற்றும் `PATH` இலிருந்து தீர்க்கப்பட்ட இயங்கக்கூடியவை ஆகியவற்றைப் பயன்படுத்துகின்றன. இணைக்கப்பட்ட பட அட்டை ஸ்ட்ரீம்கள் இயக்கக்கூடிய வேட்பாளர்கள் அல்ல. விளையாடக்கூடிய அனைத்து ஸ்ட்ரீம்களும் வரம்புகளை பூர்த்தி செய்ய வேண்டும், மேலும் உறுதியான குறைந்த-இண்டெக்ஸ் வீழ்ச்சிக்கு முன் வெளிப்படையான இயல்புநிலை ஸ்ட்ரீம் விரும்பப்படுகிறது. வீடியோக்கள் 600 வினாடிகள், ஒரு பரிமாணத்திற்கு 8,192 பிக்சல்கள் மற்றும் 33,554,432 மூல பிக்சல்கள். FFmpeg மாதிரிகள் 1–16 நடுப்புள்ளி JPEG பிரேம்கள், சிறிய உள்ளீடுகளை அதிகரிக்காமல் நீண்ட விளிம்பில் இருந்து அதிகபட்சம் 1,024 பிக்சல்கள் வரை அளவிடுகிறது, மேலும் URL பெறாது. மாதிரியானது முன்னிருப்பாக `uniform` ஆகும். விருப்பமான `scene_aware` மற்றும் சோதனை `segment_aware` கொள்கைகள் ஏற்கனவே சரிபார்க்கப்பட்ட உள்ளூர் ஸ்ட்ரீமில் ஒரு கூடுதல் நிலையான FFmpeg பாஸைச் செயல்படுத்துகின்றன, வரம்புக்குட்பட்ட `showinfo` காட்சி நேர முத்திரைகளைத் தேர்ந்தெடுத்து, கண்டறிதல் தோல்வி, காலக்கெடு, தவறான வெளியீடு அல்லது வெற்று வேட்பாளர் தொகுப்பு ஆகியவற்றில் அதே சீரான நடுப்புள்ளிகளுக்குத் தீர்மானிக்கின்றன. பிரிவு-விழிப்புணர்வு பயன்முறை சரிபார்க்கப்பட்ட காட்சி இடைவெளிகளுக்கு விகிதாசாரமாக நடுப்புள்ளி மாதிரிகளை ஒதுக்குகிறது; பிரிவு-விழிப்புணர்வு சான்றுகள் மற்றும் பின்னடைவு நடத்தை கீழே விவரிக்கப்பட்டுள்ளன. ஒவ்வொரு கொள்கையிலும் தேர்ந்தெடுக்கப்பட்ட பிறகு கடினமான 16-ஃபிரேம் தொப்பி பயன்படுத்தப்படும். ஒரு காட்சி-விழிப்புணர்வு கோரிக்கையானது ஒரு-பிரேம் பட்ஜெட்டை மட்டுமே கொண்டிருக்கும் போது, அது செயலில் உள்ள முழு-வீடியோ அல்லது ஃபோகஸ் விண்டோவின் சீரான நடுப்புள்ளியைப் பயன்படுத்துகிறது மற்றும் `policyEffective: uniform` புகாரளிக்கிறது: ஒரு தேர்ந்தெடுக்கப்பட்ட காட்சிச் சட்டத்தால் இரண்டு தற்காலிக முனைகளையும் பாதுகாக்க முடியாது. ஒரு அழைப்பாளர் விருப்பமாக வரையறுக்கப்பட்ட ஃபோகஸ் சாளரத்தை வழங்கலாம் (`start`/`end` வினாடிகள்); மீடியா காலத்திற்கு எல்லைகள் இணைக்கப்பட்டுள்ளன, தலைகீழ் அல்லது வரையறுக்கப்படாத சாளரங்கள் நிராகரிக்கப்படுகின்றன, மேலும் அனைத்து மாதிரி கொள்கைகளும் இயல்பாக்கப்பட்ட இடைவெளியில் மட்டுமே செய்யப்படுகின்றன. இதன் விளைவாக வரும் சாளரம் மாதிரி மெட்டாடேட்டாவிலும் நம்பத்தகாத விளக்க முன்னொட்டிலும் சேர்க்கப்பட்டுள்ளது, எனவே கீழ்நிலை மாதிரிகள் முழு காலவரிசையிலிருந்து ஒரு மையப்படுத்தப்பட்ட பகுதியை வேறுபடுத்தி அறியலாம்.

சொற்பொருள் தலைப்பு கவனம் என்பது ஒரு தனி, வெளிப்படையான அமைப்பாகும். இயல்புநிலை `full` பகுப்பாய்வு பயன்முறை ஏற்கனவே உள்ள சட்ட வரியில் பாதுகாக்கிறது மற்றும் தலைப்பு மாதிரிக்கு கோரிக்கை உரையை ஒருபோதும் அனுப்பாது. `focused` பயன்முறையில், அதே Chat அல்லது Responses கொள்கலனில் இருந்து சமீபத்திய காலியாக இல்லாத பயனர் எழுதிய `text`/`input_text` ஐ மட்டுமே பிரிட்ஜ் படிக்கிறது, அதை NFC க்கு இயல்பாக்குகிறது, கட்டுப்பாட்டு எழுத்துகள் மற்றும் இடைவெளியைக் குறைக்கிறது, மேலும் அதை 500 யூனிகோட் குறியீடு புள்ளிகளாகக் கட்டுப்படுத்துகிறது. ஒரு வெற்று முடிவு சரியான `full` வரியில் மீண்டும் வரும். பயன்படுத்தக்கூடிய குறிப்பு JSON என வரிசைப்படுத்தப்பட்ட நம்பகமற்ற-பயனர்-சூழல் தொகுதியில் வரிசைப்படுத்தப்படுகிறது மற்றும் கவனிக்கக்கூடிய விவரங்களுக்கு மட்டுமே முன்னுரிமை அளிக்கலாம்; மீடியாவில் தெரியும் அல்லது கேட்கக்கூடிய பின்வரும் வழிமுறைகளுக்கு எதிரான தனி எச்சரிக்கையை இது மீற முடியாது. உரை கவனம் ஒருபோதும் `start`/`end` ஐ ஊகிக்காது அல்லது தற்காலிக மாதிரியை மாற்றாது.

#### FU-07 கட்டமைப்பு பிரிவு சான்றுகள்

`segment_aware` ஏற்கனவே சரிபார்க்கப்பட்ட உள்ளூர் வீடியோ ஸ்ட்ரீமில் ஒரு வரம்பிற்குட்பட்ட முன் பகுப்பாய்வு பாஸைப் பயன்படுத்துகிறது. நிலையான வடிகட்டி சங்கிலி முதலில் அதிகபட்சம் 320 பிக்சல்கள் அகலத்திற்கு அளவிடுகிறது, காட்சி மாற்றங்கள் மற்றும் உறைந்த இடைவெளிகளைக் கண்டறிந்து, பின்னர் தெளிவின்மை, சராசரி லுமா மற்றும் spatial/temporal தகவலுக்காக ஒரு வினாடிக்கு 1 சட்டத்தில் மாதிரிகள். 600 கட்டமைப்பு மாதிரிகள், ஒரு FFmpeg/filter நூல், அதே `file` -only நெறிமுறை மற்றும் கொள்கலன் அனுமதி பட்டியல்கள், 1 MiB செயல்முறை-வெளியீடு வரம்பிற்கு உட்பட்டது, மேலும் தரகரின் பகிரப்பட்ட abort/deadline. க்குள் அதிகபட்சம் 30 வினாடிகள் இது கோரிக்கையிலிருந்து கட்டளை, வடிகட்டி, பாதை அல்லது URL ஆகியவற்றை ஏற்காது.

கட்டமைப்பு மதிப்புகள், தீர்மானகரமான மாதிரி சான்றுகள், சொற்பொருள் வீடியோ புரிதல் அல்ல. அவை பாடங்கள், செயல்கள், தலைப்புகள், பேச்சு அல்லது பயனர் நோக்கத்தை ஊகிக்கவில்லை. காட்சி மற்றும் உறைதல் எல்லைகள் பிரிவுகளை உருவாக்குகின்றன; உறைதல் கவரேஜ், தெளிவின்மை, வெளிப்பாடு, இடஞ்சார்ந்த விவரம் மற்றும் தற்காலிக மாற்றம் ஆகியவை ஏற்கனவே இருக்கும் 1-16 பிரேம் பட்ஜெட் எவ்வாறு ஒதுக்கப்படுகிறது என்பதை மட்டுமே பாதிக்கிறது. ஒரு முழு உறைந்த பிரிவு ஒரு சட்டத்தில் மூடப்பட்டுள்ளது, அதே நேரத்தில் உறைந்திருக்காத பிரிவுகள் மீதமுள்ள பட்ஜெட்டுக்கு போட்டியிடுகின்றன. எல்லைகள் பிரேம்களை விட அதிகமாக இருக்கும்போது, ஒரே மாதிரியான காலவரிசை கவரேஜ் தக்கவைக்கப்படுகிறது, எனவே விரைவான ஆரம்ப வெட்டுக்கள் நீண்ட பின்தங்கிய பகுதியை மறைக்க முடியாது. உறைதல் எல்லையின் 1-வினாடி பகுப்பாய்வுத் தீர்மானத்தில் உள்ள காட்சி எல்லைகள் ஒன்றிணைக்கப்படுகின்றன.

விடுபட்ட வடிப்பான்கள், malformed/empty சான்றுகள், கண்டறிதல் பிழை அல்லது வரம்பிற்குட்பட்ட முன் பகுப்பாய்வு நேரமுடிவு ஆகியவை சரியான சீரான நடுநிலைக் கொள்கையில் தோல்வியடைகின்றன. அழைப்பாளர் நிறுத்தம் அல்லது தரகர் காலக்கெடு திறக்கப்படாது: இது விமானத்தில் உள்ள துணைச் செயல்முறையை நிறுத்துகிறது, பின்னர் சட்டத்தை பிரித்தெடுப்பதைத் தடுக்கிறது, மேலும் தனியார் தற்காலிக மரம் `finally` இல் அகற்றப்படும்.

`scripts/perf/video-bridge-fu07-eval.ts` ஆனது போஸ்ட்-டெடப் கேப்ஷன்-அழைப்பு சேமிப்புகள், அடர்த்தியான-மோஷன் பட்ஜெட் ஒதுக்கீடு, blur/exposure/SI-TI சான்றுகள், நீண்ட வால் கொண்ட விரைவான வெட்டுக்கள் மற்றும் படிப்படியாக மங்கலான தவறான நேர்மறைகளுக்கு உறுதியான உண்மையான FFmpeg சாதனங்களை உருவாக்குகிறது. இது பகுப்பாய்விற்கு முந்தைய சுவர் நேரம் மற்றும் `/usr/bin/time` கிடைக்கும் இடத்தில், குழந்தை CPU மற்றும் உச்ச RSS பதிவு செய்கிறது. அதன் தர சோதனைகள் கட்டமைப்பு ஆரக்கிள்ஸ் மட்டுமே. உண்மையான தலைப்பு-மாடல் தரம் `HOLD` ஆக உள்ளது, ஏனெனில் இந்த சேனலில் அங்கீகரிக்கப்பட்ட இறுதிப்புள்ளி அல்லது உறைந்த நீதிபதி இல்லை. `--caption-cost-per-call-usd` ஒரு அழைப்புக்கு வெளிப்படையான நேர்மறை மதிப்பீட்டை வழங்காத வரையில் பணச் சேமிப்பு `HOLD` ஆக இருக்கும்; ஸ்கிரிப்ட் ஒருபோதும் எந்த முடிவையும் உருவாக்காது.

ஒவ்வொரு சட்டமும் 4 MiB ஆகவும், அனைத்து மூல சட்டங்களும் ஒன்றாக 23 MiB ஆகவும், வரிசைப்படுத்தப்பட்ட தரகர் பதில் 32 MiB ஆகவும் வரையறுக்கப்பட்டுள்ளது. ஒரு தனிப்பட்ட தற்காலிக அடைவு `finally` இல் அகற்றப்பட்டது. ஊக்குவிப்பு சான்றுகள் செயற்கை கலவை மைக்ரோ பெஞ்ச்மார்க்கிலிருந்து வேண்டுமென்றே தனித்தனியாக உள்ளது. உண்மையான OpenAI-இணக்கமான பார்வை மாதிரிகளுக்கான ஸ்கீமா-பதிப்பு செய்யப்பட்ட A/B சேனலை `scripts/perf/video-bridge-contact-sheet-eval.ts` வரையறுக்கிறது. இது வழங்குநர்-அறிக்கையிடப்பட்ட டோக்கன்கள், எண்ட்-டு-எண்ட் சுவர் தாமதம் (தாள் கலவை உட்பட), மாதிரி-அழைப்பு எண்ணிக்கை மற்றும் வெளிப்படையாக வரையறுக்கப்பட்ட உண்மைத் தக்கவைப்பு ஆகியவற்றை அளவிடுகிறது. மூல மாதிரி பதில்கள் அறிக்கைக்கு எழுதப்படவில்லை; SHA-256 digests மற்றும் பொருந்திய உண்மை IDs மட்டுமே தக்கவைக்கப்படுகிறது. `--execute-real` கடந்து, `--model`, `OMNIROUTE_BASE_URL`, மற்றும் `OMNIROUTE_API_KEY` ஆகியவை கட்டமைக்கப்படும் வரை சேணம் நெட்வொர்க் அல்லது கட்டண மாதிரி அழைப்பை மேற்கொள்ளாது. அந்த வெளிப்படையான உண்மையான ஓட்டம் இல்லாமல், அதன் இயந்திரம் படிக்கக்கூடிய தீர்ப்பு `HOLD`; செயற்கை payload/call-count அளவீடுகள் மட்டும் பதவி உயர்வு சான்றுகள் அல்ல.

சேகரிப்பாளர்கள் நினைவகத்தில் பதில்களை ஸ்கோர் செய்ய வேண்டும் மற்றும் `responseDigest` பிளஸ் அளவீடுகள் மற்றும் கண்காணிப்பு பிணைப்புகளை சேமிக்க வேண்டும், ஒருபோதும் உரைக்கு பதிலளிக்க வேண்டாம். நுகர்வோர் மரபு மூலமான அவதானிப்புகளையும் படிக்கிறார், ஆனால் அந்த உரையை அதன் அறிக்கைகளில் நகலெடுப்பதில்லை. ஒவ்வொரு கவனிப்புக்கும் `responseDigest` அல்லது `rawResponseText` இல் சரியாக ஒன்று ஏற்றுக்கொள்ளப்படுகிறது. மாற்ற முடியாத `hold` இயல்புநிலையுடன் பதிப்பு செய்யப்பட்ட அனுமதிப் பட்டியல் காலியாகவே உள்ளது. ஒரு தகுதியான நுழைவுக்கு அதன் ஆதாரக் குறிப்பு, கொள்கை, மாதிரித் திருத்தம், சரியான வேட்பாளர் SHA, மேனிஃபெஸ்ட் டைஜஸ்ட் மற்றும் இரண்டு தனித்துவமான ரன் IDs தேவை; முரண்பட்ட சூழல்கள் நிராகரிக்கப்படுகின்றன. இந்த மெட்டாடேட்டா ஒரு தணிக்கை ஒப்பந்தம், ஒரு குறிப்பிடப்பட்ட கோப்பில் உண்மையான அளவீடுகள் உள்ளன என்பதற்கான ஆதாரம் அல்ல. எந்த உள்ளீட்டையும் சேர்ப்பதற்கு முன் உண்மையான ரசீதுகளை மதிப்பாய்வு செய்யவும். மேலாண்மை புள்ளிவிவரங்கள் இறுதிப்புள்ளி மற்றும் வீடியோ டாஷ்போர்டு பழமைவாத தயார்நிலையை வெளிப்படுத்துகின்றன. ஒரு கட்டமைக்கப்பட்ட மாதிரி மாற்றுப்பெயர் மட்டும் அதன் திருத்தம் அல்லது இயங்கும் வேட்பாளர் SHA நிறுவவில்லை, எனவே தற்போதைய டாஷ்போர்டு மற்றொரு செயல்படுத்தல் சூழலில் இருந்து தகுதியை மீண்டும் பயன்படுத்துவதற்குப் பதிலாக `HOLD` புகாரளிக்கிறது. வெளிப்படையான சோதனைத் தேர்வு, விளம்பரத்திலிருந்து தனித்தனியாக உள்ளது; எந்த இயல்புநிலையும் தானாக மாறாது.

அழைப்பாளர்கள் ஏற்கனவே சீரமைக்கப்பட்ட உரையை வைத்திருந்தால், ஆதரிக்கப்படும் வீடியோ பகுதிக்கு விருப்பமான `transcript.cues` வரிசையை இணைக்கலாம். ஒவ்வொரு குறியும் `text`, ஆய்வு செய்யப்பட்ட காலத்திற்குள் வரையறுக்கப்பட்ட `start`/`end` இடைவெளி மற்றும் அனுமதிப்பட்டியலில் உள்ள `source` (`client`, `embedded`, அல்லது `audio-bridge`) ஆகியவற்றைக் கொண்டு செல்ல வேண்டும்; `confidence` `1` க்கு இயல்புநிலை மற்றும் `0` மற்றும் `1` க்கு இடையில் இருக்க வேண்டும். சரியான நகல் குறிப்புகள் சுருக்கப்பட்டன. OmniRoute இந்த மெட்டாடேட்டாவிலிருந்து டிரான்ஸ்கிரிப்ஷனைத் தொடங்குவதில்லை: சரிபார்க்கப்பட்ட குறிப்புகள் விவரித்த முடிவில் ஆதாரம், நம்பிக்கை மற்றும் இடைவெளியுடன் நகலெடுக்கப்படுகின்றன, மேலும் அவை சட்ட தலைப்புகளுடன் நம்பத்தகாத அவதானிப்புகளாக வழங்கப்படுகின்றன. தவறான, வரம்பிற்கு அப்பாற்பட்ட அல்லது ஆதாரம் இல்லாத உரை தலைப்பு ஸ்ட்ரீமில் கலக்கப்படுவதற்குப் பதிலாக நிராகரிக்கப்படுகிறது. இரண்டு கோரிக்கை-உடல் டிரான்ஸ்கிரிப்ட் சேனல்களும் `client` க்கு வழங்கப்பட்ட ஆதாரத்தை இயல்பாக்குகின்றன, இதில் சுய-உறுதிப்படுத்தப்பட்ட `embedded` அல்லது `audio-bridge` லேபிள்கள் அடங்கும். சேவையகத்திற்குச் சொந்தமான அடாப்டரால் மட்டுமே அந்த நம்பகமான லேபிள்களை குறியீடு-மட்டும் `trustedSource` வாதத்தின் மூலம் ஒதுக்க முடியும்; ஒரு கோரிக்கை JSON புலம் அந்த வாதத்தை அடைய முடியாது. டிரான்ஸ்கிரிப்ட் உரை அதன் ஆதாரத்தைப் பொருட்படுத்தாமல், நம்பத்தகாத மீடியா-பெறப்பட்ட உள்ளடக்கமாகவே உள்ளது, மேலும் அங்கீகாரத்தை ஒருபோதும் தீர்மானிக்கக்கூடாது.

ஒரு மேம்பட்ட அழைப்பாளர் அதே வீடியோவிற்கு `audioTranscript` டிராக்கை வழங்கலாம்; இது கிளையன்ட் வழங்கிய உரையாகக் கருதப்படுகிறது, சர்வர் டிரான்ஸ்கிரிப்ஷனுக்கான ஆதாரம் அல்ல. இணைவு தையல் ஒரு காலக்கெடுவின் கீழ் காட்சி மற்றும் ஆடியோ அவதானிப்புகளை இயக்குகிறது மற்றும் சிக்னலை நிறுத்துகிறது, அவற்றை ஒரு பொதுவான காலவரிசையில் ஆர்டர் செய்கிறது, சரியான நகல்களை சரிசெய்கிறது மற்றும் ஒரு பக்கம் மட்டுமே வெற்றிபெறும் போது ஒரு பகுதி முடிவைப் புகாரளிக்கிறது. ஒரு தவறான `audioTranscript` அந்த பகுதி முடிவு — க்கு குறைகிறது, காட்சி விளக்கம் வைக்கப்பட்டு, ஆடியோ கிளை முழு வீடியோவும் தோல்வியடைவதற்குப் பதிலாக — சுத்திகரிக்கப்பட்ட தோல்விக் குறியீட்டைப் பதிவு செய்கிறது. ஒவ்வொரு கிளைக்கும் கிடைக்கும் தன்மை, பகுதிக் கொடி மற்றும் சுத்திகரிக்கப்பட்ட தோல்விக் குறியீடுகள் விவரிக்கப்பட்ட முடிவிலும், காட்ரெயில் மெட்டாடேட்டாவிலும் (`audioFusionRuns`/`audioFusionPartials`/ `audioFusionFailureCodes`), முடிவு-கேச் மெட்டாடேட்டாவிலும், பிரிட்ஜ் ஃப்யூஷன் கவுண்டர்களிலும் பாதுகாக்கப்படுகின்றன. இயல்புநிலை வீடியோ பிரிட்ஜ் பாதை பேச்சிலிருந்து உரைக்கு அழைப்பு விடுக்காது அல்லது இரண்டாவது மீடியா நகலைப் பதிவிறக்காது; வெளிப்படையான டிராக் இல்லாமல், அது வீடியோவில் மட்டுமே இருக்கும்.

**டிரான்ஸ்கிரிப்ட் தக்கவைப்பு (#12150 P1).** வீடியோ பிரிட்ஜ் (தன்னைத் தேர்ந்தெடுக்கும் போது) டிரான்ஸ்கிரிப்ட் க்யூ — வழங்கும்போது இது தானாகவே பொருந்தும், தனித் தக்கவைப்புக் கொடி இல்லை. கோரிக்கை எந்த டிரான்ஸ்கிரிப்ட் குறியையும் (அழைப்பாளர் அறிவித்த `transcript` அல்லது ஒரு இணைந்த `audioTranscript`) வழங்கும்போது, காவலர் அதை `videoBridgeObserved` எனக் குறிக்கும் மற்றும் வீடியோ விளக்கத்தின் — இன் மறுவடிவமைக்கப்பட்ட நிழலை ஒரே மாதிரியான ரெண்டரிங் உருவாக்குகிறது. கூடியது (தட்டையான உரையை பாகுபடுத்துவதன் மூலம், அதனால் `[inaudible]`/`[music]` `[redacted-video-transcript]` போன்ற `]` உள்ள உடல்கள் உட்பட, — எதிரி அல்லது சாதாரணமான எந்தக் குறிப்பு உள்ளடக்கமும் — முடியாது). தொடர்ச்சியான அழைப்பு-பதிவு கோரிக்கை அமைப்பு, வீடியோவில் இருந்து பெறப்பட்ட ஒவ்வொரு உரைப் பகுதியையும் அந்தத் திருத்தப்பட்ட நிழலுக்காக மாற்றுகிறது, இது உள்ளடக்க சமத்துவத்துடன் பொருந்துகிறது; `fullText` நங்கூரம் முடிக்கப்பட்ட முன்-அழைப்பு காவலர் பேலோடில் இருந்து மீண்டும் படிக்கப்படுகிறது, எனவே பின்னாளில் செயின் காவலர்கள் ( PII மற்றும் நற்சான்றிதழ் முகமூடிகள், முன்னுரிமைகள் 10/95) விளக்க உரையை மீண்டும் எழுதுவதற்குப் பிறகும், system-prompt/handoff/memory உட்செலுத்தலுக்குப் பிறகு செய்தி வரிசையை மாற்றியமைத்த பின்னரும் போட்டி வெற்றிபெறும். மாதிரிக்கு அப்ஸ்ட்ரீம் அனுப்பப்பட்ட உடல் மாறாமல் உள்ளது. கவனிக்கப்பட்ட கோரிக்கையில் நீடித்த நினைவகம் இல்லை (கோரிக்கை மற்றும் பதில்-பெறப்பட்ட பிரித்தெடுத்தல் இரண்டும் தவிர்க்கப்பட்டது), எனவே மாதிரியின் சொந்தப் பதிலால் டிரான்ஸ்கிரிப்ட் உரையை நினைவகத்தில் எதிரொலிக்க முடியாது.

**மூல வீடியோ புலங்கள் (#12430).** பிரிட்ஜ் இயக்கப்பட்டிருக்கும் போது மற்றும் நேட்டிவ் வீடியோ ஆதரவு தெரியவில்லை அல்லது இல்லாவிட்டால், வரையறுக்கப்பட்ட `transcript`/`audioTranscript` புலங்களும் `videoBridgeObserved` செயல்படுத்தும் , விளக்கம் தோல்வி அல்லது `maxVideos` வரம்புக்கு பிறகும். `null` மற்றும் வெற்று சரங்களின் எண்ணிக்கை; இல்லாத புலங்கள் மற்றும் வீடியோ அல்லாத மெட்டாடேட்டா இல்லை. தக்கவைக்கப்பட்ட நகல்கள் இந்தப் புலங்களைத் திருத்துகின்றன அல்லது கோரிக்கையைத் தவிர்க்கின்றன, மேலும் caches/Memory புறக்கணிக்கப்படும்.

அந்த ஃபால்பேக் பாதைகளில், செல்லுபடியாகும் அழைப்பாளர் குறிப்புகள் தரமற்ற வழங்குநர் புலங்களை விட ஆதரிக்கப்படும் `text`/`input_text` பகுதிகளாக மாறும். கோரிக்கை வழங்கப்பட்ட இரண்டு தடங்களும் நம்பத்தகாத `client` அவதானிப்புகளாகவே உள்ளன, வீடியோ விவரிக்கப்படவில்லை மற்றும் நேரமுத்திரைகள் மீடியாவிற்கு எதிராக சரிபார்க்கப்படவில்லை என்ற வெளிப்படையான எச்சரிக்கையுடன். தற்போதுள்ள 256-cue/64-KiB மொத்த மற்றும் ஒரு கியூ வரவுசெலவுத் திட்டங்கள் இரண்டு தடங்களில் ஒன்றாகப் பொருந்தும்; நேர முத்திரைகள் தரகரின் 600-வினாடி உச்சவரம்பு மற்றும் வழங்கப்பட்ட ஃபோகஸ் சாளரத்திற்கு பொருந்த வேண்டும். தவறான டிராக்குகள் நிராகரிக்கப்பட்டன, தன்னிச்சையான உரையாக அனுப்பப்படாது; ஒரு செல்லுபடியாகும் உடன்பிறப்பு அவர்களின் ஒருங்கிணைந்த வரவுசெலவுத் தொகையை மீறும் வரை பயன்படுத்தப்படலாம். Null/empty புலங்கள் எந்த உரையையும் சேர்க்காது. இந்த ஃபால்பேக் மூலம் மீடியா பெறுதல் அல்லது டிரான்ஸ்கிரிப்ஷன் எதுவும் சேர்க்கப்படவில்லை. டிரான்ஸ்கிரிப்ட் நீட்டிப்பு புலங்கள் ஃபால்பேக் வீடியோ கேரியர் மற்றும் அதன் `video_url`/`source` ஆப்ஜெக்ட்களிலிருந்து அகற்றப்படும். OpenAI கம்பி அனுமதிப்பட்டியல் கண்டிப்பாக இருக்கும்; தெரியாத-சொந்த வீடியோ கேரியர்கள் கிடைக்கின்றன மற்றும் அறியப்பட்ட உரை-மட்டும் இலக்குகள் பாதுகாப்பான குறிப்பான்களை வைத்திருக்கின்றன. கட்டமைக்கப்பட்ட மறுவடிவமைப்பு நிழல்கள் இணைக்கப்பட்ட டிரான்ஸ்கிரிப்ட் உரையைப் பாதுகாக்கும், அதே சமயம் அசல் அழைப்பாளருக்குச் சொந்தமான கோரிக்கை மாறாமல் இருக்கும். பூர்வீக-ஆதரவு இலக்குகள் மற்றும் முடக்கப்பட்ட பாலங்கள் அவற்றின் தற்போதைய பைபாஸ் நடத்தையைத் தக்கவைத்துக்கொள்கின்றன.

கூடுதல் தக்கவைக்கப்பட்ட பிரதிகள் அதே கவனிக்கப்பட்ட-கோரிக்கை சமிக்ஞையைப் பயன்படுத்துகின்றன. ரா ப்ரீ-கார்ட்ரெயில் கிளையன்ட்-கோரிக்கை ஸ்னாப்ஷாட், இன்-மெமரி நிலுவையில் உள்ள கோரிக்கை, மற்றும் ஆரம்ப நிராகரிக்கப்பட்ட கோரிக்கை பதிவு ஆகியவை வீடியோ பாகங்களில் டிரான்ஸ்கிரிப்ட் புலங்களை கட்டமைப்பு ரீதியாக மாற்றும்; பைப்லைன் நிலைகள் மற்றும் சூழல் ஹேண்ட்ஆஃப் மூலம் ஒருங்கிணைக்கப்பட்ட சரம் தூண்டுதல்கள் தொடர்ந்து-கோரிக்கை-உடல் சிங்கில் மாற்றியமைக்கப்படுகின்றன. வேண்டுமென்றே நிராகரிக்கப்பட்ட உரையை மறுகட்டமைப்பதற்குப் பதிலாக, நீடித்த `video_content_removed` மார்க்கர், `previous_response_id` தொடர்ச்சியை மூடச் செய்கிறது. ஒரு கவனிக்கப்பட்ட கோரிக்கையானது உள்நுழைவதற்கு முன் அதன் ஒவ்வொரு பகுதியின் மறுவடிவமைப்பின் நிழலை இழந்தாலோ அல்லது பல வீடியோ நிழல்களில் ஒன்று கூட பின்னர் கோரிக்கை பிறழ்வுகளுக்குப் பிறகும் பொருந்தவில்லை என்றால், ஓரளவு திருத்தப்பட்ட டிரான்ஸ்கிரிப்டைத் தக்கவைத்துக்கொள்வதற்குப் பதிலாக, தக்கவைக்கப்பட்ட கோரிக்கை அமைப்பு முற்றிலும் தவிர்க்கப்படும்.

கவனிக்கப்பட்ட கோரிக்கைக்கு, ஒரு மாதிரி பதில், டிரான்ஸ்கிரிப்ட்டின் எந்தப் பகுதியையும் கட்டமைக்கப்பட்ட குறி எல்லை இல்லாமல் மேற்கோள் காட்டலாம். அதன் தொடர்ச்சியான அழைப்பு-பதிவு `responseBody`, ஒரு தவிர்க்கும் குறிப்பான் மூலம் மாற்றப்படுகிறது; விரிவான பைப்லைன் கலைப்பொருள் (இதில் upstream/client உடல்கள் மற்றும் ஸ்ட்ரீம் துகள்கள் அடங்கும்) தக்கவைக்கப்படவில்லை. செமாண்டிக், ஐடிம்போடென்சி மற்றும் ரீசனிங்-ரீப்ளே தற்காலிகச் சேமிப்புகள் அந்தக் கோரிக்கைக்கான வாசிப்பு மற்றும் எழுதுவதைத் தவிர்க்கின்றன. வழங்குநரின் கோரிக்கை மற்றும் கிளையன்ட் காணக்கூடிய பதில் மாறாமல் இருக்கும். விரிவான கலைப்பொருள் தவிர்க்கப்படும்போது, தற்காலிக இடையகத்திலிருந்து ஆரம்பகால கீப்பிலைவ் பைட்டுகள் வெளியேற்றப்படும். Kiro இன் தவறான EventStream எச்சரிக்கையானது பேலோட் பைட் எண்ணிக்கையை மட்டுமே தெரிவிக்கிறது, அதன் உள்ளடக்கங்கள் அல்லது JSON பாகுபடுத்தியின் மூலப் பிழையை ஒருபோதும் தெரிவிக்காது. இது தொடர்பில்லாத ஒவ்வொரு provider/plugin கண்டறிதலும் தணிக்கை செய்யப்பட்டதாகக் கூறவில்லை; பரந்த தக்கவைக்கப்பட்ட ஸ்வீப் #11658 இல் கண்காணிக்கப்படுகிறது.

உள் `/api/modality-bridge/video/drilldown` வாழ்க்கைச் சுழற்சி ஒரு தனி, loopback/token-authenticated கேச் அடி மூலக்கூறு ஆகும். ஒவ்வொரு செயல்பாட்டிற்கும் ஒரு நியமன ஒளிபுகா முதன்மை ID தேவைப்படுகிறது. ஒரு உற்பத்தி அழைப்பாளர் இயக்கப்படுவதற்கு முன், அது அங்கீகரிக்கப்பட்ட குத்தகைதாரரிடமிருந்து அந்த ID ஐப் பெற வேண்டும் மற்றும் கிளையன்ட்-தேர்ந்தெடுக்கப்பட்ட மதிப்பை ஒருபோதும் அனுப்பக்கூடாது. கேச் விசைகள் அந்த முதன்மையை நியமன அமர்வு மற்றும் வீடியோ-குறிப்பு IDs உடன் பிணைத்து, அவற்றின் SHA-256-derived விசைகளை மட்டுமே சேமித்து, அதே முதன்மைக்கு வாசிப்பு மற்றும் நீக்குதல் ஆகிய இரண்டையும் நோக்கமாகக் கொண்டுள்ளது. கேச் ஒரு நுழைவுக்கு அதிகபட்சமாக 16 பெறப்பட்ட JPEG பிரேம்களை சேமிக்கிறது, பத்து நிமிடங்களுக்குப் பிறகு அவை காலாவதியாகிவிடும், மேலும் வரம்புக்குட்பட்ட `start`/`end` வாசிப்புகள் அல்லது வெளிப்படையான அமர்வு நீக்கத்தை ஆதரிக்கிறது.

ஒவ்வொரு முதன்மையும் 16 உள்ளீடுகள் மற்றும் 64 MiB நியமன JPEG தரவுகளுக்கு வரம்பிடப்பட்டுள்ளது. அந்த வரம்புகள் உலகளாவிய 64-entry/256 MiB உச்சவரம்பிலிருந்து சுயாதீனமானவை: உலகளாவிய LRU வெளியேற்றத்திற்கு முன் அதிபரின் குறைந்தபட்சம் சமீபத்தில் பயன்படுத்தப்பட்ட உள்ளீடுகளை மட்டுமே முதன்மை ஒதுக்கீடு அழுத்தம் வெளியேற்றுகிறது. காலாவதியான உள்ளீடுகள் கேச் செயல்பாட்டின் முதன்மை மற்றும் உலகளாவிய கணக்கியலில் இருந்து துடைக்கப்படுகின்றன, அதே நேரத்தில் ரத்துசெய்தல் மற்றும் சரிபார்த்தல் தோல்வி ஒரு பகுதியளவு மாற்றத்தை செய்யாது.

கேச் கேச் கேனானிகல் அல்லாத Base64, அதிகப்படியான திணிப்பு, JPEG அல்லாத மீடியா, தவறான அல்லது துண்டிக்கப்பட்ட JPEGs, மற்றும் JPEGs ஆகியவற்றை நிராகரிக்கிறது, இது வரம்பிற்குட்பட்ட முழு-பட `sharp` டிகோடின் போது எச்சரிக்கையை உருவாக்குகிறது. இது ஏற்றுக்கொள்ளப்பட்ட ஒவ்வொரு படத்தையும் ஒரு நியமன JPEG ஆக மறு-குறியீடு செய்கிறது, அழைப்பாளர் புலங்களை நம்புவதற்குப் பதிலாக டிகோட் செய்யப்பட்ட பைட்டுகளிலிருந்து அகலத்தையும் உயரத்தையும் பெறுகிறது, மேலும் அவற்றைத் தக்கவைத்துக்கொள்வதற்குப் பதிலாக எந்தப் பின்தொடரும் பாலிகிளாட் பைட்டுகளையும் நிராகரிக்கிறது. இரண்டு ஒதுக்கீட்டிற்கும் வரம்பிற்குட்பட்ட நியமன சுருக்கப்பட்ட தாங்கல் மட்டுமே வசூலிக்கப்படுகிறது. JSON கம்பி வரம்பு 32 MiB டிகோட்-இன்புட் உச்சவரம்புக்கான Base64 மேல்நிலையை உள்ளடக்கியது. ஒவ்வொரு சேமிக்கப்பட்ட வழித்தோன்றலும் அதன் சரிபார்க்கப்பட்ட JPEG format/resolution, மாதிரிக் கொள்கை, வழித்தோன்றல் பதிப்பு, உருவாக்கும் நேரம், சர்வர்-கணிக்கப்பட்ட உள்ளடக்க ஹாஷ் மற்றும் ஹாஷ் செய்யப்பட்ட பெற்றோர் குறிப்பு மற்றும் நம்பகமான அழைப்பாளரின் பெற்றோர்-உள்ளடக்க ஹாஷ் ஆகியவற்றைப் பதிவுசெய்கிறது. அணு கேச் கமிட் செய்வதற்கு முன், ஒத்திசைவற்ற decode/hash கட்டங்களுக்கு இடையே ரத்துச் சரிபார்க்கப்படுகிறது.

இரண்டாவது வீடியோ download/extraction. இல்லாமல், வெற்றிகரமான காட்சிப் பகுப்பாய்விற்குப் பிறகுதான் உற்பத்தித் தயாரிப்பாளர் ஏற்கனவே பெறப்பட்ட தரகர் பிரேம்களை மீண்டும் பயன்படுத்துகிறார், இதற்கு ஆபரேட்டர் `modalityBridgeVideoDrilldownEnabled=true`, கண்டிப்பான ஒவ்வொரு பகுதி `drilldown: true`, மற்றும் அங்கீகரிக்கப்பட்ட API-கீ பதிவு ID. கிளையண்ட் அறிவித்த principal/session மதிப்புகள் ஒருபோதும் உரிமையை நிறுவாது. மூன்று நிபந்தனைகளும் இல்லாமல், இது கூடுதல் பிரேம்களை ஹாஷ் செய்யவோ, அளவை மாற்றவோ அல்லது தக்கவைக்கவோ முடியாது. தக்கவைத்தல் தோல்வி பயன்படுத்தக்கூடிய காட்சி பதிலைப் பாதுகாக்கிறது. ஒப்புதல் கோரிக்கைகள் முழு-வீடியோ முடிவு தற்காலிக சேமிப்பையும் கடந்து செல்கின்றன, எனவே தற்காலிகச் சேமிப்பு முடிவுகள் ஒருபோதும் ஹேண்டில்களை மீண்டும் இயக்காது.

வெற்றிகரமான JSON மற்றும் SSE பதில்கள் வரம்பிற்குட்பட்ட `x-omniroute-video-drilldown` தலைப்பில் அதிகபட்சம் நான்கு ஒளிபுகா கைப்பிடிகளை வெளிப்படுத்தும். அங்கீகரிக்கப்பட்ட உலாவி மூலங்கள் CORS மூலக் கொள்கையை விரிவுபடுத்தாமல் அந்தத் தலைப்பைப் படிக்கலாம். புதிய கைப்பிடிகள் `v1.<32-byte random base64url token>` பயன்படுத்துகின்றன, மேலும் பதிவகம் அவற்றின் SHA-256 ஹாஷ்களை மட்டுமே வைத்திருக்கிறது. reader/header பாகுபடுத்தி மரபு 64-ஹெக்ஸ் டோக்கன்களையும் ஏற்றுக்கொள்கிறது. அங்கீகரிக்கப்பட்ட பொது நுகர்வோர் `GET /api/v1/video-bridge/drilldown?handle=...`, `modalityBridgeVideoDrilldownRemoteEnabled=true` மூலம் சுயாதீனமாக நுழைவு. லெகசி `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_REMOTE_ENABLED` env ஃபால்பேக் இயக்கப்பட்டிருந்தாலும், வெளிப்படையான தவறான அணுகலை திரும்பப் பெறுகிறது. உற்பத்தித் தக்கவைப்பு ஒத்த மரபு `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_ENABLED` வீழ்ச்சியைக் கொண்டுள்ளது. இரண்டு ஃபால்பேக்குகளும் இயல்புநிலை ஆஃப்.

நுகர்வோர் அங்கீகரிக்கப்பட்ட விசையிலிருந்து உரிமையைப் பெறுகிறார் மற்றும் முக்கிய கொள்கையைப் பயன்படுத்துகிறார்: GET மற்றும் DELETE இரண்டும் `/v1` மற்றும் `/api/v1` மாற்றுப்பெயர்கள் உட்பட `video` எண்ட்பாயிண்ட் வகையைச் சேர்ந்தவை. காலியாக இல்லாத இறுதிப்புள்ளி அனுமதிப்பட்டியலுடன் கூடிய விசைகள் கண்டிப்பாக `video`; கட்டுப்பாடற்ற விசைகள் இணக்கமாக இருக்கும். நுகர்வோர் அறியப்படாத, காலாவதியான மற்றும் மற்றொரு விசையின் கைப்பிடிகளுக்கு அதே 404 ஐத் திருப்பித் தருகிறார். இது `variant=preview|standard|detail` (அதிகபட்ச JPEG பரிமாணம் 320/640/1280, ஒருபோதும் உயர்த்தப்படவில்லை), `limit=1..8` (அல்லது மரபு `frames` மாற்று, இரண்டுமே இல்லை), பூஜ்ஜிய அடிப்படையிலான `page`, மற்றும் விருப்பமான `start`/`end` ஃபோகஸ் வினாடிகள் ஆகியவற்றை ஏற்றுக்கொள்கிறது. நகல் வினவல் விசைகள் மற்றும் தலைகீழ் கவனம் சாளரங்கள் நிராகரிக்கப்படுகின்றன. திரும்பிய ஒவ்வொரு மாறுபாட்டிலும் அதன் உண்மையான உள்ளடக்கம் மற்றும் உண்மையான தெளிவுத்திறன் மெட்டாடேட்டாவின் ஹாஷ் உள்ளது, அவை தக்கவைக்கப்பட்ட மூலத்துடன் இணைக்கப்பட்டுள்ளன. மாறுபாடுகள் கூடுதல் தக்கவைக்கப்பட்ட பிரதிகளாக சேமிக்கப்படுவதற்குப் பதிலாக படிக்கும்போது பெறப்படுகின்றன. Base64/envelope உட்பட JSON மறுமொழியானது 32 MiB ஆக மூடப்பட்டுள்ளது; பெரிதாக்கப்பட்ட பக்கம் 413ஐ வழங்குகிறது மற்றும் கிளையன்ட் குறைவான பிரேம்களைக் கோர வேண்டும். திரும்புவதற்கு முன், ஒவ்வொரு மறுஅளவும் மற்றும் கைப்பிடியின் செல்லுபடியை மறுபரிசீலனை செய்யும்போது காசோலை ரத்துசெய்தலைப் படிக்கும். உரிமையாளரின் `DELETE` ஐடியம்போடென்ட்; நீக்குதல் அல்லது TTL காலாவதியானது தக்க ஆதாரம் மற்றும் பயன்பாட்டு கணக்கை வெளியிடுகிறது.

பகிரப்பட்ட ஸ்டோர் செயல்முறை-உள்ளூர்: மறுதொடக்கம் செய்யும் போது கைப்பிடிகள் காலாவதியாகும் மற்றும் சுயாதீன OmniRoute செயல்முறைகளுக்கு இடையில் மாற்ற முடியாது. மேலாண்மை புள்ளிவிவரங்கள் பயனுள்ள தக்கவைப்பு/தொலைநிலைக் கொள்கையை அம்பலப்படுத்துகின்றன மற்றும் entries/bytes மட்டும் வைத்திருக்கின்றன, ஒருபோதும் ஊடகங்கள், குறிப்புகள், முதன்மை IDs அல்லது கையாளுதல்கள். வீடியோ அமைப்புகள் குழு அந்த மதிப்புகளைக் காட்டுகிறது மற்றும் இரண்டு ஒப்புதல் சுவிட்சுகளையும் தொடரலாம். இந்த செயல்படுத்தல் ஆவணம் நேரடி வரிசைப்படுத்தல் அல்லது பதவி உயர்வு சான்று அல்ல; உண்மையான மாதிரி ஏற்றுக்கொள்ளல் தனித்தனியாக கண்காணிக்கப்படுகிறது.

கட்டமைக்கப்பட்ட வீடியோ மாதிரியுடன் ஃபிரேம்கள் வரிசையாகத் தலைப்பிடப்பட்டுள்ளன. வெற்று வீடியோ மேலெழுதல் பார்வை அமைப்பைப் பெறுகிறது; இரண்டும் காலியாக இருந்தால், விஷன் ஆட்டோ-ரௌட்டர் பயனுள்ள பார்வை திறன் கொண்ட மாதிரியைத் தேர்ந்தெடுக்கும். வெற்றிகரமான தலைப்புகள் அசல் பகுதியை நிலையான `[Video description:` முன்னொட்டுடன் மாற்றும், இது உரையை நம்பத்தகாத மீடியா-பெறப்பட்ட கண்காணிப்பாகவும் குறிக்கிறது மற்றும் மீடியாவில் உள்ள வழிமுறைகளைப் பின்பற்ற வேண்டாம் என்று கீழ்நிலை மாதிரிகள் கூறுகிறது. ஃபிரேம்-கேப்ஷன் கேச் கீகளில் JPEG பைட்டுகள், ப்ராம்ட், டைம்ஸ்டாம்ப் மற்றும் பயனுள்ள மாதிரி ஆகியவை அடங்கும்; வெற்றிகரமான தலைப்புகள் மட்டுமே தற்காலிகமாக சேமிக்கப்படும். கேச் உள்ளீடுகள் உண்மையான வெற்றிகரமான தயாரிப்பாளர் மாதிரியைத் தக்கவைத்துக்கொள்கின்றன, இதில் ஃபால்பேக் மாடல் அடங்கும்; வெவ்வேறு மாடல்களால் வெவ்வேறு பிரேம்கள் தயாரிக்கப்படும் போது பிரிட்ஜ் `mixed` புகாரளிக்கிறது. கேச் ஹிட் ஆனது அந்த தயாரிப்பாளர் அடையாளத்தை கோரப்பட்ட ரூட்டிங் திட்டமாக மறுபெயரிடுவதற்குப் பதிலாக மீண்டும் பயன்படுத்துகிறது. அவுட்புட் — ப்ராம்ட், பயனுள்ள மாதிரி, மாதிரிக் கொள்கை, பிரேம் எண்ணிக்கை, சொற்பொருள் பகுப்பாய்வு முறை, இயல்பாக்கப்பட்ட ஃபோகஸ் ஹின்ட்டின் SHA-256 கைரேகை, ஃபோகஸ் விண்டோ, `transcript`, `audioTranscript`, மற்றும் காண்டாக்ட்-ஷீட் கொடி — ஆகியவற்றை மாற்றும் ஒவ்வொரு உள்ளீட்டிலும் முழு-வீடியோ ரிசல்ட் கேச் முக்கியமானது. காட்சி நீக்குதல் கொள்கை பதிப்பு, வரம்பு மற்றும் வரம்புக்குட்பட்ட வேட்பாளர்-சட்ட எண்ணிக்கை ஆகியவை முடிவு-கேச் கீ மற்றும் மெட்டாடேட்டாவில் வெளிப்படையானவை; கொள்கை மாற்றத்தால் பழைய முழு வீடியோ விளக்கத்தை மீண்டும் பயன்படுத்த முடியாது. ரிசல்ட்-கேச் v4 மெட்டாடேட்டா பயன்முறையையும் கைரேகையையும் வைத்திருக்கிறது. Guardrail மெட்டாடேட்டா கோரப்பட்ட மற்றும் பயனுள்ள பகுப்பாய்வு முறைகள் இரண்டையும் தெரிவிக்கிறது; பயன்படுத்தக்கூடிய பயனர் உரை இல்லாமல் கோரப்பட்ட `focused` பயன்முறையானது திறம்பட `full` என தெரிவிக்கப்படுகிறது.

காவலர் ஒவ்வொரு ஆதரிக்கப்படும் வீடியோ பகுதியையும் பிரித்தெடுக்கிறது ஆனால் `modalityBridgeVideoMaxVideos` விட அதிகமாக விவரிக்கவில்லை. `supportsVideo === false` உள்ளதாக நிரூபிக்கப்பட்ட இலக்குக்கு, தோல்வியுற்ற மற்றும் அதிக வரம்பிற்குட்பட்ட வீடியோக்கள் வெளிப்படையான பாதுகாப்பான உரை குறிப்பான்களாக மாறும், அதனால் எந்த மூல வீடியோவும் உயிர்வாழாது. திறன் தெரியாத போது, அந்த பாகங்கள் தங்கள் வீடியோ கேரியரைத் தக்கவைத்துக்கொள்கின்றன; எந்த ஃபால்பேக் டிரான்ஸ்கிரிப்ட்டும் மேலே உள்ள வரம்புக்குட்பட்ட உரை மாற்றத்தைப் பின்பற்றுகிறது. `supportsVideo === true` உடன் இலக்குகள் பாலத்தை கடந்து செல்கின்றன. கிளையன்ட் கோரிக்கை நிறுத்து சமிக்ஞை பதிவிறக்கம், தரகர் வரிசை, துணை செயல்முறைகள் மற்றும் தலைப்பு அழைப்புகள் மூலம் பரவுகிறது; வீடியோக்களுக்கு இடையில் நிறுத்தப்படுவதை நிறுத்துகிறது மற்றும் மூல மீடியாவில் ஒருபோதும் தோல்வியடையாது.

### PII மாஸ்கர் (`piiMasker.ts`)

இயங்குகிறது** இரண்டும்** நிலைகள்.

- **`preCall`** பேலோடை குளோன் செய்கிறது, `system`, `messages`, `input`, மற்றும் `prompt` (வெற்று சரம் உருப்படிகள் உட்பட) மற்றும் `processPII()` ( `@/shared/utils/inputSanitizer` இலிருந்து) சரம் `content`/`text` புலங்களுக்குப் பயன்படுத்துகிறது. `PII_REDACTION_ENABLED=true`, கண்டறியப்பட்ட PII ஆனது வெளிச்செல்லும் பேலோடில் மாற்றியமைக்கப்படும். இது `INPUT_SANITIZER_MODE` இலிருந்து சுயாதீனமானது (இது உடனடி ஊசி கொள்கையை மட்டுமே கட்டுப்படுத்துகிறது). மறுசீரமைப்பு முடக்கப்பட்டிருக்கும் போது, அழைப்பு பதிவுகள் கண்டறிதல் எண்ணிக்கையை உள்ளடக்கத்தை மீண்டும் எழுதாமல் இருக்கும்.
- **`postCall`** பதிலை ஆழமாக குளோன் செய்கிறது, `sanitizePIIResponse()` மற்றும் Responses-API- வடிவ முகமூடியை இயக்குகிறது (`maskResponsesOutput` — `output_text` மற்றும் `output[].content[].text` உள்ளடக்கியது). ஏதேனும் குறைப்பு ஏற்பட்டால், மாற்றியமைக்கப்பட்ட பதில் அசலுக்குப் பதிலாக இருக்கும்.

காவலரண் ஒருபோதும் தடுப்பதில்லை; அது மட்டும் சிறுகுறிப்பு (`meta.detections`, `meta.redacted`) அல்லது மீண்டும் எழுதுகிறது.

**மீளக்கூடிய பெட்டகம் (`PII_REVERSIBLE_VAULT_ENABLED`, இயல்புநிலை `false`).** `PII_REDACTION_ENABLED` மற்றும் `PII_REVERSIBLE_VAULT_ENABLED` இரண்டும் இயக்கத்தில் இருக்கும் போது (DB override > env > default, ஒரு கோரிக்கைக்கு ஒரு முறை படிக்கவும்), `handleChat` ஒரு கிளையன்ட் கோரிக்கைக்கு ஒரு பெட்டகத்தைத் திறந்து (`src/lib/pii/requestTokenVaultScope.ts`) அதை `GuardrailContext.tokenVault` என முன் அழைப்பு பாஸுக்கு அனுப்புகிறது. முகமூடியாளர் பின்னர் `[EMAIL_REDACTED]` க்கு பதிலாக `<<PII_EMAIL_QWERTYUI_1>>` போன்ற பினாமி டோக்கன்களை, உள்ளமைக்கப்பட்ட, சரிபார்க்கப்பட்ட (GDPR/POPIA) மற்றும் தனிப்பயன் விதிகளுக்கு ஒரே மாதிரியாக எழுதுகிறார். நான்ஸ் என்பது ஒரு கோரிக்கைக்கு 8 சீரற்ற பெரிய எழுத்துக்கள் ஆகும், அதே மதிப்பு கோரிக்கைக்குள் அதே டோக்கனைப் பெறுகிறது. முகமூடிகள் மட்டுமே மிண்ட்ஸ்: ப்ராம்ட்-இன்ஜெக்ஷன் கார்டு மற்றும் `/api/guardrails/test` வால்ட் இல்லாமல் இயங்கும் மற்றும் பிளேஸ்ஹோல்டர்களை வைத்திருக்கும்.

- வழங்குநர், ஒவ்வொரு காம்போ லெக், மீண்டும் முயற்சி, இணைவு குழு உறுப்பினர் மற்றும் இணைவு நீதிபதி டோக்கன்களை மட்டுமே பார்க்கிறார்கள். பாகுபடுத்தப்பட்ட `handleChat` இல் உள்ள ஒரு புலத்திற்கு 2xx பதிலில், டோக்கன்கள் ஒருமுறை மீட்டமைக்கப்படும்: பாகுபடுத்தப்பட்ட SSE இல் ஒரு புலத்திற்கு (நிகழ்வுகள் முழுவதும் ஒரு டோக்கன் பிரிப்பு இன்னும் தீர்க்கப்படுகிறது; கருவி-அழைப்பு வாதங்கள் JSON-எஸ்கேப் செய்யப்பட்டவை) அல்லது ஒரு JSON உடலில் ஒரு புலத்திற்கு, மறுகணிக்கப்பட்ட `Content-Length`. உள்ளடக்கம் மற்றும் பகுத்தறிவு உரை மற்றும் கருவி அழைப்பு வாதங்கள் மீட்டமைக்கப்படுகின்றன. பிழை உடல்கள் (4xx/5xx) டோக்கன்களை வைத்திருக்கும்.
- தோல்விகள் தனிப்பட்டதாகவே இருக்கும்: அச்சிடுதல் தோல்வியுற்றால் அல்லது பெட்டகம் மதிப்பை மறுத்தால் (1000 உள்ளீடுகள், ஒரு மதிப்புக்கு 256 எழுத்துகள், மொத்தம் 64 KB ), அதற்குப் பதிலாக ஒதுக்கிட எழுதப்படும்; பெட்டகத்தால் தீர்க்க முடியாத ஒரு டோக்கன், அல்லது தோல்வியுற்ற மறுசீரமைப்பு, உண்மையில் இருக்கும் மற்றும் ஒரு எண்ணிக்கை மட்டுமே பதிவு செய்யப்பட்டுள்ளது. பெட்டகத்தில் டைமர்கள் இல்லை மற்றும் உலகளாவிய நிலை இல்லை; மறுமொழி ஸ்ட்ரீம் முடிவடையும் போது, ரத்துசெய்யப்பட்டால் அல்லது பிழைகள் ஏற்பட்டால் அது அழிக்கப்படும்.
- ஒரு கோரிக்கை டோக்கன்கள், நினைவகப் பிரித்தெடுத்தல், ஐடெம்போடென்சி சேமிப்பு மற்றும் சொற்பொருள்-கேச் எழுதுதல் ஆகிய இரண்டும் தவிர்க்கப்படும், ஏனெனில் பின்னர் எந்த கோரிக்கையும் அந்த டோக்கன்களைத் தீர்க்க முடியாது. அழைப்பு பதிவுகளில் வழங்குநரின் கோரிக்கை மற்றும் பதில் டோக்கன்களை எடுத்துச் செல்லும்; உள்நுழைந்த கிளையன்ட் கோரிக்கை அமைப்பு இன்னும் மூல கிளையன்ட் உள்ளீடாக உள்ளது, இது வெற்று மறுவடிவமைப்புடன் உள்ளது.
- டோக்கன்கள் ஒரு கோரிக்கைக்கு ரேண்டம் அல்லாததைப் பயன்படுத்துகின்றன, எனவே ஒவ்வொரு திருப்பத்திலும் ப்ராம்ட் முன்னொட்டு மாறுகிறது: வழங்குநர் பக்க ப்ராம்ட் கேச்சிங் முகமூடியான திருப்பங்களுக்குத் தாக்காது, மேலும் ஒரு டோக்கன் பின்னர் திரும்பும்போது (உதாரணமாக `previous_response_id` வழியாக ) பழைய கோரிக்கையைச் சேர்ந்தது மற்றும் எழுத்துப்பூர்வமாக இருக்கும்.

#### ஒவ்வொரு வகை தேர்வு, தனிப்பயன் வடிவங்கள் மற்றும் கண்டறிதல் கவுண்டர்கள்

**டாஷ்போர்டு → அமைப்புகள் → பாதுகாப்பு → PII மறைத்தல்** மறைக்கப்பட்டதை_தேர்கிறது. இது முகமூடியை ஆன் செய்யாது: அது இன்னும் `PII_REDACTION_ENABLED` (கோரிக்கை) மற்றும் `PII_RESPONSE_SANITIZATION` (பதில் + SSE), இரண்டும் முன்னிருப்பாக முடக்கப்பட்டுள்ளன.

- **ஒவ்வொரு வகை தேர்வு** — உள்ளமைக்கப்பட்ட ஐடிகள் `src/shared/constants/piiTypes.ts` (`PII_BUILTIN_TYPES`) இல் பட்டியலிடப்பட்டுள்ளன. அமைக்கப்படாதது என்பது ஒவ்வொரு வகை (இந்த அமைப்பிற்கு முந்தைய நடத்தை) கோரிக்கை இயந்திரத்தின் `ssn_us` வடிவமானது `ssn` க்கு வரைபடமாக்குகிறது. டெம்ப்ளேட்கள் (குறைந்தபட்ச, நிலையான, நிதி, பிரேசிலியன், USA, GDPR, POPIA, முழு) UI இல் உள்ள தேர்வுப்பெட்டிகளை மட்டுமே நிரப்பும்.
- **GDPR மற்றும் POPIA அடையாளங்காட்டிகள்** — பன்னிரண்டு உள்ளமைக்கப்பட்ட ஐடிகள் EU மற்றும் தென்னாப்பிரிக்க தனிப்பட்ட அடையாளங்காட்டிகளை உள்ளடக்கியது (கீழே உள்ள அட்டவணை). அவற்றின் ரீஜெக்ஸ்கள், வேலிடேட்டர்கள் மற்றும் அதிகார வரம்பு குறிச்சொற்கள் ஒரே டேபிளில் வாழ்கின்றன, `src/shared/utils/piiPatterns.ts`, இவை ரெஸ்பான்ஸ் சானிடைசர் (`src/lib/piiSanitizer.ts`) மற்றும் கோரிக்கை முகமூடி (`src/shared/utils/inputSanitizer.ts`) ஆகிய இரண்டும் உட்கொள்ளும். ஒரு பொருத்தம் அதன் மதிப்பீட்டாளர் அதை ஏற்றுக்கொண்டால் மட்டுமே திருத்தப்படும்; வெறும் இலக்கங்கள் மட்டும் போதாது. இந்த ஐடிகள் இருப்பதற்கு முன்பு ஒரு குறுகலான தேர்வைச் சேமித்த ஒரு ஆபரேட்டர், புதிய ஐடிகள் டிக் செய்யப்படும் வரை அதன் நடத்தையை வைத்திருக்கிறார்.
- **விருப்ப வடிவங்கள்** — வரை 20 regex அல்லது வைல்டு கார்டு வடிவங்கள் (`*` = வரை 64 வைட்ஸ்பேஸ் அல்லாத எழுத்துக்கள், `?` = ஒன்று). போட்டிகள் `[CUSTOM_REDACTED]` ஆக மாறும். ஒவ்வொரு வடிவமும் `compilePiiCustomPattern()` (`src/shared/utils/piiCustomPatterns.ts`) வழியாக செல்கிறது: அதிகபட்சம் 500 எழுத்துகள், `g i m s u` க்கு மட்டுப்படுத்தப்பட்ட கொடிகள், தொகுக்க வேண்டும், `safe-regex` (பேரழிவு பின்னடைவு) கடந்து செல்ல வேண்டும், மேலும் வெற்று சரம் அல்லது ரிடாக்ஷன் பிளேஸ்ஹோல்டருடன் பொருந்தக்கூடாது. சேமிக்கப்படும் போது மற்றும் சோதிக்கப்படும் போது தோல்வியடையும் ஒரு முறை நிராகரிக்கப்படுகிறது, மேலும் தோல்வியடைந்த ஒரு சேமிக்கப்பட்ட வரிசை தொகுக்கப்படுவதற்குப் பதிலாக இயக்க நேரத்தில் தவிர்க்கப்படும். முகமூடி இயக்கத்தில் இருக்கும்போது மட்டுமே தனிப்பயன் வடிவங்கள் இயங்கும்.
- **கண்டறிதல் கவுண்டர்கள்** — per-type எண்ணிக்கைகள் (ஒருபோதும் பொருந்தாத மதிப்புகள்), நினைவகத்தில் வைக்கப்பட்டு மறுதொடக்கம் செய்யும்போது மீட்டமைக்கப்படும் (`src/lib/pii/piiDetectionStats.ts`). முகமூடி இயக்கத்தில் இருக்கும்போது மட்டுமே அவை அதிகரிக்கும்.

அமைப்புகள் `key_value` அட்டவணையில் உள்ளன (பெயர்வெளி `pii_settings`, `src/lib/db/piiSettings.ts`) மற்றும் 1 s கேச் மூலம் படிக்கப்படும். API:

| முறை   | பாதை                     | நோக்கம்                                                                                 |
| ------ | ------------------------ | --------------------------------------------------------------------------------------- |
| `GET`  | `/api/settings/pii`      | கொடி நிலை, `enabledTypes`, `customPatterns`, கண்டறிதல் கவுண்டர்கள்                      |
| `PUT`  | `/api/settings/pii`      | `enabledTypes` (`null` = all) and/or `customPatterns` ஐ மாற்றவும்                       |
| `POST` | `/api/settings/pii/test` | அதிகபட்சம் 8 KB மாதிரிக்கு எதிராக ஒரு மாதிரியை உலர வைக்கவும்; எதுவும் சேமிக்கப்படவில்லை |

மூன்றுக்கும் நிர்வாக அங்கீகாரம் தேவை மற்றும் உடலை Zod (`src/shared/validation/schemas/piiSettings.ts`) மூலம் சரிபார்க்க வேண்டும். உள்நுழைவு முடக்கப்பட்ட நிலையில் (`requireLogin=false`) `GET` மற்றும் சோதனை முடிவுப் புள்ளி திறந்திருக்கும், ஆனால் `PUT` இன்னும் ஒரு டாஷ்போர்டு அமர்வு, `manage` -scope API விசை, எழுதும் ஸ்கோப் அல்லது அதற்கு மேற்பட்ட `oma_` அணுகல் டோக்கன் அல்லது லூப்பேக்கிலிருந்து அனுப்பப்பட்ட CLI டோக்கன் அல்லது உள்-சேவை டோக்கன் தேவை.

### உடனடி ஊசி (`promptInjection.ts`)

பயனர் வழங்கிய உள்ளடக்கத்தில் எதிர்மறையான கட்டமைப்புகளைக் கண்டறிந்து, உள்ளமைக்கப்பட்ட கொள்கையைச் செயல்படுத்துகிறது. நடத்தை சூழல் மாறிகள் மற்றும் கட்டமைப்பாளர் விருப்பங்களால் இயக்கப்படுகிறது:

| அமைத்தல்      | Env var                                                                                                   | இயல்புநிலை | விளைவு                                                                                                                                                                                                                       |
| ------------- | --------------------------------------------------------------------------------------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| இயக்கப்பட்டது | `INPUT_SANITIZER_ENABLED`                                                                                 | `true`     | போது `false`, கார்ட்ரெயில் குறுகிய சுற்றுகள்.                                                                                                                                                                                |
| பயன்முறை      | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                           | `warn`     | ஊசி கொள்கை: `block`, `warn`, அல்லது `log`. (பேக்-காம்பாட்க்கு`redact` ஏற்றுக்கொள்ளப்படுகிறது, ஆனால் செய்கிறது** இல்லை** துண்டு ஊசி உரை; கோரிக்கை PII மீண்டும் எழுதுவது `PII_REDACTION_ENABLED` ஆல் கட்டுப்படுத்தப்படுகிறது.) |
| தொகுதி வாசல்  | `blockThreshold` விருப்பம் / `INPUT_SANITIZER_BLOCK_THRESHOLD` (மாற்று `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`     | தடுக்க குறைந்தபட்ச தீவிரத்தன்மை தேவை. இயல்புநிலையில் மீடியம் கவனிக்க மட்டுமே.                                                                                                                                                |

**முறை முன்னுரிமை** (`getMode`): அழைப்பவர் `options.mode` → `INJECTION_GUARD_MODE`**DB அம்சம்-கொடி மேலெழுதல்** (டாஷ்போர்டு → அமைப்புகள் → அம்சக் கொடிகள்) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env → `warn`. ஒரு டாஷ்போர்டு மேலெழுதுதல் env vars மீது வெற்றி பெறுகிறது, எனவே அம்சக் கொடிகள் UI இயங்கும் காவலரை நேரலையில் கட்டுப்படுத்துகிறது (மறுதொடக்கம் இல்லை). DB ரீட் தோல்வி-பாதுகாப்பானது: அது பிழைகள் ஏற்பட்டால், காவலர் env-அடிப்படையிலான நடத்தைக்குத் திரும்புவார், மேலும் மேலெழுதப்படாவிட்டால் நடத்தை env-மட்டும் தீர்மானத்திற்கு ஒத்ததாக இருக்கும்.

கண்டறிதல் ஆதாரங்கள்:

1. `@/shared/utils/inputSanitizer` இலிருந்து`sanitizeRequest()` (பைப்லைனில் வேறு இடங்களில் பயன்படுத்தப்படும் பகிரப்பட்ட கண்டறிதல் தொகுப்பு).
2. உள்ளமைக்கப்பட்ட `DEFAULT_GUARD_PATTERNS` (தற்போது `system_override_inline` மற்றும் `markdown_system_block`, இரண்டும் `high` தீவிரம்).
3. விருப்ப `customPatterns` கன்ஸ்ட்ரக்டர் விருப்பங்கள் (ஸ்ட்ரிங்க்ஸ், ரீஜெக்ஸ் அல்லது `{ name, pattern, severity }` பதிவுகள்) வழியாக அனுப்பப்பட்டது.

போது `mode === "block"`** மற்றும்** குறைந்தபட்சம் ஒரு கண்டறிதல் தீவிர வரம்பை சந்திக்கிறது, `preCall` `{ block: true, message: "Request rejected: suspicious content detected" }` ஐ வழங்குகிறது. `warn`/`log` முறைகளில் காவலர் பதிவுகள் ஆனால் அழைப்பை அனுமதிக்கிறது. பகிரப்பட்ட உதவியாளர் `evaluatePromptInjection()` ஆனது, பதிவேட்டில் செல்லாமலேயே அறிவுறுத்தல்களை மதிப்பீடு செய்ய வேண்டிய அழைப்பாளர்களுக்காகவும் ஏற்றுமதி செய்யப்படுகிறது.

**ஸ்கேன் பிணைப்பு (v3.8.20):** டிடெக்டர் மட்டுமே ஆய்வு செய்கிறது** முதல் 16 KB** `src/shared/utils/inputSanitizer.ts` இல் இணைந்த உடனடி உரை — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 பைட்டுகள்) . பேட்டர்ன் லூப்பை இயக்கும் முன் `detectInjection()` மற்றும் `evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` இரண்டும். உட்செலுத்துதல் வழிமுறைகள் உள்ளீட்டின் மேற்பகுதியில் அமர்ந்திருக்கும், எனவே இது பல நூறு-கேபி பேலோடுகளில் ரீஜெக்ஸ் CPU/GC கண்டறியும் பலவீனமடையாமல் (cf. #3932, #4041).

### நற்சான்றிதழ் முகமூடி (`credentialMasker.ts`)

இயங்குகிறது** இரண்டும்** நிலைகள், இயல்புநிலை சங்கிலியில் கடைசியாக (முன்னுரிமை `95`). வெளிச்செல்லும் பேலோடில் இருந்து நன்கு அறியப்பட்ட API-விசை / ரகசிய-டோக்கன் வடிவங்களைச் செதுக்குகிறது (செய்தி உள்ளடக்கம், கருவி-அழைப்பு வாதங்கள், கருவி முடிவுகள்)** மற்றும்** வழங்குநரின் பதில், எனவே ஒரு ப்ராம்ட்டில் ஒட்டப்பட்ட நற்சான்றிதழ் (அல்லது ஒரு கருவி முடிவு மூலம் எதிரொலிக்கப்பட்டது) அப்ஸ்ட்ரீம் வழங்குநருக்கு அல்லது கிளையண்டிற்குத் திரும்பக் கசிந்துவிடாது.

- **தேர்வு மட்டும்** , PII redaction போன்ற அதே மரபு (கடினமான விதி #20-அருகிலுள்ள): `settings.credentialRedactionEnabled === true` இல்லாவிட்டால் முடக்கப்பட்டது** அல்லது** `CREDENTIAL_REDACTION_ENABLED=true` அதை முடக்கினால், காவலர் தடையற்ற — இது ஒருபோதும் தடுக்காது மற்றும் மீண்டும் எழுதாது.
- `redactCredentials()` முழு payload/response மரத்தை (`walkValue()`, முன்மாதிரி-மாசு-பாதுகாப்பானது, சுழற்சி-பாதுகாப்பானது `WeakSet` வழியாக) நடந்து, போட்டிகளை `[REDACTED:<type>]` ஒதுக்கிடத்துடன் மாற்றுகிறது, உண்மையில் மாறிய கிளைகளை மட்டும் குளோனிங் செய்கிறது.
- `CREDENTIAL_PATTERNS` உள்ளடக்கியது LLM வழங்குநர் விசைகள் (OpenAI, OpenAI-proj, Anthropic, Google, கட்டிப்பிடிக்கும் முகம், பிரதி), VCS/SaaS டோக்கன்கள் (GitHub, Slack, லீனியர், Notion, npm, போஸ்ட்மேன், Discord), க்ளவுட் விசைகள், விசைகள், விசைகள்AWS, SendGrid, Mailgun), தனிப்பட்ட விசைகள் / JWTs, நற்சான்றிதழ்-தாங்கி இணைப்பு சரங்கள் (`mongodb://user:pass@...`, முதலியன), மற்றும் ஒரு பொதுவான `Authorization`/`x-api-key`/`api-key`/`apikey` தலைப்பு-மதிப்பு முறை. ஹெடர் வடிவ விசைகள் (`authorization`, `x-api-key`, `api-key`, `apikey`) பொதுவான உரை ரீஜெக்ஸ் வழியாக இல்லாமல் கட்டமைப்பு ரீதியாக (மதிப்பு மட்டும், `Bearer `/`Basic ` பாதுகாக்கப்பட்ட திட்ட முன்னொட்டு) மாற்றியமைக்கப்படுகின்றன.
- காவலரண் ஒருபோதும் தடுப்பதில்லை; அது மீண்டும் எழுதும் (`modifiedPayload` / `modifiedResponse`) மற்றும் சிறுகுறிப்பு (`meta.credentialsRedacted`, `meta.count`) மட்டுமே.

பின்னடைவு காவலர்: `tests/unit/credential-masker-guardrail.test.ts`.

## அடிப்படை ஒப்பந்தம் (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true எனில் சங்கிலி உடனே நிறுத்தப்படும்
  message?: string; // தடுக்கும்போது வெளிக்காட்டப்படும்
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // கோரிக்கையை மீளெழுத preCall திருப்பியனுப்புகிறது
  modifiedResponse?: TValue; // பதிலை மீளெழுத postCall திருப்பியனுப்புகிறது
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ஒரு guardrail `void`, `{}`, அல்லது `{ block: false }` ஆகியவற்றில் ஏதேனும் ஒன்றைத் திருப்பியனுப்புவதன் மூலம் "மாற்றமில்லை" என்பதைக் குறிக்கிறது. `modifiedPayload`/`modifiedResponse` திருப்பியனுப்புவது, downstream guardrail-களுக்குச் சங்கிலி வழியாகப் பாயும் மதிப்பை மாற்றியமைக்கிறது. `signal?: AbortSignal` அழைப்பாளரின் lifecycle-ஐ guardrail-களுக்குள் கொண்டு செல்கிறது. கோரிக்கை abort என்பது வேண்டுமென்றே விதிக்கப்பட்ட fail-open விதிவிலக்கு: media bridge-கள் வேலையை நிறுத்தி, அதை ஆதரிக்காது என அறியப்பட்ட இலக்குக்கு மூல (raw) media-வை மீட்டமைக்காமல் சுத்தம் செய்கின்றன.

## பதிவேடு (`registry.ts`)

`guardrailRegistry` singleton பின்வருவனவற்றை வெளிப்படுத்துகிறது:

- `register(guardrail)` — ஒரு guardrail-ஐச் சேர்க்கிறது (அல்லது இயல்பாக்கப்பட்ட பெயரால் மாற்றுகிறது), மேலும் ஏறுவரிசை `priority`-படி மீண்டும் வரிசைப்படுத்துகிறது.
- `clear()` / `list()` — நிர்வாக உதவிகள்.
- `runPreCallHooks(payload, context)` — செயலிலுள்ள guardrail-கள் வழியே சென்று, payload-ஐ `modifiedPayload` மூலம் தொடர்ச்சியாக அனுப்பி, முதல் `block: true`-இல் நிற்கிறது.
- `runPostCallHooks(response, context)` — response பக்கத்திலும் அதே ஓட்டம்.
- `resetGuardrailsForTests({ registerDefaults })` — நிலையை அழித்து, சுத்தமான test தனிமைக்காக விருப்பமானால் இயல்புநிலைகளை மீண்டும் பதிவு செய்கிறது.

இரு runner-களும் `{ blocked, payload|response, results, guardrail?, message? }` ஐத் திருப்பியனுப்புகின்றன; இங்கு `results` என்பது guardrail தோறும் `blocked`, `skipped`, `modified`, `error`, மற்றும் `meta` புலங்களைக் கொண்ட `GuardrailExecutionResult` பதிவுகளின் array ஆகும் — இது tracing-க்குப் பயனுள்ளதாக உள்ளது.

### ஒவ்வொரு கோரிக்கைக்கும் Guardrail-களை முடக்குதல்

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` தற்போதைய கோரிக்கைக்குத் தவிர்க்கப்பட வேண்டிய guardrail பெயர்களின் நகல்-நீக்கப்பட்ட பட்டியலை ஒன்றுபடுத்துகிறது. ஐந்து வழிகள் (channels) உள்ளன; அவை இந்த வரிசையில் படிக்கப்பட்டு ஒரே பட்டியலில் இணைக்கப்படுகின்றன (நகல் நீக்கும்போது முதன்முதலில் தோன்றியதே நிலைக்கும்):

1. `apiKeyInfo.disabledGuardrails`
2. கோரிக்கை body `disabledGuardrails` (மேல்-நிலை)
3. கோரிக்கை body `metadata.disabledGuardrails` (`metadata` ஒரு object ஆக இருக்கும்போது மட்டுமே)
4. Header `x-omniroute-disabled-guardrails`
5. பழமையான (legacy) header `x-disabled-guardrails`

ஐந்து வழிகளும் — இரண்டு header-களும் உட்பட — இணைக்கப்படுகின்றன: `x-omniroute-disabled-guardrails` மற்றும் `x-disabled-guardrails` இரண்டையும் அனுப்பினால், அவற்றின் பட்டியல்களின் ஒன்றிப்பு தவிர்க்கப்படும்; மேலும் வெற்று நவீன header இனி பழமையானதை மறைக்காது
([#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412),
[#16805](https://github.com/diegosouzapw/OmniRoute/pull/16805)-இல் சரிசெய்யப்பட்டது).

மதிப்புகள் string-களின் array-களாகவோ அல்லது கமாவால் பிரிக்கப்பட்ட string-ஆகவோ இருக்கலாம்; பெயர்கள் trim செய்யப்பட்டு சிற்றெழுத்து kebab-case-க்கு இயல்பாக்கப்படுகின்றன (`pii_masker` → `pii-masker`), வெற்று உள்ளீடுகள் கைவிடப்படுகின்றன. இதன் விளைவு `context.disabledGuardrails` வழியாக பதிவேட்டிற்கு அனுப்பப்படுகிறது; பதிவேடு பொருந்தும் guardrail-களைத் தவிர்க்கிறது (`results`-இல் `skipped: true`).

முடக்குப் பட்டியல் **பதிவேட்டை** மட்டுமே பாதிக்கிறது. Prompt-injection `block` பயன்முறை ஒரு கட்டாய எல்லை: injection-guard middleware
(`src/middleware/promptInjectionGuard.ts`) எந்த அழைப்பாளர்-கட்டுப்பாட்டு முடக்குப் பட்டியலும் இன்றி `evaluatePromptInjection()`-ஐ அழைக்கிறது (அது முன்பு செய்துவந்த செயலற்ற
`resolveDisabledGuardrails({ body })` அழைப்பு
[#16934](https://github.com/diegosouzapw/OmniRoute/pull/16934)-இல் நீக்கப்பட்டது), எனவே `prompt-injection`-ஐ முடக்கும் கோரிக்கைக்கூட `block` பயன்முறையில் இன்னும் நிராகரிக்கப்படுகிறது. இது வேண்டுமென்றே அப்படி வடிவமைக்கப்பட்டது. முடக்கு வழிகள் அழைப்பாளரின் கட்டுப்பாட்டில் உள்ளன (கோரிக்கை body, metadata, headers); operator அமைத்த பாதுகாப்புக் கட்டுப்பாட்டை அழைப்பாளரால் அணைக்க முடியாதிருக்க வேண்டும்
([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)).
[#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412)-இன் header ஒன்றிப்பு எந்த பதிவேட்டு guardrail-கள் தவிர்க்கப்படுகின்றன என்பதை மட்டுமே மாற்றுகிறது; அது client-ஐ middleware-ஐத் தாண்டிச் செல்ல அனுமதிக்காது. key தோறும் மற்றும் group தோறும் கட்டாய guardrail கொள்கைகள் v4 RFC [#16417](https://github.com/diegosouzapw/OmniRoute/issues/16417)-இல் கண்காணிக்கப்படுகின்றன.
[கவரேஜ் மற்றும் வரம்புகள்](#coverage-and-limits) ஐப் பார்க்கவும்.

## மரணதண்டனை உத்தரவு

`src/sse/handlers/chat.ts` மற்றும் `open-sse/handlers/chatCore.ts` வழியாக வரும் ஒவ்வொரு கோரிக்கைக்கும் ( [கவரேஜ் மற்றும் வரம்புகளின்](#coverage-and-limits) கீழ் பட்டியலிடப்பட்டுள்ள அரட்டை-குடும்ப வழிகள்):

1. `resolveDisabledGuardrails(...)` API விசை, உடல் மற்றும் தலைப்புகளிலிருந்து தவிர்க்கும் பட்டியலை உருவாக்குகிறது.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` கார்ட்ரெயில்களை ஏறுவரிசையில் முன்னுரிமை வரிசையில் இயக்குகிறது:
   - முடக்கப்பட்ட காவலர்கள் `skipped` என பதிவு செய்யப்படுகின்றன.
   - ஒவ்வொரு காவலரின் `preCall` `modifiedPayload` வழியாக பேலோடை மீண்டும் எழுதலாம்.
   - முதல் `block: true` சங்கிலியை குறுகிய சுற்றுகள் மற்றும் கையாளுபவர் ஒரு காவலர் நிராகரிப்பு பதிலைத் தருகிறார்.
3. (திரும்ப எழுதப்பட்ட) பேலோட் காம்போ ரூட்டிங் மற்றும் அப்ஸ்ட்ரீம் டிஸ்பாட்ச் ஆகியவற்றில் பாய்கிறது.
4. **ஸ்ட்ரீமிங் அல்லாதவை மட்டும்:** பதில் கூடிய பிறகு, `guardrailRegistry.runPostCallHooks(...)` பதிலில் அதே சங்கிலியை இயக்குகிறது. `block: true` இங்கே அப்ஸ்ட்ரீம் பதிலைக் குறைத்து HTTP 400 ஐ வழங்குகிறது. ஸ்ட்ரீம் செய்யப்பட்ட பதில்கள் இந்தப் படியை முழுவதுமாகத் தவிர்க்கின்றன.
5. **மீளக்கூடிய பெட்டகம் மட்டும்:** கோரிக்கை டோக்கன்களை அச்சிடும்போது, அழைப்புக்குப் பிந்தைய கொக்கிகள் மற்றும் ஸ்ட்ரீமிங் PII மாற்றத்திற்குப் பிறகு, `handleChat` 2xx மறுமொழியில் அவற்றை மீட்டெடுக்கிறது, எனவே `PII_RESPONSE_SANITIZATION` டோக்கன்கள் மற்றும் மாதிரி-உருவாக்கப்பட்ட PII ஐப் பார்க்கிறது, இது ஒருபோதும் அசல் அல்ல.

எறியும் காவலர்கள் `error: <message>` உடன் பதிவுசெய்யப்பட்டு `logger.warn` வழியாக உள்நுழையப்படும், ஆனால் சங்கிலியானது — தோல்வியைத் திறக்கும் வடிவமைப்பில் தொடர்கிறது.

### என்ன மறைக்கப்படவில்லை

- **மீடியா, உட்பொதிப்புகள் மற்றும் தரவு வழிகள்** (`/v1/images/*`, `/v1/embeddings`, `/v1/audio/*`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/rerank`, `/v1/search`, `/v1/moderations`) பதிவேட்டை எப்பொழுதும் சென்றடையாது. PII மாஸ்க்கிங், நற்சான்றிதழ் மறைத்தல் அல்லது மாடலிட்டி பிரிட்ஜ் எதுவும் அங்கு இயங்காது. அவர்களின் ஒரே காசோலை மரபு ஊசி-பாதுகாவலர் மிடில்வேர் ஆகும்.
- **ஸ்ட்ரீம் செய்யப்பட்ட பதில்கள்** அழைப்புக்குப் பிந்தைய பாதுகாப்புக் கம்பிகளைப் பெற வேண்டாம்: `pii-masker` அல்லது `credential-masker` போஸ்ட் கால் இல்லை, மேலும் அழைப்புக்குப் பிந்தைய தடை இல்லை. ஸ்ட்ரீமிங் PII உருமாற்றம் மட்டுமே பொருந்தும் ( `PII_RESPONSE_SANITIZATION` இயக்கத்தில் இருக்கும் போது). ஸ்ட்ரீம் செய்யப்பட்ட பதிலில் மீண்டும் எதிரொலிக்கப்பட்ட நற்சான்றிதழ் மாற்றியமைக்கப்படவில்லை.
- **சேனல்களுக்கு எதிராக மிடில்வேரை முடக்கு (வடிவமைப்பு மூலம்):** மிடில்வேர் `evaluatePromptInjection()` க்கு அதன் சொந்த அழைப்பின் மூலம் உடனடி ஊசியை மதிப்பிடுகிறது, எந்த அழைப்பாளரால் கட்டுப்படுத்தப்படும் முடக்கப்பட்ட பட்டியலையும் கடந்து செல்லாமல். `block` பயன்முறை என்பது அரட்டை-குடும்ப வழிகள் ( [#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413) ) உட்பட அழைப்பாளரால் கட்டுப்படுத்தப்படும் முடக்கங்களால் புறக்கணிக்க முடியாத ஒரு கட்டாய எல்லையாகும். `prompt-injection` முடக்கினால், பதிவேடு காவலரை மட்டும் தவிர்க்கலாம்.

### போஸ்ட்-அழைப்புக்கு முன் என்ன பதில் வரும்

ஸ்ட்ரீமிங் அல்லாத பாதையில் வரிசை: நினைவகப் பிரித்தெடுத்தல் → உள்ளமைக்கப்பட்ட கருவி செயல்படுத்தல் → போஸ்ட்-கால் கார்ட்ரெயில்ஸ் → போஸ்ட்-கால் பிளாக் எக்சிட் → செமாண்டிக்-கேச் ஸ்டோர்.

- **நினைவக பிரித்தெடுத்தல்** மற்றும்** கருவி செயல்படுத்தல்** அழைப்புக்குப் பிந்தைய காவலர்கள் அதை மீண்டும் எழுத அல்லது தடுக்கும் முன் பதிலைப் பார்க்கவும். [#16401](https://github.com/diegosouzapw/OmniRoute/pull/16401) இலிருந்து, `PII_RESPONSE_SANITIZATION` இயக்கத்தில் இருக்கும்போது (ஸ்ட்ரீமிங் மற்றும் ஸ்ட்ரீமிங் அல்லாத இரண்டும்) பிரித்தெடுக்கப்பட்ட உரையை `sanitizePII` மூலம் நினைவகப் பிரித்தெடுத்தல் இயக்குகிறது, ஆனால் பிந்தைய அழைப்புத் தொகுதிகள் நினைவகம் மற்றும் கருவிகளுக்கு இன்னும் வழங்கப்படுகின்றன.
- **சொற்பொருள் கேச்** பிந்தைய அழைப்பிற்குப் பிறகு பதிலைச் சேமிக்கிறது, எனவே அது மீண்டும் எழுதப்பட்ட பதிலைச் சேமிக்கிறது, மேலும் தடுக்கப்பட்ட பதில் ஒருபோதும் தற்காலிகமாக சேமிக்கப்படாது. கேச் உள்ளீடுகள் ஒரு API விசைக்கு விசை.

உள்ளமைக்கப்பட்ட காவலரண்களால் வாசிக்கப்படும் சுற்றுச்சூழல் மாறிகள்:

| மாறி                                  | பயன்படுத்தியது             | விளைவு                                                                                                   |
| ------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------- |

மோடலிட்டி பிரிட்ஜ் காவலர்கள் இயக்க நேர கட்டமைப்பை DB-ஆதரவு அமைப்புகள் ஸ்டோரிலிருந்து (`getSettings()`) படிக்கின்றன, என்வி வார்ஸ் அல்ல. விஷனின் முதன்மை விசைகள் `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes` மற்றும் `modalityBridgeCacheMaxEntries`. பாரம்பரிய `visionBridge*` விசைகள் ஆவணப்படுத்தப்பட்ட ஒரு-சுழற்சி ரீட் ஃபால்பேக்காக மட்டுமே ஏற்றுக்கொள்ளப்படுகின்றன; டாஷ்போர்டு எழுதும் முதன்மை விசைகளைப் பயன்படுத்துகிறது. இயல்புநிலைகள் மற்றும் ஃபால்பேக் ரிசல்வர் `src/shared/constants/modalityBridgeDefaults.ts` இல் வாழ்கின்றன, மரபு மாறிலிகள் `src/shared/constants/visionBridgeDefaults.ts` இல் தக்கவைக்கப்படுகின்றன.

ஆடியோ `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout` மற்றும் `modalityBridgeAudioMaxClips` மற்றும் பகிரப்பட்ட `modalityBridgeCache*` அமைப்புகளைப் பயன்படுத்துகிறது. இந்த விசைகள் மாடலிட்டி பிரிட்ஜ் ஸ்கீமாவுடன் அறிமுகப்படுத்தப்பட்டதால், ஆடியோவில் லெகஸி-கீ ஃபால்பேக் இல்லை.

வீடியோ `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, மற்றும் `modalityBridgeVideoTimeout` மற்றும் பகிரப்பட்ட `modalityBridgeCache*` அமைப்புகளைப் பயன்படுத்துகிறது. FFmpeg/ffprobe என்பது விருப்ப இயக்க சார்புகள் மற்றும் சட்ட தலைப்புகள் தாமதம் மற்றும் மாதிரி விலையை சேர்க்கிறது என்பதால் இது முன்னிருப்பாக முடக்கப்பட்டுள்ளது.

## தனிப்பயன் கார்ட்ரெயில்கள்

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

படிகள்:

1. `BaseGuardrail`-ஐ நீட்டிக்கும் `src/lib/guardrails/myGuardrail.ts` ஐ உருவாக்கவும்.
2. `preCall` மற்றும்/அல்லது `postCall` ஐ செயலாக்கவும்.
3. இம்போர்ட் நேரத்தில் பதிவு செய்யவும் (`registerDefaultGuardrails`-இலிருந்து push செய்து) அல்லது
   ரன்டைமில் `guardrailRegistry.register(...)` ஐ அழைக்கவும் — ரெஜிஸ்ட்ரி அதே இயல்பாக்கப்பட்ட
   (normalized) பெயரைக் கொண்ட முந்தைய எந்த கார்ட்ரெயிலையும் மாற்றிவிடும்.
4. `tests/unit/`-இன் கீழ் டெஸ்டுகளைச் சேர்க்கவும் (தற்போதைய எடுத்துக்காட்டுகள்:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`).

## சோதனை

சோதனைகளுக்கு இடையில் அறியப்பட்ட நிலையிலிருந்து தொடங்க `resetGuardrailsForTests()` ஐப் பயன்படுத்தவும்.
வெற்று ரெஜிஸ்ட்ரியுடன் தொடங்கி, சோதனையில் உள்ள கார்ட்ரெயில்களை மட்டும் பதிவு செய்ய
`{ registerDefaults: false }` ஐ அனுப்பவும். Vision Bridge சார்பு செலுத்துதலை
(dependency injection) ஏற்கிறது (`deps.getSettings`, `deps.callVisionModel`); Audio Bridge
அமைப்புகள், திறன்கள், STT மாதிரி தேர்வு, நறுசான்றிதழ் சரிபார்ப்புகள் மற்றும்
படியெழுத்தல் (transcription) ஆகியவற்றுக்கான சமமான இடைவெளிகளை (seams) வெளிப்படுத்துகிறது.
எனவே சோதனைகள் DB அல்லது நெட்வொர்க் அணுகல் இல்லாமலேயே இரு ஓட்டங்களையும் சோதிக்க முடியும்.

  கட்டாய-பிரிட்ஜ் மாதிரி பட்டியல்
- `src/shared/constants/modalityBridgeDefaults.ts` — பகிரப்பட்ட Vision/Audio ரன்டைம் இயல்புநிலைகள்

## Injection-guard ரூட் கவரேஜ் & ரெட்-டீம் (Phase 8 · Block D)

Injection-guard (`createInjectionGuard` / `withInjectionGuard`) பயனர் ப்ராம்ட்டுகளை ஏற்கும்
அனைத்து ரூட்டுகளையும் உள்ளடக்குகிறது. இது `INJECTION_GUARD_MODE` ஐ மதிக்கிறது (இயல்புநிலை `warn` = லாக் மட்டும்;
`block` = HTTP 400 `SECURITY_001` திருப்புகிறது).

| வகை            | ரூட்டுகள்                                                                                                                                            | இயல்புநிலை முறை |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| உரை (தற்போதைய) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn            |
| ஜெனரேட்டிவ்    | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn            |
| தரவு           | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn            |

உரை பிரித்தெடுப்பு (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ஐ உள்ளடக்குகிறது.

**ரெட்-டீம் (இரவுநேர, `nightly-llm-security.yml`):** promptfoo ஒவ்வொரு ரூட்டும்
`INJECTION_GUARD_MODE=block`-இல் OWASP-LLM கார்பஸைத் தடுக்கிறது என்பதைச் சரிபார்க்கிறது; garak
ப்ரோபுகளை இயக்குகிறது (ரகசியம் இல்லையெனில் தவிர்க்கிறது). `moderations` நிலைத்தன்மைக்காகச்
சேர்க்கப்பட்டுள்ளது. Block முறை ஒரு கட்டாய எல்லை: `evaluatePromptInjection()`
மிடில்வேர் அனுப்பும் கோரிக்கை-வாரி முடக்கு பட்டியலைப் புறக்கணிக்கிறது, எனவே `disabledGuardrails`
ஒரு ரூட்டை அதிலிருந்து **விலக்காது** ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)).

இரவுநேர வொர்க்ஃப்ளோ (`.github/workflows/nightly-llm-security.yml`, cron + கைமுறை
dispatch) இரண்டு ஜாபுகளைக் கொண்டுள்ளது:

- **`promptfoo-guard` (தடுக்கும்)** — `INJECTION_GUARD_MODE=block` உடன்
  `promptfoo eval -c promptfooconfig.yaml` ஐ இயக்குகிறது. ஒவ்வொரு adversarial
  வழக்கும் (எ.கா. "ignore all previous instructions…", DAN-பாணி ஜெயில்பிரேக்குகள்)
  பதிலில் `error.code === "SECURITY_001"` இருப்பதை உறுதிப்படுத்துகிறது, அதாவது
  கார்டு உண்மையில் கோரிக்கையை நிராகரித்தது என்பதை.
- **`garak` (ஆலோசனை)** — உள்ளூர் OmniRoute நிகழ்வுக்கு எதிராக
  (`http://localhost:20128/v1`) garak `--probes promptinject,dan,leakreplay` ஐ இயக்குகிறது.
  வழங்குநர் ரகசியத்தால் (`PROMPTFOO_PROVIDER_KEY`) கட்டுப்படுத்தப்பட்டது; மென்மையாகத்
  தவிர்க்கிறது மற்றும் `|| true` பின்னொட்டுடன் உள்ளது, எனவே CI ஐ தோல்வியடையச்
  செய்யாமல் அறிக்கை செய்கிறது.

கார்டு ஹெல்பரின் கவரேஜ் (`createInjectionGuard` / `withInjectionGuard`)
ப்ராம்ட் சுமக்கும் ஒவ்வொரு `/v1` ரூட்டையும் உள்ளடக்குகிறது; ப்ராம்ட் உரை
`src/shared/utils/inputSanitizer.ts`-இல் உள்ள `extractMessageContents()` மூலம்
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`-இலிருந்து எடுக்கப்படுகிறது.
