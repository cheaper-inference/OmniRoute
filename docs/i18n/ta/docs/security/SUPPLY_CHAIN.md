OmniRoute ஆனது npm + Docker ஆர்ட்டிஃபேக்ட்களை வெளியிடுகிறது. இந்த கேட்கள் ஆதாரம், இன்வென்டரி (SBOM) மற்றும் CVE ஸ்கேனிங் ஆகியவற்றை வழங்குகின்றன, இவை அனைத்தும் OSS ஆகும், மேலும் வெளியீட்டு பணிப்பாய்வுகளில் இணைக்கப்பட்டுள்ளன.
**ஆலோசனை-முதன்மை** நிலைப்பாடு — அவை இப்போது புகாரளிக்கின்றன, முதல் பச்சை வெளியீட்டிற்குப் பிறகு தடுக்கும் நிலைக்கு உயர்த்துகின்றன.

| கேட்                | கருவி                                          | எங்கே                         | தடுக்கிறதா?                       | வெளியீடு                                      |
| ------------------- | ---------------------------------------------- | ----------------------------- | --------------------------------- | --------------------------------------------- |
| SLSA ஆதாரம் (npm)   | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | வெளியீடு தோல்வியுற்றால் மட்டுமே   | பேட்ஜ் npmjs / `npm audit signatures`         |
| SBOM npm            | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | உருவாக்கம் தோல்வியுற்றால் மட்டுமே | வெளியீட்டு சொத்து + ஆர்ட்டிஃபேக்ட்            |
| SBOM படம்           | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | ஆலோசனை                            | CycloneDX ஆர்ட்டிஃபேக்ட்                      |
| Trivy CVE (SARIF)   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | ஆலோசனை                            | SARIF (HIGH+CRITICAL) → பாதுகாப்பு தாவல்      |
| Trivy CRITICAL கேட் | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **தடுக்கும்**                     | சரிசெய்யக்கூடிய CRITICAL இல் `exit-code: '1'` |
| osv vulnCount       | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **தடுக்கும்**                     | ratchets `metrics.vulnCount` (திசை:கீழ்)      |
| OpenSSF Scorecard   | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | ஆலோசனை                            | SARIF → பாதுகாப்பு + பேட்ஜ்                   |

பட CVE ராட்செட் `docker-publish.yml` இல் **இரண்டு படிகளை** பயன்படுத்துகிறது: SARIF படி (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL ஐ பாதுகாப்பு தாவலில் தடுப்பு இல்லாமல் தெரியும் வகையில் வைத்திருக்கிறது; _CRITICAL கேட்_ படி (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) ஒரு CRITICAL CVE **சரிசெய்யக்கூடியதாக இருந்தால்** வெளியீட்டை தோல்வியடையச் செய்கிறது. `ignore-unfixed` ஆனது ஒரு பேஸ்-இமேஜ் CVE க்கு மேல்நிலை பேட்ச் இல்லாமல் வெளியீட்டைத் தடுப்பதைத் தடுக்கிறது.

## ⚠️ CVE மாறுபாடு (osv/Trivy தடுப்பு வாயில்கள்)

osv மற்றும் Trivy, சார்புகளை **தொடர்ந்து வளர்ந்துகொண்டிருக்கும்** CVE தரவுத்தளங்களுடன் ஒப்பிடுகின்றன. **எந்தச் சார்புகளையும் மாற்றாத** ஒரு PR கூட, ஏற்கனவே உள்ள ஒரு சார்பில் புதிய CVE வெளிப்படுத்தப்படுவதால் திடீரெனச் சிவப்பு நிலைக்குச் செல்லலாம் (osv: அளவிடப்பட்ட `vulnCount` > அடிப்படை அளவு; Trivy: image-இல் புதிதாகச் சரிசெய்யக்கூடிய CRITICAL பாதிப்பு). **இது தடுப்பு CVE வாயிலின் எதிர்பார்க்கப்படும் செயல்பாட்டு நடத்தை; தயாரிப்பின் பின்னடைவு அல்ல.**

புதிதாக வெளிப்படுத்தப்பட்ட CVE காரணமாக osv அல்லது Trivy சிவப்பு நிலைக்குச் செல்லும்போது, தீர்வு:

1. **பாதிக்கப்பட்ட சார்பின் பதிப்பை உயர்த்தவும்** (விரும்பத்தக்கது) — `package.json`-இல் உள்ள
   `overrides` (இடைநிலைச் சார்புகள்) வழியாகத் திருத்தப்பட்ட பதிப்புக்கு மேம்படுத்தவும் அல்லது திருத்தப்பட்ட அடிப்படையில் image-ஐ மீண்டும் உருவாக்கவும்.
2. **மேல்நிலைத் திருத்தம் எதுவும் இல்லை என்றால்:**
   - **osv:** `config/quality/quality-baseline.json`-இல் உள்ள `metrics.vulnCount`-ஐ மீண்டும் அடிப்படையாக அமைக்கவும்
     (`npm run quality:ratchet -- --update` பிரத்யேக வாயில்களை உள்ளடக்காது — நியாயப்படுத்தும் குறிப்பு + கண்காணிப்புச் சிக்கலுடன் மதிப்பைக்
     கைமுறையாகத் திருத்தவும், `direction:down`).
   - **Trivy:** நியாயப்படுத்தும் கருத்துரை + கண்காணிப்புச் சிக்கலுடன் `.trivyignore`-இல் ஓர் உள்ளீட்டைச் சேர்க்கவும்
     (ஒரு வரிக்கு ஒரு CVE-ID). திருத்தங்கள் இல்லாத CVE-களை `ignore-unfixed: true` ஏற்கனவே
     தானாகவே உள்ளடக்குகிறது.

தேவையான OSV செயல்பாடுகள் (`check:vuln-ratchet -- --ratchet`), ஸ்கேனர், அறிக்கை அல்லது அடிப்படை அளவைச் சரிபார்க்க முடியாதபோது
`INCOMPLETE` நிலையுடனும் வெளியேற்றக் குறியீடு 2 உடனும் பாதுகாப்பாகத் தோல்வியடைகின்றன.
அளவிடப்பட்ட பின்னடைவு வெளியேற்றக் குறியீடு 1-ஐ வழங்குகிறது. ஆலோசனைச் செயல்பாடு இன்னும் வெளியேற்றக் குறியீடு 0 உடன் `SKIP` எனப் புகாரளிக்கலாம்; இது சார்புகள் ஸ்கேனை வெற்றிகரமாகக் கடந்தன என்பதை உறுதிப்படுத்தாது. தடுப்பு
Trivy படிக்கும் வெற்றிகரமான அளவீடும் தேவைப்படுகிறது: கிடைக்காத கருவிகள், தோல்வியடைந்த பணிகள்
மற்றும் காணாமல் போன image ஆதாரம் ஆகியவற்றால் ஓர் image பாதிப்பற்றது எனச் சான்றளிக்க முடியாது.

## நீக்கப்பட்ட சார்பு அபாயம்

நிலையாகப் பதிப்பிடப்பட்ட promptfoo மேம்பாட்டுக் கருவியை மேம்படுத்திய பிறகு, மூல lockfile-இல் இனி `extract-zip` அல்லது அதற்கான சார்பு இணைப்பு இடம்பெறாது. இது #14482-இல் கண்காணிக்கப்பட்டு, முன்பு ஏற்றுக்கொள்ளப்பட்ட `promptfoo` → `@openai/codex-security` → `extract-zip` சங்கிலியை நீக்குகிறது.
`tests/unit/extract-zip-14482-exposure.test.ts`-இல் உள்ள பின்னடைவு சோதனைகள் அது மீண்டும் அறிமுகப்படுத்தப்படுவதை நிராகரிப்பதுடன், உற்பத்திக் குறியீட்டிலிருந்து அதை இறக்குமதி செய்வதற்கான தடையையும் தக்கவைக்கின்றன.

தற்போதைய சார்பு திருத்தம், இணக்கத்தன்மை மேலெழுதல்களை Azure identity-இன் MSAL client, get-uri-இன் FTP client மற்றும் OpenCode v1 SDK-இன் Zod சார்பு ஆகியவற்றுக்கு மட்டுப்படுத்துகிறது. Azure token பெறுதலும் FTP மீட்டெடுப்பும் கட்டுப்படுத்தப்பட்ட போக்குவரத்து வழிமுறைகளைக் கொண்டு சோதிக்கப்படுகின்றன; இரண்டு OpenCode package-களும் அவற்றின் சொந்த build மற்றும் test suite-களை இயக்குகின்றன. Registry advisory எண்ணிக்கைகள் ஒரு குறிப்பிட்ட நேரப் புள்ளியில் எடுக்கப்பட்ட அளவீடுகள் என்பதால், lockfile commit செய்யப்பட்ட பிறகு அவை மாறக்கூடும்.

## நிலுவையில்: ஸ்கோர்கார்டு ஆலோசனை → தடுப்பது

ஸ்கோர்கார்டு அறிக்கையுடன் முதல் பச்சை வெளியீட்டிற்குப் பிறகு:

- ஸ்கோர்கார்டு: ஸ்கோர் ராட்செட் (அளவிடப்பட்ட ஸ்கோரை உறைய வைக்கிறது; குறைக்க முடியாது).

கட்டம் 7 கேட்ஸை (osv-scanner, gitleaks, actionlint+zizmor) பூர்த்தி செய்கிறது: zizmor
பணிப்பாய்வுகளை தணிக்கை செய்கிறது; ஸ்கோர்கார்டு ஒட்டுமொத்தமாக ரெப்போ நிலையை அளவிடுகிறது.
