OmniRoute எதைக் கட்டுப்படுத்துகிறது**உலாவியின் தோற்றம்** ஒற்றை, மையப்படுத்தப்பட்ட அனுமதிப் பட்டியலில் இருந்து குறுக்கு மூல பதில்களைப் படிக்கலாம். மாதிரி உள்ளது**இயல்பாகவே தோல்வி-மூடப்பட்டது** : நீங்கள் ஒன்றைத் தேர்ந்தெடுக்கும் வரை எந்த தோற்றமும் அனுமதிக்கப்படாது. அனுமதிப்பட்டியல் எவ்வாறு தீர்க்கிறது, `CORS_ALLOW_ALL=true` உண்மையில் எதை வெளிப்படுத்துகிறது (மற்றும், முக்கியமாக, அது என்ன செய்கிறது என்பதை இந்தப் பக்கம் ஆவணப்படுத்துகிறது.**இல்லை** ), dev vs தயாரிப்பை எவ்வாறு பாதுகாப்பாக கட்டமைப்பது மற்றும் வைல்டு கார்டு நேரலையில் இருக்கும் போது டாஷ்போர்டின் இயக்க நேர எச்சரிக்கை காட்டுகிறது.

**உண்மையின் ஆதாரம்:** `src/server/cors/origins.ts` (`resolveAllowedOrigin`, `applyCorsHeaders`, `getCorsStatus`). அனுமதிப்பட்டியல் ஒருமுறை பயன்படுத்தப்படும், மிடில்வேரில் (`src/server/authz/pipeline.ts`) — ஒவ்வொரு-வழி கையாளுபவர்களும் `Access-Control-Allow-Origin` தாங்களாகவே அமைக்க மாட்டார்கள்.

## ஒரு தோற்றம் எவ்வாறு தீர்க்கப்படுகிறது

ஒவ்வொரு கோரிக்கைக்கும் மிடில்வேர் இந்த வரிசையில் `Access-Control-Allow-Origin` மதிப்பைக் கணக்கிடுகிறது:

1. **`CORS_ALLOW_ALL=true`** (அல்லது மரபு `CORS_ORIGIN=*`) → `Vary: Origin` உடன் அழைப்பாளரின் `Origin` பின்புறத்தை எதிரொலிக்கிறது (அல்லது `Origin` தலைப்பு இல்லாத போது `*` ), அதனால் தற்காலிக சேமிப்புகள் சரியாக இருக்கும். அதே `applyCorsHeaders()` சோக்பாயிண்ட், டோக்கன்-அங்கீகரிக்கப்பட்ட `/v1*`/`/v1beta*` மேற்பரப்பில் உள்ள ஒவ்வொரு 2xx-உடலுமான பதிலுடன் `Vary: Accept-Encoding` இணைக்கிறது (`relaxForTokenAuth`, RFC 9110 §12.5.5, #6737 வெளியீடு ), எனவே downstream/shared கேச்கள் சுருக்கப்பட்ட மாறுபாடுகள் மற்றும் சுருக்கப்பட்ட மாறுபாடுகளை சரியாக வேறுபடுத்தி அறியலாம்.
2. இல்லையெனில், `Origin` கோரிக்கை இயல்பாக்கப்பட்டது (குறைந்த-அடுக்கு, பின்னிணைப்பு ஸ்லாஷ் அகற்றப்பட்டது) மற்றும் அதற்கு எதிராகப் பொருத்தப்பட்டது**ஒன்றிணைக்கப்பட்ட அனுமதிப்பட்டியல்** :
   - env **`CORS_ALLOWED_ORIGINS`** — கமாவால் பிரிக்கப்பட்ட பட்டியல் மற்றும்
   - இயக்க நேரம்**`corsOrigins`** அமைப்பு (டாஷ்போர்டு → பாதுகாப்பு → _CORS அனுமதிக்கப்பட்ட தோற்றம்_), `src/lib/config/runtimeSettings.ts` இலிருந்து `setRuntimeAllowedOrigins()` வழியாக செலுத்தப்பட்டது.
3. → உடன் பொருந்தவில்லை**`Access-Control-Allow-Origin` தலைப்பு எதுவும் வெளியிடப்படவில்லை** . உலாவி குறுக்கு மூல வாசிப்பைத் தடுக்கிறது. இது திட்டமிடப்பட்ட தோல்வி-மூடப்பட்ட இயல்புநிலை.

| Env var                | பொருள்                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| `CORS_ALLOWED_ORIGINS` | அனுமதிக்கும் சரியான தோற்றத்தின்CSV (பரிந்துரைக்கப்படுகிறது).                                     |
| `CORS_ALLOW_ALL`       | `true`/`1` → எந்த மூலத்தையும் எதிரொலிக்கும் (வைல்டு கார்டு). தேவ் மட்டும்.                       |
| `CORS_ORIGIN`          | மரபு. `*` `CORS_ALLOW_ALL` போல் செயல்படுகிறது; அனுமதிப்பட்டியலில் ஒற்றை மதிப்பு சேர்க்கப்பட்டது. |

## அச்சுறுத்தல் மாதிரி — `CORS_ALLOW_ALL=true` உண்மையில் என்ன அம்பலப்படுத்துகிறது

பொதுவான OWASP எச்சரிக்கை ("வைல்டு கார்டு CORS = எந்த தளமும் உங்கள் API அழைக்கலாம்") தீவிரமாக எடுத்துக் கொள்ளத்தக்கது, ஆனால் OmniRoute இன் வெளிப்பாடு**பொதுவான வழக்கை விட குறுகியது** , ஒரு உறுதியான செயல்படுத்தல் உண்மையின் காரணமாக:

> **மத்திய `applyCorsHeaders()` ஒருபோதும் `Access-Control-Allow-Credentials` வெளியிடுவதில்லை.** சேவையகம் `Access-Control-Allow-Credentials: true` அனுப்பும் வரை, உலாவி _credentialed_ (குக்கீ-பேரிங்) குறுக்கு-ஆரிஜின் பதிலை வெளிப்படுத்தாது. OmniRoute இன் பகிரப்பட்ட CORS பாதை ஒருபோதும் செய்யாது.

`CORS_ALLOW_ALL=true` உடன் கூட, ஒரு மேற்பரப்புக்கு என்ன அர்த்தம்:

| மேற்பரப்பு                             | அங்கீகார பொறிமுறை                | வைல்டு கார்டு CORS இன் விளைவு                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| டாஷ்போர்டு / MANAGEMENT `/api/*`       | குக்கீ அமர்வு                    | தோற்றம் எதிரொலித்தது, ஆனால்**`Allow-Credentials` இல்லாமல்** உலாவி**தொகுதிகள்** அங்கீகாரம் பெற்ற வாசிப்பு. ஒரு தீங்கிழைக்கும் குறுக்கு தோற்றம் கொண்ட தளம்**படிக்க முடியாது** உங்கள் அங்கீகரிக்கப்பட்ட டாஷ்போர்டு பதில்கள், மற்றும் அமர்வு குக்கீ வெளிப்படவில்லை.                                                                                                                                                                                                                                                                                                               |
| கிளையண்ட் API `/v1/*`, `/v1beta/*`     | தாங்குபவர் / `x-api-key` தலைப்பு | ஏற்கனவே அனுமதிக்கப்பட்டது**வடிவமைப்பு மூலம்** (`relaxForTokenAuth`): உலாவிகள் ஒருபோதும் `Authorization`/`x-api-key` ஐ தானாக இணைக்காது, எனவே தாக்குபவர்களின் பக்கம் உங்கள் விசையை வழங்க முடியாது. தளர்வான எதிரொலிக்கு அங்கீகரிக்கப்பட்ட பொருள் (சரிபார்க்கப்பட்ட API விசை அல்லது டாஷ்போர்டு அமர்வு) தேவைப்படுகிறது, இது ஒரு நற்சான்றிதழ் தலைப்பு மட்டுமல்ல, `Access-Control-Allow-Credentials` உள்ளடக்காது. அநாமதேய பதில்கள் (`REQUIRE_API_KEY=false`) உள்ளமைக்கப்பட்ட மூல அனுமதிப் பட்டியலைப் பயன்படுத்துகின்றன, இதில் வெளிப்படையான `CORS_ALLOW_ALL=true` விருப்பம் அடங்கும். |
| பொது படிக்க மட்டும் (`/api/health`, …) | இல்லை                            | உணர்திறன் இல்லாதது; வைல்டு கார்டு பாதிப்பில்லாதது.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

எனவே தி**எஞ்சிய** `CORS_ALLOW_ALL=true` இன் வெளிப்பாடு வரம்புக்குட்பட்டது: (அ) நற்சான்றிதழ் இல்லாத குறுக்கு தோற்றம்**வாசிக்கிறார்** ஏற்கனவே அங்கீகரிக்கப்படாத தரவு, மற்றும் (b) CORS அனுமதிக்கும்**முன் விமான பாஸ்** நிர்வாக வழித்தடங்களில் — இன்னும் அங்கீகாரம் தேவைப்படுகிறது, இது குறுக்கு தோற்றம் பக்கம் வழங்க முடியாது. அது**இல்லை** பகிரப்பட்ட CORS பாதையில் ஒரு அமர்வு-ஹைஜாக் அல்லது நற்சான்றிதழ்-திருட்டு திசையன்.

### ஒரு உண்மையான விதிவிலக்கு — `/api/v1/agents/`

கிளவுட்-ஏஜென்ட் வழிகள் (`/api/v1/agents/{health,credentials,tasks,tasks/[id]}`) அவற்றை அமைக்கின்றன **சொந்தம்** CORS தலைப்புகள் (`src/lib/cloudAgent/api.ts`, `getCloudAgentCorsHeaders`) மற்றும்**செய்ய** `Access-Control-Allow-Credentials: true` உடன் `Access-Control-Allow-Origin: <origin>|*` வெளியிடுங்கள். தோற்றம்-எதிரொலி மற்றும் நற்சான்றிதழ்கள் இணைந்திருக்கும் ஒற்றை மேற்பரப்பு இதுவாகும்**`CORS_ALLOW_ALL` இல் இருந்து சுயாதீனமானது** . இந்த வழிகள் மேலாண்மை-அங்கீகரிக்கப்பட்டவை (`requireManagementAuth`); டேஷ்போர்டை ஆஃப்-ஹோஸ்ட்டை வெளிப்படுத்தும் ஆபரேட்டர்கள், பதில் தலைப்புகளால் கிராஸ்-ஆரிஜின் நற்சான்றிதழ் படிக்க அனுமதிக்கப்படும் இடம் இது என்பதை அறிந்திருக்க வேண்டும். இந்த CORS வழிகாட்டுதலில் இருந்து தனித்தனியாக ஒரு வெளிப்படையான அனுமதிப் பட்டியலில் அதை இறுக்குவது.

## உற்பத்தி சரிபார்ப்பு பட்டியல்

- **உற்பத்தியில் `CORS_ALLOW_ALL=true` அமைக்க வேண்டாம்.** அமைக்காமல் விட்டு விடுங்கள்.
- ஒரு அமைக்கவும்**வெளிப்படையான** தோற்றப் பட்டியல் — env var அல்லது Security-tab புலம்:

  ```bash
  CORS_ALLOWED_ORIGINS="https://app.example.com, https://admin.example.com"
  ```

- OmniRoute ஒரு ரிவர்ஸ் ப்ராக்ஸி / டன்னல் (nginx, Caddy, Cloudflare Tunnel, Tailscale) பின்னால் இயங்கினால், CORS**இல்லை** உங்கள் ஒரே கட்டுப்பாடு — லூப்பேக் ரூட் கார்டு இன்னும் ஸ்பான் திறன் கொண்ட வழிகளைப் பாதுகாக்கிறது (பார்க்க [ROUTE_GUARD_TIERS](./ROUTE_GUARD_TIERS.md) ). 403 ஐ "சரிசெய்ய" `X-Forwarded-For: 127.0.0.1` உருவாக்க வேண்டாம்; இது RCE வகுப்பை மீண்டும் திறக்கிறது, பாதை காவலர் மூடுகிறார்.
- இயக்க நேர நிலையை உறுதிசெய்க: டாஷ்போர்டு a காட்டுகிறது**நிலையான அம்பர் பேனர்** டாஷ்போர்டின் கீழ் → பாதுகாப்பு → அங்கீகரிப்பு சரக்கு `CORS_ALLOW_ALL=true` நேரலையில் இருக்கும் போது, `/api/settings/authz-inventory` ஒரு `cors: { allowAll, allowedOrigins }` உறை கண்காணிப்பு கருவிகளை வாக்களிக்க முடியும்.

## வளர்ச்சி வசதி — குறிப்பிட்ட உள்ளூர் மூலங்களை அனுமதிக்கிறது

dev இல் கூட உங்களுக்கு வைல்டு கார்டு அரிதாகவே தேவைப்படும். நீங்கள் பயன்படுத்தும் டெவ் சர்வர்களை மட்டும் அனுமதிக்கவும்:

```bash
# Vite (5173) + Next.js (3000) dev servers calling a local OmniRoute
CORS_ALLOWED_ORIGINS="http://localhost:5173, http://localhost:3000"
```

புறக்கணிக்கப்பட்ட பின்தங்கிய சாய்வுடன் தோற்றங்கள் கேஸ்-சென்சிட்டிவ் முறையில் பொருந்துகின்றன, எனவே `http://localhost:3000` மற்றும் `http://localhost:3000/` ஆகியவை சமமானவை. அதே CSV இயக்க நேரத்தில் அமைக்கலாம்**டாஷ்போர்டு → பாதுகாப்பு → CORS அனுமதிக்கப்பட்ட தோற்றம்** மறுதொடக்கம் இல்லாமல்.

## API விசைகள் vs குக்கீ அமர்வுகள்

- **தாங்குபவர் / `x-api-key` ( `/v1/*` அனுமான மேற்பரப்பு):** உலாவிகள் இவற்றை தானாக இணைக்கவே இல்லை. CORS என்பது இங்கே அர்த்தமுள்ள தடையாக இல்லை — API விசை என்பது — தடையாகும், அதனால்தான் அந்த மேற்பரப்பு வேண்டுமென்றே அனுமதிக்கப்படுகிறது, எனவே உலாவி மற்றும் Electron கிளையன்ட்கள் தங்களுக்கு ஏற்கனவே உரிமையுள்ள பதில்களைப் படிக்க முடியும். தளர்வான எதிரொலிக்கு அங்கீகரிக்கப்பட்ட பொருள் (சரிபார்க்கப்பட்ட API விசை அல்லது டாஷ்போர்டு அமர்வு) தேவைப்படுகிறது, இது ஒரு நற்சான்றிதழ் தலைப்பு மட்டுமல்ல, `Access-Control-Allow-Credentials` உள்ளடக்காது. அநாமதேய பதில்கள் (`REQUIRE_API_KEY=false`) உள்ளமைக்கப்பட்ட மூல அனுமதிப் பட்டியலைப் பயன்படுத்துகின்றன, இதில் வெளிப்படையான `CORS_ALLOW_ALL=true` தெரிவு அடங்கும். அங்கீகார நிராகரிப்புகள் (401) படிக்கக்கூடியதாக இருக்கும், இதனால் வாடிக்கையாளர்கள் ரத்து செய்யப்பட்ட அல்லது தவறாக தட்டச்சு செய்யப்பட்ட விசையை (#5242) வெளியிடலாம்: பைப்லைனின் சொந்த 401 எதிரொலியை வைத்திருக்கிறது, மேலும் பைப்லைன் அதை அநாமதேயமாக வழங்கிய பிறகு சாவியை மறுக்கும் ஒரு வழி (`/v1/models` மற்றும் `/v1beta/models` உடன் நிர்வாக அங்கீகாரம், `/v1/files`, `/v1/batches`, `/v1/media`, `/v1/session-leases` உள்ளமைக்கப்பட்ட. ஆட்டோ-காம்போ வேட்பாளர் வழிகள்) `credentialRejectionHeaders()` வழியாக அந்த 401 க்கு எதிரொலியைச் சேர்க்கிறது. நற்சான்றிதழ் தலைப்பு (`Authorization`, `x-api-key`, `x-goog-api-key` அல்லது `auth_token` குக்கீ) கொண்ட கோரிக்கையின் மீது எதிரொலி முக்கியப்படுத்தப்படுகிறது, அவற்றில் எந்த பாதை சரிபார்க்கப்பட்டது, `Access-Control-Allow-Credentials` உடன் இணைக்கப்படாது; உடல் ஒரு நிலையான பிழை உறை. `requireManagementAuth()` (`/api/v1/management/*`, `/api/v1/registered-keys`, `/api/v1/providers/[provider]/limits`, `/api/v1/accounts/[id]/limits`, `/api/v1/issues/report`) ஆல் பாதுகாக்கப்படும் `/api/v1/` இன் கீழ் மேலாண்மை வழிகள் இந்த நற்சான்றிதழ்-நிராகரிப்பு விதிவிலக்கைப் பயன்படுத்தாது: `REQUIRE_API_KEY=false` உடன், அவற்றின் 401/403 பதில்கள் உள்ளமைக்கப்பட்ட CORS மூலக் கொள்கையைப் பின்பற்றுகின்றன.
- **குக்கீ அமர்வு (டாஷ்போர்டு):** தோல்வி-மூடப்பட்ட இயல்புநிலை மூலம் பாதுகாக்கப்படுகிறது**மற்றும்** பகிரப்பட்ட பாதையில் `Access-Control-Allow-Credentials` இல்லாததால். management/dashboard ஆரிஜின்களை எந்த அனுமதிக்கும் கட்டமைப்புக்கு வெளியே வைத்திருங்கள்; அவை சரியாக மூடப்படாமல் இருக்க வேண்டும்.

## WebSocket ஹேண்ட்ஷேக்குகள் (`/v1/responses`, `/v1/ws`)

உலாவிகள் WebSocket க்கு CORS பயன்படுத்தாது, எனவே WebSocket டிரான்ஸ்போர்ட்கள் அனுமான வெளியீட்டை திரும்பப் பெறுகின்றன `Origin` கைகுலுக்கலைச் சரிபார்க்கிறது (`src/server/origin/wsOrigin.ts`): பதில்கள் WebSocket (`/v1/responses`) மற்றும், `npm start` / `npm run dev` வழியாக OmniRoute இயங்கும் போது, `/v1/ws` மற்றும் `/api/v1/ws` பிரிட்ஜ், `/v1/chat/completions`, `/v1/messages` மற்றும் `/v1/responses` என ஸ்ட்ரீம் செய்கிறது. பாலம் `/api/v1/ws?handshake=1` யிடம் தீர்ப்பைக் கேட்கிறது மற்றும் அந்த பாதை சோதனையை இயக்காத வரை மேம்படுத்த மறுக்கிறது. அங்கீகாரத் தேவைகள் இன்னும் தனித்தனியாக பொருந்தும். மூலச் சரிபார்ப்பு எப்போது கடந்து செல்கிறது:

- இதில் `Origin` தலைப்பு இல்லை (Codex CLI, SDKs மற்றும் பிற உலாவி அல்லாத கிளையண்டுகள்);
- `Origin` மேலே உள்ள அனுமதிப்பட்டியலால் அனுமதிக்கப்படுகிறது (`CORS_ALLOWED_ORIGINS`, `corsOrigins` அமைப்பு, `CORS_ORIGIN`, `CORS_ALLOW_ALL`);
- `Origin` என்பது OmniRoute யின் சொந்த பொது தோற்றங்களில் ஒன்றாகும் (கட்டமைக்கப்பட்ட பொது அடிப்படையான URL, நம்பகமான ப்ராக்ஸியின் அனுப்பப்பட்ட தோற்றம் அல்லது நேரடி loopback/LAN ஹோஸ்ட் IP எழுத்து அல்லது `localhost` — என கொடுக்கப்பட்ட அதே வேட்பாளர்களை டாஷ்போர்டு பிறழ்வு சரிபார்ப்பு பயன்படுத்துகிறது); அல்லது
- இது HTTP `/v1/*` மேற்பரப்பைப் போலவே சரியான API விசையைக் கொண்டுள்ளது.

வேறு எதுவும் `403 ws_origin_forbidden` பெறுகிறது. டாஷ்போர்டு அமர்வு குக்கீ வெளிநாட்டு `Origin` விலக்கு அளிக்காது, ஏனெனில் உலாவி அதை எந்த பக்கத்தின் சாக்கெட்டிலும் இணைக்கிறது. மற்றொரு போர்ட்டில் உள்ள `localhost` ஒரே தோற்றமாகக் கருதப்படுவதில்லை; `CORS_ALLOWED_ORIGINS` இல் அத்தகைய தேவ் மூலங்களைச் சேர்க்கவும்.

## எடுத்துக்காட்டு: OmniRoute க்கு முன்னால் உள்ள ரிவர்ஸ் ப்ராக்ஸி

CORS ஆனது OmniRoute ஆல் செயல்படுத்தப்படுகிறது, எனவே ப்ராக்ஸி பொதுவாக வேண்டும்**இல்லை** `Access-Control-*` தலைப்புகளைச் சேர்க்கவும் அல்லது மீண்டும் எழுதவும் (இரட்டை தலைப்புகள் உலாவிகளை உடைக்கும்). TLS முடித்துவிட்டு — முன்னோக்கி OmniRoute பதிலளிக்க அனுமதிக்கவும்:

```nginx
# nginx — forward to OmniRoute; do NOT inject Access-Control-* here
location / {
    proxy_pass http://127.0.0.1:20128;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    # Keep the forwarding headers: a proxy on the same host connects from loopback, and they are
    # what tells OmniRoute the caller is not the local operator. A proxy that adds none of them
    # makes every remote caller look local. Never set X-Forwarded-For to 127.0.0.1 either.
}
```

ப்ராக்ஸியில் இல்லாமல், OmniRoute (`CORS_ALLOWED_ORIGINS` அல்லது பாதுகாப்பு தாவலில்) அனுமதிக்கப்பட்ட உலாவி மூலங்களை அமைக்கவும்.
