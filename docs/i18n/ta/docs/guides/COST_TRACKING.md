## இது என்ன (மேலும் இது என்ன அல்ல)

டோக்கன்களின் எண்ணிக்கையை ஒரு மாதிரியின் விலை விகிதங்களால் பெருக்குவதன் மூலம் ஒவ்வொரு நிறைவுக்கும்
கோரிக்கை ஒன்றுக்கான USD செலவை OmniRoute ஒதுக்குகிறது. இந்த எண்கள் **செலவுகள்** டாஷ்போர்டு,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON ஏற்றுமதிகள் மற்றும் API விசை வாரியான வரவுசெலவுத் திட்டங்களை இயக்குகின்றன.

> **டாஷ்போர்டின் "செலவு" என்பது ஒரு சேமிப்புக் கண்காணிப்பான், கட்டணம் அல்ல.** OmniRoute உங்களிடம் ஒருபோதும் கட்டணம் வசூலிப்பதில்லை
> — நீங்கள் ஏற்கெனவே இணைத்துள்ள வழங்குநர்களுக்கு (உங்களுடைய சொந்த
> சந்தாக்கள், இலவச அடுக்குகள் மற்றும் API விசைகள்) உங்கள் கோரிக்கைகளை அது வழிமாற்றுகிறது. முழுவதும் இலவச
> மாதிரிகளில் சேர்ந்த "$290 மொத்தச் செலவு" என்பது, கட்டண API ஒன்றுக்கு நீங்கள் ஏறத்தாழ **$290 செலுத்தவில்லை** என்பதைக் குறிக்கிறது. அதே போக்குவரத்திற்கு நிலையான பட்டியல் விலைகளில் எவ்வளவு செலவாகியிருக்கும் என்பதற்கான _மதிப்பீடே_
> இந்த எண்ணாகும்; இதனால் உங்கள் பயன்பாடு எங்கு குவிந்துள்ளது என்பதையும், மலிவான/இலவச வழங்குநர்களுக்கு வழிமாற்றுவதன் மூலம் நீங்கள் எவ்வளவு சேமிக்கிறீர்கள் என்பதையும் பார்க்க முடியும்.

இந்தக் கருத்தாக்கம் திட்டத்தின் [README](../../README.md)-இல் நேரடியாகக் குறிப்பிடப்பட்டுள்ளது ("டாஷ்போர்டின்
'செலவு' என்பது ஒரு சேமிப்புக் கண்காணிப்பான், கட்டணம் அல்ல").

இந்த எண் ஒரு மதிப்பீடு என்பதால்:

- ஒவ்வொரு மாதிரிக்கும் OmniRoute வைத்துள்ள விலை அட்டவணையை இது சார்ந்துள்ளது. விலைப்
  பதிவு இல்லாத ஒரு மாதிரி `0` செலவைப் பங்களிக்கும் (ஆய்வியில் அது "மரபு / இலவசம்" வரிசையாகக் காட்டப்படும்).

  நீங்கள் சேமிக்கும் தொகையே தவிர, செலுத்த வேண்டிய தொகை அல்ல.

## செலவுகள் எவ்வாறு மதிப்பிடப்படுகின்றன

### விலை ஆதாரம்

இந்த முன்னுரிமை வரிசையில், [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) இல் இணைக்கப்பட்ட விலை அட்டவணையில் இருந்து செலவுகள் வருகின்றன (** மிக உயர்ந்த முதல்** ):

1. **பயனர் மேலெழுதுகிறார்** — விலைகள் டாஷ்போர்டில் அல்லது `PATCH /api/pricing` ( `pricing` பெயர்வெளி) வழியாக அமைக்கப்பட்டுள்ளன.
2. **models.dev ஒத்திசைவு** — விலை `https://models.dev/api.json` இலிருந்து பெறப்பட்டது ( `models_dev_pricing` பெயர்வெளி).
3. **LiteLLM ஒத்திசைவு** — விலைகள் LiteLLM இன் பொது `model_prices_and_context_window.json` ( `pricing_synced` பெயர்வெளி) இலிருந்து பெறப்பட்டது.
4. **ஹார்டுகோட் செய்யப்பட்ட இயல்புநிலைகள்** — விகிதங்கள் [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) இல் அனுப்பப்படுகின்றன.

அதே provider/model க்கு, அதிக முன்னுரிமை அடுக்குகளின் மதிப்புகள் கீழ் அடுக்குகளில் பொருந்தும் புலங்களை மேலெழுதும்; மேல் அடுக்கில் இல்லாத புலங்கள் இன்னும் கீழ் அடுக்கிலிருந்து வரலாம். இரண்டு சுயாதீன ஒத்திசைவு வேலைகளும் ஒரே நேரத்தில் இயங்கும் போது கூட ஒழுங்கு சரி செய்யப்படுகிறது. `GET /api/pricing?includeSources=1` `pricing` மற்றும் `sourceMap` வழங்குகிறது, அதன் மாதிரி லேபிள்கள் (`user`, `modelsDev`, `litellm`, `default`) அந்த மாதிரியைக் கொண்ட மிக உயர்ந்த முன்னுரிமை லேயரை அடையாளம் காணும்.

**LiteLLM ஒத்திசைவு** தேர்வு செய்யப்பட்டுள்ளது, இயல்பாகவே முடக்கப்பட்டுள்ளது. அதன் சூழல் மாறிகள் (பார்க்க [`.env.example`](../../.env.example) ):

| Env var                 | இயல்புநிலை | நோக்கம்                                                                                |
| ----------------------- | ---------- | -------------------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`    | பின்னணி LiteLLM விலை ஒத்திசைவை இயக்கு.                                                 |
| `PRICING_SYNC_INTERVAL` | `86400`    | வினாடிகளில் (தினசரி) இடைவெளியை ஒத்திசைக்கவும்.                                         |
| `PRICING_SYNC_SOURCES`  | `litellm`  | இந்த ஒத்திசைவுக்கான மூலத் தேர்வு மட்டும்; தற்போது `litellm` மட்டுமே ஆதரிக்கப்படுகிறது. |

**models.dev ஒத்திசைவு** LiteLLM ஒத்திசைவிலிருந்து தனித்தனியாக உள்ளது மற்றும் முன்னிருப்பாக முடக்கப்பட்டுள்ளது. அமைப்புகளில் (models.dev ஒத்திசைவு) அதை இயக்கவும் அல்லது இந்த மாறிகளைப் பயன்படுத்தவும்:

| Env var                    | இயல்புநிலை         | நோக்கம்                                                                                                                                       |
| -------------------------- | ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(அமைக்கப்படாதது)_ | அமைப்புகளை மாற்றுவதைத் தொடர்ந்து அமைக்கப்படாதது; `1/true/on/yes` ஆன் மற்றும் `0/false/off/no` ஃபோர்ஸ் ஆஃப் (அமைப்புகள் அதை இயக்கினாலும் கூட). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`            | இயல்புநிலை models.dev ஒத்திசைவு இடைவெளி நொடிகளில் (தினசரி).                                                                                   |

`PRICING_SYNC_SOURCES` செய்கிறது** இல்லை** models.dev ஐ இயக்கு; இது LiteLLM ஒத்திசைவை மட்டுமே கட்டுப்படுத்துகிறது. பயனர் மேலெழுதலை நீக்குவது ஒத்திசைக்கப்பட்ட பெயர்வெளியை அழிக்காது; கிடைக்கும் அடுத்த விலை அடுக்கு பயனுள்ளதாக இருக்கும். விலையில்லா மாடலுக்கு, கைமுறை மேலெழுதலைச் சேர்ப்பதற்கு முன், ஒத்திசைவு அமைப்புகள் மற்றும் `sourceMap` இரண்டையும் சரிபார்க்கவும்.

### செலவு சூத்திரம்

டோக்கன் எண்ணிக்கை மற்றும் [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`) இல் ஒரு மில்லியனுக்கு டோக்கன் விகிதங்கள் ஆகியவற்றிலிருந்து ஒரு கோரிக்கையின் விலை கணக்கிடப்படுகிறது:

- **உள்ளீடு டோக்கன்கள்** (கேச் ரீட்கள் மற்றும் கேச்-கிரியேஷன் டோக்கன்கள் கழித்தல்) × `input` விகிதம்.
- **கேச்-ரீட் டோக்கன்கள்** × `cached` வீதம் (உள்ளீட்டு விகிதத்திற்கு மீண்டும் குறைகிறது).
- **கேச் உருவாக்க டோக்கன்கள்** × `cache_creation` வீதம் (உள்ளீட்டு விகிதத்திற்கு மீண்டும் குறைகிறது).
- **வெளியீடு டோக்கன்கள்** × `output` விகிதம்.
- **பகுத்தறிவு டோக்கன்கள்** × `reasoning` விகிதம் (வெளியீட்டு விகிதத்திற்கு மீண்டும் குறைகிறது).

அனைத்து விகிதங்களும் 1,000,000 டோக்கன்களுக்கு USD என விளக்கப்படுகின்றன. ஒரு Codex "வேகமான"/"முன்னுரிமை" அல்லது "ஃப்ளெக்ஸ்" சேவை அடுக்கு ஒரு செலவு பெருக்கியைப் பயன்படுத்துகிறது (`getCodexFastCostMultiplier`) — எ.கா ஃப்ளெக்ஸ் 50% டோக்கன் தள்ளுபடியில் பில் செய்யப்படுகிறது.** நெகிழ்வு சேமிப்பு** டாஷ்போர்டில்.

மாதிரிப் பெயர்கள் முதலில் இயல்பாக்கப்படுகின்றன ( `openai/` அல்லது `accounts/fireworks/models/` போன்ற வழங்குநர்-பாதை முன்னொட்டுகள் அகற்றப்படுகின்றன) எனவே வரலாற்று வரிசைகள் இன்னும் விலையுடன் பொருந்துகின்றன.

### செலவு எப்படி பதிவு செய்யப்படுகிறது

- ஒரு கோரிக்கைக்கான செலவு பதிலுக்குப் பிறகு கணக்கிடப்படுகிறது மற்றும் பதிவுசெய்யப்பட்ட தீ-மற்றும்-மறதி, எனவே இது வாடிக்கையாளருக்கு ஒருபோதும் தாமதத்தை சேர்க்காது. பகிரப்பட்ட ஒதுக்கீடு நுகர்வு [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) வழியாக அடுத்த நிகழ்வு-லூப் டிக் இல் திட்டமிடப்பட்டுள்ளது.
- API-முக்கிய செலவு [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (இயல்புநிலை 60s ஃப்ளஷ் இடைவெளி, 1,000-நுழைவு இடையகம்) மூலம் இடையகப்படுத்தப்பட்டு, ஃப்ளஷ் செய்யப்படுகிறது. இதன் மூலம் டியூன் செய்யலாம்:

  | Env var                             | இயல்புநிலை | நோக்கம்                                     |
  | ----------------------------------- | ---------- | ------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`    | மில்லி விநாடிகளில் ஃப்ளஷ் இடைவெளி.          |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`     | பறிப்பதற்கு முன் அதிகபட்ச இடையக உள்ளீடுகள். |

டாஷ்போர்டின் விலை புள்ளிவிவரங்கள்** இல்லை** ஒவ்வொரு வரிசையிலும் சேமிக்கப்பட்ட டாலர் தொகை — இலிருந்து டோக்கன் எண்ணிக்கை மற்றும் தற்போதைய விலை அட்டவணையில் இருந்து ஒவ்வொரு முறையும் பகுப்பாய்வு எண்ட்பாயிண்ட் இயங்கும் போது அவை மீண்டும் கணக்கிடப்படுகின்றன. அதாவது தவறான விலையை சரிசெய்தல் (மற்றும் மீண்டும் ஒத்திசைத்தல்) வரலாற்று செலவு மதிப்பீடுகளை முன்னோட்டமாக புதுப்பிக்கிறது.

## Dashboard: செலவுகள் பக்கம்

**Costs** பக்கம் `/dashboard/costs` இல் உள்ளது
(`src/app/(dashboard)/dashboard/costs/`).
இதன் முதன்மைக் காட்சி **Cost Overview** தாவல் ஆகும்
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`);
இது அனைத்துத் தரவையும் `GET /api/usage/analytics` இலிருந்து ஏற்றுகிறது.

இது காண்பிப்பவை:

- **செலவுத் தொகுப்புகள்** — _இன்று (1d)_, _7d_, _30d_ மற்றும் தேர்ந்தெடுக்கப்பட்ட
  காலச்சாளரத்திற்கான மதிப்பிடப்பட்ட செலவு. வரம்புத் தேர்வி: `7d`, `30d`, `90d`, `all`.
- **முக்கிய அளவீடுகள்** — காலச்சாளரத்திலுள்ள கோரிக்கைகள், செயலில் உள்ள வழங்குநர்கள், செயலில் உள்ள மாதிரிகள்,
  ஒரு கோரிக்கைக்கான சராசரிச் செலவு.
- **செலவு ஆய்வி** — **வழங்குநர்**, **மாதிரி**,
  **API விசை**, **கணக்கு** அல்லது **சேவை நிலை** அடிப்படையில் தொகுக்கப்பட்ட, வரிசைப்படுத்தவும் வடிகட்டவும் கூடிய அட்டவணை; இதில் செலவு, கோரிக்கைகள், டோக்கன்கள்,
  சராசரி செலவு/கோரிக்கை மற்றும் மொத்தத்தில் பங்கு % ஆகியவை இடம்பெறும்.
- **டோக்கன் பயன்பாடு** — மொத்த / உள்ளீட்டு / வெளியீட்டு டோக்கன்கள் மற்றும் உள்ளீடு:வெளியீடு விகிதம்.
- **வழிப்படுத்தல் செயல்திறன்** — மாற்று வழிக்குச் சென்ற எண்ணிக்கை, மாற்று வழி விகிதம் மற்றும் கோரப்பட்ட மாதிரிக்கான கிடைப்புப் பரப்பு.
- **மாதாந்திர முன்னறிவிப்பு** — அண்மைய தினசரிச் சராசரியைப் பயன்படுத்தி மாத இறுதிச் செலவைக் கணிக்கிறது.
- **காலகட்ட ஒப்பீடு** — காலச்சாளரத்தின் முதல் பாதிக்கும் இரண்டாம் பாதிக்கும் இடையிலான % மாற்றம்.
- **விளக்கப்படங்கள்** — தினசரிச் செலவுப் போக்கு, வழங்குநர் பங்கு (வட்ட விளக்கப்படம்), முன்னணி வழங்குநர்கள், முன்னணி மாதிரிகள், API விசை
  வாரியான செலவு, கணக்கு வாரியான செலவு, வாராந்திர பயன்பாட்டு முறை மற்றும் செயல்பாட்டு வெப்ப வரைபடம்.
- **ஏற்றுமதி** — தற்போதைய காலச்சாளரத்தை **CSV** அல்லது **JSON** ஆகப் பதிவிறக்கலாம் (பூஜ்ஜியமல்லாத
  செலவுத் தரவு இருக்கும்போது பொத்தான்கள் தோன்றும்).

விலை நிர்ணயிக்கப்பட்ட போக்குவரத்து இல்லாதபோது, வரிசைகள் `$0` என்பதற்குப் பதிலாக "Legacy / Free" என்ற லேபிளைக் காட்டும்;
இது சேமிப்புக் கண்காணிப்பு மாதிரியைப் பிரதிபலிக்கிறது.

## CLI

OmniRoute-இன் CLI, செலவு, பயன்பாடு மற்றும் விலை நிர்ணயக் கட்டளைகளை வழங்குகிறது (அவை
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)-இல் பதிவு செய்யப்பட்டுள்ளன).

### `omniroute cost`

`/api/usage/analytics`-இலிருந்து ஒருங்கிணைக்கப்பட்ட செலவு அறிக்கை.

```bash
omniroute cost                          # கடந்த 30 நாட்கள், வழங்குநரின் அடிப்படையில் தொகுக்கப்பட்டது
omniroute cost --period 7d              # கடந்த 7 நாட்கள்
omniroute cost --group-by model         # provider | model | combo | api-key | day அடிப்படையில் தொகுக்கவும்
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

நெடுவரிசைகள்: குழு, கோரிக்கைகள், உள்ளீடு/வெளியீட்டு டோக்கன்கள், செலவு (USD) மற்றும் மொத்தத்தின் %. இறுதியில் ஒட்டுமொத்த மொத்த வரி
அச்சிடப்படும் (`--quiet` அல்லது `--output json` மூலம் அது தவிர்க்கப்படும்).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ஒவ்வொரு வழங்குநருக்குமான செலவுச் சுருக்கம்
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# வரவுசெலவுத் திட்டங்கள்
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`, `GET /api/pricing/defaults`-ஐப் படிக்கிறது. அதற்குப் பதிலாக தனிப்பட்ட மாதிரி
> விலைகளைத் திருத்த, **விலை நிர்ணயம்** டாஷ்போர்டு பக்கத்தை அல்லது `PATCH /api/pricing`-ஐப் பயன்படுத்தவும்.

## சிக்கல் தீர்வு

- **அனைத்துச் செலவுகளும் $0 / "Legacy / Free" எனக் காட்டப்படுகின்றன.** பயன்பாட்டில் உள்ள மாதிரிகளுக்கு விலை நிர்ணயப் பதிவு இல்லை.
  வெளிப்புற ஒத்திசைவை (`PRICING_SYNC_ENABLED=true`) இயக்கி `omniroute pricing sync`-ஐ இயக்கவும் அல்லது
  விலை நிர்ணயப் பக்கம் / `PATCH /api/pricing` வழியாக விலைகளை கைமுறையாக அமைக்கவும்.
- **வரலாற்று மாதிரி ஒன்றின் விலை தவறாக நிர்ணயிக்கப்பட்டுள்ளது.** விலையைச் சரிசெய்யவும் (மேலெழுதுதல் அல்லது மீண்டும் ஒத்திசைத்தல்) — ஒவ்வொரு பகுப்பாய்வு வாசிப்பிலும் டோக்கன் எண்ணிக்கைகளிலிருந்து செலவு
  மீண்டும் கணக்கிடப்படுவதால், மதிப்பீடுகள் பின்னோக்கியும் புதுப்பிக்கப்படும்.
- **செலவுத் தொகை நிகழ்நேரத்தைவிடப் பின்தங்குகிறது.** ஒவ்வொரு விசைக்குமான செலவுத் தொகை தொகுதிகளாகச் செயலாக்கப்படுகிறது; மேலும் புதுப்பித்த எண்ணிக்கைகள் தேவைப்பட்டால்
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS`-ஐக் குறைக்கவும்.
