நடுநிலை `config/cli-tools-manifest.json` ஒப்பந்தமானது நியமன IDs, மாற்றுப்பெயர்கள், பைனரி வேட்பாளர்கள், அமைவு செய்முறைகள், மாதிரி வாதங்கள் மற்றும் திறன்களை அறிவிக்கிறது. `bin/cli/cli-manifest.mjs` இல் உள்ள எளிய நோட் அடாப்டரும், `src/shared/constants/cliIntegrationManifest.ts` இல் உள்ள TypeScript அடாப்டரும் ஒரே கோப்பைப் படிக்கின்றன. இயக்க நேரம், பட்டியல், கட்டமைத்தல், நிறைவு, ஜெனரேட்டர்கள் மற்றும் பின்தளப் பதிவு ஆகியவை `tests/unit/cli/cli-manifest-drift.test.ts` ஆல் ஒன்றாகச் சரிபார்க்கப்படுகின்றன. பட்டியலிடப்பட்டிருப்பது ஒரு கருவியைத் தொடங்கலாம் அல்லது கட்டமைக்கப்படலாம் என்று அர்த்தமல்ல. குறிப்பாக, 5dive உள்ளமைவுக்கு மட்டுமே உள்ளது.

## குழந்தை சூழல் மற்றும் வாழ்க்கைச் சுழற்சி

`omniroute run`, `omniroute launch` மற்றும் `omniroute launch-codex` OS/terminal பொருந்தக்கூடிய அனுமதிப் பட்டியலைப் பெறுகின்றன மற்றும் தேர்ந்தெடுக்கப்பட்ட இலக்கின் நற்சான்றிதழ்களை உட்செலுத்துகின்றன. தொடர்பில்லாத வழங்குநர் மற்றும் தரவுத்தள இரகசியங்கள் முன்னிருப்பாக மரபுரிமையாக இல்லை. `--inherit-env` முழு பெற்றோர்-சுற்றுச்சூழல் பரம்பரையை வெளிப்படையாக மீட்டெடுக்கிறது; தேர்ந்தெடுக்கப்பட்ட மூன்றாம் தரப்பு செயல்முறை அந்த மதிப்புகளைப் பெறும்போது மட்டுமே அதைப் பயன்படுத்தவும். இது சூழல் வடிகட்டுதல், OS சாண்ட்பாக்ஸ் அல்ல: இந்த செயல்முறை இன்னும் அழைப்பாளரின் கோப்பு முறைமை அனுமதிகளுடன் இயங்குகிறது.

குறுக்கீடு மற்றும் முடிவுக்கு சமிக்ஞைகள் குழந்தைக்கு அனுப்பப்படுகின்றன. தற்காலிக உள்ளமைவை அகற்றுவதற்கு முன், குழந்தையின் நெருங்கிய நிகழ்வுக்காக துவக்கி காத்திருக்கிறது. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` கட்டாய நிறுத்தத்திற்கு முன் சலுகை காலத்தை கட்டுப்படுத்துகிறது (இயல்புநிலை 5000 மில்லி விநாடிகள்).

## Gemini நிலையான அமைப்பு

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

முதல் இரண்டு கட்டளைகள் தேர்ந்தெடுக்கப்பட்ட உள்ளூர் அல்லது தொலை சேவையகத்திற்காக இந்த இயந்திரத்தை உள்ளமைக்கிறது. அமைவு தொடர்பில்லாத JSON அமைப்புகளைப் பாதுகாக்கிறது, Gemini API-விசை அங்கீகாரத்தைத் தேர்ந்தெடுத்து, ஒரு தனிப்பட்ட `.gemini/.env` கோப்பில் இறுதிப்புள்ளி மற்றும் நற்சான்றிதழை எழுதுகிறது. இது தவறான JSON மேலெழுத மறுக்கிறது. உட்பொதிக்கப்பட்ட நற்சான்றிதழ்கள், வினவல் அளவுருக்கள் அல்லது துண்டுகள் இல்லாமல் எண்ட்பாயிண்ட் URLs HTTP(S) ஆக இருக்க வேண்டும். டிரை-ரன் பிரிண்ட்ஸ் பாதைகள், நற்சான்றிதழ் மதிப்புகள் அல்ல.

`GEMINI_CLI_HOME` அல்லது `--gemini-home` நிலையான முகப்பு மூலத்தைத் தேர்ந்தெடுக்கிறது. ஒரு உண்மையான `run gemini` அதன் சொந்த தற்காலிக வீட்டை உருவாக்கி பின்னர் நீக்குகிறது. எந்தப் பயன்முறையும் Gemini இன் பணியிட-நம்பிக்கை சோதனைகளைத் தவிர்க்கவில்லை.

## Codex சுயவிவரங்கள்

`configure codex` ஒரு தனிப்பட்ட `<name>.config.toml` ஒரு மாதிரி மற்றும் அதன் OmniRoute வழங்குநர் இறுதிப் புள்ளியுடன் எழுதுகிறது. நற்சான்றிதழ்கள் `OMNIROUTE_API_KEY` மூலம் குறிப்பிடப்படுகின்றன, ஒருபோதும் உட்பொதிக்கப்படவில்லை. வெளியீட்டு கட்டளை தேர்ந்தெடுக்கப்பட்ட மாதிரியை மேல்-நிலை `model` விசையில் அமைக்கிறது, `model_providers` க்குள் அல்ல.

தனி சுயவிவர கோப்புகள் தற்போதைய ஆவணப்படுத்தப்பட்ட Codex ஒப்பந்தமாகும்; `codex --profile <name>` உடன் தேர்ந்தெடுக்கும்போது அவை பயனர் உள்ளமைவை மேலெழுதுகின்றன. [அதிகாரப்பூர்வ சுயவிவரக் குறிப்பு](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) மற்றும் [OmniRoute Codex வழிகாட்டியைப்](./CODEX-CLI-CONFIGURATION.md) பார்க்கவும்.

## ஹெர்மீடிக் கட்டளை செயல்படுத்தல்

ஒரு வெளிப்படையான `DATA_DIR` உடன், `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` அமைப்பது தொடக்கநிலை பயனர் தரவு கோப்பகத்தின் நற்சான்றிதழ் சூழலுக்கு வருவதைத் தடுக்கிறது. தனிமைப்படுத்தப்பட்ட சோதனைகளுக்கு இது பயனுள்ளதாக இருக்கும். இது வெளிப்படையாகத் தேர்ந்தெடுக்கப்பட்ட பிற சூழல் கோப்புகளை முடக்காது.

## பணி அடைவு `.env`

CLI இந்த வரிசையில் `.env` கோப்புகளைப் படிக்கிறது, மேலும் விசையை அமைக்கும் முதல் கோப்பு வெற்றி பெறுகிறது: வெளிப்படையான `DATA_DIR`, இயல்புநிலை தரவு கோப்பகம், தற்போதைய செயல்பாட்டு அடைவு, பின்னர் தொகுப்பு அடைவு. ஷெல் மாறிகள் எப்போதும் வெற்றி பெறும்.

வேலை செய்யும் கோப்பகம் வேறொருவருக்குச் சொந்தமானதாக இருக்கலாம் (குளோன் செய்யப்பட்ட களஞ்சியம், தொகுக்கப்படாத காப்பகம்), மேலும் `omniroute serve` CLI சூழலை சர்வருக்கும் சர்வர் இயங்கும் ஒவ்வொரு கருவிக்கும் அனுப்புகிறது. எனவே அங்குள்ள `.env` இந்த விசைகளை மட்டும் அமைக்கலாம், `bin/cli/utils/untrustedCwdEnv.mjs` இல் பட்டியலிடப்பட்டுள்ளது:

| முக்கிய                         | ஏற்றுக்கொள்ளப்பட்ட மதிப்புகள்                                                    |
| ------------------------------- | -------------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` அல்லது `yes` எந்தவொரு சந்தர்ப்பத்திலும், சேவையகம் கருதும் மதிப்புகள் |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 64 எழுத்துக்கள் வரை, இலக்கங்கள், `_`, `.`, `@` அல்லது `-`                        |
| `LANGUAGE`                      | அதே, பிளஸ் `:`                                                                   |
| `TZ`                            | 64 எழுத்துக்கள் வரை, இலக்கங்கள், `_`, `+`, `-` அல்லது `/`, `/` இல் தொடங்கவில்லை  |
| `NO_COLOR`, `FORCE_COLOR`       | 16 எழுத்துக்கள் மற்றும் இலக்கங்கள் வரை                                           |

`REQUIRE_API_KEY` ஏற்கும் ஒவ்வொரு மதிப்பும் காசோலையை இயக்குகிறது, எனவே கோப்பினால் காசோலையை அணைக்க முடியாது. இருப்பினும், இது முடிவைத் தீர்மானிக்கவில்லை: சேவையகம் சுற்றுச்சூழலுக்கு முன் தரவுத்தளத்தில் சேமிக்கப்பட்ட `REQUIRE_API_KEY` மேலெழுதலைப் படிக்கிறது, அதே நேரத்தில் API விசை இல்லாமல் அனைத்து இடைமுகங்களிலும் கேட்பது பற்றிய தொடக்க எச்சரிக்கை சுற்றுச்சூழலை மட்டுமே படிக்கிறது. `false` இன் சேமிக்கப்பட்ட மேலெழுதலில், வேலை செய்யும் அடைவு `REQUIRE_API_KEY=true` API ஐ திறந்து விட்டு அந்த எச்சரிக்கையை மறைக்கிறது. `TZ` விதி POSIX விட குறுகியது: இது `.`, `:`, `,` மற்றும் `<>` நிராகரிக்கிறது, எனவே `:Area/City` வடிவம் மற்றும் `EST5EDT,M3.2.0,M11.1.0` போன்ற விதிகள் ஷெல் அல்லது `<DATA_DIR>/.env` இல் அமைக்கப்பட வேண்டும்.

பெயர்கள் பெரிய எழுத்தில் சரியாக பொருந்த வேண்டும். வேறு எந்த வரியும், அதன் சரிபார்ப்பில் தோல்வியுற்ற மதிப்பு மற்றும் சாதாரண ASCII எழுத்துகள், இலக்கங்கள் மற்றும் `_` இல்லாத பெயர் (உதாரணமாக NUL பைட் அல்லது தோற்றமளிக்கும் எழுத்து) தவிர்க்கப்படும். CLI ஒரு எச்சரிக்கையை அச்சிடுகிறது, அது அமைக்க முடியாத விசைகளை பெயரிடுகிறது மற்றும் அது புறக்கணிக்கப்பட்ட அனுமதிக்கப்பட்ட விசைகளை பெயரிடுகிறது, ஒவ்வொன்றும் எதை மாற்ற வேண்டும் (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). மதிப்புகளை அச்சிடவும் இல்லை. இந்தச் செய்திகளில் உள்ள கோப்பு பாதைகள் மற்றும் `.env` பாதை `omniroute doctor` அறிக்கைகள், கட்டுப்பாடு அல்லது பிடி எழுத்துக்களைக் கொண்டிருக்கும்போது அவை தப்பிக்கப்படுகின்றன. வேலை செய்யும் கோப்பகம் தரவு கோப்பகமாக அல்லது தொகுப்பு கோப்பகமாக இருக்கும்போது கட்டுப்பாடு பொருந்தாது.

`PORT`, `API_PORT` மற்றும் `DASHBOARD_PORT` பட்டியலில் இல்லை. உயர் முன்னுரிமை மூலத்திலிருந்து அடிப்படை URL இல்லாமல், CLI `localhost:<PORT>` உடன் பேசுகிறது, மேலும் அங்கு கேட்கும் அனைத்தும் CLI இன் API விசை, சூழல் டோக்கன் மற்றும் CLI இயந்திர டோக்கனை (`x-omniroute-cli-token`, பார்க்க [CLI_TOKEN.md](../security/CLI_TOKEN.md) ) பெறுகிறது, அதை உள்ளூர் சேவையகம் லூப்பேக்கிலிருந்து நிர்வாக அழைப்புகளை ஏற்றுக்கொள்கிறது. பணிபுரியும் கோப்பகத்தில் இருந்து ஒரு போர்ட் அந்த கோப்பை கேட்பவரை தேர்வு செய்ய அனுமதிக்கும், எனவே ஷெல்லில் உள்ள போர்ட்களை `<DATA_DIR>/.env` அல்லது `--port` விருப்பத்துடன் கட்டளைகளை அமைக்கவும் (`serve`, `launch`, `run`).

பாகுபடுத்திக்கு `export` தொடரியல் இல்லை. `export LD_PRELOAD=...` போன்ற ஒரு வரி ஒரு மாறி `export LD_PRELOAD` என்று பெயரிடுகிறது; வேலை செய்யும் கோப்பகத்திலிருந்து அது தவிர்க்கப்பட்டது, மற்ற `.env` கோப்புகளில் அது எதுவும் படிக்காத நேரடிப் பெயரை அமைக்கிறது.

CLI ஒரு சூழலின் சேமிக்கப்பட்ட டோக்கனை (அணுகல் டோக்கன் அல்லது மரபு API விசை) அந்த சூழலின் சொந்த தோற்றத்துடன் மட்டுமே இணைக்கிறது: ஸ்கீம், ஹோஸ்ட் மற்றும் போர்ட், `URL.origin` உடன் ஒப்பிடும்போது. இது CLI இன் HTTP கிளையன்ட் (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) மற்றும் மற்றொரு கருவியின் கட்டமைப்பில் ஒரு அடிப்படை URL மற்றும் விசையை எழுதும் `launch`, `launch codex`, `configure` மற்றும் `setup-*` கட்டளைகளுக்குப் பொருந்தும். `--remote` உடன் மற்றொரு சேவையகத்தை சுட்டிக்காட்டி, அவை அமைக்கப்பட்டிருந்தால் வெளிப்படையான `--api-key` அல்லது `OMNIROUTE_API_KEY` ஐப் பயன்படுத்துகின்றன, மேலும் சூழல் டோக்கன் இல்லை. ஒப்பீடு துல்லியமானது, எனவே `localhost` மற்றும் `127.0.0.1`, அல்லது ட்ரெயிலிங் டாட் உள்ள மற்றும் இல்லாத ஹோஸ்ட், வெவ்வேறு சேவையகங்களாகக் கணக்கிடப்படும் மற்றும் சூழல் டோக்கனைப் பெறாது. பயனர் தகவலுடன் கூடிய URL, ஒரு பின்சாய்வு அல்லது இடைவெளி எப்போதும் பொருந்தாது, ஏனெனில் மற்ற URL பாகுபடுத்திகள் (உதாரணமாக பைத்தானின் `urllib` மற்றும் `httpx`) அதிலிருந்து வேறுபட்ட ஹோஸ்டைப் படிக்க முடியும். கோரிக்கைகளுக்கு, CLI தன்னைத்தானே அனுப்புகிறது, அந்த காசோலை திட்டம் மற்றும் அதிகாரத்தை மட்டுமே உள்ளடக்கும், எனவே பாதையில் அல்லது வினவலில் இடம் உள்ள ஐடி டோக்கனை வைத்திருக்கும்.
