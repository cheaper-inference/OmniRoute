> (LMArena-பாணி) ELO மதிப்பெண்களைப்** பயன்படுத்தித் தரவரிசைப்படுத்துகிறது. உங்கள் பணிக்கு மிகவும் வலுவான மாதிரிகளை எந்த இலவச வழங்குநர்கள் வழங்குகிறார்கள் என்பதைப் பார்க்க, டாஷ்போர்டில் உள்ள **இலவச வழங்குநர் தரவரிசைகள்** பக்கத்தைத் திறக்கவும் —
> ஒட்டுமொத்தமாகவோ அல்லது வகை வாரியாக வடிகட்டியோ (குறியீட்டாக்கம், மதிப்பாய்வு, ஆவணப்படுத்தல், பிழைத்திருத்தம்) பார்க்கலாம்.

## அது என்ன

OmniRoute 377 வழங்குநர்களை பதிவு செய்கிறது, இதில் 155 பட்டியல் உள்ளீடுகள் குறிக்கப்பட்டுள்ளன**free/no-auth** (no-auth, free-tier OAuth, அல்லது free-tier API key — [Free Tiers Guide](../getting-started/FREE-TIERS-GUIDE.md) மற்றும் முழு [இலவச அடுக்கு கோப்பகத்தைப்](../reference/FREE_TIERS.md) பார்க்கவும்). கேட்ச்: இலவச வழங்குநர்கள் மாதிரி தரத்தில் பெருமளவில் வேறுபடுகிறார்கள். ஒரு சிறிய மரபு மாதிரியை வழங்குவதை விட, அங்கீகாரம் இல்லாத வழங்குநர் எல்லைக்குட்பட்ட மாதிரியை வழங்குவது மிகவும் பயனுள்ளதாக இருக்கும்.

**இலவச வழங்குநர் தரவரிசை** பதில்கள்"** எந்த இலவச வழங்குநர் எனக்கு சிறந்த மாதிரியைத் தருகிறார்?** "ஒவ்வொரு இலவச வழங்குநரின் அட்டவணையில் சேர்வதன் மூலம்** கூட்டம் சார்ந்த தர மதிப்பெண்கள்** இருந்து** அரினா AI லீடர்போர்டு** (human-preference ELO, LMArena chatbot அரங்கின் பின்னால் அதே யோசனை). வழங்குநர்கள் பின்னர் அவர்களின் வலிமையால் தரவரிசைப்படுத்தப்படுகிறார்கள்** சிறந்த இலவச மாதிரி** .

தரவரிசை மூன்று உண்மையான ஆதாரங்களில் இருந்து கணக்கிடப்படுகிறது:

1. இலவச வழங்குநர் பட்டியல்கள் — `NOAUTH_PROVIDERS`, பிளஸ் `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` உள்ளீடுகள் கொடியிடப்பட்ட `hasFree` (`src/shared/constants/providers.ts`).
2. வழங்குநர் பதிவேட்டில் இருந்து ஒவ்வொரு வழங்குநரின் மாதிரி பட்டியல் (`open-sse/config/providerRegistry.ts`).
3. Arena ELO sync engine (`src/lib/arenaEloSync.ts`) மூலம் `model_intelligence` DB அட்டவணையில் சேமிக்கப்பட்ட ELO-பெறப்பட்ட டாஸ்க்-ஃபிட் மதிப்பெண்கள்.

சேர தர்க்கம் `src/lib/freeProviderRankings.ts` இல் வாழ்கிறது.

## அணுகுவது எப்படி

### டாஷ்போர்டு பக்கம்

டாஷ்போர்டைத் திறந்து **செலவுகள் → இலவச வழங்குநர் தரவரிசைகள்** என்பதற்குச் செல்லவும் அல்லது நேரடியாக இங்கு செல்லவும்:

```
/dashboard/free-provider-rankings
```

இந்தப் பக்கம் (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) பின்வருவனவற்றைக் காட்டுகிறது:

- சிறந்த தரவரிசை பெற்ற இலவச வழங்குநர்களின் **முதல் 3 மேடை** (🥇 🥈 🥉).
- **தரவரிசை**, **வழங்குநர்**, **சிறந்த மாதிரி**,
  **மதிப்பெண்**, **சராசரி மதிப்பெண்**, **மாதிரிகள்**, **வகை** ஆகிய நெடுவரிசைகளுடன் கூடிய முழுமையான **தரவரிசை அட்டவணை**.
- **வகை வடிகட்டல் பொத்தான்கள்**: _அனைத்து வகைகளும்_, _இயல்புநிலை_, _குறியீட்டாக்கம்_, _மதிப்பாய்வு_,
  _ஆவணப்படுத்தல்_, _பிழைத்திருத்தம்_.

ஒவ்வொரு வழங்குநரின் **வகை** அடையாளமும் அது எவ்வாறு இலவசமாக உள்ளது என்பதைக் காட்டுகிறது:

| அடையாளம் | பொருள்                                              |
| -------- | --------------------------------------------------- |
| `NOAUTH` | எப்போதும் இலவசம், சான்றுகள் தேவையில்லை              |
| `OAUTH`  | இலவச அடுக்கைக் கொண்ட OAuth வழங்குநர் (`hasFree`)    |
| `APIKEY` | இலவச அடுக்கைக் கொண்ட API-விசை வழங்குநர் (`hasFree`) |

மதிப்பெண்கள் மூல எண்களுக்குப் பதிலாக மனிதர்கள் எளிதில் புரிந்துகொள்ளக்கூடிய குறிச்சொற்களாக (எ.கா. _உயர்தரம்_, _மிகச் சிறப்பு_, _மிகவும் நன்று_,
_நன்று_, _சராசரி_) காட்டப்படுகின்றன; ஏனெனில் அடிப்படை மதிப்பு ஒரு சதவீதம் அல்ல,
ஒப்பீட்டுத் தரவரிசைத் தரமாகும்.

### API முனைப்புள்ளி

இந்தப் பக்கத்துக்கு ஒரு பொதுப் படிப்பு முனைப்புள்ளி
(`src/app/api/free-provider-rankings/route.ts`) ஆதரவளிக்கிறது:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

வினவல் அளவுருக்கள் (Zod மூலம் சரிபார்க்கப்படுகின்றன):

| அளவுரு     | வகை    | இயல்புநிலை    | குறிப்புகள்                                                                                                                 |
| ---------- | ------ | ------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `category` | string | (எதுவுமில்லை) | `default`, `coding`, `review`, `documentation`, `debugging` ஆகியவற்றில் ஒன்று. ஒருங்கிணைந்த தரவரிசைக்கு இதைத் தவிர்க்கவும். |
| `limit`    | number | `50`          | `1–100` வரம்புக்குள் கட்டுப்படுத்தப்படுகிறது.                                                                               |

பதில் வடிவம்:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` என்பது அசல் Arena ELO மதிப்பு; `score` என்பது இயல்பாக்கப்பட்ட பணிப் பொருத்த மதிப்பு
(கீழே காண்க). மதிப்பெண் வழங்கப்பட்ட மாதிரிகள் இல்லாத வழங்குநர்கள் பதிலிலிருந்து தவிர்க்கப்படுகிறார்கள்.

## மதிப்பெண்கள் எவ்வாறு செயல்படுகின்றன

### மூலம்: Arena AI leaderboard

Arena ELO ஒத்திசைவு இயந்திரம் (`src/lib/arenaEloSync.ts`) Arena AI leaderboard API-யிலிருந்து
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) இரண்டு leaderboard-களை —
`text` மற்றும் `code` — பெறுகிறது. அந்த API பயன்படுத்தக்கூடிய board எதுவும் வழங்காதபோது,
இயந்திரம் Hugging Face datasets-server-ல் உள்ள அதிகாரப்பூர்வ `lmarena-ai/leaderboard-dataset`-ஐ
காப்பு மூலமாகப் பயன்படுத்துகிறது (`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` என்பது `activeSource`, `lastError` மற்றும்
`lastFailedAt` ஆகியவற்றை அறிவிக்கிறது. ஒவ்வொரு leaderboard பதிவும்
ஒரு மாதிரி பெயர், விற்பனையாளர், ELO `score`, நம்பிக்கை இடைவெளி மற்றும் வாக்கு எண்ணிக்கையைக் கொண்டிருக்கிறது.

Leaderboard வகைகள் OmniRoute பணி வகைகளுடன் பின்வருமாறு பொருந்துகின்றன:

| Arena leaderboard | OmniRoute பணி வகைகள்                              |
| ----------------- | ------------------------------------------------- |
| `text`            | `default`, `review`, `documentation`, `debugging` |
| `code`            | `coding`                                          |

### இயல்பாக்கம் (பணி-பொருத்த மதிப்பெண்)

மூல ELO மதிப்பெண்கள் ஒவ்வொரு leaderboard-க்கும் **`[0.4, 0.98]` வரம்பில் ஒரு பணி-பொருத்த மதிப்பாக** இயல்பாக்கப்படுகின்றன:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

மதிப்பெண் ஒருபோதும் `0` அல்லது `1`-ஐ அடைவதில்லை, இதனால் பயனர் மாற்றங்களுக்கு இடம் வைக்கப்படுகிறது. இதுவே
API பதிலில் நீங்கள் காணும் `score` புலமும், டாஷ்போர்டில் காட்டப்படும் லேபிளும் ஆகும்.

### நம்பிக்கை

ஒவ்வொரு பதிவும் Arena வாக்கு எண்ணிக்கையின் அடிப்படையில் ஒரு நம்பிக்கை நிலையைப் பெறுகிறது:

| நம்பிக்கை | வாக்குகள் |
| --------- | --------- |
| `high`    | ≥ 5,000   |
| `medium`  | ≥ 1,000   |
| `low`     | < 1,000   |

### சேமிப்பு மற்றும் புத்துணர்வு

இயல்பாக்கப்பட்ட பதிவுகள் `model_intelligence` DB அட்டவணையில்
`source = "arena_elo"` என எழுதப்படுகின்றன (`src/lib/db/modelIntelligence.ts`). பதிவுகள் **7 நாட்களுக்குப் பிறகு காலாவதியாகின்றன**, எனவே ஒத்திசைவதை நிறுத்தும் ஒரு provider,
பழைய தரவை வழங்குவதற்குப் பதிலாக இறுதியில் பட்டியலிலிருந்து விலகிவிடுகிறது.

ஒத்திசைவு **இயல்பாக இயக்கப்பட்டிருக்கும்**:

- இது சர்வர் தொடக்கத்தில் ஒருமுறை இயங்குகிறது, பின்னர் அவ்வப்போது ஒரு டைமரில் இயங்குகிறது
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts`-லிருந்து இணைக்கப்பட்டுள்ளது).
- இது **தடையின்றி இயங்கும், ஒருபோதும் ஆபத்தானதல்ல** — மேல்நோக்கு (upstream) பெறுதல் தோல்வியடைந்தால், OmniRoute
  தொடர்ந்து இயங்கும், தரவரிசைகள் வெறும் கடைசி நல்ல தரவைக் காட்டும் (அல்லது வெற்று நிலையைக் காட்டும்).

இரண்டு சூழல் மாறிகள் இதைக் கட்டுப்படுத்துகின்றன
([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)-ல் ஆவணப்படுத்தப்பட்டுள்ளன):

| மாறி                      | இயல்புநிலை    | நோக்கம்                                                        |
| ------------------------- | ------------- | -------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | வெளிச்செல்லும் ஒத்திசைவில் இருந்து விலக `false` என அமைக்கவும். |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | ஒத்திசைவு இடைவெளி, வினாடிகளில்.                                |

### கைமுறை ஒத்திசைவு / நிலை / அழிப்பு

நிர்வாகிகளுக்காக, ஒரு அங்கீகரிக்கப்பட்ட நிர்வாக endpoint கைமுறைக் கட்டுப்பாட்டை வழங்குகிறது
(`src/app/api/intelligence/sync/route.ts` — நிர்வாக அங்கீகாரம் தேவை):

```
GET    /api/intelligence/sync          # தற்போதைய ஒத்திசைவு நிலை (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # கைமுறை ஒத்திசைவைத் தொடங்கு; எழுதாமல் முன்னோட்டம் பார்க்க body: { "dryRun": true }
DELETE /api/intelligence/sync          # ஒத்திசைக்கப்பட்ட அனைத்து arena_elo intelligence பதிவுகளையும் அழி
```

தரவரிசைப் பக்கம் வெற்றாக இருந்தால், ஒரு கைமுறை `POST /api/intelligence/sync` (அல்லது வெறுமனே
சர்வரை மீண்டும் தொடங்குவது) அதை மீண்டும் நிரப்பும்.

### மாதிரிகளை leaderboard உடன் பொருத்துதல்

Registry மாதிரி ID-களும் Arena மாதிரி பெயர்களும் எப்போதும் சரியாகப் பொருந்தாது. தரவரிசை
நெகிழ்வான பொருத்தத்தைப் பயன்படுத்துகிறது (`src/lib/freeProviderRankings.ts`-ல் உள்ள `findMatchingIntelligence`):

1. இயல்பாக்கப்பட்ட மாதிரி ID-யில் சரியான பொருத்தம்.
2. இறுதியில் உள்ள பதிப்பு பின்னொட்டை நீக்கிய பிறகு பொருத்தம் (எ.கா. `kimi-k2.6` → `kimi-k2`).
3. முன்னொட்டு பொருத்தம் (ஒரு leaderboard மாதிரி பெயர் registry ID-யின் முன்னொட்டாக இருத்தல்).

ஒத்திசைவு பக்கத்தில், அறியப்பட்ட விற்பனையாளர் முன்னொட்டுகள் (`anthropic/`, `openai/`, `google/`, …)
நீக்கப்படுகின்றன, மேலும் ஒரு சிறிய alias வரைபடம் மூலப் பெயர்களை OmniRoute உள்நாட்டில்
பயன்படுத்தும் மாறுபாடுகளாக விரிவாக்குகிறது, இதனால் மாதிரிகள் எந்தப் பெயரிலும் கண்டுபிடிக்கக்கூடியதாக இருக்கின்றன.

### ஒரு provider எவ்வாறு தரவரிசைப்படுத்தப்படுகிறது

ஒவ்வொரு இலவச provider-க்கும், இயந்திரம் அதன் பட்டியலில் உள்ள ஒவ்வொரு மாதிரிக்கும் மதிப்பெண் இட்டு, பின்னர்:

- **Top Model** = provider-ன் மிக அதிக மதிப்பெண் பெற்ற மாதிரி.
- **Avg Score** = அந்த provider-ன் மதிப்பெண் பெற்ற அனைத்து மாதிரிகளின் சராசரி மதிப்பெண்.
- **Models** = provider-ன் எத்தனை மாதிரிகள் Arena மதிப்பெண் பெற்றிருந்தன.

Provider-கள் முதலில் **சிறந்த-மாதிரி மதிப்பெண்** மூலமும், பின்னர் சராசரி மதிப்பெண் மூலமும் வரிசைப்படுத்தப்படுகின்றன. இது
குறைந்தது ஒரு வலுவான இலவச மாதிரியை வழங்கும் provider-ஐ வெகுமதிக்கிறது.

## இலவச வழங்குநர்களைத் தேர்ந்தெடுக்க இதைப் பயன்படுத்துதல்

1. **சரியான வகையைத் தேர்ந்தெடுக்கவும்.** ஏஜென்ட் சார்ந்த/குறியீட்டு பணிச்சுமைகளுக்கு **Coding** வடிகட்டியைப் பயன்படுத்தவும் அல்லது பொதுவான அரட்டைக்கு **All Categories** / **Default** என்பதிலேயே விடவும். ஒவ்வொரு தரவரிசைப் பட்டியலிலும் வழங்குநரின் சிறந்த மாதிரி வேறுபடுவதால், ஒரே வழங்குநர் வகைகளுக்கு ஏற்ப வெவ்வேறு இடங்களைப் பெறலாம்.
2. **ஒரேமுறை அமைப்புகளுக்கு முதல் மூன்று இடங்களை விரும்பவும்.** ஒன்று அல்லது இரண்டு இலவச வழங்குநர்களை மட்டுமே இணைக்க விரும்பினால், உங்கள் வகையில் உயர்ந்த தரவரிசையில் உள்ளவற்றிலிருந்து தொடங்கவும்.
3. **Type அடையாளக் குறியைச் சரிபார்க்கவும்.** `NOAUTH` வழங்குநர்களை மிக விரைவாக இணைக்கலாம் (சான்றுகள் தேவையில்லை). `OAUTH` / `APIKEY` இலவச அடுக்குகளுக்கு விரைவான பதிவுசெய்தல் தேவைப்படும், ஆனால் அவை பெரும்பாலும் அதிகத் திறனுள்ள மாதிரிகளை வழங்குகின்றன. இணைப்பதற்கான படிகளுக்கு [இலவச அடுக்குகள் வழிகாட்டி](../getting-started/FREE-TIERS-GUIDE.md) என்பதைப் பார்க்கவும்.
4. **பலவற்றை இணைத்து, Auto-Combo முடிவெடுக்க அனுமதிக்கவும்.** இந்தப் பக்கத்தை இயக்கும் அதே Arena ELO தரவு, Auto-Combo மதிப்பீட்டு இயந்திரத்தின் **பணிப் பொருத்தக் காரணிக்கும்** தரவளிக்கிறது (`open-sse/services/autoCombo/taskFitness.ts`, தீர்மான வரிசை:
   `user_override → arena_elo → models_dev_tier → static table`). எனவே, சிறந்த இலவச வழங்குநர்களை இணைத்த பிறகு, `model: "auto"` (எ.கா. `auto/coding`) மூலம் வழிச்செலுத்துவது ஒவ்வொரு கோரிக்கைக்கும் உயர்தரமான இலவச மாதிரிகளைத் தானாகவே முன்னுரிமைப்படுத்தும். முழுமையான 16-காரணி மதிப்பீட்டிற்கு [Auto-Combo](../routing/AUTO-COMBO.md) என்பதைப் பார்க்கவும்.
