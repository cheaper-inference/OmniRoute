தனிப்பயன் JSON API முனையானது OpenAI அல்லது Anthropic நெறிமுறையைப் பேசாத JSON வணிக முடிவுப் புள்ளியை இணைக்கிறது. OmniRoute ஒரு JSON கோரிக்கை டெம்ப்ளேட்டை நிரப்புகிறது, அதை முழுமையான இறுதிப்புள்ளி URL க்கு அனுப்புகிறது, மறுமொழி பாதையிலிருந்து பதிலைப் படித்து, கிளையண்டின் சொந்த வடிவத்தில் அதை கிளையண்டிற்கு திருப்பி அனுப்புகிறது (அரட்டை நிறைவுகள், பதில்கள், செய்திகள், ...).

இது `apiType: "custom-json"` உடன் OpenAI-இணக்கமான முனை; அதன் ஐடி `openai-compatible-custom-json-<suffix>` வடிவத்தைக் கொண்டுள்ளது. டாஷ்போர்டு படிவம் இன்னும் கிடைக்கவில்லை. கீழே உள்ள வழங்குநர்-முனை API மூலம் இந்த முனைகளை உருவாக்கி திருத்தவும்.

## ஒரு முனையை உருவாக்கவும்

`POST /api/provider-nodes` (மேலாண்மை அங்கீகாரம்):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` என்பது** முழுமையான** இறுதிப்புள்ளி URL. எதுவும் இணைக்கப்படவில்லை ( `/chat/completions` இல்லை , `/models` இல்லை ) மற்றும், மற்ற OpenAI-இணக்கமான முனைகளைப் போலல்லாமல், இயல்புநிலை URL இல்லை. இது உட்பொதிக்கப்பட்ட நற்சான்றிதழ்கள் அல்லது `#fragment` இல்லாமல் `http(s)` ஆக இருக்க வேண்டும், மேலும் இது ஒவ்வொரு வழங்குநர் முனையிலும் அதே வெளிச்செல்லும் URL காவலரைக் கடந்து செல்லும், கணு சேமிக்கப்படும் போதும் ஒவ்வொரு கோரிக்கையின் போதும்.
- இணைப்பு விசையை அனுப்பும் முனை (`authType` `bearer` அல்லது `api-key`, இயல்புநிலை உட்பட) `https://` பயன்படுத்த வேண்டும். ப்ளைன் `http://` ஒரு லூப்பேக் ஹோஸ்ட் (`localhost`, `127.0.0.0/8`, `::1`) அல்லது `authType: "none"` உடன் மட்டுமே ஏற்றுக்கொள்ளப்படுகிறது, இது எந்த விசையையும் அனுப்பாது. தனிப்பட்ட LAN முகவரிகளுக்கு (`10.x`, `172.16-31.x`, `192.168.x`) விதிவிலக்கு இல்லை: அந்த நெட்வொர்க்கில் உள்ள எவரும் விசையைப் படிக்கலாம். அத்தகைய முனையைச் சேமிப்பது `400` இல் தோல்வியடைகிறது, மேலும் முன்பு சேமிக்கப்பட்ட ஒரு முனையானது எந்த கோரிக்கையை அனுப்புவதற்கு முன்பும் அதே செய்தியுடன் ஒவ்வொரு கோரிக்கையிலும் மூடப்படும். ஒரு LAN இல் ஒரு முக்கிய முனைப்புள்ளிக்கு, அதை TLS க்கு பின்னால் வைக்கவும் (உதாரணமாக ஒரு தலைகீழ் ப்ராக்ஸி).
- `customJson` Zod உடன் சரிபார்க்கப்படுகிறது; தெரியாத விசைகள் நிராகரிக்கப்படுகின்றன. ஒவ்வொரு துறையும் விருப்பமானது:

| களம்              | மதிப்புகள்                                     | இயல்புநிலை                                             |
| ----------------- | ---------------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                         | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                    | `bearer`                                               |
| `authHeader`      | `api-key` போது பயன்படுத்தப்படும் தலைப்பு பெயர் | `X-API-Key`                                            |
| `requestTemplate` | JSON பொருள் (≤ 64 KB, ஆழம் ≤ 32)               | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | புல பாதை, அல்லது முழு உடலுக்கும் `$`           | `choices[0].message.content`                           |

- ரகசியம் இணைப்பின் API விசையில் இருக்கும், டெம்ப்ளேட்டில் இல்லை. `bearer` `Authorization: Bearer <key>` ஐ அனுப்புகிறது; `api-key` `<authHeader>: <key>` அனுப்புகிறது. அங்கீகாரத் தலைப்பு `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` அல்லது ஹாப்-பை-ஹாப் தலைப்பாக இருக்க முடியாது. `none` உடன், இணைப்புகளுக்கு விசை தேவையில்லை.
- கூடுதல் நிலையான தலைப்புகள் முனையின் வழக்கமான `customHeaders` பயன்படுத்துகின்றன (ஒவ்வொரு இணக்கமான முனையின் அதே சரிபார்ப்பு; அங்கீகார தலைப்புகள் அங்கு அனுமதிக்கப்படாது).

`PUT /api/provider-nodes/<id>` அதே `customJson` ஏற்றுக்கொள்கிறது மற்றும் `baseUrl` மற்றும் config ஐ ஏற்கனவே இருக்கும் முனையின் ஒவ்வொரு இணைப்பிலும் மீண்டும் எழுதுகிறது. `customJson` தவிர்ப்பது சேமிக்கப்பட்ட கட்டமைப்பை வைத்திருக்கிறது; `apiType` க்கு `chat` அல்லது `responses` மாறுவது கணு மற்றும் அதன் இணைப்புகளில் இருந்து நீக்குகிறது.

பின்னர் வழக்கம் போல் முனையில் இணைப்பைச் சேர்க்கவும் (நோட் ஐடியுடன்`POST /api/providers` ) மற்றும் `<prefix>/<model>` கோரவும், எடுத்துக்காட்டாக `biz/assistant-v1`. இறுதிப்புள்ளி எந்த மாதிரி பட்டியலையும் வெளிப்படுத்தாது, எனவே மாடல் ஐடிகளை கையால் சேர்க்கவும்.

## வார்ப்புருக்களைக் கோருங்கள்

வார்ப்புருக்கள் வெற்று JSON ஆகும். ஒரு சரம் மதிப்பில் `{{placeholder}}` குறிப்பான்கள் இருக்கலாம்; எதுவும் மதிப்பிடப்படவில்லை அல்லது செயல்படுத்தப்படவில்லை, மேலும் பொருள் விசைகள் ஒருபோதும் மாற்றப்படாது.

| ப்ளேஸ்ஹோல்டர்        | மதிப்பு                                                                    |
| -------------------- | -------------------------------------------------------------------------- |
| `{{prompt}}`         | சமீபத்திய பயனர் செய்தியின் உரை (புதிய வரிகளுடன் இணைக்கப்பட்ட உரை பகுதிகள்) |
| `{{messages}}`       | OpenAI அரட்டை வடிவத்தில் உரையாடல்                                          |
| `{{model}}`          | வழங்குநர் முன்னொட்டு இல்லாமல் கோரப்பட்ட மாதிரி ஐடி                         |
| `{{stream}}`         | எப்போதும் `false` — ஒரு JSON ஆவணத்துடன் இறுதிப்புள்ளி பதிலளிக்கும்         |
| `{{request.<path>}}` | மொழிபெயர்க்கப்பட்ட (OpenAI அரட்டை வடிவம்) கோரிக்கையின் புலம்               |

- சரியாக ஒரு ஒதுக்கிடமாக இருக்கும் மதிப்பு அதன் JSON வகையை வைத்திருக்கிறது (`"{{messages}}"` ஒரு வரிசையாக மாறும்); ஒரு நீண்ட சரத்திற்குள் ஒரு ஒதுக்கிடமானது உரையாக செருகப்பட்டது.
- முழுமையடையாத பேலோடை அனுப்புவதற்குப் பதிலாக HTTP 400 உடன் கோரிக்கையை தோல்வியடையச் செய்யும் ஒரு ஒதுக்கிடமானது.
- பாதைகள் புள்ளி குறியீடு மற்றும் எண் குறியீடுகளை (`data.items[0].text`) பயன்படுத்துகின்றன. `__proto__`, `prototype` மற்றும் `constructor` விசைகள் மற்றும் பாதைகளில் நிராகரிக்கப்படுகின்றன.

## பதில்கள்

`responsePath` இல் உள்ள மதிப்பு அசிஸ்டெண்ட் ரிப்ளை ஆகிறது: சரங்கள் கடந்து செல்கின்றன, மற்ற JSON மதிப்புகள் வரிசைப்படுத்தப்படுகின்றன. விடுபட்ட அல்லது `null` புலம் அல்லது JSON அல்லாத ஒரு உடல் HTTP 502 ஐ வழங்குகிறது. அப்ஸ்ட்ரீம் பிழை நிலைகள் அனுப்பப்படும். ஸ்ட்ரீமிங் கிளையண்டுகளுக்கு OmniRoute முழு JSON பதிலுக்காகக் காத்திருக்கிறது, பின்னர் அதை ஒரு உள்ளடக்கத் துண்டாக மற்றும் பூச்சு துண்டாக வெளியிடுகிறது; இது டோக்கன் ஸ்ட்ரீமிங் அல்ல. கருவி அழைப்புகள் மற்றும் பயன்பாட்டு புலங்கள் வரைபடமாக்கப்படவில்லை.

## மீண்டும் இயக்கப்படவில்லை

ஒரு வணிக கோரிக்கை தோல்வியுற்றாலும் பக்க விளைவுகளை ஏற்படுத்தலாம். எனவே OmniRoute அதை ஒருமுறை அனுப்புகிறது:

- போக்குவரத்து மறுமுயற்சி இல்லை மற்றும் பின்தொடர்தல் இல்லை;
- மற்றொரு இணைப்பில் மீண்டும் முயற்சிக்க வேண்டாம் (கணக்கு வீழ்ச்சி) — தோல்வி அப்படியே திரும்பியது மற்றும் இணைப்பு குளிர்விக்கப்படவில்லை;
- வெற்று அல்லது தோல்வியுற்ற பதிலுக்காக கூட, அடுத்த சேர்க்கை இலக்குக்கு பின்னடைவு இல்லை.

தனி கிளையன்ட் கோரிக்கைகள் மற்றும் பல மாதிரிகளை வெளிப்படையாக அழைக்கும் ஃப்யூஷன் பேனல்கள், இன்னும் இறுதிப்புள்ளியை சுயாதீனமாக செயல்படுத்துகின்றன.

## ஒரு முனையை சோதிக்கிறது

ஒரு இணைப்பைச் சேமிக்கிறது, இணைப்பு** சோதனை** பொத்தான் மற்றும் பின்புல சுகாதாரச் சோதனைகள் இறுதிப் புள்ளியை ஒருபோதும் அழைக்காது: அவை சேமிக்கப்பட்ட கட்டமைப்பை மட்டுமே சரிபார்த்து, இணைப்பைச் சரிபார்க்க முடியாது எனப் புகாரளிக்கின்றன.

`"apiType": "custom-json"` மற்றும் முனைப் புலங்களுடன்`POST /api/provider-nodes/validate` (`baseUrl`, `apiKey`, `customJson`, விருப்பமான `customHeaders` மற்றும் `modelId`) சரியாக ஒரு உண்மையான கோரிக்கையை அனுப்புகிறது, `ping` சமீபத்திய பயனர் உரையாகக் கொண்டுள்ளது. இது `{ "valid": true }` அல்லது அப்ஸ்ட்ரீம் நிலைக்கு பதிலளிக்கிறது (ஒருபோதும் அப்ஸ்ட்ரீம் உடல் அல்ல).

## சேமிப்பு

கட்டமைப்பு `provider_nodes.custom_json_config_json` (இடம்பெயர்வு `240_provider_node_custom_json_config.sql`) இல் சேமிக்கப்பட்டு ஒவ்வொரு இணைப்பின் `providerSpecificData.customJson` க்கும் நகலெடுக்கப்படுகிறது.

செயல்படுத்தல்: `open-sse/utils/customJson.ts` (சரிபார்த்தல் மற்றும் டெம்ப்ளேட்டிங்), `open-sse/executors/customJson.ts` (செயல்படுத்துபவர்), `open-sse/services/combo/noReplayLatch.ts` மற்றும் `src/sse/handlers/chat/responsePolicies.ts` (நோ-ரீப்ளே).
