## 🎯 பயன்பாட்டு நிகழ்வுகள்

### நிகழ்வு 1: "என்னிடம் Claude Pro சந்தா உள்ளது"

**சிக்கல்:** ஒதுக்கீடு பயன்படுத்தப்படாமலேயே காலாவதியாகிறது; தீவிரமாக நிரலெழுதும்போது பயன்பாட்டு வீத வரம்புகள் ஏற்படுகின்றன

```
கலவை: "maximize-claude"
  1. cc/claude-opus-4-7        (சந்தாவை முழுமையாகப் பயன்படுத்தவும்)
  2. glm/glm-4.7               (ஒதுக்கீடு தீர்ந்ததும் மலிவான மாற்றுத் தீர்வு)
  3. if/qwen3.8-max-preview       (அவசரநிலைக்கான இலவச மாற்றுத் தீர்வு)

மாதச் செலவு: $20 (சந்தா) + ~$5 (மாற்றுத் தீர்வு) = மொத்தம் $25
இதற்கு மாறாக, $20 செலுத்தியும் வரம்புகளை எட்டுவது = விரக்தி
```

### நிகழ்வு 2: "செலவே இல்லாமல் வேண்டும்"

**சிக்கல்:** சந்தாக்களை வாங்க இயலாது; நம்பகமான AI நிரலாக்கம் தேவை

```
கலவை: "zero-cost"
  1. if/kimi-k2.7-code          (இலவச அணுகல் எனப் பட்டியலிடப்பட்டுள்ளது; பயன்பாட்டு வீத வரம்புகள் பொருந்தக்கூடும்)
  2. kr/qwen3-coder-next        (Kiro இலவச மாற்றுத் தீர்வு)

மாதச் செலவு: $0
தரம்: உங்கள் பணிச்சுமைக்கான மாடல், வரம்புகள், தனியுரிமை மற்றும் SLA ஆகியவற்றைச் சரிபார்க்கவும்
```

### நிகழ்வு 3: "இடையூறுகள் இல்லாமல் 24/7 நிரலெழுத வேண்டும்"

**சிக்கல்:** காலக்கெடுக்கள் உள்ளன; செயல்படாத நேரத்தை ஏற்க முடியாது

```
கலவை: "always-on"
  1. cc/claude-opus-4-7        (சிறந்த தரம்)
  2. cx/gpt-5.5                (இரண்டாவது சந்தா)
  3. glm/glm-4.7               (மலிவானது, தினமும் மீட்டமைக்கப்படும்)
  4. minimax/MiniMax-M2.1      (மிக மலிவானது, 5 மணிநேரத்தில் மீட்டமைப்பு)
```

தட்டு முறை macOS, Windows மற்றும் வரைகலை Linux அமர்வுகளை ஆதரிக்கிறது. தட்டு முறை கட்டுப்பாட்டுப் பலகையைத் தானாகத் திறக்காது.

பின்வரும் செயல்களுக்கு தட்டு மெனுவைப் பயன்படுத்தவும்:

- கட்டுப்பாட்டுப் பலகையைத் திறக்கவும்.
- `/dashboard/logs`-ஐத் திறக்கவும்.
- தானியங்கு தொடக்கத்தை மாற்றவும்.
- OmniRoute-ஐ நிறுத்தவும்.

பின்வரும் விருப்பங்களுடன் `--tray`-ஐ இணைத்துப் பயன்படுத்த வேண்டாம்:

- `--daemon`
- `--log`
- `--no-recovery`

இந்த முறைகளுக்கு வேறுபட்ட செயல்முறை உரிமை தேவைப்படுகிறது.

அடுத்த கணினி உள்நுழைவின்போது தொடங்குவதை இயக்கவும்:

```bash
omniroute autostart enable
```

தானியங்கு தொடக்கம் macOS, Windows மற்றும் வரைகலை Linux அமர்வுகளில் தட்டு முறையைப் பயன்படுத்தும். திரையற்ற Linux ஏற்கனவே உள்ள systemd பயனர் சேவையைப் பயன்படுத்தும்.

உள்நுழையும்போது தொடங்குவதை முடக்கவும்:

```bash
omniroute autostart disable
```

### நிறுவல் நீக்கம்

OmniRoute இனி தேவையில்லாதபோது, முழுமையாக அகற்றுவதற்கு இரண்டு விரைவான ஸ்கிரிப்ட்களை வழங்குகிறோம்:

| கட்டளை                   | செயல்                                                                                                     |
| ------------------------ | --------------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | கணினிச் செயலியை அகற்றும், ஆனால் `~/.omniroute`-இல் உள்ள **உங்கள் DB மற்றும் உள்ளமைவுகளைத் தக்கவைக்கும்**. |
| `npm run uninstall:full` | செயலியை அகற்றுவதுடன் **அனைத்து உள்ளமைவுகள், விசைகள் மற்றும் தரவுத்தளங்களை நிரந்தரமாக அழிக்கும்**.         |

> குறிப்பு: இந்தக் கட்டளைகளை இயக்க, OmniRoute திட்டக் கோப்பகத்திற்குச் சென்று (அதை clone செய்திருந்தால்) அவற்றை இயக்கவும். மாற்றாக, உலகளாவிய முறையில் நிறுவியிருந்தால், `npm uninstall -g omniroute` என்பதை மட்டும் இயக்கலாம்.

### PM2 நிறுவல் (குறைந்த நினைவகம்)

குறைந்த RAM கொண்ட சேவையகங்களுக்கு, நினைவக வரம்பு விருப்பத்தைப் பயன்படுத்தவும்:

```bash
# 512MB வரம்புடன் (இயல்புநிலை)
pm2 start npm --name omniroute -- start

# அல்லது தனிப்பயன் நினைவக வரம்புடன்
OMNIROUTE_MEMORY_MB=512 pm2 start npm --name omniroute -- start

# அல்லது ecosystem.config.js-ஐப் பயன்படுத்தி
pm2 start ecosystem.config.js
```

`ecosystem.config.js`-ஐ உருவாக்கவும்:

```javascript
module.exports = {
  apps: [
    {
      name: "omniroute",
      script: "npm",
      args: "start",
      env: {
        NODE_ENV: "production",
        OMNIROUTE_MEMORY_MB: "512",
        JWT_SECRET: "your-secret",
        INITIAL_PASSWORD: "your-password",
      },
      node_args: "--max-old-space-size=512",
      max_memory_restart: "300M",
    },
  ],
};
```

### Void Linux (xbps-src)

Void Linux பயனர்கள் `xbps-src` குறுக்குத் தொகுப்பு கட்டமைப்பைப் பயன்படுத்தி OmniRoute-ஐ இயல்பாகத் தொகுப்பாக்கி நிறுவலாம். இது தேவையான `better-sqlite3` இயல்புநிலை பிணைப்புகளுடன் Node.js தனித்தியங்கும் உருவாக்கத்தையும் தானியங்குபடுத்துகிறது.

<details>
<summary><b>xbps-src வார்ப்புருவைக் காண்க</b></summary>

```bash
# 'omniroute'-க்கான வார்ப்புருக் கோப்பு
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
checksum=009400afee90a9f32599d8fe734145cfd84098140b7287990183dde45ae2245b
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# node-gyp-க்கான இலக்கு CPU கட்டமைப்பைத் தீர்மானிக்கவும்
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) அனைத்து சார்புகளையும் நிறுவவும் – ஸ்கிரிப்ட்களைத் தவிர்க்கவும்
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Next.js தனித்தியங்கும் தொகுப்பை உருவாக்கவும்
	npm run build

	# 3) நிலையான வளங்களைத் தனித்தியங்கும் தொகுப்புக்குள் நகலெடுக்கவும்
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) better-sqlite3 இயல்புநிலை பிணைப்பைத் தொகுக்கவும்
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) தொகுக்கப்பட்ட பிணைப்பைத் தனித்தியங்கும் தொகுப்புக்குள் வைக்கவும்
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) கட்டமைப்பு சார்ந்த sharp தொகுப்புகளை அகற்றவும்
	rm -rf .next/standalone/node_modules/@img

	# 7) Next.js நிலையான பகுப்பாய்வால் விடுபட்ட pino இயக்கநேரச் சார்புகளை நகலெடுக்கவும்:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# நிறுவலுக்குப் பிந்தைய hook மூலம் காலியான Next.js பயன்பாட்டு router அடைவுகள் அகற்றப்படுவதைத் தடுக்கவும்
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

## 🧩 மேம்பட்ட அம்சங்கள்

### தனிப்பயன் மாதிரிகள்

ஆப் புதுப்பிப்புக்காகக் காத்திருக்காமல், எந்த மாதிரி ID-ஐயும் எந்த வழங்குநருக்கும் சேர்க்கலாம்:

```bash
# API வழியாக
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# பட்டியலிட: curl http://localhost:20128/api/provider-models?provider=openai
# நீக்க: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

அல்லது டாஷ்போர்டைப் பயன்படுத்தவும்: **வழங்குநர்கள் → [வழங்குநர்] → தனிப்பயன் மாதிரிகள்**.

குறிப்புகள்:

- OpenRouter மற்றும் OpenAI/Anthropic-இணக்க வழங்குநர்கள் **கிடைக்கக்கூடிய மாதிரிகள்** பிரிவிலிருந்து மட்டுமே நிர்வகிக்கப்படுகின்றன. கைமுறைச் சேர்ப்பு, இறக்குமதி மற்றும் தானியங்கு ஒத்திசைவு அனைத்தும் ஒரே கிடைக்கக்கூடிய-மாதிரி பட்டியலில் சேரும்; எனவே அந்த வழங்குநர்களுக்குத் தனியான தனிப்பயன் மாதிரிகள் பிரிவு இல்லை.
- **தனிப்பயன் மாதிரிகள்** பிரிவு, நிர்வகிக்கப்படும் கிடைக்கக்கூடிய-மாதிரி இறக்குமதிகளை வெளிப்படுத்தாத வழங்குநர்களுக்காக நோக்கப்பட்டது.

### தனிப்பயன் OpenAI-இணக்க வழங்குநர்கள்

OpenAI API-ஐப் பேசும் எந்த நுழைவாயிலும் (சுயமாக ஹோஸ்ட் செய்யப்பட்ட ப்ராக்ஸி, vLLM, மூன்றாம்-தரப்பு ஒருங்கிணைப்பான்)
அதற்கெனத் தனி வழங்குநர் முனையமாகச் சேர்க்கப்படலாம்:

1. **வழங்குநர்கள் → OpenAI Compatible சேர்க்க**.
2. **பெயர்**: முனையத்திற்கான காட்சிப் பெயர்.
3. **முன்னொட்டு**: ரூட்டிங் பெயர். கிளையன்ட்கள் மாதிரிகளை `<prefix>/<model>` என அழைக்கின்றன; எனவே `mygw`
   முன்னொட்டு கொண்ட முனையம் `mygw/gpt-4o-mini`-ஐ வழங்கும். கட்டாயம்; எழுத்து வரம்பு எதுவும் இல்லை.
4. **API வகை**: நுழைவாயில் வழங்கும் முனைப்புக் குடும்பம் (Chat Completions, Responses,
   Embeddings, ஆடியோ, படங்கள்).
5. **Base URL**: `/v1` வரை (`/v1`-ஐ உள்ளடக்கி) API மூலம் (எடுத்துக்காட்டாக
   `https://gateway.example.com/v1`), முழு `/chat/completions` பாதை அல்ல. நிலையானதல்லாத
   பாதைகள் கொண்ட நுழைவாயில்கள் அவற்றை **மேம்பட்ட அமைப்புகள்** கீழ் அமைக்கின்றன (சாட் பாதை, மாதிரிகள் பாதை).
6. **API Key (சோதனைக்காக)** புலம் இணைப்பைச் சோதிக்க மட்டுமே பயன்படுகிறது. முனையத்தை உருவாக்கிய பிறகு,
   அதைத் திறந்து, கோரிக்கைகள் பயன்படுத்தும் விசையைச் சேமிக்க **Add Connection** ஐப் பயன்படுத்தவும்.

முனையம் `openai-compatible-<apiType>-<uuid>` வடிவிலான உள்ளார்ந்த ID-ஐப் பெறுகிறது; அதை நீங்கள் ஒருபோதும்
தட்டச்சு செய்யத் தேவையில்லை, முன்னொட்டே பொது பெயர்.

#### ஒதுக்கப்பட்ட முன்னொட்டுகள்

முன்னொட்டு, உள்ளமைந்த வழங்குநரின் ID அல்லது மாற்றுப் பெயராக (எடுத்துக்காட்டாக `openai`, `cf`) இருக்க முடியாது,
ஓய்வுபெற்ற வழங்குநரின் ID-ஆகவும் இருக்க முடியாது. மாதிரி தீர்வானம், தனிப்பயன் முனையங்களுக்கு முன்னர்
உள்ளமைந்த ID-களையும் மாற்றுப் பெயர்களையும் சரிபார்க்கிறது; எனவே அந்த முன்னொட்டுகளில் ஒன்றைப் பயன்படுத்தும்
முனையம் ஒருபோதும் ட்ராஃபிக்கைப் பெறாது: `<prefix>/model` உள்ளமைந்த வழங்குநருக்கே செல்லும், அல்லது அந்த
வழங்குநர் ஓய்வுபெற்றிருந்தால் மூடிய நிலையில் தோல்வியடையும். அத்தகைய முன்னொட்டுடன் முனையத்தை உருவாக்குவது
அல்லது திருத்துவது பின்வரும் பிழையுடன் நிராகரிக்கப்படும்:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

தனித்துவமான முன்னொட்டைத் தேர்ந்தெடுக்கவும் (`mygw`, `acme-proxy`). தனிப்பயன் முனையத்திற்கான கோரிக்கைகள்
உள்ளமைந்த வழங்குநரையோ அதன் நற்சான்றுகளையோ குறிப்பிடும் பிழையுடன் தோல்வியடைந்தால், முனையத்தின் முன்னொட்டு
ஒதுக்கப்பட்டதா எனச் சரிபார்க்கவும்: இந்த விதி உருவாவதற்கு முன் சேமிக்கப்பட்ட முனையங்கள் இன்னும்
சேமிக்கப்பட்டுள்ளன, ஆனால் அவற்றின் முன்னொட்டு உள்ளமைந்த வழங்குநருக்கு வழிநடத்தப்படுகிறது. முனையத்தைத்
திருத்தி, அதற்குப் புதிய முன்னொட்டு கொடுக்கவும்.

#### இணைப்பு வாரியான நுழைவாயில் விருப்பங்கள்

இந்த விசைகள் இணைப்பின் `providerSpecificData`-வில் செல்கின்றன (எடுத்துக்காட்டாக
`PUT /api/providers/{id}` வழியாக):

- `toolNameMaxLength` (முழு எண், 1–1024) — நீளமான கருவிப் பெயர்களை நிராகரிக்கும் நுழைவாயில் கொண்ட
  OpenAI சாட்-வடிவ இணக்க இணைப்புகளுக்காக. நீளமான பெயர்கள் குறுகிய மாற்றுப் பெயர்களாக அனுப்பப்பட்டு,
  பதிலில் மீண்டும் மீட்டமைக்கப்படுகின்றன.
- `quotaEndpoint` — டாஷ்போர்டு கோட்டா பட்டை மற்றும் கோட்டா-உணர் ரூட்டிங்கிற்காகப் படிக்கப்படும்
  நுழைவாயிலின் கோட்டா/கிரெடிட் முனைப்பு. OpenAI- மற்றும் Anthropic-இணக்க இணைப்புகள் இரண்டிலும்
  செயல்படுகிறது; முழு வடிவமைப்பு `open-sse/services/usage/openaiCompatible.ts`-இல் ஆவணப்படுத்தப்பட்டுள்ளது.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### OmniRoute பீர்களைச் சங்கிலியாக்குதல்

மற்றொரு OmniRoute நுழைவாயிலை **தனிப்பயன் OpenAI-இணக்க** வழங்குநராகச் சேர்க்கலாம். பீரின்
`/v1` அடிப்படை URL-ஐயும், அந்தப் பீர் வெளியிட்ட அர்ப்பணிக்கப்பட்ட, குறைந்த-சலுகை API விசையையும் பயன்படுத்தவும்.

பரஸ்பர அல்லது பல-தாவல் சங்கிலிகளுக்கு, ஒவ்வொரு நுழைவாயிலிலும் தேர்வு-சேர்க்கை லூப் காவலரை இயக்கவும்:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

வெளிப்படையாக அனுமதிப்பட்டியலிடப்பட்ட பீர் URL-க்கு அனுப்பப்பட்ட கோரிக்கைகள் மட்டுமே
`X-OmniRoute-Peer-Trace` தலைப்பைப் பெறுகின்றன. நுழைவாயில், மீண்டும் வந்த இன்ஸ்டன்ஸ் ID அல்லது
தீர்ந்துபோன தாவல் ஒதுக்கீட்டை HTTP `508 Loop Detected` உடன் நிராகரிக்கிறது; சாதாரண அப்ஸ்ட்ரீம்
வழங்குநர்கள் எந்தப் பீர் மெட்டாடேட்டாவையும் பெறுவதில்லை.

பீர் சங்கிலியாக்கம் டேட்டாபேஸ் ரெப்ப்ளிகேஷனோ ஹோஸ்ட் ஃபெயிலோவரோ அல்ல. ஒவ்வொரு நுழைவாயிலும் சுயாதீனமான
SQLite நிலை, கேச்சுகள், விகித எண்ணிக்கைகள் மற்றும் அமர்வுகளை வைத்திருக்கிறது. செயலில்/அமர்வு அல்லது
செயலில்/செயலில் கிடைப்புத்தன்மைக்கு ஹெல்த்-செக் செய்யப்பட்ட ரிவர்ஸ் ப்ராக்ஸி அல்லது கிளையன்ட் ஃபெயிலோவரைப்
பயன்படுத்தவும்; மேலும் ஒரே SQLite டேட்டாபேசை பல இயங்கும் OmniRoute இன்ஸ்டன்ஸ்களில் ஒருபோதும்
மவுண்ட் செய்ய வேண்டாம்.

### அர்ப்பணிக்கப்பட்ட வழங்குநர் வழிகள்

மாதிரி சரிபார்ப்புடன் குறிப்பிட்ட வழங்குநருக்கு நேரடியாகக் கோரிக்கைகளை வழிநடத்தவும்:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

வழங்குநர் முன்னொட்டு இல்லையெனில் தானாகவே சேர்க்கப்படும். பொருந்தாத மாதிரிகள் `400` ஐத் திருப்பும்.

### நெட்வொர்க் ப்ராக்ஸி கட்டமைப்பு

```bash
# குளோபல் ப்ராக்ஸியை அமைக்கவும்
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# வழங்குநர் வாரியான ப்ராக்ஸி
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# ப்ராக்ஸியைச் சோதிக்கவும்
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**முன்னுரிமை:** சாவி-குறிப்பிட்ட → காம்போ-குறிப்பிட்ட → வழங்குநர்-குறிப்பிட்ட → உலகளாவிய → சூழல்.

```bash
curl http://localhost:20128/api/models/catalog
```

### கிளவுட் ஒத்திசைவு

- சாதனங்கள் முழுவதும் வழங்குநர்கள், காம்போக்கள் மற்றும் அமைப்புகளை ஒத்திசைக்கிறது
- timeout + fail-fast உடன் தானியங்கு பின்னணி ஒத்திசைவு
- production-இல் சர்வர்-பக்க `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL`-ஐ விரும்பவும்

### Cloudflare Quick Tunnel

- Docker மற்றும் பிற சுய-ஹோஸ்ட் செய்யப்பட்ட deployment-களுக்கு **Dashboard → Endpoints**-இல் கிடைக்கிறது
- உங்கள் தற்போதைய OpenAI-இணக்க `/v1` endpoint-க்கு அனுப்பும் தற்காலிக `https://*.trycloudflare.com` URL-ஐ உருவாக்குகிறது
- முதல் இயக்கம் தேவைப்படும்போது மட்டுமே `cloudflared`-ஐ நிறுவுகிறது; அடுத்தடுத்த மறுதொடக்கங்கள் அதே நிர்வகிக்கப்பட்ட binary-ஐ மீண்டும் பயன்படுத்தும்
- OmniRoute அல்லது container மறுதொடக்கத்திற்குப் பிறகு Quick Tunnel-கள் தானாக மீட்கப்படாது; தேவைப்படும்போது dashboard-இலிருந்து மீண்டும் இயக்கவும்
- Tunnel URL-கள் தற்காலிகமானவை; tunnel-ஐ நிறுத்தி/தொடங்கும் ஒவ்வொரு முறையும் மாறும்
- கட்டுப்படுத்தப்பட்ட container-களில் சத்தமான QUIC UDP buffer எச்சரிக்கைகளைத் தவிர்க்க, நிர்வகிக்கப்படும் Quick Tunnel-கள் இயல்பாக HTTP/2 transport-ஐப் பயன்படுத்துகின்றன
- நிர்வகிக்கப்பட்ட transport தேர்வை மேலெழுத விரும்பினால் `CLOUDFLARED_PROTOCOL=quic` அல்லது `auto` என அமைக்கவும்
- நிர்வகிக்கப்பட்ட பதிவிறக்கத்திற்குப் பதிலாக முன்னரே நிறுவப்பட்ட `cloudflared` binary-ஐப் பயன்படுத்த விரும்பினால் `CLOUDFLARED_BIN` என அமைக்கவும்
- Cloudflare Quick Tunnel, Tailscale Funnel மற்றும் ngrok Tunnel பேனல்களை **Settings → Appearance**-இல் காட்டலாம் அல்லது மறைக்கலாம். ஒரு பேனலை மறைப்பது ஏற்கெனவே இயங்கும் tunnel-ஐ நிறுத்தாது.

### LLM கேட்வே நுண்ணறிவு (கட்டம் 9)

- **Semantic Cache** — streaming அல்லாத, temperature=0 பதில்களை தானாக cache செய்கிறது (`X-OmniRoute-No-Cache: true` மூலம் தவிர்க்கலாம்)
- **Request Idempotency** — `Idempotency-Key` அல்லது `X-Request-Id` header மூலம் 5 வினாடிகளுக்குள் கோரிக்கைகளை நகல்-நீக்கம் செய்கிறது
- **Progress Tracking** — `X-OmniRoute-Progress: true` header மூலம் opt-in SSE `event: progress` நிகழ்வுகள்

### ரூட்டிங் உத்திகள்

**Dashboard-இல் காணக்கூடிய உத்திகள் (கணக்கு-நிலை ரூட்டிங்):**

| **P2C (Power of Two Choices)** | 2 சீரற்ற கணக்குகளைத் தேர்ந்தெடுத்து, அதில் ஆரோக்கியமானதற்கு ரூட் செய்கிறது — ஆரோக்கிய விழிப்புணர்வுடன் சுமையைச் சமப்படுத்துகிறது |
| **Random**                     | Fisher-Yates shuffle மூலம் ஒவ்வொரு கோரிக்கைக்கும் சீரற்றமாக ஒரு கணக்கைத் தேர்ந்தெடுக்கிறது                                       |
| **Least Used**                 | மிகப் பழமையான `lastUsedAt` timestamp கொண்ட கணக்கிற்கு ரூட் செய்து, ட்ராஃபிக்கைச் சமமாகப் பரப்புகிறது                             |
| **Cost Optimized**             | மிகக் குறைந்த முன்னுரிமை மதிப்பு கொண்ட கணக்கிற்கு ரூட் செய்து, மிகக் குறைந்த-செலவு வழங்குநர்களுக்காக மேம்படுத்துகிறது            |

**மேம்பட்ட காம்போ மற்றும் auto உத்திகள்** (ஒவ்வொரு காம்போவிற்கும் அல்லது `auto/*` முன்னொட்டுகள் மூலம் கட்டமைக்கலாம் — [AUTO-COMBO.md](../routing/AUTO-COMBO.md)-ஐப் பார்க்கவும்):

- `priority` — கண்டிப்பான வரிசை, ஒருபோதும் round-robin செய்யாது
- `weighted` — மாடல் வாரியான எடைகளின் அடிப்படையில் விகிதாசார ட்ராஃபிக் பிரிவு
- `fill-first` — வரம்புகள் எட்டும் வரை முதல் மாடலை முழுவதும் பயன்படுத்தும்
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` மற்றும் `cost-optimized`
- `auto` — அனைத்து வேட்பாளர்களிலும் மதிப்பெண்-உந்துதலுடன்
- `lkgp` (Last Known Good Provider) — கடைசியாக வெற்றி பெற்ற வழங்குநரிடம் பிணைத்து, பின்னர் விதிகளுக்குத் திரும்பும்
- `context-optimized` — மிகப்பெரிய இலவச context சாளரம் கொண்ட மாடலைத் தேர்ந்தெடுக்கிறது
- `context-relay` — அடுத்தடுத்த திருப்பங்களுக்கு நீண்ட-context மாடல்களைச் சங்கிலியாக இணைக்கிறது

#### வெளிப்புற Sticky Session Header

வெளிப்புற session இணைப்பிற்காக (உதாரணமாக, reverse proxy-களுக்குப் பின்னால் இருக்கும் Claude Code/Codex agent-கள்), அனுப்பவும்:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id`-ஐயும் ஏற்று, செயலில் உள்ள session விசையை `X-OmniRoute-Session-Id`-இல் திருப்பித் தருகிறது.

Nginx பயன்படுத்தி underscore வடிவ header-களை அனுப்பினால், இயக்கவும்:

```nginx
underscores_in_headers on;
```

#### Wildcard மாடல் மாற்றுப்பெயர்கள்

மாடல் பெயர்களை மறுவழிச் செய்ய wildcard முறைகளை உருவாக்கவும்:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

Wildcard-கள் `*` (எந்த எழுத்துகளும்) மற்றும் `?` (ஒற்றை எழுத்து) ஆகியவற்றை ஆதரிக்கின்றன.

#### Fallback சங்கிலிகள்

அனைத்துக் கோரிக்கைகளிலும் பொருந்தும் உலகளாவிய fallback சங்கிலிகளை வரையறுக்கவும்:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### பொதுவான வழங்குநர் அமைப்புகள் & ரூட்டிங் முறைகள்

OmniRoute-இல் பல வழங்குநர்களை இணைத்து, அவற்றுக்கு இடையில் ரூட் செய்வதற்கான சில எடுத்துக்காட்டு முறைகள் இங்கே:

#### 1. கோடிங் ஏஜெண்ட் காம்போ: செலவு/வேக ஃபால்பேக்குடன் உயர்நிலை ரீசனிங்

கோடிங் ஏஜெண்டுகளுக்கு (OpenCode, Claude Code, Cursor, Cline) ஏற்றது. ஆரம்பத்தில் ஃபிரான்டியர் ரீசனிங் மாடல்களுக்கு ரூட் செய்து, கோட்டா தீர்ந்துவிட்டால் அல்லது பிழைகள் ஏற்பட்டால் வேகமான கோடிங் மாடல்களுக்கு ஃபால்பேக் செய்கிறது.

- **டாஷ்போர்டு**: காம்போக்கள் → புதிய காம்போ → பெயர்: `agent-coding` → ஸ்ட்ராடஜி: `Priority`
- **மாடல்கள்**:
  1. `claude/claude-sonnet-4-6` (முதன்மை கோடிங் ஏஜெண்ட்)
  2. `openai/gpt-4o` (இரண்டாம் நிலை உயர்-திறன் ஃபால்பேக்)
  3. `deepseek/deepseek-v4-flash` (அதி-செயல்திறன், செலவு-சிக்கனமான ஃபால்பேக்)

```bash
# API வழியாக உதாரணம்
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

API செலவுகளின்றி அப்டைமை அதிகரிக்க, பல ஃப்ரீ-டியர் மற்றும் கீலெஸ் புரோவைடர்களை சங்கிலித் தொடராக இணைக்கிறது.

- **ஸ்ட்ராடஜி**: `Least Used` அல்லது `Round Robin` (கோட்டாக்கள் முழுவதும் லோடைப் பிரித்தளிக்கிறது)
- **மாடல்கள்**:
  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

```bash

omniroute combo create free-stack \
```

### ரெசிலியன்ஸ் & சர்க்யூட் பிரேக்கர்கள்

**டாஷ்போர்டு → அமைப்புகள் → ரெசிலியன்ஸ்** வழியாக கான்ஃபிகர் செய்யவும்.

OmniRoute ஐந்து கூறுகளுடன் புரோவைடர்-நிலை ரெசிலியன்ஸை செயல்படுத்துகிறது:

1. **ரிக்வெஸ்ட் கியூ & பேசிங்** — சிஸ்டம்-நிலை ரிக்வெஸ்ட் ஷேப்பிங்:
   - **ஒரு நிமிடத்திற்கான ரிக்வெஸ்டுகள் (RPM)** — ஒரு அக்கௌன்டிற்கு நிமிடத்திற்கு அதிகபட்ச ரிக்வெஸ்டுகள்
   - **ரிக்வெஸ்டுகளுக்கு இடையேயான குறைந்தபட்ச நேரம்** — ரிக்வெஸ்டுகளுக்கு இடையே மில்லிசெகண்டுகளில் குறைந்தபட்ச இடைவெளி
   - **அதிகபட்ச ஒரேநேர ரிக்வெஸ்டுகள்** — ஒரு அக்கௌன்டிற்கு ஒரே நேரத்தில் அதிகபட்ச ரிக்வெஸ்டுகள்

2. **கனெக்ஷன் கூல்டவுன்** — ரீட்ரை செய்யக்கூடிய தோல்விகளுக்குப் பிறகு ஒரு கனெக்ஷனுக்கான, auth-வகை சார்ந்த கான்ஃபிகுரேஷன்:
   - **அடிப்படை கூல்டவுன்** — ரீட்ரை செய்யக்கூடிய அப்ஸ்ட்ரீம் தோல்விகளுக்கான இயல்புநிலை கூல்டவுன் விண்டோ
   - **அப்ஸ்ட்ரீம் ரீட்ரை குறிப்புகளைப் பயன்படுத்து** — வழங்கப்பட்டிருந்தால் அதிகாரப்பூர்வமான `Retry-After` அல்லது ரீசெட் குறிப்புகளை மதிக்கிறது
   - **அதிகபட்ச பேக்ஆஃப் படிகள்** — மீண்டும் மீண்டும் ஏற்படும் தோல்விகளுக்கான அதிகபட்ச எக்ஸ்போனென்ஷியல் பேக்ஆஃப் நிலை

3. **புரோவைடர் சர்க்யூட் பிரேக்கர்** — எண்ட்-டு-எண்ட் புரோவைடர் தோல்விகளைக் கண்காணித்து, கான்ஃபிகர் செய்யப்பட்ட எச்சரிக்கை வரம்பில் புரோவைடரை டிக்ரேடட் எனக் குறித்து, கான்ஃபிகர் செய்யப்பட்ட தோல்வி வரம்பை அடைந்ததும் பிரேக்கரைத் திறக்கிறது:
   - **டிக்ரேடேஷன் வரம்பு** — `DEGRADED` நிலையில் நுழைவதற்கு முன் தொடர்ச்சியான புரோவைடர் தோல்விகள்
   - **தோல்வி வரம்பு** — `OPEN` நிலையில் நுழைவதற்கு முன் தொடர்ச்சியான புரோவைடர் தோல்விகள்
   - **ரீசெட் டைம்அவுட்** — புரோவைடர் மீண்டும் சோதிக்கப்படுவதற்கு முன்னான நேர விண்டோ
   - **CLOSED** (ஆரோக்கியமானது) — ரிக்வெஸ்டுகள் வழக்கமாகப் பாய்கின்றன
   - **DEGRADED** — அதிகரித்த தோல்விகள் கண்காணிக்கப்படும்போதும் ரிக்வெஸ்டுகள் தொடர்ந்து பாய்கின்றன
   - **OPEN** — மீண்டும் மீண்டும் ஏற்பட்ட தோல்விகளுக்குப் பிறகு புரோவைடர் தற்காலிகமாகத் தடுக்கப்படுகிறது
   - **HALF_OPEN** — புரோவைடர் மீட்கப்பட்டதா எனச் சோதிக்கிறது

   கனெக்ஷன்-ஸ்கோப்டு `429` ரேட் லிமிட்கள் **கனெக்ஷன் கூல்டவுனில்** உள்ளன; அவை புரோவைடர் பிரேக்கரில் கணக்கிடப்படாது.

   புரோவைடர் பிரேக்கரின் ரன்டைம் நிலை **டாஷ்போர்டு → ஹெல்த்** பக்கத்தில் மட்டுமே காட்டப்படுகிறது.

4. **கூல்டவுனுக்காகக் காத்திரு** — ஒவ்வொரு வேட்பாளர் கனெக்ஷனும் ஏற்கனவே கூல்டவுனில் இருந்தால், OmniRoute மிக ஆரம்பகால கூல்டவுனுக்காகக் காத்திருந்து அதே கிளையண்ட் ரிக்வெஸ்டை தானாகவே ரீட்ரை செய்யும்.

5. **ரேட் லிமிட் ஆட்டோ-டிடெக்ஷன்** — அப்ஸ்ட்ரீம் புரோவைடர்கள் தெளிவான காத்திருப்பு விண்டோக்களைத் திருப்பி அனுப்பும்போது, இந்த அமைப்பு இயக்கப்பட்டிருந்தால் அந்த குறிப்புகள் உள்ளூர் கனெக்ஷன் கூல்டவுனை ஓவர்ரைட் செய்யும்.

**புரோ டிப்:** அவுடேஜுக்குப் பிறகு நேரடி புரோவைடர் பிரேக்கர்களை ஆய்வு செய்து ரீசெட் செய்ய **ஹெல்த்** பக்கத்தைப் பயன்படுத்தவும். ரெசிலியன்ஸ் பக்கம் கான்ஃபிகுரேஷனை மட்டுமே மாற்றுகிறது.

### டேட்டாபேஸ் எக்ஸ்போர்ட் / இம்போர்ட்

**டாஷ்போர்டு → அமைப்புகள் → சிஸ்டம் & ஸ்டோரேஜ்**-இல் டேட்டாபேஸ் பேக்கப்புகளை நிர்வகிக்கவும்.

| செயல்                                      | விளக்கம்                                                                                                                                                                               |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **டேட்டாபேசை எக்ஸ்போர்ட் செய்**            | தற்போதைய SQLite டேட்டாபேசை ஒரு `.sqlite` ஃபைலாக டவுன்லோட் செய்கிறது                                                                                                                    |
| **அனைத்தையும் எக்ஸ்போர்ட் செய் (.tar.gz)** | பின்வருவனவற்றை உள்ளடக்கிய முழுமையான பேக்கப் ஆர்க்கைவை டவுன்லோட் செய்கிறது: டேட்டாபேஸ், அமைப்புகள், காம்போக்கள், புரோவைடர் கனெக்ஷன்கள் (கிரெடென்ஷியல்கள் இல்லாமல்), API கீ மெட்டாடேட்டா |
| **டேட்டாபேசை இம்போர்ட் செய்**              | தற்போதைய டேட்டாபேசை மாற்ற ஒரு `.sqlite` ஃபைலை அப்லோட் செய்யவும். `DISABLE_SQLITE_AUTO_BACKUP=true` என அமைக்கப்படாத வரை, இம்போர்ட்டுக்கு முந்தைய பேக்கப் தானாகவே உருவாக்கப்படும்        |

```bash
# API: டேட்டாபேசை எக்ஸ்போர்ட் செய்தல்
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: அனைத்தையும் எக்ஸ்போர்ட் செய்தல் (முழு ஆர்க்கைவ்)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: டேட்டாபேசை இம்போர்ட் செய்தல்
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**இம்போர்ட் வேலிடேஷன்:** இம்போர்ட் செய்யப்பட்ட ஃபைல் ஒருமைப்பாடு (SQLite pragma சோதனை), தேவையான டேபிள்கள் (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) மற்றும் சைஸ் (அதிகபட்சம் 100MB) ஆகியவற்றிற்காகச் சரிபார்க்கப்படுகிறது.

**பயன்பாட்டு சூழ்நிலைகள்:**

- இயந்திரங்களுக்கு இடையே OmniRoute-ஐ மைக்ரேட் செய்தல்
- டிசாஸ்டர் ரிக்கவரிக்காக வெளிப்புற பேக்கப்புகளை உருவாக்குதல்
- டீம் உறுப்பினர்களிடையே கான்ஃபிகுரேஷன்களைப் பகிர்தல் (அனைத்தையும் எக்ஸ்போர்ட் செய் → ஆர்க்கைவைப் பகிர்)

### அமைப்புகள் டாஷ்போர்டு

அமைப்புகள் பக்கம் எளிதான நேவிகேஷனுக்காக **7 டேப்கள்** ஆக ஒழுங்கமைக்கப்பட்டுள்ளது:

| தாவல்               | உள்ளடக்கம்                                                                                                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **பொது**            | கணினி சேமிப்பக கருவிகள், இயல்புநிலை நடத்தை, Endpoint சுரங்கப்பாதை புலப்படும் தன்மை                                                                                                                     |
| **தோற்றம்**         | தீம் கட்டுப்பாடுகள் (ஒளி/இருண்ட/கணினி), பக்கப்பட்டி புலப்படும் தன்மை, Cloudflare/Tailscale/ngrok சுரங்கப்பாதை அட்டைகளுக்கான பேனல் நிலைமாற்றிகள்                                                        |
| **AI**              | சிந்தனை வரவுசெலவு (passthrough / auto-strip / custom / adaptive — [THINKING_BUDGET.md](./THINKING_BUDGET.md) ஐப் பார்க்கவும்), உலகளாவிய கணினி வரியூட்டல், வரியூட்டல் தற்காலிக சேமிப்பு புள்ளிவிவரங்கள் |
| **பாதுகாப்பு**      | உள்நுழைவு/கடவுச்சொல் அமைப்புகள், IP அணுகல் கட்டுப்பாடு, `/models` க்கான API அங்கீகாரம், வழங்குநர் தடுப்பு, வரியூட்டல்-ஊடுருவல் பாதுகாப்பு                                                              |
| **வழிச்செலுத்தல்**  | உலகளாவிய வழிச்செலுத்தல் மூலோபாயம் (Fill First / Round Robin / P2C / Random / Least Used / Cost Optimized), வைல்டுகார்டு மாதிரி மாற்றுப்பெயர்கள், மாற்றுப் பின்னடைவு சங்கிலிகள், காம்போ இயல்புநிலைகள்   |
| **நெகிழ்வுத்தன்மை** | கோரிக்கை வரிசை, இணைப்பு குளிர்வூட்டம், வழங்குநர் முறிப்பான் கட்டமைப்பு மற்றும் குளிர்வூட்டத்திற்காகக் காத்திருக்கும் நடத்தை                                                                            |
| **மேம்பட்டது**      | உலகளாவிய ப்ராக்ஸி கட்டமைப்பு (HTTP/SOCKS5), வழங்குநர் வாரியான ப்ராக்ஸி மேலெழுதல்கள்                                                                                                                    |

பொது தாவல் இனி படிக்க-மட்டும் பதிவு மற்றும் தற்காலிக சேமிப்பு குறிப்புகளை நகலெடுக்காது. தரவுத்தள தக்கவைப்பு மற்றும்
மேம்படுத்தல் அமைப்புகள் `/api/settings/database` வழியாக நிலைத்தன்மை பெறுகின்றன; கைமுறை தற்காலிக சேமிப்பு அழிப்பு
`DELETE /api/cache` ஐப் பயன்படுத்துகிறது. கோரிக்கை மற்றும் ப்ராக்ஸி பதிவு வரிசை வரம்புகள்
`CALL_LOGS_TABLE_MAX_ROWS` மற்றும் `PROXY_LOGS_TABLE_MAX_ROWS` மூலம் கட்டுப்படுத்தப்படுகின்றன.

### செலவுகள் & வரவுசெலவு நிர்வாகம்

**டாஷ்போர்டு → செலவுகள்** வழியாக அணுகவும்.

| தாவல்             | நோக்கம்                                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **வரவுசெலவு**     | ஒவ்வொரு API விசைக்கும் தினசரி/வாராந்திர/மாதாந்திர வரவுசெலவுகள் மற்றும் நிகழ்நேர கண்காணிப்புடன் செலவு வரம்புகளை அமைக்கவும் |
| **விலை நிர்ணயம்** | மாதிரி விலை பதிவுகளைப் பார்க்கவும் திருத்தவும் — ஒவ்வொரு வழங்குநருக்கும் 1K உள்ளீடு/வெளியீடு டோக்கன்களுக்கான செலவு        |

```bash
# API: வரவுசெலவை அமைக்கவும்
curl -X POST http://localhost:20128/api/usage/budget \
  -H "Content-Type: application/json" \
  -d '{"keyId": "key-123", "limit": 50.00, "period": "monthly"}'

# API: தற்போதைய வரவுசெலவு நிலையைப் பெறவும்
curl http://localhost:20128/api/usage/budget
```

**செலவு கண்காணிப்பு:** ஒவ்வொரு கோரிக்கையும் டோக்கன் பயன்பாட்டைப் பதிவு செய்து விலை அட்டவணையைப் பயன்படுத்தி செலவைக் கணக்கிடுகிறது. **டாஷ்போர்டு → பயன்பாடு** இல் வழங்குநர், மாதிரி மற்றும் API விசை வாரியான விவரங்களைப் பார்க்கவும்.

### ஆடியோ எழுத்துப்படியாக்கம்

OmniRoute OpenAI-இணக்கமான இறுதிப்புள்ளி வழியாக ஆடியோ எழுத்துப்படியாக்கத்தை ஆதரிக்கிறது:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# curl உடன் எடுத்துக்காட்டு
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

`deepgram/nova-3` என்பது சொந்தமான Deepgram வழி மற்றும் Deepgram API விசை தேவைப்படுகிறது.
OpenRouter மட்டுமே கட்டமைக்கப்பட்டிருந்தால், `openrouter/deepgram/nova-3` ஐப் பயன்படுத்தவும்.

**பேச்சு-முதல்-உரை (எழுத்துப்படியாக்கம்)** வழங்குநர்கள்:

- `openai/` (whisper-இணக்கமான)
- `groq/` (Groq Whisper Turbo)
- `deepgram/` (Nova குடும்பம்)
- `assemblyai/`
- `nvidia/` (Parakeet, Canary)
- `huggingface/` (whisper மாறுபாடுகள்)
- `qwen/`

**உரை-முதல்-பேச்சு (`POST /v1/audio/speech`)** வழங்குநர்கள்:

- `openai/` (tts-1, tts-1-hd)
- `hyperbolic/`
- `deepgram/` (Aura)
- `nvidia/` (Magpie TTS)
- `elevenlabs/`
- `huggingface/`
- `inworld/`
- `cartesia/`
- `playht/`
- `kie/`
- `aws-polly/`
- `xiaomi-mimo/`
- `coqui/`, `tortoise/`
- `qwen/`

எழுத்துப்படியாக்கத்திற்கு ஆதரிக்கப்படும் ஆடியோ வடிவங்கள்: `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`. TTS வெளியீட்டு வடிவங்கள் வழங்குநரைப் பொறுத்தது (mp3, wav, opus, pcm, mulaw).

### காம்போ இருசமமாக்கல் மூலோபாயங்கள்

**டாஷ்போர்டு → காம்போக்கள் → உருவாக்கு/திருத்து → மூலோபாயம்** இல் காம்போ வாரியான இருசமமாக்கலைக் கட்டமைக்கவும்.

| மூலோபாயம்          | விளக்கம்                                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------ |
| **Round-Robin**    | மாதிரிகள் வழியாக தொடர்ச்சியாக சுழற்றுகிறது                                                                   |
| **Priority**       | எப்போதும் முதல் மாதிரியை முயற்சிக்கிறது; பிழை ஏற்பட்டால் மட்டுமே மாற்றுப் பின்னடைவு                          |
| **Random**         | ஒவ்வொரு கோரிக்கைக்கும் காம்போவிலிருந்து சீரற்ற மாதிரியைத் தேர்ந்தெடுக்கிறது                                  |
| **Weighted**       | ஒவ்வொரு மாதிரிக்கும் ஒதுக்கப்பட்ட எடைகளின் அடிப்படையில் விகிதாசாரமாக வழிச்செலுத்துகிறது                      |
| **Least-Used**     | சமீபத்திய கோரிக்கைகள் மிகக் குறைவாக உள்ள மாதிரிக்கு வழிச்செலுத்துகிறது (காம்போ அளவீடுகளைப் பயன்படுத்துகிறது) |
| **Cost-Optimized** | மலிவான கிடைக்கும் மாதிரிக்கு வழிச்செலுத்துகிறது (விலை அட்டவணையைப் பயன்படுத்துகிறது)                          |

உலகளாவிய காம்போ இயல்புநிலைகள் **டாஷ்போர்டு → அமைப்புகள் → வழிச்செலுத்தல் → காம்போ இயல்புநிலைகள்** இல் அமைக்கப்படலாம்.
காம்போ இலக்கு காலாவதிகள் இயல்புநிலையாக தற்போதைய கோரிக்கை காலாவதியைப் பெறுகின்றன. குறுகிய இலக்கு வாரியான
வரம்பு விரைவான மாற்றுப் பின்னடைவைத் தூண்ட வேண்டுமெனில் மட்டுமே காம்போ இயல்புநிலைகள் அல்லது தனிப்பட்ட காம்போவில்
**இலக்கு காலாவதி (வினாடிகள்)** ஐப் பயன்படுத்தவும்.

பூஜ்ஜிய-தாமத காம்போ மேம்படுத்தல்கள் விருப்பத் தேர்வு (opt-in) ஆகும். இந்த தாமத அம்சங்கள் மாற்றுப் பின்னடைவு
இலக்குகளுடன் போட்டியிடுவதையும், TTFT வரலாற்றின் அடிப்படையில் இலக்குகளைத் தவிர்ப்பதையும், மாற்றுப் பின்னடைவு
கோரிக்கைகளைச் சுருக்குவதையும் தடுக்க **பூஜ்ஜிய-தாமத மேம்படுத்தல்கள்** ஐ முடக்கியே வைக்கவும்; அதை இயக்குவது
கட்டமைக்கப்பட்ட ஹெட்ஜிங், முன்னறிவிப்பு TTFT தவிர்ப்புகள் மற்றும் முன்னெச்சரிக்கை மாற்றுப் பின்னடைவு சுருக்கம்
ஆகியவை குறைந்த வால் தாமதத்திற்காக வழிச்செலுத்தல்/கோரிக்கை நம்பகத்தன்மையை வர்த்தகம் செய்ய அனுமதிக்கிறது.

மேல்நோக்கு (upstream) வழங்குநர்கள் கண்டிப்பான `max_tokens` / `maxOutputTokens` வரம்புகளைக் கோரும்போது **ரீசனிங் டோக்கன் பஃபர்** வசதியை முடக்கவும். இது இயக்கப்பட்டிருக்கும்போது, காம்போ ரூட்டிங் அறியப்பட்ட வெளியீட்டு உச்சவரம்பு உள்ள மாதிரிகளுக்கு மட்டுமே ரீசனிங்-மாடல் கூடுதல் இடைவெளியைச் சேர்க்கும்; பாதுகாப்பான பஃபர் செய்யப்பட்ட மதிப்பு அந்த உச்சவரம்பை மீறிவிடும் போது கிளையன்ட் டோக்கன் வரம்பை மாற்றாமல் விட்டுவிடும். கிளையன்ட் வரம்பு ஏற்கனவே அறியப்பட்ட உச்சவரம்புக்கு மேலே இருந்தால், மேல்நோக்கு கோரிக்கையை அனுப்புவதற்கு முன் OmniRoute அதை அந்த உச்சவரம்பிற்குக் குறைத்துக் கட்டுப்படுத்தும்.

## 🤖 தானியங்கு வழித்தேர்வு (அமைப்புகள் தேவையில்லை)

இணைக்கப்பட்டுள்ள அனைத்து வழங்குநர்களிலும் ஒவ்வொரு கோரிக்கைக்கும் சிறந்த மாதிரியைத் தேர்ந்தெடுக்கும் **மதிப்பெண் அடிப்படையிலான தானியங்கு வழித்தேர்வியுடன்** OmniRoute வழங்கப்படுகிறது — பராமரிக்க வேண்டிய சேர்க்கைகள் எதுவுமில்லை. `auto/*` முன்னொட்டுகளில் ஒன்றைப் பயன்படுத்திக் கோரிக்கையை அனுப்பினால் போதும்; தாமதம், செலவு, வெற்றி விகிதம், சூழல் பொருத்தம், பணிக்கான மாதிரியின் தகுதி, சமீபத்திய தோல்விகள், ஒதுக்கீடு மற்றும் சர்க்யூட்-பிரேக்கர் நிலை ஆகியவற்றின் அடிப்படையில் தேர்வுக்குரியவற்றுக்கு மதிப்பெண் அளித்து, OmniRoute உடனடியாக ஒரு மெய்நிகர் சேர்க்கையை உருவாக்கும்.

| முன்னொட்டு     | மேம்படுத்தப்படுவது                                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `auto`         | சமநிலையான இயல்புநிலை (தாமதம் × செலவு × வெற்றி விகிதம்)                                                                     |
| `auto/coding`  | நிரலாக்கப் பணிகள்: Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek coders ஆகியவற்றுக்கு முன்னுரிமை அளிக்கிறது               |
| `auto/cheap`   | மிகக் குறைந்த $/token; அதிக தாமதத்தை ஏற்கிறது                                                                              |
| `auto/fast`    | மிகக் குறைந்த தாமதம்; செலவைப் புறக்கணிக்கிறது                                                                              |
| `auto/offline` | உள்ளூர் வழங்குநர்கள் மட்டும் (Ollama, vLLM, llama.cpp) — வலையமைப்பிலிருந்து தனிமைப்படுத்தப்பட்ட அமைப்புகளுக்குப் பயனுள்ளது |
| `auto/smart`   | பகுத்தறிவுத் தரத்திற்கு முதலிடம் (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)                                                |
| `auto/lkgp`    | "கடைசியாகச் சிறப்பாகச் செயல்பட்ட வழங்குநர்" — கடைசியாக வெற்றிபெற்ற வழங்குநரைப் பயன்படுத்தி, பின்னர் விதிகளுக்கு மாறுகிறது  |

எடுத்துக்காட்டு:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

தானியங்கு வழித்தேர்வி குறித்த முழு விவரமும் [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ஆவணத்தில் உள்ளது — மதிப்பீட்டு எடைகளைச் சரிசெய்வது, வழங்குநர்களைத் தடுப்புப் பட்டியலில் சேர்ப்பது மற்றும் **Dashboard → Auto Combo** பகுதியில் வழித்தேர்வு முடிவுகளை ஆய்வு செய்வது உள்ளிட்டவை இதில் அடங்கும்.

## 🔌 MCP & A2A ஒருங்கிணைப்பு

OmniRoute ஓர் **MCP சேவையகமாகவும்** (Model Context Protocol), ஓர் **A2A சேவையகமாகவும்** (Agent-to-Agent JSON-RPC 2.0) செயல்படுகிறது. MCP-இணக்கமான எந்த IDE அல்லது முகவர் ஹோஸ்ட்டும் OmniRoute கருவிகளை நேரடியாக அழைக்கலாம் — கூடுதல் உறையாக்கம் எதுவும் தேவையில்லை.

### MCP பரிமாற்ற முறைகள்

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **ஸ்ட்ரீம் செய்யக்கூடிய HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (stdio-ஐ விரும்பும் IDE செருகுநிரல்களுக்கு)

### Claude Desktop-ஐ இணைத்தல்

`~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) கோப்பை அல்லது Windows/Linux-இல் அதற்குச் சமமான கோப்பைத் திருத்தவும்:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCP-ஐ இணைத்தல்

SSE URL `http://localhost:20128/api/mcp/sse` மற்றும் **Dashboard → API Keys** பகுதியில் உருவாக்கப்பட்ட Bearer API விசையைப் பயன்படுத்தவும்.

### அணுகல் வரம்புகள்

MCP தற்போது பெயரிடப்பட்ட 32 அணுகல் வரம்புகளை வரையறுக்கிறது. ஒவ்வொரு Bearer விசையையும் குறிப்பிட்ட அணுகல் வரம்புகளுக்கு மட்டும் கட்டுப்படுத்தலாம் — அதிகாரப்பூர்வ அணுகல் வரம்பு மற்றும் கருவிப் பட்டியலுக்கு [MCP-SERVER.md](../frameworks/MCP-SERVER.md) ஆவணத்தையும், JSON-RPC திட்டவடிவத்திற்கு [A2A-SERVER.md](../frameworks/A2A-SERVER.md) ஆவணத்தையும் பார்க்கவும்.

## 🧠 திறன்கள் அமைப்பு

முகவர்கள் மற்றும் A2A முனைப்புள்ளி, களம் சார்ந்த செயல்முறைகளை (எ.கா. `code-review`, `summarize`, `extract-facts`, `web-research`) இயக்குவதற்காக OmniRoute விரிவாக்கக்கூடிய **திறன் கட்டமைப்பை** (`src/lib/skills/`) வழங்குகிறது.

- **சந்தை பயனர் இடைமுகம்** — **கட்டுப்பாட்டுப் பலகை → திறன்கள்** என்பதிலிருந்து திறன்களை உலாவி நிறுவலாம்
- **ஒவ்வொரு விசைக்குமான வரம்புகள்** — எந்த API விசைகள் எந்தத் திறன்களை அழைக்கலாம் என்பதைக் கட்டுப்படுத்தலாம்
- **தனிப்பயன் திறன்கள்** — `src/lib/a2a/skills/` கோப்பகத்தில் ஒரு TypeScript கோப்பைச் சேர்த்து, அதைப் பதிவுசெய்தால், அது உடனடியாக A2A வழியாக அழைக்கக்கூடியதாகிவிடும்

முழுமையான குறிப்பு: [SKILLS.md](../frameworks/SKILLS.md).

## 💾 நினைவக அமைப்பு

OmniRoute, கலப்பு மீட்டெடுப்புடன் **நீண்டகால உரையாடல் நினைவகத்தை** நிலையாகச் சேமிக்கிறது:

- கடந்தகால உரையாடல் சுற்றுகள் முழுவதிலும் திறவுச்சொல் தேடலுக்காக **SQLite FTS5**
- பொருள்சார் நினைவுகூரலுக்காக **Qdrant vector store** (விருப்பத்தேர்வு)
- **தானியங்கிய உண்மைத் தகவல் பிரித்தெடுப்பு** — ஒவ்வொரு அமர்வுக்குப் பிறகும் பொருள்கள், விருப்பத்தேர்வுகள் மற்றும் முடிவுகள் சுருக்கப்பட்டு `memory_facts` அட்டவணையில் சேமிக்கப்படுகின்றன
- நினைவகங்கள் ஒவ்வொரு API விசை மற்றும் ஒவ்வொரு அமர்வின் அடிப்படையில் வரம்பிடப்படுகின்றன

**கட்டுப்பாட்டுப் பலகை → நினைவகம்** என்பதில் நினைவகங்களை நிர்வகிக்கலாம் (தேடுதல், திருத்துதல், ஏற்றுமதி செய்தல், முற்றிலும் நீக்குதல்). HTTP இடைமுகம் (`/api/memory/*`), முகவர்கள் உண்மைத் தகவல்களை நிரல்முறையாக அனுப்பவும் வினவவும் அனுமதிக்கிறது — [MEMORY.md](../frameworks/MEMORY.md)-ஐப் பார்க்கவும்.

## 🔔 Webhooks

நிகழ்நேரக் கண்காணிப்பு மற்றும் தானியக்கமாக்கலுக்காக OmniRoute நிகழ்வுகளுக்குச் சந்தா சேருங்கள்.

- இலக்கு URL மற்றும் HMAC கையொப்பமிடும் ரகசியத்துடன் **கட்டுப்பாட்டுப் பலகை → Webhooks** என்பதில் ஒரு webhook-ஐ உருவாக்கவும்
- கிடைக்கக்கூடிய நிகழ்வுகள்: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- சரிபார்ப்பிற்காக ஒவ்வொரு தரவுச்சுமையிலும் `X-OmniRoute-Signature` (HMAC-SHA256) இடம்பெறும்
- மறுமுயற்சிகள்: அதிவேகமாக அதிகரிக்கும் தாமதத்துடன் 3 முயற்சிகள், பின்னர் செயலிழந்த செய்திகளுக்கான வரிசை

முழுமையான அமைப்புமுறை [WEBHOOKS.md](../frameworks/WEBHOOKS.md)-இல் உள்ளது.

உங்கள் உள்ளக வழிப்படுத்தலைக் கையாளும் அதே கட்டுப்பாட்டுப் பலகையிலிருந்து நீண்ட நேரம் இயங்கும் பணிகளை அனுப்புவதற்காக, OmniRoute மேகக் குறியீட்டு முகவர்களுடன் (**OpenAI Codex Cloud**, **Devin**, **Jules**, **Antigravity**) ஒருங்கிணைகிறது.

- **கட்டுப்பாட்டுப் பலகை → மேக முகவர்கள்** என்பதிலோ அல்லது `POST /api/v1/agents/tasks` வழியாகவோ பணிகளை உருவாக்கவும்
- ஒவ்வொரு பணிக்குமான நிலை, பதிவுகள் மற்றும் உருவாக்கப்பட்ட வெளியீடுகளைக் கண்காணிக்கவும்
- ஒவ்வொரு வழங்குநருக்கும் உங்கள் சொந்த API விசையைப் பயன்படுத்தலாம் — சான்றுகள் OmniRoute நிகழ்விலிருந்து ஒருபோதும் வெளியேறாது

முழுமையான குறிப்பு: [CLOUD_AGENT.md](../frameworks/CLOUD_AGENT.md).

## 🛠️ நிரல்முறை மேலாண்மை

**`manage` வரம்பைக் கொண்ட Bearer விசையைப்** பயன்படுத்தி, ஒவ்வொரு OmniRoute வளத்தையும் (வழங்குநர்கள், சேர்க்கைகள், விசைகள், அமைப்புகள்) HTTP வழியாக நிர்வகிக்கலாம்.

**கட்டுப்பாட்டுப் பலகை → API விசைகள் → புதிய விசை → வரம்பு: manage** என்பதில் விசையை உருவாக்கிய பின்:

```bash
# வழங்குநர்களைப் பட்டியலிடவும்
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# வழங்குநர் இணைப்பைச் சேர்க்கவும்
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# சேர்க்கையை உருவாக்கவும்
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API விசைகளைப் பட்டியலிடவும்/உருவாக்கவும்
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

முழுமையான முனைப்புள்ளிப் பட்டியல் மற்றும் கோரிக்கை/பதில் அமைப்புமுறைகளுக்கு [API_REFERENCE.md](../reference/API_REFERENCE.md)-ஐப் பார்க்கவும்.

## 💻 உள் CLI

அமைப்பு, நோயறிதல் மற்றும் இயக்கநேரக் கட்டுப்பாட்டிற்காக OmniRoute ஓர் உள் CLI-ஐ (`omniroute …`) வழங்குகிறது. இது மூன்றாம் தரப்பு CLI-கள் (Claude Code, Cursor, Codex, Cline, …) OmniRoute உடன் தொடர்புகொள்ளும் வகையில் அவற்றை உள்ளமைக்கும் டாஷ்போர்டில் உள்ள **"CLI கருவிகள்" பக்கத்திலிருந்து தனிப்பட்டது**.

```bash
omniroute setup                    # ஊடாடும் வழிகாட்டி (கடவுச்சொல், வழங்குநர்கள், சேர்க்கைகள்)
omniroute setup --non-interactive  # CI-க்கு ஏற்றது
omniroute doctor                   # செயல்நிலை நோயறிதல்கள் (தரவுக் கோப்பகம், DB, வழங்குநர்கள், போர்ட்கள்)
omniroute providers available      # ஆதரிக்கப்படும் வழங்குநர்களைப் பட்டியலிடு
omniroute providers list           # உள்ளமைக்கப்பட்ட இணைப்புகளைப் பட்டியலிடு
omniroute providers test <id>      # வழங்குநர் இணைப்பை நேரலையாகச் சோதி
omniroute combos list              # சேர்க்கைகளைப் பட்டியலிடு
omniroute combos switch <name>     # இயல்புநிலைச் சேர்க்கையை அமை
omniroute models                   # கிடைக்கக்கூடிய மாதிரிகளைப் பட்டியலிடு (--json, --search)
omniroute keys add | list | remove # முனையத்திலிருந்து API விசைகளை நிர்வகி
omniroute backup                   # உள்ளமைவு + DB-இன் நிலைப்படத்தை உருவாக்கு
omniroute restore [<timestamp>]    # நிலைப்படத்திலிருந்து மீட்டமை
omniroute health                   # விரிவான செயல்நிலை (தடுப்பான்கள், தற்காலிக சேமிப்பு, நினைவகம்)
omniroute quota                    # வழங்குநரின் ஒதுக்கீட்டுப் பயன்பாடு
omniroute mcp status               # MCP சேவையக நிலை
omniroute a2a status               # A2A சேவையக நிலை
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok சுரங்கங்கள்
omniroute reset-password           # நிர்வாகி கடவுச்சொல்லை மீட்டமை
omniroute --mcp                    # stdio வழியாக MCP சேவையகத்தைத் தொடங்கு
omniroute --port 3000              # தனிப்பயன் போர்ட்டில் சேவையகத்தைத் தொடங்கு
```

உதவிக்குறிப்பு: செயல்நிலையற்ற வழங்குநர் இணைப்புகள் குறித்து எச்சரிக்கை பெற, உங்கள் கண்காணிப்புக் கருவியுடன் `omniroute doctor --json`-ஐ இணைத்துப் பயன்படுத்தவும்.

## 🖥️ டெஸ்க்டாப் பயன்பாடு (Electron)

Windows, macOS மற்றும் Linux-க்கான சொந்த டெஸ்க்டாப் பயன்பாடாக OmniRoute கிடைக்கிறது.

### நிறுவல்

```bash
# electron கோப்பகத்திலிருந்து:
cd electron
npm install

# உருவாக்கப் பயன்முறை (இயங்கிக்கொண்டிருக்கும் Next.js உருவாக்க சேவையகத்துடன் இணைகிறது):
npm run dev

# உற்பத்திப் பயன்முறை (தனித்தியங்கும் கட்டமைப்பைப் பயன்படுத்துகிறது):
npm start
```

### நிறுவிகளை உருவாக்குதல்

```bash
cd electron
npm run build          # தற்போதைய இயங்குதளம்
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg universal)
npm run build:linux    # Linux (.AppImage)
```

வெளியீடு → `electron/dist-electron/`
