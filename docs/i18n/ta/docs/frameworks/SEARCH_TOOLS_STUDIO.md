## தாவல்கள்

### தேடல் தாவல்

தற்போதுள்ள `SearchForm` + `ResultsPanel` + `RerankPanel` ஒரு தாவலாக மாற்றுகிறது:

- வினவல் → முடிவுகள் (தலைப்பு, URL, துணுக்கு, பொருத்தமான மதிப்பெண்).
- கட்டமைப்பு பலகத்தில் வழங்குநர் மெட்டாடேட்டா (செலவு, ஒதுக்கீடு, நிலை).
- பிரிவை மறுவரிசைப்படுத்து: மறுவரிசை மாதிரியைத் தேர்ந்தெடுக்கவும், முடிவுகளை மறுவரிசைப்படுத்தவும், `positionDelta` ஐக் காட்டு .
- தேடல் வழங்குநர்கள் கட்டமைக்கப்படாதபோது CTA உடன் வெற்று நிலை.
- `SearchHistory.tsx` வழியாக தேடல் வரலாறு.
- `POST /v1/search` அழைக்கிறது (தற்போதுள்ள இறுதிப்புள்ளி, மாற்றங்கள் இல்லை).

### ஸ்க்ரேப் தாவல்

`POST /v1/web/fetch` வழியாக URL இலிருந்து உள்ளடக்கத்தைப் பிரித்தெடுப்பதற்கான புதிய தாவல் (திட்டம் 05 இல் உருவாக்கப்பட்டது):

- உள்ளீடு: URL + முழுப் பக்கத்தை மாற்று + வடிவமைப்பு தேர்வி (markdown / text / HTML).
- → பெறு → ரெண்டர் `ScrapeResult.tsx` சமர்ப்பிக்கவும்.
- `ScrapeResult` மார்க் டவுன் முன்னோட்டத்தை + raw toggle ஐ வழங்குகிறது.
- தொப்பி: பதில் உடல் > என்றால்** 256 KB** , UI `(truncated, view raw)` ஐக் காட்டுகிறது மற்றும் மொனாக்கோ மாடலில் (D21) பச்சையாகத் திறக்கிறது.
- மெட்டாடேட்டா குழு: வழங்குநர் (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search), தாமதம், செலவு, பதில் அளவு, இணைப்புகளின் எண்ணிக்கை.
- `useScrapeFetch.ts` ஹூக்கைப் பயன்படுத்துகிறது.

### தாவலை ஒப்பிடுக

வரை ஒரே query/URL முழுவதும் இயங்கும்** இணையாக 4 வழங்குநர்கள்** (D22):

- ஒரு வழங்குநருக்கு அருகருகே நெடுவரிசைகள்.
- அளவீடுகள்: தாமதம், செலவு, முடிவு எண்ணிக்கை, பதில் அளவு.
- தேடலுக்கான URL ஒன்றுடன் ஒன்று கணக்கீடு (பகிரப்பட்ட URLs மற்றும் ஆரம்ப முடிவுகளின் எண்ணிக்கை).
- ஒரு வழங்குநருக்கு `POST /v1/search` (தேடல்) அல்லது `POST /v1/web/fetch` (ஸ்க்ரேப்) அழைப்புகள்.

## வழங்குநர் பட்டியல்

`ProviderCatalog.tsx` `GET /api/search/providers` இலிருந்து முழு வழங்குநர் பட்டியலை வெளிப்படுத்துகிறது (F4 இல் நீட்டிக்கப்பட்ட வழங்குநர்களை உள்ளடக்கியது):

| `kind` | `"search"` (24 வழங்குநர்கள்) அல்லது `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search, parallel-search, keenable-search) |

நிலை உள்ளது** கோரிக்கை நேரத்தில் பெறப்பட்டது** நற்சான்றிதழ்கள் உள்ளதா மற்றும் அனைத்து விசைகளும் தற்போது கூல்டவுனில் உள்ளனவா என்பதைச் சரிபார்ப்பதன் மூலம்.

`codex-search` (Codex வலைத் தேடல்) க்கு அதன் சொந்த விசை இல்லை: இது இணைக்கப்பட்ட Codex (ChatGPT) கணக்கை மீண்டும் பயன்படுத்துகிறது, எனவே ஒவ்வொரு தேடலும் ChatGPT சந்தா ஒதுக்கீட்டைச் செலவழித்து சுமார் 10-40 வினாடிகள் ஆகும். கோரிக்கை பெயரிடும்போது அது இயங்கும்; தானியங்கி தேர்வுக்கு `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` அம்சக் கொடி தேவை (இயல்புநிலையாக ஆஃப்).

## பின்தள மாற்றங்கள்

இந்த அம்சத்திற்கு ஒரே ஒரு பின்தளத்தில் மாற்றம் தேவை:

### நீட்டிக்கப்பட்ட `GET /api/search/providers`

`src/app/api/search/providers/route.ts` நீட்டிக்கப்பட்டது:

- ஒவ்வொரு பெறுதல் வழங்குநரையும் (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`, `keenable-search`) அணிவரிசையில் சேர்க்கவும்.
- ஒவ்வொரு பொருளுக்கும் `kind: "search" | "fetch"` சேர்க்கவும்.
- நேரடி நற்சான்றிதழ் நிலையிலிருந்து பெறப்பட்ட `status: "configured" | "missing" | "rate_limited"` சேர்க்கவும்.
- பின்தங்கிய இணக்கத்தன்மை — இருக்கும் புலங்களை (`id`, `name`, முதலியன) மாறாமல் பராமரிக்கவும்.
