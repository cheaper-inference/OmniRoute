> **உண்மைக்கான ஆதாரம்:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, மற்றும்
> `src/app/(dashboard)/dashboard/plugins/`
> **கடைசியாகப் புதுப்பிக்கப்பட்டது:** 2026-06-28 — v3.8.40

OmniRoute, WordPress பாணியிலான செருகுநிரல் அமைப்புடன் வழங்கப்படுகிறது. செருகுநிரல்கள் தன்னிறைவான
கோப்பகங்கள் — ஒவ்வொன்றிலும் ஒரு `plugin.json` மேனிஃபெஸ்ட் மற்றும் ஒரு நுழைவுக் கோப்பு இருக்கும் — அவை
கோரிக்கை செயலாக்கத் தொடரிலும் (`onRequest` / `onResponse` / `onError`), மேலும்
வாழ்க்கைச்சுழற்சி நிகழ்வுகளிலும் (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
இணைகின்றன.

**செருகுநிரல் சந்தை** என்பது அந்த அமைப்பின் மேலுள்ள கண்டறிதல் அடுக்காகும். இது
நிறுவக்கூடிய செருகுநிரல்களின் உலாவக்கூடிய பட்டியலை வழங்குகிறது. இயல்பாக, இந்தப் பட்டியல்
உள்ளமைந்த சிறிய தொடக்கப் பதிவகமாக இருக்கும்; ஓர் இயக்குநர் இதைத் தனிப்பயன் தொலைநிலைப்
பதிவக URL-க்குச் சுட்டிக்காட்டலாம். அப்படிச் செய்தால், DNS-தீர்மானிக்கும் SSRF பாதுகாப்பு
மூலம் பெறுதல் வலுப்படுத்தப்படும் ([பாதுகாப்பு](#security) என்பதைப் பார்க்கவும்).

ஒவ்வொரு செருகுநிரல் வழித்தடமும் **லூப்பேக் மட்டும்** (அடுக்கு 1 — `LOCAL_ONLY`): செருகுநிரல்கள்
துணைச் செயல்முறைகளில் குறியீட்டை ஏற்றி இயக்குவதால், அங்கீகாரத்தைப் பொருட்படுத்தாமல் லூப்பேக்
அல்லாத தோற்றுவாயிலிருந்து இந்த வழித்தடங்களை அணுக முடியாது.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) என்பதைப் பார்க்கவும்.

## இது Together எவ்வாறு பொருந்துகிறது

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **பதிவு அடுக்கு** — `src/lib/plugins/marketplace.ts`: பட்டியலைப் பட்டியலிடுகிறது / தேடுகிறது, ஏதேனும் தோல்வி ஏற்பட்டால் மீண்டும் விதைப் பதிவேட்டில் விழும்.
- **வாழ்க்கை சுழற்சி அடுக்கு** — `src/lib/plugins/manager.ts` (`pluginManager` singleton): நிறுவுதல், மேம்படுத்துதல், செயல்படுத்துதல், செயலிழக்கச் செய்தல், நிறுவல் நீக்குதல், ஸ்கேன், தொடக்க ஏற்றுதல்.
- **மேனிஃபெஸ்ட் லேயர்** — `src/lib/plugins/manifest.ts`: `plugin.json` க்கான Zod ஸ்கீமா + இயல்புநிலைகள்.
- **ஸ்கேனர்** — `src/lib/plugins/scanner.ts`: செருகுநிரல் கோப்பகத்தின் கீழ் வட்டில் உள்ள செருகுநிரல்களைக் கண்டறியும்.
- **ஏற்றி** — `src/lib/plugins/loader.ts`: ஒவ்வொரு செருகுநிரலையும் தனித்தனியான Node.js குழந்தை செயல்முறையில் உருவாக்குகிறது மற்றும் தரகர்கள் IPC மீது அழைப்புகளை இணைக்கின்றனர். குழந்தை சாண்ட்பாக்ஸ் அல்ல (கீழே உள்ள "சொருகி செயல்படுத்தல் தனிமைப்படுத்தல்" ஐப் பார்க்கவும்).

## சந்தைப் பட்டியல்

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) `MarketplaceEntry`
பொருட்களின் பட்டியலை வழங்குகிறது:

| புலம்         | வகை      | குறிப்புகள்                                     |
| ------------- | -------- | ----------------------------------------------- |
| `name`        | string   | kebab-case செருகுநிரல் பெயர்                    |
| `version`     | string   | semver                                          |
| `description` | string   | சுருக்கமான விளக்கம்                             |
| `author`      | string   | ஆசிரியர் / நிறுவனம்                             |
| `license`     | string   | SPDX பாணியிலான உரிம அடையாளம்                    |
| `downloadUrl` | string   | மூலப் பதிவிறக்க URL (காலியாக இருக்கலாம்)        |
| `repository`  | string?  | விருப்பத்தேர்வு களஞ்சிய URL                     |
| `tags`        | string[] | தேடல்/வடிகட்டல் குறிச்சொற்கள்                   |
| `downloads`   | number   | பதிவிறக்க எண்ணிக்கை                             |
| `rating`      | number   | 0–5                                             |
| `verified`    | boolean  | பதிவு சரிபார்க்கப்பட்டதாகக் குறிக்கப்பட்டுள்ளதா |
| `lastUpdated` | string   | ISO போன்ற தேதி சரம்                             |

தனிப்பயன் பதிவக URL எதுவும் உள்ளமைக்கப்படாதபோது, பட்டியல் உள்ளமைந்த
`SEED_REGISTRY` ஆகும் (தற்போது `request-logger`, `rate-limiter`, `cost-tracker`, மற்றும்
`theme-manager`). தொடக்கப் பதிவகம் எப்போதும் கிடைக்கும் — உள்ளமைக்கப்பட்ட தொலைநிலைப்
பதிவகத்தை அணுக முடியாவிட்டாலோ, அது `200` அல்லாத நிலையை வழங்கினாலோ, அல்லது
அடையாளம் காணப்படாத உள்ளடக்கத்தை வழங்கினாலோ, `listMarketplacePlugins()` ஓர்
எச்சரிக்கையைப் பதிவுசெய்து தொடக்கப் பட்டியலைப் பயன்படுத்தும்.

> குறிப்பு: சந்தை **பட்டியல்** (உலாவுதல்/தேடுதல்) முழுமையாக ஒருங்கிணைக்கப்பட்டுள்ளது, ஆனால்
> பட்டியலிலிருந்து ஒரே கிளிக்கில் செய்யும் சந்தை **நிறுவல்** இன்னும் செயல்படுத்தப்படவில்லை —
> சந்தைப் பதிவிலுள்ள முகப்புப்பலகையின் "நிறுவு" பொத்தான் தற்போது
> "விரைவில் வருகிறது" என்ற அறிவிப்பைக் காட்டுகிறது. தற்போது நிறுவல், உள்ளூர் பாதை நிறுவல்
> செயல்முறை (`POST /api/plugins`) மற்றும் வட்டிலுள்ளவற்றைக் கண்டறிதல்
> (`POST /api/plugins/scan`) வழியாக நடைபெறுகிறது.

## REST API

அனைத்து இறுதிப்புள்ளிகளுக்கும் மேலாண்மை அங்கீகாரம் தேவை (`requireManagementAuth`)** மற்றும்** loopback-only — `/api/plugins` மற்றும் `/api/plugins/` ஆகியவை `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) இல் பட்டியலிடப்பட்டுள்ளன.

| இறுதிப்புள்ளி                    | முறை   | விளக்கம்                                                                           |
| -------------------------------- | ------ | ---------------------------------------------------------------------------------- |
| `/api/plugins`                   | GET    | நிறுவப்பட்ட செருகுநிரல்களைப் பட்டியலிடுங்கள் (விரும்பினால் `?status=` வடிகட்டி)    |
| `/api/plugins`                   | POST   | செருகுநிரல் மூலங்கள் கோப்பகத்திலிருந்து ஒரு செருகுநிரலை நிறுவவும்                  |
| `/api/plugins/scan`              | POST   | செருகுநிரல் கோப்பகத்தை ஸ்கேன் செய்து புதிய செருகுநிரல்களை பதிவு செய்யவும்          |
| `/api/plugins/marketplace`       | GET    | சந்தை பட்டியல் உள்ளீடுகளை பட்டியலிடுங்கள்                                          |
| `/api/plugins/[name]`            | GET    | நிறுவப்பட்ட செருகுநிரல் விவரங்களைப் பெறவும்                                        |
| `/api/plugins/[name]`            | DELETE | செருகுநிரலை நிறுவல் நீக்கவும்                                                      |
| `/api/plugins/[name]/activate`   | POST   | செயல்படுத்து ( + பதிவு கொக்கிகளை ஏற்றவும்)                                         |
| `/api/plugins/[name]/deactivate` | POST   | செயலிழக்கச் செய் (தீ `onDeactivate`, கொக்கிகளை பதிவுநீக்கு)                        |
| `/api/plugins/[name]/config`     | GET    | சொருகி config + config ஸ்கீமாவைப் பெறுங்கள்                                        |
| `/api/plugins/[name]/config`     | PUT    | செருகுநிரல் கட்டமைப்பைப் புதுப்பிக்கவும் (திட்டத்திற்கு எதிராக சரிபார்க்கப்பட்டது) |

`GET /api/plugins` `status` வடிப்பான் `installed` / `active` / `inactive` / `error` இல் ஒன்றை ஏற்றுக்கொள்கிறது. தவறான மதிப்பு `400` ஐ வழங்குகிறது.

### நிறுவப்பட்ட செருகுநிரல்களை பட்டியலிடுங்கள்

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### உள்ளூர் பாதையிலிருந்து நிறுவவும்

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` கண்டிப்பாக an ஆக இருக்க வேண்டும்** முழுமையான** கோப்பகத்திற்கான பாதை** செருகுநிரல் மூலங்கள் கோப்பகத்தின் உள்ளே** : `plugin-sources` செருகுநிரல் ரூட்டிற்கு அடுத்ததாக, முன்னிருப்பாக `~/.omniroute/plugin-sources/`, அல்லது அந்த மாறி அமைக்கப்படும் போது `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` (`getPluginSourcesDir()` இல் `src/lib/plugins/installSource.ts`). முதலில் அங்குள்ள சொருகியை நகலெடுக்கவும் அல்லது குளோன் செய்யவும். பாதையில் `..` அல்லது ஒரு பூஜ்ய பைட் இருந்தால், அந்த கோப்பகத்திற்கு வெளியே இருக்கும் போது, அதற்கு வெளியே ஒரு சிம்லிங்க் மூலம் தீர்க்கப்படும், அதற்கு வெளியே இலக்கைக் கொண்டிருக்கும் சிம்லிங்க் அல்லது அடைவு இல்லாதபோது நிறுவல் `400` உடன் நிராகரிக்கப்படுகிறது. மூல கோப்பகத்தில் சரியான `plugin.json` இருக்க வேண்டும் (அல்லது ஒருவரின் பெற்றோராக இருக்க வேண்டும்). நிறுவப்பட்ட செருகுநிரல் வரிசையுடன் `201` வெற்றியின் பதில்.

மற்ற செருகுநிரல் வழிகளைப் போலல்லாமல், உள்நுழைவு முடக்கப்பட்டிருந்தாலும் (`requireLogin=false`) நிர்வாகச் சான்று (டாஷ்போர்டு அமர்வு அல்லது மேலாண்மை-நோக்கமுள்ள API விசை) இதற்கு தேவைப்படுகிறது: குறியீட்டை நிறுவுவது ஒரு அநாமதேய செயலாக இருக்காது.

### சந்தையை உலாவவும்

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### செருகுநிரல் கட்டமைப்பைப் புதுப்பிக்கவும்

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` சொருகியின் `configSchema` க்கு எதிராக வழங்கப்பட்ட ஒவ்வொரு மதிப்பையும் சரிபார்க்கிறது (மேனிஃபெஸ்ட்டில் அறிவிக்கப்பட்டது): `number` புலங்கள் மரியாதை `min`/`max`, `select` புலங்கள் அறிவிக்கப்பட்ட `enum` உடன் பொருந்த வேண்டும். திட்டத்தில் இல்லாத விசைகள் அனுமதிக்கப்படும்.

## உள்ளமைவு

### Plugin கோப்பகம்

Plugin-கள் OmniRoute தரவுக் கோப்பகத்தின் கீழ் உள்ளன:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (அல்லது manifest.main சுட்டிக்காட்டும் வேறு ஏதேனும் கோப்பு)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) அந்தக் கோப்பகத்தை
மூன்று படிகளில் தீர்மானிக்கிறது:

1. **`OMNIROUTE_PLUGINS_DIR`**, அமைக்கப்பட்டிருந்தால் — `HOME` என்ன சொன்னாலும், அப்படியே பயன்படுத்தப்படும். இது
   Docker/K8s-க்கான வெளிப்படையான கட்டுப்பாடாகும்; அங்கு plugin tree பொதுவாக container-இன் home கோப்பகத்துடன்
   தொடர்பில்லாத ஒரு பாதையில் bind-mount செய்யப்படுகிறது (#11827).
2. `<home>/.omniroute/plugins`; இங்கு `<home>` என்பது `HOME` / `USERPROFILE`
   சூழல் மாறிகளிலிருந்து பெறப்படுகிறது.
3. process எந்த home-ஐயும் export செய்யாதபோது, `/tmp/.omniroute/plugins`.

தீர்மானிக்கப்பட்ட கோப்பகம் startup-இல் `scanner.dir_resolved` என ஒருமுறை பதிவு செய்யப்படுகிறது; அதில்
தேர்வான input (`OMNIROUTE_PLUGINS_DIR`, `home`, அல்லது `no-home-fallback`) குறிப்பிடப்படும் — இதனால் ஒரு image
அமைதியாகப் படி 3-க்குச் சென்றால், வெற்று plugin பட்டியலை மட்டும் தெரிவிப்பதற்குப் பதிலாக அதையும் குறிப்பிடும்.
`POST /api/plugins/scan`, அங்கு செல்லுபடியாகும்
`plugin.json`-ஐக் கொண்டிருக்கும் எந்த subdirectory-யையும் கண்டறிந்து பதிவுசெய்கிறது; அதே கோப்பகமே
`pluginManager.install()` plugin-களை நகலெடுக்கும் root ஆகும், எனவே override ஒன்று discovery மற்றும்
installation ஆகிய இரண்டையும் ஒன்றாக நகர்த்தும்.

> **`OMNIROUTE_PLUGINS_DIR` என்பது `OMNIROUTE_PLUGIN_PATH` அல்ல.** பின்னையது
> `omniroute` subcommand-களைச் சேர்க்கும் `omniroute-cmd-*` npm package-களைக் கண்டறிவதற்காக CLI command-plugin loader (`bin/cli/plugins.mjs`) மூலம் மட்டுமே படிக்கப்படுகிறது —
> இங்கு விவரிக்கப்பட்டுள்ள runtime scanner மீது அதற்கு எந்தத் தாக்கமும் இல்லை.
> அந்தப் பகுதியைப் பற்றி அறிய [PLUGINS.md](./PLUGINS.md)-ஐப் பார்க்கவும்.

### தனிப்பயன் marketplace registry URL

marketplace catalog மூலம் `pluginMarketplaceUrl` setting-இலிருந்து படிக்கப்படுகிறது
(`src/lib/plugins/marketplace.ts`, `settings.pluginMarketplaceUrl`-ஐப் படிக்கிறது). அது
ஒரு `http(s)` URL-ஆக அமைக்கப்பட்டிருக்கும்போது, `listMarketplacePlugins()` அந்த URL-ஐப் பெற்று,
மேல் மட்ட JSON entry array ஒன்றையோ அல்லது `plugins` array கொண்ட object ஒன்றையோ ஏற்கிறது;
string `name` இல்லாத entry-கள் வடிகட்டப்படுகின்றன. அமைக்கப்படாதபோது (அல்லது fetch
SSRF guard-இல் தோல்வியடைந்தால் / தவறான response-ஐத் திருப்பினால்), உள்ளமைந்த seed registry
பயன்படுத்தப்படுகிறது.

dashboard-இன் "Marketplace" tab இந்த URL-க்கான புலத்தை வழங்குகிறது (`GET /api/settings`-இலிருந்து
மீண்டும் படிக்கப்படுகிறது).

> செயலாக்கக் குறிப்பு: dashboard-இன் "Save" செயல்
> `pluginMarketplaceUrl`-ஐ `PATCH /api/settings`-க்கு அனுப்புகிறது. இதை எழுதும் நேரத்தில், இந்த
> key `updateSettingsSchema`-வில் அறிவிக்கப்படவில்லை
> (`src/shared/validation/settingsSchemas.ts`), எனவே இதைச் சார்ந்திருப்பதற்கு முன் உங்கள்
> release-இல் persistence-ஐச் சரிபார்க்கவும் — settings store-இல் key வந்தவுடன் **read**
> பாதை (`getSettings()` →
> `listMarketplacePlugins()`) அதை மதிக்கிறது.

## பாதுகாப்பு

### பாதை அடுக்கு — லூப்பேக் மட்டும்

செருகுநிரல்கள் முட்டையிடப்பட்ட குழந்தை செயல்முறைகளில் குறியீட்டை செயல்படுத்துகின்றன, எனவே முழு `/api/plugins` மேற்பரப்பும் `LOCAL_ONLY` (அடுக்கு 1) வகைப்படுத்தப்படுகிறது. லூப்பேக் அமலாக்கம் நிபந்தனையின்றி இயங்குகிறது** முன்** எந்த அங்கீகாரச் சரிபார்ப்பும், அதனால் ஒரு சுரங்கப்பாதையில் உள்ள பெட்டியை அடையும் கசிந்த மேலாண்மை டோக்கன் இன்னும் செருகுநிரலை நிறுவவோ, செயல்படுத்தவோ அல்லது நிறுவல் நீக்கவோ முடியாது. [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) மற்றும் கடினமான விதிகள் #15 / #17 ஐப் பார்க்கவும்.

### சந்தைப் பதிவு SSRF காவலர்

தனிப்பயன் பதிவேட்டில் URL என்பது தாக்குபவர்-செல்வாக்கு செலுத்தக்கூடிய உள்ளமைவாகும், எனவே அதைப் பெறுவதற்கு முன் `listMarketplacePlugins()` அதை இரண்டு அடுக்குகளில் இயக்குகிறது:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` இல்லாத எதையும் நிராகரிக்கிறது.
   - நேரடியான private/loopback/link-local/ULA ஹோஸ்ட்களை நிராகரிக்கிறது (IPv4** மற்றும்** IPv6, IPv4-mapped உட்பட) நியமன `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) வழியாக.
   - தீர்க்கிறது** இரண்டும்** `A` மற்றும் `AAAA` பதிவு செய்து நிராகரித்தால்** ஏதேனும்** தீர்க்கப்பட்ட முகவரி தனிப்பட்ட — ஆகும், இது பொது ஹோஸ்ட்பெயரான → private-IP பைபாஸை மூடுகிறது.
   - **தோல்வி அடைகிறது** : ஒரு DNS தீர்மானம் தோல்வி URL ஐ நிராகரிக்கிறது.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): பெறும் நேரத்தில் பொது-மட்டும் URL காவலரை மீண்டும் பயன்படுத்துகிறது மற்றும்** வழிமாற்றுகளைத் தடுக்கிறது** (பொது → தனியார் `30x` பிவோட் இல்லை).

எந்த அடுக்கிலும் தோல்வியுற்ற URL கோரிக்கையை நிறுத்தாது — சந்தை அமைதியாக உள்ளமைக்கப்பட்ட விதைப் பதிவேட்டில் வந்து எச்சரிக்கையைப் பதிவு செய்கிறது.

> இந்த காவலர் குறிப்பாக A + AAAA தீர்க்க PR #3774 இல் கடினமாக்கப்பட்டது மற்றும் IPv4-only சரிபார்ப்புக்கு பதிலாக நியமன `isPrivateHost` பயன்படுத்துகிறது.

### செருகுநிரல் செயல்படுத்தல் தனிமைப்படுத்தல்

> **செருகுநிரல்கள் சாண்ட்பாக்ஸ் செய்யப்படவில்லை.** குழந்தை என்பது OmniRoute பயனராக இயங்கும் ஒரு சாதாரண Node.js செயல்முறையாகும், VM சூழல் மற்றும் Node.js அனுமதிக் கொடிகள் இல்லை, எனவே செருகுநிரல் குறியீடு பயனரால் எந்த கோப்பையும் படிக்கவும் எழுதவும் முடியும், நிரல்களை இயக்கவும் மற்றும் பிணையத்தை அடையவும் முடியும். குழந்தை பெறும் சூழல் மாறிகளை மட்டுமே `requires.permissions` தீர்மானிக்கிறது; மற்ற அனுமதிகள் செயல்படுத்தப்படவில்லை. நீங்கள் நம்பும் செருகுநிரல்களை மட்டும் நிறுவவும். கீழே உள்ள செயல்முறை எல்லையில் செயலிழப்புகள் மற்றும் செயலிழப்புகள் உள்ளன; அது ஒரு பாதுகாப்பு எல்லை அல்ல.

- **செயல்முறை தனிமைப்படுத்தல்** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ஒவ்வொரு செருகுநிரலையும் தனித்தனி Node.js குழந்தை செயல்முறையில் உருவாக்குகிறது மற்றும் IPC மூலம் தொடர்பு கொள்கிறது. ஹூக் அழைப்புகள் `SIGTERM` → `SIGKILL` அதிகரிப்புடன் காலாவதியாகும்.
- **Env அனுமதிப்பட்டியல்** — குழந்தை அனுமதிக்கப்படும் சூழல் மாறிகளின் தொகுப்பை மட்டுமே பெறுகிறது; மேனிஃபெஸ்ட் `env` அனுமதியைக் கோரும் போது மட்டுமே பரந்த தொகுப்பு வழங்கப்படும்.
- **மூலக் கட்டுப்பாட்டை நிறுவவும்** — `POST /api/plugins` செருகுநிரல் மூலங்களின் கோப்பகத்திலிருந்து மட்டுமே படிக்கிறது ("உள்ளூர் பாதையிலிருந்து நிறுவு" என்பதைப் பார்க்கவும்): பாதையானது `realpath` உடன் நியமனம் செய்யப்பட்டுள்ளது, அந்த கோப்பகத்தின் உள்ளே கண்டிப்பாக இருக்க வேண்டும், மேலும் ஒரு சிம்லிங்கை எடுத்துச் செல்லும் ஒரு மூல மரம் எதையும் நகலெடுக்கும் முன் மறுக்கப்படுகிறது.
- **பாதை கட்டுப்பாடு** — install/upgrade/uninstall செருகுநிரல் கோப்பகம் மற்றும் `manifest.main` தீர்க்கும் என்று உறுதியளிக்கிறது** உள்ளே** எந்த நகல் அல்லது மறுசுழற்சி நீக்குதலுக்கும் முன் நிர்வகிக்கப்படும் செருகுநிரல் ரூட் (சேதமடைந்த DB பாதைகள் மற்றும் `manifest.main` இல் `../` ட்ராவர்சல் ஆகியவற்றிற்கு எதிராக பாதுகாக்கிறது). செயல்படுத்தல் `realpath` வழியாக சிம்லிங்க்களைத் தீர்க்கிறது மற்றும் செருகுநிரல் கோப்பகத்தில் இருந்து வெளியேறும் நுழைவுப் புள்ளியை ஏற்ற மறுக்கிறது.
- **விருப்ப ஒருமைப்பாடு முள்** — ஒரு மேனிஃபெஸ்ட் ஒரு `integrity` (`sha256-<base64>`, SRI வடிவம்) புலத்தை அறிவிக்கலாம். இருக்கும் போது, ஏற்றும் நேரத்தில் உள்ளீடு கோப்பு ஹாஷை ஏற்றி சரிபார்த்து, பொருந்தாத நிலையில் செயல்படுத்த மறுக்கிறது. இது டேம்பர்-கண்டறிதல் தேர்வு,** இல்லை** ஒரு பாதுகாப்பு எல்லை: ஏற்றப்பட்ட செருகுநிரல் என்ன செய்ய முடியும் என்பதை இது கட்டுப்படுத்தாது.
- **கொக்கிகளில் வாடிக்கையாளர் சான்றுகள் இல்லை** — `onRequest`, `onResponse` மற்றும் `onError` க்கு அனுப்பப்பட்ட சூழல் `authorization`, `x-api-key`, `proxy-authorization` மற்றும் `cookie` தலைப்புகள் அகற்றப்பட்டது, மேலும் API விசை பதிவு எந்த முக்கிய மதிப்பையும் கொண்டிருக்கவில்லை ( `src/lib/plugins/hooks.ts` இல்`redactPluginContext()` ).

## மேனிஃபெஸ்ட் (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) மூலம் சரிபார்க்கப்பட்டது:

| களம்               | வகை       | குறிப்புகள்                                                          |
| ------------------ | --------- | -------------------------------------------------------------------- |
| `name`             | சரம்      | தேவை; kebab-case (`^[a-z0-9-]+$`), 1–100 எழுத்துகள்                  |
| `version`          | சரம்      | தேவை; செம்வர் (`MAJOR.MINOR.PATCH`)                                  |
| `description`      | சரம்?     | ≤ 500 எழுத்துகள்                                                     |
| `author`           | சரம்?     | ≤ 200 எழுத்துகள்                                                     |
| `license`          | சரம்?     | `MIT` க்கு இயல்புநிலை                                                |
| `main`             | சரம்?     | நுழைவு கோப்பு; `index.js` க்கு இயல்புநிலை                            |
| `source`           | enum?     | `local` \| `marketplace` ( `local` க்கு இயல்புநிலை)                  |
| `tags`             | சரம்[]?   | குறிச்சொற்களைத் தேடுங்கள்                                            |
| `requires`         | பொருளா?   | `{ omniroute?, permissions[] }`                                      |
| `hooks`            | பொருளா?   | எந்த சொருகி செயல்படுத்துகிறது என்பதை பூலியன்கள் அறிவிக்கிறார்கள்     |
| `skills`           | பொருள்[]? | விருப்பத் திறன் வரையறைகள்                                            |
| `enabledByDefault` | பூலியன்?  | நிறுவலில் தானாகச் செயல்படுத்தவும்                                    |
| `configSchema`     | பொருளா?   | கட்டமைப்பு புலங்களின் வரைபடம் (`string`/`number`/`boolean`/`select`) |
| `integrity`        | சரம்?     | விருப்பமான `sha256-<base64>` நுழைவு-கோப்பு பின்                      |

`network` / `file-read` / `file-write` / `env` / `exec` என்ற enum இலிருந்து அனுமதிகள் பெறப்படுகின்றன. `env` மட்டுமே இயக்க நேர விளைவைக் கொண்டுள்ளது (குழந்தைக்கான சூழல்-மாறி அனுமதிப்பத்திரம் சற்று பெரியது); மற்றவை அறிவிப்புகள் மற்றும் செயல்படுத்தப்படவில்லை.

## வாழ்க்கைச்சுழற்சி ஓட்டம்

```
install (POST /api/plugins, பாதை)
  → manifest-ஐ ஸ்கேன் செய்து/சரிபார் → staging-க்குப் பிரதி செய் → main கோப்பகம் உள்ளேயே இருப்பதை உறுதிசெய்
  → ~/.omniroute/plugins/<name>-க்கு அணுவியல் முறையில் மறுபெயரிடு → DB வரிசையைச் சேர்
  → onInstall-ஐத் தூண்டு → enabledByDefault எனில்: செயல்படுத்து

activate (POST /api/plugins/{name}/activate)
  → realpath உள்ளடக்கச் சரிபார்ப்பு → loadPlugin() (துணைச் செயல்முறையைத் தொடங்கு)
  → அறிவிக்கப்பட்ட hooks-ஐப் பதிவுசெய் → status = "active" → onActivate-ஐத் தூண்டு

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate-ஐத் தூண்டு (பதிவுநீக்கத்திற்கு முன்) → hooks-ஐப் பதிவுநீக்கு
  → துணைச் செயல்முறையை நிறுத்து → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → செயலில் இருந்தால் செயல்நீக்கு → onUninstall-ஐத் தூண்டு
  → உள்ளடக்கச் சரிபார்ப்புடன் plugin கோப்பகத்தைச் சுழல்நிலையில் நீக்கு → DB வரிசையை நீக்கு
```

நிறுவப்பட்ட பதிப்பைவிட manifest பதிப்பு **கண்டிப்பாகப் புதியதாக** உள்ள ஒரு கோப்பகத்திற்கு எதிராக `install`-ஐ மீண்டும் இயக்குவது தானாக மேம்படுத்தும் (சுத்தமான மறுநிறுவல்; config இயல்புநிலைகளுக்கு மீட்டமைக்கப்படும்). அதே அல்லது பழைய பதிப்பு நிராகரிக்கப்படும்.

## டாஷ்போர்டு

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) இல் உள்ள டாஷ்போர்டு பக்கம் இரண்டு தாவல்களை வழங்குகிறது:

- **நிறுவப்பட்டது** — நிறுவப்பட்ட செருகுநிரல்களை அவற்றின் அறிவிக்கப்பட்ட கொக்கிகள், ஒரு activate/deactivate நிலைமாற்றம், ஒரு நிறுவல் நீக்கு பொத்தான் மற்றும் "செருகுகளுக்கான ஸ்கேன்" செயல் (`POST /api/plugins/scan`) ஆகியவற்றைப் பட்டியலிடுகிறது.
- **சந்தை** — தனிப்பயன் பதிவு URL அமைக்க ஒரு புலத்துடன் `GET /api/plugins/marketplace` இலிருந்து பட்டியலைக் காட்டுகிறது.

OmniRoute செயல்முறையின் முழு சிறப்புரிமைகளுடன் செருகுநிரல்கள் இயங்கும் என்ற எச்சரிக்கையை பக்கம் எப்போதும் காட்டுகிறது.

ஒரு சொருகி கட்டமைப்பு பக்கம் `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) இல் உள்ளது.
