OpenAI-உடன் இணக்கமான குறிப்பிட்ட நெறிமுறை மற்றும் வழங்குநர் திறன் அணிக்காக,
[`OPENAI_COMPATIBILITY.md`](./OPENAI_COMPATIBILITY.md)-ஐப் பார்க்கவும்.

## அரட்டை நிறைவுகள்

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### தனிப்பயன் தலைப்புகள்

| தலைப்பு                  | திசை     | விளக்கம்                                                                                                                                                                                                                                                   |
| ------------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | கோரிக்கை | தற்காலிகச் சேமிப்பைத் தவிர்க்க `true` என அமைக்கவும்                                                                                                                                                                                                        |
| `x-omniroute-no-memory`  | கோரிக்கை | இந்தக் கோரிக்கைக்கான நினைவகம் + திறன்கள் உட்செலுத்தலைத் தவிர்க்க `true` என அமைக்கவும் (தற்காலிகச் சேமிப்பு தவிர்ப்பைப் பிரதிபலிக்கிறது; ஒவ்வொரு அழைப்புக்குமான டோக்கன்/செலவு கூடுதலைத் தவிர்க்கிறது)                                                       |
| `X-OmniRoute-Progress`   | கோரிக்கை | முன்னேற்ற நிகழ்வுகளுக்கு `true` என அமைக்கவும்                                                                                                                                                                                                              |
| `X-Session-Id`           | கோரிக்கை | வெளிப்புற அமர்வு சார்புக்கான நிலையான அமர்வுச் சாவி                                                                                                                                                                                                         |
| `x_session_id`           | கோரிக்கை | அடிக்கோடு மாறுபாடும் ஏற்கப்படுகிறது (நேரடி HTTP)                                                                                                                                                                                                           |
| `X-OmniRoute-Session-Id` | கோரிக்கை | அழைப்பாளரால் வழங்கப்படும் அமர்வு/உரையாடல் குறிச்சொல் (நினைவகத்திற்கும் வழங்கப்படும்). இது இருக்கும்போது, ஒவ்வொரு அமர்வுக்குமான செலவுப் பகிர்விற்காக `call_logs.session_tag`-இல் அப்படியே நிலைநிறுத்தப்படும் (#8249) — இல்லாதபோது ஒருபோதும் உருவாக்கப்படாது |
| `Idempotency-Key`        | கோரிக்கை | நகல் நீக்கச் சாவி (5s சாளரம்)                                                                                                                                                                                                                              |
| `X-Request-Id`           | கோரிக்கை | மாற்று நகல் நீக்கச் சாவி                                                                                                                                                                                                                                   |
| `x-omniroute-connection` | கோரிக்கை | ஒற்றை-மாதிரி கோரிக்கையை அதன் id மூலம் ஒரு வழங்குநர் இணைப்புடன் (கணக்கு) பிணைக்கவும் — [ஒவ்வொரு கோரிக்கைக்குமான கணக்குப் பிணைப்பு](#account-pinning-per-request) என்பதைப் பார்க்கவும்                                                                       |
| `X-OmniRoute-Cache`      | பதில்    | `HIT` அல்லது `MISS` (ஸ்ட்ரீமிங் அல்லாதது)                                                                                                                                                                                                                  |
| `X-OmniRoute-Idempotent` | பதில்    | நகல் நீக்கப்பட்டிருந்தால் `true`                                                                                                                                                                                                                           |
| `X-OmniRoute-Progress`   | பதில்    | முன்னேற்றக் கண்காணிப்பு இயக்கத்தில் இருந்தால் `enabled`                                                                                                                                                                                                    |
| `X-OmniRoute-Session-Id` | பதில்    | OmniRoute பயன்படுத்திய நடைமுறை அமர்வு ID                                                                                                                                                                                                                   |
| `X-OmniRoute-Request-Id` | பதில்    | கோரிக்கைத் தொடர்புப்படுத்தல் id (அறியப்பட்டிருக்கும்போது)                                                                                                                                                                                                  |
| `X-OmniRoute-Version`    | பதில்    | OmniRoute உருவாக்கப் பதிப்பு (எப்போதும் இருக்கும்)                                                                                                                                                                                                         |
| `X-OmniRoute-Cost-Saved` | பதில்    | HIT ஒன்றில் தற்காலிகச் சேமிப்பு தவிர்த்த USD செலவு (தற்காலிகச் சேமிப்பு HIT-களுக்கு மட்டும்)                                                                                                                                                               |
| `X-OmniRoute-Decision`   | பதில்    | வழித்தடத் தடம்: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` என்பது சேர்க்கை உத்தி அல்லது சேர்க்கை அல்லாத கோரிக்கைக்கு `single`) — நிறைவு பதில்களில் எப்போதும் இருக்கும்                                                                  |

> Nginx குறிப்பு: அடிக்கோடு கொண்ட தலைப்புகளை (எடுத்துக்காட்டாக `x_session_id`) நீங்கள் சார்ந்திருந்தால், `underscores_in_headers on;` என்பதை இயக்கவும்.

#### ஒவ்வொரு கோரிக்கைக்குமான கணக்குப் பிணைப்பு

ஒரு வழங்குநருக்குப் பல இணைப்புகள் (கணக்குகள் அல்லது சாவிகள்) இருக்கும்போது, OmniRoute பொதுவாக அதன் கணக்குத் தேர்வு உத்தி மூலம் ஒன்றைத் தேர்ந்தெடுக்கும்.
அதற்குப் பதிலாக, ஒரு கோரிக்கையானது `x-omniroute-connection` தலைப்பைக் கொண்டு ஒரு குறிப்பிட்ட இணைப்புடன் பிணைக்கப்படலாம்:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **id-ஐ எங்கே கண்டறிவது.** டாஷ்போர்டில் வழங்குநரின் பக்கத்தைத் திறக்கவும்
  (**டாஷ்போர்டு → வழங்குநர்கள் → <provider>**) மற்றும் இணைப்பு வரிசையில் உள்ள `xxxxxxxx…` id சிப்பைக்
  கிளிக் செய்யவும் — இது முழு connection id-ஐ நகலெடுக்கும்.
- **எந்தக் கோரிக்கைகள் இதைப் பின்பற்றும்.** `/v1/chat/completions`, `/v1/messages` மற்றும்
  `/v1/responses` ஆகியவற்றில் ஒற்றை-மாதிரி கோரிக்கைகள் (`provider/model`). Combos இந்த header-ஐப் புறக்கணிக்கும்:
  அதற்குப் பதிலாக ஒவ்வொரு combo படிக்கும் அதன் சொந்த இணைப்பின் மூலம் ஒரு கணக்கைப் பின் செய்யவும்.
- **பின் என்பது கண்டிப்பானது; விருப்பத்தேர்வு அல்ல.** பின் செய்யப்பட்ட இணைப்பு மட்டுமே பயன்படுத்தப்படும். ஒரு
  கோரிக்கைக்குள் ஏற்படும் தோல்வி கணக்கின் cooldown-ஐப் பதிவுசெய்யும்; ஆனால் அதே வழங்குநரின்
  மற்றொரு இணைப்பிற்குச் சுழற்சி செய்யாது.
- **Cooldown மற்றும் quota ஆகியவை பின்னை விடுவிக்கும்.** பின் செய்யப்பட்ட இணைப்பு cooldown-இல் இருக்கும்போது,
  quota தீர்ந்திருக்கும்போது அல்லது quota கொள்கையால் தடுக்கப்பட்டிருக்கும்போது, பின்னர் வரும் கோரிக்கைகள் பின் செய்யப்படாத
  போக்குவரத்தைப் போலவே வழங்குநரின் மற்ற இணைப்புகளுக்குத் திரும்பிச் செல்லும்.
- **அறியப்படாத அல்லது முடக்கப்பட்ட id-கள் தோல்வியடையும்.** வழங்குநரின் செயலில் உள்ள தொகுப்பில் இல்லாத id ஒன்று (நீக்கப்பட்டது,
  செயலிழக்கச் செய்யப்பட்டது அல்லது வேறொரு வழங்குநருக்குச் சொந்தமானது) தகுதியான கணக்கு எதையும் விட்டுவைக்காது; எனவே கோரிக்கை
  அமைதியாக வேறிடத்திற்கு வழிமாற்றப்படுவதற்குப் பதிலாகத் தோல்வியடையும்.

Claude Code, `ANTHROPIC_CUSTOM_HEADERS` மூலம் தனிப்பயன் header-களை அனுப்புகிறது. ஒவ்வொரு திட்டத்திற்கும் வேறொரு
கணக்கைப் பின் செய்ய, அதை `~/.claude/settings.json`-இன் `env` தொகுதியில் அல்லது திட்ட-நிலை
`.claude/settings.json`-இல் இடவும்:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

மூலம்: `src/sse/handlers/chat.ts` (header வாசிப்பு), `src/sse/services/auth.ts` மற்றும்
`src/sse/services/sessionAffinityPin.ts` (பின்னை விடுவித்தல் மற்றும் தொகுப்பில் இல்லாததற்கான சரிபார்ப்பு).

> **செலவு telemetry header-கள்:** streaming அல்லாத வெற்றிகரமான பதில்கள் `X-OmniRoute-*` செலவு-telemetry தொகுப்பையும் கொண்டிருக்கும் — `X-OmniRoute-Response-Cost` (USD, நிலையான 10 தசம இடங்கள்; இலவசமான/விலை நிர்ணயிக்கப்படாதவற்றுக்கு `0.0000000000`), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, மற்றும் `X-OmniRoute-Fallback-Attempts` (> 0 ஆக இருக்கும்போது மட்டும்), மேலும் `X-OmniRoute-Request-Id` மற்றும் `X-OmniRoute-Version`. இவை chat completions, `/v1/responses`, `/v1/messages`, **மற்றும் media endpoint-களாலும்** வெளியிடப்படுகின்றன — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations`, மற்றும் `/v1/moderations` (செலவு எப்போதும் `0`). விலைத் தகவல் கிடைக்கும்போது media செலவு modality ஒன்றுக்கு (படம் ஒன்றுக்கு, வினாடி ஒன்றுக்கு, எழுத்து ஒன்றுக்கு, தேடல்-அலகு ஒன்றுக்கு) கணக்கிடப்படும்; இல்லையெனில் `0` (fail-open).

> **Cache-hit செலவு அர்த்தவியல்:** semantic-cache HIT (`X-OmniRoute-Cache-Hit: true`) நிகழும்போது upstream அழைப்பு எதுவும் செய்யப்படாது; எனவே `X-OmniRoute-Response-Cost` என்பது `0.0000000000` (அந்த hit-ஐ வழங்குவதற்கான **கூடுதல்** செலவு). அசல்/ஏற்பட்டிருக்கக்கூடிய செலவு `X-OmniRoute-Cost-Saved`-இல் தனியாகத் தெரிவிக்கப்படும். Billing நுகர்வோர் `X-OmniRoute-Response-Cost`-ஐக் கூட்ட வேண்டும் (hit-களுக்கு எந்தச் செலவும் இல்லை); cache analytics, `X-OmniRoute-Cost-Saved`-ஐத் தொகுக்கலாம்.

## பிரத்தியேகமாக நிர்வகிக்கப்படும் அமர்வு குத்தகைகள்

பிரத்தியேகமாக நிர்வகிக்கப்படும் அமர்வு குத்தகை என்பது ஒரு விருப்பமான, கிளையன்ட்-நடுநிலை ரூட்டிங் ஒப்பந்தமாகும்: ஒரு செயலில் உள்ள உரிமையாளர் ஒரு தகுதியான OmniRoute இணைப்பை வைத்திருப்பார். இது ஒரு மாதிரியை குத்தகைக்கு விடாது, OAuth தேவையில்லை, ஒரு குறிப்பிட்ட கிளையன்ட்டை அடையாளம் காணாது, அல்லது ஒரு குறிப்பிட்ட வழங்குநரை தேவையில்லை.

அங்கீகரிக்கும் API விசைக்கு `lease:exclusive` ஸ்கோப் மற்றும் ஒரு வெளிப்படையான காலியற்ற `allowedConnections` பட்டியல் இருக்க வேண்டும். தரவுத்தள மாற்ற எல்லை, விசை உருவாக்கம் மற்றும் பகுதி புதுப்பித்தல்களில் இரண்டு புலங்களையும் ஒன்றாக அமல்படுத்துகிறது.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

வெற்றிகரமான கையகப்படுத்துதல், புதுப்பித்தல் மற்றும் வெளியீட்டு பதில்கள் நேர முத்திரைகள், `state` மற்றும் துல்லியமான நேர்மறை `generation` ஆகியவற்றை வெளிப்படுத்துகின்றன, ஆனால் தேர்ந்தெடுக்கப்பட்ட இணைப்பு அல்லது சான்றுகளை ஒருபோதும் வெளிப்படுத்தாது. புதுப்பித்தல் மற்றும் வெளியீடு JSON உடலில் தலைமுறையை வழங்குகின்றன:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

ஒரு செயலில் உள்ள குத்தகை உரிமையாளர் அதன் தற்போதைய பிணைப்பிற்கான தனியுரிமை-பாதுகாப்பான காட்சி மெட்டாடேட்டாவை வெளிப்படையாகக் கோரலாம்:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

இந்த விருப்பமான நிலை செயல்பாடு ஒளிபுகா உரிமையாளர், அங்கீகரிக்கப்பட்ட நிர்வகிக்கப்பட்ட API விசை மற்றும் ஒரு தரவுத்தள பரிவர்த்தனையில் துல்லியமான செயலில் உள்ள தலைமுறை ஆகியவற்றால் பாதுகாக்கப்படும். `displayName` என்பது வெட்டப்பட்ட கட்டமைக்கப்பட்ட இணைப்பு பெயர் மட்டுமே; பாதுகாப்பான கட்டமைக்கப்பட்ட பெயர் இல்லாதபோது அது `null` ஆகும். OmniRoute ஒருபோதும் மின்னஞ்சல் அல்லது உருவாக்கப்பட்ட கணக்கு அடையாளத்தை மாற்றாது. வழங்குநர் மதிப்பு ஒரு உணர்வற்ற காட்சி லேபிள் மற்றும் ஒருபோதும் உருவாக்கப்பட்ட இணக்கமான-வழங்குநர் அடையாளங்காட்டி அல்ல. சான்றுகள், டோக்கன்கள், குக்கீகள், மூல இணைப்பு அல்லது API விசை ஐடிகள், உரிமையாளர் ஹாஷ்கள், ஃபென்சிங் ரகசியங்கள் மற்றும் உள் ரூட்டிங் தரவு ஆகியவை விலக்கப்பட்டுள்ளன.

தவறான விசை, தவறான உரிமையாளர், காலாவதியான தலைமுறை, காணாமல் போன, காலாவதியான, வெளியிடப்பட்ட மற்றும் செல்லாத தேடல்கள் அனைத்தும் இணைப்பு மெட்டாடேட்டா இல்லாமல் ஒரே `409 LEASE_FENCE_STALE` பிழையைத் தருகின்றன. திறன்-காத்திருப்பு பதிலைப் பெற்ற ஒரு கிளையன்ட் ஆய்வு செய்ய செயலில் உள்ள பிணைப்பைக் கொண்டிருக்கவில்லை. ரூட்டிங் ஒரு செயலில் உள்ள குத்தகையை மாற்றும்போது, அதே தலைமுறை செல்லுபடியாகும் மற்றும் நிலை அணுக்கருவாக புதிய பிணைப்பைத் தருகிறது, பழையதை ஒருபோதும் தராது. ஏற்கனவே உள்ள கிளையன்ட்கள் மாறாமல் இருக்கும், ஏனெனில் கையகப்படுத்துதல், புதுப்பித்தல், வெளியீடு மற்றும் காத்திருப்பு பதில்கள் அவற்றின் முந்தைய வடிவங்களைத் தக்கவைத்துக்கொள்கின்றன.

இந்த சர்வர் ஒப்பந்தம் ஸ்டாக் OpenAI Codex `/status` ஐ மாற்றாது. ஸ்டாக் Codex தற்போது அதன் மாதிரி வழங்குநர் மற்றும் உள்ளமைக்கப்பட்ட அங்கீகாரம்/கணக்கு நிலையைப் புகாரளிக்கிறது, ஆனால் தன்னிச்சையான தனிப்பயன் வழங்குநர் கணக்கு மெட்டாடேட்டாவை வழங்காது; ஒரு பிந்தைய கிளையன்ட் ஒருங்கிணைப்பு இந்தச் செயலை அழைத்து `connection.displayName` ஐ எவ்வாறு காண்பிப்பது என்பதை தீர்மானிக்க வேண்டும்.

ஒவ்வொரு நிர்வகிக்கப்பட்ட அனுமான கோரிக்கையும் இரண்டு கட்டுப்பாட்டு தலைப்புகளை வழங்குகிறது:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

துல்லியமான உரிமையாளர், தலைமுறை, செயலில் உள்ள இணைப்பு மற்றும் அங்கீகரிக்கப்பட்ட API விசை ஆகியவை ஒவ்வொரு ஆதரிக்கப்படும் அப்ஸ்ட்ரீம் முயற்சிக்கும் உடனடியாக பாதுகாக்கப்படுகின்றன. அதே இணைப்பை அந்த விசை அனுமதித்தாலும், மற்றொரு விசையுடன் உரிமையாளர் மற்றும் தலைமுறையை மீண்டும் இயக்குவது தோல்வியடையும். மூல உரிமையாளர்கள் நிலைத்திருக்க மாட்டார்கள், பதிவு செய்யப்பட மாட்டார்கள், கோரிக்கை ஸ்னாப்ஷாட்டில் தக்கவைக்கப்பட மாட்டார்கள் அல்லது அப்ஸ்ட்ரீம் அனுப்பப்பட மாட்டார்கள்.

தற்காலிக மோதல் HTTP `429` ஐ `Retry-After` உடன் திருப்பித் தருகிறது மற்றும்:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

இந்த பதில் சாதாரண தகுதியான தொகுப்பு காலியற்றது மற்றும் ஒவ்வொரு இலவச வேட்பாளரும் ஒரு வெளிநாட்டு செயலில் உள்ள குத்தகையால் நடத்தப்பட்டது என்பதை மட்டுமே குறிக்கிறது. ஆதரிக்கப்படாத மாதிரிகள்/வழங்குநர்கள், கொள்கை பொருந்தாமை, கூல்டவுன், ஒதுக்கீடு, ஆரோக்கியம் மற்றும் பிற சாதாரண தகுதி தோல்விகள் அவற்றின் ஏற்கனவே உள்ள OmniRoute பதில்களைத் தக்கவைத்துக்கொள்கின்றன.

### `x-omniroute-compression`

சுருக்கத் திட்டத்தின் ஒரு கோரிக்கைக்கான மேலெழுதல். மிக உயர்ந்த முன்னுரிமை — ரூட்டிங்-காம்ப் மேலெழுதல், செயலில் உள்ள சுயவிவரம், தானியங்கு-தூண்டுதல் மற்றும் பேனல் இயல்புநிலையை வெல்லும். மதிப்புகள்:

| மதிப்பு       | விளைவு                                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------- |
| `off`         | இந்த கோரிக்கைக்கான சுருக்கம் இல்லை.                                                                                 |
| `default`     | பேனல்-பெறப்பட்ட இயல்புநிலை சுயவிவரம் (செயலில் உள்ள சுயவிவரத்தை புறக்கணிக்கிறது). இழப்பு இயந்திரங்கள் அணைக்கப்படும். |
| `safe`        | நகல் நீக்கம் மற்றும் வெற்று இட மடிப்பு மட்டுமே.                                                                     |
| `allow-lossy` | சுருக்கங்கள் மற்றும் பாணி மறுஎழுத்துக்கள் உட்பட, இந்த கோரிக்கைக்கான ஆபரேட்டர் திட்டத்தை வைத்திருங்கள்.              |
| `engine:<id>` | இயக்கப்பட்டால் ஒரு ஒற்றை இயந்திரம், எ.கா. `engine:rtk`. அந்த இயந்திரத்திற்கான ஒரு கோரிக்கைக்கான விருப்பத் தேர்வு.   |
| `<combo>`     | ஒரு பெயரிடப்பட்ட காம்போ, முதலில் பெயரால் (பெரிய/சிறிய எழுத்துக்களைப் பொருட்படுத்தாமல்), பின்னர் ஐடியால் பொருந்தும். |

குறிப்புகள்:

- அறியப்படாத மதிப்புகள் புறக்கணிக்கப்படும் (கோரிக்கை ஒருபோதும் நிராகரிக்கப்படாது); தீர்வு சாதாரண ஆபரேட்டர் முன்னுரிமைக்கு விழும்.
- பல காம்போக்கள் ஒரு பெயரைப் பகிர்ந்து கொண்டால், ஒரு தீர்மானகரமான பொருத்தத்திற்கு காம்போ **id** ஐ அனுப்பவும்.
- `off` அல்லது `default` என்ற பெயரைக் கொண்ட ஒரு காம்போவை பெயரால் தேர்ந்தெடுக்க முடியாது (அந்த முக்கிய வார்த்தைகள் முதலில் விளக்கப்படும்); அத்தகைய காம்போவை அதன் ஐடியால் குறிப்பிடவும்.
- மாஸ்டர் சுருக்க சுவிட்ச் ஒரு கடினமான கேட் ஆகும்: சுருக்கம் உலகளவில் முடக்கப்பட்டிருக்கும் போது, இந்த தலைப்பு அதை இயக்க முடியாது.

பயன்படுத்தப்பட்ட திட்டம் பதில் தலைப்பில் மீண்டும் எதிரொலிக்கப்படுகிறது:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

இங்கு `<source>` என்பது `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, அல்லது `off` இவற்றில் ஒன்றாகும்.

## உட்பொதிவுகள்

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

கிடைக்கக்கூடிய வழங்குநர்கள்: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

பட்டியல் அடையாளங்கள் `provider/model` வடிவில் இருக்கும் (எடுத்துக்காட்டு: `jina-ai/jina-embeddings-v5-omni-small`). பதிவேட்டில் உள்ள வெறும் Jina மாதிரி அடையாளங்களும் (எடுத்துக்காட்டாக `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) சரியாகத் தீர்மானிக்கப்படும். Jina embed/rerank/classify/segment செயல்பாடுகள் முதலில் டாஷ்போர்டின் `jina-ai` நற்சான்றுகளைப் பயன்படுத்தும்; டாஷ்போர்டு விசை இல்லாதபோது மட்டுமே `JINA_AI_API_KEY` மாற்றாகப் பயன்படுத்தப்படும். `jina-reader` அட்டை Reader / `r.jina.ai` பயன்பாட்டிற்கு மட்டுமே (`POST /v1/web/fetch`); அது ஒருபோதும் உட்பொதிவுகளையோ rerank செயல்பாட்டையோ வழங்காது.

பல்முறைமை ஆதரவை அறிவிக்கும் பதிவேட்டு மாதிரிகள், வழங்குநர் சார்பற்ற அதிகபட்சம் 32 கட்டமைக்கப்பட்ட
உருப்படிகளையும் ஏற்கும். ஊடக உருப்படி வகைகள் `text`, `image`, `audio`, `video`, மற்றும் `document` ஆகும். அவற்றின் ஊடக `source`
`{"type":"url","url":"https://..."}` அல்லது
`{"type":"base64","data":"...","media_type":"..."}` ஆகியவற்றில் ஒன்றாக இருக்கும்.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
மற்றும் குடும்ப மாற்றுப்பெயர் `jina-ai/jina-embeddings-v5-omni` → omni-small) Jina-வின் இயல்பான
EmbeddingsV5Request ஆவணங்களையும் ஏற்று, அவற்றை `https://api.jina.ai/v1/embeddings` என்பதற்கு **மாற்றமின்றி அனுப்புகிறது**:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    {
      "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }]
    }
  ]
}
```

இயல்பான `{ image | audio | video | pdf }` மதிப்புகள் ஒரு பொது HTTPS URL, ஒரு `data:` URI அல்லது மூல
base64 ஆக இருக்கலாம். OmniRoute அந்தப் பொருட்களைச் சரங்களாக மாற்றுவதோ இயல்பான பட URL-களைப் பெறுவதோ இல்லை — Jina பொது
ஊடகத்தைத் தானாகவே பெறுகிறது. கூடுதல் Jina புலங்கள் (`task`, `normalized`, `truncate`, `embedding_type`)
அனுப்பப்படுகின்றன. உரை மட்டும் ஆதரிக்கும் Jina SKU-கள் இன்னும் உரையல்லாத ஆவணங்களை நிராகரிக்கும்.

பாதுகாப்பு மற்றும் பரிமாற்ற வரம்புகள்:

- தொலைநிலை ஊடக URL-கள் பொது HTTPS ஆக இருக்க வேண்டும். நியமப்படுத்தப்பட்ட `{type,source:url}` உருப்படிகள்
  சேவையகப் பக்கத்தில் பெறப்பட்டு (திசைமாற்ற மறுசரிபார்ப்பு, நேர வரம்பு, அளவு வரம்புகள், பொது DNS, இணைப்புப் பிணைப்பு),
  வழங்குநர் அழைப்புக்கு முன் உட்பதிக்கப்படும். Jina-வின் இயல்பான `{image:"https://..."}` உருப்படிகள்
  அதே பொது-HTTPS சரிபார்ப்புக்குப் பிறகு மாற்றமின்றி அனுப்பப்படும்; Jina அந்த URL-ஐப் பெறும்.
- வரியக base64 ஊடகம், ஒவ்வொரு உருப்படிக்கும் குறியீடு நீக்கப்பட்ட நிலையில் 8 MiB ஆகவும், கோரிக்கை முழுவதற்கும் குறியீடு நீக்கப்பட்ட நிலையில் 16 MiB ஆகவும் வரம்பிடப்பட்டுள்ளது.

வழங்குநர் மாற்றம் (நியமப்படுத்தப்பட்ட உருப்படிகள் ஒருபோதும் மாற்றமின்றி அனுப்பப்படாது):

- Jina பல்முறைமை மாதிரிகள்: ஒவ்வொரு மேல்-நிலை உருப்படியும், வரியக ஊடகத்திற்கு data URI-களைப் பயன்படுத்தி,
  முறைமை-விசையிடப்பட்ட ஒரு பொருளாக (`text` / `image` / `audio` / `video` / `pdf`) மாறும்; ஒவ்வொரு
  மேல்-நிலை உருப்படிக்கும் ஒரு வெக்டர்.
- Gemini Embedding 2 குடும்பம்: ஒரு மேல்-நிலை அணி, `content.parts` (`text` அல்லது `inline_data`) உடன் கூடிய ஒரே இயல்பான
  `models/{model}:embedContent` கோரிக்கையாக மாறும்.
- llama.cpp (`llama-cpp/<model>`, உள்ளூர் சேவையகம் ஏற்றியுள்ள எந்த மாதிரியும்): நியமப்படுத்தப்பட்ட `text` உருப்படிகள்
  எளிய சரங்களாக மாறும்; மேலும் `image` / `audio` / `video` ஆகியவை ஒவ்வொன்றும், llama-server-இன் அரட்டை உள்ளடக்கப் பகுதிகளை (`image_url`,
  `input_audio` உடன் `wav` / `mp3` / `flac` வடிவமைப்பு, `input_video`) வரியகத் தரவுடன் பயன்படுத்தி,
  ஒரு `{"content": [part]}` பொருளாக மாறும்; ஒவ்வொரு மேல்-நிலை உருப்படிக்கும் ஒரு வெக்டர்.
  சேவையகம் `--embedding --mmproj …` உடன் இயங்க வேண்டும்; projector இல்லையெனில்
  அது ஊடகத்தைத் தானாகவே நிராகரிக்கும். `document` ஆதரிக்கப்படவில்லை.
- வெளிப்படையான முறைமை மெட்டாதரவு இல்லாத அறியப்படாத/இயங்குநிலை மாதிரிகள், கட்டமைக்கப்பட்ட உள்ளீட்டை HTTP 400 உடன் நிராகரிக்கும்.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

ஆதரிக்கப்படாத மாதிரி/முறைமைச் சேர்க்கைகள், உருப்படியை வலுக்கட்டாயமாக மாற்றுவதற்குப் பதிலாக HTTP 400-ஐத் திருப்பும். மரபுவழி சரம்/டோக்கன் கோரிக்கைகளில் உள்ளீடு சாராத
நீட்டிப்புப் புலங்கள் மாற்றமின்றி தொடர்ந்து அனுப்பப்படும்.

```bash
# அனைத்து உட்பொதிவு மாதிரிகளையும் பட்டியலிடவும்
GET /v1/embeddings
```

## பட உருவாக்கம்

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "மலைகளுக்கு மேலே ஒரு அழகான சூரிய அஸ்தமனம்",
  "size": "1024x1024"
}
```

கிடைக்கக்கூடிய வழங்குநர்களில் OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (உள்ளூர்), ComfyUI (உள்ளூர்) ஆகியவை அடங்கும்.

`n` ஆனது `data[]`-இல் `n` படங்களை வழங்கும். ஒரு அழைப்புக்கு ஒரு படத்தை வழங்கும் அப்ஸ்ட்ரீம் API-களைக் கொண்ட வழங்குநர்களுக்கு
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI), அதிகபட்சம் 4 அழைப்புகள் ஒரே நேரத்தில் நடைபெறும் வகையில் `n` தனித்தனி அப்ஸ்ட்ரீம் அழைப்புகள் மேற்கொள்ளப்படும். நிலையான
`seed`, அழைப்பின் குறியீட்டால் (`seed`, `seed + 1`, …) மாற்றப்படும்; இதனால் படங்கள் வேறுபட்டிருந்தாலும் மீண்டும்
உருவாக்கக்கூடியவையாக இருக்கும். `n`-இன் அதிகபட்ச வரம்பு 10. ஏதேனும் ஓர் அழைப்பு தோல்வியடைந்தால், கோரிக்கை
முழுமையாகத் தோல்வியடையும். ஃபேன்-அவுட் வடிவங்களின் பட்டியல்
`open-sse/handlers/imageGeneration/fanOut.ts`-இல் உள்ள `SINGLE_IMAGE_FANOUT_FORMATS` ஆகும்.

ZenMux ஏற்கனவே உள்ள API-key இணைப்பை மீண்டும் பயன்படுத்துகிறது மற்றும் `zenmux/` அல்லது `zm/` முன்னொட்டுகளை ஏற்கிறது:

- `zenmux/openai/gpt-image-2`, ZenMux-இன் OpenAI Images API-ஐப் பயன்படுத்துகிறது. விருப்பங்களில் `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background`, மற்றும் `response_format` ஆகியவை அடங்கும்.
- `zm/meta/muse-image-1.0` போன்ற பிற வெளியீட்டாளர்கள், ZenMux-இன் Vertex AI `:predict`
  எண்ட்பாயிண்டைப் பயன்படுத்துகின்றனர். `n` ஆனது `sampleCount`-க்கும், `aspect_ratio` ஆனது `aspectRatio`-க்கும், `image_size`
  (`1K`, `2K`, `4K`) ஆனது `sampleImageSize`-க்கும் பொருத்தப்படுகிறது. பிக்சல் `size` ஒரு விகிதத்தை மட்டுமே வழங்கும்;
  பிக்சல் பரிமாணங்கள் உத்தரவாதம் அளிக்கப்படுவதில்லை. ஆதரிக்கப்படும் விகிதங்கள், தெளிவுத்திறன்கள் மற்றும் எண்ணிக்கைகள் மாடலுக்கு ஏற்ப மாறுபடும்.
- `zm/inclusionai/ming-image-0.1-design` அதன் பரிமாணங்களைத் தானாகத் தேர்ந்தெடுக்கிறது. `size`,
  `aspect_ratio`, மற்றும் `image_size` ஆகியவற்றைத் தவிர்க்கவும்; வெளிப்படையான மதிப்புகள் HTTP 400-ஐ வழங்கும். PNG, JPEG, மற்றும் WebP
  ஆகியவற்றை `output_format` மூலம் கோரலாம்.

இந்த ஒருங்கிணைப்பு உரையிலிருந்து படத்தை உருவாக்குவதை ஆதரிக்கிறது; மேற்கோள்-படத் திருத்தத்தை ஆதரிக்காது. Vertex
வெளியீடு `data[].b64_json` ஆக இயல்பாக்கப்படுகிறது; `response_format: "url"` ஆனது ஒரு அப்ஸ்ட்ரீம்
HTTPS URL-ஐ அல்லது பட பைட்டுகள் மட்டுமே கிடைக்கும்போது ஒரு base64 தரவு URL-ஐ வழங்கும். காலியான/வடிகட்டப்பட்ட வெளியீடுகள்
காலியான வெற்றிப் பதிலுக்குப் பதிலாகப் பிழையை வழங்கும். மாடல் அணுகல் ZenMux கணக்கைப் பொறுத்தது.
[ZenMux-இன் Vertex API](https://docs.zenmux.ai/api/vertexai/generate-images) மற்றும்
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image) ஆகியவற்றைப் பார்க்கவும்.

```bash
# அனைத்து பட மாடல்களையும் பட்டியலிடவும்
GET /v1/images/generations
```

## ஆவண OCR

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model` ஆனது `provider/model` முன்னொட்டைப் பயன்படுத்தி OCR வழங்குநரைத் தேர்ந்தெடுக்கிறது; வழங்குநர் இல்லாத மாதிரி id (எ.கா.
`mistral-ocr-latest`) அதன் பதிவுசெய்யப்பட்ட வழங்குநருக்குத் தீர்மானிக்கப்படுகிறது, மேலும் `model` விடுபட்டால் இயல்புநிலையாக
Mistral (`mistral-ocr-latest`) பயன்படுத்தப்படும். பதிவுசெய்யப்பட்ட வழங்குநர்கள் (`open-sse/config/ocrRegistry.ts`):

| வழங்குநர் id                  | மாதிரி id            | `model` மதிப்பு                                                             | குறிப்புகள்                                                                                                                |
| ----------------------------- | -------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (அல்லது வழங்குநர் இல்லாத `mistral-ocr-latest`) | ஒத்திசைவானது — ஒற்றை மேல்நிலை அழைப்பிலிருந்து பதில் நேரடியாகத் திருப்பி அனுப்பப்படும்.                                     |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                                 | ஒத்திசைவற்ற மேல்நிலை (`analyze` + வாக்கெடுப்பு) — கீழே காண்க.                                                              |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                                     | ஒத்திசைவானது, Vertex AI-இன் `openapi/chat/completions` கூட்டாளர் முனைப்புள்ளி வழியாக — அங்கீகாரம்/URL குறித்து கீழே காண்க. |

மூன்று வழங்குநர்களும் ஒரே Mistral வடிவமைப்பிலான உட்பகுதியில் பதிலளிக்கின்றன:

```json
{
  "pages": [{ "index": 0, "markdown": "# பிரித்தெடுக்கப்பட்ட உரை..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Azure Document Intelligence வாக்கெடுப்பு ஓட்டம்

Azure Document Intelligence-இன் `analyze` API ஒத்திசைவற்றது: தொடக்கக் கோரிக்கை உட்பகுதிக்குப் பதிலாக
`Operation-Location` தலைப்பைத் திருப்பி அனுப்புகிறது, மேலும் முடிவுக்காக வாக்கெடுப்பு நடத்தப்பட வேண்டும். கையாளுநர்
(`open-sse/handlers/ocr.ts`) அந்த URL-ஐ ஒவ்வொரு வினாடியும் அதிகபட்சம் 30 முயற்சிகள் வரை வாக்கெடுக்கும்; `ok` அல்லாத வாக்கெடுப்புப் பதில் அல்லது `"failed"` நிலை ஏற்பட்டால் உடனடியாகத் தோல்வியடையும் (தொடர்ந்து
வாக்கெடுப்பதில்லை), மேலும் முயற்சி வரம்பு தீர்ந்த பின்னரும் செயல்பாடு இயங்கிக்கொண்டிருந்தால் `504`-ஐத் திருப்பி அனுப்பும். இறுதி Azure பதில், அழைப்பாளருக்குத் திருப்பி அனுப்பப்படுவதற்கு முன், Mistral பயன்படுத்தும் அதே `pages`/`markdown` வடிவத்திற்கு
இயல்பாக்கப்படுகிறது; எனவே கிளையண்ட் குறியீடு வழங்குநருக்கெனத் தனிப்பட்ட கையாளுதலைச் செய்ய வேண்டியதில்லை.

### Vertex AI DeepSeek OCR அங்கீகாரம் மற்றும் முனைப்புள்ளித் தீர்மானம்

`vertex-deepseek-ocr`, அரட்டை/படப் போக்குவரத்திற்காக OmniRoute ஏற்கனவே ஆதரிக்கும் அதே Vertex AI அங்கீகாரத்தை மீண்டும் பயன்படுத்துகிறது
(`open-sse/executors/vertex.ts`): இணைப்பின் API விசை, Service Account JSON நற்சான்றாகவோ (JWT-bearer
ஓட்டத்தின் மூலம் குறுகிய ஆயுளுடைய OAuth அணுகல் டோக்கனாக மாற்றப்படும்) அல்லது ஏற்கனவே உருவாக்கப்பட்டு அப்படியே பயன்படுத்தப்படும் OAuth அணுகல் டோக்கனாகவோ இருக்கும். மேல்நிலை முனைப்புள்ளி URL என்பது Vertex-இன்
பொதுவான `openapi/chat/completions` கூட்டாளர் முனைப்புள்ளியாகும்; இது இணைப்பின் திட்டம் மற்றும்
பிராந்தியத்திலிருந்து உருவாக்கப்படுகிறது — வெளிப்படையான `providerSpecificData.project`/`providerSpecificData.region` எப்போதும் முன்னுரிமை பெறும்;
இல்லையெனில், திட்டம் Service Account JSON-இன் `project_id`-இலிருந்து பெறப்படும், மேலும் பிராந்தியம்
இயல்புநிலையாக `us-central1` ஆகும். இரண்டு தீர்மானங்களும் `open-sse/handlers/ocr.ts`-இல்
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) நடைபெற்று,
`handleOcr`-க்கு அனுப்புவதற்கு முன் `src/app/api/v1/ocr/route.ts` மூலம் பயன்படுத்தப்படுகின்றன.

## மாடல்களைப் பட்டியலிடுதல்

```bash
GET /v1/models

```

### மாடல் id முன்னொட்டுகள் (`?prefix=`)

பெரும்பாலான மாடல்கள் ஒரு **வழங்குநர் முன்னொட்டின்** கீழ் விளம்பரப்படுத்தப்படுகின்றன. உங்களுக்கு எந்த முன்னொட்டு கிடைக்கும் என்பது
`MODELS_CATALOG_PREFIX_MODE` அம்சக் கொடியால் கட்டுப்படுத்தப்படுகிறது; மேலும், அனைவருக்குமான
சேவையக அளவிலான அமைப்பை மாற்றாமல் சுத்தமான பட்டியலை விரும்பும் கிளையண்டிற்கு உதவும் வகையில், வினவல் அளவுருவைப் பயன்படுத்தி
**ஒவ்வொரு கோரிக்கைக்கும்** அதை மேலெழுதலாம்:

```bash
GET /v1/models?prefix=alias        # ஒவ்வொரு மாடலுக்கும் ஒரு id — குறுகிய மாற்றுப்பெயர் முன்னொட்டு
GET /v1/models?prefix=dual         # இரண்டு வடிவங்களும் (சேவையக இயல்புநிலை)
GET /v1/models?prefix=canonical    # முழுமையான வழங்குநர்-id முன்னொட்டு மட்டும்
```

| பயன்முறை    | வெளியிடுவது                                                   | குறிப்புகள்                                                                                                                                                                                                                                    |
| ----------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **மற்றும்** `claude/claude-sonnet-4-6` | **இயல்புநிலை.** இரண்டு id-களும் ஒரே மாடலுக்கு வழிமாற்றப்படும்; இரு வடிவங்களில் ஏதேனும் ஒன்றை நிரந்தரமாகக் குறிப்பிட்ட கிளையண்ட் உள்ளமைவுகள் தொடர்ந்து செயல்படுவதற்காக இது வைத்திருக்கப்படுகிறது. இது பட்டியலின் அளவை ஏறத்தாழ இரட்டிப்பாக்கும். |
| `alias`     | `cc/claude-sonnet-4-6`                                        | ஒவ்வொரு மாடலுக்கும் ஒரு பதிவு. தனித்துவமான மாற்றுப்பெயர் இல்லாத வழங்குநர்களும் தங்கள் பதிவை வெளியிடுவதால் எதுவும் இழக்கப்படாது.                                                                                                                |
| `canonical` | `claude/claude-sonnet-4-6`                                    | முழுமையான வழங்குநர்-id முன்னொட்டின் கீழ் ஒவ்வொரு மாடலுக்கும் ஒரு பதிவு. தனித்துவமான மாற்றுப்பெயர் இல்லாத வழங்குநர்களும் (எ.கா. `antigravity/…`, `agy/…`) தங்களின் ஒற்றை id-ஐ இங்கும் வெளியிடுவதால் எதுவும் இழக்கப்படாது.                       |

`dual` பயன்முறை பிரதியை வினவல் அளவுரு இல்லாமலும் அடையாளம் காணலாம்: அதில் முதன்மை id-ஐச் சுட்டும் `parent`
புலம் இருக்கும்.

மாடல் தேர்வியை வழங்கும் கிளையண்டுகள் `?prefix=alias`-ஐக் கோர வேண்டும் — இதைத்தான்
[OmniCopilot VS Code நீட்டிப்பு](../guides/VSCODE-COPILOT.md) செய்கிறது.

### கண்டறிதல் வடிகட்டிகள் (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` விருப்பத்தேர்வு அடிப்படையிலான கண்டறிதல் வடிகட்டிகளை ஏற்கிறது. அவற்றில் எதுவும் இல்லையெனில் பதில்
மாறாது. அழைப்பாளர் ஏற்கெனவே காணும் பட்டியலை அவை குறுக்குகின்றன (API-key அனுமதிகள் முதலில் பயன்படுத்தப்படும்);
மேலும், OpenAI பாணியிலான `limit` / `after` பக்கமாக்கலுக்கு முன்பு அவை செயல்படும்:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # பட்டியலிடப்பட்ட ஒவ்வொரு திறனும் true ஆக இருக்க வேண்டும்
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # பட்டியல் `type`; அது இல்லாத வரிசைகள் `chat`
GET /v1/models?q=sonnet&limit=10                           # id அல்லது பெயரில் பேரெழுத்து/சிற்றெழுத்து வேறுபாடற்ற பொருத்தம்
```

| அளவுரு        | மதிப்புகள்                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | எதிர்மறையல்லாத முழு எண்; `context_length` உடன் ஒப்பிடப்படும்                                        |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 எழுத்துகள்                                                                                    |

அறியப்படாத மதிப்பு அல்லது எதிர்மறையல்லாத முழு எண்ணாக இல்லாத `min_context` (எடுத்துக்காட்டாக `1.5`)
HTTP `400`-ஐ வழங்கும்; மேலும், செய்தியில் செல்லுபடியாகும் மதிப்புகள் பட்டியலிடப்படும். செயலாக்கம்:
`src/app/api/v1/models/catalogFilters.ts`.

### மாடல் சுருக்கப்பட்ட பட்டியல் (`POST /v1/models/query`)

`POST /v1/models/query`, `GET /v1/models` பயன்படுத்தும் அதே பட்டியலிலிருந்து, அதே
அங்கீகாரம் மற்றும் ஒவ்வொரு விசைக்குமான தெரிவுநிலையுடன், குறுகியதும் தீர்மானகரமானதுமான பட்டியலை வழங்குகிறது:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

ஒவ்வொரு புலமும் விருப்பத்தேர்வானது. `capabilities` மற்றும் `exclude` ஆகியவை ஒரு அணியையோ காற்புள்ளியால் பிரிக்கப்பட்ட சரத்தையோ
ஏற்கும்; `max_output`, `max_output_tokens` உடன் ஒப்பிடப்படும். முடிவுகள் முதலில் `owned_by`, பின்னர் `id`
அடிப்படையில் வரிசைப்படுத்தப்படும். `limit`-இன் இயல்புநிலை `20`; மேலும், `100`-க்கு மேலான மதிப்புகள் `100` ஆக வரம்பிடப்படும். செல்லுபடியாகாத JSON, அறியப்படாத
புலம் அல்லது செல்லுபடியாகாத மதிப்பு HTTP `400`-ஐ வழங்கும்.

### தனித்தனியாக மறைக்கப்பட்ட அரட்டை மாடல்கள்

அதன் வழங்குநர் பக்கத்தில் **மறைக்கப்பட்டது** எனக் குறிக்கப்பட்ட மாடல் பட்டியலிலிருந்து விலக்கப்படும்; மேலும், வெளிப்படையாகக்
கோரப்படும்போது HTTP `404` / `model_not_found` உடன் நிராகரிக்கப்படும். வழங்குநர் மாற்றுப்பெயர்கள், இணக்கமான-வழங்குநர் முனை முன்னொட்டுகள் மற்றும்
இணைப்பு இயல்புநிலைகள் உள்ளிட்ட தீர்மானிக்கப்பட்ட வழங்குநரையும் மாடலையும் இந்தச் சரிபார்ப்பு பயன்படுத்துகிறது.
ஒரு சேர்க்கை மறைக்கப்பட்ட இலக்குகளைத் தவிர்த்து, தெரியும் உடன்பிறப்பைப் பயன்படுத்தலாம்; செயல்படுத்தக்கூடிய இலக்கு எதுவும்
மீதமில்லை எனில், அதே பிழைக் குறியீட்டை வழங்கும். மறைப்பை நீக்குவது அடுத்த கோரிக்கையில் நடைமுறைக்கு வரும்.
படத்திற்கு மட்டுமான தெரிவுநிலை மேலெழுதல்கள், அதே ID கொண்ட அரட்டை மாடலை மறைக்காது.

இந்தத் தனிப்பட்ட மாடல் அமைப்பு,
[மாடல் வெளிப்படுத்தல் அனுமதி/மறுப்புப் பட்டியல்கள்](../routing/MODEL_EXPOSURE_LIST.md) என்பதிலிருந்து வேறுபட்டது; அவை வெளிப்படையான அனுப்புதலைத் தக்கவைத்தபடி பட்டியல்
விளம்பரங்களையும் தானியங்கு-வழிமாற்ற வேட்பாளர்களையும் வடிகட்டுகின்றன. API-key மாடல்
அனுமதிகள் தொடர்ந்து தனித்தனியாகப் பயன்படுத்தப்படும். இயல்புநிலை பட்டியல் முன்னொட்டுப் பயன்முறை `dual` ஆகவே இருக்கும்.

### சிந்தனையற்ற மாடல் மாறுபாடுகள்

சிந்திக்கும் திறனுடைய Claude மாடல்களுக்கு, `/v1/models`, `claude-3-omniroute-no-thinking/` என்ற முன்னொட்டுடன் கூடிய id-ஐக் கொண்ட ஒரு **சிந்தனையற்ற** மாறுபாட்டையும் விளம்பரப்படுத்துகிறது:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

இந்த id-ஐத் தேர்ந்தெடுப்பது (எ.கா., எப்போதும் ஒரு `thinking` தொகுதியை இணைக்கும் Claude Code கட்டமைப்பில்) reasoning ஒடுக்கப்பட்ட நிலையில் உண்மையான `<provider>/<model>`-க்கு மீண்டும் தீர்வுகாண்கிறது — `/v1/messages` பாதையில் `thinking:{type:"disabled"}` பயன்படுத்தப்படும், அல்லது `/v1/chat/completions` பாதையில் `reasoning`/`reasoning_effort` புலங்கள் நீக்கப்படும். Thinking-ஐ ஆதரித்து **மேலும்** `disabled`-ஐ ஏற்கும் Claude-family மாடல்களுக்கு மட்டுமே இந்த variant பட்டியலிடப்படும் (எனவே, எ.கா., `disabled`-ஐ நிராகரிக்கும் adaptive-only மாடல்கள் விலக்கப்படும்). ஒவ்வொரு மாடலுக்கும் இந்த variant-ஐ இயக்க அல்லது முடக்க operators `ModelSpec.noThinkingAlias` வழியாக கட்டாயப்படுத்தலாம்.

## வழங்குநர் செருகுநிரல் அறிக்கை

```bash
GET /api/v1/provider-plugin-manifest
```

Bifrost, CLIProxyAPI மற்றும் எதிர்கால sidecar router-கள் பயன்படுத்தும் JSON-பாதுகாப்பான வழங்குநர் செருகுநிரல் அறிக்கையை வழங்குகிறது. இந்தப் பதில் TypeScript வழங்குநர் பதிவகத்திலிருந்து உருவாக்கப்படுகிறது; மேலும் OAuth client secret-கள், இயக்கநேரச் சூழல் மதிப்புத் தீர்மானம், executor function-கள், கோரிக்கை header-கள் மற்றும் கணக்குத் தரவு ஆகியவற்றை வேண்டுமென்றே விலக்குகிறது.

ஒரு sidecar தனிச் செயல்முறையாக இயங்கி, `open-sse/config/providerPluginManifestRegistry.ts`-ஐ நேரடியாக import செய்ய முடியாதபோது இந்த endpoint-ஐப் பயன்படுத்தவும்.

`Authorization: Bearer ...`-ஐ இணைக்க முடியாத கிளையன்ட்களுக்காக, வினவல்-சர இணக்கத்தன்மை (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`) அல்லது கீழே ஆவணப்படுத்தப்பட்டுள்ள பிரத்யேக `/api/v1/vscode/{token}/...` முனைப்புள்ளிகள் வழியாக URL-இல் API விசைகளையும் OmniRoute ஏற்றுக்கொள்கிறது.

```bash

POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Jina பிரிப்பான்
POST /v1/segment     { "content": "...", "return_chunks": true }

# Jina தேடல் (s.jina.ai; வழங்குநர் மாற்றுப்பெயர்கள்: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# உள்ளடக்கக் கட்டுப்பாடுகள்
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — audio/mpeg (அல்லது கோரப்பட்ட வடிவம்) உடற்பகுதியைத் திருப்பும்
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS-க்கு ஒரு மொழியும் ஒரு குரலும் தேவை: `language` இயல்பாக "en" ஆகும்; குரல்
# விடுபட்டிருந்தால் அல்லது OpenAI-இன் வழக்கமான குரல் பெயராக (alloy, nova, …) இருந்தால் அது "Adrian" ஆகும்
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
```

> **மறுதரவரிசைப்படுத்தல் வழங்குநர் முனைகள்:** `POST /v1/rerank` என்பது `<node-prefix>/<model>` எனக் குறிப்பிடப்படும் OpenAI-இணக்கமான வழங்குநர் முனைகளுக்கும்
> (oMLX, vLLM, Infinity, நுழைவாயிலுக்குப் பின்னால் உள்ள TEI, …) கோரிக்கைகளை வழிமாற்றும். லூப்பேக்
> முனைகள் (`localhost`, `127.0.0.1`, `172.16.0.0/12`) எப்போதும் தகுதியுடையவை; மேலும், இயக்குநர்
> `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS`-இல் பட்டியலிடும் ஹோஸ்ட்பெயர்களும் தகுதியுடையவை (எ.கா.
> `http://reranker:8080/v1` போன்ற Docker/Compose சேவைப் பெயர்; இவை `HTTP(S)_PROXY` அல்லது
> இணைப்பில் நிலைநிறுத்தப்பட்ட ப்ராக்ஸி வழியாக ஒருபோதும் அனுப்பப்படாமல் நேரடியாக அழைக்கப்படுகின்றன).
> வேறு ஏதேனும் ஹோஸ்டில் உள்ள முனைகள் — LAN கணினி அல்லது Tailscale பியர் — இயக்குநர்
> `RERANK_REMOTE_PROVIDER_NODES` அம்சக் கொடியை இயக்கியிருப்பதுடன், முனையின் அடிப்படை URL வழங்குநரின்
> வெளிச்செல்லும் URL கொள்கையை (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`)
> நிறைவேற்றினால் மட்டுமே தகுதிபெறும். நினைவக எஞ்சினின் மறுதரவரிசைப்படுத்தல் படிநிலை இந்த வழித்தடத்தை
> லூப்பேக் வழியாக அழைப்பதால், நினைவக அமைப்புகளில் உள்ள `rerankProviderModel`-க்கும் இதே விதி பொருந்தும்.
>
> **உள்ளூர் சேவையக வடிவங்கள்:** முனை `<base>/v1/rerank` முகவரியிலும், 404 கிடைத்தால் `<base>/rerank`
> முகவரியிலும் (Infinity, TEI) அழைக்கப்படுகிறது. அப்ஸ்ட்ரீம் கோரிக்கை உடல் Cohere/OpenAI எழுத்துமுறையையும்
> (`documents`, `return_documents`) TEI எழுத்துமுறையையும் (`texts`, `return_text`) கொண்டிருக்கும்; மேலும்,
> அப்ஸ்ட்ரீம் பதில் Cohere உறை வடிவத்திற்கு இயல்பாக்கப்படுகிறது: TEI-இன் நேரடி `[{index, score, text}]`,
> எளிய நுழைவாயில்களிலிருந்து வரும் `{results: [{index, score}]}`, மற்றும் Voyage-பாணி `{data: [...]}`
> ஆகிய அனைத்தும் கிளையண்டுக்கு `{results: [{index, relevance_score, document?}]}` என்ற வடிவில்,
> மதிப்பெண் அடிப்படையில் வரிசைப்படுத்தப்பட்டு `top_n` வரம்புக்கு உட்படுத்தப்பட்டுத் திரும்பும்.

> **வழங்குநர்-முனை கண்டறிதல்:** OpenAI-இணக்கமான வழங்குநர் முனையிலுள்ள மாடல்கள், முனை முன்னொட்டின் கீழ்
> `GET /v1/models`-இல் தோன்றும். இறுதிப்புள்ளி மெட்டாடேட்டா இல்லாத வரிசைகள் (உள்ளூர் `/v1/models`
> பட்டியல்களுக்கு இது வழக்கமானது) முனையின் `apiType`-ஐப் பெறுகின்றன; எனவே, அரட்டையை இயல்புநிலையாகக்
> கொள்வதற்குப் பதிலாக, `embeddings` முனையின் மாடல்கள் `type: "embedding"` ஆகவும், `rerank` முனையின்
> மாடல்கள் `type: "rerank"` ஆகவும் இருக்கும்; ஒத்திசைக்கப்பட்ட அல்லது கைமுறையாகச் சேர்க்கப்பட்ட வரிசையில்
> வெளிப்படையாகக் குறிப்பிடப்பட்ட `supportedEndpoints` இருந்தால், அதற்கே இன்னும் முன்னுரிமை வழங்கப்படும்.

## கோப்புகள் API

தொகுதி உள்ளீடு/வெளியீடு மற்றும் கோப்பு-நோக்கப் பதிவேற்றங்களுக்கான OpenAI-இணக்கமான கோப்புகள் முனைப்புள்ளி.

| முறை   | பாதை                     | விளக்கம்                                                                                                                        |
| ------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/files`              | ஒரு கோப்பைப் பதிவேற்றும் (multipart: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — அதிகபட்சம் 512 MiB |
| GET    | `/v1/files`              | அங்கீகரிக்கப்பட்ட API விசைக்கான கோப்புகளைப் பட்டியலிடும்                                                                        |

**அங்கீகாரம்:** Bearer API விசை — கோப்புகள் `getApiKeyRequestScope` வழியாக ஒவ்வொரு API விசைக்கும் தனித்த வரம்பில் இருக்கும். ஒரு விசை
தனக்குச் சொந்தமான கோப்புகளை மட்டுமே பார்க்கவும், பதிவிறக்கவும், நீக்கவும் முடியும்; விசையில்லாத டாஷ்போர்டு அமர்வு
முழு நிகழ்வையும் வாசிக்க முடியும்; உரிமையாளர் இல்லாத கோப்பு (அநாமதேய அல்லது டாஷ்போர்டு-அமர்வுப் பதிவேற்றம்) ஒவ்வொரு
அமர்வற்ற அழைப்பாளருக்கும் மறுக்கப்படும். `GET /v1/files`, `REQUIRE_API_KEY=false` ஆக இருந்தாலும், ஒவ்வொரு குத்தகையாளரின்
கோப்புகளையும் பட்டியலிடுவதற்குப் பதிலாக, அநாமதேய அழைப்பாளரையும் — மேலும் செல்லுபடியாகத் தீர்மானிக்க முடியாத வழங்கப்பட்ட விசையையும் —
`401` உடன் நிராகரிக்கும் (GHSA-m3hp-hq9g-fpmv, GHSA-2jm2-mpx8-6523).

**அங்கீகாரம்:** Bearer API விசை. கோப்புகளுக்குப் பயன்படுத்தப்படும் அதே மும்முனை விதியின் கீழ், தொகுதிகள் ஒவ்வொரு API விசைக்கும்
தனித்த வரம்பில் இருக்கும்: சொந்த விசைக்கு மட்டும் அணுகல், டாஷ்போர்டு அமர்வுக்கு நிகழ்வு முழுவதுமான அணுகல், உரிமையாளர் இல்லாத பதிவுகள் ஒவ்வொரு
அமர்வற்ற அழைப்பாளருக்கும் மறுக்கப்படும் (பெறுதல், நீக்குதல், ரத்துசெய்தல் மற்றும் உருவாக்கும்போதான `input_file_id` சரிபார்ப்பு).
`REQUIRE_API_KEY=false` ஆக இருந்தாலும், `GET /v1/batches` அநாமதேய அழைப்பாளரை `401` உடன் நிராகரிக்கும்.

## Search API

வலை/தேடல் வழங்குநர் சுருக்க அடுக்கு (Tavily, Brave, Exa, Serper போன்றவை).

| முறை | பாதை                   | விளக்கம்                                                                                                                     |
| ---- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| GET  | `/v1/search`           | உள்ளமைக்கப்பட்ட தேடல் வழங்குநர்கள் + திறன்களைப் பட்டியலிடுகிறது                                                              |
| POST | `/v1/search`           | ஒரு தேடல் வினவலை இயக்குகிறது — கோரிக்கை உடல் `v1SearchSchema` மூலம் சரிபார்க்கப்படுகிறது, தேக்ககம்/ஒருங்கிணைப்பை ஆதரிக்கிறது |
| GET  | `/v1/search/analytics` | ஒவ்வொரு வழங்குநருக்குமான பெறல்/தாமதம்/தேக்ககப் புள்ளிவிவரங்கள்                                                               |

**அங்கீகாரம்:** Bearer API விசை (`extractApiKey` + `isValidApiKey`). தேடல் கொள்கை `enforceApiKeyPolicy` மூலம் அமல்படுத்தப்படுகிறது.

### Exa மற்றும் Tavily `provider_options`

Exa மற்றும் Tavily, பெயர்வெளியிடப்பட்ட தொகுப்பிலிருந்து வழங்குநருக்கே உரிய புலங்களைப் படிக்கின்றன:
`provider_options.exa` (அல்லது `provider_options["exa-search"]`) மற்றும் `provider_options.tavily`
(அல்லது `provider_options["tavily-search"]`). கீழேயுள்ள விசைகள் மட்டுமே அனுப்பப்படுகின்றன. ஒவ்வொன்றும்
`open-sse/handlers/search/providerOptionsPassthrough.ts`-இல் உள்ள அதன் சொந்த Zod schema-க்கு எதிராகச்
சரிபார்க்கப்படுகிறது; தவறான வகையைக் கொண்ட விசை நீக்கப்படும். அங்கீகாரம், அடிப்படை URL,
`stream` மற்றும் `outputSchema` உட்பட வேறு எந்த விசையும் புறக்கணிக்கப்படும். பிற வழங்குநர்கள் பயன்படுத்தும்
தட்டையான விசைகள் (`cx`, `depth`, ...) முன்பைப் போலவே செயல்படும்.

| வழங்குநர் | மேல்நிலைப் புலங்கள்                                                                                                                                                                                                                                                                                                                                                       | உள்ளமைந்தவை                                                                                                                                                                    |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Exa       | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (தட்டையான அடிப்படை மதிப்புகள்), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                 | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` இயல்புநிலை `{ text: true, highlights: true }` மீது ஒன்றிணைக்கப்படுகிறது |
| Tavily    | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                              |

பொதுவான புலங்கள் எப்போதும் முன்னுரிமை பெறும்: `query`, `max_results`, `filters` (களங்கள்), `country` மற்றும்
`search_type`-இலிருந்து பெறப்படும் தலைப்பு. Exa-வில், `search_type: "news"` என்பது `category: "news"` என்பதைத் தக்கவைக்கிறது.
Tavily, `search_type: "finance"` என்பதையும் ஏற்கிறது (`topic: "finance"`).

பொதுவான `time_range` இப்போது இரு வழங்குநர்களையும் சென்றடைகிறது: Exa-க்கு `startPublishedDate` (ISO
நேர முத்திரை) கிடைக்கும்; Tavily-க்கு `start_date` (`YYYY-MM-DD`) கிடைக்கும். `provider_options`-இல்
வெளிப்படையாகக் குறிப்பிடப்பட்ட தேதி, பொருத்தப்பட்ட தேதியை மேலெழுதும்.

Exa முடிவுகள் `id`, `highlight_scores`, `summary`, `subpages`, `entities` மற்றும் `extras` ஆகியவற்றை
`provider_raw`-இல் தக்கவைக்கின்றன. Tavily முடிவுகள் `images` மற்றும் `favicon` ஆகியவற்றைத் தக்கவைக்கின்றன.

செலவுக் கணக்கீடு இன்னும் தட்டையான பதிவகமான `costPerQuery` ஆகவே உள்ளது. Tavily,
`search_depth: "advanced"`-க்கு ஒவ்வொரு அழைப்பிலும் அதிக கிரெடிட்களை வசூலிக்கிறது; அந்த வேறுபாடு
`usage.search_cost_usd`-இல் பிரதிபலிக்கப்படுவதில்லை.

## Web Fetch API

கட்டமைக்கப்பட்ட web-fetch வழங்குநர் (Firecrawl, Jina Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract) வழியாக ஒரு URL-இலிருந்து உள்ளடக்கத்தைப் பிரித்தெடுக்கிறது.

Parallel Extract (`parallel-search`, Parallel Search பயன்படுத்தும் அதே API key) Markdown-ஐ மட்டுமே வழங்கும் — வேறு எந்த `format`-உம் `400` பிழையை ஏற்படுத்தும் — மேலும் உள்ளடக்கத்தை 100,000 எழுத்துகளாக வரம்பிடும். இலக்குப் பக்கத்தையே பிரித்தெடுக்க முடியாதபோது, upstream அதை HTTP 200 பதிலுக்குள் தெரிவிக்கும்; OmniRoute அதை ஒரு நிலையான செய்தியுடன் `422` ஆக வெளிப்படுத்தும்.

| முறை | பாதை            | விளக்கம்                                                                        |
| ---- | --------------- | ------------------------------------------------------------------------------- |
| POST | `/v1/web/fetch` | ஒரு URL-ஐப் பெற்று/சுரண்டும் — body, `v1WebFetchSchema` மூலம் சரிபார்க்கப்படும் |

**அங்கீகாரம்:** Bearer API key (`extractApiKey` + `isValidApiKey`). கொள்கை `enforceApiKeyPolicy` மூலம் அமல்படுத்தப்படுகிறது.

**ஒதுக்கீட்டைக் கருத்தில்கொள்ளும் fallback (#8297):** வெளிப்படையான `provider` எதுவும் கொடுக்கப்படாதபோது, pool
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) நிலையான முன்னுரிமை வரிசையில் (fill-first)
பரிசீலிக்கப்படும் — rate limit எட்டியிருந்தாலும் கட்டமைக்கப்பட்டுள்ள வழங்குநர்,
கோரிக்கையை உடனடியாக நிறுத்துவதற்குப் பதிலாகத் தவிர்க்கப்படும்; மேலும் மீண்டும் முயற்சிக்கக்கூடிய/ஒதுக்கீடு சார்ந்த upstream தோல்வி
(HTTP 429 எப்போதும்; Firecrawl/Tavily/TinyFish-இன் ஒதுக்கீடு சார்ந்த இலவச அடுக்குகளுக்கு 402/403 —
Jina Reader-க்கு அல்ல, மேலும் சாதாரண 400 தவறான கோரிக்கைக்கு ஒருபோதும் அல்ல) ஏற்பட்டால், கோரிக்கை நேரத்தில்
இதுவரை முயற்சிக்கப்படாத, சான்றுகள் உள்ள அடுத்த வழங்குநருக்கு fallback செய்யப்படும். pool-இல் உள்ள ஒவ்வொரு வழங்குநரும்
தீர்ந்துவிட்டால், முந்தைய பொதுவான `400`-க்குப் பதிலாக endpoint ஒரு `429`-ஐ
(`Retry-After` header-உடன்) வழங்கும். வெளிப்படையான `provider` கோரப்பட்டால்,
அமைதியான fallback **இல்லை** — rate limit எட்டிய அல்லது தோல்வியடைந்த வெளிப்படையான
வழங்குநர் அதன் சொந்தப் பிழையை வெளிப்படுத்தும் (rate limit எட்டியிருந்தால் `429`, இல்லையெனில் upstream
status).

## WebSocket ஸ்ட்ரீமிங்

```bash
GET /v1/ws?handshake=1
```

WebSocket மேம்படுத்தல் கைகுலுக்கலைச் சரிபார்த்து, கம்பி நெறிமுறை எடுத்துக்காட்டுச் செய்திகளை (`request`, `cancel`) திருப்பி அனுப்புகிறது. உண்மையான WS சட்டகங்கள் Next.js வழித்தட அட்டவணைக்கு வெளியே உள்ள தொகுக்கப்பட்ட WS சேவையகத்தால் கையாளப்படுகின்றன.

**அங்கீகாரம்:** கைகுலுக்கலின்போது Bearer API விசை.

### WebSocket வழியான Responses API (codex மட்டும்)

```bash
# HTTP API-இன் அதே host:port (இயல்புநிலை 20128); இணைப்பை மேம்படுத்தவும்:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (அல்லது: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# முதல் சட்டகம் response.create ஆகவே இருக்க வேண்டும்:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Responses-API-over-WebSocket proxy **`codex` உடன் மட்டுமே பிரத்தியேகமாக இணைக்கப்பட்டுள்ளது** (ChatGPT
பின்புலம்). இது API/dashboard பயன்படுத்தும் அதே port-இல் `/v1/responses`,
`/responses`, மற்றும் `/api/v1/responses` பாதைகளில் கவனித்துக் கொண்டிருக்கும். முதல் `response.create` சட்டகத்தில் இது
உள் `codex-responses-ws` bridge வழியாக அங்கீகரித்து + தயார்படுத்தி, ஒரு
codex OAuth இணைப்பைத் தேர்ந்தெடுத்து, `wreq-js` போக்குவரத்து வழியாக `wss://chatgpt.com/backend-api/codex/responses`
க்கு tunnel செய்கிறது. **codex அல்லாத models நிராகரிக்கப்படுகின்றன** (`codex_ws_provider_required`).
ஒதுக்கீட்டுப் பகிர்வு routing-க்கு `model: "qtSd/<group>/codex/<model>"` ஐப் பயன்படுத்தவும். இது
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts` ஆகியவற்றில் செயல்படுத்தப்பட்டுள்ளது.

**அங்கீகாரம்:** கைகுலுக்கலின்போது Bearer API விசை. தொகுக்கப்பட்ட HTTP சேவையகம் (`server-ws.mjs`)
செயலில் உள்ள entrypoint ஆக இருக்க வேண்டும் (`app/server-ws.mjs` இருந்தால், இயல்புநிலையாக அதுவே இருக்கும்).

#### Model id: எளிய ChatGPT id-ஐப் பயன்படுத்தவும் (`codex/` முன்னொட்டு வேண்டாம்)

`supports_websockets = true` ஆக இருக்கும்போது OpenAI **Codex CLI** model பெயரை client பக்கத்தில் சரிபார்த்து,
`codex/gpt-5.5` போன்ற **வழங்குநர் முன்னொட்டுள்ள ids-ஐ நிராகரிக்கிறது**
(`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). **எளிய** id-ஐ அனுப்பவும் (எ.கா. `gpt-5.5`). OmniRoute-இன் bridge
codex-க்கு மட்டுமே உரியது; எனவே மேல்நிலைக்கு tunnel செய்வதற்கு முன்,
எளிய `gpt-5.5` HTTP வழியாக வேறொரு வழங்குநருக்கு route ஆகக்கூடும் என்றாலும்,
அது எளிய id-ஐ codex model ஆக மீண்டும் தீர்மானிக்கிறது
(`resolveCodexWsModelInfo`).

#### OpenAI Codex CLI-ஐக் கட்டமைத்தல்

WebSocket ஆதரவுள்ள தனிப்பயன் வழங்குநரை `~/.codex/config.toml` இல் சேர்த்து Codex CLI-ஐ
OmniRoute-ஐ நோக்குமாறு அமைக்கவும் (ஏற்கனவே உள்ள கட்டமைப்பை மாற்றாமல் இருக்கத் தனியான `CODEX_HOME`-ஐப் பயன்படுத்தவும்):

```toml
model = "gpt-5.5"                 # எளிய id — "codex/gpt-5.5" அல்ல
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # இறுதியில் slash வேண்டாம்; WS URL இதிலிருந்து பெறப்படுகிறது (production-இல் https/wss பயன்படுத்தவும்)
wire_api = "responses"                    # Feb 2026 முதல் ஆதரிக்கப்படும் ஒரே மதிப்பு
supports_websockets = true                # Responses-over-WS போக்குவரத்தைச் செயல்படுத்துகிறது
env_key = "OMNIROUTE_API_KEY"             # OmniRoute API விசையை வைத்திருக்கும் (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # ஒரு OmniRoute API விசை (REQUIRE_API_KEY=false எனில் எந்த விசையும்)
codex exec "Responda apenas: PONG"
```

CLI ஆனது `base_url + /responses` ஐ WebSocket ஆக மேம்படுத்துகிறது; OmniRoute அதைத் தேர்ந்தெடுக்கப்பட்ட
codex OAuth இணைப்புக்குத் tunnel செய்கிறது. உள்ளூர் சேவையகத்தில் தொடக்கம் முதல் முடிவு வரை சரிபார்க்கப்பட்டது:
ChatGPT `codex.rate_limits` + `response.created` ஐத் திருப்பி அனுப்பி, நிறைவை
stream செய்கிறது.

## சுய சேவைப் பயன்பாடு (`/api/usage/om-usage`)

எந்த API விசையும் **அதன் சொந்த** பயன்பாடு மற்றும் ஒதுக்கீடுகளைப் படிக்கலாம் — மேலாண்மை அங்கீகாரம் தேவையில்லை. ஒரு விசை வைத்திருப்பவருக்கு அவருடைய செலவைக் காட்ட ஒரு கிளையன்ட் (CLI, OmniCopilot பலகம்) பயன்படுத்தும் முனைப்புள்ளி இதுவாகும்.

```bash
# உரை வடிவம் (வரலாற்று ஒப்பந்தம் — முனையத்திற்கான சாதாரண உரை)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# கட்டமைக்கப்பட்ட வடிவம் — UI பயன்படுத்துவது
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

விசையில் **`allowUsageCommand`** இயக்கப்பட்டிருக்க வேண்டும் (இயல்புநிலையில் முடக்கப்பட்டிருக்கும் — முகப்புப் பலகையின் API-விசை மேலாளர் ஒவ்வொரு விசைக்கும் இதை மாற்றி அமைக்கிறார்). அது இல்லாமல் முனைப்புள்ளி `403` எனப் பதிலளிக்கும்.

அழைப்பாளர் மறுப்பிலிருந்து தரவுப் புலத்தை ஒருபோதும் படிக்காமல் இருக்க, `?format=json` வேறுபடுத்தப்பட்ட வடிவமைப்பை வழங்குகிறது. வெற்றியடையும்போது:

```jsonc
{
  "allowed": true,
  // ஒவ்வொரு விசைக்குமான பயன்பாட்டு வரம்புகளை (தினசரி/வாராந்திர USD) விசை தேர்ந்தெடுத்திருந்தால் மட்டுமே இருக்கும்:
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // தேர்ந்தெடுக்கப்பட்ட வழங்குநரின் ஒதுக்கீட்டு நிலைப்படம்; இதுவரை எதுவும் தற்காலிக சேமிப்பில் இல்லையெனில் null:
  "provider": {
    "connectionId": "…",
    "provider": "claude",
    "plan": "…",
    "quotas": {/* … */},
  },
  // UI பல வழங்குநர்களை அருகருகே காட்டுவதற்காக, ஒவ்வொரு இணைப்பின் நிலைப்படமும்:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

மறுக்கப்படும்போது (`401` தவறான விசை / `403` அனுமதிக்கப்படவில்லை), அதே வழித்தடம்
`{ "allowed": false, "error": { "message": "…" } }` என்பதை வழங்கும் — உள்ளதாயினும் காலியாக இருக்கும் `personal`/`provider` (விசைக்கு அனுமதி உள்ளது, ஆனால் இதுவரை எதுவும் அறியப்படவில்லை) என்பது மறுப்பிலிருந்து வேறுபட்ட நிலையாகும்; JSON வடிவம் மட்டுமே அவற்றை வேறுபடுத்துகிறது.

**அங்கீகாரம்:** அழைப்பாளரின் சொந்த Bearer API விசை, `isValidApiKey` மூலம் சரிபார்க்கப்படுகிறது — இது `requireManagementAuth`-க்குப் பின்னால் தொடர்ந்திருக்கும் மேலாண்மைத் தளம் (`/api/keys/…`) _அல்ல_.

### மூல மற்றும் துண்டிப்பு-சரிசெய்யப்பட்ட ஒதுக்கீட்டு சதவீதங்கள்

`/api/usage/om-usage`-ஐப் பயன்படுத்தும்போது, **சாதாரண-உரை வெளியீடு** மற்றும் கட்டமைக்கப்பட்ட **JSON வெளியீடு** வழங்கும் சதவீதங்களுக்கு இடையிலான வேறுபாட்டை அழைப்பாளர்கள் கவனத்தில் கொள்ள வேண்டும்:

| அம்சம்                       | சாதாரண-உரை வடிவம் (`/api/usage/om-usage` / `@@om-usage`)                                                         | JSON வடிவம் (`?format=json`)                                                                    |
| :--------------------------- | :--------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------- |
| **வெளியீட்டுப் புலம்**       | `NN% left` (எ.கா., `20% left`)                                                                                   | `provider.quotas` / `providers[].quotas`                                                        |
| **அளவீடு**                   | **துண்டிப்பு-சரிசெய்யப்பட்ட பயன்படுத்தத்தக்க அனுமதி**: துண்டிப்பு வரம்புக்கு மேலுள்ள மீதித் திறன்                | **மூல மேல்நிலை ஒதுக்கீடு**: சரிசெய்யப்படாத வழங்குநர் அளவீடு                                     |
| **துண்டிப்பு அளவீட்டாக்கம்** | பாதுகாக்கப்பட்ட இருப்பு `0% left` எனக் காட்டப்படும்படி `effectiveRemainingPercent()` மூலம் அளவீட்டாக்கப்படுகிறது | இல்லை (வழங்குநர் அறிவித்தபடியான மூல நிலைப்பட மதிப்புகள்)                                        |
| **வரம்புத் தரவு**            | காட்டப்படும் சதவீதத்தில் சேர்க்கப்பட்டுள்ளது                                                                     | ஒவ்வொரு இணைப்பிலும் `quotaWindowThresholds`-இல் சேமிக்கப்படுகிறது (அல்லது சேவையக இயல்புநிலைகள்) |
| **முதன்மைப் பயனாளர்**        | ஊடாடும் CLI-கள், முனையத் தூண்டல்கள், மனித இயக்குநர்கள்                                                           | நிரலாக்க ஒருங்கிணைப்புகள், முகப்புப் பலகைகள், பகுப்பாய்வுகள், கட்டணக் கண்காணிப்பான்கள்          |

#### துண்டிப்பு சரிசெய்தல் சூத்திரம்

மேல்நிலை வளங்கள் தீர்ந்துபோவதைத் தடுக்க OmniRoute முன்கூட்டிய ஒதுக்கீட்டுத் துண்டிப்புகளை ஆதரிக்கிறது (இணைப்பு `quotaWindowThresholds`, வழங்குநர் இயல்புநிலைகள் அல்லது உலகளாவிய மீட்சித்தன்மை அமைப்புகள் வழியாக உள்ளமைக்கப்படுகிறது). ஒரு ஒதுக்கீட்டுச் சாளரத்தில் துண்டிப்பு வரம்பு (எ.கா., `cutoff = 25%`) செயல்பாட்டில் இருக்கும்போது, உரை வழங்குநிரல் மீதமுள்ள அனுமதியைப் பின்வருமாறு கணக்கிடுகிறது:

- `remaining <= cutoff` எனில்: `0%`-ஐ வழங்கும்.
- `remaining > cutoff` எனில்: `((remaining - cutoff) / (100 - cutoff)) * 100`-ஐ வழங்கும்.

வடிவமைக்கப்பட்ட உரை வெளியீடு இதை அருகிலுள்ள முழு எண்ணுக்கு முழுமைப்படுத்துகிறது (`Math.round(...)`).

#### விளக்க எடுத்துக்காட்டு

**60% மூலப் பயன்பாடு** (எனவே **40% மூல மீதி ஒதுக்கீடு**) கொண்ட வழங்குநர் சாளரத்தையும், உள்ளமைக்கப்பட்ட **25% மீதி-ஒதுக்கீட்டுத் துண்டிப்பு** வரம்பையும் எடுத்துக்கொள்வோம்:

| பிரதிநிதித்துவம்              | கணக்கீடு                                           | மீதமுள்ளது |       குறிப்பாக உணர்த்தப்படும் பயன்பாடு       |
| :---------------------------- | :------------------------------------------------- | :--------: | :-------------------------------------------: |
| **மூல JSON (`?format=json`)** | மேல்நிலை நிலைப்படம் (`quotas[window]`)             |  **40%**   |                    **60%**                    |
| **உரை வடிவம் (`NN% left`)**   | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` |  **20%**   | **80%** (`100 - remaining` எனக் கணக்கிட்டால்) |

- **உரையில் ஏன் 20% மீதமுள்ளதாகக் காட்டப்படுகிறது:** கணக்கில் மீதமுள்ள 40% இயல்பான ஒதுக்கீட்டில், 25% துண்டிப்புக் கொள்கையால் ஒதுக்கி வைக்கப்படுகிறது. இந்த இணைப்புக்கு வழிப்படுத்துவதை வழிப்படுத்தி நிறுத்துவதற்கு முன், பயன்படுத்தத்தக்க 75% இடைவெளியில் அழைப்பாளருக்கு 15% மட்டுமே மீதமுள்ளது. வழிப்படுத்துதல் நிறுத்தப்படும் சரியான தருணத்தில் இணைப்பு தீர்ந்துபோனதாக (`0% left`) காட்டப்படுவதை அளவீட்டாக்கம் உறுதிசெய்கிறது.
- **JSON ஏன் மூல மதிப்புகளைப் பாதுகாக்கிறது:** JSON தரவுச்சுமை துல்லியமான வழங்குநர் நிலைப்படத்தை (`UsageSnapshot`) வழங்குகிறது; இதனால் வெளிப்புறக் கருவிகள் சேவையகத் தரப்பிலான இழப்புடைய அளவீட்டாக்கம் இல்லாமல், மேல்நிலைப் பயன்பாட்டின் உண்மைத் தரவையும் இணைப்பு-நிலை `quotaWindowThresholds`-ஐயும் அணுக முடியும்.

#### பயனாளர் இடமாற்ற வழிகாட்டுதல்

வெளிப்புற ஒருங்கிணைப்பு (எடுத்துக்காட்டாக, தொகுப்பான் செருகுநிரல் அல்லது முகவர் நீட்டிப்பு) முன்பு உரை முனைப்புள்ளியிலிருந்து (`NN% left`) தரவைப் பிரித்தெடுத்து, பயன்படுத்தப்பட்ட சதவீதத்தை `100 - NN` எனக் கணக்கிட்டிருந்தால், `?format=json`-க்கு இடமாற்றுவது என்பது:

- மூல JSON மதிப்புகளைப் படிப்பது **உண்மையான மேல்நிலை நுகர்வைப்** பிரதிபலிக்கும் (மேலுள்ள எடுத்துக்காட்டில் 60% பயன்படுத்தப்பட்டுள்ளது).
- உரை முனைப்புள்ளியின் பயன்படுத்தத்தக்க-அனுமதிப் பொருளியலை ஒருங்கிணைப்பு தொடர்ந்து பாதுகாக்க விரும்பினால், இணைப்பு-நிலை மேலெழுதல்களுக்கான `quotaWindowThresholds`-ஐப் பயன்படுத்தி, பயனாளர் தரப்பில் செயல்திறனுள்ள மீதி சூத்திரத்தை மதிப்பிடலாம்.

## பொருள்சார் Cache

```bash
# Cache புள்ளிவிவரங்களைப் பெறவும்
GET /api/cache/stats

# அனைத்து cache-களையும் அழிக்கவும்
DELETE /api/cache/stats
```

பதில் எடுத்துக்காட்டு:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### தாமதத்தின் மீதான தாக்கம்

ஒரு பொருள்சார் cache HIT, **upstream அழைப்பு இல்லாமல்** cache-இலிருந்து பதிலை வழங்கும்;
எனவே அறிக்கையிடப்படும் `X-OmniRoute-Response-Latency` ஏறத்தாழ பூஜ்ஜியமாக இருக்கும்
(அசல் upstream தாமதத்தைப் பொருட்படுத்தாமல்). தாமதத்தைப் பொறுத்து செயல்படும் client-கள்
(தரநிலைச் சோதனை, p50/p99 கண்காணிப்பு) `X-OmniRoute-Cache-Latency` response header-ஐச்
சரிபார்க்க வேண்டும்:

| மதிப்பு     | பொருள்                                                                |
| ----------- | --------------------------------------------------------------------- |
| `synthetic` | பதில் cache-இலிருந்து வழங்கப்பட்டது; தாமதம் உண்மையான upstream நேரமல்ல |
| _(இல்லை)_   | உண்மையான upstream அழைப்பிலிருந்து வந்த பதில்                          |

### ஒவ்வொரு விசைக்குமான cache தவிர்ப்பு

API விசைகள் `cacheDefaultMode` வழியாக பொருள்சார் cache வாசிப்புகளைத் தவிர்க்கலாம்:

| மதிப்பு  | செயல்பாடு                                                       |
| -------- | --------------------------------------------------------------- |
| `legacy` | இயல்பான cache செயல்பாடு (இயல்புநிலை)                            |
| `bypass` | Cache தேடலை முழுமையாகத் தவிர்த்து, எப்போதும் upstream-ஐ அணுகும் |

விசை உருவாக்கத்தின்போது (`POST /api/keys`) அமைக்கவும் அல்லது புதுப்பிக்கவும் (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### ஒவ்வொரு கோரிக்கைக்குமான தவிர்ப்பு

விசை அமைப்புகளைப் பொருட்படுத்தாமல் எந்தக் கோரிக்கையும் cache-ஐத் தவிர்க்கலாம்:

```
X-OmniRoute-No-Cache: true
```

OpenAI-இணக்க வழங்குநர் பக்கம் அதே திருத்து/அழி கட்டுப்பாடுகளை வழங்குகிறது, மேலும் வெளிப்படையான காட்சி ஆதரவு கொண்ட மாதிரிகளைக் குறிக்கிறது.

தனிப்பயன் Chat Completions முனைகள் வெளிப்படையான பகுத்தறிவு தேர்வு-விலக்குகளை மேல்நோக்கு பின்தங்கலுக்கு ஏற்றவாறு மாற்றியமைக்கின்றன. வெற்றிகரமான இணைப்பு சோதனையானது, அங்கீகரிக்கப்பட்ட `owned_by` மதிப்பைத் தனது `/models` பதிவு நிரூபிக்கும் ஒவ்வொரு சரியான மாதிரி ID-க்கும் தானாகவே chat-template கட்டுப்பாடுகளைத் தேர்ந்தெடுக்கிறது: `vllm`, `sglang`, அல்லது `llamacpp`. வெளிப்படையான OpenAI-இணக்க மடிப்புகள் அசல் மாதிரி பதிவை உள்ளடக்கப்பட்ட `openai` பொருளுக்குள் பாதுகாக்கலாம்; கண்டறிதல் மூன்று அத்தகைய உறைகள் வரை தொடர்கிறது. உரிமை விடுபட்ட, தெரியாத, அல்லது முரண்பாடான மாதிரிகள் சாதாரண OpenAI நடத்தையைத் தொடர்கின்றன. கண்டறிதல் ஏற்கனவே உள்ள பட்டியல் கோரிக்கையை மீண்டும் பயன்படுத்துகிறது, எந்த நிறைவு டோக்கன்களையும் உருவாக்குவதில்லை, மேலும் இணைப்பு இறுதிப்புள்ளி மாறும்போது செல்லாததாகிறது.

அந்த மெட்டாடேட்டாவை வெளிப்படுத்தாத பின்தங்கலுக்கு நடத்தையை நிலைநிறுத்த, ஏற்கனவே உள்ள பகுதி வழங்குநர் புதுப்பிப்பு API ஐப் பயன்படுத்தவும்:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

அந்த body-ஐ `PUT /api/providers/<connection-id>` உடன் அனுப்பவும். அந்த இணைப்பில், `none` என்ற வெளிப்படையான reasoning முயற்சி `chat_template_kwargs.thinking=false` மற்றும் `chat_template_kwargs.enable_thinking=false` ஆக அனுப்பப்படுகிறது. சர்வர்-பக்க reasoning விதி ஒரு முயற்சியைக் கட்டாயப்படுத்தாத வரை, வெளிப்படையான நேட்டிவ் டெம்ப்ளேட் மதிப்புகள் அதிகாரப்பூர்வமாக இருக்கும். தனிப்பயன் OpenAI-இணக்கமான இணைப்பு Chat Completions body-ஐ அனுப்பும்போது மட்டுமே இந்த அமைப்பு பொருந்தும்; Responses கோரிக்கைகள் மற்றும் சாதாரண provider-கள் தங்கள் நேட்டிவ் கோரிக்கை வடிவத்தைத் தக்கவைத்துக்கொள்ளும். சாதாரண OpenAI `reasoning_effort` passthrough-ஐ கட்டாயப்படுத்த `reasoningControl`-ஐ `openai` என அமைக்கவும், அல்லது தானியங்கு கண்டறிதலைப் பயன்படுத்த அதை விட்டுவிடவும்/`null` என அமைக்கவும்.

வெளிப்படையான reasoning கட்டுப்பாடுகள் எதுவும் இல்லாதபோது, Claude Code auto-mode classifier கோரிக்கைகள் நேட்டிவ் thinking-ஐ முடக்கப்பட்டதாக இயல்புநிலைப்படுத்துகின்றன. கண்டறிதல் மாடல் பெயர்கள் அல்லது completion வரம்புகளை அல்லாமல், Claude-வடிவ கோரிக்கைகளில் உள்ள classifier-இன் system marker-ஐப் பயன்படுத்துகிறது. வெளிப்படையான body கட்டுப்பாடுகள், ஆதரிக்கப்படும் effort/thinking header-கள், routing விதிகள் மற்றும் தீர்மானிக்கப்பட்ட மாடல் effort ஆகியவை தங்கள் தற்போதைய முன்னுரிமையைத் தக்கவைத்துக்கொள்கின்றன. இரண்டு classifier நிலைகளும் தங்கள் prompt-கள், completion வரம்புகள், stop sequence-கள் மற்றும் உண்மையான upstream அனுமதி தீர்ப்புகளைத் தக்கவைத்துக்கொள்கின்றன; இரண்டாம் நிலை தனது கோரப்பட்ட புலனாகும் reasoning-ஐ இன்னும் சாதாரண உரையாக உருவாக்க முடியும்.

`PATCH /api/keys/{id}` ஏற்கனவே உள்ள key-இன் அனுமதிகளைப் புதுப்பிக்கிறது. மற்ற எல்லா `/api/keys*` ரூட்களைப் போலவே, இதற்கு inference key அல்ல, நிர்வாக அங்கீகாரம் தேவை ([நிர்வாக அங்கீகாரம்](../guides/MANAGEMENT-AUTH.md) பார்க்கவும்). மாற்ற விரும்பும் புலங்களை மட்டும் அனுப்பவும்; அவற்றில் எதுவும் இல்லாத கோரிக்கை `No valid fields to update` என்று நிராகரிக்கப்படும். ஏற்றுக்கொள்ளப்படும் புலங்கள் `src/shared/validation/schemas/keys.ts`-இல் உள்ள `updateKeyPermissionsSchema` மூலம் வரையறுக்கப்பட்டுள்ளன.

`/api/db-backups/export`, `/api/db-backups/exportAll` மற்றும் `/api/settings/export-json` ஆகியவை சேமிக்கப்பட்ட ஒவ்வொரு நற்சான்றிதழையும் வழங்குகின்றன, எனவே அவை டாஷ்போர்டு அமர்வை அல்லது உள்ளூர் CLI-ஐ (அல்லது உள்நுழைவு முடக்கப்பட்டிருத்தலை) தேவைப்படுத்துகின்றன. எந்தவொரு நோக்கத்தின் API விசைகளும் `oma_` அணுகல் டோக்கன்களும் `403` பெறுகின்றன. மீட்டெடுப்புகளும் அதே எல்லையைக் கொண்டுள்ளன: `POST /api/db-backups/import` (`dryRun=true` உட்பட), `POST /api/db-backups` (id மூலம் மீட்டெடுப்பு) மற்றும் `POST /api/settings/import-json` ஆகியவை நேரடி தரவுத்தளத்தையோ அமைப்புகளையோ மாற்றுகின்றன, எனவே இயந்திர நற்சான்றிதழும் அங்கு `403` பெறுகிறது; `omniroute sync import` உள்ளூர் CLI நற்சான்றிதழை அனுப்புகிறது. `DELETE /api/db-backups` (சேமிக்கப்பட்ட காப்புப்பிரதிகளைக் குறைத்தல்) மற்றும் `PATCH /api/db-backups` (தக்கவைப்பு அமைப்புகள்: நிலைத்திருக்கும் மதிப்புகள் ஒவ்வொரு காப்புப்பிரதிக்குப் பிறகும் தானியங்கு குறைப்பை இயக்குகின்றன) ஆகியவையும் அவ்வாறே. பட்டியலிடுதல் (`GET`) மற்றும் கைமுறை காப்புப்பிரதியை உருவாக்குதல் (`PUT`) சாதாரண நிர்வாக அங்கீகாரத்தைத் தக்கவைக்கின்றன.

### பதிப்பு மற்றும் வெளியீட்டு சேனல்

```bash
GET /api/system/version
```

லூப்பேக்-மட்டுமேயான நிர்வாக வழி (admin அங்கீகாரம்). இயங்கும் பதிப்பு, சமீபத்திய வெளியிடப்பட்ட பதிப்பு மற்றும் தானியங்கு-புதுப்பிப்பு நிலையைத் திருப்பி அனுப்புகிறது. `releaseChannel` மற்றும் `channels` கூடுதல் புலங்கள் (rail 3.8.54); `channel` தனது அர்த்தத்தைத் தக்கவைத்துக் கொள்கிறது — டேஷ்போர்டு புதுப்பிப்பாளர் பயன்படுத்தும் அமைப்பு முறை (`npm`, `source` அல்லது `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — இயங்கும் பில்டின் npm சேனல்: `-nightly.*` பதிப்புகளுக்கு `nightly`, மற்ற முன்-வெளியீடுகளுக்கு (`-rc.*`, `-beta.*`, `-alpha.*`) `next`, `channels.latest`-ஐ விடப் பழைய மேஜர் பதிப்பின் நிலையான பதிப்புக்கு `lts`, இல்லையெனில் `latest`. வெளியீட்டு நேரத்தில் npm dist-tag-ஐத் தேர்ந்தெடுக்கும் `scripts/release/dist-tag.mjs`-ஐப் போலவே அதே விதிகள்.
- `channels` — ஒவ்வொரு dist-tag-இன் வெளியிடப்பட்ட சமீபத்திய பதிப்பு, `npm view omniroute dist-tags`-இலிருந்து (registry HTTP தற்காலிக மாற்று), `latest`-ஐப் போலவே அதே 10-நிமிட TTL உடன் கேஷ் செய்யப்படுகிறது. `latest` எப்போதும் இருக்கும் (முதலில் `latest` புலத்தை நோக்கிச் சென்று, பின்னர் `"unavailable"`-ஆக மாறுகிறது); `next`, `nightly` மற்றும் `lts` அந்த dist-tag இருக்கும்போது மட்டுமே தோன்றும். `Cache-Control: no-cache` கோரிக்கை இரண்டு தேடல்களையும் புதுப்பிக்கிறது.

சேனல் மாதிரி (4.0 GA வரை `latest` = v3, `next` = rc, `nightly` = `develop` பில்டுகள், 4.0 GA-க்குப் பிறகு `lts` = v3 பேட்சுகள்) `docs/ops/RELEASE_STRATEGY.md`-இல் விவரிக்கப்பட்டுள்ளது.

உள்ளமைக்கப்பட்ட எந்தவொரு STT வழங்குநரையும் பயன்படுத்தி ஒலிக் கோப்புகளை எழுத்துப்பதிவு செய்யலாம். பாதையின் முதல்
பகுதி மூல வழங்குநரைத் தேர்ந்தெடுக்கிறது (`openai/…`, `deepgram/…`). வேறொரு வழங்குநரின் மாதிரியை
மறுஏற்றுமதி செய்யும் நுழைவாயில்கள் தகுதிப்படுத்தப்பட்ட id-ஐப் பயன்படுத்துகின்றன
(`openrouter/deepgram/nova-3`).

**கோரிக்கை:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**பதில்:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**எடுத்துக்காட்டு மாதிரி id-கள்:** `openai/whisper-1` (OpenAI விசை தேவை),
`openrouter/deepgram/nova-3` (OpenRouter விசை தேவை),
`deepgram/nova-3` (மூல Deepgram விசை தேவை). வெறும்
`deepgram/nova-3` கோரிக்கை OpenRouter-ஐப் பயன்படுத்தாது.

**ஆதரிக்கப்படும் வடிவங்கள்:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`.

Ollama-வின் API வடிவத்தைப் பயன்படுத்தும் கிளையன்ட்களுக்கு:

## டோக்கன் சேர்க்கப்பட்ட VS Code / தலைப்பில்லா மாற்றுப்பெயர்கள்

ஒரு ஒருங்கிணைப்பால் `Authorization` தலைப்பைச் சேர்க்க முடியாதபோதும், API விசையை அடிப்படை URL-இல் உட்பொதிக்க வேண்டியபோதும் இந்த மாற்றுப்பெயர்களைப் பயன்படுத்தவும்.

```bash
# OpenAI பாணி பட்டியல் மாற்றுப்பெயர்
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# OpenAI பாணி அரட்டை மாற்றுப்பெயர்கள்
POST /api/v1/vscode/{token}/chat/completions
POST /api/v1/vscode/{token}/responses

# Ollama பாணி மாற்றுப்பெயர்கள்
POST /api/v1/vscode/{token}/api/chat
GET /api/v1/vscode/{token}/api/tags
```

எடுத்துக்காட்டு:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'
```

குறிப்புகள்:

- டோக்கன் சேர்க்கப்பட்ட மாற்றுப்பெயர்கள் `/v1/*` மற்றும் `/api/tags` பயன்படுத்தும் அதே கையாளிகளை மீண்டும் பயன்படுத்துகின்றன; பதில் வடிவங்கள் மாற்றமின்றி இருக்கும்.
- கிளையன்ட் தனிப்பயன் தலைப்புகளை ஆதரிக்கும்போதெல்லாம் `Authorization: Bearer ...` பயன்படுத்துவதற்கு முன்னுரிமை அளிக்கவும்.
- URL அடிப்படையிலான டோக்கன்கள், OmniRoute-க்கு வெளியேயுள்ள reverse-proxy பதிவுகள், உலாவி வரலாறு மற்றும் தொலைஅளவீட்டுத் தரவுகளில் தோன்றக்கூடும். அவற்றை இயல்புநிலை அங்கீகார முறையாக அல்லாமல், இணக்கத்தன்மைக்கான ஒரு விருப்பமாகக் கருதவும்.

## வரவுசெலவுத் திட்டம்

```bash
# அனைத்து API விசைகளுக்குமான வரவுசெலவுத் திட்ட நிலையைப் பெறுதல்
GET /api/usage/budget

# வரவுசெலவுத் திட்டத்தை அமைத்தல் அல்லது புதுப்பித்தல்
POST /api/usage/budget
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "dailyLimitUsd": 5.00,
  "weeklyLimitUsd": 30.00,
  "monthlyLimitUsd": 100.00,
  "warningThreshold": 0.8,
  "resetInterval": "monthly"
}
```

> **திட்டவடிவக் குறிப்புகள்** (`setBudgetSchema`): `apiKeyId` கட்டாயமானது; `dailyLimitUsd`, `weeklyLimitUsd`, அல்லது `monthlyLimitUsd` ஆகியவற்றில் குறைந்தது ஒன்று பூஜ்ஜியத்தைவிட அதிகமாக இருக்க வேண்டும். விருப்பப் புலங்கள்: `warningThreshold` (0–1), `resetInterval` (`daily` | `weekly` | `monthly`), `resetTime` (`HH:MM`). பழைய `{keyId, limit, period}` வடிவம் `400 Bad Request` என்பதைத் திருப்பியளிக்கும்.

## டோக்கன் வரம்புகள்

ஒவ்வொரு API விசைக்குமான **டோக்கன்** ஒதுக்கீடுகள் (மேலே உள்ள USD அடிப்படையிலான ஒதுக்கீட்டிலிருந்து வேறுபட்டவை). கோரிக்கை பாதையிலேயே அமல்படுத்தப்படுகின்றன: ஒரு விசையின் தற்போதைய சாளரப் பயன்பாடு அதன் வரம்பை எட்டும்போது, கோரிக்கைகள் `429 Too Many Requests` உடன் நிராகரிக்கப்படும். வரம்புகளை ஒரு குறிப்பிட்ட `model`, ஒரு `provider` ஆகியவற்றுக்கு வரையறுக்கலாம் அல்லது விசை முழுவதும் `global` ஆகப் பயன்படுத்தலாம்; ஒரு கோரிக்கைக்குப் பல வரம்புகள் பொருந்தும்போது, மிகவும் கட்டுப்பாடான வரம்பே செயல்படுத்தப்படும்.

```bash
# ஒரு விசையின் டோக்கன் வரம்புகளைப் பட்டியலிடுதல் (நேரடி சாளரப் பயன்பாட்டையும் உள்ளடக்கும்)
GET /api/usage/token-limits?apiKeyId=key-123

# ஒரு டோக்கன் வரம்பை உருவாக்குதல் அல்லது புதுப்பித்தல்
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# id மூலம் ஒரு டோக்கன் வரம்பை நீக்குதல்
DELETE /api/usage/token-limits?id=tl-abc
```

> **ஸ்கீமா குறிப்புகள்** (`setTokenLimitSchema`): `apiKeyId` மற்றும் `scopeType` (`model` | `provider` | `global`) கட்டாயமானவை. `scopeType` என்பது `global` ஆக இல்லாவிட்டால் `scopeValue` கட்டாயமாகும் (எ.கா., `model` வரம்பிற்கான ஒரு மாதிரி id, `provider` வரம்பிற்கான ஒரு வழங்குநர் id). `tokenLimit` ஒரு நேர்ம முழு எண்ணாக இருக்க வேண்டும் (சரத்திலிருந்து மாற்றப்படும்). விருப்பத்திற்குரியவை: `id` (உருவாக்கத் தவிர்க்கவும், புதுப்பிக்க வழங்கவும்), `resetInterval` (`daily` | `weekly` | `monthly`, இயல்புநிலை `monthly`), `resetTime` (`HH:MM`), `enabled` (இயல்புநிலை `true`). `GET` பதில்கள் ஒவ்வொரு வரம்பையும் `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, மற்றும் `nextResetAt` ஆகியவற்றுடன் செறிவூட்டுகின்றன. இது ஒரு மேலாண்மை-வகுப்பு முனைப்புள்ளி (அங்கீகாரம் authz செயலாக்கத் தொடரால் மையமாக அமல்படுத்தப்படுகிறது).

## கோரிக்கை செயலாக்கம்

1. கிளையண்ட் `/v1/*` க்கு கோரிக்கையை அனுப்புகிறது
2. வழித்தடக் கையாளி `handleChat`, `handleEmbedding`, `handleAudioTranscription`, அல்லது `handleImageGeneration` ஐ அழைக்கிறது
3. மாதிரி தீர்மானிக்கப்படுகிறது (நேரடி வழங்குநர்/மாதிரி அல்லது மாற்றுப்பெயர்/காம்போ)
4. கணக்குக் கிடைப்புத்தன்மை வடிகட்டலுடன் உள்ளூர் DB-யிலிருந்து சான்றுகள் தேர்ந்தெடுக்கப்படுகின்றன
5. அரட்டைக்கு: `handleChatCore` அர்த்தவியல்/கையொப்பத் தற்காலிகச் சேமிப்பைச் சரிபார்த்து, காம்போ சுருக்க அமைப்புகளைத் தீர்மானிக்கிறது
6. இயக்கப்பட்டிருக்கும்போது வழங்குநர் மொழிபெயர்ப்புக்கு முன் முன்செயல் சுருக்கம் இயங்குகிறது (`lite`, Caveman, RTK, அல்லது அடுக்கப்பட்டவை)
7. வழங்குநர் செயல்படுத்தி மேல்நிலை கோரிக்கையை அனுப்புகிறது
8. பதில் மீண்டும் கிளையண்ட் வடிவத்திற்கு மொழிபெயர்க்கப்படுகிறது (அரட்டை) அல்லது உள்ளபடியே திருப்பி அனுப்பப்படுகிறது (உட்பொதிவுகள்/படங்கள்/ஒலி)
9. பயன்பாடு, சுருக்கப் பகுப்பாய்வு மற்றும் கோரிக்கைப் பதிவுகள் பதியப்படுகின்றன
10. காம்போ விதிகளின்படி பிழைகளின்போது மாற்று நடைமுறை பயன்படுத்தப்படுகிறது

முழுமையான கட்டமைப்புக் குறிப்பு: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## காம்போ மேலாண்மை

உயர்நிலை வழித்தடக் காம்போக்களை (`/api/combos*` என்பதன் கீழ் ஏற்கனவே சுருக்கப்பட்டுள்ளவை) ஒரு மாதிரி id வடிவத்திலிருந்து 1:1 ஆகவும் பொருத்தலாம்; இது OpenAI-பாணி மாதிரி id ஒன்றை வெளிப்படையாகத் தெரியாமல் ஒரு காம்போவிற்குத் திருப்பிவிட அனுமதிக்கிறது.

| முறை   | பாதை                             | விளக்கம்                                                                                 |
| ------ | -------------------------------- | ---------------------------------------------------------------------------------------- |
| GET    | `/api/model-combo-mappings`      | அனைத்து மாதிரி→காம்போ பொருத்தங்களையும் பட்டியலிடுதல்                                     |
| POST   | `/api/model-combo-mappings`      | பொருத்தத்தை உருவாக்குதல் — உடல்: `{pattern, comboId, priority?, enabled?, description?}` |
| GET    | `/api/model-combo-mappings/[id]` | ஒற்றைப் பொருத்தத்தைப் பெறுதல்                                                            |
| PUT    | `/api/model-combo-mappings/[id]` | ஏற்கனவே உள்ள பொருத்தத்தின் புலங்களைப் புதுப்பித்தல்                                      |
| DELETE | `/api/model-combo-mappings/[id]` | ஒரு பொருத்தத்தை அகற்றுதல்                                                                |

**அங்கீகாரம்:** மேலாண்மை அமர்வு/API விசை (`requireManagementAuth`).

## Webhooks

OmniRoute நிகழ்வுகளுக்கான வெளிச்செல்லும் webhook சந்தாக்கள் (கோரிக்கை நிறைவடைதல், ஒதுக்கீடு தீர்ந்துபோதல், விசைச் சுழற்சி போன்றவை).

| முறை   | பாதை                      | விளக்கம்                                                                         |
| ------ | ------------------------- | -------------------------------------------------------------------------------- |
| GET    | `/api/webhooks`           | Webhook-களைப் பட்டியலிடும் (ரகசியங்கள் `<prefix>...` என மறைக்கப்படும்)           |
| POST   | `/api/webhooks`           | Webhook-ஐ உருவாக்கும் — உடல்: `{url, events?: ["*"], secret?, description?}`     |
| GET    | `/api/webhooks/[id]`      | ஒரு webhook-ஐப் பெறும்                                                           |
| PUT    | `/api/webhooks/[id]`      | url/events/secret/description-ஐப் புதுப்பிக்கும்                                 |
| DELETE | `/api/webhooks/[id]`      | ஒரு webhook-ஐ அகற்றும்                                                           |
| POST   | `/api/webhooks/[id]/test` | Webhook URL-க்கு ஒரு சோதனை payload-ஐ அனுப்பி, விநியோக நிலையைத் திருப்பியளிக்கும் |

**அங்கீகாரம்:** மேலாண்மை அமர்வு/API விசை (`requireManagementAuth`).

## பதிவுசெய்யப்பட்ட விசைகள் (தானியங்கி மேலாண்மை)

தினசரி/மணிநேர ஒதுக்கீடுகளுடன், பின்னணி வழங்குநர்/கணக்கிற்கு எதிராக API விசைகளை வழங்கவும் சுழற்சி முறையில் மாற்றவும் தானியங்கி விசை மேலாண்மை துணைஅமைப்பால் பயன்படுத்தப்படுகிறது.

| முறை   | பாதை                                  | விளக்கம்                                                                                                                                                                                                                     |
| ------ | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/v1/registered-keys`             | பதிவுசெய்யப்பட்ட விசைகளைப் பட்டியலிடும் (மறைக்கப்பட்ட முன்னொட்டு மட்டும்)                                                                                                                                                    |
| POST   | `/api/v1/registered-keys`             | புதிய பதிவுசெய்யப்பட்ட விசையை வழங்கும் — உடல்: `{name, provider?, accountId?, idempotencyKey?, expiresAt?, dailyBudget?, hourlyBudget?}`. மூல விசையை **ஒருமுறை** மட்டும் வழங்கும். ஒதுக்கீடு மறுக்கப்பட்டால் `429` வழங்கும். |
| GET    | `/api/v1/registered-keys/[id]`        | பதிவுசெய்யப்பட்ட விசையின் மேனிலைத் தரவைப் பெறும் (மூல விசை இல்லை)                                                                                                                                                            |
| DELETE | `/api/v1/registered-keys/[id]`        | பதிவுசெய்யப்பட்ட விசையைத் திரும்பப்பெறும்                                                                                                                                                                                    |
| POST   | `/api/v1/registered-keys/[id]/revoke` | வெளிப்படையான திரும்பப்பெறல் முனைப்புள்ளி (DELETE போன்ற அதே விளைவு)                                                                                                                                                           |

**அங்கீகாரம்:** மேலாண்மை அமர்வு/API விசை (`requireManagementAuth`) — `/api/keys` பயன்படுத்தும் அதே பாதுகாப்புச் சோதனை: டாஷ்போர்டு அமர்வு, உள்ளூர் CLI டோக்கன் அல்லது `manage`/`admin` வரம்பைக் கொண்ட API விசை; அனுமானத்திற்கு மட்டும் உரிய API விசைகள் `403` பெறும். மேலும் `/v1/quotas/check` மற்றும் `/v1/issues/report` ஆகியவற்றைப் பார்க்கவும்.

## மீள்தன்மை (விரிவாக்கம்)

OmniRoute மூன்று சுயாதீனமான தற்காலிகத் தோல்வி பொறிமுறைகளை வெளிப்படுத்துகிறது; கீழே உள்ள மேலாண்மை இறுதிப்புள்ளிகள் இயக்குநர்களை அவற்றைப் படிக்கவும் மேலெழுதவும் அனுமதிக்கின்றன:

| நோக்குநிலை          | நிலை சேமிப்பு                             | வாசிப்பு                                  | மீட்டமை / அழித்தல்                                                      |
| ------------------- | ----------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------- |
| வழங்குநர் பிரேக்கர் | `domain_circuit_breakers` + உள்-நினைவகம்  | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                            |
| இணைப்பு கூல்டவுன்   | வழங்குநர் இணைப்புகளில் `rateLimitedUntil` | `/api/rate-limits`, `/api/providers/[id]` | (தேவைப்படும்போது மீண்டும் இயக்கப்படும்; வழங்குநர் PUT மூலம் அழிக்கலாம்) |
| மாதிரி பூட்டுதல்    | உள்-நினைவக மாதிரி-கிடைக்கும்தன்மை பதிவேடு | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                                |

`PATCH /api/resilience` என்பது `providerBreaker.oauth` மற்றும் `providerBreaker.apikey` ஆகியவற்றின் கீழ் வழங்குநர் பிரேக்கர் மேலெழுதல்களை ஏற்றுக்கொள்கிறது. ஒவ்வொரு சுயவிவரமும் `degradationThreshold`, `failureThreshold` மற்றும் `resetTimeoutMs` ஆகியவற்றை ஆதரிக்கிறது; அதே புலங்கள் டாஷ்போர்டு → அமைப்புகள் → மீள்தன்மை பகுதியிலும் வெளிப்படுத்தப்பட்டுள்ளன.

```bash
# ஒரே ஒரு மாதிரி பூட்டுதலை அழிக்கவும்
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# அனைத்து பூட்டுதல்களையும் அழிக்கவும்
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

முழுமையான கருத்தியல் குறிப்பு மற்றும் பிரேக்கர் இயல்புநிலைகள்: [`CLAUDE.md`](../../CLAUDE.md) → "Resilience Runtime State" மற்றும் [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) ஆகியவற்றைப் பார்க்கவும்.

### விகித-வரம்பு வரிசை & தானாக-இயக்கும் பாதுகாப்பு வலை

- **ஆதரிக்கப்படும் எழுதும் பாதை**: ஒரு இணைப்பிற்கான விகித-வரம்பு பாதுகாப்பை மாற்றுவதற்கு, `{"connectionId": "<id>", "enabled": true|false}` என்ற உடலுடன் `POST /api/rate-limits` என்பதே ஆதரிக்கப்படும் மேலாண்மை இறுதிப்புள்ளியாகும். `PUT /api/providers/[id]` வேண்டுமென்றே `rateLimitProtection` ஐ மாற்றுவதில்லை அல்லது புரட்டுவதில்லை (#11278).
- **`enabled: false` இன் பொருள்**: `enabled: false` என அமைப்பது இணைப்பிற்கான வெளிப்படையான பாதுகாப்பை நீக்குகிறது, ஆனால் செயலில் உள்ள API-key இணைப்பை உலகளாவிய தானாக-இயக்கும் பாதுகாப்பு வலையிலிருந்து **விலக்காது** (`autoEnableApiKeyProviders = true`). `reconcileEnabledConnections` இல் (`open-sse/services/rateLimitManager.ts`), `false` மற்றும் `undefined` சமமானவை; வெளிப்படையான பாதுகாப்பு இல்லாத செயலில் உள்ள API-key இணைப்புகள் தானாக-இயக்கும் பாதுகாப்பு வலையின் கீழ் தொடர்ந்து பாதுகாக்கப்படும்.
- **உலகளாவிய முடக்கம்**: விகித-வரம்பு வரிசைகள் இல்லாமல் API-key இணைப்புகளை இயக்க, `RATE_LIMIT_AUTO_ENABLE=false` (env) அல்லது `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (அமைப்புகள் → மீள்தன்மை / `PATCH /api/resilience`) மூலம் பாதுகாப்பு வலையை உலகளவில் முடக்கவும்.

## MCP சேவையகம்

OmniRoute ஆனது 3 பரிமாற்ற முறைகள் (stdio, SSE, streamable-http) மற்றும் வரையறுக்கப்பட்ட கருவிகளைக் கொண்ட உட்பொதிக்கப்பட்ட Model Context Protocol சேவையகத்துடன் வழங்கப்படுகிறது. கீழேயுள்ள dashboard முனைப்புள்ளிகள் நிலை/தணிக்கைத் தரவைப் படித்து, HTTP பரிமாற்ற முறைகளை proxy செய்கின்றன.

| முறை | பாதை | விளக்கம் |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | இதயத்துடிப்பு, பரிமாற்ற முறை, இணையநிலை, கடைசி அழைப்பு, முன்னணி கருவிகள், 24 மணிநேர வெற்றி விகிதம் |
| GET | `/api/mcp/tools` | `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints` ஆகியவற்றுடன் MCP கருவிகளின் பட்டியல் |
| GET | `/api/mcp/sse` | SSE பரிமாற்ற முறைக்கான SSE ஸ்ட்ரீமைத் திறக்கும் (MCP முடக்கப்பட்டிருந்தாலோ பரிமாற்ற முறை பொருந்தாவிட்டாலோ `503`-ஐத் திருப்பியளிக்கும்) |
| POST | `/api/mcp/sse` | SSE பரிமாற்ற முறையில் JSON-RPC frame-ஐ அனுப்பும் |
| GET | `/api/mcp/stream` | Streamable HTTP பரிமாற்ற முறையின் SSE பக்கத்தைத் திறக்கும் (சேவையகத்தால் தொடங்கப்படும் செய்திகள்) |
| POST | `/api/mcp/stream` | Streamable HTTP பரிமாற்ற முறையில் JSON-RPC frame-ஐ அனுப்பும் |
| DELETE | `/api/mcp/stream` | Streamable HTTP அமர்வை முடிக்கும் |
| GET | `/api/mcp/audit` | தணிக்கைப் பதிவை வினவும் — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | ஒருங்கிணைக்கப்பட்ட தணிக்கைப் புள்ளிவிவரங்கள் (மொத்தங்கள், வெற்றி விகிதம், சராசரி காலஅளவு, முன்னணி கருவிகள்) |

**அங்கீகாரம்:** `sse`/`stream` பரிமாற்ற முறைகள் MCP-க்கான குறிப்பிட்ட அங்கீகார இடைமுகத்தை மதிக்கின்றன (`mcp` scope கொண்ட Bearer API விசை); `status`/`tools`/`audit*` வழித்தடங்களை dashboard-இலிருந்து படிக்கலாம் (dashboard host-ஐ அணுகுவதற்கு அப்பால் கூடுதல் அங்கீகாரம் தேவையில்லை).

> இரண்டு HTTP பரிமாற்ற முறைகளும் `settings.mcpEnabled` மற்றும் `settings.mcpTransport` ஆகியவற்றால் கட்டுப்படுத்தப்படுகின்றன — பரிமாற்ற முறை பொருந்தாமை `400`-ஐத் திருப்பியளிக்கும்; MCP முடக்கப்பட்ட நிலை `503`-ஐத் திருப்பியளிக்கும்.

## A2A சேவையகம்

OmniRoute ஆனது A2A (Agent-to-Agent) JSON-RPC 2.0 முனைப்புள்ளியையும், ஆய்வு/முகப்புப்பலகைப் பயன்பாட்டிற்கான REST உறையையும் வழங்குகிறது.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # OMNIROUTE_API_KEY அமைக்கப்பட்டிருந்தால் தவிர இது விருப்பத்திற்குரியது
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

ஆதரிக்கப்படும் முறைகள் (அனைத்தும் `settings.a2aEnabled` மூலம் கட்டுப்படுத்தப்படுகின்றன):

| முறை             | விளக்கம்                                                                              |
| ---------------- | ------------------------------------------------------------------------------------- |
| `message/send`   | ஒத்திசைவான திறன் செயலாக்கம்; `{task, artifacts, metadata}` என்பதைத் திருப்பியளிக்கும் |
| `message/stream` | அதே திறன் தொகுப்பின் ஸ்ட்ரீமிங் SSE செயலாக்கம்                                        |
| `tasks/get`      | `taskId` மூலம் ஒரு பணியைப் பெறும்                                                     |
| `tasks/cancel`   | `taskId` மூலம் ஒரு பணியை ரத்துசெய்யும்                                                |

உள்ளமைந்த திறன்கள்: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### முகவர் அட்டை

```bash
GET /.well-known/agent.json
```

பொது A2A முகவர் அட்டையை (பெயர், விளக்கம், திறன்கள், திறன் பட்டியல், அங்கீகாரத் திட்டம்) திருப்பியளிக்கிறது — 1 மணிநேரத்திற்குப் பொதுவாகத் தற்காலிகச் சேமிப்பில் வைக்கப்படும். அங்கீகாரம் தேவையில்லை.

### REST உதவிச் செயல்பாடுகள்

| முறை | பாதை                         | விளக்கம்                                                                                                                   |
| ---- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| GET  | `/api/a2a/status`            | A2A இயக்கப்பட்ட நிலை + பணிப் புள்ளிவிவரங்கள் + தற்காலிகச் சேமிப்பிலுள்ள முகவர் அட்டைச் சுருக்கம்                           |
| GET  | `/api/a2a/tasks`             | பணிகளைப் பட்டியலிடும் — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST | `/api/a2a/tasks`             | (REST உதவிச் செயல்பாடாக அமல்படுத்தப்படவில்லை — JSON-RPC `message/send` வழியாக உருவாக்கவும்)                                |
| GET  | `/api/a2a/tasks/[id]`        | ஒரு பணியைப் பெறும்                                                                                                         |
| POST | `/api/a2a/tasks/[id]/cancel` | ஒரு பணியை ரத்துசெய்யும்                                                                                                    |

**அங்கீகாரம்:** REST உதவிச் செயல்பாடுகள் மேலாண்மை அங்கீகாரம் இல்லாமல் இயங்குகின்றன (முகப்புப்பலகையிலிருந்து படிக்கக்கூடியவை); JSON-RPC `/a2a` பாதை, கட்டமைக்கப்பட்டிருந்தால் Bearer `OMNIROUTE_API_KEY`-ஐப் பயன்படுத்துகிறது.

## ACP (Agent Client Protocol) மேலாண்மை

துணைச் செயல்முறைகளாக. இந்த முனைப்புள்ளிகள் ACP முகவர் கண்டறிதலையும் தனிப்பயன் முகவர்
பதிவையும் நிர்வகிக்கின்றன.

| முறை   | பாதை              | விளக்கம்                                                                                                                                                                                                  |
| ------ | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/acp/agents` | நிறுவல் நிலை, பதிப்பு மற்றும் பைனரி விவரங்களுடன் அறியப்பட்ட அனைத்து CLI முகவர்களையும் (உள்ளமைக்கப்பட்டவை + தனிப்பயனாக்கப்பட்டவை) பட்டியலிடுகிறது                                                          |
| POST   | `/api/acp/agents` | தனிப்பயன் ACP முகவரைப் பதிவுசெய்கிறது அல்லது தற்காலிகச் சேமிப்பைப் புதுப்பிக்கிறது — கோரிக்கை உடல்: `{id, name, binary, versionCommand, providerAlias, spawnArgs, protocol}` அல்லது `{action: "refresh"}` |
| DELETE | `/api/acp/agents` | தனிப்பயன் ACP முகவரை அகற்றுகிறது — வினவல் அளவுரு: `?id=<agentId>`                                                                                                                                         |

**பதில் எடுத்துக்காட்டு** (`GET /api/acp/agents`):

```json
{
  "agents": [
    {
      "id": "claude",
      "name": "Claude Code CLI",
      "binary": "claude",
      "version": "1.0.45",
      "installed": true,
      "protocol": "stdio",
      "providerAlias": "claude",
      "isCustom": false
    },
```

| DELETE | `/api/skills/[id]`       | ஒரு திறனை நிறுவல் நீக்கும்                                                                        |
| PUT    | `/api/skills/[id]`       | ஒரு திறனை இயக்கும் அல்லது முடக்கும் — உடல்: `{enabled?: boolean, mode?: "on" \| "off" \| "auto"}` |
| POST   | `/api/skills/executions` | ஒரு திறனைச் செயல்படுத்தும் — உடல்: `{skillName, apiKeyId, input?, sessionId?}`                    |
| GET    | `/api/skills/executions` | அனைத்து திறன்களின் செயல்படுத்தல் வரலாற்றையும் பட்டியலிடும் (`?apiKeyId=` மூலம் வடிகட்டலாம்)       |

**அங்கீகாரம்:** மேலாண்மை அமர்வு அல்லது மேலாண்மை வரம்புடைய API விசை தேவை.

முழு விவரங்களுக்கு [திறன்கள் கட்டமைப்பு](../frameworks/SKILLS.md) என்பதைப் பார்க்கவும்.

## பாதுகாப்புத் தடுப்புகள்

இயக்கநேர பாதுகாப்புத் தடுப்புகளை (PII கண்டறிதல், தூண்டல் உட்செலுத்தல் கண்டறிதல், காட்சி இணைப்பு) ஆய்வு செய்யவும். ஒவ்வொரு கோரிக்கையிலும் பாதுகாப்புத் தடுப்புகள் இயங்குகின்றன; ஒவ்வொரு அழைப்பிற்குமான விலகல் `x-omniroute-disabled-guardrails` கோரிக்கைத் தலைப்பு மூலம் செய்யப்படுகிறது — நிலையாகச் சேமிக்கப்படும் இயக்கு/முடக்கு தளம் எதுவும் இல்லை.

| முறை | பாதை                   | விளக்கம்                                                                                                                      |
| ---- | ---------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| GET  | `/api/guardrails`      | பதிவுசெய்யப்பட்ட பாதுகாப்புத் தடுப்புகளையும் அவற்றின் நிலையையும் பட்டியலிடும் (பெயர் / இயக்கப்பட்டது / முன்னுரிமை)            |
| POST | `/api/guardrails/test` | மாதிரி உள்ளீட்டின் மீது அழைப்புக்கு முந்தைய செயலாக்கத் தொடரைச் சோதனை முறையில் இயக்கும் — உடல்: `{input, disabledGuardrails?}` |

**அங்கீகாரம்:** மேலாண்மை அமர்வு தேவை.

முழு விவரங்களுக்கு [பாதுகாப்பு > பாதுகாப்புத் தடுப்புகள்](../security/GUARDRAILS.md) என்பதைப் பார்க்கவும்.

## அங்கீகாரம்

நான்கு நற்சான்று வகைகள் (டாஷ்போர்டு அமர்வு, உள்ளக CLI டோக்கன், `oma_live_…` அணுகல் டோக்கன், மேலாண்மை வரம்புடைய API விசை) மற்றும் அவை அனுமான விசைகளிலிருந்து எவ்வாறு வேறுபடுகின்றன என்பதை அறிய [மேலாண்மை அங்கீகாரம்](../guides/MANAGEMENT-AUTH.md) என்பதைப் பார்க்கவும்.

- டாஷ்போர்டு வழித்தடங்கள் (`/dashboard/*`) `auth_token` குக்கீயைப் பயன்படுத்துகின்றன
- உள்நுழைவு சேமிக்கப்பட்ட கடவுச்சொல் ஹாஷைப் பயன்படுத்துகிறது; மாற்று வழியாக `INITIAL_PASSWORD` பயன்படுத்தப்படுகிறது
- `requireLogin`-ஐ `/api/settings/require-login` மூலம் மாற்றியமைக்கலாம்
- `REQUIRE_API_KEY=true` ஆக இருக்கும்போது, `/v1/*` வழித்தடங்களுக்கு விருப்பத்தேர்வாக Bearer API விசை தேவைப்படும்
- இந்தக் குறிப்பில் "மேலாண்மை டோக்கன்" / "மேலாண்மை வரம்புடைய API விசை" என்பது அந்த வழிகாட்டியில் உள்ள வகைகளில் ஒன்றைக் குறிக்கிறது — வரையறுக்கப்படாத கூடுதல் ரகசிய வகையைக் குறிக்காது

> **முறிவை ஏற்படுத்தும் மாற்றம் (v3.8.0)** — `/api/v1/agents/tasks/*` மற்றும் கூல்டவுன் மேலாண்மை இறுதிப்புள்ளிகளுக்கு இப்போது **மேலாண்மை அங்கீகாரம்** (டாஷ்போர்டு `auth_token` குக்கீ அல்லது மேலாண்மை வரம்புடைய API விசை) தேவைப்படுகிறது. முன்பு அங்கீகாரம் இல்லாமல் இந்த வழித்தடங்களை அழைத்த கிளையன்ட்கள் `401 Unauthorized` பதிலைப் பெறுவார்கள். `588a0333` கமிட்டைப் பார்க்கவும் (`fix(auth): require management auth for agent and cooldown APIs`).
