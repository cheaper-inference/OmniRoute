OpenAI-இணக்கமான நெறிமுறை மற்றும் வழங்குநர் திறன் அணிக்கான விரிவான தகவல்களுக்கு,
[`OPENAI_COMPATIBILITY.md`](./OPENAI_COMPATIBILITY.md)-ஐப் பார்க்கவும்.

## அரட்டை நிறைவுகள்

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### தனிப்பயன் தலைப்புகள்

| தலைப்பு                  | திசை     | விளக்கம்                                                                                                                                                                                                                                                  |
| ------------------------ | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | கோரிக்கை | கேச்சைத் தவிர்க்க `true` என அமைக்கவும்                                                                                                                                                                                                                    |
| `x-omniroute-no-memory`  | கோரிக்கை | இந்தக் கோரிக்கைக்கான நினைவகம் + திறன்கள் உட்செலுத்தலைத் தவிர்க்க `true` என அமைக்கவும் (no-cache நடத்தையைப் பிரதிபலிக்கிறது; ஒவ்வொரு அழைப்புக்குமான டோக்கன்/செலவு கூடுதல் சுமையைத் தவிர்க்கிறது)                                                           |
| `X-OmniRoute-Progress`   | கோரிக்கை | முன்னேற்ற நிகழ்வுகளுக்கு `true` என அமைக்கவும்                                                                                                                                                                                                             |
| `X-Session-Id`           | கோரிக்கை | வெளிப்புற அமர்வு இணக்கத்திற்கான ஒட்டுநிலை அமர்வு விசை                                                                                                                                                                                                     |
| `x_session_id`           | கோரிக்கை | அடிக்கோடு மாறுபாடும் ஏற்கப்படுகிறது (நேரடி HTTP)                                                                                                                                                                                                          |
| `X-OmniRoute-Session-Id` | கோரிக்கை | அழைப்பாளர் வழங்கும் அமர்வு/உரையாடல் குறிச்சொல் (நினைவகத்திற்கும் வழங்கப்படுகிறது). இது இருக்கும்போது, ஒவ்வொரு அமர்வுக்குமான செலவுப் பங்கீட்டிற்காக `call_logs.session_tag` இல் அப்படியே நிலைநிறுத்தப்படும் (#8249) — இல்லாதபோது ஒருபோதும் உருவாக்கப்படாது |
| `Idempotency-Key`        | கோரிக்கை | நகல் நீக்கல் விசை (5 வினாடிச் சாளரம்)                                                                                                                                                                                                                     |
| `X-Request-Id`           | கோரிக்கை | மாற்று நகல் நீக்கல் விசை                                                                                                                                                                                                                                  |
| `x-omniroute-connection` | கோரிக்கை | ஒற்றை-மாதிரி கோரிக்கையை அதன் id மூலம் ஒரு வழங்குநர் இணைப்புடன் (கணக்குடன்) பிணைக்கவும் — [ஒவ்வொரு கோரிக்கைக்குமான கணக்கு பிணைப்பு](#account-pinning-per-request) என்பதைப் பார்க்கவும்                                                                     |
| `X-OmniRoute-Cache`      | பதில்    | `HIT` அல்லது `MISS` (ஸ்ட்ரீமிங் அல்லாதது)                                                                                                                                                                                                                 |
| `X-OmniRoute-Idempotent` | பதில்    | நகல் நீக்கப்பட்டிருந்தால் `true`                                                                                                                                                                                                                          |
| `X-OmniRoute-Progress`   | பதில்    | முன்னேற்றக் கண்காணிப்பு இயக்கத்தில் இருந்தால் `enabled`                                                                                                                                                                                                   |
| `X-OmniRoute-Session-Id` | பதில்    | OmniRoute பயன்படுத்திய செயல்பாட்டு அமர்வு ID                                                                                                                                                                                                              |
| `X-OmniRoute-Request-Id` | பதில்    | கோரிக்கை தொடர்புபடுத்தல் id (அறியப்பட்டிருக்கும்போது)                                                                                                                                                                                                     |
| `X-OmniRoute-Version`    | பதில்    | OmniRoute கட்டமைப்புப் பதிப்பு (எப்போதும் இருக்கும்)                                                                                                                                                                                                      |
| `X-OmniRoute-Cost-Saved` | பதில்    | HIT ஏற்பட்டபோது கேச் தவிர்த்த USD செலவு (கேச் ஹிட்களுக்கு மட்டும்)                                                                                                                                                                                        |
| `X-OmniRoute-Decision`   | பதில்    | வழித்தடத் தடம்: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` என்பது காம்போ உத்தி அல்லது காம்போ அல்லாத கோரிக்கைக்கு `single`) — நிறைவு பதில்களில் எப்போதும் இருக்கும்                                                                     |

> Nginx குறிப்பு: அடிக்கோடுகளைக் கொண்ட headers-ஐ நீங்கள் சார்ந்திருந்தால் (எடுத்துக்காட்டாக `x_session_id`), `underscores_in_headers on;` என்பதை இயக்கவும்.

#### ஒவ்வொரு கோரிக்கைக்கும் கணக்கைப் பின் செய்தல்

ஒரு provider-க்கு பல connections (கணக்குகள் அல்லது keys) இருக்கும்போது, OmniRoute பொதுவாக அதன் கணக்கு-தேர்வு உத்தியின் மூலம் ஒன்றைத் தேர்ந்தெடுக்கும். அதற்குப் பதிலாக, ஒரு கோரிக்கையானது `x-omniroute-connection` header மூலம் குறிப்பிட்ட ஒரு connection-ஐப் பின் செய்யலாம்:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **id-ஐ எங்கே கண்டறிவது.** Dashboard-இல் provider பக்கத்தைத் திறந்து
  (**Dashboard → Providers → <provider>**), ஒரு connection வரிசையிலுள்ள `xxxxxxxx…` id chip-ஐக் கிளிக் செய்யவும்
  — இது முழுமையான connection id-ஐ நகலெடுக்கும்.
- **எந்தக் கோரிக்கைகள் இதை மதிக்கின்றன.** `/v1/chat/completions`, `/v1/messages` மற்றும்
  `/v1/responses` ஆகியவற்றுக்கான ஒற்றை-model கோரிக்கைகள் (`provider/model`). Combos இந்த header-ஐப் புறக்கணிக்கும்: அதற்குப் பதிலாக, ஒவ்வொரு combo படிக்கும் அதன் சொந்த connection மூலம் ஒரு கணக்கைப் பின் செய்யவும்.
- **பின் செய்தல் என்பது கடுமையானது, விருப்பத்தேர்வு அல்ல.** பின் செய்யப்பட்ட connection மட்டுமே பிரத்தியேகமாகப் பயன்படுத்தப்படும். கோரிக்கைக்குள் ஏற்படும் ஒரு தோல்வி, கணக்கின் cooldown-ஐப் பதிவுசெய்யும்; ஆனால் அதே provider-இன் மற்றொரு இணை கணக்குக்கு **மாறாது**.
- **Cooldown மற்றும் quota ஆகியவை பினை விடுவிக்கும்.** பின் செய்யப்பட்ட connection cooldown-இல் இருக்கும்போது,
  quota தீர்ந்திருக்கும்போது அல்லது quota policy ஒன்றால் தடுக்கப்பட்டிருக்கும்போது, பின்னர் வரும் கோரிக்கைகள் பின் செய்யப்படாத traffic போலவே provider-இன் பிற connections-ஐப் பயன்படுத்தும்.
- **அறியப்படாத அல்லது முடக்கப்பட்ட id-கள் தோல்வியடையும்.** provider-இன் செயலில் உள்ள pool-இல் இல்லாத ஒரு id (நீக்கப்பட்டது,
  செயலிழக்கச் செய்யப்பட்டது அல்லது வேறொரு provider-க்குச் சொந்தமானது) தகுதியான கணக்கு எதையும் விட்டுவைக்காது; எனவே கோரிக்கை வேறு இடத்துக்கு அமைதியாக route செய்யப்படுவதற்குப் பதிலாகத் தோல்வியடையும்.

Claude Code, `ANTHROPIC_CUSTOM_HEADERS` மூலம் தனிப்பயன் headers-ஐ அனுப்புகிறது. இதை `~/.claude/settings.json`-இன் `env` block-இல் வைக்கவும் அல்லது ஒவ்வொரு project-க்கும் வேறொரு கணக்கைப் பின் செய்ய project-level `.claude/settings.json`-இல் வைக்கவும்:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

மூலம்: `src/sse/handlers/chat.ts` (header வாசிப்பு), `src/sse/services/auth.ts` மற்றும்
`src/sse/services/sessionAffinityPin.ts` (பினை விடுவித்தல் மற்றும் pool-இல் இல்லாததைச் சரிபார்த்தல்).

> **செலவு telemetry headers:** streaming அல்லாத வெற்றிகரமான responses, `X-OmniRoute-*` செலவு-telemetry தொகுப்பையும் கொண்டிருக்கும் — `X-OmniRoute-Response-Cost` (USD, நிலையான 10 தசம இடங்கள்; இலவசமான/விலை நிர்ணயிக்கப்படாதவற்றுக்கு `0.0000000000`), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` மற்றும் `X-OmniRoute-Fallback-Attempts` (> 0 ஆக இருக்கும்போது மட்டும்), அத்துடன் `X-OmniRoute-Request-Id` மற்றும் `X-OmniRoute-Version`. இவை chat completions, `/v1/responses`, `/v1/messages`, **மற்றும் media endpoints** ஆகியவற்றால் வெளியிடப்படுகின்றன — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` மற்றும் `/v1/moderations` (செலவு எப்போதும் `0`). விலைத் தகவல் கிடைக்கும்போது, media செலவு modality ஒன்றுக்கு (ஒவ்வொரு image, ஒவ்வொரு second, ஒவ்வொரு character, ஒவ்வொரு search-unit) கணக்கிடப்படும்; இல்லையெனில் `0` (fail-open).

> **Cache-hit செலவின் பொருள்:** semantic-cache HIT (`X-OmniRoute-Cache-Hit: true`) ஒன்றில் upstream call எதுவும் செய்யப்படாது; எனவே `X-OmniRoute-Response-Cost` என்பது `0.0000000000` (அந்த hit-ஐ வழங்குவதற்கான **கூடுதல்** செலவு). அசல்/ஏற்பட்டிருக்கக்கூடிய செலவு `X-OmniRoute-Cost-Saved`-இல் தனியாகத் தெரிவிக்கப்படுகிறது. Billing consumers, `X-OmniRoute-Response-Cost`-ஐக் கூட்ட வேண்டும் (hits-க்கு எந்தச் செலவும் இல்லை); cache analytics, `X-OmniRoute-Cost-Saved`-ஐத் தொகுக்கலாம்.

## பிரத்தியேக நிர்வகிக்கப்பட்ட அமர்வு குத்தகைகள்

பிரத்தியேக நிர்வகிக்கப்பட்ட அமர்வுக் குத்தகை என்பது விருப்பத்தேர்வுக்குரிய, கிளையன்ட்-சார்பற்ற வழித்தட ஒப்பந்தமாகும்: ஒரு செயலில் உள்ள உரிமையாளர்
தகுதியான ஒரு OmniRoute இணைப்பை வைத்திருப்பார். இது ஒரு மாதிரியைக் குத்தகைக்கு எடுக்காது, OAuth-ஐக் கோராது, ஒரு
குறிப்பிட்ட கிளையன்டை அடையாளம் காணாது அல்லது ஒரு குறிப்பிட்ட வழங்குநரைத் தேவைப்படுத்தாது.

அங்கீகரிக்கும் API விசைக்கு `lease:exclusive` வரம்பும், வெளிப்படையான காலியாக இல்லாத
`allowedConnections` பட்டியலும் இருக்க வேண்டும். விசை உருவாக்கத்திலும் பகுதியளவு புதுப்பிப்புகளிலும் இந்த இரு புலங்களையும்
தரவுத்தள மாற்ற எல்லை ஒன்றாக அமல்படுத்துகிறது.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

வெற்றிகரமான பெறுதல், புதுப்பித்தல் மற்றும் விடுவித்தல் பதில்கள் நேரமுத்திரைகள், `state` மற்றும் துல்லியமான நேர்மறை
`generation` ஆகியவற்றை வெளிப்படுத்தும்; ஆனால் தேர்ந்தெடுக்கப்பட்ட இணைப்பையோ நற்சான்றுகளையோ ஒருபோதும் வெளிப்படுத்தாது. புதுப்பித்தல் மற்றும் விடுவித்தல் செயல்கள்
JSON உடலில் தலைமுறையை வழங்குகின்றன:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

செயலில் உள்ள குத்தகை உரிமையாளர் தனது தற்போதைய பிணைப்புக்கான தனியுரிமைக்குப் பாதுகாப்பான காட்சி மெட்டாடேட்டாவை வெளிப்படையாகக் கோரலாம்:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

இந்த விருப்பத்தேர்வு நிலைச் செயல், ஒளிபுகா உரிமையாளர், அங்கீகரிக்கப்பட்ட நிர்வகிக்கப்பட்ட API விசை மற்றும் துல்லியமான
செயலில் உள்ள தலைமுறை ஆகியவற்றால் ஒரே தரவுத்தளப் பரிவர்த்தனையில் வேலியிடப்படுகிறது. `displayName` என்பது இடைவெளிகள் நீக்கப்பட்ட, உள்ளமைக்கப்பட்ட
இணைப்புப் பெயர் மட்டுமே; பாதுகாப்பான உள்ளமைக்கப்பட்ட பெயர் இல்லாதபோது அது `null` ஆகும். OmniRoute ஒருபோதும்
மின்னஞ்சலையோ உருவாக்கப்பட்ட கணக்கு அடையாளத்தையோ மாற்றாகப் பயன்படுத்தாது. வழங்குநர் மதிப்பு என்பது உணர்திறனற்ற காட்சி லேபிள் மட்டுமே; அது ஒருபோதும்
உருவாக்கப்பட்ட இணக்கமான-வழங்குநர் அடையாளங்காட்டி அல்ல. நற்சான்றுகள், டோக்கன்கள், குக்கீகள், மூல இணைப்பு அல்லது API
விசை ID-கள், உரிமையாளர் ஹாஷ்கள், வேலியிடும் இரகசியங்கள் மற்றும் அக வழித்தடத் தரவு ஆகியவை விலக்கப்படுகின்றன.

தவறான விசை, தவறான உரிமையாளர், காலாவதியான தலைமுறை, காணாமற்போன, காலாவதியான, விடுவிக்கப்பட்ட மற்றும் செல்லாததாக்கப்பட்ட தேடல்கள் அனைத்தும்
இணைப்பு மெட்டாடேட்டா இல்லாமல் அதே `409 LEASE_FENCE_STALE` பிழையைத் திருப்பியளிக்கும். திறன்-காத்திருப்புப் பதிலைப் பெற்ற கிளையன்டிடம் ஆய்வு செய்வதற்கான செயலில் உள்ள பிணைப்பு எதுவும் இருக்காது. வழித்தடம் செயலில் உள்ள ஒரு குத்தகையை மாற்றும்போது,
அதே தலைமுறை செல்லுபடியாக இருக்கும்; மேலும் நிலை புதிய பிணைப்பை அணுவளவில் திருப்பியளிக்கும், பழையதை ஒருபோதும் திருப்பியளிக்காது.
பெறுதல், புதுப்பித்தல், விடுவித்தல் மற்றும் காத்திருப்புப் பதில்கள் தங்களின் முந்தைய வடிவங்களைத் தக்கவைத்திருப்பதால்
ஏற்கனவே உள்ள கிளையன்ட்கள் மாறாமல் இருக்கும்.

இந்தச் சேவையக ஒப்பந்தம் இயல்புநிலை OpenAI Codex `/status`-ஐ மாற்றாது. இயல்புநிலை Codex தற்போது அதன்
மாதிரி வழங்குநரையும் உள்ளமைந்த அங்கீகார/கணக்கு நிலையையும் அறிக்கையிடுகிறது; ஆனால் தன்னிச்சையான தனிப்பயன்
வழங்குநர் கணக்கு மெட்டாடேட்டாவை வெளிப்படுத்தாது. பிந்தைய கிளையன்ட் ஒருங்கிணைப்பு இந்தச் செயலை அழைத்து
`connection.displayName`-ஐ எவ்வாறு காட்டுவது என்பதைத் தீர்மானிக்க வேண்டும்.

அதன்பின் ஒவ்வொரு நிர்வகிக்கப்பட்ட இன்ஃபரன்ஸ் கோரிக்கையும் இரண்டு கட்டுப்பாட்டுத் தலைப்புகளையும் வழங்கும்:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

ஒவ்வொரு ஆதரிக்கப்படும் அப்ஸ்ட்ரீம் முயற்சிக்கும் உடனடியாக முன்பு, துல்லியமான உரிமையாளர், தலைமுறை, செயலில் உள்ள இணைப்பு மற்றும் அங்கீகரிக்கப்பட்ட API விசை
வேலியிடப்படுகின்றன. அதே இணைப்பை அந்த விசை அனுமதித்தாலும், வேறொரு விசையுடன் உரிமையாளர் மற்றும் தலைமுறையை மறுஇயக்குவது
தோல்வியடையும். மூல உரிமையாளர்கள் நிலையாகச் சேமிக்கப்படுவதில்லை, பதிவிடப்படுவதில்லை, கோரிக்கை ஸ்னாப்ஷாட்டில் தக்கவைக்கப்படுவதில்லை அல்லது அப்ஸ்ட்ரீமுக்கு அனுப்பப்படுவதில்லை.

தற்காலிகப் போட்டிநிலை HTTP `429`-ஐ `Retry-After` மற்றும் பின்வருவனவற்றுடன் திருப்பியளிக்கும்:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

இந்தப் பதில், வழக்கமான தகுதியான தொகுப்பு காலியாக இல்லை என்பதையும், ஒவ்வொரு இலவச வேட்பாளரும்
வேறொரு செயலில் உள்ள குத்தகையால் பிடித்துவைக்கப்பட்டிருந்தது என்பதையும் மட்டுமே குறிக்கிறது. ஆதரிக்கப்படாத மாதிரிகள்/வழங்குநர்கள், கொள்கைப் பொருத்தமின்மை, கூல்டவுன், ஒதுக்கீடு,
நலநிலை மற்றும் பிற வழக்கமான தகுதித் தோல்விகள் தங்களின் தற்போதைய OmniRoute பதில்களைத் தக்கவைத்துக்கொள்ளும்.

### `x-omniroute-compression`

சுருக்கத் திட்டத்தை ஒவ்வொரு கோரிக்கைக்கும் மேலெழுதுதல். மிக உயர்ந்த முன்னுரிமை — வழித்தடக் காம்போ
மேலெழுதுதல், செயலில் உள்ள சுயவிவரம், தானியங்கித் தூண்டுதல் மற்றும் பேனலின் இயல்புநிலை ஆகிய அனைத்தையும் மீறும். மதிப்புகள்:

| மதிப்பு       | விளைவு                                                                                                                                    |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `off`         | இந்தக் கோரிக்கைக்குச் சுருக்கம் இல்லை.                                                                                                    |
| `default`     | பேனலிலிருந்து பெறப்பட்ட இயல்புநிலை சுயவிவரம் (செயலில் உள்ள சுயவிவரத்தைப் புறக்கணிக்கும்). இழப்புள்ள இயந்திரங்கள் முடக்கப்பட்டே இருக்கும். |
| `safe`        | நகல் நீக்கமும் இடைவெளி மடிப்பும் மட்டும்.                                                                                                 |
| `allow-lossy` | சுருக்கங்கள் மற்றும் பாணி மறுஎழுதல்கள் உட்பட, இந்தக் கோரிக்கைக்கான ஆபரேட்டர் திட்டத்தைத் தக்கவைக்கும்.                                    |
| `engine:<id>` | இயக்கப்பட்டிருக்கும்போது ஒற்றை இயந்திரம், எ.கா. `engine:rtk`. அந்த இயந்திரத்திற்கான ஒவ்வொரு கோரிக்கை விருப்பத்தேர்வு.                     |
| `<combo>`     | பெயரிடப்பட்ட காம்போ; முதலில் பெயரால் (எழுத்துப் பெட்டி வேறுபாடு கருதாமல்), பின்னர் ID மூலம் பொருத்தப்படும்.                               |

குறிப்புகள்:

- அறியப்படாத மதிப்புகள் புறக்கணிக்கப்படும் (கோரிக்கை ஒருபோதும் நிராகரிக்கப்படாது); தீர்மானம் வழக்கமான ஆபரேட்டர் முன்னுரிமைக்குத் தொடரும்.
- பல காம்போக்கள் ஒரே பெயரைப் பகிர்ந்தால், உறுதியான பொருத்தத்திற்குக் காம்போ **id**-ஐ அனுப்பவும்.
- `off` அல்லது `default` என்ற பெயருடைய காம்போவைப் பெயரால் தேர்ந்தெடுக்க முடியாது (அந்தத் திறவுச்சொற்கள் முதலில் விளக்கப்படுகின்றன); அத்தகைய காம்போவை அதன் ID மூலம் குறிப்பிடவும்.
- முதன்மைச் சுருக்க மாற்றி ஒரு கடுமையான தடையாகும்: சுருக்கம் உலகளவில் முடக்கப்பட்டிருக்கும்போது, இந்தத் தலைப்பால் அதை இயக்க முடியாது.

பயன்படுத்தப்பட்ட திட்டம் பதில் தலைப்பில் மீண்டும் பிரதிபலிக்கப்படும்:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

இங்கு `<source>` என்பது `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` அல்லது `off` ஆகியவற்றில் ஒன்றாகும்.

## உட்பதிவுகள்

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

கிடைக்கக்கூடிய வழங்குநர்கள்: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

பட்டியல் அடையாளங்கள் `provider/model` வடிவில் இருக்கும் (எடுத்துக்காட்டு: `jina-ai/jina-embeddings-v5-omni-small`). பதிவகத்தில் இடம்பெறும் வழங்குநர் முன்னொட்டு இல்லாத Jina மாதிரி அடையாளங்களும் (எடுத்துக்காட்டாக `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) தீர்மானிக்கப்படும். Jina embed/rerank/classify/segment முதலில் டாஷ்போர்டின் `jina-ai` நற்சான்றுகளைப் பயன்படுத்தும்; டாஷ்போர்டு விசை இல்லாதபோது மட்டுமே `JINA_AI_API_KEY` மாற்றாகப் பயன்படுத்தப்படும். `jina-reader` அட்டை Reader / `r.jina.ai` பயன்பாட்டுக்கு மட்டும் (`POST /v1/web/fetch`); அது ஒருபோதும் உட்பதிவுகளையோ மறுதரவரிசைப்படுத்தலையோ வழங்காது.

பல்மாதிரி ஆதரவைக் குறிப்பிடும் பதிவக மாதிரிகள், வழங்குநரைச் சாராத கட்டமைக்கப்பட்ட உருப்படிகளில் அதிகபட்சம் 32 வரை ஏற்கும். ஊடக உருப்படி வகைகள் `text`, `image`, `audio`, `video`, மற்றும் `document`. அவற்றின் ஊடக `source` என்பது `{"type":"url","url":"https://..."}` அல்லது `{"type":"base64","data":"...","media_type":"..."}` ஆக இருக்கும்.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
மற்றும் குடும்ப மாற்றுப்பெயரான `jina-ai/jina-embeddings-v5-omni` → omni-small) Jina-வின் சொந்த
EmbeddingsV5Request ஆவணங்களையும் ஏற்று, அவற்றை `https://api.jina.ai/v1/embeddings`-க்கு **மாற்றமின்றி அனுப்பும்**:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

சொந்த `{ image | audio | video | pdf }` மதிப்புகள் பொது HTTPS URL, `data:` URI அல்லது மூல
base64 ஆக இருக்கலாம். OmniRoute அந்தப் பொருட்களைச் சரமாக மாற்றுவதோ சொந்தப் பட URL-களைப் பெறுவதோ இல்லை — பொது ஊடகத்தை Jina தானாகவே பெறுகிறது. கூடுதல் Jina புலங்கள் (`task`, `normalized`, `truncate`, `embedding_type`)
அப்படியே அனுப்பப்படும். உரை மட்டும் கொண்ட Jina SKU-கள், உரையல்லாத ஆவணங்களைத் தொடர்ந்து நிராகரிக்கும்.

பாதுகாப்பு மற்றும் பரிமாற்ற வரம்புகள்:

- தொலைநிலை ஊடக URL-கள் பொது HTTPS ஆக இருக்க வேண்டும். வழமையான `{type,source:url}` உருப்படிகள்
  சேவையகப் பக்கத்தில் பெறப்பட்டு (திசைமாற்ற மறுசரிபார்ப்பு, காலக்கெடு, அளவு வரம்புகள், பொது DNS, இணைப்புப் பிணைப்பு),
  வழங்குநருக்கான அழைப்புக்கு முன் உட்பொதிக்கப்படும். Jina-வின் சொந்த `{image:"https://..."}` உருப்படிகள்
  அதே பொது-HTTPS சோதனைக்குப் பிறகு மாற்றமின்றி அனுப்பப்படும்; URL-ஐ Jina பெறும்.
- இன்லைன் base64 ஊடகம், ஒவ்வொரு உருப்படிக்கும் குறிநீக்கம் செய்யப்பட்ட அளவில் 8 MiB ஆகவும், கோரிக்கை முழுவதற்கும் குறிநீக்கம் செய்யப்பட்ட அளவில் 16 MiB ஆகவும் வரம்பிடப்பட்டுள்ளது.

வழங்குநர் மொழிமாற்றம் (வழமையான உருப்படிகள் ஒருபோதும் மாற்றமின்றி அனுப்பப்படாது):

- Jina பல்மாதிரி மாதிரிகள்: ஒவ்வொரு மேல்நிலை உருப்படியும், இன்லைன் ஊடகத்திற்கு data URI-களைப் பயன்படுத்தி,
  முறைமை விசையைக் கொண்ட ஒரு பொருளாக (`text` / `image` / `audio` / `video` / `pdf`) மாற்றப்படும்; ஒவ்வொரு
  மேல்நிலை உருப்படிக்கும் ஒரு திசையன்.
- Gemini Embedding 2 குடும்பம்: ஒரு மேல்நிலை வரிசை, `content.parts` (`text` அல்லது `inline_data`) கொண்ட ஒற்றை சொந்த
  `models/{model}:embedContent` கோரிக்கையாக மாற்றப்படும்.
- llama.cpp (`llama-cpp/<model>`, உள்ளூர் சேவையகம் ஏற்றிய எந்த மாதிரியும்): வழமையான `text` உருப்படிகள்
  எளிய சரங்களாக மாறும்; மேலும் `image` / `audio` / `video` ஆகியவை தலா ஒரு
  `{"content": [part]}` பொருளாக மாறும். இதில் இன்லைன் தரவுடன் llama-server-இன் அரட்டை உள்ளடக்கப் பகுதிகள் (`image_url`,
  `input_audio` உடன் `wav` / `mp3` / `flac` வடிவம், `input_video`) பயன்படுத்தப்படும்; ஒவ்வொரு
  மேல்நிலை உருப்படிக்கும் ஒரு திசையன். சேவையகம் `--embedding --mmproj …` உடன் இயங்க வேண்டும்; ப்ரொஜெக்டர் இல்லையெனில்
  ஊடகத்தைச் சேவையகமே நிராகரிக்கும். `document` ஆதரிக்கப்படவில்லை.
- வெளிப்படையான முறைமை மெட்டாடேட்டா இல்லாத அறியப்படாத/இயக்கநிலை மாதிரிகள், கட்டமைக்கப்பட்ட உள்ளீட்டை HTTP 400 உடன் நிராகரிக்கும்.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

ஆதரிக்கப்படாத மாதிரி/முறைமைச் சேர்க்கைகள், உருப்படியை வலுக்கட்டாயமாக மாற்றுவதற்குப் பதிலாக HTTP 400-ஐத் திருப்பும். பழைய சரம்/டோக்கன் கோரிக்கைகளில் உள்ளீடு சாராத
நீட்டிப்புப் புலங்கள் மாற்றமின்றித் தொடர்ந்து அனுப்பப்படும்.

## பட உருவாக்கம்

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

கிடைக்கக்கூடிய வழங்குநர்களில் OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (உள்ளூர்), ComfyUI (உள்ளூர்) ஆகியவை அடங்கும்.

`n` ஆனது `data[]` இல் `n` படங்களைத் திருப்பித் தரும். ஒவ்வொரு அழைப்புக்கும் ஒரு படத்தைத் திருப்பித் தரும் upstream API-ஐக் கொண்ட வழங்குநர்களுக்கு
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI), அதிகபட்சம் 4 அழைப்புகள் ஒரே நேரத்தில் செயல்படும் வகையில் `n` தனித்தனி upstream அழைப்புகள் செய்யப்படும். நிலையான
`seed`, அழைப்பின் குறியீட்டால் (`seed`, `seed + 1`, …) நகர்த்தப்படுகிறது; எனவே படங்கள் வேறுபட்டிருந்தாலும் அவற்றை
மீண்டும் அதேபடி உருவாக்க முடியும். `n`-இன் அதிகபட்ச வரம்பு 10. எந்தவொரு அழைப்பும் தோல்வியடைந்தால், கோரிக்கை
முழுவதுமாகத் தோல்வியடையும். Fan-out வடிவங்களின் பட்டியல்
`open-sse/handlers/imageGeneration/fanOut.ts` இல் உள்ள `SINGLE_IMAGE_FANOUT_FORMATS` ஆகும்.

ZenMux ஏற்கனவே உள்ள API-key இணைப்பை மீண்டும் பயன்படுத்துகிறது; மேலும் `zenmux/` அல்லது `zm/` முன்னொட்டுகளை ஏற்றுக்கொள்கிறது:

- `zenmux/openai/gpt-image-2` ஆனது ZenMux-இன் OpenAI Images API-ஐப் பயன்படுத்துகிறது. விருப்பங்களில் `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background`, மற்றும் `response_format` ஆகியவை அடங்கும்.
- `zm/meta/muse-image-1.0` போன்ற பிற வெளியீட்டாளர்கள் ZenMux-இன் Vertex AI `:predict`
  endpoint-ஐப் பயன்படுத்துகின்றனர். `n` ஆனது `sampleCount` உடனும், `aspect_ratio` ஆனது `aspectRatio` உடனும், `image_size`
  (`1K`, `2K`, `4K`) ஆனது `sampleImageSize` உடனும் வரைபடமாக்கப்படுகின்றன. பிக்சல் `size` ஆனது விகிதத்தை மட்டுமே வழங்கும்;
  உறுதியான பிக்சல் பரிமாணங்களை வழங்காது. ஆதரிக்கப்படும் விகிதங்கள், தெளிவுத்திறன்கள் மற்றும் எண்ணிக்கைகள் மாதிரிக்கு ஏற்ப மாறுபடும்.
- `zm/inclusionai/ming-image-0.1-design` அதன் சொந்த பரிமாணங்களைத் தேர்ந்தெடுக்கிறது. `size`,
  `aspect_ratio`, மற்றும் `image_size` ஆகியவற்றைத் தவிர்க்கவும்; வெளிப்படையாக வழங்கப்படும் மதிப்புகள் HTTP 400-ஐத் திருப்பித் தரும். PNG, JPEG மற்றும் WebP
  ஆகியவற்றை `output_format` மூலம் கோரலாம்.

இந்த ஒருங்கிணைப்பு உரையிலிருந்து படத்தை உருவாக்குவதை ஆதரிக்கிறது; குறிப்புப் படத்தைத் திருத்துவதை அல்ல. Vertex
வெளியீடு `data[].b64_json` ஆக இயல்பாக்கப்படுகிறது; `response_format: "url"` ஆனது upstream
HTTPS URL-ஐ அல்லது படத்தின் பைட்டுகள் மட்டுமே கிடைக்கும்போது base64 data URL-ஐத் திருப்பித் தருகிறது. காலியான/வடிகட்டப்பட்ட வெளியீடுகள்
காலியான வெற்றிப் பதிலுக்குப் பதிலாகப் பிழையைத் திருப்பித் தருகின்றன. மாதிரி அணுகல் ZenMux கணக்கைப் பொறுத்தது.
[ZenMux-இன் Vertex API](https://docs.zenmux.ai/api/vertexai/generate-images) மற்றும்
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image) ஆகியவற்றைப் பார்க்கவும்.

## ஆவண OCR

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model` ஆனது `provider/model` முன்னொட்டின் மூலம் OCR வழங்குநரைத் தேர்ந்தெடுக்கிறது; வழங்குநர் இல்லாத மாதிரி ID (எ.கா.
`mistral-ocr-latest`) அதன் பதிவுசெய்யப்பட்ட வழங்குநருக்குத் தீர்மானிக்கப்படுகிறது; மேலும் `model` தவிர்க்கப்பட்டால் இயல்புநிலையாக
Mistral (`mistral-ocr-latest`) பயன்படுத்தப்படும். பதிவுசெய்யப்பட்ட வழங்குநர்கள் (`open-sse/config/ocrRegistry.ts`):

| வழங்குநர் ID                  | மாதிரி ID            | `model` மதிப்பு                                            | குறிப்புகள்                                                                                                                         |
| ----------------------------- | -------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (அல்லது `mistral-ocr-latest`) | ஒத்திசைவானது — ஒற்றை upstream அழைப்பிலிருந்து பதில் நேரடியாகத் திருப்பித் தரப்படுகிறது.                                             |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                | ஒத்திசைவற்ற upstream (`analyze` + poll) — கீழே காண்க.                                                                               |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                    | ஒத்திசைவானது, Vertex AI-இன் `openapi/chat/completions` கூட்டாளர் endpoint வழியாக — அங்கீகாரம்/URL குறித்த விவரங்களுக்கு கீழே காண்க. |

மூன்று வழங்குநர்களும் ஒரே Mistral வடிவமைப்பிலான body-யில் பதிலளிக்கின்றனர்:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Azure Document Intelligence poll ஓட்டம்

Azure Document Intelligence-இன் `analyze` API ஒத்திசைவற்றது: தொடக்கக் கோரிக்கை body-க்குப் பதிலாக
`Operation-Location` header-ஐத் திருப்பித் தருகிறது; அதன் முடிவை poll செய்ய வேண்டும். Handler
(`open-sse/handlers/ocr.ts`) அந்த URL-ஐ ஒவ்வொரு வினாடியும் அதிகபட்சம் 30 முயற்சிகள் வரை poll செய்கிறது; `ok` அல்லாத poll பதில் அல்லது `"failed"` நிலை ஏற்பட்டால் உடனடியாகத் தோல்வியடைகிறது (தொடர்ந்து
poll செய்யாது); முயற்சி வரம்பு தீர்ந்த பிறகும் செயல்பாடு இயங்கிக்கொண்டிருந்தால்
`504`-ஐத் திருப்பித் தருகிறது. இறுதி Azure பதில், அழைப்பாளருக்குத் திருப்பித் தரப்படுவதற்கு முன்பு,
Mistral பயன்படுத்தும் அதே `pages`/`markdown` வடிவத்துக்கு இயல்பாக்கப்படுகிறது; எனவே client code வழங்குநருக்கென தனிப்பட்ட கையாளுதலைச் செய்ய வேண்டியதில்லை.

### Vertex AI DeepSeek OCR அங்கீகாரம் மற்றும் endpoint தீர்மானம்

`vertex-deepseek-ocr`, chat/image போக்குவரத்திற்காக OmniRoute ஏற்கனவே ஆதரிக்கும் அதே Vertex AI அங்கீகாரத்தை
மீண்டும் பயன்படுத்துகிறது (`open-sse/executors/vertex.ts`): இணைப்பின் API key என்பது
Service Account JSON credential ஆகும் (JWT-bearer ஓட்டத்தின் மூலம் குறுகிய கால OAuth access token-ஆக மாற்றப்படும்)
அல்லது ஏற்கனவே உருவாக்கப்பட்ட OAuth access token அப்படியே பயன்படுத்தப்படும். Upstream endpoint URL என்பது Vertex-இன்
பொதுவான `openapi/chat/completions` கூட்டாளர் endpoint ஆகும்; இது இணைப்பின் project மற்றும்
region ஆகியவற்றிலிருந்து உருவாக்கப்படுகிறது — வெளிப்படையான `providerSpecificData.project`/`providerSpecificData.region` எப்போதும் முன்னுரிமை பெறும்;
இல்லையெனில் project ஆனது Service Account JSON-இன் `project_id` இலிருந்து பெறப்படும், மேலும் region
இயல்புநிலையாக `us-central1` ஆகும். இரண்டு தீர்மானங்களும் `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) இல் நடைபெறுகின்றன; அவை
`handleOcr`-க்கு அனுப்புவதற்கு முன்பு `src/app/api/v1/ocr/route.ts` ஆல் பயன்படுத்தப்படுகின்றன.

### மாடல் விலைகள் (`pricing`)

OmniRoute-க்கு ஒரு மாடலின் விலை தெரிந்திருக்கும்போது, அந்தப் பதிவு `pricing` பொருளைக் கொண்டிருக்கும். செலவுக் கணக்கீடு பயன்படுத்தும் விலை அட்டவணையிலிருந்து விலை பெறப்படுகிறது: உள்ளமைக்கப்பட்ட இயல்புநிலைகள், ஒத்திசைக்கப்பட்ட விலைகள் மற்றும் `/api/pricing` வழியாக அமைக்கப்பட்ட மேலெழுதல்கள். இவை பட்டியல் விலைகள் என்பதால், சந்தா வழங்குநர்களும் ஒவ்வொரு டோக்கனுக்குமான விலையைக் காட்டுவார்கள்.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| புலங்கள்                                                        | அலகு                             | குறிப்புகள்                                                                                                                                                                        |
| --------------------------------------------------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | ஒரு டோக்கனுக்கான USD, தசமச் சரம் | OpenRouter-இணக்கமானது; ஒருபோதும் அடுக்குக்குறி வடிவில் இருக்காது. கேச் விலை இருக்கும்போது மட்டுமே இரண்டு கேச் புலங்களும் தோன்றும்.                                                 |
| `input`, `output`, `cached`, `cache_creation`                   | 1M டோக்கன்களுக்கான USD, எண்      | முந்தைய பட்டியல் பதிப்புகளிலிருந்த புலங்கள், ஏற்கெனவே உள்ள கிளையண்டுகளுக்காகத் தக்கவைக்கப்பட்டுள்ளன. விலை வரிசையில் `reasoning` மற்றும் `long_context` இருந்தால் அவையும் தோன்றும். |

- **சேர்க்கைகள்** அவற்றின் முதலாவது புலப்படும் இலக்கின் விலையைக் கொண்டிருக்கும். உள்ளமைக்கப்பட்ட `auto/*` சேர்க்கைகள் கோரிக்கை நேரத்தில் ஓர் இலக்கைத் தேர்ந்தெடுப்பதால், அவற்றில் `pricing` இருக்காது.
- **இலவச மாடல்கள்** அவற்றின் விலை பூஜ்ஜியமாக இருக்கும்போது `"0"` (மற்றும் `0`) என்பதைக் காட்டும். விலை வரிசை இல்லாத ஒரு மாடலையும், பட்டியல் அதை இலவசம் எனக் குறித்திருந்தால் (`free: true`) அல்லது உள்ளமைக்கப்பட்ட இலவச மாடல் பட்டியல் அதைக் கொண்டிருந்தால், `"0"` எனக் காட்டும்.
- **அறியப்படாத விலை:** அந்தப் பதிவில் `pricing` விசை இருக்காது.
- **கிரெடிட் அடிப்படையில் அளவிடப்படும் வழங்குநர்கள்** (Kiro போன்றவை) ஒவ்வொரு டோக்கனுக்கும் பதிலாக ஒவ்வொரு கோரிக்கைக்கும் கட்டணம் விதிக்கின்றன. அவற்றின் பதிவுகள் முன்பிருந்த 1M-க்கான எண் புலங்களைத் தக்கவைத்துக் கொண்டு, ஒவ்வொரு டோக்கனுக்குமான சரப் புலங்களைக் கொண்டிருக்காது.
- **மாற்றுருக்கள்** (reasoning-effort ஐடிகள், no-thinking மாற்றுப்பெயர்கள், கண்டறிதல் மற்றும் கேட்வே பிரதிகள்) அவை வழிமாற்றும் மாடலின் விலையை நகலெடுக்கின்றன.
- இந்தப் புலங்கள் அடிப்படை விகிதங்களை மட்டுமே கொண்டிருக்கும். நீண்ட-சூழல் அடுக்குகள் (எண் வகை `long_context` புலம்) மற்றும் சேவை-அடுக்கு பெருக்கிகள் (எடுத்துக்காட்டாக Codex fast அல்லது flex) `prompt` அல்லது `completion`-ஐ மாற்றாது.
- Anthropic பாணியிலான `x-api-key` மற்றும் `anthropic-version` கொண்ட கோரிக்கை உட்பட, ஒவ்வொரு அங்கீகார முறைக்கும் இந்தப் பொருள் ஒரே மாதிரியாக இருக்கும் (பதில் `{ "object": "list",
"data": [...] }` ஆகவே இருக்கும்). செயலாக்கம்: `src/app/api/v1/models/catalogPricing.ts`.

### மாடல் ஐடி முன்னொட்டுகள் (`?prefix=`)

பெரும்பாலான மாடல்கள் ஒரு **வழங்குநர் முன்னொட்டின்** கீழ் விளம்பரப்படுத்தப்படுகின்றன. உங்களுக்குக் கிடைக்கும் முன்னொட்டை `MODELS_CATALOG_PREFIX_MODE` அம்சக் கொடி கட்டுப்படுத்துகிறது; மேலும், அனைவருக்கும் பொருந்தும் சேவையக அளவிலான அமைப்பை மாற்றாமல், தெளிவான பட்டியலை விரும்பும் ஒரு கிளையண்டுக்குப் பயனுள்ளதாக இருக்கும் வகையில், வினவல் அளவுரு மூலம் **ஒவ்வொரு கோரிக்கைக்கும்** அதை மேலெழுதலாம்:

```bash
GET /v1/models?prefix=alias        # ஒரு மாடலுக்கு ஓர் ஐடி — குறுகிய மாற்றுப்பெயர் முன்னொட்டு
GET /v1/models?prefix=dual         # இரண்டு வடிவங்களும் (சேவையக இயல்புநிலை)
GET /v1/models?prefix=canonical    # முழுமையான வழங்குநர்-ஐடி முன்னொட்டு மட்டும்
```

| பயன்முறை    | வெளியிடுவது                                                   | குறிப்புகள்                                                                                                                                                                                                                                 |
| ----------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **மற்றும்** `claude/claude-sonnet-4-6` | **இயல்புநிலை.** இரண்டு ஐடிகளும் ஒரே மாடலுக்கு வழிமாற்றுகின்றன; இரண்டு வடிவங்களில் ஏதேனும் ஒன்றை நேரடியாகக் குறிப்பிட்ட கிளையண்ட் உள்ளமைவுகள் தொடர்ந்து செயல்படுவதற்காகத் தக்கவைக்கப்பட்டுள்ளன. பட்டியலின் அளவை ஏறத்தாழ இரட்டிப்பாக்குகிறது. |
| `alias`     | `cc/claude-sonnet-4-6`                                        | ஒரு மாடலுக்கு ஒரு பதிவு. தனித்துவமான மாற்றுப்பெயர் இல்லாத வழங்குநர்களும் தங்கள் பதிவை வெளியிடுவதால், எதுவும் இழக்கப்படாது.                                                                                                                  |
| `canonical` | `claude/claude-sonnet-4-6`                                    | முழுமையான வழங்குநர்-ஐடி முன்னொட்டின் கீழ் ஒரு மாடலுக்கு ஒரு பதிவு. தனித்துவமான மாற்றுப்பெயர் இல்லாத வழங்குநர்களும் (எ.கா. `antigravity/…`, `agy/…`) இங்கே தங்களின் ஒற்றை ஐடியை வெளியிடுவதால், எதுவும் இழக்கப்படாது.                         |

வினவல் அளவுரு இல்லாமலேயே ஒரு `dual`-பயன்முறை பிரதியை அடையாளம் காணலாம்: அது முதன்மை ஐடியைச் சுட்டிக்காட்டும் `parent` புலத்தைக் கொண்டிருக்கும்.

மாடல் தேர்வியை வழங்கும் கிளையண்டுகள் `?prefix=alias`-ஐக் கோர வேண்டும் — [OmniCopilot VS Code நீட்டிப்பு](../guides/VSCODE-COPILOT.md) இதைத்தான் செய்கிறது.

### கண்டறிதல் வடிப்பான்கள் (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` விருப்பத்தேர்வு அடிப்படையிலான கண்டறிதல் வடிப்பான்களை ஏற்கிறது. அவற்றில் எதுவும் இல்லையெனில் பதில் மாறாது. அழைப்பாளர் ஏற்கெனவே காணும் பட்டியலை அவை சுருக்குகின்றன (API-key அனுமதிகள் முதலில் பயன்படுத்தப்படும்); மேலும், OpenAI பாணியிலான `limit` / `after` பக்கமாக்கலுக்கு முன்பு அவை இயங்குகின்றன:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # பட்டியலிடப்பட்ட ஒவ்வொரு திறனும் true ஆக இருக்க வேண்டும்
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # பட்டியல் `type`; அது இல்லாத வரிசைகள் `chat`
GET /v1/models?q=sonnet&limit=10                           # ஐடி அல்லது பெயரில் எழுத்துப் பெட்டி உணராத பொருத்தம்
```

| அளவுரு        | மதிப்புகள்                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | எதிர்மறையல்லாத முழு எண்; `context_length` உடன் ஒப்பிடப்படும்                                        |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 எழுத்துகள்                                                                                    |

அறியப்படாத மதிப்பு அல்லது எதிர்மறையல்லாத முழு எண்ணாக இல்லாத `min_context` (எடுத்துக்காட்டாக `1.5`)
HTTP `400`-ஐத் திருப்பி அனுப்பும்; மேலும், செய்தியில் செல்லுபடியாகும் மதிப்புகள் பட்டியலிடப்படும். செயலாக்கம்:
`src/app/api/v1/models/catalogFilters.ts`.

### மாதிரிகளின் சுருக்கப்பட்ட பட்டியல் (`POST /v1/models/query`)

`POST /v1/models/query`, `GET /v1/models` பயன்படுத்தும் அதே பட்டியலிலிருந்து, அதே
அங்கீகாரம் மற்றும் ஒவ்வொரு விசைக்குமான தெரிவுநிலையுடன், குறுகிய மற்றும் நிர்ணயிக்கப்பட்ட பட்டியலைத் திருப்பி அனுப்புகிறது:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

ஒவ்வொரு புலமும் விருப்பத்திற்குரியது. `capabilities` மற்றும் `exclude` ஆகியவை ஓர் அணிவரிசை அல்லது காற்புள்ளியால் பிரிக்கப்பட்ட சரத்தை
ஏற்கின்றன; `max_output`, `max_output_tokens` உடன் ஒப்பிடப்படுகிறது. முடிவுகள் முதலில் `owned_by`, பின்னர் `id`
ஆகியவற்றின்படி வரிசைப்படுத்தப்படுகின்றன. `limit`-இன் இயல்புநிலை `20`; மேலும் `100`-ஐ விட அதிகமான மதிப்புகள் `100` ஆக வரம்பிடப்படுகின்றன. செல்லுபடியாகாத JSON, அறியப்படாத
புலம் அல்லது செல்லுபடியாகாத மதிப்பு HTTP `400`-ஐத் திருப்பி அனுப்பும்.

### தனித்தனியாக மறைக்கப்பட்ட அரட்டை மாதிரிகள்

வழங்குநர் பக்கத்தில் **மறைக்கப்பட்டது** எனக் குறிக்கப்பட்ட மாதிரி பட்டியலிலிருந்து விலக்கப்படும்; மேலும், வெளிப்படையாகக்
கோரப்படும்போது HTTP `404` / `model_not_found` உடன் நிராகரிக்கப்படும். வழங்குநர் மாற்றுப்பெயர்கள், இணக்கமான வழங்குநரின் முனைக் கூறு முன்னொட்டுகள் மற்றும்
இணைப்பு இயல்புநிலைகள் உட்பட, தீர்மானிக்கப்பட்ட வழங்குநர் மற்றும் மாதிரியை இந்தச் சரிபார்ப்பு பயன்படுத்துகிறது.
ஒரு கூட்டுத் தொகுப்பு மறைக்கப்பட்ட இலக்குகளைத் தவிர்த்து, காணக்கூடிய இணை மாதிரியைப் பயன்படுத்தலாம்; இயக்கக்கூடிய
இலக்கு எதுவும் மீதமில்லாதபோது, அதே பிழைக் குறியீட்டைத் திருப்பி அனுப்பும். மறைத்தலை நீக்குவது அடுத்த
கோரிக்கையிலிருந்து நடைமுறைக்கு வரும். படங்களுக்கு மட்டும் உரிய தெரிவுநிலை மேலெழுதல்கள், அதே ID கொண்ட அரட்டை மாதிரியை மறைக்காது.

இந்தத் தனிப்பட்ட மாதிரி அமைப்பு,
[மாதிரி வெளிப்பாடு அனுமதி/மறுப்புப் பட்டியல்கள்](../routing/MODEL_EXPOSURE_LIST.md) என்பவற்றிலிருந்து தனிப்பட்டது; அவை வெளிப்படையான அனுப்புதலைத் தக்கவைத்தபடி பட்டியல்
விளம்பரத்தையும் தானியங்கி வழிப்படுத்தல் தேர்வுகளையும் வடிகட்டுகின்றன. API விசை மாதிரி
அனுமதிகள் தொடர்ந்து தனித்தனியாகப் பொருந்தும். இயல்புநிலை பட்டியல் முன்னொட்டு முறை `dual` ஆகவே இருக்கும்.

### சிந்தனை இல்லாத மாதிரி மாறுபாடுகள்

சிந்திக்கும் திறனுள்ள Claude மாதிரிகளுக்கு, `/v1/models`, `claude-3-omniroute-no-thinking/` என்ற முன்னொட்டைக் கொண்ட id உடைய **சிந்தனை இல்லாத** மாறுபாட்டையும் வெளியிடுகிறது:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

இந்த id-ஐத் தேர்ந்தெடுப்பது (எடுத்துக்காட்டாக, எப்போதும் `thinking` தொகுதியை இணைக்கும் Claude Code உள்ளமைவில்) reasoning ஒடுக்கப்பட்ட நிலையில் உண்மையான `<provider>/<model>`-க்குத் திரும்பத் தீர்மானிக்கப்படுகிறது — `/v1/messages` பாதையில் `thinking:{type:"disabled"}` பயன்படுத்தப்படும் அல்லது `/v1/chat/completions` பாதையில் `reasoning`/`reasoning_effort` புலங்கள் நீக்கப்படும். சிந்தனையை ஆதரிப்பதுடன் **மேலும்** `disabled`-ஐ மதிக்கும் Claude-குடும்ப மாதிரிகளுக்கு மட்டுமே இந்த மாறுபாடு பட்டியலிடப்படும் (எனவே, எடுத்துக்காட்டாக, `disabled`-ஐ நிராகரிக்கும் adaptive-only மாதிரிகள் விலக்கப்படும்). இயக்குநர்கள் `ModelSpec.noThinkingAlias` வழியாக ஒவ்வொரு மாதிரிக்கும் இந்த மாறுபாட்டைக் கட்டாயமாக இயக்கவோ முடக்கவோ முடியும்.

## ElevenLabs ஒலி உருவாக்கம்

உங்கள் ElevenLabs API விசையுடன் OmniRoute-இல் ஓர் `elevenlabs` வழங்குநர் இணைப்பை உள்ளமைக்கவும்.
கிளையன்ட்கள் தங்களின் **OmniRoute** விசையைக் கொண்டு (`Authorization: Bearer $OMNIROUTE_API_KEY`) அங்கீகரிக்கின்றன;
நுழைவாயில் சேமிக்கப்பட்ட வழங்குநர் விசையை `xi-api-key` ஆக வழங்குகிறது. ElevenLabs விசையை ஒருபோதும்
நுழைவாயிலின் bearer token ஆக அனுப்ப வேண்டாம்.

| முறை | பாதை                        | பதில்                                                 | API விசை endpoint வகை |
| ---- | --------------------------- | ----------------------------------------------------- | --------------------- |
| POST | `/v1/sound-generation`      | இயல்புநிலை ஒலி bytes                                  | `elevenlabs`          |
| POST | `/v1/music`                 | இயல்புநிலை ஒலி bytes                                  | `music`               |
| POST | `/v1/music/stream`          | ஸ்ட்ரீமிங் ஒலி bytes                                  | `music`               |
| POST | `/v1/music/detailed`        | இயல்புநிலை multipart ஒலி மற்றும் இசையமைப்புத் திட்டம் | `music`               |
| POST | `/v1/music/detailed/stream` | இயல்புநிலை SSE metadata மற்றும் ஒலித் துண்டுகள்       | `music`               |
| POST | `/v1/music/plan`            | JSON இசையமைப்புத் திட்டம்                             | `music`               |

இந்த endpoint-கள் ஏற்கனவே உள்ள `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` மற்றும் `/v1/speech-to-text` வழித்தடங்களை நிறைவு செய்கின்றன. `output_format` மற்றும் `enable_logging` போன்ற இயல்புநிலை JSON புலங்களும்
வினவல் அளவுருக்களும் மாற்றமின்றிப் பாதுகாக்கப்படுகின்றன.
`/v1/music/detailed` பதில்கள் அவற்றின் multipart எல்லைகளைத் தக்கவைத்துக் கொள்கின்றன; அவற்றை multipart ஆகப் பகுப்பாய்வு செய்யவும்.
`/v1/music/detailed/stream`, இசையமைப்பு metadata மற்றும்
base64 ஒலித் துண்டுகளைக் கொண்ட SSE நிகழ்வுகளுடன் `text/event-stream`-ஐத் திருப்பியளிக்கிறது. ஆறு வழித்தடங்களும் CORS preflight-ஐ ஆதரிக்கின்றன.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# ஒரு குறுகிய ஒலி விளைவு. கால அளவு: 0.5 முதல் 30 வினாடிகள்.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# இசைக் கால அளவு மில்லிவினாடிகளில் குறிப்பிடப்படுகிறது: 3000 முதல் 600000 வரை.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

படிப்படியான ஒலி வழங்கலுக்கு அதே JSON body-யுடன் `/v1/music/stream`-ஐப் பயன்படுத்தவும். இசையமைப்பு
`prompt` அல்லது `composition_plan` ஆகியவற்றில் சரியாக ஒன்றை ஏற்கிறது; `/v1/music/plan`-க்கு `prompt`
தேவை, மேலும் அது விருப்பமாக `source_composition_plan`-ஐ ஏற்கிறது. இயல்புநிலை schemas கூடுதல்
வழங்குநர் புலங்களைப் பாதுகாப்பதால் இசையமைப்புத் திட்டப் பதிப்புகளும் நுண்-சீரமைப்பு விருப்பங்களும் ElevenLabs-ஐச் சென்றடைகின்றன.

ஒருங்கிணைந்த `/v1/music/generations` endpoint, `elevenlabs/music_v1`,
`elevenlabs/music_v2` மற்றும் `elevenlabs/music_v2_5` ஆகியவற்றையும் ஏற்கிறது. செயலில் உள்ள ElevenLabs இணைப்புடன்,
இந்த மாதிரிகள் இசைப் பட்டியலில் வெளிப்படுத்தப்படுகின்றன. இந்த endpoint
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}` என்பதைத் திருப்பியளிக்கிறது. அதன் `duration` புலம்
வினாடிகளில் உள்ளது மற்றும் `music_length_ms`-க்கு வரைபடுத்தப்படுகிறது; வெளிப்படையாகக் குறிப்பிடப்பட்ட `music_length_ms` முன்னுரிமை பெறுகிறது.
`instrumental`, `force_instrumental`-க்கு வரைபடுத்தப்படுகிறது; இதில் இயல்புநிலைப் புலம் முன்னுரிமை பெறுகிறது.
ஸ்ட்ரீமிங்கிற்கு இயல்புநிலை ஸ்ட்ரீமிங் endpoint-களையும், இசையமைப்புத் திட்டத்தால் மட்டுமே இயக்கப்படும் கோரிக்கைகளுக்கு
இயல்புநிலை இசையமைப்பு endpoint-ஐயும் பயன்படுத்தவும்.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Upstream அழைப்பிற்கு முன் endpoint, மாதிரி, budget மற்றும் இணைப்புக் கட்டுப்பாடுகள் பயன்படுத்தப்படுகின்றன. இயல்புநிலை
வழித்தடங்கள் upstream நிலைக் குறியீடுகள் மற்றும் பிழை body-களை மாற்றமின்றித் திருப்பியளிக்கின்றன; திட்டக்
கட்டுப்பாட்டிற்கான `402` மற்றும் quota வரம்பிற்கான `429` ஆகியவையும் இதில் அடங்கும். `character-cost`, `song-id`, `request-id` மற்றும் `retry-after`
தலைப்புகள் இருந்தால் அவை பாதுகாக்கப்படுகின்றன. இலவச credit இருப்பு, ஒவ்வொரு
இசை மாதிரி, வெளியீட்டு வடிவம் அல்லது API அம்சத்திற்குமான அணுகலை உறுதிசெய்யாது: ஒவ்வொரு கோரிக்கைக்குமான உரிமையை ElevenLabs தீர்மானிக்கிறது.
ஒருங்கிணைந்த endpoint, OmniRoute-இன் இயல்பாக்கப்பட்ட பிழை உறையில் பிழை நிலைக் குறியீடுகளைப் பாதுகாக்கிறது.

Upstream ஒப்பந்தங்கள்: [ஒலி விளைவுகள்](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[இசையமைப்பு](https://elevenlabs.io/docs/api-reference/music/compose) மற்றும்
[ஸ்ட்ரீமிங் இசை விவரங்கள்](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

அனைத்து POST வழித்தடங்களும் ஒரே வடிவமைப்பைப் பின்பற்றுகின்றன: `Bearer your-api-key` + Zod மூலம் சரிபார்க்கப்பட்ட JSON body (`v1RerankSchema`, `v1ModerationSchema`, `v1AudioSpeechSchema` போன்றவை; `src/shared/validation/schemas.ts`-ஐப் பார்க்கவும்). schema சரிபார்ப்பு தோல்வியடைந்தால் 4xx வழங்கப்படும்.

`Authorization: Bearer ...`-ஐ இணைக்க முடியாத client-களுக்காக, query-string இணக்கத்தன்மை (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`) அல்லது கீழே ஆவணப்படுத்தப்பட்டுள்ள பிரத்யேக `/api/v1/vscode/{token}/...` முனைப்புள்ளிகள் மூலமாக URL-இல் API key-களையும் OmniRoute ஏற்றுக்கொள்கிறது.

```bash
# மறுதரவரிசையாக்கம் (cloud registry provider அல்லது "<prefix>/<model>" என்ற OpenAI-இணக்கமான provider node)
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Jina வகைப்படுத்தல் (Foundation API சான்றுகள்)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Jina பிரிப்பான்
POST /v1/segment     { "content": "...", "return_chunks": true }

# Jina தேடல் (s.jina.ai; provider மாற்றுப்பெயர்கள்: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# உள்ளடக்க மதிப்பாய்வுகள்
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — audio/mpeg (அல்லது கோரப்பட்ட வடிவம்) body-ஐ வழங்கும்
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }
```

> **மறுதரவரிசைப்படுத்தல் வழங்குநர் முனைகள்:** `POST /v1/rerank` என்பது OpenAI-இணக்கமான வழங்குநர் முனைகளுக்கும்
> (oMLX, vLLM, Infinity, நுழைவாயிலுக்குப் பின்னால் உள்ள TEI, …) வழிச்செலுத்தப்படுகிறது; அவை `<node-prefix>/<model>` எனக்
> குறிப்பிடப்படுகின்றன. லூப்பேக் முனைகள் (`localhost`, `127.0.0.1`, `172.16.0.0/12`) எப்போதும் தகுதியுடையவை; மேலும்,
> இயக்குநர் `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS`-இல் பட்டியலிடும் ஹோஸ்ட்பெயர்களும் தகுதியுடையவை (எ.கா.,
> `http://reranker:8080/v1` போன்ற Docker/Compose சேவைப் பெயர்; இவை `HTTP(S)_PROXY` அல்லது இணைப்பில்
> நிலையாகப் பொருத்தப்பட்ட ப்ராக்ஸி வழியாக ஒருபோதும் செல்லாமல், நேரடியாக அழைக்கப்படுகின்றன). வேறு எந்த
> ஹோஸ்டிலுள்ள முனைகளும் — LAN சாதனம் அல்லது Tailscale பியர் — இயக்குநர்
> `RERANK_REMOTE_PROVIDER_NODES` அம்சக் கொடியை இயக்கியிருந்து, முனையின் அடிப்படை URL வழங்குநரின்
> வெளிச்செல்லும் URL கொள்கையை (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`)
> பூர்த்தி செய்தால் மட்டுமே தகுதியுடையவை. நினைவக இயந்திரத்தின் மறுதரவரிசைப்படுத்தல் படி, இந்த வழித்தடத்தை
> லூப்பேக் வழியாக அழைக்கிறது; எனவே நினைவக அமைப்புகளில் உள்ள `rerankProviderModel`-க்கும் இதே விதி பொருந்தும்.
>
> **உள்ளூர் சேவையக வடிவங்கள்:** முனை முதலில் `<base>/v1/rerank`-இலும், 404 ஏற்பட்டால்
> `<base>/rerank`-இலும் (Infinity, TEI) அழைக்கப்படுகிறது. அப்ஸ்ட்ரீம் கோரிக்கை உடல் Cohere/OpenAI எழுத்துமுறையையும்
> (`documents`, `return_documents`), TEI எழுத்துமுறையையும் (`texts`, `return_text`) கொண்டிருக்கும்; அப்ஸ்ட்ரீம்
> பதில் Cohere உறை வடிவத்திற்கு இயல்பாக்கப்படுகிறது: TEI-இன் வெற்று `[{index, score, text}]`, எளிய
> நுழைவாயில்களிலிருந்து வரும் `{results: [{index, score}]}`, மற்றும் Voyage பாணியிலான `{data: [...]}` ஆகிய அனைத்தும்
> கிளையண்டிற்கு `{results: [{index, relevance_score, document?}]}` ஆகத் திருப்பி அனுப்பப்படுகின்றன; மதிப்பெண் அடிப்படையில்
> வரிசைப்படுத்தப்பட்டு, `top_n` வரை வரம்பிடப்படுகின்றன.

> **வழங்குநர் முனை கண்டறிதல்:** OpenAI-இணக்கமான வழங்குநர் முனையிலுள்ள மாதிரிகள், முனை முன்னொட்டின் கீழ்
> `GET /v1/models`-இல் தோன்றும். எண்ட்பாயிண்ட் மெட்டாடேட்டா இல்லாத வரிசைகள் (உள்ளூர் `/v1/models` பட்டியல்களில்
> பொதுவானவை) முனையின் `apiType`-ஐப் பெறுகின்றன; எனவே `embeddings` முனையின் மாதிரிகள் இயல்பாக அரட்டையாக
> அமைவதற்குப் பதிலாக `type: "embedding"` ஆகவும், `rerank` முனையின் மாதிரிகள் `type: "rerank"` ஆகவும் இருக்கும்;
> ஒத்திசைக்கப்பட்ட அல்லது கைமுறையாகச் சேர்க்கப்பட்ட வரிசையில் வெளிப்படையாகக் குறிப்பிடப்பட்ட `supportedEndpoints`
> இன்னும் முன்னுரிமை பெறும்.

## Files API

தொகுதி உள்ளீடு/வெளியீடு மற்றும் கோப்பு-நோக்கப் பதிவேற்றங்களுக்கான OpenAI-இணக்கமான கோப்புகள் முனைப்புள்ளி.

| முறை   | பாதை                     | விளக்கம்                                                                                                                       |
| ------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| POST   | `/v1/files`              | ஒரு கோப்பைப் பதிவேற்றும் (பல்பகுதி: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — அதிகபட்சம் 512 MiB |
| GET    | `/v1/files`              | அங்கீகரிக்கப்பட்ட API விசைக்கான கோப்புகளைப் பட்டியலிடும்                                                                       |
| GET    | `/v1/files/[id]`         | ஒரு கோப்பின் மெட்டாடேட்டாவைப் பெறும்                                                                                           |
| DELETE | `/v1/files/[id]`         | ஒரு கோப்பை நீக்கும்                                                                                                            |
| GET    | `/v1/files/[id]/content` | மூலக் கோப்பு உடற்பகுதியை ஸ்ட்ரீம் செய்து திருப்பி அனுப்பும்                                                                    |

**அங்கீகாரம்:** Bearer API விசை — `getApiKeyRequestScope` வழியாக ஒவ்வொரு API விசைக்கும் தனித்தனியாகக் கோப்புகள் வரையறுக்கப்படுகின்றன. ஒரு விசை
தனக்குச் சொந்தமான கோப்புகளை மட்டுமே பார்க்கவும், பதிவிறக்கவும், நீக்கவும் முடியும்; விசை இல்லாத டாஷ்போர்டு அமர்வு
முழு நிகழ்வையும் படிக்கும்; உரிமையாளர் இல்லாத கோப்பு (அநாமதேய அல்லது டாஷ்போர்டு-அமர்வுப் பதிவேற்றம்) ஒவ்வொரு
அமர்வு அல்லாத அழைப்பாளருக்கும் மறுக்கப்படும். `GET /v1/files`, `REQUIRE_API_KEY=false` ஆக இருந்தாலும், ஒவ்வொரு குத்தகையாளரின்
கோப்புகளையும் பட்டியலிடுவதற்குப் பதிலாக, அநாமதேய அழைப்பாளரையும் — மேலும் வழங்கப்பட்ட விசை செல்லுபடியாகாதபோதும் —
`401` உடன் நிராகரிக்கும் (GHSA-m3hp-hq9g-fpmv, GHSA-2jm2-mpx8-6523).

## Batches API

OpenAI-இணக்கமான தொகுதிச் செயலாக்கம்.

| முறை   | பாதை                      | விளக்கம்                                                                                                                          |
| ------ | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/batches`             | தொகுதியை உருவாக்கும் — `v1BatchCreateSchema` மூலம் உடற்பகுதி சரிபார்க்கப்படும் (`input_file_id`, `endpoint`, `completion_window`) |
| GET    | `/v1/batches`             | தொகுதிகளைப் பட்டியலிடும்                                                                                                          |
| GET    | `/v1/batches/[id]`        | தொகுதி நிலை + `request_counts` ஆகியவற்றைப் பெறும்                                                                                 |
| DELETE | `/v1/batches/[id]`        | முடிந்த/தோல்வியடைந்த தொகுதியை நீக்கும்                                                                                            |
| POST   | `/v1/batches/[id]/cancel` | செயல்பாட்டிலுள்ள தொகுதியை ரத்துசெய்யும்                                                                                           |

**அங்கீகாரம்:** Bearer API விசை. கோப்புகளுக்குப் பொருந்தும் அதே மும்முனை விதியின் கீழ், ஒவ்வொரு API விசைக்கும் தனித்தனியாகத்
தொகுதிகள் வரையறுக்கப்படுகின்றன: சொந்த விசைக்கு மட்டும், டாஷ்போர்டு அமர்வுக்கு நிகழ்வு முழுவதும், உரிமையாளர் இல்லாத பதிவுகள் ஒவ்வொரு
அமர்வு அல்லாத அழைப்பாளருக்கும் மறுக்கப்படும் (பெறுதல், நீக்குதல், ரத்துசெய்தல் மற்றும் உருவாக்கும்போதான `input_file_id` சரிபார்ப்பு).
`REQUIRE_API_KEY=false` ஆக இருந்தாலும், `GET /v1/batches` அநாமதேய அழைப்பாளரை `401` உடன் நிராகரிக்கும்.

## API தேடுங்கள்

Web/search வழங்குநர் சுருக்கம் (Tavily, Brave, Exa, Serper, முதலியன).

| முறை | பாதை                   | விளக்கம்                                                                                           |
| ---- | ---------------------- | -------------------------------------------------------------------------------------------------- |
| GET  | `/v1/search`           | உள்ளமைக்கப்பட்ட தேடல் வழங்குநர்களின் + திறன்களைப் பட்டியலிடுங்கள்                                  |
| POST | `/v1/search`           | `v1SearchSchema` ஆல் சரிபார்க்கப்பட்ட தேடல் வினவல் — ஐ இயக்கவும், caching/coalescing ஐ ஆதரிக்கிறது |
| GET  | `/v1/search/analytics` | ஒவ்வொரு வழங்குநருக்கும் hit/latency/cache புள்ளிவிவரங்கள்                                          |

**அங்கீகாரம்:** தாங்கி API விசை (`extractApiKey` + `isValidApiKey`). தேடல் கொள்கை `enforceApiKeyPolicy` வழியாக செயல்படுத்தப்பட்டது.

### Exa மற்றும் Tavily `provider_options`

Exa மற்றும் Tavily ஒரு பெயர் இடைவெளி பையில் இருந்து வழங்குநர்-குறிப்பிட்ட புலங்களைப் படிக்கவும்: `provider_options.exa` (அல்லது `provider_options["exa-search"]`) மற்றும் `provider_options.tavily` (அல்லது `provider_options["tavily-search"]`). கீழே உள்ள விசைகள் மட்டுமே அனுப்பப்படும். ஒவ்வொன்றும் அதன் சொந்த Zod ஸ்கீமாவிற்கு எதிராக `open-sse/handlers/search/providerOptionsPassthrough.ts` இல் சரிபார்க்கப்பட்டது, மேலும் தவறான வகையுடன் ஒரு விசை கைவிடப்பட்டது. அங்கீகாரம், அடிப்படை URL, `stream` மற்றும் `outputSchema` உட்பட வேறு எந்த விசையும் புறக்கணிக்கப்படும். பிற வழங்குநர்கள் பயன்படுத்தும் பிளாட் கீகள் (`cx`, `depth`, ...) முன்பு போலவே செயல்படும்.

| வழங்குபவர் | உயர்மட்ட புலங்கள்                                                                                                                                                                                                                                                                                                                                                         | கூடு கட்டப்பட்டது                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa        | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (பிளாட் primitives), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                            | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` இயல்புநிலை `{ text: true, highlights: true }` மீது இணைக்கப்பட்டது |
| தவிலி      | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                               |

பொதுவான புலங்கள் எப்போதும் வெற்றி பெறும்: `query`, `max_results`, `filters` (டொமைன்கள்), `country` மற்றும் `search_type` இலிருந்து பெறப்பட்ட தலைப்பு. எக்ஸாவில், `search_type: "news"` `category: "news"` வைத்திருக்கும். Tavily `search_type: "finance"` (`topic: "finance"`) ஐயும் ஏற்றுக்கொள்கிறது.

Firecrawl தேடல் செலவு 10 திரும்பிய முடிவுகளின் ஒரு தொடக்கத் தொகுதிக்கு பதிவு செய்யப்படுகிறது, ஒரு தொகுதிக்கு $0.002 (2 வரவுகள்) மற்றும் ஒரு அழைப்புக்கு குறைந்தபட்சம் ஒரு தொகுதி ( [Firecrawl billing](https://docs.firecrawl.dev/billing) ): 11 முடிவுகளுக்கு $0.004 செலவாகும்.

பொதுவான `time_range` இப்போது இரு வழங்குநர்களையும் சென்றடைகிறது: Exa `startPublishedDate` (ISO நேர முத்திரை) மற்றும் Tavily `start_date` (`YYYY-MM-DD`) பெறுகிறது. `provider_options` இல் ஒரு வெளிப்படையான தேதி மேப் செய்யப்பட்டதை மீறுகிறது.

தேர்வு முடிவுகள் `id`, `highlight_scores`, `summary`, `subpages`, `entities` மற்றும் `extras` ஐ `provider_raw` இல் வைத்திருக்கும். Tavily முடிவுகள் `images` மற்றும் `favicon` வைத்திருக்கின்றன.

இணைப்புத் தேடல் செலவு `depth` `fast` மற்றும் `standard` க்கு $0.005 ஆகவும், `deep` க்கு $0.05 ஆகவும் ( [Linkup விலை நிர்ணயம்](https://docs.linkup.so/pages/documentation/development/pricing) ), `depth` `provider_options` அல்லது இணைப்பின் அமைப்புகளில் இருந்து வந்தாலும்.

Exa `type: "lite"` (Exa 3.0) ஒரு சிறிய புலங்களை ஏற்றுக்கொள்கிறது மற்றும் வேறு ஏதேனும் புலம் அமைக்கப்படும் போது முழு கோரிக்கையையும் நிராகரிக்கிறது. லைட்டிற்கு, `additionalQueries`, `systemPrompt` மற்றும் `text` மற்றும் `highlights` தவிர ஒவ்வொரு `contents` விசையும் அழைப்புக்கு முன் கைவிடப்படும். நிறுத்தப்பட்ட `subpages`, `subpageTarget`, `highlights.numSentences` மற்றும் `highlights.highlightsPerUrl` ஆகியவை இனி அனுப்பப்படாது.

எக்ஸாவின் சொந்த `auto` பின்பற்றும் எக்ஸாவைத் தவிர, காஸ்ட் `lite` என்பது பிளாட் `fast` `costPerQuery` `instant`. மேலும் ஒவ்வொரு முடிவுக்கும் $0.001; மற்றும் `contents.summary` அமைக்கப்படும் போது திரும்பிய முடிவு ஒன்றுக்கு $0.001. Tavily `search_depth` `basic`, `fast` மற்றும் `ultra-fast` க்கு 1 கிரெடிட் ($0.008) மற்றும் `advanced` க்கு 2 கிரெடிட்கள் ($0.016) ( [Tavily API கிரெடிட்ஸ்](https://docs.tavily.com/documentation/api-credits) ) என பதிவு செய்யப்பட்டுள்ளது. Tavily மேம்பட்டதாக மேம்படுத்தும் `auto_parameters: true` உடன் அழைப்பு இன்னும் 1 கிரெடிட்டில் பதிவுசெய்யப்படுகிறது.

## Web Fetch API

கட்டமைக்கப்பட்ட web-fetch வழங்குநர் (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract) வழியாக ஒரு URL-இலிருந்து உள்ளடக்கத்தைப் பிரித்தெடுக்கிறது.

Parallel Extract (`parallel-search`, Parallel Search பயன்படுத்தும் அதே API விசை) Markdown-ஐ
மட்டுமே வழங்கும் — வேறு எந்த `format`-உம் `400` பிழையை ஏற்படுத்தும் — மேலும் உள்ளடக்கத்தை 100,000 எழுத்துகளுக்கு வரம்பிடும். இலக்குப்
பக்கத்தையே பிரித்தெடுக்க முடியாதபோது, upstream அதை HTTP 200 பதிலுக்குள் தெரிவிக்கும்;
OmniRoute அதை ஒரு நிலையான செய்தியுடன் `422` ஆக வெளிப்படுத்தும்.

| முறை | பாதை            | விளக்கம்                                                                             |
| ---- | --------------- | ------------------------------------------------------------------------------------ |
| POST | `/v1/web/fetch` | ஒரு URL-ஐப் பெறுதல்/scrape செய்தல் — body `v1WebFetchSchema` மூலம் சரிபார்க்கப்படும் |

**அங்கீகாரம்:** Bearer API விசை (`extractApiKey` + `isValidApiKey`). கொள்கை `enforceApiKeyPolicy` வழியாகச் செயல்படுத்தப்படுகிறது.

**Quota-விழிப்புணர்வுள்ள fallback (#8297):** வெளிப்படையான `provider` எதுவும் வழங்கப்படாதபோது, pool
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) நிலையான
முன்னுரிமை வரிசையில் (fill-first) பயன்படுத்தப்படுகிறது — rate limit அடைந்திருந்தாலும் கட்டமைக்கப்பட்டுள்ள வழங்குநர்,
கோரிக்கையை உடனடியாக நிறுத்துவதற்குப் பதிலாகத் தவிர்க்கப்படும்; மேலும் மீண்டும் முயற்சிக்கக்கூடிய/quota தொடர்பான upstream தோல்வி
(HTTP 429 எப்போதும்; Firecrawl/Tavily/TinyFish quota வகை இலவச அடுக்குகளுக்கு 402/403 —
Jina Reader-க்கு அல்ல, மேலும் சாதாரணமான 400 தவறான கோரிக்கைக்கு ஒருபோதும் அல்ல) கோரிக்கை நேரத்தில்
இதுவரை முயற்சிக்கப்படாத அடுத்த credential கொண்ட வழங்குநருக்குச் செல்லும். Pool-இல் உள்ள ஒவ்வொரு வழங்குநரும்
தீர்ந்துவிட்டால், endpoint முந்தைய பொதுவான `400`-க்குப் பதிலாக ஒரே `429`-ஐ (`Retry-After`
header-உடன்) வழங்கும். வெளிப்படையான `provider` கோரப்பட்டால்,
அமைதியான fallback **இல்லை** — rate limit அடைந்த அல்லது தோல்வியடைந்த வெளிப்படையான
வழங்குநர் தனது சொந்தப் பிழையை வெளிப்படுத்தும் (rate limit அடைந்தால் `429`, இல்லையெனில் upstream
status).

## WebSocket ஸ்ட்ரீமிங்

```bash
GET /v1/ws?handshake=1
```

WebSocket upgrade handshake-ஐச் சரிபார்த்து, wire protocol எடுத்துக்காட்டு செய்திகளை (`request`, `cancel`) வழங்குகிறது. உண்மையான WS frame-கள் Next.js route table-க்கு வெளியே தொகுக்கப்பட்ட WS server மூலம் கையாளப்படுகின்றன.

**அங்கீகாரம்:** Handshake-இன் போது Bearer API விசை.

### WebSocket வழியான Responses API (codex மட்டும்)

```bash
# HTTP API பயன்படுத்தும் அதே host:port (இயல்புநிலை 20128); இணைப்பை upgrade செய்யவும்:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (அல்லது: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# முதல் frame கட்டாயமாக response.create ஆக இருக்க வேண்டும்:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Responses-API-over-WebSocket proxy **`codex`-க்கு மட்டுமே பிரத்யேகமாக** இணைக்கப்பட்டுள்ளது (ChatGPT
backend). இது API/dashboard பயன்படுத்தும் அதே port-இல் `/v1/responses`,
`/responses`, மற்றும் `/api/v1/responses` பாதைகளில் listen செய்கிறது. முதல் `response.create` frame-இல் இது
உள் `codex-responses-ws` bridge வழியாக அங்கீகரித்து + தயார்படுத்தி, ஒரு
codex OAuth இணைப்பைத் தேர்ந்தெடுத்து, `wreq-js` transport வழியாக `wss://chatgpt.com/backend-api/codex/responses`
என்பதற்குச் சுரங்க இணைப்பை உருவாக்குகிறது. **codex அல்லாத மாதிரிகள் நிராகரிக்கப்படும்** (`codex_ws_provider_required`).
Quota-share routing-க்கு `model: "qtSd/<group>/codex/<model>"` பயன்படுத்தவும். இது
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts` ஆகியவற்றில் செயல்படுத்தப்பட்டுள்ளது.

**அங்கீகாரம்:** Handshake-இன் போது Bearer API விசை. தொகுக்கப்பட்ட HTTP server (`server-ws.mjs`)
செயலில் உள்ள entrypoint ஆக இருக்க வேண்டும் (`app/server-ws.mjs` இருந்தால், இயல்புநிலையாக அதுவே இருக்கும்).

#### மாதிரி ID: அடிப்படை ChatGPT ID-ஐப் பயன்படுத்தவும் (`codex/` முன்னொட்டு வேண்டாம்)

OpenAI **Codex CLI**, `supports_websockets = true` ஆக இருக்கும்போது மாதிரிப் பெயரை client-side-இல் சரிபார்த்து,
`codex/gpt-5.5` போன்ற **வழங்குநர் முன்னொட்டுள்ள ID-களை நிராகரிக்கிறது**
(`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). **அடிப்படை** ID-ஐ அனுப்பவும் (எ.கா. `gpt-5.5`). OmniRoute-இன் bridge
codex-க்கு மட்டுமே உரியது; எனவே upstream-க்குச் சுரங்க இணைப்பை உருவாக்குவதற்கு முன், அடிப்படை ID-ஐ codex மாதிரியாக
(`resolveCodexWsModelInfo`) மீண்டும் resolve செய்கிறது — அடிப்படை
`gpt-5.5` HTTP வழியாக வேறொரு வழங்குநருக்கு route செய்யப்பட்டாலும் கூட.

#### OpenAI Codex CLI-ஐக் கட்டமைத்தல்

WebSocket ஆதரவுள்ள தனிப்பயன் வழங்குநரை `~/.codex/config.toml`-இல் சேர்த்து, Codex CLI-ஐ OmniRoute-ஐ நோக்கச் செய்யவும் (ஏற்கெனவே உள்ள கட்டமைப்பைத்
தொடாமல் இருக்கத் தனியான `CODEX_HOME`-ஐப் பயன்படுத்தவும்):

```toml
model = "gpt-5.5"                 # அடிப்படை ID — "codex/gpt-5.5" அல்ல
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # இறுதியில் slash வேண்டாம்; WS URL இதிலிருந்து பெறப்படும் (production-இல் https/wss பயன்படுத்தவும்)
wire_api = "responses"                    # Feb 2026 முதல் ஆதரிக்கப்படும் ஒரே மதிப்பு
supports_websockets = true                # Responses-over-WS transport-ஐச் செயல்படுத்துகிறது
env_key = "OMNIROUTE_API_KEY"             # OmniRoute API விசையை வைத்திருக்கும் (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # ஒரு OmniRoute API விசை (REQUIRE_API_KEY=false எனில் எந்த விசையும்)
codex exec "Responda apenas: PONG"
```

CLI, `base_url + /responses`-ஐ WebSocket ஆக upgrade செய்கிறது; OmniRoute அதைத்
தேர்ந்தெடுக்கப்பட்ட codex OAuth இணைப்புக்குச் சுரங்கப்படுத்துகிறது. உள்ளூர்
server-க்கு எதிராக முழுமையாகச் சரிபார்க்கப்பட்டது: ChatGPT `codex.rate_limits` + `response.created`-ஐ வழங்கி,
completion-ஐ stream செய்கிறது.

## சுயசேவைப் பயன்பாடு (`/api/usage/om-usage`)

எந்த API விசையும் **தனது சொந்த** பயன்பாட்டையும் ஒதுக்கீடுகளையும் படிக்கலாம் — நிர்வாக அங்கீகாரம் தேவையில்லை. ஒரு
விசை வைத்திருப்பவருக்கு அவருடைய செலவைக் காட்டுவதற்காக ஒரு கிளையன்ட் (CLI, OmniCopilot பேனல்) பயன்படுத்தும் முனைப்புள்ளி இதுவாகும்.

```bash
# உரை வடிவம் (வரலாற்று ஒப்பந்தம் — terminal-க்கான எளிய உரை)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# கட்டமைக்கப்பட்ட வடிவம் — UI பயன்படுத்துவது
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

விசையில் **`allowUsageCommand`** இயக்கப்பட்டிருக்க வேண்டும் (இயல்பாக முடக்கப்பட்டிருக்கும் — dashboard-இன் API-விசை
மேலாளர் ஒவ்வொரு விசைக்கும் இதை மாற்றியமைக்கிறார்). இது இல்லாமல் முனைப்புள்ளி `403` எனப் பதிலளிக்கும்.

`?format=json` ஒரு வேறுபடுத்தப்பட்ட வடிவமைப்பைத் திருப்பித் தருவதால், அழைப்பவர் மறுப்பு நிலையிலிருந்து தரவுப் புலத்தை ஒருபோதும்
படிக்கமாட்டார். வெற்றியின்போது:

```jsonc
{
  "allowed": true,
  // ஒவ்வொரு விசைக்குமான பயன்பாட்டு வரம்புகளை (தினசரி/வாராந்திர USD) விசை ஏற்றுக்கொண்டிருந்தால் மட்டுமே இருக்கும்:
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // தேர்ந்தெடுக்கப்பட்ட வழங்குநரின் ஒதுக்கீட்டு நிலைப்படம், அல்லது இதுவரை எதுவும் cache செய்யப்படவில்லை எனில் null:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // ஒவ்வொரு இணைப்பின் நிலைப்படமும்; இதனால் UI பல வழங்குநர்களை அருகருகே காட்ட முடியும்:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

மறுக்கப்படும்போது (`401` தவறான விசை / `403` அனுமதிக்கப்படவில்லை), அதே வழித்தடம்
`{ "allowed": false, "error": { "message": "…" } }` என்பதைத் திருப்பித் தரும் — உள்ளதாயினும் காலியாக இருக்கும் `personal`/`provider`
(விசை அனுமதிக்கப்பட்டுள்ளது, ஆனால் இதுவரை எதுவும் அறியப்படவில்லை) என்பது மறுப்பிலிருந்து வேறுபட்ட நிலையாகும்; JSON வடிவம்
மட்டுமே இவற்றை வேறுபடுத்திக் காட்டுகிறது.

**அங்கீகாரம்:** அழைப்பவரின் சொந்த Bearer API விசை, `isValidApiKey` மூலம் சரிபார்க்கப்படுகிறது — இது
`requireManagementAuth`-க்குப் பின்னால் தொடர்ந்து இருக்கும் நிர்வாக இடைமுகம் (`/api/keys/…`) _அல்ல_.

### மூல ஒதுக்கீட்டு சதவீதங்கள் மற்றும் வெட்டு வரம்புக்கேற்பச் சரிசெய்யப்பட்ட ஒதுக்கீட்டு சதவீதங்கள்

`/api/usage/om-usage`-ஐப் பயன்படுத்தும்போது, **எளிய உரை வெளியீடு** மற்றும் கட்டமைக்கப்பட்ட **JSON வெளியீடு**
வழங்கும் சதவீதங்களுக்கு இடையிலான வேறுபாட்டை அழைப்பவர்கள் கவனத்தில் கொள்ள வேண்டும்:

| அம்சம்                 | எளிய உரை வடிவம் (`/api/usage/om-usage` / `@@om-usage`)                                                        | JSON வடிவம் (`?format=json`)                                                                   |
| :--------------------- | :------------------------------------------------------------------------------------------------------------ | :--------------------------------------------------------------------------------------------- |
| **வெளியீட்டுப் புலம்** | `NN% left` (எ.கா., `20% left`)                                                                                | `provider.quotas` / `providers[].quotas`                                                       |
| **அளவீடு**             | **வெட்டு வரம்புக்கேற்பச் சரிசெய்யப்பட்ட பயன்படுத்தக்கூடிய அளவு**: வெட்டு வரம்புக்கு மேலுள்ள மீதமுள்ள கொள்ளளவு | **மூல upstream ஒதுக்கீடு**: சரிசெய்யப்படாத வழங்குநர் அளவீடு                                    |
| **வெட்டு அளவிடல்**     | `effectiveRemainingPercent()` மூலம் அளவிடப்படுவதால் பாதுகாக்கப்பட்ட இருப்பு `0% left` எனக் காட்டப்படும்       | இல்லை (வழங்குநர் அறிக்கையிட்டபடியான மூல நிலைப்பட மதிப்புகள்)                                   |
| **வரம்புத் தரவு**      | காட்டப்படும் சதவீதத்தில் சேர்க்கப்பட்டுள்ளது                                                                  | ஒவ்வொரு இணைப்பிற்கும் `quotaWindowThresholds`-இல் சேமிக்கப்படும் (அல்லது சேவையக இயல்புநிலைகள்) |
| **முதன்மைப் பயனர்**    | ஊடாடும் CLI-கள், terminal prompt-கள், மனித இயக்குநர்கள்                                                       | நிரலாக்க ஒருங்கிணைப்புகள், dashboard-கள், பகுப்பாய்வு, பில்லிங் கண்காணிப்பான்கள்               |

#### வெட்டு வரம்புச் சரிசெய்தல் சூத்திரம்

Upstream தீர்ந்துபோவதைத் தடுக்க OmniRoute முன்கூட்டிய ஒதுக்கீட்டு வெட்டு வரம்புகளை ஆதரிக்கிறது (இணைப்பின்
`quotaWindowThresholds`, வழங்குநரின் இயல்புநிலைகள் அல்லது உலகளாவிய மீள்திறன் அமைப்புகள் மூலம் கட்டமைக்கப்படுகிறது). ஒரு ஒதுக்கீட்டுச் சாளரத்தில்
வெட்டு வரம்பு (எ.கா., `cutoff = 25%`) செயலில் இருக்கும்போது, உரை வழங்கி மீதமுள்ள அளவைப் பின்வருமாறு கணக்கிடுகிறது:

- `remaining <= cutoff` எனில்: `0%` என்பதைத் திருப்பித் தரும்.
- `remaining > cutoff` எனில்: `((remaining - cutoff) / (100 - cutoff)) * 100` என்பதைத் திருப்பித் தரும்.

வடிவமைக்கப்பட்ட உரை வெளியீடு இதை அருகிலுள்ள முழு எண்ணாகச் சுற்றுகிறது (`Math.round(...)`).

#### விளக்க எடுத்துக்காட்டு

**60% மூலப் பயன்பாடு** (எனவே **40% மூல மீதமுள்ள ஒதுக்கீடு**) கொண்ட வழங்குநர் சாளரத்தையும், கட்டமைக்கப்பட்ட
**25% மீதமுள்ள-ஒதுக்கீட்டு வெட்டு** வரம்பையும் எடுத்துக்கொள்வோம்:

| பிரதிநிதித்துவம்              | கணக்கீடு                                           | மீதமுள்ளது |        மறைமுகமாகப் பயன்படுத்தப்பட்டது         |
| :---------------------------- | :------------------------------------------------- | :--------: | :-------------------------------------------: |
| **மூல JSON (`?format=json`)** | Upstream நிலைப்படம் (`quotas[window]`)             |  **40%**   |                    **60%**                    |
| **உரை வடிவம் (`NN% left`)**   | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` |  **20%**   | **80%** (`100 - remaining` எனக் கணக்கிட்டால்) |

- **உரை ஏன் 20% மீதமுள்ளதாகக் காட்டுகிறது:** கணக்கில் எஞ்சியுள்ள 40% இயற்பொருள் ஒதுக்கீட்டில், 25% வெட்டு
  கொள்கையால் ஒதுக்கி வைக்கப்பட்டுள்ளது. இந்த இணைப்பிற்கு router வழிச்செலுத்துவதை நிறுத்துவதற்கு முன், பயன்படுத்தக்கூடிய 75%-இல்
  அழைப்பவருக்கு 15% இடவசதி மட்டுமே மீதமுள்ளது. வழிச்செலுத்தல் நிறுத்தப்படும் சரியான தருணத்தில் இணைப்பு தீர்ந்துவிட்டதாக
  (`0% left`) குறிப்பதை அளவிடல் உறுதிசெய்கிறது.
- **JSON ஏன் மூல மதிப்புகளைப் பாதுகாக்கிறது:** JSON payload துல்லியமான வழங்குநர் நிலைப்படத்தை (`UsageSnapshot`)
  திருப்பித் தருவதால், வெளிப்புறக் கருவிகள் உண்மையான upstream பயன்பாடு மற்றும் இணைப்பு-நிலை
  `quotaWindowThresholds` ஆகியவற்றைச் சேவையகப் பக்க இழப்புடைய அளவிடல் இல்லாமல் அணுக முடியும்.

#### பயனர்களுக்கான இடம்பெயர்வு வழிகாட்டுதல்

ஒரு வெளிப்புற ஒருங்கிணைப்பு (எடிட்டர் செருகுநிரல் அல்லது முகவர் நீட்டிப்பு போன்றது) முன்பு உரை
முனைப்புள்ளியை (`NN% left`) ஸ்கிரேப் செய்து, பயன்படுத்தப்பட்ட சதவீதத்தை `100 - NN` எனக் கணக்கிட்டிருந்தால், `?format=json`-க்கு இடம்பெயர்வதன் பொருள்:

- மூல JSON மதிப்புகளைப் படிப்பது **மேல்நிலை மூலத்தின் உண்மையான பயன்பாட்டைப்** பிரதிபலிக்கும் (மேலே உள்ள எடுத்துக்காட்டில் 60% பயன்படுத்தப்பட்டுள்ளது).
- உரை முனைப்புள்ளியின் பயன்படுத்தக்கூடிய ஒதுக்கீட்டு அர்த்தத்தை ஒருங்கிணைப்பு தொடர்ந்து பாதுகாக்க விரும்பினால், இணைப்பு-நிலை மேலெழுதல்களுக்கான `quotaWindowThresholds`-ஐப் பயன்படுத்தி,
  நடைமுறையிலுள்ள மீதமுள்ள அளவுக்கான சூத்திரத்தை கிளையன்ட் பக்கத்தில் மதிப்பிடலாம்.

## சொற்பொருள் கேச்

```bash
# கேச் புள்ளிவிவரங்களைப் பெறுதல்
GET /api/cache/stats

# அனைத்து கேச்களையும் அழித்தல்
DELETE /api/cache/stats
```

பதில் எடுத்துக்காட்டு:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### தாமதத்தின் தாக்கம்

சொற்பொருள் கேச் HIT ஆனது **அப்ஸ்ட்ரீம் அழைப்பு இல்லாமல்** கேச்சிலிருந்து பதிலை வழங்கும்,
எனவே அறிக்கையிடப்படும் `X-OmniRoute-Response-Latency` ஏறக்குறைய பூஜ்ஜியமாக இருக்கும்
(அசல் அப்ஸ்ட்ரீம் தாமதத்தைப் பொருட்படுத்தாமல்). தாமதத்திற்கு உணர்திறன் கொண்ட கிளையன்ட்கள்
(பெஞ்ச்மார்க்கிங், p50/p99 கண்காணிப்பு) `X-OmniRoute-Cache-Latency` பதில் தலைப்பைச்
சரிபார்க்க வேண்டும்:

| மதிப்பு     | பொருள்                                                                     |
| ----------- | -------------------------------------------------------------------------- |
| `synthetic` | கேச்சிலிருந்து பதில் வழங்கப்பட்டது; தாமதம் உண்மையான அப்ஸ்ட்ரீம் நேரம் அல்ல |
| _(இல்லை)_   | உண்மையான அப்ஸ்ட்ரீம் அழைப்பிலிருந்து வந்த பதில்                            |

### ஒவ்வொரு விசைக்குமான கேச் தவிர்ப்பு

API விசைகள் `cacheDefaultMode` வழியாக சொற்பொருள் கேச் வாசிப்புகளைத் தவிர்க்கலாம்:

| மதிப்பு  | செயல்பாடு                                                       |
| -------- | --------------------------------------------------------------- |
| `legacy` | இயல்பான கேச் செயல்பாடு (முன்னிருப்பு)                           |
| `bypass` | கேச் தேடலை முழுமையாகத் தவிர்த்து, எப்போதும் அப்ஸ்ட்ரீமை அணுகும் |

விசை உருவாக்கத்தின்போது (`POST /api/keys`) அமைக்கவும் அல்லது புதுப்பிக்கவும் (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### ஒவ்வொரு கோரிக்கைக்குமான தவிர்ப்பு

விசை அமைப்புகளைப் பொருட்படுத்தாமல் எந்தக் கோரிக்கையும் கேச்சைத் தவிர்க்கலாம்:

```
X-OmniRoute-No-Cache: true
```

## டாஷ்போர்டு & மேலாண்மை

மேலாண்மை வழித்தடங்கள் (`/api/*`, பொது auth/login தவிர) சாதாரண இன்ஃபரன்ஸ் API
விசைகளால் அங்கீகரிக்கப்படுவதில்லை. நற்சான்றுக் குடும்பங்கள், ஸ்கோப்புகள் மற்றும் curl எடுத்துக்காட்டுகள்:

ஒத்திசைக்கப்பட்ட/இறக்குமதி செய்யப்பட்ட மாதிரிகளுக்கு, `PUT /api/provider-models` ஆனது `provider`, `modelId`, மற்றும்
`maxOutputTokenOverride` ஆகியவற்றை ஏற்கிறது: ஒரு நேர்மறை முழு எண் கைமுறை வெளியீட்டு-token வரம்பை அமைக்கும், மேலும் `null`
அதை அழித்து இயல்புநிலையை மீட்டமைக்கும். `GET /api/provider-models?provider=<provider>` ஆனது தனிப்பயன்-மாதிரி வரிசை இல்லாத
மாதிரிகளையும் உள்ளடக்கி, இந்த மதிப்புகளை `modelOutputOverrides` என்பதில் வழங்குகிறது. இந்த மேலெழுதல் இயக்கநேர
`max_output_tokens` திறனைப் பயன்படுத்துவதுடன், மாதிரி மீண்டும் ஒத்திசைக்கப்பட்ட பின்னரும் நீடிக்கிறது. OpenAI-இணக்கமான
வழங்குநர் பக்கம் இதே திருத்துதல்/அழித்தல் கட்டுப்பாடுகளை வழங்குவதோடு, வெளிப்படையான பார்வை ஆதரவுள்ள மாதிரிகளைக் குறிக்கிறது.

தனிப்பயன் Chat Completions கணுக்கள் வெளிப்படையான பகுத்தறிவு விலக்குகளை மேல்நிலைப் பின்தளத்திற்கு ஏற்ப மாற்றுகின்றன.
வெற்றிகரமான இணைப்புச் சோதனை, `/models` பதிவில் அங்கீகரிக்கப்பட்ட `owned_by` மதிப்பான `vllm`, `sglang`, அல்லது `llamacpp`
இருப்பது உறுதிப்படுத்தப்பட்ட ஒவ்வொரு துல்லியமான மாதிரி ID-க்கும் chat-template கட்டுப்பாடுகளைத் தானாகத் தேர்ந்தெடுக்கிறது.
வெளிப்படையான OpenAI-இணக்கமான wrappers, அசல் மாதிரிப் பதிவை உள்ளமைந்த `openai` பொருளுக்குள் தக்கவைக்கக்கூடும்;
கண்டறிதல் அத்தகைய மூன்று உறைகள் வரை பின்தொடரும். உரிமைத் தகவல் விடுபட்ட, அறியப்படாத, அல்லது முரண்பட்ட மாதிரிகள்
வழக்கமான OpenAI நடத்தையையே தக்கவைக்கும். கண்டறிதல் ஏற்கெனவே உள்ள catalog கோரிக்கையை மீண்டும் பயன்படுத்துகிறது,
completion token எதையும் உருவாக்காது, மேலும் இணைப்பு இறுதிப்புள்ளி மாறும்போது செல்லாததாக்கப்படுகிறது.

அந்த metadata-வை வெளிப்படுத்தாத ஒரு பின்தளத்திற்கான நடத்தையை நிலைநிறுத்த, ஏற்கெனவே உள்ள பகுதியளவு
வழங்குநர் புதுப்பிப்பு API-ஐப் பயன்படுத்தவும்:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

அந்த body-ஐ `PUT /api/providers/<connection-id>` உடன் அனுப்பவும். அந்த இணைப்பில், `none` என்ற வெளிப்படையான
பகுத்தறிவு முயற்சி `chat_template_kwargs.thinking=false` மற்றும்
`chat_template_kwargs.enable_thinking=false` ஆக அனுப்பப்படுகிறது. சேவையகப் பக்க பகுத்தறிவு விதி ஒன்று
முயற்சியைக் கட்டாயப்படுத்தாத வரை, வெளிப்படையான native template மதிப்புகளே அதிகாரப்பூர்வமானவை.
ஒரு தனிப்பயன் OpenAI-இணக்கமான இணைப்பு Chat Completions body-ஐ அனுப்பும்போது மட்டுமே இந்த அமைப்பு பொருந்தும்;
Responses கோரிக்கைகளும் வழக்கமான வழங்குநர்களும் தங்களின் native கோரிக்கை வடிவத்தைத் தக்கவைக்கும்.
வழக்கமான OpenAI `reasoning_effort` நேரடி அனுப்பலைக் கட்டாயப்படுத்த `reasoningControl` என்பதை `openai` ஆக
அமைக்கவும்; அல்லது தானியங்குக் கண்டறிதலைப் பயன்படுத்த அதைத் தவிர்க்கவும்/`null` ஆக அமைக்கவும்.

Claude Code தானியங்கு-முறை classifier கோரிக்கைகளில் வெளிப்படையான பகுத்தறிவுக் கட்டுப்பாடுகள் எதுவும் இல்லாதபோது,
native thinking இயல்புநிலையாக முடக்கப்படும். கண்டறிதல் மாதிரிப் பெயர்களையோ completion வரம்புகளையோ அல்லாமல்,
Claude-வடிவக் கோரிக்கைகளில் உள்ள classifier-இன் system marker-ஐப் பயன்படுத்துகிறது. வெளிப்படையான body கட்டுப்பாடுகள்,
ஆதரிக்கப்படும் effort/thinking headers, வழிப்படுத்தல் விதிகள், மற்றும் தீர்மானிக்கப்பட்ட மாதிரி முயற்சி ஆகியவை
தற்போதுள்ள முன்னுரிமையைத் தக்கவைத்துக்கொள்கின்றன. இரு classifier கட்டங்களும் தங்களின் prompts, completion வரம்புகள்,
stop sequences, மற்றும் உண்மையான மேல்நிலை அனுமதித் தீர்ப்புகளைத் தக்கவைக்கின்றன; இரண்டாவது கட்டத்தால் இன்னும் அது
கோரிய காணக்கூடிய பகுத்தறிவை வழக்கமான உரையாக உருவாக்க முடியும்.

### API விசை அனுமதிகள்

காப்புப்பிரதிக்குப் பிறகும் நடைபெறும் தானியங்கித் துப்புரவை நிர்ணயிக்கின்றன) ஆகியவையும் அவ்வாறே
செயல்படும். பட்டியலிடுதல் (`GET`) மற்றும் கைமுறை காப்புப்பிரதியை உருவாக்குதல் (`PUT`) ஆகியவை

### பதிப்பு மற்றும் வெளியீட்டுச் சேனல்

```bash
GET /api/system/version
```

லூப்பேக்கில் மட்டும் அணுகக்கூடிய மேலாண்மை வழித்தடம் (நிர்வாக அங்கீகாரம்). இயங்கிக்கொண்டிருக்கும் பதிப்பு, சமீபத்தில்
வெளியிடப்பட்ட பதிப்பு மற்றும் தானியங்கு புதுப்பிப்பு நிலையைத் திருப்பித் தருகிறது. `releaseChannel` மற்றும் `channels` ஆகியவை கூடுதலாகச்
சேர்க்கப்பட்ட புலங்கள் (rail 3.8.54); `channel` அதன் பொருளைத் தக்கவைத்துக்கொள்கிறது — டாஷ்போர்டு புதுப்பிப்பான்
பயன்படுத்தும் வரிசைப்படுத்தல் முறை (`npm`, `source` அல்லது `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — இயங்கும் பில்டின் npm சேனல்: `-nightly.*` பதிப்புகளுக்கு `nightly`,
  மற்ற முன்-வெளியீடுகளுக்கு (`-rc.*`, `-beta.*`, `-alpha.*`) `next`, `channels.latest`-ஐ விடப் பழைய முதன்மைப் பதிப்பின்
  நிலையான பதிப்புக்கு `lts`, இல்லையெனில் `latest`. வெளியீட்டு நேரத்தில் npm dist-tag-ஐத் தேர்ந்தெடுக்கும்
  `scripts/release/dist-tag.mjs`-இன் அதே விதிகள்.
- `channels` — `npm view omniroute dist-tags`-இலிருந்து (பதிவக
  HTTP மாற்றுவழி) பெறப்படும் ஒவ்வொரு dist-tag-இன் வெளியிடப்பட்ட சமீபத்திய பதிப்பு; `latest`-ஐப் போலவே அதே 10 நிமிட TTL உடன் தற்காலிகமாகச் சேமிக்கப்படுகிறது. `latest` எப்போதும் இருக்கும்
  (முதலில் `latest` புலத்திற்கும், பின்னர் `"unavailable"`-க்கும் மாற்றுவழியாகச் செல்லும்); அந்த dist-tag இருக்கும்போது மட்டுமே `next`, `nightly` மற்றும் `lts`
  தோன்றும். `Cache-Control: no-cache` கோரிக்கை இரண்டு தேடல்களையும் புதுப்பிக்கும்.

சேனல் மாதிரி (`latest` = 4.0 GA வரை v3, `next` = rc, `nightly` = `develop` பில்ட்கள்,
`lts` = 4.0 GA-க்குப் பிறகான v3 திருத்தங்கள்) `docs/ops/RELEASE_STRATEGY.md`-இல் விவரிக்கப்பட்டுள்ளது.

உள்ளமைக்கப்பட்டுள்ள எந்தவொரு STT வழங்குநரையும் பயன்படுத்தி ஆடியோ கோப்புகளை உரையாக மாற்றவும். முதல் பாதைப்
பகுதி நேரடி வழங்குநரைத் தேர்ந்தெடுக்கிறது (`openai/…`, `deepgram/…`). மற்றொரு விற்பனையாளரின் மாதிரியை
மறுஏற்றுமதி செய்யும் நுழைவாயில்கள் தகுதிப்படுத்தப்பட்ட அடையாளத்தைப் பயன்படுத்துகின்றன
(`openrouter/deepgram/nova-3`).

**கோரிக்கை:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**பதில்:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**எடுத்துக்காட்டு மாதிரி அடையாளங்கள்:** `openai/whisper-1` (OpenAI விசை தேவை),
`openrouter/deepgram/nova-3` (OpenRouter விசை தேவை),
`deepgram/nova-3` (நேரடி Deepgram விசை தேவை). வெறும்
`deepgram/nova-3` கோரிக்கை OpenRouter-ஐப் பயன்படுத்தாது.

**ஆதரிக்கப்படும் வடிவங்கள்:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`.

## டோக்கன் சேர்க்கப்பட்ட VS Code / தலைப்பில்லா மாற்றுப்பெயர்கள்

ஒரு ஒருங்கிணைப்பால் `Authorization` தலைப்பைச் சேர்க்க முடியாதபோதும், API விசையை அடிப்படை URL-இல் உட்பொதிக்க வேண்டியிருக்கும்போதும் இந்த மாற்றுப்பெயர்களைப் பயன்படுத்தவும்.

```bash
# OpenAI-பாணி பட்டியல் மாற்றுப்பெயர்
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# OpenAI-பாணி அரட்டை மாற்றுப்பெயர்கள்
POST /api/v1/vscode/{token}/chat/completions
POST /api/v1/vscode/{token}/responses

# Ollama-பாணி மாற்றுப்பெயர்கள்
POST /api/v1/vscode/{token}/api/chat
GET /api/v1/vscode/{token}/api/tags
```

எடுத்துக்காட்டு:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'
```

குறிப்புகள்:

- டோக்கன் சேர்க்கப்பட்ட மாற்றுப்பெயர்கள் `/v1/*` மற்றும் `/api/tags` ஆகியவற்றின் அதே கையாளிகளை மீண்டும் பயன்படுத்துகின்றன; பதில் வடிவங்கள் மாறாமல் இருக்கும்.
- கிளையன்ட் தனிப்பயன் தலைப்புகளை ஆதரிக்கும்போதெல்லாம் `Authorization: Bearer ...` என்பதைப் பயன்படுத்துவது சிறந்தது.
- URL அடிப்படையிலான டோக்கன்கள், OmniRoute-க்கு வெளியேயுள்ள எதிர்மறை-பதிலி பதிவுகள், உலாவி வரலாறு மற்றும் தொலைஅளவீட்டுத் தரவுகளில் தோன்றக்கூடும். அவற்றை இயல்புநிலை அங்கீகார முறையாக அல்லாமல், இணக்கத்தன்மைக்கான ஒரு விருப்பமாகக் கருதவும்.

## செலவுத்திட்டம்

```bash
# அனைத்து API விசைகளுக்குமான செலவுத்திட்ட நிலையைப் பெறவும்
GET /api/usage/budget

# செலவுத்திட்டத்தை அமைக்கவும் அல்லது புதுப்பிக்கவும்
POST /api/usage/budget
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "dailyLimitUsd": 5.00,
  "weeklyLimitUsd": 30.00,
  "monthlyLimitUsd": 100.00,
  "warningThreshold": 0.8,
  "resetInterval": "monthly"
}
```

> **திட்டவடிவக் குறிப்புகள்** (`setBudgetSchema`): `apiKeyId` கட்டாயமானது; `dailyLimitUsd`, `weeklyLimitUsd` அல்லது `monthlyLimitUsd` ஆகியவற்றில் குறைந்தது ஒன்று பூஜ்ஜியத்தைவிட அதிகமாக இருக்க வேண்டும். விருப்பப் புலங்கள்: `warningThreshold` (0–1), `resetInterval` (`daily` | `weekly` | `monthly`), `resetTime` (`HH:MM`). மரபுவழி `{keyId, limit, period}` வடிவம் `400 Bad Request` என்பதைத் திருப்பியனுப்பும்.

## டோக்கன் வரம்புகள்

ஒவ்வொரு API விசைக்கும் தனித்தனியான **டோக்கன்** ஒதுக்கீடுகள் (மேலே உள்ள USD-அடிப்படையிலான பட்ஜெட்டிலிருந்து வேறுபட்டவை). கோரிக்கை பாதையிலேயே அமல்படுத்தப்படும்: ஒரு விசையின் தற்போதைய சாளரப் பயன்பாடு அதன் வரம்பை அடையும்போது, கோரிக்கைகள் `429 Too Many Requests` உடன் நிராகரிக்கப்படும். வரம்புகளை ஒரு குறிப்பிட்ட `model`, ஒரு `provider` ஆகியவற்றிற்கானதாக வரையறுக்கலாம் அல்லது விசை முழுவதும் `global` ஆகப் பயன்படுத்தலாம்; ஒரு கோரிக்கைக்குப் பல வரம்புகள் பொருந்தும்போது, மிகவும் கட்டுப்பாடான வரம்பே செயல்படுத்தப்படும்.

```bash
# ஒரு விசையின் டோக்கன் வரம்புகளைப் பட்டியலிடவும் (நேரடி சாளரப் பயன்பாடு உட்பட)
GET /api/usage/token-limits?apiKeyId=key-123

# ஒரு டோக்கன் வரம்பை உருவாக்கவும் அல்லது புதுப்பிக்கவும்
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# ID மூலம் ஒரு டோக்கன் வரம்பை நீக்கவும்
DELETE /api/usage/token-limits?id=tl-abc
```

> **திட்டவடிவக் குறிப்புகள்** (`setTokenLimitSchema`): `apiKeyId` மற்றும் `scopeType` (`model` | `provider` | `global`) அவசியம். `scopeType` என்பது `global` ஆக இல்லாவிட்டால் `scopeValue` அவசியம் (எ.கா., `model` வரம்பிற்கான மாதிரி ID, `provider` வரம்பிற்கான வழங்குநர் ID). `tokenLimit` ஒரு நேர்மறை முழு எண்ணாக இருக்க வேண்டும் (சரத்திலிருந்து மாற்றப்படும்). விருப்பத்திற்குரியவை: `id` (உருவாக்குவதற்குத் தவிர்க்கவும், புதுப்பிப்பதற்கு வழங்கவும்), `resetInterval` (`daily` | `weekly` | `monthly`, இயல்புநிலை `monthly`), `resetTime` (`HH:MM`), `enabled` (இயல்புநிலை `true`). `GET` பதில்கள் ஒவ்வொரு வரம்பையும் `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, மற்றும் `nextResetAt` ஆகியவற்றுடன் செறிவூட்டுகின்றன. இது மேலாண்மை-வகுப்பு முனைப்புள்ளி (அங்கீகாரம் authz பைப்லைனால் மையமாக அமல்படுத்தப்படுகிறது).

## கோரிக்கை செயலாக்கம்

1. கிளையன்ட் `/v1/*` க்குக் கோரிக்கையை அனுப்புகிறது
2. வழித்தடக் கையாளுநர் `handleChat`, `handleEmbedding`, `handleAudioTranscription`, அல்லது `handleImageGeneration` ஐ அழைக்கிறது
3. மாதிரி தீர்மானிக்கப்படுகிறது (நேரடி வழங்குநர்/மாதிரி அல்லது மாற்றுப்பெயர்/காம்போ)
4. கணக்குக் கிடைப்புத்தன்மை வடிகட்டலுடன் உள்ளூர் DB-யிலிருந்து நற்சான்றுகள் தேர்ந்தெடுக்கப்படுகின்றன
5. அரட்டைக்காக: `handleChatCore` சொற்பொருள்/கையொப்ப கேஷைச் சரிபார்த்து, காம்போ சுருக்க அமைப்புகளைத் தீர்மானிக்கிறது
6. செயல்படுத்தப்பட்டிருக்கும்போது, வழங்குநர் மொழிபெயர்ப்புக்கு முன் முன்கூட்டிய சுருக்கம் இயங்குகிறது (`lite`, Caveman, RTK, அல்லது அடுக்கப்பட்டவை)
7. வழங்குநர் செயலாக்கி அப்ஸ்ட்ரீம் கோரிக்கையை அனுப்புகிறது
8. பதில் மீண்டும் கிளையன்ட் வடிவமைப்பிற்கு மொழிபெயர்க்கப்படுகிறது (அரட்டை) அல்லது உள்ளபடியே திருப்பி அனுப்பப்படுகிறது (உட்பொதிவுகள்/படங்கள்/ஆடியோ)
9. பயன்பாடு, சுருக்கப் பகுப்பாய்வு மற்றும் கோரிக்கைப் பதிவுகள் பதிவு செய்யப்படுகின்றன
10. காம்போ விதிகளின்படி பிழைகள் ஏற்படும்போது மாற்று வழி பயன்படுத்தப்படுகிறது

முழுமையான கட்டமைப்புக் குறிப்பு: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## காம்போ மேலாண்மை

உயர்-நிலை வழிச்செலுத்தல் காம்போக்களை (`/api/combos*` என்பதன் கீழ் ஏற்கனவே சுருக்கப்பட்டுள்ளவை) ஒரு மாதிரி ID வடிவத்திலிருந்து 1:1 ஆகவும் பொருத்தலாம்; இதனால் OpenAI-பாணி மாதிரி ID-ஐ ஒரு காம்போவிற்குத் தடையின்றித் திருப்பிவிட முடியும்.

| முறை   | பாதை                             | விளக்கம்                                                                                 |
| ------ | -------------------------------- | ---------------------------------------------------------------------------------------- |
| GET    | `/api/model-combo-mappings`      | அனைத்து மாதிரி→காம்போ பொருத்தங்களையும் பட்டியலிடவும்                                     |
| POST   | `/api/model-combo-mappings`      | பொருத்தத்தை உருவாக்கவும் — உடல்: `{pattern, comboId, priority?, enabled?, description?}` |
| GET    | `/api/model-combo-mappings/[id]` | ஒரு தனிப்பட்ட பொருத்தத்தைப் பெறவும்                                                      |
| PUT    | `/api/model-combo-mappings/[id]` | ஏற்கனவே உள்ள பொருத்தத்தின் புலங்களைப் புதுப்பிக்கவும்                                    |
| DELETE | `/api/model-combo-mappings/[id]` | ஒரு பொருத்தத்தை அகற்றவும்                                                                |

**அங்கீகாரம்:** மேலாண்மை அமர்வு/API விசை (`requireManagementAuth`).

## Webhooks

OmniRoute நிகழ்வுகளுக்கான வெளிச்செல்லும் webhook சந்தாக்கள் (கோரிக்கை நிறைவு, ஒதுக்கீடு தீர்ந்துபோதல், சாவி சுழற்சி போன்றவை).

| முறை   | பாதை                      | விளக்கம்                                                                     |
| ------ | ------------------------- | ---------------------------------------------------------------------------- |
| GET    | `/api/webhooks`           | Webhook-களைப் பட்டியலிடும் (ரகசியங்கள் `<prefix>...` என மறைக்கப்படும்)       |
| POST   | `/api/webhooks`           | Webhook-ஐ உருவாக்கும் — body: `{url, events?: ["*"], secret?, description?}` |
| GET    | `/api/webhooks/[id]`      | Webhook ஒன்றைப் பெறும்                                                       |
| PUT    | `/api/webhooks/[id]`      | url/events/secret/description ஆகியவற்றைப் புதுப்பிக்கும்                     |
| DELETE | `/api/webhooks/[id]`      | Webhook ஒன்றை அகற்றும்                                                       |
| POST   | `/api/webhooks/[id]/test` | Webhook URL-க்கு சோதனை payload ஒன்றை அனுப்பி, விநியோக நிலையைக் கொடுக்கும்    |

**அங்கீகாரம்:** மேலாண்மை அமர்வு/API சாவி (`requireManagementAuth`).

## பதிவுசெய்யப்பட்ட சாவிகள் (தானியங்கு மேலாண்மை)

தினசரி/மணிநேர ஒதுக்கீடுகளுடன், ஆதரவளிக்கும் வழங்குநர்/கணக்கில் API சாவிகளை வழங்கவும் சுழற்சி செய்யவும் தானியங்கு சாவி மேலாண்மை துணைஅமைப்பால் பயன்படுத்தப்படுகிறது.

| முறை   | பாதை                                  | விளக்கம்                                                                                                                                                                                                                       |
| ------ | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| GET    | `/api/v1/registered-keys`             | பதிவுசெய்யப்பட்ட சாவிகளைப் பட்டியலிடும் (மறைக்கப்பட்ட முன்னொட்டு மட்டும்)                                                                                                                                                      |
| POST   | `/api/v1/registered-keys`             | புதிய பதிவுசெய்யப்பட்ட சாவியை வழங்கும் — body: `{name, provider?, accountId?, idempotencyKey?, expiresAt?, dailyBudget?, hourlyBudget?}`. மூலச் சாவியை **ஒருமுறை** மட்டும் வழங்கும். ஒதுக்கீடு மறுக்கப்பட்டால் `429` வழங்கும். |
| GET    | `/api/v1/registered-keys/[id]`        | பதிவுசெய்யப்பட்ட சாவியின் metadata-ஐப் பெறும் (மூலப் பொருள் இல்லை)                                                                                                                                                             |
| DELETE | `/api/v1/registered-keys/[id]`        | பதிவுசெய்யப்பட்ட சாவியைத் திரும்பப்பெறும்                                                                                                                                                                                      |
| POST   | `/api/v1/registered-keys/[id]/revoke` | வெளிப்படையான திரும்பப்பெறுதல் endpoint (DELETE போன்ற அதே விளைவு)                                                                                                                                                               |

**அங்கீகாரம்:** மேலாண்மை அமர்வு/API சாவி (`requireManagementAuth`) — `/api/keys` பயன்படுத்தும் அதே பாதுகாப்புச் சோதனை: dashboard அமர்வு, உள்ளூர் CLI token அல்லது `manage`/`admin` scope கொண்ட API சாவி; inference-க்கு மட்டும் உரிய API சாவிகளுக்கு `403` கிடைக்கும். மேலும் `/v1/quotas/check` மற்றும் `/v1/issues/report` ஆகியவற்றையும் பார்க்கவும்.

## முகவர்கள் நெறிமுறை

OmniRoute பயனர்களின் சார்பில் தொலைநிலையில் செயல்படுத்தப்படும் கிளவுட் முகவர் பணிகள் (Claude Code, Codex Cloud, OpenHands போன்றவை).

| முறை   | பாதை                          | விளக்கம்                                                                                                                                                                   |
| ------ | ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/v1/agents/tasks`        | பணிகளைப் பட்டியலிடும் — விருப்பத்தேர்வாக `?provider=`, `?status=`, `?limit=` (1–500, இயல்புநிலை 50)                                                                        |
| POST   | `/api/v1/agents/tasks`        | பணியை உருவாக்கும் — கோரிக்கை உள்ளடக்கம் `CreateCloudAgentTaskSchema` மூலம் சரிபார்க்கப்படும் (`providerId`, `prompt`, `source`, `options?`). பணி உறையுடன் `201`-ஐ வழங்கும் |
| DELETE | `/api/v1/agents/tasks?id=...` | ஒரு பணியை நீக்கும்                                                                                                                                                         |
| GET    | `/api/v1/agents/tasks/[id]`   | பணியைப் படிக்கும் — `external_id` அமைக்கப்பட்டிருக்கும்போது மேல்நிலை கிளவுட் முகவரிடமிருந்து நிலையை ஒத்தியங்கும் முறையில் புதுப்பிக்கும்                                   |
| POST   | `/api/v1/agents/tasks/[id]`   | வேறுபடுத்தப்பட்ட செயல்: `{action: "approve"}`, `{action: "message", message}`, அல்லது `{action: "cancel"}`                                                                 |
| DELETE | `/api/v1/agents/tasks/[id]`   | id மூலம் குறிப்பிட்ட பணியை நீக்கும்                                                                                                                                        |

> **அங்கீகாரம்:** ஒவ்வொரு முறைக்கும் மேலாண்மை அங்கீகாரம் தேவை (`requireCloudAgentManagementAuth`). v3.8.0-க்கு முன்பு இவை அங்கீகரிக்கப்படாதவையாக இருந்தன — இணக்கமுறிவு மாற்றத்திற்கு `588a0333` commit-ஐப் பார்க்கவும்.

```bash
# Claude Code கிளவுட் பணியை உருவாக்கவும்
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Authorization: Bearer your-management-key" \
  -H "Content-Type: application/json" \
  -d '{"providerId":"claude-code-cloud","prompt":"Fix the failing test","source":{"repo":"...","branch":"..."}}'
```

## மீள்திறன் (விரிவாக்கப்பட்டது)

OmniRoute மூன்று தனித்தனி தற்காலிகத் தோல்வி வழிமுறைகளை வழங்குகிறது; கீழேயுள்ள மேலாண்மை முனைப்புள்ளிகள் அவற்றின் நிலையைப் படிக்கவும் மீறியமைக்கவும் நிர்வாகிகளை அனுமதிக்கின்றன:

| வரம்பு                       | நிலைச் சேமிப்பகம்                                | படித்தல்                                  | மீட்டமைத்தல் / அழித்தல்                                               |
| ---------------------------- | ------------------------------------------------ | ----------------------------------------- | --------------------------------------------------------------------- |
| வழங்குநர் பிரேக்கர்          | `domain_circuit_breakers` + நினைவகத்தில்         | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                          |
| இணைப்பு காத்திருப்புக் காலம் | வழங்குநர் இணைப்புகளில் `rateLimitedUntil`        | `/api/rate-limits`, `/api/providers/[id]` | (தேவையின்போது மீண்டும் இயக்கப்படும்; வழங்குநர் PUT வழியாக அழிக்கவும்) |
| மாதிரி பூட்டல்               | நினைவகத்திலுள்ள மாதிரி-கிடைப்புத்தன்மைப் பதிவகம் | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                              |

`PATCH /api/resilience` ஆனது `providerBreaker.oauth` மற்றும் `providerBreaker.apikey` ஆகியவற்றின் கீழ் வழங்குநர் பிரேக்கர் மீறியமைப்புகளை ஏற்கிறது. ஒவ்வொரு சுயவிவரமும் `degradationThreshold`, `failureThreshold`, மற்றும் `resetTimeoutMs` ஆகியவற்றை ஆதரிக்கிறது; இதே புலங்கள் கட்டுப்பாட்டுப் பலகை → அமைப்புகள் → மீள்திறன் என்பதிலும் கிடைக்கின்றன.

```bash
# ஒற்றை மாதிரிப் பூட்டலை அழிக்கவும்
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# அனைத்து பூட்டல்களையும் அழிக்கவும்
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

முழுமையான கருத்தியல் மேற்கோள் மற்றும் பிரேக்கரின் இயல்புநிலைகளுக்கு: [`CLAUDE.md`](../../CLAUDE.md) → "மீள்திறன் இயக்கநேர நிலை" மற்றும் [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) ஆகியவற்றைப் பார்க்கவும்.

### வீத-வரம்பு வரிசை & தானியக்க-இயக்கப் பாதுகாப்பு வலை

- **ஆதரிக்கப்படும் எழுதும் பாதை**: `{"connectionId": "<id>", "enabled": true|false}` உடலுடன் `POST /api/rate-limits` என்பது ஓர் இணைப்பிற்கான வீத-வரம்புப் பாதுகாப்பை மாற்றுவதற்கான ஆதரிக்கப்படும் மேலாண்மை முனைப்புள்ளியாகும். `PUT /api/providers/[id]` திட்டமிட்டே `rateLimitProtection`-ஐ மாற்றவோ நிலைமாற்றவோ செய்யாது (#11278).
- **`enabled: false` என்பதன் பொருள்**: `enabled: false` என அமைப்பது இணைப்பிற்கான வெளிப்படையான பாதுகாப்பை நீக்குகிறது, ஆனால் செயலில் உள்ள API-விசை இணைப்பை உலகளாவிய தானியக்க-இயக்கப் பாதுகாப்பு வலையிலிருந்து (`autoEnableApiKeyProviders = true`) **விலக்காது**. `reconcileEnabledConnections`-இல் (`open-sse/services/rateLimitManager.ts`), `false` மற்றும் `undefined` ஆகியவை சமமானவை; வெளிப்படையான பாதுகாப்பு இல்லாத செயலில் உள்ள API-விசை இணைப்புகள் தானியக்க-இயக்கப் பாதுகாப்பு வலையின் கீழ் தொடர்ந்து பாதுகாக்கப்படும்.
- **உலகளாவிய முடக்கம்**: வீத-வரம்பு வரிசைகள் இல்லாமல் API-விசை இணைப்புகளை இயக்க, `RATE_LIMIT_AUTO_ENABLE=false` (சூழல் மாறி) அல்லது `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (அமைப்புகள் → மீள்திறன் / `PATCH /api/resilience`) வழியாகப் பாதுகாப்பு வலையை உலகளவில் முடக்கவும்.

## MCP சேவையகம்

OmniRoute ஆனது 3 transports (stdio, SSE, streamable-http) மற்றும் வரம்பிடப்பட்ட கருவிகளுடன் உட்பொதிக்கப்பட்ட Model Context Protocol சேவையகத்தை வழங்குகிறது. கீழே உள்ள dashboard endpoints நிலை/audit தரவைப் படித்து HTTP transports-ஐ proxy செய்கின்றன.

| முறை | பாதை | விளக்கம் |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | Heartbeat, transport, online நிலை, கடைசி அழைப்பு, முன்னணி கருவிகள், 24h வெற்றி விகிதம் |
| GET | `/api/mcp/tools` | `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints` ஆகியவற்றுடன் MCP கருவிகளின் பட்டியல் |
| GET | `/api/mcp/sse` | SSE transport-க்காக SSE stream-ஐத் திறத்தல் (MCP முடக்கப்பட்டிருந்தாலோ transport பொருந்தாவிட்டாலோ `503`-ஐத் திருப்பும்) |
| POST | `/api/mcp/sse` | SSE transport-இல் JSON-RPC frame-ஐ அனுப்புதல் |
| GET | `/api/mcp/stream` | Streamable HTTP transport-இன் SSE பக்கத்தைத் திறத்தல் (சேவையகத்தால் தொடங்கப்படும் செய்திகள்) |
| POST | `/api/mcp/stream` | Streamable HTTP transport-இல் JSON-RPC frame-ஐ அனுப்புதல் |
| DELETE | `/api/mcp/stream` | Streamable HTTP session-ஐ முடித்தல் |
| GET | `/api/mcp/audit` | audit log-ஐ வினவுதல் — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | திரட்டப்பட்ட audit புள்ளிவிவரங்கள் (மொத்தங்கள், வெற்றி விகிதம், சராசரி கால அளவு, முன்னணி கருவிகள்) |

**அங்கீகாரம்:** `sse`/`stream` transports MCP-க்கான பிரத்யேக அங்கீகாரப் பரப்பை மதிக்கின்றன (`mcp` scope கொண்ட Bearer API key); `status`/`tools`/`audit*` routes dashboard-இலிருந்து படிக்கக்கூடியவை (dashboard host-ஐ அணுகுவதற்கு அப்பால் கூடுதல் அங்கீகாரம் தேவையில்லை).

> இரண்டு HTTP transports-உம் `settings.mcpEnabled` மற்றும் `settings.mcpTransport` ஆகியவற்றால் கட்டுப்படுத்தப்படுகின்றன — transport பொருத்தமின்மை `400`-ஐத் திருப்பும், MCP முடக்கப்பட்ட நிலை `503`-ஐத் திருப்பும்.

## A2A சேவையகம்

OmniRoute, A2A (Agent-to-Agent) JSON-RPC 2.0 முனைப்புள்ளியையும், ஆய்வு/டாஷ்போர்டு பயன்பாட்டிற்கான REST மேலுறையையும் வழங்குகிறது.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # OMNIROUTE_API_KEY அமைக்கப்பட்டிருந்தால் தவிர, விருப்பத்தேர்வு
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

ஆதரிக்கப்படும் முறைகள் (அனைத்தும் `settings.a2aEnabled` மூலம் கட்டுப்படுத்தப்படுகின்றன):

| முறை             | விளக்கம்                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------- |
| `message/send`   | ஒத்திசைவான திறன் செயல்படுத்தல்; `{task, artifacts, metadata}` என்பதைத் திருப்பியளிக்கும் |
| `message/stream` | அதே திறன் தொகுப்பின் ஸ்ட்ரீமிங் SSE செயல்படுத்தல்                                        |
| `tasks/get`      | `taskId` மூலம் ஒரு பணியைப் பெறும்                                                        |
| `tasks/cancel`   | `taskId` மூலம் ஒரு பணியை ரத்துசெய்யும்                                                   |

உள்ளமைக்கப்பட்ட திறன்கள்: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### முகவர் அட்டை

```bash
GET /.well-known/agent.json
```

பொது A2A முகவர் அட்டையை (பெயர், விளக்கம், திறன்கள், திறன் பட்டியல், அங்கீகாரத் திட்டம்) திருப்பியளிக்கும் — பொதுவாக 1h நேரத்திற்கு தற்காலிகச் சேமிப்பில் வைக்கப்படும். அங்கீகாரம் தேவையில்லை.

### REST உதவியாளர்கள்

| முறை | பாதை                         | விளக்கம்                                                                                                                   |
| ---- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| GET  | `/api/a2a/status`            | A2A இயக்கப்பட்ட நிலை + பணிப் புள்ளிவிவரங்கள் + தற்காலிகச் சேமிப்பிலுள்ள முகவர் அட்டைச் சுருக்கம்                           |
| GET  | `/api/a2a/tasks`             | பணிகளைப் பட்டியலிடும் — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST | `/api/a2a/tasks`             | (REST உதவியாளராகச் செயல்படுத்தப்படவில்லை — JSON-RPC `message/send` மூலம் உருவாக்கவும்)                                     |
| GET  | `/api/a2a/tasks/[id]`        | ஒரு பணியைப் பெறும்                                                                                                         |
| POST | `/api/a2a/tasks/[id]/cancel` | ஒரு பணியை ரத்துசெய்யும்                                                                                                    |

**அங்கீகாரம்:** REST உதவியாளர்கள் மேலாண்மை அங்கீகாரம் இல்லாமல் இயங்குகின்றன (டாஷ்போர்டில் படிக்கக்கூடியவை); JSON-RPC `/a2a` பாதை உள்ளமைக்கப்பட்டிருந்தால் Bearer `OMNIROUTE_API_KEY` விசையைப் பயன்படுத்தும்.

## ACP (Agent Client Protocol) மேலாண்மை

துணைச் செயல்முறைகளாக. இந்த endpoint-கள் ACP agent கண்டறிதல் மற்றும் தனிப்பயன் agent
பதிவை நிர்வகிக்கின்றன.

| முறை   | பாதை              | விளக்கம்                                                                                                                                                                              |
| ------ | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/acp/agents` | நிறுவல் நிலை, பதிப்பு, binary ஆகியவற்றுடன் அறியப்பட்ட அனைத்து CLI agent-களையும் (உள்ளமைந்தவை + தனிப்பயன்) பட்டியலிடுகிறது                                                             |
| POST   | `/api/acp/agents` | தனிப்பயன் ACP agent-ஐப் பதிவுசெய்கிறது அல்லது cache-ஐப் புதுப்பிக்கிறது — body: `{id, name, binary, versionCommand, providerAlias, spawnArgs, protocol}` அல்லது `{action: "refresh"}` |
| DELETE | `/api/acp/agents` | தனிப்பயன் ACP agent-ஐ அகற்றுகிறது — query அளவுரு: `?id=<agentId>`                                                                                                                     |

**பதில் எடுத்துக்காட்டு** (`GET /api/acp/agents`):

```json
{
  "agents": [
    {
      "id": "claude",
      "name": "Claude Code CLI",
      "binary": "claude",
      "version": "1.0.45",
      "installed": true,
      "protocol": "stdio",
      "providerAlias": "claude",
      "isCustom": false
    },
    {
      "id": "my-custom-cli",
      "name": "My Custom CLI",
      "installed": false,
      "protocol": "stdio",
      "providerAlias": "my-provider",
      "isCustom": true
    }
  ],
  "cacheTtlMs": 60000,
  "cacheAge": 1234
}
```

**அங்கீகாரம்:** மேலாண்மை அமர்வு (dashboard `auth_token` cookie) அல்லது
மேலாண்மை வரம்புடைய API key தேவை.

முழு விவரங்களுக்கு [ACP கட்டமைப்பு](../frameworks/ACP.md) என்பதைப் பார்க்கவும்.

## பகுப்பாய்வு & கண்காணிப்புத் திறன்

வழித்தடத் தேர்வு, சுருக்கம் மற்றும் provider பன்முகத்தன்மையைக் கண்காணிப்பதற்கான

### தானியங்கு வழித்தடப் பகுப்பாய்வு

## செருகுநிரல்கள்

OmniRoute செருகுநிரல்களை (மூன்றாம் தரப்பு நீட்டிப்புகள்) நிர்வகிக்கவும்.

| முறை   | பாதை                               | விளக்கம்                                  |
| ------ | ---------------------------------- | ----------------------------------------- |
| GET    | `/api/plugins`                     | நிறுவப்பட்ட செருகுநிரல்களைப் பட்டியலிடும் |
| POST   | `/api/plugins/marketplace/install` | சந்தையிலிருந்து ஒரு செருகுநிரலை நிறுவும்  |
| DELETE | `/api/plugins/[name]`              | ஒரு செருகுநிரலை நிறுவல் நீக்கும்          |
| POST   | `/api/plugins/[name]/activate`     | ஒரு செருகுநிரலைச் செயல்படுத்தும்          |
| POST   | `/api/plugins/[name]/deactivate`   | ஒரு செருகுநிரலைச் செயலிழக்கச் செய்யும்    |
| GET    | `/api/plugins/[name]/config`       | செருகுநிரல் உள்ளமைவைப் பெறும்             |
| PUT    | `/api/plugins/[name]/config`       | செருகுநிரல் உள்ளமைவைப் புதுப்பிக்கும்     |

**அங்கீகாரம்:** மேலாண்மை அமர்வு தேவை.

முழு விவரங்களுக்கு [செருகுநிரல்கள் கட்டமைப்பு](../frameworks/PLUGIN_SDK.md) என்பதைப் பார்க்கவும்.

## நிழல் வழித்தடம்

வழங்குநர்களின் நிழல் / A-B ஒப்பீடு என்பது **தனித்த REST மேற்பரப்பு அல்ல** — இது சேர்க்கை வழித்தடம் மூலம் உள்ளமைக்கப்படுகிறது ([தானியங்கு-சேர்க்கை](../routing/AUTO-COMBO.md) என்பதைப் பார்க்கவும்). ஒவ்வொரு சேர்க்கைக்குமான ஒப்பீட்டு அளவீடுகள் `GET /api/combos/metrics` மூலம் வழங்கப்படுகின்றன.

## பாதுகாப்புக் கட்டுப்பாடுகள்

இயக்கநேரப் பாதுகாப்புக் கட்டுப்பாடுகளை (PII கண்டறிதல், தூண்டுரை உட்செலுத்தல் கண்டறிதல், பார்வை இணைப்பு) ஆய்வு செய்யவும். ஒவ்வொரு கோரிக்கையிலும் பாதுகாப்புக் கட்டுப்பாடுகள் இயங்கும்; ஒவ்வொரு அழைப்புக்கும் விலகுவதற்கு `x-omniroute-disabled-guardrails` கோரிக்கைத் தலைப்பைப் பயன்படுத்தலாம் — நிலையாகச் சேமிக்கப்படும் இயக்குதல்/முடக்குதல் மேற்பரப்பு எதுவும் இல்லை.

| முறை | பாதை                   | விளக்கம்                                                                                                                       |
| ---- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| GET  | `/api/guardrails`      | பதிவுசெய்யப்பட்ட பாதுகாப்புக் கட்டுப்பாடுகளையும் அவற்றின் நிலையையும் பட்டியலிடும் (பெயர் / இயக்கப்பட்டது / முன்னுரிமை)         |
| POST | `/api/guardrails/test` | மாதிரி உள்ளீட்டின் மீது அழைப்புக்கு முந்தைய செயலாக்கத் தொடரை உலர்-இயக்கமாகச் சோதிக்கும் — உடல்: `{input, disabledGuardrails?}` |

**அங்கீகாரம்:** மேலாண்மை அமர்வு தேவை.

முழு விவரங்களுக்கு [பாதுகாப்பு > பாதுகாப்புக் கட்டுப்பாடுகள்](../security/GUARDRAILS.md) என்பதைப் பார்க்கவும்.

## அங்கீகாரம்

நான்கு நற்சான்றுக் குடும்பங்கள் (டாஷ்போர்டு அமர்வு, உள்ளக CLI டோக்கன், `oma_live_…` அணுகல் டோக்கன், மேலாண்மை வரம்புடைய API விசை) மற்றும் அவை அனுமான விசைகளிலிருந்து எவ்வாறு வேறுபடுகின்றன என்பதை அறிய [மேலாண்மை அங்கீகாரம்](../guides/MANAGEMENT-AUTH.md) என்பதைப் பார்க்கவும்.

- டாஷ்போர்டு வழித்தடங்கள் (`/dashboard/*`) `auth_token` குக்கீயைப் பயன்படுத்துகின்றன
- உள்நுழைவு சேமிக்கப்பட்ட கடவுச்சொல் ஹாஷைப் பயன்படுத்துகிறது; அது இல்லையெனில் `INITIAL_PASSWORD` பயன்படுத்தப்படும்
- `requireLogin`-ஐ `/api/settings/require-login` வழியாக மாற்றி அமைக்கலாம்
- `REQUIRE_API_KEY=true` என இருக்கும்போது `/v1/*` வழித்தடங்களுக்கு விருப்பத்தேர்வாக Bearer API விசை தேவைப்படும்
- இந்தக் குறிப்பில் உள்ள "மேலாண்மை டோக்கன்" / "மேலாண்மை வரம்புடைய API விசை" என்பது அந்த வழிகாட்டியில் உள்ள குடும்பங்களில் ஒன்றைக் குறிக்கிறது — வரையறுக்கப்படாத கூடுதல் ரகசிய வகையை அல்ல

> **முறிக்கும் மாற்றம் (v3.8.0)** — `/api/v1/agents/tasks/*` மற்றும் கூல்டவுன் மேலாண்மை முனைப்புள்ளிகள் இப்போது **மேலாண்மை அங்கீகாரத்தைக்** கோருகின்றன (டாஷ்போர்டு `auth_token` குக்கீ அல்லது மேலாண்மை வரம்புடைய API விசை). முன்பு அங்கீகாரம் இல்லாமல் இந்த வழித்தடங்களை அழைத்த கிளையண்டுகள் `401 Unauthorized` பதிலைப் பெறும். `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`) கமிட்டைப் பார்க்கவும்.
