> தேர்வு, முன்னிருப்பாக ஆஃப் (`modelVisibilityAllowlist`/`modelVisibilityDenylist` இரண்டும் காலியாக இருக்கும் `/v1/models` அட்டவணை AND ஒவ்வொரு `auto/*` வேட்பாளர் பூல் பைட்-ஒத்த மாதிரி). `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`) இன் உடன்பிறப்பு ஆபரேட்டர்களுக்கு விலையுடன் எந்தத் தொடர்பும் இல்லாத காரணங்களுக்காக க்யூரேட்டட் மாடல் பட்டியலை விரும்புகிறது.

## இது ஏன் உள்ளது

`hidePaidModels` பதில் "இந்த மாதிரி இலவசமா?" மற்றும் `hideAutoCombos` பதில்கள் " `auto/*` மெய்நிகர் ஐடிகள் விளம்பரப்படுத்தப்பட வேண்டுமா?" — அல்லது ஒரு ஆபரேட்டரை தன்னிச்சையான மாதிரிகளின் துணைக்குழுவைக் கட்டுப்படுத்த அனுமதிக்காது (எ.கா. கொடுக்கப்பட்ட Claude குறியீடு / OpenCode கிளையன்ட் பார்க்க வேண்டிய மாதிரிகளை சரியாக வழங்குதல், விலை நிர்ணயம் இல்லாமல்). #11481 இரண்டு சுயாதீன, தேர்வு சரம்-வரிசை அமைப்புகளாக சேர்க்கிறது.

## அமைப்புகள்

| முக்கிய                    | வகை        | இயல்புநிலை | பொருள்                                                                                         |
| -------------------------- | ---------- | ---------- | ---------------------------------------------------------------------------------------------- |
| `modelVisibilityDenylist`  | `string[]` | `[]`       | ஒரு வேட்பாளருக்குப் பொருந்தும் உள்ளீடுகள் அதை catalog/candidate குளத்தில் இருந்து மறைக்கின்றன. |
| `modelVisibilityAllowlist` | `string[]` | `[]`       | காலியாக இல்லாதபோது, ஒரு வேட்பாளருடன் பொருந்தக்கூடிய ONLY உள்ளீடுகள் வெளிப்படும்.               |

இரண்டும் ஒவ்வொன்றும் 200 எழுத்துகள் வரை 500 உள்ளீடுகளை ஏற்றுக்கொள்கின்றன ( `src/shared/validation/settingsSchemas.ts` இல் Zod-சரிபார்க்கப்பட்டது). ஒரு நுழைவு:

- ஒரு சரியான பட்டியல் ஐடி — `"gpt-4o"` (பேர் மாடல் ஐடி) அல்லது `"openai/gpt-4o"` (வழங்குபவர்-முன்னொட்டு), அல்லது
- `*`/`?` — ஐப் பயன்படுத்தி ஒரு குளோப் பேட்டர்ன் எ.கா. `"openai/gpt-4*"` அல்லது `"anthropic/*"` — அதே பகிரப்பட்ட `globToRegex()` மேட்சர் (`src/shared/utils/globPattern.ts`) மூலம் தீர்க்கப்பட்டது, ஏற்கனவே `ModelRoutingSection` இன் ஒவ்வொரு மாடல் காம்போ மேப்பிங்ஸ் மற்றும் `freeModels.ts::matchesOnlyPaidModels` மூலம் பயன்படுத்தப்பட்டது.

முன்னுரிமை: மறுக்கப்பட்டவர் முதலில் சரிபார்க்கப்படுவார் (மறுக்கப்பட்ட நுழைவு எப்போதும் மறைக்கப்படும், அது அனுமதிப்பட்டியலுடன் பொருந்தினாலும் கூட); அனுமதிப்பட்டியல் காலியாக இல்லாதபோது, அது பொருந்தும் உள்ளீடுகள் மட்டுமே உயிர்வாழும்.

## இரண்டு சோக்பாயிண்ட்கள், ஒன்றல்ல

#6512 இலிருந்து பாடம் (ஒரு `hidePaidModels` -only அட்டவணை வடிப்பான் இன்னும் `auto/*` கட்டண மாடலுக்கு அனுப்ப அனுமதிக்கிறது, ஏனெனில் காம்போ கேண்டிடேட் பூல் சுயாதீனமாக கட்டப்பட்டது) இங்கே ஒரே மாதிரியாக பொருந்தும். பொருந்தும் முன்னறிவிப்பு `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`) BOTH இலிருந்து அழைக்கப்படுகிறது:

- `src/app/api/v1/models/catalog.ts` — `/v1/models` பட்டியலிடுகிறது, அதே 5 ஒவ்வொரு மூல சோக்பாயிண்ட் `shouldHidePaid()` ஏற்கனவே கேட்ஸ் (நிலையான `PROVIDER_MODELS`, ஒத்திசைக்கப்பட்ட வழங்குநர் வரிசைகள், தனிப்பயன் வரிசைகள், மாற்று ஆதரவு வரிசைகள், நிர்வகிக்கப்பட்ட-குறுக்கு வரிசைகள்).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — ஆனது `virtualFactory.ts::buildPreparedPool` இலிருந்து அழைக்கப்பட்டது, அதற்கு சமமான `filterPaidOnlyCandidates()` அழைப்பிற்குப் பிறகு உடனடியாக, மறுக்கப்பட்ட மாதிரியை `auto/*` வேட்பாளர் குழுவில் தேர்ந்தெடுக்க முடியாது.

## NOT என்ன வடிகட்டப்படுகிறது

கண்ணாடிகள் `hideAutoCombos` இன் தற்போதைய நடத்தை: ஒரு மாதிரி ஐடி அனுப்பப்பட்டது** வெளிப்படையாக** ( `auto/*` வழியாக அல்ல, மற்றும் பட்டியல் பட்டியல் மூலம் கண்டறியப்படவில்லை) அனுப்பும்போது ஒருபோதும் தடுக்கப்படவில்லை — மட்டுமே advertisement/candidate-pool உறுப்பினர் வடிகட்டப்படுகிறது. இது `hidePaidModels` இலிருந்து சுயாதீனமானது; ஒரு ஆபரேட்டர், செலவுக்கு எந்தத் தொடர்பும் இல்லாத காரணங்களுக்காக ஒரு க்யூரேட்டட் தொகுப்பை விரும்பலாம், எனவே இரண்டு அமைப்புகளும் `catalog.ts` இல் இருக்கும் பல-கொடி கலவையைப் போலவே சுயாதீனமான மற்றும்-எட் வடிப்பான்களாக உருவாக்கப்படுகின்றன.

அமைப்புகளின் ஏற்றுமதி (`GET /api/settings/export-json`) இரண்டு வரிசைகளையும் வினைச்சொல்லாக உள்ளடக்கியது, `hidePaidModels` இன் சேர்க்கை-படி ஏற்றுமதி வடிகட்டியைப் போலல்லாமல், — மற்ற அமைப்புகளின் புலத்தைப் போலவே, இங்கு மறு-நீரேற்றம் ஆபத்து இல்லை: ஏற்றுமதி செய்யப்பட்ட சேர்க்கை படியில் உட்பொதிக்கப்பட்ட மறுக்கப்பட்ட ஐடி என்பது ஆபரேட்டரின் சொந்த வெளிப்படையான ரூட்டிங் தேர்வு ஆகும், ஏற்றுமதி செய்ய வேண்டிய அவசியமில்லை.

## காம்போஸ் மட்டும் பட்டியல் (`exposeCombosOnly`)

ஒரு தனி பூலியன், இயல்பாக தேர்வு மற்றும் `false`, சேர்க்கைகள் பொது மாதிரி மேற்பரப்பு மற்றும் வழங்குநர்கள் மட்டுமே பின்தளத்தில் இருக்கும் வரிசைப்படுத்தல்களுக்கு. இது `true` இருக்கும் போது, பொதுப் பட்டியல் (`GET /v1/models`, `GET /v1`, மற்றும் `getUnifiedModelsResponse()` இல் கட்டமைக்கப்பட்ட பிற `/v1` கண்டுபிடிப்பு வழிகள்) `owned_by: "combo"`: பயனர் சேர்க்கைகள் மற்றும் உள்ளமைக்கப்பட்ட `auto/*` சேர்க்கைகள் ( `hideAutoCombos` அவற்றை மறைக்கும் வரை) கொண்ட வரிசைகளை மட்டுமே வைத்திருக்கும். இது ஒரு விசைக்கு `catalogScope: "combos"` போன்ற அதே வரிசை சோதனையைப் பயன்படுத்துகிறது, மேலும் ஒரு விசையின் சொந்த allow/deny/scope வடிப்பான்கள் இன்னும் மேலே பொருந்தும்.

அதை உள்ளிடவும்** அமைப்புகள் → ரூட்டிங் → மாதிரிகள் API பட்டியல்** , அல்லது `PATCH /api/settings {"exposeCombosOnly": true}` உடன்.

மேலே உள்ள பட்டியல்களைப் போலவே, இது விளம்பரத்தை மட்டுமே மாற்றுகிறது:

- ஒரு வெளிப்படையான `provider/model` ஐடி இன்னும் அனுப்புகிறது, மேலும் `GET /v1/models/{id}` இன்னும் அதைத் தீர்க்கிறது;
- டாஷ்போர்டு பட்டியல் (`GET /api/models/catalog`, மாதிரி பிக்கர்களால் பயன்படுத்தப்படுகிறது) குறுகவில்லை;
- இது `auto/*` கேண்டிடேட் பூல்களில் பிரதிபலிக்கப்படவில்லை, எனவே `auto/*` காம்போக்கள் தங்கள் முழு தொகுப்பையும் வைத்திருக்கின்றன.
