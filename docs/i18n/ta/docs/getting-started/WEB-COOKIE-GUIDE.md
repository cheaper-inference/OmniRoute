Web Cookie வழங்குநர்கள், API விசைக்குப் பதிலாக உங்கள் தற்போதைய உலாவி அமர்வின் மூலம் ஓர் AI சேவையைப் பயன்படுத்த OmniRoute-ஐ அனுமதிக்கின்றன. ஒரு சேவையை அதன் இணையதளம் வழியாக நீங்கள் ஏற்கெனவே அணுக முடிந்தால், அதே அங்கீகரிக்கப்பட்ட அமர்வை OmniRoute பயன்படுத்த வேண்டும் என நீங்கள் விரும்பும்போது இவை பயனுள்ளதாக இருக்கும்.

API-key வழங்குநர்களைப் போலன்றி, Web Cookie வழங்குநர்கள் உங்கள் உலாவி இணையதளத்திற்கு அனுப்பும் நற்சான்றுகளைப் பயன்படுத்தி அங்கீகரிக்கின்றன.

# தொடங்குவதற்கு முன்

> **முக்கியம்:** நற்சான்றுகளை எப்போதும் **நேரடி நெட்வொர்க் கோரிக்கையிலிருந்து** நகலெடுக்கவும்; உங்கள் உலாவியின் குக்கீ சேமிப்பகத்திலிருந்து **நகலெடுக்க வேண்டாம்**.

தவறான இடத்திலிருந்து குக்கீகளை நகலெடுப்பதால் பல அங்கீகாரச் சிக்கல்கள் ஏற்படுகின்றன.

## Cookie Storage-இலிருந்து நகலெடுக்க வேண்டாம்

பெரும்பாலான உலாவிகள் சேமிக்கப்பட்ட குக்கீகளைப் பின்வரும் வழியாகக் காட்டுகின்றன:

```
DevTools
→ Application (அல்லது Storage)
→ Cookies
```

இந்தக் குக்கீகள் சரியானவை போல் தோன்றினாலும், அவை:

- காலாவதியானவையாக இருக்கலாம்
- முழுமையற்றவையாக இருக்கலாம்
- அங்கீகரிக்கப்பட்ட கோரிக்கைகளில் மட்டுமே அனுப்பப்படும் குக்கீகள் இல்லாமல் இருக்கலாம்

இந்த மதிப்புகள் செல்லுபடியாகத் தோன்றினாலும், அவற்றைப் பயன்படுத்துவது அங்கீகாரத் தோல்விகளை ஏற்படுத்தக்கூடும்.

## நேரடி கோரிக்கையிலிருந்து நகலெடுக்கவும்

அதற்குப் பதிலாக, வெற்றிகரமான கோரிக்கையிலிருந்து குக்கீகளைப் பயன்படுத்தவும்:

```
DevTools
→ Network
→ பக்கத்தைப் புதுப்பிக்கவும்
→ ஓர் அரட்டை அல்லது உரையாடல் கோரிக்கையைத் திறக்கவும்
→ Request Headers
→ Cookie
```

`Cookie` கோரிக்கைத் தலைப்பில், உங்கள் உலாவி வெற்றிகரமாகப் பயன்படுத்திய துல்லியமான அங்கீகாரத் தகவல்கள் உள்ளன.

பெரும்பாலான Web Cookie வழங்குநர்களுக்கு, OmniRoute-இல் ஒட்ட வேண்டிய மதிப்பு இதுவாகும்.

# பொதுவான அமைப்பு

பெரும்பாலான Web Cookie வழங்குநர்களுக்கான அமைப்புச் செயல்முறை ஒரே மாதிரியாக இருக்கும்.

1. வழங்குநரின் இணையதளத்தில் உள்நுழையவும்.
2. உலாவியின் Developer Tools-ஐத் திறக்கவும்.
3. **Network** தாவலைத் திறக்கவும்.
4. பக்கத்தைப் புதுப்பிக்கவும்.
5. அங்கீகரிக்கப்பட்ட அரட்டை அல்லது உரையாடல் கோரிக்கையைத் திறக்கவும்.
6. தேவையான அங்கீகார நற்சான்றுகளை நகலெடுக்கவும்.
7. OmniRoute-ஐத் திறக்கவும்.
8. **Providers → Add Provider** என்பதற்குச் செல்லவும்.
9. உங்கள் Web Cookie வழங்குநரைத் தேர்ந்தெடுக்கவும்.
10. நற்சான்றுகளை ஒட்டவும்.
11. **Test Connection** என்பதைக் கிளிக் செய்யவும்.
12. வழங்குநரைச் சேமிக்கவும்.

தேவையான துல்லியமான நற்சான்றுகள் வழங்குநரைப் பொறுத்து மாறுபடும்.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) என்பது பதிவுசெய்தல் தேவையில்லாத இலவச நுகர்வோர் அரட்டைத் தளமாகும் — முதல் வருகையின்போது அமர்வு பெயரில்லாமல் உருவாக்கப்பட்டு, `uid`, `si_usr_id`, மற்றும் `si_ses_id` ஆகிய மூன்று குக்கிகள் மூலம் தொடர்ந்து நிலைத்திருக்கும். OmniRoute, அதே `/api/dispatch` முனைப்புள்ளியை ஒற்றை மாதிரி அடையாளம் (`notrack-c`, மாற்றுப்பெயர் `ntw`) மூலம் ப்ராக்ஸி செய்கிறது.

### இணைப்பதற்கான படிகள்

1. உங்கள் உலாவியில் [notrack.ai](https://notrack.ai)-ஐத் திறந்து, பெயரில்லா அமர்வுக் குக்கி அமைக்கப்பட அனுமதிக்கவும்.
2. **DevTools → Network** என்பதைத் திறந்து, பக்கத்தைப் புதுப்பித்து, ஏதேனும் `/api` கோரிக்கையைக் கிளிக் செய்யவும்.
3. **Request Headers** என்பதில், முழு `Cookie` தலைப்பு மதிப்பையும் நகலெடுக்கவும்.
4. OmniRoute-இல், **Providers → Add Provider → NoTrack Web (Free)** என்பதற்குச் செல்லவும்.
5. குக்கி சரத்தை `apiKey` புலத்தில் ஒட்டி, **Save** என்பதைக் கிளிக் செய்யவும்.

ஒட்டப்பட்ட சரத்திலிருந்து `uid`, `si_usr_id`, மற்றும் `si_ses_id` ஆகியவற்றை OmniRoute பிரித்தெடுத்து, அந்த இணைகளுடன் மட்டும் ஒரு சுத்தமான `Cookie` தலைப்பை மீண்டும் உருவாக்குகிறது — மேலும், இருந்தால் `nt_session`-ஐயும் (உள்நுழைந்த கணக்குகளுக்காக அமைக்கப்படும் `ntk_…` டோக்கன்) சேர்க்கிறது. இம்மூன்றில் ஏதேனும் ஒன்று இல்லையெனில், மாற்று வடிவமைப்புகளுடன் இயக்குநர்கள் பரிசோதிக்க ஏதுவாக, ஒட்டப்பட்ட மூலச் சரம் மாற்றமின்றி அனுப்பப்படுகிறது.

### மாதிரி அடையாளங்கள்

| மாதிரி அடையாளம் | காட்சிப் பெயர் | குறிப்புகள்                                                               |
| --------------- | -------------- | ------------------------------------------------------------------------- |
| `notrack-c`     | NoTrack C      | இயல்புநிலை — அப்ஸ்ட்ரீம் அனுப்பீட்டு மாதிரி `C`.                          |
| `C`             | NoTrack C      | `notrack-c`-க்கான மாற்றுப்பெயர் (மூல அப்ஸ்ட்ரீம் அனுப்பீட்டுக் குறியீடு). |
| `notrack`       | NoTrack C      | `notrack-c`-க்கான மாற்றுப்பெயர்.                                          |
| `ntw`           | NoTrack C      | `notrack-c`-க்கான குறுகிய மாற்றுப்பெயர்.                                  |

நான்கு மாதிரி அடையாளங்களும் ஒரே அப்ஸ்ட்ரீம் அனுப்பீட்டு மாதிரியுடன் (`C`) பொருத்தப்படுகின்றன.

### கோரிக்கை விருப்பங்கள்

கோரிக்கை உடலில் பின்வரும் விருப்பப் புலங்களைச் செயல்படுத்தி ஏற்கிறது:

| உடல் புலம்            | இயல்புநிலை | நோக்கம்                                                                             |
| --------------------- | ---------- | ----------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`    | அனுப்பீட்டு முறை (கட்டற்ற வடிவச் சரம்; அப்ஸ்ட்ரீம் `usual`, … ஆகியவற்றை ஏற்கிறது)   |
| `notrack_max_turns`   | `6`        | பதிலளிப்பதற்கு முன் அப்ஸ்ட்ரீம் மேற்கொள்ளக்கூடிய உள் சுற்றுகளின் எண்ணிக்கை.         |
| `notrack_chat_id`     | `null`     | ஏற்கனவே உள்ள அப்ஸ்ட்ரீம் அரட்டையைத் தொடரவும் (புதிய அரட்டைக்கு இதைத் தவிர்க்கவும்). |
| `notrack_attachments` | `[]`       | அப்ஸ்ட்ரீம் இணைப்பு விவரிப்பான்களின் நேரடியாகக் கடத்தப்படும் வரிசை.                 |
| `notrack_regenerate`  | `false`    | முந்தைய சுற்றுக்கான பதிலை மீண்டும் உருவாக்கக் கோர, `true` என அமைக்கவும்.            |

### திறன்கள்

- **ஸ்ட்ரீமிங் மற்றும் ஸ்ட்ரீமிங் அல்லாத** அரட்டை நிறைவுகள்.
- **கருவி அழைப்பு** — கோரிக்கையில் `tools: [...]` என்பதை அமைக்கவும்; செயல்படுத்தி அவற்றை ஒரு கருவி-அழைப்பு உறை ஒப்பந்தமாகத் தொடராக்கி, மாதிரியின் பதில்களை மீண்டும் OpenAI `tool_calls` ஆகப் பகுப்பாய்வு செய்கிறது.
- **`response_format`** — `json_object` மற்றும் `json_schema` ஆதரிக்கப்படுகின்றன. திருப்பி அனுப்புவதற்கு முன், செயல்படுத்தி மாதிரியின் பதிலிலிருந்து முதல் JSON பொருளைப் பிரித்தெடுத்து அதைச் சரமாக மாற்றுகிறது.
- **பகுத்தறிவுக் குறிப்பு** — அப்ஸ்ட்ரீம் ஒரு `thinking` நிகழ்வை அனுப்பும்போது, செயல்படுத்தி ஒரு `reasoning` டெல்டாவை வெளியிடுகிறது.

### வரம்புகள்

- அப்ஸ்ட்ரீம் பெயரில்லா பயன்பாட்டு ஒதுக்கீடுகளை அமல்படுத்துகிறது — அவை மீறப்படும்போது, செயல்படுத்தி பயனருக்கு ஏற்ற செய்தியுடன் 429 பிழையை வெளிப்படுத்துகிறது.
- அனைத்து மாதிரி அடையாளங்களும் ஒரே அப்ஸ்ட்ரீம் அனுப்பீட்டு மாதிரியாகத் தீர்மானிக்கப்படுகின்றன; ஒவ்வொரு மாதிரிக்கும் தனித்தனி மாற்றி இல்லை.
- செயல்படுத்தி அப்ஸ்ட்ரீமின் `/api/chats` முனைப்புள்ளியை அழைப்பதில்லை; எனவே அரட்டை வரலாறு / அமர்வுகள் தானாக நிர்வகிக்கப்படுவதில்லை. ஏற்கனவே உள்ள அப்ஸ்ட்ரீம் அரட்டையைத் தொடர `notrack_chat_id`-ஐப் பயன்படுத்தவும்.

# வலைக் குக்கி வழங்குநர்கள் செய்யக்கூடியவை மற்றும் செய்ய முடியாதவை

வலைக் குக்கி வழங்குநர்கள் ஒரு வலைத்தளத்தின் அரட்டை இடைமுகத்தை மீண்டும் பயன்படுத்துகின்றனர். அவை அதிகாரப்பூர்வ API-களுக்கு இணையான திறன்களை வழங்குவதில்லை.

## ஆதரிக்கப்படுபவை

- ஏற்கனவே உள்ள உங்கள் உலாவி அமர்வைப் பயன்படுத்தி அங்கீகரித்தல்
- உங்கள் கணக்கின் மூலம் கிடைக்கும் மாடல்களை அணுகுதல்
- அரட்டை பதில்களை ஸ்ட்ரீம் செய்தல்
- API விசை தேவையில்லை

## ஆதரிக்கப்படாதவை

- செயல்பாடு அழைத்தல்
- கருவி அழைத்தல்
- தானியங்கி கோப்புத் திருத்தம்
- தன்னியக்க முகவர் சார்ந்த IDE பணிப்பாய்வுகள்
- API-க்கு மட்டுமே உரிய அம்சங்கள்

இது எதிர்பார்க்கப்படும் நடத்தையாகும், **பிழை அல்ல**.

கருவிகளை இயக்குதல், தானியங்கி கோப்புத் திருத்தம் அல்லது பிற முகவர் பணிப்பாய்வுகள் உங்களுக்குத் தேவைப்பட்டால், Web Cookie வழங்குநருக்குப் பதிலாக **API-key வழங்குநரைப்** பயன்படுத்தவும்.

# சரிபார்ப்பு தொடர்பான எச்சரிக்கை

வெற்றிகரமான **இணைப்புச் சோதனை** அல்லது குக்கீ சரிபார்ப்பு, வழங்கப்பட்ட நற்சான்றுகள் எதிர்பார்க்கப்படும் வடிவமைப்பில் இருப்பதாகத் தோன்றுவதை மட்டுமே உறுதிப்படுத்துகிறது.

Issue #7857 தீர்க்கப்படும் வரை, வெற்றிகரமான சரிபார்ப்பு, வழங்குநர் வெற்றிகரமாக அங்கீகரிப்பார் என்பதற்கு **உத்தரவாதம் அளிக்காது**.

அங்கீகாரம் இன்னும் தோல்வியடைந்தால், உலாவியின் குக்கீ சேமிப்பகத்திலிருந்து அல்லாமல், செயலில் உள்ள நெட்வொர்க் கோரிக்கையிலிருந்து நற்சான்றுகளை நகலெடுத்துள்ளீர்கள் என்பதை உறுதிப்படுத்தவும்.

## அமர்வு காலாவதியானது

Web Cookie வழங்குநர்கள் ஏற்கனவே உள்ள உங்கள் உலாவி அமர்வைப் பயன்படுத்துகின்றனர்.

உங்கள் உலாவி அமர்வு காலாவதியானாலோ அல்லது நீங்கள் வெளியேறினாலோ, புதிய நற்சான்றுத் தொகுப்பை நகலெடுக்க வேண்டும். ஆதரிக்கப்படும் இணைய வழங்குநர்களுக்கான குக்கீ புதுப்பிப்பைத் தானியக்கமாக்க, துணைக் கருவியான [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md)-ஐப் பார்க்கவும்.

## "Unsupported ChatGPT integrity dependency" பிழையுடன் ChatGPT Web தோல்வியடைகிறது

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

நற்சான்றில் பிரச்சினையில்லை — அந்தப் பிழை அமர்விலிருந்து அல்ல, bridge-இலிருந்து வருகிறது. chatgpt.com அதன்
module id-களை ஒவ்வொரு deployment-க்கும் ஒதுக்குகிறது; bridge, அது உருவாக்கும் Sentinel helper-இன் id-ஐ முன்பு நிலையாகப் பிணைத்திருந்ததால்,
helper-க்குப் புதிய பெயரிட்ட chatgpt.com rebuild, குக்கீ செல்லுபடியாக இருந்தபோதிலும் ஒவ்வொரு turn-ஐயும் செயலிழக்கச் செய்தது. இணைப்பை
மீண்டும் அங்கீகரிப்பதால் இதைச் சரிசெய்ய முடியாது.

பக்கத்தின் சொந்த runtime மூலம் module-ஐத் தீர்மானிக்கும் build-கள் எந்த id-ஐயும் நிலையாகப் பிணைக்காது, எனவே இந்தப் பிரச்சினையைச் சந்திப்பதில்லை. இந்தப்
பிழையை நீங்கள் கண்டால், OmniRoute-ஐ மேம்படுத்தி, இணைப்புச் சோதனையை மீண்டும் இயக்கவும்.
