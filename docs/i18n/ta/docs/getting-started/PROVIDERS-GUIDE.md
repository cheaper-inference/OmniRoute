## வழங்குநர் என்றால் என்ன?

வழங்குநரை ஒரு **தொலைபேசி சேவை வழங்குநர்** போலக் கருதுங்கள். அழைப்புகளைச் செய்ய உங்களுக்குத் தொலைபேசி சேவை வழங்குநர் தேவைப்படுவது போலவே, AI மாதிரிகளைப் பயன்படுத்த உங்களுக்கு AI வழங்குநர் தேவை. OmniRoute என்பது **அனைத்து சேவை வழங்குநர்களுடனும்** செயல்படும் தொலைபேசி போன்றது — அவற்றுக்கு இடையே நீங்கள் தானாக மாறலாம்.

### வழங்குநர்களின் வகைகள்

| வகை            | அது என்ன                               | எடுத்துக்காட்டுகள்              | செலவு                                 |
| -------------- | -------------------------------------- | ------------------------------- | ------------------------------------- |
| **இலவசம்**     | கட்டணம் தேவையில்லை                     | Kiro, Pollinations              | $0                                    |
| **API விசை**   | உங்களுக்கு API விசை தேவை               | OpenAI, Anthropic, Google       | பயன்பாட்டுக்கு ஏற்ப கட்டணம்           |
| **OAuth**      | உங்கள் கணக்கைப் பயன்படுத்தி உள்நுழைதல் | Claude Code, GitHub Copilot     | சந்தா                                 |
| **வலை குக்கீ** | உங்கள் உலாவி அமர்வைப் பயன்படுத்துகிறது | ChatGPT Web (Codex), Gemini Web | $0 (உங்கள் கணக்கைப் பயன்படுத்துகிறது) |

### வலை குக்கீ வழங்குநர்கள்

பொதுவான அமைவு வழிமுறைகள், வரம்புகள், சிக்கல் தீர்வு மற்றும் வழங்குநர் சார்ந்த அங்கீகார வழிகாட்டுதலுக்கு **[WEB-COOKIE-GUIDE.md](./WEB-COOKIE-GUIDE.md)**-ஐப் பார்க்கவும்.

## விரைவான தொடக்கம்: உங்கள் முதல் வழங்குநரை இணைக்கவும்

### விருப்பத்திற்குரிய முதல் இயக்க இலவச-வழங்குநர் அமைப்பு

முதல் இயக்க வழிகாட்டி, வெளிப்படையான **இலவச வழங்குநர்களை அமைக்கவும்** அட்டையை வழங்குகிறது. இது OmniRoute-இன் அங்கீகாரம் தேவையில்லாத வழங்குநர் பதிவேட்டிலிருந்து தற்போது
தகுதியுள்ள பட்டியலைப் பெறுகிறது; பின்னர் உறுதிப்படுத்துவதற்கு முன் ஒவ்வொரு
வழங்குநரையும் மதிப்பாய்வு செய்து தேர்வுநீக்கம் செய்ய உங்களை அனுமதிக்கிறது. மூன்றாம் தரப்பு விதிமுறைகள், தனியுரிமை, கிடைக்கும் தன்மை மற்றும் விகித வரம்புகளை நீங்கள் முதலில் மதிப்பாய்வு செய்யும் வகையில், வழங்குநரின் எச்சரிக்கை அறிவிப்பையும் அதன் தளத்திற்கான இணைப்பையும் OmniRoute காட்டுகிறது.

இந்தச் செயல் விருப்பத்திற்குரியது: வழிகாட்டியை நிறைவுசெய்வது ஒருபோதும் இலவச-வழங்குநர் இணைப்புகளை மறைமுகமாக உருவாக்காது.
இன்னும் இல்லாத வழங்குநர்களை மட்டுமே இது உருவாக்குகிறது, ஏற்கெனவே தனிப்பயனாக்கப்பட்ட இணைப்புகளை
மாற்றாமல் விட்டுவிடுகிறது, மேலும் உருவாக்கப்பட்ட, ஏற்கெனவே உள்ளமைக்கப்பட்ட மற்றும் தோல்வியடைந்த வழங்குநர்களைத் தனித்தனியாக அறிக்கையிடுகிறது. பகுதியளவு முடிவு ஏற்பட்ட பிறகு, தோல்வியடைந்தவற்றை மட்டும் நீங்கள் பாதுகாப்பாக மீண்டும் முயற்சிக்கலாம்.

### விருப்பம் A: இலவச வழங்குநர் (கடன் அட்டை தேவையில்லை)

1. `http://localhost:20128` முகவரியில் கட்டுப்பாட்டுப் பலகையைத் திறக்கவும்
2. **வழங்குநர்கள்** → **வழங்குநரைச் சேர்** என்பதற்குச் செல்லவும்
3. இந்த இலவச வழங்குநர்களில் ஒன்றைத் தேர்ந்தெடுக்கவும்:
   - **Kiro AI** — இலவச Claude மாதிரிகள் (அங்கீகாரம் தேவையில்லை)
   - **Pollinations** — இலவச GPT-5, Claude, Gemini (விசை தேவையில்லை)
   - **LongCat** — 10M டோக்கன்கள் இலவசம் (ஒருமுறை மானியம், கணக்கு + KYC தேவை)
   - **Cloudflare AI** — 50+ மாதிரிகள், நாளொன்றுக்கு 10K நியூரான்கள்
   - **MLX Gemma 26B** — உள்ளூர் Apple Silicon மாதிரி (~38.5 tok/s, ~15.9GB RAM)
   - **MLX Qwen 3.8 27B** — உள்ளூர் Apple Silicon மாதிரி (~9.1 tok/s, ~13.1GB RAM)
4. **இணைக்கவும்** என்பதைக் கிளிக் செய்யவும்
5. முடிந்தது! இப்போது உங்களுக்கு இலவச AI அணுகல் உள்ளது.

3. **வழங்குநர்கள்** → **வழங்குநரைச் சேர்** என்பதற்குச் செல்லவும்

### விருப்பம் C: OAuth வழங்குநர் (சந்தா)

### விருப்பம் D: உள்ளூர் MLX மாதிரிகள் (Apple Silicon)

ஒருங்கிணைந்த நினைவகம் கொண்ட Apple Silicon Macs-களில், `mlx-lm.server` வழியாக இயங்கும் உள்ளூர் MLX மாதிரிகளை வழக்கமான OpenAI-இணக்கமான உள்ளூர் வழங்குநர்களாக இணைப்பதை OmniRoute ஆதரிக்கிறது.

#### முன்தேவைகள்

- 24GB+ ஒருங்கிணைந்த நினைவகத்துடன் கூடிய **Apple Silicon Mac** (M1/M2/M3/M4) பரிந்துரைக்கப்படுகிறது
- **uv** தொகுப்பு மேலாளர்: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- **mlx-lm**: `uv pip install mlx-lm`

#### விரைவான தொடக்கம்

1. **சார்புகளை நிறுவவும்**:

   ```bash
   # ஏற்கெனவே நிறுவப்படவில்லை என்றால் uv-ஐ நிறுவவும்
   curl -LsSf https://astral.sh/uv/install.sh | sh

   # mlx-lm-ஐ நிறுவவும்
   uv pip install mlx-lm
   ```

2. **MLX சேவையகங்களைக் கைமுறையாகத் தொடங்கவும்** (தனித்தனி முனையங்களில்):

   ```bash
   # முனையம் 1: Gemma 4 26B A4B IT-QAT (போர்ட் 11435)
   uv run mlx_lm.server --model mlx-community/gemma-4-26B-A4B-it-qat-q4_0-mlx-aligned --port 11435 --host 127.0.0.1

   # முனையம் 2: Qwen 3.8 27B MLX Mixed (போர்ட் 11436)
   uv run mlx_lm.server --model maglun/Qwen3.8-27B-MLX-Mixed-3.80bpw --port 11436 --host 127.0.0.1
   ```

3. **OmniRoute கட்டுப்பாட்டுப் பலகையில் இணைக்கவும்**:
   - **வழங்குநர்கள்** → **வழங்குநரைச் சேர்** என்பதற்குச் செல்லவும்
   - **MLX Gemma 26B** அல்லது **MLX Qwen 3.8 27B** என்பதைத் தேர்ந்தெடுக்கவும்
   - **இணைக்கவும்** என்பதைக் கிளிக் செய்யவும் (API விசை தேவையில்லை)

4. **OpenCode உடன் பயன்படுத்தவும்**:
   ```bash
   # OmniRoute-ஐப் பயன்படுத்த OpenCode-ஐ உள்ளமைக்கவும்
   opencode config set api.base_url http://localhost:20128/v1
   opencode config set api.key <your-omniroute-api-key>
   ```

### படி 4: உங்கள் வழங்குநரைத் தேர்ந்தெடுக்கவும்

பட்டியலை உலாவவும் அல்லது உங்கள் வழங்குநரைத் தேடவும். அதன் மீது கிளிக் செய்யவும்.

### படி 5: அணுகல் விவரங்களை உள்ளிடவும்

- **இலவச வழங்குநர்கள்**: அணுகல் விவரங்கள் தேவையில்லை — **இணை** என்பதைக் கிளிக் செய்தால் போதும்
- **API சாவி வழங்குநர்கள்**: உங்கள் API சாவியை ஒட்டவும்
- **OAuth வழங்குநர்கள்**: **OAuth மூலம் இணை** என்பதைக் கிளிக் செய்து உள்நுழையவும்

### படி 6: இணைப்பைச் சோதிக்கவும்

அது செயல்படுகிறதா என்பதைச் சரிபார்க்க **இணைப்பைச் சோதி** என்பதைக் கிளிக் செய்யவும்.

### படி 7: முடிந்தது!

உங்கள் வழங்குநர் இப்போது இணைக்கப்பட்டுள்ளார். அதை `model: "auto"` உடன் பயன்படுத்தலாம் அல்லது வழங்குநரை நேரடியாகக் குறிப்பிடலாம்.

Qoder-க்கு நற்சான்றுகள் தேவை. அதன் இரு பரிமாற்ற முறைகளும் வெவ்வேறு திறன்களைக் கொண்டுள்ளன; ஒரு மாதிரிப் பெயர் மட்டும் குறிப்பிட்ட இணைப்பால் என்ன செய்ய முடியும் என்பதை அடையாளம் காட்டாது.

| நற்சான்று                                 | OmniRoute பரிமாற்ற முறை                              | அழைப்பாளர் கருவி அழைப்பு                                  | ஸ்ட்ரீமிங்                                                                     |
| ----------------------------------------- | ---------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `pt-` என்று தொடங்கும் PAT                 | OmniRoute ஹோஸ்டில் உள்ள உள்ளூர் `qodercli` செயல்முறை | ஆதரிக்கப்படவில்லை                                         | இடையகப்படுத்தப்பட்டது: CLI முழுப் பதிலையும் வழங்கிய பின்னரே SSE வெளியிடப்படும் |

PAT-க்கு, OmniRoute இருக்கும் அதே ஹோஸ்ட் அல்லது கண்டெய்னரில் Qoder CLI-ஐ நிறுவவும். செயல்படுத்தக்கூடிய கோப்பு `qodercli` எனக் கண்டறியக்கூடியதாக இருக்க வேண்டும், அல்லது `CLI_QODER_BIN`-ஐ அதன் செயல்படுத்தக்கூடிய கோப்புப் பாதைக்கு அமைக்கவும். Docker ஹோஸ்டில் மட்டும் நிறுவப்பட்ட CLI, கண்டெய்னரில் தானாகவே கிடைக்காது. பைனரிகள் இல்லாவிட்டால், நிறுவல் அல்லது பாதை அமைப்பைச் சுட்டிக்காட்டும் வெளிப்படையான பிழை உருவாகும்.

PAT அரட்டைப் பாதைக்கு 45-வினாடி செயல்முறை காலக்கெடு உள்ளது. இது உரையாடலை ஒரே தூண்டுரையாகத் தட்டையாக்கி, ஸ்ட்ரீமிங் அல்லாத அச்சு முறையில் CLI-ஐ அழைக்கிறது. `stream: true`-ஐக் கோருவது பதில் உறையை SSE ஆக மாற்றும்; அது மேல்நிலையிலிருந்து படிப்படியான டோக்கன் வழங்கலை அளிக்காது. CLI சரிபார்ப்பு/மாதிரிப் பட்டியலிடுதல் தனியான 20-வினாடி காலக்கெட்டைப் பயன்படுத்துகிறது. இவை தற்போதைய குறியீட்டு இயல்புநிலைகள்; உள்ளமைக்கக்கூடிய டாஷ்போர்டு அமைப்புகள் அல்ல.

எளிய அரட்டைக்கு PAT இணைப்புகளைப் பயன்படுத்தவும். `tools` அல்லது பழைய `functions`-ஐக் கொண்ட ஏஜென்ட் கோரிக்கைகள், பின் செய்யப்பட்ட காம்போ இலக்குகள் உட்பட, நற்சான்றுத் தேர்வின்போது PAT கணக்குகளை விலக்குகின்றன. கலப்பு Qoder தொகுப்பு இன்னும் அதன் HTTP கணக்கைத் தேர்ந்தெடுக்க முடியும். PAT இயக்கிக்கான நேரடி அழைப்புகளும் கருவி வரையறைகளை அமைதியாகக் கைவிடுவதற்குப் பதிலாக, CLI-ஐத் தொடங்குவதற்கு முன்பே வெளிப்படையாகத் தோல்வியடையும். இந்தக் கட்டுப்பாடு API அழைப்பாளர் வழங்கும் கருவிகளைப் பற்றியது; Qoder CLI தானாகப் பயன்படுத்தக்கூடிய உள் கருவிகளைப் பற்றியது அல்ல. HTTP விசை இருப்பது ஒவ்வொரு மாதிரியும் கருவிகளை ஆதரிக்கும் என்பதற்கு உத்தரவாதமல்ல; வழக்கமான மாதிரித் திறன் சரிபார்ப்புகள் தொடர்ந்து பொருந்தும்.

நிர்வாகி பின்வரும் ஐந்து அமைப்புகளையும் உள்ளமைத்தால் மட்டுமே உலாவி OAuth கிடைக்கும்:
`QODER_OAUTH_AUTHORIZE_URL`, `QODER_OAUTH_TOKEN_URL`, `QODER_OAUTH_USERINFO_URL`,
`QODER_OAUTH_CLIENT_ID`, மற்றும் `QODER_OAUTH_CLIENT_SECRET`. அவை இயல்புநிலையில் காலியாக இருக்கும்; உள்ளமைக்கப்படாத நிறுவல், உலாவி உள்நுழைவு ஓட்டம் தயாராக இருப்பதாகக் கருதுவதற்குப் பதிலாக, ஆதரிக்கப்படும் நற்சான்று இறக்குமதியைப் பயன்படுத்த வேண்டும்.

செயலாக்க மேற்கோள்கள்: [Qoder இயக்கி](../../open-sse/executors/qoder.ts),
[CLI இயக்கநேரம்](../../open-sse/services/qoderCli.ts), மற்றும்
[OAuth உள்ளமைவு](../../src/lib/oauth/constants/oauth.ts). படிப்படியான PAT ஸ்ட்ரீமிங் மற்றும் உள்ளமைக்கக்கூடிய காலக்கெடு ஆகியவை தனித்தனி மேம்பாடுகள்; இந்த நடத்தை அவற்றை உறுதியளிக்கவில்லை.

## பொதுவான கேள்விகள்

### "OmniRoute-ஐப் பயன்படுத்த நான் பணம் செலுத்த வேண்டுமா?"

**இல்லை!** OmniRoute இலவசமானதும் திறந்த மூலமானதும் ஆகும். எதுவும் செலுத்தாமல் இலவச வழங்குநர்களை (Kiro, Pollinations) நீங்கள் பயன்படுத்தலாம். கட்டண வழங்குநர்களைப் பயன்படுத்தத் தேர்வுசெய்தால் மட்டுமே நீங்கள் பணம் செலுத்த வேண்டும்.

### "எந்த வழங்குநருடன் நான் தொடங்க வேண்டும்?"

**Kiro AI** உடன் தொடங்குங்கள் — இது இலவசமானது, API key தேவையில்லை, மேலும் Claude models-ஐ அணுக அனுமதிக்கிறது. பின்னர் தேவைக்கேற்ப மேலும் வழங்குநர்களைச் சேருங்கள்.

### "ஒரே நேரத்தில் பல வழங்குநர்களைப் பயன்படுத்த முடியுமா?"

**ஆம்!** அதுதான் OmniRoute-ன் முக்கிய நோக்கம். பல வழங்குநர்களை இணைத்து, ஒவ்வொரு கோரிக்கைக்கும் சிறந்த வழங்குநரை OmniRoute தேர்ந்தெடுக்க அனுமதிக்க `model: "auto"` என்பதைப் பயன்படுத்துங்கள்.

### "ஒரு வழங்குநர் செயலிழந்தால் என்ன ஆகும்?"

தோல்வியடைந்த வழங்குநர்களை OmniRoute தானாகத் தவிர்த்துவிட்டு, அடுத்த வழங்குநரை முயற்சிக்கும். நீங்கள் எதுவும் செய்ய வேண்டியதில்லை.

### "ஒரு வழங்குநரின் இணைப்பை எவ்வாறு துண்டிப்பது?"

Providers → வழங்குநரைக் கிளிக் செய்யுங்கள் → **Disconnect** என்பதைக் கிளிக் செய்யுங்கள்.

### "ஏற்கனவே என்னிடம் உள்ள API keys-ஐப் பயன்படுத்த முடியுமா?"

**ஆம்!** OpenAI, Anthropic, Google போன்றவற்றுக்கான API keys ஏற்கனவே உங்களிடம் இருந்தால், அவற்றை OmniRoute-ல் பயன்படுத்தலாம். வழங்குநரை இணைக்கும்போது அவற்றை ஒட்டினால் போதும்.
