## ஒரு வெளியீட்டு கிளையில் இறங்குதல்

சர்வ-வரிசை `release/vX.Y.Z` க்குள் இறங்குவதை நிர்வகிக்கிறது. ஒரு PR இறங்கும் முன் இயல்புநிலை கிளையில் `config/merge-queue/config.json` இல் உயர்நிலை `mode` படிக்கவும். [ஆம்னி-வரிசையைப்](OMNI_QUEUE.md) பார்க்கவும்.

- **`shadow`** சரிபார்ப்பை இயக்குகிறது மற்றும் கைமுறையாக ஒன்றிணைக்க தரையிறங்குகிறது. அங்கீகரிக்கப்பட்ட PR க்கு `omni-queue` அதன் இறுதித் தலைப்பில் பயன்படுத்தவும். `npm run queue -- why <PR>` உடன் தகுதியைச் சரிபார்க்கவும். `npm run queue -- history --base <branch>` இல் அந்த தலைக்கான தீர்ப்புக்காக காத்திருங்கள். `would-land` இல் தொடரவும். `culprit-found` அல்லது `would-dequeue` இல், ஒன்றிணைப்பைப் பிடித்து, காரணத்தைச் சரிசெய்யவும்.
- **நிழல் விதிவிலக்குகள்.** தற்போதைய அடிப்படை முனைக்கு எதிராக பச்சை நிற முழு CI கொண்ட ரயில் தனி வரிசை தீர்ப்பு இல்லாமல் தொடரலாம். அதே விதிவிலக்கு PR தலையில் ஏற்கனவே தற்போதைய அடிப்படை முனை இருக்கும் போது பொருந்தும்.
- **`live`** தரையிறக்கத்தைத் தூண்டுவதற்கு `omni-queue` லேபிளைப் பயன்படுத்துகிறது. வரிசையில் மட்டும் PR தரையிறங்குகிறது. ஒன்றிணைக்கும் கட்டளைகள் மற்றும் நேரடி புஷ்களை வரிசையில் விடுங்கள்.

ஒவ்வொரு தரையிறக்கத்திற்கும் உரிமையாளரின் அங்கீகாரம் மற்றும் பொருந்தக்கூடிய தேவையான காசோலைகள் தேவை. உரிமையாளர் தரையிறங்குவதற்கு அங்கீகாரம் அளித்த பின்னரே `omni-queue` பயன்படுத்தவும். வரிசைப்படுத்தப்பட்ட PRs பாதுகாக்கப்பட்ட பாதைகளைத் தொடுவதற்கு, அந்த PR க்கான உரிமையாளரின் `protected-approved` முடிவும் தேவைப்படுகிறது.

"செயல்திறன் வெளியீட்டில் பச்சை வாயில்கள் தேவை" என்ற விதிகளுக்கு பச்சை `Gate / CI` மற்றும் தலையில் `Gate / Quality` தேவை. சிவப்பு வாயிலைக் கடந்து செல்ல `--admin` பயன்படுத்த வேண்டாம். ஒரு வெளியீட்டு முடக்கம் தொகுதிகள் உறைந்த கிளையில் இணைகிறது. [கடினமான விதி 21 ஐப்](HARD_RULES_DETAIL.md) பார்க்கவும். மற்றொரு அமர்வு வேலை செய்கிறது என்று ஒருபோதும் லேபிளிடவோ, ஒன்றிணைக்கவோ அல்லது இழுக்கும் கோரிக்கைக்கு தள்ளவோ வேண்டாம். [கடினமான விதி 22 ஐப்](HARD_RULES_DETAIL.md) பார்க்கவும்.

## ரயில் இழுக்க கோரிக்கை

1. தற்போதைய வெளியீட்டு அடிப்படை முனையில் ரயில் கிளையைத் தொடங்கவும். ஒன்றிணைக்கப்பட்ட கமிட்களைப் பயன்படுத்தி சரியான அங்கீகரிக்கப்பட்ட உறுப்பினர் தலைவர்களை ஒருங்கிணைக்கவும். ஸ்குவாஷ் மற்றும் மறுபரிசீலனையைத் தவிர்ப்பதன் மூலம் அவர்களின் உறுதிப்பாட்டின் வரலாற்றைப் பாதுகாக்கவும்.
2. ரயில் கிளைக்கான ஒரு இழுப்பு கோரிக்கையைத் திறக்கவும். தற்போதைய அடிப்படை முனையில் அதன் சொந்த முழு CI உடன் அந்த PR சரிபார்க்கவும். தரையிறங்குவதற்கு முன் அடிப்படை முனை மற்றும் அங்கீகரிக்கப்பட்ட உறுப்பினர் தலைவர்களை மீண்டும் சரிபார்க்கவும். சரிபார்க்கப்பட்ட வேட்பாளர் மாறும்போது ரயிலையும் அதன் CI ஐயும் புதுப்பிக்கவும்.
3. பொருந்தக்கூடிய வரிசை பயன்முறையின் கீழ் ஒரு இணைப்பு உறுதியுடன் ரயிலை PR தரையிறக்கவும். லைவ் பயன்முறையில், வரிசையின் `merge-ff` இறங்கும் முறை, ஒன்றிணைப்புகளை பாதுகாக்கிறது. அசல் உறுப்பினர் தலைவர்கள் வெளியீட்டு கிளையில் இருந்து அணுகலாம். GitHub உறுப்பினர் PRs இணைக்கப்பட்டதாகக் குறிக்கிறது மற்றும் கமிட்டிகள் தங்கள் ஆசிரியர்களைத் தக்கவைத்துக்கொள்கின்றன.

ஒரு பொது உதாரணம் [PR #21071](https://github.com/cheaper-inference/OmniRoute/pull/21071). இது 18 உறுப்பினர் PRs இணைத்து, 2026-11-24 அன்று ஒரு இணைப்பு உறுதியுடன் இறங்கியது.

`main` இலிருந்து அடுத்த வெளியீட்டு கிளைக்கு ஒரு ஒத்திசைவு-பேக் ஒரு இணைப்பு உறுதி மூலம் தரையிறங்குகிறது. பிற்கால ஒத்திசைவுகளுக்கு `main` வம்சாவளியைப் பாதுகாப்பது அவசியம். [ஒர்க்ட்ரீ தனிமைப்படுத்தலைப்](WORKTREE_ISOLATION.md#sync-back-landings-are-merge-commits-never-squash) பார்க்கவும்.

## உள்ளூர் ஒன்றிணைப்பு-ரயில் வேலிடேட்டர்

```bash
scripts/release/merge-train.sh [--plan] [--fast] <base-branch> <PR#> [<PR#>...]
```

வேலிடேட்டர் அடிப்படை மற்றும் PR ஹெட்களைப் பெற்று, அவற்றை ஒரு செலவழிப்பு வேலை மரத்தில் இணைக்கிறது. இதன் விளைவாக வரும் மரத்தில் ஒரு முறை அதன் சமநிலை தொகுப்பை இயக்குகிறது. தோல்வியுற்ற தலையைப் பெறுதல் அல்லது ஒன்றிணைத்தல் முரண்பாடு PR ஐ வெளியேற்றுகிறது மற்றும் மீதமுள்ள PRs உடன் ஸ்கிரிப்ட் தொடர்கிறது.

- **`--plan`** தேர்ந்தெடுக்கப்பட்ட பயன்முறையின் படிகளை அச்சிட்டு, பணிமரத்தை உருவாக்காமல் அல்லது ரிமோட்டைத் தொடர்பு கொள்ளாமல் வெளியேறுகிறது. வேகமான திட்டத்தை ஆய்வு செய்ய அதை `--fast` உடன் இணைக்கவும்.
- **`--fast`** பொதுவான நிலையான வாயில்கள், தேர்ந்தெடுக்கப்பட்ட மாற்றப்பட்ட `node:test` கோப்புகளை `tests/unit/`, மற்றும் `npm run test:vitest` ஆகியவற்றின் கீழ் இயக்குகிறது. ஃபாஸ்ட் பயன்முறையைப் பயன்படுத்தும் போது, திரட்டப்பட்ட முனையில் ஒரு நாளைக்கு ஒரு முறையாவது முழு உள்ளூர் சரிபார்ப்பை இயக்கவும்.
- **முழு பயன்முறை** முழு-மட்டும் நிலையான வாயில்களைச் சேர்த்து `npm run test:unit` மற்றும் `npm run test:vitest` இயக்குகிறது.

அடிப்படை ஆய்வு இருந்தால், தோல்வியுற்ற நிலையான கேட் தொடப்படாத தளத்தில் மீண்டும் இயக்கப்படும். ஸ்கிரிப்ட் பரம்பரை தோல்விகளைப் புகாரளிக்கிறது மற்றும் ஒவ்வொரு அங்கீகரிக்கப்பட்ட மீறல் வரியும் அடிவாரத்தில் தோன்றும் மற்றும் மொத்த எண்ணிக்கை அதிகரிக்காதபோது தொடர்கிறது.

| வெளியேறு | பொருள்                                                                                                                                                                            |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`      | திட்டம் அச்சிடப்பட்டது அல்லது தொகுப்பை நிறைவு செய்தது. தொகுப்புச் சுருக்கமானது மரபுவழி நிலையான தோல்விகள் மற்றும் வெளியேற்றப்பட்ட PRs பட்டியலிடுகிறது.                             |
| `1`      | தவறான வாதங்கள், Git செக்அவுட் இல்லை, ப்ரீஃப்லைட் தோல்வியடைந்தது அல்லது PR ஏறவில்லை.                                                                                               |
| `2`      | ஒரு தொகுப்பு சரிபார்ப்பு தோல்வியடைந்தது மற்றும் மரபுரிமையாக தகுதி பெறவில்லை. ஆபரேட்டர் தொகுப்பை இரண்டாகப் பிரிக்கலாம், புண்படுத்தும் PR வெளியேற்றலாம் மற்றும் மீண்டும் இயக்கலாம். |

ஒரு உள்ளூர் பாஸ் உரிமையாளரின் ஆவணத்திற்கு மட்டுமே கண்டறியும் ஆதாரத்தை வழங்குகிறது. ஒவ்வொரு தரையிறக்கத்திற்கும் உரிமையாளரின் அங்கீகாரம், அதன் சொந்த தேவையான காசோலைகள் மற்றும் பொருந்தும் போது நிழல் வரிசை தீர்ப்பு ஆகியவை இன்னும் தேவை.

## வரிசைப்படுத்துதல்

- **ஒரு PR.** மாற்றப்பட்ட பாதைகளின் அடிப்படையில் CI மற்றும் தரம் தேர்வு காசோலைகள். கோட் PRs வேகமான தர வாயில்கள் மற்றும் தாக்கப்பட்ட சோதனைகளை இயக்குகிறது, CI இல் தனி அலகு மற்றும் Vitest வேலைகள்.
- **ஒரு வரிசை வேட்பாளர்.** CI மற்றும் Quality ஆகியவை இயற்றப்பட்ட வேட்பாளருக்கான முழு சுயவிவரத்தை அதன் வரிசையில் ref இல் இயக்குகின்றன.
- **வெளியீட்டு உதவிக்குறிப்புக்கு.** வெளியீடு-பச்சை அதன் பாதை வடிப்பான்களுடன் பொருந்தக்கூடிய புஷ்களில் விரைவான கடின வாயில்களை இயக்குகிறது. ஒரு நாளைக்கு மூன்று திட்டமிடப்பட்ட ஓட்டங்கள் வெளியீட்டு கிளைக்கு முழு ஸ்வீப்பைப் பயன்படுத்துகின்றன.
- **ஒரு வெளியீட்டிற்கு.** முழு CI மேட்ரிக்ஸில் E2E துண்டுகள், தொகுப்பு சரிபார்ப்பு, டார்பால் பூட் ஸ்மோக் மற்றும் கவரேஜ் காசோலைகள் ஆகியவை அடங்கும். [வெளியீட்டு சரிபார்ப்புப் பட்டியலைப்](RELEASE_CHECKLIST.md) பார்க்கவும்.

## `merge-train.sh` க்கான புதிய-செக்அவுட் முன்நிபந்தனைகள்

பணிமரங்களை உருவாக்கும் முன் முன்னோட்டம் இயங்கும். `npm ci` உடன் சார்புகளை நிறுவவும். `node_modules/.bin/tsc` இயங்கக்கூடியது மற்றும் `node_modules/node_modules` இல்லை என்பதை உறுதிப்படுத்தவும். `node_modules/.bin/bun --version` வெற்றியடைகிறதா என்று சரிபார்க்கவும்.

Bun postinstall தவிர்க்கப்பட்டிருந்தால், `(cd node_modules/bun && node install.js)` இயக்கவும். வழங்குநரின் நிலைத்தன்மை மற்றும் அறியப்பட்ட-சின்னச் சரிபார்ப்புகள் Bun பயன்படுத்துகின்றன. வேலிடேட்டர் `npm run check:cycles:ratchet` தடுக்கும் வாயிலாக இயக்குகிறது. தனித்த `npm run check:cycles` கட்டளை ஆலோசனையாகும்.
