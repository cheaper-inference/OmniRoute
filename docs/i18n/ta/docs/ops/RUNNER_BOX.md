சுயமாக ஹோஸ்ட் செய்யப்பட்ட pool **.113** பெட்டியில் (`tomni-proxmox-113`) இயங்குகிறது. 2026-10-18 முதல் ஒவ்வொரு
OmniRoute runner-க்கும் **ஒரே ஒரு role**, ஒரே ஒரு label மற்றும் அதன் workload-இல் அளவிடப்பட்ட தேவைக்கேற்ப
memory/CPU budget உள்ளது. Turbopack slot-க்கு build-க்குத் தேவையான வளங்கள் கிடைக்கின்றன; மற்ற slot-கள்
அவற்றின் அளவிடப்பட்ட உச்சநிலைகளுக்கு ஏற்ப ஒதுக்கப்பட்டுள்ளன. Turbopack build ஒன்று Release-Green
webpack build மற்றும் lint job உடன் ஒரே நேரத்தில் இயங்கும்போது மட்டுமே அந்தப் பெட்டி அளவுக்கு மீறி வளங்களை ஒதுக்குகிறது;
host swap (16 GB) அதைச் சமாளிக்கிறது, மேலும் pull-request Build-கள் hosted சூழலில் இயங்குவதால்

`systemctl set-property --runtime … MemoryHigh=… MemoryMax=… CPUQuota=…` மூலம் நேரடியாகப் பயன்படுத்தப்பட்டன — restart செய்யப்படவில்லை, எனவே
இயங்கிக்கொண்டிருந்த எந்த job-மும் பாதிக்கப்படவில்லை. Label-கள் runners API மூலம் (`gh api -X DELETE repos/<repo>/actions/runners/<id>/labels/<label>` /
`gh api -X POST repos/<repo>/actions/runners/<id>/labels -f 'labels[]=<label>'`) நேரடியாகவே மாற்றப்படுகின்றன.

## பராமரிப்பு ஸ்கிரிப்டை நிறுவுதல் (ஒரே முறை, சர்வரில்)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ஒவ்வொரு 30 நிமிடங்களுக்கும், /var/log/runner-janitor.log-இல் பதிவுசெய்யவும்
*/30 * * * * MAX_ACTIVE_RUNNERS=8 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` அவசியம்: ஒரு பாதையை அகற்றுவதற்கு முன், திறந்துள்ள கோப்புகளின் ஒரே ஒரு
snapshot மூலம் அது செயலற்றிருப்பதைப் பராமரிப்பு ஸ்கிரிப்ட் உறுதிப்படுத்துகிறது; இந்தக் கருவி
இல்லாவிட்டால், அது எதையும் அகற்றாமல் அதைக் குறிப்பிடுகிறது (exit 1).
எந்த மாற்றத்தையும் முதலில் `--dry-run` கொண்டு முயற்சிக்கவும் — அது என்ன செய்யும் என்பதைத்
துல்லியமாக அச்சிடும்; எதையும் மாற்றாது.

ஒவ்வொரு இயக்கத்திலும் இது செய்வது: **tmpfs-இல் 3 மணிநேரத்திற்குப்** பிறகும், வட்டிலுள்ள
`_work/_temp`-இல் 24 மணிநேரத்திற்குப் பிறகும் எங்களுடைய எஞ்சியவற்றை (`runner-*`,
`omniroute-*`, `next-build*`, `e2e-build.tar.gz`) அகற்றுகிறது; 75 நிமிடங்களுக்கும்
பழைய `next-build`-ஐ நிறுத்துகிறது (எந்தப் பணியும் அவ்வளவு நேரம் இயங்காது — 2026-08-27
அன்று GitHub அதன் பணி தொலைந்துவிட்டதாக அறிவித்த பிறகும் ஒன்று 70 நிமிடங்கள் இயங்கியது);
unit **நிறுத்தப்பட்டுள்ள** runner-களின் 48 மணிநேரம் பழைய checkout-களை நீக்குகிறது;
வட்டு பயன்பாடு ≥ 85 %, நினைவக PSI `full/avg60` ≥ 10 %, மற்றும் listener-களின் எண்ணிக்கை
`MAX_ACTIVE_RUNNERS`-ஐ விட அதிகமாக இருக்கும்போது எச்சரிக்கிறது (omniroute/மற்றவை என்ற
வகைப்பாட்டுடன்). Exit 1 = கவனம் தேவை; பதிவைப் படிக்கவும்.

GitHub ஏற்கெனவே கைவிட்டுவிட்ட ஒரு build-ஐ 75 நிமிட விதி கண்டறியாது.
`Runner.Listener` தனது பணியைப் புதுப்பிக்க முடியாதபோது, `_diag/Runner_*.log`-இல்
`POST request to …/renewjob timed out after 100 seconds` எனக் காட்டப்படும்; கடைசியாக
வெற்றிகரமாகப் புதுப்பித்த சுமார் பத்து நிமிடங்களுக்குப் பிறகு API அந்தப் பணி `completed`
(தோல்வி) எனத் தெரிவிக்கும்; ஆனால் எந்தப் பணியும் இணைக்கப்படாமல் `next-build` தொடர்ந்து
இயங்கும் (2026-10-18: #17066-இன் Build 19:43 மணிக்குத் தோல்வியடைந்தது, ஐந்து
நிமிடங்களுக்குப் பிறகும் அதன் build 40 GB-ஐப் பயன்படுத்திக்கொண்டிருந்தது). மிகப் புதிய
`_diag/Worker_*.log`-இல் ref-ஐ உறுதிப்படுத்தி, பின்னர் PID மூலம் build tree-க்கு மட்டும்
SIGTERM அனுப்பவும் — `next-build`, `npm run build`, `build-next-isolated.mjs` மற்றும்
`_work` worker-கள். `Runner.Listener`, `RunnerService.js` அல்லது `Runner.Worker`-ஐ
ஒருபோதும் தொடாதீர்கள்: worker அந்தப் பணி ரத்துசெய்யப்பட்டதாகத் தெரிவிக்கும்; listener
தானாகவே மீண்டும் online-க்கு வரும்.

## Runner unit-கள்: KillMode

Runner-இன் இயல்புநிலை `KillMode=process`, ஒரு unit நிறுத்தப்படும்போதோ மறுதொடக்கம்
செய்யப்படும்போதோ `Runner.Worker → npm → next-build`-ஐ இயங்கிக்கொண்டே விட்டுவிடுகிறது —
எந்தப் பணியும் இணைக்கப்படாமல் ஒரு orphan build தொடர்ந்து RAM மற்றும் CPU-ஐப்
பயன்படுத்தும். ஒவ்வொரு OmniRoute unit-லும்
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
என்ற drop-in உடன் `KillMode=mixed` உள்ளது: முதலில் listener-க்கு SIGTERM, பின்னர்
`TimeoutStop` நேரத்தில் முழு cgroup-க்கும் SIGKILL. Unit அடுத்த முறை மறுதொடக்கம்
செய்யப்படும்போது இது செயல்படும் — **ஒரு நேரத்தில் ஒரு runner-ஐ மட்டும், அது செயலற்றிருக்கும்போது
மட்டும்**, செயலற்ற நிலைச் சரிபார்ப்பையும் மறுதொடக்கத்தையும் ஒரே command-இல் செய்து
மறுதொடக்கம் செய்யவும்.

## செயல்பாட்டு விதிகள்
