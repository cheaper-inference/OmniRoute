`copilot-m365-web` (அலியாஸ் `m365copilot`) `m365.cloud.microsoft/chat` இல் அங்கீகரிக்கப்பட்ட Microsoft 365 Copilot அமர்வு மூலம் OpenAI- வடிவ அரட்டை கோரிக்கைகளை அனுப்புகிறது. இது ஒரு அதிகாரப்பூர்வமற்ற சொந்த ஒருங்கிணைப்பு: தனி ப்ராக்ஸி செயல்முறை அல்லது லோக்கல் ஹோஸ்ட் அப்ஸ்ட்ரீம் தேவையில்லை. வழங்குநர் ID, மாற்றுப்பெயர் மற்றும் ஏற்கனவே உள்ள இறக்குமதி செய்யப்பட்ட இணைப்புகள் மாறாமல் உள்ளன. `copilot-web` என்பது `copilot.microsoft.com` இல் நுகர்வோர் சேவைக்கான வேறுபட்ட வழங்குநராகும்.

> **வலை குக்கீ வழங்குநர்களுக்கு புதியதா?**
>
> படிக்கவும்**`docs/getting-started/WEB-COOKIE-GUIDE.md`** பொது அமைவு செயல்முறை, அங்கீகார வழிகாட்டுதல், வரம்புகள் மற்றும் இந்த வழங்குநர்-குறிப்பிட்ட வழிகாட்டியைப் பின்பற்றும் முன் சரிசெய்தல்.
>
> **மரபு இறக்குமதிகளுக்கு:** இந்த வழங்குநருக்கான நற்சான்றிதழ்** குக்கீ அல்ல** . `m365.cloud.microsoft` இலிருந்து குக்கீகளை நகலெடுக்க வேண்டாம். நற்சான்றிதழ் என்பது WebSocket URL வினவல் அளவுரு மற்றும் பாதை பிரிவு ஆகும், இவை இரண்டும் DevTools நெட்வொர்க் தாவலில் இருந்து படிக்கப்படும்.

## முன்நிபந்தனைகள்

- `m365.cloud.microsoft/chat` இல் Copilot அணுகலுடன் ஒரு Microsoft 365 கணக்கு
- DevTools WebSocket ஆய்வுக்கான Chromium அடிப்படையிலான உலாவி (Chrome, Edge).
- அந்தக் கணக்கில் கோரப்பட்ட மாதிரிக்கான அணுகல்; குத்தகைதாரர் மற்றும் உரிமத்தைப் பொறுத்து கிடைக்கும் தன்மை மாறுபடும்

## சொந்த உள்நுழைவு (பணி அல்லது பள்ளி கணக்குகள்)

தேர்வு செய்யவும்**Microsoft 365 Copilot → இணைக்கவும்** மற்றும் உள்நுழைவு முயற்சியை தயார் செய்யவும். டாஷ்போர்டு PKCE உடன் அங்கீகார-குறியீட்டு ஓட்டத்தைப் பயன்படுத்துகிறது; இது உங்கள் Microsoft கடவுச்சொல் அல்லது MFA குறியீட்டைக் கேட்காது.

1. திற a** வெற்று உலாவி தாவல்** , பின்னர் திறக்கவும்**DevTools → நெட்வொர்க்** மற்றும் செயல்படுத்தவும்** பதிவை பாதுகாக்கவும்** . Microsoft க்கு செல்லும் முன் இதைச் செய்யுங்கள் : Windows SSO உடனடியாக முடிவடையும்.
2. இணைப்பு உரையாடல் மூலம் காட்டப்படும் அங்கீகார URL நகலெடுத்து, தயாரிக்கப்பட்ட தாவலில் அதற்கு செல்லவும். Microsoft இன் கணக்குத் தேர்வை அல்லது MFA கோரப்பட்டால் முடிக்கவும்.
3. பாதுகாக்கப்பட்ட பிணைய பதிவில், `https://login.microsoftonline.com/common/oauth2/nativeclient` கோரிக்கையைக் கண்டறிந்து அதன் முழுமையை நகலெடுக்கவும்** கோரிக்கை URL** .
4. இணைப்பு உரையாடலில் அந்த URL ஒட்டவும் மற்றும் இணைக்கவும். ஒரு மூலக் குறியீடு அல்லது இறுதி `wrongplace` முகவரி-பட்டி URL ஒட்ட வேண்டாம்: தேவைப்படும் அழைப்பு ஒரு தற்காலிக வழிசெலுத்தலாகும்.

ஒவ்வொரு முயற்சியும் பத்து நிமிடங்களுக்குப் பிறகு காலாவதியாகும் மற்றும் ஒரு முறை மட்டுமே பயன்படுத்த முடியும். குறியீட்டை மாற்றுவதற்கு முன் சேவையகம் அதன் நிலை, PKCE சரிபார்ப்பு மற்றும் மறு அங்கீகார இலக்கு ஆகியவற்றைச் சரிபார்க்கிறது. காலாவதி அல்லது பரிமாற்ற தோல்விக்குப் பிறகு, புதிய முயற்சியைத் தொடங்கவும். சேவையகத்தை மறுதொடக்கம் செய்வதன் மூலம் ஒரு முயற்சியைத் தக்கவைக்க முடியாது.

டோக்கன்கள் ஏற்கனவே உள்ள இணைப்பு நற்சான்றிதழ் அங்காடியைப் பயன்படுத்துகின்றன மற்றும் பாதையைப் புதுப்பிக்கின்றன. இணைப்பை மறுஅங்கீகரிப்பதற்கு அதே Microsoft tenant/object அடையாளம் தேவை, அதே மின்னஞ்சல் மட்டும் அல்ல. இது ஆபரேட்டர் naming/settings பாதுகாக்கிறது மற்றும் காலாவதியான இறக்குமதி செய்யப்பட்ட நற்சான்றிதழ்களை மாற்றுகிறது. சொந்த உள்நுழைவு work/school கணக்குகளுக்கானது; ஏற்கனவே உள்ள இணைப்புகள் மற்றும் ஆதரிக்கப்படும் அடுக்கு கட்டமைப்புகளுக்கு மரபு இறக்குமதி பாதை உள்ளது.

முழு கால்பேக் URL ஒரு முறை நற்சான்றிதழ் ஆகும். ஸ்கிரீன்ஷாட்கள், பதிவுகள், ஆதரவு செய்திகள் அல்லது கமிட்களில் அதை ஒருபோதும் சேர்க்க வேண்டாம். இந்த ஓட்டம் சேவையகத்தில் உலாவியைத் திறக்காது, உங்கள் உலாவி வரலாற்றை ஆய்வு செய்யாது அல்லது உள்ளூர் அழைப்பு சேவையகத்தைத் தொடங்காது.

## நற்சான்றிதழ் பிடிப்பு (WebSocket முறை)

1. `https://m365.cloud.microsoft/chat` இல் உள்நுழைந்து உரையாடலைத் தொடங்கவும்.
2. திற**DevTools → நெட்வொர்க்** .
3. வடிகட்டவும்**WS** (WebSocket)
4. Chathub WebSocket இணைப்பைக் கிளிக் செய்யவும். `wss://substrate.office.com/m365Copilot/Chathub/` இல் தொடங்கும் URL ஐத் தேடுங்கள்.
5. அதன் இருந்து** கோரிக்கை URL** , நகல்:
   - `access_token` வினவல் அளவுரு மதிப்பு (ஒரு குறுகிய கால JWT).
   - `/Chathub/` க்குப் பிறகு Chathub பாதை பிரிவு (எ.கா. `<oid>@<tenant>`).

முழு URL வடிவம் உள்ளது:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute இல், தேர்ந்தெடுக்கவும்**Microsoft 365 Copilot** , மரபு API-key/import விருப்பத்தைத் தேர்ந்தெடுத்து, நற்சான்றிதழை வடிவமைப்பில் ஒட்டவும்:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. கிளிக் செய்யவும்** சோதனை இணைப்பு** மற்றும்** சேமிக்கவும்** .

## நற்சான்றிதழ் பிடிப்பு (HAR இறக்குமதி)

WebSocket URL இலிருந்து மதிப்புகளை கைமுறையாக நகலெடுப்பதற்குப் பதிலாக, நீங்கள் ஒரு DevTools HAR கோப்பை ஏற்றுமதி செய்யலாம்:

1. திற**DevTools → நெட்வொர்க்** .
2. Microsoft 365 Copilot உரையாடலைத் தொடங்கவும் அல்லது தொடரவும் (இது WebSocket இணைப்பைத் தூண்டுகிறது).
3. நெட்வொர்க் பேனலில் வலது கிளிக் செய்து தேர்ந்தெடுக்கவும்** உள்ளடக்கத்துடன் அனைத்தையும் HAR ஆக சேமிக்கவும்** .
4. OmniRoute இல், பயன்படுத்தவும்** .har கோப்பை இறக்குமதி செய்யவும்** வழங்குநர் இணைப்பு உரையாடலில் உள்ள பொத்தான்.

OmniRoute Chathub WebSocket URL க்கான HAR ஸ்கேன் செய்கிறது, `access_token` மற்றும் `chathubPath` ஐ பிரித்தெடுக்கிறது மற்றும் நற்சான்றிதழ் புலங்களை தானாகவே நிரப்புகிறது. HAR இறக்குமதியானது JWT காலாவதியை டிகோட் செய்து மீதமுள்ள டோக்கன் வாழ்நாளைக் காட்டுகிறது.

> **உண்மையான HAR ஏற்றுமதி, அணுகல் டோக்கன் அல்லது புதுப்பிப்பு டோக்கனை ஒருபோதும் செய்ய வேண்டாம்.** சோதனை மற்றும் ஆவண மதிப்புகள் எப்போதும் ஒதுக்கிடங்களாக இருக்க வேண்டும்.

## டோக்கன் வாழ்நாள் மற்றும் புதுப்பித்தல்

`access_token` குறுகிய காலம் (பொதுவாக**~ 75 நிமிடங்கள்** ) பயன்படுத்தக்கூடிய புதுப்பிப்பு டோக்கன் இல்லாமல், காலாவதியான பிறகு நீங்கள் நற்சான்றிதழை மீண்டும் கைப்பற்ற வேண்டும்.

### `refreshToken` உடன் தானியங்கி புதுப்பிப்பு

Microsoft 365 வழங்குநர்களில்** இணைப்பைச் சேர்க்கவும்** அல்லது** இணைப்பைத் திருத்து** உரையாடல், திறந்த** மேம்பட்ட அமைப்புகள் → புதுப்பிப்பு டோக்கன் (விரும்பினால்)** . `substrate.office.com/sydney` நோக்கத்திற்காக Microsoft OAuth புதுப்பிப்பு டோக்கனை ஒட்டவும் மற்றும் சேமிக்கவும். உள்ளீடு மறைக்கப்பட்டுள்ளது மற்றும் சேமிக்கப்பட்ட டோக்கனுடன் ஒருபோதும் நிரப்பப்படவில்லை. திருத்தும் போது, ஏற்கனவே உள்ள டோக்கனை வைத்திருக்க அதை காலியாக விடவும்; அதற்கு பதிலாக புதிய டோக்கனை ஒட்டவும்.

Microsoft ஒன்றைத் திரும்பப் பெறும்போது, நேட்டிவ் உள்நுழைவு புதுப்பிப்பு டோக்கனைப் பெறுகிறது. மரபு இறக்குமதிகளுக்கு, ஏற்கனவே உள்ள இணக்கமான Microsoft அங்கீகார-குறியீட்டு மானியத்தைப் பயன்படுத்தவும்; இந்த வழங்குநர் சாதன-குறியீட்டு ஓட்டத்தை செயல்படுத்தவில்லை அல்லது உறுதியளிக்கவில்லை. புதுப்பிப்பு டோக்கன் உள்ளமைக்கப்பட்ட நிலையில், OmniRoute கோரிக்கைகளுக்கு முன் `access_token` சரிபார்த்து, அதற்குப் புதுப்பித்தல் தேவைப்படும்போது மட்டும் புதுப்பிக்கும். ஒரு வெற்றிகரமான புதுப்பிப்பு, சுழற்றப்பட்ட புதுப்பிப்பு டோக்கனைத் தொடரும், புதுப்பிப்பு டோக்கன் செல்லுபடியாகும் போது கைமுறையாக மீண்டும் கைப்பற்றுவதைத் தவிர்க்கிறது.

`refreshToken` அமைக்கப்படவில்லை எனில், ஒவ்வொரு காலாவதிக்குப் பிறகும் நீங்கள் கைமுறையாக WebSocket நற்சான்றிதழை மீண்டும் கைப்பற்ற வேண்டும்.

### அடுக்கு தேர்வு

| அடுக்கு      | மாற்றுப்பெயர்  | மேற்பரப்பு             |
| ------------ | -------------- | ---------------------- |
| `individual` | _(இயல்புநிலை)_ | நுகர்வோர் M365 Copilot |
| `edu`        | `included`     | கல்வி M365 Copilot     |
| `enterprise` | `work`         | வேலைக்கான M365 Copilot |

அடுக்கை அமைக்கவும்** மேம்பட்ட அமைப்புகள் → Copilot அடுக்கு** . பூர்வீக உள்நுழைவு அதை அமைக்கவில்லை, எனவே ஒரு பணிக் கணக்கு `enterprise` (மாற்று `work`) மற்றும் கல்விக் கணக்கு `edu` தேர்ந்தெடுக்க வேண்டும், மேலும் ஆவணப்படுத்தப்பட்ட மாதிரி IDs பயன்படுத்தும் போது: அவர்கள் தங்கள் சொந்த தொனி, காட்சி மற்றும் உரிம வகையைத் தேர்வு செய்கிறார்கள், ஆனால் முகவர் மற்றும் அழைப்பு விருப்பங்கள் இன்னும் அடுக்கில் இருந்து வருகின்றன, மேலும் தனிப்பட்ட இயல்புநிலைகள் பணிபுரியும் குடியிருப்பாளரிடம் தோல்வியடையும். அடுக்கை மாற்றுவது மாதிரி உரிமத்தை வழங்காது. வெளிப்படையான மேம்பட்ட நெறிமுறை மேலெழுதுதல் முன்னுரிமை பெறுகிறது மற்றும் தேவையான கம்பி மதிப்புகள் உங்களுக்குத் தெரிந்தால் மட்டுமே பயன்படுத்தப்பட வேண்டும்.

## மாதிரிகள் மற்றும் ரூட்டிங்

பூர்வீக அட்டவணையில் அனைத்து ஆவணப்படுத்தப்பட்ட தனித்தனி IDs மற்றும் நான்கு அசல் சொந்த IDs ஆகியவை அடங்கும். பட்டியல் நிலையானது மற்றும் கணக்குச் சார்பற்றது, கணக்கு உரிமை ஆய்வு அல்ல: இணைக்கப்பட்ட கணக்கு அவற்றைப் பயன்படுத்த முடியாதபோதும் கட்டண வழிகள் மற்றும் பொருந்தக்கூடிய மாற்றுப்பெயர்கள் பட்டியலிடப்பட்டிருக்கும். மாடல் டிஸ்ப்ளே லேபிள்கள் வழங்குநரின் பெயரையும் ஒவ்வொரு மாடலின் கிடைக்கும் கொதிகலனையும் தவிர்க்கின்றன; வழங்குபவர் இருக்கிறார்**Microsoft 365 Copilot** . லேபிள்கள் குறிக்கப்பட்டன** மாற்றுப்பெயர்** அல்லது** மரபு** அவற்றின் தற்போதைய அடையாளங்காட்டிகள் மற்றும் நெறிமுறை வரைபடங்களைத் தக்கவைத்துக்கொள்ளுங்கள், வரலாற்று மாதிரி பதிப்பின் உத்தரவாதம் அல்ல. தனித்த ப்ராக்ஸிகள்** /மாடல்களில் இருந்து இறக்குமதி செய்யவும்** இந்த சொந்த WebSocket வழங்குநருக்கு அறிவுறுத்தல்கள் பொருந்தாது.

| ----------------- | ------------------------------------------------------------------------------------------------ |
| தானியங்கி         | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| முன்னதாக GPT      | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |

`auto`, `quick`, `think-deeper`, மற்றும் பதிப்பு மாற்றுப்பெயர்கள் போன்ற மாற்றுப்பெயர்களும் பதிவு செய்யப்பட்டுள்ளன. தற்போதுள்ள `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` மற்றும் `copilot-m365-gpt-5-5-chat` ஆகியவை செல்லுபடியாகும். ஆவணப்படுத்தப்பட்ட IDs க்கு வழங்குநர் முன்னொட்டு (`copilot-m365-web/claude-opus` அல்லது `m365copilot/claude-opus`) தேவை: பல பொதுவான சொற்கள் அல்லது பிற விற்பனையாளர்களின் மாதிரி பெயர்கள், எனவே ஒரு வெற்று `claude-opus` இந்த வழங்குநர் இல்லாமல் ரூட்டிங் செய்யும். பதிவு என்பது ஒவ்வொரு கணக்கிற்கும் Microsoft அந்த மாதிரியை வழங்குகிறது என்பதற்கான வாக்குறுதி அல்ல. தனித்த IDs பொது [நெறிமுறை அட்டவணையைப்](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) பின்பற்றுகிறது (ஏற்றுமதி செய்யப்பட்ட மாதிரி-க்கு-தொனி வரைபடம் மற்றும் அதன் மாதிரி-அறியும் காட்சி மெட்டாடேட்டா). அனைத்து சொந்த சுயவிவரங்களும் `availability: "unverified"` ஐத் தக்கவைத்துக்கொள்கின்றன; பட்டியலில் சேர்ப்பது வெற்றிகரமான கணக்கு சோதனை அல்ல.

- ஒரு வெளிப்படையான மாதிரி உரிமம் மறுப்பு திரும்பும்** 403** `m365_model_not_licensed`, 502 அல்ல. connection/model ஜோடியை ரூட்டிங் பூட்டுகள், இணைப்பில் உரிமம் பெற்ற மாதிரிகள் பயன்படுத்தக்கூடியதாக இருக்கும்.
- `InvalidCopilotLicense` என்பது கணக்கு அளவிலான உரிமம் மறுப்பு, `m365_account_not_licensed` என தனித்தனியாகப் புகாரளிக்கப்படுகிறது.
- ஒரு பயனர் த்ரோட்டில் திரும்பும்** 429** `m365_throttled` மற்றும் இணைப்பை குளிர்விக்கிறது. முன்னுரிமை-அணுகல் சோர்வு திரும்பும்** 429** `priority_access_exhausted` மற்றும் மாதிரி நோக்கம் கொண்டது. `errorCode: "ReasoningTurnExhausted"` உடன் `OutOfCredits` இன் முடிவு** 429** அதற்குப் பதிலாக `reasoning_turns_exhausted`, மாதிரி-நோக்கம் கொண்டது, மீட்டமைக்கும் நேரம் எதுவும் கோரப்படவில்லை. குயிக் டோன்கள் தொடர்ந்து சேவை செய்யும் போது "ஆழமாக சிந்தியுங்கள்" டோன்களை மூடுவதற்கு ஒரு வேலை வாடகைதாரர் மீது புகாரளிக்கப்பட்டது; நோக்கம் ஒரு நுகர்வோர் கவனிப்பு, இந்த களஞ்சியம் மீண்டும் உருவாக்கியது அல்ல. எனவே ரூட்டிங் மற்ற ஆவணப்படுத்தப்பட்ட திங்க் டீப் மாடல்களான `gpt-5.5` மற்றும் `gpt-5.6` ஆகியவற்றை அதே கூல்டவுனுக்காக அந்த இணைப்பின் சுழற்சியிலிருந்து வெளியேற்றுகிறது, மேலும் விரைவு டோன்களையும் மற்ற எல்லா தோல்விகளையும் அதன் சொந்த மாதிரியில் விட்டுவிடுகிறது. வழங்கப்பட்ட மறு முயற்சி குறிப்புகள் பாதுகாக்கப்படுகின்றன; விடுபட்ட மீட்டமைப்பு அறியப்பட்ட மீட்டமைப்பு நேரமாக விளம்பரப்படுத்தப்படவில்லை.
- ஒரு Copilot பாதுகாப்பு மறுப்பு (`Disengaged`) திரும்பும்** 400** `provider_safety_rejection`, பகிரப்பட்ட வழங்குநர் பாதுகாப்பு-நிறுத்த லேபிள். இணைப்பின் ஆரோக்கியத்திற்கு எதிராக இது ஒருபோதும் கணக்கிடப்படாது, கிளையன்ட் SDKs 400 ஐ மீண்டும் முயற்சிக்க வேண்டாம், மேலும் `PROVIDER_SAFETY_STOPS_TERMINAL` இயக்கப்பட்ட காம்போ ரூட்டிங் மற்றொரு இலக்குக்கு எதிராக கோரிக்கையை மீண்டும் இயக்குவதற்குப் பதிலாக அங்கேயே நிறுத்தப்படும்.
- ஒரு இணைப்புக்கான கோரிக்கைகள் ஏற்கனவே இருக்கும் கணக்கு செமாஃபோர் மூலம் வரிசைப்படுத்தப்படுகின்றன. இணையான பேனல்களைக் காட்டிலும் முன்னுரிமை வீழ்ச்சியை விரும்பு; வரிசையாக்கம் மட்டும் Microsoft இன் உரையாடல்-விகித வரம்புகளை அகற்றாது.

## நடத்தை மற்றும் வரம்புகளைக் கோருங்கள்

- கருவிகள் ஆகும்** உடனடி-முன்மாதிரி** , சொந்த Microsoft செயல்பாடு அழைப்புகள் அல்ல. ஒரு கருவி-இயக்கப்பட்ட கோரிக்கை ஒரு இடையக தலைமுறையைப் பயன்படுத்துகிறது; கருவிகளைத் தேர்ந்தெடுப்பதில் அது மற்றொரு தலைமுறையைச் செலவிடாது. சரியான ஆதரவு வாத வடிவங்களைக் கொண்ட அறிவிக்கப்பட்ட கருவிகள் மட்டுமே அழைப்புகளாக வழங்கப்படும்.
- ஒரு முன்னோடி உதாரணத்துடன் நீண்ட கட்டமைக்கப்பட்ட பதில் உரைநடையாகப் பாதுகாக்கப்படுகிறது. இது ஒரு ஹூரிஸ்டிக், நோக்கத்திற்கான ஆதாரம் அல்ல; பயன்பாடுகள் இன்னும் தங்கள் சொந்த கருவி அனுமதிகளை செயல்படுத்த வேண்டும்.
- பட உள்ளீடு இணைய கிளையன்ட் அனுப்பும் விதத்தில் செயல்படுகிறது. ஒவ்வொரு படப் பகுதியும் (`image_url` ஒரு தரவு URL அல்லது ஒரு பொது HTTPS URL, அல்லது ஒரு பதில்கள் `input_image`) `/m365Copilot/UploadFile` இல் அரட்டை டோக்கனுடன் திருப்பத்தின் உரையாடலில் பதிவேற்றப்படும், மேலும் செய்தி ஒரு `ImageFile` சிறுகுறிப்புடன் அதை சுட்டிக்காட்டுகிறது; உரை அமர்ந்த இடத்தைக் குறிக்கிறது (`[image 1]`, …). ஒரு புதிய உரையாடல் வரலாற்றில் உள்ள ஒவ்வொரு படத்தையும் பதிவேற்றுகிறது, புதிய செய்திகளின் படங்களை மட்டுமே தொடரும். 10 PNG, JPEG, GIF அல்லது WebP படங்கள் அதிகபட்சம் 10 MiB ஒவ்வொன்றும் (ஒரு கோரிக்கைக்கு 40 MiB ); வடிவம் பைட்டுகளிலிருந்து படிக்கப்படுகிறது. HTTPS URLs பொது-மட்டும், DNS-பின்ன் செய்யப்பட்ட ரிமோட் இமேஜ் கார்டு மூலம் பெறப்படுகிறது. தோல்வியுற்ற பதிவேற்றம் கோரிக்கையை தோல்வியடையச் செய்கிறது (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` அல்லது `m365_image_invalid`); கொடுக்கப்பட்ட உருவம் இல்லாமல் ஒரு திருப்பம் ஒருபோதும் முன்னேறாது. உரை அல்லாத பிற பகுதிகள் (ஆடியோ, கோப்புகள்) வெளிப்படையாக நிராகரிக்கப்படுகின்றன, அமைதியாக கைவிடப்படவில்லை.
- பின்தொடர்தல் கோரிக்கையானது அதே அப்ஸ்ட்ரீம் உரையாடலைத் தொடர்கிறது மற்றும் முந்தைய பதிலுக்குப் பிறகு செய்திகளை மட்டுமே அனுப்புகிறது. அது அந்த பதிலை சரியாக நீட்டிக்க வேண்டும்: அதே இணைப்பு, மாதிரி சுயவிவரம் மற்றும் கருவி தொகுப்பு; மாறாத வரலாறு (ஒவ்வொரு செய்தியிலும் ஒரு sha256 சங்கிலி); மற்றும் பதிலின் டூல்-அழைப்பு ஐடிகள் அல்லது அதன் உரை இடைவெளி வரை இருக்கும். வேறு ஏதேனும் (திருத்தப்பட்ட வரலாறு, அதே முதல் செய்தியுடன் மற்றொரு அமர்வு, வேறு பதில், 30 நிமிடங்களுக்கு செயலற்ற உரையாடல் அல்லது Copilot இன் 600-செய்தித் தொப்பிக்கு அருகில், ஐடி இல்லாத இணைப்பு) முழு வரலாற்றுடனும் புதிய உரையாடலைத் தொடங்கும். தோல்வியுற்ற திருப்பம் மீண்டும் தொடங்கப்படாது, மேலும் புதிய உரையாடலில் ஒருமுறை உள்ளடக்கம் இல்லாத `InternalError` மீண்டும் அனுப்பப்படும் (** 502** `m365_internal_error` மீண்டும் தோல்வியுற்றால்). தொடர்ச்சிகள் செயல்முறை நினைவகத்தில் வைக்கப்படுகின்றன: மறுதொடக்கம் புதிய உரையாடல்களைத் தொடங்கும்.
- ஒவ்வொரு திருப்பமும் Copilot இன் தற்காலிக அரட்டையில் இயங்கும் (`disableMemory=1`): உரையாடல் இயங்கும் போது அதன் சூழலை வைத்திருக்கும் மற்றும் கணக்கின் அரட்டை வரலாற்றில் தோன்றாது. மாடல் சோதனைகள், அனைத்தையும் சோதிக்கவும் மற்றும் காம்போ சோதனைகள் உரையாடல்களை விட்டுவிடாமல் இந்த வழங்குநரை ஆய்வு செய்யலாம்.
- ஒரு திருப்பத்தில் 120-வினாடிகள் செயலற்ற காலக்கெடு மற்றும் வரம்பிற்குட்பட்ட ஒட்டுமொத்த காலக்கெடுவும் உள்ளது. இறுதி-மட்டும் பதில்கள், முன்னேற்றத்தை வடிகட்டுதல் மற்றும் ரத்துசெய்தல் ஆகியவை சொந்த transport/composer. ஆல் கையாளப்படுகின்றன
- இணைய அடிப்படையிலான பதில்கள் அவற்றின் ஆதாரங்களை வைத்திருக்கின்றன. Copilot தனிப்பட்ட பயன்பாட்டுக் கட்டுப்பாட்டு எழுத்துகளுடன் ஒரு மேற்கோளைக் குறிக்கிறது மற்றும் ஆதாரங்களை `references` ஆக அனுப்புகிறது; ஒவ்வொரு மார்க்கரும் எண்ணிடப்பட்ட மார்க் டவுன் இணைப்பாக (`[1](https://…)`, அல்லது Copilot மார்க்கரை ஒரு இணைப்பு இலக்காகப் பயன்படுத்தும் போது வெற்று URL ) பொருந்தக்கூடிய `url_citation` சிறுகுறிப்புடன் (`message.annotations`, அல்லது இணைப்பைச் சுமந்து செல்லும் துண்டில் `delta.annotations` ) ஆகிறது. ஒருபோதும் வராத ஒரு ஆதாரம் கைவிடப்பட்டது, எனவே குறிப்பான்கள் வாடிக்கையாளரை சென்றடையாது. ஸ்ட்ரீமிங் செய்யும்போது, மேற்கோளுக்குப் பிறகு உரை அதன் மூலம் வரும் வரை காத்திருக்கும்.
- Copilot இன் தர்க்கச் சுருக்கம் (`ChainOfThoughtSummary`), மாதிரி ஒன்றை அனுப்பும் போது, `reasoning_content` என திருப்பி அனுப்பப்படும், ஒருபோதும் பதிலின் ஒரு பகுதியாக இருக்காது. தன்னைத்தானே மாற்றி எழுதும் ஒரு சுருக்கம், முறை தவறாமல் ஸ்ட்ரீமிங்கை நிறுத்துகிறது.
- எந்தவொரு உள்ளடக்கத்திற்கும் முன், ஸ்ட்ரீமிங் கோரப்பட்டாலும் licence/throttle தோல்விகள் HTTP 403/429 ஐத் தக்கவைத்துக் கொள்ளும். உள்ளடக்கம் தொடங்கிய பிறகு, தோல்விகள் SSE பிழை நிகழ்வுகள், ஒருபோதும் வெற்றிகரமான முடிவாக இருக்காது. அப்ஸ்ட்ரீம் மீள்எழுதுதல், append-only streaming மூலம் குறிப்பிடப்பட முடியாத ஒரு வெளிப்படையான ஸ்ட்ரீம் பிழை; ஸ்ட்ரீமிங் அல்லாத மற்றும் இடையகக் கருவி பதில்கள் இறுதி உரையைத் தக்கவைத்துக்கொள்கின்றன.
- Copilot இணைப்பையே மறுக்கும் போது, அதன் பதில் பின்வருமாறு தெரிவிக்கப்படும்:** 401** நிராகரிக்கப்பட்ட அல்லது காலாவதியான உள்நுழைவுக்கான `m365_unauthorized` (மீண்டும் உள்நுழையவும்),** 429** த்ரோட்டிங்கிற்கான அதன் `Retry-After`, மற்றும் ஒரு கைகுலுக்கல் தோல்வி, ஒரு பொதுவான இணைப்பு தோல்வி.

## பட உருவாக்கம்

`model: "copilot-m365-web/m365-copilot-image"` உடன்`POST /v1/images/generations` (அலியாஸ் `m365copilot/m365-copilot-image`) இணைய கிளையன்ட் செய்வது போல, Copilot இன் உள்ளமைக்கப்பட்ட படக் கருவி மூலம் வரைகிறது. ஒவ்வொரு படமும் ஒரு Copilot டர்ன் ஆகும்: இது இணைய கிளையண்டின் பட விருப்பத்தை அமைத்து `GenerateGraphicArt` அறிவிக்கிறது, மேலும் Microsoft இன் டிசைனர் சேவையில் உள்ள ஒரு கலைப்பொருளை சுட்டிக்காட்டி முன்னேற்ற நுழைவில் படம் வந்து சேரும். அந்த கலைப்பொருள் அரட்டை டோக்கனை மறுக்கிறது, எனவே இணைப்பின் புதுப்பிப்பு டோக்கனில் இருந்து OmniRoute ஒரு வடிவமைப்பாளர் டோக்கனை உருவாக்கி பைட்டுகளைப் பதிவிறக்குகிறது; டோக்கன் எப்போதும் `designerapp.officeapps.live.com` க்கு மட்டுமே அனுப்பப்படும்.

- சொந்த உள்நுழைவு இணைப்பு தேவை (புதுப்பிப்பு டோக்கன்); ஒட்டப்பட்ட டோக்கன் தோல்வியடைந்தது** 400** எந்த திருப்பமும் செலவழிக்கும் முன்.
- `n` 1-4, ஒவ்வொன்றும் ஒரு முறை. `size` மட்டுமே நோக்குநிலையை (அகலமான, உயரமான அல்லது சதுரம்) வழிநடத்துகிறது, இது Copilot ஆனது வரியில் இருந்து படிக்கிறது; Copilot ரெண்டர் அளவைத் தேர்ந்தெடுக்கிறது.
- படங்கள் இன்லைனில் வழங்கப்படுகின்றன: இயல்புநிலையாக `b64_json`, `response_format: "url"` க்கான தரவு URL.
- உருவாக்கப்பட்ட படங்கள் அரட்டையிலிருந்து தனித்தனியாக, சிறிய தினசரி பட்ஜெட்டில் வரையப்படும். அது பயன்படுத்தப்படும் போது கோரிக்கை தோல்வியுற்றது** 429** . படமில்லாமல் பதிலளிக்கும் ஒரு திருப்பம் தோல்வியடைகிறது** 502** (அல்லது** 400** /** 503** Copilot இன் உரை ஒரு மறுப்பு அல்லது திறன் பிரச்சனை என வாசிக்கும்போது); செய்தி கூறுகிறது.

## பாதுகாப்பு மாதிரி

- **அதிகாரப்பூர்வமற்ற ஒருங்கிணைப்பு.** இந்த வழங்குநர் BizChat WebSocket நெறிமுறையைத் தலைகீழாகப் பொறியியலாக்குகிறார். Microsoft இறுதிப்புள்ளியை மாற்றும் போது அது முன்னறிவிப்பின்றி உடைந்து போகலாம்.
- `subscriptionRisk: true` கொடியானது ஒருங்கிணைப்பு ஆவணமற்ற இறுதிப்புள்ளியில் தங்கியுள்ளது என்பதை பிரதிபலிக்கிறது. கணக்கு கட்டுப்பாடுகள் சாத்தியம் ஆனால் உறுதிப்படுத்தப்படவில்லை.
- அணுகல் டோக்கன் குறுகிய கால JWT ஆகும். கடவுச்சொல்லைப் போலக் கருதுங்கள்: அதைச் செய்யவோ, பதிவு செய்யவோ அல்லது பகிரவோ வேண்டாம்.
- புதுப்பிப்பு டோக்கன் Microsoft 365 மேற்பரப்புக்கான தற்போதைய அணுகலை வழங்குகிறது. ஒரு API விசையைப் போலவே அதைச் சேமித்து வைக்கவும்.

## சரிசெய்தல்

### அங்கீகாரம் உடனடியாக தோல்வியடைகிறது

- இதிலிருந்து நீங்கள் நகலெடுத்துள்ளீர்கள் என்பதைச் சரிபார்க்கவும்**WebSocket URL** , XHR/Fetch கோரிக்கையிலிருந்து அல்ல. நற்சான்றிதழ் Chathub WebSocket இணைப்பு — இன் `access_token` வினவல் அளவுருவில் உள்ளது `Authorization: Bearer` தலைப்பில் இல்லை.
- `chathubPath` URL பாதையிலிருந்து முழு `<oid>@<tenant>` பிரிவையும் உள்ளடக்கியிருப்பதை உறுதிசெய்யவும்.

### டோக்கன் ~ 75 நிமிடங்களுக்குப் பிறகு காலாவதியாகிறது

இது எதிர்பார்க்கப்படுகிறது. `refreshToken` இல்லாமல், அணுகல் டோக்கன் குறுகிய காலம் நீடிக்கும். ஒன்று:

- DevTools இலிருந்து நற்சான்றிதழை மீண்டும் கைப்பற்றவும், அல்லது
- கட்டமைக்கவும்** மேம்பட்ட அமைப்புகள் → புதுப்பிப்பு டோக்கன் (விரும்பினால்)** தானாக புதுப்பிப்பதற்கான இணைப்பைச் சேர் அல்லது திருத்து உரையாடலில்.

### சோதனை இணைப்பு கடந்துவிட்டது, ஆனால் அரட்டை 401ஐத் தருகிறது

உடன் உருவாக்கப்பட்ட இணைப்பிற்கு** Microsoft உடன் உள்நுழையவும்** , சோதனை இணைப்பு அணுகல் டோக்கனின் காலாவதியைச் சரிபார்த்து, சேமிக்கப்பட்ட புதுப்பிப்பு டோக்கனுடன் காலாவதியான டோக்கனைப் புதுப்பிக்கிறது, எனவே தேர்ச்சி சோதனையானது புதுப்பிப்பு டோக்கன் இன்னும் செயல்படுவதை நிரூபிக்கிறது.

ஒட்டப்பட்ட நற்சான்றிதழுக்காக, சோதனை இணைப்பு நற்சான்றிதழின் வடிவத்தைச் சரிபார்க்கிறது மற்றும் டோக்கன் காலாவதியாகும் போது, வழங்குநர் பயன்படுத்தும் டோக்கன் காலாவதியாகவில்லை (இணைப்பின் சேமிக்கப்பட்ட டோக்கன் பழைய பேஸ்ட்டை வெல்லும்; புதுப்பித்த டோக்கன் புதுப்பிக்கத்தக்கதாகக் கணக்கிடப்படும்). காலாவதியாகும் முன் ரத்து செய்யப்பட்ட டோக்கன் இன்னும் சோதனையில் தேர்ச்சி பெறுகிறது; அரட்டை பின்னர் திரும்பும்** 401** `m365_unauthorized`. பயன்படுத்தவும்** Microsoft உடன் உள்நுழைக** மீண்டும், அல்லது புதிய நற்சான்றிதழை மீண்டும் கைப்பற்றவும்.

### வழங்குநர் பட்டியலில்Copilot தோன்றவில்லை

`copilot-m365-web` இயக்கப்பட்டிருப்பதை உறுதிசெய்யவும்** டாஷ்போர்டு → வழங்குநர்கள்** . வழங்குநர் சில அடுக்குகளில் முன்னிருப்பாக மறைக்கப்படலாம்.
