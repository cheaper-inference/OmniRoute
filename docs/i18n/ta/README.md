## 💰 ~ 1.62B டோக்கன்கள் / மாதம் முழுவதும் மூன்றாம் தரப்பு இலவச அடுக்குகள்

> **உங்கள் சொந்த வழங்குநர் கணக்குகளைக் கொண்டு வாருங்கள்.** இது தனித்தனியாக தகுதியான மூன்றாம் தரப்பு இலவச அடுக்குகளில் மதிப்பிடப்பட்ட மொத்தமாகும், OmniRoute வழங்கும் டோக்கன் மானியம் அல்ல. பதிவுசெய்து, தேவைப்படும் இடங்களில் நற்சான்றிதழ்களைப் பெற்று, நீங்கள் பயன்படுத்தக்கூடிய வழங்குநர்களை இணைக்கவும்; ஒவ்வொரு வழங்குநரும் அதன் வரம்புகள், கிடைக்கும் தன்மை மற்றும் விதிமுறைகளை கட்டுப்படுத்துகிறது.
>
> இலவச அடுக்குகளை கையால் அடுக்கி வைப்பது வேதனையானது — டஜன் கணக்கான SDKs, டஜன் கணக்கான கட்டண வரம்புகள் மற்றும் உங்களிடம் உண்மையில் எவ்வளவு உள்ளது என்பது தெரியவில்லை. OmniRoute பட்டியல்கள்** 34 தொடர் பூல் விசைகளில் 465 இலவச அடுக்கு உள்ளீடுகள்** மற்றும் டோக்கன் தலைப்பைக் கணக்கிடுகிறது** வெளியிடப்பட்ட பாசிட்டிவ் மாதாந்திர வரவுசெலவுத் திட்டத்துடன் 17 குளங்கள் மற்றும் ஒரு மாடலுக்கு ஐந்து Groq தொப்பிகள்** , பகிரப்பட்ட குளம் மூலம் நகலெடுக்கப்பட்டது. பிராந்திய அடையாளச் சரிபார்ப்புக்குப் பிறகு மட்டுமே திறக்கப்படும் ஒதுக்கீடுகள் (இன்று: ModelScope) தனித்தனியாகக் காட்டப்படும், பிராந்திய அடையாளச் சரிபார்ப்பிற்குப் பின்னால் +~ 6M இருக்கும், மேலும் அவை தலைப்புச் செய்தியில் சுருக்கப்படவில்லை. முடிவு டாஷ்போர்டில் தெரியும் (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute free-tier budget card: ~1.62B free tokens per month steady, up to ~2.22B in the first month with signup credits, from 34 documented recurring pool keys covering 465 cataloged free-tier entries behind one endpoint. Routing depends on available eligible connections and provider limits."/>

```bash
# After connecting a provider, copy your OmniRoute key from Dashboard → Endpoints:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

## 📡 OmniRoute Radar

மேலே ஆவணப்படுத்தப்பட்ட, பகிரப்பட்ட தொகுப்புகளில் உள்ள நகல்களை நீக்கிய பட்டியலிலிருந்து கிடைக்கும் முக்கிய இலவச அடுக்கு அளவு **~1.62B டோக்கன்கள்/மாதம்** ஆகவே உள்ளது. வழங்குநர்களின் தற்காலிகப் பதிவுச் சலுகைகள் முதல்
மாதத்திற்கான அளவைத் தனியாக **~2.22B** வரை உயர்த்தக்கூடும். OmniRoute வெளியீடுகளுக்கு இடைப்பட்ட காலத்தில்
இலவச மாடல்களின் கிடைப்புநிலை குறித்த புதிய தகவல்களை விரும்புபவர்களுக்காக Radar ஒரு விருப்பத் தேர்வாகக் கிடைக்கும், கையொப்பமிடப்பட்ட பட்டியல் மேலடுக்காகும்; சமூகப் பட்டியலும் ஏற்கெனவே உள்ள ஒவ்வொரு இலவச
அம்சமும் தொடர்ந்து இலவசமாகவே இருக்கும்.

ஆதரவாளர்கள் நேரடிப் பட்டியலையும் கூடுதல் வழங்குநர் வாய்ப்புகளையும் பெறலாம். வழங்குநர்களின் கிடைப்புநிலையைப் பொறுத்து, இதன் தனியான,
மாற்றத்தக்க உச்சவரம்பு **அதிகபட்சமாகச் சுமார் 3B டோக்கன்கள்/மாதம்** ஆகும்.
இந்த உச்சவரம்பிற்கு உத்தரவாதம் இல்லை: வழங்குநர்கள் ஒதுக்கீடுகள், தகுதித் தேவைகள், மாடல்கள் அல்லது பிராந்தியங்களை
எந்த நேரத்திலும் மாற்றலாம்.

Radar-ஐப் பயன்படுத்தத் தனியாகச் சம்மதிக்க வேண்டும்; இது GET கோரிக்கைகளை மட்டுமே பயன்படுத்துகிறது. OmniRoute கிளையன்ட் ப்ராம்ப்ட்கள், போக்குவரத்து, வழங்குநர்
உள்ளமைவு, பயன்பாட்டுத் தொலைஅளவீடு அல்லது அறிவிப்புகளை நிராகரித்த உள்ளூர் நிலை ஆகியவற்றைப் பதிவேற்றாது. தகுதித் தேவைகளையும்
தற்போதைய பட்டியலையும் **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)**-இல் அறிந்துகொள்ளுங்கள்.

## 🔌 முழுமையான CLI + A2A & MCP

</div>

> சேவையகத்தைத் தாண்டி, OmniRoute என்பது **80+ கட்டளைகளைக்** கொண்ட ஒரு **முழுமையான கட்டளை-வரி கட்டுப்பாட்டு மையம்**; மேலும், திறந்த முகவர் நெறிமுறைகளின் மூலம் ஓர் AI முகவர் அதை **தானாகவே** இயக்க முடியும்.

### ⌨️ உண்மையான CLI (`start` மட்டும் அல்ல)

```bash
omniroute               # நுழைவாயில் + கட்டுப்பாட்டுப் பலகையை வழங்கும் (போர்ட் 20128)
omniroute chat          # ஊடாடும் TUI அரட்டை கிளையன்ட் (ஸ்லாஷ்: /model /combo /skill /memory)
omniroute setup         # வழிகாட்டப்படும் முதல் இயக்க அமைவு வழிகாட்டி
omniroute doctor        # வழங்குநர்கள், போர்ட்கள், நேட்டிவ் சார்புகளைச் சோதிக்கும்
```

### 🛰️ தொலைநிலைப் பயன்முறை — CLI-ஐ இங்கே இயக்கி, OmniRoute-ஐ VPS-இல் இயக்குங்கள்

OmniRoute ஒரு சேவையகத்தில் உள்ளதா? **அதே CLI** மூலம் உங்கள் மடிக்கணினியிலிருந்து அதை இயக்குங்கள். வரையறுக்கப்பட்ட அணுகல் டோக்கனைக் கொண்டு ஒருமுறை உள்நுழையுங்கள்;
அதன்பின் ஒவ்வொரு கட்டளையும் தொலைநிலைச் சேவையகத்தைக் குறிவைக்கும்.

```bash
omniroute connect 192.168.0.15            # கடவுச்சொல் → வரையறுக்கப்பட்ட டோக்கன், ஒரு சூழலாகச் சேமிக்கப்படும்
omniroute models                         # ← தொலைநிலைச் சேவையகத்திற்கு எதிராக இயங்கும்
omniroute configure codex                 # ← தொலைநிலை மாதிரியைத் தேர்ந்தெடுத்து, உள்ளூர் Codex சுயவிவரத்தை எழுதும்
omniroute tokens create --name ci --scope read   # பிற கணினிகளுக்காக இன்னும் குறுகிய வரம்புள்ள டோக்கன்களை உருவாக்கும்
omniroute contexts use default            # ← உள்ளூர் சேவையகத்திற்கு மீண்டும் மாறும்
```

டோக்கன்கள் `read` / `write` / `admin` என வரையறுக்கப்பட்டுள்ளன; செயல்முறைகளைத் தொடங்கும் வழித்தடங்கள் loopback-க்கு மட்டுமே கட்டுப்படுத்தப்பட்டிருக்கும்.

### 🎚️ Engines-ஐத் தாண்டி — வெளியீட்டு பாணிகள், adaptive dial மற்றும் ஒவ்வொரு request-க்கான கட்டுப்பாடு

மேலுள்ள 12 engines, **உள்ளே** செல்லும் உள்ளீட்டைச் சுருக்குகின்றன. மேலும் மூன்று அடுக்குகள், **எப்படி**, **எப்போது**, மற்றும் வெளியே வருவது என்ன என்பதை வடிவமைக்கின்றன:

- **🪄 Output Styles** _(வெளியீட்டு அச்சு வழிநடத்தல்)_ — deterministic, cache-safe response-shaping வழிமுறைகளைச் செலுத்துகின்றன; ஒன்றுடன் ஒன்று இணைக்கக்கூடியவை, ஒவ்வொன்றும் `lite` / `full` / `ultra` தீவிர நிலைகளில் கிடைக்கும். ஒரு style-ஐச் சேர்ப்பது registry-ல் ஒரு வரியைச் சேர்ப்பது மட்டுமே:
  - **சுருக்கமான உரை** — filler / articles / hedging-ஐ நீக்கி; தொழில்நுட்ப உள்ளடக்கத்தைத் துல்லியமாக வைத்திருக்கும்.
  - **குறைந்த code** — "சோம்பேறி senior dev" YAGNI: செயல்படும் மிகச்சிறிய மாற்றம், கோரப்படாத scaffolding இல்லை.
  - **Ponytail (சோம்பேறி senior dev)** — YAGNI படிக்கட்டில் மேலேறி, அடிப்படைக் காரணத்தைச் சரிசெய்து, செயல்படும் மிகச்சிறிய diff.
  - **எனக்கு ADHD உள்ளது (action-first)** — அடுத்த செயல் முதலில் வரும், படிகள் எண்ணிடப்படும், ஒரு தெளிவான அடுத்த படி மட்டும், முன்னுரை இல்லை.
  - **Terse CJK (文言)** — classical-Chinese ultra-terse பாணி (`zh` locale-க்கு மட்டும்).
- **🎯 Adaptive context-budget** _(dial)_ — ஒரே on/off token threshold-க்கு பதிலாக, model-ன் context window-க்குள் **பொருந்தும்** அளவுக்கு மட்டுமே, குறைந்த செலவுடையதும் தகவல் இழப்பு குறைவானதுமான engines-ஐ அதிகரிக்கிறது. Policy: `reserve-output` (default, model-aware) · `percentage` · `absolute`. Mode: `floor` (பொருந்துவதை உறுதி செய்கிறது) · `replace-autotrigger` (உங்கள் explicit தேர்வு முன்னுரிமை பெறும்) · `off` (legacy threshold).
- **🎛️ Compression தீர்மானிக்கப்படும் இடம்** _(precedence, high → low)_ — ஒவ்வொரு request-க்குமான `x-omniroute-compression` header › routing-combo override › active named profile › adaptive / auto-trigger › panel default › off. பயன்படுத்தப்பட்ட plan, `X-OmniRoute-Compression: <mode>; source=<source>` response header-ல் திரும்ப வழங்கப்படும்.

Token threshold மூலம் auto-trigger செய்யவும், adaptive dial-ஐ இயக்கவும், named profile-ஐ pin செய்யவும், ஒவ்வொரு request-க்கும் ஒருமுறை அமைக்கவும், அல்லது ஒவ்வொரு routing combo-க்கும் pipeline-ஐ ஒதுக்கவும் — workload-க்கு ஏற்றதைத் தேர்ந்தெடுக்கலாம். Opt-in offline **eval harness** (`npm run eval:compression`), மாற்றத்தை promote செய்வதற்கு முன் pinned corpus-ல் fidelity மற்றும் savings-ஐ மதிப்பிடுகிறது.

`:latest` மிக உயர்ந்ததைப் பின்பற்றுகிறது** வெளியிடப்பட்டது** நிலையான SemVer. இது git `main` கண்காணிக்காது. GitOps க்கு `:X.Y.Z` பின் செய்யவும். [Docker வெளியீட்டு சேனல்களைப்](docs/guides/DOCKER_GUIDE.md#release-channels) பார்க்கவும் .பட பின்கள்**`OMNIROUTE_MEMORY_MB=1024`** . டேஷ்போர்டுக்கும், லேசான அரட்டைக்கும் இது போதும்.** குறியீட்டு முகவர்கள்** ( Claude குறியீடு, Codex, Grok, …) இலிருந்து`POST /v1/responses` மிகப் பெரிய V8 குவியல் அல்லது செயல்முறை `FATAL ERROR` s ~ 12 GiB இல் இரண்டு ஒன்றுடன் ஒன்று நீண்ட சூழல்களின் கீழ் தேவை. குவியலுக்கு மேலே உள்ள கொள்கலனின் அளவை அளவிடவும் (சொந்த இடையகங்கள் V8க்கு வெளியே அமர்ந்திருக்கும்):

| பணிச்சுமை                                  | குவியல் (`-e OMNIROUTE_MEMORY_MB`) | கொள்கலன் (`--memory`) |
| ------------------------------------------ | ---------------------------------- | --------------------- |
| டாஷ்போர்டு / ஒளி அரட்டை                    | `1024` (படம் இயல்புநிலை)           | ≥ 2 கிராம்            |
| ஒரு குறியீட்டு முகவர்                      | `8192`                             | ≥ 10 கிராம்           |
| இரண்டு ஒரே நேரத்தில் நீண்ட `/v1/responses` | `10240`–`12288`                    | ≥ 12-16 கிராம்        |

### பங்களிப்பது எப்படி

1. களஞ்சியத்தை Fork செய்யவும்
2. **செயலில் உள்ள** `release/vX.Y.Z` முனையிலிருந்து (`main` இலிருந்து அல்ல) கிளையை உருவாக்கவும் — [கிளை பிரித்தல் மற்றும் வெளியீட்டு மாதிரி](docs/ops/BRANCHING_MODEL.md) ஐப் பார்க்கவும்
3. உங்கள் அம்சக் கிளையை உருவாக்கவும் (`git checkout -b feat/amazing-feature`)
4. உங்கள் மாற்றங்களை கமிட் செய்யவும் (`git commit -m 'feat: add amazing feature'`)
5. கிளைக்குத் தள்ளவும் (`git push origin feat/amazing-feature`)
6. **base = அந்த `release/vX.Y.Z` கிளை** என அமைத்து Pull Request-ஐத் திறக்கவும்

விரிவான வழிகாட்டுதல்களுக்கு [CONTRIBUTING.md](CONTRIBUTING.md) ஐப் பார்க்கவும்.
