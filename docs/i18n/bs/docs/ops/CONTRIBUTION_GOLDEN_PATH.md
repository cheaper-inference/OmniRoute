Koristite ovaj vodič kako biste odabrali najmanju pouzdanu razvojnu petlju za pull request. On ne
zamjenjuje dokumente o arhitekturi i sigurnosti za određena područja, na koje su veze navedene u nastavku; povezuje svaku uobičajenu
vrstu izmjene s njenim ugovorima, ciljanim provjerama i CI pokrivenošću.

## Put koji slijedi svaka izmjena

1. **Odaberite osnovnu granu prije uređivanja.** Pronađite najvišu aktivnu granu `release/v*` i kreirajte granu iz
   njenog vrha. Kao cilj odaberite tu granu, a ne `main`. Ako je aktivno zamrzavanje izdanja, nemojte kao cilj odabrati zamrznutu
   granu; koristite sljedeći aktivni ciklus opisan u dokumentu
   [Model grananja i izdanja](BRANCHING_MODEL.md).
2. **Navedite ugovore.** Identifikujte svaki katalog, shemu, generisani artefakt, javni API ili korisničko
   sučelje na koje izmjena utiče. Tabela u nastavku navodi minimalni početni skup.
3. **Napišite ili ažurirajte ciljane testove.** Izmjene produkcijskog koda u `src/`, `open-sse/`, `electron/` ili
   `bin/` zahtijevaju automatizovani test u istom PR-u. Pokrenite najmanji skup testnih datoteka koje dokazuju
   ponašanje, a zatim navedene ciljane provjere.
4. **Prepustite CI-u pokretanje široke matrice.** Kompletni segmenti jediničnih testova, Vitest, postepeno povećavanje pokrivenosti i
   produkcijska izgradnja pokreću se na PR-u. Pokrenite širok paket lokalno samo kada ciljani neuspjeh ukazuje na
   širi uticaj ili kada izmjena obuhvata nekoliko podsistema.
5. **Uskladite izmjene prije pregleda.** Dohvatite aktivnu osnovnu granu, pregledajte njene nove commitove i razliku svojih izmjena u odnosu
   na nju, a zatim uradite rebase ili spojite osnovnu granu u skladu s tokom rada za doprinositelje. Riješite sukobe generisanih datoteka
   i kataloga polazeći od njihovog izvora, ponovo ih generišite, ponovo pokrenite ciljanu petlju i potvrdite da
   PR i dalje cilja aktivnu granu izdanja.
6. **Zabilježite dokaze.** U PR predlošku navedite pokrenute naredbe, svaku dodanu ili izmijenjenu testnu datoteku,
   migracije ili zastavice funkcionalnosti te sve validacije koje se izvršavaju samo u CI-u i još uvijek su na čekanju.

## Preporučeni putevi prema vrsti izmjene

Naredbe u nastavku predstavljaju minimalne ciljane provjere, a ne dopuštenje da preskočite test koji direktno pokriva
ponašanje koje ste izmijenili.

### Pružalac usluga

**Ugovori**

- Definicija pružaoca usluga u `src/shared/constants/providers/` i njeno sastavljanje u
  `src/shared/constants/providers.ts`.
- Modeli i mogućnosti u `open-sse/config/providerRegistry.ts` ili njegovim izdvojenim datotekama registra.
- Odabir izvršitelja/prevodioca, OAuth konfiguracija ili konfiguracija API ključa, resursi kontrolne ploče i generisana
  referenca pružaoca usluga kada je primjenjivo.
- Javni pristupni podaci moraju koristiti `resolvePublicCred()`; odgovori s greškama moraju koristiti zajedničke pomoćne funkcije za
  sanitizaciju grešaka. Pogledajte `docs/security/PUBLIC_CREDS.md` (git; nije kompiliran u `/docs`) i
  [Sanitizacija grešaka](../security/ERROR_SANITIZATION.md).

**Ciljana petlja**

```bash
npm run check:provider-consistency
npm run check:provider-assets
node --import tsx/esm --test tests/unit/provider-translate-path-golden.test.ts
node --import tsx/esm --test tests/unit/<provider-or-executor>.test.ts
npm run gen:provider-reference   # kada se katalog promijeni; commitujte generisanu razliku
npm run lint
```

Također testirajte svaku obuhvaćenu porodicu zahtjeva: chat, Responses, slike, ugrađivanja, zvuk ili video.
Pregledajte generisane razlike kataloga i referentnih rezultata kao izmjene ugovora; nemojte ih slijepo prihvatiti.

### Usmjeravanje

**Ugovori**

- Javne vrijednosti strategija i metapodaci korisničkog sučelja u `src/shared/constants/routingStrategies.ts`.
- Raspoređivanje i redoslijed u `open-sse/services/combo.ts` i `open-sse/services/combo/`.
- Combo sheme, perzistencija, stanje otpornosti, mogućnosti modela i API/UI kontrole.
- [Auto-Combo mehanizam](../routing/AUTO-COMBO.md) i dokumentacija o otpornosti kada se ponašanje promijeni.

**Ciljana petlja**

```bash
node --import tsx/esm --test tests/unit/combo-<behavior>.test.ts
npm run test:combo:matrix        # izmjene strategije ili raspoređivanja
npm run check:known-symbols      # izmjene registracije strategije
npm run lint
```

Lokalno koristite determinističke testove s lažnim uzvodnim servisima. Aktivni combo smoke testovi zahtijevaju pristupne podatke i
izvode se ručno; nisu zamjena za CI.

### UI / UX

**Ugovori**

- Granice Next.js ruta/stranica i zajedničkih komponenti u `src/app/` i
  `src/shared/components/`.
- Oblici API odgovora, stanja učitavanja/praznog sadržaja/grešaka, ponašanje tastature i čitača ekrana,
  responzivni raspored, teme i proširenje lokalizacije.
- Izvorni tekstovi korisničkog sučelja na engleskom jeziku u `src/i18n/messages/en.json`; nemojte direktno upisivati novi tekst namijenjen korisnicima.

**Ciljana petlja**

```bash
node --import tsx --test tests/unit/dashboard/<feature>.test.ts
npx vitest run --config vitest.config.ts tests/unit/ui/<component>.test.tsx
npm run check:dashboard-typecheck
npm run lint
```

Pokrenite aplikaciju za interaktivne ili vizuelne izmjene i provjerite uske i široke prikaze. CI pokreće
produkcijsku izgradnju i šire pakete testova; vizuelno ponašanje i dalje zahtijeva ciljani test komponente, Playwright test
ili dokumentovanu ručnu provjeru primjerenu izmjeni.

### i18n

**Ugovori**

- `src/i18n/messages/en.json` je izvor za korisničko sučelje; `config/i18n.json` je izvor lokalizacija.
- CLI katalozi se nalaze zasebno u `bin/cli/locales/`.
- Očuvajte ICU rezervisana mjesta i oznake u potpuno istom obliku. Nemojte prevoditi nazive proizvoda/pružalaca usluga/modela,
  nazive protokola i zaglavlja, naredbe, identifikatore koda/JSON-a, URL-ove, varijable okruženja ili
  zaštićene pojmove kao što su `OmniRoute`, `OAuth`, `MCP` i `A2A`. Trenutna izvorna lista je
  `scripts/i18n/glossary/protected-terms.json`.

**Ciljana petlja**

```bash
npm run i18n:sync-ui:dry
npm run i18n:check-ui-coverage
npm run i18n:check-value-drift
npm run i18n:check-glossary
npm run check:cli-i18n          # kada se promijene CLI tekstovi/katalozi
npm run lint
```

Ovo su smjernice za postojeći sistem, a ne poziv da proširite njegove alate ili model ključeva.
Neka i18n zakrpe budu precizno ograničene dok se osmišljava zamjenski sistem. Nemojte pokretati naredbe za prevođenje
koje pozivaju vanjske servise osim ako zadatak izričito zahtijeva generisane prijevode i ako ste
pregledali nastalu razliku.

### CLI

**Ugovori**

- Javne komande i opcije u `bin/cli/`, generirane API komande, izlazni kodovi, stdout/stderr i
  strukture JSON izlaza, ponašanje konfiguracije/okruženja i datoteke uključene u paket.
- Tekstovi CLI-ja namijenjeni korisnicima moraju koristiti CLI i18n sloj, a katalozi `en`/`pt-BR` moraju ostati usklađeni.
- Zadržite Node kao podržano izvršno okruženje i ugovor objavljene binarne datoteke.

**Fokusirani ciklus**

```bash
node --import tsx/esm --test tests/unit/cli/<command>.test.ts
npm run check:cli-i18n
npm run build:cli             # promjene generiranog/pakovanog CLI-ja
npm run check:pack-policy     # promjene javne površine paketa
npm run lint
```

Koristite tačnu komandu u privremenom direktoriju podataka kada ponašanje zavisi od raščlanjivanja, datoteka ili izlaznog
statusa. CI obavlja šire provjere artefakata paketa i ekosistema.

### Baza podataka

**Ugovori**

- Domenski moduli nalaze se u `src/lib/db/`; direktno uvozite određene module (stari sloj za ponovni izvoz `localDb.ts` je uklonjen).
- Numerirane, idempotentne SQL migracije nalaze se u `src/lib/db/migrations/`, uz sigurnost transakcija, ponašanje pri
  nadogradnji, indekse i svakog pozivaoca na kojeg utiče shema.
- Rute i rukovaoci nikada direktno ne izvršavaju sirovi SQL.

**Fokusirani ciklus**

```bash
npm run check:migration-numbering
npm run check:db-rules
node --import tsx/esm --test tests/unit/db/<domain>.test.ts
node --import tsx/esm --test tests/unit/db/migration-<number>.test.ts
npm run lint
```

Pri dodavanju migracije testirajte i novu bazu podataka i nadogradnju s prethodne sheme. Testovi baze podataka
moraju zatvoriti sve rukovaoce i pozvati `resetDbInstance()` tokom čišćenja. Pokrenite `npm run test:bun:db` samo kada
se promijeni putanja Bun adaptera bez garancije podrške; Node ostaje mjerodavan.

### Izgradnja / implementacija

**Ugovori**

- Korijenski manifest i manifesti radnih prostora/datoteka zaključavanja, `scripts/build/`, samostalno sastavljanje Next.js aplikacije, sadržaj
  paketa `dist/`, metapodaci Electron platforme, CI radni tokovi i kontrolne oznake implementacije.
- Podržani rasponi Node verzija i dozvoljena upotreba Bun-a u `CLAUDE.md` moraju ostati nepromijenjeni.
- Artefakti izgradnje ne smiju se pratiti; primjenjuju se pravila za zavisnosti, licence, radne tokove i pakete.

**Fokusirani ciklus**

```bash
node --import tsx/esm --test tests/unit/build/<behavior>.test.ts
npm run check:build-scope
npm run check:lockfile         # promjene zavisnosti ili datoteke zaključavanja
npm run check:pack-policy      # promjene javne površine objavljenog paketa
npm run lint
```

Lokalno koristite `npm run build` samo kada promjena utiče na kompilaciju, samostalno sastavljanje, resurse
ili pakovanje izvršnog okruženja. Koristite `npm run build:release` samo za provjeru izdanja/implementacije. CI izgradnja je
konačni višeplatformski signal; promjene specifične za Electron platformu zahtijevaju odgovarajuću fokusiranu izgradnju
ili dokaz dimnog testa.

## Razvojne skripte za dijeljeni računar

Dva pomoćna alata u `scripts/dev/` implementiraju lokalnu petlju na razvojnom računaru na kojem su aktivne druge sesije:

```bash
scripts/dev/typecheck-touched.sh --base release/vX.Y.Z   # datoteke iz merge-base(HEAD, base)..HEAD
scripts/dev/typecheck-touched.sh src/a.ts tests/unit/b.test.ts   # tačno ove datoteke
scripts/dev/new-worktree.sh fix/1234-slug release/vX.Y.Z  # izolirani worktree, siguran za paralelni rad
```

- `typecheck-touched.sh` provjerava tipove samo u izmijenjenim `.ts/.tsx` datotekama putem privremenog
  `tsconfig.touched.tmp.json` (`extends ./tsconfig.json`, `types: ["node"]`, `noEmit`,
  `incremental: false`) uz heap od 6 GB, pa zamjenjuje `tsc -p tsconfig.json` za cijeli projekt,
  koji ostane bez memorije na opterećenom računaru. Ispisuje greške u izmijenjenim datotekama i jedan sažeti red te završava
  kodom `1` za greške u izmijenjenim datotekama, kodom `2` kada su jedine greške u uvezenim datotekama ili kada se tsc prekine
  bez dijagnostike (pročitajte zapisnik čiji naziv ispiše pod `_artifacts/typecheck-touched/`), a kodom `0` kada
  nema grešaka. Privremeni tsconfig se uvijek uklanja; nikada ga nemojte commitovati.
- `new-worktree.sh` serijalizira istovremena pokretanja pomoću `<git-common-dir>/omniroute-new-worktree.lock`
  (čeka do 600 s prema zadanim postavkama, uz vidljivu poruku; zaglavlje skripte dokumentuje
  način promjene te postavke) i poništava
  granu koju je kreirao kada `git worktree add` ne uspije prije nego što worktree nastane, tako da ponovni pokušaj
  ne zahtijeva ručno izvršavanje `git branch -D`. Tvrdo povezani `node_modules` i kopija `.husky/_` ostaju nepromijenjeni.

## Lokalna petlja kandidata

Testovi izvornog koda ne mogu dokazati da se zapakovani artefakt pokreće: spiskovi za pakovanje, uklonjene zavisnosti
i nativne binarne datoteke ne uspijevaju tek dok se tarball ne instalira i pokrene. `npm run dev:candidate`
(`scripts/dev/candidate.mjs`) je lokalna strana toka izgradi-jednom / validiraj / promoviraj iz
RFC-a #8084: izrađuje jednog kandidata, validira upravo taj artefakt, promovira ga preimenovanjem
direktorija i vraća prethodnu verziju kada promovirani slot ne prođe provjeru stanja.

```bash
npm run dev:candidate -- run --dry-run --json  # ispiši plan, ne mijenjaj ništa
npm run dev:candidate -- run                   # izgradi + validiraj + promoviraj, automatski vrati prethodnu verziju
npm run dev:candidate -- build                 # npm pack + instalacija u _artifacts/candidate/<id>/
npm run dev:candidate -- validate --id <id>    # pokreni na slobodnom portu, /api/health + /v1/models
npm run dev:candidate -- promote --id <id>     # <id> → current, current → previous
npm run dev:candidate -- rollback              # zamijeni current i previous
npm run dev:candidate -- run --from-tarball <file.tgz>  # ponovo koristi tarball izrađen drugdje (CI)
```

- **Izgradite jednom.** `build` pakuje trenutno stablo (potreban mu je `dist/server.js`, zato prvo pokrenite
  `npm run build:release`) ili kopira `--from-tarball`, a zatim instalira tarball u
  izolirani npm prefiks jer tarball ne sadrži `node_modules`. ID je skraćeni SHA vrijednosti `HEAD`
  (`-dirty` kada stablo sadrži lokalne izmjene) ili `tgz-<sha256>` za tarball. Čisti ID koji
  je već izrađen ponovo se koristi umjesto ponovne izgradnje; proslijedite `--force` da biste ga ponovo izgradili.
- **Validirajte paket, a ne izvorni kod.** `validate` pokreće instalirani CLI
  (`serve --port <free port>`) sa svježim `DATA_DIR=<candidate>/data`, lažnim tajnama, dok su
  operatorovi `OMNIROUTE_API_KEY`, `STORAGE_ENCRYPTION_KEY` i `INITIAL_PASSWORD` uklonjeni iz
  okruženja, čime se provjerava način rada nove instalacije bez ključa preko povratne petlje. Čeka da
  `GET /api/health` vrati 200, zahtijeva da `GET /v1/models` vrati 200, zaustavlja grupu procesa
  i bilježi rezultat u `validation.json` zajedno s hashom tarballa.
- **Promovirajte isti artefakt.** `promote` odbija kandidata koji nema uspješnu validaciju za hash svog
  trenutnog tarballa. Zadani aktivni slot je `_artifacts/candidate/current`; `--target <dir>`
  bira drugi direktorij na istom sistemu datoteka, a njegov prethodni slot je `<dir>.previous`.
  Svako preimenovanje je atomsko, a greška tokom postupka poništava već izvršena preimenovanja.
- **Vratite prethodnu verziju.** `run` ponovo validira promovirani slot i zamjenjuje `current` i `previous` nazad kada
  ta provjera ne uspije. Kandidat koji ne prođe prvu validaciju nikada se ne promovira.

Sve se zapisuje pod git-ignorirani `_artifacts/candidate/`; postojeća instalacija OmniRoutea
i njen direktorij podataka nikada se ne mijenjaju. Promovirani CLI je
`_artifacts/candidate/current/prefix/bin/omniroute`; pokrenite ga s vlastitim `DATA_DIR` kada ga
koristite. Izlazni kodovi: `0` uspjeh, `1` neuspješna validacija ili promocija, `2` greška pri korištenju ili nedostajuća izgradnja.

## Lokalna petlja naspram CI-ja

| Pokretati lokalno za svaku izmjenu                                                    | CI pruža širi signal                                                                  |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Direktni testovi ponašanja i gore navedene provjere kategorija                        | Particionirani kompletni skup jediničnih testova i serijski testovi                   |
| `npm run lint`                                                                        | Vitest skupovi testova i pragovi pokrivenosti/kvaliteta                               |
| Provjera tipova ili izgradnja samo kada to zahtijeva obuhvaćeni ugovor                | Produkcijska izgradnja te provjere sigurnosti, dokumentacije, zavisnosti i PR pravila |
| Ručne interaktivne/provjere uživo samo kada automatizacija ne može dokazati ponašanje | Međuprocesne integracijske i platformske provjere konfigurirane radnim tokom          |

Uspješna fokusirana petlja predstavlja dokaz o izmijenjenom ugovoru, a ne potvrdu da će nepovezane CI provjere
proći. S druge strane, nemojte dopustiti da svaka lokalna izmjena čeka kompletnu matricu repozitorija.

## Kontrolna lista za usklađivanje

Prije nego što zatražite pregled:

- Potvrdite da je osnovna grana PR-a i dalje najviša aktivna grana `release/v*`.
- Dohvatite tu osnovnu granu i pregledajte commitove koji su dodani otkako ste kreirali svoju granu.
- Pregledajte `git diff <active-base>...HEAD` radi slučajnih ili generiranih izmjena.
- Riješite konflikte u katalozima i generiranim dokumentima ažuriranjem izvora i ponovnim generiranjem izlaza.
- Nakon usklađivanja ponovo pokrenite svaki fokusirani test/provjeru navedenu u opisu PR-a.
- Nikada nemojte ublažavati asercije niti uklanjati obavezne testove samo radi usklađivanja s pomjerenom osnovnom granom.

Za pravila zamrzavanja izdanja i promjene ciljne grane koristite
[Model grananja i izdanja](BRANCHING_MODEL.md). Za kompletan popis CI provjera koristite
[Referenca provjera kvaliteta](../architecture/QUALITY_GATES.md).
