## 🎯 Slučajevi upotrebe

### Slučaj 1: "Imam Claude Pro pretplatu"

**Problem:** Kvota ističe neiskorištena, ograničenja brzine (rate limits) tokom intenzivnog kodiranja

```
Kombinacija: "maximize-claude"
  1. cc/claude-opus-4-7        (potpuno iskoristite pretplatu)
  2. glm/glm-4.7               (jeftini rezervni model kada kvota nestane)
  3. if/qwen3.8-max-preview       (besplatna hitna alternativa)

Mjesečni trošak: $20 (pretplata) + ~$5 (rezerva) = ukupno $25
naspram $20 + dosezanje limita = frustracija
```

### Slučaj 2: "Želim nula troškova"

**Problem:** Ne mogu priuštiti pretplate, potreban je pouzdan AI za kodiranje

```
Kombinacija: "zero-cost"
  1. if/kimi-k2.7-code          (naveden besplatan pristup; mogu se primijeniti ograničenja brzine)
  2. kr/qwen3-coder-next        (Kiro besplatna alternativa)

Mjesečni trošak: $0
Kvalitet: provjerite model, limite, privatnost i SLA za vaše potrebe
```

### Slučaj 3: "Treba mi kodiranje 24/7, bez prekida"

**Problem:** Rokovi, ne mogu priuštiti zastoje

```
Kombinacija: "always-on"
  1. cc/claude-opus-4-7        (najbolji kvalitet)
  2. cx/gpt-5.5                (druga pretplata)
  3. glm/glm-4.7               (jeftino, resetuje se svakodnevno)
  4. minimax/MiniMax-M2.1      (najjeftinije, reset svakih 5h)
  5. if/deepseek-v4-flash       (naveden besplatan pristup; mogu se primijeniti ograničenja brzine)

Rezultat: 5 slojeva rezervi povećavaju otpornost; dostupnost izvora nije zagarantovana
Mjesečni trošak: $20-200 (pretplate) + $10-20 (rezerva)
```

### Slučaj 4: "Želim BESPLATAN AI u OpenClaw"

**Problem:** Potreban AI asistent u aplikacijama za razmjenu poruka, potpuno besplatno

```
Kombinacija: "openclaw-free"
  1. if/qwen3.8-max-preview     (naveden besplatan pristup; mogu se primijeniti ograničenja brzine)
  2. if/deepseek-v4-flash       (naveden besplatan pristup; mogu se primijeniti ograničenja brzine)
  3. if/kimi-k2.7-code          (naveden besplatan pristup; mogu se primijeniti ograničenja brzine)

Mjesečni trošak: $0
Pristup putem: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 Postavljanje pružalaca usluga

Za masovno dodavanje veza s API ključevima iz CSV ili JSON datoteke koristite **Kontrolna tabla → Pružaoci usluga → Uvezi iz datoteke**. Kolone su pozicijske (`provider,name,apiKey,baseUrl,priority`); `provider` već mora postojati kao upravljani pružalac usluga ili kompatibilni čvor. Pogledajte [Uvoz pružalaca usluga iz CSV ili JSON datoteke](../providers/CSV-IMPORT.md).

### 🔐 Pretplatnički pružaoci usluga

#### Claude Code (Pro/Max)

```bash
Kontrolna tabla → Pružaoci usluga → Poveži Claude Code
→ OAuth prijava → Automatsko osvježavanje tokena
→ Praćenje 5-satne + sedmične kvote

Modeli:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**Profesionalni savjet:** Koristite Opus za složene zadatke, a Sonnet za brzinu. OmniRoute prati kvotu za svaki model!

Nemate preglednik na OmniRoute hostu? Pokrenite `claude setup-token` bilo gdje gdje ste prijavljeni u Claude Code i zalijepite jednogodišnji token na karticu **Token za postavljanje**. Pogledajte [Claude Code s tokenom za postavljanje](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

Rute kompatibilne s Claudeom i Claude Codeom zadržavaju `max` intenzitet razmišljanja za modele Opus i Sonnet. Modeli Haiku ne prihvataju nivo intenziteta `max`, pa OmniRoute smanjuje taj zahtjev na visok budžet za razmišljanje prije nego što ga pošalje nadređenom pružaocu usluga.

#### OpenAI Codex (Plus/Pro)

```bash
Kontrolna tabla → Pružaoci usluga → Poveži Codex
→ OAuth prijava (port 1455)
→ 5-satno + sedmično resetovanje

Modeli:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
Kontrolna tabla → Pružaoci usluga → Poveži GitHub
→ OAuth putem GitHuba
→ Mjesečno resetovanje (1. u mjesecu)

Modeli:
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview
```

### 💰 Povoljni pružaoci usluga

#### GLM-4.7 (Dnevno resetovanje, $0.6/1M)

1. Registrujte se: [Zhipu AI](https://open.bigmodel.cn)
2. Preuzmite API ključ iz Coding Plan
3. Kontrolna tabla → Dodaj API ključ: Pružalac usluga: `glm`, API ključ: `your-key`

**Upotreba:** `glm/glm-4.7` — **Profesionalni savjet:** Coding Plan nudi 3× veću kvotu po 1/7 cijene! Resetuje se svakog dana u 10:00.

#### MiniMax M2.1 (Resetovanje svakih 5 h, $0.20/1M)

1. Registrujte se: [MiniMax](https://www.minimax.io)
2. Preuzmite API ključ → Kontrolna tabla → Dodaj API ključ

**Upotreba:** `minimax/MiniMax-M2.1` — **Profesionalni savjet:** Najjeftinija opcija za dugi kontekst (1M tokena)!

#### Kimi K2 ($9/mjesec fiksno)

1. Pretplatite se: [Moonshot AI](https://platform.kimi.ai?aff=omniroute)
2. Preuzmite API ključ → Kontrolna tabla → Dodaj API ključ

**Upotreba:** `kimi/kimi-k2.5` — **Profesionalni savjet:** Fiksnih $9/mjesec za 10M tokena = efektivni trošak od $0.90/1M!

#### Baidu Qianfan / ERNIE

1. Registrujte se: [Baidu AI Cloud Qianfan](https://cloud.baidu.com/product/wenxinworkshop)
2. Kreirajte Qianfan API ključ → Kontrolna tabla → Dodaj API ključ: Pružalac usluga: `qianfan`

**Upotreba:** `qianfan/ernie-5.1`, `qianfan/ernie-x1.1` ili drugi ID Qianfan modela kompatibilnog s OpenAI-jem.

### 🆓 BESPLATNI pružaoci usluga

Besplatni pružaoci usluga bez autentifikacije imaju prekidač pored opcije **Autentifikacija nije potrebna** na svojoj stranici.
Isključivanjem prekidača taj pružalac usluga se onemogućava, uklanja iz konfigurisanih/sažetih prikaza Pružalaca usluga te se njegovi modeli uklanjaju iz `/v1/models`.


#### Kiro (Claude BESPLATNO)

```bash
Kontrolna tabla → Poveži Kiro → AWS Builder ID ili Google/GitHub → ~50 kredita/mjesec

Modeli: kr/claude-sonnet-4.5, kr/claude-haiku-4.5
```

## 🎨 Kombinacije (Combos)

Redoslijed kartica kombinacija možete promijeniti direktno u **Dashboard → Combos** povlačenjem ručke na svakoj kartici. Redoslijed se sprema u SQLite i vraća prilikom ponovnog učitavanja.

### Primjer 1: Maksimizacija pretplate → Jeftini rezervni model

```
Dashboard → Combos → Create New

Name: premium-coding
Models:
  1. cc/claude-opus-4-7 (Primarna pretplata)
  2. glm/glm-4.7 (Jeftini rezervni, $0.6/1M)
  3. minimax/MiniMax-M2.7 (Najjeftiniji fallback, $0.3/1M)

Use in CLI: premium-coding
```

### Primjer 2: Samo besplatni (Nula troškova)

```
Name: free-combo
Models:
  1. if/kimi-k2.7-code (naveden besplatan pristup; mogu se primijeniti ograničenja provajdera)
  2. kr/qwen3-coder-next (Kiro besplatni fallback)

Cost: trenutno naveden kao $0; uvjeti i dostupnost se mogu promijeniti
```

## 🔧 CLI Integracija

### Cursor IDE

**Korištenje Cursora kao OmniRoute klijenta** (usmjeravanje Cursor chata kroz OmniRoute):

```
Settings → Models → Advanced:
  OpenAI API Base URL: http://localhost:20128/v1
  OpenAI API Key: [iz omniroute dashboarda]
  Model: cc/claude-opus-4-7
```

**Korištenje OmniRoute-a kao Cursor provajdera** (OmniRoute poziva Cursor upstream): preferirajte
**Dashboard → Providers → Cursor → Login with Cursor**. U Dockeru, pogledajte
[`docs/providers/CURSOR-DOCKER.md`](../providers/CURSOR-DOCKER.md).

### Claude Code

Uredite `~/.claude/settings.json`:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://localhost:20128",
    "ANTHROPIC_AUTH_TOKEN": "your-omniroute-api-key"
  }
```

### Tray mode (Sistemski tray)

Pokrenite OmniRoute u sistemskom tray-u:

```bash
omniroute serve --tray
```

Komanda se završava nakon što server i tray budu spremni.

Server nastavlja raditi bez terminala.

Tray mode podržava macOS, Windows i grafičke Linux sesije. Tray mode ne otvara dashboard automatski.

Koristite tray meni za ove radnje:

- Otvaranje dashboarda.
- Otvaranje `/dashboard/logs`.
- Promjena auto-starta.
- Zaustavljanje OmniRoute-a.

Nemojte kombinovati `--tray` sa ovim opcijama:

- `--daemon`
- `--log`
- `--no-recovery`

Ovi načini zahtijevaju različito vlasništvo nad procesom.

Omogućite pokretanje pri sljedećoj prijavi na mašinu:

```bash
omniroute autostart enable
```

Auto-start koristi tray mode na macOS-u, Windows-u i grafičkim Linux sesijama. Headless Linux koristi postojeći systemd user servis.

Onemogućite pokretanje pri prijavi:

```bash
omniroute autostart disable
```

## 🧩 Napredne funkcije

### Prilagođeni modeli

Dodajte bilo koji ID modela bilo kojem provajderu bez čekanja na ažuriranje aplikacije:

```bash
# Putem API-ja
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# Lista: curl http://localhost:20128/api/provider-models?provider=openai
# Uklanjanje: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

Ili koristite Dashboard: **Provajderi → [Provajder] → Prilagođeni modeli**.

Napomene:

- OpenRouter i OpenAI/Anthropic-kompatibilnim provajderima upravlja se isključivo iz **Dostupni modeli**. Ručno dodavanje, uvoz i automatska sinhronizacija — sve završava u istoj listi dostupnih modela, tako da za te provajdere ne postoji posebna sekcija Prilagođeni modeli.
- Sekcija **Prilagođeni modeli** namijenjena je provajderima koji ne pružaju upravljani uvoz dostupnih modela.

### Prilagođeni OpenAI-kompatibilni provajderi

Bilo koji gateway koji podržava OpenAI API (self-hosted proxy, vLLM, agregator treće strane)
može se dodati kao vlastiti čvor provajdera:

1. **Provajderi → Dodaj OpenAI-kompatibilan**.
2. **Ime**: oznaka za prikaz čvora.
3. **Prefiks**: naziv za rutiranje. Klijenti pozivaju modele kao `<prefix>/<model>`, tako da čvor s
   prefiksom `mygw` poslužuje `mygw/gpt-4o-mini`. Obavezno; nema ograničenja znakova.
4. **Tip API-ja**: porodica krajnjih tačaka koju gateway poslužuje (Chat Completions, Responses,
   Embeddings, audio, slike).
5. **Osnovni URL**: korijen API-ja, do i uključujući `/v1` (na primjer
   `https://gateway.example.com/v1`), a ne puna putanja `/chat/completions`. Gateway-i s
   nestandardnim putanjama postavljaju ih pod **Napredne postavke** (putanja chata, putanja modela).
6. Polje **API ključ (za provjeru)** samo testira vezu. Nakon kreiranja čvora,
   otvorite ga i koristite **Dodaj vezu** da pohranite ključ koji će zahtjevi koristiti.

Čvor dobija interni ID u obliku `openai-compatible-<apiType>-<uuid>`; nikada ga ne
trebate upisivati — prefiks je javni naziv.

#### Rezervisani prefiksi

Prefiks ne može biti ID ili pseudonim ugrađenog provajdera (na primjer `openai`, `cf`), niti
ID povučenog provajdera. Razrješavač modela provjerava ugrađene ID-eve i pseudonime prije
prilagođenih čvorova, tako da čvor koji koristi jedan od tih prefiksa nikada ne bi primao saobraćaj:
`<prefix>/model` bi umjesto toga otišao ugrađenom provajderu, ili bi sigurnosno odbio (fail closed)
ako je taj provajder povučen. Kreiranje ili uređivanje čvora s takvim prefiksom odbija se porukom:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

Odaberite drugačiji prefiks (`mygw`, `acme-proxy`). Ako zahtjevi prema prilagođenom čvoru ne uspiju
s greškom koja spominje ugrađeni provajder ili njegove kredencijale, provjerite je li prefiks čvora
rezervisan: čvorovi sačuvani prije nego što je ovo pravilo postojalo i dalje su pohranjeni, ali njihov
prefiks rutira ka ugrađenom provajderu. Uredite čvor i dodijelite mu novi prefiks.

#### Opcije gateway-a po vezi

Ovi ključevi idu u `providerSpecificData` veze (na primjer putem
`PUT /api/providers/{id}`):

- `toolNameMaxLength` (cijeli broj, 1–1024) — za OpenAI chat-format kompatibilne veze čiji
  gateway odbija dugačka imena alata. Duža imena šalju se kao kratki pseudonimi i obnavljaju se u
  odgovoru.
- `quotaEndpoint` — krajnja tačka kvote/kredita gateway-a, koja se čita za traku kvota na
  dashboardu i rutiranje na osnovu kvota. Radi i na OpenAI- i na Anthropic-kompatibilnim vezama;
  potpuni oblik dokumentiran je u `open-sse/services/usage/openaiCompatible.ts`.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### Lančano povezivanje OmniRoute peer-ova

Drugi OmniRoute gateway može se dodati kao **Prilagođeni OpenAI-kompatibilni** provajder. Koristite
`/v1` osnovni URL peera i namjenski API ključ s najmanjim privilegijama koji je izdao taj peer.

Za uzajamne ili višeskočne lance omogućite opcijsku zaštitu od petlji na svakom gateway-u:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

Samo zahtjevi poslani na eksplicitno dozvoljen (allowlistiran) peer URL dobijaju zaglavlje
`X-OmniRoute-Peer-Trace`. Gateway odbija ponovljeni ID instance ili iscrpljeni budžet
skokova s HTTP `508 Loop Detected`; obični upstream provajderi ne primaju nikakve peer metapodatke.

Lančano povezivanje peer-ova nije replikacija baze podataka niti failover hosta. Svaki gateway
zadržava nezavisno SQLite stanje, kešove, brojače brzine i sesije. Koristite reverse proxy s provjerom
zdravlja (health check) ili failover na klijentu za aktivnu/pasivnu ili aktivnu/aktivnu dostupnost, i
nikada ne montirajte jednu SQLite bazu podataka u više pokrenutih OmniRoute instanci.

### Cloudflare Quick Tunnel

- Dostupno u **Nadzorna ploča → Endpoints** za Docker i druge self-hosted implementacije
- Kreira privremeni `https://*.trycloudflare.com` URL koji prosljeđuje na vaš trenutni OpenAI-kompatibilni `/v1` endpoint
- Prvo omogućavanje instalira `cloudflared` samo kada je potrebno; kasnija ponovna pokretanja ponovno koriste isti upravljani binarni fajl
- Quick Tuneli se ne vraćaju automatski nakon ponovnog pokretanja OmniRoute-a ili kontejnera; po potrebi ih ponovno omogućite s nadzorne ploče
- URL-ovi tunela su kratkotrajni i mijenjaju se svaki put kada zaustavite/pokrenete tunel
- Upravljani Quick Tuneli po zadanim postavkama koriste HTTP/2 transport kako bi izbjegli upadažljiva QUIC UDP buffer upozorenja u ograničenim kontejnerima
- Postavite `CLOUDFLARED_PROTOCOL=quic` ili `auto` ako želite zaobići upravljani izbor transporta
- Postavite `CLOUDFLARED_BIN` ako preferirate korištenje unaprijed instaliranog `cloudflared` binarnog fajla umjesto upravljanog preuzimanja
- Paneli Cloudflare Quick Tunnel, Tailscale Funnel i ngrok Tunnel mogu se prikazati ili sakriti u **Postavke → Izgled**. Skrivanje panela ne zaustavlja aktivni tunel.

### Strategije rutiranja

Konfigurišite putem **Nadzorna ploča → Postavke → Rutiranje**. Nadzorna ploča izlaže šest najkorištenijih strategija; combo-i i auto-router interno podržavaju širi skup.

**Strategije vidljive na nadzornoj ploči (rutiranje na nivou računa):**

| Strategija                     | Opis                                                                                                      |
| ------------------------------ | --------------------------------------------------------------------------------------------------------- |
| **Fill First**                 | Koristi račune po redoslijedu prioriteta — primarni račun obrađuje sve zahtjeve dok ne postane nedostupan |
| **Round Robin**                | Rotira kroz sve račune s konfigurabilnim sticky limitom (zadano: 3 poziva po računu)                      |
| **P2C (Power of Two Choices)** | Bira 2 nasumična računa i rutira ka zdravijem — balansira opterećenje uz svjesnost o zdravlju računa      |
| **Random**                     | Nasumično bira račun za svaki zahtjev koristeći Fisher-Yates shuffle                                      |
| **Least Used**                 | Rutira ka računu s najstarijom `lastUsedAt` vremenskom oznakom, ravnomjerno raspoređujući saobraćaj       |
| **Cost Optimized**             | Rutira ka računu s najnižom vrijednošću prioriteta, optimizirajući za provajdere s najnižom cijenom       |

**Napredne combo i auto strategije** (konfigurabilne po combo-u ili putem `auto/*` prefiksa — pogledajte [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — strogi redoslijed, nikada ne rotira
- `weighted` — proporcionalna podjela saobraćaja prema težinama po modelu
- `fill-first` — iscrpljuje prvi model dok se ne dostignu limiti
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` i `cost-optimized`
- `auto` — vođen bodovanjem kroz sve kandidate
- `lkgp` (Last Known Good Provider) — vezuje se za posljednjeg uspješnog provajdera, zatim se vraća na pravila
- `context-optimized` — bira model s najvećim slobodnim kontekstnim prozorom
- `context-relay` — ulančava modele dugog konteksta za naknadne korake

#### Eksterno zaglavlje sticky sesije

Za eksterni afinitet sesije (na primjer, Claude Code/Codex agenti iza reverse proxy-a), pošaljite:

```http
X-Session-Id: your-session-key
```

OmniRoute također prihvata `x_session_id` i vraća efektivni ključ sesije u `X-OmniRoute-Session-Id`.

Ako koristite Nginx i šaljete zaglavlja s donjim crtama, omogućite:

```nginx
underscores_in_headers on;
```

#### Alijasi modela s džokerima

Kreirajte džoker obrasce za preslikavanje naziva modela:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

Džokeri podržavaju `*` (bilo koji znakovi) i `?` (jedan znak).

#### Fallback lanci

Definišite globalne fallback lance koji se primjenjuju na sve zahtjeve:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### Otpornost i prekidači kola

Konfigurišite putem **Kontrolna tabla → Postavke → Otpornost**.

OmniRoute implementira otpornost na nivou pružatelja s pet komponenti:

1. **Red zahtjeva i tempiranje** — Oblikovanje zahtjeva na nivou sistema:
   - **Zahtjevi po minuti (RPM)** — Maksimalan broj zahtjeva po minuti po nalogu
   - **Minimalno vrijeme između zahtjeva** — Minimalni razmak u milisekundama između zahtjeva
   - **Maksimalan broj istovremenih zahtjeva** — Maksimalan broj simultanih zahtjeva po nalogu

2. **Hlađenje konekcije** — Konfiguracija po tipu autentifikacije za pojedinačnu konekciju nakon grešaka koje se mogu ponoviti:
   - **Osnovno hlađenje** — Zadani prozor hlađenja za upstream greške koje se mogu ponoviti
   - **Koristi upstream savjete za ponovni pokušaj** — Poštuje autoritativne `Retry-After` ili savjete za resetovanje kada su dostupni
   - **Maksimalan broj koraka backoff-a** — Maksimalni nivo eksponencijalnog backoff-a za ponovljene greške

3. **Prekidač kola pružatelja** — Prati ukupne kvarove pružatelja, označava pružatelja kao degradiranog pri konfigurisanom pragu upozorenja i otvara prekidač kada se dosegne konfigurisani prag kvarova:
   - **Prag degradacije** — Uzastopni kvarovi pružatelja prije ulaska u stanje `DEGRADED`
   - **Prag kvara** — Uzastopni kvarovi pružatelja prije ulaska u stanje `OPEN`
   - **Vremensko ograničenje resetovanja** — Vremenski prozor prije nego što se pružatelj ponovo testira
   - **CLOSED** (Zdravo) — Zahtjevi protiču normalno
   - **DEGRADED** — Zahtjevi i dalje protiču dok se prate povećani kvarovi
   - **OPEN** — Pružatelj je privremeno blokiran nakon ponovljenih kvarova
   - **HALF_OPEN** — Testira se da li se pružatelj oporavio

   Ograničenja brzine `429` vezana za konekciju ostaju u okviru **hlađenja konekcije** i ne računaju se u prekidač pružatelja.

   Stanje prekidača pružatelja tokom rada prikazuje se samo na stranici **Kontrolna tabla → Zdravlje**.

4. **Čekanje hlađenja** — Ako su sve kandidatske konekcije već u hlađenju, OmniRoute može sačekati najranije hlađenje i automatski ponoviti isti zahtjev klijenta.

5. **Automatska detekcija ograničenja brzine** — Kada upstream pružatelji vrate eksplicitne prozore čekanja, ti savjeti zamjenjuju lokalno hlađenje konekcije kada je postavka omogućena.

**Savjet:** Koristite stranicu **Zdravlje** za pregled i resetovanje aktivnih prekidača pružatelja nakon prekida rada. Stranica Otpornost mijenja samo konfiguraciju.

### Strategije balansiranja kombinacija

Balansiranje po pojedinačnoj kombinaciji konfigurišite u **Dashboard → Kombinacije → Kreiraj/Uredi → Strategija**.

| Strategija         | Opis                                                                          |
| ------------------ | ----------------------------------------------------------------------------- |
| **Round-Robin**    | Kružno prolazi kroz modele redoslijedom                                       |
| **Priority**       | Uvijek prvo pokušava prvi model; prebacuje se na rezervni samo pri grešci     |
| **Random**         | Za svaki zahtjev bira nasumičan model iz kombinacije                          |
| **Weighted**       | Usmjerava proporcionalno prema dodijeljenim težinama po modelu                |
| **Least-Used**     | Usmjerava na model s najmanje nedavnih zahtjeva (koristi metrike kombinacija) |
| **Cost-Optimized** | Usmjerava na najjeftiniji dostupni model (koristi cjenovnu tabelu)            |

Globalne zadane postavke kombinacija mogu se postaviti u **Dashboard → Postavke → Usmjeravanje → Zadane postavke kombinacija**.
Timeouti ciljeva kombinacije po zadanim postavkama nasljeđuju trenutni timeout zahtjeva. Polje
**Ciljani timeout (sekunde)** u zadanim postavkama kombinacija ili na pojedinačnoj kombinaciji
koristite samo kada kraće ograničenje po cilju treba pokrenuti brži fallback.

Optimizacije kombinacija s nultom latencijom uključuju se po izboru (opt-in). Ostavite
**Optimizacije nulte latencije** onemogućenima kako biste spriječili da se ove funkcije za
smanjenje latencije utrkuju s fallback ciljevima, preskaču ciljeve na osnovu TTFT historije ili
komprimuju fallback zahtjeve; njihovim omogućavanjem konfigurisani hedging, prediktivna preskakanja
na osnovu TTFT-a i proaktivna kompresija fallbacka zamjenjuju vjernost usmjeravanja/zahtjeva za
nižu latenciju u repu (tail latency).

Onemogućite **Bafer tokena rezonovanja** kada upstream pružaoci usluga zahtijevaju stroga
ograničenja `max_tokens` / `maxOutputTokens`. Kada je omogućeno, kombinovano usmjeravanje dodaje
dodatni prostor za modele rezonovanja samo za modele s poznatim ograničenjem izlaza, a ostavlja
token limit klijenta nepromijenjen kada bi sigurna baferovana vrijednost premašila to ograničenje.
Ako je klijentov limit već iznad poznatog ograničenja, OmniRoute ga svodi na to ograničenje prije
slanja upstream zahtjeva.

## 🤖 Auto-Routing (Zero-config)

OmniRoute dolazi sa **score-driven auto-routerom** koji bira najbolji model za svaki zahtjev kroz sve povezane provajdere — bez potrebe za održavanjem kombinacija. Jednostavno pošaljite zahtjev sa jednim od `auto/*` prefiksa i OmniRoute će u hodu sastaviti virtuelnu kombinaciju, ocjenjujući kandidate na osnovu latencije, troška, stope uspjeha, uklapanja konteksta, prikladnosti modela za zadatak, nedavnih neuspjeha, kvote i stanja circuit-breaker-a.

| Prefiks        | Optimizira za                                                                                       |
| -------------- | --------------------------------------------------------------------------------------------------- |
| `auto`         | Balansirani default (latencija × trošak × stopa uspjeha)                                            |
| `auto/coding`  | Zadaci kodiranja: preferira Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek coders                   |
| `auto/cheap`   | Najniži $/token, prihvata veću latenciju                                                            |
| `auto/fast`    | Najniža latencija, ignoriše trošak                                                                  |
| `auto/offline` | Isključivo lokalni provajderi (Ollama, vLLM, llama.cpp) — korisno za air-gapped postavke            |
| `auto/smart`   | Prvenstveno kvalitet razmišljanja (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)                        |
| `auto/lkgp`    | "Last Known Good Provider" — fiksira na posljednjeg uspješnog provajdera, zatim se vraća na pravila |

Primjer:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

Auto-router je detaljno opisan u [AUTO-COMBO.md](../routing/AUTO-COMBO.md) — uključujući način podešavanja težina ocjenjivanja, crnu listu provajdera i pregled odluka o rutiranju u **Dashboard → Auto Combo**.

## 🔌 MCP & A2A Integracija

OmniRoute je istovremeno **MCP server** (Model Context Protocol) i **A2A server** (Agent-to-Agent JSON-RPC 2.0). Bilo koji MCP-kompatibilni IDE ili agent host može direktno pozivati OmniRoute alate — bez potrebe za dodatnim wrapperom.

### MCP transporti

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **Streamable HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (za IDE plugine koji preferiraju stdio)

### Povezivanje sa Claude Desktop

Uredite `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) ili ekvivalent na Windows/Linux sistemima:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Povezivanje sa Cursor / Continue / VS Code MCP

Koristite SSE URL `http://localhost:20128/api/mcp/sse` i Bearer API ključ generisan u **Dashboard → API Keys**.

### Scope-ovi

MCP trenutno definiše 32 imenovani scope-a. Svaki Bearer ključ može biti ograničen na specifične scope-ove — pogledajte [MCP-SERVER.md](../frameworks/MCP-SERVER.md) za autoritativni popis scope-ova i alata, te [A2A-SERVER.md](../frameworks/A2A-SERVER.md) za JSON-RPC shemu.

## 💾 Sistem memorije

OmniRoute održava **dugoročnu konverzacijsku memoriju** pomoću hibridnog pretraživanja:

- **SQLite FTS5** za pretragu ključnih riječi kroz prošle runde razgovora
- **Qdrant vector store** (opcionalno) za semantički podsjetak
- **Automatska ekstrakcija činjenica** — entiteti, preferencije i odluke se sumiraju nakon svake sesije i spremaju u tabelu `memory_facts`
- Memorije su ograničene po API ključu i po sesiji

Upravljajte memorijama u **Dashboard → Memory** (pretraga, uređivanje, izvoz, brisanje). HTTP interfejs (`/api/memory/*`) omogućava agentima da programski šalju i upituju činjenice — pogledajte [MEMORY.md](../frameworks/MEMORY.md).

## 🔔 Webhooks

Pretplatite se na OmniRoute događaje za praćenje u stvarnom vremenu i automatizaciju.

- Kreirajte webhook u **Dashboard → Webhooks** sa ciljnim URL-om i HMAC tajnom za potpisivanje
- Dostupni događaji: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- Svaki payload uključuje `X-OmniRoute-Signature` (HMAC-SHA256) za verifikaciju
- Ponovni pokušaji: 3 pokušaja sa eksponencijalnim odlaganjem (exponential backoff), zatim dead-letter queue

Potpuna shema u [WEBHOOKS.md](../frameworks/WEBHOOKS.md).

## 🛠️ Programsko upravljanje

Svakim OmniRoute resursom (provajderi, kombi, ključevi, postavke) možete upravljati putem HTTP-a koristeći **Bearer ključ sa `manage` scope-om**.

Generišite ključ u **Dashboard → API Keys → New Key → Scope: manage**, zatim:

```bash
# Listaj provajdere
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Dodaj vezu sa provajderom
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Kreiraj combo
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Listaj/kreiraj API ključeve
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

Pogledajte [API_REFERENCE.md](../reference/API_REFERENCE.md) za potpuni katalog endpoint-a i sheme zahtjeva/odgovora.

## 💻 Interni CLI

OmniRoute dolazi sa internim CLI-jem (`omniroute …`) za podešavanje, dijagnostiku i kontrolu tokom rada. Ovo je **odvojeno od stranice "CLI Tools" u kontrolnoj ploči**, koja konfiguriše CLI alate trećih strana (Claude Code, Cursor, Codex, Cline, …) kako bi mogli komunicirati sa OmniRoute-om.

```bash
omniroute setup                    # Interaktivni čarobnjak (lozinka, provajderi, kombinacije)
omniroute setup --non-interactive  # Prilagođeno za CI
omniroute doctor                   # Dijagnostika zdravlja (direktorijum podataka, DB, provajderi, portovi)
omniroute providers available      # Lista podržanih provajdera
omniroute providers list           # Lista konfigurisanih konekcija
omniroute providers test <id>      # Testiranje konekcije provajdera u realnom vremenu
omniroute combos list              # Lista kombinacija
omniroute combos switch <name>     # Postavljanje podrazumijevane kombinacije
omniroute models                   # Lista dostupnih modela (--json, --search)
omniroute keys add | list | remove # Upravljanje API ključevima iz terminala
omniroute backup                   # Snapshot konfiguracije + DB
omniroute restore [<timestamp>]    # Vraćanje iz snapshot-a
omniroute health                   # Detaljno zdravlje (breakers, cache, memorija)
omniroute quota                    # Korištenje kvote provajdera
omniroute mcp status               # Status MCP servera
omniroute a2a status               # Status A2A servera
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok tuneli
omniroute reset-password           # Resetovanje administratorske lozinke
omniroute --mcp                    # Pokretanje MCP servera preko stdio
omniroute --port 3000              # Pokretanje servera na prilagođenom portu
```

Savjet: kombinujte `omniroute doctor --json` sa vašim alatom za monitoring kako biste dobili obavještenja o neispravnim konekcijama provajdera.
