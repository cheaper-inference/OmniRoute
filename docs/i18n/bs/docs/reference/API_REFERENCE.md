## Dovršavanja razgovora

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Prilagođena zaglavlja

| Zaglavlje                | Smjer   | Opis                                                                                                                                                                                                                                                 |
| ------------------------ | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | Zahtjev | Postavite na `true` da biste zaobišli predmemoriju                                                                                                                                                                                                   |
| `x-omniroute-no-memory`  | Zahtjev | Postavite na `true` da biste preskočili umetanje memorije i vještina za ovaj zahtjev (funkcioniše poput opcije bez predmemorije; izbjegava dodatne tokene i troškove po pozivu)                                                                      |
| `X-OmniRoute-Progress`   | Zahtjev | Postavite na `true` za događaje napretka                                                                                                                                                                                                             |
| `X-Session-Id`           | Zahtjev | Ključ trajne sesije za afinitet vanjske sesije                                                                                                                                                                                                       |
| `x_session_id`           | Zahtjev | Prihvaćena je i varijanta s donjom crtom (direktni HTTP)                                                                                                                                                                                             |
| `X-OmniRoute-Session-Id` | Zahtjev | Oznaka sesije/razgovora koju dostavlja pozivatelj (također se prosljeđuje memoriji). Kada je prisutna, pohranjuje se neizmijenjena u `call_logs.session_tag` radi pripisivanja troškova po sesiji (#8249) — nikada se ne generiše kada nije prisutna |
| `Idempotency-Key`        | Zahtjev | Ključ za deduplikaciju (prozor od 5 s)                                                                                                                                                                                                               |
| `X-Request-Id`           | Zahtjev | Alternativni ključ za deduplikaciju                                                                                                                                                                                                                  |
| `x-omniroute-connection` | Zahtjev | Vezuje zahtjev za jedan model za jednu vezu pružatelja usluga (račun) prema njenom ID-u — pogledajte [Vezivanje računa po zahtjevu](#account-pinning-per-request)                                                                                    |
| `X-OmniRoute-Cache`      | Odgovor | `HIT` ili `MISS` (bez prijenosa)                                                                                                                                                                                                                     |
| `X-OmniRoute-Idempotent` | Odgovor | `true` ako je izvršena deduplikacija                                                                                                                                                                                                                 |
| `X-OmniRoute-Progress`   | Odgovor | `enabled` ako je praćenje napretka uključeno                                                                                                                                                                                                         |
| `X-OmniRoute-Session-Id` | Odgovor | Efektivni ID sesije koji koristi OmniRoute                                                                                                                                                                                                           |
| `X-OmniRoute-Request-Id` | Odgovor | ID za korelaciju zahtjeva (kada je poznat)                                                                                                                                                                                                           |
| `X-OmniRoute-Version`    | Odgovor | Verzija OmniRoute izdanja (uvijek prisutna)                                                                                                                                                                                                          |
| `X-OmniRoute-Cost-Saved` | Odgovor | Iznos u USD koji je predmemorija uštedjela pri rezultatu HIT (samo pogoci predmemorije)                                                                                                                                                              |
| `X-OmniRoute-Decision`   | Odgovor | Trag usmjeravanja: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` je strategija kombinacije ili `single` za zahtjev koji nije kombinovan) — uvijek je prisutan u odgovorima po završetku                                              |

> Napomena za Nginx: ako se oslanjate na zaglavlja s donjom crtom (na primjer `x_session_id`), omogućite `underscores_in_headers on;`.

#### Prikvačivanje računa po zahtjevu

Kada pružalac usluge ima više veza (računa ili ključeva), OmniRoute obično bira jednu
putem svoje strategije odabira računa. Umjesto toga, zahtjev može prikvačiti određenu vezu
pomoću zaglavlja `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Gdje pronaći ID.** Otvorite stranicu pružaoca usluge na kontrolnoj ploči
  (**Kontrolna ploča → Pružaoci usluga → <pružalac usluge>**) i kliknite na oznaku ID-a `xxxxxxxx…` u redu veze
  — time se kopira puni ID veze.
- **Koji zahtjevi ga uvažavaju.** Zahtjevi s jednim modelom (`provider/model`) na
  `/v1/chat/completions`, `/v1/messages` i `/v1/responses`. Kombinacije zanemaruju zaglavlje: umjesto toga
  prikvačite račun za svaki korak kombinacije putem vlastite veze tog koraka.
- **Prikvačivanje je strogo, a ne samo preferencija.** Prikvačena veza koristi se isključivo. Neuspjeh
  unutar zahtjeva evidentira period čekanja računa, ali se **ne** prebacuje na drugi
  račun istog pružaoca usluge.
- **Period čekanja i kvota oslobađaju prikvačivanje.** Dok je prikvačena veza u periodu čekanja,
  dok joj je kvota iscrpljena ili je blokirana pravilima kvote, kasniji zahtjevi prebacuju se na druge
  veze pružaoca usluge, potpuno isto kao neprikvačeni saobraćaj.
- **Nepoznati ili onemogućeni ID-ovi uzrokuju neuspjeh.** ID koji nije u aktivnom skupu pružaoca usluge (izbrisan,
  deaktiviran ili pripada drugom pružaocu usluge) ne ostavlja nijedan odgovarajući račun, pa zahtjev
  završava neuspješno umjesto da se neprimjetno usmjeri drugdje.

Claude Code šalje prilagođena zaglavlja putem `ANTHROPIC_CUSTOM_HEADERS`. Postavite ga u blok `env`
datoteke `~/.claude/settings.json` ili u projektnu datoteku `.claude/settings.json` kako biste prikvačili drugi
račun za svaki projekt:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Izvor: `src/sse/handlers/chat.ts` (čitanje zaglavlja), `src/sse/services/auth.ts` i
`src/sse/services/sessionAffinityPin.ts` (oslobađanje prikvačivanja i provjera odsustva iz skupa).

> **Zaglavlja telemetrije troškova:** uspješni odgovori bez prijenosa u toku također sadrže skup telemetrije troškova `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, fiksno 10 decimala; `0.0000000000` za besplatne ili stavke bez definisane cijene), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` i `X-OmniRoute-Fallback-Attempts` (samo kada je > 0), kao i `X-OmniRoute-Request-Id` i `X-OmniRoute-Version`. Njih šalju dovršavanja razgovora, `/v1/responses`, `/v1/messages` **i krajnje tačke za medije** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` i `/v1/moderations` (trošak je uvijek `0`). Trošak medija izračunava se prema modalitetu (po slici, sekundi, znaku ili jedinici pretrage) kada su cijene dostupne, a u suprotnom iznosi `0` (nastavak rada bez blokiranja).

> **Semantika troška pogotka u keš:** pri POGOTKU semantičkog keša (`X-OmniRoute-Cache-Hit: true`) ne upućuje se poziv prema nadređenoj usluzi, pa je `X-OmniRoute-Response-Cost` jednak `0.0000000000` (**inkrementalni** trošak posluživanja pogotka). Izvorni trošak, odnosno trošak koji bi inače nastao, zasebno se navodi u `X-OmniRoute-Cost-Saved`. Sistemi za obračun trebaju sabirati `X-OmniRoute-Response-Cost` (pogoci ne koštaju ništa); analitika keša može objedinjavati `X-OmniRoute-Cost-Saved`.

## Ekskluzivni zakup upravljanih sesija

Ekskluzivni zakup upravljanih sesija predstavlja opcionalni ugovor o usmjeravanju, nezavisan od klijenta: jedan aktivni vlasnik
drži jednu prihvatljivu OmniRoute vezu. Njime se ne zakupljuje model, ne zahtijeva OAuth, ne identificira
određeni klijent niti se zahtijeva određeni pružalac usluga.

API ključ koji se koristi za autentifikaciju mora imati opseg `lease:exclusive` i eksplicitnu nepraznu
listu `allowedConnections`. Granica izmjene baze podataka osigurava zajedničko prisustvo oba polja pri
kreiranju ključa i djelimičnim ažuriranjima.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Uspješni odgovori na preuzimanje, obnavljanje i oslobađanje prikazuju vremenske oznake, `state` i tačnu pozitivnu
`generation`, ali nikada odabranu vezu ili pristupne podatke. Za obnavljanje i oslobađanje generacija se navodi
u JSON tijelu:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Vlasnik aktivnog zakupa može eksplicitno zatražiti metapodatke za prikaz, koji čuvaju privatnost, za svoju trenutnu vezu:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Ova opcionalna radnja za provjeru statusa zaštićena je neprozirnim vlasnikom, autentificiranim upravljanim API ključem i tačnom
aktivnom generacijom unutar jedne transakcije baze podataka. `displayName` predstavlja samo skraćeni konfigurirani
naziv veze; vrijednost je `null` kada ne postoji siguran konfigurirani naziv. OmniRoute nikada ne koristi
adresu e-pošte ili generirani identitet računa kao zamjenu. Vrijednost pružaoca usluga je neosjetljiva oznaka za prikaz i nikada
nije generirani identifikator kompatibilnog pružaoca usluga. Pristupni podaci, tokeni, kolačići, sirovi ID-jevi veze ili API
ključa, sažeci vlasnika, tajne za ograđivanje i interni podaci o usmjeravanju su isključeni.

Pretrage s pogrešnim ključem, pogrešnim vlasnikom, zastarjelom generacijom te nedostajuće, istekle, oslobođene i poništene pretrage
vraćaju istu grešku `409 LEASE_FENCE_STALE` bez metapodataka o vezi. Klijent koji je primio odgovor o čekanju kapaciteta nema aktivnu vezu koju može provjeriti. Kada usmjeravanje prebaci aktivni zakup,
ista generacija ostaje važeća, a status atomski vraća novu vezu, nikada staru.
Postojeći klijenti ostaju nepromijenjeni jer odgovori na preuzimanje, obnavljanje, oslobađanje i čekanje zadržavaju
svoje prethodne oblike.

Ovaj serverski ugovor ne mijenja standardni OpenAI Codex `/status`. Standardni Codex trenutno prijavljuje svog
pružaoca modela i ugrađeno stanje autentifikacije/računa, ali ne prikazuje proizvoljne prilagođene
metapodatke računa pružaoca usluga; buduća integracija klijenta mora pozvati ovu radnju i odlučiti kako
prikazati `connection.displayName`.

Svaki upravljani zahtjev za zaključivanje zatim navodi oba kontrolna zaglavlja:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Tačan vlasnik, generacija, aktivna veza i autentificirani API ključ provjeravaju se neposredno
prije svakog podržanog pokušaja prema nadređenoj usluzi. Ponovno korištenje vlasnika i generacije s drugim ključem ne uspijeva čak
ni kada taj ključ dopušta istu vezu. Sirovi podaci o vlasnicima se ne pohranjuju, ne zapisuju u evidenciju, ne zadržavaju u
snimci zahtjeva niti se prosljeđuju nadređenoj usluzi.

Privremeno zauzeće vraća HTTP `429` s `Retry-After` i:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Ovaj odgovor znači samo da standardni skup prihvatljivih veza nije bio prazan i da je svaki slobodni kandidat bio
zauzet stranim aktivnim zakupom. Nepodržani modeli/pružaoci usluga, neusklađenost pravila, period čekanja, kvota,
stanje ispravnosti i drugi standardni neuspjesi prihvatljivosti zadržavaju svoje postojeće OmniRoute odgovore.

### `x-omniroute-compression`

Podešavanje plana sažimanja za pojedinačni zahtjev. Ima najviši prioritet — nadjačava podešavanje kombinacije usmjeravanja,
aktivni profil, automatski okidač i zadanu postavku panela. Vrijednosti:

| Vrijednost    | Efekat                                                                                                            |
| ------------- | ----------------------------------------------------------------------------------------------------------------- |
| `off`         | Bez sažimanja za ovaj zahtjev.                                                                                    |
| `default`     | Zadani profil izveden iz panela (zanemaruje aktivni profil). Mehanizmi s gubitkom ostaju isključeni.              |
| `safe`        | Samo deduplikacija i objedinjavanje praznina.                                                                     |
| `allow-lossy` | Zadržava plan operatera za ovaj zahtjev, uključujući sažetke i preoblikovanja stila.                              |
| `engine:<id>` | Jedan mehanizam kada je omogućen, npr. `engine:rtk`. Opcionalno uključivanje tog mehanizma po zahtjevu.           |
| `<combo>`     | Imenovana kombinacija koja se prvo podudara prema nazivu (bez obzira na velika i mala slova), a zatim prema ID-u. |

Napomene:

- Nepoznate vrijednosti se zanemaruju (zahtjev se nikada ne odbija); razrješavanje se nastavlja prema uobičajenom redoslijedu prioriteta operatera.
- Ako više kombinacija dijeli isti naziv, proslijedite **id** kombinacije radi determinističkog podudaranja.
- Kombinacija čiji je naziv `off` ili `default` ne može se odabrati prema nazivu (te se ključne riječi prvo tumače); takvu kombinaciju navedite pomoću njenog ID-a.
- Glavni prekidač za sažimanje predstavlja strogo ograničenje: kada je sažimanje globalno onemogućeno, ovo zaglavlje ga ne može omogućiti.

Primijenjeni plan vraća se u zaglavlju odgovora:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

gdje je `<source>` jedno od `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` ili `off`.

## Ugrađivanja

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Dostupni pružaoci usluga: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

ID-ovi kataloga imaju format `provider/model` (primjer: `jina-ai/jina-embeddings-v5-omni-small`). Osnovni ID-ovi Jina modela koji se pojavljuju u registru (na primjer `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) također se razrješavaju. Jina operacije ugrađivanja, ponovnog rangiranja, klasifikacije i segmentacije prvo koriste vjerodajnice `jina-ai` s kontrolne ploče; `JINA_AI_API_KEY` se koristi kao rezervna opcija samo kada ne postoji ključ s kontrolne ploče. Kartica `jina-reader` služi samo za Reader / `r.jina.ai` (`POST /v1/web/fetch`) i nikada ne pruža ugrađivanja niti ponovno rangiranje.

Modeli u registru koji navode podršku za više modaliteta također prihvataju do 32 strukturirane
stavke nezavisne od pružaoca usluge. Tipovi medijskih stavki su `text`, `image`, `audio`, `video` i `document`. Njihov medijski `source`
je ili `{"type":"url","url":"https://..."}` ili
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
i porodični alias `jina-ai/jina-embeddings-v5-omni` → omni-small) također prihvata Jina izvorne
EmbeddingsV5Request dokumente i **prosljeđuje ih neizmijenjene** na `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Izvorne vrijednosti `{ image | audio | video | pdf }` mogu biti javni HTTPS URL, `data:` URI ili sirovi
base64. OmniRoute ne pretvara te objekte u stringove niti dohvaća izvorne URL-ove slika — Jina sama dohvaća
javni medijski sadržaj. Dodatna Jina polja (`task`, `normalized`, `truncate`, `embedding_type`) se
prosljeđuju. Jina SKU-ovi koji podržavaju samo tekst i dalje odbijaju netekstualne dokumente.

Sigurnosna i transportna ograničenja:

- URL-ovi udaljenih medijskih sadržaja moraju biti javni HTTPS. Kanonske `{type,source:url}` stavke se dohvaćaju
  na strani servera (ponovna provjera preusmjeravanja, vremensko ograničenje, ograničenja veličine, javni DNS, vezivanje konekcije) i
  ugrađuju prije poziva pružaocu usluge. Izvorne Jina stavke `{image:"https://..."}` prosljeđuju se bez izmjena
  nakon iste provjere javnog HTTPS-a; Jina dohvaća URL.
- Ugrađeni base64 medijski sadržaj ograničen je na 8 MiB dekodiranih podataka po stavci i 16 MiB dekodiranih podataka za cijeli zahtjev.

Prevođenje za pružaoce usluga (kanonske stavke se nikada ne prosljeđuju neizmijenjene):

- Jina multimodalni modeli: svaka stavka najvišeg nivoa postaje jedan objekt s ključem modaliteta
  (`text` / `image` / `audio` / `video` / `pdf`), koristeći URI-je podataka za ugrađeni medijski sadržaj; jedan vektor po
  stavci najvišeg nivoa.
- Porodica Gemini Embedding 2: jedan niz najvišeg nivoa postaje jedan izvorni
  `models/{model}:embedContent` zahtjev s `content.parts` (`text` ili `inline_data`).
- llama.cpp (`llama-cpp/<model>`, bilo koji model koji je lokalni server učitao): kanonske `text` stavke
  postaju obični stringovi, a `image` / `audio` / `video` postaju po jedan
  `{"content": [part]}` objekt, koristeći dijelove sadržaja razgovora llama-servera (`image_url`,
  `input_audio` s formatom `wav` / `mp3` / `flac`, `input_video`) s ugrađenim podacima; jedan vektor
  po stavci najvišeg nivoa. Server mora biti pokrenut s `--embedding --mmproj …`; bez projektora
  sam odbija medijski sadržaj. `document` nije podržan.
- Nepoznati/dinamički modeli bez eksplicitnih metapodataka o modalitetima odbijaju strukturirani unos s HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Nepodržane kombinacije modela i modaliteta vraćaju HTTP 400 umjesto prisilnog pretvaranja stavke. Polja proširenja koja nisu dio unosa
u naslijeđenim zahtjevima sa stringovima/tokenima i dalje se prosljeđuju neizmijenjena.


## Generisanje slika

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Dostupni pružaoci uključuju OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (lokalno), ComfyUI (lokalno).

`n` vraća `n` slika u `data[]`. Za pružaoce čiji upstream API vraća jednu sliku po pozivu
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI) izvršava se `n` zasebnih upstream poziva, pri čemu su najviše 4 istovremeno aktivna. Fiksni
`seed` se uvećava za indeks poziva (`seed`, `seed + 1`, …), tako da se slike razlikuju, ali ostaju
reproducibilne. `n` je ograničen na 10. Cijeli zahtjev ne uspijeva ako bilo koji poziv ne uspije. Lista
formata s paralelnim pozivima nalazi se u `SINGLE_IMAGE_FANOUT_FORMATS` u
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux ponovo koristi postojeću vezu s API ključem i prihvata prefikse `zenmux/` ili `zm/`:

- `zenmux/openai/gpt-image-2` koristi ZenMuxov OpenAI Images API. Opcije uključuju `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` i `response_format`.
- Drugi izdavači, kao što je `zm/meta/muse-image-1.0`, koriste ZenMuxovu Vertex AI `:predict`
  krajnju tačku. `n` se mapira na `sampleCount`, `aspect_ratio` na `aspectRatio`, a `image_size`
  (`1K`, `2K`, `4K`) na `sampleImageSize`. Vrijednost `size` u pikselima određuje samo omjer širine i visine,
  a ne garantovane dimenzije u pikselima. Podržani omjeri, rezolucije i brojevi razlikuju se zavisno od modela.
- `zm/inclusionai/ming-image-0.1-design` samostalno bira svoje dimenzije. Izostavite `size`,
  `aspect_ratio` i `image_size`; eksplicitne vrijednosti vraćaju HTTP 400. PNG, JPEG i WebP
  mogu se zatražiti pomoću `output_format`.

Ova integracija podržava generisanje slika iz teksta, ali ne i uređivanje referentnih slika. Vertex
izlaz se normalizuje u `data[].b64_json`; `response_format: "url"` vraća upstream
HTTPS URL ili URL podataka u base64 formatu kada su dostupni samo bajtovi slike. Prazni/filtrirani izlazi
vraćaju grešku umjesto praznog uspješnog odgovora. Pristup modelu zavisi od ZenMux računa.
Pogledajte [ZenMuxov Vertex API](https://docs.zenmux.ai/api/vertexai/generate-images) i
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash

GET /v1/images/generations
```

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",

}
```

### Tok provjere statusa za Azure Document Intelligence

API `analyze` usluge Azure Document Intelligence je asinhron: početni zahtjev vraća
zaglavlje `Operation-Location` umjesto tijela, a rezultat se mora periodično provjeravati. Rukovalac
(`open-sse/handlers/ocr.ts`) provjerava taj URL svake sekunde, najviše 30 puta, odmah prekida uz grešku (ne
nastavlja provjeru) ako odgovor provjere nema status `ok` ili ima status `"failed"` te vraća `504` ako je
operacija i dalje u toku nakon što se iscrpi dozvoljeni broj pokušaja. Konačni Azureov odgovor
normalizuje se u isti oblik `pages`/`markdown` koji koristi Mistral prije nego što se vrati
pozivaocu, tako da klijentski kôd ne mora posebno obrađivati svakog pružaoca.

### Autentifikacija i razrješavanje krajnje tačke za Vertex AI DeepSeek OCR

`vertex-deepseek-ocr` ponovo koristi istu Vertex AI autentifikaciju koju OmniRoute već podržava za
saobraćaj razgovora/slika (`open-sse/executors/vertex.ts`): API ključ veze je ili
JSON vjerodajnica servisnog računa (koja se razmjenjuje za kratkotrajni OAuth pristupni token putem JWT-bearer
toka) ili već izdani OAuth pristupni token koji se koristi bez izmjena. URL upstream krajnje tačke je Vertexova
generička partnerska krajnja tačka `openapi/chat/completions`, izgrađena iz projekta i
regije veze — eksplicitni `providerSpecificData.project`/`providerSpecificData.region` uvijek imaju prednost;
u suprotnom se projekt izvodi iz `project_id` JSON-a servisnog računa, a zadana regija
je `us-central1`. Oba razrješavanja odvijaju se u `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), a koristi ih
`src/app/api/v1/ocr/route.ts` prije prosljeđivanja u `handleOcr`.

### Cijene modela (`pricing`)

Stavka sadrži objekt `pricing` kada OmniRoute zna cijenu modela. Cijena dolazi
iz tabele cijena koju koristi obračun troškova: ugrađene zadane vrijednosti, sinhronizirane cijene i
zamjene postavljene putem `/api/pricing`. Ovo su kataloške cijene, tako da pružaoci pretplate također
prikazuju cijenu po tokenu.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Polja                                                           | Jedinica                     | Napomene                                                                                                                                         |
| --------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | USD po tokenu, decimalni niz | Kompatibilno s OpenRouterom, nikada u eksponencijalnom zapisu. Dva polja predmemorije pojavljuju se samo kada postoji cijena predmemorije.       |
| `input`, `output`, `cached`, `cache_creation`                   | USD po 1M tokena, broj       | Polja iz ranijih verzija kataloga, zadržana za postojeće klijente. `reasoning` i `long_context` također se pojavljuju kada ih red cijena sadrži. |

- **Kombinacije** sadrže cijenu svog prvog vidljivog odredišta. Ugrađene `auto/*` kombinacije biraju
  odredište u trenutku zahtjeva, pa nemaju `pricing`.
- **Besplatni modeli** prikazuju `"0"` (i `0`) kada je njihova cijena nula. Model bez reda s cijenom
  također prikazuje `"0"` kada ga katalog označava kao besplatnog (`free: true`) ili kada se nalazi u ugrađenom
  katalogu besplatnih modela.
- **Nepoznata cijena:** stavka nema ključ `pricing`.
- **Pružaoci s obračunom prema kreditima** (kao što je Kiro) naplaćuju po zahtjevu umjesto po tokenu. Njihove
  stavke zadržavaju numerička polja po 1M tokena koja su ranije imale i ne sadrže tekstualna polja po tokenu.
- **Varijante** (ID-jevi nivoa intenziteta zaključivanja, aliasi bez razmišljanja, ogledala za otkrivanje i pristupnik)
  kopiraju cijenu modela na koji usmjeravaju.
- Polja sadrže samo osnovne cijene. Nivoi dugog konteksta (numeričko polje `long_context`) i
  množitelji nivoa usluge (na primjer Codex fast ili flex) ne mijenjaju `prompt` ili
  `completion`.
- Objekt je isti za svaki način autentifikacije, uključujući zahtjev u Anthropic stilu
  s `x-api-key` i `anthropic-version` (odgovor ostaje `{ "object": "list",
"data": [...] }`). Implementacija: `src/app/api/v1/models/catalogPricing.ts`.

### Prefiksi ID-jeva modela (`?prefix=`)

Većina modela oglašava se pod **prefiksom pružaoca**. Prefiks koji dobijete kontroliše
oznaka funkcionalnosti `MODELS_CATALOG_PREFIX_MODE`, a može se zamijeniti **za svaki pojedinačni zahtjev** pomoću
parametra upita — korisno za klijenta koji želi čistu listu bez mijenjanja postavke
na nivou servera za sve ostale:

```bash
GET /v1/models?prefix=alias        # jedan ID po modelu — kratki prefiks aliasa
GET /v1/models?prefix=dual         # oba oblika (zadana postavka servera)
GET /v1/models?prefix=canonical    # samo puni prefiks ID-ja pružaoca
```

| Način       | Emituje                                                 | Napomene                                                                                                                                                                                |
| ----------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **i** `claude/claude-sonnet-4-6` | **Zadano.** Oba ID-ja usmjeravaju na isti model; zadržano kako bi konfiguracije klijenata koje su unaprijed kodirale bilo koji oblik nastavile raditi. Približno udvostručuje katalog.  |
| `alias`     | `cc/claude-sonnet-4-6`                                  | Jedna stavka po modelu. Pružaoci bez zasebnog aliasa i dalje emituju svoju stavku, tako da se ništa ne gubi.                                                                            |
| `canonical` | `claude/claude-sonnet-4-6`                              | Jedna stavka po modelu pod punim prefiksom ID-ja pružaoca. Pružaoci bez zasebnog aliasa (npr. `antigravity/…`, `agy/…`) ovdje također emituju svoj jedini ID, tako da se ništa ne gubi. |

Ogledalo u načinu `dual` može se prepoznati i bez parametra upita: sadrži polje `parent`
koje upućuje na primarni ID.

Klijenti koji prikazuju birač modela trebaju zatražiti `?prefix=alias` — to radi
[OmniCopilot VS Code proširenje](../guides/VSCODE-COPILOT.md).

### Filteri za otkrivanje (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` prihvata opcionalne filtere za otkrivanje. Bez ijednog od njih odgovor ostaje
nepromijenjen. Oni sužavaju katalog koji pozivalac već vidi (dozvole API ključa primjenjuju se prvo),
a izvršavaju se prije straničenja u OpenAI stilu pomoću `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # svaka navedena sposobnost mora biti istinita
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # kataloški `type`; redovi bez njega su `chat`
GET /v1/models?q=sonnet&limit=10                           # podudaranje ID-ja ili naziva bez razlikovanja velikih i malih slova
```

| Parametar     | Vrijednosti                                                                                         |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | nenegativan cijeli broj, poredi se sa `context_length`                                              |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 znakova                                                                                       |

Nepoznata vrijednost ili `min_context` koji nije nenegativan cijeli broj (na primjer `1.5`)
vraća HTTP `400`, a poruka navodi važeće vrijednosti. Implementacija:
`src/app/api/v1/models/catalogFilters.ts`.

### Uži izbor modela (`POST /v1/models/query`)

`POST /v1/models/query` vraća kratku, determinističku listu iz istog kataloga, s istom
autentifikacijom i vidljivošću po ključu kao `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Svako polje je opcionalno. `capabilities` i `exclude` prihvataju niz ili niz znakova razdvojen zarezima;
`max_output` se poredi sa `max_output_tokens`. Rezultati se sortiraju prema `owned_by`, a zatim prema `id`.
Zadana vrijednost za `limit` je `20`, a vrijednosti iznad `100` ograničavaju se na `100`. Nevažeći JSON, nepoznato
polje ili nevažeća vrijednost vraćaju HTTP `400`.

### Pojedinačno skriveni chat modeli

Model označen kao **Skriven** na stranici svog pružatelja usluge isključen je iz kataloga i odbija se
uz HTTP `404` / `model_not_found` kada se izričito zatraži. Provjera koristi razriješenog
pružatelja usluge i model, uključujući pseudonime pružatelja usluge, prefikse čvorova kompatibilnog pružatelja usluge i
zadane vrijednosti veze. Kombinacija preskače skrivene ciljeve i može koristiti vidljivi srodni model; kada ne
preostane nijedan izvršivi cilj, vraća isti kôd greške. Uklanjanje oznake skrivenosti stupa na snagu pri sljedećem
zahtjevu. Nadjačavanja vidljivosti samo za slike ne skrivaju chat model s istim ID-om.

Ova postavka pojedinačnog modela odvojena je od
[lista dozvoljenih/zabranjenih modela za izlaganje](../routing/MODEL_EXPOSURE_LIST.md), koje filtriraju oglašavanje
kataloga i kandidate za automatsko usmjeravanje, a zadržavaju izričito prosljeđivanje. Dozvole modela
API ključa nastavljaju se primjenjivati nezavisno. Zadani način rada prefiksa kataloga ostaje `dual`.

### Varijante modela bez razmišljanja

Za Claude modele koji podržavaju razmišljanje, `/v1/models` također oglašava varijantu **bez razmišljanja** čiji ID ima prefiks `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Odabir ovog ID-a (npr. u Claude Code konfiguraciji koja uvijek prilaže blok `thinking`) razrješava se nazad na stvarni `<provider>/<model>` uz potisnuto zaključivanje — `thinking:{type:"disabled"}` na putanji `/v1/messages` ili uz uklonjena polja `reasoning`/`reasoning_effort` na putanji `/v1/chat/completions`. Varijanta se navodi samo za modele iz porodice Claude koji podržavaju razmišljanje **i** poštuju `disabled` (tako da su, npr., isključeni modeli koji podržavaju samo adaptivni način rada i odbijaju `disabled`). Operateri mogu prisilno uključiti ili isključiti varijantu za svaki model putem `ModelSpec.noThinkingAlias`.

## ElevenLabs generiranje zvuka

Konfigurirajte vezu s pružateljem `elevenlabs` u OmniRouteu koristeći svoj ElevenLabs API ključ.
Klijenti se autentificiraju svojim **OmniRoute** ključem (`Authorization: Bearer $OMNIROUTE_API_KEY`);
mrežni prolaz prosljeđuje pohranjeni ključ pružatelja kao `xi-api-key`. Nikada nemojte slati ElevenLabs ključ
kao bearer token mrežnog prolaza.

| Metoda | Putanja                     | Odgovor                                      | Kategorija krajnje tačke API ključa |
| ------ | --------------------------- | -------------------------------------------- | ----------------------------------- |
| POST   | `/v1/sound-generation`      | Izvorni audio bajtovi                        | `elevenlabs`                        |
| POST   | `/v1/music`                 | Izvorni audio bajtovi                        | `music`                             |
| POST   | `/v1/music/stream`          | Audio bajtovi u prijenosu                    | `music`                             |
| POST   | `/v1/music/detailed`        | Izvorni višedijelni audio i plan kompozicije | `music`                             |
| POST   | `/v1/music/detailed/stream` | Izvorni SSE metapodaci i audio fragmenti     | `music`                             |
| POST   | `/v1/music/plan`            | JSON plan kompozicije                        | `music`                             |

Ove krajnje tačke nadopunjuju postojeće rute `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` i `/v1/speech-to-text`. Izvorna JSON polja
i parametri upita kao što su `output_format` i `enable_logging` ostaju sačuvani.
Odgovori rute `/v1/music/detailed` zadržavaju svoje višedijelne granice; analizirajte ih kao višedijelne podatke.
`/v1/music/detailed/stream` vraća `text/event-stream` s metapodacima kompozicije i
base64 audio fragmentima u SSE događajima. Svih šest ruta podržava CORS preliminarne zahtjeve.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Kratki zvučni efekt. Trajanje: od 0,5 do 30 sekundi.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Trajanje muzike izražava se u milisekundama: od 3000 do 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Koristite `/v1/music/stream` s istim JSON tijelom za postepenu isporuku zvuka. Kompozicija
prihvata tačno jedno od `prompt` ili `composition_plan`; `/v1/music/plan` zahtijeva `prompt`
i opcionalno prihvata `source_composition_plan`. Izvorne sheme zadržavaju dodatna
polja pružatelja usluga kako bi verzije plana kompozicije i opcije finog podešavanja stigle do ElevenLabsa.

Objedinjena krajnja tačka `/v1/music/generations` također prihvata `elevenlabs/music_v1`,
`elevenlabs/music_v2` i `elevenlabs/music_v2_5`. Uz aktivnu ElevenLabs vezu,
ovi modeli se prikazuju u muzičkom katalogu. Ova krajnja tačka vraća
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Njeno polje `duration` izraženo je u
sekundama i preslikava se na `music_length_ms`; eksplicitni `music_length_ms` ima prednost.
`instrumental` se preslikava na `force_instrumental`, pri čemu izvorno polje ima prednost.
Koristite izvorne krajnje tačke za prijenos za strujanje i izvornu krajnju tačku za kompoziciju
za zahtjeve zasnovane isključivo na planu kompozicije.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Ograničenja krajnje tačke, modela, budžeta i veze primjenjuju se prije poziva prema vanjskoj usluzi. Izvorne
rute vraćaju neizmijenjene statusne kodove i tijela grešaka vanjske usluge, uključujući `402` za ograničenje
plana i `429` za ograničenje kvote. Zaglavlja `character-cost`, `song-id`, `request-id` i `retry-after`
ostaju sačuvana kada su prisutna. Besplatno kreditno stanje ne garantira pristup svakom
muzičkom modelu, izlaznom formatu ili API funkciji: ElevenLabs odlučuje o pravu pristupa za svaki zahtjev.
Objedinjena krajnja tačka zadržava statusne kodove grešaka u normaliziranoj OmniRoute omotnici greške.

Ugovori vanjske usluge: [zvučni efekti](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[muzička kompozicija](https://elevenlabs.io/docs/api-reference/music/compose) i
[detalji strujanja muzike](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

Sve POST rute imaju isti oblik: `Bearer your-api-key` + JSON tijelo validirano pomoću Zoda (`v1RerankSchema`, `v1ModerationSchema`, `v1AudioSpeechSchema` itd.; pogledajte `src/shared/validation/schemas.ts`). U slučaju neuspješne validacije šeme vraća se 4xx.

Za klijente koji ne mogu dodati `Authorization: Bearer ...`, OmniRoute također prihvata API ključeve u URL-u putem kompatibilnosti s parametrima upita (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`) ili namjenskih krajnjih tačaka `/api/v1/vscode/{token}/...` dokumentovanih u nastavku.

```bash
# Ponovno rangiranje (pružalac iz registra u oblaku ili čvor pružaoca kompatibilnog s OpenAI-jem kao "<prefix>/<model>")
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Jina klasifikacija (vjerodajnice za Foundation API)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Jina segmentator
POST /v1/segment     { "content": "...", "return_chunks": true }

# Jina pretraga (s.jina.ai; aliasi pružaoca: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# Moderacija
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — vraća tijelo u formatu audio/mpeg (ili u zatraženom formatu)
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS zahtijeva jezik i glas: zadana vrijednost za `language` je "en"; glas koji nedostaje
# ili naziv standardnog OpenAI glasa (alloy, nova, …) postaje "Adrian"
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# Uređivanje slike (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# Generisanje videa/muzike (ID modela s prefiksom pružaoca)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **Čvorovi pružatelja za ponovno rangiranje:** `POST /v1/rerank` također usmjerava na čvorove pružatelja kompatibilne s OpenAI-jem
> (oMLX, vLLM, Infinity, TEI iza pristupnika, …) adresirane kao `<node-prefix>/<model>`. Čvorovi povratne petlje
> (`localhost`, `127.0.0.1`, `172.16.0.0/12`) uvijek su prihvatljivi, kao i nazivi hostova koje
> operater navede u `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (npr. naziv Docker/Compose servisa kao što je
> `http://reranker:8080/v1`; oni se pozivaju direktno, nikada putem `HTTP(S)_PROXY` ili
> proksija prikvačenog za vezu). Čvorovi na bilo kojem drugom
> hostu — uređaju u LAN-u ili Tailscale ravnopravnom čvoru — prihvatljivi su samo kada operater omogući
> funkcijsku zastavicu `RERANK_REMOTE_PROVIDER_NODES` **i** kada osnovni URL čvora prođe politiku
> izlaznih URL-ova pružatelja (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Korak ponovnog rangiranja memorijskog pogona poziva ovu rutu putem
> povratne petlje, tako da isto pravilo upravlja postavkom `rerankProviderModel` u postavkama memorije.
>
> **Oblici lokalnog servera:** čvor se poziva na `<base>/v1/rerank`, a u slučaju odgovora 404 na `<base>/rerank`
> (Infinity, TEI). Tijelo uzvodnog zahtjeva sadrži i Cohere/OpenAI zapis (`documents`,
> `return_documents`) i TEI zapis (`texts`, `return_text`), a uzvodni odgovor
> normalizira se u Cohere omotnicu: TEI-jev neposredni `[{index, score, text}]`, `{results: [{index, score}]}`
> iz jednostavnih pristupnika i Voyageov format `{data: [...]}` vraćaju se klijentu kao
> `{results: [{index, relevance_score, document?}]}`, sortirani prema rezultatu i ograničeni na `top_n`.

> **Otkrivanje čvorova pružatelja:** modeli na čvoru pružatelja kompatibilnom s OpenAI-jem pojavljuju se u `GET /v1/models`
> pod prefiksom čvora. Redovi bez metapodataka o krajnjoj tački (što je tipično za lokalne `/v1/models` popise)
> nasljeđuju `apiType` čvora, tako da su modeli čvora `embeddings` tipa `type: "embedding"`, a modeli
> čvora `rerank` tipa `type: "rerank"` umjesto da im zadani tip bude razgovor; eksplicitni
> `supportedEndpoints` u sinhroniziranom ili ručno dodanom redu i dalje ima prednost.

| POST   | `/v1/search`           | Pokrenite upit za pretragu — tijelo potvrđeno od `v1SearchSchema`, podržava caching/coalescing |
| GET    | `/v1/search/analytics` | hit/latency/cache statistika po provajderu                                                     |

**Auth:** Nosilac API ključa (`extractApiKey` + `isValidApiKey`). Politika pretraživanja nametnuta preko `enforceApiKeyPolicy`.

### Exa i Tavily `provider_options`

Exa i Tavily čitaju polja specifična za dobavljača iz vrećice s prostorom imena: `provider_options.exa` (ili `provider_options["exa-search"]`) i `provider_options.tavily` (ili `provider_options["tavily-search"]`). Prosljeđuju se samo dolje navedeni ključevi. Svaki se provjerava u odnosu na vlastitu Zod šemu u `open-sse/handlers/search/providerOptionsPassthrough.ts`, a ključ pogrešnog tipa se ispušta. Bilo koji drugi ključ se zanemaruje, uključujući auth, bazu URL, `stream` i `outputSchema`. Ravni ključevi koje koriste drugi provajderi (`cx`, `depth`, ...) rade kao i prije.

| Provajder | Polja najvišeg nivoa                                                                                                                                                                                                                                                                                                                                                      | Nested                                                                                                                                |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Exa       | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (ravni primitivi), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                              | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` spojen preko zadanog `{ text: true, highlights: true }` |
| Tavily    | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                     |

Generička polja uvijek pobjeđuju: `query`, `max_results`, `filters` (domene), `country` i tema izvedena iz `search_type`. Na Exa, `search_type: "news"` zadržava `category: "news"`. Tavily također prihvata `search_type: "finance"` (`topic: "finance"`).

Trošak Firecrawl pretraživanja se bilježi po započetom bloku od 10 vraćenih rezultata, po 0,002 USD (2 kredita) po bloku i najmanje jednom bloku po pozivu ( [Firecrawl naplata](https://docs.firecrawl.dev/billing) ): 11 rezultata košta 0,004 USD.

Generički `time_range` sada stiže do oba provajdera: Exa dobija `startPublishedDate` (ISO vremenska oznaka), a Tavily dobija `start_date` (`YYYY-MM-DD`). Eksplicitni datum u `provider_options` nadjačava mapirani.

Exa rezultati zadržavaju `id`, `highlight_scores`, `summary`, `subpages`, `entities` i `extras` u `provider_raw`. Tavily rezultati zadržavaju `images` i `favicon`.

Trošak pretraživanja veze se bilježi na 0,005 USD za `depth` `fast` i `standard` i 0,05 USD za `deep` ( [cijene povezivanja](https://docs.linkup.so/pages/documentation/development/pricing) ), bez obzira da li `depth` dolazi iz `provider_options` ili postavki veze.

Exa `type: "lite"` (Exa 3.0) prihvata manji skup polja i odbija cijeli zahtjev kada se postavi bilo koje drugo polje. Za lite, `additionalQueries`, `systemPrompt` i svaki `contents` ključ osim `text` i `highlights` se ispuštaju prije poziva. Zastarjeli `subpages`, `subpageTarget`, `highlights.numSentences` i `highlights.highlightsPerUrl` se više ne prosljeđuju.

Računovodstvo troškova je ravni registar `costPerQuery`, osim za Exa, koji slijedi Exa-e vlastite cijene: 0,007 USD po pozivu za `auto` (i naslijeđeni `fast`) ili 0,004 USD za `lite` (i naslijeđeni `instant`), pokrivajući 10 rezultata; 0,001 $ za svaki dalji rezultat; i 0,001 $ po vraćenom rezultatu kada je postavljen `contents.summary`. Tavily je zabilježen na 1 kredit (0,008 USD) za `search_depth` `basic`, `fast` i `ultra-fast`, i 2 kredita (0,016 USD) za `advanced` ( [Tavily API krediti](https://docs.tavily.com/documentation/api-credits) ). Poziv sa `auto_parameters: true` koji Tavily nadogradi na napredni i dalje se snima na 1 kredit.

## Web Fetch API

Izdvojite sadržaj iz URL-a putem konfigurisanog web-fetch pružaoca (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, isti API ključ kao za Parallel Search) vraća samo
Markdown — bilo koji drugi `format` rezultira statusom `400` — i ograničava sadržaj na 100.000 znakova. Kada
samu ciljnu stranicu nije moguće izdvojiti, nadređeni servis to prijavljuje unutar HTTP 200 odgovora;
OmniRoute to prikazuje kao `422` s fiksnom porukom.

| Metoda | Putanja         | Opis                                                                 |
| ------ | --------------- | -------------------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Dohvata/prikuplja URL — tijelo se validira pomoću `v1WebFetchSchema` |

**Autorizacija:** Bearer API ključ (`extractApiKey` + `isValidApiKey`). Pravila se primjenjuju putem `enforceApiKeyPolicy`.

**Rezervni odabir koji uzima u obzir kvotu (#8297):** kada nije naveden eksplicitni `provider`, skup
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) prolazi se fiksnim
redoslijedom prioriteta (prvo popunjavanje) — konfigurisan pružalac s ograničenom stopom zahtjeva se preskače
umjesto da se zahtjev odmah prekine, a ponovljiva greška ili greška kvote nadređenog servisa
(HTTP 429 uvijek; 402/403 za kvote besplatnih nivoa servisa Firecrawl/Tavily/TinyFish —
ne za Jina Reader i nikada za običan 400 neispravan zahtjev) u vrijeme zahtjeva prelazi na
sljedećeg još nepokušanog pružaoca s vjerodajnicama. Kada su iscrpljeni svi pružaoci u
skupu, krajnja tačka vraća jedan `429` (sa zaglavljem `Retry-After`)
umjesto prethodnog generičkog `400`. Kada se zatraži eksplicitni `provider`,
**nema** tihog rezervnog odabira — eksplicitni pružalac s ograničenom stopom zahtjeva ili greškom
prikazuje vlastitu grešku (`429` ako je stopa ograničena, u suprotnom status
nadređenog servisa).

## WebSocket prijenos

```bash
GET /v1/ws?handshake=1
```

Validira rukovanje za WebSocket nadogradnju i vraća primjere poruka protokola na mreži (`request`, `cancel`). Stvarnim WS okvirima upravlja uključeni WS server izvan tabele Next.js ruta.

**Autorizacija:** Bearer API ključ tokom rukovanja.

### Responses API putem WebSocketa (samo codex)

```bash
# Isti host:port kao HTTP API (zadano 20128); nadogradite vezu:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (ili: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Prvi okvir MORA biti response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proxy za Responses API putem WebSocketa povezan je **isključivo s `codex`** (ChatGPT
pozadinski servis). Osluškuje na istom portu kao API/kontrolna ploča, na putanjama `/v1/responses`,
`/responses` i `/api/v1/responses`. Pri prvom okviru `response.create`
obavlja autentifikaciju i pripremu putem internog mosta `codex-responses-ws`, odabire
codex OAuth vezu i uspostavlja tunel prema `wss://chatgpt.com/backend-api/codex/responses`
putem transporta `wreq-js`. **Modeli koji nisu codex se odbijaju** (`codex_ws_provider_required`).
Za usmjeravanje s dijeljenjem kvote koristite `model: "qtSd/<group>/codex/<model>"`. Implementirano u
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Autorizacija:** Bearer API ključ tokom rukovanja. Uključeni HTTP server (`server-ws.mjs`)
mora biti aktivna ulazna tačka (što je zadano kada postoji `app/server-ws.mjs`).

#### ID modela: koristite izvorni ChatGPT ID (bez prefiksa `codex/`)

OpenAI **Codex CLI** validira naziv modela na strani klijenta kada je
`supports_websockets = true` i **odbija ID-ove s prefiksom pružaoca** poput
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Pošaljite **izvorni** ID (npr. `gpt-5.5`). OmniRouteov most je
namijenjen samo za codex, pa prije uspostavljanja tunela prema nadređenom servisu ponovo razrješava izvorni ID kao codex model
(`resolveCodexWsModelInfo`) — iako bi se izvorni
`gpt-5.5` putem HTTP-a inače usmjerio drugom pružaocu.

#### Konfigurisanje OpenAI Codex CLI-ja

Usmjerite Codex CLI na OmniRoute dodavanjem prilagođenog pružaoca s podrškom za WebSocket
u `~/.codex/config.toml` (koristite zaseban `CODEX_HOME` kako biste izbjegli mijenjanje
postojeće konfiguracije):

```toml
model = "gpt-5.5"                 # izvorni ID — NE "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"

wire_api = "responses"                    # jedina podržana vrijednost od februara 2026.
supports_websockets = true                # omogućava transport Responses-over-WS
env_key = "OMNIROUTE_API_KEY"             # sadrži OmniRoute API ključ (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # OmniRoute API ključ (bilo koji ključ ako je REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI nadograđuje `base_url + /responses` na WebSocket, a OmniRoute uspostavlja tunel
prema odabranoj codex OAuth vezi. Validirano od početka do kraja na lokalnom
serveru: ChatGPT vraća `codex.rate_limits` + `response.created` i prenosi
dovršetak.

## Samostalni pregled potrošnje (`/api/usage/om-usage`)

Svaki API ključ može očitati **vlastitu** potrošnju i kvote — bez upravljačke autentifikacije. Ovo je krajnja tačka koju
klijent (CLI, OmniCopilot panel) koristi kako bi vlasniku ključa prikazao njegovu potrošnju.

```bash
# Tekstualni oblik (historijski ugovor — obični tekst za terminal)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Strukturirani oblik — ono što korisničko sučelje koristi
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Ključ mora imati omogućen **`allowUsageCommand`** (podrazumijevano je isključen — upravitelj API ključeva
na kontrolnoj ploči uključuje ga zasebno za svaki ključ). Bez toga krajnja tačka odgovara statusom `403`.

`?format=json` vraća diskriminiranu strukturu kako pozivatelj nikada ne bi očitao podatkovno polje iz
odbijenog zahtjeva. U slučaju uspjeha:

```jsonc
{
  "allowed": true,
  // prisutno samo kada je za ključ uključeno ograničenje potrošnje po ključu (dnevno/sedmično u USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // snimak kvote odabranog pružatelja ili null kada još ništa nije keširano:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // snimak svake veze kako bi korisničko sučelje moglo prikazati više pružatelja jednog pored drugog:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

U slučaju odbijanja (`401` neispravan ključ / `403` nije dozvoljeno), ista ruta vraća
`{ "allowed": false, "error": { "message": "…" } }` — prisutan, ali prazan `personal`/`provider`
(ključ je dozvoljen, ali još ništa nije utvrđeno) predstavlja stanje koje se razlikuje od odbijanja, a samo ih JSON oblik
razlikuje.

**Autentifikacija:** pozivateljev vlastiti Bearer API ključ, provjeren pomoću `isValidApiKey` — ovo _nije_
upravljačko sučelje (`/api/keys/…`), koje ostaje zaštićeno pomoću `requireManagementAuth`.

### Sirovi postoci kvote naspram postotaka prilagođenih graničnoj vrijednosti

Pri korištenju `/api/usage/om-usage` pozivatelji trebaju obratiti pažnju na razliku između
postotaka prikazanih u **običnom tekstualnom izlazu** i strukturiranom **JSON izlazu**:

| Aspekt                              | Format običnog teksta (`/api/usage/om-usage` / `@@om-usage`)                                                        | JSON format (`?format=json`)                                                    |
| :---------------------------------- | :------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------ |
| **Izlazno polje**                   | `NN% left` (npr. `20% left`)                                                                                        | `provider.quotas` / `providers[].quotas`                                        |
| **Mjerenje**                        | **Iskoristivo ograničenje prilagođeno graničnoj vrijednosti**: preostali kapacitet iznad praga granične vrijednosti | **Sirova kvota nadređenog pružatelja**: neprilagođeno mjerenje pružatelja       |
| **Skaliranje granične vrijednosti** | Skalirano putem `effectiveRemainingPercent()` tako da se zaštićena rezerva prikazuje kao `0% left`                  | Nema (sirove vrijednosti snimka koje je prijavio pružatelj)                     |
| **Podaci o pragu**                  | Uključeni u prikazani postotak                                                                                      | Pohranjeni u `quotaWindowThresholds` po vezi (ili u zadanim postavkama servera) |
| **Primarni korisnik**               | Interaktivni CLI-jevi, terminalni upiti, ljudski operateri                                                          | Programske integracije, kontrolne ploče, analitika, alati za praćenje naplate   |

#### Formula prilagođavanja graničnoj vrijednosti

OmniRoute podržava proaktivne granične vrijednosti kvota radi sprečavanja iscrpljivanja resursa nadređenog pružatelja (konfigurirane putem
`quotaWindowThresholds` veze, zadanih postavki pružatelja ili globalnih postavki otpornosti). Kada je prag granične vrijednosti
(npr. `cutoff = 25%`) aktivan za vremenski okvir kvote, prikazivač teksta izračunava preostalo ograničenje na sljedeći način:

- Ako je `remaining <= cutoff`: vraća `0%`.
- Ako je `remaining > cutoff`: vraća `((remaining - cutoff) / (100 - cutoff)) * 100`.

Formatirani tekstualni izlaz zaokružuje ovu vrijednost na najbliži cijeli broj (`Math.round(...)`).

#### Ilustrativni primjer

Razmotrite vremenski okvir pružatelja sa **60% sirove potrošnje** (dakle, **40% sirove preostale kvote**) i konfiguriranim
pragom **granične vrijednosti od 25% preostale kvote**:

| Prikaz                             | Izračun                                            | Preostalo |        Podrazumijevano iskorišteno        |
| :--------------------------------- | :------------------------------------------------- | :-------: | :---------------------------------------: |
| **Sirovi JSON (`?format=json`)**   | Snimak nadređenog pružatelja (`quotas[window]`)    |  **40%**  |                  **60%**                  |
| **Tekstualni format (`NN% left`)** | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` |  **20%**  | **80%** (ako se računa `100 - remaining`) |

- **Zašto tekst prikazuje 20% preostalog:** Od 40% fizičke kvote preostale na računu, 25% je rezervirano pravilom
  granične vrijednosti. Pozivatelju je preostalo samo 15% od 75% iskoristivog prostora prije nego što usmjerivač prestane
  usmjeravati zahtjeve prema ovoj vezi. Skaliranje osigurava da veza signalizira iscrpljenost (`0% left`) tačno kada
  usmjeravanje prestane.
- **Zašto JSON zadržava sirove vrijednosti:** JSON korisni sadržaj vraća tačan snimak pružatelja (`UsageSnapshot`)
  kako bi vanjski alati imali pristup stvarnom iskorištenju kod nadređenog pružatelja i vrijednostima
  `quotaWindowThresholds` na nivou veze, bez gubitaka uzrokovanih skaliranjem na strani servera.

#### Smjernice za migraciju korisnika

Ako je vanjska integracija (kao što je dodatak za uređivač ili proširenje agenta) prethodno izdvajala tekst s
krajnje tačke (`NN% left`) i izračunavala iskorišteni postotak kao `100 - NN`, prelazak na `?format=json` znači:

- Čitanje neobrađenih JSON vrijednosti odražavat će **stvarnu potrošnju uzvodnog sistema** (60% iskorišteno u prethodnom primjeru).
- Ako integracija želi sačuvati semantiku iskoristivog raspoloživog limita tekstualne krajnje tačke, može izračunati
  efektivnu formulu preostalog limita na klijentskoj strani koristeći `quotaWindowThresholds` za nadjačavanja na nivou veze.

### Utjecaj na latenciju

POGODAK u semantičkoj predmemoriji poslužuje odgovor iz predmemorije **bez
uzvodnog poziva**, pa je prijavljena vrijednost `X-OmniRoute-Response-Latency`
blizu nule (bez obzira na izvornu uzvodnu latenciju). Klijenti osjetljivi na

zaglavlje odgovora `X-OmniRoute-Cache-Latency`:

| Vrijednost  | Značenje                                                                 |
| ----------- | ------------------------------------------------------------------------ |
| `synthetic` | Odgovor poslužen iz predmemorije; latencija nije stvarno uzvodno vrijeme |
| _(odsutno)_ | Odgovor iz stvarnog uzvodnog poziva                                      |

### Zaobilaženje predmemorije po ključu

API ključevi mogu isključiti čitanje semantičke predmemorije putem `cacheDefaultMode`:

| Vrijednost | Ponašanje                                                            |
| ---------- | -------------------------------------------------------------------- |
| `legacy`   | Uobičajeno ponašanje predmemorije (zadano)                           |
| `bypass`   | Potpuno preskoči provjeru predmemorije; uvijek pozovi uzvodni servis |

Postavite pri kreiranju ključa (`POST /api/keys`) ili ažuriranju (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### Zaobilaženje po zahtjevu

Svaki zahtjev može zaobići predmemoriju bez obzira na postavke ključa:

```
X-OmniRoute-No-Cache: true
```

| `/api/provider-models/validate-and-add` | POST                      | Stroga validacija veze uz autentifikaciju za upravljanje i izričitu saglasnost te atomska registracija prilagođenog modela; pogledajte [Validacija modela](../guides/MODEL-VALIDATION.md) |

Za sinhronizirane/uvezene modele, `PUT /api/provider-models` prihvata `provider`, `modelId` i
`maxOutputTokenOverride`: pozitivan cijeli broj postavlja ručno ograničenje izlaznih tokena, a `null`
ga uklanja radi vraćanja zadane vrijednosti. `GET /api/provider-models?provider=<provider>` vraća te
vrijednosti u `modelOutputOverrides`, uključujući modele bez reda prilagođenog modela. Zamjena
koristi mogućnost `max_output_tokens` u vrijeme izvršavanja i zadržava se nakon ponovne sinhronizacije modela. Stranica pružaoca
usluga kompatibilnog s OpenAI-jem nudi iste kontrole za uređivanje/uklanjanje i označava modele s izričitom podrškom za vid.

Prilagođeni čvorovi Chat Completions prilagođavaju izričito isključivanje zaključivanja nadređenom pozadinskom sistemu. Uspješan
test veze automatski odabire kontrole predloška razgovora za svaki tačan ID modela
čiji unos u `/models` dokazuje prepoznatu vrijednost `owned_by`: `vllm`, `sglang` ili `llamacpp`.
Transparentni omotači kompatibilni s OpenAI-jem mogu sačuvati izvorni unos modela unutar ugniježđenog
objekta `openai`; otkrivanje prati do tri takva omotača. Modeli s nedostajućim, nepoznatim ili
proturječnim vlasništvom zadržavaju uobičajeno OpenAI ponašanje. Otkrivanje ponovo koristi postojeći zahtjev kataloga,
ne generira tokene dovršavanja i poništava se kada se promijeni krajnja tačka veze.

Da biste fiksirali ponašanje za pozadinski sistem koji ne izlaže te metapodatke, koristite postojeći API za djelimično
ažuriranje pružaoca usluga:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Pošaljite to tijelo putem `PUT /api/providers/<connection-id>`. Na toj vezi, izričiti
napor zaključivanja postavljen na `none` šalje se kao `chat_template_kwargs.thinking=false` i
`chat_template_kwargs.enable_thinking=false`. Izričite izvorne vrijednosti predloška ostaju mjerodavne
osim ako pravilo zaključivanja na strani servera ne nametne nivo napora. Postavka se primjenjuje samo kada prilagođena
veza kompatibilna s OpenAI-jem šalje tijelo Chat Completions; zahtjevi Responses i uobičajeni
pružaoci usluga zadržavaju svoj izvorni oblik zahtjeva. Postavite `reasoningControl` na `openai` kako biste nametnuli uobičajeno OpenAI
prosljeđivanje vrijednosti `reasoning_effort` ili ga izostavite/postavite na `null` kako biste koristili automatsko otkrivanje.

Zahtjevi klasifikatora automatskog načina rada Claude Codea prema zadanim postavkama onemogućavaju izvorno razmišljanje kada
ne sadrže izričite kontrole zaključivanja. Otkrivanje koristi sistemsku oznaku klasifikatora u zahtjevima
Claude formata, a ne nazive modela ili ograničenja dovršavanja. Izričite kontrole tijela, podržana zaglavlja za nivo napora/razmišljanje,
pravila usmjeravanja i razriješeni nivo napora modela zadržavaju svoj postojeći prioritet. Obje faze klasifikatora
zadržavaju svoje upite, ograničenja dovršavanja, sekvence zaustavljanja i stvarne odluke nadređenog sistema o dozvolama;
druga faza i dalje može proizvesti traženo vidljivo zaključivanje kao običan tekst.

### Verzija i kanal izdanja

```bash
GET /api/system/version
```

Ruta za upravljanje dostupna samo putem povratne petlje (administratorska autentifikacija). Vraća pokrenutu verziju, najnoviju
objavljenu verziju i status automatskog ažuriranja. `releaseChannel` i `channels` su dodatna
polja (grana 3.8.54); `channel` zadržava svoje značenje — način implementacije koji alat za ažuriranje kontrolne ploče
koristi (`npm`, `source` ili `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — npm kanal pokrenute verzije: `nightly` za verzije `-nightly.*`,
  `next` za druga predizdanja (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` za stabilnu verziju
  starije glavne verzije od `channels.latest`, a u suprotnom `latest`. Ista pravila kao u
  `scripts/release/dist-tag.mjs`, koji bira npm dist-tag prilikom objavljivanja.
- `channels` — najnovija objavljena verzija svake dist-tag oznake, iz `npm view omniroute dist-tags` (rezervni pristup
  putem HTTP-a registru), keširana s istim TTL-om od 10 minuta kao `latest`. `latest` je uvijek prisutan
  (rezervno koristi polje `latest`, a zatim `"unavailable"`); `next`, `nightly` i `lts` pojavljuju se
  samo kada ta dist-tag oznaka postoji. Zahtjev `Cache-Control: no-cache` osvježava oba pretraživanja.

Model kanala (`latest` = v3 do opće dostupnosti verzije 4.0, `next` = rc, `nightly` = verzije iz grane `develop`,
`lts` = zakrpe za v3 nakon opće dostupnosti verzije 4.0) opisan je u `docs/ops/RELEASE_STRATEGY.md`.

## Ograničenja tokena

Budžeti **tokena** po API ključu (razlikuju se od prethodno navedenog budžeta zasnovanog na USD-u). Primjenjuju se direktno tokom obrade zahtjeva: kada korištenje ključa u trenutnom periodu dostigne svoje ograničenje, zahtjevi se odbijaju uz `429 Too Many Requests`. Ograničenja se mogu odnositi na određeni `model`, `provider` ili se primijeniti `global`no na cijeli ključ; kada zahtjevu odgovara više ograničenja, primjenjuje se najrestriktivnije.

```bash
# Prikaz ograničenja tokena za ključ (uključuje trenutno korištenje u aktivnom periodu)
GET /api/usage/token-limits?apiKeyId=key-123

# Kreiranje ili ažuriranje ograničenja tokena
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Brisanje ograničenja tokena prema ID-u
DELETE /api/usage/token-limits?id=tl-abc
```

> **Napomene o šemi** (`setTokenLimitSchema`): `apiKeyId` i `scopeType` (`model` | `provider` | `global`) su obavezni. `scopeValue` je obavezan osim ako je `scopeType` postavljen na `global` (npr. ID modela za opseg `model`, ID pružaoca usluge za opseg `provider`). `tokenLimit` mora biti pozitivan cijeli broj (konvertuje se iz stringa). Opcionalno: `id` (izostavite za kreiranje, navedite za ažuriranje), `resetInterval` (`daily` | `weekly` | `monthly`, zadano `monthly`), `resetTime` (`HH:MM`), `enabled` (zadano `true`). `GET` odgovori dopunjuju svako ograničenje poljima `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` i `nextResetAt`. Ovo je krajnja tačka upravljačke klase (autentifikacija se centralno provodi putem authz cjevovoda).

## Obrada zahtjeva

1. Klijent šalje zahtjev na `/v1/*`
2. Rukovalac rutom poziva `handleChat`, `handleEmbedding`, `handleAudioTranscription` ili `handleImageGeneration`
3. Model se razrješava (direktni pružalac usluge/model ili alias/kombinacija)
4. Akreditivi se biraju iz lokalne baze podataka uz filtriranje prema dostupnosti računa
5. Za chat: `handleChatCore` provjerava semantički/potpisni keš i razrješava postavke kompresije kombinacije
6. Proaktivna kompresija izvršava se prije prevođenja za pružaoca usluge kada je omogućena (`lite`, Caveman, RTK ili složena)
7. Izvršilac pružaoca usluge šalje zahtjev uzvodnom servisu
8. Odgovor se prevodi nazad u format klijenta (chat) ili se vraća bez izmjena (ugrađivanja/slike/zvuk)
9. Bilježe se korištenje, analitika kompresije i zapisnici zahtjeva
10. Rezervna opcija primjenjuje se pri greškama u skladu s pravilima kombinacije

Potpuna referenca arhitekture: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Otpornost (prošireno)

OmniRoute pruža tri nezavisna mehanizma za privremene kvarove; upravljačke krajnje tačke u nastavku omogućavaju operaterima da ih očitaju i nadjačaju:

| Opseg                      | Pohrana stanja                               | Očitavanje                                | Resetovanje / brisanje                                                  |
| -------------------------- | -------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------- |
| Prekidač pružatelja        | `domain_circuit_breakers` + u memoriji       | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                            |
| Period mirovanja konekcije | `rateLimitedUntil` na konekcijama pružatelja | `/api/rate-limits`, `/api/providers/[id]` | (ponovo se omogućava lijeno; obrišite putem PUT zahtjeva za pružatelja) |
| Zaključavanje modela       | Registar dostupnosti modela u memoriji       | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                                |

`PATCH /api/resilience` prihvata nadjačavanja prekidača pružatelja pod `providerBreaker.oauth` i `providerBreaker.apikey`. Svaki profil podržava `degradationThreshold`, `failureThreshold` i `resetTimeoutMs`; ista polja dostupna su u Nadzorna ploča → Postavke → Otpornost.

```bash
# Obrišite zaključavanje jednog modela
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Obrišite sva zaključavanja
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Za potpunu konceptualnu referencu i zadane postavke prekidača pogledajte [`CLAUDE.md`](../../CLAUDE.md) → „Stanje otpornosti tokom izvršavanja“ i [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Red za ograničenje brzine i zaštitni mehanizam automatskog omogućavanja

- **Podržani put za upisivanje**: `POST /api/rate-limits` s tijelom `{"connectionId": "<id>", "enabled": true|false}` predstavlja podržanu upravljačku krajnju tačku za uključivanje ili isključivanje zaštite od ograničenja brzine za konekciju. `PUT /api/providers/[id]` namjerno ne mijenja niti prebacuje `rateLimitProtection` (#11278).
- **Semantika opcije `enabled: false`**: Postavljanje opcije `enabled: false` uklanja eksplicitnu zaštitu za konekciju, ali **ne** izuzima aktivnu konekciju s API ključem iz globalnog zaštitnog mehanizma automatskog omogućavanja (`autoEnableApiKeyProviders = true`). U `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), `false` i `undefined` su ekvivalentni; aktivne konekcije s API ključem bez eksplicitne zaštite ostaju zaštićene globalnim zaštitnim mehanizmom automatskog omogućavanja.
- **Globalno onemogućavanje**: Za pokretanje konekcija s API ključem bez redova za ograničenje brzine, globalno onemogućite zaštitni mehanizam putem `RATE_LIMIT_AUTO_ENABLE=false` (varijabla okruženja) ili `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Postavke → Otpornost / `PATCH /api/resilience`).

## MCP server

OmniRoute uključuje ugrađeni server protokola Model Context Protocol s 3 transporta (stdio, SSE, streamable-http) i alatima ograničenim opsezima. Krajnje tačke kontrolne ploče u nastavku čitaju podatke o statusu/reviziji i prosljeđuju HTTP transporte.

| Metoda | Putanja | Opis |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | Signal aktivnosti, transport, stanje dostupnosti, posljednji poziv, najčešći alati, stopa uspjeha u posljednja 24 h |
| GET | `/api/mcp/tools` | Spisak MCP alata s poljima `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints` |
| GET | `/api/mcp/sse` | Otvaranje SSE toka za SSE transport (vraća `503` ako je MCP onemogućen ili se transporti ne podudaraju) |
| POST | `/api/mcp/sse` | Slanje JSON-RPC okvira putem SSE transporta |
| GET | `/api/mcp/stream` | Otvaranje SSE strane Streamable HTTP transporta (poruke koje inicira server) |
| POST | `/api/mcp/stream` | Slanje JSON-RPC okvira putem Streamable HTTP transporta |
| DELETE | `/api/mcp/stream` | Završavanje Streamable HTTP sesije |
| GET | `/api/mcp/audit` | Pretraživanje revizijskog dnevnika — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | Zbirna statistika revizije (ukupni brojevi, stopa uspjeha, prosječno trajanje, najčešći alati) |

**Autentikacija:** transporti `sse`/`stream` koriste autentikaciju specifičnu za MCP (Bearer API ključ s opsegom `mcp`); rute `status`/`tools`/`audit*` dostupne su za čitanje s kontrolne ploče (nije potrebna dodatna autentikacija osim pristupa hostu kontrolne ploče).

> Oba HTTP transporta kontroliraju `settings.mcpEnabled` i `settings.mcpTransport` — nepodudaranje transporta vraća `400`, a onemogućeno MCP stanje vraća `503`.

## A2A server

OmniRoute izlaže A2A (agent-agent) JSON-RPC 2.0 krajnju tačku i REST omotač za potrebe pregleda i kontrolne ploče.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # opcionalno, osim ako je OMNIROUTE_API_KEY postavljen
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Podržane metode (sve zavise od `settings.a2aEnabled`):

| Metoda           | Opis                                                               |
| ---------------- | ------------------------------------------------------------------ |
| `message/send`   | Sinhrono izvršavanje vještine; vraća `{task, artifacts, metadata}` |
| `message/stream` | Streaming SSE izvršavanje istog skupa vještina                     |
| `tasks/get`      | Dohvata zadatak prema `taskId`                                     |
| `tasks/cancel`   | Otkazuje zadatak prema `taskId`                                    |

Ugrađene vještine: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Kartica agenta

```bash
GET /.well-known/agent.json
```

Vraća javnu A2A karticu agenta (naziv, opis, mogućnosti, katalog vještina, shemu autentifikacije) — javno keširanu 1 sat. Autentifikacija nije potrebna.

### REST pomoćne krajnje tačke

| Metoda | Putanja                      | Opis                                                                                                                |
| ------ | ---------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | Status omogućenosti A2A + statistika zadataka + sažetak keširane kartice agenta                                     |
| GET    | `/api/a2a/tasks`             | Navodi zadatke — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Nije implementirano kao REST pomoćna krajnja tačka — kreirajte putem JSON-RPC metode `message/send`)               |
| GET    | `/api/a2a/tasks/[id]`        | Dohvata jedan zadatak                                                                                               |
| POST   | `/api/a2a/tasks/[id]/cancel` | Otkazuje zadatak                                                                                                    |

**Autentifikacija:** REST pomoćne krajnje tačke rade bez upravljačke autentifikacije (moguće ih je čitati putem kontrolne ploče); JSON-RPC ruta `/a2a` koristi Bearer `OMNIROUTE_API_KEY` ako je konfigurisan.

## Zaštitne mjere

Pregledajte zaštitne mjere u vrijeme izvršavanja (otkrivanje ličnih identifikacijskih podataka, otkrivanje ubacivanja u prompt, premošćivanje vizuelnog sadržaja). Zaštitne mjere izvršavaju se pri svakom zahtjevu; izuzimanje za pojedinačni poziv vrši se putem zaglavlja zahtjeva `x-omniroute-disabled-guardrails` — ne postoji trajno sučelje za omogućavanje/onemogućavanje.

| Metoda | Putanja                | Opis                                                                                               |
| ------ | ---------------------- | -------------------------------------------------------------------------------------------------- |
| GET    | `/api/guardrails`      | Prikazuje registrovane zaštitne mjere i njihov status (naziv / omogućeno / prioritet)              |
| POST   | `/api/guardrails/test` | Probno izvršava cjevovod prije poziva nad primjerom ulaza — tijelo: `{input, disabledGuardrails?}` |

**Autentifikacija:** Zahtijeva sesiju za upravljanje.

Za sve detalje pogledajte [Sigurnost > Zaštitne mjere](../security/GUARDRAILS.md).

## Autentifikacija

Pogledajte [Autentifikacija za upravljanje](../guides/MANAGEMENT-AUTH.md) za četiri
grupe vjerodajnica (sesija kontrolne ploče, lokalni CLI token, `oma_live_…` pristupni
token, API ključ s opsegom za upravljanje) i objašnjenje kako se razlikuju od ključeva za zaključivanje.

- Rute kontrolne ploče (`/dashboard/*`) koriste kolačić `auth_token`
- Za prijavu se koristi sačuvani hash lozinke; rezervna opcija je `INITIAL_PASSWORD`
- `requireLogin` se može uključiti ili isključiti putem `/api/settings/require-login`
- Rute `/v1/*` opcionalno zahtijevaju Bearer API ključ kada je `REQUIRE_API_KEY=true`
- „token za upravljanje“ / „API ključ s opsegom za upravljanje“ u ovoj referenci označava jednu od grupa iz tog vodiča — a ne nedefiniranu dodatnu vrstu tajne

> **Promjena koja narušava kompatibilnost (v3.8.0)** — `/api/v1/agents/tasks/*` i krajnje tačke za upravljanje periodom čekanja sada zahtijevaju **autentifikaciju za upravljanje** (kolačić `auth_token` kontrolne ploče ili API ključ s opsegom za upravljanje). Klijenti koji su prethodno pozivali ove rute bez autentifikacije primit će `401 Unauthorized`. Pogledajte commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
