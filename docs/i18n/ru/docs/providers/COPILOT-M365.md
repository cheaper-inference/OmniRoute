`copilot-m365-web` (псевдоним `m365copilot`) отправляет запросы чата в формате OpenAI через аутентифицированный сеанс Microsoft 365 Copilot на `m365.cloud.microsoft/chat`. Это неофициальная встроенная интеграция: не требуется отдельный прокси-процесс или исходящий локальный хост. Поставщик ID, псевдоним и существующие импортированные соединения не изменяются. `copilot-web` — это другой поставщик потребительских услуг в `copilot.microsoft.com`.

> **Вы впервые знакомы с поставщиками веб-куки?**
>
> Читать**`docs/getting-started/WEB-COOKIE-GUIDE.md`** для общего процесса настройки, рекомендаций по аутентификации, ограничений и устранения неполадок, прежде чем следовать этому руководству для конкретного поставщика.
>
> **Для устаревшего импорта:** Учетные данные для этого поставщика:** не печенье** . Не копируйте файлы cookie с `m365.cloud.microsoft`. Учетные данные представляют собой параметр запроса WebSocket URL и сегмент пути, которые считываются на вкладке Сеть DevTools.

## Предварительные условия

- Учетная запись Microsoft 365 с доступом к Copilot на `m365.cloud.microsoft/chat`
- Браузер на базе Chromium (Chrome, Edge) для проверки DevTools WebSocket
- Доступ к запрошенной модели в этом аккаунте; доступность зависит от арендатора и лицензии

## Встроенный вход (рабочие или учебные учетные записи)

Выбирать**Microsoft 365 Copilot → Connect** и подготовьте попытку входа. Панель мониторинга использует поток кода авторизации с PKCE; он не запрашивает ваш пароль Microsoft или код MFA.

1. Откройте** пустая вкладка браузера** , затем откройте**DevTools →** и включить** Сохранить журнал** . Сделайте это перед переходом к Microsoft: Windows SSO может завершиться немедленно.
2. Скопируйте URL авторизации, показанный в диалоговом окне подключения, и перейдите к нему на подготовленной вкладке. Завершите выбор учетной записи Microsoft или MFA если потребуется.
3. В сохранившемся журнале сети найдите запрос к `https://login.microsoftonline.com/common/oauth2/nativeclient` и скопируйте его полностью.** Запросить URL** .
4. Вставьте этот URL в диалоговое окно подключения и подключитесь. Не вставляйте необработанный код или окончательную адресную строку `wrongplace` URL: требуемый обратный вызов является временной навигацией.

Каждая попытка истекает через десять минут и может быть использована только один раз. Перед обменом кода сервер проверяет свое состояние, верификатор PKCE и цель повторной аутентификации. После истечения срока действия или неудачного обмена начните новую попытку. Попытка не может пережить перезагрузку сервера.

Токены используют существующее хранилище учетных данных подключения и путь обновления. Для повторной аутентификации соединения требуется тот же идентификатор Microsoft tenant/object, а не просто тот же адрес электронной почты. Он сохраняет оператор naming/settings и заменяет устаревшие импортированные учетные данные. Собственный вход предназначен для учетных записей work/school ; устаревший путь импорта остается доступным для существующих подключений и поддерживаемых конфигураций уровня.

Полный обратный вызов URL — это одноразовые учетные данные. Никогда не включайте его в скриншоты, журналы, сообщения поддержки или коммиты. Этот поток не открывает браузер на сервере, не проверяет историю вашего браузера и не запускает локальный сервер обратного вызова.

## Захват учетных данных (метод WebSocket )

1. Войдите в `https://m365.cloud.microsoft/chat` и начните разговор.
2. Открыть**DevTools →** .
3. Фильтровать по**WS** (WebSocket).
4. Щелкните соединение Chathub WebSocket. Найдите URL начинающийся с `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Из его** Запросить URL** , скопируйте:
   - Значение параметра запроса `access_token` (недолговечный JWT).
   - Сегмент пути Chathub после `/Chathub/` (например, `<oid>@<tenant>`).

Полная URL имеет вид:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. В OmniRoute выберите**Microsoft 365 Copilot** , выберите устаревший вариант API-key/import и вставьте учетные данные в следующем формате:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Нажмите** Тестовое соединение** и** Сохранять** .

## Захват учетных данных (импорт HAR )

Вместо копирования значений вручную из WebSocket URL вы можете экспортировать файл DevTools HAR :

1. Открыть**DevTools →** .
2. Начните или продолжите разговор Microsoft 365 Copilot (это активирует соединение WebSocket ).
3. Щелкните правой кнопкой мыши на панели «Сеть» и выберите** Сохранить все как HAR с содержимым** .
4. В OmniRoute используйте** Импортировать файл .har** кнопку в диалоге подключения провайдера.

OmniRoute сканирует HAR на предмет Chathub WebSocket URL, извлекает `access_token` и `chathubPath` и автоматически заполняет поля учетных данных. Импорт HAR декодирует срок действия JWT и показывает оставшееся время жизни токена.

> **Никогда не выполняйте настоящий экспорт HAR, токен доступа или токен обновления.** Значения теста и документации всегда должны быть заполнителями.

## Срок действия токена и обновление

`access_token` недолговечен (обычно**~ 75 минут** ). Без пригодного для использования токена обновления вам придется повторно захватить учетные данные после истечения срока их действия.

### Автоматическое обновление с помощью `refreshToken`

У провайдера Microsoft 365** Добавить соединение** или** Изменить соединение** диалог, открыть** Расширенные настройки → Обновить токен (необязательно)** . Вставьте токен обновления Microsoft OAuth для области `substrate.office.com/sydney` и сохраните. Ввод маскируется и никогда не заполняется сохраненным токеном. При редактировании оставьте это поле пустым, чтобы сохранить существующий токен; вставьте новый токен, чтобы заменить его.

Собственный вход получает токен обновления, когда Microsoft возвращает его. Для устаревшего импорта используйте существующий совместимый грант кода авторизации Microsoft ; этот поставщик не реализует и не обещает поток кода устройства. Если настроен токен обновления, OmniRoute проверяет `access_token` перед запросом и обновляет его только тогда, когда он нуждается в обновлении. При успешном обновлении также сохраняется повернутый токен обновления, что позволяет избежать повторного захвата вручную, пока токен обновления остается действительным.

Если `refreshToken` не установлен, вам необходимо повторно захватить учетные данные WebSocket вручную после каждого истечения срока действия.

### Выбор уровня

| Уровень      | Псевдоним        | Поверхность                  |
| ------------ | ---------------- | ---------------------------- |
| `individual` | _(по умолчанию)_ | Потребительский M365 Copilot |
| `edu`        | `included`       | Образование M365 Copilot     |
| `enterprise` | `work`           | Copilot M365 для работы      |

Установите уровень в** Расширенные настройки уровня → Copilot** . Собственный вход в систему не устанавливает его, поэтому рабочая учетная запись должна выбрать `enterprise` (псевдоним `work`) и учебную учетную запись `edu`, также при использовании документированной модели IDs: они выбирают свой собственный тон, сценарий и тип лицензии, но параметры агента и вызова по-прежнему поступают с уровня, и отдельные значения по умолчанию могут не работать в рабочем клиенте. Изменение уровня не дает лицензию на модель. Явные переопределения расширенного протокола имеют приоритет, и их следует использовать только в том случае, если известны необходимые значения проводов.

## Модели и маршрутизация

Собственный каталог включает все документированные автономные IDs, а также четыре исходных собственных IDs. Каталог статический и не зависит от учетной записи, а не проверка прав учетной записи: платные маршруты и псевдонимы совместимости остаются в списке, даже если подключенная учетная запись не может их использовать. В метках отображения модели не указаны имя поставщика и шаблон доступности для каждой модели; провайдер остается**Microsoft 365 Copilot** . Этикетки отмечены** Псевдоним** или** Наследие** сохраняют существующие идентификаторы и сопоставления протоколов, а не гарантию исторической версии модели. Автономные прокси** Импорт из /модели** инструкции не применимы к этому родному провайдеру WebSocket.

| Модельная семья   | Канонический IDs                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| Автоматический    | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| Ранее GPT         | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude Сонет      | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude Опус       | `claude-opus`, `claude-opus-4.8`                                                                 |

Также регистрируются псевдонимы, такие как `auto`, `quick`, `think-deeper` и псевдонимы версий. Существующие `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` и `copilot-m365-gpt-5-5-chat` остаются в силе. Документированному IDs нужен префикс провайдера (`copilot-m365-web/claude-opus` или `m365copilot/claude-opus`): многие из них являются общими словами или названиями моделей других поставщиков, поэтому голый `claude-opus` сохраняет маршрутизацию так же, как и без этого провайдера. Регистрация не является гарантией того, что Microsoft будет использовать эту модель для каждой учетной записи. Автономный IDs соответствует [каталогу общедоступных протоколов](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) (экспортированная карта тональности модели и ее метаданные сценария с учетом модели). Все собственные профили сохраняют `availability: "unverified"`; включение в каталог не является успешной проверкой аккаунта.

- Явный отказ в лицензии модели возвращается** 403** `m365_model_not_licensed`, а не 502. Маршрутизация блокирует эту пару connection/model, оставляя лицензионные модели в соединении пригодными для использования.
- `InvalidCopilotLicense` — это отказ от лицензии на уровне учетной записи, о котором сообщается отдельно как `m365_account_not_licensed`.
- Возвращение регулирования для каждого пользователя** 429** `m365_throttled` и охлаждает соединение. Возврат исчерпания приоритетного доступа** 429** `priority_access_exhausted` и распространяется на модель. Результат `OutOfCredits` с возвратом `errorCode: "ReasoningTurnExhausted"`** 429** вместо этого `reasoning_turns_exhausted`, также в рамках модели, без заявленного времени сброса. Сообщалось, что один арендатор работы ограничил звуковые сигналы «Думай глубже», в то время как быстрые звуковые сигналы продолжали работать; эта область действия — это наблюдение потребителя, а не то, что воспроизведено в этом репозитории. Таким образом, маршрутизация также выводит из ротации другие задокументированные модели Think более глубокие модели `gpt-5.5` и `gpt-5.6` в этом соединении на то же время восстановления и оставляет быстрые сигналы и все остальные сбои в отдельной модели. Предоставленные подсказки о повторных попытках сохраняются; отсутствие сброса не объявляется как известное время сброса.
- Отказ безопасности Copilot (`Disengaged`) возвращается** 400** `provider_safety_rejection`— метка остановки безопасности общего поставщика. Это никогда не влияет на работоспособность соединения, клиент SDKs не повторяет 400, а при включенном `PROVIDER_SAFETY_STOPS_TERMINAL` комбинированная маршрутизация останавливается на этом месте вместо повторного воспроизведения запроса к другой цели.
- Запросы по одному соединению сериализуются через существующий семафор учетной записи. Предпочитайте приоритетный резервный вариант, а не параллельные панели; Сама по себе сериализация не устраняет ограничения скорости обмена данными Microsoft.

## Поведение запроса и ограничения

- Инструменты** с быстрой эмуляцией** , а не вызовы собственных функций Microsoft. Запрос с поддержкой инструмента использует одну буферизованную генерацию; он не тратит еще одно поколение на выбор инструментов. В качестве вызовов возвращаются только объявленные инструменты с допустимыми поддерживаемыми формами аргументов.
- Длинный структурированный ответ с одним конечным примером сохраняется в виде прозы. Это эвристика, а не доказательство намерения; приложения по-прежнему должны применять свои собственные разрешения для инструментов.
- Ввод изображения работает так, как его отправляет веб-клиент. Каждая часть изображения (`image_url` в виде данных URL или общедоступного HTTPS URL или ответов `input_image`) загружается в `/m365Copilot/UploadFile` в диалог хода с токеном чата, и сообщение указывает на нее с аннотацией `ImageFile` ; текст отмечает, где он находился (`[image 1]`, …). При свежем разговоре загружаются все изображения в истории, при продолжении — только изображения новых сообщений. До 10 изображений PNG, JPEG, GIF или WebP размером не более 10 MiB каждое (40 MiB за запрос); формат читается из байтов. HTTPS URLs извлекаются через общедоступную удаленную защиту изображений, прикрепленную к DNS. Неудачная загрузка приводит к сбою запроса (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` или `m365_image_invalid`); поворот никогда не происходит без того образа, который ему был дан. Другие нетекстовые части (аудио, файлы) отклоняются явно, а не автоматически.
- Последующий запрос продолжает тот же восходящий диалог и отправляет только сообщения после предыдущего ответа. Он должен точно расширить этот ответ: то же соединение, профиль модели и набор инструментов; неизмененная история (цепочка sha256 над каждым сообщением); и идентификаторы вызовов инструментов ответа или его текст до пробелов. Все остальное (отредактированная история, другой сеанс с тем же первым сообщением, другой ответ, разговор бездействующий в течение 30 минут или близко к лимиту Copilot в 600 сообщений, соединение без идентификатора) запускает новый разговор со всей историей. Неудачный ход никогда не возобновляется, а `InternalError` без содержания отправляется повторно один раз в новом разговоре (** 502** `m365_internal_error` если снова произойдет сбой). Продолжения сохраняются в памяти процесса: перезапуск запускает новые диалоги.
- Каждый ход выполняется во временном чате Copilot(`disableMemory=1`): контекст разговора сохраняется во время его выполнения и никогда не отображается в истории чата учетной записи. Таким образом, модельные тесты, тесты всех и комбинированные тесты могут проверить этого поставщика, не оставляя разговоров позади.
- Ход имеет 120-секундный срок простоя и ограниченный общий срок. Только окончательные ответы, фильтрация прогресса и отмена обрабатываются встроенным transport/composer.
- Ответы, размещенные в Интернете, сохраняют свои источники. Copilot помечает цитату в строке управляющими символами для частного использования и отправляет источники как `references`; каждый маркер становится пронумерованной ссылкой Markdown (`[1](https://…)` или голым URL если Copilot использовал маркер в качестве цели ссылки) с соответствующей аннотацией `url_citation` (`message.annotations` или `delta.annotations` на фрагменте, который содержит ссылку). Источник, который никогда не поступает, удаляется, поэтому маркеры никогда не доходят до клиента. При потоковой передаче текст после цитаты ожидает прибытия источника.
- Краткое изложение рассуждений Copilot(`ChainOfThoughtSummary`), когда модель отправляет его, возвращается как `reasoning_content`, а не как часть ответа. Сводка, которая перезаписывает сама себя, останавливает потоковую передачу, не сбоев при повороте.
- Перед любым контентом при сбоях licence/throttle сохраняется HTTP 403/429 даже если была запрошена потоковая передача. После запуска контента сбои — это события ошибки SSE, а не успешное завершение. Перезапись восходящего потока, которая не может быть представлена потоковой передачей только с добавлением, является явной ошибкой потока; Непотоковые и буферизованные ответы инструмента сохраняют окончательный текст.
- Когда Copilot отказывает в соединении, ее ответ сообщается в следующем виде:** 401** `m365_unauthorized` для отклоненного или просроченного входа в систему (войдите еще раз),** 429** с его `Retry-After` для регулирования и сбоем установления связи в противном случае, а не с общим сбоем соединения.

## Генерация изображений

`POST /v1/images/generations` с `model: "copilot-m365-web/m365-copilot-image"` (псевдоним `m365copilot/m365-copilot-image`) рисует с помощью встроенного в Copilot инструмента обработки изображений, как это делает веб-клиент. Каждое изображение представляет собой один ход Copilot : оно соглашается с наборами параметров изображения веб-клиента и объявляет `GenerateGraphicArt`, а изображение поступает в запись о ходе выполнения, указывающую на артефакт в службе Designer Microsoft. Этот артефакт отказывается от токена чата, поэтому OmniRoute создает токен Designer из токена обновления соединения и загружает байты; токен отправляется только в `designerapp.officeapps.live.com`.

- Требуется собственное соединение для входа (токен обновления); вставленный токен терпит неудачу с** 400** прежде чем будет потрачен любой ход.
- `n` — 1–4, по одному ходу каждый. `size` управляет только ориентацией (шире, выше или квадратной), которую Copilot считывает из подсказки; Copilot выбирает размер рендеринга.
- Изображения возвращаются встроенными: по умолчанию `b64_json`, данные URL для `response_format: "url"`.
- Создаваемые изображения расходуют небольшой ежедневный бюджет отдельно от чата. Когда он израсходован, запрос завершается с ошибкой** 429** . Ход, который отвечает без изображения, проваливается с** 502** (или** 400** /** 503** когда текст Copilot читается как отказ или проблема с емкостью); в сообщении написано какой.

## Модель безопасности

- **Неофициальная интеграция.** Этот провайдер занимается реверс-инжинирингом протокола BizChat WebSocket. Он может выйти из строя без предварительного уведомления, когда Microsoft изменит конечную точку.
- Флаг `subscriptionRisk: true` указывает на то, что интеграция основана на недокументированной конечной точке. Ограничения аккаунта возможны, но не подтверждены.
- Токен доступа — это недолговечный JWT. Относитесь к нему как к паролю: не фиксируйте, не регистрируйте и не делитесь им.
- Токен обновления предоставляет постоянный доступ к поверхности Microsoft 365. Храните его с той же осторожностью, что и ключ API.

## Поиск неисправностей

### Аутентификация не удалась сразу

- Убедитесь, что вы скопировали из**WebSocket URL** , а не из запроса XHR/Fetch. Учетные данные находятся в параметре запроса `access_token` соединения WebSocket Chathub — а не в заголовке `Authorization: Bearer`.
- Убедитесь, что `chathubPath` включает полный сегмент `<oid>@<tenant>` из пути URL.

### Срок ~ токена истекает через 75 минут.

Это ожидаемо. Без `refreshToken` токен доступа недолговечен. Или:

- Повторно получите учетные данные из DevTools или
- Настроить** Расширенные настройки → Обновить токен (необязательно)** в диалоговом окне «Добавить или изменить соединение» для автоматического обновления.

### Тестовое соединение проходит, но чат возвращает 401

Для соединения, созданного с помощью** Войдите с помощью Microsoft** Тестовое соединение проверяет срок действия токена доступа и обновляет токен с истекшим сроком действия с помощью сохраненного токена обновления, поэтому прохождение теста также доказывает, что токен обновления все еще работает.

Для вставленных учетных данных Test Connection проверяет форму учетных данных и, когда срок действия токена истекает, не истек ли срок действия токена, который будет использовать поставщик (сохраненный токен соединения выигрывает от устаревшей вставки; токен обновления считается возобновляемым). Токен, который отозван до истечения срока его действия, все равно проходит проверку; чат затем возвращается** 401** `m365_unauthorized`. Использовать** Войдите с помощью Microsoft** снова или повторно получите новые учетные данные.

### Copilot не отображается в списке провайдеров

Убедитесь, что `copilot-m365-web` включен в** Поставщики информационных панелей →** . На некоторых уровнях поставщик может быть скрыт по умолчанию.
