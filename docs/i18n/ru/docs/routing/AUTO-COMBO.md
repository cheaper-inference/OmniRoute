## Автоматическая маршрутизация с нулевой конфигурацией (префикс `auto/` )

Создание комбо не требуется. Используйте `auto` или вариант `auto/` непосредственно в своем клиенте.

### Быстрые примеры

| Модель ID           | Поведение                                                                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`              | Подходящие модели поставщиков, стратегия LKGP и сбалансированные веса                                                                                                    |
| `auto/coding`       | Весовые коэффициенты качества для задач кодирования                                                                                                                      |
| `auto/fast`         | Предпочитает меньшую задержку и здоровых поставщиков                                                                                                                     |
| `auto/cheap`        | Экономичные гири: способствуют более низким каталожным ценам; сохраняет липкость LKGP, а не строгую сортировку по принципу «сначала дешевле»                             |
| `auto/subscription` | Только квота, включенная в план, проверенная в реальном времени; пустой пул возвращает HTTP 503, а не резервный вариант с выставлением счета                             |
| `auto/thrifty`      | подписка → без ключа → бесплатно → дешево → премиум, по одной ступени; может выставить счет                                                                              |
| `auto/offline`      | Обеспечивает доступность квот и работоспособность провайдера (`offline-friendly` package); не автономный вывод, запросы — по-прежнему отправляются удаленным поставщикам |
| `auto/smart`        | Качественные веса с коэффициентом разведки 10%.                                                                                                                          |
| `auto/lkgp`         | Явный LKGP с теми же весами, что и `auto` по умолчанию.                                                                                                                  |
| `auto/chaos`        | Параллельная панель с одной моделью для каждого поставщика, по умолчанию до пяти, возвращающая один ответ.                                                               |

Варианты веса сохраняют липкость LKGP, поэтому `fast` и `cheap` выражают предпочтения, а не гарантируют минимальную задержку или цену для каждого запроса. `auto/chaos` выполняет несколько восходящих вызовов. `auto/thrifty` может использовать платную мощность; Возврат к плановой квоте зависит от возобновления права на участие и времени восстановления соединения, а не только от времени сброса. См. [Маршрутизация по подписке](./SUBSCRIPTION_LADDER.md).

### Категория × Состав уровня (`auto/<category>:<tier>`)

Суффиксы в стиле OpenRouter разделены.** какой маршрут** (категория) из** как это оптимизировать** (уровень), поэтому вы можете свободно их составлять (#4235 Phase B, `open-sse/services/autoCombo/suffixComposition.ts`):

- **Категории** : `coding` · `reasoning` · `vision` · `chat` · `multimodal`. `vision`/`multimodal` сохраняют модели с возможностью машинного зрения; `reasoning` хранит модели reasoning/thinking. `coding` и `chat` не добавляют фильтр возможностей. Категории, не относящиеся к чату, выбирают вес в первую очередь по качеству перед переопределением уровня.
- **Уровни** (выберите веса оценки / фильтр пула): `fast` (быстрая поставка) · `cheap` (псевдоним `floor`, экономия затрат) · `reliable` (состояние выключателя, стабильность задержки + ) · `free` / `pro` (фильтрация пула по уровню модели через `classifyTier` — бесплатного уровня или премиум-класса). `subscription` и `thrifty` применяют [лестницу подписки](./SUBSCRIPTION_LADDER.md) на основе соединений.

| Пример                 | решает                                                                                |
| ---------------------- | ------------------------------------------------------------------------------------- |
| `auto/coding:fast`     | подходящий пул, веса с малой задержкой                                                |
| `auto/coding:cheap`    | соответствующий пул, веса экономии затрат (псевдоним `auto/coding:floor`)             |
| `auto/reasoning:pro`   | Только модели reasoning/thinking, премиум-уровень                                     |
| `auto/vision`          | модели с возможностью машинного зрения и качественными весами                         |
| `auto/multimodal:free` | модели с поддержкой мультимодальных перевозок, только уровень бесплатного пользования |

Любой действительный `auto/<category>[:<tier>]` разрешается по требованию; тщательно подобранное подмножество рекламируется в `/v1/models` и на информационной панели (`AUTO_SUFFIX_VARIANTS` в `open-sse/services/autoCombo/builtinCatalog.ts`). фильтрация Category/tier** по умолчанию закрыто при отказе** : если ни одна из подходящих моделей не соответствует, виртуальная комбинация имеет пустой пул, и преобразователь чата возвращает HTTP 503 (`src/sse/handlers/chatHelpers.ts`). Фильтр `narrowPoolByCategoryTier` в `open-sse/services/autoCombo/virtualFactory.ts`.

`OMNIROUTE_AUTO_FREE_FALLBACK_TO_FULL_POOL=true` восстанавливает устаревший резервный вариант category/tier в полном пуле, когда фильтр ничего не соответствует; это может привести к отмене запрошенного уровня или ограничения возможностей. Фильтры семейства моделей никогда не используют этот резервный вариант, а маршрутизация только по подписке по-прежнему требует проверенной мощности, включенной в план.

> **Живой интеллект модели:** автомаршрутизация фитнеса информируется в реальном времени** Арена ELO** рейтинги +** models.dev** данные уровня, когда флаг `ARENA_ELO_SYNC_ENABLED` включен (в противном случае происходит возврат к статической фитнес-карте).

**Как использовать:**

```bash
# Any IDE or CLI tool that supports OpenAI format
Base URL: http://localhost:20128/v1
API Key:  <your-endpoint-key>

# In your code/config, set model to:
model: "auto"                 # balanced default
model: "auto/coding"          # favor coding task fit
model: "auto/fast"            # favor lower latency
model: "auto/cheap"           # favor lower catalog cost
```

**Что происходит:**

1. OmniRoute обнаруживает префикс `auto/` в `src/sse/handlers/chat.ts`
2. Запрашивает все** активные подключения к провайдеру** из базы данных
3. Применяет фильтры учетных данных, видимости модели и приемлемости.
4. Создает логических кандидатов provider/model на основе доступных моделей, сохраняя подходящие списки учетных записей для отправки.
5. Строит** виртуальное комбо** в памяти (не хранится в DB)
6. Маршруты с использованием профиля веса выбранного варианта стратегии + LKGP

**Ключевые свойства:**

- ✅** Всегда включен:** Никакого переключения, никакого создания комбо, никакой настройки не требуется.
- ✅** Динамический:** Автоматически отражает текущих подключенных провайдеров
- ✅** Прилипчивость сеанса:** LKGP гарантирует, что приоритет будет отдан последнему успешному провайдеру
- ✅** Поддержка нескольких учетных записей:** Логические кандидаты provider/model сохраняют подходящие белые списки аккаунтов.
- ✅** Сохраненная комбинация не требуется:** Виртуальная конфигурация остается в памяти; нормальные метрики маршрутизации и состояние времени выполнения все еще могут сохраняться

### Управление кандидатами по ключу (#7819, уровень 1 + 2)

`GET /v1/auto-combo/{channel}/candidates` (`{channel}` = суффикс после `auto/` или буквальный `auto` для базового канала) — это** только для чтения** конечная точка, которая перечисляет текущий пул кандидатов канала `auto/*`, украшенный возможностью прямой достижимости, повторно используя существующие чтения устойчивости (никогда необработанный прерыватель `state`):

- автоматический выключатель поставщика — `getCircuitBreaker(provider).getStatus()` / `.canExecute()`
- Время восстановления соединения — `rateLimitedUntil` / `testStatus` в разрешенной строке `provider_connections`
- блокировка модели — `isModelLocked(provider, connectionId, model)`

Каждый кандидат также несет флаг `excluded` этого ключа API. Исключения сохраняются для каждого ключа API (таблица `auto_candidate_overrides`, миграция `128`). — OmniRoute является однотенантным, без таблицы `users`, поэтому `apiKeyId` — это ближайший реальный идентификатор каждого вызывающего абонента —, который применяется в узкой точке пула кандидатов в `open-sse/services/autoCombo/virtualFactory.ts` с помощью чистого, проверенного на модуль `filterExcludedCandidates()` (`open-sse/services/autoCombo/candidateOverrides.ts`). Фильтр** отказоустойчивый** : как неустановленный apiKeyId/channel, так и сбой поиска DB оставляют пул нефильтрованным, поэтому оператор, у которого не настроены переопределения, видит маршрутизацию, идентичную той, что была до этой функции.

**Отложено до следующего вопроса:** веса каждого кандидата + в явном порядке (уровень 3 — используется в существующих путях стратегии weighted/priority ) и закреплении конкретной стратегии `combo.ts` для каждого канала `auto/*` (уровень 4). См. план #7819 для открытого вопроса о том, должны ли переопределения оставаться для каждого ключа API или становиться глобальными, учитывая одноарендную модель.

**За кулисами:**

```txt
Request: { model: "auto/coding" }
   ↓
src/sse/handlers/chat.ts detects prefix
   ↓
createVirtualAutoCombo('coding') → candidatePool from active connections
   ↓
handleComboChat (same engine as persisted combos)
   ↓
Auto-scoring selects best provider/model per request
```

**Файлы реализации:**

| Файл                                                      | Цель                                                   |
| --------------------------------------------------------- | ------------------------------------------------------ |
| `open-sse/services/autoCombo/autoPrefix.ts`               | Парсер префиксов (`parseAutoPrefix`)                   |
| `open-sse/services/autoCombo/virtualFactory.ts`           | Создает виртуальные объекты `AutoComboConfig`          |
| `open-sse/services/autoCombo/providerRegistryAccessor.ts` | Тестовый хук для имитации реестра провайдера           |

## Настройки учетной записи для сохраненных автоматических комбинаций

Редактор Intelligent Auto предлагает дополнительный** Настройки аккаунта** раздел. Каждое соединение может быть предпочтительным, нормальным (по умолчанию), резервным или исключенным. Несколько подключений могут использовать один уровень. Автоматический выбор осуществляется в пределах первого подходящего уровня, сохраняя там свое поведение scoring/router ; неудачные попытки попадают на оставшиеся конкретные учетные записи, которые предпочтительнее обычных, а не резервных. Исключенные соединения никогда не используются этой комбинацией.

Настройка сохраняется как `config.accountPreferences` с ключом соединения ID:

```json
{
  "accountPreferences": {
    "connection-a": "preferred",
    "connection-b": "preferred",
    "connection-c": "reserve",
    "connection-d": "excluded"
  }
}
```

Пропущенная или пустая карта сохраняет существующий маршрут. Настройки не включают отключенные соединения, не предоставляют доступ к ключам API, не восстанавливают кандидатов с заблокированной квотой и не обходят проверки бюджета. Каждая попытка ограничена конкретным соединением, поэтому резервная учетная запись не может переходить на уровни позади комбинированного маршрутизатора. Существующая привязка сеанса может сохранить соответствующую учетную запись; исключение учетной записи, привязанной к собственному ходу, останавливает этот ход вместо того, чтобы автоматически менять учетные записи.

Настроенные настройки используют автоматический путь с учетом учетной записи: несвязанный контекстный кэш, интеллектуальный конвейер, хаос и теневые ярлыки не отправляются. Спекулятивное хеджирование для этих запросов отключено, поэтому резервные счета не могут соревноваться с предпочтительными. Другие комбинированные стратегии не интерпретируют этот параметр. Изменение комбинации с «Авто» сохраняет сохраненные настройки для последующего переключения обратно.

## Комбинированные имена, соответствующие реальному идентификатору модели

Комбинация, `name` которой идентична простому идентификатору модели (например, комбинация с именем `gpt-5.5`), является** намеренный, поддерживаемый шаблон** , а не ошибка: это механизм возврата поставщика для каждого идентификатора модели, описанный в [#6940](https://github.com/cheaper-inference/OmniRoute/issues/6940). Поскольку разрешение комбо проверяется перед разрешением идентификатора голой модели (`getComboForModel()` в `src/sse/services/model.ts`), запрос на голый идентификатор `gpt-5.5` маршрутизируется через целевые объекты комбо (например, `acme-responses/gpt-5.5`, `backup-responses/gpt-5.5`), а не напрямую к одному поставщику — Это повторно использует приоритет комбо-перед-перезаписью, созданный для [#3227/#3233](https://github.com/cheaper-inference/OmniRoute/issues/3227), и проходит регрессионное тестирование с помощью `tests/unit/responses-combo-resolution-3227.test.ts` и `tests/unit/combo-name-codex-responses-rewrite.test.ts`.

Создание или переименование комбинации в имя, которое затеняет реальный идентификатор модели,** никогда не отвергался** — сделав это, нарушит этот документированный рабочий процесс. Вместо этого (#8530) `POST /api/combos` и `PUT /api/combos/[id]` присоединяют к ответу неблокирующее поле `warning` когда (новое) имя конфликтует с реальным идентификатором модели:

```json
{ "warning": { "code": "COMBO_NAME_SHADOWS_MODEL", "modelId": "gpt-5.5", "providerId": "openai" } }
```

При загрузке `scanComboModelNameCollisionsAtBoot()` (`src/instrumentation-node.ts`) также регистрирует однострочное предупреждение `[STARTUP]`, перечисляющее каждую существующую комбинацию, которая затеняет идентификатор модели, поэтому операторы, которые нажимают на нее случайно (а не намеренно, согласно #6940), получают сигнал. Помощник по обнаружению находится в `src/lib/combos/modelNameCollision.ts`.

## Вызов пользовательской комбинации из клиента

Сохраняемые комбинации (Настройки → Combos) используются только тогда, когда клиент отправляет комбо.** точное имя** в поле `model` — нет нечеткого или частичного совпадения имени комбинации, а также не используется префикс `auto/`. Порядок разрешения (`getComboForModel()` в `src/sse/services/model.ts`):

1. точное совпадение комбо-имени (`model: "my-combo"`),
2. префикс `combo/<name>` (`model: "combo/my-combo"`),
3. модели → комбинированные глобальные сопоставления (`/api/model-combo-mappings`).

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"my-combo","messages":[{"role":"user","content":"Hello"}]}'
```

Две распространенные ошибки:

- **`auto` не использует ваши комбинации.** `auto`/`auto/*` создает свой собственный пул кандидатов без конфигурации и обращается к сохраненным комбинациям только в том случае, если комбинация буквально называется `auto` (не рекомендуется). Чтобы маршрутизировать комбо, отправьте его точное имя — а не `auto`.
- **`openrouter/auto` — это настоящий платный продукт OpenRouter** («Auto Best Available»), а не псевдоним OmniRoute. Это единственная запись статической модели реестра OpenRouter (`open-sse/config/providers/registry/openrouter/index.ts`), оплата за которую взимается отдельно. Используйте «Настройки» → «Маршрутизация → «Скрыть платные модели», чтобы исключить их из пулов `auto`.

См. [#7992](https://github.com/cheaper-inference/OmniRoute/issues/7992) и [#7111](https://github.com/cheaper-inference/OmniRoute/issues/7111) чтобы узнать о первоначальной путанице в этих документах.

## Как это работает (постоянные автоматические комбинации)

Механизм Auto-Combo динамически оценивает кандидатов provider/model, используя** 16 заявленных факторов** (определено в `open-sse/services/autoCombo/scoring.ts` → `DEFAULT_WEIGHTS`). Сумма весов по умолчанию равна `1.0`; пользовательские веса перенормируются с помощью `normalizeScoringWeights()`. По умолчанию три фактора имеют нулевой вес: `cacheAffinity`, `resetWindowAffinity` и `reliability`. Пакеты режимов придают `reliability` вес `0.03` или `0.04` в `reliability-first`; `quality` содержит `0.03` по умолчанию и в `quality-first`, а также `0.02` в других пакетах. `cacheAffinity` также ограничивает дедупликацию кэша запросов за пределами взвешенной оценки.

![Auto-Combo 16-factor scoring](../diagrams/exported/auto-combo-scoring.svg)

> Источник: [diagrams/auto-combo-scoring.mmd](../diagrams/auto-combo-scoring.mmd) (восстановить через `npm run docs:render-diagrams`). Имя файла является историческим; исходная и визуализированная диаграмма показывают все 16 факторов, объявленных в `DEFAULT_WEIGHTS`.

| :-------------------- | :--------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `quota`               | 0.1429           | Оставшийся запас квоты/ограничения скорости [0..1]                                                                                                                                                                                                  |
| `health`              | 0.1605           | Оценка работоспособности автоматического выключателя (CLOSED= 1,0, HALF_OPEN= 0,5, OPEN= 0,0)                                                                                                                                                       |
| `costInv`             | 0.1429           | Обратный** смешанный** стоимость (60% входной + 40% выходной цены токена, нормализованная) — дешевле = более высокий балл                                                                                                                           |

| `cacheAffinity`       | 0.00             | Привязка хеша рандеву к соединению, которое, скорее всего, уже содержит префикс кэша подсказок этого запроса (`open-sse/services/combo/promptCacheAffinity.ts`); отключено по умолчанию (#8008)                                                     |

Трекер `quality` в памяти (`open-sse/services/routing/quality.ts`) пуст после холодного перезапуска, поэтому каждый кандидат получает нейтральный `0.5` до тех пор, пока не появятся первые наблюдения.

> **Нечитаемая квота (#15347).** Если у провайдера есть сборщик квот, но он не возвращает ничего читаемого (неудачная выборка, отсутствующие учетные данные, использование только сообщений или неверный снимок без анализируемого `windows` и конечного `percentUsed`, включая `percentUsed: null`), кандидат получает оценку `0` по оси `quota`, а его окончательный балл умножается на `UNREADABLE_QUOTA_SOFT_DEPRIORITIZE_FACTOR` (0,5, `autoStrategy.ts`), тот же шаблон мягкого штрафа, что и штраф за состояние соединения. Неудачное чтение использования является свидетельством телеметрии, а не провайдера, поэтому оно ранжируется строго ниже любого реального чтения, включая подтвержденное 100%-used, но никогда не блокируется жестко или не удаляется. Поставщик, не имеющий ограничения, сообщает `unlimited: true` и оценивает его как полную квоту; поставщик без зарегистрированного средства получения квот вообще не имеет источника телеметрии и сохраняет значение по умолчанию `100`.

**Сумма:** `0.1429 + 0.1605 + 0.1429 + 0.1143 + 0.0762 + (7 × 0.0476) + 0.00 + 0.00 + 0.03 + 0.00 = 1.0` как указано в `DEFAULT_WEIGHTS`; Перед оценкой веса, настроенные пользователем, перенормируются в распределение по `normalizeScoringWeights()`.

## Пакеты режимов

6 предопределенных профилей веса в `open-sse/services/autoCombo/modePacks.ts`. Каждый пакет полностью заменяет веса по умолчанию, смещая выбор в сторону одной цели. Сумма каждого пакета уже равна `1.0` (`0.9999`, напечатанному с четырьмя десятичными знаками), поэтому `normalizeScoringWeights()` не имеет смысла исправлять, когда пакет активен. — значения, приведенные ниже, с округлением, являются теми, которые применяет счетчик.

Примечания:

- **Пакеты содержат `quality` и `reliability`** (`quality 0.02`, `quality-first 0.03`; `reliability 0.03`, `reliability-first 0.04`) и замените карту весов целиком (`weights = pack`, а не слияние). `DEFAULT_WEIGHTS` несет `quality 0.03 / reliability 0`; при выборе `balanced`/`default` сохраняются значения по умолчанию, при выборе пакета используются значения пакета, указанные выше. В холодном пуле (наблюдений пока нет, поэтому `quality 0.5` и `reliability 1`) эти два фактора добавляют `+0.04` в универсальном пакете (`0.03 + 0.01`), `+0.045` в `quality-first` и `+0.05` в `reliability-first`.
- `tierAffinity`, `specificityMatch` и `resetWindowAffinity` явно являются `0` в каждом пакете.
- Краткое описание каждого пакета:
  - **быстроходный** → latencyInv 0,3048 + health 0,2667 (малая задержка, работоспособные соединения)
  - **экономия средств** → costInv 0,3324 (выигрывают самые дешевые токены)
  - **качество прежде всего** → taskFit 0,3524 стабильность + 0,1429 качество + 0,03, самое высокое из всех пакетов (лучшая модель для задачи, стабильная)
  - **офлайн-дружественный** → quota 0,3324 + health 0,2667 (максимальный запас независимо от speed/cost)
  - **надежность прежде всего** → health 0,3524 + стабильность 0,1905 + надежность 0,04, самый высокий показатель среди всех пакетов (наименьшее количество сюрпризов)
  - **режим хаоса** → health 0,4000 + taskFit 0,1905 (пакет весов `auto/chaos` назначает своим членам панели; параллельный разветвление не считывает эти веса, и это не профиль внедрения ошибок, см. [CHAOS-MODE.md](../guides/CHAOS-MODE.md#autochaos-parallel-fan-out) )

### Элементы управления по запросу (заголовки) — #6023 / #6024 / #6025 / #3470

Комбинацией `auto` можно управлять** по запросу** через три заголовка, без изменения сохраненной конфигурации комбо. Они применимы только к стратегии `auto` и только к запросу, который их несет; сохраненные комбинации `modePack`/`budgetCap`/`budgetFallback` используются, когда заголовок отсутствует.

| Заголовок                     | Принимает                                                                                                                                                                                                       | Эффект                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| :---------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-Mode`            | предустановленный псевдоним (`fast`, `balanced`, `quality`, `cheap`, `reliable`, `offline`) или необработанное имя пакета (`ship-fast`, `cost-saver`, `quality-first`, `offline-friendly`, `reliability-first`) | Переопределяет веса оценки для этого запроса. `balanced`/`default` устанавливает вес по умолчанию (без пакета). Неизвестные значения игнорируются (конфигурация сохраняется).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

```bash
# Force the fastest profile, cap this request at $0.05, and hard-block instead of overspending
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "X-OmniRoute-Mode: fast" \
  -H "X-OmniRoute-Budget: 0.05" \
  -H "X-OmniRoute-Budget-Fallback: strict" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hi"}]}'
```

Разрешение — это чистая функция (`open-sse/services/autoCombo/requestControls.ts`); разрешенные значения подаются на существующие входные данные `config.modePack` / `config.budgetCap` / `config.budgetFallback` движка. Сохраненный `config.budgetFallback` комбинации («строгий» | «самый дешевый») устанавливает постоянную политику; заголовок переопределяет его для одного запроса.

| `lkgp`              | Last-Known-Good Path (привязывается к последнему успешному провайдеру, затем возвращается к правилам)                                                                                                                                                                                                                                                                                                                                    |
| `context-optimized` | Сначала попробуйте самое большое известное контекстное окно (устраненные ограничения возможностей модели)                                                                                                                                                                                                                                                                                                                                |
| `cache-optimized`   | Предпочитайте подходящее соединение, которое может содержать префикс приглашения в кеше (`open-sse/services/combo/promptCacheAffinity.ts`, #8008).                                                                                                                                                                                                                                                                                       |
| `fusion` 🧬         | Параллельно распределите группу моделей, затем синтезируйте один ответ через судью (см. ниже).                                                                                                                                                                                                                                                                                                                                           |
| `pipeline`          | Запускайте цели последовательно, объединяя выходные данные каждого шага с входными данными следующего шага; возвращается только окончательный ответ (#6396)                                                                                                                                                                                                                                                                              |
| `jev`               | Список предпочтений, ранжированный пользователем; TypeSafe Jev признает, какие записи выполняются для этого запроса. Победитель первым, остальные допущенные цели сохранят ваш порядок. Согласованное и платное: вызывается только тогда, когда `COMBO_JEV_STRATEGY_ENABLED` включен (по умолчанию выключен); каждый вызов отправляет ограниченный отрывок в api.typesafe.ai. Возвращается к вашему заказу, когда он недоступен (#15276) |

⭐ = Новое в версии 3.8.0 · 🧬 = Новое в версии 3.8.36

Стратегия `jev` выполняет платные вызовы TypeSafe только тогда, когда `COMBO_JEV_STRATEGY_ENABLED` включен. Сохраненный ключ TypeSafe сам по себе не активирует эту функцию. Если флажок снят, комбинация сохраняет заказ оператора без выполнения этого вызова (`open-sse/services/combo/jevAsk.ts`).

### семантика `weighted`

`weighted` - это** пропорциональный случайный розыгрыш по запросу** (`open-sse/services/combo/targetSorters.ts` → `selectWeightedTarget`), а не эквалайзер:

- Каждый запрос рисует** один** шаг с вероятностью `weight / totalWeight`; Остальные шаги упорядочены по убыванию веса в качестве резервной цепочки для этого запроса.
- Шаг, вес которого равен `0` (или отсутствует), равен** никогда не рисовался** хотя любой другой шаг имеет вес > 0 — он может служить запасным вариантом только после неудачного выполнения нарисованного шага. Только когда** все** веса равны 0, выбор становится однородным.
- Шаги, чьими целями являются недоступный автоматический выключатель — поставщика `OPEN`, время восстановления соединения, блокировка модели — удаляются из отрисовки до того, как это произойдет (`open-sse/services/combo/targetResolution.ts`), поэтому один работоспособный шаг может временно выиграть каждый запрос.
- `stickyWeightedLimit` (комбинированная конфигурация, по умолчанию `1` = выключен) закрепляет нарисованный шаг для такого количества последовательных успехов перед повторным рисованием.

Для строгой ротации используйте `round-robin`; равные веса на `weighted` дают статистический —, а не строгий баланс —.

### Режим агентского конвейера

Комбинация `pipeline`, содержащая как минимум две модели, может выбрать маршрутизацию planner/executor с помощью `config.agenticOrchestration.enabled`. Первая цель владеет планированием и окончательными ответами; вторая цель генерирует вызовы собственных клиентских инструментов. OmniRoute обнаруживает продолжение результатов инструмента из протокола запроса, спрашивает планировщика, нужен ли еще один раунд инструмента, и динамически делает либо исполнителя, либо планировщика последним шагом, связанным с клиентом.

Дополнительный `config.agenticOrchestration.contextCompaction` применяет отдельный бюджет полезной нагрузки перед каждой отправкой планировщика или исполнителя. Включите его явно:

```json
{
  "enabled": true,
  "defaultMaxChars": 400000,
  "targetRatio": 0.72,
  "toolResultMaxChars": 24000,
  "modelMaxChars": { "provider/planner": 175000, "provider/executor": 300000 }
}
```

Это сериализованные бюджеты символов JSON выбранные оператором, а не окна контекста токена или гарантированные ограничения восходящего потока. Точная модель IDs переопределяет значение по умолчанию. Выше порогового значения сжатие удаляет идентичные определения инструментов, обрезает слишком большие свидетельства инструментов с помощью дайджеста и удаляет старые полные группы истории в сторону целевого соотношения. Он сохраняет инструкции system/developer, последний запрос пользователя, последний раунд инструмента, включая параллельный calls/results, и ведущую инструкцию маршрутизации Gemini. Инструкции верхнего уровня и настройки инструмента сохраняются. Маркер пропуска записывает удаленную историю; это детерминированная обрезка, а не семантическое резюме. Если закрепленный контекст по-прежнему превышает бюджет, запрос возвращает 413 перед обращением к модели. Если сжатие отключено или значение ниже порогового значения, запрос проходит без изменений.

При продолжении результатов инструмента OmniRoute также останавливает выполнение, когда два последовательных завершенных раунда повторяют одни и те же вызовы инструмента с неизмененными результатами или когда каждый явно отмеченный результат в двух последовательных раундах не удался. Измененные результаты допускают повторные вызовы (например, опрос). Защита сбрасывается при новом запросе пользователя, группирует параллельные вызовы в один раунд и поддерживает Anthropic, завершение чата, ответы и историю Gemini. Планировщик получает причину и получает окончательный ответ, даже если он запросит еще один инструментальный раунд.

Дополнительные модели после второй цели представляют собой упорядоченные резервные копии исполнителя. Неудачный ответ HTTP или исключение транспорта передается следующему исполнителю, неся то же решение планировщика и встроенные инструменты, но собственное приглашение на шаг этого исполнителя и разрешенное соединение. Первый успешный ответ возвращается без изменений, включая потоковую передачу SSE ; сбои после успешного запуска потока здесь не могут быть повторены. Если все исполнители терпят неудачу, возвращается последняя ошибка. Клиент прерывает остановку отправки.

```json
{
  "strategy": "pipeline",
  "models": [{ "model": "provider/planner" }, { "model": "provider/executor" }],
  "config": {
    "agenticOrchestration": { "enabled": true, "maxToolRounds": 8 }
  }
}
```

Исполнитель может отправлять несколько независимых вызовов в одном ответе. Зависимые вызовы обрабатываются на более поздних этапах обработки результатов клиентского инструмента, при этом планировщик просматривает каждый результат. `maxToolRounds` по умолчанию имеет значение `8` и принимает `1`–`32`; После достижения планировщик должен дать наилучший окончательный ответ. Решения внутреннего планировщика буферизуются, в то время как выбранный клиентский ответ сохраняет исходные предпочтения потоковой передачи.

### `round-robin` липкий пакет и расширение учетной записи

Круговой перебор выполняется пакетно, а не по одному запросу на шаг:

- `stickyRoundRobinLimit` (комбинированная конфигурация, затем `comboStickyRoundRobinLimit`, затем `settings.stickyRoundRobinLimit`, по умолчанию** 3** ) сохраняет одну и ту же цель в течение указанного количества последовательных успехов перед сменой. Установите переопределение комбо на `1` для ротации по одному запросу. Редактор комбо показывает эффективное значение и из какого слоя оно получено.
- `connectionAwareExpansion` (комбинированная конфигурация, затем настройки, по умолчанию** ЛОЖЬ** ) перед ротацией расширяет каждый шаг на уровне поставщика до целевых показателей для каждого аккаунта. Стратегии группы B (приоритет, взвешенный, циклический, случайный, p2c, наименее используемый, оптимизированный по затратам, lkgp, с первым заполнением, строгий случайный, контекстно-оптимизированный, кэш-оптимизированный, контекстная ретрансляция, слияние, конвейер, jev) сохраняют представление на уровне поставщика, пока это не будет включено. Комбо-редактор предоставляет наследование/включение/выключение; inherit использует глобальное значение по умолчанию (выключено).
- Маршрутизация локальности с подсказкой-кешем (`promptCacheAffinityEnabled`, по умолчанию** истинный** ) переупорядочивает закрепленные соединения, чтобы соответствующие ключи кэша оставались в одной учетной записи. Оно имеет приоритет над циклической и взвешенной ротацией по закрепленным шагам для каждой учетной записи. Отключите его в настройках → Combo по умолчанию, если вам нужно строгое вращение. Переопределения для каждой комбинации нет.

Для ротации нескольких аккаунтов на одной модели отдайте предпочтение** один шаг динамического аккаунта** (пустой `connectionId`, весь пул) с фиксированным лимитом `1`, а не тремя закрепленными `connectionId`. Закрепленные шаги и сходство переносятся в одну и ту же учетную запись, даже если счетчик RR увеличивается.

## Стратегия Fusion

`fusion` — единственная стратегия, которая **не** выбирает одну целевую модель. Она параллельно отправляет запрос **каждой модели панели**, после чего настраиваемая **модель-судья** синтезирует единый окончательный ответ из всех ответов панели. Перенесена из исходного проекта `decolua/9router` (реализация Fusion от OpenRouter); реализация находится в `open-sse/services/fusion.ts`.

Как это работает:

0. **Обход панели для запросов с инструментами** — запрос, содержащий непустой массив `tools`, если `tool_choice` явно не задан как `"none"`, полностью минует панель: он направляется непосредственно одной модели (настроенному судье или `panel[0]`) с передачей `tools`/`tool_choice` без изменений. Участники панели не имеют доступа к инструментам, а инструкция судье по синтезу не рекомендует генерировать вызовы инструментов, поэтому агентные клиенты и клиенты, вызывающие инструменты, получают настоящее решение о вызове инструмента вместо синтезированного текста (#6771).
1. **Параллельная рассылка** (только для запросов без инструментов) — запрос одновременно отправляется каждой модели панели в принудительно непотоковом режиме и без инструментов (для синтеза судье необходимы полные текстовые ответы).
2. **Сбор с кворумом и льготным периодом** — как только поступает `minPanel` ответов, запускается короткий таймер льготного периода для отстающих моделей, после чего объединение продолжается со всеми ответами, которые удалось собрать. Это ограничивает влияние самой медленной модели на общее время выполнения, которое также ограничено жёстким тайм-аутом.
3. **Синтез судьёй** — ответы панели анонимизируются (`Source 1`, `Source 2`, … — чтобы судья оценивал содержание, а не бренд модели) и передаются судье, который анализирует консенсус / противоречия / частичный охват / уникальные выводы / слепые зоны, а затем формирует **один** авторитетный ответ. Вызов судьи сохраняет исходный флаг клиента `stream` и инструменты, поэтому потоковая передача и последующее использование инструментов продолжают работать.
4. **Плавная деградация** — 0 ответов панели → `503`; ровно 1 уцелевший ответ → он возвращается напрямую (объединять нечего); панель из одной модели отвечает напрямую.

Участником панели также может быть шаг `combo-ref` (`{kind: "combo-ref", comboName: "..."}`), ссылающийся на другую комбинацию, — он обрабатывается как **один изолированный голос панели** (полная рекурсивная диспетчеризация в указанную комбинацию, а не параллельная рассылка по собственным целевым моделям этой комбинации) с той же защитой от чрезмерной глубины и циклов, которая уже применяется всеми другими стратегиями, использующими combo-ref (#6764).

### Конфигурация

Настраивается в объекте `config` комбинации (миграция схемы не требуется — повторно используется существующая таблица `combos`):

| Поле                                     | Тип      | Значение по умолчанию | Назначение                                                                                                          |
| :--------------------------------------- | :------- | :-------------------- | :------------------------------------------------------------------------------------------------------------------ |
| `config.judgeModel`                      | `string` | первая модель панели  | Модель, синтезирующая окончательный ответ                                                                           |
| `config.fusionTuning.minPanel`           | `number` | `2`                   | Количество успешных ответов, необходимое для запуска льготного таймера (ограничивается диапазоном `[2, panelSize]`) |
| `config.fusionTuning.stragglerGraceMs`   | `number` | `8000`                | Время ожидания отстающих моделей после достижения кворума                                                           |
| `config.fusionTuning.panelHardTimeoutMs` | `number` | `90000`               | Абсолютный предел, не позволяющий одной зависшей модели задержать запрос                                            |

Значения по умолчанию находятся в `FUSION_DEFAULTS` (`open-sse/services/fusion.ts`).

### Пример

```bash
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "fusion-panel",
    "strategy": "fusion",
    "targets": [
      { "model": "cc/claude-opus-4-7" },
      { "model": "cx/gpt-5.5" },
      { "model": "glm/glm-5.1" }
    ],
    "config": {
      "judgeModel": "cc/claude-opus-4-7",
      "fusionTuning": { "minPanel": 2, "stragglerGraceMs": 8000, "panelHardTimeoutMs": 90000 }
    }
  }'
```

Затем вызывайте её как любую другую комбинацию: `{"model":"fusion-panel","messages":[...]}`.

## Виртуальная фабрика Auto-Combo

Движок Auto Combo не требует предварительно определённых комбо. Вместо этого `open-sse/services/autoCombo/virtualFactory.ts` формирует кандидатов на лету:

1. Получает `getProviderConnections({ isActive: true })` (все включённые подключения)
2. Оставляет подключения с действительными учётными данными (API-ключом или непросроченным OAuth-токеном, проверяемым через `hasUsableOAuthToken()`)
3. Сопоставляет их с `getProviderRegistry()` для определения доступности моделей и цен
4. Для каждого кортежа `(provider, model, connection)` создаёт `VirtualAutoComboCandidate`
5. Выбирает `connection.defaultModel` (или первую модель из реестра) в качестве цели маршрутизации
6. Оценивает каждого кандидата с помощью 16-факторной функции `scorePool()` и набора весов варианта
7. Возвращает получившуюся хранящуюся в памяти конфигурацию `AutoComboConfig` для `handleComboChat()` — она никогда не сохраняется в БД

Это означает, что **добавление нового провайдера с включённым `auto/*` автоматически расширяет пул кандидатов** — вручную редактировать комбо не требуется. Виртуальный комбо создаётся заново для каждого запроса, поэтому недавно добавленные или восстановившие работоспособность подключения используются немедленно.

## Самовосстановление

- **Временное исключение**: оценка < 0.2 → исключение на 5 мин (прогрессивная задержка, максимум 30 мин)
- **Учёт автоматического выключателя**: OPEN → автоматическое исключение; HALF_OPEN → пробные запросы
- **Режим инцидента**: >50% OPEN → отключить исследование, максимизировать стабильность
- **Восстановление после периода ожидания**: после исключения первый запрос является «пробным» и выполняется с уменьшенным тайм-аутом

## Исследование методом многорукого бандита

5% запросов (значение настраивается) направляются случайным провайдерам для исследования. Отключается в режиме инцидента.

## API

Есть** нет выделенной конечной точки `POST /api/combos/auto`** — Auto-Combo используется двумя способами:

1. **Нулевая конфигурация (рекомендуется):** Отправьте любой запрос на завершение чата с помощью `model: "auto"` или `model: "auto/<variant>"`. Виртуальная фабрика создает комбинацию для каждого запроса — без сохранения, никаких вызовов API не требуется.

2. **Сохраняющаяся комбинация с `strategy: "auto"`:** Создайте обычную комбинацию через `POST /api/combos` и установите `strategy: "auto"` плюс `config.auto.weights` / `config.auto.candidatePool`. Используется та же система подсчета очков; комбинация сохраняется в `combos` и может быть повторно использована ID.

Для обнаружения `GET /api/combos/auto` перечисляет каждый вариант с разрешенным пулом кандидатов, а также `context_length` / `max_output_tokens` — MAX в окнах пула кандидатов. Клиенты (например, плагин открытого кода) должны объявлять эти значения вместо `0`: нулевой контекст полностью отключает автоматическое сжатие открытого кода, позволяя сеансам расти до тех пор, пока очистка истории шлюза не уничтожит контекст. MAX безопасно рекламировать, поскольку предварительный фильтр контекста автоматического комбинирования направляет слишком большие запросы кандидатам с большим окном.

```bash
# Zero-config usage (no combo creation)
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Hello"}]}'

# Persisted auto combo via the regular combos endpoint
curl -X POST http://localhost:20128/api/combos \
  -H "Content-Type: application/json" \
  -d '{"id":"my-auto","name":"Auto Coder","strategy":"auto","config":{"auto":{"candidatePool":["anthropic","google","openai"],"weights":{"quota":0.15,"health":0.3,"costInv":0.05,"latencyInv":0.35,"taskFit":0.1,"stability":0,"tierPriority":0.05}}}}'
```

### Стратегии автоматической трассировки

Сохраняющиеся комбинации `strategy: "auto"` могут устанавливать `config.routerStrategy` (или устаревшего `config.auto.routerStrategy`) одно из следующих значений:

- `rules` — взвешенная оценка по умолчанию
- `score` — выбирает наивысший настроенный взвешенный балл. Точные связи сохраняют настроенный порядок кандидатов; существующие образцы `explorationRate` из полного ранжированного пула.
- `cost` / `eco` — самый дешевый здоровый поставщик
- `latency` / `fast` — минимальная задержка p95 со снижением надежности
- `sla-aware` / `sla` — отдает предпочтение кандидатам, которые удовлетворяют задержке p95, частоте ошибок и дополнительной стоимости SLOs
- `lkgp` — первый известный хороший провайдер
- `nadir` — узнать решение [Надира](https://getnadir.com) API какая модель в пуле нужна подсказке; подписка, открытие при сбое в `rules`
- `decision` — спросить настроенного решающего лица (TypeSafe System One, ваше собственное решение URL или одну из собственных моделей комбинации), какая модель в пуле соответствует запросу; за отключенным по умолчанию флагом `COMBO_DECISION_ROUTER_ENABLED`, отказоустойчивое открытие для `rules`

### Стратегии маршрутизатора в деталях

Автоматический комбинированный движок предоставляет 7 подключаемых**RouterStrategy** реализации, которые вы можете поменять через `config.routerStrategy` (или устаревший `config.auto.routerStrategy`). Каждая стратегия выбирает одного поставщика из пула кандидатов с учетом `RoutingContext` (тип задачи, подсказки tool/vision, оценка токена, необязательная политика SLA, необязательный последний известный хороший поставщик).

#### 1. `rules` (по умолчанию) — 16-факторная взвешенная оценка

Обертывает существующий механизм оценки. Отфильтровывает кандидатов на автоматический выключатель `OPEN`, затем запускает `scorePool()` с текущим типом задачи и `getTaskFitness()`, выбирая поставщика с наибольшим количеством баллов.

```ts
class RulesStrategyImpl implements RouterStrategy {
  readonly name = "rules";
  readonly description = "16-factor weighted scoring (see DEFAULT_WEIGHTS)";

  select(pool, context) {
    const eligible = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const ranked = scorePool(
      eligible.length > 0 ? eligible : pool,
      context.taskType,
      undefined,
      getTaskFitness
    );
    return { provider: ranked[0].provider /* ... */ };
  }
}
```

**Когда использовать** : По умолчанию. Используйте, если вам нужен сбалансированный компромисс для всех сигналов.

**Псевдоним** : `rules` (без псевдонима)

---

#### 2. `cost` / `eco` — самый дешевый здоровый поставщик

Сортирует пул кандидатов по `costPer1MTokens` (по возрастанию) и выбирает самых дешевых. Сначала отфильтровывает кандидатов `OPEN`.

```ts
class CostStrategyImpl implements RouterStrategy {
  readonly name = "cost";
  readonly description = "Always selects cheapest available provider";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort((a, b) => a.costPer1MTokens - b.costPer1MTokens);
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**Когда использовать** : чувствительные к затратам рабочие нагрузки, пакетная обработка или фоновые задания.

**Псевдонимы** : `cost`, `eco`

---

#### 3. `latency` / `fast` — минимальная задержка p95 со снижением надежности

Сортировка по `p95LatencyMs + (errorRate * 1000)`. Штраф за частоту ошибок гарантирует, что ненадежным поставщикам будет присвоен более низкий рейтинг, даже если их номинальная задержка невелика.

```ts
class LatencyStrategyImpl implements RouterStrategy {
  readonly name = "latency";
  readonly description = "Prioritizes lowest p95 latency with reliability weighting";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort(
      (a, b) => a.p95LatencyMs + a.errorRate * 1000 - (b.p95LatencyMs + b.errorRate * 1000)
    );
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**Когда использовать** : рабочие нагрузки, чувствительные к задержке, такие как чат в реальном времени, автозаполнение или интерактивные помощники по кодированию.

**Псевдонимы** : `latency`, `fast`

---

#### 4. соответствие требованиям `sla-aware` / `sla` — latency/error/cost SLO

Оценивает каждого кандидата по тому, насколько хорошо он соответствует настроенной политике SLO :

| Фактор              | Масса | Формула                                               |
| ------------------- | ----- | ----------------------------------------------------- |
| Оценка задержки     | 35%   | `threshold / max(value, ε)`                           |
| Оценка ошибки       | 35%   | `threshold / max(value, ε)`                           |
| Оценка здоровья     | 15%   | `1.0` (CLOSED) / `0.5` (HALF_OPEN) / `0.0` (OPEN)     |
| Оценка стоимости    | 10%   | `threshold / max(value, ε)` или обратная нормализация |
| Оценка стабильности | 5%    | обратная нормализованная задержка stddev              |

При `hardConstraints: true` кандидаты сортируются в первую очередь по** оценка нарушения** (насколько они превышают любой SLO), затем по составному баллу. В противном случае это просто совокупный балл.

```ts
class SLAStrategyImpl implements RouterStrategy {
  readonly name = "sla-aware";
  readonly description =
    "Selects the provider most likely to satisfy latency, error-rate, and cost SLOs";

  select(pool, context) {
    // ... scores each candidate against policy: { targetP95Ms, maxErrorRate, maxCostPer1MTokens, hardConstraints }
  }
}
```

**поля SLA** (устанавливается в комбо-конфигурации):

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "sla-aware",
    "slaTargetP95Ms": 1500,
    "slaMaxErrorRate": 0.05,
    "slaMaxCostPer1MTokens": 5,
    "slaHardConstraints": true
  }
}
```

**Когда использовать** : Производственные рабочие нагрузки со строгими требованиями к задержке, частоте ошибок или бюджету затрат.

**Псевдонимы** : `sla-aware`, `sla`

---

#### 5. `lkgp` — первый известный хороший провайдер

Пробует** последний известный хороший провайдер** (если установлено) сначала, затем возвращается к стратегии `rules`. Полезно для закрепления сеанса — один и тот же провайдер обрабатывает последующие запросы в ходе разговора.

```ts
class LKGPStrategyImpl implements RouterStrategy {
  readonly name = "lkgp";
  readonly description = "Tries last known good provider first, then falls back to rules";

  select(pool, context) {
    if (context.lkgpEnabled === false) {
      return getStrategy("rules").select(pool, context);
    }

    if (context.lastKnownGoodProvider) {
      const candidates = pool.filter(
        (c) => c.provider === context.lastKnownGoodProvider && c.circuitBreakerState !== "OPEN"
      );
      if (candidates.length > 0) {
        return { provider: candidates[0].provider /* ... */ };
      }
    }

    // Fallback to rules strategy
    return getStrategy("rules").select(pool, context);
  }
}
```

**Когда использовать** : многоходовые диалоги, в которых вы хотите, чтобы один и тот же поставщик обрабатывал последующие запросы (например, для кэширования, непрерывности контекста или согласованности цен).

**Псевдоним** : `lkgp` (без псевдонима)

---

#### 6. Выбор модели `nadir` — с подсказкой через Nadir

Каждая описанная выше стратегия ранжирует кандидатов по их собственным телеметрическим данным; никто из них не читает запрос. `nadir` отправляет последний ход пользователя, а также идентификаторы моделей пула в решение [Надира](https://getnadir.com) API (`POST /v1/bucket`) и маршруты к модели, которую Надир выбирает из этого меню (`simple` → самая дешевая доступная модель, `complex` → пограничная). Соединение, обслуживающее эту модель, по-прежнему выбирается `rules`, поэтому квота, работоспособность и стоимость продолжают определять, какая именно учетная запись.

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "nadir",
    "nadir": {
      "apiKey": "ndr_...",
      "baseUrl": "https://api.getnadir.com",
      "timeoutMs": 2000
    }
  }
}
```

`OMNIROUTE_NADIR_API_KEY` и `OMNIROUTE_NADIR_BASE_URL` — резервные варианты env для этих двух строк. `baseUrl` необходим только для локального Nadir (конечный `/v1` допускается). Бесключевые вызовы попадают на анонимный уровень Nadir, скорость которого ограничена для каждого IP. С помощью ключа ( [создайте его](https://app.getnadir.com/dashboard/api-keys) ) каждое решение записывается на вашу панель управления Nadir. Полная настройка и проверка: [getnadir.com/docs/gateway-omniroute](https://getnadir.com/docs/gateway-omniroute/).

Что остается в коробке: текст последнего сообщения пользователя (первые 16 тысяч символов), идентификаторы моделей-кандидатов и тег канала `source: "omniroute"`. Никаких системных подсказок, истории, инструментов или заголовков.

Поведение при сбое является отказо-открытым: тайм-аут (по умолчанию 2000 мс), non-2xx, недостижимый хост, неверный ответ или выбор вне пула приводит к решению `rules`, а причина имеет префикс `NadirStrategy: fallback (…)`. После неудачного вызова стратегия пропускает сеть в течение 30 секунд, поэтому сбой обходится одним тайм-аутом за 30 секунд, а не за один за запрос. События маршрутизации сообщают `strategy: "nadir"` только тогда, когда Надир действительно сделал выбор.

**Когда использовать** : трафик смешанной сложности в пуле, охватывающем уровни модели (маленькая, средняя и пограничная модель), где всегда-граничная — это стоимость, которую вы хотите сократить.

**Псевдоним** : `nadir` (без псевдонима)

---

#### 7. Подключаемый решающий модуль `decision` — выбирает модель

`decision` спрашивает** решающий** какая модель в пуле соответствует запросу, затем сужает пул до этой модели и позволяет `rules` выбрать соединение (квота, работоспособность и стоимость по-прежнему выбирают учетную запись). Решающее устройство устанавливается в блоке принятия решений комбо — `config.decision` когда ручки маршрутизатора находятся в верхней части `config` (то, что пишет приборная панель) или `config.auto.decision` рядом с `config.auto.routerStrategy`:

| `decider`     | Кто отвечает                                                                                                                | Потребности                                   |
| ------------- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `systemone`   | TypeSafe System One (`POST https://api.typesafe.ai/v1/systemone`), модель по умолчанию `jev-latest`                         | соединение `typesafe` или ключ env            |
| `http`        | ваше собственное решение на `baseUrl`: `wire: "systemone"` (`{baseUrl}/v1/systemone`) или `"openai-chat"` (завершения чата) | `baseUrl` + `model`; ключ опционально         |
| `combo-model` | одна из ваших моделей провайдера, вызываемая в процессе, как судья по слиянию                                               | `model` как `provider/model` (без комбинации) |

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "decision",
    "decision": {
      "decider": "http",
      "baseUrl": "https://decider.example.com",
      "wire": "openai-chat",
      "model": "qwen-small",
      "connectionId": "<stored connection id>",
      "timeoutMs": 2000,
      "minConfidence": 0.6,
      "descriptions": { "gpt-4o-mini": "Quick drafts and short answers" }
    }
  }
}
```

Поля (проверяются строгой схемой при сохранении и повторно во время запроса):

- `decider` — `systemone`, `http` или `combo-model`.
- `model` — модель TypeSafe, модель принятия решения в вашем URL или `provider/model` вызова комбинированной модели (до 200 символов).
- `baseUrl` — Только `http` : `http(s)` URL длиной до 500 символов, без учетных данных, запроса или фрагмента. URL указывающий на этот OmniRoute (обратная связь + `PORT`), отклоняется.
- `wire` — Только `http` : `systemone` (по умолчанию) или `openai-chat`.
- `connectionId` — сохраненное соединение, ключ которого используется (только внутри разрешенных соединений вызывающего ключа API ). Без него `systemone` считывает соединение `typesafe`, и каждый решающий элемент сети возвращается к `OMNIROUTE_DECISION_API_KEY`. Поле `apiKey` нет: ключ никогда не сохраняется в комбинации.
- `timeoutMs` — целое число, 100–5000, по умолчанию 2000.
- `minConfidence` — 0–1; ответ с более низкой уверенностью возвращается к `rules` (решающее устройство, которое сообщает об отсутствии уверенности, считается как 0).
- `descriptions` — до 50 записей (ключ до 300, текст до 1000 символов), с ключом по идентификатору модели или `provider/model`; неустановленные записи получают сгенерированное описание ранга стоимости.

**Флаг.** `COMBO_DECISION_ROUTER_ENABLED` (по умолчанию `false`) контролирует каждый решающий элемент. Пока он выключен, комбинация `decision` не считывает учетные данные, не выполняет вызовы и не маршрутизируется с помощью `rules`; в журнале написано `fallback (disabled)`. Сохраненный ключ сам по себе никогда не включит его. Комбо без блока принятия решения вообще не затрагиваются.

**Что выходит из коробки.** Только текст последнего сообщения пользователя (до 8000 символов; chat/Claude `messages` или Responses `input`) и меню идентификаторов моделей с их описаниями. Никогда не выводятся системные запросы, ответы `instructions`, инструменты, история, заголовки или данные учетной записи. Сетевые вызовы проходят через защиту исходящего трафика провайдера без повторных попыток и перенаправлений и с ограничением ответа 64 KB. Вызов `combo-model` является непотоковым, не требует инструментов, `temperature: 0`, с бюджетом в 256 токенов; решение, начатое внутри вызова принятия решения, отклоняется.

**Поведение при отказе** является отказооткрытым: любой сбой приводит к решению `rules`, а причина читается как `decision(<decider>): fallback (<reason>)`, где `<reason>` один из `disabled`, `not_configured`, `missing_credential`, `timeout`, `http_error`, `invalid_response`, `out_of_menu`, `refused`, `cooldown`, `network_error`, `recursion`, `low_confidence`, `single_option` или `no_user_text`. После тайм-аута, ошибки HTTP или сетевой ошибки конечная точка пропускается на 30 секунд. Успешный выбор читается `decision(<decider>): selected <model> from <n>; confidence <c> (<rules reason>)`. Ни один URL, ключ, приглашение или тело восходящего потока не попадают в журнал.

Построитель комбинаций показывает эти поля, если выбрана стратегия маршрутизации `decision`, со сгенерированными описаниями в качестве заполнителей и** Тестовое решение** кнопка, которая вызывает `POST /api/combos/decision-preview` один раз с несохраненными настройками (тот же флаг).

**Когда использовать** : трафик смешанной сложности, где вы хотите, чтобы уровень выбирался для каждого запроса выбранным вами классификатором, а не конкретно Надиром.

**Псевдоним** : `decision` (без псевдонима)

### Пользовательские стратегии маршрутизатора

Вы можете зарегистрировать свою собственную реализацию `RouterStrategy` через общедоступный API:

```ts
import {
  registerStrategy,
  type RouterStrategy,
} from "@omniroute/open-sse/services/autoCombo/routerStrategy";

class MyCustomStrategy implements RouterStrategy {
  readonly name = "my-custom";
  readonly description = "My custom routing strategy";

  select(pool, context) {
    // Your routing logic here
    return {
      provider: pool[0].provider,
      model: pool[0].model,
      strategy: this.name,
      reason: "MyCustomStrategy: ...",
      candidatesConsidered: pool.length,
      finalScore: 1.0,
    };
  }
}

registerStrategy("my-custom", new MyCustomStrategy());
```

Затем используйте его:

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "my-custom"
  }
}
```

## Соответствие задачам

Более 30 моделей оценены по 6 типам задач (`coding`, `review`, `planning`, `analysis`, `debugging`, `documentation`). Поддерживаются шаблоны с подстановочными знаками (например, `*-coder` → высокая оценка за программирование).

## Обзор автовариантов

`AutoVariant` в `autoPrefix.ts` заявляет** 7 значений** (`coding`, `fast`, `cheap`, `offline`, `smart`, `lkgp`, `chaos`). Together с голым `auto` (обрабатывается `parseAutoPrefix()` как `variant: undefined`) и двумя плоскими многоуровневыми наложениями `auto/subscription` и `auto/thrifty` (`FLAT_TIER_OVERLAY_IDS` в `builtinCatalog.ts`), есть** 10 плоских моделей IDs** :

`auto`, `auto/coding`, `auto/fast`, `auto/cheap`, `auto/offline`, `auto/smart`, `auto/lkgp`, `auto/chaos`, `auto/subscription`, `auto/thrifty`

Помимо этого, также разрешаются композиции `auto/<category>[:<tier>]`, семейство моделей IDs (например `auto/claude-opus`) и псевдонимы `auto/best-*` / `auto/pro-*` в `builtinCatalog.ts`.

## Как уровни вписываются в Auto-Combo

Функция оценки по 16 факторам (`open-sse/services/autoCombo/scoring.ts`) рассматривает принадлежность к уровню как два сигнала: `tierPriority` (0.0476) и `tierAffinity` (0.0476). Полный набор `DEFAULT_WEIGHTS` приведён выше в канонической [таблице факторов оценки](#how-it-works-persisted-auto-combos), а переопределения для отдельных наборов (ship-fast/cost-saver/quality-first/offline-friendly) перечислены в таблице «Профили весов для каждого набора».

Сам по себе уровень **не** обеспечивает безусловный приоритет Tier 1: если задержка Tier 1 слишком высока или соотношение стоимости и качества неоптимально, выигрывает Tier 2. Чтобы принудительно задать порядок уровней, используйте стратегию комбинации `priority` и расположите провайдеров в соответствии с уровнями.

Чтобы отдать значительное предпочтение Tier 1 (подписке), увеличьте вес `tierPriority`:

```json
{
  "strategy": "auto",
  "config": { "auto": { "weights": { "tierPriority": 0.3, "costInv": 0.05 } } }
}
```

Определения уровней и классификацию провайдеров см. в разделе [`docs/guides/TIERS.md`](../guides/TIERS.md).

## Тестирование и покрытие

### Детерминированная матрица решений о маршрутизации (`npm run test:combo:matrix`)

`tests/integration/combo-matrix/*.test.ts` подтверждает маршрутизацию** решение** общедоступных стратегий он охватывает сквозной путь через настоящий комбинированный конвейер с высмеиваемым восходящим потоком. Покрытие включает в себя:

- 18 из 22 общедоступных стратегий `ROUTING_STRATEGY_VALUES` (упорядоченные, взвешенные, стоимостные, контекстные, объединенные и т. д.); `quota-weighted`, `cache-optimized`, `pipeline` и `jev` не выполняются матрицей и полагаются на собственные модульные тесты.
- `quota-share` (внутренний) сквозной: справедливость DRR, деприоритизация насыщения + через реальный шов `selectQuotaShareTarget` (`registerQuotaFetcher` / `setLKGP` / `__setHeadroomSaturationFetcherForTests`).
- Покрытие `context-relay` с универсальной передачей обслуживания для каждого целевого счетчика.

Этот пакет работает в CI (задание `test:integration` ) с `--test-concurrency=1` и `--test-force-exit`, поэтому он детерминирован и не требует действующих учетных данных.

### Закрытый живой дым (NOT в CI — реальных поставщиков)

| Команда                                | Что он делает                                                                                   |
| :------------------------------------- | :---------------------------------------------------------------------------------------------- |
| `npm run test:combo:live`              | Реальная маршрутизация внутри процесса с помощью `RUN_COMBO_LIVE=1`; снимки живого OmniRoute DB |
| `npm run test:combo:live:vps`          | вызовы HTTP к работающему серверу OmniRoute (установите `COMBO_LIVE_BASE_URL`)                  |
| `npm run test:combo:live:vps:failover` | То же самое, с преднамеренными сценариями аварийного переключения.                              |

Эти дымовые тесты проверяют реальный путь проводов (завершение комбинированного поставщика → → ). Они намеренно исключены из CI поскольку им требуются действующие учетные данные и доступ VPS.
