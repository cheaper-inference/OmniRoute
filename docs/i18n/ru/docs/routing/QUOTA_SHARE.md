## Обзор

Механизм совместного использования квот справедливо распределяет ограниченную по времени квоту провайдера (например, 5-часовое окно Codex или 1500 запросов/ч для Kimi) между несколькими API-ключами, использующими одно и то же подключение.

**Решаемая проблема:** OmniRoute проксирует множество API-ключей через одну и ту же учётную запись вышестоящего провайдера. Без логики совместного использования всплеск запросов от ключа A может исчерпать квоту провайдера на текущий час, из-за чего ключи B и C будут заблокированы до сброса окна. Механизм предотвращает это следующим образом:

1. Отслеживает потребление каждого ключа в скользящем окне по каждому измерению (%, запросы, токены, $).
2. Применяет алгоритм справедливого распределения с полным использованием ресурсов: ключ может заимствовать неиспользуемые доли, пока общий пул не насыщен.
3. Применяет результат на критическом пути (`chatCore.ts`) до того, как запрос поступит вышестоящему исполнителю.

## Алгоритм: справедливое разделение и сохранение труда

Реализовано в `src/lib/quota/fairShare.ts`.

### Режимы

| Состояние                                  | Режим       | Поведение                                                                     |
| ------------------------------------------ | ----------- | ----------------------------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **Щедрый**  | Ключ может занимать до глобального лимита минус потребленное общее количество |
| `globalUsedPercent >= saturationThreshold` | **Строгий** | Строго соблюдайте индивидуальную справедливую долю                            |

`saturationThreshold = 0.5` по умолчанию (env `QUOTA_SATURATION_THRESHOLD`).

Эти два режима описывают пул в режиме заимствования по умолчанию, `saturation`. Пул в режиме `consent` всегда применяет строгие правила, независимо от насыщения. См. [Согласованное кредитование (согласие для каждого пула)](#consented-lending-per-pool-opt-in).

### Решение по каждому измерению

Для каждого активного измерения в пуле механизм вычисляет:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = current rolling value for this key (from QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

Для измерений `percent` вместо этого `consumed` берется из книги атрибуции (см. [Процентные измерения: атрибуция по ключам](#percent-dimensions-per-key-attribution) ).

Затем:

- **`policy = hard`** : если `consumed > fairShareAllowed` и режим строгий →** блокировать** .
- **`policy = soft`** : если `consumed > fairShareAllowed` и режим строгий →** наказывать** (уменьшите приоритет в комбо; никогда не блокируйте).
- **`policy = burst`** : разрешить, пока существует глобальный запас, независимо от справедливой доли.

### Кепка абсолюто

`capValue` + `capUnit` при выделении — это жесткий потолок, не зависящий от режима или политики. Любое измерение, где `consumed >= capValue` всегда** блоки** запрос. Для ограничения `percent` `consumed` — это только часть, присвоенная ключу.

### Многомерная проверка

Запрос блокируется, если** любой** измерение в бассейне заблокировало бы его. Измерения независимы — исчерпание 5h% не влияет на измерение еженедельного%.

### Заимствование

В щедром режиме ключ, выделение которого недостаточно использовано, может использовать излишек нераспределенных долей других ключей. Формула:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

где `consumedByOtherKeys = consumedTotal - consumedByThisKey`. Глобальный тето (пул `limit` для этого измерения) всегда является жестким потолком.

### Согласованное кредитование (согласие для каждого пула)

Каждый пул имеет режим заимствования. `saturation` используется по умолчанию и сохраняет приведенные выше правила. В режиме `consent` ключ `hard` передает свою долю только в пределах емкости, которую согласились предоставить другие ключи. Администратор устанавливает режим каждого пула. Каждый владелец ключа устанавливает свое собственное согласие через [Согласие на кредитование](#lending-consent).

Согласие представляет собой процент от 0 до 100 и необязательный срок в миллисекундах эпохи. Ключ предоставляет взаймы этот процент своей простаивающей доли, пока крайний срок наступает в будущем.

Для одного измерения `L` — это эффективный лимит: лимит плана, умноженный на количество аккаунтов в пуле. Шлюз вычисляет для запрашиваемого ключа:

```
share_k         = w_k / 100 × L
idle_k          = max(0, share_k − consumed_k)
lent            = Σ over the other keys of lend_k / 100 × idle_k
taken           = Σ over the other keys of max(0, consumed_k − share_k)
borrowAvailable = max(0, lent − taken)
```

`w_k` — это вес ключа, или `100 / n` для каждого ключа, если ни один из весов не превышает 0. `lend_k` — это активный процент ключа и 0 после истечения его крайнего срока. Собственное согласие запрашивающего ключа никогда не учитывается. Ключ `hard` отклоняется, как только его потребление достигает его доли плюс `borrowAvailable`.

Емкость, на которую не претендует никакое распределение (100 минус сумма весов), не подлежит кредитованию. Ни один ключ не согласился одолжить его.

**Пример.** `L` - 1000.

| Ключ | Масса | Делиться | Потреблено | Кредитует |
| ---- | ----- | -------- | ---------- | --------- |
| А    | 50    | 500      | 530        | 0%        |
| Б    | 30    | 300      | 100        | 50%       |
| С    | 0     | 0        | 60         | 0%        |

- B предоставляет взаймы 50% своих простаивающих 200, что составляет 100. C уже взял 60 сверх своей доли. А может одолжить 40.
- А подается на 530 и отказывается, как только его потребление достигает 540.
- До того, как C что-либо использовал, при наличии у A доли или меньшей, C мог занять 100 долларов.
- До того, как C что-либо использовал, при цене A в 530 C мог одолжить 70.

**Нулевой вес.** Ключ с весом 0 имеет долю, равную 0. Он обслуживается только тогда, когда его потребление ниже того, что одалживают другие. Когда никто не дает взаймы, ему отказывают в первой просьбе.

**Сроки.** Никакая фоновая задача не приводит к истечении срока действия согласия. Каждый запрос сравнивает срок со своим собственным временем, и срок, равный этому времени, прошел. Сохраненный срок, который не является конечным числом или превышает максимальную дату, которую может удерживать `Date`, считается пройденным.

**`soft` и `burst`.** Кредитование их не ограничивает. Ключ `soft` теряет приоритет после превышения своей доли. Ключ `burst` проходит, пока в пуле есть место. Потолок пула по-прежнему отказывается от каждого ключа, когда общее количество ключей в пуле достигает предела.

**Стоимость на пути запроса.** Пул `saturation` не читает ничего больше, чем раньше. В пуле `consent` счетное измерение считывает другие ключи только для ключа `hard` с его долей или выше, в то время как другой ключ предоставляет взаймы. Затем он параллельно выполняет одно чтение для каждого другого ключа. Неудачное чтение считается потреблением 0 для этого ключа. Измерение `percent` не добавляет чтения, поскольку в книге атрибуции хранятся все ключи.

**Редактирование пула.** При редактировании сохраняется согласие оставшихся ключей. Это справедливо для изменений распределения, замен на уровне группы и вызовов `ensure`. Удаленный ключ теряет свое согласие, а добавленный обратно ключ начинается с 0. Маршруты администратора возвращают согласие каждого ключа и никогда не записывают его. При переключении пула обратно на `saturation` все сохраненные согласия сохраняются, что не имеет никакого эффекта в этом режиме. Повторное переключение пула на `consent` повторно активирует сохраненные согласия, срок действия которых еще не истек. Владелец ключа может удалить сохраненное согласие в любом режиме.

**Обновление.** Если столбцы `lending_percent` и `lending_until` уже существуют, при миграции добавляется только `borrow_mode`, а сохраненные проценты остаются прежними. Каждый пул запускается в режиме `saturation`. Включите `consent` для каждого пула в мастере пулов. Из сохраненных значений ничего не выводится.

**Ограничения.**

- Кредитор может найти пул у своего потолка до того, как он воспользуется своей долей. Емкость, заимствованная другими, учитывается в общей сумме пула.
- Проверка выполняется перед запросом и ничего не резервирует. Одновременные запросы считывают потребление до того, как оно будет записано, поэтому предоставленная мощность может быть потрачена более одного раза, в зависимости от количества запросов в процессе. Проверка общего доступа в режиме `saturation` обладает тем же свойством.

## Счётчик скользящего окна

Реализован в `src/lib/quota/sqliteQuotaStore.ts` и `redisQuotaStore.ts`.

Два сегмента для каждой пары `(apiKeyId, dimensionKey)`:

- `curr`: текущий сегмент (`floor(nowMs / windowMs)`)
- `prev`: предыдущий сегмент (`curr - 1`)

Эффективное значение скользящего окна:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**Точность**: приблизительно 99%. Погрешность составляет не более 1% размера окна на границе между сегментами (неотъемлемое свойство приближения с двумя сегментами).

### Конкурентный доступ

Драйвер SQLite: мьютекс в памяти для каждого ключа `(apiKeyId | dimensionKey)` предотвращает состояние гонки при чтении, изменении и записи. Шаблон аналогичен защите от лавинообразных запросов в `src/sse/services/auth.ts`.

Драйвер Redis: Lua-скрипт EVAL для атомарного увеличения значения — выполняется как одна команда Redis.

## Драйверы

### SQLite (по умолчанию, не требует установки)

- Таблица: `quota_consumption` (см. миграции `073_quota_pools.sql` / `074_quota_consumption.sql`).
- Лучше всего подходит для развертываний с одним экземпляром.
- Все данные хранятся в существующей базе данных OmniRoute SQLite (`DATA_DIR/storage.sqlite`).

### Redis (необязательно, для нескольких экземпляров)

- Требуется npm-пакет `ioredis`.
- Счетчики хранятся в Redis; метаданные (пулы/распределения) по-прежнему хранятся в SQLite.
- Лучше всего подходит для развертываний с несколькими репликами, где счетчики должны быть общими.

### Переключение драйверов

Через интерфейс настроек (`/dashboard/settings` → Quota Store) или переменные окружения:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

Настройка БД имеет приоритет над переменной окружения. Если указан `driver=redis`, но URL отсутствует или
`ioredis` не установлен, фабрика переключается на SQLite и записывает предупреждение в журнал.

Порядок выбора драйвера:

1. Настройка БД `quotaStore.driver`
2. Переменная окружения `QUOTA_STORE_DRIVER`
3. По умолчанию: `sqlite`

## Многомерный

Пул может иметь несколько измерений. Каждое измерение независимо:

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // global pool ceiling for this dimension
}
```

**Пример: план Codex** (5ч% + еженедельно%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

Чтобы запрос был разрешен, он должен удовлетворять всем размерам.

### Процентные измерения: атрибуция по ключу

Процентный план сообщает об одном показателе использования для каждой учетной записи и окна плана. Провайдер не предоставляет счетчиков для каждого ключа API.

Чтобы разделить эту цифру между ключами, каждый пул ведет книгу атрибуции для каждой учетной записи и окна плана. `src/lib/quota/percentLedger.ts` придерживается правил книги. `src/lib/quota/percentAttribution.ts` превращает книгу в цифры, которые используют правоохранительные органы. Результатом является оценка, построенная на основе токенов каждого ключевого маршрута.

#### Чтения, которые трогают книгу

Книга перемещается только по собственной фигуре провайдера для запрошенного окна плана. Эти соединения сообщают об одном:

| Поставщик                      | Планирование окон |
| ------------------------------ | ----------------- |
| Claude, через соединение OAuth | `5h`, `weekly`    |
| Codex                          | `5h`, `weekly`    |

Они не считаются чтением:

- ответ, который клиент провайдера помечает как устаревший
- окно Claude процент которого провайдер не сообщил
- фигура другого окна или, в худшем случае, для всех окон
- резервный заголовок ограничения скорости
- неудачное чтение

У других провайдеров, в том числе Claude с ключом API, книги нет. Как и до этого изменения, с каждого ключа взимается 0 процентов в процентах.

Чтение использует 30-секундный кэш сигнала насыщения. Чтение Claude датируется моментом, когда фигура наблюдалась в заголовках ответа или считывалась из конечной точки использования, когда это время известно. Другие показания датированы временем создания этой записи в кэше.

#### Что хранит книга

Каждый записанный запрос добавляет свои токены один раз к счетчику для каждого пула, учетной записи и ключа. Счетчик только растет. В книге есть три вещи:

- базовая линия: цифра, когда книга открывалась или окно в последний раз поворачивалось
- последняя примененная цифра
- для каждого ключа, его счетчик токенов в тот же момент, называемый его меткой

Книга обновляется, когда принудительное применение или маршрут использования вычисляет атрибуцию. Записи сравниваются и устанавливаются по номеру версии. Писатель, который теряет повторные попытки при новом чтении.

#### Как вычисляется часть ключа

Часть каждого ключа вычисляется при чтении книги. Рост числа с момента базовой линии делится между ключами пропорционально токенам, каждый из которых маршрутизируется с момента его отметки.

Together эти токены объясняют не более одной точки цифры на каждый токен `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` (по умолчанию 1000). Рост, который они не объясняют, является внешним. Базовая линия также является внешней.

Например, книга открывается с 0. Затем ключ A маршрутизирует 900 000 жетонов, а ключ B — 100 000. При цифре 60 доля А равна 54 очкам, а доля Б — 6.

Счетчик ниже отметки ключа перезапустился и считает полностью. Ключ без метки, например ключ, который присоединяется к пулу в середине окна, подсчитывает все свои токены. Число, отстающее от токенов, вызывает ошибку, которая исчезает при следующем чтении. Он не накапливается.

`QUOTA_PERCENT_MIN_TOKENS_PER_POINT` читается при каждой атрибуции. Значение, которое не является конечным числом, равным хотя бы 1, возвращается к 1000.

#### Как чтение меняет книгу

Применяется первое правило соответствия:

1. **Книги пока нет:** чтение открывает книгу. Его фигура является базовой линией, и каждый счетчик отмечен.
2. **Старое чтение:** показания, датированные ранее последнего примененного, игнорируются. То же относится и к показаниям, время сброса которых более чем на 30 минут раньше сохраненного.
3. **Новое окно провайдера:** время сброса более чем на 30 минут позже сохраненного переворачивает книгу. Фигура становится базовой линией, и каждый счетчик отмечается снова. Ключи без жетона покидают книгу.
4. **Завершенное окно:** сохраненное время сброса, которое не наступает после времени чтения данных, означает, что окно закончилось. Чтение переворачивает книгу, какова бы ни была ее фигура.
5. **Более высокий показатель:** движется только последняя фигура. Базовая линия и отметки остаются.
6. **Та же цифра:** фигура, базовая линия и отметки остаются. Написано только время сброса, которого не хватает книге.
7. **Нижний рисунок:** более низкая цифра никогда не применяется как таковая. Книга переворачивается только тогда, когда три вещи верны. Оно как минимум на две минуты новее последнего примененного показания. Ничто не говорит о том, что окно — то же самое открытое. Это более чем на один пункт ниже.

Окно считается открытым, если сохраняются три вещи. Оба времени сброса известны. Они находятся в 30 минутах друг от друга. Сохраненное еще опережает чтение. Нижняя цифра внутри этого окна ничего не меняет.

Время сброса сохраняется только в том случае, если оно опережает время чтения данных, которое его несет. Более высокое значение сохраняет время сброса показаний, когда оно пригодно для использования, и сохраняет сохраненное в противном случае. Равная цифра записывает время сброса чтения только тогда, когда в книге его нет. Это больше ничего не меняет. Меньшая цифра, которая не поворачивает книгу, не записывает время сброса.

#### Когда книга используется

После чтения книга используется, если только ее сохраненное время сброса не наступает после текущего времени. Этот случай возникает, когда чтение, полученное непосредственно перед сбросом, например, полученное из кэша, наблюдается сразу после него.

Без полезного чтения сохраненная книга используется только до тех пор, пока она все еще может быть книгой текущего окна. Это справедливо в двух случаях:

- время его сброса известно и еще впереди
- у него нет времени сброса, и последнее показание, которое изменило его, датировано не более 15 минутами.

В противном случае ничего не приписывается, как и тогда, когда нет книги. Книга, время сброса которой прошло, никогда не взимается.

#### Правоприменение

Потребление ключа в процентном измерении — это его атрибутивная часть плюс доля внешней части. Внешняя часть сначала использует требования к емкости без выделения (100 минус сумма весов). Только избыток распределяется между ключами по весу.

Это потребление сравнивается со справедливой долей ключа, как и для любого другого измерения. Строгий режим по-прежнему запускается, когда сигнал насыщения достигает `QUOTA_SATURATION_THRESHOLD` (по умолчанию 0,5). Каждое число масштабируется в соответствии с действующим лимитом: лимит на одну учетную запись, умноженный на количество учетных записей в пуле.

Абсолютное ограничение с `capUnit: "percent"` учитывает только часть, присвоенную ключу, масштабируемую таким же образом. Возьмите ограничение на количество аккаунтов в 100 и k аккаунтов. Ограничение N достигается тогда, когда часть ключа в цифре обслуживающего аккаунта достигает N/k баллов. Каждый счет сверяется с отдельной книгой. Например, при наличии двух учетных записей предел в 10 достигается при 5 пунктах показателя одной учетной записи.

Когда хранилище не может быть прочитано, ничего не приписывается, и с каждого ключа в этом измерении взимается 0. Когда запись книги терпит неудачу, при атрибуции используется книга в том виде, в каком она была прочитана. Неудачная запись токена оставляет токены этого запроса вне книги. Ни одна из этих ошибок не блокирует запрос.

В пуле `consent` формула кредитования использует потребление каждого ключа в процентном измерении, как описано выше. Когда поддается другой ключ, книга читается один раз и приписывается каждому ключу. Без полезной книги плата за каждый ключ составляет 0. Ключ с весом затем проходит, а ключ с весом 0 проходит только тогда, когда одалживает другой ключ.

#### Маршрут использования

`GET /api/quota/pools/{id}/usage` сообщает те же цифры с помощью той же функции. Процентное измерение имеет одну запись для каждого соединения пула в `accounts`. Его `consumedTotal` и `perKey` верхнего уровня отражают первую запись.

Маршрут также применяет текущее чтение, поэтому он может продвигать книгу по запросу. `internal + external` может отличаться от `consumedTotal`, когда нет полезных показаний или когда не применяется меньшее значение.

#### Хранение и сохранение

Оба хранилища квот ведут учет. В SQLite автоматическая очистка базы данных, если она включена, удаляет строки, не обновлявшиеся в течение 60 дней. В Redis книги и счетчики соединения с пулом имеют общий ключ. Срок его действия истекает через 60 дней после последней записи токена или изменения книги. Книга, которая не изменяется, не переписывается, поэтому граница устанавливается над самым длинным окном плана. Ручной сброс истории использования также очищает книги SQLite (см. Ограничения).

#### Ограничения

- Весь прирост суммы счета с момента базового уровня делится на токены, маршрутизируемые каждым ключом с тех пор. Когда произошел этот рост, не имеет значения.
- Таким образом, за использование ключей вне OmniRoute взимается плата в пределах, допускаемых их токенами. Это включает в себя использование, выполненное до первого запроса ключа к окну, когда книга уже была открыта.
- Например, внешнее использование поднимает счет на 60 очков при отсутствии ключевых маршрутов. Затем ключ маршрутизирует 30 000 токенов, и цифра достигает 60,6.
- Если книга была открыта до этого использования, часть ключа составляет 30 очков. Он также имеет 7,65 внешнего использования с четырьмя клавишами весом 25.
- Если книга открылась после этого использования, 60 баллов являются базовыми. Часть ключа составляет 0,6 балла и имеет 15 баллов внешнего использования.
- Запрос или посещение маршрута использования открывает книгу. Таким образом, будет ли такое использование считаться базовым, зависит от того, когда книга была открыта.
- При минимальном уровне по умолчанию ключ, который маршрутизирует 60 000 токенов, в то время как внешнее использование повышает счет на 60 баллов, получает все 60 как свою часть.
- При поле в 50 000 своя часть составляет 1,2 очка. Остальные 58,8 являются внешними и взимаются по весу, как и при любом внешнем использовании.
- Установите `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` близкую к стоимости одного балла в вашем плане. Внешнее использование включает в себя трафик на том же аккаунте с ключей вне пула.
- Процентное ограничение применяется в каждом режиме. В ограниченном ключе может быть отказано, пока уровень учетной записи намного ниже порога насыщения.
- Возьмите капу из 10 и 12 очков наружного применения ранее в окне. Ключ, который маршрутизирует 20 000 токенов, затем отклоняется при показателе счета 12,4%.
- Разделение представляет собой оценку по объему токенов. Запрос учитывается как токены приглашения плюс токены завершения. Скидки на кэш и цены на модели не меняют этот счет.
- Запрос, который не заканчивается статусом 200, не записывает токены. Примерами являются поток, который клиент отключает, и ошибка восходящего потока после использования.
- Использование, вызванное таким запросом, взимается с ключей, которые записали токены, в пределах, которые позволяют их токены. Остальное внешнее. Он не движется назад. Ответ, в котором сообщается об отсутствии использования токенов, также не записывает токены.
- Использование текущего запроса может отображаться в другой части активного ключа для всего запроса. Он возвращается назад только тогда, когда запрос заканчивается статусом 200.
- Использование уже в учетной записи при открытии книги считается внешним. Это касается обновления, нового пула и новой учетной записи. Использование в новом окне до первого чтения также считается внешним.
- Каждый ключ начинается со своей весовой доли этого использования после заявления о пропускной способности. С одной учетной записью на 85% и пятью ключами веса 20, каждый начинает с 17 из 20 использованных.
- В пуле с несколькими аккаунтами к суммируемому бюджету применяется показатель обслуживающего аккаунта. В книге это не изменилось.
- Нижнее число внутри окна, которое провайдер сообщает как открытое, не применяется. Время сброса, которое перемещается назад более чем на 30 минут, рассматривается как старое показание.
- В обоих случаях книга сохраняет свое состояние до тех пор, пока не пройдет сохраненное время сброса. После этого книга не заряжается до тех пор, пока ее не прочитают.
- Решением является ручной сброс истории использования (`POST /api/settings/purge-usage-history`). Он очищает книги атрибуции и счетчики их токенов в базе данных SQLite.
- Период `all` очищает каждую книгу и счетчик. Более короткий период сначала очищает книги, не написанные в него. Затем он очищает счетчики, не записанные в нем, а только для соединения с пулом, у которого не осталось книг. Хранимая книга по-прежнему отмечает каждый ключ на своем прилавке.
- Книга, фигура которой не двигалась, не перезаписывается, поэтому более короткий период также может очистить книгу текущего окна. Следующее чтение открывает новую книгу с текущей цифрой.
- Сброс не затрагивает хранилище квот Redis. Там книга заканчивается с окном или истекает через 60 дней после последней записи.
- Когда провайдер не отправляет время сброса, окно, которое сбрасывается и заполняется выше старого значения между двумя показаниями, выглядит как более высокое значение. В книге сохранена старая база и отметки.
- Показания датируются местными часами. Когда он опережает время провайдера или источник сообщает о времени сброса немного раньше, книга может обнаружить эту разницу раньше.
- Рост за этот короткий промежуток времени делится на количество перенаправленных в него токенов. Первое чтение следующего окна исправляет это. Когда перевернутая книга не содержит времени сброса, для этой коррекции требуется меньшее значение, по крайней мере, на две минуты позднее, чем последнее примененное показание.
- Экземпляры, которые используют показания даты магазина Redis со своими собственными часами, поэтому синхронизируйте эти часы. Показания экземпляра, часы которого отстают, выглядят более старыми и игнорируются.
- Если после сохраненного времени сброса не поступает никаких полезных показаний, процентные доли и процентные ограничения для каждого ключа не применяются до тех пор, пока не вернется показания. Без времени сброса это начинается через 15 минут после последнего чтения, изменившего книгу.
- В магазине Redis срок действия книги, простаивающей в течение 60 дней, может истечь между авторским чеком и ее записью. Затем он воссоздается с версией выше 1, что является допустимым состоянием.

## Трубопроводная интеграция

### крюк PRE (`open-sse/handlers/chatCore.ts`)

Запускается перед вышестоящим исполнителем, после проверки подлинности и политики:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → getQuotaStore().peek() per dimension
      → fairShare.decideFairShare()
      → if block → return 429 (buildErrorBody, Hard Rule #12)
      → if allow + deprioritize → set quotaSoftPenalty=true on candidate
  → executor.execute()
```

**Открытие при отказе** : если `enforceQuotaShare` выдает ошибку, запрос разрешается с журналом `pino.warn`. Это предотвращает блокировку всего трафика из-за ошибки механизма квот.

**Когда работоспособность вернется.** Отказ от доли ключа или от потолка пула заканчивается одним из двух предложений в обоих режимах заимствования:

- Окно `percent` : `. The <window> window resets at <time>.` Время — это время сброса, о котором сообщает провайдер.
- Счетная единица: `. Enough <window> usage is expected to clear by <time>.` Время — это верхняя граница скользящего окна, если ключ больше ничего не отправляет.

`<time>` — это момент ISO 8601 в UTC. Тогда отказ влечет за собой `Retry-After`: целые секунды до этого момента плюс одна. Клиент, который ждет так долго, повторяет попытку не позднее, чем через одну секунду после момента. Когда момент неизвестен, отказ не содержит ни предложения, ни заголовка. Абсолютный отказ от ограничения не несет ни того, ни другого. Публичный код остается `quota_share_blocked`.

Отказ от общего доступа не затрагивает общее соединение. Он не устанавливает время восстановления, блокировку модели и сбой прерывателя поставщика, а остальные ключи пула продолжают обслуживаться. Когда каждая цель комбинации отказывается от ключа для своей доли, комбинация без ожидания отвечает на 429. Его ответ содержит подсказку как `Retry-After`. Путь внедрения завершает свой отказ тем же предложением и не отправляет `Retry-After`.

### POST хук (запись потребления)

После успешного ответа:

```
executor returns success
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → getQuotaStore().consume() per dimension
      → fail-open: errors logged as pino.warn, never propagated to client
```

**Дрифт-нота** : если `consume` не дает ответа после ответа, скользящий счетчик занижает значение. Сигнал насыщения от провайдера (например, `anthropic-ratelimit-unified-5h-utilization`) корректирует глобальную оценку при следующем запросе.

### Комбинированный мягкий штраф (`open-sse/services/combo.ts`)

Когда `decision.deprioritize === true`:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // default 0.7
}
```

Штраф применяется после всех других зачетных факторов. Это снижает вероятность автоматического комбинирования выбора насыщенной клавиши без ее жесткой блокировки.

На значке кредитования отображается процент и, если он установлен, срок в UTC с названием зоны. Он определяет крайний срок на момент снимка использования. Истекший или нечитаемый срок отображается как `lending expired`.

## Квота на самообслуживание API (согласие)

`GET /api/v1/me/quota/{provider}` (также обслуживается в `/v1/me/quota/{provider}`) позволяет держателю ключа API читать с помощью своего собственного ключа, какая часть общей подписки принадлежит ему и что его блокирует. Маршрут представляет собой тонкую оболочку над `src/server/selfService/quotaHandler.ts`; представление создается `src/lib/quota/selfView.ts`, а его контракт ответа — `src/shared/schemas/selfQuota.ts` (`SelfQuotaView` в `docs/openapi.yaml`).

### Включение и аутентификация

- Флаг функции `QUOTA_SELF_PANEL`, `false` по умолчанию. Пока он отключен, запрос, достигающий маршрута, получает код 404. При использовании `REQUIRE_API_KEY=true` политика API клиента отклоняет отсутствующий или недействительный ключ с кодом 401 до запуска маршрута, независимо от флага. Запрос без ключа, но с сеансом информационной панели, вошедшим в систему, передает эту политику и получает собственный ответ маршрута. Флаг разрешается, как и любой другой флаг (переопределение панели мониторинга или REST, затем одноименная переменная среды); см [`FEATURE_FLAGS.md`](../reference/FEATURE_FLAGS.md).
- Отображаемое имя каждого пула и метка каждого расписания возвращаются держателям ключей пула точно так, как их написал администратор. Прежде чем включать флажок, убедитесь, что его могут прочитать держатели ключей.
- Ключ читается только из заголовков: `Authorization: Bearer <key>` или `x-api-key: <key>`. Когда отправляются оба, используется первый, который проверяет. Ключ в строке запроса или файл cookie игнорируются. Ключ среды сервера отклонен (401).
- Для ключа требуется область действия `self:usage` (403 без нее).
- Сегмент поставщика обрезается, записывается в нижний регистр и проверяется по `^[a-z0-9][a-z0-9._-]{0,63}$` (в противном случае 400), а затем разрешается через реестр поставщиков, поэтому псевдоним, такой как `cc` считывает пулы `claude`. `claude` и `anthropic` читают одни и те же пулы.

### Что показывает каждая видимость

| Видимость        | Требует                                                                        | Поля                                                                                                                                                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Собственная доля | `self:usage`                                                                   | `pools[]` (ссылка, имя, поставщик, политика, вес, ограничение), `dimensions[].yourShare`, `accounts[]` с `yourShare` (в окне `percent` без `attributed` и `external`), `blocks`, `availableModels`, `expiresAt`, `apiBaseUrl`                                   |
| Уровень аккаунта | `self:usage` + `self:account-quota` и поставщик в `sharedQuotaProviders` ключа | добавляет `dimensions[].total`, `accounts[].dimensions[].account` и `accounts[].modelWindows`, `attributed` и `external` в `yourShare` окна `percent` и `members` в пул с включенным использованием участников (см. [Использование участников](#member-usage) ) |

- `sharedQuotaProviders` — это настройка для каждого ключа (`PUT /api/keys/[id]/self-service`): `null`, значение по умолчанию, означает каждого поставщика, которого достигает ключ; `[]` означает «нет». `accountVisible` каждого пула указывается, какая видимость к нему применяется.
- Панели учетных записей и окна моделей отображаются только для учетных записей, соединение которых может использовать ключ. Если ключ имеет список разрешенных подключений, учетная запись за его пределами сохраняет запись `Account N` без `account` или `modelWindows`. Пустой список означает отсутствие ограничений, как и в случае с `/v1/me/status`. Общая сумма пула (`dimensions[].total`) не зависит от этого списка.
- Две цифры, показанные только с помощью `self:usage` связаны с использованием других ключей. `exhausted` бюджета расписания отражает потребление каждого ключа в рамках этого расписания. В пуле, все веса которого равны нулю, `weight` ключа равен `100 / number of members`. И то, и другое относится к ключу.
- Пул идентифицируется только `ref`— непрозрачным значением, привязанным к вызывающему ключу. Его отображаемое имя (`name`) включено в том виде, в котором его написал администратор. `ref` получается из ключа и пула с секретным ключом API сервера (`API_KEY_SECRET`). Клиенты не должны сохранять его: он меняется, если этот секрет меняется.
- Учетные записи перечислены как `Account 1`, `Account 2`, … в порядке пула. Идентификатор пула, идентификатор соединения, адрес электронной почты или имя учетной записи не возвращаются, а ответ проходит через схему контракта, которая удаляет все поля за ее пределами.
- Счетные единицы (`requests`, `tokens`, `usd`) сообщаются как сегмент пула, который обеспечивает ограничение квоты: `limit` = плановый лимит учетных записей × в пуле, `fairShare` = вес / 100 × `limit` (равное разделение, когда каждый вес равен 0), `consumed` = собственный счетчик ключа в хранилище квот, `remaining` = `fairShare` − `consumed`, нижний предел 0.
- `blocks.schedules` перечисляет окна расписания ключа (`open`/`closed`, `blackout` или `outside-window`, `retryAfterSeconds`, резервные уровни и израсходован ли бюджет окна); `blocks.modelCaps` перечисляет почасовые ограничения для каждой модели с учетом потребления.
- Ключ вне каждого пула провайдера получает 200 с помощью `pools: []`; `availableModels` (идентификаторы `qtSd/`, которые ключ видит в `/v1/models`), `expiresAt` и `apiBaseUrl` все еще заполнены.
- `apiBaseUrl` это `OMNIROUTE_PUBLIC_API_BASE_URL`, затем `OMNIROUTE_PUBLIC_BASE_URL`, иначе `null`. Это никогда не является источником самого запроса.

### Согласие на кредитование

`PATCH /api/v1/me/quota/{provider}` записывает собственное согласие вызывающего ключа для одного пула. Он использует флаг, заголовки и правила провайдера `GET`. Область `self:usage` разрешает эту запись, хотя ее имя читается как доступное только для чтения.

```json
{
  "pool": "qpr_0123456789abcdef0123456789abcdef",
  "lendingPercent": 30,
  "lendingUntil": 1893456000000
}
```

- `pool` — это `ref` который `GET` возвращает для этого пула.
- `lendingPercent` — целое число от 0 до 100. Значение 0 отменяет согласие и срок его действия. Тело с `lendingPercent` 0 принимается в любом режиме.
- `lendingUntil` не является обязательным: эпоха в миллисекундах или `null`, если срок не указан. Оно должно быть в будущем и не более 8640000000000000. Значение ниже 100000000000 читается как секунды и отклоняется.
- Любое другое поле отклонено. Тело длиной более 4096 байт отклоняется. Чтение останавливается на этом размере, поэтому более длинное тело никогда не остается целым.

Проверки выполняются в порядке, указанном в этой таблице. При каждом отказе используется стандартное тело ошибки с фиксированным сообщением. Отказ по одной из этих проверок ничего не записывает.

| Статус | Сообщение                                                                                          | Когда                                                                       |
| ------ | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 404    | `Not found`                                                                                        | Флаг `QUOTA_SELF_PANEL` выключен.                                           |
| 401    | `Valid API key required`                                                                           | Ключ отсутствует, недействителен или является ключом среды сервера.         |
| 403    | `API key lacks the self:usage scope`                                                               | В ключе отсутствует `self:usage`.                                           |
| 400    | `Invalid provider`                                                                                 | Сегмент поставщика недействителен.                                          |
| 429    | `Too many lending changes. Retry later.`                                                           | Ключ превысил свой предел. Ответ несет `Retry-After`.                       |
| 400    | `Body must be { pool, lendingPercent, lendingUntil }. lendingPercent is an integer from 0 to 100.` | Тело не соответствует JSON, оно слишком длинное или не соответствует схеме. |
| 400    | `lendingUntil must be a Unix time in milliseconds`                                                 | Срок указывается в секундах.                                                |
| 400    | `lendingUntil must be in the future`                                                               | Крайний срок совпадает с временем запроса или раньше.                       |
| 404    | `Pool not found`                                                                                   | `ref` не называет пула этого ключа для этого провайдера.                    |
| 403    | `Lending is not enabled for this pool`                                                             | Пул находится в режиме `saturation`, а `lendingPercent` выше 0.             |
| 500    | `Failed to build quota view`                                                                       | Любая другая неудача. Его причина регистрируется на сервере.                |

Ограничение — 20 запросов за 60 секунд для каждого ключа. Засчитывается каждый запрос, прошедший проверку провайдера, даже тот, который был отклонен позже или который ничего не меняет. Он имеет свой собственный счетчик, помимо ограничения скорости запроса ключа.

Запрос, изменяющий сохраненное согласие, записывает одну запись аудита `quota.pool.lending.updated`. Он называет ключ старым и новым значениями. Одно и то же тело, отправленное дважды, один раз пишет и один раз проверяет. Ответ — 200 с полным представлением `GET`, построенным после записи.

Представление `GET` сообщает о кредитовании следующим образом:

- Каждый пул содержит `borrowMode` (`saturation` или `consent`), а также собственные `lendingPercent` и `lendingUntil` ключа.
- `lendingActive` это `true` только в пуле `consent`, с процентом выше 0 и крайним сроком, который не достигнут.
- В пуле `consent` каждый счетный `dimensions[].yourShare` содержит `borrowAvailable`. Это то, что ключ теперь может использовать сверх своей доли, предоставленной другими ключами.
- `borrowAvailable` использует формулу ворот. Он считывает все остальные ключи, даже если ключ находится под его общим ресурсом. Для ключа `hard` это одно дополнительное чтение на каждый другой ключ и счетное измерение параллельно.
- `borrowAvailable` это `null` для ключа `soft` или `burst`, а `null` в случае сбоя чтения.
- `borrowAvailable` — это одна цифра для всех остальных ключей вместе взятых. В наборе из двух ключей это фигурка другого ключа.
- `borrowAvailable` пока не сообщается ни для `percent` windows, ни для `accounts[]`.
- В пуле `saturation` представление сообщает о сохраненном согласии с `lendingActive: false` и без `borrowAvailable`.

### Ошибки

Каждый ответ этого маршрута, успешный или ошибочный, несет в себе `Cache-Control: no-store`. Отказ, который происходит до запуска маршрута, не переносит его, например, 401 политики API клиента или 403 фильтра IP. При ошибках маршрута используется стандартное тело ошибки с фиксированным сообщением: 400 (неверный поставщик), 401 (отсутствует или неверный ключ), 403 (отсутствует `self:usage`), 404 (флаг снят) и 500 (`Failed to build quota view`). 500 покрывает любой сбой после того, как запрос достигнет маршрута, включая сам поиск ключа; его причина регистрируется на сервере и никогда не возвращается. Ошибки `PATCH` перечислены в [Согласии на кредитование](#lending-consent).

### Ограничения

- `remaining` — это часть справедливой доли ключа, которую он не использовал. Это не гарантия. За ним можно подать ключ, пока в бассейне есть место. Как только общая сумма пула достигнет `limit`, каждый ключ пула будет отклонен, независимо от его собственного `remaining`, и ключ без `self:account-quota` не сможет увидеть эту сумму.
- `remaining` не учитывает абсолютный `cap` распределения. Принудительное исполнение отказывает в ключе, как только его собственное потребление в окне единицы ограничения достигает значения ограничения.
- Панель уровня учетной записи берется из кеша ограничений поставщика и может запаздывать на несколько минут при принятии решения о принудительном исполнении. Показания, время сброса которых прошло, сообщаются как `stale`.
- Окна для каждой модели (`modelWindows`) сообщаются только для поставщиков, у которых есть сопоставление окна плана: Claude и Codex сегодня. Для других провайдеров `modelWindows` по-прежнему присутствует, когда отображаются данные учетной записи, с пустым списком `windows`.
- Доля ключа в окне `percent` является приблизительной. Он взят из книги атрибуции и содержит все ограничения, перечисленные выше в разделе «Процентные измерения: атрибуция по ключам».
- `consumed` — это количество, которое принудительное исполнение сравнивает со справедливой долей. Точнее, это `attributed` плюс `external`. `attributed` — это часть, которую книга дает ключу для маршрутизируемых ею токенов. `external` — это часть ключа, используемая учетной записью, которая не учитывается ключами пула.
- Обе части отправляются только в том случае, если `accountVisible` пула имеет значение true: ключ имеет `self:account-quota`, а поставщик находится в его `sharedQuotaProviders`. Ключ без него получает только `consumed` с теми же `status` и `reason`.
- Используя как детали, так и собственный вес, держатель может рассчитывать использование за пределами бассейна, которое оплачивается ключами от бассейна. Владелец с объемом счета уже видит общую сумму счета.
- Ключ, который ничего не маршрутизировал в окне, все равно может считывать свой внешний заряд из `consumed`, поскольку его атрибутированная часть тогда равна 0.
- Например, книга открывается при 0, с ключами A и B весом 50 каждый. Ключ A маршрутизирует 900 000 токенов, а ключ B — 100 000. Затем счет достигает 60% от лимита в 100. Тогда `attributed` равен 54 для ключа A и 6 для ключа B, а `external` равен 0 для обоих.
- Представление читает книгу и никогда не записывает свое состояние. Он не открывает книгу и никогда не запрашивает у провайдера чтение. В хранилище Redis чтение удаляет замененные поля ревизий в фоновом режиме, как это происходит при чтении шлюза.
- Доля равна `ok` только до тех пор, пока кэш шлюза сохраняет чтение учетной записи. Без него это `stale`, поэтому в пуле без недавних запросов он отображается как возможно устаревший.
- Пока запрос не пройдет через пул, общий ресурс недоступен. Этот запрос открывает книгу, и сумма счета в этот момент засчитывается как использование, выполненное за пределами пула.
- В пуле с несколькими учетными записями каждая запись учетной записи использует собственную книгу этой учетной записи и ограничение в одну учетную запись. Правоприменение масштабирует обе стороны по количеству аккаунтов, поэтому пропорция одинакова.
- Окна для каждой модели не имеют общего ключа. В книге не хранятся данные по каждой модели.
- Резервные этажи расписания не оцениваются представлением: расписание может отображаться как `open` в то время как запрос отклонен по причине `schedule-reserve`.
- Когда два пула с одним и тем же ключом используют одно и то же соединение, принудительное применение применяется к одному из них, а в представлении отображаются оба.
- Ограничения на количество неудачных попыток ключа не существует: за обратным прокси-сервером вызывающие абоненты могут использовать один адрес (это зависит от того, являются ли перенаправленные клиентские адреса доверенными), поэтому блокировка может запретить маршрут каждому держателю ключа. При использовании `REQUIRE_API_KEY=true` неверный ключ отклоняется политикой API клиента до запуска маршрута, с телом 401 этой политики вместо тела этого маршрута.

### Использование участника

Администратор может позволить владельцам ключей видеть, как использование окна распределяется между участниками пула. Опция — `memberBreakdown` пула, по умолчанию отключена. Он устанавливается в мастере пула или с помощью `PATCH /api/quota/pools/{id}`. `GET /api/quota/pools` и `GET /api/quota/pools/{id}` сообщают об этом.

Измерение представления несет `members` только тогда, когда выполняются все следующие условия:

- опция бассейна включена
- в пуле имеется не более 20 выделенных ключей, и как минимум три из них могут отправлять запросы: активные, не отозванные, не забаненные и не просроченные.
- `accountVisible` пула верен: ключ имеет `self:account-quota`, а провайдер находится в его `sharedQuotaProviders`
- в окне `percent` соединение с учетной записью может использоваться ключом
- была прочитана доля ключа этого окна: его `status` не `unavailable`

В противном случае `members` отсутствует. Это никогда не пустой список.

- Каждый срез равен `{ slot, consumed, isYou }`. Схема ответа отклоняет любое другое свойство среза и список из более чем 20 срезов. Срезы перечислены в порядке слотов.
- На каждый выделенный ключ приходится один фрагмент, включая ключ, который больше не может отправлять запросы. Неиспользуемый член показывает настоящий ноль.
- Слот 1 всегда является ключом запроса, `isYou` true. Остальные номера слотов представляют собой ранги хеша с ключом. Он имеет ключ `API_KEY_SECRET` и охватывает пул, запрашивающий ключ и члена.
- Таким образом, числа не совпадают между держателями. Для одного владельца они остаются неизменными между посещениями. Они могут меняться, когда ключ присоединяется к пулу или покидает его, а также при ротации этого секрета.
- В счетном окне срез — это счетчик участника в хранилище квот, тот же счетчик, что и его собственный `consumed`.
- В окне `percent` срез — это часть `attributed` члена из той же книги, которая читается как собственный общий ресурс ключа. Использование вне пула никогда не разбивается на части. Этот заряд разделен по весу, поэтому на срезах, которые его несли, будет указан вес.
- Каждое представление параллельно считывает одно значение для каждого члена и счетного окна. В окне `percent` фрагменты не требуют чтения, кроме чтения собственной книги общего ресурса. Когда одно значение не может быть прочитано, это окно не имеет `members` и собственная доля ключа остается.
- Опция и количество используемых ключей считываются один раз для каждого пула и только для ключа, который может видеть данные учетной записи. Неудачное чтение опции или количества используемых ключей отключает полосы для этого пула. Сервер регистрирует предупреждение, а остальная часть представления строится.

Бары не имеют имен или идентификаторов. Они по-прежнему рассказывают ключнику кое-что о других участниках:

- Держатели по-прежнему могут сопоставлять фрагменты по их значениям.
- Стабильная нумерация позволяет держателю следить за одним участником с течением времени.
- Количество срезов показывает, сколько ключей выделено в пуле.
- В пуле из трех ключей тот, кто знает, какой ключ использовался последним, может сказать, какой ключ использовался последним.
- Когда уровень пула падает ниже трех пригодных для использования ключей, полоски исчезают. Просмотры, сделанные ранее, по-прежнему показывают, что использовал каждый участник.
- В счетном окне общая сумма пула за вычетом срезов может показать использование ключей, которые больше не выделяются.
- Участник, который показывает ноль в одной учетной записи и использует в другой, может показать, какой участник какую учетную запись использует.
- В счетном пуле с политикой `hard` часть, которая перестает расти при справедливой доле участника, намекает на вес этого участника.

### Серия использования (`GET /api/v1/me/usage`)

`GET /api/v1/me/usage?range=<range>` (также обслуживается в `/v1/me/usage`) возвращает использование и стоимость собственных запросов вызывающего ключа: итоговые значения, одну запись за день UTC, за день и модель, за модель и за поставщика. Он разделяет флаг, правила аутентификации, область `self:usage`, `Cache-Control: no-store` и поведение при ошибках маршрута квоты, описанного выше. Ключ проверяется перед `range`. Ошибки: 400 (`Invalid range`), 401, 403, 404 и 500 (`Failed to build usage`).

- `range` — это один из `1d`, `7d`, `30d` (по умолчанию) или `90d`. Любое другое значение, пустое значение или повторяющийся параметр — это 400. Набор останавливается на `90d`, чтобы ограничить стоимость вызова. Представление считывает только необработанную историю использования, а не ежедневные сводки, которые не содержат ключа.
- Строки выбираются по идентификатору вызывающего ключа. Столбец имени ключа никогда не сопоставляется, а строки, записанные без идентификатора ключа, никогда не учитываются.
- При построении серии выполняется пять сгруппированных запросов к строкам ключа в окне. Построенная серия повторно используется в течение 60 секунд для каждого ключа и диапазона, а повторно используемый вызов не выполняется. Его `generatedAt` дает его возраст.
- Окно заканчивается, когда серия построена. Строка, проставленная позже, например, из-за перекоса часов, не учитывается.
- `coverage.retentionDays` — это необработанная настройка хранения истории использования оператора (`retention.usageHistory` в настройках базы данных). `coverage.truncatedByRetention` имеет значение true, если запрошенный диапазон длиннее этого параметра. Он сравнивает два числа и не проверяет, действительно ли отсутствуют строки.
- Поставщик возвращается в том виде, в котором он записан для собственных запросов ключа. Модель — это записанное имя после последнего `/`, по которому группируются строки. Комбинированный запрос, каждая цель которого была отклонена, записывается с меткой маршрутизации в качестве поставщика (имя комбинации, `auto` или `combo`) и строкой модели, отправленной клиентом. Другие отклоненные запросы, например, из-за размыкания цепи, перезарядки модели или пропуска при парковке по квоте, сохраняют целевого поставщика и модель.
- Помимо количества и затрат, ответ содержит среднюю задержку, показатели успеха и время первого и последнего запроса.
- `byModel` перечисляет 50 пар «провайдер-модель» с наибольшим количеством запросов. При большем количестве пар его записи не суммируются с `summary`, и `summary.uniqueModels` учитывает каждое записанное написание модели. Тогда `byModelTruncated` истинно, и модель, пары которой попадают по обе стороны от разреза, показывает частичные итоги.
- Сообщается о двух расходах. `costUsd` — это выставленная в счет стоимость, как показывает аналитика использования. Поставщики подписок с фиксированной ставкой, такие как план Claude Code, считают там 0 долларов. `listPriceUsd` — это то же использование по прейскурантной цене, включая подписки. Запрос, в модели которого нет строки цены, подсчитывает сохраненную стоимость: стоимость, о которой сообщил поставщик, или сумму, рассчитанную при записи запроса. Только запрос без ни одного из них считается 0, без маркера, поэтому итоговая сумма может быть частичной.
- Контракт ответа — `src/shared/schemas/selfUsage.ts` (`SelfUsageSeries` в `docs/openapi.yaml`).

### Страница самообслуживания

Если `QUOTA_SELF_PANEL` включена, `/quota/{provider}` становится общедоступной страницей. Владелец ключа вводит там ключ API и видит пулы этих ключей для провайдера. В каждом пуле отображается одна карта в каждом окне пула, с указанием использования пула всеми и долей ключа. Каждый аккаунт пула имеет свои карты с указанием использования аккаунта и доли ключа. Использование аккаунта появляется только тогда, когда ключ может видеть данные аккаунта. На странице также перечислены ограничения для каждой модели для каждой учетной записи и использование собственного ключа. Уведомление появляется, когда расписание блокирует ключ прямо сейчас. На карточке перечислены все ограничения ключа для каждой модели с его использованием и отмечены достигнутые значения. `{provider}` — идентификатор провайдера или его псевдоним (`/quota/claude`, `/quota/cc`). Неизвестный провайдер и каждый путь `/quota/*`, пока флаг выключен, отвечают 404. Пулы на пользовательском узле, совместимом с OpenAI или Anthropic, не имеют страницы. API по-прежнему отвечает за них.

На странице нет сеанса. Ключ отправляется только в заголовке `Authorization` `GET /api/v1/me/quota/{provider}`, `PATCH /api/v1/me/quota/{provider}` и `GET /api/v1/me/usage`, но не в URL. Ключ, который принимает сервер, хранится в `sessionStorage` вкладки. При выборе «Запомнить на этом устройстве» он сохраняется в `localStorage`, а «Забыть ключ» удаляет его из обоих. Ключ, отклоненный сервером, удаляется из хранилища.

Пул в режиме `consent` показывает кредитную карту. Там держатель ключа устанавливает целый процент от 0 до 100 от незадействованной доли ключа для предоставления в долг. Владелец также выбирает, как долго будет действовать согласие: до отключения, 1 час, 8 часов, 24 часа, 7 дней или 30 дней. Продолжительность отсчитывается с момента сохранения. Пока срок остается в силе, держатель может вместо этого сохранить его. Если этот срок пройдет до момента сохранения, карта ничего не отправляет и запрашивает другой выбор. При 0% срок не указывается. На карточке отображается сохраненный крайний срок с указанием часового пояса. Согласие, срок действия которого истек, отображается как истекшее.

Для ключа `hard` на карточке также указано, какие другие ключи предоставляют ключу в данный момент, для каждого окна пула. Каждая строка представляет собой одну цифру для всех остальных ключей вместе взятых. В наборе из двух ключей это фигурка другого ключа. Цифра, о которой представление не сообщает, читается как недоступная, а не равна нулю. Для ключа `soft` или `burst` на карте указано, что никакие цифры не применяются.

Пул в режиме `saturation`, ключ которого хранит процент выше 0, показывает только вывод средств. Там написано, что сохраненный процент там не действует. Кнопка вывода средств отправляет 0 без указания крайнего срока. Пул в режиме `saturation` с сохраненным значением 0 не отображает кредитную карту. После сохранения карточка, которая больше не нужна возвращенному представлению, остается со своим сообщением до тех пор, пока представление страницы снова не изменится.

Ничего не сохраняется до тех пор, пока владелец не нажмет «Сохранить» или «Снять». При каждом нажатии отправляется один запрос `PATCH /api/v1/me/quota/{provider}`, а при втором нажатии ничего не отправляется, пока первое нажатие находится на рассмотрении. Тело содержит непрозрачный `ref` пула, основанный на представлении, проценте и крайнем сроке. Ответом является перестроенное представление квоты, и страница показывает его без повторного чтения. Если два сохранения перекрываются, страница считывает квоту один раз после последнего ответа. Страница не сохраняет согласие в хранилище браузера.

Отказ в изменении объясняется на карте текстом, выбранным из статуса HTTP. Тело ошибки не читается. Ошибка 401 сообщает, что ключ не принят, и квота перезагружается. 403 говорит, что пул не принимает изменений в кредитовании, а 404 говорит, что пул исчез. Оба предлагают кнопку, которая перезагружает квоту. Ответ 400 или другой 4xx просит владельца проверить процент и срок. Номер 429 просит держателя подождать с секундами `Retry-After`, когда им дадут ответ. Ответ 5xx, 408 или сбой сети говорят о том, что изменение, возможно, не было сохранено, и сохраняют введенные значения. Ответ вне контракта перезагружает квоту. Неудачное сохранение не удаляет ключ сам по себе. При перезагрузке после отказа страница удаляет ключ, как и при любом отказе в чтении.

После принятия ключа на странице также отображается карточка «Настройка инструментов» с тремя вкладками. «Claude Code» дает блок `env` для `~/.claude/settings.json`. «Shell» предоставляет те же переменные, что и строки `export`. «Claude Desktop» предоставляет значения для своего стороннего окна вывода. Модели представляют собой модели распределения квот, которые ключ может вызвать для этого поставщика. Если такого списка с ключом нет, блок вместо этого включает обнаружение модели шлюза. Адрес шлюза — это общедоступный источник API, о котором сообщает сервер (`OMNIROUTE_PUBLIC_API_BASE_URL`, затем `OMNIROUTE_PUBLIC_BASE_URL`). Если ни один из них не установлен, на карточке отображается заполнитель и предлагается владельцу обратиться к администратору. Ключ отображается в виде заполнителя. «Включить мой ключ» помещает весь ключ в текст на экране и в то, что копирует кнопка копирования. Это продолжается до тех пор, пока ящик не будет очищен, ключ не забыт или не заменен или страница не будет оставлена. Карта не отправляет запросы и не предлагает загрузку файлов.

Чтение отметки API `stale` показано как возможно устаревшее. Показание, которое он отмечает `unavailable` отображается с указанием причины, а не как ноль.

В процентных планах страница рисует собственную долю ключа, когда API сообщает об этом. Там говорится, что число является приблизительным, и называются две его части. Ограничения для каждой модели показывают только учетную запись.

Когда окно содержит `members`, на его карточке также отображается полоса с одним сегментом на каждого члена в порядке слотов. В сегменте запрашивающей клавиши используется акцентный цвет. Другие сегменты циклически меняют цвета диаграммы темы. В текстовой легенде каждый сегмент указан с его значением, поэтому от цвета ничего не зависит. Сегменты обозначаются `You` или `Member N`, где N — слот.

### Выделенный порт для страницы

`QUOTA_PANEL_PORT` открывает второй прослушиватель, который обслуживает только страницу самообслуживания. Он выключен, если переменная не установлена. `QUOTA_PANEL_HOST` — это адрес привязки, по умолчанию он равен `127.0.0.1`.

Прослушиватель передает эти пути на основной порт и отвечает 404 на каждый другой путь:

| Путь                                                                     | Служит                                       |
| ------------------------------------------------------------------------ | -------------------------------------------- |
| `/quota/{provider}`                                                      | Страница                                     |
| `/api/v1/me/quota/{provider}`, `/v1/me/quota/{provider}`                 | Квота на просмотр страницы читается          |
| `/api/v1/me/usage`, `/v1/me/usage`                                       | Серия использования, которую читает страница |
| `/_next/static/`                                                         | Скрипты, стили и шрифты сборки               |
| `/favicon.ico`, `/favicon.svg`, `/icon-512.png`, `/apple-touch-icon.png` | Иконки                                       |

`GET` и `HEAD` передаются без тела. Также передается один запрос с телом: `PATCH` пути просмотра квоты, который страница отправляет для сохранения выбора кредитования. Любой другой метод отвечает на ошибку 404, кроме запроса CONNECT, соединение с которым закрывается без ответа. Любой другой запрос, в котором объявляется, что тело отвечает 404, и его соединение закрывается. Запросы на обновление отклоняются, и их соединение закрывается. Путь с точечным сегментом или маркером фрагмента отклоняется, как и на порту API. То же самое относится и к цели запроса с символом вне печатного ASCII. Необработанный управляющий символ в цели получает ответ 400 от анализатора HTTP перед собственной проверкой этого порта. Заголовки запросов, которые платформа резервирует для собственного использования, не передаются: имена, начинающиеся с `x-middleware-`, `x-invoke-`, `x-nextjs-`, `x-now-` или `x-next-`, а также имена `x-matched-path` и `next-resume`. Запрос передается без них. Панель управления, страница входа в систему, API управления и маршруты вывода недоступны через этот порт.

`PATCH` должен содержать `Content-Type: application/json` без параметров или только с `charset=utf-8`. Он должен содержать один `Content-Length` от 1 до 4096, записанный простыми цифрами, без `Transfer-Encoding`. `PATCH`, который нарушает одно из этих правил, отвечает 404. На некоторые неверные длины, такие как знаковая или повторяющаяся, анализатор HTTP отвечает 400 перед собственной проверкой этого порта. Порт считывает объявленные байты перед тем, как связаться с основным портом, и ожидает их не более 5 секунд. Тело, которое к тому времени не завершено, отвечает на 404, и его соединение закрывается. Ничто не достигает основного порта в этом случае или когда клиент уходит первым. Порт передает именно заявленные байты с тем же `Content-Length`. Байты после них читаются как следующий запрос на соединение. Обратный прокси-сервер TLS впереди должен пересылать `Content-Length` и не должен повторно разбивать тело запроса. Основной порт проверяет ключ API в заголовке `Authorization`, как и для `GET`.

Тело 404 — `{"error":"not_found","message":"Not found."}`. Неисправное реле отвечает на номер 502 (`api_bridge_unavailable`) или 504 (`api_bridge_timeout`) без поля `detail`.

Слушатель не читает `QUOTA_SELF_PANEL` и не включает страницу. Пока флаг выключен, страница и ее API отвечают на 404 на главном порту, и прослушиватель ретранслирует этот ответ.

На сервере разработки (`next dev`) страница не становится интерактивной через этот порт. Сокет горячей перезагрузки разработки — это запрос на обновление, и порт отклоняет его. Используйте основной порт во время разработки.

Порт обслуживает обычный HTTP, а страница отправляет ключи API. Сохраните адрес привязки по умолчанию и поместите перед ним обратный прокси-сервер с TLS. Адрес привязки, отличный от адреса обратной связи, регистрирует это уведомление:

```text
[Quota Panel] Bound to <host>. This port serves plain HTTP and the page sends API keys. Put a TLS reverse proxy in front of it.
```

Узел обратной связи, который не отправляет заголовок пересылки, считается локальным на основном порту. Таким образом, прокси-сервер на том же хосте должен отправлять `X-Forwarded-For`. Прокси-серверу на частном адресе доверяют этот заголовок только с помощью `OMNIROUTE_TRUST_PROXY=private` (или `lan`). О любом другом узле сообщается по адресу его соединения, а отправленные им заголовки пересылки отбрасываются.

Слушатель поддерживает не более 256 соединений одновременно. У клиента есть 10 секунд на отправку заголовков запроса и 30 секунд на отправку всего запроса. Неактивное поддерживаемое соединение закрывается примерно через 5 секунд. Соединение, при котором в течение 60 секунд не было активности, закрывается. Эти значения фиксированы. Также установите ограничения на подключение и скорость на обратном прокси-сервере спереди. Передний обратный прокси-сервер должен сохранять бездействующие восходящие соединения менее 5 секунд или не использовать их повторно. Реле к основному порту использует тайм-ауты восходящего канала порта API (`API_BRIDGE_*`).

Прослушиватель также запускается, когда `API_PORT` не установлен. `QUOTA_PANEL_PORT` должен быть портом от 1 до 65535, записанным только цифрами. Он должен отличаться от порта приборной панели и порта API. Пока работающий сервер WebSocket включен, он также должен отличаться от `LIVE_WS_PORT` (по умолчанию 20132). Любое другое значение ничего не открывает и регистрирует предупреждение. Предупреждение об отклоненном значении дает имя переменной и не повторяет значение. Порт, который уже используется, ничего не открывает и записывает это предупреждение:

```text
[Quota Panel] Port <port> is already in use. The quota panel port stays off.
```

Если установлен `OMNIROUTE_BASE_PATH`, прослушиватель ожидает каждый путь, указанный выше, под этим префиксом. Используйте один и тот же `OMNIROUTE_BASE_PATH` во время сборки и во время выполнения. Пишите его с косой чертой в начале и без косой черты в конце, например `/omniroute`. Другая форма, включая `/` и `/omniroute/`, оставляет порт отключенным с предупреждением, хотя сборка принимает эти формы. То же самое относится и к базовому пути, первый сегмент которого называет маршрут приложения: `api`, `v1`, `v1beta`, `_next`, `quota`, `dashboard`, `docs`, `login`, `codex`, `responses`, `anthropic`, `openai`, `v0` или `connect` в любом случае.

Ограничения:

- `/quota/{provider}/` с косой чертой в конце отвечает на 404 на этом порту.
- Работник службы и манифест веб-приложения не обслуживаются через этот порт.
- Пользовательский значок, установленный на панели управления, не отображается на этом порту.
- Значки не отображаются, когда приложение запускается по базовому пути.
- В порту говорят на простом HTTP/1.1.
- Неудачная привязка не повторяется до перезапуска процесса.
- У прослушивателя нет ограничений на подключение или скорость для каждого адреса клиента.
- Настройки контейнера не рассматриваются в этом разделе.

## Устранение неполадок

### Redis настроен, но подключение не устанавливается

Убедитесь, что `ioredis` установлен (`npm ls ioredis`) и `QUOTA_STORE_REDIS_URL`
доступен. При ошибке подключения фабрика переключается на SQLite (событие записывается
в журнал с уровнем `warn`).

### `peek` возвращает устаревшие данные / работает в режиме fail-open

Если `peek` выбрасывает исключение, `enforceQuotaShare` интерпретирует результат как «разрешить» (fail-open).
Проверьте журналы `pino` на наличие записей `quota:enforce` и `quota:factory`, чтобы определить
первопричину.

### Расхождение счётчика потребления

Если фактическое потребление у провайдера отличается от показаний счётчиков, это ожидаемо:
скользящее окно из 2 сегментов имеет погрешность около 1% на границах окна, а `consume`
выполняется после отправки ответа без ожидания результата. Сигнал насыщения (`saturationSignals.ts`)
считывает фактическую утилизацию провайдера с TTL 30 с и соответствующим образом корректирует `globalUsedPercent`.

### Для скорости расходования пула отображается «нет данных»

Для `computeBurnRate` требуется не менее 2 исторических образцов. Для новых пулов без предыдущих
вызовов `consume` будут отображаться `tokensPerSecond: 0` и `timeToExhaustionMs: null`.

## Миграция из localStorage

При первой загрузке `/dashboard/costs/quota-share` хук `useLocalStoragePoolMigration`
проверяет:

1. `localStorage.getItem("omniroute:quota-share:pools")` не является пустым.
2. `GET /api/quota/pools` возвращает `[]` (БД пуста).

Если оба условия выполняются, хук пакетно отправляет каждый устаревший пул в `POST /api/quota/pools`,
а затем удаляет ключ localStorage. Миграция идемпотентна: условие 2 предотвращает
повторную миграцию.

## Классификация внутренней стратегии

`quota-share` — это стратегия маршрутизации **только для внутреннего использования** (`INTERNAL_ROUTING_STRATEGY_VALUES` в
`src/shared/constants/routingStrategies.ts`). Она используется исключительно системными
комбинациями пулов `qtSd/` и намеренно исключена из `ROUTING_STRATEGY_VALUES`, поэтому никогда
не отображается в UI или API как доступный пользователю вариант.

## Краткое описание схемы DB

Три таблицы, добавленные в результате миграции `078`, `079` и `085`:

- `quota_pools` + `quota_allocations` определения пула — и распределение по ключам.
- `quota_consumption` — скользящие счетчики с двумя сегментами на `(apiKeyId, dimensionKey)`.
- `provider_plans` — переопределяет план поставщика вручную (размеры JSON для каждого connectionId).

Все таблицы добавлены посредством идемпотентной миграции `CREATE TABLE IF NOT EXISTS`.

При предоставлении кредита по согласию добавляются три столбца: `quota_allocations.lending_percent` (целое число, по умолчанию 0), `quota_allocations.lending_until` (миллисекунды эпохи или `NULL` для отсутствия крайнего срока) и `quota_pools.borrow_mode` ( `saturation` по умолчанию). Его миграция только добавляет эти столбцы и не записывает существующие строки.

В книгу процентной атрибуции добавлены `quota_percent_ledger` (одна строка на пул, окно учетной записи и плана) и `quota_percent_ledger_tokens` (один счетчик токенов на пул, учетную запись и ключ API ). `src/lib/db/quotaPercentLedger.ts` читает и записывает их.
