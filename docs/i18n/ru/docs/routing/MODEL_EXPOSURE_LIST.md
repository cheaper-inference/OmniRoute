> Согласен, отключен по умолчанию (оба `modelVisibilityAllowlist`/`modelVisibilityDenylist` пусты, поэтому каталог `/v1/models` AND каждого пула кандидатов `auto/*` байт-идентичн). Родной брат `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`) для операторов, которым нужен тщательно подобранный список моделей по причинам, не имеющим ничего общего со стоимостью.

## Почему это существует

`hidePaidModels` отвечает: «Эта модель бесплатна?» и `hideAutoCombos` отвечает: «Должны ли вообще рекламироваться виртуальные идентификаторы `auto/*` ?» — также не позволяет оператору курировать произвольное подмножество моделей (например, представлять именно те модели, которые должен видеть данный клиент Claude Code/ OpenCode, независимо от цен). #11481 добавляет это как две независимые настройки массива строк.

## Настройки

| Ключ                       | Тип        | По умолчанию | Значение                                                                        |
| -------------------------- | ---------- | ------------ | ------------------------------------------------------------------------------- |
| `modelVisibilityDenylist`  | `string[]` | `[]`         | Записи, соответствующие кандидату, скрывают его из пула catalog/candidate.      |
| `modelVisibilityAllowlist` | `string[]` | `[]`         | Если поле не пусто, записи ONLY, соответствующие кандидату, остаются открытыми. |

Оба принимают до 500 записей длиной до 200 символов каждая (проверено Zod в `src/shared/validation/settingsSchemas.ts`). Запись может быть:

- точный идентификатор каталога — `"gpt-4o"` (идентификатор базовой модели) или `"openai/gpt-4o"` (префикс поставщика), или
- шаблон glob с использованием `*`/`?` — например, `"openai/gpt-4*"` или `"anthropic/*"` — разрешенный с помощью того же общего сопоставителя `globToRegex()` (`src/shared/utils/globPattern.ts`), который уже используется в комбинированных сопоставлениях `ModelRoutingSection` для каждой модели и `freeModels.ts::matchesOnlyPaidModels`.

Приоритет: сначала проверяется список запрещенных (запрещенная запись всегда скрыта, даже если она также соответствует списку разрешенных); если список разрешенных не пуст, сохраняются только записи, которым он соответствует.

## Два узких места, а не один

Урок из #6512 (фильтр каталога `hidePaidModels` -only по-прежнему позволяет `auto/*` маршрутизироваться к платной модели, поскольку пул комбинированных кандидатов был создан независимо) применим и здесь. Соответствующий предикат `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`) вызывается из BOTH:

- `src/app/api/v1/models/catalog.ts` — сам список `/v1/models`, в тех же 5 узких точках для каждого источника `shouldHidePaid()` уже шлюзует (статический `PROVIDER_MODELS`, строки синхронизированного поставщика, пользовательские строки, строки с поддержкой псевдонимов, строки управляемого резерва).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — вызывается из `virtualFactory.ts::buildPreparedPool` сразу после эквивалентного вызова `filterPaidOnlyCandidates()`, поэтому запрещенная модель никогда не может быть выбрана в пул кандидатов `auto/*`.

## Что фильтрует NOT

Отражает существующее поведение `hideAutoCombos`: отправлен идентификатор модели** явно** (не через `auto/*` и не обнаруженный в списке каталога) никогда не блокируется при отправке — фильтруется только членство advertisement/candidate-pool. Это не зависит от `hidePaidModels`; оператору может потребоваться курируемый набор по причинам, которые не имеют ничего общего со стоимостью, поэтому оба параметра составляются как независимые фильтры с оператором AND, так же, как существующая композиция с несколькими флагами в `catalog.ts`.

Экспорт настроек (`GET /api/settings/export-json`) включает в себя оба массива дословно, как и любое другое поле настроек — в отличие от фильтра экспорта комбинированных шагов `hidePaidModels`, здесь нет риска повторной гидратации: запрещенный идентификатор, встроенный в экспортируемый комбинированный шаг, является собственным явным выбором маршрутизации оператора, а не чем-то, что должна удалять граница экспорта.

## Объявление только для комбинаций (`exposeCombosOnly`)

Отдельное логическое значение, которое также включается и `false` по умолчанию, для развертываний, где комбинации являются общедоступной поверхностью модели, а поставщики — только серверными компонентами. Когда это `true`, общедоступный список (`GET /v1/models`, `GET /v1` и другие маршруты обнаружения `/v1` построенные на `getUnifiedModelsResponse()`) сохраняет только строки с комбинациями `owned_by: "combo"`: user плюс встроенные комбинации `auto/*` (если `hideAutoCombos` не скрывает их). Он использует тот же тест строк, что и `catalogScope: "combos"` для каждого ключа, а собственные фильтры allow/deny/scope ключа по-прежнему применяются сверху.

Включить это** Настройки → Маршрутизация → Модели Список API** или с помощью `PATCH /api/settings {"exposeCombosOnly": true}`.

Как и в списках выше, он меняет только рекламу:

- явный идентификатор `provider/model` по-прежнему отправляется, а `GET /v1/models/{id}` по-прежнему разрешает его;
- каталог дашбордов (`GET /api/models/catalog`, используемый сборщиками моделей) не сужается;
- он не отражается в пулах кандидатов `auto/*`, поэтому комбинации `auto/*` сохраняют свой полный пул.
