> **Статус:** дашборд построен на **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), завендоренном
> как workspace-пакет `packages/ui-kit` (`@omniroute/ui-kit`; снимок апстрима зафиксирован в
> `packages/ui-kit/UPSTREAM.md` и защищён проверкой `npm run check:ui-kit-snapshot`). Светлая тема — каноническая;
> предпочтение по умолчанию — `system`. Акцентный цвет — Keak lime (`--ci-color-accent`). Inter
> (letter-spacing 0, `--ci-letter-spacing-ui`) — шрифт интерфейса, Instrument Serif — только для крупного
> разреженного дисплейного текста (`.ci-dashboard-display`), IBM Plex Mono — для кода; все шрифты
> размещены локально через импорты `@fontsource/*` в начале `src/app/globals.css`. Каждая иконка — глиф Lucide.

## 1. Где что находится

- **Kit.** `packages/ui-kit/src` — побайтовая копия апстрим-каталога `src/` на коммите, зафиксированном в
  `packages/ui-kit/UPSTREAM.md` (там же записано разрешение лицензии); `PATCHES.md` перечисляет локальные
  патчи (их нет). Кит используется как исходный код, без сборки: `next.config.mjs` транспилирует его, а
  `tsconfig.json` сопоставляет `@omniroute/ui-kit` → `packages/ui-kit/src` и `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` (тот же алиас указан в `vitest.config.ts` и `vitest.mcp.config.ts`). Импортируйте
  компонент кита по его подпути (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), никогда
  через баррель `@omniroute/ui-kit`: баррель подтягивает все компоненты (включая компонент выбора даты)
  в каждый импортирующий модуль. Стили кита подключаются через `src/app/globals.css`
  (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **Токены.** `packages/ui-kit/src/ci-tokens.css` объявляет токены `--ci-*`; `src/app/globals.css`
  связывает их с прежними именами OmniRoute (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`), так что существующие обращения `var(--color-*)` и утилиты
  Tailwind продолжают работать. Новый код использует утилиты Tailwind (`bg-surface`, `text-text-muted`,
  `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) или классы кита — никогда hex-значения
  (`tests/unit/design-kit-bridge.test.ts` проверяет этот мост). `text-primary` разрешается в
  `--color-primary-ink` через `--text-color-primary` (lime-800 в светлой теме, лаймовый акцент в тёмной), так
  что основной текст остаётся читаемым, а `bg-primary`/`border-primary` сохраняют лаймовую поверхность.
  Серии графиков используют `--color-chart-1` … `--color-chart-5`.
- **Темы.** `<html className="ci-theme">` (`src/app/layout.tsx`) подключает документ к теме кита.
  Предпочтение — `light`, `dark` или `system` (`THEME_CONFIG.defaultTheme = "system"` в
  `src/shared/constants/appConfig.ts`; `system` следует за `prefers-color-scheme`). `applyTheme()` в
  `src/store/themeStore.ts` (зеркалируется встроенным загрузочным скриптом в `src/app/layout.tsx`, который
  выполняется до гидратации) одновременно устанавливает `data-theme="dark"|"light"` и переключает класс
  `.dark` на `<html>`. Тёмный набор токенов кита привязан к `data-theme="dark"`
  (`packages/ui-kit/src/ci-tokens.css`); собственные тёмные переопределения OmniRoute (блок `.dark` в
  `globals.css`) и прежние утилиты Tailwind `dark:` привязаны к классу `.dark`. Пресетов акцентного цвета
  нет: акцент всегда берётся из кита, а сохранённый пресет из более старой сборки отбрасывается при загрузке
  хранилища.
- **Компоненты (адаптеры).** `src/shared/components/index.tsx` сохраняет API компонентов OmniRoute (те же
  имена, экспорты по умолчанию и пропсы), а примитивы за ним — адаптеры над китом: формы
  (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), оверлеи и обратная связь
  (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`),
  структура (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) и таблицы
  (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). Адаптер импортирует компонент
  кита по подпути и сопоставляет с ним прежние пропсы — например, `Button variant="primary"` — это кнопка
  кита `default` (`--ci-button-primary-*`: инверсная поверхность в светлой теме, акцент с его цветом текста
  `--ci-color-accent-foreground` в тёмной), `danger` — это `destructive`, а `warning` — это `outline` плюс
  расширение `.ci-button--warning`. Правила `.ci-button--warning` и `.ci-badge[data-tone]` в конце
  `globals.css` (`@layer components`) — это расширения OmniRoute поверх классов кита.
  `tests/unit/ui/adapters/*.test.tsx` фиксируют каждый адаптер.
- **Оболочка.** `src/app/(dashboard)/layout.tsx` рендерит `DashboardLayout`, который рендерит
  `src/shared/components/layouts/DashboardShell.tsx`: `SidebarProvider` / `Sidebar` /
  `SidebarInset` из кита (`packages/ui-kit/src/sidebar.tsx`), с навигационной логикой OmniRoute в
  `src/shared/components/Sidebar.tsx`. Ссылка «перейти к содержимому» на `#main-content` — первый
  фокусируемый элемент. `src/shared/components/Header.tsx` содержит `SidebarTrigger` из кита (единственный
  переключатель сайдбара в оболочке), `ProductSwitcher` от Keak и кнопку вызова командной палитры; он
  показывает заголовок маршрута только пока внутри `#main-content` не смонтирован `PageHeader` кита
  (`.ci-page-header`), поэтому на странице со своим `PageHeader` — только один `h1`.
  `src/shared/components/CommandPalette.tsx` — это `Dialog` из кита.
- **Иконки.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) преобразует имя (словарь
  Material Symbols, который используют экраны) через `ICON_MAP` (`src/shared/constants/iconMap.ts`) в глиф
  Lucide. Шрифт и пакет Material Symbols удалены: имя, отсутствующее в карте, рендерит нейтральный
  глиф-заглушку (`data-icon-missing="true"`) и выводит предупреждение в консоль вне продакшена.
  `npm run gen:icon-map` выводит используемые имена, отсутствующие в карте
  (`tests/unit/icon-map-coverage.test.ts` падает на любом имени без иконки Lucide;
  `tests/unit/icon-map-object-values.test.ts` покрывает имена, хранящиеся в lookup-объектах);
  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` переписывает литеральные спаны
  `<span className="material-symbols-outlined">` на `<Icon>`.
- **Бренд.** `src/shared/components/OmniRouteLogo.tsx` оборачивает кит: экспорт по умолчанию `OmniRouteLogo`
  рендерит `ProductIcon product="omniroute" variant="glyph"` (встроенный SVG, безопасный относительно
  `basePath`), а `OmniRouteLockup` рендерит `ProductLockup product="omniroute"` (доступное имя "Keak
  OmniRoute") или, для white-label-операторов, их собственные `name`/`logoSrc`. Назначения переключателя
  продуктов находятся в `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`,
  `KEAK_ACTIVE_PRODUCT`). Автономные экраны — `src/app/login/page.tsx`, `src/app/status/page.tsx`,
  `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` и
  `src/shared/components/ErrorPageScaffold.tsx` — показывают локап; `tests/unit/brand-pages-static.test.ts`
  охраняет это.

## 2. Правила

1. Токены, никогда литералов. Исключения оставлены намеренно: всегда тёмный терминал консоли и
   `STATUS_HEX` (`src/shared/constants/statusColors.ts`) — зеркало палитры статусов кита с готовыми
   hex-значениями для вызывающего кода, которому нужен буквальный hex. Категориальные палитры больше
   не являются исключением: они построены на пяти chart-токенах кита (`--color-chart-1..5`) через
   `src/shared/utils/categoricalPalette.ts`, а для стратегий маршрутизации — через
   `src/app/(dashboard)/dashboard/combos/strategyPalette.ts`; рёбра ReactFlow и холст оркестрации
   читают зависящие от темы переменные `--orch-status-*` (`src/shared/components/flow/edgeStyles.ts`).
2. Никогда не правьте `packages/ui-kit/src` вручную: синхронизируйтесь через
   `scripts/dev/sync-ui-kit.sh <commit>`; pre-commit-проверка `npm run check:ui-kit-snapshot`
   (`.husky/pre-commit`) падает на любом байте, отличающемся от закреплённого апстрим-коммита (она
   пропускается с предупреждением, когда клон апстрима — `UI_KIT_CLONE` или
   `_references/cheaper-inference-ui-kit` — отсутствует). Когда в ките чего-то не хватает, обойдите
   это в адаптере или на экране и запросите нужное в апстриме.
3. Тексты кита по умолчанию — на английском (`label = "Loading"`, `loadingLabel = "Loading table"`…) —
   передавайте переведённые строки из `useTranslations(...)` всякий раз, когда компонент кита
   рендерит текст.
4. Утилиты Tailwind имеют приоритет над классами компонентов кита (кит объявляет
   `@layer theme, base, components, utilities`, и его правила живут в слое `components`) — используйте
   утилиты для отступов и раскладки, а не для перекраски компонентов кита.
5. Заголовки: `.ci-heading` (Inter, без трекинга) для заголовков страниц и разделов;
   `.ci-dashboard-display` (Instrument Serif) — только для крупного, редкого дисплейного текста,
   такого как код статуса на странице ошибки.
6. `tests/unit/dashboard-kit-sweep.test.ts` охраняет внедрение кита: никаких span с Material-лигатурами
   внутри `src/app` или `src/shared/components`; в дереве дашборда (`src/app/(dashboard)` и
   `src/shared/components`) — никаких сырых `<select>`, `<textarea>` или `<table>` и никаких самописных
   `role="dialog"` вне перечисленных исключений (нативная ветка адаптера `Select`,
   `RequestLoggerDetail`); каждый сырой `<button>` или `<input>` там требует комментария, содержащего
   `kit-exception:` (с причиной), который заканчивается не более чем за 3 строки выше него; оттенки
   палитры и варианты `dark:` — только в файлах, перечисленных в тесте.
7. Проверяйте обе темы и вьюпорт 390 px перед PR (скриншоты); `tests/e2e/a11y.spec.ts` запускает axe.

## 3. Добавление экрана

1. Начинайте страницу с китового `PageHeader` (`@omniroute/ui-kit/page-header`, `compact` внутри
   дашборда) — заголовок, описание и `actions`. Тогда шапка оболочки убирает собственный заголовок.
2. Собирайте элементы управления из `@/shared/components` (адаптеров) и используйте компоненты кита
   по подпутям там, где адаптера нет (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`,
   `Tabs`, `RadioGroup`, `Slider`…).
3. Иконки: `<Icon name="…" />`. Новое имя добавляется в `ICON_MAP` вместе с семантически подходящим
   компонентом Lucide; `npm run gen:icon-map` перечисляет имена, которых всё ещё не хватает.
4. Цвета: семантические утилиты (`text-success`, `bg-warning-bg`, `border-border`…) и
   `var(--color-chart-N)` для рядов графиков; никаких hex-значений и никаких вариантов `dark:`, которые
   лишь повторяют цвет.
5. Текст: каждая строка, включая подписи, которые вы передаёте компонентам кита, берётся из
   `useTranslations`. Новые ключи добавляются в `src/i18n/messages/en.json`, `pt-BR.json` и `vi.json`
   (тест паритета вьетнамской локали фиксирует каждый английский ключ); остальные локали заполняются
   синхронизацией i18n.
6. Запускайте проверки перед PR: `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (единственная проверка, которая отлавливает дублированный импорт
   в `iconMap.ts`), `npm run check:ui-icu` и собственные тесты экрана.

## 4. Добавление или изменение адаптера

1. Сохраняйте публичный API `src/shared/components/index.tsx`: те же имена экспортов, экспорты по умолчанию и принимаемые пропсы. Отображайте устаревшие пропсы на kit внутри адаптера (см. `Button.tsx`: `VARIANT_TO_KIT`, `SIZE_TO_KIT`).
2. Импортируйте kit по подпути (`@omniroute/ui-kit/<component>`).
3. Обходные решения для пробелов kit живут в адаптере (или в `globals.css` `@layer components`, когда исправление касается стиля), никогда — в `packages/ui-kit/src`.
4. Добавьте или обновите `tests/unit/ui/adapters/<name>.test.tsx`. Для адаптера с большим числом вызывающих мест сравните отрисованную разметку до и после изменения — изменения отступов или обёрток распространяются на каждый экран.

## 5. Обновление kit

`scripts/dev/sync-ui-kit.sh <commit> [clone]` копирует апстримовый `src/` на указанном коммите в `packages/ui-kit/src` и применяет единственное разрешённое преобразование (убирает суффикс `.js` у относительных импортов). Затем: просмотрите `git diff packages/ui-kit`, проведите визуальную проверку экранов провайдеров, настроек, комбо, использования и эндпоинта в обеих темах, запустите `npm run check:ui-kit-snapshot` и `npm run test:vitest:ui` и откройте PR с апстримовым списком изменений.

## 6. Диаграммы README

Двенадцать диаграмм, встроенных в корневой `README.md` (`docs/diagrams/*.svg`), — это kit, применённый к статическому изображению, и они генерируются, а не рисуются вручную: 13 файлов-генераторов в `scripts/docs/gen-readme-*.mjs` (двенадцать диаграмм плюс драйвер `gen-readme-diagrams.mjs`) и 12 тестов на устаревание в `tests/unit/docs/readme-*-svg.test.ts`, по одному на диаграмму, каждый побайтово сравнивает закоммиченный файл с выводом своего генератора (job `test-unit`).

- **Токены.** `scripts/docs/readme-diagram-theme.mjs` копирует палитру из `packages/ui-kit/src/ci-tokens.css` (зафиксирована относительно этого файла тестом `tests/unit/docs/readme-diagram-theme.test.ts`) и определяет текстовые роли для гарнитур kit — Instrument Serif для заголовков, Inter для текста интерфейса, IBM Plex Mono для цифр и кода — те же пакеты `@fontsource`, которые `src/app/globals.css` загружает для дашборда. Светлые значения находятся в `:root`, тёмные — за `prefers-color-scheme: dark`, внутри файла, так что каждое изображение следует теме зрителя на GitHub.
- **Шрифты.** `scripts/docs/readme-fonts.mjs` сводит эти woff2-файлы к подмножествам глифов, которые рисует каждая диаграмма, и встраивает их как `@font-face` `data:` URI — единственный способ, которым типографика kit попадает в изображение README, поскольку GitHub Markdown не переносит CSS, а прокси camo блокирует любую внешнюю загрузку. Подмножества содержат только латиницу; символьные глифы, откатывающиеся к системному стеку, разрешены по одному в `SYMBOL_FALLBACKS`, а любой другой непокрытый глиф выбрасывает ошибку.
- **Перегенерация.** `npm run docs:readme-diagrams` перезаписывает все двенадцать в порядке README и выводит по одной строке на файл с его размером. Отдельный генератор также запускается самостоятельно (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` требует `node --import tsx/esm`, поскольку его цифры берутся из живого загрузчика каталога в `open-sse/config/freeModelCatalog.ts`; последствие изменения каталога для CI описано в `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict`). Коммитьте генератор и SVG вместе.
- **Проверка.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` рендерит файл так, как его отдаёт GitHub (тег `<img>`, `Content-Security-Policy` camo, `image/svg+xml`), захватывает светлый и тёмный кадры и сообщает о внешних запросах шрифтов, которые сделала страница (должно быть 0).
- **Бюджет.** Менее 200 КБ на файл (каждый тест на устаревание это проверяет); 500 КБ — жёсткий предел для любого изображения README (правило валидатора SVG-студии).
- **Текст без изменений, цифры — из гейта.** Ребрендинг изменил шрифт и палитру, а не слова: каждый генератор хранит текст своей диаграммы в константе `*_COPY` (или строит его из живого каталога), которая одновременно является отрисовываемым текстом и входными данными для подмножества шрифта. Канонические цифры остаются в узлах `<text>`, читаемых `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`); тесты на устаревание диаграмм, которые читает гейт, также запускают его валидаторы на сгенерированном файле, так что цифра, отклонившаяся от кода, проваливает тест — исправляйте источник, который читает гейт, а не число в генераторе.
