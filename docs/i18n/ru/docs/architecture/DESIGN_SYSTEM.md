> **Статус:** дашборд построен на **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), завендоренном
> в виде воркспейса `packages/ui-kit` (`@omniroute/ui-kit`; апстрим-снапшот зафиксирован в
> `packages/ui-kit/UPSTREAM.md` и контролируется командой `npm run check:ui-kit-snapshot`). Светлая тема — каноническая;
> предпочтение по умолчанию — `system`. Акцентный цвет — Keak lime (`--ci-color-accent`). Inter
> (letter-spacing 0, `--ci-letter-spacing-ui`) — шрифтовое семейство интерфейса, Instrument Serif — только для крупного разреженного
> акцентного текста (`.ci-dashboard-display`), IBM Plex Mono — для кода; все шрифты хостятся локально через
> импорты `@fontsource/*` в начале файла `src/app/globals.css`. Каждая иконка — глиф Lucide.

## 1. Где что находится

- **Kit.** `packages/ui-kit/src` — побайтовая копия каталога `src/` апстрима на коммите, зафиксированном в
  `packages/ui-kit/UPSTREAM.md` (там же записано лицензионное разрешение); `PATCHES.md` перечисляет локальные
  патчи (их нет). Kit используется как исходный код, без сборки: `next.config.mjs` его транспилирует, а
  `tsconfig.json` отображает `@omniroute/ui-kit` → `packages/ui-kit/src` и `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` (тот же алиас содержат `vitest.config.ts` и `vitest.mcp.config.ts`). Импортируйте
  компонент kit по его подпути (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), никогда
  через barrel-файл `@omniroute/ui-kit`: barrel подтягивает все компоненты (включая выбор даты)
  в каждый импортирующий модуль. Стили kit подключаются через `src/app/globals.css`
  (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **Токены.** `packages/ui-kit/src/ci-tokens.css` объявляет токены `--ci-*`; `src/app/globals.css`
  связывает их с устаревшими именами OmniRoute (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`), так что существующие обращения `var(--color-*)` и утилиты
  Tailwind продолжают работать. Новый код использует утилиты Tailwind (`bg-surface`, `text-text-muted`,
  `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) или классы kit — никогда
  шестнадцатеричные значения (мост проверяется в `tests/unit/design-kit-bridge.test.ts`). `text-primary` разрешается в
  `--color-primary-ink` через `--text-color-primary` (lime-800 в светлой теме, лаймовый акцент в тёмной), поэтому
  основной текст остаётся читаемым, а `bg-primary`/`border-primary` сохраняют лаймовую поверхность. Серии графиков
  используют `--color-chart-1` … `--color-chart-5`.
- **Темы.** `<html className="ci-theme">` (`src/app/layout.tsx`) включает тему kit для документа.
  Настройка — `light`, `dark` или `system` (`THEME_CONFIG.defaultTheme = "system"` в
  `src/shared/constants/appConfig.ts`; `system` следует за `prefers-color-scheme`). `applyTheme()` в
  `src/store/themeStore.ts` (зеркалируется инлайн-скриптом инициализации в `src/app/layout.tsx`, который выполняется
  до гидратации) одновременно устанавливает `data-theme="dark"|"light"` и переключает класс `.dark` на `<html>`.
  Тёмный набор токенов kit привязан к `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`);
  собственные тёмные переопределения OmniRoute (блок `.dark` в `globals.css`) и устаревшие утилиты Tailwind `dark:`
  привязаны к классу `.dark`. Пресетов акцентного цвета нет: акцент всегда берётся из
  kit, а сохранённый пресет из старой сборки отбрасывается при загрузке стора.
- **Компоненты (адаптеры).** `src/shared/components/index.tsx` сохраняет API компонентов OmniRoute (те же
  имена, экспорты по умолчанию и пропсы), а примитивы за ним — адаптеры поверх kit: формы
  (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), оверлеи и обратная связь
  (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`),
  структура (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) и таблицы
  (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). Адаптер импортирует компонент kit
  по подпути и отображает на него устаревшие пропсы — например, `Button variant="primary"` — это
  кнопка kit `default` (`--ci-button-primary-*`: инверсная поверхность в светлой теме, акцент с его
  чернилами `--ci-color-accent-foreground` в тёмной), `danger` — это `destructive`, а `warning` — это `outline` плюс
  расширение `.ci-button--warning`. Правила `.ci-button--warning` и `.ci-badge[data-tone]` в
  конце `globals.css` (`@layer components`) — расширения OmniRoute поверх классов kit.
  `tests/unit/ui/adapters/*.test.tsx` фиксируют каждый адаптер.
- **Оболочка.** `src/app/(dashboard)/layout.tsx` рендерит `DashboardLayout`, который рендерит
  `src/shared/components/layouts/DashboardShell.tsx`: kit `SidebarProvider` / `Sidebar` /
  `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), с навигационной логикой OmniRoute в
  `src/shared/components/Sidebar.tsx`. Ссылка «перейти к содержимому» на `#main-content` — первый фокусируемый
  элемент. `src/shared/components/Header.tsx` содержит kit `SidebarTrigger` (единственный переключатель
  сайдбара оболочки), Keak `ProductSwitcher` и кнопку открытия командной палитры; он показывает заголовок маршрута
  только пока внутри `#main-content` не смонтирован kit `PageHeader` (`.ci-page-header`), поэтому страница с
  собственным `PageHeader` имеет один `h1`. `src/shared/components/CommandPalette.tsx` — это kit `Dialog`.
- **Иконки.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) сопоставляет имя (словарь
  Material Symbols, который используют экраны) через `ICON_MAP` (`src/shared/constants/iconMap.ts`) с
  глифом Lucide. Шрифт и пакет Material Symbols удалены: имя, отсутствующее в карте, отрисовывает
  нейтральный глиф-заглушку (`data-icon-missing="true"`) и выводит предупреждение в консоль вне production.
  `npm run gen:icon-map` выводит используемые имена, отсутствующие в карте
  (`tests/unit/icon-map-coverage.test.ts` падает на любом имени без иконки Lucide;
  `tests/unit/icon-map-object-values.test.ts` покрывает имена, хранящиеся в объектах сопоставления);
  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` переписывает литеральные
  спаны `<span className="material-symbols-outlined">` на `<Icon>`.
- **Бренд.** `src/shared/components/OmniRouteLogo.tsx` оборачивает kit: экспорт по умолчанию `OmniRouteLogo`
  рендерит `ProductIcon product="omniroute" variant="glyph"` (инлайн-SVG, безопасный для `basePath`), а
  `OmniRouteLockup` рендерит `ProductLockup product="omniroute"` (доступное имя «Keak OmniRoute») или, для
  операторов white-label, их собственные `name`/`logoSrc`. Назначения переключателя продуктов находятся в
  `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`). Автономные
  экраны — `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`,
  `src/app/offline/page.tsx`, `src/app/not-found.tsx` и `src/shared/components/ErrorPageScaffold.tsx`
  — показывают локап; `tests/unit/brand-pages-static.test.ts` это контролирует.

## 2. Правила

1. Токены, никогда литералов. Исключения оставлены намеренно: всегда тёмный терминал консоли, обводки
   ReactFlow SVG через `STATUS_HEX` (`src/shared/constants/statusColors.ts`), а также категориальные
   палитры `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) и
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`).
2. Никогда не правьте `packages/ui-kit/src` вручную: синхронизируйте через `scripts/dev/sync-ui-kit.sh <commit>`;
   pre-commit-проверка `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) падает на любом байте,
   отличающемся от закреплённого upstream-коммита (она пропускается с предупреждением, когда upstream-клон —
   `UI_KIT_CLONE` или `_references/cheaper-inference-ui-kit` — отсутствует). Если в ките чего-то не хватает,
   обойдите это в адаптере или на экране и запросите это у upstream.
3. Текст по умолчанию в ките — английский (`label = "Loading"`, `loadingLabel = "Loading table"`…) —
   передавайте переведённые строки из `useTranslations(...)` всякий раз, когда компонент кита выводит текст.
4. Утилиты Tailwind имеют приоритет над классами компонентов кита (кит объявляет
   `@layer theme, base, components, utilities`, и его правила находятся в `components`) — используйте
   утилиты для отступов и раскладки, а не для перекрашивания компонентов кита.
5. Заголовки: `.ci-heading` (Inter, без трекинга) для заголовков страниц и секций; `.ci-dashboard-display`
   (Instrument Serif) — только для крупного, разреженного акцентного текста, такого как код статуса на
   странице ошибки.
6. `tests/unit/dashboard-kit-sweep.test.ts` следит за внедрением кита: ни одного span с лигатурой Material в
   `src/app` или `src/shared/components`; в дереве дашборда (`src/app/(dashboard)` и
   `src/shared/components`) — никаких сырых `<select>`, `<textarea>` или `<table>` и никаких самодельных
   `role="dialog"` вне перечисленных исключений (нативная ветка адаптера `Select`,
   `RequestLoggerDetail`); каждый сырой `<button>` или `<input>` там требует комментария, содержащего
   `kit-exception:` (с причиной), заканчивающегося не более чем за 3 строки выше него; оттенки палитры и
   варианты `dark:` — только в файлах, перечисленных тестом.
7. Проверяйте обе темы и вьюпорт 390 px перед PR (скриншоты); `tests/e2e/a11y.spec.ts` запускает axe.

## 3. Добавление экрана

1. Начинайте страницу с `PageHeader` из кита (`@omniroute/ui-kit/page-header`, `compact` внутри
   дашборда) — заголовок, описание и `actions`. Шапка оболочки в этом случае убирает собственный заголовок.
2. Собирайте элементы управления из `@/shared/components` (адаптеры) и используйте компоненты кита по
   подпутям там, где адаптера нет (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`,
   `RadioGroup`, `Slider`…).
3. Иконки: `<Icon name="…" />`. Новое имя добавляется в `ICON_MAP` с семантически подходящим компонентом
   Lucide; `npm run gen:icon-map` выводит список имён, которых ещё не хватает.
4. Цвета: семантические утилиты (`text-success`, `bg-warning-bg`, `border-border`…) и
   `var(--color-chart-N)` для серий графиков; никаких hex-значений и вариантов `dark:`, которые лишь
   повторяют цвет.
5. Текст: каждая строка, включая метки, которые вы передаёте компонентам кита, берётся из
   `useTranslations`. Новые ключи добавляются в `src/i18n/messages/en.json`, `pt-BR.json` и `vi.json`
   (тест паритета вьетнамской локали закрепляет каждый английский ключ); остальные локали заполняются
   синхронизацией i18n.
6. Запускайте проверки перед PR: `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (единственная проверка, которая ловит дублированный импорт в
   `iconMap.ts`), `npm run check:ui-icu` и собственные тесты экрана.

## 4. Добавление или изменение адаптера

1. Сохраняйте публичный API `src/shared/components/index.tsx`: те же имена экспортов, экспорты по умолчанию и
   принимаемые пропсы. Сопоставляйте устаревшие пропсы с китом внутри адаптера (см. `Button.tsx`: `VARIANT_TO_KIT`,
   `SIZE_TO_KIT`).
2. Импортируйте кит по подпути (`@omniroute/ui-kit/<component>`).
3. Обходные решения для недостающих возможностей кита размещаются в адаптере (или в `globals.css` в `@layer components`,
   если исправление касается стиля), но никогда в `packages/ui-kit/src`.
4. Добавьте или обновите `tests/unit/ui/adapters/<name>.test.tsx`. Для адаптера с большим числом вызовов сравните
   отрисованную разметку до и после изменения — изменения отступов или обёрток распространяются на каждый экран.

## 5. Обновление кита

`scripts/dev/sync-ui-kit.sh <commit> [clone]` копирует апстрим-директорию `src/` на указанном коммите в
`packages/ui-kit/src` и применяет единственное разрешённое преобразование (удаляет суффикс `.js` из
относительных импортов). Далее: проверьте `git diff packages/ui-kit`, проведите визуальную проверку провайдеров,
настроек, комбо, использования и эндпоинта в обеих темах, запустите `npm run check:ui-kit-snapshot` и
`npm run test:vitest:ui`, а затем откройте PR с ченджлогом апстрима.
