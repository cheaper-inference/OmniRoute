> **Статус:** дашборд построен на **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), завендоренном
> как workspace-пакет `packages/ui-kit` (`@omniroute/ui-kit`; снимок апстрима зафиксирован в
> `packages/ui-kit/UPSTREAM.md` и защищён проверкой `npm run check:ui-kit-snapshot`). Светлая тема — каноническая;
> предпочтение по умолчанию — `system`. Акцентный цвет — Keak lime (`--ci-color-accent`). Switzer — это основное семейство шрифтов для UI и отображаемого текста (`--ci-font-ui`; `--ci-font-display` и `--ci-font-mono` разрешают его), размещаемое самим комплектом (`packages/ui-kit/src/ci-fonts.css`, импортированное `ci-tokens.css`). Каждая иконка представляет собой глиф Люцида.
>
> Inter служит резервным шрифтом для глифов, отсутствующих в Switzer; `--font-mono` ссылается на системный стек моноширинных шрифтов `--ci-font-code`.
>
> Если в `Switzer` нет нужного глифа, `src/app/globals.css` выбирает запасной шрифт отдельно для каждого глифа: `Inter` для кириллицы, греческого и вьетнамского, а `Vazirmatn` для арабского письма только под `html[dir="rtl"]`.

`src/app/globals.css`:

```css
:root,
.ci-theme {
  --ci-font-ui:
    "Switzer", "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif;
  --ci-font-code: ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace;
  --font-mono: var(--ci-font-code);
}
```

## 1. Где что находится

- **Kit.** `packages/ui-kit/src` — побайтовая копия апстрим-каталога `src/` на коммите, зафиксированном в
  `packages/ui-kit/UPSTREAM.md` (там же записано разрешение лицензии); `PATCHES.md` перечисляет локальные
  патчи (их нет). Кит используется как исходный код, без сборки: `next.config.mjs` транспилирует его, а
  `tsconfig.json` сопоставляет `@omniroute/ui-kit` → `packages/ui-kit/src` и `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` (тот же алиас указан в `vitest.config.ts` и `vitest.mcp.config.ts`). Импортируйте
  компонент кита по его подпути (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), никогда
  через баррель `@omniroute/ui-kit`: баррель подтягивает все компоненты (включая компонент выбора даты)
  в каждый импортирующий модуль. Стили кита подключаются через `src/app/globals.css`
  (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **Токены.** `packages/ui-kit/src/ci-tokens.css` объявляет токены `--ci-*`; `src/app/globals.css`
  связывает их с прежними именами OmniRoute (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`), так что существующие обращения `var(--color-*)` и утилиты
  Tailwind продолжают работать. Новый код использует утилиты Tailwind (`bg-surface`, `text-text-muted`,
  `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) или классы кита — никогда hex-значения
  (`tests/unit/design-kit-bridge.test.ts` проверяет этот мост). `text-primary` разрешается в
  `--color-primary-ink` через `--text-color-primary` (lime-800 в светлой теме, лаймовый акцент в тёмной), так
  что основной текст остаётся читаемым, а `bg-primary`/`border-primary` сохраняют лаймовую поверхность.
  Серии графиков используют `--color-chart-1` … `--color-chart-5`.
- **Темы.** `<html className="ci-theme">` (`src/app/layout.tsx`) подключает документ к теме кита.
  Предпочтение — `light`, `dark` или `system` (`THEME_CONFIG.defaultTheme = "system"` в
  `src/shared/constants/appConfig.ts`; `system` следует за `prefers-color-scheme`). `applyTheme()` в
  `src/store/themeStore.ts` (зеркалируется встроенным загрузочным скриптом в `src/app/layout.tsx`, который
  выполняется до гидратации) одновременно устанавливает `data-theme="dark"|"light"` и переключает класс
  `.dark` на `<html>`. Тёмный набор токенов кита привязан к `data-theme="dark"`
  (`packages/ui-kit/src/ci-tokens.css`); собственные тёмные переопределения OmniRoute (блок `.dark` в
  `globals.css`) и прежние утилиты Tailwind `dark:` привязаны к классу `.dark`. Пресетов акцентного цвета
  нет: акцент всегда берётся из кита, а сохранённый пресет из более старой сборки отбрасывается при загрузке
  хранилища.
- **Компоненты (адаптеры).** `src/shared/components/index.tsx` сохраняет API компонентов OmniRoute (те же
  имена, экспорты по умолчанию и пропсы), а примитивы за ним — адаптеры над китом: формы
  (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), оверлеи и обратная связь
  (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`),
  структура (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) и таблицы
  (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). Адаптер импортирует компонент
  кита по подпути и сопоставляет с ним прежние пропсы — например, `Button variant="primary"` — это кнопка
  кита `default` (`--ci-button-primary-*`: инверсная поверхность в светлой теме, акцент с его цветом текста
  `--ci-color-accent-foreground` в тёмной), `danger` — это `destructive`, а `warning` — это `outline` плюс
  расширение `.ci-button--warning`. Правила `.ci-button--warning` и `.ci-badge[data-tone]` в конце
  `globals.css` (`@layer components`) — это расширения OmniRoute поверх классов кита.
  `tests/unit/ui/adapters/*.test.tsx` фиксируют каждый адаптер.
- **Оболочка.** `src/app/(dashboard)/layout.tsx` рендерит `DashboardLayout`, который рендерит
  `src/shared/components/layouts/DashboardShell.tsx`: `SidebarProvider` / `Sidebar` /
  `SidebarInset` из кита (`packages/ui-kit/src/sidebar.tsx`), с навигационной логикой OmniRoute в
  `src/shared/components/Sidebar.tsx`. Ссылка «перейти к содержимому» на `#main-content` — первый
  фокусируемый элемент. `src/shared/components/Header.tsx` содержит `SidebarTrigger` из кита (единственный
  переключатель сайдбара в оболочке), `ProductSwitcher` от Keak и кнопку вызова командной палитры; он
  показывает заголовок маршрута только пока внутри `#main-content` не смонтирован `PageHeader` кита
  (`.ci-page-header`), поэтому на странице со своим `PageHeader` — только один `h1`.
  `src/shared/components/CommandPalette.tsx` — это `Dialog` из кита.
- **Иконки.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) преобразует имя (словарь
  Material Symbols, который используют экраны) через `ICON_MAP` (`src/shared/constants/iconMap.ts`) в глиф
  Lucide. Шрифт и пакет Material Symbols удалены: имя, отсутствующее в карте, рендерит нейтральный
  глиф-заглушку (`data-icon-missing="true"`) и выводит предупреждение в консоль вне продакшена.
  `npm run gen:icon-map` выводит используемые имена, отсутствующие в карте
  (`tests/unit/icon-map-coverage.test.ts` падает на любом имени без иконки Lucide;
  `tests/unit/icon-map-object-values.test.ts` покрывает имена, хранящиеся в lookup-объектах);
  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` переписывает литеральные спаны
  `<span className="material-symbols-outlined">` на `<Icon>`.
- **Бренд.** `src/shared/components/OmniRouteLogo.tsx` оборачивает кит: экспорт по умолчанию `OmniRouteLogo`
  рендерит `ProductIcon product="omniroute" variant="glyph"` (встроенный SVG, безопасный относительно
  `basePath`), а `OmniRouteLockup` рендерит `ProductLockup product="omniroute"` (доступное имя "Keak
  OmniRoute") или, для white-label-операторов, их собственные `name`/`logoSrc`. Назначения переключателя
  продуктов находятся в `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`,
  `KEAK_ACTIVE_PRODUCT`). Автономные экраны — `src/app/login/page.tsx`, `src/app/status/page.tsx`,
  `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` и
  `src/shared/components/ErrorPageScaffold.tsx` — показывают локап; `tests/unit/brand-pages-static.test.ts`
  охраняет это.

## 2. Правила

1. Токены, никогда литералы. Исключения оставлены намеренно: всегда тёмный терминал консоли и
   `STATUS_HEX` (`src/shared/constants/statusColors.ts`) — зеркало палитры статусов кита с
   вычисленными hex-значениями для вызывающего кода, которому нужен буквальный hex. Категориальные
   палитры больше не исключение: они построены на пяти chart-токенах кита (`--color-chart-1..5`)
   через `src/shared/utils/categoricalPalette.ts` и, для стратегий маршрутизации,
   `src/app/(dashboard)/dashboard/combos/strategyPalette.ts`; рёбра ReactFlow и канва оркестрации
   читают зависящие от темы переменные `--orch-status-*` (`src/shared/components/flow/edgeStyles.ts`).
2. Никогда не изменяйте `packages/ui-kit/src` вручную: синхронизируйте с помощью `scripts/dev/sync-ui-kit.sh <commit>`; проверка перед коммитом `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) завершается ошибкой при любом побайтовом отличии от закреплённого коммита вышестоящего репозитория (проверка пропускается с предупреждением, если клон вышестоящего репозитория, `UI_KIT_CLONE` или `_references/cheaper-inference-ui-kit`, отсутствует). Если в наборе чего-то не хватает, реализуйте обходное решение в адаптере или на экране и запросите добавление в вышестоящем репозитории.
3. Текстовые значения набора по умолчанию заданы на английском языке (`label = "Loading"`, `loadingLabel = "Loading table"`…) — передавайте переведённые строки из `useTranslations(...)` всякий раз, когда компонент набора отображает текст.
4. Утилиты Tailwind имеют приоритет над классами компонентов набора (набор объявляет `@layer theme, base, components, utilities`, а его правила находятся в `components`) — используйте утилиты для отступов и компоновки, но не для изменения цветов компонентов набора.
5. Заголовки: `.ci-heading` для заголовков страниц и разделов; `.ci-dashboard-display` только для большого, редкого отображаемого текста, такого как код состояния страницы ошибки. Оба используют Switzer.
6. `tests/unit/dashboard-kit-sweep.test.ts` контролирует использование набора: никаких span с лигатурами Material в `src/app` или `src/shared/components`; в дереве панели мониторинга (`src/app/(dashboard)` и `src/shared/components`) запрещены необработанные `<select>`, `<textarea>` и `<table>`, а также самодельные элементы с `role="dialog"` вне перечисленных исключений (нативная ветвь адаптера `Select`, `RequestLoggerDetail`); для каждого необработанного `<button>` или `<input>` там требуется комментарий, содержащий `kit-exception:` (с указанием причины) и завершающийся не более чем за 3 строки до элемента; оттенки палитры и варианты `dark:` разрешены только в файлах, перечисленных тестом.
7. Перед PR проверьте обе темы и область просмотра шириной 390 px (сделайте снимки экрана); `tests/e2e/a11y.spec.ts` запускает axe.

## 3. Добавление экрана

1. Начинайте страницу с китового `PageHeader` (`@omniroute/ui-kit/page-header`, `compact` внутри
   дашборда) — заголовок, описание и `actions`. Тогда шапка оболочки убирает собственный заголовок.
2. Собирайте элементы управления из `@/shared/components` (адаптеров) и используйте компоненты кита
   по подпутям там, где адаптера нет (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`,
   `Tabs`, `RadioGroup`, `Slider`…).
3. Иконки: `<Icon name="…" />`. Новое имя добавляется в `ICON_MAP` вместе с семантически подходящим
   компонентом Lucide; `npm run gen:icon-map` перечисляет имена, которых всё ещё не хватает.
4. Цвета: семантические утилиты (`text-success`, `bg-warning-bg`, `border-border`…) и
   `var(--color-chart-N)` для рядов графиков; никаких hex-значений и никаких вариантов `dark:`, которые
   лишь повторяют цвет.
5. Текст: каждая строка, включая подписи, которые вы передаёте компонентам кита, берётся из
   `useTranslations`. Новые ключи добавляются в `src/i18n/messages/en.json`, `pt-BR.json` и `vi.json`
   (тест паритета вьетнамской локали фиксирует каждый английский ключ); остальные локали заполняются
   синхронизацией i18n.
6. Запускайте проверки перед PR: `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (единственная проверка, которая отлавливает дублированный импорт
   в `iconMap.ts`), `npm run check:ui-icu` и собственные тесты экрана.

## 4. Добавление или изменение адаптера

1. Сохраняйте публичный API `src/shared/components/index.tsx`: те же имена экспортов, экспорты по умолчанию и принимаемые пропсы. Отображайте устаревшие пропсы на kit внутри адаптера (см. `Button.tsx`: `VARIANT_TO_KIT`, `SIZE_TO_KIT`).
2. Импортируйте kit по подпути (`@omniroute/ui-kit/<component>`).
3. Обходные решения для пробелов kit живут в адаптере (или в `globals.css` `@layer components`, когда исправление касается стиля), никогда — в `packages/ui-kit/src`.
4. Добавьте или обновите `tests/unit/ui/adapters/<name>.test.tsx`. Для адаптера с большим числом вызывающих мест сравните отрисованную разметку до и после изменения — изменения отступов или обёрток распространяются на каждый экран.

## 5. Обновление kit

`npm run check:ui-kit-upstream` сравнивает версию, закрепленную в `packages/ui-kit/UPSTREAM.md` с новейшим тегом `v*` исходного репозитория и печатает команду синхронизации при выходе выпуска. Еженедельный рабочий процесс `UI Kit upstream watch` (`.github/workflows/ui-kit-upstream-watch.yml`) выполняет ту же проверку и оставляет одну проблему отслеживания открытой, пока булавка находится позади; восходящий репозиторий является частным, поэтому рабочему процессу нужен токен, доступный только для чтения, в секрете `UI_KIT_READ_TOKEN`. Если проверка не может прочитать upstream (токен отсутствует, перестал работать или GitHub недоступен), она сообщает `unknown` и завершается с кодом `0`. Рабочий процесс выводит предупреждение и пытается держать одну отдельную задачу отслеживания открытой; последующий успешный запуск закрывает её после восстановления доступа. Сбой API задач GitHub приводит к сбою задания.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` копирует восходящий `src/` при этом коммите (`latest` = новейший тег `v*` ) в `packages/ui-kit/src`, применяет единственное разрешенное преобразование (оно удаляет суффикс `.js` из относительного импорта) и устанавливает версию рабочей области в `packages/ui-kit/package.json` и `package-lock.json` в исходную версию. Затем: просмотрите `git diff packages/ui-kit`, выполните визуальный просмотр поставщиков, настроек, комбинаций, использования и конечной точки в обеих темах, запустите `npm run check:ui-kit-snapshot` и `npm run test:vitest:ui` и откройте PR с исходным журналом изменений.

## 6. Диаграммы README

Двенадцать диаграмм в корневом `README.md` (`docs/diagrams/*.svg`) применяют набор компонентов к статическим изображениям. Они генерируются, а не рисуются вручную: 13 файлов генераторов в `scripts/docs/gen-readme-*.mjs` (двенадцать диаграмм и управляющий скрипт `gen-readme-diagrams.mjs`) и 12 тестов актуальности в `tests/unit/docs/readme-*-svg.test.ts`, по одному на диаграмму. Каждый тест побайтово сравнивает закоммиченный файл с выводом его генератора (задание `test-unit`).

- **Токены.** `scripts/docs/readme-diagram-theme.mjs` копирует палитру из `packages/ui-kit/src/ci-tokens.css` (прикрепленную к этому файлу с помощью `tests/unit/docs/readme-diagram-theme.test.ts`) и определяет текстовые роли на более ранних гранях набора — Instrument Serif для отображения, Inter для текста UI, IBM Plex Mono для рисунков и кода — из пакетов `@fontsource` (сама панель мониторинга использует Switzer набора, начиная с версии 0.0.66). Светлые значения располагаются на `:root`, темные значения позади `prefers-color-scheme: dark`, внутри файла, поэтому каждое изображение следует схеме зрителя на GitHub.

- **Шрифты.** `scripts/docs/readme-fonts.mjs` сокращает эти файлы woff2 до глифов, рисуемых каждой диаграммой, и встраивает их через `@font-face` в виде URI `data:`. Так шрифты набора остаются внутри SVG. Локальная проверка изображений README контролирует, что при отображении не выполняются внешние запросы шрифтов. Подмножества содержат только латиницу; глифы символов, использующие системные шрифты как запасной вариант, разрешаются по одному в `SYMBOL_FALLBACKS`. Любой другой непокрытый глиф вызывает ошибку.

- **Перегенерация.** `npm run docs:readme-diagrams` перезаписывает все двенадцать диаграмм в порядке README и выводит по строке с размером каждого файла. Генератор можно запустить отдельно (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` требует `node --import tsx/esm`, поскольку числа поступают из загрузчика текущего каталога в `open-sse/config/freeModelCatalog.ts`; влияние изменения каталога на CI описано в `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict`). Коммитьте генератор и SVG вместе.

- **Подтверждение.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` отображает файл в локальной проверке (тег `<img>`, ограничивающая `Content-Security-Policy` и ответ `image/svg+xml`), снимает светлый и тёмный кадры и сообщает о внешних запросах шрифтов со страницы; их должно быть 0.

- **Бюджет.** Менее 200 KB на файл, что проверяет каждый тест актуальности; 500 KB — жёсткий предел для любого изображения README (правило валидатора SVG studio).

- **Общий текст, числа из gate.** Каждый генератор хранит текст диаграммы в константе `*_COPY` или строит его из текущего каталога. Один и тот же текст рисуется и служит входом для подмножества шрифта. Канонические числа остаются в узлах `<text>`, которые читает `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`). Тесты актуальности диаграмм, читаемых gate, также запускают его валидаторы на сгенерированном файле. Число, расходящееся с кодом, приводит к падению теста: исправляйте источник, читаемый gate, а не число в генераторе.
