`devin-cli-agentic` позволяет реальной среде выполнения Claude Code использовать локальную
конечную точку Anthropic Messages от OmniRoute, в то время как официальный Devin CLI
предоставляет ответы модели через ACP stdio. Он не изменяет существующие провайдеры Anthropic,
Claude OAuth, Claude Web или `devin-cli`.

Для вызовов инструментов, выполняемых клиентом, направляйте запросы через
`devin-cli-agentic` (псевдоним `dva`) — провайдер с поддержкой инструментов в формате Claude.
Устаревший исполнитель ACP `devin-cli` (`dv`) поддерживает только текст: он запускает
суммаризатор Devin без инструментов и не может возвращать вызовы инструментов. Его метаданные
модели соответствующим образом помечены, поэтому маршрутизация комбинаций, требующих
инструментов, будет его избегать.

> **Текущее состояние: закреплена версия Claude Code `2.1.258`; последняя офлайн- и
> онлайн-проверка зафиксирована для `2.1.220`.** На закреплённой версии `2.1.220` были выполнены
> три изолированных сценария через Devin CLI `3000.2.17` и модель `swe-1-7-lightning`; этот
> финальный онлайн-запуск подтвердил выполнение клиентом операций `Read`, `Edit` и `Bash`,
> успешные результаты `npm test`, обнаружение команд и навыков проекта, маршрутизацию
> исключительно через Devin и полное отсутствие исходящего трафика к Claude. Затем
> закреплённая версия была повышена до `2.1.258` (поколение CLI, за которое OmniRoute выдаёт
> свою идентификацию Claude, и первая версия со встроенным уровнем Fable 5.1). Для новой
> закреплённой версии были проверены слой установки и `claude --version` на закреплённом
> базовом образе, а набор модульных тестов моста, `compose config` и статическое доказательство
> изоляции проходят успешно, однако офлайн-сценарий с имитацией и онлайн-набор из трёх
> сценариев ещё не запускались повторно. Перед использованием моста с этой версией повторно
> выполните их (см. «Обновление закреплённых инструментов»).

## Архитектура

```text
Claude Code 2.1.258 (изолированный контейнер Linux без прав root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (формат Claude, провайдер без аутентификации)
  -> devin acp --agent-type summarizer (официальный ACP stdio, без инструментов Devin)
  -> учётная запись Devin в выделенном томе devin-auth
```

Стандартный ACP-агент официального CLI может выполнять собственные инструменты, поэтому этот
мост его не использует. Он запускает фиксированный ACP-агент `summarizer`, официальный режим
CLI которого не имеет инструментов, и оформляет сериализованный запрос Anthropic как трассу
выполнения. Когда требуется ещё одно действие на стороне Claude, ответ должен содержать ровно
одну клиентскую оболочку инструмента. Любой `tool_call` или `tool_call_update` ACP отклоняется
до того, как ответ может быть признан успешным.

Сериализатор в `open-sse/executors/devin-agentic/serializer.ts` сохраняет `system`, `text`,
`tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` и инструменты,
предоставленные Claude Code. Изображения и неизвестные блоки приводят к явной ошибке.
Для больших результатов инструментов используется видимый маркер усечения.

Парсер принимает одну отдельную оболочку `<tool>{...}</tool>` на каждый ответ модели. Он
проверяет имя по списку инструментов запроса, валидирует аргументы по JSON Schema этого
инструмента, отклоняет смешение повествования с действиями и допускает одну ограниченную
попытку исправления. Затем Claude Code локально выполняет полученный Anthropic `tool_use` и
отправляет `tool_result` обратно через OmniRoute.

## Автоматическая маршрутизация

Провайдер может включаться в пулы кандидатов `auto/*` OmniRoute, если он не заблокирован.
Допуск в кандидаты не гарантирует выбора: стратегия маршрутизации комбинации (например,
последний успешно работавший вариант) может предпочесть другого провайдера. Используйте
`dva/<model>` или комбинацию с приоритетом Devin, если требуется направлять каждый запрос
через Devin.

## Изоляция и модель угроз

Установка, учетная запись и конфигурация Claude на хосте находятся вне области действия и считаются
запрещенными. Сервисы Compose:

- работают с UID/GID `10001:10001`, корневой файловой системой только для чтения, сброшенными привилегиями и
  `no-new-privileges`;
- используют приватный `/home/bridge`, отдельный том конфигурации Claude, изолированные данные OmniRoute
  и отдельный том `devin-auth`;
- монтируют только одноразовые рабочие пространства и доказательства из `.sandbox`;
- не монтируют домашний каталог хоста, Keychain, учетные данные SSH и облачных сервисов или сокет Docker;
- формируют явно заданные окружения и удаляют переменные API/OAuth/маршрутизации Anthropic;
- направляют запросы Claude Code только в `http://omniroute:20128`, используя локальный ключ.

Офлайн-профиль использует внутреннюю сеть. В профиле с сетевым доступом OmniRoute обращается к
официальным конечным точкам Devin только через `network-guard`; доступ к остальным адресам запрещен.
Claude Code имеет отдельный сетевой фильтр, запрещающий весь исходящий трафик, и может обращаться только
к локальному сервису OmniRoute через `NO_PROXY`. Файлы аудита фильтров монтируются только в соответствующий
процесс фильтра. Перед экспортом доказательств, не содержащих токенов, скрипты проверяют владельца файла,
режим доступа, количество ссылок и каждое принятое решение.

Запустите проверку изоляции отдельно:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Она проверяет топологию, именованные точки монтирования, настройки запуска не от имени root и файловой
системы только для чтения, явную локальную маршрутизацию, отсутствие конфиденциальных переменных окружения,
отсутствие сокета Docker, блокировку доступа к `api.anthropic.com` и `claude.ai`, выбор только провайдера
Devin и явное завершение с ошибкой при недоступности бэкенда ACP.

## Первоначальная настройка и обычное использование

Соберите образ с закрепленными версиями:

```bash
./scripts/devin-bridge/build
```

Выполните аутентификацию только для изолированного тома Devin:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Команда входа использует официальный процесс с ручным вводом токена, предназначенный для удаленных
и контейнерных сред. Значение вводится непосредственно в приглашение CLI; оно не передается как аргумент
процесса, не записывается в Git и не копируется с хоста.

Запустите изолированную среду выполнения Claude Code:

```bash
./scripts/devin-bridge/launch
```

Перед запуском контейнеризированного Claude Code команда `launch` повторно проверяет изоляцию,
аутентификацию Devin и обнаружение моделей. Она никогда не запускает исполняемый файл Claude с хоста.
Псевдонимы моделей можно задать в `.env.devin-bridge`; каждое настроенное значение должно сохранять
префикс `devin-cli-agentic/`.

## Команды проверки

Для воспроизводимого офлайн-сценария не требуется учетная запись Devin, а во время выполнения не нужен
доступ к Интернету:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Сценарий с аутентификацией и сетевым доступом, запускаемый только по явному запросу:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Средство запуска сценариев с сетевым доступом делает паузы между ними, чтобы не открывать сеансы ACP
одновременно, и проверяет структурированные события потока Claude вместо того, чтобы доверять текстовым
заявлениям. Три сценария подтверждают:

1. непосредственное чтение файлов проекта и анализ дефектов;
2. реальное выполнение `Edit`, принадлежащее клиенту выполнение `Bash` `npm test` и получение итогового результата;
3. выполнение `/bridge-check`, обнаружение `bridge-proof`, чтение файлов проекта, еще одно успешное
   принадлежащее клиенту выполнение `npm test` и завершение без незаконченной работы.

Финальный шлюз также проверяет аудит сети Devin и требует, чтобы аудит исходящего трафика Claude
оставался пустым.

## Обновление закреплённых инструментов

В образе закреплены версии Node, Claude Code и Devin CLI в
`docker/devin-bridge/Dockerfile`. Для обновления:

1. измените явно указанные версии;
2. замените контрольные суммы архивов Devin для обеих архитектур значениями официального
   артефакта;
3. пересоберите образ и выполните все команды автономной проверки;
4. подтвердите версии внутри образа;
5. повторно запустите аутентифицированный набор интерактивных тестов для трёх сценариев.

Не устанавливайте ни один из CLI глобально на хосте и не заменяйте проверку контрольной суммы
непроверенной загрузкой.

## Диагностика и очистка

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  показывает локальную маршрутизацию и очищенные от конфиденциальных данных ошибки исполнителя.
- `.sandbox/evidence/mock-acp.jsonl` содержит детерминированные действия фиктивного ACP.
- `.sandbox/evidence/claude-stream.jsonl` содержит результаты реального автономного запуска Claude Code.
- `.sandbox/evidence/live-*.jsonl` содержит три проверенных интерактивных потока.
- `.sandbox/evidence/egress.jsonl` и `.sandbox/evidence/claude-egress.jsonl` — это проверенные
  копии аудитов исходящего трафика, не содержащие токенов.

Остановите принадлежащие среде контейнеры и сети, сохранив тома входа и конфигурации:

```bash
./scripts/devin-bridge/clean
```

Удалите всю среду, принадлежащую мосту, включая именованные тома:

```bash
./scripts/devin-bridge/clean --all
```

## Ограничения

- Мост использует фиксированную роль `summarizer` без инструментов, поскольку Devin CLI `3000.2.17`
  не предоставляет нейтрального ACP-агента без инструментов. Адаптер компенсирует промежуточные
  ответы в формате сводки, однако одна ограниченная попытка исправления всё ещё может завершиться
  явной ошибкой.
- Интерактивные вызовы ACP могут возвращать временные ответы `502`/`504`. Средство тестирования
  выполняет сценарии с интервалами; при устойчивом сбое система продолжает работать по принципу
  fail-closed и никогда не выбирает другого провайдера.
- Контекст ACP восстанавливается из каждого запроса Anthropic; привязка к процессу или сеансу
  отсутствует.
- Для каждого ответа модели поддерживается один вызов инструмента; параллельные вызовы отклоняются.
- Изображения явно не поддерживаются. Возможности компьютерного зрения, вывод процесса рассуждений,
  управление уровнем усилий и окно контекста в 1M токенов не заявлены.
- SSE использует корректные события жизненного цикла Anthropic, но они отправляются после получения
  ограниченного хода ACP; фрагменты ACP не пересылаются по мере поступления.
