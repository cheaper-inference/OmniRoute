Провайдеры Web Cookie позволяют OmniRoute использовать сервис ИИ через существующий сеанс браузера вместо ключа API. Они полезны, если у вас уже есть доступ к сервису через его веб-сайт и вы хотите, чтобы OmniRoute использовал тот же аутентифицированный сеанс.

В отличие от провайдеров с ключами API, провайдеры Web Cookie выполняют аутентификацию с помощью учётных данных, которые ваш браузер отправляет веб-сайту.

---

# Перед началом

> **Важно:** Всегда копируйте учётные данные из **активного сетевого запроса**, а **не** из хранилища cookie-файлов браузера.

Многие проблемы с аутентификацией возникают из-за копирования cookie-файлов не из того места.

## Не копируйте данные из хранилища cookie-файлов

Большинство браузеров предоставляют доступ к сохранённым cookie-файлам через:

```
DevTools
→ Application (или Storage)
→ Cookies
```

Хотя эти cookie-файлы могут выглядеть корректно, они могут быть:

- устаревшими
- неполными
- без cookie-файлов, отправляемых только с аутентифицированными запросами

Использование этих значений может привести к сбоям аутентификации, даже если они выглядят допустимыми.

## Копируйте данные из активного запроса

Вместо этого используйте cookie-файлы из успешно выполненного запроса:

```
DevTools
→ Network
→ Обновите страницу
→ Откройте запрос чата или беседы
→ Request Headers
→ Cookie
```

Заголовок запроса `Cookie` содержит точные данные аутентификации, которые ваш браузер успешно использовал.

Для большинства провайдеров Web Cookie именно это значение следует вставить в OmniRoute.

# Общая настройка

Процесс настройки одинаков для большинства провайдеров Web Cookie.

1. Войдите на веб-сайт провайдера.
2. Откройте инструменты разработчика в браузере.
3. Откройте вкладку **Network**.
4. Обновите страницу.
5. Откройте аутентифицированный запрос чата или беседы.
6. Скопируйте необходимые учётные данные для аутентификации.
7. Откройте OmniRoute.
8. Перейдите в раздел **Providers → Add Provider**.
9. Выберите своего провайдера Web Cookie.
10. Вставьте учётные данные.
11. Нажмите **Test Connection**.
12. Сохраните провайдера.

Точный набор необходимых учётных данных зависит от провайдера.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) — это бесплатная пользовательская чат-платформа, не требующая регистрации. Сеанс создаётся анонимно при первом посещении и сохраняется с помощью трёх файлов cookie: `uid`, `si_usr_id` и `si_ses_id`. OmniRoute проксирует тот же эндпоинт `/api/dispatch` через единый идентификатор модели (`notrack-c`, псевдоним `ntw`).

### Шаги подключения

1. Откройте [notrack.ai](https://notrack.ai) в браузере и дождитесь установки cookie анонимного сеанса.
2. Откройте **Инструменты разработчика → Сеть**, обновите страницу и выберите любой запрос `/api`.
3. В разделе **Заголовки запроса** скопируйте полное значение заголовка `Cookie`.
4. В OmniRoute перейдите в раздел **Провайдеры → Добавить провайдера → NoTrack Web (бесплатно)**.
5. Вставьте строку cookie в поле `apiKey` и нажмите **Сохранить**.

OmniRoute извлекает `uid`, `si_usr_id` и `si_ses_id` из вставленной строки и заново формирует чистый заголовок `Cookie`, содержащий только эти пары, а также `nt_session` (токен `ntk_…`, устанавливаемый для авторизованных учётных записей), если он присутствует. Если какое-либо из трёх значений отсутствует, исходная вставленная строка пересылается без изменений, чтобы операторы могли экспериментировать с альтернативными форматами.

### Идентификаторы моделей

| Идентификатор модели | Отображаемое имя | Примечания                                                   |
| -------------------- | ---------------- | ------------------------------------------------------------ |
| `notrack-c`          | NoTrack C        | По умолчанию — вышестоящая модель диспетчеризации `C`.       |
| `C`                  | NoTrack C        | Псевдоним для `notrack-c` (исходный вышестоящий код модели). |
| `notrack`            | NoTrack C        | Псевдоним для `notrack-c`.                                   |
| `ntw`                | NoTrack C        | Короткий псевдоним для `notrack-c`.                          |

Все четыре идентификатора модели соответствуют одной и той же вышестоящей модели диспетчеризации (`C`).

### Параметры запроса

Исполнитель принимает следующие необязательные поля в теле запроса:

| Поле тела запроса     | Значение по умолчанию | Назначение                                                                              |
| --------------------- | --------------------- | --------------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`               | Режим диспетчеризации (произвольная строка; вышестоящий сервис принимает `usual`, …)    |
| `notrack_max_turns`   | `6`                   | Количество внутренних шагов, которые вышестоящий сервис может выполнить перед ответом.  |
| `notrack_chat_id`     | `null`                | Продолжить существующий чат вышестоящего сервиса (не указывайте для нового чата).       |
| `notrack_attachments` | `[]`                  | Сквозной массив дескрипторов вложений вышестоящего сервиса.                             |
| `notrack_regenerate`  | `false`               | Установите `true`, чтобы запросить повторно сгенерированный ответ для предыдущего шага. |

### Возможности

- **Потоковые и непотоковые** завершения чата.
- **Вызов инструментов** — укажите `tools: [...]` в запросе; исполнитель сериализует их в контракт конверта вызова инструментов и преобразует ответы модели обратно в OpenAI `tool_calls`.
- **`response_format`** — поддерживаются `json_object` и `json_schema`. Исполнитель извлекает первый объект JSON из ответа модели и преобразует его в строку перед возвратом.
- **Указание процесса рассуждения** — исполнитель отправляет дельту `reasoning`, когда вышестоящий сервис присылает событие `thinking`.

### Ограничения

- Вышестоящий сервис устанавливает квоты на анонимное использование — при их превышении исполнитель возвращает ошибку 429 с понятным сообщением.
- Все идентификаторы моделей соответствуют одной и той же вышестоящей модели диспетчеризации; переключение между моделями отсутствует.
- Исполнитель не вызывает эндпоинт `/api/chats` вышестоящего сервиса, поэтому история чатов и сеансы не управляются автоматически. Используйте `notrack_chat_id`, чтобы продолжить существующий чат вышестоящего сервиса.

# Возможности и ограничения провайдеров с веб-cookie

Провайдеры с веб-cookie повторно используют чат-интерфейс веб-сайта. Они **не** предоставляют те же возможности, что и официальные API.

## Поддерживается

- Аутентификация с использованием существующего сеанса браузера
- Доступ к моделям, доступным через вашу учётную запись
- Потоковая передача ответов чата
- API-ключ не требуется

## Не поддерживается

- Вызов функций
- Вызов инструментов
- Автоматическое редактирование файлов
- Агентные рабочие процессы в IDE
- Функции, доступные только через API

Это ожидаемое поведение, а **не** ошибка.

Если вам требуется выполнение инструментов, автоматическое редактирование файлов или другие агентные рабочие процессы, используйте **провайдера с API-ключом** вместо провайдера Web Cookie.

---

# Ограничение проверки

Успешная **проверка подключения** или проверка cookie подтверждает только то, что предоставленные учётные данные имеют ожидаемый формат.

До устранения проблемы #7857 успешная проверка **не гарантирует**, что провайдер сможет успешно выполнить аутентификацию.

Если аутентификация по-прежнему не работает, убедитесь, что вы скопировали учётные данные из активного сетевого запроса, а не из хранилища cookie браузера.

---

# Устранение неполадок

## Ошибка аутентификации

Убедитесь, что учётные данные были скопированы из:

```
Сеть
→ Заголовки запроса
→ Cookie
```

а **не** из:

```
Приложение
→ Файлы cookie
```

---

## Cookie работает в браузере, но не в OmniRoute

Некоторые провайдеры используют cookie, которые отправляются только при выполнении аутентифицированных запросов.

Повторно скопируйте учётные данные из нового сетевого запроса после успешного открытия диалога.

---

## Сеанс истёк

Провайдеры Web Cookie используют существующий сеанс браузера.

Если срок действия сеанса браузера истёк или вы вышли из системы, необходимо скопировать новый набор учётных данных. Чтобы автоматизировать обновление cookie для поддерживаемых веб-провайдеров, используйте вспомогательный инструмент [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md).

---

## Проверка подключения проходит успешно, но запросы завершаются ошибкой

До устранения проблемы #7857 успешное прохождение проверки не гарантирует, что запрос аутентификации будет выполнен успешно.

Прежде чем продолжать устранение неполадок, повторно скопируйте учётные данные из нового аутентифицированного запроса.

---

## ChatGPT Web завершается ошибкой "Unsupported ChatGPT integrity dependency"

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

С учётными данными всё в порядке — эта ошибка возникает в модуле моста, а не в сеансе. chatgpt.com назначает
идентификаторы модулей отдельно для каждого развёртывания, а мост ранее жёстко фиксировал идентификатор создаваемого им вспомогательного модуля Sentinel, поэтому
пересборка chatgpt.com, в которой вспомогательный модуль был переименован, нарушала работу каждого запроса, хотя cookie оставался действительным. Повторная авторизация
подключения не может устранить эту проблему.

Сборки, которые находят модуль через собственную среду выполнения страницы, не фиксируют идентификатор и не сталкиваются с этой проблемой. Если вы видите эту
ошибку, обновите OmniRoute и повторно запустите проверку подключения.

# Рекомендации

- Копируйте учётные данные из нового аутентифицированного запроса.
- Не используйте повторно старые cookie.
- Поддерживайте сеанс браузера активным при использовании провайдеров Web Cookie.
- Обращайтесь со скопированными cookie как с конфиденциальными учётными данными.
- Используйте провайдеров с API-ключом, если вам требуется вызов функций или агентные рабочие процессы.
