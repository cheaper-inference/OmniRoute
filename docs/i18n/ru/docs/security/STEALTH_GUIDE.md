OmniRoute интегрируется с провайдерами, пограничные узлы которых активно идентифицируют неофициальные клиенты по цифровым отпечаткам (TLS JA3/JA4, порядок заголовков, структура тела JSON, токены целостности). На этой странице описаны доступные в OmniRoute механизмы скрытности и места их реализации.

## Правовое и этическое уведомление

Функции скрытности существуют для того, чтобы OmniRoute мог выступать в качестве уровня совместимости между принадлежащими пользователям официальными учётными записями (Claude Code CLI, Codex, Antigravity, Cursor и т. д.) и унифицированным API OmniRoute. Они **не** предназначены для обхода систем обнаружения мошенничества, совместного использования учётных данных или нарушения Условий обслуживания провайдеров. Сопровождающие проекта ожидают, что операторы будут соблюдать условия обслуживания вышестоящих сервисов, которые они приняли при создании учётных записей.

## Уровень снятия TLS-отпечатков

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Постоянные сессии `wreq-js` создаются отложенно для каждой области учётной записи и разрешённого прокси. Общий для процесса пул `TlsClient` содержит не более 128 сессий, имитирующих **Chrome 124 на macOS**, для вышестоящих серверов, защищённых Cloudflare. `TlsClient.fetch()` безопасно завершает работу с ошибкой, если нативная среда выполнения недоступна; вызывающая сторона может явно выбрать резервный вариант за пределами этой обёртки.

- Профиль сессии: `browser: "chrome_124", os: "macos"`
- Разрешение прокси (в порядке приоритета): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (также варианты в нижнем регистре)
- Тайм-аут: `TLS_CLIENT_TIMEOUT_MS` (наследуется от `FETCH_TIMEOUT_MS`, значение по умолчанию — 600000)
- Response из `wreq-js` совместим с fetch (`headers`, `text()`, `json()`, `clone()`, `body`).
- Сторожевой таймер первого байта (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`
  завершается сразу после получения заголовков от вышестоящего сервера, поэтому одного
  `TLS_CLIENT_TIMEOUT_MS` недостаточно для ограничения времени ожидания тела, которое так и не
  возвращает первый байт. `guardTlsFirstByte()` запускает гонку между первым `read()` тела и
  `TLS_FIRST_BYTE_WATCHDOG_MS` (по умолчанию `10000`, значение `0` отключает его); корректное тело
  не затрагивается, а при зависании тела чтение wreq отменяется, после чего существующая в
  `proxyFetch` логика резервного TLS-подключения переходит к прямому/прокси-диспетчеру (запрос,
  небезопасный для повторной отправки, например POST с телом, по-прежнему завершается ошибкой,
  а не незаметно отправляется повторно).

### Транспорт провайдера веб-cookie — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` — общий адаптер для пяти специализированных транспортов
веб-cookie, перечисленных ниже. Каждая тонкая обёртка провайдера выбирает профиль браузера/ОС.
Адаптер использует единый загрузчик среды выполнения wreq и пул транспортов из
`open-sse/utils/tlsClient.ts`, ключом для которого служит сочетание профиля, ОС и разрешённого
прокси, при этом каждый запрос использует `cookieMode: "ephemeral"`. Таким образом, учётные записи
и запросы совместно используют соединения транспортного уровня, но никогда не используют общую
сессию wreq или хранилище cookie.

| Провайдер  | Профиль       | Эмулируемая ОС | Политика EOF потока                     |
| ---------- | ------------- | -------------- | --------------------------------------- |
| Claude     | `chrome_146`  | Linux          | включать `[DONE]`                       |
| Perplexity | `firefox_151` | macOS          | включать `event: end_of_stream`         |
| Grok       | `chrome_146`  | Linux          | исключать `[DONE]`                      |
| Notion     | `chrome_146`  | Windows        | включать `[DONE]`                       |
| LMArena    | `chrome_146`  | Windows        | без маркера; закрывать при нативном EOF |

- Потоковая передача использует нативный `ReadableStream` ответа напрямую; временный файл или
  вспомогательный процесс не создаётся.
- Перед предоставлением потока проверяются первые 256 байт. SSE-провайдеры буферизуют ошибки,
  не относящиеся к SSE; Grok/LMArena преобразуют проверки Cloudflare в `403`, а промежуточные
  HTML-страницы — в `502`.
- Тайм-аут нативного запроса дополнительно ограничивается абсолютным жёстким сроком JS. При
  зависании аннулируется и закрывается только затронутый транспорт профиля/ОС/прокси, после чего
  следующий запрос создаёт его заново.
- Приоритет разрешения прокси: переданный для вызова `proxyUrl` → привязанный к запросу контекст
  учётной записи/панели управления → `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (включая варианты
  в нижнем регистре). Ошибки разрешения безопасно завершают операцию вместо утечки прямого
  соединения. LMArena намеренно выполняет разрешение относительно `arena.ai`.
- `byteResponse` возвращает URL `data:` с указанным типом содержимого без повреждения UTF-8.
- Используются ошибки `TlsClientUnavailableError` (пакет/дополнение недоступно),
  `TlsClientHangError` (превышен крайний срок) и `WreqTransportCapacityError` (общий код ошибки
  исчерпания ёмкости сессий), когда все 128 ограниченных слотов профиля/ОС/прокси активны или
  закрываются.

Описанная выше универсальная сессия `TlsClient` остаётся специализированной для постоянного
состояния cookie, поддерживаемого браузером. Оба пути повторно используют единый кэшированный
загрузчик модуля wreq и обработчик жизненного цикла процесса; их пулы остаются раздельными,
поскольку время жизни cookie у них намеренно различается.

Профили поддерживаются закреплённой версией пакета, однако фактическое принятие WAF может меняться
независимо от локальных контрактных тестов. Прежде чем заявлять о соответствии вышестоящему
браузеру, проверяйте изменения отпечатка с использованием явно авторизованной реальной учётной
записи.

## Комплект маскировки Claude Code

Когда включён `cliCompatMode`, OmniRoute преобразует исходящие запросы Claude так, чтобы их нельзя было отличить от трафика `claude-cli`. Совместно работают три модуля:

### `claudeCodeFingerprint.ts`

Вычисляет 3-символьный отпечаток `cc_version`, встроенный в заголовок биллинга:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (жёстко задано; соответствует официальному клиенту)
- Входные данные: символы с индексами 4, 7 и 20 из текста первого сообщения пользователя + строка версии
- Выходные данные: 3-символьный шестнадцатеричный префикс

### `claudeCodeCCH.ts` (хеш содержимого клиента)

Серверная проверка целостности, которую официальный CLI Claude Code вычисляет с помощью Bun/Zig. OmniRoute воспроизводит её с использованием `xxhash-wasm`:

1. Сериализовать тело с заполнителем `cch=00000;`
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. 5-символьное шестнадцатеричное значение в нижнем регистре с дополнением нулями
4. Заменить `cch=00000;` вычисленным токеном

Константы:

- Начальное значение: `0x6e52736ac806831e`
- Шаблон: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

Вставляет Unicode-символ **соединителя нулевой ширины** (`U+200D`) после первого символа «чувствительных» имён клиентов, чтобы вышестоящие фильтры не могли обнаружить их с помощью grep. Список слов по умолчанию:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Применяется к: блокам `system`, всему содержимому `messages[].content`, а также `tools[].description` / `tools[].function.description`. Оператор может переопределить список с помощью `setSensitiveWords()`.

### `claudeCodeCompatible.ts` — провайдеры `anthropic-compatible-cc-*`

Для сторонних ретрансляторов Anthropic, принимающих только трафик «настоящего Claude Code»:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"` по умолчанию
- Переключатель «Включить бета-версию редактирования рассуждений» для отдельного подключения добавляет `redact-thinking-2026-02-12`, когда вышестоящий сервис, совместимый с CC, явно требует потоки отредактированных рассуждений
- Переключатель «Включить отображение сводки рассуждений» для отдельного подключения сохраняет `providerSpecificData.requestDefaults.summarizeThinking` и добавляет `display: "summarized"` к запросам рассуждений, совместимым с CC, если в них ещё не задан режим отображения
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (семейство Opus/Sonnet 4.x)
- Путь по умолчанию: `/v1/messages?beta=true`

Связанные модули в том же комплекте:

- `claudeCodeConstraints.ts` — правила температуры и управления кешем
- `claudeCodeToolRemapper.ts` — переназначение имён инструментов
- `claudeCodeExtraRemap.ts` — дополнительная нормализация полезной нагрузки

## Antigravity Стелс

Запросы Antigravity сохраняют текст вызывающего абонента побайтно. OmniRoute не вставляет символы нулевой ширины в подсказки или инструменты rename/inject для имитации клиента IDE.

### `antigravityHeaderScrub.ts`

Перед пересылкой удаляются маркеры SDK из нержавеющей стали (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`).

### Риск ⚠️ : `ANTIGRAVITY_CREDITS=always` (горячая точка блокировки аккаунта)

Маршруты `ANTIGRAVITY_CREDITS=always` (используемые `open-sse/executors/antigravity.ts`)**каждый** запросите через Antigravity избыток кредита AI (платные кредиты Google ) вместо того, чтобы разрешать доступ к квотам бесплатного уровня Google. Это задокументировано как функция, но это **самый распространенный отчет о нарушении ToS, который мы видим** Несколько учетных записей — Google Ultra были заблокированы с помощью `403 / "service disabled for ToS violation" / insufficient_quota` после нескольких часов работы с `=always`.

Вводится принудительное исполнение в восходящем направлении.**Сторона Google** , OmniRoute не может предотвратить ничего. Имя env var и существующая документация говорят о том, что это безопасная ручка; это не так.

**Почему это требует более активного обнаружения злоупотреблений, чем использование только бесплатного уровня:**

- Устойчивые автоматические расходы на одну учетную запись Google отмечаются иначе, чем превышение квоты и остановки на бесплатном уровне.
- Избыток кредита не имеет потолка ставки, поэтому неправильно настроенный клиент может сжечь несколько сотен USD за считанные минуты и выглядеть как перепродажа API-ключа или трафик ботов.
- Несколько пользователей OmniRoute, параллельно получающие избыточные кредиты из одного и того же внешнего IP усугубляют сигнал.

**Рекомендуемая поза:**

1. Сохраняйте `ANTIGRAVITY_CREDITS=off` по умолчанию, если только оператор явно не принимает на себя риск выплаты кредита и принудительного взыскания по счету. `retry` сначала отправляет обычный запрос и вводит кредиты не более одного раза после достижения допустимой квоты 429; `always` вводит кредиты по первому запросу.
2. **Распределите нагрузку между поставщиками с помощью Auto-Combo** (`model: "auto"` или `kr/glm/etc` -combo) вместо заполнения одной учетной записи Antigravity.
3. **Установите ограничения RPM для каждого соединения** на странице редактирования провайдера Antigravity (Панель управления поставщиками → → Antigravity →, ограничение скорости соединения → ). 30–60 RPM — это оправданная верхняя граница для длительного использования.
4. **Используйте стабильную вышестоящую сеть, контролируемую оператором.** и избегайте совместного использования одной учетной записи несвязанными пользователями или рабочими нагрузками.
5. **Если забанят** : обращение через `support.google.com` → «Восстановить доступ Workspace/Account » с точным отправленным телом ответа `quota_exceeded` / `service disabled` Google. Восстановление не гарантируется.

Справочник по среде документирует учетную запись и последствия расходов для каждого режима кредитов.

#### Не только `=always`: Antigravity OAuth маршрутизация в целом

Приостановки не ограничиваются переизбытком кредита. В отчетах за ноябрь 2026 года (#19223, #19266) описывается несколько учетных записей Google, заблокированных при маршрутизации через поставщиков `antigravity` и `agy` (Antigravity CLI), при этом:

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

Оба провайдера проходят аутентификацию с помощью сеанса OAuth продукта Antigravity, о чем предупреждает уведомление о рисках на информационной панели («Этот провайдер использует ваш официальный продукт session/OAuth, который не разрешен для использования proxy/router ») перед добавлением соединения. Ни одна из приведенных выше рекомендаций не делает такое использование разрешенным; они только уменьшают объем трафика, который несет одна учетная запись.

**Авторизованные интерфейсы API для моделей Gemini.** Google предлагает программный доступ к Gemini через свой APIs, который OmniRoute поддерживает как обычные поставщики API-ключей:

| Идентификатор поставщика | Название информационной панели | Полномочия                                                                           |
| ------------------------ | ------------------------------ | ------------------------------------------------------------------------------------ |
| `gemini`                 | Gemini (Google AI Студия)      | Ключ Gemini API от Google AI Studio (доступен бесплатный уровень)                    |
| `vertex`                 | Вертекс AI                     | Учетная запись службы JSON, токен доступа OAuth или ключ Vertex Express API (Gemini) |

Эти поставщики используют учетные данные Google для доступа к API, в отличие от сеанса продукта Antigravity. Они не обеспечивают соответствие требованиям при каждом использовании и не устраняют риск принудительного применения: каждый из них регулируется собственными условиями, которые оператор должен проверить для их развертывания. Например, [Дополнительные условия обслуживания Gemini API](https://ai.google.dev/gemini-api/terms) разрешают только Платные услуги, когда клиенты API доступны пользователям в Европейской экономической зоне, Швейцарии или Великобритании, а контент, отправленный в Неоплачиваемые услуги, может использоваться для улучшения продуктов Google. Вместо этого Vertex AI подпадает под условия Google Cloud ( [Условия для отдельных услуг](https://cloud.google.com/terms/service-terms) ). Цены и квоты соответствуют условиям API, а не подписке Antigravity.

Операторам, которые хотят избежать описанных выше приостановок Antigravity следует маршрутизировать трафик Gemini через одного из этих провайдеров вместо `antigravity` / `agy`, предварительно проверив, что их использование соответствует условиям провайдера.

Точки касания:

- `open-sse/executors/antigravity.ts` — читает `process.env.ANTIGRAVITY_CREDITS`
- `src/lib/oauth/providers/antigravity.ts` — удостоверение сантехники
- Исходный отчет об инциденте: Обсуждение [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## Реестр отпечатков CLI — `open-sse/config/cliFingerprints.ts`

Таблица для каждого провайдера, фиксирующая **точный** порядок заголовков и полей тела JSON, полученный из трассировок mitmproxy официальных CLI. В настоящее время зарегистрированы: `codex`, `claude`, а также профили, формируемые во время выполнения в `providerHeaderProfiles.ts` для `antigravity` и `github`.

```ts
interface CliFingerprint {
  headerOrder: string[]; // с учётом регистра
  bodyFieldOrder: string[]; // ключи JSON верхнего уровня
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Переключается отдельно для каждого провайдера через переменные окружения (см. ниже). Если функция отключена, заголовки и ключи тела располагаются в том порядке, в котором их предоставили Node/JSON, — это упрощает создание отпечатка.

## MITM-прокси (Antigravity, Linux/macOS/Windows)

Для CLI, бинарные файлы которых нельзя перенаправить через `OPENAI_BASE_URL`, OmniRoute запускает локальный прокси-сервер с завершением TLS. Конечные точки находятся в `src/app/api/cli-tools/antigravity-mitm/`.

| Метод  | Конечная точка                          | Назначение                                          |
| ------ | --------------------------------------- | --------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | Состояние — running, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | Запуск MITM (требуются `apiKey` и `sudoPassword`)   |
| DELETE | `/api/cli-tools/antigravity-mitm`       | Остановка MITM                                      |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | Получение списка псевдонимов моделей                |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | Сохранение псевдонимов моделей для инструмента      |

Целевой перехватываемый хост: **`daily-cloudcode-pa.googleapis.com`** (вышестоящий сервер Antigravity).

### Последовательность запуска (`src/mitm/manager.ts::startMitm`)

1. Создать самоподписанный сертификат с помощью `selfsigned` (RSA-2048, SHA-256, 1 год) — `cert/generate.ts`
2. Установить сертификат в системное хранилище доверенных сертификатов — `cert/install.ts`
3. Добавить в hosts запись `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. Запустить `src/mitm/server.cjs` с `ROUTER_API_KEY` и `MITM_LOCAL_PORT` (по умолчанию `443`)
5. Сохранить PID в `<DATA_DIR>/mitm/.mitm.pid`

### Динамическое обнаружение хранилища доверенных сертификатов Linux — `cert/install.ts`

`getLinuxCertConfig()` проходит по списку приоритетов и выбирает первый существующий каталог:

| Семейство дистрибутивов  | Каталог                                     | Команда обновления       |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Имя файла сертификата: `omniroute-mitm.crt`. Сопоставление отпечатка выполняется через `getCertFingerprint()` (SHA-1 от DER).

Кроме того, `updateNssDatabases()` устанавливает сертификат в пользовательские базы данных NSS, если доступен `certutil`: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, все профили Firefox (включая snap), под именем **`OmniRoute MITM Root CA`**.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** PowerShell с повышенными привилегиями → `certutil -addstore Root`

### Аутентификация

Все конечные точки MITM требуют управленческой аутентификации (`requireCliToolsAuth`). Пароль sudo кэшируется в области видимости модуля (но не в `globalThis`) и очищается при вызове `stopMitm()`.

## Очистка входящих заголовков

Перед пересылкой OmniRoute очищает входящие клиентские заголовки, чтобы запрос, поступивший от Cursor, не передавал `User-Agent: Cursor/X.Y.Z` вышестоящему серверу Claude. Список запрещённых заголовков находится в `src/shared/constants/upstreamHeaders.ts` и синхронизируется со схемами Zod и модульными тестами.

## Обновление отпечатков при их смене провайдером

1. Перехватите трафик официального CLI с помощью `mitmproxy` (перехват TLS + дамп)
2. Извлеките JA3/JA4 и точный порядок заголовков
3. Обновите соответствующую запись `CLI_FINGERPRINTS[...]`
4. Обновите соответствующее значение `*_USER_AGENT` по умолчанию в `.env.example`
5. Если изменилось само рукопожатие TLS, обновите соответствующую обёртку провайдера или параметр `browser:` в wreq-js
6. Запустите специфичные для провайдера тесты TLS и выполните ручную канареечную проверку на рабочем провайдере
7. Выпустите патч-релиз и задокументируйте изменения в `CHANGELOG.md`
