> `src/lib/db/obsidian.ts` (хранение токена / базового URL / настроек WebDAV),
> `src/lib/obsidianSync.ts` (синхронизация хранилища через WebDAV), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 инструмента MCP), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (API настроек). Регистрация инструментов
> и настройка областей доступа находятся в `open-sse/mcp-server/server.ts`.

## Что это такое

OmniRoute подключается к хранилищу **Obsidian** как к **источнику контекста** — локальной
базе знаний в формате Markdown, которую агенты читают и изменяют через встроенный сервер
MCP. Интеграция взаимодействует с плагином сообщества **Obsidian Local REST API**,
запущенным внутри настольного приложения, благодаря чему агенты могут искать заметки,
читать/записывать/частично изменять файлы, просматривать содержимое хранилища, работать
с ежедневными/еженедельными периодическими заметками, управлять тегами, выполнять
команды Obsidian и (опционально) координировать двунаправленную синхронизацию хранилища
между настольным и мобильным приложениями.

Клиент (`src/lib/obsidian/api.ts`) предоставляет обёртку над Local REST API со следующими возможностями:

- **Повторные попытки с увеличивающейся задержкой** для временных ошибок `5xx`,
  **30-секундный тайм-аут** через `AbortController`.
- **Типизированная классификация ошибок** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- **Понятная подсказка «не удаётся подключиться к Obsidian»**, указывающая на
  распространённую ошибку с портом (HTTP на `27123`, **а не** конечная точка MCP на
  `27124`) и вариант адреса для Tailscale.
- **Кодирование путей** относительно хранилища, позволяющее безопасно обрабатывать пути
  к заметкам с пробелами и косыми чертами.

## Настройка

Для токена Obsidian и базового URL **нет переменных окружения** — оба значения
хранятся в таблице SQLite `key_value` (пространство имён `obsidian`) через
`src/lib/db/obsidian.ts`. Токен **зашифрован при хранении** (AES-256-GCM, с резервной
поддержкой открытого текста для обратной совместимости). Настройте его на вкладке
**Источники контекста** панели управления Endpoint (`ObsidianSourceCard`) или через
REST API настроек.

> [!IMPORTANT]
> Плагин **Obsidian Local REST API** должен быть установлен и запущен. Его REST-интерфейс
> прослушивает **HTTP `127.0.0.1:27123`** (базовый URL по умолчанию). Порт `27124` —
> это _отдельная_ конечная точка MCP/HTTPS, которую маршрут настроек явно отклоняет.
> При подключении с другого устройства используйте `http://<tailscale-ip>:27123`.

### Ключи конфигурации (SQLite `key_value`, пространство имён `obsidian`)

| Ключ              | Назначение                                                        | Зашифрован |
| ----------------- | ----------------------------------------------------------------- | ---------- |
| `api_key`         | Bearer-токен Local REST API                                       | да         |
| `base_url`        | Базовый URL REST (по умолчанию `http://127.0.0.1:27123`)          | нет        |
| `vault_path`      | Абсолютный путь к каталогу хранилища (для синхронизации)          | нет        |
| `webdav_username` | Сгенерированное имя пользователя WebDAV (синхронизация хранилища) | нет        |
| `webdav_password` | Сгенерированный пароль WebDAV (синхронизация хранилища)           | да         |
| `webdav_enabled`  | Включена ли синхронизация хранилища через WebDAV                  | нет        |

### Настройка через REST

```bash
# Сохранение и проверка токена Local REST API (POST проверяет его через запрос статуса)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Проверка состояния подключения (возвращает connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Отключение (удаляет сохранённый токен)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Все методы требуют аутентификации в панели управления. `POST` отклоняет любой URL с
портом `27124` и перед сохранением проверяет токен, вызывая конечную точку статуса
Local REST API.

### Синхронизация хранилища через WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` управляет необязательной
синхронизацией хранилища через WebDAV (реализованной в `src/lib/obsidianSync.ts`).
При её включении OmniRoute связывается с локальным каталогом хранилища и создаёт
случайную пару имени пользователя и пароля WebDAV:

```bash
# Включение синхронизации через WebDAV для каталога хранилища (создаёт имя пользователя и пароль)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Получение состояния синхронизации WebDAV (учётные данные возвращаются только при включённой синхронизации)
curl http://localhost:20128/api/settings/obsidian/webdav

# Отключение синхронизации WebDAV (удаляет учётные данные и управляемый .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Безопасность и транспорт

Аутентификация WebDAV обеспечивает отслеживание и блокировку сбоев каждого IP-адреса (10 неудачных попыток в течение 60-секундного окна запускают 5-минутную блокировку с помощью `429 Too Many Requests` и `Retry-After`). Поскольку WebDAV передает учетные данные базовой аутентификации, настоятельно рекомендуется завершать TLS (или маршрутизировать через защищенный туннель, такой как Tailscale или Cloudflare Tunnel) при доступе к конечной точке WebDAV вне шлейфа.

### Источник контекста для отдельного API-ключа (необязательно)

Конфигурацию Obsidian можно задавать **отдельно для каждого API-ключа** через таблицу
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Когда вызов MCP
содержит идентификатор аутентифицированного API-ключа, `getObsidianConfigForApiKey()`
предпочитает собственные токен, базовый URL и путь к хранилищу этого ключа
(`source: "api_key"`), а при их отсутствии использует глобальную конфигурацию
(`source: "global"`).

Инструменты MCP, не связанные с синхронизацией, требуют определения личности
вызывающей стороны перед чтением этой конфигурации. Вызывающая сторона без
установленной личности получает сообщение `Obsidian API token not configured`, и
запрос к хранилищу не отправляется. Для HTTP-вызовов личность определяется по
учётным данным запроса; для вызовов через stdio — через `OMNIROUTE_API_KEY` или
`ROUTER_API_KEY`. Неопределённая вызывающая сторона HTTP не может унаследовать
идентификатор окружения сервера. Одни лишь идентификаторы-заполнители не предоставляют
доступ; по-прежнему поддерживаются действительные учётные данные окружения,
соответствующие `env-key`. Для аутентифицированных ключей без индивидуальной
конфигурации Obsidian сохраняется резервное использование глобальной конфигурации.
Четыре инструмента `obsidian_sync_*` продолжают использовать отдельный механизм
токенов синхронизации.

## инструменты MCP (22)

Определено в `open-sse/mcp-server/tools/obsidianTools.ts`. token/base-URL разрешаются для каждого вызова (сначала для каждого ключа API, затем глобально). Инструменты, которые поражают OmniRoute** сервер синхронизации** (четыре инструмента `obsidian_sync_*` ) дополнительно требуют токена аутентификации синхронизации, настроенного в настройках OmniRoute.

### Инструменты чтения (`read:obsidian`)

| Инструмент                   | Описание                                                                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Проверьте, доступен ли локальный REST API и прошел ли он аутентификацию.                                                      |
| `obsidian_search_simple`     | Полнотекстовый поиск по содержимому заметки; возвращает фрагменты с путями к файлам.                                          |
| `obsidian_search_structured` | Поиск с использованием логического выражения JSON (фильтры and/or/regex/path ).                                               |
| `obsidian_read_note`         | Прочитать заметку по пути относительно хранилища; опционально конкретный heading/block/frontmatter.                           |
| `obsidian_list_vault`        | Список файлов и каталогов в хранилище (дерево записей).                                                                       |
| `obsidian_get_document_map`  | Получите структуру заголовка заметки в виде карты номеров строк заголовков →.                                                 |
| `obsidian_get_note_metadata` | Получите заголовок, теги, ссылки и счетчик char/word без полного контента.                                                    |
| `obsidian_get_active_file`   | Получите путь к содержимому + текущего активного файла в Obsidian.                                                            |
| `obsidian_get_periodic_note` | Получите периодическую заметку daily/weekly/monthly для даты (сегодня, если она опущена).                                     |
| `obsidian_get_tags`          | Перечислите все теги хранилища с указанием их частоты.                                                                        |
| `obsidian_list_commands`     | Список доступных команд Obsidian IDs (используйте с `obsidian_execute_command`).                                              |
| `obsidian_sync_status`       | Состояние сервера синхронизации OmniRoute : работает, имя хранилища, порт, время безотказной работы, последняя синхронизация. |
| `obsidian_sync_conflicts`    | Список неразрешенных конфликтов синхронизации (путь, путь конфликта, обнаружение).                                            |

### Инструменты записи (`write:obsidian`)

| Инструмент                       | Описание                                                                                                          |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Создайте или перезапишите заметку с указанным содержимым Markdown.                                                |
| `obsidian_append_note`           | Добавить содержимое в заметку; опционально для конкретного heading/block.                                         |
| `obsidian_patch_note`            | Хирургически append/prepend/replace в поле заголовка, блока или вступительной части.                              |
| `obsidian_delete_note`           | Удалить заметку из хранилища навсегда.                                                                            |
| `obsidian_move_note`             | Переместите или переименуйте заметку в хранилище.                                                                 |
| `obsidian_execute_command`       | Выполните команду Obsidian с помощью ее команды ID.                                                               |
| `obsidian_open_file`             | Откройте файл в Obsidian (создает его, если он не существует).                                                    |
| `obsidian_sync_trigger`          | Запустите немедленную двунаправленную синхронизацию мобильного хранилища ↔ с рабочим столом.                      |
| `obsidian_sync_resolve_conflict` | Устраните конфликт синхронизации: сохраните `local` (мобильный), `remote` (настольный компьютер) или `keep-both`. |

> [!NOTE]
> Цели `obsidian_patch_note` принимают `targetType` из `heading | block | frontmatter` и `operation` из `append | prepend | replace` с необязательным `createTargetIfMissing`. Четыре инструмента `obsidian_sync_*` взаимодействуют с локальным сервером синхронизации (по умолчанию `http://127.0.0.1:27781` ) и требуют токена синхронизации.

### Области применения

Инструменты чтения требуют `read:obsidian`; инструменты записи требуют `write:obsidian`. Применение идентично Notion — обрабатываемому `withScopeEnforcement()` в `open-sse/mcp-server/server.ts`, закрытому на `OMNIROUTE_MCP_ENFORCE_SCOPES=true` и принудительно включенному для вызывающих объектов HTTP/SSE у которых в ключе API отсутствует `manage`/`admin`, с разрешенными областями, полученными из `OMNIROUTE_MCP_SCOPES` или контекста области ключа API. См. [MCP-SERVER.md](./MCP-SERVER.md).

## Эндпоинты

| Метод    | Путь                            | Назначение                                                                   |
| -------- | ------------------------------- | ---------------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Возвращает `{ connected, hasToken, baseUrl, vaultPath }`.                    |
| `POST`   | `/api/settings/obsidian`        | Сохраняет и проверяет токен (порт `27124` отклоняется).                      |
| `DELETE` | `/api/settings/obsidian`        | Отключает интеграцию (удаляет сохранённый токен).                            |
| `GET`    | `/api/settings/obsidian/webdav` | Возвращает статус синхронизации WebDAV и учётные данные (пока она включена). |
| `POST`   | `/api/settings/obsidian/webdav` | Включает синхронизацию WebDAV для каталога хранилища.                        |
| `DELETE` | `/api/settings/obsidian/webdav` | Отключает синхронизацию WebDAV.                                              |

> Это маршруты настроек панели управления. Доступ к самому хранилищу осуществляется через
> локальный REST API Obsidian (настроенный `base_url`) и через указанные выше инструменты MCP —
> публичной прокси-конечной точки Obsidian `/v1` не существует.

## Сценарии использования

- **Ответы на основе хранилища** — `obsidian_search_simple` / `obsidian_search_structured`,
  затем `obsidian_read_note`, чтобы агент отвечал на основе ваших реальных заметок.
- **Создание заметок / ведение журнала** — `obsidian_write_note`, `obsidian_append_note` или
  точечный инструмент `obsidian_patch_note` для сохранения результатов работы агента, сводок или ежедневных заметок
  (`obsidian_get_periodic_note`) в хранилище.
- **Навигация по хранилищу** — `obsidian_list_vault`, `obsidian_get_document_map` и
  `obsidian_get_tags` для изучения структуры перед чтением или записью.
- **Автоматизация Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` для
  управления плагинами и командами через агента; `obsidian_open_file` для отображения заметки в интерфейсе.
- **Мобильная синхронизация** — включите синхронизацию WebDAV, затем используйте `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  для координации синхронизации между настольным и мобильным приложениями и разрешения конфликтов.
