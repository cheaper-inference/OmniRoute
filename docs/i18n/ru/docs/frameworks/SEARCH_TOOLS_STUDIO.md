## Обзор

Search Tools Studio превращает `/dashboard/search-tools` из простой среды для экспериментов с поиском в
трёхвкладочную Студию, объединяющую веб-поиск, извлечение веб-контента и параллельное сравнение провайдеров.

```
┌ Инструменты поиска ────────────────────────────────────────────────────┐
│ [🔍 Поиск] [📄 Извлечение] [⚖ Сравнение]        142ms · $0.001  </>    │
│ ⓘ [Руководство по модальностям]                                       │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {содержимое активной вкладки}           │ ─ Конфигурация              │
│                                          │ Провайдер [авто ∨]          │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (получение)  │
│                                          │ Тип   [веб | новости]       │
│                                          │ Вся страница [ ] (извлеч.) │
│                                          │ Формат [md|текст|html]      │
│                                          │ Модель реранжир. [∨]        │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## Вкладки

### Вкладка «Поиск»

Преобразует существующую `SearchForm` + `ResultsPanel` + `RerankPanel` во вкладку:

- Запрос результатов → (заголовок, URL, фрагмент, оценка релевантности).
- Метаданные поставщика на панели конфигурации (стоимость, квота, статус).
- Раздел изменения рейтинга: выберите модель изменения рейтинга, измените порядок результатов, покажите `positionDelta`.
- Пустое состояние CTA, если не настроены поставщики поиска.
- История поиска через `SearchHistory.tsx`.
- Вызывает `POST /v1/search` (существующая конечная точка, без изменений).

### Вкладка «Очистка»

Новая вкладка для извлечения контента из URL через `POST /v1/web/fetch` (создана в плане 05):

- Ввод: URL + полностраничный переключатель формата + (markdown/text/ HTML).
- Отправить → fetch → render `ScrapeResult.tsx`.
- `ScrapeResult` отображает предварительный просмотр уценки. Переключатель + raw.
- Ограничение: если тело ответа >** 256 KB** , UI отображает `(truncated, view raw)` и открывает необработанные данные в модальном окне Монако (D21).
- Панель метаданных: поставщик (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search), задержка, стоимость, размер ответа, количество ссылок.
- Использует хук `useScrapeFetch.ts`.

### Вкладка «Сравнить»

Выполняет ту же самую query/URL до** 4 провайдера параллельно** (Д22):

- Параллельные столбцы для каждого поставщика.
- Метрики: задержка, стоимость, количество результатов, размер ответа.
- Расчет перекрытия URL для поиска (количество общих URLs по сравнению с первоначальным результатом).
- Вызывает `POST /v1/search` (поиск) или `POST /v1/web/fetch` (очистка) для каждого провайдера.

## Панель конфигурации (общая)

`SearchToolsConfigPane.tsx` — отображается всегда, можно свернуть.

| Поле                  | Примечания                                                                      |
| --------------------- | ------------------------------------------------------------------------------- |
| Провайдер             | Выпадающий список с индикатором статуса (настроен / отсутствует / ограничен)    |
| Тип                   | `web` или `news` (только для поиска)                                            |
| Полная страница       | Переключатель для извлечения — получает всю страницу или только видимый контент |
| Формат                | `markdown`, `text` или `html` (только для извлечения)                           |
| Модель реранжирования | Необязательная модель для реранжирования после поиска                           |
| История               | Сворачиваемый раздел истории поиска                                             |

## SearchConceptCard

`SearchConceptCard.tsx` — всегда видимый сворачиваемый аккордеон. Содержит пояснения:

| Концепция            | Краткое описание                                                                 |
| -------------------- | -------------------------------------------------------------------------------- |
| **Поиск**            | Получает список веб-результатов (заголовок, URL, фрагмент, оценка релевантности) |
| **Извлечение**       | Извлекает полное содержимое URL (markdown, текст или HTML)                       |
| **Сравнение**        | Выполняет один и тот же запрос параллельно у N провайдеров                       |
| **Переранжирование** | Переупорядочивает результаты с помощью LLM для повышения релевантности запросу   |
| **Авто (дешевле)**   | Автоматически выбирает самого дешёвого доступного провайдера                     |

## Каталог провайдеров

`ProviderCatalog.tsx` предоставляет полный список поставщиков из `GET /api/search/providers` (расширенный в F4 для включения поставщиков выборки):

| `kind` | `"search"` (24 провайдера) или `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, Anysearch-search, параллельный поиск, остроумный поиск) |

Статус** получено во время запроса** проверяя, существуют ли учетные данные и все ли ключи в настоящее время находятся в режиме восстановления.

`codex-search` (Codex Web Search) не имеет собственного ключа: он повторно использует подключенную учетную запись Codex (ChatGPT), поэтому каждый поиск тратит квоту подписки ChatGPT и занимает около 10–40 с. Он запускается, когда запрос называет его; для автоматического выбора требуется флаг функции `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` (по умолчанию отключен).

## Экспорт кода

`ExportCodeModal` (импортируется из Playground Studio) + `codeExport.ts` генерируют
фрагменты curl / Python / TypeScript для вызовов `/v1/search` и `/v1/web/fetch`.
Заполнителем API-ключа всегда является `$OMNIROUTE_API_KEY` (D11, используется совместно с Playground Studio).

## Изменения в бэкэнде

Для этой функции потребовалось только одно изменение серверной части:

### Расширенный `GET /api/search/providers`

`src/app/api/search/providers/route.ts` был расширен до:

- Включите в массив каждого поставщика выборки (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`, `keenable-search`).
- Добавьте `kind: "search" | "fetch"` к каждому элементу.
- Добавьте `status: "configured" | "missing" | "rate_limited"` полученный на основе действующего состояния учетных данных.
- Сохранить обратную совместимость существующих полей — (`id`, `name` и т. д.) без изменений.

## Устранение неполадок

| Симптом                                                         | Причина                                | Решение                                                                                                           |
| --------------------------------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| На вкладке Scrape отображается «endpoint недоступен»            | `/v1/web/fetch` не подключён           | Убедитесь, что план 05 объединён; проверьте наличие `src/app/api/v1/web/fetch/route.ts`                           |
| В каталоге провайдеров все они отображаются как «отсутствующие» | Учётные данные не настроены            | Добавьте учётные данные в `/dashboard/providers`                                                                  |
| Содержимое Scrape обрезано                                      | Размер ответа превышает лимит в 256 КБ | Ожидаемое поведение (D21). Используйте кнопку «просмотреть исходное содержимое» для просмотра полного содержимого |
| На вкладке Compare отображаются только 2 провайдера             | Активно ограничение частоты запросов   | Два или более провайдера могут находиться в режиме ожидания — проверьте их статус на панели Config                |
| В таблице вместо «Size» отображается необработанный ключ        | Отсутствует ключ i18n                  | Убедитесь, что `search.size` существует в файле локали; пересоберите i18n                                         |
