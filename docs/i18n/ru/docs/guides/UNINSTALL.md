## Восстановить конфигурацию клиента

Программа удаления останавливает процесс OmniRoute, управляемый PM2, если он присутствует, и оставляет конфигурацию клиента без изменений. Клиенты, которые все еще указывают на OmniRoute теряют соединение после его остановки. При полном удалении также удаляется каталог данных, по умолчанию `~/.omniroute`, вместе с резервными копиями конфигурации клиента.

### 1. Используйте панель управления во время работы OmniRoute

Открыть**CLI код** (`/dashboard/cli-code`) на приборной панели и найдите**Claude код** карта.** Применять** записывает в файл настроек кода Claude хоста OmniRoute, по умолчанию `~/.claude/settings.json`. Если у вас есть резервная копия, созданная до применения настроек OmniRoute, откройте** Резервные копии** и восстановить его. В противном случае выберите** Перезагрузить** удалить настройки шлюза из `env`. Применить и сбросить сначала создайте резервную копию существующего файла. Резервные копии хранятся под именем `<DATA_DIR>/backups`.

Если `CLI_ALLOW_CONFIG_WRITES=false` или панель мониторинга недоступны, верните файл вручную. Если OmniRoute работает в Docker, а клиент работает на хосте, верните конфигурацию хоста. Файлы в несмонтированном домашнем контейнере не влияют на хост-клиент.

### 2. Отмените оставшиеся изменения вручную.

Для кода Claude проверьте `~/.claude/settings.json`, `settings.json` в `CLAUDE_CONFIG_DIR` если он установлен, и `.claude/settings.json` проекта. Сброс удаляет следующие ключи из `env`. Удалите значения, добавленные вами для OmniRoute, или восстановите предыдущие значения.

- `"ANTHROPIC_BASE_URL"`, `"ANTHROPIC_AUTH_TOKEN"` и `"ANTHROPIC_API_KEY"`
- `"ANTHROPIC_DEFAULT_OPUS_MODEL"`, `"ANTHROPIC_DEFAULT_SONNET_MODEL"` и `"ANTHROPIC_DEFAULT_HAIKU_MODEL"`
- `"API_TIMEOUT_MS"`

При сбросе `ANTHROPIC_MODEL` остается в `env`, а настройки `model` и `apiKeyHelper` верхнего уровня остаются на месте. Удалите или восстановите их вручную, если они выберут модель OmniRoute или учетные данные. Прекратите использовать любой профиль OmniRoute, созданный `omniroute setup-claude` под `~/.claude/profiles/<name>/`, или верните его `settings.json`. Команда настройки записывает профиль без изменения файла настроек по умолчанию или сохранения токена. Удалите или восстановите соответствующие экспортированные файлы в файлах запуска оболочки и удалите старые значения из текущей оболочки. `omniroute launch` и `omniroute run claude` устанавливают шлюз URL и токен только для дочернего процесса.

Для Codex восстановите предыдущего поставщика и модель в `~/.codex/config.toml`, если он содержит `model_provider = "omniroute"`. Удалите `[model_providers.omniroute]` если он был добавлен для этого шлюза. Восстановите или удалите `openai_base_url` если он указывает на OmniRoute. Для клиентов, совместимых с OpenAI, восстановите или очистите `OPENAI_BASE_URL` везде, где вы установили его для OmniRoute.

### 3. Убедитесь, что клиент работает, а OmniRoute остановлен.

Проверьте настройки кода Claude по умолчанию и текущую среду оболочки.

```bash
grep -n ANTHROPIC ~/.claude/settings.json
env | grep ANTHROPIC
```

Ни одна из проверок не должна показывать, что `ANTHROPIC_BASE_URL` указывает на OmniRoute. Если вы используете настройки профиля или проекта, проверьте и эти файлы. Остановив OmniRoute и восстановив обычную аутентификацию, запустите код Claude напрямую.

```bash
claude -p "say hello"
```

Код Claude должен ответить, используя восстановленную конфигурацию. Если он по-прежнему указывает на остановленный шлюз, запрос завершается ошибкой соединения.

## Быстрое удаление (v3.6.2 +)

> Сначала [отмените конфигурацию клиента](#revert-client-configuration), пока OmniRoute еще работает.

OmniRoute предоставляет два встроенных сценария для чистого удаления:

### Храните свои данные

```bash
npm run uninstall
```

Это удалит приложение OmniRoute но** сохраняет** ваша база данных, конфигурации, ключи API и настройки провайдера в `~/.omniroute/`. Используйте это, если вы планируете переустановить позже и хотите сохранить настройки.

### Полное удаление

```bash
npm run uninstall:full
```

Это удалит приложение** и навсегда стирает** все данные:

- База данных (`storage.sqlite`)
- Конфигурации провайдера и ключи API
- Резервные файлы
- Файлы журналов
- Все файлы в каталоге `~/.omniroute/`

> ⚠️** Предупреждение:** `npm run uninstall:full` необратим. Все ваши подключения к провайдеру, комбинации, ключи API и история использования будут безвозвратно удалены.

## Удаление вручную

> Сначала [отмените конфигурацию клиента](#revert-client-configuration), пока OmniRoute еще работает.

### Глобальная установка NPM

```bash
# Remove the global package
npm uninstall -g omniroute

# (Optional) Remove data directory
rm -rf ~/.omniroute
```

### Глобальная установка pnpm

```bash
pnpm uninstall -g omniroute
rm -rf ~/.omniroute
```

### Docker

```bash
# Stop and remove the container
docker stop omniroute
docker rm omniroute

# Remove the volume (deletes all data)
docker volume rm omniroute-data

# (Optional) Remove the image
docker rmi cheaperinference/omniroute:latest
# Older installs pulled the legacy name:
docker rmi diegosouzapw/omniroute:latest
```

### Docker Написать

```bash
# Stop and remove containers
docker compose down

# Also remove volumes (deletes all data)
docker compose down -v
```

### Приложение Electron для ПК

**Windows:**

- Открыть `Settings → Apps → OmniRoute → Uninstall`
- Или запустите программу удаления NSIS из каталога установки.

**macOS:**

- Перетащите `OmniRoute.app` из `/Applications` в корзину.
- Удалить данные: `rm -rf ~/Library/Application Support/omniroute`

**Linux:**

- Удалить файл AppImage
- Удалить данные: `rm -rf ~/.omniroute`

### Установка исходного кода (клон git)

```bash
# Remove the cloned directory
rm -rf /path/to/omniroute

# (Optional) Remove data directory
rm -rf ~/.omniroute
```

## Каталоги данных

По умолчанию OmniRoute хранит данные в следующих расположениях:

| Платформа         | Путь по умолчанию               | Переопределение                        |
| ----------------- | ------------------------------- | -------------------------------------- |
| Linux             | `~/.omniroute/`                 | Переменная окружения `DATA_DIR`        |
| macOS             | `~/.omniroute/`                 | Переменная окружения `DATA_DIR`        |
| Windows           | `%APPDATA%/omniroute/`          | Переменная окружения `DATA_DIR`        |
| Docker            | `/app/data/` (подключённый том) | Переменная окружения `DATA_DIR`        |
| Совместимые с XDG | `$XDG_CONFIG_HOME/omniroute/`   | Переменная окружения `XDG_CONFIG_HOME` |

### Файлы в каталоге данных

| Файл/каталог         | Описание                                                        |
| -------------------- | --------------------------------------------------------------- |
| `storage.sqlite`     | Основная база данных (провайдеры, комбинации, настройки, ключи) |
| `storage.sqlite-wal` | Журнал упреждающей записи SQLite (временный)                    |
| `storage.sqlite-shm` | Общая память SQLite (временная)                                 |
| `call_logs/`         | Архивы содержимого запросов                                     |
| `backups/`           | Автоматические резервные копии базы данных                      |
| `log.txt`            | Устаревший журнал запросов (необязательно)                      |

## Проверка полного удаления

После удаления убедитесь, что никаких файлов не осталось:

```bash
# Проверка глобального пакета npm
npm list -g omniroute 2>/dev/null

# Проверка каталога данных
ls -la ~/.omniroute/ 2>/dev/null

# Проверка запущенных процессов
pgrep -f omniroute
```

Если какой-либо процесс всё ещё запущен, остановите его:

```bash
pkill -f omniroute
```
