> **Кратко**: OmniRoute ранжирует своих **бесплатных** провайдеров по качеству моделей, используя **ELO-рейтинги Arena AI
> (в стиле LMArena)**. Откройте страницу **Рейтинг бесплатных провайдеров** в
> панели управления, чтобы узнать, какие бесплатные провайдеры предлагают лучшие модели для вашей задачи —
> в целом или с фильтрацией по категориям (написание кода, проверка, документация, отладка).

---

## Что это такое

OmniRoute регистрирует 377 поставщиков, в том числе 155 записей каталога с пометкой**free/no-auth** (без аутентификации, ключ OAuth бесплатного уровня или ключ API бесплатного уровня — см. [Руководство по уровням бесплатного пользования](../getting-started/FREE-TIERS-GUIDE.md) и полный [каталог уровней бесплатного пользования](../reference/FREE_TIERS.md) ). Подвох: бесплатные провайдеры сильно различаются по качеству моделей. Поставщик без аутентификации, обслуживающий пограничную модель, гораздо полезнее, чем поставщик, обслуживающий небольшую устаревшую модель.

**Бесплатные рейтинги провайдеров** ответы"** какой бесплатный провайдер предлагает мне лучшую модель?** ", присоединившись к каталогу каждого бесплатного провайдера с помощью** краудсорсинговые показатели качества** из** Таблица лидеров Arena AI** (человеческие предпочтения ELO, та же идея, что и арена чат-бота LMArena). Затем поставщики ранжируются по силе их** лучшая бесплатная модель** .

Рейтинг рассчитывается на основе трех реальных источников:

1. Списки бесплатных провайдеров — `NOAUTH_PROVIDERS` плюс записи `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS`, помеченные как `hasFree` (`src/shared/constants/providers.ts`).
2. Каталог моделей каждого поставщика из реестра поставщиков (`open-sse/config/providerRegistry.ts`).
3. Оценки соответствия задач, полученные на основе ELO, сохраняются в таблице `model_intelligence` DB механизмом синхронизации Arena ELO (`src/lib/arenaEloSync.ts`).

Логика соединения находится в `src/lib/freeProviderRankings.ts`.

## Как получить доступ

### Страница панели управления

Откройте панель управления и перейдите в раздел **Затраты → Рейтинг бесплатных провайдеров** или откройте напрямую:

```
/dashboard/free-provider-rankings
```

На странице (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) отображаются:

- **Пьедестал трёх лидеров** (🥇 🥈 🥉) среди бесплатных провайдеров с наивысшим рейтингом.
- Полная **таблица рейтинга** со столбцами: **Место**, **Провайдер**, **Лучшая модель**,
  **Оценка**, **Средняя оценка**, **Модели**, **Тип**.
- **Кнопки фильтрации по категориям**: _Все категории_, _По умолчанию_, _Написание кода_, _Проверка_,
  _Документация_, _Отладка_.

Значок **Тип** каждого провайдера показывает, каким образом предоставляется бесплатный доступ:

| Значок   | Значение                                                |
| -------- | ------------------------------------------------------- |
| `NOAUTH` | Всегда бесплатно, учётные данные не требуются           |
| `OAUTH`  | OAuth-провайдер с бесплатным тарифом (`hasFree`)        |
| `APIKEY` | Провайдер с API-ключом и бесплатным тарифом (`hasFree`) |

Оценки отображаются в виде понятных обозначений (например, _Элитный_, _Отличный_, _Очень хороший_,
_Хороший_, _Средний_), а не чисел, поскольку базовое значение отражает относительное
качество в рейтинге, а не процент.

### Конечная точка API

Страница использует общедоступную конечную точку для чтения
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

Параметры запроса (проверяются с помощью Zod):

| Параметр   | Тип    | По умолчанию | Примечания                                                                                                        |
| ---------- | ------ | ------------ | ----------------------------------------------------------------------------------------------------------------- |
| `category` | string | (не задано)  | Одно из значений: `default`, `coding`, `review`, `documentation`, `debugging`. Не указывайте для общего рейтинга. |
| `limit`    | number | `50`         | Ограничивается диапазоном `1–100`.                                                                                |

Структура ответа:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` — исходное значение Arena ELO; `score` — нормализованная оценка соответствия задаче
(см. ниже). Провайдеры без моделей с оценками не включаются в ответ.

## Как работают оценки

### Источник: рейтинг Arena AI

Движок синхронизации Arena ELO (`src/lib/arenaEloSync.ts`) загружает два рейтинга — `text`
и `code` — из API рейтингов Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). Если этот API не возвращает
пригодный рейтинг, движок использует официальный набор данных `lmarena-ai/leaderboard-dataset`
на сервере наборов данных Hugging Face (`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` сообщает `activeSource`, `lastError` и
`lastFailedAt`. Каждая запись рейтинга
содержит название модели, поставщика, `score` ELO, доверительный интервал и количество голосов.

Категории рейтинга сопоставляются с категориями задач OmniRoute:

| Рейтинг Arena | Категории задач OmniRoute                         |
| ------------- | ------------------------------------------------- |
| `text`        | `default`, `review`, `documentation`, `debugging` |
| `code`        | `coding`                                          |

### Нормализация (оценка пригодности для задачи)

Необработанные значения ELO нормализуются для каждого рейтинга в **значение пригодности для задачи в диапазоне `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

Оценка никогда не достигает `0` или `1`, оставляя пространство для переопределений пользователя. Это
поле `score`, которое вы видите в ответе API, и метка, отображаемая на панели управления.

### Достоверность

Каждая запись получает уровень достоверности на основе количества голосов Arena:

| Достоверность | Голоса  |
| ------------- | ------- |
| `high`        | ≥ 5 000 |
| `medium`      | ≥ 1 000 |
| `low`         | < 1 000 |

### Хранение и актуальность

Нормализованные записи записываются в таблицу БД `model_intelligence` с
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). Срок действия записей **истекает
через 7 дней**, поэтому поставщик, который перестаёт синхронизироваться, со временем исключается из рейтинга,
а не продолжает предоставлять устаревшие данные.

Синхронизация работает **по умолчанию**:

- Она запускается один раз при старте сервера, а затем по периодическому таймеру
  (`src/lib/arenaEloSync.ts`, подключённому из `src/instrumentation-node.ts`).
- Она **неблокирующая и никогда не приводит к сбою** — если загрузка из внешнего источника не удалась, OmniRoute продолжает
  работать, а рейтинги просто показывают последние корректные данные (или пустое состояние).

Две переменные окружения управляют ею (описаны в
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| Переменная                | По умолчанию  | Назначение                                                       |
| ------------------------- | ------------- | ---------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | Установите `false`, чтобы отказаться от исходящей синхронизации. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24ч) | Интервал синхронизации в секундах.                               |

### Ручная синхронизация / статус / очистка

Для операторов доступна конечная точка управления с аутентификацией, предоставляющая ручное управление
(`src/app/api/intelligence/sync/route.ts` — требует аутентификации управления):

```
GET    /api/intelligence/sync          # текущий статус синхронизации (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # запустить синхронизацию вручную; тело: { "dryRun": true } для предпросмотра без записи
DELETE /api/intelligence/sync          # удалить все синхронизированные записи intelligence arena_elo
```

Если страница рейтингов пуста, ручной `POST /api/intelligence/sync` (или просто
перезапуск сервера) повторно заполнит её.

### Сопоставление моделей с рейтингом

Идентификаторы моделей реестра и названия моделей Arena не всегда совпадают точно. Рейтинг использует
гибкое сопоставление (`findMatchingIntelligence` в `src/lib/freeProviderRankings.ts`):

1. Точное совпадение по нормализованному идентификатору модели.
2. Совпадение после удаления конечного суффикса версии (например, `kimi-k2.6` → `kimi-k2`).
3. Совпадение по префиксу (название модели из рейтинга является префиксом идентификатора реестра).

На стороне синхронизации известные префиксы поставщиков (`anthropic/`, `openai/`, `google/`, …)
удаляются, а небольшая таблица псевдонимов разворачивает канонические имена в варианты, которые OmniRoute использует
внутренне, так что модели остаются доступными для поиска под любым именем.

### Как ранжируется поставщик

Для каждого бесплатного поставщика движок оценивает каждую модель в его каталоге, затем:

- **Top Model** = модель поставщика с наивысшей оценкой.
- **Avg Score** = средняя оценка по всем оценённым моделям этого поставщика.
- **Models** = сколько моделей поставщика имело оценку Arena.

Поставщики сортируются сначала по **оценке лучшей модели**, затем по средней оценке. Это поощряет
поставщика, предлагающего хотя бы одну сильную бесплатную модель.

## Использование для выбора бесплатных провайдеров

1. **Выберите подходящую категорию.** Используйте фильтр **Coding** для агентных задач и задач, связанных с кодом, либо
   оставьте **All Categories** / **Default** для обычного чата. Один и тот же провайдер может
   занимать разные позиции в разных категориях, поскольку его лучшая модель различается в зависимости от рейтинга.
2. **Для простой настройки выбирайте лидеров.** Если вы хотите подключить только одного или двух бесплатных
   провайдеров, начните с занимающих самые высокие позиции в вашей категории.
3. **Проверьте метку Type.** Провайдеры `NOAUTH` подключаются быстрее всего (учётные данные
   не требуются). Бесплатные тарифы `OAUTH` / `APIKEY` требуют быстрой регистрации, но часто предоставляют
   доступ к более мощным моделям. Инструкции по подключению см. в [руководстве по бесплатным тарифам](../getting-started/FREE-TIERS-GUIDE.md).
4. **Подключите несколько провайдеров и позвольте Auto-Combo выбрать.** Те же данные Arena ELO, на которых
   основана эта страница, также используются для расчёта **коэффициента соответствия задаче** механизмом оценки Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`, порядок разрешения:
   `user_override → arena_elo → models_dev_tier → static table`). Поэтому после подключения
   ведущих бесплатных провайдеров маршрутизация с `model: "auto"` (например, `auto/coding`) будет
   автоматически отдавать предпочтение более качественным бесплатным моделям для каждого запроса. Полное описание оценки по 16 факторам см. в разделе
   [Auto-Combo](../routing/AUTO-COMBO.md).
