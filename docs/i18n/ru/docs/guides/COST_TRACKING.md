Как OmniRoute оценивает, записывает и отображает стоимость каждого запроса — и почему число на
панели мониторинга — это **счётчик экономии**, а не счёт.

См. также: [Руководство пользователя](./USER_GUIDE.md) · [Обзор возможностей](./FEATURES.md)

---

## Что это такое (и чем это не является)

OmniRoute рассчитывает стоимость каждого запроса в долларах США, умножая количество
токенов на тарифы модели. Эти значения используются на панели **Затраты**, в командах CLI
`omniroute cost` / `omniroute usage`, при экспорте в CSV/JSON и для бюджетов отдельных API-ключей.

> **«Стоимость» на панели мониторинга — это счётчик экономии, а не счёт.** OmniRoute никогда
> не взимает с вас плату — он направляет ваши запросы провайдерам, которых вы уже подключили
> (ваши собственные подписки, бесплатные тарифы и API-ключи). Если «общая стоимость $290»
> полностью набрана на бесплатных моделях, это означает, что вы **не заплатили примерно $290**
> платному API. Эта сумма — _оценка_ того, сколько стоил бы тот же трафик по стандартным
> публичным тарифам, позволяющая увидеть, где сосредоточено использование и сколько вы
> экономите благодаря маршрутизации к более дешёвым или бесплатным провайдерам.

Такое объяснение приведено непосредственно в файле [README](../../README.md) проекта
(«„стоимость“ на панели мониторинга — это счётчик экономии, а не счёт»).

Поскольку это оценочное значение:

- Оно зависит от таблицы цен OmniRoute для каждой модели. Модель без записи о цене
  добавляет `0` к стоимости (в обозревателе она отображается как строка «Устаревшая / Бесплатная»).
- Трафик бесплатных тарифов и подписок всё равно учитывается в _расчётной_ стоимости — это
  сумма, которую вы экономите, а не задолженность.

## Как оцениваются затраты

### Источник цен

Затраты берутся из объединенной таблицы цен в [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) в следующем порядке приоритета (** самый высокий первый** ):

1. **Пользовательские переопределения** Цены — устанавливаются на панели управления или через `PATCH /api/pricing` (пространство имен `pricing` ).
2. **синхронизация models.dev** Цены — получены из `https://models.dev/api.json` (пространство имен `models_dev_pricing` ).
3. **синхронизация LiteLLM** Цены — получены из общедоступного `model_prices_and_context_window.json` LiteLLM(пространства имен `pricing_synced` ).
4. **Жестко заданные значения по умолчанию** Тарифы — отправляются в [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/).

Для того же provider/model значения из слоев с более высоким приоритетом перезаписывают совпадающие поля в нижних слоях; поля, отсутствующие в верхнем слое, все же могут поступать из нижнего слоя. Порядок фиксирован, даже если оба независимых задания синхронизации выполняются одновременно. `GET /api/pricing?includeSources=1` возвращает `pricing` и `sourceMap`, чьи метки для каждой модели (`user`, `modelsDev`, `litellm`, `default`) идентифицируют слой с наивысшим приоритетом, содержащий эту модель.

**синхронизация LiteLLM** является добровольным, по умолчанию отключено. Его переменные среды (см. [`.env.example`](../../.env.example) ):

| Конверт вар             | По умолчанию | Цель                                                                                              |
| ----------------------- | ------------ | ------------------------------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`      | Включите фоновую синхронизацию цен LiteLLM.                                                       |
| `PRICING_SYNC_INTERVAL` | `86400`      | Интервал синхронизации в секундах (ежедневно).                                                    |
| `PRICING_SYNC_SOURCES`  | `litellm`    | Выбор источника только для этой синхронизации; в настоящее время поддерживается только `litellm`. |

**синхронизация models.dev** отделен от синхронизации LiteLLM и также отключен по умолчанию. Включите его в настройках (синхронизация models.dev) или используйте эти переменные:

| Конверт вар                | По умолчанию       | Цель                                                                                                                                                                     |
| -------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `MODELS_DEV_SYNC_ENABLED`  | _(не установлено)_ | Сброс следует за переключателем настроек; `1/true/on/yes` принудительно включается, а `0/false/off/no` принудительно отключается (даже если в настройках это разрешено). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`            | Интервал синхронизации models.dev по умолчанию в секундах (ежедневно).                                                                                                   |

`PRICING_SYNC_SOURCES` делает** нет** включить models.dev; он управляет только синхронизацией LiteLLM. Удаление переопределения пользователя не очищает ни одно синхронизированное пространство имен; вступает в силу следующий доступный уровень цен. Для модели без цены проверьте настройки синхронизации и `sourceMap`, прежде чем добавлять ручное переопределение.

### Формула стоимости

Стоимость рассчитывается за запрос на основе количества токенов и ставок за миллион токенов в [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`):

- **Входные токены** (за вычетом операций чтения кэша и токенов создания кэша) Скорость × `input`.
- **Токены чтения кэша** × `cached` скорость (возврат к входной скорости).
- **Токены создания кэша** × `cache_creation` скорость (возврат к входной скорости).
- **Выходные токены** × `output` курс.
- **Жетоны рассуждений** × `reasoning` скорость (возвращается к скорости вывода).

Все ставки интерпретируются как USD за 1 000 000 токенов. Уровень обслуживания Codex «быстрый», «приоритетный» или «гибкий» применяет множитель стоимости (`getCodexFastCostMultiplier`) — например, гибкий уровень выставляется со скидкой 50 %, отображаемой как** гибкая экономия** в приборной панели.

Имена моделей сначала нормализуются (префиксы пути поставщика, такие как `openai/` или `accounts/fireworks/models/` удаляются), поэтому исторические строки по-прежнему соответствуют цене.

### Как учитываются расходы

- Стоимость каждого запроса рассчитывается по завершении запроса. Потребление общей квоты запланировано на следующий такт цикла событий через [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts).
- Расходы API-ключа буферизуются и сбрасываются пакетно с помощью [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (интервал очистки по умолчанию 60 секунд, буфер на 1000 записей). Настраивается через:

  | Конверт вар                         | По умолчанию | Цель                                                          |
  | ----------------------------------- | ------------ | ------------------------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`      | Интервал промывки в миллисекундах.                            |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`       | Максимальное количество буферизованных записей перед сбросом. |

Затраты предпочитают точную сумму, сообщаемую поставщиком (`provider_cost_usd`), затем снимок запроса по цене каталога (`calculated_cost_usd`), а затем переоценку токенов из текущего каталога. Сохраненные затраты не взимаются повторно посредством подсчета токенов. Старые строки, содержащие только токены, по-прежнему изменяются при изменении цены в каталоге.

### OCR и встраивания

- Успешные запросы `/v1/ocr` используют восходящий `usage_info.pages_processed`, а не запрошенный диапазон страниц или количество возвращенных объектов страницы. Оценка составляет страниц × `ocr_cost_per_page` (абсолютное USD/page,** нет** USD/million).
- Запросы с аннотациями к документу или ограничивающей рамкой требуют отдельного тарифа `ocr_cost_per_annotated_page`. Без этого стоимость останется неизвестной; обычный тариф OCR не заменяется молча.
- LiteLLM sync сопоставляет свое восходящее поле `annotation_cost_per_page` с `ocr_cost_per_annotated_page`, сохраняя абсолютное значение USD/page и записи только для аннотаций, включая явный ноль. Предоставленное каноническое поле имеет приоритет; недопустимые значения псевдонимов игнорируются. Переопределения цен для пользователей сохраняют свой обычный приоритет. См. [ценовые ключи LiteLLM от OCR](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking).
- Использование OCR сохраняет количество страниц, цену за единицу, расчетную стоимость USD, ключ API и выбранное соединение. Страницы никогда не представляются как токены. Журналы вызовов содержат метаданные выставления счетов, а не документы URLs, PDF байты или извлеченный текст.
- Успешные запросы `/v1/embeddings` записывают одну строку использования для каждого физического пакета, включая отдельные пакеты, завершенные за одну и ту же миллисекунду. Плата, сообщаемая поставщиком, имеет приоритет над оценками токенов; комбинированные обертки не добавляют заряд.
- Эти расходы включают историю использования, аналитику затрат, окна provider/account, лимиты расходов на ключи API, реестр затрат на запросы и ежедневные сводные данные об использовании. Ключи без регистрации сохраняют числовой учет без сохранения исходного текста.
- Отсутствует использование или тарифы.** неизвестный** , не бесплатно: заголовок стоимости ответа опускается, а существующая политика использования без цены применяется к ограниченным ключам API. Явно настроенные нулевые тарифы остаются действительными при использовании с нулевой стоимостью.

Это форвардный учет. Старые вызовы OCR/embedding, которые никогда не записывали историю использования, невозможно восстановить с помощью этой миграции. Оценки каталога представляют собой оценки USD, а не счета-фактуры, и не включают конвертацию валюты, налоги или скидки.

### Речь и изображения

- Успешные попытки `/v1/audio/transcriptions`, `/v1/audio/speech` и создания изображений используют числовой учет. Прямые и комбинированные вызовы содержат ключ API вызывающего абонента и выбранное соединение; комбо-обертка никогда не добавляет второй дебет.
- USD, сообщаемая поставщиком, превосходит оценку по каталогу, включая явную нулевую плату. OpenRouterJSON для `usage.cost` нормализуется на `cost_usd`. В противном случае для измеренных токенов используются цены токенов, для секунд транскрипции используются посекундные цены, для речевого ввода используется количество символов Юникода, а для изображений с фиксированной ценой используется фактически возвращаемое число, а не запрошенный `n`.
- Двоичный OpenRouter TTS не имеет тела использования JSON. После завершения аудио или отмены вызывающей стороны OmniRoute запрашивает генерацию ID на** такой же** настроен источник OpenRouter. Запрос EU никогда не возвращается к глобальному источнику. Это ограниченный поиск только для чтения; синтез не повторяется для учета. Записи о выставлении счетов могут появиться после завершения аудио: повторные попытки поиска выполняются в фоновом режиме примерно до 52 секунд, включая крайние сроки сети.
- Во время этого поиска звуковой ответ имеет `X-OmniRoute-Cost-Status: pending` и не имеет заголовка стоимости ответа. Его окончательная стоимость отображается в истории использования, аналитике и книге ключей после сверки. Если метаданные недоступны, используется настроенный снимок тарифа; в противном случае стоимость останется неизвестной.
- Секунды, количество символов и изображений имеют отдельные поля единиц выставления счета, а не поддельное количество токенов. При учете сохраняются только числовые значения, а не речевой текст, расшифровки или байты изображений. Существующие исключения для изображений без цены не изменились: действительно отсутствующий тариф изображения не блокирует заново ограниченный ключ, а в ответе опускается заголовок стоимости, а не объявляется звонок бесплатным. В случае сбоя магазина цен по-прежнему сохраняются доказательства использования для принудительного закрытия при сбое.

Никакая историческая плата speech/image не придумывалась и не заполнялась заново. Выставление счетов поставщику остается ссылкой для счетов и звонков, стоимость которых не была указана.

## Панель управления: страница расходов

Страница **Расходы** находится по адресу `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`).
Её основное представление — вкладка **Обзор расходов**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
которая загружает все данные через `GET /api/usage/analytics`.

Что на ней отображается:

- **Карточки расходов** — оценочные расходы за _сегодня (1d)_, _7d_, _30d_ и выбранный
  период. Выбор диапазона: `7d`, `30d`, `90d`, `all`.
- **Основные показатели** — количество запросов за период, активные провайдеры, активные модели,
  средняя стоимость запроса.
- **Анализ расходов** — сортируемая и фильтруемая таблица с группировкой по **провайдеру**, **модели**,
  **API-ключу**, **учётной записи** или **уровню обслуживания**, содержащая стоимость, количество запросов, токенов, среднюю
  стоимость запроса и долю от общей суммы в процентах.
- **Использование токенов** — общее количество, входные и выходные токены, а также соотношение входных и выходных токенов.
- **Эффективность маршрутизации** — количество резервных переключений, частота резервных переключений и охват запрошенных моделей.
- **Месячный прогноз** — прогноз расходов к концу месяца на основе недавнего среднесуточного значения.
- **Сравнение периодов** — изменение в процентах между первой и второй половинами периода.
- **Графики** — динамика расходов по дням, доля провайдеров (круговая диаграмма), ведущие провайдеры, ведущие модели, расходы
  по API-ключам, расходы по учётным записям, недельная структура использования и тепловая карта активности.
- **Экспорт** — загрузка данных за текущий период в формате **CSV** или **JSON** (кнопки появляются,
  когда имеются данные с ненулевой стоимостью).

При отсутствии тарифицируемого трафика вместо `$0` в строках отображается метка «Устаревшее / Бесплатное»,
что соответствует модели отслеживания экономии.

### Связанные подразделы расходов

Раздел «Расходы» также содержит следующие страницы (все находятся в `/dashboard/costs/`):

- **Ценообразование** (`/dashboard/costs/pricing`) — просмотр и переопределение цен для отдельных моделей (отображает
  общую вкладку «Ценообразование»).
- **Бюджет** (`/dashboard/costs/budget`) — настройка лимитов расходов для отдельных областей (отображает общую
  вкладку «Бюджет»).
- **Совместное использование квоты** (`/dashboard/costs/quota-share`) — пулы общих квот и представления
  скорости их расходования.

## конечные точки API

Все это требует аутентификации управления (loopback/JWT, через `requireManagementAuth`), если не указано иное.

### Аналитика использования и затрат

| Метод | Конечная точка           | Цель                                                                                                                                                             |
| ----- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | Полная аналитика cost/usage : сводка, дневной тренд, автор provider/model/API key/account/tier. Запрос: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET` | `/api/usage/utilization` | Использование квоты каждого поставщика с течением времени. Запрос: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                  |
| `GET` | `/api/usage/history`     | Необработанные строки истории использования.                                                                                                                     |
| `GET` | `/api/usage/call-logs`   | Журналы вызовов по запросу (модель, токены, стоимость, задержка, статус).                                                                                        |
| `GET` | `/api/usage/quota`       | Статус квоты провайдера.                                                                                                                                         |
| `GET` | `/api/usage/proxy-logs`  | Журналы запросов прокси.                                                                                                                                         |

### Бюджеты

| Метод  | Конечная точка           | Цель                                                                                                |
| ------ | ------------------------ | --------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | Сводная стоимость проверки бюджета + для одного ключа API (требуется параметр запроса `apiKeyId` ). |
| `POST` | `/api/usage/budget`      | Установите порог daily/weekly/monthly USD для предупреждения + для ключа API.                       |
| `GET`  | `/api/usage/budget/bulk` | Массовые сводки бюджета по ключам API.                                                              |

> Бюджет API ограничен** ключ API** (`apiKeyId`). Пределы, возвращаемые `GET /api/usage/budget` включают `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`, a `warningThreshold` и текущие итоги (`totalCostToday`, `totalCostMonth`, …).

### Цены

| Метод    | Конечная точка          | Цель                                                                                                                                                                                               |
| -------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | Объединенное четырехуровневое ценообразование (пользователь, models.dev, LiteLLM, значения по умолчанию). `?includeSources=1` возвращает `pricing` + `sourceMap`.                                  |

| `GET`    | `/api/pricing/defaults` | Показывать резервные ставки per-1M по умолчанию.                                                                                                                                                   |
| `GET`    | `/api/pricing/models`   | Цены в зависимости от модели.                                                                                                                                                                      |
| `POST`   | `/api/pricing/sync`     | Запустите ручную синхронизацию из внешних источников (LiteLLM).                                                                                                                                    |
| `GET`    | `/api/pricing/sync`     | Текущий статус синхронизации.                                                                                                                                                                      |
| `DELETE` | `/api/pricing/sync`     | Очистить только цены, синхронизированные с LiteLLM (`pricing_synced`); Данные models.dev являются отдельными.                                                                                      |

## CLI

CLI OmniRoute предоставляет команды для работы с расходами, использованием и ценами (зарегистрированы в
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

Отчёт о расходах, агрегированный на основе `/api/usage/analytics`.

```bash
omniroute cost                          # последние 30 дней, группировка по провайдеру
omniroute cost --period 7d              # последние 7 дней
omniroute cost --group-by model         # группировка: provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

Столбцы: группа, запросы, входящие/исходящие токены, стоимость (USD) и доля от общей суммы в процентах. В конце
выводится строка с общей суммой (не выводится при использовании `--quiet` или `--output json`).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # сводка расходов по каждому провайдеру
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# Бюджеты
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` считывает данные из `GET /api/pricing/defaults`. Чтобы изменить цены
> отдельных моделей, используйте страницу **Pricing** на панели управления или `PATCH /api/pricing`.

## Устранение неполадок

- **Все расходы отображаются как $0 / «Legacy / Free».** Для используемых моделей отсутствуют записи о ценах.
  Включите внешнюю синхронизацию (`PRICING_SYNC_ENABLED=true`) и выполните `omniroute pricing sync` либо
  задайте цены вручную на странице Pricing или через `PATCH /api/pricing`.
- **Цена ранее использованной модели указана неверно.** Исправьте цену (переопределите её или выполните повторную синхронизацию) — расходы
  пересчитываются на основе количества токенов при каждом чтении аналитики, поэтому оценки обновляются ретроспективно.
- **Данные о расходах отстают от реального времени.** Расходы по ключам обрабатываются пакетно; уменьшите
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS`, если вам нужны более актуальные данные.
