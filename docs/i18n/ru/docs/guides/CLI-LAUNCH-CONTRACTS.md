Нейтральный контракт `config/cli-tools-manifest.json` объявляет канонический IDs, псевдонимы, бинарные кандидаты, рецепты настройки, аргументы модели и возможности. Простой адаптер Node в `bin/cli/cli-manifest.mjs` и адаптер TypeScript в `src/shared/constants/cliIntegrationManifest.ts` читают один и тот же файл. Время выполнения, каталог, настройка, завершение, генераторы и регистрация бэкэнда проверяются вместе `tests/unit/cli/cli-manifest-drift.test.ts`. Наличие каталога не означает, что инструмент можно запустить или настроить. В частности, 5dive остается доступным только для настройки.

## Окружающая среда и жизненный цикл ребенка

`omniroute run`, `omniroute launch` и `omniroute launch-codex` наследуют список разрешений совместимости OS/terminal и внедряют учетные данные выбранной цели. Секреты несвязанного поставщика и базы данных по умолчанию не наследуются. `--inherit-env` явно восстанавливает полное наследование родительской среды; используйте его только тогда, когда выбранный сторонний процесс должен получить эти значения. Это фильтрация среды, а не изолированная программная среда OS : процесс по-прежнему выполняется с разрешениями файловой системы вызывающего объекта.

Сигналы прерывания и завершения передаются дочернему процессу. Средство запуска ожидает события закрытия дочернего элемента, прежде чем удалять временную конфигурацию. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` управляет льготным периодом перед принудительным завершением (по умолчанию 5000 миллисекунд).

## постоянная настройка Gemini

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

Первые две команды настраивают этот компьютер для выбранного локального или удаленного сервера. Программа установки сохраняет несвязанные настройки JSON, выбирает аутентификацию с помощью ключа API Gemini и записывает конечную точку и учетные данные в частный файл `.gemini/.env`. Он отклоняет недействительный JSON, а не перезаписывает его. Конечная точка URLs должна быть HTTP(S) без встроенных учетных данных, параметров запроса или фрагментов. При пробном прогоне печатаются пути, а не значения учетных данных.

`GEMINI_CLI_HOME` или `--gemini-home` выбирает постоянный домашний корень. Фактический `run gemini` создает, а затем удаляет свой временный дом. Ни один из режимов не обходит проверки доверия рабочей области Gemini.

## профили Codex

`configure codex` записывает частный `<name>.config.toml` с моделью и конечной точкой поставщика OmniRoute. Ссылка на учетные данные осуществляется через `OMNIROUTE_API_KEY` и никогда не внедряется. Команда запуска устанавливает выбранную модель в ключе `model` верхнего уровня, а не внутри `model_providers`.

Отдельные файлы профиля представляют собой текущий документированный контракт Codex ; они накладываются на пользовательскую конфигурацию, если выбраны с помощью `codex --profile <name>`. См. [официальную ссылку на профиль](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) и [руководство OmniRoute Codex](./CODEX-CLI-CONFIGURATION.md).

## Герметичное выполнение команды

При явном указании `DATA_DIR` установка `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` предотвращает попадание при запуске в среду учетных данных каталога пользовательских данных по умолчанию. Это полезно для изолированных тестов. Он не отключает другие явно выбранные файлы среды.

## Рабочий каталог `.env`

CLI читает файлы `.env` в следующем порядке, и побеждает тот файл, который первым установил ключ: явный `DATA_DIR`, каталог данных по умолчанию, текущий рабочий каталог, затем каталог пакета. Переменные оболочки всегда выигрывают.

Рабочий каталог может принадлежать кому-то другому (клонированному репозиторию, распакованному архиву), и `omniroute serve` передает среду CLI на сервер и каждому инструменту, который запускает сервер. Таким образом, `.env` может устанавливать только эти ключи, перечисленные в `bin/cli/utils/untrustedCwdEnv.mjs`:

| Ключ                            | Принятые значения                                                              |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `REQUIRE_API_KEY`               | `true`, `1` или `yes` в любом случае значения, которые сервер воспринимает как |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | до 64 букв, цифр, `_`, `.`, `@` или `-`                                        |
| `LANGUAGE`                      | то же самое, плюс `:`                                                          |
| `TZ`                            | до 64 букв, цифр, `_`, `+`, `-` или `/`, не начинающихся с `/`                 |
| `NO_COLOR`, `FORCE_COLOR`       | до 16 букв и цифр                                                              |

Каждое значение, принимаемое `REQUIRE_API_KEY`, включает проверку, поэтому файл не может отключить проверку самостоятельно. Однако это не определяет результат: сервер считывает переопределение `REQUIRE_API_KEY`, хранящееся в базе данных, до среды, в то время как предупреждение при запуске о прослушивании всех интерфейсов без ключа API считывает только среду. При сохраненном переопределении `false` рабочий каталог `REQUIRE_API_KEY=true` оставляет API открытым и скрывает это предупреждение. Правило `TZ` уже, чем POSIX: оно отвергает `.`, `:`, `,` и `<>`, поэтому форма `:Area/City` и правила, такие как `EST5EDT,M3.2.0,M11.1.0` должны быть установлены в оболочке или в `<DATA_DIR>/.env`.

Имена должны совпадать точно, в верхнем регистре. Любая другая строка, значение, не прошедшее проверку, а также имя, не состоящее из простых букв, цифр и `_` ASCII например, имя с байтом NUL или похожей буквой), пропускаются. CLI печатает одно предупреждение с именами ключей, которые он не может установить, и одно с именами разрешенных ключей, которые он игнорирует, каждое с указанием того, что нужно изменить (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Ни один из них не печатает значения. Пути к файлам в этих сообщениях и отчетах `.env` о пути `omniroute doctor` экранируются, если они содержат символы управления или двунаправленного текста. Ограничение не применяется, если рабочим каталогом является каталог данных или каталог пакета.

`PORT`, `API_PORT` и `DASHBOARD_PORT` нет в списке. Без базового URL из источника с более высоким приоритетом CLI обращается к `localhost:<PORT>`, и все, что там прослушивает, получает ключ API CLI, токен контекста и машинный токен CLI (`x-omniroute-cli-token`, см. [CLI_TOKEN](../security/CLI_TOKEN.md) ), которые локальный сервер принимает для вызовов управления из шлейфа. Порт из рабочего каталога позволит этому файлу выбрать прослушиватель, поэтому установите порты в оболочке, в `<DATA_DIR>/.env` или с помощью опции `--port` команд, которые ее имеют (`serve`, `launch`, `run`).

В парсере нет синтаксиса `export`. Строка типа `export LD_PRELOAD=...` называет переменную `export LD_PRELOAD`; из рабочего каталога он пропускается, а в других `.env` файлах задает то самое буквальное имя, которое ничего не читает.

CLI связывает сохраненный токен контекста (токен доступа или устаревший ключ API ) только с собственным источником этого контекста: схемой, хостом и портом, по сравнению с `URL.origin`. Это относится к запросам, сделанным через клиент HTTP CLI(`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`), а также к командам `launch`, `launch codex`, `configure` и `setup-*`, которые записывают базовый URL и ключ в конфигурацию другого инструмента. Направляясь на другой сервер с помощью `--remote`, они используют явный `--api-key` или `OMNIROUTE_API_KEY` если он установлен, и не используют токен контекста. Сравнение является точным, поэтому `localhost` и `127.0.0.1` или хост с конечной точкой или без нее считаются разными серверами и не получают маркера контекста. URL с информацией о пользователе, обратной косой чертой или пробелом никогда не совпадает, потому что другие парсеры URL (например, `urllib` и `httpx` Python) могут читать с него другой хост. Для запросов, которые CLI отправляет сам, эта проверка охватывает только схему и полномочия, поэтому идентификатор с пробелом в пути или запросе сохраняет токен.
