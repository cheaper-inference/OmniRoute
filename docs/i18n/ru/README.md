## Бесплатные токены в месяц: ~ 11,3B, как считают другие · ~ 90M Real

</div>

> **~ 11,3 млрд бесплатных токенов в месяц**<br/> <sub> считался так же, как и другие каталоги: суммировалась каждая строка, включая завершенные предложения </sub>
>
> **~ 90M реально сегодня**<br/> <sub> каждая общая квота учитывается один раз: что на самом деле можно использовать </sub>
>
> **Здесь все бесплатно. Нет платного доступа.**<br/> ★ [Понравилось? Поставьте нам звезду на GitHub](https://github.com/cheaper-inference/OmniRoute)

Другие каталоги взимают от US до 49 долларов US в год за пожизненный доступ к актуальным данным. Здесь все бесплатно. <sub> Цены проверены 18 ноября 2026 г.</sub>

<sub>Последний раз каталог проверялся 23 ноября 2026 г. [Как мы считаем →](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **Принесите свои собственные учетные записи провайдера.** Это сторонние уровни бесплатного пользования, а не гранты токенов от OmniRoute. Зарегистрируйтесь, получите учетные данные там, где их запрашивает провайдер, и подключите те, которые вы можете использовать. Каждый провайдер устанавливает свои лимиты, доступность и условия.
>
> Ручное накопление бесплатных уровней означает десятки SDKs, десятки ограничений по скорости и отсутствие четкого представления о том, что у вас осталось. OmniRoute хранит 214 строк каталога со свободным доступом и вычисляет реальную цифру по 12 пулам с опубликованной квотой, при этом каждый общий пул учитывается один раз. Квоты, которые открываются только после региональной проверки личности (сегодня ModelScope), отображаются отдельно, +~ 6M после региональной проверки личности, и никогда не добавляются к реальной цифре. То, что осталось, отображается на приборной панели (`/dashboard/free-tiers`).

The bar shows where the real figure comes from, one segment per pool. Signup credits and free providers without a token cap are listed apart and never added to it. Live used and remaining tokens on /dashboard/free-tiers."/>

>
> Каталог <sub> последний раз проверялся 23 ноября 2026 г. Фигуры движутся в обе стороны. Поставщик завершает бесплатный уровень, и реальное число падает. Новый приземляется и поднимается. Мы публикуем то, что рассчитывает каталог, а не округленный лучший вариант.</sub>

## Установите, подключите провайдера и выполните маршрутизацию через одну конечную точку.

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>`auto` нужен подходящий маршрут. В новой установке не может быть подходящих целей без ключа, и поставщик бесключевых услуг может отклонять сторонние клиенты. Провайдеры с пометкой `tos: avoid`, включая Kiro, по умолчанию исключены из автоматической маршрутизации; подключение учетной записи не отменяет эту настройку. Прежде чем выбирать поставщика, ознакомьтесь [с Руководством по уровням бесплатного пользования](docs/getting-started/FREE-TIERS-GUIDE.md).</sub>

<sub>Скопируйте и вставьте сценарии быстрого запуска для** Python, Node.js, PHP и cURL** : [`examples/quickstart/`](examples/quickstart/). Пошаговая версия: [Быстрый старт](#quick-start).</sub>

## Комбо: флагман

1. **Начните с `auto`.** Установите модель в своем OpenAI-совместимом клиенте. OmniRoute создает виртуальную компанию из подключенных поставщиков и оценивает кандидатов в режиме реального времени.
2. **Сохраните комбо для большего контроля.** Выберите имя, целевой список и стратегию, а затем используйте это имя в качестве модели. Стратегия определяет, какая цель будет достигнута в первую очередь и как будут реализовываться остальные.

Комбинация автоматически маршрутизируется по моделям. В случае исчерпания квоты, сбоя поставщика или блокировки модели он пытается использовать следующую подходящую работоспособную цель.

Варианты настройки весов. Последняя удачная маршрутизация остается у последнего успешного поставщика до тех пор, пока он не выйдет из строя, а затем восстанавливается. `auto/fast` и `auto/cheap` выражают предпочтения, не гарантируя самую быструю или дешевую модель.

Вес варьируется в зависимости от профиля. Привязка кэша, привязка окна сброса и надежность по умолчанию имеют нулевой вес. ### Устойчивость встроена: 3 независимых уровня

Сбои обрабатываются в трех областях, поэтому одна плохая модель не удаляет свою учетную запись, а другая плохая учетная запись не удаляет своего поставщика.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Если весь провайдер не работает

**автоматический выключатель провайдера** открывается после 8 (OAuth) или 12 ( ключ API ) сбоев со статусом 408, 500, 502, 503 или 504. Комбинации пропускают этого поставщика, пока он открыт. Через 60 или 30 с один тестовый запрос решает, закроется ли он.

#### Если один ключ или аккаунт ограничен по скорости

**время восстановления соединения** проверяет только это соединение с экспоненциальной задержкой от 5 с (OAuth) или 3 с (ключ API ). Другие ключи того же провайдера продолжают работать.

#### Если от одной модели отказываются

**блокировка модели** блокирует только эту модель в этом соединении после ошибок 429, 404 или отказа в доступе для каждой модели. Другие модели, подключенные к тому же соединению, продолжают работать.

Заблокированные, просроченные соединения и соединения с исчерпанным кредитом — это терминальные состояния, а не время восстановления: они ждут, пока вы их исправите.

## OmniRoute Радар

Radar — это действующая подписанная копия каталога бесплатного уровня, описанного выше, и она бесплатна для всех. Платного доступа и периода ожидания нет. Это возможность подписки и только GET. Клиент OmniRoute ничего не отправляет в Radar: никаких запросов, трафика, конфигурации провайдера или телеметрии об использовании.

Приведенные выше цифры взяты из каталога, поставляемого с этой версией. Радар может показывать новые данные между выпусками. Новые бесплатные предложения и акции добавляются каждую неделю. Наблюдайте за ростом реального числа на радаре.

## Совместимые CLIs и агенты кодирования

В каталоге приборной панели перечислены** 39 интеграций** (28 инструментов кодирования и 11 агентов). Манифест CLI добавляет Gemini CLI, который запускается с `omniroute run`, и четыре инструмента, которые он может только обнаружить. Из всех них,** 8** запустить с помощью `omniroute run`,** 12** можно настроить с помощью `omniroute configure` и** 16** иметь специальную команду `setup-*`. Выберите путь, который соответствует тому, что вы хотите.

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"
omniroute setup-whycodes && omniroute run whycodes --model glm/glm-5.2

# Or pick provider and model interactively and write the tool's own config:
omniroute configure codex   # also: claude opencode qwen aider goose gemini whycodes cline continue kilo 5dive
```

Каждая команда учитывает активный удаленный контекст (`omniroute connect <host>`). `--dry-run` печатает точные значения env и args, ничего не запуская, а `--api-key-env NAME` сохраняет ключ в истории вашей оболочки. Код Qwen и Gemini CLI запускаются во временном доме, который удаляется при выходе. WhyCodes считывает своего провайдера только из `config.toml`, поэтому запустите `setup-whycodes` один раз перед `run whycodes`. → [Интеграция CLI](docs/guides/CLI-INTEGRATIONS.md)

### OmniCopilot: OmniRoute внутри собственного Copilot чата VS Code

> Нет новой боковой панели и нового чата UI. Установить**OmniCopilot** , запустите сервер OmniRoute (расширение по умолчанию — `http://localhost:20128`), затем откройте Copilot Chat средство выбора модели → →** Управление моделями…** →**OmniRoute** и отметьте нужные модели. В редакторе вы также можете открыть** Расширения** просмотр, поиск** "OmniRoute"** и нажмите** Установить** .

## Полная CLI, MCP и A2A

> OmniRoute поставляет клиент командной строки с** 91 команда и группы команд верхнего уровня** (754 команды, считая подкоманды),** сервер MCP со 110 инструментами и 33 областями действия** и** агент A2A с 6 навыками** . Скрипты, терминалы и агенты AI могут работать с одним и тем же шлюзом.

### Настоящая CLI, а не просто `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

Глобальный флаг `--output table|json|jsonl|csv` позволяет использовать одни и те же команды из скриптов и CI.

### Удаленный режим: CLI на вашем ноутбуке, OmniRoute на сервере

Войдите один раз на удаленный сервер. CLI сохраняет его как** контекст** , и последующие команды выполняются на этом сервере, пока вы не переключитесь обратно.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Область действия токена | <img width="2000" height="0" alt=""> Что это позволяет                    |
| ----------------------- | ------------------------------------------------------------------------- |
| `read`                  | Составьте список и проверьте: модели, статус, журналы, использование.     |
| `write`                 | `read` plus настроить и применить: настройка клиента, ключи, конфигурация |
| `admin`                 | `write` plus manage: токены, провайдеры, услуги, политика                 |

Голый хост получает `http://` и порт 20128; передать полный `https://` URL когда сервер находится за TLS. Маршруты, которые могут порождать процессы, остаются только петлевыми, независимо от токена.

### Подключить агента

Агент или ваш собственный код может управлять маршрутизацией, поставщиками, комбинациями, кешем, сжатием и памятью через любой из этих интерфейсов. Пути HTTP обслуживаются шлюзом, по умолчанию `http://localhost:20128`.

| Интерфейс                 | Конечная точка или команда | Используйте его для                                                                                       |
| ------------------------- | -------------------------- | --------------------------------------------------------------------------------------------------------- |
| MCP через stdio           | `omniroute --mcp`          | Claude Desktop, Cursor и другие локальные клиенты MCP                                                     |
| MCP через Streamable HTTP | `/api/mcp/stream`          | Удаленные клиенты MCP : 110 инструментов, 33 области действия, каждый вызов записывается в журнал аудита. |
| MCP вместо SSE            | `/api/mcp/sse`             | Клиенты, которые все еще используют транспорт SSE                                                         |
| открытие A2A              | `/.well-known/agent.json`  | Карточка агента: сообщает другим агентам, что может делать OmniRoute                                      |
| выполнение A2A            | `POST /a2a`                | Задачи JSON-RPC 2.0, синхронные или потоковые через SSE, по 6 навыкам                                     |
| REST API                  | `/v1/*`                    | Чат, совместимый с OpenAI, ответы, встраивания, изображения, аудио и OCR                                  |
| Вебхуки                   | `/api/webhooks`            | События для Slack, Discord, Telegram или любого URL с подписью HMAC                                       |
| Удаленная CLI             | `omniroute connect <host>` | Управление удаленным экземпляром с помощью токенов доступа с ограниченной областью действия               |

Шесть навыков A2A — это `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` и `list-capabilities`.

**Прежде чем подключиться:**

- **запуск MCP поверх HTTP отключен.** Включите его с помощью `omniroute mcp enable --transport streamable-http` или на странице конечных точек панели управления. Одновременно активен один транспорт HTTP : `streamable-http` обслуживает `/api/mcp/stream`, `sse` обслуживает `/api/mcp/sse`.
- **A2A запускается отключенным.** Включите его на странице «Конечные точки» панели управления. Тогда `POST /a2a` следует тем же правилам использования ключей API, что и `/v1`.
- **Удаленной MCP нужен подходящий ключ.** `/api/mcp/*` по умолчанию отвечает только на петлю. С другого хоста отправьте ключ с помощью `manage` или `admin` (все инструменты) или с помощью `mcp:connect` плюс набор необходимых вам инструментов. Для ключей без `manage`/`admin` всегда применяются области действия инструмента.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

## Сэкономьте 15–95% токенов — автоматически

### Как это работает: конвейер —, архитектура и математика экономии

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

По умолчанию сложенная комбинация запускает `RTK → Caveman`. Когда оба действуют на одну и ту же полезную нагрузку tool/context, экономия увеличивается:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Блоки кода, URLs, JSON и структурированные данные** всегда защищен** с помощью механизма сохранения.

> **Зачем использовать много токенов, когда мало токенов делают свое дело?** Каждый запрос проходит через конвейер сжатия OmniRoute** прозрачно** — клиент не меняется. Теперь это** стопка из 12 сборных двигателей** которые выполняются по порядку и смешиваются и сопоставляются для каждой комбинации маршрутизации — основанной на идеях [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) и [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

#### Стили вывода

| Стиль                                       | <img width="2000" height="0" alt=""> Что он делает                                                 |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------- |

## Дополнительные способы установки — Docker, источник, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` следует за самым высоким** опубликовано** стабильный SemVer. Он не отслеживает git `main`. Закрепите `:X.Y.Z` для GitOps. См. [каналы выпуска Docker](docs/guides/DOCKER_GUIDE.md#release-channels). Изображения закреплены.**`OMNIROUTE_MEMORY_MB=1024`** . Этого достаточно для приборной панели и легкого чата.** Кодирующие агенты** (`POST /v1/responses` из кода Claude, Codex, Grok, …) требуется гораздо большая куча V8 или процесс `FATAL ERROR` s с ~ 12 GiB в двух перекрывающихся длинных контекстах. Размер контейнера выше кучи (родные буферы находятся за пределами V8):

| <img width="2000" height="0" alt=""> Рабочая нагрузка | Куча (`-e OMNIROUTE_MEMORY_MB`)   | Контейнер (`--memory`) |
| ----------------------------------------------------- | --------------------------------- | ---------------------- |
| Панель управления/легкий чат                          | `1024` (изображение по умолчанию) | ≥ 2 г                  |
| Один агент кодирования                                | `8192`                            | ≥ 10 г                 |
| Два одновременных длинных `/v1/responses`             | `10240`–`12288`                   | ≥ 12–16 г              |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Полная таблица: [Руководство Docker во время выполнения — RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Предварительная версия канала Docker :** `diegosouzapw/omniroute:next` и `diegosouzapw/omniroute:next-web` следуют за текущей веткой `release/v*` по умолчанию. Эти изменяемые теги предназначены только для тестирования невыпущенных исправлений и** не поддерживается для производства** . См. [Каналы выпуска Docker](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

Стандартная `bun install` и глобальная установка (`bun install -g omniroute`) поддерживаются посредством обнаружения во время выполнения Bun :

- **Встроенный `bun:sqlite`** : OmniRoute использует встроенный в `bun:sqlite` драйвер Bun при работе под Bun, возвращаясь к `better-sqlite3` на Node.js или `sql.js`.
- **Автоматический выбор упаковщика Webpack в разработке** : Разработка (`bun run dev`) автоматически обнаруживает Bun и отключает Turbopack в пользу Webpack, чтобы предотвратить несовместимость встроенных привязок V8. Производственные сборки (`bun run build`) следуют за `OMNIROUTE_USE_TURBOPACK` точно так же, как и в Node: Turbopack по умолчанию, `OMNIROUTE_USE_TURBOPACK=0` для сборки с помощью Webpack (`Dockerfile.bun` представляет его как `--build-arg`).
- **Выделенный Docker-файл Bun** : Многоэтапный `Dockerfile.bun` для собственных производственных развертываний Bun (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ Быстрая и экономичная установка (пропустите встроенную сборку)**

Собственный движок SQLite (`better-sqlite3`) — это** необязательный** зависимость, поэтому глобальная установка никогда не блокирует компиляцию из исходного кода: она использует готовый двоичный файл, если он соответствует вашему platform/Node, а в противном случае прозрачно возвращается к движку чистого JS (`node:sqlite` на узле 22 +, в противном случае встроенный `sql.js` WASM) — никаких инструментов сборки не требуется.

Чтобы пропустить пост-установку** родная разминка** полностью (CI, безголовые или медленные машины). Примечание. При этом пропускается только этап прогрева встроенного SQLite (`scripts/postinstall.mjs`); перехватчик binary-copy/repair (`scripts/build/postinstall.mjs`) по-прежнему работает нормально:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

Для самой быстрой установки предпочитайте** пнпм** (хранилище с адресацией содержимого + жесткие ссылки — см. выше). Для автономной среды выполнения без информационной панели используйте профиль Docker `base` (выше) или [руководство Termux](docs/guides/TERMUX_GUIDE.md). CLI и веб-панель обслуживаются одним и тем же процессом на одном порту, поэтому на сегодняшний день не существует отдельного пакета только для CLI.

### Как внести свой вклад

1. Форкнуть репозиторий
2. Филиал от** активный** Совет `release/vX.Y.Z` (не `main`) — см. [Модель ветвления и выпуска.](docs/ops/BRANCHING_MODEL.md)
3. Создайте свою ветку функций (`git checkout -b feat/amazing-feature`)
4. Зафиксируйте изменения (`git commit -m 'feat: add amazing feature'`)
5. Нажмите на ветку (`git push origin feat/amazing-feature`)
6. Откройте запрос на включение с помощью** база = и филиал `release/vX.Y.Z`**

См. [CONTRIBUTING.md](CONTRIBUTING.md) для получения подробных рекомендаций.

# Create a release — npm publish happens automatically

gh release create "v${VERSION}" --title "v${VERSION}" --generate-notes
