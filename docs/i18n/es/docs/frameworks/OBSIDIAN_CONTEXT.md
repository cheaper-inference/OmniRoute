> `src/app/api/settings/obsidian/webdav/route.ts` (API de configuración). El registro de herramientas

## Qué es

OmniRoute se conecta a una bóveda de **Obsidian** como **fuente de contexto**: una base
de conocimiento local en Markdown que los agentes leen y escriben mediante el servidor MCP
integrado. La integración se comunica con el plugin comunitario **Obsidian Local REST API** que
se ejecuta dentro de la aplicación de escritorio, por lo que los agentes pueden buscar notas,
leer/escribir/aplicar parches a archivos, listar la bóveda, trabajar con notas periódicas
diarias/semanales, gestionar etiquetas, ejecutar comandos de Obsidian y, opcionalmente,
coordinar una sincronización bidireccional de la bóveda entre escritorio y móvil.

El cliente (`src/lib/obsidian/api.ts`) encapsula la Local REST API con:

- **Reintentos con espera incremental** para errores transitorios `5xx` y un **tiempo de espera de 30 segundos** mediante `AbortController`.
- **Clasificación tipada de errores**: `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Una **indicación clara de que no se puede acceder a Obsidian** que señala el error
  habitual de puerto (HTTP en `27123`, **no** el endpoint MCP en `27124`) y el formato de Tailscale.
- **Codificación de rutas** relativas a la bóveda para que las rutas de notas con espacios o barras sean seguras.

## Configuración

**No hay ninguna variable de entorno** para el token ni para la URL base de Obsidian: ambos se
almacenan en la tabla `key_value` de SQLite (espacio de nombres `obsidian`) mediante
`src/lib/db/obsidian.ts`. El token está **cifrado en reposo** (AES-256-GCM, con
compatibilidad retroactiva mediante texto sin formato como alternativa). Configúralos desde la pestaña **Fuentes de contexto** del
panel de Endpoint (`ObsidianSourceCard`) o mediante la API REST de configuración.

> [!IMPORTANT]
> El plugin **Obsidian Local REST API** debe estar instalado y en ejecución. Su interfaz
> REST escucha en **HTTP `127.0.0.1:27123`** (la URL base predeterminada). El puerto `27124`
> es un endpoint MCP/HTTPS _independiente_ y la ruta de configuración lo rechaza explícitamente.
> Si te conectas desde otro dispositivo, utiliza `http://<tailscale-ip>:27123`.

### Claves de configuración (tabla `key_value` de SQLite, espacio de nombres `obsidian`)

| Clave             | Propósito                                                       | Cifrado |
| ----------------- | --------------------------------------------------------------- | ------- |
| `api_key`         | Token de portador de la API REST local                          | sí      |
| `base_url`        | URL base de REST (predeterminada: `http://127.0.0.1:27123`)     | no      |
| `vault_path`      | Ruta absoluta al directorio de la bóveda (para sincronizar)     | no      |
| `webdav_username` | Nombre de usuario WebDAV generado (sincronización de bóveda)    | no      |
| `webdav_password` | Contraseña WebDAV generada (sincronización de bóveda)           | sí      |
| `webdav_enabled`  | Indica si la sincronización WebDAV de la bóveda está habilitada | no      |

### Configuración mediante REST

```bash
# Guarda y valida el token de la API REST local (POST lo valida mediante una comprobación de estado)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Comprueba el estado de la conexión (devuelve connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Desconecta (elimina el token almacenado)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Todos los métodos requieren autenticación en el panel. `POST` rechaza cualquier URL que utilice el puerto `27124`
y valida el token llamando al endpoint de estado de la API REST local antes de almacenarlo.

### Sincronización de la bóveda mediante WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` gestiona una sincronización opcional de la
bóveda respaldada por WebDAV (controlada por `src/lib/obsidianSync.ts`). Al habilitarla, OmniRoute apunta a un
directorio de bóveda local y genera aleatoriamente un par de nombre de usuario y contraseña de WebDAV:

```bash
# Habilita la sincronización WebDAV para un directorio de bóveda (genera un nombre de usuario y una contraseña)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Obtiene el estado de la sincronización WebDAV (las credenciales solo se devuelven mientras está habilitada)
curl http://localhost:20128/api/settings/obsidian/webdav

# Deshabilita la sincronización WebDAV (elimina las credenciales y el archivo .stignore gestionado)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Seguridad y Transporte

La autenticación WebDAV aplica el seguimiento y bloqueo de fallas por IP (10 intentos fallidos dentro de una ventana de 60 segundos desencadenan un bloqueo de 5 minutos con `429 Too Many Requests` y `Retry-After`). Debido a que WebDAV transmite credenciales de autenticación básica, se recomienda encarecidamente finalizar TLS (o enrutar a través de un túnel seguro como Tailscale o Cloudflare Tunnel) al acceder al punto final WebDAV fuera del loopback.

### Fuente de contexto por clave de API (opcional)

La configuración de Obsidian puede definirse **por clave de API** mediante la tabla `api_key_context_sources`
(`src/lib/db/apiKeyContextSources.ts`). Cuando una llamada MCP incluye un id de clave de API
autenticado, `getObsidianConfigForApiKey()` da prioridad al token, la URL base y la ruta de la bóveda
propios de esa clave (`source: "api_key"`); de lo contrario, utiliza la configuración global como alternativa (`source: "global"`).

Las herramientas MCP que no son de sincronización requieren una identidad de invocador resuelta antes de leer esta configuración.
Un invocador sin identidad recibe `Obsidian API token not configured` y no se envía ninguna solicitud
a la bóveda. Los invocadores HTTP se resuelven mediante las credenciales de su solicitud; los invocadores stdio
pueden resolverse mediante `OMNIROUTE_API_KEY` o `ROUTER_API_KEY`. Un invocador HTTP no resuelto
no puede heredar la identidad de entorno del servidor. Los ID de marcador de posición por sí solos no autorizan
el acceso; sigue siendo compatible una credencial de entorno válida que se resuelva como `env-key`.
Las claves autenticadas sin una configuración de Obsidian específica por clave mantienen la alternativa global.
Las cuatro herramientas `obsidian_sync_*` conservan su comportamiento independiente para los tokens de sincronización.

## herramientas MCP (22)

Definido en `open-sse/mcp-server/tools/obsidianTools.ts`. Los token/base-URL se resuelven por llamada (primero por clave API, luego global). Herramientas que afectan al OmniRoute** servidor de sincronización** (las cuatro herramientas `obsidian_sync_*` ) requieren además el token de autenticación de sincronización configurado en la configuración OmniRoute.

### Herramientas de lectura (`read:obsidian`)

| Herramienta                  | Descripción                                                                                                                              |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Compruebe si el REST API local es accesible y está autenticado.                                                                          |
| `obsidian_search_simple`     | Búsqueda de texto completo del contenido de las notas; devuelve fragmentos con rutas de archivo.                                         |
| `obsidian_search_structured` | Búsqueda utilizando una expresión lógica JSON (filtros and/or/regex/path ).                                                              |
| `obsidian_read_note`         | Leer una nota por ruta relativa a la bóveda; opcionalmente un heading/block/frontmatter. específico                                      |
| `obsidian_list_vault`        | Enumere archivos y directorios en la bóveda (árbol de entradas).                                                                         |
| `obsidian_get_document_map`  | Obtenga la estructura de encabezados de la nota como un mapa de encabezados → números de línea.                                          |
| `obsidian_get_note_metadata` | Obtenga portada, etiquetas, enlaces y recuento char/word sin el contenido completo.                                                      |
| `obsidian_get_active_file`   | Obtenga la ruta + contenido del archivo actualmente activo en Obsidian.                                                                  |
| `obsidian_get_periodic_note` | Obtenga la nota periódica daily/weekly/monthly para una fecha (hoy si se omite).                                                         |
| `obsidian_get_tags`          | Enumere todas las etiquetas de bóveda con sus frecuencias.                                                                               |
| `obsidian_list_commands`     | Enumere el comando Obsidian disponible IDs (úselo con `obsidian_execute_command`).                                                       |
| `obsidian_sync_status`       | Estado del servidor de sincronización OmniRoute : en ejecución, nombre de la bóveda, puerto, tiempo de actividad, última sincronización. |
| `obsidian_sync_conflicts`    | Enumere los conflictos de sincronización no resueltos (ruta, ruta de conflicto, detectado en).                                           |

### Herramientas de escritura (`write:obsidian`)

| Herramienta                      | Descripción                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Cree o sobrescriba una nota con el contenido de Markdown determinado.                                   |
| `obsidian_append_note`           | Agregar contenido a una nota; opcionalmente a un heading/block. específico                              |
| `obsidian_patch_note`            | append/prepend/replace quirúrgicamente en un encabezado, bloque o campo frontal.                        |
| `obsidian_delete_note`           | Eliminar permanentemente una nota de la bóveda.                                                         |
| `obsidian_move_note`             | Mueva o cambie el nombre de una nota dentro de la bóveda.                                               |
| `obsidian_execute_command`       | Ejecute un comando Obsidian mediante su comando ID.                                                     |
| `obsidian_open_file`             | Abre un archivo en Obsidian (lo crea si no existe).                                                     |
| `obsidian_sync_trigger`          | Active una sincronización bidireccional inmediata de la bóveda móvil ↔ de escritorio.                   |
| `obsidian_sync_resolve_conflict` | Resuelva un conflicto de sincronización: mantenga `local` (móvil), `remote` (escritorio) o `keep-both`. |

> [!NOTE]
> Los objetivos `obsidian_patch_note` aceptan `targetType` de `heading | block | frontmatter` y `operation` de `append | prepend | replace`, con un `createTargetIfMissing` opcional. Las cuatro herramientas `obsidian_sync_*` se comunican con el servidor de sincronización local (`http://127.0.0.1:27781` de forma predeterminada) y requieren el token de sincronización.

### Alcances

Las herramientas de lectura requieren `read:obsidian`; las herramientas de escritura requieren `write:obsidian`. La aplicación es idéntica a Notion — manejada por `withScopeEnforcement()` en `open-sse/mcp-server/server.ts`, cerrada en `OMNIROUTE_MCP_ENFORCE_SCOPES=true` y forzada para los llamadores HTTP/SSE cuya clave API carece `manage`/`admin`, con alcances permitidos provenientes de `OMNIROUTE_MCP_SCOPES` o del contexto de alcance de la clave API. Ver [MCP-SERVER.md](./MCP-SERVER.md).

## Endpoints

| Método   | Ruta                            | Propósito                                                                  |
| -------- | ------------------------------- | -------------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Devuelve `{ connected, hasToken, baseUrl, vaultPath }`.                    |
| `POST`   | `/api/settings/obsidian`        | Guarda y valida el token (rechaza el puerto `27124`).                      |
| `DELETE` | `/api/settings/obsidian`        | Desconecta (elimina el token almacenado).                                  |
| `GET`    | `/api/settings/obsidian/webdav` | Estado de sincronización WebDAV y credenciales (mientras está habilitada). |
| `POST`   | `/api/settings/obsidian/webdav` | Habilita la sincronización WebDAV para un directorio de bóveda.            |
| `DELETE` | `/api/settings/obsidian/webdav` | Deshabilita la sincronización WebDAV.                                      |

> Estas son rutas de configuración del panel. Se accede a la propia bóveda mediante la API
> REST local de Obsidian (la `base_url` configurada) y mediante las herramientas MCP anteriores;
> no existe ningún endpoint proxy público `/v1` de Obsidian.

## Casos de uso

- **Respuestas basadas en la bóveda** — `obsidian_search_simple` / `obsidian_search_structured`
  y después `obsidian_read_note`, para que un agente responda a partir de tus notas reales.
- **Creación de notas / diario** — `obsidian_write_note`, `obsidian_append_note` o
  el preciso `obsidian_patch_note` para registrar en la bóveda los resultados del agente,
  resúmenes o notas diarias (`obsidian_get_periodic_note`).
- **Navegación por la bóveda** — `obsidian_list_vault`, `obsidian_get_document_map` y
  `obsidian_get_tags` para explorar la estructura antes de leer o escribir.
- **Automatización de Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` para
  controlar complementos/comandos desde un agente; `obsidian_open_file` para mostrar una nota en la interfaz.
- **Sincronización móvil** — habilita la sincronización WebDAV y, a continuación, usa
  `obsidian_sync_trigger` / `obsidian_sync_status` / `obsidian_sync_conflicts` /
  `obsidian_sync_resolve_conflict` para coordinar el escritorio↔móvil y resolver conflictos.
