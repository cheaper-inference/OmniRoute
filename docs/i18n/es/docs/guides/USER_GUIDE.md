## 🎯 Casos de uso

### Caso 1: "Tengo una suscripción a Claude Pro"

**Problema:** La cuota caduca sin utilizarse y se alcanzan los límites de uso durante sesiones intensivas de programación

```
Combinación: "maximize-claude"
  1. cc/claude-opus-4-7        (aprovechar al máximo la suscripción)
  2. glm/glm-4.7               (alternativa económica cuando se agota la cuota)
  3. if/qwen3.8-max-preview       (alternativa gratuita de emergencia)

Coste mensual: $20 (suscripción) + ~$5 (alternativa) = $25 en total
frente a $20 + alcanzar los límites = frustración
```

### Caso 2: "Quiero un coste cero"

**Problema:** No puedo permitirme suscripciones y necesito una IA fiable para programar

```
Combinación: "zero-cost"
  1. if/kimi-k2.7-code          (acceso gratuito indicado; pueden aplicarse límites de uso)
  2. kr/qwen3-coder-next        (Kiro como alternativa gratuita)

Coste mensual: $0
Calidad: verifica el modelo, los límites, la privacidad y el SLA para tu carga de trabajo
```

### Caso 3: "Necesito programar las 24 horas del día, los 7 días de la semana, sin interrupciones"

**Problema:** Hay plazos de entrega y no puedo permitirme tiempos de inactividad

```
Combinación: "always-on"
  1. cc/claude-opus-4-7        (la mejor calidad)
  2. cx/gpt-5.5                (segunda suscripción)
  3. glm/glm-4.7               (económico, se restablece diariamente)
  4. minimax/MiniMax-M2.1      (el más económico, se restablece cada 5 h)
  5. if/deepseek-v4-flash       (acceso gratuito indicado; pueden aplicarse límites de uso)

Resultado: 5 niveles de respaldo aumentan la resiliencia; no se garantiza la disponibilidad de los proveedores
Coste mensual: $20-200 (suscripciones) + $10-20 (alternativas)
```

### Caso 4: "Quiero IA GRATUITA en OpenClaw"

**Problema:** Necesito un asistente de IA en aplicaciones de mensajería, completamente gratis

```
Combinación: "openclaw-free"
  1. if/qwen3.8-max-preview     (acceso gratuito indicado; pueden aplicarse límites de uso)
  2. if/deepseek-v4-flash       (acceso gratuito indicado; pueden aplicarse límites de uso)
  3. if/kimi-k2.7-code          (acceso gratuito indicado; pueden aplicarse límites de uso)

Coste mensual: $0
Acceso mediante: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 Configuración de proveedores

Para añadir en bloque conexiones con claves de API desde un archivo CSV o JSON, usa **Panel de control → Proveedores → Importar desde archivo**. Las columnas son posicionales (`provider,name,apiKey,baseUrl,priority`); `provider` ya debe existir como proveedor administrado o nodo compatible. Consulta [Importar proveedores desde un archivo CSV o JSON](../providers/CSV-IMPORT.md).

### 🔐 Proveedores por suscripción

#### Claude Code (Pro/Max)

```bash
Panel de control → Proveedores → Conectar Claude Code
→ Inicio de sesión OAuth → Renovación automática del token
→ Seguimiento de la cuota de 5 horas y semanal

Modelos:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**Consejo profesional:** Usa Opus para tareas complejas y Sonnet para obtener mayor velocidad. ¡OmniRoute realiza un seguimiento de la cuota por modelo!

¿No hay un navegador en el host de OmniRoute? Ejecuta `claude setup-token` en cualquier lugar donde se haya iniciado sesión en Claude Code y pega el token válido durante un año en la pestaña **Token de configuración**. Consulta [Claude Code con un token de configuración](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

Las rutas compatibles con Claude y Claude Code conservan el esfuerzo de razonamiento `max` para los modelos Opus y Sonnet. Los modelos Haiku no aceptan el nivel de esfuerzo `max`, por lo que OmniRoute reduce esa solicitud a un presupuesto de razonamiento alto antes de enviarla al proveedor ascendente.

### 💰 Proveedores económicos

#### GLM-4.7 (restablecimiento diario, $0.6/1M)

1. Regístrate: [Zhipu AI](https://open.bigmodel.cn)
2. Obtén una clave de API del Coding Plan
3. Panel de control → Añadir clave de API: Proveedor: `glm`, clave de API: `your-key`

**Uso:** `glm/glm-4.7` — **Consejo profesional:** ¡Coding Plan ofrece una cuota 3 veces mayor por 1/7 del coste! Se restablece diariamente a las 10:00 a. m.

**Uso:** `minimax/MiniMax-M2.1` — **Consejo profesional:** ¡La opción más económica para contextos largos (1M de tokens)!

#### Kimi K2 ($9/mes, tarifa plana)

1. Suscríbete: [Moonshot AI](https://platform.kimi.ai?aff=omniroute)
2. Obtén una clave de API → Panel de control → Añadir clave de API

**Uso:** `kimi/kimi-k2.5` — **Consejo profesional:** ¡La tarifa fija de $9/mes por 10M de tokens equivale a un coste efectivo de $0.90/1M!

#### Baidu Qianfan / ERNIE

1. Regístrate: [Baidu AI Cloud Qianfan](https://cloud.baidu.com/product/wenxinworkshop)
2. Crea una clave de API de Qianfan → Panel de control → Añadir clave de API: Proveedor: `qianfan`

**Uso:** `qianfan/ernie-5.1`, `qianfan/ernie-x1.1` u otro ID de modelo de Qianfan compatible con OpenAI.

## 🎨 Combinaciones

Puedes reordenar las tarjetas de combinaciones directamente en **Panel → Combinaciones** arrastrando el control de cada tarjeta. El orden se almacena en SQLite y se restaura al recargar.

### Ejemplo 1: Maximizar suscripción → Respaldo económico

```
Panel → Combinaciones → Crear nueva

Nombre: premium-coding
Modelos:
  1. cc/claude-opus-4-7 (Suscripción principal)
  2. glm/glm-4.7 (Respaldo económico, $0.6/1M)
  3. minimax/MiniMax-M2.7 (Alternativa más barata, $0.3/1M)

Uso en la CLI: premium-coding
```

### Ejemplo 2: Solo gratuitos (coste cero)

```
Nombre: free-combo
Modelos:
  1. if/kimi-k2.7-code (acceso gratuito indicado; pueden aplicarse límites del proveedor)
  2. kr/qwen3-coder-next (alternativa gratuita de Kiro)

Coste: actualmente figura como $0; los términos y la disponibilidad pueden cambiar
```

## 🔧 Integración con la CLI

### Cursor IDE

**Uso de Cursor como cliente de OmniRoute** (enruta el chat de Cursor a través de OmniRoute):

```
Configuración → Modelos → Avanzado:
  URL base de la API de OpenAI: http://localhost:20128/v1
  Clave de la API de OpenAI: [desde el panel de OmniRoute]
  Modelo: cc/claude-opus-4-7
```

**Uso de OmniRoute como proveedor de Cursor** (OmniRoute llama a Cursor como servicio ascendente): se recomienda
**Panel → Proveedores → Cursor → Iniciar sesión con Cursor**. En Docker, consulta
[`docs/providers/CURSOR-DOCKER.md`](../providers/CURSOR-DOCKER.md).

### Claude Code

Edita `~/.claude/settings.json`:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://localhost:20128",
    "ANTHROPIC_AUTH_TOKEN": "tu-clave-de-api-de-omniroute"
  }
}
```

Utiliza aquí el endpoint raíz compatible con Claude. No añadas `/v1` a `ANTHROPIC_BASE_URL`.

### Codex CLI

```bash
export OPENAI_BASE_URL="http://localhost:20128"
export OPENAI_API_KEY="tu-clave-de-api-de-omniroute"
codex "tu instrucción"
```

### OpenClaw

Edita `~/.openclaw/openclaw.json`:

```json
{
  "agents": {
    "defaults": {
      "model": { "primary": "omniroute/if/kimi-k2.7-code" }
    }
  },
  "models": {
    "providers": {
      "omniroute": {
        "baseUrl": "http://localhost:20128/v1",
        "apiKey": "tu-clave-de-api-de-omniroute",
        "api": "openai-completions",
        "models": [{ "id": "if/kimi-k2.7-code", "name": "Kimi K2.7 Code" }]
      }
    }
  }
```

## 🚀 Despliegue

### Instalación global con npm (recomendada)

```bash
npm install -g omniroute

# Crear el archivo .env (consulta .env.example)

```

La CLI carga automáticamente `.env` desde `~/.omniroute/.env` o `./.env`.

### Modo de bandeja del sistema

Inicia OmniRoute en la bandeja del sistema:

```bash
omniroute serve --tray
```

El comando finaliza una vez que el servidor y la bandeja están listos.

El servidor continúa ejecutándose sin la terminal.

El modo de bandeja es compatible con macOS, Windows y sesiones gráficas de Linux. El modo de bandeja no abre automáticamente el panel.

Utiliza el menú de la bandeja para realizar estas acciones:

- Abrir el panel.
- Abrir `/dashboard/logs`.
- Cambiar el inicio automático.
- Detener OmniRoute.

No combines `--tray` con estas opciones:

- `--daemon`
- `--log`
- `--no-recovery`

Estos modos requieren una gestión de procesos diferente.

Activa el inicio durante el próximo inicio de sesión en la máquina:

```bash
omniroute autostart enable
```

El inicio automático utiliza el modo de bandeja en macOS, Windows y sesiones gráficas de Linux. Linux sin interfaz gráfica utiliza el servicio de usuario existente de systemd.

Desactiva el inicio al iniciar sesión:

```bash
omniroute autostart disable
```

## 🧩 Funciones avanzadas

### Modelos personalizados

Añade cualquier ID de modelo a cualquier proveedor sin esperar una actualización de la aplicación:

```bash
# A través de la API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# Listar: curl http://localhost:20128/api/provider-models?provider=openai
# Eliminar: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

O usa el Panel: **Proveedores → [Proveedor] → Modelos personalizados**.

Notas:

- Los proveedores OpenRouter y los compatibles con OpenAI/Anthropic se gestionan únicamente desde **Modelos disponibles**. La adición manual, la importación y la sincronización automática van a parar a la misma lista de modelos disponibles, por lo que no existe una sección separada de Modelos personalizados para esos proveedores.
- La sección **Modelos personalizados** está pensada para proveedores que no exponen importaciones gestionadas de modelos disponibles.

### Proveedores personalizados compatibles con OpenAI

Cualquier gateway que hable la API de OpenAI (un proxy autoalojado, vLLM, un agregador de terceros)
puede añadirse como su propio nodo de proveedor:

1. **Proveedores → Añadir compatible con OpenAI**.
2. **Nombre**: una etiqueta visible para el nodo.
3. **Prefijo**: el nombre de enrutamiento. Los clientes llaman a los modelos como `<prefix>/<model>`, así que un nodo con
   prefijo `mygw` sirve `mygw/gpt-4o-mini`. Obligatorio; no hay restricción de caracteres.
4. **Tipo de API**: la familia de endpoints que sirve el gateway (Chat Completions, Responses,
   Embeddings, audio, imágenes).
5. **URL base**: la raíz de la API, hasta `/v1` inclusive (por ejemplo
   `https://gateway.example.com/v1`), no la ruta completa `/chat/completions`. Los gateways con
   rutas no estándar las configuran en **Configuración avanzada** (ruta de chat, ruta de modelos).
6. El campo **Clave de API (para verificación)** solo prueba la conexión. Después de crear el nodo,
   ábrelo y usa **Añadir conexión** para guardar la clave que usarán las solicitudes.

El nodo recibe un id interno de la forma `openai-compatible-<apiType>-<uuid>`; nunca
necesitas escribirlo, el prefijo es el nombre público.

#### Prefijos reservados

Un prefijo no puede ser el id ni el alias de un proveedor integrado (por ejemplo `openai`, `cf`), ni
el id de un proveedor retirado. El resolvedor de modelos comprueba los ids y alias integrados antes
que los nodos personalizados, por lo que un nodo que usara uno de esos prefijos nunca recibiría tráfico:
`<prefix>/model` iría al proveedor integrado en su lugar, o fallaría en modo cerrado si ese proveedor
estuviera retirado. Crear o editar un nodo con tal prefijo se rechaza con:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

Elige un prefijo distinto (`mygw`, `acme-proxy`). Si las solicitudes a un nodo personalizado fallan con un
error que menciona un proveedor integrado o sus credenciales, comprueba si el prefijo del nodo está
reservado: los nodos guardados antes de que existiera esta regla siguen almacenados, pero su prefijo enruta
al proveedor integrado. Edita el nodo y asígnale un prefijo nuevo.

#### Opciones de gateway por conexión

Estas claves van en el `providerSpecificData` de una conexión (por ejemplo mediante
`PUT /api/providers/{id}`):

- `toolNameMaxLength` (entero, 1–1024): para conexiones compatibles con el formato de chat de OpenAI cuyo
  gateway rechaza nombres de herramientas largos. Los nombres más largos se envían como alias cortos y se restauran en la
  respuesta.
- `quotaEndpoint`: el endpoint de cuota/créditos del gateway, leído para la barra de cuota del panel y
  el enrutamiento consciente de la cuota. Funciona tanto en conexiones compatibles con OpenAI como con Anthropic; la forma completa

### Encadenamiento de pares de OmniRoute

Otro gateway OmniRoute puede añadirse como proveedor **personalizado compatible con OpenAI**. Usa la
URL base `/v1` del par y una clave de API dedicada, de mínimos privilegios, emitida por ese par.

Para cadenas recíprocas o de múltiples saltos, activa la protección contra bucles (de activación explícita) en cada gateway:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

Solo las solicitudes enviadas a una URL de par explícitamente incluida en la lista de permitidos reciben la
cabecera `X-OmniRoute-Peer-Trace`. Un gateway rechaza un ID de instancia repetido o un presupuesto de
saltos agotado con HTTP `508 Loop Detected`; los proveedores ascendentes ordinarios no reciben metadatos de pares.

El encadenamiento de pares no es replicación de base de datos ni conmutación por error de host. Cada gateway
mantiene estado, cachés, contadores de tasa y sesiones de SQLite independientes. Usa un proxy inverso con
comprobación de estado o conmutación por error del cliente para disponibilidad activa/pasiva o activa/activa,
y nunca montes una misma base de datos SQLite en varias instancias de OmniRoute en ejecución.

### Estrategias de enrutamiento

Se configuran en **Panel → Configuración → Enrutamiento**. El panel expone las seis estrategias más utilizadas; los combos y el enrutador automático admiten internamente un conjunto más amplio.

**Estrategias visibles en el panel (enrutamiento a nivel de cuenta):**

| Estrategia                     | Descripción                                                                                                           |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| **Fill First**                 | Usa las cuentas en orden de prioridad: la cuenta principal atiende todas las solicitudes hasta que no esté disponible |
| **Round Robin**                | Alterna entre todas las cuentas con un límite de afinidad (sticky) configurable (por defecto: 3 llamadas por cuenta)  |
| **P2C (Power of Two Choices)** | Elige 2 cuentas al azar y enruta a la más saludable: equilibra la carga teniendo en cuenta el estado de salud         |
| **Random**                     | Selecciona aleatoriamente una cuenta para cada solicitud usando la mezcla Fisher-Yates                                |
| **Least Used**                 | Enruta a la cuenta con la marca de tiempo `lastUsedAt` más antigua, distribuyendo el tráfico uniformemente            |
| **Cost Optimized**             | Enruta a la cuenta con el valor de prioridad más bajo, optimizando para los proveedores de menor costo                |

**Estrategias avanzadas de combo y automáticas** (configurables por combo o mediante los prefijos `auto/*`; consulta [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — orden estricto, nunca usa round-robin
- `weighted` — reparto de tráfico proporcional según los pesos por modelo
- `fill-first` — agota el primer modelo hasta alcanzar los límites
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` y `cost-optimized`
- `auto` — basado en puntuación entre todos los candidatos
- `lkgp` (Last Known Good Provider) — se fija al último proveedor exitoso y luego recurre a las reglas
- `context-optimized` — elige el modelo con la mayor ventana de contexto libre
- `context-relay` — encadena modelos de contexto largo para los turnos siguientes

#### Encabezado externo de sesión persistente (sticky)

Para afinidad de sesión externa (por ejemplo, agentes de Claude Code/Codex detrás de proxies inversos), envía:

```http

```

OmniRoute también acepta `x_session_id` y devuelve la clave de sesión efectiva en `X-OmniRoute-Session-Id`.

Si usas Nginx y envías encabezados con guiones bajos, habilita:

```nginx

```

#### Alias de modelos con comodines

Crea patrones con comodines para reasignar nombres de modelos:

```

```

Los comodines admiten `*` (cualquier secuencia de caracteres) y `?` (un solo carácter).

#### Cadenas de respaldo

Define cadenas de respaldo globales que se aplican a todas las solicitudes:

```

  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### Resiliencia e interruptores de circuito

Configúrelo a través de **Panel → Configuración → Resiliencia**.

OmniRoute implementa resiliencia a nivel de proveedor con cinco componentes:

1. **Cola de solicitudes y ritmo** — Modelado de solicitudes a nivel del sistema:
   - **Solicitudes por minuto (RPM)** — Número máximo de solicitudes por minuto por cuenta
   - **Tiempo mínimo entre solicitudes** — Intervalo mínimo en milisegundos entre solicitudes
   - **Máximo de solicitudes concurrentes** — Número máximo de solicitudes simultáneas por cuenta

2. **Enfriamiento de conexión** — Configuración por tipo de autenticación para una sola conexión tras fallos reintentables:
   - **Enfriamiento base** — Ventana de enfriamiento predeterminada para fallos reintentables del proveedor
   - **Usar sugerencias de reintento del proveedor** — Respeta las sugerencias autorizadas de `Retry-After` o de restablecimiento cuando se proporcionan
   - **Pasos máximos de retroceso** — Nivel máximo de retroceso exponencial para fallos repetidos

3. **Interruptor de circuito del proveedor** — Realiza un seguimiento de los fallos de extremo a extremo del proveedor, marca un proveedor como degradado al alcanzar el umbral de advertencia configurado y abre el interruptor cuando se alcanza el umbral de fallos configurado:
   - **Umbral de degradación** — Fallos consecutivos del proveedor antes de entrar en `DEGRADED`
   - **Umbral de fallos** — Fallos consecutivos del proveedor antes de entrar en `OPEN`
   - **Tiempo de espera de restablecimiento** — Ventana de tiempo antes de que se vuelva a probar el proveedor
   - **CLOSED** (Saludable) — Las solicitudes fluyen con normalidad
   - **DEGRADED** — Las solicitudes siguen fluyendo mientras se rastrean fallos elevados
   - **OPEN** — El proveedor se bloquea temporalmente tras fallos repetidos
   - **HALF_OPEN** — Se prueba si el proveedor se ha recuperado

   Los límites de velocidad `429` de ámbito de conexión permanecen en **Enfriamiento de conexión** y no cuentan para el interruptor del proveedor.

   El estado en tiempo de ejecución del interruptor del proveedor solo se muestra en **Panel → Salud**.

4. **Esperar el enfriamiento** — Si todas las conexiones candidatas ya están en enfriamiento, OmniRoute puede esperar al enfriamiento más próximo y reintentar automáticamente la misma solicitud del cliente.

5. **Detección automática de límites de velocidad** — Cuando los proveedores devuelven ventanas de espera explícitas, esas sugerencias anulan el enfriamiento de conexión local cuando la configuración está habilitada.

**Consejo profesional:** Utilice la página **Salud** para inspeccionar y restablecer los interruptores de proveedor activos tras una interrupción. La página de Resiliencia solo cambia la configuración.

### Estrategias de balanceo de combos

Configura el balanceo por combo en **Panel → Combos → Crear/Editar → Estrategia**.

| Estrategia         | Descripción                                                                   |
| ------------------ | ----------------------------------------------------------------------------- |
| **Round-Robin**    | Rota secuencialmente entre los modelos                                        |
| **Priority**       | Siempre intenta el primer modelo; solo recurre al siguiente en caso de error  |
| **Random**         | Elige un modelo aleatorio del combo para cada solicitud                       |
| **Weighted**       | Enruta proporcionalmente según los pesos asignados a cada modelo              |
| **Least-Used**     | Enruta al modelo con menos solicitudes recientes (usa las métricas del combo) |
| **Cost-Optimized** | Enruta al modelo disponible más barato (usa la tabla de precios)              |

Los valores predeterminados globales de combos se pueden establecer en **Panel → Configuración → Enrutamiento → Valores predeterminados de combos**.
Los tiempos de espera de los destinos del combo heredan el tiempo de espera de la solicitud actual de forma
predeterminada. Usa **Tiempo de espera de destino (segundos)** en los valores predeterminados de combos o en un
combo individual solo cuando un límite por destino más corto deba activar un respaldo más rápido.

Las optimizaciones de latencia cero de los combos son de activación voluntaria. Deja
**Optimizaciones de latencia cero** desactivadas para evitar que estas funciones de latencia compitan con los
destinos de respaldo, omitan destinos según el historial de TTFT o compriman las solicitudes de respaldo; al
activarlas, se permite que el hedging configurado, las omisiones predictivas basadas en TTFT y la compresión
proactiva de respaldos sacrifiquen fidelidad de enrutamiento/solicitudes a cambio de una menor latencia de cola.

Desactiva el **Búfer de tokens de razonamiento** cuando los proveedores upstream requieran límites estrictos de `max_tokens` / `maxOutputTokens`. Cuando está activado, el enrutamiento combo solo añade margen de modelo de razonamiento a los modelos con un límite de salida conocido, y deja el límite de tokens del cliente sin cambios cuando el valor seguro con búfer excedería ese límite. Si el límite del cliente ya está por encima de un límite conocido, OmniRoute lo reduce a ese límite antes de enviar la solicitud upstream.

## 🤖 Enrutamiento automático (sin configuración)

OmniRoute incluye un **enrutador automático basado en puntuaciones** que selecciona el mejor modelo para cada solicitud entre todos los proveedores conectados, sin necesidad de mantener ninguna combinación. Solo tienes que enviar la solicitud con uno de los prefijos `auto/*` y OmniRoute creará una combinación virtual al instante, puntuando a los candidatos según la latencia, el coste, la tasa de éxito, la adecuación al contexto, la idoneidad del modelo para la tarea, los fallos recientes, la cuota y el estado del disyuntor.

| Prefijo        | Optimiza para                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------- |
| `auto`         | Opción predeterminada equilibrada (latencia × coste × tasa de éxito)                              |
| `auto/coding`  | Tareas de programación: prioriza Claude, GPT-5, GLM, Kimi, Qwen Coder y programadores DeepSeek    |
| `auto/cheap`   | Menor coste por token; acepta una latencia más alta                                               |
| `auto/fast`    | Menor latencia; ignora el coste                                                                   |
| `auto/offline` | Solo proveedores locales (Ollama, vLLM, llama.cpp), útil para entornos aislados                   |
| `auto/smart`   | Prioriza la calidad del razonamiento (Opus, GPT-5 xhigh, R1, razonamiento de GLM 5.1)             |
| `auto/lkgp`    | «Último proveedor válido conocido»: fija el último proveedor exitoso y luego recurre a las reglas |

Ejemplo:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

El enrutador automático se describe por completo en [AUTO-COMBO.md](../routing/AUTO-COMBO.md), incluida la forma de ajustar los pesos de puntuación, añadir proveedores a la lista negra e inspeccionar las decisiones de enrutamiento en **Panel de control → Combinación automática**.

## 🔌 Integración con MCP y A2A

OmniRoute funciona tanto como **servidor MCP** (Model Context Protocol) como **servidor A2A** (Agent-to-Agent JSON-RPC 2.0). Cualquier IDE o host de agentes compatible con MCP puede invocar directamente las herramientas de OmniRoute, sin necesidad de ningún adaptador adicional.

### Transportes MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP transmisible**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (para complementos de IDE que prefieran stdio)

### Conectar Claude Desktop

Edita `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) o el archivo equivalente en Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Conectar Cursor / Continue / VS Code MCP

Usa la URL de SSE `http://localhost:20128/api/mcp/sse` y una clave de API Bearer generada en **Panel de control → Claves de API**.

### Ámbitos

Actualmente, MCP define 32 ámbitos con nombre. Cada clave Bearer puede limitarse a ámbitos específicos; consulta [MCP-SERVER.md](../frameworks/MCP-SERVER.md) para ver el inventario oficial de ámbitos y herramientas, y [A2A-SERVER.md](../frameworks/A2A-SERVER.md) para consultar el esquema JSON-RPC.

## 🧠 Sistema de habilidades

OmniRoute ofrece un **framework de habilidades** extensible (`src/lib/skills/`) para que los agentes y el endpoint A2A puedan ejecutar rutinas específicas de un dominio (p. ej., `code-review`, `summarize`, `extract-facts`, `web-research`).

- **Interfaz del marketplace** — Explora e instala habilidades desde **Panel de control → Habilidades**
- **Ámbitos por clave** — Restringe qué claves de API pueden invocar cada habilidad
- **Habilidades personalizadas** — Añade un archivo TypeScript en `src/lib/a2a/skills/`, regístralo y podrá invocarse inmediatamente mediante A2A

Referencia completa: [SKILLS.md](../frameworks/SKILLS.md).

## 💾 Sistema de memoria

OmniRoute conserva **memoria conversacional a largo plazo** mediante recuperación híbrida:

- **SQLite FTS5** para buscar por palabras clave en interacciones anteriores
- **Almacén vectorial Qdrant** (opcional) para la recuperación semántica
- **Extracción automática de hechos** — las entidades, preferencias y decisiones se resumen después de cada sesión y se almacenan en la tabla `memory_facts`
- Las memorias están delimitadas por clave de API y por sesión

Gestiona las memorias en **Panel de control → Memoria** (buscar, editar, exportar, purgar). La interfaz HTTP (`/api/memory/*`) permite a los agentes enviar y consultar hechos mediante programación; consulta [MEMORY.md](../frameworks/MEMORY.md).

## 🔔 Webhooks

Suscríbete a los eventos de OmniRoute para realizar supervisión y automatización en tiempo real.

- Crea un webhook en **Panel de control → Webhooks** con la URL de destino y el secreto de firma HMAC
- Eventos disponibles: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- Cada carga útil incluye `X-OmniRoute-Signature` (HMAC-SHA256) para su verificación
- Reintentos: 3 intentos con espera exponencial y, después, envío a la cola de mensajes fallidos

Esquema completo en [WEBHOOKS.md](../frameworks/WEBHOOKS.md).

## 🛠️ Gestión programática

Puedes gestionar todos los recursos de OmniRoute (proveedores, combos, claves y ajustes) mediante HTTP utilizando una **clave Bearer con el ámbito `manage`**.

Genera la clave en **Panel de control → Claves de API → Nueva clave → Ámbito: manage** y, a continuación:

```bash
# Enumerar proveedores
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Añadir una conexión de proveedor
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Crear un combo
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Enumerar/crear claves de API
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

Consulta [API_REFERENCE.md](../reference/API_REFERENCE.md) para ver el catálogo completo de endpoints y los esquemas de solicitud/respuesta.

## 💻 CLI interna

OmniRoute incluye una CLI interna (`omniroute …`) para la configuración, el diagnóstico y el control en tiempo de ejecución. Esta es **independiente de la página "Herramientas de CLI" del panel**, que configura CLI de terceros (Claude Code, Cursor, Codex, Cline, …) para que puedan comunicarse con OmniRoute.

```bash
omniroute setup                    # Asistente interactivo (contraseña, proveedores, combinaciones)
omniroute setup --non-interactive  # Adecuado para CI
omniroute doctor                   # Diagnósticos de estado (directorio de datos, BD, proveedores, puertos)
omniroute providers available      # Enumera los proveedores compatibles
omniroute providers list           # Enumera las conexiones configuradas
omniroute providers test <id>      # Prueba en vivo una conexión de proveedor
omniroute combos list              # Enumera las combinaciones
omniroute combos switch <name>     # Establece la combinación predeterminada
omniroute models                   # Enumera los modelos disponibles (--json, --search)
omniroute keys add | list | remove # Administra las claves de API desde la terminal
omniroute backup                   # Crea una instantánea de la configuración y la BD
omniroute restore [<timestamp>]    # Restaura desde una instantánea
omniroute health                   # Estado detallado (disyuntores, caché, memoria)
omniroute quota                    # Uso de cuota de los proveedores
omniroute mcp status               # Estado del servidor MCP
omniroute a2a status               # Estado del servidor A2A
omniroute tunnel list|create|stop  # Túneles de Cloudflare/Tailscale/ngrok
omniroute reset-password           # Restablece la contraseña de administrador
omniroute --mcp                    # Inicia el servidor MCP mediante stdio
omniroute --port 3000              # Inicia el servidor en un puerto personalizado
```

Consejo: combina `omniroute doctor --json` con tu herramienta de monitorización para recibir alertas sobre conexiones de proveedores que no estén en buen estado.

## 🖥️ Aplicación de escritorio (Electron)

OmniRoute está disponible como aplicación de escritorio nativa para Windows, macOS y Linux.

### Instalación

```bash
# Desde el directorio electron:
cd electron
npm install

# Modo de desarrollo (se conecta al servidor de desarrollo de Next.js en ejecución):
npm run dev

# Modo de producción (utiliza la compilación independiente):
npm start
```

### Creación de instaladores

```bash
cd electron
npm run build          # Plataforma actual
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg universal)
npm run build:linux    # Linux (.AppImage)
```

Salida → `electron/dist-electron/`

### Características principales

| Característica                         | Descripción                                                              |
| -------------------------------------- | ------------------------------------------------------------------------ |
| **Disponibilidad del servidor**        | Consulta el servidor antes de mostrar la ventana (sin pantalla vacía)    |
| **Bandeja del sistema**                | Minimiza a la bandeja, cambia el puerto y cierra desde su menú           |
| **Administración de puertos**          | Cambia el puerto desde la bandeja (reinicia el servidor automáticamente) |
| **Política de seguridad de contenido** | CSP restrictiva mediante encabezados de sesión                           |
| **Instancia única**                    | Solo puede ejecutarse una instancia de la aplicación a la vez            |
| **Modo sin conexión**                  | El servidor Next.js incluido funciona sin internet                       |

### Variables de entorno

| Variable              | Valor predeterminado | Descripción                              |
| --------------------- | -------------------- | ---------------------------------------- |
| `OMNIROUTE_PORT`      | `20128`              | Puerto del servidor                      |
| `OMNIROUTE_MEMORY_MB` | `512`                | Límite del heap de Node.js (64–16384 MB) |

📖 Documentación completa: [`electron/README.md`](../../electron/README.md)
