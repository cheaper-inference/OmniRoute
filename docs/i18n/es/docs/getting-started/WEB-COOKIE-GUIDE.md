Los proveedores de cookies web permiten que OmniRoute utilice un servicio de IA mediante la sesión existente de su navegador en lugar de una clave de API. Son útiles cuando ya tiene acceso a un servicio a través de su sitio web y desea que OmniRoute utilice la misma sesión autenticada.

A diferencia de los proveedores con clave de API, los proveedores de cookies web se autentican mediante las credenciales que su navegador envía al sitio web.

---

# Antes de comenzar

> **Importante:** Copie siempre las credenciales de una **solicitud de red activa**, **no** del almacenamiento de cookies de su navegador.

Muchos problemas de autenticación se deben a que las cookies se copian desde el lugar equivocado.

## NO copie desde el almacenamiento de cookies

La mayoría de los navegadores muestran las cookies almacenadas mediante:

```
Herramientas para desarrolladores
→ Aplicación (o Almacenamiento)
→ Cookies
```

Aunque estas cookies parezcan correctas, pueden estar:

- obsoletas
- incompletas
- sin las cookies que solo se envían en solicitudes autenticadas

El uso de estos valores puede provocar errores de autenticación, aunque parezcan válidos.

## Copie desde una solicitud activa

En su lugar, utilice las cookies de una solicitud realizada correctamente:

```
Herramientas para desarrolladores
→ Red
→ Actualizar la página
→ Abrir una solicitud de chat o conversación
→ Encabezados de solicitud
→ Cookie
```

El encabezado de solicitud `Cookie` contiene la información de autenticación exacta que su navegador utilizó correctamente.

Para la mayoría de los proveedores de cookies web, este es el valor que debe pegarse en OmniRoute.

# Configuración general

El proceso de configuración es el mismo para la mayoría de los proveedores de cookies web.

1. Inicie sesión en el sitio web del proveedor.
2. Abra las Herramientas para desarrolladores del navegador.
3. Abra la pestaña **Red**.
4. Actualice la página.
5. Abra una solicitud autenticada de chat o conversación.
6. Copie las credenciales de autenticación necesarias.
7. Abra OmniRoute.
8. Vaya a **Proveedores → Añadir proveedor**.
9. Seleccione su proveedor de cookies web.
10. Pegue las credenciales.
11. Haga clic en **Probar conexión**.
12. Guarde el proveedor.

Las credenciales exactas necesarias dependen del proveedor.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) es una plataforma gratuita de chat para consumidores que no requiere registro; la sesión se crea de forma anónima en la primera visita y persiste mediante tres cookies: `uid`, `si_usr_id` y `si_ses_id`. OmniRoute actúa como proxy del mismo endpoint `/api/dispatch` mediante un único id de modelo (`notrack-c`, alias `ntw`).

### Pasos para conectarse

1. Abra [notrack.ai](https://notrack.ai) en su navegador y permita que se establezca la cookie de sesión anónima.
2. Abra **Herramientas para desarrolladores → Red**, actualice la página y haga clic en cualquier solicitud `/api`.
3. En **Encabezados de solicitud**, copie el valor completo del encabezado `Cookie`.
4. En OmniRoute, vaya a **Proveedores → Añadir proveedor → NoTrack Web (Gratis)**.
5. Pegue la cadena de cookies en el campo `apiKey` y haga clic en **Guardar**.

OmniRoute extrae `uid`, `si_usr_id` y `si_ses_id` de la cadena pegada y reconstruye un encabezado `Cookie` limpio que contiene únicamente esos pares, además de `nt_session` (el token `ntk_…` establecido para las cuentas con sesión iniciada) cuando está presente. Si falta cualquiera de los tres, la cadena original pegada se reenvía sin cambios para que los operadores puedan experimentar con formatos alternativos.

### Ids de modelo

| Id de modelo | Nombre mostrado | Notas                                                          |
| ------------ | --------------- | -------------------------------------------------------------- |
| `notrack-c`  | NoTrack C       | Predeterminado: el modelo de despacho ascendente `C`.          |
| `C`          | NoTrack C       | Alias de `notrack-c` (código de despacho ascendente original). |
| `notrack`    | NoTrack C       | Alias de `notrack-c`.                                          |
| `ntw`        | NoTrack C       | Alias corto de `notrack-c`.                                    |

Los cuatro ids de modelo se asignan al mismo modelo de despacho ascendente (`C`).

### Opciones de solicitud

El ejecutor acepta estos campos opcionales en el cuerpo de la solicitud:

| Campo del cuerpo      | Valor predeterminado | Propósito                                                                                          |
| --------------------- | -------------------- | -------------------------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`              | Modo de despacho (cadena de formato libre; el servicio ascendente acepta `usual`, …)               |
| `notrack_max_turns`   | `6`                  | Número de turnos internos que el servicio ascendente puede realizar antes de responder.            |
| `notrack_chat_id`     | `null`               | Reanuda un chat ascendente existente (omítalo para iniciar uno nuevo).                             |
| `notrack_attachments` | `[]`                 | Matriz transferida directamente con los descriptores de archivos adjuntos del servicio ascendente. |
| `notrack_regenerate`  | `false`              | Establézcalo en `true` para solicitar que se vuelva a generar la respuesta del turno anterior.     |

### Capacidades

- Finalizaciones de chat **con y sin transmisión**.
- **Llamadas a herramientas**: establezca `tools: [...]` en la solicitud; el ejecutor las serializa en un contrato de envoltorio para llamadas a herramientas y vuelve a convertir las respuestas del modelo en `tool_calls` de OpenAI.
- **`response_format`**: se admiten `json_object` y `json_schema`. El ejecutor extrae el primer objeto JSON de la respuesta del modelo y lo convierte en una cadena antes de devolverlo.
- **Indicio de razonamiento**: el ejecutor emite un delta `reasoning` cuando el servicio ascendente envía un evento `thinking`.

### Limitaciones

- El servicio ascendente aplica cuotas de uso anónimo; cuando se superan, el ejecutor devuelve un error 429 con un mensaje descriptivo.
- Todos los ids de modelo se resuelven al mismo modelo de despacho ascendente; no existe una selección específica por modelo.
- El ejecutor no llama al endpoint `/api/chats` del servicio ascendente, por lo que el historial de chat y las sesiones no se administran automáticamente. Use `notrack_chat_id` para reanudar un chat ascendente existente.

# Qué pueden y qué no pueden hacer los proveedores de cookies web

Los proveedores de cookies web reutilizan la interfaz de chat de un sitio web. **No** ofrecen las mismas capacidades que las API oficiales.

## Compatible

- Autenticación mediante la sesión existente de su navegador
- Acceso a los modelos disponibles a través de su cuenta
- Transmisión en tiempo real de las respuestas del chat
- No se requiere una clave de API

## No compatible

- Llamadas a funciones
- Llamadas a herramientas
- Edición automática de archivos
- Flujos de trabajo agénticos en el IDE
- Funciones exclusivas de la API

Este es el comportamiento esperado y **no** es un error.

Si necesita ejecutar herramientas, editar archivos automáticamente o utilizar otros flujos de trabajo de agentes, use un **proveedor con clave de API** en lugar de un proveedor de cookies web.

# Advertencia sobre la validación

Una **prueba de conexión** o validación de cookies correcta solo verifica que las credenciales proporcionadas parezcan tener el formato esperado.

Hasta que se resuelva el problema #7857, una validación correcta **no garantiza** que el proveedor pueda autenticarse correctamente.

Si la autenticación sigue fallando, compruebe que haya copiado las credenciales de una solicitud de red activa, en lugar de hacerlo desde el almacenamiento de cookies del navegador.

---

# Solución de problemas

## Error de autenticación

Compruebe que las credenciales se hayan copiado desde:

```
Network
→ Request Headers
→ Cookie
```

y **no** desde:

```
Application
→ Cookies
```

---

## La cookie funciona en el navegador, pero no en OmniRoute

Algunos proveedores incluyen cookies que solo se envían durante las solicitudes autenticadas.

Vuelva a copiar las credenciales desde una solicitud de red reciente después de abrir correctamente una conversación.

---

## Sesión caducada

Los proveedores de cookies web utilizan la sesión existente de su navegador.

Si la sesión del navegador caduca o cierra sesión, debe copiar un nuevo conjunto de credenciales. Para automatizar la renovación de cookies en los proveedores web compatibles, consulte la herramienta complementaria [Extensión de sincronización de sesiones del navegador](../guides/SESSION-SYNC-EXTENSION.md).

---

## La prueba de conexión se supera, pero las solicitudes fallan

Hasta que se resuelva el problema #7857, superar la validación no garantiza que la solicitud de autenticación vaya a realizarse correctamente.

Vuelva a copiar sus credenciales desde una solicitud autenticada reciente antes de continuar con la solución de problemas.

---

## ChatGPT Web falla con "Unsupported ChatGPT integrity dependency"

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

La credencial es correcta: ese error procede del puente, no de la sesión. chatgpt.com asigna los
identificadores de sus módulos en cada despliegue, y el puente fijaba anteriormente el identificador del asistente Sentinel que instancia, por lo que una
nueva compilación de chatgpt.com que cambiara el nombre del asistente provocaba que todos los turnos fallaran aunque la cookie siguiera siendo válida. Volver a autorizar
la conexión no puede solucionarlo.

Las compilaciones que resuelven el módulo mediante el entorno de ejecución propio de la página no fijan ningún identificador y no presentan este problema. Si ve el
error, actualice OmniRoute y vuelva a ejecutar la comprobación de conexión.

# Prácticas recomendadas

- Copie las credenciales desde una solicitud autenticada reciente.
- Evite reutilizar cookies antiguas.
- Mantenga activa la sesión del navegador mientras utilice proveedores de cookies web.
- Trate las cookies copiadas como credenciales confidenciales.
- Utilice proveedores con clave de API cuando necesite llamadas a funciones o flujos de trabajo de agentes.
