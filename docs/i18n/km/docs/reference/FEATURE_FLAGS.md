## Feature Flag ជាអ្វី

Feature flag គឺជាកុងតាក់ដែលមានឈ្មោះ (boolean ឬ enum) ដែលតម្លៃរបស់វាអាចត្រូវបានផ្លាស់ប្តូរ
នៅពេលដំណើរការ និងរក្សាទុកក្នុងមូលដ្ឋានទិន្នន័យ ដោយមិនតម្រូវឱ្យដាក់ process ឱ្យដំណើរការឡើងវិញ។ Flag
នីមួយៗត្រូវបានពិពណ៌នាដោយ `FeatureFlagDefinition` ដែលមាន `key`, `label`,
`description`, `category`, `defaultValue`, `type` និងព័ត៌មានណែនាំ `requiresRestart`។

### លំដាប់នៃការកំណត់តម្លៃ

**តម្លៃជាក់ស្តែង** របស់ flag ត្រូវបានកំណត់ដោយ
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) តាមលំដាប់អាទិភាពខាងក្រោម (អាទិភាពខ្ពស់ជាងគេមានប្រសិទ្ធភាព)៖

1. **ការកំណត់ជំនួសក្នុង DB** — តម្លៃដែលបានរក្សាទុកក្នុងតារាង `key_value` ក្រោម
   namespace `feature_flags` (កំណត់តាមរយៈផ្ទាំងគ្រប់គ្រង ឬ REST API)។
2. **អថេរបរិស្ថាន** — `process.env[<KEY>]` ប្រសិនបើត្រូវបានកំណត់ និងមិនមែនជាតម្លៃទទេ។
3. **តម្លៃលំនាំដើមនៃនិយមន័យ** — `defaultValue` ពី `featureFlagDefinitions.ts`។

Boolean flag ត្រូវបានចាត់ទុកថា **បានបើក** នៅពេលតម្លៃជាក់ស្តែងរបស់វាគឺ `"true"`,
`"1"` ឬ `"yes"` (សូមមើល `isFeatureFlagEnabled()`)។

> [!NOTE]
> Flag ភាគច្រើនក៏មានអថេរបរិស្ថានដែលត្រូវគ្នា និងមាន **ឈ្មោះដូចគ្នា**
> ដែលបានចងក្រងជាឯកសារនៅក្នុង [`ENVIRONMENT.md`](./ENVIRONMENT.md)។ ការកំណត់ជំនួសក្នុង DB របស់ flag
> មានអាទិភាពលើអថេរបរិស្ថាននោះ។ Flag ដែលមាន
> `requiresRestart: true` ត្រូវបានរក្សាទុកភ្លាមៗ ប៉ុន្តែត្រូវបានអានឡើងវិញតែនៅពេល
> process ចាប់ផ្តើមប៉ុណ្ណោះ — ការបិទបើកវានឹងបង្ហាញបដា **"ចាប់ផ្តើមម៉ាស៊ីនមេឡើងវិញ"** នៅក្នុងផ្ទាំងគ្រប់គ្រង។

### REST API

ប្រតិបត្តិការទាំងអស់ប្រើ route តែមួយ៖
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)។
គ្រប់ method ទាំងអស់តម្រូវឱ្យមានសម័យចូលប្រើផ្ទាំងគ្រប់គ្រងដែលបានផ្ទៀងផ្ទាត់ (`401` ក្នុងករណីផ្សេងទៀត)។

#### `GET /api/settings/feature-flags`

បញ្ជូន flag ទាំងអស់ត្រឡប់មកវិញជាមួយតម្លៃមានប្រសិទ្ធភាព ប្រភព និងសេចក្ដីសង្ខេប។

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... flag ទាំង 115
  ],
  "summary": {
    "total": 115,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

កំណត់ ឬលុបការកំណត់ជំនួសតែមួយ។ Body: `{ key: string; value?: string }`។
ការមិនបញ្ចូល `value` នឹងលុបការកំណត់ជំនួស (ស្ដារទៅតម្លៃ env / default)។

```bash
# កំណត់ការកំណត់ជំនួស DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# លុបការកំណត់ជំនួស (គ្មាន "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

ការឆ្លើយតបនឹងបង្ហាញ `effectiveValue`/`source` ថ្មីឡើងវិញ រួមជាមួយ
`previousValue`/`previousSource` និង `requiresRestart`។ key ដែលមិនស្គាល់ និងតម្លៃ enum
ដែលនៅក្រៅជួរ នឹងត្រូវបដិសេធដោយ `400`។

#### `DELETE /api/settings/feature-flags`

លុបការកំណត់ជំនួស DB **ទាំងអស់** ក្នុងពេលតែមួយ ដោយស្ដារ flag នីមួយៗទៅតម្លៃ env / default
វិញ។ បញ្ជូន `{ cleared: <count>, message: "..." }` ត្រឡប់មកវិញ។

> [!NOTE]
> Flag ដែលមាន `requiresRestart: true` នឹងមានប្រសិទ្ធភាពតែបន្ទាប់ពីផ្ទុក process ឡើងវិញប៉ុណ្ណោះ។
> ដំណើរការចាប់ផ្ដើមឡើងវិញរបស់ផ្ទាំងគ្រប់គ្រង ហៅ `POST /api/restart` ហើយបន្ទាប់មកស្ទង់មើល
> `GET /api/health/ping` រហូតដល់ម៉ាស៊ីនមេដំណើរការឡើងវិញ។
