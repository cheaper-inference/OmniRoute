## Feature Flag ជាអ្វី

Feature flag គឺជាកុងតាក់ដែលមានឈ្មោះ (boolean ឬ enum) ដែលតម្លៃរបស់វាអាចត្រូវបានផ្លាស់ប្តូរ
នៅពេលដំណើរការ និងរក្សាទុកក្នុងមូលដ្ឋានទិន្នន័យ ដោយមិនតម្រូវឱ្យដាក់ process ឱ្យដំណើរការឡើងវិញ។ Flag
នីមួយៗត្រូវបានពិពណ៌នាដោយ `FeatureFlagDefinition` ដែលមាន `key`, `label`,
`description`, `category`, `defaultValue`, `type` និងព័ត៌មានណែនាំ `requiresRestart`។

### លំដាប់នៃការកំណត់តម្លៃ

**តម្លៃជាក់ស្តែង** របស់ flag ត្រូវបានកំណត់ដោយ
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) តាមលំដាប់អាទិភាពខាងក្រោម (អាទិភាពខ្ពស់ជាងគេមានប្រសិទ្ធភាព)៖

1. **ការកំណត់ជំនួសក្នុង DB** — តម្លៃដែលបានរក្សាទុកក្នុងតារាង `key_value` ក្រោម
   namespace `feature_flags` (កំណត់តាមរយៈផ្ទាំងគ្រប់គ្រង ឬ REST API)។
2. **អថេរបរិស្ថាន** — `process.env[<KEY>]` ប្រសិនបើត្រូវបានកំណត់ និងមិនមែនជាតម្លៃទទេ។
3. **តម្លៃលំនាំដើមនៃនិយមន័យ** — `defaultValue` ពី `featureFlagDefinitions.ts`។

Boolean flag ត្រូវបានចាត់ទុកថា **បានបើក** នៅពេលតម្លៃជាក់ស្តែងរបស់វាគឺ `"true"`,
`"1"` ឬ `"yes"` (សូមមើល `isFeatureFlagEnabled()`)។

> [!NOTE]
> Flag ភាគច្រើនក៏មានអថេរបរិស្ថានដែលត្រូវគ្នា និងមាន **ឈ្មោះដូចគ្នា**
> ដែលបានចងក្រងជាឯកសារនៅក្នុង [`ENVIRONMENT.md`](./ENVIRONMENT.md)។ ការកំណត់ជំនួសក្នុង DB របស់ flag
> មានអាទិភាពលើអថេរបរិស្ថាននោះ។ Flag ដែលមាន
> `requiresRestart: true` ត្រូវបានរក្សាទុកភ្លាមៗ ប៉ុន្តែត្រូវបានអានឡើងវិញតែនៅពេល
> process ចាប់ផ្តើមប៉ុណ្ណោះ — ការបិទបើកវានឹងបង្ហាញបដា **"ចាប់ផ្តើមម៉ាស៊ីនមេឡើងវិញ"** នៅក្នុងផ្ទាំងគ្រប់គ្រង។

### ផ្ទាំង Dashboard

ចូលទៅកាន់ **Dashboard → Settings → Feature Flags**
(`/dashboard/settings/feature-flags`)។ ក្រឡាចត្រង្គ
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
គាំទ្រ៖

- **ស្វែងរក** តាម key ឬ description និង **ត្រង** តាម category (រួមទាំងទិដ្ឋភាពសិប្បនិម្មិត
  **Requires Restart**)។
- **ប៊ូតុងបិទបើក** សម្រាប់ boolean flags និង **បញ្ជីទម្លាក់ចុះ** សម្រាប់ enum flags
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)។
- **ស្លាកប្រភព** សម្រាប់ flag នីមួយៗ — `DB`, `ENV`, ឬ `DEF` — បង្ហាញថាតម្លៃមានប្រសិទ្ធភាព
  មកពីណា។
- ប៊ូតុង **កំណត់ឡើងវិញ** (បង្ហាញតែសម្រាប់ flags ដែលមានប្រភពជា `DB`) ដើម្បីលុប override
  និងប៊ូតុង **កំណត់ Override ទាំងអស់ឡើងវិញ** នៅខាងក្រោម។
- បដា **ចាប់ផ្ដើម Server ឡើងវិញ** នៅពេល flag `requiresRestart` ត្រូវបានផ្លាស់ប្តូរ។

### REST API

ប្រតិបត្តិការទាំងអស់ឆ្លងកាត់ route តែមួយ៖
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)។
គ្រប់ method តម្រូវឱ្យមាន dashboard session ដែលបានផ្ទៀងផ្ទាត់ (`401` បើមិនដូច្នោះទេ)។

#### `GET /api/settings/feature-flags`

បញ្ជូន flag ទាំងអស់ជាមួយតម្លៃមានប្រសិទ្ធភាព ប្រភព និងសេចក្ដីសង្ខេប។

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 119 flags
  ],
  "summary": {
    "total": 119,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

កំណត់ ឬលុប override តែមួយ។ Body៖ `{ key: string; value?: string }`។
ការមិនបញ្ចូល `value` នឹងលុប override (ស្ដារតម្លៃ env / default)។

```bash
# កំណត់ DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# លុប override (គ្មាន "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

ចម្លើយនឹងបង្ហាញ `effectiveValue`/`source` ថ្មី
`previousValue`/`previousSource` មុន និង `requiresRestart`។ key ដែលមិនស្គាល់ និងតម្លៃ enum
ដែលនៅក្រៅជួរ នឹងត្រូវបានបដិសេធដោយ `400`។

#### `DELETE /api/settings/feature-flags`

លុប DB overrides **ទាំងអស់** ក្នុងពេលតែមួយ ដោយស្ដារ flag នីមួយៗទៅតម្លៃ env / default
របស់វា។ បញ្ជូនត្រឡប់ `{ cleared: <count>, message: "..." }`។

> [!NOTE]
> Flags ដែលមាន `requiresRestart: true` នឹងមានប្រសិទ្ធភាពតែបន្ទាប់ពី reload process ប៉ុណ្ណោះ។
> លំហូរចាប់ផ្ដើមឡើងវិញរបស់ dashboard ហៅ `POST /api/restart` ហើយបន្ទាប់មកធ្វើ polling
> `GET /api/health/ping` រហូតដល់ server ដំណើរការឡើងវិញ។
