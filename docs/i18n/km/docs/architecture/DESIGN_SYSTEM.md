## 1. កន្លែងដែលវត្ថុរស់នៅ

- **កញ្ចប់។** `packages/ui-kit/src` គឺជាការចម្លងបៃសម្រាប់បៃនៃ `src/` ខាងលើនៅការប្តេជ្ញាចិត្តដែលបានខ្ទាស់ក្នុង `packages/ui-kit/UPSTREAM.md` (ដែលក៏កត់ត្រាការអនុញ្ញាតអាជ្ញាប័ណ្ណផងដែរ); `PATCHES.md` រាយបញ្ជីបំណះក្នុងតំបន់។ វាត្រូវបានប្រើប្រាស់ជាប្រភព ដោយគ្មានការស្ថាបនា៖ `next.config.mjs` ចម្លងវា ហើយ `tsconfig.json` ផែនទី `@omniroute/ui-kit` → `packages/ui-kit/src` និង `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` (`vitest.config.ts` និង `vitest.mcp.config.ts` អនុវត្តឈ្មោះក្លែងក្លាយដូចគ្នា)។ នាំចូលសមាសធាតុឧបករណ៍ដោយផ្លូវរងរបស់វា (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`… ) មិនដែលឆ្លងកាត់ធុង `@omniroute/ui-kit` ទេ៖ ធុងទាញគ្រប់សមាសធាតុទាំងអស់ (រួមទាំងកម្មវិធីជ្រើសរើសកាលបរិច្ឆេទ) ទៅក្នុងអ្នកនាំចូលនីមួយៗ។ សន្លឹករចនាប័ទ្មកញ្ចប់បញ្ចូលតាមរយៈ `src/app/globals.css` (`@import "../../packages/ui-kit/src/ci-styles.css"` សន្លឹកពេញលេញ៖ `ci-ui.css` ស្នូល បូកនឹងគ្រួសារគំរូនីមួយៗ)។

## 3. ការបន្ថែម screen

1. បើកទំព័រជាមួយ kit `PageHeader` (`@omniroute/ui-kit/page-header`, ប្រើ `compact` នៅក្នុង dashboard) — ចំណងជើង ការពិពណ៌នា និង `actions`។ បន្ទាប់មក shell header នឹងដកចំណងជើងរបស់ខ្លួនចេញ។
2. សាងសង់ controls ពី `@/shared/components` (adapters) ហើយប្រើ kit components តាម subpath នៅកន្លែងដែលមិនមាន adapter (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`, `Slider`…)។
3. Icons: `<Icon name="…" />`។ ឈ្មោះថ្មីត្រូវបន្ថែមទៅក្នុង `ICON_MAP` ជាមួយ Lucide component ដែលត្រូវគ្នាតាមអត្ថន័យ; `npm run gen:icon-map` រាយឈ្មោះដែលនៅខ្វះ។
4. ពណ៌៖ semantic utilities (`text-success`, `bg-warning-bg`, `border-border`…) និង `var(--color-chart-N)` សម្រាប់ chart series; មិនអនុញ្ញាតតម្លៃ hex និង `dark:` variants ដែលគ្រាន់តែធ្វើពណ៌ដដែលម្តងទៀត។
5. អត្ថបទ៖ រាល់ string រួមទាំង labels ដែលអ្នកបញ្ជូនទៅ kit components ត្រូវមកពី `useTranslations`។ keys ថ្មីត្រូវបន្ថែមទៅក្នុង `src/i18n/messages/en.json`, `pt-BR.json` និង `vi.json` (Vietnamese parity test កំណត់រាល់ English key ទាំងអស់); locales ផ្សេងទៀតនឹងត្រូវបានបំពេញដោយ i18n sync។
6. ដំណើរការ guards មុនពេលបង្កើត PR៖ `tests/unit/dashboard-kit-sweep.test.ts`, `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`, `npm run check:dashboard-typecheck` (ការពិនិត្យតែមួយគត់ដែលចាប់បាន duplicated import នៅក្នុង `iconMap.ts`), `npm run check:ui-icu` និង tests ផ្ទាល់ខ្លួនរបស់ screen នោះ។

## 5. ការធ្វើបច្ចុប្បន្នភាព kit

`npm run check:ui-kit-upstream` ប្រៀបធៀបកំណែដែលបានខ្ទាស់ក្នុង `packages/ui-kit/UPSTREAM.md` ជាមួយនឹងស្លាក `v*` ថ្មីបំផុតនៃ repo ខាងលើ ហើយបោះពុម្ពពាក្យបញ្ជាធ្វើសមកាលកម្ម នៅពេលការចេញផ្សាយចេញ។

លំហូរការងារ `UI Kit upstream watch` ប្រចាំថ្ងៃ (`.github/workflows/ui-kit-upstream-watch.yml`) ដំណើរការការត្រួតពិនិត្យដូចគ្នា។ ខណៈពេលដែលម្ជុលស្ថិតនៅខាងក្រោយ `scripts/ci/ui-kit-sync-pr.sh` រក្សាសមកាលកម្មមួយ PR បើកទល់នឹងសាខា `release/vX.Y.Z` ខ្ពស់បំផុតនៅលើសាខាវិល `chore/ui-kit-sync-latest`។ វាមិនដែលបញ្ចូលគ្នាទេ៖ រាល់ការចេញផ្សាយកញ្ចប់នៅតែត្រូវការការត្រួតពិនិត្យមើលឃើញនៅលើ VPS មូលដ្ឋាន។ សាខានេះត្រូវបានសាងសង់ឡើងវិញនៅពេលដែលការចេញផ្សាយថ្មីជាងនេះចេញហើយទុកចោលតែម្នាក់ឯងបើមិនដូច្នេះទេ។ PR បើកចំហជាមួយនឹងការប្តេជ្ញាចិត្តដែលរុញដោយដៃមិនត្រូវបានសរសេរជាន់លើទេ ហើយ PR សម្រាប់កំណែដែលអ្នកថែទាំបានបិទដោយមិនបានបញ្ចូលនឹងបិទរហូតដល់ការចេញផ្សាយថ្មីជាងនេះ។

នៅពេលដែលគ្មាន PR អាចត្រូវបានបើក (ការចេញផ្សាយគោលដៅត្រូវបានជាប់គាំង PR បានប្រព្រឹត្តដោយរុញដោយដៃ PR ត្រូវបានបិទ ឬមិនមានសញ្ញាសម្ងាត់ PR ត្រូវបានកំណត់) លំហូរការងាររក្សាបញ្ហាតាមដានមួយបើកចំហដែលនិយាយថាហេតុអ្វី។

ដំណើរការការងារប្រើអាថ៌កំបាំងពីរ៖
