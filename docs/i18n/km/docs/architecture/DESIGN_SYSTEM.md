  barrel `@omniroute/ui-kit` ដាច់ខាត៖ barrel នឹងទាញ component ទាំងអស់ (រួមទាំង date picker) ចូលទៅក្នុង

  utility នៅតែបន្តដំណើរការ។ កូដថ្មីប្រើ Tailwind utility (`bg-surface`, `text-text-muted`,
  `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) ឬ class របស់ kit — កុំប្រើតម្លៃ hex ដាច់ខាត

## 3. ការបន្ថែម screen

1. បើកទំព័រជាមួយ kit `PageHeader` (`@omniroute/ui-kit/page-header`, ប្រើ `compact` នៅក្នុង dashboard) — ចំណងជើង ការពិពណ៌នា និង `actions`។ បន្ទាប់មក shell header នឹងដកចំណងជើងរបស់ខ្លួនចេញ។
2. សាងសង់ controls ពី `@/shared/components` (adapters) ហើយប្រើ kit components តាម subpath នៅកន្លែងដែលមិនមាន adapter (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`, `Slider`…)។
3. Icons: `<Icon name="…" />`។ ឈ្មោះថ្មីត្រូវបន្ថែមទៅក្នុង `ICON_MAP` ជាមួយ Lucide component ដែលត្រូវគ្នាតាមអត្ថន័យ; `npm run gen:icon-map` រាយឈ្មោះដែលនៅខ្វះ។
4. ពណ៌៖ semantic utilities (`text-success`, `bg-warning-bg`, `border-border`…) និង `var(--color-chart-N)` សម្រាប់ chart series; មិនអនុញ្ញាតតម្លៃ hex និង `dark:` variants ដែលគ្រាន់តែធ្វើពណ៌ដដែលម្តងទៀត។
5. អត្ថបទ៖ រាល់ string រួមទាំង labels ដែលអ្នកបញ្ជូនទៅ kit components ត្រូវមកពី `useTranslations`។ keys ថ្មីត្រូវបន្ថែមទៅក្នុង `src/i18n/messages/en.json`, `pt-BR.json` និង `vi.json` (Vietnamese parity test កំណត់រាល់ English key ទាំងអស់); locales ផ្សេងទៀតនឹងត្រូវបានបំពេញដោយ i18n sync។
6. ដំណើរការ guards មុនពេលបង្កើត PR៖ `tests/unit/dashboard-kit-sweep.test.ts`, `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`, `npm run check:dashboard-typecheck` (ការពិនិត្យតែមួយគត់ដែលចាប់បាន duplicated import នៅក្នុង `iconMap.ts`), `npm run check:ui-icu` និង tests ផ្ទាល់ខ្លួនរបស់ screen នោះ។

## 4. ការបន្ថែម ឬផ្លាស់ប្តូរ adapter

1. រក្សា public API របស់ `src/shared/components/index.tsx` ឱ្យនៅដដែល៖ ឈ្មោះ export ដដែល default export ដដែល និង
   props ដែលទទួលយកដដែល។ ផ្គូផ្គង legacy props ទៅលើ kit នៅខាងក្នុង adapter (មើល `Button.tsx`៖ `VARIANT_TO_KIT`,
   `SIZE_TO_KIT`)។
2. Import kit តាម subpath (`@omniroute/ui-kit/<component>`)។
3. ដំណោះស្រាយបណ្តោះអាសន្នសម្រាប់ចំណុចខ្វះរបស់ kit ស្ថិតនៅក្នុង adapter (ឬក្នុង `globals.css` `@layer components` នៅពេលដែលការជួសជុលគឺជា
   style) មិនដែលនៅក្នុង `packages/ui-kit/src` ឡើយ។
4. បន្ថែម ឬធ្វើបច្ចុប្បន្នភាព `tests/unit/ui/adapters/<name>.test.tsx`។ សម្រាប់ adapter ដែលមាន caller ច្រើន សូមប្រៀបធៀប
   markup ដែលបាន render នៅមុន និងក្រោយការផ្លាស់ប្តូរ — ការផ្លាស់ប្តូរ padding ឬ wrapper រាលដាលទៅគ្រប់ screen ទាំងអស់។

## 5. ការធ្វើបច្ចុប្បន្នភាព kit

`scripts/dev/sync-ui-kit.sh <commit> [clone]` ចម្លង `src/` ពី upstream នៅ commit នោះ ចូលទៅក្នុង
`packages/ui-kit/src` ហើយអនុវត្តការបំប្លែងតែមួយដែលត្រូវបានអនុញ្ញាត (វាដក suffix `.js` ចេញពី
relative import)។ បន្ទាប់មក៖ ពិនិត្យ `git diff packages/ui-kit` ធ្វើការត្រួតពិនិត្យមើលដោយផ្ទាល់លើ providers, settings, combos,
usage និង endpoint ក្នុង theme ទាំងពីរ ដំណើរការ `npm run check:ui-kit-snapshot` និង `npm run test:vitest:ui` ហើយ
បើក PR ជាមួយនឹង changelog ពី upstream។
