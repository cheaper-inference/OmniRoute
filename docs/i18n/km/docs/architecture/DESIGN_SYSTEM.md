## 1. ទីកន្លែងដែលអ្វីៗស្ថិតនៅ

- **ឈុត (Kit).** `packages/ui-kit/src` គឺជាការចម្លងដូចគ្នាគ្រប់ byte នៃ upstream `src/` នៅ commit ដែលបានខ្ទាស់ក្នុង
  `packages/ui-kit/UPSTREAM.md` (ដែលក៏កត់ត្រាការអនុញ្ញាតអាជ្ញាបណ្ណផងដែរ); `PATCHES.md` រាយបញ្ជី patch
  ក្នុងស្រុក (គ្មាន)។ វាត្រូវបានប្រើប្រាស់ជា source ដោយគ្មាន build៖ `next.config.mjs` transpile វា ហើយ
  `tsconfig.json` map `@omniroute/ui-kit` → `packages/ui-kit/src` និង `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` (`vitest.config.ts` និង `vitest.mcp.config.ts` មាន alias ដូចគ្នា)។ Import
  សមាសធាតុ kit តាម subpath របស់វា (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) កុំ import
  តាម barrel `@omniroute/ui-kit` ដាច់ខាត៖ barrel ទាញសមាសធាតុទាំងអស់ (រួមទាំង date picker)
  ចូលទៅក្នុង importer នីមួយៗ។ Stylesheet របស់ kit ចូលតាមរយៈ `src/app/globals.css`
  (`@import "../../packages/ui-kit/src/ci-ui.css"`)។
- **ថូខឹន (Tokens).** `packages/ui-kit/src/ci-tokens.css` ប្រកាស token `--ci-*`; `src/app/globals.css`
  ផ្សារភ្ជាប់ពួកវាទៅឈ្មោះ OmniRoute បែបចាស់ (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`) ដូច្នេះការអាន `var(--color-*)` ដែលមានស្រាប់ និង Tailwind
  utilities នៅតែដំណើរការ។ កូដថ្មីប្រើ Tailwind utilities (`bg-surface`, `text-text-muted`,
  `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) ឬថ្នាក់ kit — កុំប្រើតម្លៃ hex ដាច់ខាត
  (`tests/unit/design-kit-bridge.test.ts` បង្ខំ bridge នេះ)។ `text-primary` បកស្រាយទៅ
  `--color-primary-ink` តាមរយៈ `--text-color-primary` (lime-800 ក្នុង light, lime accent ក្នុង dark) ដូច្នេះ
  អត្ថបទ primary នៅតែអានបាន ខណៈដែល `bg-primary`/`border-primary` រក្សាផ្ទៃ lime។ Chart series ប្រើ
  `--color-chart-1` … `--color-chart-5`។
- **រូបរាង (Themes).** `<html className="ci-theme">` (`src/app/layout.tsx`) ដាក់ឯកសារឱ្យចូលរួមក្នុង theme របស់ kit។
  ចំណូលចិត្តគឺ `light`, `dark` ឬ `system` (`THEME_CONFIG.defaultTheme = "system"` ក្នុង
  `src/shared/constants/appConfig.ts`; `system` តាម `prefers-color-scheme`)។ `applyTheme()` ក្នុង
  `src/store/themeStore.ts` (ចម្លងតាមដោយ inline bootstrap script ក្នុង `src/app/layout.tsx` ដែលដំណើរការ
  មុន hydration) កំណត់ `data-theme="dark"|"light"` និងបិទ/បើក class `.dark` លើ `<html>` ព្រមគ្នា។
  សំណុំ token dark របស់ kit ផ្អែកលើ `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`);
  ការ override dark ផ្ទាល់ខ្លួនរបស់ OmniRoute (ប្លុក `.dark` ក្នុង `globals.css`) និង legacy Tailwind `dark:`
  utilities ផ្អែកលើ class `.dark`។ គ្មាន accent color preset ទេ៖ accent មកពី
  kit ជានិច្ច ហើយ preset ដែលបានរក្សាទុកពី build ចាស់ ត្រូវបានបោះបង់ចោលនៅពេល store ផ្ទុក។
- **សមាសធាតុ (Components/adapters).** `src/shared/components/index.tsx` រក្សា API សមាសធាតុ OmniRoute (ឈ្មោះដូចគ្នា
  default exports និង props ដូចគ្នា) ហើយ primitives នៅខាងក្រោយវាគឺជា adapters លើ kit៖ ទម្រង់
  (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), overlays និង feedback
  (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`),
  រចនាសម្ព័ន្ធ (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) និងតារាង
  (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`)។ Adapter មួយ import សមាសធាតុ kit
  តាម subpath ហើយ map legacy props ទៅលើវា — ឧទាហរណ៍ `Button variant="primary"` គឺជា
  button `default` របស់ kit (`--ci-button-primary-*`៖ ផ្ទៃ inverse ក្នុង light, accent ជាមួយ
  ពណ៌ទ្រិដ `--ci-color-accent-foreground` ក្នុង dark), `danger` គឺ `destructive` ហើយ `warning` គឺ `outline`
  បូកផ្នែកបន្ថែម `.ci-button--warning`។ ច្បាប់ `.ci-button--warning` និង `.ci-badge[data-tone]` នៅ
  ចុង `globals.css` (`@layer components`) គឺជាផ្នែកបន្ថែមរបស់ OmniRoute លើថ្នាក់ kit។
  `tests/unit/ui/adapters/*.test.tsx` ខ្ទាស់ adapter នីមួយៗ។

## 2. ច្បាប់

1. ប្រើ tokens ជានិច្ច កុំប្រើ literals ឡើយ។ ករណីលើកលែងដែលរក្សាទុកដោយចេតនា: console terminal ដែលងងឹតជានិច្ច, ReactFlow SVG
   strokes តាមរយៈ `STATUS_HEX` (`src/shared/constants/statusColors.ts`), និង palettes តាមប្រភេទ
   `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) និង
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`)។
2. កុំកែប្រែ `packages/ui-kit/src` ដោយដៃជាដាច់ខាត: ធ្វើសមកាលកម្មជាមួយ `scripts/dev/sync-ui-kit.sh <commit>`; ទ្វារ
   pre-commit `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) បរាជ័យលើ byte ណាមួយដែល
   ខុសពី upstream commit ដែលបាន pin (វារំលងជាមួយការព្រមាននៅពេល upstream clone,
   `UI_KIT_CLONE` ឬ `_references/cheaper-inference-ui-kit`, មិនមាន)។ នៅពេល kit ខ្វះអ្វីមួយ,

## 4. ការបន្ថែម ឬផ្លាស់ប្តូរ adapter

1. រក្សា public API របស់ `src/shared/components/index.tsx` ឱ្យនៅដដែល៖ ឈ្មោះ export ដដែល, default exports ដដែល និង props ដែលទទួលយក។ បម្លែង (map) legacy props ទៅលើ kit នៅខាងក្នុង adapter (មើល `Button.tsx`: `VARIANT_TO_KIT`, `SIZE_TO_KIT`)។
2. Import kit តាម subpath (`@omniroute/ui-kit/<component>`)។
3. Workaround សម្រាប់ចំណុចខ្វះខាតរបស់ kit ត្រូវដាក់នៅក្នុង adapter (ឬក្នុង `globals.css` `@layer components` នៅពេលដែលការជួសជុលគឺជា style) កុំដាក់នៅក្នុង `packages/ui-kit/src` ឲ្យសោះ។
4. បន្ថែម ឬធ្វើបច្ចុប្បន្នភាព `tests/unit/ui/adapters/<name>.test.tsx`។ សម្រាប់ adapter ដែលមានអ្នកហៅប្រើច្រើន សូមប្រៀបធៀប markup ដែល render ចេញមុន និងក្រោយការផ្លាស់ប្តូរ — ការផ្លាស់ប្តូរ padding ឬ wrapper នឹងរីករាលដាលទៅគ្រប់អេក្រង់ទាំងអស់។

## 5. ការធ្វើបច្ចុប្បន្នភាព kit

`scripts/dev/sync-ui-kit.sh <commit> [clone]` ចម្លង `src/` ពី upstream នៅ commit នោះ មកដាក់ក្នុង `packages/ui-kit/src` ហើយអនុវត្តការបម្លែងតែមួយគត់ដែលត្រូវបានអនុញ្ញាត (វាដក suffix `.js` ចេញពី relative imports)។ បន្ទាប់មក៖ ពិនិត្យ `git diff packages/ui-kit` ធ្វើការពិនិត្យដោយភ្នែកលើ providers, settings, combos, usage និង endpoint ក្នុង theme ទាំងពីរ ដំណើរការ `npm run check:ui-kit-snapshot` និង `npm run test:vitest:ui` រួចបើក PR ជាមួយនឹង changelog របស់ upstream។
