## ច្រកទ្វារសារពើភ័ណ្ឌ និងទម្រង់ប្រតិបត្តិ

### ការចុះឈ្មោះបេក្ខជន

លំហូរការងារ CI និង Quality Gates នីមួយៗបញ្ចេញនូវសាលក្រមដែលមានស្ថេរភាព៖ `Gate / CI` និង `Gate / Quality`។ គោលការណ៍ទទួលបានកំណែរបស់ពួកគេបានចុះបញ្ជីរាល់ការងារខាងលើតាមតម្រូវការ ឬការប្រឹក្សា។ ការងារដែលត្រូវការដែលអាចអនុវត្តបានត្រូវតែជោគជ័យ៖ បាត់ លុបចោល រំលង មិនទាន់សម្រេច និងលទ្ធផលមិនស្គាល់មិនអាចបង្កើត PASS បានទេ។ ការចាត់ថ្នាក់សម្រាប់តែឯកសារ ឬតែកាតាឡុកដែលមានសុពលភាពអាចធ្វើឱ្យផ្លូវកូដមិនអាចអនុវត្តបាន។ PR ព្រាងមិនមែនជាបេក្ខជនដែលទទួលយកទេ។ ស្លាក `hotfix` មិនលះបង់ភស្តុតាងទេ។

លំហូរការងារទាំងពីរគ្របដណ្តប់ PRs ចូលទៅក្នុងសាខា main/release រុញទៅ `main` ការបញ្ជូនដោយដៃ និងព្រឹត្តិការណ៍ក្រុមបញ្ចូលគ្នា។ រុញ បញ្ជូន និងបញ្ចូលក្រុម ដំណើរការការជ្រើសរើសពេញលេញ។ ការរុញទៅ `release/**` មិនចាប់ផ្តើមពួកវាទេ (2026-10-18): ការផ្លាស់ប្តូរនីមួយៗបានដំណើរការម៉ាទ្រីសរួចហើយនៅលើ PR របស់វា ហើយការរួមបញ្ចូលគ្នាដែលបានបញ្ចូលគ្នាគឺជាការងាររបស់ Release-Green (`docs/ops/RUNNER_BOX.md` → Hosted lane) ។ សម និងក្រុមបញ្ចូលគ្នាប្រើអ្នករត់ដែលរៀបចំសម្រាប់ការងារដែលជ្រើសរើសអ្នករត់ដែលរៀបចំដោយខ្លួនឯង សមត្ថភាពរៀបចំគ្រប់គ្រាន់ត្រូវតែផ្ទៀងផ្ទាត់មុនពេលដាក់ឱ្យដំណើរការ។

PR ធម្មតាដំណើរការការជ្រើសរើសលឿន។ ផ្លូវ `full-code` និង `full-code-e2e` នៃគោលការណ៍ចូលរៀន (E2E, ការរួមបញ្ចូល , វត្ថុបុរាណកញ្ចប់ , Electron smoke , Bun SQLite, ecosystem និង protocol clients ) ដំណើរការតែលើសេចក្តីព្រាងជួរបញ្ចូលគ្នា ឬនៅលើការដំណើរការពេញលេញប៉ុណ្ណោះ៖ `gh workflow run ci.yml --ref <branch>`។

### បញ្ចូលជួរ

ស្លាក `queue` ផ្ញើ PR ទៅកាន់ជួររួមបញ្ចូលគ្នា (`.mergify.yml`) ។ Mergify បើក PR ព្រាងនៅលើសាខា `mergify/merge-queue/` CI ដំណើរការការជ្រើសរើសពេញលេញនៅទីនោះ ហើយ PR ដើមបញ្ចូលចូលគ្នានៅពេលដែល `Gate / CI`, `Gate / Quality` និង `Merge integrity (changelog + generated skills)` ឆ្លងកាត់។

Mergify សរសេរសេចក្តីសង្ខេបជួររបស់វាទៅក្នុងសេចក្តីពិពណ៌នារបស់សេចក្តីព្រាង ហើយកម្មវិធីផ្សេងទៀតក៏អាចកែសម្រួលវាបានផងដែរ។ ព្រឹត្តិការណ៍ `pull_request` `edited` លើសេចក្តីព្រាងបែបនេះយកក្រុមស្របគ្នារបស់វា (`-queue-edit-<run_id>`) ដូច្នេះវាមិនអាចលុបចោលការដំណើរការពិតរបស់សេចក្តីព្រាងបានទេ ហើយវារំលងច្រកទ្វារ និងម៉ាទ្រីស។ មានតែ `Merge integrity` នៅតែដំណើរការ។ ការងារច្រកទ្វារដែលរំលងមានឈ្មោះធីកផ្សេងគ្នា ពីព្រោះ Mergify អាន `Gate / CI` ដែលបានរំលងជាការត្រួតពិនិត្យដែលបរាជ័យ និង dequeues PR។

បន្ទាប់ពីផ្អាកការជំរុញមិនតែងតែស្នើសុំ PRទេ។ ផ្តល់យោបល់ `@mergifyio queue` លើវា។

បង្កាន់ដៃ JSON នីមួយៗកំណត់ SHA ដែលបានពិនិត្យចេញ លំហូរការងារ និងការព្យាយាម។ CLI បដិសេធ checkout/event SHA មិនត្រូវគ្នា។ ការធ្វើតេស្តលំហូរការងារភ្ជាប់សមាជិកភាពគោលនយោបាយទៅនឹងបញ្ជី `needs` នៃការងារសាលក្រម ដូច្នេះផ្លូវថ្មី ឬដែលត្រូវបានដកចេញមិនអាចបាត់ដោយស្ងៀមស្ងាត់បានទេ។ បង្កាន់ដៃនេះគ្របដណ្តប់លើដំណើរការការងារផ្ទាល់របស់ពួកគេ មិនមែនការបោះពុម្ព ការដាក់ឱ្យប្រើប្រាស់ ឬផ្នែកខាងក្នុងនៃម៉ាស៊ីនស្កេនផ្តល់ប្រឹក្សាដែលមានស្រាប់នោះទេ។ ការធ្វើឱ្យឈ្មោះធីកទាំងពីរសកម្មនៅក្នុងច្បាប់សាខាគឺជាការផ្លាស់ប្តូររដ្ឋបាលដាច់ដោយឡែក។ ការបន្ថែមការងារទាំងនេះមិនការពារសាខាទេ។

### សារពើភ័ណ្ឌស្កេនឋិតិវន្ត

សារពើភ័ណ្ឌ npm-alias កំណែ និងសមាជិកភាព static-scan រស់នៅក្នុង `config/quality/gate-manifest.json`។ ដំណើរការ `npm run check:gate-manifest` ដើម្បីធ្វើសុពលភាពឈ្មោះស្គ្រីប និងពាក្យបញ្ជាពិតប្រាកដប្រឆាំងនឹង `package.json`; ការបន្ថែម ការដកយកចេញ និងការរសាត់ពាក្យបញ្ជាបរាជ័យទាំងទំពក់ក្នុងស្រុក និងការងារផ្លាស់ប្តូរចំណាត់ថ្នាក់នៅក្នុង CI។ ឈ្មោះក្លែងក្លាយមិនមែនជាការងារលំហូរការងារទេ ឧទាហរណ៍ម៉ាទ្រីស ឬករណីសាកល្បង៖ ចំនួនទាំងនេះមិនត្រូវបង្ហាញថាអាចផ្លាស់ប្តូរបានទេ។

ប្រើ `npm run quality:scan -- --list` ឬ `npm run quality:scan:fast -- --list` ដើម្បីពិនិត្យមើលឈ្មោះក្លែងក្លាយដែលបានជ្រើសរើសដោយមិនចាំបាច់ប្រតិបត្តិពួកវា។ អ្នករត់ការហៅចំណុចបញ្ចូល npm ដូច្នេះរយៈពេលរត់របស់វា (រួមទាំង Bun ដែលកំណត់រចនាសម្ព័ន្ធ) ត្រូវបានរក្សាទុក។ Manifest កត់ត្រាឈ្មោះក្លែងក្លាយនៅខាងក្រៅទម្រង់ទាំងនោះ ដូចដែលបានហៅដាច់ដោយឡែក ហើយពាក្យបញ្ជាថែទាំត្រូវបានហាមឃាត់នៅក្នុងទម្រង់ស្កេនបានតែអានប៉ុណ្ណោះ។

ទម្រង់ទាំងនេះគ្របដណ្តប់តែការស្កេនឋិតិវន្តប៉ុណ្ណោះ។ ពួកគេមិនបញ្ជាក់ការធ្វើតេស្តផលិតផល ការគ្របដណ្តប់ ការវេចខ្ចប់ ការត្រួតពិនិត្យខាងក្រៅ ឬការទទួលយកការចេញផ្សាយពេញលេញរបស់បេក្ខជននោះទេ។ ការទទួលយកលំហូរការងារប្រើ `config/quality/admission-policy.json` និង `scripts/quality/admission-verdict.mjs` ដែលបានភ្ជាប់។ ទម្រង់អ្នកសង្កេតការចេញផ្សាយនៅដាច់ដោយឡែក។ ត្រួតពិនិត្យការត្រួតពិនិត្យ និងបង្កាន់ដៃដែលអាចអនុវត្តបានដោយឯករាជ្យ។ សារពើភណ្ឌសុភាសិតខាងក្រោមគឺជាឯកសារយោង មិនមែនជាភ័ស្តុតាងដែលថាច្រកទ្វារមួយបានដំណើរការពិតប្រាកដនោះទេ។

ស្គ្រីបរស់នៅក្រោម `scripts/check/` (ច្រកទ្វារគោលនយោបាយ) និង `scripts/quality/` (ម៉ាស៊ីន ratchet) ។ ប្រភព CI នៃការពិតគឺ `.github/workflows/ci.yml`។

### ដោះលែង PR fast-path (`quality.yml`)

`.github/workflows/quality.yml` បំពេញបន្ថែម CI នៅលើ main/release PRs រុញទៅ `main` បញ្ជូន និងបញ្ចូលក្រុម។ PRs ប្រើការត្រួតពិនិត្យរហ័សដែលបានត្រងផ្លូវ។ ការស្ថាបនាស្ទួនដែលត្រូវបានបិទជាអចិន្ត្រៃយ៍ត្រូវបានដកចេញ។ ការត្រួតពិនិត្យ build/package/boot ពិតប្រាកដនៅតែមាននៅក្នុង CI។ ឈុតឯកតា និង vitest ដំណើរការតែនៅក្នុង CI (`Unit Tests (N/8)` និង `Vitest`) ប៉ុណ្ណោះ។

| ការងារ                                           | វិសាលភាព                                                                                                                                           | ការទប់ស្កាត់      |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| `Docs Gates (fast-path)`                         | Docs/code PRs; API docs refs និង docs-all                                                                                                          | បាទ               |
| `Fast Quality Gates`                             | កូដ PRs; ការត្រួតពិនិត្យឋិតិវន្ត, វាយអក្សរ, ការត្រួតពិនិត្យលើផ្ទៃតាប្លូ, ការធ្វើតេស្តឯកតាដែលរងផលប៉ះពាល់, ការធ្វើតេស្តបងប្អូនដែលភ្លេច (ការប្រឹក្សា) |

#### របាយការណ៏ការធ្វើតេស្តបងប្អូនដែលភ្លេច

`npm run check:forgotten-sibling-tests` ដំណើរការជាជំហានប្រឹក្សារបស់ `Fast Quality Gates` ហើយប្រើឡើងវិញនូវឧបករណ៍ដោះស្រាយការនាំចូលនៅពីក្រោយផែនទីផលប៉ះពាល់សាកល្បង។ សម្រាប់រាល់ម៉ូឌុលផលិតកម្មដែលបានផ្លាស់ប្តូរ វារាយការណ៍អំពីខ្សែសង្វាក់ `changed module/symbol -> static consumer -> candidate sibling test` ដែលកំណត់នៅពេលដែលការធ្វើតេស្តបេក្ខជនអវត្តមានពីភាពខុសគ្នានៃសំណើរទាញ។ សេចក្តីសង្ខេប Markdown និងលទ្ធផល JSON ត្រូវបានរក្សាទុកជាវត្ថុបុរាណនៃលំហូរការងារ `forgotten-sibling-tests` សម្រាប់ការក្រិតតាមខ្នាត មុនពេលការបិទដំណើរការណាមួយ។

ការនាំចេញឡើងវិញនូវធុងបារ៉ែល និងការនាំចូលថាមវន្ត គឺជាដំណោះស្រាយការវិនិច្ឆ័យតែប៉ុណ្ណោះ។ ពួកគេមិនដែលបង្កើតការរកឃើញរារាំងទេ។ ពិនិត្យករណីលើកលែងរស់នៅក្នុង `config/quality/forgotten-sibling-allowlist.json`។ ធាតុនីមួយៗត្រូវតែដាក់ឈ្មោះការធ្វើតេស្តអតិថិជន និងបេក្ខជន ផ្តល់ហេតុផលជាក់លាក់ និងភ្ជាប់បញ្ហា GitHub ឬទាញសំណើ។ ធាតុខុសទម្រង់មិនបានបិទ។ ករណីលើកលែងមិនអាចរារាំងការធ្វើតេស្តបេក្ខជនដែលបានលុប ឬភាពខុសគ្នាដែលបន្ថែម `.skip`/`.todo`; ការអះអាងចុះខ្សោយ និងការបិទបាំងផ្សេងទៀតនៅតែជាកម្មសិទ្ធិរបស់ច្រកទ្វារ `check:test-masking` ដែលរារាំងដោយឯករាជ្យ។

`typecheck:core` និង `check:build-typecheck` ចងក្រងកម្មវិធីផ្សេងគ្នានៅក្រោមជម្រើសផ្សេងគ្នា ហើយឯកសារដូចគ្នាអាចស្អាតនៅក្នុងមួយ និងពោរពេញដោយកំហុសនៅក្នុងមួយផ្សេងទៀត។

`tsconfig.build.json` កំណត់ `"strict": false` ដូច្នេះ `noImplicitAny` បិទ។ ការកំណត់រចនាសម្ព័ន្ធស្នូលចងក្រងបញ្ជីអនុញ្ញាតឯកសារចំនួន 27 ដែលមានជម្រើសតឹងរ៉ឹង ហើយធ្វើតាមក្រាហ្វនាំចូលរបស់ធាតុនីមួយៗ ដូច្នេះឯកសារដែលមិនដែលបង្ហាញក្នុងកម្មវិធីសាងសង់នៅតែត្រូវបានពិនិត្យនៅទីនោះ។

លទ្ធផលគឺសំខាន់នៅពេលវិនិច្ឆ័យថាតើឯកសារត្រូវបានវាយបញ្ចូល៖** ការធ្វើរោគវិនិច្ឆ័យសូន្យនៅក្រោម `check:build-typecheck` មិនមានន័យថាសូន្យទេ។** . ការដក `@ts-nocheck` ចេញពីឯកសារចំនួន 26 បានបង្ហាញថា 23 នៃពួកគេស្អាតនៅក្នុងកម្មវិធីសាងសង់។ ដប់ប្រាំមួយនៃអ្នកទាំងនោះបានលេចឡើងប្រហែល 120 កំហុសក្នុងការតឹងរ៉ឹង។ ពិនិត្យទាំងពីរមុនពេលហៅឯកសារស្អាត។

#### `check-ui-value-drift` — stale-translation gate

ចាប់យកការតំរែតំរង់ i18n ដែលច្រកផ្សេងទៀតមិនអាចមើលឃើញតាមរចនាសម្ព័ន្ធ៖ តម្លៃភាសាអង់គ្លេសត្រូវបានសរសេរឡើងវិញ ហើយការបកប្រែដែលបានមកពី _previous_ ភាសាអង់គ្លេសនៅខាងក្រោយ ដូច្នេះអ្នកប្រើប្រាស់ដែលមិនមែនជាភាសាអង់គ្លេសបន្តអានដោយទំនុកចិត្ត និងច្បាប់ចម្លងឥឡូវនេះខុស។

នេះបានដឹកជញ្ជូនពិតប្រាកដ។ `oauthModal.googleOAuthWarning` ត្រូវបានសរសេរឡើងវិញនៅពេលដែលជំនួយការចូល Antigravity ចុះចត (#5203);** 39 នៃ 43 មូលដ្ឋាន** បានរក្សាទុកអត្ថបទប្រាប់ប្រតិបត្តិករឱ្យ "ចម្លង URL ពេញលេញ ហើយបិទភ្ជាប់វាខាងក្រោម" — លំហូរដែលមិនអាចបំពេញបានសម្រាប់អ្នកផ្តល់សេវានោះ។ វាមិនបានកត់សម្គាល់រហូតដល់ #8463 ដោយសារតែ៖

- `sync-ui-keys` មានតែ backfill keys ដែលមាន** អវត្តមាន** ដែលមិនដែលមាន** ចាស់** ;
- `check-ui-keys-coverage` រាប់ key _presence_ ដូច្នេះការបកប្រែ stale ទទួលបានពិន្ទុដូចដែលបានគ្របដណ្តប់;
- `check-translation-drift` តាមដានឯកសារ `docs/i18n/<locale>/**.md` កញ្ចក់ — វាមិនដែលអាន `src/i18n/messages/*.json`។ ការទប់ស្កាត់នៅក្នុងការងារ `docs-sync-strict` ចាប់តាំងពីឆ្នាំ 2026-09 ធ្វើសមកាលកម្មឡើងវិញ៖ កែសម្រួលឯកសារស្នូល → `npm run i18n:run -- --files=<doc>` (កម្រិតផ្នែក តម្លៃថោក)។

**Diff-aware, មិនមានមូលដ្ឋានគាំទ្រ.** វាប្រៀបធៀប `en.json` នៅមូលដ្ឋានបញ្ចូលគ្នាប្រឆាំងនឹងដើមឈើធ្វើការ; សម្រាប់រាល់សោដែលតម្លៃភាសាអង់គ្លេសបានផ្លាស់ប្តូរ មូលដ្ឋានណាមួយដែលនៅតែរក្សាការបកប្រែដែលមិនប៉ះពាល់គឺជាប់គាំង។ នេះដោយចេតនា** បង្កកបំណុលដែលមានស្រាប់** — a diff មិនអាចបង្ហាញថាតើភាសាអង់គ្លេសចាស់ដែលមានការបកប្រែជាយូរមកហើយបានមកពីណាទេ ដូច្នេះច្រកទ្វារវិនិច្ឆ័យតែអ្វីដែលការផ្លាស់ប្តូរបច្ចុប្បន្នប៉ះពាល់។ ជម្រើសជំនួស (បន្ទាត់គោលមួយគ្រាប់ចុច) នឹងត្រូវចំណាយលើឯកសារដែលបានបង្កើត ~ 600 KB, 3 × ដែលជាខ្សែបន្ទាត់មូលដ្ឋានធំបំផុតដែលមានស្រាប់ កូររាល់ i18n PR។

វិធីពីរយ៉ាងដើម្បីបំពេញវា៖

1. ធ្វើបច្ចុប្បន្នភាពការបកប្រែដែលរងផលប៉ះពាល់ ឬ
2. កំណត់ពួកវាទៅ `__MISSING__:<new english>` — ពេលវេលារត់ បន្ទាប់មកបម្រើភាសាអង់គ្លេសដែលបានកែ (`src/i18n/request.ts::deepMergeFallback`, #7258) និងជួរគន្លឹះសម្រាប់ការបកប្រែ។

ប្រសិនបើខ្សែអក្សរ** អត្ថន័យ** បានផ្លាស់ប្តូរ, ចូលចិត្ត** ការប្តូរឈ្មោះសោ** ៖ សោថ្មីមិនអាចទទួលការបកប្រែដែលជាប់គាំងបានទេ។ នោះគឺជាគំរូ #8463 ដែលបានប្រើ។

### បញ្ចូលគ្នា / លុបភាពស្ទួន (បែបមេកានិច ហានិភ័យទាបជាង)

បេក្ខភាពនីមួយៗត្រូវបានផ្ទៀងផ្ទាត់ជាមួយស្ថានភាព gate ជាក់ស្តែងនៅថ្ងៃទី 2026-06-17 (ទុកចិត្ត ប៉ុន្តែត្រូវផ្ទៀងផ្ទាត់);
ការបញ្ចូលគ្នាដែលមើលទៅ "ជាក់ស្តែង" មួយចំនួន បែរជាលាក់បំណុល ហើយ **មិនមែន** ជាការជំនួសដោយផ្ទាល់ដែលគ្មានបញ្ហាទេ។

- **`check:docs-sync` ដំណើរការពីរដង** — ដាច់ដោយឡែកនៅក្នុង job `lint` និងម្តងទៀតនៅក្នុង `check:docs-all` (`docs-sync-strict`) ព្រមទាំង husky pre-commit hook។ ✅ **រួចរាល់** — invocation ដាច់ដោយឡែកក្នុង `lint` ត្រូវបានដកចេញ។
- **ការស្កេន CVE** — ❌ **មិនមែនជាការបញ្ចូលគ្នាដែលគ្មានបញ្ហាទេ។** `audit:deps` បរាជ័យភ្លាមៗលើ CVE កម្រិត high/critical ណាមួយ; `check:vuln-ratchet` (osv) បរាជ័យតែលើ _ការធ្លាក់ចុះ_ ធៀបនឹង baseline ប៉ុណ្ណោះ (បច្ចុប្បន្នមាន 1 MODERATE)។ អត្ថន័យខុសគ្នា — ការលុប `audit:deps` នឹងធ្វើឱ្យបាត់បង់ gate ដាច់ខាតសម្រាប់កម្រិត high/critical។ រក្សាទុកទាំងពីរ។
- **ការរកឃើញវដ្ត** — ✅ **រួចរាល់** (#15159 G-01/G-02)។ អត្ថបទចាស់នៅទីនេះបានហៅ `check:cycles` ថាជា gate "ពណ៌បៃតង ដែលបានជ្រើសរើសយ៉ាងប្រុងប្រយ័ត្ន" និងបានលើកហេតុផលឱ្យរក្សាវាជា blocking ព្រោះ `check:circular-deps` (dpdm) បានរាយការណ៍វដ្តចំនួន 91។ ស្ថានភាពពណ៌បៃតងនោះគឺជា **ភាពវិជ្ជមានក្លែងក្លាយ**៖ `check:cycles` បានស្កេនថតរងចំនួន 5 (450 files), ផ្គូផ្គងតែ `import|export … from` បែប static ហើយបានបោះបង់រាល់ specifier `@/` និង `@omniroute/open-sse/` ដូច្នេះវាមិនអាចមើលឃើញវដ្ត dynamic-import + alias ដែលមានច្រើនជាងគេក្នុង repo បានទេ។ បានកែរួច៖ ឥឡូវ gate ដើរឆ្លងកាត់ `src` + `open-sse` (5023 files), ប្រមូល specifier ពី TypeScript AST (ដូច្នេះ `import("…")` ត្រូវបានរាប់ ខណៈ `typeof import("…")` នៅទីតាំង type មិនត្រូវបានរាប់) ហើយ resolve `paths` របស់ tsconfig។ វារកឃើញវដ្តចំនួន **14** មិនមែន 0 ទេ។ ដោយសារវដ្តដែលមានស្រាប់ចំនួន 14 មិនអាចត្រូវបានជួសជុលនៅក្នុង gate PR បាន `check:cycles` ឥឡូវនេះគឺជា **ratchet** (`--ratchet`, ពិដាន `metrics.cycles.value = 14` ក្នុង `quality-baseline.json`, `direction: down`) — វារារាំង _ការធ្លាក់ចុះ_ ណាមួយ ហើយចំនួននេះអាចតែថយចុះប៉ុណ្ណោះ។ CI ដំណើរការ `npm run check:cycles:ratchet`។ ការកាត់បន្ថយជាបន្តបន្ទាប់ទៅជាមួយ **A-01**។ `check:circular-deps` (dpdm) នៅតែជាការណែនាំក្នុងនាមជាមតិទីពីរដែលទូលំទូលាយជាង។
