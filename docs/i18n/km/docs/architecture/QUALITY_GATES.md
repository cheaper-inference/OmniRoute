## បញ្ជីសារពើភ័ណ្ឌ Gate និងទម្រង់ការប្រតិបត្តិ

### ការទទួលបេក្ខជន

លំហូរការងារ CI និង Quality Gates នីមួយៗបញ្ចេញលទ្ធផលវិនិច្ឆ័យដែលមានស្ថិរភាព៖ `Gate / CI` និង
`Gate / Quality`។ គោលការណ៍ទទួលដែលមានកំណែរបស់ពួកវារាយ job ខាងលើគ្រប់គ្នា ថាជាចាំបាច់ ឬជាការណែនាំ។ job ចាំបាច់ដែលអាចអនុវត្តបាន ត្រូវតែជោគជ័យ៖ លទ្ធផលដែលបាត់,
ត្រូវបានបោះបង់, រំលង, កំពុងរង់ចាំ និងមិនស្គាល់ មិនអាចបង្កើត PASS បានទេ។ ការចាត់ថ្នាក់ docs-only ឬ catalog-only ដែលមានសុពលភាព អាចធ្វើឱ្យ code lane មិនអាចអនុវត្តបាន;
PR ជាសេចក្តីព្រាង មិនមែនជាបេក្ខជនដែលបានទទួលយកទេ។ ស្លាក `hotfix` មិនលើកលែងតម្រូវការភស្តុតាងទេ។

លំហូរការងារទាំងពីរគ្របដណ្តប់ PRs ដែលបញ្ចូលទៅ main/release branches, pushes ទៅ `main`, manual dispatch
និងព្រឹត្តិការណ៍ merge-group។ Push, dispatch និង merge-group ដំណើរការជម្រើសពេញលេញ។ Pushes ទៅ
`release/**` មិនចាប់ផ្តើមពួកវាទេ (2026-10-18)៖ រាល់ការផ្លាស់ប្តូរបានដំណើរការម៉ាទ្រីសរួចហើយនៅលើ PR របស់វា
ហើយការរួមបញ្ចូលដែលបានបញ្ចប់ គឺជាការងាររបស់ Release-Green (`docs/ops/RUNNER_BOX.md` → Hosted lane)។
Forks និង merge groups ប្រើ hosted runners សម្រាប់ jobs ដែលជាធម្មតាជ្រើសរើស
self-hosted runners; ត្រូវតែផ្ទៀងផ្ទាត់ថាមានសមត្ថភាព hosted គ្រប់គ្រាន់ មុនពេលដាក់ឱ្យប្រើ។

បង្កាន់ដៃ JSON នីមួយៗកំណត់អត្តសញ្ញាណ SHA ដែលបាន checkout, workflow run និង attempt។
CLI បដិសេធភាពមិនត្រូវគ្នារវាង checkout/event SHA។ ការធ្វើតេស្ត workflow ភ្ជាប់សមាជិកភាពគោលការណ៍
ទៅបញ្ជី `needs` របស់ verdict job ដើម្បីឱ្យ lane ថ្មី ឬ lane ដែលត្រូវបានដកចេញ មិនអាចបាត់ដោយស្ងាត់បាន។
បង្កាន់ដៃទាំងនេះគ្របដណ្តប់តែ workflow របស់ខ្លួនប៉ុណ្ណោះ មិនមែនការបោះពុម្ពផ្សាយ ការដាក់ឱ្យប្រើប្រាស់
ឬផ្នែកខាងក្នុងនៃ advisory scanner ដែលមានស្រាប់ទេ។ ការធ្វើឱ្យឈ្មោះ check ទាំងពីរសកម្មក្នុង branch rules គឺជាការផ្លាស់ប្តូរផ្នែករដ្ឋបាលដាច់ដោយឡែកមួយ;
ការបន្ថែម jobs ទាំងនេះមិនការពារ branch ដោយខ្លួនឯងទេ។

### បញ្ជីសារពើភ័ណ្ឌការស្កេនឋិតិវន្ត

បញ្ជីសារពើភ័ណ្ឌ npm-alias និងសមាជិកភាព static-scan ដែលមានកំណែ ស្ថិតនៅក្នុង
`config/quality/gate-manifest.json`។ ដំណើរការ `npm run check:gate-manifest` ដើម្បីផ្ទៀងផ្ទាត់
ឈ្មោះស្គ្រីប និងពាក្យបញ្ជាពិតប្រាកដប្រឆាំងនឹង `package.json`; ការបន្ថែម ការដកចេញ និងការប្រែប្រួលពាក្យបញ្ជា នឹងធ្វើឱ្យ local hook និង jobs ចាត់ថ្នាក់ការផ្លាស់ប្តូរនៅក្នុង CI បរាជ័យទាំងពីរ។
alias មិនមែនជា workflow job, matrix instance ឬ test case ទេ៖ ចំនួនទាំងនេះមិនត្រូវបង្ហាញថាអាចជំនួសគ្នាបានទេ។

ប្រើ `npm run quality:scan -- --list` ឬ `npm run quality:scan:fast -- --list`
ដើម្បីពិនិត្យ aliases ដែលបានជ្រើស ដោយមិនប្រតិបត្តិពួកវា។ runner ហៅ npm entrypoint ដូច្នេះ runtime របស់វា
(រួមទាំង Bun នៅពេលបានកំណត់រចនាសម្ព័ន្ធ) ត្រូវបានរក្សាទុក។ manifest កត់ត្រា aliases ដែលនៅក្រៅ profiles ទាំងនោះថាត្រូវហៅដោយឡែក ហើយ
maintenance commands ត្រូវបានហាមឃាត់នៅក្នុង read-only scan profiles។

Profiles ទាំងនេះគ្របដណ្តប់តែ static scan ប៉ុណ្ណោះ។ ពួកវាមិនបញ្ជាក់អំពី product tests,
coverage, packaging, external checks ឬការទទួលយកសម្រាប់ការចេញផ្សាយពេញលេញរបស់បេក្ខជនទេ។
ការទទួល workflow ប្រើ `config/quality/admission-policy.json` ដែលភ្ជាប់ និង `scripts/quality/admission-verdict.mjs`។
Release-observer profiles នៅដាច់ដោយឡែក; ពិនិត្យ checks និងបង្កាន់ដៃដែលអាចអនុវត្តបានរបស់ពួកវាដោយឯករាជ្យ។
បញ្ជីសារពើភ័ណ្ឌជាអត្ថបទខាងក្រោម គឺជាឯកសារយោង មិនមែនជាភស្តុតាងថា gate មួយពិតជាបានដំណើរការទេ។

ស្គ្រីបស្ថិតនៅក្រោម `scripts/check/` (policy gates) និង `scripts/quality/` (ratchet engine)។
ប្រភពការពិតសម្រាប់ CI គឺ `.github/workflows/ci.yml`។

### ផ្លូវលឿនសម្រាប់ Release PR (`quality.yml`)

`.github/workflows/quality.yml` បំពេញបន្ថែម CI លើ main/release PRs, pushes ទៅ `main`,
dispatch និង merge groups។ PRs ប្រើ fast checks ដែលបានច្រោះតាម path។ duplicate build ដែលត្រូវបានបិទជាអចិន្ត្រៃយ៍ ត្រូវបានដកចេញ; build/package/boot checks ពិតប្រាកដនៅតែមានក្នុង CI។

| Job                                              | Scope                                                                                                                                                                                                    | Blocking          |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| `Docs Gates (fast-path)`                         | PRs ឯកសារ/កូដ; API docs refs និង docs-all                                                                                                                                                                | បាទ               |
| `Fast Quality Gates`                             | PRs កូដ; static checks, typecheck, dashboard typecheck, impacted unit tests                                                                                                                              | បាទ               |
| `Forgotten sibling tests`                        | PRs កូដ; ម៉ូឌុលដែលបានផ្លាស់ប្តូរ តាមដានទៅកាន់ static consumers និង candidate sibling tests; ផ្លូវ barrel និង dynamic-import ត្រូវបានរាយការណ៍ជារោគវិនិច្ឆ័យណែនាំ ជាមួយករណីលើកលែងក្នុង allowlist ដែលបានយោង | **ជាការណែនាំ**    |
| `Vitest (fast-path)`                             | PRs កូដ; fast vitest suite                                                                                                                                                                               | បាទ               |

#### `check-ui-value-drift` — ច្រកត្រួតពិនិត្យការបកប្រែចាស់ហួសសម័យ

ចាប់បាននូវ regression i18n មួយដែលច្រកផ្សេងទៀតមិនអាចមើលឃើញតាមរចនាសម្ព័ន្ធ៖ តម្លៃអង់គ្លេសមួយត្រូវបានសរសេរឡើងវិញ ហើយការបកប្រែដែលបានមកពីអង់គ្លេស _មុន_ នៅសល់ដដែល ដូច្នេះអ្នកប្រើប្រាស់ដែលមិនមែនជាភាសាអង់គ្លេសបន្តអានអត្ថបទដែលមានសម្តីជឿជាក់ ប៉ុន្តែឥឡូវខុស។

រឿងនេះបានកើតឡើងពិតប្រាកដ។ `oauthModal.googleOAuthWarning` ត្រូវបានសរសេរឡើងវិញនៅពេលឧបករណ៍ជំនួយចូល Antigravity បានមកដល់ (#5203); **ក្នុងចំណោម 43 locale មាន 39** ដែលរក្សាអត្ថបទប្រាប់អ្នកប្រតិបត្តិឱ្យ "copy the full URL and paste it below" — ជាដំណើរការដែលមិនអាចបញ្ចប់បានសម្រាប់ provider នោះ។ វាមិនត្រូវបានគេកត់សម្គាល់រហូតដល់ #8463 ដោយសារ៖

- `sync-ui-keys` គ្រាន់តែបំពេញបន្ថែម key ដែល **អវត្តមាន** ប៉ុណ្ណោះ មិនដែលបំពេញរបស់ដែល **ហួសសម័យ** ឡើយ;
- `check-ui-keys-coverage` រាប់តែ _វត្តមាន_ នៃ key ដូច្នេះការបកប្រែហួសសម័យត្រូវបានរាប់ថាគ្របដណ្តប់;
- `check-translation-drift` តាមដានកញ្ចក់ឯកសារ `docs/i18n/<locale>/**.md` — វាមិនដែលអាន `src/i18n/messages/*.json` ទេ។ កំពុងរារាំងក្នុង job `docs-sync-strict` ចាប់តាំងពីការធ្វើសមកាលកម្មឡើងវិញ ខែកញ្ញា 2026៖ កែឯកសារស្នូល → `npm run i18n:run -- --files=<doc>` (កម្រិតផ្នែក ថោក)។

**ដឹងពី diff មិនមែនពឹងលើ baseline។** វាប្រៀបធៀប `en.json` នៅ merge base ជាមួយ working tree; សម្រាប់រាល់ key ដែលតម្លៃអង់គ្លេសបានផ្លាស់ប្តូរ locale ណាដែលនៅរក្សាការបកប្រែមិនទាន់ប៉ះពាល់ គឺហួសសម័យ។ នេះចេតនា **បង្កកបំណុលដែលមានពីមុន** — diff មិនអាចបង្ហាញថាការបកប្រែដែលមានយូរនោះមកពីអង់គ្លេសចាស់ណាទេ ដូច្នេះច្រកនេះវិនិច្ឆ័យតែអ្វីដែលការផ្លាស់ប្តូរបច្ចុប្បន្នប៉ះពាល់ប៉ុណ្ណោះ។ ជម្រើសផ្សេង (baseline hash ក្នុងមួយ key) នឹងត្រូវចំណាយឯកសារបង្កើតប្រហែល ~600 KB ដែលធំជាង baseline ដែលមានស្រាប់ធំបំផុត 3 ដង ហើយរងការផ្លាស់ប្តូររាល់ PR i18n។

មានវិធីពីរដើម្បីបំពេញវា៖

1. ធ្វើបច្ចុប្បន្នភាពការបកប្រែដែលពាក់ព័ន្ធ ឬ
2. កំណត់ពួកវាទៅ `__MISSING__:<new english>` — ពេលនោះ runtime នឹងផ្តល់អង់គ្លេសដែលបានកែតម្រូវ (`src/i18n/request.ts::deepMergeFallback`, #7258) ហើយ key នោះចូលជួររង់ចាំការបកប្រែ។

ប្រសិនបើ **អត្ថន័យ** នៃខ្សែអក្សរបានផ្លាស់ប្តូរ សូមពេញចិត្ត **ប្តូរឈ្មោះ key**៖ key ថ្មីមិនអាចទទួលមរតកការបកប្រែហួសសម័យបានទេ។ នេះជាគំរូដែល #8463 បានប្រើ។

```bash
npm run i18n:check-value-drift          # strict (what CI runs)
npm run i18n:check-value-drift:warn     # report only
BASE_REF=origin/release/vX.Y.Z npm run i18n:check-value-drift
```

ចេញដោយលេខ 0 ជាមួយ `SKIP reason=base-unresolved` នៅពេលមិនអាចអាន base catalog បាន (shallow clone ដោយគ្មាន base ref) ដែលឆ្លុះបញ្ចាំងពី `check-openapi-breaking`។

## គោលការណ៍បញ្ជីអនុញ្ញាត

រាល់ច្រកត្រួតពិនិត្យដែលមិនអាចបរាជ័យដោយសារការបំពានដែលមានស្រាប់ ប្រើបញ្ជីអនុញ្ញាតដែលបានកំណត់ថេរ
(ឧ., `KNOWN_STALE_DOC_REFS`, `KNOWN_MISSING`, `KNOWN_RAW_SQL`)។ គោលការណ៍គឺ៖

**កែសម្រួលមូលហេតុដើម; ប្រើបញ្ជីអនុញ្ញាតតែក្នុងករណីដែលការបំពានមានស្រាប់ និង
មិនអាចកែសម្រួលបាននៅក្នុង PR ដូចគ្នា។**

នៅពេលបន្ថែមធាតុទៅបញ្ជីអនុញ្ញាត៖

1. រួមបញ្ចូលមតិយោបល់ដែលបញ្ជាក់ពីហេតុផល។
2. យោងទៅបញ្ហាតាមដាន (ឧ., `// #3498 — មុខងារដំណាក់កាលទី 2 មិនទាន់ត្រូវបានអនុវត្ត`)។
3. លុបធាតុនោះនៅក្នុង PR ដូចគ្នាដែលកែសម្រួលការបំពាន — ធាតុចាស់ដែលលែង
   ទប់ស្កាត់ការបំពានសកម្ម គឺជាកំហុសដោយខ្លួនឯង (ការអនុវត្តចំពោះធាតុចាស់ 6A.3 នឹង
   ធ្វើឱ្យច្រកត្រួតពិនិត្យបរាជ័យលើធាតុបញ្ជីអនុញ្ញាតដែលគ្មានការយោង នៅពេលវាត្រូវបានអនុវត្ត)។

**កុំ** បន្ថែមធាតុបញ្ជីអនុញ្ញាតដើម្បីឱ្យការធ្វើតេស្តឆ្លងកាត់លឿនជាងមុន។ ច្រកត្រួតពិនិត្យដែលជោគជ័យ ខណៈដែល

### នៅពេលច្រកត្រួតពិនិត្យបរាជ័យលើ PR របស់អ្នក

   នៅពេលកូដត្រឹមត្រូវ។

   ការផ្លាស់ប្តូររបស់អ្នកបានធ្វើឱ្យម៉ែត្រវាស់កាន់តែអាក្រក់។ កែសម្រួលបញ្ហាមូលដ្ឋាន ឬ (ក្នុងករណីកម្រ) ដំណើរការ
