## បញ្ជីសារពើភណ្ឌ Gate និងប្រូហ្វាល់ប្រតិបត្តិ

### ការទទួលយកបេក្ខភាព

Workflow របស់ CI និង Quality Gates នីមួយៗបញ្ចេញលទ្ធផលវិនិច្ឆ័យដែលមានស្ថិរភាព៖ `Gate / CI` និង
`Gate / Quality`។ គោលការណ៍ទទួលយកដែលមានកំណែរបស់ពួកវារាយបញ្ជី job upstream ទាំងអស់
ថាជា required ឬ advisory។ job required ដែលអាចអនុវត្តបានត្រូវតែជោគជ័យ៖ លទ្ធផលដែលបាត់,
ត្រូវបានលុបចោល, ត្រូវបានរំលង, កំពុងរង់ចាំ និងមិនស្គាល់ មិនអាចបញ្ជាក់ PASS បានទេ។ ចំណាត់ថ្នាក់
docs-only ឬ catalog-only ដែលមានសុពលភាពអាចធ្វើឱ្យ lane របស់កូដមិនអាចអនុវត្តបាន;
PR ព្រាងមិនមែនជាបេក្ខភាពដែលត្រូវបានទទួលយកទេ។ ស្លាក `hotfix` មិនលើកលែងតម្រូវការភស្តុតាងឡើយ។

Workflow ទាំងពីរគ្របដណ្តប់លើ PR ទៅកាន់ branch main/release, push ទៅ `main`, manual dispatch
និងព្រឹត្តិការណ៍ merge-group។ Push, dispatch និង merge-group ដំណើរការជម្រើសពេញលេញ។ Push ទៅ
`release/**` មិនចាប់ផ្តើមពួកវាទេ (2026-10-18)៖ ការផ្លាស់ប្តូរនីមួយៗបានដំណើរការ matrix រួចហើយនៅលើ PR
របស់វា ហើយបន្សំដែលបាន merge គឺជា job របស់ Release-Green (`docs/ops/RUNNER_BOX.md` → lane Hosted)។ Fork
និង merge group ប្រើ hosted runner សម្រាប់ job ដែលជាធម្មតាជ្រើស self-hosted
runner; ត្រូវតែផ្ទៀងផ្ទាត់ថាមានសមត្ថភាព hosted គ្រប់គ្រាន់ មុនពេលដាក់ឱ្យប្រើប្រាស់។

PR ធម្មតាដំណើរការជម្រើសរហ័ស។ lane `full-code` និង `full-code-e2e` នៃ
គោលការណ៍ទទួលយក (E2E, integration, package artifact, Electron smoke, Bun SQLite, ecosystem
និង protocol clients) ដំណើរការតែលើព្រាង queue របស់ Mergify ឬលើការដំណើរការពេញលេញប៉ុណ្ណោះ៖
`gh workflow run ci.yml --ref <branch>`។

បង្កាន់ដៃ JSON នីមួយៗកំណត់អត្តសញ្ញាណ SHA ដែលបាន check out, workflow run និង attempt។
CLI បដិសេធភាពមិនត្រូវគ្នារវាង checkout/event SHA។ ការធ្វើតេស្ត Workflow ចងសមាជិកភាពគោលការណ៍
ទៅនឹងបញ្ជី `needs` របស់ job វិនិច្ឆ័យ ដើម្បីកុំឱ្យ lane ថ្មី ឬដែលបានដកចេញអាចបាត់ទៅដោយស្ងៀមស្ងាត់។
បង្កាន់ដៃគ្របដណ្តប់លើ workflow របស់វាផ្ទាល់ មិនមែនការបោះពុម្ពផ្សាយ, ការដាក់ឱ្យប្រើប្រាស់ ឬផ្នែកខាងក្នុង
នៃ advisory scanner ដែលមានស្រាប់ទេ។ ការធ្វើឱ្យ check name ទាំងពីរសកម្មនៅក្នុងច្បាប់ branch គឺជា
ការផ្លាស់ប្តូរផ្នែករដ្ឋបាលដាច់ដោយឡែកមួយ; ការបន្ថែម job ទាំងនេះមិនការពារ branch ដោយខ្លួនវាឡើយ។

### Merge queue

ស្លាក `queue` បញ្ជូន PR ទៅ Mergify queue (`.mergify.yml`)។ Mergify បើក PR ព្រាងមួយនៅលើ
branch `mergify/merge-queue/`, CI ដំណើរការជម្រើសពេញលេញនៅទីនោះ ហើយ PR ដើមត្រូវបាន merge
នៅពេល `Gate / CI`, `Gate / Quality` និង `Merge integrity (changelog + generated skills)` ជោគជ័យ។

Mergify សរសេរសេចក្តីសង្ខេប queue របស់វាទៅក្នុងសេចក្តីពិពណ៌នារបស់ព្រាង ហើយ app ផ្សេងទៀតក៏អាចកែវាបានដែរ។
ព្រឹត្តិការណ៍ `pull_request` `edited` លើព្រាងបែបនេះប្រើ concurrency group ផ្ទាល់ខ្លួន
(`-queue-edit-<run_id>`) ដូច្នេះវាមិនអាចលុបចោលការដំណើរការពិតប្រាកដរបស់ព្រាងបានទេ ហើយវារំលង gate និង
matrix។ មានតែ `Merge integrity` ប៉ុណ្ណោះដែលនៅតែដំណើរការ។ gate job ដែលត្រូវបានរំលងមាន check name ខុសគ្នា
ពីព្រោះ Mergify ចាត់ទុក `Gate / CI` ដែលត្រូវបានរំលងថាជា check បរាជ័យ ហើយដក PR ចេញពី queue។

បន្ទាប់ពីដកចេញពី queue ការ push មិនតែងតែដាក់ PR ចូល queue ឡើងវិញទេ។ សូម comment `@mergifyio queue` លើវា។

### បញ្ជីសារពើភណ្ឌការស្កេនឋិតិវន្ត

បញ្ជីសារពើភណ្ឌ npm-alias ដែលមានកំណែ និងសមាជិកភាព static-scan ស្ថិតនៅក្នុង
`config/quality/gate-manifest.json`។ ដំណើរការ `npm run check:gate-manifest` ដើម្បីផ្ទៀងផ្ទាត់
ឈ្មោះ script និង command ជាក់លាក់ទល់នឹង `package.json`; ការបន្ថែម, ការដកចេញ និង
ការប្រែប្រួល command ធ្វើឱ្យទាំង local hook និង job ចាត់ថ្នាក់ការផ្លាស់ប្តូរនៅក្នុង CI បរាជ័យ។
alias មិនមែនជា workflow job, matrix instance ឬ test case ទេ៖ ចំនួនទាំងនេះមិនត្រូវ
បង្ហាញថាអាចប្រើជំនួសគ្នាបានឡើយ។

ប្រើ `npm run quality:scan -- --list` ឬ `npm run quality:scan:fast -- --list`
ដើម្បីពិនិត្យមើល alias ដែលបានជ្រើស ដោយមិនប្រតិបត្តិពួកវា។ runner ហៅប្រើ
npm entrypoint ដូច្នេះ runtime របស់វា (រួមទាំង Bun នៅកន្លែងដែលបានកំណត់រចនាសម្ព័ន្ធ) ត្រូវបានរក្សាទុក។
manifest កត់ត្រា alias នៅក្រៅប្រូហ្វាល់ទាំងនោះថាត្រូវបានហៅប្រើដោយឡែក ហើយ
maintenance command ត្រូវបានហាមឃាត់នៅក្នុងប្រូហ្វាល់ស្កេន read-only។

ប្រូហ្វាល់ទាំងនេះគ្របដណ្តប់តែការស្កេនឋិតិវន្តប៉ុណ្ណោះ។ ពួកវាមិនបញ្ជាក់ product test,
coverage, packaging, external check ឬការទទួលយក release ពេញលេញរបស់បេក្ខភាពទេ។

#### របាយការណ៍ forgotten sibling tests

`npm run check:forgotten-sibling-tests` ដំណើរការជាជំហានផ្តល់អនុសាសន៍មួយនៃ `Fast Quality Gates` ហើយប្រើឡើងវិញនូវ
កម្មវិធីដោះស្រាយ import ដែលនៅពីក្រោយផែនទីផលប៉ះពាល់នៃការធ្វើតេស្ត។
សម្រាប់ម៉ូឌុល production ដែលបានផ្លាស់ប្តូរនីមួយៗ វារាយការណ៍ខ្សែសង្វាក់ដែលមានលទ្ធផលដូចគ្នាជានិច្ចនៃ
`changed module/symbol -> static consumer -> candidate sibling test` នៅពេលដែលការធ្វើតេស្តដែលជាបេក្ខភាព
មិនមាននៅក្នុង diff របស់ pull request។ សេចក្តីសង្ខេប Markdown និងលទ្ធផល JSON ត្រូវបានរក្សាទុកជា
artifact នៃ workflow `forgotten-sibling-tests` សម្រាប់ការក្រិតតម្រូវ មុនពេលដាក់ឱ្យប្រើប្រាស់ក្នុងទម្រង់រារាំងណាមួយ។

ការនាំចេញឡើងវិញតាម Barrel និង dynamic imports គ្រាន់តែជាព័ត៌មានវិភាគសម្រាប់ការដោះស្រាយប៉ុណ្ណោះ; ពួកវាមិនដែលបង្កើត
ការរកឃើញដែលអាចរារាំងបានទេ។ ករណីលើកលែងដែលបានពិនិត្យរួចមាននៅក្នុង
`config/quality/forgotten-sibling-allowlist.json`។ ធាតុនីមួយៗត្រូវតែបញ្ជាក់ឈ្មោះ consumer និងការធ្វើតេស្ត
ដែលជាបេក្ខភាព ផ្តល់ហេតុផលជាក់លាក់ និងភ្ជាប់ទៅ GitHub issue ឬ pull request។ ធាតុដែលមានទម្រង់មិនត្រឹមត្រូវ
នឹងបរាជ័យដោយសុវត្ថិភាព។ ករណីលើកលែងមិនអាចលាក់បាំងការធ្វើតេស្តដែលជាបេក្ខភាព និងត្រូវបានលុប ឬ diff ដែលបន្ថែម `.skip`/`.todo` បានទេ;
ការបន្ថយភាពតឹងរ៉ឹងនៃ assertion និងការលាក់បាំងផ្សេងទៀត នៅតែស្ថិតក្រោមការគ្រប់គ្រងរបស់ gate ដែលរារាំងដោយឯករាជ្យ

បញ្ហានេះពិតជាបានចេញទៅកាន់អ្នកប្រើប្រាស់។ `oauthModal.googleOAuthWarning` ត្រូវបានសរសេរឡើងវិញ នៅពេលឧបករណ៍ជំនួយសម្រាប់ login របស់ Antigravity ត្រូវបានបន្ថែម (#5203); **39 ក្នុងចំណោម 43 locale** នៅតែរក្សាអត្ថបទដែលប្រាប់ operator ឱ្យ «ចម្លង URL ទាំងមូល ហើយបិទភ្ជាប់វានៅខាងក្រោម» — ជា flow ដែលមិនអាចបញ្ចប់បានសម្រាប់ provider នោះ។ វាមិនត្រូវបានគេកត់សម្គាល់រហូតដល់ #8463 ពីព្រោះ៖

- `sync-ui-keys` គ្រាន់តែបំពេញបន្ថែម key ដែល **អវត្តមាន** ប៉ុណ្ណោះ មិនដែលបំពេញ key ដែល **ហួសសម័យ** ឡើយ;
- `check-ui-keys-coverage` រាប់ _វត្តមាន_ របស់ key ដូច្នេះការបកប្រែដែលហួសសម័យត្រូវបានចាត់ទុកថាគ្របដណ្តប់រួច;
- `check-translation-drift` តាមដាន mirror ឯកសារ `docs/i18n/<locale>/**.md` —
  វាមិនដែលអាន `src/i18n/messages/*.json` ទេ។ វារារាំងក្នុង job `docs-sync-strict` ចាប់តាំងពីការ re-sync ខែ 2026-09៖ កែសម្រួលឯកសារស្នូលមួយ → `npm run i18n:run -- --files=<doc>` (កម្រិត section, ចំណាយតិច)។

**យល់ដឹងពី diff មិនពឹងផ្អែកលើ baseline។** វាប្រៀបធៀប `en.json` នៅ merge base ជាមួយ working tree; សម្រាប់ key នីមួយៗដែលតម្លៃជាភាសាអង់គ្លេសបានផ្លាស់ប្តូរ locale ណាមួយដែលនៅតែរក្សាការបកប្រែដែលមិនបានកែប្រែ នឹងត្រូវចាត់ទុកថាហួសសម័យ។ វាមានចេតនា **បង្កកបំណុលដែលមានស្រាប់** — diff មិនអាចបង្ហាញថាការបកប្រែដែលមានយូរមកហើយកើតចេញពីអត្ថបទភាសាអង់គ្លេសចាស់ណាមួយទេ ដូច្នេះ gate វាយតម្លៃតែអ្វីដែលការផ្លាស់ប្តូរបច្ចុប្បន្នប៉ះពាល់ប៉ុណ្ណោះ។ ជម្រើសផ្សេងទៀត (baseline hash សម្រាប់ key នីមួយៗ) នឹងត្រូវការឯកសារ generated ប្រហែល 600 KB ដែលធំជាង baseline ដែលមានស្រាប់ធំបំផុត 3 ដង ហើយនឹងផ្លាស់ប្តូរជាបន្តបន្ទាប់លើគ្រប់ i18n PR។

មានពីរវិធីដើម្បីបំពេញលក្ខខណ្ឌរបស់វា៖

1. ធ្វើបច្ចុប្បន្នភាពការបកប្រែដែលរងផលប៉ះពាល់ ឬ
2. កំណត់ពួកវាទៅជា `__MISSING__:<new english>` — បន្ទាប់មក runtime នឹងផ្តល់អត្ថបទភាសាអង់គ្លេសដែលបានកែតម្រូវ
   (`src/i18n/request.ts::deepMergeFallback`, #7258) ហើយ key នោះនឹងចូលជួររង់ចាំការបកប្រែ។

ប្រសិនបើ **អត្ថន័យ** របស់ string បានផ្លាស់ប្តូរ គួរតែ **ប្តូរឈ្មោះ key**៖ key ថ្មីមិនអាចទទួលបន្តការបកប្រែដែលហួសសម័យបានទេ។ នេះជាលំនាំដែល #8463 បានប្រើ។

### បញ្ចូលគ្នា / លុបភាពស្ទួន (បែបមេកានិច ហានិភ័យទាបជាង)

បេក្ខភាពនីមួយៗត្រូវបានផ្ទៀងផ្ទាត់ជាមួយស្ថានភាព gate ជាក់ស្តែងនៅថ្ងៃទី 2026-06-17 (ទុកចិត្ត ប៉ុន្តែត្រូវផ្ទៀងផ្ទាត់);
ការបញ្ចូលគ្នាដែលមើលទៅ "ជាក់ស្តែង" មួយចំនួន បែរជាលាក់បំណុល ហើយ **មិនមែន** ជាការជំនួសដោយផ្ទាល់ដែលគ្មានបញ្ហាទេ។

- **`check:docs-sync` ដំណើរការពីរដង** — ដាច់ដោយឡែកនៅក្នុង job `lint` និងម្តងទៀតនៅក្នុង `check:docs-all` (`docs-sync-strict`) ព្រមទាំង husky pre-commit hook។ ✅ **រួចរាល់** — invocation ដាច់ដោយឡែកក្នុង `lint` ត្រូវបានដកចេញ។
- **ការស្កេន CVE** — ❌ **មិនមែនជាការបញ្ចូលគ្នាដែលគ្មានបញ្ហាទេ។** `audit:deps` បរាជ័យភ្លាមៗលើ CVE កម្រិត high/critical ណាមួយ; `check:vuln-ratchet` (osv) បរាជ័យតែលើ _ការធ្លាក់ចុះ_ ធៀបនឹង baseline ប៉ុណ្ណោះ (បច្ចុប្បន្នមាន 1 MODERATE)។ អត្ថន័យខុសគ្នា — ការលុប `audit:deps` នឹងធ្វើឱ្យបាត់បង់ gate ដាច់ខាតសម្រាប់កម្រិត high/critical។ រក្សាទុកទាំងពីរ។
- **ការរកឃើញវដ្ត** — ✅ **រួចរាល់** (#15159 G-01/G-02)។ អត្ថបទចាស់នៅទីនេះបានហៅ `check:cycles` ថាជា gate "ពណ៌បៃតង ដែលបានជ្រើសរើសយ៉ាងប្រុងប្រយ័ត្ន" និងបានលើកហេតុផលឱ្យរក្សាវាជា blocking ព្រោះ `check:circular-deps` (dpdm) បានរាយការណ៍វដ្តចំនួន 91។ ស្ថានភាពពណ៌បៃតងនោះគឺជា **ភាពវិជ្ជមានក្លែងក្លាយ**៖ `check:cycles` បានស្កេនថតរងចំនួន 5 (450 files), ផ្គូផ្គងតែ `import|export … from` បែប static ហើយបានបោះបង់រាល់ specifier `@/` និង `@omniroute/open-sse/` ដូច្នេះវាមិនអាចមើលឃើញវដ្ត dynamic-import + alias ដែលមានច្រើនជាងគេក្នុង repo បានទេ។ បានកែរួច៖ ឥឡូវ gate ដើរឆ្លងកាត់ `src` + `open-sse` (5023 files), ប្រមូល specifier ពី TypeScript AST (ដូច្នេះ `import("…")` ត្រូវបានរាប់ ខណៈ `typeof import("…")` នៅទីតាំង type មិនត្រូវបានរាប់) ហើយ resolve `paths` របស់ tsconfig។ វារកឃើញវដ្តចំនួន **14** មិនមែន 0 ទេ។ ដោយសារវដ្តដែលមានស្រាប់ចំនួន 14 មិនអាចត្រូវបានជួសជុលនៅក្នុង gate PR បាន `check:cycles` ឥឡូវនេះគឺជា **ratchet** (`--ratchet`, ពិដាន `metrics.cycles.value = 14` ក្នុង `quality-baseline.json`, `direction: down`) — វារារាំង _ការធ្លាក់ចុះ_ ណាមួយ ហើយចំនួននេះអាចតែថយចុះប៉ុណ្ណោះ។ CI ដំណើរការ `npm run check:cycles:ratchet`។ ការកាត់បន្ថយជាបន្តបន្ទាប់ទៅជាមួយ **A-01**។ `check:circular-deps` (dpdm) នៅតែជាការណែនាំក្នុងនាមជាមតិទីពីរដែលទូលំទូលាយជាង។
