## 1. បច្ចេកវិទ្យាដែលប្រើ

| ផ្នែក             | ជម្រើស                                                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Web framework     | **Next.js 16** (App Router, លទ្ធផល standalone, មិនមាន global middleware)                                                             |
| ភាសា              | **TypeScript 6.0+** — target `ES2022`, `module: esnext`, `moduleResolution: bundler`, `strict: false`                                |
| Runtime           | **Node.js** `>=22.22.2 <23` ឬ `>=24.0.0 <27` (អនុវត្តជាកំហិតតាមរយៈ `engines` + `SUPPORTED_NODE_RANGE`)                               |
| មូលដ្ឋានទិន្នន័យ  | **SQLite** តាមរយៈ `better-sqlite3` (singleton, ការកត់ត្រាបែប WAL)                                                                    |
| កម្មវិធី Desktop  | **Electron 41** + `electron-builder` 26.10 (workspace ដាច់ដោយឡែកនៅ `electron/`)                                                      |
| ការធ្វើតេស្ត      | **Node native test runner** (unit/integration), **Vitest** (MCP, autoCombo, cache), **Playwright** (e2e + protocols-e2e)             |
| ការ Build         | Next.js standalone តាមរយៈ `scripts/build/build-next-isolated.mjs`                                                                    |
| Lint/format       | ESLint flat config + Prettier (`lint-staged` តាមរយៈ Husky pre-commit)                                                                |
| ប្រព័ន្ធ Module   | ESM នៅគ្រប់ទីកន្លែង (`"type": "module"`)                                                                                             |
| UI របស់ Dashboard | **Tailwind CSS 4** + **Keak CI UI Kit** ដែលបានដាក់បញ្ចូលក្នុងគម្រោង (`packages/ui-kit`), រូបតំណាង Lucide — សូមមើល `DESIGN_SYSTEM.md` |
| Workspaces        | npm workspaces — `open-sse`, `packages/browser-pool`, `packages/ui-kit`                                                              |

ឈ្មោះកាត់ផ្លូវ (Path aliases) (`tsconfig.json`)៖

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`
- `@omniroute/ui-kit` → `packages/ui-kit/src`, `@omniroute/ui-kit/*` → `packages/ui-kit/src/*`

ច្រក HTTP លំនាំដើម៖ **`20128`** (API និង dashboard ប្រើ process ដូចគ្នា)។ ថតទិន្នន័យ
គឺជា env var `DATA_DIR` ដែលមានតម្លៃលំនាំដើមជា `~/.omniroute/`។

### 3.1 `src/app/` — រ៉ោតទ័រកម្មវិធី

App Router បង្ហាញទាំងផ្ទាំងគ្រប់គ្រង UI និង public/management HTTP API។ មាន** មិនមានឧបករណ៍កណ្តាលសកលទេ។** — ការស្ទាក់ចាប់ត្រូវបានធ្វើក្នុងមួយផ្លូវ។

ផ្នែកកម្រិតកំពូលនៅក្រោម `src/app/`:

| ផ្លូវ                                                                         | គោលបំណង                                           |
| ----------------------------------------------------------------------------- | ------------------------------------------------- |
| `api/`                                                                        | ផ្លូវ HTTP API ទាំងអស់ (សូមមើលការវិភាគខាងក្រោម)   |
| `a2a/`                                                                        | A2A JSON-RPC 2.0 ចំណុចបញ្ចប់ (`POST /a2a`)        |
| `.well-known/agent.json/`                                                     | ឯកសារស្វែងរកកាតភ្នាក់ងារ A2A                      |

| `400/`, `401/`, `403/`, `408/`, `429/`, `500/`, `502/`, `503/`                | ទំព័រកំហុសថេរ                                     |

```
Client request
  → /v1/chat/completions (route.ts)

     Rate limit (rateLimitManager, accountSemaphore)
     Combo routing (if model resolves to a combo)
       resolveComboTargets (open-sse/services/combo.ts) → per-target dispatch
     translateRequest()  (open-sse/translator/request/*)
     getExecutor(providerId).execute()  (open-sse/executors/*)
       fetch upstream → retry/backoff via accountFallback
     translateResponse() (open-sse/translator/response/*)
     SSE stream OR JSON response
     If Responses API: TransformStream via open-sse/transformer/responsesTransformer.ts
  → Compliance audit (src/lib/compliance/)
  → Response to client
```

## 10. របៀបចូលរួមចំណែក

### បន្ថែមអ្នកផ្តល់សេវាថ្មី

1. ចុះឈ្មោះក្នុង `src/shared/constants/providers.ts` (ត្រូវបានផ្ទៀងផ្ទាត់ដោយ Zod នៅពេលផ្ទុក)។
2. បន្ថែម executor មួយក្នុង `open-sse/executors/` ប្រសិនបើត្រូវការតក្កវិជ្ជាផ្ទាល់ខ្លួន
   (ពង្រីក `BaseExecutor`)។
3. បន្ថែម translator មួយក្នុង `open-sse/translator/` ប្រសិនបើវាមិនប្រើទម្រង់ OpenAI។
4. ប្រសិនបើផ្អែកលើ OAuth សូមបន្ថែមការកំណត់រចនាសម្ព័ន្ធក្រោម `src/lib/oauth/providers/` និង
   `src/lib/oauth/services/`។
5. ចុះឈ្មោះម៉ូដែលក្នុង `open-sse/config/providerRegistry.ts` (ឬ registry សម្រាប់ទម្រង់ជាក់លាក់
   ក្រោម `open-sse/config/`)។
6. សរសេរការធ្វើតេស្តក្រោម `tests/unit/`។

### បន្ថែម API route ថ្មី

1. បង្កើត `src/app/api/your-route/route.ts`។
2. អនុវត្តតាមលំនាំ៖ CORS → ការផ្ទៀងផ្ទាត់ body ដោយ Zod → ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ → ការប្រគល់ការងារទៅ handler។
3. ប្រសិនបើមានទម្រង់ request ថ្មី៖ បន្ថែម Zod schema ក្នុង `src/shared/validation/schemas.ts`។
4. ប្រសិនបើសម្រាប់តែការគ្រប់គ្រង៖ បន្ថែម path ទៅ `src/shared/constants/publicApiRoutes.ts`
   (denylist សម្រាប់ផ្ទៃ API សាធារណៈ)។
5. បន្ថែមការធ្វើតេស្តក្រោម `tests/unit/`។
6. ធ្វើបច្ចុប្បន្នភាព `docs/reference/API_REFERENCE.md` និង `docs/openapi.yaml`។

### បន្ថែមម៉ូឌុល DB ថ្មី

1. បង្កើត `src/lib/db/yourModule.ts` ហើយ import `getDbInstance()` ពី `./core.ts`។
2. Export អនុគមន៍ CRUD សម្រាប់ដែនរបស់អ្នក។
3. ប្រសិនបើមានតារាងថ្មី៖ បន្ថែម migration មួយក្រោម `src/lib/db/migrations/` ដោយដាក់លេខ
   តាមលំដាប់ អាចដំណើរការម្តងហើយម្តងទៀតដោយគ្មានផលប៉ះពាល់ និងស្ថិតក្នុង transaction។
4. អ្នក import ត្រូវប្រើ direct imports ពី `@/lib/db/yourModule` (គ្មាន barrel — ស្រទាប់ re-export ចាស់ `localDb.ts` ត្រូវបានដកចេញហើយ)។
5. បន្ថែមការធ្វើតេស្តក្រោម `tests/unit/`។

### បន្ថែមឧបករណ៍ MCP ថ្មី

1. បន្ថែមនិយមន័យឧបករណ៍ក្រោម `open-sse/mcp-server/tools/` (ឬពង្រីក

## 11. អនុសញ្ញា

- **រចនាប័ទ្មកូដ**៖ ចូលបន្ទាត់ដោយ 2 space, ប្រើ double quotes, ទទឹង 100 តួអក្សរ, ប្រើ semicolons,
  និង `es5` trailing commas — ត្រូវបានអនុវត្តដោយ Prettier តាមរយៈ `lint-staged`។
- **Imports**៖ ខាងក្រៅ → ខាងក្នុង (`@/`, `@omniroute/open-sse`) → relative។
- **ការដាក់ឈ្មោះ**៖ ឯកសារប្រើ `camelCase` ឬ `kebab-case`, components ប្រើ `PascalCase`,
  constants ប្រើ `UPPER_SNAKE`។
- **ESLint**៖ `no-eval`, `no-implied-eval`, `no-new-func` = `error` គ្រប់ទីកន្លែង;
  `no-explicit-any` = `warn` ក្នុង `open-sse/` និង `tests/`, ជា error នៅកន្លែងផ្សេង។
- **TypeScript**៖ `strict: false` (ជំហរដើម្បីគាំទ្រប្រព័ន្ធចាស់)។ គួរប្រើ types ដែលបញ្ជាក់ច្បាស់លាស់ជំនួស
  inference សម្រាប់ព្រំដែនឆ្លងម៉ូឌុល។
- **មូលដ្ឋានទិន្នន័យ**៖ មិនត្រូវសរសេរ SQL ដើមក្នុង routes ឬ handlers ឡើយ — ត្រូវឆ្លងកាត់
  ម៉ូឌុល `src/lib/db/` ជានិច្ច។ មិនត្រូវ barrel-import ឡើយ — ប្រើម៉ូឌុល `src/lib/db/*` ជាក់លាក់ដោយផ្ទាល់។
- **ការកំណត់ type សម្រាប់ DB-entity (#3512)**៖ អនុគមន៍ដែលសរសេរ ឬអានទម្រង់ row
  របស់តារាង DB គួរទទួល/ត្រឡប់ TS interface ដែលមានឈ្មោះ និងឆ្លុះបញ្ចាំង columns
  របស់តារាងនោះក្នុងសមាមាត្រ 1:1 មិនមែន `any` ឬ inline anonymous type នៅ call site ទេ។ ដាក់
  interface នៅក្បែរអនុគមន៍ (ឧ. `export interface UsageEntry` ក្នុង
  `src/lib/usage/usageHistory.ts` នៅខាងលើ `saveRequestUsage`) រក្សា fields នីមួយៗឱ្យជា
  optional/nullable នៅពេល writers ផ្សេងៗបញ្ចូលទិន្នន័យទៅក្នុង row
  ជាបន្តបន្ទាប់ ហើយគួរប្រើ `unknown` ជំនួស `any` សម្រាប់ field ដែលទម្រង់របស់វា
  ប្រែប្រួលតាម callers (ត្រូវកត់ត្រានៅលើ field ឧ. `UsageEntry.tokens`
  ទទួលយកទាំង usage ដែលមានទម្រង់ដើមរបស់ provider និងទម្រង់ដែលបានធ្វើឱ្យស្តង់ដារ)។ នៅពេលចំនួន
  `any` របស់ឯកសារមួយថយដល់សូន្យតាមវិធីនេះ សូមបន្ថែមវាទៅក្នុង allowlist
  `check:any-budget:t11` (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`) ដើម្បីកុំឱ្យវាត្រឡប់ថយក្រោយ។ នេះជាអនុសញ្ញាសម្រាប់ផ្នែកដំបូង — ការសម្អាត
  "គ្មាន anonymous `any`" ទូលំទូលាយជាងនេះ ត្រូវបានអនុវត្តជាបន្តបន្ទាប់លើផ្នែកដែលនៅសល់នៃ
  codebase។
- **កំហុស**៖ ប្រើ try/catch ជាមួយ error types ជាក់លាក់ ហើយកត់ត្រា log ជាមួយ pino context។ មិនត្រូវ
  លាក់កំហុសដោយស្ងៀមស្ងាត់ក្នុង SSE streams ឡើយ; ប្រើ abort signals សម្រាប់ការសម្អាត។
- **សុវត្ថិភាព**៖ មិនត្រូវប្រើ `eval()` / `new Function()` / implied eval ឡើយ។ ផ្ទៀងផ្ទាត់
  inputs ទាំងអស់ដោយ Zod។ អ៊ិនគ្រីប credentials ពេលរក្សាទុក (AES-256-GCM)។ រក្សា
  denylist `src/shared/constants/upstreamHeaders.ts` ឱ្យស្របគ្នាជាមួយស្រទាប់
  sanitize/validation។
- **Commits**៖ Conventional Commits — `feat(scope): subject`។ scopes ដែលអនុញ្ញាត៖
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`។
- **Branches**៖ prefixes `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`។ មិនត្រូវ commit ដោយផ្ទាល់ទៅ `main` ឡើយ។
- **Husky**៖ pre-commit ដំណើរការ `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11`; pre-push ដំណើរការ `check:any-budget:t11` + `check:tracked-artifacts` (ការត្រួតពិនិត្យរហ័ស; មិនរាប់បញ្ចូល `test:unit`)។

## 12. ច្បាប់តឹងរ៉ឹង (ពី CLAUDE.md)

1. កុំ commit ព័ត៌មានសម្ងាត់ ឬព័ត៌មានបញ្ជាក់អត្តសញ្ញាណជាដាច់ខាត។
2. កុំធ្វើ barrel-import ជាដាច់ខាត — ត្រូវប្រើម៉ូឌុល `src/lib/db/*` ជាក់លាក់ដោយផ្ទាល់។
3. កុំប្រើ `eval()` / `new Function()` / eval ដោយប្រយោលជាដាច់ខាត។
4. កុំ commit ដោយផ្ទាល់ទៅ `main` ជាដាច់ខាត។
5. កុំសរសេរ SQL ដើមនៅក្នុង routes ជាដាច់ខាត — ត្រូវឆ្លងកាត់ម៉ូឌុល `src/lib/db/` ជានិច្ច។
6. កុំមិនអើពើចំពោះកំហុសដោយស្ងៀមស្ងាត់នៅក្នុង SSE streams ជាដាច់ខាត។
7. ត្រូវផ្ទៀងផ្ទាត់ inputs ជាមួយ Zod schemas ជានិច្ច។
8. ត្រូវបញ្ចូល tests ជានិច្ច នៅពេលផ្លាស់ប្ដូរ production code។
9. Coverage ត្រូវរក្សាឱ្យនៅ ≥ 60% (statements, lines, functions, branches)។
