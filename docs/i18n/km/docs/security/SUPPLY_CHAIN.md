OmniRoute បោះពុម្ពផ្សាយ npm + Docker artifacts។ ច្រកទ្វារទាំងនេះផ្ដល់នូវ provenance, inventory (SBOM) និងការស្កេន CVE ដែលទាំងអស់នេះជា OSS ហើយត្រូវបានបញ្ចូលទៅក្នុងលំហូរការងារនៃការចេញផ្សាយ។ ឥរិយាបថ **ផ្ដល់ដំបូន្មានជាមុន** — ពួកគេរាយការណ៍ឥឡូវនេះ ហើយនឹងលើកកម្ពស់ទៅជាការទប់ស្កាត់បន្ទាប់ពីការចេញផ្សាយពណ៌បៃតងលើកទី១។

CVE ratchet រូបភាពប្រើប្រាស់ **ពីរជំហាន** នៅក្នុង `docker-publish.yml`: ជំហាន SARIF (`HIGH,CRITICAL`, `exit-code: 0`) រក្សា HIGH+CRITICAL ឱ្យមើលឃើញនៅក្នុងផ្ទាំង Security ដោយមិនទប់ស្កាត់; ជំហាន _CRITICAL gate_ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) ធ្វើឱ្យការចេញផ្សាយបរាជ័យលើ CRITICAL CVE **ដែលមានដំណោះស្រាយដែលអាចប្រើបាន**។ `ignore-unfixed` ការពារការទប់ស្កាត់ការចេញផ្សាយសម្រាប់ base-image CVE ដែលគ្មាន upstream patch។

## ⚠️ ភាពប្រែប្រួលនៃ CVE (ច្រកត្រួតពិនិត្យ osv/Trivy ដែលមានលក្ខណៈរារាំង)

osv និង Trivy ប្រៀបធៀប dependencies ជាមួយមូលដ្ឋានទិន្នន័យ CVE ដែល**កើនឡើងជាបន្តបន្ទាប់**។ PR មួយដែល
**មិនបានប៉ះពាល់ dependencies ណាមួយ** អាចប្រែជាពណ៌ក្រហមភ្លាមៗ ដោយសារ CVE ថ្មីមួយត្រូវបាន
បង្ហាញជាសាធារណៈនៅក្នុង dependency ដែលមានស្រាប់ (osv៖ `vulnCount` ដែលបានវាស់ > baseline; Trivy៖ មាន
CRITICAL ថ្មីដែលអាចជួសជុលបាននៅក្នុង image)។ **នេះជាឥរិយាបថប្រតិបត្តិការដែលត្រូវបានរំពឹងទុករបស់ច្រកត្រួតពិនិត្យ
CVE ដែលមានលក្ខណៈរារាំង មិនមែនជាការថយចុះគុណភាពរបស់ផលិតផលទេ។**

នៅពេល osv ឬ Trivy ប្រែជាពណ៌ក្រហមដោយសារ CVE ដែលទើបត្រូវបានបង្ហាញជាសាធារណៈ ដំណោះស្រាយគឺ៖

1. **ដំឡើងកំណែ dependency ដែលរងផលប៉ះពាល់** (ជាជម្រើសដែលពេញចិត្ត) — ដំឡើងទៅកំណែដែលបានបំណះតាមរយៈ `package.json`
   `overrides` (dependencies បន្តបន្ទាប់) ឬ build image ឡើងវិញដោយប្រើ base ដែលបានបំណះ។
2. **ប្រសិនបើដំណោះស្រាយមិនអាចប្រើបាន៖** រក្សាការស្វែងរកដែលបានវាស់វែង និងតាមដានភាពអាស្រ័យ ឬរូបភាពដែលរងផលប៉ះពាល់។ កុំលើកឡើងពីមូលដ្ឋាននៃភាពងាយរងគ្រោះ ដើម្បីធ្វើឱ្យបេក្ខជនបរាជ័យ។ `ignore-unfixed: true` របស់ Trivy មិនរាប់បញ្ចូលភាពងាយរងគ្រោះនៃរូបភាពរួចហើយ ដោយគ្មានបំណះខាងលើ។ ការលើកលែងណាមួយតម្រូវឱ្យពិនិត្យមើលភាពងាយរងគ្រោះ ID ផ្លូវកញ្ចប់ពិតប្រាកដ ការផុតកំណត់ និងបញ្ហាតាមដាននៅក្នុងគោលការណ៍។ វាមិនមែនជាផលវិបាកដោយស្វ័យប្រវត្តិនៃការស្កេនដែលបរាជ័យនោះទេ។

ការប្រតិបត្តិ OSV ដែលតម្រូវឱ្យមាន (`check:vuln-ratchet -- --ratchet`) នឹងបិទដោយបរាជ័យជាមួយ
`INCOMPLETE` និង exit 2 នៅពេលមិនអាចផ្ទៀងផ្ទាត់ scanner, report ឬ baseline បាន។
ការថយចុះតាមលទ្ធផលដែលបានវាស់នឹង exit 1។ ការប្រតិបត្តិបែបផ្ដល់ព័ត៌មានអាចនៅតែរាយការណ៍ `SKIP` ជាមួយ
exit 0 ដែលមិនបានបញ្ជាក់ថា dependencies បានឆ្លងកាត់ការស្កេននោះទេ។ ជំហាន Trivy ដែលមានលក្ខណៈ
រារាំងក៏តម្រូវឱ្យមានការវាស់វែងដែលបានជោគជ័យផងដែរ៖ tools ដែលមិនអាចប្រើបាន, jobs ដែលបរាជ័យ
និងការខ្វះភស្តុតាងអំពី image មិនអាចបញ្ជាក់ថា image នោះគ្មានភាពងាយរងគ្រោះបានទេ។

## គោលការណ៍ស្កេនរូបភាព

`.trivyignore.yaml` បច្ចុប្បន្នមិនមានការលើកលែងពីភាពងាយរងគ្រោះទេ។ `npm run check:trivy-ignore-policy` ធ្វើឱ្យមានសុពលភាពគោលការណ៍រចនាសម្ព័ន្ធនៅក្នុងទម្រង់ស្កេនមូលដ្ឋាន CI និងគុណភាព។ IDs មិនស្គាល់ ផ្លូវធំទូលាយ ធាតុស្ទួន និងការលើកលែងដែលផុតកំណត់ត្រូវបានបដិសេធ។ កេរ្តិ៍ដំណែល `.trivyignore` មិនមែនជាធាតុបញ្ចូលក្នុងការស្កេនដែលបានផ្ទេរទេ។
