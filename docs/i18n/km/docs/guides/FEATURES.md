## 🎨 បន្សំ

បង្កើតការបញ្ជូលផ្លូវគំរូជាមួយនឹងយុទ្ធសាស្រ្តសាធារណៈចំនួន 22៖ អាទិភាព ទម្ងន់ ជុំ-រ៉ូប៊ីន ការបញ្ជូនតតាមបរិបទ ការបំពេញដំបូង p2c (ជម្រើសថាមពលនៃជម្រើសពីរ) ចៃដន្យ ប្រើតិចបំផុត ចំណាយធ្វើឱ្យប្រសើរ កំណត់ឡើងវិញ ដឹងកំណត់ឡើងវិញ កំណត់បង្អួចឡើងវិញ ផុតកំណត់-ដំបូង កម្រិតសំឡេង កម្រិតសំឡេង កូតា (អ្នកផ្តល់សេវាល្អចុងក្រោយគេស្គាល់) បរិបទ-ធ្វើឱ្យប្រសើរ, ឃ្លាំងសម្ងាត់-ធ្វើឱ្យប្រសើរ,** ការលាយបញ្ចូលគ្នា** (អ្នកគាំទ្រក្រុមគំរូស្របគ្នា បន្ទាប់មកសំយោគចម្លើយមួយតាមរយៈចៅក្រម)** បំពង់** , និង** ជេវ** (ការជ្រើសរើសចូល TypeSafe Jev លើបញ្ជីចំណាត់ថ្នាក់របស់អ្នក)។ បន្សំនីមួយៗមានខ្សែសង្វាក់ជាច្រើនជាមួយនឹងការផ្លាស់ប្តូរដោយស្វ័យប្រវត្តិ ហើយរួមបញ្ចូលគំរូរហ័ស និងការត្រួតពិនិត្យការត្រៀមខ្លួន។

ការកែលម្អបន្សំថ្មីៗ៖

- **អ្នកបង្កើតបន្សំដែលមានរចនាសម្ព័ន្ធ** — បង្កើតជំហាននីមួយៗដោយជ្រើសរើសអ្នកផ្តល់សេវា គំរូ និង account/connection ពិតប្រាកដ
- **ការគាំទ្រអ្នកផ្តល់សេវាម្តងហើយម្តងទៀត** — ប្រើអ្នកផ្តល់សេវាដូចគ្នាម្តងទៀតច្រើនដងក្នុងបន្សំតែមួយ ដរាបណា `(provider, model, connection)` tuple មានតែមួយគត់
- **សុខភាពគោលដៅរួម** ការវិភាគ — និងផ្ទៃសុខភាពឥឡូវនេះបែងចែក combo targets/steps នីមួយៗ ជំនួសឱ្យការបង្រួមអ្វីគ្រប់យ៉ាងទៅជាខ្សែគំរូ
- **លំដាប់ថ្នាក់សមាសធាតុ** — `defaultTier -> fallbackTier` ឥឡូវនេះមានឥទ្ធិពលលើលំដាប់ execution/fallback ដែលកំពុងដំណើរការសម្រាប់ជំហានបន្សំកម្រិតកំពូល
- **គំរូប្រអប់បញ្ចូលប្រព័ន្ធ** — combo `system_message` គាំទ្រផ្នែកខាងម៉ាស៊ីនមេ `{{MODEL_ID}}`, `{{PROVIDER_ID}}`, `{{ACCOUNT}}` និង `{{FINGERPRINT}}` placeholder ពង្រីកពីគោលដៅដែលបានបញ្ជូនតាមពិតមុនពេលបញ្ជូន។ បញ្ជីដែលបានអនុញ្ញាត និងមិនប្រើឡើងវិញ; កន្លែងដាក់ដែលមិនស្គាល់ ស្ថិតនៅតាមព្យញ្ជនៈ។ តម្លៃទទេពង្រីកទៅទទេ; ការជម្រុញប្រព័ន្ធអតិថិជនមិនដែលត្រូវបានសរសេរឡើងវិញទេ។ `{{FINGERPRINT}}` ដោះស្រាយសម្រាប់តែអ្នកផ្តល់សេវាឥតគិតថ្លៃដែលមានមូលដ្ឋានលើស្នាមម្រាមដៃជាមួយនឹងស្នាមម្រាមដៃដែលបានខ្ទាស់ ឬបង្វិលដោយស្វ័យប្រវត្តិ — វាពង្រីកទៅទទេនៅកន្លែងផ្សេងទៀត (ឧទាហរណ៍ ការតភ្ជាប់ស្នាមម្រាមដៃតែមួយ អ្នកផ្តល់សេវាមិនមែន fp) ។ ការពង្រីកគ្របដណ្តប់រង្វិលជុំបញ្ជូនស្តង់ដារ ជុំ-រ៉ូប៊ីន និងវគ្គបរិបទ-ឃ្លាំងសម្ងាត់ដែលបានខ្ទាស់។ ការលាយបញ្ចូលគ្នា ភាពច្របូកច្របល់ បំពង់បង្ហូរប្រេង និងយុទ្ធសាស្ត្រប្រតិបត្តិដែលជាប់ពាក់ព័ន្ធ មិនទាន់ពង្រីកកន្លែងដាក់នៅឡើយទេ។

- **ទូទៅ** — ការផ្ទុកទិន្នន័យរបស់ប្រព័ន្ធ ការគ្រប់គ្រងទិន្នន័យបម្រុងទុក (នាំចេញ/នាំចូលមូលដ្ឋានទិន្នន័យ)
- **រូបរាង** — កម្មវិធីជ្រើសរើសស្បែក (ងងឹត/ភ្លឺ/តាមប្រព័ន្ធ), ពណ៌ស្បែកកំណត់ជាមុន និងពណ៌ផ្ទាល់ខ្លួន, ភាពមើលឃើញនៃកំណត់ហេតុសុខភាព, ការគ្រប់គ្រងភាពមើលឃើញនៃធាតុរបារចំហៀង និងបន្ទាត់បំបែកក្រុម, ការគ្រប់គ្រងភាពមើលឃើញនៃ tunnel របស់ Endpoint
- **AI** — មុខងារជំនួយការ AI, ការកំណត់ជាមុនសម្រាប់ការបញ្ជូនលំនាំដើម (Auto Combo `auto/coding`, `auto/fast`, `auto/cheap`, `auto/smart`), ឃ្លាំងសម្ងាត់សម្រាប់ចាក់ឡើងវិញនូវដំណើរការវែកញែក និងប៊ូតុងបិទបើកជំនាញ/អង្គចងចាំ
- **សុវត្ថិភាព** — ការការពារ API endpoint, ការទប់ស្កាត់អ្នកផ្តល់សេវាផ្ទាល់ខ្លួន, ការចម្រោះ IP, ព័ត៌មានសម័យ
- **ការបញ្ជូន** — ឈ្មោះជំនួសម៉ូដែល, ការបន្ថយកម្រិតភារកិច្ចផ្ទៃខាងក្រោយ, ការបញ្ជូនតាមកម្រិតដែលគិតគូរពី manifest (W1–W4), `fallbackDelayMs`, ការបញ្ជូនជាប់លាប់តាមសម័យនីមួយៗ
- **ភាពធន់** — ការរក្សាទុកកម្រិតអត្រា, ការលៃតម្រូវ circuit breaker, ការបិទគណនីដែលត្រូវបានហាមឃាត់ដោយស្វ័យប្រវត្តិ, ការត្រួតពិនិត្យការផុតកំណត់របស់អ្នកផ្តល់សេវា, កម្រិតចាប់ផ្ដើមផ្ទេរបន្តរបស់ **Context Relay** និងការកំណត់រចនាសម្ព័ន្ធម៉ូដែលសង្ខេប, ការចាត់ថ្នាក់ 429 តាមអ្នកផ្តល់សេវានីមួយៗ និងប៊ូតុងបិទបើក `useUpstream429BreakerHints`, រយៈពេលផ្អាកម៉ូដែល
- **កម្រិតខ្ពស់** — ការសរសេរជាន់លើការកំណត់រចនាសម្ព័ន្ធ, ប្រវត្តិសវនកម្មការកំណត់រចនាសម្ព័ន្ធ, របៀបបន្ថយកម្រិត fallback, ការបន្ថយកម្រិតរបៀបផ្ទៃខាងក្រោយសម្រាប់ Responses API

## 🗜️ ការបង្រួម Prompt _(v3.7.9+)_

- **Caveman** — កញ្ចប់ច្បាប់ដែលសម្របតាមភាសា ការមើលជាមុន ការគ្រប់គ្រងរបៀបលទ្ធផល និងការវិភាគ
- **RTK** — ការបង្រួមដែលសម្របតាមពាក្យបញ្ជាសម្រាប់លទ្ធផលរបស់ shell, git, test, build, package, Docker, infra, JSON និង stack-trace
- **Compression Combos** — ខ្សែដំណើរការដែលមានឈ្មោះ ដូចជា `rtk -> caveman` ដែលត្រូវបានកំណត់ឱ្យ routing combos; ការគណនាបែបដាក់ជាន់លំនាំដើមសម្រេចបានការសន្សំជាមធ្យម `~89%` និងការសន្សំបរិបទដែលមានសិទ្ធិ `78-95%` នៅពេលម៉ាស៊ីនទាំងពីរត្រូវបានអនុវត្ត
- **ការស្ដារលទ្ធផលដើម** — ទ្រនិចទៅកាន់លទ្ធផលដើមរបស់ RTK ដែលបានលាក់ព័ត៌មានរសើបជាជម្រើស សម្រាប់បំបាត់កំហុសនៃការបង្រួមដែលបរាជ័យ

## 🛡️ ការពង្រឹងសុវត្ថិភាព Proxy _(v3.5.5+)_

ការអនុវត្តការកំណត់រចនាសម្ព័ន្ធ proxy យ៉ាងទូលំទូលាយនៅទូទាំងខ្សែដំណើរការសំណើទាំងមូល៖

- **ការពិនិត្យសុខភាព Token** — ឥឡូវនេះ ការធ្វើឱ្យ OAuth ថ្មីនៅផ្ទៃខាងក្រោយនឹងដោះស្រាយការកំណត់រចនាសម្ព័ន្ធ proxy សម្រាប់ការតភ្ជាប់នីមួយៗ ដើម្បីទប់ស្កាត់ការបរាជ័យនៅក្នុងបរិស្ថានដែលតម្រូវឱ្យប្រើ proxy
- **ការផ្ទៀងផ្ទាត់ API Key** — ការផ្ទៀងផ្ទាត់សោរបស់ provider (`POST /api/providers/validate`) ត្រូវបានបញ្ជូនតាមរយៈ `runWithProxyContext` ដោយគោរពតាមការកំណត់ proxy កម្រិត provider និងការកំណត់សកល
- **ការកែតម្រូវ undici Dispatcher** — Proxy dispatchers ប្រើការអនុវត្ត fetch ផ្ទាល់របស់ undici ជំនួសឱ្យ fetch ដែលភ្ជាប់មកជាមួយ Node ដើម្បីដោះស្រាយកំហុស `invalid onRequestStart method` នៅលើ Node.js 22
- **ការរកឃើញកំណែ Node.js** — ទំព័រចូលប្រើនឹងរកឃើញកំណែ Node.js ដែលមិនឆបគ្នា (24+) ជាមុន ហើយបង្ហាញបដាព្រមានជាមួយការណែនាំឱ្យប្រើ Node 22 LTS

- **`DELETE /api/sync/tokens/:id`** — ដកហូតថូខឹនមួយ
- **`GET /api/sync/bundle`** — ទាញយក snapshot JSON របស់កំណត់រចនាសម្ព័ន្ធដែលមានកំណែ និងប្រើ ETag ជាសោ (ផ្ទៀងផ្ទាត់ដោយប្រើតែថូខឹនសមកាលកម្មប៉ុណ្ណោះ)។ ការកំណត់សម្រាប់ការផ្ទៀងផ្ទាត់ ដូចជាពាក្យសម្ងាត់របស់ dashboard ត្រូវបានដកចេញ ប៉ុន្តែព័ត៌មានសម្ងាត់របស់ provider និង API keys ត្រូវបានរួមបញ្ចូល ដូច្នេះសូមចាត់ទុកឯកសារនេះជាព័ត៌មានសម្ងាត់

កញ្ចប់កំណត់រចនាសម្ព័ន្ធត្រូវបានបង្កើតដោយ `src/lib/sync/bundle.ts`។ កម្មវិធីប្រើប្រាស់ប្រៀបធៀប response header `ETag` ដើម្បីរកឃើញការផ្លាស់ប្តូរ ដោយមិនចាំបាច់ទាញយក payload ពេញលេញឡើងវិញ។ ពី CLI ពាក្យបញ្ជា `omniroute sync bundle <outPath> --token <syncToken>` (ឬ `OMNIROUTE_SYNC_TOKEN`) រក្សាទុកវាទៅក្នុងឯកសារដែលអាចចូលប្រើបានដោយម្ចាស់តែប៉ុណ្ណោះ។

## 🛡️ Safe Outbound Fetch & SSRF Guard _(v3.6.6 +)_

រាល់ការហៅទូរស័ព្ទទៅការស្វែងរកការបញ្ជាក់របស់អ្នកផ្តល់សេវា និងការរកឃើញគំរូទាំងអស់ឥឡូវនេះ ឆ្លងកាត់ការការពារពីខាងក្រៅពីរស្រទាប់៖

1. **យាម URL** (`src/shared/network/outboundUrlGuard.ts`) — ពិនិត្យឈ្មោះម៉ាស៊ីនរបស់គោលដៅ ឬ IP ព្យញ្ជនៈដូចដែលបានសរសេរដំបូង។ ក្នុងរបៀបសម្រាប់តែសាធារណៈ កញ្ចប់ប្រមូលយកដោយសុវត្ថិភាពក៏ដោះស្រាយឈ្មោះ និងបដិសេធចម្លើយឯកជន។ តាមលំនាំដើម វារារាំងចំណុចបញ្ចប់ cloud-metadata — ទាំងអស់នៃ 169.254.0.0/16 បូកនឹងឈ្មោះម៉ាស៊ីនទិន្នន័យមេតាដែលគេស្គាល់។ `OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS=false` រារាំង hosts ឯកជន និង loopback ផងដែរ; `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS=true` (ឬ `OUTBOUND_SSRF_GUARD_ENABLED=false` កេរ្តិ៍ដំណែល) បិទការត្រួតពិនិត្យ។ តម្លៃដែលបានរក្សាទុកពីការបិទបើកផ្ទាំងគ្រប់គ្រងរបស់ទង់មានអាទិភាពលើអថេររបស់វា ហើយអ្នកផ្តល់សេវាក្នុងស្រុកដែលភ្ជាប់មកជាមួយនឹងរំលងការយាមកំឡុងពេលការបញ្ជាក់សោ។ សូមមើល `docs/reference/ENVIRONMENT.md`។
2. **កញ្ចប់យកដោយសុវត្ថិភាព** (`src/shared/network/safeOutboundFetch.ts`) — អនុវត្តការយាម URL ធ្វើឱ្យការអស់ពេលធម្មតា និងព្យាយាមឡើងវិញនូវកំហុសបណ្ដោះអាសន្នជាមួយនឹងការបិទឡើងវិញអិចស្ប៉ូណង់ស្យែល។

ការបំពានលើផ្ទៃដូចជា `URL_GUARD_BLOCKED` — HTTP 503 តាមរយៈ `getSafeOutboundFetchErrorStatus` (400 នៅលើផ្លូវស្វែងរកគំរូ) — និងប្លុក SSRF ពិតប្រាកដក្នុងអំឡុងពេលសុពលភាពត្រូវបានសរសេរទៅកាន់កំណត់ហេតុសវនកម្មជាព្រឹត្តិការណ៍ `provider.validation.ssrf_blocked` ។
