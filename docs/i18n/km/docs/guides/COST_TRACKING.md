## របៀបដែលការចំណាយត្រូវបានប៉ាន់ប្រមាណ

### ប្រភពតម្លៃ

ការចំណាយបានមកពីតារាងតម្លៃរួមបញ្ចូលគ្នានៅក្នុង [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) តាមលំដាប់អាទិភាពនេះ (**ខ្ពស់បំផុតដំបូង** ):

1. **អ្នកប្រើប្រាស់បដិសេធ** តម្លៃ — កំណត់ក្នុងផ្ទាំងគ្រប់គ្រង ឬតាមរយៈ `PATCH /api/pricing` (ចន្លោះឈ្មោះ `pricing` )។
2. **ការធ្វើសមកាលកម្ម model.dev** តម្លៃ — យកពី `https://models.dev/api.json` (ចន្លោះឈ្មោះ `models_dev_pricing` ) ។
3. **ការធ្វើសមកាលកម្ម LiteLLM** តម្លៃ — យកពី `model_prices_and_context_window.json` សាធារណៈរបស់ LiteLLM(លំហឈ្មោះ `pricing_synced` )។
4. **លំនាំដើមដែលសរសេរកូដរឹង** អត្រា — ដឹកជញ្ជូនក្នុង [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) ។

សម្រាប់ provider/model ដូចគ្នា តម្លៃពីស្រទាប់អាទិភាពខ្ពស់សរសេរជាន់លើវាលដែលត្រូវគ្នានៅក្នុងស្រទាប់ទាប។ វាលដែលអវត្តមានពីស្រទាប់ខាងលើនៅតែអាចមកពីស្រទាប់ខាងក្រោម។ ការបញ្ជាទិញត្រូវបានជួសជុល ទោះបីជាការងារធ្វើសមកាលកម្មឯករាជ្យទាំងពីរដំណើរការក្នុងពេលតែមួយក៏ដោយ។ `GET /api/pricing?includeSources=1` ត្រឡប់ `pricing` និង `sourceMap` ដែលស្លាកតាមគំរូនីមួយៗ (`user`, `modelsDev`, `litellm`, `default`) កំណត់ស្រទាប់អាទិភាពខ្ពស់បំផុតដែលមានគំរូនោះ។

**ការធ្វើសមកាលកម្ម LiteLLM** ត្រូវបានជ្រើសរើសចូល បិទតាមលំនាំដើម។ អថេរបរិស្ថានរបស់វា (សូមមើល [`.env.example`](../../.env.example) ) គឺ៖

| Env var                 | លំនាំដើម  | គោលបំណង                                                                                                     |
| ----------------------- | --------- | ----------------------------------------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | បើកដំណើរការសមកាលកម្មតម្លៃ LiteLLM ផ្ទៃខាងក្រោយ។                                                             |
| `PRICING_SYNC_INTERVAL` | `86400`   | ចន្លោះពេលធ្វើសមកាលកម្មជាវិនាទី (ប្រចាំថ្ងៃ)។                                                                |
| `PRICING_SYNC_SOURCES`  | `litellm` | ការជ្រើសរើសប្រភពសម្រាប់ការធ្វើសមកាលកម្មនេះតែប៉ុណ្ណោះ; បច្ចុប្បន្នមានតែ `litellm` ប៉ុណ្ណោះដែលត្រូវបានគាំទ្រ។ |

**ការធ្វើសមកាលកម្ម model.dev** គឺដាច់ដោយឡែកពីសមកាលកម្ម LiteLLM ហើយត្រូវបានបិទតាមលំនាំដើមផងដែរ។ បើកវានៅក្នុងការកំណត់ (ធ្វើសមកាលកម្ម model.dev) ឬប្រើអថេរទាំងនេះ៖

| Env var                    | លំនាំដើម     | គោលបំណង                                                                                                  |
| -------------------------- | ------------ | -------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(មិនកំណត់)_ | មិនបានកំណត់តាមការកំណត់បិទបើក; `1/true/on/yes` បើក ហើយ `0/false/off/no` បិទ (ទោះបីជាការកំណត់បើកវាក៏ដោយ) ។ |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`      | ចន្លោះពេលធ្វើសមកាលកម្មលំនាំដើម model.dev ជាវិនាទី (ប្រចាំថ្ងៃ)។                                          |

`PRICING_SYNC_SOURCES` ធ្វើ**ទេ។** បើកដំណើរការ model.dev; វាគ្រប់គ្រងតែការធ្វើសមកាលកម្ម LiteLLM ប៉ុណ្ណោះ។ ការលុបការបដិសេធរបស់អ្នកប្រើមិនជម្រះចន្លោះឈ្មោះដែលបានធ្វើសមកាលកម្មទេ។ ស្រទាប់តម្លៃបន្ទាប់ដែលអាចប្រើបានមានប្រសិទ្ធភាព។ សម្រាប់ម៉ូដែលដែលមិនមានតម្លៃ សូមពិនិត្យមើលទាំងការកំណត់សមកាលកម្ម និង `sourceMap` មុនពេលបន្ថែមការបដិសេធដោយដៃ។

### រូបមន្តចំណាយ

តម្លៃត្រូវបានគណនាតាមការស្នើសុំពីចំនួនសញ្ញាសម្ងាត់ និងអត្រាក្នុងមួយលានសញ្ញាសម្ងាត់ក្នុង [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`)៖

- **បញ្ចូលនិមិត្តសញ្ញា** (ដកការអានឃ្លាំងសម្ងាត់ និងនិមិត្តសញ្ញាបង្កើតឃ្លាំងសម្ងាត់) អត្រា × `input` ។
- **សញ្ញាសម្ងាត់អានឃ្លាំងសម្ងាត់** អត្រា × `cached` (ធ្លាក់ចុះត្រឡប់ទៅអត្រាបញ្ចូល) ។
- **និមិត្តសញ្ញាបង្កើតឃ្លាំងសម្ងាត់** អត្រា × `cache_creation` (ធ្លាក់ចុះត្រឡប់ទៅអត្រាបញ្ចូល) ។
- **និមិត្តសញ្ញាលទ្ធផល** អត្រា × `output` ។
- **និមិត្តសញ្ញាសមហេតុផល** អត្រា × `reasoning` (ធ្លាក់ចុះត្រឡប់ទៅអត្រាទិន្នផល) ។

អត្រាទាំងអស់ត្រូវបានបកស្រាយថាជា USD ក្នុង 1,000,000 ថូខឹន។ កម្រិតសេវាកម្ម Codex "លឿន"/"អាទិភាព" ឬ "flex" អនុវត្តមេគុណថ្លៃដើម (`getCodexFastCostMultiplier`) — ឧទាហរណ៍ flex ត្រូវបានគិតប្រាក់ដោយការបញ្ចុះតម្លៃសញ្ញាសម្ងាត់ 50% ដែលបង្ហាញជា**ការសន្សំ flex** នៅក្នុងផ្ទាំងគ្រប់គ្រង។

ឈ្មោះម៉ូដែលត្រូវបានធ្វើឱ្យធម្មតាជាមុនសិន (បុព្វបទផ្លូវអ្នកផ្តល់សេវាដូចជា `openai/` ឬ `accounts/fireworks/models/` ត្រូវបានដកចេញ) ដូច្នេះជួរប្រវត្តិសាស្ត្រនៅតែត្រូវគ្នានឹងតម្លៃ។

### របៀបចំណាយត្រូវបានកត់ត្រា

- ការចំណាយរបស់ API-key ត្រូវបានផ្អាក និងហូរចេញជាបាច់ដោយ [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (លំនាំដើម 60s flush interval, 1,000-entry buffer)។ អាចទំនាក់ទំនងបានតាមរយៈ៖

### OCR និងការបង្កប់

- សំណើ `/v1/ocr` ជោគជ័យប្រើ `usage_info.pages_processed` ខាងលើ មិនមែនជួរទំព័រដែលបានស្នើសុំ ឬចំនួនវត្ថុទំព័រដែលបានត្រឡប់មកវិញទេ។ ការប៉ាន់ស្មានគឺទំព័រ × `ocr_cost_per_page` ( USD/page ដាច់ខាត ,**ទេ។** USD/million) ។
- សំណើដែលមានឯកសារ ឬប្រអប់កំណត់ព្រំដែន ទាមទារតម្លៃ `ocr_cost_per_annotated_page` ដាច់ដោយឡែក។ បើគ្មានវា តម្លៃនៅតែមិនស្គាល់។ ពន្ធ OCR ធម្មតាមិនត្រូវបានជំនួសដោយស្ងៀមស្ងាត់ទេ។
- ការធ្វើសមកាលកម្ម LiteLLM គូសផែនទីវាល `annotation_cost_per_page` ខាងលើរបស់វាទៅក្នុង `ocr_cost_per_annotated_page` ដោយរក្សាតម្លៃ USD/page ដាច់ខាត និងធាតុសម្រាប់តែចំណារពន្យល់ រួមទាំងលេខសូន្យច្បាស់លាស់។ វាល Canonical ដែលបានផ្គត់ផ្គង់មានអាទិភាព។ តម្លៃឈ្មោះក្លែងក្លាយមិនត្រឹមត្រូវត្រូវបានមិនអើពើ។ ការបដិសេធតម្លៃអ្នកប្រើប្រាស់រក្សាអាទិភាពធម្មតារបស់ពួកគេ។ សូមមើល [គន្លឹះកំណត់តម្លៃ OCR របស់LiteLLM](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) ។
- ការប្រើប្រាស់OCR រក្សាទុកចំនួនទំព័រ តម្លៃឯកតា ការចំណាយ USD ដែលបានគណនា សោ API និងការតភ្ជាប់ដែលបានជ្រើសរើស។ ទំព័រមិនដែលត្រូវបានតំណាងជាសញ្ញាសម្ងាត់ទេ។ កំណត់ហេតុការហៅទូរសព្ទមានទិន្នន័យមេតានៃការចេញវិក្កយបត្រ មិនមែនឯកសារ URLs, PDF បៃ ឬអត្ថបទដែលបានស្រង់ចេញទេ។
- សំណើ `/v1/embeddings` ដែលទទួលបានជោគជ័យ កត់ត្រាជួរប្រើប្រាស់មួយក្នុងមួយបាច់រាងកាយ រួមទាំងបណ្តុំដាច់ដោយឡែកដែលបានបញ្ចប់ក្នុងមីលីវិនាទីដូចគ្នា។ ការគិតថ្លៃដែលរាយការណ៍ដោយអ្នកផ្តល់សេវាមានអាទិភាពជាងការប៉ាន់ប្រមាណសញ្ញាសម្ងាត់។ កញ្ចប់រុំមិនបន្ថែមបន្ទុកទេ។
- ប្រវត្តិនៃការប្រើប្រាស់, ការវិភាគតម្លៃ, បង្អួច provider/account, ដែនកំណត់ចំណាយរបស់ API-key, សៀវភៅកត់ត្រាតម្លៃសំណើ និងការប្រើប្រាស់ប្រចាំថ្ងៃរួមបញ្ចូលការគិតថ្លៃទាំងនេះ។ គ្រាប់ចុចគ្មានកំណត់ហេតុរក្សាគណនេយ្យជាលេខដោយមិនរក្សាទុកអត្ថបទប្រភព។
- ការបាត់បង់ការប្រើប្រាស់ឬពន្ធគឺ**មិនស្គាល់** មិនគិតថ្លៃទេ៖ ក្បាលតម្លៃឆ្លើយតបត្រូវបានលុបចោល ហើយគោលការណ៍ប្រើប្រាស់ដែលមិនមានតម្លៃដែលមានស្រាប់ត្រូវបានអនុវត្តចំពោះសោ API ដែលមានកំណត់។ អត្រាសូន្យដែលបានកំណត់យ៉ាងច្បាស់លាស់នៅតែមានសុពលភាពការប្រើប្រាស់តម្លៃសូន្យ។

នេះគឺជាគណនេយ្យតែទៅមុខ។ ការហៅទូរសព្ទ OCR/embedding ចាស់ដែលមិនធ្លាប់សរសេរប្រវត្តិប្រើប្រាស់មិនអាចបង្កើតឡើងវិញពីការផ្ទេរនេះបានទេ។ ការប៉ាន់ប្រមាណកាតាឡុកគឺជាការប៉ាន់ស្មាន USD មិនមែនជាវិក្កយបត្រ និងមិនរាប់បញ្ចូលការបំប្លែងរូបិយប័ណ្ណ ពន្ធ ឬការបញ្ចុះតម្លៃ។

- **ផ្ទាំងសង្ខេបការចំណាយ** — ការចំណាយប៉ាន់ស្មានសម្រាប់ _ថ្ងៃនេះ (1d)_, _7d_, _30d_ និងចន្លោះពេលដែលបានជ្រើសរើស។ ឧបករណ៍ជ្រើសរើសចន្លោះពេល៖ `7d`, `30d`, `90d`, `all`។
- **រង្វាស់សំខាន់ៗ** — ចំនួនសំណើក្នុងចន្លោះពេល ក្រុមហ៊ុនផ្តល់សេវាដែលសកម្ម ម៉ូដែលដែលសកម្ម និងតម្លៃជាមធ្យមក្នុងមួយសំណើ។
- **កម្មវិធីរុករកការចំណាយ** — តារាងដែលអាចតម្រៀប/ត្រងបាន ដោយដាក់ជាក្រុមតាម **ក្រុមហ៊ុនផ្តល់សេវា**, **ម៉ូដែល**, **API key**, **គណនី** ឬ **កម្រិតសេវាកម្ម** ព្រមទាំងបង្ហាញតម្លៃ ចំនួនសំណើ ចំនួន token តម្លៃជាមធ្យម/សំណើ និងភាគរយនៃការចំណាយសរុប។
- **ការប្រើប្រាស់ token** — ចំនួន token សរុប / input / output និងសមាមាត្រ input:output។
- **ប្រសិទ្ធភាពនៃការបញ្ជូន** — ចំនួន fallback អត្រា fallback និងវិសាលភាពគ្របដណ្តប់ម៉ូដែលដែលបានស្នើសុំ។
- **ការព្យាករណ៍ប្រចាំខែ** — ព្យាករណ៍ការចំណាយនៅចុងខែពីមធ្យមភាគប្រចាំថ្ងៃថ្មីៗ។
- **ការប្រៀបធៀបរយៈពេល** — ភាគរយនៃការប្រែប្រួលរវាងពាក់កណ្តាលទីមួយ និងពាក់កណ្តាលទីពីរនៃចន្លោះពេល។
- **គំនូសតាង** — និន្នាការតម្លៃប្រចាំថ្ងៃ ចំណែករបស់ក្រុមហ៊ុនផ្តល់សេវា (គំនូសតាងរង្វង់) ក្រុមហ៊ុនផ្តល់សេវាឈានមុខ ម៉ូដែលឈានមុខ តម្លៃតាម API key តម្លៃតាមគណនី លំនាំប្រើប្រាស់ប្រចាំសប្តាហ៍ និងផែនទីកម្ដៅសកម្មភាព។
- **ការនាំចេញ** — ទាញយកចន្លោះពេលបច្ចុប្បន្នជា **CSV** ឬ **JSON** (ប៊ូតុងនឹងបង្ហាញនៅពេលមានទិន្នន័យតម្លៃធំជាងសូន្យ)។

នៅពេលគ្មានចរាចរណ៍ដែលមានតម្លៃ ជួរដេកនឹងបង្ហាញស្លាក "Legacy / Free" ជំនួសឱ្យ `$0` ដោយឆ្លុះបញ្ចាំងពីម៉ូដែលតាមដានការសន្សំ។

### ទំព័ររងនៃ Costs ដែលពាក់ព័ន្ធ

តំបន់ Costs ក៏មានទំព័រខាងក្រោមផងដែរ (ទាំងអស់ស្ថិតនៅក្រោម `/dashboard/costs/`)៖

- **Pricing** (`/dashboard/costs/pricing`) — មើល និងកំណត់តម្លៃតាមម៉ូដែលជំនួសតម្លៃដើម (បង្ហាញផ្ទាំង Pricing ដែលប្រើរួមគ្នា)។
- **Budget** (`/dashboard/costs/budget`) — កំណត់ដែនកំណត់ចំណាយតាមវិសាលភាព (បង្ហាញផ្ទាំង Budget ដែលប្រើរួមគ្នា)។
- **Quota Share** (`/dashboard/costs/quota-share`) — ក្រុមកូតាដែលប្រើរួមគ្នា និងទិដ្ឋភាពអត្រាប្រើប្រាស់។

## API endpoints

ទាំងអស់នេះទាមទារការផ្ទៀងផ្ទាត់សិទ្ធិគ្រប់គ្រង (loopback/JWT តាមរយៈ `requireManagementAuth`) លើកលែងតែមានការបញ្ជាក់ផ្សេងពីនេះ។

### ការវិភាគការប្រើប្រាស់ និងតម្លៃ

| វិធីសាស្ត្រ | Endpoint                 | គោលបំណង                                                                                                                                                                                |
| ----------- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`       | `/api/usage/analytics`   | ការវិភាគតម្លៃ/ការប្រើប្រាស់ពេញលេញ៖ សេចក្តីសង្ខេប និន្នាការប្រចាំថ្ងៃ តាមក្រុមហ៊ុនផ្តល់សេវា/ម៉ូដែល/API key/គណនី/កម្រិត។ Query៖ `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`។ |
| `GET`       | `/api/usage/utilization` | ការប្រើប្រាស់កូតាតាមក្រុមហ៊ុនផ្តល់សេវានីមួយៗក្នុងរយៈពេល។ Query៖ `range` (`1h`/`24h`/`7d`/`30d`), `provider`។                                                                           |
| `GET`       | `/api/usage/history`     | ជួរទិន្នន័យប្រវត្តិការប្រើប្រាស់ដើម។                                                                                                                                                   |

| `GET`       | `/api/usage/quota`       | ស្ថានភាពកូតារបស់ក្រុមហ៊ុនផ្តល់សេវា។                                                                                                                                                    |
| `GET`       | `/api/usage/proxy-logs`  | កំណត់ហេតុសំណើ proxy។                                                                                                                                                                   |

## CLI

CLI របស់ OmniRoute ផ្ដល់នូវពាក្យបញ្ជាសម្រាប់ថ្លៃចំណាយ ការប្រើប្រាស់ និងតម្លៃ (ដែលបានចុះឈ្មោះនៅក្នុង
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs))។

### `omniroute cost`

របាយការណ៍ថ្លៃចំណាយដែលបានប្រមូលផ្ដុំពី `/api/usage/analytics`។

```bash
omniroute cost                          # 30d ចុងក្រោយ ដាក់ជាក្រុមតាមអ្នកផ្ដល់សេវា
omniroute cost --period 7d              # 7 ថ្ងៃចុងក្រោយ
omniroute cost --group-by model         # ដាក់ជាក្រុមតាម provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ជួរឈរ៖ ក្រុម ចំនួនសំណើ token ចូល/ចេញ ថ្លៃចំណាយ (USD) និងភាគរយនៃចំនួនសរុប។ បន្ទាត់សរុបរួម
ត្រូវបានបង្ហាញនៅចុងបញ្ចប់ (មិនបង្ហាញនៅពេលប្រើ `--quiet` ឬ `--output json`)។

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # សេចក្ដីសង្ខេបថ្លៃចំណាយតាមអ្នកផ្ដល់សេវានីមួយៗ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ថវិកា
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` អានពី `GET /api/pricing/defaults`។ ដើម្បីកែសម្រួលតម្លៃរបស់ម៉ូដែលនីមួយៗ
> សូមប្រើទំព័រ **តម្លៃ** នៅលើផ្ទាំងគ្រប់គ្រង ឬ `PATCH /api/pricing`។
