## របៀបដែលការចំណាយត្រូវបានប៉ាន់ប្រមាណ

### ប្រភពតម្លៃ

ការចំណាយបានមកពីតារាងតម្លៃរួមបញ្ចូលគ្នានៅក្នុង [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) ក្នុងលំដាប់អាទិភាពនេះ (** ខ្ពស់បំផុតដំបូង** ):

1. **អ្នកប្រើប្រាស់បដិសេធ** តម្លៃ — កំណត់ក្នុងផ្ទាំងគ្រប់គ្រង ឬតាមរយៈ `PATCH /api/pricing` (ចន្លោះឈ្មោះ `pricing` )។
2. **ការធ្វើសមកាលកម្ម model.dev** តម្លៃ — យកពី `https://models.dev/api.json` (លំហឈ្មោះ `models_dev_pricing` ) ។
3. **ធ្វើសមកាលកម្ម LiteLLM** តម្លៃ — យកពី `model_prices_and_context_window.json` សាធារណៈរបស់ LiteLLM(លំហឈ្មោះ `pricing_synced` )។
4. **លំនាំដើមដែលសរសេរកូដរឹង** អត្រា — ដឹកជញ្ជូនក្នុង [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) ។

សម្រាប់ provider/model ដូចគ្នា តម្លៃពីស្រទាប់អាទិភាពខ្ពស់សរសេរជាន់លើវាលដែលត្រូវគ្នានៅក្នុងស្រទាប់ទាប។ វាលដែលអវត្តមានពីស្រទាប់ខាងលើនៅតែអាចមកពីស្រទាប់ខាងក្រោម។ ការបញ្ជាទិញត្រូវបានជួសជុល ទោះបីជាការងារធ្វើសមកាលកម្មឯករាជ្យទាំងពីរដំណើរការក្នុងពេលតែមួយក៏ដោយ។ `GET /api/pricing?includeSources=1` ត្រឡប់ `pricing` និង `sourceMap` ដែលស្លាកតាមគំរូនីមួយៗ (`user`, `modelsDev`, `litellm`, `default`) កំណត់ស្រទាប់អាទិភាពខ្ពស់បំផុតដែលមានគំរូនោះ។

**ធ្វើសមកាលកម្ម LiteLLM** ត្រូវបានជ្រើសរើសចូល បិទតាមលំនាំដើម។ អថេរបរិស្ថានរបស់វា (សូមមើល [`.env.example`](../../.env.example) ) គឺ៖

| Env var                 | លំនាំដើម  | គោលបំណង                                                                                                     |
| ----------------------- | --------- | ----------------------------------------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | បើកដំណើរការសមកាលកម្មតម្លៃ LiteLLM ផ្ទៃខាងក្រោយ។                                                             |
| `PRICING_SYNC_INTERVAL` | `86400`   | ចន្លោះពេលធ្វើសមកាលកម្មជាវិនាទី (ប្រចាំថ្ងៃ)។                                                                |
| `PRICING_SYNC_SOURCES`  | `litellm` | ការជ្រើសរើសប្រភពសម្រាប់ការធ្វើសមកាលកម្មនេះតែប៉ុណ្ណោះ; បច្ចុប្បន្នមានតែ `litellm` ប៉ុណ្ណោះដែលត្រូវបានគាំទ្រ។ |

**ការធ្វើសមកាលកម្ម model.dev** គឺដាច់ដោយឡែកពីសមកាលកម្ម LiteLLM ហើយត្រូវបានបិទតាមលំនាំដើមផងដែរ។ បើកវានៅក្នុងការកំណត់ (ធ្វើសមកាលកម្ម model.dev) ឬប្រើអថេរទាំងនេះ៖

| Env var                    | លំនាំដើម     | គោលបំណង                                                                                                 |
| -------------------------- | ------------ | ------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(មិនកំណត់)_ | មិនបានកំណត់តាមការកំណត់បិទបើក; `1/true/on/yes` បើកហើយ `0/false/off/no` បិទ (ទោះបីជាការកំណត់បើកវាក៏ដោយ) ។ |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`      | ចន្លោះពេលធ្វើសមកាលកម្មលំនាំដើម model.dev ជាវិនាទី (ប្រចាំថ្ងៃ)។                                         |

`PRICING_SYNC_SOURCES` ធ្វើ** ទេ។** បើកដំណើរការ model.dev; វាគ្រប់គ្រងតែការធ្វើសមកាល LiteLLM ប៉ុណ្ណោះ។ ការលុបការបដិសេធរបស់អ្នកប្រើមិនជម្រះចន្លោះឈ្មោះដែលបានធ្វើសមកាលកម្មទេ។ ស្រទាប់តម្លៃដែលមានបន្ទាប់នឹងមានប្រសិទ្ធភាព។ សម្រាប់ម៉ូដែលដែលមិនមានតម្លៃ សូមពិនិត្យមើលទាំងការកំណត់សមកាលកម្ម និង `sourceMap` មុនពេលបន្ថែមការបដិសេធដោយដៃ។

### រូបមន្តចំណាយ

តម្លៃត្រូវបានគណនាតាមការស្នើសុំពីចំនួនសញ្ញាសម្ងាត់ និងអត្រាក្នុងមួយលានសញ្ញាសម្ងាត់ក្នុង [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`)៖

- **បញ្ចូលនិមិត្តសញ្ញា** (ដកការអានឃ្លាំងសម្ងាត់ និងសញ្ញាសម្ងាត់បង្កើតឃ្លាំងសម្ងាត់) អត្រា × `input` ។
- **សញ្ញាសម្ងាត់អានឃ្លាំងសម្ងាត់** អត្រា × `cached` (ធ្លាក់ត្រឡប់ទៅអត្រាបញ្ចូល) ។
- **និមិត្តសញ្ញាបង្កើតឃ្លាំងសម្ងាត់** អត្រា × `cache_creation` (ធ្លាក់ត្រឡប់ទៅអត្រាបញ្ចូល) ។
- **និមិត្តសញ្ញាលទ្ធផល** អត្រា × `output` ។
- **និមិត្តសញ្ញាសមហេតុផល** អត្រា × `reasoning` (ធ្លាក់ចុះត្រឡប់ទៅអត្រាទិន្នផល) ។

អត្រាទាំងអស់ត្រូវបានបកស្រាយជា USD ក្នុង 1,000,000 ថូខឹន។ កម្រិតសេវាកម្ម Codex "លឿន"/"អាទិភាព" ឬ "flex" អនុវត្តមេគុណតម្លៃ (`getCodexFastCostMultiplier`) — ឧ flex ត្រូវបានចេញវិក្កយបត្រដោយការបញ្ចុះតម្លៃនិមិត្តសញ្ញា 50% ដែលបង្ហាញជា** ការសន្សំ flex** នៅក្នុងផ្ទាំងគ្រប់គ្រង។

ឈ្មោះម៉ូដែលត្រូវបានធ្វើឱ្យធម្មតាជាមុនសិន (បុព្វបទផ្លូវរបស់អ្នកផ្តល់សេវាដូចជា `openai/` ឬ `accounts/fireworks/models/` ត្រូវបានដកចេញ) ដូច្នេះជួរប្រវត្តិសាស្ត្រនៅតែត្រូវគ្នានឹងតម្លៃ។

## ផ្ទាំងគ្រប់គ្រង៖ ទំព័រ Costs

ទំព័រ **Costs** ស្ថិតនៅ `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`)។
ទិដ្ឋភាពសំខាន់របស់វាគឺផ្ទាំង **Cost Overview**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`)
ដែលផ្ទុកទិន្នន័យទាំងអស់ពី `GET /api/usage/analytics`។

អ្វីដែលវាបង្ហាញ៖

- **ផ្ទាំងសង្ខេបការចំណាយ** — ការចំណាយប៉ាន់ស្មានសម្រាប់ _ថ្ងៃនេះ (1d)_, _7d_, _30d_ និងចន្លោះពេលដែលបានជ្រើសរើស។ ឧបករណ៍ជ្រើសរើសចន្លោះពេល៖ `7d`, `30d`, `90d`, `all`។
- **រង្វាស់សំខាន់ៗ** — ចំនួនសំណើក្នុងចន្លោះពេល ក្រុមហ៊ុនផ្តល់សេវាដែលសកម្ម ម៉ូដែលដែលសកម្ម និងតម្លៃជាមធ្យមក្នុងមួយសំណើ។
- **កម្មវិធីរុករកការចំណាយ** — តារាងដែលអាចតម្រៀប/ត្រងបាន ដោយដាក់ជាក្រុមតាម **ក្រុមហ៊ុនផ្តល់សេវា**, **ម៉ូដែល**, **API key**, **គណនី** ឬ **កម្រិតសេវាកម្ម** ព្រមទាំងបង្ហាញតម្លៃ ចំនួនសំណើ ចំនួន token តម្លៃជាមធ្យម/សំណើ និងភាគរយនៃការចំណាយសរុប។
- **ការប្រើប្រាស់ token** — ចំនួន token សរុប / input / output និងសមាមាត្រ input:output។
- **ប្រសិទ្ធភាពនៃការបញ្ជូន** — ចំនួន fallback អត្រា fallback និងវិសាលភាពគ្របដណ្តប់ម៉ូដែលដែលបានស្នើសុំ។
- **ការព្យាករណ៍ប្រចាំខែ** — ព្យាករណ៍ការចំណាយនៅចុងខែពីមធ្យមភាគប្រចាំថ្ងៃថ្មីៗ។
- **ការប្រៀបធៀបរយៈពេល** — ភាគរយនៃការប្រែប្រួលរវាងពាក់កណ្តាលទីមួយ និងពាក់កណ្តាលទីពីរនៃចន្លោះពេល។
- **គំនូសតាង** — និន្នាការតម្លៃប្រចាំថ្ងៃ ចំណែករបស់ក្រុមហ៊ុនផ្តល់សេវា (គំនូសតាងរង្វង់) ក្រុមហ៊ុនផ្តល់សេវាឈានមុខ ម៉ូដែលឈានមុខ តម្លៃតាម API key តម្លៃតាមគណនី លំនាំប្រើប្រាស់ប្រចាំសប្តាហ៍ និងផែនទីកម្ដៅសកម្មភាព។
- **ការនាំចេញ** — ទាញយកចន្លោះពេលបច្ចុប្បន្នជា **CSV** ឬ **JSON** (ប៊ូតុងនឹងបង្ហាញនៅពេលមានទិន្នន័យតម្លៃធំជាងសូន្យ)។

នៅពេលគ្មានចរាចរណ៍ដែលមានតម្លៃ ជួរដេកនឹងបង្ហាញស្លាក "Legacy / Free" ជំនួសឱ្យ `$0` ដោយឆ្លុះបញ្ចាំងពីម៉ូដែលតាមដានការសន្សំ។

> API ថវិកាគឺវិសាលភាពក្នុងមួយ** គ្រាប់ចុច API** (`apiKeyId`) ។ ដែនកំណត់ដែលត្រឡប់ដោយ `GET /api/usage/budget` រួមមាន `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`, a `warningThreshold`, និងចំនួនសរុបដែលកំពុងដំណើរការ (`totalCostToday`, `totalCostMonth`, … )។

## CLI

CLI របស់ OmniRoute ផ្ដល់នូវពាក្យបញ្ជាសម្រាប់ថ្លៃចំណាយ ការប្រើប្រាស់ និងតម្លៃ (ដែលបានចុះឈ្មោះនៅក្នុង
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs))។

### `omniroute cost`

របាយការណ៍ថ្លៃចំណាយដែលបានប្រមូលផ្ដុំពី `/api/usage/analytics`។

```bash
omniroute cost                          # 30d ចុងក្រោយ ដាក់ជាក្រុមតាមអ្នកផ្ដល់សេវា
omniroute cost --period 7d              # 7 ថ្ងៃចុងក្រោយ
omniroute cost --group-by model         # ដាក់ជាក្រុមតាម provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ជួរឈរ៖ ក្រុម ចំនួនសំណើ token ចូល/ចេញ ថ្លៃចំណាយ (USD) និងភាគរយនៃចំនួនសរុប។ បន្ទាត់សរុបរួម
ត្រូវបានបង្ហាញនៅចុងបញ្ចប់ (មិនបង្ហាញនៅពេលប្រើ `--quiet` ឬ `--output json`)។

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # សេចក្ដីសង្ខេបថ្លៃចំណាយតាមអ្នកផ្ដល់សេវានីមួយៗ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ថវិកា
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` អានពី `GET /api/pricing/defaults`។ ដើម្បីកែសម្រួលតម្លៃរបស់ម៉ូដែលនីមួយៗ
> សូមប្រើទំព័រ **តម្លៃ** នៅលើផ្ទាំងគ្រប់គ្រង ឬ `PATCH /api/pricing`។

## ការដោះស្រាយបញ្ហា

- **ថ្លៃចំណាយទាំងអស់បង្ហាញ $0 / "ចាស់ / ឥតគិតថ្លៃ"។** ម៉ូដែលដែលកំពុងប្រើមិនមានធាតុតម្លៃទេ។
  បើកដំណើរការការធ្វើសមកាលកម្មពីខាងក្រៅ (`PRICING_SYNC_ENABLED=true`) ហើយដំណើរការ `omniroute pricing sync` ឬ
  កំណត់តម្លៃដោយដៃតាមរយៈទំព័រតម្លៃ / `PATCH /api/pricing`។
- **ម៉ូដែលពីមុនមួយមានតម្លៃមិនត្រឹមត្រូវ។** កែតម្លៃ (កំណត់ជំនួស ឬធ្វើសមកាលកម្មឡើងវិញ) — ថ្លៃចំណាយត្រូវបាន
  គណនាឡើងវិញពីចំនួន token រាល់ពេលអានទិន្នន័យវិភាគ ដូច្នេះការប៉ាន់ស្មាននឹងធ្វើបច្ចុប្បន្នភាពដល់ទិន្នន័យពីមុន។
- **ការចំណាយមានភាពយឺតយ៉ាវជាងពេលវេលាជាក់ស្ដែង។** ការចំណាយតាម key នីមួយៗត្រូវបានដំណើរការជាបាច់; បន្ថយ
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ប្រសិនបើអ្នកត្រូវការទិន្នន័យថ្មីជាងមុន។
