`@omniroute/opencode-plugin-v2` ដាក់កាតាឡុក OmniRoute ទាំងមូលរបស់អ្នក — ម៉ូដែល, combo និង
auto-combo — ទៅក្នុងកម្មវិធីជ្រើសរើសម៉ូដែលរបស់ OpenCode v2 ព្រមទាំងឈ្មោះបង្ហាញ តម្លៃ និងកូតា
កម្រិតឥតគិតថ្លៃ។

វាជាកញ្ចប់ដាច់ដោយឡែកពី `@omniroute/opencode-plugin` ពីព្រោះ OpenCode v1 និង v2 ផ្ទុក
កម្មវិធីជំនួយតាមកិច្ចសន្យាផ្សេងគ្នា។ ជ្រើសរើសកម្មវិធីជំនួយដែលត្រូវនឹងកំណែសំខាន់របស់ OpenCode របស់អ្នក។ គ្មានអ្វី
ត្រូវបានប្រើរួមគ្នារវាងពួកវាទេ ដូច្នេះការដំឡើងកំណែរបស់មួយមិនបង្ខំឱ្យដំឡើងកំណែរបស់មួយទៀតឡើយ។

## តម្រូវការ

- OpenCode v2។
- OmniRoute gateway ដែលអាចភ្ជាប់បាន (`http://localhost:20128` តាមលំនាំដើម)។
- Node.js 22 ឬ 24។

## ការដំឡើង

បន្ថែមកម្មវិធីជំនួយទៅក្នុង `opencode.json`៖

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

បន្ទាប់មក ម៉ូដែលនឹងបង្ហាញជា `omniroute/<provider>/<model>`។ `providerId` កំណត់បុព្វបទនោះ និង
id របស់ការរួមបញ្ចូលដែល OpenCode ប្រើសម្រាប់រក្សាទុកព័ត៌មានសម្គាល់អត្តសញ្ញាណ។

## ព័ត៌មានសម្គាល់អត្តសញ្ញាណ

កម្មវិធីជំនួយស្វែងរក gateway key នៅកន្លែងបី តាមលំដាប់ដូចខាងក្រោម៖

1. **ព័ត៌មានសម្គាល់អត្តសញ្ញាណដែលអ្នកបានភ្ជាប់ក្នុង OpenCode។** កម្មវិធីជំនួយចុះឈ្មោះការរួមបញ្ចូល ដូច្នេះ
   លំហូរផ្ទៀងផ្ទាត់អត្តសញ្ញាណផ្ទាល់របស់ OpenCode អាចរក្សាទុក key បាន។ គ្មានអ្វីត្រូវបានដាក់ក្នុង `opencode.json` ទេ — គួរជ្រើសរើសវិធីនេះ។
2. `apiKey` ក្នុងជម្រើសកម្មវិធីជំនួយ សម្រាប់ការកំណត់ជាន់លើតាមគម្រោងនីមួយៗ។ វាដាក់ key ក្នុងឯកសារដែលអ្នក
   អាចនឹង commit។
3. `OMNIROUTE_API_KEY` ក្នុង environment។

ប្រសិនបើគ្មានទាំងបីទេ កាតាឡុកនឹងទទេ ហើយកម្មវិធីជំនួយនឹងជូនដំណឹងម្តងនៅពេលចាប់ផ្តើម ជំនួសឱ្យ
ការទុកឱ្យអ្នកប្រើកម្មវិធីជ្រើសរើសទទេដោយគ្មានការជូនដំណឹង។

### Management token គឺជា key ផ្សេង

Combo, ស្ថានភាពរបស់ provider និងការបន្ថែមទិន្នន័យ (ឈ្មោះបង្ហាញ តម្លៃ និងកូតាកម្រិតឥតគិតថ្លៃ) មកពី
endpoint `/api/*` របស់ gateway ដែលក្នុងការដាក់ឱ្យប្រើប្រាស់ភាគច្រើន ត្រូវបានការពារដោយ **management** token
ជំនួសឱ្យ inference key៖

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

បើមិនបានកំណត់ `managementReadToken` វានឹងត្រឡប់ទៅប្រើ `apiKey`។ នៅពេល gateway បដិសេធការប្រើជំនួសនេះ
កាតាឡុកនៅតែត្រូវបានចេញផ្សាយ ប៉ុន្តែមានតែ model id ដើម ជំនួសឱ្យឈ្មោះបង្ហាញ ដោយគ្មានការលុប alias ស្ទួនតាម canonical
គ្មានតម្លៃ និងគ្មាន combo។ កម្មវិធីជំនួយព្រមានម្តងក្នុងមួយ endpoint នៅពេលវាកើតឡើង
ដោយបញ្ជាក់ឈ្មោះ endpoint និងអ្វីដែលបានបាត់បង់ — ដូច្នេះកម្មវិធីជ្រើសរើសដែលដំណើរការមិនពេញលេញនឹងមិនក្លាយជាបញ្ហាដែលគ្មានមូលហេតុច្បាស់លាស់ឡើយ។

## របៀបដែលកាតាឡុកនៅតែស្រស់

កាតាឡុកត្រូវបានទាញយកដោយខ្ជិល និងទុកក្នុងឃ្លាំងសម្ងាត់សម្រាប់ `modelCacheTtlMs` ហើយរូបថតថាសរក្សាកាតាឡុកដែលគេស្គាល់ចុងក្រោយដែលមាននៅពេលច្រកផ្លូវមិនអាចទៅដល់ — ការដាច់មិនចំណាយអ្វីក្រៅពីភាពស្រស់ស្អាត។ ម៉ូដែល និងបន្សំត្រូវបានបោះពុម្ពផ្សាយភ្លាមៗនៅពេលពួកគេមកដល់។ បន្សំស្វ័យប្រវត្តិ បញ្ជីអ្នកផ្តល់សេវា និងការត្រួតលើគ្នានៃការពង្រឹងបន្ថែមនៅពេលពួកគេចុះចត ដូច្នេះចំណុចបញ្ចប់យឺតមួយមិនអាចចាប់ចំណាប់ខ្មាំងអ្នកជ្រើសរើសទាំងមូលបានទេ។

ឈ្មោះធ្វើតាម `Provider - Model[ (Editor)][ · budget][ (route)]`: អ្នកផ្តល់សេវាត្រូវបានបង្ហាញនៅពេលណាដែលលេខសម្គាល់មានលេខសម្គាល់មួយ (លេខសម្គាល់ដែលបង្ហាញដោយសញ្ញាតិចដោយគ្មានបុព្វបទ) `🆓` នាំមុខគេសម្គាល់ធាតុឥតគិតថ្លៃ ហើយថវិកាថ្នាក់ឥតគិតថ្លៃរបស់ពួកគេនៅតែជាបច្ច័យ `· 1M tokens/month` អ្នកកែសម្រួលឈ្មោះ `Editor: Model` ច្បាស់លាស់ផ្លាស់ទីទៅវង់ក្រចកបន្តបន្ទាប់គ្នា (គ្មានកម្មវិធីនិពន្ធឈ្មោះ `combo - <slug>` ត្រូវបានទាយដោយសេរី និងគ្មានការទាយ) រូបតំណាង។ ធាតុពីរដែលចែករំលែកឈ្មោះមួយទទួលបានបច្ច័យផ្លូវ — `(no-think)` — ដូច្នេះពួកវាអាចបែងចែកបាន។ `providerTag` ( `true` លំនាំដើម) បិទបើកវង់ក្រចកកម្មវិធីនិពន្ធបន្ទាប់។

មិនមានពាក្យបញ្ជាធ្វើឱ្យស្រស់ដោយដៃទេ៖ ពាក្យបញ្ជា OpenCode v2 គឺជាគំរូប្រអប់បញ្ចូល មិនមែនជាការហៅត្រឡប់មកវិញទេ ដូច្នេះកម្មវិធីជំនួយមិនអាចបង្ហាញវាបានទេ។ ធ្វើឱ្យស្រស់ធ្វើតាម TTL; ម៉ាស៊ីនត្រូវបានស្នើឱ្យផ្ទុកឡើងវិញតែនៅពេលដែលកាតាឡុក ឬការត្រួតគ្នាពិតជាបានផ្លាស់ប្តូរ មិនដែលម្តងក្នុងការធ្វើឱ្យស្រស់។

## ការហៅ tool នៅលើ Gemini

Gemini បដិសេធ request ទាំងមូល ប្រសិនបើសេចក្តីប្រកាស tool របស់វាមាន `$schema` ឬ
`additionalProperties` ដោយឆ្លើយតបជា `400 INVALID_ARGUMENT`។ plugin នឹងដក keyword ទាំងនោះចេញពី
schema របស់ tool ដែលត្រូវបញ្ជូនទៅម៉ូដែល Gemini របស់ provider នេះ ហើយទុក request ផ្សេងទៀតទាំងអស់ឱ្យនៅដដែល។
tool ដែលមាន `$ref` នឹងត្រូវបានបញ្ជូនបន្តដោយមិនកែប្រែ ជាជាងដកវាចេញ ពីព្រោះការដក
reference នោះនឹងពង្រីក schema ឱ្យ "ទទួលយកអ្វីក៏បាន"។
កំណត់ `"geminiSanitization": false` ដើម្បីបិទមុខងារនេះ។
