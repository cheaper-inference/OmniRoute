កិច្ចសន្យា `config/cli-tools-manifest.json` អព្យាក្រឹតប្រកាស IDs canonical, ឈ្មោះក្លែងក្លាយ, បេក្ខជនគោលពីរ, រូបមន្តរៀបចំ អាគុយម៉ង់គំរូ និងសមត្ថភាព។ អាដាប់ទ័រ Node ធម្មតានៅក្នុង `bin/cli/cli-manifest.mjs` និងអាដាប់ទ័រ TypeScript ក្នុង `src/shared/constants/cliIntegrationManifest.ts` អានឯកសារដូចគ្នា។ ពេលវេលាដំណើរការ កាតាឡុក កំណត់រចនាសម្ព័ន្ធ ការបញ្ចប់ ម៉ាស៊ីនភ្លើង និងការចុះឈ្មោះកម្មវិធីខាងក្រោយត្រូវបានត្រួតពិនិត្យរួមគ្នាដោយ `tests/unit/cli/cli-manifest-drift.test.ts`។ ការដាក់កាតាឡុកមិនមានន័យថាឧបករណ៍អាចត្រូវបានបើកដំណើរការ ឬកំណត់រចនាសម្ព័ន្ធនោះទេ។ ជាពិសេស 5dive នៅតែកំណត់រចនាសម្ព័ន្ធតែប៉ុណ្ណោះ។

## បរិស្ថានកុមារ និងវដ្តជីវិត

`omniroute run`, `omniroute launch` និង `omniroute launch-codex` ទទួលមរតកបញ្ជីអនុញ្ញាតភាពឆបគ្នា OS/terminal ហើយបញ្ចូលព័ត៌មានសម្គាល់គោលដៅដែលបានជ្រើសរើស។ អ្នកផ្តល់សេវាដែលមិនទាក់ទង និងអាថ៌កំបាំងនៃមូលដ្ឋានទិន្នន័យមិនត្រូវបានទទួលមរតកតាមលំនាំដើមទេ។ `--inherit-env` ស្ដារឡើងវិញនូវមរតកមាតាបិតាពេញលេញឡើងវិញ; ប្រើវាតែនៅពេលដែលដំណើរការភាគីទីបីដែលបានជ្រើសរើសគួរតែទទួលបានតម្លៃទាំងនោះ។ នេះគឺជាការត្រងបរិស្ថាន មិនមែនជាប្រអប់ខ្សាច់ OS ៖ ដំណើរការនៅតែដំណើរការដោយមានការអនុញ្ញាតប្រព័ន្ធឯកសាររបស់អ្នកហៅចូល។

សញ្ញារំខាន និងការបញ្ចប់ត្រូវបានបញ្ជូនបន្តទៅកុមារ។ កម្មវិធីបើកដំណើរការរង់ចាំព្រឹត្តិការណ៍ជិតស្និទ្ធរបស់កុមារ មុនពេលដកចេញការកំណត់បណ្តោះអាសន្ន។ `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` គ្រប់គ្រងរយៈពេលអនុគ្រោះ មុនពេលការបញ្ចប់ដោយបង្ខំ (លំនាំដើម 5000 មិល្លីវិនាទី)។

## Gemini ការដំឡើងជាប់លាប់

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

ពាក្យបញ្ជាពីរដំបូងកំណត់រចនាសម្ព័ន្ធម៉ាស៊ីននេះសម្រាប់ម៉ាស៊ីនមេក្នុងស្រុក ឬពីចម្ងាយដែលបានជ្រើសរើស។ ការដំឡើងរក្សាការកំណត់ JSON ដែលមិនពាក់ព័ន្ធ ជ្រើសរើស Gemini API-key auth ហើយសរសេរចំណុចបញ្ចប់ និងព័ត៌មានសម្ងាត់ទៅឯកសារ `.gemini/.env` ឯកជន។ វាបដិសេធ JSON មិនត្រឹមត្រូវ ជាជាងការសរសេរជាន់លើវា។ ចំណុចបញ្ចប់ URLs ត្រូវតែ HTTP(S) ដោយគ្មានព័ត៌មានបញ្ជាក់អត្តសញ្ញាណ ប៉ារ៉ាម៉ែត្រសំណួរ ឬបំណែក។ ផ្លូវបោះពុម្ពស្ងួត មិនមែនតម្លៃអត្តសញ្ញាណទេ។

`GEMINI_CLI_HOME` ឬ `--gemini-home` ជ្រើសរើសឫសផ្ទះជាប់លាប់។ `run gemini` ពិតប្រាកដបង្កើត ហើយក្រោយមកបានដកផ្ទះបណ្តោះអាសន្នរបស់វាចេញ។ របៀបទាំងពីរមិនឆ្លងកាត់ការត្រួតពិនិត្យកន្លែងធ្វើការ-ទុកចិត្តរបស់ Gemini ទេ។

## ទម្រង់Codex

`configure codex` សរសេរ `<name>.config.toml` ឯកជនជាមួយគំរូមួយ និងចំណុចបញ្ចប់អ្នកផ្តល់សេវា OmniRoute របស់វា។ លិខិតសម្គាល់ត្រូវបានយោងតាមរយៈ `OMNIROUTE_API_KEY` ដែលមិនដែលត្រូវបានបង្កប់។ ពាក្យបញ្ជាបើកដំណើរការកំណត់ម៉ូដែលដែលបានជ្រើសរើសនៅគ្រាប់ចុច `model` កម្រិតកំពូល មិនមែននៅខាងក្នុង `model_providers` ទេ។

ឯកសារទម្រង់ដាច់ដោយឡែកគឺជាកិច្ចសន្យា Codex ដែលបានចងក្រងបច្ចុប្បន្ន។ ពួកគេត្រួតលើការកំណត់រចនាសម្ព័ន្ធអ្នកប្រើប្រាស់នៅពេលជ្រើសរើសជាមួយ `codex --profile <name>`។ សូមមើល [ឯកសារយោងទម្រង់ផ្លូវការ](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) និង [ការណែនាំ OmniRoute Codex](./CODEX-CLI-CONFIGURATION.md) ។

## ការប្រតិបត្តិពាក្យបញ្ជា Hermetic

ជាមួយនឹង `DATA_DIR` ច្បាស់លាស់ ការកំណត់ `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` ការពារការចាប់ផ្តើមពីការធ្លាក់ចូលទៅក្នុងបរិស្ថានកំណត់អត្តសញ្ញាណរបស់ថតទិន្នន័យអ្នកប្រើប្រាស់លំនាំដើម។ វាមានប្រយោជន៍សម្រាប់ការធ្វើតេស្តដាច់ដោយឡែក។ វាមិនបិទឯកសារបរិស្ថានដែលបានជ្រើសរើសយ៉ាងច្បាស់លាស់ផ្សេងទៀតទេ។

## ថតការងារ `.env`

CLI អានឯកសារ `.env` ក្នុងលំដាប់នេះ ហើយឯកសារដំបូងដែលកំណត់គន្លឹះឈ្នះ៖ `DATA_DIR` ច្បាស់លាស់ ថតទិន្នន័យលំនាំដើម ថតការងារបច្ចុប្បន្ន បន្ទាប់មកថតកញ្ចប់។ អថេរសែលតែងតែឈ្នះ។

ថតការងារអាចជារបស់នរណាម្នាក់ផ្សេងទៀត (ឃ្លាំងក្លូន បណ្ណសារដែលមិនបានខ្ចប់) ហើយ `omniroute serve` បញ្ជូនបរិស្ថាន CLI ទៅម៉ាស៊ីនមេ និងគ្រប់ឧបករណ៍ដែលម៉ាស៊ីនមេដំណើរការ។ ដូច្នេះ `.env` នៅទីនោះអាចកំណត់តែគ្រាប់ចុចទាំងនេះប៉ុណ្ណោះ ដែលរាយក្នុង `bin/cli/utils/untrustedCwdEnv.mjs`:

| សោ                              | តម្លៃដែលទទួលយក                                                       |
| ------------------------------- | -------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` ឬ `yes` ក្នុងករណីណាក៏ដោយ តម្លៃដែលម៉ាស៊ីនមេចាត់ទុកដូចនៅលើ |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | រហូតដល់ 64 អក្សរ, ខ្ទង់, `_`, `.`, `@` ឬ `-`                         |
| `LANGUAGE`                      | ដូចគ្នា បូក `:`                                                      |
| `TZ`                            | រហូតដល់ 64 អក្សរ, ខ្ទង់, `_`, `+`, `-` ឬ `/`, មិនចាប់ផ្តើមជាមួយ `/`  |
| `NO_COLOR`, `FORCE_COLOR`       | រហូតដល់ ១៦ អក្សរ និងខ្ទង់                                            |

រាល់តម្លៃ `REQUIRE_API_KEY` ទទួលយកបើកការត្រួតពិនិត្យ ដូច្នេះឯកសារមិនអាចបិទការឆែកឆេរដោយខ្លួនវាបានទេ។ វាមិនសម្រេចលទ្ធផលទេ ទោះបីជា៖ ម៉ាស៊ីនមេអានការបដិសេធ `REQUIRE_API_KEY` ដែលរក្សាទុកក្នុងមូលដ្ឋានទិន្នន័យមុនពេលបរិស្ថាន ខណៈពេលដែលការព្រមានពេលចាប់ផ្ដើមអំពីការស្តាប់នៅលើចំណុចប្រទាក់ទាំងអស់ដោយគ្មានគ្រាប់ចុច API អានតែបរិស្ថានប៉ុណ្ណោះ។ ជាមួយនឹងការបដិសេធដែលបានរក្សាទុកនៃ `false` ថតការងារ `REQUIRE_API_KEY=true` ទុក API បើក ហើយលាក់ការព្រមាននោះ។ ច្បាប់ `TZ` តូចចង្អៀតជាង POSIX៖ វាបដិសេធ `.`, `:`, `,` និង `<>` ដូច្នេះទម្រង់ និងច្បាប់ `:Area/City` ដូចជា `EST5EDT,M3.2.0,M11.1.0` ត្រូវតែកំណត់ក្នុងសែល ឬ `<DATA_DIR>/.env`។

ឈ្មោះត្រូវតែផ្គូផ្គងយ៉ាងពិតប្រាកដ ជាអក្សរធំ។ បន្ទាត់ណាមួយផ្សេងទៀត តម្លៃដែលបរាជ័យក្នុងការត្រួតពិនិត្យរបស់វា និងឈ្មោះដែលមិនមែនជាអក្សរ ASCII ធម្មតា ខ្ទង់ និង `_` (ឧទាហរណ៍មួយជាមួយ NUL byte ឬអក្សរដែលមើលទៅដូចគ្នា) ត្រូវបានរំលង។ CLI បោះពុម្ពការព្រមានមួយដែលដាក់ឈ្មោះកូនសោដែលវាមិនអាចកំណត់បាន និងមួយដែលដាក់ឈ្មោះដែលអនុញ្ញាតឱ្យគ្រាប់ចុចដែលវាមិនអើពើ ដោយនីមួយៗមានអ្វីត្រូវផ្លាស់ប្ដូរ (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`) ។ ក៏មិនបោះពុម្ពតម្លៃដែរ។ ផ្លូវឯកសារនៅក្នុងសារទាំងនេះ និងរបាយការណ៍ `.env` ផ្លូវ `omniroute doctor` ត្រូវបានរត់គេចនៅពេលដែលពួកវាមានតួអក្សរគ្រប់គ្រង ឬ bidi ។ ការដាក់កំហិតមិនអនុវត្តនៅពេលដែលថតការងារគឺជាថតទិន្នន័យ ឬថតកញ្ចប់។

`PORT`, `API_PORT` និង `DASHBOARD_PORT` មិនមាននៅក្នុងបញ្ជីទេ។ ដោយគ្មាន URL មូលដ្ឋានពីប្រភពដែលមានអាទិភាពខ្ពស់ CLI និយាយទៅកាន់ `localhost:<PORT>` ហើយអ្វីក៏ដោយដែលស្តាប់នៅទីនោះទទួលបានសោ API របស់ CLI និមិត្តសញ្ញាបរិបទ និងនិមិត្តសញ្ញាម៉ាស៊ីន CLI (`x-omniroute-cli-token` សូមមើល [CLI_TOKEN.md](../security/CLI_TOKEN.md) ) ដែលម៉ាស៊ីនមេក្នុងស្រុកទទួលយកសម្រាប់ការហៅពីការគ្រប់គ្រងរង្វិលជុំ។ ច្រកចេញពីថតឯកសារនឹងអនុញ្ញាតឱ្យឯកសារនោះជ្រើសរើសអ្នកស្តាប់ ដូច្នេះកំណត់ច្រកនៅក្នុងសែល ជា `<DATA_DIR>/.env` ឬជាមួយជម្រើស `--port` នៃពាក្យបញ្ជាដែលមានមួយ (`serve`, `launch`, `run`) ។

ឧបករណ៍ញែកមិនមានវាក្យសម្ព័ន្ធ `export` ទេ។ បន្ទាត់ដូចជា `export LD_PRELOAD=...` ដាក់ឈ្មោះ `export LD_PRELOAD` អថេរ ; ពីថតការងារវាត្រូវបានរំលង ហើយនៅក្នុងឯកសារ `.env` ផ្សេងទៀតវាកំណត់ឈ្មោះព្យញ្ជនៈនោះ ដែលគ្មានអ្វីអានទេ។

CLI ផ្គូផ្គងនិមិត្តសញ្ញាដែលបានរក្សាទុករបស់បរិបទ (សញ្ញាសម្ងាត់ចូលប្រើ ឬគន្លឹះ API កេរ្តិ៍ដំណែល) តែជាមួយប្រភពដើមផ្ទាល់នៃបរិបទនោះប៉ុណ្ណោះ៖ គ្រោងការណ៍ ម៉ាស៊ីន និងច្រក ប្រៀបធៀបជា `URL.origin`។ នេះអនុវត្តចំពោះសំណើដែលបានធ្វើឡើងតាមរយៈម៉ាស៊ីនភ្ញៀវ HTTP របស់ CLI(`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) និងពាក្យបញ្ជា `launch`, `launch codex`, `configure` និង `setup-*` ដែលសរសេរ URL មូលដ្ឋាន និងសោចូលទៅក្នុងការកំណត់របស់ឧបករណ៍ផ្សេងទៀត។ ចង្អុលទៅម៉ាស៊ីនមេផ្សេងទៀតជាមួយ `--remote` ពួកគេប្រើ `--api-key` ឬ `OMNIROUTE_API_KEY` ច្បាស់លាស់ ប្រសិនបើវាត្រូវបានកំណត់ ហើយគ្មានសញ្ញាសម្ងាត់បរិបទទេ។ ការប្រៀបធៀបគឺពិតប្រាកដ ដូច្នេះ `localhost` និង `127.0.0.1` ឬម៉ាស៊ីនដែលមាន និងគ្មានចំណុចបន្ទាប់ រាប់ជាម៉ាស៊ីនមេផ្សេងគ្នា ហើយមិនទទួលបាននិមិត្តសញ្ញាបរិបទទេ។ URL ជាមួយ userinfo, backslash ឬ whitespace មិនដែលផ្គូផ្គងគ្នាទេ ព្រោះឧបករណ៍ញែក URL ផ្សេងទៀត (ឧទាហរណ៍ `urllib` និង `httpx` របស់ Python) អាចអាន host ផ្សេងពីវា។ សម្រាប់សំណើដែល CLI ផ្ញើដោយខ្លួនវា ការត្រួតពិនិត្យនោះគ្របដណ្តប់តែគ្រោងការណ៍ និងសិទ្ធិអំណាច ដូច្នេះលេខសម្គាល់ដែលមានចន្លោះនៅក្នុងផ្លូវ ឬសំណួររក្សាសញ្ញាសម្ងាត់។
