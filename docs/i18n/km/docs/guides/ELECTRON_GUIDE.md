## ស្ថាបត្យកម្ម

```
┌──────────────────────────────────────────────┐
│ Electron main process (electron/main.js)     │
│ ├─ Single-instance lock                       │
│ ├─ Child process: Next.js standalone server  │
│ │   (spawned with Electron's Node runtime)   │
│ ├─ BrowserWindow → http://localhost:PORT     │
│ ├─ System tray + context menu                │
│ ├─ Auto-update via electron-updater          │
│ ├─ Content Security Policy (session headers) │
│ └─ Secret bootstrap (JWT / API_KEY_SECRET)   │
└──────────────────────────────────────────────┘
            ↕ IPC bridge (electron/preload.js)
┌──────────────────────────────────────────────┐
│ Renderer (Next.js dashboard)                  │
│   window.electronAPI.* (contextIsolation)     │
└──────────────────────────────────────────────┘
```

## កញ្ចប់ពេលវេលាដំណើរការស្រេចចិត្ត

ការបង្កើតលើកុំព្យូទ័រអាចបោះផ្សាយប័ណ្ណសារពេលដំណើរការស្រេចចិត្តជាមួយនឹងកម្មវិធីដំឡើងរបស់ពួកគេ។ ការផ្ទុកម៉ាស៊ីនមេដែលបានដំឡើងមាន `optional-packs.index.json` (ក្រោម `resources/app` នៅលើ Windows និង Linux) ។ សម្រាប់ធាតុ `browser-runtime` សូមអាន `packs[].tarball` និងទាញយក** ឈ្មោះឯកសារពិតប្រាកដនោះពីការចេញផ្សាយដូចគ្នា។** . ឈ្មោះបណ្ណសាររួមមាន SHA-256 digest; ការបង្កើតផ្សេងៗគ្នាអាចទាមទារបណ្ណសារផ្សេងៗគ្នា។ រក្សាឈ្មោះឯកសារដែលបានទាញយកមិនផ្លាស់ប្តូរ។

ចម្លងលិបិក្រមកម្មវិធីដែលបានដំឡើង និងប័ណ្ណសារដែលបានជ្រើសរើសទៅក្នុងថតតែមួយ បន្ទាប់មកប្រើ CLI ពីការចេញផ្សាយដូចគ្នា៖

```bash
omniroute packs list --source /path/to/packs
omniroute packs install browser-runtime --source /path/to/packs
```

`packs list` បង្ហាញស្ថានភាពដំឡើង និងផ្ទៀងផ្ទាត់ មិនមែនជាឈ្មោះឯកសារក្នុងប័ណ្ណសារទេ។ លិបិក្រមដែលបានបាច់ជ្រើសរើសប័ណ្ណសារ។ ការដំឡើងផ្ទៀងផ្ទាត់ការពិនិត្យប័ណ្ណសាររបស់វាមុនពេលស្រង់ចេញ និងពិនិត្យកញ្ចប់របស់វាមុនពេលជំនួសកញ្ចប់ដែលបានដំឡើង។ វាអានឯកសារក្នុងស្រុក; វាមិនទាញយកបណ្ណសារដែលបាត់ទេ។ ចាប់ផ្តើមកម្មវិធីឡើងវិញបន្ទាប់ពីដំឡើង។ ប្រសិនបើការចេញផ្សាយមិនមានទ្រព្យសកម្មដែលត្រូវគ្នានោះកញ្ចប់ជម្រើសគឺមិនមានតាមរយៈទ្រព្យសម្បត្តិនៃការចេញផ្សាយនោះ។

## ស្ពាន IPC (`preload.js`)

ការផ្ទុកជាមុនបង្ហាញ API បញ្ជីសនៅលើ `window.electronAPI` ដោយប្រើ `contextBridge` ជាមួយ `contextIsolation: true` និង `nodeIntegration: false`។

```javascript
const VALID_CHANNELS = {
  invoke: [
    "get-app-info",
    "open-external",
    "get-data-dir",
    "restart-server",
    "check-for-updates",
    "download-update",
    "install-update",
    "get-app-version",
  ],
  send: ["window-minimize", "window-maximize", "window-close"],
  receive: ["server-status", "port-changed", "update-status"],
};
```

វិធីសាស្រ្តបង្ហាញ៖

| ការហៅអ្នកបង្ហាញ                                                   | ប្រភេទ                       |
| ----------------------------------------------------------------- | ---------------------------- |
| `getAppInfo()` → `{ name, version, platform, isDev, port }`       | អំពាវនាវ                     |
| `openExternal(url)`                                               | អំពាវនាវ                     |
| `getDataDir()`                                                    | អំពាវនាវ                     |
| `restartServer()`                                                 | អំពាវនាវ                     |
| `getAppVersion()`                                                 | អំពាវនាវ                     |
| `checkForUpdates()` / `downloadUpdate()` / `installUpdate()`      | អំពាវនាវ                     |
| `minimizeWindow()` / `maximizeWindow()` / `closeWindow()`         | ផ្ញើ                         |
| `onServerStatus(cb)` / `onPortChanged(cb)` / `onUpdateStatus(cb)` | ទទួល (អ្នកបោះចោលត្រឡប់មកវិញ) |

អ្នកទទួលជំនួយត្រឡប់ ក** មុខងារបោះចោល** ជាជាងការពឹងផ្អែកលើ `removeAllListeners` — វាការពារការប្រមូលផ្តុំអ្នកស្តាប់ នៅពេលដែលសមាសធាតុ React ភ្ជាប់ឡើងវិញ។

## វដ្តជីវិតរបស់ម៉ាស៊ីនមេ

`main.js` បង្កើតបណ្តុំ Next.js standalone ដោយផ្ទាល់ជាមួយ Electron Node runtime ដើម្បីជៀសវាងការមិនស៊ីគ្នានៃម៉ូឌុល ABI ដើមជាមួយ Node ប្រព័ន្ធ៖

```js
spawn(process.execPath, [serverScript], {
  cwd: NEXT_SERVER_PATH,
  env: { ...serverEnv, PORT, NODE_ENV: "production", ELECTRON_RUN_AS_NODE: "1", NODE_PATH },
  stdio: "pipe",
});
```

រំលេច៖

- `waitForServer()` ស្ទង់មតិ URL រហូតដល់ 30 វិនាទី មុនពេលបង្ហាញបង្អួច (គ្មានអេក្រង់ទទេនៅពេលចាប់ផ្តើមត្រជាក់)។
- `stdio: "pipe"` ចាប់យក stdout/stderr; ប្រយោគត្រៀមខ្លួន (`Ready` / `listening`) បញ្ចេញ `server-status: running` លើ IPC។
- `before-quit` រង់ចាំរហូតដល់ 5 វិនាទីសម្រាប់ SIGTERM ដ៏ល្អ (WAL checkpoint) បន្ទាប់មកផ្ញើ SIGKILL។
- ឧបករណ៍ប្តូរច្រកក្នុងថាស (`20128`, `3000`, `8080`) ឈប់ និងចាប់ផ្តើមម៉ាស៊ីនមេឡើងវិញ បន្ទាប់មកផ្ទុក BrowserWindow ឡើងវិញ។

## Zero-config Secret Bootstrap

នៅពេលបើកដំណើរការលើកដំបូង ដំណើរការចម្បងបង្កើតដោយស្វ័យប្រវត្តិ ហើយបន្តបាត់អាថ៌កំបាំង៖

| សម្ងាត់                  | ប្រភព                                                                            |
| ------------------------ | -------------------------------------------------------------------------------- |
| `JWT_SECRET`             | `crypto.randomBytes(64).toString("hex")`                                         |
| `STORAGE_ENCRYPTION_KEY` | `crypto.randomBytes(32).toString("hex")` (បដិសេធប្រសិនបើបានអ៊ិនគ្រីបក្រេបរួចហើយ) |
| `API_KEY_SECRET`         | `crypto.randomBytes(32).toString("hex")`                                         |

តស៊ូដើម្បី `<DATA_DIR>/server.env`។ `DATA_DIR` ដោះស្រាយទៅ៖

- Windows: `%APPDATA%\omniroute`
- Linux: `$XDG_CONFIG_HOME/omniroute` ឬ `~/.omniroute`
- macOS: `~/.omniroute`

## រកមើលឯកសារបរិស្ថាន

មុនពេលបង្កើតម៉ាស៊ីនមេ ដំណើរការចម្បង (`getPreferredEnvFilePath()` in `electron/main.js`) ជ្រើសរើស** មួយ។** `.env` ឯកសារ៖ ដំបូងបង្អស់ដែលមាន។

1. `$DATA_DIR/.env` នៅពេលដែល `DATA_DIR` ត្រូវបានកំណត់នៅក្នុងបរិស្ថានកម្មវិធីត្រូវបានបើកដំណើរការជាមួយ។
2. `<resolved DATA_DIR>/.env` ដោយប្រើលំនាំដើមដូចខាងលើ៖ `%APPDATA%\omniroute\.env` នៅលើ Windows `$XDG_CONFIG_HOME/omniroute/.env` ឬ `~/.omniroute/.env` នៅលើ Linux និង macOS។
3. `.env` នៅក្នុងថតដំណើរការដំណើរការ។

ដំណើរការចម្បងអានតែឯកសារនោះ; បេក្ខជនក្រោយៗមិនត្រូវបានបញ្ចូលចូលគ្នាទេ។ បរិយាកាសម៉ាស៊ីនមេត្រូវបានបង្កើតឡើងដោយមានអាទិភាពនេះ (ខ្ពស់បំផុតមុនគេ)៖

1. បរិស្ថានដំណើរការ Electron (អថេរទទួលបានពីអ្វីដែលបានបើកដំណើរការកម្មវិធី)។
2. ឯកសារ `.env` ដែលបានជ្រើសរើស។
3. `<DATA_DIR>/server.env` (អាថ៌កំបាំង bootstrap ខាងលើ) ។

បរិយាកាសដំណើរការត្រូវបានចាប់យកនៅពេលដែលកម្មវិធីចាប់ផ្តើម ដូច្នេះប្រព័ន្ធ ឬបរិស្ថានអ្នកប្រើប្រាស់ដែលបានកំណត់ពេលកម្មវិធីកំពុងដំណើរការ (រួមទាំងពេលដែលវាអង្គុយក្នុងថាសបន្ទាប់ពីបង្អួចរបស់វាបិទ) មិនទៅដល់ម៉ាស៊ីនមេទេ រហូតទាល់តែកម្មវិធីត្រូវបានបិទទាំងស្រុង និងដំណើរការឡើងវិញ។ សម្រាប់ប៊ូតុងរត់ដូចជា `CONTEXT_LENGTH_<PROVIDER>` (សូមមើល [អថេរបរិស្ថាន៖ ប្រវែងបរិបទរបស់អ្នកផ្តល់សេវា](../reference/ENVIRONMENT.md#per-provider-context-length-context_length_provider) ) ចូលចិត្តឯកសារ `.env` បន្ទាប់មកបិទទាំងស្រុង (ថាស,** ឈប់** ) ហើយបើកដំណើរការឡើងវិញ។

## គោលការណ៍សុវត្ថិភាពមាតិកា

កំណត់តាមរយៈ `session.defaultSession.webRequest.onHeadersReceived`។ ការណែនាំគួរឱ្យកត់សម្គាល់៖

- `frame-ancestors 'none'`, `object-src 'none'`, `child-src 'none'`
- `connect-src 'self' http://localhost:* http://127.0.0.1:* ws://localhost:* ws://127.0.0.1:* https://*.omniroute.online https://*.omniroute.dev`
- Dev mode បន្ថែម `'unsafe-eval'` ទៅ `script-src` ប៉ុណ្ណោះ។

## ធ្វើបច្ចុប្បន្នភាពដោយស្វ័យប្រវត្តិ

ប្រើ `electron-updater` ជាមួយអ្នកផ្តល់ GitHub (`diegosouzapw/OmniRoute`) ។

- `autoDownload = false`, `autoInstallOnAppQuit = true`
- ព្រឹត្តិការណ៍ត្រូវបានបញ្ជូនបន្តទៅអ្នកបង្ហាញតាមរយៈ `update-status` IPC: `checking`, `available`, `not-available`, `downloading` (ជាមួយ `percent`), `downloaded`, `error`
- `installUpdate()` សម្លាប់ម៉ាស៊ីនមេ បន្ទាប់មកហៅ `autoUpdater.quitAndInstall()`
- បានរំលងក្នុងរបៀបអ្នកអភិវឌ្ឍន៍ (`!app.isPackaged`)

## សាងសង់បំពង់

1. `npm run build` → Next.js ឯករាជ្យក្នុង `.next/standalone`។
2. `prepare-electron-standalone.mjs` → ឡើងវិញជាដំណាក់កាលចូលទៅក្នុង `.next/electron-standalone` ហើយសរសេរឡើងវិញនូវផ្លូវដាច់ខាតនៅខាងក្នុង `server.js` + `required-server-files.json` ដូច្នេះបណ្តុំអាចផ្លាស់ប្តូរទីតាំងបាន។
3. `electron-builder` កញ្ចប់ `main.js`, `preload.js`, `node_modules` និង `extraResources: { ../.next/electron-standalone → app }`។

## ការធ្វើតេស្តផ្សែង កញ្ចប់សាងសង់

```bash
npm run electron:smoke:packaged
```

`scripts/dev/smoke-electron-packaged.mjs`:

- ស្វែងរកដោយស្វ័យប្រវត្តិនូវប្រព័ន្ធគោលពីរដែលបានខ្ចប់នៅក្នុង `electron/dist-electron/` សម្រាប់វេទិកាបច្ចុប្បន្ន។
- បើកដំណើរការជាមួយថត `HOME`/`APPDATA`/`XDG_*` ដាច់ដោយឡែក ដូច្នេះវាមិនប៉ះទិន្នន័យអ្នកអភិវឌ្ឍន៍ទេ។
- ការស្ទង់មតិ `http://127.0.0.1:20128/login` សម្រាប់ HTTP 200 ក្នុងរយៈពេល 45 វិនាទី។
- នាឡិកា stderr/stdout សម្រាប់លំនាំគ្រោះថ្នាក់ (`Cannot find module`, `MODULE_NOT_FOUND`, `ERR_DLOPEN_FAILED`, `Failed to start server` ជាដើម)។
- រង់ចាំរយៈពេលរត់មានស្ថេរភាព 2 វិនាទី បន្ទាប់ពីរួចរាល់ បន្ទាប់មកចេញ SIGTERM ហើយរង់ចាំឱ្យច្រកទំនេរ។
- នៅក្នុង CI ឆ្លងកាត់ `--no-sandbox --disable-gpu` ដោយស្វ័យប្រវត្តិ (និង `--disable-dev-shm-usage` នៅលើ Linux) ។

env ត្រួតលើគ្នា៖ `ELECTRON_SMOKE_APP_EXECUTABLE`, `ELECTRON_SMOKE_URL`, `ELECTRON_SMOKE_TIMEOUT_MS`, `ELECTRON_SMOKE_SETTLE_MS`, `ELECTRON_SMOKE_DATA_DIR`, `ELECTRON_SMOKE_KEEP_DATA`, `ELECTRON_SMOKE_STREAM_LOGS`។

## ការចុះហត្ថលេខាលើលេខកូដ

`electron/package.json` ធ្វើ** ទេ។** ការចុះហត្ថលេខាលើអត្តសញ្ញាណប័ណ្ណដោយផ្ទាល់។ បញ្ជូនពួកគេតាមរយៈ env vars ទៅ `electron-builder`:

### macOS

```bash
export APPLE_ID=<email>
export APPLE_APP_SPECIFIC_PASSWORD=<password>
export APPLE_TEAM_ID=<id>
export CSC_LINK=path/to/cert.p12
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:mac
```

### Windows

```bash
export CSC_LINK=path/to/cert.pfx
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:win
```

### Linux

ការចុះហត្ថលេខាAppImage គឺជាជម្រើស — កំណត់ `LINUX_GPG_KEY` ប្រសិនបើចុះហត្ថលេខា។
