## ផ្ទាំង

### ផ្ទាំងស្វែងរក

បម្លែង `SearchForm` + `ResultsPanel` + `RerankPanel` ដែលមានស្រាប់ទៅជាផ្ទាំងមួយ៖

- សំណួរ → លទ្ធផល (ចំណងជើង, URL, សេចក្តីសង្ខេប, ពិន្ទុភាពពាក់ព័ន្ធ)។
- មេតាទិន្នន័យរបស់អ្នកផ្តល់សេវានៅក្នុងផ្ទាំងកំណត់រចនាសម្ព័ន្ធ (តម្លៃ, កូតា, ស្ថានភាព)។
- ផ្នែករៀបលំដាប់ឡើងវិញ៖ ជ្រើសរើសម៉ូដែលរៀបលំដាប់ឡើងវិញ, រៀបលំដាប់លទ្ធផលឡើងវិញ, បង្ហាញ `positionDelta`។
- ស្ថានភាពទទេដែលមាន CTA នៅពេលមិនទាន់បានកំណត់រចនាសម្ព័ន្ធអ្នកផ្តល់សេវាស្វែងរក។
- ប្រវត្តិស្វែងរកតាមរយៈ `SearchHistory.tsx`។
- ហៅ `POST /v1/search` (endpoint ដែលមានស្រាប់ ដោយគ្មានការផ្លាស់ប្តូរ)។

### ផ្ទាំងទាញយកទិន្នន័យ

ផ្ទាំងថ្មីសម្រាប់ស្រង់មាតិកាពី URL តាមរយៈ `POST /v1/web/fetch` (បានបង្កើតក្នុងផែនការ 05)៖

- ទិន្នន័យបញ្ចូល៖ URL + ប៊ូតុងបិទបើកសម្រាប់ទំព័រពេញ + ឧបករណ៍ជ្រើសរើសទម្រង់ (markdown / អត្ថបទ / HTML)។
- ដាក់ស្នើ → ទាញយក → បង្ហាញ `ScrapeResult.tsx`។
- `ScrapeResult` បង្ហាញការមើលជាមុននៃ markdown + ប៊ូតុងបិទបើកសម្រាប់មើលទិន្នន័យដើម។
- ដែនកំណត់៖ ប្រសិនបើតួការឆ្លើយតប > **256 KB** នោះ UI បង្ហាញ `(បានកាត់ខ្លី, មើលទិន្នន័យដើម)` ហើយបើកទិន្នន័យដើមក្នុងម៉ូឌែល Monaco (D21)។
- ផ្ទាំងមេតាទិន្នន័យ៖ អ្នកផ្តល់សេវា (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search), រយៈពេលឆ្លើយតប, តម្លៃ, ទំហំការឆ្លើយតប, ចំនួនតំណ។
- ប្រើ hook `useScrapeFetch.ts`។

### ផ្ទាំងប្រៀបធៀប

ដំណើរការសំណួរ/URL ដូចគ្នាជាមួយអ្នកផ្តល់សេវារហូតដល់ **4 នាក់ក្នុងពេលដំណាលគ្នា** (D22)៖

- ជួរឈរដាក់ក្បែរគ្នាសម្រាប់អ្នកផ្តល់សេវានីមួយៗ។
- រង្វាស់៖ រយៈពេលឆ្លើយតប, តម្លៃ, ចំនួនលទ្ធផល, ទំហំការឆ្លើយតប។
- ការគណនាភាពត្រួតគ្នានៃ URL សម្រាប់ការស្វែងរក (ចំនួន URL ដែលរួមគ្នា ធៀបនឹងលទ្ធផលដំបូង)។
- ហៅ `POST /v1/search` (ការស្វែងរក) ឬ `POST /v1/web/fetch` (ការទាញយកទិន្នន័យ) សម្រាប់អ្នកផ្តល់សេវានីមួយៗ។

## ការផ្លាស់ប្តូរ Backend

ត្រូវការការផ្លាស់ប្តូរ backend តែមួយប៉ុណ្ណោះសម្រាប់មុខងារនេះ៖

### `GET /api/search/providers` ដែលបានពង្រីក

`src/app/api/search/providers/route.ts` ត្រូវបានពង្រីកដើម្បី៖

- រួមបញ្ចូល fetch provider ទាំងអស់ (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`) នៅក្នុងអារេ។
- បន្ថែម `kind: "search" | "fetch"` ទៅគ្រប់ធាតុ។
- បន្ថែម `status: "configured" | "missing" | "rate_limited"` ដែលទាញយកពីស្ថានភាពព័ត៌មានសម្គាល់អត្តសញ្ញាណជាក់ស្តែង។
- រក្សាភាពឆបគ្នាជាមួយកំណែមុន — វាលដែលមានស្រាប់ (`id`, `name` ជាដើម) មិនមានការផ្លាស់ប្តូរ។
