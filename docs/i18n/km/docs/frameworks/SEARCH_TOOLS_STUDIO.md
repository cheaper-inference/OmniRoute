## ផ្ទាំង

### ផ្ទាំងស្វែងរក

វិវឌ្ឍន៍ `SearchForm` + `ResultsPanel` + `RerankPanel` ដែលមានស្រាប់ទៅក្នុងផ្ទាំងមួយ៖

- លទ្ធផលសំណួរ → (ចំណងជើង URL អត្ថបទខ្លីៗ ពិន្ទុពាក់ព័ន្ធ)។
- ទិន្នន័យមេតារបស់អ្នកផ្តល់សេវានៅក្នុងផ្ទាំងកំណត់រចនាសម្ព័ន្ធ (តម្លៃ កូតា ស្ថានភាព)។
- ផ្នែកកំណត់ឡើងវិញ៖ ជ្រើសរើសគំរូចំណាត់ថ្នាក់ឡើងវិញ លទ្ធផលលំដាប់ឡើងវិញ បង្ហាញ `positionDelta`។
- ស្ថានភាពទទេជាមួយ CTA នៅពេលដែលគ្មានអ្នកផ្តល់សេវាស្វែងរកត្រូវបានកំណត់រចនាសម្ព័ន្ធ។
- ប្រវត្តិស្វែងរកតាមរយៈ `SearchHistory.tsx`។
- ហៅទៅ `POST /v1/search` (ចំណុចបញ្ចប់ដែលមានស្រាប់ គ្មានការផ្លាស់ប្តូរ)។

### ផ្ទាំងកោស

ផ្ទាំងថ្មីសម្រាប់ទាញយកមាតិកាពី URL តាមរយៈ `POST /v1/web/fetch` (បង្កើតក្នុងផែនការ 05)៖

- ការបញ្ចូល៖ URL + ពេញទំព័របិទបើកឧបករណ៍ជ្រើសរើសទម្រង់ + (markdown / text / HTML) ។
- ដាក់ស្នើ → ទៅយក → render `ScrapeResult.tsx`។
- `ScrapeResult` បង្ហាញ markdown ការមើលជាមុន + បិទបើកឆៅ។
- Cap: ប្រសិនបើរាងកាយឆ្លើយតប >** 256 KB** , UI បង្ហាញ `(truncated, view raw)` និងបើកឆៅក្នុងម៉ូណាកូម៉ូណាកូ (D21)។
- បន្ទះទិន្នន័យមេតា៖ អ្នកផ្តល់សេវា (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search) ភាពយឺតយ៉ាវ ការចំណាយ ទំហំឆ្លើយតប រាប់តំណភ្ជាប់។
- ប្រើទំពក់ `useScrapeFetch.ts` ។

### ប្រៀបធៀបផ្ទាំង

ដំណើរការ query/URL ដូចគ្នាឆ្លងកាត់រហូតដល់** 4 អ្នកផ្តល់សេវាស្របគ្នា។** (D22)៖

- ជួរឈរជាប់គ្នាក្នុងមួយអ្នកផ្តល់សេវា។
- មាត្រដ្ឋាន៖ ភាពយឺតយ៉ាវ ការចំណាយ ការរាប់លទ្ធផល ទំហំឆ្លើយតប។
- URL ការគណនាជាន់គ្នាសម្រាប់ការស្វែងរក (ចំនួន URLs ដែលបានចែករំលែកធៀបនឹងលទ្ធផលដំបូង) ។
- ហៅទៅ `POST /v1/search` (ស្វែងរក) ឬ `POST /v1/web/fetch` (scrape) ក្នុងមួយអ្នកផ្តល់សេវា។

| `kind` | `"search"` (អ្នកផ្តល់សេវា 24 នាក់) ឬ `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search, parallel-search, keenable-search) |

ស្ថានភាពគឺ** ទទួលបាននៅពេលស្នើសុំ** ដោយពិនិត្យមើលថាតើមានព័ត៌មានសម្ងាត់ឬអត់ និងថាតើសោទាំងអស់ស្ថិតក្នុងស្ថានភាពត្រជាក់ឬអត់។

`codex-search` (Codex Web Search) មិនមានសោរបស់វាទេ៖ វាប្រើគណនី Codex (ChatGPT) ដែលបានភ្ជាប់ឡើងវិញ ដូច្នេះការស្វែងរកនីមួយៗចំណាយលើកូតាជាវ ChatGPT ហើយចំណាយពេលប្រហែល 10-40 វិនាទី។ វាដំណើរការនៅពេលសំណើដាក់ឈ្មោះវា; ការជ្រើសរើសដោយស្វ័យប្រវត្តិត្រូវការទង់មុខងារ `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` (បិទតាមលំនាំដើម)។

## ការផ្លាស់ប្តូរផ្នែកខាងក្រោយ

### ពង្រីក `GET /api/search/providers`

`src/app/api/search/providers/route.ts` ត្រូវបានពង្រីកទៅ:

- រួមបញ្ចូលរាល់អ្នកផ្តល់ការទាញយក (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`, `keenable-search`) នៅក្នុងអារេ។
- បន្ថែម `kind: "search" | "fetch"` ទៅធាតុនីមួយៗ។
- បន្ថែម `status: "configured" | "missing" | "rate_limited"` ដែលទទួលបានពីស្ថានភាពអត្តសញ្ញាណបន្តផ្ទាល់។
- រក្សាភាពឆបគ្នាថយក្រោយ — វាលដែលមានស្រាប់ (`id`, `name`, etc.) មិនផ្លាស់ប្តូរ។
