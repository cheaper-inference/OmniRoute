- OmniRoute ពង និងតាមដានពួកវាជាដំណើរការកុមារ
- OmniRoute ចាក់គន្លឹះ API មួយភ្លែតទៅក្នុងបរិយាកាសរបស់កុមារ ហើយបង្វិលវាដោយមិនចាំបាច់ចាំបាច់ (កន្លែងដែលអាចអនុវត្តបាន)
- ផ្លូវគ្រប់គ្រងទាំងអស់ (`/api/services/*`) គឺ**LOCAL_ONLY** — អាចចូលប្រើបានតែពី loopback (ច្បាប់រឹង #17)

### គ្រប់គ្រងស្នូលប្រូកស៊ី

វាលម៉ាស៊ីនប្រូកស៊ីផ្ទាល់ខ្លួនក៏ទទួលយកតំណប្រភព V2Ray ផងដែរ។ ជ្រើសរើស** ប្រអប់ចម្រៀង** ឬ** កាំរស្មីអ៊ិច** យ៉ាងច្បាស់លាស់ បន្ទាប់មកចុច រក្សាទុក។ ការវាយអក្សរមិនដែលទាញយក ឬចាប់ផ្តើមស្នូលទេ។ Save ផ្ទៀងផ្ទាត់បណ្ណសារការចេញផ្សាយជាផ្លូវការ ធ្វើឱ្យការកំណត់រចនាសម្ព័ន្ធដើមមានសុពលភាព ចាប់ផ្តើមកម្មវិធី localhost SOCKS ដាច់ដោយឡែក ហើយគ្រាន់តែសរសេរកិច្ចការចុះបញ្ជីប្រូកស៊ីប៉ុណ្ណោះ។ ការធ្វើឱ្យសកម្មបរាជ័យស្ដារការកំណត់រចនាសម្ព័ន្ធ និងដំណើរការដែលបានគ្រប់គ្រងពីមុន។ `STORAGE_ENCRYPTION_KEY` ត្រូវបានទាមទារ; តំណភ្ជាប់ប្រភពត្រូវបានអ៊ិនគ្រីប។

## 3. ម៉ាស៊ីនស្ថានភាពវដ្តជីវិត

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
             ការស្ទង់សុខភាពជោគជ័យ │         គាំង / SIGTERM      │
                               ┌────▼─────┐  (ចាកចេញក្នុង 5s)   │
                               │ running  │──── គាំង ───────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

ស្ថានភាពត្រូវបានរក្សាទុកក្នុងតារាង DB `version_manager` (ជួរឈរ `status`) និងត្រូវបានឆ្លុះបញ្ចាំង
ក្នុងស្ថានភាពនៅក្នុងអង្គចងចាំរបស់ `ServiceSupervisor`។ ស្ថានភាពនៅក្នុងអង្គចងចាំគឺជាប្រភពដែលមានសិទ្ធិសម្រេចសម្រាប់
ដំណើរការដែលកំពុងរត់ ចំណែកស្ថានភាព DB គឺជាជម្រើសបម្រុងដែលរក្សាទុកបានយូរនៅពេលចាប់ផ្ដើមប្រព័ន្ធ។

### ការផ្លាស់ប្ដូរស្ថានភាព

| ពី              | ព្រឹត្តិការណ៍                        | ទៅ                     |
| --------------- | ------------------------------------ | ---------------------- |
| `not_installed` | `install()` ជោគជ័យ                   | `stopped`              |
| `stopped`       | បានហៅ `start()`                      | `starting`             |
| `starting`      | ការស្ទង់សុខភាពត្រឡប់ 200             | `running`              |
| `starting`      | ដំណើរការចាកចេញមុនពេលមានសុខភាពល្អ     | `error`                |
| `running`       | បានហៅ `stop()`                       | `stopping` → `stopped` |
| `running`       | ដំណើរការចាកចេញដោយមិនបានរំពឹង (< 5 s) | `error` (គាំងរហ័ស)     |
| `running`       | ដំណើរការចាកចេញដោយមិនបានរំពឹង (> 5 s) | `error`                |
| `error`         | បានហៅ `start()`                      | `starting`             |
| ណាមួយ           | `stop()` ខណៈពេល `stopping`           | មិនធ្វើអ្វី            |

### សោប្រតិបត្តិការ

`ServiceSupervisor` រៀបចំប្រតិបត្តិការវដ្តជីវិតឱ្យដំណើរការតាមលំដាប់តាមរយៈសោប្រតិបត្តិការអសមកាល
(`withLock()`)។ ការហៅ `start()` ក្នុងពេលដំណាលគ្នាលើ supervisor ដូចគ្នា នឹងបង្កើតដំណើរការថ្មីតែមួយគត់;
អ្នកហៅទីពីរនឹងរង់ចាំ ហើយត្រឡប់ស្ថានភាពដែលមានស្រាប់។ វាការពារ
លក្ខខណ្ឌប្រណាំង នៅពេលដែលឧទាហរណ៍ ការចាប់ផ្ដើមស្វ័យប្រវត្តិ និងប៊ូតុង UI ត្រូវបានបើកដំណើរការក្នុងពេលដំណាលគ្នា។

### 4.9 ប្រូកស៊ីបញ្ច្រាស (9 Router dashboard បង្កប់)

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

ប្រូកស៊ីនេះ៖

- បញ្ជូនបន្តសំណើទៅ `http://127.0.0.1:{port}/{path}` (រង្វិលជុំត្រឡប់មកវិញតែប៉ុណ្ណោះ)

- ច្រូត `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` ពីការឆ្លើយតប
- សរសេរការឆ្លើយតប HTML ឡើងវិញដើម្បីចាក់ `<base href>` និងធ្វើឱ្យផ្លូវដាច់ខាតធម្មតា (`/foo` → `/dashboard/.../embed/foo`)

ការធ្វើឱ្យប្រសើរ WebSocket សម្រាប់ផ្ទៃតាប្លូដែលបានបង្កប់ត្រូវបានគ្រប់គ្រងដោយម៉ាស៊ីនមេដៃគូនៅលើច្រកជាក់លាក់មួយ (សូមមើល `src/lib/services/embedWsProxy.ts`) ។

## 5. សុវត្ថិភាព

### ការអនុវត្ត LOCAL_ONLY (ច្បាប់តឹងរ៉ឹង #17)

រាល់ route ក្រោម `/api/services/` និង `/dashboard/providers/services/*/embed/` ត្រូវបាន
ចាត់ថ្នាក់ជា LOCAL_ONLY នៅក្នុង `src/server/authz/routeGuard.ts`។ ការត្រួតពិនិត្យ loopback
ដំណើរការដោយគ្មានលក្ខខណ្ឌ មុនពេល auth branch ណាមួយ៖

```
សំណើមកដល់
  → isLocalOnlyPath(path)?
      → មិនមែន loopback → 403 LOCAL_ONLY (ជានិច្ច មុនការត្រួតពិនិត្យ auth)
      → loopback         → បន្តទៅ auth ធម្មតា
```

វារារាំង JWT ដែលបានលេចធ្លាយ (ឧទាហរណ៍ តាមរយៈ tunnel) មិនឱ្យកេះ `npm install` ឬ
ការបង្កើត process។ សូមមើល `docs/security/ROUTE_GUARD_TIERS.md` សម្រាប់ម៉ាទ្រីស
កម្រិតពេញលេញ។

### ការបញ្ចូល API key

9Router និង Mux តម្រូវឱ្យមាន API key/bearer token សម្រាប់ HTTP endpoint របស់ពួកវា។
OmniRoute៖

1. បង្កើត key តាមរយៈ `crypto.randomBytes(32).toString("base64url")` ជាមួយ
   prefix ជាក់លាក់តាម service (`nr_` សម្រាប់ 9Router និង `mx_` សម្រាប់ Mux)។
2. អ៊ិនគ្រីបវាពេលរក្សាទុកដោយប្រើ AES-256-GCM (cipher ដូចគ្នាដែលប្រើសម្រាប់ provider credentials)។
3. ឌិគ្រីប និងបញ្ចូលវាជា environment variable នៅពេលបង្កើត process —
   `NINEROUTER_API_KEY` សម្រាប់ 9Router និង `MUX_SERVER_AUTH_TOKEN` សម្រាប់ Mux (មិនប្រើជា CLI
   flag ឡើយ ដូច្នេះ token មិនដែលបង្ហាញក្នុង `ps`/បញ្ជី process ទេ)។
4. មិនដែលត្រឡប់ plaintext key នៅក្នុង HTTP response ណាមួយទេ។

CLIProxyAPI ទទួលបាន data-plane key ដាច់ដោយឡែក ដែលត្រូវបានបញ្ចូលនៅពេលបង្កើត process
(`needsApiKey: true` — ប្រើសម្រាប់ការធ្វើសមកាលកម្ម model ជាមួយ adapter)។

### ការការពារ SSRF

reverse HTTP proxy (`/dashboard/.../embed/[...path]`) ត្រូវបានកំណត់ជាប់ថា forward
បានតែទៅ `http://127.0.0.1:{port}` ប៉ុណ្ណោះ។ វាមិនដែលធ្វើតាម redirect ទៅកាន់
គោលដៅដែលមិនមែនជា loopback ទេ។ library `ssrf-req-filter` ត្រូវបានប្រើដើម្បីបដិសេធ upstream URL ណាមួយដែល
resolve ទៅក្រៅចន្លោះ loopback។

### សុវត្ថិភាព shell (ច្បាប់តឹងរ៉ឹង #13)

`npm install` ត្រូវបានហៅតាមរយៈ `execFile('npm', ['install', pkg, '--prefix', dir])` —
គ្មាន template literal គ្មាន shell និងគ្មានការធ្វើ interpolation នៃ path ខាងក្រៅទៅក្នុង command
string ទេ។ តម្លៃ runtime (port និង API key) ត្រូវបានបញ្ជូនតាម object `env` របស់ child។

### ការសម្អាត error (ច្បាប់តឹងរ៉ឹង #12)

រាល់ error response ពី `/api/services/*` ឆ្លងកាត់ `buildErrorBody()` ឬ
`sanitizeErrorMessage()`។ `err.stack` និង `err.message` ដើម មិនដែលត្រូវបានត្រឡប់
ដោយផ្ទាល់ទៅអ្នកហៅទេ។

## 6. ការបន្ថែម embedded service ថ្មី

អនុវត្តតាម 8 ជំហានខាងក្រោម។ សូមអាន implementation ដែលមានស្រាប់នៅក្នុង `src/lib/services/installers/`
និង `src/app/api/services/` ជាឯកសារយោងគោល។

### ជំហានទី 1 — បង្កើត installer

បង្កើត `src/lib/services/installers/{name}.ts` ដោយយកលំនាំតាម `ninerouter.ts`៖

```typescript
export const NAME_PACKAGE = "your-npm-package";
export const NAME_DEFAULT_PORT = 20132; // ជ្រើសរើស port ទំនេរមួយ

export async function install(version = "latest"): Promise<InstallResult> { ... }
export async function update(version = "latest"): Promise<InstallResult> { ... }
export async function uninstall(): Promise<void> { ... }

export async function getLatestVersion(): Promise<string | null> { ... }
```

ប្រើ `runNpm(['install', NAME_PACKAGE, '--prefix', dir])` ពី `installers/utils.ts`
— កុំប្រើ `execSync` ឬ shell interpolation ឡើយ។

### ជំហានទី 2 — ចុះឈ្មោះក្នុង bootstrap

បន្ថែម `ServiceEntry` មួយទៅក្នុង array `SERVICES` នៅក្នុង `src/lib/services/bootstrap.ts`៖

```typescript
{
  tool: "myservice",
  port: NAME_DEFAULT_PORT,
  healthPath: "/health",
  healthIntervalMs: 5_000,
  stopTimeoutMs: 15_000,
  logsBufferBytes: 5_242_880,
  needsApiKey: true, // false ប្រសិនបើមិនត្រូវការ API key

```

### ការចាប់ផ្ដើមត្រជាក់យឺត (> 10 វិនាទីដើម្បីឈានដល់ `running`)

3. port អាចកំណត់រចនាសម្ព័ន្ធតាមសេវានីមួយៗក្នុង `bootstrap.ts` តាមរយៈវាល `port`។

4. ប្រសិនបើនៅក្រោយ air-gap សូមទាញយក tarball ជាមុន ហើយប្រើ `npm install /path/to/tarball.tgz`។

### សេវាបង្ហាញស្ថានភាព `"error"` ភ្លាមៗបន្ទាប់ពីចាប់ផ្ដើម (គាំងរហ័ស)

**រោគសញ្ញា:** ស្ថានភាពប្ដូរពី `"starting"` ទៅ `"error"` ក្នុងរយៈពេលក្រោម 5 វិនាទី។
`lastError` បង្ហាញ `"Fast crash (exited with code 1)"`។

**បញ្ជីត្រួតពិនិត្យ:**

1. អានកំណត់ហេតុចុងក្រោយទាំងមូល៖ `GET /api/services/{name}/logs?tail=500`។
2. មូលហេតុទូទៅ៖ ខ្វះអថេរបរិស្ថានដែលសេវាត្រូវការ។
3. សម្រាប់ 9Router៖ ផ្ទៀងផ្ទាត់ថា `NINEROUTER_DISABLE_MITM=true` និង
   `NINEROUTER_DISABLE_TUNNEL=true` ស្ថិតក្នុង env ដែលបានបញ្ជូននៅពេល spawn (សូមមើល
   `installers/ninerouter.ts` `resolveSpawnArgs`)។

## 8. សំណួរដែលសួរញឹកញាប់

**សំណួរ៖ តើខ្ញុំអាចបើកឱ្យម៉ាស៊ីនភ្ញៀវដែលមិនមែនជា loopback ចូលប្រើ endpoint របស់សេវាកម្មដែលបានបង្កប់បានទេ?**

មិនបានទេ។ កម្រិត LOCAL_ONLY ត្រូវបានកំណត់ឡើងដោយចេតនា (វិធានតឹងរ៉ឹង #17)។ Route ដែលអាចហៅ
`npm install` ឬបង្កើត process `node` មិនត្រូវអាចចូលប្រើបានពី traffic ដែលមិនមែនជា loopback
នោះទេ ព្រោះបើមិនដូច្នោះទេ JWT ដែលបែកធ្លាយតាមរយៈ tunnel (Cloudflare, Ngrok, Tailscale) អាច
អនុញ្ញាតឱ្យបង្កើត process តាមអំពើចិត្តបាន។ មិនមានករណីលើកលែងដើម្បីដកចេញពីវិធាននេះសម្រាប់
`/api/services/` ទេ — ខុសពី `/api/mcp/` វាត្រូវបានដកចេញពីបញ្ជី bypass នៃ manage-scope។
សូមមើល `docs/security/ROUTE_GUARD_TIERS.md`។

---

**សំណួរ៖ តើ 9Router និង CLIProxyAPI នឹងអាចប្រើបាននៅក្នុងការដាក់ឱ្យដំណើរការបែប production/cloud ដែរឬទេ?**

បាន។ សេវាកម្មទាំងពីរអនុវត្តតាមគំរូដែលផ្តោតលើមូលដ្ឋានជាមុនដូច OmniRoute ផ្ទាល់។ ពួកវាដំណើរការ
លើម៉ាស៊ីនតែមួយ និងទាក់ទងគ្នាតាមរយៈ loopback។ "Production" នៅទីនេះមានន័យថា VPS
ឬម៉ាស៊ីនមេមូលដ្ឋានដែល OmniRoute ត្រូវបានដាក់ឱ្យដំណើរការ មិនមែនជាអ្នកផ្តល់សេវា cloud ពីចម្ងាយទេ។

---

**សំណួរ៖ តើខ្ញុំអាច debug supervisor ដោយរបៀបណា?**

1. តាមដាន stream កំណត់ហេតុ SSE៖ `curl -N http://localhost:20128/api/services/9router/logs`។
2. ពិនិត្យកំណត់ហេតុដែលមានរចនាសម្ព័ន្ធក្នុង output របស់ pino នៃ OmniRoute ដោយ filter តាម
   namespace `service:supervisor`។
3. ពិនិត្យ row ក្នុង DB៖ `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`។
4. ប្រើ `GET /api/services/9router/status` ដើម្បីមើលស្ថានភាពផ្ទាល់បច្ចុប្បន្ន PID, សុខភាព
   និង `lastError` ក្នុងការហៅតែមួយ។

---

**សំណួរ៖ Supervisor បង្ហាញ `health: "degraded"` ឬ `health: "unknown"` ប៉ុន្តែ state គឺ `"running"`។ តើវាជាបញ្ហាដែរឬទេ?**

`"degraded"` មានន័យថា health probe បានត្រឡប់ response ដែលមិនមែនជា 200។ `"unknown"` មានន័យថា
មិនទាន់មាន probe ណាមួយបានបញ្ចប់នៅឡើយ (ការប្រណាំងពេលវេលាជាមួយ poll ដំបូង)។ ទាំងពីរជាស្ថានភាពបណ្ដោះអាសន្ន
ក្នុងអំឡុងពេលចាប់ផ្ដើម។ ប្រសិនបើសុខភាពនៅតែ `"degraded"` លើសពី `healthIntervalMs * 3` ms បន្ទាប់ពី
`"running"` នោះសេវាកម្មដែលបានបង្កប់កំពុងដំណើរការ ប៉ុន្តែ HTTP API របស់វាមិនឆ្លើយតប។ សូមពិនិត្យ
ថាតើ port ក្នុង status response ត្រឹមត្រូវដែរឬទេ និងថាតើសេវាកម្មពិតជាកំពុង
listen លើ port នោះដែរឬទេ។

---

**សំណួរ៖ តើខ្ញុំអាចផ្លាស់ប្តូរ API key របស់ 9Router ដោយមិនចាំបាច់ restart ទាំងស្រុងបានទេ?**

មិនបានទេ។ API key ត្រូវបានបញ្ជូនទៅ 9Router តាមរយៈ environment variable នៅពេល spawn។
Environment variable មិនអាចត្រូវបានផ្លាស់ប្តូរក្នុង process ដែលកំពុងដំណើរការបានទេ។ `POST .../rotate-key`
នឹងបញ្ឈប់ និងចាប់ផ្តើមសេវាកម្មឡើងវិញដោយស្វ័យប្រវត្តិ ដើម្បីអនុវត្ត key ថ្មី។ ការប្ដូរ key
ចូលជាធរមានក្នុងរយៈពេល `stopTimeoutMs` របស់សេវាកម្ម (លំនាំដើម 15 s) បូកនឹងរយៈពេលចាប់ផ្ដើម
របស់វា។

---

**សំណួរ៖ តើដែនកំណត់របស់ ring buffer ជាអ្វី ហើយតើមានអ្វីកើតឡើងនៅពេលវាពេញ?**

សេវាកម្មនីមួយៗមាន ring buffer ទំហំ 5 MB ដាច់ដោយឡែក។ នៅពេល buffer ពេញ បន្ទាត់
កំណត់ហេតុចាស់បំផុតនឹងត្រូវបានដកចេញ ដើម្បីទុកកន្លែងសម្រាប់បន្ទាត់ថ្មី។ ព្រឹត្តិការណ៍ SSE `snapshot` ត្រឡប់
បន្ទាត់ថ្មីៗបំផុតនៅក្នុងដែនកំណត់ `tail`។ កំណត់ហេតុមិនត្រូវបានរក្សាទុកជាអចិន្ត្រៃយ៍ទៅ disk ទេ លុះត្រាតែ
`logsBufferPath` ត្រូវបានកំណត់ក្នុង row របស់ DB។
