## 🎯 Casos de Utilização

### Caso 1: "Tenho uma subscrição Claude Pro"

**Problema:** A quota expira sem ser utilizada e são atingidos limites de utilização durante sessões intensivas de programação

```
Combinação: "maximize-claude"
  1. cc/claude-opus-4-7        (utilizar totalmente a subscrição)
  2. glm/glm-4.7               (alternativa económica quando a quota se esgota)
  3. if/qwen3.8-max-preview       (recurso de emergência gratuito)

Custo mensal: $20 (subscrição) + ~$5 (alternativa) = $25 no total
em comparação com $20 + atingir os limites = frustração
```

### Caso 2: "Quero um custo zero"

**Problema:** Não consigo pagar subscrições e preciso de uma IA fiável para programação

```
Combinação: "zero-cost"
  1. if/kimi-k2.7-code          (acesso gratuito indicado; podem aplicar-se limites de utilização)
  2. kr/qwen3-coder-next        (Kiro como alternativa gratuita)

Custo mensal: $0
Qualidade: verifique o modelo, os limites, a privacidade e o SLA para a sua carga de trabalho
```

### Caso 3: "Preciso de programar 24 horas por dia, 7 dias por semana, sem interrupções"

**Problema:** Tenho prazos a cumprir e não posso permitir períodos de indisponibilidade

```
Combinação: "always-on"
  1. cc/claude-opus-4-7        (melhor qualidade)
  2. cx/gpt-5.5                (segunda subscrição)
  3. glm/glm-4.7               (económico, reposto diariamente)
  4. minimax/MiniMax-M2.1      (o mais barato, reposição a cada 5 h)
  5. if/deepseek-v4-flash       (acesso gratuito indicado; podem aplicar-se limites de utilização)

Resultado: 5 níveis de recurso aumentam a resiliência; a disponibilidade dos serviços a montante não é garantida
Custo mensal: $20-200 (subscrições) + $10-20 (alternativas)
```

### Caso 4: "Quero IA GRATUITA no OpenClaw"

**Problema:** Preciso de um assistente de IA em aplicações de mensagens, totalmente gratuito

```
Combinação: "openclaw-free"
  1. if/qwen3.8-max-preview     (acesso gratuito indicado; podem aplicar-se limites de utilização)
  2. if/deepseek-v4-flash       (acesso gratuito indicado; podem aplicar-se limites de utilização)
  3. if/kimi-k2.7-code          (acesso gratuito indicado; podem aplicar-se limites de utilização)

Custo mensal: $0
Acesso através de: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 Configuração de fornecedores

Para adicionar em massa ligações com chaves de API a partir de um ficheiro CSV ou JSON, utilize **Painel → Fornecedores → Importar de ficheiro**. As colunas são posicionais (`provider,name,apiKey,baseUrl,priority`); `provider` já deve existir como fornecedor gerido ou nó compatível. Consulte [Importar fornecedores a partir de um ficheiro CSV ou JSON](../providers/CSV-IMPORT.md).

### 🔐 Fornecedores por subscrição

#### Claude Code (Pro/Max)

```bash
Painel → Fornecedores → Ligar Claude Code
→ Início de sessão OAuth → Renovação automática do token
→ Monitorização da quota de 5 horas + semanal

Modelos:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**Dica profissional:** Utilize o Opus para tarefas complexas e o Sonnet para maior rapidez. O OmniRoute monitoriza a quota por modelo!

Não tem um navegador no anfitrião do OmniRoute? Execute `claude setup-token` em qualquer local onde tenha sessão iniciada no Claude Code e cole o token válido por um ano no separador **Token de configuração**. Consulte [Claude Code com um token de configuração](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

As rotas compatíveis com o Claude e o Claude Code preservam o esforço de raciocínio `max` nos modelos Opus e Sonnet. Os modelos Haiku não aceitam o nível de esforço `max`, pelo que o OmniRoute reduz esse pedido para um orçamento de raciocínio elevado antes de o enviar ao fornecedor a montante.

```
Nome: premium-coding
```

```
Custo: atualmente indicado como $0; os termos e a disponibilidade podem mudar
```

## 🔧 Integração com a CLI

### Cursor IDE

**Utilizar o Cursor como cliente do OmniRoute** (encaminhar o chat do Cursor através do OmniRoute):

```
Definições → Modelos → Avançadas:
  URL base da API OpenAI: http://localhost:20128/v1
  Chave da API OpenAI: [do painel do OmniRoute]
  Modelo: cc/claude-opus-4-7
```

**Utilizar o OmniRoute como fornecedor do Cursor** (o OmniRoute faz chamadas a montante para o Cursor): dê preferência a
**Painel → Fornecedores → Cursor → Iniciar sessão com o Cursor**. No Docker, consulte
[`docs/providers/CURSOR-DOCKER.md`](../providers/CURSOR-DOCKER.md).

### Claude Code

Edite `~/.claude/settings.json`:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://localhost:20128",
    "ANTHROPIC_AUTH_TOKEN": "your-omniroute-api-key"
  }
}
```

Utilize aqui o endpoint raiz compatível com o Claude. Não acrescente `/v1` a `ANTHROPIC_BASE_URL`.

### Codex CLI

```bash
export OPENAI_BASE_URL="http://localhost:20128"
export OPENAI_API_KEY="your-omniroute-api-key"
codex "your prompt"
```

### OpenClaw

Edite `~/.openclaw/openclaw.json`:

```json
{
  "agents": {
    "defaults": {
      "model": { "primary": "omniroute/if/kimi-k2.7-code" }
    }
  },
  "models": {
    "providers": {
      "omniroute": {
        "baseUrl": "http://localhost:20128/v1",
        "apiKey": "your-omniroute-api-key",
        "api": "openai-completions",
        "models": [{ "id": "if/kimi-k2.7-code", "name": "Kimi K2.7 Code" }]
      }
    }
  }
}
```

**Ou utilize o Painel:** Ferramentas da CLI → OpenClaw → Configuração automática

## 🚀 Implementação

### Instalação global através do npm (Recomendado)

```bash
npm install -g omniroute

# Criar o diretório de configuração
mkdir -p ~/.omniroute

# Criar o ficheiro .env (consulte .env.example)
cp .env.example ~/.omniroute/.env

# Iniciar o servidor
omniroute
# Ou com uma porta personalizada:
omniroute --port 3000
```

A CLI carrega automaticamente o `.env` a partir de `~/.omniroute/.env` ou `./.env`.

### Modo da área de notificação

Inicie o OmniRoute na área de notificação do sistema:

```bash
omniroute serve --tray
```

O comando termina depois de o servidor e o ícone da área de notificação estarem prontos.

O servidor continua em execução sem o terminal.

O modo da área de notificação é compatível com macOS, Windows e sessões gráficas de Linux. O modo da área de notificação não abre automaticamente o painel.

Utilize o menu da área de notificação para as seguintes ações:

- Abrir o painel.
- Abrir `/dashboard/logs`.
- Alterar o arranque automático.
- Parar o OmniRoute.

Não combine `--tray` com estas opções:

- `--daemon`
- `--log`
- `--no-recovery`

Estes modos exigem uma gestão de processos diferente.

Ative o arranque no próximo início de sessão da máquina:

```bash
omniroute autostart enable
```

O arranque automático utiliza o modo da área de notificação no macOS, Windows e em sessões gráficas de Linux. O Linux sem interface gráfica utiliza o serviço de utilizador systemd existente.

Desative o arranque no início de sessão:

```bash
omniroute autostart disable
```

## 🧩 Funcionalidades Avançadas

### Modelos Personalizados

Adicione qualquer ID de modelo a qualquer fornecedor sem esperar por uma atualização da aplicação:

```bash
# Via API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# Listar: curl http://localhost:20128/api/provider-models?provider=openai
# Remover: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

Ou utilize o Dashboard: **Providers → [Provider] → Custom Models**.

Notas:

- Os fornecedores OpenRouter e compatíveis com OpenAI/Anthropic são geridos apenas a partir de **Available Models**. A adição manual, a importação e a sincronização automática vão todas parar à mesma lista de modelos disponíveis, pelo que não existe uma secção separada de Custom Models para esses fornecedores.
- A secção **Custom Models** destina-se a fornecedores que não expõem importações geridas de modelos disponíveis.

### Fornecedores Personalizados Compatíveis com OpenAI

Qualquer gateway que fale a API OpenAI (um proxy autoalojado, vLLM, um agregador de terceiros)
pode ser adicionado como o seu próprio nó de fornecedor:

1. **Providers → Add OpenAI Compatible**.
2. **Name**: uma etiqueta de apresentação para o nó.
3. **Prefix**: o nome de encaminhamento. Os clientes chamam os modelos como `<prefix>/<model>`,
   pelo que um nó com o prefixo `mygw` serve `mygw/gpt-4o-mini`. Obrigatório; não existe
   restrição de caracteres.
4. **API Type**: a família de endpoints que o gateway serve (Chat Completions, Responses,
   Embeddings, áudio, imagens).
5. **Base URL**: a raiz da API, até e incluindo `/v1` (por exemplo
   `https://gateway.example.com/v1`), e não o caminho completo `/chat/completions`. Os gateways
   com caminhos não padrão definem-nos em **Advanced Settings** (caminho de chat, caminho de
   modelos).
6. O campo **API Key (for Check)** apenas testa a ligação. Depois de criar o nó,
   abra-o e utilize **Add Connection** para guardar a chave que os pedidos irão utilizar.

O nó recebe um id interno da forma `openai-compatible-<apiType>-<uuid>`; nunca precisa de o
digitar, o prefixo é o nome público.

#### Prefixos reservados

Um prefixo não pode ser o id ou alias de um fornecedor integrado (por exemplo `openai`, `cf`),
nem o id de um fornecedor descontinuado. O resolvedor de modelos verifica os ids e aliases
integrados antes dos nós personalizados, pelo que um nó que utilize um desses prefixos nunca
receberia tráfego: `<prefix>/model` seria encaminhado para o fornecedor integrado, ou falharia
de forma segura se esse fornecedor tivesse sido descontinuado. Criar ou editar um nó com esse
prefixo é rejeitado com:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

Escolha um prefixo distinto (`mygw`, `acme-proxy`). Se os pedidos a um nó personalizado
falharem com um erro que menciona um fornecedor integrado ou as suas credenciais, verifique se
o prefixo do nó é reservado: os nós guardados antes da existência desta regra continuam
armazenados, mas o seu prefixo encaminha para o fornecedor integrado. Edite o nó e atribua-lhe
um novo prefixo.

#### Opções de gateway por ligação

Estas chaves vão no `providerSpecificData` de uma ligação (por exemplo, através de
`PUT /api/providers/{id}`):

- `toolNameMaxLength` (inteiro, 1–1024) — para ligações compatíveis com o formato de chat
  OpenAI cujo gateway rejeita nomes de ferramentas longos. Os nomes mais longos são enviados
  como aliases curtos e restaurados na resposta.
- `quotaEndpoint` — o endpoint de quotas/créditos do gateway, lido para a faixa de quotas do
  dashboard e para o encaminhamento sensível a quotas. Funciona tanto em ligações compatíveis
  com OpenAI como com Anthropic; a estrutura completa está documentada em
  `open-sse/services/usage/openaiCompatible.ts`.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
```

### Encadear Peers OmniRoute

Outro gateway OmniRoute pode ser adicionado como fornecedor **Custom OpenAI-compatible**.
Utilize o URL base `/v1` do peer e uma chave de API dedicada, de privilégios mínimos, emitida
por esse peer.

Para cadeias recíprocas ou de múltiplos saltos, ative a proteção opcional contra loops em
todos os gateways:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

Apenas os pedidos enviados para um URL de peer explicitamente permitido recebem o cabeçalho
`X-OmniRoute-Peer-Trace`. Um gateway rejeita um ID de instância repetido ou um limite de
saltos esgotado com HTTP `508 Loop Detected`; os fornecedores upstream comuns não recebem
metadados de peers.

O encadeamento de peers não é replicação de bases de dados nem failover de anfitriões. Cada
gateway mantém estado SQLite, caches, contadores de taxa e sessões independentes. Utilize um
proxy reverso com verificação de estado ou failover no cliente para disponibilidade
ativa/passiva ou ativa/ativa, e nunca monte uma base de dados SQLite em várias instâncias
OmniRoute em execução.

### Cloudflare Quick Tunnel

- Disponível em **Painel → Endpoints** para Docker e outras implementações autoalojadas
- Cria um URL temporário `https://*.trycloudflare.com` que encaminha para o seu endpoint `/v1` atual compatível com OpenAI
- A primeira ativação instala o `cloudflared` apenas quando necessário; os reinícios posteriores reutilizam o mesmo binário gerido

- Os painéis Cloudflare Quick Tunnel, Tailscale Funnel e ngrok Tunnel podem ser apresentados ou ocultados em **Definições → Aparência**. Ocultar um painel não interrompe um túnel em execução.

### Estratégias de Encaminhamento

Configure através de **Painel → Definições → Encaminhamento**. O painel expõe as seis estratégias mais utilizadas; os combos e o auto-router suportam internamente um conjunto mais alargado.

**Estratégias visíveis no painel (encaminhamento ao nível da conta):**

| Estratégia                     | Descrição                                                                                                                     |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| **Fill First**                 | Utiliza as contas por ordem de prioridade — a conta principal trata de todos os pedidos até ficar indisponível                |
| **Round Robin**                | Percorre ciclicamente todas as contas com um limite de persistência configurável (predefinição: 3 chamadas por conta)         |
| **P2C (Power of Two Choices)** | Seleciona 2 contas aleatórias e encaminha para a que estiver em melhor estado — equilibra a carga com base no estado de saúde |
| **Random**                     | Seleciona aleatoriamente uma conta para cada pedido utilizando o algoritmo de baralhamento Fisher-Yates                       |
| **Least Used**                 | Encaminha para a conta com o timestamp `lastUsedAt` mais antigo, distribuindo o tráfego de forma uniforme                     |
| **Cost Optimized**             | Encaminha para a conta com o valor de prioridade mais baixo, otimizando para os fornecedores de menor custo                   |

**Estratégias avançadas de combos e automáticas** (configuráveis por combo ou através dos prefixos `auto/*` — consulte [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — ordem estrita, nunca faz round-robin
- `weighted` — divisão proporcional do tráfego consoante pesos por modelo
- `fill-first` — esgota o primeiro modelo até atingir os limites
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` e `cost-optimized`
- `auto` — baseado em pontuação entre todos os candidatos
- `lkgp` (Last Known Good Provider) — fixa o último fornecedor bem-sucedido e, depois, recorre às regras
- `context-optimized` — escolhe o modelo com a maior janela de contexto livre
- `context-relay` — encadeia modelos de contexto longo para turnos subsequentes

### Resiliência e Circuit Breakers

Configure em **Dashboard → Settings → Resilience**.

O OmniRoute implementa resiliência ao nível do fornecedor com cinco componentes:

1. **Request Queue & Pacing** — Modelação de pedidos ao nível do sistema:
   - **Requests Per Minute (RPM)** — Número máximo de pedidos por minuto por conta
   - **Min Time Between Requests** — Intervalo mínimo em milissegundos entre pedidos
   - **Max Concurrent Requests** — Número máximo de pedidos simultâneos por conta

2. **Connection Cooldown** — Configuração por tipo de autenticação para uma única ligação após falhas repetíveis:
   - **Base Cooldown** — Janela de cooldown predefinida para falhas repetíveis a montante
   - **Use Upstream Retry Hints** — Respeita as indicações autoritativas de `Retry-After` ou de reset quando fornecidas
   - **Max Backoff Steps** — Nível máximo de backoff exponencial para falhas repetidas

3. **Provider Circuit Breaker** — Monitoriza falhas de ponta a ponta do fornecedor, marca um fornecedor como degradado ao atingir o limiar de aviso configurado e abre o disjuntor quando o limiar de falhas configurado é atingido:
   - **Degradation Threshold** — Falhas consecutivas do fornecedor antes de entrar em `DEGRADED`
   - **Failure Threshold** — Falhas consecutivas do fornecedor antes de entrar em `OPEN`
   - **Reset Timeout** — Janela de tempo antes de o fornecedor ser testado novamente
   - **CLOSED** (Saudável) — Os pedidos fluem normalmente
   - **DEGRADED** — Os pedidos continuam a fluir enquanto as falhas elevadas são monitorizadas
   - **OPEN** — O fornecedor é temporariamente bloqueado após falhas repetidas
   - **HALF_OPEN** — A testar se o fornecedor recuperou

   Os limites de taxa `429` no âmbito da ligação permanecem em **Connection Cooldown** e não contam para o disjuntor do fornecedor.

   O estado de execução do disjuntor do fornecedor é apresentado apenas em **Dashboard → Health**.

4. **Wait For Cooldown** — Se todas as ligações candidatas já estiverem em cooldown, o OmniRoute pode aguardar pelo cooldown mais breve e repetir automaticamente o mesmo pedido do cliente.

5. **Rate Limit Auto-Detection** — Quando os fornecedores a montante devolvem janelas de espera explícitas, essas indicações substituem o cooldown local da ligação quando a definição está ativada.

**Dica:** Utilize a página **Health** para inspecionar e repor os disjuntores de fornecedores ativos após uma indisponibilidade. A página Resilience apenas altera a configuração.

### Estratégias de Balanceamento de Combos

Configure o balanceamento por combo em **Dashboard → Combos → Criar/Editar → Estratégia**.

| Estratégia         | Descrição                                                                         |
| ------------------ | --------------------------------------------------------------------------------- |
| **Round-Robin**    | Percorre os modelos sequencialmente                                               |
| **Priority**       | Tenta sempre o primeiro modelo; só recorre ao fallback em caso de erro            |
| **Random**         | Escolhe um modelo aleatório do combo para cada pedido                             |
| **Weighted**       | Encaminha proporcionalmente com base nos pesos atribuídos por modelo              |
| **Least-Used**     | Encaminha para o modelo com menos pedidos recentes (utiliza as métricas do combo) |
| **Cost-Optimized** | Encaminha para o modelo disponível mais barato (utiliza a tabela de preços)       |

As predefinições globais de combos podem ser definidas em **Dashboard → Definições → Encaminhamento → Predefinições de Combos**.
Os timeouts dos alvos do combo herdam, por predefinição, o timeout do pedido atual. Utilize **Timeout do alvo
(segundos)** nas predefinições de combos ou num combo individual apenas quando um limite mais curto por alvo deve
acionar um fallback mais rápido.

As otimizações de latência zero dos combos são opcionais (opt-in). Deixe as **Otimizações de latência zero**
desativadas para impedir que estas funcionalidades de latência concorram com os alvos de fallback, saltem alvos com
base no histórico de TTFT ou comprimam pedidos de fallback; ao ativá-las, permite que o hedging configurado, os
saltos preditivos de TTFT e a compressão proativa de fallback troquem fidelidade de encaminhamento/pedidos por uma
latência de cauda mais baixa.

Desative o **Buffer de tokens de raciocínio** quando os fornecedores upstream exigirem limites estritos de
`max_tokens` / `maxOutputTokens`. Quando ativado, o encaminhamento combinado apenas adiciona margem de modelo de
raciocínio a modelos com um limite de saída conhecido e mantém o limite de tokens do cliente inalterado quando o
valor com buffer seguro excederia esse limite. Se o limite do cliente já estiver acima de um teto conhecido,
o OmniRoute fixa-o nesse teto antes de enviar o pedido upstream.

## 🤖 Encaminhamento Automático (Configuração zero)

O OmniRoute inclui um **encaminhador automático orientado por pontuação** que seleciona o melhor modelo para cada pedido entre todos os fornecedores ligados — sem necessidade de manter qualquer combinação. Basta enviar o pedido com um dos prefixos `auto/*` e o OmniRoute criará dinamicamente uma combinação virtual, atribuindo pontuações aos candidatos com base na latência, custo, taxa de sucesso, adequação ao contexto, aptidão do modelo para a tarefa, falhas recentes, quota e estado do disjuntor.

| Prefixo        | Otimiza para                                                                                              |
| -------------- | --------------------------------------------------------------------------------------------------------- |
| `auto`         | Predefinição equilibrada (latência × custo × taxa de sucesso)                                             |
| `auto/coding`  | Tarefas de programação: dá preferência a Claude, GPT-5, GLM, Kimi, Qwen Coder e programadores DeepSeek    |
| `auto/cheap`   | Menor custo por token, aceitando uma latência superior                                                    |
| `auto/fast`    | Menor latência, ignorando o custo                                                                         |
| `auto/offline` | Apenas fornecedores locais (Ollama, vLLM, llama.cpp) — útil para configurações isoladas da rede           |
| `auto/smart`   | Prioriza a qualidade do raciocínio (Opus, GPT-5 xhigh, R1, raciocínio do GLM 5.1)                         |
| `auto/lkgp`    | "Último fornecedor válido conhecido" — fixa o último fornecedor bem-sucedido e, depois, recorre às regras |

Exemplo:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

O encaminhador automático está totalmente descrito em [AUTO-COMBO.md](../routing/AUTO-COMBO.md) — incluindo como ajustar os pesos de pontuação, colocar fornecedores numa lista negra e inspecionar as decisões de encaminhamento em **Painel → Combinação automática**.

## 🔌 Integração com MCP e A2A

O OmniRoute é simultaneamente um **servidor MCP** (Model Context Protocol) e um **servidor A2A** (Agent-to-Agent JSON-RPC 2.0). Qualquer IDE ou anfitrião de agentes compatível com MCP pode invocar diretamente as ferramentas do OmniRoute — sem necessidade de qualquer wrapper adicional.

### Transportes MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP transmissível**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (para plugins de IDE que prefiram stdio)

### Ligar o Claude Desktop

Edite `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) ou o equivalente no Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Ligar o Cursor / Continue / MCP do VS Code

Utilize o URL SSE `http://localhost:20128/api/mcp/sse` e uma chave de API Bearer gerada em **Painel → Chaves de API**.

### Âmbitos

Atualmente, o MCP define 32 âmbitos com nome. Cada chave Bearer pode ser limitada a âmbitos específicos — consulte [MCP-SERVER.md](../frameworks/MCP-SERVER.md) para obter o inventário oficial de âmbitos e ferramentas e [A2A-SERVER.md](../frameworks/A2A-SERVER.md) para obter o esquema JSON-RPC.

## 🧠 Sistema de Skills

## 💾 Sistema de Memória

O OmniRoute mantém **memória conversacional de longo prazo** com recuperação híbrida:

- **SQLite FTS5** para pesquisa por palavras-chave em interações anteriores
- **Armazenamento vetorial Qdrant** (opcional) para recuperação semântica
- **Extração automática de factos** — entidades, preferências e decisões são resumidas após cada sessão e armazenadas na tabela `memory_facts`
- As memórias são isoladas por chave de API e por sessão

Faça a gestão das memórias em **Painel → Memória** (pesquisar, editar, exportar, eliminar). A interface HTTP (`/api/memory/*`) permite que os agentes enviem e consultem factos programaticamente — consulte [MEMORY.md](../frameworks/MEMORY.md).

## 🔔 Webhooks

Subscreva eventos do OmniRoute para monitorização e automatização em tempo real.

- Crie um webhook em **Painel → Webhooks** com o URL de destino e o segredo de assinatura HMAC
- Eventos disponíveis: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`

## 🛠️ Gestão Programática

Pode gerir todos os recursos do OmniRoute (fornecedores, combos, chaves, definições) através de HTTP utilizando uma **chave Bearer com o âmbito `manage`**.

Gere a chave em **Painel → Chaves de API → Nova Chave → Âmbito: manage** e, em seguida:

```bash
# Listar fornecedores
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Adicionar uma ligação a um fornecedor
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Criar um combo
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Listar/criar chaves de API
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

Consulte [API_REFERENCE.md](../reference/API_REFERENCE.md) para ver o catálogo completo de endpoints e os esquemas de pedidos/respostas.

## 💻 CLI interna

O OmniRoute inclui uma CLI interna (`omniroute …`) para configuração, diagnóstico e controlo em tempo de execução. Esta é **distinta da página "Ferramentas CLI" no painel**, que configura CLIs de terceiros (Claude Code, Cursor, Codex, Cline, …) para que possam comunicar com o OmniRoute.

```bash
omniroute setup                    # Assistente interativo (palavra-passe, fornecedores, combinações)
omniroute setup --non-interactive  # Adequado para CI
omniroute doctor                   # Diagnósticos de funcionamento (diretório de dados, BD, fornecedores, portas)
omniroute providers available      # Listar fornecedores suportados
omniroute providers list           # Listar ligações configuradas
omniroute providers test <id>      # Testar em tempo real uma ligação a um fornecedor
omniroute combos list              # Listar combinações
omniroute combos switch <name>     # Definir a combinação predefinida
omniroute models                   # Listar modelos disponíveis (--json, --search)
omniroute keys add | list | remove # Gerir chaves de API a partir do terminal
omniroute backup                   # Criar um instantâneo da configuração + BD
omniroute restore [<timestamp>]    # Restaurar a partir de um instantâneo
omniroute health                   # Estado de funcionamento detalhado (disjuntores, cache, memória)
omniroute quota                    # Utilização da quota dos fornecedores
omniroute mcp status               # Estado do servidor MCP
omniroute a2a status               # Estado do servidor A2A
omniroute tunnel list|create|stop  # Túneis Cloudflare/Tailscale/ngrok
omniroute reset-password           # Repor a palavra-passe de administrador
omniroute --mcp                    # Iniciar o servidor MCP através de stdio
omniroute --port 3000              # Iniciar o servidor numa porta personalizada
```

Sugestão: associe `omniroute doctor --json` à sua ferramenta de monitorização para receber alertas sobre ligações a fornecedores com problemas.

## 🖥️ Aplicação para computador (Electron)

O OmniRoute está disponível como uma aplicação nativa para Windows, macOS e Linux.

### Instalação

```bash
# A partir do diretório electron:
cd electron
npm install

# Modo de desenvolvimento (liga ao servidor de desenvolvimento Next.js em execução):
npm run dev

# Modo de produção (utiliza a compilação autónoma):
npm start
```

### Criação de instaladores

```bash
cd electron
npm run build          # Plataforma atual
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg universal)
npm run build:linux    # Linux (.AppImage)
```

Saída → `electron/dist-electron/`

### Principais funcionalidades

| Funcionalidade                         | Descrição                                                                                        |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **Disponibilidade do servidor**        | Consulta o servidor antes de apresentar a janela (sem ecrã vazio)                                |
| **Área de notificação**                | Minimizar para a área de notificação, alterar a porta e sair através do respetivo menu           |
| **Gestão de portas**                   | Alterar a porta do servidor através da área de notificação (reinicia automaticamente o servidor) |
| **Política de Segurança de Conteúdos** | CSP restritiva através de cabeçalhos de sessão                                                   |
| **Instância única**                    | Apenas uma instância da aplicação pode ser executada de cada vez                                 |
| **Modo offline**                       | O servidor Next.js incluído funciona sem Internet                                                |

### Variáveis de ambiente

| Variável              | Predefinição | Descrição                               |
| --------------------- | ------------ | --------------------------------------- |
| `OMNIROUTE_PORT`      | `20128`      | Porta do servidor                       |
| `OMNIROUTE_MEMORY_MB` | `512`        | Limite de heap do Node.js (64–16384 MB) |
