Como o OmniRoute estima, regista e comunica o custo de cada pedido — e por que motivo o
valor apresentado no painel é um **registo de poupanças**, não uma fatura.

Consulte também: [Guia do Utilizador](./USER_GUIDE.md) · [Galeria de Funcionalidades](./FEATURES.md)

## O que é (e o que não é)

O OmniRoute atribui um custo em USD por pedido a cada conclusão, multiplicando as contagens
de tokens pelas tarifas do modelo. Estes valores alimentam o painel de **Custos**, os
comandos da CLI `omniroute cost` / `omniroute usage`, as exportações CSV/JSON e os orçamentos
por chave de API.

> **O "custo" apresentado no painel é um registo de poupanças, não uma fatura.** O OmniRoute nunca lhe cobra
> — encaminha os seus pedidos para fornecedores que já tenha associado (as suas próprias
> subscrições, níveis gratuitos e chaves de API). Um "custo total de $290" acumulado inteiramente em modelos
> gratuitos significa que, aproximadamente, **não pagou _$290_** a uma API paga. O valor é uma _estimativa_
> de quanto o mesmo tráfego teria custado aos preços de tabela padrão, para que possa ver onde
> a sua utilização está concentrada e quanto está a poupar ao encaminhar para fornecedores mais baratos/gratuitos.

Este enquadramento é indicado diretamente no [README](../../README.md) do projeto ("o 'custo'
apresentado no painel é um registo de poupanças, não uma fatura").

Como o valor é uma estimativa:

- Depende da tabela de preços que o OmniRoute tem para cada modelo. Um modelo sem uma entrada
  de preço contribui com um custo de `0` (é apresentado como uma linha "Legado / Gratuito" no explorador).
- O tráfego de níveis gratuitos e de subscrições continua a acumular um custo _estimado_ — esse é o
  montante que está a poupar, não um montante em dívida.

## Como os custos são estimados

### A fonte de preços

Os custos provêm da tabela de preços fundida no [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts), por esta ordem de precedência (**mais alto primeiro** ):

1. **Substituições de utilizador** Preços — definidos no painel ou através de `PATCH /api/pricing` (o namespace `pricing` ).
2. **sincronização de modelos.dev** Preços — obtidos a partir do `https://models.dev/api.json` (o namespace `models_dev_pricing` ).
3. **Sincronização LiteLLM** Preços — obtidos a partir do `model_prices_and_context_window.json` público do LiteLLM(o namespace `pricing_synced` ).
4. **Padrões codificados** Taxas — enviadas em [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/).

Para o mesmo provider/model, os valores das camadas de maior prioridade substituem os campos correspondentes nas camadas inferiores; os campos em falta de uma camada superior podem ainda vir de uma camada inferior. A ordem é fixa mesmo quando ambos os trabalhos de sincronização independentes são executados ao mesmo tempo. `GET /api/pricing?includeSources=1` devolve `pricing` e `sourceMap`, cujos rótulos por modelo (`user`, `modelsDev`, `litellm`, `default`) identificam a camada de maior prioridade que contém esse modelo.

**Sincronização LiteLLM** é opcional, desativado por defeito. As suas variáveis de ambiente (ver [`.env.example`](../../.env.example) ) são:

| Variável ambiente       | Predefinição | Finalidade                                                                                 |
| ----------------------- | ------------ | ------------------------------------------------------------------------------------------ |
| `PRICING_SYNC_ENABLED`  | `false`      | Ative a sincronização de preços LiteLLM em segundo plano.                                  |
| `PRICING_SYNC_INTERVAL` | `86400`      | Intervalo de sincronização em segundos (diariamente).                                      |
| `PRICING_SYNC_SOURCES`  | `litellm`    | Seleção da fonte apenas para esta sincronização; atualmente apenas `litellm` é compatível. |

**sincronização de modelos.dev** está separado da sincronização LiteLLM e também está desativado por defeito. Active-o em Definições (sincronização de models.dev) ou utilize estas variáveis:

| Variável ambiente          | Predefinição   | Finalidade                                                                                                                                 |
| -------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `MODELS_DEV_SYNC_ENABLED`  | _(desativado)_ | Desativar segue a alternância de definições; `1/true/on/yes` é ativado e `0/false/off/no` é desativado (mesmo que as Definições o ativem). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`        | Intervalo de sincronização padrão models.dev em segundos (diariamente).                                                                    |

`PRICING_SYNC_SOURCES` faz **não** enable templates.dev; apenas controla a sincronização LiteLLM. A eliminação de uma substituição de utilizador não limpa nenhum namespace sincronizado; a próxima camada de preços disponível entra em vigor. Para um modelo sem preço, verifique as definições de sincronização e o `sourceMap` antes de adicionar uma substituição manual.

### A fórmula do custo

O custo é calculado por pedido a partir das contagens de tokens e das taxas por milhão de tokens em [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`):

- **Tokens de entrada** (menos leituras de cache e tokens de criação de cache) × `input` Rate .
- **Tokens de leitura de cache** Taxa × `cached` (volta à taxa de entrada).
- **Tokens de criação de cache** Taxa × `cache_creation` (volta à taxa de entrada).
- **Tokens de saída** Taxa × `output`.
- **Tokens de raciocínio** Taxa × `reasoning` (volta à taxa de saída).

Todas as taxas são interpretadas como USD por 1.000.000 de tokens. Um nível de serviço Codex "rápido"/"prioritário" ou "flexível" aplica um multiplicador de custos (`getCodexFastCostMultiplier`). — por exemplo, o flex é cobrado com um desconto de token de 50%, apresentado como **poupança flexível** no painel.

Os nomes dos modelos são normalizados primeiro (os prefixos do caminho do fornecedor, como `openai/` ou `accounts/fireworks/models/` são removidos) para que as linhas históricas ainda correspondam a um preço.

### Como os gastos são registados

- O custo por pedido é calculado na conclusão do pedido. O consumo da quota partilhada é agendado no próximo tick do ciclo de eventos através do [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts).
- O gasto da chave API é armazenado em buffer e libertado em lotes pelo [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (intervalo de libertação padrão de 60 segundos, buffer de 1.000 entradas). Ajustável através de:

  | Variável ambiente                   | Predefinição | Finalidade                                        |
  | ----------------------------------- | ------------ | ------------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`      | Intervalo de libertação em milissegundos.         |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`       | Máximo de entradas em buffer antes da libertação. |

Os custos preferem uma cobrança exata informada pelo fornecedor (`provider_cost_usd`), depois um instantâneo de pedido com preço de catálogo (`calculated_cost_usd`) e, em seguida, uma reavaliação de token do catálogo atual. Os custos armazenados não são cobrados novamente através da contagem de tokens. As linhas apenas de token legado ainda mudam quando o preço de catálogo muda.

### OCR e incorporações

- Os pedidos `/v1/ocr` bem-sucedidos utilizam `usage_info.pages_processed` upstream, e não o intervalo de páginas solicitado ou o número de objetos de página devolvidos. A estimativa é de páginas × `ocr_cost_per_page` ( USD/page absoluto,**não** USD/million).
- Os pedidos com anotações de documento ou caixa delimitadora exigem uma tarifa `ocr_cost_per_annotated_page` separada. Sem isso, o custo permanece desconhecido; a tarifa OCR normal não é substituída silenciosamente.
- A sincronização LiteLLM mapeia o seu campo `annotation_cost_per_page` upstream em `ocr_cost_per_annotated_page`, retendo o valor USD/page absoluto e as entradas apenas de anotação, incluindo o zero explícito. Um campo canónico fornecido tem precedência; os valores de alias inválidos são ignorados. As substituições de preços do utilizador mantêm a prioridade normal. Consulte [as chaves de preços OCR da LiteLLM](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking).
- A utilização OCR armazena a contagem de páginas, o preço unitário, o custo USD calculado, a chave API e a ligação selecionada. As páginas nunca são representadas como tokens. Os registos de chamadas contêm metadados de faturação, e não documentos URLs, bytes PDF ou texto extraído.
- Os pedidos `/v1/embeddings` bem-sucedidos registam uma linha de utilização por lote físico, incluindo lotes separados concluídos no mesmo milissegundo. As cobranças reportadas pelo prestador têm precedência sobre as estimativas simbólicas; os wrappers combinados não adicionam cobrança.
- O histórico de utilização, a análise de custos, as janelas provider/account, os limites de gastos da chave API, o livro-razão de custos de solicitação e as acumulações de utilização diária incluem estas cobranças. As chaves sem registo mantêm a contabilização numérica sem reter o texto de partida.
- O uso ou as tarifas em falta são **desconhecido** , não gratuito: o cabeçalho do custo de resposta é omitido e a política de utilização sem preço existente aplica-se às chaves API limitadas. As taxas zero explicitamente configuradas continuam válidas para utilização a custo zero.

Esta é uma contabilidade apenas futura. As chamadas OCR/embedding antigas que nunca gravaram o histórico de utilização não podem ser reconstruídas a partir desta migração. As estimativas de catálogo são estimativas USD, e não uma fatura, e não incluem a conversão de moeda, impostos ou descontos.

### Fala e imagens

- As tentativas bem-sucedidas `/v1/audio/transcriptions`, `/v1/audio/speech` e geração de imagens partilham a contabilização numérica. As chamadas diretas e combinadas transportam a chave API do chamador e a ligação selecionada; um wrapper combinado nunca adiciona um segundo débito.
- USD informado pelo fornecedor vence uma estimativa de catálogo, incluindo uma cobrança zero explícita. O JSON `usage.cost` do OpenRouter está normalizado para `cost_usd`. Caso contrário, os tokens medidos utilizam preços de token, os segundos de transcrição utilizam preços por segundo, a entrada de fala utiliza contagens de caracteres Unicode e as imagens de preço fixo utilizam o número realmente devolvido, e não o `n` solicitado.
- Binário OpenRouter TTS não possui corpo de utilização JSON. Depois de o áudio estar concluído ou o chamador cancelar, OmniRoute consulta a sua geração ID no **mesmo** origem OpenRouter configurada. Um pedido EU nunca retorna à origem global. Esta é uma pesquisa limitada e de leitura apenas; a síntese não é repetida para contabilização. Os registos de faturação podem aparecer após o fim do áudio: as novas tentativas de pesquisa são executadas em segundo plano até 52 segundos, incluindo os prazos de rede.
- Durante esta pesquisa, a resposta áudio tem `X-OmniRoute-Cost-Status: pending` e não tem cabeçalho de custo de resposta. A sua cobrança final aparece no histórico de utilização, na análise e no livro principal após a reconciliação. Se os metadados não estiverem disponíveis, é utilizado um instantâneo tarifário configurado; caso contrário, o custo permanecerá desconhecido.
- As contagens de segundos, caracteres e imagens têm campos de unidade de faturação separados, nunca contagens de tokens falsos. A contabilização retém apenas o uso numérico, não o texto de fala, as transcrições ou os bytes de imagem. As isenções existentes para imagens sem preço permanecem inalteradas: uma tarifa de imagem genuinamente em falta não bloqueia novamente uma chave limitada e a resposta omite o cabeçalho de custo em vez de declarar a chamada gratuita. Uma falha na loja de preços ainda retém evidências de utilização para aplicação de falha fechada.

Nenhuma cobrança histórica speech/image é inventada ou preenchida. A faturação do prestador continua a ser a referência para as faturas e chamadas cuja faturação não foi reportada.

## Painel: a página de Custos

A página **Custos** encontra-se em `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`).
A sua vista principal é o separador **Visão geral dos custos**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
que carrega todos os dados a partir de `GET /api/usage/analytics`.

O que apresenta:

- **Blocos de despesas** — despesas estimadas para _Hoje (1d)_, _7d_, _30d_ e o intervalo
  selecionado. Seletor de intervalo: `7d`, `30d`, `90d`, `all`.
- **Métricas de destaque** — pedidos no intervalo, fornecedores ativos, modelos ativos e
  custo médio por pedido.
- **Explorador de custos** — uma tabela ordenável/filtrável, agrupada por **fornecedor**, **modelo**,
  **chave de API**, **conta** ou **nível de serviço**, com custos, pedidos, tokens, custo
  médio/pedido e percentagem do total.
- **Utilização de tokens** — total de tokens / tokens de entrada / tokens de saída e proporção entre entrada e saída.
- **Eficiência do encaminhamento** — número de fallbacks, taxa de fallback e cobertura do modelo pedido.
- **Previsão mensal** — projeta as despesas até ao final do mês com base na média diária recente.
- **Comparação de períodos** — variação percentual entre a primeira e a segunda metade do intervalo.
- **Gráficos** — tendência diária de custos, quota por fornecedor (circular), principais fornecedores, principais modelos, custo
  por chave de API, custo por conta, padrão de utilização semanal e um mapa de calor da atividade.
- **Exportação** — transfira o intervalo atual como **CSV** ou **JSON** (os botões aparecem
  assim que existam dados de custos diferentes de zero).

Quando não existe tráfego com preço definido, as linhas apresentam a etiqueta "Legacy / Gratuito" em vez de `$0`,
refletindo o modelo do monitorizador de poupanças.

### Subpáginas relacionadas com Custos

A área de Custos também inclui (todas em `/dashboard/costs/`):

- **Preços** (`/dashboard/costs/pricing`) — consulte e substitua os preços por modelo (apresenta
  o separador partilhado de Preços).
- **Orçamento** (`/dashboard/costs/budget`) — defina limites de despesas por âmbito (apresenta o separador
  partilhado de Orçamento).
- **Partilha de quota** (`/dashboard/costs/quota-share`) — conjuntos de quotas partilhadas e vistas da taxa
  de consumo.

## Endpoints da API

Todos estes endpoints requerem autenticação de gestão (loopback/JWT, através de `requireManagementAuth`), salvo
indicação em contrário.

### Análise de utilização e custos

| Método | Endpoint                 | Finalidade                                                                                                                                                                          |
| ------ | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/analytics`   | Análise completa de custos/utilização: resumo, tendência diária, por fornecedor/modelo/chave de API/conta/nível. Consulta: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET`  | `/api/usage/utilization` | Utilização da quota por fornecedor ao longo do tempo. Consulta: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                                        |
| `GET`  | `/api/usage/history`     | Linhas do histórico de utilização em bruto.                                                                                                                                         |
| `GET`  | `/api/usage/call-logs`   | Registos de chamadas por pedido (modelo, tokens, custo, latência, estado).                                                                                                          |
| `GET`  | `/api/usage/quota`       | Estado da quota do fornecedor.                                                                                                                                                      |
| `GET`  | `/api/usage/proxy-logs`  | Registos de pedidos do proxy.                                                                                                                                                       |

### Orçamentos

| Método | Endpoint                 | Finalidade                                                                                                        |
| ------ | ------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | Resumo de custos + verificação do orçamento para uma chave de API (parâmetro de consulta `apiKeyId` obrigatório). |
| `POST` | `/api/usage/budget`      | Defina limites diários/semanais/mensais em USD + limiar de aviso para uma chave de API.                           |
| `GET`  | `/api/usage/budget/bulk` | Resumos de orçamentos em massa para várias chaves de API.                                                         |

> A API de orçamento é limitada por **chave de API** (`apiKeyId`). Os limites devolvidos por
> `GET /api/usage/budget` incluem `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> um `warningThreshold` e os totais acumulados (`totalCostToday`, `totalCostMonth`, …).

### Preços

| Método   | Endpoint                | Finalidade                                                                                                                                                                                  |
| -------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | Preços combinados de quatro níveis (utilizador, models.dev, LiteLLM, predefinições). `?includeSources=1` devolve `pricing` + `sourceMap`.                                                   |
| `PATCH`  | `/api/pricing`          | Substitua os preços de `{ provider: { model: { input, output, cached, … } } }`.                                                                                                             |
| `DELETE` | `/api/pricing`          | Remove substituições de preços do utilizador (opcionalmente limitadas por `?provider=&model=`); preços sincronizados ou predefinições incorporadas continuam disponíveis como alternativas. |
| `GET`    | `/api/pricing/defaults` | Apresente as tarifas alternativas predefinidas por 1 milhão.                                                                                                                                |
| `GET`    | `/api/pricing/models`   | Preços indexados por modelo.                                                                                                                                                                |
| `POST`   | `/api/pricing/sync`     | Acione uma sincronização manual a partir de fontes externas (LiteLLM).                                                                                                                      |
| `GET`    | `/api/pricing/sync`     | Estado atual da sincronização.                                                                                                                                                              |
| `DELETE` | `/api/pricing/sync`     | Limpa apenas os preços sincronizados de LiteLLM (`pricing_synced`); os dados de models.dev são separados.                                                                                   |

### Outros endpoints relevantes para os custos

| Método | Endpoint                      | Finalidade                                                                             |
| ------ | ----------------------------- | -------------------------------------------------------------------------------------- |
| `GET`  | `/api/free-tier/summary`      | Totais de tokens de modelos gratuitos, utilização deste mês e saldo gratuito restante. |

## CLI

A CLI do OmniRoute disponibiliza comandos de custos, utilização e preços (registados em
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

Um relatório de custos agregado a partir de `/api/usage/analytics`.

```bash
omniroute cost                          # últimos 30 dias, agrupados por fornecedor
omniroute cost --period 7d              # últimos 7 dias
omniroute cost --group-by model         # agrupar por provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

Colunas: grupo, pedidos, tokens de entrada/saída, custo (USD) e % do total. No final, é apresentada
uma linha com o total geral (suprimida com `--quiet` ou `--output json`).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # resumo de custos por fornecedor
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# Orçamentos
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` lê `GET /api/pricing/defaults`. Para editar os preços de modelos
> individuais, utilize a página **Preços** do painel ou `PATCH /api/pricing`.

## Resolução de problemas

- **Todos os custos apresentam $0 / "Legacy / Free".** Os modelos utilizados não têm uma entrada de preços.
  Ative a sincronização externa (`PRICING_SYNC_ENABLED=true`) e execute `omniroute pricing sync`, ou
  defina os preços manualmente através da página Preços / `PATCH /api/pricing`.
- **O preço de um modelo histórico está incorreto.** Corrija o preço (substitua-o ou volte a sincronizar) — o custo é
  recalculado a partir das contagens de tokens em cada leitura analítica, pelo que as estimativas são atualizadas retroativamente.
- **Os gastos apresentam um atraso em relação ao tempo real.** Os gastos por chave são processados em lote; reduza
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` se precisar de valores mais atualizados.
