> Alternadores de tempo de execução que alteram o comportamento do OmniRoute **sem uma nova implementação**.
> Cada sinalizador listado aqui é definido em
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — a única fonte de verdade. O painel e a API REST leem desse arquivo, então a tabela abaixo é gerada para corresponder 1:1.

---

## O que são Sinalizadores de Funcionalidade

Um sinalizador de funcionalidade é um alternador nomeado (booleano ou enum) cujo valor pode ser alterado em tempo de execução e persistido na base de dados, sem necessidade de nova implementação do processo. Cada sinalizador é descrito por uma `FeatureFlagDefinition` com uma `key`, `label`, `description`, `category`, `defaultValue`, `type` e uma dica `requiresRestart`.

### Ordem de Resolução

O **valor efetivo** de um sinalizador é resolvido por
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) com esta precedência (o mais alto vence):

1. **Substituição da BD** — um valor armazenado na tabela `key_value` sob o espaço de nomes `feature_flags` (definido através do painel ou da API REST).
2. **Variável de ambiente** — `process.env[<KEY>]`, se definida e não vazia.
3. **Padrão de definição** — o `defaultValue` de `featureFlagDefinitions.ts`.

Um sinalizador booleano é considerado **ativado** quando o seu valor efetivo é `"true"`, `"1"` ou `"yes"` (ver `isFeatureFlagEnabled()`).

> [!NOTE]
> A maioria dos sinalizadores também tem uma variável de ambiente correspondente com o **mesmo nome**
> documentada em [`ENVIRONMENT.md`](./ENVIRONMENT.md). A substituição da BD do sinalizador tem precedência sobre essa variável de ambiente. Um sinalizador com
> `requiresRestart: true` é persistido imediatamente, mas apenas é relido no arranque do processo — alterná-lo exibe um banner **"Reiniciar Servidor"** no painel.

utilizado quando não está presente nenhuma substituição da BD nem variável de ambiente.

## Alternar sinalizadores

### Painel

Navegue até **Painel → Definições → Sinalizadores de funcionalidades**
(`/dashboard/settings/feature-flags`). A grelha
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
suporta:

- **Pesquisa** por chave ou descrição e **filtragem** por categoria (incluindo uma vista sintética de **Requer reinício**).
- Um **interruptor** para sinalizadores booleanos e uma **lista pendente** para sinalizadores enum
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Um indicador de origem por sinalizador — `DB`, `ENV` ou `DEF` — que mostra de onde veio o valor efetivo.
- Um botão **Repor** (apresentado apenas para sinalizadores com origem `DB`) para remover a substituição e um botão **Repor todas as substituições** na parte inferior.
- Um aviso de **Reiniciar servidor** quando um sinalizador `requiresRestart` é alterado.

### API REST

Todas as operações passam por uma única rota:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Todos os métodos requerem uma sessão autenticada do painel (`401` caso contrário).

#### `GET /api/settings/feature-flags`

Devolve todos os sinalizadores com o respetivo valor efetivo, origem e um resumo.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Exigir chave da API",
      "description": "Exigir uma chave da API para todos os pedidos recebidos",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... todos os 115 sinalizadores
  ],
  "summary": {
    "total": 115,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Define ou remove uma única substituição. Corpo: `{ key: string; value?: string }`.
A omissão de `value` remove a substituição (restaurando o valor do ambiente/predefinido).

```bash
# Definir uma substituição na BD
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remover a substituição (sem "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

A resposta repete o novo `effectiveValue`/`source`, o `previousValue`/
`previousSource` e `requiresRestart`. As chaves desconhecidas e os valores enum
fora do intervalo permitido são rejeitados com `400`.

#### `DELETE /api/settings/feature-flags`

Remove todas as substituições da BD de uma só vez, restaurando cada sinalizador
para o respetivo valor do ambiente/predefinido. Devolve `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Os sinalizadores com `requiresRestart: true` só produzem efeito depois de o processo ser recarregado.
> O fluxo de reinício do painel chama `POST /api/restart` e, em seguida, consulta periodicamente
> `GET /api/health/ping` até o servidor voltar a estar disponível.

## Recurso de Emergência por Esgotamento do Orçamento

`OMNIROUTE_EMERGENCY_FALLBACK` (categoria `runtime`, predefinição `true`) controla o
mecanismo de recurso gratuito de emergência em
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Quando ativado, os pedidos que esgotam o respetivo orçamento são encaminhados para um
fornecedor/modelo de recurso gratuito, em vez de falharem imediatamente. Defina-o como
`false` (ou `0`) — através da opção no painel, de uma substituição na BD ou da variável
de ambiente `OMNIROUTE_EMERGENCY_FALLBACK` — para desativar este comportamento e
permitir que os pedidos cujo orçamento se esgotou falhem. (Disponibilizado como uma
opção no painel nos PRs #3741 / #3752.)

Uma resposta fornecida por este mecanismo de recurso inclui
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, para que
um cliente consiga saber que foi reencaminhada sem comparar `X-OmniRoute-Provider` com
o respetivo pedido. O cabeçalho não está presente em nenhuma outra resposta.
