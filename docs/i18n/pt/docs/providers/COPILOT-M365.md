`copilot-m365-web` (também conhecido como `m365copilot`) envia pedidos de chat no formato OpenAI através de uma sessão Microsoft 365 Copilot autenticada em `m365.cloud.microsoft/chat`. Esta é uma integração nativa não oficial: não é necessário nenhum processo de proxy separado ou upstream de localhost. O fornecedor ID, o alias e as ligações importadas existentes permanecem inalterados. `copilot-web` é um fornecedor diferente para o serviço ao consumidor em `copilot.microsoft.com`.

> **Novo nos fornecedores de cookies da Web?**
>
> Ler**`docs/getting-started/WEB-COOKIE-GUIDE.md`** para obter informações sobre o processo de configuração geral, orientações sobre autenticação, limitações e resolução de problemas antes de seguir este guia específico do fornecedor.
>
> **Para importações legadas:** A credencial para este prestador é** não é um biscoito** . Não copie cookies do `m365.cloud.microsoft`. A credencial é um parâmetro de consulta WebSocket URL e um segmento de caminho, ambos lidos no separador Rede DevTools.

## Pré-requisitos

- Uma conta Microsoft 365 com acesso ao Copilot no `m365.cloud.microsoft/chat`
- Um browser baseado em Chromium (Chrome, Edge) para inspeção DevTools WebSocket
- Acesso ao modelo solicitado nessa conta; a disponibilidade varia de acordo com o inquilino e a licença

## Login nativo (contas corporativas ou escolares)

Escolher**Microsoft 365 Copilot → Ligar** e prepare uma tentativa de login. O painel utiliza um fluxo de código de autorização com PKCE; não solicita a sua senha Microsoft ou código MFA.

1. Abra um** separador do navegador em branco** , em seguida, abra**DevTools →** e habilitar** Preservar registo** . Faça-o antes de navegar para Microsoft: Windows SSO pode terminar imediatamente.
2. Copie o URL de autorização mostrado na caixa de diálogo de ligação e navegue até ele no separador preparado. Conclua a seleção da conta de Microsoft ou MFA se solicitado.
3. No registo de rede preservado, encontre o pedido para `https://login.microsoftonline.com/common/oauth2/nativeclient` e copie o seu conteúdo completo** Solicitar URL** .
4. Cole esse URL na caixa de diálogo de ligação e ligue-se. Não cole um código bruto ou a barra de endereço `wrongplace` final URL: o retorno de chamada necessário é uma navegação transitória.

Cada tentativa expira ao fim de dez minutos e só pode ser utilizada uma vez. O servidor verifica o seu estado, verificador PKCE e alvo de reautenticação antes de trocar o código. Após expiração ou falha da troca, inicie uma nova tentativa. Uma tentativa não pode sobreviver a um reinício do servidor.

Os tokens utilizam o armazenamento de credenciais de ligação existente e o caminho de atualização. A reautenticação de uma ligação requer a mesma identidade Microsoft tenant/object, e não apenas o mesmo e-mail. Preserva o operador naming/settings e substitui as credenciais importadas obsoletas. O login nativo é para contas work/school ; o caminho de importação herdado permanece disponível para as ligações existentes e as definições de camadas suportadas.

O URL full callback é uma credencial única. Nunca inclua isto em capturas de ecrã, registos, mensagens de suporte ou commits. Este fluxo não abre um browser no servidor, não inspeciona o histórico do browser nem inicia um servidor de retorno de chamada local.

## Captura de credenciais (método WebSocket )

1. Faça login no `https://m365.cloud.microsoft/chat` e inicie uma conversa.
2. Aberto**DevTools →** .
3. Filtrar por**WS** (WebSocket).
4. Clique na ligação Chathub WebSocket. Procure um URL começado por `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Do seu** Solicitar URL** , copie:
   - O valor do parâmetro de consulta `access_token` (um JWT de curta duração).
   - O segmento do caminho do Chathub após `/Chathub/` (por exemplo, `<oid>@<tenant>`).

O URL completo tem a forma:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Em OmniRoute, seleccione**Microsoft 365 Copilot** , escolha a opção herdada API-key/import e cole a credencial no formato:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Clique** Conexão de teste** e** Guardar** .

## Captura de credenciais (importação HAR )

Em vez de copiar manualmente os valores do WebSocket URL, pode exportar um ficheiro DevTools HAR :

1. Aberto**DevTools →** .
2. Inicie ou continue uma conversa Microsoft 365 Copilot (isto desencadeia a ligação WebSocket ).
3. Clique com o botão direito do rato no painel Rede e seleccione** Guarde tudo como HAR com conteúdo** .
4. Em OmniRoute, utilize o** Importar ficheiro .har** botão na caixa de diálogo de ligação do fornecedor.

OmniRoute verifica o HAR em busca do Chathub WebSocket URL, extrai `access_token` e `chathubPath` e preenche os campos de credenciais automaticamente. A importação HAR descodifica a expiração JWT e mostra o tempo de vida restante do token.

> **Nunca confirme uma exportação HAR, token de acesso ou token de atualização real.** Os valores de teste e documentação devem ser sempre espaços reservados.

## Vida útil e atualização do token

O `access_token` tem uma vida curta (normalmente**~ 75 minutos** ). Sem um token de atualização utilizável, terá de capturar novamente a credencial após expirar.

### Atualização automática com `refreshToken`

No fornecedor Microsoft 365** Adicionar ligação** ou** Editar ligação** diálogo, aberto** Definições avançadas token de atualização → (opcional)** . Cole um token de atualização Microsoft OAuth para o escopo `substrate.office.com/sydney` e guarde. A entrada é mascarada e nunca preenchida com o token armazenado. Ao editar deixe em branco para manter o token existente; cole um novo token para o substituir.

O login nativo adquire o token de atualização quando Microsoft retorna um. Para importações legadas, utilize uma concessão de código de autorização Microsoft compatível existente; este fornecedor não implementa nem promete um fluxo de código de dispositivo. Com um token de atualização configurado, OmniRoute verifica o `access_token` antes dos pedidos e atualiza-o apenas quando precisa de ser atualizado. Uma atualização bem-sucedida também persiste no token de atualização rotacionado, evitando a recaptura manual enquanto o token de atualização permanece válido.

Se `refreshToken` não estiver configurado, terá de capturar novamente a credencial WebSocket manualmente após cada expiração.

## Modelos e encaminhamento

O catálogo nativo inclui todos IDs autónomos documentados mais os quatro IDs nativos originais. O catálogo é estático e independente de conta, não é uma investigação de direitos de conta: as rotas pagas e os aliases de compatibilidade permanecem listados mesmo quando uma conta ligada não os pode utilizar. Os rótulos de visualização do modelo omitem o nome do fornecedor e o padrão de disponibilidade por modelo; O fornecedor permanece**Microsoft 365 Copilot** . Etiquetas marcadas** Alias** ou** Legado** retêm os seus identificadores e mapeamentos de protocolo existentes, e não uma garantia de uma versão histórica do modelo. O proxy autónomo** Importar de /modelos** as instruções não se aplicam a este fornecedor nativo WebSocket.

Aliases como `auto`, `quick`, `think-deeper` e aliases de versão também são registados. Os `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` e `copilot-m365-gpt-5-5-chat` existentes continuam válidos. O IDs documentado necessita do prefixo do fornecedor (`copilot-m365-web/claude-opus` ou `m365copilot/claude-opus`): muitas são palavras genéricas ou nomes de modelos de outros fornecedores, pelo que um `claude-opus` simples mantém o encaminhamento como acontece sem esse fornecedor. O registo não é uma promessa de que Microsoft serve este modelo para todas as contas. O IDs independente segue o [catálogo de protocolo](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) público (o mapa modelo para tom exportado e os seus metadados de cenário com reconhecimento de modelo). Todos os perfis nativos retêm `availability: "unverified"`; a inclusão no catálogo não é um teste de conta bem-sucedido.

- Uma recusa explícita de licença de modelo retorna** 403** `m365_model_not_licensed`, e não 502. O encaminhamento bloqueia este par connection/model, deixando os modelos licenciados na ligação utilizáveis.
- `InvalidCopilotLicense` é uma recusa de licença ao nível da conta, reportada separadamente como `m365_account_not_licensed`.
- Um acelerador por utilizador retorna** 429** `m365_throttled` e arrefece a ligação. Retornos de exaustão de acesso prioritário** 429** `priority_access_exhausted` e tem âmbito de modelo. Um resultado de `OutOfCredits` com retornos `errorCode: "ReasoningTurnExhausted"`** 429** em vez disso, `reasoning_turns_exhausted` também tem âmbito de modelo, sem tempo de reinicialização reivindicado. Foi relatado que um inquilino de trabalho limitou os tons "Pensar mais profundamente" enquanto os tons Rápidos continuavam a servir; este âmbito é uma observação do consumidor, não algo que este repositório tenha reproduzido. O encaminhamento, portanto, também tira os outros modelos documentados de `gpt-5.5` e `gpt-5.6` da rotação nesta ligação para o mesmo arrefecimento e deixa os tons rápidos e todas as outras falhas no seu próprio modelo. As dicas de nova tentativa fornecidas são preservadas; uma reposição em falta não é anunciada como um tempo de reposição conhecido.
- Uma recusa de segurança Copilot (`Disengaged`) retorna** 400** `provider_safety_rejection`, o rótulo de paragem de segurança do fornecedor partilhado. Isto nunca conta para a integridade da ligação, o cliente SDKs não tenta novamente um 400 e, com `PROVIDER_SAFETY_STOPS_TERMINAL` ativado, o encaminhamento combinado para lá em vez de repetir o pedido noutro destino.
- Os pedidos numa ligação são serializados por meio do semáforo de conta existente. Prefira substitutos prioritários em vez de painéis paralelos; a serialização por si só não elimina os limites da taxa de conversação de Microsoft.

## Solicitar comportamentos e limites

- As ferramentas são** emulado por prompt** , não chamadas de funções nativas Microsoft. Uma solicitação habilitada para ferramenta utiliza uma geração em buffer; já não passa uma geração a selecionar ferramentas. Apenas as ferramentas declaradas com formas de argumento válidas e suportadas são devolvidas como chamadas.
- Uma resposta longa e estruturada com um único exemplo final é preservada como prosa. Esta é uma heurística, não uma prova de intenção; as aplicações devem ainda impor as suas próprias permissões de ferramenta.
- A entrada de imagens funciona da mesma forma que o cliente web a envia. Cada parte da imagem (`image_url` como um data URL ou um HTTPS URL público ou um Responses `input_image`) é carregada no `/m365Copilot/UploadFile` na conversa do turno com o token de chat, e a mensagem aponta para ele com uma anotação `ImageFile` ; o texto assinala onde estava (`[image 1]`,…). Uma nova conversa carrega todas as imagens do histórico, uma continuação apenas as imagens das novas mensagens. Até 10 imagens PNG, JPEG, GIF ou WebP de, no máximo, 10 MiB cada (40 MiB por pedido); o formato é lido a partir dos bytes. HTTPS URLs são obtidos através do protetor de imagem remota fixado por DNS, apenas público. Um upload com falha falha no pedido (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` ou `m365_image_invalid`); uma viragem nunca acontece sem uma imagem que lhe foi dada. Outras partes não textuais (áudio, ficheiros) são rejeitadas explicitamente, e não descartadas silenciosamente.
- Um pedido de acompanhamento continua a mesma conversa a montante e envia apenas as mensagens após a resposta anterior. Deve estender exatamente esta resposta: mesma ligação, perfil do modelo e conjunto de ferramentas; um histórico inalterado (uma cadeia sha256 sobre cada mensagem); e os IDs de chamada de ferramenta da resposta ou do seu texto até ao espaço em branco. Qualquer outra coisa (um histórico editado, outra sessão com a mesma primeira mensagem, uma resposta diferente, uma conversa inativa durante 30 minutos ou perto do limite de 600 mensagens do Copilot, uma ligação sem ID) inicia uma nova conversa com todo o histórico. Um turno com falha nunca é retomado e um `InternalError` sem conteúdo é reenviado uma vez numa nova conversa (** 502** `m365_internal_error` se falhar novamente). As continuações são mantidas na memória do processo: um reinício inicia novas conversas.
- Cada turno é executado no chat temporário do Copilot(`disableMemory=1`): a conversa mantém o seu contexto enquanto é executada e nunca aparece no histórico de chat da conta. Os testes de modelo, Testar tudo e testes combinados podem, portanto, sondar este fornecedor sem deixar as conversas para trás.
- Uma curva tem um prazo de inatividade de 120 segundos e um prazo geral limitado. As respostas apenas finais, a filtragem de progresso e o cancelamento são geridos pelo transport/composer. nativo
- As respostas baseadas na Web mantêm as suas fontes. Copilot marca uma citação incorporada com caracteres de controlo de uso privado e envia as fontes como `references`; cada marcador se torna um link Markdown numerado (`[1](https://…)`, ou o URL simples quando Copilot usou o marcador como destino do link) com uma anotação `url_citation` correspondente (`message.annotations`, ou `delta.annotations` no pedaço que carrega o link). Uma fonte que nunca chega é descartada, pelo que os marcadores nunca chegam ao cliente. Durante o streaming, o texto após uma citação aguarda até que a sua fonte chegue.
- O resumo de raciocínio de Copilot(`ChainOfThoughtSummary`), quando o modelo envia um, é devolvido como `reasoning_content`, nunca como parte da resposta. Um resumo que se reescreve a si próprio interrompe a transmissão sem falhar na curva.
- Antes de qualquer conteúdo, as falhas licence/throttle retêm HTTP 403/429 mesmo quando o streaming foi solicitado. Após o início do conteúdo, as falhas são eventos de erro SSE, nunca uma conclusão bem-sucedida. Uma reescrita upstream que não pode ser representada por streaming apenas de acréscimo é um erro de stream explícito; as respostas da ferramenta sem streaming e com buffer mantêm o texto final.
- Quando Copilot recusa a ligação em si, a sua resposta é reportada tal como está:** 401** `m365_unauthorized` para um login rejeitado ou expirado (faça login novamente),** 429** com o seu `Retry-After` para limitação e uma falha de handshake, caso contrário, nunca uma falha de ligação genérica.

## Geração de imagem

`POST /v1/images/generations` com `model: "copilot-m365-web/m365-copilot-image"` (também conhecido como `m365copilot/m365-copilot-image`) desenha com a ferramenta de imagem integrada do Copilot, tal como o cliente web faz. Cada imagem é uma vez Copilot : aceita os conjuntos de opções de imagem do cliente web e declara `GenerateGraphicArt`, e a imagem chega a uma entrada de progresso apontando para um artefacto no serviço Designer do Microsoft. Este artefacto recusa o token de chat, pelo que OmniRoute cria um token do Designer a partir do token de atualização da ligação e descarrega os bytes; o token só é enviado para `designerapp.officeapps.live.com`.

- Necessita de uma ligação de login nativa (um token de atualização); um token colado falha com** 400** antes de qualquer turno ser passado.
- `n` é 1–4, um turno cada. `size` apenas orienta a orientação (mais larga, mais alta ou quadrada), que Copilot lê no prompt; Copilot escolhe o tamanho da renderização.
- As imagens são devolvidas in-line: `b64_json` por defeito, um dado URL para `response_format: "url"`.
- As imagens geradas dependem de um pequeno orçamento diário, separado do chat. Quando é utilizado, a solicitação falha com** 429** . Uma curva que responde sem imagem falha com** 502** (ou** 400** /** 503** quando o texto de Copilot parece uma recusa ou um problema de capacidade); a mensagem diz qual.

## Modelo de segurança

- **Integração não oficial.** Este fornecedor faz engenharia reversa do protocolo BizChat WebSocket. Pode quebrar sem aviso prévio quando Microsoft altera o endpoint.
- O sinalizador `subscriptionRisk: true` reflete que a integração depende de um endpoint não documentado. As restrições de conta são possíveis, mas não confirmadas.
- O token de acesso é um JWT de curta duração. Trate-a como uma palavra-passe: não a comprometa, registe ou partilhe.
- O token de atualização concede acesso contínuo à superfície Microsoft 365. Armazene-o com o mesmo cuidado que uma chave API.

## Solução de problemas

### A autenticação falha imediatamente

- Verifique se copiou do**WebSocket URL** , e não de um pedido XHR/Fetch. A credencial está no parâmetro de consulta `access_token` da ligação WebSocket do Chathub — e não num cabeçalho `Authorization: Bearer`.
- Certifique-se de que `chathubPath` inclui o segmento `<oid>@<tenant>` completo do caminho URL.

### O token expira após ~ 75 minutos

Isto é esperado. Sem `refreshToken`, o token de acesso tem uma vida curta. Qualquer:

- Capture novamente a credencial de DevTools ou
- Configurar** Definições avançadas → Token de atualização (opcional)** na caixa de diálogo Adicionar ou editar ligação para atualização automática.

### O teste de ligação passa, mas o chat retorna 401

Para uma ligação criada com** Faça login com Microsoft** , o Test Connection verifica a expiração do token de acesso e renova um token expirado com o token de atualização armazenado, pelo que um teste aprovado também prova que o token de atualização ainda funciona.

Para uma credencial colada, o Test Connection verifica o formato da credencial e, quando o token expira, se o token que o fornecedor utilizaria não expirou (o token armazenado da ligação ganha uma pasta obsoleta; um token de atualização conta como renovável). Um token revogado antes de expirar ainda passa no teste; chat então retorna** 401** `m365_unauthorized`. Usar** Iniciar sessão com Microsoft** novamente ou capture novamente uma nova credencial.

### Copilot não aparece na lista de fornecedores

Certifique-se de `copilot-m365-web` está ativado em** Fornecedores → do painel** . O fornecedor pode estar oculto por defeito em algumas camadas.
