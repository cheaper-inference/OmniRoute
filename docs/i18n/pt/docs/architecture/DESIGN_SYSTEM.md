> **Estado:** o painel é construído com o **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), incorporado
> como o workspace `packages/ui-kit` (`@omniroute/ui-kit`; o snapshot upstream está fixado em
> `packages/ui-kit/UPSTREAM.md` e protegido por `npm run check:ui-kit-snapshot`). O tema claro é o tema
> canónico; a preferência predefinida é `system`. A cor de destaque é o Keak lime (`--ci-color-accent`). A Inter
> (letter-spacing 0, `--ci-letter-spacing-ui`) é a família da UI, a Instrument Serif apenas para texto de
> exibição grande e esparso (`.ci-dashboard-display`), a IBM Plex Mono para código — todas autoalojadas através
> dos imports `@fontsource/*` no topo de `src/app/globals.css`. Cada ícone é um glifo Lucide.

## 1. Onde as coisas ficam

- **Kit.** `packages/ui-kit/src` é uma cópia byte a byte do `src/` upstream no commit fixado em
  `packages/ui-kit/UPSTREAM.md` (que também regista a autorização da licença); `PATCHES.md` lista os
  patches locais (nenhum). É consumido como código-fonte, sem build: o `next.config.mjs` transpila-o, e
  o `tsconfig.json` mapeia `@omniroute/ui-kit` → `packages/ui-kit/src` e `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` (`vitest.config.ts` e `vitest.mcp.config.ts` têm o mesmo alias). Importe um
  componente do kit pelo seu subcaminho (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…),
  nunca através do barrel `@omniroute/ui-kit`: o barrel inclui todos os componentes (incluindo o seletor
  de data) em cada importador. A folha de estilos do kit entra através de `src/app/globals.css`
  (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **Tokens.** `packages/ui-kit/src/ci-tokens.css` declara os tokens `--ci-*`; `src/app/globals.css`
  faz a ponte para os nomes legados do OmniRoute (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`), para que as leituras existentes de `var(--color-*)` e
  os utilitários Tailwind continuem a funcionar. O código novo usa os utilitários Tailwind (`bg-surface`,
  `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) ou classes do kit —
  nunca um valor hexadecimal (`tests/unit/design-kit-bridge.test.ts` assegura a ponte). `text-primary`
  resolve para `--color-primary-ink` através de `--text-color-primary` (lime-800 no tema claro, o destaque
  lime no tema escuro), pelo que o texto primário permanece legível enquanto
  `bg-primary`/`border-primary` mantêm a superfície lime. As séries de gráficos usam
  `--color-chart-1` … `--color-chart-5`.
- **Temas.** `<html className="ci-theme">` (`src/app/layout.tsx`) ativa o tema do kit no documento.
  A preferência é `light`, `dark` ou `system` (`THEME_CONFIG.defaultTheme = "system"` em
  `src/shared/constants/appConfig.ts`; `system` segue `prefers-color-scheme`). `applyTheme()` em
  `src/store/themeStore.ts` (espelhado pelo script de bootstrap inline em `src/app/layout.tsx`, que é
  executado antes da hidratação) define `data-theme="dark"|"light"` e alterna a classe `.dark` em
  `<html>` em conjunto. O conjunto de tokens do tema escuro do kit é ativado por `data-theme="dark"`
  (`packages/ui-kit/src/ci-tokens.css`); as substituições do tema escuro do próprio OmniRoute (o bloco
  `.dark` em `globals.css`) e os utilitários legados `dark:` do Tailwind dependem da classe `.dark`.
  Não existem predefinições de cor de destaque: o destaque vem sempre do kit, e uma predefinição
  persistida de uma build mais antiga é descartada quando a store é carregada.
- **Componentes (adaptadores).** `src/shared/components/index.tsx` mantém a API de componentes do
  OmniRoute (os mesmos nomes, exportações padrão e props), e os primitivos por trás dela são adaptadores
  sobre o kit: formulários (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`,
  `Card`), sobreposições e feedback (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`,
  `NotificationToast`, `EmptyState`, `Loading`), estrutura (`Collapsible`, `CollapsibleSection`,
  `SegmentedControl`, `Breadcrumbs`, `Avatar`) e tabelas (`DataTable`, `FilterBar`, `ColumnToggle`,
  `FilterPills`, `PresetSlider`). Um adaptador importa o componente do kit pelo subcaminho e mapeia as
  props legadas para ele — por exemplo, `Button variant="primary"` é o botão `default` do kit
  (`--ci-button-primary-*`: a superfície inversa no tema claro, o destaque com a sua tinta
  `--ci-color-accent-foreground` no tema escuro), `danger` é `destructive`, e `warning` é `outline` mais
  a extensão `.ci-button--warning`. As regras `.ci-button--warning` e `.ci-badge[data-tone]` no final de
  `globals.css` (`@layer components`) são extensões do OmniRoute sobre as classes do kit.
  `tests/unit/ui/adapters/*.test.tsx` fixam cada adaptador.
- **Shell.** `src/app/(dashboard)/layout.tsx` renderiza `DashboardLayout`, que renderiza
  `src/shared/components/layouts/DashboardShell.tsx`: o `SidebarProvider` / `Sidebar` /
  `SidebarInset` do kit (`packages/ui-kit/src/sidebar.tsx`), com a lógica de navegação do OmniRoute em
  `src/shared/components/Sidebar.tsx`. Uma ligação "saltar para o conteúdo" para `#main-content` é o
  primeiro elemento focável. `src/shared/components/Header.tsx` contém o `SidebarTrigger` do kit (o
  único controlo de alternância da barra lateral do shell), o `ProductSwitcher` da Keak e o elemento que
  abre a paleta de comandos; mostra o título da rota apenas enquanto nenhum `PageHeader` do kit
  (`.ci-page-header`) estiver montado dentro de `#main-content`, para que uma página com o seu próprio
  `PageHeader` tenha um único `h1`. `src/shared/components/CommandPalette.tsx` é um `Dialog` do kit.
- **Ícones.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) resolve o nome (o
  vocabulário Material Symbols que os ecrãs usam) através de `ICON_MAP`
  (`src/shared/constants/iconMap.ts`) para um glifo Lucide. A fonte e o pacote Material Symbols foram
  removidos: um nome ausente do mapa renderiza um glifo neutro de substituição
  (`data-icon-missing="true"`) e regista um aviso na consola fora do ambiente de produção.
  `npm run gen:icon-map` imprime os nomes em uso que estão em falta no mapa
  (`tests/unit/icon-map-coverage.test.ts` falha para qualquer nome sem um ícone Lucide;
  `tests/unit/icon-map-object-values.test.ts` cobre nomes armazenados em objetos de pesquisa);
  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` reescreve spans literais
  `<span className="material-symbols-outlined">` para `<Icon>`.
- **Marca.** `src/shared/components/OmniRouteLogo.tsx` envolve o kit: a exportação padrão
  `OmniRouteLogo` renderiza `ProductIcon product="omniroute" variant="glyph"` (SVG inline, compatível
  com `basePath`) e `OmniRouteLockup` renderiza `ProductLockup product="omniroute"` (nome acessível
  "Keak OmniRoute") ou, para operadores white-label, o seu próprio `name`/`logoSrc`. Os destinos do
  seletor de produtos estão em `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`,
  `KEAK_ACTIVE_PRODUCT`). Os ecrãs autónomos — `src/app/login/page.tsx`, `src/app/status/page.tsx`,
  `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` e
  `src/shared/components/ErrorPageScaffold.tsx` — mostram o lockup;
  `tests/unit/brand-pages-static.test.ts` protege-o.

## 2. Regras

1. Tokens, nunca literais. Exceções mantidas intencionalmente: o terminal de consola sempre escuro, os
   traços SVG do ReactFlow via `STATUS_HEX` (`src/shared/constants/statusColors.ts`) e as paletas
   categóricas `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) e
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`).
2. Nunca modifique `packages/ui-kit/src` manualmente: sincronize com `scripts/dev/sync-ui-kit.sh <commit>`; a
   verificação de pre-commit `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) falha em qualquer byte que
   difira do commit upstream fixado (é ignorada com um aviso quando o clone upstream,
   `UI_KIT_CLONE` ou `_references/cheaper-inference-ui-kit`, está ausente). Quando faltar algo ao kit,
   contorne no adaptador ou no ecrã e peça ao upstream.
3. Os textos predefinidos do kit estão em inglês (`label = "Loading"`, `loadingLabel = "Loading table"`…) — passe
   strings traduzidas de `useTranslations(...)` sempre que um componente do kit renderizar texto.
4. As utilidades do Tailwind prevalecem sobre as classes dos componentes do kit (o kit declara
   `@layer theme, base, components, utilities` e as suas regras vivem em `components`) — use utilidades para
   espaçamento e layout, não para recolorir componentes do kit.
5. Títulos: `.ci-heading` (Inter, sem tracking) para títulos de página e de secção; `.ci-dashboard-display`
   (Instrument Serif) apenas para texto de destaque grande e esparso, como o código de estado da página de erro.
6. `tests/unit/dashboard-kit-sweep.test.ts` protege a adoção do kit: nenhum span de ligadura Material em
   `src/app` ou `src/shared/components`; na árvore do dashboard (`src/app/(dashboard)` e
   `src/shared/components`) nenhum `<select>`, `<textarea>` ou `<table>` em bruto e nenhum
   `role="dialog"` feito à mão fora das exceções listadas (o ramo nativo do adaptador `Select`,
   `RequestLoggerDetail`); cada `<button>` ou `<input>` em bruto aí precisa de um comentário contendo
   `kit-exception:` (com o motivo) que termine no máximo 3 linhas acima dele; matizes da paleta e variantes
   `dark:` apenas nos ficheiros que o teste lista.
7. Verifique ambos os temas e a viewport de 390 px antes de um PR (capturas de ecrã); `tests/e2e/a11y.spec.ts` executa
   o axe.

## 3. Adicionar um ecrã

1. Abra a página com o `PageHeader` do kit (`@omniroute/ui-kit/page-header`, `compact` dentro do
   dashboard) — título, descrição e `actions`. O cabeçalho da shell passa então a omitir o seu próprio título.
2. Construa os controlos a partir de `@/shared/components` (os adaptadores) e use componentes do kit por
   subcaminho onde não exista adaptador (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`,
   `RadioGroup`, `Slider`…).
3. Ícones: `<Icon name="…" />`. Um nome novo entra em `ICON_MAP` com o componente Lucide semanticamente
   correspondente; `npm run gen:icon-map` lista os nomes ainda em falta.
4. Cores: utilidades semânticas (`text-success`, `bg-warning-bg`, `border-border`…) e
   `var(--color-chart-N)` para séries de gráficos; sem valores hexadecimais e sem variantes `dark:` que
   apenas repitam uma cor.
5. Texto: todas as strings, incluindo as etiquetas que passa aos componentes do kit, vêm de
   `useTranslations`. As chaves novas vão para `src/i18n/messages/en.json`, `pt-BR.json` e `vi.json` (o teste de
   paridade vietnamita fixa todas as chaves inglesas); os outros idiomas são preenchidos pela sincronização de
   i18n.
6. Execute as verificações antes do PR: `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (a única verificação que deteta uma importação duplicada em
   `iconMap.ts`), `npm run check:ui-icu` e os testes do próprio ecrã.

## 4. Adicionar ou alterar um adaptador

1. Mantenha a API pública de `src/shared/components/index.tsx`: os mesmos nomes de exportação, exportações
   predefinidas e props aceites. Mapeie as props legadas para o kit dentro do adaptador (ver `Button.tsx`:
   `VARIANT_TO_KIT`, `SIZE_TO_KIT`).
2. Importe o kit por subcaminho (`@omniroute/ui-kit/<component>`).
3. As soluções alternativas para lacunas do kit ficam no adaptador (ou em `globals.css` `@layer components`
   quando a correção é um estilo), nunca em `packages/ui-kit/src`.
4. Adicione ou atualize `tests/unit/ui/adapters/<name>.test.tsx`. Para um adaptador com muitos chamadores,
   compare a marcação renderizada antes e depois da alteração — mudanças de padding ou de wrappers propagam-se
   a todos os ecrãs.

## 5. Atualizar o kit

`scripts/dev/sync-ui-kit.sh <commit> [clone]` copia o `src/` upstream nesse commit para
`packages/ui-kit/src` e aplica a única transformação permitida (remove o sufixo `.js` das importações
relativas). Em seguida: reveja `git diff packages/ui-kit`, faça uma revisão visual de fornecedores,
definições, combos, utilização e endpoint em ambos os temas, execute `npm run check:ui-kit-snapshot` e
`npm run test:vitest:ui`, e abra o PR com o changelog upstream.
