Os fornecedores Web Cookie permitem que o OmniRoute utilize um serviço de IA através da sua sessão existente no browser, em vez de uma chave de API. São úteis quando já tem acesso a um serviço através do respetivo site e pretende que o OmniRoute utilize a mesma sessão autenticada.

Ao contrário dos fornecedores que utilizam chaves de API, os fornecedores Web Cookie autenticam-se através das credenciais que o seu browser envia para o site.

---

# Antes de Começar

> **Importante:** Copie sempre as credenciais de um **pedido de rede em tempo real**, **não** do armazenamento de cookies do seu browser.

Muitos problemas de autenticação são causados pela cópia de cookies a partir do local errado.

## NÃO copie do Armazenamento de Cookies

A maioria dos browsers disponibiliza os cookies armazenados através de:

```
DevTools
→ Application (ou Storage)
→ Cookies
```

Embora estes cookies pareçam estar corretos, podem estar:

- desatualizados
- incompletos
- sem cookies que são enviados apenas em pedidos autenticados

A utilização destes valores pode causar falhas de autenticação, mesmo que pareçam válidos.

## Copie de um Pedido em Tempo Real

Em alternativa, utilize os cookies de um pedido bem-sucedido:

```
DevTools
→ Network
→ Atualize a página
→ Abra um pedido de chat ou de conversa
→ Request Headers
→ Cookie
```

O cabeçalho de pedido `Cookie` contém as informações de autenticação exatas que o seu browser utilizou com êxito.

Para a maioria dos fornecedores Web Cookie, este é o valor que deve ser colado no OmniRoute.

# Configuração Geral

O processo de configuração é o mesmo para a maioria dos fornecedores Web Cookie.

1. Inicie sessão no site do fornecedor.
2. Abra as Ferramentas de Programador do browser.
3. Abra o separador **Network**.
4. Atualize a página.
5. Abra um pedido autenticado de chat ou de conversa.
6. Copie as credenciais de autenticação necessárias.
7. Abra o OmniRoute.
8. Aceda a **Fornecedores → Adicionar Fornecedor**.
9. Selecione o seu fornecedor Web Cookie.
10. Cole as credenciais.
11. Clique em **Testar Ligação**.
12. Guarde o fornecedor.

As credenciais exatas necessárias dependem do fornecedor.

## NoTrack (notrack-web)

O NoTrack ([notrack.ai](https://notrack.ai)) é uma plataforma gratuita de chat para consumidores que não requer registo — a sessão é criada anonimamente na primeira visita e mantida através de três cookies: `uid`, `si_usr_id` e `si_ses_id`. O OmniRoute encaminha o mesmo endpoint `/api/dispatch` através de um único identificador de modelo (`notrack-c`, alias `ntw`).

### Passos para estabelecer ligação

1. Abra [notrack.ai](https://notrack.ai) no seu navegador e permita que o cookie de sessão anónima seja definido.
2. Abra **Ferramentas de Programador → Rede**, atualize a página e clique em qualquer pedido `/api`.
3. Em **Cabeçalhos do Pedido**, copie o valor completo do cabeçalho `Cookie`.
4. No OmniRoute, aceda a **Fornecedores → Adicionar Fornecedor → NoTrack Web (Gratuito)**.
5. Cole a cadeia do cookie no campo `apiKey` e selecione **Guardar**.

O OmniRoute extrai `uid`, `si_usr_id` e `si_ses_id` da cadeia colada e reconstrói um cabeçalho `Cookie` limpo contendo apenas esses pares — além de `nt_session` (o token `ntk_…` definido para contas com sessão iniciada), quando presente. Se algum dos três estiver em falta, a cadeia original colada é reencaminhada sem alterações, para que os operadores possam experimentar formatos alternativos.

### Identificadores de modelo

| Identificador de modelo | Nome de apresentação | Notas                                                       |
| ----------------------- | -------------------- | ----------------------------------------------------------- |
| `notrack-c`             | NoTrack C            | Predefinição — o modelo de encaminhamento a montante `C`.   |
| `C`                     | NoTrack C            | Alias de `notrack-c` (código de encaminhamento a montante). |
| `notrack`               | NoTrack C            | Alias de `notrack-c`.                                       |
| `ntw`                   | NoTrack C            | Alias curto de `notrack-c`.                                 |

Os quatro identificadores de modelo correspondem ao mesmo modelo de encaminhamento a montante (`C`).

### Opções do pedido

O executor aceita estes campos opcionais no corpo do pedido:

| Campo do corpo        | Predefinição | Finalidade                                                                           |
| --------------------- | ------------ | ------------------------------------------------------------------------------------ |
| `notrack_mode`        | `usual`      | Modo de encaminhamento (cadeia de formato livre; o serviço aceita `usual`, …)        |
| `notrack_max_turns`   | `6`          | Número de interações internas que o serviço pode efetuar antes de responder.         |
| `notrack_chat_id`     | `null`       | Retoma um chat existente no serviço (omita para iniciar um novo chat).               |
| `notrack_attachments` | `[]`         | Matriz de descritores de anexos do serviço, transmitida sem alterações.              |
| `notrack_regenerate`  | `false`      | Defina como `true` para solicitar uma resposta regenerada para a interação anterior. |

### Capacidades

- Conclusões de chat **com e sem streaming**.
- **Chamadas de ferramentas** — defina `tools: [...]` no pedido; o executor serializa-as num contrato de envelope de chamada de ferramenta e converte as respostas do modelo novamente em `tool_calls` da OpenAI.
- **`response_format`** — existe suporte para `json_object` e `json_schema`. O executor extrai o primeiro objeto JSON da resposta do modelo e converte-o numa cadeia antes de o devolver.
- **Indicação de raciocínio** — o executor emite um delta `reasoning` quando o serviço a montante envia um evento `thinking`.

### Limitações

- O serviço a montante impõe quotas de utilização anónima — quando são excedidas, o executor devolve um erro 429 com uma mensagem clara.
- Todos os identificadores de modelo correspondem ao mesmo modelo de encaminhamento a montante; não existe seleção por modelo.
- O executor não chama o endpoint `/api/chats` do serviço a montante, pelo que o histórico de chats e as sessões não são geridos automaticamente. Utilize `notrack_chat_id` para retomar um chat existente no serviço a montante.

# O que os fornecedores de cookies da Web podem e não podem fazer

Os fornecedores de cookies da Web reutilizam a interface de chat de um site. **Não** disponibilizam as mesmas capacidades que as APIs oficiais.

## Suportado

- Autenticação através da sessão existente do navegador
- Acesso aos modelos disponíveis através da sua conta
- Transmissão contínua das respostas do chat
- Não é necessária uma chave de API

## Não suportado

- Chamada de funções
- Chamada de ferramentas
- Edição automática de ficheiros
- Fluxos de trabalho de IDE com agentes
- Funcionalidades exclusivas da API

Este é o comportamento esperado e **não** é um erro.

Se precisar de executar ferramentas, editar ficheiros automaticamente ou utilizar outros fluxos de trabalho com agentes, use um **fornecedor com chave de API** em vez de um fornecedor Web Cookie.

# Ressalva sobre a validação

Um **Test Connection** ou uma validação de cookies bem-sucedidos apenas confirmam que as credenciais fornecidas parecem estar no formato esperado.

Até que o Issue #7857 seja resolvido, uma validação bem-sucedida **não garante** que o fornecedor consiga efetuar a autenticação.

Se a autenticação continuar a falhar, confirme que copiou as credenciais de um pedido de rede ativo, em vez de as copiar do armazenamento de cookies do navegador.

---

# Resolução de problemas

## Falha na autenticação

Confirme que as credenciais foram copiadas de:

```
Network
→ Request Headers
→ Cookie
```

e **não** de:

```
Application
→ Cookies
```

---

## O cookie funciona no navegador, mas não no OmniRoute

Alguns fornecedores incluem cookies que apenas são enviados durante pedidos autenticados.

Copie novamente as credenciais de um novo pedido de rede depois de abrir uma conversa com êxito.

---

## Sessão expirada

Os fornecedores Web Cookie utilizam a sessão existente do navegador.

Se a sessão do navegador expirar ou se terminar a sessão, terá de copiar um novo conjunto de credenciais. Para automatizar a renovação de cookies para fornecedores Web suportados, consulte a ferramenta complementar [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md).

---

## O teste de ligação é bem-sucedido, mas os pedidos falham

Até que o Issue #7857 seja resolvido, passar na validação não garante que o pedido de autenticação seja bem-sucedido.

Copie novamente as suas credenciais de um novo pedido autenticado antes de continuar a resolução de problemas.

---

## O ChatGPT Web falha com "Unsupported ChatGPT integrity dependency"

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

A credencial está correta — esse erro tem origem na ponte, não na sessão. O chatgpt.com atribui os respetivos
IDs de módulo em cada implementação, e a ponte fixava anteriormente o ID do auxiliar Sentinel que instancia, pelo que uma
recompilação do chatgpt.com que alterasse o nome do auxiliar fazia com que todas as interações falhassem, embora o cookie continuasse válido. Voltar a autorizar
a ligação não resolve o problema.

As compilações que resolvem o módulo através do próprio runtime da página não fixam nenhum ID e não são afetadas por este problema. Se vir o
erro, atualize o OmniRoute e volte a executar a verificação da ligação.

# Boas práticas

- Copie as credenciais de um novo pedido autenticado.
- Evite reutilizar cookies antigos.
- Mantenha a sessão do navegador ativa enquanto utiliza fornecedores Web Cookie.
- Trate os cookies copiados como credenciais confidenciais.
- Utilize fornecedores com chave de API quando precisar de chamadas de funções ou de fluxos de trabalho com agentes.
