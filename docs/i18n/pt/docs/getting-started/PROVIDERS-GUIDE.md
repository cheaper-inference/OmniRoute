> **Resumindo**: um fornecedor é uma ligação a um serviço de IA (como OpenAI, Anthropic ou Google). Precisa de pelo menos um fornecedor para utilizar o OmniRoute.

---

## O que é um fornecedor?

Pense num fornecedor como uma **operadora de telecomunicações**. Tal como precisa de uma operadora para fazer chamadas, precisa de um fornecedor de IA para utilizar modelos de IA. O OmniRoute é como um telemóvel que funciona com **todas as operadoras** — pode alternar automaticamente entre elas.

### Tipos de fornecedores

| Tipo              | O que é                           | Exemplos                        | Custo                    |
| ----------------- | --------------------------------- | ------------------------------- | ------------------------ |
| **Gratuito**      | Não requer pagamento              | Kiro, Pollinations              | $0                       |
| **Chave de API**  | É necessária uma chave de API     | OpenAI, Anthropic, Google       | Pagamento por utilização |
| **OAuth**         | Início de sessão com a sua conta  | Claude Code, GitHub Copilot     | Subscrição               |
| **Cookie da Web** | Utiliza a sua sessão do navegador | ChatGPT Web (Codex), Gemini Web | $0 (utiliza a sua conta) |

### Fornecedores com cookies da Web

Consulte **[WEB-COOKIE-GUIDE.md](./WEB-COOKIE-GUIDE.md)** para obter instruções gerais de configuração, limitações, resolução de problemas e orientações de autenticação específicas de cada fornecedor.

## Início Rápido: Ligue o Seu Primeiro Fornecedor

### Configuração opcional de fornecedores gratuitos na primeira execução

O assistente da primeira execução apresenta um cartão explícito **Configurar fornecedores gratuitos**. Este obtém a lista atual de fornecedores elegíveis a partir do registo de fornecedores sem autenticação do OmniRoute e permite-lhe rever e desmarcar cada fornecedor antes de confirmar. O OmniRoute apresenta o aviso de precaução do fornecedor e uma ligação para o respetivo site, para que possa primeiro analisar os termos, a privacidade, a disponibilidade e os limites de utilização de terceiros.

Esta ação é opcional: concluir o assistente nunca cria silenciosamente ligações a fornecedores gratuitos. Cria apenas os fornecedores que ainda estão em falta, mantém inalteradas as ligações existentes personalizadas e comunica individualmente os fornecedores criados, já configurados e com falhas. Após um resultado parcial, pode voltar a tentar apenas os que falharam em segurança.

### Opção A: Fornecedor Gratuito (Sem Cartão de Crédito)

1. Abra o painel de controlo em `http://localhost:20128`
2. Aceda a **Fornecedores** → **Adicionar Fornecedor**
3. Selecione um destes fornecedores gratuitos:
   - **Kiro AI** — Modelos Claude gratuitos (não requer autenticação)
   - **Pollinations** — GPT-5, Claude e Gemini gratuitos (não requer chave)
   - **LongCat** — 10 milhões de tokens gratuitos (atribuição única, requer conta + KYC)
   - **Cloudflare AI** — Mais de 50 modelos, 10 mil neurónios/dia
   - **MLX Gemma 26B** — Modelo local para Apple Silicon (~38,5 tokens/s, ~15,9 GB de RAM)
   - **MLX Qwen 3.8 27B** — Modelo local para Apple Silicon (~9,1 tokens/s, ~13,1 GB de RAM)
4. Clique em **Ligar**
5. Concluído! Tem agora acesso gratuito a IA.

### Opção B: Fornecedor com Chave de API (Pago)

1. Obtenha uma chave de API no site do fornecedor:
   - **OpenAI**: https://platform.openai.com/api-keys
   - **Anthropic**: https://console.anthropic.com/
   - **Google**: https://aistudio.google.com/apikey
   - **DeepSeek**: https://platform.deepseek.com/
   - **Groq**: https://console.groq.com/
2. Abra o painel de controlo em `http://localhost:20128`
3. Aceda a **Fornecedores** → **Adicionar Fornecedor**
4. Selecione o seu fornecedor
5. Cole a sua chave de API
6. Clique em **Ligar**
7. Concluído! Tem agora acesso aos modelos desse fornecedor.

### Opção C: Fornecedor OAuth (Subscrição)

1. Abra o painel de controlo em `http://localhost:20128`
2. Aceda a **Fornecedores** → **Adicionar Fornecedor**
3. Selecione o seu fornecedor (por exemplo, Claude Code, GitHub Copilot)
4. Clique em **Ligar com OAuth**
5. Inicie sessão com a sua conta
6. Concluído! Tem agora acesso aos modelos da sua subscrição.

### Opção D: Modelos MLX Locais (Apple Silicon)

Para Macs com Apple Silicon e memória unificada, o OmniRoute permite estabelecer ligação a modelos MLX locais em execução através de `mlx-lm.server` como fornecedores locais normais compatíveis com a OpenAI.

#### Pré-requisitos

- **Mac com Apple Silicon** (M1/M2/M3/M4), sendo recomendados 24 GB ou mais de memória unificada
- Gestor de pacotes **uv**: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- **mlx-lm**: `uv pip install mlx-lm`

#### Início Rápido

1. **Instale as dependências**:

   ```bash
   # Instale o uv, caso ainda não esteja instalado
   curl -LsSf https://astral.sh/uv/install.sh | sh

   # Instale o mlx-lm
   uv pip install mlx-lm
   ```

2. **Inicie manualmente os servidores MLX** (em terminais separados):

   ```bash
   # Terminal 1: Gemma 4 26B A4B IT-QAT (porta 11435)
   uv run mlx_lm.server --model mlx-community/gemma-4-26B-A4B-it-qat-q4_0-mlx-aligned --port 11435 --host 127.0.0.1

   # Terminal 2: Qwen 3.8 27B MLX Mixed (porta 11436)
   uv run mlx_lm.server --model maglun/Qwen3.8-27B-MLX-Mixed-3.80bpw --port 11436 --host 127.0.0.1
   ```

3. **Estabeleça ligação no Painel de Controlo do OmniRoute**:
   - Aceda a **Fornecedores** → **Adicionar Fornecedor**
   - Selecione **MLX Gemma 26B** ou **MLX Qwen 3.8 27B**
   - Clique em **Ligar** (não requer chave de API)

4. **Utilize com o OpenCode**:
   ```bash
   # Configure o OpenCode para utilizar o OmniRoute
   opencode config set api.base_url http://localhost:20128/v1
   opencode config set api.key <your-omniroute-api-key>

   # Utilize os modelos MLX
   opencode run --model mlx-gemma/gemma-4-26b
   opencode run --model mlx-qwen/qwen3.8-27b
   ```

#### Gestão de Memória

**Importante**: Com 24 GB de memória unificada, apenas **um modelo MLX de grandes dimensões pode ser executado de cada vez**.

- Gemma 26B: ~15,9 GB de memória máxima
- Qwen 3.8 27B: ~13,1 GB de memória máxima

Tem de gerir esta situação manualmente:

- Execute apenas um servidor MLX de cada vez, ou
- Execute ambos em máquinas separadas, ou
- Pare um antes de iniciar o outro

O OmniRoute não gere automaticamente os processos dos servidores MLX — apenas encaminha os pedidos para os endpoints compatíveis com a OpenAI que configurar.

#### Suporte para Chamadas de Ferramentas

Ambos os modelos suportam chamadas de ferramentas compatíveis com a OpenAI. Teste com:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mlx-gemma/gemma-4-26b",
    "messages": [{"role": "user", "content": "Quanto é 2+2? Utilize a ferramenta de cálculo."}],
    "tools": [{"type": "function", "function": {"name": "calculator", "description": "Calcular", "parameters": {"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]}}}]
  }'
```

#### Resolução de Problemas

| Problema                       | Solução                                                                                                               |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| O servidor não inicia          | Consulte `uv run mlx_lm.server --help` e verifique os IDs dos modelos                                                 |
| Memória insuficiente           | Certifique-se de que apenas um modelo está em execução; feche outras aplicações; consulte o Monitor de Atividade      |
| Ligação recusada               | Verifique se o servidor está em execução na porta correta (11435/11436)                                               |
| Respostas lentas               | O primeiro pedido carrega o modelo para a memória (~30-60 s); os pedidos seguintes são rápidos                        |
| A chamada de ferramentas falha | Certifique-se de que o modelo suporta ferramentas; consulte os registos do OmniRoute para verificar erros de tradução |

## Como Ligar um Fornecedor (Passo a Passo)

### Passo 1: Abra o Painel

Aceda a `http://localhost:20128` no seu navegador.

### Passo 2: Aceda aos Fornecedores

Clique em **Fornecedores** na barra lateral.

### Passo 3: Clique em Adicionar Fornecedor

Clique no botão **+ Adicionar Fornecedor**.

### Passo 4: Selecione o Seu Fornecedor

Percorra a lista ou pesquise pelo seu fornecedor. Clique nele.

### Passo 5: Introduza as Credenciais

- **Fornecedores gratuitos**: Não são necessárias credenciais — basta clicar em **Ligar**
- **Fornecedores com chave de API**: Cole a sua chave de API
- **Fornecedores OAuth**: Clique em **Ligar com OAuth** e inicie sessão

### Passo 6: Teste a Ligação

Clique em **Testar Ligação** para verificar se funciona.

### Passo 7: Concluído!

O seu fornecedor está agora ligado. Pode utilizá-lo com `model: "auto"` ou especificar diretamente o fornecedor.

## Utilizar vários fornecedores

O OmniRoute funciona melhor com **vários fornecedores**. Isto proporciona-lhe:

- **Alternativa automática** — Se um fornecedor falhar, o OmniRoute tenta o seguinte
- **Otimização de custos** — O OmniRoute escolhe o fornecedor mais barato para cada pedido
- **Otimização da velocidade** — O OmniRoute escolhe o fornecedor mais rápido para cada pedido
- **Otimização da qualidade** — O OmniRoute escolhe o melhor fornecedor para cada tarefa

### Configuração recomendada

Ligue pelo menos **3 fornecedores** para obter a melhor experiência:

1. **Um fornecedor gratuito** (Kiro ou Pollinations) — Sempre disponível
2. **Um fornecedor rápido** (Groq, Cerebras) — Para respostas rápidas
3. **Um fornecedor de qualidade** (OpenAI, Anthropic, Google) — Para tarefas complexas

Em seguida, utilize `model: "auto"` e o OmniRoute escolherá automaticamente o melhor fornecedor para cada pedido.

### Qoder: escolha o transporte de credenciais

O Qoder requer credenciais. Os seus dois transportes têm capacidades diferentes; o nome de um modelo
por si só não identifica o que uma determinada ligação consegue fazer.

| Credencial                                       | Transporte do OmniRoute                             | Chamadas de ferramentas pelo cliente              | Streaming                                                                  |
| ------------------------------------------------ | --------------------------------------------------- | ------------------------------------------------- | -------------------------------------------------------------------------- |
| PAT começando por `pt-`                          | Processo `qodercli` local no anfitrião do OmniRoute | Não suportadas                                    | Em buffer: o SSE só é emitido depois de a CLI devolver a resposta completa |
| Token de acesso que não seja PAT ou chave de API | Endpoint HTTP compatível com OpenAI do DashScope    | Encaminhadas, sujeitas ao modelo/chave a montante | Caminho HTTP/SSE a montante                                                |

Para uma PAT, instale a CLI do Qoder no mesmo anfitrião ou contentor que o OmniRoute. O executável
tem de poder ser encontrado como `qodercli`; em alternativa, defina `CLI_QODER_BIN` como o respetivo caminho. Uma CLI
instalada apenas no anfitrião do Docker não fica automaticamente disponível no contentor. A ausência
dos binários produz um erro explícito que indica a instalação ou a definição do caminho.

O caminho de chat com PAT tem um tempo limite de processo de 45 segundos. Converte a conversa num
único prompt e invoca a CLI no modo de impressão sem streaming. Pedir `stream: true` altera
o formato da resposta para SSE; não fornece a entrega incremental de tokens a montante.
A validação pela CLI/listagem de modelos utiliza um tempo limite separado de 20 segundos. Estes são os valores predefinidos
atuais do código, não definições configuráveis no painel.

Utilize ligações PAT para chat simples. Os pedidos de agente que incluam `tools` ou `functions`
legadas excluem as contas PAT durante a seleção de credenciais, incluindo alvos de combinação fixados. Um conjunto
misto do Qoder ainda pode selecionar a respetiva conta HTTP. As chamadas diretas ao executor PAT também falham
explicitamente antes de iniciar a CLI, em vez de ignorarem silenciosamente as definições de ferramentas. Esta
restrição diz respeito às ferramentas fornecidas pelo cliente da API, não a quaisquer ferramentas internas que a CLI do Qoder
possa utilizar. Uma chave HTTP não garante que todos os modelos suportem ferramentas; continuam a aplicar-se
as verificações normais das capacidades do modelo.

O OAuth através do navegador só está disponível quando o administrador configura as cinco definições:
`QODER_OAUTH_AUTHORIZE_URL`, `QODER_OAUTH_TOKEN_URL`, `QODER_OAUTH_USERINFO_URL`,
`QODER_OAUTH_CLIENT_ID` e `QODER_OAUTH_CLIENT_SECRET`. Por predefinição, estão vazias; uma
instalação não configurada deve utilizar uma importação de credenciais suportada, em vez de presumir
que o fluxo de início de sessão através do navegador está pronto.

Referências de implementação: [executor do Qoder](../../open-sse/executors/qoder.ts),
[ambiente de execução da CLI](../../open-sse/services/qoderCli.ts) e
[configuração do OAuth](../../src/lib/oauth/constants/oauth.ts). O streaming incremental com PAT
e um tempo limite configurável são melhorias separadas; este comportamento não as garante.

## Perguntas frequentes

### "Preciso de pagar para utilizar o OmniRoute?"

**Não!** O OmniRoute é gratuito e de código aberto. Pode utilizar fornecedores gratuitos (Kiro, Pollinations) sem pagar nada. Só paga se optar por utilizar fornecedores pagos.

### "Com que fornecedor devo começar?"

Comece pelo **Kiro AI** — é gratuito, não requer uma chave de API e dá-lhe acesso aos modelos Claude. Depois, adicione mais fornecedores conforme necessário.

### "Posso utilizar vários fornecedores ao mesmo tempo?"

**Sim!** Esse é o principal objetivo do OmniRoute. Ligue vários fornecedores e utilize `model: "auto"` para permitir que o OmniRoute escolha o melhor para cada pedido.

### "E se um fornecedor ficar indisponível?"

O OmniRoute ignora automaticamente os fornecedores que falharem e tenta o seguinte. Não precisa de fazer nada.

### "Como desligo um fornecedor?"

Aceda a Fornecedores → clique no fornecedor → clique em **Desligar**.

### "Posso utilizar as minhas chaves de API existentes?"

**Sim!** Se já tiver chaves de API para a OpenAI, Anthropic, Google, etc., pode utilizá-las no OmniRoute. Basta colá-las ao ligar o fornecedor.
