O `devin-cli-agentic` permite que o runtime real do Claude Code utilize o endpoint local de
Messages da Anthropic do OmniRoute, enquanto a CLI oficial do Devin fornece respostas do modelo
através de ACP stdio. Não modifica os fornecedores existentes Anthropic, Claude OAuth,
Claude Web ou `devin-cli`.

Para chamadas de ferramentas executadas pelo cliente, encaminhe através do `devin-cli-agentic`
(alias `dva`), o fornecedor compatível com ferramentas no formato Claude. O executor ACP
legado `devin-cli` (`dv`) suporta apenas texto: executa o resumidor sem ferramentas do Devin
e não consegue devolver chamadas de ferramentas. Os respetivos metadados do modelo estão
assinalados em conformidade, para que o encaminhamento combinado que exija ferramentas o evite.

> registada na versão `2.1.220`.** A versão fixada `2.1.220` concluiu três cenários isolados
> através da Devin CLI `3000.2.17` e do modelo `swe-1-7-lightning`; essa execução final em

## Arquitetura

```text
Claude Code 2.1.258 (contentor Linux isolado sem privilégios de root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (formato Claude, fornecedor sem autenticação)
  -> devin acp --agent-type summarizer (ACP stdio oficial, sem ferramentas do Devin)
  -> Conta Devin no volume dedicado devin-auth
```

O agente ACP predefinido da CLI oficial consegue executar as suas próprias ferramentas, pelo
que esta ponte não o utiliza. Inicia o agente ACP `summarizer` fixo, cujo modo oficial da CLI
não tem ferramentas, e enquadra o pedido Anthropic serializado como um rastreio de execução.
Quando for necessária outra ação executada pelo Claude, a resposta tem de conter exatamente
um envelope de ferramenta do cliente. Qualquer `tool_call` ou `tool_call_update` do ACP é
rejeitado antes de uma resposta poder ser comunicada como bem-sucedida.

O serializador em `open-sse/executors/devin-agentic/serializer.ts` preserva `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` e as
ferramentas fornecidas pelo Claude Code. As imagens e os blocos desconhecidos falham
explicitamente. Os resultados extensos de ferramentas utilizam um marcador de truncagem
visível.

O analisador aceita um envelope `<tool>{...}</tool>` autónomo por interação do modelo.
Verifica o nome face à lista de ferramentas do pedido, valida os argumentos de acordo com o
JSON Schema dessa ferramenta, rejeita a combinação de narrativa e ações e permite uma
tentativa de correção limitada. Em seguida, o Claude Code executa localmente o `tool_use`
Anthropic resultante e envia o `tool_result` de volta através do OmniRoute.

## Encaminhamento automático

O fornecedor é elegível nos conjuntos de candidatos `auto/*` do OmniRoute quando não está
bloqueado. A elegibilidade como candidato não garante a seleção: a estratégia de
encaminhamento da combinação (por exemplo, o último estado funcional conhecido) pode dar
preferência a outro fornecedor. Utilize `dva/<model>` ou uma combinação que dê prioridade ao
Devin quando precisar que todos os pedidos sejam encaminhados através do Devin.

## Modelo de isolamento e de ameaças

A instalação, a conta e a configuração do Claude no anfitrião estão fora do âmbito e são
consideradas proibidas. Os serviços do Compose:

- são executados com o UID/GID `10001:10001`, com um sistema de ficheiros raiz só de leitura, capacidades removidas e
  `no-new-privileges`;
- utilizam uma `/home/bridge` privada, um volume dedicado para a configuração do Claude, dados isolados do OmniRoute
  e um volume `devin-auth` separado;
- montam apenas espaços de trabalho/provas `.sandbox` descartáveis;
- não montam a pasta pessoal do anfitrião, o Keychain, credenciais SSH ou da nuvem, nem o socket do Docker;
- constroem ambientes explícitos e removem variáveis de API/OAuth/encaminhamento da Anthropic;
- encaminham a inferência do Claude Code apenas para `http://omniroute:20128`, com uma chave exclusivamente local.

O perfil offline utiliza uma rede interna. No perfil em direto, o OmniRoute acede aos
endpoints oficiais do Devin apenas através do `network-guard`; os destinos não relacionados são bloqueados.
O Claude Code tem uma proteção de saída separada que bloqueia tudo e só consegue aceder ao serviço
OmniRoute local através de `NO_PROXY`. Os ficheiros de auditoria das proteções são montados apenas pelo respetivo processo de proteção. Os
scripts verificam a propriedade, o modo, a contagem de ligações e todas as decisões antes de exportarem
provas sem tokens.

Execute a prova de isolamento de forma independente:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Esta valida a topologia, as montagens nomeadas, as definições de execução sem root e de só de leitura, o encaminhamento local explícito,
a ausência de variáveis de ambiente confidenciais, a ausência do socket do Docker, o acesso bloqueado a
`api.anthropic.com` e `claude.ai`, a seleção exclusiva do fornecedor Devin e a falha explícita quando
o backend ACP não está disponível.

## Configuração inicial e utilização normal

Crie a imagem com versões fixadas:

```bash
./scripts/devin-bridge/build
```

Autentique apenas o volume isolado do Devin:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

O comando de início de sessão utiliza o fluxo oficial de tokens manuais destinado a ambientes
remotos/em contentores. O valor é introduzido diretamente no pedido da CLI; não é passado como
argumento do processo, guardado no Git nem copiado do anfitrião.

Inicie o ambiente de execução isolado do Claude Code:

```bash
./scripts/devin-bridge/launch
```

`launch` volta a verificar o isolamento, a autenticação do Devin e a descoberta de modelos antes de iniciar o
Claude Code em contentor. Nunca executa o ficheiro executável do Claude presente no anfitrião. Os aliases dos modelos podem ser
definidos em `.env.devin-bridge`; todos os valores configurados devem manter o prefixo
`devin-cli-agentic/`.

## Comandos de validação

O percurso offline reproduzível não requer uma conta Devin e não tem acesso à Internet durante a execução:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

O percurso em direto autenticado e de adesão explícita é:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

O executor em direto aguarda entre cenários para evitar abrir sessões ACP em rajada e
valida eventos estruturados do fluxo do Claude em vez de confiar em afirmações textuais. Os seus três
cenários demonstram:

1. leituras diretas do projeto e análise de defeitos;
2. uma operação `Edit` real, um `Bash` `npm test` controlado pelo cliente e um resultado final;
3. `/bridge-check` juntamente com a descoberta de `bridge-proof`, leituras do projeto, outro
   `npm test` controlado pelo cliente executado com êxito e conclusão sem trabalho pendente.

A verificação final também examina a auditoria de rede do Devin e exige que a auditoria de saída do Claude
permaneça vazia.

## Atualizar ferramentas com versões fixas

A imagem fixa as versões do Node, Claude Code e Devin CLI em
`docker/devin-bridge/Dockerfile`. Para atualizar:

1. altere as versões explícitas;
2. substitua ambas as somas de verificação dos arquivos Devin específicas de cada arquitetura pelos valores do artefacto
   oficial;
3. reconstrua e execute todos os comandos de validação offline;
4. confirme as versões dentro da imagem;
5. execute novamente o conjunto autenticado de três cenários em ambiente real.

Não instale nenhuma das CLI globalmente no anfitrião nem substitua a verificação da soma de verificação por uma
transferência não verificada.

## Diagnóstico e limpeza

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  apresenta o encaminhamento local e os erros higienizados do executor.
- `.sandbox/evidence/mock-acp.jsonl` regista ações ACP simuladas determinísticas.
- `.sandbox/evidence/claude-stream.jsonl` regista a execução offline real do Claude Code.
- `.sandbox/evidence/live-*.jsonl` regista os três fluxos validados em ambiente real.
- `.sandbox/evidence/egress.jsonl` e `.sandbox/evidence/claude-egress.jsonl` são cópias validadas,
  sem tokens, das auditorias do controlo de saída.

Pare os contentores e as redes pertencentes à solução, preservando os volumes de início de sessão/configuração:

```bash
./scripts/devin-bridge/clean
```

Remova o ambiente completo pertencente à ponte, incluindo os volumes nomeados:

```bash
./scripts/devin-bridge/clean --all
```

## Limitações

- A ponte depende da função `summarizer` fixa e sem ferramentas porque a Devin CLI `3000.2.17`
  não disponibiliza um agente ACP neutro sem ferramentas. O adaptador compensa as respostas
  intermédias em formato de resumo, mas uma única reparação limitada ainda pode falhar explicitamente.
- As chamadas ACP em ambiente real podem devolver respostas `502`/`504` transitórias. O harness espaça os cenários;
  uma falha persistente mantém o comportamento fail-closed e nunca seleciona outro fornecedor.
- O contexto ACP é reconstruído a partir de cada pedido Anthropic; não existe afinidade de
  processo/sessão.
- É suportada uma chamada de ferramenta por resposta do modelo; as chamadas paralelas são rejeitadas.
- As imagens não são explicitamente suportadas. A visão, a saída de raciocínio, os controlos de esforço e uma janela
  de contexto de 1M não são anunciados.
- O SSE utiliza eventos válidos do ciclo de vida Anthropic, mas é emitido depois de o turno ACP limitado ser
  recolhido; os fragmentos ACP não são reencaminhados incrementalmente.
