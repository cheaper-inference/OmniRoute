## Tokens grátis por mês: ~ 11,3 mil milhões conforme outros contam · ~ 90 milhões de reais

</div>

> **~ 11,3 mil milhões de tokens grátis/mês**<br/> <sub> contou da mesma forma que os outros catálogos contam: cada linha somada, ofertas encerradas incluídas </sub>
>
> **~ 90 milhões de reais hoje**<br/> <sub> cada quota partilhada contada uma vez: o que pode realmente utilizar </sub>
>
> **Tudo aqui é gratuito. Sem acesso pago.**<br/> ★ [Gostou? Marque-nos no GitHub](https://github.com/cheaper-inference/OmniRoute)

Outros catálogos cobram desde US 19 dólares por ano até US 49 dólares por acesso vitalício a dados ao vivo. Aqui tudo é gratuito. Preços <sub> verificados a 18/11/2026.</sub>

<sub>Catálogo auditado pela última vez em 23/11/2026. [Como contamos →](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **Traga as suas próprias contas de fornecedor.** Estes são níveis gratuitos de terceiros, não uma concessão de tokens do OmniRoute. Registe-se, obtenha credenciais onde um fornecedor as solicite e ligue aquelas que pode utilizar. Cada fornecedor define os seus próprios limites, disponibilidade e termos.
>
> Empilhar níveis gratuitos manualmente significa dezenas de SDKs, dezenas de limites de taxas e nenhuma ideia clara do que resta. OmniRoute mantém 214 linhas de catálogo com acesso livre e calcula o valor real de 12 pools com quota publicada, cada pool partilhado contabilizado uma vez. As quotas que só abrem após uma verificação de identidade regional (hoje, ModelScope) são mostradas separadamente, +~ 6 milhões atrás da verificação de identidade regional, e nunca adicionadas ao número real. O que resta aparece no painel (`/dashboard/free-tiers`).

The bar shows where the real figure comes from, one segment per pool. Signup credits and free providers without a token cap are listed apart and never added to it. Live used and remaining tokens on /dashboard/free-tiers."/>

>
> Catálogo <sub> auditado pela última vez em 23/11/2026. As figuras movem-se nos dois sentidos. Um fornecedor termina um nível gratuito e o número real cai. Um novo aterra e sobe. Publicamos o que o catálogo calcula, nunca um melhor caso arredondado.</sub>

## Instalar, ligar um fornecedor e encaminhar através de um endpoint

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

## Combos: o carro-chefe

1. **Comece por `auto`.** Defina o modelo no seu cliente compatível com OpenAI. OmniRoute cria um combo virtual de fornecedores ligados e pontua os candidatos ao vivo.
2. **Guarde um combo para ter mais controlo.** Escolha um nome, uma lista de objetivos e uma estratégia e, em seguida, utilize esse nome como modelo. A estratégia define qual o alvo que será atingido em primeiro lugar e como os restantes serão tentados.

Um combo é automaticamente encaminhado entre modelos. No esgotamento da quota, falha do fornecedor ou bloqueio do modelo, tenta o próximo alvo elegível e íntegro.

### Configuração zero: basta usar `auto`

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

As variantes ajustam os pesos. O último encaminhamento válido permanece com o último fornecedor bem-sucedido até falhar e, em seguida, é remarcado. `auto/fast` e `auto/cheap` expressam preferências sem garantir o modelo mais rápido ou mais barato.

| Modelo ID           | Comportamento                                                                                                                                                                                                                                                                                         |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Pesos padrão equilibrados.                                                                                                                                                                                                                                                                            |
| `auto/fast`         | Favorece a baixa latência e a saúde do fornecedor.                                                                                                                                                                                                                                                    |
| `auto/cheap`        | Favorece preços de catálogo mais baixos.                                                                                                                                                                                                                                                              |
| `auto/coding`       | Pesos de qualidade em primeiro lugar para a geração de código.                                                                                                                                                                                                                                        |
| `auto/smart`        | Pesos de qualidade com 10% de exploração (padrão 5%).                                                                                                                                                                                                                                                 |
| `auto/lkgp`         | Encaminhamento explícito de último valor conhecido com os mesmos pesos que `auto`.                                                                                                                                                                                                                    |
| `auto/subscription` | Utiliza apenas quota de plano verificada ao vivo. Retorna HTTP 503 quando nenhum está disponível e evita o substituto cobrado.                                                                                                                                                                        |
| `auto/thrifty`      | Plano → keyless → grátis → barato → premium. Pode atingir modelos faturados e voltar ao plano quando a quota e o cooldown o permitirem.                                                                                                                                                               |
| `auto/offline`      | Favorece a margem de quota e limite de taxa. As solicitações ainda vão para os seus fornecedores.                                                                                                                                                                                                     |
| `auto/chaos`        | Um modelo por fornecedor em paralelo, até cinco por defeito ou dez quando configurado. Uma chamada upstream por modelo. Retorna a resposta com melhor classificação ou a última resposta bem-sucedida do painel se o modelo principal falhar. Utilize `fusion` para sintetizar respostas com um juiz. |

Exemplos de categoria e nível opcional incluem `auto/coding:fast`, `auto/coding:free`, `auto/reasoning:pro` e `auto/vision`. Se nenhum candidato ligado corresponder, o pedido retornará HTTP 503 e o pool permanecerá restrito. [Guia de combinação automática](./docs/routing/AUTO-COMBO.md) · [Encaminhamento que prioriza a assinatura](./docs/routing/SUBSCRIPTION_LADDER.md)

### Ou crie a sua própria: 22 estratégias de encaminhamento

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

O CLI aceita 15 das 22 estratégias. O painel e os combos API aceitam todos os 22.

| Estratégia          | Comportamento                                                                                                                                                                                                                                    |
| :------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Os candidatos à classificação vivem com o marcador Auto-Combo de 16 fatores.                                                                                                                                                                     |
| `cache-optimized`   | Prefira a conta que provavelmente conterá o prefixo do aviso na cache.                                                                                                                                                                           |
| `context-optimized` | Experimente primeiro a maior janela de contexto conhecida.                                                                                                                                                                                       |
| `context-relay`     | Guarde o seu pedido e passe um resumo da conversa quando trocar de conta.                                                                                                                                                                        |
| `cost-optimized`    | Classifique por preço do token de entrada do catálogo, por último as incógnitas. O custo do pedido final pode ser diferente.                                                                                                                     |
| `expiry-first`      | Quota de gastos com probabilidade de expirar, maior sobra por hora até ser reiniciada primeiro.                                                                                                                                                  |
| `fill-first`        | Permaneça no primeiro alvo disponível até que este se esgote ou falhe e depois siga em frente.                                                                                                                                                   |
| `fusion`            | Consulte um painel em paralelo e peça a um juiz que sintetize uma resposta.                                                                                                                                                                      |
| `headroom`          | Escolha a capacidade mais livre em janelas semanais e de 5 horas.                                                                                                                                                                                |
| `jev`               | TypeSafe Jev escolhe quais as entradas da sua lista de classificação que serão executadas. Ative o `COMBO_JEV_STRATEGY_ENABLED` para enviar um trecho por pedido e utilizar chamadas TypeSafe pagas. Com ele desativado, o seu pedido aplica-se. |
| `least-used`        | Escolha o alvo com o menor número de pedidos registados neste combo.                                                                                                                                                                             |
| `lkgp`              | Experimente primeiro o último fornecedor bem-sucedido, caso contrário, mantenha o seu pedido.                                                                                                                                                    |
| `p2c`               | Experimente dois alvos e escolha por taxa de sucesso e latência.                                                                                                                                                                                 |
| `pipeline`          | Alimente a saída de cada passo no próximo alvo em sequência e devolva apenas a resposta final.                                                                                                                                                   |
| `priority`          | Experimente alvos no seu pedido. A adesão da sessão preserva-a.                                                                                                                                                                                  |
| `quota-weighted`    | Ignore as contas esgotadas e aproveite a quota restante e a carga em voo.                                                                                                                                                                        |
| `random`            | Baralhar para cada solicitação. O mesmo primeiro alvo pode ser repetido.                                                                                                                                                                         |
| `reset-aware`       | Pontue a quota restante e o tempo para repor nas janelas de sessão e semanais.                                                                                                                                                                   |
| `reset-window`      | Experimente a conta cuja janela de quotas será reposta mais rapidamente.                                                                                                                                                                         |
| `round-robin`       | Rode por ordem, três sucessos por alvo por defeito.                                                                                                                                                                                              |
| `strict-random`     | Distribua a partir de um baralho embaralhado para que cada alvo lidere uma vez antes de repetir.                                                                                                                                                 |
| `weighted`          | Desenhe um primeiro alvo por peso e mantenha os restantes como substitutos. A divisão é estatística. Utilize `round-robin` para rotação estrita.                                                                                                 |

As estratégias de quotas utilizam dados em tempo real onde os fornecedores os reportam, incluindo janelas de subscrição semanais e de 5 horas. `fusion` e `pipeline` fazem múltiplas chamadas upstream por pedido.

O marcador de 16 fatores utiliza quota, integridade, custo, latência, ajuste de tarefa, estabilidade, prioridade de nível, afinidade de nível, correspondência de especificidade, afinidade de contexto, afinidade de cache, disponibilidade de sessão, afinidade de janela de redefinição, densidade de ligação, qualidade e fiabilidade. Os pesos variam de acordo com o perfil. A afinidade de cache, a afinidade de janela de reposição e a fiabilidade têm peso zero por predefinição. ### A resiliência está integrada em: 3 camadas independentes

As falhas são tratadas em três âmbitos, pelo que um modelo incorreto não desativa a sua conta e uma conta incorreta não desativa o seu fornecedor.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Se um fornecedor inteiro estiver inoperacional

O** disjuntor do fornecedor** abre após 8 (OAuth) ou 12 (API key) falhas com o estado 408, 500, 502, 503 ou 504. Os combos ignoram este fornecedor enquanto está aberto. Após 60 ou 30 s, um pedido de teste decide se será fechado.

#### Se uma chave ou conta tiver uma taxa limitada

O** arrefecimento da conexão** bancada apenas esta ligação, com backoff exponencial de 5 s (OAuth) ou 3 s (tecla API ). Outras chaves do mesmo fornecedor continuam a ser veiculadas.

#### Se um modelo for recusado

O** bloqueio de modelo** bloqueia apenas esse modelo nessa ligação após um modelo 429, 404 ou negação de acesso. Outros modelos na mesma ligação continuam a servir.

As ligações banidas, expiradas e sem crédito são estados terminais, não tempos de espera: esperam que as repare.

## CLI, MCP e A2A completos

> OmniRoute fornece um cliente de linha de comandos com** 91 comandos e grupos de comandos de nível superior** (754 comandos contando subcomandos), um** servidor MCP com 110 ferramentas e 33 escopos** , e um** agente A2A com 6 habilidades** . Os scripts, terminais e agentes AI podem operar no mesmo gateway.

### Um verdadeiro CLI, e não apenas `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

O sinalizador global `--output table|json|jsonl|csv` torna os mesmos comandos utilizáveis em scripts e CI.

### Modo remoto: o CLI no seu portátil, OmniRoute num servidor

Faça login uma vez num servidor remoto. O CLI salva-o como um** conteúdo** e os comandos posteriores são executados nesse servidor até voltar.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Escopo do token | <img width="2000" height="0" alt=""> O que permite                              |
| --------------- | ------------------------------------------------------------------------------- |
| `read`          | Listar e inspecionar: modelos, estado, logs, utilização                         |
| `write`         | `read` plus configurar e aplicar: configuração do cliente, chaves, configuração |
| `admin`         | `write` plus gere: tokens, fornecedores, serviços, política                     |

Um host simples obtém `http://` e a porta 20128; passe um `https://` URL completo quando o servidor estiver atrás de TLS. As rotas que podem gerar processos apenas permanecem em loopback, qualquer que seja o token.

### Ligue um agente

Um agente, ou o seu próprio código, pode conduzir o encaminhamento, fornecedores, combos, cache, compressão e memória através de qualquer uma destas interfaces. Os caminhos HTTP são servidos pelo gateway, por defeito em `http://localhost:20128`.

| Interface                   | Ponto final ou comando     | Utilize-o para                                                                                  |
| --------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------- |
| MCP sobre stdio             | `omniroute --mcp`          | Claude Desktop, Cursor e outros clientes MCP locais                                             |
| MCP sobre HTTP transmitível | `/api/mcp/stream`          | Clientes MCP remotos: 110 ferramentas, 33 escopos, cada chamada gravada no registo de auditoria |
| MCP sobre SSE               | `/api/mcp/sse`             | Os clientes que ainda utilizam o transporte SSE                                                 |
| descoberta A2A              | `/.well-known/agent.json`  | Cartão de Agente: informa os outros agentes do que OmniRoute pode fazer                         |
| execução A2A                | `POST /a2a`                | Tarefas JSON-RPC 2.0, síncronas ou transmitidas por SSE, em 6 habilidades                       |
| REST API                    | `/v1/*`                    | Chat, respostas, embeddings, imagens, áudio e OCR compatíveis com OpenAI                        |
| Webhooks                    | `/api/webhooks`            | Eventos para Slack, Discord, Telegram ou qualquer URL com assinatura HMAC                       |
| CLI remoto                  | `omniroute connect <host>` | Gere uma instância remota com tokens de acesso com âmbito definido                              |

As seis competências A2A são `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` e `list-capabilities`.

**Antes de ligar:**

- **MCP sobre HTTP inicia desativado.** Ative-o com `omniroute mcp enable --transport streamable-http` ou na página Endpoints do painel. Um transporte HTTP está ativo de cada vez: `streamable-http` atende `/api/mcp/stream`, `sse` atende `/api/mcp/sse`.
- **A2A inicia desativado.** Active-o na página Endpoints do painel. `POST /a2a` segue as mesmas regras de chave API que `/v1`.
- **MCP remoto necessita de uma chave adequada.** `/api/mcp/*` apenas responde loopback por defeito. A partir de outro host, envie uma chave com `manage` ou `admin` (todas as ferramentas), ou com `mcp:connect` mais os escopos das ferramentas de que necessita. Para chaves sem `manage`/`admin`, os escopos da ferramenta são sempre aplicados.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

## Poupe 15–95% de tokens — automaticamente

### Como funciona o pipeline —, arquitetura e matemática de economia

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

O combo empilhado padrão é executado `RTK → Caveman`. Quando ambos atuam sobre a mesma carga útil tool/context, a poupança aumenta:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Os blocos de código, URLs, JSON e dados estruturados são** sempre protegido** pelo mecanismo de preservação.

> **Porquê usar muitos tokens quando poucos tokens resolvem?** Cada pedido passa pelo pipeline de compressão do OmniRoute** transparentemente** — nenhuma alteração no cliente. Agora é um** pilha de 12 motores combináveis** que são executados por ordem e combinados por combinação de encaminhamento — com base em ideias de [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) e [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

### A pilha de 12 motores

Os motores funcionam por ordem de pipeline; cada um pode ser alternado de forma independente e configurável por combinação:

<table>
  <tr><th align="center">#</th><th align="left">Motor</th><th align="left">O que faz</th></tr>
  <tr><td align="center" nowrap>1</td><td align="left" nowrap><b>Sessão-Dedup</b></td><td align="left">Descarta o conteúdo repetido entre turnos (endereçado ao conteúdo, turno cruzado)</td></tr>
  <tr><td align="center" nowrap>2</td><td align="left" nowrap><b>CCR</b></td><td align="left">Arquiva grandes blocos atrás de marcadores de recuperação, obtidos a pedido</td></tr>
  <tr><td align="center" nowrap>3</td><td align="left" nowrap><b>Leve</b></td><td align="left">Corte de URL de imagem + de espaço em branco (linha de base de luz de latência)</td></tr>
  <tr><td align="center" nowrap>4</td><td align="left" nowrap><b>RTK</b></td><td align="left">Filtragem inteligente de resultados de ferramentas, desduplicação e truncamento (com reconhecimento de comandos)</td></tr>
  <tr><td align="center" nowrap>5</td><td align="left" nowrap><b>Resultado da ferramenta de respostas</b></td><td align="left">Compressão de diagnóstico limitada JSON + sem perdas para saídas shell/patch/search/build (respostas API)</td></tr>
  <tr><td align="center" nowrap>6</td><td align="left" nowrap><b>Altura livre</b></td><td align="left">Compactação tabular sem perdas de matrizes JSON (~ 30%) através de um fornecedor <b>GCF</b> codec</td></tr>
  <tr><td align="center" nowrap>7</td><td align="left" nowrap><b>Relevância</b></td><td align="left">Pontuação da frase extrativa em relação à última consulta do utilizador</td></tr>
  <tr><td align="center" nowrap>8</td><td align="left" nowrap><b>Homem das cavernas</b></td><td align="left">Compressão de prosa baseada em regras (~ 65–75% na saída)</td></tr>
  <tr><td align="center" nowrap>9</td><td align="left" nowrap><b>Agressivo</b></td><td align="left">Resumindo + envelhecimento progressivo de voltas antigas</td></tr>
  <tr><td align="center" nowrap>10</td><td align="left" nowrap><b>LLMLingua-2</b></td><td align="left">poda semântica ML via MobileBERT ONNX — code-safe, assíncrono</td></tr>

### Além dos estilos de saída — dos motores, o mostrador adaptativo e o controlo por solicitação

Molde a resposta, dirija a janela de contexto do modelo ou escolha um plano de compressão por pedido.

#### Estilos de saída

| Estilo                                           | <img width="2000" height="0" alt=""> O que faz                                         |
| ------------------------------------------------ | -------------------------------------------------------------------------------------- |
| Prosa concisa                                    | Corta o enchimento e a cobertura preservando os detalhes técnicos.                     |
| Menos código                                     | Solicita a mais pequena alteração funcional e reutiliza o código existente.            |
| Rabo de cavalo (desenvolvedor sénior preguiçoso) | Verifica o que pode ser reutilizado ou removido e solicita uma correção da causa raiz. |
| Tenho ADHD (ação primeiro)                       | Inicia a ação, numera os passos e termina com um próximo passo concreto.               |
| Conciso CJK (文言)                               | Usa chinês clássico conciso. Disponível para `zh`.                                     |

Cada estilo possui intensidades `lite`, `full` e `ultra`. Adicione um estilo com uma entrada no registo de estilo de saída.

#### Orçamento de contexto adaptativo

| Definição | Opções                                                                                                                                                                                                       |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Política  | `reserve-output` (padrão) reserva espaço para resposta e uma margem de segurança. `percentage` utiliza uma partilha da janela de contexto. `absolute` define um alvo de token fixo.                          |
| Modo      | `floor` pode escalar o plano selecionado para caber na janela de contexto. `replace-autotrigger` utiliza o orçamento para o escalonamento automático. `off` mantém o disparo automático do limite de tokens. |

#### Onde a compressão é decidida

| Encomenda | Fonte <img width="2000" height="0" alt="">                                   |
| --------- | ---------------------------------------------------------------------------- |
| 1         | Cabeçalho de pedido `x-omniroute-compression` reconhecido                    |
| 2         | Substituição de combinação de encaminhamento                                 |
| 3         | Perfil nomeado ativo                                                         |
| 4         | Orçamento de contexto adaptável ou acionamento automático de limite de token |
| 5         | Padrão do painel de compactação                                              |
| 6         | Desativado quando não se aplica nenhum plano                                 |

O switch de compressão global tem prioridade sobre esta tabela. O cabeçalho de resposta `X-OmniRoute-Compression` reporta `<mode>; source=<source>`.

[Guia de compressão](docs/compression/COMPRESSION_GUIDE.md) · [compressão RTK](docs/compression/RTK_COMPRESSION.md) · [Mecanismos de compressão](docs/compression/COMPRESSION_ENGINES.md)

O chicote de avaliação opcional (`npm run eval:compression`) compara a fidelidade da resposta e a poupança de tokens num corpus fixo.

## Mais métodos de instalação — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` segue o mais alto** publicado** estável SemVer. Não rastreia git `main`. Fixe `:X.Y.Z` para GitOps. Consulte [os canais de lançamento Docker](docs/guides/DOCKER_GUIDE.md#release-channels). Os pinos da imagem**`OMNIROUTE_MEMORY_MB=1024`** . Isto é suficiente para o painel e um chat leve.** Agentes de codificação** (`POST /v1/responses` do código Claude, Codex, Grok,…) necessita de um heap V8 muito maior ou do processo `FATAL ERROR` s em ~ 12 GiB sob dois contextos longos sobrepostos. Dimensione o contentor acima do heap (os buffers nativos ficam fora do V8):

| Carga de trabalho <img width="2000" height="0" alt=""> | Pilha (`-e OMNIROUTE_MEMORY_MB`) | Contentor (`--memory`) |
| ------------------------------------------------------ | -------------------------------- | ---------------------- |
| Painel/chat leve                                       | `1024` (imagem padrão)           | ≥ 2 g                  |
| Um agente de codificação                               | `8192`                           | ≥ 10 g                 |
| Dois `/v1/responses` longos simultâneos                | `10240`–`12288`                  | ≥ 12–16 g              |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Tabela completa: [Guia Docker — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Canal Docker de pré-lançamento:** `diegosouzapw/omniroute:next` e `diegosouzapw/omniroute:next-web` seguem o branch `release/v*` padrão atual. Estas tags mutáveis destinam-se apenas ao teste de correções não lançadas e são** não suportado para produção** . Consulte [Canais de lançamento Docker](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

`bun install` padrão e a instalação global (`bun install -g omniroute`) são suportados através da deteção de tempo de execução Bun :

- **`bun:sqlite` integrado** : OmniRoute utiliza o driver `bun:sqlite` integrado do Bun quando é executado no Bun, recorrendo ao `better-sqlite3` no Node.js ou `sql.js`.
- **Seleção automática do empacotador Webpack em dev** : O desenvolvimento (`bun run dev`) deteta automaticamente Bun e desativa Turbopack em favor do Webpack para evitar incompatibilidades de ligação nativa do V8. As compilações de produção (`bun run build`) seguem `OMNIROUTE_USE_TURBOPACK` exactamente como no Node: Turbopack por defeito, `OMNIROUTE_USE_TURBOPACK=0` para compilar com o Webpack (`Dockerfile.bun` expõe-no como um `--build-arg`).
- **Dockerfile Bun dedicado** : `Dockerfile.bun` de várias fases para implementações de produção Bun nativas (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ Instalação mais rápida/enxuta (ignorar a compilação nativa)**

O mecanismo nativo de SQLite (`better-sqlite3`) é um** opcional** dependência, pelo que uma instalação global nunca bloqueia a compilação a partir da fonte: utiliza um binário pré-construído quando um corresponde ao seu platform/Node e, caso contrário, recorre de forma transparente a um mecanismo JS puro (`node:sqlite` no nó 22 +, caso contrário, o pacote `sql.js` WASM) — não requer ferramentas de construção.

Para saltar a pós-instalação** aquecimento nativo** inteiramente ( máquinas CI, headless ou lentas). Nota: isto apenas ignora a etapa de aquecimento nativa SQLite (`scripts/postinstall.mjs`); o binary-copy/repair (`scripts/build/postinstall.mjs`) ainda funciona normalmente:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

Para instalações mais rápidas prefira** pnpm** (hard links + da loja endereçada ao conteúdo — ver acima). Para um tempo de execução sem painel e sem interface, utilize o perfil Docker `base` (acima) ou o [separador Termux](docs/guides/TERMUX_GUIDE.md). O CLI e o painel web são servidos pelo mesmo processo numa porta, pelo que atualmente não existe um pacote separado apenas para CLI.

### Como contribuir

1. Bifurque o repositório
2. Filial do** ativo** `release/vX.Y.Z` tip (não `main`) — consulte [Modelo de ramificação e libertação](docs/ops/BRANCHING_MODEL.md)
3. Crie a sua ramificação de recursos (`git checkout -b feat/amazing-feature`)
4. Confirme as suas alterações (`git commit -m 'feat: add amazing feature'`)
5. Empurre para o ramo (`git push origin feat/amazing-feature`)
6. Abra uma pull request com** base = aquele ramo `release/vX.Y.Z`**

Consulte [CONTRIBUTING.md](CONTRIBUTING.md) para orientações detalhadas.
