## npm Patikimas leidimas (numatytasis nuo 3.8.51) — surengtas pagal užklausą, tiesioginis kaip atsarginis

`npm-publish.yml` skelbia per** npm patikima leidyba (OIDC)** pagal numatytuosius nustatymus: `stage-npm` užduotis (priglobta „github“) pakeičia GitHub id-žetoną į trumpalaikį npm kredencialą, skirtą tos — metu. Tai yra apeiti npm sankcijas dabar, kai žetonai, kurie praleidžia 2FA, yra panaikinami; jis atkuria visiškai automatinį srautą, kurį projektas turėjo iki v3.8.48, išlaikant WS1.3 garantiją (nutekėjęs prieigos raktas negali paskelbti vien — nėra prieigos rakto).

**Vienkartinė sąranka (savininkas):** npmjs.com → paketas `omniroute` → Nustatymai → _Trusted Publisher_ → GitHub: savininkas `diegosouzapw`, repo `OmniRoute`, workflow `npm-publish.yml` (aplinka: nėra). Kol tai neegzistuoja, automatinis veiksmas nepavyksta naudojant `ENEEDAUTH`: iš naujo išsiųsti naudojant `publish_mode=staged` (žemiau) arba `direct`.

### Pakopinis leidimas (pagal užklausą — `publish_mode=staged`)

npm-publish darbo eiga nebeskelbia tiesiogiai: ji paleidžia supakuotą tarbalą (`check:pack-boot`) ir paleidžia `npm stage publish` — tikslius baitus, įrašytus registre,** neįrengiamas** kol savininkas patvirtins. Žmogaus 2FA vartai persikėlė AFTER įrodymą, o ne prieš jį.

**Savininko srautas po darbo eigos tampa žalias:**

1. `npm stage list omniroute` — suraskite etapo ID (taip pat atspausdintas darbo eigos suvestinėje).
2. Patikrinkite pakopinius baitus (rekomenduojama): `npm stage download <id>`, tada įdiekite atsisiųstą tarbalą į laikinąjį priešdėlį ir paleiskite jį (`npm run check:pack-boot` automatizuoja tą patį paketą → install → įkrovos verdiktą CI).
3. `npm stage approve <id>` — 2FA raginimas IS paskelbti. `npm stage reject <id>` išmeta.
4. Tinklas po paskelbimo: patvirtinimo priemonė po paskelbimo (v3.8.49 plano WS1.4) įdiegia paskelbtą versiją iš viešojo registro į švarų konteinerį ir ją paleidžia.

**Avarinis atsarginis atšaukimas:** `workflow_dispatch` su `publish_mode=direct` atkuria senąjį tiesioginį `npm publish` (naudokite tik tuo atveju, jei pati inscenizacija veikia netinkamai; įrašykite kodėl).

**Vienkartinis grūdinimas (savininkas, npmjs.com):** sukonfigūruokite patikimą leidėją `omniroute` tik etapo režimu, kad nutekėjęs ilgalaikis prieigos raktas negalėtų `npm publish` tiesiogiai iš bet kurios — CI gali tik paleisti; tik savininko 2FA leidimai.

**Sugedusių artefaktų knygelė (nepakeista):** `npm deprecate omniroute@<bad> "<reason> — use <fixed>"` kaip numatytasis refleksas (minutės, grįžtamasis); `npm unpublish` tik 72h/no-dependents lange ir niekada kaip pirmasis žingsnis. Docker: niekada neperrašykite versijos žymos. — atšaukimas nukreipia `latest` į paskutinį gerą santrauką.

**Docker Hub `latest` (reikalingas kiekviename stabiliame SemVer publikacijoje):** `docker-publish` darbo eiga turi būti pažymėta** tiek** `X.Y.Z` ir, kai `should-promote-latest.sh` sutinka, tai yra didžiausias stabilus SemVer, `:latest` su** tas pats santrauka** . Nepalikite `:latest` senesnės versijos versijoje, o laidos pastabose kalbama apie pataisymus, kurie egzistuoja tik „git“. Sukurti greitas pradžias naudoti `:latest`; GitOps turėtų nuolat prisegti `X.Y.Z`. Žr. [Docker išleidimo kanalus](../guides/DOCKER_GUIDE.md#release-channels) ir #10317.

## Spartusis karštųjų pataisų kelias (žyma `hotfix`)

PR su žyma `hotfix` praleidžia sudėtingą CI matricą (9 segmentų E2E, aprėpties kartelę,
quality-gate, quality-extended) ir palieka sparčias, patikimas patikras: komponavimą,
modulių segmentus, integracinius testus, vitest, lint/typecheck, docs-sync, `check:pack-artifact`
ir tar archyvo paleidimo dūminį testą (`check:pack-boot`). Tikslas: žalia būsena per ≤15 min., o ne per ~33 min.

**Naudojimo politika — privalomos visos keturios sąlygos (parengta pagal Chromium/VS Code/Node avarinius kelius):**

1. **Kritiškumas**: produkcinė aplinka neveikia — paskelbtas artefaktas užstringa paleidžiant /
   saugos pataisa / problema paveikia kiekvieną leidimo naudotoją. „Svarbu“ nereiškia „neveikia“.
2. **Įgaliojimai**: tik saugyklos savininkas priskiria žymą `hotfix`. Žyma YRA
   patvirtinimas — niekada nepriskirkite jos patys kampanijos PR.
3. **Įrodymai**: PR apraše pateikiama nuoroda į ankstesnį visiškai žalią sudėtingą vykdymą (rinkinį,
   kurį praleistos užduotys patikrintų pakartotinai) ir į pačios pataisos testą, kuris iš pradžių nepavyko, o po to pavyko.
4. **Apimtis**: tik cherry-pick — minimali pataisa, jokių pertvarkymų ar papildomų pakeitimų.

Praleista aprėpties / kartelės sritis iš naujo patikrinama per kitą visą vykdymą
leidimo šakoje (nuolat žalia leidimo būsena) — šis kelias praleidžia LAUKIMĄ, bet niekada ne patikrą.
Pakeitimai, apimantys tik testus (visi failai yra `tests/`, nė vieno nėra `tests/e2e/`), automatiškai praleidžia E2E
matricą be jokios žymos.

Saugykla naudoja tris skirtingus išvesties katalogus — niekada jų nemaišykite:

| Katalogas | Tikslas                                                 | Stebimi?       |
| --------- | ------------------------------------------------------- | -------------- |
| `src/`    | Programos šaltinis (TypeScript / TSX)                   | Taip           |
| `.build/` | Sukurti tarpinius — `next build` išvestį (`distDir`)    | Ne (nepaisoma) |
| `dist/`   | Siunčiamas npm paketas — surinktas `assembleStandalone` | Ne (nepaisoma) |

> **Operatoriaus pastaba:** nuotolinis VPS vaizdų katalogas išlieka `/usr/lib/node_modules/omniroute/app/`. Tik** in-repo** kūrimo išvestis perkelta (`app/` → `dist/`). Diegdami įgūdžius rsync `dist/` turinį nuotoliniame `app/` dir — nereikia keisti VPS kelio.

**Vienos konstrukcijos srautas:**

```
npm run build:release
  └─ rm -rf .build dist          (clean)
  └─ next build → .build/next/   (intermediates)
  └─ assembleStandalone          (copies standalone + static + public + natives → dist/)
  └─ writes dist/BUILD_SHA       (HEAD sentinel)
```

Ar NOT paleiskite `npm run build` o po to atskirą `npm run build:cli` skirtą — diegti, naudokite `npm run build:release` kuris atlieka švarų + sentinel atstatymą viena komanda.
