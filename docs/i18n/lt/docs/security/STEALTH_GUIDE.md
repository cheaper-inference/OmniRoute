„OmniRoute“ integruojamas su teikėjais, kurių perimetro sistemos aktyviai identifikuoja neoficialių klientų skaitmeninius atspaudus (TLS JA3/JA4, antraščių tvarką, JSON turinio struktūrą, vientisumo prieigos raktus). Šiame puslapyje aprašomi „OmniRoute“ suteikiami maskavimo mechanizmai ir jų įgyvendinimo vietos.

## Teisinė ir etinė pastaba

Maskavimo funkcijos sukurtos tam, kad „OmniRoute“ galėtų veikti kaip suderinamumo sluoksnis tarp naudotojams priklausančių oficialių paskyrų („Claude Code CLI“, „Codex“, „Antigravity“, „Cursor“ ir kt.) ir „OmniRoute“ suvienodintos API. Jos **nėra** skirtos sukčiavimo aptikimo sistemoms apeiti, prisijungimo duomenims bendrinti ar teikėjų paslaugų teikimo sąlygoms pažeisti. Prižiūrėtojai tikisi, kad operatoriai laikysis pirminių teikėjų paslaugų teikimo sąlygų, su kuriomis sutiko kurdami paskyras.

## TLS pirštų atspaudų sluoksnis

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Nuolatinės `wreq-js` sesijos sukuriamos atidėtai kiekvienai paskyros aprėpčiai ir nustatytam tarpiniam serveriui. Viso
proceso `TlsClient` telkinyje laikoma ne daugiau kaip 128 sesijos, apsimetančios **Chrome 124 naršykle macOS sistemoje**,
skirtos už Cloudflare esančioms aukštesnio lygio paslaugoms. `TlsClient.fetch()` klaidos atveju neleidžia tęsti darbo, kai
savoji vykdymo aplinka nepasiekiama; kviečiančioji šalis gali aiškiai pasirinkti atsarginį variantą už šio apvalkalo ribų.

- Sesijos profilis: `browser: "chrome_124", os: "macos"`
- Tarpinio serverio nustatymas (prioriteto tvarka): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (taip pat mažosiomis raidėmis)
- Skirtasis laikas: `TLS_CLIENT_TIMEOUT_MS` (paveldimas iš `FETCH_TIMEOUT_MS`, numatytoji reikšmė 600000)
- `wreq-js` Response yra suderinamas su fetch (`headers`, `text()`, `json()`, `clone()`, `body`).
- Pirmojo baito stebėjimo mechanizmas (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`
  užbaigiamas, kai tik gaunamos aukštesnio lygio paslaugos antraštės, todėl vien `TLS_CLIENT_TIMEOUT_MS` negali apriboti
  atsako turinio, kuris niekada nepateikia pirmojo baito. `guardTlsFirstByte()` lenktynių principu vykdo pirmąjį atsako turinio `read()`
  ir `TLS_FIRST_BYTE_WATCHDOG_MS` (numatytoji reikšmė `10000`, `0` jį išjungia); tinkamai veikiantis atsako turinys
  nepaveikiamas, o užstrigęs atsako turinys atšaukia wreq skaitytuvą ir leidžia `proxyFetch` esamai
  TLS atsarginio varianto logikai pereiti prie tiesioginio / tarpinio serverio skirstytuvo (pakartotinai saugiai nevykdoma užklausa, pvz.,
  POST su turiniu, vis tiek pateikia klaidą, užuot buvusi nepastebimai pakartota).

### Žiniatinklio slapukų teikėjo transportas — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` yra bendras penkių toliau nurodytų specializuotų
žiniatinklio slapukų transportų adapteris. Kiekvienas plonas teikėjo apvalkalas pasirenka naršyklės / OS profilį. Adapteris
naudoja vieną wreq vykdymo aplinkos įkėliklį ir transporto telkinį iš `open-sse/utils/tlsClient.ts`, indeksuojamą pagal
profilį + OS + nustatytą tarpinį serverį, o kiekvienoje užklausoje naudojama `cookieMode: "ephemeral"`. Todėl paskyros ir
užklausos bendrina transporto lygmens ryšius, tačiau niekada nebendrina wreq sesijos ar slapukų saugyklos.

| Teikėjas   | Profilis      | Emuliuojama OS | Srauto EOF strategija                   |
| ---------- | ------------- | -------------- | --------------------------------------- |
| Claude     | `chrome_146`  | Linux          | įtraukti `[DONE]`                       |
| Perplexity | `firefox_151` | macOS          | įtraukti `event: end_of_stream`         |
| Grok       | `chrome_146`  | Linux          | neįtraukti `[DONE]`                     |
| Notion     | `chrome_146`  | Windows        | įtraukti `[DONE]`                       |
| LMArena    | `chrome_146`  | Windows        | nėra žymeklio; užverti gavus savąjį EOF |

- Srautinis perdavimas tiesiogiai naudoja savosios sistemos atsako `ReadableStream`; laikinasis failas ar pagalbinis
  procesas nesukuriamas.
- Prieš pateikiant srautą patikrinama iki 256 pradinių baitų. SSE teikėjai buferizuoja ne SSE
  klaidas; Grok/LMArena susieja Cloudflare iššūkius su `403`, o HTML tarpinius puslapius – su `502`.
- Savasis užklausos skirtasis laikas ir toliau apribojamas absoliučiu JS galutiniu terminu. Užstrigus užklausai,
  anuliuojamas ir užveriamas tik paveiktas profilio / OS / tarpinio serverio transportas, o prieš kitą užklausą jis sukuriamas iš naujo.
- Tarpinio serverio nustatymo prioritetas: kiekvieno iškvietimo `proxyUrl` → užklausos aprėpties paskyros / valdymo skydelio kontekstas →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (įskaitant variantus mažosiomis raidėmis). Nustatymo klaidos neleidžia tęsti darbo,
  užuot nutekinusios tiesioginį ryšį. LMArena sąmoningai atlieka nustatymą pagal `arena.ai`.
- `byteResponse` grąžina pagal turinio tipą suformuotą `data:` URL, nesugadindamas UTF-8.
- Klaidos yra `TlsClientUnavailableError` (paketas / priedas nepasiekiamas), `TlsClientHangError`
  (viršytas galutinis terminas) ir `WreqTransportCapacityError` (bendras sesijos talpos klaidos kodas),
  kai visi 128 apriboti profilio / OS / tarpinio serverio lizdai yra aktyvūs arba uždaromi.

Pirmiau aprašytas bendrasis `TlsClient` išlieka specializuotas nuolatinei naršyklės palaikomai slapukų
būsenai. Abu keliai pakartotinai naudoja vieną podėlyje saugomą wreq modulio įkėliklį ir proceso gyvavimo ciklo kablį; jų telkiniai lieka
atskiri, nes jų slapukų gyvavimo trukmės sąmoningai skiriasi.

Profilius palaiko fiksuotos versijos paketas, tačiau faktinis WAF priėmimas gali kisti nepriklausomai
nuo vietinių sutarties testų. Prieš teigdami, kad pasiektas lygiavertiškumas su aukštesnio lygio paslaugos naršykle,
patikrinkite pirštų atspaudų pakeitimus naudodami aiškiai autorizuotą realią paskyrą.

## Claude Code maskavimo rinkinys

Kai `cliCompatMode` įjungtas, OmniRoute pertvarko siunčiamas Claude užklausas taip, kad jų nebūtų galima atskirti nuo `claude-cli` srauto. Kartu veikia trys moduliai:

### `claudeCodeFingerprint.ts`

Apskaičiuoja 3 simbolių `cc_version` kontrolinį atspaudą, įterpiamą į atsiskaitymo antraštę:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (įrašyta tiesiogiai; sutampa su oficialiu klientu)
- Įvestys: pirmojo naudotojo pranešimo teksto simboliai, esantys 4, 7 ir 20 indeksuose, bei versijos eilutė
- Išvestis: 3 simbolių šešioliktainis prefiksas

### `claudeCodeCCH.ts` (kliento turinio maiša)

Serverio pusės vientisumo patikra, kurią oficiali Claude Code CLI apskaičiuoja naudodama Bun/Zig. OmniRoute ją iš naujo įgyvendina su `xxhash-wasm`:

1. Serializuoti turinį naudojant `cch=00000;` vietos rezervavimo reikšmę
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. Nuliais iš kairės papildytas 5 simbolių mažųjų raidžių šešioliktainis skaičius
4. Pakeisti `cch=00000;` apskaičiuotu žetonu

Konstantos:

- Pradinė reikšmė: `0x6e52736ac806831e`
- Šablonas: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

Po pirmojo „jautrių“ klientų pavadinimų simbolio įterpia Unicode **nulinio pločio jungiklį** (`U+200D`), kad aukštesnio lygio filtrai negalėtų jų aptikti naudodami grep. Numatytasis žodžių sąrašas:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Taikoma: `system` blokams, visam `messages[].content` ir `tools[].description` / `tools[].function.description` turiniui. Operatorius gali pakeisti naudodamas `setSensitiveWords()`.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` teikėjai

Trečiųjų šalių Anthropic tarpinėms tarnyboms, priimančioms tik „tikrą Claude Code“ srautą:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- Pagal numatytuosius nustatymus `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- Kiekvieno ryšio perjungiklis „Įjungti redact-thinking beta“ prideda `redact-thinking-2026-02-12`, kai CC Compatible aukštesnio lygio tarnybai konkrečiai reikia redaguotų samprotavimo srautų
- Kiekvieno ryšio perjungiklis „Įjungti apibendrinto samprotavimo rodymą“ išsaugo `providerSpecificData.requestDefaults.summarizeThinking` ir prideda `display: "summarized"` prie CC Compatible samprotavimo užklausų, kuriose rodymo režimas dar nenustatytas
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x šeima)
- Numatytasis kelias: `/v1/messages?beta=true`

Susiję to paties rinkinio moduliai:

- `claudeCodeConstraints.ts` — temperatūros ir podėlio valdymo taisyklės
- `claudeCodeToolRemapper.ts` — įrankių pavadinimų persiejimas
- `claudeCodeExtraRemap.ts` — papildomas naudingosios apkrovos normalizavimas

## Antigravity Stealth

Antigravity užklausos išsaugoti skambinančiojo tekstą baitais už baitą. OmniRoute neįterpia nulinio pločio simbolių į raginimus ar rename/inject įrankius, kad imituotų IDE klientą.

### `antigravityHeaderScrub.ts`

Nerūdijančio plieno SDK žymeklius (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) prieš persiuntimą nulupame.

### ⚠️ rizika: `ANTIGRAVITY_CREDITS=always` (sąskaitos uždraudimo karštoji vieta)

`ANTIGRAVITY_CREDITS=always` (sunaudoja `open-sse/executors/antigravity.ts`) maršrutai** kas** pateikite užklausą per Antigravity AI kreditų viršijimą (sumokėtus Google kreditus), o ne leiskite Google laisvos pakopos kvotos vartams. Tai dokumentuojama kaip savybė, bet taip yra** vienintelė dažniausiai matoma paslaugų teikimo sąlygų pažeidimo ataskaita** — kelios Google Ultra paskyros buvo uždraustos naudojant `403 / "service disabled for ToS violation" / insufficient_quota` po kelių valandų su `=always`.

Prieš srovę vykdomas vykdymas**Google pusė** , nieko OmniRoute negali užkirsti kelio. Dėl env var pavadinimo ir esamų dokumentų jis skamba kaip saugi rankenėlė, kurią galima apversti; tai ne.

**Kodėl dėl to piktnaudžiavimo aptikimas yra agresyvesnis nei naudojant tik laisvos pakopos:**

- Nuolatinės automatizuotos išlaidos vienoje Google paskyroje žymimos kitaip nei nemokamos pakopos įvykdymas-kvota ir sustojimas.
- Kredito viršijimas neturi normos lubų, todėl netinkamai sukonfigūruotas klientas per kelias minutes gali sudeginti kelis šimtus USD ir atrodyti kaip API rakto perpardavimas arba robotų srautas.
- Keli OmniRoute naudotojai, lygiagrečiai gaunantys perviršio kreditus iš to paties išorinio IP sujungia signalą.

**Rekomenduojama laikysena:**

1. Išsaugokite numatytąjį `ANTIGRAVITY_CREDITS=off` nebent operatorius aiškiai prisiima apmokėto kredito ir sąskaitos vykdymo riziką. `retry` pirmiausia išsiunčia įprastą užklausą ir įveda kreditus ne daugiau kaip vieną kartą po tinkamos kvotos 429; `always` įveda kreditus pagal pirmą užklausą.
2. **Paskirstykite apkrovą tarp paslaugų teikėjų naudodami automatinį derinimą** (`model: "auto"` arba `kr/glm/etc` -combo), užuot užpildę vieną Antigravity paskyrą.
3. **Nustatykite jungties RPM ribas** Antigravity teikėjo redagavimo puslapyje (Dashboard → Providers → Antigravity → connection → rate limit). 30–60 RPM yra tinkama viršutinė riba ilgalaikiam naudojimui.
4. **Naudokite stabilų, operatoriaus valdomą tinklo ryšį** ir venkite dalytis viena paskyra nesusijusiems naudotojams ar darbo krūviams.
5. **Jei uždrausta** : apeliacija per `support.google.com` → „Atkurti Workspace/Account prieigą“ ir tiksliai Google `quota_exceeded` / `service disabled` atsakymo tekstas. Atkūrimas negarantuojamas.

Aplinkos nuoroda dokumentuoja kiekvieno kreditų režimo sąskaitą ir išlaidas.

#### Ne tik `=always`: Antigravity OAuth maršrutizavimas apskritai

Sustabdymas neapsiriboja kredito perviršiu. 2026 m. lapkričio mėn. ataskaitose (#19223, #19266) aprašomos kelios Google paskyros, sustabdytos nukreipiant per `antigravity` ir `agy` (Antigravity CLI) teikėjus su:

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

Abu teikėjai autentifikuojasi naudodami Antigravity produkto OAuth seansą, apie kurį įspėja prietaisų skydelio pranešimas apie riziką („Šis teikėjas naudoja jūsų oficialų produktą session/OAuth, kuris nėra įgaliotas naudoti proxy/router “) prieš prijungiant ryšį. Nė viena iš aukščiau pateiktų rekomendacijų neleidžia naudoti tokio naudojimo; jie tik sumažina vienos paskyros srautą.

**Įgaliotos API sąsajos Gemini modeliams.** Google siūlo programinę prieigą prie Gemini per savo APIs, kurią OmniRoute palaiko kaip įprastus API raktų teikėjus:

| Teikėjo ID | Prietaisų skydelio pavadinimas | Kredencialas                                                                          |
| ---------- | ------------------------------ | ------------------------------------------------------------------------------------- |
| `gemini`   | Gemini (Google AI Studio)      | Gemini API raktas iš Google AI Studio (galima nemokama pakopa)                        |
| `vertex`   | Viršūnė AI                     | Paslaugos paskyra JSON, OAuth prieigos raktas arba Vertex Express API raktas (Gemini) |

Šie teikėjai naudoja kredencialų Google problemas API prieigai, skirtingai nei Antigravity produkto seanso metu. Jomis ne kiekvienas naudojimas atitinka reikalavimus arba pašalinama vykdymo rizika: kiekvienai jų taikomos atskiros sąlygos, kurias operatorius turi patikrinti, kad būtų naudojamasi. Pavyzdžiui, [Gemini API papildomos paslaugų teikimo sąlygos](https://ai.google.dev/gemini-api/terms) leidžia teikti tik mokamas paslaugas, kai API klientai yra prieinami vartotojams Europos ekonominėje erdvėje, Šveicarijoje arba Jungtinėje Karalystėje, o į nemokamoms paslaugoms išsiųstas turinys gali būti naudojamas Google produktams tobulinti. Vietoj to Vertex AI patenka į Google Cloud sąlygas ( [specifinės paslaugos sąlygos](https://cloud.google.com/terms/service-terms) ). Kainos ir kvotos atitinka šias API sąlygas, o ne Antigravity prenumeratą.

Operatoriai, norintys išvengti anksčiau aprašytų Antigravity sustabdymų, patikrinę, ar jų naudojimas atitinka teikėjo sąlygas, turėtų nukreipti Gemini srautą per vieną iš šių teikėjų, o ne `antigravity` / `agy`.

Lietimo taškai:

- `open-sse/executors/antigravity.ts` — skaito `process.env.ANTIGRAVITY_CREDITS`

## CLI kontrolinių požymių registras — `open-sse/config/cliFingerprints.ts`

Kiekvienam teikėjui skirta lentelė, nustatanti **tikslią** antraščių ir JSON turinio laukų tvarką, užfiksuotą iš oficialių CLI mitmproxy trasų. Šiuo metu užregistruoti: `codex`, `claude`, taip pat vykdymo metu nustatomi profiliai faile `providerHeaderProfiles.ts`, skirti `antigravity` ir `github`.

```ts
interface CliFingerprint {
  headerOrder: string[]; // skiriamos didžiosios ir mažosios raidės
  bodyFieldOrder: string[]; // aukščiausio lygio JSON raktai
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Įjunkite arba išjunkite kiekvienam teikėjui naudodami aplinkos kintamuosius (žr. toliau). Kai ši funkcija išjungta, antraštės ir turinio raktai pateikiami tokia tvarka, kokią nustatė Node/JSON, todėl juos lengva identifikuoti pagal kontrolinius požymius.

## MITM tarpinis serveris (Antigravity, Linux/macOS/Windows)

CLI, kurių dvejetainių failų negalima nukreipti naudojant `OPENAI_BASE_URL`, atveju OmniRoute paleidžia vietinį TLS užbaigiantį tarpinį serverį. Galiniai taškai yra kataloge `src/app/api/cli-tools/antigravity-mitm/`.

| Metodas | Galinis taškas                          | Paskirtis                                             |
| ------- | --------------------------------------- | ----------------------------------------------------- |
| GET     | `/api/cli-tools/antigravity-mitm`       | Būsena — veikia, pid, dnsConfigured, certExists       |
| POST    | `/api/cli-tools/antigravity-mitm`       | Paleisti MITM (reikalingi `apiKey` ir `sudoPassword`) |
| DELETE  | `/api/cli-tools/antigravity-mitm`       | Sustabdyti MITM                                       |
| GET     | `/api/cli-tools/antigravity-mitm/alias` | Pateikti modelių alternatyviuosius vardus             |
| PUT     | `/api/cli-tools/antigravity-mitm/alias` | Išsaugoti įrankio modelių alternatyviuosius vardus    |

Perimamas tikslinis pagrindinis kompiuteris: **`daily-cloudcode-pa.googleapis.com`** („Antigravity“ aukštesniojo lygio serveris).

### Paleidimo seka (`src/mitm/manager.ts::startMitm`)

1. Sugeneruoti savarankiškai pasirašytą sertifikatą naudojant `selfsigned` (RSA-2048, SHA-256, 1 metams) — `cert/generate.ts`
2. Įdiegti sertifikatą sistemos patikimų sertifikatų saugykloje — `cert/install.ts`
3. Pridėti pagrindinių kompiuterių įrašą `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. Paleisti `src/mitm/server.cjs` su `ROUTER_API_KEY` ir `MITM_LOCAL_PORT` (numatytoji reikšmė `443`)
5. Įrašyti PID į `<DATA_DIR>/mitm/.mitm.pid`

### Dinaminis Linux patikimų sertifikatų saugyklos aptikimas — `cert/install.ts`

`getLinuxCertConfig()` nuosekliai tikrina prioritetų sąrašą ir pasirenka pirmą esamą katalogą:

| Distribucijų šeima       | Katalogas                                   | Atnaujinimo komanda      |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Sertifikato failo pavadinimas: `omniroute-mitm.crt`. Kontrolinis požymis tikrinamas naudojant `getCertFingerprint()` (DER SHA-1).

Be to, kai pasiekiama `certutil`, `updateNssDatabases()` įdiegia sertifikatą kiekvieno naudotojo NSS duomenų bazėse: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, visuose Firefox profiliuose (įskaitant snap), naudodama slapyvardį **`OmniRoute MITM Root CA`**.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** padidintomis teisėmis paleista PowerShell → `certutil -addstore Root`

### Autentifikavimas

Visuose MITM galiniuose taškuose privalomas valdymo autentifikavimas (`requireCliToolsAuth`). Sudo slaptažodis laikomas modulio srityje (niekada ne `globalThis`) ir išvalomas iškvietus `stopMitm()`.

## Kontrolinių atspaudų atnaujinimas paslaugų teikėjui juos pakeitus

1. Užfiksuokite oficialaus CLI srautą naudodami `mitmproxy` (TLS perėmimas ir išklotinė)
2. Išgaukite JA3/JA4 ir tikslų antraščių eiliškumą
3. Atnaujinkite atitinkamą `CLI_FINGERPRINTS[...]` įrašą
4. Atnaujinkite atitinkamą numatytąją `*_USER_AGENT` reikšmę faile `.env.example`
5. Jei pasikeitė pati TLS prisijungimo procedūra, atnaujinkite atitinkamą paslaugų teikėjo apvalkalą arba wreq-js parinktį `browser:`
6. Paleiskite konkrečiam paslaugų teikėjui skirtus TLS testus ir rankinį bandomąjį testą su veikiančia paslaugų teikėjo sistema
7. Išleiskite pataisos leidimą; dokumentuokite pakeitimą faile `CHANGELOG.md`
