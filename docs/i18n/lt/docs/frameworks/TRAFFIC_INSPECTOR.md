Traffic Inspector yra „OmniRoute“ integruota HTTPS srauto derinimo priemonė — į „Charles Proxy“ / „mitmweb“ / „HTTP Toolkit“ panašus įrankis, kuris **atpažįsta LLM** ir **agentus**. Jis pasiekiamas adresu `/dashboard/tools/traffic-inspector` ir realiuoju laiku gauna srautą iš iki 5 vienu metu veikiančių fiksavimo šaltinių.

**Vieta valdymo skydelyje:** `/dashboard/tools/traffic-inspector`
**Šoninės juostos grupė:** Įrankiai (po AgentBridge)
**Taip pat žr.:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge yra 1-asis fiksavimo režimas.

### Architektūra vienoje pastraipoje

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) yra bendrinamas atmintyje saugomas žiedinis buferis (numatytoji talpa — 1000 įrašų; ją galima konfigūruoti naudojant `INSPECTOR_BUFFER_SIZE`). Visi fiksavimo šaltiniai rašo į jį naudodami `push()`. Buferio klasė suskirsto kiekvieną įrašą į kategorijas naudodama `kindDetector.ts` (nustato, ar tai LLM užklausa), apskaičiuoja `contextKey` (sistemos raginimo SHA-256 kontrolinį atspaudą) ir siunčia duomenis visiems WebSocket prenumeratoriams per `globalTrafficBuffer.subscribe()`. Valdymo skydelis prisijungia per `GET /api/tools/traffic-inspector/ws`; prisijungus jam pateikiama momentinė kopija, o vėliau siunčiami `new`/`update`/`clear` įvykiai.

## §2 Fiksavimo režimai

Traffic Inspector palaiko **5 vienu metu veikiančius fiksavimo šaltinius**. Kiekvieną iš jų galima įjungti arba išjungti atskirai. Kiekvieno `InterceptedRequest` (`src/mitm/inspector/types.ts`) laukas `source` turi vieną iš šių reikšmių: `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"` arba `"tproxy"`.

### 1 režimas — AgentBridge (numatytasis, visada įjungtas)

**Šaltinis:** AgentBridge apdorojimo programos (`src/mitm/handlers/base.ts`)
**Mechanizmas:** Kiekvienas `intercept()` iškvietimas klasėje `MitmHandlerBase` prieš persiųsdamas iškviečia `hookBufferStart()`, o baigęs — `hookBufferUpdate()`. Nereikia jokios papildomos konfigūracijos — veikia vos paleidus AgentBridge.
**Aprėptis:** 9 IDE agentai, sukonfigūruoti AgentBridge
**Pastaba:** `InterceptedRequest` laukas `source` = `"agent-bridge"`

### 2 režimas — pasirinktiniai pagrindiniai kompiuteriai (DNS peradresavimas)

**Šaltinis:** Naudotojo apibrėžtas pagrindinių kompiuterių sąrašas (lentelė `inspector_custom_hosts`)
**Mechanizmas:** Per NS pridėjus pagrindinį kompiuterį, į `/etc/hosts` įrašoma `127.0.0.1 <host>` (reikia sudo). Esamas AgentBridge MITM serveris (443 prievadas) dinamiškai sugeneruoja naujo pagrindinio kompiuterio SNI sertifikatą.
**Aprėptis:** Bet kuri programa, naudojanti pridėtą pagrindinį kompiuterį — programos konfigūracijos keisti nereikia
**Pastaba:** `source` = `"custom-host"`

Naudojimo atvejų pavyzdžiai:

- Stebėti `api.openai.com` srautą iš Python scenarijų
- Derinti `my-internal-llm.company.com`
- Fiksuoti srautą iš tame pačiame tinkle esančių mobiliųjų įrenginių (naudojant ARP klastojimą — skirta pažengusiesiems)

### 3 režimas — HTTP_PROXY klausymo tarnyba (8080 prievadas)

**Šaltinis:** Programos, naudojančios `HTTP_PROXY`/`HTTPS_PROXY` aplinkos kintamuosius
**Mechanizmas:** Antrinė klausymo tarnyba, veikianti 8080 prievade (`src/mitm/inspector/httpProxyServer.ts`) ir atliekanti standartinio tiesioginio HTTP/HTTPS tarpinio serverio funkciją. Priima `CONNECT` tunelius (HTTPS) ir tiesiogines HTTP užklausas.
**Aprėptis:** Bet kuri programa, naudojanti `HTTP_PROXY` aplinkos kintamąjį — nereikia keisti DNS ir nereikia sudo
**Pastaba:** `source` = `"http-proxy"`

```bash
# Greitas vienos komandos srauto fiksavimas:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# Nuolatinis fiksavimas apvalkalo seanso metu:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS apribojimas:** HTTPS perduodamas per paprastą `CONNECT` tunelį: klausymo tarnyba persiunčia užšifruotus baitus jų nekeisdama ir įrašo tik metaduomenis (pagrindinį kompiuterį, prievadą, laiko informaciją). Ji niekada neiššifruoja HTTPS, o nustatymo, kuris įjungtų šio režimo iššifravimą, nėra. Norėdami fiksuoti HTTPS turinį, nukreipkite pagrindinį kompiuterį per 1 režimą (AgentBridge), 2 režimą (pasirinktiniai pagrindiniai kompiuteriai) arba 5 režimą (TPROXY iššifravimas).

**Prievado konfliktas:** Jei 8080 prievadas naudojamas, AgentBridge grąžina 409 su struktūrizuota klaida. Pakeiskite prievadą naudodami `INSPECTOR_HTTP_PROXY_PORT` aplinkos kintamąjį.

### 4 režimas — visos sistemos tarpinis serveris (skirta pažengusiesiems, pasirenkama)

**Šaltinis:** OS lygmens tarpinio serverio nustatymai (taikomi visoms kompiuterio programoms)
**Mechanizmas:** Naudoja OS API, kad per HTTP_PROXY klausymo tarnybą peradresuotų visą HTTP/HTTPS srautą:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **Aprėptis:** Kiekviena kompiuterio programa, naudojanti sistemos tarpinio serverio nustatymus
  **Pastaba:** `source` = `"system-proxy"`

**Saugos mechanizmai:**

- Automatinio išjungimo laikmatis (numatytoji reikšmė — 30 min., konfigūruojamas naudojant `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES`)
- Ankstesnė sistemos tarpinio serverio būsena išsaugoma DB ir atkuriama atšaukus pakeitimus
- Jei naudotojas išeina iš puslapio, kol funkcija aktyvi, valdymo skydelyje rodomas raginimas „Atkuriami sistemos tarpinio serverio nustatymai“
- NS rodomas ženklelis `⚠ Pažengusiesiems` ir aiškus patvirtinimo žymimasis langelis

### 5 režimas — TPROXY skaidrusis iššifravimas (Linux, root, pasirenkama)

**Šaltinis:** Branduolio TPROXY + strateginis maršruto parinkimas (`src/mitm/tproxy/`)
**Mechanizmas:** Nauji vietiniai į tikslinį prievadą (numatytasis — `443`) nukreipti išeinantys TCP ryšiai pažymimi grandinėje `mangle OUTPUT`, `ip rule` peradresuoja pažymėtus paketus vietiniam pristatymui, o grandinės `mangle PREROUTING` paskirties vieta `TPROXY` perduoda juos skaidriajai (**IP_TRANSPARENT**) klausymo tarnybai (numatytasis prievadas — `8443`). Klausymo tarnyba užbaigia TLS ryšį naudodama dinaminės CA **kiekvienam SNI pagrindinio kompiuterio vardui pareikalavus** išduotą galutinio subjekto sertifikatą, užfiksuoja iššifruotus duomenų mainus ir persiunčia iš naujo užšifruotą užklausą į pradinę paskirties vietą.
**Aprėptis:** **Bet kokie** paskirties pagrindiniai kompiuteriai tiksliniame prievade — nereikia `/etc/hosts` klastojimo, `HTTP_PROXY` aplinkos kintamojo ar visos sistemos tarpinio serverio pakeitimų. Perimamo proceso konfigūracijos keisti nereikia, tačiau jis turi pasitikėti dinamine CA.
**Pastaba:** `source` = `"tproxy"`

**Reikalavimai:** Tik Linux (**IP_TRANSPARENT** veikia tik Linux), galimybė **CAP_NET_ADMIN** (root) ir savasis N-API priedas, kurį reikia sukompiliuoti naudojant C įrankių grandinę (`npm run build:native:tproxy`). Kai funkcija nepasiekiama, valdymo skydelio jungiklis išjungiamas ir rodoma paaiškinamoji etiketė „TPROXY iššifravimui reikia Linux + root + savojo priedo“. Užkardos taisyklės pritaikomos ir atšaukiamos tranzakciniu būdu (dėl gedimo niekada nelieka `mangle` taisyklės), o paleidus sistemą iš naujo jos pašalinamos. SO_MARK pagrįsta apsauga nuo ciklų neleidžia pakartotinai perimti paties tarpinio serverio iš naujo užšifruoto persiunčiamo srauto.

Tai yra didelė posistemė, turinti atskirą operatoriaus vadovą — išsamų užkardos receptą, kiekvienam SNI dinamiškai veikiančios CA ir patikimų sertifikatų saugyklos diegimo programą, tik vietinį maršrutą, išsamią informaciją apie apsaugą nuo ciklų ir konfigūracijos schemą žr. `docs/security/MITM-TPROXY-DECRYPT.md` (git; nekompiliuojama į `/docs`). Jungiklis valdomas naudojant `GET / POST / DELETE /api/tools/agent-bridge/tproxy` (pastaba: maršrutas yra su AgentBridge prefiksu, o ne su Traffic Inspector prefiksu).

### 3.2 Užklausų sąrašas (kairysis skydelis)

- **Virtualizuotas** (`useVirtualList` + `ResizeObserver`): apdoroja 1000 elementų neužstrigdamas
- **Automatinis slinkimas** su perjungikliu, leidžiančiu jį pristabdyti peržiūros metu
- **Spalvomis pažymėtos būsenos**: žalia (2xx), geltona (3xx), raudona (4xx/5xx), pilka (vykdoma)
- **Agento jaustukas**: 🔵 Antigravity, 🟢 Copilot, 🟠 Kiro, 🟣 Codex, 🔷 Cursor, 🟤 Zed, 🟡 Claude Code, ⚫ Open Code, 🌐 pasirinktinis serveris
- **Konteksto spalvinė juosta**: 1 px kairysis kraštas, kurio spalva nustatoma pagal `contextKey` (sistemos raginimo SHA-256) — vizualiai sugrupuoja susijusius pokalbius
- **Atidėtasis turinio įkėlimas**: išsamios informacijos kortelėse pateikiamas tik pasirinktos užklausos turinys (taip išvengiama 1000 × 1 MB turinių atvaizdavimo)

## §4 LLM pritaikytos funkcijos

### 4.1 Tipo aptikimo priemonė (`src/mitm/inspector/kindDetector.ts`)

Kiekviena užklausa klasifikuojama kaip `"llm"`, `"app"` arba `"unknown"` naudojant 4 požymius:

1. **Hostų registras** — ~18 žinomų LLM API hostų vardų (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot ir kt.)
2. **Kelio šablonai** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses` ir kt.
3. **Turinio struktūra** — aptinkami `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input` laukai
4. **User-agent požymiai** — `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor` UA eilutėje

Naudojant 2 režimą pridėti pasirinktiniai hostai paveldi savo `kind` iš formos įvesties (numatytoji reikšmė yra `"custom"`).

### 4.2 SSE sujungimo priemonė (`src/mitm/inspector/sseMerger.ts`)

**Nepriklausoma „clean-room“ realizacija.** Įvykių analizė atitinka
[WHATWG serverio siunčiamų įvykių algoritmą](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream),
o atkūrimas atitinka viešas [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming) ir
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
srautinio perdavimo schemas.

Iš neapdorotų SSE skirtuminių įvykių atkuriamas galutinis asistento pranešimas:

- **Anthropic**: kaupiami `content_block_delta` pagal indeksą; apdorojami `text_delta`, `input_json_delta` (įrankių iškvietimai), `thinking_delta`
- **OpenAI**: kaupiami Chat Completions pasirinkimai / įrankių iškvietimai ir Responses API išvesties elementai
  pagal indeksą
- **Gemini**: kaupiami `candidates[i].content.parts`
- **Nežinomas**: neapdoroti įvykiai grąžinami nepakeisti

Atsakymo skirtuke rodomas perjungiklis: **„Neapdoroti įvykiai ↔ Sujungta“**.

### 4.3 Pokalbio normalizavimo priemonė (`src/mitm/inspector/conversationNormalizer.ts`)

**Nepriklausoma „clean-room“ realizacija.** Normalizavimas apibrėžtas vietinėmis juodosios dėžės
sutartimis ir viešomis OpenAI, Anthropic bei Gemini pranešimų schemomis; joks pirminio
projekto realizacijos kodas nenaudojamas.

Prieš atvaizdavimą OpenAI, Anthropic ir Gemini pranešimų formatai konvertuojami į vieną `NormalizedConversation`:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // pranešimai / turinys / užklausos tekstas iš užklausos turinio
  response: NormalizedTurn[]; // asistento atsakymas (sujungtas naudojant sseMerger)
  contextKey: string | null; // sistemos užklausos SHA-256 kontrolinis atspaudas
}
```

Blokų tipai: `text`, `tool_use`, `tool_result`. Pokalbio skirtuke ši struktūra naudojama nepriklausomai nuo teikėjo.

### 4.4 Konteksto rakto spalvinimas (`src/mitm/inspector/contextKey.ts`)

- Apskaičiuojamas sistemos užklausos `SHA-256` (pirmojo pranešimo su `role:system`, lauko `system` arba Gemini `systemInstruction`)
- Grąžinamas 12 simbolių šešioliktainis prefiksas (`"a3f9c2..."`)
- Sąsaja susieja raktą su deterministine HSL spalva, naudojama kairiojo krašto juostai
- **Filtras „tas pats kontekstas“**: spustelėjus žymą `ctx #a3f`, pridedamas filtras, rodantis tik užklausas su tuo pačiu kontroliniu atspaudu

Tai leidžia lengvai vizualiai atskirti skirtingas „personas“ arba užduotis, vykdomas toje pačioje agento sesijoje.

### 4.5 LLM metaduomenų išgavimas

LLM užklausų skirtuke „LLM informacija“ išgaunami šie duomenys:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // iš užklausos turinio arba atsakymo
  messages: number; // pokalbio žingsnių skaičius
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // true, jei tai SSE atsakymas
  mappedTo: string | null; // x-omniroute-mapped antraštė
  costEstimateUsd: number | null; // numatomos išlaidos pagal OmniRoute kainodarą
}
```

### 4.6 Tiesioginis vykdomų užklausų filtras

Užklausos laukas `status` yra `number | "in-flight" | "error"` — įrašas
pridedamas kaip `"in-flight"` vos prasidėjus užklausai ir **atnaujinamas vietoje**,
kai gaunamas atsakymas (arba klaida). Įrankių juostos perjungiklis **„Tiesiogiai“**
(`liveOnly`, i18n raktas `trafficInspector.liveOnly`) apriboja sąrašą iki įrašų,
kurių `status === "in-flight"`, todėl atviras jungtis galima stebėti realiuoju laiku.

Filtras yra grynasis kliento pusės predikatas faile
`src/lib/inspector/matchesTrafficFilter.ts`:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

Perjungiklio būsena saugoma `useTrafficFilters` (inspektoriaus suvestinės saitai) ir
derinama su kitais filtrais (profilio, hosto, agento, šaltinio, būsenos, konteksto).

### 4.7 Priskyrimas procesui (Linux)

Linux sistemoje kiekvieną perimtą užklausą galima priskirti **ją inicijavusiam vietiniam
procesui**. Prie `InterceptedRequest` pridedami du pasirinktiniai laukai:

```ts
pid?: number;          // inicijavusio proceso ID (tik Linux)
processName?: string;  // inicijavusio proceso pavadinimas (tik Linux)
```

`src/mitm/inspector/processAttribution.ts` susieja ryšio _kliento_
laikinąjį prievadą su PID ir pavadinimu:

1. Nuskaitomi `/proc/net/tcp` ir `/proc/net/tcp6`, kad būtų rastas prievado
   lizdo inode (`parseProcNetTcpForInode`, grynasis analizatorius, kurį galima testuoti naudojant fikstūras).
2. `/proc/<pid>/fd/` kataloge ieškoma simbolinės nuorodos į `socket:[<inode>]`.
3. Proceso pavadinimas nuskaitomas iš `/proc/<pid>/comm`.

1 sekundės TTL podėlis apriboja procfs nuskaitymo sąnaudas esant apkrovai. Priskyrimas
atliekamas **kiek įmanoma** — bet kokios trikties atveju grąžinama `null`, o duomenų fiksavimas
niekada neblokuojamas. macOS/Windows sistemose funkcija grąžina `null` (pakaitinė realizacija;
`lsof`/`GetExtendedTcpTable` palaikymas bus pridėtas vėliau).

## §6 Saugumas

Traffic Inspector rodo **visą perimtą HTTPS srautą**, įskaitant autorizavimo antraštes ir užklausų turinį. Taikomos šios kontrolės priemonės:

| Kontrolės priemonė                             | Išsami informacija                                                                                                                                                                                              |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                                 | Visi maršrutai ir WebSocket galinis taškas pasiekiami tik per loopback sąsają (tai užtikrinama `routeGuard.ts` prieš autentifikavimą)                                                                           |
| **Paslapčių maskavimas**                       | Tiesinis `maskSecret()` skaitytuvas paslepia RFC 6750 Bearer kredencialus, teikėjo prefiksą turinčius raktus ir ilgus neskaidrius prieigos raktus prieš `TrafficBuffer.push()`                                  |
| **Turinio dydžio riba**                        | Turinys, viršijantis `INSPECTOR_MAX_BODY_KB` (numatytoji reikšmė – 1024 KB), sutrumpinamas pateikiant pranešimą `"(sutrumpinta siekiant didesnio našumo)"`                                                      |
| **Antraščių išvalymas**                        | Pavadinimai paverčiami mažosiomis raidėmis; kadravimo, tarpinių mazgų ir tarpinio serverio autentifikavimo antraštės pašalinamos; slapukai visiškai paslepiami; kredencialų reikšmės perduodamos `maskSecret()` |
| **CSP**                                        | Traffic Inspector puslapiams taikoma griežta turinio saugos politika, apsauganti nuo XSS per įterptą atsakymų turinį                                                                                            |
| **Pagal numatytuosius nustatymus neišsaugoma** | `TrafficBuffer` laikomas atmintyje ir prarandamas paleidus serverį iš naujo. Seansai išsaugomi tik tada, kai aiškiai nurodoma juos įrašyti                                                                      |

### Taikomos griežtos taisyklės

| Taisyklė                          | Taikymas                                                                                             |
| --------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Visi HTTP klaidų atsakymai iš Traffic Inspector maršrutų yra išvalomi                                |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` yra LOCAL_ONLY + SPAWN_CAPABLE (sistemos tarpinio serverio komandos) |

### Žinomi apribojimai

- **Visos sistemos tarpinio serverio režimas** veikia visas įrenginio programas, įskaitant VPN klientus ir SSO. Visada naudokite su automatinio išjungimo laikmačiu. Nenaudokite bendro naudojimo įrenginiuose.
- **CONNECT tunelio HTTPS**: 3 režimas (HTTP_PROXY) fiksuoja tik HTTPS paskirties vietų tunelio metaduomenis ir niekada jų neiššifruoja. Taip numatyta – norint iššifruoti, kiekvienas klientas turėtų pasitikėti MITM sertifikatu, todėl klausytuvas išlaiko ištisinį HTTPS šifravimą nuo vieno galinio taško iki kito. Kai reikia HTTPS turinio, naudokite AgentBridge, Custom Hosts arba TPROXY decrypt.
- **Kai kuriuose komponentuose tiesiogiai įrašytos eilutės**: kai kuriuose UI komponentuose (F7/F8) yra nedaug tiesiogiai įrašytų eilučių, kurioms dar netaikomi i18n raktai. Jos dokumentuotos kaip žinomas apribojimas i18n spragų ataskaitoje; jos bus perkeltos per kitą etapą. Paveiktos eilutės yra dekoratyvinės UI žymos, kurių nereikia versti funkciniam naudojimui.

## §7 Trikčių šalinimas

### WebSocket atsijungimas

Jei tiesioginiame sraute rodoma „Atsijungta“:

1. Patikrinkite, ar serveris vis dar veikia: `GET /api/tools/traffic-inspector/capture-modes`
2. Iš naujo įkelkite puslapį — WebSocket prisijungs iš naujo ir gaus naują momentinę kopiją
3. Jei serveris buvo paleistas iš naujo, atmintyje laikomas buferis buvo išvalytas — senų įrašų nebėra, nebent buvo įrašyta sesija

### 8080 prievado konfliktas

Jei nepavyksta paleisti HTTP_PROXY režimo:

```bash
lsof -i :8080    # rasti procesą
```

Pakeiskite prievadą:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### Sistemos tarpinio serverio nuostatos neatkurtos

Jei OmniRoute užstringa, kai aktyvus visos sistemos tarpinio serverio režimas:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

Kitą kartą įkėlus valdymo skydą taip pat bus pasiūlyta „Atkurti sistemos tarpinio serverio nuostatas“, jei aptikta duomenų bazės būsena rodys, kad tarpinis serveris buvo aktyvus.

### Buferis pilnas

Kai buferis pasiekia `INSPECTOR_BUFFER_SIZE` dydį (numatytoji reikšmė — 1000), nauji įrašai išstumia seniausius. Jei prarandamos svarbios užklausos:

- Padidinkite `INSPECTOR_BUFFER_SIZE` (pvz., iki 5000) — taip sunaudojama daugiau atminties, bet įrašai išlaikomi ilgiau
- Įrašykite sesiją, kad aktualus intervalas būtų išsaugotas duomenų bazėje
