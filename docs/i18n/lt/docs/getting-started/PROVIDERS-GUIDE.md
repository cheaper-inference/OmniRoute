## Kas yra teikėjas?

Įsivaizduokite teikėją kaip **mobiliojo ryšio operatorių**. Kaip skambinti reikia mobiliojo ryšio operatoriaus, taip DI modeliams naudoti reikia DI teikėjo. OmniRoute yra tarsi telefonas, veikiantis su **visais operatoriais** — galite automatiškai juos perjungti.

### Teikėjų tipai

| Tipas                     | Kas tai yra                          | Pavyzdžiai                      | Kaina                       |
| ------------------------- | ------------------------------------ | ------------------------------- | --------------------------- |
| **Nemokamas**             | Mokėti nereikia                      | Kiro, Pollinations              | $0                          |
| **API raktas**            | Reikia API rakto                     | OpenAI, Anthropic, Google       | Mokama pagal naudojimą      |
| **OAuth**                 | Prisijungiama naudojant savo paskyrą | Claude Code, GitHub Copilot     | Prenumerata                 |
| **Žiniatinklio slapukas** | Naudojama jūsų naršyklės sesija      | ChatGPT Web (Codex), Gemini Web | $0 (naudojama jūsų paskyra) |

### Žiniatinklio slapukų teikėjai

Bendrąsias sąrankos instrukcijas, apribojimus, trikčių šalinimo informaciją ir konkretiems teikėjams skirtas autentifikavimo gaires rasite faile **[WEB-COOKIE-GUIDE.md](./WEB-COOKIE-GUIDE.md)**.

## Greitoji pradžia: prijunkite pirmąjį teikėją

### Pasirenkama nemokamo teikėjo sąranka pirmojo paleidimo metu

Pirmojo paleidimo vediklyje pateikiama atskira kortelė **Nustatyti nemokamus teikėjus**. Pagal OmniRoute teikėjų, kuriems nereikia tapatybės nustatymo, registrą sudaromas aktualus
tinkamų teikėjų sąrašas, kurį prieš patvirtindami galite peržiūrėti ir panaikinti atskirų
teikėjų pasirinkimą. OmniRoute pateikia teikėjo įspėjimą ir nuorodą į jo svetainę,
kad pirmiausia galėtumėte peržiūrėti trečiosios šalies sąlygas, privatumo nuostatas, pasiekiamumą ir užklausų dažnio apribojimus.

Šis veiksmas yra pasirenkamas: užbaigus vediklį nemokamų teikėjų ryšiai niekada nesukuriami nepastebimai.
Sukuriami tik dar nepridėti teikėjai, esami individualiai sukonfigūruoti ryšiai
nekeičiami, o sukurti, jau sukonfigūruoti ir nesėkmingai pridėti teikėjai nurodomi atskirai. Gavę
dalinį rezultatą galite saugiai pakartoti bandymą tik su nesėkmingai pridėtais teikėjais.

### A variantas: nemokamas teikėjas (nereikia kredito kortelės)

1. Atidarykite valdymo skydelį adresu `http://localhost:20128`
2. Eikite į **Teikėjai** → **Pridėti teikėją**
3. Pasirinkite vieną iš šių nemokamų teikėjų:
   - **Kiro AI** — Nemokami Claude modeliai (tapatybės nustatyti nereikia)
   - **Pollinations** — Nemokami GPT-5, Claude, Gemini (rakto nereikia)
   - **LongCat** — 10 mln. nemokamų žetonų (vienkartinis paketas, reikalinga paskyra ir KYC)
   - **Cloudflare AI** — Daugiau nei 50 modelių, 10 tūkst. neuronų per dieną
   - **MLX Gemma 26B** — Vietinis Apple Silicon modelis (~38.5 žet./s, ~15.9GB RAM)
   - **MLX Qwen 3.8 27B** — Vietinis Apple Silicon modelis (~9.1 žet./s, ~13.1GB RAM)
4. Spustelėkite **Prisijungti**
5. Baigta! Dabar galite nemokamai naudotis DI.

### B variantas: API rakto teikėjas (mokamas)

1. Gaukite API raktą teikėjo svetainėje:
   - **OpenAI**: https://platform.openai.com/api-keys
   - **Anthropic**: https://console.anthropic.com/
   - **Google**: https://aistudio.google.com/apikey
   - **DeepSeek**: https://platform.deepseek.com/
   - **Groq**: https://console.groq.com/
2. Atidarykite valdymo skydelį adresu `http://localhost:20128`
3. Eikite į **Teikėjai** → **Pridėti teikėją**
4. Pasirinkite savo teikėją
5. Įklijuokite savo API raktą
6. Spustelėkite **Prisijungti**
7. Baigta! Dabar galite naudotis to teikėjo modeliais.

### C variantas: OAuth teikėjas (prenumerata)

1. Atidarykite valdymo skydelį adresu `http://localhost:20128`
2. Eikite į **Teikėjai** → **Pridėti teikėją**
3. Pasirinkite savo teikėją (pvz., Claude Code, GitHub Copilot)
4. Spustelėkite **Prisijungti naudojant OAuth**
5. Prisijunkite prie savo paskyros
6. Baigta! Dabar galite naudotis į prenumeratą įtrauktais modeliais.

### D variantas: vietiniai MLX modeliai (Apple Silicon)

Apple Silicon Mac kompiuteriuose su bendrąja atmintimi OmniRoute leidžia prisijungti prie vietinių MLX modelių, veikiančių per `mlx-lm.server`, kaip prie įprastų vietinių teikėjų, suderinamų su OpenAI.

#### Būtinosios sąlygos

- **Apple Silicon Mac** (M1/M2/M3/M4); rekomenduojama bent 24GB bendrosios atminties
- **uv** paketų tvarkytuvė: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- **mlx-lm**: `uv pip install mlx-lm`

#### Greitoji pradžia

1. **Įdiekite priklausomybes**:

   ```bash
   # Įdiekite uv, jei jis dar neįdiegtas
   curl -LsSf https://astral.sh/uv/install.sh | sh

   # Įdiekite mlx-lm
   uv pip install mlx-lm
   ```

2. **Paleiskite MLX serverius rankiniu būdu** (atskiruose terminaluose):

   ```bash
   # 1 terminalas: Gemma 4 26B A4B IT-QAT (prievadas 11435)
   uv run mlx_lm.server --model mlx-community/gemma-4-26B-A4B-it-qat-q4_0-mlx-aligned --port 11435 --host 127.0.0.1

   # 2 terminalas: Qwen 3.8 27B MLX Mixed (prievadas 11436)
   uv run mlx_lm.server --model maglun/Qwen3.8-27B-MLX-Mixed-3.80bpw --port 11436 --host 127.0.0.1
   ```

3. **Prisijunkite OmniRoute valdymo skydelyje**:
   - Eikite į **Teikėjai** → **Pridėti teikėją**
   - Pasirinkite **MLX Gemma 26B** arba **MLX Qwen 3.8 27B**
   - Spustelėkite **Prisijungti** (API rakto nereikia)

4. **Naudokite su OpenCode**:
   ```bash
   # Sukonfigūruokite OpenCode naudoti OmniRoute
   opencode config set api.base_url http://localhost:20128/v1
   opencode config set api.key <your-omniroute-api-key>

   # Naudokite MLX modelius
   opencode run --model mlx-gemma/gemma-4-26b
   opencode run --model mlx-qwen/qwen3.8-27b
   ```

#### Atminties valdymas

**Svarbu**: turint 24GB bendrosios atminties vienu metu gali veikti tik **vienas didelis MLX modelis**.

- Gemma 26B: ~15.9GB didžiausias atminties naudojimas
- Qwen 3.8 27B: ~13.1GB didžiausias atminties naudojimas

Tai turite valdyti rankiniu būdu:

- Vienu metu paleiskite tik vieną MLX serverį arba
- Abu paleiskite atskiruose kompiuteriuose, arba
- Prieš paleisdami kitą, sustabdykite vieną serverį

OmniRoute automatiškai nevaldo MLX serverio procesų — jis tik nukreipia užklausas į jūsų sukonfigūruotus su OpenAI suderinamus galinius taškus.

#### Įrankių iškvietimo palaikymas

Abu modeliai palaiko su OpenAI suderinamą įrankių iškvietimą. Išbandykite naudodami:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mlx-gemma/gemma-4-26b",
    "messages": [{"role": "user", "content": "What is 2+2? Use the calculator tool."}],
    "tools": [{"type": "function", "function": {"name": "calculator", "description": "Calculate", "parameters": {"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]}}}]
  }'
```

#### Trikčių šalinimas

| Problema                     | Sprendimas                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ |
| Serverio nepavyksta paleisti | Patikrinkite `uv run mlx_lm.server --help` ir modelių ID                                               |
| Nepakanka atminties          | Įsitikinkite, kad veikia tik vienas modelis; uždarykite kitas programas; patikrinkite Activity Monitor |
| Atsisakoma užmegzti ryšį     | Patikrinkite, ar serveris veikia tinkamame prievade (11435/11436)                                      |
| Atsakymai lėti               | Per pirmąją užklausą modelis įkeliamas į atmintį (~30-60s); tolesnės užklausos vykdomos greitai        |
| Nepavyksta iškviesti įrankio | Įsitikinkite, kad modelis palaiko įrankius; OmniRoute žurnaluose patikrinkite vertimo klaidas          |

## Kaip prijungti paslaugų teikėją (žingsnis po žingsnio)

### 1 žingsnis: atidarykite valdymo skydą

Naršyklėje atidarykite `http://localhost:20128`.

### 2 žingsnis: eikite į paslaugų teikėjų skiltį

Šoninėje juostoje spustelėkite **Paslaugų teikėjai**.

### 3 žingsnis: spustelėkite „Pridėti paslaugų teikėją“

Spustelėkite mygtuką **+ Pridėti paslaugų teikėją**.

### 4 žingsnis: pasirinkite paslaugų teikėją

Peržiūrėkite sąrašą arba raskite savo paslaugų teikėją naudodami paiešką. Spustelėkite jį.

### 5 žingsnis: įveskite prisijungimo duomenis

- **Nemokami paslaugų teikėjai**: prisijungimo duomenų nereikia — tiesiog spustelėkite **Prisijungti**
- **API raktą naudojantys paslaugų teikėjai**: įklijuokite savo API raktą
- **OAuth paslaugų teikėjai**: spustelėkite **Prisijungti naudojant OAuth** ir prisijunkite

### 6 žingsnis: patikrinkite ryšį

Spustelėkite **Patikrinti ryšį**, kad įsitikintumėte, jog jis veikia.

### 7 žingsnis: atlikta!

Jūsų paslaugų teikėjas prijungtas. Galite jį naudoti su `model: "auto"` arba tiesiogiai nurodyti paslaugų teikėją.

## Kelių teikėjų naudojimas

OmniRoute geriausiai veikia su **keliais teikėjais**. Tai suteikia:

- **Automatinį perjungimą** — Jei vienas teikėjas neveikia, OmniRoute bando kitą
- **Kaštų optimizavimą** — OmniRoute kiekvienai užklausai parenka pigiausią teikėją
- **Spartos optimizavimą** — OmniRoute kiekvienai užklausai parenka greičiausią teikėją
- **Kokybės optimizavimą** — OmniRoute kiekvienai užduočiai parenka geriausią teikėją

### Rekomenduojama sąranka

Kad naudotis būtų patogiausia, prijunkite bent **3 teikėjus**:

1. **Vieną nemokamą teikėją** (Kiro arba Pollinations) — Visada pasiekiamą
2. **Vieną spartų teikėją** (Groq, Cerebras) — Greitiems atsakymams
3. **Vieną aukštos kokybės teikėją** (OpenAI, Anthropic, Google) — Sudėtingoms užduotims

Tada naudokite `model: "auto"`, o OmniRoute automatiškai parinks geriausią teikėją kiekvienai užklausai.

### Qoder: pasirinkite kredencialų perdavimo būdą

Qoder reikalingi kredencialai. Du jų perdavimo būdai pasižymi skirtingomis galimybėmis; vien modelio pavadinimas
nenurodo, ką gali atlikti konkretus ryšys.

| Kredencialas                                    | OmniRoute perdavimo būdas                           | Iškviečiančiojo įrankių iškvietimas                                   | Srautinis perdavimas                                        |
| ----------------------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------- |
| PAT, prasidedantis `pt-`                        | Vietinis `qodercli` procesas OmniRoute serveryje    | Nepalaikomas                                                          | Buferizuotas: SSE siunčiamas tik CLI grąžinus visą atsakymą |
| Ne PAT prieigos prieigos raktas arba API raktas | Su OpenAI suderinamas DashScope HTTP galinis taškas | Perduodamas toliau, atsižvelgiant į aukštesniojo lygio modelį / raktą | Aukštesniojo lygio HTTP/SSE kelias                          |

Jei naudojate PAT, įdiekite Qoder CLI tame pačiame serveryje arba konteineryje kaip OmniRoute. Vykdomasis failas
turi būti aptinkamas kaip `qodercli`, kitu atveju nustatykite `CLI_QODER_BIN` į jo vykdomojo failo kelią. Tik
Docker pagrindiniame kompiuteryje įdiegtas CLI nėra automatiškai pasiekiamas konteineryje. Jei dvejetainio
failo nėra, pateikiama aiški klaida, nurodanti įdiegti programą arba nustatyti kelią.

PAT pokalbių keliui taikomas 45 sekundžių proceso skirtasis laikas. Jis sujungia pokalbį į vieną
užklausą ir iškviečia CLI nesrautiniu spausdinimo režimu. Nurodžius `stream: true`,
atsakymo apvalkalas pakeičiamas į SSE; tai nesuteikia laipsniško aukštesniojo lygio žetonų pristatymo.
CLI patvirtinimui / modelių sąrašo gavimui taikomas atskiras 20 sekundžių skirtasis laikas. Tai yra dabartinės kodo
numatytosios reikšmės, o ne prietaisų skydelyje konfigūruojami nustatymai.

PAT ryšius naudokite paprastiems pokalbiams. Agento užklausose, kuriose perduodami `tools` arba pasenusios `functions`,
PAT paskyros neįtraukiamos renkantis kredencialus, įskaitant prisegtus kombinuotuosius tikslus. Mišrus
Qoder telkinys vis tiek gali pasirinkti savo HTTP paskyrą. Tiesioginiai PAT vykdyklės iškvietimai taip pat aiškiai
nutraukiami prieš paleidžiant CLI, užuot tyliai atmetus įrankių apibrėžtis. Šis
apribojimas taikomas API iškviečiančiojo pateiktiems įrankiams, o ne vidiniams įrankiams, kuriuos gali naudoti pats Qoder
CLI. HTTP raktas negarantuoja, kad kiekvienas modelis palaiko įrankius; vis tiek taikomos įprastos
modelio galimybių patikros.

Naršyklės OAuth pasiekiamas tik administratoriui sukonfigūravus visus penkis nustatymus:
`QODER_OAUTH_AUTHORIZE_URL`, `QODER_OAUTH_TOKEN_URL`, `QODER_OAUTH_USERINFO_URL`,
`QODER_OAUTH_CLIENT_ID` ir `QODER_OAUTH_CLIENT_SECRET`. Pagal numatytuosius nustatymus jų reikšmės tuščios; jei
diegimas nesukonfigūruotas, reikia importuoti palaikomus kredencialus, o ne daryti prielaidą,
kad prisijungimo per naršyklę eiga paruošta.

Įgyvendinimo nuorodos: [Qoder vykdyklė](../../open-sse/executors/qoder.ts),
[CLI vykdymo aplinka](../../open-sse/services/qoderCli.ts) ir
[OAuth konfigūracija](../../src/lib/oauth/constants/oauth.ts). Laipsniškas PAT srautinis perdavimas
ir konfigūruojamas skirtasis laikas yra atskiri patobulinimai; šis veikimas jų nežada.

## Dažniausiai užduodami klausimai

### „Ar reikia mokėti už naudojimąsi OmniRoute?“

**Ne!** OmniRoute yra nemokamas ir atvirojo kodo. Nemokamais paslaugų teikėjais (Kiro, Pollinations) galite naudotis visiškai nemokamai. Mokėti reikės tik tuo atveju, jei nuspręsite naudotis mokamais paslaugų teikėjais.

### „Nuo kurio paslaugų teikėjo turėčiau pradėti?“

Pradėkite nuo **Kiro AI** — jis nemokamas, jam nereikia API rakto ir jis suteikia prieigą prie Claude modelių. Vėliau pagal poreikį pridėkite daugiau paslaugų teikėjų.

### „Ar galiu vienu metu naudotis keliais paslaugų teikėjais?“

**Taip!** Būtent tam ir skirtas OmniRoute. Prijunkite kelis paslaugų teikėjus ir naudokite `model: "auto"`, kad OmniRoute kiekvienai užklausai parinktų tinkamiausią.

### „Kas nutiks, jei paslaugų teikėjas nustos veikti?“

OmniRoute automatiškai praleidžia neveikiančius paslaugų teikėjus ir išbando kitą. Jums nieko nereikia daryti.

### „Kaip atjungti paslaugų teikėją?“

Eikite į „Providers“ → spustelėkite paslaugų teikėją → spustelėkite **Disconnect**.

### „Ar galiu naudoti jau turimus API raktus?“

**Taip!** Jei jau turite OpenAI, Anthropic, Google ar kitų paslaugų teikėjų API raktus, galite juos naudoti OmniRoute. Prijungdami paslaugų teikėją tiesiog juos įklijuokite.
