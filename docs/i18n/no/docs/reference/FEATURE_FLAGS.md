> Kjøretidsveksler som endrer OmniRoutes oppførsel **uten en ny distribusjon**.
> Hvert flagg som er oppført her er definert i
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — den eneste kilden til sannhet. Dashbordet og REST API-et leser begge fra
> den filen, så tabellen nedenfor er generert for å matche den 1:1.

---

## Hva funksjonsflagg er

Et funksjonsflagg er en navngitt veksler (boolsk eller enum) hvis verdi kan endres ved
kjøretid og lagres i databasen, uten at det kreves en ny prosessdistribusjon. Hvert
flagg er beskrevet av en `FeatureFlagDefinition` med en `key`, `label`,
`description`, `category`, `defaultValue`, `type`, og et `requiresRestart`-hint.

### Oppløsningsrekkefølge

Den **effektive verdien** av et flagg løses av
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) med denne
prioriteten (høyest vinner):

1. **DB-overstyring** — en verdi lagret i `key_value`-tabellen under
   `feature_flags`-navneområdet (angitt via dashbordet eller REST API-et).
2. **Miljøvariabel** — `process.env[<KEY>]`, hvis satt og ikke-tom.
3. **Definisjonsstandard** — `defaultValue` fra `featureFlagDefinitions.ts`.

Et boolsk flagg anses som **aktivert** når dets effektive verdi er `"true"`,
`"1"`, eller `"yes"` (se `isFeatureFlagEnabled()`).

> [!NOTE]
> De fleste flagg har også en matchende miljøvariabel med **samme navn**
> dokumentert i [`ENVIRONMENT.md`](./ENVIRONMENT.md). Flaggens DB-overstyring
> har forrang over den miljøvariabelen. Et flagg med
> `requiresRestart: true` lagres umiddelbart, men leses bare på nytt ved prosess
> oppstart — å veksle det viser en **"Start server på nytt"**-banner i dashbordet.

## Veksle flagg

### Dashbord

Naviger til** Dashboard → Innstillinger → Funksjonsflagg** (`/dashboard/settings/feature-flags`). Rutenettet (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) støtter:

- **Søk** etter nøkkel eller beskrivelse, og** filter** etter kategori (pluss en syntetisk** Krever omstart** utsikt).
- EN** veksle** for booleske flagg og en** rullegardinmenyen** for enum-flagg (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- EN** kildemerket** per flagg — `DB`, `ENV` eller `DEF` — som viser hvor den effektive verdien kom fra.
- EN** Tilbakestill** knappen (vises kun for `DB` -sourced -flagg) for å slippe overstyringen, og en** Tilbakestill alle overstyringer** knappen nederst.
- EN** Start server på nytt** banner når et `requiresRestart` flagg endres.

### REST API

Alle operasjoner går gjennom en enkelt rute: [`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts). Hver metode krever en autentisert dashbordøkt ( ellers `401` ).

#### `GET /api/settings/feature-flags`

Returnerer hvert flagg med dens effektive verdi, kilde og et sammendrag.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 114 flags
  ],
  "summary": {
    "total": 114,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Angi eller fjern en enkelt overstyring. Kropp: `{ key: string; value?: string }`. Å utelate `value` fjerner overstyringen (gjenoppretter env / standard).

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Responsen ekko den nye `effectiveValue`/`source`, `previousValue`/ `previousSource` og `requiresRestart`. Ukjente nøkler og enum-verdier utenfor området avvises med `400`.

#### `DELETE /api/settings/feature-flags`

Rydder** alle** DB overstyrer på en gang, og gjenoppretter hvert flagg til dets env/standardverdi. Returnerer `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Flagg med `requiresRestart: true` trer bare i kraft etter en prosess-innlasting. Dashbordets omstartsflyt kaller `POST /api/restart` og poller deretter `GET /api/health/ping` til serveren er tilbake.

## Reserveløsning for nødbudsjett

`OMNIROUTE_EMERGENCY_FALLBACK` (kategori `runtime`, standardverdi `true`) styrer
den kostnadsfrie reservebanen for nødstilfeller i
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Når den er aktivert, rutes forespørsler som har brukt opp budsjettet sitt, til en
kostnadsfri reserveleverandør/-modell i stedet for å mislykkes umiddelbart. Sett
den til `false` (eller `0`) — via bryteren i kontrollpanelet, en overstyring i
databasen eller miljøvariabelen `OMNIROUTE_EMERGENCY_FALLBACK` — for å deaktivere
denne virkemåten og la forespørsler med oppbrukt budsjett mislykkes. (Tilgjengelig
som en bryter i kontrollpanelet i PR-er #3741 / #3752.)

Et svar levert av denne reserveløsningen inneholder
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, slik
at en klient kan se at forespørselen ble omdirigert uten å sammenligne
`X-OmniRoute-Provider` med den opprinnelige forespørselen. Headeren finnes ikke i
noen andre svar.
