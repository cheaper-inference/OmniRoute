Koble **Claude Code**-CLI-en (`claude`) til OmniRoute — lokalt eller på en ekstern VPS —
med profiler per modell, tilsvarende Codex-oppsettet.

---

## Hurtigstart

```bash
# Start Claude Code mot en lokal OmniRoute (oppdager automatisk den aktive konteksten)
omniroute launch

# Mot en ekstern OmniRoute (etter `omniroute connect <host>` skjer dette automatisk)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Generer profiler per modell, og start deretter en av dem
omniroute setup-claude            # skriver ~/.claude/profiles/<name>/settings.json
omniroute launch --profile glm52  # Claude Code som bruker glm/glm-5.2 via OmniRoute
```

## Hvordan Claude Code kobles til en gateway

Claude Code snakker om**Anthropic Meldinger API** og peker på et tilpasset endepunkt med miljøvariabler (det har ikke noe `--base-url` flagg):

| Variabel                                     | Hensikt                                                                                         |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | Gateway-rot URL (Claude -koden legger til `/v1/messages`).** Ingen `/v1` suffiks.**             |
| `ANTHROPIC_AUTH_TOKEN`                       | Sendt som `Authorization: Bearer …` — bruk din OmniRoute -tilgangstoken / API nøkkel            |
| `ANTHROPIC_API_KEY`                          | Alternativ: sendes som `x-api-key`. Hvis begge er satt, vinner `ANTHROPIC_AUTH_TOKEN`           |
| `ANTHROPIC_MODEL`                            | Tving frem en spesifikk modell (overstyrer standarden for `/model` velgeren)                    |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → den opprinnelige `/model` velgeren viser `claude*`/`anthropic*` modeller fra `/v1/models` |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | Avgrens utdatatokens per svar (f.eks. `65536`)                                                  |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | Token-terskel for automatisk komprimering                                                       |

> Env vars leses** en gang ved oppstart** — start Claude -koden på nytt etter å ha endret dem.

For en legitimasjon som roterer i stedet for en fast streng, sett `apiKeyHelper` i `~/.claude/settings.json` til en kommando som skriver ut gjeldende legitimasjon til stdout. Claude Code cacher utdataene i fem minutter som standard (`CLAUDE_CODE_API_KEY_HELPER_TTL_MS` overstyrer det) og sender verdien i både `Authorization: Bearer` og `x-api-key`. Skriptet må skrive ut legitimasjonen og ingenting annet — et banner ved siden av det svikter hjelperen på v2.1.227 +.

Slik fungerer Entra ID SSO : `scripts/cli/omniroute-sso.mjs token` skriver ut en kortvarig Entra-tilgangstoken som OmniRoute verifiserer i stedet for en API nøkkel. Se [`docs/security/ENTRA_SSO.md`](../security/ENTRA_SSO.md).

`omniroute launch` setter alle disse for deg: den løser basis URL + token fra den aktive konteksten (så `omniroute connect <vps>` da fungerer `omniroute launch` bare), helsesjekker serveren og execs `claude`.

## Bruksattribusjon: økter og prosjekter

OmniRoute grupperer hver API nøkkels forespørsler i** agent økter** og registrerer hvilke** prosjekt** hver økt jobbet på (`agent_sessions` tabell), slik at bruk og kostnader kan rapporteres per teammedlem, per prosjekt og per økt.

Hva er registrert uten klientoppsett:

| Felt     | Kilde                                                                                                                                           |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Sesjon   | `x-claude-code-session-id` header (samme verdi som `metadata.user_id.session_id`), stabil per økt                                               |
| Prosjekt | `Primary working directory:` linjen Claude -koden sender inn sin miljømelding; worktree-mapper under `.claude/worktrees/` løses til depotnavnet |
| gren     | `Current branch:` fra git-statusen Claude Code sender med den første meldingen                                                                  |
| Klient   | `user-agent` (`claude-cli/<version>`)                                                                                                           |

Codex (`<environment_context><cwd>`) og OpenCode (`x-opencode-session`) gjenkjennes på samme måte. Nøkler med** ingen logg** aktivert, behold bare sesjons-ID-en og prosjektfeltene levert av overskrift; ingenting som er lest fra ledeteksten (bane, gren) lagres.

### Navngi prosjektet eksplisitt (anbefalt)

Arbeidskatalogen er forskjellig mellom maskiner, så det samme depotet kan dukke opp under forskjellige baner. Send prosjektet eksplisitt i stedet: Claude Code legger til alle overskrifter oppført i `ANTHROPIC_CUSTOM_HEADERS` til hver modellforespørsel, og OmniRoute leser to av dem:

| Overskrift                 | Verdi                                                                 |
| -------------------------- | --------------------------------------------------------------------- |
| `x-omniroute-project`      | Prosjektnavn, f.eks. `omniroute`                                      |
| `x-omniroute-project-repo` | Normalisert fjernkontroll, f.eks. `github.com/diegosouzapw/OmniRoute` |

Begge leses kun for attribusjon; de blir aldri videresendt til oppstrømsleverandøren.

`ANTHROPIC_CUSTOM_HEADERS` leses én gang ved oppstart, og innstillingsfiler lagrer bokstavelige verdier, så beregn det når Claude Code starter. Legg dette til `~/.zshrc` eller `~/.bashrc` og fortsett å starte `claude` fra prosjektmappen:

```bash
claude() {
  local common name repo
  if common=$(git rev-parse --path-format=absolute --git-common-dir 2>/dev/null); then
    name=$(basename "$(dirname "$common")")  # repository name, also inside worktrees
    repo=$(git remote get-url origin 2>/dev/null \
      | sed -E 's#^[a-zA-Z][a-zA-Z0-9+.-]*://([^@/]*@)?##; s#^[^@/]+@([^:]+):#\1/#; s#\.git$##')
  else
    name=$(basename "$PWD")                  # not a git repository: folder name
  fi
  ANTHROPIC_CUSTOM_HEADERS="x-omniroute-project: ${name}${repo:+
x-omniroute-project-repo: ${repo}}" command claude "$@"
}
```

`sed` uttrykket fjerner all legitimasjon som er innebygd i den eksterne URL. IDE utvidelser starter Claude koden uten skallet ditt, så øktene deres faller tilbake til arbeidskatalogen.

## Discovery-aliaser — vis ikke-Claude-modeller i `/model`-velgeren

Claude Codes gateway-modelloppdagelse lister bare ID-er som begynner med `claude`
eller `anthropic`, så med `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` viser den
innebygde `/model`-velgeren normalt **bare** OmniRoutes Claude/Anthropic-modeller — en
`kimi/kimi-k2.6` eller `glm/glm-5.2` dukker aldri opp, selv om den ruter helt fint.

OmniRoute kan speile enhver aktivert modell (og kombinasjon) under en `claude/…`-ID
slik at den passerer filteret og vises i velgeren:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

Når du velger en av disse i Claude Code, fjerner OmniRoute `claude/`-innpakningen
tilbake til den virkelige ID-en før ruting — en ekte `claude/<real-claude-model>`-ID
(den faktiske Claude OAuth-leverandøren) forblir alltid urørt.

Som standard speiles bare grunn-ID-er. Med det valgfrie funksjonsflagget
`CATALOG_MIRROR_REFINEMENTS_ENABLED` slått på speiles varianter med resonneringsinnsats
som katalogen allerede lister (f.eks. `codex/gpt-6-sol-high`) som enhver annen
ID, slik at Claude Code kan velge et eksplisitt innsatsnivå, og innebygde `auto/*`-ID-er
som forespørselsstien ikke kan materialisere, speiles ikke. Om innsatsvarianter i det
hele tatt listes, styres fortsatt av `OMNIROUTE_DISABLE_THINKING_LEVEL_VARIANTS` —
speilet legger aldri til en variant som grunnkatalogen ikke har.

**Dette er av som standard** og styres av en port med tre nivåer (mest spesifikke
vinner), slik at en vanlig OmniRoute aldri dobler katalogen sin for klienter som ikke
bruker Claude Code:

| Nivå       | Hvor                                                                             |
| ---------- | -------------------------------------------------------------------------------- |
| Modell     | Leverandørens detaljside → «Vis i Claude Code»-bryter per modell                 |
| Leverandør | Leverandørens detaljside → bryter på leverandørnivå (dekker alle modellene)      |
| Global     | Innstillinger → Funksjonsflagg → `EXPOSE_CC_DISCOVERY_ALIASES` (av som standard) |

Miljøvariabelen `EXPOSE_CC_DISCOVERY_ALIASES` tvinger det globale nivået på
og har forrang over dashbord-overstyringen (Funksjonsflagg-skjermen viser
et «aktiv via miljøvariabel»-notat når den gjør det). Brytere per leverandør og
per modell raffinerer videre derfra — f.eks. globalt av + Kimi-leverandør på eksponerer
bare Kimis modeller.

> ⚠️ **Vindusavvik på ikke-Claude-modeller.** Claude Code antar et kontekstvindu
> på 200K for enhver ID den ikke kjenner igjen (den kan ikke lese et reelt vindu fra
> `/v1/models`). For en modell med et større vindu (f.eks. Kimi K2s 256K), sett
> `CLAUDE_CODE_AUTO_COMPACT_WINDOW` til en verdi under modellens reelle vindu slik
> at automatisk komprimering ikke utløses for tidlig. De genererte profilene ovenfor
> gjør allerede dette per modell.

## Onboarding-blokk på instrumentpanelet

Claude-verktøykortet (**Instrumentpanel → CLI Code**) viser det nøyaktige `settings.json`-fragmentet
for denne instansen, ved siden av informasjonsknappen for discovery-aliaset, med en kopieringsknapp:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<din OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<din OmniRoute API-nøkkel>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

Basis-URL-en er den som kortet har funnet (inkludert en egendefinert overstyring du skrev inn), og er allerede
normalisert — uten `/v1`-suffiks og uten avsluttende skråstrek. **Nøkkelen vises aldri**: blokken inneholder en
plassholder, slik at et skjermbilde eller et innlimt utdrag ikke kan lekke nøkkelen. Lim inn nøkkelen din over plassholderen.

Legg til `CLAUDE_CODE_AUTO_COMPACT_WINDOW` under den samme `env`-blokken for alle modeller der det reelle
kontekstvinduet ikke er 200K — Claude Code antar 200K for hver id den ikke gjenkjenner, så
automatisk komprimering utløses ellers på feil tidspunkt (se advarselen i forrige avsnitt).
Utdragsbyggeren godtar også denne verdien, slik at en anroper som kjenner målmodellens kontekstvindu,
kan generere den direkte.

Kilde: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (ren
bygger, enhetstestet), gjengitt av `ClaudeGatewayOnboardingBlock`.

### Fest én konto (valgfritt)

For å sende hver Claude Code-forespørsel gjennom én bestemt leverandørkonto legger du til
`x-omniroute-connection`-headeren via `ANTHROPIC_CUSTOM_HEADERS` i den samme `env`-blokken:

```jsonc
"ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>"
```

Kopier id-en fra `xxxxxxxx…`-brikken på tilkoblingsraden på leverandørsiden. Festingen
gjelder bare enkeltmodell-id-er (`provider/model`), ikke kombinasjoner. Se
[Kontofesting per forespørsel](../reference/API_REFERENCE.md#account-pinning-per-request) for
nøyaktig reserveatferd.

## Profiler (`CLAUDE_CONFIG_DIR`)

Claude Code har **ingen innebygde profilfiler** (i motsetning til Codex' `~/.codex/<name>.config.toml`).
Den idiomatiske mekanismen er `CLAUDE_CONFIG_DIR` — en separat konfigurasjonskatalog per
profil, hver med sine egne `settings.json`, legitimasjonsopplysninger, historikk og hurtigbuffer.

`omniroute setup-claude` henter den aktive `/v1/models`-katalogen og skriver én
profil per modell til `~/.claude/profiles/<name>/settings.json`, med de
**samme navnene som `setup-codex`** (`glm52`, `kimi-k27`, `deepseek-pro`, …):

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **Autentiseringstokenet skrives aldri til profilen.** Start med
> `omniroute launch --profile <name>` (den setter inn `ANTHROPIC_AUTH_TOKEN` fra den
> aktive konteksten), eller eksporter `ANTHROPIC_AUTH_TOKEN` selv og kjør
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`.

**Automatisk synkronisering etter modelloppdagelse (valgfritt).** OmniRoute kan automatisk generere disse
`~/.claude/profiles/<name>/settings.json`-filene på nytt hver gang en synkronisering av leverandørmodeller
endrer den aktive katalogen — slik at nye modeller eller modeller med endrede navn får profiler uten at kommandoen må
kjøres på nytt. Dette er **slått av som standard**: slå det på fra **CLI Code-kontrollpanelet** («Automatisk synkronisering
av CLI-profiler» → Claude Code), eller angi `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` (det respekterer også
`CLI_ALLOW_CONFIG_WRITES`, som er slått på som standard). Når dette er aktivert, skriver det bare profilfiler; det endrer aldri
den aktive Claude-standardkonfigurasjonen, autentiseringen eller `~/.claude/settings.json`.

### Generere og bruke profiler

```bash
# Lokal OmniRoute
omniroute setup-claude

# Ekstern VPS (bygger inn VPS-URL-en i hver profil)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Bare enkelte leverandører
omniroute setup-claude --only glm,kimi

# Skriv også profiler for lokale CLI-leverandører (zcode, auggie, devin-cli-agentic,
# codex-app-server) som ikke oppdages på denne verten (hoppes over som standard for et lokalt mål)
omniroute setup-claude --include-local

# Forhåndsvis uten å skrive
omniroute setup-claude --dry-run

# Start en profil
omniroute launch --profile kimi-k27
```

## Modellnivåer (valgfritt)

Claude Code ruter til kapabilitetsnivåer. Knytt hvert nivå til en OmniRoute-modell via miljøvariabler /
innstillinger hvis du ønsker ulike leverandører per nivå:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

Ellers brukes én enkelt `ANTHROPIC_MODEL` (som profiler angir) til alt.

[Ekstern modus](./REMOTE-MODE.md)), retter `omniroute launch` og `omniroute setup-claude`

## Feilsøking

**Claude Code ignorerer gatewayen** — bekreft at `ANTHROPIC_BASE_URL` **ikke har
`/v1`**, og start `claude` på nytt (miljøvariablene leses én gang ved oppstart). `omniroute launch`
håndterer dette for deg.

**`/model`-velgeren er tom / mangler gateway-modeller** — krever Claude Code
v2.1.219+ og `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`. Bare modell-ID-er av typen `claude*` /
`anthropic*` vises i velgeren; fremtving en hvilken som helst annen modell med
`ANTHROPIC_MODEL=<id>` (det er dette profiler gjør).

**`400 Ambiguous model 'claude-…'`** — Claude Code sender alltid modell-ID-er
**uten prefiks** (f.eks. `claude-opus-4-8`), så når både Claude Code (`cc/…`)- og
Claude (`claude/…`)-leverandørene er tilkoblet, samsvarer ID-en uten prefiks med to ruter, og
OmniRoute nekter å gjette. Løs det på én av følgende måter: Fest en ID med prefiks ved hjelp av
`ANTHROPIC_MODEL=cc/claude-opus-4-8`, eller aktiver **Foretrekk Claude Code for
Claude-modeller uten prefiks** — bryteren på Claude-leverandørsiden, eller
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (av som standard;
se [Miljø](../reference/ENVIRONMENT.md)) — som i stedet ruter `claude-*`-ID-er
uten prefiks til Claude Code. Eksplisitte leverandørprefikser har alltid forrang.

**Autentiseringsfeil** — profilen inneholder ikke noe token. Bruk `omniroute launch --profile`
(setter det inn) eller eksporter `ANTHROPIC_AUTH_TOKEN`.

**Profiler isoleres ikke** — hver profil har en egen `CLAUDE_CONFIG_DIR`;
kontroller at `echo $CLAUDE_CONFIG_DIR` i økten peker på
`~/.claude/profiles/<name>`.
