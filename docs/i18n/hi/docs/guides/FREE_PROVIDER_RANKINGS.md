> **संक्षेप में**: OmniRoute अपने **मुफ़्त** प्रदाताओं को मॉडल की गुणवत्ता के आधार पर **Arena AI
> (LMArena-शैली) ELO स्कोर** का उपयोग करके रैंक करता है। यह देखने के लिए कि कौन-से मुफ़्त प्रदाता आपके कार्य के लिए
> सबसे शक्तिशाली मॉडल उपलब्ध कराते हैं, डैशबोर्ड में **मुफ़्त प्रदाता रैंकिंग** पृष्ठ खोलें —
> समग्र रूप से, या श्रेणी (कोडिंग, समीक्षा, दस्तावेज़ीकरण, डीबगिंग) के अनुसार फ़िल्टर करके।

## यह क्या है

OmniRoute 377 प्रदाताओं को पंजीकृत करता है, जिसमें 155 कैटलॉग प्रविष्टियाँ चिह्नित हैं**free/no-auth** (नो-ऑथ, फ्री-टियर OAuth, या फ्री-टियर API कुंजी - [फ्री टियर गाइड](../getting-started/FREE-TIERS-GUIDE.md) और पूर्ण [फ्री टियर निर्देशिका](../reference/FREE_TIERS.md) देखें)। पकड़: मुफ़्त प्रदाता मॉडल गुणवत्ता में बेतहाशा भिन्न होते हैं। फ्रंटियर मॉडल की सेवा देने वाला एक नो-ऑथ प्रदाता एक छोटे विरासत मॉडल की सेवा की तुलना में कहीं अधिक उपयोगी है।

**मुफ़्त प्रदाता रैंकिंग** उत्तर "** कौन सा निःशुल्क प्रदाता मुझे सर्वोत्तम मॉडल देता है?** "प्रत्येक निःशुल्क प्रदाता के कैटलॉग से जुड़कर** भीड़-स्रोत गुणवत्ता स्कोर** से** एरिना AI लीडरबोर्ड** (मानव-वरीयता ELO, LMArena चैटबॉट क्षेत्र के पीछे भी यही विचार है)। फिर प्रदाताओं को उनकी ताकत के आधार पर रैंक किया जाता है** सर्वोत्तम निःशुल्क मॉडल** .

रैंकिंग की गणना तीन वास्तविक स्रोतों से की जाती है:

1. मुफ़्त-प्रदाता सूचियाँ - `NOAUTH_PROVIDERS`, साथ ही `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` प्रविष्टियाँ ध्वजांकित `hasFree` (`src/shared/constants/providers.ts`)।
2. प्रदाता रजिस्ट्री (`open-sse/config/providerRegistry.ts`) से प्रत्येक प्रदाता का मॉडल कैटलॉग।
3. एरिना ELO सिंक इंजन (`src/lib/arenaEloSync.ts`) द्वारा `model_intelligence` DB तालिका में संग्रहीत ELO-व्युत्पन्न कार्य-फिट स्कोर।

सम्मिलित तर्क `src/lib/freeProviderRankings.ts` में रहता है।

## एक्सेस करने का तरीका

### डैशबोर्ड पृष्ठ

डैशबोर्ड खोलें और **लागत → मुफ़्त प्रदाता रैंकिंग** पर जाएँ, या सीधे यहाँ नेविगेट करें:

```
/dashboard/free-provider-rankings
```

यह पृष्ठ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) निम्नलिखित दिखाता है:

- सर्वोच्च रैंक वाले मुफ़्त प्रदाताओं का **शीर्ष-3 पोडियम** (🥇 🥈 🥉)।
- इन कॉलम वाली एक पूर्ण **रैंकिंग तालिका**: **रैंक**, **प्रदाता**, **शीर्ष मॉडल**,
  **स्कोर**, **औसत स्कोर**, **मॉडल**, **प्रकार**।
- **श्रेणी फ़िल्टर बटन**: _सभी श्रेणियाँ_, _डिफ़ॉल्ट_, _कोडिंग_, _समीक्षा_,
  _दस्तावेज़ीकरण_, _डीबगिंग_।

प्रत्येक प्रदाता का **प्रकार** बैज बताता है कि वह किस प्रकार मुफ़्त है:

| बैज      | अर्थ                                            |
| -------- | ----------------------------------------------- |
| `NOAUTH` | हमेशा मुफ़्त, किसी क्रेडेंशियल की आवश्यकता नहीं |
| `OAUTH`  | मुफ़्त टियर (`hasFree`) वाला OAuth प्रदाता      |
| `APIKEY` | मुफ़्त टियर (`hasFree`) वाला API-कुंजी प्रदाता  |

स्कोर को अपरिष्कृत संख्याओं के बजाय मानव-पठनीय लेबल (जैसे _विशिष्ट_, _उत्कृष्ट_, _बहुत अच्छा_,
_अच्छा_, _औसत_) के रूप में दिखाया जाता है, क्योंकि अंतर्निहित मान सापेक्ष
रैंकिंग गुणवत्ता है, प्रतिशत नहीं।

### API एंडपॉइंट

यह पृष्ठ एक सार्वजनिक रीड एंडपॉइंट
(`src/app/api/free-provider-rankings/route.ts`) द्वारा समर्थित है:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

क्वेरी पैरामीटर (Zod से सत्यापित):

| पैरामीटर   | प्रकार | डिफ़ॉल्ट   | टिप्पणियाँ                                                                                                  |
| ---------- | ------ | ---------- | ----------------------------------------------------------------------------------------------------------- |
| `category` | string | (कोई नहीं) | `default`, `coding`, `review`, `documentation`, `debugging` में से एक। संयुक्त रैंकिंग के लिए इसे छोड़ दें। |
| `limit`    | number | `50`       | `1–100` की सीमा में सीमित।                                                                                  |

प्रतिक्रिया की संरचना:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` मूल Arena ELO मान है; `score` सामान्यीकृत कार्य-उपयुक्तता मान है
(नीचे देखें)। जिन प्रदाताओं के पास कोई स्कोर किया गया मॉडल नहीं है, उन्हें प्रतिक्रिया से हटा दिया जाता है।

## स्कोर कैसे काम करते हैं

### स्रोत: Arena AI लीडरबोर्ड

Arena ELO सिंक इंजन (`src/lib/arenaEloSync.ts`) Arena AI लीडरबोर्ड API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) से दो लीडरबोर्ड — `text`
और `code` — प्राप्त करता है। जब वह API कोई उपयोगी बोर्ड नहीं लौटाता, तो इंजन Hugging Face
datasets-server पर आधिकारिक `lmarena-ai/leaderboard-dataset` पर वापस चला जाता है
(`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` `activeSource`, `lastError` और
`lastFailedAt` की रिपोर्ट देता है। प्रत्येक लीडरबोर्ड एंट्री में
मॉडल का नाम, वेंडर, ELO `score`, कॉन्फ़िडेंस अंतराल और वोट संख्या होती है।

लीडरबोर्ड श्रेणियाँ OmniRoute टास्क श्रेणियों से इस प्रकार मैप होती हैं:

| Arena लीडरबोर्ड | OmniRoute टास्क श्रेणियाँ                         |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### नॉर्मलाइज़ेशन (टास्क-फ़िट स्कोर)

कच्चे ELO स्कोर प्रत्येक लीडरबोर्ड के लिए **`[0.4, 0.98]` में एक टास्क-फ़िट मान** में नॉर्मलाइज़ किए जाते हैं:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

स्कोर कभी `0` या `1` तक नहीं पहुँचता, जिससे उपयोगकर्ता ओवरराइड के लिए गुंजाइश बचती है। यही
वह `score` फ़ील्ड है जो आपको API रिस्पॉन्स में दिखता है और डैशबोर्ड पर दिखने वाला लेबल है।

### कॉन्फ़िडेंस

प्रत्येक एंट्री को Arena वोट संख्या के आधार पर एक कॉन्फ़िडेंस स्तर मिलता है:

| कॉन्फ़िडेंस | वोट     |
| ----------- | ------- |
| `high`      | ≥ 5,000 |
| `medium`    | ≥ 1,000 |
| `low`       | < 1,000 |

### स्टोरेज और ताज़गी

नॉर्मलाइज़ की गई एंट्रियाँ `model_intelligence` DB टेबल में
`source = "arena_elo"` के साथ लिखी जाती हैं (`src/lib/db/modelIntelligence.ts`)। एंट्रियाँ
**7 दिनों के बाद समाप्त हो जाती हैं**, इसलिए जो प्रदाता सिंक करना बंद कर देता है, वह पुराना
डेटा परोसने के बजाय धीरे-धीरे सूची से बाहर हो जाता है।

सिंक **डिफ़ॉल्ट रूप से चालू** रहता है:

- यह सर्वर स्टार्टअप पर एक बार चलता है और फिर एक आवधिक टाइमर पर
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` से वायर्ड)।
- यह **नॉन-ब्लॉकिंग है और कभी भी घातक नहीं** — अगर अपस्ट्रीम फ़ेच विफल हो जाता है, तो OmniRoute
  चलता रहता है और रैंकिंग बस अंतिम सही डेटा (या खाली स्थिति) दिखाती है।

दो एनवायरनमेंट वेरिएबल इसे नियंत्रित करते हैं (दस्तावेज़ीकरण
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) में):

| वेरिएबल                   | डिफ़ॉल्ट      | उद्देश्य                                                |
| ------------------------- | ------------- | ------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | आउटबाउंड सिंक से ऑप्ट आउट करने के लिए `false` सेट करें। |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | सिंक अंतराल, सेकंड में।                                 |

### मैनुअल सिंक / स्थिति / साफ़ करना

ऑपरेटरों के लिए, एक प्रमाणित प्रबंधन एंडपॉइंट मैनुअल नियंत्रण प्रदान करता है
(`src/app/api/intelligence/sync/route.ts` — प्रबंधन प्रमाणीकरण आवश्यक):

```
GET    /api/intelligence/sync          # वर्तमान सिंक स्थिति (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # मैनुअल सिंक ट्रिगर करें; बिना लिखे पूर्वावलोकन के लिए बॉडी: { "dryRun": true }
DELETE /api/intelligence/sync          # सभी सिंक की गई arena_elo इंटेलिजेंस एंट्रियाँ साफ़ करें
```

अगर रैंकिंग पेज खाली है, तो मैनुअल `POST /api/intelligence/sync` (या बस
सर्वर को रीस्टार्ट करना) उसे फिर से भर देता है।

### मॉडलों को लीडरबोर्ड से मिलाना

रजिस्ट्री मॉडल ID और Arena मॉडल नाम हमेशा बिल्कुल मेल नहीं खाते। रैंकिंग लचीले मिलान
(`src/lib/freeProviderRankings.ts` में `findMatchingIntelligence`) का उपयोग करती है:

1. नॉर्मलाइज़ किए गए मॉडल ID पर सटीक मिलान।
2. अंतिम संस्करण प्रत्यय हटाने के बाद मिलान (जैसे `kimi-k2.6` → `kimi-k2`)।
3. प्रीफ़िक्स मिलान (लीडरबोर्ड मॉडल नाम रजिस्ट्री ID का प्रीफ़िक्स है)।

सिंक की ओर, ज्ञात वेंडर प्रीफ़िक्स (`anthropic/`, `openai/`, `google/`, …)
हटा दिए जाते हैं और एक छोटा alias मैप कैनोनिकल नामों को उन वेरिएंट में विस्तारित करता है जिनका
उपयोग OmniRoute आंतरिक रूप से करता है, ताकि मॉडल किसी भी नाम से खोजे जा सकें।

### किसी प्रदाता की रैंकिंग कैसे होती है

प्रत्येक मुफ़्त प्रदाता के लिए, इंजन उसके कैटलॉग के हर मॉडल को स्कोर करता है, फिर:

- **Top Model** = प्रदाता का सबसे अधिक स्कोर वाला मॉडल।
- **Avg Score** = उस प्रदाता के सभी स्कोर किए गए मॉडलों का औसत स्कोर।
- **Models** = प्रदाता के कितने मॉडलों के पास Arena स्कोर था।

प्रदाताओं को पहले **टॉप-मॉडल स्कोर** के आधार पर, फिर औसत स्कोर के आधार पर क्रमबद्ध किया जाता है। यह
उस प्रदाता को पुरस्कृत करता है जो कम से कम एक मजबूत मुफ़्त मॉडल प्रदान करता है।

## मुफ़्त प्रदाताओं को चुनने के लिए इसका उपयोग

1. **सही श्रेणी चुनें।** एजेंट-आधारित/कोड कार्यभार के लिए **Coding** फ़िल्टर का उपयोग करें, या
   सामान्य चैट के लिए इसे **All Categories** / **Default** पर छोड़ दें। एक ही प्रदाता की
   रैंक अलग-अलग श्रेणियों में भिन्न हो सकती है, क्योंकि प्रत्येक लीडरबोर्ड के अनुसार उसका शीर्ष मॉडल अलग होता है।
2. **एकल सेटअप के लिए पोडियम को प्राथमिकता दें।** यदि आप केवल एक या दो मुफ़्त
   प्रदाताओं को कनेक्ट करना चाहते हैं, तो अपनी श्रेणी में सर्वोच्च रैंक वाले प्रदाताओं से शुरुआत करें।
3. **Type बैज जाँचें।** `NOAUTH` प्रदाताओं को कनेक्ट करना सबसे तेज़ है (किसी
   क्रेडेंशियल की आवश्यकता नहीं)। `OAUTH` / `APIKEY` मुफ़्त टियर के लिए तुरंत साइन-अप करना पड़ता है, लेकिन वे अक्सर
   अधिक शक्तिशाली मॉडल उपलब्ध कराते हैं। कनेक्शन के चरणों के लिए
   [मुफ़्त टियर मार्गदर्शिका](../getting-started/FREE-TIERS-GUIDE.md) देखें।
4. **कई प्रदाताओं को कनेक्ट करें और Auto-Combo को निर्णय लेने दें।** इस पृष्ठ को संचालित करने वाला वही Arena ELO डेटा
   Auto-Combo स्कोरिंग इंजन के **कार्य-उपयुक्तता कारक** को भी डेटा प्रदान करता है
   (`open-sse/services/autoCombo/taskFitness.ts`, समाधान क्रम
   `user_override → arena_elo → models_dev_tier → static table`)। इसलिए, शीर्ष मुफ़्त प्रदाताओं को कनेक्ट करने के बाद,
   `model: "auto"` (जैसे `auto/coding`) के साथ रूटिंग प्रत्येक अनुरोध के लिए
   उच्च-गुणवत्ता वाले मुफ़्त मॉडलों को स्वचालित रूप से प्राथमिकता देगी। संपूर्ण 16-कारक स्कोरिंग के लिए
   [Auto-Combo](../routing/AUTO-COMBO.md) देखें।
