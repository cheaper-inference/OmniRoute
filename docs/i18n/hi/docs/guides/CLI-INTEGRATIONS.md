साझा निष्पादन योग्य मैनिफ़ेस्ट, प्रतिबंधित चाइल्ड वातावरण और लगातार Gemini सेटअप के लिए, [CLI लॉन्च अनुबंध](./CLI-LAUNCH-CONTRACTS.md) देखें।

OmniRoute `setup-*` कमांड के एक परिवार को शिप करता है जो OmniRoute अपने बैकएंड — के रूप में उपयोग करने के लिए एक कोडिंग CLI (Codex, Claude Code, OpenCode, Cline,…) को कॉन्फ़िगर करता है ताकि टूल बात कर सके।** एक** ऑटो-फ़ॉलबैक के साथ एंडपॉइंट और OmniRoute रूट सही प्रदाता तक। सेटअप कमांड आपके सक्रिय स्थानीय या दूरस्थ OmniRoute संदर्भ का उपयोग करते हैं और टूल को कॉन्फ़िगर करते हैं** आपका** मशीन। कैटलॉग-आधारित व्यंजन सर्वर से मॉडल लाते हैं; एकल-मॉडल व्यंजन मॉडल ID के लिए `--model` या प्रॉम्प्ट स्वीकार करते हैं। जहां भी उपकरण इसका समर्थन करता है, वहां API कुंजी को एक पर्यावरण चर द्वारा संदर्भित किया जाता है। उपकरण-स्थानीय वातावरण फ़ाइल को बनाए रखने वाले आदेश नीचे दिए गए हैं।

कैटलॉग और ऑटोमेशन कमांड टूल के विभिन्न सेटों को कवर करते हैं:

| सतह                            | गिनती करना | इसका क्या मतलब है                                                                      |
| ------------------------------ | ---------- | -------------------------------------------------------------------------------------- |
| उपकरण सूची                     | 39         | मैनुअल और IDE एकीकरण सहित प्रलेखित कोडिंग उपकरण और एजेंट                               |
| `omniroute run <target>`       | 8          | एडेप्टर लॉन्च करें जो लक्ष्य के समापन बिंदु, क्रेडेंशियल्स और मॉडल की आपूर्ति करते हैं |
| `omniroute configure <target>` | 12         | `setup-*` कमांड द्वारा समर्थित इंटरएक्टिव कॉन्फ़िगरेशन रेसिपी                          |
| `setup-*` आदेश                 | 16         | पंजीकृत सेटअप कमांड, जिसमें guided/manual संपादक सेटअप भी शामिल है                     |

गणना 2026-11-17 को [टूल मेनिफेस्ट](../../config/cli-tools-manifest.json) और [कमांड रजिस्ट्री को](../../bin/cli/commands/registry.mjs) दर्शाती है। कैटलॉग प्रविष्टि का तात्पर्य लॉन्च एडॉप्टर से नहीं है। संपूर्ण सूची के लिए [CLI टूल कैटलॉग](../reference/CLI-TOOLS.md) देखें।

एक जेनेरिक लॉन्चर — `omniroute run <target>` — भी है जो `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen`, `gemini` या `whycodes` को सही एनवी इंजेक्ट के साथ उत्पन्न करता है, बिना कोई कॉन्फिगरेशन लिखे। लक्ष्य और उनके उपनाम विहित प्रकट `bin/cli/cli-manifest.mjs` (`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`, `open-code`, `qwen-code`, `gemini-cli`, `why-codes|why`) से आते हैं, और `omniroute completion` समान प्रकट-व्युत्पन्न लक्ष्य शब्द प्रदान करता है। `omniroute launch <tool>` एक समर्थित कोडिंग टूल को प्रति-लॉन्च सत्र टोकन और आपके द्वारा कनेक्ट किए गए प्रदाताओं से निर्मित एक मॉडल सूची के साथ शुरू करता है, और जब कोई भी नहीं चलता है तो एक स्थानीय गेटवे को स्वचालित रूप से शुरू करता है (देखें [LAUNCH.md](./LAUNCH.md) )। बिना टूल नाम (Claude Code) और `omniroute launch-codex` (Codex) — लीगेसी प्रति-टूल लॉन्चर — `omniroute launch` उपलब्ध रहते हैं।

प्रदाता ऑनबोर्डिंग उसी local/remote संदर्भ से उपलब्ध है। नीचे दिए गए एपीआई-प्रथम आदेश प्रबंधन प्रमाणीकरण को प्रदाता क्रेडेंशियल से अलग रखते हैं और कभी भी संरचित आउटपुट में क्रेडेंशियल प्रिंट नहीं करते हैं:

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

स्क्रिप्ट के लिए, `--credential-stdin` या `--credential-env` को प्राथमिकता दें; `--credential` को नियंत्रित स्थानीय उपयोग के लिए रखा गया है। `providers remove` को एक गैर-इंटरैक्टिव टर्मिनल पर `--yes` आवश्यकता होती है, और सभी पांच कमांड सक्रिय संदर्भ या वैश्विक `--base-url`/`--api-key` विकल्पों का सम्मान करते हैं।

प्रदाता चयनकर्ता अस्पष्ट ID उपसर्गों, नामों या प्रदाता नामों को अस्वीकार करते हैं; जब कई कनेक्शन मेल खाते हों तो पूर्ण कनेक्शन ID का उपयोग करें। कमांड बनाएं और संपादित करें, सहेजे गए कनेक्शन को वापस पढ़ें, और हटाने से यह सत्यापित होता है कि यह अब पढ़ने योग्य नहीं है। एक आयात मौजूदा provider/name जोड़ी को छोड़ देता है। आयातित प्रविष्टियाँ CLI को आपूर्ति किए गए प्रबंधन समापन बिंदु, संदर्भ या प्रबंधन क्रेडेंशियल्स को ओवरराइड नहीं कर सकती हैं।

दो सबसे समृद्ध एकीकरणों के एक बार के हस्तलिखित आधार सेटअप के लिए, प्रति-टूल गहराई से जानकारी देखें:

- [Claude कोड कॉन्फ़िगरेशन](./CLAUDE-CODE-CONFIGURATION.md)
- [Codex CLI विन्यास](./CODEX-CLI-CONFIGURATION.md)
- [रिमोट मोड](./REMOTE-MODE.md) — आपके लैपटॉप से रिमोट OmniRoute (VPS / टेलनेट) चलाता है
- [VS कोड Copilot चैट](./VSCODE-COPILOT.md) — OmniCopilot एक्सटेंशन; यह संपादक के अंदर से आपके लिए ये `setup-*` कमांड भी चला सकता है

## मास्टर टेबल

हर आदेश का सम्मान करता है** सक्रिय संदर्भ** ( `omniroute connect` के साथ सेट करें, [रिमोट मोड](./REMOTE-MODE.md) देखें) या स्पष्ट `--remote <url> --api-key <key>` झंडे। नीचे दिए गए "स्थानीय बनाम दूरस्थ" का अर्थ है: बिना किसी झंडे के यह `http://localhost:20128` को लक्षित करता है; `--remote` (या एक सक्रिय दूरस्थ संदर्भ) के साथ यह उस सर्वर को बैकएंड के रूप में कॉन्फ़िगर करता है और स्थानीय रूप से कॉन्फ़िगरेशन लिखता है। कैटलॉग-आधारित व्यंजन उस सर्वर से मॉडल भी लाते हैं।

| `omniroute setup-whycodes` | WhyCodes                      | WhyCodes `config.toml` (`[providers.omniroute]` + `[default_model]`); पथ `$WHYCODES_HOME/config.toml` या `~/.whycodes/config.toml` है                                                   | `--remote` `--api-key` `--model` `--yes` `--dry-run` `--port` `--config-path`                                                              | दोनों               |
| `omniroute run <target>`   | रनटाइम लॉन्च (सामान्य)        | कुछ भी नहीं — सही env और args के साथ `claude`/`codex` `aider` `goose`/`opencode`/`qwen`/`gemini`/`whycodes` को जन्म देता है; Qwen और Gemini एक अस्थायी पृथक घर का उपयोग करते हैं        | `--remote` `--base-url` `--context` `--provider` `--model` `--api-key` `--api-key-env` `--dry-run` `--json` `--port` `--profile` `--token` | दोनों               |
| `omniroute launch`         | Claude कोड                    | कुछ भी नहीं — `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` इंजेक्शन के साथ `claude` जन्म देता है                                                                                         | `--remote` `--api-key` `--token` `--profile` `--port`                                                                                      | दोनों               |
| `omniroute launch <tool>`  | कोई भी लॉन्च करने योग्य उपकरण | आपकी अपनी कॉन्फ़िगरेशन में कुछ भी नहीं: एक निजी अस्थायी डीआईआर में प्रति-लॉन्च कॉन्फ़िगरेशन, एक सत्र टोकन                                                                               | `--model` `--all-models` `--list` `--remote` `--port` `--api-key` `--profile` `--dry-run` `--json`                                         | दोनों               |
| `omniroute launch-codex`   | OpenAI Codex CLI              | कुछ भी नहीं — `codex` को `omniroute` प्रदाता के साथ `-c` झंडे के माध्यम से उत्पन्न करता है                                                                                              | `--remote` `--api-key` `--profile` (`-p`) `--port`                                                                                         | दोनों               |

झंडे पर नोट्स (कमांड स्रोत में सत्यापित):

- `--remote <url>` — एक दूरस्थ OmniRoute उपयोग करता है ( `--port` और सक्रिय संदर्भ को ओवरराइड करता है)। `--api-key <key>` उस सर्वर के लिए क्रेडेंशियल प्रदान करता है ( `OMNIROUTE_API_KEY` env var, या सक्रिय संदर्भ के टोकन पर डिफ़ॉल्ट)।
- `--only <patterns>` — अल्पविराम से अलग किए गए सबस्ट्रिंग्स; केवल वही मॉडल IDs रखें जो मेल खाता हो (जैसे `--only glm,kimi`)। `setup-codex`, `setup-claude`, `setup-opencode`, `setup-continue`, `setup-cursor`, `setup-crush`, `setup-zed` पर उपलब्ध है।
- `--dry-run` — फ़ाइल सिस्टम को छुए बिना बिल्कुल वही प्रिंट करें जो लिखा जाएगा। प्रत्येक `setup-*` कमांड पर उपलब्ध है** के अलावा** `setup-cursor` (जो कभी फ़ाइल नहीं लिखता)।
- `--model <id>` — उन टूल के लिए आवश्यक है (या इंटरैक्टिव रूप से चुना गया है) जिनमें कोई मॉडल ऑटो-डिस्कवरी नहीं है: Cline, Kilo, Roo, Goose, Qwen, Gemini, Aider, 5dive, WhyCodes। वे उपकरण गैर-इंटरैक्टिव रन के लिए `--yes` भी स्वीकार करते हैं (जिसके लिए `--model` की आवश्यकता होती है)। `setup-opencode` डिफ़ॉल्ट शीर्ष-स्तरीय मॉडल सेट करने के लिए `--model` लेता है।
- `omniroute run` पर `--model <id>` मेनिफेस्ट की प्रति-लक्ष्य वायरिंग (`bin/cli/cli-manifest.mjs`) का अनुसरण करता है:** सहायक** `--model openai/<id>` और प्राप्त करता है** opencode** `--model omniroute/<id>` (उपसर्ग केवल तभी जोड़ा जाता है जब आईडी में यह पहले से न हो);** क्वेन** और** मिथुन** आईडी शब्दशः प्राप्त करें;** क्लाउड** इसे `ANTHROPIC_MODEL` के माध्यम से प्राप्त करता है,** बत्तख** `GOOSE_MODEL` के माध्यम से,** क्योंकोड** `-P omniroute -m <id>` के माध्यम से, और** कोडेक्स** `-c model_providers.omniroute.*` args के माध्यम से।**Qwen एकमात्र रन लक्ष्य है जिसके लिए `--model` सख्त आवश्यकता होती है** इसके बिना — `omniroute run qwen` एक स्पष्ट त्रुटि के साथ `2` बाहर निकलता है।
- `--port <port>` — स्थानीय OmniRoute पोर्ट (डिफ़ॉल्ट `20128`, `--remote` सेट होने पर अनदेखा कर दिया जाता है)। सभी `setup-*` और दोनों लॉन्चरों पर मौजूद।
- `omniroute run` निकास कोड: बच्चे CLI का अपना निकास कोड शब्दशः प्रचारित किया जाता है; `2` = अमान्य तर्क (असमर्थित लक्ष्य, आवश्यक `--model` गायब, कंटेनर गार्ड); `127` = लक्ष्य बाइनरी `PATH` में नहीं है; `130`/`143`/`129` जब लॉन्च `SIGINT`/`SIGTERM`/`SIGHUP` द्वारा समाप्त हो जाता है; `1` = अन्य रनटाइम लॉन्च विफलता।
- दो लॉन्चर (`launch`, `launch-codex`) `setup-claude` / `setup-codex` द्वारा लिखी गई प्रोफ़ाइल का चयन करने के लिए `--profile <name>` स्वीकार करते हैं, साथ ही अंतर्निहित `claude` / `codex` बाइनरी के लिए पास-थ्रू तर्क भी स्वीकार करते हैं।

इंटरैक्टिव पिकर को सेटअप व्यंजनों द्वारा भी साझा किया जाता है:

```bash
# Pick from the active local or remote model catalog and configure the target.
omniroute configure claude
omniroute configure opencode --provider glm
omniroute configure qwen --model qwen/qwen3.8-max-preview --yes
omniroute configure gemini
omniroute configure whycodes
```

`configure` वर्तमान में `codex`, `claude`, `opencode`, `qwen`, `gemini`, `aider`, `goose`, `cline`, `continue`, `kilo`, `5dive`, और `whycodes` के लिए परीक्षण किए गए व्यंजनों को सौंपता है। केवल-आईडीई, MITM और गाइड-केवल कैटलॉग प्रविष्टियाँ स्पष्ट `setup-*`/मैन्युअल प्रवाह बनी रहती हैं और लॉन्च करने योग्य लक्ष्य के रूप में प्रस्तुत नहीं की जाती हैं।

> `setup-opencode` है** हल्का ओपनई-संगत** OpenCode एकीकरण। एक समृद्ध प्लगइन एकीकरण — `omniroute setup opencode` — भी है जो `@omniroute/opencode-plugin` स्थापित करता है। वे अलग-अलग आदेश हैं; दस्तावेज़ों के ऊपर दी गई तालिका `setup-opencode`.
>
> प्लगइन दो पैकेजों में आता है, एक प्रति OpenCode प्रमुख, क्योंकि दो लोडर अलग-अलग प्रविष्टि बिंदुओं की अपेक्षा करते हैं: OpenCode v1 के लिए `@omniroute/opencode-plugin` और OpenCode v2 के लिए `@omniroute/opencode-plugin-v2` । V2 पैकेज नया (`0.1.0`) है और एक होस्ट अनुबंध का पालन करता है जो अभी भी चल रहा है, इसलिए यह आकार OpenCode बीजों को एक मानने के बजाय कैटलॉग ड्राफ्ट में पढ़ता है। `opencode.json` में `plugins` प्रविष्टि जोड़कर इसे स्थापित करें; `omniroute setup opencode` अभी भी v1 पैकेज स्थापित करता है। विकल्प और क्रेडेंशियल लुकअप ऑर्डर पैकेज README में हैं।

## स्थानीय उपयोग

`localhost:20128` पर OmniRoute के चलने के दौरान, बस अपने टूल के लिए सेटअप कमांड चलाएँ। कैटलॉग स्थानीय सर्वर से प्राप्त किया जाता है।

```bash
# Codex: प्रत्येक मेल खाने वाले मॉडल के लिए ~/.codex/ में एक प्रोफ़ाइल लिखें
omniroute setup-codex
codex --profile glm52            # जनरेट की गई प्रोफ़ाइल का उपयोग करें

# Claude Code: प्रत्येक मॉडल के लिए प्रोफ़ाइल लिखें, फिर किसी एक को लॉन्च करें
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode: सभी कैटलॉग मॉडलों के साथ openai-संगत प्रोवाइडर लिखें
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # {env:OMNIROUTE_API_KEY} के माध्यम से संदर्भित, डिस्क पर कभी नहीं
opencode -m omniroute/glm/glm-5.2 "..."

# स्वतः खोज की सुविधा के बिना टूल्स के लिए स्पष्ट मॉडल आवश्यक है:
omniroute setup-aider --model glm/glm-5.2
omniroute setup-qwen --model qwen/qwen3.8-max-preview

# कुछ भी लिखे बिना पूर्वावलोकन करें:
omniroute setup-continue --dry-run
```

कोई भी कॉन्फ़िगरेशन लिखे बिना लॉन्च करें (केवल एनवायरनमेंट इंजेक्शन):

```bash
omniroute launch                 # Claude Code → स्थानीय OmniRoute
omniroute launch-codex           # Codex CLI → स्थानीय OmniRoute
omniroute launch-codex --profile glm52
omniroute run claude --model openai/gpt-5.4
omniroute run codex --model openai/gpt-5.4 --dry-run --json
omniroute run aider --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# स्पष्ट कमांड पथ: -- के बाद आने वाली हर चीज़ को ज्यों का त्यों पास करें
omniroute run claude -- --print-system-prompt "review this diff"
```

## रिमोट उपयोग

किसी भी सेटअप कमांड को `--remote` + `--api-key` के साथ किसी रिमोट OmniRoute की ओर निर्देशित करें। कैटलॉग रिमोट से प्राप्त किया जाता है; कॉन्फ़िगरेशन आपकी स्थानीय मशीन पर लिखा जाता है।

```bash
# रिमोट VPS के साथ OpenCode, केवल glm/kimi मॉडल रखें
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx \
  --only glm,kimi
opencode -m omniroute/glm/glm-5.2 "..."   # पहले OMNIROUTE_API_KEY एक्सपोर्ट करें

# रिमोट कैटलॉग से Codex प्रोफ़ाइल
omniroute setup-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# CLI को सीधे रिमोट के साथ लॉन्च करें
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

हर बार `--remote`/`--api-key` पास करने के बजाय, एक बार लॉग इन करें और **सक्रिय कॉन्टेक्स्ट** को उन्हें स्वचालित रूप से प्रदान करने दें:

```bash
omniroute connect 192.168.0.15        # सीमित-स्कोप वाला टोकन बनाता है, कॉन्टेक्स्ट संग्रहीत करता है
omniroute setup-codex                 # ← अब रिमोट कैटलॉग का उपयोग करता है
omniroute setup-opencode              # ← वही
omniroute launch                      # ← रिमोट के साथ Claude Code
```

कॉन्टेक्स्ट, स्कोप और टोकन प्रबंधन के लिए [रिमोट मोड](./REMOTE-MODE.md) देखें।

## 5गोताखोर एजेंट बेड़े

[5dive](https://5dive.ai) लंबे समय तक चलने वाले कोडिंग एजेंटों का एक बेड़ा चलाता है, जिनमें से प्रत्येक अपने स्वयं के यूनिक्स उपयोगकर्ता के तहत एक सिस्टम यूनिट है। यह स्वयं कोडिंग CLI नहीं है, इसलिए `omniroute run` के लिए — लॉन्च करने के लिए कुछ भी नहीं है `5dive` एक है** केवल-कॉन्फ़िगर करें** लक्ष्य।

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

दोनों फॉर्म एक 5डाइव लिखते हैं** प्रामाणिक प्रोफ़ाइल** , और उस प्रोफ़ाइल से जुड़ी प्रत्येक `claude` सीट फिर OmniRoute से बात करती है। इस लक्ष्य के लिए तीन बातें विशिष्ट हैं:

- **यह फ़्लीट होस्ट पर रूट के रूप में चलता है।** 5डाइव की क्रियाएं स्थानीय सिस्टमड इकाइयों और रूट-स्वामित्व वाली राज्य डीआईआर पर कार्य करती हैं; कोई रिमोट मोड नहीं है. नुस्खा `sudo` के माध्यम से फिर से निष्पादित होता है जब यह पहले से ही रूट नहीं होता है (`--no-sudo` इसे बंद कर देता है और इसके बजाय कमांड प्रिंट करता है)।
- **जब तक यह लूपबैक न हो, समापन बिंदु `https://` होना चाहिए।** एजेंट की API कुंजी प्रत्येक अनुरोध पर उस URL की सवारी करती है, और 5dive एक प्लेनटेक्स्ट ऑफ-बॉक्स एंडपॉइंट को अस्वीकार कर देता है। एक निजी LAN पता कोई अपवाद नहीं है।
- **प्रत्येक सीट का अपना मॉडल पिन प्रोफ़ाइल से आगे निकल जाता है।** प्रोफ़ाइल में `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` है, लेकिन स्टॉक मॉडल आईडी पर अभी भी पिन की गई एक सीट _"चयनित मॉडल के साथ एक समस्या है"_ के साथ अपनी पहली बारी में विफल हो जाती है। सीटों को पिन करने के लिए `--agent <name>` (दोहराने योग्य) पास करें; जब आप ऐसा नहीं करते तो रेसिपी कमांड प्रिंट कर देती है।

API कुंजी 5dive को सौंपी जाती है** stdin** (`--api-key=-`), इसलिए यह `ps` आउटपुट में कभी प्रकट नहीं होता है।

प्रोफ़ाइल को OmniRoute पर इंगित करना** कॉम्बो** एकल मॉडल के बजाय फ़्लीट प्रदाता फ़ेलओवर प्राप्त करता है: जब प्राथमिक समापन बिंदु [#11578](https://github.com/cheaper-inference/OmniRoute/issues/11578) पर रिकॉर्ड किए गए रन के मध्य-मोड़ में हार्ड-डाउन हो गया, तो एजेंट ने फ़ॉलबैक पर अपने शेष चरण पूरे कर लिए और कभी भी आउटेज सामने नहीं आया।

## अपडेट के दौरान नेटिव डिपेंडेंसी बनाए रखना: `--include=optional`

जब आप `omniroute update` से अपडेट करते हैं (पुष्टि करने के बाद, या `--apply` के साथ),
तो OmniRoute इंस्टॉल कमांड को पहले से शामिल `--include=optional` के साथ चलाता है:

```bash
npm install -g omniroute@latest --include=optional
```

यह कोई ऐसा फ़्लैग **नहीं** है जिसे आप `omniroute update` को पास करते हैं — अपडेटर इसे हमेशा
लागू करता है। यह सुनिश्चित करता है कि `optionalDependencies` (`better-sqlite3`, `keytar`,
`tls-client`, LLMLingua SLM स्टैक) अपडेट के बाद भी बने रहें, भले ही आपके npm कॉन्फ़िगरेशन में
`omit=optional` सेट हो, जो अन्यथा नेटिव SQLite ड्राइवर और OS-कीरिंग बाइंडिंग को
बिना सूचना दिए हटा देता। लागू किए बिना सटीक कमांड का पूर्वावलोकन करने के लिए:

```bash
omniroute update --dry-run
# [ड्राई रन] यह चलाया जाएगा: npm install -g omniroute@latest --include=optional
```

अन्य `omniroute update` फ़्लैग (स्रोत में सत्यापित): `--check` (पुराना संस्करण होने पर
1 के साथ बाहर निकलें), `--apply` (बिना पूछे इंस्टॉल करें), `--changelog`, `--no-backup`,
`--yes`।

## `omniroute run gemini` के माध्यम से Google Gemini CLI

`@google/gemini-cli` 0.50.0 के विरुद्ध अनुबंध सत्यापित: CLI
`GOOGLE_GEMINI_BASE_URL` का पालन करता है और उसके विरुद्ध `POST /v1beta/models/<model>:generateContent`
(और `:streamGenerateContent?alt=sse`) अनुरोध भेजता है — बिल्कुल OmniRoute के नेटिव
Gemini इंटरफ़ेस (`/v1beta`) की तरह। `omniroute run gemini` इसे स्वचालित रूप से जोड़ता है:

- `GOOGLE_GEMINI_BASE_URL` → सक्रिय OmniRoute बेस URL (रूट, `/v1` के बिना);
- `GEMINI_API_KEY` → निर्धारित OmniRoute क्रेडेंशियल (विकल्प/env/कॉन्टेक्स्ट);
- एक **अस्थायी पृथक `GEMINI_CLI_HOME`**, जिसकी `.gemini/settings.json`
  `gemini-api-key` प्रमाणीकरण चुनती है, ताकि संग्रहीत Google OAuth सेशन (Code Assist)
  कभी भी OmniRoute को निर्देशित लॉन्च को ओवरराइड न करे — बाहर निकलने के बाद इसे हटा दिया जाता है;
- **env स्वच्छता**: चाइल्ड env से `GOOGLE_API_KEY`,
  `GOOGLE_GENAI_USE_VERTEXAI` और `GOOGLE_GENAI_USE_GCA` हटा दिए जाते हैं (जो प्रमाणीकरण को
  Vertex/Code Assist की ओर रीडायरेक्ट कर देते), और अतिरिक्त सुरक्षा के लिए `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key`
  सेट किया जाता है — अन्य `run` लक्ष्यों के अपने परस्पर-विरोधी वेरिएबल्स के साथ भी यही
  प्रक्रिया अपनाई जाती है;
- `--provider`/`--model` से `--model <id>` इंजेक्शन।

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

Gemini का वर्कस्पेस-ट्रस्ट गार्ड हेडलेस मोड में भी लागू होता है — स्वयं
`--skip-trust` पास करें (या डायरेक्टरी पर इंटरैक्टिव रूप से भरोसा करें); लॉन्चर
जानबूझकर इसे बायपास नहीं करता। यह लॉन्चर **ACP
पंजीकरण** (`src/lib/acp/registry.ts`, `gemini --acp`) से अलग है, जो
`/dashboard/acp-agents` के लिए एजेंट-प्रोटोकॉल इंटीग्रेशन बना रहता है।

## वास्तविक स्मोक स्वीप (ऑप्ट-इन)

निर्धारित लॉन्च-प्लान रिग्रेशन CI में चलता है (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`)। वास्तविक OmniRoute सर्वर के विरुद्ध वास्तविक
बाइनरी को सत्यापित करने के लिए, एक ऑप्ट-इन हार्नेस
`tests/integration/upstream-cli-smoke.int.test.ts` पर उपलब्ध है। यह कभी भी स्वचालित रूप से नहीं चलता
(जब तक `RUN_CLI_SMOKE=1` न हो, प्रत्येक उप-परीक्षण छोड़ दिया जाता है), क्रेडेंशियल को env-var
नाम के माध्यम से पास करता है (मान के माध्यम से कभी नहीं), किसी भी रिकॉर्ड किए गए आउटपुट से कुंजी-जैसी स्ट्रिंग को छिपाता है, ऐसे
लक्ष्यों को छोड़ देता है जिनकी बाइनरी इंस्टॉल नहीं है, और विफलताओं को केवल बूलियन के बजाय
auth / upstream / config के रूप में वर्गीकृत करता है:

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

वैकल्पिक: `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` स्वीप को सीमित करता है;
`OMNIROUTE_SMOKE_TIMEOUT_MS` प्रत्येक लक्ष्य के लिए 120s टाइमआउट को ओवरराइड करता है।
