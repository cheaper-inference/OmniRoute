एक कस्टम JSON API नोड एक JSON बिजनेस एंडपॉइंट को जोड़ता है जो OpenAI या Anthropic प्रोटोकॉल को नहीं बोलता है। OmniRoute एक JSON अनुरोध टेम्पलेट भरता है, इसे पूर्ण समापन बिंदु URL पर भेजता है, प्रतिक्रिया पथ से उत्तर पढ़ता है और इसे क्लाइंट के अपने प्रारूप में क्लाइंट को लौटाता है (चैट पूर्णताएं, प्रतिक्रियाएं, संदेश, ...)।

यह `apiType: "custom-json"` के साथ एक OpenAI-संगत नोड है; इसकी आईडी का फॉर्म `openai-compatible-custom-json-<suffix>` है। डैशबोर्ड फॉर्म अभी उपलब्ध नहीं है. नीचे दिए गए प्रदाता-नोड API के माध्यम से इन नोड्स को बनाएं और संपादित करें।

## एक नोड बनाएं

`POST /api/provider-nodes` (प्रबंधन प्राधिकरण):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` है** पूरा** समापन बिंदु URL। कुछ भी नहीं जोड़ा गया है (कोई `/chat/completions` नहीं, कोई `/models` नहीं) और, अन्य OpenAI-संगत नोड्स के विपरीत, कोई डिफ़ॉल्ट URL नहीं है। यह `http(s)` होना चाहिए, बिना एंबेडेड क्रेडेंशियल या `#fragment`, और यह प्रत्येक प्रदाता नोड के समान आउटबाउंड URL गार्ड को पास करता है, जब नोड सहेजा जाता है और प्रत्येक अनुरोध पर।
- एक नोड जो कनेक्शन कुंजी (`authType` `bearer` या `api-key`, डिफ़ॉल्ट सहित) भेजता है, उसे `https://` उपयोग करना चाहिए। सादा `http://` केवल लूपबैक होस्ट (`localhost`, `127.0.0.0/8`, `::1`) या `authType: "none"` के साथ स्वीकार किया जाता है, जो कोई कुंजी नहीं भेजता है। निजी LAN पते (`10.x`, `172.16-31.x`, `192.168.x`) को छूट नहीं है: उस नेटवर्क पर कोई भी व्यक्ति कुंजी पढ़ सकता है। ऐसे नोड को सहेजना `400` के साथ विफल हो जाता है, और पहले से संग्रहीत नोड किसी भी अनुरोध को भेजे जाने से पहले उसी संदेश के साथ प्रत्येक अनुरोध पर बंद हो जाता है। LAN पर एक कुंजीयुक्त समापन बिंदु के लिए, इसे TLS के पीछे रखें (उदाहरण के लिए एक रिवर्स प्रॉक्सी)।
- `customJson` Zod के साथ मान्य किया गया है; अज्ञात कुंजियाँ अस्वीकार कर दी जाती हैं. प्रत्येक फ़ील्ड वैकल्पिक है:

| मैदान             | मान                                             | गलती करना                                              |
| ----------------- | ----------------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                          | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                     | `bearer`                                               |
| `authHeader`      | हेडर नाम का उपयोग `api-key` के समय किया जाता है | `X-API-Key`                                            |
| `requestTemplate` | JSON ऑब्जेक्ट (≤ 64 KB, गहराई ≤ 32)             | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | पूरे शरीर के लिए फ़ील्ड पथ, या `$`              | `choices[0].message.content`                           |

- रहस्य कनेक्शन की API कुंजी में रहता है, टेम्पलेट में कभी नहीं। `bearer` `Authorization: Bearer <key>` भेजता है; `api-key` `<authHeader>: <key>` भेजता है। ऑथ हेडर `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` या हॉप-बाय-हॉप हेडर नहीं हो सकता। `none` के साथ, कनेक्शन के लिए किसी कुंजी की आवश्यकता नहीं होती है।
- अतिरिक्त स्थैतिक हेडर नोड के नियमित `customHeaders` उपयोग करते हैं (प्रत्येक अन्य संगत नोड के समान सत्यापन; ऑथ हेडर की वहां अनुमति नहीं है)।

`PUT /api/provider-nodes/<id>` उसी `customJson` स्वीकार करता है और नोड के प्रत्येक मौजूदा कनेक्शन पर `baseUrl` और कॉन्फ़िगरेशन को फिर से लिखता है। `customJson` को छोड़ने से संग्रहीत कॉन्फ़िगरेशन बना रहता है; `apiType` को `chat` या `responses` पर स्विच करने से यह नोड और उसके कनेक्शन से हट जाता है।

फिर हमेशा की तरह नोड में एक कनेक्शन जोड़ें (नोड आईडी के साथ `POST /api/providers` ) और `<prefix>/<model>` का अनुरोध करें, उदाहरण के लिए `biz/assistant-v1`। समापन बिंदु कोई मॉडल सूची नहीं दिखाता है, इसलिए मॉडल आईडी हाथ से जोड़ें।

## टेम्प्लेट का अनुरोध करें

टेम्प्लेट सादे JSON हैं। एक स्ट्रिंग मान में `{{placeholder}}` मार्कर हो सकते हैं; किसी भी चीज़ का मूल्यांकन या निष्पादन नहीं किया जाता है, और ऑब्जेक्ट कुंजियाँ कभी भी प्रतिस्थापित नहीं की जाती हैं।

| प्लेसहोल्डर          | कीमत                                                                      |
| -------------------- | ------------------------------------------------------------------------- |
| `{{prompt}}`         | नवीनतम उपयोगकर्ता संदेश का पाठ (पाठ के भाग नई पंक्तियों के साथ जुड़े हुए) |
| `{{messages}}`       | OpenAI चैट प्रारूप में बातचीत                                             |
| `{{model}}`          | अनुरोधित मॉडल आईडी, प्रदाता उपसर्ग के बिना                                |
| `{{stream}}`         | हमेशा एक JSON दस्तावेज़ के साथ समापन बिंदु उत्तर `false` —                |
| `{{request.<path>}}` | अनुवादित (OpenAI चैट प्रारूप) अनुरोध का एक क्षेत्र                        |

- एक मान जो बिल्कुल एक प्लेसहोल्डर है, अपना JSON प्रकार रखता है (`"{{messages}}"` एक सरणी बन जाता है); एक लंबी स्ट्रिंग के अंदर एक प्लेसहोल्डर को टेक्स्ट के रूप में डाला जाता है।
- एक प्लेसहोल्डर जो कुछ भी नहीं हल करता है वह अपूर्ण पेलोड भेजने के बजाय HTTP 400 के साथ अनुरोध को विफल कर देता है।
- पथ डॉट नोटेशन और संख्यात्मक अनुक्रमणिका (`data.items[0].text`) का उपयोग करते हैं। `__proto__`, `prototype` और `constructor` कुंजियों और पथों में अस्वीकार कर दिया गया है।

## जवाब

`responsePath` पर मान सहायक उत्तर बन जाता है: तार गुजरते हैं, अन्य JSON मान क्रमबद्ध होते हैं। एक गुम या `null` फ़ील्ड, या एक निकाय जो JSON नहीं है, HTTP 502 लौटाता है। अपस्ट्रीम त्रुटि स्थितियाँ पारित की जाती हैं। स्ट्रीमिंग क्लाइंट के लिए OmniRoute संपूर्ण JSON प्रतिक्रिया की प्रतीक्षा करता है और फिर इसे एक सामग्री खंड और अंतिम खंड के रूप में उत्सर्जित करता है; यह टोकन स्ट्रीमिंग नहीं है. टूल कॉल और उपयोग फ़ील्ड मैप नहीं किए गए हैं।

## दोबारा कभी नहीं खेला गया

किसी व्यावसायिक अनुरोध के विफल होने पर भी उसके दुष्प्रभाव हो सकते हैं। इसलिए OmniRoute इसे एक बार भेजता है:

- कोई परिवहन पुनः प्रयास नहीं और कोई पुनर्निर्देशन नहीं;
- किसी अन्य कनेक्शन पर कोई पुनः प्रयास नहीं (खाता फ़ॉलबैक) — विफलता यथावत लौटा दी जाती है और कनेक्शन ठंडा नहीं होता है;
- खाली या असफल उत्तर के लिए भी, अगले कॉम्बो लक्ष्य पर कोई फ़ॉलबैक नहीं।

अलग-अलग क्लाइंट अनुरोध, और फ़्यूज़न पैनल जो स्पष्ट रूप से कई मॉडलों को कॉल करते हैं, फिर भी स्वतंत्र रूप से एंडपॉइंट को कॉल करते हैं।

## एक नोड का परीक्षण

कनेक्शन सहेजा जा रहा है, कनेक्शन** परीक्षा** बटन और पृष्ठभूमि स्वास्थ्य जांच कभी भी समापन बिंदु को कॉल नहीं करती है: वे केवल संग्रहीत कॉन्फ़िगरेशन को मान्य करते हैं और कनेक्शन को सत्यापन योग्य नहीं के रूप में रिपोर्ट करते हैं।

`POST /api/provider-nodes/validate` `"apiType": "custom-json"` और नोड फ़ील्ड (`baseUrl`, `apiKey`, `customJson`, वैकल्पिक `customHeaders` और `modelId`) के साथ, नवीनतम उपयोगकर्ता पाठ के रूप में `ping` के साथ, बिल्कुल एक वास्तविक अनुरोध भेजता है। यह `{ "valid": true }` या अपस्ट्रीम स्थिति (अपस्ट्रीम बॉडी कभी नहीं) का उत्तर देता है।

## भंडारण

कॉन्फ़िगरेशन को `provider_nodes.custom_json_config_json` (माइग्रेशन `240_provider_node_custom_json_config.sql`) में संग्रहीत किया जाता है और प्रत्येक कनेक्शन के `providerSpecificData.customJson` में कॉपी किया जाता है।

कार्यान्वयन: `open-sse/utils/customJson.ts` (सत्यापन और टेम्प्लेटिंग), `open-sse/executors/customJson.ts` (निष्पादक), `open-sse/services/combo/noReplayLatch.ts` और `src/sse/handlers/chat/responsePolicies.ts` (नो-रीप्ले)।
