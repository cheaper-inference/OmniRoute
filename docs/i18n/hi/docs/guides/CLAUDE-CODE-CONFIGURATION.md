**Claude Code** CLI (`claude`) को OmniRoute — स्थानीय या रिमोट VPS — की ओर इंगित करें,
Codex सेटअप की तरह ही प्रति-मॉडल प्रोफ़ाइलों के साथ।

---

## त्वरित शुरुआत

```bash
# स्थानीय OmniRoute के साथ Claude Code लॉन्च करें (सक्रिय कॉन्टेक्स्ट का स्वतः पता लगाता है)
omniroute launch

# रिमोट OmniRoute के साथ (`omniroute connect <host>` के बाद यह स्वचालित होता है)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# प्रति-मॉडल प्रोफ़ाइलें जनरेट करें, फिर उनमें से एक लॉन्च करें
omniroute setup-claude            # ~/.claude/profiles/<name>/settings.json में लिखता है
omniroute launch --profile glm52  # OmniRoute के माध्यम से glm/glm-5.2 का उपयोग करता Claude Code
```

## Claude कोड गेटवे से कैसे जुड़ता है

Claude कोड बात करता है**Anthropic संदेश API** और पर्यावरण चर के साथ एक कस्टम समापन बिंदु पर इंगित किया गया है (इसमें कोई `--base-url` ध्वज नहीं है):

| चर                                           | उद्देश्य                                                                                                    |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | गेटवे रूट URL (Claude कोड `/v1/messages` जोड़ता है)।** कोई `/v1` प्रत्यय नहीं.**                            |
| `ANTHROPIC_AUTH_TOKEN`                       | `Authorization: Bearer …` — के रूप में भेजा गया अपनी OmniRoute एक्सेस टोकन / API कुंजी का उपयोग करें        |
| `ANTHROPIC_API_KEY`                          | वैकल्पिक: `x-api-key` के रूप में भेजा गया। यदि दोनों सेट हो जाते हैं, तो `ANTHROPIC_AUTH_TOKEN` जीत जाता है |
| `ANTHROPIC_MODEL`                            | एक विशिष्ट मॉडल को बाध्य करें ( `/model` पिकर डिफ़ॉल्ट को ओवरराइड करता है)                                  |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → मूल `/model` पिकर `/v1/models` से `claude*`/`anthropic*` मॉडल सूचीबद्ध करता है                        |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | प्रति प्रतिक्रिया कैप आउटपुट टोकन (जैसे `65536`)                                                            |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | ऑटो-संपीड़न के लिए टोकन सीमा                                                                                |

> Env संस्करण पढ़े जाते हैं** एक बार स्टार्टअप पर** — उन्हें बदलने के बाद Claude कोड को पुनरारंभ करें।

एक निश्चित स्ट्रिंग के बजाय घूमने वाले क्रेडेंशियल के लिए, `apiKeyHelper` `~/.claude/settings.json` में एक कमांड पर सेट करें जो वर्तमान क्रेडेंशियल को stdout पर प्रिंट करता है। Claude कोड अपने आउटपुट को डिफ़ॉल्ट रूप से पांच मिनट के लिए कैश करता है (`CLAUDE_CODE_API_KEY_HELPER_TTL_MS` उसे ओवरराइड करता है) और `Authorization: Bearer` और `x-api-key` दोनों में मान भेजता है। स्क्रिप्ट को क्रेडेंशियल प्रिंट करना होगा और इसके अलावा एक बैनर — नहीं होना चाहिए, यह v2.1.227 + पर सहायक को विफल कर देता है।

Entra ID SSO इस प्रकार काम करता है: `scripts/cli/omniroute-sso.mjs token` एक अल्पकालिक एंट्रा एक्सेस टोकन प्रिंट करता है जिसे OmniRoute एक API कुंजी के बजाय सत्यापित करता है। [`docs/security/ENTRA_SSO.md`](../security/ENTRA_SSO.md) देखें।

`omniroute launch` आपके लिए ये सब सेट करता है: यह सक्रिय संदर्भ से आधार URL + टोकन को हल करता है (इसलिए `omniroute connect <vps>` तब `omniroute launch` बस काम करता है), सर्वर की स्वास्थ्य जांच करता है, और `claude` निष्पादित करता है।

## उपयोग विशेषता: सत्र और परियोजनाएँ

OmniRoute प्रत्येक API कुंजी के अनुरोधों को समूहित करता है** एजेंट सत्र** और जो रिकार्ड करता है** परियोजना** प्रत्येक सत्र (`agent_sessions` तालिका) पर काम करता है, इसलिए प्रति टीम सदस्य, प्रति प्रोजेक्ट और प्रति सत्र उपयोग और लागत की रिपोर्ट की जा सकती है।

बिना किसी क्लाइंट सेटअप के क्या रिकॉर्ड किया गया है:

| मैदान    | स्रोत                                                                                                                                                    |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| सत्र     | `x-claude-code-session-id` हेडर ( `metadata.user_id.session_id` के समान मान), प्रति सत्र स्थिर                                                           |
| परियोजना | `Primary working directory:` लाइन Claude कोड अपने पर्यावरण संदेश भेजता है; `.claude/worktrees/` के अंतर्गत वर्कट्री फ़ोल्डर रिपॉजिटरी नाम पर हल होते हैं |
| शाखा     | git स्थिति से`Current branch:` Claude कोड पहले संदेश के साथ भेजता है                                                                                     |
| ग्राहक   | `user-agent` (`claude-cli/<version>`)                                                                                                                    |

Codex (`<environment_context><cwd>`) और OpenCode (`x-opencode-session`) को एक ही तरह से पहचाना जाता है। चाबियाँ के साथ** कोई लॉग** केवल सत्र आईडी और हेडर द्वारा प्रदत्त प्रोजेक्ट फ़ील्ड को सक्षम बनाए रखें; प्रॉम्प्ट (पथ, शाखा) से पढ़ा गया कुछ भी संग्रहीत नहीं है।

### प्रोजेक्ट का स्पष्ट नामकरण (अनुशंसित)

कार्यशील निर्देशिका मशीनों के बीच भिन्न होती है, इसलिए एक ही रिपॉजिटरी विभिन्न पथों के अंतर्गत दिखाई दे सकती है। इसके बजाय प्रोजेक्ट को स्पष्ट रूप से भेजें: Claude कोड प्रत्येक मॉडल अनुरोध में `ANTHROPIC_CUSTOM_HEADERS` में सूचीबद्ध किसी भी हेडर को जोड़ता है, और OmniRoute उनमें से दो को पढ़ता है:

| हैडर                       | कीमत                                                                 |
| -------------------------- | -------------------------------------------------------------------- |
| `x-omniroute-project`      | प्रोजेक्ट का नाम, उदाहरण के लिए `omniroute`                          |
| `x-omniroute-project-repo` | सामान्यीकृत रिमोट, उदाहरण के लिए `github.com/diegosouzapw/OmniRoute` |

दोनों को केवल श्रेय के लिए पढ़ा जाता है; उन्हें कभी भी अपस्ट्रीम प्रदाता को अग्रेषित नहीं किया जाता है।

`ANTHROPIC_CUSTOM_HEADERS` को स्टार्टअप पर एक बार पढ़ा जाता है, और सेटिंग्स फ़ाइलें शाब्दिक मान संग्रहीत करती हैं, इसलिए Claude कोड लॉन्च होने पर इसकी गणना करें। इसे `~/.zshrc` या `~/.bashrc` में जोड़ें और प्रोजेक्ट फ़ोल्डर से `claude` प्रारंभ करना जारी रखें:

```bash
claude() {
  local common name repo
  if common=$(git rev-parse --path-format=absolute --git-common-dir 2>/dev/null); then
    name=$(basename "$(dirname "$common")")  # repository name, also inside worktrees
    repo=$(git remote get-url origin 2>/dev/null \
      | sed -E 's#^[a-zA-Z][a-zA-Z0-9+.-]*://([^@/]*@)?##; s#^[^@/]+@([^:]+):#\1/#; s#\.git$##')
  else
    name=$(basename "$PWD")                  # not a git repository: folder name
  fi
  ANTHROPIC_CUSTOM_HEADERS="x-omniroute-project: ${name}${repo:+
x-omniroute-project-repo: ${repo}}" command claude "$@"
}
```

`sed` अभिव्यक्ति दूरस्थ URL में एम्बेडेड किसी भी क्रेडेंशियल को हटा देती है। IDE एक्सटेंशन आपके शेल के बिना Claude कोड लॉन्च करते हैं, इसलिए उनके सत्र कार्यशील निर्देशिका में वापस आ जाते हैं।

## डिस्कवरी एलियास — `/model` पिकर में गैर-Claude मॉडल दिखाना

Claude Code की गेटवे मॉडल डिस्कवरी केवल उन्हीं ids को सूचीबद्ध करती है जो `claude`
या `anthropic` से शुरू होती हैं, इसलिए `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`
के साथ भी मूल `/model` पिकर सामान्य रूप से **केवल** OmniRoute के Claude/Anthropic
मॉडल दिखाता है — कोई `kimi/kimi-k2.6` या `glm/glm-5.2` कभी नहीं दिखता, भले ही वह
ठीक से रूट होता हो।

OmniRoute किसी भी सक्षम मॉडल (और कॉम्बो) को `claude/…` id के अंतर्गत मिरर कर सकता
है ताकि वह उस फ़िल्टर को पास करके पिकर में दिखाई दे:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

जब आप Claude Code में इनमें से कोई एक चुनते हैं, तो OmniRoute रूटिंग से पहले
`claude/` रैपर हटाकर असली id पर वापस कर देता है — किसी असली
`claude/<real-claude-model>` id (वास्तविक Claude OAuth प्रदाता) को हमेशा अछूता
छोड़ा जाता है।

डिफ़ॉल्ट रूप से केवल बेस ids ही मिरर की जाती हैं। ऑप्ट-इन
`CATALOG_MIRROR_REFINEMENTS_ENABLED` फ़ीचर फ़्लैग चालू होने पर, कैटलॉग में पहले से
सूचीबद्ध reasoning-effort वैरिएंट (जैसे `codex/gpt-6-sol-high`) भी किसी अन्य id की
तरह मिरर किए जाते हैं, ताकि Claude Code कोई स्पष्ट effort स्तर चुन सके, और ऐसी
बिल्ट-इन `auto/*` ids जिन्हें रिक्वेस्ट पाथ मैटेरियलाइज़ नहीं कर सकता, मिरर नहीं
की जातीं। effort वैरिएंट सूचीबद्ध होते भी हैं या नहीं, यह अब भी
`OMNIROUTE_DISABLE_THINKING_LEVEL_VARIANTS` द्वारा नियंत्रित होता है — मिरर कभी भी
ऐसा वैरिएंट नहीं जोड़ता जो बेस कैटलॉग में मौजूद न हो।

**यह डिफ़ॉल्ट रूप से बंद होता है** और तीन-स्तरीय गेट द्वारा नियंत्रित होता है
(सबसे विशिष्ट स्तर प्राथमिकता पाता है), ताकि साधारण OmniRoute उन क्लाइंट के लिए
अपना कैटलॉग कभी दोगुना न करे जो Claude Code का उपयोग नहीं करते:

| स्तर    | कहाँ                                                                       |
| ------- | -------------------------------------------------------------------------- |
| मॉडल    | प्रदाता विवरण पृष्ठ → प्रति-मॉडल "Expose in Claude Code" टॉगल              |
| प्रदाता | प्रदाता विवरण पृष्ठ → प्रदाता-स्तरीय टॉगल (उसके सभी मॉडलों को कवर करता है) |
| वैश्विक | सेटिंग्स → फ़ीचर फ़्लैग्स → `EXPOSE_CC_DISCOVERY_ALIASES` (डिफ़ॉल्ट बंद)   |

`EXPOSE_CC_DISCOVERY_ALIASES` एनवायरनमेंट वेरिएबल वैश्विक स्तर को जबरन चालू कर
देता है और डैशबोर्ड ओवरराइड पर प्राथमिकता रखता है (ऐसा होने पर फ़ीचर फ़्लैग्स
स्क्रीन एक "active via environment variable" नोट दिखाती है)। प्रति-प्रदाता और
प्रति-मॉडल टॉगल वहाँ से आगे परिष्कृत करते हैं — जैसे वैश्विक बंद + Kimi प्रदाता
चालू करने पर केवल Kimi के मॉडल ही दिखते हैं।

> ⚠️ **गैर-Claude मॉडलों पर विंडो असंगति।** Claude Code किसी भी अपरिचित id के लिए
> 200K कॉन्टेक्स्ट विंडो मान लेता है (वह `/v1/models` से असली विंडो नहीं पढ़
> सकता)। बड़ी विंडो वाले मॉडल (जैसे Kimi K2 की 256K) के लिए,
> `CLAUDE_CODE_AUTO_COMPACT_WINDOW` को मॉडल की असली विंडो से कम मान पर सेट करें
> ताकि ऑटो-कॉम्पैक्शन समय से पहले ट्रिगर न हो। ऊपर बताई गई जनरेट की गई
> प्रोफ़ाइलें यह पहले से ही प्रति-मॉडल करती हैं।

## डैशबोर्ड पर ऑनबोर्डिंग ब्लॉक

Claude टूल कार्ड (**Dashboard → CLI Code**) इस इंस्टेंस के लिए सटीक `settings.json` फ़्रैगमेंट को
डिस्कवरी-अलियास जानकारी बटन के पास, एक कॉपी बटन के साथ प्रदर्शित करता है:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

बेस URL वही है जिसे कार्ड ने रिज़ॉल्व किया है (आपके द्वारा टाइप किया गया कस्टम ओवरराइड भी शामिल है), और वह पहले से
नॉर्मलाइज़ किया हुआ है — कोई `/v1` सफ़िक्स नहीं, कोई अंतिम स्लैश नहीं। **कुंजी कभी प्रदर्शित नहीं की जाती**: ब्लॉक में एक
प्लेसहोल्डर दिया जाता है, इसलिए किसी स्क्रीनशॉट या पेस्ट किए गए स्निपेट से वह लीक नहीं हो सकती। अपनी कुंजी उसके स्थान पर पेस्ट करें।

ऐसे किसी भी मॉडल के लिए, जिसकी वास्तविक कॉन्टेक्स्ट विंडो 200K नहीं है, उसी `env` ब्लॉक के अंतर्गत
`CLAUDE_CODE_AUTO_COMPACT_WINDOW` जोड़ें — Claude Code हर उस id के लिए 200K मानता है जिसे वह नहीं पहचानता, इसलिए
अन्यथा ऑटो-कम्पैक्शन गलत बिंदु पर सक्रिय होगा (पिछले अनुभाग की चेतावनी देखें)।
स्निपेट बिल्डर भी यह मान स्वीकार करता है, इसलिए लक्ष्य मॉडल की विंडो जानने वाला कॉलर
इसे सीधे उत्सर्जित कर सकता है।

स्रोत: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (शुद्ध
बिल्डर, यूनिट-परीक्षित), जिसे `ClaudeGatewayOnboardingBlock` द्वारा प्रदर्शित किया जाता है।

### एक अकाउंट पिन करें (वैकल्पिक)

हर Claude Code अनुरोध को किसी एक विशिष्ट प्रदाता अकाउंट के माध्यम से भेजने के लिए, उसी `env` ब्लॉक में
`ANTHROPIC_CUSTOM_HEADERS` के ज़रिए `x-omniroute-connection` हेडर जोड़ें:

```jsonc
"ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>"
```

प्रदाता पेज की कनेक्शन पंक्ति पर मौजूद `xxxxxxxx…` चिप से id कॉपी करें। पिन केवल
एकल-मॉडल ids (`provider/model`) पर लागू होता है, कॉम्बो पर नहीं। सटीक फ़ॉलबैक व्यवहार के लिए
[प्रति अनुरोध अकाउंट पिनिंग](../reference/API_REFERENCE.md#account-pinning-per-request) देखें।

## प्रोफ़ाइल (`CLAUDE_CONFIG_DIR`)

Claude Code में **कोई मूल प्रोफ़ाइल फ़ाइल नहीं होती** (Codex की `~/.codex/<name>.config.toml` के विपरीत)।
प्रचलित तंत्र `CLAUDE_CONFIG_DIR` है — प्रत्येक प्रोफ़ाइल के लिए एक अलग कॉन्फ़िगरेशन डायरेक्टरी,
जिसमें उसकी अपनी `settings.json`, क्रेडेंशियल, हिस्ट्री और कैश होती है।

`omniroute setup-claude` लाइव `/v1/models` कैटलॉग प्राप्त करता है और प्रत्येक मॉडल के लिए
`~/.claude/profiles/<name>/settings.json` पर एक प्रोफ़ाइल लिखता है, जिसमें
**`setup-codex` वाले समान नामों का पुनः उपयोग होता है** (`glm52`, `kimi-k27`, `deepseek-pro`, …):

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **ऑथ टोकन कभी भी प्रोफ़ाइल में नहीं लिखा जाता।** इसे
> `omniroute launch --profile <name>` से लॉन्च करें (यह सक्रिय कॉन्टेक्स्ट से `ANTHROPIC_AUTH_TOKEN`
> इंजेक्ट करता है), या स्वयं `ANTHROPIC_AUTH_TOKEN` एक्सपोर्ट करें और
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude` चलाएँ।

**मॉडल डिस्कवरी के बाद ऑटो-सिंक (ऑप्ट-इन)।** जब भी किसी प्रोवाइडर का मॉडल सिंक लाइव कैटलॉग को
बदलता है, OmniRoute इन्हीं `~/.claude/profiles/<name>/settings.json` फ़ाइलों को अपने-आप फिर से
जनरेट कर सकता है — जिससे नए/पुनर्नामित मॉडलों को कमांड दोबारा चलाए बिना प्रोफ़ाइल मिल जाती हैं।
यह **डिफ़ॉल्ट रूप से बंद** होता है: इसे **CLI Code डैशबोर्ड** से टॉगल करें ("CLI profile
auto-sync" → Claude Code), या `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` सेट करें (यह
`CLI_ALLOW_CONFIG_WRITES` का भी सम्मान करता है, जो डिफ़ॉल्ट रूप से चालू होता है)। सक्षम होने पर यह केवल
प्रोफ़ाइल फ़ाइलें लिखता है; यह आपके सक्रिय/डिफ़ॉल्ट Claude कॉन्फ़िगरेशन, ऑथ या `~/.claude/settings.json`
को कभी नहीं बदलता।

### प्रोफ़ाइल जनरेट करना + उनका उपयोग करना

```bash
# स्थानीय OmniRoute
omniroute setup-claude

# रिमोट VPS (प्रत्येक प्रोफ़ाइल में VPS URL समाहित करता है)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# केवल कुछ प्रोवाइडर
omniroute setup-claude --only glm,kimi

# इस होस्ट पर नहीं मिले स्थानीय-CLI प्रोवाइडर (zcode, auggie, devin-cli-agentic,
# codex-app-server) के लिए भी प्रोफ़ाइल लिखें (स्थानीय लक्ष्य के लिए डिफ़ॉल्ट रूप से छोड़ दिए जाते हैं)
omniroute setup-claude --include-local

# बिना लिखे पूर्वावलोकन करें
omniroute setup-claude --dry-run

# कोई प्रोफ़ाइल लॉन्च करें
omniroute launch --profile kimi-k27
```

## मॉडल स्तर (वैकल्पिक)

Claude Code क्षमताओं के अनुसार अलग-अलग स्तरों पर रूट करता है। यदि आप प्रत्येक स्तर के लिए अलग प्रदाता चाहते हैं, तो env /
सेटिंग्स के माध्यम से प्रत्येक स्तर को एक OmniRoute मॉडल से मैप करें:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

अन्यथा हर चीज़ के लिए एक ही `ANTHROPIC_MODEL` (जिसे प्रोफ़ाइल सेट करती हैं) का उपयोग किया जाता है।

## रिमोट मोड

एक बार `omniroute connect <host>` चलाने के बाद ([रिमोट मोड](./REMOTE-MODE.md) देखें), `omniroute launch` और `omniroute setup-claude`
स्वचालित रूप से उस रिमोट सर्वर को लक्षित करते हैं और उसके सीमित-दायरे वाले एक्सेस टोकन का उपयोग करते हैं — किसी
अतिरिक्त फ़्लैग की आवश्यकता नहीं होती। प्रत्येक आमंत्रण के लिए `--remote` / `--api-key` से इसे ओवरराइड करें।

## समस्या निवारण

**Claude Code गेटवे की अनदेखी करता है** — पुष्टि करें कि `ANTHROPIC_BASE_URL` में **`/v1`
नहीं है** और `claude` को पुनः आरंभ करें (env को स्टार्टअप के समय केवल एक बार पढ़ा जाता है)। `omniroute launch`
आपके लिए इसे संभालता है।

**`/model` चयनकर्ता खाली है / गेटवे मॉडल मौजूद नहीं हैं** — इसके लिए Claude Code
v2.1.219+ और `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` आवश्यक हैं। चयनकर्ता में केवल `claude*` /
`anthropic*` मॉडल ID दिखाई देती हैं; किसी अन्य मॉडल को
`ANTHROPIC_MODEL=<id>` से बाध्य करें (प्रोफ़ाइल यही करती हैं)।

**`400 Ambiguous model 'claude-…'`** — Claude Code हमेशा **उपसर्ग-रहित**
मॉडल ID भेजता है (उदा. `claude-opus-4-8`), इसलिए जब Claude Code (`cc/…`) और
Claude (`claude/…`) दोनों प्रदाता कनेक्ट हों, तो मूल ID दो रूट से मेल खाती है और
OmniRoute अनुमान लगाने से मना कर देता है। इसे किसी भी तरह ठीक करें: उपसर्ग वाली ID को
`ANTHROPIC_MODEL=cc/claude-opus-4-8` से पिन करें, या **उपसर्ग-रहित Claude मॉडलों के लिए Claude Code को प्राथमिकता दें**
सक्षम करें — Claude प्रदाता पृष्ठ पर मौजूद टॉगल, या
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (डिफ़ॉल्ट रूप से बंद;
[परिवेश](../reference/ENVIRONMENT.md) देखें) — जो मूल `claude-*`
ID को इसके बजाय Claude Code पर रूट करता है। स्पष्ट प्रदाता उपसर्गों को हमेशा प्राथमिकता मिलती है।

**प्रमाणीकरण त्रुटियाँ** — प्रोफ़ाइल में कोई टोकन नहीं होता। `omniroute launch --profile`
का उपयोग करें (यह उसे इंजेक्ट करता है) या `ANTHROPIC_AUTH_TOKEN` एक्सपोर्ट करें।

**प्रोफ़ाइल अलग-अलग नहीं रहतीं** — प्रत्येक प्रोफ़ाइल एक अलग `CLAUDE_CONFIG_DIR` है;
सत्यापित करें कि सत्र के भीतर `echo $CLAUDE_CONFIG_DIR`
`~/.claude/profiles/<name>` की ओर इंगित करता है।
