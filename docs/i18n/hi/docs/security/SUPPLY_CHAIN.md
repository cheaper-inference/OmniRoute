OmniRoute npm + Docker आर्टिफैक्ट प्रकाशित करता है। ये गेट प्रोवेनेंस, इन्वेंट्री (SBOM) और CVE स्कैनिंग प्रदान करते हैं, ये सभी OSS हैं, और रिलीज़ वर्कफ़्लो में प्लग किए गए हैं। **सलाह-प्रथम** दृष्टिकोण — वे अभी रिपोर्ट करते हैं, और पहली सफल रिलीज़ के बाद अवरुद्ध करने के लिए बढ़ावा देते हैं।

| गेट                   | टूल                                            | कहाँ                          | ब्लॉक करता है?              | आउटपुट                                            |
| --------------------- | ---------------------------------------------- | ----------------------------- | --------------------------- | ------------------------------------------------- |
| SLSA प्रोवेनेंस (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | केवल तभी जब प्रकाशन विफल हो | बैज npmjs / `npm audit signatures`                |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | केवल तभी जब जनरेशन विफल हो  | रिलीज़ एसेट + आर्टिफैक्ट                          |
| SBOM इमेज             | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | सलाहकारी                    | CycloneDX आर्टिफैक्ट                              |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | सलाहकारी                    | SARIF (HIGH+CRITICAL) → सुरक्षा टैब               |
| Trivy CRITICAL गेट    | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **अवरुद्ध करने वाला**       | `exit-code: '1'` फिक्स करने योग्य CRITICAL पर     |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **अवरुद्ध करने वाला**       | `metrics.vulnCount` को रैटचेट करता है (दिशा:नीचे) |
| OpenSSF स्कोरकार्ड    | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | सलाहकारी                    | SARIF → सुरक्षा + बैज                             |

इमेज CVE रैटचेट `docker-publish.yml` में **दो चरणों** का उपयोग करता है: SARIF चरण (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL को सुरक्षा टैब में बिना अवरुद्ध किए दृश्यमान रखता है; _CRITICAL गेट_ चरण (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) एक CRITICAL CVE पर रिलीज़ को विफल कर देता है **जिसके लिए एक फिक्स उपलब्ध है**। `ignore-unfixed` अपस्ट्रीम पैच के बिना बेस-इमेज CVE के लिए रिलीज़ को अवरुद्ध होने से रोकता है।

## ⚠️ CVE भिन्नता (osv/Trivy गेट्स को अवरुद्ध करना)

osv और Trivy deps की तुलना CVE डेटाबेस से करते हैं जो **लगातार बढ़ते रहते हैं**। एक PR जो **किसी भी डिपेंडेंसी को नहीं छूता है** वह अचानक लाल हो सकता है क्योंकि एक मौजूदा डिपेंडेंसी में एक नया CVE सामने आया है (osv: मापा गया `vulnCount` > बेसलाइन; Trivy: इमेज में एक नया फिक्स करने योग्य CRITICAL)। **यह एक अवरुद्ध CVE गेट का अपेक्षित परिचालन व्यवहार है, न कि उत्पाद प्रतिगमन।**

जब एक नए सामने आए CVE के कारण osv या Trivy लाल हो जाते हैं, तो उपाय है:

1.  **प्रभावित डिपेंडेंसी को बढ़ाएँ** (पसंदीदा) — `package.json` `overrides` (ट्रांजिटिव डिपेंडेंसी) के माध्यम से पैच किए गए संस्करण में अपग्रेड करें या पैच किए गए बेस पर इमेज को फिर से बनाएं।
2.  **यदि कोई अपस्ट्रीम फिक्स नहीं है:**
    - **osv:** `config/quality/quality-baseline.json` में `metrics.vulnCount` को फिर से बेसलाइन करें (`npm run quality:ratchet -- --update` समर्पित गेट्स को कवर नहीं करता है — मान को मैन्युअल रूप से संपादित करें, `direction:down`) एक औचित्य नोट + ट्रैकिंग इश्यू के साथ।
    - **Trivy:** `.trivyignore` में एक प्रविष्टि जोड़ें (प्रति पंक्ति CVE-ID) एक औचित्य टिप्पणी + ट्रैकिंग इश्यू के साथ। `ignore-unfixed: true` बिना पैच वाले CVEs को स्वचालित रूप से कवर करता है।

दोनों गेट **सफलतापूर्वक छोड़ देते हैं** (exit 0) जब टूल अनुपस्थित होता है या माप विफल हो जाता है (PATH में osv-scanner नहीं है, osv.dev/network पहुंच योग्य नहीं है, अमान्य JSON) — एक **माप** विफलता कभी ब्लॉक नहीं करती है, केवल एक **मापी गई** प्रतिगमन ब्लॉक करती है।

## हटाई गई निर्भरता का जोखिम

पिन किए गए promptfoo विकास टूल को अपग्रेड करने के बाद रूट lockfile में अब
`extract-zip` या उससे जुड़ने वाला कोई निर्भरता संबंध शामिल नहीं है। इससे #14482 में ट्रैक की गई, पहले स्वीकार की गई
`promptfoo` → `@openai/codex-security` → `extract-zip` शृंखला हटा दी गई है।
`tests/unit/extract-zip-14482-exposure.test.ts` में मौजूद रिग्रेशन जाँचें इसे
दोबारा जोड़े जाने से रोकती हैं और प्रोडक्शन कोड से इम्पोर्ट पर प्रतिबंध बनाए रखती हैं।

वर्तमान निर्भरता सुधार, संगतता ओवरराइड को Azure identity के
MSAL क्लाइंट, get-uri के FTP क्लाइंट और OpenCode v1 SDK की Zod निर्भरता तक भी सीमित करता है। Azure टोकन
प्राप्ति और FTP रिट्रीवल का परीक्षण नियंत्रित ट्रांसपोर्ट के साथ किया जाता है; दोनों OpenCode
पैकेज अपने स्वयं के बिल्ड और परीक्षण सुइट चलाते हैं। Registry advisory की गणनाएँ किसी
विशिष्ट समय पर किए गए मापन हैं और lockfile कमिट होने के बाद बदल सकती हैं।
