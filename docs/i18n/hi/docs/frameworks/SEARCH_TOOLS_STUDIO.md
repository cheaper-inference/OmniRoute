## टैब

### टैब खोजें

मौजूदा `SearchForm` + `ResultsPanel` + `RerankPanel` को एक टैब में विकसित करता है:

- क्वेरी → परिणाम (शीर्षक, URL, स्निपेट, प्रासंगिकता स्कोर)।
- कॉन्फ़िगरेशन फलक में प्रदाता मेटाडेटा (लागत, कोटा, स्थिति)।
- रीरैंक अनुभाग: एक रीरैंक मॉडल चुनें, परिणाम पुन: व्यवस्थित करें, `positionDelta` दिखाएं।
- जब कोई खोज प्रदाता कॉन्फ़िगर नहीं किया जाता है तो CTA के साथ खाली स्थिति।
- `SearchHistory.tsx` के माध्यम से इतिहास खोजें।
- कॉल `POST /v1/search` (मौजूदा समापन बिंदु, कोई परिवर्तन नहीं)।

### स्क्रैप टैब

`POST /v1/web/fetch` के माध्यम से URL से सामग्री निकालने के लिए नया टैब (योजना 05 में बनाया गया):

- इनपुट: URL + पूर्ण पृष्ठ टॉगल + प्रारूप चयनकर्ता (मार्कडाउन / टेक्स्ट / HTML)।
- → फ़ेच → रेंडर `ScrapeResult.tsx` सबमिट करें।
- `ScrapeResult` मार्कडाउन पूर्वावलोकन + रॉ टॉगल प्रस्तुत करता है।
- कैप: यदि प्रतिक्रिया निकाय >** 256 KB** , UI `(truncated, view raw)` दिखाता है और मोनाको मोडल (D21) में रॉ खोलता है।
- मेटाडेटा पैनल: प्रदाता (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search), विलंबता, लागत, प्रतिक्रिया आकार, लिंक गिनती।
- `useScrapeFetch.ts` हुक का उपयोग करता है।

### टैब की तुलना करें

तक समान query/URL चलाता है** समानांतर में 4 प्रदाता** (डी22):

- प्रति प्रदाता अगल-बगल कॉलम।
- मेट्रिक्स: विलंबता, लागत, परिणाम गणना, प्रतिक्रिया आकार।
- खोज के लिए URL ओवरलैप गणना (साझा URLs की संख्या बनाम प्रारंभिक परिणाम)।
- प्रति प्रदाता `POST /v1/search` (खोज) या `POST /v1/web/fetch` (स्क्रैप) को कॉल करता है।

`SearchToolsConfigPane.tsx` — हमेशा दिखाई देता है, संक्षिप्त किया जा सकता है।

| फ़ील्ड      | विवरण                                                                     |
| ----------- | ------------------------------------------------------------------------- |
| प्रोवाइडर   | स्थिति बैज वाला ड्रॉपडाउन (कॉन्फ़िगर किया गया / अनुपलब्ध / दर-सीमित)      |
| प्रकार      | `web` या `news` (केवल सर्च)                                               |
| पूरा पेज    | स्क्रैप के लिए टॉगल — पहली दृश्यमान सामग्री के बजाय पूरा पेज फ़ेच करता है |
| फ़ॉर्मेट    | `markdown`, `text`, या `html` (केवल स्क्रैप)                              |
| रीरैंक मॉडल | सर्च के बाद रीरैंकिंग के लिए वैकल्पिक मॉडल                                |
| इतिहास      | संक्षिप्त किया जा सकने वाला सर्च इतिहास सेक्शन                            |

## SearchConceptCard

`SearchConceptCard.tsx` — हमेशा दिखाई देने वाला, संक्षिप्त किया जा सकने वाला अकॉर्डियन। यह समझाता है:

| अवधारणा                   | संक्षिप्त विवरण                                                                         |
| ------------------------- | --------------------------------------------------------------------------------------- |
| **खोज**                   | वेब परिणामों की सूची प्राप्त करता है (शीर्षक, URL, स्निपेट, प्रासंगिकता स्कोर)          |
| **स्क्रैप**               | किसी URL की पूरी सामग्री निकालता है (मार्कडाउन, टेक्स्ट या HTML)                        |
| **तुलना**                 | एक ही क्वेरी को N प्रदाताओं में साथ-साथ चलाता है                                        |
| **पुनः रैंकिंग**          | क्वेरी की प्रासंगिकता सुधारने के लिए LLM के माध्यम से परिणामों को पुनः क्रमबद्ध करता है |
| **स्वचालित (सबसे सस्ता)** | सबसे सस्ता उपलब्ध प्रदाता स्वचालित रूप से चुनता है                                      |

## प्रदाता सूची

`ProviderCatalog.tsx` `GET /api/search/providers` से पूर्ण प्रदाता सूची को उजागर करता है (फ़ेच प्रदाताओं को शामिल करने के लिए F4 में विस्तारित):

| `kind` | `"search"` (24 प्रदाता) या `"fetch"` (फ़ायरक्रॉल, जिना-रीडर, टैविली-सर्च, टिनीफ़िश, फुर्तीला-सर्च, कोई भी खोज-खोज, समानांतर-खोज, कीनेबल-खोज) |

स्थिति है** अनुरोध समय पर प्राप्त किया गया** यह जाँच कर कि क्या क्रेडेंशियल मौजूद हैं और क्या सभी कुंजियाँ वर्तमान में कोल्डडाउन में हैं।

`codex-search` (Codex वेब सर्च) की अपनी कोई कुंजी नहीं है: यह कनेक्टेड Codex (ChatGPT) खाते का पुन: उपयोग करता है, इसलिए प्रत्येक खोज ChatGPT सदस्यता कोटा खर्च करती है और लगभग 10-40 सेकंड लेती है। यह तब चलता है जब कोई अनुरोध इसे नाम देता है; स्वचालित चयन के लिए `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` सुविधा ध्वज (डिफ़ॉल्ट रूप से बंद) की आवश्यकता होती है।

## बैकएंड परिवर्तन

इस सुविधा के लिए केवल एक बैकएंड परिवर्तन की आवश्यकता थी:

### विस्तारित `GET /api/search/providers`

`src/app/api/search/providers/route.ts` विस्तार इस प्रकार किया गया:

- सरणी में प्रत्येक फ़ेच प्रदाता (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`, `keenable-search`) को शामिल करें।
- प्रत्येक आइटम में `kind: "search" | "fetch"` जोड़ें।
- लाइव क्रेडेंशियल स्थिति से प्राप्त `status: "configured" | "missing" | "rate_limited"` जोड़ें।
- मौजूदा फ़ील्ड्स (`id`, `name`, आदि) को अपरिवर्तित — हुए बैकवर्ड संगतता बनाए रखें।
