## यह क्या है

OmniRoute एक **Obsidian** वॉल्ट से **संदर्भ स्रोत** के रूप में जुड़ता है — एक स्थानीय Markdown
ज्ञान आधार, जिसे एजेंट अंतर्निहित MCP सर्वर के माध्यम से पढ़ते और लिखते हैं। यह
एकीकरण डेस्कटॉप ऐप के भीतर चल रहे **Obsidian Local REST API** कम्युनिटी प्लगइन से संचार करता है,
जिससे एजेंट नोट खोज सकते हैं, फ़ाइलें पढ़/लिख/पैच कर सकते हैं, वॉल्ट की सूची देख सकते हैं, दैनिक/साप्ताहिक
आवधिक नोट्स के साथ काम कर सकते हैं, टैग प्रबंधित कर सकते हैं, Obsidian कमांड चला सकते हैं और (वैकल्पिक रूप से)
द्विदिशात्मक डेस्कटॉप↔मोबाइल वॉल्ट सिंक का समन्वय कर सकते हैं।

क्लाइंट (`src/lib/obsidian/api.ts`) Local REST API को निम्न सुविधाओं के साथ रैप करता है:

- अस्थायी `5xx` त्रुटियों के लिए **बैकऑफ़ के साथ पुनः प्रयास**, `AbortController` के माध्यम से **30-सेकंड की टाइमआउट**।
- **टाइप-आधारित त्रुटि वर्गीकरण** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`।
- एक **उपयोगकर्ता-अनुकूल "Obsidian तक नहीं पहुँचा जा सकता" संकेत**, जो पोर्ट से जुड़ी सामान्य गलती
  (HTTP के लिए `27123`, `27124` पर MCP एंडपॉइंट **नहीं**) और Tailscale प्रारूप को स्पष्ट करता है।
- वॉल्ट-सापेक्ष **पाथ एन्कोडिंग**, ताकि रिक्त स्थान/स्लैश वाले नोट पाथ सुरक्षित रहें।

## सेटअप

Obsidian टोकन या बेस URL के लिए **कोई environment variable नहीं है** — दोनों को
`src/lib/db/obsidian.ts` के माध्यम से SQLite की `key_value` टेबल (namespace `obsidian`) में
संग्रहीत किया जाता है। टोकन **संग्रहित अवस्था में एन्क्रिप्टेड** होता है (AES-256-GCM,
plaintext backward-compat fallback के साथ)। इसे Endpoint डैशबोर्ड के **Context Sources**
टैब (`ObsidianSourceCard`) से या settings REST API के माध्यम से कॉन्फ़िगर करें।

> [!IMPORTANT]
> **Obsidian Local REST API** प्लगइन इंस्टॉल और चालू होना चाहिए। इसका REST
> इंटरफ़ेस **HTTP `127.0.0.1:27123`** (डिफ़ॉल्ट बेस URL) पर सुनता है। पोर्ट `27124`
> एक _अलग_ MCP/HTTPS endpoint है और settings route द्वारा स्पष्ट रूप से अस्वीकार किया जाता है।
> यदि किसी अन्य डिवाइस से कनेक्ट कर रहे हैं, तो `http://<tailscale-ip>:27123` का उपयोग करें।

### कॉन्फ़िगरेशन कुंजियाँ (SQLite `key_value`, namespace `obsidian`)

| कुंजी             | उद्देश्य                                         | एन्क्रिप्टेड |
| ----------------- | ------------------------------------------------ | ------------ |
| `api_key`         | Local REST API bearer टोकन                       | हाँ          |
| `base_url`        | REST बेस URL (डिफ़ॉल्ट `http://127.0.0.1:27123`) | नहीं         |
| `vault_path`      | vault डायरेक्टरी का absolute path (sync के लिए)  | नहीं         |
| `webdav_username` | जनरेट किया गया WebDAV username (vault sync)      | नहीं         |
| `webdav_password` | जनरेट किया गया WebDAV password (vault sync)      | हाँ          |
| `webdav_enabled`  | WebDAV vault sync सक्षम है या नहीं               | नहीं         |

### REST के माध्यम से कॉन्फ़िगर करें

```bash
# Local REST API टोकन सहेजें + सत्यापित करें (POST एक status check के माध्यम से सत्यापन करता है)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# कनेक्शन status जाँचें (connected, hasToken, baseUrl, vaultPath लौटाता है)
curl http://localhost:20128/api/settings/obsidian

# डिस्कनेक्ट करें (संग्रहीत टोकन साफ़ करता है)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

सभी methods के लिए dashboard authentication आवश्यक है। `POST`, पोर्ट `27124` वाले किसी भी URL
को अस्वीकार करता है और संग्रहीत करने से पहले Local REST API status endpoint को कॉल करके टोकन सत्यापित करता है।

### WebDAV vault sync

`src/app/api/settings/obsidian/webdav/route.ts`, एक वैकल्पिक WebDAV-समर्थित
vault sync (`src/lib/obsidianSync.ts` द्वारा संचालित) प्रबंधित करता है। इसे सक्षम करने पर OmniRoute को एक
स्थानीय vault डायरेक्टरी की ओर इंगित किया जाता है और एक random WebDAV username/password जोड़ी बनाई जाती है:

```bash
# किसी vault डायरेक्टरी के लिए WebDAV sync सक्षम करें (username/password बनाता है)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV sync status प्राप्त करें (credentials केवल सक्षम होने पर लौटाए जाते हैं)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV sync अक्षम करें (credentials + प्रबंधित .stignore साफ़ करता है)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### सुरक्षा एवं परिवहन

WebDAV प्रमाणीकरण प्रति-आईपी विफलता ट्रैकिंग और लॉकआउट को लागू करता है (60-सेकंड विंडो के भीतर 10 असफल प्रयास `429 Too Many Requests` और `Retry-After` के साथ 5 मिनट के लॉकआउट को ट्रिगर करता है)। चूँकि WebDAV बुनियादी प्रमाणीकरण क्रेडेंशियल प्रसारित करता है, लूपबैक के बाहर WebDAV समापन बिंदु तक पहुँचने पर TLS समाप्त करना (या Tailscale या Cloudflare Tunnel जैसी सुरक्षित सुरंग पर रूट करना) की दृढ़ता से अनुशंसा की जाती है।

### प्रति-API-key context source (वैकल्पिक)

Obsidian config को `api_key_context_sources` टेबल
(`src/lib/db/apiKeyContextSources.ts`) के माध्यम से **प्रति API key** सीमित किया जा सकता है। जब कोई MCP call एक authenticated API
key id साथ लाता है, तो `getObsidianConfigForApiKey()` उस key के स्वयं के token/base-URL/vault-path
(`source: "api_key"`) को प्राथमिकता देता है और अन्यथा global config (`source: "global"`) पर fallback करता है।

Non-sync MCP tools को यह configuration पढ़ने से पहले एक resolved caller identity चाहिए।
बिना identity वाले caller को `Obsidian API token not configured` प्राप्त होता है और कोई vault
request नहीं भेजा जाता। HTTP callers को उनकी request credentials के माध्यम से resolve किया जाता है; stdio callers
को `OMNIROUTE_API_KEY` या `ROUTER_API_KEY` के माध्यम से resolve किया जा सकता है। कोई unresolved HTTP caller
server की environment identity inherit नहीं कर सकता। केवल placeholder IDs access को authorize नहीं करते;
`env-key` में resolve होने वाला एक valid environment credential अभी भी supported है।
बिना per-key Obsidian configuration वाली authenticated keys के लिए global fallback बना रहता है।
चार `obsidian_sync_*` tools अपना अलग sync-token व्यवहार बनाए रखते हैं।

## MCP उपकरण (22)

`open-sse/mcp-server/tools/obsidianTools.ts` में परिभाषित। token/base-URL प्रति कॉल हल किया जाता है (प्रति-एपीआई-कुंजी पहले, फिर वैश्विक)। उपकरण जो OmniRoute को हिट करते हैं** सिंक सर्वर** (चार `obsidian_sync_*` उपकरण) को अतिरिक्त रूप से OmniRoute सेटिंग्स में कॉन्फ़िगर किए गए सिंक ऑथ टोकन की आवश्यकता होती है।

| `obsidian_sync_status`       | OmniRoute सिंक सर्वर स्थिति: चल रहा है, वॉल्ट नाम, पोर्ट, अपटाइम, अंतिम सिंक।               |
| `obsidian_sync_conflicts`    | अनसुलझे सिंक विवादों की सूची बनाएं (पथ, संघर्ष पथ, पता लगाया गया)।                          |

| `obsidian_open_file`             | Obsidian में एक फ़ाइल खोलें (यदि यह मौजूद नहीं है तो इसे बनाएं)।                       |
| `obsidian_sync_trigger`          | एक तत्काल द्विदिश डेस्कटॉप ↔ मोबाइल वॉल्ट सिंक ट्रिगर करें।                            |
| `obsidian_sync_resolve_conflict` | सिंक विरोध का समाधान करें: `local` (मोबाइल), `remote` (डेस्कटॉप), या `keep-both` रखें। |

> [!NOTE]
> `obsidian_patch_note` लक्ष्य वैकल्पिक `createTargetIfMissing` के साथ, `heading | block | frontmatter` के `targetType` और `append | prepend | replace` के `operation` स्वीकार करते हैं। चार `obsidian_sync_*` उपकरण स्थानीय सिंक सर्वर (डिफ़ॉल्ट रूप से`http://127.0.0.1:27781` ) से बात करते हैं और सिंक टोकन की आवश्यकता होती है।

### कार्यक्षेत्र

पढ़ने के उपकरणों के लिए `read:obsidian` आवश्यकता होती है; लेखन उपकरण के लिए `write:obsidian` आवश्यकता होती है। प्रवर्तन `open-sse/mcp-server/server.ts` में `withScopeEnforcement()` द्वारा प्रबंधित Notion — के समान है, `OMNIROUTE_MCP_ENFORCE_SCOPES=true` पर गेट किया गया है और HTTP/SSE कॉल करने वालों के लिए मजबूर किया गया है जिनकी API कुंजी में `manage`/`admin` अभाव है, `OMNIROUTE_MCP_SCOPES` या API कुंजी के स्कोप संदर्भ से प्राप्त अनुमत स्कोप के साथ। [MCP-SERVER.md](./MCP-SERVER.md) देखें।

| `POST`   | `/api/settings/obsidian/webdav` | किसी वॉल्ट डायरेक्टरी के लिए WebDAV सिंक सक्षम करें।          |

> कोई सार्वजनिक `/v1` Obsidian प्रॉक्सी एंडपॉइंट नहीं है।

## उपयोग के मामले

- **वॉल्ट-आधारित उत्तर** — `obsidian_search_simple` / `obsidian_search_structured`
  और फिर `obsidian_read_note`, ताकि एजेंट आपके वास्तविक नोट्स से उत्तर दे।
- **नोट लेखन / जर्नलिंग** — एजेंट आउटपुट, सारांश या दैनिक नोट्स
  (`obsidian_get_periodic_note`) को वॉल्ट में दर्ज करने के लिए `obsidian_write_note`,
  `obsidian_append_note` या सटीक बदलाव करने वाला `obsidian_patch_note`।
- **वॉल्ट नेविगेशन** — पढ़ने/लिखने से पहले संरचना का अन्वेषण करने के लिए
  `obsidian_list_vault`, `obsidian_get_document_map` और `obsidian_get_tags`।
- **Obsidian ऑटोमेशन** — एजेंट से प्लगइन/कमांड संचालित करने के लिए
  `obsidian_list_commands` + `obsidian_execute_command`; UI में कोई नोट दिखाने के लिए
  `obsidian_open_file`।
- **मोबाइल सिंक** — WebDAV सिंक सक्षम करें, फिर डेस्कटॉप↔मोबाइल का समन्वय करने और
  टकरावों को हल करने के लिए `obsidian_sync_trigger` / `obsidian_sync_status` /
  `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict` का उपयोग करें।
