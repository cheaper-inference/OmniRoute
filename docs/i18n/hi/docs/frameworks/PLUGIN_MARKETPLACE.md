> **सत्य का स्रोत:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, और
> `src/app/(dashboard)/dashboard/plugins/`
> **अंतिम अपडेट:** 2026-06-28 — v3.8.40

OmniRoute में WordPress-शैली का प्लगइन सिस्टम शामिल है। प्लगइन स्व-निहित
डायरेक्टरियाँ हैं — प्रत्येक में एक `plugin.json` मैनिफ़ेस्ट और एक एंट्री फ़ाइल होती है — जो
अनुरोध पाइपलाइन (`onRequest` / `onResponse` / `onError`) और
लाइफ़साइकल इवेंट्स (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`) से जुड़ती हैं।

**प्लगइन मार्केटप्लेस** उस सिस्टम के ऊपर बनी डिस्कवरी लेयर है। यह
इंस्टॉल किए जा सकने वाले प्लगइन्स की ब्राउज़ करने योग्य कैटलॉग उपलब्ध कराती है। डिफ़ॉल्ट रूप से कैटलॉग एक
छोटी अंतर्निहित सीड रजिस्ट्री होती है; कोई ऑपरेटर इसे कस्टम रिमोट
रजिस्ट्री URL पर इंगित कर सकता है, ऐसी स्थिति में फ़ेच को DNS-रिज़ॉल्विंग SSRF गार्ड द्वारा
सुरक्षित बनाया जाता है ([सुरक्षा](#security) देखें)।

प्रत्येक प्लगइन रूट **केवल लूपबैक** है (Tier 1 — `LOCAL_ONLY`): प्लगइन्स चाइल्ड प्रोसेसेज़ में
कोड लोड और निष्पादित करते हैं, इसलिए प्रमाणीकरण की परवाह किए बिना ये रूट किसी भी
गैर-लूपबैक मूल से पहुँच योग्य नहीं हैं। देखें
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)।

## यह कैसे फिट बैठता है Together

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **रजिस्ट्री परत** — `src/lib/plugins/marketplace.ts`: कैटलॉग को सूचीबद्ध/खोजता है, किसी भी विफलता पर बीज रजिस्ट्री पर वापस जाता है।
- **जीवनचक्र परत** — `src/lib/plugins/manager.ts` (`pluginManager` सिंगलटन): स्थापित करें, अपग्रेड करें, सक्रिय करें, निष्क्रिय करें, अनइंस्टॉल करें, स्कैन करें, स्टार्टअप लोड करें।
- **प्रकट परत** — `src/lib/plugins/manifest.ts`: `plugin.json` के लिए Zod स्कीमा + डिफ़ॉल्ट।
- **स्कैनर** — `src/lib/plugins/scanner.ts`: प्लगइन निर्देशिका के अंतर्गत डिस्क पर प्लगइन्स खोजता है।
- **लोडर** — `src/lib/plugins/loader.ts`: प्रत्येक प्लगइन को एक अलग Node.js चाइल्ड प्रोसेस में उत्पन्न करता है और ब्रोकर IPC पर हुक कॉल करते हैं। बच्चा सैंडबॉक्स नहीं है (नीचे "प्लगइन निष्पादन अलगाव" देखें)।

## मार्केटप्लेस कैटलॉग

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`)
`MarketplaceEntry` ऑब्जेक्ट्स की एक सूची लौटाता है:

| फ़ील्ड        | प्रकार   | टिप्पणियाँ                                 |
| ------------- | -------- | ------------------------------------------ |
| `name`        | string   | kebab-case प्लगइन नाम                      |
| `version`     | string   | semver                                     |
| `description` | string   | संक्षिप्त सारांश                           |
| `author`      | string   | लेखक / संगठन                               |
| `license`     | string   | SPDX-शैली लाइसेंस आईडी                     |
| `downloadUrl` | string   | स्रोत डाउनलोड URL (रिक्त हो सकता है)       |
| `repository`  | string?  | वैकल्पिक रिपॉज़िटरी URL                    |
| `tags`        | string[] | खोज/फ़िल्टर टैग्स                          |
| `downloads`   | number   | डाउनलोड संख्या                             |
| `rating`      | number   | 0–5                                        |
| `verified`    | boolean  | क्या एंट्री सत्यापित के रूप में चिह्नित है |
| `lastUpdated` | string   | ISO-जैसी दिनांक स्ट्रिंग                   |

जब कोई कस्टम रजिस्ट्री URL कॉन्फ़िगर नहीं किया गया हो, तब कैटलॉग अंतर्निहित
`SEED_REGISTRY` होता है (वर्तमान में `request-logger`, `rate-limiter`, `cost-tracker`, और
`theme-manager`)। सीड रजिस्ट्री हमेशा उपलब्ध रहती है — यदि कॉन्फ़िगर की गई रिमोट
रजिस्ट्री पहुँच योग्य न हो, गैर-`200` स्थिति लौटाए या कोई अपरिचित
बॉडी लौटाए, तो `listMarketplacePlugins()` एक चेतावनी लॉग करता है और सीड सूची का उपयोग करता है।

> नोट: मार्केटप्लेस **कैटलॉग** (ब्राउज़/खोज) पूरी तरह से जुड़ी हुई है, लेकिन
> कैटलॉग से एक-क्लिक मार्केटप्लेस **इंस्टॉल** अभी लागू नहीं किया गया है — किसी
> मार्केटप्लेस एंट्री पर डैशबोर्ड का "इंस्टॉल करें" बटन वर्तमान में
> "जल्द आ रहा है" सूचना दिखाता है। फ़िलहाल इंस्टॉलेशन स्थानीय-पाथ इंस्टॉल
> फ़्लो (`POST /api/plugins`) और ऑन-डिस्क डिस्कवरी (`POST /api/plugins/scan`) के माध्यम से होता है।

## REST API

सभी समापन बिंदुओं को प्रबंधन प्रमाणीकरण (`requireManagementAuth`) की आवश्यकता होती है** और** केवल लूपबैक हैं — `/api/plugins` और `/api/plugins/` `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) में सूचीबद्ध हैं।

| endpoint                           | तरीका  | विवरण                                                       |
| ---------------------------------- | ------ | ----------------------------------------------------------- |
| `/api/plugins`                     | GET    | स्थापित प्लगइन्स की सूची (वैकल्पिक `?status=` फ़िल्टर)      |
| `/api/plugins`                     | POST   | प्लगइन स्रोत निर्देशिका से एक प्लगइन स्थापित करें           |
| `/api/plugins/scan`                | POST   | प्लगइन निर्देशिका को स्कैन करें और नए प्लगइन्स पंजीकृत करें |
| `/api/plugins/marketplace`         | GET    | मार्केटप्लेस कैटलॉग प्रविष्टियों की सूची बनाएं              |
| `/api/plugins/marketplace/install` | POST   | नाम से मार्केटप्लेस प्लगइन इंस्टॉल करें                     |
| `/api/plugins/[name]`              | GET    | इंस्टॉल किए गए प्लगइन विवरण प्राप्त करें                    |
| `/api/plugins/[name]`              | DELETE | एक प्लगइन अनइंस्टॉल करें                                    |
| `/api/plugins/[name]/activate`     | POST   | सक्रिय करें ( + रजिस्टर हुक लोड करें)                       |
| `/api/plugins/[name]/deactivate`   | POST   | निष्क्रिय करें (फ़ायर `onDeactivate`, अपंजीकृत हुक)         |
| `/api/plugins/[name]/config`       | GET    | प्लगइन कॉन्फिग + कॉन्फिग स्कीमा प्राप्त करें                |
| `/api/plugins/[name]/config`       | PUT    | प्लगइन कॉन्फ़िगरेशन अपडेट करें (स्कीमा के विरुद्ध मान्य)    |

`GET /api/plugins` `status` फ़िल्टर `installed` / `active` / `inactive` / `error` में से एक को स्वीकार करता है। एक अमान्य मान `400` लौटाता है।

### स्थापित प्लगइन्स की सूची बनाएं

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### स्थानीय पथ से स्थापित करें

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` एक होना चाहिए** निरपेक्ष** किसी निर्देशिका का पथ** प्लगइन स्रोत निर्देशिका के अंदर** : प्लगइन रूट के बगल में `plugin-sources`, इसलिए डिफ़ॉल्ट रूप से `~/.omniroute/plugin-sources/`, या जब वह वेरिएबल सेट होता है तो `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` ( `src/lib/plugins/installSource.ts` में`getPluginSourcesDir()` )। पहले वहां प्लगइन को कॉपी या क्लोन करें। इंस्टॉल को `400` के साथ अस्वीकार कर दिया जाता है जब पथ में `..` या एक शून्य बाइट होता है, उस निर्देशिका के बाहर होता है, एक सिम्लिंक के माध्यम से इसके बाहर हल होता है, एक सिम्लिंक होता है जिसका लक्ष्य इसके बाहर होता है, या जब निर्देशिका मौजूद नहीं होती है। स्रोत निर्देशिका में एक वैध `plugin.json` होना चाहिए (या किसी एक का मूल होना चाहिए)। सफलता पर स्थापित प्लगइन पंक्ति के साथ प्रतिक्रिया `201` है।

अन्य प्लगइन मार्गों के विपरीत, इसमें लॉगिन अक्षम होने पर भी प्रबंधन क्रेडेंशियल (डैशबोर्ड सत्र या प्रबंधन-स्कोप्ड API कुंजी) की आवश्यकता होती है (`requireLogin=false`): कोड स्थापित करना कभी भी एक गुमनाम क्रिया नहीं होती है। यही बात `POST /api/plugins/marketplace/install` (बॉडी `{ "name": "<plugin>" }`) पर भी लागू होती है।

### बाज़ार ब्राउज़ करें

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### प्लगइन कॉन्फ़िगरेशन अपडेट करें

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` प्लगइन के `configSchema` (मेनिफेस्ट में घोषित) के विरुद्ध बॉडी को `src/lib/plugins/manifest.ts` से `validatePluginConfig()` के साथ मान्य करता है: प्रत्येक कुंजी को स्कीमा में घोषित किया जाना चाहिए, मान घोषित प्रकार से मेल खाना चाहिए, `number` फ़ील्ड `min`/`max` का सम्मान करते हैं, और `select` फ़ील्ड घोषित `enum` मेल खाना चाहिए। कोई भी उल्लंघन `400` लौटाता है और कुछ भी संग्रहीत नहीं होता है। एक प्लगइन जो घोषित करता है कि कोई `configSchema` नहीं है, उसमें कोई कॉन्फ़िगर करने योग्य कुंजी नहीं है, इसलिए अनुरोध `400` के साथ अस्वीकार कर दिया गया है ("प्लगइन कोई कॉन्फ़िगर करने योग्य कुंजी घोषित नहीं करता है")।

## कॉन्फ़िगरेशन

### प्लगइन डायरेक्टरी

प्लगइन OmniRoute डेटा डायरेक्टरी के अंतर्गत रहते हैं:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (या manifest.main जिस ओर इंगित करता हो)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) उस डायरेक्टरी को
तीन चरणों में निर्धारित करता है:

1. **`OMNIROUTE_PLUGINS_DIR`**, सेट होने पर — `HOME` का मान चाहे जो हो, इसे ज्यों का त्यों उपयोग किया जाता है। यह
   Docker/K8s के लिए स्पष्ट नियंत्रण है, जहाँ प्लगइन ट्री ऐसे पथ पर बाइंड-माउंट किया जाता है
   जिसका आमतौर पर कंटेनर की होम डायरेक्टरी से कोई संबंध नहीं होता (#11827)।
2. `<home>/.omniroute/plugins`, जहाँ `<home>` को `HOME` / `USERPROFILE`
   एनवायरनमेंट वेरिएबल से लिया जाता है।
3. `/tmp/.omniroute/plugins`, जब प्रोसेस कोई होम बिल्कुल एक्सपोर्ट नहीं करती।

निर्धारित डायरेक्टरी को स्टार्टअप पर एक बार `scanner.dir_resolved` के रूप में लॉग किया जाता है, जिसमें
प्रभावी इनपुट (`OMNIROUTE_PLUGINS_DIR`, `home`, या `no-home-fallback`) का नाम होता है — ताकि कोई इमेज
जो चुपचाप चरण 3 पर पहुँच जाती है, केवल खाली प्लगइन सूची दिखाने के बजाय इसकी जानकारी भी दे।
`POST /api/plugins/scan` वहाँ की ऐसी किसी भी सबडायरेक्टरी को खोजता और पंजीकृत करता है जिसमें मान्य
`plugin.json` मौजूद हो; यही डायरेक्टरी वह रूट भी है जिसमें
`pluginManager.install()` प्लगइन कॉपी करता है, इसलिए ओवरराइड से खोज और
इंस्टॉलेशन दोनों एक साथ स्थानांतरित होते हैं।

> **`OMNIROUTE_PLUGINS_DIR`, `OMNIROUTE_PLUGIN_PATH` नहीं है।** बाद वाले को केवल
> CLI कमांड-प्लगइन लोडर (`bin/cli/plugins.mjs`), `omniroute` सबकमांड जोड़ने वाले
> `omniroute-cmd-*` npm पैकेज खोजने के लिए पढ़ता है — इसका यहाँ वर्णित रनटाइम स्कैनर
> पर कोई प्रभाव नहीं पड़ता। उस पक्ष की जानकारी के लिए [PLUGINS.md](./PLUGINS.md) देखें।

### कस्टम मार्केटप्लेस रजिस्ट्री URL

मार्केटप्लेस कैटलॉग का स्रोत `pluginMarketplaceUrl` सेटिंग से पढ़ा जाता है
(`src/lib/plugins/marketplace.ts`, `settings.pluginMarketplaceUrl` को पढ़ता है)। जब
इसे किसी `http(s)` URL पर सेट किया जाता है, तब `listMarketplacePlugins()` उस URL को फ़ेच करता है और
या तो प्रविष्टियों की शीर्ष-स्तरीय JSON सरणी या `plugins` सरणी वाला ऑब्जेक्ट स्वीकार करता है;
स्ट्रिंग `name` के बिना प्रविष्टियों को फ़िल्टर कर दिया जाता है। सेट न होने पर (या फ़ेच के
SSRF गार्ड में विफल होने / खराब प्रतिक्रिया लौटाने पर), अंतर्निहित सीड रजिस्ट्री का
उपयोग किया जाता है।

डैशबोर्ड का "Marketplace" टैब इस URL के लिए एक फ़ील्ड दिखाता है (जिसे
`GET /api/settings` से वापस पढ़ा जाता है)।

> कार्यान्वयन संबंधी नोट: डैशबोर्ड की "Save" क्रिया
> `pluginMarketplaceUrl` को `PATCH /api/settings` पर भेजती है। इसे लिखे जाने के समय यह
> कुंजी `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) में घोषित नहीं है, इसलिए इस पर निर्भर होने से पहले अपने
> रिलीज़ में इसके स्थायी रूप से सहेजे जाने की पुष्टि करें — सेटिंग्स
> स्टोर में कुंजी मौजूद होने के बाद **रीड** पथ (`getSettings()` →
> `listMarketplacePlugins()`) उसका उपयोग करता है।

## सुरक्षा

### केवल रूट टियर — लूपबैक

प्लगइन्स उत्पन्न चाइल्ड प्रक्रियाओं में कोड निष्पादित करते हैं, इसलिए संपूर्ण `/api/plugins` सतह को `LOCAL_ONLY` (टियर 1) वर्गीकृत किया जाता है। लूपबैक प्रवर्तन बिना शर्त चलता है** पहले** कोई भी प्रमाणीकरण जांच, इसलिए सुरंग के ऊपर बॉक्स तक पहुंचने वाला एक लीक प्रबंधन टोकन अभी भी प्लगइन को इंस्टॉल, सक्रिय या अनइंस्टॉल नहीं कर सकता है। [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) और कठिन नियम #15 / #17 देखें।

### बाज़ार रजिस्ट्री SSRF गार्ड

एक कस्टम रजिस्ट्री URL हमलावर-प्रभावी कॉन्फ़िगरेशन है, इसलिए इसे लाने से पहले `listMarketplacePlugins()` इसे दो परतों के माध्यम से चलाता है:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - ऐसी किसी भी चीज़ को अस्वीकार करता है जो `http:` / `https:` नहीं है।
   - शाब्दिक private/loopback/link-local/ULA होस्ट को अस्वीकार करता है (IPv4** और** IPv6, IPv4-mapped सहित) विहित `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) के माध्यम से।
   - हल** दोनों** `A` और `AAAA` यदि रिकॉर्ड करते हैं और अस्वीकार करते हैं** कोई** हल किया गया पता निजी — है जो सार्वजनिक-होस्टनाम → निजी-आईपी बाईपास को बंद कर रहा है।
   - **विफल बंद हो गया** : एक DNS रिज़ॉल्यूशन विफलता URL को अस्वीकार कर देती है।
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): फ़ेच समय पर केवल-सार्वजनिक URL गार्ड को पुनः लागू करता है** रीडायरेक्ट को ब्लॉक करता है** (कोई सार्वजनिक → निजी `30x` धुरी नहीं)।

एक URL जो किसी भी परत में विफल रहता है वह अनुरोध को निरस्त नहीं करता है — बाज़ार चुपचाप अंतर्निहित बीज रजिस्ट्री पर वापस आ जाता है और एक चेतावनी लॉग करता है।

> इस गार्ड को PR #3774 में विशेष रूप से A + AAAA हल करने और IPv4-only चेक के बजाय कैनोनिकल `isPrivateHost` उपयोग करने के लिए कठोर किया गया था।

### प्लगइन निष्पादन अलगाव

> **प्लगइन्स डिफ़ॉल्ट रूप से सैंडबॉक्स नहीं होते हैं।** चाइल्ड एक सामान्य Node.js प्रक्रिया है जो OmniRoute उपयोगकर्ता के रूप में चल रही है, जिसमें कोई VM संदर्भ नहीं है और कोई Node.js अनुमति ध्वज नहीं है, इसलिए प्लगइन कोड किसी भी फ़ाइल को पढ़ और लिख सकता है जो उपयोगकर्ता कर सकता है, प्रोग्राम चला सकता है और नेटवर्क तक पहुंच सकता है। `requires.permissions` केवल यह तय करता है कि बच्चे को कौन से पर्यावरण चर प्राप्त होंगे; अन्य अनुमतियाँ लागू नहीं हैं. ऑप्ट-इन `PLUGIN_PERMISSION_MODEL_ENABLED` सुविधा ध्वज (डिफ़ॉल्ट रूप से बंद) उन अनुमतियों से निर्मित Node.js अनुमति मॉडल के तहत प्रत्येक प्लगइन को चलाता है, `network` छोड़कर, जिसे Node.js प्रतिबंधित नहीं कर सकता ( [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#%E0%A4%85%E0%A4%A8%E0%A5%81%E0%A4%AE%E0%A4%A4%E0%A4%BF-%E0%A4%AA%E0%A5%8D%E0%A4%B0%E0%A4%A3%E0%A4%BE%E0%A4%B2%E0%A5%80) देखें)। केवल वही प्लगइन्स इंस्टॉल करें जिन पर आपको भरोसा हो। नीचे दी गई प्रक्रिया सीमा में क्रैश और हैंग शामिल हैं; यह कोई सुरक्षा सीमा नहीं है.

- **प्रक्रिया अलगाव** — `loadPlugin()` (`src/lib/plugins/loader.ts`) प्रत्येक प्लगइन को एक अलग Node.js चाइल्ड प्रक्रिया में उत्पन्न करता है और IPC पर संचार करता है। हुक कॉल में `SIGTERM` → `SIGKILL` एस्केलेशन के साथ टाइमआउट होता है।
- **पर्यावरण अनुमति सूची** — बच्चे को केवल पर्यावरण चर का एक अनुमत सूचीबद्ध सेट प्राप्त होता है; व्यापक सेट केवल तभी प्रदान किया जाता है जब मेनिफेस्ट `env` अनुमति का अनुरोध करता है।
- **स्रोत रोकथाम स्थापित करें** — `POST /api/plugins` केवल प्लगइन स्रोत निर्देशिका से पढ़ता है ("स्थानीय पथ से इंस्टॉल करें" देखें): पथ को `realpath` के साथ विहित किया गया है, उस निर्देशिका के अंदर सख्ती से रहना चाहिए, और एक सिम्लिंक ले जाने वाला स्रोत पेड़ जो इससे बच जाता है, कुछ भी कॉपी करने से पहले अस्वीकार कर दिया जाता है।
- **पथ रोकथाम** — install/upgrade/uninstall दावा करता है कि प्लगइन निर्देशिका और `manifest.main` समाधान** अंदर** किसी भी कॉपी या रिकर्सिव डिलीट से पहले प्रबंधित प्लगइन रूट ( `manifest.main` में छेड़छाड़ किए गए DB पथ और `../` ट्रैवर्सल के विरुद्ध सुरक्षा)। सक्रियण `realpath` के माध्यम से सिम्लिंक का समाधान करता है और प्लगइन निर्देशिका से निकलने वाले प्रवेश बिंदु को लोड करने से इंकार कर देता है।
- **वैकल्पिक अखंडता पिन** — एक मेनिफेस्ट एक `integrity` (`sha256-<base64>`, SRI प्रारूप) फ़ील्ड घोषित कर सकता है। मौजूद होने पर, लोडर लोड समय पर प्रविष्टि फ़ाइल हैश का सत्यापन करता है और बेमेल होने पर सक्रिय करने से इंकार कर देता है। यह ऑप्ट-इन टैम्पर-डिटेक्शन है,** नहीं** एक सुरक्षा सीमा: यह यह सीमित नहीं करती कि एक लोडेड प्लगइन क्या कर सकता है।
- **हुक में कोई ग्राहक क्रेडेंशियल नहीं** — संदर्भ `onRequest`, `onResponse` और `onError` को पारित कर दिया गया है जिसमें `authorization`, `x-api-key`, `proxy-authorization` और `cookie` हेडर हटा दिए गए हैं, और API कुंजी रिकॉर्ड में कोई महत्वपूर्ण मान नहीं है ( `src/lib/plugins/hooks.ts` में`redactPluginContext()` )।

## प्रकट (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) द्वारा मान्य:

| मैदान              | प्रकार   | टिप्पणियाँ                                                             |
| ------------------ | -------- | ---------------------------------------------------------------------- |
| `name`             | डोरी     | आवश्यक; कबाब-केस (`^[a-z0-9-]+$`), 1-100 अक्षर                         |
| `version`          | डोरी     | आवश्यक; सेम्वर (`MAJOR.MINOR.PATCH`)                                   |
| `description`      | डोरी?    | ≤ 500 वर्ण                                                             |
| `author`           | डोरी?    | ≤ 200 वर्ण                                                             |
| `license`          | डोरी?    | `MIT` पर डिफ़ॉल्ट                                                      |
| `main`             | डोरी?    | प्रवेश फ़ाइल; `index.js` के लिए डिफ़ॉल्ट                               |
| `source`           | enum?    | `local` \| `marketplace` (डिफ़ॉल्ट रूप से `local`)                     |
| `tags`             | डोरी[]?  | टैग खोजें                                                              |
| `requires`         | वस्तु?   | `{ omniroute?, permissions[] }`                                        |
| `hooks`            | वस्तु?   | बूलियन्स यह घोषणा करते हैं कि प्लगइन को कौन सा हुक लागू करता है        |
| `skills`           | वस्तु[]? | वैकल्पिक कौशल परिभाषाएँ                                                |
| `enabledByDefault` | बूलियन?  | इंस्टॉल पर स्वतः सक्रिय करें                                           |
| `configSchema`     | वस्तु?   | कॉन्फ़िगरेशन फ़ील्ड का मानचित्र (`string`/`number`/`boolean`/`select`) |
| `integrity`        | डोरी?    | वैकल्पिक `sha256-<base64>` एंट्री-फ़ाइल पिन                            |

अनुमतियाँ enum `network` / `file-read` / `file-write` / `env` / `exec` से ली गई हैं। केवल `env` में रनटाइम प्रभाव होता है (बच्चे के लिए थोड़ी बड़ी पर्यावरण-परिवर्तनीय अनुमति सूची); अन्य घोषणाएँ हैं और उन्हें लागू नहीं किया जाता है।

## जीवनचक्र प्रवाह

```
install (POST /api/plugins, पथ)
  → मैनिफ़ेस्ट को स्कैन/सत्यापित करें → स्टेजिंग में कॉपी करें → सुनिश्चित करें कि main डायरेक्टरी के भीतर है
  → परमाणु रूप से नाम बदलकर ~/.omniroute/plugins/<name> में रखें → DB पंक्ति जोड़ें
  → onInstall चलाएँ → यदि enabledByDefault हो: सक्रिय करें

activate (POST /api/plugins/{name}/activate)
  → realpath सीमांकन जाँच → loadPlugin() (चाइल्ड प्रोसेस आरंभ करें)
  → घोषित हुक पंजीकृत करें → status = "active" → onActivate चलाएँ

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate चलाएँ (अपंजीकरण से पहले) → हुक अपंजीकृत करें
  → चाइल्ड प्रोसेस समाप्त करें → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → सक्रिय होने पर निष्क्रिय करें → onUninstall चलाएँ
  → सीमांकन-जाँच के साथ प्लगइन डायरेक्टरी पुनरावर्ती रूप से हटाएँ → DB पंक्ति हटाएँ
```

किसी ऐसी डायरेक्टरी पर `install` को दोबारा चलाने पर, जिसके मैनिफ़ेस्ट का संस्करण इंस्टॉल किए गए संस्करण से **निश्चित रूप से
नया** है, स्वतः अपग्रेड हो जाता है (स्वच्छ पुनः-इंस्टॉल; कॉन्फ़िगरेशन डिफ़ॉल्ट मानों पर रीसेट
हो जाता है)। समान या पुराने संस्करण को अस्वीकार कर दिया जाता है।

(`090_plugin_metrics.sql`, `091_plugin_analytics.sql`)।

## डैशबोर्ड

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) पर डैशबोर्ड पेज दो टैब प्रदान करता है:

- **स्थापित** — स्थापित प्लगइन्स को उनके घोषित हुक, एक activate/deactivate टॉगल, एक अनइंस्टॉल बटन और एक "प्लगइन के लिए स्कैन करें" क्रिया (`POST /api/plugins/scan`) के साथ सूचीबद्ध करता है।
- **बाजार** — कस्टम रजिस्ट्री URL सेट करने के लिए फ़ील्ड के साथ `GET /api/plugins/marketplace` से कैटलॉग दिखाता है।

पृष्ठ हमेशा एक चेतावनी दिखाता है कि प्लगइन्स OmniRoute प्रक्रिया के पूर्ण विशेषाधिकारों के साथ चलते हैं।

एक प्रति-प्लगइन कॉन्फ़िगरेशन पृष्ठ `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) पर रहता है।
