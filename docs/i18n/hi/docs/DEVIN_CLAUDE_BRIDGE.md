`devin-cli-agentic` वास्तविक Claude Code रनटाइम को OmniRoute के स्थानीय Anthropic
Messages endpoint का उपयोग करने देता है, जबकि आधिकारिक Devin CLI ACP stdio पर मॉडल प्रतिक्रियाएँ
प्रदान करता है। यह मौजूदा Anthropic, Claude OAuth, Claude Web या `devin-cli` providers को
संशोधित नहीं करता।

क्लाइंट-स्वामित्व वाली tool calls के लिए, Claude-format के tool-सक्षम provider
`devin-cli-agentic` (उपनाम `dva`) के माध्यम से रूट करें। पुराना `devin-cli` (`dv`) ACP executor
केवल टेक्स्ट के लिए है: यह Devin के बिना-tools वाले summarizer को चलाता है और tool calls नहीं लौटा
सकता। इसके मॉडल metadata को उसी के अनुसार चिह्नित किया गया है, ताकि tool की आवश्यकता वाली combo
routing इससे बचे।

> **वर्तमान स्थिति: Claude Code `2.1.258` पर पिन किया गया; offline और live validation अंतिम बार
> `2.1.220` पर रिकॉर्ड किए गए।** `2.1.220` पिन ने Devin CLI `3000.2.17` और मॉडल
> `swe-1-7-lightning` के माध्यम से तीन पृथक scenarios पूरे किए; उस अंतिम live run ने क्लाइंट-स्वामित्व
> वाले `Read`, `Edit` और `Bash` turns, सफल `npm test` परिणाम, project command और skill
> discovery, केवल-Devin routing और शून्य Claude egress को प्रमाणित किया। इसके बाद पिन को बढ़ाकर
> `2.1.258` कर दिया गया (यह वह CLI generation है जिसका OmniRoute की Claude identity प्रतिरूपण करती
> है, और पहली line है जो Fable 5.1 tier को मूल रूप से उपलब्ध कराती है)। नए पिन पर install layer और
> `claude --version` को पिन की गई base image पर सत्यापित किया गया, और bridge unit suite,
> `compose config` तथा static isolation proof पास होते हैं — लेकिन offline mock scenario और live
> three-scenario suite को अभी तक दोबारा नहीं चलाया गया है। इस पिन के साथ bridge पर निर्भर होने से
> पहले उन्हें दोबारा चलाएँ (“पिन किए गए tools को अपडेट करना” देखें)।

## आर्किटेक्चर

```text
Claude Code 2.1.258 (पृथक non-root Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format, no-auth provider)
  -> devin acp --agent-type summarizer (आधिकारिक ACP stdio, कोई Devin tools नहीं)
  -> समर्पित devin-auth volume में Devin account
```

आधिकारिक CLI का default ACP agent अपने स्वयं के tools निष्पादित कर सकता है, इसलिए यह bridge उसका
उपयोग नहीं करता। यह निश्चित `summarizer` ACP agent शुरू करता है, जिसके आधिकारिक CLI mode में कोई
tools नहीं होते, और serialized Anthropic request को execution trace के रूप में frame करता है। जब
Claude-स्वामित्व वाली किसी अन्य कार्रवाई की आवश्यकता होती है, तो प्रतिक्रिया में ठीक एक client
tool envelope होना चाहिए। प्रतिक्रिया को सफल बताए जाने से पहले किसी भी ACP `tool_call` या
`tool_call_update` को अस्वीकार कर दिया जाता है।

`open-sse/executors/devin-agentic/serializer.ts` में मौजूद serializer Claude Code द्वारा दिए गए
`system`, `text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` और
tools को संरक्षित रखता है। Images और अज्ञात blocks स्पष्ट रूप से विफल होते हैं। बड़े tool results
एक दृश्यमान truncation marker का उपयोग करते हैं।

Parser प्रत्येक model turn में एक standalone `<tool>{...}</tool>` envelope स्वीकार करता है। यह
request की tool list के विरुद्ध नाम की जाँच करता है, उस tool के JSON Schema के अनुसार arguments
को validate करता है, मिश्रित narrative/actions को अस्वीकार करता है और एक सीमित repair की अनुमति
देता है। इसके बाद Claude Code परिणामी Anthropic `tool_use` को स्थानीय रूप से निष्पादित करता है और
`tool_result` को OmniRoute के माध्यम से वापस भेजता है।

## स्वतः-routing

जब provider blocked नहीं होता, तब वह OmniRoute के `auto/*` candidate pools में पात्र होता है।
Candidate eligibility चयन की गारंटी नहीं देती: combo की routing strategy (उदाहरण के लिए,
last-known-good) किसी अन्य provider को प्राथमिकता दे सकती है। जब आपको हर request को Devin के
माध्यम से भेजना आवश्यक हो, तब `dva/<model>` या Devin-first combo का उपयोग करें।

## पृथक्करण और खतरा मॉडल

होस्ट का Claude इंस्टॉलेशन, खाता और कॉन्फ़िगरेशन कार्यक्षेत्र से बाहर हैं और उन्हें
निषिद्ध माना जाता है। Compose सेवाएँ:

- UID/GID `10001:10001` के रूप में, केवल-पढ़ने योग्य रूट फ़ाइल सिस्टम, हटाई गई क्षमताओं और
  `no-new-privileges` के साथ चलती हैं;
- निजी `/home/bridge`, एक समर्पित Claude कॉन्फ़िगरेशन वॉल्यूम, पृथक OmniRoute डेटा
  और एक अलग `devin-auth` वॉल्यूम का उपयोग करती हैं;
- केवल अस्थायी `.sandbox` कार्यस्थानों/साक्ष्यों को माउंट करती हैं;
- होस्ट होम, Keychain, SSH, क्लाउड क्रेडेंशियल या Docker सॉकेट को माउंट नहीं करती हैं;
- स्पष्ट एनवायरनमेंट बनाती हैं और Anthropic API/OAuth/रूटिंग वेरिएबल हटाती हैं;
- Claude Code इन्फ़रेंस को केवल स्थानीय कुंजी के साथ `http://omniroute:20128` की ओर निर्देशित करती हैं।

ऑफ़लाइन प्रोफ़ाइल एक आंतरिक नेटवर्क का उपयोग करती है। लाइव प्रोफ़ाइल में, OmniRoute केवल
`network-guard` के माध्यम से आधिकारिक Devin एंडपॉइंट तक पहुँचता है; असंबंधित गंतव्यों को अस्वीकार किया जाता है।
Claude Code के पास एक अलग, सभी आउटबाउंड ट्रैफ़िक अस्वीकार करने वाला गार्ड है और वह `NO_PROXY` के माध्यम से केवल स्थानीय OmniRoute
सेवा तक पहुँच सकता है। गार्ड ऑडिट फ़ाइलें केवल उनकी गार्ड प्रक्रिया द्वारा माउंट की जाती हैं। स्क्रिप्ट
टोकन-मुक्त साक्ष्य एक्सपोर्ट करने से पहले फ़ाइल स्वामित्व, मोड, लिंक संख्या और प्रत्येक निर्णय को सत्यापित करती हैं।

पृथक्करण प्रमाण को स्वतंत्र रूप से चलाएँ:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

यह टोपोलॉजी, नामित माउंट, गैर-रूट/केवल-पढ़ने योग्य सेटिंग्स, स्पष्ट स्थानीय रूटिंग,
संवेदनशील एनवायरनमेंट वेरिएबल की अनुपस्थिति, Docker सॉकेट की अनुपस्थिति, `api.anthropic.com`
और `claude.ai` तक अवरुद्ध पहुँच, केवल-Devin प्रदाता चयन, तथा ACP बैकएंड अनुपलब्ध होने पर
स्पष्ट विफलता को सत्यापित करता है।

## पहली बार सेटअप और सामान्य उपयोग

पिन की गई इमेज बनाएँ:

```bash
./scripts/devin-bridge/build
```

केवल पृथक Devin वॉल्यूम को प्रमाणित करें:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

लॉगिन कमांड रिमोट/कंटेनर एनवायरनमेंट के लिए बनाई गई आधिकारिक मैन्युअल-टोकन प्रक्रिया का
उपयोग करता है। मान सीधे CLI प्रॉम्प्ट में दर्ज किया जाता है; इसे प्रोसेस आर्ग्युमेंट के रूप में
पास नहीं किया जाता, Git में नहीं लिखा जाता और न ही होस्ट से कॉपी किया जाता है।

पृथक Claude Code रनटाइम शुरू करें:

```bash
./scripts/devin-bridge/launch
```

`launch`, कंटेनरीकृत Claude Code शुरू करने से पहले पृथक्करण, Devin प्रमाणीकरण और मॉडल डिस्कवरी की
दोबारा जाँच करता है। यह होस्ट के Claude एक्ज़ीक्यूटेबल को कभी नहीं चलाता। मॉडल उपनाम
`.env.devin-bridge` में सेट किए जा सकते हैं; प्रत्येक कॉन्फ़िगर किए गए मान में
`devin-cli-agentic/` प्रीफ़िक्स बना रहना चाहिए।

## सत्यापन कमांड

पुनरुत्पाद्य ऑफ़लाइन पथ के लिए Devin खाते की आवश्यकता नहीं होती और रनटाइम के दौरान इंटरनेट उपलब्ध नहीं होता:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

प्रमाणित, वैकल्पिक रूप से सक्षम किया जाने वाला लाइव पथ है:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

लाइव रनर ACP सत्रों को एक साथ तेज़ी से खोलने से बचने के लिए परिदृश्यों के बीच प्रतीक्षा करता है और
पाठ्य दावों पर भरोसा करने के बजाय संरचित Claude स्ट्रीम इवेंट को सत्यापित करता है। इसके तीन
परिदृश्य निम्नलिखित को प्रमाणित करते हैं:

1. प्रोजेक्ट को सीधे पढ़ना और दोष विश्लेषण;
2. एक वास्तविक `Edit`, क्लाइंट-स्वामित्व वाला `Bash` `npm test` और एक अंतिम परिणाम;
3. `/bridge-check` के साथ `bridge-proof` डिस्कवरी, प्रोजेक्ट को पढ़ना, एक और सफल
   क्लाइंट-स्वामित्व वाला `npm test` और कोई लंबित कार्य छोड़े बिना पूर्णता।

अंतिम गेट Devin नेटवर्क ऑडिट की भी जाँच करता है और यह आवश्यक बनाता है कि Claude आउटबाउंड
ऑडिट खाली रहे।

## पिन किए गए टूल अपडेट करना

इमेज में Node, Claude Code और Devin CLI को
`docker/devin-bridge/Dockerfile` में पिन किया गया है। अपडेट करने के लिए:

1. स्पष्ट रूप से निर्दिष्ट वर्ज़न बदलें;
2. दोनों आर्किटेक्चर-विशिष्ट Devin आर्काइव चेकसम को आधिकारिक
   आर्टिफ़ैक्ट के मानों से बदलें;
3. दोबारा बिल्ड करें और प्रत्येक ऑफ़लाइन सत्यापन कमांड चलाएँ;
4. इमेज के भीतर वर्ज़न की पुष्टि करें;
5. प्रमाणीकृत तीन-परिदृश्य वाली लाइव सुइट को दोबारा चलाएँ।

किसी भी CLI को होस्ट पर ग्लोबल रूप से इंस्टॉल न करें और चेकसम सत्यापन को किसी
असत्यापित डाउनलोड से न बदलें।

## निदान और क्लीनअप

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  स्थानीय रूटिंग और सैनिटाइज़ की गई एक्ज़ीक्यूटर त्रुटियाँ दिखाता है।
- `.sandbox/evidence/mock-acp.jsonl` नियतात्मक मॉक ACP कार्रवाइयाँ रिकॉर्ड करती है।
- `.sandbox/evidence/claude-stream.jsonl` वास्तविक Claude Code ऑफ़लाइन रन रिकॉर्ड करती है।
- `.sandbox/evidence/live-*.jsonl` तीन सत्यापित लाइव स्ट्रीम रिकॉर्ड करती हैं।
- `.sandbox/evidence/egress.jsonl` और `.sandbox/evidence/claude-egress.jsonl` गार्ड ऑडिट की
  सत्यापित, टोकन-मुक्त प्रतियाँ हैं।

```bash
./scripts/devin-bridge/clean
```

नामित वॉल्यूम सहित, ब्रिज के स्वामित्व वाले पूरे एनवायरनमेंट को हटाएँ:

```bash
./scripts/devin-bridge/clean --all
```

## सीमाएँ

- ब्रिज निश्चित, बिना-टूल वाली `summarizer` भूमिका पर निर्भर करता है क्योंकि Devin CLI `3000.2.17`
  कोई न्यूट्रल, बिना-टूल वाला ACP एजेंट उपलब्ध नहीं कराता। अडैप्टर सारांश-जैसे
  मध्यवर्ती उत्तरों की भरपाई करता है, लेकिन एक सीमाबद्ध सुधार फिर भी स्पष्ट रूप से विफल हो सकता है।
- लाइव ACP कॉल क्षणिक `502`/`504` उत्तर दे सकती हैं। हार्नेस परिदृश्यों के बीच अंतराल रखता है;
  लगातार विफलता की स्थिति में यह फ़ेल-क्लोज़्ड रहता है और कभी भी दूसरा प्रोवाइडर नहीं चुनता।
- ACP कॉन्टेक्स्ट प्रत्येक Anthropic अनुरोध से फिर से बनाया जाता है; कोई प्रोसेस/सेशन
  एफ़िनिटी नहीं है।
- प्रत्येक मॉडल उत्तर में एक टूल कॉल समर्थित है; समानांतर कॉल अस्वीकार की जाती हैं।
- इमेज स्पष्ट रूप से असमर्थित हैं। विज़न, थिंकिंग आउटपुट, एफ़र्ट कंट्रोल और 1M
  कॉन्टेक्स्ट विंडो का विज्ञापन नहीं किया जाता।
- SSE मान्य Anthropic लाइफ़साइकल इवेंट का उपयोग करता है, लेकिन सीमाबद्ध ACP टर्न
  एकत्र होने के बाद उत्सर्जित होता है; ACP चंक क्रमशः फ़ॉरवर्ड नहीं किए जाते।
