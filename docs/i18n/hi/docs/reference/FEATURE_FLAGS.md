रनटाइम टॉगल जो **बिना रीडिप्लॉय किए** OmniRoute के व्यवहार को बदलते हैं।
यहां सूचीबद्ध प्रत्येक फ़्लैग [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts) में परिभाषित है — जो सत्य का एकमात्र स्रोत है। डैशबोर्ड और REST API दोनों उस फ़ाइल से पढ़ते हैं, इसलिए नीचे दी गई तालिका इसे 1:1 से मेल खाने के लिए उत्पन्न की गई है।

---

## फ़ीचर फ़्लैग क्या हैं

एक फ़ीचर फ़्लैग एक नामित टॉगल (बूलियन या एनम) है जिसका मान रनटाइम पर बदला जा सकता है और डेटाबेस में स्थायी किया जा सकता है, जिसके लिए किसी प्रक्रिया रीडिप्लॉय की आवश्यकता नहीं होती है। प्रत्येक फ़्लैग को एक `FeatureFlagDefinition` द्वारा वर्णित किया जाता है जिसमें एक `key`, `label`, `description`, `category`, `defaultValue`, `type`, और एक `requiresRestart` संकेत होता है।

### रिज़ॉल्यूशन क्रम

एक फ़्लैग का **प्रभावी मान** [`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) द्वारा इस वरीयता (उच्चतम जीतता है) के साथ हल किया जाता है:

1.  **DB ओवरराइड** — `feature_flags` नेमस्पेस के तहत `key_value` तालिका में संग्रहीत एक मान (डैशबोर्ड या REST API के माध्यम से सेट किया गया)।
2.  **पर्यावरण चर** — `process.env[<KEY>]`, यदि सेट और गैर-खाली है।
3.  **परिभाषा डिफ़ॉल्ट** — `featureFlagDefinitions.ts` से `defaultValue`।

एक बूलियन फ़्लैग को **सक्षम** माना जाता है जब उसका प्रभावी मान `"true"`, `"1"`, या `"yes"` होता है (देखें `isFeatureFlagEnabled()`)।

> [!NOTE]
> अधिकांश फ़्लैग में [`ENVIRONMENT.md`](./ENVIRONMENT.md) में प्रलेखित **समान नाम** का एक मिलान पर्यावरण चर भी होता है। फ़्लैग का DB ओवरराइड उस पर्यावरण चर पर वरीयता लेता है। `requiresRestart: true` वाले फ़्लैग को तुरंत स्थायी किया जाता है लेकिन प्रक्रिया शुरू होने पर ही फिर से पढ़ा जाता है — इसे टॉगल करने पर डैशबोर्ड में एक **"सर्वर पुनरारंभ करें"** बैनर दिखाई देता है।

> `INPUT_SANITIZER_BLOCK_THRESHOLD` और इसका लीगेसी उपनाम
> `INJECTION_GUARD_BLOCK_THRESHOLD`, `INJECTION_GUARD_MODE` के `block` मोड को
> समायोजित करते हैं, लेकिन ये साधारण एनवायरनमेंट वेरिएबल हैं जिन्हें
> [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts)
> पढ़ता है, फ़ीचर फ़्लैग नहीं: इनके लिए कोई DB ओवरराइड या डैशबोर्ड टॉगल नहीं है। देखें
> [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication)।

> [!NOTE]
> `Restart` कॉलम `requiresRestart: true` वाले फ़्लैग को चिह्नित करता है — मान
> तुरंत स्थायी रूप से सहेज दिया जाता है, लेकिन प्रक्रिया के पुनः लोड होने के बाद ही प्रभावी होता है। Enum
> फ़्लैग अपने अनुमत सेट से बाहर के किसी भी मान को अस्वीकार करते हैं (सर्वर-साइड पर
> `setFeatureFlagOverride()` और REST `PUT` हैंडलर, दोनों में सत्यापित)।

## फ़्लैग टॉगल करना

### डैशबोर्ड

**Dashboard → Settings → Feature Flags** पर जाएँ
(`/dashboard/settings/feature-flags`)। ग्रिड
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
इन सुविधाओं का समर्थन करता है:

- कुंजी या विवरण के आधार पर **खोज**, और श्रेणी के आधार पर **फ़िल्टर** (साथ ही एक कृत्रिम
  **Requires Restart** दृश्य)।
- बूलियन फ़्लैग के लिए एक **टॉगल** और enum फ़्लैग के लिए एक **ड्रॉपडाउन**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)।
- प्रत्येक फ़्लैग के लिए एक **स्रोत बैज** — `DB`, `ENV`, या `DEF` — जो दिखाता है कि
  प्रभावी मान कहाँ से आया है।
- ओवरराइड हटाने के लिए एक **Reset** बटन (केवल `DB`-स्रोत वाले फ़्लैग के लिए प्रदर्शित),
  और नीचे एक **Reset All Overrides** बटन।
- किसी `requiresRestart` फ़्लैग को बदलने पर एक **Restart Server** बैनर।

### REST API

सभी ऑपरेशन एक ही रूट से होकर जाते हैं:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)।
प्रत्येक मेथड के लिए प्रमाणीकृत डैशबोर्ड सत्र आवश्यक है (अन्यथा `401`)।

#### `GET /api/settings/feature-flags`

प्रत्येक फ़्लैग को उसके प्रभावी मान, स्रोत और सारांश सहित लौटाता है।

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... सभी 111 फ़्लैग
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

एक ओवरराइड सेट करें या हटाएँ। बॉडी: `{ key: string; value?: string }`।
`value` को छोड़ देने पर ओवरराइड हट जाता है (env / डिफ़ॉल्ट पुनर्स्थापित होता है)।

```bash
# DB ओवरराइड सेट करें
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ओवरराइड हटाएँ ("value" के बिना)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

प्रतिक्रिया नया `effectiveValue`/`source`, `previousValue`/
`previousSource`, और `requiresRestart` वापस लौटाती है। अज्ञात कुंजियाँ और सीमा से बाहर के enum
मान `400` के साथ अस्वीकार कर दिए जाते हैं।

#### `DELETE /api/settings/feature-flags`

सभी DB ओवरराइड एक साथ साफ़ करता है, जिससे प्रत्येक फ़्लैग अपने env / डिफ़ॉल्ट
मान पर पुनर्स्थापित हो जाता है। `{ cleared: <count>, message: "..." }` लौटाता है।

> [!NOTE]
> `requiresRestart: true` वाले फ़्लैग केवल प्रक्रिया को पुनः लोड करने के बाद प्रभावी होते हैं।
> डैशबोर्ड का रीस्टार्ट प्रवाह `POST /api/restart` को कॉल करता है और फिर सर्वर के दोबारा चालू होने तक
> `GET /api/health/ping` को पोल करता है।

## आपातकालीन बजट फ़ॉलबैक

`OMNIROUTE_EMERGENCY_FALLBACK` (श्रेणी `runtime`, डिफ़ॉल्ट `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
में आपातकालीन मुफ़्त-फ़ॉलबैक पथ को नियंत्रित करता है। सक्षम होने पर, जिन अनुरोधों का बजट समाप्त हो जाता है, उन्हें पूरी तरह विफल करने के बजाय किसी मुफ़्त फ़ॉलबैक प्रदाता/मॉडल पर रूट किया जाता है। इस व्यवहार को अक्षम करने और बजट समाप्त हो चुके अनुरोधों को विफल होने देने के लिए इसे `false` (या `0`) पर सेट करें—डैशबोर्ड टॉगल, DB ओवरराइड या `OMNIROUTE_EMERGENCY_FALLBACK` एनवायरनमेंट वेरिएबल के माध्यम से। (PRs #3741 / #3752 में इसे डैशबोर्ड टॉगल के रूप में उपलब्ध कराया गया है।)

इस फ़ॉलबैक द्वारा प्रदान की गई प्रतिक्रिया में
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` होता है, ताकि क्लाइंट अपने अनुरोध से `X-OmniRoute-Provider` की तुलना किए बिना यह पता लगा सके कि उसे फिर से रूट किया गया था। अन्य सभी प्रतिक्रियाओं में यह हेडर अनुपस्थित होता है।
