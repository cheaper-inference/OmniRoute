## प्रदाता क्या है?

प्रदाता को एक **फ़ोन सेवा प्रदाता** की तरह समझें। जैसे कॉल करने के लिए आपको फ़ोन सेवा प्रदाता की आवश्यकता होती है, वैसे ही AI मॉडल का उपयोग करने के लिए आपको AI प्रदाता की आवश्यकता होती है। OmniRoute एक ऐसे फ़ोन की तरह है जो **सभी सेवा प्रदाताओं** के साथ काम करता है — आप उनके बीच स्वचालित रूप से स्विच कर सकते हैं।

### प्रदाताओं के प्रकार

| प्रकार         | यह क्या है                          | उदाहरण                          | लागत                            |
| -------------- | ----------------------------------- | ------------------------------- | ------------------------------- |
| **निःशुल्क**   | किसी भुगतान की आवश्यकता नहीं है     | Kiro, Pollinations              | $0                              |
| **API Key**    | आपको API key की आवश्यकता होती है    | OpenAI, Anthropic, Google       | उपयोग के अनुसार भुगतान          |
| **OAuth**      | अपने खाते से लॉग इन करें            | Claude Code, GitHub Copilot     | सदस्यता                         |
| **Web Cookie** | आपके ब्राउज़र सत्र का उपयोग करता है | ChatGPT Web (Codex), Gemini Web | $0 (आपके खाते का उपयोग करता है) |

### Web Cookie प्रदाता

सामान्य सेटअप निर्देशों, सीमाओं, समस्या निवारण और प्रदाता-विशिष्ट प्रमाणीकरण मार्गदर्शन के लिए **[WEB-COOKIE-GUIDE.md](./WEB-COOKIE-GUIDE.md)** देखें।

## त्वरित शुरुआत: अपने पहले प्रदाता को कनेक्ट करें

### वैकल्पिक प्रथम-रन मुफ़्त-प्रदाता सेटअप

प्रथम-रन विज़ार्ड एक स्पष्ट **मुफ़्त प्रदाता सेट अप करें** कार्ड प्रदान करता है। यह OmniRoute की प्रमाणीकरण-रहित प्रदाता रजिस्ट्री से वर्तमान
पात्र सूची प्राप्त करता है, फिर पुष्टि करने से पहले आपको प्रत्येक
प्रदाता की समीक्षा करने और उसका चयन हटाने देता है। OmniRoute प्रदाता की सावधानी सूचना और उसकी साइट का लिंक दिखाता है,
ताकि आप पहले तृतीय-पक्ष की शर्तों, गोपनीयता, उपलब्धता और दर सीमाओं की समीक्षा कर सकें।

यह कार्रवाई वैकल्पिक है: विज़ार्ड पूरा करने पर मुफ़्त-प्रदाता कनेक्शन कभी भी चुपचाप नहीं बनाए जाते।
यह केवल उन प्रदाताओं को बनाता है जो अभी भी अनुपस्थित हैं, मौजूदा अनुकूलित कनेक्शन को
अपरिवर्तित छोड़ता है, और बनाए गए, पहले से कॉन्फ़िगर किए गए तथा विफल प्रदाताओं की अलग-अलग रिपोर्ट देता है। आंशिक परिणाम के बाद
आप केवल विफल प्रदाताओं के लिए सुरक्षित रूप से पुनः प्रयास कर सकते हैं।

### विकल्प A: मुफ़्त प्रदाता (क्रेडिट कार्ड की आवश्यकता नहीं)

1. `http://localhost:20128` पर डैशबोर्ड खोलें
2. **प्रदाता** → **प्रदाता जोड़ें** पर जाएँ
3. इनमें से कोई एक मुफ़्त प्रदाता चुनें:
   - **Kiro AI** — मुफ़्त Claude मॉडल (प्रमाणीकरण की आवश्यकता नहीं)
   - **Pollinations** — मुफ़्त GPT-5, Claude, Gemini (कुंजी की आवश्यकता नहीं)
   - **LongCat** — 10M टोकन मुफ़्त (एकमुश्त अनुदान, खाता + KYC आवश्यक)
   - **Cloudflare AI** — 50+ मॉडल, 10K न्यूरॉन/दिन
   - **MLX Gemma 26B** — स्थानीय Apple Silicon मॉडल (~38.5 टोकन/सेकंड, ~15.9GB RAM)
   - **MLX Qwen 3.8 27B** — स्थानीय Apple Silicon मॉडल (~9.1 टोकन/सेकंड, ~13.1GB RAM)
4. **कनेक्ट करें** पर क्लिक करें
5. हो गया! अब आपके पास मुफ़्त AI पहुँच है।

### विकल्प B: API कुंजी प्रदाता (सशुल्क)

1. प्रदाता की वेबसाइट से API कुंजी प्राप्त करें:
   - **OpenAI**: https://platform.openai.com/api-keys
   - **Anthropic**: https://console.anthropic.com/
   - **Google**: https://aistudio.google.com/apikey
   - **DeepSeek**: https://platform.deepseek.com/
   - **Groq**: https://console.groq.com/
2. `http://localhost:20128` पर डैशबोर्ड खोलें
3. **प्रदाता** → **प्रदाता जोड़ें** पर जाएँ
4. अपना प्रदाता चुनें
5. अपनी API कुंजी पेस्ट करें
6. **कनेक्ट करें** पर क्लिक करें
7. हो गया! अब आपके पास उस प्रदाता के मॉडल की पहुँच है।

### विकल्प C: OAuth प्रदाता (सदस्यता)

1. `http://localhost:20128` पर डैशबोर्ड खोलें
2. **प्रदाता** → **प्रदाता जोड़ें** पर जाएँ
3. अपना प्रदाता चुनें (जैसे, Claude Code, GitHub Copilot)
4. **OAuth से कनेक्ट करें** पर क्लिक करें
5. अपने खाते से लॉग इन करें
6. हो गया! अब आपके पास अपनी सदस्यता के मॉडल की पहुँच है।

### विकल्प D: स्थानीय MLX मॉडल (Apple Silicon)

यूनिफ़ाइड मेमोरी वाले Apple Silicon Mac के लिए, OmniRoute नियमित OpenAI-संगत स्थानीय प्रदाताओं के रूप में `mlx-lm.server` के माध्यम से चल रहे स्थानीय MLX मॉडल से कनेक्ट होने का समर्थन करता है।

#### पूर्वापेक्षाएँ

- **Apple Silicon Mac** (M1/M2/M3/M4), 24GB+ यूनिफ़ाइड मेमोरी अनुशंसित
- **uv** पैकेज मैनेजर: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- **mlx-lm**: `uv pip install mlx-lm`

#### त्वरित शुरुआत

1. **निर्भरताएँ इंस्टॉल करें**:

   ```bash
   # यदि uv पहले से इंस्टॉल नहीं है, तो उसे इंस्टॉल करें
   curl -LsSf https://astral.sh/uv/install.sh | sh

   # mlx-lm इंस्टॉल करें
   uv pip install mlx-lm
   ```

2. **MLX सर्वर मैन्युअल रूप से शुरू करें** (अलग-अलग टर्मिनल में):

   ```bash
   # टर्मिनल 1: Gemma 4 26B A4B IT-QAT (पोर्ट 11435)
   uv run mlx_lm.server --model mlx-community/gemma-4-26B-A4B-it-qat-q4_0-mlx-aligned --port 11435 --host 127.0.0.1

   # टर्मिनल 2: Qwen 3.8 27B MLX Mixed (पोर्ट 11436)
   uv run mlx_lm.server --model maglun/Qwen3.8-27B-MLX-Mixed-3.80bpw --port 11436 --host 127.0.0.1
   ```

3. **OmniRoute डैशबोर्ड में कनेक्ट करें**:
   - **प्रदाता** → **प्रदाता जोड़ें** पर जाएँ
   - **MLX Gemma 26B** या **MLX Qwen 3.8 27B** चुनें
   - **कनेक्ट करें** पर क्लिक करें (API कुंजी की आवश्यकता नहीं)

4. **OpenCode के साथ उपयोग करें**:
   ```bash
   # OmniRoute का उपयोग करने के लिए OpenCode को कॉन्फ़िगर करें
   opencode config set api.base_url http://localhost:20128/v1
   opencode config set api.key <your-omniroute-api-key>

   # MLX मॉडल का उपयोग करें
   opencode run --model mlx-gemma/gemma-4-26b
   opencode run --model mlx-qwen/qwen3.8-27b
   ```

#### मेमोरी प्रबंधन

**महत्वपूर्ण**: 24GB यूनिफ़ाइड मेमोरी के साथ, एक समय में केवल **एक बड़ा MLX मॉडल चल सकता है**।

- Gemma 26B: ~15.9GB अधिकतम मेमोरी
- Qwen 3.8 27B: ~13.1GB अधिकतम मेमोरी

आपको इसे मैन्युअल रूप से प्रबंधित करना होगा:

- एक समय में केवल एक MLX सर्वर चलाएँ, या
- दोनों को अलग-अलग मशीनों पर चलाएँ, या
- दूसरे को शुरू करने से पहले पहले वाले को रोकें

OmniRoute स्वचालित रूप से MLX सर्वर प्रक्रियाओं को प्रबंधित नहीं करता — यह केवल अनुरोधों को आपके द्वारा कॉन्फ़िगर किए गए OpenAI-संगत एंडपॉइंट पर रूट करता है।

#### टूल कॉलिंग समर्थन

दोनों मॉडल OpenAI-संगत टूल कॉलिंग का समर्थन करते हैं। इसके साथ परीक्षण करें:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mlx-gemma/gemma-4-26b",
    "messages": [{"role": "user", "content": "What is 2+2? Use the calculator tool."}],
    "tools": [{"type": "function", "function": {"name": "calculator", "description": "Calculate", "parameters": {"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]}}}]
  }'
```

#### समस्या निवारण

| समस्या               | समाधान                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------ |
| सर्वर शुरू नहीं होता | `uv run mlx_lm.server --help` जाँचें और मॉडल ID सत्यापित करें                              |
| मेमोरी समाप्त हो गई  | सुनिश्चित करें कि केवल एक मॉडल चल रहा है; अन्य ऐप बंद करें; Activity Monitor जाँचें        |
| कनेक्शन अस्वीकृत     | सत्यापित करें कि सर्वर सही पोर्ट (11435/11436) पर चल रहा है                                |
| धीमी प्रतिक्रियाएँ   | पहला अनुरोध मॉडल को मेमोरी में लोड करता है (~30-60 सेकंड); बाद के अनुरोध तेज़ होते हैं     |
| टूल कॉलिंग विफल      | सुनिश्चित करें कि मॉडल टूल का समर्थन करता है; अनुवाद त्रुटियों के लिए OmniRoute लॉग जाँचें |

## प्रदाता को कनेक्ट करने का तरीका (चरण-दर-चरण)

### चरण 1: डैशबोर्ड खोलें

अपने ब्राउज़र में `http://localhost:20128` पर जाएँ।

### चरण 2: प्रदाताओं पर जाएँ

साइडबार में **Providers** पर क्लिक करें।

### चरण 3: प्रदाता जोड़ें पर क्लिक करें

**+ Add Provider** बटन पर क्लिक करें।

### चरण 4: अपना प्रदाता चुनें

सूची ब्राउज़ करें या अपने प्रदाता को खोजें। उस पर क्लिक करें।

### चरण 5: क्रेडेंशियल दर्ज करें

- **मुफ़्त प्रदाता**: किसी क्रेडेंशियल की आवश्यकता नहीं — बस **Connect** पर क्लिक करें
- **API कुंजी प्रदाता**: अपनी API कुंजी पेस्ट करें
- **OAuth प्रदाता**: **Connect with OAuth** पर क्लिक करें और लॉग इन करें

### चरण 6: कनेक्शन का परीक्षण करें

यह सत्यापित करने के लिए कि कनेक्शन काम करता है, **Test Connection** पर क्लिक करें।

### चरण 7: हो गया!

आपका प्रदाता अब कनेक्ट हो गया है। आप इसे `model: "auto"` के साथ उपयोग कर सकते हैं या सीधे प्रदाता निर्दिष्ट कर सकते हैं।

## एकाधिक प्रदाताओं का उपयोग

OmniRoute **एकाधिक प्रदाताओं** के साथ सबसे अच्छा काम करता है। इससे आपको मिलते हैं:

- **स्वचालित फ़ॉलबैक** — यदि एक प्रदाता विफल हो जाता है, तो OmniRoute अगले को आज़माता है
- **लागत अनुकूलन** — OmniRoute प्रत्येक अनुरोध के लिए सबसे किफ़ायती प्रदाता चुनता है
- **गति अनुकूलन** — OmniRoute प्रत्येक अनुरोध के लिए सबसे तेज़ प्रदाता चुनता है
- **गुणवत्ता अनुकूलन** — OmniRoute प्रत्येक कार्य के लिए सबसे अच्छा प्रदाता चुनता है

### अनुशंसित सेटअप

सर्वोत्तम अनुभव के लिए कम से कम **3 प्रदाताओं** को कनेक्ट करें:

1. **एक निःशुल्क प्रदाता** (Kiro या Pollinations) — हमेशा उपलब्ध
2. **एक तेज़ प्रदाता** (Groq, Cerebras) — त्वरित प्रतिक्रियाओं के लिए
3. **एक उच्च-गुणवत्ता वाला प्रदाता** (OpenAI, Anthropic, Google) — जटिल कार्यों के लिए

इसके बाद `model: "auto"` का उपयोग करें और OmniRoute प्रत्येक अनुरोध के लिए स्वचालित रूप से सबसे उपयुक्त प्रदाता चुन लेगा।

### Qoder: क्रेडेंशियल ट्रांसपोर्ट चुनें

Qoder को क्रेडेंशियल की आवश्यकता होती है। इसके दोनों ट्रांसपोर्ट की क्षमताएँ अलग-अलग हैं; केवल मॉडल का नाम यह नहीं बताता कि कोई विशिष्ट कनेक्शन क्या कर सकता है।

| क्रेडेंशियल                      | OmniRoute ट्रांसपोर्ट                           | कॉलर टूल कॉलिंग                                | स्ट्रीमिंग                                                           |
| -------------------------------- | ----------------------------------------------- | ---------------------------------------------- | -------------------------------------------------------------------- |
| `pt-` से शुरू होने वाला PAT      | OmniRoute होस्ट पर स्थानीय `qodercli` प्रक्रिया | समर्थित नहीं                                   | बफ़र्ड: CLI द्वारा पूरा उत्तर लौटाने के बाद ही SSE उत्सर्जित होता है |
| गैर-PAT एक्सेस टोकन या API कुंजी | DashScope का OpenAI-संगत HTTP एंडपॉइंट          | अपस्ट्रीम मॉडल/कुंजी के अधीन, आगे भेजा जाता है | अपस्ट्रीम HTTP/SSE पथ                                                |

PAT के लिए, Qoder CLI को OmniRoute वाले उसी होस्ट या कंटेनर पर इंस्टॉल करें। एक्ज़ीक्यूटेबल `qodercli` के रूप में खोजने योग्य होना चाहिए, या `CLI_QODER_BIN` को उसके एक्ज़ीक्यूटेबल पथ पर सेट करें। केवल Docker होस्ट पर इंस्टॉल किया गया CLI कंटेनर में स्वचालित रूप से उपलब्ध नहीं होता। बाइनरी अनुपलब्ध होने पर एक स्पष्ट त्रुटि दिखाई जाती है, जो आपको इंस्टॉलेशन या पथ सेटिंग की ओर निर्देशित करती है।

PAT चैट पथ की प्रक्रिया टाइमआउट अवधि 45 सेकंड है। यह वार्तालाप को एक प्रॉम्प्ट में समतल करता है और CLI को गैर-स्ट्रीमिंग प्रिंट मोड में आमंत्रित करता है। `stream: true` का अनुरोध करने से प्रतिक्रिया एनवेलप SSE में बदल जाता है; यह अपस्ट्रीम टोकनों की क्रमिक डिलीवरी प्रदान नहीं करता। CLI सत्यापन/मॉडल सूचीकरण के लिए अलग से 20 सेकंड की टाइमआउट अवधि होती है। ये वर्तमान कोड डिफ़ॉल्ट हैं, कॉन्फ़िगर करने योग्य डैशबोर्ड सेटिंग्स नहीं।

सामान्य चैट के लिए PAT कनेक्शन का उपयोग करें। `tools` या पुराने `functions` वाले एजेंट अनुरोध क्रेडेंशियल चयन के दौरान PAT खातों को बाहर रखते हैं, जिनमें पिन किए गए कॉम्बो लक्ष्य भी शामिल हैं। मिश्रित Qoder पूल अब भी अपना HTTP खाता चुन सकता है। PAT एक्ज़ीक्यूटर को किए गए प्रत्यक्ष कॉल भी टूल परिभाषाओं को चुपचाप हटाने के बजाय CLI लॉन्च करने से पहले स्पष्ट रूप से विफल होते हैं। यह प्रतिबंध API कॉलर द्वारा दिए गए टूल से संबंधित है, न कि ऐसे किसी आंतरिक टूल से जिसे Qoder CLI स्वयं उपयोग कर सकता है। HTTP कुंजी इस बात की गारंटी नहीं देती कि हर मॉडल टूल का समर्थन करता है; मॉडल की सामान्य क्षमता जाँच अभी भी लागू होती है।

ब्राउज़र OAuth केवल तभी उपलब्ध होता है, जब व्यवस्थापक सभी पाँच सेटिंग्स कॉन्फ़िगर करता है:
`QODER_OAUTH_AUTHORIZE_URL`, `QODER_OAUTH_TOKEN_URL`, `QODER_OAUTH_USERINFO_URL`,
`QODER_OAUTH_CLIENT_ID`, और `QODER_OAUTH_CLIENT_SECRET`। वे डिफ़ॉल्ट रूप से खाली होती हैं; कॉन्फ़िगर न किए गए इंस्टॉलेशन में यह मानने के बजाय समर्थित क्रेडेंशियल इंपोर्ट का उपयोग करना चाहिए कि ब्राउज़र साइन-इन फ़्लो तैयार है।

कार्यान्वयन संदर्भ: [Qoder एक्ज़ीक्यूटर](../../open-sse/executors/qoder.ts),
[CLI रनटाइम](../../open-sse/services/qoderCli.ts), और
[OAuth कॉन्फ़िगरेशन](../../src/lib/oauth/constants/oauth.ts)। क्रमिक PAT स्ट्रीमिंग और कॉन्फ़िगर करने योग्य टाइमआउट अलग-अलग सुधार हैं; यह व्यवहार उनका वादा नहीं करता।

## सामान्य प्रश्न

### "क्या OmniRoute का उपयोग करने के लिए मुझे भुगतान करना होगा?"

**नहीं!** OmniRoute मुफ़्त और ओपन-सोर्स है। आप बिना कोई भुगतान किए मुफ़्त प्रदाताओं (Kiro, Pollinations) का उपयोग कर सकते हैं। आपको केवल तभी भुगतान करना होगा, जब आप सशुल्क प्रदाताओं का उपयोग करना चुनते हैं।

### "मुझे किस प्रदाता से शुरुआत करनी चाहिए?"

**Kiro AI** से शुरुआत करें — यह मुफ़्त है, इसके लिए API key की आवश्यकता नहीं है, और यह आपको Claude मॉडल का एक्सेस देता है। फिर आवश्यकता के अनुसार और प्रदाता जोड़ें।

### "क्या मैं एक साथ कई प्रदाताओं का उपयोग कर सकता हूँ?"

**हाँ!** यही OmniRoute का मुख्य उद्देश्य है। कई प्रदाताओं को कनेक्ट करें और प्रत्येक अनुरोध के लिए OmniRoute को सबसे उपयुक्त प्रदाता चुनने देने हेतु `model: "auto"` का उपयोग करें।

### "यदि कोई प्रदाता बंद हो जाए, तो क्या होगा?"

OmniRoute विफल प्रदाताओं को अपने-आप छोड़ देता है और अगले प्रदाता को आज़माता है। आपको कुछ भी करने की आवश्यकता नहीं है।

### "मैं किसी प्रदाता को डिस्कनेक्ट कैसे करूँ?"

Providers पर जाएँ → प्रदाता पर क्लिक करें → **Disconnect** पर क्लिक करें।

### "क्या मैं अपनी मौजूदा API keys का उपयोग कर सकता हूँ?"

**हाँ!** यदि आपके पास OpenAI, Anthropic, Google आदि के लिए पहले से API keys हैं, तो आप OmniRoute में उनका उपयोग कर सकते हैं। प्रदाता को कनेक्ट करते समय बस उन्हें पेस्ट करें।
