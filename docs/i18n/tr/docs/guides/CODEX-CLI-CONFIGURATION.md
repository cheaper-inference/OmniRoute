---

> **Etkili olan tek biçim TOML'dur.** Modern Codex yalnızca `~/.codex/config.toml`
> dosyasını okur (codex-cli 0.147.0 ile doğrulanmıştır: `codex --help`,
> `-c/--config` geçersiz kılmalarının "`~/.codex/config.toml` dosyasından yüklendiğini"
> belirtir). Eski `~/.codex/config.yaml`, eski npm CLI'a aitti ve sessizce yok sayılır.
> Kontrol paneli oluşturucusu (`/api/cli-tools/apply`, araç `codex`), korumacı bir
> birleştirme yaklaşımıyla TOML yazar — mevcut anahtarlar ve diğer sağlayıcı blokları
> korunur, API anahtarı `OMNIROUTE_API_KEY` içinde kalır (asla dosyaya yazılmaz) ve
> geride kalmış eski bir `config.yaml` dosyası, dosyaya dokunulmadan taşıma notu olarak
> bildirilir.

## Yapıştırmaya hazır config.toml

`<YOUR_HOST>` ve `<YOUR_KEY>` değerlerini kendi değerlerinizle değiştirin:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # araç çağrısı başına geçmiş depolama sınırı

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc veya ~/.zshrc — gerçek anahtar değeri, asla config.toml içinde değil
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: ChatGPT uygulamasının içinde paketlenmiş Codex

Codex'i ChatGPT masaüstü uygulaması üzerinden yüklediyseniz `codex` ikili dosyası
yalnızca uygulama paketinin içinde bulunabilir ve henüz kabuğunuzun `PATH`
değişkeninde olmayabilir. Kaynaklar dizinini kabuk başlangıç dosyanıza ekleyin:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Yeni bir kabuk açın, ardından doğrulayın:

```bash
command -v codex
codex --version
```

### Kimlik doğrulaması olmayan yerel OmniRoute: yer tutucu anahtar yeterlidir

Codex, ilk istek CLI'dan ayrılmadan **önce** `env_key` tarafından belirtilen
ortam değişkeninin mevcut olduğunu doğrular. **Yerel** OmniRoute örneğiniz kimlik
doğrulaması gerektirmiyorsa boş olmayan herhangi bir yer tutucu yeterlidir:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

OmniRoute sunucunuz korumalı veya uzaksa bunun yerine gerçek bir anahtar kullanın.

> **Yaygın ana makine seçenekleri**
>
> | Erişim     | URL                           |
> | ---------- | ----------------------------- |
> | Yerel ağ   | `http://192.168.0.1:20128/v1` |
> | Tailscale  | `http://100.x.x.x:20128/v1`   |
> | Geri döngü | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — tüm modellerde neden çalışır?

Codex CLI, `wire_api = "chat"` (Chat Completions) seçeneğini Şubat 2026'da kullanımdan kaldırdı ve artık `wire_api = "responses"` (OpenAI Responses API) kullanımını **zorunlu tutuyor**. `wire_api = "chat"` olarak ayarlandığında v0.138'den itibaren başlatma sırasında anında çökme meydana gelir.

GLM ve Kimi dahil birçok sağlayıcı hâlâ yalnızca bir Chat Completions uç noktası sunar. DeepSeek V4 artık Anthropic uyumlu bir uç noktanın yanı sıra yerel bir Responses API da sunuyor; OmniRoute varsayılan olarak Responses kullanır ve her DeepSeek bağlantısının Anthropic uyumluluğunu seçmesine olanak tanır.

**OmniRoute bunu şeffaf biçimde çözer:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute, sağlayıcının yerel protokolünü seçer ve gerektiğinde dönüştürür
    → POST /responses (DeepSeek V4) veya /chat/completions (Mistral / GLM / Kimi / diğerleri)
```

OmniRoute kullanırken hiçbir zaman ayrı bir dönüştürme proxy'sine ihtiyaç duymazsınız. **Tüm modeller `wire_api = "responses"` kullanır** — geri kalanını OmniRoute halleder.

> **`wire_api` varsayılan değerdir** — alanın varsayılanı `"responses"` olduğundan
> `config.toml` dosyasından tamamen çıkarılabilir. Yalnızca amacı belgeliyorsanız bunu
> açıkça ayarlayın.

## Bağlam penceresi ve sıkıştırma

### Token yapılandırma alanları

| Alan                             | Açıklama                                                                                                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `model_context_window`           | Etkin model için toplam token bütçesi. Modelin ilan edilen sınırına ayarlayın.                                                                                                       |
| `model_auto_compact_token_limit` | Otomatik geçmiş sıkıştırmasını tetikleyen eşik. **Maksimum: `model_context_window` değerinin %90'ı** — %90'ın üzerindeki değerler sessizce yok sayılır.                              |
| `tool_output_token_limit`        | Geçmişte araç çağrısı çıktısı başına saklanan token sınırı. Tek bir büyük araç yanıtının pencereyi doldurmasını önler. **Bu, maksimum çıktı değildir** — geçmişte saklama sınırıdır. |
| `compact_prompt`                 | Sıkıştırma sırasında kullanılan sistem istemini satır içi olarak geçersiz kılar (v0.138+).                                                                                           |

> **`model_max_output_tokens` hakkında not**: Bu alan **Codex CLI yapılandırma şemasının bir parçası değildir** (Codex Rust kod tabanında bulunmaz). Ayarlanırsa sessizce yok sayılır. Buna güvenmeyin — geçmişte ne kadar araç çıktısının saklanacağını kontrol etmek için `tool_output_token_limit` kullanın.

## Akıl Yürütme Çabası

Modelin yanıt vermeden önce ne kadar "düşüneceğini" kontrol eder.

| Değer    | Kullanım amacı                                         |
| -------- | ------------------------------------------------------ |
| `none`   | Akıl yürütme yok — doğrudan yanıt                      |
| `low`    | Basit görevler (yeniden adlandırma, biçimlendirme)     |
| `medium` | Belirtilmediğinde **sunucu varsayılanı**               |
| `high`   | Orta düzey görevler (yeniden düzenleme, hata ayıklama) |
| `xhigh`  | Mimari, derin analiz, karmaşık problemler              |

```bash
# Her çalıştırma için geçersiz kılma
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Ayrıca Desktop'ın düşünme metnini (yalnızca şifrelenmiş veri bloklarını değil) görüntüleyebilmesi için bir akıl yürütme **özeti** ayarlayın:

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # veya desteklendiğinde ultra
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute Düşünme Bütçesi (sunucu ayarı)

OmniRoute ana makinesinde, Codex çaba/özet bilgilerinin üst sağlayıcıya ulaşması için **Settings → AI → Thinking Budget** ayarı **`passthrough`** olmalıdır. **`auto` modu**, istemciden gelen tüm `reasoning` / `reasoning_effort` alanlarını kaldırır ve Codex doğru yapılandırılmış olsa bile düşünme panellerinin boş kalmasına neden olur.

Tam kılavuz: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Sıkıştırma ve istem önbelleği birbirinden bağımsızdır ve `passthrough` altında çalışmaya devam eder.

## Profiller — model/iş akışı başına adlandırılmış yapılandırmalar

Profiller, tek bir bayrakla model ve bağlam penceresi arasında geçiş yapmanızı sağlar. Her profil, temel `config.toml` dosyasının üzerine uygulanan düz bir
`~/.codex/<name>.config.toml` dosyasıdır.

> **Adlandırma kuralı (Codex CLI v0.137+):** dosya `~/.codex/<name>.config.toml` olmalıdır — **`profile-` öneki kullanılmaz**.
> CLI, `-p kimi-k27` → `~/.codex/kimi-k27.config.toml` olarak çözümler. Dosya bulunamazsa varsayılan yapılandırma sessizce uygulanır.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # hızlı, ucuz
```

### Çaba profilleri (aynı model, farklı çaba)

```bash
codex -p low      # cx/gpt-5.5, çaba=low
codex -p medium   # cx/gpt-5.5, çaba=medium
codex -p high     # cx/gpt-5.5, çaba=high
codex -p xhigh    # cx/gpt-5.5, çaba=xhigh (varsayılan)
codex -p chat     # cx/gpt-5.5, çaba ayarlanmamış (sunucu varsayılanı)
```

## `omniroute setup-codex` ile profilleri otomatik olarak oluşturma

OmniRoute'u bir VPS üzerinde çalıştırıyorsanız canlı model kataloğundan otomatik olarak profil dosyaları oluşturabilirsiniz:

```bash
# Bir VPS'ten (20128 numaralı bağlantı noktasındaki yerel OmniRoute'u kullanır)
omniroute setup-codex

# Herhangi bir makineden — VPS'nizi belirtin
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Dosyaları yazmadan önizleyin
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Yalnızca GLM ve Kimi profillerini oluşturun
omniroute setup-codex --only glm,kimi

# Özel bir dizine yazın
omniroute setup-codex --codex-home /path/to/.codex
```

Komut `/v1/models` verilerini alır, bilinen modeller için ayarlanmış profilleri kullanır, diğer uyumlu metin modelleri için katalog meta verilerine başvurur ve her biri için `~/.codex/<name>.config.toml` dosyasını yazar. İdempotenttir — yeniden çalıştırılması güvenlidir.

Temel `config.toml` dosyasında `model_providers.omniroute` tanımı yoksa açıkça çalıştırılan `setup-codex`, seçilen yerel veya uzak uç noktayı kullanarak bu tanımı oluşturulan her katmana ekler. Temel dosya değiştirilmeden bırakılır. Mevcut bir sağlayıcı tanımı, uç noktası ve kimlik doğrulama ayarları da dâhil olmak üzere devralınır. Geçersiz temel TOML, profiller yazılmadan önce oluşturma işlemini durdurur.

`--api-key` veya `OMNIROUTE_API_KEY` sağladığınızda yeni tanımlanan sağlayıcı `env_key = "OMNIROUTE_API_KEY"` ifadesine başvurur; anahtarın kendisi asla kaydedilmez veya önizlemede yazdırılmaz. Bu değişkeni Codex'i başlattığınız ortamda ayarlayın. Bir anahtar sağlanmadığında yeni tanım, kimlik doğrulaması yapılmamış istekleri kabul edecek şekilde yapılandırılmış bir OmniRoute örneği için anahtar gerektirmez.

Aşağıda açıklanan isteğe bağlı katalog otomatik eşitlemesi, bir katmanda zaten bulunan sağlayıcı tanımlarını korur ancak yeni sağlayıcı ayarlarını ilk kez oluşturmaz; sağlayıcıyı önce açık kurulumla veya kontrol panelinden yapılandırın. Operatör tarafından yönetilen kimlik bilgileri içerebileceklerinden mevcut sağlayıcı ayarları deneme çalıştırması önizlemelerinde gösterilmez.

OmniRoute, başarılı bir sağlayıcı model keşfi/içe aktarma işlemi canlı kataloğu değiştirdikten sonra bu aynı profil dosyalarını **otomatik olarak eşitleyebilir**. Bu özellik **isteğe bağlıdır ve varsayılan olarak kapalıdır**: **CLI Code kontrol panelinden** etkinleştirin ("CLI profile auto-sync" → Codex) veya `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` olarak ayarlayın (`CLI_ALLOW_CONFIG_WRITES` ayarını da dikkate alır; bu ayar varsayılan olarak açıktır). Etkinleştirildiğinde yalnızca ayrı `~/.codex/*.config.toml` profil dosyalarını yazar; etkin/varsayılan `~/.codex/config.toml` dosyasını, Codex-lb ayarlarını, kimlik doğrulamasını veya sağlayıcı seçimini asla değiştirmez.

## Uzun süren görevler

İki OmniRoute varsayılanı, birden fazla saat süren Codex CLI oturumlarını sessizce sabote edebilir. Codex CLI ayarı da — her ikisi de OmniRoute tarafında canlı değildir. Hesapları sabitleyen ve boşta kalan kesintileri devre dışı bırakan yukarı akış proxy'lerinden bir yapılandırma geçiren kullanıcılar genellikle her ikisine de ulaşır ve OmniRoute "uzun bir oturumu sürdüremeyeceği" sonucuna varır.

| Belirti                                                                                           | Muhtemel sebep                                                                | Topuz                    |
| ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------ |
| Oturumda hesaplar değiştiriliyor / sıralar arasında bilgi istemi önbelleği sürekliliği kayboluyor | Oturum benzeşimi TTL : `0` (devre dışı)                                       | `sessionAffinityTtlMs`   |
| Müşteriye yönelik bir istem olmadan bağlantı, akıl yürütmenin ortasında kesiliyor                 | Akış boşta denetleyicisi, yukarı akış öbeği olmadan 10 dakika sonra ateşlendi | `STREAM_IDLE_TIMEOUT_MS` |

İlgili tartışmalar: [#7126](https://github.com/cheaper-inference/OmniRoute/discussions/7126) (uzun görev düşüşleri), [#5718](https://github.com/cheaper-inference/OmniRoute/discussions/5718) (benzerliğin neden varsayılan olarak devre dışı kaldığı). Takip: [#7287](https://github.com/cheaper-inference/OmniRoute/issues/7287).

### 1. Oturum benzeşimi — bir görüşmeyi tek bir hesaba sabitleme

**Varsayılan:** `sessionAffinityTtlMs = 0` (devre dışı).

**Nereye ayarlanacağı**

- Kontrol paneli →** Ayarlar → Yönlendirme** →** Oturum benzeşimi** →** Yakın ilgi TTL (saniye)** (`ComboDefaultsTab`)
- Veya `sessionAffinityTtlMs` ile PATCH ayarları** milisaniye** (Zod aralığı `0`–`86_400_000`, yani 24 saate kadar)

> Yalnızca Codex `codexSessionAffinityTtlMs` #7274 olarak yeniden adlandırıldı. Eski anahtar hâlâ salt okunur bir takma ad olarak kabul edilmektedir; yeni yapılandırmalar `sessionAffinityTtlMs` kullanmalıdır. Yakın ilgi artık şunlar için geçerlidir:** herhangi** sağlayıcı TTL `0` üzerinde olduğunda, yalnızca Codex — değil, [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Oturum benzeşimine bakın.

**0'da kaldığında ne kırılır**

Çok turlu bir Codex görüşmesinin her turu, aktif kombo stratejisi tarafından bağımsız olarak yönlendirilir ve** tur başına farklı hesap** . Bu, yukarı akış oturumu/istem-önbellek sürekliliğini bozar. OmniRoute TTL `0` (`extractSessionAffinityKey` `src/sse/services/auth.ts`) büyük olduğunda yalnızca Codex oturum başlıklarına (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) ve `prompt_cache_key` / `session_id` gibi gövde alanlarına başvurur.

**Çok saatlik tek bir görev için önerilir**

TTL ayarlayın** görevin beklenen duvar saati uzunluğunun üzerinde** (UI maksimum** 86400 saniye** = 24 saat):

| Beklenen görev uzunluğu | Yakın ilgi TTL (UI, saniye) | `sessionAffinityTtlMs` |
| ----------------------- | --------------------------- | ---------------------- |
| Birkaç saat             | `14400` (4 saat)            | `14400000`             |
| Gecelik / ~ 12h         | `43200` (12 saat)           | `43200000`             |
| Tam gün                 | `86400` (24 saat, maksimum) | `86400000`             |

Katılım kasıtlıdır: benzeşimin devre dışı bırakılması, hesaplar arasında yük dengelemeyi kolaylaştırır; bu sayede uzun bir temsilci oturumu boyunca devamlılık sağlanır. Bu kılavuz şunları yapar:** Olumsuz** Uzun Codex görevlerini çalıştıran varsayılan — operatörlerinin etkinleştirilmesi gerekir.

### 2. Akışın boşta kalma zaman aşımı — sessiz muhakeme dönüşlerini öldürmez

**Varsayılan:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 dakika). Ayarlanmadığında `REQUEST_TIMEOUT_MS` miras alır; paylaşılan taban çizgisi de 600000'dir. Bkz. [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Zaman Aşımları.

**Varsayılanda ne bozulur?**

10 dakikadan fazla sessiz kalan bir Codex akıl yürütme/araç dönüşü** gerçek bir yukarı akış parçası yok** SSE boşta gözlemcisi (`open-sse/utils/stream.ts`) tarafından zorla kapatılır. İstemci genellikle "herhangi bir bildirimde bulunulmadan otomatik olarak durduruldu" ile eşleşen çıplak bir bağlantı düşüşü — görür.

Kritik detay: OmniRoute sentetik SSE** kalp atışı sıfırlanmıyor** boş saat. Yalnızca gerçek bir yukarı akış gövde parçası `lastChunkTime` dosyasını günceller. Hala "düşünen" sessiz bir model, bekçi köpeğinin bakış açısından, akıntıya karşı durmuş bir modelle aynı görünür.

İlgili Undici gövdesi hareketsizliği: `FETCH_BODY_TIMEOUT_MS` (ayrıca varsayılan olarak aynı 10 dakikalık taban çizgisine ayarlanır; `0` bunu devre dışı bırakır). Akış için, `FETCH_TIMEOUT_MS` yalnızca akış aktif olduğunda bağlantı kurulumunu / ilk başlıkları — kapsar, duraklamalar `STREAM_IDLE_TIMEOUT_MS` ve `FETCH_BODY_TIMEOUT_MS` tarafından yönetilir.

**Çok saatlik tek bir görev için önerilir**

OmniRoute işlem ortamında (`.env` / compose / systemd):

```bash
# Disable stream idle + body inactivity cutoffs for long reasoning turns
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Veya bunları beklediğiniz en uzun sessiz aralığın üzerine çıkarın (değerler milisaniyedir):

```bash
# Example: allow up to 2 hours of silence between upstream chunks
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Bu env değişkenlerini değiştirdikten sonra OmniRoute yeniden başlatın.

### Beton tarifi — çok saatlik Codex görevi

1. **Hesabı sabitle:** Kontrol Paneli → Ayarlar → Yönlendirme → Oturum benzeşimi → Yakın İlgi TTL = `43200` (12 saat) veya `86400` (maks. 24 saat).
2. **Boşta kalma kesintilerini artırın / devre dışı bırakın** OmniRoute ortamında:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Her zamanki Codex `config.toml` koruyun (`wire_api = "responses"`, doğru `base_url`, `OMNIROUTE_API_KEY`) — Bu iki davranış için Codex tarafında affinity/idle düğmeleri yoktur.
4. OmniRoute yeniden başlatın, ardından uzun Codex görevini başlatın.

### Temerrüt kararı (#7287)

| Topuz                    | Varsayılan gemi  | Bu kılavuzda değişiklik var mı?                                                                          |
| ------------------------ | ---------------- | -------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (kapalı)     | **HAYIR** — katılıma devam ediyor (yük dengeleme ve süreklilik; bkz. Tartışma #5718)                     |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 dk) | **HAYIR** — genel trafiğe 10 dakika kalır; uzun Codex operatörleri onu yükseltir veya devre dışı bırakır |

Varsayılanlardan herhangi birinin global olarak çevrilmesi, yalnızca Codex için değil, örneğin her istemcisi için davranışı değiştirir. Düğmeleri belgeleyin; Açık bir operatör kararı aksini söyleyene kadar varsayılanları olduğu gibi bırakın.

### Boşta kesmelerin teşhisi

Boştaki bekçi köpeği ateş ettiğinde OmniRoute şu şekilde bir çizgi kaydeder:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

`Idle timeout: no data from` için Grep (veya `stream_idle_timeout` kodu / hata adı `StreamIdleTimeoutError`). Sağlayıcı segmenti, bu istek için kullanılan OmniRoute (`codex`, başka bir sağlayıcı kimliği veya bilinmiyorsa `provider` ) — her zaman `codex` değişmez dizgesi değildir.

## Sorun Giderme

**`Error: wire_api = "chat" is no longer supported`**
Yapılandırmanızdan `wire_api = "chat"` satırını kaldırın. `wire_api = "responses"` olarak ayarlayın veya alanı atlayın (v0.138 sürümünden beri varsayılan değer `"responses"`).

**`Error: model not found`**
Modelin OmniRoute'ta doğru ön ekle mevcut olduğunu doğrulayın. `omniroute models list` komutunu kullanın veya `/dashboard/providers/<provider>` yolunu açın.

**`Authentication error`**
`OMNIROUTE_API_KEY` değişkeninin dışa aktarıldığını doğrulayın: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
Codex, ilk isteği yapmadan önce ortam değişkeninin mevcut olduğunu doğrular. Korumalı sunucular için gerçek bir anahtarı dışa aktarın veya **yerel** OmniRoute örneğiniz kimlik doğrulaması gerektirmiyorsa `OMNIROUTE_API_KEY=local` gibi boş olmayan bir yer tutucu kullanın. Değişkeni `~/.bashrc` veya `~/.zshrc` dosyasına eklediyseniz kabuğu yeniden başlatın.

**`Connection refused`**
OmniRoute'un çalıştığını ve `base_url` ana makinesinin/bağlantı noktasının ağınız için doğru olduğunu doğrulayın (yerel, Tailscale veya VPS).

**Oturum bağlam sınırına yakınken çöküyor**
`model_context_window` ve `model_auto_compact_token_limit` değerlerini açıkça ayarlayın. Yukarıdaki bağlam penceresi tablosuna bakın.

**Sıkıştırma çok geç devreye giriyor**
`model_auto_compact_token_limit` değerini pencerenin %80–85'ine düşürün. Asla %90'ın üzerinde ayarlamayın.

**Profil yüklenmiyor (`-p <name>` sessizce yok sayılıyor)**
Dosyanın `~/.codex/<name>.config.toml` konumunda bulunduğunu doğrulayın (`profile-` ön eki olmadan). `ls ~/.codex/*.config.toml` komutunu çalıştırın.

**Uzun Codex görevi çalışmanın ortasında kesiliyor / turlar arasında hesap değiştiriyor**
[Uzun süren görevler](#long-running-tasks) bölümüne bakın. Oturum benzeşimini etkinleştirin (TTL, görev süresinden uzun olmalıdır) ve `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS` değerlerini artırın veya devre dışı bırakın. OmniRoute günlüklerinde `Idle timeout: no data from` ifadesini grep ile arayın.
