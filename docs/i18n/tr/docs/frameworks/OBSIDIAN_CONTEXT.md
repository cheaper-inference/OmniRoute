> **Doğruluk kaynağı:** `src/lib/obsidian/api.ts` (REST + senkronizasyon istemcisi),
> `src/lib/db/obsidian.ts` (token / temel URL / WebDAV kalıcılığı),
> `src/lib/obsidianSync.ts` (WebDAV kasa senkronizasyonu), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 MCP aracı), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (ayar API'leri). Araç kaydı
> ve kapsam bağlantıları `open-sse/mcp-server/server.ts` içinde bulunur.

## Nedir?

OmniRoute, yerleşik MCP sunucusu aracılığıyla ajanların okuyup yazdığı yerel bir Markdown
bilgi tabanı olan **Obsidian** kasasına bir **bağlam kaynağı** olarak bağlanır.
Entegrasyon, masaüstü uygulamasında çalışan **Obsidian Local REST API** topluluk eklentisiyle
iletişim kurar; böylece ajanlar notlarda arama yapabilir, dosyaları okuyabilir/yazabilir/yamalayabilir,
kasayı listeleyebilir, günlük/haftalık periyodik notlarla çalışabilir, etiketleri yönetebilir,
Obsidian komutlarını çalıştırabilir ve (isteğe bağlı olarak) çift yönlü bir masaüstü↔mobil
kasa senkronizasyonunu koordine edebilir.

İstemci (`src/lib/obsidian/api.ts`), Local REST API'yi şu özelliklerle sarmalar:

- Geçici `5xx` hataları için **geri çekilmeli yeniden deneme**, `AbortController` aracılığıyla **30 saniyelik zaman aşımı**.
- **Türü belirlenmiş hata sınıflandırması** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Yaygın port hatasını (MCP uç noktası olan `27124` **değil**, `27123` üzerinde HTTP)
  ve Tailscale biçimini belirten, kullanıcı dostu bir **"Obsidian'a ulaşılamıyor" ipucu**.
- Boşluk/eğik çizgi içeren not yollarının güvenli olması için kasaya göreli **yol kodlama**.

## Kurulum

Obsidian tokeni veya temel URL için **ortam değişkeni yoktur** — her ikisi de
`src/lib/db/obsidian.ts` aracılığıyla SQLite `key_value` tablosunda (`obsidian` ad alanı)
saklanır. Token **bekleme durumunda şifrelenir** (AES-256-GCM, düz metinle geriye dönük
uyumluluk yedeğiyle). Endpoint kontrol panelinin **Bağlam Kaynakları** sekmesinden
(`ObsidianSourceCard`) veya ayarlar REST API'si aracılığıyla yapılandırın.

> [!IMPORTANT]
> **Obsidian Local REST API** eklentisi yüklenmiş ve çalışıyor olmalıdır. REST
> arayüzü **HTTP `127.0.0.1:27123`** adresini dinler (varsayılan temel URL). `27124`
> portu _ayrı_ bir MCP/HTTPS uç noktasıdır ve ayarlar rotası tarafından açıkça reddedilir.
> Başka bir cihazdan bağlanıyorsanız `http://<tailscale-ip>:27123` kullanın.

### Yapılandırma anahtarları (SQLite `key_value`, `obsidian` ad alanı)

| Anahtar           | Amaç                                                    | Şifreli |
| ----------------- | ------------------------------------------------------- | ------- |
| `api_key`         | Local REST API bearer tokeni                            | evet    |
| `base_url`        | REST temel URL'si (varsayılan `http://127.0.0.1:27123`) | hayır   |
| `vault_path`      | Kasa dizininin mutlak yolu (senkronizasyon için)        | hayır   |
| `webdav_username` | Oluşturulan WebDAV kullanıcı adı (kasa senkronizasyonu) | hayır   |
| `webdav_password` | Oluşturulan WebDAV parolası (kasa senkronizasyonu)      | evet    |
| `webdav_enabled`  | WebDAV kasa senkronizasyonunun etkin olup olmadığı      | hayır   |

### REST aracılığıyla yapılandırma

```bash
# Local REST API tokenini kaydedin ve doğrulayın (POST, durum kontrolüyle doğrular)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Bağlantı durumunu kontrol edin (connected, hasToken, baseUrl, vaultPath döndürür)
curl http://localhost:20128/api/settings/obsidian

# Bağlantıyı kesin (saklanan tokeni temizler)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Tüm yöntemler kontrol paneli kimlik doğrulaması gerektirir. `POST`, `27124` portundaki
tüm URL'leri reddeder ve kalıcı olarak kaydetmeden önce Local REST API durum uç noktasını
çağırarak tokeni doğrular.

### WebDAV kasa senkronizasyonu

`src/app/api/settings/obsidian/webdav/route.ts`, isteğe bağlı WebDAV destekli bir
kasa senkronizasyonunu yönetir (`src/lib/obsidianSync.ts` tarafından yürütülür).
Bu özellik etkinleştirildiğinde OmniRoute yerel bir kasa dizinine yönlendirilir ve
rastgele bir WebDAV kullanıcı adı/parola çifti oluşturulur:

```bash
# Bir kasa dizini için WebDAV senkronizasyonunu etkinleştirin (kullanıcı adı/parola oluşturur)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV senkronizasyon durumunu alın (kimlik bilgileri yalnızca etkinken döndürülür)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV senkronizasyonunu devre dışı bırakın (kimlik bilgilerini ve yönetilen .stignore dosyasını temizler)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Güvenlik ve Taşıma

WebDAV kimlik doğrulaması, IP başına arıza izlemeyi ve kilitlemeyi zorunlu kılar (60 saniyelik bir pencere içinde 10 başarısız deneme, `429 Too Many Requests` ve `Retry-After` ile 5 dakikalık bir kilitlemeyi tetikler). WebDAV Temel kimlik doğrulama bilgilerini ilettiğinden, geridöngü dışındaki WebDAV uç noktasına erişirken TLS sonlandırılması (veya Tailscale veya Cloudflare Tunnel gibi güvenli bir tünel üzerinden yönlendirme) önemle tavsiye edilir.

### API anahtarı başına bağlam kaynağı (isteğe bağlı)

Obsidian yapılandırması, `api_key_context_sources` tablosu
(`src/lib/db/apiKeyContextSources.ts`) aracılığıyla **API anahtarı başına**
kapsamlandırılabilir. Bir MCP çağrısı kimliği doğrulanmış bir API anahtarı kimliği
taşıdığında `getObsidianConfigForApiKey()`, o anahtarın kendi tokenini/temel URL'sini/kasa
yolunu (`source: "api_key"`) tercih eder; aksi takdirde genel yapılandırmaya
(`source: "global"`) geri döner.

Senkronizasyon dışı MCP araçları, bu yapılandırmayı okumadan önce çözümlenmiş bir çağıran
kimliği gerektirir. Kimliği olmayan bir çağıran `Obsidian API token not configured`
yanıtını alır ve hiçbir kasa isteği gönderilmez. HTTP çağıranları istek kimlik bilgileri
üzerinden çözümlenir; stdio çağıranları `OMNIROUTE_API_KEY` veya `ROUTER_API_KEY`
üzerinden çözümlenebilir. Çözümlenemeyen bir HTTP çağıranı, sunucunun ortam kimliğini
devralamaz. Yer tutucu kimlikler tek başına erişim yetkisi vermez; `env-key` değerine
çözümlenen geçerli bir ortam kimlik bilgisi desteklenmeye devam eder. API anahtarına özel
Obsidian yapılandırması bulunmayan kimliği doğrulanmış anahtarlar, genel yapılandırmaya
geri dönme davranışını korur. Dört `obsidian_sync_*` aracı, ayrı senkronizasyon tokeni
davranışını korur.

## MCP araçları (22)

`open-sse/mcp-server/tools/obsidianTools.ts` tanımlıdır. token/base-URL çağrı başına çözümlenir (önce API anahtarı başına, ardından genel). OmniRoute çarpan araçlar** senkronizasyon sunucusu** (dört `obsidian_sync_*` aracı) ayrıca OmniRoute ayarlarında yapılandırılmış senkronizasyon kimlik doğrulama belirtecini gerektirir.

### Araçları okuma (`read:obsidian`)

| Alet                         | Tanım                                                                                                                |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Yerel REST API erişilebilir olup olmadığını ve kimliğinin doğrulanıp doğrulanmadığını kontrol edin.                  |
| `obsidian_search_simple`     | Not içeriğinin tam metin araması; dosya yollarıyla birlikte parçacıkları döndürür.                                   |
| `obsidian_search_structured` | JSON Mantık ifadesini (and/or/regex/path filtreleri) kullanarak arama yapın.                                         |
| `obsidian_read_note`         | Bir notu kasaya bağlı yola göre okuyun; isteğe bağlı olarak belirli bir heading/block/frontmatter.                   |
| `obsidian_list_vault`        | Kasadaki dosyaları ve dizinleri listeleyin (giriş ağacı).                                                            |
| `obsidian_get_document_map`  | Notun başlık yapısını, başlıkların → satır numaralarının haritası olarak alın.                                       |
| `obsidian_get_note_metadata` | İçeriğin tamamı olmadan ön maddeyi, etiketleri, bağlantıları ve char/word sayısını alın.                             |
| `obsidian_get_active_file`   | Şu anda aktif olan dosyanın + içeriğini Obsidian alın.                                                               |
| `obsidian_get_periodic_note` | Bir tarih için daily/weekly/monthly periyodik notunu alın (eğer belirtilmemişse bugün).                              |
| `obsidian_get_tags`          | Tüm kasa etiketlerini frekanslarıyla birlikte listeleyin.                                                            |
| `obsidian_list_commands`     | Kullanılabilir Obsidian komutunu IDs listeleyin ( `obsidian_execute_command` ile kullanın).                          |
| `obsidian_sync_status`       | OmniRoute senkronizasyon sunucusu durumu: çalışıyor, kasa adı, bağlantı noktası, çalışma süresi, son senkronizasyon. |
| `obsidian_sync_conflicts`    | Çözülmemiş senkronizasyon çakışmalarını listeleyin (yol, çakışma yolu, tespit edilen yer).                           |

### Yazma araçları (`write:obsidian`)

| Alet                             | Tanım                                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------------------ |
| `obsidian_write_note`            | Verilen Markdown içeriğiyle bir not oluşturun veya üzerine yazın.                                |
| `obsidian_append_note`           | Bir nota içerik ekleyin; isteğe bağlı olarak belirli bir heading/block.                          |
| `obsidian_patch_note`            | Bir başlık, blok veya ön madde alanında cerrahi olarak append/prepend/replace.                   |
| `obsidian_delete_note`           | Kasadaki bir notu kalıcı olarak silin.                                                           |
| `obsidian_move_note`             | Kasa içindeki bir notu taşıyın veya yeniden adlandırın.                                          |
| `obsidian_execute_command`       | Bir Obsidian komutunu ID komutuyla yürütün.                                                      |
| `obsidian_open_file`             | Obsidian bir dosya açın (eğer mevcut değilse onu oluşturur).                                     |
| `obsidian_sync_trigger`          | Anında çift yönlü bir masaüstü ↔ mobil kasa senkronizasyonunu tetikleyin.                        |
| `obsidian_sync_resolve_conflict` | Senkronizasyon çakışmasını çözün: `local` (mobil), `remote` (masaüstü) veya `keep-both` koruyun. |

> [!NOTE]
> `obsidian_patch_note` hedefleri, isteğe bağlı bir `createTargetIfMissing` ile `heading | block | frontmatter` `targetType` ve `append | prepend | replace` `operation` kabul eder. Dört `obsidian_sync_*` aracı, yerel senkronizasyon sunucusuyla (varsayılan olarak `http://127.0.0.1:27781` ) konuşur ve senkronizasyon belirtecini gerektirir.

### Kapsamlar

Okuma araçları `read:obsidian` gerektirir; yazma araçları `write:obsidian` gerektirir. Uygulama, `open-sse/mcp-server/server.ts` içinde `withScopeEnforcement()` tarafından işlenen, `OMNIROUTE_MCP_ENFORCE_SCOPES=true` bağlanan ve API anahtarında `manage`/`admin` bulunmayan HTTP/SSE arayanlar için zorlanan Notion — ile aynıdır; izin verilen kapsamlar `OMNIROUTE_MCP_SCOPES` veya API anahtarının kapsam bağlamından alınır. Bkz [MCP-SERVER.md](./MCP-SERVER.md).

## Uç Noktalar

| Yöntem   | Yol                             | Amaç                                                         |
| -------- | ------------------------------- | ------------------------------------------------------------ |
| `GET`    | `/api/settings/obsidian`        | `{ connected, hasToken, baseUrl, vaultPath }` döndürür.      |
| `POST`   | `/api/settings/obsidian`        | Tokenı kaydeder ve doğrular (`27124` portunu reddeder).      |
| `DELETE` | `/api/settings/obsidian`        | Bağlantıyı keser (saklanan tokenı temizler).                 |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV senkronizasyon durumu + kimlik bilgileri (etkinken).  |
| `POST`   | `/api/settings/obsidian/webdav` | Bir kasa dizini için WebDAV senkronizasyonunu etkinleştirir. |
| `DELETE` | `/api/settings/obsidian/webdav` | WebDAV senkronizasyonunu devre dışı bırakır.                 |

> Bunlar kontrol paneli ayar rotalarıdır. Kasanın kendisine Obsidian
> Local REST API (yapılandırılmış `base_url`) ve yukarıdaki MCP araçları üzerinden erişilir —
> herkese açık bir `/v1` Obsidian proxy uç noktası yoktur.

## Kullanım alanları

- **Kasayı temel alan yanıtlar** — Bir aracının gerçek notlarınızdan yararlanarak yanıt vermesi için
  `obsidian_search_simple` / `obsidian_search_structured` ve ardından `obsidian_read_note`.
- **Not yazımı / günlük tutma** — Aracı çıktısını, özetleri veya günlük notları
  (`obsidian_get_periodic_note`) kasaya kaydetmek için `obsidian_write_note`, `obsidian_append_note`
  ya da hassas düzenleme sağlayan `obsidian_patch_note`.
- **Kasada gezinme** — Okuma/yazma işleminden önce yapıyı keşfetmek için
  `obsidian_list_vault`, `obsidian_get_document_map` ve `obsidian_get_tags`.
- **Obsidian otomasyonu** — Eklentileri/komutları bir aracı üzerinden yönetmek için
  `obsidian_list_commands` + `obsidian_execute_command`; bir notu kullanıcı arayüzünde görüntülemek
  için `obsidian_open_file`.
- **Mobil senkronizasyon** — WebDAV senkronizasyonunu etkinleştirin, ardından masaüstü↔mobil
  senkronizasyonunu koordine etmek ve çakışmaları çözmek için `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`.
