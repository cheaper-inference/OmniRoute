## Sohbet Tamamlamaları

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

| Üstbilgi                 | Yön   | Açıklama                                                                                                                                                                                                                         |
| ------------------------ | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `x-omniroute-no-memory`  | İstek | Bu istek için bellek + beceri eklemeyi atlamak üzere `true` olarak ayarlayın (önbelleksiz davranışı yansıtır; çağrı başına token/maliyet ek yükünü önler)                                                                        |
| `X-OmniRoute-Progress`   | İstek | İlerleme olayları için `true` olarak ayarlayın                                                                                                                                                                                   |
| `X-Session-Id`           | İstek | Harici oturum yakınlığı için yapışkan oturum anahtarı                                                                                                                                                                            |
| `x_session_id`           | İstek | Alt çizgili varyant da kabul edilir (doğrudan HTTP)                                                                                                                                                                              |
| `X-OmniRoute-Session-Id` | İstek | Çağıran tarafından sağlanan oturum/konuşma etiketi (belleği de besler). Mevcut olduğunda oturum başına maliyet ilişkilendirmesi için aynen `call_logs.session_tag` alanına kaydedilir (#8249) — mevcut değilse asla oluşturulmaz |
| `Idempotency-Key`        | İstek | Tekilleştirme anahtarı (5 saniyelik pencere)                                                                                                                                                                                     |
| `X-Request-Id`           | İstek | Alternatif tekilleştirme anahtarı                                                                                                                                                                                                |
| `x-omniroute-connection` | İstek | Tek modelli bir isteği kimliğine göre tek bir sağlayıcı bağlantısına (hesaba) sabitler — bkz. [İstek başına hesap sabitleme](#account-pinning-per-request)                                                                       |
| `X-OmniRoute-Cache`      | Yanıt | `HIT` veya `MISS` (akışsız)                                                                                                                                                                                                      |
| `X-OmniRoute-Idempotent` | Yanıt | Tekilleştirildiyse `true`                                                                                                                                                                                                        |
| `X-OmniRoute-Progress`   | Yanıt | İlerleme takibi açıksa `enabled`                                                                                                                                                                                                 |
| `X-OmniRoute-Session-Id` | Yanıt | OmniRoute tarafından kullanılan etkin oturum kimliği                                                                                                                                                                             |
| `X-OmniRoute-Request-Id` | Yanıt | İstek korelasyon kimliği (biliniyorsa)                                                                                                                                                                                           |
| `X-OmniRoute-Version`    | Yanıt | OmniRoute derleme sürümü (her zaman mevcut)                                                                                                                                                                                      |
| `X-OmniRoute-Cost-Saved` | Yanıt | Önbelleğin bir HIT durumunda önlediği USD tutarı (yalnızca önbellek isabetleri)                                                                                                                                                  |

#### İstek başına hesap sabitleme

Bir sağlayıcının birden fazla bağlantısı (hesabı veya anahtarı) olduğunda OmniRoute normalde
hesap seçme stratejisi aracılığıyla bunlardan birini seçer. Bunun yerine bir istek,
`x-omniroute-connection` üstbilgisiyle belirli bir bağlantıyı sabitleyebilir:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Kimlik nerede bulunur?** Kontrol panelinde sağlayıcı sayfasını açın
  (**Kontrol Paneli → Sağlayıcılar → <sağlayıcı>**) ve bir bağlantı satırındaki `xxxxxxxx…`
  kimlik etiketine tıklayın — tam bağlantı kimliği panoya kopyalanır.
- **Hangi istekler bunu dikkate alır?** `/v1/chat/completions`, `/v1/messages` ve
  `/v1/responses` üzerindeki tek modelli istekler (`provider/model`). Kombolar üstbilgiyi
  yok sayar: Bunun yerine her kombo adımı için adımın kendi bağlantısı aracılığıyla bir hesap sabitleyin.
- **Sabitleme bir tercih değil, kesin bir kuraldır.** Yalnızca sabitlenen bağlantı kullanılır.
  İstek içindeki bir hata, hesabın bekleme süresini kaydeder ancak aynı sağlayıcının
  başka bir hesabına **geçiş yapmaz**.
- **Bekleme süresi ve kota, sabitlemeyi kaldırır.** Sabitlenen bağlantı bekleme süresindeyken,
  kotası tükenmişken veya bir kota politikası tarafından engellenmişken sonraki istekler,
  tıpkı sabitlenmemiş trafikte olduğu gibi sağlayıcının diğer bağlantılarına geri döner.
- **Bilinmeyen veya devre dışı bırakılmış kimlikler başarısız olur.** Sağlayıcının etkin
  havuzunda bulunmayan bir kimlik (silinmiş, devre dışı bırakılmış veya başka bir sağlayıcıya
  ait), uygun hesap bırakmaz; dolayısıyla istek sessizce başka bir yere yönlendirilmek yerine
  başarısız olur.

Claude Code, özel üstbilgileri `ANTHROPIC_CUSTOM_HEADERS` aracılığıyla gönderir. Bunu
`~/.claude/settings.json` dosyasındaki `env` bloğuna veya proje başına farklı bir hesap
sabitlemek için proje düzeyindeki `.claude/settings.json` dosyasına ekleyin:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Kaynak: `src/sse/handlers/chat.ts` (üstbilginin okunması), `src/sse/services/auth.ts` ve
`src/sse/services/sessionAffinityPin.ts` (sabitlemenin kaldırılması ve havuzda bulunmama denetimi).

> **Maliyet telemetrisi üstbilgileri:** Akışsız başarılı yanıtlar ayrıca `X-OmniRoute-*` maliyet telemetrisi kümesini taşır — `X-OmniRoute-Response-Cost` (USD, sabit 10 ondalık basamak; ücretsiz/fiyatlandırılmamış olanlar için `0.0000000000`), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` ve `X-OmniRoute-Fallback-Attempts` (yalnızca > 0 olduğunda), ayrıca `X-OmniRoute-Request-Id` ve `X-OmniRoute-Version`. Bunlar sohbet tamamlamaları, `/v1/responses`, `/v1/messages` **ve medya uç noktaları** tarafından yayımlanır — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` ve `/v1/moderations` (maliyet her zaman `0`). Fiyatlandırma mevcut olduğunda medya maliyeti modalite başına (görsel, saniye, karakter veya arama birimi başına) hesaplanır; aksi hâlde `0` olur (hata durumunda izin verilir).

> **Önbellek isabeti maliyet semantiği:** Semantik önbellek İSABETİNDE (`X-OmniRoute-Cache-Hit: true`) yukarı akış çağrısı yapılmaz; bu nedenle `X-OmniRoute-Response-Cost`, `0.0000000000` değerindedir (isabeti sunmanın **artımlı** maliyeti). Orijinal/gerçekleşmiş olacak maliyet ayrıca `X-OmniRoute-Cost-Saved` içinde bildirilir. Faturalandırma tüketicileri `X-OmniRoute-Response-Cost` değerlerini toplamalıdır (isabetlerin maliyeti yoktur); önbellek analitiği ise `X-OmniRoute-Cost-Saved` değerlerini bir araya getirebilir.

## Özel Yönetilen Oturum Kiralamaları

Özel yönetilen oturum kiralama, isteğe bağlı ve istemciden bağımsız bir yönlendirme sözleşmesidir: tek bir etkin sahip, uygun bir OmniRoute bağlantısını elinde tutar. Bir modeli kiralamaz, OAuth gerektirmez, belirli bir istemciyi tanımlamaz veya belirli bir sağlayıcıyı zorunlu kılmaz.

Kimlik doğrulaması yapan API anahtarının `lease:exclusive` kapsamına ve açıkça belirtilmiş, boş olmayan bir `allowedConnections` listesine sahip olması gerekir. Veritabanı mutasyon sınırı, anahtar oluşturma ve kısmi güncellemeler sırasında her iki alanı birlikte zorunlu kılar.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Başarılı edinme, yenileme ve serbest bırakma yanıtları zaman damgalarını, `state` değerini ve pozitif `generation` değerinin aynısını sunar; ancak seçilen bağlantıyı veya kimlik bilgilerini hiçbir zaman sunmaz. Yenileme ve serbest bırakma işlemleri, nesli JSON gövdesinde belirtir:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Etkin bir kiralama sahibi, mevcut bağlaması için gizliliği koruyan görüntüleme meta verilerini açıkça talep edebilir:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Bu isteğe bağlı durum eylemi; opak sahip, kimliği doğrulanmış yönetilen API anahtarı ve etkin neslin tam değeriyle tek bir veritabanı işlemi içinde sınırlandırılır. `displayName` yalnızca baştaki ve sondaki boşlukları kaldırılmış, yapılandırılmış bağlantı adıdır; güvenli bir yapılandırılmış ad mevcut olmadığında `null` olur. OmniRoute hiçbir zaman bunun yerine e-posta veya oluşturulmuş hesap kimliği kullanmaz. Sağlayıcı değeri, hassas olmayan bir görüntüleme etiketidir ve hiçbir zaman oluşturulmuş uyumlu sağlayıcı tanımlayıcısı değildir. Kimlik bilgileri, belirteçler, çerezler, ham bağlantı veya API anahtarı kimlikleri, sahip karmaları, sınırlandırma gizli anahtarları ve dahili yönlendirme verileri hariç tutulur.

Yanlış anahtar, yanlış sahip, eski nesil, eksik, süresi dolmuş, serbest bırakılmış ve geçersiz kılınmış aramaların tümü, bağlantı meta verileri olmadan aynı `409 LEASE_FENCE_STALE` hatasını döndürür. Kapasite bekleme yanıtını alan bir istemcinin incelenebilecek etkin bir bağlaması yoktur. Yönlendirme etkin bir kiralamayı başka bir bağlantıya geçirdiğinde aynı nesil geçerli kalır ve durum işlemi, eski bağlamayı hiçbir zaman döndürmeden yeni bağlamayı atomik olarak döndürür. Edinme, yenileme, serbest bırakma ve bekleme yanıtları önceki biçimlerini koruduğundan mevcut istemciler değişmeden kalır.

Bu sunucu sözleşmesi, standart OpenAI Codex `/status` davranışını değiştirmez. Standart Codex şu anda model sağlayıcısını ve yerleşik kimlik doğrulama/hesap durumunu bildirir ancak isteğe bağlı özel sağlayıcı hesap meta verilerini görüntülemez; gelecekteki bir istemci entegrasyonunun bu eylemi çağırması ve `connection.displayName` değerinin nasıl görüntüleneceğine karar vermesi gerekir.

Bundan sonra yönetilen her çıkarım isteği, her iki kontrol başlığını da sağlar:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Tam sahip, nesil, etkin bağlantı ve kimliği doğrulanmış API anahtarı, desteklenen her yukarı akış denemesinden hemen önce sınırlandırılır. Başka bir anahtarla sahip ve neslin yeniden oynatılması, söz konusu anahtar aynı bağlantıya izin verse bile başarısız olur. Ham sahipler kalıcı olarak saklanmaz, günlüğe kaydedilmez, istek anlık görüntüsünde tutulmaz veya yukarı akışa iletilmez.

Geçici çekişme, `Retry-After` ile birlikte HTTP `429` ve aşağıdaki yanıtı döndürür:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Bu yanıt yalnızca normal uygun kümenin boş olmadığı ve kullanılabilir her adayın yabancı bir etkin kiralama tarafından tutulduğu anlamına gelir. Desteklenmeyen modeller/sağlayıcılar, politika uyuşmazlığı, bekleme süresi, kota, sistem durumu ve diğer normal uygunluk hataları, mevcut OmniRoute yanıtlarını korur.

### `x-omniroute-compression`

Sıkıştırma planının istek bazında geçersiz kılınması. En yüksek önceliğe sahiptir — yönlendirme kombinasyonu geçersiz kılmasını, etkin profili, otomatik tetikleyiciyi ve paneldeki Varsayılanı geçersiz kılar. Değerler:

| Değer         | Etki                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------- |
| `off`         | Bu istek için sıkıştırma uygulanmaz.                                                                          |
| `default`     | Panelden türetilen Varsayılan profil (etkin profili yok sayar). Kayıplı motorlar kapalı bırakılır.            |
| `safe`        | Yalnızca yinelenenleri kaldırma ve boşlukları daraltma.                                                       |
| `allow-lossy` | Özetler ve stil yeniden yazımları dahil olmak üzere operatör planını bu istek için korur.                     |
| `engine:<id>` | Etkinleştirilmişse tek bir motor; ör. `engine:rtk`. Söz konusu motor için istek bazında katılım.              |
| `<combo>`     | Önce ada göre (büyük/küçük harfe duyarsız), ardından kimliğe göre eşleştirilen adlandırılmış bir kombinasyon. |

Notlar:

- Bilinmeyen değerler yok sayılır (istek hiçbir zaman reddedilmez); çözümleme normal operatör önceliğine geri döner.
- Birden fazla kombinasyon aynı adı paylaşıyorsa deterministik bir eşleşme için kombinasyon **kimliğini** iletin.
- Adı `off` veya `default` olan bir kombinasyon adıyla seçilemez (önce bu anahtar sözcükler yorumlanır); böyle bir kombinasyona kimliğiyle başvurun.
- Ana sıkıştırma anahtarı kesin bir geçittir: sıkıştırma genel olarak devre dışı bırakıldığında bu başlık onu etkinleştiremez.

Uygulanan plan, yanıt başlığında geri yansıtılır:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

burada `<source>`; `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` veya `off` değerlerinden biridir.

## Embedding'ler

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Kullanılabilir sağlayıcılar: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Katalog kimlikleri `provider/model` biçimindedir (örnek: `jina-ai/jina-embeddings-v5-omni-small`). Kayıt defterinde bulunan sağlayıcı öneki olmayan Jina model kimlikleri de (örneğin `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) çözümlenir. Jina embed/rerank/classify/segment işlemleri önce kontrol panelindeki `jina-ai` kimlik bilgilerini kullanır; `JINA_AI_API_KEY` yalnızca kontrol paneli anahtarı olmadığında yedek olarak kullanılır. `jina-reader` kartı yalnızca Reader / `r.jina.ai` içindir (`POST /v1/web/fetch`) ve hiçbir zaman embedding veya rerank hizmeti sunmaz.

Çok modlu desteğe sahip olduğunu belirten kayıt defteri modelleri, sağlayıcıdan bağımsız en fazla 32 yapılandırılmış
öğeyi de kabul eder. Medya öğesi türleri `text`, `image`, `audio`, `video` ve `document` şeklindedir. Bunların medya `source`
değeri ya `{"type":"url","url":"https://..."}` ya da
`{"type":"base64","data":"...","media_type":"..."}` biçimindedir.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
ve aile takma adı `jina-ai/jina-embeddings-v5-omni` → omni-small), Jina'nın yerel
EmbeddingsV5Request belgelerini de kabul eder ve bunları **değiştirmeden** `https://api.jina.ai/v1/embeddings` adresine iletir:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Yerel `{ image | audio | video | pdf }` değerleri herkese açık bir HTTPS URL'si, bir `data:` URI'si veya ham
base64 olabilir. OmniRoute bu nesneleri dizeye dönüştürmez veya yerel görüntü URL'lerini getirmez — herkese açık
medyayı Jina'nın kendisi alır. Ek Jina alanları (`task`, `normalized`, `truncate`, `embedding_type`)
iletilir. Yalnızca metin destekleyen Jina SKU'ları metin dışı belgeleri yine reddeder.

Güvenlik ve aktarım sınırları:

- Uzak medya URL'leri herkese açık HTTPS olmalıdır. Standart `{type,source:url}` öğeleri
  sunucu tarafında alınır (yönlendirmelerin yeniden doğrulanması, zaman aşımı, boyut sınırları, herkese açık DNS, bağlantı sabitleme) ve
  sağlayıcı çağrısından önce satır içine gömülür. Jina'ya özgü `{image:"https://..."}` öğeleri, aynı herkese açık HTTPS
  kontrolünden sonra olduğu gibi iletilir; URL'yi Jina alır.
- Satır içi base64 medyası, öğe başına çözülmüş olarak 8 MiB ve istek genelinde çözülmüş olarak 16 MiB ile sınırlıdır.

Sağlayıcıya dönüştürme (standart öğeler hiçbir zaman değiştirilmeden iletilmez):

- Jina çok modlu modelleri: her üst düzey öğe, satır içi medya için veri URI'leri kullanılarak
  modalite anahtarlı tek bir nesneye (`text` / `image` / `audio` / `video` / `pdf`) dönüşür; her
  üst düzey öğe için bir vektör oluşturulur.
- Gemini Embedding 2 ailesi: üst düzey tek bir dizi, `content.parts` (`text` veya `inline_data`) içeren tek bir yerel
  `models/{model}:embedContent` isteğine dönüşür.
- llama.cpp (`llama-cpp/<model>`, yerel sunucunun yüklediği herhangi bir model): standart `text` öğeleri
  düz dizelere dönüşür; `image` / `audio` / `video` öğelerinin her biri ise satır içi verilerle llama-server'ın sohbet içerik parçalarını (`image_url`,
  `input_audio` ve `wav` / `mp3` / `flac` biçimi, `input_video`) kullanan tek bir
  `{"content": [part]}` nesnesine dönüşür; her üst düzey öğe için bir vektör oluşturulur. Sunucu `--embedding --mmproj …` ile
  çalıştırılmalıdır; projektör olmadığında medyayı sunucunun kendisi reddeder. `document` desteklenmez.
- Açık modalite meta verileri olmayan, bilinmeyen/dinamik modeller yapılandırılmış girdiyi HTTP 400 ile reddeder.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Desteklenmeyen model/modalite kombinasyonları, öğeyi zorla dönüştürmek yerine HTTP 400 döndürür. Eski dize/token
isteklerindeki girdi dışı uzantı alanları değişiklik yapılmadan aktarılmaya devam eder.

```bash
# Tüm embedding modellerini listele
GET /v1/embeddings
```

## Görüntü Oluşturma

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Kullanılabilir sağlayıcılar arasında OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (yerel) ve ComfyUI (yerel) bulunur.

`n`, `data[]` içinde `n` adet görüntü döndürür. Üst API'si çağrı başına tek bir görüntü döndüren sağlayıcılar
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI) için, aynı anda en fazla 4 çağrı yürütülecek şekilde `n` ayrı üst API çağrısı yapılır. Sabit bir
`seed`, çağrı indeksine göre artırılır (`seed`, `seed + 1`, …); böylece görüntüler farklı olurken
yeniden üretilebilirlik korunur. `n` en fazla 10 olabilir. Çağrılardan herhangi biri başarısız olursa isteğin
tamamı başarısız olur. Dağıtımlı çağrı biçimlerinin listesi
`open-sse/handlers/imageGeneration/fanOut.ts` içindeki `SINGLE_IMAGE_FANOUT_FORMATS` sabitinde bulunur.

ZenMux, mevcut API anahtarı bağlantısını yeniden kullanır ve `zenmux/` veya `zm/` öneklerini kabul eder:

- `zenmux/openai/gpt-image-2`, ZenMux'ın OpenAI Images API'sini kullanır. Seçenekler arasında `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` ve `response_format` bulunur.
- `zm/meta/muse-image-1.0` gibi diğer yayıncılar, ZenMux'ın Vertex AI `:predict`
  uç noktasını kullanır. `n`, `sampleCount` alanına; `aspect_ratio`, `aspectRatio` alanına; `image_size`
  (`1K`, `2K`, `4K`) ise `sampleImageSize` alanına eşlenir. Piksel cinsinden bir `size`, yalnızca en-boy oranını
  belirler; piksel boyutları garanti edilmez. Desteklenen oranlar, çözünürlükler ve adetler modele göre değişir.
- `zm/inclusionai/ming-image-0.1-design` kendi boyutlarını seçer. `size`,
  `aspect_ratio` ve `image_size` alanlarını atlayın; açıkça belirtilen değerler HTTP 400 döndürür. PNG, JPEG ve WebP
  biçimleri `output_format` ile istenebilir.

Bu entegrasyon, referans görüntü düzenlemeyi değil, metinden görüntü oluşturmayı destekler. Vertex
çıktısı `data[].b64_json` biçimine normalleştirilir; `response_format: "url"`, yalnızca görüntü baytlarının
mevcut olduğu durumlarda üst API'den gelen bir HTTPS URL'si veya base64 veri URL'si döndürür. Boş/filtrelenmiş çıktılar,
boş bir başarılı yanıt yerine hata döndürür. Model erişimi ZenMux hesabına bağlıdır.
Bkz. [ZenMux Vertex API'si](https://docs.zenmux.ai/api/vertexai/generate-images) ve
[OpenAI Images API'si](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# Tüm görüntü modellerini listele
GET /v1/images/generations
```

{
  "model": "mistral/mistral-ocr-latest",

`model`, bir `provider/model` öneki aracılığıyla OCR sağlayıcısını seçer; yalnızca model kimliği (ör.

| ----------------------------- | -------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (veya yalnızca `mistral-ocr-latest`) | Eşzamanlı — yanıt, tek üst API çağrısından doğrudan döndürülür.                                                              |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                       | Eşzamansız üst API (`analyze` + yoklama) — aşağıya bakın.                                                                    |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                           | Eşzamanlı, Vertex AI'ın `openapi/chat/completions` iş ortağı uç noktası üzerinden — kimlik doğrulama/URL için aşağıya bakın. |

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Azure Document Intelligence yoklama akışı

Azure Document Intelligence'ın `analyze` API'si eşzamansızdır: ilk istek bir gövde yerine
`Operation-Location` üst bilgisi döndürür ve sonuç için yoklama yapılması gerekir. İşleyici
(`open-sse/handlers/ocr.ts`), bu URL'yi en fazla 30 deneme boyunca her saniye yoklar; `ok` olmayan bir
yoklama yanıtında veya `"failed"` durumunda hemen başarısız olur (yoklamayı sürdürmez) ve deneme
hakkı tükendikten sonra işlem hâlâ çalışıyorsa `504` döndürür. Son Azure yanıtı, çağırana döndürülmeden
önce Mistral tarafından kullanılan aynı `pages`/`markdown` biçimine normalleştirilir; böylece istemci
kodunun sağlayıcıya özel işlem yapması gerekmez.

### Vertex AI DeepSeek OCR kimlik doğrulaması ve uç nokta çözümlemesi

`vertex-deepseek-ocr`, OmniRoute'un sohbet/görüntü trafiği için hâlihazırda desteklediği aynı Vertex AI
kimlik doğrulamasını (`open-sse/executors/vertex.ts`) yeniden kullanır: bağlantının API anahtarı, ya
JWT taşıyıcı akışı aracılığıyla kısa ömürlü bir OAuth erişim belirteciyle değiştirilen bir Hizmet Hesabı
JSON kimlik bilgisidir ya da olduğu gibi kullanılan, önceden oluşturulmuş bir OAuth erişim belirtecidir. Üst API
uç noktası URL'si, bağlantının projesi ve bölgesi kullanılarak oluşturulan Vertex'ın genel
`openapi/chat/completions` iş ortağı uç noktasıdır — açıkça belirtilmiş bir `providerSpecificData.project`/`providerSpecificData.region`
her zaman önceliklidir; aksi takdirde proje, Hizmet Hesabı JSON'undaki `project_id` alanından türetilir ve bölge
varsayılan olarak `us-central1` olur. Her iki çözümleme de `open-sse/handlers/ocr.ts` içinde
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) gerçekleştirilir ve `handleOcr` işlevine
gönderilmeden önce `src/app/api/v1/ocr/route.ts` tarafından kullanılır.

### Model fiyatları (`pricing`)

OmniRoute modelin fiyatını bildiğinde, bir giriş `pricing` nesnesi içerir. Fiyat, maliyet muhasebesinin kullandığı fiyatlandırma tablosundan gelir: yerleşik varsayılanlar, senkronize edilmiş fiyatlar ve `/api/pricing` üzerinden ayarlanan geçersiz kılmalar. Bunlar liste fiyatlarıdır; dolayısıyla abonelik sağlayıcıları da token başına fiyat gösterir.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Alanlar                                                         | Birim                           | Notlar                                                                                                                                                              |
| --------------------------------------------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | Token başına USD, ondalık dize  | OpenRouter uyumludur, hiçbir zaman üstel gösterimde değildir. İki önbellek alanı yalnızca bir önbellek fiyatı olduğunda görünür.                                    |
| `input`, `output`, `cached`, `cache_creation`                   | 1 milyon token başına USD, sayı | Önceki katalog sürümlerinden kalan ve mevcut istemciler için korunan alanlar. Fiyatlandırma satırında mevcut olduklarında `reasoning` ve `long_context` da görünür. |

- **Kombinasyonlar**, görünür ilk hedeflerinin fiyatını taşır. Yerleşik `auto/*` kombinasyonları çalışma zamanında bir hedef seçtiğinden `pricing` içermez.
- **Ücretsiz modeller**, fiyatları sıfır olduğunda `"0"` (ve `0`) gösterir. Fiyatlandırma satırı olmayan bir model de katalog onu ücretsiz olarak işaretlediğinde (`free: true`) veya yerleşik ücretsiz model kataloğu onu listelediğinde `"0"` gösterir.
- **Bilinmeyen fiyat:** Girişte `pricing` anahtarı bulunmaz.
- **Kredi bazında ücretlendiren sağlayıcılar** (Kiro gibi), token başına değil istek başına faturalandırır. Bunların girişleri, daha önce sahip oldukları 1 milyon başına sayısal alanları korur ve token başına dize alanlarını içermez.
- **Varyantlar** (reasoning-effort kimlikleri, no-thinking takma adları, keşif ve ağ geçidi yansımaları), yönlendirdikleri modelin fiyatını kopyalar.
- Alanlar yalnızca temel ücretleri içerir. Uzun bağlam katmanları (sayısal `long_context` alanı) ve hizmet katmanı çarpanları (örneğin Codex fast veya flex), `prompt` ya da `completion` değerini değiştirmez.
- Nesne, `x-api-key` ve `anthropic-version` kullanan Anthropic tarzı bir istek de dahil olmak üzere her kimlik doğrulama biçimi için aynıdır (yanıt `{ "object": "list",
"data": [...] }` olarak kalır). Uygulama: `src/app/api/v1/models/catalogPricing.ts`.

### Model kimliği önekleri (`?prefix=`)

Çoğu model bir **sağlayıcı öneki** altında sunulur. Hangi öneki alacağınız `MODELS_CATALOG_PREFIX_MODE` özellik bayrağı tarafından belirlenir ve bir sorgu parametresiyle **her istek için** geçersiz kılınabilir. Bu, sunucu genelindeki ayarı diğer herkes için değiştirmeden temiz bir liste isteyen istemciler açısından kullanışlıdır:

```bash
GET /v1/models?prefix=alias        # model başına bir kimlik — kısa takma ad öneki
GET /v1/models?prefix=dual         # her iki biçim (sunucu varsayılanı)
GET /v1/models?prefix=canonical    # yalnızca tam sağlayıcı kimliği öneki
```

| Mod         | Üretilen                                                 | Notlar                                                                                                                                                                                                         |
| ----------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **ve** `claude/claude-sonnet-4-6` | **Varsayılan.** Her iki kimlik de aynı modele yönlendirilir; iki biçimden birini sabit kodlamış istemci yapılandırmalarının çalışmaya devam etmesi için korunur. Katalog boyutunu yaklaşık iki katına çıkarır. |
| `alias`     | `cc/claude-sonnet-4-6`                                   | Model başına bir giriş. Ayrı bir takma adı olmayan sağlayıcılar da girişlerini üretmeye devam eder; dolayısıyla hiçbir şey kaybolmaz.                                                                          |
| `canonical` | `claude/claude-sonnet-4-6`                               | Tam sağlayıcı kimliği öneki altında model başına bir giriş. Ayrı bir takma adı olmayan sağlayıcılar (ör. `antigravity/…`, `agy/…`) da burada tek kimliklerini üretir; dolayısıyla hiçbir şey kaybolmaz.        |

`dual` modundaki bir yansıma, sorgu parametresi olmadan da tanınabilir: birincil kimliği gösteren bir `parent` alanı taşır.

Model seçici oluşturan istemciler `?prefix=alias` istemelidir; [OmniCopilot VS Code uzantısı](../guides/VSCODE-COPILOT.md) bunu yapar.

### Keşif filtreleri (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models`, isteğe bağlı keşif filtrelerini kabul eder. Bunların hiçbiri kullanılmadığında yanıt değişmez. Bu filtreler, çağıranın zaten gördüğü kataloğu daraltır (önce API anahtarı izinleri uygulanır) ve OpenAI tarzı `limit` / `after` sayfalandırmasından önce çalışır:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # listelenen her yetenek doğru olmalıdır
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # katalog `type`; bu alanı olmayan satırlar `chat` kabul edilir
GET /v1/models?q=sonnet&limit=10                           # kimlik veya ad üzerinde büyük/küçük harfe duyarsız eşleşme
```

| Parametre     | Değerler                                                                                            |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | negatif olmayan tam sayı, `context_length` ile karşılaştırılır                                      |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 karakter                                                                                      |

Bilinmeyen bir değer veya negatif olmayan bir tam sayı olmayan bir `min_context` (örneğin `1.5`),
HTTP `400` döndürür ve mesaj geçerli değerleri listeler. Uygulama:
`src/app/api/v1/models/catalogFilters.ts`.

### Kısa model listesi (`POST /v1/models/query`)

`POST /v1/models/query`, `GET /v1/models` ile aynı katalogdan, aynı kimlik doğrulama ve anahtar
başına görünürlük kurallarıyla kısa ve deterministik bir liste döndürür:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Her alan isteğe bağlıdır. `capabilities` ve `exclude`, bir dizi veya virgülle ayrılmış bir dize
kabul eder; `max_output`, `max_output_tokens` ile karşılaştırılır. Sonuçlar önce `owned_by`,
ardından `id` değerine göre sıralanır. `limit` varsayılan olarak `20` değerini alır ve `100`
üzerindeki değerler `100` ile sınırlandırılır. Geçersiz JSON, bilinmeyen bir alan veya geçersiz
bir değer HTTP `400` döndürür.

### Ayrı ayrı gizlenen sohbet modelleri

Sağlayıcı sayfasında **Gizli** olarak işaretlenen bir model katalogdan çıkarılır ve açıkça
istendiğinde HTTP `404` / `model_not_found` ile reddedilir. Kontrol; sağlayıcı takma adları,
uyumlu sağlayıcı düğüm ön ekleri ve bağlantı varsayılanları dâhil olmak üzere çözümlenmiş
sağlayıcıyı ve modeli kullanır. Bir kombinasyon, gizli hedefleri atlar ve görünür bir eş modeli
kullanabilir; çalıştırılabilir bir hedef kalmadığında aynı hata kodunu döndürür. Gizliliğin
kaldırılması bir sonraki istekte geçerli olur. Yalnızca görüntüye yönelik görünürlük geçersiz
kılmaları, aynı ID'ye sahip sohbet modelini gizlemez.

Bu ayrı model ayarı, açık gönderimi korurken katalogda gösterimi ve otomatik yönlendirme
adaylarını filtreleyen [model gösterimi izin/ret listelerinden](../routing/MODEL_EXPOSURE_LIST.md)
ayrıdır. API anahtarı model izinleri bağımsız olarak uygulanmaya devam eder. Varsayılan katalog
ön ek modu `dual` olarak kalır.

### Düşünmesiz model varyantları

Düşünme yeteneğine sahip Claude modelleri için `/v1/models`, kimliği `claude-3-omniroute-no-thinking/` ön ekiyle başlayan bir **düşünmesiz** varyantı da gösterir:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Bu kimliğin seçilmesi (ör. her zaman bir `thinking` bloğu ekleyen Claude Code yapılandırmasında), muhakeme engellenmiş şekilde gerçek `<provider>/<model>` modeline geri çözümlenir — `/v1/messages` yolunda `thinking:{type:"disabled"}` kullanılır veya `/v1/chat/completions` yolunda `reasoning`/`reasoning_effort` alanları kaldırılır. Varyant yalnızca düşünmeyi destekleyen **ve** `disabled` değerine uyan Claude ailesi modelleri için listelenir (dolayısıyla, örneğin `disabled` değerini reddeden yalnızca uyarlamalı modeller hariç tutulur). Operatörler, `ModelSpec.noThinkingAlias` aracılığıyla varyantı model bazında etkinleştirmeye veya devre dışı bırakmaya zorlayabilir.

## ElevenLabs ses oluşturma

OmniRoute'ta ElevenLabs API anahtarınızla bir `elevenlabs` sağlayıcı bağlantısı yapılandırın. İstemciler **OmniRoute** anahtarlarıyla (`Authorization: Bearer $OMNIROUTE_API_KEY`) kimlik doğrulaması yapar; ağ geçidi, depolanan sağlayıcı anahtarını `xi-api-key` olarak iletir. ElevenLabs anahtarını hiçbir zaman ağ geçidi bearer belirteci olarak göndermeyin.

| Yöntem | Yol                         | Yanıt                                      | API anahtarı uç nokta kategorisi |
| ------ | --------------------------- | ------------------------------------------ | -------------------------------- |
| POST   | `/v1/sound-generation`      | Yerel ses baytları                         | `elevenlabs`                     |
| POST   | `/v1/music`                 | Yerel ses baytları                         | `music`                          |
| POST   | `/v1/music/stream`          | Akış halinde ses baytları                  | `music`                          |
| POST   | `/v1/music/detailed`        | Yerel çok parçalı ses ve kompozisyon planı | `music`                          |
| POST   | `/v1/music/detailed/stream` | Yerel SSE meta verileri ve ses parçaları   | `music`                          |
| POST   | `/v1/music/plan`            | JSON kompozisyon planı                     | `music`                          |

Bu uç noktalar mevcut `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/voices`, `/v1/text-to-speech/{voiceId}` ve `/v1/speech-to-text` rotalarını tamamlar. `output_format` ve `enable_logging` gibi yerel JSON alanları ve sorgu parametreleri korunur. `/v1/music/detailed` yanıtları çok parçalı sınırlarını korur; bunları çok parçalı olarak ayrıştırın. `/v1/music/detailed/stream`, kompozisyon meta verileri ve SSE olaylarında base64 ses parçaları içeren `text/event-stream` döndürür. Altı rotanın tamamı CORS ön kontrolünü destekler.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Kısa bir ses efekti. Süre: 0,5 ile 30 saniye.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Müzik süresi milisaniye cinsinden ifade edilir: 3000 ile 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Artımlı ses iletimi için aynı JSON gövdesiyle `/v1/music/stream` kullanın. Kompozisyon, `prompt` veya `composition_plan` alanlarından tam olarak birini kabul eder; `/v1/music/plan`, `prompt` alanını gerektirir ve isteğe bağlı olarak `source_composition_plan` alanını kabul eder. Yerel şemalar ek sağlayıcı alanlarını korur; böylece kompozisyon planı sürümleri ve ince ayar seçenekleri ElevenLabs'e ulaşır.

Birleşik `/v1/music/generations` uç noktası ayrıca `elevenlabs/music_v1`, `elevenlabs/music_v2` ve `elevenlabs/music_v2_5` modellerini kabul eder. Etkin bir ElevenLabs bağlantısı olduğunda bu modeller müzik kataloğunda sunulur. Bu uç nokta `{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}` döndürür. `duration` alanı saniye cinsindedir ve `music_length_ms` alanına eşlenir; açıkça belirtilen bir `music_length_ms` değeri önceliklidir. `instrumental`, `force_instrumental` alanına eşlenir ve yerel alan önceliklidir. Akış için yerel akış uç noktalarını, yalnızca bir kompozisyon planına dayalı istekler içinse yerel kompozisyon uç noktasını kullanın.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Uç nokta, model, bütçe ve bağlantı kısıtlamaları, üst hizmet çağrısından önce uygulanır. Yerel rotalar, bir plan kısıtlaması için `402` ve bir kota sınırı için `429` dahil olmak üzere üst hizmet durum kodlarını ve hata gövdelerini değiştirmeden döndürür. Mevcut olduklarında `character-cost`, `song-id`, `request-id` ve `retry-after` başlıkları korunur. Ücretsiz kredi bakiyesi, her müzik modeline, çıktı biçimine veya API özelliğine erişimi garanti etmez: ElevenLabs, her istek için yetkilendirmeye karar verir. Birleşik uç nokta, OmniRoute'un normalleştirilmiş hata zarfındaki hata durum kodlarını korur.

Üst hizmet sözleşmeleri: [ses efektleri](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert), [müzik kompozisyonu](https://elevenlabs.io/docs/api-reference/music/compose) ve [akışlı müzik ayrıntıları](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> **Yeniden sıralama sağlayıcı düğümleri:** `POST /v1/rerank`, `<node-prefix>/<model>` olarak adreslenen
> OpenAI uyumlu sağlayıcı düğümlerine (oMLX, vLLM, Infinity, bir ağ geçidinin arkasındaki TEI, …) de yönlendirilir.
> Geri döngü düğümleri (`localhost`, `127.0.0.1`, `172.16.0.0/12`) her zaman uygundur; operatörün
> `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` içinde listelediği ana bilgisayar adları da uygundur (ör. `http://reranker:8080/v1`
> gibi bir Docker/Compose hizmet adı; bunlar hiçbir zaman `HTTP(S)_PROXY` veya bir bağlantının sabitlenmiş
> proxy'si üzerinden değil, doğrudan çağrılır). Başka herhangi bir
> ana bilgisayardaki düğümler — bir LAN makinesi veya Tailscale eş düğümü — yalnızca operatör
> `RERANK_REMOTE_PROVIDER_NODES` özellik bayrağını etkinleştirdiğinde **ve** düğümün temel URL'si sağlayıcının
> giden URL politikasını (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`) geçtiğinde uygundur.
> Bellek motorunun yeniden sıralama adımı bu rotayı
> geri döngü üzerinden çağırdığından, Bellek ayarlarındaki `rerankProviderModel` için de aynı kural geçerlidir.
>
> **Yerel sunucu biçimleri:** düğüm önce `<base>/v1/rerank`, 404 durumunda ise `<base>/rerank`
> (Infinity, TEI) üzerinden çağrılır. Yukarı akış gövdesi hem Cohere/OpenAI yazımını (`documents`,
> `return_documents`) hem de TEI yazımını (`texts`, `return_text`) taşır ve yukarı akış yanıtı
> Cohere zarfına normalleştirilir: TEI'nin yalın `[{index, score, text}]` biçimi, ince ağ geçitlerinden gelen
> `{results: [{index, score}]}` ve Voyage tarzı `{data: [...]}`, istemciye
> `{results: [{index, relevance_score, document?}]}` olarak, puana göre sıralanmış ve `top_n` ile sınırlandırılmış biçimde döner.

> **Sağlayıcı düğümü keşfi:** OpenAI uyumlu bir sağlayıcı düğümündeki modeller, düğüm öneki altında `GET /v1/models`
> içinde görünür. Uç nokta meta verisi taşımayan satırlar (yerel `/v1/models` listelerinde tipik olduğu üzere)
> düğümün `apiType` değerini devralır; böylece bir `embeddings` düğümünün modelleri varsayılan olarak sohbet türüne atanmak yerine
> `type: "embedding"`, bir `rerank` düğümünün modelleri ise `type: "rerank"` olur; eşitlenmiş veya elle eklenmiş bir satırdaki açık
> `supportedEndpoints` yine önceliklidir.

### Exa ve Tavily `provider_options`

Exa ve Tavily, sağlayıcıya özel alanları ad alanlı bir paketten okur: `provider_options.exa` (veya `provider_options["exa-search"]`) ve `provider_options.tavily` (veya `provider_options["tavily-search"]`). Yalnızca aşağıdaki anahtarlar iletilir. Her biri `open-sse/handlers/search/providerOptionsPassthrough.ts` içindeki kendi Zod şemasına göre kontrol edilir ve yanlış türde bir anahtar bırakılır. Auth, base URL, `stream` ve `outputSchema` dahil diğer anahtarlar göz ardı edilir. Diğer sağlayıcılar tarafından kullanılan düz tuşlar (`cx`, `depth`, ...) daha önce olduğu gibi çalışır.

| sağlayıcı | Üst düzey alanlar                                                                                                                                                                                                                                                                                                                                                         | Yuvalanmış                                                                                                                                          |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa       | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (düz temeller), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                                 | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` varsayılan `{ text: true, highlights: true }` üzerinden birleştirildi |
| Tavily    | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                   |

Genel alanlar her zaman kazanır: `query`, `max_results`, `filters` (domainler), `country` ve `search_type` türetilen konu. Exa'da `search_type: "news"`, `category: "news"` değerini korur. Tavily ayrıca `search_type: "finance"` (`topic: "finance"`) de kabul eder.

Firecrawl arama maliyeti, döndürülen 10 sonuçtan oluşan başlatılan blok başına, blok başına 0,002 USD (2 kredi) ve çağrı başına en az bir blok ( [Firecrawl faturalandırması](https://docs.firecrawl.dev/billing) ) olarak kaydedilir: 11 sonucun maliyeti 0,004 USD'dir.

Jenerik `time_range` artık her iki sağlayıcıya da ulaşıyor: Exa `startPublishedDate` (ISO zaman damgası) alıyor ve Tavily `start_date` (`YYYY-MM-DD`) alıyor. `provider_options` açık bir tarih, eşlenen tarihi geçersiz kılar.

Exa sonuçları `id`, `highlight_scores`, `summary`, `subpages`, `entities` ve `extras` `provider_raw` tutar. Tavily sonuçları `images` ve `favicon` korur.

`depth` `provider_options` veya bağlantı ayarlarından gelmesine bakılmaksızın, bağlantı arama maliyeti `depth` `fast` ve `standard` için 0,005 ABD doları ve `deep` ( [Bağlantı fiyatlandırması](https://docs.linkup.so/pages/documentation/development/pricing) ) için 0,05 ABD doları olarak kaydedilir.

Exa `type: "lite"` (Exa 3.0) daha küçük bir alan kümesini kabul eder ve başka bir alan ayarlandığında isteğin tamamını reddeder. Lite için `additionalQueries`, `systemPrompt` ve `text` ile `highlights` dışındaki tüm `contents` tuşları çağrıdan önce bırakılır. Kullanımdan kaldırılan `subpages`, `subpageTarget`, `highlights.numSentences` ve `highlights.highlightsPerUrl` artık iletilmiyor.

Maliyet muhasebesi, Exa hariç, Exa'nın kendi fiyatlandırmasını izleyen düz kayıt `costPerQuery`: 10 sonucu kapsayan `auto` (ve eski `fast`) için çağrı başına 0,007 ABD doları veya `lite` (ve eski `instant`) için 0,004 ABD doları; Sonraki her sonuç için 0,001 ABD doları; ve `contents.summary` ayarlandığında döndürülen sonuç başına 0,001 ABD doları. Tavily `search_depth` `basic`, `fast` ve `ultra-fast` için 1 kredi (0,008 ABD doları) ve `advanced` ( [Tavily API kredileri](https://docs.tavily.com/documentation/api-credits) ) için 2 kredi (0,016 ABD doları) olarak kaydedilmiştir. Tavily'nin gelişmiş seviyeye yükselttiği `auto_parameters: true` ile yapılan bir çağrı hâlâ 1 kredi olarak kaydediliyor.

## Web Fetch API

Yapılandırılmış bir web-fetch sağlayıcısı (Firecrawl, Jina Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract) aracılığıyla bir URL'den içerik çıkarın.

Parallel Extract (`parallel-search`, Parallel Search ile aynı API anahtarı) yalnızca Markdown döndürür — diğer tüm `format` değerleri `400` sonucunu verir — ve içeriği 100.000 karakterle sınırlar. Hedef sayfanın kendisi çıkarılamadığında üst sağlayıcı bunu HTTP 200 yanıtı içinde bildirir; OmniRoute bunu sabit bir mesajla `422` olarak sunar.

| Yöntem | Yol             | Açıklama                                                        |
| ------ | --------------- | --------------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Bir URL'yi getir/tara — gövde `v1WebFetchSchema` ile doğrulanır |

**Kimlik doğrulama:** Bearer API anahtarı (`extractApiKey` + `isValidApiKey`). Politika `enforceApiKeyPolicy` aracılığıyla uygulanır.

**Kota duyarlı geri dönüş (#8297):** açıkça bir `provider` belirtilmediğinde havuz
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) sabit
öncelik sırasıyla (önce doldurma) dolaşılır — hız sınırına takılmış ancak yapılandırılmış bir sağlayıcı,
isteğin kısa devreyle sonlandırılması yerine atlanır ve yeniden denenebilir/kota kaynaklı bir üst sağlayıcı hatası
(HTTP 429 her zaman; Firecrawl/Tavily/TinyFish'in kota türündeki ücretsiz katmanları için 402/403 —
Jina Reader için değil ve sıradan bir 400 hatalı istek için hiçbir zaman değil) istek sırasında
henüz denenmemiş ve kimlik bilgileri bulunan bir sonraki sağlayıcıya geçer. Havuzdaki tüm sağlayıcılar
tükendiğinde uç nokta, önceki genel `400` yerine tek bir `429` (`Retry-After`
üst bilgisiyle) döndürür. Açıkça bir `provider` istendiğinde **sessiz geri dönüş yoktur** — hız sınırına
takılan veya başarısız olan açık sağlayıcı kendi hatasını sunar (hız sınırına takılmışsa `429`, aksi takdirde
üst sağlayıcının durumu).

## WebSocket Akışı

```bash
GET /v1/ws?handshake=1
```

Bir WebSocket yükseltme el sıkışmasını doğrular ve kablo protokolü örnek mesajlarını (`request`, `cancel`) döndürür. Gerçek WS çerçeveleri, Next.js yönlendirme tablosunun dışında paketlenmiş WS sunucusu tarafından işlenir.

**Kimlik doğrulama:** El sıkışma sırasında Bearer API anahtarı.

### WebSocket üzerinden Responses API (yalnızca codex)

```bash
# HTTP API ile aynı ana makine:bağlantı noktası (varsayılan 20128); bağlantıyı yükseltin:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (veya: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# İlk çerçeve response.create OLMALIDIR:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

WebSocket üzerinden Responses API proxy'si **yalnızca `codex` için** (ChatGPT
arka ucu) bağlanmıştır. API/pano ile aynı bağlantı noktasında `/v1/responses`,
`/responses` ve `/api/v1/responses` yollarını dinler. İlk `response.create` çerçevesinde
dahili `codex-responses-ws` köprüsü aracılığıyla kimlik doğrulaması ve hazırlık yapar, bir
codex OAuth bağlantısı seçer ve `wreq-js` aktarımı aracılığıyla
`wss://chatgpt.com/backend-api/codex/responses` adresine tünel oluşturur.
**Codex dışındaki modeller reddedilir** (`codex_ws_provider_required`).
Kota paylaşımı yönlendirmesi için `model: "qtSd/<group>/codex/<model>"` kullanın. Uygulama
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts` içinde yer alır.

**Kimlik doğrulama:** El sıkışma sırasında Bearer API anahtarı. Paketlenmiş HTTP sunucusu (`server-ws.mjs`)
etkin giriş noktası olmalıdır (`app/server-ws.mjs` mevcut olduğunda varsayılan olarak etkindir).

#### Model kimliği: yalnızca ChatGPT kimliğini kullanın (`codex/` ön eki olmadan)

OpenAI **Codex CLI**, `supports_websockets = true` olduğunda model adını istemci tarafında
doğrular ve `codex/gpt-5.5` gibi **sağlayıcı ön ekli kimlikleri reddeder**
(`The 'codex/gpt-5.5' model is not supported when using Codex with a ChatGPT account`).
**Yalnızca** kimliği gönderin (ör. `gpt-5.5`). OmniRoute'un köprüsü yalnızca codex içindir;
bu nedenle üst sağlayıcıya tünellemeden önce yalnızca bir kimliği codex modeli olarak
(`resolveCodexWsModelInfo`) yeniden çözümler — yalnızca `gpt-5.5` normalde HTTP üzerinden
başka bir sağlayıcıya yönlendirilecek olsa bile.

#### OpenAI Codex CLI'ı yapılandırma

Codex CLI'ı OmniRoute'a yönlendirmek için `~/.codex/config.toml` dosyasına WebSocket
destekli özel bir sağlayıcı ekleyin (mevcut bir yapılandırmaya dokunmamak için ayrı bir
`CODEX_HOME` kullanın):

```toml
model = "gpt-5.5"                 # yalnızca kimlik — "codex/gpt-5.5" DEĞİL
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # sonunda eğik çizgi yoktur; WS URL'si türetilir (üretimde https/wss kullanın)
wire_api = "responses"                    # Şubat 2026'dan beri desteklenen tek değer
supports_websockets = true                # Responses-over-WS aktarımını etkinleştirir
env_key = "OMNIROUTE_API_KEY"             # OmniRoute API anahtarını içerir (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # bir OmniRoute API anahtarı (REQUIRE_API_KEY=false ise herhangi bir anahtar)
codex exec "Responda apenas: PONG"
```

CLI, `base_url + /responses` adresini bir WebSocket'e yükseltir ve OmniRoute bunu
seçilen codex OAuth bağlantısına tüneller. Yerel sunucuda uçtan uca doğrulanmıştır:
ChatGPT `codex.rate_limits` + `response.created` döndürür ve tamamlamayı akış halinde iletir.

## Self servis kullanım (`/api/usage/om-usage`)

Herhangi bir API anahtarı, yönetim kimlik doğrulaması olmadan **kendi** kullanımını ve kotalarını okuyabilir. Bu, bir
istemcinin (CLI, OmniCopilot paneli) anahtar sahibine harcamasını göstermek için kullandığı uç noktadır.

```bash
# Metin biçimi (geçmişten gelen sözleşme — terminal için düz metin)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Yapılandırılmış biçim — bir kullanıcı arayüzünün kullandığı biçim
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Anahtarda **`allowUsageCommand`** etkinleştirilmiş olmalıdır (varsayılan olarak kapalıdır — kontrol panelinin API anahtarı
yöneticisi bunu her anahtar için ayrı ayrı açıp kapatır). Bu özellik olmadan uç nokta `403` yanıtını verir.

`?format=json`, çağıranın bir ret yanıtından veri alanı okumaması için ayırt edilebilir bir yapı döndürür.
Başarı durumunda:

```jsonc
{
  "allowed": true,
  // yalnızca anahtar günlük/haftalık USD cinsinden anahtar başına kullanım sınırlarını etkinleştirdiğinde bulunur:
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // seçilen sağlayıcının kota anlık görüntüsü veya henüz hiçbir şey önbelleğe alınmamışsa null:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // kullanıcı arayüzünün birden fazla sağlayıcıyı yan yana görüntüleyebilmesi için her bağlantının anlık görüntüsü:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Ret durumunda (`401` hatalı anahtar / `403` izin verilmedi) aynı rota
`{ "allowed": false, "error": { "message": "…" } }` döndürür — mevcut ancak boş bir `personal`/`provider`
(anahtara izin verilmiş ancak henüz bilgi edinilmemiştir), ret durumundan farklıdır ve yalnızca JSON biçimi
bu durumları birbirinden ayırır.

**Kimlik doğrulama:** Çağıranın kendi Bearer API anahtarı, `isValidApiKey` ile doğrulanır — bu, yönetim
yüzeyi (`/api/keys/…`) _değildir_; yönetim yüzeyi `requireManagementAuth` ile korunmaya devam eder.

### Ham ve Kesme Noktasına Göre Ayarlanmış Kota Yüzdeleri

Çağıranlar, `/api/usage/om-usage` kullanırken **düz metin çıktısında** ve yapılandırılmış
**JSON çıktısında** sunulan yüzdeler arasındaki ayrıma dikkat etmelidir:

| Unsur                 | Düz metin biçimi (`/api/usage/om-usage` / `@@om-usage`)                                       | JSON biçimi (`?format=json`)                                                            |
| :-------------------- | :-------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------- |
| **Çıktı alanı**       | `NN% left` (ör. `20% left`)                                                                   | `provider.quotas` / `providers[].quotas`                                                |
| **Ölçüm**             | **Kesme noktasına göre ayarlanmış kullanılabilir pay**: kesme eşiğinin üzerindeki kapasite    | **Ham üst sağlayıcı kotası**: sağlayıcının ayarlanmamış ölçümü                          |
| **Kesme ölçeklemesi** | Korunan rezervin `0% left` olarak görünmesi için `effectiveRemainingPercent()` ile ölçeklenir | Yok (sağlayıcı tarafından bildirilen ham anlık görüntü değerleri)                       |
| **Eşik verileri**     | Görüntülenen yüzdeye dahil edilir                                                             | Bağlantı başına `quotaWindowThresholds` içinde (veya sunucu varsayılanlarında) saklanır |
| **Birincil tüketici** | Etkileşimli CLI'lar, terminal istemleri, insan operatörler                                    | Programatik entegrasyonlar, kontrol panelleri, analizler, faturalandırma izleyicileri   |

#### Kesme Noktası Ayarlama Formülü

OmniRoute, üst sağlayıcı kotasının tükenmesini önlemek için proaktif kota kesme noktalarını destekler (bağlantı
`quotaWindowThresholds`, sağlayıcı varsayılanları veya genel dayanıklılık ayarları aracılığıyla yapılandırılır). Bir kota penceresinde
bir kesme eşiği (ör. `cutoff = 25%`) etkin olduğunda, metin oluşturucu kalan payı şu şekilde hesaplar:

- `remaining <= cutoff` ise: `0%` döndürür.
- `remaining > cutoff` ise: `((remaining - cutoff) / (100 - cutoff)) * 100` döndürür.

Biçimlendirilmiş metin çıktısı bunu en yakın tam sayıya yuvarlar (`Math.round(...)`).

#### Açıklayıcı Örnek

**%60 ham kullanıma** (dolayısıyla **%40 ham kalan kotaya**) ve yapılandırılmış
**%25 kalan kota kesme** eşiğine sahip bir sağlayıcı penceresini ele alalım:

| Gösterim                      | Hesaplama                                          |  Kalan  |              Dolaylı Kullanım              |
| :---------------------------- | :------------------------------------------------- | :-----: | :----------------------------------------: |
| **Ham JSON (`?format=json`)** | Üst sağlayıcı anlık görüntüsü (`quotas[window]`)   | **%40** |                  **%60**                   |
| **Metin biçimi (`NN% left`)** | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **%20** | **%80** (`100 - remaining` hesaplanıyorsa) |

- **Metnin neden %20 kaldığını gösterdiği:** Hesapta kalan %40 fiziksel kotanın %25'i, kesme politikası tarafından
  rezerve edilmiştir. Yönlendirici bu bağlantıya yönlendirmeyi durdurmadan önce çağıranın, kullanılabilir %75'lik kapasiteden
  yalnızca %15'i kalmıştır. Ölçekleme, yönlendirmenin duracağı anda bağlantının tükenme sinyali (`0% left`) vermesini
  sağlar.
- **JSON'ın ham değerleri koruma nedeni:** JSON yükü, harici araçların gerçek üst sağlayıcı kullanımına ve bağlantı düzeyindeki
  `quotaWindowThresholds` verilerine sunucu tarafında kayıplı ölçekleme uygulanmadan erişebilmesi için sağlayıcının tam anlık görüntüsünü (`UsageSnapshot`)
  döndürür.

#### Tüketiciler İçin Geçiş Rehberi

Harici bir entegrasyon (örneğin bir editör eklentisi veya aracı uzantısı) daha önce metin
uç noktasını (`NN% left`) ayrıştırıyor ve kullanılan yüzdeyi `100 - NN` olarak hesaplıyorsa, `?format=json` biçimine geçiş şu anlama gelir:

- Ham JSON değerlerinin okunması, **yukarı akıştaki gerçek tüketimi** yansıtır (yukarıdaki örnekte %60 kullanılmıştır).
- Entegrasyon, metin uç noktasının kullanılabilir kota semantiğini korumak istiyorsa bağlantı düzeyindeki geçersiz kılmalar için `quotaWindowThresholds` kullanarak etkin kalan miktar formülünü istemci tarafında değerlendirebilir.

## Semantik Önbellek

```bash
# Önbellek istatistiklerini al
GET /api/cache/stats

# Tüm önbellekleri temizle
DELETE /api/cache/stats
```

Yanıt örneği:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### Gecikme etkisi

Bir semantik önbellek İSABETİ, yanıtı **üst sağlayıcı çağrısı olmadan**
önbellekten sunar; bu nedenle bildirilen `X-OmniRoute-Response-Latency` değeri
neredeyse sıfırdır (özgün üst sağlayıcı gecikmesinden bağımsız olarak).
Gecikmeye duyarlı istemciler (kıyaslama, p50/p99 izleme) şu
`X-OmniRoute-Cache-Latency` yanıt başlığını kontrol etmelidir:

| Değer       | Anlamı                                                                  |
| ----------- | ----------------------------------------------------------------------- |
| `synthetic` | Yanıt önbellekten sunuldu; gecikme gerçek üst sağlayıcı süresi değildir |
| _(yok)_     | Gerçek üst sağlayıcı çağrısından gelen yanıt                            |

### Anahtar bazında önbelleği atlama

API anahtarları, `cacheDefaultMode` aracılığıyla semantik önbellek okumalarını
devre dışı bırakabilir:

| Değer    | Davranış                                                       |
| -------- | -------------------------------------------------------------- |
| `legacy` | Normal önbellek davranışı (varsayılan)                         |
| `bypass` | Önbellek aramasını tamamen atla; her zaman üst sağlayıcıya git |

Anahtar oluşturulurken (`POST /api/keys`) ayarlayın veya
(`PATCH /api/keys/[id]`) ile güncelleyin:

```json
{ "cacheDefaultMode": "bypass" }
```

### İstek bazında atlama

Herhangi bir istek, anahtar ayarlarından bağımsız olarak önbelleği atlayabilir:

```
X-OmniRoute-No-Cache: true
```

Senkronize/içe aktarılmış modeller için `PUT /api/provider-models`; `provider`, `modelId` ve
`maxOutputTokenOverride` değerlerini kabul eder: pozitif bir tam sayı, manuel çıktı token'ı sınırını
ayarlar ve `null`, varsayılanı geri yüklemek için bu sınırı temizler.
`GET /api/provider-models?provider=<provider>`, özel model satırı olmayan modeller de dâhil olmak
üzere bu değerleri `modelOutputOverrides` içinde döndürür. Geçersiz kılma, çalışma zamanındaki
`max_output_tokens` yeteneğini kullanır ve model yeniden senkronize edildiğinde korunur. OpenAI uyumlu
sağlayıcı sayfası aynı düzenleme/temizleme denetimlerini sunar ve açık görsel desteğine sahip modelleri işaretler.

Özel Chat Completions düğümleri, açık akıl yürütme devre dışı bırakma seçeneklerini yukarı akış
arka ucuna uyarlar. Başarılı bir bağlantı testi, `/models` girdisi tanınan bir `owned_by` değerini
kesin olarak gösteren her bir tam model kimliği için sohbet şablonu denetimlerini otomatik olarak
seçer: `vllm`, `sglang` veya `llamacpp`. Şeffaf OpenAI uyumlu sarmalayıcılar, özgün model girdisini
iç içe bir `openai` nesnesinde koruyabilir; algılama, bu tür en fazla üç zarfı takip eder. Sahiplik
bilgisi eksik, bilinmeyen veya çelişkili olan modeller sıradan OpenAI davranışını korur. Algılama,
mevcut katalog isteğini yeniden kullanır, hiçbir tamamlama token'ı oluşturmaz ve bağlantı uç noktası
değiştiğinde geçersiz kılınır.

Bu meta verileri sunmayan bir arka uç için davranışı sabitlemek üzere mevcut kısmi
sağlayıcı güncelleme API'sini kullanın:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Bu gövdeyi `PUT /api/providers/<connection-id>` ile gönderin. Bu bağlantıda, açıkça belirtilen
`none` akıl yürütme eforu; `chat_template_kwargs.thinking=false` ve
`chat_template_kwargs.enable_thinking=false` olarak gönderilir. Sunucu tarafındaki bir akıl yürütme
kuralı belirli bir eforu zorunlu kılmadığı sürece, açık yerel şablon değerleri belirleyici olmaya devam
eder. Ayar yalnızca özel bir OpenAI uyumlu bağlantı bir Chat Completions gövdesi gönderdiğinde uygulanır;
Responses istekleri ve sıradan sağlayıcılar yerel istek yapılarını korur. Sıradan OpenAI
`reasoning_effort` değerinin doğrudan aktarılmasını zorlamak için `reasoningControl` değerini `openai`
olarak ayarlayın veya otomatik algılamayı kullanmak için bunu atlayın/değerini `null` olarak ayarlayın.

Claude Code otomatik mod sınıflandırıcı istekleri, açık akıl yürütme denetimleri içermediğinde yerel
düşünmeyi varsayılan olarak devre dışı bırakır. Algılama, model adlarını veya tamamlama sınırlarını
değil, Claude biçimindeki isteklerde bulunan sınıflandırıcının sistem işaretçisini kullanır. Açık gövde
denetimleri, desteklenen efor/düşünme başlıkları, yönlendirme kuralları ve çözümlenmiş model eforu
mevcut önceliklerini korur. Her iki sınıflandırıcı aşaması da istemlerini, tamamlama sınırlarını,
durdurma dizilerini ve yukarı akıştan gelen gerçek izin kararlarını korur; ikinci aşama, talep ettiği
görünür akıl yürütmeyi sıradan metin olarak üretmeye devam edebilir.

### Sürüm ve Yayın Kanalı

```bash
GET /api/system/version
```

Yalnızca geri döngü arabiriminden erişilebilen yönetim rotası (yönetici kimlik doğrulaması). Çalışan sürümü, yayımlanmış en son
sürümü ve otomatik güncelleme durumunu döndürür. `releaseChannel` ve `channels` ek
alanlardır (hat 3.8.54); `channel` mevcut anlamını korur — kontrol paneli güncelleyicisinin
kullandığı dağıtım modu (`npm`, `source` veya `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — çalışan derlemenin npm kanalı: `-nightly.*` sürümleri için `nightly`,
  diğer ön sürümler (`-rc.*`, `-beta.*`, `-alpha.*`) için `next`, `channels.latest` sürümünden
  daha eski bir ana sürümün kararlı sürümü için `lts`, aksi takdirde `latest`. Yayımlama sırasında
  npm dist-tag değerini seçen `scripts/release/dist-tag.mjs` ile aynı kurallar geçerlidir.
- `channels` — `npm view omniroute dist-tags` üzerinden (kayıt defteri
  HTTP geri dönüşüyle) alınan her dist-tag'in yayımlanmış en son sürümü; `latest` ile aynı 10 dakikalık TTL kullanılarak önbelleğe alınır. `latest` her zaman bulunur
  (önce `latest` alanına, ardından `"unavailable"` değerine geri döner); `next`, `nightly` ve `lts` yalnızca
  ilgili dist-tag mevcut olduğunda görünür. Bir `Cache-Control: no-cache` isteği her iki sorgulamayı da yeniler.

Kanal modeli (`latest` = 4.0 GA'ya kadar v3, `next` = rc, `nightly` = `develop` derlemeleri,
`lts` = 4.0 GA'dan sonraki v3 yamaları) `docs/ops/RELEASE_STRATEGY.md` içinde açıklanmıştır.

## Ses Transkripsiyonu

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data
```

Yapılandırılmış herhangi bir STT sağlayıcısını kullanarak ses dosyalarını yazıya dönüştürün. İlk yol
segmenti yerel sağlayıcıyı seçer (`openai/…`, `deepgram/…`). Başka bir sağlayıcının modelini
yeniden dışa aktaran ağ geçitleri nitelikli bir kimlik kullanır
(`openrouter/deepgram/nova-3`).

**İstek:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**Yanıt:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**Örnek model kimlikleri:** `openai/whisper-1` (bir OpenAI anahtarı gerektirir),
`openrouter/deepgram/nova-3` (bir OpenRouter anahtarı gerektirir),
`deepgram/nova-3` (yerel bir Deepgram anahtarı gerektirir). Yalın bir
`deepgram/nova-3` isteği OpenRouter'ı **kullanmaz**.

**Desteklenen biçimler:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`.

## Token Sınırları

API anahtarı başına **token** bütçeleri (yukarıdaki USD tabanlı Bütçeden farklıdır). İstek yolu üzerinde doğrudan uygulanır: Bir anahtarın geçerli pencere kullanımı sınırına ulaştığında istekler `429 Too Many Requests` ile reddedilir. Sınırlar belirli bir `model` veya `provider` ile sınırlandırılabilir ya da anahtar genelinde `global` olarak uygulanabilir; bir istekle birden fazla sınır eşleştiğinde en kısıtlayıcı olan geçerli olur.

```bash
# Bir anahtarın token sınırlarını listele (canlı pencere kullanımı dahil)
GET /api/usage/token-limits?apiKeyId=key-123

# Bir token sınırı oluştur veya güncelle
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Bir token sınırını kimliğine göre sil
DELETE /api/usage/token-limits?id=tl-abc
```

> **Şema notları** (`setTokenLimitSchema`): `apiKeyId` ve `scopeType` (`model` | `provider` | `global`) zorunludur. `scopeType`, `global` olmadığı sürece `scopeValue` zorunludur (ör. `model` kapsamı için bir model kimliği, `provider` kapsamı için bir sağlayıcı kimliği). `tokenLimit` pozitif bir tam sayı olmalıdır (dizeden dönüştürülür). İsteğe bağlı: `id` (oluşturmak için dahil etmeyin, güncellemek için sağlayın), `resetInterval` (`daily` | `weekly` | `monthly`, varsayılan `monthly`), `resetTime` (`HH:MM`), `enabled` (varsayılan `true`). `GET` yanıtları her sınırı `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` ve `nextResetAt` ile zenginleştirir. Bu, yönetim sınıfı bir uç noktadır (kimlik doğrulama, authz işlem hattı tarafından merkezi olarak uygulanır).

## İstek İşleme

1. İstemci `/v1/*` adresine istek gönderir
2. Rota işleyicisi `handleChat`, `handleEmbedding`, `handleAudioTranscription` veya `handleImageGeneration` çağrısını yapar
3. Model çözümlenir (doğrudan sağlayıcı/model veya takma ad/kombinasyon)
4. Kimlik bilgileri, hesap kullanılabilirliği filtrelemesiyle yerel veritabanından seçilir
5. Sohbet için: `handleChatCore`, semantik/imza önbelleğini kontrol eder ve kombinasyon sıkıştırma ayarlarını çözümler
6. Etkinleştirildiğinde sağlayıcı biçimine dönüştürmeden önce proaktif sıkıştırma çalıştırılır (`lite`, Caveman, RTK veya yığınlanmış)
7. Sağlayıcı yürütücüsü, yukarı akış isteğini gönderir
8. Yanıt, istemci biçimine geri dönüştürülür (sohbet) veya olduğu gibi döndürülür (gömme/görsel/ses)
9. Kullanım, sıkıştırma analizleri ve istek günlükleri kaydedilir
10. Hata durumunda kombinasyon kurallarına göre yedek seçeneğe geçilir

Tam mimari referansı: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Yönetim Proxy'leri

Sağlayıcılara, hesaplara veya genel olarak atanabilen giden HTTP(S)/SOCKS proxy'leri.

| Yöntem | Yol                                          | Açıklama                                                                                                                                                       |
| ------ | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/v1/management/proxies`                 | Proxy'leri listeler (`?id=` ile bir proxy döndürür; `?id=&where_used=1` ile atama grafiğini döndürür)                                                          |
| POST   | `/api/v1/management/proxies`                 | Proxy oluşturur — gövde `createProxyRegistrySchema` tarafından doğrulanır                                                                                      |
| PATCH  | `/api/v1/management/proxies`                 | Proxy'yi günceller — gövde `updateProxyRegistrySchema` tarafından doğrulanır (`id` gerektirir)                                                                 |
| DELETE | `/api/v1/management/proxies?id=...&force=1`  | Proxy'yi siler (atamaları kaldırmak için `force=1` kullanın)                                                                                                   |
| GET    | `/api/v1/management/proxies/assignments`     | Atamaları listeler — `proxy_id`, `scope`, `scope_id` ile filtrelenebilir; bir bağlantının etkin proxy'sini çözümlemek için `resolve_connection_id=<id>` iletin |
| PUT    | `/api/v1/management/proxies/assignments`     | Atar — gövde `proxyAssignmentSchema` (`{scope, scopeId?, proxyId?}`) tarafından doğrulanır. Dağıtıcı önbelleğini temizler                                      |

**Kimlik doğrulama:** her rotada yönetim oturumu/API anahtarı gerekir (`requireManagementAuth`).

> Görev açıklamasındaki `POST /api/v1/management/proxies/[id]/assignments` ve `POST /api/v1/management/proxies/[id]/health`, yukarıda gösterilen düz `/assignments` ve `/health` rotaları tarafından sunulur — kod tabanında kimliğe özel alt rotalar yoktur.

## Dayanıklılık (genişletilmiş)

OmniRoute, birbirinden bağımsız üç geçici hata mekanizması sunar; aşağıdaki yönetim uç noktaları, operatörlerin bunları görüntülemesine ve geçersiz kılmasına olanak tanır:

| Kapsam                   | Durum depolama                                    | Görüntüleme                               | Sıfırlama / temizleme                                                      |
| ------------------------ | ------------------------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------- |
| Sağlayıcı devre kesicisi | `domain_circuit_breakers` + bellek içi            | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                               |
| Bağlantı bekleme süresi  | Sağlayıcı bağlantılarındaki `rateLimitedUntil`    | `/api/rate-limits`, `/api/providers/[id]` | (gerektiğinde yeniden etkinleştirilir; sağlayıcı PUT isteğiyle temizlenir) |
| Model kilitleme          | Bellek içi model kullanılabilirliği kayıt defteri | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                                   |

`PATCH /api/resilience`, `providerBreaker.oauth` ve `providerBreaker.apikey` altında sağlayıcı devre kesicisi geçersiz kılmalarını kabul eder. Her profil `degradationThreshold`, `failureThreshold` ve `resetTimeoutMs` alanlarını destekler; aynı alanlar Dashboard → Settings → Resilience bölümünde de sunulur.

```bash
# Tek bir model kilidini temizle
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Tüm kilitleri temizle
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Tam kavramsal referans ve devre kesici varsayılanları için: [`CLAUDE.md`](../../CLAUDE.md) → "Dayanıklılık Çalışma Zamanı Durumu" ve [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) belgelerine bakın.

### Hız Sınırı Kuyruğu ve Otomatik Etkinleştirme Güvenlik Ağı

- **Desteklenen yazma yolu**: `{"connectionId": "<id>", "enabled": true|false}` gövdesiyle `POST /api/rate-limits`, bir bağlantının hız sınırı korumasını açıp kapatmak için desteklenen yönetim uç noktasıdır. `PUT /api/providers/[id]`, tasarım gereği `rateLimitProtection` değerini değiştirmez veya tersine çevirmez (#11278).
- **`enabled: false` semantiği**: `enabled: false` olarak ayarlamak, bağlantının açık korumasını kaldırır ancak etkin bir API anahtarı bağlantısını global otomatik etkinleştirme güvenlik ağının (`autoEnableApiKeyProviders = true`) dışında **bırakmaz**. `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) içinde `false` ve `undefined` eşdeğerdir; açık koruması bulunmayan etkin API anahtarı bağlantıları, otomatik etkinleştirme güvenlik ağı kapsamında korunmaya devam eder.
- **Global olarak devre dışı bırakma**: API anahtarı bağlantılarını hız sınırı kuyrukları olmadan çalıştırmak için güvenlik ağını `RATE_LIMIT_AUTO_ENABLE=false` (ortam değişkeni) veya `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Settings → Resilience / `PATCH /api/resilience`) aracılığıyla global olarak devre dışı bırakın.

## MCP Sunucusu

OmniRoute; 3 taşıma yöntemi (stdio, SSE, streamable-http) ve kapsamlandırılmış araçlar içeren yerleşik bir Model Context Protocol sunucusuyla birlikte gelir. Aşağıdaki pano uç noktaları durum/denetim verilerini okur ve HTTP taşıma yöntemleri için proxy görevi görür.

| Yöntem | Yol | Açıklama |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | Sinyal, taşıma yöntemi, çevrimiçi durum, son çağrı, en çok kullanılan araçlar, 24 saatlik başarı oranı |
| GET | `/api/mcp/tools` | `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints` alanlarıyla MCP araçlarının listesi |
| GET | `/api/mcp/sse` | SSE taşıma yöntemi için SSE akışı açar (MCP devre dışıysa veya taşıma yöntemi eşleşmiyorsa `503` döndürür) |
| POST | `/api/mcp/sse` | SSE taşıma yöntemi üzerinden JSON-RPC çerçevesi gönderir |
| GET | `/api/mcp/stream` | Streamable HTTP taşıma yönteminin SSE tarafını açar (sunucu tarafından başlatılan mesajlar) |
| POST | `/api/mcp/stream` | Streamable HTTP taşıma yöntemi üzerinden JSON-RPC çerçevesi gönderir |
| DELETE | `/api/mcp/stream` | Bir Streamable HTTP oturumunu sonlandırır |
| GET | `/api/mcp/audit` | Denetim günlüğünü sorgular — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | Toplu denetim istatistikleri (toplamlar, başarı oranı, ortalama süre, en çok kullanılan araçlar) |

**Kimlik doğrulama:** `sse`/`stream` taşıma yöntemleri MCP'ye özgü kimlik doğrulama yüzeyini (`mcp` kapsamına sahip Bearer API anahtarı) kullanır; `status`/`tools`/`audit*` rotaları panodan okunabilir (pano ana makinesine erişimin ötesinde ek kimlik doğrulama gerekmez).

> Her iki HTTP taşıma yöntemi de `settings.mcpEnabled` ve `settings.mcpTransport` tarafından denetlenir — taşıma yöntemi eşleşmezse `400`, MCP devre dışıysa `503` döndürülür.

## A2A Sunucusu

OmniRoute, inceleme/pano kullanımı için bir REST sarmalayıcısının yanı sıra bir A2A (Agent-to-Agent) JSON-RPC 2.0 uç noktası sunar.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # OMNIROUTE_API_KEY ayarlanmadığı sürece isteğe bağlıdır
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Desteklenen yöntemler (tümü `settings.a2aEnabled` ayarına bağlıdır):

| Yöntem           | Açıklama                                                         |
| ---------------- | ---------------------------------------------------------------- |
| `message/send`   | Eşzamanlı beceri yürütme; `{task, artifacts, metadata}` döndürür |
| `message/stream` | Aynı beceri kümesinin SSE üzerinden akışlı yürütülmesi           |
| `tasks/get`      | Bir görevi `taskId` ile getirir                                  |
| `tasks/cancel`   | Bir görevi `taskId` ile iptal eder                               |

Yerleşik beceriler: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Aracı Kartı

```bash
GET /.well-known/agent.json
```

Herkese açık A2A aracı kartını (ad, açıklama, yetenekler, beceri kataloğu, kimlik doğrulama şeması) döndürür — herkese açık olarak 1 saat önbelleğe alınır. Kimlik doğrulama gerekmez.

### REST yardımcıları

| Yöntem | Yol                          | Açıklama                                                                                                                |
| ------ | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | A2A etkinlik durumu + görev istatistikleri + önbelleğe alınmış aracı kartı özeti                                        |
| GET    | `/api/a2a/tasks`             | Görevleri listeler — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (REST yardımcısı olarak uygulanmamıştır — JSON-RPC `message/send` aracılığıyla oluşturun)                               |
| GET    | `/api/a2a/tasks/[id]`        | Tek bir görevi getirir                                                                                                  |
| POST   | `/api/a2a/tasks/[id]/cancel` | Bir görevi iptal eder                                                                                                   |

**Kimlik doğrulama:** REST yardımcıları yönetim kimlik doğrulaması olmadan çalışır (pano tarafından okunabilir); JSON-RPC `/a2a` rotası, yapılandırılmışsa Bearer `OMNIROUTE_API_KEY` kullanır.

## Kimlik Doğrulama

Dört kimlik bilgisi ailesi (pano oturumu, yerel CLI belirteci, `oma_live_…` Erişim Belirteci, yönetim kapsamlı API anahtarı) ve bunların çıkarım anahtarlarından farkları için [Yönetim Kimlik Doğrulaması](../guides/MANAGEMENT-AUTH.md) bölümüne bakın.

- Pano rotaları (`/dashboard/*`) `auth_token` çerezini kullanır
- Oturum açma, kaydedilmiş parola karmasını kullanır; geri dönüş olarak `INITIAL_PASSWORD` kullanılır
- `requireLogin`, `/api/settings/require-login` aracılığıyla açılıp kapatılabilir
- `/v1/*` rotaları, `REQUIRE_API_KEY=true` olduğunda isteğe bağlı olarak Bearer API anahtarı gerektirir
- Bu referansta "yönetim belirteci" / "yönetim kapsamlı API anahtarı", söz konusu kılavuzdaki ailelerden birini ifade eder; tanımlanmamış ek bir gizli bilgi türünü değil

> **Geriye dönük uyumsuz değişiklik (v3.8.0)** — `/api/v1/agents/tasks/*` ve bekleme süresi yönetimi uç noktaları artık **yönetim kimlik doğrulaması** (pano `auth_token` çerezi veya yönetim kapsamlı bir API anahtarı) gerektiriyor. Daha önce bu rotaları kimlik doğrulaması olmadan çağıran istemciler `401 Unauthorized` yanıtını alacaktır. `588a0333` commit'ine bakın (`fix(auth): require management auth for agent and cooldown APIs`).
