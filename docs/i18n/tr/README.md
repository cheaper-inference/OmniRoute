## Aylık Ücretsiz Tokenlar: Diğerlerinin Sayısına Göre 11,3 Milyar ~· 90 Milyon Real ~

</div>

> **~ 11.3B ücretsiz jeton / ay**<br/> <sub> diğer katalogların sayıldığı şekilde saydı: her satır eklendi, biten teklifler dahil edildi </sub>
>
> **bugün ~ 90M gerçek**<br/> <sub> her paylaşılan kota bir kez sayılır: gerçekte ne kullanabilirsiniz </sub>
>
> **Burada her şey ücretsizdir. Ödeme duvarı yok.**<br/> ★ [Beğendin mi? Bize GitHub yıldız verin](https://github.com/cheaper-inference/OmniRoute)

Diğer kataloglar, canlı verilere ömür boyu erişim için yıllık 19 $ US 49 $ US kadar ücret almaktadır. Burada her şey bedava. <sub> Fiyatlar 2026-11-18'de kontrol edildi.</sub>

<sub>Katalog en son 2026-11-23 tarihinde denetlendi. [→ nasıl sayarız?](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **Kendi sağlayıcı hesaplarınızı getirin.** Bunlar, OmniRoute jeton bağışı değil, üçüncü taraf ücretsiz katmanlardır. Kaydolun, sağlayıcının istediği kimlik bilgilerini alın ve kullanabileceğiniz kimlik bilgilerini bağlayın. Her sağlayıcı kendi sınırlarını, kullanılabilirliğini ve koşullarını belirler.
>
> Ücretsiz katmanları elle istiflemek, düzinelerce SDKs, düzinelerce oran sınırı ve geriye ne kaldığınız konusunda net bir fikrin olmaması anlamına gelir. OmniRoute 214 katalog satırını ücretsiz erişimle tutar ve yayınlanmış bir kotaya sahip 12 havuzdan gerçek rakamı hesaplar; her paylaşılan havuz bir kez sayılır. Yalnızca bölgesel kimlik kontrolünden sonra açılan kotalar (bugün, ModelScope) ayrı olarak gösterilir, bölgesel kimlik doğrulamasının 6 milyon +~ gerisindedir ve hiçbir zaman gerçek rakama eklenmez. Geriye kalanlar kontrol panelinde gösterilir (`/dashboard/free-tiers`).

## Bir sağlayıcı yükleyin, bağlayın ve ardından tek bir uç nokta üzerinden yönlendirin

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

## Kombinasyonlar: amiral gemisi

1. **`auto` ile başlayın.** Modeli OpenAI uyumlu istemcinizde ayarlayın. OmniRoute bağlı sağlayıcılardan sanal bir kombinasyon oluşturur ve adayları canlı olarak puanlar.
2. **Daha fazla kontrol için bir komboyu kaydedin.** Bir ad, hedef listesi ve strateji seçin, ardından bu adı model olarak kullanın. Strateji hangi hedefin önce gideceğini ve geri kalanların nasıl deneneceğini belirler.

Kombinasyon, modeller arasında otomatik olarak yönlendirir. Kotanın tükenmesi, sağlayıcının başarısız olması veya modelin kilitlenmesi durumunda bir sonraki uygun, sağlıklı hedefi dener.

### Sıfır yapılandırma: sadece `auto` kullanın

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

Varyantlar ağırlıkları ayarlar. Son bilinen iyi yönlendirme, başarısız olana kadar son başarılı sağlayıcıda kalır, ardından yeniden puanlanır. `auto/fast` ve `auto/cheap` en hızlı veya en ucuz modeli garanti etmeden tercihleri ifade eder.

| Model ID            | Davranış                                                                                                                                                                                                                                                                                                           |
| :------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Dengeli varsayılan ağırlıklar.                                                                                                                                                                                                                                                                                     |
| `auto/fast`         | Düşük gecikmeyi ve sağlayıcı sağlığını destekler.                                                                                                                                                                                                                                                                  |
| `auto/cheap`        | Daha düşük katalog fiyatlarını tercih eder.                                                                                                                                                                                                                                                                        |
| `auto/coding`       | Kod oluşturma için kalite öncelikli ağırlıklar.                                                                                                                                                                                                                                                                    |
| `auto/smart`        | %10 keşifle kalite öncelikli ağırlıklar (varsayılan %5).                                                                                                                                                                                                                                                           |
| `auto/lkgp`         | `auto` ile aynı ağırlıklara sahip açık son bilinen iyi yönlendirme.                                                                                                                                                                                                                                                |
| `auto/subscription` | Yalnızca canlı olarak doğrulanmış plan kotasını kullanır. Hiçbiri mevcut olmadığında HTTP 503'ü döndürür ve faturalandırılmış geri dönüşü önler.                                                                                                                                                                   |
| `auto/thrifty`      | Plan → anahtarsız → ücretsiz → ucuz → premium. Faturalandırılan modellere ulaşabilir ve kota ve bekleme süresi izin verdiğinde plana geri dönebilir.                                                                                                                                                               |
| `auto/offline`      | Kotayı ve oran sınırı boşluğunu tercih eder. İstekler hâlâ sağlayıcılarınıza gidiyor.                                                                                                                                                                                                                              |
| `auto/chaos`        | Paralel olarak sağlayıcı başına bir model; varsayılan olarak beşe kadar veya yapılandırıldığında on taneye kadar. Model başına bir yukarı akış çağrısı. En üst model başarısız olursa, en üst sıradaki yanıtı veya son başarılı panel yanıtını döndürür. Yanıtları bir hakimle sentezlemek için `fusion` kullanın. |

Kategori ve isteğe bağlı katman örnekleri arasında `auto/coding:fast`, `auto/coding:free`, `auto/reasoning:pro` ve `auto/vision` bulunur. Bağlı adaylardan hiçbiri eşleşmezse istek HTTP 503 değerini döndürür ve havuz dar kalır. ### Dayanıklılık yerleşiktir: 3 bağımsız katman

Arızalar üç kapsamda ele alınır; böylece kötü bir model hesabını kapatmaz ve kötü bir hesap da sağlayıcısını kapatmaz.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Bir sağlayıcının tamamı kapalıysa

**sağlayıcı devre kesici** 408, 500, 502, 503 veya 504 durumuyla 8 (OAuth) veya 12 (API anahtarı) arızadan sonra açılır. Kombinasyonlar açıkken o sağlayıcıyı atlar. 60 saniye veya 30 saniye sonra, bir sonda isteği kapanıp kapanmadığına karar verir.

#### Bir anahtar veya hesabın hızı sınırlıysa

**bağlantı bekleme süresi** 5 sn'lik (OAuth) veya 3 sn'lik (API tuşu) üstel geri çekilme ile yalnızca bu bağlantıyı destekler. Aynı sağlayıcıya ait diğer anahtarlar hizmet vermeye devam ediyor.

#### Bir model reddedilirse

**modeli kilitleme** model başına 429, 404 veya erişim reddinden sonra yalnızca söz konusu bağlantıdaki o modeli engeller. Aynı bağlantıdaki diğer modeller hizmet vermeye devam ediyor.

Yasaklanmış, süresi dolmuş ve kredisi tükenmiş bağlantılar bekleme süreleri değil, son durumlardır: bunları düzeltmenizi beklerler.

```bash
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"
omniroute setup-whycodes && omniroute run whycodes --model glm/glm-5.2

# Or pick provider and model interactively and write the tool's own config:
omniroute configure codex   # also: claude opencode qwen aider goose gemini whycodes cline continue kilo 5dive
```

Her komut etkin uzak bağlamı (`omniroute connect <host>`) dikkate alır. `--dry-run` hiçbir şeyi çalıştırmadan env ve args'ı tam olarak yazdırır ve `--api-key-env NAME` anahtarı kabuk geçmişinizin dışında tutar. Qwen Code ve Gemini CLI çıkışta silinen geçici bir evde çalışır. WhyCodes sağlayıcısını yalnızca `config.toml` okur, bu nedenle `run whycodes` önce `setup-whycodes` bir kez çalıştırın. → [CLI Entegrasyonlar](docs/guides/CLI-INTEGRATIONS.md)

## Tam CLI, MCP ve A2A

> OmniRoute bir komut satırı istemcisini birlikte gönderir** 91 üst düzey komut ve komut grubu** (alt komutları sayan 754 komut), bir** 110 araç ve 33 kapsam içeren MCP sunucusu** ve bir** 6 beceriye sahip A2A ajanı** . Komut dosyaları, terminaller ve AI aracılarının tümü aynı ağ geçidini çalıştırabilir.

### Sadece `start` değil, gerçek bir CLI

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

Global `--output table|json|jsonl|csv` bayrağı aynı komutların betiklerden ve CI kullanılabilir olmasını sağlar.

### Uzak mod: dizüstü bilgisayarınızdaki CLI, sunucudaki OmniRoute

Uzak bir sunucuda bir kez oturum açın. CLI bunu bir** bağlam** ve daha sonraki komutlar, siz geri dönene kadar bu sunucuda çalışır.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Belirteç kapsamı | <img width="2000" height="0" alt=""> Neye izin verir                             |
| ---------------- | -------------------------------------------------------------------------------- |
| `read`           | Listeleyin ve inceleyin: modeller, durum, günlükler, kullanım                    |
| `write`          | `read` plus yapılandırma ve uygulama: istemci kurulumu, anahtarlar, yapılandırma |
| `admin`          | `write` plus yönetimi: belirteçler, sağlayıcılar, hizmetler, politika            |

Çıplak bir ana bilgisayar `http://` ve 20128 numaralı bağlantı noktasını alır; sunucu TLS arkasında oturduğunda tam bir `https://` URL iletin. Süreçleri oluşturabilen rotalar, belirteç ne olursa olsun yalnızca geri döngüde kalır.

### Bir temsilci bağlayın

Bir aracı veya kendi kodunuz, bu arayüzlerin herhangi biri aracılığıyla yönlendirmeyi, sağlayıcıları, kombinasyonları, önbelleği, sıkıştırmayı ve belleği yönlendirebilir. HTTP yolları, varsayılan olarak `http://localhost:20128` adresinde ağ geçidi tarafından sunulur.

| Arayüz                              | Uç nokta veya komut        | Bunun için kullan                                                                   |
| ----------------------------------- | -------------------------- | ----------------------------------------------------------------------------------- |
| stdio üzerinden MCP                 | `omniroute --mcp`          | Claude Masaüstü, Cursor ve diğer yerel MCP istemcileri                              |
| Akış yapılabilir HTTP üzerinden MCP | `/api/mcp/stream`          | Uzak MCP istemcileri: 110 araç, 33 kapsam, her çağrı denetim günlüğüne yazılır      |
| SSE üzerinden MCP                   | `/api/mcp/sse`             | Hala SSE taşımacılığını kullanan müşteriler                                         |
| A2A keşfi                           | `/.well-known/agent.json`  | Temsilci Kartı: diğer temsilcilere OmniRoute neler yapabileceğini anlatır           |
| A2A infazı                          | `POST /a2a`                | 6 beceride SSE üzerinden eşzamanlı veya akışlı JSON-RPC 2.0 görevleri               |
| REST API                            | `/v1/*`                    | OpenAI uyumlu sohbet, Yanıtlar, yerleştirmeler, resimler, ses ve OCR                |
| Web kancaları                       | `/api/webhooks`            | Slack, Discord, Telegram veya HMAC imzalamayla herhangi bir URL yönelik etkinlikler |
| Uzaktan CLI                         | `omniroute connect <host>` | Kapsamlı erişim belirteçleriyle uzak bir örneği yönetin                             |

Altı A2A becerisi `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` ve `list-capabilities`.

**Bağlanmadan önce:**

- **HTTP üzerinden MCP devre dışı bırakılır.** `omniroute mcp enable --transport streamable-http` ile veya kontrol panelinin Uç Noktalar sayfasından açın. Aynı anda bir HTTP aktarımı aktiftir: `streamable-http` `/api/mcp/stream` hizmet eder, `sse` `/api/mcp/sse` hizmet eder.
- **A2A devre dışı bırakılır.** Bunu kontrol panelinin Uç Noktalar sayfasında etkinleştirin. `POST /a2a` daha sonra `/v1` ile aynı API anahtarı kurallarını izler.
- **Remote MCP uygun bir anahtara ihtiyacı var.** `/api/mcp/*` varsayılan olarak yalnızca geri döngüye yanıt verir. Başka bir ana bilgisayardan `manage` veya `admin` (tüm araçlar) veya `mcp:connect` artı ihtiyaç duyduğunuz araçların kapsamlarını içeren bir anahtar gönderin. `manage`/`admin` içermeyen anahtarlar için araç kapsamları her zaman uygulanır.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

## Otomatik Olarak %15-95 Token — Tasarrufu Yapın

### — boru hattı, mimari ve tasarruf matematiği nasıl çalışır?

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

Varsayılan yığılmış kombo `RTK → Caveman` çalıştırır. Her ikisi de aynı tool/context yükü üzerinde hareket ettiğinde tasarruf artar:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Kod blokları, URLs, JSON ve yapılandırılmış veriler** her zaman korunur** koruma motoru tarafından.

> **Az sayıda jeton işe yararken neden çok sayıda jeton kullanasınız ki?** Her istek OmniRoute sıkıştırma hattından geçer** şeffaf olarak** — istemci değişikliği yok. Artık bir** 12 adet şekillendirilebilir motor yığını** [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) ve [Troglodita'dan](https://github.com/leninejunior/troglodita) (PT-BR) gelen fikirleri temel alarak — yönlendirme kombinasyonuna göre sırayla çalışan ve karıştırıp eşleştiren.

`:latest` en yüksek olanı takip ediyor** yayınlandı** kararlı SemVer git `main` izlemez. GitOps için `:X.Y.Z` sabitleyin. Bkz. [Docker Yayın Kanalları](docs/guides/DOCKER_GUIDE.md#release-channels). Görüntü pinleri**`OMNIROUTE_MEMORY_MB=1024`** . Bu, kontrol paneli ve hafif bir sohbet için yeterlidir.** Kodlama ajanları** ( Claude Code'dan `POST /v1/responses`, Codex, Grok, …) çok daha büyük bir V8 yığınına veya örtüşen iki uzun bağlam altında ~ 12 GiB `FATAL ERROR` s sürecine ihtiyaç duyar. Kabı yığının üzerinde boyutlandırın (yerel arabellekler V8'in dışında bulunur):

| <img width="2000" height="0" alt=""> İş Yükü | Yığın (`-e OMNIROUTE_MEMORY_MB`) | Konteyner (`--memory`) |
| -------------------------------------------- | -------------------------------- | ---------------------- |
| Kontrol paneli / hafif sohbet                | `1024` (görüntü varsayılanı)     | ≥ 2g                   |
| Bir kodlama aracısı                          | `8192`                           | ≥ 10 gr                |
| İki eşzamanlı uzun `/v1/responses`           | `10240`–`12288`                  | ≥ 12–16 gr             |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Tam tablo: [Docker Kılavuzu — çalışma zamanı RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

Bu değiştirilebilir etiketler yalnızca yayınlanmamış düzeltmeleri test etmek için tasarlanmıştır ve** üretim için desteklenmiyor** . Bkz. **🥟 Bun**

Standart `bun install` ve genel kurulum (`bun install -g omniroute`), Bun çalışma zamanı algılama yoluyla desteklenir:

- **Yerleşik `bun:sqlite`** : OmniRoute Bun altında çalışırken Bun yerleşik `bun:sqlite` sürücüsünü kullanır ve Node.js veya `sql.js` `better-sqlite3` geri döner.
- **Geliştiricide otomatik Webpack paketleyici seçimi** : Geliştirme (`bun run dev`), yerel V8 bağlama uyumsuzluklarını önlemek için Bun otomatik olarak algılar ve Turbopack Webpack lehine devre dışı bırakır. Üretim yapıları (`bun run build`), `OMNIROUTE_USE_TURBOPACK` tam olarak Düğümdeki gibi takip eder: varsayılan olarak Turbopack, Webpack ile derlemek için `OMNIROUTE_USE_TURBOPACK=0` (`Dockerfile.bun` onu bir `--build-arg` olarak gösterir).
- **Özel Bun Docker dosyası** : Yerel Bun üretim dağıtımları (`docker build -f Dockerfile.bun -t omniroute:bun .`) için çok aşamalı `Dockerfile.bun`.

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ Daha hızlı / daha yalın kurulum (yerel yapıyı atlayın)**

Yerel SQLite motoru (`better-sqlite3`) bir** isteğe bağlı** bağımlılık, bu nedenle genel kurulum hiçbir zaman kaynaktan derlemeyi engellemez: platform/Node ile eşleştiğinde önceden oluşturulmuş bir ikili dosya kullanır ve aksi takdirde şeffaf bir şekilde saf JS motoruna geri döner ( Düğüm 22'de + `node:sqlite`, aksi takdirde paketlenmiş `sql.js` WASM) — hiçbir derleme aracına gerek yoktur.

Kurulum sonrası aşamasını atlamak için** yerli ısınma** tamamen (CI, başsız veya yavaş makineler). Not: bu yalnızca yerel SQLite ısınma adımını (`scripts/postinstall.mjs`) atlar; binary-copy/repair kancası (`scripts/build/postinstall.mjs`) hala normal şekilde çalışıyor:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

En hızlı kurulumlar için tercih edin** ppmpm** (içerik adresli mağaza + sabit bağlantıları — yukarıya bakın). Kontrol paneli olmayan, başsız bir çalışma zamanı için Docker `base` profilini (yukarıda) veya [Termux kılavuzunu](docs/guides/TERMUX_GUIDE.md) kullanın. CLI ve web kontrol paneli tek bir bağlantı noktasında aynı işlemle sunulur, dolayısıyla günümüzde ayrı bir yalnızca CLI paketi yoktur.

### Nasıl Katkıda Bulunulur?

1. Depoyu çatallayın
2. Şubeden** aktif** `release/vX.Y.Z` ipucu ( `main` değil) — bkz. [Dallanma ve Serbest Bırakma Modeli](docs/ops/BRANCHING_MODEL.md)
3. Özellik dalınızı (`git checkout -b feat/amazing-feature`) oluşturun
4. Değişikliklerinizi gerçekleştirin (`git commit -m 'feat: add amazing feature'`)
5. Şubeye itin (`git push origin feat/amazing-feature`)
6. Şununla bir Çekme İsteği açın:** temel = bu `release/vX.Y.Z` şubesi**

Ayrıntılı yönergeler için [CONTRIBUTING.md](CONTRIBUTING.md) bakın.
