> Ajonaikaiset valitsimet, jotka muuttavat OmniRouten toimintaa **ilman uutta käyttöönottoa**.
> Jokainen tässä lueteltu lippu on määritelty tiedostossa
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — joka on ainoa totuuden lähde. Sekä hallintapaneeli että REST API lukevat
> kyseistä tiedostoa, joten alla oleva taulukko luodaan vastaamaan sitä täsmälleen suhteessa 1:1.

---

## Mitä ominaisuusliput ovat

Ominaisuuslippu on nimetty valitsin (totuusarvo tai luettelotyyppi), jonka arvoa voidaan muuttaa
ajonaikaisesti ja joka voidaan tallentaa tietokantaan ilman prosessin uutta käyttöönottoa. Jokainen
lippu kuvataan `FeatureFlagDefinition`-määrityksellä, jolla on `key`, `label`,
`description`, `category`, `defaultValue`, `type` ja `requiresRestart`-vihje.

### Ratkaisujärjestys

Lipun **voimassa oleva arvo** ratkaistaan funktiolla
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) seuraavassa
etusijajärjestyksessä (korkein voittaa):

1. **Tietokannan ohitusarvo** — `key_value`-tauluun nimiavaruudessa
   `feature_flags` tallennettu arvo (asetetaan hallintapaneelin tai REST API:n kautta).
2. **Ympäristömuuttuja** — `process.env[<KEY>]`, jos se on asetettu eikä ole tyhjä.
3. **Määrityksen oletusarvo** — tiedoston `featureFlagDefinitions.ts` `defaultValue`.

Totuusarvoinen lippu katsotaan **käytössä olevaksi**, kun sen voimassa oleva arvo on `"true"`,
`"1"` tai `"yes"` (katso `isFeatureFlagEnabled()`).

> [!NOTE]
> Useimmilla lipuilla on myös **samanniminen** vastaava ympäristömuuttuja,
> joka on dokumentoitu tiedostossa [`ENVIRONMENT.md`](./ENVIRONMENT.md). Lipun tietokannan ohitusarvo
> on ensisijainen kyseiseen ympäristömuuttujaan nähden. Lippu, jolla on
> `requiresRestart: true`, tallennetaan välittömästi, mutta luetaan uudelleen vasta prosessin
> käynnistyessä — sen vaihtaminen näyttää hallintapaneelissa **"Käynnistä palvelin uudelleen"** -bannerin.

> `INPUT_SANITIZER_BLOCK_THRESHOLD` ja sen vanha alias `INJECTION_GUARD_BLOCK_THRESHOLD` virittävät `INJECTION_GUARD_MODE`:n `block` -tilan, mutta ne ovat pelkkiä ympäristömuuttujia, jotka [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts) lukee, ei ominaisuuslippuja: niillä ei ole DB ohitusta eikä kojelaudan vaihtokytkintä. Katso [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication).

> [!NOTE]
> `Restart` -sarake merkitsee liput `requiresRestart: true` — -arvolla, joka säilyy välittömästi, mutta se tulee voimaan vasta prosessin uudelleenlatauksen jälkeen. Enum-liput hylkäävät kaikki sallitun joukkonsa ulkopuolella olevat arvot (validoitu palvelinpuolella sekä `setFeatureFlagOverride()` ssä että REST `PUT` -käsittelijässä).

## Lippujen vaihto

### Kojelauta

Navigoi kohteeseen** Dashboard → Asetukset → Ominaisuusliput** (`/dashboard/settings/feature-flags`). Ruudukko (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) tukee:

- **Haku** avaimella tai kuvauksella ja** suodattaa** luokittain (plus synteettinen** Vaatii uudelleenkäynnistyksen** näkymä).
- A** vaihtaa** Boolen lipuille ja a** pudotusvalikosta** enum-lipuille (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- A** lähdemerkki** per lippu — `DB`, `ENV` tai `DEF` — joka osoittaa, mistä tehollinen arvo tuli.
- A** Nollaa** -painiketta (näkyy vain `DB` -sourced -lippujen kohdalla) ohituksen poistamiseksi, ja a** Nollaa kaikki ohitukset** painiketta alareunassa.
- A** Käynnistä palvelin uudelleen** banneri, kun `requiresRestart` lippu vaihdetaan.

### REST API

Kaikki toiminnot kulkevat yhden reitin kautta: [`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts). Jokainen menetelmä edellyttää todennettua kojelautaistuntoa (muuten `401` ).

Kun sisäänkirjautuminen on estetty (`requireLogin=false`), reitti on auki paitsi suojattuja lippuja: jokainen Suojaus-luokan lippu plus `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`, `OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS`, `MITM_DISABLE_TLS_VERIFY`, `OMNIROUTE_MCP_ENFORCE_SCOPES` ja `SKILLS_SANDBOX_NETWORK_ENABLED` (`isProtectedFeatureFlag()` in `protectedFeatureFlags.ts`). Yhdellä niistä oleva `PUT` ja `DELETE`, kun toisessa niistä on DB ohitus, tarvitsee silti kojelautaistunnon, `manage` -scope API avaimen, `oma_` käyttöoikeustunnuksen, jolla on kirjoitusalue tai suurempi, tai CLI tunnuksen tai sisäisen palvelun tunnuksen, joka lähetetään silmukasta. Tämä joukko on laajempi kuin sisäänkirjautumisen yhteydessä, jolloin reitti hyväksyy vain istunnon tai `manage` -scope -avaimen.

#### `GET /api/settings/feature-flags`

Palauttaa jokaisen lipun tehollisen arvon, lähteen ja yhteenvedon kera.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 119 flags
  ],
  "summary": {
    "total": 119,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Aseta tai poista yksi ohitus. Runko: `{ key: string; value?: string }`. Jos `value` jätetään pois, ohitus poistetaan (palautetaan env / oletus).

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Vastaus toistaa uudet `effectiveValue`/`source`, `previousValue`/ `previousSource` ja `requiresRestart`. Tuntemattomat avaimet ja alueen ulkopuoliset enum-arvot hylätään komennolla `400`.

#### `DELETE /api/settings/feature-flags`

Tyhjentää** kaikki** DB ohittaa kerralla ja palauttaa jokaisen lipun sen env / oletusarvoon. Palauttaa `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> `requiresRestart: true` -merkit tulevat voimaan vasta prosessin uudelleenlatauksen jälkeen. Kojelaudan uudelleenkäynnistysvirta kutsuu `POST /api/restart` ja sitten kyselyä `GET /api/health/ping`, kunnes palvelin on varmuuskopioitu.

## Budjetin hätävaravaihtoehto

`OMNIROUTE_EMERGENCY_FALLBACK` (luokka `runtime`, oletusarvo `true`) hallitsee
maksutonta hätävarareittiä tiedostossa
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Kun asetus on käytössä, budjettinsa loppuun käyttäneet pyynnöt ohjataan maksuttomalle varapalveluntarjoajalle/-mallille sen sijaan, että ne epäonnistuisivat suoraan. Aseta arvoksi `false` (tai `0`) — hallintapaneelin valitsimella, tietokannan ohitusasetuksella tai
`OMNIROUTE_EMERGENCY_FALLBACK`-ympäristömuuttujalla — poistaaksesi toiminnon käytöstä ja antaaksesi budjettinsa loppuun käyttäneiden pyyntöjen epäonnistua. (Tuotu hallintapaneeliin valitsimena PR-muutoksissa #3741 / #3752.)

Tämän varavaihtoehdon kautta toimitettu vastaus sisältää otsakkeen
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, joten asiakas voi havaita uudelleenreitityksen vertaamatta `X-OmniRoute-Provider`-otsaketta pyyntöönsä. Otsake puuttuu kaikista muista vastauksista.
