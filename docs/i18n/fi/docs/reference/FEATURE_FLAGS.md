> Ajonaikaiset valitsimet, jotka muuttavat OmniRouten toimintaa **ilman uutta käyttöönottoa**.
> Jokainen tässä lueteltu lippu on määritelty tiedostossa
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — joka on ainoa totuuden lähde. Sekä hallintapaneeli että REST API lukevat
> kyseistä tiedostoa, joten alla oleva taulukko luodaan vastaamaan sitä täsmälleen suhteessa 1:1.

---

## Mitä ominaisuusliput ovat

Ominaisuuslippu on nimetty valitsin (totuusarvo tai luettelotyyppi), jonka arvoa voidaan muuttaa
ajonaikaisesti ja joka voidaan tallentaa tietokantaan ilman prosessin uutta käyttöönottoa. Jokainen
lippu kuvataan `FeatureFlagDefinition`-määrityksellä, jolla on `key`, `label`,
`description`, `category`, `defaultValue`, `type` ja `requiresRestart`-vihje.

### Ratkaisujärjestys

Lipun **voimassa oleva arvo** ratkaistaan funktiolla
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) seuraavassa
etusijajärjestyksessä (korkein voittaa):

1. **Tietokannan ohitusarvo** — `key_value`-tauluun nimiavaruudessa
   `feature_flags` tallennettu arvo (asetetaan hallintapaneelin tai REST API:n kautta).
2. **Ympäristömuuttuja** — `process.env[<KEY>]`, jos se on asetettu eikä ole tyhjä.
3. **Määrityksen oletusarvo** — tiedoston `featureFlagDefinitions.ts` `defaultValue`.

Totuusarvoinen lippu katsotaan **käytössä olevaksi**, kun sen voimassa oleva arvo on `"true"`,
`"1"` tai `"yes"` (katso `isFeatureFlagEnabled()`).

> [!NOTE]
> Useimmilla lipuilla on myös **samanniminen** vastaava ympäristömuuttuja,
> joka on dokumentoitu tiedostossa [`ENVIRONMENT.md`](./ENVIRONMENT.md). Lipun tietokannan ohitusarvo
> on ensisijainen kyseiseen ympäristömuuttujaan nähden. Lippu, jolla on
> `requiresRestart: true`, tallennetaan välittömästi, mutta luetaan uudelleen vasta prosessin
> käynnistyessä — sen vaihtaminen näyttää hallintapaneelissa **"Käynnistä palvelin uudelleen"** -bannerin.

Kun tämä on käytössä, myös muita epäselviä diagnooseja (moniselitteisiä virheitä, tukemattomia tarkistuksia ja tyypittämättömiä ajoittimen virheitä) käsitellään tuntemattomina, jolloin liikenne sallitaan. Oletusarvoisesti poissa käytöstä: muut välimuistissa olevat tarkistusvirheet estävät edelleen välityksen välimuistin TTL-ajan (5 minuuttia). |

> [!NOTE]
> `INPUT_SANITIZER_BLOCK_THRESHOLD` ja sen vanha alias
> `INJECTION_GUARD_BLOCK_THRESHOLD` säätävät asetuksen
> `INJECTION_GUARD_MODE` `block`-tilaa, mutta ne ovat tavallisia ympäristömuuttujia, joita luetaan tiedostosta
> [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts),
> eivät ominaisuuslippuja: niillä ei ole DB-ohitusta eikä koontinäytön vaihtokytkintä. Katso
> [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication).

> [!NOTE]
> `Restart`-sarake merkitsee lippuja, joiden arvona on `requiresRestart: true` — arvo
> tallennetaan välittömästi, mutta se tulee voimaan vasta prosessin uudelleenlatauksen jälkeen. Enum-liput hylkäävät kaikki arvot, jotka eivät kuulu niiden sallittuun joukkoon (palvelin validoi tämän sekä `setFeatureFlagOverride()`- että REST `PUT` -käsittelijässä).

## Lippujen vaihtaminen

### Kojelauta

Siirry kohtaan **Kojelauta → Asetukset → Ominaisuusliput**
(`/dashboard/settings/feature-flags`). Ruudukko
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
tukee seuraavia toimintoja:

- **Haku** avaimen tai kuvauksen perusteella ja **suodatus** luokan mukaan (sekä synteettinen
  **Käynnistys vaaditaan** -näkymä).
- Boolen lippujen **vaihtokytkin** ja enum-lippujen **pudotusvalikko**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Kunkin lipun **lähdemerkintä** — `DB`, `ENV` tai `DEF` — joka näyttää, mistä
  voimassa oleva arvo on peräisin.
- **Palauta**-painike (näkyy vain `DB`-lähteisille lipuille), jolla ohitusarvo
  poistetaan, sekä alareunassa oleva **Palauta kaikki ohitukset** -painike.
- **Käynnistä palvelin uudelleen** -banneri, kun `requiresRestart`-lippua muutetaan.

### REST API

Kaikki toiminnot käyttävät yhtä reittiä:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Jokainen menetelmä edellyttää todennettua kojelaudan istuntoa (muussa tapauksessa `401`).

#### `GET /api/settings/feature-flags`

Palauttaa jokaisen lipun voimassa olevan arvon, lähteen ja yhteenvedon.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... kaikki 114 lippua
  ],
  "summary": {
    "total": 114,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Asettaa tai poistaa yksittäisen ohituksen. Runko: `{ key: string; value?: string }`.
Jos `value` jätetään pois, ohitus poistetaan (jolloin palautetaan env- / oletusarvo).

```bash
# Aseta DB-ohitus
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Poista ohitus (ei "value"-arvoa)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Vastaus sisältää uuden `effectiveValue`-arvon ja `source`-lähteen, `previousValue`-arvon/
`previousSource`-lähteen sekä `requiresRestart`-arvon. Tuntemattomat avaimet ja sallitun
alueen ulkopuoliset enum-arvot hylätään vastauksella `400`.

#### `DELETE /api/settings/feature-flags`

Tyhjentää **kaikki** DB-ohitukset kerralla ja palauttaa jokaisen lipun env- /
oletusarvoonsa. Palauttaa arvon `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Liput, joiden `requiresRestart: true`, tulevat voimaan vasta prosessin uudelleenlatauksen jälkeen.
> Kojelaudan uudelleenkäynnistysprosessi kutsuu `POST /api/restart`-reittiä ja suorittaa sen jälkeen
> kyselyjä `GET /api/health/ping`-reitille, kunnes palvelin on jälleen käytettävissä.

## Budjetin hätävaravaihtoehto

`OMNIROUTE_EMERGENCY_FALLBACK` (luokka `runtime`, oletusarvo `true`) hallitsee
maksutonta hätävarareittiä tiedostossa
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Kun asetus on käytössä, budjettinsa loppuun käyttäneet pyynnöt ohjataan maksuttomalle varapalveluntarjoajalle/-mallille sen sijaan, että ne epäonnistuisivat suoraan. Aseta arvoksi `false` (tai `0`) — hallintapaneelin valitsimella, tietokannan ohitusasetuksella tai
`OMNIROUTE_EMERGENCY_FALLBACK`-ympäristömuuttujalla — poistaaksesi toiminnon käytöstä ja antaaksesi budjettinsa loppuun käyttäneiden pyyntöjen epäonnistua. (Tuotu hallintapaneeliin valitsimena PR-muutoksissa #3741 / #3752.)

Tämän varavaihtoehdon kautta toimitettu vastaus sisältää otsakkeen
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, joten asiakas voi havaita uudelleenreitityksen vertaamatta `X-OmniRoute-Provider`-otsaketta pyyntöönsä. Otsake puuttuu kaikista muista vastauksista.
