Neutraali `config/cli-tools-manifest.json` -sopimus ilmoittaa kanonisen IDs, aliakset, binääriehdokkaat, asennusreseptit, malliargumentit ja ominaisuudet. Tavallinen Node-sovitin `bin/cli/cli-manifest.mjs` :ssä ja TypeScript -sovitin `src/shared/constants/cliIntegrationManifest.ts` ssä lukevat saman tiedoston. Ajonaika, luettelo, konfigurointi, valmistuminen, generaattorit ja taustarekisteröinti tarkistetaan yhdessä `tests/unit/cli/cli-manifest-drift.test.ts` avulla. Luettelointi ei tarkoita, että työkalu voidaan käynnistää tai määrittää. Erityisesti 5-sukellus on vain konfiguroitavissa.

## Lapsen ympäristö ja elämänkaari

`omniroute run`, `omniroute launch` ja `omniroute launch-codex` perivät OS/terminal yhteensopivuuden sallittujen luettelon ja lisäävät valitun kohteen tunnistetiedot. Asiaankuulumattomien palveluntarjoajien ja tietokantojen salaisuuksia ei ole oletuksena peritty. `--inherit-env` nimenomaisesti palauttaa täyden vanhemman ympäristön perinnön; käytä sitä vain, kun valitun kolmannen osapuolen prosessin pitäisi saada kyseiset arvot. Tämä on ympäristön suodatusta, ei OS hiekkalaatikkoa: prosessi suoritetaan edelleen soittajan tiedostojärjestelmän käyttöoikeuksilla.

Keskeytys- ja lopetussignaalit välitetään lapselle. Käynnistysohjelma odottaa lapsen sulkemistapahtumaa ennen väliaikaisen määrityksen poistamista. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` ohjaa lisäaikaa ennen pakotettua lopettamista (oletus 5000 millisekuntia).

## Gemini jatkuva asennus

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

Kaksi ensimmäistä komentoa määrittävät tämän koneen valitulle paikalliselle tai etäpalvelimelle. Asennus säilyttää aiheeseen liittymättömät JSON asetukset, valitsee Gemini API-avaimen todennuksen ja kirjoittaa päätepisteen ja valtuustiedot yksityiseen `.gemini/.env` tiedostoon. Se hylkää virheellisen JSON sen sijaan, että kirjoittaisi sen päälle. Päätepisteen URLs on oltava HTTP(S), ilman upotettuja tunnistetietoja, kyselyparametreja tai fragmentteja. Kuivakäyttö tulostaa polut, ei tunnistearvot.

`GEMINI_CLI_HOME` tai `--gemini-home` valitsee pysyvän kotijuuren. Varsinainen `run gemini` luo ja myöhemmin poistaa oman väliaikaisen kotinsa. Kumpikaan tila ei ohita Gemini:n työtilan luotettavuustarkistuksia.

## Codex profiilit

`configure codex` kirjoittaa yksityisen `<name>.config.toml` mallilla ja sen OmniRoute palveluntarjoajan päätepisteellä. Tunnuksiin viitataan `OMNIROUTE_API_KEY` kautta, ei niitä koskaan upotettu. Käynnistyskomento asettaa valitun mallin ylätason `model` -näppäimeen, ei `model_providers` sisään.

Erilliset profiilitiedostot ovat nykyinen dokumentoitu Codex sopimus; ne peittävät käyttäjän kokoonpanon, kun ne on valittu `codex --profile <name>` llä. Katso [virallinen profiiliviittaus](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) ja [OmniRoute Codex -opas](./CODEX-CLI-CONFIGURATION.md).

## Hermeettinen komennon suoritus

Eksplisiittisellä `DATA_DIR`: `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` asettaminen estää käynnistystä putoamasta oletusarvoisen käyttäjän tietohakemiston tunnistetietoympäristöön. Tämä on hyödyllistä yksittäisissä testeissä. Se ei poista käytöstä muita erikseen valittuja ympäristötiedostoja.

## Työhakemisto `.env`

CLI lukee `.env` -tiedostot tässä järjestyksessä, ja ensimmäinen avaimen määrittävä tiedosto voittaa: eksplisiittinen `DATA_DIR`, oletustietohakemisto, nykyinen työhakemisto ja sitten pakettihakemisto. Shell-muuttujat voittaa aina.

Työhakemisto voi kuulua jollekin muulle (kloonattu arkisto, pakkaamaton arkisto), ja `omniroute serve` välittää CLI ympäristön palvelimelle ja jokaiselle palvelimen käyttämälle työkalulle. Joten siellä oleva `.env` voi asettaa vain nämä `bin/cli/utils/untrustedCwdEnv.mjs`:ssä luetellut avaimet:

| Avain                           | Hyväksytyt arvot                                                               |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `REQUIRE_API_KEY`               | `true`, `1` tai `yes` joka tapauksessa arvot, joita palvelin käsittelee        |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | enintään 64 kirjainta, numeroa, `_`, `.`, `@` tai `-`                          |
| `LANGUAGE`                      | sama, plus `:`                                                                 |
| `TZ`                            | enintään 64 kirjainta, numeroa, `_`, `+`, `-` tai `/`, jotka eivät ala `/` llä |
| `NO_COLOR`, `FORCE_COLOR`       | enintään 16 kirjainta ja numeroa                                               |

Jokainen arvo, jonka `REQUIRE_API_KEY` hyväksyy, ottaa tarkistuksen käyttöön, joten tiedosto ei voi poistaa tarkistusta itsestään. Se ei kuitenkaan ratkaise tulosta: palvelin lukee tietokantaan tallennetun `REQUIRE_API_KEY` -ohjauksen ennen ympäristöä, kun taas käynnistysvaroitus kuuntelusta kaikilla liitännöillä ilman API -avainta lukee vain ympäristön. Kun `false` on tallennettu, työhakemisto `REQUIRE_API_KEY=true` jättää API auki ja piilottaa varoituksen. `TZ` sääntö on kapeampi kuin POSIX: se hylkää `.`, `:`, `,` ja `<>`, joten `:Area/City` -muoto ja säännöt, kuten `EST5EDT,M3.2.0,M11.1.0` on asetettava komentotulkissa tai `<DATA_DIR>/.env` ssa.

Nimien tulee vastata täsmälleen isoilla kirjaimilla. Kaikki muut rivit, arvot, jotka eivät läpäise tarkistusta, ja nimi, joka ei ole pelkkiä ASCII kirjaimia, numeroita ja `_` (esimerkiksi sellainen, jossa on NUL -tavu tai samankaltainen kirjain), ohitetaan. CLI tulostaa yhden varoituksen, joka nimeää avaimet, joita se ei voi asettaa, ja yhden, joka nimeää sallitut näppäimet, joita se jättää huomiotta. Jokaisessa on mitä muuttaa (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Kumpikaan ei tulosta arvoja. Näiden viestien tiedostopolut ja `.env` -polku `omniroute doctor` -raportit on ohitettu, kun ne sisältävät ohjaus- tai bidi-merkkejä. Rajoitus ei koske, kun työhakemisto on datahakemisto tai pakettihakemisto.

`PORT`, `API_PORT` ja `DASHBOARD_PORT` eivät ole luettelossa. Ilman perus URL korkeamman prioriteetin lähteestä, CLI puhuu `localhost:<PORT>` lle, ja mikä tahansa siellä kuuntelee, vastaanottaa CLI:n API -avaimen, kontekstitunnuksen ja CLI -konetokenin (`x-omniroute-cli-token`, katso [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), jotka paikallinen palvelin hyväksyy hallintakutsuja varten loopbackista. Työhakemiston portti antaisi tiedoston valita kuuntelijan, joten aseta portit komentotulkissa, `<DATA_DIR>/.env` ssä tai `--port` -vaihtoehdolla komennoilla, joilla on yksi (`serve`, `launch`, `run`).

Jäsentimessä ei ole `export` syntaksia. Rivi, kuten `export LD_PRELOAD=...` nimeää muuttujan `export LD_PRELOAD`; työhakemistosta se ohitetaan, ja muissa `.env` -tiedostoissa se asettaa sen kirjaimellisen nimen, jota mikään ei lue.

CLI yhdistää kontekstin tallennetun tunnuksen (pääsytunnus tai vanha API -avain) vain kyseisen kontekstin oman alkuperän kanssa: skeema, isäntä ja portti, verrattuna `URL.origin`. Tämä koskee CLI:n HTTP -asiakkaan (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) kautta tehtyjä pyyntöjä sekä `launch`, `launch codex`, `configure` ja `setup-*` -komentoja, jotka kirjoittavat perus- URL ja avaimen toisen työkalun konfiguraatioon. Osoittaessaan toiseen palvelimeen, jossa on `--remote`, ne käyttävät eksplisiittistä `--api-key` tai `OMNIROUTE_API_KEY` jos sellainen on asetettu, eikä kontekstitunnusta. Vertailu on tarkka, joten `localhost` ja `127.0.0.1` tai isäntä, jossa on ja ilman pistettä, lasketaan eri palvelimiksi eivätkä saa kontekstitunnusta. URL jossa on käyttäjätiedot, kenoviiva tai välilyönti, ei koskaan täsmää, koska muut URL jäsentimet (esim. Pythonin `urllib` ja `httpx`) voivat lukea siitä eri koneen. Pyynnöissä CLI lähettää itsensä, tämä tarkistus kattaa vain mallin ja auktoriteetin, joten id, jossa on välilyönti polussa tai kyselyssä, säilyttää tunnuksen.
