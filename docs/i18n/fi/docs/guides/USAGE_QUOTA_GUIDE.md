> **TL;DR**: OmniRoute seuraa jokaisen pyynnön tokenien käyttöä, laskee kustannukset, valvoo API-avainkohtaisia kiintiöitä ja näyttää analytiikan hallintapaneelissa. Tässä oppaassa selitetään, miten tämä kaikki toimii.

**Lähteet:**

- `open-sse/services/usage.ts` (~70KB) — käytön pääasiallinen seuranta
- `src/lib/usageAnalytics.ts` (~10KB) — tietojen koostaminen hallintapaneelia varten
- `src/lib/db/quotaSnapshots.ts` — historialliset kiintiötiedot
- `src/lib/db/usage*.ts` — useita käyttöön liittyviä tietokantamoduuleja

## Yleiskatsaus

Jokainen OmniRouten kautta kulkeva pyyntö luo **käyttötietueen**, johon tallennetaan:

- **Tunnistetiedot**: API-avain, palveluntarjoaja, malli ja yhdistelmä
- **Tokenit**: kehotetokenit, vastaustokenit, välimuistissa olevat tokenit ja kokonaismäärä
- **Kustannus**: määrä Yhdysvaltain dollareina (lasketaan hinnoittelutiedoista)
- **Ajoitus**: viive sekä aloitus- ja lopetusaikaleimat
- **Tila**: onnistunut, virhe, nopeusrajoitettu jne.

Nämä tietueet koostetaan **analytiikaksi**, tallennetaan pysyvästi **kiintiövedoksina** ja niitä käytetään **avainkohtaisten budjettirajojen** valvontaan.

```
Pyyntö ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    analytiikka kiintiö laskutus
                    (hallintapaneeli) (valvonta) (vienti)
```

## Mitä tallennetaan

`usage.ts`-palvelu tallentaa **käyttötapahtuman** jokaisesta pyynnöstä:

| Kenttä             | Tyyppi      | Lähde                                                                     |
| ------------------ | ----------- | ------------------------------------------------------------------------- |
| `id`               | merkkijono  | Tallennettaessa luotu UUID                                                |
| `apiKeyId`         | merkkijono  | Pyynnön käynnistänyt API-avain                                            |
| `provider`         | merkkijono  | Palveluntarjoajan tunniste (openai, anthropic jne.)                       |
| `model`            | merkkijono  | Mallin tunniste (gpt-5, claude-opus-4-6 jne.)                             |
| `comboId`          | merkkijono? | Yhdistelmän tunniste, jos pyyntö reititettiin yhdistelmän kautta          |
| `promptTokens`     | luku        | Taustapalvelun vastauksesta                                               |
| `completionTokens` | luku        | Taustapalvelun vastauksesta                                               |
| `cachedTokens`     | luku        | Välimuistista löytyneet tokenit (Anthropicin kehotteiden välimuisti jne.) |
| `totalTokens`      | luku        | Kehote + täydennys                                                        |
| `costUsd`          | luku        | Laskettu hinnoittelutiedoista                                             |
| `latencyMs`        | luku        | Pyynnön kokonaiskesto                                                     |
| `status`           | luettelo    | `success`, `error`, `rate_limited`, `timeout`, `cancelled`                |
| `errorClass`       | merkkijono? | Virheluokka, jos tila ei ole success                                      |
| `timestamp`        | merkkijono  | ISO 8601 UTC                                                              |
| `metadata`         | objekti     | Lisäosan lisäämät mukautetut tiedot                                       |

### Mistä tokenit tulevat

Tokenit poimitaan taustapalveluntarjoajan vastauksesta **vastauksen käsittelijässä**:

```ts
// Tiedostosta open-sse/handlers/chatCore.ts
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

Jos palveluntarjoaja ei palauta käyttötietoja (jotkin verkkoevästeitä käyttävät palveluntarjoajat), OmniRoute **arvioi** tokenien määrän heuristiikalla `~4 chars per token` (katso `open-sse/services/autoCombo/pipelineRouter.ts`).

### Välimuistiin tallennetut tokenit

OmniRoute seuraa `cached_tokens`-arvoa erillään `prompt_tokens`-arvosta, koska:

- Anthropicin kehotteiden välimuisti veloittaa välimuistiin tallennetuista tokeneista alennetun hinnan (10 % normaalihinnasta)
- Jotkin palveluntarjoajat palauttavat `cache_read_input_tokens`-arvon, joka on hinnoiteltava eri tavalla
- Analytiikka voi näyttää **välimuistin osumaprosentin** = `cached_tokens / prompt_tokens`

### Välimuistikirjoitusten tasojen diagnostiikka

Analytiikkanäkymän kehotevälimuistin tilapaneeli erottaa palveluntarjoajan ilmoittamat
5 minuutin ja 1 tunnin välimuistikirjoitukset. Anthropicin
`usage.cache_creation.ephemeral_5m_input_tokens` ja
`usage.cache_creation.ephemeral_1h_input_tokens` säilytetään sekä suoratoistettavien että
muiden vastausten käyttötietojen muunnoksessa ja tallennetaan kutsulokien yhteenvetoihin. Yhdistettyä
välimuistikirjoitusten kokonaismäärää ei lisätä näihin luokkiin toistamiseen.

Kutsujen, joilla on vain yhdistetty kirjoituslaskuri, myös vanhempien tietueiden, taso on
tuntematon. Osittaisessa erittelyssä kohdistamaton loppuosa jää tuntemattomaksi; virheelliset tai
ristiriitaiset laskurit merkitään sen sijaan, että niille määritettäisiin TTL-arvo ilman ilmoitusta. Pyynnön
TTL-merkinnät eivät osoita laskutettua tasoa.

Paneelin API-vastaava kirjoituskustannusarvio kattaa vain ilmoitetut, hinnoitellut tasot, ei
koko pyyntöä. Natiivissa Claude/Anthropic-mallien hinnoittelussa se käyttää 5 minuutin kirjoituksille
1,25-kertaista syötehintaa ja 1 tunnin kirjoituksille kaksinkertaista syötehintaa. Puuttuva
hinnoittelu tarkoittaa, ettei tietoa ole saatavilla, ei nollahintaa. Hinnat tallennetaan, kun kukin uusi kutsu kirjataan;
historiallisten tietueiden hintoja ei lasketa uudelleen. Tilaustileillä voi siten olla
API-vastaava arvio ilman, että kyseinen summa aiheuttaa rahallisia kuluja tai kuluttaa tilauksen
kiintiötä. Nykyiset kiintiö-, budjetti- ja palveluntarjoajakohtaiset tarkat kustannuslaskelmat säilyvät ennallaan.

Tämä diagnostiikka käyttää nykyistä rajattua välimuistin tilayhteenvetoa ja kutsulokien
säilytyskäytäntöä. Se ei muuta pyyntöjen TTL-oletusarvoja, reititystä tai tilin valintaa.
Asiakkaan pyytämän ja tosiasiallisen lähtevän TTL-arvon tallentaminen palveluntarjoajalle lähettämisen
yhteydessä on siirretty myöhemmäksi; tämä paneeli raportoi kuittien tasot, ei tosiasiallista lähtevää TTL-arvoa.

Toteutus: `src/lib/usage/cacheWriteEstimate.ts`,
`src/lib/usage/cacheHealth.ts` ja `open-sse/utils/cacheWriteUsage.ts`.

## Kustannusten laskenta

Kustannukset lasketaan LiteLLM:stä synkronoitujen **hinnoittelutietojen** perusteella (`src/lib/pricingSync.ts`):

| Malli             | Syöte $/1M | Tuloste $/1M | Välimuistista $/1M |
| ----------------- | ---------- | ------------ | ------------------ |
| gpt-5             | $2.50      | $10.00       | —                  |
| claude-opus-4-6   | $15.00     | $75.00       | $1.50              |
| claude-sonnet-4-5 | $3.00      | $15.00       | $0.30              |
| gemini-2.5-pro    | $1.25      | $10.00       | —                  |

Kustannuskaava (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **Miksi välimuistista haetut tokenit vähennetään kehotteen tokeneista?** Välimuistista haettu osuus hinnoitellaan erikseen. Syötehinnan veloittaminen koko kehotteesta johtaisi kustannusten laskemiseen liian suuriksi.

### Hinnoittelun synkronointi

Hinnoittelutiedot synkronoidaan automaattisesti LiteLLM:stä `/api/pricing/sync`-päätepisteen kautta (sisäänrakennettu cron-tehtävä käynnistää synkronoinnin, ei käyttäjälle tarkoitettu ympäristömuuttuja):

```bash
# Manuaalinen käynnistys
curl -X POST http://localhost:20128/api/pricing/sync
```

Malleille, joille ei ole saatavilla hinnoittelutietoja, OmniRoute **arvioi kustannukset** käyttäen sisäisiä keskimääräisiä hintoja (jotka perustuvat LiteLLM:n hinnoittelutietoihin).

## Päivämäärävälin koostaminen

`usageAnalytics.ts`-moduuli laskee hallintapaneelin pienoisohjelmien tiedot raakamuotoisista käyttötiedoista. Se tukee 7 aikaväliä:

| Aikaväli | Tarkastelujakso                     | Käyttötarkoitus                                 |
| -------- | ----------------------------------- | ----------------------------------------------- |
| `1d`     | Viimeiset 24 tuntia                 | Tuntikohtaisten kustannuspiikkien havaitseminen |
| `7d`     | Viimeiset 7 päivää                  | Viikkokatsaus                                   |
| `30d`    | Viimeiset 30 päivää                 | Kuukausilaskutus                                |
| `90d`    | Viimeiset 90 päivää                 | Neljännesvuosianalyysi                          |
| `ytd`    | Kuluvan vuoden 1. tammikuuta alkaen | Vuosibudjetin seuranta                          |
| `all`    | Koko ajanjakso                      | Koko käyttöajan tilastot                        |
| `custom` | Käyttäjän määrittämä alku ja loppu  | Auditoinnit, ad hoc -kyselyt                    |

### Laskettavat hallintapaneelin pienoisohjelmat

Analytiikkakerros laskee mille tahansa päivämäärävälille seuraavat tiedot:

| Pienoisohjelma                         | Kuvaus                                                                                |
| -------------------------------------- | ------------------------------------------------------------------------------------- |
| **Yhteenvetokortit**                   | Pyyntöjen kokonaismäärä, kokonaiskustannukset, tokenien kokonaismäärä, onnistumisaste |
| **Päivittäinen trendikaavio**          | Kustannukset + tokenit päivittäin, pinottuna malleittain                              |
| **Aktiivisuuden lämpökartta**          | Vuorokauden tunti × viikonpäivä -ruudukko, väri = pyyntöjen määrä                     |
| **Mallikohtainen erittely**            | Ympyräkaavio kustannuksista malleittain                                               |
| **Palveluntarjoajakohtainen erittely** | Pylväskaavio pyynnöistä palveluntarjoajittain                                         |
| **Eniten käytetyt API-avaimet**        | Taulukko 10 suurimmat kustannukset aiheuttaneesta avaimesta                           |
| **Virheanalyysi**                      | Virheaste ajan kuluessa, yleisimmät virheluokat                                       |

### Ohjelmallinen käyttö

````ts
import { computeAnalytics } from "@/lib/usageAnalytics";

const analytics = await computeAnalytics(
  history,              // käyttöhistorian tietueet
  "7d",                 // aikaväli: "1d" | "7d" | "30d" | "90d" | "ytd" | "all" | "custom"
  connectionMap,        // palveluntarjoajan yhteyskartta (connectionId → tilin nimi)
  {
    startDate: "2025-01-01",  // valinnainen: "custom"-aikavälille
    endDate: "2025-06-01",   // valinnainen: "custom"-aikavälille
  }
);

console.log(analytics.summary.totalCost);   // 12.34 (senttiä)
console.log(analytics.byModel[0]);           // { model, cost, requests, promptTokens, completionTokens }

## Kiintiöiden valvonta

API-avainkohtaista kiintiötä valvotaan kahdessa kohdassa:

1. **Pehmeä raja** (`quotaWarnAt`): varoitus hallintapaneelissa, kun käyttö ylittää kynnysarvon
2. **Kova raja** (`quotaLimit`): pyyntö hylätään HTTP 429 -vastauksella, kun raja ylittyy

### Määritys

```ts
// API-avainkohtaisesti
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — näytä varoitus
  quotaLimit: 10_00,    // $10.00 — ehdoton pysäytys
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### Valvonnan kulku

```
Pyyntö ──▶ quotaCheck()
              │
              ├── Rajan sisällä?  ──▶ salli
              │
              └── Raja ylitetty?  ──▶ 429 Too Many Requests
                                   Retry-After-otsakkeella
```

### Kiintiön tilannevedokset

`quotaSnapshots`-taulukko tallentaa **kiintiön historiallisen tilan** trendianalyysiä varten:

| Kenttä | Kuvaus |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | Seurattava avain |
| `window` | "day" | "week" | "month" |
| `used` | Tällä jaksolla kertyneet kustannukset (sentteinä) |
| `limit` | Raja (sentteinä) |
| `resetAt` | Jakson nollautumisajankohta |
| `createdAt` | Tilannevedoksen tallennusajankohta |

Tilannevedos tallennetaan **jokaisesta pyynnöstä**, jonka kustannukset ovat > 0, ja niitä käytetään seuraaviin tarkoituksiin:

- Kiintiön edistymispalkin esittäminen hallintapaneelissa
- Kiintiön 30 päivän trendikaavioiden näyttäminen
- Hälytysten käynnistäminen, kun käyttö lähestyy rajaa

## Säilytys ja siivous

Käyttötietojen määrä kasvaa noin 1–10 kt pyyntöä kohden. Suuressa mittakaavassa tämä voi olla merkittävä määrä.

### Säilytysasetukset

Käyttöhistorian säilytys määritetään käyttöliittymän tietokanta-asetuksissa tai päätepisteen `/api/settings/database` kautta.

Oletusarvoisesti käyttöhistoriaa säilytetään **90 päivää**.

### Siivous

Vanhat tietueet siivotaan tiedoston `src/lib/db/cleanup.ts` avulla:

- Taustalla toimiva cron-prosessi käynnistää siivouksen
- Poistaa taulusta `usage_history` tietueet, jotka ovat vanhempia kuin määritetyn `usageHistory`-säilytysasetuksen sallima aika

### Tallennustilan arviointi

| Pyyntömäärä           | Tallennustila 30 päivälle | Tallennustila 90 päivälle |
| --------------------- | ------------------------- | ------------------------- |
| 100 pyyntöä/päivä     | ~3 Mt                     | ~9 Mt                     |
| 1 000 pyyntöä/päivä   | ~30 Mt                    | ~90 Mt                    |
| 10 000 pyyntöä/päivä  | ~300 Mt                   | ~900 Mt                   |
| 100 000 pyyntöä/päivä | ~3 Gt                     | ~9 Gt                     |

Jos liikennemäärä on erittäin suuri, harkitse seuraavia:

- Säilytysajan lyhentäminen tietokanta-asetuksissa
- Taulun `aggregated_metrics` käyttäminen raakatietueiden sijaan (vain analytiikkaan)

### 1. Käytä sopivaa mallia

```bash
# Nopea vastaus — käytä halpaa ja nopeaa mallia
curl -d '{"model":"auto/fast","messages":[...]}'

# Monimutkainen tehtävä — panosta laatuun
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. Ota välimuisti käyttöön

Anthropicin kehotteiden välimuisti säästää **90% toistuvan kontekstin kustannuksista**:

```ts
// Välimuisti toimii automaattisesti — sisällytä vain sama laaja järjestelmäkehote
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // Tallennetaan välimuistiin automaattisesti
  messages: [{ role: "user", content: "..." }],
});
```

### 3. Käytä pakkausta

RTK + Caveman -pakkaus säästää **15-95% kustannuksista istunnoissa, joissa käytetään paljon työkaluja**:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. Aseta avainkohtaiset kiintiöt

Aseta aina `quotaLimit`, jotta kustannukset eivät karkaa käsistä:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // Enimmäiskustannus 10 dollaria kuukaudessa
```

### 5. Tarkista suurimmat kuluttajat

Ryhmittele API-avaimen mukaan ja lajittele kustannusten perusteella hallintapaneelissa tai käyttämällä päätepistettä **`/api/usage/analytics`**:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## Vianmääritys

### "Kustannukset ovat odotettua suuremmat"

1. Tarkista **`/api/usage/analytics?groupBy=model`** — etsi kallis malli
2. Tarkista **`/api/usage/analytics?groupBy=apiKey`** — etsi suurkuluttaja
3. Varmista, että hintatiedot ovat ajan tasalla: `POST /api/pricing/sync`

### "Tietueita puuttuu"

- Tarkista tietokannan säilytysasetukset kohdasta Hallintapaneeli → Tietokanta → Siivous — ajoittainen siivoustehtävä poistaa vanhat tietueet (`src/lib/db/cleanup.ts`)
- Tarkista virheet tiedostoista `src/lib/db/usage*.ts` — tietokantaan kirjoittamisen virheet kirjataan lokiin, mutta niitä ei näytetä
- Varmista, että pyyntö todella saavutti `chatCore`-toiminnon — tarkista yhdistelmäreititys

### "Kiintiötä ei noudateta"

- Tarkista avaimen `quotaLimit`-asetus
- Varmista, että `quotaWindow` on asetettu oikein
- Etsi `quotaSnapshots`-tietueita — niitä pitäisi syntyä jokaisesta pyynnöstä
