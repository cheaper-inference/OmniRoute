Sulautetut palvelut ovat paikallisesti asennettuja prosessin sivuvaunutyökaluja, jotka OmniRoute asentaa, valvoo ja paljastaa ensiluokkaisina reitityskohteina. Toisin kuin ulkoiset palveluntarjoajat (joihin päästään Internetin kautta API -näppäimien kautta), sulautetut palvelut toimivat samassa koneessa kuin OmniRoute ja kommunikoivat silmukan kautta.

Kaikki kahdeksan noudattavat samaa valvontamallia:

- OmniRoute asentaa ne `DATA_DIR/services/{name}/` n alle (eristettynä OmniRoute:n omasta `package.json`)
- OmniRoute synnyttää ja valvoo niitä lapsiprosesseina
- OmniRoute ruiskuttaa lyhytaikaisen API -avaimen lapsen ympäristöön ja pyörittää sitä ilman seisokkeja (tarvittaessa)
- Kaikki hallintareitit (`/api/services/*`) ovat**LOCAL_ONLY** — käytettävissä vain silmukan kautta (kova sääntö 17)

| Päätös                                       | Arvo                                                                                   |

| Kulutustila                                  | Palveluntarjoaja on rekisteröity reititysmoottoriin nimellä `9router/{sub}/{model}`    |

| Automaattinen käynnistys                     | Vaihda palvelukohtaisesti, oletus OFF                                                  |

```
│  src/app/(dashboard)/dashboard/providers/services/                 │

│    │                          MuxServiceTab                        │
│    └── components/            ServiceStatusCard, ServiceLifecycleButtons,│
│                               ServiceLogsPanel, ApiKeyCard, ...    │
└──────────────────────┬─────────────────────────────────────────────┘
                       │ HTTP (Next.js fetch)
┌──────────────────────▼─────────────────────────────────────────────┐
│  Layer 2 — API (LOCAL_ONLY — loopback only)                        │
│                                                                    │
│  /api/services/9router/{install|start|stop|restart|update|         │
│                          rotate-key|status|auto-start|logs}        │

│    (reverse HTTP + WebSocket proxy → 9Router upstream)             │
│                                                                    │
│  Gate: LOCAL_ONLY_API_PREFIXES includes "/api/services/" and       │
│        "/dashboard/providers/services/*/embed/"                    │

┌──────────────────────▼─────────────────────────────────────────────┐

│                                                                    │

│  installers/        ninerouter.ts, cliproxy.ts, mux.ts, openwa.ts  │
│                      (installer adapters)                          │

┌──────────────────────▼─────────────────────────────────────────────┐
│  Layer 4 — Provider / Routing                                      │
│                                                                    │
│  open-sse/executors/ninerouter.ts                                  │
│    Re-looks up port and API key per-request (no caching).          │
│    Strips "9router/" prefix from model id before proxying.         │
│    Returns 503 service_not_running if supervisor not in "running". │
│                                                                    │
│  src/shared/constants/providers.ts                                 │
│    Entry for "9router": isEmbeddedService: true                    │
│                                                                    │
│  open-sse/config/providerRegistry.ts                               │
│    Models stored as "9router/{sub}/{model}" (prefixed).            │

│                                                                    │
│  Mux is lifecycle-managed ONLY (Layers 1-3) — it is an agent-       │
```

## 3. Elinkaaren tilakone

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
               kuntotarkistus OK    │         kaatuminen / SIGTERM│
                               ┌────▼─────┐  (poistuu 5 s:ssa)  │
                               │ running  │── kaatuminen ───────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

Tilat tallennetaan `version_manager`-tietokantatauluun (`status`-sarake) ja peilataan
`ServiceSupervisor`-komponentin muistitilaan. Muistitila on ensisijainen totuuden lähde
käynnissä olevalle prosessille; tietokantatila toimii pysyvänä varatilana käynnistyksen yhteydessä.

### Tilasiirtymät

| Mistä           | Tapahtuma                            | Mihin                      |
| --------------- | ------------------------------------ | -------------------------- |
| `not_installed` | `install()` onnistuu                 | `stopped`                  |
| `stopped`       | `start()` kutsutaan                  | `starting`                 |
| `starting`      | kuntotarkistus palauttaa 200         | `running`                  |
| `starting`      | prosessi poistuu ennen tervehtymistä | `error`                    |
| `running`       | `stop()` kutsutaan                   | `stopping` → `stopped`     |
| `running`       | prosessi poistuu odottamatta (< 5 s) | `error` (nopea kaatuminen) |
| `running`       | prosessi poistuu odottamatta (> 5 s) | `error`                    |
| `error`         | `start()` kutsutaan                  | `starting`                 |
| mikä tahansa    | `stop()` tilassa `stopping`          | ei toimintoa               |

### Toimintolukko

`ServiceSupervisor` suorittaa elinkaaritoiminnot sarjamuotoisesti asynkronisen toimintolukon
(`withLock()`) avulla. Samanaikaiset `start()`-kutsut samalle valvojalle johtavat täsmälleen
yhden prosessin käynnistämiseen; toinen kutsuja odottaa ja palauttaa nykyisen tilan. Tämä estää
kilpailutilanteet esimerkiksi silloin, kun automaattinen käynnistys ja käyttöliittymän painike aktivoituvat samanaikaisesti.

## 4. API viittaus

Kaikki `/api/services/` alaiset reitit ovat**LOCAL_ONLY** (vain silmukka, kova sääntö #17). Ei-paluupyynnöt saavat `403 LOCAL_ONLY` todennustunnuksesta riippumatta.

### 4.1 9Reitittimen päätepisteet (11 reittiä)

#### `POST /api/services/9router/install`

Asenna 9Router npm:stä. Luo `DATA_DIR/services/9router/` omilla `package.json` llä ja `node_modules/`. Ei ole ristiriidassa OmniRoute:n omien depsien kanssa.

**Pyynnön runko** (kaikki valinnaiset):

```json
{ "version": "latest" }
```

| Ala       | Tyyppi   | Oletus     | Kuvaus                                    |
| --------- | -------- | ---------- | ----------------------------------------- |
| `version` | `string` | `"latest"` | npm version tag tai semver asennettavaksi |

**Vastaukset:**

| Status | Kuvaus                                                          |
| ------ | --------------------------------------------------------------- |
| `200`  | `{ ok: true, installedVersion: "x.y.z", path: "..." }`          |
| `400`  | Virheellinen pyynnön runko (Zod -vahvistusvirhe)                |
| `409`  | Asennus jo (lukko pidetty)                                      |
| `500`  | npm-asennus epäonnistui — katso `message` :n ystävällinen virhe |

**Huomautuksia:** Käyttää `execFile('npm', [...])` — ei kuorta, ei interpolointia (kova sääntö #13). EACCES virheet tulevat esiin ystäväviesteinä.

---

#### `POST /api/services/9router/start`

Käynnistä 9Router. Rekisteröi valvojan, jos ei ole jo rekisteröitynyt, ja soittaa sitten `supervisor.start()`. Idempotentti jo käynnissä ollessaan.

**Pyynnön runko:** ei yhtään

**Vastaukset:**

| Status | Kuvaus                                                     |
| ------ | ---------------------------------------------------------- |
| `200`  | `ServiceStatus` objekti (katso kaavio alla)                |
| `409`  | 9Reititintä ei ole asennettu (`status: "not_installed"`)   |
| `503`  | Käynnistys epäonnistui (prosessivirhe — katso `lastError`) |

**ServiceStatus -skeema:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

---

#### `POST /api/services/9router/stop`

Pysäytä kauniisti 9Router. Lähettää SIGTERM, odottaa 15 s ja sitten SIGKILL, jos on vielä elossa. Idempotentti, kun se on jo pysähtynyt.

**Pyynnön runko:** ei yhtään

**Vastaukset:**

| Status | Kuvaus                               |
| ------ | ------------------------------------ |
| `200`  | `ServiceStatus` (tila: "pysähtynyt") |
| `503`  | Pysäytys epäonnistui odottamatta     |

---

#### `POST /api/services/9router/restart`

Vastaa `stop()` ja sitten `start()` käyttölukon alla.

**Pyynnön runko:** ei yhtään

**Vastaukset:** sama kuin `start` (palauttaa lopullisen `ServiceStatus`).

---

#### `POST /api/services/9router/update`

Päivittää 9Routerin uudempaan npm-versioon. Jos palvelu on käynnissä, se pysäytetään ensin, npm-asennus suoritetaan (uudemman version asentaminen paikalleen) ja sitten palvelu käynnistetään uudelleen.

**Pyynnön runko** (kaikki valinnaiset):

```json
{ "version": "latest" }
```

**Vastaukset:**

| Status | Kuvaus                                                          |
| ------ | --------------------------------------------------------------- |
| `200`  | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400`  | Virheellinen runko                                              |
| `500`  | npm päivitys epäonnistui                                        |

---

#### `POST /api/services/9router/rotate-key`

Luo uuden API avaimen 9Routerille, salaa sen lepotilassa ja käynnistää palvelun uudelleen (jos se on käynnissä), jotta se poimii uuden avaimen ympäristöstään. Vanha avain mitätöityy välittömästi.

**Pyynnön runko:** ei yhtään

**Vastaukset:**

| Status | Kuvaus                                     |
| ------ | ------------------------------------------ |

### 4.9 Käänteinen välityspalvelin (9reitittimen kojelautaan upotettu)

Kojelauta upottaa 9Router web UI -kehyksen iframe-kehykseen sisäisen käänteisen välityspalvelimen kautta osoitteessa:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

Tämä välityspalvelin:

- Välittää pyynnön `http://127.0.0.1:{port}/{path}` (vain silmukka)
- Poistaa saapuvat `cookie` ja `authorization` otsikot (ei OmniRoute istunnon vuotoa)
- Ruiskuttaa `Authorization: Bearer {apiKey}` 9reitittimen todennusta varten
- Poistaa vastauksesta `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*`
- Kirjoittaa uudelleen HTML -vastaukset injektoimaan `<base href>` ja normalisoimaan absoluuttiset polut (`/foo` → `/dashboard/.../embed/foo`)

WebSocket päivitykset sulautettuun kojelautaan hoitaa kumppanipalvelin erillisessä portissa (katso `src/lib/services/embedWsProxy.ts`).

**Turvallisuus:** Upotetut välityspalvelimen reitit luokitellaan `LOCAL_ONLY_API_PREFIXES` kategoriaan, ja niihin pääsee vain silmukan kautta. Hyökkääjä, joka saa JWT Cloudflare/Ngrok tunnelin kautta, ei voi käyttää välityspalvelinta sulautettuihin palveluihin.

## 5. Tietoturva

### LOCAL_ONLY-valvonta (ehdoton sääntö #17)

Kaikki reitit polkujen `/api/services/` ja `/dashboard/providers/services/*/embed/` alla on
luokiteltu LOCAL_ONLY-reiteiksi tiedostossa `src/server/authz/routeGuard.ts`. Loopback-tarkistus
suoritetaan ehdoitta ennen mitään todennushaaraa:

```
pyyntö saapuu
  → isLocalOnlyPath(path)?
      → ei-loopback → 403 LOCAL_ONLY (aina ennen todennustarkistusta)
      → loopback    → jatka normaaliin todennukseen
```

Tämä estää vuotanutta JWT:tä (esim. tunnelin kautta) käynnistämästä `npm install` -komentoa
tai prosesseja. Katso täydellinen tasomatriisi tiedostosta
`docs/security/ROUTE_GUARD_TIERS.md`.

### API-avaimen syöttäminen

9Router ja Mux edellyttävät API-avainta/bearer-tokenia omille HTTP-päätepisteilleen.
OmniRoute:

1. Luo avaimen kutsulla `crypto.randomBytes(32).toString("base64url")` käyttäen
   palvelukohtaista etuliitettä (`nr_` 9Routerille, `mx_` Muxille).
2. Salaa sen levossa AES-256-GCM:llä (sama salausmenetelmä, jota käytetään palveluntarjoajien tunnistetietoihin).
3. Purkaa salauksen ja syöttää sen ympäristömuuttujana prosessin käynnistyksen yhteydessä —
   `NINEROUTER_API_KEY` 9Routerille, `MUX_SERVER_AUTH_TOKEN` Muxille (ei koskaan CLI-
   valitsimena, joten token ei koskaan näy `ps`-tulosteissa/prosessiluetteloissa).
4. Ei koskaan palauta selväkielistä avainta missään HTTP-vastauksessa.

CLIProxyAPI saa erillisen datatason avaimen, joka syötetään prosessin käynnistyksen yhteydessä
(`needsApiKey: true` — käytetään mallien synkronointiin sovittimen kanssa).

### SSRF-suojaus

Käänteinen HTTP-välityspalvelin (`/dashboard/.../embed/[...path]`) on kovakoodattu välittämään
pyyntöjä vain osoitteeseen `http://127.0.0.1:{port}`. Se ei koskaan seuraa uudelleenohjauksia
loopback-alueen ulkopuolisiin kohteisiin. `ssrf-req-filter`-kirjastoa käytetään hylkäämään kaikki
ylävirran URL-osoitteet, jotka ratkeavat loopback-alueen ulkopuolelle.

### Komentoturvallisuus (ehdoton sääntö #13)

`npm install` suoritetaan kutsulla `execFile('npm', ['install', pkg, '--prefix', dir])` —
ei malliliteraaleja, komentotulkkia eikä ulkoisten polkujen interpolointia komentomerkkijonoon.
Ajonaikaiset arvot (portit, API-avaimet) välitetään aliprosessin `env`-objektin kautta.

### Virheiden puhdistus (ehdoton sääntö #12)

Kaikki polun `/api/services/*` virhevastaukset kulkevat funktion `buildErrorBody()` tai
`sanitizeErrorMessage()` kautta. Raakoja `err.stack`- ja `err.message`-arvoja ei koskaan palauteta
sellaisinaan kutsujalle.

#### Liitettävä palveluntarjoajaliitännäisen sopimus (vaihe 1, #7333)

`src/lib/services/providerPlugins/` esittelee `ServiceProviderPlugin`-sopimuksen, joka
kokoaa taustajärjestelmän `bootstrap.ts`-tiedoston `ServiceEntry`-kentät ja
`serviceBackends.ts`-tiedoston manifestimallin kentät yhdeksi objektiksi sen sijaan, että
saman taustajärjestelmän rakenne ilmaistaisiin erikseen kahdessa toisiinsa liittymättömässä
tiedostossa. Tätä kirjoitettaessa **vain `9router` on migroitu** — `bootstrap.ts` johtaa
`SERVICES[]`-merkintänsä kutsusta `getServiceProviderPlugin("9router")`
(`src/lib/services/providerPlugins/registry.ts`) ja aiheuttaa käynnistysvirheen, jos
liitännäinen joskus puuttuu. `cliproxy`, `mux` ja `bifrost` käyttävät edelleen aiempia
sisäisiä `SERVICES[]`-literaaleja muuttumattomina.

Myös `open-sse/config/providerPluginManifest.ts` sai täydentävän
`createServiceBackendManifestEntry(pluginId, template)`-apufunktion, joka muodostaa
oikeamuotoisen `ProviderPluginManifestEntry`-merkinnän
`SERVICE_BACKEND_MANIFEST_TEMPLATE`-merkinnästä — sitä **ei** ole vielä kytketty mihinkään
aktiiviseen pyyntöpolkuun (ei funktioon `generateProviderPluginManifestFromRegistry()`
eikä polkuun `/v1/providers/[provider]/models`); tämä jää jatkotoimeksi, kun sopimus on
todistettu toimivaksi toisella taustajärjestelmällä.

Seuraavat tehtävät on siirretty jatko-PR:iin ja niitä seurataan ongelmassa #7333:
`cliproxyapi`:n migrointi saman rekisterin kautta, `mux`/`bifrost`:n yleistäminen
`ServiceBackendPluginId`-unionityyppiin, suorittimen reitityksen erityiskäsittelyn
(`open-sse/executors/index.ts`, `open-sse/handlers/chatCore/executorProxy.ts`) sisällyttäminen
liitännäissopimukseen sekä `createServiceBackendManifestEntry()`-funktion kytkeminen
aktiiviseen manifestien/mallien koodipolkuun.

```
start/route.ts     POST — kutsuu supervisor.start()
stop/route.ts      POST — kutsuu supervisor.stop()
restart/route.ts   POST — kutsuu supervisor.restart()
update/route.ts    POST — kutsuu installer.update()
status/route.ts    GET  — yhdistää ajantasaisen ja tietokannan tilan
auto-start/route.ts POST — vaihtaa auto_start-lipun tilaa
```

Jaettu `GET /api/services/[name]/logs`-reitti on jo kytketty — siihen ei tarvita
muutoksia.

Delegoi kaikki virhevastaukset funktioiden `createErrorResponse()` / `buildErrorBody()` kautta.

## 7. Vianmääritys

### Palvelu ei käynnisty

**Oireet:** Käynnistyspainike palauttaa 503-virheen, ja tilaksi jää `"error"` tai `"starting"`.

**Tarkistuslista:**

1. Tarkista `GET /api/services/{name}/logs` (tai hallintapaneelin Logs-paneeli). Etsi
   rivejä, kuten `Error: ENOENT`, `address already in use` tai `Cannot find module`.
2. Varmista, että `npm` on PATH-muuttujassa: suorita `which npm` samalla käyttäjätilillä, jolla OmniRoute suoritetaan.
3. Varmista, että palvelu on asennettu: tarkista `GET /api/services/{name}/status`-vastauksen
   `installedVersion`. Jos se on `null`, suorita ensin asennus.
4. Tarkista, että `DATA_DIR/services/{name}/node_modules/` on olemassa eikä ole tyhjä.
5. Tarkista tilavastauksen `lastError`-kentästä puhdistettu lopettamisen syy.

---

### Kylmäkäynnistys on hidas (> 10 s ennen `running`-tilaa)

**Oireet:** Tilaksi jää pitkäksi aikaa `"starting"`, ennen kuin se vaihtuu tilaksi `"running"` tai `"error"`.

**Selitys:** 9Routerin kylmäkäynnistykseen kuuluu suurten riippuvuuspuiden tuonti (DNS-,
tunneli- ja MITM-moduulit). Oletusarvoinen kuntotarkistusväli on 2 s, ja yrityksiä tehdään 3 ennen kuin
valvoja ilmoittaa aikakatkaisusta (mutta jatkaa kyselyä).

**Korjaus:** `healthIntervalMs` ja `waitForHealthy`-aikakatkaisu
(`healthIntervalMs * 3`) voidaan määrittää tiedostossa `bootstrap.ts`. Jos palvelun
käynnistyminen kestää pidempään, suurenna `healthIntervalMs` arvoon 5000 ja `stopTimeoutMs` arvoon 30 000.

---

### Porttiristiriita (`EADDRINUSE`)

**Oireet:** Lokeissa näkyy `address already in use :::20130`.

**Syyt:**

- Toinen prosessi käyttää jo porttia 20130.
- Edellistä 9Router-prosessia ei pysäytetty kokonaan (zombie-PID).

**Korjaus:**

1. Vaihda oletusportti `.env`-tiedoston `NINEROUTER_PORT`-ympäristömuuttujalla.
2. Etsi ja lopeta ristiriidan aiheuttava prosessi: `lsof -ti :20130 | xargs kill -9`.
3. Portti voidaan määrittää palvelukohtaisesti tiedostossa `bootstrap.ts` `port`-kentän avulla.

**Huomautus:** 9Router käyttää oletuksena nimenomaan porttia 20130 välttääkseen
ristiriidan OmniRouten oletusportin 20128 kanssa.

---

### Käyttö estetty (EACCES) asennuksen aikana

**Oireet:** Asennus palauttaa 500-virheen, ja lokeissa näkyy `EACCES` tai `permission denied`.

**Syyt:**

- OmniRoute-prosessilla ei ole kirjoitusoikeutta `DATA_DIR`-hakemistoon tai sen ylähakemistoon.
- Sovellusta suoritetaan rootless Dockerissa ilman kirjoitusoikeutta liitettyyn taltioon.

**Korjaus:**

1. Tarkista `DATA_DIR` (oletus: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. Varmista, että OmniRoute-prosessin käyttäjä omistaa hakemiston: `chown -R $USER ~/.omniroute/`
3. Varmista Dockerissa, että taltioliitoksella on oikeat käyttöoikeudet kontin käyttäjälle.

---

### Päivitys epäonnistuu (`npm install` -aikakatkaisu tai verkkovirhe)

**Oireet:** Päivitys palauttaa 500-virheen ja `InstallError`-ilmoituksen, ja lokeissa näkyy verkon aikakatkaisu.

**Tarkistuslista:**

1. Varmista, että npm-rekisteri on tavoitettavissa: `npm ping`.
2. Tarkista yritysvälityspalvelimen asetukset: `npm config get proxy`, `npm config get https-proxy`.
3. Kokeile asennusta manuaalisesti: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. Jos järjestelmä on eristetyssä verkossa, lataa tarball-paketti etukäteen ja käytä komentoa `npm install /path/to/tarball.tgz`.

---

### Palvelun tilaksi tulee heti käynnistyksen jälkeen `"error"` (nopea kaatuminen)

**Oireet:** Tila vaihtuu `"starting"`-tilasta `"error"`-tilaan alle 5 sekunnissa.
`lastError` näyttää `"Fast crash (exited with code 1)"`.

**Tarkistuslista:**

1. Lue lokin loppuosa kokonaisuudessaan: `GET /api/services/{name}/logs?tail=500`.
2. Yleinen syy: palvelun edellyttämät ympäristömuuttujat puuttuvat.
3. 9Router: varmista, että `NINEROUTER_DISABLE_MITM=true` ja
   `NINEROUTER_DISABLE_TUNNEL=true` ovat käynnistettäessä välitetyssä ympäristössä (katso
   tiedoston `installers/ninerouter.ts` tunnistetta `resolveSpawnArgs`).

## 8. Usein kysytyt kysymykset

**K: Voinko sallia sulautettujen palvelujen päätepisteiden käytön muille kuin loopback-asiakkaille?**

Et. LOCAL_ONLY-taso on tarkoituksellinen (ehdoton sääntö #17). Reitit, jotka voivat suorittaa
`npm install` -komennon tai käynnistää `node`-prosesseja, eivät saa olla muiden kuin loopback-
asiakkaiden saavutettavissa, koska tunnelin (Cloudflare, Ngrok, Tailscale) kautta vuotanut JWT
mahdollistaisi muuten mielivaltaisten prosessien käynnistämisen. Reitille
`/api/services/` ei ole poikkeusta — toisin kuin `/api/mcp/`, se ei kuulu manage-käyttöalueen
ohitusluetteloon. Katso `docs/security/ROUTE_GUARD_TIERS.md`.

---

**K: Ovatko 9Router ja CLIProxyAPI käytettävissä tuotanto- tai pilviympäristöissä?**

Kyllä. Molemmat palvelut noudattavat samaa ensisijaisesti paikallista mallia kuin OmniRoute itse. Ne toimivat
samalla koneella ja viestivät loopback-yhteyden kautta. Tässä ”tuotanto” tarkoittaa VPS-palvelinta
tai paikallista palvelinta, johon OmniRoute on otettu käyttöön, ei pilvipalveluntarjoajan etäpalvelua.

---

**K: Miten teen supervisorin vianmäärityksen?**

1. Seuraa SSE-lokivirtaa: `curl -N http://localhost:20128/api/services/9router/logs`.
2. Tarkista OmniRouten pino-tulosteen rakenteiset lokit suodatettuina
   `service:supervisor`-nimiavaruuden perusteella.
3. Tarkista tietokantarivi: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. Käytä pyyntöä `GET /api/services/9router/status`, jotta näet nykyisen ajonaikaisen tilan, PID:n, terveystilan
   ja `lastError`-arvon yhdellä kutsulla.

---

**K: Supervisor näyttää arvon `health: "degraded"` tai `health: "unknown"`, mutta tila on `"running"`. Onko tämä ongelma?**

`"degraded"` tarkoittaa, että terveystarkistus palautti muun kuin 200-vastauksen. `"unknown"` tarkoittaa, ettei
yksikään tarkistus ole vielä valmistunut (kilpatilanne ensimmäisen kyselyn kanssa). Molemmat ovat tilapäisiä käynnistyksen aikana.
Jos terveystila pysyy arvossa `"degraded"` yli `healthIntervalMs * 3` ms
tilan vaihtumisesta arvoon `"running"`, sulautettu palvelu on käynnissä, mutta sen HTTP API ei vastaa. Tarkista,
onko tilavastauksessa ilmoitettu portti oikea ja kuunteleeko palvelu todella
kyseistä porttia.

---

**K: Voinko vaihtaa 9Routerin API-avaimen ilman täydellistä uudelleenkäynnistystä?**

Et. API-avain välitetään 9Routerille ympäristömuuttujan kautta prosessin käynnistyksen yhteydessä.
Ympäristömuuttujia ei voi muuttaa käynnissä olevassa prosessissa. `POST .../rotate-key`
pysäyttää ja käynnistää palvelun automaattisesti uudelleen uuden avaimen käyttöönottoa varten. Avaimen vaihto
tulee voimaan palvelun `stopTimeoutMs`-ajan (oletusarvo 15 s) ja sen käynnistymisajan
kuluessa.

---

**K: Mikä on rengaspuskurin raja ja mitä tapahtuu sen täyttyessä?**

Jokaisella palvelulla on oma 5 MB:n rengaspuskurinsa. Kun puskuri on täynnä, vanhimmat
lokirivit poistetaan uusien tieltä. SSE:n `snapshot`-tapahtuma palauttaa
uusimmat rivit `tail`-rajan puitteissa. Lokeja ei tallenneta levylle, ellei
`logsBufferPath`-arvoa ole asetettu tietokantarivillä.
