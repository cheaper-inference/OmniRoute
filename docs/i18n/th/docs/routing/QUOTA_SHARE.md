## ภาพรวม

Quota Sharing Engine กระจายโควตาตามเวลาของผู้ให้บริการ (เช่น หน้าต่างเวลา 5 ชั่วโมงของ Codex,
Kimi 1500 คำขอ/ชม.) อย่างเป็นธรรมระหว่าง API key หลายรายการที่ใช้การเชื่อมต่อ
เดียวกัน

**ปัญหาที่ระบบนี้แก้ไข:** OmniRoute ทำหน้าที่เป็นพร็อกซีให้ API key หลายรายการกับบัญชี
ผู้ให้บริการต้นทางเดียวกัน หากไม่มีตรรกะการแบ่งปัน การส่งคำขอจำนวนมากอย่างฉับพลันจากคีย์ A อาจใช้
โควตาของผู้ให้บริการสำหรับชั่วโมงนั้นจนหมด ทำให้คีย์ B และ C ถูกบล็อกจนกว่าหน้าต่างเวลาจะรีเซ็ต
เอนจินป้องกันปัญหานี้ด้วยวิธีต่อไปนี้:

1. ติดตามการใช้งานแบบต่อเนื่องของแต่ละคีย์ในแต่ละมิติ (%, คำขอ, โทเค็น, $)
2. ใช้อัลกอริทึมการแบ่งส่วนอย่างเป็นธรรมที่ไม่ปล่อยให้ทรัพยากรว่าง: คีย์สามารถยืมส่วนแบ่งที่ไม่ได้ใช้งาน
   ได้ตราบใดที่พูลส่วนกลางยังไม่อิ่มตัว
3. บังคับใช้ผลลัพธ์ในเส้นทางหลัก (`chatCore.ts`) ก่อนที่คำขอ
   จะไปถึงตัวดำเนินการต้นทาง

## อัลกอริทึม: การแบ่งปันงานอย่างยุติธรรม-การอนุรักษ์

ดำเนินการใน `src/lib/quota/fairShare.ts`

### โหมด

| เงื่อนไข                                   | โหมด        | พฤติกรรม                                               |
| ------------------------------------------ | ----------- | ------------------------------------------------------ |
| `globalUsedPercent < saturationThreshold`  | **ใจกว้าง** | คีย์สามารถยืมได้ถึงขีดจำกัดทั่วโลกลบด้วยยอดรวมที่ใช้ไป |
| `globalUsedPercent >= saturationThreshold` | **เข้มงวด** | บังคับใช้การแบ่งส่วนยุติธรรมส่วนบุคคลอย่างเคร่งครัด    |

ค่าเริ่มต้น `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`)

สองโหมดนี้อธิบายพูลในโหมดยืมดีฟอลต์ `saturation` พูลในโหมด `consent` จะใช้กฎที่เข้มงวดเสมอ ไม่ว่าความอิ่มตัวจะเป็นอย่างไร ดู [การให้กู้ยืมที่ยินยอม (การเลือกเข้าร่วมแบบต่อกลุ่ม)](#consented-lending-per-pool-opt-in)

### การตัดสินใจต่อมิติ

สำหรับแต่ละมิติที่ใช้งานอยู่ในพูล กลไกจะคำนวณ:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = current rolling value for this key (from QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

สำหรับมิติข้อมูล `percent` นั้น `consumed` จะมาจากหนังสือระบุแหล่งที่มาแทน (ดู [มิติข้อมูลเปอร์เซ็นต์: การระบุแหล่งที่มาต่อคีย์](#percent-dimensions-per-key-attribution) )

แล้ว:

- **`policy = hard`** : ถ้า `consumed > fairShareAllowed` และโหมดเข้มงวด →** ปิดกั้น** .
- **`policy = soft`** : ถ้า `consumed > fairShareAllowed` และโหมดเข้มงวด →** ลงโทษ** (ลดลำดับความสำคัญในคอมโบ ห้ามฮาร์ดบล็อค)
- **`policy = burst`** : อนุญาตในขณะที่ยังมีช่องว่างทั่วโลกโดยไม่คำนึงถึงส่วนแบ่งที่ยุติธรรม

### หมวกสัมบูรณ์

`capValue` + `capUnit` ในการจัดสรรเป็นเพดานแข็งที่ไม่ขึ้นกับโหมดหรือนโยบาย มิติใดๆ ที่ `consumed >= capValue` เสมอ** บล็อก** คำขอ สำหรับ `percent` cap นั้น `consumed` เป็นเพียงส่วนที่ประกอบกับคีย์เท่านั้น

### การตรวจสอบหลายมิติ

คำขอจะถูกบล็อกหาก** ใดๆ** มิติในสระก็จะขวางกั้นไว้ มิติข้อมูลเป็นอิสระ — ความสิ้นเปลือง 5h% ไม่ส่งผลต่อมิติ % รายสัปดาห์

### การยืม

ในโหมดใจกว้าง คีย์ที่มีการจัดสรรน้อยเกินไปสามารถใช้ส่วนเกินจากการแชร์ที่ไม่ได้จัดสรรของคีย์อื่นได้ สูตรคือ:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

ที่ไหน `consumedByOtherKeys = consumedTotal - consumedByThisKey` teto global (พูล `limit` สำหรับมิตินั้น) จะเป็นเพดานแข็งเสมอ

### การให้กู้ยืมที่ยินยอม (การเลือกเข้าร่วมต่อพูล)

แต่ละพูลมีโหมดยืม `saturation` เป็นค่าเริ่มต้นและคงกฎข้างต้นไว้ ในโหมด `consent` คีย์ `hard` จะส่งผ่านการแบ่งใช้เฉพาะภายในความจุที่คีย์อื่นยินยอมให้ยืมเท่านั้น ผู้ดูแลระบบจะตั้งค่าโหมดของแต่ละพูล ผู้ถือกุญแจแต่ละรายจะกำหนดความยินยอมของตนเองผ่าน [การยินยอมให้ยืม](#lending-consent)

ความยินยอมคือเปอร์เซ็นต์ตั้งแต่ 0 ถึง 100 และกำหนดเวลาที่ไม่บังคับในหน่วยมิลลิวินาที กุญแจสำคัญจะให้เปอร์เซ็นต์ของส่วนแบ่งที่ไม่ได้ใช้งานในขณะที่กำหนดเวลาอยู่ในอนาคต

สำหรับมิติหนึ่ง `L` คือขีดจำกัดที่มีผล: ขีดจำกัดของแผนคูณกับบัญชีในกลุ่ม ประตูคำนวณสำหรับรหัสที่ร้องขอ:

```
share_k         = w_k / 100 × L
idle_k          = max(0, share_k − consumed_k)
lent            = Σ over the other keys of lend_k / 100 × idle_k
taken           = Σ over the other keys of max(0, consumed_k − share_k)
borrowAvailable = max(0, lent − taken)
```

`w_k` คือน้ำหนักของคีย์ หรือ `100 / n` สำหรับทุกคีย์เมื่อไม่มีน้ำหนักใดเกิน 0 `lend_k` คือเปอร์เซ็นต์ที่ใช้งานอยู่ของคีย์ และเป็น 0 เมื่อเลยกำหนดเวลาไปแล้ว ความยินยอมของคีย์ที่ร้องขอจะไม่นับรวม คีย์ `hard` จะถูกปฏิเสธเมื่อปริมาณการใช้ถึงส่วนแบ่งบวก `borrowAvailable`

ความจุที่ไม่มีการอ้างสิทธิ์การจัดสรร (100 ลบด้วยผลรวมของน้ำหนัก) ไม่สามารถให้ยืมได้ ไม่มีคีย์ตกลงที่จะให้ยืม

**ตัวอย่าง.** `L` คือ 1,000

| สำคัญ | น้ำหนัก | แบ่งปัน | บริโภค | ยืม |
| ----- | ------- | ------- | ------ | --- |
| ก     | 50      | 500     | 530    | 0%  |
| บี    | 30      | 300     | 100    | 50% |
| ค     | 0       | 0       | 60     | 0%  |

- B ให้ยืม 50% ของ Idle 200 ซึ่งก็คือ 100 C ให้ยืม 60 มากกว่าส่วนแบ่งแล้ว ก. ยืมได้ 40.
- A ให้บริการที่ 530 และปฏิเสธเมื่อบริโภคถึง 540
- ก่อนที่ C จะใช้อะไรก็ตาม โดยมี A เท่ากับหรือน้อยกว่าส่วนแบ่ง C สามารถยืมได้ 100
- ก่อนที่ C จะใช้อะไรก็ตาม โดยมี A อยู่ที่ 530 C สามารถยืมได้ 70

**น้ำหนักเป็นศูนย์** คีย์ที่มีน้ำหนัก 0 จะมีส่วนแบ่งเป็น 0 โดยจะให้บริการเฉพาะในขณะที่ปริมาณการใช้ต่ำกว่าที่ผู้อื่นยืม เมื่อไม่มีใครให้ยืมก็จะถูกปฏิเสธตั้งแต่คำขอครั้งแรก

**กำหนดเวลา** ไม่มีงานพื้นหลังใดที่หมดอายุความยินยอม คำขอแต่ละรายการจะเปรียบเทียบกำหนดเวลากับเวลาของตนเอง และกำหนดเวลาที่เท่ากับเวลานั้นผ่านไปแล้ว กำหนดเวลาที่เก็บไว้ซึ่งไม่ใช่จำนวนจำกัด หรือเลยวันที่ใหญ่ที่สุดที่ `Date` สามารถเก็บไว้ได้ ให้นับว่าผ่านแล้ว

**`soft` และ `burst`** การให้กู้ยืมไม่ได้จำกัดพวกเขา คีย์ `soft` จะถูกลดความสำคัญลงเมื่อผ่านการแชร์ไปแล้ว คีย์ `burst` จะผ่านไปในขณะที่สระยังมีที่ว่าง เพดานสระว่ายน้ำยังคงปฏิเสธทุกกุญแจเมื่อยอดรวมของสระถึงขีดจำกัด

**ต้นทุนในเส้นทางคำขอ** พูล `saturation` ไม่อ่านอะไรมากไปกว่าเมื่อก่อน ในพูล `consent` มิติที่นับได้จะอ่านคีย์อื่นๆ เฉพาะสำหรับคีย์ `hard` ที่หรือสูงกว่าการแบ่งใช้ ในขณะที่คีย์อื่นให้ยืม จากนั้นจะอ่านหนึ่งรายการต่ออีกคีย์หนึ่งพร้อมกัน การอ่านที่ล้มเหลวจะนับเป็นการใช้ 0 สำหรับคีย์นั้น มิติข้อมูล `percent` จะไม่เพิ่มการอ่าน เนื่องจากสมุดการระบุแหล่งที่มาเก็บทุกคีย์

**แก้ไขสระน้ำ.** การแก้ไขจะรักษาความยินยอมของคีย์ที่ยังคงอยู่ สิ่งนี้มีไว้สำหรับการแก้ไขการจัดสรร การแทนที่ทั้งกลุ่ม และการเรียก `ensure` คีย์ที่ถูกลบออกจะสูญเสียความยินยอม และคีย์ที่เพิ่มกลับจะเริ่มต้นที่ 0 เส้นทางของผู้ดูแลระบบจะส่งคืนความยินยอมของแต่ละคีย์และไม่ต้องเขียนมัน การเปลี่ยนพูลกลับเป็น `saturation` จะเก็บความยินยอมที่เก็บไว้ไว้ทั้งหมด ซึ่งไม่มีผลในโหมดนั้น การเปลี่ยนพูลเป็น `consent` จะเปิดใช้งานความยินยอมที่เก็บไว้อีกครั้งซึ่งยังไม่ผ่านกำหนดเวลา ผู้ถือกุญแจสามารถล้างความยินยอมที่เก็บไว้ในโหมดใดโหมดหนึ่งได้

**กำลังอัปเกรด** หากมีคอลัมน์ `lending_percent` และ `lending_until` อยู่แล้ว การย้ายข้อมูลจะเพิ่มเฉพาะ `borrow_mode` และเปอร์เซ็นต์ที่เก็บไว้จะยังคงเหมือนเดิม ทุกพูลเริ่มต้นในโหมด `saturation` เปิด `consent` ต่อพูลในตัวช่วยสร้างพูล ไม่มีสิ่งใดอนุมานได้จากค่าที่เก็บไว้

**ข้อจำกัด**

- ผู้ให้กู้สามารถหาสระว่ายน้ำได้ที่เพดานก่อนที่จะใช้ส่วนแบ่งของตัวเอง ความจุที่ผู้อื่นยืมมาจะนับรวมกับผลรวมของพูล
- การตรวจสอบจะดำเนินการก่อนคำขอและไม่สงวนอะไรเลย คำขอที่อ่านพร้อมกันก่อนที่จะมีการบันทึก ดังนั้นความจุที่ให้ยืมจึงสามารถนำไปใช้ได้มากกว่าหนึ่งครั้ง โดยถูกผูกไว้กับคำขอที่กำลังดำเนินการอยู่ การตรวจสอบการแชร์ของโหมด `saturation` มีคุณสมบัติเหมือนกัน

## ตัวนับแบบหน้าต่างเลื่อน

นำไปใช้ใน `src/lib/quota/sqliteQuotaStore.ts` และ `redisQuotaStore.ts`

มีสองบัคเก็ตต่อ `(apiKeyId, dimensionKey)`:

- `curr`: บัคเก็ตปัจจุบัน (`floor(nowMs / windowMs)`)
- `prev`: บัคเก็ตก่อนหน้า (`curr - 1`)

ค่าต่อเนื่องที่มีผล:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**ความแม่นยำ**: แม่นยำประมาณ 99% ค่าคลาดเคลื่อนสูงสุดคือ 1% ของขนาดหน้าต่าง ณ
รอยต่อระหว่างบัคเก็ต (เป็นข้อจำกัดโดยธรรมชาติของการประมาณแบบ 2 บัคเก็ต)

### การทำงานพร้อมกัน

ไดรเวอร์ SQLite: mutex ในหน่วยความจำต่อคีย์ `(apiKeyId | dimensionKey)` ป้องกันภาวะ
การแข่งขันแบบอ่าน-แก้ไข-เขียน โดยใช้รูปแบบเดียวกับการป้องกันปัญหา anti-thundering-herd ใน `src/sse/services/auth.ts`

ไดรเวอร์ Redis: สคริปต์ Lua EVAL สำหรับการเพิ่มค่าแบบอะตอมมิก — ทำงานเป็นคำสั่ง Redis เดียว

## ไดรเวอร์

### SQLite (ค่าเริ่มต้น, ไม่ต้องติดตั้ง)

- ตาราง: `quota_consumption` (ดู migration `073_quota_pools.sql` / `074_quota_consumption.sql`)
- เหมาะที่สุดสำหรับการติดตั้งใช้งานแบบอินสแตนซ์เดียว
- ข้อมูลถาวรทั้งหมดอยู่ในฐานข้อมูล SQLite เดิมของ OmniRoute (`DATA_DIR/storage.sqlite`)

### Redis (ตัวเลือกเสริม, หลายอินสแตนซ์)

- ต้องใช้แพ็กเกจ npm `ioredis`
- ตัวนับจัดเก็บไว้ใน Redis ส่วนข้อมูลเมตา (พูล/การจัดสรร) ยังคงอยู่ใน SQLite
- เหมาะที่สุดสำหรับการติดตั้งใช้งานแบบหลายเรพลิกาที่ต้องแชร์ตัวนับร่วมกัน

### การสลับไดรเวอร์

ผ่าน UI การตั้งค่า (`/dashboard/settings` → ที่เก็บโควตา) หรือผ่านตัวแปรสภาพแวดล้อม:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

การตั้งค่าใน DB มีลำดับความสำคัญสูงกว่าตัวแปรสภาพแวดล้อม หาก `driver=redis` แต่ไม่มี URL หรือ
ไม่ได้ติดตั้ง `ioredis` แฟกทอรีจะย้อนกลับไปใช้ SQLite และบันทึกคำเตือนในล็อก

ลำดับการเลือกไดรเวอร์:

1. การตั้งค่า DB `quotaStore.driver`
2. ตัวแปรสภาพแวดล้อม `QUOTA_STORE_DRIVER`
3. ค่าเริ่มต้น: `sqlite`

## หลายมิติ

พูลสามารถมีได้หลายมิติ แต่ละมิติมีความเป็นอิสระ:

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // global pool ceiling for this dimension
}
```

**ตัวอย่าง: แผน Codex** (5h% + รายสัปดาห์%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

คำขอต้องเป็นไปตามมิติข้อมูลทั้งหมดจึงจะได้รับอนุญาต

### มิติข้อมูลเปอร์เซ็นต์: การระบุแหล่งที่มาต่อคีย์

แผนเปอร์เซ็นต์รายงานตัวเลขการใช้งานหนึ่งรายการต่อบัญชีและหน้าต่างแผน ผู้ให้บริการไม่ให้ตัวนับต่อคีย์ API

หากต้องการแยกตัวเลขดังกล่าวระหว่างคีย์ แต่ละกลุ่มจะเก็บสมุดระบุแหล่งที่มาต่อบัญชีและหน้าต่างแผน `src/lib/quota/percentLedger.ts` ถือกฎของหนังสือ `src/lib/quota/percentAttribution.ts` เปลี่ยนหนังสือให้เป็นตัวเลขที่หน่วยงานบังคับใช้ใช้ ผลลัพธ์คือการประมาณที่สร้างขึ้นจากโทเค็นแต่ละเส้นทางหลัก

#### การอ่านที่ทำให้หนังสือเคลื่อนไหว

หนังสือจะเคลื่อนไหวตามรูปร่างของผู้ให้บริการเท่านั้นสำหรับหน้าต่างแผนที่ร้องขอ การเชื่อมต่อเหล่านี้รายงานอย่างใดอย่างหนึ่ง:

| ผู้ให้บริการ                  | วางแผนหน้าต่าง |
| ----------------------------- | -------------- |
| Claude ผ่านการเชื่อมต่อ OAuth | `5h`, `weekly` |
| Codex                         | `5h`, `weekly` |

สิ่งเหล่านี้ไม่นับเป็นการอ่าน:

- การตอบกลับที่ไคลเอนต์ผู้ให้บริการทำเครื่องหมายว่าไม่อัปเดต
- หน้าต่าง Claude ซึ่งเปอร์เซ็นต์ที่ผู้ให้บริการไม่ได้รายงาน
- รูปแบบของหน้าต่างอื่น หรือกรณีที่เลวร้ายที่สุดในหน้าต่างต่างๆ
- ทางเลือกส่วนหัวที่จำกัดอัตรา
- การอ่านล้มเหลว

ผู้ให้บริการรายอื่น รวมถึง Claude ที่มีคีย์ API ไม่มีหนังสือ แต่ละคีย์จะถูกเรียกเก็บเงิน 0 ตามขนาดเปอร์เซ็นต์ เช่นเดียวกับก่อนการเปลี่ยนแปลงนี้

การอ่านจะแชร์แคช 30 วินาทีของสัญญาณความอิ่มตัว การอ่าน Claude จะลงวันที่ตามเวลาที่สังเกตตัวเลขในส่วนหัวการตอบกลับหรืออ่านจากจุดสิ้นสุดการใช้งาน เมื่อทราบเวลาดังกล่าว การอ่านอื่นๆ จะลงวันที่เมื่อรายการแคชนั้นถูกสร้างขึ้น

#### สิ่งที่หนังสือเก็บไว้

คำขอที่บันทึกไว้แต่ละรายการจะเพิ่มโทเค็นหนึ่งครั้งไปยังตัวนับต่อพูล บัญชี และคีย์ เคาน์เตอร์เติบโตเท่านั้น หนังสือเล่มนี้มีสามสิ่ง:

- เส้นฐาน: รูปที่หนังสือเปิดออกหรือเปิดหน้าต่างครั้งสุดท้าย
- รูปที่ใช้ล่าสุด
- ต่อคีย์ ตัวนับโทเค็นในขณะเดียวกันนั้นเรียกว่าเครื่องหมายของมัน

หนังสือได้รับการอัปเดตเมื่อมีการบังคับใช้หรือเส้นทางการใช้งานคำนวณการระบุแหล่งที่มา การเขียนจะถูกเปรียบเทียบและตั้งค่ากับหมายเลขการแก้ไข นักเขียนที่พลาดการลองอ่านใหม่เพียงครั้งเดียว

#### วิธีคำนวณส่วนของคีย์

แต่ละส่วนของคีย์จะถูกคำนวณเมื่ออ่านหนังสือ การเติบโตของตัวเลขตั้งแต่เส้นฐานถูกแบ่งระหว่างคีย์ตามสัดส่วนของโทเค็นที่แต่ละอันกำหนดเส้นทางตั้งแต่เครื่องหมาย

Together โทเค็นเหล่านั้นอธิบายได้มากที่สุดหนึ่งจุดของตัวเลขต่อโทเค็น `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` (ค่าเริ่มต้น 1,000) การเติบโตที่พวกเขาไม่ได้อธิบายนั้นเป็นเรื่องภายนอก พื้นฐานก็เป็นภายนอกเช่นกัน

ตัวอย่างเช่น หนังสือเปิดที่ 0 จากนั้นคีย์ A จะกำหนดเส้นทางโทเค็น 900,000 รายการ และคีย์ B จะกำหนดเส้นทาง 100,000 รายการ ที่เลข 60 ส่วน A คือ 54 คะแนน และส่วน B คือ 6

ตัวนับที่อยู่ด้านล่างเครื่องหมายของคีย์ได้รีสตาร์ทและนับเต็มแล้ว คีย์ที่ไม่มีเครื่องหมาย เช่น คีย์ที่เชื่อมพูลตรงกลางหน้าต่าง จะนับโทเค็นทั้งหมด ตัวเลขที่ล่าช้าของโทเค็นทำให้เกิดข้อผิดพลาดที่หายไปในการอ่านครั้งถัดไป มันไม่สะสม.

`QUOTA_PERCENT_MIN_TOKENS_PER_POINT` ถูกอ่านในทุกการระบุแหล่งที่มา ค่าที่ไม่ใช่จำนวนจำกัดอย่างน้อย 1 จะกลับไปเป็น 1,000

#### การอ่านเปลี่ยนแปลงหนังสืออย่างไร

กฎการจับคู่ข้อแรกจะใช้:

1. **ยังไม่มีหนังสือ:** การอ่านจะเปิดหนังสือ ตัวเลขของมันคือเส้นฐานและทุกตัวนับจะถูกทำเครื่องหมายไว้
2. **การอ่านเก่า:** การอ่านวันที่ก่อนที่จะใช้ครั้งล่าสุดจะถูกละเว้น การอ่านที่มีเวลารีเซ็ตเร็วกว่าเวลาที่เก็บไว้มากกว่า 30 นาทีก็เช่นกัน
3. **หน้าต่างผู้ให้บริการใหม่:** เวลารีเซ็ตช้ากว่าเวลาที่เก็บไว้มากกว่า 30 นาทีจะเปลี่ยนหนังสือ ตัวเลขจะกลายเป็นเส้นฐานและทุกตัวนับจะถูกทำเครื่องหมายอีกครั้ง กุญแจที่ไม่มีตัวนับออกจากหนังสือ
4. **หน้าต่างสิ้นสุด:** เวลารีเซ็ตที่เก็บไว้ซึ่งไม่ใช่หลังจากเวลาข้อมูลการอ่านหมายความว่าหน้าต่างนั้นสิ้นสุดลงแล้ว การอ่านจะเปลี่ยนหนังสือไม่ว่ารูปร่างจะเป็นเช่นไรก็ตาม
5. **ตัวเลขที่สูงขึ้น:** เฉพาะร่างสุดท้ายเท่านั้นที่เคลื่อนไหว เส้นฐานและเครื่องหมายยังคงอยู่
6. **รูปเดียวกัน:** รูปร่าง เส้นฐาน และเครื่องหมายยังคงอยู่ มีเพียงเวลารีเซ็ตที่หนังสือขาดหายไปเท่านั้นจึงจะเขียนได้
7. **รูปล่าง:** ตัวเลขที่ต่ำกว่าจะไม่ถูกนำมาใช้เช่นนี้ มันจะพลิกหนังสือเมื่อมีสามสิ่งเท่านั้น ใหม่กว่าการอ่านครั้งล่าสุดอย่างน้อยสองนาที ไม่มีอะไรบอกว่าหน้าต่างเป็นแบบเดียวกับที่เปิดอยู่ มันต่ำกว่าหนึ่งจุด

หน้าต่างจะนับเป็นหน้าต่างที่เปิดอยู่เหมือนกันเมื่อมีสามสิ่งค้างไว้ ทราบเวลารีเซ็ตทั้งสองครั้งแล้ว พวกเขาอยู่ห่างจากกันไม่เกิน 30 นาที ที่เก็บไว้ยังอยู่ข้างหน้าการอ่าน ตัวเลขด้านล่างภายในหน้าต่างนั้นไม่เปลี่ยนแปลงอะไรเลย

เวลารีเซ็ตจะถูกเก็บไว้เฉพาะในขณะที่อยู่ก่อนเวลาข้อมูลของการอ่านค่านั้นเท่านั้น ตัวเลขที่สูงกว่าจะเก็บเวลารีเซ็ตการอ่านเมื่อใช้งานได้ และจะเก็บค่าที่เก็บไว้ไว้เป็นอย่างอื่น ตัวเลขที่เท่ากันจะบันทึกเวลารีเซ็ตการอ่านเฉพาะเมื่อไม่มีหนังสือเลย มันเปลี่ยนแปลงอะไรอย่างอื่นไม่ได้ ตัวเลขที่ต่ำกว่าที่ไม่เปิดบันทึกหนังสือไม่มีเวลารีเซ็ต

#### เมื่อใช้หนังสือแล้ว

หลังจากการอ่าน หนังสือจะถูกใช้เว้นแต่เวลารีเซ็ตที่เก็บไว้ไม่ได้อยู่หลังเวลาปัจจุบัน กรณีดังกล่าวเกิดขึ้นเมื่อการอ่านค่าที่เกิดขึ้นก่อนการรีเซ็ต เช่น การอ่านค่าจากแคช ถูกสังเกตหลังจากนั้น

หากไม่มีการอ่านที่ใช้งานได้ หนังสือที่เก็บไว้จะถูกใช้เฉพาะในขณะที่ยังคงเป็นหนังสือของหน้าต่างปัจจุบันเท่านั้น ซึ่งถือได้เป็น 2 กรณี คือ

- ทราบเวลารีเซ็ตแล้วและยังรออยู่ข้างหน้า
- ไม่มีเวลารีเซ็ต และการอ่านครั้งล่าสุดที่เปลี่ยนแปลงนั้นมีอายุไม่เกิน 15 นาที

มิฉะนั้นจะไม่มีอะไรเป็นเหตุเหมือนเมื่อไม่มีหนังสือ หนังสือที่เลยเวลารีเซ็ตที่เก็บไว้ไปแล้วจะไม่ถูกเรียกเก็บเงิน

#### การบังคับใช้

ปริมาณการใช้คีย์ในมิติเปอร์เซ็นต์คือส่วนที่ประกอบกับส่วนแบ่งของส่วนภายนอก ส่วนภายนอกจะใช้การอ้างสิทธิ์กำลังการผลิตที่ไม่มีการจัดสรรก่อน (100 ลบด้วยผลรวมของน้ำหนัก) เฉพาะส่วนเกินเท่านั้นที่จะถูกแบ่งระหว่างคีย์ตามน้ำหนัก

ปริมาณการใช้นั้นจะถูกเปรียบเทียบกับส่วนแบ่งที่ยุติธรรมของคีย์เหมือนกับมิติอื่นๆ โหมดเข้มงวดยังคงเริ่มต้นเมื่อสัญญาณความอิ่มถึง `QUOTA_SATURATION_THRESHOLD` (ค่าเริ่มต้น 0.5) ทุกตัวเลขจะถูกปรับขนาดตามขีดจำกัดที่มีผล: ขีดจำกัดต่อบัญชีจะคูณด้วยจำนวนบัญชีในกลุ่ม

หมวกแบบสัมบูรณ์ที่มี `capUnit: "percent"` จะนับเฉพาะส่วนที่ประกอบกับคีย์ โดยมีการปรับขนาดในลักษณะเดียวกัน จำกัดบัญชีไว้ที่ 100 และ k บัญชี จากนั้นถึงขีดจำกัดของ N เมื่อส่วนของคีย์ในบัญชีที่ให้บริการถึงจุด N/k แต่ละบัญชีจะถูกตรวจสอบกับบัญชีของตัวเอง ตัวอย่างเช่น สำหรับสองบัญชี จะมีขีดจำกัดสูงสุดที่ 10 ที่ 5 คะแนนจากหนึ่งบัญชี

เมื่อไม่สามารถอ่านร้านค้าได้ จะไม่มีการระบุแหล่งที่มา และทุกคีย์จะถูกเรียกเก็บเงินเป็น 0 ในมิตินั้น เมื่อการเขียนหนังสือล้มเหลว การระบุแหล่งที่มานั้นจะใช้หนังสือในขณะที่อ่าน การเขียนโทเค็นที่ล้มเหลวจะทำให้โทเค็นของคำขอนั้นไม่อยู่ในหนังสือ ไม่มีความล้มเหลวใดที่ขัดขวางคำขอ

ในพูล `consent` สูตรการให้ยืมจะใช้ปริมาณการใช้ของแต่ละคีย์ในมิติเปอร์เซ็นต์ตามที่อธิบายไว้ข้างต้น เมื่อมีการยืมคีย์อื่น หนังสือเล่มนี้จะถูกอ่านหนึ่งครั้งและเชื่อมโยงกับทุกคีย์ หากไม่มีหนังสือที่ใช้งานได้ ทุกคีย์จะถูกเรียกเก็บเงิน 0 จากนั้นคีย์ที่มีน้ำหนักจะผ่าน และคีย์ที่มีน้ำหนัก 0 จะส่งผ่านเมื่อมีคีย์อื่นให้ยืมเท่านั้น

#### เส้นทางการใช้งาน

`GET /api/quota/pools/{id}/usage` รายงานตัวเลขเดียวกันผ่านฟังก์ชันเดียวกัน มิติเปอร์เซ็นต์มีหนึ่งรายการต่อการเชื่อมต่อพูลใน `accounts` `consumedTotal` และ `perKey` ระดับบนสุดจะสะท้อนรายการแรก

เส้นทางนี้ใช้การอ่านในปัจจุบันด้วย จึงสามารถเลื่อนหนังสือไปข้างหน้าได้ตามคำขอ `internal + external` อาจแตกต่างจาก `consumedTotal` เมื่อไม่มีการอ่านที่ใช้งานได้ หรือเมื่อไม่ได้ใช้ตัวเลขที่ต่ำกว่า

#### การจัดเก็บและการเก็บรักษา

ร้านค้าโควต้าทั้งสองร้านเก็บหนังสือไว้ บน SQLite การล้างฐานข้อมูลอัตโนมัติเมื่อเปิดใช้งาน จะลบแถวที่ไม่ได้รับการอัปเดตเป็นเวลา 60 วัน บน Redis หนังสือและตัวนับของการเชื่อมต่อพูลจะใช้คีย์เดียวร่วมกัน จะหมดอายุใน 60 วันหลังจากการเขียนโทเค็นหรือการเปลี่ยนแปลงหนังสือครั้งล่าสุด หนังสือที่ไม่มีการเปลี่ยนแปลงจะไม่ถูกเขียนใหม่ ดังนั้นจึงกำหนดจุดตัดไว้เหนือหน้าต่างแผนผังที่ยาวที่สุด การรีเซ็ตประวัติการใช้งานด้วยตนเองยังล้างหนังสือใน SQLite ด้วย (ดูข้อจำกัด)

#### ข้อจำกัด

- การเติบโตทั้งหมดของตัวเลขบัญชีตั้งแต่พื้นฐานถูกแบ่งตามโทเค็นแต่ละคีย์ที่กำหนดเส้นทางตั้งแต่นั้นมา เมื่อการเติบโตนั้นเกิดขึ้นไม่สำคัญ
- ดังนั้นการใช้งานภายนอก OmniRoute จะถูกเรียกเก็บเงินจากคีย์ตามจำนวนที่โทเค็นอนุญาต ซึ่งรวมถึงการใช้งานที่เกิดขึ้นก่อนคำขอคีย์ครั้งแรกของหน้าต่าง เมื่อหนังสือถูกเปิดแล้ว
- เช่น การใช้งานภายนอกทำให้บัญชีเพิ่มขึ้น 60 คะแนน ในขณะที่ไม่มีเส้นทางหลัก คีย์จะกำหนดเส้นทาง 30,000 โทเค็น และตัวเลขถึง 60.6
- ถ้าหนังสือถูกเปิดก่อนการใช้งานครั้งนั้น ส่วนของกุญแจคือ 30 คะแนน นอกจากนี้ยังมีการใช้งานภายนอก 7.65 โดยมีสี่คีย์น้ำหนัก 25
- หากหนังสือเปิดหลังจากการใช้งานครั้งนั้น 60 คะแนนจะเป็นพื้นฐาน ส่วนของกุญแจ 0.6 จุด ใช้งานภายนอกได้ 15 จุด
- การร้องขอหรือการเยี่ยมชมเส้นทางการใช้งานจะเปิดหนังสือ ดังนั้น การใช้ดังกล่าวจะนับเป็นข้อมูลพื้นฐานหรือไม่นั้นขึ้นอยู่กับว่าหนังสือเปิดเมื่อใด
- ด้วยค่าพื้นฐานเริ่มต้น คีย์ที่กำหนดเส้นทางโทเค็น 60,000 โทเค็นในขณะที่ใช้งานภายนอกจะเพิ่มคะแนนบัญชี 60 แต้ม จะได้รับทั้งหมด 60 แต้มเป็นส่วนหนึ่งของตัวมันเอง
- โดยพื้นอยู่ที่ 50,000 ส่วนของตัวเองคือ 1.2 คะแนน ส่วนอีก 58.8 อันเป็นแบบภายนอกและคิดตามน้ำหนัก เช่นเดียวกับการใช้งานภายนอกอื่นๆ
- ตั้งค่า `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` ให้ใกล้เคียงกับราคาหนึ่งจุดในแผนของคุณ การใช้งานภายนอกรวมถึงการรับส่งข้อมูลในบัญชีเดียวกันจากคีย์ที่อยู่นอกพูล
- เปอร์เซ็นต์สูงสุดจะใช้ในทุกโหมด สามารถปฏิเสธคีย์ที่ต่อยอดได้ในขณะที่บัญชีอยู่ต่ำกว่าเกณฑ์ความอิ่มตัวมาก
- แคปการใช้งานภายนอก 10 และ 12 จุดก่อนหน้านี้ในหน้าต่าง คีย์ที่กำหนดเส้นทางโทเค็น 20,000 โทเค็นจะถูกปฏิเสธที่ตัวเลขบัญชี 12.4%
- การแยกเป็นค่าประมาณตามปริมาณโทเค็น คำขอจะนับเป็นโทเค็นพร้อมท์บวกกับโทเค็นการเสร็จสิ้น ส่วนลดแคชและราคารุ่นจะไม่เปลี่ยนแปลงจำนวนนั้น
- คำขอที่ไม่ลงท้ายด้วยสถานะ 200 จะบันทึกว่าไม่มีโทเค็น ตัวอย่างคือสตรีมที่ไคลเอ็นต์ตัดการเชื่อมต่อและข้อผิดพลาดอัปสตรีมหลังจากใช้งานไปแล้ว
- การใช้งานที่คำขอดังกล่าวเกิดขึ้นจะถูกเรียกเก็บเงินจากคีย์ที่ทำการบันทึกโทเค็น ขึ้นอยู่กับจำนวนที่โทเค็นอนุญาต ส่วนที่เหลือเป็นภายนอก มันไม่ขยับกลับ การตอบสนองที่รายงานว่าไม่มีบันทึกการใช้โทเค็นไม่มีโทเค็นเช่นกัน
- การใช้คำขอที่กำลังดำเนินการสามารถแสดงในส่วนของคีย์ที่ใช้งานอื่นสำหรับคำขอทั้งหมด โดยจะย้ายกลับเฉพาะเมื่อคำขอสิ้นสุดด้วยสถานะ 200
- การใช้งานในบัญชีอยู่แล้วเมื่อเปิดหนังสือจะนับเป็นการใช้งานภายนอก ซึ่งครอบคลุมถึงการอัพเกรด พูลใหม่และบัญชีใหม่ การใช้งานในหน้าต่างใหม่ก่อนการอ่านครั้งแรกจะนับเป็นการใช้งานภายนอกด้วย
- แต่ละคีย์เริ่มต้นด้วยส่วนแบ่งน้ำหนักของการใช้งานนั้น หลังจากอ้างสิทธิ์ความจุที่ไม่มีการจัดสรรแล้ว ด้วยหนึ่งบัญชีที่ 85% และห้าคีย์น้ำหนัก 20 แต่ละคีย์เริ่มต้นด้วย 17 จาก 20 ที่ใช้ไป
- ในกลุ่มที่มีหลายบัญชี ตัวเลขของบัญชีที่ให้บริการจะถูกนำไปใช้กับงบประมาณรวม หนังสือเล่มนี้ไม่เปลี่ยนแปลง
- ตัวเลขด้านล่างภายในหน้าต่างที่ผู้ให้บริการรายงานว่าเปิดจะไม่ถูกนำมาใช้ เวลารีเซ็ตที่ย้อนกลับไปมากกว่า 30 นาทีจะถือเป็นการอ่านแบบเก่า
- ในทั้งสองกรณี หนังสือจะคงสถานะไว้จนกว่าเวลารีเซ็ตที่เก็บไว้จะผ่านไป หลังจากนั้น หนังสือจะไม่ถูกเรียกเก็บเงินจนกว่าจะเปลี่ยนการอ่าน
- วิธีแก้ไขคือการรีเซ็ตประวัติการใช้งานด้วยตนเอง (`POST /api/settings/purge-usage-history`) จะล้างสมุดระบุแหล่งที่มาและตัวนับโทเค็นในฐานข้อมูล SQLite
- ช่วง `all` จะล้างหนังสือและตัวนับทุกเล่ม ระยะเวลาที่สั้นกว่าจะล้างหนังสือที่ไม่ได้เขียนไว้ภายในนั้นก่อน จากนั้นจะล้างตัวนับที่ไม่ได้เขียนไว้ภายใน แต่สำหรับการเชื่อมต่อพูลที่ไม่มีหนังสือเหลืออยู่เท่านั้น หนังสือที่เก็บไว้ยังคงทำเครื่องหมายแต่ละปุ่มไว้กับตัวนับ
- หนังสือที่ร่างไม่ขยับจะไม่ถูกเขียนใหม่ ดังนั้นระยะเวลาที่สั้นกว่าจึงสามารถล้างหนังสือในหน้าต่างปัจจุบันได้ การอ่านครั้งต่อไปจะเปิดหนังสือเล่มใหม่ที่ตัวเลขปัจจุบัน
- การรีเซ็ตไม่ได้สัมผัสกับที่เก็บโควต้า Redis มีหนังสือเล่มหนึ่งปิดท้ายด้วยหน้าต่างหรือหมดอายุ 60 วันหลังจากเขียนครั้งล่าสุด
- เมื่อผู้ให้บริการไม่ส่งเวลารีเซ็ต หน้าต่างที่รีเซ็ตและเติมเหนือตัวเลขเก่าระหว่างการอ่านสองครั้งจะดูเหมือนเป็นตัวเลขที่สูงกว่า หนังสือเล่มนี้ยังคงรักษาพื้นฐานและเครื่องหมายเก่าไว้
- การอ่านจะลงวันที่ตามนาฬิกาท้องถิ่น เมื่อดำเนินการเร็วกว่าผู้ให้บริการหรือแหล่งข่าวรายงานเวลารีเซ็ตก่อนเวลาเล็กน้อย หนังสืออาจถึงส่วนต่างดังกล่าวตั้งแต่เนิ่นๆ
- การเติบโตในช่วงเวลาสั้น ๆ นั้นจะถูกแบ่งตามโทเค็นที่ส่งไปในนั้น การอ่านครั้งแรกของหน้าต่างถัดไปจะแก้ไขให้ถูกต้อง เมื่อหนังสือที่พลิกกลับไม่มีเวลารีเซ็ต การแก้ไขนั้นจะต้องมีตัวเลขที่ต่ำกว่าค่าที่ใหม่กว่าค่าที่อ่านครั้งล่าสุดอย่างน้อยสองนาที
- อินสแตนซ์ที่แชร์การอ่านวันที่ที่จัดเก็บ Redis กับนาฬิกาของตัวเอง ดังนั้นให้ซิงค์นาฬิกาเหล่านั้นไว้ การอ่านตัวอย่างที่นาฬิกาเดินตามหลังจะดูเก่ากว่าและถูกละเลย
- เมื่อไม่มีการอ่านที่ใช้งานได้มาถึงหลังจากเวลารีเซ็ตที่เก็บไว้ เปอร์เซ็นต์การแบ่งใช้ต่อคีย์และเปอร์เซ็นต์สูงสุดจะไม่บังคับใช้จนกว่าการอ่านจะกลับมา หากไม่มีเวลารีเซ็ต การดำเนินการนี้จะเริ่มต้น 15 นาทีหลังจากการอ่านครั้งล่าสุดที่เปลี่ยนแปลงหนังสือ
- ในร้าน Redis หนังสือที่ไม่ได้ใช้งานเป็นเวลา 60 วันสามารถหมดอายุได้ระหว่างเช็คของผู้เขียนและการเขียนของหนังสือ จากนั้นจะสร้างขึ้นใหม่ตามการแก้ไขข้างต้น 1 ซึ่งเป็นสถานะที่ถูกต้อง

## บูรณาการไปป์ไลน์

### ตะขอ PRE (`open-sse/handlers/chatCore.ts`)

ทำงานก่อนตัวดำเนินการอัปสตรีม หลังจากการตรวจสอบสิทธิ์และนโยบาย:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → getQuotaStore().peek() per dimension
      → fairShare.decideFairShare()
      → if block → return 429 (buildErrorBody, Hard Rule #12)
      → if allow + deprioritize → set quotaSoftPenalty=true on candidate
  → executor.execute()
```

**เปิดไม่สำเร็จ** : หาก `enforceQuotaShare` พ่น คำขอจะได้รับอนุญาตผ่านบันทึก `pino.warn` วิธีนี้จะป้องกันไม่ให้ข้อผิดพลาดของโควต้าเอ็นจิ้นปิดกั้นการรับส่งข้อมูลทั้งหมด

**เมื่อความจุกลับมา** การปฏิเสธส่วนแบ่งของกุญแจหรือที่เพดานสระจะจบลงด้วยหนึ่งในสองประโยค ในโหมดการยืมทั้งสองแบบ:

- หน้าต่าง `percent` : `. The <window> window resets at <time>.` เวลาคือการรีเซ็ตรายงานของผู้ให้บริการ
- หน่วยนับได้: `. Enough <window> usage is expected to clear by <time>.` เวลาเป็นขอบเขตบนจากหน้าต่างบานเลื่อน หากคีย์ไม่ส่งอย่างอื่นอีก

`<time>` เป็น ISO 8601 ทันทีใน UTC การปฏิเสธนั้นจะมีค่า `Retry-After`: วินาทีทั้งหมดจนกระทั่งถึงช่วงเวลานั้น บวกหนึ่ง ไคลเอนต์ที่รอนานและลองใหม่อีกครั้งมากที่สุดหนึ่งวินาทีหลังจากช่วงเวลานั้น เมื่อไม่ทราบช่วงเวลา การปฏิเสธจะไม่มีทั้งประโยคหรือส่วนหัว การปฏิเสธหมวกแบบสัมบูรณ์จะไม่มีผลทั้งสองอย่าง รหัสสาธารณะยังคงอยู่ `quota_share_blocked`

การปฏิเสธการแชร์ไม่ได้กระทบต่อการเชื่อมต่อที่แชร์ ไม่มีการตั้งค่าคูลดาวน์ ไม่มีการล็อกโมเดล และไม่มีตัวแบ่งเบรกเกอร์ของผู้ให้บริการ และคีย์อื่นๆ ของพูลยังคงให้บริการอยู่ เมื่อทุกเป้าหมายของคอมโบปฏิเสธกุญแจสำหรับการแบ่งใช้ คอมโบจะตอบ 429 โดยไม่ต้องรอ คำตอบมีคำใบ้เป็น `Retry-After` เส้นทางการฝังจะสิ้นสุดการปฏิเสธด้วยประโยคเดียวกันและไม่ส่ง `Retry-After`

### ตะขอ POST (ปริมาณการใช้บันทึก)

หลังจากการตอบกลับสำเร็จ:

```
executor returns success
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → getQuotaStore().consume() per dimension
      → fail-open: errors logged as pino.warn, never propagated to client
```

**บันทึกดริฟท์** : ถ้า `consume` ล้มเหลวหลังการตอบกลับ ตัวนับที่กลิ้งจะนับต่ำกว่า สัญญาณความอิ่มตัวจากผู้ให้บริการ (เช่น `anthropic-ratelimit-unified-5h-utilization`) จะแก้ไขการประมาณการทั่วโลกในคำขอถัดไป

### บทลงโทษอ่อนคอมโบ (`open-sse/services/combo.ts`)

เมื่อ `decision.deprioritize === true`:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // default 0.7
}
```

การปรับโทษจะถูกนำมาใช้หลังจากปัจจัยการให้คะแนนอื่นๆ ทั้งหมด จะช่วยลดความน่าจะเป็นของคำสั่งผสมอัตโนมัติในการเลือกคีย์ที่อิ่มตัวโดยไม่ต้องปิดกั้นคีย์นั้นอย่างหนัก

## โควต้าบริการตนเอง API (เลือกใช้)

`GET /api/v1/me/quota/{provider}` (ให้บริการที่ `/v1/me/quota/{provider}`) อนุญาตให้ผู้ถือคีย์ API อ่านด้วยรหัสของตนเอง จำนวนการสมัครสมาชิกที่ใช้ร่วมกันเป็นของพวกเขา และสิ่งที่บล็อกพวกเขา เส้นทางเป็นเปลือกบางกว่า `src/server/selfService/quotaHandler.ts`; มุมมองถูกสร้างขึ้นโดย `src/lib/quota/selfView.ts` และสัญญาตอบกลับคือ `src/shared/schemas/selfQuota.ts` (`SelfQuotaView` ใน `docs/openapi.yaml`)

### การเปิดใช้งานและการรับรองความถูกต้อง

- คุณลักษณะแฟล็ก `QUOTA_SELF_PANEL`, `false` เริ่มต้น ขณะที่ปิดอยู่ คำขอที่ไปถึงเส้นทางจะได้รับ 404 ด้วย `REQUIRE_API_KEY=true` นโยบายไคลเอ็นต์ API จะปฏิเสธคีย์ที่หายไปหรือไม่ถูกต้องด้วย 401 ก่อนที่เส้นทางจะทำงาน ไม่ว่าแฟล็กจะเป็นอย่างไรก็ตาม คำขอที่ไม่มีคีย์แต่มีเซสชันแดชบอร์ดที่ลงชื่อเข้าใช้ผ่านนโยบายนั้นและรับคำตอบของเส้นทางเอง การตั้งค่าสถานะได้รับการแก้ไขเช่นเดียวกับการตั้งค่าสถานะอื่น ๆ (แดชบอร์ดหรือ REST จากนั้นตัวแปรสภาพแวดล้อมที่มีชื่อเดียวกัน) ดู [`FEATURE_FLAGS.md`](../reference/FEATURE_FLAGS.md)
- ชื่อที่แสดงของแต่ละพูลและป้ายกำกับของกำหนดการแต่ละรายการจะถูกส่งกลับไปยังผู้ถือคีย์ของพูลทุกประการตามที่ผู้ดูแลระบบเขียนไว้ ก่อนที่จะเปิดแฟล็ก ให้ตรวจสอบว่าพอดีกับที่ผู้ถือกุญแจจะอ่านได้
- คีย์จะอ่านจากส่วนหัวเท่านั้น: `Authorization: Bearer <key>` หรือ `x-api-key: <key>` เมื่อทั้งสองถูกส่งไป ระบบจะใช้อันแรกที่ตรวจสอบความถูกต้อง คีย์ในสตริงการสืบค้นหรือคุกกี้จะถูกละเว้น รหัสสภาพแวดล้อมของเซิร์ฟเวอร์ถูกปฏิเสธ (401)
- คีย์ต้องการขอบเขต `self:usage` (403 ที่ไม่มีขอบเขต)
- เซ็กเมนต์ของผู้ให้บริการจะถูกตัดแต่ง ใช้ตัวพิมพ์เล็ก และตรวจสอบกับ `^[a-z0-9][a-z0-9._-]{0,63}$` (400 หรืออย่างอื่น) จากนั้นแก้ไขผ่านรีจิสทรีของผู้ให้บริการ ดังนั้นนามแฝง เช่น `cc` จะอ่านพูล `claude` `claude` และ `anthropic` อ่านพูลเดียวกัน

### การมองเห็นแต่ละครั้งแสดงให้เห็นอะไร

| การมองเห็น        | กำหนดให้มี                                                                           | เขตข้อมูล                                                                                                                                                                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ส่วนแบ่งของตัวเอง | `self:usage`                                                                         | `pools[]` (อ้างอิง, ชื่อ, ผู้ให้บริการ, นโยบาย, น้ำหนัก, หมวก), `dimensions[].yourShare`, `accounts[]` กับ `yourShare` (บนหน้าต่าง `percent` ไม่มี `attributed` และ `external`), `blocks`, `availableModels`, `expiresAt`, `apiBaseUrl`         |
| ระดับบัญชี        | `self:usage` + `self:account-quota` และผู้ให้บริการใน `sharedQuotaProviders` ของคีย์ | เพิ่ม `dimensions[].total`, `accounts[].dimensions[].account` และ `accounts[].modelWindows`, `attributed` และ `external` บน `yourShare` ของหน้าต่าง `percent` และ `members` บนพูลโดยเปิดการใช้งานสมาชิก (ดู [การใช้งาน Member](#member-usage) ) |

- `sharedQuotaProviders` เป็นการตั้งค่าต่อคีย์ (`PUT /api/keys/[id]/self-service`): `null` เป็นค่าเริ่มต้น หมายถึงผู้ให้บริการทุกรายที่เข้าถึงคีย์ได้ `[]` หมายถึงไม่มี `accountVisible` ของแต่ละพูลบอกว่าการมองเห็นแบบใดที่ใช้กับสระนั้น
- แถบบัญชีและหน้าต่างโมเดลจะแสดงเฉพาะสำหรับบัญชีที่อาจใช้การเชื่อมต่อคีย์เท่านั้น เมื่อคีย์มีรายการการเชื่อมต่อที่อนุญาต บัญชีภายนอกจะเก็บรายการ `Account N` ไว้โดยไม่มี `account` หรือ `modelWindows` รายการว่างหมายความว่าไม่มีข้อจำกัด สำหรับ `/v1/me/status` ผลรวมพูล (`dimensions[].total`) ไม่ได้ขึ้นอยู่กับรายการนั้น
- ตัวเลขสองตัวที่แสดงด้วย `self:usage` เพียงอย่างเดียวนั้นมาจากการใช้คีย์อื่น `exhausted` ของงบประมาณกำหนดการสะท้อนถึงการใช้ทุกคีย์ภายใต้กำหนดการนั้น ในพูลที่มีน้ำหนักเป็นศูนย์ทั้งหมด `weight` ของคีย์คือ `100 / number of members` ทั้งสองอย่างเป็นสิ่งที่บังคับใช้กับคีย์
- พูลจะถูกระบุโดย `ref` เท่านั้น ซึ่งเป็นค่าทึบแสงที่เชื่อมโยงกับคีย์การโทร ชื่อที่แสดง (`name`) รวมอยู่ด้วยตามที่ผู้ดูแลระบบเขียน `ref` ได้มาจากคีย์และพูลที่มีรหัสลับ API ของเซิร์ฟเวอร์ (`API_KEY_SECRET`) ลูกค้าจะต้องไม่คงอยู่: จะเปลี่ยนแปลงหากข้อมูลลับนั้นถูกหมุนเวียน
- บัญชีจะแสดงเป็น `Account 1`, `Account 2`, … ตามลำดับพูล ไม่มีการส่งคืนรหัสพูล รหัสการเชื่อมต่อ อีเมลบัญชี หรือชื่อบัญชี และการตอบกลับจะดำเนินผ่านสคีมาสัญญา ซึ่งจะทิ้งฟิลด์ใดๆ ไว้ภายนอก
- หน่วยนับได้ (`requests`, `tokens`, `usd`) ได้รับการรายงานว่าเป็นกลุ่มพูลที่ประตูโควต้าบังคับใช้: `limit` แผน = จำกัด บัญชี × ในพูล, `fairShare` = น้ำหนัก / 100 × `limit` (แยกเท่ากันเมื่อทุกน้ำหนักเป็น 0), `consumed` = ตัวนับของคีย์ในที่เก็บโควต้า `remaining` = `fairShare` − `consumed` พื้นอยู่ที่ 0
- `blocks.schedules` แสดงรายการหน้าต่างกำหนดการของคีย์ (`open`/`closed`, `blackout` หรือ `outside-window`, `retryAfterSeconds`, ชั้นสำรอง และงบประมาณของหน้าต่างถูกใช้ไปหรือไม่) `blocks.modelCaps` แสดงรายการขีดจำกัดต่อชั่วโมงต่อรุ่นพร้อมปริมาณการใช้
- คีย์นอกทุกกลุ่มของผู้ให้บริการจะได้รับ 200 ด้วย `pools: []`; `availableModels` (รหัส `qtSd/` ที่คีย์เห็นใน `/v1/models`) `expiresAt` และ `apiBaseUrl` ยังคงเต็มอยู่
- `apiBaseUrl` คือ `OMNIROUTE_PUBLIC_API_BASE_URL` จากนั้น `OMNIROUTE_PUBLIC_BASE_URL` อย่างอื่น `null` มันไม่เคยเป็นจุดกำเนิดของคำขอของตัวเอง

| `unavailable` | ไม่มีการอ่าน ตัวเลขคือ `null` ไม่เคย `0` `reason` บอกว่าทำไม                                                                                                                                                                                                                                                             |

| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |

### ความยินยอมในการให้กู้ยืม

`PATCH /api/v1/me/quota/{provider}` บันทึกความยินยอมของคีย์การโทรสำหรับหนึ่งพูล โดยจะใช้แฟล็ก ส่วนหัว และกฎของผู้ให้บริการของ `GET` ขอบเขต `self:usage` อนุญาตให้เขียนสิ่งนี้ได้ แม้ว่าชื่อจะอ่านได้อย่างเดียวก็ตาม

```json
{
  "pool": "qpr_0123456789abcdef0123456789abcdef",
  "lendingPercent": 30,
  "lendingUntil": 1893456000000
}
```

- `pool` คือ `ref` ที่ `GET` ส่งคืนสำหรับพูลนั้น
- `lendingPercent` เป็นจำนวนเต็มตั้งแต่ 0 ถึง 100 ค่า 0 จะล้างความยินยอมและกำหนดเวลา ยอมรับเนื้อหาที่มี `lendingPercent` 0 ในโหมดใดโหมดหนึ่ง
- `lendingUntil` เป็นทางเลือก: epoch มิลลิวินาที หรือ `null` โดยไม่มีกำหนดเวลา ต้องเป็นในอนาคตและไม่เกิน 8640000000000000 ค่าที่ต่ำกว่า 100000000000 จะอ่านเป็นวินาทีและถูกปฏิเสธ
- ฟิลด์อื่นใดจะถูกปฏิเสธ เนื้อความที่ยาวเกิน 4096 ไบต์จะถูกปฏิเสธ การอ่านจะหยุดที่ขนาดนั้น ดังนั้นตัวที่ยาวกว่าจะไม่ถูกยึดไว้ทั้งหมด

การตรวจสอบจะดำเนินการตามลำดับของตารางนี้ การปฏิเสธทุกครั้งจะใช้เนื้อหาข้อผิดพลาดมาตรฐานพร้อมข้อความคงที่ การปฏิเสธโดยเช็คข้อใดข้อหนึ่งจะไม่เกิดผลใดๆ

| สถานะ | ข้อความ                                                                                            | เมื่อไร                                                        |
| ----- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 404   | `Not found`                                                                                        | แฟล็ก `QUOTA_SELF_PANEL` ปิดอยู่                               |
| 401   | `Valid API key required`                                                                           | คีย์หายไปหรือไม่ถูกต้อง หรือเป็นคีย์สภาพแวดล้อมของเซิร์ฟเวอร์  |
| 403   | `API key lacks the self:usage scope`                                                               | คีย์ขาด `self:usage`                                           |
| 400   | `Invalid provider`                                                                                 | กลุ่มผู้ให้บริการไม่ถูกต้อง                                    |
| 429   | `Too many lending changes. Retry later.`                                                           | คีย์เกินขีดจำกัดแล้ว คำตอบดำเนิน `Retry-After`                 |
| 400   | `Body must be { pool, lendingPercent, lendingUntil }. lendingPercent is an integer from 0 to 100.` | เนื้อความไม่ JSON ยาวเกินไป หรือไม่ตรงกับสคีมา                 |
| 400   | `lendingUntil must be a Unix time in milliseconds`                                                 | กำหนดเวลาอ่านเป็นวินาที                                        |
| 400   | `lendingUntil must be in the future`                                                               | กำหนดเวลาอยู่ที่หรือก่อนเวลาที่ขอ                              |
| 404   | `Pool not found`                                                                                   | `ref` ตั้งชื่อว่าไม่มีพูลของคีย์นี้สำหรับผู้ให้บริการรายนี้    |
| 403   | `Lending is not enabled for this pool`                                                             | พูลอยู่ในโหมด `saturation` และ `lendingPercent` มีค่ามากกว่า 0 |
| 500   | `Failed to build quota view`                                                                       | ความล้มเหลวอื่นใด สาเหตุของมันถูกบันทึกไว้บนเซิร์ฟเวอร์        |

ขีดจำกัดคือ 20 คำขอต่อ 60 วินาทีสำหรับแต่ละคีย์ ทุกคำขอที่ผ่านการตรวจสอบของผู้ให้บริการจะนับ แม้กระทั่งคำขอที่ถูกปฏิเสธในภายหลังหรือคำขอที่ไม่เปลี่ยนแปลงอะไรเลย มีตัวนับของตัวเอง นอกเหนือจากขีดจำกัดอัตราคำขอของคีย์

คำขอที่เปลี่ยนแปลงความยินยอมที่เก็บไว้จะเขียนบันทึกการตรวจสอบ `quota.pool.lending.updated` หนึ่งรายการ มันตั้งชื่อคีย์ด้วยค่าเก่าและใหม่ เนื้อหาเดียวกันส่งการเขียนสองครั้งครั้งเดียวและตรวจสอบหนึ่งครั้ง คำตอบคือ 200 พร้อมมุมมอง `GET` แบบเต็ม ซึ่งสร้างขึ้นหลังจากการเขียน

มุมมอง `GET` รายงานการให้ยืมดังนี้:

- แต่ละพูลจะมี `borrowMode` (`saturation` หรือ `consent`) และคีย์ของคีย์เอง `lendingPercent` และ `lendingUntil`
- `lendingActive` เป็น `true` เฉพาะในพูล `consent` โดยมีเปอร์เซ็นต์สูงกว่า 0 และไม่ถึงกำหนดเวลา
- ในพูล `consent` แต่ละ `dimensions[].yourShare` ที่นับได้จะมี `borrowAvailable` นี่คือสิ่งที่คีย์อาจใช้เหนือส่วนแบ่งของมันในตอนนี้ โดยให้ยืมโดยคีย์อื่นๆ
- `borrowAvailable` ใช้สูตรของเกต มันจะอ่านคีย์อื่นๆ ทั้งหมด ในขณะที่คีย์นั้นอยู่ภายใต้การแชร์ของมัน สำหรับคีย์ `hard` ที่เป็นการอ่านเพิ่มเติมหนึ่งครั้งต่อคีย์อื่นๆ และมิติที่นับได้แบบขนาน
- `borrowAvailable` คือ `null` สำหรับคีย์ `soft` หรือ `burst` และ `null` เมื่อการอ่านล้มเหลว
- `borrowAvailable` เป็นรูปหนึ่งสำหรับคีย์อื่นๆ ทั้งหมดรวมกัน ในกลุ่มที่มีสองคีย์ มันคือร่างของอีกคีย์หนึ่งเอง
- `borrowAvailable` ยังไม่ถูกรายงานสำหรับ `percent` windows หรือใน `accounts[]`
- ในพูล `saturation` มุมมองจะรายงานความยินยอมที่เก็บไว้ด้วย `lendingActive: false` และไม่มี `borrowAvailable`

### ข้อผิดพลาด

ทุกการตอบสนองของเส้นทางนี้ ไม่ว่าจะสำเร็จหรือผิดพลาด จะมี `Cache-Control: no-store` ไปด้วย การปฏิเสธที่เกิดขึ้นก่อนการรันเส้นทางจะไม่เกิดขึ้น เช่น 401 ของนโยบาย API ของไคลเอ็นต์หรือ 403 ของตัวกรอง IP ข้อผิดพลาดของเส้นทางใช้เนื้อหาข้อผิดพลาดมาตรฐานพร้อมข้อความคงที่: 400 (ผู้ให้บริการไม่ถูกต้อง), 401 (คีย์หายไปหรือไม่ถูกต้อง), 403 (ขาดหายไป `self:usage`), 404 (ตั้งค่าสถานะปิด) และ 500 (`Failed to build quota view`) 500 ครอบคลุมความล้มเหลวใดๆ เมื่อคำขอไปถึงเส้นทาง รวมถึงการค้นหาคีย์ด้วย สาเหตุของมันถูกบันทึกไว้บนเซิร์ฟเวอร์และไม่เคยส่งคืน ข้อผิดพลาดของ `PATCH` แสดงอยู่ใน [Lendingยินยอม](#lending-consent)

### ข้อจำกัด

- `remaining` เป็นส่วนหนึ่งของส่วนแบ่งที่ยุติธรรมของคีย์ที่ไม่ได้ใช้ มันไม่ใช่การรับประกัน อาจยังคงรับกุญแจอยู่เลยในขณะที่สระว่ายน้ำยังมีที่ว่าง เมื่อผลรวมของพูลถึง `limit` แล้ว ทุกคีย์ของพูลจะถูกปฏิเสธ ไม่ว่าจะเป็นอะไรก็ตาม `remaining` และคีย์ที่ไม่มี `self:account-quota` จะไม่เห็นผลรวมนั้น
- `remaining` ไม่ได้นำ `cap` สัมบูรณ์ของการจัดสรรมาพิจารณาด้วย การบังคับใช้จะปฏิเสธคีย์เมื่อปริมาณการใช้ในหน้าต่างของหน่วยของฝาครอบถึงค่าของฝาครอบ
- แถบระดับบัญชีมาจากแคชขีดจำกัดของผู้ให้บริการ และทำให้การตัดสินใจบังคับใช้ล่าช้าไปไม่กี่นาที การอ่านค่าที่ผ่านไปแล้วจะถูกรายงานเป็น `stale`
- หน้าต่างต่อรุ่น (`modelWindows`) ได้รับการรายงานสำหรับผู้ให้บริการที่มีการแมปแผนหน้าต่างเท่านั้น: Claude และ Codex ในปัจจุบัน สำหรับผู้ให้บริการรายอื่น `modelWindows` ยังคงอยู่เมื่อมีการแสดงข้อมูลบัญชี โดยมีรายการ `windows` ว่างเปล่า
- ส่วนแบ่งของคีย์ในหน้าต่าง `percent` เป็นการประมาณการ มาจากหนังสือระบุแหล่งที่มาและมีข้อจำกัดทุกประการที่ระบุไว้ใน "มิติข้อมูลเปอร์เซ็นต์: การระบุแหล่งที่มาต่อคีย์" ด้านบน
- `consumed` คือการบังคับใช้ตัวเลขเปรียบเทียบกับส่วนแบ่งที่ยุติธรรม มันคือ `attributed` บวก `external` เป๊ะๆ `attributed` คือส่วนที่หนังสือให้กุญแจสำหรับโทเค็นที่กำหนดเส้นทาง `external` เป็นส่วนหนึ่งของการใช้บัญชีของคีย์ซึ่งคีย์ของพูลไม่ได้คำนึงถึง
- ทั้งสองส่วนจะถูกส่งเมื่อ `accountVisible` ของพูลเป็นจริงเท่านั้น: คีย์มี `self:account-quota` และผู้ให้บริการอยู่ใน `sharedQuotaProviders` คีย์ที่ไม่มีคีย์จะได้รับ `consumed` เพียงอย่างเดียวโดยมี `status` และ `reason` เหมือนกัน
- ด้วยทั้งชิ้นส่วนและน้ำหนักของมันเอง ที่จับจึงสามารถคำนวณการใช้งานนอกสระที่ชาร์จเข้ากับกุญแจของสระได้ เจ้าของที่มีขอบเขตบัญชีจะเห็นยอดรวมของบัญชีแล้ว
- คีย์ที่ไม่กำหนดเส้นทางใด ๆ ในหน้าต่างยังคงสามารถอ่านประจุภายนอกจาก `consumed` ได้ เนื่องจากส่วนที่ประกอบเป็น 0
- ตัวอย่างเช่น หนังสือเปิดที่ 0 โดยปุ่ม A และ B มีน้ำหนักปุ่มละ 50 คีย์ A กำหนดเส้นทาง 900,000 โทเค็น และคีย์ B 100,000 จากนั้นบัญชีถึง 60% ของขีดจำกัด 100 จากนั้น `attributed` จะเป็น 54 สำหรับคีย์ A และ 6 สำหรับคีย์ B และ `external` เป็น 0 สำหรับทั้งสอง
- มุมมองอ่านหนังสือและไม่เคยเขียนสถานะของหนังสือ มันไม่ได้เปิดหนังสือและไม่เคยขอให้ผู้ให้บริการอ่านด้วย ด้วยที่เก็บ Redis การอ่านจะลบฟิลด์การแก้ไขที่ถูกแทนที่ในพื้นหลัง เหมือนกับที่เกตทำการอ่าน
- การแชร์จะเป็น `ok` เท่านั้นในขณะที่แคชของเกทเก็บการอ่านบัญชีไว้ หากไม่มีสิ่งใดเลย `stale` ดังนั้นในพูลที่ไม่มีคำขอล่าสุดแสดงว่าอาจล้าสมัย
- จนกว่าคำขอจะผ่านพูล การใช้ร่วมกันจะไม่พร้อมใช้งาน คำขอดังกล่าวจะเปิดหนังสือ และตัวเลขของบัญชีในขณะนั้นจะถูกนับเป็นการใช้งานนอกกลุ่ม
- ในกลุ่มที่มีหลายบัญชี รายการบัญชีแต่ละรายการจะใช้สมุดบัญชีของตนเองและจำกัดเพียงบัญชีเดียว การบังคับใช้จะปรับขนาดทั้งสองฝ่ายตามจำนวนบัญชี ดังนั้นสัดส่วนจึงเท่ากัน
- กระจกหน้าต่างแต่ละรุ่นไม่มีการแชร์กุญแจ หนังสือเล่มนี้ไม่เก็บข้อมูลต่อรุ่น
- ชั้นสำรองของกำหนดการไม่ได้รับการประเมินโดยมุมมอง: กำหนดการสามารถแสดงเป็น `open` ในขณะที่คำขอถูกปฏิเสธด้วยเหตุผล `schedule-reserve`
- เมื่อคีย์เดียวกันสองกลุ่มใช้การเชื่อมต่อร่วมกัน การบังคับใช้จะใช้หนึ่งในนั้น และมุมมองจะแสดงทั้งสองรายการ
- ไม่มีการจำกัดต่อที่อยู่สำหรับความพยายามในการคีย์ที่ล้มเหลว: เบื้องหลังผู้เรียกพร็อกซีแบบย้อนกลับสามารถแชร์ที่อยู่เดียวได้ (ขึ้นอยู่กับว่าที่อยู่ไคลเอ็นต์ที่ส่งต่อนั้นเชื่อถือได้หรือไม่) ดังนั้นการล็อคอาจปฏิเสธเส้นทางไปยังผู้ถือกุญแจทุกราย เมื่อใช้ `REQUIRE_API_KEY=true` คีย์ที่ไม่ถูกต้องจะถูกปฏิเสธโดยนโยบาย API ไคลเอ็นต์ก่อนที่เส้นทางจะทำงาน โดยมีเนื้อหา 401 ของนโยบายนั้นแทนที่จะเป็นเส้นทางนี้

### การใช้งานของสมาชิก

ผู้ดูแลระบบสามารถให้ผู้ถือกุญแจดูว่าการใช้งานของหน้าต่างแบ่งระหว่างสมาชิกของพูลอย่างไร ตัวเลือกคือ `memberBreakdown` ของพูล ปิดตามค่าเริ่มต้น มันถูกตั้งค่าในตัวช่วยสร้างพูลหรือด้วย `PATCH /api/quota/pools/{id}` `GET /api/quota/pools` และ `GET /api/quota/pools/{id}` รายงานมัน

มิติของมุมมองจะมี `members` เฉพาะเมื่อสิ่งเหล่านี้ทั้งหมดมีอยู่:

- ตัวเลือกของพูลเปิดอยู่
- พูลมีคีย์ที่จัดสรรไว้มากที่สุด 20 คีย์ และอย่างน้อย 3 คีย์สามารถส่งคำขอได้: ใช้งานอยู่ ไม่เพิกถอน ไม่ถูกแบน และไม่เลยวันหมดอายุ
- `accountVisible` ของพูลเป็นจริง: คีย์มี `self:account-quota` และผู้ให้บริการอยู่ใน `sharedQuotaProviders`
- ในหน้าต่าง `percent` การเชื่อมต่อของบัญชีคือคีย์ที่อาจใช้
- ส่วนแบ่งของคีย์ในหน้าต่างนั้นถูกอ่าน: `status` ไม่ใช่ `unavailable`

มิฉะนั้น `members` จะหายไป มันไม่เคยเป็นรายการที่ว่างเปล่า

- แต่ละชิ้นคือ `{ slot, consumed, isYou }` สคีมาการตอบสนองจะปฏิเสธคุณสมบัติอื่นใดบนสไลซ์และรายการมากกว่า 20 สไลซ์ ชิ้นจะแสดงรายการตามลำดับช่อง
- มีหนึ่งชิ้นต่อคีย์ที่จัดสรร รวมถึงคีย์ที่ไม่สามารถส่งคำขอได้อีกต่อไป สมาชิกที่ไม่มีประโยชน์จะแสดงค่าศูนย์จริง
- ช่องที่ 1 จะเป็นปุ่มถามเสมอ โดยที่ `isYou` เป็นจริง หมายเลขช่องอื่นๆ เป็นลำดับของคีย์แฮช มันถูกคีย์ด้วย `API_KEY_SECRET` และครอบคลุมพูล คีย์ถาม และสมาชิก
- ดังนั้นตัวเลขจึงไม่เรียงกันระหว่างผู้ถือ สำหรับผู้ถือครองรายหนึ่ง พวกเขายังคงเหมือนเดิมระหว่างการมาเยือน พวกเขาสามารถเปลี่ยนแปลงได้เมื่อคีย์เข้าร่วมหรือออกจากพูล หรือเมื่อข้อมูลลับนั้นถูกหมุน
- บนหน้าต่างที่นับได้ ชิ้นคือตัวนับของสมาชิกในร้านค้าโควต้า ซึ่งเป็นตัวนับเดียวกันกับตัวมันเอง `consumed`
- บนหน้าต่าง `percent` ชิ้นเป็นส่วน `attributed` ของสมาชิก จากหนังสือเล่มเดียวกันที่อ่านเป็นการแชร์ของคีย์ การใช้งานนอกสระจะไม่ถูกแบ่งเป็นชิ้นๆ ประจุนั้นแบ่งตามน้ำหนัก ดังนั้นชิ้นส่วนที่บรรทุกมันจึงจะแสดงน้ำหนัก
- แต่ละมุมมองจะอ่านค่าหนึ่งค่าต่อสมาชิกอื่นและหน้าต่างที่นับได้พร้อมกัน บนหน้าต่าง `percent` ส่วนต่างๆ ไม่มีค่าใช้จ่ายในการอ่าน นอกเหนือจากการอ่านหนังสือของการแบ่งปัน เมื่อไม่สามารถอ่านค่าหนึ่งได้ หน้าต่างนั้นจะไม่มี `members` และการแชร์ของคีย์จะยังคงอยู่
- ตัวเลือกและจำนวนคีย์ที่ใช้งานได้จะถูกอ่านหนึ่งครั้งต่อพูล และเฉพาะคีย์ที่อาจดูข้อมูลบัญชีเท่านั้น การอ่านตัวเลือกที่ล้มเหลวหรือการนับจำนวนคีย์ที่ใช้งานได้จะปิดแถบสำหรับพูลนั้น เซิร์ฟเวอร์บันทึกคำเตือน และสร้างมุมมองส่วนที่เหลือ

แถบไม่มีชื่อหรือรหัส พวกเขายังคงบอกผู้ถือกุญแจเกี่ยวกับสมาชิกคนอื่นๆ:

- ผู้ถือยังคงสามารถจับคู่ชิ้นส่วนตามค่าได้
- การกำหนดหมายเลขที่มั่นคงช่วยให้ผู้ถือติดตามสมาชิกคนหนึ่งเมื่อเวลาผ่านไป
- จำนวนสไลซ์แสดงจำนวนคีย์ที่ได้รับการจัดสรรในพูล
- ในกลุ่มคีย์สามคีย์ คนที่รู้ว่าคีย์หนึ่งใช้อะไรสามารถบอกได้ว่าคีย์สุดท้ายใช้อะไร
- เมื่อพูลลดลงต่ำกว่าสามคีย์ที่ใช้งานได้ แถบจะหายไป การดูก่อนหน้านี้ยังคงแสดงให้เห็นว่าสมาชิกแต่ละคนใช้อะไร
- บนหน้าต่างที่นับได้ ผลรวมพูลลบด้วยสไลซ์สามารถแสดงการใช้คีย์ที่ไม่ได้รับการจัดสรรอีกต่อไป
- สมาชิกที่แสดงศูนย์ต่อบัญชีหนึ่งและใช้ในอีกบัญชีหนึ่งสามารถแสดงว่าสมาชิกคนใดใช้บัญชีใด
- ในพูลที่นับได้ที่มีนโยบาย `hard` ชิ้นที่หยุดเติบโตเมื่อส่วนแบ่งที่ยุติธรรมของสมาชิกบ่งบอกถึงน้ำหนักของสมาชิกนั้น

### ชุดการใช้งาน (`GET /api/v1/me/usage`)

`GET /api/v1/me/usage?range=<range>` (ยังให้บริการที่ `/v1/me/usage`) ส่งคืนการใช้งานและต้นทุนของคำขอของคีย์การโทร: ผลรวม หนึ่งรายการต่อ UTC วัน ต่อวันและโมเดล ต่อโมเดล และต่อผู้ให้บริการ โดยจะแชร์แฟล็ก กฎการตรวจสอบสิทธิ์ ขอบเขต `self:usage` `Cache-Control: no-store` และพฤติกรรมข้อผิดพลาดของเส้นทางโควต้าด้านบน คีย์จะถูกตรวจสอบก่อน `range` ข้อผิดพลาดคือ 400 (`Invalid range`), 401, 403, 404 และ 500 (`Failed to build usage`)

- `range` เป็นหนึ่งใน `1d`, `7d`, `30d` (ค่าเริ่มต้น) หรือ `90d` ค่าอื่นใด ค่าว่าง หรือพารามิเตอร์ที่ซ้ำกันคือ 400 ชุดหยุดที่ `90d` เพื่อผูกค่าใช้จ่ายในการโทร มุมมองจะอ่านประวัติการใช้งานดิบเท่านั้น ไม่อ่านสรุปรายวันซึ่งไม่มีคีย์
- แถวจะถูกเลือกโดยรหัสของปุ่มโทร คอลัมน์ชื่อคีย์จะไม่ตรงกัน และแถวที่บันทึกโดยไม่มีรหัสคีย์จะไม่ถูกนับ
- การสร้างซีรีส์จะดำเนินการค้นหาห้ากลุ่มบนแถวของคีย์ในหน้าต่าง ซีรีส์ที่สร้างขึ้นจะถูกนำมาใช้ซ้ำเป็นเวลา 60 วินาทีต่อคีย์และช่วง และการเรียกใช้ซ้ำจะไม่ทำงานเลย `generatedAt` ของมันให้อายุของมัน
- หน้าต่างจะสิ้นสุดลงเมื่อมีการสร้างซีรีส์ แถวที่ประทับภายหลัง เช่น โดยการเอียงนาฬิกา จะไม่นับ
- `coverage.retentionDays` คือการตั้งค่าการเก็บรักษาประวัติการใช้งานดิบของผู้ดำเนินการ (`retention.usageHistory` ในการตั้งค่าฐานข้อมูล) `coverage.truncatedByRetention` เป็นจริงเมื่อช่วงที่ร้องขอยาวกว่าการตั้งค่านั้น โดยจะเปรียบเทียบตัวเลขทั้งสองและไม่ตรวจสอบว่าแถวหายไปจริงหรือไม่
- ผู้ให้บริการจะถูกส่งกลับตามที่บันทึกไว้สำหรับคำขอของคีย์เอง โมเดลคือชื่อที่บันทึกไว้หลัง `/` สุดท้าย และแถวต่างๆ จะถูกจัดกลุ่มตามโมเดล คำขอคอมโบที่ทุกเป้าหมายถูกปฏิเสธจะถูกบันทึกพร้อมกับป้ายกำกับเส้นทางในฐานะผู้ให้บริการ (ชื่อคอมโบ `auto` หรือ `combo`) และสตริงโมเดลที่ไคลเอนต์ส่ง คำขออื่นๆ ที่ถูกปฏิเสธ เช่น โดยเบรกเกอร์วงจรเปิด คูลดาวน์โมเดล หรือการข้ามโควต้าที่จอดไว้ ให้คงผู้ให้บริการเป้าหมายและโมเดลไว้
- นอกจากการนับและต้นทุนแล้ว การตอบสนองยังมีเวลาแฝงโดยเฉลี่ย อัตราความสำเร็จ และเวลาของคำขอแรกและคำขอสุดท้าย
- `byModel` แสดงรายการคู่ผู้ให้บริการและรุ่น 50 คู่ที่มีการร้องขอมากที่สุด หากมีคู่มากขึ้น รายการจะไม่รวมกันเป็น `summary` และ `summary.uniqueModels` จะนับทุกการสะกดแบบจำลองที่บันทึกไว้ `byModelTruncated` เป็นจริง และแบบจำลองที่มีคู่อยู่ทั้งสองด้านของการตัดจะแสดงผลรวมบางส่วน
- มีการรายงานค่าใช้จ่ายสองรายการ `costUsd` คือต้นทุนที่เรียกเก็บ ดังที่การวิเคราะห์การใช้งานแสดงให้เห็น ผู้ให้บริการสมัครสมาชิกแบบเหมาจ่าย เช่น แผน Claude Code นับ 0 ดอลลาร์ที่นั่น `listPriceUsd` เป็นราคาการใช้งานเดียวกันกับราคาปลีก รวมการสมัครใช้งานแล้ว คำขอที่มีโมเดลไม่มีแถวราคาจะนับต้นทุนที่เก็บไว้: ต้นทุนที่ผู้ให้บริการรายงาน หรือต้นทุนที่คำนวณเมื่อมีการบันทึกคำขอ เฉพาะคำขอที่ไม่นับ 0 โดยไม่มีเครื่องหมาย ดังนั้นผลรวมจึงสามารถเป็นบางส่วนได้
- สัญญาตอบกลับคือ `src/shared/schemas/selfUsage.ts` (`SelfUsageSeries` ใน `docs/openapi.yaml`)

### หน้าบริการตนเอง

เมื่อเปิด `QUOTA_SELF_PANEL` ไว้ `/quota/{provider}` จะเป็นเพจสาธารณะ ผู้ถือกุญแจพิมพ์คีย์ API ที่นั่นและเห็นว่าพูลของคีย์นั้นสำหรับผู้ให้บริการ แต่ละพูลจะแสดงการ์ดหนึ่งใบต่อหน้าต่างพูล โดยการใช้พูลสำหรับทุกคนและส่วนแบ่งของคีย์เอง แต่ละบัญชีของพูลจะมีการ์ดของตัวเอง พร้อมด้วยการใช้บัญชีและส่วนแบ่งของคีย์ การใช้งานบัญชีจะปรากฏเฉพาะเมื่อคีย์อาจเห็นข้อมูลบัญชีเท่านั้น หน้านี้ยังแสดงรายการขีดจำกัดต่อรุ่นของแต่ละบัญชีและการใช้งานของคีย์ด้วย การแจ้งเตือนจะปรากฏขึ้นเมื่อกำหนดการบล็อกคีย์ในขณะนี้ การ์ดจะแสดงรายการขีดจำกัดของคีย์แต่ละรุ่นพร้อมการใช้งาน และทำเครื่องหมายว่าถึงขีดจำกัดแล้ว `{provider}` เป็นรหัสผู้ให้บริการหรือนามแฝง (`/quota/claude`, `/quota/cc`) ผู้ให้บริการที่ไม่รู้จัก และทุกเส้นทาง `/quota/*` ขณะที่แฟล็กปิดอยู่ ให้ตอบ 404 พูลบนโหนดที่เข้ากันได้กับ OpenAI หรือ Anthropic แบบกำหนดเองไม่มีเพจ API ยังคงตอบสำหรับพวกเขา

เพจไม่มีเซสชัน คีย์จะถูกส่งเฉพาะในส่วนหัว `Authorization` ของ `GET /api/v1/me/quota/{provider}`, `PATCH /api/v1/me/quota/{provider}` และ `GET /api/v1/me/usage` ไม่เคยอยู่ใน URL คีย์ที่เซิร์ฟเวอร์ยอมรับจะถูกเก็บไว้ใน `sessionStorage` ของแท็บ เมื่อใช้ "จดจำบนอุปกรณ์นี้" อุปกรณ์จะเก็บไว้ใน `localStorage` แทน และ "ลืมรหัส" จะลบออกจากอุปกรณ์ทั้งสอง คีย์ที่เซิร์ฟเวอร์ปฏิเสธจะถูกลบออกจากที่เก็บข้อมูล

พูลในโหมด `consent` แสดงบัตรการให้ยืม ผู้ถือกุญแจจะตั้งค่าเปอร์เซ็นต์ทั้งหมดตั้งแต่ 0 ถึง 100 ของส่วนแบ่งการไม่ได้ใช้งานของกุญแจที่จะให้ยืม ผู้ถือยังเลือกระยะเวลาที่ความยินยอมจะคงอยู่: จนกว่าจะปิด, 1 ชั่วโมง, 8 ชั่วโมง, 24 ชั่วโมง, 7 วัน หรือ 30 วัน ระยะเวลานับจากช่วงเวลาที่บันทึก ในขณะที่กำหนดเวลามีผลใช้บังคับ ผู้ถือสามารถเก็บไว้แทนได้ หากกำหนดเวลาดังกล่าวผ่านไปก่อนบันทึก การ์ดจะไม่ส่งอะไรเลยและขอตัวเลือกอื่น ด้วย 0% จะไม่มีการส่งกำหนดเวลา การ์ดจะแสดงกำหนดเวลาที่เก็บไว้พร้อมชื่อโซนเวลา ความยินยอมที่เลยกำหนดเวลาไปแล้วจะแสดงเป็นสิ้นสุด

สำหรับคีย์ `hard` การ์ดยังแสดงรายการต่อหน้าต่างพูลด้วย ว่าคีย์อื่นใดที่ยืมให้กับคีย์ในขณะนี้ แต่ละแถวเป็นรูปหนึ่งสำหรับคีย์อื่นๆ ทั้งหมดรวมกัน ในกลุ่มที่มีสองคีย์ มันคือร่างของอีกคีย์หนึ่งเอง ตัวเลขที่มุมมองไม่รายงานการอ่านว่าไม่พร้อมใช้งาน ไม่ใช่ศูนย์ สำหรับคีย์ `soft` หรือ `burst` การ์ดจะบอกว่าไม่มีตัวเลข

พูลในโหมด `saturation` ซึ่งคีย์เก็บเปอร์เซ็นต์สูงกว่า 0 จะแสดงการถอนออกเท่านั้น มันบอกว่าเปอร์เซ็นต์ที่เก็บไว้ไม่มีผลที่นั่น ปุ่มถอนเงินจะส่ง 0 โดยไม่มีกำหนดเวลา พูลในโหมด `saturation` ด้วยค่า 0 ที่เก็บไว้แสดงว่าไม่มีบัตรให้ยืม หลังจากบันทึก การ์ดที่มุมมองที่ส่งคืนไม่ต้องการอีกต่อไปจะคงอยู่กับข้อความจนกว่ามุมมองของเพจจะเปลี่ยนไปอีกครั้ง

ไม่มีสิ่งใดถูกบันทึกจนกว่าผู้ถือจะกดบันทึกหรือถอน การกดแต่ละครั้งจะส่งคำขอ `PATCH /api/v1/me/quota/{provider}` หนึ่งคำขอ และการกดครั้งที่สองจะไม่ส่งอะไรเลยในขณะที่คำขอแรกอยู่ระหว่างการพิจารณา ร่างกายจะแบก `ref` ทึบแสงของสระจากมุมมอง เปอร์เซ็นต์ และกำหนดเวลา คำตอบคือมุมมองโควต้าที่สร้างขึ้นใหม่และหน้าจะแสดงโดยไม่ต้องอ่านครั้งที่สอง เมื่อบันทึกสองรายการทับซ้อนกัน เพจจะอ่านโควต้าหนึ่งครั้งหลังจากคำตอบสุดท้าย หน้านี้ไม่ได้เก็บความยินยอมไว้ในที่เก็บข้อมูลของเบราว์เซอร์

การเปลี่ยนแปลงที่ถูกปฏิเสธจะมีการอธิบายบนการ์ดด้วยข้อความที่เลือกจากสถานะ HTTP ไม่ได้อ่านเนื้อหาข้อผิดพลาด 401 แจ้งว่าคีย์ไม่ได้รับการยอมรับและโหลดโควต้าใหม่ 403 บอกว่าพูลไม่ได้รับการเปลี่ยนแปลงการให้ยืม และ 404 บอกว่าพูลหายไปแล้ว ทั้งสองมีปุ่มที่จะโหลดโควต้าซ้ำ คำตอบ 400 หรือ 4xx อื่นขอให้ผู้ถือตรวจสอบเปอร์เซ็นต์และกำหนดเวลา 429 ขอให้ผู้ถือรอ โดยมีวินาทีเป็น `Retry-After` เมื่อคำตอบให้ คำตอบ 5xx, 408 หรือเครือข่ายล้มเหลวแจ้งว่าการเปลี่ยนแปลงอาจไม่ได้รับการบันทึก และเก็บค่าที่พิมพ์ไว้ คำตอบนอกสัญญาจะรีโหลดโควต้า การบันทึกที่ล้มเหลวไม่ได้ลบคีย์ออกด้วยตัวเอง เมื่อโหลดซ้ำหลังจากถูกปฏิเสธ เพจจะลบคีย์เหมือนกับการอ่านที่ถูกปฏิเสธ

เมื่อยอมรับคีย์แล้ว หน้าดังกล่าวจะแสดงการ์ด "ตั้งค่าเครื่องมือ" พร้อมแท็บ 3 แท็บด้วย "Claude Code" ให้บล็อก `env` สำหรับ `~/.claude/settings.json`"Shell" ให้ตัวแปรเหมือนกับบรรทัด `export` "Claude Desktop" จะให้ค่าสำหรับหน้าต่างการอนุมานของบุคคลที่สาม โมเดลเหล่านี้คือโมเดลการแบ่งโควต้าที่คีย์อาจเรียกใช้สำหรับผู้ให้บริการรายนั้น เมื่อไม่มีรายการดังกล่าวมาพร้อมกับคีย์ บล็อกจะเปิดการค้นหาโมเดลเกตเวย์แทน ที่อยู่เกตเวย์คือต้นกำเนิด API สาธารณะที่เซิร์ฟเวอร์รายงาน (`OMNIROUTE_PUBLIC_API_BASE_URL` จากนั้น `OMNIROUTE_PUBLIC_BASE_URL`) เมื่อไม่ได้ตั้งค่าทั้งสอง การ์ดจะแสดงพื้นที่ที่สำรองไว้และบอกให้ผู้ถือถามผู้ดูแลระบบ คีย์จะแสดงเป็นตัวยึดตำแหน่ง "รวมรหัสของฉัน" จะใส่รหัสทั้งหมดลงในข้อความบนหน้าจอและในสิ่งที่ปุ่มคัดลอกคัดลอก ซึ่งจะคงอยู่จนกว่ากล่องจะถูกล้าง ลืมหรือเปลี่ยนกุญแจ หรือหน้าถูกทิ้งไว้ การ์ดไม่ส่งคำขอและไม่มีการดาวน์โหลดไฟล์

การอ่านเครื่องหมาย API `stale` แสดงว่าอาจล้าสมัย การอ่านที่ทำเครื่องหมาย `unavailable` จะแสดงพร้อมเหตุผล ไม่ใช่ศูนย์

ตามแผนเปอร์เซ็นต์ เพจจะดึงส่วนแบ่งของคีย์เองเมื่อ API รายงาน มันบอกว่าตัวเลขเป็นเพียงค่าประมาณและตั้งชื่อเป็นสองส่วน ขีดจำกัดต่อรุ่นจะแสดงเฉพาะบัญชีเท่านั้น

เมื่อหน้าต่างมี `members` การ์ดจะแสดงแถบที่มีหนึ่งส่วนต่อสมาชิกตามลำดับช่อง ส่วนของคีย์ถามจะใช้สีที่ถูกเน้น ส่วนอื่นๆ วนไปตามสีแผนภูมิของธีม คำอธิบายข้อความจะแสดงรายการทุกส่วนด้วยค่าของมัน ดังนั้นจึงไม่มีอะไรขึ้นอยู่กับสี เซ็กเมนต์จะมีป้ายกำกับว่า `You` หรือ `Member N` โดยที่ N คือช่อง

### พอร์ตเฉพาะสำหรับเพจ

`QUOTA_PANEL_PORT` เปิด Listener ตัวที่สองที่ให้บริการเฉพาะหน้าบริการตนเอง ปิดอยู่เว้นแต่จะตั้งค่าตัวแปรไว้ `QUOTA_PANEL_HOST` เป็นที่อยู่การเชื่อมโยงและมีค่าเริ่มต้นเป็น `127.0.0.1`

ผู้ฟังถ่ายทอดเส้นทางเหล่านี้ไปยังพอร์ตหลักและตอบ 404 สำหรับเส้นทางอื่น ๆ :

| เส้นทาง                                                                  | เสิร์ฟ                            |
| ------------------------------------------------------------------------ | --------------------------------- |
| `/quota/{provider}`                                                      | หน้า                              |
| `/api/v1/me/quota/{provider}`, `/v1/me/quota/{provider}`                 | โควต้าดูหน้าอ่าน                  |
| `/api/v1/me/usage`, `/v1/me/usage`                                       | ชุดการใช้งานที่เพจอ่าน            |
| `/_next/static/`                                                         | สคริปต์ สไตล์ และแบบอักษรของบิลด์ |
| `/favicon.ico`, `/favicon.svg`, `/icon-512.png`, `/apple-touch-icon.png` | ไอคอน                             |

`GET` และ `HEAD` ถูกถ่ายทอดโดยไม่มีเนื้อหา คำขอหนึ่งรายการที่มีเนื้อความก็จะถูกส่งต่อเช่นกัน: `PATCH` ของเส้นทางการดูโควต้า ซึ่งเพจจะส่งไปเพื่อบันทึกตัวเลือกการให้กู้ยืม วิธีอื่นใดจะตอบ 404 ยกเว้นคำขอ CONNECT ซึ่งการเชื่อมต่อถูกปิดโดยไม่มีคำตอบ คำขออื่นใดที่ประกาศว่าเนื้อหาตอบ 404 และการเชื่อมต่อถูกปิด คำขออัปเกรดถูกปฏิเสธและการเชื่อมต่อถูกปิด เส้นทางที่มีส่วนของจุดหรือเครื่องหมายส่วนจะถูกปฏิเสธ เช่นเดียวกับบนพอร์ต API เป้าหมายคำขอที่มีอักขระอยู่นอก ASCII ที่พิมพ์ได้ก็เช่นกัน อักขระควบคุมดิบในเป้าหมายจะได้รับคำตอบ 400 โดยตัวแยกวิเคราะห์ HTTP ก่อนที่จะตรวจสอบพอร์ตนี้เอง ส่วนหัวคำขอที่เฟรมเวิร์กสงวนไว้สำหรับการใช้งานของตัวเองไม่ได้รับการส่งต่อ: ชื่อที่ขึ้นต้นด้วย `x-middleware-`, `x-invoke-`, `x-nextjs-`, `x-now-` หรือ `x-next-` และชื่อ `x-matched-path` และ `next-resume` คำขอจะถูกส่งต่อโดยไม่มีพวกเขา ไม่สามารถเข้าถึงแดชบอร์ด หน้าเข้าสู่ระบบ API การจัดการ และเส้นทางการอนุมานผ่านพอร์ตนี้ได้

`PATCH` ต้องมี `Content-Type: application/json` โดยไม่มีพารามิเตอร์หรือมีเพียง `charset=utf-8` เท่านั้น ต้องมีหนึ่ง `Content-Length` ตั้งแต่ 1 ถึง 4096 ซึ่งเขียนเป็นตัวเลขธรรมดา และไม่มี `Transfer-Encoding` `PATCH` ที่ฝ่าฝืนกฎข้อใดข้อหนึ่งเหล่านี้จะตอบ 404 ความยาวที่มีรูปแบบไม่ถูกต้อง เช่น ความยาวที่ลงนามหรือซ้ำ จะได้รับคำตอบ 400 โดยตัวแยกวิเคราะห์ HTTP ก่อนการตรวจสอบของพอร์ตนี้เอง พอร์ตจะอ่านไบต์ที่ประกาศก่อนที่จะติดต่อกับพอร์ตหลัก และรอไม่เกิน 5 วินาที เนื้อความที่ไม่สมบูรณ์ภายในเวลานั้นจึงตอบ 404 และการเชื่อมต่อถูกปิด ไม่มีสิ่งใดไปถึงท่าเรือหลักในกรณีนั้น หรือเมื่อลูกค้าออกไปก่อน พอร์ตถ่ายทอดไบต์ที่ประกาศไว้ทุกประการ โดยมี `Content-Length` เหมือนกัน ไบต์หลังจากนั้นจะถูกอ่านเป็นคำขอถัดไปในการเชื่อมต่อ พร็อกซีย้อนกลับ TLS ที่อยู่ด้านหน้าจะต้องส่งต่อ `Content-Length` และต้องไม่สร้างเนื้อหาคำขอซ้ำ พอร์ตหลักจะตรวจสอบคีย์ API ในส่วนหัว `Authorization` เช่นเดียวกับ `GET`

ตัว 404 คือ `{"error":"not_found","message":"Not found."}` รีเลย์ที่ล้มเหลวจะตอบ 502 (`api_bridge_unavailable`) หรือ 504 (`api_bridge_timeout`) โดยไม่มีฟิลด์ `detail`

Listener ไม่ได้อ่าน `QUOTA_SELF_PANEL` และไม่เปิดเพจ ขณะที่แฟล็กปิดอยู่ เพจและ API ของเพจจะตอบ 404 บนพอร์ตหลัก และผู้ฟังจะถ่ายทอดคำตอบนั้น

ภายใต้เซิร์ฟเวอร์การพัฒนา (`next dev`) เพจจะไม่โต้ตอบผ่านพอร์ตนี้ ซ็อกเก็ต hot-reload การพัฒนาเป็นการร้องขอการอัพเกรด และพอร์ตปฏิเสธ ใช้พอร์ตหลักในขณะที่พัฒนา

พอร์ตให้บริการ HTTP ธรรมดาและเพจจะส่งคีย์ API เก็บที่อยู่การเชื่อมโยงเริ่มต้นไว้และใส่พร็อกซีย้อนกลับที่มี TLS อยู่ข้างหน้า ที่อยู่การเชื่อมโยงอื่นที่ไม่ใช่ลูปแบ็คจะบันทึกการแจ้งเตือนนี้:

```text
[Quota Panel] Bound to <host>. This port serves plain HTTP and the page sends API keys. Put a TLS reverse proxy in front of it.
```

เพียร์ย้อนกลับที่ไม่ส่งส่วนหัวการส่งต่อจะนับเป็นโลคัลบนพอร์ตหลัก ดังนั้นพร็อกซีบนโฮสต์เดียวกันจะต้องส่ง `X-Forwarded-For` พร็อกซีบนที่อยู่ส่วนตัวได้รับความเชื่อถือสำหรับส่วนหัวนั้นด้วย `OMNIROUTE_TRUST_PROXY=private` (หรือ `lan`) เท่านั้น เพียร์อื่นๆ จะถูกรายงานตามที่อยู่ของการเชื่อมต่อ และส่วนหัวการส่งต่อที่ส่งไปจะถูกละทิ้ง

Listener รองรับการเชื่อมต่อได้สูงสุด 256 รายการในแต่ละครั้ง ลูกค้ามีเวลา 10 วินาทีในการส่งส่วนหัวของคำขอ และ 30 วินาทีในการส่งคำขอทั้งหมด การเชื่อมต่อ Keep-alive ที่ไม่ได้ใช้งานจะปิดลงหลังจากผ่านไปประมาณ 5 วินาที การเชื่อมต่อที่ไม่มีกิจกรรมเป็นเวลา 60 วินาทีถูกปิด ค่าเหล่านี้ได้รับการแก้ไขแล้ว ตั้งค่าขีดจำกัดการเชื่อมต่อและอัตราบนพร็อกซีย้อนกลับด้านหน้าด้วย พร็อกซีย้อนกลับที่อยู่ด้านหน้าควรคงการเชื่อมต่ออัปสตรีมที่ไม่ได้ใช้งานไว้เป็นเวลาน้อยกว่า 5 วินาที หรือไม่นำมาใช้ซ้ำ รีเลย์ไปยังพอร์ตหลักใช้การหมดเวลาอัปสตรีมของพอร์ต API (`API_BRIDGE_*`)

Listener ยังเริ่มทำงานเมื่อไม่ได้ตั้งค่า `API_PORT` ไว้ `QUOTA_PANEL_PORT` ต้องเป็นพอร์ตตั้งแต่ 1 ถึง 65535 เขียนเป็นตัวเลขเท่านั้น ต้องแตกต่างจากพอร์ตแดชบอร์ดและพอร์ต API ขณะที่เซิร์ฟเวอร์ WebSocket ทำงานอยู่ เซิร์ฟเวอร์นั้นจะต้องแตกต่างจาก `LIVE_WS_PORT` ด้วย (ค่าเริ่มต้นคือ 20132) ค่าอื่นๆ จะไม่เปิดอะไรเลยและบันทึกคำเตือน คำเตือนเกี่ยวกับค่าที่ถูกปฏิเสธจะตั้งชื่อตัวแปรและไม่ทำซ้ำค่า พอร์ตที่ใช้งานอยู่แล้วจะไม่เปิดอะไรเลยและบันทึกคำเตือนนี้:

```text
[Quota Panel] Port <port> is already in use. The quota panel port stays off.
```

ด้วยชุด `OMNIROUTE_BASE_PATH` ผู้ฟังคาดหวังทุกเส้นทางด้านบนภายใต้คำนำหน้านั้น ใช้ `OMNIROUTE_BASE_PATH` เดียวกันในเวลาบิลด์และรันไทม์ เขียนโดยใช้เครื่องหมายทับนำหน้าและไม่มีเครื่องหมายทับต่อท้าย เช่น `/omniroute` รูปร่างอื่น รวมถึง `/` และ `/omniroute/` จะออกจากพอร์ตพร้อมกับคำเตือน แม้ว่า build จะยอมรับแบบฟอร์มเหล่านั้นก็ตาม เส้นทางฐานที่มีส่วนแรกชื่อเส้นทางแอปพลิเคชัน: `api`, `v1`, `v1beta`, `_next`, `quota`, `dashboard`, `docs`, `login`, `codex`, `responses`, `anthropic`, `openai`, `v0` หรือ `connect` ไม่ว่าในกรณีใด

ข้อจำกัด:

- `/quota/{provider}/` พร้อมด้วยเครื่องหมายทับต่อท้ายตอบ 404 บนพอร์ตนี้
- พนักงานบริการและรายการแอปพลิเคชันเว็บไม่ให้บริการบนพอร์ตนี้
- ไอคอน Fav แบบกำหนดเองที่ตั้งค่าไว้ในแดชบอร์ดจะไม่แสดงบนพอร์ตนี้
- ไอคอนจะไม่แสดงเมื่อแอปพลิเคชันทำงานภายใต้เส้นทางพื้นฐาน
- พอร์ตพูด HTTP/1.1. ธรรมดา
- การเชื่อมโยงที่ล้มเหลวจะไม่ถูกลองใหม่จนกว่ากระบวนการจะรีสตาร์ท
- ผู้ฟังไม่มีการเชื่อมต่อหรือจำกัดอัตราต่อที่อยู่ไคลเอ็นต์
- การตั้งค่าคอนเทนเนอร์ไม่ครอบคลุมอยู่ในส่วนนี้

## การแก้ไขปัญหา

### กำหนดค่า Redis แล้วแต่เชื่อมต่อไม่ได้

ตรวจสอบว่าติดตั้ง `ioredis` แล้ว (`npm ls ioredis`) และสามารถเข้าถึง
`QUOTA_STORE_REDIS_URL` ได้ หากการเชื่อมต่อล้มเหลว factory จะย้อนกลับไปใช้ SQLite (บันทึกที่ระดับ
`warn`)

### `peek` ส่งคืนข้อมูลเก่า / เปิดให้ผ่านเมื่อเกิดข้อผิดพลาด

หาก `peek` โยนข้อผิดพลาด `enforceQuotaShare` จะถือว่าผลลัพธ์เป็น "อนุญาต" (เปิดให้ผ่านเมื่อเกิดข้อผิดพลาด)
ตรวจสอบบันทึก `pino` สำหรับรายการ `quota:enforce` และ `quota:factory` เพื่อระบุ
สาเหตุที่แท้จริง

### ตัวนับการใช้งานคลาดเคลื่อน

หากการใช้งานจริงของผู้ให้บริการแตกต่างจากตัวนับ ถือว่าเป็นพฤติกรรมที่คาดไว้ — หน้าต่างเลื่อนแบบ
2 บักเก็ตมีข้อผิดพลาดประมาณ 1% ที่ขอบเขตของหน้าต่าง และ `consume` ทำงานแบบ
ส่งแล้วไม่รอผลหลังการตอบกลับ สัญญาณความอิ่มตัว (`saturationSignals.ts`)
จะอ่านอัตราการใช้งานจริงของผู้ให้บริการด้วย TTL 30 วินาที และปรับ `globalUsedPercent`
ตามนั้น

### พูลแสดง "ไม่มีข้อมูล" สำหรับอัตราการใช้

`computeBurnRate` ต้องมีตัวอย่างข้อมูลย้อนหลังอย่างน้อย 2 รายการ พูลใหม่ที่ยังไม่มีการเรียก
`consume` ก่อนหน้านี้จะแสดง `tokensPerSecond: 0` และ `timeToExhaustionMs: null`

## การย้ายข้อมูลจาก localStorage

เมื่อ `/dashboard/costs/quota-share` โหลดเป็นครั้งแรก hook `useLocalStoragePoolMigration`
จะตรวจสอบว่า:

1. `localStorage.getItem("omniroute:quota-share:pools")` ไม่ว่างเปล่า
2. `GET /api/quota/pools` ส่งคืน `[]` (DB ว่างเปล่า)

หากทั้งสองเงื่อนไขเป็นจริง ระบบจะส่งแต่ละ pool แบบเดิมไปยัง `POST /api/quota/pools` เป็นชุด
จากนั้นลบ key ใน localStorage การย้ายข้อมูลนี้เป็นแบบ idempotent: เงื่อนไขข้อ 2 ช่วยป้องกัน
การย้ายข้อมูลซ้ำ

## สรุปสคีมา DB

เพิ่มสามตารางโดยการโยกย้าย `078`, `079` และ `085`:

- `quota_pools` + `quota_allocations` — คำจำกัดความพูลและการจัดสรรต่อคีย์
- `quota_consumption` — กลิ้งเคาน์เตอร์ 2 ถังต่อ `(apiKeyId, dimensionKey)`
- `provider_plans` — การแทนที่แผนผู้ให้บริการด้วยตนเอง (ขนาด JSON ต่อ connectionId)

ตารางทั้งหมดที่เพิ่มผ่านการย้ายข้อมูล `CREATE TABLE IF NOT EXISTS` ของ idempotent

การให้ยืมที่ยินยอมจะเพิ่มสามคอลัมน์: `quota_allocations.lending_percent` (จำนวนเต็ม, ค่าเริ่มต้น 0), `quota_allocations.lending_until` (ยุคมิลลิวินาที หรือ `NULL` โดยไม่มีกำหนดเวลา) และ `quota_pools.borrow_mode` (ค่าเริ่มต้น `saturation`) การโยกย้ายจะเพิ่มคอลัมน์เหล่านี้เท่านั้นและไม่มีการเขียนแถวที่มีอยู่

หนังสือระบุแหล่งที่มาเป็นเปอร์เซ็นต์จะเพิ่ม `quota_percent_ledger` (หนึ่งแถวต่อพูล บัญชีและหน้าต่างแผน) และ `quota_percent_ledger_tokens` (หนึ่งตัวนับโทเค็นต่อพูล บัญชี และคีย์ API ) `src/lib/db/quotaPercentLedger.ts` อ่านและเขียนมัน
