> เลือกใช้ ปิด ตามค่าเริ่มต้น (`modelVisibilityAllowlist`/`modelVisibilityDenylist` ว่างทั้งสองรายการ ปล่อยให้แคตตาล็อก `/v1/models` AND ทุกไบต์ของผู้สมัคร `auto/*` ไบต์เหมือนกัน) รุ่นพี่ของ `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`) สำหรับโอเปอเรเตอร์ที่ต้องการรายการโมเดลที่ได้รับการดูแลด้วยเหตุผลที่ไม่เกี่ยวข้องกับต้นทุน

## ทำไมถึงมีสิ่งนี้

`hidePaidModels` ตอบว่า "รุ่นนี้ฟรีหรือเปล่า?" และ `hideAutoCombos` ตอบว่า "ควรโฆษณารหัสเสมือน `auto/*` เลยหรือไม่" — ไม่อนุญาตให้โอเปอเรเตอร์ดูแลจัดการชุดย่อยของโมเดลที่ต้องการ (เช่น การนำเสนอโมเดลที่ไคลเอ็นต์ Claude Code / OpenCode ควรเห็น โดยไม่ขึ้นกับราคา) #11481 เพิ่มสิ่งนั้นเป็นการตั้งค่าอาร์เรย์สตริงที่แยกจากกันสองรายการ

## การตั้งค่า

| สำคัญ                      | พิมพ์      | ค่าเริ่มต้น | ความหมาย                                                         |
| -------------------------- | ---------- | ----------- | ---------------------------------------------------------------- |
| `modelVisibilityDenylist`  | `string[]` | `[]`        | รายการที่ตรงกับผู้สมัครจะซ่อนจากพูล catalog/candidate            |
| `modelVisibilityAllowlist` | `string[]` | `[]`        | เมื่อไม่ว่างเปล่า รายการ ONLY ที่ตรงกับผู้สมัครจะยังคงถูกเปิดเผย |

ทั้งสองยอมรับได้สูงสุด 500 รายการ แต่ละรายการมีอักขระสูงสุด 200 ตัว (Zod-validated ใน `src/shared/validation/settingsSchemas.ts`) รายการคือ:

- รหัสแค็ตตาล็อกที่แน่นอน — `"gpt-4o"` (id โมเดลเปล่า) หรือ `"openai/gpt-4o"` (นำหน้าผู้ให้บริการ) หรือ
- รูปแบบ glob โดยใช้ `*`/`?` — เช่น `"openai/gpt-4*"` หรือ `"anthropic/*"` — แก้ไขผ่าน `globToRegex()` matcher ที่ใช้ร่วมกัน (`src/shared/utils/globPattern.ts`) ที่ใช้อยู่แล้วโดยการแมปคำสั่งผสมต่อรุ่นของ `ModelRoutingSection` และ `freeModels.ts::matchesOnlyPaidModels`

ลำดับความสำคัญ: รายการปฏิเสธจะถูกตรวจสอบก่อน (รายการที่ถูกปฏิเสธจะถูกซ่อนอยู่เสมอ แม้ว่าจะตรงกับรายการที่อนุญาตก็ตาม) เมื่อรายการที่อนุญาตไม่ว่างเปล่า เฉพาะรายการที่ตรงกันเท่านั้นที่จะยังคงอยู่

## จุดปิดสองจุด ไม่ใช่หนึ่งจุด

บทเรียนจาก #6512 (ตัวกรองแค็ตตาล็อก `hidePaidModels` -only ยังคงให้ `auto/*` กำหนดเส้นทางไปยังโมเดลแบบชำระเงิน เนื่องจากกลุ่มตัวเลือกคอมโบถูกสร้างขึ้นแยกจากกัน) จะมีผลเหมือนกันที่นี่ เพรดิเคตที่ตรงกัน `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`) ถูกเรียกจาก BOTH:

- `src/app/api/v1/models/catalog.ts` — รายการ `/v1/models` ของตัวเองที่จุดควบคุม 5 จุดต่อแหล่งที่มาเดียวกัน `shouldHidePaid()` ประตูแล้ว ( `PROVIDER_MODELS` แบบคงที่, แถวผู้ให้บริการที่ซิงค์, แถวที่กำหนดเอง, แถวที่สำรองด้วยนามแฝง, แถวสำรองที่มีการจัดการ)
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — ถูกเรียกจาก `virtualFactory.ts::buildPreparedPool` ทันทีหลังจากการเรียก `filterPaidOnlyCandidates()` ที่เทียบเท่า ดังนั้นจึงไม่สามารถเลือกแบบจำลองที่ถูกปฏิเสธในกลุ่มผู้สมัคร `auto/*` ได้เช่นกัน

## NOT กรองอะไร

พฤติกรรมที่มีอยู่ของ Mirrors `hideAutoCombos`: ส่งรหัสโมเดลแล้ว** อย่างชัดเจน** (ไม่ใช่ผ่าน `auto/*` และไม่ถูกค้นพบผ่านรายการแค็ตตาล็อก) จะไม่ถูกบล็อกที่การจัดส่ง — เฉพาะสมาชิก advertisement/candidate-pool เท่านั้นที่ถูกกรอง สิ่งนี้ไม่ขึ้นอยู่กับ `hidePaidModels`; ผู้ปฏิบัติงานอาจต้องการชุดที่ดูแลจัดการด้วยเหตุผลที่ไม่เกี่ยวข้องกับต้นทุน ดังนั้นการตั้งค่าทั้งสองจึงเขียนเป็นตัวกรอง AND-ed อิสระ เช่นเดียวกับองค์ประกอบ multi-flag ที่มีอยู่ใน `catalog.ts`

การตั้งค่าการส่งออก (`GET /api/settings/export-json`) รวมถึงอาร์เรย์ทั้งสองแบบคำต่อคำ เช่นเดียวกับฟิลด์การตั้งค่าอื่น ๆ — ซึ่งแตกต่างจากตัวกรองการส่งออกขั้นตอนคำสั่งผสมของ `hidePaidModels` ไม่มีความเสี่ยงในการเติมน้ำอีกครั้งที่นี่: รหัสที่ถูกปฏิเสธที่ฝังอยู่ในขั้นตอนคำสั่งผสมที่ส่งออกคือตัวเลือกการกำหนดเส้นทางที่ชัดเจนของผู้ปฏิบัติงาน ไม่ใช่สิ่งที่ขอบเขตการส่งออกจำเป็นต้องตัดออก

## รายการคอมโบเท่านั้น (`exposeCombosOnly`)

บูลีนที่แยกต่างหาก ซึ่งเลือกใช้และ `false` เป็นค่าเริ่มต้น สำหรับการปรับใช้โดยที่คอมโบเป็นโมเดลสาธารณะและผู้ให้บริการเป็นเพียงแบ็กเอนด์เท่านั้น เมื่อเป็น `true` รายการสาธารณะ (`GET /v1/models`, `GET /v1` และเส้นทางการค้นพบ `/v1` อื่นๆ ที่สร้างขึ้นบน `getUnifiedModelsResponse()`) จะเก็บเฉพาะแถวที่มี `owned_by: "combo"`: user combos บวกกับคอมโบ `auto/*` ในตัว (เว้นแต่ `hideAutoCombos` จะซ่อนไว้) โดยจะใช้การทดสอบแถวเดียวกันกับ per-key `catalogScope: "combos"` และตัวกรอง allow/deny/scope ของคีย์เองยังคงใช้อยู่ด้านบน

สลับเข้า** การตั้งค่า → การกำหนดเส้นทาง → รุ่น API รายการ** หรือด้วย `PATCH /api/settings {"exposeCombosOnly": true}`

เช่นเดียวกับรายการด้านบน การเปลี่ยนแปลงเฉพาะโฆษณา:

- รหัส `provider/model` ที่ชัดเจนยังคงถูกจัดส่ง และ `GET /v1/models/{id}` ยังคงแก้ไขได้
- แค็ตตาล็อกแดชบอร์ด (`GET /api/models/catalog` ใช้โดยตัวเลือกโมเดล) ไม่ได้ถูกจำกัดให้แคบลง
- มันไม่ได้มิเรอร์ลงในพูลผู้สมัคร `auto/*` ดังนั้นคอมโบ `auto/*` จึงเก็บพูลเต็มไว้
