ความล้มเหลวจะถูกจัดประเภทก่อนที่จะตัดสินใจลองอีกครั้ง

ความล้มเหลวชั่วคราว เช่น การหมดเวลา ข้อผิดพลาดของเครือข่าย ขีดจำกัดอัตรา และการตอบสนองของผู้ให้บริการ 5xx อาจล้มเหลว โควต้าหรือเครดิตที่หมด (โควต้า 429 หรือต้องชำระเงิน 402) จะไม่ลองใหม่กับผู้ให้บริการรายเดียวกัน แต่จะล้มเหลวในการส่งต่อไปยังผู้ให้บริการรายอื่นซึ่งมีโควต้าแยกจากกัน ข้อผิดพลาดในการรับรองความถูกต้อง ข้อผิดพลาดในการอนุญาต คำขอที่ไม่ถูกต้อง โมเดลที่ไม่พร้อมใช้งาน และความล้มเหลวที่ไม่รู้จักจะไม่ลองใหม่แบบสุ่มสี่สุ่มห้า

นโยบายผู้ให้บริการข้ามค่าเริ่มต้นอนุญาตให้พยายามใช้ผู้ให้บริการได้สูงสุดสามครั้ง พยายามจำกัดอัตราและหมดเวลาอีกครั้ง โอเวอร์โอเวอร์เมื่อโควต้าหมด และแยกการปิดใช้งานด้านการดูแลระบบแยกจากสถานะวงจรชั่วคราว

## มันใช้ที่ไหน

- **คอมโบ** ล้มเหลวระหว่างเป้าหมายตามกลยุทธ์และการตั้งค่าของคอมโบ
- **รหัสโมเดลเปลือย** (ไม่มีคำนำหน้า `provider/` ) ที่ผู้ให้บริการที่ใช้งานอยู่หลายรายให้บริการ โดยไม่มีคำสั่งผสมของชื่อที่ตรงกันทั้งหมด จะถูกส่งไปยังตัวเลือกการอนุมานของผู้ให้บริการก่อน หากความพยายามนั้นล้มเหลวในลักษณะที่นโยบายล้มเหลว คำขอเดียวกันจะถูกส่งไปยังผู้ให้บริการรายถัดไปที่ใช้งานอยู่ซึ่งให้บริการรหัส การตอบกลับจะมี `x-omniroute-fallback-attempts` โดยมีจำนวนผู้ให้บริการที่ลองก่อนผู้ให้บริการที่ตอบ
  - ทางเลือกแต่ละรายการจะได้รับอนุญาตเหมือนกับว่าการอนุมานได้เลือกมันแล้ว เป้าหมายที่คีย์ API บล็อกหรือไม่ยอมรับจะถูกข้ามโดยไม่มีการเรียกอัปสตรีม และไคลเอ็นต์ได้รับข้อผิดพลาดอัปสตรีมที่แท้จริง ไม่ใช่การปฏิเสธนโยบายสำหรับเป้าหมายที่ไม่เคยตั้งชื่อ
  - เฉพาะการตอบสนองที่ล้มเหลวเท่านั้นที่จะดำเนินต่อไป: ไม่มีอะไรล้มเหลวหลังจากไบต์แรกที่สตรีม
  - การสลับโมเดลสำรองฉุกเฉินจะใช้หลังจากที่ผู้ให้บริการทุกรายของโมเดลที่ร้องขอล้มเหลวเท่านั้น
  - คำขอที่ตรึงไว้กับการเชื่อมต่อ (`x-omniroute-connection`) จะยังคงอยู่
  - รหัสนำหน้า (`provider/model`) จะไม่ถูกเปลี่ยนเส้นทางไปยังผู้ให้บริการรายอื่น

สถานะของวงจรคือ `closed`, `open` และ `half_open` คูลดาวน์กำหนดเวลาการสอบสวนที่มีขอบเขต โพรบที่สำเร็จจะปิดวงจร และโพรบที่ล้มเหลวจะเปิดใหม่อีกครั้ง
