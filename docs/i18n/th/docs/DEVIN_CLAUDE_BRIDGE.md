`devin-cli-agentic` ช่วยให้รันไทม์ Claude Code ตัวจริงสามารถใช้ปลายทาง Anthropic
Messages ภายในเครื่องของ OmniRoute ขณะที่ Devin CLI อย่างเป็นทางการส่งการตอบกลับของโมเดลผ่าน ACP stdio โดย
จะไม่แก้ไขผู้ให้บริการ Anthropic, Claude OAuth, Claude Web หรือ `devin-cli` ที่มีอยู่

สำหรับการเรียกใช้เครื่องมือที่ไคลเอนต์เป็นผู้ควบคุม ให้กำหนดเส้นทางผ่าน `devin-cli-agentic` (นามแฝง `dva`) ซึ่งเป็น
ผู้ให้บริการที่รองรับเครื่องมือในรูปแบบ Claude ส่วนตัวดำเนินการ ACP แบบเดิม `devin-cli` (`dv`) รองรับ
เฉพาะข้อความเท่านั้น: โดยจะเรียกใช้ตัวสรุปแบบไม่มีเครื่องมือของ Devin และไม่สามารถส่งคืนการเรียกใช้เครื่องมือได้ เมทาดาทาของโมเดล
ถูกทำเครื่องหมายไว้ตามนั้น เพื่อให้การกำหนดเส้นทางแบบผสมที่ต้องใช้เครื่องมือหลีกเลี่ยงผู้ให้บริการนี้

> **สถานะปัจจุบัน: ตรึง Claude Code ไว้ที่ `2.1.258`; การตรวจสอบแบบออฟไลน์และแบบสดได้รับการบันทึกครั้งล่าสุด
> บน `2.1.220`** การตรึงเวอร์ชัน `2.1.220` ดำเนินการครบสามสถานการณ์ที่แยกจากกันผ่าน Devin CLI
> `3000.2.17` และโมเดล `swe-1-7-lightning`; การรันแบบสดครั้งสุดท้ายนั้นพิสูจน์การทำงานของ `Read`,
> `Edit` และ `Bash` ที่ไคลเอนต์เป็นผู้ควบคุม ผลลัพธ์ `npm test` ที่สำเร็จ การค้นพบคำสั่งและสกิล
> ของโปรเจกต์ การกำหนดเส้นทางผ่าน Devin เท่านั้น และไม่มีทราฟฟิกขาออกไปยัง Claude จากนั้นจึงเพิ่มเวอร์ชันที่ตรึงไว้เป็น `2.1.258`
> (ซึ่งเป็นรุ่นของ CLI ที่ข้อมูลประจำตัว Claude ของ OmniRoute ปลอมเป็น และเป็นรุ่นแรกที่มาพร้อม
> ระดับ Fable 5.1 โดยตรง) สำหรับเวอร์ชันที่ตรึงใหม่นี้ ได้ตรวจสอบเลเยอร์การติดตั้งและ `claude --version`
> บนอิมเมจฐานที่ตรึงไว้แล้ว และชุดทดสอบยูนิตของบริดจ์, `compose config` และ
> หลักฐานการแยกแบบสแตติกผ่านทั้งหมด — แต่ยังไม่ได้รันสถานการณ์จำลองแบบออฟไลน์และชุดทดสอบ
> สามสถานการณ์แบบสดอีกครั้ง โปรดรันรายการเหล่านี้อีกครั้ง (ดู "การอัปเดตเครื่องมือที่ตรึงเวอร์ชันไว้") ก่อนใช้งาน
> บริดจ์กับเวอร์ชันที่ตรึงนี้

## สถาปัตยกรรม

```text
Claude Code 2.1.258 (คอนเทนเนอร์ Linux แบบแยกที่ไม่ใช่ root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (รูปแบบ Claude, ผู้ให้บริการที่ไม่ต้องยืนยันตัวตน)
  -> devin acp --agent-type summarizer (ACP stdio อย่างเป็นทางการ, ไม่มีเครื่องมือ Devin)
  -> บัญชี Devin ในวอลุ่ม devin-auth เฉพาะ
```

เอเจนต์ ACP เริ่มต้นของ CLI อย่างเป็นทางการสามารถเรียกใช้เครื่องมือของตนเองได้ ดังนั้นบริดจ์นี้จึงไม่ใช้
เอเจนต์ดังกล่าว แต่จะเริ่มเอเจนต์ ACP แบบ `summarizer` ที่กำหนดตายตัว ซึ่งโหมด CLI อย่างเป็นทางการไม่มีเครื่องมือ และ
จัดเฟรมคำขอ Anthropic ที่ซีเรียลไลซ์แล้วเป็นร่องรอยการดำเนินการ เมื่อต้องการการดำเนินการอื่นที่ Claude เป็นผู้ควบคุม
การตอบกลับต้องมีเอนเวโลปเครื่องมือฝั่งไคลเอนต์เพียงหนึ่งรายการเท่านั้น `tool_call` หรือ
`tool_call_update` ใดๆ จาก ACP จะถูกปฏิเสธก่อนที่จะสามารถรายงานว่าการตอบกลับ
สำเร็จ

ซีเรียลไลเซอร์ใน `open-sse/executors/devin-agentic/serializer.ts` จะคง `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` และ
เครื่องมือที่ Claude Code จัดเตรียมไว้ รูปภาพและบล็อกที่ไม่รู้จักจะล้มเหลวอย่างชัดเจน ผลลัพธ์เครื่องมือขนาดใหญ่
จะใช้เครื่องหมายระบุการตัดทอนที่มองเห็นได้

พาร์เซอร์ยอมรับเอนเวโลป `<tool>{...}</tool>` แบบเดี่ยวหนึ่งรายการต่อหนึ่งเทิร์นของโมเดล โดยจะตรวจสอบ
ชื่อกับรายการเครื่องมือของคำขอ ตรวจสอบอาร์กิวเมนต์กับ JSON
Schema ของเครื่องมือนั้น ปฏิเสธการผสมข้อความบรรยายกับการดำเนินการ และอนุญาตให้ซ่อมแซมได้หนึ่งครั้งภายในขอบเขตที่กำหนด จากนั้น Claude Code
จะเรียกใช้ `tool_use` ของ Anthropic ที่ได้ภายในเครื่อง และส่ง `tool_result` กลับผ่าน
OmniRoute

## การกำหนดเส้นทางอัตโนมัติ

ผู้ให้บริการนี้มีสิทธิ์อยู่ในพูลผู้สมัคร `auto/*` ของ OmniRoute เมื่อไม่ได้ถูกบล็อก
การมีสิทธิ์เป็นผู้สมัครไม่ได้รับประกันว่าจะถูกเลือก: กลยุทธ์การกำหนดเส้นทางของคอมโบ (ตัวอย่างเช่น
รายการล่าสุดที่ทราบว่าใช้งานได้) อาจเลือกผู้ให้บริการรายอื่นก่อน ใช้ `dva/<model>` หรือคอมโบที่ให้ Devin มาก่อนเมื่อ
คุณต้องการให้ทุกคำขอผ่าน Devin

## การแยกสภาพแวดล้อมและแบบจำลองภัยคุกคาม

การติดตั้ง Claude, บัญชี และการกำหนดค่าบนโฮสต์อยู่นอกขอบเขตและถือเป็นสิ่งต้องห้าม
บริการ Compose:

- ทำงานด้วย UID/GID `10001:10001` พร้อมระบบไฟล์รากแบบอ่านอย่างเดียว การเพิกถอน capabilities และ
  `no-new-privileges`;
- ใช้ `/home/bridge` แบบส่วนตัว, volume การกำหนดค่า Claude โดยเฉพาะ, ข้อมูล OmniRoute ที่แยกออกจากกัน
  และ volume `devin-auth` แยกต่างหาก;
- เมานต์เฉพาะ workspace/evidence `.sandbox` ที่ใช้แล้วทิ้งได้;
- ไม่เมานต์ home ของโฮสต์, Keychain, ข้อมูลรับรอง SSH, ข้อมูลรับรองระบบคลาวด์ หรือ Docker socket;
- สร้าง environment อย่างชัดเจนและลบตัวแปร Anthropic API/OAuth/routing;
- กำหนดให้การอนุมานของ Claude Code ส่งไปยัง `http://omniroute:20128` เท่านั้น โดยใช้คีย์เฉพาะภายในเครื่อง

โปรไฟล์ออฟไลน์ใช้เครือข่ายภายใน ในโปรไฟล์แบบ live นั้น OmniRoute จะเข้าถึง
endpoint อย่างเป็นทางการของ Devin ผ่าน `network-guard` เท่านั้น และปฏิเสธปลายทางอื่นที่ไม่เกี่ยวข้อง
Claude Code มีตัวป้องกันทราฟฟิกขาออกแบบปฏิเสธทั้งหมดแยกต่างหาก และสามารถเข้าถึงได้เฉพาะบริการ OmniRoute
ภายในเครื่องผ่าน `NO_PROXY` เท่านั้น ไฟล์บันทึกการตรวจสอบของตัวป้องกันจะถูกเมานต์โดยกระบวนการตัวป้องกันที่เกี่ยวข้องเท่านั้น
สคริปต์จะตรวจสอบความเป็นเจ้าของไฟล์, mode, จำนวนลิงก์ และทุกการตัดสินใจก่อนส่งออก
หลักฐานที่ไม่มีโทเค็น

เรียกใช้การพิสูจน์การแยกสภาพแวดล้อมอย่างอิสระ:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

คำสั่งนี้ตรวจสอบ topology, named mounts, การตั้งค่า non-root/read-only, การกำหนดเส้นทางภายในเครื่องอย่างชัดเจน,
การไม่มีตัวแปร environment ที่ละเอียดอ่อน, การไม่มี Docker socket, การปิดกั้นการเข้าถึง
`api.anthropic.com` และ `claude.ai`, การเลือกเฉพาะผู้ให้บริการ Devin และการล้มเหลวอย่างชัดเจนเมื่อ
backend ของ ACP ไม่พร้อมใช้งาน

## การตั้งค่าครั้งแรกและการใช้งานตามปกติ

สร้าง image ที่ตรึงเวอร์ชันไว้:

```bash
./scripts/devin-bridge/build
```

ยืนยันตัวตนเฉพาะ volume Devin ที่แยกไว้:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

คำสั่งเข้าสู่ระบบใช้ขั้นตอน manual-token อย่างเป็นทางการซึ่งออกแบบมาสำหรับ environment
แบบรีโมต/คอนเทนเนอร์ ค่าจะถูกป้อนโดยตรงในพรอมต์ของ CLI โดยไม่ได้ส่งเป็น
อาร์กิวเมนต์ของกระบวนการ, เขียนลง Git หรือคัดลอกจากโฮสต์

เปิดใช้ runtime ของ Claude Code ที่แยกสภาพแวดล้อมไว้:

```bash
./scripts/devin-bridge/launch
```

`launch` จะตรวจสอบการแยกสภาพแวดล้อม, การยืนยันตัวตน Devin และการค้นหาโมเดลอีกครั้งก่อนเริ่ม
Claude Code ภายในคอนเทนเนอร์ โดยจะไม่เรียกใช้ executable ของ Claude บนโฮสต์ นามแฝงของโมเดลสามารถ
กำหนดได้ใน `.env.devin-bridge`; ค่าที่กำหนดไว้ทุกค่าต้องคงคำนำหน้า
`devin-cli-agentic/` ไว้

## คำสั่งสำหรับการตรวจสอบความถูกต้อง

เส้นทางออฟไลน์ที่ทำซ้ำได้ไม่จำเป็นต้องใช้บัญชี Devin และไม่มีการเชื่อมต่ออินเทอร์เน็ตขณะทำงาน:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

เส้นทาง live แบบเลือกใช้ที่ผ่านการยืนยันตัวตนคือ:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ตัวรันแบบ live จะรอระหว่างแต่ละสถานการณ์เพื่อหลีกเลี่ยงการเปิดเซสชัน ACP แบบต่อเนื่องในคราวเดียว และ
ตรวจสอบเหตุการณ์ stream แบบมีโครงสร้างของ Claude แทนการเชื่อคำกล่าวอ้างในข้อความ สถานการณ์ทั้งสาม
พิสูจน์สิ่งต่อไปนี้:

1. การอ่านโปรเจกต์โดยตรงและการวิเคราะห์ข้อบกพร่อง;
2. `Edit` จริง, `Bash` `npm test` ที่ไคลเอนต์เป็นผู้ควบคุม และผลลัพธ์ปลายทาง;
3. `/bridge-check` พร้อมการค้นพบ `bridge-proof`, การอ่านโปรเจกต์, `npm test`
   ที่ไคลเอนต์เป็นผู้ควบคุมและสำเร็จอีกครั้ง รวมถึงการทำงานเสร็จสิ้นโดยไม่มีงานค้างอยู่

ด่านตรวจสอบสุดท้ายยังตรวจสอบบันทึกการตรวจสอบเครือข่ายของ Devin และกำหนดให้บันทึกการตรวจสอบทราฟฟิกขาออกของ Claude
ต้องว่างเปล่าตลอดเวลา

## การอัปเดตเครื่องมือที่ตรึงเวอร์ชันไว้

อิมเมจตรึงเวอร์ชันของ Node, Claude Code และ Devin CLI ไว้ใน
`docker/devin-bridge/Dockerfile` หากต้องการอัปเดต:

1. เปลี่ยนเวอร์ชันที่ระบุไว้อย่างชัดเจน
2. แทนที่ checksum ของไฟล์เก็บถาวร Devin สำหรับทั้งสองสถาปัตยกรรมด้วยค่าของอาร์ติแฟกต์อย่างเป็นทางการ
3. สร้างใหม่และเรียกใช้คำสั่งตรวจสอบแบบออฟไลน์ทุกคำสั่ง
4. ยืนยันเวอร์ชันภายในอิมเมจ
5. เรียกใช้ชุดทดสอบจริงสามสถานการณ์ที่มีการยืนยันตัวตนอีกครั้ง

ห้ามติดตั้ง CLI ใดๆ จากทั้งสองรายการแบบโกลบอลบนโฮสต์ หรือแทนที่การตรวจสอบ checksum ด้วยการดาวน์โหลดที่ไม่มีการตรวจสอบ

## การวินิจฉัยและการล้างข้อมูล

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  แสดงการกำหนดเส้นทางภายในเครื่องและข้อผิดพลาดของตัวดำเนินการที่ผ่านการกรองข้อมูลละเอียดอ่อนแล้ว
- `.sandbox/evidence/mock-acp.jsonl` บันทึกการดำเนินการ ACP จำลองที่ให้ผลลัพธ์แบบกำหนดแน่นอน
- `.sandbox/evidence/claude-stream.jsonl` บันทึกการเรียกใช้ Claude Code แบบออฟไลน์จริง
- `.sandbox/evidence/live-*.jsonl` บันทึกสตรีมจริงสามรายการที่ผ่านการตรวจสอบแล้ว
- `.sandbox/evidence/egress.jsonl` และ `.sandbox/evidence/claude-egress.jsonl` เป็นสำเนาบันทึกการตรวจสอบการรับส่งข้อมูลขาออกที่ผ่านการตรวจสอบแล้วและไม่มีโทเค็น

หยุดคอนเทนเนอร์และเครือข่ายที่เป็นของระบบ โดยคงวอลุ่มสำหรับการเข้าสู่ระบบ/การกำหนดค่าไว้:

```bash
./scripts/devin-bridge/clean
```

ลบสภาพแวดล้อมทั้งหมดที่เป็นของบริดจ์ รวมถึง named volume:

```bash
./scripts/devin-bridge/clean --all
```

## ข้อจำกัด

- บริดจ์อาศัยบทบาท `summarizer` แบบไม่มีเครื่องมือที่กำหนดไว้ตายตัว เนื่องจาก Devin CLI `3000.2.17`
  ไม่ได้เปิดเผยเอเจนต์ ACP ที่เป็นกลางและไม่มีเครื่องมือ อะแดปเตอร์จะชดเชยการตอบกลับระหว่างทาง
  ที่มีรูปแบบคล้ายบทสรุป แต่การซ่อมแซมที่จำกัดไว้หนึ่งครั้งยังคงอาจล้มเหลวอย่างชัดเจนได้
- การเรียก ACP แบบจริงอาจได้รับการตอบกลับ `502`/`504` ชั่วคราว ชุดทดสอบจะเว้นช่วงระหว่างสถานการณ์ต่างๆ
  หากยังคงล้มเหลวอย่างต่อเนื่อง ระบบจะยังคงปิดเมื่อเกิดความล้มเหลวและจะไม่เลือกผู้ให้บริการรายอื่น
- บริบท ACP จะถูกสร้างขึ้นใหม่จากคำขอ Anthropic แต่ละรายการ โดยไม่มีความผูกพันกับโปรเซส/เซสชัน
- รองรับการเรียกเครื่องมือหนึ่งครั้งต่อการตอบกลับของโมเดล และจะปฏิเสธการเรียกแบบขนาน
- ไม่รองรับรูปภาพอย่างชัดเจน และไม่มีการประกาศรองรับการมองเห็น เอาต์พุตกระบวนการคิด การควบคุมระดับความพยายาม หรือหน้าต่างบริบทขนาด 1M
- SSE ใช้อีเวนต์วงจรชีวิตของ Anthropic ที่ถูกต้อง แต่จะส่งออกหลังจากรวบรวมรอบ ACP ที่มีขอบเขตจำกัดเสร็จแล้ว โดยจะไม่ส่งต่อชิ้นข้อมูล ACP แบบเพิ่มขึ้นทีละส่วน
