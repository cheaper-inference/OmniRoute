สัญญา `config/cli-tools-manifest.json` ที่เป็นกลางประกาศ canonical IDs นามแฝง ตัวเลือกไบนารี สูตรการตั้งค่า อาร์กิวเมนต์โมเดล และความสามารถ อะแดปเตอร์โหนดธรรมดาใน `bin/cli/cli-manifest.mjs` และอะแดปเตอร์ TypeScript ใน `src/shared/constants/cliIntegrationManifest.ts` อ่านไฟล์เดียวกัน รันไทม์ แค็ตตาล็อก กำหนดค่า ความสมบูรณ์ ตัวสร้าง และการลงทะเบียนแบ็กเอนด์ได้รับการตรวจสอบร่วมกันโดย `tests/unit/cli/cli-manifest-drift.test.ts` การจัดทำแค็ตตาล็อกไม่ได้หมายความว่าสามารถเปิดใช้หรือกำหนดค่าเครื่องมือได้ โดยเฉพาะอย่างยิ่ง 5dive ยังคงกำหนดค่าไว้เท่านั้น

## สภาพแวดล้อมและวงจรชีวิตของเด็ก

`omniroute run`, `omniroute launch` และ `omniroute launch-codex` สืบทอดรายการอนุญาตความเข้ากันได้ OS/terminal และแทรกข้อมูลรับรองของเป้าหมายที่เลือก ผู้ให้บริการที่ไม่เกี่ยวข้องและความลับของฐานข้อมูลจะไม่สืบทอดตามค่าเริ่มต้น `--inherit-env` คืนค่าการสืบทอดสภาพแวดล้อมพาเรนต์แบบเต็มอย่างชัดเจน ใช้เมื่อกระบวนการของบุคคลที่สามที่เลือกควรได้รับค่าเหล่านั้นเท่านั้น นี่คือการกรองสภาพแวดล้อม ไม่ใช่แซนด์บ็อกซ์ OS : กระบวนการยังคงทำงานโดยมีสิทธิ์ระบบไฟล์ของผู้เรียก

สัญญาณขัดจังหวะและการยุติจะถูกส่งต่อไปยังเด็ก ตัวเรียกใช้งานจะรอเหตุการณ์ปิดของเด็กก่อนที่จะลบการกำหนดค่าชั่วคราว `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` ควบคุมระยะเวลาผ่อนผันก่อนการบังคับยุติ (ค่าเริ่มต้นคือ 5,000 มิลลิวินาที)

## Gemini การตั้งค่าแบบถาวร

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

คำสั่งสองคำสั่งแรกกำหนดค่าเครื่องนี้สำหรับเซิร์ฟเวอร์ภายในหรือเซิร์ฟเวอร์ระยะไกลที่เลือก การตั้งค่าจะรักษาการตั้งค่า JSON ที่ไม่เกี่ยวข้อง เลือก Gemini API-key auth และเขียนจุดสิ้นสุดและข้อมูลรับรองลงในไฟล์ `.gemini/.env` ส่วนตัว มันปฏิเสธ JSON ที่ไม่ถูกต้องแทนที่จะเขียนทับ จุดสิ้นสุด URLs ต้องเป็น HTTP(S) โดยไม่มีข้อมูลรับรอง พารามิเตอร์การค้นหา หรือแฟรกเมนต์ฝังอยู่ เส้นทางการพิมพ์แบบทดลองรัน ไม่ใช่ค่าข้อมูลรับรอง

`GEMINI_CLI_HOME` หรือ `--gemini-home` เลือกโฮมรูทถาวร `run gemini` จริงจะสร้างและลบบ้านชั่วคราวของตัวเองออกในภายหลัง ไม่มีโหมดใดข้ามการตรวจสอบ workspace-trust ของ Gemini

## โปรไฟล์Codex

`configure codex` เขียน `<name>.config.toml` ส่วนตัวพร้อมโมเดลและจุดสิ้นสุดของผู้ให้บริการ OmniRoute ข้อมูลรับรองมีการอ้างอิงผ่าน `OMNIROUTE_API_KEY` โดยไม่มีการฝัง คำสั่ง launch จะตั้งค่าโมเดลที่เลือกไว้ที่คีย์ `model` ระดับบนสุด ไม่ใช่ภายใน `model_providers`

ไฟล์โปรไฟล์ที่แยกจากกันคือสัญญา Codex ที่จัดทำเป็นเอกสารปัจจุบัน พวกเขาซ้อนทับการกำหนดค่าผู้ใช้เมื่อเลือกด้วย `codex --profile <name>` ดู [การอ้างอิงโปรไฟล์อย่างเป็นทางการ](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) และ [คู่มือ OmniRoute Codex](./CODEX-CLI-CONFIGURATION.md)

## การดำเนินการคำสั่ง Hermetic

เมื่อใช้ `DATA_DIR` ที่ชัดเจน การตั้งค่า `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` จะป้องกันไม่ให้สตาร์ทอัพตกสู่สภาพแวดล้อมข้อมูลประจำตัวของไดเร็กทอรีข้อมูลผู้ใช้เริ่มต้น สิ่งนี้มีประโยชน์สำหรับการทดสอบแบบแยกส่วน ไม่ปิดใช้งานไฟล์สภาพแวดล้อมอื่นๆ ที่เลือกไว้อย่างชัดเจน

## ไดเร็กทอรีการทำงาน `.env`

CLI อ่านไฟล์ `.env` ตามลำดับนี้ และไฟล์แรกที่ตั้งค่าคีย์จะชนะ: `DATA_DIR` ที่ชัดเจน ไดเร็กทอรีข้อมูลดีฟอลต์ ไดเร็กทอรีการทำงานปัจจุบัน ตามด้วยไดเร็กทอรีแพ็กเกจ ตัวแปรเชลล์จะชนะเสมอ

ไดเร็กทอรีการทำงานอาจเป็นของบุคคลอื่น (พื้นที่เก็บข้อมูลโคลน, ไฟล์เก็บถาวรที่คลายแพ็ก) และ `omniroute serve` ส่งสภาพแวดล้อม CLI ไปยังเซิร์ฟเวอร์และไปยังทุกเครื่องมือที่เซิร์ฟเวอร์ทำงาน ดังนั้น `.env` อาจตั้งค่าเฉพาะคีย์เหล่านี้ซึ่งแสดงอยู่ใน `bin/cli/utils/untrustedCwdEnv.mjs`:

| สำคัญ                           | ค่าที่ยอมรับ                                                             |
| ------------------------------- | ------------------------------------------------------------------------ |
| `REQUIRE_API_KEY`               | `true`, `1` หรือ `yes` ไม่ว่าในกรณีใด ค่าที่เซิร์ฟเวอร์จะถือว่าเปิด      |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | สูงสุด 64 ตัวอักษร, ตัวเลข, `_`, `.`, `@` หรือ `-`                       |
| `LANGUAGE`                      | เหมือนกัน บวก `:`                                                        |
| `TZ`                            | สูงสุด 64 ตัวอักษร, ตัวเลข, `_`, `+`, `-` หรือ `/` โดยไม่ขึ้นต้นด้วย `/` |
| `NO_COLOR`, `FORCE_COLOR`       | มากถึง 16 ตัวอักษรและตัวเลข                                              |

ทุกค่าที่ `REQUIRE_API_KEY` ยอมรับจะเปิดการตรวจสอบ ดังนั้นไฟล์จึงไม่สามารถปิดการตรวจสอบได้เอง แต่ไม่ได้ตัดสินผลลัพธ์: เซิร์ฟเวอร์อ่านการแทนที่ `REQUIRE_API_KEY` ที่จัดเก็บไว้ในฐานข้อมูลก่อนสภาพแวดล้อม ในขณะที่คำเตือนการเริ่มต้นเกี่ยวกับการฟังบนอินเทอร์เฟซทั้งหมดที่ไม่มีคีย์ API จะอ่านเฉพาะสภาพแวดล้อม ด้วยการแทนที่ที่เก็บไว้ `false` `REQUIRE_API_KEY=true` ไดเร็กทอรีการทำงานจะปล่อยให้ API เปิดอยู่และซ่อนคำเตือนนั้น กฎ `TZ` นั้นแคบกว่า POSIX: ปฏิเสธ `.`, `:`, `,` และ `<>` ดังนั้นจึงต้องตั้งค่ารูปแบบ `:Area/City` และกฎ เช่น `EST5EDT,M3.2.0,M11.1.0` ในเชลล์หรือใน `<DATA_DIR>/.env`

ชื่อต้องตรงกันทุกประการโดยใช้ตัวพิมพ์ใหญ่ บรรทัดอื่นๆ ค่าที่ไม่ผ่านการตรวจสอบ และชื่อที่ไม่ใช่ตัวอักษร ASCII ธรรมดา ตัวเลข และ `_` (เช่น บรรทัดที่มีไบต์ NUL หรือตัวอักษรที่เหมือนกัน) จะถูกข้ามไป CLI พิมพ์คำเตือนหนึ่งรายการที่ระบุชื่อคีย์ที่ไม่สามารถตั้งค่าได้ และอีกรายการหนึ่งที่อนุญาตให้ตั้งชื่อคีย์ที่ละเว้น โดยแต่ละรายการระบุสิ่งที่ต้องเปลี่ยนแปลง (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`) ไม่พิมพ์ค่าใดๆ เส้นทางของไฟล์ในข้อความเหล่านี้และรายงานเส้นทาง `.env` `omniroute doctor` จะถูกหลีกเมื่อมีอักขระควบคุมหรือ bidi ข้อจำกัดจะไม่มีผลเมื่อไดเร็กทอรีการทำงานเป็นไดเร็กทอรีข้อมูลหรือไดเร็กทอรีแพ็คเกจ

`PORT`, `API_PORT` และ `DASHBOARD_PORT` ไม่อยู่ในรายการ หากไม่มีฐาน URL จากแหล่งที่มาที่มีลำดับความสำคัญสูงกว่า CLI จะพูดคุยกับ `localhost:<PORT>` และอะไรก็ตามที่ฟังที่นั่นจะได้รับคีย์ API ของ CLI โทเค็นบริบทและโทเค็นของเครื่อง CLI (`x-omniroute-cli-token` ดู [CLI_TOKEN.md](../security/CLI_TOKEN.md) ) ซึ่งเซิร์ฟเวอร์ภายในเครื่องยอมรับสำหรับการโทรการจัดการจากลูปแบ็ค พอร์ตจากไดเร็กทอรีการทำงานจะอนุญาตให้ไฟล์นั้นเลือกตัวฟัง ดังนั้นให้ตั้งค่าพอร์ตในเชลล์ใน `<DATA_DIR>/.env` หรือด้วยตัวเลือก `--port` ของคำสั่งที่มีหนึ่ง (`serve`, `launch`, `run`)

parser ไม่มีไวยากรณ์ `export` บรรทัดเช่น `export LD_PRELOAD=...` ตั้งชื่อตัวแปร `export LD_PRELOAD`; จากไดเร็กทอรีการทำงานจะถูกข้ามไป และในไฟล์ `.env` อื่นๆ จะตั้งชื่อตามตัวอักษรนั้น ซึ่งไม่มีอะไรอ่านเลย

CLI จะจับคู่โทเค็นที่จัดเก็บของบริบท (โทเค็นการเข้าถึงหรือคีย์ API แบบเดิม) กับที่มาของบริบทนั้นเท่านั้น: แบบแผน โฮสต์ และพอร์ต เมื่อเปรียบเทียบกับ `URL.origin` สิ่งนี้ใช้กับคำขอที่ทำผ่านไคลเอนต์ HTTP ของ CLI(`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) และกับคำสั่ง `launch`, `launch codex`, `configure` และ `setup-*` ที่เขียน URL ฐานและคีย์ลงในการกำหนดค่าของเครื่องมืออื่น ชี้ไปที่เซิร์ฟเวอร์อื่นด้วย `--remote` พวกเขาใช้ `--api-key` หรือ `OMNIROUTE_API_KEY` ที่ชัดเจนหากมีการตั้งค่าไว้ และไม่มีโทเค็นบริบท การเปรียบเทียบนั้นแม่นยำ ดังนั้น `localhost` และ `127.0.0.1` หรือโฮสต์ที่มีและไม่มีจุดต่อท้าย จะถูกนับเป็นเซิร์ฟเวอร์ที่แตกต่างกัน และไม่มีโทเค็นบริบท URL ที่มีข้อมูลผู้ใช้ แบ็กสแลช หรือช่องว่างจะไม่ตรงกัน เนื่องจากตัวแยกวิเคราะห์ URL อื่นๆ (เช่น `urllib` และ `httpx` ของ Python) สามารถอ่านโฮสต์อื่นได้ สำหรับคำขอที่ CLI ส่งเอง การตรวจสอบนั้นจะครอบคลุมเฉพาะโครงร่างและสิทธิ์ ดังนั้น id ที่มีช่องว่างในเส้นทางหรือแบบสอบถามจะเก็บโทเค็นไว้
