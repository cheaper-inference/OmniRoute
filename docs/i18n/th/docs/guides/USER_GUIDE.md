## 🎯 กรณีการใช้งาน

### กรณีที่ 1: "ฉันมีการสมัครสมาชิก Claude Pro"

**ปัญหา:** โควตาหมดอายุโดยไม่ได้ใช้งาน และติดข้อจำกัดอัตราการใช้งานระหว่างเขียนโค้ดหนัก

```
ชุดผสม: "maximize-claude"
  1. cc/claude-opus-4-7        (ใช้สิทธิ์การสมัครสมาชิกอย่างเต็มที่)
  2. glm/glm-4.7               (ตัวสำรองราคาประหยัดเมื่อโควตาหมด)
  3. if/qwen3.8-max-preview       (ตัวสำรองฉุกเฉินฟรี)

ค่าใช้จ่ายรายเดือน: $20 (ค่าสมัครสมาชิก) + ~$5 (ตัวสำรอง) = รวม $25
เทียบกับ $20 + การติดข้อจำกัด = ความหงุดหงิด
```

### กรณีที่ 2: "ฉันไม่ต้องการเสียค่าใช้จ่ายเลย"

**ปัญหา:** ไม่สามารถจ่ายค่าสมัครสมาชิกได้ แต่ต้องการ AI สำหรับเขียนโค้ดที่เชื่อถือได้

```
ชุดผสม: "zero-cost"
  1. if/kimi-k2.7-code          (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)
  2. kr/qwen3-coder-next        (ตัวสำรอง Kiro ฟรี)

ค่าใช้จ่ายรายเดือน: $0
คุณภาพ: ตรวจสอบโมเดล ข้อจำกัด ความเป็นส่วนตัว และ SLA ให้เหมาะกับเวิร์กโหลดของคุณ
```

### กรณีที่ 3: "ฉันต้องการเขียนโค้ดได้ตลอด 24/7 โดยไม่สะดุด"

**ปัญหา:** มีเส้นตายและไม่สามารถยอมรับช่วงเวลาที่ระบบหยุดให้บริการได้

```
ชุดผสม: "always-on"
  1. cc/claude-opus-4-7        (คุณภาพดีที่สุด)
  2. cx/gpt-5.5                (การสมัครสมาชิกรายการที่สอง)
  3. glm/glm-4.7               (ราคาประหยัด รีเซ็ตทุกวัน)
  4. minimax/MiniMax-M2.1      (ถูกที่สุด รีเซ็ตทุก 5 ชม.)
  5. if/deepseek-v4-flash       (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)

ผลลัพธ์: ตัวสำรอง 5 ชั้นช่วยเพิ่มความยืดหยุ่น แต่ไม่รับประกันความพร้อมใช้งานของบริการต้นทาง
ค่าใช้จ่ายรายเดือน: $20-200 (ค่าสมัครสมาชิก) + $10-20 (ตัวสำรอง)
```

### กรณีที่ 4: "ฉันต้องการ AI ฟรีใน OpenClaw"

**ปัญหา:** ต้องการผู้ช่วย AI ในแอปรับส่งข้อความโดยไม่มีค่าใช้จ่ายใด ๆ

```
ชุดผสม: "openclaw-free"
  1. if/qwen3.8-max-preview     (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)
  2. if/deepseek-v4-flash       (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)
  3. if/kimi-k2.7-code          (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)

ค่าใช้จ่ายรายเดือน: $0
เข้าถึงผ่าน: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 การตั้งค่าผู้ให้บริการ

หากต้องการเพิ่มการเชื่อมต่อ API Key จำนวนมากจากไฟล์ CSV หรือ JSON ให้ใช้ **แดชบอร์ด → ผู้ให้บริการ → นำเข้าจากไฟล์** คอลัมน์จะเรียงตามตำแหน่ง (`provider,name,apiKey,baseUrl,priority`) โดย `provider` ต้องมีอยู่แล้วในฐานะผู้ให้บริการที่มีการจัดการหรือโหนดที่เข้ากันได้ ดู [นำเข้าผู้ให้บริการจากไฟล์ CSV หรือ JSON](../providers/CSV-IMPORT.md)

### 🔐 ผู้ให้บริการแบบสมัครสมาชิก

#### Claude Code (Pro/Max)

```bash
แดชบอร์ด → ผู้ให้บริการ → เชื่อมต่อ Claude Code
→ เข้าสู่ระบบด้วย OAuth → รีเฟรชโทเค็นอัตโนมัติ
→ ติดตามโควตาแบบ 5 ชั่วโมงและรายสัปดาห์

โมเดล:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**เคล็ดลับ:** ใช้ Opus สำหรับงานที่ซับซ้อน และ Sonnet เมื่อต้องการความเร็ว OmniRoute ติดตามโควตาแยกตามโมเดล!

CLI จะโหลด `.env` จาก `~/.omniroute/.env` หรือ `./.env` โดยอัตโนมัติ

### โหมดถาดระบบ

เริ่มต้น OmniRoute ในถาดระบบ:

```bash
omniroute serve --tray
```

คำสั่งจะสิ้นสุดการทำงานหลังจากเซิร์ฟเวอร์และถาดระบบพร้อมใช้งานแล้ว

เซิร์ฟเวอร์จะทำงานต่อไปโดยไม่ต้องเปิดเทอร์มินัลไว้

โหมดถาดระบบรองรับ macOS, Windows และเซสชัน Linux แบบกราฟิก โหมดถาดระบบจะไม่เปิดแดชบอร์ดโดยอัตโนมัติ

ใช้เมนูถาดระบบเพื่อดำเนินการต่อไปนี้:

- เปิดแดชบอร์ด
- เปิด `/dashboard/logs`
- เปลี่ยนการตั้งค่าเริ่มต้นอัตโนมัติ
- หยุด OmniRoute

อย่าใช้ `--tray` ร่วมกับตัวเลือกต่อไปนี้:

- `--daemon`
- `--log`
- `--no-recovery`

โหมดเหล่านี้ต้องใช้การเป็นเจ้าของโปรเซสที่แตกต่างกัน

เปิดใช้งานการเริ่มต้นระบบเมื่อเข้าสู่ระบบเครื่องครั้งถัดไป:

```bash
omniroute autostart enable
```

การเริ่มต้นอัตโนมัติจะใช้โหมดถาดระบบบน macOS, Windows และเซสชัน Linux แบบกราฟิก ส่วน Linux แบบไม่มีส่วนติดต่อกราฟิกจะใช้บริการผู้ใช้ systemd ที่มีอยู่

ปิดใช้งานการเริ่มต้นระบบเมื่อเข้าสู่ระบบ:

```bash
omniroute autostart disable
```

### การถอนการติดตั้ง

เมื่อคุณไม่ต้องการใช้ OmniRoute อีกต่อไป เรามีสคริปต์ด่วนสองรายการสำหรับการลบออกอย่างหมดจด:

| คำสั่ง                   | การดำเนินการ                                                             |

	cp -r .next/static .next/standalone/.next/static

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do

}

### โมเดลแบบกำหนดเอง

เพิ่ม model ID ใดก็ได้ให้กับ provider ใดก็ได้โดยไม่ต้องรอการอัปเดตแอป:

```bash
# ผ่าน API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# แสดงรายการ: curl http://localhost:20128/api/provider-models?provider=openai
# ลบ: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

หรือใช้ Dashboard: **Providers → [Provider] → Custom Models**

หมายเหตุ:

- OpenRouter และ provider ที่รองรับ OpenAI/Anthropic-compatible จะถูกจัดการจาก **Available Models** เท่านั้น การเพิ่มด้วยตนเอง การนำเข้า และการซิงก์อัตโนมัติทั้งหมดจะไปรวมอยู่ในรายการ available-model เดียวกัน ดังนั้นจึงไม่มีส่วน Custom Models แยกต่างหากสำหรับ provider เหล่านั้น
- ส่วน **Custom Models** มีไว้สำหรับ provider ที่ไม่ได้เปิดให้นำเข้า available-model แบบจัดการได้

### ผู้ให้บริการ OpenAI-Compatible แบบกำหนดเอง

เกตเวย์ใดก็ตามที่ใช้ OpenAI API (พร็อกซีที่โฮสต์เอง, vLLM หรือตัวรวมบริการจากภายนอก)
สามารถเพิ่มเป็นโหนด provider ของตัวเองได้:

1. **Providers → Add OpenAI Compatible**
2. **Name**: ป้ายชื่อที่ใช้แสดงผลของโหนด
3. **Prefix**: ชื่อสำหรับการกำหนดเส้นทาง ไคลเอนต์เรียกโมเดลในรูปแบบ `<prefix>/<model>` ดังนั้นโหนดที่มี
   prefix เป็น `mygw` จะให้บริการ `mygw/gpt-4o-mini` จำเป็นต้องระบุ และไม่มีข้อจำกัดด้านตัวอักษร
4. **API Type**: กลุ่มเอนด์พอยต์ที่เกตเวย์ให้บริการ (Chat Completions, Responses,
   Embeddings, audio, images)
5. **Base URL**: รูทของ API จนถึงและรวมถึง `/v1` (เช่น
   `https://gateway.example.com/v1`) ไม่ใช่พาธเต็ม `/chat/completions` เกตเวย์ที่มี
   พาธไม่เป็นไปตามมาตรฐานสามารถตั้งค่าได้ภายใต้ **Advanced Settings** (chat path, models path)
6. ฟิลด์ **API Key (for Check)** ใช้สำหรับทดสอบการเชื่อมต่อเท่านั้น หลังจากสร้างโหนดแล้ว
   ให้เปิดโหนดนั้นและใช้ **Add Connection** เพื่อจัดเก็บคีย์ที่คำขอจะใช้

โหนดจะได้รับ id ภายในในรูปแบบ `openai-compatible-<apiType>-<uuid>` คุณไม่จำเป็นต้อง
พิมพ์มันเอง prefix คือชื่อสาธารณะ

#### Prefix ที่สงวนไว้

Prefix ต้องไม่เป็น id หรือ alias ของ provider ในตัว (เช่น `openai`, `cf`) และต้องไม่เป็น
id ของ provider ที่ถูกปิดใช้งานแล้ว ตัวแก้เส้นทางโมเดล (model resolver) จะตรวจสอบ id และ alias ในตัวก่อน
โหนดที่กำหนดเอง ดังนั้นโหนดที่ใช้ prefix เหล่านั้นจะไม่ได้รับทราฟฟิกเลย:
`<prefix>/model` จะถูกส่งไปยัง provider ในตัวแทน หรือล้มเหลวแบบ fail-closed หาก provider นั้น
ถูกปิดใช้งานแล้ว การสร้างหรือแก้ไขโหนดที่มี prefix ดังกล่าวจะถูกปฏิเสธด้วยข้อความ:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

เลือก prefix ที่ไม่ซ้ำกัน (`mygw`, `acme-proxy`) หากคำขอไปยังโหนดที่กำหนดเองล้มเหลวพร้อม
ข้อผิดพลาดที่กล่าวถึง provider ในตัวหรือข้อมูลประจำตัวของมัน ให้ตรวจสอบว่า prefix ของโหนดนั้น
ถูกสงวนไว้หรือไม่: โหนดที่บันทึกไว้ก่อนที่กฎนี้จะมีอยู่ยังคงถูกเก็บไว้ แต่ prefix ของมันจะถูกส่งไปยัง
provider ในตัว ให้แก้ไขโหนดและตั้ง prefix ใหม่ให้กับมัน

#### ตัวเลือกเกตเวย์ต่อการเชื่อมต่อ

คีย์เหล่านี้อยู่ใน `providerSpecificData` ของการเชื่อมต่อ (เช่น ผ่าน
`PUT /api/providers/{id}`):

- `toolNameMaxLength` (จำนวนเต็ม, 1–1024) — สำหรับการเชื่อมต่อแบบ OpenAI chat-format compatible ที่

  การตอบกลับ

### การเชื่อมต่อ OmniRoute Peer แบบลูกโซ่

เกตเวย์ OmniRoute อีกตัวสามารถเพิ่มเป็น provider แบบ **Custom OpenAI-compatible** ได้ ใช้
base URL `/v1` ของ peer และ API key เฉพาะที่มีสิทธิ์ขั้นต่ำ (least-privilege) ซึ่งออกโดย peer นั้น

สำหรับลูกโซ่แบบสองทิศทางหรือหลาย hop ให้เปิดใช้งานตัวป้องกันลูปแบบ opt-in บนทุกเกตเวย์:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

เฉพาะคำขอที่ส่งไปยัง URL ของ peer ที่อยู่ใน allowlist อย่างชัดเจนเท่านั้นที่จะได้รับ
ส่วนหัว `X-OmniRoute-Peer-Trace` เกตเวย์จะปฏิเสธ instance ID ที่ซ้ำกันหรือจำนวน hop ที่ใช้
หมดแล้วด้วย HTTP `508 Loop Detected` โดย provider ต้นทางทั่วไปจะไม่ได้รับเมทาดาทาของ peer ใดๆ

การเชื่อมต่อ peer ไม่ใช่การทำสำเนาฐานข้อมูลหรือ host failover แต่ละเกตเวย์เก็บสถานะ SQLite
แคช ตัวนับอัตรา และเซสชันแยกกันอย่างอิสระ ใช้ reverse proxy ที่มีการตรวจสอบสุขภาพหรือ client
failover สำหรับความพร้อมใช้งานแบบ active/passive หรือ active/active และอย่าเมานต์ฐานข้อมูล SQLite
เดียวกันเข้ากับอินสแตนซ์ OmniRoute ที่กำลังทำงานหลายตัว

### Cloudflare Quick Tunnel

- ใช้งานได้ใน **Dashboard → Endpoints** สำหรับ Docker และการติดตั้งแบบ self-hosted อื่น ๆ
- สร้าง URL ชั่วคราว `https://*.trycloudflare.com` ที่ส่งต่อไปยัง endpoint `/v1` ที่เข้ากันได้กับ OpenAI ปัจจุบันของคุณ
- การเปิดใช้งานครั้งแรกจะติดตั้ง `cloudflared` เฉพาะเมื่อจำเป็นเท่านั้น การรีสตาร์ทครั้งต่อ ๆ ไปจะใช้ binary ที่ระบบจัดการให้ตัวเดิมซ้ำ
- Quick Tunnel จะไม่ถูกกู้คืนอัตโนมัติหลังจากรีสตาร์ท OmniRoute หรือ container โปรดเปิดใช้งานอีกครั้งจากแดชบอร์ดเมื่อต้องการ
- URL ของ tunnel เป็นแบบชั่วคราวและจะเปลี่ยนทุกครั้งที่คุณหยุด/เริ่ม tunnel
- Quick Tunnel แบบ managed ใช้ HTTP/2 transport เป็นค่าเริ่มต้นเพื่อหลีกเลี่ยงคำเตือน QUIC UDP buffer ที่รบกวนใน container ที่มีทรัพยากรจำกัด
- ตั้งค่า `CLOUDFLARED_PROTOCOL=quic` หรือ `auto` หากต้องการแทนที่การเลือก transport แบบ managed
- ตั้งค่า `CLOUDFLARED_BIN` หากต้องการใช้ binary `cloudflared` ที่ติดตั้งไว้ล่วงหน้าแทนการดาวน์โหลดแบบ managed
- สามารถแสดงหรือซ่อนแผง Cloudflare Quick Tunnel, Tailscale Funnel และ ngrok Tunnel ได้ใน **Settings → Appearance** การซ่อนแผงจะไม่หยุด tunnel ที่กำลังทำงานอยู่

### LLM Gateway Intelligence (เฟส 9)

- **Semantic Cache** — แคชการตอบกลับแบบ non-streaming ที่ temperature=0 โดยอัตโนมัติ (ข้ามได้ด้วย `X-OmniRoute-No-Cache: true`)
- **Request Idempotency** — กรองคำขอที่ซ้ำกันภายใน 5 วินาทีผ่าน header `Idempotency-Key` หรือ `X-Request-Id`
- **Progress Tracking** — เลือกรับอีเวนต์ SSE `event: progress` ผ่าน header `X-OmniRoute-Progress: true`

### กลยุทธ์การกำหนดเส้นทาง

กำหนดค่าผ่าน **Dashboard → Settings → Routing** แดชบอร์ดจะแสดงกลยุทธ์หกแบบที่ใช้บ่อยที่สุด ส่วนคอมโบและ auto-router รองรับชุดกลยุทธ์ที่กว้างกว่าภายใน

**กลยุทธ์ที่มองเห็นในแดชบอร์ด (การกำหนดเส้นทางระดับบัญชี):**

| กลยุทธ์                        | คำอธิบาย                                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------------------- |
| **Fill First**                 | ใช้บัญชีตามลำดับความสำคัญ — บัญชีหลักจัดการคำขอทั้งหมดจนกว่าจะไม่พร้อมใช้งาน                |
| **Round Robin**                | วนใช้บัญชีทั้งหมดโดยมีขีดจำกัด sticky ที่กำหนดค่าได้ (ค่าเริ่มต้น: 3 ครั้งต่อบัญชี)         |
| **P2C (Power of Two Choices)** | สุ่มเลือก 2 บัญชีแล้วส่งไปยังบัญชีที่มีสถานะดีกว่า — กระจายโหลดโดยคำนึงถึงสถานะความพร้อม    |
| **Random**                     | สุ่มเลือกบัญชีสำหรับแต่ละคำขอด้วยการสับแบบ Fisher-Yates                                     |
| **Least Used**                 | ส่งไปยังบัญชีที่มี timestamp `lastUsedAt` เก่าที่สุด เพื่อกระจายทราฟฟิกอย่างเท่าเทียม       |
| **Cost Optimized**             | ส่งไปยังบัญชีที่มีค่า priority ต่ำที่สุด เพื่อปรับให้เหมาะกับผู้ให้บริการที่ต้นทุนต่ำที่สุด |

**กลยุทธ์ขั้นสูงสำหรับคอมโบและ auto** (กำหนดค่าได้ต่อคอมโบหรือผ่าน prefix `auto/*` — ดู [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — ลำดับแบบเข้มงวด ไม่มีการ round-robin
- `weighted` — แบ่งทราฟฟิกตามสัดส่วนจากน้ำหนักของแต่ละโมเดล
- `fill-first` — ใช้โมเดลแรกจนสุดขีดจำกัด
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` และ `cost-optimized`
- `auto` — ขับเคลื่อนด้วยคะแนนจากตัวเลือกทั้งหมด
- `lkgp` (Last Known Good Provider) — ปักหมุดกับผู้ให้บริการที่สำเร็จล่าสุด จากนั้น fallback ตามกฎ
- `context-optimized` — เลือกโมเดลที่มี context window ว่างมากที่สุด
- `context-relay` — ต่อโมเดลที่รองรับ context ยาวเข้าด้วยกันสำหรับเทิร์นต่อเนื่อง

#### Header Sticky Session จากภายนอก

สำหรับ session affinity จากภายนอก (เช่น เอเจนต์ Claude Code/Codex ที่อยู่หลัง reverse proxy) ให้ส่ง:

```http
X-Session-Id: your-session-key
```

OmniRoute ยังรับ `x_session_id` และคืนค่า session key ที่ใช้จริงใน `X-OmniRoute-Session-Id`

หากคุณใช้ Nginx และส่ง header แบบมีขีดล่าง ให้เปิดใช้งาน:

```nginx
underscores_in_headers on;
```

#### นามแฝงโมเดลแบบ Wildcard

สร้างรูปแบบ wildcard เพื่อแมปชื่อโมเดลใหม่:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

Wildcard รองรับ `*` (อักขระใดก็ได้) และ `?` (อักขระตัวเดียว)

#### ห่วงโซ่ Fallback

กำหนดห่วงโซ่ fallback แบบโกลบอลที่ใช้กับคำขอทั้งหมด:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### ความทนทานและ Circuit Breaker

กำหนดค่าผ่าน **Dashboard → Settings → Resilience**

OmniRoute ใช้กลไกความทนทานระดับ provider ด้วยองค์ประกอบห้าส่วน:

1. **Request Queue & Pacing** — การจัดรูปแบบคำขอระดับระบบ:
   - **Requests Per Minute (RPM)** — จำนวนคำขอสูงสุดต่อนาทีต่อบัญชี
   - **Min Time Between Requests** — ช่วงห่างขั้นต่ำระหว่างคำขอ (หน่วยเป็นมิลลิวินาที)
   - **Max Concurrent Requests** — จำนวนคำขอพร้อมกันสูงสุดต่อบัญชี

2. **Connection Cooldown** — การกำหนดค่าตามประเภทการยืนยันตัวตนสำหรับการเชื่อมต่อเดียว หลังจากเกิดความล้มเหลวที่ลองใหม่ได้:
   - **Base Cooldown** — ช่วงเวลาพักเริ่มต้นสำหรับความล้มเหลวจาก upstream ที่ลองใหม่ได้
   - **Use Upstream Retry Hints** — เคารพคำแนะนำ `Retry-After` หรือ reset hint ที่เชื่อถือได้เมื่อมีการส่งมาให้
   - **Max Backoff Steps** — ระดับ exponential backoff สูงสุดสำหรับความล้มเหลวที่เกิดซ้ำ ๆ

3. **Provider Circuit Breaker** — ติดตามความล้มเหลวของ provider แบบ end-to-end ทำเครื่องหมาย provider ว่า degraded เมื่อถึงเกณฑ์เตือนที่กำหนด และเปิด breaker เมื่อถึงเกณฑ์ความล้มเหลวที่กำหนด:
   - **Degradation Threshold** — จำนวนความล้มเหลวติดต่อกันของ provider ก่อนเข้าสู่สถานะ `DEGRADED`
   - **Failure Threshold** — จำนวนความล้มเหลวติดต่อกันของ provider ก่อนเข้าสู่สถานะ `OPEN`
   - **Reset Timeout** — ช่วงเวลาก่อนที่ provider จะถูกทดสอบอีกครั้ง
   - **CLOSED** (ปกติ) — คำขอไหลผ่านตามปกติ
   - **DEGRADED** — คำขอยังคงไหลผ่าน ขณะที่ระบบติดตามความล้มเหลวที่เพิ่มขึ้น
   - **OPEN** — provider ถูกบล็อกชั่วคราวหลังจากเกิดความล้มเหลวซ้ำ ๆ
   - **HALF_OPEN** — กำลังทดสอบว่า provider กลับมาใช้งานได้แล้วหรือไม่

   การจำกัดอัตรา `429` ที่ผูกกับการเชื่อมต่อจะอยู่ใน **Connection Cooldown** และไม่ถูกนับรวมใน provider breaker

   สถานะรันไทม์ของ provider breaker จะแสดงที่ **Dashboard → Health** เท่านั้น

4. **Wait For Cooldown** — หากการเชื่อมต่อที่เป็นไปได้ทุกรายการอยู่ในช่วง cooldown หมดแล้ว OmniRoute สามารถรอ cooldown ที่จะสิ้นสุดเร็วที่สุด แล้วลองคำขอของไคลเอนต์เดิมซ้ำโดยอัตโนมัติ

5. **Rate Limit Auto-Detection** — เมื่อ provider ต้นทางส่งช่วงเวลารอที่ชัดเจนกลับมา คำแนะนำเหล่านั้นจะแทนที่ connection cooldown ในเครื่อง เมื่อเปิดใช้งานการตั้งค่านี้

**เคล็ดลับ:** ใช้หน้า **Health** เพื่อตรวจสอบและรีเซ็ต provider breaker ที่กำลังทำงานอยู่หลังจากเกิด outage ส่วนหน้า Resilience ใช้สำหรับเปลี่ยนการกำหนดค่าเท่านั้น

### การส่งออก / นำเข้าฐานข้อมูล

จัดการการสำรองฐานข้อมูลได้ที่ **Dashboard → Settings → System & Storage**

| การกระทำ                 | คำอธิบาย                                                                                                                                              |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Export Database**      | ดาวน์โหลดฐานข้อมูล SQLite ปัจจุบันเป็นไฟล์ `.sqlite`                                                                                                  |
| **Export All (.tar.gz)** | ดาวน์โหลดไฟล์สำรองแบบเต็ม ซึ่งประกอบด้วย: ฐานข้อมูล การตั้งค่า combo การเชื่อมต่อ provider (ไม่รวมข้อมูลรับรอง) และเมทาดาทาของ API key                |
| **Import Database**      | อัปโหลดไฟล์ `.sqlite` เพื่อแทนที่ฐานข้อมูลปัจจุบัน ระบบจะสร้างการสำรองข้อมูลก่อนนำเข้าโดยอัตโนมัติ เว้นแต่จะตั้งค่า `DISABLE_SQLITE_AUTO_BACKUP=true` |

```bash
# API: ส่งออกฐานข้อมูล
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: ส่งออกทั้งหมด (ไฟล์เก็บถาวรแบบเต็ม)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: นำเข้าฐานข้อมูล
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**การตรวจสอบการนำเข้า:** ไฟล์ที่นำเข้าจะถูกตรวจสอบความสมบูรณ์ (SQLite pragma check) ตารางที่จำเป็น (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) และขนาด (สูงสุด 100MB)

**กรณีการใช้งาน:**

- ย้าย OmniRoute ระหว่างเครื่อง
- สร้างการสำรองข้อมูลภายนอกเพื่อการกู้คืนจากภัยพิบัติ
- แชร์การกำหนดค่าระหว่างสมาชิกในทีม (ส่งออกทั้งหมด → แชร์ไฟล์เก็บถาวร)

### แดชบอร์ดการตั้งค่า

หน้าการตั้งค่าถูกจัดเป็น **7 แท็บ** เพื่อให้นำทางได้ง่าย:

| แท็บ                          | เนื้อหา                                                                                                                                                                                      |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **General (ทั่วไป)**          | เครื่องมือจัดการพื้นที่จัดเก็บของระบบ พฤติกรรมเริ่มต้น และการมองเห็นทันเนลของ Endpoint                                                                                                       |
| **Appearance (รูปลักษณ์)**    | ตัวควบคุมธีม (สว่าง/มืด/ตามระบบ) การแสดงแถบด้านข้าง และตัวสลับแผงสำหรับการ์ดทันเนล Cloudflare/Tailscale/ngrok                                                                                |
| **AI**                        | Thinking budget (passthrough / auto-strip / custom / adaptive — ดู [THINKING_BUDGET.md](./THINKING_BUDGET.md)) system prompt ส่วนกลาง และสถิติแคชพรอมป์                                      |
| **Security (ความปลอดภัย)**    | การตั้งค่าการเข้าสู่ระบบ/รหัสผ่าน การควบคุมการเข้าถึงด้วย IP (IP Access Control) การยืนยันตัวตน API สำหรับ `/models` การบล็อกผู้ให้บริการ (Provider Blocking) และการป้องกัน prompt injection |
| **Routing (การกำหนดเส้นทาง)** | กลยุทธ์การกำหนดเส้นทางส่วนกลาง (Fill First / Round Robin / P2C / Random / Least Used / Cost Optimized) นามแฝงโมเดลแบบ wildcard ห่วงโซ่ fallback และค่าเริ่มต้นของ combo                      |
| **Resilience (ความคงทน)**     | คิวคำขอ การคูลดาวน์การเชื่อมต่อ การกำหนดค่า breaker ของผู้ให้บริการ และพฤติกรรมการรอคูลดาวน์ (wait-for-cooldown)                                                                             |
| **Advanced (ขั้นสูง)**        | การกำหนดค่าพร็อกซีส่วนกลาง (HTTP/SOCKS5) และการกำหนดพร็อกซีแยกตามผู้ให้บริการแต่ละราย                                                                                                        |

แท็บ General ไม่แสดงหมายเหตุแบบอ่านอย่างเดียวเกี่ยวกับการบันทึกล็อกและแคชซ้ำอีกต่อไป การตั้งค่าการเก็บรักษาและ
การเพิ่มประสิทธิภาพฐานข้อมูลจะถูกบันทึกผ่าน `/api/settings/database` ส่วนการล้างแคชด้วยตนเองจะใช้
`DELETE /api/cache` และการจำกัดจำนวนแถวของล็อกคำขอและล็อกพร็อกซีจะควบคุมโดย
`CALL_LOGS_TABLE_MAX_ROWS` และ `PROXY_LOGS_TABLE_MAX_ROWS`

### กลยุทธ์การกระจายโหลดของ Combo

กำหนดค่าการกระจายโหลดสำหรับ combo แต่ละตัวได้ที่ **Dashboard → Combos → Create/Edit → Strategy**

| กลยุทธ์            | คำอธิบาย                                                                    |
| ------------------ | --------------------------------------------------------------------------- |
| **Round-Robin**    | หมุนเวียนใช้โมเดลตามลำดับ                                                   |
| **Priority**       | ลองใช้โมเดลแรกเสมอ จะสลับไปใช้ตัวสำรองเมื่อเกิดข้อผิดพลาดเท่านั้น           |
| **Random**         | สุ่มเลือกโมเดลจาก combo สำหรับแต่ละคำขอ                                     |
| **Weighted**       | กำหนดเส้นทางตามสัดส่วนของน้ำหนักที่กำหนดให้แต่ละโมเดล                       |
| **Least-Used**     | กำหนดเส้นทางไปยังโมเดลที่มีจำนวนคำขอล่าสุดน้อยที่สุด (ใช้เมทริกซ์ของ combo) |
| **Cost-Optimized** | กำหนดเส้นทางไปยังโมเดลที่ถูกที่สุดที่พร้อมใช้งาน (ใช้ตารางราคา)             |

สามารถตั้งค่าเริ่มต้นของ combo แบบส่วนกลางได้ที่ **Dashboard → Settings → Routing → Combo Defaults**
โดยค่าเริ่มต้น การหมดเวลา (timeout) ของเป้าหมายใน combo จะสืบทอดจากการหมดเวลาของคำขอปัจจุบัน ใช้ **Target timeout
(seconds)** ที่ค่าเริ่มต้นของ combo หรือที่ combo แต่ละตัว เฉพาะเมื่อต้องการให้ขีดจำกัดต่อเป้าหมายที่สั้นกว่า
ไปกระตุ้นการสลับไปใช้ตัวสำรอง (fallback) ให้เร็วขึ้น

การเพิ่มประสิทธิภาพแบบ zero-latency ของ combo เป็นแบบ opt-in (ต้องเปิดใช้งานเอง) ปล่อยให้ **Zero-latency optimizations** ถูกปิดไว้
เพื่อป้องกันไม่ให้ฟีเจอร์ด้านความหน่วงเหล่านี้แข่งขัน (race) กับเป้าหมายสำรอง ข้ามเป้าหมายตามประวัติ TTFT
หรือบีบอัดคำขอสำรอง การเปิดใช้งานจะอนุญาตให้ใช้ hedging ที่กำหนดค่าไว้ การข้ามเป้าหมายแบบคาดการณ์จาก TTFT
และการบีบอัดคำขอสำรองเชิงรุก เพื่อแลกความเที่ยงตรงของการกำหนดเส้นทาง/คำขอกับความหน่วงช่วงท้าย (tail latency) ที่ต่ำลง

ปิดใช้งาน **บัฟเฟอร์โทเค็นสำหรับการให้เหตุผล** เมื่อผู้ให้บริการ upstream กำหนดขีดจำกัด
`max_tokens` / `maxOutputTokens` แบบเคร่งครัด เมื่อเปิดใช้งาน การเราต์แบบคอมโบจะเพิ่ม headroom ของโมเดลการให้เหตุผล
เฉพาะกับโมเดลที่ทราบขีดจำกัดเอาต์พุตเท่านั้น และจะคงขีดจำกัดโทเค็นของไคลเอนต์ไว้เท่าเดิมเมื่อ
ค่าที่เผื่อบัฟเฟอร์อย่างปลอดภัยจะเกินขีดจำกัดดังกล่าว หากขีดจำกัดของไคลเอนต์สูงกว่าขีดจำกัดที่ทราบอยู่แล้ว
OmniRoute จะบีบค่าลงให้เท่ากับขีดจำกัดนั้นก่อนส่งคำขอไปยัง upstream

### แดชบอร์ดสุขภาพระบบ

เข้าถึงผ่าน **แดชบอร์ด → สุขภาพระบบ** ภาพรวมสุขภาพของระบบแบบเรียลไทม์พร้อมการ์ด 6 ใบ:

| การ์ด                         | สิ่งที่แสดง                                                           |
| ----------------------------- | --------------------------------------------------------------------- |
| **สถานะระบบ**                 | ระยะเวลาที่ระบบทำงาน, เวอร์ชัน, การใช้งานหน่วยความจำ, ไดเรกทอรีข้อมูล |
| **สุขภาพของผู้ให้บริการ**     | สถานะรันไทม์ของเซอร์กิตเบรกเกอร์ผู้ให้บริการแบบโกลบอล                 |
| **ขีดจำกัดอัตราการเรียกใช้**  | ช่วงคูลดาวน์การเชื่อมต่อที่ยังใช้งานอยู่ต่อบัญชี พร้อมเวลาที่เหลือ    |
| **การล็อกเอาต์ที่ใช้งานอยู่** | การล็อกเอาต์ที่ใช้งานอยู่ในระดับโมเดลและการยกเว้นชั่วคราว             |
| **แคชลายเซ็น**                | สถิติแคชสำหรับตัดข้อมูลซ้ำ (คีย์ที่ใช้งานอยู่, อัตราการเข้าถึงแคช)    |
| **เทเลเมทรีความหน่วง**        | การรวบรวมค่าความหน่วง p50/p95/p99 ต่อผู้ให้บริการ                     |

**เคล็ดลับ:** หน้าสุขภาพระบบจะรีเฟรชอัตโนมัติทุก 10 วินาที ใช้การ์ดเซอร์กิตเบรกเกอร์เพื่อระบุว่าผู้ให้บริการรายใดกำลังประสบปัญหา

## 🤖 การกำหนดเส้นทางอัตโนมัติ (ไม่ต้องตั้งค่า)

OmniRoute มาพร้อมกับ **เราเตอร์อัตโนมัติที่ขับเคลื่อนด้วยคะแนน** ซึ่งเลือกโมเดลที่ดีที่สุดสำหรับแต่ละคำขอจากผู้ให้บริการที่เชื่อมต่อทั้งหมด โดยไม่ต้องดูแลคอมโบใดๆ เพียงส่งคำขอโดยใช้คำนำหน้า `auto/*` รายการใดรายการหนึ่ง แล้ว OmniRoute จะประกอบคอมโบเสมือนขึ้นทันที พร้อมให้คะแนนตัวเลือกโดยพิจารณาจากเวลาแฝง ต้นทุน อัตราความสำเร็จ ความเหมาะสมกับบริบท ความเหมาะสมของโมเดลต่องาน ความล้มเหลวล่าสุด โควตา และสถานะของเซอร์กิตเบรกเกอร์

| คำนำหน้า       | ปรับให้เหมาะสมสำหรับ                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| `auto`         | ค่าเริ่มต้นแบบสมดุล (เวลาแฝง × ต้นทุน × อัตราความสำเร็จ)                                                   |
| `auto/coding`  | งานเขียนโค้ด: ให้ความสำคัญกับ Claude, GPT-5, GLM, Kimi, Qwen Coder และโมเดลเขียนโค้ดของ DeepSeek           |
| `auto/cheap`   | ราคาต่อโทเค็นต่ำที่สุด โดยยอมรับเวลาแฝงที่สูงขึ้น                                                          |
| `auto/fast`    | เวลาแฝงต่ำที่สุด โดยไม่คำนึงถึงต้นทุน                                                                      |
| `auto/offline` | ผู้ให้บริการภายในเครื่องเท่านั้น (Ollama, vLLM, llama.cpp) — มีประโยชน์สำหรับระบบที่ตัดขาดจากเครือข่าย     |
| `auto/smart`   | ให้ความสำคัญกับคุณภาพการให้เหตุผลเป็นอันดับแรก (Opus, GPT-5 xhigh, R1, การให้เหตุผลของ GLM 5.1)            |
| `auto/lkgp`    | "ผู้ให้บริการล่าสุดที่ใช้งานได้" — ตรึงไว้กับผู้ให้บริการรายล่าสุดที่ทำงานสำเร็จ จากนั้นจึงย้อนกลับไปใช้กฎ |

ตัวอย่าง:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "ปรับโครงสร้างฟังก์ชัน Python นี้" }],
    "stream": true
  }'
```

เราเตอร์อัตโนมัติมีคำอธิบายฉบับสมบูรณ์อยู่ใน [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ซึ่งรวมถึงวิธีปรับแต่งค่าน้ำหนักการให้คะแนน ขึ้นบัญชีดำผู้ให้บริการ และตรวจสอบการตัดสินใจกำหนดเส้นทางใน **แดชบอร์ด → คอมโบอัตโนมัติ**

## 🔌 การผสานรวม MCP และ A2A

OmniRoute เป็นทั้ง **เซิร์ฟเวอร์ MCP** (Model Context Protocol) และ **เซิร์ฟเวอร์ A2A** (Agent-to-Agent JSON-RPC 2.0) IDE หรือโฮสต์เอเจนต์ใดๆ ที่รองรับ MCP สามารถเรียกใช้เครื่องมือของ OmniRoute ได้โดยตรง โดยไม่ต้องมีแรปเปอร์เพิ่มเติม

### การรับส่งข้อมูลของ MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP แบบสตรีมได้**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (สำหรับปลั๊กอิน IDE ที่ต้องการใช้ stdio)

### เชื่อมต่อ Claude Desktop

แก้ไข `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) หรือไฟล์ที่เทียบเท่ากันบน Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### เชื่อมต่อ Cursor / Continue / VS Code MCP

ใช้ URL ของ SSE `http://localhost:20128/api/mcp/sse` และคีย์ Bearer API ที่สร้างใน **แดชบอร์ด → คีย์ API**

### ขอบเขตสิทธิ์

ปัจจุบัน MCP กำหนดขอบเขตสิทธิ์ที่มีชื่อไว้ 32 รายการ โดยคีย์ Bearer แต่ละคีย์สามารถจำกัดให้ใช้เฉพาะขอบเขตสิทธิ์ที่กำหนดได้ — ดูรายการขอบเขตสิทธิ์และเครื่องมือที่เป็นแหล่งอ้างอิงหลักได้ใน [MCP-SERVER.md](../frameworks/MCP-SERVER.md) และดูสคีมา JSON-RPC ได้ใน [A2A-SERVER.md](../frameworks/A2A-SERVER.md)

## 🧠 ระบบทักษะ

OmniRoute มี **เฟรมเวิร์กทักษะ** ที่ขยายความสามารถได้ (`src/lib/skills/`) เพื่อให้เอเจนต์และปลายทาง A2A สามารถเรียกใช้รูทีนเฉพาะด้านได้ (เช่น `code-review`, `summarize`, `extract-facts`, `web-research`)

- **UI มาร์เก็ตเพลส** — เรียกดูและติดตั้งทักษะจาก **แดชบอร์ด → ทักษะ**
- **ขอบเขตต่อคีย์** — จำกัดว่า API key ใดสามารถเรียกใช้ทักษะใดได้บ้าง
- **ทักษะแบบกำหนดเอง** — วางไฟล์ TypeScript ใน `src/lib/a2a/skills/` ลงทะเบียนไฟล์ดังกล่าว แล้วทักษะนั้นจะพร้อมให้เรียกใช้ผ่าน A2A ได้ทันที

เอกสารอ้างอิงฉบับเต็ม: [SKILLS.md](../frameworks/SKILLS.md)

## 💾 ระบบหน่วยความจำ

OmniRoute จัดเก็บ **หน่วยความจำการสนทนาระยะยาว** พร้อมการค้นคืนแบบไฮบริด:

- **SQLite FTS5** สำหรับค้นหาด้วยคีย์เวิร์ดจากบทสนทนาที่ผ่านมา
- **ที่เก็บเวกเตอร์ Qdrant** (ไม่บังคับ) สำหรับเรียกคืนข้อมูลตามความหมาย
- **การสกัดข้อเท็จจริงอัตโนมัติ** — เอนทิตี ความชอบ และการตัดสินใจจะถูกสรุปหลังจากแต่ละเซสชันและจัดเก็บไว้ในตาราง `memory_facts`
- หน่วยความจำจะถูกแยกขอบเขตตาม API key และตามเซสชัน

จัดการหน่วยความจำได้ใน **แดชบอร์ด → หน่วยความจำ** (ค้นหา แก้ไข ส่งออก ล้างข้อมูล) อินเทอร์เฟซ HTTP (`/api/memory/*`) ช่วยให้เอเจนต์ส่งและค้นหาข้อเท็จจริงผ่านโปรแกรมได้ — ดู [MEMORY.md](../frameworks/MEMORY.md)

## 🔔 Webhook

สมัครรับเหตุการณ์จาก OmniRoute เพื่อการตรวจสอบและระบบอัตโนมัติแบบเรียลไทม์

- สร้าง webhook ใน **แดชบอร์ด → Webhook** พร้อม URL ปลายทางและข้อมูลลับสำหรับการลงนาม HMAC
- เหตุการณ์ที่พร้อมใช้งาน: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- ทุกเพย์โหลดมี `X-OmniRoute-Signature` (HMAC-SHA256) สำหรับการตรวจสอบความถูกต้อง
- การลองใหม่: 3 ครั้งโดยเพิ่มระยะเวลารอแบบทวีคูณ จากนั้นส่งไปยังคิวข้อความที่ไม่สามารถประมวลผลได้

สคีมาฉบับเต็มอยู่ใน [WEBHOOKS.md](../frameworks/WEBHOOKS.md)

## 🛠️ การจัดการผ่านโปรแกรม

คุณสามารถจัดการทรัพยากรทั้งหมดของ OmniRoute (ผู้ให้บริการ คอมโบ คีย์ และการตั้งค่า) ผ่าน HTTP โดยใช้ **Bearer key ที่มีขอบเขต `manage`**

สร้างคีย์ใน **แดชบอร์ด → API Key → คีย์ใหม่ → ขอบเขต: manage** จากนั้น:

```bash
# แสดงรายการผู้ให้บริการ
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# เพิ่มการเชื่อมต่อผู้ให้บริการ
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# สร้างคอมโบ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# แสดงรายการ/สร้าง API key
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

ดูแค็ตตาล็อกปลายทางและสคีมาคำขอ/การตอบกลับทั้งหมดได้ใน [API_REFERENCE.md](../reference/API_REFERENCE.md)

## 💻 CLI ภายใน

OmniRoute มาพร้อม CLI ภายใน (`omniroute …`) สำหรับการตั้งค่า การวินิจฉัย และการควบคุมขณะรันไทม์ ซึ่ง **แยกจากหน้า "CLI Tools" ในแดชบอร์ด** ที่ใช้กำหนดค่า CLI ของบุคคลที่สาม (Claude Code, Cursor, Codex, Cline, …) เพื่อให้สามารถสื่อสารกับ OmniRoute ได้

```bash
omniroute setup                    # วิซาร์ดแบบโต้ตอบ (รหัสผ่าน ผู้ให้บริการ คอมโบ)
omniroute setup --non-interactive  # เหมาะสำหรับ CI
omniroute doctor                   # การวินิจฉัยสถานะ (ไดเรกทอรีข้อมูล, DB, ผู้ให้บริการ, พอร์ต)
omniroute providers available      # แสดงรายการผู้ให้บริการที่รองรับ
omniroute providers list           # แสดงรายการการเชื่อมต่อที่กำหนดค่าไว้
omniroute providers test <id>      # ทดสอบการเชื่อมต่อผู้ให้บริการแบบสด
omniroute combos list              # แสดงรายการคอมโบ
omniroute combos switch <name>     # ตั้งค่าคอมโบเริ่มต้น
omniroute models                   # แสดงรายการโมเดลที่พร้อมใช้งาน (--json, --search)
omniroute keys add | list | remove # จัดการคีย์ API จากเทอร์มินัล
omniroute backup                   # สร้างสแนปช็อตการกำหนดค่า + DB
omniroute restore [<timestamp>]    # กู้คืนจากสแนปช็อต
omniroute health                   # สถานะโดยละเอียด (เบรกเกอร์, แคช, หน่วยความจำ)
omniroute quota                    # การใช้โควตาของผู้ให้บริการ
omniroute mcp status               # สถานะเซิร์ฟเวอร์ MCP
omniroute a2a status               # สถานะเซิร์ฟเวอร์ A2A
omniroute tunnel list|create|stop  # ทันเนล Cloudflare/Tailscale/ngrok
omniroute reset-password           # รีเซ็ตรหัสผ่านผู้ดูแลระบบ
omniroute --mcp                    # เริ่มเซิร์ฟเวอร์ MCP ผ่าน stdio
omniroute --port 3000              # เริ่มเซิร์ฟเวอร์บนพอร์ตที่กำหนดเอง
```

เคล็ดลับ: ใช้ `omniroute doctor --json` ร่วมกับเครื่องมือตรวจสอบของคุณเพื่อแจ้งเตือนเมื่อการเชื่อมต่อผู้ให้บริการมีปัญหา

## 🖥️ แอปพลิเคชันเดสก์ท็อป (Electron)

npm run dev

npm start

cd electron
