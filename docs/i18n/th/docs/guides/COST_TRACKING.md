OmniRoute ประเมิน บันทึก และรายงานค่าใช้จ่ายของทุกคำขออย่างไร — และเหตุใดตัวเลขบน
แดชบอร์ดจึงเป็น **ตัวติดตามการประหยัด** ไม่ใช่ใบเรียกเก็บเงิน

ดูเพิ่มเติม: [คู่มือผู้ใช้](./USER_GUIDE.md) · [แกลเลอรีฟีเจอร์](./FEATURES.md)

## สิ่งนี้คืออะไร (และไม่ใช่อะไร)

OmniRoute ระบุค่าใช้จ่ายเป็น USD ต่อคำขอให้กับทุก completion โดยนำจำนวนโทเค็น
มาคูณกับอัตราราคาของโมเดล ตัวเลขเหล่านี้ใช้ขับเคลื่อนแดชบอร์ด **ค่าใช้จ่าย**
CLI `omniroute cost` / `omniroute usage` การส่งออก CSV/JSON และงบประมาณต่อ API key

> **"ค่าใช้จ่าย" บนแดชบอร์ดคือตัวติดตามการประหยัด ไม่ใช่ใบเรียกเก็บเงิน** OmniRoute ไม่เคยเรียกเก็บเงินจากคุณ
> — แต่จะกำหนดเส้นทางคำขอของคุณไปยังผู้ให้บริการที่คุณเชื่อมต่อไว้แล้ว (การสมัครใช้งาน
> แพ็กเกจฟรี และ API key ของคุณเอง) หากมี "ค่าใช้จ่ายรวม $290" ที่เกิดจากโมเดลฟรีทั้งหมด
> นั่นหมายความว่าโดยประมาณคุณ **ไม่ได้จ่ายเงิน $290** ให้กับ API แบบชำระเงิน ตัวเลขดังกล่าวเป็น
> _ค่าประมาณ_ ว่าทราฟฟิกเดียวกันนี้จะมีค่าใช้จ่ายเท่าใดตามราคามาตรฐาน เพื่อให้คุณเห็นว่า
> การใช้งานของคุณกระจุกตัวอยู่ที่ใด และการกำหนดเส้นทางไปยังผู้ให้บริการที่ราคาถูกกว่า/ฟรีช่วยประหยัดเงินให้คุณได้มากเพียงใด

กรอบแนวคิดนี้ระบุไว้อย่างชัดเจนใน [README](../../README.md) ของโปรเจกต์ ("'ค่าใช้จ่าย'
บนแดชบอร์ดคือตัวติดตามการประหยัด ไม่ใช่ใบเรียกเก็บเงิน")

เนื่องจากตัวเลขนี้เป็นค่าประมาณ:

- ตัวเลขจะขึ้นอยู่กับตารางราคาที่ OmniRoute มีสำหรับแต่ละโมเดล โมเดลที่ไม่มีรายการราคา
  จะมีค่าใช้จ่าย `0` (แสดงเป็นแถว "รุ่นเก่า / ฟรี" ในเครื่องมือสำรวจ)
- ทราฟฟิกจากแพ็กเกจฟรีและการสมัครใช้งานยังคงสะสมค่าใช้จ่าย _โดยประมาณ_ — ซึ่งก็คือ
  จำนวนเงินที่คุณประหยัดได้ ไม่ใช่จำนวนเงินที่ต้องชำระ

## มีการประมาณต้นทุนอย่างไร

### แหล่งที่มาของราคา

ต้นทุนมาจากตารางราคาที่รวมใน [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) โดยเรียงลำดับความสำคัญนี้ (** สูงสุดก่อน** ):

1. **การแทนที่ผู้ใช้** ราคา — ที่ตั้งไว้ในแดชบอร์ดหรือผ่าน `PATCH /api/pricing` (เนมสเป `pricing` )
2. **การซิงค์ models.dev** ราคา — ดึงมาจาก `https://models.dev/api.json` (เนมสเป `models_dev_pricing` )
3. **การซิงค์LiteLLM** ราคา — ดึงมาจากสาธารณะของ LiteLLM `model_prices_and_context_window.json` (เนมสเป `pricing_synced` )
4. **ค่าเริ่มต้นแบบฮาร์ดโค้ด** อัตรา — จัดส่งเป็น [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/)

สำหรับ provider/model เดียวกัน ค่าจากเลเยอร์ที่มีลำดับความสำคัญสูงกว่าจะเขียนทับฟิลด์ที่ตรงกันในเลเยอร์ที่ต่ำกว่า ฟิลด์ที่ขาดหายไปจากชั้นบนยังสามารถมาจากชั้นล่างได้ ลำดับจะได้รับการแก้ไขแม้ว่างานซิงค์อิสระทั้งสองจะทำงานพร้อมกันก็ตาม `GET /api/pricing?includeSources=1` ส่งคืน `pricing` และ `sourceMap` ซึ่งมีป้ายกำกับต่อรุ่น (`user`, `modelsDev`, `litellm`, `default`) ระบุเลเยอร์ที่มีลำดับความสำคัญสูงสุดที่มีโมเดลนั้น

**การซิงค์LiteLLM** เป็นแบบเลือกใช้ ปิดใช้งานตามค่าเริ่มต้น ตัวแปรสภาพแวดล้อม (ดู [`.env.example`](../../.env.example) ) คือ:

| สภาพแวดล้อมที่หลากหลาย  | ค่าเริ่มต้น | วัตถุประสงค์                                                                       |
| ----------------------- | ----------- | ---------------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`     | เปิดใช้งานการซิงค์ราคา LiteLLM ในเบื้องหลัง                                        |
| `PRICING_SYNC_INTERVAL` | `86400`     | ช่วงเวลาการซิงค์เป็นวินาที (รายวัน)                                                |
| `PRICING_SYNC_SOURCES`  | `litellm`   | การเลือกแหล่งที่มาสำหรับการซิงค์นี้เท่านั้น ปัจจุบันรองรับเฉพาะ `litellm` เท่านั้น |

**การซิงค์ models.dev** แยกจากการซิงค์ LiteLLM และถูกปิดใช้งานตามค่าเริ่มต้นด้วย เปิดใช้งานในการตั้งค่า (การซิงค์ models.dev) หรือใช้ตัวแปรเหล่านี้:

| สภาพแวดล้อมที่หลากหลาย     | ค่าเริ่มต้น       | วัตถุประสงค์                                                                                                               |
| -------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(ไม่ได้ตั้งค่า)_ | Unset เป็นไปตามการสลับการตั้งค่า บังคับ `1/true/on/yes` และบังคับ `0/false/off/no` ปิด (แม้ว่าการตั้งค่าจะเปิดใช้งานก็ตาม) |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`           | ช่วงเวลาการซิงค์ของ models.dev เริ่มต้นเป็นวินาที (รายวัน)                                                                 |

`PRICING_SYNC_SOURCES` ทำ** ไม่** เปิดใช้งาน models.dev; มันควบคุมเฉพาะการซิงค์ LiteLLM การลบการแทนที่ผู้ใช้จะไม่ล้างเนมสเปซที่ซิงค์ไว้ ชั้นการกำหนดราคาถัดไปที่มีอยู่จะมีผลบังคับใช้ สำหรับรุ่นที่ไม่มีการกำหนดราคา ให้ตรวจสอบทั้งการตั้งค่าการซิงค์และ `sourceMap` ก่อนที่จะเพิ่มการลบล้างด้วยตนเอง

### สูตรต้นทุน

ต้นทุนคำนวณต่อคำขอจากจำนวนโทเค็นและอัตราต่อล้านโทเค็นใน [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`):

- **โทเค็นอินพุต** (ลบการอ่านแคชและโทเค็นการสร้างแคช) อัตรา × `input`
- **โทเค็นการอ่านแคช** อัตรา × `cached` (ถอยกลับไปเป็นอัตราอินพุต)
- **โทเค็นการสร้างแคช** อัตรา × `cache_creation` (ถอยกลับไปเป็นอัตราอินพุต)
- **โทเค็นเอาท์พุต** อัตรา × `output`
- **โทเค็นการใช้เหตุผล** อัตรา × `reasoning` (ถอยกลับไปที่อัตราเอาต์พุต)

อัตราทั้งหมดตีความว่าเป็น USD ต่อ 1,000,000 โทเค็น ระดับบริการ Codex "fast"/"priority" หรือ "flex" ใช้ตัวคูณต้นทุน (`getCodexFastCostMultiplier`) — เช่น flex จะถูกเรียกเก็บเงินด้วยส่วนลดโทเค็น 50% ซึ่งแสดงเป็น** ประหยัดแบบยืดหยุ่น** ในแดชบอร์ด

ชื่อโมเดลจะถูกทำให้เป็นมาตรฐานก่อน (คำนำหน้าเส้นทางผู้ให้บริการ เช่น `openai/` หรือ `accounts/fireworks/models/` จะถูกแยกออก) ดังนั้นแถวในอดีตจึงยังคงตรงกับราคา

### มีการบันทึกการใช้จ่ายอย่างไร

- ต้นทุนต่อคำขอจะถูกคำนวณเมื่อคำขอเสร็จสิ้น ปริมาณการใช้โควต้าที่ใช้ร่วมกันถูกกำหนดไว้ที่ขีดเหตุการณ์วนรอบถัดไปผ่าน [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts)
- การใช้จ่ายคีย์ API จะถูกบัฟเฟอร์และล้างเป็นชุดโดย [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (ช่วงฟลัชเริ่มต้น 60 วินาที บัฟเฟอร์ 1,000 รายการ) ปรับแต่งได้ทาง:

  | สภาพแวดล้อมที่หลากหลาย              | ค่าเริ่มต้น | วัตถุประสงค์                 |
  | ----------------------------------- | ----------- | ---------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`     | ช่วงเวลาฟลัชเป็นมิลลิวินาที  |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`      | รายการบัฟเฟอร์สูงสุดก่อนฟลัช |

ต้นทุนต้องการค่าบริการที่ผู้ให้บริการรายงาน (`provider_cost_usd`) ที่แน่นอน จากนั้นจึงใช้สแน็ปช็อตคำขอราคาแคตตาล็อก (`calculated_cost_usd`) จากนั้นจึงกำหนดราคาโทเค็นจากแค็ตตาล็อกปัจจุบัน ต้นทุนที่เก็บไว้จะไม่ถูกเรียกเก็บเงินอีกครั้งผ่านการนับโทเค็น แถวที่มีเฉพาะโทเค็นแบบเดิมยังคงเปลี่ยนแปลงเมื่อราคาแค็ตตาล็อกเปลี่ยนแปลง

### OCR และการฝัง

- คำขอ `/v1/ocr` ที่สำเร็จจะใช้อัปสตรีม `usage_info.pages_processed` ไม่ใช่ช่วงหน้าที่ร้องขอหรือจำนวนออบเจ็กต์หน้าที่ส่งคืน การประมาณคือหน้า × `ocr_cost_per_page` (สัมบูรณ์ USD/page,** ไม่** USD/million)
- คำขอที่มีเอกสารหรือคำอธิบายประกอบแบบ Bounding Box จะต้องเสียภาษี `ocr_cost_per_annotated_page` แยกต่างหาก หากไม่มีสิ่งนี้ ต้นทุนก็ยังไม่ทราบ อัตราภาษี OCR ธรรมดาไม่ได้ถูกทดแทนอย่างเงียบๆ
- LiteLLM sync แมปฟิลด์ `annotation_cost_per_page` อัปสตรีมลงใน `ocr_cost_per_annotated_page` โดยคงค่า USD/page สัมบูรณ์และรายการคำอธิบายประกอบเท่านั้น รวมถึงศูนย์ที่ชัดเจน ฟิลด์ตามรูปแบบบัญญัติที่ให้มาจะมีความสำคัญกว่า ค่านามแฝงที่ไม่ถูกต้องจะถูกละเว้น การแทนที่การกำหนดราคาของผู้ใช้จะยังคงมีลำดับความสำคัญตามปกติ ดู [คีย์การกำหนดราคา OCR ของ LiteLLM](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking)
- การใช้งาน OCR จะจัดเก็บจำนวนหน้า ราคาต่อหน่วย ต้นทุน USD ที่คำนวณได้ คีย์ API และการเชื่อมต่อที่เลือก เพจไม่เคยถูกแสดงเป็นโทเค็น บันทึกการโทรมีข้อมูลเมตาการเรียกเก็บเงิน ไม่ใช่เอกสาร URLs, PDF ไบต์ หรือข้อความที่แยกออกมา
- คำขอ `/v1/embeddings` ที่สำเร็จจะบันทึกหนึ่งแถวการใช้งานต่อแบตช์จริง รวมถึงแบตช์ที่แยกจากกันซึ่งเสร็จสมบูรณ์ในมิลลิวินาทีเดียวกัน ค่าบริการที่ผู้ให้บริการรายงานมีความสำคัญมากกว่าการประมาณการโทเค็น การห่อคำสั่งผสมไม่ได้เพิ่มค่าธรรมเนียม
- ประวัติการใช้งาน, การวิเคราะห์ต้นทุน, หน้าต่าง provider/account, ขีดจำกัดการใช้จ่ายของคีย์ API, บัญชีแยกประเภทต้นทุนคำขอ และการรวบรวมการใช้งานรายวันจะรวมค่าบริการเหล่านี้ด้วย ปุ่มที่ไม่มีการบันทึกจะเก็บการบัญชีตัวเลขไว้โดยไม่เก็บข้อความต้นฉบับ
- การใช้งานหรือภาษีหายไป** ไม่ทราบ** ไม่ฟรี: ละเว้นส่วนหัวการตอบกลับ และนโยบายการใช้งานที่ไม่มีการกำหนดราคาที่มีอยู่จะนำไปใช้กับคีย์ API ที่จำกัด อัตราศูนย์ที่กำหนดค่าไว้อย่างชัดเจนยังคงการใช้งานแบบไม่มีต้นทุนที่ถูกต้อง

นี่เป็นการบัญชีล่วงหน้าเท่านั้น การเรียก OCR/embedding เก่าที่ไม่เคยเขียนประวัติการใช้งานไม่สามารถสร้างใหม่จากการย้ายข้อมูลนี้ได้ การประมาณการแคตตาล็อกเป็นการประมาณการ USD ไม่ใช่ใบแจ้งหนี้ และไม่รวมการแปลงสกุลเงิน ภาษี หรือส่วนลด

### คำพูดและภาพ

- ความพยายาม `/v1/audio/transcriptions`, `/v1/audio/speech` และการสร้างอิมเมจที่ประสบความสำเร็จจะใช้บัญชีตัวเลขร่วมกัน การโทรโดยตรงและการโทรแบบคอมโบจะมีคีย์ API ของผู้โทรและการเชื่อมต่อที่เลือก wrapper คำสั่งผสมจะไม่เพิ่มเดบิตครั้งที่สอง
- USD ที่ผู้ให้บริการรายงานชนะเหนือการประมาณการแค็ตตาล็อก รวมถึงการเรียกเก็บเงินเป็นศูนย์อย่างชัดเจน OpenRouter ของ JSON `usage.cost` ถูกทำให้เป็นมาตรฐานเป็น `cost_usd` มิฉะนั้น โทเค็นที่วัดได้จะใช้ราคาโทเค็น วินาทีการถอดเสียงใช้ราคาต่อวินาที การป้อนข้อมูลด้วยเสียงใช้การนับอักขระ Unicode และรูปภาพราคาคงที่ใช้ตัวเลขที่ส่งคืนจริง ไม่ใช่ `n` ที่ร้องขอ
- ไบนารี OpenRouter TTS ไม่มีเนื้อหาการใช้งาน JSON หลังจากที่เสียงเสร็จสิ้นหรือผู้โทรยกเลิก OmniRoute จะสอบถามการสร้าง ID บน** เดียวกัน** ต้นกำเนิด OpenRouter ที่กำหนดค่าไว้ คำขอ EU จะไม่กลับไปอยู่ที่ต้นทางส่วนกลาง นี่คือการค้นหาแบบมีขอบเขตและแบบอ่านอย่างเดียว การสังเคราะห์ไม่ได้ถูกลองใหม่เพื่อการบัญชี บันทึกการเรียกเก็บเงินอาจปรากฏขึ้นหลังจากที่เสียงเสร็จสิ้น: การลองค้นหาใหม่จะทำงานในเบื้องหลังเป็นเวลาประมาณ 52 วินาที รวมถึงกำหนดเวลาของเครือข่ายด้วย
- ในระหว่างการค้นหานั้น การตอบสนองด้วยเสียงมี `X-OmniRoute-Cost-Status: pending` และไม่มีส่วนหัวต้นทุนการตอบกลับ การเรียกเก็บเงินครั้งสุดท้ายจะปรากฏในประวัติการใช้งาน การวิเคราะห์ และบัญชีแยกประเภทหลักหลังจากการกระทบยอด หากไม่มีข้อมูลเมตา ระบบจะใช้สแนปช็อตภาษีที่กำหนดค่าไว้ มิฉะนั้นจะไม่ทราบราคา
- จำนวนวินาที ตัวอักษร และรูปภาพมีฟิลด์หน่วยการเรียกเก็บเงินแยกกัน ไม่เคยนับโทเค็นปลอม การบัญชียังคงใช้เฉพาะการใช้ตัวเลขเท่านั้น ไม่ใช่ข้อความคำพูด การถอดเสียง หรือไบต์ของรูปภาพ การยกเว้นรูปภาพที่ไม่มีการกำหนดราคาที่มีอยู่จะไม่เปลี่ยนแปลง: อัตราภาษีรูปภาพที่หายไปอย่างแท้จริงไม่ได้ล็อคคีย์ที่จำกัดไว้ใหม่ และการตอบกลับจะละเว้นส่วนหัวของต้นทุนแทนที่จะประกาศการโทรฟรี ความล้มเหลวของร้านค้ากำหนดราคายังคงรักษาหลักฐานการใช้งานสำหรับการบังคับใช้ที่ปิดไม่สำเร็จ

ไม่มีการประดิษฐ์หรือทดแทนค่าธรรมเนียม speech/image ในอดีต การเรียกเก็บเงินของผู้ให้บริการยังคงเป็นข้อมูลอ้างอิงสำหรับใบแจ้งหนี้และการโทรที่ไม่ได้รายงานการเรียกเก็บเงิน

## แดชบอร์ด: หน้า Costs

หน้า **Costs** อยู่ที่ `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`)
มุมมองหลักคือแท็บ **Cost Overview**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`)
ซึ่งโหลดข้อมูลทั้งหมดจาก `GET /api/usage/analytics`

สิ่งที่แสดง:

- **การ์ดค่าใช้จ่าย** — ค่าใช้จ่ายโดยประมาณสำหรับ _วันนี้ (1d)_, _7d_, _30d_ และช่วงเวลา
  ที่เลือก ตัวเลือกช่วงเวลา: `7d`, `30d`, `90d`, `all`
- **เมตริกหลัก** — จำนวนคำขอในช่วงเวลา, ผู้ให้บริการที่ใช้งานอยู่, โมเดลที่ใช้งานอยู่ และค่าใช้จ่ายเฉลี่ย
  ต่อคำขอ
- **เครื่องมือสำรวจค่าใช้จ่าย** — ตารางที่จัดเรียง/กรองได้ โดยจัดกลุ่มตาม **ผู้ให้บริการ**, **โมเดล**,
  **คีย์ API**, **บัญชี** หรือ **ระดับบริการ** พร้อมค่าใช้จ่าย, จำนวนคำขอ, โทเค็น, ค่าใช้จ่ายเฉลี่ย
  ต่อคำขอ และเปอร์เซ็นต์สัดส่วนของยอดรวม
- **การใช้โทเค็น** — จำนวนโทเค็นทั้งหมด / อินพุต / เอาต์พุต และอัตราส่วนอินพุต:เอาต์พุต
- **ประสิทธิภาพการกำหนดเส้นทาง** — จำนวนการใช้ตัวเลือกสำรอง, อัตราการใช้ตัวเลือกสำรอง และความครอบคลุมของโมเดลที่ร้องขอ
- **การคาดการณ์รายเดือน** — คาดการณ์ค่าใช้จ่าย ณ สิ้นเดือนจากค่าเฉลี่ยรายวันล่าสุด
- **การเปรียบเทียบช่วงเวลา** — เปอร์เซ็นต์การเปลี่ยนแปลงระหว่างครึ่งแรกและครึ่งหลังของช่วงเวลา
- **แผนภูมิ** — แนวโน้มค่าใช้จ่ายรายวัน, สัดส่วนผู้ให้บริการ (แผนภูมิวงกลม), ผู้ให้บริการอันดับต้น ๆ, โมเดลอันดับต้น ๆ, ค่าใช้จ่าย
  ตามคีย์ API, ค่าใช้จ่ายตามบัญชี, รูปแบบการใช้งานรายสัปดาห์ และแผนที่ความร้อนของกิจกรรม
- **ส่งออก** — ดาวน์โหลดข้อมูลของช่วงเวลาปัจจุบันเป็น **CSV** หรือ **JSON** (ปุ่มจะปรากฏ
  เมื่อมีข้อมูลค่าใช้จ่ายที่มากกว่าศูนย์)

เมื่อไม่มีทราฟฟิกที่มีการคิดราคา แถวจะแสดงป้ายกำกับ "Legacy / Free" แทน `$0`
เพื่อสะท้อนโมเดลติดตามการประหยัดค่าใช้จ่าย

### หน้าย่อยที่เกี่ยวข้องใน Costs

พื้นที่ Costs ยังมีหน้าต่อไปนี้ (ทั้งหมดอยู่ภายใต้ `/dashboard/costs/`):

- **การกำหนดราคา** (`/dashboard/costs/pricing`) — ดูและแทนที่ราคาของแต่ละโมเดล (แสดงผล
  แท็บ Pricing ที่ใช้ร่วมกัน)

  Budget ที่ใช้ร่วมกัน)
- **โควตาที่ใช้ร่วมกัน** (`/dashboard/costs/quota-share`) — พูลโควตาที่ใช้ร่วมกันและมุมมอง
  อัตราการใช้โควตา

## จุดสิ้นสุด API

ทั้งหมดนี้จำเป็นต้องมี Management auth (loopback/JWT, via `requireManagementAuth`) เว้นแต่จะระบุไว้

### การวิเคราะห์การใช้งานและต้นทุน

| วิธี  | จุดสิ้นสุด               | วัตถุประสงค์                                                                                                                                                |
| ----- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | การวิเคราะห์ cost/usage แบบเต็ม: สรุป แนวโน้มรายวัน โดย provider/model/API key/account/tier. Query: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets` |
| `GET` | `/api/usage/utilization` | การใช้โควต้าต่อผู้ให้บริการในช่วงเวลาหนึ่ง ข้อความค้นหา: `range` (`1h`/`24h`/`7d`/`30d`), `provider`                                                        |
| `GET` | `/api/usage/history`     | แถวประวัติการใช้งานดิบ                                                                                                                                      |
| `GET` | `/api/usage/call-logs`   | บันทึกการโทรต่อคำขอ (โมเดล โทเค็น ต้นทุน เวลาแฝง สถานะ)                                                                                                     |
| `GET` | `/api/usage/quota`       | สถานะโควต้าของผู้ให้บริการ                                                                                                                                  |
| `GET` | `/api/usage/proxy-logs`  | บันทึกคำขอพร็อกซี                                                                                                                                           |

### งบประมาณ

| วิธี   | จุดสิ้นสุด               | วัตถุประสงค์                                                                                   |
| ------ | ------------------------ | ---------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | การตรวจสอบงบประมาณ + สรุปต้นทุนสำหรับคีย์ API หนึ่งคีย์ (ต้องใช้พารามิเตอร์เคียวรี`apiKeyId` ) |
| `POST` | `/api/usage/budget`      | ตั้งค่า daily/weekly/monthly USD จำกัดขีดจำกัดการเตือน + สำหรับคีย์ API                        |
| `GET`  | `/api/usage/budget/bulk` | สรุปงบประมาณจำนวนมากสำหรับคีย์ API                                                             |

> งบประมาณ API มีขอบเขตตาม** คีย์API** (`apiKeyId`). ขีดจำกัดที่ส่งคืนโดย `GET /api/usage/budget` ได้แก่ `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`, a `warningThreshold` และผลรวมที่ทำงานอยู่ (`totalCostToday`, `totalCostMonth`, …)

## CLI

CLI ของ OmniRoute มีคำสั่งสำหรับค่าใช้จ่าย การใช้งาน และการกำหนดราคา (ลงทะเบียนไว้ใน
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs))

### `omniroute cost`

รายงานค่าใช้จ่ายที่รวบรวมจาก `/api/usage/analytics`

```bash
omniroute cost                          # 30 วันที่ผ่านมา จัดกลุ่มตามผู้ให้บริการ
omniroute cost --period 7d              # 7 วันที่ผ่านมา
omniroute cost --group-by model         # จัดกลุ่มตาม provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

คอลัมน์: กลุ่ม, จำนวนคำขอ, โทเค็นขาเข้า/ขาออก, ค่าใช้จ่าย (USD) และเปอร์เซ็นต์ของยอดรวม ระบบจะแสดงบรรทัดยอดรวมทั้งหมด
ที่ส่วนท้าย (ไม่แสดงเมื่อใช้ `--quiet` หรือ `--output json`)

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # สรุปค่าใช้จ่ายแยกตามผู้ให้บริการ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# งบประมาณ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` อ่านข้อมูลจาก `GET /api/pricing/defaults` หากต้องการแก้ไขราคาเฉพาะโมเดล
> ให้ใช้หน้าแดชบอร์ด **การกำหนดราคา** หรือ `PATCH /api/pricing` แทน

## การแก้ไขปัญหา

- **ค่าใช้จ่ายทั้งหมดแสดงเป็น $0 / "Legacy / Free"** โมเดลที่ใช้งานไม่มีรายการราคา
  ให้เปิดใช้การซิงค์ภายนอก (`PRICING_SYNC_ENABLED=true`) และเรียกใช้ `omniroute pricing sync` หรือ
  กำหนดราคาด้วยตนเองผ่านหน้าการกำหนดราคา / `PATCH /api/pricing`
- **ราคาของโมเดลในอดีตไม่ถูกต้อง** แก้ไขราคา (เขียนทับหรือซิงค์ใหม่) — ระบบจะ
  คำนวณค่าใช้จ่ายใหม่จากจำนวนโทเค็นทุกครั้งที่อ่านข้อมูลวิเคราะห์ ดังนั้นค่าประมาณจะได้รับการอัปเดตย้อนหลัง
- **ยอดใช้จ่ายล่าช้ากว่าเวลาจริง** ยอดใช้จ่ายต่อคีย์จะถูกประมวลผลเป็นชุด ให้ลดค่า
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` หากต้องการตัวเลขที่เป็นปัจจุบันมากขึ้น
