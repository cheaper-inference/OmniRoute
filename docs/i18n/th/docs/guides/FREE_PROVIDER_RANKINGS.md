> **สรุปสั้นๆ**: OmniRoute จัดอันดับผู้ให้บริการ **ฟรี** ตามคุณภาพของโมเดลโดยใช้ **คะแนน ELO
> จาก Arena AI (รูปแบบเดียวกับ LMArena)** เปิดหน้า **Free Provider Rankings** ใน
> แดชบอร์ดเพื่อดูว่าผู้ให้บริการฟรีรายใดมีโมเดลที่ทรงประสิทธิภาพที่สุดสำหรับงานของคุณ —
> ทั้งในภาพรวมหรือกรองตามหมวดหมู่ (การเขียนโค้ด การรีวิว การจัดทำเอกสาร การดีบัก)

## มันคืออะไร

OmniRoute ลงทะเบียนผู้ให้บริการ 377 ราย รวมถึงรายการแค็ตตาล็อก 155 รายการที่มีการทำเครื่องหมายไว้**free/no-auth** (no-auth, free-tier OAuth หรือคีย์ API free-tier — ดู [Free Tiers Guide](../getting-started/FREE-TIERS-GUIDE.md) และ [ไดเร็กทอรี Free Tiers](../reference/FREE_TIERS.md) ฉบับเต็ม) สิ่งที่จับได้: ผู้ให้บริการฟรีมีความแตกต่างกันอย่างมากในด้านคุณภาพของโมเดล ผู้ให้บริการที่ไม่ตรวจสอบสิทธิ์ซึ่งให้บริการโมเดลชายแดนนั้นมีประโยชน์มากกว่าผู้ให้บริการรายหนึ่งที่ให้บริการโมเดลดั้งเดิมขนาดเล็ก

**การจัดอันดับผู้ให้บริการฟรี** คำตอบ "** ผู้ให้บริการฟรีรายใดที่ให้โมเดลที่ดีที่สุดแก่ฉัน?** "โดยการเข้าร่วมแค็ตตาล็อกของผู้ให้บริการฟรีแต่ละรายด้วย** คะแนนคุณภาพที่มาจากฝูงชน** จาก** ลีดเดอร์บอร์ด Arena AI** (การตั้งค่าของมนุษย์ ELO ซึ่งเป็นแนวคิดเดียวกันที่อยู่เบื้องหลังเวทีแชทบอท LMArena) ผู้ให้บริการจะถูกจัดอันดับตามความแข็งแกร่งของพวกเขา** โมเดลฟรีที่ดีที่สุด** .

การจัดอันดับคำนวณจากแหล่งข้อมูลจริงสามแหล่ง:

1. รายชื่อผู้ให้บริการฟรี — `NOAUTH_PROVIDERS` บวกกับรายการ `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` ที่ถูกตั้งค่าสถานะ `hasFree` (`src/shared/constants/providers.ts`)
2. แค็ตตาล็อกโมเดลของผู้ให้บริการแต่ละรายจากการลงทะเบียนผู้ให้บริการ (`open-sse/config/providerRegistry.ts`)
3. คะแนนที่เหมาะกับงานที่ได้รับจาก ELO เก็บไว้ในตาราง `model_intelligence` DB โดยเอ็นจิ้นการซิงค์ Arena ELO (`src/lib/arenaEloSync.ts`)

ตรรกะการเข้าร่วมอาศัยอยู่ใน `src/lib/freeProviderRankings.ts`

## วิธีเข้าถึง

### หน้าแดชบอร์ด

เปิดแดชบอร์ดแล้วไปที่ **Costs → Free Provider Rankings** หรือไปยังเส้นทางต่อไปนี้โดยตรง:

```
/dashboard/free-provider-rankings
```

หน้า (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) แสดง:

- **โพเดียม 3 อันดับแรก** (🥇 🥈 🥉) ของผู้ให้บริการฟรีที่ได้รับการจัดอันดับสูงสุด
- **ตารางจัดอันดับ** ฉบับเต็มพร้อมคอลัมน์: **อันดับ**, **ผู้ให้บริการ**, **โมเดลยอดนิยม**,
  **คะแนน**, **คะแนนเฉลี่ย**, **โมเดล**, **ประเภท**
- **ปุ่มกรองหมวดหมู่**: _ทุกหมวดหมู่_, _ค่าเริ่มต้น_, _การเขียนโค้ด_, _การรีวิว_,
  _การจัดทำเอกสาร_, _การดีบัก_

ป้าย **ประเภท** ของผู้ให้บริการแต่ละรายบอกให้ทราบว่าให้บริการฟรีในรูปแบบใด:

| ป้าย     | ความหมาย                                             |
| -------- | ---------------------------------------------------- |
| `NOAUTH` | ฟรีตลอดเวลา โดยไม่ต้องใช้ข้อมูลประจำตัว              |
| `OAUTH`  | ผู้ให้บริการ OAuth ที่มีระดับฟรี (`hasFree`)         |
| `APIKEY` | ผู้ให้บริการที่ใช้ API key และมีระดับฟรี (`hasFree`) |

คะแนนจะแสดงเป็นป้ายกำกับที่มนุษย์อ่านเข้าใจได้ (เช่น _ยอดเยี่ยมที่สุด_, _ยอดเยี่ยม_, _ดีมาก_,
_ดี_, _ปานกลาง_) แทนตัวเลขดิบ เนื่องจากค่าพื้นฐานเป็นคุณภาพการจัดอันดับเชิงสัมพัทธ์
ไม่ใช่เปอร์เซ็นต์

### API endpoint

หน้านี้ใช้ endpoint สำหรับการอ่านแบบสาธารณะ
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

พารามิเตอร์คิวรี (ตรวจสอบความถูกต้องด้วย Zod):

| พารามิเตอร์ | ประเภท | ค่าเริ่มต้น | หมายเหตุ                                                                                                              |
| ----------- | ------ | ----------- | --------------------------------------------------------------------------------------------------------------------- |
| `category`  | string | (ไม่มี)     | ค่าใดค่าหนึ่งใน `default`, `coding`, `review`, `documentation`, `debugging` ละเว้นพารามิเตอร์นี้สำหรับการจัดอันดับรวม |
| `limit`     | number | `50`        | จำกัดให้อยู่ในช่วง `1–100`                                                                                            |

รูปแบบการตอบกลับ:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` คือค่า Arena ELO ดั้งเดิม ส่วน `score` คือค่าความเหมาะสมกับงานที่ผ่านการปรับมาตรฐานแล้ว
(ดูด้านล่าง) ผู้ให้บริการที่ไม่มีโมเดลซึ่งได้รับคะแนนจะไม่รวมอยู่ในการตอบกลับ

## คะแนนทำงานอย่างไร

### แหล่งข้อมูล: Arena AI leaderboard

ตัวซิงค์ Arena ELO (`src/lib/arenaEloSync.ts`) ดึงข้อมูล leaderboard สองชุด — ได้แก่ `text`
และ `code` — จาก API ของ Arena AI leaderboard
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) เมื่อ API นั้นไม่ส่งคืน
บอร์ดที่ใช้งานได้ ระบบจะเปลี่ยนไปใช้ `lmarena-ai/leaderboard-dataset` อย่างเป็นทางการ
บน Hugging Face datasets-server แทน (`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` จะรายงานค่า `activeSource`, `lastError` และ
`lastFailedAt` แต่ละรายการใน leaderboard จะมีชื่อโมเดล ผู้ผลิต คะแนน ELO `score`
ช่วงความเชื่อมั่น และจำนวนโหวต

หมวดหมู่ของ leaderboard จับคู่กับหมวดหมู่งานของ OmniRoute ดังนี้:

| Arena leaderboard | หมวดหมู่งานของ OmniRoute                          |
| ----------------- | ------------------------------------------------- |
| `text`            | `default`, `review`, `documentation`, `debugging` |
| `code`            | `coding`                                          |

### การปรับให้เป็นมาตรฐาน (คะแนนความเหมาะสมกับงาน)

คะแนน ELO ดิบจะถูกปรับให้เป็นมาตรฐานแยกตาม leaderboard ให้เป็น **ค่าความเหมาะสมกับงานในช่วง `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

คะแนนจะไม่มีวันแตะ `0` หรือ `1` เพื่อเว้นที่ไว้สำหรับการกำหนดค่าเองโดยผู้ใช้ นี่คือ
ฟิลด์ `score` ที่คุณเห็นใน response ของ API และป้ายกำกับที่แสดงบนแดชบอร์ด

### ระดับความเชื่อมั่น

แต่ละรายการจะได้รับระดับความเชื่อมั่นตามจำนวนโหวตใน Arena:

| ความเชื่อมั่น | จำนวนโหวต |
| ------------- | --------- |
| `high`        | ≥ 5,000   |
| `medium`      | ≥ 1,000   |
| `low`         | < 1,000   |

### การจัดเก็บและความสดใหม่

รายการที่ปรับให้เป็นมาตรฐานแล้วจะถูกเขียนลงในตาราง DB ชื่อ `model_intelligence`
โดยมี `source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`) รายการเหล่านี้ **จะหมดอายุหลังจาก
7 วัน** ดังนั้นผู้ให้บริการที่หยุดซิงค์จะค่อยๆ หายไป แทนที่จะยังคงให้บริการ
ข้อมูลที่ล้าสมัย

การซิงค์ทำงาน **เปิดไว้เป็นค่าเริ่มต้น**:

- ทำงานหนึ่งครั้งตอนเริ่มเซิร์ฟเวอร์ จากนั้นทำงานตามตัวจับเวลาเป็นระยะ
  (`src/lib/arenaEloSync.ts` เชื่อมต่อจาก `src/instrumentation-node.ts`)
- เป็นแบบ **non-blocking และไม่ทำให้ระบบล้มเหลว** — หากการดึงข้อมูลจากต้นทางล้มเหลว OmniRoute จะยังคง
  ทำงานต่อไป และการจัดอันดับจะแสดงข้อมูลล่าสุดที่ดี (หรือสถานะว่างเปล่า)

มีตัวแปรสภาพแวดล้อมสองตัวที่ควบคุมการทำงานนี้ (มีเอกสารอธิบายใน
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| ตัวแปร                    | ค่าเริ่มต้น   | วัตถุประสงค์                                      |
| ------------------------- | ------------- | ------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | ตั้งค่าเป็น `false` เพื่อเลือกไม่ใช้การซิงค์ขาออก |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | ช่วงเวลาการซิงค์ หน่วยเป็นวินาที                  |

### การซิงค์ด้วยตนเอง / สถานะ / การล้างข้อมูล

สำหรับผู้ดูแลระบบ มี endpoint สำหรับจัดการที่ต้องยืนยันตัวตนซึ่งให้การควบคุมด้วยตนเอง
(`src/app/api/intelligence/sync/route.ts` — ต้องใช้สิทธิ์การจัดการ):

```
GET    /api/intelligence/sync          # current sync status (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # trigger a manual sync; body: { "dryRun": true } to preview without writing
DELETE /api/intelligence/sync          # clear all synced arena_elo intelligence entries
```

หากหน้าการจัดอันดับว่างเปล่า การเรียก `POST /api/intelligence/sync` ด้วยตนเอง (หรือเพียงแค่
รีสตาร์ทเซิร์ฟเวอร์) จะเติมข้อมูลใหม่อีกครั้ง

### การจับคู่โมเดลกับ leaderboard

ID โมเดลใน registry กับชื่อโมเดลใน Arena ไม่ได้ตรงกันเสมอไป การจัดอันดับใช้
การจับคู่แบบยืดหยุ่น (`findMatchingIntelligence` ใน `src/lib/freeProviderRankings.ts`):

1. จับคู่ตรงกันแน่นอนกับ ID โมเดลที่ถูกปรับให้เป็นมาตรฐาน
2. จับคู่หลังจากตัด suffix เวอร์ชันท้ายชื่อออก (เช่น `kimi-k2.6` → `kimi-k2`)
3. จับคู่แบบ prefix (ชื่อโมเดลใน leaderboard เป็น prefix ของ ID ใน registry)

ในฝั่งการซิงค์ prefix ของผู้ผลิตที่รู้จัก (`anthropic/`, `openai/`, `google/`, …) จะถูก
ตัดออก และมีแผนที่ alias ขนาดเล็กที่ขยายชื่อมาตรฐานให้เป็นชื่อรูปแบบต่างๆ ที่ OmniRoute ใช้
ภายใน เพื่อให้ค้นหาโมเดลเจอได้ไม่ว่าจะใช้ชื่อใด

### วิธีจัดอันดับผู้ให้บริการ

สำหรับผู้ให้บริการฟรีแต่ละราย ระบบจะให้คะแนนทุกโมเดลในแคตตาล็อกของตน จากนั้น:

- **Top Model** = โมเดลที่มีคะแนนสูงสุดของผู้ให้บริการรายนั้น
- **Avg Score** = คะแนนเฉลี่ยของโมเดลทั้งหมดที่ได้รับการให้คะแนนของผู้ให้บริการรายนั้น
- **Models** = จำนวนโมเดลของผู้ให้บริการที่มีคะแนนจาก Arena

ผู้ให้บริการจะถูกเรียงลำดับตาม **คะแนนของโมเดลอันดับสูงสุด** ก่อน แล้วจึงเรียงตามคะแนนเฉลี่ย วิธีนี้ให้รางวัลแก่
ผู้ให้บริการที่มีโมเดลฟรีที่แข็งแกร่งอย่างน้อยหนึ่งตัว

## การใช้ข้อมูลนี้เพื่อเลือกผู้ให้บริการฟรี

1. **เลือกหมวดหมู่ที่เหมาะสม** ใช้ตัวกรอง **Coding** สำหรับเวิร์กโหลดแบบเอเจนต์/งานเขียนโค้ด หรือ
   คงไว้ที่ **All Categories** / **Default** สำหรับการแชททั่วไป ผู้ให้บริการรายเดียวกันอาจ
   มีอันดับแตกต่างกันในแต่ละหมวดหมู่ เนื่องจากโมเดลอันดับสูงสุดของผู้ให้บริการจะแตกต่างกันไปตามแต่ละลีดเดอร์บอร์ด
2. **เลือกผู้ให้บริการบนโพเดียมสำหรับการตั้งค่าแบบครั้งเดียว** หากคุณต้องการเชื่อมต่อผู้ให้บริการฟรี
   เพียงหนึ่งหรือสองราย ให้เริ่มจากรายที่มีอันดับสูงสุดในหมวดหมู่ของคุณ
3. **ตรวจสอบป้าย Type** ผู้ให้บริการ `NOAUTH` เชื่อมต่อได้รวดเร็วที่สุด (ไม่ต้องใช้
   ข้อมูลประจำตัว) แพ็กเกจฟรีแบบ `OAUTH` / `APIKEY` ต้องสมัครใช้งานอย่างรวดเร็ว แต่มักเปิดให้ใช้
   โมเดลที่มีประสิทธิภาพสูงกว่า ดูขั้นตอนการเชื่อมต่อได้ที่ [คู่มือแพ็กเกจฟรี](../getting-started/FREE-TIERS-GUIDE.md)
4. **เชื่อมต่อหลายรายแล้วให้ Auto-Combo ตัดสินใจ** ข้อมูล Arena ELO ชุดเดียวกับที่ขับเคลื่อน
   หน้านี้ยังถูกนำไปใช้เป็น **ปัจจัยความเหมาะสมกับงาน** ของเอนจินให้คะแนน Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`, ลำดับการพิจารณา
   `user_override → arena_elo → models_dev_tier → static table`) ดังนั้น หลังจากเชื่อมต่อ
   ผู้ให้บริการฟรีอันดับต้น ๆ แล้ว การกำหนดเส้นทางด้วย `model: "auto"` (เช่น `auto/coding`) จะ
   เลือกใช้โมเดลฟรีที่มีคุณภาพสูงกว่าสำหรับแต่ละคำขอโดยอัตโนมัติ ดูรายละเอียดการให้คะแนนครบทั้ง 16 ปัจจัยได้ที่
   [Auto-Combo](../routing/AUTO-COMBO.md)
