> **สรุปสั้นๆ**: OmniRoute จัดอันดับผู้ให้บริการ **ฟรี** ตามคุณภาพของโมเดลโดยใช้ **คะแนน ELO
> จาก Arena AI (รูปแบบเดียวกับ LMArena)** เปิดหน้า **Free Provider Rankings** ใน
> แดชบอร์ดเพื่อดูว่าผู้ให้บริการฟรีรายใดมีโมเดลที่ทรงประสิทธิภาพที่สุดสำหรับงานของคุณ —
> ทั้งในภาพรวมหรือกรองตามหมวดหมู่ (การเขียนโค้ด การรีวิว การจัดทำเอกสาร การดีบัก)

## คืออะไร

OmniRoute ลงทะเบียนผู้ให้บริการไว้ 376 ราย รวมถึงรายการแคตตาล็อก 155 รายการที่ระบุว่า **ฟรี/ไม่ต้องยืนยันตัวตน**
(ไม่ต้องยืนยันตัวตน,
OAuth ระดับฟรี หรือคีย์ API ระดับฟรี — ดู
[คู่มือระดับฟรี](../getting-started/FREE-TIERS-GUIDE.md) และ
[ไดเรกทอรีระดับฟรี](../reference/FREE_TIERS.md) ฉบับเต็ม) แต่มีข้อควรระวังคือ ผู้ให้บริการฟรีมีคุณภาพของโมเดล
แตกต่างกันอย่างมาก ผู้ให้บริการที่ไม่ต้องยืนยันตัวตนซึ่งให้บริการโมเดลแนวหน้าย่อมมีประโยชน์มากกว่า
ผู้ให้บริการที่ให้บริการโมเดลรุ่นเก่าขนาดเล็ก

**การจัดอันดับผู้ให้บริการฟรี** ตอบคำถามว่า "**ผู้ให้บริการฟรีรายใดมีโมเดลที่ดีที่สุดสำหรับฉัน?**" โดย
เชื่อมโยงแคตตาล็อกของผู้ให้บริการฟรีแต่ละรายเข้ากับ **คะแนนคุณภาพจากการรวบรวมความคิดเห็นของผู้ใช้** จาก
**กระดานผู้นำ Arena AI** (ELO จากความพึงพอใจของมนุษย์ ซึ่งเป็นแนวคิดเดียวกับที่ใช้ในสนามประลอง
แชตบอต LMArena) จากนั้นผู้ให้บริการจะถูกจัดอันดับตามศักยภาพของ **โมเดลฟรีที่ดีที่สุด** ของตน

การจัดอันดับคำนวณจากแหล่งข้อมูลจริงสามแหล่ง:

1. รายชื่อผู้ให้บริการฟรี — `NOAUTH_PROVIDERS` รวมถึงรายการ `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` ที่ตั้งค่าสถานะ `hasFree`
   (`src/shared/constants/providers.ts`)
2. แคตตาล็อกโมเดลของผู้ให้บริการแต่ละรายจากรีจิสทรีผู้ให้บริการ
   (`open-sse/config/providerRegistry.ts`)
3. คะแนนความเหมาะสมกับงานที่คำนวณจาก ELO ซึ่งจัดเก็บไว้ในตารางฐานข้อมูล `model_intelligence` โดย
   เอนจินซิงค์ Arena ELO (`src/lib/arenaEloSync.ts`)

ตรรกะการเชื่อมโยงข้อมูลอยู่ใน `src/lib/freeProviderRankings.ts`

## วิธีเข้าถึง

### หน้าแดชบอร์ด

เปิดแดชบอร์ดแล้วไปที่ **Costs → Free Provider Rankings** หรือไปยังเส้นทางต่อไปนี้โดยตรง:

```
/dashboard/free-provider-rankings
```

หน้า (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) แสดง:

- **โพเดียม 3 อันดับแรก** (🥇 🥈 🥉) ของผู้ให้บริการฟรีที่ได้รับการจัดอันดับสูงสุด
- **ตารางจัดอันดับ** ฉบับเต็มพร้อมคอลัมน์: **อันดับ**, **ผู้ให้บริการ**, **โมเดลยอดนิยม**,
  **คะแนน**, **คะแนนเฉลี่ย**, **โมเดล**, **ประเภท**
- **ปุ่มกรองหมวดหมู่**: _ทุกหมวดหมู่_, _ค่าเริ่มต้น_, _การเขียนโค้ด_, _การรีวิว_,
  _การจัดทำเอกสาร_, _การดีบัก_

ป้าย **ประเภท** ของผู้ให้บริการแต่ละรายบอกให้ทราบว่าให้บริการฟรีในรูปแบบใด:

| ป้าย     | ความหมาย                                             |
| -------- | ---------------------------------------------------- |
| `NOAUTH` | ฟรีตลอดเวลา โดยไม่ต้องใช้ข้อมูลประจำตัว              |
| `OAUTH`  | ผู้ให้บริการ OAuth ที่มีระดับฟรี (`hasFree`)         |
| `APIKEY` | ผู้ให้บริการที่ใช้ API key และมีระดับฟรี (`hasFree`) |

คะแนนจะแสดงเป็นป้ายกำกับที่มนุษย์อ่านเข้าใจได้ (เช่น _ยอดเยี่ยมที่สุด_, _ยอดเยี่ยม_, _ดีมาก_,
_ดี_, _ปานกลาง_) แทนตัวเลขดิบ เนื่องจากค่าพื้นฐานเป็นคุณภาพการจัดอันดับเชิงสัมพัทธ์
ไม่ใช่เปอร์เซ็นต์

### API endpoint

หน้านี้ใช้ endpoint สำหรับการอ่านแบบสาธารณะ
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

พารามิเตอร์คิวรี (ตรวจสอบความถูกต้องด้วย Zod):

| พารามิเตอร์ | ประเภท | ค่าเริ่มต้น | หมายเหตุ                                                                                                              |
| ----------- | ------ | ----------- | --------------------------------------------------------------------------------------------------------------------- |
| `category`  | string | (ไม่มี)     | ค่าใดค่าหนึ่งใน `default`, `coding`, `review`, `documentation`, `debugging` ละเว้นพารามิเตอร์นี้สำหรับการจัดอันดับรวม |
| `limit`     | number | `50`        | จำกัดให้อยู่ในช่วง `1–100`                                                                                            |

รูปแบบการตอบกลับ:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` คือค่า Arena ELO ดั้งเดิม ส่วน `score` คือค่าความเหมาะสมกับงานที่ผ่านการปรับมาตรฐานแล้ว
(ดูด้านล่าง) ผู้ให้บริการที่ไม่มีโมเดลซึ่งได้รับคะแนนจะไม่รวมอยู่ในการตอบกลับ

## การทำงานของคะแนน

### แหล่งข้อมูล: Arena AI leaderboard

เอนจินซิงก์ Arena ELO (`src/lib/arenaEloSync.ts`) ดึงข้อมูล leaderboard สองชุด — `text`
และ `code` — จาก Arena AI leaderboard API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) เมื่อ API ดังกล่าวไม่ส่ง
คืน board ที่ใช้งานได้ เอนจินจะสลับไปใช้ `lmarena-ai/leaderboard-dataset` อย่างเป็นทางการบน
Hugging Face datasets-server แทน (`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` จะรายงาน `activeSource`, `lastError` และ
`lastFailedAt` แต่ละรายการใน leaderboard
จะมีชื่อโมเดล ผู้ผลิต (vendor) `score` ของ ELO ช่วงความเชื่อมั่น (confidence interval) และจำนวนโหวตกำกับอยู่

หมวดหมู่ของ leaderboard จับคู่กับหมวดหมู่งานของ OmniRoute ดังนี้:

| Arena leaderboard | หมวดหมู่งานของ OmniRoute                          |
| ----------------- | ------------------------------------------------- |
| `text`            | `default`, `review`, `documentation`, `debugging` |
| `code`            | `coding`                                          |

### การปรับให้เป็นมาตรฐาน (คะแนนความเหมาะสมกับงาน)

คะแนน ELO ดิบจะถูกปรับให้เป็นมาตรฐาน (normalize) ตาม leaderboard แต่ละชุด ให้กลายเป็น **ค่าความเหมาะสมกับงาน (task-fit) ในช่วง `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

คะแนนจะไม่มีทางถึง `0` หรือ `1` เพื่อเผื่อที่ว่างไว้สำหรับการกำหนดค่าเองโดยผู้ใช้ นี่คือ
ฟิลด์ `score` ที่คุณเห็นในการตอบกลับของ API และป้ายกำกับที่แสดงบนแดชบอร์ด

### ความเชื่อมั่น (Confidence)

แต่ละรายการจะได้รับระดับความเชื่อมั่นตามจำนวนโหวตของ Arena:

| ความเชื่อมั่น | จำนวนโหวต |
| ------------- | --------- |
| `high`        | ≥ 5,000   |
| `medium`      | ≥ 1,000   |
| `low`         | < 1,000   |

### การจัดเก็บและความสดใหม่ของข้อมูล

รายการที่ผ่านการปรับให้เป็นมาตรฐานแล้วจะถูกเขียนลงในตาราง DB ชื่อ `model_intelligence` พร้อมกับ
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`) รายการเหล่านี้ **จะหมดอายุหลังจาก
7 วัน** ดังนั้นหาก provider ใดหยุดซิงก์ข้อมูล ข้อมูลของ provider นั้นจะค่อย ๆ หายไป แทนที่จะ
ยังคงแสดงข้อมูลที่ล้าสมัยอยู่

การซิงก์ทำงานอยู่ **เป็นค่าเริ่มต้น**:

- มันทำงานหนึ่งครั้งตอนเซิร์ฟเวอร์เริ่มทำงาน จากนั้นจะทำงานตามตัวตั้งเวลาเป็นระยะ
  (`src/lib/arenaEloSync.ts` เชื่อมต่อจาก `src/instrumentation-node.ts`)
- มันเป็นแบบ **ไม่บล็อกการทำงาน (non-blocking) และไม่ทำให้ระบบล่ม (never fatal)** — หากการดึงข้อมูลจาก upstream ล้มเหลว OmniRoute จะยังคง
  ทำงานต่อไป และอันดับจะแสดงข้อมูลชุดล่าสุดที่ยังใช้ได้ (หรือแสดงสถานะว่างเปล่า)

มี environment variable สองตัวที่ควบคุมการทำงานนี้ (มีเอกสารอธิบายไว้ใน
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| ตัวแปร                    | ค่าเริ่มต้น   | วัตถุประสงค์                                      |
| ------------------------- | ------------- | ------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | ตั้งค่าเป็น `false` เพื่อเลือกไม่ใช้การซิงก์ขาออก |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | ช่วงเวลาในการซิงก์ มีหน่วยเป็นวินาที              |

### การซิงก์ด้วยตนเอง / ตรวจสอบสถานะ / ล้างข้อมูล

สำหรับผู้ดูแลระบบ มี management endpoint ที่ต้องยืนยันตัวตนเพื่อเปิดการควบคุมด้วยตนเอง
(`src/app/api/intelligence/sync/route.ts` — ต้องใช้การยืนยันตัวตนแบบ management):

```
GET    /api/intelligence/sync          # สถานะการซิงก์ปัจจุบัน (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # เรียกการซิงก์ด้วยตนเอง; body: { "dryRun": true } เพื่อดูตัวอย่างโดยไม่เขียนข้อมูล
DELETE /api/intelligence/sync          # ล้างรายการ intelligence ทั้งหมดที่ซิงก์มาจาก arena_elo
```

หากหน้าอันดับว่างเปล่า การเรียก `POST /api/intelligence/sync` ด้วยตนเอง (หรือเพียงแค่
รีสตาร์ทเซิร์ฟเวอร์) จะเติมข้อมูลกลับเข้าไปใหม่

### การจับคู่โมเดลกับ leaderboard

รหัสโมเดลใน Registry กับชื่อโมเดลของ Arena ไม่ได้ตรงกันเสมอไป การจัดอันดับจึงใช้
การจับคู่แบบยืดหยุ่น (`findMatchingIntelligence` ใน `src/lib/freeProviderRankings.ts`):

1. จับคู่แบบตรงทุกตัวอักษรกับรหัสโมเดลที่ผ่านการปรับให้เป็นมาตรฐานแล้ว
2. จับคู่หลังจากตัด suffix เวอร์ชันที่ต่อท้ายออก (เช่น `kimi-k2.6` → `kimi-k2`)
3. จับคู่แบบ prefix (ชื่อโมเดลใน leaderboard เป็น prefix ของรหัสใน registry)

ในฝั่งการซิงก์ prefix ของผู้ผลิตที่รู้จัก (`anthropic/`, `openai/`, `google/`, …) จะถูก
ตัดออก และมี alias map ขนาดเล็กที่ขยายชื่อมาตรฐานออกเป็นรูปแบบต่าง ๆ ที่ OmniRoute ใช้
ภายใน เพื่อให้ค้นหาโมเดลเจอได้ไม่ว่าจะใช้ชื่อใด

### วิธีจัดอันดับ provider

สำหรับ provider ฟรีแต่ละราย เอนจินจะให้คะแนนทุกโมเดลในแคตตาล็อกของมัน จากนั้น:

- **Top Model** = โมเดลที่มีคะแนนสูงสุดของ provider นั้น
- **Avg Score** = คะแนนเฉลี่ยของโมเดลทั้งหมดที่ได้รับการให้คะแนนของ provider นั้น
- **Models** = จำนวนโมเดลของ provider ที่มีคะแนนจาก Arena

provider จะถูกเรียงลำดับโดยใช้ **คะแนนของโมเดลอันดับสูงสุด** เป็นอันดับแรก แล้วจึงเรียงตามคะแนนเฉลี่ย วิธีนี้ให้รางวัลกับ
provider ที่มีโมเดลฟรีที่แข็งแกร่งอย่างน้อยหนึ่งตัว

## การใช้ข้อมูลนี้เพื่อเลือกผู้ให้บริการฟรี

1. **เลือกหมวดหมู่ที่เหมาะสม** ใช้ตัวกรอง **Coding** สำหรับเวิร์กโหลดแบบเอเจนต์/งานเขียนโค้ด หรือ
   คงไว้ที่ **All Categories** / **Default** สำหรับการแชททั่วไป ผู้ให้บริการรายเดียวกันอาจ
   มีอันดับแตกต่างกันในแต่ละหมวดหมู่ เนื่องจากโมเดลอันดับสูงสุดของผู้ให้บริการจะแตกต่างกันไปตามแต่ละลีดเดอร์บอร์ด
2. **เลือกผู้ให้บริการบนโพเดียมสำหรับการตั้งค่าแบบครั้งเดียว** หากคุณต้องการเชื่อมต่อผู้ให้บริการฟรี
   เพียงหนึ่งหรือสองราย ให้เริ่มจากรายที่มีอันดับสูงสุดในหมวดหมู่ของคุณ
3. **ตรวจสอบป้าย Type** ผู้ให้บริการ `NOAUTH` เชื่อมต่อได้รวดเร็วที่สุด (ไม่ต้องใช้
   ข้อมูลประจำตัว) แพ็กเกจฟรีแบบ `OAUTH` / `APIKEY` ต้องสมัครใช้งานอย่างรวดเร็ว แต่มักเปิดให้ใช้
   โมเดลที่มีประสิทธิภาพสูงกว่า ดูขั้นตอนการเชื่อมต่อได้ที่ [คู่มือแพ็กเกจฟรี](../getting-started/FREE-TIERS-GUIDE.md)
4. **เชื่อมต่อหลายรายแล้วให้ Auto-Combo ตัดสินใจ** ข้อมูล Arena ELO ชุดเดียวกับที่ขับเคลื่อน
   หน้านี้ยังถูกนำไปใช้เป็น **ปัจจัยความเหมาะสมกับงาน** ของเอนจินให้คะแนน Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`, ลำดับการพิจารณา
   `user_override → arena_elo → models_dev_tier → static table`) ดังนั้น หลังจากเชื่อมต่อ
   ผู้ให้บริการฟรีอันดับต้น ๆ แล้ว การกำหนดเส้นทางด้วย `model: "auto"` (เช่น `auto/coding`) จะ
   เลือกใช้โมเดลฟรีที่มีคุณภาพสูงกว่าสำหรับแต่ละคำขอโดยอัตโนมัติ ดูรายละเอียดการให้คะแนนครบทั้ง 16 ปัจจัยได้ที่
   [Auto-Combo](../routing/AUTO-COMBO.md)
