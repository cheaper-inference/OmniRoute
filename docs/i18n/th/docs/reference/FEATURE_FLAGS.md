## Feature Flags คืออะไร

Feature flag คือตัวสลับที่มีชื่อ (ชนิด boolean หรือ enum) ซึ่งสามารถเปลี่ยนค่าได้ใน
ขณะรันไทม์และบันทึกถาวรไว้ในฐานข้อมูล โดยไม่จำเป็นต้องปรับใช้โปรเซสใหม่ แต่ละ
แฟล็กอธิบายด้วย `FeatureFlagDefinition` ซึ่งประกอบด้วย `key`, `label`,
`description`, `category`, `defaultValue`, `type` และคำใบ้ `requiresRestart`

### ลำดับการกำหนดค่า

**ค่าที่มีผลจริง** ของแฟล็กจะถูกกำหนดโดย
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ตามลำดับ
ความสำคัญต่อไปนี้ (ลำดับที่สูงกว่าจะมีผล):

1. **ค่าที่กำหนดทับใน DB** — ค่าที่จัดเก็บไว้ในตาราง `key_value` ภายใต้
   namespace `feature_flags` (ตั้งค่าผ่านแดชบอร์ดหรือ REST API)
2. **ตัวแปรสภาพแวดล้อม** — `process.env[<KEY>]` หากมีการตั้งค่าและค่าไม่ว่างเปล่า
3. **ค่าเริ่มต้นจากข้อกำหนด** — `defaultValue` จาก `featureFlagDefinitions.ts`

แฟล็กชนิด boolean จะถือว่า **เปิดใช้งาน** เมื่อค่าที่มีผลจริงคือ `"true"`,
`"1"` หรือ `"yes"` (ดู `isFeatureFlagEnabled()`)

> [!NOTE]
> แฟล็กส่วนใหญ่ยังมีตัวแปรสภาพแวดล้อมที่ตรงกันและใช้ **ชื่อเดียวกัน**
> ซึ่งจัดทำเอกสารไว้ใน [`ENVIRONMENT.md`](./ENVIRONMENT.md) ค่าที่กำหนดทับใน DB
> ของแฟล็กจะมีลำดับความสำคัญเหนือกว่าตัวแปรสภาพแวดล้อมดังกล่าว แฟล็กที่มี
> `requiresRestart: true` จะถูกบันทึกถาวรทันที แต่จะถูกอ่านใหม่เฉพาะตอนเริ่มต้น
> โปรเซสเท่านั้น การสลับแฟล็กดังกล่าวจะแสดงแบนเนอร์ **"รีสตาร์ตเซิร์ฟเวอร์"** ในแดชบอร์ด

## แคตตาล็อกธง

126 ธงใน 6 หมวดหมู่** ค่าเริ่มต้น** คือคำจำกัดความเริ่มต้น — ซึ่งเป็นค่าที่ใช้เมื่อไม่มีการแทนที่ DB หรือตัวแปรสภาพแวดล้อม

> `INPUT_SANITIZER_BLOCK_THRESHOLD` และนามแฝงดั้งเดิม `INJECTION_GUARD_BLOCK_THRESHOLD` ปรับโหมด `block` ของ `INJECTION_GUARD_MODE` แต่เป็นตัวแปรสภาพแวดล้อมธรรมดาที่อ่านโดย [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts) ไม่ใช่แฟล็กคุณลักษณะ: ไม่มีการแทนที่ DB และไม่มีการสลับแดชบอร์ด ดู [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication).

> [!NOTE]
> คอลัมน์ `Restart` ทำเครื่องหมายแฟล็กด้วย `requiresRestart: true` — ค่าจะคงอยู่ทันที แต่จะมีผลหลังจากกระบวนการโหลดซ้ำเท่านั้น แฟล็ก Enum ปฏิเสธค่าใด ๆ ที่อยู่นอกชุดที่อนุญาต (ฝั่งเซิร์ฟเวอร์ที่ได้รับการตรวจสอบทั้งใน `setFeatureFlagOverride()` และตัวจัดการ REST `PUT` )

## การสลับการตั้งค่าสถานะ

### แดชบอร์ด

นำทางไปยัง** แดชบอร์ด การตั้งค่า → การตั้งค่าสถานะ →** (`/dashboard/settings/feature-flags`). ตาราง (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) รองรับ:

- **ค้นหา** ตามคีย์หรือคำอธิบาย และ** กรอง** ตามหมวดหมู่ (บวกกับสารสังเคราะห์** ต้องรีสตาร์ท** ดู).
- ก** สลับ** สำหรับแฟล็กบูลีนและ** แบบเลื่อนลง** สำหรับแฟล็ก enum (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)
- ก** ป้ายแหล่งที่มา** ต่อแฟล็ก — `DB`, `ENV` หรือ `DEF` — แสดงว่าค่าที่มีประสิทธิผลมาจากไหน
- ก** รีเซ็ต** ปุ่ม (แสดงเฉพาะสำหรับแฟล็ก `DB` -sourced ) เพื่อยกเลิกการแทนที่ และ a** รีเซ็ตการแทนที่ทั้งหมด** ปุ่มที่ด้านล่าง
- ก** รีสตาร์ทเซิร์ฟเวอร์** แบนเนอร์เมื่อธง `requiresRestart` มีการเปลี่ยนแปลง

### REST API

การดำเนินการทั้งหมดต้องผ่านเส้นทางเดียว: [`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts) ทุกวิธีต้องมีเซสชันแดชบอร์ดที่ได้รับการรับรองความถูกต้อง (เป็นอย่างอื่น `401` )

เมื่อปิดใช้งานการเข้าสู่ระบบ (`requireLogin=false`) เส้นทางจะเปิดขึ้น ยกเว้นแฟล็กที่ได้รับการป้องกัน: ทุกแฟล็กในหมวดความปลอดภัยบวก `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`, `OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS`, `MITM_DISABLE_TLS_VERIFY`, `OMNIROUTE_MCP_ENFORCE_SCOPES` และ `SKILLS_SANDBOX_NETWORK_ENABLED` (`isProtectedFeatureFlag()` ใน `protectedFeatureFlags.ts`) `PUT` บนหนึ่งในนั้น และ `DELETE` ในขณะที่หนึ่งในนั้นมีการแทนที่ DB ยังคงต้องการเซสชันแดชบอร์ด คีย์ `manage` -scope API โทเค็นการเข้าถึง `oma_` ที่มีขอบเขตการเขียนหรือสูงกว่า หรือโทเค็น CLI หรือโทเค็นบริการภายในที่ส่งจากลูปแบ็ค ชุดนั้นกว้างกว่าเมื่อเปิดการเข้าสู่ระบบ โดยที่เส้นทางยอมรับเฉพาะเซสชันหรือคีย์ `manage` -scope

#### `GET /api/settings/feature-flags`

ส่งกลับทุกแฟล็กพร้อมค่าที่มีประสิทธิผล แหล่งที่มา และข้อมูลสรุป

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 126 flags
  ],
  "summary": {
    "total": 126,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ตั้งค่าหรือลบการแทนที่เดียว ร่างกาย: `{ key: string; value?: string }`. การละเว้น `value` จะลบการแทนที่ (การเรียกคืน env / ค่าเริ่มต้น)

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

การตอบสนองสะท้อนถึง `effectiveValue`/`source` ใหม่ , `previousValue`/ `previousSource` และ `requiresRestart` คีย์ที่ไม่รู้จักและค่าแจงนับนอกช่วงจะถูกปฏิเสธด้วย `400`

#### `DELETE /api/settings/feature-flags`

เคลียร์** ทั้งหมด** DB จะแทนที่พร้อมกัน โดยกู้คืนทุกแฟล็กให้เป็น env / ค่าเริ่มต้น ส่งกลับ `{ cleared: <count>, message: "..." }`

> [!NOTE]
> แฟล็กที่มี `requiresRestart: true` จะมีผลหลังจากโหลดกระบวนการใหม่เท่านั้น โฟลว์การรีสตาร์ทของแดชบอร์ดจะเรียก `POST /api/restart` จากนั้นจึงสำรวจ `GET /api/health/ping` จนกว่าเซิร์ฟเวอร์จะสำรองข้อมูล

## ทางเลือกสำรองฉุกเฉินเมื่องบประมาณหมด

`OMNIROUTE_EMERGENCY_FALLBACK` (หมวดหมู่ `runtime`, ค่าเริ่มต้น `true`) ใช้ควบคุม
เส้นทางทางเลือกสำรองแบบไม่มีค่าใช้จ่ายในกรณีฉุกเฉินใน
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
เมื่อเปิดใช้งาน คำขอที่ใช้งบประมาณจนหมดจะถูกส่งต่อไปยังผู้ให้บริการ/โมเดลทางเลือกสำรอง
แบบไม่มีค่าใช้จ่าย แทนที่จะล้มเหลวทันที ให้ตั้งค่าเป็น `false` (หรือ `0`) — ผ่านสวิตช์
บนแดชบอร์ด การแทนที่ค่าใน DB หรือตัวแปรสภาพแวดล้อม
`OMNIROUTE_EMERGENCY_FALLBACK` — เพื่อปิดใช้งานลักษณะการทำงานนี้ และปล่อยให้คำขอ
ที่ใช้งบประมาณจนหมดล้มเหลว (แสดงเป็นสวิตช์บนแดชบอร์ดใน PR #3741 / #3752)

การตอบกลับที่ให้บริการผ่านทางเลือกสำรองนี้จะมี
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` เพื่อให้
ไคลเอนต์ทราบได้ว่าคำขอถูกเปลี่ยนเส้นทาง โดยไม่ต้องเปรียบเทียบความแตกต่างระหว่าง
`X-OmniRoute-Provider` กับคำขอของตน ส่วนการตอบกลับอื่นทั้งหมดจะไม่มีส่วนหัวนี้
