> **สถานะ:** แดชบอร์ดถูกสร้างขึ้นบน **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`) ที่รวมอยู่ในที่เก็บนี้เป็นพื้นที่ทำงาน `packages/ui-kit` (`@omniroute/ui-kit`; สแน็ปช็อตอัปสตรีมถูกปักหมุดใน `packages/ui-kit/UPSTREAM.md` และป้องกันโดย `npm run check:ui-kit-snapshot`) แสงเป็นธีมที่เป็นที่ยอมรับ การตั้งค่าเริ่มต้นคือ `system` จานสีเริ่มต้นคือชุดอุปกรณ์**Editions** ลักษณะ (กระดาษโทนกลางโทนอุ่น และสำเนียงทองแดง `#e5ac82`, `packages/ui-kit/src/ci-editions.css`); การตั้งค่า → ลักษณะที่ปรากฏ → จานสีเสนอ **Classic** โทเค็นฐานของชุดอุปกรณ์พร้อมสำเนียงมะนาว Switzer เป็นตระกูลหลักสำหรับ UI และข้อความที่แสดง (`--ci-font-ui`; `--ci-font-display` และ `--ci-font-mono` แก้ไขได้) ซึ่งโฮสต์เองโดยชุดอุปกรณ์เอง (`packages/ui-kit/src/ci-fonts.css` นำเข้าโดย `ci-tokens.css`) ทุกไอคอนเป็นสัญลักษณ์ Lucide
>
> Inter ใช้เพื่อแสดงรูปร่างอักขระแต่ละตัวที่ไม่มีอยู่ใน Switzer; `--font-mono` แมปกับระบบ monospace stack `--ci-font-code`
>
> `src/app/globals.css` เลือกแบบอักษรทางเลือกต่อสัญลักษณ์เมื่อ `Switzer` ไม่มีสัญลักษณ์: `Inter` สำหรับซีริลลิก กรีกและเวียดนาม และ `Vazirmatn` สำหรับสคริปต์ภาษาอาหรับภายใต้ `html[dir="rtl"]` เท่านั้น

`src/app/globals.css`:

```css
:root,
.ci-theme {
  --ci-font-ui:
    "Switzer", "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif;
  --ci-font-code: ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace;
  --font-mono: var(--ci-font-code);
}
```

## 1. ที่ซึ่งสิ่งต่างๆ อาศัยอยู่

- **ชุด.** `packages/ui-kit/src` เป็นสำเนาแบบไบต์ต่อไบต์ของอัปสตรีม `src/` ที่คอมมิตที่ปักหมุดไว้ใน `packages/ui-kit/UPSTREAM.md` (ซึ่งบันทึกการอนุญาตใบอนุญาตด้วย) `PATCHES.md` แสดงรายการแพทช์ในเครื่อง มันถูกใช้เป็นแหล่งที่มาโดยไม่มีบิลด์: `next.config.mjs` ทรานสไพล์มัน และ `tsconfig.json` จะแมป `@omniroute/ui-kit` → `packages/ui-kit/src` และ `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` (`vitest.config.ts` และ `vitest.mcp.config.ts` มีนามแฝงเดียวกัน) นำเข้าส่วนประกอบ kit ตามเส้นทางย่อย (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) ห้ามผ่านบาร์เรล `@omniroute/ui-kit` : บาร์เรลจะดึงส่วนประกอบทั้งหมด (รวมถึงตัวเลือกวันที่) ลงสู่ผู้นำเข้าแต่ละราย kit stylesheet เข้าสู่ `src/app/globals.css` (`@import "../../packages/ui-kit/src/ci-styles.css"` แผ่นงานที่สมบูรณ์: แกน `ci-ui.css` บวกทุกกลุ่มรูปแบบ)
- **โทเค็น** `packages/ui-kit/src/ci-tokens.css` ประกาศโทเค็น `--ci-*` ; `src/app/globals.css` เชื่อมโยงพวกเขากับชื่อ OmniRoute ดั้งเดิม (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) ดังนั้น `var(--color-*)` ที่มีอยู่จะอ่านและยูทิลิตี้ Tailwind ยังคงทำงานต่อไป รหัสใหม่ใช้ยูทิลิตี้ Tailwind (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) หรือคลาส kit — ไม่เคยมีค่าฐานสิบหก (`tests/unit/design-kit-bridge.test.ts` บังคับใช้บริดจ์) `text-primary` แก้ไขเป็น `--color-primary-ink` ถึง `--text-color-primary` ดังนั้นข้อความหลักยังคงสามารถอ่านได้ในขณะที่ `bg-primary`/`border-primary` คงพื้นผิวสำเนียงไว้: ภายใต้ Editions มันคือ `--ci-color-accent-active` ของชุดอุปกรณ์ (ทองแดงลึก `#99562f` ในแสง, สำเนียงทองแดงในที่มืด); ภายใต้ Classic, lime-800 ในแสงสว่าง และสำเนียงมะนาวในความมืด ชุดแผนภูมิใช้ `--color-chart-1` … `--color-chart-8` โดยแต่ละชุดมี `--color-chart-N-ink` แบบปลอดภัยสำหรับข้อความและสีชิป `--color-chart-N-subtle` แบบทึบ ซึ่งกำหนดไว้ในลำดับชุดชุด (`ciChartSeriesOrder`)
- **ธีมส์** `<html className="ci-theme">` (`src/app/layout.tsx`) เลือกเอกสารให้เป็นธีมชุด การตั้งค่าคือ `light`, `dark` หรือ `system` (`THEME_CONFIG.defaultTheme = "system"` ใน `src/shared/constants/appConfig.ts`; `system` ตาม `prefers-color-scheme`) `applyTheme()` ใน `src/store/themeStore.ts` (มิเรอร์โดย `THEME_BOOT_SCRIPT`, อินไลน์ใน `src/app/layout.tsx` ซึ่งทำงานก่อนไฮเดรชั่น) ตั้งค่า `data-theme="dark"|"light"` และสลับคลาส `.dark` บน `<html>` ด้วยกัน ชุดโทเค็นสีเข้มของชุดถูกคีย์ไว้ที่ `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`); การแทนที่ความมืดของ OmniRoute(บล็อก `.dark` ใน `globals.css`) และคีย์ยูทิลิตี้ Tailwind `dark:` แบบเดิมบนคลาส `.dark` ไม่มีการตั้งค่าสีที่ถูกเน้นล่วงหน้า: การเน้นจะมาจากชุดอุปกรณ์เสมอ และค่าที่ตั้งไว้ล่วงหน้าที่คงอยู่จากรุ่นเก่าจะหายไปเมื่อโหลดร้านค้า
- **จานสี** สอง ทั้งคู่จากชุด (`src/shared/constants/appearancePalette.ts`): `editions` ค่าเริ่มต้น และ `classic` Editions เป็นแอตทริบิวต์ `data-ci-appearance="editions"` ของชุดบน `<html>` ซึ่ง `ci-editions.css` (นำเข้าโดย `ci-ui.css`) รวมกับ `data-theme`; Classic คือการไม่มีแอตทริบิวต์ เซิร์ฟเวอร์โครงร่างรูทจะเรนเดอร์แอตทริบิวต์ ดังนั้นผู้เยี่ยมชมที่ไม่มีสิ่งใดเก็บไว้ (หรือไม่มี JS) จะได้รับ Editions บนแดชบอร์ด — ทุกพื้นผิว การเข้าสู่ระบบ `/status` หน้าแสดงข้อผิดพลาด `/docs` และ PWA ตัวเลือกยังคงอยู่ถัดจากธีมในร้านค้า `theme` เดียวกัน (`palette`, `setPalette()`, `applyPalette()` ใน `src/store/themeStore.ts`) และนำไปใช้ก่อนทาสีโดย `THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`, อินไลน์ใน `<head>` ของโครงร่าง) ซึ่งจะลบแอ็ตทริบิวต์เฉพาะเมื่อพาเล็ตที่เก็บไว้เป็น `"classic"`; `src/app/global-error.tsx` นอกโครงร่างรูท นำไปใช้จากร้านค้าเดียวกัน อย่าวาง `data-ci-appearance` บนองค์ประกอบอื่นใด: ชุดจะจับคู่กับ `html:root:has([data-ci-appearance="editions"])` ดังนั้นผู้สืบทอดคนหนึ่งจะเปลี่ยนทั้งเอกสาร ตัวแปร Editions `data-ci-editions-variant="landing"` ใช้สำหรับเพจทางการตลาด ไม่ใช่แดชบอร์ด เบราว์เซอร์ chrome: เซิร์ฟเวอร์แสดงผลค่าเริ่มต้น Editions ใน `viewport.themeColor` (หนึ่งแท็กต่อ `prefers-color-scheme`) และรายการเว็บ — `PWA_THEME_COLORS` ใน `src/shared/constants/pwaThemeColors.ts` หนึ่งมิเรอร์ของ Editions `--ci-color-background` (`#f3f1e9` / `#11120f`) ปักหมุดไว้ที่ `ci-editions.css` โดย `tests/unit/pwa-theme-colors.test.ts` จากนั้น `<meta name="theme-color">` แบบสดจะติดตามจานสีและโหมดที่เก็บไว้: `THEME_BOOT_SCRIPT` เขียนแท็กใหม่ก่อนที่จะทาสีและการดำเนินการของที่เก็บธีมจะดำเนินการกับการเปลี่ยนแปลงทุกครั้ง (`resolveThemeColor()` / `applyThemeColor()` ใน `src/shared/utils/themeColorMeta.ts` โดยที่ `CLASSIC_PAGE_BACKGROUND` อ่านจากชุด `ciTokens`) ธีม light/dark ที่ชัดเจนจะตั้งค่าทุกแท็กเป็นโหมดนั้น `system` เก็บหนึ่งสีต่อโครงร่าง ไฟล์ Manifest ยังคงอยู่ Editions: จะถูกดึงข้อมูลหนึ่งครั้งต่อการติดตั้ง โดยไม่มีค่ากำหนด โมนาโกอ่านสีของมันจากโพรบ (`monacoKitTheme.ts`); ภายใต้ Editions การอ่านโพรบจะพลิกรูท `data-theme` สำหรับการส่งผ่านแบบซิงโครนัสหนึ่งครั้ง เนื่องจากชุดคิทจะแก้ไข Editions light/dark จากรูท
- **ส่วนประกอบ (อะแดปเตอร์)** `src/shared/components/index.tsx` เก็บองค์ประกอบ OmniRoute API (ชื่อเดียวกัน การส่งออกเริ่มต้นและอุปกรณ์ประกอบฉาก) และพื้นฐานด้านหลังเป็นอะแดปเตอร์เหนือชุด: รูปแบบ (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`) ภาพซ้อนทับและข้อเสนอแนะ (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`) โครงสร้าง (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) และตาราง (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`) อะแดปเตอร์นำเข้าส่วนประกอบ kit โดยพาธย่อยและแมปอุปกรณ์ประกอบฉากดั้งเดิมลงไป — เช่น `Button variant="primary"` คือปุ่ม kit `default` (`--ci-button-primary-*`: พื้นผิวผกผันในแสง การเน้นด้วยหมึก `--ci-color-accent-foreground` ในที่มืด) `danger` คือ `destructive` และ `warning` คือปุ่ม kit `warning` ตัวแปรสถานะ `Badge` คือชุดโทนเสียง และ `Select` ที่มีลูก `<option>` แสดงผลชุด `NativeSelect` `tests/unit/ui/adapters/*.test.tsx` ปักหมุดอะแดปเตอร์แต่ละตัว
- **เปลือก.** `src/app/(dashboard)/layout.tsx` แสดงผล `DashboardLayout` ซึ่งแสดงผล `src/shared/components/layouts/DashboardShell.tsx`: ชุด `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`) พร้อมด้วยตรรกะการนำทางของ OmniRoute ใน `src/shared/components/Sidebar.tsx` ลิงก์ "ข้ามไปที่เนื้อหา" ไปยัง `#main-content` เป็นองค์ประกอบแรกที่สามารถโฟกัสได้ `src/shared/components/Header.tsx` เก็บ kit `SidebarTrigger` (ตัวสลับแถบด้านข้างเพียงตัวเดียวของเชลล์), Keak `ProductSwitcher` และตัวเปิด command-palette; มันแสดงชื่อเส้นทางเฉพาะในขณะที่ไม่มีการติดตั้งชุด `PageHeader` (`.ci-page-header`) ภายใน `#main-content` ดังนั้นหน้าเว็บที่มี `PageHeader` ของตัวเองจะมี `h1` เดียว `src/shared/components/CommandPalette.tsx` เป็นชุด `Dialog`

## 2. กฎเกณฑ์

1. โทเค็น ไม่ใช่ตัวอักษร ข้อยกเว้นที่เก็บไว้ตามวัตถุประสงค์: เทอร์มินัลคอนโซลที่มืดตลอดเวลาและ `STATUS_HEX` (`src/shared/constants/statusColors.ts`) มิเรอร์เลขฐานสิบหกที่แก้ไขแล้วของชุดสถานะชุดสำหรับผู้โทรที่ต้องการเลขฐานสิบหกตามตัวอักษร จานสีหมวดหมู่นั้นไม่มีข้อยกเว้นอีกต่อไป: โดยจะอยู่บนโทเค็นแผนภูมิแปดรายการของชุด (`--color-chart-1..8` บวก `-ink`/`-subtle`) ตามลำดับชุดชุด ผ่าน `src/shared/utils/categoricalPalette.ts` และสำหรับกลยุทธ์การกำหนดเส้นทาง `src/app/(dashboard)/dashboard/combos/strategyPalette.ts`; ReactFlow edges และ canvas orchestration จะอ่านตัวแปร `--orch-status-*` ที่รับรู้ธีม (`src/shared/components/flow/edgeStyles.ts`)
2. ไม่ต้องแพตช์ `packages/ui-kit/src` ด้วยมือ: ซิงค์กับ `scripts/dev/sync-ui-kit.sh <commit>`; pre-commit gate `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) ล้มเหลวในไบต์ใด ๆ ที่แตกต่างจากการคอมมิตอัปสตรีมที่ปักหมุดไว้ (จะข้ามโดยมีคำเตือนเมื่ออัพสตรีมโคลน `UI_KIT_CLONE` หรือ `_references/cheaper-inference-ui-kit` หายไป) เมื่อชุดอุปกรณ์ขาดหายไป ให้แก้ไขโดยใช้อะแดปเตอร์หรือหน้าจอแล้วถามอัปสตรีม
3. ค่าเริ่มต้นของข้อความ Kit คือภาษาอังกฤษ (`label = "Loading"`, `loadingLabel = "Loading table"`…) — ส่งสตริงที่แปลจาก `useTranslations(...)` เมื่อใดก็ตามที่ส่วนประกอบ kit แสดงผลข้อความ
4. ยูทิลิตี้Tailwind ชนะเหนือคลาสส่วนประกอบ kit (ชุดประกาศ `@layer theme, base, components, utilities` และกฎของมันอยู่ใน `components`) — ใช้ยูทิลิตี้สำหรับการเว้นวรรคและเค้าโครง ไม่ใช่เพื่อเปลี่ยนสีส่วนประกอบของชุดใหม่
5. ส่วนหัว: `.ci-heading` สำหรับชื่อหน้าและส่วน; `.ci-dashboard-display` สำหรับข้อความที่แสดงขนาดใหญ่และกระจัดกระจาย เช่น รหัสสถานะหน้าข้อผิดพลาด ใช้สวิตเซอร์ทั้งคู่
6. `tests/unit/dashboard-kit-sweep.test.ts` ป้องกันการนำชุดอุปกรณ์ไปใช้: ไม่มีช่วงการมัดวัสดุภายใต้ `src/app` หรือ `src/shared/components`; ในแผนผังแดชบอร์ด (`src/app/(dashboard)` และ `src/shared/components`) ไม่มีดิบ `<select>`, `<textarea>` หรือ `<table>` และไม่มี `role="dialog"` ที่ทำด้วยมือนอกข้อยกเว้นที่ระบุไว้ (สาขาดั้งเดิมของอะแดปเตอร์ `Select`, `RequestLoggerDetail`) `<button>` หรือ `<input>` ดิบทุกรายการจำเป็นต้องมีความคิดเห็นที่มี `kit-exception:` (พร้อมเหตุผล) ซึ่งลงท้ายด้วยไม่เกิน 3 บรรทัดด้านบน จานสีและตัวแปร `dark:` เฉพาะในไฟล์ในรายการทดสอบเท่านั้น

## 4. การเพิ่มหรือเปลี่ยนแปลง adapter

1. รักษา public API ของ `src/shared/components/index.tsx` ไว้: ชื่อ export เหมือนเดิม, default exports และ props ที่รับ โดยแมป legacy props ไปยัง kit ภายใน adapter (ดู `Button.tsx`: `VARIANT_TO_KIT`, `SIZE_TO_KIT`)
2. import kit ด้วย subpath (`@omniroute/ui-kit/<component>`)
3. workaround สำหรับช่องว่างของ kit ให้อยู่ใน adapter (หรือใน `globals.css` `@layer components` เมื่อการแก้ไขเป็น style) ห้ามอยู่ใน `packages/ui-kit/src`
4. เพิ่มหรืออัปเดต `tests/unit/ui/adapters/<name>.test.tsx` สำหรับ adapter ที่มี caller จำนวนมาก ให้เปรียบเทียบ markup ที่ render ก่อนและหลังการเปลี่ยนแปลง — การเปลี่ยน padding หรือ wrapper จะแพร่ไปทุกหน้าจอ

## 5. การอัปเดต kit

`npm run check:ui-kit-upstream` เปรียบเทียบเวอร์ชันที่ปักหมุดใน `packages/ui-kit/UPSTREAM.md` กับแท็ก `v*` ใหม่ล่าสุดของ upstream repo และพิมพ์คำสั่ง sync เมื่อรีลีสหมด

เวิร์กโฟลว์ `UI Kit upstream watch` รายวัน (`.github/workflows/ui-kit-upstream-watch.yml`) รันการตรวจสอบเดียวกัน ในขณะที่พินอยู่ด้านหลัง `scripts/ci/ui-kit-sync-pr.sh` จะเปิดการซิงค์ PR ไว้หนึ่งรายการเทียบกับสาขา `release/vX.Y.Z` สูงสุดบนสาขากลิ้ง `chore/ui-kit-sync-latest` มันไม่มีวันรวมเข้าด้วยกัน: ทุก kit release ยังคงต้องมีการตรวจสอบด้วยภาพบน VPS ในเครื่อง สาขาจะถูกสร้างขึ้นใหม่เมื่อมีการออกรุ่นใหม่และปล่อยทิ้งไว้ตามลำพัง PR แบบเปิดที่มีการคอมมิตที่พุชด้วยมือจะไม่ถูกเขียนทับ และ PR สำหรับเวอร์ชันที่ผู้ดูแลปิดและยังไม่ได้ผสานจะยังคงปิดอยู่จนกว่าจะมีเวอร์ชันใหม่

เมื่อไม่สามารถเปิด PR ได้ (การเผยแพร่เป้าหมายถูกหยุดนิ่ง PR มีการคอมมิตการพุชด้วยมือ PR ถูกปิด หรือไม่ได้ตั้งค่าโทเค็น PR ) เวิร์กโฟลว์จะเปิดปัญหาการติดตามหนึ่งรายการไว้ซึ่งระบุสาเหตุ

เวิร์กโฟลว์ใช้ข้อมูลลับสองประการ:

- `secrets.UI_KIT_READ_TOKEN`: โทเค็นแบบอ่านอย่างเดียวสำหรับ repo อัพสตรีมส่วนตัว เมื่อการตรวจสอบอัปสตรีมไม่สามารถอ่านข้อมูลได้ (ไม่มีโทเค็น โทเค็นที่หยุดทำงาน หรือไม่สามารถเข้าถึง GitHub ) ระบบจะรายงาน `unknown` และออกด้วยโค้ด `0` เวิร์กโฟลว์เขียนคำเตือนและพยายามเปิดประเด็นการติดตามที่แยกจากกันไว้ การรันที่สำเร็จในภายหลังจะปิดลงหลังจากการเข้าถึงกลับมา ความล้มเหลวของปัญหา GitHub API ทำให้งานล้มเหลว
- `secrets.UI_KIT_SYNC_PR_TOKEN`: โทเค็นแบบละเอียดบนที่เก็บนี้พร้อมการเข้าถึงการเขียนคำขอ Content และ Pull เวิร์กโฟลว์นี้เปิดหรืออัปเดต PRs การซิงโครไนซ์เมื่อมีการกำหนดค่าโทเค็นเฉพาะเท่านั้น หากไม่มีสิ่งนี้ เวิร์กโฟลว์จะพุชสาขาและรายงานว่าไม่มีการเปิด PR

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` คัดลอกอัปสตรีม `src/` ที่คอมมิตนั้น (`latest` = แท็ก `v*` ใหม่ล่าสุด) ลงใน `packages/ui-kit/src` ใช้การแปลงที่อนุญาตเพียงครั้งเดียว (โดยจะปล่อยส่วนต่อท้าย `.js` จากการนำเข้าแบบสัมพันธ์) และตั้งค่าเวอร์ชันพื้นที่ทำงานเป็น `packages/ui-kit/package.json` และ `package-lock.json` เป็นเวอร์ชันอัปสตรีม จากนั้น: ตรวจสอบ `git diff packages/ui-kit` ตรวจดูหน้าจอของผู้ให้บริการ การตั้งค่า คอมโบ การใช้งาน และจุดสิ้นสุดในทั้งสองธีม รัน `npm run check:ui-kit-snapshot` และ `npm run test:vitest:ui` และเปิด PR ด้วยบันทึกการเปลี่ยนแปลงอัปสตรีม

## 6. แผนภาพ README

แผนภาพสิบสองภาพที่ฝังใน `README.md` ระดับราก (`docs/diagrams/*.svg`) นำชุด UI มาใช้กับภาพนิ่ง โดยสร้างจากโปรแกรม ไม่ได้วาดด้วยมือ: มีไฟล์ตัวสร้าง 13 ไฟล์ใน `scripts/docs/gen-readme-*.mjs` (สิบสองแผนภาพและตัวควบคุม `gen-readme-diagrams.mjs`) และการทดสอบความล้าสมัย 12 รายการใน `tests/unit/docs/readme-*-svg.test.ts` หนึ่งรายการต่อแผนภาพ แต่ละการทดสอบเปรียบเทียบไฟล์ที่ commit แล้วกับผลลัพธ์ของตัวสร้างแบบไบต์ต่อไบต์ (งาน `test-unit`).

- **โทเค็น** `scripts/docs/readme-diagram-theme.mjs` คัดลอกพาเล็ต Editions (รูปลักษณ์เริ่มต้น) จาก `packages/ui-kit/src/ci-editions.css` (ปักหมุดไว้กับไฟล์นั้นโดย `tests/unit/docs/readme-diagram-theme.test.ts` ซึ่งจะตรวจสอบ WCAG AA สำหรับสีข้อความทุกสีบนทุกพื้นผิวในทั้งสองโครงร่าง ข้อยกเว้นประการหนึ่งคือ light `warn` คือคำเตือน kit เข้มขึ้น 10 % เนื่องจากค่า kit คือ 4.46:1 บนพื้นที่ทำงาน) และกำหนดบทบาทข้อความในระดับประเภทของ kit (`ci-tokens.css`): สวิตเซอร์ที่น้ำหนักของชุด (400/500/600, แสดงที่ 500) และติดตามทุกอย่าง ยกเว้นบทบาทของโค้ด (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`) ซึ่งเป็น IBM Plex Mono และมีไว้สำหรับคำสั่ง URLs ตัวระบุ และหน้าจอเทอร์มินัลเท่านั้น ค่าแสงจะอยู่ที่ `:root` ค่าสีเข้มด้านหลัง `prefers-color-scheme: dark` ภายในไฟล์ ดังนั้นแต่ละภาพจึงเป็นไปตามโครงร่างของผู้ดูบน GitHub
- **แบบอักษร** GitHub Markdown ไม่มี CSS และพร็อกซี camo จะบล็อกการดึงข้อมูลภายนอกทุกครั้ง ดังนั้นประเภท kit จึงต้องเคลื่อนที่ภายในไฟล์ `scripts/docs/readme-outline.mjs` ซึ่งเป็นขั้นตอนสุดท้ายของตัวสร้างทุกตัว กำหนดรูปร่างบทบาทของ Switzer ด้วย HarfBuzz และวาดเป็นโครงร่างเวกเตอร์ (`<defs>` paths และ `<use>`) โดยมีลูกศรและสัญลักษณ์ทางเรขาคณิตที่ Switzer ขาดไปในการวัดของตัวเอง โครงร่าง ไม่ใช้แบบอักษรฝังตัว: ใบอนุญาตของสวิสเซอร์แลนด์ (`packages/ui-kit/src/fonts/FFL.txt`) ห้ามไม่ให้มีการตั้งค่าย่อยและการแปลงรูปแบบโดยไม่ได้รับความยินยอมเป็นลายลักษณ์อักษร และอนุญาตให้วาดภาพเวกเตอร์ได้ ดังนั้น ห้ามแนะนำ Switzer `@font-face` หรือ `data:` URI อีกครั้ง แบบอักษรเดียวที่เหลืออยู่ในไฟล์คือชุดย่อย OFL IBM Plex Mono สำหรับสิ่งที่ยังคงเป็นข้อความโค้ดจริง (`scripts/docs/readme-fonts.mjs`) ที่สร้างขึ้นจากอักขระเหล่านั้น สัญลักษณ์ใดๆ ที่ไม่สามารถฝังการขว้างได้
- **สร้างใหม่** `npm run docs:readme-diagrams` เขียนใหม่ทั้งสิบสองตามลำดับ README และพิมพ์หนึ่งบรรทัดต่อไฟล์ด้วยขนาดของมัน เครื่องกำเนิดไฟฟ้าตัวเดียวยังทำงานด้วยตัวเอง (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` ต้องการ `node --import tsx/esm` เนื่องจากตัวเลขของมันมาจากตัวโหลดแค็ตตาล็อกสดใน `open-sse/config/freeModelCatalog.ts`; ผลลัพธ์ CI ของการเปลี่ยนแปลงแค็ตตาล็อกอยู่ใน `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict`) คอมมิตตัวสร้างและ SVG ร่วมกัน
- **หลักฐาน.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` เรนเดอร์ไฟล์ในการทดสอบภายในเครื่อง (แท็ก `<img>`, `Content-Security-Policy` แบบจำกัดและการตอบกลับ `image/svg+xml`) จับภาพโหมดสว่างและมืด แล้วรายงานคำขอฟอนต์ภายนอกที่หน้าเว็บส่งออกมา ซึ่งต้องเป็น 0.

- **งบประมาณ.** ต่ำกว่า 200 KB ต่อไฟล์ (การทดสอบความเก่าแต่ละครั้งยืนยัน) 500 KB เป็นฮาร์ดแคปสำหรับอิมเมจ README ใดๆ (กฎของเครื่องมือตรวจสอบ SVG studio)
- **ข้อความร่วมกัน ตัวเลขจาก gate.** ตัวสร้างแต่ละตัวจะมีสำเนาของไดอะแกรมเป็นค่าคงที่ `*_COPY` (หรือสร้างจากแค็ตตาล็อกสด) ซึ่งเป็นทั้งข้อความที่วาดและอินพุตของขั้นตอนการสรุป ตัวเลข Canonical อยู่ในโหนด `<text>` (มองไม่เห็นเมื่อระบุไว้ `fill-opacity:0`) อ่านโดย `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`); การทดสอบความเก่าของไดอะแกรมที่เกตอ่านยังรันเครื่องมือตรวจสอบความถูกต้องในไฟล์ที่สร้างขึ้น ดังนั้นตัวเลขที่เบี่ยงเบนไปจากโค้ดจึงล้มเหลว การทดสอบ — แก้ไขแหล่งที่มาที่เกตอ่าน ไม่ใช่ตัวเลขในตัวสร้าง
