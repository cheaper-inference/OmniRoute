`copilot-m365-web` (นามแฝง `m365copilot`) ส่งคำขอแชทในรูปแบบ OpenAI ผ่านเซสชัน Microsoft 365 Copilot ที่ได้รับการรับรองความถูกต้องที่ `m365.cloud.microsoft/chat` นี่เป็นการรวมระบบแบบเนทีฟอย่างไม่เป็นทางการ: ไม่จำเป็นต้องมีกระบวนการพร็อกซีหรือโลคัลโฮสต์อัปสตรีมแยกต่างหาก ผู้ให้บริการ ID นามแฝง และการเชื่อมต่อที่นำเข้าที่มีอยู่จะไม่เปลี่ยนแปลง `copilot-web` เป็นผู้ให้บริการรายอื่นสำหรับบริการลูกค้าที่ `copilot.microsoft.com`

> **ยังใหม่กับผู้ให้บริการคุกกี้เว็บใช่ไหม?**
>
> อ่าน**`docs/getting-started/WEB-COOKIE-GUIDE.md`** สำหรับกระบวนการตั้งค่าทั่วไป คำแนะนำในการตรวจสอบสิทธิ์ ข้อจำกัด และการแก้ไขปัญหา ก่อนที่จะปฏิบัติตามคำแนะนำเฉพาะของผู้ให้บริการนี้
>
> **สำหรับการนำเข้าแบบเดิม:** ข้อมูลรับรองสำหรับผู้ให้บริการรายนี้คือ** ไม่ใช่คุกกี้** . ห้ามคัดลอกคุกกี้จาก `m365.cloud.microsoft` ข้อมูลรับรองคือพารามิเตอร์การค้นหา WebSocket URL และส่วนของเส้นทาง ซึ่งทั้งคู่อ่านจากแท็บเครือข่าย DevTools

## ข้อกำหนดเบื้องต้น

- บัญชี Microsoft 365 พร้อมสิทธิ์เข้าถึง Copilot ที่ `m365.cloud.microsoft/chat`
- เบราว์เซอร์ที่ใช้ Chromium (Chrome, Edge) สำหรับการตรวจสอบ DevTools WebSocket
- เข้าถึงโมเดลที่ร้องขอในบัญชีนั้น ความพร้อมใช้งานแตกต่างกันไปตามผู้เช่าและใบอนุญาต

## การลงชื่อเข้าใช้แบบเนทีฟ (บัญชีที่ทำงานหรือโรงเรียน)

เลือก**Microsoft 365 Copilot → เชื่อมต่อ** และเตรียมการพยายามลงชื่อเข้าใช้ แดชบอร์ดใช้โฟลว์รหัสการอนุญาตด้วย PKCE; มันไม่ถามรหัสผ่าน Microsoft หรือรหัส MFA ของคุณ

1. เปิด** แท็บเบราว์เซอร์ว่างเปล่า** จากนั้นเปิด** เครือข่าย DevTools →** และเปิดใช้งาน** เก็บรักษาบันทึก** . ทำสิ่งนี้ก่อนนำทางไปยัง Microsoft: Windows SSO อาจเสร็จสิ้นทันที
2. คัดลอก URL การอนุญาตที่แสดงโดยกล่องโต้ตอบการเชื่อมต่อ และไปที่แท็บที่เตรียมไว้นั้น เลือกบัญชีของ Microsoft หรือ MFA หากได้รับการร้องขอ
3. ในบันทึกเครือข่ายที่เก็บรักษาไว้ ให้ค้นหาคำขอไปยัง `https://login.microsoftonline.com/common/oauth2/nativeclient` และคัดลอกคำขอทั้งหมด** ขอ URL** .
4. วาง URL นั้นลงในกล่องโต้ตอบการเชื่อมต่อแล้วเชื่อมต่อ อย่าวางโค้ดดิบหรือแถบที่อยู่ `wrongplace` สุดท้าย URL: การเรียกกลับที่จำเป็นคือการนำทางชั่วคราว

ความพยายามแต่ละครั้งจะหมดอายุหลังจากผ่านไปสิบนาทีและสามารถใช้ได้เพียงครั้งเดียว เซิร์ฟเวอร์จะตรวจสอบสถานะ ตัวตรวจสอบ PKCE และเป้าหมายการตรวจสอบสิทธิ์อีกครั้งก่อนที่จะแลกเปลี่ยนโค้ด หลังจากหมดอายุหรือการแลกเปลี่ยนล้มเหลว ให้เริ่มความพยายามใหม่ ความพยายามไม่สามารถรอดจากการรีสตาร์ทเซิร์ฟเวอร์

โทเค็นใช้ที่เก็บข้อมูลรับรองการเชื่อมต่อที่มีอยู่และเส้นทางการรีเฟรช การตรวจสอบสิทธิ์การเชื่อมต่ออีกครั้งต้องใช้ข้อมูลระบุตัวตน Microsoft tenant/object ที่เหมือนกัน ไม่ใช่เพียงอีเมลเดียวกัน โดยจะรักษาตัวดำเนินการ naming/settings และแทนที่ข้อมูลประจำตัวที่นำเข้าที่ล้าสมัย การลงชื่อเข้าใช้แบบเนทีฟใช้สำหรับบัญชี work/school เส้นทางการนำเข้าแบบเดิมยังคงพร้อมใช้งานสำหรับการเชื่อมต่อที่มีอยู่และการกำหนดค่าระดับที่รองรับ

URL การติดต่อกลับแบบเต็มเป็นข้อมูลประจำตัวแบบครั้งเดียว อย่ารวมไว้ในภาพหน้าจอ บันทึก ข้อความสนับสนุน หรือคอมมิต ขั้นตอนนี้ไม่ได้เปิดเบราว์เซอร์บนเซิร์ฟเวอร์ ตรวจสอบประวัติเบราว์เซอร์ของคุณ หรือเริ่มต้นเซิร์ฟเวอร์ติดต่อกลับภายในเครื่อง

## การจับข้อมูลรับรอง (วิธีWebSocket )

1. ลงชื่อเข้าใช้ที่ `https://m365.cloud.microsoft/chat` และเริ่มการสนทนา
2. เปิด** เครือข่าย DevTools →** .
3. กรองตาม**WS** (WebSocket).
4. คลิกการเชื่อมต่อ Chathub WebSocket มองหา URL ที่ขึ้นต้นด้วย `wss://substrate.office.com/m365Copilot/Chathub/`
5. จากมัน** ขอ URL** , สำเนา:
   - ค่าพารามิเตอร์การค้นหา `access_token` ( JWT มีอายุสั้น)
   - ส่วนเส้นทาง Chathub หลัง `/Chathub/` (เช่น `<oid>@<tenant>`)

URL แบบเต็มมีรูปแบบ:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. ใน OmniRoute ให้เลือก**Microsoft 365 Copilot** เลือกตัวเลือก API-key/import แบบเดิม และวางข้อมูลประจำตัวในรูปแบบ:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. คลิก** ทดสอบการเชื่อมต่อ** และ** บันทึก** .

## การบันทึกข้อมูลรับรอง (การนำเข้า HAR )

แทนที่จะคัดลอกค่าจาก WebSocket URL ด้วยตนเอง คุณสามารถส่งออกไฟล์ DevTools HAR ได้:

1. เปิด** เครือข่าย DevTools →** .
2. เริ่มต้นหรือสนทนาต่อ Microsoft 365 Copilot (ซึ่งจะทริกเกอร์การเชื่อมต่อ WebSocket )
3. คลิกขวาในแผงเครือข่ายแล้วเลือก** บันทึกทั้งหมดเป็น HAR พร้อมเนื้อหา** .
4. ใน OmniRoute ให้ใช้** นำเข้าไฟล์ .har** ปุ่มบนกล่องโต้ตอบการเชื่อมต่อของผู้ให้บริการ

OmniRoute สแกน HAR สำหรับ Chathub WebSocket URL แยก `access_token` และ `chathubPath` และเติมฟิลด์ข้อมูลประจำตัวโดยอัตโนมัติ การนำเข้า HAR จะถอดรหัสการหมดอายุของ JWT และแสดงอายุการใช้งานโทเค็นที่เหลืออยู่

> **อย่าส่งการส่งออก HAR จริง โทเค็นการเข้าถึง หรือโทเค็นการรีเฟรช** ค่าการทดสอบและเอกสารจะต้องเป็นตัวยึดตำแหน่งเสมอ

## อายุการใช้งานโทเค็นและการรีเฟรช

`access_token` มีอายุสั้น (โดยทั่วไป**~ 75 นาที** ). หากไม่มีโทเค็นการรีเฟรชที่ใช้งานได้ คุณต้องบันทึกข้อมูลรับรองอีกครั้งหลังจากหมดอายุ

### รีเฟรชอัตโนมัติด้วย `refreshToken`

ในผู้ให้บริการ Microsoft 365** เพิ่มการเชื่อมต่อ** หรือ** แก้ไขการเชื่อมต่อ** กล่องโต้ตอบ เปิด** การตั้งค่าขั้นสูง โทเค็นการรีเฟรช → (ตัวเลือก)** . วางโทเค็นการรีเฟรช Microsoft OAuth สำหรับขอบเขต `substrate.office.com/sydney` แล้วบันทึก อินพุตถูกมาสก์และไม่เคยเติมโทเค็นที่เก็บไว้ล่วงหน้า เมื่อแก้ไข ให้เว้นว่างไว้เพื่อเก็บโทเค็นที่มีอยู่ วางโทเค็นใหม่เพื่อแทนที่

การลงชื่อเข้าใช้แบบเนทีฟจะได้รับโทเค็นการรีเฟรชเมื่อ Microsoft ส่งคืนโทเค็นดังกล่าว สำหรับการนำเข้าแบบเดิม ให้ใช้การให้สิทธิ์รหัสอนุญาต Microsoft ที่เข้ากันได้ที่มีอยู่ ผู้ให้บริการรายนี้ไม่ได้ใช้หรือสัญญาว่าจะมีโฟลว์โค้ดอุปกรณ์ เมื่อกำหนดค่าโทเค็นการรีเฟรชแล้ว OmniRoute จะตรวจสอบ `access_token` ก่อนคำขอ และรีเฟรชเฉพาะเมื่อจำเป็นต้องรีเฟรชเท่านั้น การรีเฟรชที่สำเร็จจะยังคงอยู่ในโทเค็นการรีเฟรชที่หมุนอยู่ โดยหลีกเลี่ยงการจับภาพซ้ำด้วยตนเองในขณะที่โทเค็นการรีเฟรชยังคงใช้งานได้

หากไม่ได้ตั้งค่า `refreshToken` คุณต้องบันทึกข้อมูลประจำตัว WebSocket อีกครั้งด้วยตนเองหลังจากการหมดอายุแต่ละครั้ง

### การเลือกระดับ

| ชั้น         | นามแฝง          | พื้นผิว                     |
| ------------ | --------------- | --------------------------- |
| `individual` | _(ค่าเริ่มต้น)_ | ผู้บริโภค M365 Copilot      |
| `edu`        | `included`      | การศึกษา M365 Copilot       |
| `enterprise` | `work`          | M365 Copilot สำหรับการทำงาน |

ตั้งระดับไว้** การตั้งค่าขั้นสูง → Copilot tier** . การลงชื่อเข้าใช้แบบเนทีฟไม่ได้ตั้งค่าไว้ ดังนั้นบัญชีงานจะต้องเลือก `enterprise` (นามแฝง `work`) และบัญชีการศึกษา `edu` นอกจากนี้ เมื่อใช้โมเดลที่บันทึกไว้ IDs: บัญชีเหล่านั้นจะเลือกโทน สถานการณ์ และประเภทใบอนุญาตของตนเอง แต่ตัวเลือกตัวแทนและการร้องขอยังคงมาจากระดับ และค่าเริ่มต้นแต่ละรายการอาจล้มเหลวในผู้เช่างาน การเปลี่ยนระดับไม่ได้ให้สิทธิ์ใช้งานโมเดล การแทนที่โปรโตคอลขั้นสูงที่ชัดเจนจะมีความสำคัญเหนือกว่า และควรใช้เมื่อคุณทราบค่าการโยงที่จำเป็นเท่านั้น

## โมเดลและเส้นทาง

แค็ตตาล็อกดั้งเดิมประกอบด้วย IDs แบบสแตนด์อโลนที่มีเอกสารประกอบทั้งหมด บวกกับ IDs ดั้งเดิมสี่รายการ แค็ตตาล็อกเป็นแบบคงที่และไม่ขึ้นอยู่กับบัญชี ไม่ใช่การตรวจสอบการให้สิทธิ์บัญชี: เส้นทางแบบชำระเงินและนามแฝงความเข้ากันได้จะยังคงแสดงอยู่แม้ว่าบัญชีที่เชื่อมต่อจะไม่สามารถใช้รายการเหล่านั้นได้ ป้ายแสดงโมเดลจะละเว้นชื่อผู้ให้บริการและต้นแบบความพร้อมใช้งานของแต่ละรุ่น ผู้ให้บริการยังคงอยู่**Microsoft 365 Copilot** . ป้ายกำกับที่ทำเครื่องหมายไว้** นามแฝง** หรือ** มรดก** คงตัวระบุที่มีอยู่และการแมปโปรโตคอลไว้ ไม่ใช่การรับประกันเวอร์ชันโมเดลในอดีต พร็อกซีแบบสแตนด์อโลน** นำเข้าจาก /models** คำแนะนำใช้ไม่ได้กับผู้ให้บริการ WebSocket ดั้งเดิมนี้

| ก่อนหน้านี้ GPT   | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |

นามแฝง เช่น `auto`, `quick`, `think-deeper` และ version aliases จะถูกลงทะเบียนด้วย `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` และ `copilot-m365-gpt-5-5-chat` ที่มีอยู่ยังคงใช้ได้ เอกสาร IDs จำเป็นต้องมีคำนำหน้าผู้ให้บริการ (`copilot-m365-web/claude-opus` หรือ `m365copilot/claude-opus`): หลายคำเป็นคำทั่วไปหรือชื่อรุ่นของผู้จำหน่ายรายอื่น ดังนั้น `claude-opus` เปล่าจึงยังคงกำหนดเส้นทางเหมือนที่ไม่มีผู้ให้บริการรายนี้ การลงทะเบียนไม่ใช่คำมั่นสัญญาว่า Microsoft จะให้บริการโมเดลนั้นกับทุกบัญชี IDs แบบสแตนด์อโลนเป็นไปตาม [แค็ตตาล็อกโปรโตคอล](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) สาธารณะ (แผนที่แบบต่อโทนที่ส่งออกและข้อมูลเมตาของสถานการณ์ที่ทราบโมเดล) โปรไฟล์ดั้งเดิมทั้งหมดจะคงไว้ `availability: "unverified"`; การรวมไว้ในแค็ตตาล็อกไม่ใช่การทดสอบบัญชีที่ประสบความสำเร็จ

- การปฏิเสธใบอนุญาตแบบจำลองที่ชัดเจนส่งกลับ** 403** `m365_model_not_licensed` ไม่ใช่ 502 การล็อกการกำหนดเส้นทางที่ connection/model จับคู่ ทำให้โมเดลที่มีลิขสิทธิ์สามารถใช้การเชื่อมต่อได้
- `InvalidCopilotLicense` เป็นการปฏิเสธใบอนุญาตระดับบัญชี ซึ่งรายงานแยกต่างหากในชื่อ `m365_account_not_licensed`
- เค้นกลับต่อผู้ใช้** 429** `m365_throttled` และทำให้การเชื่อมต่อเย็นลง ผลตอบแทนจากความเหนื่อยล้าในการเข้าถึงลำดับความสำคัญ** 429** `priority_access_exhausted` และอยู่ในขอบเขตของโมเดล ผลลัพธ์ของ `OutOfCredits` พร้อมผลตอบแทน `errorCode: "ReasoningTurnExhausted"`** 429** `reasoning_turns_exhausted` แทน ซึ่งมีการกำหนดขอบเขตโมเดลด้วย โดยไม่มีการอ้างสิทธิ์เวลารีเซ็ต มีรายงานว่าผู้เช่างานรายหนึ่งปิดโทนเสียง "คิดให้ลึกขึ้น" ในขณะที่โทนเสียงด่วนยังคงให้บริการต่อไป ขอบเขตนั้นเป็นการสังเกตของผู้บริโภค ไม่ใช่สิ่งที่พื้นที่เก็บข้อมูลนี้ได้ทำซ้ำ ดังนั้นการกำหนดเส้นทางยังนำโมเดล Think deeper อื่นๆ ของ `gpt-5.5` และ `gpt-5.6` ออกจากการหมุนบนการเชื่อมต่อนั้นสำหรับคูลดาวน์เดียวกัน และปล่อยเสียงด่วนและความล้มเหลวอื่นๆ ทั้งหมดไว้ในโมเดลของตัวเอง คำแนะนำในการลองใหม่ที่ให้มาจะถูกเก็บรักษาไว้ การรีเซ็ตที่หายไปไม่ได้รับการโฆษณาว่าเป็นเวลารีเซ็ตที่ทราบ
- การปฏิเสธความปลอดภัย Copilot (`Disengaged`) ส่งคืน** 400** `provider_safety_rejection` ป้ายกำกับหยุดความปลอดภัยของผู้ให้บริการที่ใช้ร่วมกัน มันไม่เคยนับรวมกับความสมบูรณ์ของการเชื่อมต่อ ไคลเอนต์ SDKs จะไม่ลอง 400 อีกครั้ง และด้วยการกำหนดเส้นทางคอมโบที่เปิดใช้งาน `PROVIDER_SAFETY_STOPS_TERMINAL` จะหยุดอยู่ที่นั่นแทนที่จะเล่นซ้ำคำขอกับเป้าหมายอื่น
- คำขอในการเชื่อมต่อเดียวจะถูกทำให้เป็นอนุกรมผ่านเซมาฟอร์บัญชีที่มีอยู่ ต้องการทางเลือกสำรองที่มีลำดับความสำคัญมากกว่าแผงแบบขนาน การทำให้เป็นอนุกรมเพียงอย่างเดียวไม่ได้กำจัดขีดจำกัดอัตราการสนทนาของ Microsoft

## พฤติกรรมคำขอและขีดจำกัด

- เครื่องมือมี** พร้อมท์จำลอง** ไม่ใช่การเรียกใช้ฟังก์ชัน Microsoft ดั้งเดิม คำขอที่เปิดใช้งานเครื่องมือใช้หนึ่งการสร้างบัฟเฟอร์ ไม่ต้องเสียเวลาเลือกเครื่องมือรุ่นอื่น เฉพาะเครื่องมือที่ประกาศซึ่งมีรูปร่างอาร์กิวเมนต์ที่รองรับที่ถูกต้องเท่านั้นที่จะถูกส่งกลับเป็นการเรียก
- คำตอบที่มีโครงสร้างยาวพร้อมตัวอย่างต่อท้ายเพียงตัวอย่างเดียวจะถูกเก็บรักษาไว้เป็นร้อยแก้ว นี่เป็นการวิเคราะห์พฤติกรรม ไม่ใช่ข้อพิสูจน์ถึงเจตนา แอปพลิเคชันยังคงต้องบังคับใช้สิทธิ์ของเครื่องมือของตนเอง
- อินพุตรูปภาพทำงานในลักษณะเดียวกับที่เว็บไคลเอ็นต์ส่ง แต่ละส่วนของรูปภาพ (`image_url` เป็น data URL หรือ a public HTTPS URL หรือ a Responses `input_image`) จะถูกอัปโหลดไปยัง `/m365Copilot/UploadFile` ในการสนทนาของเทิร์นด้วยโทเค็นการแชท และข้อความจะชี้ไปที่ส่วนนั้นพร้อมกับคำอธิบายประกอบ `ImageFile` ข้อความทำเครื่องหมายตำแหน่งที่มันนั่งอยู่ (`[image 1]`, …) การสนทนาใหม่จะอัปโหลดทุกภาพในประวัติศาสตร์ การสนทนาต่อจะอัปโหลดเฉพาะรูปภาพของข้อความใหม่เท่านั้น สูงสุด 10 PNG, JPEG, GIF หรือ WebP รูปภาพ แต่ละขนาดสูงสุด 10 MiB (40 MiB ต่อคำขอ) รูปแบบจะอ่านจากไบต์ HTTPS URLs ถูกดึงข้อมูลผ่านตัวป้องกันรูปภาพระยะไกลที่ปักหมุด DNS สาธารณะเท่านั้น การอัปโหลดที่ล้มเหลวทำให้คำขอล้มเหลว (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` หรือ `m365_image_invalid`); การเลี้ยวจะไม่ดำเนินต่อไปหากไม่มีภาพที่ได้รับ ส่วนอื่นๆ ที่ไม่ใช่ข้อความ (เสียง ไฟล์) จะถูกปฏิเสธอย่างชัดเจน และไม่มีการดร็อปอย่างเงียบๆ
- คำขอติดตามผลจะดำเนินการสนทนาต้นทางต่อไป และส่งเฉพาะข้อความหลังจากการตอบกลับครั้งก่อนเท่านั้น จะต้องขยายคำตอบนั้นให้ครบถ้วน: การเชื่อมต่อเดียวกัน โปรไฟล์รุ่น และชุดเครื่องมือ; ประวัติที่ไม่เปลี่ยนแปลง (สายโซ่ sha256 เหนือทุกข้อความ); และรหัสการเรียกเครื่องมือของการตอบกลับ หรือข้อความจนถึงช่องว่าง สิ่งอื่นใด (ประวัติที่แก้ไข, เซสชันอื่นที่มีข้อความแรกเหมือนกัน, ตอบกลับอื่น, การสนทนาไม่ได้ใช้งานเป็นเวลา 30 นาทีหรือเกือบถึงขีดจำกัด 600 ข้อความของ Copilot, การเชื่อมต่อโดยไม่มีรหัส) จะเริ่มต้นการสนทนาใหม่พร้อมประวัติทั้งหมด การเลี้ยวที่ล้มเหลวจะไม่ดำเนินการต่อ และ `InternalError` ที่ไม่มีเนื้อหาจะถูกส่งอีกครั้งในการสนทนาใหม่ (** 502** `m365_internal_error` หากล้มเหลวอีกครั้ง) ความต่อเนื่องจะถูกเก็บไว้ในหน่วยความจำกระบวนการ: การรีสตาร์ทจะเริ่มต้นการสนทนาใหม่
- ทุกเทิร์นดำเนินไปในการแชทชั่วคราวของ Copilot(`disableMemory=1`): การสนทนาจะคงบริบทไว้ในขณะที่ดำเนินไป และจะไม่ปรากฏในประวัติการแชทของบัญชี การทดสอบโมเดล การทดสอบทั้งหมด และการทดสอบคอมโบจึงอาจตรวจสอบผู้ให้บริการรายนี้โดยไม่ทิ้งการสนทนาไว้เบื้องหลัง
- เทิร์นหนึ่งมีกำหนดเวลาในการไม่ได้ใช้งาน 120 วินาทีและมีกำหนดเวลาโดยรวมแบบมีขอบเขต คำตอบสุดท้ายเท่านั้น การกรองความคืบหน้า และการยกเลิกได้รับการจัดการโดย transport/composer. ดั้งเดิม
- คำตอบแบบมีพื้นฐานทางเว็บจะเก็บแหล่งที่มาไว้ Copilot ทำเครื่องหมายการอ้างอิงแบบอินไลน์ด้วยอักขระควบคุมการใช้งานส่วนตัวและส่งแหล่งที่มาเป็น `references`; เครื่องหมายแต่ละตัวจะกลายเป็นลิงก์ Markdown ที่มีหมายเลข (`[1](https://…)` หรือ URL เปล่าเมื่อ Copilot ใช้เครื่องหมายเป็นเป้าหมายลิงก์) พร้อมด้วยคำอธิบายประกอบ `url_citation` ที่ตรงกัน (`message.annotations` หรือ `delta.annotations` บนส่วนที่มีลิงก์) แหล่งที่มาที่ไม่เคยมาถึงจะถูกละทิ้ง ดังนั้นเครื่องหมายจึงไม่ไปถึงไคลเอนต์ เมื่อสตรีมมิ่ง ข้อความหลังจากการอ้างอิงจะรอจนกว่าแหล่งที่มาจะมาถึง
- สรุปการใช้เหตุผลของ Copilot(`ChainOfThoughtSummary`) เมื่อแบบจำลองส่งสิ่งใดสิ่งหนึ่งจะถูกส่งกลับเป็น `reasoning_content` ไม่เคยเป็นส่วนหนึ่งของคำตอบ บทสรุปที่เขียนใหม่จะหยุดการสตรีมโดยไม่ทำให้เทิร์นล้มเหลว
- ก่อนเนื้อหาใดๆ ความล้มเหลว licence/throttle จะยังคงอยู่ HTTP 403/429 แม้ว่าจะมีการร้องขอการสตรีมก็ตาม หลังจากเนื้อหาเริ่มต้น ความล้มเหลวคือเหตุการณ์ข้อผิดพลาด SSE ซึ่งไม่มีวันสำเร็จสำเร็จ การเขียนอัปสตรีมใหม่ที่ไม่สามารถแสดงโดยการสตรีมแบบต่อท้ายเท่านั้นถือเป็นข้อผิดพลาดของสตรีมที่ชัดเจน การตอบสนองของเครื่องมือที่ไม่ใช่สตรีมมิ่งและบัฟเฟอร์จะคงข้อความสุดท้ายไว้
- เมื่อ Copilot ปฏิเสธการเชื่อมต่อ คำตอบของมันจะถูกรายงานตามที่เป็น:** 401** `m365_unauthorized` สำหรับการลงชื่อเข้าใช้ที่ถูกปฏิเสธหรือหมดอายุ (ลงชื่อเข้าใช้อีกครั้ง)** 429** ด้วย `Retry-After` สำหรับการควบคุมปริมาณ และการจับมือล้มเหลว ไม่เช่นนั้นจะไม่เกิดความล้มเหลวในการเชื่อมต่อทั่วไป

## การสร้างภาพ

`POST /v1/images/generations` ด้วย `model: "copilot-m365-web/m365-copilot-image"` (นามแฝง `m365copilot/m365-copilot-image`) วาดด้วยเครื่องมือรูปภาพในตัวของ Copilot เหมือนกับที่เว็บไคลเอ็นต์ทำ รูปภาพแต่ละรูปมี Copilot หนึ่งครั้ง โดยเลือกใช้ชุดตัวเลือกรูปภาพของเว็บไคลเอ็นต์และประกาศ `GenerateGraphicArt` และรูปภาพมาถึงรายการความคืบหน้าโดยชี้ไปที่ส่วนที่สร้างขึ้นในบริการ Designer ของ Microsoft อาร์ติแฟกต์นั้นปฏิเสธโทเค็นการแชท ดังนั้น OmniRoute จึงสร้างโทเค็น Designer จากโทเค็นการรีเฟรชของการเชื่อมต่อและดาวน์โหลดไบต์ โทเค็นจะถูกส่งไปยัง `designerapp.officeapps.live.com` เท่านั้น

- ต้องการการเชื่อมต่อการลงชื่อเข้าใช้แบบเนทีฟ (โทเค็นการรีเฟรช) โทเค็นที่วางล้มเหลวด้วย** 400** ก่อนที่จะหมดเทิร์นใดๆ
- `n` คือ 1–4 แต่ละเทิร์น `size` กำหนดทิศทางเท่านั้น (กว้างขึ้น สูงกว่า หรือสี่เหลี่ยมจัตุรัส) ซึ่ง Copilot อ่านจากพรอมต์ Copilot เลือกขนาดการเรนเดอร์
- รูปภาพจะถูกส่งกลับแบบอินไลน์: `b64_json` โดยค่าเริ่มต้น, ข้อมูล URL สำหรับ `response_format: "url"`
- รูปภาพที่สร้างขึ้นใช้งบประมาณรายวันเพียงเล็กน้อย แยกจากการแชท เมื่อใช้จนหมดคำขอจะล้มเหลวด้วย** 429** . เทิร์นที่ตอบโดยไม่มีรูปภาพจะล้มเหลวด้วย** 502** (หรือ** 400** /** 503** เมื่อข้อความของ Copilot อ่านเป็นการปฏิเสธหรือปัญหาด้านความจุ) ข้อความบอกว่าอันไหน

## รูปแบบการรักษาความปลอดภัย

- **การบูรณาการอย่างไม่เป็นทางการ** ผู้ให้บริการรายนี้ทำวิศวกรรมย้อนกลับโปรโตคอล BizChat WebSocket อาจพังโดยไม่ต้องแจ้งให้ทราบล่วงหน้าเมื่อ Microsoft เปลี่ยนจุดสิ้นสุด
- แฟล็ก `subscriptionRisk: true` แสดงให้เห็นว่าการรวมระบบอาศัยจุดสิ้นสุดที่ไม่มีเอกสารประกอบ ข้อจำกัดบัญชีเป็นไปได้แต่ไม่ได้รับการยืนยัน
- โทเค็นการเข้าถึงเป็น JWT ที่มีอายุสั้น ปฏิบัติต่อมันเหมือนเป็นรหัสผ่าน: ห้ามกระทำ บันทึก หรือแชร์มัน
- โทเค็นการรีเฟรชให้สิทธิ์การเข้าถึงพื้นผิว Microsoft 365 อย่างต่อเนื่อง จัดเก็บด้วยความระมัดระวังเช่นเดียวกับคีย์ API

## การแก้ไขปัญหา

### การรับรองความถูกต้องล้มเหลวทันที

- ตรวจสอบว่าคุณคัดลอกมาจาก**WebSocket URL** ไม่ใช่จากคำขอ XHR/Fetch ข้อมูลประจำตัวอยู่ในพารามิเตอร์แบบสอบถาม `access_token` ของการเชื่อมต่อ Chathub WebSocket — ไม่ได้อยู่ในส่วนหัว `Authorization: Bearer`
- ตรวจสอบให้แน่ใจว่า `chathubPath` รวมเซ็กเมนต์ `<oid>@<tenant>` แบบเต็มจากเส้นทาง URL

### โทเค็นจะหมดอายุหลังจาก ~ 75 นาที

นี้เป็นที่คาดหวัง หากไม่มี `refreshToken` โทเค็นการเข้าถึงจะมีอายุการใช้งานสั้น ทั้ง:

- จับภาพข้อมูลประจำตัวอีกครั้งจาก DevTools หรือ
- กำหนดค่า** การตั้งค่าขั้นสูง โทเค็นการรีเฟรช → (ตัวเลือก)** ในกล่องโต้ตอบเพิ่มหรือแก้ไขการเชื่อมต่อสำหรับการรีเฟรชอัตโนมัติ

### ทดสอบการเชื่อมต่อผ่าน แต่การแชทส่งคืน 401

สำหรับการเชื่อมต่อที่สร้างขึ้นด้วย** เข้าสู่ระบบด้วย Microsoft** , Test Connection จะตรวจสอบการหมดอายุของโทเค็นการเข้าถึงและต่ออายุโทเค็นที่หมดอายุด้วยโทเค็นการรีเฟรชที่เก็บไว้ ดังนั้นการทดสอบที่ผ่านการทดสอบจะพิสูจน์ว่าโทเค็นการรีเฟรชยังคงใช้งานได้

สำหรับข้อมูลรับรองที่วาง ทดสอบการเชื่อมต่อจะตรวจสอบรูปร่างของข้อมูลรับรอง และเมื่อโทเค็นมีการหมดอายุ โทเค็นที่ผู้ให้บริการจะใช้ยังไม่หมดอายุ (โทเค็นที่จัดเก็บของการเชื่อมต่อชนะการวางเก่า โทเค็นการรีเฟรชจะนับว่าสามารถต่ออายุได้) โทเค็นที่ถูกเพิกถอนก่อนที่จะหมดอายุยังคงผ่านการทดสอบ แชทแล้วกลับมา** 401** `m365_unauthorized` ใช้** เข้าสู่ระบบด้วย Microsoft** อีกครั้งหรือบันทึกข้อมูลประจำตัวใหม่อีกครั้ง

### Copilot ไม่ปรากฏในรายชื่อผู้ให้บริการ

ตรวจสอบให้แน่ใจว่าเปิดใช้งาน `copilot-m365-web` แล้ว** ผู้ให้บริการแดชบอร์ด →** . ผู้ให้บริการอาจถูกซ่อนไว้ตามค่าเริ่มต้นในบางระดับ
