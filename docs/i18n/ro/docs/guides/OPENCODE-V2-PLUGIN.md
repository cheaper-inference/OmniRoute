`@omniroute/opencode-plugin-v2` adaugă întregul catalog OmniRoute — modele, combinații și
combinații automate — în selectorul de modele din OpenCode v2, împreună cu denumirile afișate,
prețurile și limitele nivelului gratuit.

Este un pachet separat de `@omniroute/opencode-plugin`, deoarece OpenCode v1 și v2 încarcă
pluginurile prin contracte diferite. Alegeți-l pe cel care corespunde versiunii majore OpenCode;
nimic nu este partajat între ele, astfel încât actualizarea unuia nu impune niciodată actualizarea
celuilalt.

## Cerințe

- OpenCode v2.
- Un gateway OmniRoute accesibil (`http://localhost:20128` în mod implicit).
- Node.js 22 sau 24.

## Instalare

Adăugați pluginul în `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Modelele apar apoi sub forma `omniroute/<provider>/<model>`; `providerId` determină acel prefix și
id-ul integrării sub care OpenCode stochează acreditarea.

## Acreditări

Pluginul caută o cheie pentru gateway în trei locuri, în această ordine:

1. **Acreditarea pe care ați conectat-o în OpenCode.** Pluginul înregistrează o integrare, astfel încât
   fluxul propriu de autentificare al OpenCode poate stoca cheia. Nimic nu ajunge în `opencode.json` — preferați această opțiune.
2. `apiKey` din opțiunile pluginului, pentru o suprascriere la nivel de proiect. Aceasta introduce cheia într-un fișier pe care
   este posibil să-l includeți în commituri.
3. `OMNIROUTE_API_KEY` din mediu.

Dacă niciuna dintre cele trei nu este disponibilă, catalogul este gol, iar pluginul menționează acest lucru o singură dată la pornire,
în loc să vă lase cu un selector gol fără nicio explicație.

### Tokenul de administrare este o cheie diferită

Combinațiile, starea furnizorilor și îmbogățirea datelor (denumiri afișate, prețuri, limitele nivelului gratuit) provin de la
endpointurile `/api/*` ale gateway-ului, pe care majoritatea implementărilor le protejează cu un token de
**administrare**, nu cu cheia de inferență:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<token de citire pentru administrare>"
}
```

Dacă nu este setat, `managementReadToken` revine la `apiKey`. Atunci când un gateway respinge această soluție de rezervă,
catalogul este publicat în continuare, dar cu id-urile brute ale modelelor în locul denumirilor afișate, fără
deduplicarea aliasurilor canonice, fără prețuri și fără combinații. Pluginul emite un avertisment o singură dată pentru fiecare endpoint
atunci când se întâmplă acest lucru, indicând endpointul și ceea ce s-a pierdut — astfel încât un selector degradat nu rămâne niciodată un mister.

## Cum rămâne catalogul proaspăt

Catalogul este preluat leneș și stocat în cache pentru `modelCacheTtlMs`, iar un instantaneu de disc păstrează disponibil ultimul catalog cunoscut atunci când gateway-ul este inaccesibil — o întrerupere nu vă costă altceva decât prospețime. Modelele și combo-urile sunt publicate imediat ce sosesc; combo-urile automate, lista de furnizori și suprapunerea de îmbogățire se pliază atunci când aterizează, astfel încât un punct final lent nu poate ține ostatic întregul selector.

Numele urmează `Provider - Model[ (Editor)][ · budget][ (route)]`: furnizorul este afișat ori de câte ori id-ul poartă unul (un ID fără bară oblică se redă fără prefix), un `🆓` principal marchează intrările gratuite și bugetul lor de nivel liber rămâne ca un sufix `· 1M tokens/month`, editorul unui nume `Editor: Model` explicit se mută într-o paranteză finală (niciun editor nu este ghicit fără alte pictograme), și combină fără alte nume ca `combo - <slug>`. Două intrări care au în comun un nume primesc un sufix de rută — `(no-think)` —, astfel încât să rămână distinse. `providerTag` (implicit `true`) comută între parantezele editorului final.

Nu există nicio comandă de reîmprospătare manuală: comenzile OpenCode v2 sunt șabloane prompte, nu apeluri inverse, așa că un plugin nu poate expune unul. Actualizările urmează TTL; gazdei i se cere să reîncarce numai atunci când catalogul sau suprapunerea s-au schimbat efectiv, niciodată o dată pe reîmprospătare.

## Apelarea instrumentelor în Gemini

Gemini respinge în întregime o solicitare ale cărei declarații de instrumente conțin `$schema` sau `additionalProperties`, răspunzând cu `400 INVALID_ARGUMENT`. Pluginul elimină acele cuvinte-cheie din schemele instrumentelor destinate unui model Gemini al acestui furnizor și lasă neschimbate toate celelalte solicitări. Un instrument care conține un `$ref` este transmis fără modificări, în loc să fie eliminat, deoarece eliminarea referinței ar extinde schema pentru a „accepta orice”.
Setați `"geminiSanitization": false` pentru a dezactiva această funcționalitate.

## Depanare

| Simptom                                         | Cauza                                                                                                                                   |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Picker nu prezintă niciun model OmniRoute       | Nicio cheie nu a fost rezolvată (verificați avertismentul de pornire) sau gateway-ul este inaccesibil                                   |
| Id-uri brute de model, fără combo, fără prețuri | Punctele finale de management au refuzat jetonul — set `managementReadToken`                                                            |
| Catalog `freeOnly` scurt sau gol                | Niciun simbol de gestionare sau un jeton refuzat — a citit linia rezumat de reîmprospătare (număr `unmatched-free` ) în jurnalul gazdei |
| O sesiune fixată pe `opencode-<id>/...`         | Pluginul v1 a publicat `opencode-<id>`; v2 publică `<id>` bare, așa că reselectați modelul sub `<id>/...`                               |

Variabilele de mediu trebuie să ajungă la procesul serverului opencode: atunci când gazda rulează ca un serviciu, shell-ul care rulează `opencode models` și mediul serverului sunt diferite, deci exportați cheia acolo unde o citește serverul.
