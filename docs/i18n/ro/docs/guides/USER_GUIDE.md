## 🎯 Cazuri de utilizare

### Cazul 1: „Am un abonament Claude Pro”

**Problemă:** Cota expiră neutilizată, iar în timpul sesiunilor intensive de programare sunt atinse limitele de rată

```
Combinație: "maximize-claude"
  1. cc/claude-opus-4-7        (folosește integral abonamentul)
  2. glm/glm-4.7               (variantă de rezervă ieftină când cota se epuizează)
  3. if/qwen3.8-max-preview       (variantă gratuită de urgență)

Cost lunar: $20 (abonament) + ~$5 (rezervă) = $25 în total
față de $20 + atingerea limitelor = frustrare
```

### Cazul 2: „Nu vreau niciun cost”

**Problemă:** Nu-mi permit abonamente și am nevoie de un AI fiabil pentru programare

```
Combinație: "zero-cost"
  1. if/kimi-k2.7-code          (acces listat drept gratuit; se pot aplica limite de rată)
  2. kr/qwen3-coder-next        (variantă de rezervă gratuită prin Kiro)

Cost lunar: $0
Calitate: verificați modelul, limitele, confidențialitatea și SLA-ul pentru volumul dvs. de lucru
```

### Cazul 3: „Am nevoie să programez non-stop, fără întreruperi”

**Problemă:** Am termene-limită și nu-mi permit perioade de nefuncționare

```
Combinație: "always-on"
  1. cc/claude-opus-4-7        (cea mai bună calitate)
  2. cx/gpt-5.5                (al doilea abonament)
  3. glm/glm-4.7               (ieftin, se resetează zilnic)
  4. minimax/MiniMax-M2.1      (cel mai ieftin, resetare la 5 ore)
  5. if/deepseek-v4-flash       (acces listat drept gratuit; se pot aplica limite de rată)

Rezultat: 5 niveluri de rezervă sporesc reziliența; disponibilitatea serviciilor din amonte nu este garantată
Cost lunar: $20-200 (abonamente) + $10-20 (rezervă)
```

### Cazul 4: „Vreau AI GRATUIT în OpenClaw”

**Problemă:** Am nevoie de un asistent AI în aplicațiile de mesagerie, complet gratuit

```
Combinație: "openclaw-free"
  1. if/qwen3.8-max-preview     (acces listat drept gratuit; se pot aplica limite de rată)
  2. if/deepseek-v4-flash       (acces listat drept gratuit; se pot aplica limite de rată)
  3. if/kimi-k2.7-code          (acces listat drept gratuit; se pot aplica limite de rată)

Cost lunar: $0
Acces prin: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 Configurarea furnizorilor

Pentru a adăuga în bloc conexiuni cu chei API dintr-un fișier CSV sau JSON, utilizați **Panou de control → Furnizori → Importă din fișier**. Coloanele sunt poziționale (`provider,name,apiKey,baseUrl,priority`); `provider` trebuie să existe deja ca furnizor gestionat sau ca nod compatibil. Consultați [Importarea furnizorilor dintr-un fișier CSV sau JSON](../providers/CSV-IMPORT.md).

### 🔐 Furnizori pe bază de abonament

#### Claude Code (Pro/Max)

```bash
Panou de control → Furnizori → Conectează Claude Code
→ Autentificare OAuth → Reîmprospătare automată a tokenului
→ Monitorizarea cotei la 5 ore + săptămânale

Modele:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**Sfat util:** Utilizați Opus pentru sarcini complexe și Sonnet pentru viteză. OmniRoute monitorizează cota pentru fiecare model!

Nu aveți un browser pe gazda OmniRoute? Rulați `claude setup-token` oriunde sunteți autentificat în Claude Code și inserați tokenul valabil un an în fila **Token de configurare**. Consultați [Claude Code cu un token de configurare](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

Rutele compatibile cu Claude și Claude Code păstrează nivelul `max` al efortului de raționament pentru modelele Opus și Sonnet. Modelele Haiku nu acceptă nivelul de efort `max`, astfel încât OmniRoute reduce solicitarea la un buget ridicat de raționament înainte de a o trimite serviciului din amonte.

#### OpenAI Codex (Plus/Pro)

```bash
Panou de control → Furnizori → Conectează Codex
→ Autentificare OAuth (portul 1455)
→ Resetare la 5 ore + săptămânală

Modele:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
Panou de control → Furnizori → Conectează GitHub
→ OAuth prin GitHub
→ Resetare lunară (în prima zi a lunii)

Modele:
  gh/gpt-5.5
  gh/gpt-5.4
```

### 💰 Furnizori ieftini

1. Înregistrați-vă: [Zhipu AI](https://open.bigmodel.cn)

**Utilizare:** `glm/glm-4.7` — **Sfat util:** Coding Plan oferă o cotă de 3× mai mare la 1/7 din cost! Se resetează zilnic la ora 10:00.

**Utilizare:** `kimi/kimi-k2.5` — **Sfat util:** Tariful fix de $9/lună pentru 10M tokenuri înseamnă un cost efectiv de $0.90/1M!

#### Baidu Qianfan / ERNIE

1. Înregistrați-vă: [Baidu AI Cloud Qianfan](https://cloud.baidu.com/product/wenxinworkshop)

**Utilizare:** `qianfan/ernie-5.1`, `qianfan/ernie-x1.1` sau un alt ID de model Qianfan compatibil cu OpenAI.

## 🎨 Combinații

```
Panou de control → Combinații → Creează una nouă

Nume: premium-coding
Modele:
  1. cc/claude-opus-4-7 (Abonament principal)
  2. glm/glm-4.7 (Rezervă ieftină, $0.6/1M)
  3. minimax/MiniMax-M2.7 (Alternativă de ultimă instanță cu cel mai mic cost, $0.3/1M)

Utilizare în CLI: premium-coding
```

### Exemplul 2: Numai opțiuni gratuite (cost zero)

```
Nume: free-combo
Modele:
  1. if/kimi-k2.7-code (acces gratuit conform informațiilor afișate; se pot aplica limitele furnizorului)
  2. kr/qwen3-coder-next (alternativă gratuită Kiro)

Cost: afișat în prezent ca $0; termenii și disponibilitatea se pot modifica
```

## 🔧 Integrarea cu CLI

### Cursor IDE

**Utilizarea Cursor drept client OmniRoute** (direcționează conversațiile Cursor prin OmniRoute):

```
Setări → Modele → Avansat:
  URL de bază pentru API-ul OpenAI: http://localhost:20128/v1
  Cheie API OpenAI: [din panoul de control OmniRoute]
  Model: cc/claude-opus-4-7
```

**Utilizarea OmniRoute drept furnizor Cursor** (OmniRoute apelează Cursor în amonte): este recomandat
**Panou de control → Furnizori → Cursor → Autentificare cu Cursor**. În Docker, consultă
[`docs/providers/CURSOR-DOCKER.md`](../providers/CURSOR-DOCKER.md).

### Claude Code

Editează `~/.claude/settings.json`:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://localhost:20128",
    "ANTHROPIC_AUTH_TOKEN": "your-omniroute-api-key"
  }
}
```

Folosește aici punctul final rădăcină compatibil cu Claude. Nu adăuga `/v1` la `ANTHROPIC_BASE_URL`.

### Codex CLI

```bash
export OPENAI_BASE_URL="http://localhost:20128"
export OPENAI_API_KEY="your-omniroute-api-key"
codex "your prompt"
```

### OpenClaw

Editează `~/.openclaw/openclaw.json`:

```json
{
  "agents": {
    "defaults": {
      "model": { "primary": "omniroute/if/kimi-k2.7-code" }
    }
  },
  "models": {
```

## 🚀 Implementare

### Instalare globală cu npm (recomandat)

```bash
npm install -g omniroute

# Creează directorul de configurare
mkdir -p ~/.omniroute

# Creează fișierul .env (consultă .env.example)
cp .env.example ~/.omniroute/.env

# Pornește serverul
omniroute
# Sau cu un port personalizat:
omniroute --port 3000
```

CLI-ul încarcă automat `.env` din `~/.omniroute/.env` sau `./.env`.

### Modul bară de sistem

Pornește OmniRoute în bara de sistem:

```bash
omniroute serve --tray
```

Comanda se încheie după ce serverul și pictograma din bara de sistem sunt pregătite.

Serverul continuă să ruleze fără terminal.

Modul bară de sistem este compatibil cu macOS, Windows și sesiunile grafice Linux. Modul bară de sistem nu deschide automat panoul de control.

Folosește meniul din bara de sistem pentru următoarele acțiuni:

- Deschide panoul de control.
- Deschide `/dashboard/logs`.
- Modifică pornirea automată.
- Oprește OmniRoute.

Nu combina `--tray` cu următoarele opțiuni:

- `--daemon`
- `--log`
- `--no-recovery`

Aceste moduri necesită o administrare diferită a proceselor.

Activează pornirea la următoarea autentificare pe sistem:

```bash
omniroute autostart enable
```

Pornirea automată folosește modul bară de sistem pe macOS, Windows și în sesiunile grafice Linux. Sistemele Linux fără interfață grafică folosesc serviciul de utilizator systemd existent.

Dezactivează pornirea la autentificare:

```bash
omniroute autostart disable
```

## 🧩 Funcții avansate

### Modele personalizate

Adăugați orice model ID oricărui furnizor fără a aștepta o actualizare a aplicației:

```bash
# Via API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# List: curl http://localhost:20128/api/provider-models?provider=openai
# Remove: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

Sau folosiți Dashboard:** Furnizori → [Furnizor] → Modele personalizate** .

Note:

- Furnizorii OpenRouter și OpenAI/Anthropic-compatible sunt gestionați de la** Modele disponibile** numai. Adăugarea manuală, importarea și sincronizarea automată ajung toate în aceeași listă de modele disponibile, așa că nu există o secțiune separată de modele personalizate pentru acei furnizori.
- The** Modele personalizate** secțiunea este destinată furnizorilor care nu expun importurile gestionate de modele disponibile.

### Furnizori personalizați compatibili cu OpenAI

Orice gateway care rostește OpenAI API (un proxy auto-găzduit, vLLM, un agregator terță parte) poate fi adăugat ca propriul nod de furnizor:

1. **Furnizori → Adaugă OpenAI Compatibil** .
2. **Nume** : o etichetă de afișare pentru nod.
3. **Prefix** : numele de rutare. Clienții numesc modelele ca `<prefix>/<model>`, deci un nod cu prefixul `mygw` servește `mygw/gpt-4o-mini`. Necesar; nu există nicio restricție de caracter.
4. **API Tip** : familia de puncte finale pe care o deservește gateway-ul (finalizări de chat, răspunsuri, încorporare, audio, imagini).
5. **Baza URL** : rădăcina API, până la `/v1` inclusiv (de exemplu `https://gateway.example.com/v1`), nu calea `/chat/completions` completă. Gateway-uri cu căi non-standard le setează sub** Setări avansate** (cale de chat, cale de modele).
6. The** cheie API (pentru verificare)** câmpul testează doar conexiunea. După crearea nodului, deschideți-l și utilizați** Adăugați o conexiune** pentru a stoca cheia pe care o vor folosi cererile.

Nodul primește un id intern de forma `openai-compatible-<apiType>-<uuid>`; nu trebuie să-l tastați niciodată, prefixul este numele public.

#### Prefixe rezervate

Un prefix nu poate fi id-ul sau alias-ul unui furnizor încorporat (de exemplu `openai`, `cf`), nici id-ul unui furnizor retras. Rezolvatorul model verifică ID-urile și aliasurile încorporate înainte de nodurile personalizate, astfel încât un nod care folosește unul dintre aceste prefixe nu ar primi niciodată trafic: `<prefix>/model` ar merge la furnizorul încorporat sau nu ar fi închis dacă acel furnizor ar fi retras. Crearea sau editarea unui nod cu un astfel de prefix este respinsă cu:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

Alegeți un prefix distinct (`mygw`, `acme-proxy`). Dacă cererile către un nod personalizat eșuează cu o eroare care denumește un furnizor încorporat sau acreditările acestuia, verificați dacă prefixul nodului este rezervat: nodurile salvate înainte de a exista această regulă sunt încă stocate, dar rutele lor de prefix către furnizorul încorporat. Editați nodul și dați-i un nou prefix.

#### Opțiuni de gateway per conexiune

Aceste chei merg în `providerSpecificData` a unei conexiuni (de exemplu, prin `PUT /api/providers/{id}`):

- `toolNameMaxLength` (întreg, 1–1024) — pentru conexiuni compatibile cu formatul de chat OpenAI al căror gateway respinge numele lungi de instrumente. Numele mai lungi sunt trimise ca aliasuri scurte și restaurate în răspuns.
- `quotaEndpoint` — punctul final quota/credits al gateway-ului, citit pentru banda de cote din tabloul de bord și rutare în funcție de cotă. Funcționează atât pe conexiuni compatibile cu OpenAI, cât și cu Anthropic; forma completă este documentată în `open-sse/services/usage/openaiCompatible.ts`.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### Înlănțuirea OmniRoute Peers

Un alt gateway OmniRoute poate fi adăugat ca a** Compatibil cu OpenAI personalizat** furnizor. Utilizați baza `/v1` URL a peer-ului și o cheie API dedicată, cu cel mai mic privilegiu, emisă de acel peer.

Pentru lanțuri reciproce sau multi-hop, activați protecția buclei opt-in pe fiecare gateway:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

Doar cererile trimise către un peer URL listat în mod explicit primesc antetul `X-OmniRoute-Peer-Trace`. Un gateway respinge o instanță repetată ID sau un buget hop epuizat cu HTTP `508 Loop Detected`; furnizorii obișnuiți din amonte nu primesc metadate de la egal la egal.

Înlănțuirea peer nu este o replicare a bazei de date sau un failover al gazdei. Fiecare gateway păstrează starea SQLite, cache-urile, contoarele de rate și sesiunile independente. Utilizați un proxy invers verificat de starea de sănătate sau un failover al clientului pentru disponibilitatea active/passive sau active/active și nu montați niciodată o bază de date SQLite în mai multe instanțe OmniRoute care rulează.

### Cloudflare Quick Tunnel

- Disponibil în** Tabloul de bord → Endpoints** pentru Docker și alte implementări auto-găzduite
- Creează un `https://*.trycloudflare.com` URL temporar care redirecționează către punctul final `/v1` compatibil cu OpenAI
- Mai întâi, activați instalează `cloudflared` numai când este necesar; repornirile ulterioare reutilizează același binar gestionat
- Tunelurile rapide nu sunt restaurate automat după repornirea unui OmniRoute sau a containerului; reactivați-le din tabloul de bord când este necesar
- Tunnel URLs sunt efemere și se schimbă de fiecare dată când stop/start tunelul
- Tunelele rapide gestionate se folosesc implicit de transport HTTP/2 pentru a evita avertismentele zgomotoase QUIC UDP buffer în containerele constrânse
- Setați `CLOUDFLARED_PROTOCOL=quic` sau `auto` dacă doriți să înlocuiți opțiunea de transport gestionat
- Setați `CLOUDFLARED_BIN` dacă preferați să utilizați un binar `cloudflared` preinstalat în loc de descărcarea gestionată
- Panourile Cloudflare Quick Tunnel, Tailscale Funnel și ngrok Tunnel pot fi afișate sau ascunse în** Setări → Aspect** . Ascunderea unui panou nu oprește un tunel care rulează.

### Strategii de rutare

Configurați prin** Tabloul de bord → Setări → Rutare** . Tabloul de bord expune cele mai utilizate șase strategii; combo-urile și auto-ruterul acceptă intern un set mai larg.

**Strategii vizibile în tabloul de bord (rutare la nivel de cont):**

| Strategie                            | Descriere                                                                                                                   |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| **Umpleți mai întâi**                | Utilizează conturile în ordine de prioritate — contul principal gestionează toate solicitările până când nu este disponibil |
| **Round Robin**                      | Parcurge toate conturile cu o limită stabilă configurabilă (implicit: 3 apeluri per cont)                                   |
| **P2C (Puterea celor două opțiuni)** | Alege 2 conturi aleatorii și rută către cel mai sănătos — echilibrează sarcina cu conștientizarea sănătății                 |
| **Aleatoriu**                        | Selectează aleatoriu un cont pentru fiecare solicitare folosind Fisher-Yates shuffle                                        |
| **Cel mai puțin folosit**            | Rute către contul cu cea mai veche ștampilă de timp `lastUsedAt`, distribuind traficul uniform                              |
| **Cost optimizat**                   | Rute către contul cu cea mai mică valoare de prioritate, optimizând pentru furnizorii cu cel mai mic cost                   |

**Combo avansate și strategii automate** (configurabil per combo sau prin prefixe `auto/*` - vezi [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ):

- `priority` — ordine strictă, niciodată round-robins
- `weighted` — trafic proporțional împărțit în funcție de ponderile pe model
- `fill-first` — goliți primul model până când atingeți limitele
- `round-robin` / `strict-random` / `random`
- `p2c` (Puterea celor două opțiuni)
- `least-used` și `cost-optimized`
- `auto` — bazat pe scor pentru toți candidații
- `lkgp` (Ultimul furnizor bun cunoscut) — fixează ultimul furnizor de succes, apoi revine la reguli
- `context-optimized` — alege modelul cu cea mai mare fereastră de context liberă
- `context-relay` — înlănțuiește modele de context lung pentru virajele ulterioare

#### Antet de sesiune lipicios extern

Pentru afinitatea sesiunii externe (de exemplu, agenți Claude Code/Codex din spatele proxy-urilor inverse), trimiteți:

```http
X-Session-Id: your-session-key
```

OmniRoute acceptă, de asemenea, `x_session_id` și returnează cheia de sesiune efectivă în `X-OmniRoute-Session-Id`.

Dacă utilizați Nginx și trimiteți antete pentru formulare de subliniere, activați:

```nginx
underscores_in_headers on;
```

#### Aliasuri ale modelului wildcard

Creați modele de metacara pentru a remapa numele modelelor:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

Wildcardurile acceptă `*` (orice caractere) și `?` (un singur caracter).

#### Lanțuri de rezervă

Definiți lanțuri globale de rezervă care se aplică tuturor solicitărilor:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### Reziliență și întrerupătoare de circuit

Configurați prin** Tabloul de bord → Setări → Reziliență** .

OmniRoute implementează rezistența la nivel de furnizor cu cinci componente:

1. **Solicitare coadă și ritm** — Formarea cererilor la nivel de sistem:
   - **Solicitări pe minut (RPM)** — Numărul maxim de solicitări pe minut per cont
   - **Timp minim între solicitări** — Intervalul minim în milisecunde între solicitări
   - **Max solicitări simultane** — Numărul maxim de solicitări simultane pe cont

2. **Răcirea conexiunii** — Configurație de tip per-auth pentru o singură conexiune după erori care pot fi reîncercate:
   - **Răcire de bază** — Fereastra de răcire implicită pentru eșecurile din amonte care pot fi reîncercate
   - **Utilizați sfaturi de reîncercare în amonte** — Onorează `Retry-After` autorizat sau indicii de resetare atunci când sunt furnizate
   - **Pași de retragere maximă** — Nivelul maxim de retragere exponențială pentru defecțiuni repetate

3. **Furnizor Circuit Breaker** — Urmărește eșecurile furnizorului de la capăt la capăt, marchează un furnizor degradat la pragul de avertizare configurat și deschide întrerupătorul atunci când este atins pragul de eșec configurat:
   - **Pragul de degradare** — Eșecuri consecutive ale furnizorului înainte de a introduce `DEGRADED`
   - **Pragul de eșec** — Eșecuri consecutive ale furnizorului înainte de a introduce `OPEN`
   - **Reset Timeout** — Fereastra de timp înainte ca furnizorul să fie testat din nou
   - **CLOSED** (Sanatoasa) — Cererile curg normal
   - **DEGRADED** — Solicitările continuă să curgă în timp ce eșecurile ridicate sunt urmărite
   - **OPEN** — Furnizorul este blocat temporar după defecțiuni repetate
   - **HALF_OPEN** — Testarea dacă furnizorul și-a revenit

   Limitele de rată `429` stabilite pentru conexiune rămân în vigoare** Răcirea conexiunii** și nu contați pentru întrerupătorul furnizorului.

   Starea de rulare a întreruptorului furnizorului este afișată** Tabloul de bord → Health** numai.

4. **Așteptați răcirea** — Dacă fiecare conexiune candidată se răcește deja, OmniRoute poate aștepta cea mai devreme rece și poate reîncerca automat aceeași cerere de client.

5. **Detectare automată a limitei ratei** — Când furnizorii din amonte returnează ferestre de așteptare explicite, acele indicii înlocuiesc timpul de răcire a conexiunii locale atunci când setarea este activată.

**Sfat pro:** Utilizați** Sănătate** pagina pentru a inspecta și a reseta întreruptoarele live ale furnizorului după o întrerupere. Pagina Reziliență modifică doar configurația.

### Strategii de echilibrare combinate

Configurați echilibrarea per-combo în** Tabloul de bord → Combo → Create/Edit → Strategie** .

| Strategie                    | Descriere                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| **Round-Robin**              | Se rotește succesiv prin modele                                                       |
| **Prioritate**               | Încearcă întotdeauna primul model; cade înapoi doar din greșeală                      |
| **Aleatoriu**                | Alege un model aleatoriu din combo pentru fiecare cerere                              |
| **ponderat**                 | Rute proporționale pe baza greutăților atribuite per model                            |
| **Cel mai puțin folosit**    | Rute către modelul cu cele mai puține solicitări recente (folosește valori combinate) |
| **Optimizat pentru costuri** | Rute către cel mai ieftin model disponibil (folosește tabelul de prețuri)             |

Pot fi setate setările implicite globale pentru combo** Dashboard → Settings → Routing → Combo Defaults** . Timeout-urile țintă combinate moștenesc în mod prestabilit timpul de expirare a solicitării curente. Utilizare** Timeout țintă (secunde)** pentru setările implicite de combo sau pentru o combo individuală numai atunci când o limită mai scurtă pe țintă ar trebui să declanșeze o rezervă mai rapidă.

Optimizările combinate cu latență zero sunt opt-in. Pleacă** Optimizări cu latență zero** dezactivat pentru a împiedica aceste caracteristici de latență să concureze ținte de rezervă, să omite ținte pe baza istoricului TTFT sau să comprima solicitările de rezervă; activarea acestuia permite acoperirea configurată, ochiurile TTFT predictive și compresia proactivă de rezervă pentru a tranzacționa fidelitatea routing/request pentru o latență mai mică.

Dezactivați** Tampon pentru token de raționament** atunci când furnizorii din amonte solicită limite stricte `max_tokens` / `maxOutputTokens`. Când este activată, rutarea combinată adaugă doar un spațiu liber pentru modelul de raționament pentru modelele cu o limită de ieșire cunoscută și lasă neschimbată limita de simboluri client atunci când valoarea tamponului sigur ar depăși această limită. Dacă limita clientului este deja peste o limită cunoscută, OmniRoute o limitează la acel plafon înainte de a trimite cererea în amonte.

## 🤖 Rutare automată (fără configurare)

OmniRoute include un **router automat bazat pe scoruri**, care alege cel mai bun model pentru fiecare solicitare dintre toți furnizorii conectați — fără combinații de întreținut. Trimiteți pur și simplu solicitarea folosind unul dintre prefixele `auto/*`, iar OmniRoute va asambla dinamic o combinație virtuală, evaluând candidații în funcție de latență, cost, rata de succes, compatibilitatea cu dimensiunea contextului, adecvarea modelului pentru sarcină, eșecurile recente, cotă și starea mecanismului de întrerupere a circuitului.

| Prefix         | Optimizează pentru                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------- |
| `auto`         | Opțiune implicită echilibrată (latență × cost × rata de succes)                                                |
| `auto/coding`  | Sarcini de programare: preferă Claude, GPT-5, GLM, Kimi, Qwen Coder, programatoarele DeepSeek                  |
| `auto/cheap`   | Cel mai mic cost per token, acceptă o latență mai mare                                                         |
| `auto/fast`    | Cea mai mică latență, ignoră costul                                                                            |
| `auto/offline` | Numai furnizori locali (Ollama, vLLM, llama.cpp) — util pentru configurații izolate de rețea                   |
| `auto/smart`   | Calitatea raționamentului pe primul loc (Opus, GPT-5 xhigh, R1, raționament GLM 5.1)                           |
| `auto/lkgp`    | „Ultimul furnizor cunoscut ca funcțional” — fixează ultimul furnizor utilizat cu succes, apoi revine la reguli |

Exemplu:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactorizați această funcție Python" }],
    "stream": true
  }'
```

Routerul automat este descris în detaliu în [AUTO-COMBO.md](../routing/AUTO-COMBO.md) — inclusiv modul de ajustare a ponderilor de evaluare, de adăugare a furnizorilor pe lista neagră și de inspectare a deciziilor de rutare în **Panou de control → Combinație automată**.

## 🔌 Integrare MCP și A2A

OmniRoute este atât un **server MCP** (Model Context Protocol), cât și un **server A2A** (JSON-RPC 2.0 între agenți). Orice IDE sau gazdă de agenți compatibilă cu MCP poate apela direct instrumentele OmniRoute — fără a necesita un wrapper suplimentar.

### Transporturi MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP cu streaming**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (pentru pluginurile IDE care preferă stdio)

### Conectarea Claude Desktop

Editați `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) sau fișierul echivalent pe Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Conectarea Cursor / Continue / VS Code MCP

Utilizați URL-ul SSE `http://localhost:20128/api/mcp/sse` și o cheie API Bearer generată în **Panou de control → Chei API**.

### Domenii de acces

MCP definește în prezent 32 de domenii de acces denumite. Fiecare cheie Bearer poate fi limitată la anumite domenii de acces — consultați [MCP-SERVER.md](../frameworks/MCP-SERVER.md) pentru lista oficială a domeniilor de acces și a instrumentelor și [A2A-SERVER.md](../frameworks/A2A-SERVER.md) pentru schema JSON-RPC.

## 🧠 Sistemul de abilități

OmniRoute oferă un **cadru extensibil pentru abilități** (`src/lib/skills/`), astfel încât agenții și endpointul A2A să poată executa rutine specifice domeniului (de exemplu, `code-review`, `summarize`, `extract-facts`, `web-research`).

- **Interfață Marketplace** — Răsfoiți și instalați abilități din **Panou de control → Abilități**
- **Domenii per cheie** — Restricționați abilitățile pe care le poate invoca fiecare cheie API
- **Abilități personalizate** — Adăugați un fișier TypeScript în `src/lib/a2a/skills/`, înregistrați-l și acesta devine imediat invocabil prin A2A

Referință completă: [SKILLS.md](../frameworks/SKILLS.md).

## 💾 Sistemul de memorie

OmniRoute păstrează **memoria conversațională pe termen lung** folosind regăsirea hibridă:

- **SQLite FTS5** pentru căutarea după cuvinte-cheie în interacțiunile anterioare
- **Depozit vectorial Qdrant** (opțional) pentru regăsirea semantică
- **Extragere automată a faptelor** — entitățile, preferințele și deciziile sunt rezumate după fiecare sesiune și stocate în tabelul `memory_facts`
- Memoriile sunt delimitate pentru fiecare cheie API și fiecare sesiune

Gestionați memoriile în **Panou de control → Memorie** (căutare, editare, exportare, ștergere). Interfața HTTP (`/api/memory/*`) permite agenților să trimită și să interogheze fapte în mod programatic — consultați [MEMORY.md](../frameworks/MEMORY.md).

## 🔔 Webhookuri

Abonați-vă la evenimentele OmniRoute pentru monitorizare și automatizare în timp real.

- Creați un webhook în **Panou de control → Webhookuri**, folosind URL-ul țintă și secretul de semnare HMAC

## 🛠️ Gestionare programatică

Puteți gestiona fiecare resursă OmniRoute (furnizori, combinații, chei, setări) prin HTTP, utilizând o **cheie Bearer cu domeniul `manage`**.

Generați cheia în **Panou de control → Chei API → Cheie nouă → Domeniu: manage**, apoi:

```bash
# Listează furnizorii
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Adaugă o conexiune la un furnizor
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Creează o combinație
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Listează/creează chei API
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

Consultați [API_REFERENCE.md](../reference/API_REFERENCE.md) pentru catalogul complet de endpointuri și schemele solicitărilor/răspunsurilor.

## 💻 CLI intern

OmniRoute include un CLI intern (`omniroute …`) pentru configurare, diagnosticare și control în timpul rulării. Acesta este **separat de pagina „Instrumente CLI” din panoul de control**, care configurează CLI-uri terțe (Claude Code, Cursor, Codex, Cline, …), astfel încât acestea să poată comunica cu OmniRoute.

```bash
omniroute setup                    # Expert interactiv (parolă, furnizori, combinații)
omniroute setup --non-interactive  # Adecvat pentru CI
omniroute doctor                   # Diagnosticarea stării (director de date, BD, furnizori, porturi)
omniroute providers available      # Listează furnizorii acceptați
omniroute providers list           # Listează conexiunile configurate
omniroute providers test <id>      # Testează în timp real conexiunea unui furnizor
omniroute combos list              # Listează combinațiile
omniroute combos switch <name>     # Setează combinația implicită
omniroute models                   # Listează modelele disponibile (--json, --search)
omniroute keys add | list | remove # Gestionează cheile API din terminal
omniroute backup                   # Creează un instantaneu al configurației + BD
omniroute restore [<timestamp>]    # Restaurează dintr-un instantaneu
omniroute health                   # Stare detaliată (întrerupătoare, cache, memorie)
omniroute quota                    # Utilizarea cotei furnizorului
omniroute mcp status               # Starea serverului MCP
omniroute a2a status               # Starea serverului A2A
omniroute tunnel list|create|stop  # Tuneluri Cloudflare/Tailscale/ngrok
omniroute reset-password           # Resetează parola de administrator
omniroute --mcp                    # Pornește serverul MCP prin stdio
omniroute --port 3000              # Pornește serverul pe un port personalizat
```

Sfat: utilizați `omniroute doctor --json` împreună cu instrumentul dumneavoastră de monitorizare pentru a primi alerte privind conexiunile nesănătoase ale furnizorilor.

## 🖥️ Aplicație desktop (Electron)

OmniRoute este disponibil ca aplicație desktop nativă pentru Windows, macOS și Linux.

### Instalare

```bash
# Din directorul electron:
cd electron
npm install

# Mod de dezvoltare (se conectează la serverul de dezvoltare Next.js care rulează):
npm run dev

# Mod de producție (utilizează versiunea autonomă):
npm start
```

### Crearea programelor de instalare

```bash
cd electron
npm run build          # Platforma curentă
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg universal)
npm run build:linux    # Linux (.AppImage)
```

Rezultat → `electron/dist-electron/`

### Funcționalități principale

| Funcționalitate                           | Descriere                                                                              |
| ----------------------------------------- | -------------------------------------------------------------------------------------- |
| **Disponibilitatea serverului**           | Interoghează serverul înainte de afișarea ferestrei (fără ecran gol)                   |
| **Zona de notificare**                    | Minimizare în zona de notificare, schimbarea portului și închidere din meniul acesteia |
| **Gestionarea portului**                  | Schimbă portul serverului din zona de notificare (repornește automat serverul)         |
| **Politica de securitate a conținutului** | CSP restrictivă prin anteturile sesiunii                                               |
| **Instanță unică**                        | Poate rula o singură instanță a aplicației simultan                                    |
| **Mod offline**                           | Serverul Next.js inclus funcționează fără internet                                     |

### Variabile de mediu

| Variabilă             | Valoare implicită | Descriere                              |
| --------------------- | ----------------- | -------------------------------------- |
| `OMNIROUTE_PORT`      | `20128`           | Portul serverului                      |
| `OMNIROUTE_MEMORY_MB` | `512`             | Limita heap-ului Node.js (64–16384 MB) |
