Contractul `config/cli-tools-manifest.json` neutru declară IDs canonic, aliasuri, candidați binari, rețete de configurare, argumente model și capabilități. Adaptorul simplu Node din `bin/cli/cli-manifest.mjs` și adaptorul TypeScript din `src/shared/constants/cliIntegrationManifest.ts` citesc același fișier. Timpul de rulare, catalogul, configurarea, finalizarea, generatoarele și înregistrarea backend sunt verificate împreună de `tests/unit/cli/cli-manifest-drift.test.ts`. A fi catalogat nu înseamnă că un instrument poate fi lansat sau configurat. În special, 5dive rămâne doar configurat.

## Mediul și ciclul de viață al copilului

`omniroute run`, `omniroute launch` și `omniroute launch-codex` moștenesc o listă de compatibilitate OS/terminal și injectează acreditările țintei selectate. Furnizorul neînrudit și secretele bazei de date nu sunt moștenite în mod implicit. `--inherit-env` restabilește în mod explicit moștenirea completă a mediului părinte; utilizați-l numai atunci când procesul terț selectat ar trebui să primească acele valori. Aceasta este filtrarea mediului, nu un sandbox OS : procesul încă rulează cu permisiunile sistemului de fișiere ale apelantului.

Semnalele de întrerupere și de terminare sunt transmise copilului. Lansatorul așteaptă evenimentul de închidere al copilului înainte de a elimina configurația temporară. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` controlează perioada de grație înainte de terminarea forțată (implicit 5000 milisecunde).

## Gemini configurare persistentă

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

Primele două comenzi configurează această mașină pentru serverul local sau la distanță selectat. Configurarea păstrează setările JSON care nu au legătură, selectează autentificarea cheii API Gemini și scrie punctul final și acreditările într-un fișier `.gemini/.env` privat. Refuză JSON invalid în loc să-l suprascrie. Punctul final URLs trebuie să fie HTTP(S), fără acreditări încorporate, parametri de interogare sau fragmente. Dry-run imprimă căile, nu valorile acreditărilor.

`GEMINI_CLI_HOME` sau `--gemini-home` selectează rădăcina de acasă persistentă. Un `run gemini` real își creează și mai târziu își elimină propria casă temporară. Niciunul dintre mod nu ocolește verificările de încredere în spațiul de lucru ale Gemini.

## profile Codex

`configure codex` scrie un `<name>.config.toml` privat cu un model și punctul final al furnizorului OmniRoute. Acreditările sunt referite prin `OMNIROUTE_API_KEY`, niciodată încorporate. Comanda de lansare setează modelul selectat la cheia `model` de nivel superior, nu în interiorul `model_providers`.

Fișierele de profil separate sunt contractul Codex documentat curent; acestea suprapun configurația utilizatorului atunci când sunt selectate cu `codex --profile <name>`. Consultați [referința oficială a profilului](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) și [ghidul OmniRoute Codex](./CODEX-CLI-CONFIGURATION.md).

## Executarea comenzii ermetice

Cu un `DATA_DIR` explicit, setarea `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` împiedică pornirea să cadă în mediul de acreditări implicit al directorului de date utilizator. Acest lucru este util pentru teste izolate. Nu dezactivează alte fișiere de mediu selectate în mod explicit.

## Directorul de lucru `.env`

CLI citește fișierele `.env` în această ordine, iar primul fișier care setează o cheie câștigă: `DATA_DIR` explicit, directorul de date implicit, directorul de lucru curent, apoi directorul pachetului. Variabilele Shell câștigă întotdeauna.

Directorul de lucru poate aparține altcuiva (un depozit clonat, o arhivă dezambalată), iar `omniroute serve` transmite mediul CLI serverului și fiecărui instrument pe care îl rulează serverul. Deci, un `.env` acolo poate seta doar aceste chei, enumerate în `bin/cli/utils/untrustedCwdEnv.mjs`:

| Cheie                           | Valori acceptate                                                          |
| ------------------------------- | ------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` sau `yes` în orice caz, valorile pe care serverul le tratează |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | până la 64 de litere, cifre, `_`, `.`, `@` sau `-`                        |
| `LANGUAGE`                      | la fel, plus `:`                                                          |
| `TZ`                            | până la 64 de litere, cifre, `_`, `+`, `-` sau `/`, care nu încep cu `/`  |
| `NO_COLOR`, `FORCE_COLOR`       | până la 16 litere și cifre                                                |

Fiecare valoare acceptată `REQUIRE_API_KEY` activează verificarea, astfel încât fișierul nu poate dezactiva verificarea în sine. Totuși, nu decide rezultatul: serverul citește o suprascriere `REQUIRE_API_KEY` stocată în baza de date înainte de mediu, în timp ce avertismentul de pornire despre ascultarea pe toate interfețele fără o cheie API citește doar mediul. Cu o modificare stocată a `false`, un director de lucru `REQUIRE_API_KEY=true` lasă API deschis și ascunde acel avertisment. Regula `TZ` este mai restrânsă decât POSIX: respinge `.`, `:`, `,` și `<>`, deci forma `:Area/City` și reguli precum `EST5EDT,M3.2.0,M11.1.0` trebuie să fie stabilite în shell sau în `<DATA_DIR>/.env`.

Numele trebuie să se potrivească exact, cu litere mari. Orice altă linie, o valoare care eșuează verificarea și un nume care nu este litere simple ASCII, cifre și `_` (de exemplu unul cu un octet NUL sau o literă asemănătoare) sunt omise. CLI afișează un avertisment care denumește cheile pe care nu le poate seta și unul care numește cheile permise pe care le-a ignorat, fiecare cu ce trebuie schimbat (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Nici unul nu imprimă valorile. Căile de fișiere din aceste mesaje și calea `.env` rapoartele `omniroute doctor` sunt escape atunci când conțin caractere de control sau bidi. Restricția nu se aplică atunci când directorul de lucru este directorul de date sau directorul pachetului.

`PORT`, `API_PORT` și `DASHBOARD_PORT` nu sunt pe listă. Fără un URL de bază dintr-o sursă cu prioritate mai mare, CLI vorbește cu `localhost:<PORT>`, iar orice ascultă acolo primește cheia API a lui CLI, tokenul de context și jetonul CLI mașină (`x-omniroute-cli-token`, vezi [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), pe care serverul local le acceptă pentru apelurile de management din loopback. Un port din directorul de lucru ar lăsa acel fișier să aleagă ascultătorul, așa că setați porturile în shell, în `<DATA_DIR>/.env` sau cu opțiunea `--port` a comenzilor care au una (`serve`, `launch`, `run`).

Analizorul nu are sintaxă `export`. O linie precum `export LD_PRELOAD=...` denumește o variabilă `export LD_PRELOAD`; din directorul de lucru este omis, iar în alte fișiere `.env` setează acel nume literal, pe care nu îl citește nimic.

CLI împerechează jetonul stocat al unui context (jeton de acces sau cheie API moștenită) numai cu originea acelui context: schemă, gazdă și port, în comparație cu `URL.origin`. Acest lucru se aplică solicitărilor făcute prin clientul HTTP al lui CLI(`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) și comenzilor `launch`, `launch codex`, `configure` și `setup-*` care scriu un URL de bază și introduc configurația altui instrument. Îndreptați către un alt server cu `--remote`, ei folosesc un `--api-key` sau `OMNIROUTE_API_KEY` explicit, dacă este setat unul, și niciun simbol de context. Comparația este exactă, deci `localhost` și `127.0.0.1`, sau o gazdă cu și fără un punct final, sunt considerate servere diferite și nu primesc nici un simbol de context. Un URL cu informații despre utilizator, o bară oblică inversă sau un spațiu alb nu se potrivește niciodată, deoarece alți analizatori URL ( `urllib` și `httpx` din Python, de exemplu) pot citi o gazdă diferită de el. Pentru cererile pe care CLI le trimite singur, acea verificare acoperă doar schema și autoritatea, astfel încât un id cu un spațiu în cale sau interogare păstrează jetonul.
