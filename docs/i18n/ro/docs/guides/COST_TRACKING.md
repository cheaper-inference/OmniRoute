Cum estimează, înregistrează și raportează OmniRoute costul fiecărei solicitări — și de ce
valoarea din panoul de control este un **instrument de urmărire a economiilor**, nu o factură.

Consultați și: [Ghidul utilizatorului](./USER_GUIDE.md) · [Galeria de funcționalități](./FEATURES.md)

---

## Ce este (și ce nu este)

OmniRoute atribuie fiecărei completări un cost în USD per solicitare, înmulțind numărul de
tokenuri cu tarifele modelului. Aceste valori alimentează panoul de control **Costuri**,
CLI-ul `omniroute cost` / `omniroute usage`, exporturile CSV/JSON și bugetele per cheie API.

> **„Costul” din panoul de control este un instrument de urmărire a economiilor, nu o factură.** OmniRoute nu vă taxează
> niciodată — vă direcționează solicitările către furnizorii pe care i-ați conectat deja
> (propriile abonamente, niveluri gratuite și chei API). Un „cost total de 290 USD” acumulat exclusiv prin modele
> gratuite înseamnă că, aproximativ, **nu ați plătit 290 USD** unui API cu plată. Valoarea este o _estimare_
> a costului pe care l-ar fi avut același trafic la prețurile standard de listă, astfel încât să puteți vedea unde
> este concentrată utilizarea și cât economisiți prin direcționarea către furnizori mai ieftini/gratuiți.

Această interpretare este menționată direct în fișierul [README](../../README.md) al proiectului
(„«costul» din panoul de control este un instrument de urmărire a economiilor, nu o factură”).

Deoarece valoarea este o estimare:

- Aceasta depinde de tabelul de prețuri pe care OmniRoute îl are pentru fiecare model. Un model fără o intrare
  de preț contribuie cu un cost de `0` (apare ca un rând „Moștenit / Gratuit” în explorator).
- Traficul din nivelurile gratuite și abonamente acumulează în continuare un cost _estimat_ — acesta este
  cuantumul pe care îl economisiți, nu o sumă datorată.

## Cum sunt estimate costurile

### Sursa de stabilire a prețurilor

Costurile provin din tabelul de prețuri combinat în [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts), în această ordine de prioritate (** cel mai înalt primul** ):

1. **Utilizatorul anulează** Prețurile — sunt stabilite în tabloul de bord sau prin `PATCH /api/pricing` (spațiul de nume `pricing` ).
2. **modele.dev sincronizare** prețul — preluat de la `https://models.dev/api.json` (spațiul de nume `models_dev_pricing` ).
3. **sincronizare LiteLLM** Prețurile — preluate din `model_prices_and_context_window.json` public al lui LiteLLM(spațiul de nume `pricing_synced` ).
4. **Valori implicite codificate** tarifele — sunt expediate în [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/).

Pentru același provider/model, valorile din straturile cu prioritate mai mare suprascriu câmpurile care se potrivesc în straturile inferioare; câmpurile absente dintr-un strat superior pot proveni în continuare dintr-un strat inferior. Ordinea este fixată chiar și atunci când ambele joburi de sincronizare independente rulează în același timp. `GET /api/pricing?includeSources=1` returnează `pricing` și `sourceMap`, ale căror etichete per model (`user`, `modelsDev`, `litellm`, `default`) identifică stratul cu cea mai mare prioritate care conține modelul respectiv.

**sincronizare LiteLLM** este opt-in, dezactivat implicit. Variabilele sale de mediu (vezi [`.env.example`](../../.env.example) ) sunt:

| Env var                 | Implicit  | Scop                                                                                           |
| ----------------------- | --------- | ---------------------------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | Activați sincronizarea prețurilor LiteLLM în fundal.                                           |
| `PRICING_SYNC_INTERVAL` | `86400`   | Interval de sincronizare în secunde (zilnic).                                                  |
| `PRICING_SYNC_SOURCES`  | `litellm` | Selectarea sursei numai pentru această sincronizare; în prezent, doar `litellm` este acceptat. |

**modele.dev sincronizare** este separat de sincronizarea LiteLLM și este, de asemenea, dezactivat implicit. Activați-l în Setări (models.dev sync) sau utilizați aceste variabile:

| Env var                    | Implicit       | Scop                                                                                                                                                 |
| -------------------------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(dezactivat)_ | Dezactivat urmează comutatorul Setări; `1/true/on/yes` forțează activarea și `0/false/off/no` forțează dezactivarea (chiar dacă Setări o activează). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`        | Intervalul de sincronizare modele implicite.dev în secunde (zilnic).                                                                                 |

`PRICING_SYNC_SOURCES` face** nu** enable models.dev; controlează doar sincronizarea LiteLLM. Ștergerea unei înlocuiri de utilizator nu șterge nici spațiul de nume sincronizat; următorul nivel de preț disponibil devine efectiv. Pentru un model fără preț, verificați atât setările de sincronizare, cât și `sourceMap` înainte de a adăuga o modificare manuală.

### Formula costului

Costul este calculat pe solicitare din numărul de jetoane și ratele pe milion de jetoane în [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`):

- **Jetoane de intrare** (minus citirile cache-ului și jetoanele de creare a memoriei cache) × `input` rate.
- **Jetoane citite în cache** × `cached` rate (reduce la rata de intrare).
- **Jetoane de creare a memoriei cache** × `cache_creation` rate (reduce la rata de intrare).
- **Jetoane de ieșire** rata × `output`.
- **Jetoane de raționament** × `reasoning` rate (reduce la rata de ieșire).

Toate tarifele sunt interpretate ca USD pentru 1.000.000 de jetoane. Un nivel de serviciu Codex „rapid”/„prioritario” sau „flex” aplică un multiplicator de cost (`getCodexFastCostMultiplier`) — de exemplu, flex este facturat cu o reducere de 50%, care apare ca** economii flexibile** în tabloul de bord.

Numele modelelor sunt normalizate mai întâi (prefixele căii furnizorului, cum ar fi `openai/` sau `accounts/fireworks/models/` sunt eliminate), astfel încât rândurile istorice se potrivesc în continuare cu un preț.

### Cum se înregistrează cheltuielile

- Costul per cerere este calculat la finalizarea cererii. Consumul cotei partajate este programat la următoarea bifare a buclei de eveniment prin [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts).
- Cheltuielile cheii API sunt stocate în tampon și eliminate în loturi de [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (interval de spălare implicit de 60 de secunde, tampon de 1.000 de intrări). Reglabil prin:

  | Env var                             | Implicit | Scop                                                   |
  | ----------------------------------- | -------- | ------------------------------------------------------ |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`  | Interval de spălare în milisecunde.                    |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`   | Numărul maxim de intrări în tampon înainte de spălare. |

Costurile preferă o taxă exactă raportată de furnizor (`provider_cost_usd`), apoi un instantaneu al cererii cu prețul de catalog (`calculated_cost_usd`), apoi reprecierea simbolului din catalogul actual. Costurile stocate nu sunt taxate din nou prin numărul de simboluri. Rândurile vechi doar cu simboluri se modifică atunci când prețul lor de catalog se modifică.

### OCR și înglobări

- Solicitările `/v1/ocr` reușite folosesc `usage_info.pages_processed` în amonte, nu intervalul de pagini solicitat sau numărul de obiecte de pagină returnate. Estimarea este de pagini × `ocr_cost_per_page` ( USD/page absolut,** nu** USD/million).
- Solicitările cu adnotări pentru documente sau casete de delimitare necesită un tarif `ocr_cost_per_annotated_page` separat. Fără el, costul rămâne necunoscut; tariful OCR obișnuit nu este înlocuit în tăcere.
- LiteLLM sync mapează câmpul `annotation_cost_per_page` din amonte în `ocr_cost_per_annotated_page`, păstrând valoarea USD/page absolută și intrările numai pentru adnotări, inclusiv zero explicit. Un câmp canonic furnizat are prioritate; valorile de alias nevalide sunt ignorate. Modificarea prețurilor de utilizator își păstrează prioritatea normală. Consultați [cheile de prețuri OCR ale LiteLLM](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking).
- Utilizarea OCR stochează numărul de pagini, prețul unitar, costul USD calculat, cheia API și conexiunea selectată. Paginile nu sunt niciodată reprezentate ca simboluri. Jurnalele de apeluri conțin metadate de facturare, nu documentul URLs, PDF bytes sau text extras.
- Solicitările `/v1/embeddings` reușite înregistrează un rând de utilizare per lot fizic, inclusiv loturi separate finalizate în aceeași milisecundă. Taxele raportate de furnizor au prioritate față de estimările indicative; ambalajele combinate nu adaugă o taxă.
- Istoricul utilizării, analiza costurilor, ferestrele provider/account, limitele de cheltuieli pentru cheia API, registrul costuri-solicitare și cumulările zilnice de utilizare includ aceste taxe. Cheile fără jurnal păstrează contabilitatea numerică fără a păstra textul sursă.
- Lipsesc utilizarea sau tarifele sunt** necunoscut** , nu este gratuit: antetul cost-cost de răspuns este omis, iar politica de utilizare fără preț existentă se aplică cheilor API limitate. Tarifele zero configurate explicit rămân valabile pentru utilizare fără costuri.

Aceasta este o contabilitate forward. Vechile apeluri OCR/embedding care nu au scris niciodată istoricul utilizării nu pot fi reconstruite din această migrare. Estimările de catalog sunt estimări USD, nu o factură și nu includ conversia valutară, taxele sau reducerile.

### Discurs și imagini

- Încercările reușite `/v1/audio/transcriptions`, `/v1/audio/speech` și de generare de imagini împărtășesc contabilitatea numerică. Apelurile directe și combinate poartă tasta API a apelantului și conexiunea selectată; un pachet combo nu adaugă niciodată un al doilea debit.
- USD raportat de furnizor câștigă o estimare de catalog, inclusiv o taxă explicită zero. OpenRouter lui JSON `usage.cost` este normalizat la `cost_usd`. În caz contrar, jetoanele măsurate folosesc prețuri de simboluri, secundele de transcriere folosesc prețuri pe secundă, introducerea vocală utilizează numărul de caractere Unicode, iar imaginile cu preț fix utilizează numărul returnat efectiv, nu `n` solicitat.
- Binarul OpenRouter TTS nu are corp de utilizare JSON. După terminarea sunetului sau după ce apelantul se anulează, OmniRoute interogează generația sa ID pe** aceleaşi** originea OpenRouter configurată. O solicitare EU nu revine niciodată la originea globală. Aceasta este o căutare limitată, numai pentru citire; sinteza nu este reîncercată pentru contabilitate. Înregistrările de facturare pot apărea după terminarea sunetului: încercările de căutare se execută în fundal timp de până la aproximativ 52 de secunde, inclusiv termenele limită ale rețelei.
- În timpul acelei căutări, răspunsul audio are `X-OmniRoute-Cost-Status: pending` și niciun antet pentru costul răspunsului. Taxa sa finală apare în istoricul utilizării, analize și registrul cheie după reconciliere. Dacă metadatele nu sunt disponibile, se utilizează un instantaneu de tarif configurat; altfel costul rămâne necunoscut.
- Numărările de secunde, caractere și imagini au câmpuri separate pentru unități de facturare, niciodată numărătoare de simboluri false. Contabilitatea păstrează doar utilizarea numerică, nu textul vorbirii, transcrierile sau octeții de imagine. Scutirile existente pentru imagini fără preț sunt neschimbate: un tarif de imagine care lipsește cu adevărat nu blochează o cheie limitată, iar răspunsul omite antetul de cost în loc să declare apelul gratuit. Un eșec al magazinului de prețuri păstrează în continuare dovezile de utilizare pentru aplicarea în mod neînchis.

Nicio taxă speech/image istorică nu este inventată sau completată. Facturarea furnizorului rămâne referința pentru facturi și pentru apelurile a căror taxă nu a fost raportată.

## Tablou de bord: pagina Costuri

Pagina **Costuri** se află la `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`).
Vizualizarea sa principală este fila **Prezentare generală a costurilor**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
care încarcă toate datele de la `GET /api/usage/analytics`.

Ce afișează:

- **Casete de cheltuieli** — cheltuielile estimate pentru _Astăzi (1d)_, _7d_, _30d_ și
  intervalul selectat. Selector de interval: `7d`, `30d`, `90d`, `all`.
- **Indicatori principali** — solicitările din interval, furnizorii activi, modelele active,
  costul mediu per solicitare.
- **Explorator de costuri** — un tabel care poate fi sortat și filtrat, grupat după
  **furnizor**, **model**, **cheie API**, **cont** sau **nivel de serviciu**, cu costul,
  solicitările, tokenurile, costul mediu per solicitare și ponderea procentuală din total.
- **Utilizarea tokenurilor** — totalul tokenurilor / tokenurile de intrare / tokenurile de
  ieșire și raportul intrare:ieșire.
- **Eficiența rutării** — numărul de reveniri la alternative, rata de revenire la alternative
  și acoperirea modelelor solicitate.
- **Prognoză lunară** — estimează cheltuielile de la sfârșitul lunii pe baza mediei zilnice
  recente.
- **Comparație între perioade** — modificarea procentuală dintre prima și a doua jumătate a
  intervalului.
- **Grafice** — tendința zilnică a costurilor, ponderea furnizorilor (diagramă circulară),
  principalii furnizori, principalele modele, costul per cheie API, costul per cont, tiparul
  săptămânal de utilizare și o hartă termică a activității.
- **Export** — descărcarea intervalului curent în format **CSV** sau **JSON** (butoanele apar
  după ce există date cu un cost diferit de zero).

Atunci când nu există trafic tarifat, rândurile afișează eticheta „Moștenit / Gratuit” în
loc de `$0`, reflectând modelul instrumentului de monitorizare a economiilor.

### Subpagini asociate secțiunii Costuri

Zona Costuri găzduiește, de asemenea (toate sub `/dashboard/costs/`):

- **Tarifare** (`/dashboard/costs/pricing`) — vizualizarea și înlocuirea prețurilor per model
  (afișează fila comună Tarifare).
- **Buget** (`/dashboard/costs/budget`) — stabilirea limitelor de cheltuieli per domeniu
  (afișează fila comună Buget).
- **Partajarea cotei** (`/dashboard/costs/quota-share`) — grupuri cu cote partajate și
  vizualizări ale ratei de consum.

## puncte finale API

Toate acestea necesită autentificare de gestionare (loopback/JWT, prin `requireManagementAuth`) dacă nu este menționat.

### Analize de utilizare și costuri

| Metodă | Punct final              | Scop                                                                                                                                                                    |
| ------ | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/analytics`   | Analize complete cost/usage : rezumat, tendință zilnică, după provider/model/API key/account/tier. Interogare: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET`  | `/api/usage/utilization` | Utilizarea cotei per furnizor în timp. Interogare: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                                         |
| `GET`  | `/api/usage/history`     | Rânduri brute din istoricul utilizării.                                                                                                                                 |
| `GET`  | `/api/usage/call-logs`   | Jurnalele de apeluri la cerere (model, jetoane, cost, latență, stare).                                                                                                  |
| `GET`  | `/api/usage/quota`       | Starea cotei furnizorului.                                                                                                                                              |
| `GET`  | `/api/usage/proxy-logs`  | Jurnalele cererilor de proxy.                                                                                                                                           |

### Bugetele

| Metodă | Punct final              | Scop                                                                                                                   |
| ------ | ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | Rezumatul costurilor Verificarea bugetului + pentru o cheie API (este necesar un parametru de interogare `apiKeyId` ). |
| `POST` | `/api/usage/budget`      | Setați daily/weekly/monthly USD limits pragul de avertizare + pentru o cheie API.                                      |
| `GET`  | `/api/usage/budget/bulk` | Rezumate bugetare în bloc pentru cheile API.                                                                           |

> Bugetul API este acoperit per**API** (`apiKeyId`). Limitele returnate de `GET /api/usage/budget` includ `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`, a `warningThreshold` și totalurile curente (`totalCostToday`, `totalCostMonth`, …).

### Prețuri

| Metodă   | Punct final             | Scop                                                                                                                                                                      |
| -------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | Prețuri îmbinate pe patru straturi (utilizator, models.dev, LiteLLM, valori prestabilite). `?includeSources=1` returnează `pricing` + `sourceMap`.                        |
| `PATCH`  | `/api/pricing`          | Înlocuiți prețul pentru `{ provider: { model: { input, output, cached, … } } }`.                                                                                          |
| `DELETE` | `/api/pricing`          | Eliminați suprascrierile de preț de utilizator (opțional, acoperite de `?provider=&model=`); ratele sincronizate sau valorile implicite încorporate rămân ca alternative. |
| `GET`    | `/api/pricing/defaults` | Afișați ratele implicite de rezervă per-1M.                                                                                                                               |
| `GET`    | `/api/pricing/models`   | Prețul stabilit în funcție de model.                                                                                                                                      |
| `POST`   | `/api/pricing/sync`     | Declanșează o sincronizare manuală de la surse externe (LiteLLM).                                                                                                         |
| `GET`    | `/api/pricing/sync`     | Starea curentă de sincronizare.                                                                                                                                           |
| `DELETE` | `/api/pricing/sync`     | Ștergeți doar prețurile sincronizate cu LiteLLM (`pricing_synced`); datele model.dev sunt separate.                                                                       |

### Alte efecte relevante pentru cost

| Metodă | Punct final                   | Scop                                                                                               |
| ------ | ----------------------------- | -------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/free-tier/summary`      | Totaluri de jetoane pentru modele gratuite, utilizate în această lună și alocația gratuită rămasă. |
| `GET`  | `/api/quota/pools/[id]/usage` | Utilizare pentru un pool cu cotă partajată.                                                        |

## CLI

CLI-ul OmniRoute expune comenzi pentru costuri, utilizare și prețuri (înregistrate în
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

Un raport de costuri agregat din `/api/usage/analytics`.

```bash
omniroute cost                          # ultimele 30 de zile, grupate după furnizor
omniroute cost --period 7d              # ultimele 7 zile
omniroute cost --group-by model         # grupare după provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

Coloane: grup, solicitări, tokenuri de intrare/ieșire, cost (USD) și % din total. La final
este afișată o linie cu totalul general (suprimată cu `--quiet` sau `--output json`).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # rezumatul costurilor pentru fiecare furnizor
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# Bugete
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` citește `GET /api/pricing/defaults`. Pentru a edita în schimb
> prețurile modelelor individuale, utilizați pagina **Pricing** din panoul de control sau `PATCH /api/pricing`.

## Depanare

- **Toate costurile sunt afișate ca $0 / „Legacy / Free”.** Modelele utilizate nu au nicio intrare de preț.
  Activați sincronizarea externă (`PRICING_SYNC_ENABLED=true`) și rulați `omniroute pricing sync` sau
  setați manual prețurile prin pagina Pricing / `PATCH /api/pricing`.
- **Un model istoric are un preț incorect.** Corectați prețul (prin suprascriere sau resincronizare) — costul este
  recalculat pe baza numărului de tokenuri la fiecare citire a datelor analitice, astfel încât estimările sunt actualizate retroactiv.
- **Cheltuielile sunt afișate cu întârziere față de timpul real.** Cheltuielile per cheie sunt procesate în loturi; reduceți
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` dacă aveți nevoie de valori mai recente.
