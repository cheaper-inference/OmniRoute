## Completări de chat

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Anteturi personalizate

| Antet                    | Direcție | Descriere                                                                                                                                                                                                                                          |
| ------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | Cerere   | Setați la `true` pentru a ocoli memoria cache                                                                                                                                                                                                      |
| `x-omniroute-no-memory`  | Cerere   | Setați la `true` pentru a omite injectarea memoriei și a abilităților pentru această cerere (similar cu opțiunea fără cache; evită costul suplimentar per apel aferent tokenurilor/costurilor)                                                     |
| `X-OmniRoute-Progress`   | Cerere   | Setați la `true` pentru evenimente de progres                                                                                                                                                                                                      |
| `X-Session-Id`           | Cerere   | Cheie de sesiune persistentă pentru afinitatea externă a sesiunii                                                                                                                                                                                  |
| `x_session_id`           | Cerere   | Este acceptată și varianta cu caracter de subliniere (HTTP direct)                                                                                                                                                                                 |
| `X-OmniRoute-Session-Id` | Cerere   | Etichetă de sesiune/conversație furnizată de apelant (folosită și pentru memorie). Când este prezentă, este stocată textual în `call_logs.session_tag` pentru atribuirea costurilor per sesiune (#8249) — nu este generată niciodată când lipsește |
| `Idempotency-Key`        | Cerere   | Cheie de deduplicare (fereastră de 5 s)                                                                                                                                                                                                            |
| `X-Request-Id`           | Cerere   | Cheie de deduplicare alternativă                                                                                                                                                                                                                   |
| `x-omniroute-connection` | Cerere   | Asociază o cerere pentru un singur model cu o conexiune de furnizor (cont) prin ID-ul acesteia — consultați [Asocierea contului per cerere](#account-pinning-per-request)                                                                          |
| `X-OmniRoute-Cache`      | Răspuns  | `HIT` sau `MISS` (fără streaming)                                                                                                                                                                                                                  |
| `X-OmniRoute-Idempotent` | Răspuns  | `true` dacă a fost deduplicată                                                                                                                                                                                                                     |
| `X-OmniRoute-Progress`   | Răspuns  | `enabled` dacă urmărirea progresului este activată                                                                                                                                                                                                 |
| `X-OmniRoute-Session-Id` | Răspuns  | ID-ul efectiv al sesiunii utilizat de OmniRoute                                                                                                                                                                                                    |
| `X-OmniRoute-Request-Id` | Răspuns  | ID-ul de corelare al cererii (când este cunoscut)                                                                                                                                                                                                  |
| `X-OmniRoute-Version`    | Răspuns  | Versiunea compilării OmniRoute (prezentă întotdeauna)                                                                                                                                                                                              |
| `X-OmniRoute-Cost-Saved` | Răspuns  | Suma în USD economisită datorită memoriei cache la un HIT (numai pentru rezultate din cache)                                                                                                                                                       |
| `X-OmniRoute-Decision`   | Răspuns  | Urmărirea rutării: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` este strategia combinației sau `single` pentru o cerere fără combinație) — prezentă întotdeauna în răspunsurile finale                                            |

> Notă Nginx: dacă vă bazați pe anteturi cu caractere de subliniere (de exemplu, `x_session_id`), activați `underscores_in_headers on;`.

#### Fixarea contului pentru fiecare solicitare

Atunci când un furnizor are mai multe conexiuni (conturi sau chei), OmniRoute alege în mod normal una
prin strategia sa de selectare a contului. În schimb, o solicitare poate fixa o anumită conexiune
cu antetul `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <cheia API OmniRoute>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <id-ul conexiunii>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Unde găsiți ID-ul.** Deschideți pagina furnizorului în panoul de control
  (**Panou de control → Furnizori → <furnizor>**) și faceți clic pe cipul de ID `xxxxxxxx…` dintr-un rând
  de conexiune — acesta copiază ID-ul complet al conexiunii.
- **Ce solicitări îl respectă.** Solicitările cu un singur model (`provider/model`) către
  `/v1/chat/completions`, `/v1/messages` și `/v1/responses`. Combinațiile ignoră antetul: fixați
  câte un cont pentru fiecare pas al combinației prin intermediul conexiunii proprii a pasului.
- **Fixarea este strictă, nu o preferință.** Conexiunea fixată este utilizată exclusiv. O
  eroare în cadrul solicitării înregistrează perioada de așteptare a contului, dar **nu** trece la un
  alt cont al aceluiași furnizor.
- **Perioada de așteptare și cota anulează fixarea.** Cât timp conexiunea fixată se află în perioada de așteptare,
  are cota epuizată sau este blocată de o politică de cote, solicitările ulterioare recurg la celelalte
  conexiuni ale furnizorului, exact ca traficul fără fixare.
- **ID-urile necunoscute sau dezactivate provoacă o eroare.** Un ID care nu se află în grupul activ al furnizorului (șters,
  dezactivat sau aparținând altui furnizor) nu lasă niciun cont eligibil, astfel încât solicitarea
  eșuează în loc să fie direcționată în mod silențios în altă parte.

Claude Code trimite anteturi personalizate prin `ANTHROPIC_CUSTOM_HEADERS`. Introduceți-l în blocul `env`
din `~/.claude/settings.json` sau într-un fișier `.claude/settings.json` la nivel de proiect pentru a fixa un
cont diferit pentru fiecare proiect:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<instanța OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<cheia API OmniRoute>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <id-ul conexiunii>",
  },
}
```

Sursă: `src/sse/handlers/chat.ts` (citirea antetului), `src/sse/services/auth.ts` și
`src/sse/services/sessionAffinityPin.ts` (anularea fixării și verificarea absenței din grup).

> **Anteturi de telemetrie a costurilor:** răspunsurile reușite fără streaming includ și setul de telemetrie a costurilor `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, exact 10 zecimale; `0.0000000000` pentru opțiuni gratuite/fără preț), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` și `X-OmniRoute-Fallback-Attempts` (numai când > 0), plus `X-OmniRoute-Request-Id` și `X-OmniRoute-Version`. Acestea sunt emise de completările conversaționale, `/v1/responses`, `/v1/messages`, **precum și de endpointurile media** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` și `/v1/moderations` (cost întotdeauna `0`). Costul media este calculat pentru fiecare modalitate (per imagine, secundă, caracter sau unitate de căutare) atunci când sunt disponibile informații despre prețuri; în caz contrar, este `0` (fail-open).

> **Semantica costurilor pentru accesările cache-ului:** la un HIT în cache-ul semantic (`X-OmniRoute-Cache-Hit: true`) nu se efectuează niciun apel în amonte, astfel încât `X-OmniRoute-Response-Cost` este `0.0000000000` (costul **incremental** al servirii rezultatului din cache). Costul original/care ar fi fost suportat este raportat separat în `X-OmniRoute-Cost-Saved`. Consumatorii datelor de facturare ar trebui să însumeze `X-OmniRoute-Response-Cost` (rezultatele din cache nu costă nimic); sistemele de analiză a cache-ului pot agrega `X-OmniRoute-Cost-Saved`.

## Închirieri exclusive ale sesiunilor gestionate

Închirierea exclusivă a sesiunilor gestionate este un contract de rutare opțional și neutru față de client: un proprietar activ
deține o conexiune OmniRoute eligibilă. Aceasta nu închiriază un model, nu necesită OAuth, nu identifică un
anumit client și nu necesită un anumit furnizor.

Cheia API utilizată pentru autentificare trebuie să aibă domeniul de autorizare `lease:exclusive` și o listă
`allowedConnections` explicită și nevidă. Limita de mutație a bazei de date impune prezența ambelor câmpuri
împreună la crearea cheii și la actualizările parțiale.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Răspunsurile reușite pentru achiziționare, reînnoire și eliberare expun marcajele temporale, `state` și valoarea pozitivă exactă
`generation`, dar niciodată conexiunea selectată sau acreditările. Reînnoirea și eliberarea furnizează
generația în corpul JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Proprietarul unei închirieri active poate solicita explicit metadate de afișare care protejează confidențialitatea pentru asocierea sa curentă:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Această acțiune opțională de verificare a stării este protejată de proprietarul opac, cheia API gestionată autentificată și
generația activă exactă, în cadrul unei singure tranzacții în baza de date. `displayName` reprezintă numai numele configurat
al conexiunii, fără spațiile albe de la extremități; acesta este `null` atunci când nu există un nume configurat sigur. OmniRoute nu îl înlocuiește niciodată cu
o adresă de e-mail sau cu o identitate de cont generată. Valoarea furnizorului este o etichetă de afișare nesensibilă și nu este niciodată
un identificator generat al unui furnizor compatibil. Sunt excluse acreditările, tokenurile, modulele cookie, identificatorii neprelucrați ai conexiunilor sau ai cheilor
API, hashurile proprietarilor, secretele de delimitare și datele interne de rutare.

Căutările cu o cheie greșită, un proprietar greșit, o generație învechită, o închiriere absentă, expirată, eliberată sau invalidată
returnează toate aceeași eroare `409 LEASE_FENCE_STALE`, fără metadatele conexiunii. Un client care a primit răspunsul de așteptare a capacității nu are nicio asociere activă pe care să o poată inspecta. Atunci când rutarea face tranziția unei închirieri active,
aceeași generație rămâne validă, iar starea returnează atomic noua asociere, niciodată pe cea veche.
Clienții existenți rămân neschimbați, deoarece răspunsurile pentru achiziționare, reînnoire, eliberare și așteptare își păstrează
formatele anterioare.

Acest contract de server nu modifică `/status` din versiunea standard OpenAI Codex. În prezent, Codex standard raportează
furnizorul modelului și starea încorporată a autentificării/contului, dar nu afișează metadate arbitrare de cont
pentru furnizori personalizați; o integrare ulterioară în client trebuie să apeleze această acțiune și să decidă cum să
afișeze `connection.displayName`.

Fiecare cerere de inferență gestionată furnizează apoi ambele anteturi de control:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Proprietarul exact, generația, conexiunea activă și cheia API autentificată sunt verificate prin mecanismul de delimitare imediat
înaintea fiecărei încercări acceptate către serviciul din amonte. Reutilizarea proprietarului și a generației cu o altă cheie eșuează chiar
și atunci când cheia respectivă permite aceeași conexiune. Proprietarii în formă brută nu sunt persistați, înregistrați în jurnale, păstrați în
instantaneul cererii și nici redirecționați către serviciul din amonte.

Concurența temporară returnează HTTP `429` cu `Retry-After` și:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Acest răspuns înseamnă doar că setul obișnuit de conexiuni eligibile nu era gol și că fiecare candidat liber era
deținut de o închiriere activă străină. Modelele/furnizorii neacceptați, neconcordanțele cu politica, perioadele de așteptare, cotele,
starea de funcționare și alte eșecuri obișnuite de eligibilitate își păstrează răspunsurile OmniRoute existente.

### `x-omniroute-compression`

Suprascriere per cerere a planului de comprimare. Are prioritatea cea mai mare — prevalează asupra suprascrierii combinației de rutare,
profilului activ, declanșării automate și valorii implicite din panou. Valori:

| Valoare       | Efect                                                                                                                              |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `off`         | Fără comprimare pentru această cerere.                                                                                             |
| `default`     | Profilul implicit derivat din panou (ignoră profilul activ). Motoarele cu pierderi rămân dezactivate.                              |
| `safe`        | Numai deduplicare și compactarea spațiilor albe.                                                                                   |
| `allow-lossy` | Păstrează planul operatorului pentru această cerere, inclusiv rezumatele și rescrierile de stil.                                   |
| `engine:<id>` | Un singur motor, atunci când este activat, de exemplu `engine:rtk`. Activare per cerere pentru acel motor.                         |
| `<combo>`     | O combinație denumită, identificată mai întâi după nume (fără diferențiere între majuscule și minuscule), apoi după identificator. |

Note:

- Valorile necunoscute sunt ignorate (cererea nu este niciodată respinsă); rezoluția revine la ordinea normală de prioritate a operatorului.
- Dacă mai multe combinații au același nume, transmiteți **identificatorul** combinației pentru o potrivire deterministă.
- O combinație al cărei nume este `off` sau `default` nu poate fi selectată după nume (aceste cuvinte-cheie sunt interpretate mai întâi); referiți o astfel de combinație prin identificatorul său.
- Comutatorul principal pentru comprimare este o barieră strictă: când comprimarea este dezactivată global, acest antet nu o poate activa.

Planul aplicat este reprodus în antetul răspunsului:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

unde `<source>` este una dintre valorile `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` sau `off`.

## Embeddings

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Furnizori disponibili: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

ID-urile din catalog au forma `provider/model` (exemplu: `jina-ai/jina-embeddings-v5-omni-small`). ID-urile simple ale modelelor Jina care apar în registru (de exemplu, `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) sunt, de asemenea, rezolvate. Operațiile Jina de încorporare/rerankare/clasificare/segmentare utilizează mai întâi acreditările `jina-ai` din panoul de control; `JINA_AI_API_KEY` este utilizată ca alternativă numai atunci când nu există nicio cheie în panoul de control. Fișa `jina-reader` este destinată exclusiv pentru Reader / `r.jina.ai` (`POST /v1/web/fetch`) și nu furnizează niciodată încorporări sau rerankare.

Modelele din registru care declară suport multimodal acceptă, de asemenea, până la 32 de elemente structurate
independente de furnizor. Tipurile elementelor media sunt `text`, `image`, `audio`, `video` și `document`. Câmpul media `source`
este fie `{"type":"url","url":"https://..."}`, fie
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
și aliasul familiei `jina-ai/jina-embeddings-v5-omni` → omni-small) acceptă, de asemenea, documentele native
EmbeddingsV5Request ale Jina și **le redirecționează intacte** către `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Valorile native `{ image | audio | video | pdf }` pot fi un URL HTTPS public, un URI `data:` sau date brute
base64. OmniRoute nu transformă acele obiecte în șiruri și nu preia URL-urile imaginilor native — Jina preia
direct conținutul media public. Câmpurile Jina suplimentare (`task`, `normalized`, `truncate`, `embedding_type`) sunt
redirecționate. SKU-urile Jina exclusiv text resping în continuare documentele care nu sunt text.

Limite de securitate și transport:

- URL-urile media la distanță trebuie să fie HTTPS publice. Elementele canonice `{type,source:url}` sunt preluate
  pe server (revalidarea redirecționărilor, expirarea timpului, limite de dimensiune, DNS public, fixarea conexiunii) și
  incluse inline înainte de apelul către furnizor. Elementele native Jina `{image:"https://..."}` sunt redirecționate ca atare
  după aceeași verificare HTTPS publică; Jina preia URL-ul.
- Conținutul media base64 inline este limitat la 8 MiB decodați per element și la 16 MiB decodați pentru întreaga cerere.

Conversia pentru furnizori (elementele canonice nu sunt niciodată redirecționate nemodificate):

- Modele multimodale Jina: fiecare element de nivel superior devine un obiect cu o cheie corespunzătoare modalității
  (`text` / `image` / `audio` / `video` / `pdf`), utilizând URI-uri de date pentru conținutul media inline; câte un vector pentru
  fiecare element de nivel superior.
- Familia Gemini Embedding 2: o matrice de nivel superior devine o singură cerere nativă
  `models/{model}:embedContent` cu `content.parts` (`text` sau `inline_data`).
- llama.cpp (`llama-cpp/<model>`, orice model încărcat de serverul local): elementele canonice `text`
  devin șiruri simple, iar `image` / `audio` / `video` devin fiecare câte un obiect
  `{"content": [part]}`, utilizând părțile de conținut pentru chat ale llama-server (`image_url`,
  `input_audio` cu formatul `wav` / `mp3` / `flac`, `input_video`) cu date inline; câte un vector
  pentru fiecare element de nivel superior. Serverul trebuie să ruleze cu `--embedding --mmproj …`; fără un proiector,
  acesta respinge conținutul media. `document` nu este acceptat.
- Modelele necunoscute/dinamice fără metadate explicite despre modalități resping intrările structurate cu HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Combinațiile model/modalitate neacceptate returnează HTTP 400 în loc să convertească forțat elementul. Câmpurile de extensie
care nu fac parte din intrare, din cererile vechi bazate pe șiruri/tokenuri, continuă să fie transmise nemodificate.

```bash
# Listează toate modelele de încorporare
GET /v1/embeddings
```

## Generarea imaginilor

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Furnizorii disponibili includ OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (local), ComfyUI (local).

`n` returnează `n` imagini în `data[]`. Pentru furnizorii al căror API din amonte returnează o singură imagine per apel
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI), sunt efectuate `n` apeluri separate în amonte, dintre care cel mult 4 simultan. O valoare
`seed` fixă este decalată cu indexul apelului (`seed`, `seed + 1`, …), astfel încât imaginile diferă, dar rămân
reproductibile. `n` este limitat la 10. Solicitarea eșuează în întregime dacă oricare dintre apeluri eșuează. Lista
formatelor cu distribuire în evantai este `SINGLE_IMAGE_FANOUT_FORMATS` în
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux reutilizează conexiunea existentă cu cheia API și acceptă prefixele `zenmux/` sau `zm/`:

- `zenmux/openai/gpt-image-2` utilizează API-ul OpenAI Images al ZenMux. Opțiunile includ `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` și `response_format`.
- Alți editori, precum `zm/meta/muse-image-1.0`, utilizează endpointul Vertex AI `:predict`
  al ZenMux. `n` corespunde lui `sampleCount`, `aspect_ratio` lui `aspectRatio`, iar `image_size`
  (`1K`, `2K`, `4K`) lui `sampleImageSize`. O valoare `size` exprimată în pixeli furnizează doar un raport de aspect,
  nu dimensiuni garantate în pixeli. Rapoartele, rezoluțiile și numărul de imagini acceptate variază în funcție de model.
- `zm/inclusionai/ming-image-0.1-design` își alege propriile dimensiuni. Omiteți `size`,
  `aspect_ratio` și `image_size`; valorile explicite returnează HTTP 400. Formatele PNG, JPEG și WebP
  pot fi solicitate cu `output_format`.

Această integrare acceptă generarea text-imagine, nu editarea imaginilor de referință. Rezultatul Vertex
este normalizat în `data[].b64_json`; `response_format: "url"` returnează un URL HTTPS din amonte
sau un URL de date base64 atunci când sunt disponibile doar datele binare ale imaginii. Rezultatele goale/filtrate
returnează o eroare, nu un răspuns reușit gol. Accesul la modele depinde de contul ZenMux.
Consultați [API-ul Vertex al ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) și
[API-ul OpenAI Images](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash

GET /v1/images/generations
```

## OCR pentru documente

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model` selectează furnizorul OCR printr-un prefix `provider/model`; un identificator simplu de model (de ex.
`mistral-ocr-latest`) este asociat furnizorului său înregistrat, iar dacă `model` este omis, valoarea implicită este
Mistral (`mistral-ocr-latest`). Furnizori înregistrați (`open-sse/config/ocrRegistry.ts`):

| ID furnizor                   | ID model             | Valoarea `model`                                               | Note                                                                                                               |
| ----------------------------- | -------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (sau simplu `mistral-ocr-latest`) | Sincron — răspunsul este returnat direct din unicul apel în amonte.                                                |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                    | Proces asincron în amonte (`analyze` + interogare periodică) — consultați detaliile de mai jos.                    |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                        | Sincron, prin endpointul partener Vertex AI `openapi/chat/completions` — consultați mai jos autentificarea/URL-ul. |

Toți cei trei furnizori răspund folosind același corp în format Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Fluxul de interogare periodică Azure Document Intelligence

API-ul `analyze` al Azure Document Intelligence este asincron: solicitarea inițială returnează un antet
`Operation-Location` în locul unui corp, iar rezultatul trebuie interogat periodic. Gestionarul
(`open-sse/handlers/ocr.ts`) interoghează acel URL în fiecare secundă, de cel mult 30 de ori, eșuează imediat (nu
continuă interogarea) dacă răspunsul unei interogări nu este `ok` sau dacă starea este `"failed"` și returnează `504` dacă
operațiunea încă rulează după epuizarea numărului de încercări. Răspunsul Azure final este
normalizat în același format `pages`/`markdown` utilizat de Mistral înainte de a fi returnat
apelantului, astfel încât codul client nu trebuie să trateze furnizorul ca pe un caz special.

### Autentificarea și rezolvarea endpointului pentru Vertex AI DeepSeek OCR

`vertex-deepseek-ocr` reutilizează aceeași autentificare Vertex AI pe care OmniRoute o acceptă deja pentru
traficul de chat/imagini (`open-sse/executors/vertex.ts`): cheia API a conexiunii este fie o
credențială Service Account în format JSON (schimbată cu un token de acces OAuth cu durată scurtă prin fluxul JWT-bearer),
fie un token de acces OAuth deja emis, utilizat ca atare. URL-ul endpointului din amonte este endpointul partener generic
`openapi/chat/completions` al Vertex, construit pe baza proiectului și regiunii conexiunii
— valorile explicite `providerSpecificData.project`/`providerSpecificData.region` au întotdeauna prioritate;
în caz contrar, proiectul este derivat din `project_id` din obiectul JSON al Service Account, iar regiunea
implicită este `us-central1`. Ambele rezolvări au loc în `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) și sunt utilizate de
`src/app/api/v1/ocr/route.ts` înainte de trimiterea către `handleOcr`.

## Listarea modelelor

```bash
GET /v1/models
Authorization: Bearer your-api-key

→ Returnează toate modelele de chat, embedding și imagini + combinațiile, în format OpenAI
```

### Prețurile modelelor (`pricing`)

O intrare conține un obiect `pricing` atunci când OmniRoute cunoaște prețul modelului. Prețul provine
din tabelul de prețuri utilizat pentru contabilizarea costurilor: valorile implicite încorporate, prețurile sincronizate și
suprascrierile configurate prin `/api/pricing`. Acestea sunt prețuri de listă, astfel încât furnizorii pe bază de abonament afișează, de asemenea,
un preț per token.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Câmpuri                                                         | Unitate                    | Note                                                                                                                                                                              |
| --------------------------------------------------------------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | USD per token, șir zecimal | Compatibile cu OpenRouter, niciodată în notație exponențială. Cele două câmpuri pentru cache apar numai atunci când există un preț pentru cache.                                  |
| `input`, `output`, `cached`, `cache_creation`                   | USD per 1M tokeni, număr   | Câmpuri din versiunile anterioare ale catalogului, păstrate pentru clienții existenți. `reasoning` și `long_context` apar, de asemenea, atunci când rândul de prețuri le conține. |

- **Combinațiile** preiau prețul primei lor destinații vizibile. Combinațiile `auto/*` încorporate aleg o
  destinație în momentul solicitării, astfel încât nu au `pricing`.
- **Modelele gratuite** afișează `"0"` (și `0`) atunci când prețul lor este zero. Un model fără un rând de prețuri
  afișează, de asemenea, `"0"` atunci când catalogul îl marchează ca gratuit (`free: true`) sau când catalogul încorporat de modele
  gratuite îl listează.
- **Preț necunoscut:** intrarea nu are cheia `pricing`.
- **Furnizorii contorizați prin credite** (precum Kiro) facturează per solicitare, nu per token. Intrările lor
  păstrează câmpurile numerice per 1M pe care le aveau anterior și nu conțin câmpurile șir per token.
- **Variantele** (id-uri pentru nivelul efortului de raționament, aliasuri fără gândire, oglinzi de descoperire și de gateway)
  copiază prețul modelului către care direcționează.
- Câmpurile conțin numai tarifele de bază. Nivelurile pentru context extins (câmpul numeric `long_context`) și
  multiplicatorii nivelului de serviciu (de exemplu, Codex rapid sau flexibil) nu modifică `prompt` sau
  `completion`.
- Obiectul este același pentru fiecare stil de autentificare, inclusiv pentru o solicitare în stil Anthropic
  cu `x-api-key` și `anthropic-version` (răspunsul rămâne `{ "object": "list",
"data": [...] }`). Implementare: `src/app/api/v1/models/catalogPricing.ts`.

### Prefixele id-urilor modelelor (`?prefix=`)

Majoritatea modelelor sunt publicate sub un **prefix de furnizor**. Prefixul primit este controlat de
indicatorul de funcționalitate `MODELS_CATALOG_PREFIX_MODE` și poate fi suprascris **pentru fiecare solicitare** printr-un
parametru de interogare — util pentru un client care dorește o listă curată fără a modifica setarea la nivelul întregului server
pentru toți ceilalți:

```bash
GET /v1/models?prefix=alias        # un id per model — prefixul scurt al aliasului
GET /v1/models?prefix=dual         # ambele forme (valoarea implicită a serverului)
GET /v1/models?prefix=canonical    # numai prefixul complet al id-ului furnizorului
```

| Mod         | Emite                                                    | Note                                                                                                                                                                                                                            |
| ----------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **și** `claude/claude-sonnet-4-6` | **Implicit.** Ambele id-uri direcționează către același model; sunt păstrate astfel încât configurațiile clienților care au codificat explicit oricare dintre forme să continue să funcționeze. Aproximativ dublează catalogul. |
| `alias`     | `cc/claude-sonnet-4-6`                                   | O intrare per model. Furnizorii fără un alias distinct își emit în continuare intrarea, astfel încât nu se pierde nimic.                                                                                                        |
| `canonical` | `claude/claude-sonnet-4-6`                               | O intrare per model sub prefixul complet al id-ului furnizorului. Furnizorii fără un alias distinct (de exemplu, `antigravity/…`, `agy/…`) își emit și aici unicul id, astfel încât nu se pierde nimic.                         |

O oglindă în modul `dual` poate fi recunoscută și fără parametrul de interogare: conține un câmp `parent`
care indică id-ul principal.

Clienții care afișează un selector de modele ar trebui să solicite `?prefix=alias` — aceasta este abordarea utilizată de
[extensia OmniCopilot pentru VS Code](../guides/VSCODE-COPILOT.md).

### Filtre de descoperire (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` acceptă filtre de descoperire opționale. Fără niciunul dintre acestea, răspunsul rămâne
neschimbat. Acestea restrâng catalogul pe care apelantul îl vede deja (permisiunile cheii API se aplică mai întâi)
și sunt executate înaintea paginării în stil OpenAI cu `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # fiecare capabilitate listată trebuie să fie adevărată
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` din catalog; rândurile fără acesta sunt `chat`
GET /v1/models?q=sonnet&limit=10                           # potrivire fără diferențiere între majuscule și minuscule după id sau nume
```

| Parametru     | Valori                                                                                              |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | număr întreg nenegativ, comparat cu `context_length`                                                |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 de caractere                                                                                  |

O valoare necunoscută sau un `min_context` care nu este un număr întreg nenegativ (de exemplu, `1.5`)
returnează HTTP `400`, iar mesajul enumeră valorile valide. Implementare:
`src/app/api/v1/models/catalogFilters.ts`.

### Lista scurtă de modele (`POST /v1/models/query`)

`POST /v1/models/query` returnează o listă scurtă și deterministă din același catalog, cu aceeași
autentificare și vizibilitate per cheie ca `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Fiecare câmp este opțional. `capabilities` și `exclude` acceptă un tablou sau un șir separat prin virgule;
`max_output` este comparat cu `max_output_tokens`. Rezultatele sunt sortate după `owned_by`, apoi după `id`.
Valoarea implicită pentru `limit` este `20`, iar valorile mai mari de `100` sunt limitate la `100`. Un JSON nevalid, un câmp
necunoscut sau o valoare nevalidă returnează HTTP `400`.

### Modele de chat ascunse individual

Un model marcat ca **Ascuns** pe pagina furnizorului său este exclus din catalog și respins
cu HTTP `404` / `model_not_found` atunci când este solicitat explicit. Verificarea utilizează
furnizorul și modelul rezolvate, inclusiv aliasurile furnizorilor, prefixele nodurilor furnizorilor compatibili și
valorile implicite ale conexiunii. O combinație omite țintele ascunse și poate utiliza o alternativă vizibilă; când nu
mai rămâne nicio țintă executabilă, returnează același cod de eroare. Anularea ascunderii intră în vigoare la următoarea
solicitare. Suprascrierile de vizibilitate destinate exclusiv imaginilor nu ascund modelul de chat cu același ID.

Această setare individuală a modelului este separată de
[listele de permitere/interzicere pentru expunerea modelelor](../routing/MODEL_EXPOSURE_LIST.md), care filtrează
afișarea în catalog și candidații pentru rutarea automată, păstrând în același timp expedierea explicită. Permisiunile
pentru modele ale cheilor API continuă să se aplice independent. Modul implicit pentru prefixele catalogului rămâne `dual`.

### Variante de modele fără gândire

Pentru modelele Claude cu capacități de gândire, `/v1/models` publică și o variantă **fără gândire**, al cărei ID are prefixul `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Selectarea acestui ID (de exemplu, într-o configurație Claude Code care atașează întotdeauna un bloc `thinking`) este rezolvată înapoi la modelul real `<provider>/<model>`, cu raționamentul suprimat — `thinking:{type:"disabled"}` pe ruta `/v1/messages` sau câmpurile `reasoning`/`reasoning_effort` eliminate pe ruta `/v1/chat/completions`. Varianta este listată numai pentru modelele din familia Claude care acceptă gândirea **și** respectă `disabled` (așadar, de exemplu, modelele exclusiv adaptive care resping `disabled` sunt excluse). Operatorii pot activa sau dezactiva forțat varianta pentru fiecare model prin `ModelSpec.noThinkingAlias`.

## Generarea audio ElevenLabs

Configurați în OmniRoute o conexiune la furnizorul `elevenlabs` folosind cheia API ElevenLabs.
Clienții se autentifică folosind cheia lor **OmniRoute** (`Authorization: Bearer $OMNIROUTE_API_KEY`);
gateway-ul furnizează cheia stocată a furnizorului drept `xi-api-key`. Nu trimiteți niciodată o cheie ElevenLabs
drept token bearer pentru gateway.

| Metodă | Cale                        | Răspuns                                     | Categoria endpointului pentru cheia API |
| ------ | --------------------------- | ------------------------------------------- | --------------------------------------- |
| POST   | `/v1/sound-generation`      | Octeți audio nativi                         | `elevenlabs`                            |
| POST   | `/v1/music`                 | Octeți audio nativi                         | `music`                                 |
| POST   | `/v1/music/stream`          | Octeți audio transmiși în flux              | `music`                                 |
| POST   | `/v1/music/detailed`        | Audio multipart nativ și plan de compoziție | `music`                                 |
| POST   | `/v1/music/detailed/stream` | Metadate SSE native și fragmente audio      | `music`                                 |
| POST   | `/v1/music/plan`            | Plan de compoziție JSON                     | `music`                                 |

Aceste endpointuri completează rutele existente `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` și `/v1/speech-to-text`. Câmpurile JSON native
și parametrii de interogare precum `output_format` și `enable_logging` sunt păstrați.
Răspunsurile `/v1/music/detailed` își păstrează delimitatoarele multipart; analizați-le ca multipart.
`/v1/music/detailed/stream` returnează `text/event-stream` cu metadate despre compoziție și
fragmente audio base64 în evenimente SSE. Toate cele șase rute acceptă cereri preliminare CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Un efect sonor scurt. Durată: între 0,5 și 30 de secunde.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Durata muzicii este exprimată în milisecunde: între 3000 și 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Utilizați `/v1/music/stream` cu același corp JSON pentru livrarea audio incrementală. Compoziția
acceptă exact unul dintre `prompt` sau `composition_plan`; `/v1/music/plan` necesită `prompt`
și acceptă opțional `source_composition_plan`. Schemele native păstrează câmpurile suplimentare
ale furnizorului, astfel încât versiunile planului de compoziție și opțiunile de ajustare fină să ajungă la ElevenLabs.

Endpointul unificat `/v1/music/generations` acceptă, de asemenea, `elevenlabs/music_v1`,
`elevenlabs/music_v2` și `elevenlabs/music_v2_5`. Atunci când există o conexiune ElevenLabs activă,
aceste modele sunt expuse în catalogul muzical. Acest endpoint returnează
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Câmpul său `duration` este exprimat în
secunde și este mapat la `music_length_ms`; o valoare `music_length_ms` explicită are prioritate.
`instrumental` este mapat la `force_instrumental`, câmpul nativ având prioritate.
Utilizați endpointurile native de streaming pentru transmiterea în flux și endpointul nativ pentru compoziție
în cazul cererilor bazate exclusiv pe un plan de compoziție.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Restricțiile privind endpointul, modelul, bugetul și conexiunea se aplică înaintea unui apel către serviciul din amonte. Rutele
native returnează neschimbate codurile de stare și corpurile erorilor din amonte, inclusiv `402` pentru o restricție
a planului și `429` pentru o limită de cotă. Anteturile `character-cost`, `song-id`, `request-id` și `retry-after`
sunt păstrate atunci când sunt prezente. Un sold de credite gratuite nu garantează accesul la fiecare
model muzical, format de ieșire sau funcționalitate API: ElevenLabs stabilește drepturile pentru fiecare cerere.
Endpointul unificat păstrează codurile de stare ale erorilor în anvelopa de eroare normalizată a OmniRoute.

Contracte din amonte: [efecte sonore](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[compoziție muzicală](https://elevenlabs.io/docs/api-reference/music/compose) și
[detalii despre muzica transmisă în flux](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> **Noduri furnizor pentru reclasificare:** `POST /v1/rerank` direcționează, de asemenea, solicitările către noduri furnizor compatibile cu OpenAI
> (oMLX, vLLM, Infinity, TEI în spatele unui gateway, …), adresate sub forma `<node-prefix>/<model>`. Nodurile
> loopback (`localhost`, `127.0.0.1`, `172.16.0.0/12`) sunt întotdeauna eligibile, la fel ca numele de gazdă
> enumerate de operator în `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (de exemplu, numele unui serviciu Docker/Compose,
> precum `http://reranker:8080/v1`; acestea sunt apelate direct, niciodată prin `HTTP(S)_PROXY` sau prin
> proxy-ul fixat al unei conexiuni). Nodurile de pe orice altă
> gazdă — un sistem din rețeaua LAN sau un peer Tailscale — sunt eligibile numai atunci când operatorul activează
> indicatorul de funcționalitate `RERANK_REMOTE_PROVIDER_NODES` **și** URL-ul de bază al nodului respectă politica
> privind URL-urile de ieșire ale furnizorului (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Etapa de reclasificare a motorului de memorie apelează această rută prin
> loopback, astfel încât aceeași regulă se aplică pentru `rerankProviderModel` în setările pentru memorie.
>
> **Formatele serverelor locale:** nodul este apelat la `<base>/v1/rerank` și, în cazul unui răspuns 404, la `<base>/rerank`
> (Infinity, TEI). Corpul solicitării din amonte include atât denumirile Cohere/OpenAI (`documents`,
> `return_documents`), cât și denumirile TEI (`texts`, `return_text`), iar răspunsul din amonte este
> normalizat la anvelopa Cohere: răspunsul simplu TEI `[{index, score, text}]`, răspunsul `{results: [{index, score}]}`
> de la gateway-uri minimale și răspunsul de tip Voyage `{data: [...]}` sunt toate returnate clientului sub forma
> `{results: [{index, relevance_score, document?}]}`, sortate după scor și limitate la `top_n`.

> **Descoperirea nodurilor furnizor:** modelele de pe un nod furnizor compatibil cu OpenAI apar în `GET /v1/models`
> sub prefixul nodului. Rândurile care nu conțin metadate despre punctele finale (situație tipică pentru listările locale `/v1/models`)
> moștenesc valoarea `apiType` a nodului, astfel încât modelele unui nod `embeddings` au `type: "embedding"`, iar modelele unui
> nod `rerank` au `type: "rerank"`, în loc să utilizeze în mod implicit tipul de chat; o valoare explicită
> `supportedEndpoints` dintr-un rând sincronizat sau adăugat manual are în continuare prioritate.

### `provider_options` pentru Exa și Tavily

Exa și Tavily citesc câmpurile specifice furnizorului dintr-un obiect cu spațiu de nume:
`provider_options.exa` (sau `provider_options["exa-search"]`) și `provider_options.tavily`
(sau `provider_options["tavily-search"]`). Sunt transmise mai departe doar cheile de mai jos. Fiecare este
verificată în raport cu propria schemă Zod din `open-sse/handlers/search/providerOptionsPassthrough.ts`,
iar o cheie cu un tip incorect este eliminată. Orice altă cheie este ignorată, inclusiv autentificarea, URL-ul de bază,
`stream` și `outputSchema`. Cheile fără imbricare utilizate de alți furnizori (`cx`, `depth`, ...) funcționează
ca înainte.

| Furnizor | Câmpuri de nivel superior                                                                                                                                                                                                                                                                                                                                                 | Imbricate                                                                                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa      | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (primitive fără imbricare), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                     | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` îmbinate peste valoarea implicită `{ text: true, highlights: true }` |
| Tavily   | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                           |

Câmpurile generice au întotdeauna prioritate: `query`, `max_results`, `filters` (domenii), `country` și
subiectul derivat din `search_type`. Pentru Exa, `search_type: "news"` păstrează `category: "news"`.
Tavily acceptă și `search_type: "finance"` (`topic: "finance"`).

Câmpul generic `time_range` ajunge acum la ambii furnizori: Exa primește `startPublishedDate` (marcaj temporal ISO),
iar Tavily primește `start_date` (`YYYY-MM-DD`). O dată explicită din `provider_options`
o suprascrie pe cea mapată.

Rezultatele Exa păstrează `id`, `highlight_scores`, `summary`, `subpages`, `entities` și `extras` în
`provider_raw`. Rezultatele Tavily păstrează `images` și `favicon`.

Contabilizarea costurilor utilizează în continuare registrul fără imbricare `costPerQuery`. Tavily facturează
`search_depth: "advanced"` cu mai multe credite per apel, iar această diferență nu este reflectată în
`usage.search_cost_usd`.

## API de preluare web

Extrage conținutul dintr-un URL prin intermediul unui furnizor de preluare web configurat (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, aceeași cheie API ca pentru Parallel Search) returnează numai Markdown
— orice alt `format` generează un `400` — și limitează conținutul la 100.000 de caractere. Atunci când
pagina-țintă nu poate fi extrasă, serviciul din amonte raportează acest lucru într-un răspuns HTTP 200;
OmniRoute îl expune ca `422`, cu un mesaj fix.

| Metodă | Cale            | Descriere                                                 |
| ------ | --------------- | --------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Preia/extrage un URL — corp validat de `v1WebFetchSchema` |

**Autentificare:** cheie API Bearer (`extractApiKey` + `isValidApiKey`). Politica este aplicată prin `enforceApiKeyPolicy`.

**Revenire alternativă în funcție de cotă (#8297):** când nu este furnizat niciun `provider` explicit, lista
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) este
parcursă într-o ordine fixă
de prioritate (se utilizează primul disponibil) — un furnizor configurat, dar limitat ca rată, este omis
în loc să întrerupă imediat cererea, iar o eroare reîncercabilă/de cotă a serviciului din amonte
(HTTP 429 întotdeauna; 402/403 pentru nivelurile gratuite de tip cotă ale Firecrawl/Tavily/TinyFish —
nu pentru Jina Reader și niciodată pentru o cerere simplă incorectă 400) determină trecerea la
următorul furnizor neîncercat pentru care există acreditări, în momentul cererii. Când toți furnizorii din
listă sunt epuizați, endpointul returnează un singur `429` (cu un antet `Retry-After`)
în locul răspunsului generic `400` anterior. Când este solicitat un `provider` explicit,
**nu** există revenire alternativă silențioasă — un furnizor explicit limitat ca rată sau care eșuează
își expune propria eroare (`429` dacă este limitat ca rată, în caz contrar starea
serviciului din amonte).

### API-ul Responses prin WebSocket (numai codex)

`/responses` și `/api/v1/responses`. La primul cadru `response.create`, acesta

**Autentificare:** cheie API Bearer în timpul negocierii. Serverul HTTP inclus (`server-ws.mjs`)

#### ID-ul modelului: utilizați ID-ul ChatGPT simplu (fără prefixul `codex/`)

**Codex CLI** de la OpenAI validează numele modelului pe partea clientului atunci când

unei configurații existente):


## Utilizare în regim self-service (`/api/usage/om-usage`)

Orice cheie API își poate citi **propria** utilizare și propriile cote — fără autentificare de administrare. Acesta este endpointul pe care un
client (CLI, panoul OmniCopilot) îl utilizează pentru a-i afișa titularului unei chei consumul său.

```bash
# Format text (contractul istoric — text simplu pentru un terminal)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Format structurat — ceea ce utilizează o interfață cu utilizatorul
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Cheia trebuie să aibă activată opțiunea **`allowUsageCommand`** (dezactivată implicit — managerul de chei API al tabloului de bord
o comută individual pentru fiecare cheie). Fără aceasta, endpointul răspunde cu `403`.

`?format=json` returnează o structură discriminată, astfel încât un apelant să nu citească niciodată un câmp de date dintr-un
refuz. În caz de succes:

```jsonc
{
  "allowed": true,
  // prezent numai când cheia a optat pentru limite de utilizare per cheie (USD zilnic/săptămânal):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // instantaneul de cotă al furnizorului selectat sau null când încă nu există nimic în cache:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // instantaneul fiecărei conexiuni, astfel încât o interfață să poată reda mai mulți furnizori unul lângă altul:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

În caz de refuz (`401` cheie incorectă / `403` acces nepermis), aceeași rută returnează
`{ "allowed": false, "error": { "message": "…" } }` — un câmp `personal`/`provider` prezent, dar gol
(cheie permisă, încă nu s-a obținut nicio informație) reprezintă o stare diferită de un refuz, iar numai formatul JSON
le diferențiază.

**Autentificare:** propria cheie API Bearer a apelantului, validată cu `isValidApiKey` — aceasta _nu_ este
suprafața de administrare (`/api/keys/…`), care rămâne protejată de `requireManagementAuth`.

### Procente brute față de procentele cotelor ajustate în funcție de pragul de întrerupere

Când utilizează `/api/usage/om-usage`, apelanții trebuie să observe diferența dintre
procentele prezentate în **rezultatul în text simplu** și în rezultatul structurat în format **JSON**:

| Aspect                   | Format text simplu (`/api/usage/om-usage` / `@@om-usage`)                                        | Format JSON (`?format=json`)                                                             |
| :----------------------- | :----------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------- |
| **Câmp de ieșire**       | `NN% left` (de exemplu, `20% left`)                                                              | `provider.quotas` / `providers[].quotas`                                                 |
| **Măsurare**             | **Capacitate utilizabilă ajustată în funcție de prag**: capacitatea rămasă peste pragul limită   | **Cotă brută din amonte**: măsurătoarea neajustată a furnizorului                        |
| **Scalarea pragului**    | Scalată prin `effectiveRemainingPercent()`, astfel încât rezerva protejată să apară ca `0% left` | Niciuna (valori brute ale instantaneului, așa cum sunt raportate de furnizor)            |
| **Date despre prag**     | Incluse în procentul afișat                                                                      | Stocate în `quotaWindowThresholds` per conexiune (sau valorile implicite ale serverului) |
| **Consumator principal** | CLI-uri interactive, prompturi de terminal, operatori umani                                      | Integrări programatice, tablouri de bord, analize, sisteme de urmărire a facturării      |

#### Formula de ajustare în funcție de pragul de întrerupere

OmniRoute acceptă praguri proactive de întrerupere a cotelor pentru a preveni epuizarea resurselor din amonte (configurate prin
`quotaWindowThresholds` ale conexiunii, valorile implicite ale furnizorului sau setările globale de reziliență). Când un prag de întrerupere
(de exemplu, `cutoff = 25%`) este activ într-o fereastră de cotă, componenta de redare a textului calculează capacitatea rămasă astfel:

- Dacă `remaining <= cutoff`: returnează `0%`.
- Dacă `remaining > cutoff`: returnează `((remaining - cutoff) / (100 - cutoff)) * 100`.

Rezultatul text formatat este rotunjit la cel mai apropiat număr întreg (`Math.round(...)`).

#### Exemplu ilustrativ

Luați în considerare o fereastră a furnizorului cu **60% utilizare brută** (așadar, **40% cotă brută rămasă**) și un prag configurat de
**25% din cota rămasă**:

| Reprezentare                   | Calcul                                             |  Rămas  |              Utilizare implicită               |
| :----------------------------- | :------------------------------------------------- | :-----: | :--------------------------------------------: |
| **JSON brut (`?format=json`)** | Instantaneu din amonte (`quotas[window]`)          | **40%** |                    **60%**                     |
| **Format text (`NN% left`)**   | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (dacă se calculează `100 - remaining`) |

- **De ce textul afișează 20% rămas:** Din cota fizică de 40% rămasă în cont, 25% este rezervată de
  politica pragului de întrerupere. Apelantului îi mai rămân doar 15% din marja utilizabilă de 75% înainte ca routerul să oprească
  direcționarea către această conexiune. Scalarea asigură faptul că o conexiune semnalează epuizarea (`0% left`) exact atunci când
  direcționarea va înceta.
- **De ce JSON păstrează valorile brute:** Sarcina utilă JSON returnează instantaneul exact al furnizorului (`UsageSnapshot`),
  astfel încât instrumentele externe să aibă acces la utilizarea reală din amonte și la
  `quotaWindowThresholds` la nivel de conexiune, fără scalări cu pierderi efectuate pe server.

#### Ghid de migrare pentru consumatori

Dacă o integrare externă (cum ar fi un plugin pentru editor sau o extensie de agent) extrăgea anterior datele din endpointul
text (`NN% left`) și calcula procentul utilizat ca `100 - NN`, migrarea la `?format=json` înseamnă:

- Citirea valorilor JSON brute va reflecta **consumul real din amonte** (60% utilizat în exemplul de mai sus).
- Dacă integrarea dorește să păstreze semantica alocației utilizabile a endpointului text, aceasta poate evalua
  formula efectivă pentru resursele rămase pe partea de client, utilizând `quotaWindowThresholds` pentru suprascrieri la nivel de conexiune.

### Impactul asupra latenței

O potrivire în cache-ul semantic (HIT) furnizează răspunsul din cache **fără un
apel în amonte**, astfel încât valoarea raportată pentru `X-OmniRoute-Response-Latency` este aproape de zero
(indiferent de latența inițială din amonte). Clienții sensibili la latență
(benchmarking, monitorizare p50/p99) ar trebui să verifice antetul de răspuns
`X-OmniRoute-Cache-Latency`:

| Valoare     | Semnificație                                                       |
| ----------- | ------------------------------------------------------------------ |
| `synthetic` | Răspuns furnizat din cache; latența nu este timpul real din amonte |
| _(absent)_  | Răspuns provenit dintr-un apel real în amonte                      |

### Ocolirea cache-ului per cheie

Cheile API pot renunța la citirile din cache-ul semantic prin `cacheDefaultMode`:

| Valoare  | Comportament                                                                    |
| -------- | ------------------------------------------------------------------------------- |
| `legacy` | Comportament normal al cache-ului (implicit)                                    |
| `bypass` | Omite complet verificarea cache-ului; apelează întotdeauna serviciul din amonte |

Setați la crearea cheii (`POST /api/keys`) sau la actualizare (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### Ocolirea per solicitare

Orice solicitare poate ocoli cache-ul, indiferent de setările cheii:

```

```

Pentru modelele sincronizate/importate, `PUT /api/provider-models` acceptă `provider`, `modelId` și

test de conexiune reușit selectează automat controalele șablonului de chat pentru fiecare ID exact de model
a cărui intrare `/models` confirmă o valoare `owned_by` recunoscută: `vllm`, `sglang` sau `llamacpp`.
Wrapperele transparente compatibile cu OpenAI pot păstra intrarea originală a modelului într-un obiect
`openai` imbricat; detectarea urmărește până la trei astfel de niveluri de încapsulare. Modelele cu informații de proprietate lipsă, necunoscute sau
contradictorii păstrează comportamentul OpenAI obișnuit. Detectarea reutilizează solicitarea existentă către catalog,
nu generează tokenuri de completare și este invalidată atunci când endpointul conexiunii se modifică.

pentru actualizarea parțială a furnizorului:

```json

    "reasoningControl": "chat-template"
  }
}
```

Trimiteți acest corp cu `PUT /api/providers/<connection-id>`. Pentru conexiunea respectivă, un efort explicit
de raționament de tip `none` este trimis ca `chat_template_kwargs.thinking=false` și
`chat_template_kwargs.enable_thinking=false`. Valorile native explicite ale șablonului rămân decisive,
cu excepția cazului în care o regulă de raționament de pe server impune un anumit efort. Setarea se aplică numai atunci când o conexiune
personalizată compatibilă cu OpenAI expediază un corp Chat Completions; solicitările Responses și furnizorii
obișnuiți își păstrează structura nativă a solicitării. Setați `reasoningControl` la `openai` pentru a impune transmiterea
obișnuită a valorii OpenAI `reasoning_effort` sau omiteți-l/setați-l la `null` pentru a utiliza detectarea automată.

Solicitările clasificatorului Claude Code în modul automat dezactivează implicit raționamentul nativ atunci când nu conțin
controale explicite de raționament. Detectarea utilizează marcatorul de sistem al clasificatorului din solicitările în format Claude,
nu numele modelelor sau limitele de completare. Controalele explicite din corp, anteturile acceptate pentru efort/raționament,
regulile de rutare și efortul rezolvat al modelului își păstrează prioritatea existentă. Ambele etape ale clasificatorului
își păstrează prompturile, limitele de completare, secvențele de oprire și deciziile reale privind permisiunile din amonte;
a doua etapă poate produce în continuare raționamentul vizibil solicitat ca text obișnuit.

### Versiune și canal de lansare

```bash
GET /api/system/version
```

Rută de administrare disponibilă numai prin loopback (autentificare de administrator). Returnează versiunea rulată, cea mai recentă
versiune publicată și starea actualizării automate. `releaseChannel` și `channels` sunt câmpuri
aditive (seria 3.8.54); `channel` își păstrează semnificația — modul de implementare utilizat de
componenta de actualizare a tabloului de bord (`npm`, `source` sau `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — canalul npm al compilării rulate: `nightly` pentru versiunile `-nightly.*`,
  `next` pentru alte versiuni preliminare (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` pentru o versiune stabilă
  dintr-o versiune majoră mai veche decât `channels.latest`, iar în caz contrar `latest`. Aceleași reguli ca în
  `scripts/release/dist-tag.mjs`, care selectează eticheta de distribuție npm în momentul publicării.
- `channels` — cea mai recentă versiune publicată pentru fiecare etichetă de distribuție, obținută prin `npm view omniroute dist-tags` (cu
  revenire la HTTP pentru registru), memorată în cache cu același TTL de 10 minute ca `latest`. `latest` este prezent întotdeauna
  (revine la câmpul `latest`, apoi la `"unavailable"`); `next`, `nightly` și `lts` apar
  numai atunci când există eticheta de distribuție respectivă. O solicitare `Cache-Control: no-cache` reîmprospătează ambele interogări.

Modelul de canale (`latest` = v3 până la versiunea GA 4.0, `next` = rc, `nightly` = compilări `develop`,
`lts` = corecții v3 după versiunea GA 4.0) este descris în `docs/ops/RELEASE_STRATEGY.md`.

## Transcriere audio

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data
```

Transcrieți fișiere audio utilizând orice furnizor STT configurat. Primul segment
al căii selectează furnizorul nativ (`openai/…`, `deepgram/…`). Gateway-urile care
reexportă modelul altui furnizor utilizează un identificator calificat
(`openrouter/deepgram/nova-3`).

**Cerere:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**Răspuns:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**Exemple de identificatori de modele:** `openai/whisper-1` (necesită o cheie OpenAI),
`openrouter/deepgram/nova-3` (necesită o cheie OpenRouter),
`deepgram/nova-3` (necesită o cheie Deepgram nativă). O cerere simplă
`deepgram/nova-3` **nu** utilizează OpenRouter.

**Formate acceptate:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`.

## Aliasuri VS Code tokenizate / fără antet

Utilizați aceste aliasuri atunci când o integrare nu poate injecta un antet `Authorization` și necesită încorporarea cheii API în URL-ul de bază.

```bash
# Alias pentru catalog în stil OpenAI
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# Aliasuri pentru chat în stil OpenAI
POST /api/v1/vscode/{token}/chat/completions
POST /api/v1/vscode/{token}/responses

# Aliasuri în stil Ollama
POST /api/v1/vscode/{token}/api/chat
GET /api/v1/vscode/{token}/api/tags
```

Exemplu:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'
```

Note:

- Aliasurile tokenizate reutilizează aceleași rutine de gestionare ca `/v1/*` și `/api/tags`; structurile răspunsurilor rămân identice.
- Preferați `Authorization: Bearer ...` ori de câte ori clientul acceptă antete personalizate.
- Tokenurile bazate pe URL pot apărea în jurnalele proxy-ului invers, istoricul browserului și telemetria din afara OmniRoute. Tratați-le ca pe o opțiune de compatibilitate, nu ca pe modul implicit de autentificare.

> **Note privind schema** (`setBudgetSchema`): `apiKeyId` este obligatoriu; cel puțin unul dintre `dailyLimitUsd`, `weeklyLimitUsd` sau `monthlyLimitUsd` trebuie să fie mai mare decât zero. Câmpuri opționale: `warningThreshold` (0–1), `resetInterval` (`daily` | `weekly` | `monthly`), `resetTime` (`HH:MM`). Formatul vechi `{keyId, limit, period}` returnează `400 Bad Request`.

## Limite de tokenuri

Bugete de **tokenuri** per cheie API (distincte de Bugetul bazat pe USD de mai sus). Aplicate direct în fluxul de procesare a solicitării: când utilizarea din fereastra curentă a unei chei atinge limita, solicitările sunt respinse cu `429 Too Many Requests`. Limitele pot fi restrânse la un anumit `model`, la un `provider` sau aplicate la nivel `global` pentru întreaga cheie; când mai multe limite corespund unei solicitări, se aplică cea mai restrictivă.

```bash
# Listează limitele de tokenuri ale unei chei (include utilizarea curentă din fereastră)
GET /api/usage/token-limits?apiKeyId=key-123

# Creează sau actualizează o limită de tokenuri
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Șterge o limită de tokenuri după id
DELETE /api/usage/token-limits?id=tl-abc
```

> **Note privind schema** (`setTokenLimitSchema`): `apiKeyId` și `scopeType` (`model` | `provider` | `global`) sunt obligatorii. `scopeValue` este obligatoriu, cu excepția cazului în care `scopeType` este `global` (de exemplu, un id de model pentru domeniul `model`, un id de furnizor pentru domeniul `provider`). `tokenLimit` trebuie să fie un număr întreg pozitiv (convertit din șir de caractere). Opționale: `id` (omiteți-l pentru creare, furnizați-l pentru actualizare), `resetInterval` (`daily` | `weekly` | `monthly`, valoare implicită `monthly`), `resetTime` (`HH:MM`), `enabled` (valoare implicită `true`). Răspunsurile `GET` îmbogățesc fiecare limită cu `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` și `nextResetAt`. Acesta este un endpoint din categoria de administrare (autentificarea este impusă centralizat de fluxul de autorizare).

## Procesarea solicitărilor

1. Clientul trimite solicitarea către `/v1/*`
2. Gestionarul rutei apelează `handleChat`, `handleEmbedding`, `handleAudioTranscription` sau `handleImageGeneration`
3. Modelul este identificat (furnizor/model direct sau alias/combinație)
4. Credențialele sunt selectate din baza de date locală, cu filtrare în funcție de disponibilitatea contului
5. Pentru chat: `handleChatCore` verifică memoria cache semantică/de semnături și determină setările de compresie ale combinației
6. Compresia proactivă rulează înaintea traducerii pentru furnizor atunci când este activată (`lite`, Caveman, RTK sau în mod suprapus)
7. Executorul furnizorului trimite solicitarea către serviciul din amonte
8. Răspunsul este tradus înapoi în formatul clientului (chat) sau returnat ca atare (încorporări/imagini/audio)
9. Utilizarea, datele analitice privind compresia și jurnalele solicitărilor sunt înregistrate
10. Mecanismul de rezervă se aplică în caz de erori, conform regulilor combinației

Referință completă privind arhitectura: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Reziliență (extinsă)

OmniRoute oferă trei mecanisme independente pentru gestionarea defecțiunilor temporare; endpointurile de administrare de mai jos le permit operatorilor să le consulte și să le suprascrie:

| Domeniu de aplicare                | Stocarea stării                                       | Consultare                                | Resetare / ștergere                                           |
| ---------------------------------- | ----------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------- |
| Circuit breaker al furnizorului    | `domain_circuit_breakers` + în memorie                | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                  |
| Perioadă de așteptare a conexiunii | `rateLimitedUntil` pentru conexiunile furnizorilor    | `/api/rate-limits`, `/api/providers/[id]` | (se reactivează la nevoie; ștergere prin PUT pentru furnizor) |
| Blocarea modelului                 | Registru în memorie pentru disponibilitatea modelelor | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                      |

`PATCH /api/resilience` acceptă suprascrieri pentru circuit breaker-ul furnizorului în `providerBreaker.oauth` și `providerBreaker.apikey`. Fiecare profil acceptă `degradationThreshold`, `failureThreshold` și `resetTimeoutMs`; aceleași câmpuri sunt disponibile în Panou de control → Setări → Reziliență.

```bash
# Șterge blocarea unui singur model
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Șterge toate blocările
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Pentru referința conceptuală completă și valorile implicite ale circuit breaker-ului, consultați [`CLAUDE.md`](../../CLAUDE.md) → „Starea de execuție a rezilienței” și [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Coada pentru limitarea ratei și mecanismul de siguranță pentru activarea automată

- **Cale de scriere acceptată**: `POST /api/rate-limits` cu corpul `{"connectionId": "<id>", "enabled": true|false}` este endpointul de administrare acceptat pentru activarea sau dezactivarea protecției împotriva limitării ratei pentru o conexiune. `PUT /api/providers/[id]` nu modifică și nu comută în mod deliberat `rateLimitProtection` (#11278).
- **Semantica pentru `enabled: false`**: Setarea `enabled: false` elimină protecția explicită pentru conexiune, dar **nu** exclude o conexiune activă cu cheie API din mecanismul global de siguranță pentru activarea automată (`autoEnableApiKeyProviders = true`). În `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), `false` și `undefined` sunt echivalente; conexiunile active cu cheie API fără protecție explicită rămân protejate prin mecanismul de siguranță pentru activarea automată.
- **Dezactivare globală**: Pentru a utiliza conexiuni cu cheie API fără cozi de limitare a ratei, dezactivați global mecanismul de siguranță prin `RATE_LIMIT_AUTO_ENABLE=false` (variabilă de mediu) sau `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Setări → Reziliență / `PATCH /api/resilience`).

## Server A2A

OmniRoute expune un endpoint A2A (Agent-to-Agent) JSON-RPC 2.0, precum și un wrapper REST pentru inspectare/utilizare în panoul de control.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # opțional, cu excepția cazului în care OMNIROUTE_API_KEY este setată
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Metode acceptate (toate condiționate de `settings.a2aEnabled`):

| Metodă           | Descriere                                                                  |
| ---------------- | -------------------------------------------------------------------------- |
| `message/send`   | Executarea sincronă a abilității; returnează `{task, artifacts, metadata}` |
| `message/stream` | Executarea prin flux SSE a aceluiași set de abilități                      |
| `tasks/get`      | Preia o sarcină după `taskId`                                              |
| `tasks/cancel`   | Anulează o sarcină după `taskId`                                           |

Abilități încorporate: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

```bash
GET /.well-known/agent.json
```

Returnează fișa publică a agentului A2A (nume, descriere, capabilități, catalog de abilități, schemă de autentificare) — stocată în cache public timp de 1 h. Nu este necesară autentificarea.

**Autentificare:** utilitarele REST rulează fără autentificare de administrare (pot fi citite de panoul de control); ruta JSON-RPC `/a2a` utilizează Bearer `OMNIROUTE_API_KEY` dacă este configurată.

## Autentificare

Consultați [Autentificarea pentru administrare](../guides/MANAGEMENT-AUTH.md) pentru cele patru
familii de credențiale (sesiune de panou de control, token CLI local, token de acces
`oma_live_…`, cheie API cu domeniu de administrare) și diferențele dintre acestea și cheile de inferență.

- Rutele panoului de control (`/dashboard/*`) utilizează cookie-ul `auth_token`
- Autentificarea utilizează hashul parolei salvate; alternativ, utilizează `INITIAL_PASSWORD`
- `requireLogin` poate fi activat sau dezactivat prin `/api/settings/require-login`
- Rutele `/v1/*` necesită opțional o cheie API Bearer când `REQUIRE_API_KEY=true`
- În această documentație de referință, „token de administrare” / „cheie API cu domeniu de administrare” înseamnă una dintre familiile descrise în ghidul respectiv — nu un tip suplimentar de secret nedefinit

> **Modificare incompatibilă (v3.8.0)** — `/api/v1/agents/tasks/*` și endpointurile de administrare a perioadei de așteptare necesită acum **autentificare pentru administrare** (cookie-ul `auth_token` al panoului de control sau o cheie API cu domeniu de administrare). Clienții care apelau anterior aceste rute fără autentificare vor primi `401 Unauthorized`. Consultați commitul `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
