> Comutatoare de execuție care modifică comportamentul OmniRoute **fără o redeployare**.
> Fiecare flag enumerat aici este definit în
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — sursa unică de adevăr. Atât panoul de control, cât și API-ul REST citesc din
> acel fișier, astfel încât tabelul de mai jos este generat pentru a corespunde 1:1.

---

## Ce sunt flagurile de funcționalitate

Un flag de funcționalitate este un comutator cu nume (boolean sau enum) a cărui valoare poate fi modificată în
timpul execuției și salvată în baza de date, fără a necesita redeployarea procesului. Fiecare
flag este descris printr-un `FeatureFlagDefinition` cu un `key`, `label`,
`description`, `category`, `defaultValue`, `type` și un indicator `requiresRestart`.

### Ordinea de rezolvare

**Valoarea efectivă** a unui flag este rezolvată de
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) conform următoarei
ordini de prioritate (cea mai mare are întâietate):

1. **Suprascriere din BD** — o valoare stocată în tabelul `key_value` sub spațiul de nume
   `feature_flags` (setată prin panoul de control sau prin API-ul REST).
2. **Variabilă de mediu** — `process.env[<KEY>]`, dacă este setată și nu este goală.
3. **Valoarea implicită din definiție** — `defaultValue` din `featureFlagDefinitions.ts`.

Un flag boolean este considerat **activat** atunci când valoarea sa efectivă este `"true"`,
`"1"` sau `"yes"` (consultați `isFeatureFlagEnabled()`).

> [!NOTE]
> Majoritatea flagurilor au și o variabilă de mediu corespunzătoare, cu **același nume**,
> documentată în [`ENVIRONMENT.md`](./ENVIRONMENT.md). Suprascrierea din BD a flagului
> are prioritate față de variabila de mediu respectivă. Un flag cu
> `requiresRestart: true` este salvat imediat, dar este recitit numai la pornirea
> procesului — comutarea acestuia afișează un banner **„Reporniți serverul”** în panoul de control.

116 flaguri în 6 categorii. **Implicit** este valoarea implicită a definiției — valoarea
utilizată atunci când nu este prezentă nici o suprascriere în DB, nici o variabilă de mediu.

## Comutarea indicatorilor

### Panou de control

Navigați la **Dashboard → Settings → Feature Flags**
(`/dashboard/settings/feature-flags`). Grila
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
acceptă:

- **Căutarea** după cheie sau descriere și **filtrarea** după categorie (plus o vizualizare sintetică
  **Requires Restart**).
- Un **comutator** pentru indicatorii booleeni și un **meniu derulant** pentru indicatorii enum
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- O insignă de **sursă** pentru fiecare indicator — `DB`, `ENV` sau `DEF` — care arată de unde provine valoarea efectivă.
- Un buton **Reset** (afișat doar pentru indicatorii cu sursa `DB`) pentru eliminarea suprascrierii și un buton **Reset All Overrides** în partea de jos.
- Un banner **Restart Server** atunci când este modificat un indicator `requiresRestart`.

### API REST

Toate operațiunile trec printr-o singură rută:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Fiecare metodă necesită o sesiune autentificată de panou de control (`401` în caz contrar).

#### `GET /api/settings/feature-flags`

Returnează fiecare indicator împreună cu valoarea efectivă, sursa și un rezumat.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... toți cei 116 indicatori
  ],
  "summary": {
    "total": 116,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Setează sau elimină o singură suprascriere. Corpul cererii: `{ key: string; value?: string }`.
Omiterea lui `value` elimină suprascrierea (restabilind valoarea din env / valoarea implicită).

```bash
# Setează o suprascriere DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Elimină suprascrierea (fără "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Răspunsul repetă noua `effectiveValue`/`source`, `previousValue`/
`previousSource` și `requiresRestart`. Cheile necunoscute și valorile enum
în afara intervalului acceptat sunt respinse cu `400`.

#### `DELETE /api/settings/feature-flags`

Șterge **toate** suprascrierile DB simultan, restabilind pentru fiecare indicator valoarea din env / valoarea implicită. Returnează `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Indicatorii cu `requiresRestart: true` intră în vigoare doar după reîncărcarea procesului.
> Fluxul de repornire al panoului de control apelează `POST /api/restart`, apoi interoghează periodic
> `GET /api/health/ping` până când serverul este din nou disponibil.

## Mecanism de rezervă de urgență pentru buget

`OMNIROUTE_EMERGENCY_FALLBACK` (categoria `runtime`, valoarea implicită `true`) controlează
ruta gratuită de rezervă pentru situații de urgență din
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Când este activată, solicitările care își epuizează bugetul sunt direcționate către un
furnizor/model de rezervă gratuit, în loc să eșueze complet. Setați-o la `false` (sau `0`) — prin
comutatorul din panoul de control, o suprascriere în DB sau variabila de mediu
`OMNIROUTE_EMERGENCY_FALLBACK` — pentru a dezactiva acest comportament și a permite solicitărilor
cu bugetul epuizat să eșueze. (Expusă sub forma unui comutator în panoul de control în PR-urile #3741 / #3752.)

Un răspuns furnizat prin acest mecanism de rezervă conține
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, astfel încât un
client să poată identifica faptul că solicitarea a fost redirecționată fără a compara `X-OmniRoute-Provider` cu
solicitarea sa. Antetul lipsește din toate celelalte răspunsuri.
