OmniRoute se integrează cu furnizori ale căror infrastructuri de margine identifică activ clienții neoficiali prin amprentare (TLS JA3/JA4, ordinea antetelor, structura corpului JSON, tokenuri de integritate). Această pagină documentează suprafețele de disimulare expuse de OmniRoute și locurile în care sunt implementate.

## Notificare juridică și etică

Funcționalitățile de disimulare există pentru ca OmniRoute să poată acționa ca strat de compatibilitate între conturile oficiale deținute de utilizatori (Claude Code CLI, Codex, Antigravity, Cursor etc.) și API-ul unificat al OmniRoute. Acestea **nu** sunt destinate evitării detectării fraudelor, partajării credențialelor sau încălcării Condițiilor de utilizare ale furnizorilor. Responsabilii de întreținere se așteaptă ca operatorii să respecte condițiile de utilizare ale furnizorilor din amonte pe care le-au acceptat la crearea conturilor.

## Strat de amprentare TLS

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Sesiunile persistente `wreq-js` sunt create la cerere pentru fiecare domeniu al contului și proxy rezolvat. Instanța `TlsClient` la nivel de proces păstrează în pool cel mult 128 de sesiuni care simulează **Chrome 124 pe macOS** pentru serviciile upstream aflate în spatele Cloudflare. `TlsClient.fetch()` eșuează în mod sigur atunci când runtime-ul nativ nu este disponibil; un apelant poate selecta explicit o soluție de rezervă în afara acestui wrapper.

- Profilul sesiunii: `browser: "chrome_124", os: "macos"`
- Rezolvarea proxy-ului (prioritate): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (inclusiv variantele cu litere mici)
- Timp de expirare: `TLS_CLIENT_TIMEOUT_MS` (moștenit din `FETCH_TIMEOUT_MS`, implicit 600000)
- Response din `wreq-js` este compatibil cu fetch (`headers`, `text()`, `json()`, `clone()`, `body`).
- Temporizator de siguranță pentru primul octet (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`
  se finalizează imediat ce sosesc antetele upstream, astfel încât `TLS_CLIENT_TIMEOUT_MS` singur nu poate limita durata unui
  corp care nu furnizează niciodată primul octet. `guardTlsFirstByte()` pune în competiție primul `read()` al corpului
  cu `TLS_FIRST_BYTE_WATCHDOG_MS` (implicit `10000`, `0` îl dezactivează); un corp funcțional nu este
  afectat, în timp ce un corp blocat anulează cititorul wreq și permite logicii existente de
  rezervă TLS din `proxyFetch` să continue către dispecerul direct/proxy (o solicitare care nu poate fi reluată în siguranță, de exemplu
  un POST cu un corp, va genera în continuare o eroare în loc să fie reîncercată fără avertisment).

### Transportul furnizorilor cu cookie-uri web — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` este adaptorul comun pentru cele cinci transporturi specializate
cu cookie-uri web de mai jos. Fiecare wrapper minimal al furnizorului selectează un profil de browser/sistem de operare. Adaptorul
folosește încărcătorul unic al runtime-ului wreq și pool-ul de transporturi din `open-sse/utils/tlsClient.ts`, indexat după
profil + sistem de operare + proxy rezolvat, în timp ce fiecare solicitare folosește `cookieMode: "ephemeral"`. Prin urmare, conturile și
solicitările partajează conexiunile la nivel de transport, dar niciodată o sesiune wreq sau un depozit de cookie-uri.

| Furnizor   | Profil        | Sistem de operare emulat | Politica EOF pentru flux                  |
| ---------- | ------------- | ------------------------ | ----------------------------------------- |
| Claude     | `chrome_146`  | Linux                    | include `[DONE]`                          |
| Perplexity | `firefox_151` | macOS                    | include `event: end_of_stream`            |
| Grok       | `chrome_146`  | Linux                    | exclude `[DONE]`                          |
| Notion     | `chrome_146`  | Windows                  | include `[DONE]`                          |
| LMArena    | `chrome_146`  | Windows                  | fără santinelă; închidere la EOF-ul nativ |

- Redarea în flux consumă direct `ReadableStream` din răspunsul nativ; nu este creat niciun fișier temporar sau proces auxiliar.
- Sunt inspectați până la 256 de octeți inițiali înainte de expunerea unui flux. Furnizorii SSE stochează în buffer erorile non-SSE;
  Grok/LMArena mapează provocările Cloudflare la `403`, iar paginile HTML intermediare la `502`.
- Timpul de expirare al solicitării native rămâne încadrat de un termen-limită JS absolut. O blocare invalidează
  și închide numai transportul afectat pentru profil/sistem de operare/proxy, înainte ca următoarea solicitare să îl recreeze.
- Prioritatea rezolvării proxy-ului este, pentru fiecare apel, `proxyUrl` → contextul contului/panoului de control asociat solicitării →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (inclusiv variantele cu litere mici). Erorile de rezolvare eșuează
  în mod sigur, în loc să permită accidental o conexiune directă. LMArena efectuează intenționat rezolvarea pentru `arena.ai`.
- `byteResponse` returnează un URL `data:` cu tipul de conținut corespunzător, fără coruperea UTF-8.
- Erorile sunt `TlsClientUnavailableError` (pachetul/modulul addon nu este disponibil), `TlsClientHangError`
  (termen-limită depășit) și `WreqTransportCapacityError` (codul comun de eroare privind capacitatea sesiunilor)
  atunci când toate cele 128 de sloturi limitate pentru profil/sistem de operare/proxy sunt active sau în curs de închidere.

Sesiunea generică `TlsClient` de mai sus rămâne specializată pentru starea persistentă a cookie-urilor susținută de browser.
Ambele căi reutilizează un singur încărcător de module wreq stocat în cache și un hook pentru ciclul de viață al procesului; pool-urile lor rămân
separate deoarece duratele de viață ale cookie-urilor sunt intenționat diferite.

Profilurile sunt acceptate de pachetul fixat la versiunea specificată, însă acceptarea reală de către WAF se poate modifica independent
de testele locale de contract. Validați modificările amprentei folosind un cont activ autorizat în mod explicit
înainte de a declara paritatea cu un browser upstream.

## Pachetul Stealth Claude Code

Când `cliCompatMode` este activat, OmniRoute remodelează cererile Claude trimise astfel încât acestea să nu poată fi deosebite de traficul `claude-cli`. Trei module colaborează:

### `claudeCodeFingerprint.ts`

Calculează amprenta `cc_version` de 3 caractere încorporată în antetul de facturare:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (codificat direct; corespunde clientului oficial)
- Intrări: caracterele de la indicii 4, 7 și 20 din textul primului mesaj al utilizatorului + șirul versiunii
- Ieșire: prefix hexazecimal de 3 caractere

### `claudeCodeCCH.ts` (Hashul conținutului clientului)

Verificare a integrității pe server, calculată de CLI-ul oficial Claude Code prin Bun/Zig. OmniRoute o reimplementează cu `xxhash-wasm`:

1. Serializează corpul cu substituentul `cch=00000;`
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. Valoare hexazecimală cu litere mici, de 5 caractere, completată cu zerouri
4. Înlocuiește `cch=00000;` cu tokenul calculat

Constante:

- Seed: `0x6e52736ac806831e`
- Șablon: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

Inserează un caracter Unicode **zero-width joiner** (`U+200D`) după primul caracter al numelor de clienți „sensibile”, astfel încât filtrele din amonte să nu le poată găsi prin grep. Lista implicită de cuvinte:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Se aplică pentru: blocurile `system`, întregul conținut `messages[].content` și `tools[].description` / `tools[].function.description`. Poate fi suprascris de operator prin `setSensitiveWords()`.

### `claudeCodeCompatible.ts` — furnizori `anthropic-compatible-cc-*`

Pentru relee Anthropic terțe care acceptă numai trafic „Claude Code autentic”:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"` în mod implicit
- Comutatorul per conexiune „Activează versiunea beta redact-thinking” adaugă `redact-thinking-2026-02-12` când un serviciu CC Compatible din amonte necesită în mod explicit fluxuri de raționament redactate
- Comutatorul per conexiune „Activează afișarea raționamentului rezumat” stochează `providerSpecificData.requestDefaults.summarizeThinking` și adaugă `display: "summarized"` la cererile de raționament CC Compatible care nu au setat deja un mod de afișare
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (familia Opus/Sonnet 4.x)
- Cale implicită: `/v1/messages?beta=true`

Module asociate din același pachet:

- `claudeCodeConstraints.ts` — reguli pentru temperatură + controlul memoriei cache
- `claudeCodeToolRemapper.ts` — remaparea numelor instrumentelor
- `claudeCodeExtraRemap.ts` — normalizarea suplimentară a sarcinii utile

## Antigravity Stealth

Solicitările Antigravity păstrează textul apelantului octet pentru octet. OmniRoute nu inserează caractere cu lățime zero în solicitări sau instrumente rename/inject pentru a imita un client IDE.

### `antigravityHeaderScrub.ts`

Îndepărtează marcajele inoxidabile SDK (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) înainte de a trimite.

### Risc ⚠️ : `ANTIGRAVITY_CREDITS=always` (hot spot de interzicere a contului)

Rute `ANTIGRAVITY_CREDITS=always` (consumate de `open-sse/executors/antigravity.ts`).**fiecare** solicitați prin Antigravity AI Credit Overages (credite plătite Google ) în loc să lăsați Google-ului de nivel liber cota lucruri. Acest lucru este documentat ca o caracteristică, dar este **cel mai frecvent raport de încălcare a ToS pe care îl vedem** — mai multe conturi Google Ultra au fost interzise cu `403 / "service disabled for ToS violation" / insufficient_quota` după ce au rulat câteva ore cu `=always`.

Executarea în amonte este activată **Partea lui Google** , nimic OmniRoute nu poate preveni. Numele env var și documentele existente îl fac să sune ca un buton sigur de răsturnat; nu este.

**De ce acest lucru atrage detectarea abuzurilor mai agresiv decât utilizarea exclusivă a nivelului gratuit:**

- Cheltuielile automate susținute pentru un singur cont Google semnalează diferit față de accesările-cotă-și-opriri de nivel gratuit.
- Depășirile de credit nu au plafon de rată, așa că un client configurat greșit poate arde câteva sute USD în câteva minute și poate arăta ca revânzarea cheii API sau trafic bot.
- Mai mulți utilizatori OmniRoute care obțin credite pentru depășire în paralel de la același IP extern compun semnalul.

**Postura recomandata:**

1. Păstrați `ANTIGRAVITY_CREDITS=off` implicită, cu excepția cazului în care operatorul acceptă în mod explicit riscul de credit plătit și de executare a contului. `retry` trimite mai întâi cererea normală și injectează credite cel mult o dată după o cotă eligibilă 429; `always` injectează credite la prima solicitare.
2. **Răspândește sarcina între furnizori prin Auto-Combo** (`model: "auto"` sau `kr/glm/etc` -combo) în loc să saturați un singur cont Antigravity.
3. **Setați limitele RPM per conexiune** în pagina de editare a furnizorului Antigravity (Tabloul de bord → Providers → Antigravity → connection → rate limit). 30–60 RPM este o limită superioară defensabilă pentru utilizare susținută.
4. **Utilizați o rețea în amonte stabilă, controlată de operator** și evitați partajarea unui cont între utilizatori sau sarcini de lucru care nu au legătură.
5. **Dacă este interzis** : apel prin `support.google.com` → „Restaurați accesul Workspace/Account ” cu corpul de răspuns exact `quota_exceeded` / `service disabled` trimis Google. Restaurarea nu este garantată.

Referința de mediu documentează implicațiile privind contul și cheltuielile fiecărui mod de creditare.

#### Nu numai `=always`: Antigravity OAuth rutare în general

Suspendarile nu se limitează la depășirea creditelor. Rapoartele din noiembrie 2026 (#19223, #19266) descriu mai multe conturi Google suspendate în timpul direcționării prin furnizorii `antigravity` și `agy` (Antigravity CLI), cu:

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

Ambii furnizori se autentifică cu sesiunea OAuth a produsului Antigravity, care este cazul în care notificarea de risc a tabloului de bord ("Acest furnizor folosește produsul dvs. oficial session/OAuth, care nu este autorizat pentru utilizarea proxy/router ") avertizează înainte de adăugarea unei conexiuni. Niciuna dintre recomandările de mai sus nu face această utilizare autorizată; ele reduc doar cât trafic transportă un cont.

**Interfețe autorizate API pentru modelele Gemini.** Google oferă acces programatic la Gemini prin APIs, pe care OmniRoute îl acceptă ca furnizori obișnuiți de chei API:

| ID furnizor | Numele tabloului de bord  | Acreditare                                                                        |
| ----------- | ------------------------- | --------------------------------------------------------------------------------- |
| `gemini`    | Gemini (Google AI Studio) | Cheie Gemini API de Google AI Studio (nivel gratuit disponibil)                   |
| `vertex`    | Vertex AI                 | Cont de serviciu JSON, jeton de acces OAuth sau cheie Vertex Express API (Gemini) |

Acești furnizori folosesc probleme de acreditări Google pentru accesul API, spre deosebire de sesiunea de produs Antigravity. Ele nu fac fiecare utilizare conformă și nu înlătură riscul de aplicare: fiecare este guvernat de propriii termeni, pe care operatorul trebuie să-i verifice pentru implementarea lor. De exemplu, [Termenii și condițiile adiționale Gemini API](https://ai.google.dev/gemini-api/terms) permit numai Servicii cu plată atunci când clienții API sunt pusi la dispoziția utilizatorilor din Spațiul Economic European, Elveția sau Regatul Unit, iar conținutul trimis către Serviciile neplătite poate fi utilizat pentru a îmbunătăți produsele Google. Vertex AI se încadrează în schimb sub termenii Google Cloud ( [Termeni specifici serviciului](https://cloud.google.com/terms/service-terms) ). Prețurile și cotele urmează acești termeni API mai degrabă decât un abonament Antigravity.

Operatorii care doresc să evite suspendările Antigravity descrise mai sus ar trebui să direcționeze traficul Gemini prin unul dintre acești furnizori în loc de `antigravity` / `agy`, după ce au verificat dacă utilizarea acestora se potrivește cu termenii furnizorului.

Puncte de atingere:

- `open-sse/executors/antigravity.ts` — citește `process.env.ANTIGRAVITY_CREDITS`
- `src/lib/oauth/providers/antigravity.ts` — acreditare instalații sanitare
- Raportul original al incidentului: Discuție [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## Registrul de amprente CLI — `open-sse/config/cliFingerprints.ts`

Tabel per furnizor care fixează ordinea **exactă** a antetelor și ordinea câmpurilor din corpul JSON, capturate din urmele mitmproxy ale CLI-urilor oficiale. În prezent sunt înregistrate: `codex`, `claude`, plus profilurile derivate în timpul rulării din `providerHeaderProfiles.ts` pentru `antigravity` și `github`.

```ts
interface CliFingerprint {
  headerOrder: string[]; // sensibilă la litere mari și mici
  bodyFieldOrder: string[]; // chei JSON de nivel superior
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Activați sau dezactivați pentru fiecare furnizor prin intermediul variabilelor de mediu (consultați mai jos). Când funcționalitatea este dezactivată, antetele/cheile corpului apar în ordinea furnizată de Node/JSON — ușor de identificat prin amprentare.

## Proxy MITM (Antigravity, Linux/macOS/Windows)

Pentru CLI-urile ale căror binare nu pot fi redirecționate prin `OPENAI_BASE_URL`, OmniRoute rulează un proxy local care termină conexiunile TLS. Endpointurile se află în `src/app/api/cli-tools/antigravity-mitm/`.

| Metodă | Endpoint                                | Scop                                               |
| ------ | --------------------------------------- | -------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | Stare — rulează, pid, dnsConfigured, certExists    |
| POST   | `/api/cli-tools/antigravity-mitm`       | Pornește MITM (necesită `apiKey` + `sudoPassword`) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | Oprește MITM                                       |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | Listează aliasurile modelelor                      |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | Salvează aliasurile modelelor pentru un instrument |

Gazda țintă interceptată: **`daily-cloudcode-pa.googleapis.com`** (serverul upstream al Antigravity).

### Secvența de pornire (`src/mitm/manager.ts::startMitm`)

1. Generează un certificat autosemnat prin `selfsigned` (RSA-2048, SHA-256, 1 an) — `cert/generate.ts`
2. Instalează certificatul în depozitul de încredere al sistemului — `cert/install.ts`
3. Adaugă în fișierul hosts intrarea `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. Pornește `src/mitm/server.cjs` cu `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (implicit `443`)
5. Salvează persistent PID-ul în `<DATA_DIR>/mitm/.mitm.pid`

### Detectarea dinamică a depozitului de încredere pe Linux — `cert/install.ts`

`getLinuxCertConfig()` parcurge o listă de priorități și selectează primul director existent:

| Familie de distribuții   | Director                                    | Comandă de actualizare   |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Numele fișierului certificatului: `omniroute-mitm.crt`. Verificarea amprentei se face prin `getCertFingerprint()` (SHA-1 al DER).

În plus, `updateNssDatabases()` instalează certificatul în bazele de date NSS ale fiecărui utilizator atunci când `certutil` este disponibil: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, toate profilurile Firefox (inclusiv snap), sub pseudonimul **`OmniRoute MITM Root CA`**.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** PowerShell cu privilegii ridicate → `certutil -addstore Root`

### Autentificare

Toate endpointurile MITM necesită autentificare de administrare (`requireCliToolsAuth`). Parola sudo este stocată temporar în domeniul modulului (niciodată în `globalThis`) și este ștearsă la apelarea `stopMitm()`.

## Igienizarea antetelor de intrare

OmniRoute elimină antetele clientului primit înainte de redirecționare, astfel încât o cerere provenită de la Cursor să nu divulge `User-Agent: Cursor/X.Y.Z` către un serviciu Claude din amonte. Consultați `src/shared/constants/upstreamHeaders.ts` pentru lista de blocare, menținută sincronizată cu schemele Zod și testele unitare.

## Actualizarea amprentelor când un furnizor le rotește

1. Capturați traficul CLI oficial cu `mitmproxy` (interceptare TLS + captură)
2. Extrageți JA3/JA4 și ordinea literală a antetelor
3. Actualizați intrarea relevantă `CLI_FINGERPRINTS[...]`
4. Actualizați valoarea implicită corespunzătoare `*_USER_AGENT` din `.env.example`
5. Dacă s-a modificat chiar handshake-ul TLS, actualizați wrapperul furnizorului relevant sau opțiunea `browser:` din wreq-js
6. Rulați testele TLS specifice furnizorului și un test canar manual cu furnizorul activ
7. Livrați modificările într-o versiune de corecție; documentați-le în `CHANGELOG.md`
