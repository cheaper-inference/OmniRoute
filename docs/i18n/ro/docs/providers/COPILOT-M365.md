`copilot-m365-web` (alias `m365copilot`) trimite solicitări de chat în format OpenAI printr-o
sesiune autentificată de browser Microsoft 365 Copilot BizChat la
`m365.cloud.microsoft/chat`. Aceasta este o integrare neoficială.

> **Nu ați mai utilizat furnizori Web Cookie?**
>
> Citiți **`docs/getting-started/WEB-COOKIE-GUIDE.md`** pentru procesul general de configurare, îndrumări privind autentificarea, limitări și depanare înainte de a urma acest ghid specific furnizorului.
>
> **Important:** Acreditarea pentru acest furnizor **nu este un cookie**. Nu copiați
> cookie-uri din `m365.cloud.microsoft`. Acreditarea este alcătuită dintr-un parametru de interogare al URL-ului WebSocket
> și un segment de cale, ambele preluate din fila Network din DevTools.

## Cerințe preliminare

- Un cont Microsoft 365 cu acces la BizChat la `m365.cloud.microsoft/chat`
- Un browser bazat pe Chromium (Chrome, Edge) pentru inspectarea WebSocket în DevTools
- O licență M365 Copilot (inclusă în multe planuri Microsoft 365 Business/Enterprise)

## Capturarea acreditării (metoda WebSocket)

1. Autentificați-vă la `https://m365.cloud.microsoft/chat` și începeți o conversație.
2. Deschideți **DevTools → Network**.
3. Filtrați după **WS** (WebSocket).
4. Faceți clic pe conexiunea WebSocket Chathub. Căutați un URL care începe cu
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Din **Request URL**, copiați:
   - Valoarea parametrului de interogare `access_token` (un JWT cu durată scurtă de viață).
   - Segmentul căii Chathub de după `/Chathub/` (de exemplu, `<oid>@<tenant>`).

URL-ul complet are următoarea formă:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. În OmniRoute, accesați **Providers → Add Provider**, selectați **Microsoft 365 Copilot
   (BizChat)** și inserați acreditarea în următorul format:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Faceți clic pe **Test Connection** și pe **Save**.

## Capturarea acreditării (import HAR)

În loc să copiați manual valorile din URL-ul WebSocket, puteți exporta un fișier HAR din
DevTools:

1. Deschideți **DevTools → Network**.
2. Începeți sau continuați o conversație BizChat (aceasta declanșează conexiunea WebSocket).
3. Faceți clic dreapta în panoul Network și selectați **Save all as HAR with content**.
4. În OmniRoute, utilizați butonul **Import .har file** din caseta de dialog pentru conexiunea furnizorului.

OmniRoute scanează fișierul HAR pentru a găsi URL-ul WebSocket Chathub, extrage
`access_token` și `chathubPath` și completează automat câmpurile acreditării. Importul
HAR decodează data expirării JWT-ului și afișează durata de viață rămasă a tokenului.

> **Nu includeți niciodată într-un commit un export HAR real, un token de acces sau un token de reîmprospătare.** Valorile pentru teste și
> documentație trebuie să fie întotdeauna substituenți.

## Durata de viață și reîmprospătarea tokenului

`access_token` este de scurtă durată (de obicei **~ 75 de minute** ). Fără un token de reîmprospătare utilizabil, trebuie să recapturați acreditările după expirare.

### Reîmprospătarea automată cu `refreshToken`

În furnizorul Microsoft 365 **Adăugați conexiune** sau **Editați conexiunea** dialog, deschide **Setări avansate → Refresh token (opțional)** . Lipiți un simbol de reîmprospătare Microsoft OAuth pentru domeniul `substrate.office.com/sydney` și salvați. Intrarea este mascată și nu este niciodată precompletată cu simbolul stocat. Când editați, lăsați-l necompletat pentru a păstra simbolul existent; lipiți un nou token pentru al înlocui.

Obțineți indicativul de reîmprospătare de la un cod de dispozitiv Microsoft sau un flux de cod de autorizare întins la `substrate.office.com/sydney`; tabloul de bord nu îl achiziționează pentru dvs. Cu un jeton de reîmprospătare configurat, OmniRoute verifică `access_token` înainte de solicitări și îl reîmprospătează numai atunci când are nevoie de reîmprospătare. O reîmprospătare reușită persistă, de asemenea, simbolul de reîmprospătare rotit, evitând recapturarea manuală în timp ce simbolul de reîmprospătare rămâne valabil.

Dacă `refreshToken` nu este setat, trebuie să capturați din nou manual acreditarea WebSocket
după fiecare expirare.

### Selectarea nivelului

| Nivel        | Alias        | Interfață                              |
| ------------ | ------------ | -------------------------------------- |
| `individual` | _(implicit)_ | M365 Copilot pentru consumatori        |
| `edu`        | `included`   | M365 Copilot pentru educație           |
| `enterprise` | `work`       | M365 Copilot pentru mediul profesional |

Setați nivelul **Setări avansate → Copilot tier** . Nivelul afectează rutarea BizChat și accesul la model.

## Model de securitate

- **Integrare neoficială.** Acest furnizor utilizează un protocol BizChat WebSocket
  obținut prin inginerie inversă. Poate înceta să funcționeze fără notificare atunci când Microsoft modifică endpoint-ul.
- Indicatorul `subscriptionRisk: true` reflectă faptul că integrarea se bazează pe un
  endpoint nedocumentat. Sunt posibile restricții asupra contului, dar acestea nu sunt confirmate.
- Tokenul de acces este un JWT cu durată scurtă de viață. Tratați-l ca pe o parolă: nu îl includeți în commituri,
  nu îl înregistrați în jurnale și nu îl distribuiți.
- Tokenul de reîmprospătare acordă acces pe termen lung la interfața BizChat. Stocați-l cu
  aceeași grijă ca pe o cheie API.

## Depanare

### Autentificarea eșuează imediat

- Verificați dacă ați copiat din **URL-ul WebSocket**, nu dintr-o solicitare XHR/Fetch. Datele de
  autentificare se află în parametrul de interogare `access_token` al conexiunii Chathub WebSocket
  — nu într-un antet `Authorization: Bearer`.
- Asigurați-vă că `chathubPath` include întregul segment `<oid>@<tenant>` din calea
  URL-ului.

### Tokenul expiră după aproximativ 75 de minute

Acest lucru este normal. Fără un `refreshToken`, tokenul de acces are o durată scurtă de viață. Puteți fie:

- Să capturați din nou datele de autentificare din DevTools, fie
- Configurați **Setări avansate → Jeton de reîmprospătare (opțional)** în caseta de dialog Adăugați sau Editați conexiunea pentru reîmprospătarea automată.

### Testarea conexiunii reușește, dar chatul returnează 401

Este posibil ca tokenul să fi expirat între validare și prima solicitare. Capturați din nou
date de autentificare actualizate.

### Copilot nu apare în lista de furnizori

Asigurați-vă că `copilot-m365-web` este activat în **Tablou de bord → Furnizori**. Este posibil ca furnizorul
să fie ascuns în mod implicit în anumite niveluri.
