`devin-cli-agentic` به محیط اجرای واقعی Claude Code اجازه میدهد از نقطه پایانی محلی Anthropic
Messages در OmniRoute استفاده کند، درحالیکه CLI رسمی Devin پاسخهای مدل را ازطریق ACP stdio ارائه
میدهد. این قابلیت ارائهدهندگان موجود Anthropic، Claude OAuth، Claude Web یا `devin-cli` را
تغییر نمیدهد.

برای فراخوانی ابزارهایی که تحت مالکیت کلاینت هستند، درخواستها را ازطریق `devin-cli-agentic` (با نام مستعار `dva`)، یعنی
ارائهدهنده ابزارمحور با قالب Claude، مسیریابی کنید. اجراکننده قدیمی ACP یعنی `devin-cli` (`dv`)
فقط متنی است: این اجراکننده خلاصهساز بدون ابزار Devin را اجرا میکند و نمیتواند فراخوانی ابزار برگرداند. فراداده مدل
آن نیز متناسب با این محدودیت علامتگذاری شده است تا مسیریابی ترکیبیِ نیازمند ابزار از آن اجتناب کند.

> **وضعیت فعلی: Claude Code روی نسخه `2.1.258` پین شده است؛ آخرین اعتبارسنجی آفلاین و زنده
> روی نسخه `2.1.220` ثبت شده است.** پین `2.1.220` سه سناریوی ایزوله را ازطریق Devin CLI
> `3000.2.17` و مدل `swe-1-7-lightning` تکمیل کرد؛ آن اجرای زنده نهایی، نوبتهای تحت مالکیت کلاینتِ `Read`،
> `Edit` و `Bash`، نتایج موفق `npm test`، کشف فرمانها و مهارتهای پروژه،
> مسیریابی منحصراً ازطریق Devin و صفر بودن خروجی ترافیک به Claude را اثبات کرد. سپس پین به `2.1.258`
> ارتقا یافت (نسل CLI که هویت Claude در OmniRoute از آن تقلید میکند و نخستین شاخهای که
> رده Fable 5.1 را بهصورت بومی ارائه میدهد). در پین جدید، لایه نصب و `claude --version`
> روی ایمیج پایه پینشده بررسی شدند و مجموعه آزمون واحد پل، `compose config` و
> اثبات ایزولهسازی ایستا با موفقیت اجرا میشوند — اما سناریوی شبیهسازی آفلاین و مجموعه زنده سهسناریویی
> هنوز دوباره اجرا نشدهاند. پیش از اتکا به پل با این پین، آنها را دوباره اجرا کنید (به بخش «بهروزرسانی ابزارهای پینشده» مراجعه کنید).

## معماری

```text
Claude Code 2.1.258 (کانتینر ایزوله Linux با کاربر غیر root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (با قالب Claude، ارائهدهنده بدون احراز هویت)
  -> devin acp --agent-type summarizer (ACP stdio رسمی، بدون ابزارهای Devin)
  -> حساب Devin در volume اختصاصی devin-auth
```

عامل پیشفرض ACP در CLI رسمی میتواند ابزارهای خودش را اجرا کند، بنابراین این پل از
آن استفاده نمیکند. این پل عامل ثابت `summarizer` در ACP را اجرا میکند که حالت رسمی CLI آن فاقد ابزار است و
درخواست سریالشده Anthropic را بهصورت رد اجرای عملیات قالببندی میکند. هنگامی که اقدام دیگری تحت مالکیت Claude
لازم باشد، پاسخ باید دقیقاً شامل یک پوشش ابزار کلاینت باشد. هرگونه
`tool_call` یا `tool_call_update` متعلق به ACP پیش از آنکه پاسخ بتواند موفق گزارش شود، رد میشود.

سریالساز موجود در `open-sse/executors/devin-agentic/serializer.ts` موارد `system`،
`text`، `tool_use`، `tool_result`، `thinking`، `redacted_thinking`، `tool_choice` و
ابزارهای ارائهشده توسط Claude Code را حفظ میکند. تصاویر و بلوکهای ناشناخته صراحتاً با خطا مواجه میشوند. نتایج حجیم ابزار
از یک نشانگر قابل مشاهده برای کوتاهسازی استفاده میکنند.

تجزیهگر در هر نوبت مدل، یک پوشش مستقل `<tool>{...}</tool>` را میپذیرد. این تجزیهگر
نام را با فهرست ابزارهای درخواست تطبیق میدهد، آرگومانها را براساس JSON
Schema همان ابزار اعتبارسنجی میکند، ترکیب روایت و عملیات را رد میکند و یک تلاش اصلاحی محدود را مجاز میداند. سپس Claude Code
`tool_use` حاصل از Anthropic را بهصورت محلی اجرا میکند و `tool_result` را ازطریق
OmniRoute بازمیگرداند.

## مسیریابی خودکار

این ارائهدهنده، تا زمانی که مسدود نشده باشد، واجد شرایط حضور در مجموعه نامزدهای `auto/*` در OmniRoute است.
واجد شرایط بودن یک نامزد، انتخاب آن را تضمین نمیکند: راهبرد مسیریابی ترکیب (برای مثال،
آخرین گزینه سالم شناختهشده) ممکن است ارائهدهنده دیگری را ترجیح دهد. هنگامی که لازم است
تمام درخواستها ازطریق Devin ارسال شوند، از `dva/<model>` یا یک ترکیب با اولویت Devin استفاده کنید.

## مدل ایزولهسازی و تهدید

نصب، حساب و پیکربندی Claude روی میزبان خارج از محدوده هستند و ممنوع در نظر گرفته
میشوند. سرویسهای Compose:

- با UID/GID برابر با `10001:10001`، فایلسیستم ریشهٔ فقطخواندنی، قابلیتهای حذفشده و
  `no-new-privileges` اجرا میشوند؛
- از یک `/home/bridge` خصوصی، یک volume اختصاصی برای پیکربندی Claude، دادههای ایزولهشدهٔ OmniRoute
  و یک volume جداگانهٔ `devin-auth` استفاده میکنند؛
- فقط workspaceها و شواهد یکبارمصرف `.sandbox` را mount میکنند؛
- پوشهٔ خانگی میزبان، Keychain، اعتبارنامههای SSH، اعتبارنامههای ابری یا socket مربوط به Docker را mount نمیکنند؛
- محیطها را بهصورت صریح میسازند و متغیرهای API،‏ OAuth و مسیریابی Anthropic را حذف میکنند؛
- استنتاج Claude Code را فقط با یک کلید صرفاً محلی به `http://omniroute:20128` هدایت میکنند.

پروفایل آفلاین از یک شبکهٔ داخلی استفاده میکند. در پروفایل زنده، OmniRoute فقط از طریق
`network-guard` به endpointهای رسمی Devin دسترسی پیدا میکند؛ مقصدهای نامرتبط مسدود میشوند.
Claude Code دارای یک محافظ خروجی مجزای مسدودکنندهٔ همهٔ ترافیک است و فقط از طریق `NO_PROXY`
میتواند به سرویس محلی OmniRoute دسترسی پیدا کند. فایلهای ممیزی محافظ فقط توسط فرایند محافظ
مربوط به خودشان mount میشوند. اسکریپتها پیش از خروجیگرفتن از شواهد بدون توکن،
مالکیت فایل، mode، تعداد linkها و تکتک تصمیمها را بررسی میکنند.

اثبات ایزولهسازی را بهصورت مستقل اجرا کنید:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

این دستور توپولوژی، mountهای نامگذاریشده، تنظیمات غیر-root/فقطخواندنی، مسیریابی محلی صریح،
نبود متغیرهای محیطی حساس، نبود socket مربوط به Docker، مسدودبودن دسترسی به
`api.anthropic.com` و `claude.ai`، انتخاب ارائهدهندهٔ صرفاً Devin و شکست صریح در زمان
دردسترسنبودن backend مربوط به ACP را اعتبارسنجی میکند.

## راهاندازی اولیه و استفادهٔ معمول

image سنجاقشده را build کنید:

```bash
./scripts/devin-bridge/build
```

فقط volume ایزولهشدهٔ Devin را احراز هویت کنید:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

فرمان ورود از جریان رسمی توکن دستی، که برای محیطهای راهدور/container در نظر گرفته شده است،
استفاده میکند. مقدار مستقیماً در prompt مربوط به CLI وارد میشود؛ این مقدار بهعنوان آرگومان
فرایند ارسال نمیشود، در Git نوشته نمیشود و از میزبان کپی نمیشود.

محیط اجرای ایزولهشدهٔ Claude Code را راهاندازی کنید:

```bash
./scripts/devin-bridge/launch
```

`launch` پیش از اجرای Claude Code درون container، ایزولهسازی، احراز هویت Devin و کشف مدل
را دوباره بررسی میکند. این فرمان هرگز فایل اجرایی Claude میزبان را اجرا نمیکند. نامهای
مستعار مدل را میتوان در `.env.devin-bridge` تنظیم کرد؛ هر مقدار پیکربندیشده باید پیشوند
`devin-cli-agentic/` را حفظ کند.

## فرمانهای اعتبارسنجی

مسیر آفلاین بازتولیدپذیر به حساب Devin نیاز ندارد و هنگام اجرا به اینترنت دسترسی ندارد:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

مسیر زندهٔ نیازمند احراز هویت و فعالسازی صریح بهشکل زیر است:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

اجراکنندهٔ زنده بین سناریوها منتظر میماند تا از بازکردن ناگهانی چندین نشست ACP جلوگیری کند و
بهجای اعتماد به ادعاهای متنی، رویدادهای ساختیافتهٔ stream مربوط به Claude را اعتبارسنجی میکند.
سه سناریوی آن موارد زیر را اثبات میکنند:

1. خواندن مستقیم پروژه و تحلیل نقص؛
2. یک `Edit` واقعی، یک `Bash` تحت مالکیت client برای اجرای `npm test` و یک نتیجهٔ نهایی؛
3. کشف `/bridge-check` و `bridge-proof`، خواندن پروژه، یک اجرای موفق دیگر از `npm test`
   تحت مالکیت client و تکمیل بدون کار معوق.

دروازهٔ نهایی همچنین ممیزی شبکهٔ Devin را بررسی میکند و ایجاب میکند که ممیزی خروجی Claude
خالی باقی بماند.

## بهروزرسانی ابزارهای پینشده

ایمیج، نسخههای Node، Claude Code و Devin CLI را در
`docker/devin-bridge/Dockerfile` پین میکند. برای بهروزرسانی:

1. نسخههای صریح را تغییر دهید؛
2. هر دو checksum آرشیو Devin مختص معماری را با مقادیر مربوط به آرتیفکت رسمی جایگزین کنید؛
3. ایمیج را دوباره بسازید و همهٔ فرمانهای اعتبارسنجی آفلاین را اجرا کنید؛
4. نسخهها را درون ایمیج تأیید کنید؛
5. مجموعهٔ زندهٔ احراز هویتشده با سه سناریو را دوباره اجرا کنید.

هیچیک از CLIها را بهصورت سراسری روی میزبان نصب نکنید و اعتبارسنجی checksum را با دانلودی
تأییدنشده جایگزین نکنید.

## عیبیابی و پاکسازی

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  مسیریابی محلی و خطاهای پاکسازیشدهٔ اجراکننده را نمایش میدهد.
- `.sandbox/evidence/mock-acp.jsonl` کنشهای قطعی ACP ساختگی را ثبت میکند.
- `.sandbox/evidence/claude-stream.jsonl` اجرای آفلاین واقعی Claude Code را ثبت میکند.
- `.sandbox/evidence/live-*.jsonl` سه جریان زندهٔ اعتبارسنجیشده را ثبت میکند.
- `.sandbox/evidence/egress.jsonl` و `.sandbox/evidence/claude-egress.jsonl` نسخههای اعتبارسنجیشده و فاقد توکن از ممیزیهای محافظ هستند.

کانتینرها و شبکههای تحت مالکیت را متوقف کنید و در عین حال volumeهای ورود/پیکربندی را حفظ کنید:

```bash
./scripts/devin-bridge/clean
```

کل محیط تحت مالکیت bridge، از جمله volumeهای نامگذاریشده را حذف کنید:

```bash
./scripts/devin-bridge/clean --all
```

## محدودیتها

- bridge به نقش ثابت و بدون ابزار `summarizer` متکی است، زیرا Devin CLI `3000.2.17`
  یک عامل ACP خنثی و بدون ابزار ارائه نمیکند. adapter پاسخهای میانیِ خلاصهمحور را جبران
  میکند، اما یک ترمیم محدود همچنان ممکن است بهطور صریح شکست بخورد.
- فراخوانیهای زندهٔ ACP ممکن است پاسخهای موقت `502`/`504` برگردانند. harness بین سناریوها
  فاصله ایجاد میکند؛ شکست پایدار همچنان بهصورت fail-closed باقی میماند و هرگز ارائهدهندهٔ
  دیگری را انتخاب نمیکند.
- زمینهٔ ACP از هر درخواست Anthropic بازسازی میشود؛ هیچ وابستگی به فرایند/نشست وجود ندارد.
- در هر پاسخ مدل، یک فراخوانی ابزار پشتیبانی میشود؛ فراخوانیهای موازی رد میشوند.
- تصاویر صراحتاً پشتیبانی نمیشوند. قابلیت بینایی، خروجی تفکر، کنترلهای effort و پنجرهٔ
  زمینهٔ 1M اعلام نمیشوند.
- SSE از رویدادهای معتبر چرخهٔ حیات Anthropic استفاده میکند، اما پس از جمعآوری نوبت محدود
