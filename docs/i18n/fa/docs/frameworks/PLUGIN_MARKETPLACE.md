> **منبع اصلی:** `src/lib/plugins/` (`marketplace.ts`، `manager.ts`، `manifest.ts`،
> `scanner.ts`، `loader.ts`)، `src/app/api/plugins/` و
> `src/app/(dashboard)/dashboard/plugins/`
> **آخرین بهروزرسانی:** 2026-06-28 — v3.8.40

OmniRoute همراه با یک سیستم افزونه به سبک WordPress ارائه میشود. افزونهها
دایرکتوریهای مستقلی هستند — هرکدام دارای یک مانیفست `plugin.json` و یک فایل
ورودی — که به خط لوله درخواست (`onRequest` / `onResponse` / `onError`) و
رویدادهای چرخه حیات (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
متصل میشوند.

**بازار افزونهها** لایه کشف روی این سیستم است. این لایه، کاتالوگی قابل مرور از
افزونههای قابل نصب ارائه میکند. بهطور پیشفرض، کاتالوگ یک رجیستری اولیه داخلی
و کوچک است؛ اپراتور میتواند آن را به یک URL رجیستری راهدور سفارشی متصل کند که
در این حالت، دریافت داده بهوسیله یک محافظ SSRF با قابلیت تفکیک DNS ایمنسازی
میشود (به [امنیت](#security) مراجعه کنید).

تمام مسیرهای افزونه **فقط از طریق loopback** در دسترس هستند (سطح 1 —
`LOCAL_ONLY`): افزونهها کد را در فرایندهای فرزند بارگذاری و اجرا میکنند،
بنابراین این مسیرها، صرفنظر از احراز هویت، از هیچ مبدأ غیر-loopback قابل دسترسی
نیستند. به
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)
مراجعه کنید.

## چگونه آن را متناسب با Together

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **لایه رجیستری** — `src/lib/plugins/marketplace.ts`: فهرستبندی/جستجوی کاتالوگ، در صورت بروز هر گونه خرابی به رجیستری دانه بازمیگردد.
- **لایه چرخه حیات** — `src/lib/plugins/manager.ts` (`pluginManager` singleton): نصب، ارتقاء، فعال کردن، غیرفعال کردن، حذف نصب، اسکن، بارگذاری راهاندازی.
- **لایه آشکار** — `src/lib/plugins/manifest.ts`: طرح Zod + پیشفرض برای `plugin.json` است.
- **اسکنر** — `src/lib/plugins/scanner.ts`: افزونهها را بر روی دیسک تحت فهرست پلاگین کشف میکند.
- **لودر** — `src/lib/plugins/loader.ts`: هر افزونه را در یک فرآیند فرزند Node.js جداگانه ایجاد می کند و کارگزاران تماس ها را روی IPC قلاب می کنند. کودک سندباکس نیست (به «جداسازی اجرای افزونه» در زیر مراجعه کنید).

## کاتالوگ بازار

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) فهرستی از
اشیای `MarketplaceEntry` را برمیگرداند:

| فیلد          | نوع      | توضیحات                                       |
| ------------- | -------- | --------------------------------------------- |
| `name`        | string   | نام افزونه با قالب kebab-case                 |
| `version`     | string   | semver                                        |
| `description` | string   | خلاصه کوتاه                                   |
| `author`      | string   | نویسنده / سازمان                              |
| `license`     | string   | شناسه مجوز به سبک SPDX                        |
| `downloadUrl` | string   | URL دانلود منبع (ممکن است خالی باشد)          |
| `repository`  | string?  | URL اختیاری مخزن                              |
| `tags`        | string[] | برچسبهای جستوجو/فیلتر                         |
| `downloads`   | number   | تعداد دانلودها                                |
| `rating`      | number   | 0–5                                           |
| `verified`    | boolean  | آیا ورودی بهعنوان تأییدشده علامتگذاری شده است |
| `lastUpdated` | string   | رشته تاریخ تقریباً مطابق ISO                  |

وقتی هیچ URL رجیستری سفارشی پیکربندی نشده باشد، کاتالوگ همان
`SEED_REGISTRY` داخلی است (در حال حاضر شامل `request-logger`، `rate-limiter`،
`cost-tracker` و `theme-manager`). رجیستری اولیه همیشه در دسترس است — اگر
رجیستری راهدور پیکربندیشده قابل دسترسی نباشد، وضعیتی غیر از `200` برگرداند یا
بدنهای ناشناخته ارائه کند، `listMarketplacePlugins()` یک هشدار ثبت میکند و به
فهرست اولیه بازمیگردد.

> نکته: **کاتالوگ** بازار (مرور/جستوجو) بهطور کامل از ابتدا تا انتها متصل شده
> است، اما **نصب** تککلیکی از کاتالوگ بازار هنوز پیادهسازی نشده است — دکمه
> «نصب» داشبورد برای یک ورودی بازار در حال حاضر پیام «بهزودی» را نمایش میدهد.
> در حال حاضر، نصب از طریق جریان نصب با مسیر محلی (`POST /api/plugins`) و کشف
> روی دیسک (`POST /api/plugins/scan`) انجام میشود.

## REST API

همه نقاط پایانی به اعتبار مدیریت (`requireManagementAuth`) نیاز دارند** و** — `/api/plugins` فقط حلقه بک هستند و `/api/plugins/` در `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) فهرست شده اند.

| نقطه پایانی                        | روش    | توضیحات                                                 |
| ---------------------------------- | ------ | ------------------------------------------------------- |
| `/api/plugins`                     | GET    | فهرست پلاگین های نصب شده (فیلتر `?status=` اختیاری)     |
| `/api/plugins`                     | POST   | یک افزونه را از فهرست منابع افزونه نصب کنید             |
| `/api/plugins/scan`                | POST   | فهرست پلاگین را اسکن کنید و افزونه های جدید را ثبت کنید |
| `/api/plugins/marketplace`         | GET    | فهرست ورودی های کاتالوگ بازار                           |
| `/api/plugins/marketplace/install` | POST   | یک پلاگین بازار را با نام نصب کنید                      |
| `/api/plugins/[name]`              | GET    | جزئیات افزونه نصب شده را دریافت کنید                    |
| `/api/plugins/[name]`              | DELETE | یک افزونه را حذف نصب کنید                               |
| `/api/plugins/[name]/activate`     | POST   | فعال کردن (بارگیری قلاب های ثبت + )                     |
| `/api/plugins/[name]/deactivate`   | POST   | غیرفعال کردن (آتش `onDeactivate`، لغو ثبت قلاب ها)      |
| `/api/plugins/[name]/config`       | GET    | طرح پیکربندی پلاگین + را دریافت کنید                    |
| `/api/plugins/[name]/config`       | PUT    | پیکربندی افزونه را به روز کنید (تایید شده در طرحواره)   |

فیلتر `GET /api/plugins` `status` یکی از `installed` / `active` / `inactive` / `error` را می پذیرد. یک مقدار نامعتبر `400` را برمیگرداند.

### پلاگین های نصب شده را فهرست کنید

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### از مسیر محلی نصب کنید

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` باید یک باشد** مطلق** مسیر یک دایرکتوری** داخل فهرست منابع افزونه** : `plugin-sources` در کنار ریشه پلاگین، بنابراین `~/.omniroute/plugin-sources/` به طور پیش فرض، یا `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` زمانی که آن متغیر تنظیم شده است (`getPluginSourcesDir()` در `src/lib/plugins/installSource.ts`). ابتدا افزونه را در آنجا کپی یا کلون کنید. نصب با `400` رد می شود زمانی که مسیر حاوی `..` یا بایت تهی باشد، خارج از آن دایرکتوری قرار داشته باشد، خارج از آن از طریق یک پیوند نمادین حل شود، حاوی یک پیوند نمادین باشد که هدف آن خارج از آن است، یا زمانی که دایرکتوری وجود ندارد. دایرکتوری منبع باید حاوی `plugin.json` معتبر باشد (یا والد یکی باشد). در صورت موفقیت، پاسخ `201` با ردیف پلاگین نصب شده است.

برخلاف سایر مسیرهای افزونه، این یکی به اعتبار مدیریت (یک جلسه داشبورد یا یک کلید API با محدوده مدیریت) نیاز دارد، حتی زمانی که ورود به سیستم غیرفعال است (`requireLogin=false`): نصب کد هرگز یک اقدام ناشناس نیست. همین امر در مورد `POST /api/plugins/marketplace/install` (بدن `{ "name": "<plugin>" }`) صدق می کند.

### بازار را مرور کنید

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### پیکربندی افزونه را به روز کنید

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` بدنه را در برابر `configSchema` افزونه (اعلام شده در مانیفست) با `validatePluginConfig()` از `src/lib/plugins/manifest.ts` اعتبارسنجی میکند: هر کلید باید در طرح اعلان شود، مقادیر باید با نوع اعلامشده مطابقت داشته باشند، فیلدهای `number` `min`/`max` احترام میگذارند و فیلدهای `select` باید با `enum` اعلامشده مطابقت داشته باشند. هر گونه تخلف `400` را برمی گرداند و چیزی ذخیره نمی شود. افزونهای که اعلام میکند `configSchema` هیچ کلید قابل تنظیمی ندارد، بنابراین درخواست با `400` رد میشود ("افزونه هیچ کلید قابل تنظیمی را اعلام نمیکند").

## پیکربندی

### دایرکتوری افزونهها

افزونهها در دایرکتوری دادهٔ OmniRoute قرار میگیرند:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (یا هر فایلی که manifest.main به آن اشاره میکند)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) آن دایرکتوری را در
سه مرحله تعیین میکند:

1. **`OMNIROUTE_PLUGINS_DIR`**، در صورت تنظیم بودن — بدون هیچ تغییری و مستقل از مقدار `HOME` استفاده میشود. این
   گزینهٔ صریح برای Docker/K8s است؛ جایی که درخت افزونهها بهصورت bind mount در مسیری
   قرار میگیرد که معمولاً ارتباطی با دایرکتوری home کانتینر ندارد (#11827).
2. `<home>/.omniroute/plugins`، که در آن `<home>` از متغیرهای محیطی `HOME` / `USERPROFILE`
   گرفته میشود.
3. `/tmp/.omniroute/plugins`، هنگامی که فرایند هیچ homeای export نکرده باشد.

دایرکتوری تعیینشده هنگام راهاندازی یکبار با عنوان `scanner.dir_resolved` ثبت میشود و
ورودی انتخابشده (`OMNIROUTE_PLUGINS_DIR`، `home` یا `no-home-fallback`) را مشخص میکند — بنابراین imageای
که بدون اعلام روی مرحلهٔ 3 قرار میگیرد، این موضوع را گزارش میکند، نه اینکه فقط فهرست خالی افزونهها را نمایش دهد.
`POST /api/plugins/scan` هر زیردایرکتوری موجود در آن مسیر را که دارای یک
`plugin.json` معتبر باشد، کشف و ثبت میکند؛ همین دایرکتوری همچنین ریشهای است که
`pluginManager.install()` افزونهها را در آن کپی میکند، بنابراین override، فرایند کشف و
نصب را با هم جابهجا میکند.

> **`OMNIROUTE_PLUGINS_DIR` همان `OMNIROUTE_PLUGIN_PATH` نیست.** مورد دوم فقط توسط
> بارگذار افزونههای فرمان CLI (`bin/cli/plugins.mjs`) خوانده میشود تا packageهای npm با نام `omniroute-cmd-*`
> را پیدا کند که زیرفرمانهایی به `omniroute` اضافه میکنند — این متغیر هیچ تأثیری بر اسکنر زمان اجرا
> که در اینجا توضیح داده شد ندارد. برای اطلاعات مربوط به آن بخش، [PLUGINS.md](./PLUGINS.md) را ببینید.

### URL سفارشی registry بازارچه

منبع کاتالوگ بازارچه از تنظیم `pluginMarketplaceUrl`
خوانده میشود (`src/lib/plugins/marketplace.ts` مقدار `settings.pluginMarketplaceUrl` را میخواند). هنگامی که
روی یک URL از نوع `http(s)` تنظیم شده باشد، `listMarketplacePlugins()` آن URL را دریافت میکند و
یا یک آرایهٔ JSON سطحبالا از ورودیها یا یک شیء دارای آرایهٔ `plugins` را میپذیرد؛
ورودیهایی که `name` رشتهای ندارند، فیلتر میشوند. هنگامی که تنظیم نشده باشد (یا زمانی که fetch
در بررسی SSRF رد شود / پاسخ نامعتبری برگرداند)، از seed registry داخلی
استفاده میشود.

زبانهٔ «بازارچه» در داشبورد، فیلدی برای این URL ارائه میکند (که مقدار آن از
`GET /api/settings` بازخوانی میشود).

> نکتهٔ پیادهسازی: عمل «ذخیره» در داشبورد، مقدار
> `pluginMarketplaceUrl` را به `PATCH /api/settings` ارسال میکند. در زمان نگارش این متن، این
> کلید در `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) تعریف نشده است؛ بنابراین پیش از اتکا به آن، ماندگاری مقدار را در
> release خود بررسی کنید — مسیر **خواندن** (`getSettings()` →
> `listMarketplacePlugins()`) پس از موجود شدن کلید در محل ذخیرهسازی تنظیمات، آن را در نظر میگیرد.

## امنیت

### فقط حلقه بک — ردیف مسیر

پلاگین ها کد را در فرآیندهای فرزند ایجاد شده اجرا می کنند، بنابراین کل سطح `/api/plugins` `LOCAL_ONLY` طبقه بندی می شود (Tier 1). اجرای Loopback بدون قید و شرط اجرا می شود** قبل از** هر گونه تأیید اعتبار، بنابراین یک توکن مدیریت لو رفته که از طریق یک تونل به جعبه می رسد هنوز نمی تواند یک افزونه را نصب، فعال یا حذف نصب کند. [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) و قوانین سخت #15 / #17 را ببینید.

### نگهبان SSRF رجیستری بازار

یک رجیستری سفارشی URL پیکربندی نفوذپذیر است، بنابراین قبل از واکشی آن `listMarketplacePlugins()` آن را در دو لایه اجرا می کند:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - هر چیزی را که `http:` / `https:` نباشد رد می کند .
   - میزبان های private/loopback/link-local/ULA تحت اللفظی را رد می کند (IPv4** و** IPv6، از جمله IPv4-mapped) از طریق `isPrivateHost` متعارف (`src/shared/network/outboundUrlGuard.ts`).
   - حل می کند** هر دو** `A` و `AAAA` ثبت و رد اگر** هر** آدرس حل شده خصوصی — است که بای پس از IP خصوصی → نام میزبان عمومی را می بندد.
   - **بسته شد** : شکست وضوح DNS URL را رد می کند.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): در زمان واکشی مجدداً محافظ URL فقط عمومی را اعمال می کند** تغییر مسیرها را مسدود می کند** (نه عمومی → خصوصی `30x` pivot).

URL که در هر یک از لایه ها با شکست مواجه می شود، درخواست را لغو نمی کند — بازار بی سر و صدا به رجیستری seed داخلی باز می گردد و یک هشدار ثبت می کند.

> این محافظ در PR #3774 مخصوصاً برای حل A + AAAA و استفاده از `isPrivateHost` متعارف به جای چک IPv4-only سخت شد.

### جداسازی اجرای پلاگین

> **افزونه ها به طور پیش فرض سندباکس نیستند.** فرزند یک فرآیند معمولی Node.js است که بهعنوان کاربر OmniRoute اجرا میشود، بدون زمینه VM و هیچ پرچم مجوز Node.js ، بنابراین کد افزونه میتواند هر فایلی را که کاربر میتواند بخواند و بنویسد، برنامهها را اجرا کند و به شبکه دسترسی پیدا کند. `requires.permissions` فقط تصمیم می گیرد که کودک کدام متغیرهای محیطی را دریافت کند. سایر مجوزها اجرا نمی شوند. پرچم ویژگی `PLUGIN_PERMISSION_MODEL_ENABLED` انتخابی (به طور پیشفرض خاموش) هر افزونه را تحت مدل مجوز Node.js ساخته شده از آن مجوزها اجرا میکند، به جز `network` که Node.js نمیتواند آن را محدود کند (به [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#%D8%B3%DB%8C%D8%B3%D8%AA%D9%85-%D9%85%D8%AC%D9%88%D8%B2) مراجعه کنید). فقط افزونه هایی را که به آنها اعتماد دارید نصب کنید. مرز فرآیند زیر شامل خرابی و هنگ است. این یک مرز امنیتی نیست.

- **جداسازی فرآیند** — `loadPlugin()` (`src/lib/plugins/loader.ts`) هر افزونه را در یک فرآیند فرزند Node.js جداگانه ایجاد می کند و از طریق IPC ارتباط برقرار می کند. تماسهای هوک با تشدید `SIGTERM` → `SIGKILL` دارای مهلت زمانی هستند.
- **فهرست مجاز Env** — کودک فقط یک مجموعه مجاز از متغیرهای محیطی را دریافت می کند. مجموعه گسترده تر تنها زمانی اعطا می شود که مانیفست مجوز `env` را درخواست کند.
- **محتوی منبع را نصب کنید** — `POST /api/plugins` فقط از دایرکتوری منابع افزونه می خواند (نگاه کنید به "نصب از یک مسیر محلی"): مسیر با `realpath` متعارف است، باید کاملاً در داخل آن دایرکتوری بماند، و درخت منبع حاوی یک پیوند نمادین که از آن فرار می کند قبل از کپی شدن رد می شود.
- **مهار مسیر** — install/upgrade/uninstall ادعا می کند که دایرکتوری افزونه و `manifest.main` حل می شوند** در داخل** ریشه پلاگین مدیریت شده قبل از هر گونه کپی یا حذف بازگشتی (محافظت در برابر مسیرهای DB دستکاری شده و پیمایش `../` در `manifest.main`). فعالسازی پیوندهای نمادین را از طریق `realpath` حل میکند و از بارگیری نقطه ورودی که از فهرست پلاگین فرار میکند خودداری میکند.
- **پین یکپارچگی اختیاری** — یک مانیفست ممکن است یک فیلد `integrity` (`sha256-<base64>`، فرمت SRI ) را اعلام کند. در صورت وجود، لودر هش فایل ورودی را در زمان بارگذاری تأیید میکند و در صورت عدم تطابق از فعالسازی خودداری میکند. این قابلیت تشخیص دستکاری است،** نه** یک مرز امنیتی: کاری که پلاگین بارگذاری شده می تواند انجام دهد را محدود نمی کند.
- **هیچ اعتبار مشتری در قلاب وجود ندارد** — متن ارسال شده به `onRequest`، `onResponse` و `onError` دارای سرصفحههای `authorization`، `x-api-key`، `proxy-authorization` و `cookie` حذف شده است و رکورد کلید API هیچ مقدار کلیدی ندارد (`redactPluginContext()` در `src/lib/plugins/hooks.ts`).

## مانیفست (`plugin.json`)

تایید شده توسط `PluginManifestSchema` (`src/lib/plugins/manifest.ts`):

| میدان              | تایپ کنید | یادداشت ها                                                   |
| ------------------ | --------- | ------------------------------------------------------------ |
| `name`             | رشته      | مورد نیاز؛ کباب مورد (`^[a-z0-9-]+$`)، 1 تا 100 کاراکتر      |
| `version`          | رشته      | مورد نیاز؛ semver (`MAJOR.MINOR.PATCH`)                      |
| `description`      | رشته؟     | ≤ 500 کاراکتر                                                |
| `author`           | رشته؟     | ≤ 200 کاراکتر                                                |
| `license`          | رشته؟     | پیشفرض `MIT` است                                             |
| `main`             | رشته؟     | فایل ورودی؛ پیش فرض `index.js` است                           |
| `source`           | enum      | `local` \| `marketplace` (پیشفرض به `local`)                 |
| `tags`             | رشته[]    | برچسب ها را جستجو کنید                                       |
| `requires`         | شی؟       | `{ omniroute?, permissions[] }`                              |
| `hooks`            | شی؟       | Booleans اعلام می کند که کدام قلاب ها را پیاده سازی می کند   |
| `skills`           | شی[]؟     | تعاریف اختیاری مهارت                                         |
| `enabledByDefault` | بولی؟     | فعال سازی خودکار در هنگام نصب                                |
| `configSchema`     | شی؟       | نقشه فیلدهای پیکربندی (`string`/`number`/`boolean`/`select`) |
| `integrity`        | رشته؟     | پین فایل ورودی اختیاری `sha256-<base64>`                     |

مجوزها از enum `network` / `file-read` / `file-write` / `env` / `exec` گرفته می شوند. فقط `env` اثر زمان اجرا دارد (لیست مجاز متغیرهای محیطی کمی بزرگتر برای کودک). بقیه اعلامیه هستند و اجرا نمی شوند.

## جریان چرخهٔ حیات

```
نصب (POST /api/plugins، مسیر)
  → اسکن/اعتبارسنجی manifest → کپی به staging → اطمینان از قرار داشتن main درون دایرکتوری
  → تغییر نام اتمی به ~/.omniroute/plugins/<name> → درج ردیف در پایگاه داده
  → اجرای onInstall → اگر enabledByDefault بود: فعالسازی

فعالسازی (POST /api/plugins/{name}/activate)
  → بررسی محصور بودن realpath → loadPlugin() (ایجاد فرایند فرزند)
  → ثبت hookهای اعلامشده → status = "active" → اجرای onActivate

غیرفعالسازی (POST /api/plugins/{name}/deactivate)
  → اجرای onDeactivate (پیش از لغو ثبت) → لغو ثبت hookها
  → خاتمه دادن به فرایند فرزند → status = "inactive"

حذف نصب (DELETE /api/plugins/{name})
  → در صورت فعال بودن، غیرفعالسازی → اجرای onUninstall
  → حذف بازگشتی دایرکتوری افزونه با بررسی محصور بودن → حذف ردیف از پایگاه داده
```

اجرای مجدد `install` برای دایرکتوریای که نسخهٔ manifest آن **اکیداً
جدیدتر** از نسخهٔ نصبشده است، بهطور خودکار ارتقا را انجام میدهد (نصب مجدد پاک؛ پیکربندی به
مقادیر پیشفرض بازنشانی میشود). نسخهٔ یکسان یا قدیمیتر رد میشود.

## داشبورد

صفحه داشبورد در `/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) دو برگه را ارائه می دهد:

- **نصب شده است** — افزونههای نصبشده را با قلابهای اعلامشده، کلید activate/deactivate ، دکمه حذف نصب، و عمل «اسکن برای افزونهها» (`POST /api/plugins/scan`) فهرست میکند.
- **بازار** — کاتالوگ `GET /api/plugins/marketplace` را با فیلدی برای تنظیم رجیستری سفارشی URL نشان می دهد.

صفحه همیشه هشداری را نشان می دهد که افزونه ها با امتیازات کامل فرآیند OmniRoute اجرا می شوند.

یک صفحه پیکربندی هر پلاگین در `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) زندگی می کند.
