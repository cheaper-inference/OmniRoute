## چیست

OmniRoute به یک مخزن **Obsidian** بهعنوان **منبع زمینه** متصل میشود — یک پایگاه دانش
محلی Markdown که عاملها از طریق سرور داخلی MCP آن را میخوانند و در آن مینویسند.
این یکپارچهسازی با افزونهٔ عمومی **Obsidian Local REST API** که درون برنامهٔ دسکتاپ
اجرا میشود ارتباط برقرار میکند؛ بنابراین عاملها میتوانند یادداشتها را جستوجو کنند،
فایلها را بخوانند/بنویسند/وصله کنند، محتوای مخزن را فهرست کنند، با یادداشتهای دورهای
روزانه/هفتگی کار کنند، برچسبها را مدیریت کنند، فرمانهای Obsidian را اجرا کنند و
(بهصورت اختیاری) همگامسازی دوطرفهٔ مخزن بین دسکتاپ↔موبایل را هماهنگ کنند.

کلاینت (`src/lib/obsidian/api.ts`) قابلیتهای زیر را پیرامون Local REST API فراهم میکند:

- **تلاش مجدد با تأخیر افزایشی** برای خطاهای گذرای `5xx` و **مهلت زمانی ۳۰ ثانیهای** از طریق `AbortController`.
- **دستهبندی نوعدار خطاها** — `ObsidianAuthError` (401/403)،
  `ObsidianNotFoundError` (404)، `ObsidianServerError` (5xx)، `ObsidianTimeoutError`.
- یک **راهنمای دوستانه برای «عدم دسترسی به Obsidian»** که اشتباه رایج در انتخاب پورت
  را توضیح میدهد (HTTP روی `27123`، **نه** نقطهٔ پایانی MCP روی `27124`) و قالب Tailscale را ذکر میکند.
- **کدگذاری مسیر** نسبت به ریشهٔ مخزن، تا مسیر یادداشتهایی که فاصله یا اسلش دارند ایمن باشند.

## راهاندازی

برای توکن Obsidian یا URL پایه **هیچ متغیر محیطیای وجود ندارد** — هر دو از طریق
`src/lib/db/obsidian.ts` در جدول SQLite با نام `key_value` (در فضای نام `obsidian`)
ذخیره میشوند. توکن **در حالت ذخیرهشده رمزگذاری میشود** (AES-256-GCM، همراه با
روش جایگزین سازگار با نسخههای قبلی برای متن ساده). آن را از زبانهٔ **Context Sources**
در داشبورد Endpoint (`ObsidianSourceCard`) یا از طریق REST API تنظیمات پیکربندی کنید.

> [!IMPORTANT]
> افزونهٔ **Obsidian Local REST API** باید نصب و در حال اجرا باشد. رابط REST آن روی
> **HTTP `127.0.0.1:27123`** (URL پایهٔ پیشفرض) گوش میدهد. پورت `27124` یک نقطهٔ
> پایانی _مجزای_ MCP/HTTPS است و مسیر تنظیمات صراحتاً آن را رد میکند.
> در صورت اتصال از دستگاهی دیگر، از `http://<tailscale-ip>:27123` استفاده کنید.

### کلیدهای پیکربندی (SQLite `key_value`، فضای نام `obsidian`)

| کلید              | کاربرد                                           | رمزگذاریشده |
| ----------------- | ------------------------------------------------ | ----------- |
| `api_key`         | توکن bearer مربوط به Local REST API              | بله         |
| `base_url`        | URL پایهٔ REST (پیشفرض `http://127.0.0.1:27123`) | خیر         |
| `vault_path`      | مسیر مطلق پوشهٔ vault (برای همگامسازی)           | خیر         |
| `webdav_username` | نام کاربری WebDAV تولیدشده (همگامسازی vault)     | خیر         |
| `webdav_password` | گذرواژهٔ WebDAV تولیدشده (همگامسازی vault)       | بله         |
| `webdav_enabled`  | فعال بودن یا نبودن همگامسازی vault با WebDAV     | خیر         |

### پیکربندی از طریق REST

```bash
# ذخیره و اعتبارسنجی توکن Local REST API (درخواست POST با بررسی وضعیت اعتبارسنجی میکند)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# بررسی وضعیت اتصال (مقادیر connected، hasToken، baseUrl و vaultPath را برمیگرداند)
curl http://localhost:20128/api/settings/obsidian

# قطع اتصال (توکن ذخیرهشده را پاک میکند)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

همهٔ متدها به احراز هویت داشبورد نیاز دارند. `POST` هر URL روی پورت `27124` را رد
میکند و پیش از ذخیرهسازی، توکن را با فراخوانی نقطهٔ پایانی وضعیت Local REST API
اعتبارسنجی میکند.

### همگامسازی vault با WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` همگامسازی اختیاری vault مبتنی بر
WebDAV را مدیریت میکند (با هدایت `src/lib/obsidianSync.ts`). فعالسازی آن، OmniRoute
را به یک پوشهٔ محلی vault متصل میکند و یک جفت نام کاربری/گذرواژهٔ تصادفی WebDAV
میسازد:

```bash
# فعالسازی همگامسازی WebDAV برای یک پوشهٔ vault (نام کاربری/گذرواژه ایجاد میکند)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# دریافت وضعیت همگامسازی WebDAV (اعتبارنامهها فقط در حالت فعال برگردانده میشوند)
curl http://localhost:20128/api/settings/obsidian/webdav

# غیرفعالسازی همگامسازی WebDAV (اعتبارنامهها و فایل مدیریتشدهٔ .stignore را پاک میکند)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### امنیت و حمل و نقل

احراز هویت WebDAV ردیابی و قفل شکست در هر IP را اعمال می کند (10 تلاش ناموفق در یک پنجره 60 ثانیه ای یک قفل 5 دقیقه ای با `429 Too Many Requests` و `Retry-After` را آغاز می کند). از آنجایی که WebDAV اعتبار احراز هویت اولیه را ارسال می کند، خاتمه TLS (یا مسیریابی از طریق یک تونل امن مانند Tailscale یا Cloudflare Tunnel) به شدت توصیه می شود هنگام دسترسی به نقطه پایانی WebDAV در خارج از حلقه بک.

### منبع زمینهٔ اختصاصی برای هر کلید API (اختیاری)

پیکربندی Obsidian را میتوان از طریق جدول `api_key_context_sources` بهصورت
**اختصاصی برای هر کلید API** محدود کرد (`src/lib/db/apiKeyContextSources.ts`). هنگامی
که یک فراخوانی MCP دارای شناسهٔ کلید API احراز هویتشده باشد،
`getObsidianConfigForApiKey()` ابتدا توکن، URL پایه و مسیر vault مختص همان کلید
(`source: "api_key"`) را ترجیح میدهد و در غیر این صورت به پیکربندی سراسری
(`source: "global"`) بازمیگردد.

ابزارهای MCP غیرهمگامسازی پیش از خواندن این پیکربندی به هویت تعیینشدهٔ فراخواننده
نیاز دارند. فراخوانندهٔ فاقد هویت، پیام `Obsidian API token not configured` را دریافت
میکند و هیچ درخواستی به vault ارسال نمیشود. هویت فراخوانندگان HTTP از طریق
اعتبارنامههای درخواستشان تعیین میشود؛ هویت فراخوانندگان stdio میتواند از طریق
`OMNIROUTE_API_KEY` یا `ROUTER_API_KEY` تعیین شود. یک فراخوانندهٔ HTTP با هویت
تعییننشده نمیتواند هویت محیطی سرور را به ارث ببرد. شناسههای جاینگهدار بهتنهایی
مجوز دسترسی نمیدهند؛ پشتیبانی از یک اعتبارنامهٔ محیطی معتبر که به `env-key` نگاشت
میشود همچنان برقرار است. کلیدهای احراز هویتشدهای که پیکربندی اختصاصی Obsidian
ندارند، همچنان از پیکربندی سراسری بهعنوان گزینهٔ جایگزین استفاده میکنند. چهار ابزار
`obsidian_sync_*` رفتار جداگانهٔ خود را برای توکن همگامسازی حفظ میکنند.

## ابزار MCP (22)

در `open-sse/mcp-server/tools/obsidianTools.ts` تعریف شده است. token/base-URL در هر تماس حل می شود (اول به ازای کلید API، سپس سراسری). ابزارهایی که به OmniRoute ضربه می زنند** سرور همگام سازی** (چهار ابزار `obsidian_sync_*` ) علاوه بر این به نشانه تأیید اعتبار همگام سازی پیکربندی شده در تنظیمات OmniRoute نیاز دارند.

### ابزار خواندن (`read:obsidian`)

| ابزار                        | توضیحات                                                                                     |
| ---------------------------- | ------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | بررسی کنید که آیا REST API محلی قابل دسترسی و تأیید اعتبار است یا خیر.                      |
| `obsidian_search_simple`     | جستجوی متن کامل محتوای یادداشت؛ قطعه هایی را با مسیرهای فایل برمی گرداند.                   |
| `obsidian_search_structured` | جستجو با استفاده از عبارت منطق JSON (فیلترهای and/or/regex/path ).                          |
| `obsidian_read_note`         | خواندن یادداشت بر اساس مسیر طاق نسبی. اختیاری یک heading/block/frontmatter. خاص             |
| `obsidian_list_vault`        | فایل ها و دایرکتوری ها را در صندوق (درخت ورودی) فهرست کنید.                                 |
| `obsidian_get_document_map`  | ساختار عنوان یادداشت را به عنوان نقشه ای از اعداد خط سرفصل های → دریافت کنید.               |
| `obsidian_get_note_metadata` | مطالب اصلی، برچسبها، پیوندها، تعداد char/word را بدون محتوای کامل دریافت کنید.              |
| `obsidian_get_active_file`   | مسیر + محتوای فایل فعال فعلی را در Obsidian دریافت کنید.                                    |
| `obsidian_get_periodic_note` | یادداشت ادواری daily/weekly/monthly را برای یک تاریخ دریافت کنید (اگر امروز حذف شود).       |
| `obsidian_get_tags`          | همه تگ های طاق را با فرکانس آنها فهرست کنید.                                                |
| `obsidian_list_commands`     | دستور Obsidian موجود IDs را فهرست کنید (از `obsidian_execute_command` استفاده کنید).        |
| `obsidian_sync_status`       | وضعیت سرور همگام سازی OmniRoute : در حال اجرا، نام طاق، پورت، زمان آپدیت، آخرین همگام سازی. |
| `obsidian_sync_conflicts`    | تضادهای حل نشده همگام سازی (مسیر، مسیر تضاد، شناسایی-در) را فهرست کنید.                     |

### ابزار نوشتن (`write:obsidian`)

| ابزار                            | توضیحات                                                                                      |
| -------------------------------- | -------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | یک یادداشت با محتوای Markdown ایجاد کنید یا بازنویسی کنید.                                   |
| `obsidian_append_note`           | افزودن محتوا به یادداشت؛ اختیاری به یک heading/block. خاص                                    |
| `obsidian_patch_note`            | append/prepend/replace جراحی در یک میدان سرفصل، بلوک یا قسمت جلویی.                          |
| `obsidian_delete_note`           | یک یادداشت را برای همیشه از صندوق حذف کنید.                                                  |
| `obsidian_move_note`             | یک یادداشت را در خزانه جابجا یا تغییر نام دهید.                                              |
| `obsidian_execute_command`       | یک دستور Obsidian را با دستور ID آن اجرا کنید.                                               |
| `obsidian_open_file`             | یک فایل را در Obsidian باز کنید (اگر وجود نداشته باشد آن را ایجاد می کند).                   |
| `obsidian_sync_trigger`          | همگامسازی خزانه موبایل دسکتاپ ↔ فوری دو طرفه را راهاندازی کنید.                              |
| `obsidian_sync_resolve_conflict` | تضاد همگام سازی را حل کنید: `local` (موبایل)، `remote` (رومیزی) یا `keep-both` را نگه دارید. |

> [!NOTE]
> اهداف `obsidian_patch_note` `targetType` `heading | block | frontmatter` و `operation` `append | prepend | replace` را با `createTargetIfMissing` اختیاری می پذیرند. چهار ابزار `obsidian_sync_*` با سرور همگام سازی محلی (به طور پیش فرض `http://127.0.0.1:27781` ) صحبت می کنند و به نشانه همگام سازی نیاز دارند.

### محدوده ها

ابزار خواندن نیاز به `read:obsidian` دارد. ابزار نوشتن `write:obsidian` نیاز دارد. اجرا مشابه Notion — است که توسط `withScopeEnforcement()` در `open-sse/mcp-server/server.ts` انجام میشود، در `OMNIROUTE_MCP_ENFORCE_SCOPES=true` قرار میگیرد و برای تماسگیرندگان HTTP/SSE که کلید API فاقد `manage`/`admin` است، اجباری میشود، با محدودههای مجاز که از `OMNIROUTE_MCP_SCOPES` یا زمینه محدوده کلید API منبع میشوند. رجوع [MCP-SERVER.md](./MCP-SERVER.md) شود.

| `GET`    | `/api/settings/obsidian`        | برگرداندن `{ connected, hasToken, baseUrl, vaultPath }`.    |
| `POST`   | `/api/settings/obsidian`        | ذخیره و اعتبارسنجی توکن (پورت `27124` را رد میکند).         |
| `DELETE` | `/api/settings/obsidian`        | قطع اتصال (پاککردن توکن ذخیرهشده).                          |
| `GET`    | `/api/settings/obsidian/webdav` | وضعیت همگامسازی WebDAV و اطلاعات احراز هویت (در حالت فعال). |
| `POST`   | `/api/settings/obsidian/webdav` | فعالکردن همگامسازی WebDAV برای یک دایرکتوری مخزن.           |
| `DELETE` | `/api/settings/obsidian/webdav` | غیرفعالکردن همگامسازی WebDAV.                               |

> اینها مسیرهای تنظیمات داشبورد هستند. خود مخزن از طریق API محلی REST آبسیدین
> (`base_url` پیکربندیشده) و ابزارهای MCP بالا قابل دسترسی است — هیچ نقطه پایانی عمومی
> پراکسی آبسیدین در `/v1` وجود ندارد.

## موارد استفاده

- **پاسخهای مبتنی بر مخزن** — ابتدا `obsidian_search_simple` / `obsidian_search_structured`
  و سپس `obsidian_read_note` تا عامل بر اساس یادداشتهای واقعی شما پاسخ دهد.
- **نگارش یادداشت / روزنگاری** — استفاده از `obsidian_write_note`، `obsidian_append_note` یا
  `obsidian_patch_note` برای ویرایش دقیق، با هدف ثبت خروجی عامل، خلاصهها یا یادداشتهای روزانه
  (`obsidian_get_periodic_note`) در مخزن.
- **پیمایش مخزن** — استفاده از `obsidian_list_vault`، `obsidian_get_document_map` و
  `obsidian_get_tags` برای بررسی ساختار پیش از خواندن/نوشتن.
- **خودکارسازی آبسیدین** — استفاده از `obsidian_list_commands` + `obsidian_execute_command` برای
  اجرای افزونهها/فرمانها توسط عامل؛ و `obsidian_open_file` برای نمایش یک یادداشت در رابط کاربری.
- **همگامسازی موبایل** — همگامسازی WebDAV را فعال کنید، سپس از `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  برای هماهنگی دسکتاپ↔موبایل و رفع تعارضها استفاده کنید.
