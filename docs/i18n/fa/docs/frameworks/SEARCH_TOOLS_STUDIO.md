## نمای کلی

Search Tools Studio صفحهٔ `/dashboard/search-tools` را از یک محیط آزمایشی ساده برای جستجو به یک
استودیوی سهزبانه تبدیل میکند که جستجوی وب، استخراج محتوای وب و مقایسهٔ کنارهم ارائهدهندگان را یکپارچه میسازد.

```
┌ ابزارهای جستجو ────────────────────────────────────────────────────────┐
│ [🔍 جستجو] [📄 استخراج] [⚖ مقایسه]             142ms · $0.001  </>    │
│ ⓘ [راهنمای شیوهها]                                                    │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {محتوای زبانهٔ فعال}                    │ ─ پیکربندی                  │
│                                          │ ارائهدهنده [auto ∨]        │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (واکشی)      │
│                                          │ نوع   [وب | اخبار]          │
│                                          │ صفحهٔ کامل [ ] (استخراج)    │
│                                          │ قالب [md|متن|html]          │
│                                          │ مدل بازرتبهبندی [∨]        │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## زبانه ها

### برگه جستجو

`SearchForm` + `ResultsPanel` + `RerankPanel` موجود را به یک برگه تبدیل می کند:

- نتایج → را جستجو کنید (عنوان، URL، قطعه، امتیاز مربوط).
- فراداده ارائه دهنده در بخش پیکربندی (هزینه، سهمیه، وضعیت).
- بخش رتبهبندی مجدد: مدل رتبهبندی مجدد را انتخاب کنید، نتایج را دوباره ترتیب دهید، `positionDelta` را نشان دهید.
- حالت خالی با CTA هنگامی که هیچ ارائه دهنده جستجو پیکربندی نشده است.
- تاریخچه جستجو از طریق `SearchHistory.tsx`.
- `POST /v1/search` را فرا می خواند (نقطه پایانی موجود، بدون تغییر).

### Scrape Tab

تب جدید برای استخراج محتوا از URL از طریق `POST /v1/web/fetch` (ایجاد شده در طرح 05):

- ورودی: URL + تمام صفحه انتخابگر قالب + را تغییر دهید (مارک داون / متن / HTML).
- ارسال → fetch → رندر `ScrapeResult.tsx`.
- `ScrapeResult` ضامن پیش نمایش علامت گذاری + خام را ارائه می دهد.
- سرپوش: اگر بدن پاسخ >** 256 KB** ، UI `(truncated, view raw)` نشان می دهد و به صورت خام در حالت موناکو (D21) باز می شود.
- پانل فراداده: ارائه دهنده (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search)، تأخیر، هزینه، اندازه پاسخ، تعداد پیوندها.
- از قلاب `useScrapeFetch.ts` استفاده می کند.

### برگه مقایسه

اجرای همان query/URL در سراسر تا** 4 ارائه دهنده به صورت موازی** (D22):

- ستون های کنار هم به ازای هر ارائه دهنده.
- معیارها: تاخیر، هزینه، تعداد نتایج، اندازه پاسخ.
- محاسبه همپوشانی URL برای جستجو (تعداد URLs مشترک در مقابل نتیجه اولیه).
- به ازای هر ارائه دهنده، `POST /v1/search` (جستجو) یا `POST /v1/web/fetch` (خراش) را صدا می کند.

## SearchConceptCard

`SearchConceptCard.tsx` — همیشه قابل مشاهده، آکاردئونی و جمعشونده. موارد زیر را توضیح میدهد:

| مفهوم                  | توضیح کوتاه                                                               |
| ---------------------- | ------------------------------------------------------------------------- |
| **جستوجو**             | فهرستی از نتایج وب (عنوان، URL، خلاصه و امتیاز مرتبطبودن) را دریافت میکند |
| **استخراج**            | محتوای کامل یک URL را استخراج میکند (markdown، متن یا HTML)               |
| **مقایسه**             | یک کوئری یکسان را بهصورت همزمان در N ارائهدهنده اجرا میکند                |
| **رتبهبندی مجدد**      | برای بهبود ارتباط با کوئری، نتایج را با استفاده از LLM دوباره مرتب میکند  |
| **خودکار (ارزانترین)** | ارزانترین ارائهدهنده موجود را بهطور خودکار انتخاب میکند                   |

## کاتالوگ ارائه دهنده

`ProviderCatalog.tsx` فهرست کامل ارائهدهندگان را از `GET /api/search/providers` نشان میدهد (در F4 گسترش یافته تا ارائهدهندگان واکشی را نیز شامل شود):

| `kind` | `"search"` (24 ارائه دهنده) یا `"fetch"` (firecrawl، jina-reader، tavily-search، tinyfish، nimble-search، anysearch-search، parallel-search، enable-search) |

وضعیت است** به دست آمده در زمان درخواست** با بررسی اینکه آیا اعتبارنامه ها وجود دارند و آیا همه کلیدها در حال حاضر در حالت خنک کننده هستند یا خیر.

`codex-search` (جستجوی وب Codex ) کلیدی ندارد: از یک حساب متصل Codex (ChatGPT) مجددا استفاده می کند، بنابراین هر جستجو سهمیه اشتراک ChatGPT را صرف می کند و حدود 10 تا 40 ثانیه طول می کشد. زمانی اجرا می شود که یک درخواست آن را نامگذاری کند. انتخاب خودکار به پرچم ویژگی `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` (به طور پیش فرض خاموش) نیاز دارد.

`ExportCodeModal` (واردشده از Playground Studio) بههمراه `codeExport.ts`، قطعهکدهای
curl / Python / TypeScript را برای فراخوانیهای `/v1/search` و `/v1/web/fetch` تولید میکنند.
مقدار جایگزین کلید API همیشه `$OMNIROUTE_API_KEY` است (D11، مشترک با Playground Studio).

## تغییرات Backend

فقط یک تغییر باطن برای این ویژگی مورد نیاز بود:

### توسعه یافته `GET /api/search/providers`

`src/app/api/search/providers/route.ts` به:

- هر ارائه دهنده واکشی (`firecrawl`، `jina-reader`، `tavily-search`، `tinyfish`، `nimble-search`، `anysearch-search`، `parallel-search`، `keenable-search`) را در آرایه قرار دهید.
- `kind: "search" | "fetch"` به هر مورد اضافه کنید.
- `status: "configured" | "missing" | "rate_limited"` مشتق شده از حالت اعتبار زنده را اضافه کنید.
- فیلدهای موجود — (`id`، `name`، و غیره) سازگاری عقب مانده را بدون تغییر حفظ کنید.
