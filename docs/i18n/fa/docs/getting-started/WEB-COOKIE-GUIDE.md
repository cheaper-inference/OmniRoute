ارائهدهندگان کوکی وب به OmniRoute اجازه میدهند بهجای کلید API، از طریق نشست فعلی مرورگر شما از یک سرویس هوش مصنوعی استفاده کند. این ارائهدهندگان زمانی مفید هستند که از قبل از طریق وبسایت یک سرویس به آن دسترسی دارید و میخواهید OmniRoute از همان نشست احراز هویتشده استفاده کند.

برخلاف ارائهدهندگان مبتنی بر کلید API، ارائهدهندگان کوکی وب با استفاده از اطلاعات اعتباریای احراز هویت میکنند که مرورگر شما برای وبسایت ارسال میکند.

# پیش از شروع

> **مهم:** همیشه اطلاعات اعتباری را از یک **درخواست زنده شبکه** کپی کنید، **نه** از محل ذخیرهسازی کوکی مرورگر.

بسیاری از مشکلات احراز هویت بهدلیل کپیکردن کوکیها از محل اشتباه رخ میدهند.

## از محل ذخیرهسازی کوکی کپی نکنید

بیشتر مرورگرها کوکیهای ذخیرهشده را از طریق مسیر زیر نمایش میدهند:

```
ابزارهای توسعهدهنده
→ برنامه (یا فضای ذخیرهسازی)
→ کوکیها
```

اگرچه ممکن است این کوکیها صحیح به نظر برسند، ممکن است:

- منقضیشده باشند
- ناقص باشند
- فاقد کوکیهایی باشند که فقط در درخواستهای احراز هویتشده ارسال میشوند

استفاده از این مقادیر ممکن است حتی در صورت معتبر به نظر رسیدن آنها، باعث شکست احراز هویت شود.

## از یک درخواست زنده کپی کنید

در عوض، از کوکیهای یک درخواست موفق استفاده کنید:

```
ابزارهای توسعهدهنده
→ شبکه
→ تازهسازی صفحه
→ بازکردن یک درخواست چت یا مکالمه
→ سرآیندهای درخواست
→ کوکی
```

سرآیند درخواست `Cookie` حاوی اطلاعات دقیق احراز هویتی است که مرورگر شما با موفقیت از آن استفاده کرده است.

برای بیشتر ارائهدهندگان کوکی وب، این همان مقداری است که باید در OmniRoute جایگذاری شود.

# راهاندازی عمومی

فرایند راهاندازی برای بیشتر ارائهدهندگان کوکی وب یکسان است.

1. وارد وبسایت ارائهدهنده شوید.
2. ابزارهای توسعهدهنده مرورگر را باز کنید.
3. زبانه **شبکه** را باز کنید.
4. صفحه را تازهسازی کنید.
5. یک درخواست چت یا مکالمه احراز هویتشده را باز کنید.
6. اطلاعات اعتباری موردنیاز برای احراز هویت را کپی کنید.
7. OmniRoute را باز کنید.
8. به **ارائهدهندگان ← افزودن ارائهدهنده** بروید.
9. ارائهدهنده کوکی وب خود را انتخاب کنید.
10. اطلاعات اعتباری را جایگذاری کنید.
11. روی **آزمایش اتصال** کلیک کنید.
12. ارائهدهنده را ذخیره کنید.

اطلاعات اعتباری دقیق موردنیاز به ارائهدهنده بستگی دارد.

وبسایتهای مختلف اطلاعات احراز هویت را به روشهای متفاوتی ذخیره میکنند. برخی فقط به کوکیها نیاز دارند، درحالیکه برخی دیگر ممکن است به سرآیندها یا توکنهای اضافی نیاز داشته باشند.

| ارائهدهنده                      | قالب اطلاعات اعتباری          | راهنمای ارائهدهنده               |
| ------------------------------- | ----------------------------- | -------------------------------- |
| Claude Web                      | سرآیند کامل درخواست Cookie    | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | سرآیند کامل Cookie            | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(نیازمند بررسی)_             |                                  |
| Copilot Web                     | _(نیازمند بررسی)_             | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(نیازمند بررسی)_             |                                  |
| ...                             | ...                           | ...                              |

> با اضافهشدن ارائهدهندگان جدید کوکی وب یا تغییر الزامات احراز هویت ارائهدهندگان موجود، این جدول را بهروزرسانی کنید.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) یک پلتفرم رایگان چت برای کاربران است که به ثبتنام نیاز ندارد — نشست در اولین بازدید بهصورت ناشناس ایجاد میشود و از طریق سه کوکی `uid`، `si_usr_id` و `si_ses_id` پایدار میماند. OmniRoute همان نقطه پایانی `/api/dispatch` را از طریق یک شناسه مدل واحد (`notrack-c`، با نام مستعار `ntw`) پروکسی میکند.

### مراحل اتصال

1. وبسایت [notrack.ai](https://notrack.ai) را در مرورگر خود باز کنید و اجازه دهید کوکی نشست ناشناس تنظیم شود.
2. **ابزارهای توسعه → شبکه** را باز کنید، صفحه را تازهسازی کنید و روی یکی از درخواستهای `/api` کلیک کنید.
3. در بخش **سرآیندهای درخواست**، مقدار کامل سرآیند `Cookie` را کپی کنید.
4. در OmniRoute، به **ارائهدهندگان → افزودن ارائهدهنده → NoTrack Web (رایگان)** بروید.
5. رشته کوکی را در فیلد `apiKey` جایگذاری کنید و **ذخیره** را بزنید.

OmniRoute مقادیر `uid`، `si_usr_id` و `si_ses_id` را از رشته جایگذاریشده استخراج میکند و یک سرآیند پاکسازیشده `Cookie` را تنها با همین جفتها بازسازی میکند — و در صورت وجود، `nt_session` (توکن `ntk_…` که برای حسابهای واردشده تنظیم میشود) را نیز اضافه میکند. اگر هر یک از این سه مورد وجود نداشته باشد، رشته خام جایگذاریشده بدون تغییر ارسال میشود تا اپراتورها بتوانند ساختارهای جایگزین را آزمایش کنند.

### شناسههای مدل

| شناسه مدل   | نام نمایشی | توضیحات                                         |
| ----------- | ---------- | ----------------------------------------------- |
| `notrack-c` | NoTrack C  | پیشفرض — مدل توزیع بالادستی `C`.                |
| `C`         | NoTrack C  | نام مستعار `notrack-c` (کد خام توزیع بالادستی). |
| `notrack`   | NoTrack C  | نام مستعار `notrack-c`.                         |
| `ntw`       | NoTrack C  | نام مستعار کوتاه برای `notrack-c`.              |

هر چهار شناسه مدل به یک مدل توزیع بالادستی یکسان (`C`) نگاشت میشوند.

### گزینههای درخواست

اجراکننده این فیلدهای اختیاری را در بدنه درخواست میپذیرد:

| فیلد بدنه             | پیشفرض  | کاربرد                                                                           |
| --------------------- | ------- | -------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual` | حالت توزیع (رشتهای با قالب آزاد؛ سرویس بالادستی `usual` و موارد دیگر را میپذیرد) |
| `notrack_max_turns`   | `6`     | تعداد نوبتهای داخلی که سرویس بالادستی میتواند پیش از پاسخگویی طی کند.            |
| `notrack_chat_id`     | `null`  | ادامهدادن یک چت بالادستی موجود (برای چت جدید حذف شود).                           |
| `notrack_attachments` | `[]`    | آرایه عبوریِ توصیفگرهای پیوست بالادستی.                                          |
| `notrack_regenerate`  | `false` | برای درخواست تولید مجدد پاسخ نوبت قبلی، روی `true` تنظیم شود.                    |

### قابلیتها

- تکمیلهای چت **جریانی و غیرجریانی**.
- **فراخوانی ابزار** — در درخواست، `tools: [...]` را تنظیم کنید؛ اجراکننده آنها را در قالب قرارداد پوششی فراخوانی ابزار سریالسازی میکند و پاسخهای مدل را دوباره به `tool_calls` مربوط به OpenAI تبدیل میکند.
- **`response_format`** — از `json_object` و `json_schema` پشتیبانی میشود. اجراکننده نخستین شیء JSON را از پاسخ مدل استخراج میکند و پیش از بازگرداندن، آن را به رشته تبدیل میکند.
- **نشانه استدلال** — هنگامی که سرویس بالادستی رویداد `thinking` را ارسال میکند، اجراکننده یک دلتا از نوع `reasoning` منتشر میکند.

### محدودیتها

- سرویس بالادستی سهمیههای استفاده ناشناس را اعمال میکند — در صورت عبور از سهمیه، اجراکننده خطای 429 را همراه با پیامی کاربرپسند نمایش میدهد.
- همه شناسههای مدل به یک مدل توزیع بالادستی یکسان منتهی میشوند؛ امکان تغییر مستقل برای هر مدل وجود ندارد.
- اجراکننده نقطه پایانی `/api/chats` سرویس بالادستی را فراخوانی نمیکند؛ بنابراین تاریخچه چت و نشستها بهصورت خودکار مدیریت نمیشوند. برای ادامهدادن یک چت بالادستی موجود، از `notrack_chat_id` استفاده کنید.

# ارائهدهندگان کوکی وب چه کارهایی میتوانند و نمیتوانند انجام دهند

ارائهدهندگان کوکی وب از رابط چت یک وبسایت دوباره استفاده میکنند. آنها قابلیتهایی یکسان با APIهای رسمی ارائه **نمیدهند**.

## پشتیبانیشده

- احراز هویت با استفاده از نشست فعلی مرورگر شما
- دسترسی به مدلهای موجود از طریق حساب شما
- استریم پاسخهای چت
- بدون نیاز به کلید API

## پشتیبانینشده

- فراخوانی تابع
- فراخوانی ابزار
- ویرایش خودکار فایل
- گردشکارهای عاملی IDE
- قابلیتهای مختص API

این رفتار مورد انتظار است و **باگ نیست**.

اگر به اجرای ابزار، ویرایش خودکار فایل یا سایر گردشکارهای عاملی نیاز دارید، بهجای ارائهدهنده Web Cookie از یک **ارائهدهنده مبتنی بر کلید API** استفاده کنید.

# نکته مهم درباره اعتبارسنجی

موفقیت در **Test Connection** یا اعتبارسنجی کوکی فقط تأیید میکند که اطلاعات احراز هویت ارائهشده ظاهراً قالب مورد انتظار را دارند.

تا زمانی که Issue #7857 برطرف نشده است، اعتبارسنجی موفق **تضمین نمیکند** که ارائهدهنده بتواند احراز هویت را با موفقیت انجام دهد.

اگر احراز هویت همچنان ناموفق است، بررسی کنید که اطلاعات احراز هویت را بهجای فضای ذخیرهسازی کوکی مرورگر، از یک درخواست زنده شبکه کپی کرده باشید.

---

# عیبیابی

## احراز هویت ناموفق است

بررسی کنید که اطلاعات احراز هویت از مسیر زیر کپی شده باشند:

```
Network
→ Request Headers
→ Cookie
```

و **نه** از مسیر زیر:

```
Application
→ Cookies
```

---

## کوکی در مرورگر کار میکند، اما در OmniRoute کار نمیکند

برخی ارائهدهندگان کوکیهایی دارند که فقط هنگام ارسال درخواستهای احرازشده فرستاده میشوند.

پس از باز کردن موفقیتآمیز یک گفتگو، اطلاعات احراز هویت را دوباره از یک درخواست جدید شبکه کپی کنید.

---

## نشست منقضی شده است

ارائهدهندگان Web Cookie از نشست فعلی مرورگر شما استفاده میکنند.

اگر نشست مرورگر شما منقضی شود یا از حساب خارج شوید، باید مجموعه جدیدی از اطلاعات احراز هویت را کپی کنید. برای خودکارسازی تمدید کوکی در ارائهدهندگان وب پشتیبانیشده، ابزار همراه [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) را ببینید.

---

## Test Connection موفق است، اما درخواستها ناموفقاند

تا زمانی که Issue #7857 برطرف نشده است، موفقیت در اعتبارسنجی تضمین نمیکند که درخواست احراز هویت موفق شود.

پیش از ادامه عیبیابی، اطلاعات احراز هویت خود را دوباره از یک درخواست احرازشده جدید کپی کنید.

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

اطلاعات احراز هویت مشکلی ندارد — این خطا از پل ارتباطی ناشی میشود، نه از نشست. chatgpt.com شناسههای
ماژول خود را در هر استقرار تعیین میکند و پل ارتباطی قبلاً شناسه ابزار کمکی Sentinel را که نمونهسازی میکرد ثابت نگه میداشت؛ بنابراین
بازسازی chatgpt.com که نام ابزار کمکی را تغییر میداد، باعث میشد همه نوبتها با شکست مواجه شوند، در حالی که کوکی همچنان معتبر بود. صدور مجدد مجوز
برای اتصال نمیتواند این مشکل را برطرف کند.

بیلدهایی که ماژول را از طریق زمان اجرای خود صفحه پیدا میکنند، هیچ شناسهای را ثابت نگه نمیدارند و با این مشکل مواجه نمیشوند. اگر این
خطا را مشاهده کردید، OmniRoute را ارتقا دهید و بررسی اتصال را دوباره اجرا کنید.

# بهترین روشها

- اطلاعات احراز هویت را از یک درخواست احرازشده جدید کپی کنید.
- از استفاده مجدد کوکیهای قدیمی خودداری کنید.
- هنگام استفاده از ارائهدهندگان Web Cookie، نشست مرورگر خود را فعال نگه دارید.
- کوکیهای کپیشده را اطلاعات احراز هویت حساس در نظر بگیرید.
- هنگامی که به فراخوانی تابع یا گردشکارهای عاملی نیاز دارید، از ارائهدهندگان مبتنی بر کلید API استفاده کنید.
