> کلیدهای runtime که رفتار OmniRoute را **بدون استقرار مجدد** تغییر میدهند.
> تمام فلگهای فهرستشده در اینجا در
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> تعریف شدهاند — منبع واحد حقیقت. داشبورد و REST API هر دو از
> آن فایل میخوانند، بنابراین جدول زیر بهگونهای تولید شده است که دقیقاً بهصورت 1:1 با آن مطابقت داشته باشد.

## فلگهای قابلیت چیستند

فلگ قابلیت یک کلید نامگذاریشده (از نوع boolean یا enum) است که مقدار آن را میتوان در
runtime تغییر داد و در پایگاه داده ذخیره کرد، بدون اینکه نیاز به استقرار مجدد فرایند باشد. هر
فلگ با یک `FeatureFlagDefinition` توصیف میشود که شامل `key`، `label`،
`description`، `category`، `defaultValue`، `type` و راهنمای `requiresRestart` است.

### ترتیب تعیین مقدار

**مقدار مؤثر** یک فلگ توسط
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) و با ترتیب
اولویت زیر تعیین میشود (بالاترین اولویت برنده است):

1. **بازنویسی DB** — مقداری که در جدول `key_value` و در فضای نام
   `feature_flags` ذخیره شده است (از طریق داشبورد یا REST API تنظیم میشود).
2. **متغیر محیطی** — `process.env[<KEY>]`، در صورتی که تنظیم شده و خالی نباشد.
3. **مقدار پیشفرض تعریف** — مقدار `defaultValue` از `featureFlagDefinitions.ts`.

یک فلگ boolean زمانی **فعال** در نظر گرفته میشود که مقدار مؤثر آن `"true"`،
`"1"` یا `"yes"` باشد (`isFeatureFlagEnabled()` را ببینید).

> [!NOTE]
> بیشتر فلگها همچنین یک متغیر محیطی متناظر با **همان نام** دارند
> که در [`ENVIRONMENT.md`](./ENVIRONMENT.md) مستند شده است. بازنویسی DB فلگ
> نسبت به آن متغیر محیطی اولویت دارد. فلگی با
> `requiresRestart: true` بلافاصله ذخیره میشود، اما فقط هنگام راهاندازی
> فرایند دوباره خوانده میشود — تغییر آن، بنر **«راهاندازی مجدد سرور»** را در داشبورد نمایش میدهد.

| `CREDENTIAL_GATE_AUTH_DIAGNOSES_ONLY`     | boolean | `false` | دروازهٔ اعتبارنامهٔ ترکیبی را محدود میکند تا یک بررسی ناموفقِ ذخیرهشده در حافظهٔ نهان، تنها زمانی اتصال را مسدود کند که تشخیص آن، نامعتبر بودن اعتبارنامهها را اثبات کند (`upstream_auth_error`، `auth_missing`، `token_expired`، `token_refresh_failed`، `reauth_required`، `account_deactivated`، `auth_required`). در این حالت، خطاهای غیرقطعی (مهلتهای زمانی، محدودیتهای نرخ، قطعی سرویس، بررسیهای پشتیبانینشده و خطاهای زمانبندِ بدون نوع) ناشناخته تلقی میشوند و اتصال همچنان ترافیک دریافت میکند. بهطور پیشفرض غیرفعال است: هر خطای بررسیِ ذخیرهشده در حافظهٔ نهان، اتصال را برای مدت TTL حافظهٔ نهان (۵ دقیقه) مسدود میکند. |

> [!NOTE]
> `INPUT_SANITIZER_BLOCK_THRESHOLD` و نام مستعار قدیمی آن
> `INJECTION_GUARD_BLOCK_THRESHOLD` حالت `block` مربوط به
> `INJECTION_GUARD_MODE` را تنظیم میکنند، اما متغیرهای محیطی سادهای هستند که توسط
> [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts)
> خوانده میشوند، نه پرچمهای قابلیت: آنها نه بازنویسی در DB دارند و نه کلیدی در داشبورد. به
> [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication) مراجعه کنید.

> [!NOTE]
> ستون `Restart` پرچمهایی را که دارای `requiresRestart: true` هستند مشخص میکند — مقدار
> بلافاصله ذخیره میشود، اما تنها پس از بارگذاری مجدد فرایند اعمال میشود. پرچمهای
> enum هر مقداری خارج از مجموعهٔ مجاز خود را رد میکنند (اعتبارسنجی در سمت سرور، هم در
> `setFeatureFlagOverride()` و هم در کنترلکنندهٔ REST `PUT` انجام میشود).

## تغییر وضعیت پرچمها

### داشبورد

به مسیر **داشبورد ← تنظیمات ← پرچمهای قابلیت**
(`/dashboard/settings/feature-flags`) بروید. شبکه
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
از موارد زیر پشتیبانی میکند:

- **جستوجو** بر اساس کلید یا توضیحات، و **فیلترکردن** بر اساس دستهبندی (بهعلاوهٔ نمای مصنوعی
  **نیازمند راهاندازی مجدد**).
- یک **کلید تغییر وضعیت** برای پرچمهای بولی و یک **فهرست کشویی** برای پرچمهای enum
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- یک **نشان منبع** برای هر پرچم — `DB`، `ENV` یا `DEF` — که نشان میدهد
  مقدار مؤثر از کجا آمده است.
- یک دکمهٔ **بازنشانی** (که فقط برای پرچمهایی با منبع `DB` نمایش داده میشود) برای حذف مقدار بازنویسیشده،
  و یک دکمهٔ **بازنشانی همهٔ بازنویسیها** در پایین صفحه.
- هنگامی که پرچمی با `requiresRestart` تغییر کند، یک بنر **راهاندازی مجدد سرور** نمایش داده میشود.

### API مبتنی بر REST

تمام عملیات از طریق یک مسیر واحد انجام میشوند:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
هر متد به یک نشست احرازهویتشدهٔ داشبورد نیاز دارد (در غیر این صورت `401`).

#### `GET /api/settings/feature-flags`

همهٔ پرچمها را همراه با مقدار مؤثر، منبع و خلاصهای از آنها برمیگرداند.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... همهٔ 111 پرچم
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

یک بازنویسی را تنظیم یا حذف میکند. بدنه: `{ key: string; value?: string }`.
حذف `value` از بدنه، بازنویسی را حذف میکند (و مقدار env / پیشفرض را بازمیگرداند).

```bash
# تنظیم یک بازنویسی در DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# حذف بازنویسی (بدون "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

پاسخ، `effectiveValue`/`source` جدید، `previousValue`/
`previousSource` و `requiresRestart` را بازمیگرداند. کلیدهای ناشناخته و مقادیر enum
خارج از محدوده با `400` رد میشوند.

#### `DELETE /api/settings/feature-flags`

**همهٔ** بازنویسیهای DB را بهصورت همزمان پاک میکند و تمام پرچمها را به مقدار env / پیشفرض
آنها بازمیگرداند. `{ cleared: <count>, message: "..." }` را برمیگرداند.

> [!NOTE]
> پرچمهایی با `requiresRestart: true` تنها پس از بارگذاری مجدد فرایند اعمال میشوند.
> روند راهاندازی مجدد داشبورد، `POST /api/restart` را فراخوانی میکند و سپس
> `GET /api/health/ping` را تا زمان راهاندازی مجدد سرور بهطور دورهای بررسی میکند.

## جایگزین اضطراری بودجه

`OMNIROUTE_EMERGENCY_FALLBACK` (دستهٔ `runtime`، مقدار پیشفرض `true`) مسیر
جایگزین رایگان اضطراری را در
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
کنترل میکند. هنگامی که فعال باشد، درخواستهایی که بودجهٔ خود را به پایان
رساندهاند، بهجای شکست کامل، به یک ارائهدهنده/مدل جایگزین رایگان هدایت
میشوند. برای غیرفعال کردن این رفتار و شکست خوردن درخواستهایی که بودجهشان
تمام شده است، آن را — از طریق کلید داشبورد، بازنویسی DB یا متغیر محیطی
`OMNIROUTE_EMERGENCY_FALLBACK` — روی `false` (یا `0`) تنظیم کنید. (در PRهای
#3741 / #3752 بهصورت یک کلید داشبورد ارائه شده است.)

پاسخی که توسط این جایگزین ارائه میشود، دارای هدر
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` است؛
بنابراین، کلاینت بدون مقایسهٔ `X-OmniRoute-Provider` با درخواست خود میتواند
تشخیص دهد که درخواست دوباره مسیریابی شده است. این هدر در هیچ پاسخ دیگری وجود
ندارد.
