OmniRoute آرتیفکتهای npm + Docker را منتشر میکند. این دروازهها اصالت (provenance)، موجودی (SBOM) و اسکن CVE را فراهم میکنند، که همگی متنباز (OSS) هستند و در جریانهای کاری انتشار (release workflows) ادغام شدهاند. رویکرد **مشاورهای-اول** — آنها اکنون گزارش میدهند، و پس از اولین انتشار موفق (green release) به حالت مسدودکننده ارتقا مییابند.

| دروازه                | ابزار                                          | کجا                           | مسدود میکند؟            | خروجی                                           |
| :-------------------- | :--------------------------------------------- | :---------------------------- | :---------------------- | :---------------------------------------------- |
| اصالت SLSA (npm)      | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | فقط در صورت شکست انتشار | نشان npmjs / `npm audit signatures`             |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | فقط در صورت شکست تولید  | دارایی انتشار + آرتیفکت                         |
| SBOM ایمیج            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | مشاورهای                | آرتیفکت CycloneDX                               |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | مشاورهای                | SARIF (HIGH+CRITICAL) → تب Security             |
| دروازه CRITICAL Trivy | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **مسدودکننده**          | `exit-code: '1'` در CRITICAL قابل رفع           |
| شمارش آسیبپذیری osv   | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **مسدودکننده**          | `metrics.vulnCount` را تنظیم میکند (جهت: نزولی) |
| کارت امتیازی OpenSSF  | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | مشاورهای                | SARIF → Security + نشان                         |

تنظیمکننده CVE ایمیج از **دو مرحله** در `docker-publish.yml` استفاده میکند: مرحله SARIF (`HIGH,CRITICAL`, `exit-code: 0`) موارد HIGH+CRITICAL را در تب Security بدون مسدود کردن قابل مشاهده نگه میدارد؛ مرحله _دروازه CRITICAL_ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) انتشار را در صورت وجود یک CVE از نوع CRITICAL **با راهحل موجود** با شکست مواجه میکند. `ignore-unfixed` از مسدود شدن انتشار برای یک CVE ایمیج پایه بدون پچ بالادستی جلوگیری میکند.

## ⚠️ تغییرپذیری CVE (گیتهای مسدودکنندهٔ osv/Trivy)

osv و Trivy وابستگیها را با پایگاههای دادهٔ CVE مقایسه میکنند که **بهطور مداوم رشد میکنند**. یک PR که **هیچ وابستگیای را تغییر نمیدهد** ممکن است ناگهان قرمز شود، زیرا یک CVE جدید در یکی از وابستگیهای موجود افشا شده است (osv: مقدار اندازهگیریشدهٔ `vulnCount` بیشتر از خط مبنا؛ Trivy: وجود یک آسیبپذیری CRITICAL جدید و قابلرفع در ایمیج). **این رفتار عملیاتی مورد انتظار از یک گیت مسدودکنندهٔ CVE است، نه یک پسرفت در محصول.**

هنگامی که osv یا Trivy بهدلیل یک CVE تازه افشاشده قرمز میشوند، راهحل این است:

1. **نسخهٔ وابستگی متأثر را ارتقا دهید** (ترجیحی) — از طریق `package.json` و
   `overrides` (برای وابستگیهای گذرا) به نسخهٔ وصلهشده ارتقا دهید، یا ایمیج را بر پایهٔ یک بیس وصلهشده دوباره بسازید.
2. **اگر درمان در دسترس نیست:** یافته های اندازه گیری شده را حفظ کرده و وابستگی یا تصویر آسیب دیده را دنبال کنید. خط پایه آسیب پذیری را افزایش ندهید تا نامزد ناموفق قبول شود. Trivy's `ignore-unfixed: true` در حال حاضر آسیبپذیریهای تصویر را بدون وصله بالادستی حذف میکند. هر استثنا مستلزم یک آسیبپذیری بازبینی شده ID، مسیر دقیق بسته، انقضا و موضوع ردیابی در خطمشی است. این یک پیامد خودکار یک اسکن ناموفق نیست.

اجراهای الزامی OSV (`check:vuln-ratchet -- --ratchet`) هنگامی که اسکنر، گزارش یا خط مبنا قابل اعتبارسنجی نباشد، بهصورت بسته شکست میخورند و با
`INCOMPLETE` و کد خروج 2 خاتمه مییابند.
یک پسرفت اندازهگیریشده با کد خروج 1 خاتمه مییابد. اجرای مشورتی همچنان میتواند `SKIP` را با
کد خروج 0 گزارش کند، اما این نتیجه اثبات نمیکند که وابستگیها اسکن را با موفقیت گذراندهاند. مرحلهٔ مسدودکنندهٔ
Trivy نیز به یک اندازهگیری موفق نیاز دارد: ابزارهای دردسترسنبودنی، کارهای ناموفق
و شواهد مفقود دربارهٔ ایمیج نمیتوانند پاکبودن یک ایمیج را تأیید کنند.

## سیاست اسکن تصویر

`.trivyignore.yaml` فعلی هیچ استثنایی در مورد آسیبپذیری ندارد. `npm run check:trivy-ignore-policy` خط مشی ساختاریافته را در پروفایل های اسکن محلی، CI و کیفیت تأیید می کند. IDs ناشناخته، مسیرهای گسترده تر، ورودی های تکراری و استثناهای منقضی شده رد می شوند. میراث `.trivyignore` ورودی اسکن های منتقل شده نیست.

Docker ابزارهای خط مشی را از `github.workflow_sha` و خط مشی منبع تصویر را با همان منبع انتخابگر ساخت بررسی می کند. انتخابگر خط مشی دامنه های ناسازگار را رد می کند و یک فایل را برای هر دو اسکن Trivy آماده می کند. منبع تاریخی بدون خط مشی ساختاریافته هیچ استثنایی دریافت نمی کند. هر دو اسکن Trivy `v0.70.0` را پین می کنند. اعتبار سنجی خط مشی ثبات پیکربندی را ثابت می کند. تصویر همچنان نیاز به اسکن موفقیت آمیز دارد.

## خطر وابستگی بازنشسته

پس از ارتقاء ابزار توسعه promptfoo پین شده، فایل lock root دیگر شامل `extract-zip` یا لبه وابستگی به آن نیست. این امر زنجیره `promptfoo` → `@openai/codex-security` → `extract-zip` #14482 که قبلاً پذیرفته شده بود بازنشسته میکند. بررسی های رگرسیون در `tests/unit/extract-zip-14482-exposure.test.ts` معرفی مجدد آن را رد کرده و ممنوعیت واردات از کد تولید را حفظ می کند.

تعمیر وابستگی کنونی همچنین سازگاری را به مشتری MSAL هویت Azure و مشتری FTP get-uri لغو می کند. کسب توکن Azure و بازیابی FTP با حمل و نقل کنترل شده آزمایش می شود. هر دو بسته OpenCode مجموعه های ساخت و آزمایش خود را اجرا می کنند. شمارش مشاوره رجیستری اندازه گیری در یک نقطه از زمان است و می تواند پس از تعهد فایل قفل تغییر کند.

## بکلاگ: مشاوره Scorecard → مسدودکننده

- Scorecard: ratchet امتیاز (امتیاز اندازهگیری شده را ثابت میکند؛ نمیتواند کاهش یابد).
