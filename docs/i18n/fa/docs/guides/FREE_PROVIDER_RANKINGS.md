> **خلاصه**: OmniRoute ارائهدهندگان **رایگان** خود را بر اساس کیفیت مدل و با استفاده از **امتیازهای ELO در Arena AI
> (به سبک LMArena)** رتبهبندی میکند. صفحهٔ **رتبهبندی ارائهدهندگان رایگان** را در
> داشبورد باز کنید تا ببینید کدام ارائهدهندگان رایگان، قدرتمندترین مدلها را برای وظیفهٔ شما عرضه میکنند —
> چه بهصورت کلی و چه با فیلتر بر اساس دستهبندی (کدنویسی، بازبینی، مستندسازی، اشکالزدایی).

## چیست

OmniRoute تعداد ۳۷۶ ارائهدهنده (provider) را ثبت میکند که از این میان ۱۵۵ ورودی کاتالوگ با برچسب **free/no-auth** مشخص شدهاند
(no-auth،
OAuth با سطح رایگان، یا کلید API با سطح رایگان — به
[راهنمای سطحهای رایگان](../getting-started/FREE-TIERS-GUIDE.md) و فهرست کامل
[سطحهای رایگان](../reference/FREE_TIERS.md) مراجعه کنید). نکته اینجاست: کیفیت مدلهای ارائهدهندگان رایگان بسیار متفاوت است. یک ارائهدهنده no-auth که مدلی پیشرفته (frontier) ارائه میدهد، بسیار مفیدتر از ارائهدهندهای است که مدلی کوچک و قدیمی ارائه میدهد.

**رتبهبندی ارائهدهندگان رایگان** به این پرسش پاسخ میدهد: «**کدام ارائهدهنده رایگان بهترین مدل را در اختیارم میگذارد؟**»
این کار با پیوند دادن کاتالوگ هر ارائهدهنده رایگان به **امتیازهای کیفی جمعسپاریشده** از
**تابلوی امتیازات Arena AI** انجام میشود (ELO مبتنی بر ترجیح انسانی، همان ایدهای که پشت
چتبات آرِنای LMArena قرار دارد). سپس ارائهدهندگان بر اساس قدرت **بهترین مدل رایگان** خود رتبهبندی میشوند.

این رتبهبندی از سه منبع واقعی محاسبه میشود:

1. فهرستهای ارائهدهندگان رایگان — `NOAUTH_PROVIDERS`، بهعلاوه ورودیهای `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` که با پرچم `hasFree` مشخص شدهاند
   (`src/shared/constants/providers.ts`).
2. کاتالوگ مدلهای هر ارائهدهنده از رجیستری ارائهدهندگان
   (`open-sse/config/providerRegistry.ts`).
3. امتیازهای تناسب با وظیفه (task-fit) مشتق از ELO که توسط موتور همگامسازی Arena ELO
   (`src/lib/arenaEloSync.ts`) در جدول `model_intelligence` پایگاه داده ذخیره شدهاند.

منطق پیوند (join) در فایل `src/lib/freeProviderRankings.ts` قرار دارد.

## نحوهٔ دسترسی

### صفحهٔ داشبورد

داشبورد را باز کنید و به **هزینهها ← رتبهبندی ارائهدهندگان رایگان** بروید، یا مستقیماً به مسیر زیر مراجعه کنید:

```
/dashboard/free-provider-rankings
```

این صفحه (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) موارد زیر را نمایش میدهد:

- یک **سکوی سه رتبهٔ برتر** (🥇 🥈 🥉) برای ارائهدهندگان رایگان با بالاترین رتبه.
- یک **جدول رتبهبندی** کامل با ستونهای **رتبه**، **ارائهدهنده**، **مدل برتر**،
  **امتیاز**، **میانگین امتیاز**، **مدلها** و **نوع**.
- **دکمههای فیلتر دستهبندی**: _همهٔ دستهبندیها_، _پیشفرض_، _کدنویسی_، _بازبینی_،
  _مستندسازی_، _اشکالزدایی_.

نشان **نوع** هر ارائهدهنده مشخص میکند که خدمات آن چگونه رایگان است:

| نشان     | معنی                                                    |
| -------- | ------------------------------------------------------- |
| `NOAUTH` | همیشه رایگان، بدون نیاز به اطلاعات احراز هویت           |
| `OAUTH`  | ارائهدهندهٔ OAuth با سطح رایگان (`hasFree`)             |
| `APIKEY` | ارائهدهندهٔ مبتنی بر کلید API با سطح رایگان (`hasFree`) |

امتیازها بهجای اعداد خام، بهصورت برچسبهای قابلفهم برای انسان (مانند _نخبه_، _عالی_، _بسیار خوب_،
_خوب_، _متوسط_) نمایش داده میشوند، زیرا مقدار زیربنایی نشاندهندهٔ کیفیت نسبی
رتبهبندی است، نه درصد.

### نقطهٔ پایانی API

این صفحه توسط یک نقطهٔ پایانی عمومی و فقطخواندنی
(`src/app/api/free-provider-rankings/route.ts`) پشتیبانی میشود:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

پارامترهای کوئری (اعتبارسنجیشده با Zod):

| پارامتر    | نوع  | پیشفرض    | توضیحات                                                                                                  |
| ---------- | ---- | --------- | -------------------------------------------------------------------------------------------------------- |
| `category` | رشته | (هیچکدام) | یکی از `default`، `coding`، `review`، `documentation`، `debugging`. برای رتبهبندی ترکیبی آن را حذف کنید. |
| `limit`    | عدد  | `50`      | به بازهٔ `1–100` محدود میشود.                                                                            |

ساختار پاسخ:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` مقدار اصلی Arena ELO است؛ `score` مقدار نرمالشدهٔ تناسب با وظیفه
است (در ادامه ببینید). ارائهدهندگانی که هیچ مدل امتیازدهیشدهای ندارند، از پاسخ حذف میشوند.

## نحوهٔ کارکرد امتیازها

### منبع: جدول امتیازات Arena AI

موتور همگامسازی Arena ELO (`src/lib/arenaEloSync.ts`) دو جدول امتیازات — `text`
و `code` — را از API جدول امتیازات Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) دریافت میکند. وقتی آن API هیچ
جدول قابل استفادهای برنگرداند، موتور به دیتاست رسمی `lmarena-ai/leaderboard-dataset` روی
datasets-server در Hugging Face بازمیگردد (`src/lib/arenaEloHfSource.ts`، با مجوز CC-BY-4.0؛ `overall` → `text`،
`coding` → `code`)؛ و `GET /api/intelligence/sync` مقادیر `activeSource`، `lastError` و
`lastFailedAt` را گزارش میدهد. هر ورودیِ جدول امتیازات
شامل نام مدل، فروشنده (vendor)، امتیاز `score` بر اساس ELO، بازهٔ اطمینان و تعداد آرا است.

دستههای جدول امتیازات به دستههای وظایف OmniRoute نگاشت میشوند:

| جدول امتیازات Arena | دستههای وظایف OmniRoute                           |
| ------------------- | ------------------------------------------------- |
| `text`              | `default`, `review`, `documentation`, `debugging` |
| `code`              | `coding`                                          |

### نرمالسازی (امتیاز تناسب با وظیفه)

امتیازهای خام ELO بهصورت جداگانه برای هر جدول امتیازات به یک **مقدار تناسب با وظیفه در بازهٔ `[0.4, 0.98]`** نرمال میشوند:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

این امتیاز هرگز به `0` یا `1` نمیرسد تا فضای کافی برای بازنویسیهای کاربر باقی بماند. این همان
فیلد `score` است که در پاسخ API میبینید و همچنین برچسبی است که روی داشبورد نمایش داده میشود.

### اطمینان (Confidence)

هر ورودی بر اساس تعداد آرا در Arena یک سطح اطمینان دریافت میکند:

| اطمینان  | آرا     |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### ذخیرهسازی و تازگی دادهها

ورودیهای نرمالشده در جدول `model_intelligence` در پایگاه داده با
`source = "arena_elo"` نوشته میشوند (`src/lib/db/modelIntelligence.ts`). ورودیها **پس از
7 روز منقضی میشوند**، بنابراین ارائهدهندهای که همگامسازی را متوقف کند، در نهایت حذف میشود بهجای اینکه
دادههای کهنه ارائه دهد.

همگامسازی **بهصورت پیشفرض فعال** است:

- یک بار هنگام راهاندازی سرور و سپس با یک تایمر دورهای اجرا میشود
  (`src/lib/arenaEloSync.ts`، که از `src/instrumentation-node.ts` متصل شده است).
- **غیرمسدودکننده است و هرگز باعث توقف نمیشود** — اگر دریافت از منبع بالادستی با شکست مواجه شود، OmniRoute به
  کار خود ادامه میدهد و رتبهبندیها صرفاً آخرین دادههای معتبر را نشان میدهند (یا یک حالت خالی).

دو متغیر محیطی آن را کنترل میکنند (مستندسازی شده در
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| متغیر                     | مقدار پیشفرض  | هدف                                                     |
| ------------------------- | ------------- | ------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | برای انصراف از همگامسازی خروجی، روی `false` تنظیم کنید. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | فاصلهٔ زمانی همگامسازی، به ثانیه.                       |

### همگامسازی دستی / وضعیت / پاکسازی

برای اپراتورها، یک endpoint مدیریتی احراز هویتشده کنترل دستی را فراهم میکند
(`src/app/api/intelligence/sync/route.ts` — نیازمند احراز هویت مدیریتی):

```
GET    /api/intelligence/sync          # وضعیت فعلی همگامسازی (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # راهاندازی همگامسازی دستی؛ بدنه: { "dryRun": true } برای پیشنمایش بدون نوشتن
DELETE /api/intelligence/sync          # پاک کردن همهٔ ورودیهای همگامسازیشدهٔ arena_elo
```

اگر صفحهٔ رتبهبندیها خالی باشد، یک `POST /api/intelligence/sync` دستی (یا صرفاً
راهاندازی مجدد سرور) آن را دوباره پر میکند.

### تطبیق مدلها با جدول امتیازات

شناسههای مدل در رجیستری و نامهای مدل در Arena همیشه دقیقاً مطابقت ندارند. رتبهبندی از
تطبیق انعطافپذیر استفاده میکند (`findMatchingIntelligence` در `src/lib/freeProviderRankings.ts`):

1. تطبیق دقیق روی شناسهٔ مدل نرمالشده.
2. تطبیق پس از حذف پسوند نسخهٔ انتهایی (مثلاً `kimi-k2.6` → `kimi-k2`).
3. تطبیق پیشوندی (نام مدل در جدول امتیازات پیشوند شناسهٔ رجیستری باشد).

در سمت همگامسازی، پیشوندهای شناختهشدهٔ فروشنده (`anthropic/`, `openai/`, `google/`, …)
حذف میشوند و یک نگاشت نام مستعار کوچک، نامهای کانونیکال را به واریانتهایی که OmniRoute
بهصورت داخلی استفاده میکند، گسترش میدهد تا مدلها تحت هر نامی قابل یافتن بمانند.

### نحوهٔ رتبهبندی یک ارائهدهنده

برای هر ارائهدهندهٔ رایگان، موتور به همهٔ مدلهای موجود در کاتالوگ آن امتیاز میدهد، سپس:

- **Top Model** = بالاترین امتیاز مدل در آن ارائهدهنده.
- **Avg Score** = میانگین امتیاز در میان همهٔ مدلهای امتیازدهیشدهٔ آن ارائهدهنده.
- **Models** = تعداد مدلهای آن ارائهدهنده که امتیاز Arena داشتند.

ارائهدهندگان ابتدا بر اساس **امتیاز بالاترین مدل** و سپس بر اساس امتیاز میانگین مرتب میشوند. این روش
به ارائهدهندهای که حداقل یک مدل رایگان قوی ارائه دهد، پاداش میدهد.

## استفاده از آن برای انتخاب ارائهدهندگان رایگان

1. **دستهبندی مناسب را انتخاب کنید.** برای بارهای کاری عاملمحور/کدنویسی از فیلتر **Coding** استفاده کنید، یا
   برای گفتوگوی عمومی آن را روی **All Categories** / **Default** بگذارید. رتبه یک ارائهدهنده یکسان ممکن است
   در دستهبندیهای مختلف متفاوت باشد، زیرا مدل برتر آن در هر تابلوی امتیازات متفاوت است.
2. **برای راهاندازیهای تکمرحلهای، رتبههای برتر را ترجیح دهید.** اگر فقط میخواهید یک یا دو ارائهدهنده رایگان را
   متصل کنید، از ارائهدهندگان دارای بالاترین رتبه در دستهبندی خود شروع کنید.
3. **نشان Type را بررسی کنید.** ارائهدهندگان `NOAUTH` سریعترین گزینه برای اتصال هستند (بدون
   نیاز به اطلاعات احراز هویت). سطوح رایگان `OAUTH` / `APIKEY` به یک ثبتنام سریع نیاز دارند، اما اغلب
   مدلهای قدرتمندتری ارائه میکنند. برای مراحل اتصال، به [راهنمای سطوح رایگان](../getting-started/FREE-TIERS-GUIDE.md) مراجعه کنید.
4. **چندین ارائهدهنده را متصل کنید و اجازه دهید Auto-Combo تصمیم بگیرد.** همان دادههای Arena ELO که
   این صفحه را تغذیه میکنند، در **عامل تناسب با وظیفه** موتور امتیازدهی Auto-Combo نیز به کار میروند
   (`open-sse/services/autoCombo/taskFitness.ts`، ترتیب اولویت
   `user_override → arena_elo → models_dev_tier → static table`). بنابراین، پس از اتصال
   برترین ارائهدهندگان رایگان، مسیریابی با `model: "auto"` (برای مثال، `auto/coding`) در هر درخواست
   بهطور خودکار مدلهای رایگان باکیفیتتر را ترجیح میدهد. برای مشاهده امتیازدهی کامل ۱۶ عاملی، به
   [Auto-Combo](../routing/AUTO-COMBO.md) مراجعه کنید.

## مستندات مرتبط

- [راهنمای سطوح رایگان](../getting-started/FREE-TIERS-GUIDE.md) — نحوه اتصال ارائهدهندگان رایگان،
  بدون نیاز به کارت اعتباری.
- [فهرست سطوح رایگان](../reference/FREE_TIERS.md) — فهرست کامل ارائهدهندگان رایگان
  و محدودیتهای آنها.
- [Auto-Combo](../routing/AUTO-COMBO.md) — موتور مسیریابی ۱۶ عاملی که از همان
  دادههای تناسب با وظیفه Arena ELO استفاده میکند.
- [متغیرهای محیطی](../reference/ENVIRONMENT.md) — مرجع `ARENA_ELO_SYNC_ENABLED` /
  `ARENA_ELO_SYNC_INTERVAL`.
