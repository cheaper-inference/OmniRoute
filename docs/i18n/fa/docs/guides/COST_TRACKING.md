OmniRoute چگونه هزینهٔ هر درخواست را تخمین میزند، ثبت میکند و گزارش میدهد — و چرا عدد
داشبورد یک **ردیاب صرفهجویی** است، نه یک صورتحساب.

همچنین ببینید: [راهنمای کاربر](./USER_GUIDE.md) · [گالری قابلیتها](./FEATURES.md)

## چیست (و چه چیزی نیست)

OmniRoute با ضرب تعداد توکنها در نرخهای قیمتگذاری مدل، برای هر تکمیل یک هزینهٔ دلاری
بهازای هر درخواست تعیین میکند. این اعداد مبنای داشبورد **هزینهها**، رابط خط فرمان
`omniroute cost` / `omniroute usage`، خروجیهای CSV/JSON و بودجههای هر کلید API هستند.

> **«هزینه» در داشبورد یک ردیاب صرفهجویی است، نه یک صورتحساب.** OmniRoute هرگز از شما
> هزینهای دریافت نمیکند — بلکه درخواستهایتان را به ارائهدهندگانی هدایت میکند که از قبل
> متصل کردهاید (اشتراکهای خودتان، سطوح رایگان و کلیدهای API). اگر «هزینهٔ کل ۲۹۰ دلار»
> کاملاً از مدلهای رایگان ناشی شده باشد، یعنی تقریباً **۲۹۰ دلار است که به یک API پولی
> پرداخت _نکردهاید_**. این رقم، _تخمینی_ از هزینهای است که همان ترافیک بر اساس قیمتهای
> فهرست استاندارد میداشت؛ بنابراین میتوانید ببینید مصرفتان در کجا متمرکز است و هدایت
> درخواستها به ارائهدهندگان ارزانتر/رایگان چقدر برایتان صرفهجویی ایجاد میکند.

این توضیح مستقیماً در [README](../../README.md) پروژه نیز آمده است («هزینهٔ داشبورد یک
ردیاب صرفهجویی است، نه یک صورتحساب»).

از آنجا که این عدد تخمینی است:

- به جدول قیمتگذاریای وابسته است که OmniRoute برای هر مدل در اختیار دارد. مدلی که ورودی
  قیمتگذاری نداشته باشد، هزینهٔ `0` ایجاد میکند (در مرورگر بهصورت ردیف «قدیمی / رایگان»
  نمایش داده میشود).
- ترافیک سطح رایگان و اشتراکی نیز همچنان یک هزینهٔ _تخمینی_ انباشته میکند — این همان
  مبلغی است که صرفهجویی میکنید، نه مبلغی که بدهکار هستید.

## نحوه برآورد هزینه ها

### منبع قیمت گذاری

هزینه ها از جدول قیمت گذاری ادغام شده در [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) به ترتیب اولویت به دست می آیند (**اول بالاترین** ):

1. **کاربر لغو می شود** قیمت های — در داشبورد یا از طریق `PATCH /api/pricing` (فضای نام `pricing` ) تنظیم شده است.
2. **همگام سازی models.dev** قیمت گذاری — از `https://models.dev/api.json` (فضای نام `models_dev_pricing` ) واکشی شده است.
3. **همگام سازی LiteLLM** قیمت — از `model_prices_and_context_window.json` عمومی LiteLLM(فضای نام `pricing_synced` ) واکشی شده است.
4. **پیش فرض هاردکد شده** نرخ — در [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) ارسال می شود.

برای همان provider/model، مقادیر لایههای با اولویت بالاتر، فیلدهای منطبق را در لایههای پایینتر بازنویسی میکنند. فیلدهای غایب از لایه بالایی همچنان می توانند از لایه پایین تر بیایند. حتی زمانی که هر دو کار همگامسازی مستقل به طور همزمان اجرا میشوند، این سفارش ثابت میشود. `GET /api/pricing?includeSources=1` `pricing` و `sourceMap` را برمیگرداند، که برچسبهای هر مدل (`user`، `modelsDev`، `litellm`، `default`) لایه با بالاترین اولویت حاوی آن مدل را شناسایی میکنند.

**همگام سازی LiteLLM** انتخاب شده است، به طور پیش فرض غیرفعال است. متغیرهای محیطی آن (به [`.env.example`](../../.env.example) مراجعه کنید) عبارتند از:

| Env var                 | پیش فرض   | هدف                                                                             |
| ----------------------- | --------- | ------------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | همگامسازی قیمت پسزمینه LiteLLM را فعال کنید.                                    |
| `PRICING_SYNC_INTERVAL` | `86400`   | فاصله همگام سازی در ثانیه (روزانه).                                             |
| `PRICING_SYNC_SOURCES`  | `litellm` | انتخاب منبع فقط برای این همگام سازی. در حال حاضر فقط `litellm` پشتیبانی می شود. |

**همگام سازی models.dev** جدا از همگام سازی LiteLLM است و به طور پیش فرض نیز غیرفعال است. آن را در تنظیمات (models.dev sync) فعال کنید یا از این متغیرها استفاده کنید:

| Env var                    | پیش فرض        | هدف                                                                                                                        |
| -------------------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(تنظیم نشده)_ | Unset از کلید تنظیمات پیروی می کند. `1/true/on/yes` فعال و `0/false/off/no` خاموش می شود (حتی اگر تنظیمات آن را فعال کند). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`        | فاصله همگام سازی پیش فرض models.dev بر حسب ثانیه (روزانه).                                                                 |

`PRICING_SYNC_SOURCES` انجام می دهد **نه** فعال کردن models.dev. فقط همگام سازی LiteLLM را کنترل می کند. حذف نادیده گرفتن کاربر، فضای نام همگامسازی شده را پاک نمیکند. لایه قیمت گذاری موجود بعدی موثر می شود. برای یک مدل بدون قیمت، قبل از اضافه کردن یک لغو دستی، تنظیمات همگامسازی و `sourceMap` را بررسی کنید.

### فرمول هزینه

هزینه به ازای هر درخواست از تعداد توکن ها و نرخ های هر میلیون توکن در [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`) محاسبه می شود:

- **توکن های ورودی** (منهای خواندن کش و توکن های ایجاد حافظه پنهان) نرخ × `input`.
- **نشانههای کشخوان** نرخ × `cached` (به نرخ ورودی برمی گردد).
- **توکن های ایجاد حافظه پنهان** نرخ × `cache_creation` (به نرخ ورودی برمی گردد).
- **توکن های خروجی** نرخ × `output`.
- **نشانه های استدلال** نرخ × `reasoning` (به نرخ خروجی باز می گردد).

همه نرخ ها به صورت USD در هر 1000000 توکن تفسیر می شوند. یک ردیف خدمات "سریع"/"اولویت" یا "فلکس" Codex یک ضریب هزینه (`getCodexFastCostMultiplier`) اعمال میکند —**پس انداز انعطاف پذیر** در داشبورد

نام مدل ها ابتدا نرمال می شوند (پیوندهای مسیر ارائه دهنده مانند `openai/` یا `accounts/fireworks/models/` حذف می شوند) بنابراین ردیف های تاریخی همچنان با قیمت مطابقت دارند.

### نحوه ثبت هزینه ها

- هزینه هر درخواست در صورت تکمیل درخواست محاسبه می شود. مصرف سهمیه مشترک در تیک حلقه رویداد بعدی از طریق [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) برنامه ریزی شده است.
- خرج کردن کلید API به صورت دستهای توسط [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (فاصله شستشوی پیشفرض 60 ثانیه، بافر 1000 ورودی) بافر و پاک میشود. قابل تنظیم از طریق:

  | Env var                             | پیش فرض | هدف                                    |
  | ----------------------------------- | ------- | -------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | فاصله فلاش به میلی ثانیه.              |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | حداکثر ورودی های بافر شده قبل از فلاش. |

هزینهها هزینههای دقیق گزارششده توسط ارائهدهنده (`provider_cost_usd`)، سپس یک عکس فوری درخواستی با قیمت کاتالوگ (`calculated_cost_usd`) و سپس قیمتگذاری مجدد رمز از کاتالوگ فعلی را ترجیح میدهند. هزینه های ذخیره شده مجدداً از طریق تعداد توکن آنها شارژ نمی شود. زمانی که قیمت کاتالوگ آنها تغییر می کند، ردیف های فقط توکن قدیمی همچنان تغییر می کنند.

### OCR و تعبیهها

- درخواستهای موفق `/v1/ocr` از `usage_info.pages_processed` بالادست استفاده میکنند، نه از محدوده صفحه درخواستی یا تعداد اشیاء صفحه برگشتی. تخمین صفحات × `ocr_cost_per_page` ( USD/page مطلق،**نه** USD/million).
- درخواستهای دارای حاشیهنویسی سند یا جعبه مرزی به تعرفه جداگانه `ocr_cost_per_annotated_page` نیاز دارند. بدون آن، هزینه ناشناخته باقی می ماند. تعرفه معمولی OCR بی سر و صدا جایگزین نمی شود.
- همگام سازی LiteLLM ، میدان `annotation_cost_per_page` بالادست خود را به `ocr_cost_per_annotated_page` نگاشت می کند، مقدار مطلق USD/page و ورودی های فقط حاشیه نویسی، از جمله صفر صریح را حفظ می کند. یک زمینه متعارف ارائه شده اولویت دارد. مقادیر نامعتبر نادیده گرفته می شوند. نادیده گرفتن قیمت گذاری کاربر اولویت عادی خود را حفظ می کند. [کلیدهای قیمت گذاری LiteLLMOCR را](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) ببینید.
- استفاده از OCR تعداد صفحات، قیمت واحد، هزینه محاسبهشده USD ، کلید API و اتصال انتخابشده را ذخیره میکند. صفحات هرگز به عنوان نشانه نمایش داده نمی شوند. گزارش تماس حاوی فراداده صورتحساب است، نه سند URLs، بایت PDF یا متن استخراج شده.
- درخواستهای موفق `/v1/embeddings` یک ردیف استفاده را در هر دسته فیزیکی ثبت میکنند، از جمله دستههای جداگانه تکمیل شده در همان میلیثانیه. هزینههای گزارششده توسط ارائهدهنده بر تخمینهای رمزی اولویت دارند. بسته بندی های ترکیبی شارژی اضافه نمی کنند.
- تاریخچه استفاده، تجزیه و تحلیل هزینهها، پنجرههای provider/account ، محدودیتهای هزینههای کلید API، دفتر کل درخواست-هزینه و مجموعههای استفاده روزانه شامل این هزینهها میشوند. کلیدهای No-log حسابداری عددی را بدون حفظ متن منبع حفظ می کنند.
- استفاده از دست رفته یا تعرفه ها هستند **ناشناخته** رایگان نیست: هدر پاسخ-هزینه حذف شده است و خط مشی استفاده بدون قیمت موجود برای کلیدهای محدود API اعمال می شود. نرخهای صفر پیکربندی شده صریحاً در استفاده با هزینه صفر معتبر باقی میمانند.

این فقط حسابداری آینده است. فراخوانهای قدیمی OCR/embedding که هرگز سابقه استفاده را ننوشتند، نمیتوانند از این مهاجرت بازسازی شوند. برآوردهای کاتالوگ تخمین های USD هستند، نه یک فاکتور، و شامل تبدیل ارز، مالیات یا تخفیف نمی شوند.

### گفتار و تصاویر

- تلاشهای موفق `/v1/audio/transcriptions`، `/v1/audio/speech` و تولید تصویر، حسابداری عددی را به اشتراک میگذارند. تماسهای مستقیم و ترکیبی کلید API تماسگیرنده و اتصال انتخابشده را حمل میکنند. یک بسته بندی ترکیبی هرگز یک بدهی دوم اضافه نمی کند.
- USD گزارششده توسط ارائهدهنده بر برآورد کاتالوگ، از جمله هزینه صفر صریح، برنده است. OpenRouterJSON `cost_usd` `usage.cost` شده است. در غیر این صورت، نشانههای اندازهگیری شده از قیمتهای رمز استفاده میکنند، ثانیههای رونویسی از قیمتهای هر ثانیه استفاده میکنند، ورودی گفتار از تعداد کاراکترهای یونیکد استفاده میکند، و تصاویر با قیمت ثابت از عدد واقعی بازگردانده شده استفاده میکنند، نه `n` درخواستی.
- باینری OpenRouter TTS بدنه استفاده از JSON ندارد. پس از تکمیل صدا یا لغو تماسگیرنده، OmniRoute از نسل ID خود درخواست میکند **همان** منشا OpenRouter پیکربندی شده است. درخواست EU هرگز به منشاء جهانی باز نمی گردد. این یک جستجوی محدود و فقط خواندنی است. سنتز برای حسابداری دوباره امتحان نمی شود. سوابق صورتحساب میتوانند پس از اتمام صدا ظاهر شوند: تلاشهای مجدد جستجو در پسزمینه تا حدود 52 ثانیه اجرا میشوند، از جمله مهلتهای شبکه.
- در طی آن جستجو، پاسخ صوتی دارای `X-OmniRoute-Cost-Status: pending` است و سربرگ هزینه پاسخ ندارد. شارژ نهایی آن در تاریخچه استفاده، تجزیه و تحلیل و دفتر کل کلید پس از تطبیق ظاهر می شود. اگر فراداده در دسترس نباشد، از یک عکس فوری تعرفه پیکربندی شده استفاده می شود. در غیر این صورت هزینه ناشناخته می ماند.
- ثانیه ها، کاراکترها و تعداد تصاویر دارای فیلدهای واحد صورتحساب جداگانه هستند، هرگز تعداد توکن های جعلی ندارند. حسابداری فقط استفاده عددی را حفظ می کند، نه متن گفتاری، رونوشت ها یا بایت های تصویر. معافیتهای تصویر بدون قیمت موجود بدون تغییر هستند: تعرفه تصویری که واقعاً مفقود شده است، به تازگی کلید محدودی را قفل نمیکند و پاسخ بهجای اعلام رایگان تماس، هدر هزینه را حذف میکند. شکست فروشگاه قیمتگذاری همچنان شواهد استفاده را برای اجرای شکست در بسته نگه میدارد.

هیچ هزینه تاریخی speech/image اختراع یا پر نشده است. صورتحساب ارائهدهنده مرجع برای فاکتورها و تماسهایی است که هزینه آنها گزارش نشده است.

## داشبورد: صفحه هزینهها

صفحه **هزینهها** در `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`) قرار دارد.
نمای اصلی آن، زبانه **نمای کلی هزینهها** است
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`)
که همهچیز را از `GET /api/usage/analytics` بارگذاری میکند.

مواردی که نمایش میدهد:

- **کاشیهای مخارج** — مخارج تخمینی برای _امروز (1d)_، _7d_، _30d_ و بازه انتخابشده.
  انتخابگر بازه: `7d`، `30d`، `90d`، `all`.
- **معیارهای اصلی** — درخواستهای بازه، ارائهدهندگان فعال، مدلهای فعال و میانگین
  هزینه بهازای هر درخواست.
- **کاوشگر هزینه** — جدولی قابل مرتبسازی/فیلتر که بر اساس **ارائهدهنده**، **مدل**،
  **کلید API**، **حساب** یا **سطح سرویس** گروهبندی میشود و هزینه، درخواستها، توکنها،
  میانگین هزینه/درخواست و درصد سهم از کل را نشان میدهد.
- **مصرف توکن** — تعداد کل توکنها / توکنهای ورودی / توکنهای خروجی و نسبت ورودی به خروجی.
- **کارایی مسیریابی** — تعداد بازگشتها، نرخ بازگشت و پوشش مدل درخواستشده.
- **پیشبینی ماهانه** — مخارج پایان ماه را بر اساس میانگین روزانه اخیر پیشبینی میکند.
- **مقایسه دورهای** — درصد تغییر بین نیمه اول و دوم بازه.
- **نمودارها** — روند روزانه هزینه، سهم ارائهدهندگان (دایرهای)، ارائهدهندگان برتر،
  مدلهای برتر، هزینه بر اساس کلید API، هزینه بر اساس حساب، الگوی مصرف هفتگی و نقشه حرارتی فعالیت.
- **برونبری** — بازه فعلی را بهصورت **CSV** یا **JSON** دانلود میکند (دکمهها زمانی
  ظاهر میشوند که داده هزینه غیرصفر وجود داشته باشد).

وقتی ترافیک قیمتگذاریشدهای وجود نداشته باشد، ردیفها بهجای `$0` با برچسب
"قدیمی / رایگان" نمایش داده میشوند که بازتابدهنده مدل ردیاب صرفهجویی است.

### زیربرگههای مرتبط با هزینهها

بخش هزینهها همچنین میزبان موارد زیر است (همه در مسیر `/dashboard/costs/`):

- **قیمتگذاری** (`/dashboard/costs/pricing`) — مشاهده و بازنویسی قیمتهای هر مدل
  (زبانه مشترک قیمتگذاری را رندر میکند).
- **بودجه** (`/dashboard/costs/budget`) — تعیین محدودیت مخارج برای هر دامنه
  (زبانه مشترک بودجه را رندر میکند).
- **اشتراک سهمیه** (`/dashboard/costs/quota-share`) — نماهای مخازن سهمیه مشترک و نرخ مصرف.

## نقاط پایانی API

همه این موارد به احراز هویت مدیریتی نیاز دارند (loopback/JWT، از طریق
`requireManagementAuth`)، مگر اینکه خلاف آن ذکر شده باشد.

### تحلیل مصرف و هزینه

| متد   | نقطه پایانی              | هدف                                                                                                                                                  |
| ----- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | تحلیل کامل هزینه/مصرف: خلاصه، روند روزانه، بر اساس ارائهدهنده/مدل/کلید API/حساب/سطح. کوئری: `range`، `startDate`، `endDate`، `apiKeyIds`، `presets`. |
| `GET` | `/api/usage/utilization` | میزان استفاده از سهمیه هر ارائهدهنده در گذر زمان. کوئری: `range` ‏(`1h`/`24h`/`7d`/`30d`)، `provider`.                                               |
| `GET` | `/api/usage/history`     | ردیفهای خام تاریخچه مصرف.                                                                                                                            |
| `GET` | `/api/usage/call-logs`   | گزارش فراخوانی هر درخواست (مدل، توکنها، هزینه، تأخیر، وضعیت).                                                                                        |
| `GET` | `/api/usage/quota`       | وضعیت سهمیه ارائهدهنده.                                                                                                                              |
| `GET` | `/api/usage/proxy-logs`  | گزارش درخواستهای پراکسی.                                                                                                                             |

### بودجهها

| متد    | نقطه پایانی              | هدف                                                                                  |
| ------ | ------------------------ | ------------------------------------------------------------------------------------ |
| `GET`  | `/api/usage/budget`      | خلاصه هزینه + بررسی بودجه برای یک کلید API (پارامتر کوئری `apiKeyId` الزامی است).    |
| `POST` | `/api/usage/budget`      | تنظیم محدودیتهای روزانه/هفتگی/ماهانه به دلار آمریکا + آستانه هشدار برای یک کلید API. |
| `GET`  | `/api/usage/budget/bulk` | خلاصههای بودجه بهصورت انبوه در میان کلیدهای API.                                     |

> API بودجه برای هر **کلید API** (`apiKeyId`) دامنهبندی میشود. محدودیتهای بازگرداندهشده توسط
> `GET /api/usage/budget` شامل `dailyLimitUsd`، `weeklyLimitUsd`، `monthlyLimitUsd`،
> یک `warningThreshold` و مجموعهای جاری (`totalCostToday`، `totalCostMonth`، …) هستند.

### قیمتگذاری

| متد      | نقطه پایانی             | هدف                                                                                                                                                       |
| -------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | قیمت ادغام‌شدهٔ چهار لایه (کاربر، models.dev، LiteLLM، پیش‌فرض‌ها). `?includeSources=1` اشیای `pricing` + `sourceMap` را برمی‌گرداند.                     |
| `PATCH`  | `/api/pricing`          | بازنویسی قیمتگذاری برای `{ provider: { model: { input, output, cached, … } } }`.                                                                          |
| `DELETE` | `/api/pricing`          | بازنویسی‌های قیمت کاربر را حذف می‌کند (با امکان محدودکردن به `?provider=&model=`)؛ نرخ‌های همگام‌شده یا پیش‌فرض‌های داخلی به‌عنوان جایگزین باقی می‌مانند. |
| `GET`    | `/api/pricing/defaults` | نمایش نرخهای جایگزین پیشفرض بهازای هر 1M.                                                                                                                 |
| `GET`    | `/api/pricing/models`   | قیمتگذاری کلیدگذاریشده بر اساس مدل.                                                                                                                       |
| `POST`   | `/api/pricing/sync`     | راهاندازی همگامسازی دستی از منابع خارجی (LiteLLM).                                                                                                        |
| `GET`    | `/api/pricing/sync`     | وضعیت فعلی همگامسازی.                                                                                                                                     |
| `DELETE` | `/api/pricing/sync`     | فقط قیمت‌های همگام‌شدهٔ LiteLLM را پاک می‌کند (`pricing_synced`)؛ داده‌های models.dev جدا هستند.                                                          |

### سایر نقاط پایانی مرتبط با هزینه

| متد   | نقطه پایانی                   | هدف                                                                    |
| ----- | ----------------------------- | ---------------------------------------------------------------------- |
| `GET` | `/api/free-tier/summary`      | مجموع توکنهای مدل رایگان، میزان مصرف این ماه و سهمیه رایگان باقیمانده. |
| `GET` | `/api/quota/pools/[id]/usage` | میزان مصرف یک مخزن سهمیه مشترک.                                        |

## CLI

رابط خط فرمان OmniRoute فرمانهای هزینه، مصرف و قیمتگذاری را ارائه میکند (ثبتشده در
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

گزارش هزینه تجمیعشده از `/api/usage/analytics`.

```bash
omniroute cost                          # ۳۰ روز گذشته، گروهبندیشده بر اساس ارائهدهنده
omniroute cost --period 7d              # ۷ روز گذشته
omniroute cost --group-by model         # گروهبندی بر اساس provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ستونها: گروه، درخواستها، توکنهای ورودی/خروجی، هزینه (USD) و درصد از کل. یک خط جمع کل
در انتها نمایش داده میشود (با `--quiet` یا `--output json` نمایش داده نمیشود).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # خلاصه هزینه بهازای هر ارائهدهنده
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# بودجهها
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` دادهها را از `GET /api/pricing/defaults` میخواند. برای ویرایش قیمت
> مدلهای منفرد، بهجای آن از صفحه **قیمتگذاری** در داشبورد یا `PATCH /api/pricing` استفاده کنید.

## عیبیابی

- **همه هزینهها $0 / «قدیمی / رایگان» نمایش داده میشوند.** مدلهای در حال استفاده ورودی قیمتگذاری ندارند.
  همگامسازی خارجی را فعال کنید (`PRICING_SYNC_ENABLED=true`) و `omniroute pricing sync` را اجرا کنید، یا
  قیمتها را بهصورت دستی از طریق صفحه قیمتگذاری / `PATCH /api/pricing` تنظیم کنید.
- **قیمت یک مدل قدیمی اشتباه است.** قیمت را اصلاح کنید (با لغو مقدار یا همگامسازی مجدد) — هزینه
  در هر بار خواندن تحلیلها بر اساس تعداد توکنها دوباره محاسبه میشود، بنابراین برآوردها بهصورت عطفبهماسبق بهروزرسانی میشوند.
- **میزان هزینهکرد از زمان واقعی عقبتر است.** هزینهکرد هر کلید بهصورت دستهای ثبت میشود؛ اگر به اعداد
  بهروزتری نیاز دارید، مقدار `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` را کاهش دهید.
