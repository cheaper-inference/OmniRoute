## 🎯 موارد استفاده

### مورد ۱: «اشتراک Claude Pro دارم»

**مشکل:** سهمیه بدون استفاده منقضی میشود و هنگام کدنویسی سنگین با محدودیت نرخ مواجه میشوم

```
ترکیب: "maximize-claude"
  1. cc/claude-opus-4-7        (استفاده کامل از اشتراک)
  2. glm/glm-4.7               (پشتیبان ارزان هنگام اتمام سهمیه)
  3. if/qwen3.8-max-preview       (گزینه جایگزین رایگان برای مواقع اضطراری)

هزینه ماهانه: $20 (اشتراک) + حدود $5 (پشتیبان) = در مجموع $25
در مقایسه با $20 + برخورد با محدودیتها = کلافگی
```

### مورد ۲: «هزینه صفر میخواهم»

**مشکل:** توان پرداخت هزینه اشتراکها را ندارم و به هوش مصنوعی قابلاعتماد برای کدنویسی نیاز دارم

```
ترکیب: "zero-cost"
  1. if/kimi-k2.7-code          (دسترسی رایگان فهرستشده؛ ممکن است محدودیت نرخ اعمال شود)
  2. kr/qwen3-coder-next        (گزینه جایگزین رایگان Kiro)

هزینه ماهانه: $0
کیفیت: مدل، محدودیتها، حریم خصوصی و SLA را برای حجم کاری خود بررسی کنید
```

### مورد ۳: «به کدنویسی شبانهروزی و بدون وقفه نیاز دارم»

**مشکل:** مهلتهای تحویل دارم و نمیتوانم قطعی سرویس را تحمل کنم

```
ترکیب: "always-on"
  1. cc/claude-opus-4-7        (بهترین کیفیت)
  2. cx/gpt-5.5                (اشتراک دوم)
  3. glm/glm-4.7               (ارزان، بازنشانی روزانه)
  4. minimax/MiniMax-M2.1      (ارزانترین، بازنشانی ۵ ساعته)
  5. if/deepseek-v4-flash       (دسترسی رایگان فهرستشده؛ ممکن است محدودیت نرخ اعمال شود)

نتیجه: ۵ لایه جایگزین، تابآوری را افزایش میدهند؛ در دسترس بودن سرویسهای بالادستی تضمینشده نیست
هزینه ماهانه: $20-200 (اشتراکها) + $10-20 (پشتیبان)
```

### مورد ۴: «در OpenClaw هوش مصنوعی رایگان میخواهم»

**مشکل:** به یک دستیار هوش مصنوعی در برنامههای پیامرسان نیاز دارم که کاملاً رایگان باشد

```
ترکیب: "openclaw-free"
  1. if/qwen3.8-max-preview     (دسترسی رایگان فهرستشده؛ ممکن است محدودیت نرخ اعمال شود)
  2. if/deepseek-v4-flash       (دسترسی رایگان فهرستشده؛ ممکن است محدودیت نرخ اعمال شود)
  3. if/kimi-k2.7-code          (دسترسی رایگان فهرستشده؛ ممکن است محدودیت نرخ اعمال شود)

هزینه ماهانه: $0
دسترسی از طریق: WhatsApp، Telegram، Slack، Discord، iMessage، Signal...
```

## 📖 راهاندازی ارائهدهنده

برای افزودن انبوه اتصالهای کلید API از یک فایل CSV یا JSON، از مسیر **داشبورد ← ارائهدهندگان ← درونریزی از فایل** استفاده کنید. ستونها موقعیتی هستند (`provider,name,apiKey,baseUrl,priority`)؛ مقدار `provider` باید از قبل بهعنوان یک ارائهدهنده مدیریتشده یا یک گره سازگار وجود داشته باشد. به [درونریزی ارائهدهندگان از فایل CSV یا JSON](../providers/CSV-IMPORT.md) مراجعه کنید.

### 🔐 ارائهدهندگان اشتراکی

#### Claude Code (Pro/Max)

```bash
داشبورد ← ارائهدهندگان ← اتصال Claude Code
← ورود با OAuth ← نوسازی خودکار توکن
← پیگیری سهمیه ۵ ساعته + هفتگی

مدلها:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**نکته حرفهای:** برای وظایف پیچیده از Opus و برای سرعت از Sonnet استفاده کنید. OmniRoute سهمیه را بهازای هر مدل پیگیری میکند!

روی میزبان OmniRoute مرورگر ندارید؟ دستور `claude setup-token` را در هر جایی که Claude Code وارد حساب شده است اجرا کنید و توکن یکساله را در زبانه **Setup Token** جایگذاری کنید. به [استفاده از Claude Code با setup token](../providers/CLAUDE_CODE_SETUP_TOKEN.md) مراجعه کنید.

مسیرهای سازگار با Claude و Claude Code، میزان تلاش تفکر `max` را برای مدلهای Opus و Sonnet
حفظ میکنند. مدلهای Haiku سطح تلاش `max` را نمیپذیرند؛ بنابراین OmniRoute پیش از ارسال درخواست
به سرویس بالادستی، آن را به بودجه تفکر بالا کاهش میدهد.

#### OpenAI Codex (Plus/Pro)

```bash
داشبورد ← ارائهدهندگان ← اتصال Codex
← ورود با OAuth (درگاه 1455)
← بازنشانی ۵ ساعته + هفتگی

مدلها:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
داشبورد ← ارائهدهندگان ← اتصال GitHub
← OAuth از طریق GitHub
← بازنشانی ماهانه (روز اول ماه)

مدلها:
  gh/gpt-5.5
  gh/gpt-5.4
```

### 💰 ارائهدهندگان ارزان

#### GLM-4.7 (بازنشانی روزانه، $0.6/1M)

1. ثبتنام کنید: [Zhipu AI](https://open.bigmodel.cn)
2. کلید API را از Coding Plan دریافت کنید
3. داشبورد ← افزودن کلید API: ارائهدهنده: `glm`، کلید API: `your-key`

**استفاده:** `glm/glm-4.7` — **نکته حرفهای:** Coding Plan با یکهفتم هزینه، ۳ برابر سهمیه ارائه میدهد! بازنشانی روزانه در ساعت ۱۰:۰۰ صبح انجام میشود.

#### MiniMax M2.1 (بازنشانی ۵ ساعته، $0.20/1M)

1. ثبتنام کنید: [MiniMax](https://www.minimax.io)
2. کلید API را دریافت کنید ← داشبورد ← افزودن کلید API

**استفاده:** `minimax/MiniMax-M2.1` — **نکته حرفهای:** ارزانترین گزینه برای زمینه طولانی (۱ میلیون توکن)!

#### Kimi K2 (ماهانه ثابت $9)

## 🚀 استقرار

### نصب سراسری npm (توصیهشده)

```bash
npm install -g omniroute

# ایجاد پوشهٔ پیکربندی
mkdir -p ~/.omniroute

# ایجاد فایل .env (به .env.example مراجعه کنید)
cp .env.example ~/.omniroute/.env

# راهاندازی سرور
omniroute
# یا با درگاه سفارشی:
omniroute --port 3000
```

CLI بهطور خودکار `.env` را از `~/.omniroute/.env` یا `./.env` بارگذاری میکند.

### حالت سینی سیستم

OmniRoute را در سینی سیستم اجرا کنید:

```bash
omniroute serve --tray
```

پس از آمادهشدن سرور و سینی سیستم، فرمان خاتمه مییابد.

سرور بدون ترمینال به کار خود ادامه میدهد.

حالت سینی سیستم از macOS، Windows و نشستهای گرافیکی Linux پشتیبانی میکند. حالت سینی سیستم داشبورد را بهطور خودکار باز نمیکند.

برای انجام اقدامات زیر از منوی سینی سیستم استفاده کنید:

- بازکردن داشبورد.
- بازکردن `/dashboard/logs`.
- تغییر راهاندازی خودکار.
- توقف OmniRoute.

از `--tray` همراه با گزینههای زیر استفاده نکنید:

- `--daemon`
- `--log`
- `--no-recovery`

این حالتها به مالکیت فرایند متفاوتی نیاز دارند.

راهاندازی در ورود بعدی به سیستم را فعال کنید:

```bash
omniroute autostart enable
```

راهاندازی خودکار در macOS، Windows و نشستهای گرافیکی Linux از حالت سینی سیستم استفاده میکند. Linux بدون رابط گرافیکی از سرویس کاربری systemd موجود استفاده میکند.

راهاندازی در هنگام ورود را غیرفعال کنید:

```bash
omniroute autostart disable
```

### حذف نصب

هنگامی که دیگر به OmniRoute نیاز ندارید، دو اسکریپت سریع برای حذف کامل ارائه میکنیم:

| فرمان                    | عملکرد                                                                                             |
| ------------------------ | -------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | برنامهٔ سیستم را حذف میکند، اما **پایگاه داده و پیکربندیهای شما** را در `~/.omniroute` نگه میدارد. |
| `npm run uninstall:full` | برنامه را حذف میکند و همچنین **تمام پیکربندیها، کلیدها و پایگاههای داده را برای همیشه پاک میکند**. |

> نکته: برای اجرای این فرمانها، به پوشهٔ پروژهٔ OmniRoute بروید (اگر آن را کلون کردهاید) و فرمانها را اجرا کنید. در غیر این صورت، اگر بهصورت سراسری نصب شده است، میتوانید بهسادگی `npm uninstall -g omniroute` را اجرا کنید.

| `JWT_SECRET`                            | `omniroute-default-secret-change-me` | کلید محرمانه امضای JWT (**در محیط عملیاتی تغییر دهید**)                                                                                  |
| `INITIAL_PASSWORD`                      | `CHANGEME`                           | رمز عبور اولین ورود                                                                                                                      |
| `DATA_DIR`                              | `~/.omniroute`                       | دایرکتوری دادهها (پایگاه داده، میزان استفاده، گزارشها)                                                                                   |
| `PORT`                                  | پیشفرض چارچوب                        | درگاه سرویس (`20128` در مثالها)                                                                                                          |

| `NEXT_PUBLIC_BASE_URL`                  | `http://localhost:20128`             | URL پایه عمومی که در داشبورد نمایش داده شده و در اختیار سرور قرار میگیرد (جایگزین `BASE_URL` قدیمی)                                      |
| `NEXT_PUBLIC_CLOUD_URL`                 | `https://omniroute.dev`              | URL پایه نقطه پایانی همگامسازی ابری (جایگزین `CLOUD_URL` قدیمی)                                                                          |
| `API_KEY_SECRET`                        | `endpoint-proxy-api-key-secret`      | کلید محرمانه HMAC برای کلیدهای API تولیدشده                                                                                              |
| `REQUIRE_API_KEY`                       | `false`                              | الزام کلید API از نوع Bearer برای `/v1/*`                                                                                                |
| `ALLOW_API_KEY_REVEAL`                  | `false`                              | اجازه به کاربران احراز هویتشده داشبورد برای نمایش مقادیر کامل کلیدهای API ذخیرهشده در صورت درخواست                                       |

| `DISABLE_SQLITE_AUTO_BACKUP`            | `false`                              | غیرفعالسازی اسنپشاتهای خودکار SQLite پیش از نوشتن/درونریزی/بازیابی؛ پشتیبانگیری دستی همچنان کار میکند                                    |

| `AUTH_COOKIE_SECURE`                    | `false`                              | اجبار ویژگی `Secure` برای کوکی احراز هویت (پشت پراکسی معکوس HTTPS)                                                                       |

| `OMNIROUTE_MEMORY_MB`                   | `512`                                | محدودیت حافظه heap در Node.js بر حسب MB                                                                                                  |
| `PROMPT_CACHE_MAX_SIZE`                 | `50`                                 | حداکثر تعداد ورودیهای کش پرامپت                                                                                                          |

## 🧩 قابلیتهای پیشرفته

### مدلهای سفارشی

هر شناسه مدلی را میتوانید بدون انتظار برای بهروزرسانی برنامه به هر ارائهدهندهای اضافه کنید:

```bash
# از طریق API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# فهرست کردن: curl http://localhost:20128/api/provider-models?provider=openai
# حذف: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

یا از داشبورد استفاده کنید: **Providers → [Provider] → Custom Models**.

نکتهها:

- ارائهدهندگان OpenRouter و ارائهدهندگان سازگار با OpenAI/Anthropic فقط از بخش **Available Models** مدیریت میشوند. افزودن دستی، وارد کردن و همگامسازی خودکار همگی در همان فهرست مدلهای موجود قرار میگیرند، بنابراین بخش جداگانهای برای مدلهای سفارشی آن ارائهدهندگان وجود ندارد.
- بخش **Custom Models** برای ارائهدهندگانی در نظر گرفته شده که قابلیت وارد کردن مدلهای موجودِ مدیریتشده را ارائه نمیدهند.

### ارائهدهندگان سفارشی سازگار با OpenAI

هر درگاهی که با API‎ای OpenAI صحبت کند (یک پراکسی خودمیزبان، vLLM، یک تجمیعکننده شخص ثالث)
میتواند بهعنوان گره ارائهدهنده مستقل خودش اضافه شود:

1. **Providers → Add OpenAI Compatible**.
2. **Name**: برچسب نمایشی برای گره.
3. **Prefix**: نام مسیریابی. کلاینتها مدلها را بهصورت `<prefix>/<model>` فراخوانی میکنند، بنابراین گرهی با
   پیشوند `mygw` مدل `mygw/gpt-4o-mini` را سرو میکند. الزامی است؛ هیچ محدودیتی روی کاراکترها وجود ندارد.
4. **API Type**: خانواده نقطه پایانی که درگاه سرو میکند (Chat Completions، Responses،
   Embeddings، صوت، تصاویر).
5. **Base URL**: ریشه API، تا و شامل `/v1` (برای مثال
   `https://gateway.example.com/v1`)، نه مسیر کامل `/chat/completions`. درگاههایی با
   مسیرهای غیراستاندارد آنها را در **Advanced Settings** تنظیم میکنند (مسیر chat، مسیر models).
6. فیلد **API Key (for Check)** فقط اتصال را آزمایش میکند. پس از ساخت گره،
   آن را باز کنید و با **Add Connection** کلیدی را که درخواستها از آن استفاده خواهند کرد ذخیره کنید.

این گره یک شناسه داخلی به شکل `openai-compatible-<apiType>-<uuid>` میگیرد؛ هرگز
لازم نیست آن را تایپ کنید، پیشوند نام عمومی است.

#### پیشوندهای رزرو شده

پیشوند نمیتواند شناسه یا نام مستعار یک ارائهدهنده داخلی باشد (برای مثال `openai`، `cf`) و نه
شناسه یک ارائهدهنده منقضیشده. واکنشگر مدل، شناسهها و نامهای مستعار داخلی را پیش از
گرههای سفارشی بررسی میکند، بنابراین گرهی که از یکی از آن پیشوندها استفاده کند هرگز ترافیکی دریافت نخواهد کرد:
`<prefix>/model` بهجای آن به ارائهدهنده داخلی میرود، یا اگر آن ارائهدهنده
منقضی شده باشد، بهصورت fail closed با شکست مواجه میشود. ساخت یا ویرایش گرهی با چنین پیشوندی با این پیام رد میشود:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

یک پیشوند متمایز انتخاب کنید (`mygw`، `acme-proxy`). اگر درخواستهای یک گره سفارشی با خطایی
مواجه شوند که نام یک ارائهدهنده داخلی یا اطلاعات احراز هویت آن را ذکر میکند، بررسی کنید که آیا پیشوند گره
رزرو شده است یا نه: گرههایی که پیش از وجود این قاعده ذخیره شدهاند همچنان باقی میمانند، اما پیشوند آنها به
ارائهدهنده داخلی مسیریابی میشود. گره را ویرایش کنید و پیشوند جدیدی به آن بدهید.

#### گزینههای درگاه بهازای هر اتصال

این کلیدها در `providerSpecificData` یک اتصال قرار میگیرند (برای مثال از طریق
`PUT /api/providers/{id}`):

- `toolNameMaxLength` (عدد صحیح، ۱–۱۰۲۴) — برای اتصالهای سازگار با قالب chat‎ای OpenAI که
  درگاه آنها نامهای طولانی ابزار را رد میکند. نامهای طولانیتر بهصورت نامهای مستعار کوتاه ارسال میشوند و در
  پاسخ بازیابی میشوند.
- `quotaEndpoint` — نقطه پایانی سهمیه/اعتبار درگاه، که برای نوار سهمیه داشبورد و
  مسیریابی آگاه از سهمیه خوانده میشود. روی اتصالهای سازگار با OpenAI و Anthropic هر دو کار میکند؛ ساختار کامل
  آن در `open-sse/services/usage/openaiCompatible.ts` مستند شده است.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### زنجیرهکردن همتاهای OmniRoute

یک درگاه OmniRoute دیگر را میتوان بهعنوان ارائهدهنده **Custom OpenAI-compatible** اضافه کرد. از
URL پایه `/v1` همتا و یک کلید API اختصاصی با کمترین دسترسی که توسط همان همتا صادر شده استفاده کنید.

برای زنجیرههای دوطرفه یا چندپرشی، نگهبان حلقه opt-in را روی هر درگاه فعال کنید:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

فقط درخواستهایی که به یک URL همتای صراحتاً allowlist شده ارسال شوند، هدر
`X-OmniRoute-Peer-Trace` را دریافت میکنند. یک درگاه، شناسه نمونه تکراری یا بودجه پرش تمامشده
را با HTTP `508 Loop Detected` رد میکند؛ ارائهدهندگان بالادستی عادی هیچ فراداده همتایی دریافت نمیکنند.

زنجیرهکردن همتایا، تکثیر پایگاهداده یا failover میزبان نیست. هر درگاه وضعیت
SQLite، کشها، شمارندههای نرخ و نشستهای مستقل خود را نگه میدارد. برای دسترسپذیری فعال/غیرفعال یا
فعال/فعال از یک پراکسی معکوس دارای health check یا failover سمت کلاینت استفاده کنید و هرگز یک پایگاهداده
SQLite را در چند نمونه در حال اجرای OmniRoute مونت نکنید.

### همگامسازی ابری

- همگامسازی ارائهدهندهها، کامبوها و تنظیمات در میان دستگاهها
- همگامسازی خودکار در پسزمینه با مهلت زمانی (timeout) و شکست سریع (fail-fast)
- در محیط production ترجیحاً از `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` سمت سرور استفاده کنید

### تونل سریع Cloudflare

- در **داشبورد (Dashboard) → نقاط پایانی (Endpoints)** برای Docker و سایر استقرارهای self-hosted در دسترس است
- یک URL موقت `https://*.trycloudflare.com` ایجاد میکند که به نقطهٔ پایانی `/v1` سازگار با OpenAI فعلی شما هدایت میشود
- نخستین فعالسازی، `cloudflared` را فقط در صورت نیاز نصب میکند؛ راهاندازیهای مجدد بعدی از همان باینری مدیریتشده استفاده میکنند
- تونلهای سریع پس از راهاندازی مجدد OmniRoute یا کانتینر بهطور خودکار بازیابی نمیشوند؛ در صورت نیاز آنها را از داشبورد دوباره فعال کنید
- نشانیهای تونل زودگذر هستند و هر بار که تونل را متوقف/راهاندازی کنید تغییر میکنند
- تونلهای سریع مدیریتشده بهطور پیشفرض از انتقال HTTP/2 استفاده میکنند تا از هشدارهای پرتکرار بافر UDP مربوط به QUIC در کانتینرهای محدود جلوگیری شود
- اگر میخواهید انتخاب انتقال مدیریتشده را نادیده بگیرید، `CLOUDFLARED_PROTOCOL=quic` یا `auto` را تنظیم کنید
- اگر ترجیح میدهید بهجای دانلود مدیریتشده از باینری از پیش نصبشدهٔ `cloudflared` استفاده کنید، `CLOUDFLARED_BIN` را تنظیم کنید
- پنلهای Cloudflare Quick Tunnel، Tailscale Funnel و ngrok Tunnel را میتوان در **تنظیمات (Settings) → ظاهر (Appearance)** نمایش داد یا پنهان کرد. پنهانکردن یک پنل، تونل در حال اجرا را متوقف نمیکند.

### هوش دروازهٔ LLM (فاز 9)

- **کش معنایی (Semantic Cache)** — پاسخهای غیراستریمی با temperature=0 را بهطور خودکار کش میکند (عبور از کش با `X-OmniRoute-No-Cache: true`)
- **ایدمپوتنسی درخواست (Request Idempotency)** — درخواستهای تکراری را در بازهٔ 5 ثانیهای از طریق هدر `Idempotency-Key` یا `X-Request-Id` حذف میکند
- **ردیابی پیشرفت (Progress Tracking)** — رویدادهای SSE اختیاری (opt-in) از نوع `event: progress` از طریق هدر `X-OmniRoute-Progress: true`

| ---------------- | ---------------------------------------------------------------------------------------------- |

### راهبردهای مسیریابی

از طریق **داشبورد → تنظیمات → مسیریابی (Routing)** پیکربندی کنید. داشبورد شش راهبرد پرکاربرد را ارائه میدهد؛ کامبوها و روتر خودکار بهطور داخلی مجموعهٔ گستردهتری را پشتیبانی میکنند.

**راهبردهای قابلمشاهده در داشبورد (مسیریابی در سطح حساب):**

| راهبرد                         | توضیح                                                                                                       |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| **Fill First**                 | از حسابها به ترتیب اولویت استفاده میکند — حساب اصلی همهٔ درخواستها را تا زمانی که در دسترس است مدیریت میکند |
| **Round Robin**                | میان همهٔ حسابها با یک محدودیت چسبندگی (sticky) قابلپیکربندی میچرخد (پیشفرض: 3 فراخوانی به ازای هر حساب)    |
| **P2C (Power of Two Choices)** | ۲ حساب تصادفی برمیدارد و به حساب سالمتر مسیریابی میکند — با آگاهی از وضعیت سلامت، بار را متعادل میکند       |
| **Random**                     | برای هر درخواست با استفاده از بر زدن Fisher-Yates یک حساب را بهطور تصادفی انتخاب میکند                      |
| **Least Used**                 | به حسابی با قدیمیترین مُهر زمانی `lastUsedAt` مسیریابی میکند و ترافیک را بهطور یکنواخت توزیع میکند          |
| **Cost Optimized**             | به حسابی با کمترین مقدار اولویت مسیریابی میکند و برای ارائهدهندگان کمهزینهتر بهینهسازی میکند                |

**راهبردهای پیشرفتهٔ کامبو و خودکار** (قابلپیکربندی برای هر کامبو یا از طریق پیشوندهای `auto/*` — مراجعه کنید به [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — ترتیب سختگیرانه، هرگز بهصورت round-robin عمل نمیکند
- `weighted` — تقسیم متناسب ترافیک بر اساس وزنهای هر مدل
- `fill-first` — مدل اول را تا رسیدن به محدودیتها تخلیه میکند
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` و `cost-optimized`
- `auto` — مبتنی بر امتیاز در میان همهٔ نامزدها
- `lkgp` (Last Known Good Provider) — به آخرین ارائهدهندهٔ موفق سنجاق میشود، سپس به قواعد بازمیگردد
- `context-optimized` — مدلی را انتخاب میکند که بزرگترین پنجرهٔ کانتکست آزاد را دارد
- `context-relay` — مدلهای کانتکستبلند را برای نوبتهای ادامهدار به هم زنجیر میکند

#### هدر نشست چسبندهٔ خارجی

برای چسبندگی نشست خارجی (برای مثال، عاملهای Claude Code/Codex پشت پراکسیهای معکوس)، ارسال کنید:

```http
X-Session-Id: your-session-key
```

OmniRoute همچنین `x_session_id` را میپذیرد و کلید نشست مؤثر را در `X-OmniRoute-Session-Id` برمیگرداند.

اگر از Nginx استفاده میکنید و هدرهایی با فرم زیرخطدار (underscore) ارسال میکنید، این را فعال کنید:

```nginx
underscores_in_headers on;
```

#### نامهای مستعار مدل با کاراکتر عام (Wildcard)

برای بازنگاشت نام مدلها، الگوهای wildcard ایجاد کنید:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

کاراکترهای عام از `*` (هر تعداد کاراکتر) و `?` (یک کاراکتر) پشتیبانی میکنند.

#### زنجیرههای جایگزین (Fallback)

زنجیرههای جایگزین سراسری تعریف کنید که روی همهٔ درخواستها اعمال میشوند:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### ترکیبهای رایج ارائهدهندگان و الگوهای مسیریابی

در ادامه الگوهایی نمونه برای ترکیب چند ارائهدهنده و مسیریابی میان آنها در OmniRoute آمده است:

#### ۱. ترکیب ایجنت کدنویسی: استدلال سطحبالا با جایگزینی کمهزینه/پرسرعت

ایدهآل برای ایجنتهای کدنویسی (OpenCode، Claude Code، Cursor، Cline). درخواستها ابتدا به مدلهای استدلال پیشرفته (frontier) هدایت میشوند و هنگام اتمام سهمیه یا بروز خطا، به مدلهای کدنویسی سریع بازگردانده میشوند.

- **Dashboard**: Combos → New Combo → Name: `agent-coding` → Strategy: `Priority`
- **مدلها**:
  1. `claude/claude-sonnet-4-6` (ایجنت اصلی کدنویسی)
  2. `openai/gpt-4o` (جایگزین ثانویه با ظرفیت بالا)
  3. `deepseek/deepseek-v4-flash` (جایگزین بهینه و کمهزینه)

```bash
# مثال از طریق API
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

#### ۲. ترکیب جایگزینی خودکار (Failover) برای سطح رایگان

چندین ارائهدهنده سطح رایگان و بدون نیاز به کلید را بهصورت زنجیرهای به هم متصل میکند تا بدون هزینه API، بیشترین زمان در دسترس بودن فراهم شود.

- **استراتژی**: `Least Used` یا `Round Robin` (بار را میان سهمیهها توزیع میکند)
- **مدلها**:
  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

```bash
# مثال از طریق CLI
omniroute combo create free-stack \
  --models "groq/llama-3.3-70b-versatile,gemini/gemini-2.5-flash,cerebras/gpt-oss-120b" \
  --strategy round-robin
```

#### ۳. خط لوله چندرسانهای / بینایی و متن

ترکیب مدلهای تخصصی بینایی با تولید متن پرسرعت، برای گردشکارهایی که شامل درک تصویر و تولید کد هستند.

- **الگو**: یک ترکیب `Priority` که مدلهای دارای قابلیت بینایی را در ابتدا و یک مدل متن/کد با توان خروجی بالا را در انتها فهرست میکند.
- **مدلها**:
  1. `gemini/gemini-2.5-pro` (درک قوی تصویر/محتوای چندرسانهای)
  2. `openai/gpt-4o` (تعادل میان بینایی و استفاده از ابزار)
  3. `deepseek/deepseek-v4-flash` (تولید متن/کد)

### تابآوری و قطعکنندههای مدار

از مسیر **Dashboard → Settings → Resilience** پیکربندی کنید.

OmniRoute تابآوری در سطح ارائهدهنده را با پنج مؤلفه پیادهسازی میکند:

1. **صف درخواستها و تنظیم آهنگ ارسال (Request Queue & Pacing)** — شکلدهی به درخواستها در سطح سیستم:
   - **Requests Per Minute (RPM)** — حداکثر تعداد درخواست در دقیقه برای هر حساب
   - **Min Time Between Requests** — حداقل فاصله زمانی میان درخواستها (به میلیثانیه)
   - **Max Concurrent Requests** — حداکثر تعداد درخواستهای همزمان برای هر حساب

2. **خنکسازی اتصال (Connection Cooldown)** — پیکربندی جداگانه برای هر نوع احراز هویت، که روی یک اتصال پس از خطاهای قابل تلاش مجدد اعمال میشود:
   - **Base Cooldown** — پنجره خنکسازی پیشفرض برای خطاهای قابل تلاش مجددِ سمت بالادست
   - **Use Upstream Retry Hints** — در صورت ارائه، اشارههای معتبر `Retry-After` یا بازنشانی را لحاظ میکند
   - **Max Backoff Steps** — حداکثر سطح عقبنشینی نمایی برای خطاهای مکرر

3. **قطعکننده مدار ارائهدهنده (Provider Circuit Breaker)** — خطاهای سرتاسری ارائهدهنده را ردیابی میکند، در آستانه هشدار پیکربندیشده ارائهدهنده را تخریبشده علامتگذاری میکند و با رسیدن به آستانه خطای پیکربندیشده، قطعکننده را باز میکند:
   - **Degradation Threshold** — تعداد خطاهای متوالی ارائهدهنده پیش از ورود به `DEGRADED`
   - **Failure Threshold** — تعداد خطاهای متوالی ارائهدهنده پیش از ورود به `OPEN`
   - **Reset Timeout** — بازه زمانی پیش از آزمایش دوباره ارائهدهنده
   - **CLOSED** (سالم) — درخواستها بهطور عادی جریان دارند
   - **DEGRADED** — درخواستها همچنان جریان دارند، در حالی که خطاهای افزایشیافته ردیابی میشوند
   - **OPEN** — ارائهدهنده پس از خطاهای مکرر موقتاً مسدود میشود
   - **HALF_OPEN** — در حال آزمایش اینکه ارائهدهنده بازیابی شده است یا خیر

   محدودیتهای نرخ `429` که در سطح اتصال رخ میدهند، در بخش **خنکسازی اتصال** باقی میمانند و در شمارش قطعکننده ارائهدهنده لحاظ نمیشوند.

   وضعیت زمان اجرای قطعکننده ارائهدهنده فقط در **Dashboard → Health** نمایش داده میشود.

4. **انتظار برای پایان خنکسازی (Wait For Cooldown)** — اگر همه اتصالات کاندید از قبل در حال خنکسازی باشند، OmniRoute میتواند تا نزدیکترین پایان خنکسازی منتظر بماند و سپس همان درخواست کلاینت را بهطور خودکار دوباره تلاش کند.

5. **تشخیص خودکار محدودیت نرخ (Rate Limit Auto-Detection)** — هنگامی که ارائهدهندگان بالادست پنجرههای انتظار صریح برمیگردانند، در صورت فعال بودن این تنظیم، آن اشارهها بر خنکسازی محلی اتصال اولویت مییابند.

**نکته حرفهای:** پس از یک قطعی، از صفحه **Health** برای بررسی و بازنشانی قطعکنندههای فعال ارائهدهنده استفاده کنید. صفحه Resilience فقط پیکربندی را تغییر میدهد.

### خروجی گرفتن / وارد کردن پایگاه داده

پشتیبانگیریهای پایگاه داده را در **Dashboard → Settings → System & Storage** مدیریت کنید.

| عمل                                         | توضیحات                                                                                                                                                                                 |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **خروجی پایگاه داده (Export Database)**     | دانلود پایگاه داده فعلی SQLite بهصورت یک فایل `.sqlite`                                                                                                                                 |
| **خروجی کامل (.tar.gz)**                    | دانلود یک بایگانی پشتیبان کامل که شامل: پایگاه داده، تنظیمات، ترکیبها، اتصالات ارائهدهنده (بدون اعتبارنامهها) و فراداده کلیدهای API است                                                 |
| **وارد کردن پایگاه داده (Import Database)** | بارگذاری یک فایل `.sqlite` برای جایگزینی پایگاه داده فعلی. مگر در صورتی که `DISABLE_SQLITE_AUTO_BACKUP=true` تنظیم شده باشد، پیش از وارد کردن، یک نسخه پشتیبان بهطور خودکار ایجاد میشود |

```bash
# API: خروجی پایگاه داده
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: خروجی کامل (بایگانی کامل)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: وارد کردن پایگاه داده
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**اعتبارسنجی هنگام وارد کردن:** فایل واردشده از نظر یکپارچگی (بررسی pragma در SQLite)، وجود جداول ضروری (`provider_connections`، `provider_nodes`، `combos`، `api_keys`) و اندازه (حداکثر 100MB) اعتبارسنجی میشود.

**موارد استفاده:**

- انتقال OmniRoute بین ماشینها
- ایجاد نسخههای پشتیبان خارجی برای بازیابی پس از بحران
- اشتراکگذاری پیکربندیها بین اعضای تیم (خروجی کامل → اشتراکگذاری بایگانی)

### داشبورد تنظیمات

صفحه تنظیمات برای پیمایش آسان به **۷ تب** سازماندهی شده است:

| برگه           | محتوا                                                                                                                                                                |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **عمومی**      | ابزارهای ذخیرهسازی سیستم، رفتار پیشفرض، قابلیت مشاهده تونل Endpoint                                                                                                  |
| **ظاهر**       | کنترلهای تم (روشن/تیره/سیستم)، قابلیت مشاهده نوار کناری، کلیدهای تغییر وضعیت پانل برای کارتهای تونل Cloudflare/Tailscale/ngrok                                       |
| **هوش مصنوعی** | بودجه تفکر (passthrough / auto-strip / custom / adaptive — مراجعه به [THINKING_BUDGET.md](./THINKING_BUDGET.md))، پرامپت سیستمی سراسری، آمار کش پرامپت               |
| **امنیت**      | تنظیمات ورود/رمز عبور، کنترل دسترسی IP، احراز هویت API برای `/models`، مسدودسازی ارائهدهنده، محافظ تزریق پرامپت                                                      |
| **مسیریابی**   | استراتژی مسیریابی سراسری (Fill First / Round Robin / P2C / Random / Least Used / Cost Optimized)، نامهای مستعار مدل با wildcard، زنجیرههای fallback، پیشفرضهای کامبو |
| **تابآوری**    | صف درخواست، cooldown اتصال، پیکربندی breaker ارائهدهنده، و رفتار انتظار برای cooldown                                                                                |
| **پیشرفته**    | پیکربندی پراکسی سراسری (HTTP/SOCKS5)، بازنویسیهای پراکسی بهازای هر ارائهدهنده                                                                                        |

برگه عمومی دیگر یادداشتهای فقطخواندنی مربوط به لاگگیری و کش را تکرار نمیکند. تنظیمات نگهداری و بهینهسازی پایگاه داده از طریق `/api/settings/database` ذخیره میشوند؛ پاکسازی دستی کش از `DELETE /api/cache` استفاده میکند. سقف ردیفهای لاگ درخواست و پراکسی توسط `CALL_LOGS_TABLE_MAX_ROWS` و `PROXY_LOGS_TABLE_MAX_ROWS` کنترل میشود.

### رونویسی صوت

OmniRoute از رونویسی صوت از طریق endpoint سازگار با OpenAI پشتیبانی میکند:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# مثال با curl
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

ارائهدهندگان **تبدیل گفتار به متن (رونویسی)**:

- `deepgram/` (Nova family)
- `assemblyai/`
- `nvidia/` (Parakeet, Canary)
- `huggingface/` (whisper variants)
- `qwen/`

### استراتژیهای توازن کامبو

توازن هر کامبو را در **داشبورد → کامبوها → ایجاد/ویرایش → استراتژی** پیکربندی کنید.

| استراتژی           | توضیحات                                                                            |
| ------------------ | ---------------------------------------------------------------------------------- |
| **Round-Robin**    | مدلها را بهترتیب و بهنوبت میچرخاند                                                 |
| **Priority**       | همیشه اولین مدل را امتحان میکند؛ فقط در صورت خطا به مدل بعدی برمیگردد              |
| **Random**         | برای هر درخواست، یک مدل تصادفی از کامبو انتخاب میکند                               |
| **Weighted**       | بر اساس وزنهای تخصیصیافته به هر مدل، بهصورت متناسب مسیریابی میکند                  |
| **Least-Used**     | به مدلی با کمترین درخواستهای اخیر مسیریابی میکند (از معیارهای کامبو استفاده میکند) |
| **Cost-Optimized** | به ارزانترین مدل موجود مسیریابی میکند (از جدول قیمتگذاری استفاده میکند)            |

پیشفرضهای سراسری کامبو را میتوان در **داشبورد → تنظیمات → مسیریابی → پیشفرضهای کامبو** تنظیم کرد.
مهلتهای زمانی (timeout) اهداف کامبو بهطور پیشفرض از مهلت زمانی درخواست فعلی به ارث میرسند. از **مهلت زمانی هدف (ثانیه)** در پیشفرضهای کامبو یا یک کامبو منفرد فقط زمانی استفاده کنید که یک محدودیت کوتاهتر بهازای هر هدف باید fallback سریعتری را فعال کند.

بهینهسازیهای تأخیر صفر کامبو اختیاری (opt-in) هستند. **بهینهسازیهای تأخیر صفر** را غیرفعال نگه دارید تا این قابلیتهای کاهش تأخیر با اهداف fallback وارد رقابت نشوند، بر اساس تاریخچه TTFT اهداف را رد نکنند، یا درخواستهای fallback را فشرده نکنند؛ فعالکردن آن به hedging پیکربندیشده، ردکردنهای پیشبینانه TTFT و فشردهسازی پیشدستانه fallback اجازه میدهد تا وفاداری مسیریابی/درخواست را در ازای تأخیر دمی (tail latency) کمتر معاوضه کنند.

وقتی ارائهدهندگان بالادستی محدودیتهای سختگیرانهای برای `max_tokens` / `maxOutputTokens` اعمال میکنند، گزینه **بافر توکن استدلال (Reasoning token buffer)** را غیرفعال کنید. وقتی این گزینه فعال است، مسیریابی ترکیبی (combo routing) تنها برای مدلهایی که سقف خروجی مشخصی دارند، فضای اضافیِ مدل استدلالی اضافه میکند و هرگاه مقدار امنِ بافرشده از آن سقف فراتر رود، محدودیت توکن کلاینت را بدون تغییر باقی میگذارد. اگر محدودیت کلاینت از پیش بالاتر از یک سقف مشخص باشد، OmniRoute پیش از ارسال درخواست بالادستی، آن را تا همان سقف پایین میآورد.

### داشبورد سلامت

از مسیر **Dashboard → Health** به آن دسترسی پیدا کنید. نمای کلی بلادرنگ از سلامت سیستم با ۶ کارت:

| کارت                   | چه چیزی را نشان میدهد                                          |
| ---------------------- | -------------------------------------------------------------- |
| **وضعیت سیستم**        | زمان کارکرد، نسخه، میزان استفاده از حافظه، دایرکتوری دادهها    |
| **سلامت ارائهدهندگان** | وضعیت زمان اجرای مدارشکن (circuit breaker) سراسری ارائهدهندگان |
| **محدودیتهای نرخ**     | کولداونهای فعال اتصال بهازای هر حساب همراه با زمان باقیمانده   |
| **مسدودیهای فعال**     | مسدودیهای فعال در سطح مدل و محرومیتهای موقت                    |
| **کش امضا**            | آمار کش حذف موارد تکراری (کلیدهای فعال، نرخ موفقیت)            |
| **تلهمتری تأخیر**      | تجمیع تأخیر p50/p95/p99 بهازای هر ارائهدهنده                   |

**نکته حرفهای:** صفحه Health هر ۱۰ ثانیه بهصورت خودکار بهروزرسانی میشود. از کارت مدارشکن برای شناسایی ارائهدهندگانی که با مشکل مواجه هستند استفاده کنید.

## 🤖 مسیریابی خودکار (بدون نیاز به پیکربندی)

OmniRoute همراه با یک **مسیریاب خودکار مبتنی بر امتیازدهی** عرضه میشود که برای هر درخواست، بهترین مدل را از میان تمام ارائهدهندگان متصل انتخاب میکند — بدون نیاز به نگهداری هیچ ترکیبی. کافی است درخواست را با یکی از پیشوندهای `auto/*` ارسال کنید؛ OmniRoute در لحظه یک ترکیب مجازی میسازد و گزینهها را بر اساس تأخیر، هزینه، نرخ موفقیت، تناسب پنجره زمینه، مناسببودن مدل برای وظیفه، خطاهای اخیر، سهمیه و وضعیت قطعکننده مدار امتیازدهی میکند.

| پیشوند         | معیار بهینهسازی                                                                                                   |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| `auto`         | حالت پیشفرض متعادل (تأخیر × هزینه × نرخ موفقیت)                                                                   |
| `auto/coding`  | وظایف برنامهنویسی: Claude، GPT-5، GLM، Kimi، Qwen Coder و مدلهای برنامهنویسی DeepSeek را ترجیح میدهد              |
| `auto/cheap`   | کمترین هزینه بهازای هر توکن؛ تأخیر بیشتر را میپذیرد                                                               |
| `auto/fast`    | کمترین تأخیر؛ هزینه را نادیده میگیرد                                                                              |
| `auto/offline` | فقط ارائهدهندگان محلی (Ollama، vLLM، llama.cpp) — مناسب برای محیطهای ایزوله از شبکه                               |
| `auto/smart`   | اولویت با کیفیت استدلال (Opus، GPT-5 xhigh، R1، استدلال GLM 5.1)                                                  |
| `auto/lkgp`    | «آخرین ارائهدهنده مطلوب شناختهشده» — ابتدا به آخرین ارائهدهنده موفق متصل میماند، سپس به قوانین جایگزین رجوع میکند |

مثال:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "این تابع Python را بازآرایی کن" }],
    "stream": true
  }'
```

مسیریاب خودکار بهطور کامل در [AUTO-COMBO.md](../routing/AUTO-COMBO.md) توضیح داده شده است — از جمله نحوه تنظیم وزنهای امتیازدهی، قراردادن ارائهدهندگان در فهرست سیاه و بررسی تصمیمهای مسیریابی در **داشبورد ← ترکیب خودکار**.

## 🔌 یکپارچهسازی MCP و A2A

OmniRoute هم یک **سرور MCP** (پروتکل زمینه مدل) و هم یک **سرور A2A** (JSON-RPC 2.0 عاملبهعامل) است. هر محیط توسعه یا میزبان عامل سازگار با MCP میتواند ابزارهای OmniRoute را مستقیماً فراخوانی کند — بدون نیاز به هیچ پوشش اضافی.

### روشهای انتقال MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP قابلجریان**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (برای افزونههای محیط توسعه که stdio را ترجیح میدهند)

### اتصال Claude Desktop

فایل `~/Library/Application Support/Claude/claude_desktop_config.json` را در macOS، یا فایل معادل آن را در Windows/Linux ویرایش کنید:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### اتصال Cursor / Continue / VS Code MCP

از URL مربوط به SSE یعنی `http://localhost:20128/api/mcp/sse` و یک کلید API از نوع Bearer که در **داشبورد ← کلیدهای API** ایجاد شده است، استفاده کنید.

### دامنهها

MCP در حال حاضر 32 دامنه نامگذاریشده تعریف میکند. هر کلید Bearer را میتوان به دامنههای مشخصی محدود کرد — برای فهرست مرجع دامنهها و ابزارها به [MCP-SERVER.md](../frameworks/MCP-SERVER.md) و برای طرحواره JSON-RPC به [A2A-SERVER.md](../frameworks/A2A-SERVER.md) مراجعه کنید.

## 🧠 سیستم مهارتها

OmniRoute یک **چارچوب مهارت** توسعهپذیر (`src/lib/skills/`) ارائه میدهد تا عاملها و نقطه پایانی A2A بتوانند روالهای مختص دامنه را اجرا کنند (برای مثال `code-review`، `summarize`، `extract-facts` و `web-research`).

- **رابط کاربری بازارچه** — مهارتها را از مسیر **داشبورد ← مهارتها** مرور و نصب کنید
- **دامنههای اختصاصی هر کلید** — مشخص کنید کدام کلیدهای API میتوانند کدام مهارتها را فراخوانی کنند
- **مهارتهای سفارشی** — یک فایل TypeScript را در `src/lib/a2a/skills/` قرار دهید و آن را ثبت کنید تا بلافاصله از طریق A2A قابل فراخوانی شود

مرجع کامل: [SKILLS.md](../frameworks/SKILLS.md).

## 💾 سیستم حافظه

OmniRoute **حافظه مکالمهای بلندمدت** را با بازیابی ترکیبی ذخیره میکند:

- **SQLite FTS5** برای جستوجوی کلیدواژهای در نوبتهای مکالمه گذشته
- **ذخیرهساز برداری Qdrant** (اختیاری) برای یادآوری معنایی
- **استخراج خودکار واقعیتها** — موجودیتها، ترجیحات و تصمیمها پس از هر نشست خلاصه شده و در جدول `memory_facts` ذخیره میشوند
- حافظهها بهازای هر کلید API و هر نشست تفکیک میشوند

حافظهها را در **داشبورد ← حافظه** مدیریت کنید (جستوجو، ویرایش، برونبری و پاکسازی). رابط HTTP (`/api/memory/*`) به عاملها اجازه میدهد واقعیتها را بهصورت برنامهنویسیشده ارسال و جستوجو کنند — به [MEMORY.md](../frameworks/MEMORY.md) مراجعه کنید.

## 🔔 وبهوکها

برای پایش و خودکارسازی بلادرنگ، در رویدادهای OmniRoute مشترک شوید.

- در مسیر **داشبورد ← وبهوکها** یک وبهوک با URL مقصد و کلید محرمانه امضای HMAC ایجاد کنید
- رویدادهای موجود: `request.completed`، `request.failed`، `provider.unavailable`، `budget.exceeded`، `combo.switched`، `circuit_breaker.opened`، `circuit_breaker.closed`
- هر بار ارسالی برای اعتبارسنجی شامل `X-OmniRoute-Signature` (HMAC-SHA256) است
- تلاشهای مجدد: 3 تلاش با تأخیر تصاعدی، سپس انتقال به صف نامههای مرده

طرحواره کامل در [WEBHOOKS.md](../frameworks/WEBHOOKS.md).

## 🛠️ مدیریت برنامهنویسیشده

میتوانید تمام منابع OmniRoute (ارائهدهندگان، ترکیبها، کلیدها و تنظیمات) را از طریق HTTP و با استفاده از یک **کلید Bearer دارای دامنه `manage`** مدیریت کنید.

کلید را در مسیر **داشبورد ← کلیدهای API ← کلید جدید ← دامنه: manage** ایجاد کنید، سپس:

```bash
# فهرست ارائهدهندگان
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# افزودن اتصال ارائهدهنده
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# ایجاد یک ترکیب
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# فهرستکردن/ایجاد کلیدهای API
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

برای مشاهده فهرست کامل نقاط پایانی و طرحوارههای درخواست/پاسخ، به [API_REFERENCE.md](../reference/API_REFERENCE.md) مراجعه کنید.

## 💻 CLI داخلی

OmniRoute یک CLI داخلی (`omniroute …`) برای راهاندازی، عیبیابی و کنترل زمان اجرا ارائه میکند. این ابزار **از صفحه «ابزارهای CLI» در داشبورد جدا است**؛ آن صفحه CLIهای شخص ثالث (Claude Code، Cursor، Codex، Cline و …) را پیکربندی میکند تا بتوانند با OmniRoute ارتباط برقرار کنند.

```bash
omniroute setup                    # راهنمای تعاملی (رمز عبور، ارائهدهندگان، ترکیبها)
omniroute setup --non-interactive  # مناسب برای CI
omniroute doctor                   # عیبیابی سلامت (دایرکتوری داده، پایگاه داده، ارائهدهندگان، پورتها)
omniroute providers available      # فهرست ارائهدهندگان پشتیبانیشده
omniroute providers list           # فهرست اتصالهای پیکربندیشده
omniroute providers test <id>      # آزمایش زنده اتصال یک ارائهدهنده
omniroute combos list              # فهرست ترکیبها
omniroute combos switch <name>     # تنظیم ترکیب پیشفرض
omniroute models                   # فهرست مدلهای موجود (--json، --search)
omniroute keys add | list | remove # مدیریت کلیدهای API از ترمینال
omniroute backup                   # تهیه اسنپشات از پیکربندی و پایگاه داده
omniroute restore [<timestamp>]    # بازیابی از یک اسنپشات
omniroute health                   # جزئیات سلامت (قطعکنندهها، کش، حافظه)
omniroute quota                    # میزان مصرف سهمیه ارائهدهنده
omniroute mcp status               # وضعیت سرور MCP
omniroute a2a status               # وضعیت سرور A2A
omniroute tunnel list|create|stop  # تونلهای Cloudflare/Tailscale/ngrok
omniroute reset-password           # بازنشانی رمز عبور مدیر
omniroute --mcp                    # راهاندازی سرور MCP از طریق stdio
omniroute --port 3000              # راهاندازی سرور روی یک پورت سفارشی
```

نکته: `omniroute doctor --json` را با ابزار پایش خود همراه کنید تا درباره اتصالهای ناسالم ارائهدهندگان هشدار دریافت کنید.

## 🖥️ برنامه دسکتاپ (Electron)

```bash
# از دایرکتوری electron:
cd electron
npm install

# حالت توسعه (اتصال به سرور توسعه در حال اجرای Next.js):
npm run dev

# حالت تولید (از بیلد مستقل استفاده میکند):
npm start
```

### ساخت نصبکنندهها

```bash
cd electron
npm run build          # پلتفرم فعلی
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg عمومی)
npm run build:linux    # Linux (.AppImage)
```
