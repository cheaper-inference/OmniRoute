**OmniCopilot** مدلها و ترکیبهای چت OmniRoute شما را به انتخابگر مدل گپ اصلی Copilot اضافه میکند. از جریانهای کاری چت و عامل موجود ویرایشگر، با فراخوانی ابزار و دید زمانی که توسط مدل انتخابی پشتیبانی میشود، استفاده کنید.

در دسترس بودن VSX باز به خودی خود با هر ویرایشگری که از آن رجیستری استفاده می کند سازگاری ندارد. چت ویرایشگر و پشتیبانی از مدل زبان API را بررسی کنید.

> **برای چت BYOK در کد VS 1.122 + به اشتراک Copilot نیاز نیست.** Microsoft از چت، ابزارها و MCP بدون ورود به سیستم GitHub در هنگام پیکربندی ارائهدهنده پشتیبانی میکند. در کد VS 1.104-1.121 برنامه افزودنی همچنان کار میکند، اما VS Code به یک طرح Copilot وارد شده نیاز دارد. پیشنهادات درون خطی و ویژگیهای مبتنی بر جاسازی خارج از ارائهدهنده API باقی میمانند و همچنان به Copilot نیاز دارند. ادمین های Copilot Business/Enterprise می توانند ارائه دهندگان مدل های شخص ثالث را با خط مشی غیرفعال کنند. یک فورک تنها در صورتی مدل ها را نشان می دهد که ارائه دهنده چت API را پیاده سازی کند. استفاده از ارائهدهنده بالادستی همچنان میتواند متحمل هزینه باشد. به [یادداشتهای انتشار کد VS 1.122](https://code.visualstudio.com/updates/v1_122#_use-byok-without-a-github-sign-in) و [راهنمای مدل زبان](https://code.visualstudio.com/docs/agent-customization/language-models) مراجعه کنید.

## راه اندازی

1. **OmniRoute را اجرا کنید** — `npm install -g omniroute && omniroute` (داشبورد روی `http://localhost:20128`).
2. **افزونه را نصب کنید** — "OmniRoute" را در نمای برنامه های افزودنی جستجو کنید.
3. **اتصال** — `http://localhost:20128` پیش فرض را نگه دارید یا کلید URL و API سرور خود را تنظیم کنید**OmniRoute: مدیریت اتصال** .
4. **یک مدل انتخاب کنید** — Copilot چت → مدل picker →** مدیریت مدل ها…** →**OmniRoute** ، سپس آنچه را که می خواهید علامت بزنید.

برای تنظیمات اتصال، را باز کنید** نماد OmniRoute در نوار فعالیت** (یا `OmniRoute: Manage Connection` را اجرا کنید) و تنظیم کنید:

- **سرور URL** — ریشه سرور، به عنوان مثال `http://omniroute.example.com:20128`. پسوند `/v1` توسط پسوند اضافه شده است. آن را شامل نشود.
- **کلید API** زمانی که خط مشی احراز هویت استنتاج سرور به یک مورد نیاز دارد، — مورد نیاز است. ذخیره شده از طریق کد VS SecretStorage، هرگز در `settings.json`. کلیدهای مخصوص فضای کاری در دسترس هستند. از یک کلید مجاز برای مدل هایی که می خواهید در معرض نمایش قرار دهید استفاده کنید.

این برنامه افزودنی همچنین نشانگر اتصال، بهروزرسانی مدل، بافت مدل و ابردادههای قیمتگذاری (شامل ترکیبهای ترکیبی)، استدلال جریانی با** تلاش فکری** منوی کد VS 1.120 +، نشانگر محدودیت روزانه نوار وضعیت و پانل استفاده (OmniRoute 3.8.50 +)، پیکربندی CLI و برگه داشبورد اختیاری. مدل انتخاب شده و خط مشی سرور تعیین کننده قابلیت هایی است که می توانید استفاده کنید.

## آنچه انتخابگر نمایش میدهد

افزونه محتوای خام `GET /v1/models` را نمایش نمیدهد — آن را شکلدهی میکند، و تعداد نمایشدادهشده به دو دلیل عمدی کمتر از اندازهٔ کاتالوگ است.

### برای هر مدل یک شناسه درخواست میکند

مقدار پیشفرض `MODELS_CATALOG_PREFIX_MODE` برابر با **`dual`** است که هر مدل را دو بار معرفی میکند — یک بار با پیشوند کوتاه مستعار و یک بار با پیشوند رسمی ارائهدهنده — تا پیکربندیهای قدیمیتر کلاینت همچنان بتوانند هر دو شکل را تفسیر کنند:

```
cc/claude-sonnet-4-6        ← پیشوند مستعار
claude/claude-sonnet-4-6    ← پیشوند رسمی، همان مدل
```

افزونه **`GET /v1/models?prefix=alias`** را درخواست میکند تا بدون تغییر تنظیم سراسری سرور برای سایر کلاینتهای شما، بهازای هر مدل یک شناسه دریافت شود. در یک نمونهٔ مرجع، این کار **2345 ورودی را به 1396 کاهش داد — 949 مورد تکراری و صفر مدل ازدسترفته.**

اگر ترجیح میدهید این مورد را در سطح سرور برای _همهٔ_ کلاینتها اصلاح کنید، پرچم قابلیت `MODELS_CATALOG_PREFIX_MODE` را در داشبورد روی `alias` تنظیم کنید. برای پارامتر پرسوجو و جدول مربوط به هر حالت، به [API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) مراجعه کنید.

### مدلهایی را که نمیتوانند چت کنند پنهان میکند

کاتالوگ همچنین مدلهای تصویر، ویدئو، صدا، رتبهبندی مجدد، تعبیهسازی و تعدیل محتوا را فهرست میکند. این مدلها در هر صورت هنگام درخواست چت رد میشوند:

```
HTTP 400 — مدل '<id>' یک مدل تولید تصویر است و نمیتواند در
/v1/chat/completions استفاده شود. در عوض از POST /v1/images/generations استفاده کنید.
```

بنابراین پیش از رسیدن به انتخابگر، بر اساس فیلد `type` خود فیلتر میشوند. **مدلهای Responses-API حفظ میشوند** — هر ورودی Codex / GPT-5.x مقدار `supported_endpoints: ["responses"]` را اعلام میکند و OmniRoute آنها را برای `/v1/chat/completions` ترجمه میکند؛ بنابراین کاملاً قابل استفاده هستند.

### ارائهدهندگانی که هرگز پیکربندی نکردهاید

کاتالوگ، مدلهای ارائهدهندگانی با **اتصال فعال** را بههمراه تمام ارائهدهندگان **noAuth** فهرست میکند — همان ارائهدهندگان بدون کلیدی که بخش بزرگی از سطح رایگان را تشکیل میدهند. این رفتار عمدی است. برای پنهان کردن آنها، در تنظیمات داشبورد به `blockedProviders` اضافهشان کنید؛ هیچ تغییری در افزونه لازم نیست.

## داشبورد درون یک تب VS Code

`omnicopilot.dashboardOpen: "editor"` داشبورد OmniRoute را از طریق Simple Browser در یک تب ویرایشگر نمایش میدهد، نه در یک مرورگر خارجی. جاسازی باید **در سمت سرور بهصورت اختیاری فعال شود**؛ این کار از طریق `DASHBOARD_ALLOW_EMBED=vscode` انجام میشود که صفحات HTML را با
`frame-ancestors 'self' vscode-webview:` بهجای مقدار پیشفرض `frame-ancestors 'none'` +
`X-Frame-Options: DENY` ارائه میکند. سطح API (`/api`، `/v1`، `/v1beta`، `/a2a`، `/healthz`) در هر دو حالت هدرهای سختگیرانه را حفظ میکند.

> ⚠️ **این یک پرچم زمان ساخت است، نه زمان اجرا.** Next.js تابع `headers()` را در مانیفست مسیر کامپایل میکند؛ بنابراین `next.config.mjs` متغیر را هنگام ساخت باندل میخواند
> (`next.config.mjs` → `resolveDashboardEmbedMode`، `scripts/build/dashboardEmbed.mjs`).
> تعریف آن پیش از اجرای سروری که از قبل ساخته شده است، هیچ تغییری ایجاد نمیکند — هدرها در زمان ساخت تثبیت شدهاند.

```bash
# متغیر باید در فرمان BUILD وجود داشته باشد
DASHBOARD_ALLOW_EMBED=vscode npm run build        # یا npm run build:release
npm start
```

| روش نصب                    | آیا میتوانید جاسازی را فعال کنید؟                                                                                                             |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| از کد منبع                 | ✅ متغیر را همانطور که در بالا آمده است، روی فرمان ساخت تنظیم کنید                                                                            |
| `npm install -g omniroute` | ❌ بسته منتشرشده همراه با یک باندل ازپیشساختهشده ارائه میشود — در عوض، آن را از کد منبع بسازید                                                |
| ایمیج Docker               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — ایمیج ازپیشساختهشده در Docker Hub برای جاسازی فعال نشده است |

بدون یک بیلد با قابلیت جاسازی، صفحه از قرار گرفتن در فریم خودداری میکند؛ افزونه این موضوع را از روی هدرهای پاسخ تشخیص میدهد و به مرورگر خارجی برمیگردد — چیزی از کار نمیافتد و افزونه یکبار این موضوع را اطلاع میدهد.
به [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) و ایشوی
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273) مراجعه کنید.

## پیکربندی ابزارهای دیگر خود از داخل کد VS

**`OmniRoute: Configure Coding CLI`** `omniroute` CLI برای نوشتن پروفایل های آماده برای 16 ابزار هدایت می کند: Codex CLI، Claude Code، Cline، Continue، Cursor، Aider، OpenCode، Goose، Crush، Qwen Code، Kilo، Roo، Gemini CLI، Zed، WhyCodes و 5dive. برنامه افزودنی دستورات `setup-*` را در ترمینال یکپارچه فراخوانی می کند. یک نسخه از OmniRoute CLI را نصب کنید که شامل دستور انتخاب شده است. [راهنمای ادغام CLI را](CLI-INTEGRATIONS.md) برای فایلها و پرچمهایی که هر دستور غذا استفاده میکند و [رجیستری ابزار برنامه افزودنی را](https://github.com/cheaper-inference/OmniCopilot/blob/main/src/cliBridge.ts) ببینید.

کلید API از طریق `OMNIROUTE_API_KEY` به CLI داده می شود و هرگز در خط فرمان نیست. دستور العمل های راه اندازی می توانند اعتبارنامه ها را در پیکربندی ابزار هدف حفظ کنند. هنگام اشتراک گذاری یک کلید مخصوص فضای کاری با پیکربندی سطح کاربر ابزار، برنامه افزودنی ابتدا درخواست تأیید می کند.

| لیست مدل ها پس از تغییر ارائه دهندگان قدیمی است                | `OmniRoute: Refresh Models` یا پیوند ↻ در پنل.                                                                                                                                                                                                                        |
| پنل می گوید _آنلاین (مدل ها مسدود شده اند)_، انتخابگر خالی است | سرور کلید را رد می کند. کلید مناسب را با** ذخیره و تست کنید** . اگر به جای آن کلید روی سرور ثابت شده باشد (فعال شده یا به مدل ها دسترسی داشته باشد)، برنامه افزودنی به خودی خود متوجه نمی شود: `OmniRoute: Refresh Models` را اجرا کنید یا پنل OmniRoute را باز کنید. |
