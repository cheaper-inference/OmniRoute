## توکنهای رایگان در ماه: ~ 11.3 بایت به عنوان تعداد دیگران · ~ 90 میلیون واقعی

</div>

> **~ 11.3B توکن رایگان در ماه**<br/> <sub> روش شمارش سایر کاتالوگ ها را محاسبه کرد: هر ردیف اضافه شد، پیشنهادات پایان یافته شامل </sub> بود
>
> **~ 90M واقعی امروز**<br/> <sub> هر سهمیه مشترک یک بار محاسبه میشود: چیزی که واقعاً میتوانید از </sub> استفاده کنید
>
> **اینجا همه چیز رایگان است. بدون پرداخت دیوار.**<br/> ★ [آن را دوست دارم؟ ستاره ما در GitHub](https://github.com/cheaper-inference/OmniRoute)

سایر کاتالوگ ها از US 19 دلار در سال تا US 49 دلار برای دسترسی مادام العمر به داده های زنده دریافت می کنند. اینجا همه چیز رایگان است. <sub> قیمتها در 18-11-2026 بررسی شدند.</sub>

<sub>آخرین بازرسی کاتالوگ در 23/11/2026. [چگونه → را بشماریم](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **حساب های ارائه دهنده خود را بیاورید.** اینها ردیفهای رایگان شخص ثالث هستند، نه یک کمک هزینه نمادین از OmniRoute. ثبتنام کنید، اعتبارنامههایی را در جایی که ارائهدهنده درخواست میکند، دریافت کنید، و مواردی را که میتوانید استفاده کنید وصل کنید. هر ارائه دهنده محدودیت ها، در دسترس بودن و شرایط خود را تعیین می کند.
>
> انباشتن طبقات رایگان با دست به معنای دهها SDKs، دهها محدودیت نرخ و هیچ ایده روشنی از آنچه باقی مانده است. OmniRoute 214 ردیف کاتالوگ را با دسترسی آزاد نگه می دارد و رقم واقعی را از 12 استخر با سهمیه منتشر شده محاسبه می کند، هر استخر مشترک یک بار شمارش می شود. سهمیههایی که فقط پس از بررسی هویت منطقهای باز میشوند (امروز، ModelScope) جدا نشان داده میشوند، +~ 6M پشت راستیآزمایی هویت منطقهای، و هرگز به رقم واقعی اضافه نمیشوند. آنچه باقی می ماند در داشبورد (`/dashboard/free-tiers`) نشان داده می شود.

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute free-tier budget card. Free tokens a month: ~11.3B as others count · ~90M real. Up to ~153M in your first month with one-time signup credits. 12 pools with a published quota and 214 catalog rows with free access behind one endpoint, catalog audited 2026-11-23. The bar shows where the real figure comes from, one segment per pool. Signup credits and free providers without a token cap are listed apart and never added to it. Live used and remaining tokens on /dashboard/free-tiers."/>

> خلاصه متحرک صفحه زنده `/dashboard/free-tiers`. نحوه شمارش هر رقم:** [docs/reference/FREE_TIERS.md#چگونه می شماریم](docs/reference/FREE_TIERS.md#how-we-count)** .
>
> آخرین بازرسی کاتالوگ <sub> در 23/11/2026. ارقام به دو طرف حرکت می کنند. یک ارائه دهنده یک ردیف رایگان را پایان می دهد و تعداد واقعی کاهش می یابد. یکی جدید فرود می آید و بالا می رود. ما آنچه را که کاتالوگ محاسبه میکند منتشر میکنیم، هرگز بهترین حالت گرد شده نیست.</sub>

## نصب کنید، یک ارائه دهنده را متصل کنید، سپس از طریق یک نقطه پایانی مسیریابی کنید

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>`auto` به یک مسیر واجد شرایط نیاز دارد. یک نصب جدید نمیتواند هیچ هدف بدون کلید واجد شرایطی داشته باشد، و یک ارائهدهنده بدون کلید ممکن است مشتریان شخص ثالث را رد کند. ارائه دهندگان علامت گذاری شده به `tos: avoid`، از جمله Kiro، به طور پیش فرض از مسیریابی خودکار مستثنی هستند. اتصال یک حساب آن تنظیم را لغو نمی کند. قبل از انتخاب ارائهدهنده، [راهنمای ردیفهای رایگان را](docs/getting-started/FREE-TIERS-GUIDE.md) ببینید.</sub>

<sub>اسکریپت های شروع سریع را کپی-پیست کنید** پایتون، Node.js، PHP و cURL** : [`examples/quickstart/`](examples/quickstart/). نسخه گام به گام: [شروع سریع](#quick-start).</sub>

## ترکیب: گل سرسبد

1. **با `auto` شروع کنید.** مدل را در کلاینت سازگار با OpenAI خود تنظیم کنید. OmniRoute یک ترکیب مجازی از ارائه دهندگان متصل ایجاد می کند و کاندیداها را به صورت زنده امتیاز می دهد.
2. **برای کنترل بیشتر، ترکیبی را ذخیره کنید.** یک نام، لیست هدف و استراتژی انتخاب کنید، سپس از آن نام به عنوان مدل استفاده کنید. استراتژی تعیین میکند که کدام هدف اول میرود و بقیه چگونه امتحان میشوند.

مسیرهای ترکیبی در بین مدل ها به طور خودکار. در صورت اتمام سهمیه، شکست ارائه دهنده یا قفل شدن مدل، هدف واجد شرایط و سالم بعدی را امتحان می کند.

### Zero-config: فقط `auto` استفاده کنید

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

انواع وزن ها را تنظیم می کنند. آخرین مسیریابی خوب شناخته شده با آخرین ارائه دهنده موفق باقی می ماند تا زمانی که شکست بخورد، سپس دوباره امتیاز می گیرد. `auto/fast` و `auto/cheap` ترجیحات را بدون تضمین سریعترین یا ارزانترین مدل بیان می کنند.

| مدل ID              | رفتار                                                                                                                                                                                                                                                                         |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | وزن های پیش فرض متوازن                                                                                                                                                                                                                                                        |
| `auto/fast`         | از تأخیر کم و سلامت ارائه دهنده حمایت می کند.                                                                                                                                                                                                                                 |
| `auto/cheap`        | به قیمت پایین کاتالوگ ترجیح می دهد.                                                                                                                                                                                                                                           |
| `auto/coding`       | وزن اول کیفیت برای تولید کد.                                                                                                                                                                                                                                                  |
| `auto/smart`        | اوزان کیفیت اول با 10٪ کاوش (پیش فرض 5٪).                                                                                                                                                                                                                                     |
| `auto/lkgp`         | مسیریابی صریح آخرین شناخته شده-خوب با همان وزن های `auto`.                                                                                                                                                                                                                    |
| `auto/subscription` | فقط از سهمیه طرح تأیید شده مستقیم استفاده می کند. HTTP 503 را وقتی در دسترس نباشد برمیگرداند و از بازگرداندن صورتحساب جلوگیری میکند.                                                                                                                                          |
| `auto/thrifty`      | طرح → keyless → رایگان → → premium ارزان. ممکن است به مدلهای صورتحسابشده برسد و زمانی که سهمیه و خنکسازی اجازه دهد، به طرح بازمیگردد.                                                                                                                                         |
| `auto/offline`      | طرفدار سهمیه و نرخ محدود فضای سر است. درخواست ها همچنان به ارائه دهندگان شما ارسال می شود.                                                                                                                                                                                    |
| `auto/chaos`        | یک مدل برای هر ارائه دهنده به صورت موازی، حداکثر تا پنج مدل به طور پیش فرض یا ده مدل در هنگام پیکربندی. یک تماس بالادستی برای هر مدل. در صورت عدم موفقیت مدل برتر، پاسخ رتبه برتر یا آخرین پاسخ پانل موفق را برمیگرداند. `fusion` برای ترکیب پاسخ ها با یک قاضی استفاده کنید. |

نمونههای طبقهبندی و ردیف اختیاری عبارتند از `auto/coding:fast`، `auto/coding:free`، `auto/reasoning:pro` و `auto/vision`. اگر هیچ نامزد متصلی مطابقت نداشته باشد، درخواست HTTP 503 را برمی گرداند و استخر باریک می ماند. ### یا خودتان بسازید: 22 استراتژی مسیریابی

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

CLI 15 استراتژی از 22 استراتژی را می پذیرد. داشبورد و ترکیبات API همه 22 را می پذیرد.

| استراتژی            | رفتار                                                                                                                                                                                                                                       |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`              | کاندیداهای رتبه زنده با گلزن 16 عاملی Auto-Combo.                                                                                                                                                                                           |
| `cache-optimized`   | حسابی را ترجیح دهید که احتمالاً پیشوند درخواست را در حافظه پنهان نگه می دارد.                                                                                                                                                               |
| `context-optimized` | ابتدا بزرگترین پنجره زمینه شناخته شده را امتحان کنید.                                                                                                                                                                                       |
| `context-relay`     | سفارش خود را حفظ کنید و هنگام تغییر حساب، خلاصه مکالمه را ارسال کنید.                                                                                                                                                                       |
| `cost-optimized`    | مرتبسازی بر اساس قیمت نشانه ورودی کاتالوگ، آخرین مجهولات. هزینه درخواست نهایی ممکن است متفاوت باشد.                                                                                                                                         |
| `expiry-first`      | سهمیه خرج کنید احتمالاً منقضی میشود، بالاترین مقدار باقیمانده در ساعت تا ابتدا بازنشانی شود.                                                                                                                                                |
| `fill-first`        | روی اولین هدف موجود بمانید تا زمانی که تمام شود یا شکست بخورد، سپس ادامه دهید.                                                                                                                                                              |
| `fusion`            | از یک پانل به صورت موازی سؤال کنید و از یک قاضی بخواهید که یک پاسخ را ترکیب کند.                                                                                                                                                            |
| `headroom`          | رایگان ترین ظرفیت را در پنجره های 5 ساعته و هفتگی انتخاب کنید.                                                                                                                                                                              |
| `jev`               | TypeSafe Jev انتخاب می کند که کدام ورودی ها در لیست رتبه بندی شما اجرا شوند. `COMBO_JEV_STRATEGY_ENABLED` را روشن کنید تا در هر درخواست گزیده ای ارسال شود و از تماس های پولی TypeSafe استفاده کنید. با خاموش بودن، سفارش شما اعمال می شود. |
| `least-used`        | هدفی را با کمترین درخواست های ثبت شده در این ترکیب انتخاب کنید.                                                                                                                                                                             |
| `lkgp`              | ابتدا آخرین ارائه دهنده موفق را امتحان کنید، در غیر این صورت سفارش خود را حفظ کنید.                                                                                                                                                         |
| `p2c`               | دو هدف را نمونه بگیرید و بر اساس میزان موفقیت و تأخیر انتخاب کنید.                                                                                                                                                                          |
| `pipeline`          | خروجی هر مرحله را به ترتیب به هدف بعدی وارد کنید و فقط پاسخ نهایی را برگردانید.                                                                                                                                                             |
| `priority`          | اهداف را در سفارش خود امتحان کنید. چسبندگی جلسه آن را حفظ می کند.                                                                                                                                                                           |
| `quota-weighted`    | حساب های تمام شده را رها کنید و با سهمیه باقیمانده و بار حین پرواز قرعه کشی کنید.                                                                                                                                                           |
| `random`            | برای هر درخواست مخلوط کنید. همان هدف اول می تواند تکرار شود.                                                                                                                                                                                |
| `reset-aware`       | به سهمیه و زمان باقیمانده برای بازنشانی در هر جلسه و پنجره هفتگی امتیاز دهید.                                                                                                                                                               |
| `reset-window`      | حسابی را امتحان کنید که پنجره سهمیه آن زودتر بازنشانی میشود.                                                                                                                                                                                |
| `round-robin`       | چرخش به ترتیب، سه موفقیت در هر هدف به طور پیش فرض.                                                                                                                                                                                          |
| `strict-random`     | از یک عرشه به هم ریخته برخورد کنید تا هر هدف یک بار قبل از تکرار پیشروی کند.                                                                                                                                                                |

### انعطاف پذیری در: 3 لایه مستقل ساخته شده است

خرابیها در سه حوزه بررسی میشوند، بنابراین یک مدل بد حساب خود را حذف نمیکند و یک حساب بد ارائهدهنده خود را حذف نمیکند.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### اگر یک ارائه دهنده کامل از کار افتاده باشد

را** مدار شکن ارائه دهنده** پس از 8 شکست (OAuth) یا 12 (کلید API ) با وضعیت 408، 500، 502، 503 یا 504 باز میشود. هنگامی که ارائهدهنده باز است، Combos از آن رد میشوند. پس از 60 یا 30 ثانیه، یک درخواست پروب تصمیم می گیرد که بسته شود یا خیر.

#### اگر یک کلید یا حساب دارای نرخ محدود باشد

را** خنک شدن اتصال** نیمکت فقط آن اتصال، با عقب نشینی نمایی از 5 ثانیه (OAuth) یا 3 ثانیه (کلید API ). کلیدهای دیگر برای همان ارائه دهنده به خدمت ادامه می دهند.

#### اگر یک مدل رد شود

را** قفل مدل** فقط آن مدل را در آن اتصال پس از هر مدل 429، 404 یا رد دسترسی مسدود می کند. مدل های دیگر در همان اتصال به خدمت ادامه می دهند.

اتصالات ممنوعه، منقضی شده و بدون اعتبار حالت پایانی هستند، نه خنکدان: آنها منتظر میمانند تا شما آنها را برطرف کنید.

## رادار OmniRoute

رادار نسخه زنده و امضا شده کاتالوگ لایه آزاد بالا است و برای همه رایگان است. هیچ دیوار پرداختی و دوره انتظاری وجود ندارد. این گزینه انتخابی و فقط GET است. مشتری OmniRoute چیزی به رادار ارسال نمی کند: هیچ پیامی، ترافیک، پیکربندی ارائه دهنده یا تله متری استفاده.

اعداد بالا از کاتالوگ ارسال شده با این نسخه آمده است. رادار می تواند داده های جدیدتر را بین نسخه ها نشان دهد. پیشنهادات و تبلیغات رایگان جدید هر هفته اضافه می شود. رشد عدد واقعی را در رادار تماشا کنید.

## CLIs و عوامل کدنویسی سازگار

فهرست کاتالوگ داشبورد** 39 ادغام** (28 ابزار کدنویسی و 11 عامل). مانیفست CLI Gemini CLI را اضافه میکند که با `omniroute run` راهاندازی میشود و چهار ابزاری که فقط میتواند شناسایی کند. از همه آنها،** 8** راه اندازی با `omniroute run`،** 12** می توان با `omniroute configure` راه اندازی کرد و** 16** یک دستور اختصاصی `setup-*` داشته باشید. مسیری را انتخاب کنید که با آنچه می خواهید مطابقت دارد.

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"
omniroute setup-whycodes && omniroute run whycodes --model glm/glm-5.2

# Or pick provider and model interactively and write the tool's own config:
omniroute configure codex   # also: claude opencode qwen aider goose gemini whycodes cline continue kilo 5dive
```

هر دستوری به زمینه فعال از راه دور (`omniroute connect <host>`) احترام می گذارد. `--dry-run` دقیقاً env و args را بدون اجرای چیزی چاپ میکند و `--api-key-env NAME` کلید را از تاریخچه پوسته شما دور نگه میدارد. کد Qwen و Gemini CLI در یک خانه موقت اجرا می شود که در هنگام خروج حذف می شود. WhyCodes ارائه دهنده خود را فقط از `config.toml` می خواند پس `setup-whycodes` یک بار قبل از `run whycodes` اجرا کنید. → [CLI](docs/guides/CLI-INTEGRATIONS.md)

## کامل CLI، MCP و A2A

> OmniRoute یک مشتری خط فرمان را با** 91 دستورات سطح بالا و گروه های فرمان** (754 فرمان شمارش دستورات فرعی)، an** سرور MCP با 110 ابزار و 33 اسکوپ** ، و یک** نماینده A2A با 6 مهارت** . اسکریپت ها، ترمینال ها و عوامل AI همگی می توانند از یک دروازه استفاده کنند.

### یک CLI واقعی، نه فقط `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

پرچم جهانی `--output table|json|jsonl|csv` همان دستورات را از اسکریپت ها و CI قابل استفاده می کند.

### حالت از راه دور: CLI در لپ تاپ شما، OmniRoute در سرور

یک بار به یک سرور راه دور وارد شوید. CLI آن را به عنوان یک ذخیره می کند** زمینه** و دستورات بعدی در مقابل آن سرور اجرا می شوند تا زمانی که به عقب برگردید.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| محدوده توکن | <img width="2000" height="0" alt=""> آنچه اجازه می دهد           |
| ----------- | ---------------------------------------------------------------- |
| `read`      | لیست و بازرسی: مدل ها، وضعیت، سیاهههای مربوط، استفاده            |
| `write`     | `read` plus پیکربندی و اعمال: راه اندازی مشتری، کلیدها، پیکربندی |
| `admin`     | `write` plus management: نشانه ها، ارائه دهندگان، خدمات، سیاست   |

یک میزبان لخت `http://` و پورت 20128 را دریافت می کند. وقتی سرور پشت TLS مینشیند یک URL `https://` کامل را ارسال کنید. مسیرهایی که میتوانند فرآیندها را ایجاد کنند، صرف نظر از نشانه، فقط به صورت حلقهای باقی میمانند.

### یک عامل را وصل کنید

یک عامل یا کد شما میتواند مسیریابی، ارائهدهندهها، ترکیبها، حافظه پنهان، فشردهسازی و حافظه را از طریق هر یک از این رابطها هدایت کند. مسیرهای HTTP توسط دروازه، به طور پیشفرض در `http://localhost:20128` ارائه میشوند.

| رابط                    | نقطه پایانی یا دستور       | از آن استفاده کنید                                                              |
| ----------------------- | -------------------------- | ------------------------------------------------------------------------------- |
| MCP بیش از stdio        | `omniroute --mcp`          | Claude Desktop، Cursor و سایر مشتریان MCP محلی                                  |
| MCP روی HTTP قابل جریان | `/api/mcp/stream`          | مشتریان MCP راه دور: 110 ابزار، 33 محدوده، هر تماس نوشته شده در گزارش حسابرسی   |
| MCP بر SSE              | `/api/mcp/sse`             | مشتریانی که هنوز از حمل و نقل SSE استفاده می کنند                               |
| کشف A2A                 | `/.well-known/agent.json`  | کارت نماینده: به سایر نمایندگان می گوید که OmniRoute چه کاری می تواند انجام دهد |
| اعدام A2A               | `POST /a2a`                | وظایف JSON-RPC 2.0، همزمان یا پخش شده از طریق SSE، در 6 مهارت                   |
| REST API                | `/v1/*`                    | چت سازگار با OpenAI، پاسخ ها، جاسازی ها، تصاویر، صدا و OCR                      |
| وب هوک ها               | `/api/webhooks`            | رویدادها به Slack، Discord، Telegram، یا هر URL با امضای HMAC                   |
| CLI از راه دور          | `omniroute connect <host>` | یک نمونه از راه دور را با نشانههای دسترسی محدوده هدایت کنید                     |

شش مهارت A2A عبارتند از `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` و `list-capabilities`.

**قبل از اتصال:**

- **MCP over HTTP غیر فعال می شود.** آن را با `omniroute mcp enable --transport streamable-http` یا از صفحه Endpoints داشبورد روشن کنید. یک حمل و نقل HTTP در یک زمان فعال است: `streamable-http` خدمت `/api/mcp/stream`، `sse` خدمت `/api/mcp/sse`.
- **A2A غیر فعال می شود.** آن را در صفحه نقاط پایانی داشبورد فعال کنید. سپس `POST /a2a` از همان قوانین کلید API مانند `/v1` پیروی می کند.
- **MCP از راه دور به یک کلید مناسب نیاز دارد.** `/api/mcp/*` به طور پیش فرض فقط به صورت حلقه بک پاسخ می دهد. از یک هاست دیگر، یک کلید با `manage` یا `admin` (همه ابزارها) یا با `mcp:connect` به اضافه دامنه ابزارهای مورد نیاز خود ارسال کنید. برای کلیدهای بدون `manage`/`admin`، دامنه ابزار همیشه اعمال می شود.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

### چگونه کار می کند — خط لوله، معماری و ریاضی پس انداز

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. ترکیب پیشفرض انباشته `RTK → Caveman` را اجرا میکند. هنگامی که هر دو بر روی یک محموله tool/context عمل می کنند، پس انداز ترکیب می شود:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

**درخواست اول**

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

**بررسی کنید که کلید شما به کدام مدلها دسترسی دارد**

```bash
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_OMNIROUTE_KEY"
```

**تنظیمات ابزار دستی**

```txt
Base URL: http://localhost:20128/v1
API Key:  [the key from Dashboard → API Keys]
Model:    auto            (routes among eligible connections — or choose provider/model)
```

> **انتخاب ارائه دهنده** یکی را انتخاب کنید که شرایط فعلی و سهمیه آن متناسب با مورد استفاده شما باشد. سطوح رایگان ممکن است نیاز به ثبت نام، تأیید یا روش پرداخت داشته باشند.   -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest

`:latest` بالاترین را دنبال می کند** منتشر شده است** ثابت SemVer. git `main` را ردیابی نمی کند. پین `:X.Y.Z` برای GitOps. به [کانالهای انتشار Docker](docs/guides/DOCKER_GUIDE.md#release-channels) مراجعه کنید. پینهای تصویر**`OMNIROUTE_MEMORY_MB=1024`** . این برای داشبورد و یک چت سبک کافی است.** عوامل کدنویسی** (`POST /v1/responses` از کد Claude ، Codex، Grok، ...) به یک پشته V8 بسیار بزرگتر یا فرآیند `FATAL ERROR` در ~ 12 GiB تحت دو زمینه طولانی با هم همپوشانی نیاز دارید. اندازه ظرف را بالای پشته قرار دهید (بافرهای بومی خارج از V8 قرار دارند):

| حجم کاری <img width="2000" height="0" alt=""> | هیپ (`-e OMNIROUTE_MEMORY_MB`) | ظرف (`--memory`) |
| --------------------------------------------- | ------------------------------ | ---------------- |
| داشبورد / چت سبک                              | `1024` (پیشفرض تصویر)          | ≥ 2 گرم          |
| یک عامل کد نویسی                              | `8192`                         | ≥ 10 گرم         |
| دو `/v1/responses` طولانی همزمان              | `10240`–`12288`                | ≥ 12-16 گرم      |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

جدول کامل: [Docker Guide — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **کانال Docker پیش از انتشار:** `diegosouzapw/omniroute:next` و `diegosouzapw/omniroute:next-web` از شاخه پیش فرض `release/v*` فعلی پیروی می کنند. این تگهای قابل تغییر فقط برای آزمایش رفعهای منتشر نشده در نظر گرفته شدهاند و هستند** برای تولید پشتیبانی نمی شود** . به [کانال های انتشار Docker](docs/guides/DOCKER_GUIDE.md#release-channels) مراجعه کنید.

**🥟 Bun**

نصب استاندارد `bun install` و جهانی (`bun install -g omniroute`) از طریق تشخیص زمان اجرا Bun پشتیبانی می شود:

- **`bun:sqlite` توکار** : OmniRoute هنگام اجرای زیر Bun از درایور `bun:sqlite` داخلی Bun استفاده میکند و در Node.js یا `sql.js` به `better-sqlite3` برمیگردد.
- **انتخاب خودکار باندلر Webpack در توسعه دهنده** : توسعه (`bun run dev`) به طور خودکار Bun شناسایی می کند و Turbopack به نفع Webpack غیرفعال می کند تا از ناسازگاری های اتصال V8 بومی جلوگیری کند. ساختهای تولیدی (`bun run build`) دقیقاً مانند Node از `OMNIROUTE_USE_TURBOPACK` پیروی میکنند: Turbopack به طور پیشفرض، `OMNIROUTE_USE_TURBOPACK=0` برای ساخت با Webpack (`Dockerfile.bun` آن را به عنوان `--build-arg` نشان میدهد).
- **اختصاصی Bun Dockerfile** : `Dockerfile.bun` چند مرحله ای برای استقرار تولید Bun بومی (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
bun run dev
```

**نصب سریعتر / ناب ⚡ (از ساخت بومی صرفنظر کنید)**

موتور SQLite بومی (`better-sqlite3`) یک است** اختیاری** وابستگی، بنابراین یک نصب سراسری هرگز کامپایل از منبع را مسدود نمی کند: زمانی که با platform/Node شما مطابقت دارد از یک باینری از پیش ساخته شده استفاده می کند و در غیر این صورت به طور شفاف به یک موتور خالص JS (`node:sqlite` در Node 22 +، در غیر این صورت `sql.js` WASM همراه) — بدون نیاز به ابزار ساخت برمی گردد.

برای رد شدن از نصب پس از نصب** گرم کردن بومی** به طور کامل (CI، ماشین های بدون سر یا کند). توجه: این فقط مرحله گرم کردن SQLite بومی (`scripts/postinstall.mjs`) را رد می کند. قلاب binary-copy/repair (`scripts/build/postinstall.mjs`) هنوز به طور معمول کار می کند:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

برای سریع ترین نصب ترجیح می دهند** pnpm** (لینکهای سخت + فروشگاه آدرسدهی محتوا — را در بالا ببینید). برای یک زمان اجرا بدون داشبورد و بدون هد از نمایه Docker `base` (بالا) یا [راهنمای Termux](docs/guides/TERMUX_GUIDE.md) استفاده کنید. CLI و داشبورد وب با فرآیند یکسانی در یک پورت ارائه میشوند، بنابراین امروزه بستهای جداگانه برای CLI وجود ندارد.

### نحوه مشارکت

1. مخزن را چنگال کنید
2. شعبه از** فعال** نکته `release/vX.Y.Z` (نه `main`) — به [مدل انشعاب و انتشار](docs/ops/BRANCHING_MODEL.md) مراجعه کنید
3. شاخه ویژگی خود را ایجاد کنید (`git checkout -b feat/amazing-feature`)
4. تغییرات خود را انجام دهید (`git commit -m 'feat: add amazing feature'`)
5. هل دادن به شاخه (`git push origin feat/amazing-feature`)
6. باز کردن درخواست کشش با** پایه = که شعبه `release/vX.Y.Z`**

برای دستورالعمل های دقیق به [CONTRIBUTING.md](CONTRIBUTING.md) مراجعه کنید.
