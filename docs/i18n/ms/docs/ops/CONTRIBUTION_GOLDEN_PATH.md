Gunakan panduan ini untuk memilih kitaran pembangunan boleh dipercayai yang paling ringkas bagi sesuatu pull request. Panduan ini tidak
menggantikan dokumen seni bina dan keselamatan khusus bidang yang dipautkan di bawah; sebaliknya, ia menghubungkan setiap jenis
perubahan lazim kepada kontraknya, semakan berfokus dan liputan CI.

## Laluan yang diikuti oleh setiap perubahan

1. **Pilih asas sebelum mengedit.** Cari cabang `release/v*` aktif yang tertinggi dan cipta cabang daripada
   hujungnya. Sasarkan cabang tersebut, bukan `main`. Jika pembekuan keluaran sedang berkuat kuasa, jangan sasarkan cabang
   yang dibekukan; gunakan kitaran aktif seterusnya yang diterangkan dalam
   [Model Percabangan & Keluaran](BRANCHING_MODEL.md).
2. **Nyatakan kontrak.** Kenal pasti setiap katalog, skema, artifak terjana, API awam atau antara muka
   pengguna yang dipengaruhi oleh perubahan tersebut. Jadual di bawah memberikan set permulaan minimum.
3. **Tulis atau kemas kini ujian berfokus.** Perubahan produksi dalam `src/`, `open-sse/`, `electron/` atau
   `bin/` memerlukan ujian automatik dalam PR yang sama. Jalankan fail ujian paling minimum yang membuktikan
   tingkah laku tersebut, kemudian jalankan gerbang berfokus yang disenaraikan.
4. **Biarkan CI menjalankan matriks menyeluruh.** Kesemua serpihan ujian unit, Vitest, pengetatan liputan dan
   binaan produksi dijalankan pada PR. Jalankan suit menyeluruh secara setempat hanya apabila kegagalan berfokus menunjukkan
   kesan yang lebih luas atau apabila perubahan merangkumi beberapa subsistem.
5. **Selaraskan sebelum semakan.** Dapatkan asas aktif, periksa komit baharunya dan perbezaan perubahan anda berbanding
   dengannya, kemudian lakukan rebase atau gabungkan asas mengikut aliran kerja penyumbang. Selesaikan konflik fail terjana
   dan katalog daripada sumbernya, jana semula fail tersebut, jalankan semula kitaran berfokus dan sahkan bahawa
   PR masih menyasarkan cabang keluaran aktif.
6. **Rekodkan bukti.** Dalam templat PR, senaraikan perintah yang dijalankan, setiap fail ujian yang ditambah atau diubah,
   migrasi atau bendera ciri, serta sebarang pengesahan khusus CI yang masih belum selesai.

## Laluan utama mengikut jenis perubahan

Perintah di bawah ialah semakan berfokus minimum, bukan kebenaran untuk melangkau ujian yang secara langsung meliputi
tingkah laku yang anda ubah.

### Penyedia

**Kontrak**

- Takrif penyedia dalam `src/shared/constants/providers/` dan komposisinya dalam
  `src/shared/constants/providers.ts`.
- Model dan keupayaan dalam `open-sse/config/providerRegistry.ts` atau fail pendaftaran yang diekstrak daripadanya.
- Pemilihan pelaksana/penterjemah, konfigurasi OAuth atau kunci API, aset papan pemuka dan rujukan penyedia
  terjana apabila berkenaan.
- Bukti kelayakan awam mesti menggunakan `resolvePublicCred()`; respons ralat mesti menggunakan pembantu ralat
  tersanitasi yang dikongsi. Lihat `docs/security/PUBLIC_CREDS.md` (git; tidak dikompil ke dalam `/docs`) dan
  [Sanitasi Ralat](../security/ERROR_SANITIZATION.md).

**Kitaran berfokus**

```bash
npm run check:provider-consistency
npm run check:provider-assets
node --import tsx/esm --test tests/unit/provider-translate-path-golden.test.ts
node --import tsx/esm --test tests/unit/<provider-or-executor>.test.ts
npm run gen:provider-reference   # apabila katalog berubah; komitkan perbezaan perubahan terjana
npm run lint
```

Uji juga setiap keluarga permintaan yang terjejas: sembang, Responses, imej, pembenaman, audio atau video.
Semak katalog terjana dan perbezaan perubahan golden sebagai perubahan kontrak; jangan terimanya secara membuta tuli.

### Penghalaan

**Kontrak**

- Nilai strategi awam dan metadata UI dalam `src/shared/constants/routingStrategies.ts`.
- Penghantaran dan penyusunan di bawah `open-sse/services/combo.ts` dan `open-sse/services/combo/`.
- Skema combo, pengekalan, keadaan daya tahan, keupayaan model serta kawalan API/UI.
- [Enjin Auto-Combo](../routing/AUTO-COMBO.md) dan dokumentasi daya tahan apabila tingkah laku berubah.

**Kitaran berfokus**

```bash
node --import tsx/esm --test tests/unit/combo-<behavior>.test.ts
npm run test:combo:matrix        # perubahan strategi atau penghantaran
npm run check:known-symbols      # perubahan pendaftaran strategi
npm run lint
```

Gunakan ujian upstream olok-olok yang deterministik secara setempat. Ujian ringkas combo langsung memerlukan bukti kelayakan dan
bersifat manual, bukan pengganti CI.

### UI / UX

**Kontrak**

- Laluan/halaman Next.js dan sempadan komponen dikongsi di bawah `src/app/` dan
  `src/shared/components/`.
- Bentuk respons API, keadaan pemuatan/kosong/ralat, tingkah laku papan kekunci dan pembaca skrin,
  reka letak responsif, tema dan peluasan lokal.
- Rentetan sumber UI bahasa Inggeris dalam `src/i18n/messages/en.json`; jangan tetapkan teks baharu yang dilihat pengguna secara terus dalam kod.

**Kitaran berfokus**

```bash
node --import tsx --test tests/unit/dashboard/<feature>.test.ts
npx vitest run --config vitest.config.ts tests/unit/ui/<component>.test.tsx
npm run check:dashboard-typecheck
npm run lint
```

Jalankan aplikasi untuk perubahan interaksi atau visual dan semak kedua-dua ruang pandang sempit serta lebar. CI menjalankan
binaan produksi dan suit yang lebih luas; tingkah laku visual masih memerlukan komponen berfokus, Playwright
atau semakan manual yang didokumenkan dan bersesuaian dengan perubahan tersebut.

### i18n

**Kontrak**

- `src/i18n/messages/en.json` ialah sumber UI; `config/i18n.json` ialah sumber lokal.
- Katalog CLI disimpan secara berasingan di bawah `bin/cli/locales/`.
- Kekalkan ruang letak dan tag ICU dengan tepat. Jangan terjemahkan nama produk/penyedia/model,
  nama protokol dan pengepala, perintah, pengecam kod/JSON, URL, pemboleh ubah persekitaran atau
  istilah terlindung seperti `OmniRoute`, `OAuth`, `MCP` dan `A2A`. Senarai sumber semasa ialah
  `scripts/i18n/glossary/protected-terms.json`.

**Kitaran berfokus**

```bash
npm run i18n:sync-ui:dry
npm run i18n:check-ui-coverage
npm run i18n:check-value-drift
npm run i18n:check-glossary
npm run check:cli-i18n          # apabila rentetan/katalog CLI berubah
npm run lint
```

Ini ialah panduan untuk sistem sedia ada, bukannya pelawaan untuk memperluas alat atau model kekuncinya.
Pastikan tampalan i18n kekal tertumpu sementara sistem pengganti sedang direka. Jangan jalankan perintah terjemahan
yang memanggil perkhidmatan luaran melainkan tugas tersebut secara jelas memerlukan terjemahan terjana dan
anda telah menyemak perbezaan perubahan yang terhasil.

### CLI

**Kontrak**

- Perintah dan bendera awam dalam `bin/cli/`, perintah API yang dijana, kod keluar, stdout/stderr dan
  bentuk output JSON, tingkah laku konfigurasi/persekitaran, serta fail yang dipakejkan.
- Rentetan CLI yang dilihat pengguna mesti menggunakan lapisan i18n CLI dan memastikan katalog `en`/`pt-BR` sentiasa diselaraskan.
- Kekalkan Node sebagai masa jalan yang disokong dan kontrak binari yang diterbitkan.

**Kitaran berfokus**

```bash
node --import tsx/esm --test tests/unit/cli/<command>.test.ts
npm run check:cli-i18n
npm run build:cli             # perubahan CLI yang dijana/dihimpunkan
npm run check:pack-policy     # perubahan permukaan pakej
npm run lint
```

Gunakan perintah yang tepat dalam direktori data sementara apabila tingkah laku bergantung pada penghuraian, fail atau status
keluar. CI menjalankan semakan artifak pakej dan ekosistem yang lebih menyeluruh.

### Pangkalan data

**Kontrak**

- Modul domain di bawah `src/lib/db/`; import modul tertentu secara langsung (lapisan eksport semula `localDb.ts` yang lama telah dialih keluar).
- Migrasi SQL bernombor dan idempoten di bawah `src/lib/db/migrations/`, keselamatan transaksi, tingkah laku
  naik taraf, indeks dan setiap pemanggil yang terjejas oleh skema.
- Laluan dan pengendali tidak sekali-kali mengeluarkan SQL mentah secara langsung.

**Kitaran berfokus**

```bash
npm run check:migration-numbering
npm run check:db-rules
node --import tsx/esm --test tests/unit/db/<domain>.test.ts
node --import tsx/esm --test tests/unit/db/migration-<number>.test.ts
npm run lint
```

Uji kedua-dua pangkalan data baharu dan naik taraf daripada skema terdahulu apabila menambahkan migrasi. Ujian pangkalan data
mesti menutup pemegang dan memanggil `resetDbInstance()` semasa pembersihan. Jalankan `npm run test:bun:db` hanya apabila
laluan penyesuai Bun berdaya usaha terbaik berubah; Node kekal sebagai rujukan berautoriti.

### Binaan / pelaksanaan

**Kontrak**

- Manifes/fail kunci akar dan ruang kerja, `scripts/build/`, pemasangan kendiri Next.js, kandungan pakej
  `dist/`, metadata platform Electron, aliran kerja CI dan penanda pelaksanaan.
- Julat Node yang disokong dan penggunaan Bun yang disenaraikan sebagai dibenarkan dalam `CLAUDE.md` mesti dikekalkan.
- Artifak binaan kekal tidak dijejaki; dasar kebergantungan, lesen, aliran kerja dan pakej terpakai.

**Kitaran berfokus**

```bash
node --import tsx/esm --test tests/unit/build/<behavior>.test.ts
npm run check:build-scope
npm run check:lockfile         # perubahan kebergantungan atau fail kunci
npm run check:pack-policy      # perubahan permukaan pakej yang diterbitkan
npm run lint
```

Gunakan `npm run build` secara setempat hanya apabila perubahan menjejaskan kompilasi, pemasangan kendiri, aset
atau penghimpunan masa jalan. Gunakan `npm run build:release` hanya untuk pengesahan keluaran/pelaksanaan. Binaan CI ialah
isyarat rentas platform muktamad; perubahan Electron khusus platform memerlukan binaan berfokus yang sepadan
atau bukti ujian ringkas.

## Skrip pembangun untuk mesin kongsi

Dua pembantu `scripts/dev/` mengekodkan kitaran setempat pada devbox yang mempunyai sesi aktif lain:

```bash
scripts/dev/typecheck-touched.sh --base release/vX.Y.Z   # fail daripada merge-base(HEAD, base)..HEAD
scripts/dev/typecheck-touched.sh src/a.ts tests/unit/b.test.ts   # fail-fail ini sahaja
scripts/dev/new-worktree.sh fix/1234-slug release/vX.Y.Z  # worktree terpencil, selamat secara selari
```

- `typecheck-touched.sh` menyemak jenis hanya bagi fail `.ts/.tsx` yang disentuh melalui
  `tsconfig.touched.tmp.json` sementara (`extends ./tsconfig.json`, `types: ["node"]`, `noEmit`,
  `incremental: false`) dengan heap 6 GB, jadi ia menggantikan `tsc -p tsconfig.json` seluruh projek
  yang mengalami OOM pada mesin dengan beban tinggi. Ia mencetak ralat dalam fail yang disentuh serta
  satu baris ringkasan dan keluar dengan `1` bagi ralat dalam fail yang disentuh, `2` apabila ralat
  hanya terdapat dalam fail yang diimport atau tsc terhenti tanpa diagnostik (baca log yang dinamakannya
  di bawah `_artifacts/typecheck-touched/`), `0` apabila tiada ralat. tsconfig sementara sentiasa
  dialih keluar; jangan sekali-kali melakukan commit terhadapnya.
- `new-worktree.sh` menyusun jalanan serentak secara bersiri pada
  `<git-common-dir>/omniroute-new-worktree.lock` (menunggu sehingga 600 s secara lalai, dengan mesej
  yang dapat dilihat; pengepala skrip mendokumenkan penggantian) dan mengembalikan perubahan pada
  branch yang diciptanya apabila `git worktree add` gagal sebelum worktree wujud, jadi percubaan semula
  tidak memerlukan `git branch -D` secara manual. `node_modules` yang dipaut keras dan salinan
  `.husky/_` tidak berubah.

## Kitaran calon setempat

Ujian sumber tidak dapat membuktikan bahawa artifak yang dipakejkan boleh dimulakan: senarai
pemakejan, kebergantungan yang dipangkas dan binari natif hanya gagal setelah tarball dipasang dan
dimulakan. `npm run dev:candidate` (`scripts/dev/candidate.mjs`) ialah bahagian setempat bagi aliran
bina sekali / sahkan / promosikan daripada RFC #8084: ia membina satu calon, mengesahkan artifak yang
tepat itu, mempromosikannya melalui penamaan semula direktori dan mengembalikan perubahan apabila
slot yang dipromosikan gagal dalam semakan kesihatannya.

```bash
npm run dev:candidate -- run --dry-run --json  # cetak pelan, jangan ubah apa-apa
npm run dev:candidate -- run                   # bina + sahkan + promosikan, kembali secara automatik
npm run dev:candidate -- build                 # npm pack + pasang ke dalam _artifacts/candidate/<id>/
npm run dev:candidate -- validate --id <id>    # mulakan pada port bebas, /api/health + /v1/models
npm run dev:candidate -- promote --id <id>     # <id> → current, current → previous
npm run dev:candidate -- rollback              # tukar ganti current dan previous
npm run dev:candidate -- run --from-tarball <file.tgz>  # gunakan semula tarball yang dibina di tempat lain (CI)
```

- **Bina sekali.** `build` membungkus pepohon semasa (ia memerlukan `dist/server.js`, jadi jalankan
  `npm run build:release` terlebih dahulu) atau menyalin `--from-tarball`, kemudian memasang tarball
  ke dalam awalan npm yang terpencil kerana tarball tidak mengandungi `node_modules`. Id ialah sha
  pendek `HEAD` (`-dirty` apabila pepohon mempunyai perubahan setempat) atau `tgz-<sha256>` untuk
  tarball. Id bersih yang sudah dibina akan digunakan semula dan bukannya dibina semula; gunakan
  `--force` untuk membinanya semula.
- **Sahkan pakej, bukan sumber.** `validate` memulakan CLI yang dipasang
  (`serve --port <free port>`) dengan `DATA_DIR=<candidate>/data` baharu, rahsia palsu serta
  `OMNIROUTE_API_KEY`, `STORAGE_ENCRYPTION_KEY` dan `INITIAL_PASSWORD` milik pengendali dialih keluar
  daripada persekitaran supaya ia menyemak postur gelung balik tanpa kunci bagi pemasangan baharu.
  Ia menunggu `GET /api/health` mengembalikan 200, mewajibkan `GET /v1/models` mengembalikan 200,
  menghentikan kumpulan proses dan merekodkan keputusan dalam `validation.json` bersama-sama hash
  tarball.
- **Promosikan artifak yang sama.** `promote` menolak calon tanpa pengesahan yang lulus untuk hash
  tarball semasanya. Slot aktif lalai ialah `_artifacts/candidate/current`; `--target <dir>` memilih
  direktori lain pada sistem fail yang sama dan slot terdahulunya ialah `<dir>.previous`.
  Setiap penamaan semula adalah atomik dan kegagalan di pertengahan proses akan membalikkan penamaan
  semula yang telah dijalankan.
- **Kembalikan perubahan.** `run` mengesahkan semula slot yang dipromosikan dan menukar ganti
  `current` dengan `previous` kembali apabila semakan tersebut gagal. Calon yang gagal dalam
  pengesahan pertama tidak akan dipromosikan.

Semuanya ditulis di bawah `_artifacts/candidate/` yang diabaikan oleh git; pemasangan OmniRoute
sedia ada dan direktori datanya tidak pernah disentuh. CLI yang dipromosikan ialah
`_artifacts/candidate/current/prefix/bin/omniroute`; mulakannya dengan `DATA_DIR` anda sendiri apabila
anda menggunakannya. Kod keluar: `0` berjaya, `1` pengesahan atau promosi gagal, `2` ralat penggunaan
atau binaan tiada.

## Gelung setempat berbanding CI

| Jalankan secara setempat untuk setiap tampalan                                                | CI menyediakan isyarat menyeluruh                                                   |
| --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Ujian tingkah laku langsung dan get kategori di atas                                          | Set unit penuh yang dibahagikan dan ujian bersiri                                   |
| `npm run lint`                                                                                | Set Vitest dan mekanisme ratchet liputan/kualiti                                    |
| Semakan jenis atau binaan hanya apabila kontrak yang terjejas memerlukannya                   | Binaan produksi, keselamatan, dokumentasi, kebergantungan dan get dasar PR          |
| Interaksi manual/semakan langsung hanya apabila automasi tidak dapat membuktikan tingkah laku | Semakan integrasi antara tugas dan platform yang dikonfigurasikan oleh aliran kerja |

Gelung terfokus yang berjaya ialah bukti tentang kontrak yang diubah, bukan jaminan bahawa semakan CI yang tidak berkaitan
akan lulus. Sebaliknya, jangan biarkan setiap suntingan setempat perlu menunggu keseluruhan matriks repositori.

## Senarai semak penyelarasan

Sebelum meminta semakan:

- Sahkan bahawa asas PR masih merupakan cabang `release/v*` aktif yang tertinggi.
- Ambil asas tersebut dan semak komit yang telah dimasukkan sejak anda mencipta cabang.
- Semak `git diff <active-base>...HEAD` untuk perubahan tidak sengaja atau yang dijana.
- Selesaikan konflik katalog dan dokumen dijana dengan mengemas kini sumber dan menjana semula output.
- Jalankan semula setiap ujian/get terfokus yang disenaraikan dalam perihalan PR selepas penyelarasan.
- Jangan sekali-kali melonggarkan penegasan atau menggugurkan ujian yang diperlukan semata-mata untuk dipadankan dengan asas yang telah berubah.

Untuk peraturan pembekuan keluaran dan penyasaran semula, gunakan
[Model Percabangan & Keluaran](BRANCHING_MODEL.md). Untuk inventori CI yang lengkap, gunakan
[Rujukan Get Kualiti](../architecture/QUALITY_GATES.md).
