`copilot-m365-web` (alias `m365copilot`) menghantar permintaan sembang format OpenAI melalui sesi Microsoft 365 Copilot yang disahkan di `m365.cloud.microsoft/chat`. Ini ialah integrasi asli tidak rasmi: tiada proses proksi berasingan atau localhost huluan diperlukan. Pembekal ID, alias dan sambungan import sedia ada tidak berubah. `copilot-web` ialah pembekal yang berbeza untuk perkhidmatan pengguna di `copilot.microsoft.com`.

> **Baru kepada pembekal Kuki Web?**
>
> Baca**`docs/getting-started/WEB-COOKIE-GUIDE.md`** untuk proses persediaan umum, panduan pengesahan, pengehadan dan penyelesaian masalah sebelum mengikuti panduan khusus pembekal ini.
>
> **Untuk import warisan:** Tauliah untuk pembekal ini ialah** bukan biskut** . Jangan salin cookies dari `m365.cloud.microsoft`. Bukti kelayakan ialah parameter pertanyaan WebSocket URL dan segmen laluan, kedua-duanya dibaca daripada tab Rangkaian DevTools.

## Prasyarat

- Akaun Microsoft 365 dengan akses kepada Copilot di `m365.cloud.microsoft/chat`
- Penyemak imbas berasaskan Chromium (Chrome, Edge) untuk pemeriksaan DevTools WebSocket
- Akses kepada model yang diminta pada akaun itu; ketersediaan berbeza mengikut penyewa dan lesen

## Log masuk asli (akaun kerja atau sekolah)

pilih**Microsoft 365 Copilot → Sambung** dan sediakan percubaan log masuk. Papan pemuka menggunakan aliran kod kebenaran dengan PKCE; ia tidak meminta kata laluan Microsoft atau kod MFA anda.

1. Buka a** tab pelayar kosong** , kemudian buka**DevTools → Rangkaian** dan membolehkan** Simpan log** . Lakukan ini sebelum menavigasi ke Microsoft: Windows SSO boleh selesai serta-merta.
2. Salin URL kebenaran yang ditunjukkan oleh dialog sambungan dan navigasi ke sana dalam tab yang disediakan itu. Lengkapkan pemilihan akaun Microsoft atau MFA jika diminta.
3. Dalam log Rangkaian yang dipelihara, cari permintaan untuk `https://login.microsoftonline.com/common/oauth2/nativeclient` dan salin sepenuhnya** Minta URL** .
4. Tampal URL itu ke dalam dialog sambungan dan sambungkan. Jangan tampal kod mentah atau bar alamat `wrongplace` terakhir URL: panggilan balik yang diperlukan ialah navigasi sementara.

Setiap percubaan tamat tempoh selepas sepuluh minit dan boleh digunakan sekali sahaja. Pelayan menyemak keadaan, pengesah PKCE dan sasaran pengesahan semula sebelum menukar kod. Selepas tamat tempoh atau kegagalan pertukaran, mulakan percubaan baharu. Percubaan tidak dapat bertahan dari permulaan semula pelayan.

Token menggunakan stor bukti kelayakan sambungan sedia ada dan laluan muat semula. Mengesahkan semula sambungan memerlukan identiti Microsoft tenant/object yang sama, bukan hanya e-mel yang sama. Ia mengekalkan naming/settings pengendali dan menggantikan kelayakan yang diimport usang. Log masuk asli adalah untuk akaun work/school ; laluan import warisan kekal tersedia untuk sambungan sedia ada dan konfigurasi peringkat yang disokong.

URL panggil balik penuh ialah bukti kelayakan sekali sahaja. Jangan sekali-kali masukkannya dalam tangkapan skrin, log, mesej sokongan atau komitmen. Aliran ini tidak membuka penyemak imbas pada pelayan, memeriksa sejarah penyemak imbas anda atau memulakan pelayan panggil balik setempat.

## Tangkapan kelayakan ( kaedah WebSocket )

1. Log masuk di `https://m365.cloud.microsoft/chat` dan mulakan perbualan.
2. Buka**DevTools → Rangkaian** .
3. Tapis mengikut**WS** (WebSocket).
4. Klik sambungan Chathub WebSocket. Cari URL yang bermula dengan `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Daripadanya** Minta URL** , salinan:
   - Nilai parameter pertanyaan `access_token` ( JWT jangka pendek).
   - Segmen laluan Chathub selepas `/Chathub/` (cth `<oid>@<tenant>`).

URL penuh mempunyai bentuk:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Dalam OmniRoute, pilih**Microsoft 365 Copilot** , pilih pilihan API-key/import lama, dan tampal bukti kelayakan dalam format:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. klik** Sambungan Ujian** dan** Jimat** .

## Tangkapan kelayakan (HAR import)

Daripada menyalin nilai secara manual daripada WebSocket URL, anda boleh mengeksport fail DevTools HAR :

1. Buka**DevTools → Rangkaian** .
2. Mulakan atau teruskan perbualan Microsoft 365 Copilot (ini mencetuskan sambungan WebSocket ).
3. Klik kanan dalam panel Rangkaian dan pilih** Simpan semua sebagai HAR dengan kandungan** .
4. Dalam OmniRoute, gunakan** Import fail .har** butang pada dialog sambungan pembekal.

OmniRoute mengimbas HAR untuk Chathub WebSocket URL, mengekstrak `access_token` dan `chathubPath`, dan mengisi medan kelayakan secara automatik. Import HAR menyahkod tamat tempoh JWT dan menunjukkan baki hayat token.

> **Jangan sekali-kali melakukan eksport HAR sebenar, token akses atau token muat semula.** Nilai ujian dan dokumentasi mestilah sentiasa menjadi pemegang tempat.

## Token seumur hidup dan segar semula

`access_token` adalah jangka pendek (biasanya**~ 75 minit** ). Tanpa token muat semula yang boleh digunakan, anda mesti menangkap semula kelayakan selepas tamat tempoh.

### Muat semula automatik dengan `refreshToken`

Dalam pembekal Microsoft 365** Tambah sambungan** atau** Edit sambungan** dialog, buka** Token Segar Semula → Tetapan Lanjutan (pilihan)** . Tampalkan token muat semula Microsoft OAuth untuk skop `substrate.office.com/sydney` dan simpan. Input bertopeng dan tidak pernah diisi terlebih dahulu dengan token yang disimpan. Apabila mengedit, biarkan kosong untuk menyimpan token sedia ada; tampal token baharu untuk menggantikannya.

Log masuk asli memperoleh token muat semula apabila Microsoft mengembalikan satu. Untuk import warisan, gunakan geran kod kebenaran Microsoft sedia ada yang serasi; pembekal ini tidak melaksanakan atau menjanjikan aliran kod peranti. Dengan token muat semula yang dikonfigurasikan, OmniRoute menyemak `access_token` sebelum permintaan dan menyegarkannya hanya apabila ia memerlukan penyegaran. Muat semula yang berjaya juga mengekalkan token muat semula yang diputar, mengelakkan tangkapan semula manual sementara token muat semula kekal sah.

Jika `refreshToken` tidak ditetapkan, anda mesti menangkap semula kelayakan WebSocket secara manual selepas setiap tamat tempoh.

| Peringkat    | Alias      | Permukaan                |
| ------------ | ---------- | ------------------------ |
| `individual` | _(lalai)_  | Pengguna M365 Copilot    |
| `edu`        | `included` | Pendidikan M365 Copilot  |
| `enterprise` | `work`     | M365 Copilot untuk Kerja |

Tetapkan peringkat itu** Tetapan Lanjutan → Copilot tier** . Log masuk asli tidak menetapkannya, jadi akaun kerja mesti memilih `enterprise` (alias `work`) dan akaun pendidikan `edu`, juga apabila menggunakan model yang didokumenkan IDs: mereka memilih nada, senario dan jenis lesen mereka sendiri, tetapi pilihan ejen dan invokasi masih datang dari peringkat, dan lalai individu boleh gagal pada penyewa kerja. Menukar peringkat tidak memberikan lesen model. Penggantian protokol lanjutan yang eksplisit diutamakan dan hanya boleh digunakan apabila anda mengetahui nilai wayar yang diperlukan.

## Model dan penghalaan

Katalog asli termasuk semua IDs kendiri yang didokumenkan serta empat IDs asli asli . Katalog adalah statik dan bebas akaun, bukan siasatan kelayakan akaun: laluan berbayar dan alias keserasian kekal disenaraikan walaupun akaun yang disambungkan tidak boleh menggunakannya. Label paparan model meninggalkan nama pembekal dan plat dandang ketersediaan setiap model; pembekal kekal**Microsoft 365 Copilot** . Label ditanda** Alias** atau** Legasi** mengekalkan pengecam sedia ada dan pemetaan protokol, bukan jaminan versi model sejarah. Proksi kendiri** Import daripada /models** arahan tidak digunakan untuk pembekal WebSocket asli ini.

| Keluarga model    | IDs kanonik                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| Automatik         | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| Tadi GPT          | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude Sonnet     | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude Opus       | `claude-opus`, `claude-opus-4.8`                                                                 |

Alias seperti `auto`, `quick`, `think-deeper` dan alias versi juga didaftarkan. `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` dan `copilot-m365-gpt-5-5-chat` sedia ada kekal sah. IDs yang didokumenkan memerlukan awalan penyedia (`copilot-m365-web/claude-opus` atau `m365copilot/claude-opus`): kebanyakannya adalah perkataan generik atau nama model vendor lain, jadi `claude-opus` kosong terus menghala seperti yang dilakukan tanpa penyedia ini. Pendaftaran bukan janji bahawa Microsoft menyediakan model itu kepada setiap akaun. IDs kendiri mengikut [katalog protokol](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) awam (peta model-ke-nada yang dieksport dan metadata senario sedar modelnya). Semua profil asli mengekalkan `availability: "unverified"`; kemasukan dalam katalog bukanlah ujian akaun yang berjaya.

- Penolakan lesen model eksplisit kembali** 403** `m365_model_not_licensed`, bukan 502. Penghalaan mengunci pasangan connection/model itu, menjadikan model berlesen pada sambungan boleh digunakan.
- `InvalidCopilotLicense` ialah penolakan lesen peringkat akaun, dilaporkan secara berasingan sebagai `m365_account_not_licensed`.
- Pendikit setiap pengguna kembali** 429** `m365_throttled` dan menyejukkan sambungan. Kehausan akses keutamaan kembali** 429** `priority_access_exhausted` dan berskop model. Hasil daripada `OutOfCredits` dengan `errorCode: "ReasoningTurnExhausted"` kembali** 429** `reasoning_turns_exhausted` sebaliknya, juga berskop model, tanpa masa penetapan semula dituntut. Ia telah dilaporkan pada satu penyewa kerja untuk mengehadkan nada "Think deeper" manakala nada Quick terus berkhidmat; skop itu adalah pemerhatian pengguna, bukan sesuatu yang telah dihasilkan semula oleh repositori ini. Oleh itu, penghalaan juga mengambil model Think deeper lain yang didokumentasikan bagi `gpt-5.5` dan `gpt-5.6` daripada putaran pada sambungan itu untuk cooldown yang sama, dan meninggalkan nada Pantas dan setiap kegagalan lain pada modelnya sendiri. Petua cuba semula yang dibekalkan disimpan; tetapan semula yang hilang tidak diiklankan sebagai masa tetapan semula yang diketahui.
- Penolakan keselamatan Copilot (`Disengaged`) kembali** 400** `provider_safety_rejection`, label hentian keselamatan pembekal dikongsi. Ia tidak pernah dikira terhadap kesihatan sambungan, pelanggan SDKs tidak mencuba semula 400, dan dengan penghalaan kombo didayakan `PROVIDER_SAFETY_STOPS_TERMINAL` berhenti di sana dan bukannya memainkan semula permintaan terhadap sasaran lain.
- Permintaan pada satu sambungan bersiri melalui semaphore akaun sedia ada. Mengutamakan sandaran keutamaan daripada panel selari; siri sahaja tidak menghapuskan had kadar perbualan Microsoft.

## Permintaan tingkah laku dan had

- Alat adalah** segera dicontohi** , bukan panggilan fungsi Microsoft asli. Permintaan yang didayakan alat menggunakan satu generasi penimbal; ia tidak menghabiskan generasi lain memilih alat. Hanya alat yang diisytiharkan dengan bentuk hujah yang disokong yang sah dikembalikan sebagai panggilan.
- Jawapan berstruktur panjang dengan satu contoh mengekor dikekalkan sebagai prosa. Ini adalah heuristik, bukan bukti niat; aplikasi masih mesti menguatkuasakan kebenaran alat mereka sendiri.
- Input imej berfungsi seperti cara klien web menghantarnya. Setiap bahagian imej (`image_url` sebagai data URL atau HTTPS awam URL, atau Responses `input_image`) dimuat naik ke `/m365Copilot/UploadFile` ke dalam perbualan giliran dengan token sembang dan mesej menghalakannya dengan anotasi `ImageFile` ; teks menandakan tempat ia duduk (`[image 1]`, …). Perbualan baharu memuat naik setiap imej dalam sejarah, yang berterusan hanya imej mesej baharu. Sehingga 10 PNG, JPEG, GIF atau WebP imej paling banyak 10 MiB setiap satu (40 MiB setiap permintaan); format dibaca daripada bait. HTTPS URLs diambil melalui pengawal imej jauh yang disematkan DNS awam sahaja. Muat naik yang gagal gagal permintaan (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` atau `m365_image_invalid`); giliran tidak akan berlaku tanpa imej yang diberikan. Bahagian bukan teks lain (audio, fail) ditolak secara eksplisit, bukan digugurkan secara senyap.
- Permintaan susulan meneruskan perbualan huluan yang sama dan hanya menghantar mesej selepas balasan sebelumnya. Ia mesti memanjangkan balasan itu dengan tepat: sambungan yang sama, profil model dan set alat; sejarah yang tidak berubah (rantai sha256 atas setiap mesej); dan id panggilan alat balasan, atau teksnya sehingga ruang kosong. Perkara lain (sejarah yang diedit, sesi lain dengan mesej pertama yang sama, balasan berbeza, perbualan melahu selama 30 minit atau hampir dengan had 600 mesej Copilot, sambungan tanpa id) memulakan perbualan baharu dengan keseluruhan sejarah. Giliran yang gagal tidak akan disambung semula dan `InternalError` tanpa kandungan dihantar semula sekali dalam perbualan baharu (** 502** `m365_internal_error` jika gagal lagi). Kesinambungan disimpan dalam memori proses: permulaan semula memulakan perbualan baharu.
- Setiap giliran berjalan dalam sembang sementara Copilot(`disableMemory=1`): perbualan mengekalkan konteksnya semasa ia berjalan dan tidak pernah muncul dalam sejarah sembang akaun. Ujian model, Uji Semua dan ujian kombo mungkin menyiasat penyedia ini tanpa meninggalkan perbualan.
- Satu giliran mempunyai tarikh akhir melahu selama 120 saat dan tarikh akhir keseluruhan terhad. Jawapan akhir sahaja, penapisan kemajuan dan pembatalan dikendalikan oleh transport/composer. asli
- Jawapan berasaskan web mengekalkan sumbernya. Copilot menandakan petikan sebaris dengan aksara kawalan penggunaan persendirian dan menghantar sumber sebagai `references`; setiap penanda menjadi pautan Markdown bernombor (`[1](https://…)`, atau URL kosong apabila Copilot menggunakan penanda sebagai sasaran pautan) dengan anotasi `url_citation` yang sepadan (`message.annotations`, atau `delta.annotations` pada bongkah yang membawa pautan). Sumber yang tidak pernah tiba digugurkan, jadi penanda tidak pernah sampai kepada pelanggan. Semasa penstriman, teks selepas petikan menunggu sehingga sumbernya tiba.
- ringkasan penaakulan Copilot(`ChainOfThoughtSummary`), apabila model menghantar satu, dikembalikan sebagai `reasoning_content`, tidak sekali-kali sebagai sebahagian daripada jawapan. Ringkasan yang menulis semula dirinya berhenti menstrim tanpa gagal pusingan.
- Sebelum sebarang kandungan, kegagalan licence/throttle mengekalkan HTTP 403/429 walaupun semasa penstriman diminta. Selepas kandungan dimulakan, kegagalan ialah peristiwa ralat SSE, bukan penamat yang berjaya. Tulisan semula huluan yang tidak boleh diwakili oleh penstriman tambahan sahaja ialah ralat strim yang jelas; respons alat bukan penstriman dan penimbal mengekalkan teks akhir.
- Apabila Copilot menolak sambungan itu sendiri, jawapannya dilaporkan seperti berikut:** 401** `m365_unauthorized` untuk log masuk yang ditolak atau tamat tempoh (log masuk semula),** 429** dengan `Retry-After` untuk pendikitan, dan kegagalan jabat tangan jika tidak, tidak sekali-kali kegagalan sambungan generik.

## Penjanaan imej

`POST /v1/images/generations` dengan `model: "copilot-m365-web/m365-copilot-image"` (alias `m365copilot/m365-copilot-image`) melukis dengan alat imej terbina dalam Copilot, seperti yang dilakukan oleh pelanggan web. Setiap imej ialah satu pusingan Copilot : ia mengikut serta dengan set pilihan imej klien web dan mengisytiharkan `GenerateGraphicArt`, dan imej itu tiba pada entri kemajuan yang menunjuk pada artifak pada perkhidmatan Designer Microsoft. Artifak itu menolak token sembang, jadi OmniRoute mencetak token Designer daripada token segar semula sambungan dan memuat turun bait; token hanya dihantar kepada `designerapp.officeapps.live.com`.

- Memerlukan sambungan log masuk asli (token segar semula); token yang ditampal gagal dengan** 400** sebelum apa-apa giliran dihabiskan.
- `n` ialah 1–4, setiap satu pusingan. `size` hanya mengemudi orientasi (lebih luas, lebih tinggi atau persegi), yang dibaca oleh Copilot daripada gesaan; Copilot memilih saiz pemaparan.
- Imej dikembalikan sebaris: `b64_json` secara lalai, URL data untuk `response_format: "url"`.
- Imej yang dijana menggunakan belanjawan harian yang kecil, berasingan daripada sembang. Apabila ia digunakan, permintaan gagal dengan** 429** . Giliran yang menjawab tanpa imej gagal** 502** (atau** 400** /** 503** apabila teks Copilot dibaca sebagai penolakan atau masalah kapasiti); mesej itu mengatakan yang.

## Model keselamatan

- **Integrasi tidak rasmi.** Penyedia ini merekayasa balik protokol BizChat WebSocket. Ia mungkin pecah tanpa notis apabila Microsoft menukar titik akhir.
- Bendera `subscriptionRisk: true` menggambarkan bahawa penyepaduan bergantung pada titik akhir yang tidak didokumenkan. Sekatan akaun adalah mungkin tetapi tidak disahkan.
- Token akses ialah JWT jangka pendek. Anggap ia seperti kata laluan: jangan komit, log atau kongsikannya.
- Token segar semula memberikan akses berterusan ke permukaan Microsoft 365. Simpannya dengan penjagaan yang sama seperti kunci API.

## Menyelesaikan masalah

### Pengesahan gagal serta-merta

- Sahkan anda menyalin daripada**WebSocket URL** , bukan daripada permintaan XHR/Fetch. Bukti kelayakan berada dalam parameter pertanyaan `access_token` bagi sambungan WebSocket Chathub — bukan dalam pengepala `Authorization: Bearer`.
- Pastikan `chathubPath` termasuk segmen `<oid>@<tenant>` penuh dari laluan URL.

### Token tamat tempoh selepas ~ 75 minit

Ini dijangka. Tanpa `refreshToken`, token akses adalah jangka pendek. sama ada:

- Tangkap semula bukti kelayakan daripada DevTools, atau
- Konfigurasikan** Token Segar Semula → Tetapan Lanjutan (pilihan)** dalam dialog Tambah atau Edit sambungan untuk muat semula automatik.

### Sambungan Ujian lulus tetapi sembang mengembalikan 401

Untuk sambungan yang dibuat dengan** Log masuk dengan Microsoft** , Sambungan Ujian menyemak tamat tempoh token akses dan memperbaharui token yang telah tamat tempoh dengan token muat semula yang disimpan, jadi ujian yang lulus juga membuktikan token muat semula masih berfungsi.

Untuk bukti kelayakan yang ditampal, Sambungan Ujian menyemak bentuk bukti kelayakan dan, apabila token membawa tamat tempoh, token yang akan digunakan oleh pembekal belum tamat tempoh (token yang disimpan sambungan memenangi tampalan basi; token muat semula dikira sebagai boleh diperbaharui). Token yang dibatalkan sebelum tamat tempoh masih lulus ujian; sembang kemudian kembali** 401** `m365_unauthorized`. guna** Log masuk dengan Microsoft** sekali lagi, atau tangkap semula bukti kelayakan baharu.

### Copilot tidak muncul dalam senarai pembekal

Pastikan `copilot-m365-web` didayakan dalam** Pembekal → papan pemuka** . Pembekal mungkin disembunyikan secara lalai dalam beberapa peringkat.
