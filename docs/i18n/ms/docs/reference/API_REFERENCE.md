Alat yang mengimport fail yang dimuat turun tidak mempunyai hos sedemikian dan memerlukan URL asas ditetapkan secara manual.

## Pelengkapan Sembang

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Pengepala Tersuai

| Header                   | Arah       | Penerangan                                                                                                                                                                                                                    |
| ------------------------ | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | Permintaan | Tetapkan kepada `true` untuk memintas cache                                                                                                                                                                                   |
| `x-omniroute-no-memory`  | Permintaan | Tetapkan kepada `true` untuk melangkau suntikan memori + kemahiran bagi permintaan ini (mencerminkan no-cache; mengelakkan overhed token/kos setiap panggilan)                                                                |
| `X-OmniRoute-Progress`   | Permintaan | Tetapkan kepada `true` untuk peristiwa kemajuan                                                                                                                                                                               |
| `X-Session-Id`           | Permintaan | Kunci sesi lekat untuk afiniti sesi luaran                                                                                                                                                                                    |
| `x_session_id`           | Permintaan | Varian garis bawah juga diterima (HTTP langsung)                                                                                                                                                                              |
| `X-OmniRoute-Session-Id` | Permintaan | Tag sesi/perbualan yang dibekalkan pemanggil (juga disalurkan kepada memori). Apabila hadir, disimpan secara verbatim ke `call_logs.session_tag` untuk atribusi kos mengikut sesi (#8249) — tidak pernah dijana apabila tiada |
| `Idempotency-Key`        | Permintaan | Kunci deduplikasi (tetingkap 5s)                                                                                                                                                                                              |
| `X-Request-Id`           | Permintaan | Kunci deduplikasi alternatif                                                                                                                                                                                                  |
| `x-omniroute-connection` | Permintaan | Ikat permintaan model tunggal kepada satu sambungan penyedia (akaun) mengikut idnya — lihat [Pengikatan akaun bagi setiap permintaan](#account-pinning-per-request)                                                           |
| `X-OmniRoute-Cache`      | Respons    | `HIT` atau `MISS` (bukan penstriman)                                                                                                                                                                                          |
| `X-OmniRoute-Idempotent` | Respons    | `true` jika dideduplikasi                                                                                                                                                                                                     |
| `X-OmniRoute-Progress`   | Respons    | `enabled` jika penjejakan kemajuan diaktifkan                                                                                                                                                                                 |
| `X-OmniRoute-Session-Id` | Respons    | ID sesi berkesan yang digunakan oleh OmniRoute                                                                                                                                                                                |
| `X-OmniRoute-Request-Id` | Respons    | ID korelasi permintaan (apabila diketahui)                                                                                                                                                                                    |
| `X-OmniRoute-Version`    | Respons    | Versi binaan OmniRoute (sentiasa hadir)                                                                                                                                                                                       |
| `X-OmniRoute-Cost-Saved` | Respons    | USD yang dijimatkan oleh cache pada `HIT` (hanya cache hit)                                                                                                                                                                   |
| `X-OmniRoute-Decision`   | Respons    | Jejak penghalaan: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` ialah strategi gabungan, atau `single` untuk permintaan bukan gabungan) — sentiasa hadir pada respons penyelesaian                            |

> Nota Nginx: jika anda bergantung pada pengepala garis bawah (contohnya `x_session_id`), dayakan `underscores_in_headers on;`.

#### Pengikatan akaun bagi setiap permintaan

Apabila penyedia mempunyai beberapa sambungan (akaun atau kunci), OmniRoute biasanya memilih salah satu
melalui strategi pemilihan akaunnya. Sebaliknya, permintaan boleh mengikat satu sambungan tertentu
dengan pengepala `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Tempat untuk mencari id.** Buka halaman penyedia dalam papan pemuka
  (**Dashboard → Providers → <provider>**) dan klik cip id `xxxxxxxx…` pada baris sambungan —
  ia menyalin id sambungan penuh.
- **Permintaan yang menghormatinya.** Permintaan model tunggal (`provider/model`) pada
  `/v1/chat/completions`, `/v1/messages` dan `/v1/responses`. Gabungan mengabaikan pengepala ini:
  tetapkan akaun bagi setiap langkah gabungan melalui sambungan langkah itu sendiri.
- **Pin adalah ketetapan, bukan keutamaan.** Sambungan yang dipinkan digunakan secara eksklusif. Jika
  berlaku kegagalan dalam permintaan, ia merekodkan tempoh penyejukan akaun tetapi **tidak** beralih
  kepada akaun lain daripada penyedia yang sama.
- **Tempoh penyejukan dan kuota melepaskan pin.** Selagi sambungan yang dipinkan dalam tempoh
  penyejukan, kehabisan kuota atau disekat oleh dasar kuota, permintaan seterusnya akan beralih kepada
  sambungan lain penyedia, sama seperti trafik tanpa pin.
- **Id yang tidak diketahui atau dilumpuhkan akan gagal.** Id yang tiada dalam kumpulan aktif penyedia
  (dipadamkan, dinyahaktifkan atau milik penyedia lain) tidak meninggalkan akaun yang layak, maka
  permintaan gagal dan bukannya dihalakan secara senyap ke tempat lain.

Claude Code menghantar pengepala tersuai melalui `ANTHROPIC_CUSTOM_HEADERS`. Letakkannya dalam blok
`env` bagi `~/.claude/settings.json`, atau dalam `.claude/settings.json` peringkat projek untuk
menetapkan akaun yang berbeza bagi setiap projek:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Sumber: `src/sse/handlers/chat.ts` (pembacaan pengepala), `src/sse/services/auth.ts` dan
`src/sse/services/sessionAffinityPin.ts` (pelepasan pin dan semakan sambungan yang tiada dalam kumpulan).

> **Pengepala telemetri kos:** respons berjaya tanpa penstriman turut membawa set telemetri kos `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, tetap 10 tempat perpuluhan; `0.0000000000` untuk percuma/tanpa harga), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` dan `X-OmniRoute-Fallback-Attempts` (hanya apabila > 0), serta `X-OmniRoute-Request-Id` dan `X-OmniRoute-Version`. Semua ini dijana oleh penyempurnaan chat, `/v1/responses`, `/v1/messages`, **dan titik akhir media** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` dan `/v1/moderations` (sentiasa dengan kos `0`). Kos media dikira mengikut modaliti (setiap imej, setiap saat, setiap aksara, setiap unit carian) apabila harga tersedia, jika tidak `0` (gagal terbuka).

> **Semantik kos capaian cache:** pada HIT cache semantik (`X-OmniRoute-Cache-Hit: true`), tiada panggilan huluan dibuat, maka `X-OmniRoute-Response-Cost` ialah `0.0000000000` (kos **tambahan** untuk menyediakan capaian tersebut). Kos asal/yang sepatutnya berlaku dilaporkan secara berasingan dalam `X-OmniRoute-Cost-Saved`. Pengguna pengebilan hendaklah menjumlahkan `X-OmniRoute-Response-Cost` (capaian cache tidak berkos); analitik cache boleh mengagregatkan `X-OmniRoute-Cost-Saved`.

## Pajakan Sesi Terurus Eksklusif

Pajakan sesi terurus eksklusif ialah kontrak penghalaan yang bersifat pilihan dan neutral terhadap klien: satu pemilik aktif
memegang satu sambungan OmniRoute yang layak. Ia tidak memajak model, memerlukan OAuth, mengenal pasti
klien tertentu, atau memerlukan pembekal tertentu.

Kunci API yang mengesahkan mestilah mempunyai skop `lease:exclusive` dan senarai `allowedConnections` yang jelas serta tidak kosong. Sempadan mutasi pangkalan data menguatkuasakan kedua-dua medan ini secara bersama semasa penciptaan kunci dan kemas kini separa.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Respons pemerolehan, pembaharuan dan pelepasan yang berjaya mendedahkan cap masa, `state`, dan
`generation` positif yang tepat, tetapi tidak pernah mendedahkan sambungan atau kelayakan yang dipilih. Pembaharuan dan pelepasan membekalkan
generation dalam badan JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Pemilik pajakan aktif boleh meminta metadata paparan yang selamat dari segi privasi secara jelas untuk binding semasanya:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Tindakan status pilihan ini dipagari oleh pemilik legap, kunci API terurus yang disahkan, dan generasi aktif yang tepat dalam satu transaksi pangkalan data. `displayName` hanyalah nama sambungan yang dikonfigurasikan dan telah dipangkas; nilainya ialah `null` apabila tiada nama dikonfigurasikan yang selamat tersedia. OmniRoute tidak pernah menggantikan nama tersebut dengan e-mel atau identiti akaun yang dijana. Nilai pembekal ialah label paparan yang tidak sensitif dan tidak pernah menjadi pengecam pembekal serasi yang dijana. Kelayakan, token, kuki, id sambungan atau kunci API mentah, cincangan pemilik, rahsia pemagaran, dan data penghalaan dalaman tidak disertakan.

Carian dengan kunci yang salah, pemilik yang salah, generasi lapuk, pajakan yang tiada, tamat tempoh, telah dilepaskan, atau telah dibatalkan semuanya mengembalikan ralat `409 LEASE_FENCE_STALE` yang sama tanpa metadata sambungan. Klien yang menerima respons menunggu kapasiti tidak mempunyai binding aktif untuk diperiksa. Apabila penghalaan mengalihkan pajakan aktif, generasi yang sama kekal sah dan status secara atom mengembalikan binding baharu, tidak pernah binding lama. Klien sedia ada kekal tidak berubah kerana respons pemerolehan, pembaharuan, pelepasan dan menunggu mengekalkan bentuk sebelumnya.

Kontrak pelayan ini tidak mengubah `/status` OpenAI Codex standard. Codex standard pada masa ini melaporkan
pembekal model serta keadaan pengesahan/akaun terbina dalamnya, tetapi tidak memaparkan metadata akaun
pembekal tersuai sewenang-wenangnya; integrasi klien kemudian mestilah memanggil tindakan ini dan menentukan cara untuk
memaparkan `connection.displayName`.

Setiap permintaan inferens terurus kemudiannya membekalkan kedua-dua pengepala kawalan:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Pemilik, generasi, sambungan aktif dan kunci API yang disahkan yang tepat dipagari serta-merta
sebelum setiap percubaan huluan yang disokong. Mengulangi pemilik dan generasi dengan kunci lain akan gagal walaupun
kunci tersebut membenarkan sambungan yang sama. Pemilik mentah tidak disimpan, dilog, dikekalkan dalam syot kilat
permintaan, atau dihantar ke huluan.

Pertikaian sementara mengembalikan HTTP `429` dengan `Retry-After` dan:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Respons ini hanya bermaksud bahawa set yang layak biasa tidak kosong dan setiap calon yang tersedia
sedang dipegang oleh pajakan aktif asing. Model/pembekal yang tidak disokong, ketidakpadanan dasar, tempoh bertenang, kuota,
kesihatan dan kegagalan kelayakan biasa yang lain mengekalkan respons OmniRoute sedia ada.

### `x-omniroute-compression`

Penggantian setiap permintaan untuk pelan pemampatan. Keutamaan tertinggi — mengatasi penggantian gabungan penghalaan,
profil aktif, pencetus automatik dan Default panel. Nilai:

| Nilai         | Kesan                                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------------------- |
| `off`         | Tiada pemampatan untuk permintaan ini.                                                                        |
| `default`     | Profil Default yang diperoleh daripada panel (mengabaikan profil aktif). Enjin lossy dibiarkan mati.          |
| `safe`        | Dedup dan pelipatan ruang putih sahaja.                                                                       |
| `allow-lossy` | Kekalkan pelan operator untuk permintaan ini, termasuk ringkasan dan penulisan semula gaya.                   |
| `engine:<id>` | Satu enjin apabila didayakan, contohnya `engine:rtk`. Pilihan masuk setiap permintaan untuk enjin tersebut.   |
| `<combo>`     | Gabungan bernama, dipadankan mengikut nama (tidak membezakan huruf besar-kecil) dahulu, kemudian mengikut id. |

Nota:

- Nilai yang tidak diketahui diabaikan (permintaan tidak pernah ditolak); penyelesaian diteruskan mengikut keutamaan operator biasa.
- Jika beberapa gabungan berkongsi nama, berikan **id** gabungan untuk padanan yang deterministik.
- Gabungan yang namanya ialah `off` atau `default` tidak boleh dipilih mengikut nama (kata kunci tersebut ditafsirkan terlebih dahulu); rujuk gabungan sedemikian menggunakan idnya.
- Suis pemampatan induk ialah get tegar: apabila pemampatan dilumpuhkan secara global, pengepala ini tidak boleh mendayakannya.

Pelan yang digunakan dipantulkan kembali dalam pengepala respons:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

yang mana `<source>` ialah salah satu daripada `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, atau `off`.

## Embedding

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Penyedia yang tersedia: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

ID katalog ialah `provider/model` (contoh: `jina-ai/jina-embeddings-v5-omni-small`). ID model Jina tanpa awalan yang muncul dalam pendaftaran (contohnya `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) turut diselesaikan. Embed/rerank/classify/segment Jina menggunakan kelayakan `jina-ai` papan pemuka terlebih dahulu; `JINA_AI_API_KEY` hanya menjadi sandaran apabila tiada kunci papan pemuka. Kad `jina-reader` hanya untuk Reader / `r.jina.ai` (`POST /v1/web/fetch`) dan tidak pernah menyediakan embedding atau rerank.

Model pendaftaran yang mengiklankan sokongan multimodal turut menerima sehingga 32 item berstruktur yang neutral kepada penyedia. Jenis item media ialah `text`, `image`, `audio`, `video`, dan `document`. `source` media tersebut ialah sama ada `{"type":"url","url":"https://..."}` atau
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
dan alias keluarga `jina-ai/jina-embeddings-v5-omni` → omni-small) turut menerima dokumen
EmbeddingsV5Request asli Jina dan **meneruskannya tanpa perubahan** ke `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Nilai asli `{ image | audio | video | pdf }` boleh berupa URL HTTPS awam, URI `data:`, atau
base64 mentah. OmniRoute tidak menukar objek tersebut kepada rentetan atau mengambil URL imej asli — Jina mengambil media awam itu sendiri. Medan Jina tambahan (`task`, `normalized`, `truncate`, `embedding_type`) akan diteruskan. SKU Jina teks sahaja masih menolak dokumen bukan teks.

Had keselamatan dan pengangkutan:

- URL media jauh mestilah HTTPS awam. Item kanonik `{type,source:url}` diambil
  di sisi pelayan (pengesahan semula ubah hala, tamat masa, had saiz, DNS awam, pemautan sambungan) dan disisipkan sebelum panggilan kepada penyedia. Item asli Jina `{image:"https://..."}` diteruskan seperti adanya selepas pemeriksaan HTTPS awam yang sama; Jina mengambil URL tersebut.
- Media base64 sebaris dihadkan kepada 8 MiB selepas dinyahkod bagi setiap item dan 16 MiB selepas dinyahkod merentas permintaan.

Terjemahan penyedia (item kanonik tidak pernah diteruskan tanpa perubahan):

- Model multimodal Jina: setiap item peringkat teratas menjadi satu objek berkunci modaliti
  (`text` / `image` / `audio` / `video` / `pdf`) menggunakan URI data untuk media sebaris; satu vektor bagi setiap item peringkat teratas.
- Keluarga Gemini Embedding 2: satu tatasusunan peringkat teratas menjadi satu permintaan asli `models/{model}:embedContent` dengan `content.parts` (`text` atau `inline_data`).
- llama.cpp (`llama-cpp/<model>`, mana-mana model yang dimuatkan oleh pelayan tempatan): item kanonik `text`
  menjadi rentetan biasa, manakala `image` / `audio` / `video` masing-masing menjadi satu objek
  `{"content": [part]}`, menggunakan bahagian kandungan sembang llama-server (`image_url`,
  `input_audio` dengan format `wav` / `mp3` / `flac`, `input_video`) dengan data sebaris; satu vektor bagi setiap item peringkat teratas. Pelayan mesti dijalankan dengan `--embedding --mmproj …`; tanpa projektor, pelayan itu sendiri menolak media. `document` tidak disokong.
- Model tidak diketahui/dinamik tanpa metadata modaliti yang jelas akan menolak input berstruktur dengan HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Gabungan model/modaliti yang tidak disokong akan mengembalikan HTTP 400 dan bukannya memaksa penukaran item. Medan sambungan bukan input pada permintaan rentetan/token legasi terus diteruskan tanpa perubahan.

```bash
# Senaraikan semua model embedding
GET /v1/embeddings
```

## Penjanaan Imej

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Penyedia yang tersedia termasuk OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (tempatan), ComfyUI (tempatan).

`n` mengembalikan `n` imej dalam `data[]`. Penyedia yang API huluannya mengembalikan satu imej bagi setiap panggilan
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI) menerima `n` panggilan huluan berasingan, dengan maksimum 4 panggilan berjalan serentak. `seed`
yang ditetapkan akan dianjak mengikut indeks panggilan (`seed`, `seed + 1`, …), supaya imej berbeza tetapi kekal boleh dihasilkan semula. `n` dihadkan kepada 10. Permintaan gagal secara keseluruhan jika mana-mana panggilan gagal. Senarai format fan-out ialah `SINGLE_IMAGE_FANOUT_FORMATS` dalam
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux menggunakan semula sambungan kunci API sedia ada dan menerima awalan `zenmux/` atau `zm/`:

- `zenmux/openai/gpt-image-2` menggunakan API OpenAI Images ZenMux. Pilihan termasuk `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background`, dan `response_format`.
- Penerbit lain, seperti `zm/meta/muse-image-1.0`, menggunakan titik akhir Vertex AI `:predict` ZenMux. `n` dipetakan kepada `sampleCount`, `aspect_ratio` kepada `aspectRatio`, dan `image_size`
  (`1K`, `2K`, `4K`) kepada `sampleImageSize`. `size` dalam piksel hanya membekalkan nisbah aspek,
  bukan dimensi piksel yang dijamin. Nisbah, resolusi dan bilangan yang disokong berbeza mengikut model.
- `zm/inclusionai/ming-image-0.1-design` memilih dimensinya sendiri. Abaikan `size`,
  `aspect_ratio`, dan `image_size`; nilai yang dinyatakan secara jelas mengembalikan HTTP 400. PNG, JPEG, dan WebP
  boleh diminta dengan `output_format`.

Integrasi ini menyokong penjanaan teks-ke-imej, bukan penyuntingan imej rujukan. Output Vertex
dinormalkan kepada `data[].b64_json`; `response_format: "url"` mengembalikan URL HTTPS huluan atau URL data base64 apabila hanya bait imej tersedia. Output kosong/ditapis
mengembalikan ralat dan bukannya kejayaan kosong. Akses model bergantung pada akaun ZenMux.
Lihat [API Vertex ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) dan
[API Images OpenAI](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# Senaraikan semua model imej
GET /v1/images/generations
```

  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }

### Aliran tinjauan Azure Document Intelligence

API `analyze` Azure Document Intelligence adalah tak segerak: permintaan awal mengembalikan pengepala
`Operation-Location` dan bukannya badan, dan hasilnya mesti ditinjau. Pengendali
(`open-sse/handlers/ocr.ts`) meninjau URL tersebut setiap saat sehingga 30 percubaan, berhenti dengan segera (tidak
meneruskan tinjauan) apabila respons tinjauan bukan `ok` atau statusnya `"failed"`, dan mengembalikan `504` jika operasi masih berjalan selepas bajet percubaan habis. Respons Azure akhir
dinormalkan kepada bentuk `pages`/`markdown` yang sama seperti yang digunakan oleh Mistral sebelum dikembalikan kepada
pemanggil, jadi kod klien tidak perlu mengendalikan penyedia secara khusus.

### Pengesahan dan penyelesaian titik akhir Vertex AI DeepSeek OCR

`vertex-deepseek-ocr` menggunakan semula pengesahan Vertex AI yang sama yang telah disokong oleh OmniRoute untuk
trafik chat/imej (`open-sse/executors/vertex.ts`): kunci API sambungan sama ada merupakan kelayakan JSON
Akaun Perkhidmatan (ditukar kepada token akses OAuth berjangka pendek melalui aliran JWT-bearer)
atau token akses OAuth yang telah dikeluarkan dan digunakan seadanya. URL titik akhir huluan ialah titik akhir rakan kongsi
generik `openapi/chat/completions` Vertex, yang dibina daripada projek dan rantau sambungan — `providerSpecificData.project`/`providerSpecificData.region` yang dinyatakan secara jelas sentiasa diutamakan;
jika tidak, projek diperoleh daripada `project_id` JSON Akaun Perkhidmatan dan rantau lalai ialah
`us-central1`. Kedua-dua penyelesaian berlaku dalam `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), yang digunakan oleh
`src/app/api/v1/ocr/route.ts` sebelum dihantar kepada `handleOcr`.

### Harga model (`pricing`)

Sesuatu entri membawa objek `pricing` apabila OmniRoute mengetahui harga model tersebut. Harga datang
daripada jadual harga yang digunakan oleh perakaunan kos: lalai terbina dalam, harga yang disegerakkan dan
penggantian yang ditetapkan melalui `/api/pricing`. Ini ialah harga senarai, jadi penyedia langganan juga
memaparkan harga setiap token.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Medan                                                           | Unit                                  | Nota                                                                                                                                                   |
| --------------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | USD setiap token, rentetan perpuluhan | Serasi dengan OpenRouter, tidak pernah dalam notasi eksponen. Dua medan cache hanya muncul apabila terdapat harga cache.                               |
| `input`, `output`, `cached`, `cache_creation`                   | USD setiap 1M token, nombor           | Medan daripada versi katalog terdahulu, dikekalkan untuk klien sedia ada. `reasoning` dan `long_context` juga muncul apabila baris harga mempunyainya. |

- **Gabungan** membawa harga sasaran pertama yang kelihatan. Gabungan `auto/*` terbina dalam memilih
  sasaran semasa permintaan, jadi ia tidak mempunyai `pricing`.
- **Model percuma** memaparkan `"0"` (dan `0`) apabila harganya sifar. Model tanpa baris harga
  juga memaparkan `"0"` apabila katalog menandakannya sebagai percuma (`free: true`) atau katalog
  model percuma terbina dalam menyenaraikannya.
- **Harga tidak diketahui:** entri tersebut tidak mempunyai kunci `pricing`.
- **Penyedia yang diukur berdasarkan kredit** (seperti Kiro) mengebil setiap permintaan dan bukannya setiap token. Entri mereka
  mengekalkan medan berangka setiap-1M yang dimilikinya sebelum ini dan tidak membawa medan rentetan setiap token.
- **Varian** (id usaha penaakulan, alias tanpa pemikiran, cerminan penemuan dan get laluan)
  menyalin harga model yang dirutekannya.
- Medan tersebut hanya membawa kadar asas. Tingkat konteks panjang (medan berangka `long_context`) dan
  pengganda tingkat perkhidmatan (contohnya Codex pantas atau fleksibel) tidak mengubah `prompt` atau
  `completion`.
- Objek tersebut sama untuk setiap gaya pengesahan, termasuk permintaan bergaya Anthropic
  dengan `x-api-key` dan `anthropic-version` (respons kekal `{ "object": "list",
"data": [...] }`). Pelaksanaan: `src/app/api/v1/models/catalogPricing.ts`.

### Awalan id model (`?prefix=`)

Kebanyakan model diiklankan dengan **awalan penyedia**. Awalan yang anda terima dikawal oleh
flag ciri `MODELS_CATALOG_PREFIX_MODE`, dan boleh diubah **bagi setiap permintaan** dengan
parameter pertanyaan — berguna untuk klien yang mahukan senarai bersih tanpa mengubah tetapan seluruh
pelayan untuk orang lain:

```bash
GET /v1/models?prefix=alias        # satu id bagi setiap model — awalan alias ringkas
GET /v1/models?prefix=dual         # kedua-dua bentuk (lalai pelayan)
GET /v1/models?prefix=canonical    # hanya awalan id penyedia penuh
```

| Mod         | Menghasilkan                                              | Nota                                                                                                                                                                                                                 |
| ----------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **dan** `claude/claude-sonnet-4-6` | **Lalai.** Kedua-dua id merutekan ke model yang sama; dikekalkan supaya konfigurasi klien yang menetapkan salah satu bentuk secara keras terus berfungsi. Katalog kira-kira berganda.                                |
| `alias`     | `cc/claude-sonnet-4-6`                                    | Satu entri bagi setiap model. Penyedia tanpa alias yang berbeza masih menghasilkan entri mereka, jadi tiada apa-apa yang hilang.                                                                                     |
| `canonical` | `claude/claude-sonnet-4-6`                                | Satu entri bagi setiap model di bawah awalan id penyedia penuh. Penyedia tanpa alias yang berbeza (contohnya `antigravity/…`, `agy/…`) turut menghasilkan id tunggal mereka di sini, jadi tiada apa-apa yang hilang. |

Cerminan mod `dual` juga boleh dikenal pasti tanpa parameter pertanyaan: ia membawa medan `parent`
yang menunjuk kepada id utama.

Klien yang memaparkan pemilih model hendaklah meminta `?prefix=alias` — inilah yang dilakukan oleh
[sambungan OmniCopilot VS Code](../guides/VSCODE-COPILOT.md).

### Penapis penemuan (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` menerima penapis penemuan pilihan. Tanpa mana-mana penapis ini, respons tidak
berubah. Penapis ini mengecilkan katalog yang sudah boleh dilihat oleh pemanggil (kebenaran kunci API
digunakan terlebih dahulu), dan dijalankan sebelum penomboran `limit` / `after` gaya OpenAI:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # setiap keupayaan yang disenaraikan mesti benar
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` katalog; baris tanpanya ialah `chat`
GET /v1/models?q=sonnet&limit=10                           # padanan tidak peka huruf besar-kecil pada id atau nama
```

| Parameter     | Nilai                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | integer bukan negatif, dibandingkan dengan `context_length`                                         |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 aksara                                                                                        |

Nilai yang tidak diketahui, atau `min_context` yang bukan integer bukan negatif (contohnya `1.5`),
mengembalikan HTTP `400` dan mesej menyenaraikan nilai yang sah. Pelaksanaan:
`src/app/api/v1/models/catalogFilters.ts`.

### Senarai pendek model (`POST /v1/models/query`)

`POST /v1/models/query` mengembalikan senarai pendek deterministik daripada katalog yang sama, dengan
pengesahan dan keterlihatan setiap kunci yang sama seperti `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Setiap medan adalah pilihan. `capabilities` dan `exclude` menerima tatasusunan atau rentetan
dipisahkan koma; `max_output` dibandingkan dengan `max_output_tokens`. Hasilnya diisih mengikut
`owned_by`, kemudian `id`. `limit` lalai kepada `20` dan nilai melebihi `100` dihadkan kepada
`100`. JSON yang tidak sah, medan yang tidak diketahui atau nilai yang tidak sah mengembalikan
HTTP `400`.

### Model sembang yang disembunyikan secara individu

Model yang ditandakan **Tersembunyi** pada halaman penyedianya dikecualikan daripada katalog dan
ditolak dengan HTTP `404` / `model_not_found` apabila diminta secara eksplisit. Semakan ini
menggunakan penyedia dan model yang telah diselesaikan, termasuk alias penyedia, awalan nod
penyedia yang serasi dan lalai sambungan. Gabungan melangkau sasaran tersembunyi dan boleh
menggunakan adik-beradik yang kelihatan; apabila tiada sasaran boleh laku yang tinggal, ia
mengembalikan kod ralat yang sama. Menyahsembunyikan berkuat kuasa pada permintaan seterusnya.
Penggantian keterlihatan untuk imej sahaja tidak menyembunyikan model sembang dengan ID yang sama.

Tetapan model individu ini berasingan daripada
[senarai benarkan/tolak pendedahan model](../routing/MODEL_EXPOSURE_LIST.md), yang menapis
pengiklanan katalog dan calon penghalaan automatik sambil mengekalkan penghantaran eksplisit.
Kebenaran model untuk kunci API terus digunakan secara bebas. Mod awalan katalog lalai kekal
`dual`.

### Varian model tanpa thinking

Untuk model Claude yang menyokong thinking, `/v1/models` turut mengiklankan varian **tanpa thinking**
yang ID-nya diawali dengan `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Memilih ID ini (contohnya dalam konfigurasi Claude Code yang sentiasa melampirkan blok `thinking`)
akan menyelesaikan semula kepada `<provider>/<model>` sebenar dengan penaakulan dilumpuhkan —
`thinking:{type:"disabled"}` pada laluan `/v1/messages`, atau medan
`reasoning`/`reasoning_effort` digugurkan pada laluan `/v1/chat/completions`. Varian ini hanya
disenaraikan untuk model keluarga Claude yang menyokong thinking **dan** mematuhi `disabled`
(contohnya model adaptif sahaja yang menolak `disabled` dikecualikan). Operator boleh memaksa
varian ini hidup atau mati bagi setiap model melalui `ModelSpec.noThinkingAlias`.

## Penjanaan audio ElevenLabs

Konfigurasikan sambungan pembekal `elevenlabs` dalam OmniRoute dengan kunci API ElevenLabs anda.
Klien mengesahkan dirinya dengan kunci **OmniRoute** (`Authorization: Bearer $OMNIROUTE_API_KEY`);
get laluan membekalkan kunci pembekal yang disimpan sebagai `xi-api-key`. Jangan sekali-kali menghantar kunci ElevenLabs
sebagai token pembawa get laluan.

| Kaedah | Laluan                      | Respons                                   | Kategori titik akhir kunci API |
| ------ | --------------------------- | ----------------------------------------- | ------------------------------ |
| POST   | `/v1/sound-generation`      | Bait audio natif                          | `elevenlabs`                   |
| POST   | `/v1/music`                 | Bait audio natif                          | `music`                        |
| POST   | `/v1/music/stream`          | Bait audio penstriman                     | `music`                        |
| POST   | `/v1/music/detailed`        | Audio multipart natif dan pelan komposisi | `music`                        |
| POST   | `/v1/music/detailed/stream` | Metadata SSE natif dan cebisan audio      | `music`                        |
| POST   | `/v1/music/plan`            | Pelan komposisi JSON                      | `music`                        |

Titik akhir ini melengkapi laluan `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` dan `/v1/speech-to-text` yang sedia ada. Medan JSON natif
dan parameter pertanyaan seperti `output_format` dan `enable_logging` dikekalkan.
Respons `/v1/music/detailed` mengekalkan sempadan multipartnya; huraikannya sebagai multipart.
`/v1/music/detailed/stream` mengembalikan `text/event-stream` dengan metadata komposisi dan
cebisan audio berkod base64 dalam peristiwa SSE. Kesemua enam laluan menyokong prapenerbangan CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Kesan bunyi pendek. Tempoh: 0.5 hingga 30 saat.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Tempoh muzik dinyatakan dalam milisaat: 3000 hingga 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Gunakan `/v1/music/stream` dengan badan JSON yang sama untuk penghantaran audio secara berperingkat. Komposisi
menerima tepat satu daripada `prompt` atau `composition_plan`; `/v1/music/plan` memerlukan `prompt`
dan secara pilihan menerima `source_composition_plan`. Skema natif mengekalkan medan pembekal tambahan supaya versi
pelan komposisi dan pilihan penalaan halus sampai kepada ElevenLabs.

Titik akhir bersatu `/v1/music/generations` juga menerima `elevenlabs/music_v1`,
`elevenlabs/music_v2` dan `elevenlabs/music_v2_5`. Dengan sambungan ElevenLabs yang aktif,
model ini didedahkan oleh katalog muzik. Titik akhir ini mengembalikan
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Medan `duration` adalah dalam
saat dan dipetakan kepada `music_length_ms`; `music_length_ms` yang dinyatakan secara jelas diutamakan.
`instrumental` dipetakan kepada `force_instrumental`, dengan medan natif diutamakan.
Gunakan titik akhir penstriman natif untuk penstriman dan titik akhir komposisi natif
untuk permintaan yang dipacu hanya oleh pelan komposisi.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Sekatan titik akhir, model, belanjawan dan sambungan dikenakan sebelum panggilan huluan. Laluan natif
mengembalikan kod status huluan dan isi ralat tanpa perubahan, termasuk `402` untuk sekatan pelan dan
`429` untuk had kuota. Pengepala `character-cost`, `song-id`, `request-id` dan `retry-after`
dikekalkan apabila tersedia. Baki kredit percuma tidak menjamin akses kepada setiap
model muzik, format output atau ciri API: ElevenLabs menentukan kelayakan bagi setiap permintaan.
Titik akhir bersatu mengekalkan kod status ralat dalam sampul ralat ternormal OmniRoute.

Kontrak huluan: [kesan bunyi](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[komposisi muzik](https://elevenlabs.io/docs/api-reference/music/compose) dan
[butiran muzik penstriman](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> (oMLX, vLLM, Infinity, TEI di belakang get laluan, …) yang dialamatkan sebagai `<node-prefix>/<model>`. Nod
> gelung balik (`localhost`, `127.0.0.1`, `172.16.0.0/12`) sentiasa layak, begitu juga nama hos yang
> disenaraikan oleh operator dalam `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (contohnya nama perkhidmatan
> Docker/Compose seperti `http://reranker:8080/v1`; nod ini dipanggil secara terus, tidak melalui
> `HTTP(S)_PROXY` atau proksi yang dipasangkan pada sambungan). Nod pada mana-mana
> hos lain — mesin LAN atau rakan Tailscale — hanya layak apabila operator mendayakan
> bendera ciri `RERANK_REMOTE_PROVIDER_NODES` **dan** URL asas nod melepasi dasar URL keluar penyedia
> (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Langkah rerank enjin memori memanggil laluan ini melalui
> gelung balik, jadi peraturan yang sama mengawal `rerankProviderModel` dalam tetapan Memori.
>
> **Bentuk pelayan tempatan:** nod dipanggil pada `<base>/v1/rerank` dan, apabila 404, pada `<base>/rerank`
> (Infinity, TEI). Isi huluan membawa kedua-dua ejaan Cohere/OpenAI (`documents`,
> `return_documents`) dan ejaan TEI (`texts`, `return_text`), dan respons huluan
> dinormalkan kepada sampul Cohere: `[{index, score, text}]` kosong milik TEI, `{results: [{index, score}]}`
> daripada get laluan nipis, serta `{data: [...]}` gaya Voyage semuanya dikembalikan kepada klien sebagai
> `{results: [{index, relevance_score, document?}]}`, diisih mengikut skor dan dihadkan kepada `top_n`.

> **Penemuan nod penyedia:** model pada nod penyedia yang serasi dengan OpenAI muncul dalam `GET /v1/models`
> di bawah awalan nod. Baris yang tidak mempunyai metadata titik akhir (tipikal untuk penyenaraian `/v1/models` tempatan)
> mewarisi `apiType` nod, jadi model nod `embeddings` mempunyai `type: "embedding"` dan
> model nod `rerank` mempunyai `type: "rerank"` dan bukannya lalai kepada chat; `supportedEndpoints` eksplisit
> pada baris yang disegerakkan atau ditambah secara manual tetap mempunyai keutamaan.

## API Fail

Titik akhir fail serasi OpenAI untuk input/output kelompok dan muat naik fail mengikut tujuan.

| Kaedah | Laluan                   | Perihalan                                                                                                           |
| ------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/files`              | Muat naik fail (multipart: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — maksimum 512 MiB |
| GET    | `/v1/files`              | Senaraikan fail untuk kunci API yang disahkan                                                                       |
| GET    | `/v1/files/[id]`         | Dapatkan metadata fail                                                                                              |
| DELETE | `/v1/files/[id]`         | Padam fail                                                                                                          |
| GET    | `/v1/files/[id]/content` | Strim isi badan fail mentah kembali                                                                                 |

**Pengesahan:** Kunci API Bearer — fail dilingkungi mengikut kunci API melalui `getApiKeyRequestScope`. Satu kunci
hanya boleh melihat, memuat turun dan memadam failnya sendiri; sesi papan pemuka tanpa kunci membaca
keseluruhan tika; fail tanpa pemilik (muat naik tanpa nama atau melalui sesi papan pemuka) dinafikan kepada
setiap pemanggil bukan sesi. `GET /v1/files` menolak pemanggil tanpa nama — serta kunci yang diberikan tetapi
tidak dapat diselesaikan — dengan `401` walaupun `REQUIRE_API_KEY=false`, dan bukannya menyenaraikan fail
semua penyewa (GHSA-m3hp-hq9g-fpmv, GHSA-2jm2-mpx8-6523).

### `provider_options` Exa dan Tavily

Exa dan Tavily membaca medan khusus penyedia daripada bekas bernamespace:
`provider_options.exa` (atau `provider_options["exa-search"]`) dan `provider_options.tavily`
(atau `provider_options["tavily-search"]`). Hanya kunci di bawah akan dihantar. Setiap kunci
disemak terhadap skema Zod tersendiri dalam `open-sse/handlers/search/providerOptionsPassthrough.ts`,
dan kunci dengan jenis yang salah akan digugurkan. Sebarang kunci lain diabaikan, termasuk pengesahan, URL asas,
`stream` dan `outputSchema`. Kunci rata yang digunakan oleh penyedia lain (`cx`, `depth`, ...) berfungsi
seperti sebelum ini.

| Penyedia | Medan peringkat atas                                                                                                                                                                                                                                                                                                                                                      | Bersarang                                                                                                                                       |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa      | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (primitif rata), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                                | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` digabungkan dengan nilai lalai `{ text: true, highlights: true }` |
| Tavily   | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                               |

Medan generik sentiasa diutamakan: `query`, `max_results`, `filters` (domain), `country` dan
topik yang diterbitkan daripada `search_type`. Pada Exa, `search_type: "news"` mengekalkan
`category: "news"`. Tavily juga menerima `search_type: "finance"` (`topic: "finance"`).

Kos carian Firecrawl direkodkan bagi setiap blok 10 hasil yang dikembalikan dan telah dimulakan, pada kadar $0.002 (2
kredit) setiap blok serta sekurang-kurangnya satu blok bagi setiap panggilan
([pengebilan Firecrawl](https://docs.firecrawl.dev/billing)): 11 hasil berharga $0.004.

Generik `time_range` kini sampai kepada kedua-dua penyedia: Exa menerima `startPublishedDate` (cap masa ISO)
dan Tavily menerima `start_date` (`YYYY-MM-DD`). Tarikh eksplisit dalam `provider_options`
mengatasi tarikh yang dipetakan.

Hasil Exa mengekalkan `id`, `highlights` (setiap sorotan, bukan hanya yang pertama yang digunakan sebagai
`snippet`), `highlight_scores`, `summary`, `subpages`, `entities` dan `extras` dalam
`provider_raw`. Hasil Tavily mengekalkan `images` dan `favicon`.

Kos carian Linkup direkodkan pada $0.005 untuk `depth` `fast` dan `standard` serta $0.05 untuk
`deep` ([harga Linkup](https://docs.linkup.so/pages/documentation/development/pricing)),
sama ada `depth` datang daripada `provider_options` atau tetapan sambungan.

Exa `type: "lite"` (Exa 3.0) menerima set medan yang lebih kecil dan menolak keseluruhan permintaan
apabila mana-mana medan lain ditetapkan. Untuk lite, `additionalQueries`, `systemPrompt` dan setiap
kunci `contents` kecuali `text` dan `highlights` digugurkan sebelum panggilan. Medan yang telah ditamatkan
`subpages`, `subpageTarget`, `highlights.numSentences` dan `highlights.highlightsPerUrl` tidak lagi
dihantar.

Exa: $0.007 setiap panggilan untuk `auto` (dan `fast` legasi ) atau $0.004 untuk `lite` (dan `instant` warisan ), meliputi 10 keputusan; $0.001 untuk setiap keputusan selanjutnya; dan $0.001 setiap hasil yang dikembalikan apabila `contents.summary` ditetapkan. Tavily direkodkan pada 1 kredit ($0.008) untuk `search_depth` `basic`, `fast` dan `ultra-fast`, dan 2 kredit ($0.016) untuk `advanced` ( [Tavily API credits](https://docs.tavily.com/documentation/api-credits) ). Panggilan dengan `auto_parameters: true` yang Tavily naik taraf kepada lanjutan masih direkodkan pada 1 kredit.

## API Ambilan Web

Ekstrak kandungan daripada URL melalui penyedia ambilan web yang dikonfigurasi (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, kunci API yang sama seperti Parallel Search) hanya mengembalikan Markdown
— sebarang `format` lain ialah `400` — dan mengehadkan kandungan kepada 100,000 aksara. Apabila halaman sasaran
itu sendiri tidak dapat diekstrak, upstream melaporkannya dalam HTTP 200;
OmniRoute mendedahkannya sebagai `422` dengan mesej tetap.

| Kaedah | Laluan          | Perihalan                                                |
| ------ | --------------- | -------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Ambil/kerik URL — badan disahkan oleh `v1WebFetchSchema` |

**Pengesahan:** Kunci API Bearer (`extractApiKey` + `isValidApiKey`). Dasar dikuatkuasakan melalui `enforceApiKeyPolicy`.

**Fallback peka kuota (#8297):** apabila tiada `provider` yang dinyatakan secara eksplisit, kumpulan
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) dilalui mengikut susunan keutamaan tetap (isi dahulu) — penyedia yang dihadkan kadar tetapi telah dikonfigurasi dilangkau
dan bukannya memendekkan permintaan, manakala kegagalan upstream yang boleh dicuba semula/berkaitan kuota (HTTP 429 sentiasa;
402/403 untuk peringkat percuma Firecrawl/Tavily/TinyFish yang bergaya kuota —
bukan untuk Jina Reader, dan tidak pernah untuk permintaan buruk 400 biasa) diteruskan kepada penyedia bertauliah berikutnya yang belum dicuba pada masa permintaan. Apabila setiap penyedia dalam kumpulan telah habis digunakan, endpoint mengembalikan satu `429` (dengan pengepala `Retry-After`) dan bukannya `400` generik yang sebelumnya. Apabila `provider` eksplisit diminta, **tiada fallback senyap** — penyedia eksplisit yang dihadkan kadar atau gagal memaparkan ralatnya sendiri (`429` jika dihadkan kadar, selain itu status upstream).

## Penstriman WebSocket

```bash
GET /v1/ws?handshake=1
```

Mengesahkan jabat tangan naik taraf WebSocket dan mengembalikan mesej contoh protokol wayar (`request`, `cancel`). Bingkai WS sebenar dikendalikan oleh pelayan WS terbina dalam di luar jadual laluan Next.js.

**Pengesahan:** Kunci API Bearer semasa jabat tangan.

### API Responses melalui WebSocket (codex sahaja)

```bash
# Hos:port yang sama seperti API HTTP (lalai 20128); naik taraf sambungan:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (atau: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Bingkai pertama MESTI ialah response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proksi Responses-API-over-WebSocket disambungkan **secara eksklusif kepada `codex`** (backend ChatGPT). Ia mendengar pada port yang sama seperti API/papan pemuka di laluan `/v1/responses`,
`/responses`, dan `/api/v1/responses`. Pada bingkai `response.create` pertama, ia mengesahkan + membuat persediaan melalui jambatan dalaman `codex-responses-ws`, memilih sambungan OAuth codex, dan membuat terowong ke `wss://chatgpt.com/backend-api/codex/responses`
melalui pengangkutan `wreq-js`. Model bukan codex ditolak (`codex_ws_provider_required`).
Untuk penghalaan perkongsian kuota gunakan `model: "qtSd/<group>/codex/<model>"`. Dilaksanakan dalam
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Pengesahan:** Kunci API Bearer semasa jabat tangan. Pelayan HTTP terbina dalam (`server-ws.mjs`)
mesti menjadi titik masuk aktif (secara lalai, ia adalah aktif apabila `app/server-ws.mjs` wujud).

#### ID model: gunakan ID ChatGPT tanpa awalan (tiada awalan `codex/`)

**Codex CLI** OpenAI mengesahkan nama model pada pihak klien apabila
`supports_websockets = true` dan **menolak** ID yang diawali penyedia seperti
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Hantar ID **tanpa awalan** (contohnya `gpt-5.5`). Jambatan OmniRoute hanya untuk codex, jadi ia menyelesaikan semula ID tanpa awalan sebagai model codex
(`resolveCodexWsModelInfo`) sebelum membuat terowong ke upstream — walaupun `gpt-5.5` tanpa awalan sebaliknya akan dihalakan kepada penyedia lain melalui HTTP.

#### Mengkonfigurasi Codex CLI OpenAI

Halakan Codex CLI ke OmniRoute dengan menambahkan penyedia tersuai yang menyokong WebSocket
kepada `~/.codex/config.toml` (gunakan `CODEX_HOME` berasingan untuk mengelakkan pengubahsuaian konfigurasi sedia ada):

```toml
model = "gpt-5.5"                 # id tanpa awalan — BUKAN "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # tiada garis miring di hujung; URL WS diterbitkan daripadanya (gunakan https/wss dalam produksi)
wire_api = "responses"                    # satu-satunya nilai yang disokong sejak Feb 2026
supports_websockets = true                # mendayakan pengangkutan Responses-over-WS
env_key = "OMNIROUTE_API_KEY"             # menyimpan kunci API OmniRoute (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # kunci API OmniRoute (sebarang kunci jika REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI menaik taraf `base_url + /responses` kepada WebSocket dan OmniRoute membuat terowong ke sambungan OAuth codex yang dipilih. Divalidasi dari hujung ke hujung terhadap pelayan tempatan: ChatGPT mengembalikan
`codex.rate_limits` + `response.created` dan menstrim pelengkapan.

### Pemulihan sesi kuota (pilihan)

Permintaan `POST /v1/chat/completions` atau `POST /v1/responses` tanpa penstriman yang gagal dengan
ralat kuota terminal (`402`/`429`/`503` yang isi kandungannya menyatakan kuota atau kredit telah habis)
boleh diletakkan sementara dan dimainkan semula kemudian dan bukannya memulangkan ralat tersebut. Pemanggil memilih
fungsi ini untuk setiap permintaan menggunakan tiga pengepala:

| Pengepala                    | Nilai                                                 |
| ---------------------------- | ----------------------------------------------------- |
| `x-omniroute-quota-recovery` | `auto`                                                |
| `x-omniroute-session`        | id sesi, `[A-Za-z0-9._:-]{1,128}`                     |
| `x-omniroute-recovery-turn`  | id giliran yang unik dalam sesi (peraturan yang sama) |

Hanya giliran `stream: false` tanpa alat, sejarah alat atau `previous_response_id`, dan tanpa
pin `x-omniroute-connection`, layak diproses, serta `STORAGE_ENCRYPTION_KEY` mesti ditetapkan (permintaan
disimpan secara disulitkan sehingga 24 jam). Respons kemudiannya ialah `202` dengan
`recovery.poll`; lakukan tinjauan pada `GET /v1/quota-recoveries/{id}` (`202` sementara menunggu, `200` dengan
isi kandungan yang dipulihkan apabila selesai) atau batalkan dengan `DELETE`. Tiket hanya boleh dilihat oleh kunci API
yang menciptanya. Main semula yang keputusannya tidak pasti akan berakhir dalam `needs_confirmation`
dan bukannya dihantar dua kali. Sumber: `src/lib/quota/quotaSessionRecovery.ts`.

## Penggunaan layan diri (`/api/usage/om-usage`)

Mana-mana kunci API boleh membaca penggunaan dan kuotanya **sendiri** — tanpa pengesahan pengurusan. Inilah titik akhir yang
digunakan oleh klien (CLI, panel OmniCopilot) untuk menunjukkan perbelanjaan pemegang kunci.

```bash
# Bentuk teks (kontrak sejarah — teks biasa untuk terminal)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Bentuk berstruktur — perkara yang digunakan oleh UI
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Kunci tersebut mesti mempunyai **`allowUsageCommand`** yang didayakan (dilumpuhkan secara lalai — pengurus kunci API
papan pemuka menogolkannya untuk setiap kunci). Tanpanya, titik akhir ini akan memberikan respons `403`.

`?format=json` mengembalikan bentuk terbeza supaya pemanggil tidak akan membaca medan data daripada penolakan. Apabila berjaya:

```jsonc
{
  "allowed": true,
  // hadir hanya apabila kunci memilih masuk kepada had penggunaan setiap kunci (USD harian/mingguan):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // petikan kuota pembekal yang dipilih, atau null apabila belum ada apa-apa yang dicache:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // petikan setiap sambungan, supaya UI boleh memaparkan beberapa pembekal bersebelahan:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Apabila ditolak (kunci `401` tidak sah / `403` tidak dibenarkan), laluan yang sama mengembalikan
`{ "allowed": false, "error": { "message": "…" } }` — `personal`/`provider` yang hadir tetapi kosong
(kunci dibenarkan, belum ada maklumat yang diperoleh) ialah keadaan yang berbeza daripada penolakan, dan hanya bentuk JSON
membezakannya.

**Pengesahan:** kunci API Bearer milik pemanggil, disahkan menggunakan `isValidApiKey` — ini _bukan_ permukaan
pengurusan (`/api/keys/…`), yang kekal dilindungi oleh `requireManagementAuth`.

### Peratusan Kuota Mentah berbanding Kuota yang Diselaraskan dengan Ambang

Apabila menggunakan `/api/usage/om-usage`, pemanggil perlu mengambil perhatian terhadap perbezaan antara
peratusan yang dipaparkan oleh **output teks biasa** dan output **JSON berstruktur**:

| Aspek                 | Format teks biasa (`/api/usage/om-usage` / `@@om-usage`)                                              | Format JSON (`?format=json`)                                                      |
| :-------------------- | :---------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------- |
| **Medan output**      | `NN% left` (contohnya, `20% left`)                                                                    | `provider.quotas` / `providers[].quotas`                                          |
| **Pengukuran**        | **Elaun boleh guna yang diselaraskan dengan ambang**: kapasiti yang tinggal di atas ambang pemotongan | **Kuota hulu mentah**: pengukuran pembekal yang tidak diselaraskan                |
| **Penskalaan ambang** | Diskalakan melalui `effectiveRemainingPercent()` supaya rizab terlindung dibaca sebagai `0% left`     | Tiada (nilai petikan mentah seperti yang dilaporkan oleh pembekal)                |
| **Data ambang**       | Dimasukkan ke dalam peratusan yang dipaparkan                                                         | Disimpan dalam `quotaWindowThresholds` bagi setiap sambungan (atau lalai pelayan) |
| **Pengguna utama**    | CLI interaktif, gesaan terminal, pengendali manusia                                                   | Integrasi berprogram, papan pemuka, analitik, penjejak pengebilan                 |

#### Formula Pelarasan Ambang

OmniRoute menyokong ambang pemotongan kuota proaktif untuk mengelakkan kehabisan kuota hulu (dikonfigurasi melalui sambungan
`quotaWindowThresholds`, lalai pembekal atau tetapan daya tahan global). Apabila ambang pemotongan
(contohnya, `cutoff = 25%`) aktif pada tetingkap kuota, pemapar teks mengira elaun yang tinggal seperti berikut:

- Jika `remaining <= cutoff`: mengembalikan `0%`.
- Jika `remaining > cutoff`: `((remaining - cutoff) / (100 - cutoff)) * 100`.

Output teks berformat membundarkan nilai ini kepada integer terdekat (`Math.round(...)`).

#### Contoh Ilustrasi

Pertimbangkan tetingkap pembekal dengan **penggunaan mentah 60%** (maka **kuota mentah yang berbaki 40%**) dan ambang **25% kuota berbaki** yang dikonfigurasikan:

| Perwakilan                       | Pengiraan                                          | Berbaki |           Penggunaan Tersirat            |
| :------------------------------- | :------------------------------------------------- | :-----: | :--------------------------------------: |
| **JSON Mentah (`?format=json`)** | Syot kilat huluan (`quotas[window]`)               | **40%** |                 **60%**                  |
| **Format teks (`NN% left`)**     | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (jika mengira `100 - remaining`) |

- **Mengapa teks menunjukkan 20% berbaki:** Daripada kuota fizikal 40% yang berbaki pada akaun, 25% dikhaskan oleh dasar pemotongan. Pemanggil hanya mempunyai 15% daripada 75% ruang lebihan yang boleh digunakan sebelum penghala berhenti menghala ke sambungan ini. Penskalaan memastikan sambungan menandakan kehabisan (`0% left`) tepat apabila penghalaan akan dihentikan.
- **Mengapa JSON mengekalkan nilai mentah:** Muatan JSON mengembalikan syot kilat tepat pembekal (`UsageSnapshot`) supaya alat luaran mempunyai akses kepada penggunaan huluan sebenar dan `quotaWindowThresholds` pada peringkat sambungan tanpa penskalaan lossy pada sisi pelayan.

#### Panduan Migrasi Pengguna

Jika integrasi luaran (seperti pemalam editor atau sambungan ejen) sebelum ini mengekstrak kandungan daripada titik akhir teks (`NN% left`) dan mengira peratus penggunaan sebagai `100 - NN`, migrasi ke `?format=json` bermaksud:

- Membaca nilai JSON mentah akan mencerminkan **penggunaan sebenar huluan** (60% digunakan dalam contoh di atas).
- Jika integrasi ingin mengekalkan semantik elaun boleh guna titik akhir teks, integrasi tersebut boleh menilai formula baki efektif pada sisi klien menggunakan `quotaWindowThresholds` untuk penggantian pada peringkat sambungan.

## Cache Semantik

```bash
# Dapatkan statistik cache
GET /api/cache/stats

# Kosongkan semua cache
DELETE /api/cache/stats
```

Contoh respons:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### Kesan kependaman

Cache semantik HIT menyampaikan respons daripada cache **tanpa panggilan upstream**, jadi `X-OmniRoute-Response-Latency` yang dilaporkan adalah hampir sifar (tanpa mengira kependaman upstream asal). Klien yang sensitif terhadap kependaman (penanda aras, pemantauan p50/p99) hendaklah menyemak pengepala respons `X-OmniRoute-Cache-Latency`:

| Nilai       | Maksud                                                                     |
| ----------- | -------------------------------------------------------------------------- |
| `synthetic` | Respons disampaikan daripada cache; kependaman bukan masa upstream sebenar |
| _(absent)_  | Respons daripada panggilan upstream sebenar                                |

### Pintasan cache mengikut kunci

Kunci API boleh memilih untuk tidak menggunakan bacaan cache semantik melalui `cacheDefaultMode`:

| Nilai    | Tingkah laku                                                   |
| -------- | -------------------------------------------------------------- |
| `legacy` | Tingkah laku cache biasa (lalai)                               |
| `bypass` | Langkau carian cache sepenuhnya; sentiasa menghubungi upstream |

Tetapkan semasa penciptaan kunci (`POST /api/keys`) atau kemas kini (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### Pintasan cache mengikut permintaan

Mana-mana permintaan boleh memintas cache tanpa mengira tetapan kunci:

```
X-OmniRoute-No-Cache: true
```

## Keserasian Pengurusan CLIProxyAPI

OmniRoute menjawab tiga endpoint pengurusan [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) yang dipanggil oleh papan pemuka penggunaan untuk membaca had langganan Claude dan Codex (contohnya sumber had penggunaan `cliproxy` T3 Code). Halakan URL asas klien kepada OmniRoute dan gunakan kunci API dengan skop `manage` sebagai kunci pengurusan. Laluan ini disediakan di `/v0/management/*` dan `/api/v0/management/*`.

| Kaedah | Laluan                       | Penerangan                                                                                                                                                      |
| ------ | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/v0/management/auth-files`  | Sambungan OAuth Claude dan Codex sebagai `{ files: [{ id, auth_index, provider, email, disabled, id_token }] }`. Tiada token                                    |
| POST   | `/v0/management/api-call`    | Isi `{ auth_index, method, url, header?, data? }`. Menghantar satu permintaan yang dibenarkan menggunakan token akaun dan mengembalikan `{ status_code, body }` |
| POST   | `/v0/management/reset-quota` | Isi `{ auth_index }`. Mengosongkan tempoh bertenang sambungan, sekatan model dan tempoh bertenang mengikut skop Codex bagi satu akaun                           |

- `auth_index` ialah id sambungan OmniRoute. `provider` ialah `claude` atau `codex` (sambungan OAuth sahaja; penyedia kunci API `anthropic` tidak disenaraikan). Bagi Codex, `id_token.chatgpt_account_id` ialah id ruang kerja tersimpan dan `plan_type` ialah pelan tersimpan.
- `api-call` bukan proksi umum. Ia hanya menerima Claude `GET
https://api.anthropic.com/api/oauth/usage` dan Codex `GET
https://chatgpt.com/backend-api/wham/usage`, `GET .../wham/rate-limit-reset-credits` dan `POST .../wham/rate-limit-reset-credits/consume`, setiap satunya hanya untuk akaun penyedia yang sepadan. Selain itu, semuanya mengembalikan `403` tanpa menghubungi upstream. Pengepala `Authorization` pemanggil (termasuk pemegang tempat `$TOKEN$`) diabaikan: OmniRoute menyuntik token akses sambungan, menyegarkannya terlebih dahulu apabila hampir luput, dan hanya memajukan pengepala yang dibenarkan (`anthropic-beta`; `OpenAI-Beta`, `Originator`, `Chatgpt-Account-Id`; `Accept`, `Content-Type`). `Chatgpt-Account-Id` yang tiada menggunakan id ruang kerja tersimpan secara lalai. Jika respons upstream pertama ialah `401`, ia menyegar sekali dan mencuba semula hanya apabila token akses berubah. Setiap percubaan upstream tamat masa selepas 15 saat dan menggunakan proksi sambungan.
- `reset-quota` tidak mengubah keadaan terminal (banned, expired, credits_exhausted). `auth_index` yang tidak diketahui mengembalikan `404`.

**Pengesahan:** sesi papan pemuka atau kunci API berskop `manage`, diperlukan walaupun log masuk dilumpuhkan (laluan tersebut berada dalam `ALWAYS_PROTECTED_API_PATHS`). Kunci yang hanya mempunyai keupayaan inferens menerima `403`. Sumber: `src/lib/cliproxyCompat/managementApi.ts`.

## Papan Pemuka & Pengurusan

Laluan pengurusan (`/api/*` kecuali pengesahan/log masuk awam) **tidak** dibenarkan oleh
kunci API inferens biasa. Keluarga kelayakan, skop dan contoh curl:
[Pengesahan Pengurusan](../guides/MANAGEMENT-AUTH.md).

### Pengesahan

| Endpoint                      | Method   | Description                                                                                                                                                                                                                                                                                                     |
| ----------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api/auth/login`             | POST     | Log masuk                                                                                                                                                                                                                                                                                                       |
| `/api/auth/logout`            | POST     | Log keluar                                                                                                                                                                                                                                                                                                      |
| `/api/settings/require-login` | GET/POST | Status log masuk (GET, awam). POST menetapkan kata laluan / menogol log masuk: hanya operator selepas kata laluan wujud (sesi papan pemuka, CLI tempatan atau log masuk dilumpuhkan — kunci API dan token `oma_` menerima `403`); sesi papan pemuka menghantar `currentPassword` untuk menggantikan kata laluan |

### Pengurusan Pembekal

| Endpoint                                | Method                    | Description                                                                                                                                                                     |
| --------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api/providers`                        | GET/POST                  | Senaraikan / cipta pembekal                                                                                                                                                     |
| `/api/providers/[id]`                   | GET/PUT/DELETE            | Urus pembekal                                                                                                                                                                   |
| `/api/providers/[id]/test`              | POST                      | Uji sambungan pembekal                                                                                                                                                          |
| `/api/providers/[id]/models`            | GET                       | Senaraikan model pembekal                                                                                                                                                       |
| `/api/providers/validate`               | POST                      | Sahkan konfigurasi pembekal                                                                                                                                                     |
| `/api/providers/bulk`                   | POST                      | Tambah kunci API secara pukal untuk SATU pembekal                                                                                                                               |
| `/api/providers/import`                 | POST                      | Import SENARAI pembekal heterogen daripada fail CSV/JSON yang dihuraikan (#6836); hasil kegagalan separa bagi setiap baris                                                      |
| `/api/provider-nodes*`                  | Various                   | Pengurusan nod pembekal                                                                                                                                                         |
| `/api/provider-models`                  | GET/POST/PUT/PATCH/DELETE | Model tersuai dan penggantian bagi setiap model (tambah, kemas kini, sembunyi/tunjuk, padam)                                                                                    |
| `/api/provider-models/validate-and-add` | POST                      | Pengesahan sambungan ketat yang didayakan secara pilihan dan pendaftaran model tersuai atomik yang disahkan pengurusan; lihat [Pengesahan model](../guides/MODEL-VALIDATION.md) |

Untuk model yang disegerakkan/diimport, `PUT /api/provider-models` menerima `provider`, `modelId` dan
`maxOutputTokenOverride`: integer positif menetapkan had token output manual, manakala `null`
mengosongkannya untuk memulihkan nilai lalai. `GET /api/provider-models?provider=<provider>` mengembalikan nilai ini dalam
`modelOutputOverrides`, termasuk model tanpa baris model tersuai. Penggantian ini menggunakan keupayaan masa jalan
`max_output_tokens` dan kekal selepas penyegerakan semula model. Halaman pembekal serasi OpenAI menawarkan kawalan edit/kosong yang sama dan menandakan model dengan sokongan visi yang jelas.

Pada nod pembekal yang serasi, laluan penulisan (`POST`, `PUT`, `PATCH`, `DELETE` dan
`/api/provider-models/validate-and-add`) menyimpan id model sebagai id upstream mentah: id
yang ditampal daripada senarai berawalan akan mengalami semua awalan nod itu sendiri yang berlebihan diruntuhkan, dan
respons mengembalikan id yang disimpan. Id berpalang pembekal kanonik (contohnya `nvidia/nemotron-…`) disimpan secara verbatim. `/v1/models` tidak pernah menghasilkan id bertindan `<prefix>/<prefix>/<model>`.

Nod Chat Completions tersuai menyesuaikan pilihan keluar penaakulan eksplisit dengan bahagian belakang huluan. Ujian sambungan yang berjaya memilih kawalan templat chat secara automatik untuk setiap ID model tepat yang entri `/models`-nya membuktikan nilai `owned_by` yang dikenali: `vllm`, `sglang`, atau `llamacpp`.
Pembungkus serasi OpenAI yang telus mungkin mengekalkan entri model asal di dalam objek `openai` berhierarki; pengesanan mengikuti sehingga tiga sampul sedemikian. Model dengan pemilikan yang hilang, tidak diketahui atau bercanggah mengekalkan tingkah laku OpenAI biasa. Pengesanan menggunakan semula permintaan katalog sedia ada, tidak menjana token pelengkapan, dan dibatalkan apabila titik akhir sambungan berubah.

Untuk menetapkan tingkah laku bagi bahagian belakang yang tidak mendedahkan metadata tersebut, gunakan API kemas kini separa penyedia sedia ada:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Hantar isi tersebut dengan `PUT /api/providers/<connection-id>`. Pada sambungan itu, usaha penaakulan eksplisit `none` dihantar sebagai `chat_template_kwargs.thinking=false` dan
`chat_template_kwargs.enable_thinking=false`. Nilai templat asli yang eksplisit kekal berkuasa melainkan peraturan penaakulan pada sisi pelayan memaksa sesuatu usaha. Tetapan ini hanya digunakan apabila sambungan OpenAI-serasi tersuai menghantar badan Chat Completions; permintaan Responses dan penyedia biasa mengekalkan bentuk permintaan aslinya. Tetapkan `reasoningControl` kepada `openai` untuk memaksa passthrough OpenAI biasa bagi `reasoning_effort`, atau abaikan/tetapkannya kepada `null` untuk menggunakan pengesanan automatik.

Permintaan pengelas mod automatik Claude Code secara lalai menetapkan pemikiran asli kepada dilumpuhkan apabila tidak mengandungi kawalan penaakulan eksplisit. Pengesanan menggunakan penanda sistem pengelas dalam permintaan berformat Claude, bukannya nama model atau had pelengkapan. Kawalan badan eksplisit, pengepala usaha/pemikiran yang disokong, peraturan penghalaan dan usaha model yang diselesaikan mengekalkan keutamaan sedia ada. Kedua-dua peringkat pengelas mengekalkan gesaan, had pelengkapan, jujukan henti dan keputusan kebenaran huluan sebenar masing-masing; peringkat kedua masih boleh menghasilkan penaakulan kelihatan yang dimintanya sebagai teks biasa.

#### Asal had model

`GET /api/models?withLimits=1` (juga `true`; `0`/`false` atau mengabaikannya mengekalkan muatan lalai tanpa perubahan) menambah `contextWindow`, `maxInputTokens`, `maxOutputTokens` dan objek `capsSource` pada setiap baris model. `capsSource` menamakan peraturan yang membekalkan setiap had, supaya had yang mengejutkan (contohnya 128k pada model 1M) boleh dijejaki kepada asalnya. Nilai yang diselesaikan adalah sama seperti yang digunakan oleh penghalaan; bendera ini hanya menambah medan dan tidak pernah mengubah nilai. Sebarang nilai `withLimits` yang lain ditolak dengan `400`.

| Nilai `capsSource`                           | Asal                                                                         |
| -------------------------------------------- | ---------------------------------------------------------------------------- |
| `override:context`                           | Penggantian tetingkap konteks yang disimpan (`model_context_overrides`)      |
| `override:max_input` / `override:max_output` | Penggantian keupayaan `max_input_tokens` / `max_output_tokens` yang disimpan |
| `static-authoritative:<provider>/<model>`    | Jadual tetingkap konteks berautoriti statik                                  |
| `synced:<provider>/<model>`                  | Baris keupayaan yang disegerakkan oleh models.dev                            |
| `registry:<provider>/<model>`                | Entri daftar penyedia                                                        |
| `spec:<model>`                               | Spesifikasi model statik                                                     |
| Awalan `effort-base:`                        | Baris yang dipinjam daripada model asas bagi varian dengan akhiran usaha     |
| `none`                                       | Tiada sumber mengisytiharkan had tersebut (nilai ialah `null`)               |

Pelaksanaan: `getResolvedModelCapabilitiesWithLimitSources()` dalam `src/lib/modelCapabilities.ts`
dan rantai keutamaan dalam `src/lib/modelCapabilityLimits.ts`.

### Versi dan Saluran Keluaran

```bash
GET /api/system/version
```

Laluan pengurusan yang hanya boleh diakses melalui loopback (pengesahan pentadbir). Mengembalikan versi yang sedang berjalan, versi terkini yang diterbitkan dan status kemas kini automatik. `releaseChannel` dan `channels` ialah medan tambahan (rail 3.8.54); `channel` mengekalkan maksudnya — mod penggunaan yang digunakan oleh pengemas kini papan pemuka (`npm`, `source` atau `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — saluran npm bagi binaan yang sedang berjalan: `nightly` untuk versi `-nightly.*`,
  `next` untuk prapelancaran lain (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` untuk versi stabil bagi major
  yang lebih lama daripada `channels.latest`, selain itu `latest`. Peraturan yang sama seperti
  `scripts/release/dist-tag.mjs`, yang memilih tag edaran npm pada masa penerbitan.
- `channels` — keluaran terkini bagi setiap dist-tag yang diterbitkan, daripada `npm view omniroute dist-tags` (sandaran HTTP pendaftaran), dicache dengan TTL 10 minit yang sama seperti `latest`. `latest` sentiasa wujud
  (kembali kepada medan `latest`, kemudian `"unavailable"`); `next`, `nightly` dan `lts` hanya muncul
  apabila dist-tag tersebut wujud. Permintaan `Cache-Control: no-cache` akan memuat semula kedua-dua carian.

Model saluran (`latest` = v3 sehingga GA 4.0, `next` = rc, `nightly` = binaan `develop`,
`lts` = tampalan v3 selepas GA 4.0) diterangkan dalam `docs/ops/RELEASE_STRATEGY.md`.

## Transkripsi Audio

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data
```

Transkripsikan fail audio menggunakan mana-mana penyedia STT yang dikonfigurasikan. Segmen laluan pertama memilih penyedia natif (`openai/…`, `deepgram/…`). Gateway yang mengeksport semula model vendor lain menggunakan ID berkelayakan
(`openrouter/deepgram/nova-3`).

**Permintaan:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**Respons:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**Contoh ID model:** `openai/whisper-1` (memerlukan kunci OpenAI),
`openrouter/deepgram/nova-3` (memerlukan kunci OpenRouter),
`deepgram/nova-3` (memerlukan kunci Deepgram natif). Permintaan
`deepgram/nova-3` tanpa awalan **tidak** menggunakan OpenRouter.

**Format yang disokong:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`.

**Gemini Live (`gemini/gemini-3.5-transcribe-live`):** transkripsi mod fail melalui WebSocket Gemini Live
(memerlukan kunci API Gemini). Muat naik ditukar kepada PCM mono 16 kHz menggunakan `ffmpeg`
(`ffmpeg` mesti berada dalam `PATH`, melainkan fail tersebut sudah merupakan WAV PCM mono 16 kHz), distrim ke sesi dan
teks yang dimuktamadkan dikembalikan sebagai `{ "text": "..." }`. Medan borang `language` dan `prompt` pilihan
dimajukan. Had: muat naik melebihi 25 MiB atau audio yang dinyahkod melebihi 10 minit akan memberikan respons
`413`; penukaran yang berjalan lebih daripada 60 saat akan dihentikan dan memberikan respons `504`. Kunci API dihantar
hanya dalam pengepala `x-goog-api-key`, tidak pernah dalam URL WebSocket.

## Had Token

Had **token** bagi setiap kunci API (berbeza daripada Bajet berasaskan USD di atas). Dikuatkuasakan sebaris pada laluan permintaan: apabila penggunaan tetingkap semasa sesuatu kunci mencapai hadnya, permintaan ditolak dengan `429 Too Many Requests`. Had boleh dikhususkan kepada `model` tertentu, `provider`, atau digunakan secara `global` merentasi kunci; apabila beberapa had sepadan dengan sesuatu permintaan, had yang paling ketat akan digunakan.

```bash
# Senaraikan had token sesuatu kunci (termasuk penggunaan tetingkap semasa)
GET /api/usage/token-limits?apiKeyId=key-123

# Cipta atau kemas kini had token
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Padam had token mengikut id
DELETE /api/usage/token-limits?id=tl-abc
```

> **Nota skema** (`setTokenLimitSchema`): `apiKeyId` dan `scopeType` (`model` | `provider` | `global`) diperlukan. `scopeValue` diperlukan melainkan `scopeType` ialah `global` (contohnya, id model untuk skop `model`, id penyedia untuk skop `provider`). `tokenLimit` mestilah integer positif (ditukar daripada rentetan). Pilihan: `id` (tinggalkan untuk mencipta, bekalkan untuk mengemas kini), `resetInterval` (`daily` | `weekly` | `monthly`, lalai `monthly`), `resetTime` (`HH:MM`), `enabled` (lalai `true`). Respons `GET` memperkaya setiap had dengan `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, dan `nextResetAt`. Ini ialah titik akhir kelas pengurusan (pengesahan dikuatkuasakan secara berpusat oleh saluran paip authz).

## Pemprosesan Permintaan

1. Klien menghantar permintaan ke `/v1/*`
2. Pengendali laluan memanggil `handleChat`, `handleEmbedding`, `handleAudioTranscription`, atau `handleImageGeneration`
3. Model diselesaikan (penyedia/model secara langsung atau alias/gabungan)
4. Bukti kelayakan dipilih daripada pangkalan data tempatan dengan penapisan ketersediaan akaun
5. Untuk chat: `handleChatCore` menyemak cache semantik/tandatangan dan menyelesaikan tetapan pemampatan gabungan
6. Pemampatan proaktif dijalankan sebelum penterjemahan penyedia apabila didayakan (`lite`, Caveman, RTK, atau bertindan)
7. Pelaksana penyedia menghantar permintaan huluan
8. Respons diterjemahkan kembali kepada format klien (chat) atau dikembalikan seadanya (embeddings/imej/audio)
9. Penggunaan, analitik pemampatan, dan log permintaan direkodkan
10. Fallback digunakan apabila berlaku ralat mengikut peraturan gabungan

Rujukan seni bina penuh: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Ketahanan (dilanjutkan)

OmniRoute menyediakan tiga mekanisme kegagalan sementara yang bebas; endpoint pengurusan di bawah membolehkan operator membacanya dan mengatasinya:

| Skop                       | Penyimpanan keadaan                        | Baca                                      | Tetapkan semula / kosongkan                                     |
| -------------------------- | ------------------------------------------ | ----------------------------------------- | --------------------------------------------------------------- |
| Pemutus provider           | `domain_circuit_breakers` + dalam memori   | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                    |
| Tempoh bertenang sambungan | `rateLimitedUntil` pada sambungan provider | `/api/rate-limits`, `/api/providers/[id]` | (didayakan semula secara malas; kosongkan melalui PUT provider) |
| Sekatan model              | Registry ketersediaan model dalam memori   | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                        |

`PATCH /api/resilience` menerima penggantian pemutus provider di bawah `providerBreaker.oauth` dan `providerBreaker.apikey`. Setiap profil menyokong `degradationThreshold`, `failureThreshold`, dan `resetTimeoutMs`; medan yang sama didedahkan dalam Papan Pemuka → Tetapan → Ketahanan.

```bash
# Kosongkan sekatan satu model
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Kosongkan semua sekatan
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Rujukan konseptual penuh dan nilai lalai pemutus: lihat [`CLAUDE.md`](../../CLAUDE.md) → "Keadaan Runtime Ketahanan" dan [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Baris Giliran Had Kadar & Jaring Keselamatan Pengaktifan Automatik

- **Laluan tulis yang disokong**: `POST /api/rate-limits` dengan badan `{"connectionId": "<id>", "enabled": true|false}` ialah endpoint pengurusan yang disokong untuk menogol perlindungan had kadar bagi sambungan. `PUT /api/providers/[id]` sengaja tidak mengubah atau menogol `rateLimitProtection` (#11278).
- **Semantik `enabled: false`**: Menetapkan `enabled: false` mengalih keluar perlindungan eksplisit bagi sambungan tersebut, tetapi **tidak** mengecualikan sambungan kunci API yang aktif daripada jaring keselamatan pengaktifan automatik global (`autoEnableApiKeyProviders = true`). Dalam `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), `false` dan `undefined` adalah setara; sambungan kunci API aktif tanpa perlindungan eksplisit kekal dilindungi di bawah jaring keselamatan pengaktifan automatik.
- **Penyahdayaan global**: Untuk menjalankan sambungan kunci API tanpa baris giliran had kadar, nyahdayakan jaring keselamatan secara global melalui `RATE_LIMIT_AUTO_ENABLE=false` (env) atau `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Tetapan → Ketahanan / `PATCH /api/resilience`).

## Pelayan A2A

OmniRoute menyediakan titik akhir JSON-RPC 2.0 A2A (Agent-to-Agent) serta pembalut REST untuk tujuan pemeriksaan/papan pemuka.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # pilihan melainkan OMNIROUTE_API_KEY ditetapkan
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Kaedah yang disokong (semuanya dikawal oleh `settings.a2aEnabled`):

| Kaedah           | Penerangan                                                                 |
| ---------------- | -------------------------------------------------------------------------- |
| `message/send`   | Pelaksanaan kemahiran segerak; mengembalikan `{task, artifacts, metadata}` |
| `message/stream` | Pelaksanaan SSE penstriman bagi set kemahiran yang sama                    |
| `tasks/get`      | Mendapatkan tugas berdasarkan `taskId`                                     |
| `tasks/cancel`   | Membatalkan tugas berdasarkan `taskId`                                     |

Kemahiran terbina dalam: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Kad Ejen

```bash
GET /.well-known/agent.json
```

Mengembalikan kad ejen A2A awam (nama, penerangan, keupayaan, katalog kemahiran, skema pengesahan) — dicache secara awam selama 1 jam. Tiada pengesahan diperlukan.

### Pembantu REST

| Kaedah | Laluan                       | Penerangan                                                                                                            |
| ------ | ---------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | Status A2A diaktifkan + statistik tugas + ringkasan kad ejen yang dicache                                             |
| GET    | `/api/a2a/tasks`             | Senaraikan tugas — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Belum dilaksanakan sebagai pembantu REST — cipta melalui JSON-RPC `message/send`)                                    |
| GET    | `/api/a2a/tasks/[id]`        | Dapatkan satu tugas                                                                                                   |
| POST   | `/api/a2a/tasks/[id]/cancel` | Batalkan satu tugas                                                                                                   |

**Pengesahan:** pembantu REST berjalan tanpa pengesahan pengurusan (boleh dibaca melalui papan pemuka); laluan JSON-RPC `/a2a` menggunakan Bearer `OMNIROUTE_API_KEY` jika dikonfigurasikan.

## Pengesahan

Lihat [Pengesahan Pengurusan](../guides/MANAGEMENT-AUTH.md) untuk empat
keluarga kelayakan (sesi papan pemuka, token CLI tempatan, Token Akses `oma_live_…`, kunci API berskop pengurusan) dan perbezaannya daripada kunci inferens.

- Laluan papan pemuka (`/dashboard/*`) menggunakan kuki `auth_token`
- Log masuk menggunakan cincangan kata laluan yang disimpan; kembali kepada `INITIAL_PASSWORD`
- Togol `requireLogin` boleh ditukar melalui `/api/settings/require-login`
- Laluan `/v1/*` secara pilihan memerlukan kunci API Bearer apabila `REQUIRE_API_KEY=true`
- "token pengurusan" / "kunci API berskop pengurusan" dalam rujukan ini bermaksud salah satu keluarga dalam panduan tersebut — bukan jenis rahsia tambahan yang tidak ditakrifkan

> **Perubahan pecah (v3.8.0)** — `/api/v1/agents/tasks/*` dan titik akhir pengurusan tempoh bertenang kini memerlukan **pengesahan pengurusan** (kuki `auth_token` papan pemuka atau kunci API berskop pengurusan). Klien yang sebelum ini memanggil laluan ini tanpa pengesahan akan menerima `401 Unauthorized`. Lihat komit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
