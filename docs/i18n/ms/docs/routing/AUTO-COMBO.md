## Penghalaan Automatik Tanpa Konfigurasi (awalan `auto/`)

> **BAHARU:** Penciptaan kombo tidak diperlukan. Gunakan awalan `auto/` secara langsung dalam mana-mana klien.

### Contoh Ringkas

| ID Model       | Varian  | Tingkah Laku                                                                                    |
| -------------- | ------- | ----------------------------------------------------------------------------------------------- |
| `auto`         | lalai   | Semua penyedia yang disambungkan, strategi LKGP, pemberat seimbang                              |
| `auto/coding`  | coding  | Pemberat yang mengutamakan kualiti, sesuai untuk penjanaan kod                                  |
| `auto/fast`    | fast    | Pemilihan berwajaran dengan kependaman rendah                                                   |
| `auto/cheap`   | cheap   | Penghalaan yang dioptimumkan untuk kos (kos terendah didahulukan)                               |
| `auto/offline` | offline | Mengutamakan penyedia dengan ketersediaan kuota tertinggi                                       |
| `auto/smart`   | smart   | Mengutamakan kualiti + kadar penerokaan lebih tinggi (10%) untuk penemuan model yang lebih baik |
| `auto/lkgp`    | lkgp    | LKGP eksplisit (sama seperti `auto` lalai)                                                      |
| `auto/chaos`   | chaos   | Pengembangan selari, satu model bagi setiap penyedia (bukan suntikan kegagalan)                 |

### Komposisi Kategori × Tahap (`auto/<category>:<tier>`)

Akhiran gaya OpenRouter memisahkan **jenis laluan** (kategori) daripada **cara mengoptimumkannya** (tahap), supaya anda boleh menggubahnya secara bebas (#4235 Fasa B, `open-sse/services/autoCombo/suffixComposition.ts`):

- **Kategori** (tapis kumpulan calon mengikut keupayaan): `coding` · `reasoning` · `vision` · `chat` · `multimodal`. `vision`/`multimodal` mengekalkan model berkeupayaan penglihatan; `reasoning` mengekalkan model penaakulan/pemikiran.
- **Tahap** (pilih pemberat pemarkahan / penapis kumpulan): `fast` (penghantaran pantas) · `cheap` (alias `floor`, penjimat kos) · `reliable` (kesihatan pemutus litar + kestabilan kependaman) · `free` / `pro` (tapis kumpulan mengikut tahap model melalui `classifyTier` — tahap percuma berbanding premium).

| Contoh                 | Diselesaikan kepada                                                     |
| ---------------------- | ----------------------------------------------------------------------- |
| `auto/coding:fast`     | kumpulan pengekodan, pemberat kependaman rendah                         |
| `auto/coding:cheap`    | kumpulan pengekodan, dioptimumkan untuk kos (alias `auto/coding:floor`) |
| `auto/reasoning:pro`   | model penaakulan/pemikiran sahaja, tahap premium                        |
| `auto/vision`          | model berkeupayaan penglihatan (tiada tahap → pemberat seimbang)        |
| `auto/multimodal:free` | model berkeupayaan multimodal, tahap percuma sahaja                     |

Mana-mana `auto/<category>[:<tier>]` yang sah diselesaikan apabila diperlukan; subset terpilih diiklankan dalam `/v1/models` dan papan pemuka (`AUTO_SUFFIX_VARIANTS` dalam `open-sse/services/autoCombo/builtinCatalog.ts`). Penapisan adalah **gagal-terbuka** — jika sesuatu kekangan tidak sepadan dengan mana-mana model yang disambungkan, kumpulan penuh digunakan supaya penghalaan tidak pernah terjejas. Pemarkah teras (`combo.ts`) tidak berubah; penapis kategori/tahap digunakan dalam `buildAutoCandidates`.

> **Kecerdasan model langsung:** kesesuaian penghalaan automatik dipandu oleh kedudukan **Arena ELO** langsung + data tahap **models.dev** apabila bendera `ARENA_ELO_SYNC_ENABLED` dihidupkan (jika tidak, kembali menggunakan peta kesesuaian statik).

**Cara menggunakan:**

```bash
# Mana-mana alat IDE atau CLI yang menyokong format OpenAI
URL Asas: http://localhost:20128/v1
Kunci API:  <kunci-titik-akhir-anda>

# Dalam kod/konfigurasi anda, tetapkan model kepada:
model: "auto"                 # lalai seimbang
model: "auto/coding"          # terbaik untuk tugas pengekodan
model: "auto/fast"            # paling pantas yang tersedia
model: "auto/cheap"           # paling murah bagi setiap token
```

**Perkara yang berlaku:**

1. OmniRoute mengesan awalan `auto/` dalam `src/sse/handlers/chat.ts`
2. Mendapatkan semua **sambungan penyedia aktif** daripada pangkalan data
3. Menapis kepada sambungan yang mempunyai bukti kelayakan sah (kunci API atau token OAuth)
4. Menentukan model bagi setiap sambungan (`connection.defaultModel` atau model pertama penyedia)
5. Membina **kombo maya** dalam memori (tidak disimpan dalam DB)
6. Menghalakan menggunakan profil pemberat varian yang dipilih + strategi LKGP

**Sifat utama:**

- ✅ **Sentiasa aktif:** Tiada togol, tiada penciptaan kombo, tiada konfigurasi diperlukan
- ✅ **Dinamik:** Mencerminkan penyedia yang sedang disambungkan secara automatik
- ✅ **Kelekatan sesi:** LKGP memastikan penyedia terakhir yang berjaya diberi keutamaan
- ✅ **Menyokong berbilang akaun:** Setiap sambungan penyedia menjadi calon yang berasingan
- ✅ **Tiada penulisan DB:** Kombo maya hanya wujud untuk permintaan tersebut, tanpa overhed pengekalan

### Kawalan calon bagi setiap kunci (#7819, Tahap 1+2)

`GET /v1/auto-combo/{channel}/candidates` (`{channel}` = akhiran selepas `auto/`, atau
literal `auto` untuk saluran asas) ialah titik akhir **baca sahaja** yang menyenaraikan
kumpulan calon semasa bagi saluran `auto/*` yang dilengkapi dengan status kebolehcapaian langsung, dengan menggunakan semula
bacaan ketahanan sedia ada (bukan `state` pemutus mentah):

- pemutus litar penyedia — `getCircuitBreaker(provider).getStatus()` / `.canExecute()`
- tempoh bertenang sambungan — `rateLimitedUntil` / `testStatus` pada baris
  `provider_connections` yang telah diselesaikan
- penguncian model — `isModelLocked(provider, connectionId, model)`

Setiap calon turut membawa bendera `excluded` bagi kunci API ini. Pengecualian disimpan
bagi setiap kunci API (jadual `auto_candidate_overrides`, migrasi `128`) — OmniRoute ialah
sistem penyewa tunggal tanpa jadual `users`, maka `apiKeyId` ialah identiti sebenar
bagi setiap pemanggil yang paling hampir — dan dikuatkuasakan pada titik sempit kumpulan calon dalam
`open-sse/services/autoCombo/virtualFactory.ts` melalui
`filterExcludedCandidates()` yang tulen dan diuji unit (`open-sse/services/autoCombo/candidateOverrides.ts`).
Penapis ini bersifat **gagal-terbuka**: apiKeyId/saluran yang tidak ditetapkan atau kegagalan carian DB kedua-duanya
membiarkan kumpulan tidak ditapis, supaya pengendali tanpa tindanan yang dikonfigurasikan melihat penghalaan
yang serupa bait demi bait seperti sebelum ciri ini.

**Ditangguhkan kepada isu susulan:** pemberat bagi setiap calon + pengisihan eksplisit (Tahap 3
— disalurkan ke laluan strategi berwajaran/keutamaan sedia ada) dan menyematkan strategi
`combo.ts` tertentu bagi setiap saluran `auto/*` (Tahap 4). Lihat rancangan #7819 untuk persoalan
terbuka sama ada penggantian harus kekal bagi setiap kunci API atau menjadi global berdasarkan
model penyewa tunggal.

**Di sebalik tabir:**

```txt
Permintaan: { model: "auto/coding" }
   ↓
src/sse/handlers/chat.ts mengesan awalan
   ↓
createVirtualAutoCombo('coding') → candidatePool daripada sambungan aktif
   ↓
handleComboChat (enjin yang sama seperti kombo tersimpan)
   ↓
Pemarkahan automatik memilih penyedia/model terbaik bagi setiap permintaan
```

**Fail pelaksanaan:**

| Fail                                                      | Tujuan                                              |
| --------------------------------------------------------- | --------------------------------------------------- |
| `open-sse/services/autoCombo/autoPrefix.ts`               | Penghurai awalan (`parseAutoPrefix`)                |
| `open-sse/services/autoCombo/virtualFactory.ts`           | Mencipta objek `AutoComboConfig` maya               |
| `open-sse/services/autoCombo/providerRegistryAccessor.ts` | Cangkuk ujian untuk mengolah penyedia daftar tiruan |
| `src/sse/handlers/chat.ts`                                | Penyepaduan: pintasan awal awalan automatik         |
| `src/shared/constants/providers.ts`                       | Entri sistem `SYSTEM_PROVIDERS.auto`                |

## Pilihan akaun untuk kombo Auto yang disimpan

Editor Auto Pintar menawarkan pilihan** Pilihan akaun** bahagian. Setiap sambungan boleh Diutamakan, Normal (lalai), Rizab, atau Dikecualikan. Berbilang sambungan boleh berkongsi satu peringkat. Auto memilih dalam peringkat pertama yang layak, mengekalkan tingkah laku scoring/router di sana; percubaan gagal jatuh ke akaun konkrit yang tinggal, diutamakan sebelum biasa sebelum rizab. Sambungan yang dikecualikan tidak pernah digunakan oleh kombo ini.

Tetapan disimpan sebagai `config.accountPreferences`, dikunci oleh sambungan ID:

```json
{
  "accountPreferences": {
    "connection-a": "preferred",
    "connection-b": "preferred",
    "connection-c": "reserve",
    "connection-d": "excluded"
  }
}
```

Peta yang ditinggalkan atau kosong mengekalkan penghalaan sedia ada. Keutamaan tidak mendayakan sambungan yang dilumpuhkan, memberikan akses kunci API, memulihkan calon yang disekat kuota atau memintas semakan belanjawan. Setiap percubaan adalah terhad kepada sambungan konkritnya, jadi sandaran akaun tidak boleh melompat peringkat di belakang penghala kombo. Perkaitan sesi sedia ada mungkin mengekalkan akaun yang layak; mengecualikan akaun terikat kepada pusingan asli, berhenti pusingan itu dan bukannya menukar akaun secara senyap.

Keutamaan yang dikonfigurasikan menggunakan laluan Auto sedar akaun: pintasan cache konteks yang tidak terikat, saluran paip pintar, huru-hara dan bayangan tidak dihantar. Lindung nilai spekulatif dilumpuhkan untuk permintaan ini jadi akaun rizab tidak boleh berlumba dengan akaun pilihan. Strategi kombo lain tidak mentafsir tetapan ini. Menukar kombo dari Auto mengekalkan pilihan yang disimpan untuk pertukaran kemudian kembali.

## Nama Combo yang Sepadan dengan Id Model Sebenar

Combo yang `name`-nya sama dengan id model biasa (contohnya combo bernama
`gpt-5.5`) ialah **corak yang disengajakan dan disokong**, bukannya pepijat: ia merupakan
mekanisme sandaran penyedia bagi setiap id model yang didokumentasikan dalam
[#6940](https://github.com/diegosouzapw/OmniRoute/issues/6940). Oleh sebab resolusi combo
disemak sebelum resolusi id model biasa
(`getComboForModel()` dalam `src/sse/services/model.ts`), permintaan untuk id biasa
`gpt-5.5` dihalakan melalui sasaran combo tersebut (contohnya
`acme-responses/gpt-5.5`, `backup-responses/gpt-5.5`) dan bukannya terus kepada
satu penyedia — ini menggunakan semula keutamaan combo-sebelum-penulisan-semula yang dibina untuk
[#3227/#3233](https://github.com/diegosouzapw/OmniRoute/issues/3227) dan
diuji bagi regresi oleh `tests/unit/responses-combo-resolution-3227.test.ts` dan
`tests/unit/combo-name-codex-responses-rewrite.test.ts`.

Mencipta atau menamakan semula combo kepada nama yang membayangi id model sebenar
**tidak akan sekali-kali ditolak** — tindakan sedemikian akan menjejaskan aliran kerja yang didokumentasikan ini. Sebaliknya
(#8530), `POST /api/combos` dan `PUT /api/combos/[id]` melampirkan medan
`warning` yang tidak menyekat pada respons apabila nama (baharu) bertembung dengan id
model sebenar:

```json
{
  "warning": {
    "code": "COMBO_NAME_SHADOWS_MODEL",
    "modelId": "gpt-5.5",
    "providerId": "openai"
  }
}
```

Semasa pemulaan, `scanComboModelNameCollisionsAtBoot()`
(`src/instrumentation-node.ts`) turut merekodkan amaran `[STARTUP]` satu baris
yang menyenaraikan setiap combo sedia ada yang membayangi id model, supaya pengendali yang
menghadapi perkara ini secara tidak sengaja (dan bukannya dengan sengaja, seperti dalam #6940) menerima isyarat.
Pembantu pengesanan terletak dalam `src/lib/combos/modelNameCollision.ts`.

## Memanggil Combo Tersuai daripada Klien

Combo tersimpan (Settings → Combos) hanya digunakan apabila klien menghantar **nama tepat** combo tersebut dalam medan `model` — tiada pemadanan kabur atau separa bagi nama combo, dan tiada awalan `auto/` yang terlibat. Urutan resolusi (`getComboForModel()` dalam `src/sse/services/model.ts`):

1. padanan tepat nama combo (`model: "my-combo"`),
2. awalan `combo/<name>` (`model: "combo/my-combo"`),
3. pemetaan glob model→combo (`/api/model-combo-mappings`).

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"my-combo","messages":[{"role":"user","content":"Hello"}]}'
```

Dua kesilapan lazim:

- **`auto` tidak menggunakan combo anda.** `auto`/`auto/*` membina kumpulan calonnya sendiri tanpa konfigurasi dan hanya merujuk combo tersimpan jika sesuatu combo benar-benar dinamakan `auto` (tidak disyorkan). Untuk menghalakan melalui combo, hantar nama tepatnya — bukan `auto`.
- **`openrouter/auto` ialah produk OpenRouter berbayar yang sebenar** ("Auto Best Available"), bukannya alias OmniRoute. Ia merupakan entri model statik tunggal dalam daftar OpenRouter (`open-sse/config/providers/registry/openrouter/index.ts`) dan dibilkan secara berasingan. Gunakan Settings → Routing → Hide paid models untuk mengecualikannya daripada kumpulan `auto`.

Lihat [#7992](https://github.com/diegosouzapw/OmniRoute/issues/7992) dan [#7111](https://github.com/diegosouzapw/OmniRoute/issues/7111) untuk kekeliruan asal yang didokumentasikan di sini.

## Cara Ia Berfungsi (Auto-Combo Berterusan)

Enjin Auto-Combo memilih penyedia/model terbaik secara dinamik bagi setiap permintaan menggunakan **fungsi pemarkahan 16 faktor** (ditakrifkan dalam `open-sse/services/autoCombo/scoring.ts` → `DEFAULT_WEIGHTS`). Pemberat lalai berjumlah `1.0`; pemberat tersuai dinormalkan semula oleh `normalizeScoringWeights()`. Dua daripada enam belas faktor — `cacheAffinity` dan `resetWindowAffinity` — mempunyai pemberat lalai `0`; `reliability` mempunyai nilai `0` dalam `DEFAULT_WEIGHTS` tetapi `0.03` dalam pek generik dan `0.04` dalam `reliability-first`, manakala `quality` mempunyai nilai `0.02` dalam pek (`0.03` dalam `quality-first`): kesemuanya masih dikira untuk setiap calon, dan `cacheAffinity` mengawal deduplikasi cache gesaan di luar skor, jadi faktor yang lalai kepada sifar tidak mengundi secara lalai, manakala pek menggunakannya.

| `reliability`         | 0.00           | Bahagian kejayaan yang diperhatikan, `1 - failureRate`, daripada sejarah penggunaan 24 jam dengan ambang minimum sepuluh sampel (metrik masa nyata digunakan sebaliknya); calon tanpa pemerhatian dianggap bernilai 1.0. Dilumpuhkan secara lalai |

Penjejak `quality` dalam memori (`open-sse/services/routing/quality.ts`) kosong
selepas permulaan semula sejuk, jadi setiap calon mendapat skor neutral `0.5` sehingga
pemerhatian pertama direkodkan.

> **Kuota tidak boleh dibaca (#15347).** Apabila penyedia mempunyai pengambil kuota tetapi ia tidak mengembalikan apa-apa yang boleh dibaca
> (pengambilan gagal, kelayakan tiada, penggunaan yang hanya mengandungi mesej, atau snapshot cacat tanpa
> `windows` yang boleh dihuraikan dan tanpa `percentUsed` terhingga, termasuk `percentUsed: null`), calon
> mendapat skor `0` pada paksi `quota` dan skor akhirnya didarab dengan
> `UNREADABLE_QUOTA_SOFT_DEPRIORITIZE_FACTOR` (0.5, `autoStrategy.ts`), mengikut corak penalti lembut
> yang sama seperti penalti status sambungan. Pembacaan penggunaan yang gagal ialah bukti tentang telemetri,
> bukan tentang penyedia, maka ia diletakkan secara ketat di bawah mana-mana pembacaan sebenar, termasuk
> pembacaan yang mengesahkan penggunaan 100%, tetapi tidak pernah disekat sepenuhnya atau disingkirkan. Penyedia
> tanpa had melaporkan `unlimited: true` dan mendapat skor kuota penuh; penyedia tanpa pengambil kuota
> yang didaftarkan langsung tidak mempunyai sumber telemetri dan mengekalkan nilai lalai `100`.

**Jumlah:** `0.1429 + 0.1605 + 0.1429 + 0.1143 + 0.0762 + (7 × 0.0476) + 0.00 + 0.00 + 0.03 + 0.00 = 1.0` seperti yang diisytiharkan dalam `DEFAULT_WEIGHTS`; pemberat yang dikonfigurasikan pengguna dinormalkan semula menjadi taburan oleh `normalizeScoringWeights()` sebelum pemarkahan.

### Semantik `weighted`

`weighted` ialah **cabutan rawak berkadar bagi setiap permintaan**
(`open-sse/services/combo/targetSorters.ts` → `selectWeightedTarget`), bukannya penyama:

- Setiap permintaan memilih **satu** langkah dengan kebarangkalian `weight / totalWeight`; langkah yang selebihnya
  disusun mengikut berat menurun sebagai rantaian sandaran untuk permintaan tersebut.
- Langkah yang beratnya `0` (atau tiada) **tidak pernah dipilih** selagi mana-mana langkah lain mempunyai
  berat > 0 — langkah itu hanya boleh berfungsi sebagai sandaran selepas langkah yang dipilih gagal. Hanya apabila
  semua berat ialah 0, pemilihan menjadi seragam.
- Langkah yang semua sasarannya tidak tersedia — pemutus litar penyedia `OPEN`, tempoh bertenang sambungan,
  kunci keluar model — dialih keluar daripada pemilihan sebelum ia berlaku
  (`open-sse/services/combo/targetResolution.ts`), maka satu langkah yang sihat boleh memenangi setiap permintaan buat sementara waktu.
- `stickyWeightedLimit` (konfigurasi combo, lalai `1` = dimatikan) mengekalkan langkah yang dipilih untuk sejumlah kejayaan berturut-turut sebelum pemilihan semula.

Untuk putaran ketat, gunakan `round-robin`; berat yang sama pada `weighted` memberikan keseimbangan statistik — bukan keseimbangan ketat.

### Mod saluran paip ejen

Combo `pipeline` dengan sekurang-kurangnya dua model boleh memilih penghalaan perancang/pelaksana dengan
`config.agenticOrchestration.enabled`. Sasaran pertama mengendalikan perancangan dan jawapan akhir;
sasaran kedua menghasilkan panggilan alat asli klien. OmniRoute mengesan kesinambungan hasil alat daripada protokol
permintaan, bertanya kepada perancang sama ada pusingan alat yang lain diperlukan, dan secara dinamik menjadikan
pelaksana atau perancang sebagai langkah akhir yang menghadap klien.

`config.agenticOrchestration.contextCompaction` pilihan menggunakan belanjawan muatan berasingan sebelum setiap
penghantaran perancang atau pelaksana. Dayakannya secara eksplisit:

```json
{
  "enabled": true,
  "defaultMaxChars": 400000,
  "targetRatio": 0.72,
  "toolResultMaxChars": 24000,
  "modelMaxChars": { "provider/planner": 175000, "provider/executor": 300000 }
}
```

Ini ialah belanjawan aksara JSON bersiri yang dipilih oleh pengendali, bukan tetingkap konteks token atau had hulu
yang dijamin. ID model tepat mengatasi lalai. Melebihi ambang, pemadatan mengalih keluar definisi alat yang sama,
memendekkan bukti alat yang terlalu besar dengan digest, dan mengalih keluar kumpulan sejarah lengkap yang lama
ke arah nisbah sasaran. Ia mengekalkan arahan sistem/pembangun, permintaan pengguna terkini, pusingan alat terakhir
termasuk panggilan/hasil selari, dan arahan penghalaan utama Gemini. Arahan peringkat teratas dan tetapan alat
dikekalkan. Penanda peninggalan merekodkan sejarah yang dialih keluar; ini ialah pemangkasan deterministik, bukan
ringkasan semantik. Jika konteks yang dipinkan masih melebihi belanjawan, permintaan mengembalikan 413 sebelum
menghubungi model. Apabila pemadatan dilumpuhkan atau berada di bawah ambang, permintaan diteruskan tanpa perubahan.

Pada kesinambungan hasil alat, OmniRoute turut menghentikan pelaksanaan apabila dua pusingan lengkap berturut-turut
mengulangi panggilan alat yang sama dengan hasil yang tidak berubah, atau apabila setiap hasil yang ditandakan secara
eksplisit dalam dua pusingan berturut-turut gagal. Hasil yang berubah membenarkan panggilan berulang (contohnya,
pengundian). Pengawal ini ditetapkan semula pada permintaan pengguna baharu, mengumpulkan panggilan selari menjadi
satu pusingan, dan menyokong sejarah Anthropic, Chat Completions, Responses dan Gemini. Perancang menerima sebab
tersebut dan mengendalikan jawapan akhir walaupun ia meminta pusingan alat yang lain.

Model tambahan selepas sasaran kedua disusun sebagai sandaran pelaksana. Respons HTTP yang gagal atau pengecualian
pengangkutan beralih kepada pelaksana seterusnya, dengan membawa keputusan perancang dan alat asli yang sama, tetapi
menggunakan gesaan langkah dan sambungan terselesai milik pelaksana tersebut. Respons berjaya pertama dikembalikan
tanpa perubahan, termasuk penstriman SSE; kegagalan selepas penstriman berjaya bermula tidak boleh dicuba semula
di sini. Jika semua pelaksana gagal, kegagalan terakhir dikembalikan. Pembatalan oleh klien menghentikan penghantaran.

```json
{
  "strategy": "pipeline",
  "models": [{ "model": "provider/planner" }, { "model": "provider/executor" }],
  "config": {
    "agenticOrchestration": { "enabled": true, "maxToolRounds": 8 }
  }
}
```

Pelaksana boleh menghasilkan berbilang panggilan bebas dalam satu respons. Panggilan bersandar dikendalikan dalam
pusingan hasil alat klien yang seterusnya, dengan perancang menyemak setiap hasil.
`maxToolRounds` lalai kepada `8` dan menerima `1`–`32`; apabila had dicapai, perancang mesti menghasilkan jawapan
akhir terbaik yang tersedia. Keputusan dalaman perancang disimpan dalam penimbal, manakala respons yang dipilih
untuk menghadap klien mengekalkan keutamaan penstriman asal.

### `round-robin` dan pengembangan akaun secara kelompok melekat

Round-robin dilakukan secara berkelompok, bukan satu permintaan bagi setiap langkah:

- `stickyRoundRobinLimit` (konfigurasi combo, kemudian `comboStickyRoundRobinLimit`, kemudian
  `settings.stickyRoundRobinLimit`, lalai **3**) mengekalkan sasaran yang sama untuk sejumlah kejayaan berturut-turut
  sebelum berputar. Tetapkan penggantian combo kepada `1` untuk putaran satu permintaan. Editor combo memaparkan
  nilai berkesan dan lapisan asalnya.
- `connectionAwareExpansion` (konfigurasi combo, kemudian settings, lalai **false**) mengembangkan setiap langkah
  peringkat penyedia menjadi sasaran setiap akaun sebelum putaran. Strategi Kumpulan-B (priority, weighted,
  round-robin, random, p2c, least-used, cost-optimized, lkgp, fill-first, strict-random, context-optimized,
  cache-optimized, context-relay, fusion, pipeline, jev) mengekalkan paparan peringkat penyedia sehingga pilihan
  ini dihidupkan. Editor combo menyediakan inherit / on / off; inherit menggunakan lalai global (off).
- Penghalaan lokaliti cache gesaan (`promptCacheAffinityEnabled`, lalai **true**) menyusun semula sambungan yang
  dipinkan supaya kunci cache yang sepadan kekal pada satu akaun. Ia mengatasi putaran round-robin dan weighted
  merentas langkah setiap akaun yang dipinkan. Matikannya di bawah Tetapan → Lalai Combo jika anda memerlukan
  putaran ketat. Tiada penggantian setiap combo.

Untuk putaran berbilang akaun pada satu model, gunakan **satu langkah akaun dinamik** (`connectionId` kosong,
keseluruhan kumpulan) dengan had melekat `1`, bukan tiga `connectionId` yang dipinkan. Langkah yang dipinkan
berserta afiniti runtuh pada akaun yang sama walaupun pembilang RR terus bergerak.

## Strategi Fusion

`fusion` ialah satu-satunya strategi yang **tidak** memilih satu sasaran sahaja. Ia menghantar gesaan
kepada **setiap model panel secara selari**, kemudian **model penilai** yang boleh dikonfigurasikan mensintesis
satu jawapan akhir daripada semua respons panel. Diport daripada `decolua/9router` huluan
(reka bentuk Fusion OpenRouter); pelaksanaannya terdapat dalam `open-sse/services/fusion.ts`.

Cara ia berfungsi:

0. **Pintasan permintaan dengan alat** — permintaan yang membawa tatasusunan `tools` yang tidak kosong dengan
   `tool_choice` yang tidak ditetapkan secara jelas kepada `"none"` akan melangkau panel sepenuhnya: ia dihalakan terus kepada
   satu model (penilai yang dikonfigurasikan, atau `panel[0]`) dengan `tools`/`tool_choice`
   diteruskan tanpa pengubahsuaian. Ahli panel tidak mempunyai akses kepada alat dan arahan
   sintesis penilai menghalang penghasilan panggilan alat, supaya klien berasaskan ejen/panggilan alat
   memperoleh keputusan panggilan alat sebenar dan bukannya prosa yang disintesis (#6771).
1. **Penghantaran serentak** (hanya untuk permintaan tanpa alat) — gesaan dihantar kepada setiap model
   panel serentak, dengan mod bukan penstriman dipaksa dan alat disingkirkan (penilai memerlukan
   prosa lengkap untuk melakukan sintesis).
2. **Pengumpulan kuorum dengan tempoh ihsan** — sebaik sahaja `minPanel` jawapan diterima, pemasa
   ihsan singkat dimulakan untuk respons yang lewat, kemudian fusion diteruskan dengan apa sahaja yang telah dikumpulkan.
   Ini mengehadkan penalti masa sebenar daripada model paling perlahan, tertakluk pada had masa tamat mutlak.
3. **Sintesis penilai** — jawapan panel dianonimkan (`Source 1`, `Source 2`, … — supaya
   penilai menimbang isi kandungan, bukannya jenama model) dan diberikan kepada penilai, yang menganalisis
   konsensus / percanggahan / liputan separa / pandangan unik / titik buta, kemudian
   menulis **satu** jawapan berwibawa. Panggilan penilai mengekalkan nilai asal `stream`
   milik klien berserta alat, supaya penstriman dan penggunaan alat hiliran masih berfungsi.
4. **Degradasi beransur-ansur** — 0 jawapan panel → `503`; tepat 1 jawapan yang berjaya → jawapan tersebut
   dikembalikan secara terus (tiada apa-apa untuk digabungkan); panel dengan satu model memberikan jawapan secara terus.

Ahli panel juga boleh berupa langkah `combo-ref` (`{kind: "combo-ref", comboName: "..."}`) yang merujuk
kepada combo lain — ia diselesaikan sebagai **satu suara panel kotak hitam** (penghantaran rekursif penuh ke dalam
combo yang dirujuk, bukannya penghantaran serentak kepada sasaran combo tersebut), dengan perlindungan kedalaman/kitaran yang sama
yang telah digunakan oleh setiap strategi lain yang menggunakan combo-ref (#6764).

### Konfigurasi

Dikonfigurasikan pada blob `config` combo (tiada migrasi skema — ia menggunakan semula jadual
`combos` yang sedia ada):

| Medan                                    | Jenis    | Lalai               | Tujuan                                                                                        |
| :--------------------------------------- | :------- | :------------------ | :-------------------------------------------------------------------------------------------- |
| `config.judgeModel`                      | `string` | model panel pertama | Model yang mensintesis jawapan akhir                                                          |
| `config.fusionTuning.minPanel`           | `number` | `2`                 | Jawapan berjaya yang diperlukan sebelum pemasa ihsan bermula (diapit kepada `[2, panelSize]`) |
| `config.fusionTuning.stragglerGraceMs`   | `number` | `8000`              | Tempoh menunggu respons yang lewat setelah kuorum dicapai                                     |
| `config.fusionTuning.panelHardTimeoutMs` | `number` | `90000`             | Had mutlak supaya satu model yang tergantung tidak dapat melengahkan permintaan               |

Nilai lalai terdapat dalam `FUSION_DEFAULTS` (`open-sse/services/fusion.ts`).

## Kilang Kombo Auto Maya

Enjin Auto Combo tidak memerlukan kombo yang dipratakrifkan. Sebaliknya, `open-sse/services/autoCombo/virtualFactory.ts` membina calon secara dinamik:

1. Mengambil `getProviderConnections({ isActive: true })` (semua sambungan yang didayakan)
2. Menapis kepada sambungan yang mempunyai kelayakan sah (kunci API atau token OAuth yang belum tamat tempoh melalui `hasUsableOAuthToken()`)
3. Membuat rujukan silang dengan `getProviderRegistry()` untuk ketersediaan model + harga
4. Bagi setiap tupel `(provider, model, connection)`, membina `VirtualAutoComboCandidate`
5. Memilih `connection.defaultModel` (atau model pertama dalam daftar) sebagai sasaran penghantaran
6. Memberikan skor kepada setiap calon menggunakan `scorePool()` 16 faktor dan pek pemberat varian
7. Mengembalikan `AutoComboConfig` dalam memori yang terhasil untuk `handleComboChat()` — tidak pernah disimpan ke DB

Ini bermakna **penambahan penyedia baharu dengan `auto/*` didayakan akan mengembangkan kumpulan calon secara automatik** — tiada penyuntingan kombo secara manual diperlukan. Kombo maya dibina semula bagi setiap permintaan, jadi sambungan yang baru ditambahkan atau baru kembali sihat akan digunakan serta-merta.

## Pemulihan Kendiri

- **Pengecualian sementara**: Skor < 0.2 → dikecualikan selama 5 minit (undur bertahap, maksimum 30 minit)
- **Kesedaran pemutus litar**: OPEN → dikecualikan secara automatik; HALF_OPEN → permintaan percubaan
- **Mod insiden**: >50% OPEN → lumpuhkan penerokaan, maksimumkan kestabilan
- **Pemulihan tempoh bertenang**: Selepas pengecualian, permintaan pertama ialah "percubaan" dengan tamat masa yang dikurangkan

## Penerokaan Bandit

5% daripada permintaan (boleh dikonfigurasikan) dihalakan kepada penyedia rawak untuk penerokaan. Dilumpuhkan dalam mod insiden.

### Strategi penghala automatik

Kombo `strategy: "auto"` yang berterusan boleh menetapkan `config.routerStrategy` (atau `config.auto.routerStrategy` warisan ) kepada salah satu daripada:

- `rules` — pemarkahan wajaran lalai
- `score` — memilih skor wajaran yang dikonfigurasikan tertinggi. Ikatan yang tepat mengekalkan susunan calon yang dikonfigurasikan; sampel `explorationRate` sedia ada daripada kumpulan kedudukan penuh.
- `cost` / `eco` — pembekal sihat termurah
- `latency` / `fast` — kependaman p95 terendah dengan penalti kebolehpercayaan
- `sla-aware` / `sla` — memilih calon yang memenuhi kependaman p95, kadar ralat dan kos pilihan SLOs
- `lkgp` — terakhir dikenali pembekal yang baik dahulu
- `nadir` — tanya keputusan [Nadir](https://getnadir.com) API model mana dalam kumpulan yang diperlukan segera; ikut serta, gagal-buka kepada `rules`
- `decision` — minta penentu yang dikonfigurasikan (TypeSafe System One, keputusan anda sendiri URL, atau salah satu model kombo sendiri) model mana dalam kumpulan yang sesuai dengan permintaan; di belakang bendera `COMBO_DECISION_ROUTER_ENABLED` lalai, fail-buka kepada `rules`

### Strategi penghala secara terperinci

Enjin auto-kombo mendedahkan 7 boleh pasang**RouterStrategy** pelaksanaan yang boleh anda tukar melalui `config.routerStrategy` (atau warisan `config.auto.routerStrategy`). Setiap strategi memilih satu penyedia daripada kumpulan calon, diberi `RoutingContext` (jenis tugasan, petunjuk tool/vision, anggaran token, dasar SLA pilihan, penyedia pilihan yang paling terkenal).

#### 1. `rules` (lalai) — 16-faktor pemarkahan wajaran

Membungkus enjin pemarkahan sedia ada. Tapis keluar calon pemutus litar `OPEN`, kemudian jalankan `scorePool()` dengan jenis tugasan semasa dan `getTaskFitness()`, memilih penyedia yang mendapat markah tertinggi.

```ts
class RulesStrategyImpl implements RouterStrategy {
  readonly name = "rules";
  readonly description = "16-factor weighted scoring (see DEFAULT_WEIGHTS)";

  select(pool, context) {
    const eligible = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const ranked = scorePool(
      eligible.length > 0 ? eligible : pool,
      context.taskType,
      undefined,
      getTaskFitness
    );
    return { provider: ranked[0].provider /* ... */ };
  }
}
```

**Bila nak guna** : Lalai. Gunakan apabila anda mahukan pertukaran yang seimbang merentas semua isyarat.

**Alias** : `rules` (tiada alias)

---

#### 2. `cost` / `eco` — pembekal sihat termurah

Isih kumpulan calon mengikut `costPer1MTokens` (menaik) dan pilih yang paling murah. Tapis calon `OPEN` dahulu.

```ts
class CostStrategyImpl implements RouterStrategy {
  readonly name = "cost";
  readonly description = "Always selects cheapest available provider";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort((a, b) => a.costPer1MTokens - b.costPer1MTokens);
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**Bila nak guna** : Beban kerja sensitif kos, pemprosesan kelompok atau kerja latar belakang.

**Alias** : `cost`, `eco`

---

#### 3. `latency` / `fast` — kependaman p95 terendah dengan penalti kebolehpercayaan

Disusun mengikut `p95LatencyMs + (errorRate * 1000)`. Penalti kadar ralat memastikan penyedia yang tidak boleh dipercayai diberi kedudukan lebih rendah walaupun kependaman nominal mereka rendah.

```ts
class LatencyStrategyImpl implements RouterStrategy {
  readonly name = "latency";
  readonly description = "Prioritizes lowest p95 latency with reliability weighting";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort(
      (a, b) => a.p95LatencyMs + a.errorRate * 1000 - (b.p95LatencyMs + b.errorRate * 1000)
    );
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**Bila nak guna** : Beban kerja sensitif kependaman seperti sembang masa nyata, autolengkap atau pembantu pengekodan interaktif.

**Alias** : `latency`, `fast`

---

#### 4. `sla-aware` / `sla` — latency/error/cost SLO pematuhan

Menjaringkan setiap calon mengikut tahap ia memenuhi dasar SLO yang dikonfigurasikan:

| Faktor          | Berat badan | Formula                                               |
| --------------- | ----------- | ----------------------------------------------------- |
| Skor kependaman | 35%         | `threshold / max(value, ε)`                           |
| Skor ralat      | 35%         | `threshold / max(value, ε)`                           |
| Skor kesihatan  | 15%         | `1.0` (CLOSED) / `0.5` (HALF_OPEN) / `0.0` (OPEN)     |
| Skor kos        | 10%         | `threshold / max(value, ε)` atau songsang dinormalkan |
| Skor kestabilan | 5%          | stddev kependaman ternormal songsang                  |

Apabila `hardConstraints: true`, calon diisih terutamanya mengikut** skor pelanggaran** (berapa jauh mereka melebihi sebarang SLO), kemudian dengan skor komposit. Jika tidak, ia hanya skor komposit.

```ts
class SLAStrategyImpl implements RouterStrategy {
  readonly name = "sla-aware";
  readonly description =
    "Selects the provider most likely to satisfy latency, error-rate, and cost SLOs";

  select(pool, context) {
    // ... scores each candidate against policy: { targetP95Ms, maxErrorRate, maxCostPer1MTokens, hardConstraints }
  }
}
```

**SLA** (ditetapkan pada konfigurasi kombo):

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "sla-aware",
    "slaTargetP95Ms": 1500,
    "slaMaxErrorRate": 0.05,
    "slaMaxCostPer1MTokens": 5,
    "slaHardConstraints": true
  }
}
```

**Bila nak guna** : Beban kerja pengeluaran dengan kependaman yang ketat, kadar ralat atau belanjawan kos.

**Alias** : `sla-aware`, `sla`

---

#### 5. `lkgp` — terakhir diketahui pembekal yang baik dahulu

Mencuba** pembekal baik yang terakhir diketahui** (jika ditetapkan) dahulu, kemudian kembali kepada strategi `rules`. Berguna untuk kelekatan sesi — pembekal yang sama mengendalikan permintaan susulan dalam perbualan.

```ts
class LKGPStrategyImpl implements RouterStrategy {
  readonly name = "lkgp";
  readonly description = "Tries last known good provider first, then falls back to rules";

  select(pool, context) {
    if (context.lkgpEnabled === false) {
      return getStrategy("rules").select(pool, context);
    }

    if (context.lastKnownGoodProvider) {
      const candidates = pool.filter(
        (c) => c.provider === context.lastKnownGoodProvider && c.circuitBreakerState !== "OPEN"
      );
      if (candidates.length > 0) {
        return { provider: candidates[0].provider /* ... */ };
      }
    }

    // Fallback to rules strategy
    return getStrategy("rules").select(pool, context);
  }
}
```

**Bila nak guna** : Perbualan berbilang pusingan di mana anda mahu penyedia yang sama mengendalikan permintaan susulan (cth, untuk caching, kesinambungan konteks atau ketekalan harga).

**Alias** : `lkgp` (tiada alias)

---

#### 6. `nadir` — pilihan model yang sedar segera melalui Nadir

Setiap strategi di atas meletakkan calon mengikut telemetri mereka sendiri; tiada seorang pun daripada mereka membaca permintaan itu. `nadir` menghantar giliran pengguna terakhir serta id model kumpulan kepada keputusan [Nadir](https://getnadir.com) API (`POST /v1/bucket`) dan laluan ke model yang dipilih Nadir daripada menu itu (`simple` → model berkemampuan paling murah, `complex` → yang sempadan). Sambungan yang menyampaikan model itu masih dipilih oleh `rules`, jadi kuota, kesihatan dan kos terus menentukan akaun yang mana.

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "nadir",
    "nadir": {
      "apiKey": "ndr_...",
      "baseUrl": "https://api.getnadir.com",
      "timeoutMs": 2000
    }
  }
}
```

`OMNIROUTE_NADIR_API_KEY` dan `OMNIROUTE_NADIR_BASE_URL` ialah sandaran env untuk dua rentetan. `baseUrl` hanya diperlukan untuk Nadir yang dihoskan sendiri ( `/v1` yang ketinggalan boleh diterima). Panggilan tanpa kunci tiba di peringkat awanama Nadir, yang dihadkan kadar setiap IP. Dengan kunci ( [buat satu](https://app.getnadir.com/dashboard/api-keys) ), setiap keputusan dilog ke papan pemuka Nadir anda. Persediaan dan pengesahan penuh: [getnadir.com/docs/gateway-omniroute](https://getnadir.com/docs/gateway-omniroute/).

Perkara yang meninggalkan kotak: teks mesej pengguna terakhir (16k aksara pertama), id model calon dan teg saluran `source: "omniroute"`. Tiada gesaan sistem, sejarah, alatan atau pengepala.

Tingkah laku kegagalan adalah terbuka-gagal: tamat masa (lalai 2000 ms), non-2xx, hos yang tidak boleh dicapai, respons yang salah bentuk atau pilihan di luar kumpulan menyelesaikan keputusan `rules` dan sebabnya diawali `NadirStrategy: fallback (…)`. Selepas panggilan gagal, strategi melangkau rangkaian selama 30 saat, jadi pemadaman kos satu tamat masa setiap 30 saat dan bukannya satu bagi setiap permintaan. Peristiwa penghalaan melaporkan `strategy: "nadir"` hanya apabila Nadir benar-benar membuat pilihan.

**Bila nak guna** : trafik kesukaran bercampur di kolam yang merangkumi peringkat model (model kecil, pertengahan dan sempadan), di mana sentiasa sempadan ialah kos yang anda ingin potong.

**Alias** : `nadir` (tiada alias)

---

#### 7. `decision` — pluggable decider memilih model

`decision` bertanya kepada a** penentu** model mana dalam kumpulan yang sesuai dengan permintaan, kemudian sempitkan kumpulan kepada model tersebut dan benarkan `rules` memilih sambungan (kuota, kesihatan dan kos masih memilih akaun). Penentu ditetapkan dalam blok keputusan kombo — `config.decision` apabila tombol penghala terletak di bahagian atas `config` (apa yang ditulis oleh papan pemuka), atau `config.auto.decision` di sebelah `config.auto.routerStrategy`:

| `decider`     | Siapa jawab                                                                                                                   | Keperluan                                      |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `systemone`   | TypeSafe Sistem Satu (`POST https://api.typesafe.ai/v1/systemone`), model lalai `jev-latest`                                  | sambungan `typesafe` atau kunci env            |
| `http`        | penentu anda sendiri di `baseUrl`: `wire: "systemone"` (`{baseUrl}/v1/systemone`) atau `"openai-chat"` (penyelesaian sembang) | `baseUrl` + `model`; kunci pilihan             |
| `combo-model` | salah satu model pembekal anda, dipanggil dalam proses seperti hakim gabungan                                                 | `model` sebagai `provider/model` (tiada kombo) |

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "decision",
    "decision": {
      "decider": "http",
      "baseUrl": "https://decider.example.com",
      "wire": "openai-chat",
      "model": "qwen-small",
      "connectionId": "<stored connection id>",
      "timeoutMs": 2000,
      "minConfidence": 0.6,
      "descriptions": { "gpt-4o-mini": "Quick drafts and short answers" }
    }
  }
}
```

Medan (disahkan oleh skema yang ketat pada simpan dan sekali lagi pada masa permintaan):

- `decider` — `systemone`, `http` atau `combo-model`.
- model `model` — TypeSafe, model keputusan di URL anda atau `provider/model` panggilan model kombo (sehingga 200 aksara).
- `baseUrl` — `http` sahaja: `http(s)` URL sehingga 500 aksara, tanpa bukti kelayakan, pertanyaan atau serpihan. URL yang menunjuk pada OmniRoute ini (gelung belakang + `PORT`) ditolak.
- `wire` — `http` sahaja: `systemone` (lalai) atau `openai-chat`.
- `connectionId` — sambungan tersimpan yang kuncinya digunakan (hanya di dalam sambungan kunci API panggilan yang dibenarkan). Tanpa itu, `systemone` membaca sambungan `typesafe` dan setiap penentu rangkaian kembali kepada `OMNIROUTE_DECISION_API_KEY`. Tiada medan `apiKey` : kunci tidak pernah disimpan dalam kombo.
- `timeoutMs` — integer, 100–5000, lalai 2000.
- `minConfidence` — 0–1; jawapan keyakinan rendah kembali kepada `rules` (penentu yang melaporkan tiada keyakinan dikira sebagai 0).
- `descriptions` — sehingga 50 entri (kunci sehingga 300, teks sehingga 1000 aksara), dikunci oleh id model atau `provider/model`; entri yang tidak ditetapkan mendapat perihalan peringkat kos yang dijana.

**Bendera.** `COMBO_DECISION_ROUTER_ENABLED` ( `false` lalai ) gerbang setiap penentu. Semasa ia dimatikan, kombo `decision` tidak membaca bukti kelayakan, tidak membuat panggilan dan laluan dengan `rules`; log itu berkata `fallback (disabled)`. Kunci yang disimpan sahaja tidak pernah menghidupkannya. Kombo tanpa blok keputusan tidak terjejas sama sekali.

**Apa yang meninggalkan kotak.** Hanya teks mesej pengguna terakhir (sehingga 8000 aksara; chat/Claude `messages` atau Responses `input`) dan menu id model dengan penerangannya. Jangan sekali-kali gesaan sistem, Respons `instructions`, alatan, sejarah, pengepala atau data akaun. Panggilan rangkaian melalui pengawal keluar penyedia tanpa cuba semula, tiada ubah hala dan had respons 64 KB. Panggilan `combo-model` adalah bukan penstriman, bebas alat, `temperature: 0`, dengan belanjawan 256 token; keputusan yang dimulakan dalam panggilan keputusan ditolak.

**Tingkah laku kegagalan** adalah fail-open: sebarang kegagalan diselesaikan kepada keputusan `rules`, dan sebabnya berbunyi `decision(<decider>): fallback (<reason>)`, dengan `<reason>` satu daripada `disabled`, `not_configured`, `missing_credential`, `timeout`, `http_error`, `invalid_response`, `out_of_menu`, `refused`, `cooldown`, `network_error`, `recursion`, `low_confidence`, `single_option` atau `no_user_text` Selepas tamat masa, ralat HTTP atau ralat rangkaian titik tamat dilangkau selama 30 saat. Pilihan yang berjaya berbunyi `decision(<decider>): selected <model> from <n>; confidence <c> (<rules reason>)`. Tiada URL, kunci, gesaan atau badan hulu mencapai log.

Pembina kombo menunjukkan medan ini apabila strategi penghala ialah `decision`, dengan perihalan yang dijana sebagai ruang letak dan** Keputusan ujian** butang yang memanggil `POST /api/combos/decision-preview` sekali dengan tetapan yang belum disimpan (bendera yang sama).

**Bila nak guna** : trafik kesukaran bercampur di mana anda mahu peringkat dipilih setiap permintaan oleh pengelas yang anda pilih, bukan oleh Nadir secara khusus.

**Alias** : `decision` (tiada alias)

### Strategi penghala tersuai

Anda boleh mendaftar pelaksanaan `RouterStrategy` anda sendiri melalui API awam :

```ts
import {
  registerStrategy,
  type RouterStrategy,
} from "@omniroute/open-sse/services/autoCombo/routerStrategy";

class MyCustomStrategy implements RouterStrategy {
  readonly name = "my-custom";
  readonly description = "My custom routing strategy";

  select(pool, context) {
    // Your routing logic here
    return {
      provider: pool[0].provider,
      model: pool[0].model,
      strategy: this.name,
      reason: "MyCustomStrategy: ...",
      candidatesConsidered: pool.length,
      finalScore: 1.0,
    };
  }
}

registerStrategy("my-custom", new MyCustomStrategy());
```

Kemudian gunakannya:

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "my-custom"
  }
}
```

## Kesesuaian Tugas

Lebih 30 model dinilai merentas 6 jenis tugas (`coding`, `review`, `planning`, `analysis`, `debugging`, `documentation`). Menyokong corak kad bebas (contohnya, `*-coder` → skor pengekodan tinggi).

## Ringkasan Varian Auto

Termasuk `auto` asas (lalai) serta 6 nilai `AutoVariant` yang diisytiharkan dalam `autoPrefix.ts`, terdapat **7 ID model yang boleh digunakan**:

`auto`, `auto/coding`, `auto/fast`, `auto/cheap`, `auto/offline`, `auto/smart`, `auto/lkgp`

(`AutoVariant` itu sendiri menyenaraikan 6 nilai; pilihan ke-7 ialah "tiada varian" — `auto` asas — yang dikendalikan oleh `parseAutoPrefix()` sebagai `variant: undefined`.)

## Cara peringkat berfungsi dalam Auto-Combo

Fungsi pemarkahan 16 faktor (`open-sse/services/autoCombo/scoring.ts`) menganggap keahlian
peringkat sebagai dua isyarat: `tierPriority` (0.0476) dan `tierAffinity` (0.0476). Lihat
[jadual faktor pemarkahan](#how-it-works-persisted-auto-combos) kanonik di atas untuk set
`DEFAULT_WEIGHTS` penuh — penggantian bagi setiap pek (ship-fast/cost-saver/quality-first/
offline-friendly) disenaraikan dalam jadual "Profil berat bagi setiap pek".

Peringkat sahaja **tidak** memaksa Peringkat 1 didahulukan — jika kependaman Peringkat 1 buruk atau
nisbah kos berbanding kualiti tidak optimum, Peringkat 2 akan menang. Untuk memaksa susunan peringkat, gunakan
strategi kombo `priority` dan susun penyedia mengikut peringkat.

Untuk mengutamakan Peringkat 1 (langganan) dengan ketara, tingkatkan berat `tierPriority`:

```json
{
  "strategy": "auto",
  "config": { "auto": { "weights": { "tierPriority": 0.3, "costInv": 0.05 } } }
}
```

Lihat [`docs/guides/TIERS.md`](../guides/TIERS.md) untuk takrif peringkat dan pengelasan penyedia.

## Pengujian & Liputan

### Matriks keputusan penghalaan deterministik (`npm run test:combo:matrix`)

`tests/integration/combo-matrix/*.test.ts` membuktikan **keputusan** penghalaan strategi awam
yang diliputinya dari hujung ke hujung melalui saluran paip combo sebenar dengan upstream yang
dimock.
Liputan merangkumi:

- Kesemua 21 strategi `ROUTING_STRATEGY_VALUES` (ordered, weighted, cost, context, fusion, …).
- `quota-share` (dalaman) dari hujung ke hujung: keadilan DRR + penyusunan keutamaan lebih rendah
  apabila tepu melalui seam `selectQuotaShareTarget` sebenar (`registerQuotaFetcher` / `setLKGP` /
  `__setHeadroomSaturationFetcherForTests`).
- Liputan universal-handoff `context-relay` merentasi setiap bilangan sasaran.

Suite ini dijalankan dalam CI (tugas `test:integration`) dengan `--test-concurrency=1` dan
`--test-force-exit` supaya bersifat deterministik dan tidak memerlukan kelayakan langsung.

### Smoke langsung berpagar (BUKAN dalam CI — penyedia sebenar)

| Perintah                               | Fungsinya                                                                                                    |
| :------------------------------------- | :----------------------------------------------------------------------------------------------------------- |
| `npm run test:combo:live`              | Penghalaan langsung sebenar dalam proses dengan `RUN_COMBO_LIVE=1`; mengambil snapshot DB OmniRoute langsung |
| `npm run test:combo:live:vps`          | Panggilan HTTP terhadap pelayan OmniRoute langsung (tetapkan `COMBO_LIVE_BASE_URL`)                          |
| `npm run test:combo:live:vps:failover` | Sama, dengan senario failover yang disengajakan                                                              |

Ujian smoke ini menguji laluan wayar sebenar (combo → penyedia → penyiapan). Ujian ini
sengaja dikecualikan daripada CI kerana memerlukan kelayakan langsung dan akses VPS.
