Nod JSON API tersuai menyambungkan titik akhir perniagaan JSON yang tidak bercakap dengan protokol OpenAI atau Anthropic. OmniRoute mengisi templat permintaan JSON, menghantarnya ke titik akhir yang lengkap URL, membaca balasan daripada laluan respons dan mengembalikannya kepada klien dalam format pelanggan sendiri (Penyelesaian Sembang, Respons, Mesej, ...).

Ia adalah nod serasi OpenAI dengan `apiType: "custom-json"`; idnya mempunyai bentuk `openai-compatible-custom-json-<suffix>`. Borang papan pemuka belum tersedia lagi. Cipta dan edit nod ini melalui pembekal-nod API di bawah.

## Buat nod

`POST /api/provider-nodes` (pengesahan pengurusan):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` ialah** lengkap** titik akhir URL. Tiada apa-apa yang dilampirkan (tiada `/chat/completions`, tiada `/models`) dan, tidak seperti nod serasi OpenAI yang lain, tiada URL lalai. Ia mestilah `http(s)`, tanpa bukti kelayakan terbenam atau `#fragment`, dan ia melepasi pengawal URL keluar yang sama seperti setiap nod pembekal, kedua-duanya apabila nod disimpan dan pada setiap permintaan.
- Nod yang menghantar kekunci sambungan (`authType` `bearer` atau `api-key`, termasuk lalai) mesti menggunakan `https://`. `http://` biasa diterima hanya untuk hos gelung balik (`localhost`, `127.0.0.0/8`, `::1`) atau dengan `authType: "none"`, yang tidak menghantar kunci. Alamat LAN peribadi (`10.x`, `172.16-31.x`, `192.168.x`) tidak dikecualikan: sesiapa sahaja di rangkaian itu boleh membaca kuncinya. Menyimpan nod sedemikian gagal dengan `400`, dan nod yang disimpan lebih awal gagal ditutup pada setiap permintaan dengan mesej yang sama, sebelum sebarang permintaan dihantar. Untuk titik akhir berkunci pada LAN, letakkannya di belakang TLS (contohnya proksi terbalik).
- `customJson` disahkan dengan Zod; kunci yang tidak diketahui ditolak. Setiap medan adalah pilihan:

| Padang            | Nilai                                      | Lalai                                                  |
| ----------------- | ------------------------------------------ | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                     | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                | `bearer`                                               |
| `authHeader`      | nama pengepala digunakan apabila `api-key` | `X-API-Key`                                            |
| `requestTemplate` | objek JSON (≤ 64 KB, kedalaman ≤ 32)       | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | laluan medan, atau `$` untuk seluruh badan | `choices[0].message.content`                           |

- Rahsia kekal dalam kunci API sambungan, tidak pernah dalam templat. `bearer` menghantar `Authorization: Bearer <key>`; `api-key` hantar `<authHeader>: <key>`. Pengepala auth tidak boleh menjadi `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` atau pengepala lompat demi lompat. Dengan `none`, sambungan tidak memerlukan kunci.
- Pengepala statik tambahan menggunakan `customHeaders` biasa nod (pengesahan yang sama seperti setiap nod serasi lain; pengepala auth tidak dibenarkan di sana).

`PUT /api/provider-nodes/<id>` menerima `customJson` yang sama dan menulis semula `baseUrl` dan konfigurasi pada setiap sambungan sedia ada nod. Mengeluarkan `customJson` mengekalkan konfigurasi yang disimpan; menukar `apiType` kepada `chat` atau `responses` mengeluarkannya daripada nod dan sambungannya.

Kemudian tambahkan sambungan ke nod seperti biasa (`POST /api/providers` dengan id nod) dan minta `<prefix>/<model>`, contohnya `biz/assistant-v1`. Titik akhir tidak mendedahkan senarai model, jadi tambah id model dengan tangan.

## Minta templat

Templat adalah JSON biasa. Nilai rentetan mungkin mengandungi penanda `{{placeholder}}` ; tiada apa-apa yang dinilai atau dilaksanakan, dan kekunci objek tidak pernah digantikan.

| Pemegang tempat      | Nilai                                                                       |
| -------------------- | --------------------------------------------------------------------------- |
| `{{prompt}}`         | Teks mesej pengguna terkini (bahagian teks digabungkan dengan baris baharu) |
| `{{messages}}`       | Perbualan dalam format sembang OpenAI                                       |
| `{{model}}`          | Id model yang diminta, tanpa awalan pembekal                                |
| `{{stream}}`         | Sentiasa `false` — jawapan titik akhir dengan satu dokumen JSON             |
| `{{request.<path>}}` | Medan permintaan yang diterjemahkan (format sembang OpenAI ).               |

- Nilai yang betul-betul satu pemegang tempat mengekalkan jenis JSON (`"{{messages}}"` menjadi tatasusunan); pemegang tempat di dalam rentetan yang lebih panjang disisipkan sebagai teks.
- Pemegang tempat yang memutuskan untuk tidak melakukan apa-apa gagal permintaan dengan HTTP 400 dan bukannya menghantar muatan yang tidak lengkap.
- Laluan menggunakan notasi titik dan indeks berangka (`data.items[0].text`). `__proto__`, `prototype` dan `constructor` ditolak dalam kunci dan laluan.

## Jawapan

Nilai pada `responsePath` menjadi balasan pembantu: rentetan melepasi, nilai JSON lain disirikan. Medan yang tiada atau `null`, atau badan yang bukan JSON, mengembalikan HTTP 502. Status ralat huluan dilalui. Untuk pelanggan penstriman OmniRoute menunggu untuk keseluruhan respons JSON dan kemudian memancarkannya sebagai satu bahagian kandungan ditambah bahagian penamat; ini bukan penstriman token. Panggilan alat dan medan penggunaan tidak dipetakan.

## Tidak pernah ditayangkan semula

Permintaan perniagaan boleh mempunyai kesan sampingan walaupun gagal. Oleh itu, OmniRoute menghantarnya sekali:

- tiada percubaan semula pengangkutan dan tiada ubah hala berikut;
- tiada cuba semula pada sambungan lain (saling balik akaun) — kegagalan dikembalikan seperti sedia ada dan sambungan tidak disejukkan;
- tiada sandaran kepada sasaran kombo seterusnya, walaupun untuk balasan kosong atau gagal.

Asingkan permintaan pelanggan dan panel gabungan yang secara eksplisit memanggil beberapa model, masih menggunakan titik akhir secara bebas.

## Menguji nod

Menyimpan sambungan, sambungan** Ujian** pemeriksaan kesihatan butang dan latar belakang tidak pernah memanggil titik akhir: mereka hanya mengesahkan konfigurasi yang disimpan dan melaporkan sambungan sebagai tidak boleh disahkan.

`POST /api/provider-nodes/validate` dengan `"apiType": "custom-json"` dan medan nod (`baseUrl`, `apiKey`, `customJson`, `customHeaders` pilihan dan `modelId`) menghantar tepat satu permintaan sebenar, dengan `ping` sebagai teks pengguna terkini. Ia menjawab `{ "valid": true }` atau status hulu (tidak pernah badan hulu).

## Penyimpanan

Konfigurasi disimpan dalam `provider_nodes.custom_json_config_json` (migration `240_provider_node_custom_json_config.sql`) dan disalin ke dalam setiap sambungan `providerSpecificData.customJson`.

Pelaksanaan: `open-sse/utils/customJson.ts` (pengesahan dan templat), `open-sse/executors/customJson.ts` (pelaksana), `open-sse/services/combo/noReplayLatch.ts` dan `src/sse/handlers/chat/responsePolicies.ts` (tiada ulang tayang).
