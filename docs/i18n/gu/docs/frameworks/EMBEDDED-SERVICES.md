એમ્બેડેડ સેવાઓ એ સ્થાનિક રીતે ઇન્સ્ટોલ કરેલ પ્રોસેસ સાઇડકાર ટૂલ્સ છે જે OmniRoute પ્રથમ-વર્ગના રૂટીંગ લક્ષ્યો તરીકે ઇન્સ્ટોલ કરે છે, દેખરેખ રાખે છે અને એક્સપોઝ કરે છે. બાહ્ય પ્રદાતાઓથી વિપરીત (જે API કી દ્વારા ઇન્ટરનેટ પર પહોંચે છે), એમ્બેડેડ સેવાઓ OmniRoute જેવા જ મશીન પર ચાલે છે અને લૂપબેક પર વાતચીત કરે છે.

તમામ આઠ સમાન સુપરવાઇઝરી મોડેલને અનુસરે છે:

- OmniRoute તેમને `DATA_DIR/services/{name}/` હેઠળ ઇન્સ્ટોલ કરે છે ( OmniRoute ના પોતાના `package.json` થી અલગ)
- OmniRoute તેમને બાળ પ્રક્રિયાઓ તરીકે પેદા કરે છે અને તેનું નિરીક્ષણ કરે છે
- OmniRoute બાળકના વાતાવરણમાં એક ક્ષણિક API કી દાખલ કરે છે અને તેને ડાઉનટાઇમ વિના ફેરવે છે (જ્યાં લાગુ હોય)
- તમામ વ્યવસ્થાપન માર્ગો (`/api/services/*`) છે**LOCAL_ONLY** — ફક્ત લૂપબેકથી જ સુલભ છે (સખત નિયમ #17)

| ઓટો-સ્ટાર્ટ                        | સેવા દીઠ ટૉગલ કરો, ડિફોલ્ટ OFF                                                                   |

## 2. આર્કિટેક્ચર — 4 સ્તરો

```
┌────────────────────────────────────────────────────────────────────┐
│  Layer 1 — UI                                                      │
│  /dashboard/providers/services  (tabs: CLIProxyAPI | 9Router | Mux)│
│  Logs live (SSE), Start/Stop/Restart/Update, Settings, Install     │
│                                                                    │
│  src/app/(dashboard)/dashboard/providers/services/                 │
│    ├── page.tsx               Shell + tab routing by ?tab=         │
│    ├── tabs/                  CliproxyServiceTab, NinerouterServiceTab,│
│    │                          MuxServiceTab                        │
│    └── components/            ServiceStatusCard, ServiceLifecycleButtons,│
│                               ServiceLogsPanel, ApiKeyCard, ...    │
└──────────────────────┬─────────────────────────────────────────────┘
                       │ HTTP (Next.js fetch)
┌──────────────────────▼─────────────────────────────────────────────┐
│  Layer 2 — API (LOCAL_ONLY — loopback only)                        │
│                                                                    │
│  /api/services/9router/{install|start|stop|restart|update|         │
│                          rotate-key|status|auto-start|logs}        │
│  /api/services/cliproxy/{install|start|stop|restart|update|        │
│                           status|auto-start|logs}                  │
│  /api/services/mux/{install|start|stop|restart|update|             │
│                      status|auto-start|logs}                       │
│  /dashboard/providers/services/9router/embed/[...path]             │
│    (reverse HTTP + WebSocket proxy → 9Router upstream)             │
│                                                                    │
│  Gate: LOCAL_ONLY_API_PREFIXES includes "/api/services/" and       │
│        "/dashboard/providers/services/*/embed/"                    │
└──────────────────────┬─────────────────────────────────────────────┘
                       │ in-process calls
┌──────────────────────▼─────────────────────────────────────────────┐
│  Layer 3 — ServiceSupervisor (src/lib/services/)                   │
│                                                                    │
│  ServiceSupervisor.ts   Generic supervisor (child_process.spawn)   │
│    ├── install:    execFile('npm', ['install', pkg, '--prefix'])    │
│    ├── start:      spawn(node, [entrypoint], {env, cwd})           │
│    ├── api_key:    crypto.randomBytes(32) → env NINEROUTER_API_KEY  │
│    ├── port:       20130 for 9Router (configurable)                │
│    ├── logs:       stdio ring buffer 5 MB → SSE events             │
│    ├── health:     HTTP GET /health every 2–5 s, lazy recovery     │
│    └── lifecycle:  SIGTERM 15 s → SIGKILL                          │
│                                                                    │
│  registry.ts        getSupervisor(name) / registerSupervisor()     │
│  bootstrap.ts       Bootstraps all SERVICES[] at process start     │
│  apiKey.ts          getOrCreateApiKey(), generateServiceApiKey()   │
│  modelSync.ts       Periodic GET /v1/models → service_models table │
│  ringBuffer.ts      Circular log buffer (5 MB per service)         │
│  healthCheck.ts     Polling HTTP health probe                      │
│  installers/        ninerouter.ts, cliproxy.ts, mux.ts, openwa.ts  │
│                      (installer adapters)                          │
└──────────────────────┬─────────────────────────────────────────────┘
                       │ OpenAI-compatible HTTP (loopback)
┌──────────────────────▼─────────────────────────────────────────────┐
│  Layer 4 — Provider / Routing                                      │
│                                                                    │
│  open-sse/executors/ninerouter.ts                                  │
│    Re-looks up port and API key per-request (no caching).          │
│    Strips "9router/" prefix from model id before proxying.         │
│    Returns 503 service_not_running if supervisor not in "running". │
│                                                                    │
│  src/shared/constants/providers.ts                                 │
│    Entry for "9router": isEmbeddedService: true                    │
│                                                                    │
│  open-sse/config/providerRegistry.ts                               │
│    Models stored as "9router/{sub}/{model}" (prefixed).            │
│    Synced every 5 min by modelSync.ts.                             │
│                                                                    │
│  Mux is lifecycle-managed ONLY (Layers 1-3) — it is an agent-       │
│  orchestration daemon, not an LLM proxy, so it has no Layer 4      │
│  executor/provider entry and is never a routing target.            │
└────────────────────────────────────────────────────────────────────┘
```

### મુખ્ય સ્ત્રોત ફાઇલો

| ફાઈલ                                        | ભૂમિકા                                        |
| ------------------------------------------- | --------------------------------------------- |
| `src/lib/services/ServiceSupervisor.ts`     | મુખ્ય વર્ગ: જીવનચક્ર, લોક, આરોગ્ય, રિંગ બફર   |
| `src/lib/services/bootstrap.ts`             | પ્રક્રિયા-સ્તરની નોંધણી અને સ્વતઃ-પ્રારંભ     |

## 3. લાઇફસાઇકલ સ્ટેટ મશીન

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
               હેલ્થ પ્રોબ સફળ     │         ક્રેશ / SIGTERM    │
                               ┌────▼─────┐  (5sમાં એક્ઝિટ)     │
                               │ running  │──── ક્રેશ ──────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

સ્ટેટ્સ `version_manager` DB ટેબલમાં (`status` કૉલમ) સંગ્રહિત થાય છે અને
`ServiceSupervisor`ની ઇન-મેમરી સ્ટેટમાં પ્રતિબિંબિત થાય છે. ચાલતી પ્રક્રિયા માટે
ઇન-મેમરી સ્ટેટ અધિકૃત છે; બૂટ વખતે DB સ્ટેટ ટકાઉ ફૉલબૅક છે.

### સ્ટેટ ટ્રાન્ઝિશન્સ

| માંથી           | ઇવેન્ટ                                   | માં                    |
| --------------- | ---------------------------------------- | ---------------------- |
| `not_installed` | `install()` સફળ થાય                      | `stopped`              |
| `stopped`       | `start()` કૉલ કરવામાં આવે                | `starting`             |
| `starting`      | હેલ્થ પ્રોબ 200 પરત કરે                  | `running`              |
| `starting`      | સ્વસ્થ થાય તે પહેલાં પ્રક્રિયા બંધ થાય   | `error`                |
| `running`       | `stop()` કૉલ કરવામાં આવે                 | `stopping` → `stopped` |
| `running`       | પ્રક્રિયા અનપેક્ષિત રીતે બંધ થાય (< 5 s) | `error` (ઝડપી ક્રેશ)   |
| `running`       | પ્રક્રિયા અનપેક્ષિત રીતે બંધ થાય (> 5 s) | `error`                |
| `error`         | `start()` કૉલ કરવામાં આવે                | `starting`             |
| કોઈપણ           | `stopping` દરમિયાન `stop()`              | કોઈ ક્રિયા નહીં        |

### ઑપરેશન લૉક

`ServiceSupervisor` અસિંક ઑપરેશન લૉક (`withLock()`) મારફતે લાઇફસાઇકલ ઑપરેશન્સને
ક્રમબદ્ધ કરે છે. એક જ સુપરવાઇઝર પર સમકાલીન `start()` કૉલ્સનું પરિણામ ચોક્કસપણે
એક જ spawnમાં આવે છે; બીજો કૉલર રાહ જુએ છે અને હાલની સ્થિતિ પરત કરે છે. આ
રેસ કન્ડિશન્સને અટકાવે છે, ઉદાહરણ તરીકે જ્યારે ઑટો-સ્ટાર્ટ અને UI બટન એકસાથે
ટ્રિગર થાય.

#### `POST /api/services/9router/install`

npm થી 9 રાઉટર ઇન્સ્ટોલ કરો. તેના પોતાના `package.json` અને `node_modules/` સાથે `DATA_DIR/services/9router/` બનાવે છે. OmniRoute ના પોતાના ડેપ્સ સાથે સંઘર્ષ કરતું નથી.

**શરીરની વિનંતી કરો** (બધા વૈકલ્પિક):

```json
{ "version": "latest" }
```

| ક્ષેત્ર   | પ્રકાર   | ડિફૉલ્ટ    | વર્ણન                                        |
| --------- | -------- | ---------- | -------------------------------------------- |
| `version` | `string` | `"latest"` | npm વર્ઝન ટેગ અથવા સેમેવર ઇન્સ્ટોલ કરવા માટે |

**પ્રતિભાવો:**

| સ્થિતિ | વર્ણન                                                    |
| ------ | -------------------------------------------------------- |
| `200`  | `{ ok: true, installedVersion: "x.y.z", path: "..." }`   |
| `400`  | અમાન્ય વિનંતીનો મુખ્ય ભાગ (Zod માન્યતા નિષ્ફળતા)         |
| `409`  | પહેલેથી જ ઇન્સ્ટોલ કરી રહ્યું છે (લોક રાખેલ છે)          |
| `500`  | npm ઇન્સ્ટોલ નિષ્ફળ — મૈત્રીપૂર્ણ ભૂલ માટે `message` જુઓ |

**નોંધો:** `execFile('npm', [...])` — નો શેલ, નો ઇન્ટરપોલેશન (સખત નિયમ #13) નો ઉપયોગ કરે છે. EACCES ભૂલો મૈત્રીપૂર્ણ સંદેશાઓ તરીકે સપાટી પર આવે છે.

### 4.2 CLIProxyAPI અંતિમ બિંદુઓ (10 માર્ગો)

| પદ્ધતિ | પાથ                                 | વર્ણન                                     |
| ------ | ----------------------------------- | ----------------------------------------- |
| `POST` | `/api/services/cliproxy/install`    | npm થી CLIProxyAPI ઇન્સ્ટોલ કરો           |
| `POST` | `/api/services/cliproxy/start`      | CLIProxyAPI શરૂ કરો                       |

| `POST` | `/api/services/singbox/auto-restart-adopted` | અપનાવેલ (પહેલાથી અસ્તિત્વમાં રહેલી) પ્રક્રિયા માટે સ્વતઃ પુનઃપ્રારંભને ટૉગલ કરો |

**TPROXY વાયરિંગ:** `ensureSingboxTproxy()` (`src/mitm/tproxy/setup.ts`) `config.json` લખે છે અને `applyTproxy()` TPROXY ફાયરવોલ નિયમો ઇન્સ્ટોલ કરે તે પહેલાં સુપરવાઇઝર શરૂ કરે છે. જો સુપરવાઈઝર ખૂટે છે અથવા `running` સુધી પહોંચવામાં નિષ્ફળ જાય છે, તો તે હવે ભૂલના સ્તરે લૉગ કરે છે (નિષ્ફળતાને ચૂપચાપ ગળી જવાને બદલે) જેથી ઑપરેટર કહી શકે કે TPROXY નિયમો તેમની પાછળ કાર્યરત શ્રોતા વગર લાગુ કરવામાં આવ્યા હતા.

### 4.9 રિવર્સ પ્રોક્સી (9 રાઉટર ડેશબોર્ડ એમ્બેડ)

ડેશબોર્ડ 9રાઉટર વેબ UI આઈફ્રેમની અંદર આંતરિક રિવર્સ પ્રોક્સી દ્વારા અહીં એમ્બેડ કરે છે:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

આ પ્રોક્સી:

- વિનંતીને `http://127.0.0.1:{port}/{path}` ને ફોરવર્ડ કરો (ફક્ત લૂપબેક)
- સ્ટ્રીપ્સ ઇનકમિંગ `cookie` અને `authorization` હેડરો ( OmniRoute સત્રનું કોઈ લીકેજ નથી)
- 9રાઉટર ઓથેન્ટિકેશન માટે `Authorization: Bearer {apiKey}` ઇન્જેક્ટ કરે છે
- પ્રતિસાદમાંથી `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` સ્ટ્રિપ્સ
- `<base href>` ઇન્જેક્ટ કરવા અને સંપૂર્ણ પાથને સામાન્ય બનાવવા માટે HTML પ્રતિસાદો ફરીથી લખે છે (`/foo` → `/dashboard/.../embed/foo`)

એમ્બેડેડ ડેશબોર્ડ માટેWebSocket અપગ્રેડ્સને સમર્પિત પોર્ટ પર સાથી સર્વર દ્વારા નિયંત્રિત કરવામાં આવે છે (જુઓ `src/lib/services/embedWsProxy.ts`).

**સુરક્ષા:** એમ્બેડ પ્રોક્સી રૂટ્સ `LOCAL_ONLY_API_PREFIXES` હેઠળ વર્ગીકૃત કરવામાં આવે છે અને ફક્ત લૂપબેકથી જ પહોંચી શકાય છે. હુમલાખોર જે Cloudflare/Ngrok ટનલ દ્વારા JWT મેળવે છે તે એમ્બેડેડ સેવાઓમાં પ્રોક્સી કરી શકતો નથી.

## 5. સુરક્ષા

### LOCAL_ONLY અમલીકરણ (કડક નિયમ #17)

`/api/services/` અને `/dashboard/providers/services/*/embed/` હેઠળના બધા રૂટને
`src/server/authz/routeGuard.ts` માં LOCAL_ONLY તરીકે વર્ગીકૃત કરવામાં આવ્યા છે. કોઈપણ auth શાખા પહેલાં
લૂપબૅક ચકાસણી બિનશરતી રીતે ચાલે છે:

```
વિનંતી આવે છે
  → isLocalOnlyPath(path)?
      → બિન-લૂપબૅક → 403 LOCAL_ONLY (હંમેશાં, auth ચકાસણી પહેલાં)
      → લૂપબૅક     → સામાન્ય auth તરફ આગળ વધે છે
```

આનાથી લીક થયેલ JWT (દા.ત., ટનલ મારફતે) `npm install` ટ્રિગર કરવાથી અથવા
પ્રોસેસ શરૂ કરવાથી અટકે છે. સંપૂર્ણ સ્તર
મેટ્રિક્સ માટે `docs/security/ROUTE_GUARD_TIERS.md` જુઓ.

### API કી ઇન્જેક્શન

9Router અને Mux ને તેમના પોતાના HTTP એન્ડપોઇન્ટ માટે API કી/બેરર ટોકનની જરૂર પડે છે.
OmniRoute:

1. સેવા-વિશિષ્ટ પ્રિફિક્સ સાથે `crypto.randomBytes(32).toString("base64url")` દ્વારા કી
   જનરેટ કરે છે (9Router માટે `nr_`, Mux માટે `mx_`).
2. AES-256-GCM નો ઉપયોગ કરીને તેને સંગ્રહિત સ્થિતિમાં એન્ક્રિપ્ટ કરે છે (પ્રદાતા ક્રેડેન્શિયલ્સ માટે વપરાતું એ જ સાઇફર).
3. પ્રોસેસ શરૂ કરતી વખતે તેને ડિક્રિપ્ટ કરીને એન્વાયર્નમેન્ટ વેરિએબલ તરીકે ઇન્જેક્ટ કરે છે —
   9Router માટે `NINEROUTER_API_KEY`, Mux માટે `MUX_SERVER_AUTH_TOKEN` (CLI
   ફ્લૅગ તરીકે ક્યારેય નહીં, જેથી ટોકન `ps`/પ્રોસેસ સૂચિઓમાં ક્યારેય દેખાતું નથી).
4. કોઈપણ HTTP પ્રતિસાદમાં પ્લેનટેક્સ્ટ કી ક્યારેય પરત કરતું નથી.

CLIProxyAPI ને પ્રોસેસ શરૂ કરતી વખતે ઇન્જેક્ટ કરાતી સમર્પિત ડેટા-પ્લેન કી મળે છે
(`needsApiKey: true` — એડેપ્ટર સામે મોડેલ સિંક માટે વપરાય છે).

### SSRF સંરક્ષણ

રિવર્સ HTTP પ્રોક્સી (`/dashboard/.../embed/[...path]`) માત્ર
`http://127.0.0.1:{port}` તરફ ફોરવર્ડ કરવા માટે હાર્ડકોડ કરેલી છે. તે બિન-લૂપબૅક
ગંતવ્યો તરફના રીડાયરેક્ટને ક્યારેય અનુસરતી નથી. લૂપબૅક રેન્જની બહાર રિઝોલ્વ થતા કોઈપણ અપસ્ટ્રીમ URL ને
નકારવા માટે `ssrf-req-filter` લાઇબ્રેરીનો ઉપયોગ થાય છે.

### શેલ સુરક્ષા (કડક નિયમ #13)

`npm install` ને `execFile('npm', ['install', pkg, '--prefix', dir])` મારફતે ચલાવવામાં આવે છે —
કોઈ ટેમ્પલેટ લિટરલ નહીં, કોઈ શેલ નહીં અને કમાન્ડ
સ્ટ્રિંગમાં બાહ્ય પાથનું કોઈ ઇન્ટરપોલેશન નહીં. રનટાઇમ મૂલ્યો (પોર્ટ, API કી) ચાઇલ્ડના `env` ઑબ્જેક્ટ મારફતે પાસ કરવામાં આવે છે.

### ભૂલ સેનિટાઇઝેશન (કડક નિયમ #12)

`/api/services/*` તરફથી મળતા બધા ભૂલ પ્રતિસાદ `buildErrorBody()` અથવા
`sanitizeErrorMessage()` મારફતે પસાર થાય છે. કાચા `err.stack` અને `err.message` કૉલરને ક્યારેય
જેમના તેમ પરત કરવામાં આવતા નથી.

## 6. નવી એમ્બેડેડ સેવા ઉમેરવી

આ 8 પગલાં અનુસરો. પ્રમાણભૂત સંદર્ભ તરીકે `src/lib/services/installers/`
અને `src/app/api/services/` માં રહેલા વર્તમાન અમલીકરણો વાંચો.

### પગલું 1 — ઇન્સ્ટોલર બનાવો

`ninerouter.ts` ના આધારે `src/lib/services/installers/{name}.ts` બનાવો:

```typescript
export const NAME_PACKAGE = "your-npm-package";
export const NAME_DEFAULT_PORT = 20132; // કોઈ ખાલી પોર્ટ પસંદ કરો

export async function install(version = "latest"): Promise<InstallResult> { ... }
export async function update(version = "latest"): Promise<InstallResult> { ... }
export async function uninstall(): Promise<void> { ... }
export function resolveSpawnArgs(apiKey: string, port: number): SpawnArgs { ... }
export async function getInstalledVersion(): Promise<string | null> { ... }
export async function getLatestVersion(): Promise<string | null> { ... }
```

`installers/utils.ts` માંથી `runNpm(['install', NAME_PACKAGE, '--prefix', dir])` નો ઉપયોગ કરો
— `execSync` અથવા શેલ ઇન્ટરપોલેશનનો ક્યારેય ઉપયોગ કરશો નહીં.

### પગલું 2 — બૂટસ્ટ્રૅપમાં નોંધણી કરો

`src/lib/services/bootstrap.ts` માંના `SERVICES` ઍરેમાં `ServiceEntry` ઉમેરો:

```typescript
{
  tool: "myservice",
  port: NAME_DEFAULT_PORT,
  healthPath: "/health",
  healthIntervalMs: 5_000,
  stopTimeoutMs: 15_000,
  logsBufferBytes: 5_242_880,
  needsApiKey: true, // API કીની જરૂર ન હોય તો false
}
```

`cfg.tool === "myservice"` ને હૅન્ડલ કરવા માટે `buildSpawnArgsFactory()` વિસ્તારો.

#### પ્લગ કરી શકાય તેવો પ્રદાતા-પ્લગઇન કરાર (તબક્કો 1, #7333)

`src/lib/services/providerPlugins/` એવો `ServiceProviderPlugin` કરાર રજૂ કરે છે જે
એક બૅકએન્ડના `bootstrap.ts` ના `ServiceEntry` ફિલ્ડ્સ અને `serviceBackends.ts` ના
મેનિફેસ્ટ-ટેમ્પલેટ ફિલ્ડ્સને એક ઑબ્જેક્ટમાં પૅકેજ કરે છે, જેથી એ જ બૅકએન્ડનું સ્વરૂપ
બે અસંબંધિત ફાઇલોમાં અલગથી વ્યક્ત કરવું ન પડે. આ લખાય છે ત્યારે **માત્ર `9router` ને
માઇગ્રેટ કરવામાં આવ્યું છે** — `bootstrap.ts` તેની `SERVICES[]` એન્ટ્રી
`getServiceProviderPlugin("9router")` (`src/lib/services/providerPlugins/registry.ts`) માંથી મેળવે છે,
અને જો પ્લગઇન ક્યારેય ખૂટતું હોય તો સ્ટાર્ટઅપ ભૂલ ફેંકે છે. `cliproxy`, `mux`, અને `bifrost`
કોઈ ફેરફાર વિના પહેલાંથી અસ્તિત્વમાં રહેલા ઇનલાઇન `SERVICES[]` લિટરલ્સ પર રહે છે.

`open-sse/config/providerPluginManifest.ts` માં ઉમેરાત્મક
`createServiceBackendManifestEntry(pluginId, template)` હેલ્પર પણ ઉમેરવામાં આવ્યું છે, જે
`SERVICE_BACKEND_MANIFEST_TEMPLATE` એન્ટ્રીમાંથી યોગ્ય રીતે રચાયેલી
`ProviderPluginManifestEntry` બનાવે છે — તે હજી સુધી કોઈ સક્રિય રિક્વેસ્ટ પાથ સાથે
જોડાયેલું **નથી** (`generateProviderPluginManifestFromRegistry()` સાથે પણ નહીં કે
`/v1/providers/[provider]/models` સાથે પણ નહીં); બીજા બૅકએન્ડ માટે કરાર સાબિત થઈ જાય પછી
તે ફૉલો-અપ તરીકે કરવાનું બાકી છે.

ફૉલો-અપ PRs માટે મુલતવી રાખેલાં કાર્યો, જે issue #7333 હેઠળ ટ્રૅક થાય છે: સમાન
રજિસ્ટ્રી મારફતે `cliproxyapi` ને માઇગ્રેટ કરવું, `mux`/`bifrost` ને
`ServiceBackendPluginId` યુનિયનમાં સામાન્યકૃત કરવું, એક્ઝિક્યુટર-રાઉટિંગના વિશેષ કેસ
(`open-sse/executors/index.ts`,
`open-sse/handlers/chatCore/executorProxy.ts`) ને પ્લગઇન કરારમાં સમાવવું, અને
`createServiceBackendManifestEntry()` ને સક્રિય મેનિફેસ્ટ/મોડેલ્સ કોડ પાથ સાથે જોડવું.

### પગલું 3 — માઇગ્રેશન અને DB સીડ ઉમેરો

`src/lib/db/migrations/` માં માઇગ્રેશન મારફતે ખાતરી કરો કે સેવાની `version_manager` માં એક રો છે.

INSERT OR IGNORE INTO version_manager (tool, status, auto_start, provider_expose)

### પગલું 4 — 7 API એન્ડપોઇન્ટ બનાવો

`src/app/api/services/{name}/` હેઠળ:

```
_lib.ts            getOrInitSupervisor() હેલ્પર
install/route.ts   POST — installer.install() ને કૉલ કરે છે
start/route.ts     POST — supervisor.start() ને કૉલ કરે છે
stop/route.ts      POST — supervisor.stop() ને કૉલ કરે છે
restart/route.ts   POST — supervisor.restart() ને કૉલ કરે છે
update/route.ts    POST — installer.update() ને કૉલ કરે છે
status/route.ts    GET  — લાઇવ + DB સ્થિતિને મર્જ કરે છે
auto-start/route.ts POST — auto_start ફ્લૅગને ટૉગલ કરે છે
```

શેર કરાયેલ `GET /api/services/[name]/logs` રૂટ પહેલેથી જ જોડાયેલો છે — ત્યાં કોઈ ફેરફારની
જરૂર નથી.

તમામ ભૂલ પ્રતિસાદો `createErrorResponse()` / `buildErrorBody()` મારફતે સોંપો.

### પગલું 5 — LOCAL_ONLY_API_PREFIXES માં ઉમેરો

`src/server/authz/routeGuard.ts` માં ચકાસો કે `/api/services/` પહેલેથી સૂચિબદ્ધ છે.
જો તમે નવો પ્રિફિક્સ રજૂ કરો (દા.ત., `/api/tools/`), તો તેને
`LOCAL_ONLY_API_PREFIXES` અને, જો તે પ્રોસેસ શરૂ કરતું હોય, તો `SPAWN_CAPABLE_PREFIXES`
બંનેમાં ઉમેરો. `tests/unit/authz/routeGuard.test.ts` માં એક ટેસ્ટ ઉમેરો.

### પગલું 6 — UI ટૅબ ઉમેરો

## 7. સમસ્યાનિવારણ

### સેવા શરૂ થતી નથી

**લક્ષણો:** Start બટન 503 પરત કરે છે, સ્થિતિ `"error"` અથવા `"starting"` પર જ રહે છે.

**તપાસસૂચિ:**

1. `GET /api/services/{name}/logs` તપાસો (અથવા ડૅશબોર્ડમાં Logs પેનલ). `Error: ENOENT`, `address already in use`, અથવા `Cannot find module` જેવી પંક્તિઓ શોધો.
2. ખાતરી કરો કે `npm` PATHમાં છે: OmniRoute ચલાવતા એ જ વપરાશકર્તા ખાતામાંથી `which npm` ચલાવો.
3. ખાતરી કરો કે સેવા ઇન્સ્ટૉલ થયેલી છે: `installedVersion` માટે `GET /api/services/{name}/status` તપાસો. જો તે `null` હોય, તો પહેલાં ઇન્સ્ટૉલ ચલાવો.
4. તપાસો કે `DATA_DIR/services/{name}/node_modules/` અસ્તિત્વમાં છે અને ખાલી નથી.
5. શુદ્ધ કરાયેલ બહાર નીકળવાના કારણ માટે સ્થિતિ પ્રતિસાદમાં `lastError` ફીલ્ડ તપાસો.

---

### કોલ્ડ સ્ટાર્ટ ધીમું છે (`running` સુધી પહોંચવામાં > 10 s)

**લક્ષણો:** `"running"` અથવા `"error"` પર જતા પહેલાં સ્થિતિ લાંબા સમય સુધી `"starting"` પર રહે છે.

**સમજૂતી:** 9Routerના કોલ્ડ સ્ટાર્ટમાં વિશાળ ડિપેન્ડન્સી ટ્રી (DNS, ટનલ, MITM મોડ્યુલો) ઇમ્પોર્ટ કરવાનો સમાવેશ થાય છે. ડિફૉલ્ટ હેલ્થ ઇન્ટરવલ 2 s છે અને સુપરવાઇઝર ટાઇમઆઉટ જાહેર કરે તે પહેલાં 3 પ્રયાસ થાય છે (પરંતુ પોલિંગ ચાલુ રહે છે).

**ઉકેલ:** `healthIntervalMs` અને `waitForHealthy` ટાઇમઆઉટ (`healthIntervalMs * 3`) `bootstrap.ts`માં કૉન્ફિગર કરી શકાય છે. વધુ સ્ટાર્ટઅપ સમય ધરાવતી સેવાઓ માટે `healthIntervalMs`ને 5000 અને `stopTimeoutMs`ને 30 000 સુધી વધારો.

---

### પોર્ટ અથડામણ (`EADDRINUSE`)

**લક્ષણો:** લૉગ્સમાં `address already in use :::20130` દેખાય છે.

**કારણો:**

- બીજી કોઈ પ્રોસેસ પહેલેથી પોર્ટ 20130નો ઉપયોગ કરી રહી છે.
- અગાઉની 9Router પ્રોસેસ સંપૂર્ણપણે બંધ થઈ નહોતી (ઝોમ્બી PID).

**ઉકેલ:**

1. `.env`માં `NINEROUTER_PORT` એન્વાયર્નમેન્ટ વેરિએબલ દ્વારા ડિફૉલ્ટ પોર્ટ બદલો.
2. અથડાતી પ્રોસેસ શોધીને બંધ કરો: `lsof -ti :20130 | xargs kill -9`.
3. `bootstrap.ts`માં `port` ફીલ્ડ દ્વારા દરેક સેવા માટે પોર્ટ કૉન્ફિગર કરી શકાય છે.

**નોંધ:** OmniRouteના ડિફૉલ્ટ પોર્ટ 20128 સાથે અથડામણ ટાળવા માટે 9Router ખાસ કરીને પોર્ટ 20130નો ડિફૉલ્ટ તરીકે ઉપયોગ કરે છે.

---

### ઇન્સ્ટૉલ કરતી વખતે પરવાનગી નકારાઈ (EACCES)

**લક્ષણો:** ઇન્સ્ટૉલ 500 પરત કરે છે, લૉગ્સમાં `EACCES` અથવા `permission denied` દેખાય છે.

**કારણો:**

- `DATA_DIR` અથવા તેની પેરન્ટ ડિરેક્ટરી OmniRoute પ્રોસેસ દ્વારા લખી શકાય તેવી નથી.
- મૅપ કરેલા વૉલ્યુમમાં લખવાની ઍક્સેસ વિના Docker rootlessમાં ચાલી રહ્યું છે.

**ઉકેલ:**

1. `DATA_DIR` તપાસો (ડિફૉલ્ટ: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. ખાતરી કરો કે OmniRoute પ્રોસેસ વપરાશકર્તા આ ડિરેક્ટરીનો માલિક છે: `chown -R $USER ~/.omniroute/`
3. Dockerમાં ખાતરી કરો કે વૉલ્યુમ માઉન્ટ પાસે કન્ટેનર વપરાશકર્તા માટે યોગ્ય પરવાનગીઓ છે.

---

### અપડેટ નિષ્ફળ થાય છે (`npm install` ટાઇમઆઉટ અથવા નેટવર્ક ભૂલ)

**લક્ષણો:** અપડેટ `InstallError` સાથે 500 પરત કરે છે, લૉગ્સમાં નેટવર્ક ટાઇમઆઉટ દેખાય છે.

**તપાસસૂચિ:**

1. ખાતરી કરો કે npm રજિસ્ટ્રી ઍક્સેસ કરી શકાય તેવી છે: `npm ping`.
2. કૉર્પોરેટ પ્રૉક્સી માટે તપાસો: `npm config get proxy`, `npm config get https-proxy`.
3. ઇન્સ્ટૉલ મૅન્યુઅલી અજમાવો: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. જો ઍર-ગૅપ પાછળ હો, તો tarball અગાઉથી ડાઉનલોડ કરો અને `npm install /path/to/tarball.tgz`નો ઉપયોગ કરો.

---

### શરૂ કર્યા પછી તરત જ સેવા `"error"` સ્થિતિ દર્શાવે છે (ઝડપી ક્રૅશ)

**લક્ષણો:** સ્થિતિ 5 સેકન્ડથી ઓછા સમયમાં `"starting"`માંથી `"error"`માં બદલાય છે. `lastError`માં `"Fast crash (exited with code 1)"` દેખાય છે.

**તપાસસૂચિ:**

1. સંપૂર્ણ લૉગ ટેઇલ વાંચો: `GET /api/services/{name}/logs?tail=500`.
2. સામાન્ય કારણ: સેવા દ્વારા અપેક્ષિત એન્વાયર્નમેન્ટ વેરિએબલ્સ ઉપલબ્ધ નથી.
3. 9Router માટે: ખાતરી કરો કે સ્પૉન સમયે પસાર કરાયેલા એન્વાયર્નમેન્ટમાં `NINEROUTER_DISABLE_MITM=true` અને `NINEROUTER_DISABLE_TUNNEL=true` છે (`installers/ninerouter.ts`માં `resolveSpawnArgs` જુઓ).

## 8. વારંવાર પૂછાતા પ્રશ્નો

**પ્ર: શું હું એમ્બેડેડ સેવાઓના એન્ડપોઇન્ટ્સને નોન-લૂપબૅક ક્લાયન્ટ્સ માટે ખુલ્લા મૂકી શકું?**

ના. LOCAL_ONLY ટિયર ઇરાદાપૂર્વક છે (કડક નિયમ #17). જે રૂટ્સ
`npm install` ચલાવી શકે છે અથવા `node` પ્રોસેસ શરૂ કરી શકે છે, તેઓ નોન-લૂપબૅક
ટ્રાફિક માટે ઍક્સેસિબલ ન હોવા જોઈએ, કારણ કે અન્યથા ટનલ (Cloudflare, Ngrok, Tailscale) મારફતે
લીક થયેલું JWT મનસ્વી પ્રોસેસ શરૂ કરવાની મંજૂરી આપી શકે છે. આમાંથી બહાર નીકળવા માટે
`/api/services/` માટે કોઈ અપવાદ નથી — `/api/mcp/`થી વિપરીત, તેને manage-scope bypass
સૂચિમાંથી બાકાત રાખવામાં આવ્યું છે. `docs/security/ROUTE_GUARD_TIERS.md` જુઓ.

---

**પ્ર: શું 9Router અને CLIProxyAPI પ્રોડક્શન/ક્લાઉડ ડિપ્લોયમેન્ટ્સમાં ઉપલબ્ધ હશે?**

હા. બંને સેવાઓ OmniRouteની જેમ જ local-first મોડેલને અનુસરે છે. તેઓ
એક જ મશીન પર ચાલે છે અને લૂપબૅક મારફતે સંચાર કરે છે. અહીં "પ્રોડક્શન"નો અર્થ તે VPS
અથવા લોકલ સર્વર છે જ્યાં OmniRoute ડિપ્લોય થયેલું છે, રિમોટ ક્લાઉડ પ્રોવાઇડર નહીં.

---

**પ્ર: હું supervisorને કેવી રીતે ડિબગ કરું?**

1. SSE લૉગ સ્ટ્રીમને ટેઇલ કરો: `curl -N http://localhost:20128/api/services/9router/logs`.
2. `service:supervisor` namespace દ્વારા ફિલ્ટર કરેલા OmniRouteના pino આઉટપુટમાં
   સ્ટ્રક્ચર્ડ લૉગ્સ તપાસો.
3. DB રો તપાસો: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. હાલની લાઇવ સ્થિતિ, PID, હેલ્થ અને `lastError` એક જ કૉલમાં જોવા માટે
   `GET /api/services/9router/status`નો ઉપયોગ કરો.

---

**પ્ર: supervisor `health: "degraded"` અથવા `health: "unknown"` બતાવે છે, પરંતુ સ્થિતિ `"running"` છે. શું આ સમસ્યા છે?**

`"degraded"`નો અર્થ છે કે હેલ્થ પ્રોબે non-200 પ્રતિસાદ આપ્યો છે. `"unknown"`નો અર્થ છે કે હજી સુધી કોઈ
પ્રોબ પૂર્ણ થયો નથી (પ્રથમ પોલ સાથેની રેસ). સ્ટાર્ટઅપ દરમિયાન બંને સ્થિતિઓ ક્ષણિક હોય છે.
જો `"running"` પછી `healthIntervalMs * 3` ms કરતાં વધુ સમય સુધી હેલ્થ
`"degraded"` રહે, તો એમ્બેડેડ સેવા ચાલી રહી છે પરંતુ તેની HTTP API પ્રતિસાદ આપી રહી નથી. સ્ટેટસ
પ્રતિસાદમાં પોર્ટ સાચો છે કે નહીં અને સેવા ખરેખર તે પોર્ટ પર
લિસન કરી રહી છે કે નહીં તે તપાસો.

---

**પ્ર: શું હું સંપૂર્ણ રીસ્ટાર્ટ વિના 9Router API કી બદલી શકું?**

ના. API કી spawn સમયે environment variable મારફતે 9Routerને આપવામાં આવે છે.
ચાલતી પ્રોસેસમાં environment variables બદલી શકાતા નથી. નવી કી લાગુ કરવા માટે `POST .../rotate-key`
આપમેળે સેવાને બંધ કરીને ફરી શરૂ કરે છે. કી રોટેશન
સેવાના `stopTimeoutMs` (ડિફૉલ્ટ 15 s) ઉપરાંત તેના સ્ટાર્ટઅપ
સમયની અંદર અમલમાં આવે છે.

---

**પ્ર: રિંગ બફરની મર્યાદા શું છે અને તે ભરાઈ જાય ત્યારે શું થાય છે?**

દરેક સેવા પાસે અલગ 5 MB રિંગ બફર હોય છે. જ્યારે બફર ભરાઈ જાય છે, ત્યારે નવી લાઇનો માટે જગ્યા બનાવવા
સૌથી જૂની લૉગ લાઇનો દૂર કરવામાં આવે છે. SSE `snapshot` ઇવેન્ટ
`tail` મર્યાદાની અંદરની સૌથી તાજેતરની લાઇનો પરત કરે છે. DB રોમાં
`logsBufferPath` સેટ ન હોય ત્યાં સુધી લૉગ્સ ડિસ્ક પર સંગ્રહિત થતા નથી.
