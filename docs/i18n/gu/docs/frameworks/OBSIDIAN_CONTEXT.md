## તે શું છે

OmniRoute **Obsidian** વૉલ્ટ સાથે **સંદર્ભ સ્રોત** તરીકે જોડાય છે — એક સ્થાનિક Markdown
જ્ઞાનભંડાર, જેને એજન્ટ્સ બિલ્ટ-ઇન MCP સર્વર મારફતે વાંચે અને તેમાં લખે છે. આ
ઇન્ટિગ્રેશન ડેસ્કટૉપ ઍપની અંદર ચાલી રહેલા **Obsidian Local REST API** કમ્યુનિટી પ્લગઇન
સાથે સંચાર કરે છે, જેથી એજન્ટ્સ નોંધો શોધી શકે, ફાઇલો વાંચી/લખી/પૅચ કરી શકે, વૉલ્ટની
યાદી જોઈ શકે, દૈનિક/સાપ્તાહિક આવર્તક નોંધો સાથે કામ કરી શકે, ટૅગ્સનું સંચાલન કરી શકે,
Obsidian કમાન્ડ્સ ચલાવી શકે અને (વૈકલ્પિક રીતે) દ્વિદિશીય ડેસ્કટૉપ↔મોબાઇલ વૉલ્ટ સિંકનું
સંકલન કરી શકે.

ક્લાયન્ટ (`src/lib/obsidian/api.ts`) Local REST APIને નીચેની સુવિધાઓ સાથે રૅપ કરે છે:

- ક્ષણિક `5xx` માટે **બૅકઓફ સાથે પુનઃપ્રયાસ**, `AbortController` મારફતે **30-સેકન્ડનો સમયસમાપ્તિ સમય**.
- **ટાઇપ કરેલું ભૂલ વર્ગીકરણ** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- એક **મૈત્રીપૂર્ણ "Obsidian સુધી પહોંચી શકાતું નથી" સંકેત**, જે સામાન્ય પોર્ટની ભૂલ
  (HTTP `27123` પર, `27124` પરના MCP એન્ડપોઇન્ટ પર **નહીં**) અને Tailscale સ્વરૂપ સમજાવે છે.
- વૉલ્ટ-સાપેક્ષ **પાથ એન્કોડિંગ**, જેથી સ્પેસ/સ્લૅશ ધરાવતા નોંધ પાથ સુરક્ષિત રહે.

## સેટઅપ

Obsidian ટોકન અથવા બેઝ URL માટે **કોઈ environment variable નથી** — બંનેને
`src/lib/db/obsidian.ts` દ્વારા SQLite `key_value` ટેબલમાં (namespace `obsidian`) સંગ્રહિત
કરવામાં આવે છે. ટોકન **સંગ્રહિત સ્થિતિમાં એન્ક્રિપ્ટેડ** હોય છે (AES-256-GCM, plaintext
backward-compat fallback સાથે). Endpoint dashboardની **Context Sources** ટૅબ
(`ObsidianSourceCard`)માંથી અથવા settings REST API દ્વારા કૉન્ફિગર કરો.

> [!IMPORTANT]
> **Obsidian Local REST API** plugin ઇન્સ્ટૉલ થયેલું અને ચાલુ હોવું આવશ્યક છે. તેનું REST
> interface **HTTP `127.0.0.1:27123`** (ડિફૉલ્ટ બેઝ URL) પર સાંભળે છે. પોર્ટ `27124`
> એક _અલગ_ MCP/HTTPS endpoint છે અને settings route દ્વારા સ્પષ્ટપણે નકારવામાં આવે છે.
> અન્ય ડિવાઇસમાંથી કનેક્ટ કરતા હો, તો `http://<tailscale-ip>:27123` વાપરો.

### કૉન્ફિગરેશન કીઝ (SQLite `key_value`, namespace `obsidian`)

| કી                | હેતુ                                            | એન્ક્રિપ્ટેડ |
| ----------------- | ----------------------------------------------- | ------------ |
| `api_key`         | Local REST API bearer token                     | હા           |
| `base_url`        | REST બેઝ URL (ડિફૉલ્ટ `http://127.0.0.1:27123`) | ના           |
| `vault_path`      | vault ડિરેક્ટરીનો સંપૂર્ણ પાથ (sync માટે)       | ના           |
| `webdav_username` | જનરેટ કરેલું WebDAV username (vault sync)       | ના           |
| `webdav_password` | જનરેટ કરેલો WebDAV password (vault sync)        | હા           |
| `webdav_enabled`  | WebDAV vault sync સક્ષમ છે કે નહીં              | ના           |

### REST દ્વારા કૉન્ફિગર કરો

```bash
# Local REST API ટોકન સાચવો + માન્ય કરો (POST status check દ્વારા માન્ય કરે છે)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# કનેક્શન status તપાસો (connected, hasToken, baseUrl, vaultPath પરત કરે છે)
curl http://localhost:20128/api/settings/obsidian

# ડિસ્કનેક્ટ કરો (સંગ્રહિત ટોકન સાફ કરે છે)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

તમામ methods માટે dashboard authentication આવશ્યક છે. `POST` પોર્ટ `27124` પરના કોઈપણ URLને
નકારે છે અને સાચવતા પહેલાં Local REST API status endpointને કૉલ કરીને ટોકનને માન્ય કરે છે.

### WebDAV vault sync

`src/app/api/settings/obsidian/webdav/route.ts` વૈકલ્પિક WebDAV-backed
vault syncનું સંચાલન કરે છે (જે `src/lib/obsidianSync.ts` દ્વારા સંચાલિત થાય છે). તેને સક્ષમ કરવાથી
OmniRouteને સ્થાનિક vault ડિરેક્ટરી તરફ નિર્દેશિત કરવામાં આવે છે અને એક રૅન્ડમ WebDAV username/password જોડી બનાવવામાં આવે છે:

```bash
# vault ડિરેક્ટરી માટે WebDAV sync સક્ષમ કરો (username/password બનાવે છે)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV sync status મેળવો (credentials માત્ર સક્ષમ હોય ત્યારે જ પરત કરવામાં આવે છે)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV sync અક્ષમ કરો (credentials + સંચાલિત .stignore સાફ કરે છે)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### સુરક્ષા અને પરિવહન

WebDAV પ્રમાણીકરણ પ્રતિ-IP નિષ્ફળતા ટ્રેકિંગ અને લોકઆઉટને લાગુ કરે છે (60-સેકન્ડની વિન્ડોમાં 10 નિષ્ફળ પ્રયાસો `429 Too Many Requests` અને `Retry-After` સાથે 5-મિનિટના લોકઆઉટને ટ્રિગર કરે છે). કારણ કે WebDAV મૂળભૂત પ્રમાણીકરણ ઓળખપત્રો પ્રસારિત કરે છે, લૂપબેકની બહાર WebDAV એન્ડપોઇન્ટને ઍક્સેસ કરતી વખતે TLS (અથવા સુરક્ષિત ટનલ જેમ કે Tailscale અથવા Cloudflare Tunnel પર રૂટીંગ) સમાપ્ત કરવાની ભારપૂર્વક ભલામણ કરવામાં આવે છે.

### પ્રતિ-API-key context source (વૈકલ્પિક)

Obsidian configને `api_key_context_sources` ટેબલ
(`src/lib/db/apiKeyContextSources.ts`) દ્વારા **પ્રતિ API key** મર્યાદિત કરી શકાય છે. જ્યારે કોઈ MCP કૉલ પ્રમાણિત API
key id ધરાવે છે, ત્યારે `getObsidianConfigForApiKey()` તે કીની પોતાની token/base-URL/vault-path
(`source: "api_key"`)ને પ્રાથમિકતા આપે છે અને અન્યથા global config (`source: "global"`)નો ઉપયોગ કરે છે.

Non-sync MCP toolsને આ configuration વાંચતા પહેલાં ઉકેલાયેલી caller identity આવશ્યક છે.
identity વિનાના callerને `Obsidian API token not configured` મળે છે અને કોઈ vault
request મોકલવામાં આવતી નથી. HTTP callers તેમના request credentials દ્વારા ઉકેલાય છે; stdio callers
`OMNIROUTE_API_KEY` અથવા `ROUTER_API_KEY` દ્વારા ઉકેલાઈ શકે છે. ઉકેલી ન શકાયેલો HTTP caller
serverની environment identity વારસામાં મેળવી શકતો નથી. માત્ર placeholder IDs access માટે અધિકૃતતા આપતા નથી;
`env-key` તરીકે ઉકેલાતું માન્ય environment credential હજુ પણ સમર્થિત છે.
પ્રતિ-key Obsidian configuration વિનાની authenticated keys માટે global fallback યથાવત્ રહે છે.
ચાર `obsidian_sync_*` tools તેમનું અલગ sync-token વર્તન જાળવી રાખે છે.

## MCP સાધનો (22)

`open-sse/mcp-server/tools/obsidianTools.ts` માં વ્યાખ્યાયિત. token/base-URL પ્રતિ કોલ ઉકેલાય છે (પ્રથમ પ્રતિ-API-કી, પછી વૈશ્વિક). સાધનો કે જે OmniRoute હિટ કરે છે** સમન્વયન સર્વર** (ચાર `obsidian_sync_*` ટૂલ્સ) વધુમાં OmniRoute સેટિંગ્સમાં ગોઠવેલ સમન્વયન ઓથ ટોકન જરૂરી છે.

| `obsidian_search_structured` | JSON લોજિક એક્સપ્રેશન (and/or/regex/path ફિલ્ટર્સ) નો ઉપયોગ કરીને શોધો.                 |
| `obsidian_read_note`         | વૉલ્ટ-રિલેટિવ પાથ દ્વારા નોંધ વાંચો; વૈકલ્પિક રીતે ચોક્કસ heading/block/frontmatter.    |
| `obsidian_list_vault`        | તિજોરીમાં ફાઇલો અને ડિરેક્ટરીઓની સૂચિ બનાવો (એન્ટ્રીઓનું વૃક્ષ).                        |
| `obsidian_get_document_map`  | → લાઇન નંબરના હેડિંગના નકશા તરીકે નોંધનું મથાળું માળખું મેળવો.                          |
| `obsidian_get_note_metadata` | સંપૂર્ણ સામગ્રી વિના ફ્રન્ટમેટર, ટૅગ્સ, લિંક્સ, char/word ગણતરી મેળવો.                  |
| `obsidian_get_active_file`   | Obsidian માં હાલમાં સક્રિય ફાઇલની પાથ + સામગ્રી મેળવો.                                  |
| `obsidian_get_periodic_note` | તારીખ માટે daily/weekly/monthly સામયિક નોંધ મેળવો (આજે જો અવગણવામાં આવે તો).            |
| `obsidian_get_tags`          | બધા વૉલ્ટ ટૅગ્સને તેમની ફ્રીક્વન્સીઝ સાથે સૂચિબદ્ધ કરો.                                 |
| `obsidian_list_commands`     | ઉપલબ્ધ Obsidian આદેશ IDs ( `obsidian_execute_command` સાથે ઉપયોગ કરો) ની સૂચિ બનાવો.    |
| `obsidian_sync_status`       | OmniRoute સિંક સર્વર સ્ટેટસ: ચાલી રહ્યું છે, વૉલ્ટનું નામ, પોર્ટ, અપટાઇમ, છેલ્લું સિંક. |
| `obsidian_sync_conflicts`    | વણઉકેલાયેલી સમન્વયન તકરારની સૂચિ બનાવો (પાથ, સંઘર્ષ માર્ગ, શોધાયેલ-એટ).                 |

### લખવાના સાધનો (`write:obsidian`)

| સાધન                             | વર્ણન                                                                                |
| -------------------------------- | ------------------------------------------------------------------------------------ |
| `obsidian_write_note`            | આપેલ માર્કડાઉન સામગ્રી સાથે નોંધ બનાવો અથવા ફરીથી લખો.                               |
| `obsidian_append_note`           | નોંધમાં સામગ્રી જોડો; વૈકલ્પિક રીતે ચોક્કસ heading/block. માટે                       |
| `obsidian_patch_note`            | હેડિંગ, બ્લોક અથવા ફ્રન્ટમેટર ફીલ્ડ પર સર્જિકલ રીતે append/prepend/replace.          |
| `obsidian_delete_note`           | તિજોરીમાંથી એક નોંધ કાયમી ધોરણે કાઢી નાખો.                                           |
| `obsidian_move_note`             | વૉલ્ટની અંદર નોંધ ખસેડો અથવા તેનું નામ બદલો.                                         |
| `obsidian_execute_command`       | Obsidian આદેશને તેના આદેશ ID દ્વારા ચલાવો.                                           |
| `obsidian_open_file`             | Obsidian માં ફાઇલ ખોલો (જો તે અસ્તિત્વમાં ન હોય તો તેને બનાવે છે).                   |
| `obsidian_sync_trigger`          | તાત્કાલિક બાયડાયરેક્શનલ ડેસ્કટૉપ ↔ મોબાઇલ વૉલ્ટ સિંકને ટ્રિગર કરો.                   |
| `obsidian_sync_resolve_conflict` | સમન્વયન સંઘર્ષને ઉકેલો: `local` (મોબાઇલ), `remote` (ડેસ્કટોપ) અથવા `keep-both` રાખો. |

> [!NOTE]
> `obsidian_patch_note` લક્ષ્યો વૈકલ્પિક `createTargetIfMissing` સાથે `heading | block | frontmatter` ના `targetType` અને `append | prepend | replace` ના `operation` સ્વીકારે છે. ચાર `obsidian_sync_*` ટૂલ્સ સ્થાનિક સિંક સર્વર સાથે વાત કરે છે (`http://127.0.0.1:27781` બાય ડિફૉલ્ટ) અને સિંક ટોકન જરૂરી છે.

### અવકાશ

વાંચન સાધનો માટે `read:obsidian` જરૂર છે; લખવાના સાધનોને `write:obsidian` જરૂર છે. અમલીકરણ એ `open-sse/mcp-server/server.ts` માં `withScopeEnforcement()` દ્વારા સંચાલિત Notion — જેવું જ છે, `OMNIROUTE_MCP_ENFORCE_SCOPES=true` પર ગેટેડ અને HTTP/SSE કૉલર્સ માટે ફરજ પાડવામાં આવે છે જેમની API કીમાં `manage`/`admin` અભાવ હોય છે, `OMNIROUTE_MCP_SCOPES` અથવા API કીના અવકાશ સંદર્ભમાંથી પ્રાપ્ત કરેલ મંજૂર સ્કોપ્સ સાથે. [MCP-SERVER.md](./MCP-SERVER.md) જુઓ.

## ઉપયોગના કિસ્સાઓ

- **વૉલ્ટ-આધારિત જવાબો** — `obsidian_search_simple` / `obsidian_search_structured`
  પછી `obsidian_read_note`, જેથી એજન્ટ તમારી વાસ્તવિક નોંધોના આધારે જવાબ આપે.
- **નોંધ લેખન / જર્નલિંગ** — એજન્ટનું આઉટપુટ, સારાંશો અથવા દૈનિક નોંધો
  (`obsidian_get_periodic_note`) વૉલ્ટમાં નોંધવા માટે `obsidian_write_note`, `obsidian_append_note` અથવા
  ચોક્કસ ફેરફાર કરતું `obsidian_patch_note`.
- **વૉલ્ટ નેવિગેશન** — વાંચવા/લખવા પહેલાં માળખું શોધવા માટે `obsidian_list_vault`, `obsidian_get_document_map` અને
  `obsidian_get_tags`.
- **Obsidian ઑટોમેશન** — એજન્ટમાંથી પ્લગઇન્સ/કમાન્ડ્સ ચલાવવા માટે `obsidian_list_commands` + `obsidian_execute_command`;
  UIમાં નોંધ દર્શાવવા માટે `obsidian_open_file`.
- **મોબાઇલ સિંક** — WebDAV સિંક સક્ષમ કરો, પછી ડેસ્કટૉપ↔મોબાઇલનું સંકલન કરવા અને વિરોધાભાસો ઉકેલવા માટે `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`.
