> **સત્તાવાર સ્રોત:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, અને
> `src/app/(dashboard)/dashboard/plugins/`
> **છેલ્લે અપડેટ કરેલું:** 2026-06-28 — v3.8.40

OmniRoute સાથે WordPress-શૈલીની પ્લગઇન સિસ્ટમ આવે છે. પ્લગઇન્સ સ્વયં-સમાવિષ્ટ
ડિરેક્ટરીઓ છે — દરેકમાં `plugin.json` મેનિફેસ્ટ અને એક એન્ટ્રી ફાઇલ હોય છે — જે
રેક્વેસ્ટ પાઇપલાઇન (`onRequest` / `onResponse` / `onError`) અને લાઇફસાઇકલ
ઇવેન્ટ્સ (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`) સાથે હૂક થાય છે.

**પ્લગઇન માર્કેટપ્લેસ** એ આ સિસ્ટમની ઉપરનું શોધ સ્તર છે. તે ઇન્સ્ટોલ કરી શકાય
તેવા પ્લગઇન્સનો બ્રાઉઝ કરી શકાય એવો કેટલોગ પ્રસ્તુત કરે છે. મૂળભૂત રીતે કેટલોગ
એક નાની બિલ્ટ-ઇન સીડ રજિસ્ટ્રી છે; ઓપરેટર તેને કસ્ટમ રિમોટ રજિસ્ટ્રી URL તરફ
નિર્દેશિત કરી શકે છે, અને તે સ્થિતિમાં fetch ને DNS-રિઝોલ્વિંગ SSRF ગાર્ડ દ્વારા
સુરક્ષિત બનાવવામાં આવે છે ([સુરક્ષા](#security) જુઓ).

દરેક પ્લગઇન રૂટ **માત્ર લૂપબૅક માટે** છે (Tier 1 — `LOCAL_ONLY`): પ્લગઇન્સ
ચાઇલ્ડ પ્રોસેસમાં કોડ લોડ અને એક્ઝિક્યુટ કરે છે, તેથી auth ગમે તે હોય,
નોન-લૂપબૅક મૂળથી રૂટ્સ સુધી પહોંચી શકાતું નથી. જુઓ
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md).

## તે કેવી રીતે બંધબેસે છે Together

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **રજિસ્ટ્રી સ્તર** — `src/lib/plugins/marketplace.ts`: સૂચિ / સૂચિની શોધ કરે છે, કોઈપણ નિષ્ફળતા પર બીજ રજિસ્ટ્રી પર પાછા આવે છે.
- **જીવનચક્ર સ્તર** — `src/lib/plugins/manager.ts` (`pluginManager` સિંગલટન): ઇન્સ્ટોલ કરો, અપગ્રેડ કરો, સક્રિય કરો, નિષ્ક્રિય કરો, અનઇન્સ્ટોલ કરો, સ્કેન કરો, સ્ટાર્ટઅપ લોડ કરો.
- **મેનિફેસ્ટ સ્તર** — `src/lib/plugins/manifest.ts`: `plugin.json` માટે Zod સ્કીમા + ડિફોલ્ટ્સ.
- **સ્કેનર** — `src/lib/plugins/scanner.ts`: પ્લગઇન ડિરેક્ટરી હેઠળ ડિસ્ક પર પ્લગઇન્સ શોધે છે.
- **લોડર** — `src/lib/plugins/loader.ts`: દરેક પ્લગઇનને અલગ Node.js ચાઇલ્ડ પ્રક્રિયામાં બનાવે છે અને બ્રોકર્સ IPC પર કૉલને હૂક કરે છે. બાળક સેન્ડબોક્સ નથી (નીચે "પ્લગઇન એક્ઝેક્યુશન આઇસોલેશન" જુઓ).

## માર્કેટપ્લેસ કેટલોગ

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) `MarketplaceEntry`
ઑબ્જેક્ટ્સની સૂચિ પરત કરે છે:

| ફીલ્ડ         | પ્રકાર   | નોંધો                                     |
| ------------- | -------- | ----------------------------------------- |
| `name`        | string   | kebab-case પ્લગઇન નામ                     |
| `version`     | string   | semver                                    |
| `description` | string   | સંક્ષિપ્ત સારાંશ                          |
| `author`      | string   | લેખક / સંસ્થા                             |
| `license`     | string   | SPDX-શૈલીનું લાઇસન્સ id                   |
| `downloadUrl` | string   | સ્રોત ડાઉનલોડ URL (ખાલી હોઈ શકે)          |
| `repository`  | string?  | વૈકલ્પિક રિપોઝિટરી URL                    |
| `tags`        | string[] | શોધ/ફિલ્ટર ટૅગ્સ                          |
| `downloads`   | number   | ડાઉનલોડની સંખ્યા                          |
| `rating`      | number   | 0–5                                       |
| `verified`    | boolean  | એન્ટ્રી ચકાસાયેલ તરીકે ચિહ્નિત છે કે નહીં |
| `lastUpdated` | string   | ISO-જેવી તારીખની સ્ટ્રિંગ                 |

જ્યારે કોઈ કસ્ટમ રજિસ્ટ્રી URL કૉન્ફિગર કરેલું ન હોય, ત્યારે કેટલોગ બિલ્ટ-ઇન
`SEED_REGISTRY` હોય છે (હાલમાં `request-logger`, `rate-limiter`, `cost-tracker`, અને
`theme-manager`). સીડ રજિસ્ટ્રી હંમેશાં ઉપલબ્ધ હોય છે — જો કૉન્ફિગર કરેલી રિમોટ
રજિસ્ટ્રી સુધી પહોંચી ન શકાય, તે નોન-`200` સ્ટેટસ પરત કરે, અથવા અજાણ્યું બૉડી
પરત કરે, તો `listMarketplacePlugins()` ચેતવણી લૉગ કરે છે અને સીડ સૂચિનો ઉપયોગ કરે છે.

> નોંધ: માર્કેટપ્લેસ **કેટલોગ** (બ્રાઉઝ/શોધ) એક છેડાથી બીજા છેડા સુધી જોડાયેલો
> છે, પરંતુ કેટલોગમાંથી એક-ક્લિક માર્કેટપ્લેસ **ઇન્સ્ટોલ** હજી અમલમાં મૂકાયું નથી —
> માર્કેટપ્લેસ એન્ટ્રી પરનું ડૅશબોર્ડનું "ઇન્સ્ટોલ" બટન હાલમાં "ટૂંક સમયમાં આવી રહ્યું છે"
> એવી સૂચના દર્શાવે છે. હાલમાં ઇન્સ્ટોલેશન લોકલ-પાથ ઇન્સ્ટોલ ફ્લો
> (`POST /api/plugins`) અને ઑન-ડિસ્ક શોધ (`POST /api/plugins/scan`) દ્વારા થાય છે.

## REST API

બધા અંતિમ બિંદુઓને મેનેજમેન્ટ ઓથ (`requireManagementAuth`)ની જરૂર છે** અને** લૂપબેક માત્ર — `/api/plugins` છે અને `/api/plugins/` `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) માં સૂચિબદ્ધ છે.

| અંતિમ બિંદુ                        | પદ્ધતિ | વર્ણન                                                             |
| ---------------------------------- | ------ | ----------------------------------------------------------------- |
| `/api/plugins`                     | GET    | ઇન્સ્ટોલ કરેલા પ્લગિન્સની સૂચિ બનાવો (વૈકલ્પિક `?status=` ફિલ્ટર) |
| `/api/plugins`                     | POST   | પ્લગઇન સ્ત્રોત ડિરેક્ટરીમાંથી પ્લગઇન ઇન્સ્ટોલ કરો                 |
| `/api/plugins/scan`                | POST   | પ્લગઈન ડાયરેક્ટરી સ્કેન કરો અને નવા પ્લગઈન્સ રજીસ્ટર કરો          |
| `/api/plugins/marketplace`         | GET    | માર્કેટપ્લેસ કેટલોગ એન્ટ્રીઓની સૂચિ બનાવો                         |
| `/api/plugins/marketplace/install` | POST   | નામ દ્વારા માર્કેટપ્લેસ પ્લગઇન ઇન્સ્ટોલ કરો                       |
| `/api/plugins/[name]`              | GET    | ઇન્સ્ટોલ કરેલ પ્લગઇન વિગતો મેળવો                                  |
| `/api/plugins/[name]`              | DELETE | પ્લગઇન અનઇન્સ્ટોલ કરો                                             |
| `/api/plugins/[name]/activate`     | POST   | સક્રિય કરો ( + રજિસ્ટર હુક્સ લોડ કરો)                             |
| `/api/plugins/[name]/deactivate`   | POST   | નિષ્ક્રિય કરો (ફાયર `onDeactivate`, અનરજિસ્ટર હુક્સ)              |
| `/api/plugins/[name]/config`       | GET    | પ્લગઇન રૂપરેખા + રૂપરેખા સ્કીમા મેળવો                             |
| `/api/plugins/[name]/config`       | PUT    | પ્લગઇન રૂપરેખા અપડેટ કરો (સ્કીમા સામે માન્ય)                      |

`GET /api/plugins` `status` ફિલ્ટર `installed` / `active` / `inactive` / `error` માંથી એકને સ્વીકારે છે. અમાન્ય મૂલ્ય `400` પરત કરે છે.

### ઇન્સ્ટોલ કરેલા પ્લગિન્સની સૂચિ બનાવો

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### સ્થાનિક પાથથી ઇન્સ્ટોલ કરો

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` એ હોવું જ જોઈએ** સંપૂર્ણ** ડિરેક્ટરીનો માર્ગ** પ્લગઇન સ્ત્રોત નિર્દેશિકાની અંદર** : પ્લગઇન રૂટની બાજુમાં `plugin-sources`, તેથી ડિફૉલ્ટ રૂપે `~/.omniroute/plugin-sources/`, અથવા જ્યારે તે ચલ સેટ હોય ત્યારે `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` (`getPluginSourcesDir()` માં `src/lib/plugins/installSource.ts`). ત્યાં પહેલા પ્લગઇનની નકલ અથવા ક્લોન કરો. જ્યારે પાથમાં `..` અથવા નલ બાઈટ હોય, તે ડિરેક્ટરીની બહાર હોય, સિમલિંક દ્વારા તેની બહાર રિઝોલ્યુશન થાય, સિમલિંક હોય કે જેનું લક્ષ્ય તેની બહાર હોય અથવા જ્યારે ડિરેક્ટરી અસ્તિત્વમાં ન હોય ત્યારે `400` સાથે ઇન્સ્ટોલને નકારવામાં આવે છે. સ્ત્રોત નિર્દેશિકામાં માન્ય `plugin.json` (અથવા એકના માતા-પિતા હોવો) હોવો આવશ્યક છે. સફળતા પર પ્રતિભાવ સ્થાપિત પ્લગઇન પંક્તિ સાથે `201` છે.

અન્ય પ્લગઇન રૂટ્સથી વિપરીત, આને મેનેજમેન્ટ ઓળખપત્ર (ડેશબોર્ડ સત્ર અથવા મેનેજ-સ્કોપ્ડ API કી) ની જરૂર પડે છે, ભલે લૉગિન અક્ષમ હોય (`requireLogin=false`): કોડ ઇન્સ્ટોલ કરવું એ ક્યારેય અનામી ક્રિયા નથી. આ જ `POST /api/plugins/marketplace/install` (body `{ "name": "<plugin>" }`) પર લાગુ પડે છે.

### બજાર બ્રાઉઝ કરો

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### પ્લગઇન રૂપરેખા અપડેટ કરો

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` એ પ્લગઇનના `configSchema` (મેનિફેસ્ટમાં ઘોષિત) ની સામે `src/lib/plugins/manifest.ts` થી `validatePluginConfig()` સાથે શરીરને માન્ય કરે છે : દરેક કી સ્કીમામાં જાહેર થવી જોઈએ, મૂલ્યો ઘોષિત પ્રકાર સાથે મેળ ખાતી હોવી જોઈએ, `number` ફીલ્ડ્સ `min`/`max` નું સન્માન કરે છે, અને `select` ફીલ્ડ્સ ઘોષિત `enum` સાથે મેળ ખાતી હોવી જોઈએ. કોઈપણ ઉલ્લંઘન `400` પરત કરે છે અને કંઈપણ સંગ્રહિત થતું નથી. એક પ્લગઇન કે જે `configSchema` જાહેર કરતું નથી તેની પાસે કોઈ રૂપરેખાંકિત કી નથી, તેથી વિનંતીને `400` સાથે નકારી કાઢવામાં આવે છે ("પ્લગઇન કોઈપણ રૂપરેખાંકિત કી જાહેર કરતું નથી").

## Configuration

### Plugin directory

Plugins OmniRoute data directory હેઠળ રહે છે:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (અથવા manifest.main જે તરફ નિર્દેશ કરે તે)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) તે directory ને
ત્રણ પગલાંમાં resolve કરે છે:

1. **`OMNIROUTE_PLUGINS_DIR`**, જ્યારે set હોય — `HOME` માં જે કંઈ હોય તેને ધ્યાનમાં લીધા વિના, તેનો જેમનો તેમ ઉપયોગ થાય છે. આ
   Docker/K8s માટેનું સ્પષ્ટ નિયંત્રણ છે, જ્યાં plugin tree એવા path પર bind-mounted હોય છે
   જેને સામાન્ય રીતે container ની home directory સાથે કોઈ સંબંધ હોતો નથી (#11827).
2. `<home>/.omniroute/plugins`, જ્યાં `<home>` `HOME` / `USERPROFILE`
   environment variables માંથી મળે છે.
3. `/tmp/.omniroute/plugins`, જ્યારે process કોઈ home export કરતું જ ન હોય.

Resolve થયેલી directory startup વખતે એક વાર `scanner.dir_resolved` તરીકે log થાય છે અને
જે input પસંદ થયો તેનું નામ (`OMNIROUTE_PLUGINS_DIR`, `home`, અથવા `no-home-fallback`) દર્શાવે છે — જેથી
ચુપચાપ પગલું 3 પર પહોંચતી image માત્ર ખાલી plugin list report કરવાને બદલે તે બાબત સ્પષ્ટ કરે.
`POST /api/plugins/scan` ત્યાંની એવી કોઈપણ subdirectory શોધે છે જેમાં માન્ય
`plugin.json` હોય અને તેને register કરે છે; એ જ directory એ root છે જેમાં
`pluginManager.install()` plugins copy કરે છે, તેથી override discovery અને
installation બંનેને સાથે ખસેડે છે.

> **`OMNIROUTE_PLUGINS_DIR`, `OMNIROUTE_PLUGIN_PATH` નથી.** બાદવાળું માત્ર
> CLI command-plugin loader (`bin/cli/plugins.mjs`) દ્વારા `omniroute-cmd-*` npm
> packages શોધવા માટે વાંચવામાં આવે છે, જે `omniroute` subcommands ઉમેરે છે — અહીં વર્ણવેલા runtime scanner પર
> તેની કોઈ અસર નથી. તેની વિગતો માટે [PLUGINS.md](./PLUGINS.md) જુઓ.

### Custom marketplace registry URL

Marketplace catalog source `pluginMarketplaceUrl` setting માંથી વાંચવામાં આવે છે
(`src/lib/plugins/marketplace.ts`, `settings.pluginMarketplaceUrl` વાંચે છે). જ્યારે તેને
`http(s)` URL પર set કરવામાં આવે છે, ત્યારે `listMarketplacePlugins()` તે URL fetch કરે છે અને
entries ની top-level JSON array અથવા `plugins` array ધરાવતો object,
બંનેમાંથી કોઈ એક સ્વીકારે છે; string `name` વગરની entries filter કરીને દૂર કરવામાં આવે છે. જ્યારે તે unset હોય (અથવા fetch
SSRF guard માં નિષ્ફળ જાય / ખરાબ response પરત કરે), ત્યારે built-in seed registry નો
ઉપયોગ થાય છે.

Dashboard માં "Marketplace" tab આ URL માટે field આપે છે (તેને
`GET /api/settings` માંથી પાછું વાંચવામાં આવે છે).

> અમલીકરણ નોંધ: dashboard ની "Save" action
> `pluginMarketplaceUrl` ને `PATCH /api/settings` પર મોકલે છે. આ લખતી વખતે આ
> key `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) માં જાહેર કરેલી નથી, તેથી તેના પર આધાર રાખતા પહેલાં તમારા
> release માં persistence ચકાસો — settings
> store માં key હાજર થયા પછી **read** path (`getSettings()` →
> `listMarketplacePlugins()`) તેનું પાલન કરે છે.

## સુરક્ષા

### માત્ર રૂટ ટાયર — લૂપબેક

પ્લગઇન્સ પેદા કરેલી ચાઇલ્ડ પ્રક્રિયાઓમાં કોડનો અમલ કરે છે, તેથી સમગ્ર `/api/plugins` સપાટીને `LOCAL_ONLY` (ટાયર 1) વર્ગીકૃત કરવામાં આવે છે. લૂપબેક અમલ બિનશરતી ચાલે છે** પહેલાં** કોઈપણ ઓથ ચેક, જેથી ટનલ પર બોક્સ સુધી પહોંચતું લીક થયેલ મેનેજમેન્ટ ટોકન હજુ પણ પ્લગઈનને ઈન્સ્ટોલ, એક્ટિવેટ કે અનઈન્સ્ટોલ કરી શકતું નથી. [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) અને સખત નિયમો #15 / #17 જુઓ.

### માર્કેટપ્લેસ રજિસ્ટ્રી SSRF ગાર્ડ

કસ્ટમ રજિસ્ટ્રી URL એ હુમલાખોર-પ્રભાવી ગોઠવણી છે, તેથી તેને લાવતા પહેલા `listMarketplacePlugins()` તેને બે સ્તરો દ્વારા ચલાવે છે:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` ન હોય તેવી કોઈપણ વસ્તુને નકારી કાઢે છે.
   - શાબ્દિક private/loopback/link-local/ULA હોસ્ટને નકારી કાઢે છે (IPv4** અને** IPv6, IPv4-mapped સહિત ) પ્રમાણભૂત `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) દ્વારા.
   - ઉકેલે છે** બંને** `A` અને `AAAA` રેકોર્ડ કરે છે અને જો નકારે છે** કોઈપણ** ઉકેલાયેલ સરનામું ખાનગી — છે જે જાહેર-યજમાનનામ → ખાનગી-IP બાયપાસને બંધ કરે છે.
   - **નિષ્ફળ બંધ** : DNS રીઝોલ્યુશન નિષ્ફળતા URL ને નકારી કાઢે છે.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`) : લાવવાના સમયે માત્ર જાહેર-માત્ર URL ગાર્ડને ફરીથી લાગુ કરે છે અને** બ્લોક્સ રીડાયરેક્ટ** (કોઈ જાહેર → ખાનગી `30x` પીવોટ નથી).

એક URL જે કોઈપણ સ્તરમાં નિષ્ફળ જાય છે તે વિનંતીને રદ કરતું નથી — માર્કેટપ્લેસ ચુપચાપ બિલ્ટ-ઇન સીડ રજિસ્ટ્રીમાં પાછું આવે છે અને ચેતવણી લોગ કરે છે.

> આ રક્ષકને PR #3774 માં ખાસ કરીને A + AAAA ઉકેલવા અને IPv4-only ચેકને બદલે પ્રમાણભૂત `isPrivateHost` ઉપયોગ કરવા માટે સખત બનાવવામાં આવ્યો હતો.

### પ્લગઇન એક્ઝેક્યુશન આઇસોલેશન

> **પ્લગઇન્સ ડિફૉલ્ટ રૂપે સેન્ડબોક્સ કરેલા નથી.** બાળક એ OmniRoute વપરાશકર્તા તરીકે ચાલતી સામાન્ય Node.js પ્રક્રિયા છે, જેમાં કોઈ VM સંદર્ભ અને કોઈ Node.js પરવાનગી ફ્લેગ નથી, તેથી પ્લગઈન કોડ કોઈપણ ફાઇલ વાંચી અને લખી શકે છે જે વપરાશકર્તા કરી શકે છે, પ્રોગ્રામ ચલાવી શકે છે અને નેટવર્ક સુધી પહોંચી શકે છે. `requires.permissions` માત્ર નક્કી કરે છે કે બાળકને કયા પર્યાવરણ ચલો પ્રાપ્ત થાય છે; અન્ય પરવાનગીઓ લાગુ કરવામાં આવી નથી. ઑપ્ટ-ઇન `PLUGIN_PERMISSION_MODEL_ENABLED` ફીચર ફ્લેગ (ડિફૉલ્ટ રૂપે બંધ) દરેક પ્લગઇનને તે પરવાનગીઓમાંથી બનેલ Node.js પરવાનગી મૉડલ હેઠળ ચલાવે છે, `network` સિવાય, જેને Node.js પ્રતિબંધિત કરી શકતું નથી (જુઓ [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#%E0%AA%AA%E0%AA%B0%E0%AA%B5%E0%AA%BE%E0%AA%A8%E0%AA%97%E0%AB%80-%E0%AA%B8%E0%AA%BF%E0%AA%B8%E0%AB%8D%E0%AA%9F%E0%AA%AE) ). તમે વિશ્વાસ કરો છો તે જ પ્લગઇન્સ ઇન્સ્ટોલ કરો. નીચેની પ્રક્રિયાની સીમા ક્રેશ અને હેંગ્સ ધરાવે છે; તે સુરક્ષા સીમા નથી.

- **પ્રક્રિયા અલગતા** — `loadPlugin()` (`src/lib/plugins/loader.ts`) દરેક પ્લગઇનને અલગ Node.js ચાઇલ્ડ પ્રક્રિયામાં બનાવે છે અને IPC પર વાતચીત કરે છે. `SIGTERM` → `SIGKILL` એસ્કેલેશન સાથે હૂક કૉલ્સનો સમય સમાપ્ત થાય છે.
- **Env મંજૂર સૂચિ** — બાળકને પર્યાવરણ ચલોનો માત્ર માન્ય સૂચિબદ્ધ સમૂહ પ્રાપ્ત થાય છે; જ્યારે મેનિફેસ્ટ `env` પરવાનગીની વિનંતી કરે ત્યારે જ વ્યાપક સમૂહ આપવામાં આવે છે.
- **સ્ત્રોત નિયંત્રણ સ્થાપિત કરો** — `POST /api/plugins` ફક્ત પ્લગઇન સ્ત્રોત નિર્દેશિકામાંથી જ વાંચે છે (જુઓ "સ્થાનિક પાથમાંથી ઇન્સ્ટોલ કરો"): પાથ `realpath` સાથે પ્રમાણભૂત છે, તે નિર્દેશિકાની અંદર સખત રીતે રહેવું જોઈએ, અને કોઈ પણ વસ્તુની નકલ કરવામાં આવે તે પહેલાં સિમલિંક વહન કરતા સ્ત્રોત વૃક્ષને નકારવામાં આવે છે.
- **પાથ નિયંત્રણ** — install/upgrade/uninstall ભારપૂર્વક જણાવે છે કે પ્લગઇન ડિરેક્ટરી અને `manifest.main` ઉકેલે છે** અંદર** કોઈપણ નકલ અથવા પુનરાવર્તિત કાઢી નાખતા પહેલા મેનેજ્ડ પ્લગઇન રૂટ (ટેમ્પર્ડ DB પાથ અને `manifest.main` માં `../` ટ્રાવર્સલ સામે રક્ષણ આપે છે). સક્રિયકરણ `realpath` દ્વારા સિમલિંક્સને ઉકેલે છે અને એન્ટ્રી પોઈન્ટ લોડ કરવાનો ઇનકાર કરે છે જે પ્લગઇન ડિરેક્ટરીમાંથી બહાર નીકળી જાય છે.
- **વૈકલ્પિક અખંડિતતા પિન** — મેનિફેસ્ટ `integrity` (`sha256-<base64>`, SRI ફોર્મેટ) ફીલ્ડ જાહેર કરી શકે છે. જ્યારે હાજર હોય, ત્યારે લોડર લોડ સમયે એન્ટ્રી ફાઇલ હેશને ચકાસે છે અને મેળ ખાતી વખતે સક્રિય કરવાનો ઇનકાર કરે છે. તે છેડછાડ-શોધની પસંદગી છે,** નથી** સુરક્ષા સીમા: લોડ કરેલ પ્લગઇન શું કરી શકે છે તે મર્યાદિત કરતું નથી.
- **હુક્સમાં કોઈ ક્લાયંટ ઓળખપત્રો નથી** — સંદર્ભ `onRequest`, `onResponse` અને `onError` ને `authorization`, `x-api-key`, `proxy-authorization` અને `cookie` હેડરો દૂર કરવામાં આવ્યા છે, અને API કી રેકોર્ડ કોઈ કી મૂલ્ય ધરાવતું નથી ( `src/lib/plugins/hooks.ts` માં`redactPluginContext()` ).

## મેનિફેસ્ટ (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) દ્વારા માન્ય :

| ક્ષેત્ર            | પ્રકાર      | નોંધો                                                          |
| ------------------ | ----------- | -------------------------------------------------------------- |
| `name`             | શબ્દમાળા    | જરૂરી; કબાબ-કેસ (`^[a-z0-9-]+$`), 1–100 અક્ષરો                 |
| `version`          | શબ્દમાળા    | જરૂરી; સેમેવર (`MAJOR.MINOR.PATCH`)                            |
| `description`      | શબ્દમાળા?   | ≤ 500 અક્ષરો                                                   |
| `author`           | શબ્દમાળા?   | ≤ 200 અક્ષરો                                                   |
| `license`          | શબ્દમાળા?   | `MIT` માટે ડિફોલ્ટ                                             |
| `main`             | શબ્દમાળા?   | એન્ટ્રી ફાઇલ; `index.js` માટે ડિફોલ્ટ                          |
| `source`           | enum?       | `local` \| `marketplace` ( `local` માટે ડિફોલ્ટ )              |
| `tags`             | શબ્દમાળા[]? | ટૅગ્સ શોધો                                                     |
| `requires`         | પદાર્થ?     | `{ omniroute?, permissions[] }`                                |
| `hooks`            | પદાર્થ?     | બુલિયન્સ જાહેર કરે છે કે પ્લગઇન કયા હૂકને અમલમાં મૂકે છે       |
| `skills`           | પદાર્થ[]?   | વૈકલ્પિક કૌશલ્ય વ્યાખ્યાઓ                                      |
| `enabledByDefault` | બુલિયન?     | ઇન્સ્ટોલ પર સ્વતઃ-સક્રિય કરો                                   |
| `configSchema`     | પદાર્થ?     | રૂપરેખા ક્ષેત્રોનો નકશો (`string`/`number`/`boolean`/`select`) |
| `integrity`        | શબ્દમાળા?   | વૈકલ્પિક `sha256-<base64>` એન્ટ્રી-ફાઈલ પિન                    |

પરવાનગીઓ enum `network` / `file-read` / `file-write` / `env` / `exec` માંથી લેવામાં આવે છે. માત્ર `env` રનટાઇમ અસર હોય છે (બાળક માટે થોડી મોટી પર્યાવરણ-ચલ મંજૂર સૂચિ); અન્ય ઘોષણાઓ છે અને તેનો અમલ થતો નથી.

## જીવનચક્ર પ્રવાહ

```
install (POST /api/plugins, પાથ)
  → મેનિફેસ્ટ સ્કૅન/માન્ય કરો → સ્ટેજિંગમાં કૉપિ કરો → main ડિરેક્ટરીની અંદર હોવાની ખાતરી કરો
  → ~/.omniroute/plugins/<name> માં અવિભાજ્ય રીતે નામ બદલો → DB પંક્તિ દાખલ કરો
  → onInstall ચલાવો → જો enabledByDefault હોય: સક્રિય કરો

activate (POST /api/plugins/{name}/activate)
  → realpath સમાવિષ્ટતા તપાસ → loadPlugin() (ચાઇલ્ડ પ્રોસેસ શરૂ કરો)
  → જાહેર કરેલા હૂક્સ નોંધણી કરો → status = "active" → onActivate ચલાવો

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate ચલાવો (નોંધણી રદ કરતાં પહેલાં) → હૂક્સની નોંધણી રદ કરો
  → ચાઇલ્ડ પ્રોસેસ સમાપ્ત કરો → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → સક્રિય હોય તો નિષ્ક્રિય કરો → onUninstall ચલાવો
  → સમાવિષ્ટતા ચકાસીને પ્લગઇન ડિરેક્ટરી પુનરાવર્તિત રીતે કાઢી નાખો → DB પંક્તિ કાઢી નાખો
```

જે ડિરેક્ટરીનું મેનિફેસ્ટ સંસ્કરણ ઇન્સ્ટૉલ કરેલા સંસ્કરણ કરતાં **ચોક્કસપણે
નવું** હોય, તેની સામે `install` ફરી ચલાવવાથી આપમેળે અપગ્રેડ થાય છે (સ્વચ્છ પુનઃઇન્સ્ટૉલેશન; કૉન્ફિગ
ડિફૉલ્ટ મૂલ્યો પર રીસેટ થાય છે). સમાન અથવા જૂનું સંસ્કરણ નકારવામાં આવે છે.

## ડેશબોર્ડ

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) પરનું ડેશબોર્ડ પૃષ્ઠ બે ટેબ પ્રદાન કરે છે:

- **ઇન્સ્ટોલ કરેલ** — તેમના ઘોષિત હુક્સ, એક activate/deactivate ટૉગલ, અનઇન્સ્ટોલ બટન અને "પ્લગઇન્સ માટે સ્કેન" ક્રિયા (`POST /api/plugins/scan`) સાથે સ્થાપિત પ્લગિન્સની યાદી આપે છે.
- **બજાર** — કસ્ટમ રજિસ્ટ્રી URL સેટ કરવા માટે ફીલ્ડ સાથે `GET /api/plugins/marketplace` માંથી કેટલોગ બતાવે છે.

પૃષ્ઠ હંમેશા ચેતવણી બતાવે છે કે પ્લગઇન્સ OmniRoute પ્રક્રિયાના સંપૂર્ણ વિશેષાધિકારો સાથે ચાલે છે.

પ્રતિ-પ્લગઇન રૂપરેખા પૃષ્ઠ `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) પર રહે છે.
