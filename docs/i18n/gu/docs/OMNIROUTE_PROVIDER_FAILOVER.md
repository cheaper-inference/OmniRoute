ફરી પ્રયાસના નિર્ણયો લેવામાં આવે તે પહેલાં નિષ્ફળતાઓનું વર્ગીકરણ કરવામાં આવે છે.

સમયસમાપ્તિ, નેટવર્ક ભૂલો, દર મર્યાદાઓ અને પ્રદાતા 5xx પ્રતિસાદો જેવી ક્ષણિક નિષ્ફળતાઓ નિષ્ફળ થઈ શકે છે. એક્ઝોસ્ટેડ ક્વોટા અથવા ક્રેડિટ (ક્વોટા 429, અથવા 402 ચુકવણી જરૂરી) એ જ પ્રદાતા પર ક્યારેય ફરી પ્રયાસ કરવામાં આવતો નથી પરંતુ અન્ય એકને નિષ્ફળ જાય છે, જેનો ક્વોટા અલગ છે. પ્રમાણીકરણ ભૂલો, પરવાનગી ભૂલો, અમાન્ય વિનંતીઓ, અનુપલબ્ધ મોડેલો અને અજાણી નિષ્ફળતાઓ માટે આંખ આડા કાન કરવામાં આવતાં નથી.

ડિફૉલ્ટ ક્રોસ-પ્રોવાઇડર નીતિ પ્રદાતાના ત્રણ પ્રયાસો, દર મર્યાદાઓ અને સમયસમાપ્તિનો પુનઃપ્રયાસ કરવાની મંજૂરી આપે છે, થાકેલા ક્વોટા પર નિષ્ફળ જાય છે અને વહીવટી અક્ષમતાને અસ્થાયી સર્કિટ સ્થિતિથી અલગ રાખે છે.

## જ્યાં તે લાગુ પડે છે

- **કોમ્બોઝ** કોમ્બોની પોતાની વ્યૂહરચના અને સેટિંગ્સ અનુસાર તેમના લક્ષ્યો વચ્ચે નિષ્ફળ જાય છે.
- **એકદમ મોડેલ આઈડી** (કોઈ `provider/` ઉપસર્ગ નથી) કે જે ઘણા સક્રિય પ્રદાતાઓ સેવા આપે છે, તે ચોક્કસ નામના કોમ્બો વિના, પ્રથમ પ્રદાતા અનુમાન પસંદગીઓને મોકલવામાં આવે છે. જો તે પ્રયાસ નિષ્ફળ જાય તે રીતે નીતિ પર નિષ્ફળ જાય, તો તે જ વિનંતી આગામી સક્રિય પ્રદાતાને મોકલવામાં આવે છે જે id સેવા આપે છે. પ્રતિસાદમાં `x-omniroute-fallback-attempts` હોય છે, જેણે જવાબ આપ્યો હોય તે પહેલાં અજમાવેલા પ્રદાતાઓની સંખ્યા હોય છે.
  - દરેક વૈકલ્પિકને બરાબર અધિકૃત કરવામાં આવે છે જાણે અનુમાન તેને પસંદ કર્યું હોય. API કી બ્લોક્સનું લક્ષ્ય અથવા સ્વીકારતું નથી તે અપસ્ટ્રીમ કૉલ વિના છોડવામાં આવે છે, અને ક્લાયન્ટને વાસ્તવિક અપસ્ટ્રીમ ભૂલ મળે છે, તે લક્ષ્ય માટે નીતિ અસ્વીકાર નહીં કે જેનું નામ ક્યારેય આપવામાં આવ્યું નથી.
  - માત્ર નિષ્ફળ પ્રતિસાદ આગળ વધે છે: પ્રથમ સ્ટ્રીમ કરેલ બાઈટ પછી કંઈપણ નિષ્ફળ થતું નથી.
  - વિનંતી કરેલ મોડેલના દરેક પ્રદાતા નિષ્ફળ જાય પછી જ ઇમરજન્સી ફોલબેક મોડલ સ્વેપ લાગુ થાય છે.
  - કનેક્શન (`x-omniroute-connection`) પર પિન કરેલી વિનંતી તેના પર રહે છે.
  - પ્રિફિક્સ્ડ આઈડી (`provider/model`) ક્યારેય બીજા પ્રદાતાને રીરુટ કરવામાં આવતું નથી.

સર્કિટ સ્ટેટ્સ `closed`, `open`, અને `half_open` છે. કૂલડાઉન એ બાઉન્ડેડ પ્રોબને સુનિશ્ચિત કરે છે; સફળ ચકાસણી સર્કિટ બંધ કરે છે અને નિષ્ફળ ચકાસણી તેને ફરીથી ખોલે છે.
