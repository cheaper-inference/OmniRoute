OmniRoute એવા પ્રદાતાઓ સાથે એકીકૃત થાય છે, જેમની એજ સેવાઓ બિન-સત્તાવાર ક્લાયન્ટ્સની સક્રિય રીતે ફિંગરપ્રિન્ટિંગ કરે છે (TLS JA3/JA4, હેડરનો ક્રમ, JSON બૉડીનું સ્વરૂપ, ઇન્ટેગ્રિટી ટોકન્સ). આ પૃષ્ઠ OmniRoute દ્વારા ઉપલબ્ધ કરાવવામાં આવતી સ્ટેલ્થ સપાટીઓ અને તેમના અમલીકરણનાં સ્થાનોનું દસ્તાવેજીકરણ કરે છે.

## કાનૂની અને નૈતિક સૂચના

સ્ટેલ્થ સુવિધાઓ એટલા માટે અસ્તિત્વમાં છે કે OmniRoute વપરાશકર્તાની માલિકીનાં સત્તાવાર એકાઉન્ટ્સ (Claude Code CLI, Codex, Antigravity, Cursor, વગેરે) અને OmniRouteના એકીકૃત API વચ્ચે સુસંગતતા સ્તર તરીકે કાર્ય કરી શકે. તે છેતરપિંડી શોધ ટાળવા, ઓળખપત્રો શેર કરવા અથવા પ્રદાતાની સેવાની શરતોનું ઉલ્લંઘન કરવા માટે **નથી**. જાળવણીકર્તાઓ અપેક્ષા રાખે છે કે ઓપરેટરો એકાઉન્ટ્સ બનાવતી વખતે સ્વીકારેલી અપસ્ટ્રીમ ToSનું પાલન કરે.

## TLS ફિંગરપ્રિન્ટિંગ સ્તર

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

દરેક એકાઉન્ટ સ્કોપ અને ઉકેલાયેલા પ્રોક્સી માટે સ્થાયી `wreq-js` સત્રો જરૂર પડ્યે બનાવવામાં આવે છે.
પ્રક્રિયા-વ્યાપી `TlsClient` Cloudflare પાછળના અપસ્ટ્રીમ માટે **macOS પર Chrome 124** તરીકે
અનુકરણ કરતાં વધુમાં વધુ 128 સત્રો પૂલ કરે છે. નેટિવ રનટાઇમ ઉપલબ્ધ ન હોય ત્યારે
`TlsClient.fetch()` સુરક્ષિત રીતે નિષ્ફળ થાય છે; કૉલર આ રૅપરની બહાર સ્પષ્ટપણે ફૉલબૅક પસંદ કરી શકે છે.

- સત્ર પ્રોફાઇલ: `browser: "chrome_124", os: "macos"`
- પ્રોક્સી રિઝોલ્યુશન (પ્રાથમિકતા): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (લોઅર-કેસ પણ)
- સમયસમાપ્તિ: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS`માંથી વારસામાં મળે છે, ડિફૉલ્ટ 600000)
- `wreq-js` Response fetch-સુસંગત છે (`headers`, `text()`, `json()`, `clone()`, `body`).
- પ્રથમ-બાઇટ વૉચડૉગ (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): અપસ્ટ્રીમ હેડર્સ આવતાં જ `TlsClient.fetch()`
  રિઝોલ્વ થાય છે, તેથી એકલું `TLS_CLIENT_TIMEOUT_MS` ક્યારેય પ્રથમ બાઇટ ન આપતી
  બૉડીને મર્યાદિત કરી શકતું નથી. `guardTlsFirstByte()` બૉડીના પ્રથમ `read()`ને
  `TLS_FIRST_BYTE_WATCHDOG_MS` (ડિફૉલ્ટ `10000`, `0` તેને અક્ષમ કરે છે) સામે રેસ કરાવે છે; સ્વસ્થ બૉડી
  અપ્રભાવિત રહે છે, જ્યારે અટકેલી બૉડી wreq રીડરને રદ કરે છે અને `proxyFetch`ના હાલના
  TLS-ફૉલબૅક લૉજિકને ડાયરેક્ટ/પ્રોક્સી ડિસ્પૅચર સુધી આગળ વધવા દે છે (રીપ્લે માટે અસુરક્ષિત વિનંતી, દા.ત.
  બૉડી ધરાવતી POST, મૌન રીતે ફરી પ્રયાસ થવાને બદલે હજુ પણ ભૂલ ફેંકે છે).

### વેબ-કૂકી પ્રોવાઇડર ટ્રાન્સપોર્ટ — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` નીચેના પાંચ વિશિષ્ટ
વેબ-કૂકી ટ્રાન્સપોર્ટ માટેનો સહિયારો ઍડૅપ્ટર છે. દરેક પાતળું પ્રોવાઇડર રૅપર બ્રાઉઝર/OS પ્રોફાઇલ પસંદ કરે છે. ઍડૅપ્ટર
`open-sse/utils/tlsClient.ts`માં રહેલા એકમાત્ર wreq રનટાઇમ લોડર અને ટ્રાન્સપોર્ટ પૂલનો ઉપયોગ કરે છે, જે
પ્રોફાઇલ + OS + ઉકેલાયેલા પ્રોક્સી દ્વારા કી કરાયેલ છે, જ્યારે દરેક વિનંતી `cookieMode: "ephemeral"`નો ઉપયોગ કરે છે. તેથી એકાઉન્ટ્સ અને
વિનંતીઓ ટ્રાન્સપોર્ટ-સ્તરના કનેક્શન્સ વહેંચે છે, પરંતુ ક્યારેય wreq સત્ર અથવા કૂકી જાર વહેંચતા નથી.

| પ્રોવાઇડર  | પ્રોફાઇલ      | અનુકરિત OS | સ્ટ્રીમ EOF નીતિ                        |
| ---------- | ------------- | ---------- | --------------------------------------- |
| Claude     | `chrome_146`  | Linux      | `[DONE]` સામેલ કરો                      |
| Perplexity | `firefox_151` | macOS      | `event: end_of_stream` સામેલ કરો        |
| Grok       | `chrome_146`  | Linux      | `[DONE]` બાકાત રાખો                     |
| Notion     | `chrome_146`  | Windows    | `[DONE]` સામેલ કરો                      |
| LMArena    | `chrome_146`  | Windows    | કોઈ સેન્ટિનલ નહીં; નેટિવ EOF પર બંધ કરો |

- સ્ટ્રીમિંગ નેટિવ રિસ્પૉન્સ `ReadableStream`નો સીધો ઉપયોગ કરે છે; કોઈ અસ્થાયી ફાઇલ અથવા સાઇડકાર
  બનાવવામાં આવતું નથી.
- સ્ટ્રીમ ઉપલબ્ધ કરાવતા પહેલાં પ્રારંભિક 256 બાઇટ સુધીનું નિરીક્ષણ કરવામાં આવે છે. SSE પ્રોવાઇડર્સ બિન-SSE
  ભૂલો બફર કરે છે; Grok/LMArena Cloudflare પડકારોને `403` અને HTML ઇન્ટરસ્ટિશિયલ્સને `502`માં મૅપ કરે છે.
- નેટિવ વિનંતીની સમયસમાપ્તિ સંપૂર્ણ JS હાર્ડ ડેડલાઇન દ્વારા રૅપ થયેલી રહે છે. હૅંગ થવાથી
  માત્ર અસરગ્રસ્ત પ્રોફાઇલ/OS/પ્રોક્સી ટ્રાન્સપોર્ટ અમાન્ય અને બંધ થાય છે, ત્યારબાદ આગલી વિનંતી તેને ફરી બનાવે છે.
- પ્રોક્સી રિઝોલ્યુશનની પ્રાથમિકતા દરેક કૉલનું `proxyUrl` → વિનંતી-સ્કોપવાળો એકાઉન્ટ/ડૅશબોર્ડ સંદર્ભ →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (લોઅરકેસ વેરિઅન્ટ્સ સહિત) છે. રિઝોલ્યુશન ભૂલો
  ડાયરેક્ટ કનેક્શન લીક કરવાને બદલે સુરક્ષિત રીતે નિષ્ફળ થાય છે. LMArena ઇરાદાપૂર્વક `arena.ai` સામે રિઝોલ્વ કરે છે.
- `byteResponse` UTF-8 બગાડ વિના કન્ટેન્ટ-ટાઇપવાળું `data:` URL પરત કરે છે.
- ભૂલો `TlsClientUnavailableError` (પૅકેજ/ઍડઑન અનુપલબ્ધ), `TlsClientHangError`
  (ડેડલાઇન વટાવી), અને `WreqTransportCapacityError` (સહિયારો સત્ર-ક્ષમતા ભૂલ કોડ)
  છે, જ્યારે તમામ 128 મર્યાદિત પ્રોફાઇલ/OS/પ્રોક્સી સ્લોટ સક્રિય હોય અથવા બંધ થઈ રહ્યા હોય.

ઉપરોક્ત સામાન્ય `TlsClient` સત્ર સ્થાયી બ્રાઉઝર-સમર્થિત કૂકી
સ્થિતિ માટે વિશિષ્ટ રહે છે. બંને પાથ એક કૅશ કરેલા wreq મોડ્યુલ લોડર અને પ્રક્રિયા લાઇફસાઇકલ હૂકનો ફરી ઉપયોગ કરે છે; તેમના પૂલ
અલગ રહે છે કારણ કે તેમની કૂકી લાઇફટાઇમ્સ ઇરાદાપૂર્વક અલગ છે.

પિન કરેલું પૅકેજ આ પ્રોફાઇલ્સને સમર્થન આપે છે, પરંતુ વાસ્તવિક WAF સ્વીકાર્યતા સ્થાનિક
કરાર પરીક્ષણોથી સ્વતંત્ર રીતે બદલાઈ શકે છે. અપસ્ટ્રીમ બ્રાઉઝર સાથે સમાનતાનો દાવો કરતાં પહેલાં
સ્પષ્ટપણે અધિકૃત કરાયેલા લાઇવ એકાઉન્ટ સામે ફિંગરપ્રિન્ટ ફેરફારોને માન્ય કરો.

## Claude Code સ્ટેલ્થ બંડલ

જ્યારે `cliCompatMode` ચાલુ હોય છે, ત્યારે OmniRoute બહાર જતી Claude વિનંતીઓને એવી રીતે પુનઃઆકાર આપે છે કે તેઓ `claude-cli` ટ્રાફિકથી અલગ ઓળખી ન શકાય. ત્રણ મોડ્યુલો સાથે મળીને કાર્ય કરે છે:

### `claudeCodeFingerprint.ts`

બિલિંગ હેડરમાં સમાવિષ્ટ 3-અક્ષરનું `cc_version` ફિંગરપ્રિન્ટ ગણે છે:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (હાર્ડકોડ કરેલું; સત્તાવાર ક્લાયન્ટ સાથે મેળ ખાય છે)
- ઇનપુટ્સ: પ્રથમ વપરાશકર્તા સંદેશના ટેક્સ્ટમાં ઇન્ડેક્સ 4, 7, 20 પરનાં અક્ષરો + વર્ઝન સ્ટ્રિંગ
- આઉટપુટ: 3-અક્ષરનો હેક્સ પ્રિફિક્સ

### `claudeCodeCCH.ts` (ક્લાયન્ટ કન્ટેન્ટ હેશ)

સત્તાવાર Claude Code CLI દ્વારા Bun/Zig મારફતે કરવામાં આવતી સર્વર-સાઇડ અખંડિતતા ચકાસણી. OmniRoute તેને `xxhash-wasm` વડે ફરી અમલમાં મૂકે છે:

1. બોડીને `cch=00000;` પ્લેસહોલ્ડર સાથે સિરિયલાઇઝ કરો
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. શૂન્ય વડે પેડ કરેલું 5-અક્ષરનું લોઅરકેસ હેક્સ
4. `cch=00000;` ને ગણતરી કરેલા ટોકનથી બદલો

અચળાંકો:

- સીડ: `0x6e52736ac806831e`
- પેટર્ન: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

"સંવેદનશીલ" ક્લાયન્ટ નામોના પ્રથમ અક્ષર પછી Unicode **ઝીરો-વિડ્થ જોઇનર** (`U+200D`) દાખલ કરે છે, જેથી અપસ્ટ્રીમ ફિલ્ટરો તેમને grep ન કરી શકે. ડિફૉલ્ટ શબ્દસૂચિ:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

આના પર લાગુ પડે છે: `system` બ્લોક્સ, તમામ `messages[].content`, અને `tools[].description` / `tools[].function.description`. ઑપરેટર દ્વારા `setSensitiveWords()` મારફતે ઓવરરાઇડ કરી શકાય છે.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` પ્રોવાઇડર્સ

ફક્ત "વાસ્તવિક Claude Code" ટ્રાફિક સ્વીકારતા તૃતીય-પક્ષીય Anthropic રિલે માટે:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- ડિફૉલ્ટ રૂપે `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- જ્યારે કોઈ CC Compatible અપસ્ટ્રીમને ખાસ કરીને રિડેક્ટ કરેલા થિંકિંગ સ્ટ્રીમ્સની જરૂર હોય, ત્યારે પ્રતિ-કનેક્શન "Enable redact-thinking beta" ટૉગલ `redact-thinking-2026-02-12` ઉમેરે છે
- પ્રતિ-કનેક્શન "Enable summarized thinking display" ટૉગલ `providerSpecificData.requestDefaults.summarizeThinking` સંગ્રહે છે અને જે CC Compatible થિંકિંગ વિનંતીઓએ પહેલેથી ડિસ્પ્લે મોડ સેટ ન કર્યો હોય તેમાં `display: "summarized"` ઉમેરે છે
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x ફેમિલી)
- ડિફૉલ્ટ પાથ: `/v1/messages?beta=true`

એ જ બંડલમાંનાં સંબંધિત મોડ્યુલો:

- `claudeCodeConstraints.ts` — ટેમ્પરેચર + કૅશ-કંટ્રોલ નિયમો
- `claudeCodeToolRemapper.ts` — ટૂલ-નામ રીમૅપિંગ
- `claudeCodeExtraRemap.ts` — વધારાનું પેલોડ નોર્મલાઇઝેશન

## Antigravity સ્ટીલ્થ

Antigravity વિનંતીઓ કોલર ટેક્સ્ટ બાઇટ-ફોર-બાઇટ સાચવે છે. OmniRoute IDE ક્લાયંટનું અનુકરણ કરવા માટે પ્રોમ્પ્ટ અથવા rename/inject ટૂલ્સમાં શૂન્ય-પહોળાઈના અક્ષરો દાખલ કરતું નથી.

### `antigravityHeaderScrub.ts`

ફોરવર્ડ કરતા પહેલા સ્ટેનલેસ SDK માર્કર્સ (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) સ્ટ્રીપ્સ કરો.

### ⚠️ જોખમ: `ANTIGRAVITY_CREDITS=always` (એકાઉન્ટ-બેન હોટ સ્પોટ)

`ANTIGRAVITY_CREDITS=always` ( `open-sse/executors/antigravity.ts` દ્વારા વપરાશ) માર્ગો** દરેક** Google ના ફ્રી-ટાયર ક્વોટા ગેટ વસ્તુઓ આપવાને બદલે Antigravity AI ક્રેડિટ ઓવરેજ (ચૂકવેલ Google ક્રેડિટ) દ્વારા વિનંતી કરો. આ એક લક્ષણ તરીકે દસ્તાવેજીકૃત થયેલ છે, પરંતુ તે છે** એક સૌથી સામાન્ય ToS-ઉલ્લંઘન રિપોર્ટ આપણે જોઈએ છીએ** — બહુવિધ Google અલ્ટ્રા એકાઉન્ટ્સ `=always` સાથે થોડા કલાકો સુધી ચાલ્યા પછી `403 / "service disabled for ToS violation" / insufficient_quota` સાથે પ્રતિબંધિત કરવામાં આવ્યા છે.

અપસ્ટ્રીમ અમલ ચાલુ છે**Google ની બાજુ** , કંઈપણ OmniRoute રોકી શકતું નથી. env var નામ અને હાલના દસ્તાવેજો તેને ફ્લિપ કરવા માટે સલામત નોબ જેવો અવાજ આપે છે; તે નથી.

**આ શા માટે દુરુપયોગ શોધને ફ્રી-ટાયર-ઓન્લી વપરાશ કરતાં વધુ આક્રમક રીતે દોરે છે:**

- એક જ Google એકાઉન્ટ પર સતત સ્વચાલિત ખર્ચ ફ્રી-ટાયર હિટ્સ-ક્વોટા-અને-સ્ટોપ્સ કરતાં અલગ રીતે ફ્લેગ કરે છે.
- ક્રેડિટ ઓવરએજની કોઈ દરની ટોચમર્યાદા હોતી નથી, તેથી ખોટી રીતે ગોઠવેલ ક્લાયંટ મિનિટોમાં કેટલાક સો USD દ્વારા બર્ન કરી શકે છે અને API-કી રિસેલ અથવા બોટ ટ્રાફિક જેવો દેખાય છે.
- બહુવિધ OmniRoute વપરાશકર્તાઓ સમાન બાહ્ય IP માંથી સમાંતર ઓવરએજ ક્રેડિટને ફટકારતા સિગ્નલને સંયોજન કરે છે.

**ભલામણ કરેલ મુદ્રા:**

1. ડિફૉલ્ટ `ANTIGRAVITY_CREDITS=off` રાખો જ્યાં સુધી ઑપરેટર સ્પષ્ટપણે પેઇડ-ક્રેડિટ અને એકાઉન્ટ-એન્ફોર્સમેન્ટ જોખમ સ્વીકારે નહીં. `retry` પહેલા સામાન્ય વિનંતિ મોકલે છે અને પાત્ર ક્વોટા 429 પછી વધુમાં વધુ એક જ વાર ક્રેડિટ દાખલ કરે છે; `always` પ્રથમ વિનંતી પર ક્રેડિટ દાખલ કરે છે.
2. **ઓટો-કોમ્બો દ્વારા પ્રદાતાઓમાં લોડ ફેલાવો** એક Antigravity એકાઉન્ટને સંતૃપ્ત કરવાને બદલે (`model: "auto"` અથવા `kr/glm/etc` -combo)
3. **પ્રતિ-કનેક્શન RPM મર્યાદા સેટ કરો** Antigravity પ્રદાતાના સંપાદન પૃષ્ઠમાં (ડેશબોર્ડ → પ્રદાતાઓ → Antigravity → કનેક્શન → દર મર્યાદા). 30–60 RPM એ સતત ઉપયોગ માટે સંરક્ષણક્ષમ ઉપલા બાઉન્ડ છે.
4. **સ્થિર, ઓપરેટર-નિયંત્રિત અપસ્ટ્રીમ નેટવર્કિંગનો ઉપયોગ કરો** અને બિનસંબંધિત વપરાશકર્તાઓ અથવા વર્કલોડ પર એક એકાઉન્ટ શેર કરવાનું ટાળો.
5. **જો પ્રતિબંધિત છે** : `support.google.com` → દ્વારા અપીલ " Workspace/Account ઍક્સેસ પુનઃસ્થાપિત કરો" ચોક્કસ `quota_exceeded` / `service disabled` પ્રતિસાદ બોડી Google મોકલવામાં આવે છે. પુનઃસંગ્રહની ખાતરી નથી.

પર્યાવરણ સંદર્ભ દરેક ક્રેડિટ મોડના એકાઉન્ટ અને ખર્ચની અસરોને દસ્તાવેજ કરે છે.

#### સામાન્ય રીતે માત્ર `=always` જ નહીં : Antigravity OAuth રૂટીંગ

સસ્પેન્શન ક્રેડિટ ઓવરેજ સુધી મર્યાદિત નથી. નવેમ્બર 2026 (#19223, #19266) ના અહેવાલો `antigravity` અને `agy` (Antigravity CLI) પ્રદાતાઓ દ્વારા રૂટ કરતી વખતે સસ્પેન્ડ કરાયેલા કેટલાંક Google એકાઉન્ટ્સનું વર્ણન કરે છે, આ સાથે:

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

બંને પ્રદાતાઓ Antigravity ઉત્પાદન OAuth સત્ર સાથે પ્રમાણિત કરે છે, જે કિસ્સામાં ડેશબોર્ડની જોખમ સૂચના ("આ પ્રદાતા તમારા સત્તાવાર ઉત્પાદન session/OAuth નો ઉપયોગ કરે છે, જે proxy/router ઉપયોગ માટે અધિકૃત નથી") કનેક્શન ઉમેરતા પહેલા ચેતવણી આપે છે. ઉપરોક્ત ભલામણોમાંથી કોઈપણ તે ઉપયોગને અધિકૃત બનાવતી નથી; તેઓ માત્ર એક ખાતામાં કેટલો ટ્રાફિક વહન કરે છે તે ઘટાડે છે.

**Gemini મોડલ્સ માટે અધિકૃત API ઇન્ટરફેસ.** Google તેના APIs દ્વારા Gemini ને પ્રોગ્રામેટિક એક્સેસ ઓફર કરે છે, જેને OmniRoute સામાન્ય API-કી પ્રદાતાઓ તરીકે સપોર્ટ કરે છે:

| પ્રદાતા આઈડી | ડેશબોર્ડ નામ                | ઓળખપત્ર                                                                    |
| ------------ | --------------------------- | -------------------------------------------------------------------------- |
| `gemini`     | Gemini (Google AI સ્ટુડિયો) | Google AI સ્ટુડિયોમાંથીGemini API કી (મફત ટાયર ઉપલબ્ધ છે)                  |
| `vertex`     | શિરોબિંદુ AI                | સર્વિસ એકાઉન્ટ JSON, OAuth એક્સેસ ટોકન અથવા Vertex Express API કી (Gemini) |

આ પ્રદાતાઓ API એક્સેસ માટે ઓળખપત્ર Google મુદ્દાઓનો ઉપયોગ કરે છે, Antigravity ઉત્પાદન સત્રથી વિપરીત. તેઓ દરેક ઉપયોગને સુસંગત બનાવતા નથી અથવા અમલીકરણના જોખમને દૂર કરતા નથી: દરેક તેની પોતાની શરતો દ્વારા સંચાલિત થાય છે, જે ઓપરેટરે તેમની જમાવટ માટે તપાસવાની હોય છે. ઉદાહરણ તરીકે, [Gemini API વધારાની સેવાની શરતો](https://ai.google.dev/gemini-api/terms) જ્યારે API ક્લાયન્ટ્સ યુરોપિયન ઇકોનોમિક એરિયા, સ્વિટ્ઝર્લૅન્ડ અથવા યુનાઇટેડ કિંગડમમાં વપરાશકર્તાઓને ઉપલબ્ધ કરાવવામાં આવે ત્યારે જ ચૂકવેલ સેવાઓને મંજૂરી આપે છે અને અવેતન સેવાઓને મોકલવામાં આવેલી સામગ્રીનો ઉપયોગ Google ના ઉત્પાદનોને સુધારવા માટે થઈ શકે છે. Vertex AI તેના બદલે Google ક્લાઉડ શરતો હેઠળ આવે છે ( [સેવા વિશિષ્ટ શરતો](https://cloud.google.com/terms/service-terms) ). કિંમત નિર્ધારણ અને ક્વોટા Antigravity સબ્સ્ક્રિપ્શનને બદલે તે API શરતોને અનુસરે છે.

ઉપર વર્ણવેલ Antigravity સસ્પેન્શનને ટાળવા માંગતા ઓપરેટરોએ `antigravity` / `agy` ને બદલે Gemini ટ્રાફિકને આમાંથી કોઈ એક પ્રદાતા દ્વારા રૂટ કરવો જોઈએ, તે તપાસ્યા પછી કે તેમનો ઉપયોગ પ્રદાતાની શરતોને અનુરૂપ છે.

ટચ પોઈન્ટ:

- `open-sse/executors/antigravity.ts` — `process.env.ANTIGRAVITY_CREDITS` વાંચે છે
- `src/lib/oauth/providers/antigravity.ts` — ઓળખપત્ર પ્લમ્બિંગ
- મૂળ ઘટના અહેવાલ: ચર્ચા [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## CLI ફિંગરપ્રિન્ટ રજિસ્ટ્રી — `open-sse/config/cliFingerprints.ts`

દરેક પ્રદાતા માટેનું કોષ્ટક, જે અધિકૃત CLIના mitmproxy ટ્રેસમાંથી કૅપ્ચર કરેલા હેડરનો **ચોક્કસ** ક્રમ અને JSON બૉડી ફીલ્ડનો ક્રમ નિશ્ચિત કરે છે. હાલમાં નોંધાયેલા: `codex`, `claude`, ઉપરાંત `antigravity` અને `github` માટે `providerHeaderProfiles.ts`માં રનટાઇમથી મેળવેલી પ્રોફાઇલ્સ.

```ts
interface CliFingerprint {
  headerOrder: string[]; // અક્ષરકેસ પ્રત્યે સંવેદનશીલ
  bodyFieldOrder: string[]; // ટોચના સ્તરની JSON કીઝ
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

દરેક પ્રદાતા માટે env દ્વારા ટૉગલ કરો (નીચે જુઓ). અક્ષમ હોય ત્યારે, હેડર્સ/બૉડી કીઝ Node/JSON દ્વારા આપવામાં આવેલા કોઈપણ ક્રમમાં દેખાય છે — જેની ફિંગરપ્રિન્ટ લેવી સરળ છે.

## MITM પ્રૉક્સી (Antigravity, Linux/macOS/Windows)

જે CLIની બાઇનરીઝને `OPENAI_BASE_URL` દ્વારા રીડાયરેક્ટ કરી શકાતી નથી, તેમના માટે OmniRoute સ્થાનિક TLS-ટર્મિનેટિંગ પ્રૉક્સી ચલાવે છે. એન્ડપોઇન્ટ્સ `src/app/api/cli-tools/antigravity-mitm/` હેઠળ સ્થિત છે.

| પદ્ધતિ | એન્ડપોઇન્ટ                              | હેતુ                                                    |
| ------ | --------------------------------------- | ------------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | સ્થિતિ — ચાલી રહ્યું છે, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM શરૂ કરો (`apiKey` + `sudoPassword` જરૂરી)          |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM બંધ કરો                                            |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | મોડલ ઉપનામોની સૂચિ                                      |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | ટૂલ માટે મોડલ ઉપનામો સાચવો                              |

ઇન્ટરસેપ્ટ થતું લક્ષ્ય હોસ્ટ: **`daily-cloudcode-pa.googleapis.com`** (Antigravityનું અપસ્ટ્રીમ).

### પ્રારંભ ક્રમ (`src/mitm/manager.ts::startMitm`)

1. `selfsigned` દ્વારા સ્વ-હસ્તાક્ષરિત પ્રમાણપત્ર બનાવો (RSA-2048, SHA-256, 1y) — `cert/generate.ts`
2. સિસ્ટમ ટ્રસ્ટ સ્ટોરમાં પ્રમાણપત્ર ઇન્સ્ટોલ કરો — `cert/install.ts`
3. hosts એન્ટ્રી `127.0.0.1 daily-cloudcode-pa.googleapis.com` ઉમેરો — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (ડિફૉલ્ટ `443`) સાથે `src/mitm/server.cjs` સ્પૉન કરો
5. PIDને `<DATA_DIR>/mitm/.mitm.pid`માં કાયમી રીતે સાચવો

### Linux ડાયનેમિક ટ્રસ્ટ-સ્ટોર શોધ — `cert/install.ts`

`getLinuxCertConfig()` પ્રાથમિકતા સૂચિમાં તપાસ કરે છે અને અસ્તિત્વમાં રહેલી પ્રથમ ડિરેક્ટરી પસંદ કરે છે:

| ડિસ્ટ્રો પરિવાર          | ડિરેક્ટરી                                   | અપડેટ કમાન્ડ             |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

પ્રમાણપત્ર ફાઇલનામ: `omniroute-mitm.crt`. `getCertFingerprint()` દ્વારા ફિંગરપ્રિન્ટ મેચ (DERનું SHA-1).

વધુમાં, `certutil` ઉપલબ્ધ હોય ત્યારે `updateNssDatabases()` દરેક વપરાશકર્તાના NSS DBમાં ઇન્સ્ટોલ કરે છે: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, તમામ Firefox પ્રોફાઇલ્સ (snap સહિત), **`OmniRoute MITM Root CA`** ઉપનામ હેઠળ.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** એલિવેટેડ PowerShell → `certutil -addstore Root`

### પ્રમાણીકરણ

તમામ MITM એન્ડપોઇન્ટ્સ માટે મેનેજમેન્ટ પ્રમાણીકરણ (`requireCliToolsAuth`) જરૂરી છે. sudo પાસવર્ડ મોડ્યુલ સ્કોપમાં કૅશ થાય છે (ક્યારેય `globalThis`માં નહીં) અને `stopMitm()` વખતે સાફ થાય છે.

## પ્રદાતા રોટેટ કરે ત્યારે ફિંગરપ્રિન્ટ્સ અપડેટ કરવા

1. `mitmproxy` વડે અધિકૃત CLI ટ્રાફિક કૅપ્ચર કરો (TLS ઇન્ટરસેપ્શન + ડમ્પ)
2. JA3/JA4 અને હેડર્સનો શાબ્દિક ક્રમ એક્સટ્રેક્ટ કરો
3. સંબંધિત `CLI_FINGERPRINTS[...]` એન્ટ્રી અપડેટ કરો
4. `.env.example`માં મેળ ખાતું `*_USER_AGENT` ડિફૉલ્ટ અપડેટ કરો
5. જો TLS હેન્ડશેક પોતે બદલાયો હોય, તો સંબંધિત પ્રદાતા રૅપર અથવા wreq-js `browser:` વિકલ્પ અપડેટ કરો
6. પ્રદાતા-વિશિષ્ટ TLS ટેસ્ટ્સ અને લાઇવ પ્રદાતા સામે મેન્યુઅલ કેનેરી ચલાવો
7. પૅચ રિલીઝમાં શિપ કરો; `CHANGELOG.md`માં દસ્તાવેજીકરણ કરો
