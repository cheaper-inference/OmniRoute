OmniRoute npm + Docker આર્ટિફેક્ટ્સ પ્રકાશિત કરે છે. આ ગેટ્સ પ્રોવેનન્સ, ઇન્વેન્ટરી (SBOM) અને CVE સ્કેનિંગ પ્રદાન કરે છે, જે બધા OSS છે અને રિલીઝ વર્કફ્લોમાં પ્લગ થયેલા છે. **સલાહ-પ્રથમ** અભિગમ — તેઓ અત્યારે રિપોર્ટ કરે છે, અને પ્રથમ સફળ રિલીઝ પછી બ્લોકિંગમાં પ્રમોટ કરે છે.

| ગેટ                   | ટૂલ                                            | ક્યાં                         | બ્લોક કરે છે?              | આઉટપુટ                                          |
| --------------------- | ---------------------------------------------- | ----------------------------- | -------------------------- | ----------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | ફક્ત જો પ્રકાશન નિષ્ફળ જાય | બેજ npmjs / `npm audit signatures`              |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | ફક્ત જો જનરેશન નિષ્ફળ જાય  | રિલીઝ એસેટ + આર્ટિફેક્ટ                         |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | સલાહકારી                   | CycloneDX આર્ટિફેક્ટ                            |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | સલાહકારી                   | SARIF (HIGH+CRITICAL) → સિક્યોરિટી ટેબ          |
| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **બ્લોકિંગ**               | સુધારી શકાય તેવા CRITICAL પર `exit-code: '1'`   |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **બ્લોકિંગ**               | `metrics.vulnCount` ને રૅચેટ કરે છે (દિશા:નીચે) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | સલાહકારી                   | SARIF → સિક્યોરિટી + બેજ                        |

ઇમેજ CVE રૅચેટ `docker-publish.yml` માં **બે પગલાં** નો ઉપયોગ કરે છે: SARIF પગલું (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL ને બ્લોક કર્યા વિના સિક્યોરિટી ટેબમાં દૃશ્યમાન રાખે છે; _CRITICAL ગેટ_ પગલું (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) ઉપલબ્ધ સુધારા સાથેના CRITICAL CVE પર રિલીઝને નિષ્ફળ બનાવે છે. `ignore-unfixed` અપસ્ટ્રીમ પેચ વિના બેઝ-ઇમેજ CVE માટે રિલીઝને બ્લોક થતી અટકાવે છે.

## ⚠️ CVE ભિન્નતા (અવરોધક osv/Trivy ગેટ્સ)

osv અને Trivy નિર્ભરતાઓની સરખામણી એવા CVE ડેટાબેઝ સાથે કરે છે જે **સતત વધતા રહે છે**. કોઈ PR
જે **કોઈ નિર્ભરતાને સ્પર્શતો નથી** તે પણ અચાનક નિષ્ફળ થઈ શકે છે, કારણ કે હાલની નિર્ભરતામાં
નવું CVE જાહેર થયું હોય (osv: માપેલ `vulnCount` > બેઝલાઇન; Trivy: ઇમેજમાં નવું
સુધારી શકાય તેવું CRITICAL). **આ અવરોધક CVE ગેટનું અપેક્ષિત કાર્યકારી વર્તન છે,
પ્રોડક્ટ રિગ્રેશન નહીં.**

નવા જાહેર થયેલા CVEને કારણે osv અથવા Trivy નિષ્ફળ થાય ત્યારે ઉપાય આ છે:

1. **અસરગ્રસ્ત નિર્ભરતાનું વર્ઝન વધારો** (પ્રાધાન્યપૂર્ણ) — `package.json`
   `overrides` (પરોક્ષ નિર્ભરતાઓ) મારફતે પેચ કરેલા વર્ઝન પર અપગ્રેડ કરો અથવા પેચ કરેલા બેઝ પર ઇમેજ ફરીથી બનાવો.
2. **જો કોઈ અપસ્ટ્રીમ સુધારો ઉપલબ્ધ ન હોય:**
   - **osv:** `config/quality/quality-baseline.json`માં `metrics.vulnCount` માટે ફરીથી બેઝલાઇન સેટ કરો
     (`npm run quality:ratchet -- --update` સમર્પિત ગેટ્સને આવરી લેતું નથી — વાજબી કારણની
     નોંધ + ટ્રેકિંગ ઇશ્યૂ સાથે મૂલ્ય હાથથી સંપાદિત કરો, `direction:down`).
   - **Trivy:** `.trivyignore`માં વાજબી કારણ દર્શાવતી
     ટિપ્પણી + ટ્રેકિંગ ઇશ્યૂ સાથે એક એન્ટ્રી ઉમેરો (દરેક લાઇનમાં એક CVE-ID). `ignore-unfixed: true` પહેલેથી જ
     પેચ વગરના CVEને આપમેળે આવરી લે છે.

જરૂરી OSV એક્ઝિક્યુશન (`check:vuln-ratchet -- --ratchet`) સ્કેનર, રિપોર્ટ અથવા બેઝલાઇનની
માન્યતા ચકાસી ન શકાય ત્યારે `INCOMPLETE` સાથે બંધ સ્થિતિમાં નિષ્ફળ થાય છે અને એક્ઝિટ કોડ 2 આપે છે.
માપવામાં આવેલ રિગ્રેશન એક્ઝિટ કોડ 1 આપે છે. સલાહકારી એક્ઝિક્યુશન હજી પણ `SKIP` દર્શાવીને
એક્ઝિટ કોડ 0 આપી શકે છે, પરંતુ તેનાથી નિર્ભરતાઓ સ્કેનમાં પાસ થઈ હતી એવું સ્થાપિત થતું નથી. અવરોધક
Trivy પગલામાં પણ સફળ માપન જરૂરી છે: અનુપલબ્ધ ટૂલ્સ, નિષ્ફળ જોબ્સ
અને ઇમેજના પુરાવાનો અભાવ કોઈ ઇમેજને સ્વચ્છ તરીકે પ્રમાણિત કરી શકતા નથી.

## નિવૃત્ત કરેલી નિર્ભરતાનું જોખમ

પિન કરેલા promptfoo ડેવલપમેન્ટ ટૂલને અપગ્રેડ કર્યા પછી રૂટ લૉકફાઇલમાં હવે `extract-zip` અથવા તેના તરફ દોરી જતી કોઈ નિર્ભરતા એજ સામેલ નથી. આથી #14482માં ટ્રૅક કરાયેલી અને અગાઉ સ્વીકારાયેલી `promptfoo` → `@openai/codex-security` → `extract-zip` શૃંખલા નિવૃત્ત થાય છે. `tests/unit/extract-zip-14482-exposure.test.ts`માંના રિગ્રેશન ચેક્સ તેને ફરીથી રજૂ કરવાના પ્રયાસને નકારે છે અને પ્રોડક્શન કોડમાંથી ઇમ્પોર્ટ પરનો પ્રતિબંધ જાળવી રાખે છે.

વર્તમાન નિર્ભરતા સુધારો સુસંગતતા ઓવરરાઇડ્સને Azure identityના MSAL ક્લાયન્ટ, get-uriના FTP ક્લાયન્ટ અને OpenCode v1 SDKની Zod નિર્ભરતા પૂરતા પણ મર્યાદિત કરે છે. Azure ટોકન પ્રાપ્તિ અને FTP રિટ્રીવલનું પરીક્ષણ નિયંત્રિત ટ્રાન્સપોર્ટ્સ સાથે કરવામાં આવે છે; બંને OpenCode પૅકેજ પોતાની બિલ્ડ અને ટેસ્ટ સ્યુટ ચલાવે છે. Registry એડવાઇઝરીની સંખ્યાઓ કોઈ ચોક્કસ સમયબિંદુએ લીધેલાં માપ છે અને લૉકફાઇલ કમિટ થયા પછી બદલાઈ શકે છે.
