## તે કેવી રીતે કાર્ય કરે છે

```
CLI Code's / CLI Agents (ઉપભોગ પ્રવાહ):
Claude / Codex / OpenCode / Cline / KiloCode / Continue / Hermes Agent / Goose / ...
           │
           ▼  (બધા OmniRoute તરફ નિર્દેશ કરે છે)
    http://YOUR_SERVER:20128/v1
           │
           ▼  (OmniRoute યોગ્ય પ્રદાતા તરફ રૂટ કરે છે)
    Anthropic / OpenAI / Gemini / DeepSeek / Groq / Mistral / ...

ACP Agents (વિપરીત સ્પૉન પ્રવાહ):
    ક્લાયન્ટ વિનંતી → OmniRoute → stdio/ACP મારફતે CLI શરૂ કરે છે → પ્રતિસાદ
```

**લાભો:**

- બધા ટૂલ્સનું સંચાલન કરવા માટે એક API કી
- ડેશબોર્ડમાં તમામ CLI માટે ખર્ચ ટ્રૅકિંગ
- દરેક ટૂલને ફરીથી કૉન્ફિગર કર્યા વિના મોડેલ બદલવું
- સ્થાનિક રીતે અને રિમોટ સર્વર્સ પર કાર્ય કરે છે (VPS, Docker, Akamai, Cloudflare Tunnel)

## `setup-*` સાથે સ્વતઃ રૂપરેખાંકિત કરો

તમારે દરેક ટૂલની રૂપરેખા હાથથી લખવાની જરૂર નથી. OmniRoute સપોર્ટેડ CLI દીઠ `setup-*` આદેશ મોકલે છે જે વાંચે છે** જીવંત** ચાલી રહેલ OmniRoute (સ્થાનિક અથવા દૂરસ્થ) માંથી મોડલ કેટલોગ અને તમારા મશીન પર ટૂલની પોતાની રૂપરેખા લખે છે:

```bash
omniroute setup-codex        omniroute setup-claude       omniroute setup-opencode
omniroute setup-cline        omniroute setup-kilo         omniroute setup-continue
omniroute setup-cursor       omniroute setup-roo          omniroute setup-crush
omniroute setup-goose        omniroute setup-qwen         omniroute setup-aider
omniroute setup-5dive        omniroute setup-zed
omniroute setup-whycodes
```

દરેક `--remote <url> --api-key <key>` (દૂરસ્થ OmniRoute સામે સ્થાનિક સાધનને ગોઠવો), `--dry-run` (લેખ્યા વિના પૂર્વાવલોકન), અને `--port` સ્વીકારે છે. મૉડલ ઑટો-ડિસ્કવરી વિનાના સાધનો (Cline, Kilo, Roo, Goose, Aider, Qwen, 5dive, WhyCodes) `--model <id>` (અને બિન-ઇન્ટરેક્ટિવ રન માટે `--yes` ) લે છે. `setup-5dive` એ એક રેસીપી છે જે `$HOME` હેઠળ લખતી નથી: તે ફ્લીટ હોસ્ટ પર રૂટ-માલિકીની ઓથ પ્રોફાઇલ લખીને 5dive એજન્ટ ફ્લીટને ગોઠવે છે, તેથી તે `sudo` દ્વારા ફરીથી અમલમાં આવે છે અને તેનો પોતાનો કોઈ રિમોટ મોડ નથી. જમણી એન્વ ઇન્જેક્ટેડ અને બિલકુલ લખેલી રૂપરેખા સાથે CLI લોન્ચ કરવા માટે, સામાન્ય `omniroute run <target>` લોન્ચરનો ઉપયોગ કરો (ક્લાઉડ, કોડેક્સ, એઇડર, હંસ, ઓપનકોડ, ક્વેન, જેમિની, વાયકોડ્સ — લક્ષ્યો અને ઉપનામો `bin/cli/cli-manifest.mjs` માંથી આવે છે); લેગસી પ્રતિ-ટૂલ લોન્ચર્સ `omniroute launch` (Claude કોડ) અને `omniroute launch-codex` (Codex) ઉપલબ્ધ રહે છે. Gemini CLI એ ફક્ત લોન્ચ કરવા માટે છે: તે એક `omniroute run` લક્ષ્ય છે પરંતુ તેની કોઈ `setup-*`/`configure` રેસીપી નથી.

> **સંપૂર્ણ સંદર્ભ:** મુખ્ય ટેબલ — દરેક આદેશ શું લખે છે, દરેક ધ્વજ, સ્થાનિક વિ રિમોટ, અને કયા ટૂલ્સને `/v1` પ્રત્યય જોઈએ છે — તેમાં રહે છે** [CLI એકીકરણ](../guides/CLI-INTEGRATIONS.md)** .

### આને કન્ટેનરની અંદર ચલાવવું

`setup-*` કમાન્ડ OmniRoute કન્ટેનરની અંદર ચલાવવામાં આવે છે તે કન્ટેનરના પોતાના ઘરમાં લખે છે, જેને કોઈ યજમાન CLI વાંચતું નથી અને જે કન્ટેનર સાથે અદૃશ્ય થઈ જાય છે. OmniRoute તે શોધે છે અને લખવાને બદલે સૂચનાઓ સાથે `2` માંથી બહાર નીકળી જાય છે. આગળ બે સપોર્ટેડ રીતો - હોસ્ટ પર CLI અને `omniroute connect` કન્ટેનર પર ઇન્સ્ટોલ કરો, અથવા config dirs ને બાંધી-માઉન્ટ કરો અને `CLI_CONFIG_HOME` (કમ્પોઝ `host` પ્રોફાઇલ) સેટ કરો. દરેક `setup-*` આદેશ, વત્તા `omniroute configure` અને `omniroute config set`, `--allow-container-write` સ્વીકારે છે જ્યારે કન્ટેનરની પોતાની CLIs રૂપરેખાંકિત કરતી વખતે તમે ખરેખર શું કહેવા માંગતા હતા; `OMNIROUTE_ALLOW_CONTAINER_CONFIG_WRITE=true` સર્વર માટે તે જ કરે છે. [Docker માર્ગદર્શિકા → હોસ્ટ CLI ટૂલ્સને ગોઠવવા](../guides/DOCKER_GUIDE.md#configuring-host-cli-tools-when-omniroute-runs-in-docker) જુઓ.

ડેશબોર્ડની** અંતિમ બિંદુ લાગુ કરો** (`POST /api/cli-tools/apply`) એ જ રક્ષકને લાગુ કરે છે: કન્ટેનરમાં, એક લખાણ કે જેનું લક્ષ્ય યજમાન જવાબોથી બાંધેલું નથી**`422`** `containerEphemeralTarget: true` સાથે , સલામત ભૂલ લખાણ અને — હોસ્ટ રેસીપી (ક્લાઉડ, કોડેક્સ, ઓપનકોડ, ક્લાઈન, કિલો, ચાલુ રાખો) સાથેના સાધનો માટે — તેના બદલે હોસ્ટ પર ચલાવવા માટે `hostSetupCommand` (દા.ત. `omniroute setup-opencode`); કશું લખ્યું નથી. `dryRun: true` કન્ટેનર મોડમાં કામ કરવાનું ચાલુ રાખે છે અને ડિસ્કને ટચ કર્યા વિના રીડેક્ટેડ પૂર્વાવલોકન + લક્ષ્ય પાથ પરત કરે છે. પૂર્વાવલોકન સામગ્રી નકલ અથવા આયાત કરવા માટે પ્રમાણપત્ર-બેરિંગ ગોઠવણી નથી. હોસ્ટ પર મૂળ tool/base URL/API key/model ઇનપુટ્સ સાથે અરજી કરો અથવા સૂચવેલ હોસ્ટ-સાઇડ સેટઅપ આદેશનો ઉપયોગ કરો. પૂર્વાવલોકન હેડર અને વિનંતી કરાર માટે [CLI રૂપરેખાંકન સુરક્ષા](../security/CLI-CONFIGURATION.md) જુઓ. આ વર્તણૂક ઇરાદાપૂર્વકની છે અને `tests/unit/api/cli-tools/apply-container-guard.test.ts` દ્વારા રીગ્રેસન-ગાર્ડ છે — ગાર્ડને દૂર કરીને 422ને ક્યારેય "ફિક્સ" કરશો નહીં.

## સત્યનો પ્રામાણિક સ્રોત

એકીકૃત કેટલોગ `src/shared/constants/cliTools.ts`માં `CLI_TOOLS: Record<string, CliCatalogEntry>` તરીકે સ્થિત છે.

દરેક એન્ટ્રીમાં આ ફીલ્ડ્સ હોય છે (`src/shared/schemas/cliCatalog.ts`માં વ્યાખ્યાયિત):

| ફીલ્ડ                                           | પ્રકાર                                                       | વર્ણન                                                   |
| ----------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------- |
| `category`                                      | `"code" \| "agent"`                                          | ટૂલ કયા પેજ પર દેખાય છે                                 |
| `vendor`                                        | `string`                                                     | ટૂલનું મૂળ ("Anthropic", "OSS (P. Gauthier)")           |
| `acpSpawnable`                                  | `boolean`                                                    | ACP Agent તરીકે પણ ઉપયોગ કરી શકાય છે (બેજ દર્શાવાય છે)  |
| `baseUrlSupport`                                | `"full" \| "partial" \| "none"`                              | કસ્ટમ એન્ડપોઇન્ટ સપોર્ટનું સ્તર. `"none"` = MITM બેકલૉગ |
| `configType`                                    | `"env" \| "custom" \| "guide" \| "custom-builder" \| "mitm"` | કન્ફિગરેશનની કાર્યપદ્ધતિ                                |
| `id`, `name`, `color`, `description`, `docsUrl` | માનક                                                         | મુખ્ય ડિસ્પ્લે ફીલ્ડ્સ                                  |

`baseUrlSupport: "none"` ધરાવતી એન્ટ્રીઓ ડેશબોર્ડ પેજોમાં **દર્શાવવામાં આવતી નથી** — તે પ્લાન 11 માટેના MITM બેકલૉગમાં નોંધાયેલ છે (`_tasks/features-v3.8.6/refactorpages/_orchestration/_plan11-mitm-backlog.md` જુઓ).

### ક્ષમતા સ્તરો (કેટલોગ કરેલું × શોધી શકાય તેવું × કન્ફિગર કરી શકાય તેવું × લોન્ચ કરી શકાય તેવું)

કેટલોગમાં સામેલ દરેક ટૂલ શોધી શકાય તેવું, કન્ફિગર કરી શકાય તેવું અથવા લોન્ચ કરી શકાય તેવું હોય જ એવું નથી. દરેક સ્તર માટે એક
ઘોષણાત્મક સ્રોત છે, અને ડ્રિફ્ટ ટેસ્ટ તેમને સુસંગત રાખે છે:

| સ્તર                       | અર્થ                                                                                    | આમાં ઘોષિત                                                      |
| -------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| **કેટલોગ કરેલું**          | ડેશબોર્ડ કેટલોગમાં દેખાય છે (નામ, વેન્ડર, દસ્તાવેજો, કન્ફિગ પ્રકાર)                     | `src/shared/constants/cliTools.ts` (`CLI_TOOLS`)                |
| **શોધી શકાય તેવું**        | બાઇનરી/કન્ફિગ શોધ, હેલ્થ ચેક્સ, કન્ફિગ પાથ્સ                                            | `src/shared/services/cliRuntime.ts` (`CLI_TOOLS` રનટાઇમ કેટલોગ) |
| **કન્ફિગર કરી શકાય તેવું** | `omniroute configure <cli>` દ્વારા સપોર્ટેડ છે (સેટઅપ રેસિપી ઉપલબ્ધ છે)                 | `bin/cli/cli-manifest.mjs` (`configure: true`)                  |
| **લોન્ચ કરી શકાય તેવું**   | `omniroute run <target>` દ્વારા સપોર્ટેડ છે (env/આર્ગ્યુમેન્ટ ઇન્જેક્શન વ્યાખ્યાયિત છે) | `bin/cli/cli-manifest.mjs` (`run: true`)                        |

`bin/cli/cli-manifest.mjs` એ CLI કમાન્ડ
સર્ફેસ માટેનું પ્રામાણિક એક્ઝિક્યુટેબલ મેનિફેસ્ટ છે: `run`, `configure` અને શેલ-કમ્પ્લીશન જનરેટર્સ બધા જ તેમની
ટાર્ગેટ યાદીઓ, એલિયાસ રિઝોલ્યુશન (ઉદાહરણ તરીકે `kilocode`/`kilo-code`/`kilo_cli` → `kilo`)
અને `--model` ફ્લેગ વાયરિંગ તેમાંથી મેળવે છે. ડ્રિફ્ટ ગાર્ડ
`tests/unit/cli/cli-manifest-drift.test.ts` ખાતરી કરે છે કે મેનિફેસ્ટ, રનટાઇમ
કેટલોગ, UI કેટલોગ અને દરેક કન્ઝ્યુમર સર્ફેસ સુસંગત રહે — અન્ય સર્ફેસમાં ઉમેર્યા વિના
કોઈ એક સર્ફેસમાં ઉમેરાયેલ ટાર્ગેટ શાંતિથી ડ્રિફ્ટ થવાને બદલે ટેસ્ટ સ્યુટને નિષ્ફળ બનાવે છે.

## 5. બૅચ ડિટેક્શન API

બધા ટૂલનું ડિટેક્શન એક જ એન્ડપોઇન્ટ મારફતે એકત્રિત કરવામાં આવે છે:

**`GET /api/cli-tools/all-statuses`**

- ઑથ: `requireCliToolsAuth(request)` (અન્ય `/api/cli-tools/` રૂટ્સ જેવું જ)
- પરત કરે છે: `Record<toolId, ToolBatchStatus>` (પ્રકાર: `src/shared/types/cliBatchStatus.ts`)
- વ્યૂહરચના: બધા ટૂલ્સ પર `Promise.all`, દરેક ટૂલ માટે 5s ટાઇમઆઉટ
- કૅશ: કન્ફિગ ફાઇલના `mtime` વડે ઇન્ડેક્સ કરાયેલ ઇન-મેમરી LRU. mtime બદલાય ત્યારે કૅશ અમાન્ય કરવામાં આવે છે. સર્વર પુનઃપ્રારંભ થાય ત્યારે રીસેટ થાય છે.

ટૂલ દીઠ રિસ્પોન્સનું સ્વરૂપ:

```ts
interface ToolBatchStatus {
  detection: {
    installed: boolean;
    runnable: boolean;
    version?: string;
    command?: string;
    commandPath?: string;
    reason?: string;
  };
  config: {
    status: "configured" | "not_configured" | "not_installed" | "unknown" | "other";
    endpoint?: string | null;
    lastConfiguredAt?: string | null;
  };
  error?: string; // સૅનિટાઇઝ કરેલું, કોઈ સ્ટૅક ટ્રેસ નહીં
}
```

#### VS Code Insiders (`chatLanguageModels.json`)

જ્યારે VS Code Insiders કસ્ટમ એન્ડપોઇન્ટ મોડેલ્સ માટે કૉન્ફિગર કરેલું હોય અને તમે કોઈ કસ્ટમ હેડર ફીલ્ડ વિના OmniRouteને કાર્યરત કરવા માંગતા હો ત્યારે આનો ઉપયોગ કરો.

**ભલામણ કરેલ સ્થાન:**

- Linux: `~/.config/Code - Insiders/User/chatLanguageModels.json`
- Windows: `%APPDATA%/Code - Insiders/User/chatLanguageModels.json`

**ટોકનાઇઝ્ડ OmniRoute ઉપનામનો ઉપયોગ કરતું ઉદાહરણ:**

```json
[
  {
    "vendor": "customendpoint",
    "id": "auto",
    "name": "OmniRoute Auto",
    "family": "gpt-4",
    "version": "1.0.0",
    "url": "http://localhost:20128/api/v1/vscode/sk-your-omniroute-key/chat/completions",
    "modelsUrl": "http://localhost:20128/api/v1/vscode/sk-your-omniroute-key/models",
    "requestFormat": "openai-chat-completions",
    "contextWindow": 256000,
    "maxOutputTokens": 32768,
    "auth": {
      "type": "none"
    }
  }
]
```

**નોંધો:**

- `sk-your-omniroute-key` ને OmniRouteમાં બનાવેલી API કી વડે બદલો.
- `url` ફીલ્ડ `/api/v1/vscode/{token}/chat/completions` તરફ નિર્દેશ કરવું જોઈએ.
- `modelsUrl` ફીલ્ડ `/api/v1/vscode/{token}/models` તરફ નિર્દેશ કરવું જોઈએ.
- જ્યારે ક્લાયન્ટ કસ્ટમ હેડર્સને સપોર્ટ કરતું હોય, ત્યારે સામાન્ય `/v1` + Bearer હેડર ફ્લોને પ્રાધાન્ય આપો.
- URLમાં એમ્બેડ કરેલા ટોકન્સ સુસંગતતા માટેનો વૈકલ્પિક ઉપાય છે અને તે એડિટર લૉગ્સ અથવા પ્રૉક્સી હિસ્ટ્રીમાં દેખાઈ શકે છે.

## 10. આંતરિક OmniRoute CLI

`omniroute` બાઇનરી સર્વર જીવનચક્ર, સેટઅપ, નિદાન અને પ્રદાતા વ્યવસ્થાપન માટેના આદેશો પ્રદાન કરે છે. પ્રવેશબિંદુ: `bin/omniroute.mjs`.

```bash
omniroute                              # સર્વર શરૂ કરો (ડિફૉલ્ટ પોર્ટ 20128)
omniroute setup                        # ઇન્ટરેક્ટિવ સેટઅપ વિઝાર્ડ
omniroute doctor                       # કૉન્ફિગ, DB, પોર્ટ્સ અને રનટાઇમ તપાસો
omniroute providers list               # કૉન્ફિગર કરેલ પ્રદાતા કનેક્શનો
omniroute providers test-all           # દરેક સક્રિય કનેક્શનનું પરીક્ષણ કરો
omniroute reset-password               # ઍડમિન પાસવર્ડ રીસેટ કરો
omniroute logs                         # રિક્વેસ્ટ લૉગ્સ સ્ટ્રીમ કરો
omniroute health                       # વિગતવાર હેલ્થ (બ્રેકર્સ, કૅશ, મેમરી)
omniroute --version                    # વર્ઝન પ્રિન્ટ કરો
omniroute --help                       # બધા આદેશો બતાવો
```

### સેટઅપ અને પ્રારંભીકરણ

```bash
omniroute setup                        # ઇન્ટરેક્ટિવ સેટઅપ વિઝાર્ડ
omniroute setup --non-interactive      # CI/ઑટોમેશન મોડ (env vars + ફ્લૅગ્સ વાંચે છે)
omniroute setup --password '<value>'   # ઍડમિન પાસવર્ડ સીધો સેટ કરો
omniroute setup --add-provider \
  --provider openai \
  --api-key '<value>' \
  --test-provider                      # એક જ વખતમાં પ્રદાતા ઉમેરો અને તેનું પરીક્ષણ કરો
```

નૉન-ઇન્ટરેક્ટિવ સેટઅપ માટે ઓળખાતા એન્વાયર્નમેન્ટ વેરિએબલ્સ:

| વેરિએબલ             | હેતુ                                                                 |
| ------------------- | -------------------------------------------------------------------- |
| `OMNIROUTE_API_KEY` | પ્રદાતા API કી (Commander `.env()` દ્વારા `--api-key` સાથે બંધાયેલી) |
| `DATA_DIR`          | OmniRoute ડેટા ડિરેક્ટરીને ઓવરરાઇડ કરો                               |

અન્ય તમામ નૉન-ઇન્ટરેક્ટિવ ઇનપુટ્સ એન્વાયર્નમેન્ટ વેરિએબલ્સ તરીકે નહીં, પરંતુ ફ્લૅગ્સ તરીકે પસાર કરવામાં આવે છે:
`--password`, `--provider`, `--provider-name`, `--provider-base-url`, `--default-model`
(ઉપરના `omniroute setup` વિકલ્પો જુઓ).

### નિદાન

```bash
omniroute doctor                       # કૉન્ફિગ, DB, પોર્ટ્સ, રનટાઇમ, મેમરી અને લાઇવનેસ તપાસો
omniroute doctor --json                # મશીન દ્વારા વાંચી શકાય તેવું JSON
omniroute doctor --no-liveness         # HTTP હેલ્થ પ્રોબ છોડો
omniroute doctor --host 0.0.0.0        # લાઇવનેસ હોસ્ટને ઓવરરાઇડ કરો
omniroute doctor --liveness-url <url>  # સંપૂર્ણ હેલ્થ એન્ડપૉઇન્ટ URL ઓવરરાઇડ
```

ડૉક્ટર આ તપાસો ચલાવે છે: `Config`, `Database`, `Storage/encryption`,
`Port availability`, `Node runtime`, `Native binary` (better-sqlite3),
`Memory`, અને `Server liveness`. જો કોઈપણ તપાસ `fail` હોય, તો તે નૉન-ઝીરો કોડ સાથે બહાર નીકળે છે.

### પ્રદાતા વ્યવસ્થાપન

```bash
omniroute providers available                       # OmniRoute પ્રદાતા કૅટલૉગ
omniroute providers available --search openai       # id/name/alias/category દ્વારા કૅટલૉગ ફિલ્ટર કરો
omniroute providers available --category api-key    # કૅટેગરી દ્વારા ફિલ્ટર કરો (api-key, oauth, free, ...)
omniroute providers available --json                # મશીન દ્વારા વાંચી શકાય તેવું JSON

omniroute providers list                            # કૉન્ફિગર કરેલ પ્રદાતા કનેક્શનો
omniroute providers list --json

omniroute providers test <id|name>                  # કૉન્ફિગર કરેલા એક કનેક્શનનું પરીક્ષણ કરો
omniroute providers test-all                        # દરેક સક્રિય કનેક્શનનું પરીક્ષણ કરો
omniroute providers validate                        # માત્ર-સ્થાનિક માળખાકીય માન્યતા ચકાસણી
omniroute providers add <provider> --credential-env PROVIDER_KEY
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth <provider>                 # હાલનો OAuth પ્રવાહ
omniroute providers edit <id|name> --default-model <model>
omniroute providers remove <id|name> --yes
```

`providers add/import/auth/edit/remove` API-પ્રથમ છે અને તેથી સક્રિય
સ્થાનિક અથવા રિમોટ કૉન્ટેક્સ્ટ સામે કાર્ય કરે છે. ક્રેડેન્શિયલ ઇનપુટ માટે
`--credential-stdin` અથવા `--credential-env` વાપરવું જોઈએ; `--dry-run --json` માત્ર
રિડૅક્ટ કરેલી હાજરી/આકારની જાણ કરે છે. `providers available` OmniRoute કૅટલૉગ વાંચે છે;
`providers list/test/test-all/validate` તેમનું સ્થાનિક SQLite વર્તન જાળવી રાખે છે અને
તેના માટે સર્વર ચાલતું હોવું જરૂરી નથી.

કસ્ટમ OpenAI-સુસંગત અથવા Anthropic-સુસંગત નોડ માટે, `omniroute nodes add` દ્વારા પરત મળેલા
નોડ ID સાથે `omniroute keys add "$NODE_ID" --stdin` વાપરીને ક્રેડેન્શિયલ્સ જોડો.
આ માટે સક્રિય કૉન્ટેક્સ્ટમાં ચાલતું સર્વર અને મેનેજમેન્ટ ઑથેન્ટિકેશન જરૂરી છે.
CLI `POST /api/providers` નો ઉપયોગ કરે છે, જે નોડની માન્યતા ચકાસે છે અને તેની એન્ડપૉઇન્ટ
સેટિંગ્સ કનેક્શનમાં કૉપી કરે છે. નોડ ખૂટતો હોય, અધિકૃતતા નિષ્ફળ જાય અથવા
સર્વર અનુપલબ્ધ હોય, તો સ્થાનિક ફૉલબૅક ક્રેડેન્શિયલ બનાવ્યા વિના ભૂલ પરત મળે છે.

`nodes add --base-url` નોડ એન્ડપૉઇન્ટ સેટ કરે છે; તે `OMNIROUTE_BASE_URL` માંના સર્વર ઍડ્રેસથી
અલગ છે. OpenAPI ફાઇલો માટે,
`omniroute openapi dump --format json --out ./openapi.json` વાપરો; વૈશ્વિક `--output`
CLI ડિસ્પ્લે ફૉર્મેટિંગ પસંદ કરે છે, ગંતવ્ય ફાઇલનામ નહીં.

### પુનઃપ્રાપ્તિ અને રીસેટ

```bash
omniroute reset-password                # ઍડમિન પાસવર્ડ રીસેટ કરો (આ પણ: omniroute-reset-password)
omniroute reset-encrypted-columns       # એન્ક્રિપ્ટેડ ક્રેડેન્શિયલ રીસેટ માટે ચેતવણી + ડ્રાય-રન બતાવો
omniroute reset-encrypted-columns --force  # SQLite માં એન્ક્રિપ્ટેડ ક્રેડેન્શિયલ્સને ખરેખર null કરો
```

### ક્રેડેન્શિયલ નિકાસ (⚠ સાવધાનીથી સંભાળો)

```bash
omniroute auth export                                 # ચેતવણી + પુષ્ટિ ગેટ બતાવો — DB ઍક્સેસ નહીં
omniroute auth export --force                          # બધા કનેક્શન્સનાં ડિક્રિપ્ટ કરેલા ક્રેડેન્શિયલ્સ stdout પર JSON તરીકે નિકાસ કરો
omniroute auth export --force --id <id>                 # માત્ર મેળ ખાતું કનેક્શન નિકાસ કરો
omniroute auth export --force --format env               # OMNIROUTE_<PROVIDER>_<FIELD>=<value> લાઇન્સ આઉટપુટ કરો
omniroute auth export --force --out creds.json           # ફાઇલમાં લખો (0600 પરવાનગીઓ સાથે બનાવવામાં આવે છે)
```

`auth export` **માત્ર-સ્થાનિક** છે (સીધું SQLite વાંચન, કોઈ HTTP રૂટ નહીં) અને તે ઇરાદાપૂર્વક
**પ્લેનટેક્સ્ટ** `apiKey`/`accessToken`/`refreshToken`/`idToken` મૂલ્યો પ્રિન્ટ/લખે છે — આ સુવિધા છે,
બગ નથી. `--force` વિના ડેટાબેઝમાંથી કંઈપણ વાંચવામાં આવતું નથી અને કંઈપણ ડિક્રિપ્ટ કરવામાં આવતું નથી. કોઈપણ પ્લેનટેક્સ્ટ આઉટપુટ કરતાં પહેલાં stderr પર
ચેતવણી બેનર હંમેશાં પ્રિન્ટ થાય છે. `STORAGE_ENCRYPTION_KEY` સેટ કરેલી હોવી
આવશ્યક છે. જે ફીલ્ડ ડિક્રિપ્ટ કરવામાં નિષ્ફળ જાય છે (જૂની કી, દૂષિત સાઇફરટેક્સ્ટ), તેની જાણ સમગ્ર એક્સપોર્ટને
રદ કરવાને અથવા મૂળભૂત ભૂલ જાહેર કરવાને બદલે `<field>DecryptFailed: true` તરીકે કરવામાં આવે છે.

### અન્ય સબકમાન્ડ્સ

અન્યથા નોંધ્યું ન હોય ત્યાં સુધી, આ માટે ચાલુ OmniRoute સર્વર આવશ્યક છે:

```bash
omniroute status                       # વ્યાપક રનટાઇમ સ્થિતિ
omniroute logs                         # રિક્વેસ્ટ લૉગ્સ સ્ટ્રીમ કરો (--json, --search, --follow)
omniroute config list                  # કૉન્ફિગર કરેલ CLI ટૂલ્સ દર્શાવો

omniroute provider list                # ઉપલબ્ધ પ્રોવાઇડર્સની સૂચિ બનાવો (providers listનું ઉપનામ)
omniroute provider add                 # કોઈ ટૂલ પર OmniRouteને પ્રોવાઇડર તરીકે રજિસ્ટર કરો
omniroute keys add | list | remove     # API કીઝ મેનેજ કરો
omniroute models [provider]            # મોડલ્સની સૂચિ બનાવો (--json, --search)
omniroute combo list | switch | create | delete

omniroute backup                       # કૉન્ફિગ + DBનો સ્નૅપશૉટ
omniroute restore                      # અગાઉના સ્નૅપશૉટમાંથી પુનઃસ્થાપિત કરો

omniroute health                       # વિગતવાર આરોગ્ય સ્થિતિ (બ્રેકર્સ, કૅશ, મેમરી)
omniroute quota                        # પ્રોવાઇડર ક્વોટાનો ઉપયોગ
omniroute cache                        # કૅશની સ્થિતિ
omniroute cache clear                  # સિમેન્ટિક + સિગ્નેચર કૅશ સાફ કરો

omniroute mcp status | restart         # MCP સર્વરની સ્થિતિ / પુનઃપ્રારંભ
omniroute a2a status | card            # A2A સર્વરની સ્થિતિ / એજન્ટ કાર્ડ

omniroute tunnel list | create | stop  # ટનલ્સ મેનેજ કરો (cloudflare/tailscale/ngrok)
omniroute env show | get <k> | set <k> <v>  # env વેરિએબલ્સ તપાસો / સેટ કરો (કામચલાઉ)

omniroute test                         # પ્રોવાઇડર કનેક્ટિવિટી સ્મોક ટેસ્ટ
omniroute update                       # અપડેટ્સ માટે તપાસો
omniroute completion                   # શેલ કમ્પ્લીશન જનરેટ કરો
```

## OmniRoute CLI વડે ઇન્ફરન્સ-કી નીતિ મેનેજ કરો

કોઈ હાલની ઇન્ફરન્સ કીને તેના ID દ્વારા તપાસવા અથવા અપડેટ કરવા માટે પ્રમાણિત મેનેજમેન્ટ કૉન્ટેક્સ્ટનો ઉપયોગ કરો ([રિમોટ મોડ](../guides/REMOTE-MODE.md) જુઓ):

```bash
omniroute --output json keys policy show KEY_ID
omniroute keys policy set KEY_ID --unrestricted
omniroute --output json keys policy show KEY_ID
```

`--unrestricted`, `--model-access-mode all` માટેનું ઉપનામ છે. આ અપડેટ મોડેલની મંજૂરીસૂચિ સાફ કરે છે. તે સ્કોપ્સ, કનેક્શન નિયમો, અવરોધિત મોડેલ્સ, રેટ મર્યાદાઓ અને ખર્ચ મર્યાદાઓ જાળવી રાખે છે, તેથી તે અન્ય નિયંત્રણો હજુ પણ કોઈ વિનંતીને નકારી શકે છે. સ્પષ્ટ રીતે આપેલું `--allowed-models ""` પણ `all` પસંદ કરે છે; કોઈ મંજૂર મોડેલ ન ધરાવતી પ્રતિબંધિત કી જાળવી રાખવા માટે તેને `--model-access-mode restricted` સાથે જોડો. ખાલી ન હોય તેવી અલ્પવિરામથી અલગ કરેલી સૂચિ, સ્પષ્ટ રીતે અન્યથા નિર્દિષ્ટ ન હોય તો, `restricted` પસંદ કરે છે. વિરોધાભાસી `all` સાથે ખાલી ન હોય તેવી મંજૂરીસૂચિ હોય તો વિનંતી મોકલતાં પહેલાં જ તેને નકારવામાં આવે છે.

`--rate-limit 30` પ્રતિ મિનિટ વિનંતીઓની મર્યાદા સેટ કરે છે અને અન્ય સમયગાળાઓ માટેના નિયમો જાળવી રાખે છે. `--max-cost 5`, સાપ્તાહિક મર્યાદા બદલ્યા વિના દૈનિક USD મર્યાદા સક્ષમ કરે છે; `--max-cost 0` દૈનિક મર્યાદા દૂર કરે છે અને હાલનું વપરાશ-મર્યાદા ટૉગલ તથા સાપ્તાહિક મર્યાદા જાળવી રાખે છે. છોડવામાં આવેલા નીતિ ફીલ્ડ્સ યથાવત્ રહે છે. રેટમાં ફેરફાર કરતાં પહેલાં વર્તમાન નીતિ વાંચવામાં આવે છે; એક જ કીની રેટ-લિમિટ એરેમાં એકસાથે ફેરફાર કરવાનું ટાળો.

નીતિ કમાન્ડ્સ પ્રમાણિત `GET`/`PATCH /api/keys/{id}` નો ઉપયોગ કરે છે અને સક્રિય કૉન્ટેક્સ્ટ તથા વૈશ્વિક `--api-key` વિકલ્પનું પાલન કરે છે. JSON આઉટપુટમાં ફક્ત નીતિ ફીલ્ડ્સ હોય છે, સંગ્રહિત કી અથવા તેનું માસ્ક કરેલું પ્રતિનિધિત્વ નહીં. માત્ર ઇન્ફરન્સ માટેનું ક્રેડેન્શિયલ મેનેજમેન્ટ ફેરફારોને અધિકૃત કરી શકતું નથી. 401/403 મળે તો મેનેજમેન્ટ ક્રેડેન્શિયલ અને કૉન્ટેક્સ્ટ તપાસવા જરૂરી છે; તે સ્થાનિક CLI-ટોકન અથવા સૉલ્ટની નિષ્ફળતા સાબિત કરતું નથી. અલગ સ્થાનિક પ્રમાણીકરણ કરાર માટે [CLI ટોકન](../security/CLI_TOKEN.md) જુઓ.
