## ફીચર ફ્લૅગ્સ શું છે

ફીચર ફ્લૅગ એ નામ ધરાવતું ટૉગલ (બુલિયન અથવા એનમ) છે, જેનું મૂલ્ય
રનટાઇમ દરમિયાન બદલી શકાય છે અને ડેટાબેઝમાં સાચવી શકાય છે, જેના માટે પ્રોસેસને
ફરીથી ડિપ્લોય કરવાની જરૂર નથી. દરેક ફ્લૅગનું વર્ણન `FeatureFlagDefinition` દ્વારા
`key`, `label`, `description`, `category`, `defaultValue`, `type`, અને
`requiresRestart` સંકેત સાથે કરવામાં આવે છે.

### રિઝોલ્યુશન ક્રમ

ફ્લૅગનું **અસરકારક મૂલ્ય**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) દ્વારા નીચેની
અગ્રતાના ક્રમમાં નક્કી થાય છે (સૌથી ઊંચી અગ્રતા જીતે છે):

1. **DB ઓવરરાઇડ** — `feature_flags` નેમસ્પેસ હેઠળ `key_value` કોષ્ટકમાં
   સંગ્રહિત મૂલ્ય (ડૅશબોર્ડ અથવા REST API દ્વારા સેટ કરેલું).
2. **એન્વાયર્નમેન્ટ વેરિએબલ** — `process.env[<KEY>]`, જો તે સેટ થયેલું અને ખાલી ન હોય.
3. **વ્યાખ્યાનું ડિફૉલ્ટ** — `featureFlagDefinitions.ts`માંથી `defaultValue`.

બુલિયન ફ્લૅગનું અસરકારક મૂલ્ય `"true"`, `"1"`, અથવા `"yes"` હોય ત્યારે તેને
**સક્ષમ** માનવામાં આવે છે (`isFeatureFlagEnabled()` જુઓ).

> [!NOTE]
> મોટાભાગના ફ્લૅગ્સ માટે [`ENVIRONMENT.md`](./ENVIRONMENT.md)માં દસ્તાવેજીકૃત
> **સમાન નામ** ધરાવતું અનુરૂપ એન્વાયર્નમેન્ટ વેરિએબલ પણ હોય છે. ફ્લૅગનું DB ઓવરરાઇડ
> તે એન્વાયર્નમેન્ટ વેરિએબલ કરતાં અગ્રતા ધરાવે છે. `requiresRestart: true` ધરાવતો
> ફ્લૅગ તરત જ સાચવવામાં આવે છે, પરંતુ તેને માત્ર પ્રોસેસ શરૂ થાય ત્યારે ફરીથી વાંચવામાં
> આવે છે — તેને ટૉગલ કરવાથી ડૅશબોર્ડમાં **"સર્વર પુનઃપ્રારંભ કરો"** બૅનર દેખાય છે.

## ફ્લૅગ સૂચિ

6 શ્રેણીઓમાં 111 ફ્લૅગ્સ. **મૂળભૂત** એટલે વ્યાખ્યામાં નિર્ધારિત મૂળભૂત મૂલ્ય — જ્યારે
DB ઓવરરાઇડ કે પર્યાવરણ ચલ, બંનેમાંથી કોઈ હાજર ન હોય ત્યારે ઉપયોગમાં લેવાતું મૂલ્ય.

> `setFeatureFlagOverride()` અને REST `PUT` હૅન્ડલર બંનેમાં માન્ય કરવામાં આવે છે).

## ફ્લૅગ્સ ટૉગલ કરવા

### ડૅશબોર્ડ

**ડૅશબોર્ડ → સેટિંગ્સ → ફીચર ફ્લૅગ્સ** પર જાઓ
(`/dashboard/settings/feature-flags`). ગ્રિડ
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
આ સુવિધાઓને સપોર્ટ કરે છે:

- કી અથવા વર્ણન દ્વારા **શોધ**, અને કેટેગરી દ્વારા **ફિલ્ટર** (ઉપરાંત કૃત્રિમ
  **પુનઃપ્રારંભ જરૂરી છે** વ્યૂ).
- બુલિયન ફ્લૅગ્સ માટે **ટૉગલ** અને enum ફ્લૅગ્સ માટે **ડ્રૉપડાઉન**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- દરેક ફ્લૅગ માટે **સ્રોત બૅજ** — `DB`, `ENV`, અથવા `DEF` — જે દર્શાવે છે કે
  અસરકારક મૂલ્ય ક્યાંથી આવ્યું છે.
- ઓવરરાઇડ દૂર કરવા માટેનું **રીસેટ** બટન (માત્ર `DB`-સ્રોતવાળા ફ્લૅગ્સ માટે દર્શાવાય છે),
  અને નીચે **બધા ઓવરરાઇડ્સ રીસેટ કરો** બટન.
- જ્યારે `requiresRestart` ફ્લૅગ બદલવામાં આવે ત્યારે **સર્વર પુનઃપ્રારંભ કરો** બૅનર.

### REST API

બધી ક્રિયાઓ એક જ રૂટ મારફતે થાય છે:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
દરેક મેથડ માટે પ્રમાણિત ડૅશબોર્ડ સેશન જરૂરી છે (અન્યથા `401`).

#### `GET /api/settings/feature-flags`

દરેક ફ્લૅગને તેના અસરકારક મૂલ્ય, સ્રોત અને સારાંશ સાથે પરત કરે છે.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... બધા 111 ફ્લૅગ્સ
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

એક ઓવરરાઇડ સેટ કરો અથવા દૂર કરો. બૉડી: `{ key: string; value?: string }`.
`value` ન આપવાથી ઓવરરાઇડ દૂર થાય છે (env / ડિફૉલ્ટ પુનઃસ્થાપિત થાય છે).

```bash
# DB ઓવરરાઇડ સેટ કરો
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ઓવરરાઇડ દૂર કરો ("value" વગર)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

પ્રતિસાદ નવું `effectiveValue`/`source`, અગાઉનું `previousValue`/
`previousSource`, અને `requiresRestart` પરત કરે છે. અજાણી કી અને માન્ય રેન્જની બહારનાં enum
મૂલ્યોને `400` સાથે નકારવામાં આવે છે.

#### `DELETE /api/settings/feature-flags`

બધા DB ઓવરરાઇડ્સને એકસાથે સાફ કરે છે અને દરેક ફ્લૅગને તેના env / ડિફૉલ્ટ
મૂલ્ય પર પુનઃસ્થાપિત કરે છે. `{ cleared: <count>, message: "..." }` પરત કરે છે.

> [!NOTE]
> `requiresRestart: true` ધરાવતા ફ્લૅગ્સ માત્ર પ્રોસેસ ફરી લોડ થયા પછી જ અમલમાં આવે છે.
> ડૅશબોર્ડનો પુનઃપ્રારંભ પ્રવાહ `POST /api/restart`ને કૉલ કરે છે અને ત્યારબાદ સર્વર ફરી
> ચાલુ થાય ત્યાં સુધી `GET /api/health/ping`ને વારંવાર પોલ કરે છે.

## કટોકટી બજેટ ફૉલબૅક

`OMNIROUTE_EMERGENCY_FALLBACK` (શ્રેણી `runtime`, ડિફૉલ્ટ `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)માંના
કટોકટી મફત-ફૉલબૅક પાથને નિયંત્રિત કરે છે.
જ્યારે તે સક્ષમ હોય, ત્યારે પોતાનું બજેટ સમાપ્ત કરી ચૂકેલી વિનંતીઓને સંપૂર્ણપણે નિષ્ફળ કરવાને બદલે મફત ફૉલબૅક
પ્રદાતા/મૉડલ તરફ રૂટ કરવામાં આવે છે. આ વર્તણૂકને અક્ષમ કરવા અને બજેટ સમાપ્ત થઈ ગયેલી વિનંતીઓને
નિષ્ફળ થવા દેવા માટે, ડૅશબોર્ડ ટૉગલ, DB ઓવરરાઇડ અથવા
`OMNIROUTE_EMERGENCY_FALLBACK` પર્યાવરણ ચલ દ્વારા તેને `false` (અથવા `0`) પર સેટ કરો.
(PRs #3741 / #3752માં ડૅશબોર્ડ ટૉગલ તરીકે ઉપલબ્ધ કરાવવામાં આવ્યું છે.)

આ ફૉલબૅક દ્વારા આપવામાં આવેલા પ્રતિસાદમાં
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` હોય છે, જેથી
ક્લાયન્ટ તેની વિનંતી સાથે `X-OmniRoute-Provider`ની સરખામણી કર્યા વિના જાણી શકે કે તેને ફરીથી રૂટ કરવામાં આવી હતી.
અન્ય દરેક પ્રતિસાદમાં આ હેડર ગેરહાજર હોય છે.
