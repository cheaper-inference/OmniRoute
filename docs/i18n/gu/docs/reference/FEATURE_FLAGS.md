## ફીચર ફ્લૅગ્સ શું છે

ફીચર ફ્લૅગ એ નામ ધરાવતું ટૉગલ (બુલિયન અથવા એનમ) છે, જેનું મૂલ્ય
રનટાઇમ દરમિયાન બદલી શકાય છે અને ડેટાબેઝમાં સાચવી શકાય છે, જેના માટે પ્રોસેસને
ફરીથી ડિપ્લોય કરવાની જરૂર નથી. દરેક ફ્લૅગનું વર્ણન `FeatureFlagDefinition` દ્વારા
`key`, `label`, `description`, `category`, `defaultValue`, `type`, અને
`requiresRestart` સંકેત સાથે કરવામાં આવે છે.

### રિઝોલ્યુશન ક્રમ

ફ્લૅગનું **અસરકારક મૂલ્ય**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) દ્વારા નીચેની
અગ્રતાના ક્રમમાં નક્કી થાય છે (સૌથી ઊંચી અગ્રતા જીતે છે):

1. **DB ઓવરરાઇડ** — `feature_flags` નેમસ્પેસ હેઠળ `key_value` કોષ્ટકમાં
   સંગ્રહિત મૂલ્ય (ડૅશબોર્ડ અથવા REST API દ્વારા સેટ કરેલું).
2. **એન્વાયર્નમેન્ટ વેરિએબલ** — `process.env[<KEY>]`, જો તે સેટ થયેલું અને ખાલી ન હોય.
3. **વ્યાખ્યાનું ડિફૉલ્ટ** — `featureFlagDefinitions.ts`માંથી `defaultValue`.

બુલિયન ફ્લૅગનું અસરકારક મૂલ્ય `"true"`, `"1"`, અથવા `"yes"` હોય ત્યારે તેને
**સક્ષમ** માનવામાં આવે છે (`isFeatureFlagEnabled()` જુઓ).

> [!NOTE]
> મોટાભાગના ફ્લૅગ્સ માટે [`ENVIRONMENT.md`](./ENVIRONMENT.md)માં દસ્તાવેજીકૃત
> **સમાન નામ** ધરાવતું અનુરૂપ એન્વાયર્નમેન્ટ વેરિએબલ પણ હોય છે. ફ્લૅગનું DB ઓવરરાઇડ
> તે એન્વાયર્નમેન્ટ વેરિએબલ કરતાં અગ્રતા ધરાવે છે. `requiresRestart: true` ધરાવતો
> ફ્લૅગ તરત જ સાચવવામાં આવે છે, પરંતુ તેને માત્ર પ્રોસેસ શરૂ થાય ત્યારે ફરીથી વાંચવામાં
> આવે છે — તેને ટૉગલ કરવાથી ડૅશબોર્ડમાં **"સર્વર પુનઃપ્રારંભ કરો"** બૅનર દેખાય છે.

## ટૉગલિંગ ફ્લેગ્સ

### ડેશબોર્ડ

પર નેવિગેટ કરો** ડેશબોર્ડ → સેટિંગ્સ → લક્ષણ ફ્લેગ્સ** (`/dashboard/settings/feature-flags`) ગ્રીડ (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) સપોર્ટ કરે છે:

- **શોધો** કી અથવા વર્ણન દ્વારા, અને** ફિલ્ટર** શ્રેણી દ્વારા (વત્તા એક કૃત્રિમ** પુનઃપ્રારંભની જરૂર છે** જુઓ).
- એ** ટૉગલ** બુલિયન ફ્લેગ માટે અને એ** ડ્રોપડાઉન** enum ફ્લેગો માટે (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- એ** સ્ત્રોત બેજ** પ્રતિ ધ્વજ — `DB`, `ENV`, અથવા `DEF` — દર્શાવે છે કે અસરકારક મૂલ્ય ક્યાંથી આવ્યું છે.
- એ** રીસેટ કરો** ઓવરરાઇડ છોડવા માટે બટન (માત્ર `DB` -sourced ફ્લેગ્સ માટે બતાવવામાં આવે છે), અને a** બધા ઓવરરાઇડ્સને ફરીથી સેટ કરો** તળિયે બટન.
- એ** સર્વર પુનઃપ્રારંભ કરો** બેનર જ્યારે `requiresRestart` ધ્વજ બદલવામાં આવે છે.

### REST API

તમામ કામગીરી એક જ રૂટમાંથી પસાર થાય છે: [`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts). દરેક પદ્ધતિ માટે પ્રમાણિત ડેશબોર્ડ સત્રની જરૂર છે ( અન્યથા`401` ).

લૉગિન અક્ષમ (`requireLogin=false`) સાથે માર્ગ ખુલ્લો છે, સંરક્ષિત ફ્લેગ્સ સિવાય: સુરક્ષા શ્રેણીમાં દરેક ધ્વજ વત્તા `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`, `OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS`, `MITM_DISABLE_TLS_VERIFY`, `OMNIROUTE_MCP_ENFORCE_SCOPES` અને `SKILLS_SANDBOX_NETWORK_ENABLED` ( `protectedFeatureFlags.ts` માં`isProtectedFeatureFlag()` ). તેમાંથી એક પર `PUT`, અને `DELETE` જ્યારે તેમાંથી એક DB ઓવરરાઇડ ધરાવે છે, ત્યારે હજુ પણ ડેશબોર્ડ સત્ર, `manage` -scope API કી, `oma_` એક્સેસ ટોકન લખવાની અવકાશ અથવા ઉચ્ચ, અથવા લૂપબેકમાંથી મોકલેલ CLI ટોકન અથવા આંતરિક-સેવા ટોકનની જરૂર છે. તે સેટ લોગિન ઓન કરતાં વધુ પહોળો છે, જ્યાં રૂટ માત્ર સત્ર અથવા `manage` -scope કી સ્વીકારે છે.

#### `GET /api/settings/feature-flags`

દરેક ધ્વજને તેના અસરકારક મૂલ્ય, સ્ત્રોત અને સારાંશ સાથે પરત કરે છે.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 119 flags
  ],
  "summary": {
    "total": 119,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

એક ઓવરરાઇડ સેટ કરો અથવા દૂર કરો. શરીર: `{ key: string; value?: string }`. `value` ને છોડી દેવાથી ઓવરરાઇડ દૂર થાય છે (env/default પુનઃસ્થાપિત કરવું).

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

પ્રતિભાવ નવા `effectiveValue`/`source`, `previousValue`/ `previousSource`, અને `requiresRestart` પડઘો પાડે છે. અજાણી કીઓ અને રેન્જની બહારની enum કિંમતો `400` સાથે નકારી કાઢવામાં આવે છે.

#### `DELETE /api/settings/feature-flags`

સાફ કરે છે** બધા** DB એક જ સમયે ઓવરરાઇડ કરે છે, દરેક ફ્લેગને તેના env / ડિફોલ્ટ મૂલ્યમાં પુનઃસ્થાપિત કરે છે. `{ cleared: <count>, message: "..." }` પરત કરે છે.

> [!NOTE]
> `requiresRestart: true` સાથેના ફ્લેગ પ્રક્રિયાને ફરીથી લોડ કર્યા પછી જ પ્રભાવી થાય છે. ડેશબોર્ડનો પુનઃપ્રારંભ પ્રવાહ `POST /api/restart` કૉલ કરે છે અને પછી સર્વર બેકઅપ ન થાય ત્યાં સુધી `GET /api/health/ping` મતદાન કરે છે.

## કટોકટી બજેટ ફૉલબૅક

`OMNIROUTE_EMERGENCY_FALLBACK` (શ્રેણી `runtime`, ડિફૉલ્ટ `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)માંના
કટોકટી મફત-ફૉલબૅક પાથને નિયંત્રિત કરે છે.
જ્યારે તે સક્ષમ હોય, ત્યારે પોતાનું બજેટ સમાપ્ત કરી ચૂકેલી વિનંતીઓને સંપૂર્ણપણે નિષ્ફળ કરવાને બદલે મફત ફૉલબૅક
પ્રદાતા/મૉડલ તરફ રૂટ કરવામાં આવે છે. આ વર્તણૂકને અક્ષમ કરવા અને બજેટ સમાપ્ત થઈ ગયેલી વિનંતીઓને
નિષ્ફળ થવા દેવા માટે, ડૅશબોર્ડ ટૉગલ, DB ઓવરરાઇડ અથવા
`OMNIROUTE_EMERGENCY_FALLBACK` પર્યાવરણ ચલ દ્વારા તેને `false` (અથવા `0`) પર સેટ કરો.
(PRs #3741 / #3752માં ડૅશબોર્ડ ટૉગલ તરીકે ઉપલબ્ધ કરાવવામાં આવ્યું છે.)

આ ફૉલબૅક દ્વારા આપવામાં આવેલા પ્રતિસાદમાં
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` હોય છે, જેથી
ક્લાયન્ટ તેની વિનંતી સાથે `X-OmniRoute-Provider`ની સરખામણી કર્યા વિના જાણી શકે કે તેને ફરીથી રૂટ કરવામાં આવી હતી.
અન્ય દરેક પ્રતિસાદમાં આ હેડર ગેરહાજર હોય છે.
