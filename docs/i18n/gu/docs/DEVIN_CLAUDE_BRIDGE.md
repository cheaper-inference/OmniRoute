`devin-cli-agentic` વાસ્તવિક Claude Code રનટાઇમને OmniRouteના સ્થાનિક Anthropic
Messages એન્ડપોઇન્ટનો ઉપયોગ કરવા દે છે, જ્યારે અધિકૃત Devin CLI ACP stdio પર મોડેલ પ્રતિસાદો
પૂરા પાડે છે. તે હાલના Anthropic, Claude OAuth, Claude Web અથવા `devin-cli` પ્રદાતાઓમાં
ફેરફાર કરતું નથી.

ક્લાયન્ટની માલિકીના ટૂલ કૉલ્સ માટે, Claude-ફોર્મેટના ટૂલ-સક્ષમ પ્રદાતા
`devin-cli-agentic` (ઉપનામ `dva`) મારફતે રૂટ કરો. લેગસી `devin-cli` (`dv`) ACP એક્ઝિક્યુટર
માત્ર ટેક્સ્ટ માટે છે: તે Devinનું ટૂલ્સ-વિનાનું સમરાઇઝર ચલાવે છે અને ટૂલ કૉલ્સ પરત કરી શકતું
નથી. તેના મોડેલ મેટાડેટાને તે મુજબ ચિહ્નિત કરવામાં આવ્યું છે, જેથી ટૂલ્સ જરૂરી હોય તેવું કોમ્બો
રૂટિંગ તેને ટાળશે.

> **વર્તમાન સ્થિતિ: Claude Code `2.1.258` પર પિન કરેલું; ઑફલાઇન અને લાઇવ માન્યતા છેલ્લે
> `2.1.220` પર નોંધાઈ હતી.** `2.1.220` પિને Devin CLI `3000.2.17` અને મોડેલ
> `swe-1-7-lightning` દ્વારા ત્રણ અલગ કરેલા દૃશ્યો પૂર્ણ કર્યા; તે અંતિમ લાઇવ રને ક્લાયન્ટની
> માલિકીના `Read`, `Edit` અને `Bash` ટર્ન્સ, સફળ `npm test` પરિણામો, પ્રોજેક્ટ કમાન્ડ અને સ્કિલ
> શોધ, માત્ર-Devin રૂટિંગ અને શૂન્ય Claude ઇગ્રેસ સાબિત કર્યા. ત્યારબાદ પિનને `2.1.258` સુધી
> વધારવામાં આવ્યું (જે CLI જનરેશનનું OmniRouteની Claude ઓળખ અનુકરણ કરે છે અને જે Fable 5.1
> ટિયર મૂળરૂપે સમાવતી પ્રથમ લાઇન છે). નવા પિન પર પિન કરેલી બેઝ ઇમેજમાં ઇન્સ્ટોલ લેયર અને
> `claude --version`ની ચકાસણી કરવામાં આવી હતી, તેમજ બ્રિજ યુનિટ સ્યુટ, `compose config` અને
> સ્ટેટિક આઇસોલેશન પ્રૂફ પાસ થાય છે — પરંતુ ઑફલાઇન મૉક દૃશ્ય અને લાઇવ ત્રણ-દૃશ્ય સ્યુટ હજી
> ફરી ચલાવવામાં આવ્યા નથી. આ પિન સાથે બ્રિજ પર આધાર રાખતા પહેલાં તેમને ફરી ચલાવો
> ("પિન કરેલા ટૂલ્સ અપડેટ કરવા" જુઓ).

## આર્કિટેક્ચર

```text
Claude Code 2.1.258 (isolated non-root Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format, no-auth provider)
  -> devin acp --agent-type summarizer (official ACP stdio, no Devin tools)
  -> Devin account in the dedicated devin-auth volume
```

અધિકૃત CLIનું ડિફૉલ્ટ ACP એજન્ટ પોતાના ટૂલ્સ ચલાવી શકે છે, તેથી આ બ્રિજ તેનો ઉપયોગ કરતું
નથી. તે નિશ્ચિત `summarizer` ACP એજન્ટ શરૂ કરે છે, જેના અધિકૃત CLI મોડમાં કોઈ ટૂલ્સ નથી, અને
સીરિયલાઇઝ કરેલી Anthropic વિનંતીને એક્ઝિક્યુશન ટ્રેસ તરીકે ફ્રેમ કરે છે. જ્યારે Claudeની માલિકીની
બીજી ક્રિયા જરૂરી હોય, ત્યારે પ્રતિસાદમાં બરાબર એક ક્લાયન્ટ ટૂલ એન્વલપ હોવું આવશ્યક છે. પ્રતિસાદને
સફળ તરીકે રિપોર્ટ કરી શકાય તે પહેલાં કોઈપણ ACP `tool_call` અથવા `tool_call_update` નકારવામાં
આવે છે.

`open-sse/executors/devin-agentic/serializer.ts`માંનો સીરિયલાઇઝર `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` અને
Claude Code દ્વારા પૂરા પાડવામાં આવેલા ટૂલ્સને જાળવી રાખે છે. ઇમેજ અને અજાણ્યા બ્લૉક્સ સ્પષ્ટપણે
નિષ્ફળ થાય છે. મોટા ટૂલ પરિણામો દૃશ્યમાન ટ્રન્કેશન માર્કરનો ઉપયોગ કરે છે.

પાર્સર દરેક મોડેલ ટર્ન માટે એક સ્વતંત્ર `<tool>{...}</tool>` એન્વલપ સ્વીકારે છે. તે વિનંતીની
ટૂલ સૂચિ સામે નામ તપાસે છે, તે ટૂલના JSON Schema અનુસાર આર્ગ્યુમેન્ટ્સને માન્ય કરે છે, મિશ્ર
વર્ણન/ક્રિયાઓને નકારે છે અને એક મર્યાદિત રિપેરની પરવાનગી આપે છે. ત્યારબાદ Claude Code પરિણામી
Anthropic `tool_use`ને સ્થાનિક રીતે ચલાવે છે અને `tool_result`ને OmniRoute મારફતે પાછું મોકલે છે.

## ઑટો-રૂટિંગ

જ્યારે પ્રદાતા બ્લૉક ન હોય ત્યારે તે OmniRouteના `auto/*` કૅન્ડિડેટ પૂલ્સમાં પાત્ર હોય છે.
કૅન્ડિડેટ પાત્રતા પસંદગીની ખાતરી આપતી નથી: કોમ્બોની રૂટિંગ વ્યૂહરચના (ઉદાહરણ તરીકે,
last-known-good) અન્ય પ્રદાતાને પ્રાધાન્ય આપી શકે છે. જ્યારે દરેક વિનંતી Devin મારફતે જ
જવી જરૂરી હોય ત્યારે `dva/<model>` અથવા Devin-પ્રથમ કોમ્બોનો ઉપયોગ કરો.

## આઇસોલેશન અને જોખમ મોડેલ

હોસ્ટનું Claude ઇન્સ્ટોલેશન, એકાઉન્ટ અને કૉન્ફિગરેશન કાર્યક્ષેત્રની બહાર છે અને તેને
પ્રતિબંધિત માનવામાં આવે છે. Compose સેવાઓ:

- UID/GID `10001:10001` તરીકે, ફક્ત વાંચી શકાય તેવી રૂટ ફાઇલસિસ્ટમ, દૂર કરેલી ક્ષમતાઓ અને
  `no-new-privileges` સાથે ચાલે છે;
- ખાનગી `/home/bridge`, સમર્પિત Claude કૉન્ફિગરેશન વોલ્યુમ, અલગ કરેલો OmniRoute ડેટા
  અને અલગ `devin-auth` વોલ્યુમનો ઉપયોગ કરે છે;
- ફક્ત નિકાલ કરી શકાય તેવા `.sandbox` વર્કસ્પેસ/પુરાવા માઉન્ટ કરે છે;
- હોસ્ટ હોમ, Keychain, SSH, ક્લાઉડ ક્રેડેન્શિયલ્સ અથવા Docker સૉકેટ માઉન્ટ કરતા નથી;
- સ્પષ્ટ એન્વાયર્નમેન્ટ બનાવે છે અને Anthropic API/OAuth/રાઉટિંગ વેરિયેબલ્સ દૂર કરે છે;
- ફક્ત સ્થાનિક કી સાથે Claude Code ઇન્ફરન્સને `http://omniroute:20128` તરફ દોરે છે.

ઑફલાઇન પ્રોફાઇલ આંતરિક નેટવર્કનો ઉપયોગ કરે છે. લાઇવ પ્રોફાઇલમાં, OmniRoute ફક્ત
`network-guard` મારફતે સત્તાવાર Devin એન્ડપોઇન્ટ્સ સુધી પહોંચે છે; અસંબંધિત ગંતવ્યો નકારવામાં આવે છે.
Claude Code પાસે અલગ deny-all ઇગ્રેસ ગાર્ડ છે અને તે `NO_PROXY` મારફતે ફક્ત સ્થાનિક OmniRoute
સેવા સુધી પહોંચી શકે છે. ગાર્ડ ઑડિટ ફાઇલો ફક્ત તેમની ગાર્ડ પ્રક્રિયા દ્વારા માઉન્ટ કરવામાં આવે છે.
સ્ક્રિપ્ટ્સ ટોકન-મુક્ત પુરાવા નિકાસ કરતાં પહેલાં ફાઇલની માલિકી, મોડ, લિંક સંખ્યા અને દરેક નિર્ણયની
ચકાસણી કરે છે.

આઇસોલેશનનો પુરાવો સ્વતંત્ર રીતે ચલાવો:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

તે ટોપોલોજી, નામિત માઉન્ટ્સ, નોન-રૂટ/ફક્ત વાંચી શકાય તેવી સેટિંગ્સ, સ્પષ્ટ સ્થાનિક રાઉટિંગ,
સંવેદનશીલ એન્વાયર્નમેન્ટ વેરિયેબલ્સની ગેરહાજરી, Docker સૉકેટની ગેરહાજરી,
`api.anthropic.com` અને `claude.ai` પર અવરોધિત ઍક્સેસ, ફક્ત Devin પ્રદાતા પસંદગી અને
ACP બૅકએન્ડ ઉપલબ્ધ ન હોય ત્યારે સ્પષ્ટ નિષ્ફળતાની ચકાસણી કરે છે.

## પ્રથમ વખતનું સેટઅપ અને સામાન્ય ઉપયોગ

પિન કરેલી ઇમેજ બિલ્ડ કરો:

```bash
./scripts/devin-bridge/build
```

ફક્ત અલગ કરેલા Devin વોલ્યુમને પ્રમાણિત કરો:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

લૉગિન આદેશ રિમોટ/કન્ટેનર એન્વાયર્નમેન્ટ માટે નિર્ધારિત સત્તાવાર મેન્યુઅલ-ટોકન પ્રવાહનો
ઉપયોગ કરે છે. મૂલ્ય સીધું CLI પ્રોમ્પ્ટમાં દાખલ કરવામાં આવે છે; તેને પ્રોસેસ આર્ગ્યુમેન્ટ તરીકે
પસાર કરવામાં, Gitમાં લખવામાં અથવા હોસ્ટમાંથી કૉપિ કરવામાં આવતું નથી.

અલગ કરેલો Claude Code રનટાઇમ શરૂ કરો:

```bash
./scripts/devin-bridge/launch
```

`launch` કન્ટેનરાઇઝ્ડ Claude Code શરૂ કરતાં પહેલાં આઇસોલેશન, Devin પ્રમાણીકરણ અને મોડેલ
ડિસ્કવરી ફરીથી તપાસે છે. તે ક્યારેય હોસ્ટનું Claude એક્ઝિક્યુટેબલ ચલાવતું નથી. મોડેલ ઉપનામો
`.env.devin-bridge`માં સેટ કરી શકાય છે; દરેક કૉન્ફિગર કરેલા મૂલ્યમાં
`devin-cli-agentic/` ઉપસર્ગ જળવાયેલો હોવો આવશ્યક છે.

## માન્યતા આદેશો

પુનરુત્પાદિત કરી શકાય એવા ઑફલાઇન પાથ માટે Devin એકાઉન્ટની જરૂર નથી અને તેમાં રનટાઇમ દરમિયાન ઇન્ટરનેટ નથી:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

પ્રમાણિત, વૈકલ્પિક લાઇવ પાથ આ છે:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ACP સેશન્સ એકસાથે મોટા પ્રમાણમાં ખોલવાનું ટાળવા માટે લાઇવ રનર વિવિધ પરિદૃશ્યો વચ્ચે રાહ જુએ છે અને
લખાણરૂપ દાવાઓ પર વિશ્વાસ કરવાને બદલે સ્ટ્રક્ચર્ડ Claude સ્ટ્રીમ ઇવેન્ટ્સની ચકાસણી કરે છે. તેના ત્રણ
પરિદૃશ્યો આ બાબતો સાબિત કરે છે:

1. સીધું પ્રોજેક્ટ વાંચન અને ખામી વિશ્લેષણ;
2. વાસ્તવિક `Edit`, ક્લાયન્ટ-માલિકીનું `Bash` `npm test` અને અંતિમ પરિણામ;
3. `/bridge-check` સાથે `bridge-proof` ડિસ્કવરી, પ્રોજેક્ટ વાંચન, બીજું સફળ
   ક્લાયન્ટ-માલિકીનું `npm test` અને કોઈ બાકી કાર્ય વિના પૂર્ણતા.

અંતિમ ગેટ Devin નેટવર્ક ઑડિટ પણ તપાસે છે અને Claude ઇગ્રેસ ઑડિટ ખાલી જ રહે તે જરૂરી બનાવે છે.

## પિન કરેલા ટૂલ્સ અપડેટ કરવા

ઇમેજમાં Node, Claude Code અને Devin CLI ને
`docker/devin-bridge/Dockerfile` માં પિન કરવામાં આવ્યા છે. અપડેટ કરવા માટે:

1. સ્પષ્ટ રીતે આપેલી આવૃત્તિઓ બદલો;
2. બંને આર્કિટેક્ચર-વિશિષ્ટ Devin આર્કાઇવ ચેકસમને સત્તાવાર આર્ટિફેક્ટ માટેનાં મૂલ્યોથી બદલો;
3. ફરીથી બિલ્ડ કરો અને દરેક ઑફલાઇન માન્યતા આદેશ ચલાવો;
4. ઇમેજની અંદરની આવૃત્તિઓની પુષ્ટિ કરો;
5. પ્રમાણીકૃત ત્રણ-પરિદૃશ્યવાળી લાઇવ સ્યુટ ફરીથી ચલાવો.

હોસ્ટ પર કોઈપણ CLI વૈશ્વિક રીતે ઇન્સ્ટૉલ કરશો નહીં અથવા ચેકસમ ચકાસણીને
ચકાસણી વિનાના ડાઉનલોડથી બદલશો નહીં.

  સ્થાનિક રાઉટિંગ અને સંવેદનશીલ વિગતો દૂર કરેલી એક્ઝિક્યુટર ભૂલો દર્શાવે છે.

- `.sandbox/evidence/claude-stream.jsonl` વાસ્તવિક Claude Code ઑફલાઇન રન રેકોર્ડ કરે છે.
- `.sandbox/evidence/live-*.jsonl` ત્રણ માન્ય કરેલી લાઇવ સ્ટ્રીમ રેકોર્ડ કરે છે.

./scripts/devin-bridge/clean --all

## મર્યાદાઓ

- બ્રિજ સાધનો વિનાની નિશ્ચિત `summarizer` ભૂમિકા પર આધાર રાખે છે, કારણ કે Devin CLI `3000.2.17`
  તટસ્થ, સાધનો વિનાનો ACP એજન્ટ ઉપલબ્ધ કરાવતું નથી. ઍડૅપ્ટર સારાંશ-સ્વરૂપના
  મધ્યવર્તી પ્રતિસાદોની ક્ષતિપૂર્તિ કરે છે, પરંતુ એક મર્યાદિત સુધારો હજુ પણ સ્પષ્ટ રીતે નિષ્ફળ થઈ શકે છે.
- લાઇવ ACP કૉલ ક્ષણિક `502`/`504` પ્રતિસાદ આપી શકે છે. હાર્નેસ પરિદૃશ્યો વચ્ચે અંતર રાખે છે;
  સતત નિષ્ફળતામાં સિસ્ટમ બંધ સ્થિતિમાં રહે છે અને ક્યારેય બીજો પ્રદાતા પસંદ કરતી નથી.
- દરેક Anthropic વિનંતીમાંથી ACP સંદર્ભનું પુનઃનિર્માણ થાય છે; કોઈ પ્રોસેસ/સત્ર
  અનુસંગતા નથી.
- દરેક મોડલ પ્રતિસાદ માટે એક ટૂલ કૉલ સમર્થિત છે; સમાંતર કૉલ નકારવામાં આવે છે.
- ઇમેજ સ્પષ્ટ રીતે અસમર્થિત છે. વિઝન, વિચાર-પ્રક્રિયા આઉટપુટ, પ્રયત્ન નિયંત્રણો અને 1M
  સંદર્ભ વિન્ડોને ઉપલબ્ધ તરીકે દર્શાવવામાં આવતાં નથી.
- SSE માન્ય Anthropic લાઇફસાઇકલ ઇવેન્ટનો ઉપયોગ કરે છે, પરંતુ મર્યાદિત ACP ટર્ન
  એકત્રિત થયા પછી જ તેને ઉત્સર્જિત કરવામાં આવે છે; ACP ચંક્સ ક્રમશઃ ફૉર્વર્ડ કરવામાં આવતા નથી.
