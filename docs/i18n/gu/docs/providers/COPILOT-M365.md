`copilot-m365-web` (ઉર્ફે `m365copilot`) `m365.cloud.microsoft/chat` પર પ્રમાણિત Microsoft 365 Copilot સત્ર દ્વારા OpenAI-ફોર્મેટ ચેટ વિનંતીઓ મોકલે છે. આ એક બિનસત્તાવાર મૂળ એકીકરણ છે: કોઈ અલગ પ્રોક્સી પ્રક્રિયા અથવા લોકલહોસ્ટ અપસ્ટ્રીમ જરૂરી નથી. પ્રદાતા ID, ઉપનામ અને હાલના આયાત કરેલ જોડાણો યથાવત છે. `copilot.microsoft.com` પર ગ્રાહક સેવા માટે `copilot-web` એ એક અલગ પ્રદાતા છે.

> **વેબ કૂકી પ્રદાતાઓ માટે નવા છો?**
>
> વાંચો**`docs/getting-started/WEB-COOKIE-GUIDE.md`** આ પ્રદાતા-વિશિષ્ટ માર્ગદર્શિકાને અનુસરતા પહેલા સામાન્ય સેટઅપ પ્રક્રિયા, પ્રમાણીકરણ માર્ગદર્શન, મર્યાદાઓ અને મુશ્કેલીનિવારણ માટે.
>
> **લેગસી આયાત માટે:** આ પ્રદાતા માટે ઓળખપત્ર છે** કૂકી નથી** . `m365.cloud.microsoft` માંથી કૂકીઝની નકલ કરશો નહીં. ઓળખપત્ર એ WebSocket URL ક્વેરી પેરામીટર અને પાથ સેગમેન્ટ છે, બંને DevTools નેટવર્ક ટૅબમાંથી વાંચવામાં આવે છે.

## પૂર્વજરૂરીયાતો

- Microsoft 365 એકાઉન્ટ `m365.cloud.microsoft/chat` પર Copilot ની ઍક્સેસ સાથે
- DevTools WebSocket નિરીક્ષણ માટે ક્રોમિયમ-આધારિત બ્રાઉઝર (ક્રોમ, એજ)
- તે એકાઉન્ટ પર વિનંતી કરેલ મોડેલની ઍક્સેસ; ભાડૂત અને લાયસન્સ દ્વારા ઉપલબ્ધતા બદલાય છે

## મૂળ સાઇન-ઇન (કામ અથવા શાળા એકાઉન્ટ્સ)

પસંદ કરો**Microsoft 365 Copilot → કનેક્ટ કરો** અને સાઇન-ઇન પ્રયાસ તૈયાર કરો. ડેશબોર્ડ PKCE સાથે અધિકૃતતા-કોડ પ્રવાહનો ઉપયોગ કરે છે; તે તમારા Microsoft પાસવર્ડ અથવા MFA કોડ માટે પૂછતું નથી.

1. ખોલો એ** ખાલી બ્રાઉઝર ટેબ** , પછી ખોલો**DevTools → નેટવર્ક** અને સક્ષમ કરો** લોગ સાચવો** . Microsoft પર નેવિગેટ કરતા પહેલા આ કરો : Windows SSO તરત જ સમાપ્ત થઈ શકે છે.
2. કનેક્શન ડાયલોગ દ્વારા દર્શાવેલ અધિકૃતતા URL ની નકલ કરો અને તે તૈયાર કરેલ ટેબમાં નેવિગેટ કરો. જો વિનંતી કરવામાં આવે તો Microsoft ની એકાઉન્ટ પસંદગી અથવા MFA પૂર્ણ કરો.
3. સાચવેલ નેટવર્ક લોગમાં, `https://login.microsoftonline.com/common/oauth2/nativeclient` ની વિનંતી શોધો અને તેની સંપૂર્ણ નકલ કરો** URL વિનંતી કરો** .
4. તે URL કનેક્શન ડાયલોગમાં પેસ્ટ કરો અને કનેક્ટ કરો. કાચો કોડ અથવા અંતિમ `wrongplace` એડ્રેસ-બાર URL પેસ્ટ કરશો નહીં : જરૂરી કૉલબેક એક ક્ષણિક નેવિગેશન છે.

દરેક પ્રયાસ દસ મિનિટ પછી સમાપ્ત થાય છે અને માત્ર એક જ વાર ઉપયોગ કરી શકાય છે. કોડની આપલે કરતા પહેલા સર્વર તેની સ્થિતિ, PKCE વેરિફાયર અને પુનઃપ્રમાણીકરણ લક્ષ્યને તપાસે છે. સમાપ્તિ અથવા વિનિમય નિષ્ફળતા પછી, નવો પ્રયાસ શરૂ કરો. એક પ્રયાસ સર્વર પુનઃપ્રારંભ ટકી શકતો નથી.

ટોકન્સ હાલના કનેક્શન ઓળખપત્ર સ્ટોર અને રિફ્રેશ પાથનો ઉપયોગ કરે છે. કનેક્શનને ફરીથી પ્રમાણિત કરવા માટે સમાન Microsoft tenant/object ઓળખની જરૂર છે, માત્ર સમાન ઇમેઇલની જ નહીં. તે ઓપરેટર naming/settings સાચવે છે અને અપ્રચલિત આયાતી ઓળખપત્રોને બદલે છે. મૂળ સાઇન-ઇન work/school એકાઉન્ટ્સ માટે છે; લેગસી આયાત પાથ હાલના કનેક્શન્સ અને સપોર્ટેડ ટાયર રૂપરેખાંકનો માટે ઉપલબ્ધ રહે છે.

સંપૂર્ણ કૉલબેક URL એ એક વખતનું ઓળખપત્ર છે. સ્ક્રીનશૉટ્સ, લૉગ્સ, સપોર્ટ સંદેશાઓ અથવા કમિટ્સમાં તેને ક્યારેય શામેલ કરશો નહીં. આ પ્રવાહ સર્વર પર બ્રાઉઝર ખોલતો નથી, તમારા બ્રાઉઝર ઇતિહાસનું નિરીક્ષણ કરતું નથી અથવા સ્થાનિક કૉલબેક સર્વર શરૂ કરતું નથી.

## ઓળખપત્ર કેપ્ચર (WebSocket પદ્ધતિ)

1. `https://m365.cloud.microsoft/chat` પર સાઇન ઇન કરો અને વાતચીત શરૂ કરો.
2. ખોલો**DevTools → નેટવર્ક** .
3. દ્વારા ફિલ્ટર કરો**WS** (WebSocket)
4. Chathub WebSocket કનેક્શન પર ક્લિક કરો. `wss://substrate.office.com/m365Copilot/Chathub/` થી શરૂ થતા URL માટે જુઓ.
5. તેના પરથી** URL વિનંતી કરો** , નકલ:
   - `access_token` ક્વેરી પેરામીટર મૂલ્ય (એક અલ્પજીવી JWT).
   - `/Chathub/` પછી ચથુબ પાથ સેગમેન્ટ (દા.ત. `<oid>@<tenant>`).

સંપૂર્ણ URL નું સ્વરૂપ છે:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute માં, પસંદ કરો**Microsoft 365 Copilot** , લેગસી API-key/import વિકલ્પ પસંદ કરો અને ફોર્મેટમાં ઓળખપત્ર પેસ્ટ કરો:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. ક્લિક કરો** ટેસ્ટ કનેક્શન** અને** સાચવો** .

## ઓળખપત્ર કેપ્ચર (HAR આયાત)

WebSocket URL માંથી મેન્યુઅલી વેલ્યુ કૉપિ કરવાને બદલે, તમે DevTools HAR ફાઇલ નિકાસ કરી શકો છો:

1. ખોલો**DevTools → નેટવર્ક** .
2. Microsoft 365 Copilot વાતચીત શરૂ કરો અથવા ચાલુ રાખો (આ WebSocket કનેક્શનને ટ્રિગર કરે છે).
3. નેટવર્ક પેનલમાં જમણું-ક્લિક કરો અને પસંદ કરો** બધાને સામગ્રી સાથે HAR તરીકે સાચવો** .
4. OmniRoute માં, ઉપયોગ કરો** .har ફાઇલ આયાત કરો** પ્રદાતા કનેક્શન સંવાદ પરનું બટન.

OmniRoute ચથબ WebSocket URL માટે HAR ને સ્કેન કરે છે, `access_token` અને `chathubPath` ને બહાર કાઢે છે, અને ઓળખપત્ર ક્ષેત્રોને આપમેળે ભરે છે. HAR આયાત JWT સમાપ્તિને ડીકોડ કરે છે અને બાકીના ટોકન જીવનકાળ દર્શાવે છે.

> **વાસ્તવિક HAR નિકાસ, એક્સેસ ટોકન અથવા રીફ્રેશ ટોકન ક્યારેય ન કરો.** પરીક્ષણ અને દસ્તાવેજીકરણ મૂલ્યો હંમેશા પ્લેસહોલ્ડર હોવા જોઈએ.

## ટોકન આજીવન અને તાજું કરો

`access_token` અલ્પજીવી છે (સામાન્ય રીતે**~ 75 મિનિટ** ). ઉપયોગ કરી શકાય તેવા રીફ્રેશ ટોકન વિના, તમારે સમાપ્તિ પછી ઓળખપત્ર ફરીથી મેળવવું આવશ્યક છે.

### `refreshToken` સાથે સ્વચાલિત તાજું

Microsoft 365 પ્રદાતાઓમાં** કનેક્શન ઉમેરો** અથવા** કનેક્શન સંપાદિત કરો** સંવાદ, ખોલો** અદ્યતન સેટિંગ્સ → રીફ્રેશ ટોકન (વૈકલ્પિક)** . `substrate.office.com/sydney` સ્કોપ માટે Microsoft OAuth રિફ્રેશ ટોકન પેસ્ટ કરો અને સાચવો. ઇનપુટ માસ્ક કરેલ છે અને સંગ્રહિત ટોકન સાથે ક્યારેય પ્રીફિલ કરવામાં આવતું નથી. સંપાદિત કરતી વખતે, વર્તમાન ટોકન રાખવા માટે તેને ખાલી છોડી દો; તેને બદલવા માટે નવું ટોકન પેસ્ટ કરો.

જ્યારે Microsoft એક પરત કરે છે ત્યારે મૂળ સાઇન-ઇન રિફ્રેશ ટોકન મેળવે છે. લેગસી આયાત માટે, હાલની સુસંગત Microsoft અધિકૃતતા-કોડ ગ્રાન્ટનો ઉપયોગ કરો; આ પ્રદાતા ઉપકરણ-કોડ પ્રવાહનો અમલ અથવા વચન આપતું નથી. રિફ્રેશ ટોકન રૂપરેખાંકિત સાથે, OmniRoute વિનંતી કરતા પહેલા `access_token` ને તપાસે છે અને જ્યારે તેને તાજું કરવાની જરૂર હોય ત્યારે જ તેને રિફ્રેશ કરે છે. સફળ રીફ્રેશ પણ ફેરવેલ રીફ્રેશ ટોકનને ચાલુ રાખે છે, જ્યારે રીફ્રેશ ટોકન માન્ય રહે છે ત્યારે મેન્યુઅલ રી-કેપ્ચર ટાળે છે.

જો `refreshToken` સેટ કરેલ ન હોય, તો તમારે દરેક સમાપ્તિ પછી WebSocket ઓળખપત્રને મેન્યુઅલી ફરીથી કેપ્ચર કરવું આવશ્યક છે.

### સ્તરની પસંદગી

| ટાયર         | ઉપનામ      | સપાટી                 |
| ------------ | ---------- | --------------------- |
| `individual` | _(મૂળભૂત)_ | ઉપભોક્તા M365 Copilot |
| `edu`        | `included` | શિક્ષણ M365 Copilot   |
| `enterprise` | `work`     | કામ માટે M365 Copilot |

ટાયર સેટ કરો** અદ્યતન સેટિંગ્સ → Copilot ટાયર** . મૂળ સાઇન-ઇન તેને સેટ કરતું નથી, તેથી કાર્ય ખાતાએ `enterprise` (ઉર્ફે `work`) અને શિક્ષણ ખાતું `edu` પસંદ કરવું આવશ્યક છે, જ્યારે દસ્તાવેજીકૃત મોડલ IDs ઉપયોગ કરવામાં આવે છે: તે પોતાનો સ્વર, દૃશ્ય અને લાયસન્સ પ્રકાર પસંદ કરે છે, પરંતુ એજન્ટ અને વિનંતી વિકલ્પો હજી પણ ટાયરમાંથી આવે છે, અને વ્યક્તિગત ડિફોલ્ટ્સ વર્ક ટેનન્ટ પર નિષ્ફળ થઈ શકે છે. ટાયર બદલવાથી મોડલ લાઇસન્સ મળતું નથી. સ્પષ્ટ અદ્યતન પ્રોટોકોલ ઓવરરાઇડ્સ અગ્રતા લે છે અને જ્યારે તમે આવશ્યક વાયર મૂલ્યો જાણતા હોવ ત્યારે જ તેનો ઉપયોગ થવો જોઈએ.

## મોડલ્સ અને રૂટીંગ

મૂળ સૂચિમાં તમામ દસ્તાવેજીકૃત સ્ટેન્ડઅલોન IDs વત્તા ચાર મૂળ મૂળ IDs સમાવેશ થાય છે. કેટલોગ સ્ટેટિક અને એકાઉન્ટ-સ્વતંત્ર છે, એકાઉન્ટ એન્ટાઇટલમેન્ટ પ્રોબ નથી: પેઇડ રૂટ્સ અને સુસંગતતા ઉપનામો સૂચિબદ્ધ રહે છે, જ્યારે કનેક્ટેડ એકાઉન્ટ તેનો ઉપયોગ કરી શકતું નથી. મોડલ ડિસ્પ્લે લેબલ્સ પ્રદાતાનું નામ અને પ્રતિ-મોડલ ઉપલબ્ધતા બોઈલરપ્લેટને છોડી દે છે; પ્રદાતા રહે છે**Microsoft 365 Copilot** . લેબલ્સ ચિહ્નિત** ઉપનામ** અથવા** વારસો** તેમના હાલના ઓળખકર્તાઓ અને પ્રોટોકોલ મેપિંગ્સ જાળવી રાખો, ઐતિહાસિક મોડલ સંસ્કરણની ગેરંટી નહીં. એકલ પ્રોક્સી** /મોડલ્સમાંથી આયાત કરો** સૂચનાઓ આ મૂળ WebSocket પ્રદાતાને લાગુ પડતી નથી.

| મોડેલ પરિવાર      | પ્રમાણભૂત IDs                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| આપોઆપ             | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| અગાઉ GPT          | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude સોનેટ      | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude ઓપસ        | `claude-opus`, `claude-opus-4.8`                                                                 |

`auto`, `quick`, `think-deeper`, અને સંસ્કરણ ઉપનામો જેવા ઉપનામો પણ નોંધાયેલા છે. વર્તમાન `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` અને `copilot-m365-gpt-5-5-chat` માન્ય રહે છે. દસ્તાવેજીકૃત IDs ને પ્રદાતા ઉપસર્ગની જરૂર છે (`copilot-m365-web/claude-opus` અથવા `m365copilot/claude-opus`): ઘણા સામાન્ય શબ્દો અથવા અન્ય વિક્રેતાઓના મોડલ નામો છે, તેથી એકદમ `claude-opus` આ પ્રદાતા વિના કરે છે તેમ રૂટીંગ ચાલુ રાખે છે. નોંધણી એ વચન નથી કે Microsoft તે મોડેલને દરેક ખાતામાં સેવા આપે છે. સ્ટેન્ડઅલોન IDs પબ્લિક [પ્રોટોકોલ કેટલોગ](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) (નિકાસ કરેલ મોડલ-ટુ-ટોન મેપ અને તેના મોડલ-જાગૃત દૃશ્ય મેટાડેટા) ને અનુસરે છે. તમામ મૂળ પ્રોફાઇલ્સ `availability: "unverified"` જાળવી રાખે છે; કેટલોગમાં સમાવેશ સફળ એકાઉન્ટ ટેસ્ટ નથી.

- સ્પષ્ટ મોડેલ લાઇસન્સ ઇનકાર પરત કરે છે** 403** `m365_model_not_licensed`, 502 નહીં. connection/model ની જોડીને રાઉટીંગ લોક કરે છે, કનેક્શન પર લાઇસન્સવાળા મોડલ્સને વાપરી શકાય તેવું છોડી દે છે.
- `InvalidCopilotLicense` એ એકાઉન્ટ-લેવલ લાયસન્સ ઇનકાર છે, જે અલગથી `m365_account_not_licensed` તરીકે જાણ કરવામાં આવે છે.
- પ્રતિ-વપરાશકર્તા થ્રોટલ પરત કરે છે** 429** `m365_throttled` અને જોડાણને ઠંડુ કરે છે. પ્રાધાન્યતા-એક્સેસ થાક વળતર** 429** `priority_access_exhausted` અને મોડેલ-સ્કોપ્ડ છે. `errorCode: "ReasoningTurnExhausted"` વળતર સાથે `OutOfCredits` નું પરિણામ** 429** તેના બદલે `reasoning_turns_exhausted`, મોડલ-સ્કોપ્ડ પણ, રીસેટ સમયનો દાવો કર્યો નથી. એક વર્ક ભાડૂતને "થિંક ડીપર" ટોનને કેપ કરવા માટે જાણ કરવામાં આવી હતી જ્યારે ઝડપી ટોન સેવા આપતા હતા; તે અવકાશ એ ઉપભોક્તા અવલોકન છે, આ ભંડાર દ્વારા પુનઃઉત્પાદિત થયેલ વસ્તુ નથી. આથી રૂટીંગ એ જ કૂલડાઉન માટે તે કનેક્શન પર રોટેશનમાંથી `gpt-5.5` અને `gpt-5.6` ના અન્ય દસ્તાવેજીકૃત થિંક ડીપર મોડલ્સને પણ લઈ જાય છે, અને ક્વિક ટોન અને દરેક અન્ય નિષ્ફળતાને તેના પોતાના મોડેલ પર છોડી દે છે. પૂરા પાડવામાં આવેલ ફરીથી પ્રયાસ સંકેતો સાચવેલ છે; ગુમ થયેલ રીસેટની જાહેરાત જાણીતા રીસેટ સમય તરીકે કરવામાં આવતી નથી.
- Copilot સલામતી ઇનકાર (`Disengaged`) પરત કરે છે** 400** `provider_safety_rejection`, વહેંચાયેલ પ્રદાતા સલામતી-સ્ટોપ લેબલ. તે કનેક્શનના સ્વાસ્થ્ય સામે ક્યારેય ગણાતું નથી, ક્લાયન્ટ SDKs 400નો ફરીથી પ્રયાસ કરતું નથી, અને `PROVIDER_SAFETY_STOPS_TERMINAL` સક્ષમ કોમ્બો રૂટીંગ સાથે અન્ય લક્ષ્ય સામે વિનંતીને ફરીથી ચલાવવાને બદલે ત્યાં અટકી જાય છે.
- એક કનેક્શન પરની વિનંતીઓ વર્તમાન એકાઉન્ટ સેમાફોર દ્વારા ક્રમાંકિત કરવામાં આવે છે. સમાંતર પેનલને બદલે પ્રાધાન્યતા ફોલબેકને પ્રાધાન્ય આપો; સીરીયલાઇઝેશન જ Microsoft ની વાતચીત-દર મર્યાદાને દૂર કરતું નથી.

## વર્તન અને મર્યાદાઓની વિનંતી કરો

- સાધનો છે** પ્રોમ્પ્ટ-એમ્યુલેટેડ** , નેટીવ Microsoft ફંક્શન કોલ્સ નથી. ટૂલ-સક્ષમ વિનંતી એક બફર જનરેશનનો ઉપયોગ કરે છે; તે બીજી પેઢીના સાધનો પસંદ કરવામાં ખર્ચ કરતું નથી. માન્ય સમર્થિત દલીલ આકારો સાથે માત્ર જાહેર કરેલ સાધનો જ કૉલ તરીકે પરત કરવામાં આવે છે.
- એક જ પાછળના ઉદાહરણ સાથેનો લાંબો સંરચિત જવાબ ગદ્ય તરીકે સાચવેલ છે. આ એક સંશોધનાત્મક છે, ઉદ્દેશ્યનો પુરાવો નથી; એપ્લિકેશનોએ હજુ પણ તેમની પોતાની ટૂલ પરવાનગીઓ લાગુ કરવી પડશે.
- ઇમેજ ઇનપુટ વેબ ક્લાયંટ તેને મોકલે છે તે રીતે કાર્ય કરે છે. દરેક ઇમેજ ભાગ (ડેટા URL તરીકે`image_url` અથવા જાહેર HTTPS URL, અથવા પ્રતિસાદ `input_image`) ચેટ ટોકન સાથે ટર્નની વાતચીતમાં `/m365Copilot/UploadFile` પર અપલોડ કરવામાં આવે છે, અને સંદેશ `ImageFile` એનોટેશન સાથે તેના તરફ નિર્દેશ કરે છે; ટેક્સ્ટ જ્યાં તે બેઠું છે તે ચિહ્નિત કરે છે (`[image 1]`, …). એક તાજી વાર્તાલાપ ઇતિહાસની દરેક છબીને અપલોડ કરે છે, એક ચાલુ રહેલ માત્ર નવા સંદેશાની છબીઓ. વધુમાં વધુ 10 PNG, JPEG, GIF અથવા WebP ઇમેજ દરેક 10 MiB સુધી (પ્રતિ વિનંતી 40 MiB ); ફોર્મેટ બાઇટ્સમાંથી વાંચવામાં આવે છે. HTTPS URLs ફક્ત-જાહેર, DNS-પિન કરેલા રિમોટ ઇમેજ ગાર્ડ દ્વારા મેળવવામાં આવે છે. નિષ્ફળ અપલોડ વિનંતીને નિષ્ફળ કરે છે (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` અથવા `m365_image_invalid`); આપેલી છબી વિના વળાંક ક્યારેય આગળ વધતો નથી. અન્ય નોન-ટેક્સ્ટ ભાગો (ઓડિયો, ફાઇલો) સ્પષ્ટપણે નકારી કાઢવામાં આવે છે, શાંતિથી છોડવામાં આવતા નથી.
- ફોલો-અપ વિનંતી એ જ અપસ્ટ્રીમ વાતચીત ચાલુ રાખે છે અને પહેલાના જવાબ પછી જ સંદેશા મોકલે છે. તે જવાબને બરાબર લંબાવવો જોઈએ: સમાન જોડાણ, મોડેલ પ્રોફાઇલ અને ટૂલ સેટ; એક અપરિવર્તિત ઇતિહાસ (દરેક સંદેશ પર sha256 સાંકળ); અને જવાબના ટૂલ-કોલ આઈડી અથવા તેનો ટેક્સ્ટ વ્હાઇટસ્પેસ સુધી. બીજું કંઈપણ (એક સંપાદિત ઇતિહાસ, સમાન પ્રથમ સંદેશ સાથેનું બીજું સત્ર, એક અલગ જવાબ, 30 મિનિટ માટે વાતચીત નિષ્ક્રિય અથવા Copilot ની 600-સંદેશા મર્યાદાની નજીક, id વગરનું જોડાણ) સમગ્ર ઇતિહાસ સાથે નવી વાતચીત શરૂ કરે છે. નિષ્ફળ વળાંક ક્યારેય ફરી શરૂ થતો નથી, અને તાજી વાતચીતમાં એકવાર સામગ્રી-રહિત `InternalError` ફરીથી મોકલવામાં આવે છે (** 502** `m365_internal_error` જો તે ફરીથી નિષ્ફળ જાય તો). ચાલુ રાખવાની પ્રક્રિયા મેમરીમાં રાખવામાં આવે છે: પુનઃપ્રારંભ કરવાથી તાજી વાતચીત શરૂ થાય છે.
- દરેક વળાંક Copilot ની અસ્થાયી ચેટ (`disableMemory=1`) માં ચાલે છે : વાર્તાલાપ ચાલે ત્યારે તેનો સંદર્ભ રાખે છે અને એકાઉન્ટના ચેટ ઇતિહાસમાં ક્યારેય દેખાતો નથી. મોડલ ટેસ્ટ, ટેસ્ટ ઓલ અને કોમ્બો ટેસ્ટ તેથી વાતચીતને પાછળ રાખ્યા વિના આ પ્રદાતાની તપાસ કરી શકે છે.
- વળાંકમાં 120-સેકન્ડની નિષ્ક્રિય સમયમર્યાદા અને બાઉન્ડેડ એકંદર સમયમર્યાદા હોય છે. માત્ર-અંતિમ જવાબો, પ્રોગ્રેસ ફિલ્ટરિંગ અને કેન્સલેશન નેટીવ transport/composer. દ્વારા હેન્ડલ કરવામાં આવે છે
- વેબ આધારિત જવાબો તેમના સ્ત્રોતો રાખે છે. Copilot ખાનગી-ઉપયોગ નિયંત્રણ અક્ષરો સાથે અવતરણ ઇનલાઇન ચિહ્નિત કરે છે અને સ્ત્રોતોને `references` તરીકે મોકલે છે; દરેક માર્કર એક ક્રમાંકિત માર્કડાઉન લિંક બની જાય છે (`[1](https://…)`, અથવા એકદમ URL જ્યારે Copilot માર્કરનો લિંક લક્ષ્ય તરીકે ઉપયોગ કરે છે) મેચિંગ `url_citation` એનોટેશન સાથે (`message.annotations`, અથવા `delta.annotations` જે લિંકને વહન કરે છે). એક સ્ત્રોત કે જે ક્યારેય આવતું નથી તે છોડવામાં આવે છે, તેથી માર્કર ક્યારેય ક્લાયંટ સુધી પહોંચતા નથી. સ્ટ્રીમિંગ કરતી વખતે, ટાંકણા પછીનો ટેક્સ્ટ તેનો સ્રોત આવે ત્યાં સુધી રાહ જુએ છે.
- Copilot નો તર્ક સારાંશ (`ChainOfThoughtSummary`), જ્યારે મોડેલ એક મોકલે છે, તે `reasoning_content` તરીકે પરત કરવામાં આવે છે, જવાબના ભાગ રૂપે ક્યારેય નહીં. એક સારાંશ જે ફરીથી લખે છે તે વળાંકને નિષ્ફળ કર્યા વિના સ્ટ્રીમિંગ બંધ કરે છે.
- કોઈપણ સામગ્રી પહેલાં, જ્યારે સ્ટ્રીમિંગની વિનંતી કરવામાં આવી હોય ત્યારે પણ licence/throttle નિષ્ફળતાઓ HTTP 403/429 જાળવી રાખે છે. સામગ્રી શરૂ થયા પછી, નિષ્ફળતા એ SSE ભૂલની ઘટનાઓ છે, ક્યારેય સફળ સમાપ્ત થતી નથી. અપસ્ટ્રીમ પુનઃલેખન કે જે ફક્ત એપેન્ડ-ઓન્લી સ્ટ્રીમિંગ દ્વારા દર્શાવી શકાતું નથી તે સ્પષ્ટ સ્ટ્રીમ એરર છે; બિન-સ્ટ્રીમિંગ અને બફર કરેલ ટૂલ પ્રતિસાદો અંતિમ ટેક્સ્ટ જાળવી રાખે છે.
- જ્યારે Copilot પોતે કનેક્શનનો ઇનકાર કરે છે, ત્યારે તેનો જવાબ આ પ્રમાણે નોંધવામાં આવે છે:** 401** નકારેલ અથવા સમાપ્ત થયેલ સાઇન-ઇન માટે `m365_unauthorized` (ફરીથી સાઇન ઇન કરો),** 429** થ્રોટલિંગ માટે તેના `Retry-After` સાથે, અને હેન્ડશેક નિષ્ફળતા અન્યથા, સામાન્ય કનેક્શન નિષ્ફળતા ક્યારેય નહીં.

## છબી જનરેશન

`POST /v1/images/generations` સાથે `model: "copilot-m365-web/m365-copilot-image"` (ઉર્ફે `m365copilot/m365-copilot-image`) Copilot ના બિલ્ટ-ઇન ઈમેજ ટૂલ સાથે દોરે છે, જેમ વેબ ક્લાયન્ટ કરે છે. દરેક ઇમેજ એક Copilot ટર્ન છે: તે વેબ ક્લાયન્ટના ઇમેજ વિકલ્પ સેટ સાથે પસંદ કરે છે અને `GenerateGraphicArt` જાહેર કરે છે, અને ઇમેજ Microsoft ની ડિઝાઇનર સેવા પર આર્ટિફેક્ટ તરફ નિર્દેશ કરતી પ્રોગ્રેસ એન્ટ્રી પર આવે છે. તે આર્ટિફેક્ટ ચેટ ટોકનનો ઇનકાર કરે છે, તેથી OmniRoute કનેક્શનના રિફ્રેશ ટોકનમાંથી ડિઝાઇનર ટોકન મિન્ટ કરે છે અને બાઇટ્સ ડાઉનલોડ કરે છે; ટોકન ફક્ત `designerapp.officeapps.live.com` ને જ મોકલવામાં આવે છે.

- મૂળ સાઇન-ઇન કનેક્શનની જરૂર છે (તાજું ટોકન); પેસ્ટ કરેલ ટોકન નિષ્ફળ જાય છે** 400** કોઈપણ વળાંક પસાર થાય તે પહેલાં.
- `n` 1-4 છે, દરેક એક વળાંક. `size` માત્ર ઓરિએન્ટેશનનું સંચાલન કરે છે (વિશાળ, ઊંચું અથવા ચોરસ), જે Copilot પ્રોમ્પ્ટમાંથી વાંચે છે; Copilot રેન્ડર કદ પસંદ કરે છે.
- છબીઓ ઇનલાઇન પરત કરવામાં આવે છે: `b64_json` મૂળભૂત રીતે, `response_format: "url"` માટે ડેટા URL.
- જનરેટ કરેલી છબીઓ ચેટથી અલગ, નાના દૈનિક બજેટ પર દોરવામાં આવે છે. જ્યારે તેનો ઉપયોગ થાય છે ત્યારે વિનંતી નિષ્ફળ જાય છે** 429** . એક વળાંક જે છબી વિના જવાબ આપે છે તે નિષ્ફળ જાય છે** 502** (અથવા** 400** /** 503** જ્યારે Copilot નું લખાણ ઇનકાર અથવા ક્ષમતા સમસ્યા તરીકે વાંચે છે); સંદેશ કહે છે કે જે.

## સુરક્ષા મોડેલ

- **બિનસત્તાવાર એકીકરણ.** આ પ્રદાતા BizChat WebSocket પ્રોટોકોલને રિવર્સ-એન્જિનિયર કરે છે. જ્યારે Microsoft એન્ડપોઇન્ટ બદલે છે ત્યારે તે નોટિસ વિના તૂટી શકે છે.
- `subscriptionRisk: true` ધ્વજ પ્રતિબિંબિત કરે છે કે એકીકરણ બિનદસ્તાવેજીકૃત અંતિમ બિંદુ પર આધાર રાખે છે. એકાઉન્ટ પ્રતિબંધો શક્ય છે પરંતુ પુષ્ટિ નથી.
- એક્સેસ ટોકન અલ્પજીવી JWT છે. તેને પાસવર્ડની જેમ માનો: તેને પ્રતિબદ્ધ ન કરો, લોગ કરો અથવા તેને શેર કરશો નહીં.
- રિફ્રેશ ટોકન Microsoft 365 સપાટી પર ચાલુ ઍક્સેસ આપે છે. તેને API કી જેવી જ કાળજીથી સ્ટોર કરો.

- રૂપરેખાંકિત કરો** અદ્યતન સેટિંગ્સ → રીફ્રેશ ટોકન (વૈકલ્પિક)** આપોઆપ રીફ્રેશ માટે કનેક્શન ઉમેરો અથવા સંપાદિત કરો સંવાદમાં.

### ટેસ્ટ કનેક્શન પાસ થાય છે પરંતુ ચેટ 401 પરત કરે છે

સાથે બનાવેલ જોડાણ માટે** Microsoft સાથે સાઇન ઇન કરો** , ટેસ્ટ કનેક્શન એક્સેસ ટોકનની એક્સપાયરી તપાસે છે અને સ્ટોર કરેલા રિફ્રેશ ટોકન સાથે એક્સપાયર થયેલ ટોકન રિન્યૂ કરે છે, તેથી પાસ થનારી ટેસ્ટ પણ સાબિત કરે છે કે રિફ્રેશ ટોકન હજુ પણ કામ કરે છે.

પેસ્ટ કરેલ ઓળખપત્ર માટે, ટેસ્ટ કનેક્શન ઓળખપત્રના આકારને તપાસે છે અને, જ્યારે ટોકન સમાપ્ત થાય છે, ત્યારે પ્રદાતા જે ટોકનનો ઉપયોગ કરશે તે સમાપ્ત થયું નથી (કનેક્શનનું સંગ્રહિત ટોકન વાસી પેસ્ટ જીતે છે; રીફ્રેશ ટોકન નવીનીકરણીય તરીકે ગણવામાં આવે છે). એક ટોકન કે જે તેની સમયસીમા સમાપ્ત થાય તે પહેલા રદ કરવામાં આવે છે તે હજુ પણ પરીક્ષણ પાસ કરે છે; ચેટ પછી પરત આવે છે** 401** `m365_unauthorized` ઉપયોગ કરો** Microsoft સાથે સાઇન ઇન કરો** ફરીથી, અથવા એક નવું ઓળખપત્ર ફરીથી મેળવો.

### Copilot પ્રદાતા સૂચિમાં દેખાતું નથી

ખાતરી કરો કે માં `copilot-m365-web` સક્ષમ છે** ડેશબોર્ડ → પ્રદાતાઓ** . પ્રદાતા કેટલાક સ્તરોમાં મૂળભૂત રીતે છુપાયેલ હોઈ શકે છે.
