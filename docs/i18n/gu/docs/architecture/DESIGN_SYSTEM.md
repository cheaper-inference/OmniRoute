> **સ્થિતિ:** ડેશબોર્ડ પર બનેલ છે**Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), વર્કસ્પેસ `packages/ui-kit` (`@omniroute/ui-kit`; અપસ્ટ્રીમ સ્નેપશોટ `packages/ui-kit/UPSTREAM.md` માં પિન કરેલ છે અને `npm run check:ui-kit-snapshot` દ્વારા સુરક્ષિત છે) તરીકે આ ભંડારમાં સમાવિષ્ટ છે. પ્રકાશ કેનોનિકલ થીમ છે; મૂળભૂત પસંદગી `system` છે. ડિફૉલ્ટ પેલેટ કીટની છે**Editions** દેખાવ (ગરમ પેપર ન્યુટ્રલ્સ અને કોપર એક્સેન્ટ `#e5ac82`, `packages/ui-kit/src/ci-editions.css`); સેટિંગ્સ → દેખાવ → કલર પેલેટ ઓફર કરે છે**Classic** , ચૂનો ઉચ્ચાર સાથે કીટના આધાર ટોકન્સ. Switzer એ UI અને ડિસ્પ્લે ટેક્સ્ટ (`--ci-font-ui`; `--ci-font-display` અને `--ci-font-mono` રિઝોલ્યુશન) માટેનું પ્રાથમિક કુટુંબ છે, જે કીટ દ્વારા જ સ્વ-હોસ્ટ કરવામાં આવે છે (`packages/ui-kit/src/ci-fonts.css`, `ci-tokens.css` દ્વારા આયાત કરેલ). દરેક આઇકન એક Lucide glyph છે.
>
> Inter એ Switzer માંથી ગુમ થયેલ ગ્લિફ્સ માટે ફોલબેક છે; સિસ્ટમ મોનોસ્પેસ સ્ટેક `--ci-font-code` પર `--font-mono` નકશા.
>
> `src/app/globals.css` ગ્લિફ દીઠ ફોલબેક ફોન્ટ પસંદ કરે છે જ્યારે `Switzer` માં ગ્લિફનો અભાવ હોય છે: સિરિલિક, ગ્રીક અને વિયેતનામીસ માટે `Inter`, અને માત્ર `html[dir="rtl"]` હેઠળ અરબી સ્ક્રિપ્ટ માટે `Vazirmatn`.

`src/app/globals.css`:

```css
:root,
.ci-theme {
  --ci-font-ui:
    "Switzer", "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif;
  --ci-font-code: ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace;
  --font-mono: var(--ci-font-code);
}
```

## 1. જ્યાં વસ્તુઓ રહે છે

- **કિટ.** `packages/ui-kit/src` એ `packages/ui-kit/UPSTREAM.md` માં પિન કરેલ કમીટ પર અપસ્ટ્રીમ `src/` ની બાઈટ-બદ-બાઈટ નકલ છે (જે લાયસન્સ અધિકૃતતા પણ રેકોર્ડ કરે છે); `PATCHES.md` સ્થાનિક પેચોની યાદી આપે છે. તે સ્ત્રોત તરીકે ઉપયોગમાં લેવાય છે, જેમાં કોઈ બિલ્ડ નથી: `next.config.mjs` તેને ટ્રાન્સપીલ કરે છે, અને `tsconfig.json` નકશા `@omniroute/ui-kit` → `packages/ui-kit/src` અને `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` (`vitest.config.ts` અને `vitest.mcp.config.ts` સમાન ઉપનામ ધરાવે છે). કિટ ઘટકને તેના સબપાથ દ્વારા આયાત કરો (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), ક્યારેય `@omniroute/ui-kit` બેરલ દ્વારા: બેરલ દરેક આયાતકારમાં દરેક ઘટક (તારીખ પીકર સહિત) ખેંચે છે. કીટ સ્ટાઈલશીટ `src/app/globals.css` (`@import "../../packages/ui-kit/src/ci-styles.css"`, સંપૂર્ણ શીટ: કોર `ci-ui.css` વત્તા દરેક પેટર્ન કુટુંબ) દ્વારા પ્રવેશે છે.
- **ટોકન્સ.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` ટોકન્સ જાહેર કરે છે; `src/app/globals.css` તેમને લેગસી OmniRoute નામો (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) સાથે જોડે છે, તેથી હાલની `var(--color-*)` રીડ અને Tailwind ઉપયોગિતાઓ કામ કરતી રહે છે. નવો કોડ Tailwind ઉપયોગિતાઓનો ઉપયોગ કરે છે (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) અથવા કિટ વર્ગો — ક્યારેય હેક્સ મૂલ્ય નથી (`tests/unit/design-kit-bridge.test.ts` પુલને લાગુ કરે છે). `text-primary` એ `--text-color-primary` દ્વારા `--color-primary-ink` ને ઉકેલે છે, તેથી પ્રાથમિક લખાણ વાંચી શકાય તેવું રહે છે જ્યારે `bg-primary`/`border-primary` ઉચ્ચાર સપાટી રાખે છે: Editions હેઠળ તે કિટનું `--ci-color-accent-active` છે (પ્રકાશમાં ઊંડા કોપર `#99562f`, અંધારામાં કોપર ઉચ્ચાર); Classic હેઠળ, પ્રકાશમાં lime-800 અને અંધારામાં ચૂનો ઉચ્ચાર. ચાર્ટ સિરીઝ `--color-chart-1` … `--color-chart-8` ઉપયોગ કરે છે, પ્રત્યેક ટેક્સ્ટ-સેફ `--color-chart-N-ink` અને અપારદર્શક `--color-chart-N-subtle` ચિપ ટિન્ટ સાથે, કિટ શ્રેણીના ક્રમમાં સોંપેલ છે (`ciChartSeriesOrder`).
- **થીમ્સ.** `<html className="ci-theme">` (`src/app/layout.tsx`) દસ્તાવેજને કીટ થીમમાં પસંદ કરે છે. પસંદગી `light`, `dark` અથવા `system` છે ( `src/shared/constants/appConfig.ts` માં`THEME_CONFIG.defaultTheme = "system"` ; `system` `prefers-color-scheme` ને અનુસરે છે). `src/store/themeStore.ts` માં `applyTheme()` ( `THEME_BOOT_SCRIPT` દ્વારા પ્રતિબિંબિત, `src/app/layout.tsx` માં ઇનલાઇન, જે હાઇડ્રેશન પહેલા ચાલે છે) `data-theme="dark"|"light"` સેટ કરે છે અને `<html>` પર `.dark` ક્લાસને એકસાથે ટૉગલ કરે છે. કીટનો ડાર્ક ટોકન સેટ `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`); OmniRoute ની પોતાની ડાર્ક ઓવરરાઇડ્સ ( `globals.css` માં `.dark` બ્લોક) અને `.dark` ક્લાસ પર લેગસી Tailwind `dark:` યુટિલિટીઝ કી. ત્યાં કોઈ ઉચ્ચારણ રંગ પ્રીસેટ્સ નથી: ઉચ્ચાર હંમેશા કીટમાંથી આવે છે, અને જ્યારે સ્ટોર લોડ થાય છે ત્યારે જૂની બિલ્ડમાંથી સતત પ્રીસેટ છોડવામાં આવે છે.
- **પૅલેટ્સ.** બે, બંને કીટમાંથી (`src/shared/constants/appearancePalette.ts`): `editions`, ડિફોલ્ટ અને `classic`. Editions એ `<html>` પર કીટનું `data-ci-appearance="editions"` લક્ષણ છે, જે `ci-editions.css` ( `ci-ui.css` દ્વારા આયાત કરેલું) `data-theme` સાથે જોડાય છે; Classic એ લક્ષણની ગેરહાજરી છે. રુટ લેઆઉટ સર્વર એટ્રિબ્યુટને રેન્ડર કરે છે, તેથી કોઈ પણ વસ્તુ સંગ્રહિત નથી (અથવા કોઈ JS નથી) સાથે મુલાકાતીને દરેક સપાટી પર — ડેશબોર્ડ, લૉગિન, `/status`, ભૂલ પૃષ્ઠો, `/docs` અને PWA પર Editions મળે છે. પસંદગી એ જ `theme` સ્ટોરમાં થીમની બાજુમાં રહે છે (`palette`, `setPalette()`, `src/store/themeStore.ts` માં `applyPalette()` ) અને `THEME_BOOT_SCRIPT` દ્વારા પેઇન્ટ પહેલાં લાગુ કરવામાં આવે છે (`src/shared/utils/themeBootScript.ts`, લેઆઉટના `<head>` માં ઇનલાઇન કરેલું), જે સંગ્રહિત પેલેટ `"classic"` હોય ત્યારે જ એટ્રિબ્યુટને દૂર કરે છે; `src/app/global-error.tsx`, રૂટ લેઆઉટની બહાર, તે જ સ્ટોરમાંથી લાગુ કરે છે. અન્ય કોઈપણ ઘટક પર `data-ci-appearance` નાખશો નહીં: કિટ તેની સાથે `html:root:has([data-ci-appearance="editions"])` સાથે મેળ ખાય છે, તેથી એક વંશજ આખા દસ્તાવેજને સ્વિચ કરશે. Editions `data-ci-editions-variant="landing"` વેરિઅન્ટ માર્કેટિંગ પૃષ્ઠો માટે છે, ડેશબોર્ડ માટે નહીં. બ્રાઉઝર ક્રોમ: સર્વર ડિફૉલ્ટ, Editions, `viewport.themeColor` ( `prefers-color-scheme` દીઠ એક ટૅગ) માં રેન્ડર કરે છે અને `src/shared/constants/pwaThemeColors.ts` માં વેબ મેનિફેસ્ટ — `PWA_THEME_COLORS`, Editions `--ci-color-background` નો એક અરીસો (`#f3f1e9` `tests/unit/pwa-theme-colors.test.ts` `#11120f` to `ci-editions.css` ), લાઇવ `<meta name="theme-color">` પછી સંગ્રહિત પેલેટ અને મોડને અનુસરે છે: `THEME_BOOT_SCRIPT` પેઇન્ટ કરતા પહેલા ટૅગ્સને ફરીથી લખે છે અને થીમ સ્ટોરની ક્રિયાઓ દરેક ફેરફાર પર તે કરે છે ( `src/shared/utils/themeColorMeta.ts` માં`resolveThemeColor()` / `applyThemeColor()`, કિટના `ciTokens` માંથી `CLASSIC_PAGE_BACKGROUND` વાંચવામાં આવે છે). એક સ્પષ્ટ light/dark થીમ દરેક ટેગને તે મોડ પર સેટ કરે છે; `system` યોજના દીઠ એક રંગ રાખે છે. મેનિફેસ્ટ Editions રહે છે : તે પસંદગી વિના, ઇન્સ્ટોલ દીઠ એકવાર મેળવવામાં આવે છે. મોનાકો તેના રંગોને ચકાસણીમાંથી વાંચે છે (`monacoKitTheme.ts`); Editions હેઠળ ચકાસણી રીડ રૂટ `data-theme` એક સિંક્રનસ પાસ માટે ફ્લિપ કરે છે, કારણ કે કિટ Editions light/dark રૂટમાંથી ઉકેલે છે.

## 4. એડેપ્ટર ઉમેરવો અથવા બદલવો

1. `src/shared/components/index.tsx` ની પબ્લિક API જાળવી રાખો: એક જ એક્સપોર્ટ નામો, ડિફોલ્ટ એક્સપોર્ટ્સ અને
   સ્વીકારાતા પ્રોપ્સ. એડેપ્ટરની અંદર લેગસી પ્રોપ્સને કિટ પર મેપ કરો (જુઓ `Button.tsx`: `VARIANT_TO_KIT`,
   `SIZE_TO_KIT`).
2. કિટને સબપાથ દ્વારા ઇમ્પોર્ટ કરો (`@omniroute/ui-kit/<component>`).
3. કિટની ખૂણતાઓ માટેના વર્કઅરાઉન્ડ એડેપ્ટરમાં રહે છે (અથવા જ્યારે ફિક્સ સ્ટાઇલ હોય ત્યારે `globals.css`
   `@layer components` માં), ક્યારેય `packages/ui-kit/src` માં નહીં.
4. `tests/unit/ui/adapters/<name>.test.tsx` ઉમેરો અથવા અપડેટ કરો. ઘણા કૉલર્સ ધરાવતા એડેપ્ટર માટે, ફેરફાર
   પહેલાં અને પછીનું રેન્ડર થયેલ માર્કઅપ સરખાવો — પેડિંગ અથવા રેપર ફેરફારો દરેક સ્ક્રીન પર ફેલાય છે.

## 5. કિટ અપડેટ કરવી

`npm run check:ui-kit-upstream` અપસ્ટ્રીમ રેપોના નવા `v*` ટેગ સાથે `packages/ui-kit/UPSTREAM.md` માં પિન કરેલા સંસ્કરણની તુલના કરે છે અને જ્યારે રીલીઝ બહાર હોય ત્યારે સિંક કમાન્ડ છાપે છે.

દૈનિક `UI Kit upstream watch` વર્કફ્લો (`.github/workflows/ui-kit-upstream-watch.yml`) એ જ ચેક ચલાવે છે. જ્યારે પિન પાછળ હોય છે, ત્યારે `scripts/ci/ui-kit-sync-pr.sh` એક સિંક PR સૌથી વધુ `release/vX.Y.Z` શાખા સામે, રોલિંગ બ્રાન્ચ `chore/ui-kit-sync-latest` પર ખુલ્લું રાખે છે. તે ક્યારેય મર્જ થતું નથી: દરેક કિટ રિલીઝને હજુ પણ સ્થાનિક VPS પર વિઝ્યુઅલ ચેકની જરૂર છે. જ્યારે નવી રીલીઝ બહાર આવે અને અન્યથા એકલી છોડી દેવામાં આવે ત્યારે શાખાનું પુનઃનિર્માણ કરવામાં આવે છે. હાથ વડે દબાણ કરાયેલ કમિટ સાથેનો ઓપન PR ઓવરરાઈટ થતો નથી, અને એવા વર્ઝન માટે PR કે જે જાળવણીકારે બંધ કરેલ અનમર્જ કરેલ હોય તે નવી રિલીઝ સુધી બંધ રહે છે.

જ્યારે કોઈ PR ખોલી શકાતું નથી (લક્ષ્ય પ્રકાશન સ્થિર છે, PR એ હાથથી દબાણ કર્યું છે, PR બંધ હતું, અથવા કોઈ PR ટોકન સેટ નથી) વર્કફ્લો એક ટ્રેકિંગ સમસ્યાને ખુલ્લી રાખે છે જે કહે છે કે શા માટે.

વર્કફ્લો બે રહસ્યોનો ઉપયોગ કરે છે:

- `secrets.UI_KIT_READ_TOKEN`: ખાનગી અપસ્ટ્રીમ રેપો માટે માત્ર વાંચવા માટેનું ટોકન. જ્યારે અપસ્ટ્રીમ ચેક ડેટા વાંચી શકતું નથી (કોઈ ટોકન નથી, ટોકન કે જે કામ કરવાનું બંધ કરે છે, અથવા GitHub અગમ્ય), તે `unknown` રિપોર્ટ કરે છે અને કોડ `0` સાથે બહાર નીકળે છે. વર્કફ્લો એક ચેતવણી લખે છે અને એક અલગ ટ્રેકિંગ સમસ્યાને ખુલ્લો રાખવાનો પ્રયાસ કરે છે; પાછળથી સફળ રન એક્સેસ રીટર્ન પછી તેને બંધ કરે છે. GitHub મુદ્દાની નિષ્ફળતા API કામને નિષ્ફળ કરે છે.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: સમાવિષ્ટો અને પુલ વિનંતીઓ લખવાની ઍક્સેસ સાથે આ ભંડાર પર એક સરસ ટોકન. જ્યારે સમર્પિત ટોકન ગોઠવેલું હોય ત્યારે જ આ વર્કફ્લો સિંક્રનાઇઝેશન PRs ખોલે છે અથવા અપડેટ કરે છે; તેના વિના, વર્કફ્લો શાખાને દબાણ કરે છે અને અહેવાલ આપે છે કે કોઈ PR ખોલવામાં આવ્યું ન હતું.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` તે કમિટ પર અપસ્ટ્રીમ `src/` નકલ કરે છે (`latest` = સૌથી નવું `v*` ટેગ) `packages/ui-kit/src` માં, સિંગલ મંજૂર ટ્રાન્સફોર્મેશન લાગુ કરે છે (તે સંબંધિત આયાતમાંથી `.js` પ્રત્યયને ડ્રોપ કરે છે), અને વર્કસ્પેસ વર્ઝનને `packages/ui-kit/package.json` અને `package-lock.json` માં અપસ્ટ્રીમમાં સેટ કરે છે. પછી: `git diff packages/ui-kit` ની સમીક્ષા કરો, બંને થીમમાં પ્રદાતાઓ, સેટિંગ્સ, કોમ્બોઝ, ઉપયોગ અને એન્ડપોઇન્ટ પર વિઝ્યુઅલ પાસ કરો, `npm run check:ui-kit-snapshot` અને `npm run test:vitest:ui` ચલાવો, અને અપસ્ટ્રીમ ચેન્જલોગ સાથે PR ખોલો.

- **પુરાવો.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` સ્થાનિક તપાસમાં ફાઇલ રેન્ડર કરે છે (`<img>` ટૅગ, નિયંત્રણવાળી `Content-Security-Policy` અને `image/svg+xml` પ્રતિસાદ), હળવી અને ઘેરી ફ્રેમ લે છે અને પૃષ્ઠની બાહ્ય ફોન્ટ વિનંતીઓ દર્શાવે છે; તેમની સંખ્યા 0 હોવી જ જોઈએ.

- **બજેટ.** દરેક ફાઇલ 200 KB કરતાં ઓછી (દરેક જૂનાપણાની કસોટી આની ખાતરી કરે છે); કોઈપણ README
  છબી માટે 500 KB ની સખત મર્યાદા છે (SVG સ્ટુડિયો વૅલિડેટરનો નિયમ).
- **સહિયારું લખાણ, ગણતરી gate માંથી.** દરેક જનરેટર પોતાની આકૃતિની કૉપી `*_COPY` કૉન્સ્ટન્ટમાં રાખે છે (અથવા લાઇવ કૅટલૉગમાંથી બનાવે છે), જે દોરવામાં આવેલા ટેક્સ્ટ અને આઉટલાઇનિંગ પગલાના ઇનપુટ બંને છે. કૅનોનિકલ આકૃતિઓ `<text>` નોડ્સમાં જ રહે છે (આઉટલાઇન થયા પછી અદૃશ્ય, `fill-opacity:0`), અને તેને `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) વાંચે છે; આકૃતિઓના સ્ટેલનેસ ટેસ્ટ્સ, જે વાંચનને ગેટ કરે છે, જનરેટ કરેલી ફાઇલ પર તેના વૅલિડેટર્સ પણ ચલાવે છે, તેથી કોડથી ભટકતી આકૃતિ ટેસ્ટ નિષ્ફળ બનાવે છે — જનરેટરમાંની સંખ્યા ક્યારેય સુધારશો નહીં, ગેટ જે સ્રોત વાંચે છે તેને સુધારો.
