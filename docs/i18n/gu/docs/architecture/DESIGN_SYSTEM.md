> workspace `packages/ui-kit` (`@omniroute/ui-kit`) તરીકે vendored કરવામાં આવ્યું છે; upstream snapshotને
> `packages/ui-kit/UPSTREAM.md`માં પિન કરવામાં આવ્યું છે અને `npm run check:ui-kit-snapshot` દ્વારા સુરક્ષિત રાખવામાં આવ્યું છે. લાઇટ એ પ્રમાણભૂત
> થીમ છે; ડિફૉલ્ટ પસંદગી `system` છે. ઍક્સેન્ટ Keak lime (`--ci-color-accent`) છે. Inter
> (અક્ષર-અંતર 0, `--ci-letter-spacing-ui`) એ UI font family છે, Instrument Serif માત્ર મોટા અને ઓછી ઘનતાવાળા
> display text (`.ci-dashboard-display`) માટે છે, અને IBM Plex Mono કોડ માટે છે — આ બધા
> `src/app/globals.css`ની શરૂઆતમાં રહેલા `@fontsource/*` imports દ્વારા self-host કરવામાં આવ્યા છે. દરેક icon Lucide glyph છે.

## 1. વસ્તુઓ ક્યાં આવેલી છે

- **કિટ.** `packages/ui-kit/src` એ `packages/ui-kit/UPSTREAM.md`માં પિન કરેલા કમિટ પરના અપસ્ટ્રીમ `src/`ની બાઇટ-દર-બાઇટ નકલ છે (જે લાઇસન્સ અધિકૃતતા પણ નોંધે છે); `PATCHES.md` સ્થાનિક પૅચોની યાદી આપે છે (કોઈ નથી). તેનો કોઈ બિલ્ડ વિના સોર્સ તરીકે ઉપયોગ થાય છે: `next.config.mjs` તેને ટ્રાન્સપાઇલ કરે છે અને `tsconfig.json` `@omniroute/ui-kit` → `packages/ui-kit/src` તથા `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` મેપ કરે છે (`vitest.config.ts` અને `vitest.mcp.config.ts`માં પણ એ જ એલિયાસ છે). કિટ કમ્પોનન્ટને તેના સબપાથ દ્વારા ઇમ્પોર્ટ કરો (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), `@omniroute/ui-kit` બેરલ મારફતે ક્યારેય નહીં: બેરલ દરેક કમ્પોનન્ટને (ડેટ પિકર સહિત) દરેક ઇમ્પોર્ટરમાં ખેંચી લાવે છે. કિટ સ્ટાઇલશીટ `src/app/globals.css` મારફતે પ્રવેશે છે (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **ટોકન્સ.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` ટોકન્સ જાહેર કરે છે; `src/app/globals.css` તેમને જૂનાં OmniRoute નામો (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) સાથે જોડે છે, જેથી હાલનાં `var(--color-*)` રીડ્સ અને Tailwind યુટિલિટીઝ કાર્યરત રહે. નવો કોડ Tailwind યુટિલિટીઝ (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) અથવા કિટ ક્લાસનો ઉપયોગ કરે છે — હેક્સ મૂલ્યનો ક્યારેય નહીં (`tests/unit/design-kit-bridge.test.ts` આ બ્રિજને લાગુ કરાવે છે). `text-primary`, `--text-color-primary` મારફતે `--color-primary-ink` તરીકે રિઝોલ્વ થાય છે (લાઇટમાં lime-800 અને ડાર્કમાં લાઇમ ઍક્સેન્ટ), જેથી પ્રાઇમરી ટેક્સ્ટ વાંચી શકાય તેવો રહે, જ્યારે `bg-primary`/`border-primary` લાઇમ સરફેસ જાળવી રાખે છે. ચાર્ટ શ્રેણીઓ `--color-chart-1` … `--color-chart-5`નો ઉપયોગ કરે છે.
- **થીમ્સ.** `<html className="ci-theme">` (`src/app/layout.tsx`) ડોક્યુમેન્ટને કિટ થીમમાં સામેલ કરે છે. પસંદગી `light`, `dark` અથવા `system` છે (`src/shared/constants/appConfig.ts`માં `THEME_CONFIG.defaultTheme = "system"`; `system`, `prefers-color-scheme`ને અનુસરે છે). `src/store/themeStore.ts`માંનું `applyTheme()` (`src/app/layout.tsx`ની ઇનલાઇન બુટસ્ટ્રૅપ સ્ક્રિપ્ટ પણ આ જ કાર્ય કરે છે, જે હાઇડ્રેશન પહેલાં ચાલે છે) `data-theme="dark"|"light"` સેટ કરે છે અને સાથે જ `<html>` પર `.dark` ક્લાસ ટૉગલ કરે છે. કિટનો ડાર્ક ટોકન સેટ `data-theme="dark"` પર આધારિત છે (`packages/ui-kit/src/ci-tokens.css`); OmniRouteના પોતાના ડાર્ક ઓવરરાઇડ્સ (`globals.css`માંનો `.dark` બ્લૉક) અને જૂની Tailwind `dark:` યુટિલિટીઝ `.dark` ક્લાસ પર આધારિત છે. ઍક્સેન્ટ કલર પ્રીસેટ્સ નથી: ઍક્સેન્ટ હંમેશાં કિટમાંથી આવે છે અને જૂના બિલ્ડમાંથી સાચવાયેલ પ્રીસેટ સ્ટોર લોડ થાય ત્યારે કાઢી નાખવામાં આવે છે.
- **કમ્પોનન્ટ્સ (અડૅપ્ટર્સ).** `src/shared/components/index.tsx` OmniRoute કમ્પોનન્ટ API (સમાન નામો, ડિફૉલ્ટ એક્સપોર્ટ્સ અને પ્રૉપ્સ) જાળવી રાખે છે અને તેની પાછળનાં પ્રિમિટિવ્સ કિટ ઉપરના અડૅપ્ટર્સ છે: ફૉર્મ્સ (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), ઓવરલેઝ અને પ્રતિસાદ (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`), માળખું (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) અને ટેબલ્સ (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). અડૅપ્ટર કિટ કમ્પોનન્ટને સબપાથ દ્વારા ઇમ્પોર્ટ કરે છે અને જૂના પ્રૉપ્સને તેના પર મેપ કરે છે — ઉદાહરણ તરીકે, `Button variant="primary"` એ કિટનું `default` બટન છે (`--ci-button-primary-*`: લાઇટમાં ઇન્વર્સ સરફેસ અને ડાર્કમાં તેના `--ci-color-accent-foreground` ઇંક સાથેનું ઍક્સેન્ટ), `danger` એ `destructive` છે અને `warning` એ `outline` ઉપરાંત `.ci-button--warning` એક્સ્ટેન્શન છે. `globals.css`ના અંતે (`@layer components`) આવેલા `.ci-button--warning` અને `.ci-badge[data-tone]` નિયમો કિટ ક્લાસ ઉપરનાં OmniRoute એક્સ્ટેન્શન્સ છે. `tests/unit/ui/adapters/*.test.tsx` દરેક અડૅપ્ટરને પિન કરે છે.
- **શેલ.** `src/app/(dashboard)/layout.tsx`, `DashboardLayout` રેન્ડર કરે છે, જે `src/shared/components/layouts/DashboardShell.tsx` રેન્ડર કરે છે: કિટ `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), સાથે `src/shared/components/Sidebar.tsx`માં OmniRouteનું નેવિગેશન લૉજિક. `#main-content` માટેની "કન્ટેન્ટ પર જાઓ" લિંક પ્રથમ ફોકસ કરી શકાય તેવું એલિમેન્ટ છે. `src/shared/components/Header.tsx`માં કિટ `SidebarTrigger` (શેલનું એકમાત્ર સાઇડબાર ટૉગલ), Keak `ProductSwitcher` અને કમાન્ડ-પૅલેટ ઓપનર છે; જ્યાં સુધી `#main-content`ની અંદર કોઈ કિટ `PageHeader` (`.ci-page-header`) માઉન્ટ થયેલું ન હોય ત્યાં સુધી જ તે રૂટ શીર્ષક બતાવે છે, જેથી પોતાનું `PageHeader` ધરાવતા પેજમાં માત્ર એક `h1` હોય. `src/shared/components/CommandPalette.tsx` એ કિટ `Dialog` છે.
- **આઇકન્સ.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) નામને (સ્ક્રીન્સ દ્વારા ઉપયોગમાં લેવાતી Material Symbols શબ્દાવલી) `ICON_MAP` (`src/shared/constants/iconMap.ts`) મારફતે Lucide ગ્લિફમાં રિઝોલ્વ કરે છે. Material Symbols ફૉન્ટ અને પૅકેજ દૂર થઈ ગયા છે: મેપમાંથી ગેરહાજર નામ ન્યુટ્રલ પ્લેસહોલ્ડર ગ્લિફ (`data-icon-missing="true"`) રેન્ડર કરે છે અને પ્રોડક્શનની બહાર કન્સોલ ચેતવણી લૉગ કરે છે. `npm run gen:icon-map` ઉપયોગમાં રહેલાં અને મેપમાંથી ગેરહાજર નામો પ્રિન્ટ કરે છે (`tests/unit/icon-map-coverage.test.ts` Lucide આઇકન વિનાના કોઈપણ નામ પર નિષ્ફળ થાય છે; `tests/unit/icon-map-object-values.test.ts` લુકઅપ ઑબ્જેક્ટ્સમાં સંગ્રહિત નામોને આવરી લે છે); `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` લિટરલ `<span className="material-symbols-outlined">` સ્પૅન્સને `<Icon>`માં ફરી લખે છે.
- **બ્રાન્ડ.** `src/shared/components/OmniRouteLogo.tsx` કિટને રૅપ કરે છે: ડિફૉલ્ટ એક્સપોર્ટ `OmniRouteLogo`, `ProductIcon product="omniroute" variant="glyph"` (ઇનલાઇન SVG, `basePath`-સુરક્ષિત) રેન્ડર કરે છે અને `OmniRouteLockup`, `ProductLockup product="omniroute"` (ઍક્સેસિબલ નામ "Keak OmniRoute") અથવા વ્હાઇટ-લેબલ ઑપરેટર્સ માટે તેમનું પોતાનું `name`/`logoSrc` રેન્ડર કરે છે. પ્રોડક્ટ-સ્વિચર ગંતવ્યો `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`)માં છે. સ્વતંત્ર સ્ક્રીન્સ — `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` અને `src/shared/components/ErrorPageScaffold.tsx` — લૉકઅપ બતાવે છે; `tests/unit/brand-pages-static.test.ts` તેને સુરક્ષિત રાખે છે.

## 2. નિયમો

1. ટોકન્સ, ક્યારેય લિટરલ્સ નહીં. જાણીજોઈને રાખવામાં આવેલા અપવાદો: હંમેશાં ડાર્ક રહેતું કન્સોલ ટર્મિનલ અને
   `STATUS_HEX` (`src/shared/constants/statusColors.ts`), કિટ સ્ટેટસ પેલેટનું રિઝોલ્વ થયેલ hex પ્રતિબિંબ,
   જે એવા કૉલર્સ માટે છે જેમને લિટરલ hex જોઈએ છે. કેટેગોરિકલ પેલેટ્સ હવે અપવાદ રહી નથી:
   તેઓ `src/shared/utils/categoricalPalette.ts` દ્વારા કિટના પાંચ ચાર્ટ ટોકન્સ
   (`--color-chart-1..5`) પર આધારિત છે અને, રૂટિંગ સ્ટ્રેટેજીઝ માટે,
   `src/app/(dashboard)/dashboard/combos/strategyPalette.ts`; ReactFlow એજીસ અને ઓર્કેસ્ટ્રેશન
   કેનવસ થીમ-અવેર `--orch-status-*` વેરિએબલ્સ વાંચે છે (`src/shared/components/flow/edgeStyles.ts`).
2. `packages/ui-kit/src` ને હાથથી ક્યારેય પેચ કરશો નહીં: `scripts/dev/sync-ui-kit.sh <commit>` સાથે
   સિંક કરો; પ્રી-કમિટ ગેટ `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) પિન કરેલી અપસ્ટ્રીમ
   કમિટથી અલગ પડતી દરેક બાઇટ પર નિષ્ફળ જાય છે (જ્યારે અપસ્ટ્રીમ ક્લોન,
   `UI_KIT_CLONE` અથવા `_references/cheaper-inference-ui-kit`, ગેરહાજર હોય ત્યારે તે ચેતવણી સાથે
   સ્કિપ થાય છે). જ્યારે કિટમાં કંઈક ખૂટતું હોય, ત્યારે એડેપ્ટર અથવા સ્ક્રીનમાં તેનો વર્કઅરાઉન્ડ
   કરો અને તેના માટે અપસ્ટ્રીમને વિનંતી કરો.
3. કિટ ટેક્સ્ટ ડિફોલ્ટ્સ અંગ્રેજી છે (`label = "Loading"`, `loadingLabel = "Loading table"`…) —
   જ્યારે પણ કોઈ કિટ કોમ્પોનન્ટ ટેક્સ્ટ રેન્ડર કરે ત્યારે `useTranslations(...)` માંથી અનુવાદિત
   સ્ટ્રિંગ્સ પાસ કરો.
4. Tailwind યુટિલિટીઝ કિટ કોમ્પોનન્ટ ક્લાસીસ પર વિજયી થાય છે (કિટ
   `@layer theme, base, components, utilities` ડિક્લેર કરે છે અને તેના નિયમો `components` માં રહે છે) —
   સ્પેસિંગ અને લેઆઉટ માટે યુટિલિટીઝ વાપરો, કિટ કોમ્પોનન્ટ્સને ફરી રંગવા માટે નહીં.
5. હેડિંગ્સ: પેજ અને સેક્શન ટાઇટલ્સ માટે `.ci-heading` (Inter, ટ્રેકિંગ વગર); `.ci-dashboard-display`
   (Instrument Serif) ફક્ત મોટા, વિરળ ડિસ્પ્લે ટેક્સ્ટ માટે, જેમ કે એરર-પેજ સ્ટેટસ કોડ.
6. `tests/unit/dashboard-kit-sweep.test.ts` કિટ અપનાવવાની દેખરેખ રાખે છે: `src/app` અથવા
   `src/shared/components` હેઠળ કોઈ Material ligature span નહીં; ડેશબોર્ડ ટ્રીમાં (`src/app/(dashboard)`
   અને `src/shared/components`) કોઈ રો `<select>`, `<textarea>` અથવા `<table>` નહીં અને સૂચિબદ્ધ
   અપવાદો (`Select` એડેપ્ટરની નેટિવ બ્રાન્ચ, `RequestLoggerDetail`) સિવાય કોઈ હાથથી બનાવેલું
   `role="dialog"` નહીં; ત્યાં દરેક રો `<button>` અથવા `<input>` માટે `kit-exception:` ધરાવતી
   (કારણ સહિતની) ટિપ્પણી જરૂરી છે જે તેની ઉપર મહત્તમ 3 લાઇનમાં સમાપ્ત થતી હોય; પેલેટ હ્યુઝ અને
   `dark:` વેરિઅન્ટ્સ ફક્ત ટેસ્ટમાં સૂચિબદ્ધ ફાઇલોમાં જ.
7. PR પહેલાં બંને થીમ્સ અને 390 px વ્યુપોર્ટ ચકાસો (સ્ક્રીનશોટ્સ); `tests/e2e/a11y.spec.ts`
   axe ચલાવે છે.

## 3. સ્ક્રીન ઉમેરવી

1. પેજને કિટના `PageHeader` (`@omniroute/ui-kit/page-header`, ડૅશબોર્ડની અંદર `compact`) સાથે ખોલો — ટાઇટલ, વર્ણન અને `actions`. ત્યારબાદ શેલ હેડર પોતાનું ટાઇટલ દૂર કરે છે.
2. `@/shared/components` (એડેપ્ટર્સ)માંથી કન્ટ્રોલ્સ બનાવો અને જ્યાં કોઈ એડેપ્ટર ઉપલબ્ધ ન હોય ત્યાં સબપાથ દ્વારા કિટ કમ્પોનન્ટ્સ (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`, `Slider`…) વાપરો.
3. આઇકન્સ: `<Icon name="…" />`. નવું નામ અર્થની દૃષ્ટિએ મેળ ખાતા Lucide કમ્પોનન્ટ સાથે `ICON_MAP` માં ઉમેરવું; `npm run gen:icon-map` હજુ ખૂટતાં નામોની સૂચિ આપે છે.
4. રંગો: સેમેન્ટિક યુટિલિટીઝ (`text-success`, `bg-warning-bg`, `border-border`…) અને ચાર્ટ સિરીઝ માટે `var(--color-chart-N)`; કોઈ hex વેલ્યૂ નહીં અને માત્ર રંગનું પુનરાવર્તન કરતા કોઈ `dark:` વેરિઅન્ટ્સ નહીં.
5. ટેક્સ્ટ: કિટ કમ્પોનન્ટ્સને પાસ કરાતા લેબલ્સ સહિત દરેક સ્ટ્રિંગ `useTranslations` માંથી આવે છે. નવી કીઝ `src/i18n/messages/en.json`, `pt-BR.json` અને `vi.json` માં ઉમેરો (વિયેતનામી પેરિટી ટેસ્ટ દરેક અંગ્રેજી કીને પિન કરે છે); અન્ય લોકેલ્સ i18n સિંક દ્વારા ભરાય છે.
6. PR પહેલાં ગાર્ડ્સ ચલાવો: `tests/unit/dashboard-kit-sweep.test.ts`, `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`, `npm run check:dashboard-typecheck` (`iconMap.ts` માં ડુપ્લિકેટ થયેલા ઇમ્પોર્ટને પકડતી એકમાત્ર ચકાસણી), `npm run check:ui-icu`, અને સ્ક્રીનના પોતાના ટેસ્ટ્સ.

## 4. ઍડૅપ્ટર ઉમેરવું અથવા બદલવું

1. `src/shared/components/index.tsx` નું જાહેર API યથાવત્ રાખો: સમાન export નામો, default exports અને
   સ્વીકાર્ય props. ઍડૅપ્ટરની અંદર legacy props ને kit સાથે map કરો (`Button.tsx` જુઓ: `VARIANT_TO_KIT`,
   `SIZE_TO_KIT`).
2. kit ને subpath દ્વારા import કરો (`@omniroute/ui-kit/<component>`).
3. kit માં રહેલી ખામીઓ માટેના workarounds ઍડૅપ્ટરમાં (અથવા fix style હોય ત્યારે `globals.css` ના `@layer components` માં) રાખો,
   `packages/ui-kit/src` માં ક્યારેય નહીં.
4. `tests/unit/ui/adapters/<name>.test.tsx` ઉમેરો અથવા અપડેટ કરો. ઘણા callers ધરાવતા ઍડૅપ્ટર માટે,
   ફેરફાર પહેલાં અને પછીના rendered markup ની તુલના કરો — padding અથવા wrapper ના ફેરફારો દરેક screen પર ફેલાય છે.

## 5. kit અપડેટ કરવી

`scripts/dev/sync-ui-kit.sh <commit> [clone]` તે commit પરના upstream `src/` ને
`packages/ui-kit/src` માં copy કરે છે અને એકમાત્ર મંજૂર transformation લાગુ કરે છે (તે relative imports માંથી `.js` suffix દૂર કરે છે).
ત્યારબાદ: `git diff packages/ui-kit` ની સમીક્ષા કરો, બંને themes માં providers, settings, combos,
usage અને endpoint નું visual નિરીક્ષણ કરો, `npm run check:ui-kit-snapshot` અને `npm run test:vitest:ui` ચલાવો, અને
upstream changelog સાથે PR ખોલો.
