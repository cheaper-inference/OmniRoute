> **સ્થિતિ:** ડેશબોર્ડ **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`) પર બનાવવામાં આવ્યું છે, જે
> વર્કસ્પેસ `packages/ui-kit` (`@omniroute/ui-kit`; અપસ્ટ્રીમ સ્નેપશોટ `packages/ui-kit/UPSTREAM.md` માં
> પિન કરેલું છે અને `npm run check:ui-kit-snapshot` દ્વારા સુરક્ષિત છે) તરીકે વેન્ડર કરવામાં આવ્યું છે. Light કેનોનિકલ
> થીમ છે; ડિફોલ્ટ પસંદગી `system` છે. એક્સેન્ટ Keak lime (`--ci-color-accent`) છે. સ્વિટ્ઝર એ UI અને ડિસ્પ્લે ટેક્સ્ટ (`--ci-font-ui`; `--ci-font-display` અને `--ci-font-mono` રિઝોલ્યુશન) માટેનું મુખ્ય ફોન્ટ કુટુંબ છે, જે કીટ દ્વારા જ સ્વ-હોસ્ટ કરવામાં આવે છે (`packages/ui-kit/src/ci-fonts.css`, `ci-tokens.css` દ્વારા આયાત કરેલું). દરેક ચિહ્ન એ લ્યુસાઇડ ગ્લિફ છે.
>
> Switzer માં ન હોય તેવા ગ્લિફ માટે Inter વિકલ્પ ફોન્ટ છે; `--font-mono` સિસ્ટમના મોનોસ્પેસ ફોન્ટ સ્ટેક `--ci-font-code` તરફ નિર્દેશ કરે છે.
>
> `Switzer`માં કોઈ ગ્લિફ ન હોય ત્યારે `src/app/globals.css` દરેક ગ્લિફ માટે અલગથી વૈકલ્પિક ફોન્ટ પસંદ કરે છે: સિરિલિક, ગ્રીક અને વિયેતનામી માટે `Inter`, અને અરબી લિપિ માટે ફક્ત `html[dir="rtl"]` હેઠળ `Vazirmatn`.

`src/app/globals.css`:

```css
:root,
.ci-theme {
  --ci-font-ui:
    "Switzer", "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif;
  --ci-font-code: ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace;
  --font-mono: var(--ci-font-code);
}
```

## 1. વસ્તુઓ ક્યાં રહેલી છે

- **કિટ.** `packages/ui-kit/src` એ `packages/ui-kit/UPSTREAM.md` માં પિન કરેલા કમિટ પરના અપસ્ટ્રીમ `src/` ની બાઈટ-ફોર-બાઈટ નકલ છે (જે લાઇસન્સ અધિકરણ પણ નોંધે છે); `PATCHES.md` સ્થાનિક પેચોની યાદી આપે છે (કોઈ નહીં). તે બિલ્ડ વિના, સોર્સ તરીકે વપરાય છે: `next.config.mjs` તેને ટ્રાન્સપાઇલ કરે છે, અને `tsconfig.json` `@omniroute/ui-kit` → `packages/ui-kit/src` તથા `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` મેપ કરે છે (`vitest.config.ts` અને `vitest.mcp.config.ts` એ જ એલિયસ ધરાવે છે). કિટ કમ્પોનન્ટને તેના સબપાથથી ઇમ્પોર્ટ કરો (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), ક્યારેય `@omniroute/ui-kit` બેરલ મારફતે નહીં: બેરલ દરેક ઇમ્પોર્ટરમાં બધા કમ્પોનન્ટ્સ (ડેટ પિકર સહિત) ખેંચી લાવે છે. કિટ સ્ટાઇલશીટ `src/app/globals.css` મારફતે પ્રવેશે છે (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **ટોકન્સ.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` ટોકન્સ જાહેર કરે છે; `src/app/globals.css` તેમને લિગસી OmniRoute નામો (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) સાથે બ્રિજ કરે છે, જેથી હાલના `var(--color-*)` વાંચન અને Tailwind યુટિલિટીઝ કામ કરતા રહે. નવો કોડ Tailwind યુટિલિટીઝ (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) અથવા કિટ ક્લાસેસ વાપરે છે — ક્યારેય હેક્સ વેલ્યુ નહીં (`tests/unit/design-kit-bridge.test.ts` બ્રિજને લાગૂ કરે છે). `text-primary` `--text-color-primary` મારફતે `--color-primary-ink` પર રિઝોલ્વ થાય છે (લાઇટમાં lime-800, ડાર્કમાં લાઇમ એક્સેન્ટ), જેથી `bg-primary`/`border-primary` લાઇમ સરફેસ જાળવી રાખે ત્યારે પ્રાઇમરી ટેક્સ્ટ વાંચી શકાય તેવું રહે. ચાર્ટ સીરીઝ `--color-chart-1` … `--color-chart-5` વાપરે છે.
- **થીમ્સ.** `<html className="ci-theme">` (`src/app/layout.tsx`) ડોક્યુમેન્ટને કિટ થીમમાં સામેલ કરે છે. પસંદગી `light`, `dark` અથવા `system` છે (`src/shared/constants/appConfig.ts` માં `THEME_CONFIG.defaultTheme = "system"`; `system` એ `prefers-color-scheme` ને અનુસરે છે). `src/store/themeStore.ts` માં `applyTheme()` (`src/app/layout.tsx` માં ઇનલાઇન બૂટસ્ટ્રેપ સ્ક્રિપ્ટ દ્વારા મિરર થયેલ, જે હાઇડ્રેશન પહેલાં ચાલે છે) `data-theme="dark"|"light"` સેટ કરે છે અને `<html>` પર `.dark` ક્લાસને સાથે મળીને ટોગલ કરે છે. કિટનો ડાર્ક ટોકન સેટ `data-theme="dark"` પર આધારિત છે (`packages/ui-kit/src/ci-tokens.css`); OmniRoute ના પોતાના ડાર્ક ઓવરરાઇડ્સ (`globals.css` માં `.dark` બ્લોક) અને લિગસી Tailwind `dark:` યુટિલિટીઝ `.dark` ક્લાસ પર આધારિત છે. કોઈ એક્સેન્ટ કલર પ્રીસેટ્સ નથી: એક્સેન્ટ હંમેશા કિટમાંથી જ આવે છે, અને જૂના બિલ્ડથી સંગ્રહિત પ્રીસેટ સ્ટોર લોડ થાય ત્યારે કાઢી નાખવામાં આવે છે.
- **કમ્પોનન્ટ્સ (એડેપ્ટર્સ).** `src/shared/components/index.tsx` OmniRoute કમ્પોનન્ટ API જાળવી રાખે છે (એ જ નામો, ડિફોલ્ટ એક્સપોર્ટ્સ અને પ્રોપ્સ), અને તેની પાછળના પ્રિમિટિવ્સ કિટ પરના એડેપ્ટર્સ છે: ફોર્મ્સ (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), ઓવરલે અને ફીડબેક (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`), સ્ટ્રક્ચર (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) અને ટેબલ્સ (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). એડેપ્ટર કિટ કમ્પોનન્ટને સબપાથથી ઇમ્પોર્ટ કરે છે અને લિગસી પ્રોપ્સને તેના પર મેપ કરે છે — ઉદાહરણ તરીકે `Button variant="primary"` એ કિટનું `default` બટન છે (`--ci-button-primary-*`: લાઇટમાં ઇન્વર્સ સરફેસ, ડાર્કમાં તેની `--ci-color-accent-foreground` ઇંક સાથેનો એક્સેન્ટ), `danger` એ `destructive` છે, અને `warning` એ `outline` વત્તા `.ci-button--warning` એક્સ્ટેન્શન છે. `globals.css` ના અંતે (`@layer components`) આવેલા `.ci-button--warning` અને `.ci-badge[data-tone]` નિયમો કિટ ક્લાસેસ પરના OmniRoute એક્સ્ટેન્શન્સ છે. `tests/unit/ui/adapters/*.test.tsx` દરેક એડેપ્ટરને પિન કરે છે.
- **શેલ.** `src/app/(dashboard)/layout.tsx` `DashboardLayout` રેન્ડર કરે છે, જે `src/shared/components/layouts/DashboardShell.tsx` રેન્ડર કરે છે: કિટ `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), જેમાં OmniRoute નું નેવિગેશન લોજિક `src/shared/components/Sidebar.tsx` માં છે. `#main-content` તરફ દોરતી "કન્ટેન્ટ પર જાઓ" લિંક પ્રથમ ફોકસેબલ એલિમેન્ટ છે. `src/shared/components/Header.tsx` કિટ `SidebarTrigger` (શેલનું એકમાત્ર સાઇડબાર ટોગલ), Keak `ProductSwitcher` અને કમાન્ડ-પેલેટ ઓપનર ધરાવે છે; તે `#main-content` ની અંદર કોઈ કિટ `PageHeader` (`.ci-page-header`) માઉન્ટ ન થયેલ હોય ત્યાં સુધી જ રૂટ ટાઇટલ બતાવે છે, જેથી પોતાનું `PageHeader` ધરાવતા પેજને એક જ `h1` હોય. `src/shared/components/CommandPalette.tsx` એ કિટ `Dialog` છે.
- **આઇકોન્સ.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) નામને (સ્ક્રીન્સ જે Material Symbols શબ્દસંગ્રહ વાપરે છે તે) `ICON_MAP` (`src/shared/constants/iconMap.ts`) મારફતે Lucide ગ્લિફ પર રિઝોલ્વ કરે છે. [--write]` લિટરલ `<span className="material-symbols-outlined">` સ્પાન્સને `<Icon>` માં ફેરવે છે.

## 5. કિટ અપડેટ કરવી

`npm run check:ui-kit-upstream` અપસ્ટ્રીમ રેપોના સૌથી નવા `v*` ટેગ સાથે `packages/ui-kit/UPSTREAM.md` માં પિન કરેલ સંસ્કરણની તુલના કરે છે અને જ્યારે રીલીઝ બહાર હોય ત્યારે સિંક કમાન્ડ છાપે છે. સાપ્તાહિક `UI Kit upstream watch` વર્કફ્લો (`.github/workflows/ui-kit-upstream-watch.yml`) એ જ ચેક ચલાવે છે અને જ્યારે પિન પાછળ હોય ત્યારે એક ટ્રેકિંગ સમસ્યા ખુલ્લી રાખે છે; અપસ્ટ્રીમ રેપો ખાનગી છે, તેથી વર્કફ્લોને `UI_KIT_READ_TOKEN` સિક્રેટમાં ફક્ત વાંચવા માટેના ટોકનની જરૂર છે. અપસ્ટ્રીમ ચકાસક વાંચી ન શકે (ટોકન ન હોય, ટોકન કામ કરતું બંધ થયું હોય અથવા GitHub સુધી પહોંચી ન શકાય), તો તે `unknown` જણાવે છે અને એક્ઝિટ કોડ `0` સાથે પૂર્ણ થાય છે. વર્કફ્લો ચેતવણી લખે છે અને એક અલગ ટ્રેકિંગ ઇશ્યૂ ખુલ્લો રાખવાનો પ્રયાસ કરે છે; ઍક્સેસ પાછો આવ્યા પછીનો સફળ રન તેને બંધ કરે છે. GitHub ઇશ્યૂ API નિષ્ફળ જાય તો જૉબ નિષ્ફળ થાય છે.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` તે કમિટ પર અપસ્ટ્રીમ `src/` નકલ કરે છે (`latest` = સૌથી નવું `v*` ટેગ) `packages/ui-kit/src` માં, સિંગલ મંજૂર ટ્રાન્સફોર્મેશન લાગુ કરે છે (તે સંબંધિત આયાતમાંથી `.js` પ્રત્યયને ડ્રોપ કરે છે), અને વર્કસ્પેસ વર્ઝનને `packages/ui-kit/package.json` અને `package-lock.json` માં અપસ્ટ્રીમમાં સેટ કરે છે. પછી: `git diff packages/ui-kit` ની સમીક્ષા કરો, બંને થીમમાં પ્રદાતાઓ, સેટિંગ્સ, કોમ્બોઝ, ઉપયોગ અને એન્ડપોઇન્ટ પર વિઝ્યુઅલ પાસ કરો, `npm run check:ui-kit-snapshot` અને `npm run test:vitest:ui` ચલાવો, અને અપસ્ટ્રીમ ચેન્જલોગ સાથે PR ખોલો.

## 6. README ના આલેખો

મૂળ `README.md` માં સમાવાયેલા બાર આલેખો (`docs/diagrams/*.svg`) કિટને સ્થિર ચિત્રો પર લાગુ કરે છે. તેઓ જનરેટ થાય છે, હાથથી દોરાતા નથી: `scripts/docs/gen-readme-*.mjs` માં 13 જનરેટર ફાઇલો (બાર આલેખો અને નિયંત્રક `gen-readme-diagrams.mjs`), અને `tests/unit/docs/readme-*-svg.test.ts` માં 12 જૂનાપણાની કસોટીઓ છે, દરેક આલેખ માટે એક. દરેક કસોટી commit કરેલી ફાઇલને તેના જનરેટરના આઉટપુટ સાથે બાઇટ પ્રમાણે સરખાવે છે (જોબ `test-unit`).

- **ટોકન્સ.** `scripts/docs/readme-diagram-theme.mjs` `packages/ui-kit/src/ci-tokens.css` ( `tests/unit/docs/readme-diagram-theme.test.ts` દ્વારા તે ફાઇલ સામે પિન કરેલ) માંથી પેલેટની નકલ કરે છે અને કીટના પહેલાના ચહેરા પર ટેક્સ્ટની ભૂમિકાઓ વ્યાખ્યાયિત કરે છે - ડિસ્પ્લે માટે ઇન્સ્ટ્રુમેન્ટ સેરીફ, UI ટેક્સ્ટ માટે ઇન્ટર, ફિગર અને કોડ માટે IBM Plex Mono — `@fontsource` પેકેજોમાંથી (ડેશબોર્ડ પોતે kit 0.0.66 થી kit ના Switzer નો ઉપયોગ કરે છે). પ્રકાશ મૂલ્યો `:root` પર બેસે છે, `prefers-color-scheme: dark` પાછળ શ્યામ મૂલ્યો, ફાઇલની અંદર, તેથી દરેક છબી GitHub પર દર્શકની યોજનાને અનુસરે છે.

- **ફોન્ટ.** `scripts/docs/readme-fonts.mjs` તે woff2 ફાઇલોને દરેક આલેખમાં દોરાતા ગ્લિફ સુધી મર્યાદિત કરે છે અને તેમને `@font-face` દ્વારા `data:` URI તરીકે સમાવે છે. આથી કિટના ફોન્ટ SVGની અંદર જ રહે છે. README ચિત્રની સ્થાનિક તપાસ ચકાસે છે કે રેન્ડરિંગ કોઈ બાહ્ય ફોન્ટ વિનંતી કરતું નથી. ઉપસમૂહોમાં માત્ર લેટિન અક્ષરો છે; સિસ્ટમના ફોન્ટ પર પાછા જતાં પ્રતીક-ગ્લિફને `SYMBOL_FALLBACKS` માં એક-એક કરીને મંજૂરી મળે છે. બીજા કોઈ પણ ન આવરાયેલા ગ્લિફથી ભૂલ થાય છે.

- **ફરી જનરેટ કરો.** `npm run docs:readme-diagrams` બધા બાર આલેખો README ક્રમમાં ફરી લખે છે અને દરેક ફાઇલના કદ સાથે એક લીટી છાપે છે. જનરેટર અલગથી પણ ચાલી શકે છે (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` માટે `node --import tsx/esm` જરૂરી છે, કારણ કે તેના આંકડા `open-sse/config/freeModelCatalog.ts` ના વર્તમાન કેટલોગ લોડરમાંથી આવે છે; કેટલોગ ફેરફારની CI પર અસર `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict` માં છે). જનરેટર અને SVG સાથે commit કરો.

- **પુરાવો.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` સ્થાનિક તપાસમાં ફાઇલ રેન્ડર કરે છે (`<img>` ટૅગ, નિયંત્રણવાળી `Content-Security-Policy` અને `image/svg+xml` પ્રતિસાદ), હળવી અને ઘેરી ફ્રેમ લે છે અને પૃષ્ઠની બાહ્ય ફોન્ટ વિનંતીઓ દર્શાવે છે; તેમની સંખ્યા 0 હોવી જ જોઈએ.

- **કદમર્યાદા.** દરેક ફાઇલ 200 KB કરતાં નાની હોવી જોઈએ, જે દરેક જૂનાપણાની કસોટી ચકાસે છે; કોઈપણ README ચિત્રની કડક મહત્તમ મર્યાદા 500 KB છે (SVG studio વેલિડેટરનો નિયમ).

- **સહિયારું લખાણ, ગણતરી gate માંથી.** દરેક જનરેટર તેના આલેખનું લખાણ `*_COPY` અચળમાં રાખે છે અથવા વર્તમાન કેટલોગમાંથી બનાવે છે. આ જ લખાણ દોરાય છે અને ફોન્ટ ઉપસમૂહનું ઇનપુટ પણ છે. પ્રમાણભૂત આંકડા `<text>` નોડમાં રહે છે, જેને `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) વાંચે છે. gate વાંચે છે તે આલેખોની જૂનાપણાની કસોટીઓ જનરેટ કરેલી ફાઇલ પર તેના વેલિડેટર પણ ચલાવે છે. કોડથી અલગ આંકડો કસોટી નિષ્ફળ કરે છે: gate વાંચે છે તે સ્રોત સુધારો, જનરેટરનો આંકડો ક્યારેય નહીં.
