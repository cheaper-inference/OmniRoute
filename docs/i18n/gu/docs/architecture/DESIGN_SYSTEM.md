> **સ્થિતિ:** ડેશબોર્ડ પર બનેલ છે** Keak CI UI કિટ** (`@keak/cheaper-inference-ui-kit`), વર્કસ્પેસ `packages/ui-kit` તરીકે વેચવામાં આવે છે (`@omniroute/ui-kit`; અપસ્ટ્રીમ સ્નેપશોટ `packages/ui-kit/UPSTREAM.md` માં પિન કરેલ છે અને `npm run check:ui-kit-snapshot` દ્વારા સુરક્ષિત છે). પ્રકાશ કેનોનિકલ થીમ છે; મૂળભૂત પસંદગી `system` છે. ઉચ્ચાર કીક લાઈમ (`--ci-color-accent`) છે. સ્વિટ્ઝર એ UI, ડિસ્પ્લે અને કોડ ટેક્સ્ટ (`--ci-font-ui`; `--ci-font-display` અને `--ci-font-mono` રિઝોલ્યુશન) માટેનું એકલ કુટુંબ છે, જે કીટ દ્વારા જ સ્વ-હોસ્ટ કરવામાં આવે છે (`packages/ui-kit/src/ci-fonts.css`, `ci-tokens.css` દ્વારા આયાત કરેલું). સ્ક્રિપ્ટ્સ સ્વિટ્ઝરમાં ગ્લિફ દ્વારા ગ્લિફ દ્વારા ફોલનો અભાવ છે (`src/app/globals.css`): સિરિલિક, ગ્રીક અને વિયેતનામીસ માટે ઇન્ટર અને અરબી લિપિ માટે માત્ર `html[dir="rtl"]` હેઠળ, વઝિરમાટન. દરેક ચિહ્ન એ લ્યુસાઇડ ગ્લિફ છે.

## 1. જ્યાં વસ્તુઓ રહે છે

- **કિટ.** `packages/ui-kit/src` એ `packages/ui-kit/UPSTREAM.md` માં પિન કરેલ કમીટ પર અપસ્ટ્રીમ `src/` ની બાઈટ-બદ-બાઈટ નકલ છે (જે લાયસન્સ અધિકૃતતા પણ રેકોર્ડ કરે છે); `PATCHES.md` સ્થાનિક પેચોની યાદી આપે છે (કોઈ નહીં). તે સ્ત્રોત તરીકે ઉપયોગમાં લેવાય છે, જેમાં કોઈ બિલ્ડ નથી: `next.config.mjs` તેને ટ્રાન્સપીલ કરે છે, અને `tsconfig.json` નકશા `@omniroute/ui-kit` → `packages/ui-kit/src` અને `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` (`vitest.config.ts` અને `vitest.mcp.config.ts` સમાન ઉપનામ ધરાવે છે). કિટ ઘટકને તેના સબપાથ દ્વારા આયાત કરો (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), ક્યારેય `@omniroute/ui-kit` બેરલ દ્વારા: બેરલ દરેક આયાતકારમાં દરેક ઘટક (તારીખ પીકર સહિત) ખેંચે છે. કીટ સ્ટાઈલશીટ `src/app/globals.css` (`@import "../../packages/ui-kit/src/ci-styles.css"`, સંપૂર્ણ શીટ: કોર `ci-ui.css` વત્તા દરેક પેટર્ન કુટુંબ) દ્વારા પ્રવેશે છે.
- **ટોકન્સ.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` ટોકન્સ જાહેર કરે છે; `src/app/globals.css` તેમને લેગસી OmniRoute નામો (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) સાથે જોડે છે, તેથી હાલની `var(--color-*)` રીડ અને Tailwind ઉપયોગિતાઓ કામ કરતી રહે છે. નવો કોડ Tailwind ઉપયોગિતાઓનો ઉપયોગ કરે છે (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) અથવા કિટ વર્ગો — ક્યારેય હેક્સ મૂલ્ય નથી (`tests/unit/design-kit-bridge.test.ts` પુલને લાગુ કરે છે). `text-primary` એ `--text-color-primary` દ્વારા `--color-primary-ink` ને રિઝોલ્યુશન કરે છે ( પ્રકાશમાંlime-800, અંધારામાં ચૂનો ઉચ્ચાર), તેથી પ્રાથમિક લખાણ વાંચી શકાય તેવું રહે છે જ્યારે `bg-primary`/`border-primary` ચૂનાની સપાટીને જાળવી રાખે છે. ચાર્ટ શ્રેણી `--color-chart-1` … `--color-chart-5` ઉપયોગ કરે છે.
- **થીમ્સ.** `<html className="ci-theme">` (`src/app/layout.tsx`) દસ્તાવેજને કીટ થીમમાં પસંદ કરે છે. પસંદગી `light`, `dark` અથવા `system` છે ( `src/shared/constants/appConfig.ts` માં`THEME_CONFIG.defaultTheme = "system"` ; `system` `prefers-color-scheme` ને અનુસરે છે). `src/store/themeStore.ts` માં `applyTheme()` ( `src/app/layout.tsx` માં ઇનલાઇન બુટસ્ટ્રેપ સ્ક્રિપ્ટ દ્વારા પ્રતિબિંબિત, જે હાઇડ્રેશન પહેલા ચાલે છે) `data-theme="dark"|"light"` સેટ કરે છે અને `<html>` પર `.dark` ક્લાસને એકસાથે ટૉગલ કરે છે. કીટનો ડાર્ક ટોકન સેટ `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`); OmniRoute ની પોતાની ડાર્ક ઓવરરાઇડ્સ ( `globals.css` માં `.dark` બ્લોક) અને `.dark` ક્લાસ પર લેગસી Tailwind `dark:` યુટિલિટીઝ કી. ત્યાં કોઈ ઉચ્ચારણ રંગ પ્રીસેટ્સ નથી: ઉચ્ચાર હંમેશા કીટમાંથી આવે છે, અને જ્યારે સ્ટોર લોડ થાય છે ત્યારે જૂની બિલ્ડમાંથી સતત પ્રીસેટ છોડવામાં આવે છે.
- **ઘટકો (એડેપ્ટરો).** `src/shared/components/index.tsx` એ OmniRoute ઘટક API (સમાન નામો, ડિફૉલ્ટ નિકાસ અને પ્રોપ્સ) રાખે છે, અને તેની પાછળના આદિમ કીટ પર એડેપ્ટર છે: ફોર્મ્સ (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge` `EmptyState` `Loading` `Modal` `ConfirmModal` `Tooltip` `InfoTooltip` `NotificationToast` `Card` `Collapsible` `CollapsibleSection` `SegmentedControl`, `Breadcrumbs`, `Avatar`) અને કોષ્ટકો (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). એડેપ્ટર સબપાથ દ્વારા કીટના ઘટકને આયાત કરે છે અને તેના પર — પર લેગસી પ્રોપ્સનો નકશો બનાવે છે ઉદાહરણ તરીકે `Button variant="primary"` એ કીટ `default` બટન છે (`--ci-button-primary-*`: પ્રકાશમાં વિપરીત સપાટી, અંધારામાં તેની `--ci-color-accent-foreground` શાહી સાથેનો ઉચ્ચાર), `danger` એ `destructive` છે , `.ci-button--warning` `warning` પ્લસ `outline` પ્લસ છે. `globals.css` (`@layer components`) ના અંતે `.ci-button--warning` અને `.ci-badge[data-tone]` નિયમો એ કિટ વર્ગોની ટોચ પર OmniRoute એક્સટેન્શન છે. `tests/unit/ui/adapters/*.test.tsx` દરેક એડેપ્ટરને પિન કરો.
- **શેલ.** `src/app/(dashboard)/layout.tsx` રેન્ડર કરે છે `DashboardLayout`, જે `src/shared/components/layouts/DashboardShell.tsx` રેન્ડર કરે છે : કિટ `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), `src/shared/components/Sidebar.tsx` માં OmniRoute ના નેવિગેશન લોજિક સાથે. `#main-content` ની "સામગ્રી પર જાઓ" લિંક એ પ્રથમ ધ્યાન કેન્દ્રિત કરવા યોગ્ય તત્વ છે. `src/shared/components/Header.tsx` કીટ `SidebarTrigger` (શેલનું એકમાત્ર સાઇડબાર ટૉગલ), Keak `ProductSwitcher` અને કમાન્ડ-પેલેટ ઓપનર ધરાવે છે; તે રૂટ શીર્ષક માત્ર ત્યારે જ બતાવે છે જ્યારે `#main-content` અંદર કોઈ કીટ `PageHeader` (`.ci-page-header`) માઉન્ટ થયેલ ન હોય, તેથી તેના પોતાના `PageHeader` સાથેના પૃષ્ઠમાં એક જ `h1` હોય છે. `src/shared/components/CommandPalette.tsx` એ કિટ `Dialog` છે.
- **ચિહ્નો.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) `ICON_MAP` (`src/shared/constants/iconMap.ts`) દ્વારા લ્યુસાઇડ ગ્લિફમાં નામ (મટીરિયલ સિમ્બોલ્સ શબ્દભંડોળ જે સ્ક્રીનનો ઉપયોગ કરે છે) ઉકેલે છે. મટીરીયલ સિમ્બોલ્સ ફોન્ટ અને પેકેજ અદૃશ્ય થઈ ગયા છે: નકશામાંથી ખૂટતું નામ તટસ્થ પ્લેસહોલ્ડર ગ્લિફ (`data-icon-missing="true"`) રેન્ડર કરે છે અને ઉત્પાદનની બહાર કન્સોલ ચેતવણી લૉગ કરે છે. `npm run gen:icon-map` ઉપયોગમાં લેવાતા નામોને છાપે છે જે નકશામાંથી ખૂટે છે (`tests/unit/icon-map-coverage.test.ts` લ્યુસાઇડ આઇકન વિના કોઈપણ નામ પર નિષ્ફળ જાય છે; `tests/unit/icon-map-object-values.test.ts` લુકઅપ ઑબ્જેક્ટ્સમાં સંગ્રહિત નામોને આવરી લે છે); `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` શાબ્દિક `<span className="material-symbols-outlined">` ને `<Icon>` સુધી ફરીથી લખે છે.
- **બ્રાન્ડ.** `src/shared/components/OmniRouteLogo.tsx` કીટને લપેટી લે છે: ડિફૉલ્ટ નિકાસ `OmniRouteLogo` `ProductIcon product="omniroute" variant="glyph"` (ઇનલાઇન SVG, `basePath` -safe) રેન્ડર કરે છે અને `OmniRouteLockup` રેન્ડર કરે છે `ProductLockup product="omniroute"` (ઍક્સેસિબલ નામ "Keak OmniRoute") અથવા, વ્હાઇટ-લેબલ ઑપરેટરો માટે, તેમના પોતાના `name`/`logoSrc`. પ્રોડક્ટ-સ્વિચર ગંતવ્ય `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`) માં રહે છે. સ્ટેન્ડઅલોન સ્ક્રીન્સ — `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` અને `src/shared/components/ErrorPageScaffold.tsx` — લોકઅપ દર્શાવે છે; `tests/unit/brand-pages-static.test.ts` તેની રક્ષા કરે છે.

## 2. નિયમો

1. ટોકન્સ, શાબ્દિક ક્યારેય નહીં. અપવાદો હેતુસર રાખવામાં આવે છે: હંમેશા-શ્યામ કન્સોલ ટર્મિનલ અને `STATUS_HEX` (`src/shared/constants/statusColors.ts`), કોલર્સ માટે કીટ સ્ટેટસ પેલેટનો ઉકેલાયેલ-હેક્સ મિરર કે જેને શાબ્દિક હેક્સની જરૂર હોય છે. સ્પષ્ટ પેલેટ હવે કોઈ અપવાદ નથી: તેઓ કિટના પાંચ ચાર્ટ ટોકન્સ (`--color-chart-1..5`) પર `src/shared/utils/categoricalPalette.ts` અને રૂટીંગ વ્યૂહરચનાઓ માટે, `src/app/(dashboard)/dashboard/combos/strategyPalette.ts`; ReactFlow ધાર અને ઓર્કેસ્ટ્રેશન કેનવાસ થીમ-અવેર `--orch-status-*` ચલો (`src/shared/components/flow/edgeStyles.ts`) વાંચે છે.

## 5. કીટ અપડેટ કરી રહ્યા છીએ

`npm run check:ui-kit-upstream` અપસ્ટ્રીમ રેપોના નવા `v*` ટેગ સાથે `packages/ui-kit/UPSTREAM.md` માં પિન કરેલા સંસ્કરણની તુલના કરે છે અને જ્યારે રીલીઝ બહાર હોય ત્યારે સિંક કમાન્ડ છાપે છે.

દૈનિક `UI Kit upstream watch` વર્કફ્લો (`.github/workflows/ui-kit-upstream-watch.yml`) એ જ ચેક ચલાવે છે. જ્યારે પિન પાછળ હોય છે, ત્યારે `scripts/ci/ui-kit-sync-pr.sh` એક સિંક PR સૌથી વધુ `release/vX.Y.Z` શાખા સામે, રોલિંગ બ્રાન્ચ `chore/ui-kit-sync-latest` પર ખુલ્લું રાખે છે. તે ક્યારેય મર્જ થતું નથી: દરેક કિટ રિલીઝને હજુ પણ સ્થાનિક VPS પર વિઝ્યુઅલ ચેકની જરૂર છે. જ્યારે નવી રીલીઝ બહાર આવે અને અન્યથા એકલી છોડી દેવામાં આવે ત્યારે શાખાનું પુનઃનિર્માણ કરવામાં આવે છે. હાથ વડે દબાણ કરાયેલ કમિટ સાથેનો ઓપન PR ઓવરરાઈટ થતો નથી, અને એવા વર્ઝન માટે PR કે જે જાળવણીકારે બંધ કરેલ અનમર્જ કરેલ હોય તે નવી રિલીઝ સુધી બંધ રહે છે.

જ્યારે કોઈ PR ખોલી શકાતું નથી (લક્ષ્ય પ્રકાશન સ્થિર છે, PR એ હાથથી દબાણ કર્યું છે, PR બંધ હતું, અથવા કોઈ PR ટોકન સેટ નથી) વર્કફ્લો એક ટ્રેકિંગ સમસ્યાને ખુલ્લી રાખે છે જે કહે છે કે શા માટે.

વર્કફ્લો બે રહસ્યોનો ઉપયોગ કરે છે:

- `secrets.UI_KIT_READ_TOKEN`: ખાનગી અપસ્ટ્રીમ રેપો માટે માત્ર વાંચવા માટેનું ટોકન. જ્યારે વર્કફ્લો અપસ્ટ્રીમ વાંચી શકતું નથી (કોઈ ટોકન, ટોકન કે જે કામ કરવાનું બંધ કરે છે, અથવા GitHub અગમ્ય) રન લીલો રહે છે પરંતુ ચેતવણી લખે છે અને એક અલગ મુદ્દો ખુલ્લો રાખે છે, જે પછીથી ચાલ્યા પછી ફરીથી અપસ્ટ્રીમ વાંચી શકે છે તે બંધ થઈ જાય છે.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: સમાવિષ્ટો અને પુલ વિનંતીઓ લખવાની ઍક્સેસ સાથે આ ભંડાર પર એક સરસ ટોકન. ડિફૉલ્ટ `GITHUB_TOKEN` અહીં PRs બનાવી શકતું નથી, અને PR તે ખોલે છે CI ટ્રિગર કરશે નહીં. આ ટોકન વિના વર્કફ્લો માત્ર શાખાને દબાણ કરે છે.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` તે કમિટ પર અપસ્ટ્રીમ `src/` નકલ કરે છે (`latest` = સૌથી નવું `v*` ટેગ) `packages/ui-kit/src` માં, સિંગલ મંજૂર ટ્રાન્સફોર્મેશન લાગુ કરે છે (તે સંબંધિત આયાતમાંથી `.js` પ્રત્યયને ડ્રોપ કરે છે), અને વર્કસ્પેસ વર્ઝનને `packages/ui-kit/package.json` અને `package-lock.json` માં અપસ્ટ્રીમમાં સેટ કરે છે. પછી: `git diff packages/ui-kit` ની સમીક્ષા કરો, બંને થીમમાં પ્રદાતાઓ, સેટિંગ્સ, કોમ્બોઝ, ઉપયોગ અને એન્ડપોઇન્ટ પર વિઝ્યુઅલ પાસ કરો, `npm run check:ui-kit-snapshot` અને `npm run test:vitest:ui` ચલાવો, અને અપસ્ટ્રીમ ચેન્જલોગ સાથે PR ખોલો.

## 6. README આકૃતિઓ

રૂટ `README.md`માં એમ્બેડ કરેલી બાર આકૃતિઓ (`docs/diagrams/*.svg`) સ્થિર ઇમેજ પર લાગુ કરાયેલ કિટ છે અને તે હાથથી દોરવામાં આવેલી નથી, પરંતુ જનરેટ કરવામાં આવે છે: `scripts/docs/gen-readme-*.mjs`માં 13 જનરેટર ફાઇલો (બાર આકૃતિઓ ઉપરાંત `gen-readme-diagrams.mjs` ડ્રાઇવર) અને `tests/unit/docs/readme-*-svg.test.ts`માં 12 સ્ટેલનેસ ટેસ્ટ્સ, દરેક આકૃતિ માટે એક, જે કમિટ કરેલી ફાઇલની તેના જનરેટરના આઉટપુટ સાથે બાઇટ-દર-બાઇટ સરખામણી કરે છે (`test-unit` જોબ).

- **ટોકન્સ.** `scripts/docs/readme-diagram-theme.mjs` પેલેટને `packages/ui-kit/src/ci-tokens.css`માંથી કૉપી કરે છે (`tests/unit/docs/readme-diagram-theme.test.ts` દ્વારા તે ફાઇલ સામે પિન કરાયેલું) અને કિટના ટાઇપ સ્કેલ પર ટેક્સ્ટ ભૂમિકાઓ વ્યાખ્યાયિત કરે છે: કિટના વેઇટ્સ (400/500/600, ડિસ્પ્લે માટે 500) અને દરેક વસ્તુ માટે ટ્રેકિંગ સાથે Switzer, સિવાય કે કોડ ભૂમિકાઓ (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`) માટે, જે IBM Plex Mono છે અને માત્ર કમાન્ડ્સ, URLs, ઓળખાણીઓ અને ટર્મિનલ સ્ક્રીન્સ માટે છે.
  હળવા મૂલ્યો `:root` પર અને ડાર્ક મૂલ્યો ફાઇલની અંદર `prefers-color-scheme: dark` પાછળ રાખવામાં આવે છે, તેથી GitHub પર દરેક ઇમેજ દર્શકની સ્કીમને અનુસરે છે.
- **ફોન્ટ્સ.** GitHub Markdownમાં CSS હોતું નથી અને camo proxy દરેક બાહ્ય fetchને અવરોધે છે, તેથી કિટનો ટાઇપ ફાઇલની અંદર જ હોવો જરૂરી છે. દરેક જનરેટરનું છેલ્લું પગલું `scripts/docs/readme-outline.mjs`, HarfBuzz વડે Switzer ભૂમિકાઓને આકાર આપે છે અને તેમને વેક્ટર આઉટલાઇન (`<defs>` પાથ્સ અને `<use>`) તરીકે દોરે છે; Switzerમાં ન હોય તેવા તીરો અને ભૌમિતિક ચિહ્નો તેના પોતાના મેટ્રિક્સ પર દોરવામાં આવે છે. એમ્બેડેડ ફોન્ટ ક્યારેય નહીં, માત્ર આઉટલાઇન્સ: Switzerનું લાઇસન્સ (`packages/ui-kit/src/fonts/FFL.txt`) લેખિત સંમતિ વિના સબસેટિંગ અને ફૉર્મેટ રૂપાંતરણને પ્રતિબંધિત કરે છે અને વેક્ટર ડ્રોઇંગ્સને મંજૂરી આપે છે, તેથી Switzerનું `@font-face` અથવા `data:` URI ફરીથી રજૂ કરશો નહીં. ફાઇલમાં રહેલો એકમાત્ર ફોન્ટ OFL IBM Plex Mono સબસેટ છે, જે વાસ્તવિક કોડ ટેક્સ્ટ તરીકે રહેલી વસ્તુઓ માટે છે (`scripts/docs/readme-fonts.mjs`), અને તે અક્ષરોમાંથી બનાવવામાં આવે છે; તે એમ્બેડ ન કરી શકે તેવો કોઈપણ ગ્લિફ ભૂલ ફેંકે છે.
- **ફરી જનરેટ કરો.** `npm run docs:readme-diagrams` READMEના ક્રમમાં તમામ બાર આકૃતિઓ ફરી લખે છે અને દરેક ફાઇલના કદ સાથે એક લાઇન છાપે છે. એક જનરેટર પોતે પણ ચલાવી શકાય છે (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` માટે `node --import tsx/esm` જરૂરી છે, કારણ કે તેની આકૃતિઓ `open-sse/config/freeModelCatalog.ts`માંના લાઇવ કૅટલૉગ લોડરમાંથી આવે છે; કૅટલૉગમાં ફેરફારનું CI પરિણામ `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict`માં છે). જનરેટર અને SVG બંને કમિટ કરો.
- **ચકાસણી.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` ફાઇલને GitHub જે રીતે સર્વ કરે છે તે રીતે રેન્ડર કરે છે (`<img>` ટૅગ, camoનું `Content-Security-Policy`, `image/svg+xml`), હળવી અને ડાર્ક ફ્રેમ કૅપ્ચર કરે છે અને પેજે કરેલી બાહ્ય ફોન્ટ વિનંતીઓની જાણ કરે છે (આ સંખ્યા 0 હોવી આવશ્યક છે).
- **બજેટ.** દરેક ફાઇલ માટે 200 KBથી ઓછી (દરેક સ્ટેલનેસ ટેસ્ટ તેની ખાતરી કરે છે); કોઈપણ README ઇમેજ માટે 500 KB કઠોર મર્યાદા છે (SVG સ્ટુડિયો વૅલિડેટરનો નિયમ).
- **કૉપી અપરિવર્તિત રાખો, ગણતરીઓ ગેટમાંથી લો.** રિબ્રાન્ડે શબ્દો નહીં, પરંતુ ટાઇપ અને પેલેટ બદલ્યાં છે: દરેક જનરેટર પોતાની આકૃતિની કૉપી `*_COPY` કૉન્સ્ટન્ટમાં રાખે છે (અથવા લાઇવ કૅટલૉગમાંથી બનાવે છે), જે દોરવામાં આવેલા ટેક્સ્ટ અને આઉટલાઇનિંગ પગલાના ઇનપુટ બંને છે. કૅનોનિકલ આકૃતિઓ `<text>` નોડ્સમાં જ રહે છે (આઉટલાઇન થયા પછી અદૃશ્ય, `fill-opacity:0`), અને તેને `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) વાંચે છે; આકૃતિઓના સ્ટેલનેસ ટેસ્ટ્સ, જે વાંચનને ગેટ કરે છે, જનરેટ કરેલી ફાઇલ પર તેના વૅલિડેટર્સ પણ ચલાવે છે, તેથી કોડથી ભટકતી આકૃતિ ટેસ્ટ નિષ્ફળ બનાવે છે — જનરેટરમાંની સંખ્યા ક્યારેય સુધારશો નહીં, ગેટ જે સ્રોત વાંચે છે તેને સુધારો.
