## દરવાન સ્થાપિત કરો (એક વખત, બોક્સ પર)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): every 30 min, log to /var/log/runner-janitor.log
*/30 * * * * MAX_ACTIVE_RUNNERS=8 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` આવશ્યક છે: દરવાન સાબિત કરે છે કે પાથને દૂર કરતા પહેલા ખુલ્લી ફાઇલોના એક સ્નેપશોટ સાથે નિષ્ક્રિય છે, અને સાધન વિના તે કંઈપણ દૂર કરતું નથી અને આમ કહે છે (એક્ઝિટ 1). `--dry-run` પ્રથમ — સાથે કોઈપણ ફેરફાર કરવાનો પ્રયાસ કરો તે બરાબર શું કરશે તે છાપે છે અને કંઈપણ સ્પર્શતું નથી.

તે દરેક દોડે શું કરે છે: આપણા પોતાના બચેલા (`runner-*`, `omniroute-*`, `next-build*`, `e2e-build.tar.gz`) પછી**tmpfs પર 3 કલાક** અને ડિસ્ક `_work/_temp` પર 24 કલાક ; 75 મિનિટ કરતાં જૂના `next-build` પર ચેતવણીઓ અને તેને ચાલુ રાખે છે; જેની એકમ છે દોડવીરો 48 કલાક જૂના ચેકઆઉટ prunes **બંધ** ; ડિસ્ક પર ચેતવણીઓ ≥ 85 %, મેમરી PSI `full/avg60` ≥ 10 %, અને `MAX_ACTIVE_RUNNERS` કરતાં વધુ શ્રોતાઓ ( omniroute/other બ્રેકડાઉન સાથે). બહાર નીકળો 1 = ધ્યાન જરૂરી; લોગ વાંચો.

એકલો વીતી ગયેલો સમય એ સાબિત કરતું નથી કે પ્રક્રિયા અનાથ છે. દરવાન ક્યારેય ઉંમરના આધારે સંકેતો મોકલતો નથી. વર્તમાન `ZOMBIE_BUILD_MAX_MIN` અને `ZOMBIE_BUILD_COMM` પર્યાવરણ નામો ક્રોન રૂપરેખાંકનો માટે સમર્થિત રહે છે. શંકાસ્પદ અનાથની સફાઈ કરતા પહેલા, ખાતરી કરો કે તેનું ચોક્કસ GitHub જોબ ટર્મિનલ છે અને તે જોબથી સંબંધિત પ્રક્રિયાઓને ઓળખો. જ્યારે `Runner.Listener` તેની નોકરીનું નવીકરણ કરી શકતું નથી, ત્યારે `_diag/Runner_*.log` `POST request to …/renewjob timed out after 100 seconds` બતાવે છે, API છેલ્લા સફળ નવીકરણ પછી લગભગ દસ મિનિટ પછી જોબ `completed` (નિષ્ફળતા) ની જાણ કરે છે, અને `next-build` કોઈ જોબ જોડ્યા વિના ચાલતું રહે છે (2026-10-18: #17066 નું બિલ્ડ 19:43 વાગ્યે નિષ્ફળ થયું હતું અને તેનું બિલ્ડ GB 5 મિનિટ પછી પણ હોલ્ડિંગ હતું). નવા `_diag/Worker_*.log` માં સંદર્ભની પુષ્ટિ કરો, પછી PID — `next-build`, `npm run build`, `build-next-isolated.mjs` અને `_work` કામદારો દ્વારા ફક્ત SIGTERM જ બિલ્ડ ટ્રી. `Runner.Listener`, `RunnerService.js` અથવા `Runner.Worker` ક્યારેય સ્પર્શ કરશો નહીં : કાર્યકર જોબને કેન્સલ કર્યાની જાણ કરે છે અને સાંભળનાર પોતે જ ઓનલાઈન થઈ જાય છે.

## Runner units: KillMode

Runnerનું ડિફૉલ્ટ `KillMode=process`, unitને બંધ કે restart કરવામાં આવે ત્યારે `Runner.Worker → npm → next-build`ને જીવંત છોડી દે છે — કોઈ job જોડાયેલું ન હોવા છતાં orphan build RAM અને CPU વાપરતું રહે છે. દરેક OmniRoute unitમાં `KillMode=mixed` સાથેનું drop-in (`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`) હોય છે: પહેલાં listenerને SIGTERM અને `TimeoutStop` પર સમગ્ર cgroupને SIGKILL. તે unitના આગામી restart વખતે અમલમાં આવે છે — **એક સમયે માત્ર એક runnerને, અને તે idle હોય ત્યારે જ** restart કરો, તથા idle check અને restart એક જ commandમાં રાખો.

  ત્યાં Turbopack પૅનિક થયું હતું, run 33253576569). arm64 Docker લેગ `ubuntu-24.04-arm` પર જ રહે છે.
  `docker-publish`નું amd64, `ci.yml`ના `Build` સાથે `heavy-build-main` concurrency group શેર કરે છે
  (`cancel-in-progress: false`). Docker Engine `omniroute-113-5` પર હોવું આવશ્યક છે. બીજો Turbopack
