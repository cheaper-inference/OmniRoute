સ્વ-હોસ્ટેડ પૂલ **.113** બૉક્સ (`tomni-proxmox-113`) પર ચાલે છે. 2026-10-18થી દરેક
OmniRoute રનર પાસે **એક ભૂમિકા**, એક લેબલ અને તેના વર્કલોડના માપેલા વપરાશને અનુરૂપ મેમરી/CPU બજેટ
છે. Turbopack સ્લોટને બિલ્ડ માટે જરૂરી સંસાધનો મળે છે; અન્ય સ્લોટનું કદ તેમના
માપેલા મહત્તમ વપરાશ મુજબ નક્કી કરાયું છે. બૉક્સ માત્ર ત્યારે જ ક્ષમતા કરતાં વધુ ફાળવણી કરે છે જ્યારે Turbopack બિલ્ડ સાથે Release-Green
webpack બિલ્ડ અને lint જોબ એકસાથે ચાલે; હોસ્ટ swap (16 GB) તેને સંભાળી લે છે અને pull-request Builds

## જૅનિટર ઇન્સ્ટોલ કરો (એક વખત, મશીન પર)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): દર 30 મિનિટે, /var/log/runner-janitor.log માં લૉગ કરો
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` આવશ્યક છે: જૅનિટર કોઈ પાથને દૂર કરતાં પહેલાં ખુલ્લી ફાઇલોનો એક snapshot લઈને તે નિષ્ક્રિય હોવાનું સાબિત કરે છે, અને આ ટૂલ વિના તે કશું દૂર કરતું નથી તથા તેમ જણાવે છે (exit 1). કોઈપણ ફેરફારને પહેલાં `--dry-run` સાથે અજમાવો — તે બરાબર શું કરશે તે પ્રિન્ટ કરે છે અને કશામાં ફેરફાર કરતું નથી.

દરેક રન વખતે તે શું કરે છે: **tmpfs પર 3 કલાક** અને ડિસ્કના `_work/_temp` પર 24 કલાક પછી અમારા પોતાના અવશેષો (`runner-*`, `omniroute-*`, `next-build*`, `e2e-build.tar.gz`) સાફ કરે છે; 75 મિનિટથી જૂના `next-build`ને બંધ કરે છે (કોઈ job એટલો લાંબો ચાલતો નથી — 2026-08-27ના રોજ GitHubએ તેનો job ખોવાઈ ગયો હોવાનું જાહેર કર્યા પછી એક job 70 મિનિટ સુધી ચાલ્યો હતો); જે runnersનું unit **બંધ છે** તેમના 48 કલાક જૂના checkouts દૂર કરે છે; ડિસ્ક ≥ 85 %, memory PSI `full/avg60` ≥ 10 %, અને `MAX_ACTIVE_RUNNERS` કરતાં વધુ listeners હોય ત્યારે ચેતવણી આપે છે (omniroute/other વિભાજન સાથે). Exit 1 = ધ્યાન આપવું જરૂરી છે; લૉગ વાંચો.

75-મિનિટનો નિયમ એવા buildને પકડી શકતો નથી જેના jobને GitHub પહેલેથી જ છોડી ચૂક્યું હોય. જ્યારે `Runner.Listener` તેના jobને renew કરી શકતું નથી, ત્યારે `_diag/Runner_*.log`માં `POST request to …/renewjob timed out after 100 seconds` દેખાય છે, છેલ્લી સફળ renewal પછી લગભગ દસ મિનિટે API jobને `completed` (failure) તરીકે દર્શાવે છે, અને કોઈ job જોડાયેલું ન હોવા છતાં `next-build` ચાલતું રહે છે (2026-10-18: #17066નું Build 19:43 વાગ્યે failed થયું હતું અને પાંચ મિનિટ પછી પણ તેનું build 40 GB રોકીને બેઠું હતું). સૌથી નવા `_diag/Worker_*.log`માં refની પુષ્ટિ કરો, ત્યારબાદ માત્ર build treeને PID દ્વારા SIGTERM મોકલો — `next-build`, `npm run build`, `build-next-isolated.mjs` અને `_work` workers. `Runner.Listener`, `RunnerService.js` અથવા `Runner.Worker`ને ક્યારેય સ્પર્શશો નહીં: worker jobને cancelled તરીકે રિપોર્ટ કરે છે અને listener આપમેળે ફરી online થઈ જાય છે.

## Runner units: KillMode

Runnerનું ડિફૉલ્ટ `KillMode=process`, unitને બંધ કે restart કરવામાં આવે ત્યારે `Runner.Worker → npm → next-build`ને જીવંત છોડી દે છે — કોઈ job જોડાયેલું ન હોવા છતાં orphan build RAM અને CPU વાપરતું રહે છે. દરેક OmniRoute unitમાં `KillMode=mixed` સાથેનું drop-in (`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`) હોય છે: પહેલાં listenerને SIGTERM અને `TimeoutStop` પર સમગ્ર cgroupને SIGKILL. તે unitના આગામી restart વખતે અમલમાં આવે છે — **એક સમયે માત્ર એક runnerને, અને તે idle હોય ત્યારે જ** restart કરો, તથા idle check અને restart એક જ commandમાં રાખો.

  ત્યાં Turbopack પૅનિક થયું હતું, run 33253576569). arm64 Docker લેગ `ubuntu-24.04-arm` પર જ રહે છે.

  `push` અને `workflow_dispatch` માટે જ `omni-build` સુધી પહોંચે છે; દરેક `pull_request` (પોતાના originમાંથી કે forkમાંથી)
