રીલીઝ-ગ્રીન ચોક્કસ પ્રતિબદ્ધતાનું અવલોકન કરે છે અને તેના માન્યતા પરિણામોની જાણ કરે છે. [ક્વોલિટી ગેટ્સ સંદર્ભ](../architecture/QUALITY_GATES.md) વર્તમાન CI પ્રોફાઇલ્સ, જરૂરી તપાસો અને સ્વીકૃતિ નીતિને વ્યાખ્યાયિત કરે છે. સંસ્કરણિત [પ્રવેશ નીતિ](../../config/quality/admission-policy.json) એ `Gate / CI` અને `Gate / Quality` માટે એક્ઝિક્યુટેબલ કરાર છે.

## CI અને નિરીક્ષક અવકાશ

`ci.yml` અને `quality.yml` કવર વિનંતીઓને મુખ્ય અને રિલીઝ શાખાઓમાં ખેંચે છે. પસંદ કરેલ પ્રોફાઇલ નક્કી કરે છે કે કઈ નોકરીઓ લાગુ પડે છે. સંપૂર્ણ CI લેનનો પણ સમાવેશ થાય છે જે સામાન્ય પુલ વિનંતી એક્ઝિક્યુટ થતી નથી. ઝડપી નિરીક્ષક પરિણામ તે નોકરીઓને બદલી શકતું નથી, અને પૂર્ણ થયેલ વર્કફ્લો રેપર તેની રસીદોને બદલી શકતું નથી.

ઉત્પાદન બિલ્ડ CI નું છે. `quality.yml` માં કોઈ ડુપ્લિકેટ એડવાઇઝરી બિલ્ડ નથી. ગુમ થયેલ કલાકૃતિઓ, રદ કરેલ કાર્ય અને અપૂર્ણ માપન સફળ જરૂરી તપાસ સ્થાપિત કરતા નથી. પરિણામો સ્વીકારતા પહેલા વર્તમાન આધાર, વડા અને સંયુક્ત ઉમેદવારની પુષ્ટિ કરો.

## સ્થાનિક માન્યતા

નિરીક્ષકને તેની નિર્ભરતા તૈયાર કર્યા પછી માલિકીની વર્કટ્રીમાં ચલાવો. ભારે માન્યતા પહેલા [વર્કટ્રી અને રિસોર્સ પ્રોટોકોલનો](WORKTREE_ISOLATION.md) ઉપયોગ કરો.

```bash
npm run check:release-green -- --quick --json
npm run check:release-green -- --with-build --full-ci --json
```

ઝડપી પ્રોફાઇલ આંશિક છે. સંપૂર્ણ પ્રોફાઇલ તેની મોડેલ કરેલી આવશ્યકતાઓને તપાસે છે અને આદેશ રસીદોને સાચવે છે; તે લાગુ હોસ્ટ કરેલ ચેક માટે જમાવટ અથવા અવેજી પ્રમાણિત કરતું નથી. રિપોર્ટ મેટ્રિક ડ્રિફ્ટથી એક્ઝેક્યુશન નિષ્ફળતાને અલગ પાડે છે. જરૂરી રેચેટ્સ પસંદ કરેલી નીતિ અનુસાર અવરોધિત રહે છે. માત્ર પાસ થયેલ પરિણામ મેળવવા માટે આધારરેખા વધારશો નહીં.

## રાત્રે અને મેન્યુઅલ સ્વીપ

રાત્રિના પ્રકાશન અને સુસંગતતા ઉકેલનારાઓ પ્રમાણભૂત પ્રકાશન શાખા પસંદ કરે છે. તે પસંદગી વર્કફ્લોને ટ્રિગર કરનાર શાખા સાથે મેળ ખાતી હોવી જોઈએ અને સ્યુટ્સ ઇવેન્ટના અપરિવર્તનશીલ SHA ઉપયોગ કરે છે. મેન્યુઅલ એક્ઝેક્યુશન માટે, `release_branch` માં ઇચ્છિત પ્રકાશન પસંદ કરો અને તે જ સંદર્ભ પર મોકલો:

```bash
gh workflow run nightly-release-green.yml --ref "$release_branch" -f branch="$release_branch"
gh workflow run nightly-compat.yml --ref "$release_branch" -f branch="$release_branch"
```

પસંદ કરેલા કોડને અમલમાં મૂકતા પહેલા ક્રોસ-બ્રાંચ ડિસ્પેચને નકારવામાં આવે છે. હોસ્ટ કરેલ મુખ્ય સ્યુટ્સ `main` ચેકઆઉટ કરે છે અને ચકાસો કે તેનો SHA હજી પણ ઇન્સ્ટોલેશન પહેલાં ઉકેલાયેલા લક્ષ્ય સાથે મેળ ખાય છે. જો રિઝોલ્યુશન દરમિયાન મુખ્ય ચાલ હોય, તો નવી કમિટ પર અપૂર્ણ સ્વીપને ફરીથી ચલાવો. જુદા જુદા ઉમેદવારોની સ્યુટ રસીદો ભેગા કરશો નહીં.

## નિષ્ફળતા ટ્રાયજ અને પુનઃપ્રાપ્તિ

ઘટનાનો ડાયગ્નોસ્ટિક ઇન્ડેક્સ તરીકે ઉપયોગ કરો, પછી ચોક્કસ રન, પ્રયાસ, નિષ્ફળતાના પગલા અને આર્ટિફેક્ટનું નિરીક્ષણ કરો. ફાળો આપનારને નિષ્ફળતા ગણાવતા પહેલા સમકક્ષ આધાર અને ઉમેદવારના પુરાવાની તુલના કરો. ઈન્ફ્રાસ્ટ્રક્ચરની ભૂલો, વારસાગત ખામીઓ, ઉમેદવારોની રીગ્રેસન અને બાકી મંજૂરીઓ માટે વિવિધ ઉપાયોની જરૂર છે.

`/green-prs`, `/sweep-reds`, `/validate-release-green` અને `/babysit` કૌશલ્યો પુરાવા એકત્રિત કરે છે અને તેમના દસ્તાવેજી અવકાશ હેઠળ સુધારાઓ તૈયાર કરે છે. ફાળો આપનાર ક્રેડિટ રાખો, અલગ રિપેર શાખાઓનો ઉપયોગ કરો અને અધિકૃત મર્જ કરતા પહેલા તમામ જરૂરી ચેકની ચકાસણી કરો. પાસ થયેલા વર્તમાન ઉમેદવાર માટે કોઈ સ્વચાલિત રીબેસલાઈન અથવા ઘટના બંધનો વિકલ્પ નથી.
