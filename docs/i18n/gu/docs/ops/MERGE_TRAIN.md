## પ્રકાશન શાખા પર ઉતરાણ

ઓમ્ની-કતાર `release/vX.Y.Z` માં ઉતરાણને નિયંત્રિત કરે છે. PR ઉતરતા પહેલા ડિફોલ્ટ બ્રાન્ચ પર `config/merge-queue/config.json` માં ટોપ-લેવલ `mode` વાંચો. [ઓમ્ની-કતાર](OMNI_QUEUE.md) જુઓ.

- **`shadow`** માન્યતા ચલાવે છે અને મેન્યુઅલ મર્જ પર ઉતરાણ છોડે છે. મંજૂર PR ને તેના અંતિમ મથાળે `omni-queue` લાગુ કરો. `npm run queue -- why <PR>` સાથે યોગ્યતા તપાસો. `npm run queue -- history --base <branch>` માં તે માથા માટેના ચુકાદાની રાહ જુઓ. `would-land` પર આગળ વધો. `culprit-found` અથવા `would-dequeue` પર, મર્જને પકડી રાખો અને કારણને ઠીક કરો.
- **શેડો અપવાદો.** વર્તમાન બેઝ ટીપ સામે લીલા રંગની સંપૂર્ણ CI સાથેની ટ્રેન અલગ કતારના ચુકાદા વિના આગળ વધી શકે છે. સમાન અપવાદ લાગુ પડે છે જ્યારે PR હેડ પહેલાથી જ વર્તમાન આધાર ટીપ ધરાવે છે.
- **`live`** ઉતરાણને ટ્રિગર કરવા માટે `omni-queue` લેબલનો ઉપયોગ કરે છે. એકલી કતાર PR પર ઉતરે છે. મર્જ આદેશો છોડો અને કતારમાં સીધા દબાણ કરો.

દરેક ઉતરાણ માટે માલિકની અધિકૃતતા અને લાગુ જરૂરી ચેકની જરૂર પડે છે. માલિકે ઉતરાણ માટે અધિકૃત કર્યા પછી જ `omni-queue` લાગુ કરો. કતારબદ્ધ PRs ને સ્પર્શતા સંરક્ષિત પાથને પણ તે PR માટે માલિકના `protected-approved` નિર્ણયની જરૂર છે.

"સક્રિય પ્રકાશન પર ગ્રીન ગેટ્સની જરૂર છે" નિયમોને માથા પર લીલા `Gate / CI` અને `Gate / Quality` જરૂર છે. લાલ દરવાજાને બાયપાસ કરવા માટે ક્યારેય `--admin` ઉપયોગ કરશો નહીં. એક રિલીઝ ફ્રીઝ બ્લોક્સ સ્થિર શાખામાં ભળી જાય છે. [સખત નિયમ 21](HARD_RULES_DETAIL.md) જુઓ. પુલ વિનંતી પર ક્યારેય લેબલ, મર્જ અથવા દબાણ કરશો નહીં કે બીજું સત્ર કાર્ય કરી રહ્યું છે. [સખત નિયમ 22](HARD_RULES_DETAIL.md) જુઓ.

## ટ્રેન ખેંચવાની વિનંતી

1. વર્તમાન પ્રકાશન આધાર ટીપ પર ટ્રેન શાખા શરૂ કરો. મર્જ કમિટનો ઉપયોગ કરીને ચોક્કસ મંજૂર સભ્ય હેડને એકીકૃત કરો. સ્ક્વોશ અને રિબેઝ ટાળીને તેમના પ્રતિબદ્ધ ઇતિહાસને સાચવો.
2. ટ્રેન શાખા માટે એક પુલ વિનંતી ખોલો. વર્તમાન આધાર ટીપ પર તે PR તેના પોતાના સંપૂર્ણ CI સાથે માન્ય કરો. ઉતરાણ કરતા પહેલા બેઝ ટીપ અને મંજૂર સભ્ય હેડને ફરીથી તપાસો. જ્યારે માન્ય ઉમેદવાર બદલાય ત્યારે ટ્રેન અને તેના CI તાજું કરો.
3. લાગુ પડતા કતાર મોડ હેઠળ મર્જ કમિટ સાથે ટ્રેન PR લેન્ડ કરો. લાઇવ મોડમાં, કતારની `merge-ff` લેન્ડિંગ પદ્ધતિ મર્જ કમિટ્સને સાચવે છે. મૂળ સભ્યના વડાઓ પ્રકાશન શાખામાંથી પહોંચી શકાય છે. GitHub સભ્ય PRs મર્જ કરેલ તરીકે ચિહ્નિત કરે છે અને કમિટ તેમના લેખકોને જાળવી રાખે છે.

જાહેર ઉદાહરણ [PR #21071](https://github.com/cheaper-inference/OmniRoute/pull/21071) છે. તે 18 સભ્યો PRs જોડે છે અને 2026-11-24 ના રોજ મર્જ કમિટ સાથે ઉતરી આવ્યું છે.

`main` થી આગામી પ્રકાશન શાખામાં સિંક-બેક પણ મર્જ કમિટ દ્વારા ઉતરે છે. પાછળથી સિંક-બેક માટે `main` વંશની જાળવણી જરૂરી છે. [વર્કટ્રી આઇસોલેશન](WORKTREE_ISOLATION.md#sync-back-landings-are-merge-commits-never-squash) જુઓ.

## સ્થાનિક મર્જ-ટ્રેન માન્યકર્તા

```bash
scripts/release/merge-train.sh [--plan] [--fast] <base-branch> <PR#> [<PR#>...]
```

વેલિડેટર આધાર અને PR હેડ મેળવે છે અને તેમને નિકાલજોગ વર્કટ્રીમાં જોડે છે. તે પરિણામી વૃક્ષ પર તેના પેરિટી સ્યુટને એકવાર ચલાવે છે. નિષ્ફળ હેડ ફેચ અથવા મર્જ સંઘર્ષ તે PR બહાર કાઢે છે અને સ્ક્રિપ્ટ બાકીના PRs સાથે ચાલુ રહે છે.

- **`--plan`** પસંદ કરેલા મોડના સ્ટેપ્સને પ્રિન્ટ કરે છે અને વર્કટ્રી બનાવ્યા વિના અથવા રિમોટનો સંપર્ક કર્યા વિના બહાર નીકળી જાય છે. ઝડપી યોજનાનું નિરીક્ષણ કરવા માટે તેને `--fast` સાથે જોડો.
- **`--fast`** સામાન્ય સ્થિર દરવાજા ચલાવે છે, `tests/unit/` અને `npm run test:vitest` હેઠળ પસંદ કરેલ બદલાયેલ `node:test` ફાઇલો. ફાસ્ટ મોડનો ઉપયોગ કરતી વખતે સંચિત ટીપ પર દિવસમાં ઓછામાં ઓછું એકવાર સંપૂર્ણ સ્થાનિક માન્યતા ચલાવો.
- **સંપૂર્ણ મોડ** સંપૂર્ણ-માત્ર સ્થિર દરવાજા ઉમેરે છે અને `npm run test:unit` અને `npm run test:vitest` ચલાવે છે.

જો બેઝ પ્રોબ ઉપલબ્ધ હોય તો અસ્પૃશ્ય બેઝ પર નિષ્ફળ સ્ટેટિક ગેટ ફરીથી ચલાવવામાં આવે છે. સ્ક્રિપ્ટ વારસાગત નિષ્ફળતાઓની જાણ કરે છે અને જ્યારે દરેક માન્ય ઉલ્લંઘન રેખા પણ આધાર પર દેખાય છે અને કુલ ગણતરી વધી નથી ત્યારે ચાલુ રહે છે.

| બહાર નીકળો | અર્થ                                                                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `0`        | પ્લાન પ્રિન્ટ કર્યો અથવા સ્યુટ પૂર્ણ કર્યો. સ્યુટ સારાંશ કોઈપણ વારસાગત સ્થિર નિષ્ફળતા અને બહાર કાઢેલ PRs યાદી આપે છે.                      |
| `1`        | અમાન્ય દલીલો, કોઈ Git ચેકઆઉટ નથી, નિષ્ફળ પ્રીફ્લાઇટ, અથવા PR બોર્ડ નથી.                                                                    |
| `2`        | સ્યુટ ચેક નિષ્ફળ ગયો અને વારસાગત તરીકે લાયક ન હતો. ઓપરેટર બેચને દ્વિભાજિત કરી શકે છે, વાંધાજનક PR બહાર કાઢી શકે છે અને ફરીથી ચલાવી શકે છે. |

સ્થાનિક પાસ માત્ર માલિકના ડોઝિયર માટે ડાયગ્નોસ્ટિક પુરાવા પૂરા પાડે છે. દરેક ઉતરાણ માટે હજુ પણ માલિકની અધિકૃતતા, તેની પોતાની જરૂરી તપાસો અને જ્યારે લાગુ પડતી હોય ત્યારે શેડો કતારના ચુકાદાની જરૂર પડે છે.

## ટાયરિંગ

- **PR દીઠ.** CI અને ગુણવત્તાની પસંદગી બદલાયેલ પાથના આધારે તપાસ કરે છે. કોડ PRs ઝડપી ગુણવત્તાવાળા દરવાજા અને અસરગ્રસ્ત પરીક્ષણો ચલાવે છે, CI માં અલગ યુનિટ અને Vitest જોબ્સ સાથે.
- **કતાર ઉમેદવાર દીઠ.** CI અને ગુણવત્તા તેના કતાર રેફ પર કમ્પોઝ કરેલ ઉમેદવાર માટે સંપૂર્ણ પ્રોફાઇલ ચલાવે છે.
- **પ્રકાશન ટીપ દીઠ.** રીલીઝ-ગ્રીન તેના પાથ ફિલ્ટર્સ સાથે મેળ ખાતા પુશ પર ઝડપી હાર્ડ ગેટ ચલાવે છે. દરરોજ ત્રણ સુનિશ્ચિત રન પ્રકાશન શાખા માટે સંપૂર્ણ સ્વીપનો ઉપયોગ કરે છે.
- **પ્રકાશન દીઠ.** સંપૂર્ણ CI મેટ્રિક્સમાં E2E શાર્ડ્સ, પેકેજ માન્યતા, ટારબોલ બૂટ સ્મોક અને કવરેજ તપાસનો સમાવેશ થાય છે. [પ્રકાશન ચેકલિસ્ટ](RELEASE_CHECKLIST.md) જુઓ.

## `merge-train.sh` માટે ફ્રેશ-ચેકઆઉટ પૂર્વજરૂરીયાતો

વર્કટ્રીસ બનાવતા પહેલા પ્રીફ્લાઇટ ચાલે છે. `npm ci` સાથે નિર્ભરતા સ્થાપિત કરો. પુષ્ટિ કરો કે `node_modules/.bin/tsc` એક્ઝિક્યુટેબલ છે અને તે `node_modules/node_modules` ગેરહાજર છે. તપાસો કે `node_modules/.bin/bun --version` સફળ થાય છે.

જો Bun પોસ્ટઇન્સ્ટોલ છોડવામાં આવ્યું હોય, તો `(cd node_modules/bun && node install.js)` ચલાવો. પ્રદાતા સુસંગતતા અને જાણીતા-પ્રતીક તપાસો Bun ઉપયોગ કરે છે. વેલિડેટર `npm run check:cycles:ratchet` બ્લોકીંગ ગેટ તરીકે ચલાવે છે. સ્ટેન્ડઅલોન `npm run check:cycles` આદેશ સલાહકારી છે.
