## npm ટ્રસ્ટેડ પબ્લિશિંગ (v3.8.51 થી ડિફોલ્ટ) — વિનંતી પર સ્ટેજ, ફૉલબેક તરીકે ડાયરેક્ટ

`npm-publish.yml` દ્વારા પ્રકાશિત થાય છે** npm ટ્રસ્ટેડ પબ્લિશિંગ (OIDC)** મૂળભૂત રીતે: `stage-npm` જોબ (ગીથબ-હોસ્ટેડ) તે રન માટે ટૂંકા ગાળાના npm ઓળખપત્ર માટે GitHub ના id-ટોકનનું વિનિમય કરે છે. રિપોઝીટરી સિક્રેટ્સમાં — લાંબા ગાળાના npm ટોકન નથી, કોઈ 2FA પ્રોમ્પ્ટ, પ્રોવેનન્સ જોડાયેલ નથી. તે હવે બાયપાસ એનપીએમ પ્રતિબંધો છે કે જે ટોકન્સ 2FA છોડે છે તે નિવૃત્ત કરવામાં આવી રહ્યા છે; તે WS1.3 ગેરંટી રાખતી વખતે પ્રોજેક્ટમાં v3.8.48 સુધીનો સંપૂર્ણ સ્વચાલિત પ્રવાહ પુનઃસ્થાપિત કરે છે (લીક થયેલ ટોકન એકલા — પ્રકાશિત કરી શકતું નથી ત્યાં કોઈ ટોકન નથી).

**વન-ટાઇમ સેટઅપ (માલિક):** npmjs.com → પેકેજ `omniroute` → સેટિંગ્સ → _Trusted Publisher_ → GitHub: માલિક `diegosouzapw`, રેપો `OmniRoute`, વર્કફ્લો `npm-publish.yml` (પર્યાવરણ: કોઈ નહીં). જ્યાં સુધી તે અસ્તિત્વમાં ન હોય ત્યાં સુધી, સ્વચાલિત પગલું `ENEEDAUTH` સાથે નિષ્ફળ જાય છે : `publish_mode=staged` (નીચે) અથવા `direct` સાથે ફરીથી મોકલો.

### તબક્કાવાર પ્રકાશન (વિનંતિ — `publish_mode=staged` પર)

npm-publish વર્કફ્લો હવે સીધો પ્રકાશિત થતો નથી: તે પેક્ડ ટારબોલ (`check:pack-boot`) ને બુટ કરે છે અને પછી `npm stage publish` — ચલાવે છે ચોક્કસ બાઇટ્સ રજિસ્ટ્રી પર પાર્ક કરવામાં આવે છે,** ઇન્સ્ટોલ કરી શકાય તેવું નથી** જ્યાં સુધી માલિક મંજૂર ન કરે. માનવ 2FA ગેટ AFTER પુરાવા માટે ખસેડવામાં આવ્યો, તેની પહેલાં નહીં.

**વર્કફ્લો લીલો થઈ જાય પછી માલિકનો પ્રવાહ:**

1. `npm stage list omniroute` — સ્ટેજ આઈડી શોધો (વર્કફ્લો સારાંશમાં પણ મુદ્રિત).
2. સ્ટેજ કરેલ બાઇટ્સ ચકાસો (ભલામણ કરેલ): `npm stage download <id>`, પછી ડાઉનલોડ કરેલ ટારબોલને ટેમ્પ પ્રીફિક્સમાં ઇન્સ્ટોલ કરો અને તેને બુટ કરો (`npm run check:pack-boot` એ જ પેકને સ્વચાલિત કરે છે→CI માં→ બૂટ ચુકાદો ઇન્સ્ટોલ કરે છે).
3. `npm stage approve <id>` — ધ 2FA પ્રોમ્પ્ટ IS પ્રકાશિત કરો. `npm stage reject <id>` કાઢી નાખે છે.
4. પોસ્ટ-પબ્લિશ નેટ: પોસ્ટ-પબ્લિશ વેરિફાયર ( v3.8.49 પ્લાનનુંWS1.4) સાર્વજનિક રજિસ્ટ્રીમાંથી પ્રકાશિત સંસ્કરણને સ્વચ્છ કન્ટેનરમાં ઇન્સ્ટોલ કરે છે અને તેને બૂટ કરે છે.

**ઇમર્જન્સી ફોલબેક:** `publish_mode=direct` સાથે `workflow_dispatch` વારસાને તાત્કાલિક `npm publish` પુનઃસ્થાપિત કરે છે (જો સ્ટેજિંગ પોતે ગેરવર્તન કરે તો જ ઉપયોગ કરો; શા માટે રેકોર્ડ કરો).

**વન-ટાઇમ સખ્તાઇ (માલિક, npmjs.com):** માત્ર સ્ટેજ મોડમાં `omniroute` માટે ટ્રસ્ટેડ પબ્લિશરને ગોઠવો જેથી લીક થયેલ લાંબો સમય ટકી રહેલું ટોકન સીધું ગમે ત્યાંથી `npm publish` કરી શકતું નથી — CI માત્ર સ્ટેજ કરી શકે છે; માત્ર માલિકની 2FA રિલીઝ.

**તૂટેલી-આર્ટિફેક્ટ પ્લેબુક (અપરિવર્તિત):** `npm deprecate omniroute@<bad> "<reason> — use <fixed>"` મૂળભૂત રીફ્લેક્સ તરીકે (મિનિટ, ઉલટાવી શકાય તેવું); `npm unpublish` માત્ર 72h/no-dependents વિન્ડોની અંદર અને પ્રથમ ચાલ તરીકે ક્યારેય નહીં. Docker: સંસ્કરણ ટેગ ક્યારેય ફરીથી લખશો નહીં — રોલબેક `latest` છેલ્લા સારા ડાયજેસ્ટ પર ફરીથી નિર્દેશિત કરી રહ્યું છે.

**Docker હબ `latest` (દરેક સ્થિર SemVer પ્રકાશન પર જરૂરી છે):** `docker-publish` વર્કફ્લોને ટેગ કરવું આવશ્યક છે** બંને** `X.Y.Z` અને, જ્યારે `should-promote-latest.sh` સંમત થાય છે ત્યારે આ સૌથી વધુ સ્થિર SemVer છે, `:latest` સાથે** સમાન પાચન** . નોકરી પછી: હબ `latest` ડાયજેસ્ટ નવા SemVer ડાયજેસ્ટ અને `last_updated` ખસેડવામાં આવે છે. `:latest` જૂની બિલ્ડ પર છોડશો નહીં જ્યારે રીલીઝ નોટ્સ ફિક્સેસ વિશે વાત કરે છે જે ફક્ત git પર અસ્તિત્વ ધરાવે છે. કંપોઝ ક્વિકસ્ટાર્ટ્સ `:latest` ઉપયોગ કરે છે; GitOps `X.Y.Z` પિન કરતા રહેવું જોઈએ. [Docker રિલીઝ ચેનલો](../guides/DOCKER_GUIDE.md#release-channels) અને #10317 જુઓ.

**Docker હબ સંસ્થા ભંડાર (`cheaperinference/omniroute`):** Docker હબ નેમસ્પેસ વચ્ચે રીપોઝીટરીને ખસેડી શકતું નથી, તેથી `diegosouzapw/omniroute` તેનો પુલ હિસ્ટ્રી અને દરેક રીલીઝ રાખે છે, અને `docker-publish` નું `mirror-org-dockerhub` જોબ `ghcr.io/cheaper-inference/omniroute` થી ઓર્ગેનાઈઝેશન રીપોઝીટરીમાં દરેક રીલીઝ થયેલ વર્ઝન (અને `:latest` જ્યારે પ્રમોટ કરવામાં આવે છે) ની નકલ કરે છે. તેને `DOCKERHUB_ORG_USERNAME` / `DOCKERHUB_ORG_TOKEN` રહસ્યોની જરૂર છે; તેમના વિના જોબ "Docker Hub org mirror skipped" ચેતવણી સાથે લીલી રહે છે અને અન્ય રજિસ્ટ્રી સામાન્ય રીતે પ્રકાશિત થાય છે. ત્યાં પછીથી પ્રકાશિત સંસ્કરણ પ્રકાશિત કરવા માટે, ચલાવો** ક્રિયાઓ → મિરર Docker ઇમેજને Docker હબ org → રન વર્કફ્લો** `version=X.Y.Z` (અને ઉચ્ચતમ સ્થિર સંસ્કરણ માટે `promote_latest` ): તે હાલની છબીઓની નકલ કરે છે, કોઈ પુનઃબીલ્ડ નથી. તે રીપોઝીટરીનું Docker હબ વિહંગાવલોકન હાથ દ્વારા સેટ કરવામાં આવ્યું છે: API કે જે તેને સંપાદિત કરે છે તે સંસ્થા એક્સેસ ટોકન્સને નકારે છે.

## હોટફિક્સ ફાસ્ટ-લેન (લેબલ `hotfix`)

`hotfix` લેબલ ધરાવતું PR ભારે CI મેટ્રિક્સ (9-શાર્ડ E2E, કવરેજ રેચેટ,
ક્વૉલિટી-ગેટ, ક્વૉલિટી-એક્સ્ટેન્ડેડ)ને સ્કિપ કરે છે અને ઝડપી, ઉચ્ચ-સિગ્નલ ગેટ્સ જાળવી રાખે છે: બિલ્ડ,
યૂનિટ શાર્ડ્સ, ઇન્ટિગ્રેશન, vitest, lint/typecheck, docs-sync, `check:pack-artifact`
અને ટારબૉલ બૂટ-સ્મોક (`check:pack-boot`). લક્ષ્ય: લગભગ 33 મિનિટની બદલે ≤15 મિનિટમાં લીલું પરિણામ.

**પ્રવેશ નીતિ — ચારેય જરૂરી (Chromium/VS Code/Node ઇમર્જન્સી લેનના આધારે):**

1. **તીવ્રતા**: પ્રોડક્શન તૂટી ગયું છે — પ્રકાશિત આર્ટિફેક્ટ બૂટ સમયે ક્રેશ થાય છે / સુરક્ષા સુધારો છે / રિલીઝનો દરેક વપરાશકર્તા અસરગ્રસ્ત છે. "મહત્વપૂર્ણ" એટલે "તૂટેલું" નથી.
2. **સત્તા**: માત્ર રિપોઝિટરીનો માલિક `hotfix` લેબલ લાગુ કરે છે. લેબલ જ મંજૂરી છે — કેમ્પેઇન PR પર ક્યારેય સ્વ-સેવા ન કરવી.
3. **પુરાવો**: PR બૉડીમાં અગાઉના સંપૂર્ણ-લીલા ભારે રન (જે સ્કિપ થયેલી જોબ્સને ફરી માન્ય કરશે તે સ્યુટ) તેમજ ફિક્સના પોતાના નિષ્ફળ-પછી-પાસ થયેલા ટેસ્ટની લિંક હોવી જોઈએ.
4. **સ્કોપ**: માત્ર cherry-pick — ન્યૂનતમ ફિક્સ, કોઈ રિફેક્ટર નહીં, કોઈ સાથોસાથના ફેરફારો નહીં.

સ્કિપ થયેલી કવરેજ/રેચેટ સપાટી રિલીઝ બ્રાન્ચ પરના આગામી સંપૂર્ણ રન દ્વારા ફરી માન્ય કરવામાં આવે છે
(સતત release-green) — લેન WAITINGને સ્કિપ કરે છે, માન્યતાને નહીં.
માત્ર ટેસ્ટવાળા ડિફ્સ (બધી ફાઇલો `tests/` હેઠળ, `tests/e2e/` હેઠળ એકપણ નહીં) E2E
મેટ્રિક્સને આપમેળે સ્કિપ કરે છે, કોઈ લેબલ વિના.

### લેઆઉટ બનાવો

રિપોઝીટરી ત્રણ અલગ-અલગ આઉટપુટ ડિરેક્ટરીઓનો ઉપયોગ કરે છે — તેમને ક્યારેય મિશ્રિત કરતું નથી:

| ડિરેક્ટરી | હેતુ                                                       | ટ્રૅક કર્યું? |
| --------- | ---------------------------------------------------------- | ------------- |
| `src/`    | એપ્લિકેશન સ્ત્રોત (TypeScript / TSX)                       | હા            |
| `.build/` | મધ્યવર્તી — `next build` આઉટપુટ બનાવો (`distDir`)          | ના (અવગણાયેલ) |
| `dist/`   | `assembleStandalone` દ્વારા એસેમ્બલ કરેલ શિપેબલ npm બંડલ — | ના (અવગણાયેલ) |

> **ઓપરેટરની નોંધ:** રિમોટ VPS ઇમેજ ડિરેક્ટરી `/usr/lib/node_modules/omniroute/app/` રહે છે. માત્ર આ** ઇન-રેપો** બિલ્ડ આઉટપુટ ખસેડ્યું (`app/` → `dist/`). રિમોટ `app/` dir — no VPS પાથ ફેરફારોની આવશ્યકતામાં કૌશલ્યો rsync `dist/` સમાવિષ્ટો ગોઠવે છે.

**સિંગલ-બિલ્ડ ફ્લો:**

```
npm run build:release
  └─ rm -rf .build dist          (clean)
  └─ next build → .build/next/   (intermediates)
  └─ assembleStandalone          (copies standalone + static + public + natives → dist/)
  └─ writes dist/BUILD_SHA       (HEAD sentinel)
```

શું NOT ચલાવો `npm run build` જમાવવા માટે અલગ `npm run build:cli` પછી — નો ઉપયોગ કરો `npm run build:release` જે એક આદેશમાં સ્વચ્છ + કરે છે.

## 3.9.0 LTS કટ (3.8.58 માં રિહર્સલ)

v3.8.59 પછી આગળનું સંસ્કરણ 3.9.0 છે, અને તેની ટોચ બે લાંબા સમય સુધી ચાલતી શાખાઓ બની જાય છે: `stable/v3` (v3 LTS લાઇન, npm `latest`) અને `develop` (v4, 4.0.0 પર ટક્કર, npm `nightly`). branch/channel મોડેલ, ફોરવર્ડ-પોર્ટ અને લેબલ્સ [RELEASE_STRATEGY.md](./RELEASE_STRATEGY.md) માં છે; યોજના [ROADMAP](../../ROADMAP.md) (તબક્કો 3) માં છે. કટ એકવાર ચાલે છે; 3.8.58 તેને ફોર્ક પર અંતથી અંત સુધી રિહર્સલ કરે છે, અને 3.8.59 [GO/NO-GO ચેકલિસ્ટ](./LTS_GO_NO_GO.md) સાથે બંધ થાય છે.

### ડ્રાય-રન (ફક્ત વાંચવા માટે, કોઈપણ સમયે સલામત)

```bash
npm run release:dry-run-lts-cut                       # the real cut: 3.9.0 from HEAD, previous tag v3.8.59
npm run release:dry-run-lts-cut -- --from <3.9.0-tip> # pin the source commit
```

`scripts/release/dry-run-lts-cut.mjs` કંઈપણ ચલાવતું નથી: તે git અને `gh` વાંચે છે અને સમગ્ર ક્રમ — પૂર્વશરતોને છાપે છે (સ્રોત ઉકેલો, સ્ત્રોત રીપોઝીટરીનો સંપૂર્ણ ઇતિહાસ — છે છીછરો ક્લોન `stable/v3` દબાણ કરી શકતો નથી, પ્રાપ્ત કરનાર બાજુ પ્રથમ કલમી પેરેન્ટ પર પેકને નકારી કાઢે છે, તેથી પહેલાના — ટેગને કાપી નાખો અથવા પહેલાના `git fetch --unshallow origin` ટેગમાંથી અસ્તિત્વમાં છે. `package.json` એ લક્ષ્ય સંસ્કરણ છે, `release-freeze` મુદ્દો ખુલ્લો છે, હાલની પ્રકાશન શાખા પર કોઈ ખુલ્લી `Release branch not green` સમસ્યા નથી — જે શાખા અસ્તિત્વમાં નથી `release/*` `?` અજ્ઞાત અહેવાલ આપે છે, ક્યારેય ગ્રીન — ઑમ્ની-ક્યૂ રિલીઝ PRs પર ઉતરતી નથી (G11: `config/merge-queue/config.json` માન્ય છે, તેનું `bases` પ્રકાશન શાખાનું સંચાલન કરે છે, `mode` `live` તેના નિયમો હજુ પણ અસ્તિત્વમાં છે) ડિલીશન અને ફોર્સ-પુશ, અને `stable/v3` અને `develop` હજી અસ્તિત્વમાં નથી), બે શાખા પગલાઓ, જે નિષ્ક્રિય-વર્કફ્લો ટ્રિગર કરે છે અને `if:` શરતો સાચી થાય છે (અને જે રિપોઝીટરી વેરીએબલ દ્વારા ગેટેડ રહે છે અથવા કેનોનિકલ રિપોઝીટરી પર પિન કરે છે), અપેક્ષિત ડિસ્ટ-ટેગ્સ (`latest` → 3.qz `next` અને `nightly` ) અને. `0` = `RESULT: READY` થી બહાર નીકળો , `1` = અવરોધિત કરવાની પૂર્વશરત નિષ્ફળ (`✗`), `2` = વપરાશ ભૂલ. `--advisory <id,...>` ચેકને છુપાવ્યા વિના ચેતવણી (`!`) પર ડાઉનગ્રેડ કરે છે.

વાસ્તવિક કટના ડ્રાય-રન ચલાવો જ્યારે 3.9.0 રીલીઝ ફ્રીઝ હજુ પણ ખુલ્લું છે — ટેગ પછી અને તબક્કો 12c ફ્રીઝ ઉપાડે તે પહેલાં શાખાઓ બનાવવામાં આવે છે.

### 3.8.58 રિહર્સલ (ફક્ત કાંટો)

```bash
# 1. Dry-run on the current tip with rehearsal parameters
npm run release:dry-run-lts-cut -- --target-version 3.8.58 --previous-tag v3.8.57 \
  --advisory freeze,base-green

# 2. Execute against a FORK remote (origin, or any remote whose URL is the canonical
#    repository, is refused; every step asks for confirmation on the terminal)
git remote add rehearsal https://github.com/<you>/OmniRoute.git
node scripts/release/dry-run-lts-cut.mjs --execute --remote rehearsal \
  --target-version 3.8.58 --previous-tag v3.8.57 --advisory freeze,base-green

# 3. Exercise the dormant workflows in the fork (workflow_dispatch where the dry-run
#    reports a canonical-repository pin), then roll back
node scripts/release/dry-run-lts-cut.mjs --execute --rollback --remote rehearsal \
  --target-version 3.8.58 --previous-tag v3.8.57 --advisory freeze,base-green
```

ડેવલપ બમ્પ કમિટ ગિટ પ્લમ્બિંગ સાથે બનેલ છે (કોઈ વર્કિંગ ટ્રી ટચ નથી) અને સાયકલ-ઓપન કમિટ જેવી જ પાંચ ફાઇલોને બમ્પ કરે છે: `package.json`, `open-sse/package.json`, `electron/package.json`, `package-lock.json` અને `docs/openapi.yaml`. `[4.0.0]` CHANGELOG વિભાગ અને તેના i18n મિરર્સ `develop` પર તેના પ્રથમ PR પહેલા ખોલવામાં આવે છે. સ્ક્રિપ્ટ કદી npm ડિસ્ટ-ટેગ્સ — રિહર્સલ કરે છે તે સ્ક્રેચ પેકેજ પર બદલાતી નથી.

### PR પૂર્વાવલોકન આર્ટિફેક્ટ (એકવાર બનાવો, સમાન બાઇટ્સનો પ્રચાર કરો)

`.github/workflows/preview-artifact.yml` PR હેડમાંથી એક પ્રોડક્શન ટારબોલ બનાવે છે અને તે ચોક્કસ બિલ્ડ (#8084 સ્લાઇસ (a))ને માન્ય કરે છે. માત્ર સેમ-રિપોઝીટરી PRs ; કંઈ પ્રકાશિત નથી.

```bash
gh workflow run preview-artifact.yml -f pr_number=<N>   # or add the `preview-artifact` label
gh run download <run-id> --name preview-artifact-pr<N>-<sha7> --dir preview
cd preview && sha256sum -c SHA256SUMS
gh attestation verify omniroute-*.tgz --repo cheaper-inference/OmniRoute
npm install -g ./omniroute-*.tgz                          # preview install
```

રન `npm ci`, `npm run build:release`, `npm run check:pack-artifact`, ટારબોલને પેક કરે છે, `npm run check:pack-boot` (નકલી રહસ્યો, ક્ષણિક ડેટા ડીર) ચલાવે છે, ફરીથી પેક કરે છે અને નિષ્ફળ જાય છે સિવાય કે ડાયજેસ્ટ સમાન હોય, પછી `artifact-identity.json` રેકોર્ડ કરે છે (હેડ SHA, બેઝ SHA, lockfile હેશ, bqunde પોલિસી, બીલ્ડ પોલિસી, બિલ્ડ ABI, પ્લેટફોર્મ — `scripts/release/artifact-identity.mjs`) અને ટારબોલને અલગ કામમાં પ્રમાણિત કરે છે. પૂર્વાવલોકનનો પ્રચાર કરવાનો અર્થ એ છે કે તે ટારબોલ ઇન્સ્ટોલ કરવું: સ્ત્રોતમાંથી ક્યારેય પુનઃબીલ્ડ કરશો નહીં.

### કટ (3.9.0, GO પછી)

1. GO [LTS_GO_NO_GO માં નોંધાયેલ છે .md](./LTS_GO_NO_GO.md).
2. `npm run release:dry-run-lts-cut -- --from v3.9.0` `RESULT: READY` પ્રિન્ટ કરે છે.
3. Create the branches on `origin` by hand with the commands the dry-run prints — the script refuses to push to `origin`. To reuse a reviewed develop commit, run the `--execute` rehearsal on the 3.9.0 tip against your fork first; it prints both SHAs, and the same commits can be pushed:

   ```bash
   git push origin <stable-sha>:refs/heads/stable/v3 <develop-sha>:refs/heads/develop
   ```

4. પ્રથમ PR ઉતરતા પહેલા `stable/v3` અને `develop` (નિયમો + મર્જ કતાર) ને સુરક્ષિત કરો.
5. નિષ્ક્રિય વર્કફ્લો શાખાના અસ્તિત્વ દ્વારા સ્વિચ કરે છે: `forward-port.yml` ( `stable/v3` પર દબાણ કરો), `validate-stable-pr.yml` (PRs થી `stable/v3`) અને `nightly-v4-build.yml` ( `develop` બનાવે છે). ગો-લાઇવ પહેલાં, `secrets.FORWARD_PORT_TOKEN` રિપોઝીટરી સિક્રેટ સેટ કરો (જેથી CI ફોરવર્ડ-પોર્ટ PRs પર ચાલે છે); જ્યાં સુધી માલિક રીપોઝીટરી વેરીએબલ `vars.NIGHTLY_PUBLISH` ને `true` પર સેટ ન કરે અને npm ટ્રસ્ટેડ પબ્લિશિંગ `nightly-v4-build.yml` સ્વીકારે ત્યાં સુધી રાત્રિ પ્રકાશન બંધ રહે છે. ચેનલ રિઝોલ્યુશન `scripts/release/dist-tag.mjs` છે, તે જ રિઝોલ્વર `npm-publish.yml` વાપરે છે.
6. ચેનલો ચકાસો: `npm view omniroute dist-tags --json` `latest` = 3.9.0 બતાવે છે અને v4 પ્રકાશિત થાય ત્યાં સુધી `next` / `nightly` નહીં.
7. રોલબેક, જો જરૂરી હોય તો: `git push origin --delete refs/heads/stable/v3 refs/heads/develop` અને `npm dist-tag add omniroute@3.8.59 latest`.

## રોલબેક

જો રિલીઝમાં ગંભીર સમસ્યા હોય:

1. `gh release edit vX.Y.Z --prerelease` (તેને નવીનતમ રિલીઝ તરીકે ચિહ્નિત થતું અટકાવે છે)
2. `git tag -d vX.Y.Z && git push --delete origin vX.Y.Z` (ફક્ત ત્યારે જ, જો વપરાશકર્તાઓએ હજી તેને અપનાવી ન હોય)
3. અથવા: `release/vX.Y.0` પર હોટફિક્સ → પેચ રિલીઝ `vX.Y.(Z+1)`
4. GitHub Discussions અને Discord પર તરત જ જાણ કરો

- ક્યારેય સિક્રેટ્સ, ઓળખપત્રો અથવા `.env` ફાઇલો કમિટ ન કરો
- કવરેજ ≥60/60/60/60 (સ્ટેટમેન્ટ્સ/લાઇન્સ/ફંક્શન્સ/બ્રાન્ચિસ) જળવાઈ રહેવું આવશ્યક છે
- `src/`, `open-sse/`, `electron/`, અથવા `bin/` માં પ્રોડક્શન કોડ બદલતી વખતે હંમેશાં ટેસ્ટ્સ ઉમેરો અથવા અપડેટ કરો

## સ્વચાલિત સિંક તપાસ

PR ખોલતા પહેલાં સ્થાનિક રીતે દસ્તાવેજોનું સિંક ગાર્ડ ચલાવો:

```bash
npm run check:docs-sync
```

CI આ તપાસ `.github/workflows/ci.yml` (લિન્ટ જોબ) માં પણ ચલાવે છે.
