Web Cookie પ્રદાતાઓ OmniRouteને API keyને બદલે તમારા હાલના બ્રાઉઝર સત્ર દ્વારા AI સેવાનો ઉપયોગ કરવાની મંજૂરી આપે છે. જ્યારે તમારી પાસે પહેલેથી જ કોઈ સેવાની વેબસાઇટ દ્વારા તેની ઍક્સેસ હોય અને તમે OmniRoute દ્વારા એ જ પ્રમાણિત સત્રનો ઉપયોગ કરાવવા માંગતા હો ત્યારે તેઓ ઉપયોગી છે.

API-key પ્રદાતાઓથી વિપરીત, Web Cookie પ્રદાતાઓ તમારું બ્રાઉઝર વેબસાઇટને મોકલે છે તે ઓળખપત્રોનો ઉપયોગ કરીને પ્રમાણીકરણ કરે છે.

# શરૂ કરતાં પહેલાં

> **મહત્વપૂર્ણ:** ઓળખપત્રો હંમેશાં **સક્રિય નેટવર્ક વિનંતી**માંથી કૉપિ કરો, તમારા બ્રાઉઝરના cookie storageમાંથી **નહીં**.

ઘણી પ્રમાણીકરણ સમસ્યાઓ ખોટી જગ્યાએથી cookies કૉપિ કરવાને કારણે થાય છે.

## Cookie Storageમાંથી કૉપિ કરશો નહીં

મોટાભાગનાં બ્રાઉઝર્સ સંગ્રહિત cookiesને આના દ્વારા ઉપલબ્ધ કરાવે છે:

```
DevTools
→ Application (or Storage)
→ Cookies
```

આ cookies યોગ્ય દેખાતી હોવા છતાં, તે નીચે મુજબ હોઈ શકે છે:

- જૂની
- અપૂર્ણ
- માત્ર પ્રમાણિત વિનંતીઓ પર મોકલાતી cookies વિનાની

આ મૂલ્યો માન્ય દેખાતા હોવા છતાં તેમનો ઉપયોગ પ્રમાણીકરણ નિષ્ફળતાઓનું કારણ બની શકે છે.

## સક્રિય વિનંતીમાંથી કૉપિ કરો

તેના બદલે, સફળ વિનંતીની cookiesનો ઉપયોગ કરો:

```
DevTools
→ Network
→ Refresh the page
→ Open a chat or conversation request
→ Request Headers
→ Cookie
```

`Cookie` વિનંતી હેડરમાં તે ચોક્કસ પ્રમાણીકરણ માહિતી હોય છે જેનો તમારા બ્રાઉઝરે સફળતાપૂર્વક ઉપયોગ કર્યો હતો.

મોટાભાગના Web Cookie પ્રદાતાઓ માટે, આ જ મૂલ્ય OmniRouteમાં પેસ્ટ કરવું જોઈએ.

# સામાન્ય સેટઅપ

મોટાભાગના Web Cookie પ્રદાતાઓ માટે સેટઅપ પ્રક્રિયા સમાન છે.

1. પ્રદાતાની વેબસાઇટમાં સાઇન ઇન કરો.
2. બ્રાઉઝરના Developer Tools ખોલો.
3. **Network** ટૅબ ખોલો.
4. પેજ રિફ્રેશ કરો.
5. પ્રમાણિત chat અથવા conversation વિનંતી ખોલો.
6. જરૂરી પ્રમાણીકરણ ઓળખપત્રો કૉપિ કરો.
7. OmniRoute ખોલો.
8. **Providers → Add Provider** પર જાઓ.
9. તમારો Web Cookie પ્રદાતા પસંદ કરો.
10. ઓળખપત્રો પેસ્ટ કરો.
11. **Test Connection** પર ક્લિક કરો.
12. પ્રદાતાને સાચવો.

જરૂરી ચોક્કસ ઓળખપત્રો પ્રદાતા પર આધાર રાખે છે.

| પ્રદાતા                         | ઓળખપત્ર ફોર્મેટ               | પ્રદાતા માર્ગદર્શિકા             |
| ------------------------------- | ----------------------------- | -------------------------------- |
| Claude Web                      | સંપૂર્ણ Cookie વિનંતી હેડર    | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | સંપૂર્ણ Cookie હેડર           | `docs/providers/CHATGPT_WEB.md`  |

| Copilot Web                     | _(ચકાસો)_                     | `docs/providers/COPILOT-M365.md` |

| Grok Web                        | _(ચકાસો)_                     |                                  |
| ...                             | ...                           | ...                              |

> નવા Web Cookie પ્રદાતાઓ ઉમેરવામાં આવે અથવા હાલના પ્રદાતાઓની પ્રમાણીકરણ આવશ્યકતાઓ બદલાય ત્યારે આ કોષ્ટક અપડેટ કરો.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) એક મફત ગ્રાહક ચેટ પ્લેટફોર્મ છે, જેમાં સાઇન અપ કરવાની જરૂર નથી — પ્રથમ મુલાકાત વખતે સત્ર અનામી રીતે બનાવવામાં આવે છે અને ત્રણ કૂકીઝ દ્વારા જળવાઈ રહે છે: `uid`, `si_usr_id`, અને `si_ses_id`. OmniRoute એ જ `/api/dispatch` એન્ડપોઇન્ટને એક જ મોડેલ id (`notrack-c`, ઉપનામ `ntw`) દ્વારા પ્રોક્સી કરે છે.

### કનેક્ટ કરવાનાં પગલાં

1. તમારા બ્રાઉઝરમાં [notrack.ai](https://notrack.ai) ખોલો અને અનામી સત્ર કૂકી સેટ થવા દો.
2. **DevTools → Network** ખોલો, પેજ રિફ્રેશ કરો અને કોઈપણ `/api` વિનંતી પર ક્લિક કરો.
3. **Request Headers** માંથી સંપૂર્ણ `Cookie` હેડર મૂલ્ય કૉપિ કરો.
4. OmniRoute માં **Providers → Add Provider → NoTrack Web (Free)** પર જાઓ.
5. કૂકી સ્ટ્રિંગને `apiKey` ફીલ્ડમાં પેસ્ટ કરો અને **Save** કરો.

OmniRoute પેસ્ટ કરેલી સ્ટ્રિંગમાંથી `uid`, `si_usr_id`, અને `si_ses_id` કાઢે છે અને માત્ર એ જ જોડીઓ સાથે સ્વચ્છ `Cookie` હેડર ફરીથી બનાવે છે — ઉપરાંત, જ્યારે ઉપલબ્ધ હોય ત્યારે `nt_session` (લૉગ ઇન કરેલા એકાઉન્ટ્સ માટે સેટ થતું `ntk_…` ટોકન) પણ ઉમેરે છે. જો ત્રણમાંથી કોઈપણ એક ગેરહાજર હોય, તો ઑપરેટર્સ વૈકલ્પિક સ્વરૂપો સાથે પ્રયોગ કરી શકે તે માટે પેસ્ટ કરેલી મૂળ સ્ટ્રિંગ કોઈ ફેરફાર વિના ફૉર્વર્ડ કરવામાં આવે છે.

### મોડેલ ids

| મોડેલ id    | પ્રદર્શિત નામ | નોંધો                                                  |
| ----------- | ------------- | ------------------------------------------------------ |
| `notrack-c` | NoTrack C     | ડિફૉલ્ટ — અપસ્ટ્રીમ ડિસ્પૅચ મોડેલ `C`.                 |
| `C`         | NoTrack C     | `notrack-c` માટેનું ઉપનામ (મૂળ અપસ્ટ્રીમ ડિસ્પૅચ કોડ). |
| `notrack`   | NoTrack C     | `notrack-c` માટેનું ઉપનામ.                             |
| `ntw`       | NoTrack C     | `notrack-c` માટેનું ટૂંકું ઉપનામ.                      |

ચારેય મોડેલ ids સમાન અપસ્ટ્રીમ ડિસ્પૅચ મોડેલ (`C`) સાથે મેપ થાય છે.

### વિનંતીના વિકલ્પો

એક્ઝિક્યુટર વિનંતી બોડીમાં આ વૈકલ્પિક ફીલ્ડ્સ સ્વીકારે છે:

| બોડી ફીલ્ડ            | ડિફૉલ્ટ | હેતુ                                                                  |
| --------------------- | ------- | --------------------------------------------------------------------- |
| `notrack_mode`        | `usual` | ડિસ્પૅચ મોડ (મુક્ત-સ્વરૂપ સ્ટ્રિંગ; અપસ્ટ્રીમ `usual`, … સ્વીકારે છે) |
| `notrack_max_turns`   | `6`     | જવાબ આપતા પહેલાં અપસ્ટ્રીમ લઈ શકે તેવા આંતરિક ટર્ન્સની સંખ્યા.        |
| `notrack_chat_id`     | `null`  | હાલની અપસ્ટ્રીમ ચેટ ફરી શરૂ કરો (નવી ચેટ માટે તેને છોડો).             |
| `notrack_attachments` | `[]`    | અપસ્ટ્રીમ અટૅચમેન્ટ વર્ણનકારોની પાસ-થ્રૂ એરે.                         |
| `notrack_regenerate`  | `false` | અગાઉના ટર્ન માટે ફરીથી જનરેટ કરેલો જવાબ મેળવવા `true` સેટ કરો.        |

### ક્ષમતાઓ

- **સ્ટ્રીમિંગ અને નૉન-સ્ટ્રીમિંગ** ચેટ પૂર્ણતાઓ.
- **ટૂલ કૉલિંગ** — વિનંતીમાં `tools: [...]` સેટ કરો; એક્ઝિક્યુટર તેમને ટૂલ-કૉલ એન્વલપ કોન્ટ્રાક્ટમાં સીરિયલાઇઝ કરે છે અને મોડેલના પ્રતિસાદોને ફરીથી OpenAI `tool_calls` માં પાર્સ કરે છે.
- **`response_format`** — `json_object` અને `json_schema` સપોર્ટેડ છે. એક્ઝિક્યુટર મોડેલના જવાબમાંથી પ્રથમ JSON ઑબ્જેક્ટ કાઢે છે અને તેને પરત કરતાં પહેલાં સ્ટ્રિંગમાં રૂપાંતરિત કરે છે.
- **રીઝનિંગ સંકેત** — જ્યારે અપસ્ટ્રીમ `thinking` ઇવેન્ટ મોકલે છે, ત્યારે એક્ઝિક્યુટર `reasoning` ડેલ્ટા ઉત્સર્જિત કરે છે.

### મર્યાદાઓ

- અપસ્ટ્રીમ અનામી વપરાશ ક્વોટા લાગુ કરે છે — જ્યારે તે મર્યાદા વટાય છે, ત્યારે એક્ઝિક્યુટર વપરાશકર્તા-મૈત્રીપૂર્ણ સંદેશ સાથે 429 દર્શાવે છે.
- બધા મોડેલ ids સમાન અપસ્ટ્રીમ ડિસ્પૅચ મોડેલ પર રિઝૉલ્વ થાય છે; દરેક મોડેલ માટે અલગ સ્વિચ નથી.
- એક્ઝિક્યુટર અપસ્ટ્રીમના `/api/chats` એન્ડપોઇન્ટને કૉલ કરતું નથી, તેથી ચેટ ઇતિહાસ / સત્રો આપમેળે મેનેજ થતા નથી. હાલની અપસ્ટ્રીમ ચેટ ફરી શરૂ કરવા માટે `notrack_chat_id` નો ઉપયોગ કરો.

# વેબ કૂકી પ્રદાતાઓ શું કરી શકે છે અને શું કરી શકતા નથી

વેબ કૂકી પ્રદાતાઓ વેબસાઇટના ચેટ ઇન્ટરફેસનો ફરીથી ઉપયોગ કરે છે. તેઓ અધિકૃત APIs જેવી સમાન ક્ષમતાઓ **પ્રદાન કરતા નથી**.

## સમર્થિત

- તમારા હાલના બ્રાઉઝર સત્રનો ઉપયોગ કરીને પ્રમાણીકરણ
- તમારા એકાઉન્ટ દ્વારા ઉપલબ્ધ મોડલ્સને ઍક્સેસ કરવા
- ચેટ પ્રતિસાદો સ્ટ્રીમ કરવા
- API કી જરૂરી નથી

## અસમર્થિત

- ફંક્શન કૉલિંગ
- ટૂલ કૉલિંગ
- ઑટોમૅટિક ફાઇલ સંપાદન
- એજન્ટિક IDE વર્કફ્લો
- માત્ર-API સુવિધાઓ

આ અપેક્ષિત વર્તન છે અને આ **બગ નથી**.

જો તમને ટૂલ એક્ઝિક્યુશન, ઑટોમૅટિક ફાઇલ સંપાદન અથવા અન્ય એજન્ટ વર્કફ્લોની જરૂર હોય, તો Web Cookie પ્રોવાઇડરને બદલે **API-key પ્રોવાઇડર**નો ઉપયોગ કરો.

# માન્યતા અંગેની મર્યાદા

સફળ **Test Connection** અથવા કૂકી માન્યતા ફક્ત એટલું ચકાસે છે કે આપેલા ક્રેડેન્શિયલ્સ અપેક્ષિત ફોર્મેટમાં હોવાનું જણાય છે.

Issue #7857 ઉકેલાય ત્યાં સુધી, સફળ માન્યતા એ વાતની **ખાતરી આપતી નથી** કે પ્રોવાઇડર સફળતાપૂર્વક પ્રમાણીકરણ કરશે.

જો પ્રમાણીકરણ હજી પણ નિષ્ફળ જાય, તો ખાતરી કરો કે તમે ક્રેડેન્શિયલ્સ બ્રાઉઝર કૂકી સ્ટોરેજને બદલે સક્રિય નેટવર્ક રિક્વેસ્ટમાંથી કૉપિ કર્યા છે.

---

# સમસ્યાનિવારણ

## પ્રમાણીકરણ નિષ્ફળ જાય છે

ચકાસો કે ક્રેડેન્શિયલ્સ અહીંથી કૉપિ કરવામાં આવ્યા હતા:

```
Network
→ Request Headers
→ Cookie
```

અને અહીંથી **નહીં**:

```
Application
→ Cookies
```

---

## કૂકી બ્રાઉઝરમાં કામ કરે છે પરંતુ OmniRouteમાં નહીં

કેટલાક પ્રોવાઇડર્સ એવી કૂકીઝનો સમાવેશ કરે છે જે ફક્ત પ્રમાણીકૃત રિક્વેસ્ટ્સ દરમિયાન જ મોકલવામાં આવે છે.

સફળતાપૂર્વક વાતચીત ખોલ્યા પછી નવી નેટવર્ક રિક્વેસ્ટમાંથી ક્રેડેન્શિયલ્સ ફરીથી કૉપિ કરો.

---

## સત્ર સમાપ્ત થઈ ગયું

Web Cookie પ્રોવાઇડર્સ તમારા હાલના બ્રાઉઝર સત્રનો ઉપયોગ કરે છે.

જો તમારા બ્રાઉઝર સત્રની મુદત સમાપ્ત થાય અથવા તમે સાઇન આઉટ કરો, તો તમારે ક્રેડેન્શિયલ્સનો નવો સેટ કૉપિ કરવો પડશે. સમર્થિત વેબ પ્રોવાઇડર્સ માટે કૂકી નવીનીકરણ ઑટોમેટ કરવા, સહાયક ટૂલ [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) જુઓ.

## ChatGPT Web `"Unsupported ChatGPT integrity dependency"` સાથે નિષ્ફળ જાય છે

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

ક્રેડેન્શિયલમાં કોઈ સમસ્યા નથી — તે ભૂલ સત્રમાંથી નહીં, પરંતુ બ્રિજમાંથી આવે છે. chatgpt.com દરેક ડિપ્લોયમેન્ટ માટે તેના
મોડ્યુલ IDs નિર્ધારિત કરે છે, અને બ્રિજ જે Sentinel હેલ્પર ઇન્સ્ટૅન્શિએટ કરે છે તેના IDને અગાઉ પિન કરતું હતું, તેથી
જ્યારે chatgpt.com રીબિલ્ડમાં હેલ્પરનું નામ બદલાયું ત્યારે કૂકી માન્ય હોવા છતાં દરેક ટર્ન નિષ્ફળ થયો. કનેક્શનને ફરીથી અધિકૃત
કરવાથી આ સમસ્યા ઉકેલી શકાતી નથી.

જે બિલ્ડ્સ પેજના પોતાના રનટાઇમ દ્વારા મોડ્યુલને રિઝૉલ્વ કરે છે તે કોઈ IDને પિન કરતા નથી અને આ સમસ્યાનો સામનો કરતા નથી. જો તમને આ
ભૂલ દેખાય, તો OmniRoute અપગ્રેડ કરો અને કનેક્શન ચેક ફરીથી ચલાવો.

# શ્રેષ્ઠ પ્રથાઓ

- નવી પ્રમાણીકૃત રિક્વેસ્ટમાંથી ક્રેડેન્શિયલ્સ કૉપિ કરો.
- જૂની કૂકીઝનો ફરીથી ઉપયોગ કરવાનું ટાળો.
- Web Cookie પ્રોવાઇડર્સનો ઉપયોગ કરતી વખતે તમારા બ્રાઉઝર સત્રને સક્રિય રાખો.
- કૉપિ કરેલી કૂકીઝને સંવેદનશીલ ક્રેડેન્શિયલ્સ તરીકે ગણો.
- જ્યારે તમને ફંક્શન કૉલિંગ અથવા એજન્ટ વર્કફ્લોની જરૂર હોય ત્યારે API-key પ્રોવાઇડર્સનો ઉપયોગ કરો.
