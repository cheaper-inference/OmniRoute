OmniRoute ને OpenAI-સુસંગત બૅકએન્ડ તરીકે નિર્દેશિત કરીને Codex CLI નો ઉપયોગ કરવા માટેની સંપૂર્ણ માર્ગદર્શિકા.

---

> **TOML એકમાત્ર અસરકારક ફોર્મેટ છે.** આધુનિક Codex ફક્ત `~/.codex/config.toml`
> વાંચે છે (codex-cli 0.147.0 સાથે ચકાસાયેલ: `codex --help` મુજબ
> `-c/--config` ઓવરરાઇડ્સ "`~/.codex/config.toml` માંથી લોડ થાય છે"). જૂની
> `~/.codex/config.yaml` લેગસી npm CLI ની હતી અને તેને કોઈ સૂચના વિના અવગણવામાં આવે છે.
> ડૅશબોર્ડ જનરેટર (`/api/cli-tools/apply`, ટૂલ `codex`) સંયમિત મર્જ સાથે TOML લખે છે —
> હાલની કીઓ અને અન્ય પ્રોવાઇડર બ્લૉક્સ જાળવી રાખવામાં આવે છે,
> API કી `OMNIROUTE_API_KEY` માં રહે છે (ફાઇલમાં ક્યારેય નહીં), અને બચી ગયેલી લેગસી
> `config.yaml` ને સ્પર્શ કર્યા વિના માઇગ્રેશન નોંધ તરીકે દર્શાવવામાં આવે છે.

## સીધું પેસ્ટ કરવા માટે તૈયાર config.toml

`<YOUR_HOST>` અને `<YOUR_KEY>` ને તમારા મૂલ્યોથી બદલો:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # દરેક ટૂલ કૉલ દીઠ હિસ્ટ્રી સ્ટોરેજ મર્યાદા

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc અથવા ~/.zshrc — વાસ્તવિક કી મૂલ્ય, config.toml માં ક્યારેય નહીં
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: ChatGPT ઍપની અંદર બંડલ કરાયેલ Codex

જો તમે ChatGPT ડેસ્કટૉપ ઍપ મારફતે Codex ઇન્સ્ટૉલ કર્યું હોય, તો `codex` બાઇનરી
ફક્ત ઍપ બંડલની અંદર હોઈ શકે છે અને હજી તમારા શેલ `PATH` પર ન હોઈ શકે. તમારી
શેલ સ્ટાર્ટઅપ ફાઇલમાં રિસોર્સિસ ડિરેક્ટરી ઉમેરો:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

નવું શેલ ખોલો, પછી ચકાસો:

```bash
command -v codex
codex --version
```

### સ્થાનિક બિન-પ્રમાણિત OmniRoute: પ્લેસહોલ્ડર કી પૂરતી છે

પ્રથમ રિક્વેસ્ટ CLI માંથી બહાર જાય તે **પહેલાં** Codex ચકાસે છે કે `env_key` દ્વારા
નામિત એન્વાયર્નમેન્ટ વેરિએબલ અસ્તિત્વમાં છે કે નહીં. જો તમારા **સ્થાનિક** OmniRoute
ઇન્સ્ટન્સને ઑથેન્ટિકેશનની જરૂર ન હોય, તો કોઈપણ ખાલી ન હોય એવો પ્લેસહોલ્ડર કામ કરશે:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

જો તમારું OmniRoute સર્વર સુરક્ષિત અથવા રિમોટ હોય, તો તેના બદલે વાસ્તવિક કીનો ઉપયોગ કરો.

> **સામાન્ય હોસ્ટ વિકલ્પો**
>
> | ઍક્સેસ          | URL                           |
> | --------------- | ----------------------------- |
> | સ્થાનિક નેટવર્ક | `http://192.168.0.1:20128/v1` |
> | Tailscale       | `http://100.x.x.x:20128/v1`   |
> | લૂપબૅક          | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — તે બધા મૉડલ્સ માટે શા માટે કાર્ય કરે છે

Codex CLI એ ફેબ્રુઆરી 2026 માં `wire_api = "chat"` (Chat Completions) ને ડિપ્રિકેટ કર્યું અને હવે `wire_api = "responses"` (OpenAI Responses API) **આવશ્યક** છે. v0.138 થી `wire_api = "chat"` સેટ કરવાથી સ્ટાર્ટઅપ વખતે તરત જ ક્રૅશ થાય છે.

GLM અને Kimi સહિતના ઘણા પ્રોવાઇડર્સ હજી પણ ફક્ત Chat Completions એન્ડપૉઇન્ટ ઉપલબ્ધ કરાવે છે. DeepSeek V4 હવે મૂળ Responses API તેમજ Anthropic-સુસંગત એન્ડપૉઇન્ટ ઉપલબ્ધ કરાવે છે; OmniRoute ડિફૉલ્ટ રૂપે Responses નો ઉપયોગ કરે છે અને દરેક DeepSeek કનેક્શનને Anthropic સુસંગતતા પસંદ કરવાની મંજૂરી આપે છે.

**OmniRoute આને પારદર્શક રીતે ઉકેલે છે:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute પ્રોવાઇડરનો મૂળ પ્રોટોકૉલ પસંદ કરે છે અને જરૂર પડે ત્યારે રૂપાંતર કરે છે
    → POST /responses (DeepSeek V4) અથવા /chat/completions (Mistral / GLM / Kimi / અન્ય)
```

OmniRoute નો ઉપયોગ કરતી વખતે તમને ક્યારેય અલગ ટ્રાન્સલેશન પ્રૉક્સીની જરૂર પડતી નથી. **બધા મૉડલ્સ `wire_api = "responses"` નો ઉપયોગ કરે છે** — બાકીનું OmniRoute સંભાળે છે.

> **`wire_api` ડિફૉલ્ટ છે** — આ ફીલ્ડનું ડિફૉલ્ટ મૂલ્ય `"responses"` છે અને તેને `config.toml` માંથી સંપૂર્ણપણે છોડી શકાય છે. માત્ર ઇરાદાનું દસ્તાવેજીકરણ કરતા હો ત્યારે જ તેને સ્પષ્ટ રીતે સેટ કરો.

## સંદર્ભ વિન્ડો અને સંક્ષિપ્તીકરણ

### ટોકન રૂપરેખાંકન ફીલ્ડ્સ

| ફીલ્ડ                            | વર્ણન                                                                                                                                                                               |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | સક્રિય મોડેલ માટેનું કુલ ટોકન બજેટ. તેને મોડેલની જાહેર કરેલી મર્યાદા પર સેટ કરો.                                                                                                    |
| `model_auto_compact_token_limit` | સ્વચાલિત ઇતિહાસ સંક્ષિપ્તીકરણ શરૂ કરતી થ્રેશોલ્ડ. **મહત્તમ: `model_context_window`ના 90%** — 90%થી વધુ મૂલ્યોને કોઈ સૂચના વિના અવગણવામાં આવે છે.                                    |
| `tool_output_token_limit`        | ઇતિહાસમાં દરેક ટૂલ કૉલના આઉટપુટ માટે સંગ્રહિત ટોકનની મર્યાદા. એક મોટો ટૂલ પ્રતિસાદ આખી વિન્ડો ભરી ન દે તે સુનિશ્ચિત કરે છે. **આ મહત્તમ આઉટપુટ નથી** — આ ઇતિહાસની સંગ્રહ મર્યાદા છે. |
| `compact_prompt`                 | સંક્ષિપ્તીકરણ દરમિયાન વપરાતા સિસ્ટમ પ્રોમ્પ્ટ માટે ઇનલાઇન ઓવરરાઇડ (v0.138+).                                                                                                        |

> **`model_max_output_tokens` અંગે નોંધ**: આ ફીલ્ડ **Codex CLI રૂપરેખાંકન સ્કીમાનો ભાગ નથી** (Codex Rust કોડબેઝમાં ગેરહાજર છે). તેને સેટ કરવામાં આવે તો કોઈ સૂચના વિના અવગણવામાં આવે છે. તેના પર આધાર રાખશો નહીં — ઇતિહાસમાં કેટલું ટૂલ આઉટપુટ સંગ્રહિત થાય છે તે નિયંત્રિત કરવા માટે `tool_output_token_limit`નો ઉપયોગ કરો.

> **સંક્ષિપ્તીકરણ સૂત્ર:** `effective_window = model_context_window - min(tool_output_token_limit, 20000)`. 20kથી વધુ મૂલ્યો સંક્ષિપ્તીકરણ શરૂ થવાના બિંદુને બદલતા નથી.

> **સામાન્ય માર્ગદર્શિકા:** `model_auto_compact_token_limit`ને `model_context_window`ના 85–88% પર સેટ કરો. ક્યારેય 90%થી વધુ ન રાખો — તેને કોઈ સૂચના વિના અવગણવામાં આવે છે.

## રીઝનિંગ એફર્ટ

પ્રતિસાદ આપતા પહેલાં મોડેલ કેટલું "વિચારે" છે તે નિયંત્રિત કરે છે.

| મૂલ્ય    | આ માટે ઉપયોગ કરો                          |
| -------- | ----------------------------------------- |
| `none`   | કોઈ તર્ક નહીં — સીધો પ્રતિસાદ             |
| `low`    | સરળ કાર્યો (નામ બદલવું, ફોર્મેટ કરવું)    |
| `medium` | ઉલ્લેખિત ન હોય ત્યારે **સર્વર ડિફૉલ્ટ**   |
| `high`   | મધ્યમ સ્તરના કાર્યો (રિફેક્ટરિંગ, ડિબગ)   |
| `xhigh`  | આર્કિટેક્ચર, ઊંડું વિશ્લેષણ, જટિલ સમસ્યાઓ |

```bash
# દરેક આમંત્રણ માટે ઓવરરાઇડ
codex -c model_reasoning_effort=low "ચલ xનું નામ બદલીને count કરો"
codex -c model_reasoning_effort=xhigh "auth મોડ્યુલની રચના કરો"
```

રીઝનિંગનો **સારાંશ** પણ સેટ કરો જેથી Desktop વિચારનું લખાણ રેન્ડર કરી શકે (માત્ર એન્ક્રિપ્ટ કરેલા બ્લૉબ્સ નહીં):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # અથવા જ્યારે સપોર્ટેડ હોય ત્યારે ultra
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute થિંકિંગ બજેટ (સર્વર સેટિંગ)

OmniRoute હોસ્ટ પર, Codex એફર્ટ/સારાંશ અપસ્ટ્રીમ સુધી પહોંચે તે માટે **Settings → AI → Thinking Budget**નું મૂલ્ય **`passthrough`** હોવું આવશ્યક છે. **`auto` મોડ** ક્લાયન્ટના બધા `reasoning` / `reasoning_effort` ફીલ્ડ દૂર કરે છે અને Codex યોગ્ય રીતે કૉન્ફિગર કરેલું હોય ત્યારે પણ થિંકિંગ પેનલ ખાલી રાખશે.

સંપૂર્ણ માર્ગદર્શિકા: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

કમ્પ્રેશન અને પ્રોમ્પ્ટ કૅશ સ્વતંત્ર છે અને `passthrough` હેઠળ કાર્ય કરવાનું ચાલુ રાખે છે.

## `omniroute setup-codex` વડે પ્રોફાઇલ્સ આપમેળે જનરેટ કરવી

જો તમે VPS પર OmniRoute ચલાવતા હો, તો તમે લાઇવ મોડલ કેટલોગમાંથી પ્રોફાઇલ ફાઇલો આપમેળે જનરેટ કરી શકો છો:

```bash
# VPS પરથી (પોર્ટ 20128 પર સ્થાનિક OmniRoute વાપરે છે)
omniroute setup-codex

# કોઈપણ મશીન પરથી — તમારા VPS તરફ નિર્દેશ કરો
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# ફાઇલો લખ્યા વિના પૂર્વાવલોકન કરો
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# ફક્ત GLM અને Kimi પ્રોફાઇલ્સ જનરેટ કરો
omniroute setup-codex --only glm,kimi

# કસ્ટમ ડિરેક્ટરીમાં લખો
omniroute setup-codex --codex-home /path/to/.codex
```

આ કમાન્ડ `/v1/models` મેળવે છે, જાણીતા મોડલ્સ માટે સુસંગત બનાવેલી પ્રોફાઇલ્સનો ઉપયોગ કરે છે, અન્ય સુસંગત ટેક્સ્ટ મોડલ્સ માટે કેટલોગ મેટાડેટાનો ફૉલબૅક તરીકે ઉપયોગ કરે છે અને દરેક માટે `~/.codex/<name>.config.toml` લખે છે. આ પ્રક્રિયા આઇડેમ્પોટન્ટ છે — તેને ફરી ચલાવવી સુરક્ષિત છે.

જો મૂળ `config.toml`માં `model_providers.omniroute`ની વ્યાખ્યા ન હોય, તો સ્પષ્ટ
`setup-codex` પસંદ કરેલા સ્થાનિક અથવા રિમોટ એન્ડપોઇન્ટનો ઉપયોગ કરીને જનરેટ થયેલા દરેક
ઓવરલેમાં તે વ્યાખ્યા સમાવે છે. તે મૂળ ફાઇલને બદલ્યા વિના રાખે છે. હાલની પ્રોવાઇડર
વ્યાખ્યા તેના એન્ડપોઇન્ટ અને પ્રમાણીકરણ સેટિંગ્સ સહિત વારસામાં મળે છે. અમાન્ય
મૂળ TOML પ્રોફાઇલ્સ લખાય તે પહેલાં જનરેશન અટકાવે છે.

જ્યારે તમે `--api-key` અથવા `OMNIROUTE_API_KEY` આપો છો, ત્યારે નવી વ્યાખ્યાયિત પ્રોવાઇડર
`env_key = "OMNIROUTE_API_KEY"`નો સંદર્ભ લે છે; કી પોતે ક્યારેય સાચવવામાં આવતી નથી કે
પૂર્વાવલોકનમાં છાપવામાં આવતી નથી. જ્યાંથી તમે Codex શરૂ કરો છો તે એન્વાયર્નમેન્ટમાં આ
વેરિયેબલ સેટ કરો. કી આપવામાં ન આવે તો નવી વ્યાખ્યામાં કીની કોઈ આવશ્યકતા હોતી નથી,
જે પ્રમાણીકરણ વિનાની વિનંતીઓ સ્વીકારવા માટે કૉન્ફિગર કરેલા OmniRoute ઇન્સ્ટન્સ માટે છે.

નીચે વર્ણવેલ ઑપ્ટ-ઇન કેટલોગ ઑટો-સિંક ઓવરલેમાં પહેલેથી રહેલી પ્રોવાઇડર વ્યાખ્યાઓને
જાળવી રાખે છે, પરંતુ નવી પ્રોવાઇડર સેટિંગ્સને બુટસ્ટ્રેપ કરતું નથી; પહેલાં સ્પષ્ટ સેટઅપ
અથવા ડેશબોર્ડ દ્વારા પ્રોવાઇડરને કૉન્ફિગર કરો. હાલની પ્રોવાઇડર સેટિંગ્સને ડ્રાય-રન
પૂર્વાવલોકનોમાંથી બાકાત રાખવામાં આવે છે, કારણ કે તેમાં ઑપરેટર દ્વારા સંચાલિત ક્રેડેન્શિયલ્સ હોઈ શકે છે.

સફળ પ્રોવાઇડર મોડલ ડિસ્કવરી/ઇમ્પોર્ટ લાઇવ કેટલોગને બદલે ત્યાર પછી OmniRoute આ જ પ્રોફાઇલ ફાઇલોને **આપમેળે સિંક** પણ કરી શકે છે. આ **ઑપ્ટ-ઇન છે અને ડિફૉલ્ટ રૂપે બંધ છે**: તેને **CLI Code dashboard** પરથી ટૉગલ કરો ("CLI profile auto-sync" → Codex), અથવા `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` સેટ કરો (તે ડિફૉલ્ટ રૂપે ચાલુ રહેલા `CLI_ALLOW_CONFIG_WRITES`ને પણ માન આપે છે). સક્ષમ કરેલું હોય ત્યારે તે ફક્ત અલગ `~/.codex/*.config.toml` પ્રોફાઇલ ફાઇલો જ લખે છે; તે સક્રિય/ડિફૉલ્ટ `~/.codex/config.toml`, Codex-lb સેટિંગ્સ, પ્રમાણીકરણ અથવા પ્રોવાઇડરની પસંદગીને ક્યારેય બદલતું નથી.

## `omniroute launch-codex` વડે Codex લૉન્ચ કરવું

Codex લૉન્ચ કરતાં પહેલાં તમારા OmniRoute ઇન્સ્ટન્સનું હેલ્થ-ચેક કરે છે:

```bash
omniroute launch-codex --profile kimi-k27

omniroute launch-codex --remote http://100.x.x.x:20128/v1 --api-key sk-xxx
```

(`bin/cli/cli-manifest.mjs`):

```bash
# ઇન્ટરેક્ટિવ મોડેલ પિકર → ~/.codex/<name>.config.toml લખે છે (TOML, env_key)
omniroute configure codex

# -c ફ્લૅગ્સ દ્વારા omniroute પ્રોવાઇડર દાખલ કરીને codex લૉન્ચ કરો (કોઈ કૉન્ફિગ લખાતું નથી)
```

## લાંબા સમયથી ચાલતા કાર્યો

બે OmniRoute ડિફોલ્ટ્સ મલ્ટિ-અવર Codex CLI સત્રોને શાંતિપૂર્વક તોડફોડ કરી શકે છે. બેમાંથી એક Codex CLI સેટિંગ — બંને OmniRoute બાજુ પર રહે છે. વપરાશકર્તાઓ અપસ્ટ્રીમ પ્રોક્સીમાંથી રૂપરેખાને સ્થાનાંતરિત કરે છે જે એકાઉન્ટ્સને પિન કરે છે અને નિષ્ક્રિય કટઓફને નિષ્ક્રિય કરે છે અને OmniRoute "લાંબા સત્રને ટકાવી શકતા નથી."

| લક્ષણ                                                                                     | સંભવિત કારણ                                                        | નોબ                      |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------ |
| સત્ર એકાઉન્ટ્સ સ્વિચ કરવાનું ચાલુ રાખે છે / વળાંક વચ્ચે પ્રોમ્પ્ટ-કેશ સાતત્ય ખોવાઈ જાય છે | સત્ર એફિનિટી TTL એ `0` છે (અક્ષમ)                                  | `sessionAffinityTtlMs`   |
| ક્લાયંટ-ફેસિંગ પ્રોમ્પ્ટ વિના કનેક્શન મધ્ય-તર્ક સાથે મૃત્યુ પામે છે                       | સ્ટ્રીમ નિષ્ક્રિય વોચડોગ 10 મિનિટ પછી અપસ્ટ્રીમ ચંક વિના બરતરફ થયો | `STREAM_IDLE_TIMEOUT_MS` |

સંબંધિત ચર્ચાઓ: [#7126](https://github.com/cheaper-inference/OmniRoute/discussions/7126) (લાંબા કાર્ય ડ્રોપ્સ), [#5718](https://github.com/cheaper-inference/OmniRoute/discussions/5718) (શા માટે એફિનિટી ડિફોલ્ટ બંધ છે). ટ્રેકિંગ: [#7287](https://github.com/cheaper-inference/OmniRoute/issues/7287).

### 1. સત્ર એફિનિટી — એક વાતચીતને એક એકાઉન્ટ પર પિન કરો

**ડિફૉલ્ટ:** `sessionAffinityTtlMs = 0` (અક્ષમ).

**તેને ક્યાં સેટ કરવું**

- ડેશબોર્ડ →** સેટિંગ્સ → રૂટીંગ** →** સત્ર સંબંધ** →** એફિનિટી TTL (સેકન્ડ)** (`ComboDefaultsTab`)
- અથવા `sessionAffinityTtlMs` in સાથે PATCH સેટિંગ્સ** મિલિસેકન્ડ** (Zod રેન્જ `0`–`86_400_000`, એટલે કે 24 કલાક સુધી)

> કોડેક્સ-ઓન્લી `codexSessionAffinityTtlMs` પરથી #7274 માં નામ બદલ્યું. લેગસી કી હજી પણ ફક્ત વાંચવા માટેના ઉપનામ તરીકે સ્વીકારવામાં આવે છે; નવી રૂપરેખાઓએ `sessionAffinityTtlMs` ઉપયોગ કરવો જોઈએ. એફિનિટી હવે લાગુ પડે છે** કોઈપણ** પ્રદાતા એકવાર TTL `0` ઉપર હોય, માત્ર Codex — જ નહીં [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → સત્ર સંબંધ જુઓ.

**જ્યારે તે 0 પર રહે છે ત્યારે શું તૂટી જાય છે**

મલ્ટી-ટર્ન Codex વાર્તાલાપના દરેક વળાંકને સક્રિય કોમ્બો વ્યૂહરચના દ્વારા સ્વતંત્ર રીતે રૂટ કરવામાં આવે છે અને** વળાંક દીઠ અલગ એકાઉન્ટ** . તે અપસ્ટ્રીમ સત્ર / પ્રોમ્પ્ટ-કેશ સાતત્યને તોડે છે. OmniRoute માત્ર Codex સત્ર હેડરો (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) અને `prompt_cache_key` / `session_id` જેવા બોડી ફીલ્ડની સલાહ લે છે જ્યારે TTL `0` ( `src/sse/services/auth.ts` માં`extractSessionAffinityKey` ) કરતા વધારે હોય.

**બહુ-કલાકના એક કાર્ય માટે ભલામણ કરેલ**

TTL સેટ કરો** કાર્યની અપેક્ષિત દિવાલ-ઘડિયાળની લંબાઈથી ઉપર** (UI મહત્તમ છે** 86400 સેકન્ડ** = 24 કલાક):

| અપેક્ષિત કાર્ય લંબાઈ | એફિનિટી TTL (UI, સેકન્ડ)  | `sessionAffinityTtlMs` |
| -------------------- | ------------------------- | ---------------------- |
| થોડા કલાકો           | `14400` (4h)              | `14400000`             |
| રાતોરાત / ~ 12h      | `43200` (12h)             | `43200000`             |
| આખો દિવસ             | `86400` (24 કલાક, મહત્તમ) | `86400000`             |

ઑપ્ટ-ઇન ઇરાદાપૂર્વક છે: અફિનિટીને અક્ષમ કરવાથી સમગ્ર એકાઉન્ટમાં લોડ-બેલેન્સિંગની તરફેણ થાય છે; તેને સક્ષમ કરવું એક લાંબા એજન્ટ સત્ર માટે સાતત્યની તરફેણ કરે છે. આ માર્ગદર્શિકા કરે છે** નથી** લાંબા Codex કાર્યો ચલાવતા ડિફોલ્ટ — ઓપરેટરોને બદલો પસંદ કરવું આવશ્યક છે.

### 2. સ્ટ્રીમ નિષ્ક્રિય સમયસમાપ્તિ — શાંત તર્કના વળાંકને મારશો નહીં

**ડિફૉલ્ટ:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 મિનિટ). જ્યારે સેટ ન હોય ત્યારે તે `REQUEST_TIMEOUT_MS` પાસેથી વારસામાં મળે છે; વહેંચાયેલ આધારરેખા પણ 600000 છે. [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → સમયસમાપ્તિ જુઓ.

**ડિફોલ્ટ પર શું તૂટી જાય છે**

એક Codex તર્ક / સાધન વળાંક કે જેની સાથે 10 મિનિટથી વધુ સમય માટે મૌન રહે છે** કોઈ વાસ્તવિક અપસ્ટ્રીમ ભાગ નથી** SSE નિષ્ક્રિય વોચડોગ (`open-sse/utils/stream.ts`) દ્વારા બળપૂર્વક બંધ કરવામાં આવે છે. ક્લાયન્ટ ઘણીવાર "કોઈપણ સૂચના વિના આપમેળે બંધ થઈ ગયેલું" મેળ ખાતું — કનેક્શન ડ્રોપ જુએ છે.

જટિલ વિગત: OmniRoute ની સિન્થેટિક SSE** હૃદયના ધબકારા ફરીથી સેટ થતા નથી** નિષ્ક્રિય ઘડિયાળ. માત્ર એક વાસ્તવિક અપસ્ટ્રીમ બોડી ભાગ `lastChunkTime` ને અપડેટ કરે છે. એક શાંત મોડલ જે હજુ પણ "વિચારી રહ્યું છે" વોચડોગના દૃષ્ટિકોણથી અટકેલા અપસ્ટ્રીમ જેવું જ લાગે છે.

સંબંધિત Undici બોડી નિષ્ક્રિયતા: `FETCH_BODY_TIMEOUT_MS` (તે જ 10-મિનિટની બેઝલાઇનમાં પણ ડિફોલ્ટ છે; `0` તેને અક્ષમ કરે છે). સ્ટ્રીમિંગ માટે, `FETCH_TIMEOUT_MS` માત્ર કનેક્શન સેટઅપ / ફર્સ્ટ હેડર — આવરી લે છે એકવાર સ્ટ્રીમ સક્રિય થઈ જાય, સ્ટોલ `STREAM_IDLE_TIMEOUT_MS` અને `FETCH_BODY_TIMEOUT_MS` દ્વારા સંચાલિત થાય છે.

**બહુ-કલાકના એક કાર્ય માટે ભલામણ કરેલ**

OmniRoute પ્રક્રિયા વાતાવરણમાં (`.env` / કંપોઝ / સિસ્ટમડી):

```bash
# Disable stream idle + body inactivity cutoffs for long reasoning turns
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

અથવા તેમને તમે અપેક્ષા રાખતા સૌથી લાંબા શાંત ગેપથી ઉપર ઉભા કરો (મૂલ્યો મિલિસેકન્ડ છે):

```bash
# Example: allow up to 2 hours of silence between upstream chunks
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

આ env vars ને બદલ્યા પછી OmniRoute પુનઃપ્રારંભ કરો.

### કોંક્રિટ રેસીપી — બહુ-કલાક Codex કાર્ય

1. **એકાઉન્ટ પિન કરો:** ડેશબોર્ડ → સેટિંગ્સ → રૂટીંગ → સત્ર એફિનિટી → એફિનિટી TTL = `43200` (12h) અથવા `86400` (24h મહત્તમ).
2. **નિષ્ક્રિય કટઓફને વધારો / અક્ષમ કરો** OmniRoute ના વાતાવરણમાં:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. આ બે વર્તણૂકો માટે સામાન્ય Codex `config.toml` (`wire_api = "responses"`, સાચો `base_url`, `OMNIROUTE_API_KEY`) — રાખો કોડેક્સ-સાઇડ affinity/idle નોબ્સ અસ્તિત્વમાં નથી.
4. OmniRoute પુનઃપ્રારંભ કરો, પછી લાંબા Codex કાર્ય શરૂ કરો.

### ડિફોલ્ટ નિર્ણય (#7287)

| નોબ                      | શિપ ડિફોલ્ટ         | આ માર્ગદર્શિકામાં ફેરફાર કરશો?                                                                    |
| ------------------------ | ------------------- | ------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (બંધ)           | **ના** — ઑપ્ટ-ઇન રહે છે (લોડ-બેલેન્સિંગ વિ સાતત્ય; ચર્ચા જુઓ #5718)                               |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 મિનિટ) | **ના** સામાન્ય ટ્રાફિક માટે — 10 મિનિટ બાકી છે; લાંબા Codex ઓપરેટરો તેને વધારવા અથવા અક્ષમ કરે છે |

વૈશ્વિક સ્તરે ડિફૉલ્ટને ફ્લિપ કરવાથી માત્ર Codex જ નહીં, દરેક ક્લાયન્ટ માટે વર્તન બદલાશે. knobs દસ્તાવેજ; જ્યાં સુધી સ્પષ્ટ ઓપરેટર નિર્ણય અન્યથા કહે નહીં ત્યાં સુધી ડિફોલ્ટ્સને એકલા છોડી દો.

### નિષ્ક્રિય કટનું નિદાન

જ્યારે નિષ્ક્રિય વૉચડોગ ફાયર કરે છે, ત્યારે OmniRoute આના આકારની રેખા લૉગ કરે છે:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

`Idle timeout: no data from` (અથવા કોડ `stream_idle_timeout` / ભૂલ નામ `StreamIdleTimeoutError`) માટે Grep. પ્રદાતા સેગમેન્ટ એ વિનંતી માટે જે પણ OmniRoute વપરાય છે (`codex`, અન્ય પ્રદાતા id, અથવા `provider` જો અજાણ હોય તો) — તે હંમેશા શાબ્દિક શબ્દમાળા `codex` હોતી નથી.

## મુશ્કેલીનિવારણ

**`Error: wire_api = "chat" is no longer supported`** તમારી રૂપરેખામાંથી `wire_api = "chat"` દૂર કરો. `wire_api = "responses"` સેટ કરો અથવા ફીલ્ડને છોડી દો (v0.138 થી `"responses"` પર ડિફોલ્ટ).

**`Error: model not found`** સાચા ઉપસર્ગ સાથે OmniRoute માં મોડેલ અસ્તિત્વમાં છે તે ચકાસો. `omniroute models list` અથવા ઓપન `/dashboard/providers/<provider>` ઉપયોગ કરો.

**`Authentication error`** પુષ્ટિ કરો કે `OMNIROUTE_API_KEY` નિકાસ થયેલ છે: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`** Codex માન્ય કરે છે કે પ્રથમ વિનંતી કરતા પહેલા env var અસ્તિત્વમાં છે. સુરક્ષિત સર્વર્સ માટે વાસ્તવિક કી નિકાસ કરો, અથવા બિન-ખાલી પ્લેસહોલ્ડર જેમ કે `OMNIROUTE_API_KEY=local` જ્યારે તમારા** સ્થાનિક** OmniRoute ઉદાહરણને પ્રમાણીકરણની જરૂર નથી. જો તમે તેને `~/.bashrc` અથવા `~/.zshrc` માં ઉમેર્યું હોય તો શેલને પુનઃપ્રારંભ કરો.

**`Connection refused`** ચકાસો કે OmniRoute ચાલી રહ્યું છે અને `base_url` host/port તમારા નેટવર્ક માટે યોગ્ય છે (સ્થાનિક vs Tailscale vs VPS).

**સંદર્ભ મર્યાદાની નજીક સત્ર ક્રેશ થયું** સ્પષ્ટપણે `model_context_window` અને `model_auto_compact_token_limit` સેટ કરો. ઉપરોક્ત સંદર્ભ વિન્ડો કોષ્ટક જુઓ.

**કોમ્પેક્શન ખૂબ મોડું થાય છે** વિન્ડોના 80-85% સુધી `model_auto_compact_token_limit` નીચે કરો. 90% થી ઉપર ક્યારેય સેટ ન કરો.

**પ્રોફાઇલ લોડ થતી નથી (`-p <name>` ચુપચાપ અવગણવામાં આવે છે)** પુષ્ટિ કરો કે ફાઇલ `~/.codex/<name>.config.toml` પર અસ્તિત્વમાં છે (કોઈ `profile-` ઉપસર્ગ નથી). `ls ~/.codex/*.config.toml` ચલાવો.

**લાંબી Codex ટાસ્ક મિડ-રન / વળાંક વચ્ચે એકાઉન્ટ્સ સ્વિચ કરે છે** [લાંબા સમયથી ચાલતા કાર્યો](#long-running-tasks) જુઓ. સત્ર એફિનિટી સક્ષમ કરો (ટાસ્ક લંબાઈ ઉપર TTL ) અને `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS` વધારો અથવા અક્ષમ કરો. `Idle timeout: no data from` માટે Grep OmniRoute લોગ્સ.
