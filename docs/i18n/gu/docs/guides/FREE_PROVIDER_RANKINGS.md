> **TL;DR**: OmniRoute તેના **મફત** પ્રદાતાઓને મોડેલની ગુણવત્તા અનુસાર **Arena AI
> (LMArena-શૈલીના) ELO સ્કોર્સ**નો ઉપયોગ કરીને ક્રમ આપે છે. તમારા કાર્ય માટે કયા મફત
> પ્રદાતાઓ સૌથી મજબૂત મોડેલો આપે છે તે જોવા માટે ડૅશબોર્ડમાં **મફત પ્રદાતા રૅન્કિંગ્સ**
> પેજ ખોલો — એકંદરે અથવા કૅટેગરી (કોડિંગ, સમીક્ષા, દસ્તાવેજીકરણ, ડિબગિંગ) મુજબ ફિલ્ટર કરીને.

## આ શું છે

OmniRoute 376 પ્રદાતાઓને નોંધે છે, જેમાં **મફત/પ્રમાણીકરણ-રહિત** તરીકે ચિહ્નિત 155 કેટલોગ એન્ટ્રીઓનો સમાવેશ થાય છે
(પ્રમાણીકરણ-રહિત,
મફત-સ્તર OAuth, અથવા મફત-સ્તર API કી — જુઓ
[મફત સ્તરો માટેની માર્ગદર્શિકા](../getting-started/FREE-TIERS-GUIDE.md) અને સંપૂર્ણ
[મફત સ્તરોની ડિરેક્ટરી](../reference/FREE_TIERS.md)). પરંતુ એક અડચણ છે: મફત પ્રદાતાઓની મોડેલ ગુણવત્તામાં
ખૂબ મોટો તફાવત હોય છે. અગ્રણી મોડેલ પ્રદાન કરતો પ્રમાણીકરણ-રહિત પ્રદાતા
નાનું જૂનું મોડેલ પ્રદાન કરતા પ્રદાતા કરતાં ઘણો વધુ ઉપયોગી છે.

**મફત પ્રદાતા રેન્કિંગ્સ**, "**કયો મફત પ્રદાતા મને શ્રેષ્ઠ મોડેલ આપે છે?**" એ પ્રશ્નનો જવાબ આપવા માટે
દરેક મફત પ્રદાતાના કેટલોગને **Arena AI લીડરબોર્ડ**ના
**સમુદાય-સ્રોતિત ગુણવત્તા સ્કોર્સ** સાથે જોડે છે (માનવીય પસંદગી આધારિત ELO, જે LMArena
ચેટબોટ એરેનાની પાછળ રહેલા વિચાર જેવું જ છે). ત્યારબાદ પ્રદાતાઓને તેમના **શ્રેષ્ઠ મફત મોડેલ**ની ક્ષમતાના આધારે ક્રમ આપવામાં આવે છે.

રેન્કિંગની ગણતરી ત્રણ વાસ્તવિક સ્રોતોમાંથી કરવામાં આવે છે:

1. મફત પ્રદાતાઓની યાદીઓ — `NOAUTH_PROVIDERS`, તેમજ `hasFree` તરીકે ચિહ્નિત `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` એન્ટ્રીઓ
   (`src/shared/constants/providers.ts`).
2. પ્રદાતા રજિસ્ટ્રીમાંથી દરેક પ્રદાતાનો મોડેલ કેટલોગ
   (`open-sse/config/providerRegistry.ts`).
3. Arena ELO સિંક એન્જિન (`src/lib/arenaEloSync.ts`) દ્વારા `model_intelligence` DB કોષ્ટકમાં
   સંગ્રહિત ELO-આધારિત કાર્ય-અનુકૂળતા સ્કોર્સ.

જોડાણનો તર્ક `src/lib/freeProviderRankings.ts`માં આવેલો છે.

## ઍક્સેસ કરવાની રીત

### ડૅશબોર્ડ પેજ

ડૅશબોર્ડ ખોલીને **ખર્ચ → મફત પ્રદાતા રૅન્કિંગ્સ** પર જાઓ અથવા સીધા અહીં નેવિગેટ કરો:

```
/dashboard/free-provider-rankings
```

આ પેજ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) નીચેની વસ્તુઓ દર્શાવે છે:

- શ્રેષ્ઠ ક્રમ ધરાવતા મફત પ્રદાતાઓનું **ટોચ-3 પોડિયમ** (🥇 🥈 🥉).
- આ કૉલમ સાથેનું સંપૂર્ણ **રૅન્કિંગ કોષ્ટક**: **ક્રમ**, **પ્રદાતા**, **ટોચનું મોડેલ**,
  **સ્કોર**, **સરેરાશ સ્કોર**, **મોડેલો**, **પ્રકાર**.
- **કૅટેગરી ફિલ્ટર બટનો**: _બધી કૅટેગરીઓ_, _ડિફૉલ્ટ_, _કોડિંગ_, _સમીક્ષા_,
  _દસ્તાવેજીકરણ_, _ડિબગિંગ_.

દરેક પ્રદાતાનું **પ્રકાર** બૅજ તે કેવી રીતે મફત છે તે જણાવે છે:

| બૅજ      | અર્થ                                       |
| -------- | ------------------------------------------ |
| `NOAUTH` | હંમેશાં મફત, કોઈ ઓળખપત્રોની જરૂર નથી       |
| `OAUTH`  | મફત ટિયર (`hasFree`) ધરાવતો OAuth પ્રદાતા  |
| `APIKEY` | મફત ટિયર (`hasFree`) ધરાવતો API-કી પ્રદાતા |

સ્કોર્સને કાચા આંકડાઓના બદલે માનવી સરળતાથી સમજી શકે તેવા લેબલ તરીકે દર્શાવવામાં આવે છે
(દા.ત. _શ્રેષ્ઠ_, _ઉત્કૃષ્ટ_, _ખૂબ સારું_, _સારું_, _સરેરાશ_), કારણ કે મૂળભૂત મૂલ્ય
ટકાવારી નહીં પરંતુ સાપેક્ષ રૅન્કિંગ ગુણવત્તા છે.

### API એન્ડપૉઇન્ટ

આ પેજને જાહેર રીડ એન્ડપૉઇન્ટ
(`src/app/api/free-provider-rankings/route.ts`) દ્વારા ડેટા મળે છે:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

ક્વેરી પેરામીટર્સ (Zod વડે માન્ય કરેલા):

| પેરામીટર   | પ્રકાર | ડિફૉલ્ટ    | નોંધો                                                                                                 |
| ---------- | ------ | ---------- | ----------------------------------------------------------------------------------------------------- |
| `category` | string | (કંઈ નહીં) | `default`, `coding`, `review`, `documentation`, `debugging`માંથી એક. સંયુક્ત રૅન્કિંગ માટે તેને છોડો. |
| `limit`    | number | `50`       | `1–100`ની શ્રેણી સુધી મર્યાદિત.                                                                       |

પ્રતિસાદનું માળખું:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` મૂળ Arena ELO મૂલ્ય છે; `score` સામાન્યકૃત કાર્ય-અનુકૂળતા મૂલ્ય છે
(નીચે જુઓ). કોઈ સ્કોર કરેલા મોડેલો ન ધરાવતા પ્રદાતાઓને પ્રતિસાદમાંથી બાકાત રાખવામાં આવે છે.

## સ્કોર કેવી રીતે કામ કરે છે

### સ્ત્રોત: Arena AI લીડરબોર્ડ

Arena ELO સિંક એન્જિન (`src/lib/arenaEloSync.ts`) Arena AI લીડરબોર્ડ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) પરથી બે લીડરબોર્ડ — `text`
અને `code` — મેળવે છે. જ્યારે તે API કોઈ ઉપયોગી બોર્ડ પરત આપતું નથી, ત્યારે એન્જિન
Hugging Face datasets-server પરની સત્તાવાર `lmarena-ai/leaderboard-dataset` પર ફોલબેક
કરે છે (`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` `activeSource`, `lastError` અને
`lastFailedAt` જાણ કરે છે. દરેક લીડરબોર્ડ એન્ટ્રીમાં
મોડેલનું નામ, વેન્ડર, ELO `score`, કોન્ફિડન્સ ઇન્ટરવલ અને મતોની સંખ્યા હોય છે.

લીડરબોર્ડ શ્રેણીઓ OmniRoute કાર્ય શ્રેણીઓમાં મેપ થાય છે:

| Arena લીડરબોર્ડ | OmniRoute કાર્ય શ્રેણીઓ                           |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### સામાન્યીકરણ (ટાસ્ક-ફિટ સ્કોર)

કાચા ELO સ્કોરને દરેક લીડરબોર્ડ માટે **`[0.4, 0.98]` માં ટાસ્ક-ફિટ મૂલ્ય**માં સામાન્યીકૃત કરવામાં આવે છે:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

સ્કોર ક્યારેય `0` કે `1` સુધી પહોંચતો નથી, જેથી વપરાશકર્તા ઓવરરાઇડ માટે જગ્યા રહી જાય. આ જ
`score` ફીલ્ડ છે જે તમને API પ્રતિભાવમાં દેખાય છે અને ડેશબોર્ડ પર બતાવાયેલું લેબલ છે.

### વિશ્વાસ

દરેક એન્ટ્રીને Arena મતોની સંખ્યાના આધારે વિશ્વાસ સ્તર મળે છે:

| વિશ્વાસ  | મતો     |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### સંગ્રહ અને તાજગી

સામાન્યીકૃત એન્ટ્રીઓ `source = "arena_elo"` સાથે `model_intelligence` DB ટેબલમાં
લખવામાં આવે છે (`src/lib/db/modelIntelligence.ts`). એન્ટ્રીઓ **7 દિવસ પછી સમાપ્ત
થઈ જાય છે**, જેથી સિંક કરવાનું બંધ કરી દેનાર પ્રોવાઇડર જૂનો ડેટા આપવાને બદલે
આખરે યાદીમાંથી ગાયબ થઈ જાય છે.

સિંક **ડિફૉલ્ટ રૂપે ચાલુ** ચાલે છે:

- તે સર્વર સ્ટાર્ટઅપ પર એક વાર ચાલે છે અને પછી આવર્તક ટાઇમર પર
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` થી વાયર્ડ).
- તે **નોન-બ્લોકિંગ છે અને ક્યારેય fatal નથી** — જો અપસ્ટ્રીમ ફેચ નિષ્ફળ જાય, તો OmniRoute
  ચાલુ રહે છે અને રેન્કિંગ્સ ફક્ત છેલ્લો સારો ડેટા (અથવા ખાલી સ્થિતિ) બતાવે છે.

બે environment variables તેને નિયંત્રિત કરે છે (દસ્તાવેજીકરણ
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) માં):

| વેરિયેબલ                  | ડિફૉલ્ટ       | હेतુ                                                |
| ------------------------- | ------------- | --------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | આઉટબાઉન્ડ સિંકથી દૂર રહેવા માટે `false` પર સેટ કરો. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | સિંક અંતરાલ, સેકન્ડમાં.                             |

### મેન્યુઅલ સિંક / સ્થિતિ / સાફ કરવું

ઓપરેટરો માટે, એક authenticated મેનેજમેન્ટ એન્ડપોઇન્ટ મેન્યુઅલ નિયંત્રણ પૂરું પાડે છે
(`src/app/api/intelligence/sync/route.ts` — મેનેજમેન્ટ auth જરૂરી છે):

```
GET    /api/intelligence/sync          # વર્તમાન સિંક સ્થિતિ (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # મેન્યુઅલ સિંક શરૂ કરો; body: { "dryRun": true } લખ્યા વિના પૂર્વાવલોકન માટે
DELETE /api/intelligence/sync          # બધી સિંક થયેલી arena_elo intelligence એન્ટ્રીઓ સાફ કરો
```

જો રેન્કિંગ્સ પેજ ખાલી હોય, તો મેન્યુઅલ `POST /api/intelligence/sync` (અથવા ફક્ત
સર્વર રીસ્ટાર્ટ કરવો) તેને ફરીથી ભરી દે છે.

### મોડેલ્સને લીડરબોર્ડ સાથે મેળ કરવા

Registry મોડેલ ID અને Arena મોડેલ નામો હંમેશા બરાબર મેળ ખાતા નથી. રેન્કિંગ
ફ્લેક્સિબલ મેચિંગ વાપરે છે (`src/lib/freeProviderRankings.ts` માં `findMatchingIntelligence`):

1. સામાન્યીકૃત મોડેલ ID પર ચોક્કસ મેળ.
2. અંતિમ વર્ઝન સફિક્સ કાઢી નાખ્યા પછી મેળ (દા.ત. `kimi-k2.6` → `kimi-k2`).
3. પ્રીફિક્સ મેળ (લીડરબોર્ડ મોડેલ નામ registry ID નો પ્રીફિક્સ હોય છે).

સિંક બાજુએ, જાણીતા વેન્ડર પ્રીફિક્સ (`anthropic/`, `openai/`, `google/`, …)
કાઢી નાખવામાં આવે છે અને નાનો alias map કેનોનિકલ નામોને OmniRoute આંતરિક રૂપે
વાપરતા વેરિઅન્ટ્સમાં વિસ્તારે છે, જેથી મોડેલ્સ કોઈપણ નામ હેઠળ શોધી શકાય.

### પ્રોવાઇડરનું રેન્કિંગ કેવી રીતે થાય છે

દરેક ફ્રી પ્રોવાઇડર માટે, એન્જિન તેના કેટલોગમાંના દરેક મોડેલને સ્કોર કરે છે, પછી:

- **ટોપ મોડેલ** = પ્રોવાઇડરનું સૌથી વધુ સ્કોર ધરાવતું મોડેલ.
- **સરેરાશ સ્કોર** = તે પ્રોવાઇડરના તમામ સ્કોર થયેલા મોડેલ્સનો સરેરાશ સ્કોર.
- **મોડેલ્સ** = પ્રોવાઇડરના કેટલા મોડેલ્સ પાસે Arena સ્કોર હતો.

પ્રોવાઇડરોને પહેલા **ટોપ-મોડેલ સ્કોર** અને પછી સરેરાશ સ્કોર પ્રમાણે ક્રમમાં ગોઠવવામાં આવે છે. આ એવા
પ્રોવાઇડરને પુરસ્કાર આપે છે જે ઓછામાં ઓછું એક મજબૂત ફ્રી મોડેલ પૂરું પાડે છે.

## મફત પ્રદાતાઓ પસંદ કરવા માટે તેનો ઉપયોગ

1. **યોગ્ય શ્રેણી પસંદ કરો.** એજન્ટિક/કોડ વર્કલોડ માટે **Coding** ફિલ્ટરનો ઉપયોગ કરો અથવા
   સામાન્ય ચેટ માટે તેને **All Categories** / **Default** પર રાખો. એક જ પ્રદાતાનું
   રેન્કિંગ અલગ-અલગ શ્રેણીઓમાં જુદું હોઈ શકે છે, કારણ કે દરેક લીડરબોર્ડ મુજબ તેનું ટોચનું મોડેલ અલગ હોય છે.
2. **એક-વખતના સેટઅપ માટે પોડિયમને પ્રાધાન્ય આપો.** જો તમે માત્ર એક કે બે મફત
   પ્રદાતાઓને કનેક્ટ કરવા માંગતા હો, તો તમારી શ્રેણીમાં ટોચનું રેન્કિંગ ધરાવતા પ્રદાતાઓથી શરૂઆત કરો.
3. **Type બેજ તપાસો.** `NOAUTH` પ્રદાતાઓ સૌથી ઝડપથી કનેક્ટ થાય છે (કોઈ
   ઓળખપત્રોની જરૂર નથી). `OAUTH` / `APIKEY` મફત ટિયર માટે ઝડપી સાઇન-અપ જરૂરી છે, પરંતુ તે ઘણીવાર
   વધુ શક્તિશાળી મોડેલ ઉપલબ્ધ કરાવે છે. કનેક્શનનાં પગલાં માટે
   [મફત ટિયર માર્ગદર્શિકા](../getting-started/FREE-TIERS-GUIDE.md) જુઓ.
4. **ઘણા પ્રદાતાઓને કનેક્ટ કરો અને Auto-Comboને નિર્ણય લેવા દો.** આ પેજને
   શક્તિ આપતો એ જ Arena ELO ડેટા Auto-Combo સ્કોરિંગ એન્જિનના **કાર્ય-યોગ્યતા પરિબળ**ને પણ ડેટા પૂરો પાડે છે
   (`open-sse/services/autoCombo/taskFitness.ts`, રિઝોલ્યુશન ક્રમ
   `user_override → arena_elo → models_dev_tier → static table`). તેથી, તમે ટોચના
   મફત પ્રદાતાઓને કનેક્ટ કર્યા પછી, `model: "auto"` (દા.ત. `auto/coding`) વડે રાઉટિંગ કરવાથી
   દરેક વિનંતી માટે ઉચ્ચ-ગુણવત્તાવાળા મફત મોડેલને આપમેળે પ્રાધાન્ય મળશે. સંપૂર્ણ 16-પરિબળ સ્કોરિંગ માટે
   [Auto-Combo](../routing/AUTO-COMBO.md) જુઓ.
