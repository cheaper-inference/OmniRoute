> **TL;DR**: OmniRoute તેના **મફત** પ્રદાતાઓને મોડેલની ગુણવત્તા અનુસાર **Arena AI
> (LMArena-શૈલીના) ELO સ્કોર્સ**નો ઉપયોગ કરીને ક્રમ આપે છે. તમારા કાર્ય માટે કયા મફત
> પ્રદાતાઓ સૌથી મજબૂત મોડેલો આપે છે તે જોવા માટે ડૅશબોર્ડમાં **મફત પ્રદાતા રૅન્કિંગ્સ**
> પેજ ખોલો — એકંદરે અથવા કૅટેગરી (કોડિંગ, સમીક્ષા, દસ્તાવેજીકરણ, ડિબગિંગ) મુજબ ફિલ્ટર કરીને.

## તે શું છે

OmniRoute 377 પ્રદાતાઓની નોંધણી કરે છે, જેમાં 155 કેટલોગ એન્ટ્રીઓ ચિહ્નિત છે**free/no-auth** (નો-ઓથ, ફ્રી-ટાયર OAuth, અથવા ફ્રી-ટાયર API કી — [ફ્રી ટાયર ગાઈડ](../getting-started/FREE-TIERS-GUIDE.md) અને સંપૂર્ણ [ફ્રી ટિયર્સ ડિરેક્ટરી](../reference/FREE_TIERS.md) જુઓ). કેચ: મફત પ્રદાતાઓ મોડેલ ગુણવત્તામાં જંગલી રીતે બદલાય છે. ફ્રન્ટિયર મૉડલને સેવા આપતો નો-ઓથ પ્રદાતા એ નાના લેગસી મૉડલને સેવા આપતા કરતાં વધુ ઉપયોગી છે.

**મફત પ્રદાતા રેન્કિંગ્સ** જવાબો "** કયા મફત પ્રદાતા મને શ્રેષ્ઠ મોડેલ આપે છે?** " સાથે દરેક મફત પ્રદાતાના કેટલોગમાં જોડાઈને** ક્રાઉડ-સોર્સ્ડ ગુણવત્તા સ્કોર્સ** થી** એરેના AI લીડરબોર્ડ** (માનવ-પસંદગી ELO, LMArena ચેટબોટ એરેના પાછળ સમાન વિચાર). પછી પ્રદાતાઓને તેમની શક્તિ દ્વારા ક્રમાંકિત કરવામાં આવે છે** શ્રેષ્ઠ મફત મોડેલ** .

રેન્કિંગની ગણતરી ત્રણ વાસ્તવિક સ્ત્રોતોમાંથી કરવામાં આવે છે:

1. ફ્રી-પ્રોવાઇડર યાદીઓ — `NOAUTH_PROVIDERS`, વત્તા `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` એન્ટ્રીઝ ફ્લેગ કરેલ `hasFree` (`src/shared/constants/providers.ts`).
2. પ્રદાતા રજિસ્ટ્રી (`open-sse/config/providerRegistry.ts`) માંથી દરેક પ્રદાતાના મોડલનો કેટલોગ.
3. એરેના ELO સિંક એન્જિન (`src/lib/arenaEloSync.ts`) દ્વારા `model_intelligence` DB કોષ્ટકમાં સંગ્રહિત ELO-પ્રાપ્ત ટાસ્ક-ફિટ સ્કોર્સ.

જોડાવા તર્ક `src/lib/freeProviderRankings.ts` માં રહે છે.

## ઍક્સેસ કરવાની રીત

### ડૅશબોર્ડ પેજ

ડૅશબોર્ડ ખોલીને **ખર્ચ → મફત પ્રદાતા રૅન્કિંગ્સ** પર જાઓ અથવા સીધા અહીં નેવિગેટ કરો:

```
/dashboard/free-provider-rankings
```

આ પેજ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) નીચેની વસ્તુઓ દર્શાવે છે:

- શ્રેષ્ઠ ક્રમ ધરાવતા મફત પ્રદાતાઓનું **ટોચ-3 પોડિયમ** (🥇 🥈 🥉).
- આ કૉલમ સાથેનું સંપૂર્ણ **રૅન્કિંગ કોષ્ટક**: **ક્રમ**, **પ્રદાતા**, **ટોચનું મોડેલ**,
  **સ્કોર**, **સરેરાશ સ્કોર**, **મોડેલો**, **પ્રકાર**.
- **કૅટેગરી ફિલ્ટર બટનો**: _બધી કૅટેગરીઓ_, _ડિફૉલ્ટ_, _કોડિંગ_, _સમીક્ષા_,
  _દસ્તાવેજીકરણ_, _ડિબગિંગ_.

દરેક પ્રદાતાનું **પ્રકાર** બૅજ તે કેવી રીતે મફત છે તે જણાવે છે:

| બૅજ      | અર્થ                                       |
| -------- | ------------------------------------------ |
| `NOAUTH` | હંમેશાં મફત, કોઈ ઓળખપત્રોની જરૂર નથી       |
| `OAUTH`  | મફત ટિયર (`hasFree`) ધરાવતો OAuth પ્રદાતા  |
| `APIKEY` | મફત ટિયર (`hasFree`) ધરાવતો API-કી પ્રદાતા |

સ્કોર્સને કાચા આંકડાઓના બદલે માનવી સરળતાથી સમજી શકે તેવા લેબલ તરીકે દર્શાવવામાં આવે છે
(દા.ત. _શ્રેષ્ઠ_, _ઉત્કૃષ્ટ_, _ખૂબ સારું_, _સારું_, _સરેરાશ_), કારણ કે મૂળભૂત મૂલ્ય
ટકાવારી નહીં પરંતુ સાપેક્ષ રૅન્કિંગ ગુણવત્તા છે.

### API એન્ડપૉઇન્ટ

આ પેજને જાહેર રીડ એન્ડપૉઇન્ટ
(`src/app/api/free-provider-rankings/route.ts`) દ્વારા ડેટા મળે છે:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

ક્વેરી પેરામીટર્સ (Zod વડે માન્ય કરેલા):

| પેરામીટર   | પ્રકાર | ડિફૉલ્ટ    | નોંધો                                                                                                 |
| ---------- | ------ | ---------- | ----------------------------------------------------------------------------------------------------- |
| `category` | string | (કંઈ નહીં) | `default`, `coding`, `review`, `documentation`, `debugging`માંથી એક. સંયુક્ત રૅન્કિંગ માટે તેને છોડો. |
| `limit`    | number | `50`       | `1–100`ની શ્રેણી સુધી મર્યાદિત.                                                                       |

પ્રતિસાદનું માળખું:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` મૂળ Arena ELO મૂલ્ય છે; `score` સામાન્યકૃત કાર્ય-અનુકૂળતા મૂલ્ય છે
(નીચે જુઓ). કોઈ સ્કોર કરેલા મોડેલો ન ધરાવતા પ્રદાતાઓને પ્રતિસાદમાંથી બાકાત રાખવામાં આવે છે.

## સ્કોર કેવી રીતે કામ કરે છે

### સ્ત્રોત: Arena AI લીડરબોર્ડ

Arena ELO સિંક એન્જિન (`src/lib/arenaEloSync.ts`) Arena AI લીડરબોર્ડ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) પરથી બે લીડરબોર્ડ — `text`
અને `code` — લાવે છે. જ્યારે તે API કોઈ ઉપયોગી બોર્ડ પરત ન આપે, ત્યારે એન્જિન Hugging Face
datasets-server પરના ઓફિશિયલ `lmarena-ai/leaderboard-dataset` પર ફોલબેક કરે છે
(`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` એ `activeSource`, `lastError` અને
`lastFailedAt` રિપોર્ટ કરે છે. દરેક લીડરબોર્ડ એન્ટ્રીમાં
મોડેલનું નામ, વેન્ડર, ELO `score`, કોન્ફિડન્સ ઇન્ટરવલ અને વોટ સંખ્યા હોય છે.

લીડરબોર્ડ કેટેગરીઓ OmniRoute ટાસ્ક કેટેગરીઓ સાથે આ રીતે મેપ થાય છે:

| Arena લીડરબોર્ડ | OmniRoute ટાસ્ક કેટેગરીઓ                          |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### નોર્મલાઇઝેશન (ટાસ્ક-ફિટ સ્કોર)

કાચા ELO સ્કોર્સને દરેક લીડરબોર્ડ માટે **`[0.4, 0.98]` માં ટાસ્ક-ફિટ વેલ્યુ**માં નોર્મલાઇઝ કરવામાં આવે છે:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

સ્કોર ક્યારેય `0` કે `1` સુધી પહોંચતો નથી, જે યુઝર ઓવરરાઇડ્સ માટે જગ્યા છોડે છે. આ જ
`score` ફીલ્ડ છે જે તમને API રિસ્પોન્સમાં દેખાય છે અને ડેશબોર્ડ પર બતાવાય છે.

### કોન્ફિડન્સ

દરેક એન્ટ્રીને Arena વોટ સંખ્યાના આધારે કોન્ફિડન્સ લેવલ મળે છે:

| કોન્ફિડન્સ | વોટ્સ   |
| ---------- | ------- |
| `high`     | ≥ 5,000 |
| `medium`   | ≥ 1,000 |
| `low`      | < 1,000 |

### સ્ટોરેજ અને તાજગી

નોર્મલાઇઝ કરેલી એન્ટ્રીઓ `model_intelligence` DB ટેબલમાં
`source = "arena_elo"` સાથે લખવામાં આવે છે (`src/lib/db/modelIntelligence.ts`). એન્ટ્રીઓ
**7 દિવસ પછી સમાપ્ત થઈ જાય છે**, જેથી જે પ્રોવાઇડર સિંક કરવાનું બંધ કરી દે તે જૂનો ડેટા
આપવાને બદલે ધીમે ધીમે યાદીમાંથી ગાયબ થઈ જાય છે.

સિંક **ડિફોલ્ટ રૂપે ચાલુ** હોય છે:

- તે સર્વર સ્ટાર્ટઅપ સમયે એક વાર ચાલે છે અને પછી આવર્તક ટાઇમર પર ચાલતું રહે છે
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` થી વાયર્ડ).
- તે **નોન-બ્લોકિંગ છે અને ક્યારેય ફેટલ નથી** — જો અપસ્ટ્રીમ ફેચ નિષ્ફળ જાય, તો OmniRoute
  ચાલુ રહે છે અને રેન્કિંગ્સ ફક્ત છેલ્લો સારો ડેટા (અથવા ખાલી સ્થિતિ) બતાવે છે.

બે એન્વાયરનમેન્ટ વેરિયેબલ્સ તેને નિયંત્રિત કરે છે (
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) માં દસ્તાવેજિત):

| વેરિયેબલ                  | ડિફોલ્ટ       | હેતુ                                               |
| ------------------------- | ------------- | -------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | આઉટબાઉન્ડ સિંકથી બહાર નિકળવા માટે `false` સેટ કરો. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | સિંક ઇન્ટરવલ, સેકન્ડમાં.                           |

### મેન્યુઅલ સિંક / સ્ટેટસ / ક્લિયર

ઓપરેટર્સ માટે, એક ઓથેન્ટિકેટેડ મેનેજમેન્ટ એન્ડપોઇન્ટ મેન્યુઅલ નિયંત્રણ આપે છે
(`src/app/api/intelligence/sync/route.ts` — મેનેજમેન્ટ ઓથ જરૂરી છે):

```
GET    /api/intelligence/sync          # current sync status (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # trigger a manual sync; body: { "dryRun": true } to preview without writing
DELETE /api/intelligence/sync          # clear all synced arena_elo intelligence entries
```

જો રેન્કિંગ્સ પેજ ખાલી હોય, તો મેન્યુઅલ `POST /api/intelligence/sync` (અથવા ફક્ત
સર્વર રીસ્ટાર્ટ કરવાથી) તેને ફરીથી ભરે છે.

### મોડેલ્સને લીડરબોર્ડ સાથે મેચ કરવા

રજિસ્ટ્રી મોડેલ ID અને Arena મોડેલ નામો હંમેશા બરાબર મેળ ખાતા નથી. રેન્કિંગ ફ્લેક્સિબલ
મેચિંગનો ઉપયોગ કરે છે (`src/lib/freeProviderRankings.ts` માં `findMatchingIntelligence`):

1. નોર્મલાઇઝ કરેલા મોડેલ ID પર ચોક્કસ મેચ.
2. પાછળનો વર્ઝન સફિક્સ કાઢી નાખ્યા પછી મેચ (દા.ત. `kimi-k2.6` → `kimi-k2`).
3. પ્રીફિક્સ મેચ (લીડરબોર્ડ મોડેલ નામ રજિસ્ટ્રી ID નું પ્રીફિક્સ છે).

સિંક બાજુ, જાણીતા વેન્ડર પ્રીફિક્સ (`anthropic/`, `openai/`, `google/`, …) કાઢી
નાખવામાં આવે છે અને નાની એલિયાસ મેપ કેનોનિકલ નામોને OmniRoute અંદરરીયે વાપરતા વેરિઅન્ટ્સમાં
વિસ્તારે છે, જેથી મોડેલ્સ કોઈપણ નામ હેઠળ શોધી શકાય.

### પ્રોવાઇડરને કેવી રીતે રેન્ક કરવામાં આવે છે

દરેક ફ્રી પ્રોવાઇડર માટે, એન્જિન તેના કેટલોગના દરેક મોડેલને સ્કોર કરે છે, પછી:

- **Top Model** = પ્રોવાઇડરનું સૌથી વધુ સ્કોર ધરાવતું મોડેલ.
- **Avg Score** = તે પ્રોવાઇડરના તમામ સ્કોર કરેલા મોડેલ્સનો સરેરાશ સ્કોર.
- **Models** = પ્રોવાઇડરના કેટલા મોડેલ્સ પાસે Arena સ્કોર હતો.

પ્રોવાઇડર્સને પહેલા **ટોપ-મોડેલ સ્કોર** અને પછી સરેરાશ સ્કોર પ્રમાણે ગોઠવવામાં આવે છે. આ
એવા પ્રોવાઇડરને પુરસ્કાર આપે છે જે ઓછામાં ઓછું એક મજબૂત ફ્રી મોડેલ આપે છે.

## મફત પ્રદાતાઓ પસંદ કરવા માટે તેનો ઉપયોગ

1. **યોગ્ય શ્રેણી પસંદ કરો.** એજન્ટિક/કોડ વર્કલોડ માટે **Coding** ફિલ્ટરનો ઉપયોગ કરો અથવા
   સામાન્ય ચેટ માટે તેને **All Categories** / **Default** પર રાખો. એક જ પ્રદાતાનું
   રેન્કિંગ અલગ-અલગ શ્રેણીઓમાં જુદું હોઈ શકે છે, કારણ કે દરેક લીડરબોર્ડ મુજબ તેનું ટોચનું મોડેલ અલગ હોય છે.
2. **એક-વખતના સેટઅપ માટે પોડિયમને પ્રાધાન્ય આપો.** જો તમે માત્ર એક કે બે મફત
   પ્રદાતાઓને કનેક્ટ કરવા માંગતા હો, તો તમારી શ્રેણીમાં ટોચનું રેન્કિંગ ધરાવતા પ્રદાતાઓથી શરૂઆત કરો.
3. **Type બેજ તપાસો.** `NOAUTH` પ્રદાતાઓ સૌથી ઝડપથી કનેક્ટ થાય છે (કોઈ
   ઓળખપત્રોની જરૂર નથી). `OAUTH` / `APIKEY` મફત ટિયર માટે ઝડપી સાઇન-અપ જરૂરી છે, પરંતુ તે ઘણીવાર
   વધુ શક્તિશાળી મોડેલ ઉપલબ્ધ કરાવે છે. કનેક્શનનાં પગલાં માટે
   [મફત ટિયર માર્ગદર્શિકા](../getting-started/FREE-TIERS-GUIDE.md) જુઓ.
4. **ઘણા પ્રદાતાઓને કનેક્ટ કરો અને Auto-Comboને નિર્ણય લેવા દો.** આ પેજને
   શક્તિ આપતો એ જ Arena ELO ડેટા Auto-Combo સ્કોરિંગ એન્જિનના **કાર્ય-યોગ્યતા પરિબળ**ને પણ ડેટા પૂરો પાડે છે
   (`open-sse/services/autoCombo/taskFitness.ts`, રિઝોલ્યુશન ક્રમ
   `user_override → arena_elo → models_dev_tier → static table`). તેથી, તમે ટોચના
   મફત પ્રદાતાઓને કનેક્ટ કર્યા પછી, `model: "auto"` (દા.ત. `auto/coding`) વડે રાઉટિંગ કરવાથી
   દરેક વિનંતી માટે ઉચ્ચ-ગુણવત્તાવાળા મફત મોડેલને આપમેળે પ્રાધાન્ય મળશે. સંપૂર્ણ 16-પરિબળ સ્કોરિંગ માટે
   [Auto-Combo](../routing/AUTO-COMBO.md) જુઓ.
