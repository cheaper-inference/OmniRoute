તટસ્થ `config/cli-tools-manifest.json` કરાર પ્રમાણભૂત IDs, ઉપનામો, દ્વિસંગી ઉમેદવારો, સેટઅપ રેસિપિ, મોડેલ દલીલો અને ક્ષમતાઓ જાહેર કરે છે. `bin/cli/cli-manifest.mjs` માં સાદા નોડ એડેપ્ટર અને `src/shared/constants/cliIntegrationManifest.ts` માં TypeScript એડેપ્ટર સમાન ફાઇલ વાંચે છે. રનટાઇમ, કેટલોગ, રૂપરેખાંકન, પૂર્ણતા, જનરેટર અને બેકએન્ડ નોંધણી `tests/unit/cli/cli-manifest-drift.test.ts` દ્વારા એકસાથે તપાસવામાં આવે છે. સૂચિબદ્ધ હોવાનો અર્થ એ નથી કે ટૂલ લોન્ચ અથવા ગોઠવી શકાય છે. ખાસ કરીને, 5 ડાઇવ ફક્ત ગોઠવણી માટે જ રહે છે.

## બાળ પર્યાવરણ અને જીવનચક્ર

`omniroute run`, `omniroute launch` અને `omniroute launch-codex` એક OS/terminal સુસંગતતા અનુમતિ સૂચિને વારસામાં મેળવે છે અને પસંદ કરેલા લક્ષ્યના ઓળખપત્રોને ઇન્જેક્ટ કરે છે. અસંબંધિત પ્રદાતા અને ડેટાબેઝ રહસ્યો મૂળભૂત રીતે વારસામાં મળતા નથી. `--inherit-env` સ્પષ્ટપણે સંપૂર્ણ પિતૃ-પર્યાવરણ વારસાને પુનઃસ્થાપિત કરે છે; જ્યારે પસંદ કરેલ તૃતીય-પક્ષ પ્રક્રિયાએ તે મૂલ્યો પ્રાપ્ત કરવા જોઈએ ત્યારે જ તેનો ઉપયોગ કરો. આ પર્યાવરણ ફિલ્ટરિંગ છે, OS સેન્ડબોક્સ નથી: પ્રક્રિયા હજી પણ કૉલરની ફાઇલસિસ્ટમ પરવાનગીઓ સાથે ચાલે છે.

વિક્ષેપ અને સમાપ્તિ સંકેતો બાળકને ફોરવર્ડ કરવામાં આવે છે. લૉન્ચર અસ્થાયી ગોઠવણીને દૂર કરતા પહેલા બાળકની નજીકની ઘટનાની રાહ જુએ છે. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` ફરજિયાત સમાપ્તિ (ડિફોલ્ટ 5000 મિલિસેકન્ડ્સ) પહેલાના ગ્રેસ પીરિયડને નિયંત્રિત કરે છે.

## Gemini સતત સેટઅપ

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

પ્રથમ બે આદેશો આ મશીનને પસંદ કરેલ સ્થાનિક અથવા દૂરસ્થ સર્વર માટે ગોઠવે છે. સેટઅપ અસંબંધિત JSON સેટિંગ્સને સાચવે છે, Gemini API-key auth પસંદ કરે છે અને ખાનગી `.gemini/.env` ફાઇલમાં એન્ડપોઇન્ટ અને ઓળખપત્ર લખે છે. તે ફરીથી લખવાને બદલે અમાન્ય JSON નો ઇનકાર કરે છે. એન્ડપોઇન્ટ URLs એમ્બેડેડ ઓળખપત્રો, ક્વેરી પેરામીટર્સ અથવા ટુકડાઓ વિના HTTP(S) હોવું આવશ્યક છે. ડ્રાય-રન પ્રિન્ટ પાથ, ઓળખપત્ર મૂલ્યો નહીં.

`GEMINI_CLI_HOME` અથવા `--gemini-home` સતત હોમ રુટ પસંદ કરે છે. વાસ્તવિક `run gemini` તેનું પોતાનું કામચલાઉ ઘર બનાવે છે અને પછીથી દૂર કરે છે. કોઈપણ મોડ Gemini ની વર્કસ્પેસ-ટ્રસ્ટ તપાસને બાયપાસ કરતું નથી.

## Codex પ્રોફાઇલ્સ

`configure codex` એક મોડેલ અને તેના OmniRoute પ્રદાતા એન્ડપોઇન્ટ સાથે ખાનગી `<name>.config.toml` લખે છે. ઓળખપત્રો `OMNIROUTE_API_KEY` દ્વારા સંદર્ભિત કરવામાં આવે છે, ક્યારેય એમ્બેડેડ નથી. લોન્ચ કમાન્ડ પસંદ કરેલ મોડલને ટોપ-લેવલ `model` કી પર સેટ કરે છે, `model_providers` અંદર નહીં.

અલગ પ્રોફાઇલ ફાઇલો વર્તમાન દસ્તાવેજીકૃત Codex કરાર છે; જ્યારે `codex --profile <name>` સાથે પસંદ કરવામાં આવે ત્યારે તેઓ વપરાશકર્તા રૂપરેખાંકનને ઓવરલે કરે છે. [સત્તાવાર પ્રોફાઇલ સંદર્ભ](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) અને [OmniRoute Codex માર્ગદર્શિકા](./CODEX-CLI-CONFIGURATION.md) જુઓ.

## હર્મેટિક કમાન્ડ એક્ઝેક્યુશન

સ્પષ્ટ `DATA_DIR` સાથે, `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` સેટ કરવું સ્ટાર્ટઅપને ડિફોલ્ટ યુઝર ડેટા ડાયરેક્ટરીનાં ઓળખપત્ર પર્યાવરણમાં આવતા અટકાવે છે. આ અલગ પરીક્ષણો માટે ઉપયોગી છે. તે અન્ય સ્પષ્ટ રીતે પસંદ કરેલ પર્યાવરણ ફાઇલોને નિષ્ક્રિય કરતું નથી.

## વર્કિંગ-ડિરેક્ટરી `.env`

CLI આ ક્રમમાં `.env` ફાઇલોને વાંચે છે, અને કીને સેટ કરવા માટેની પ્રથમ ફાઇલ જીતે છે: સ્પષ્ટ `DATA_DIR`, ડિફોલ્ટ ડેટા ડિરેક્ટરી, વર્તમાન કાર્યકારી ડિરેક્ટરી, પછી પેકેજ ડિરેક્ટરી. શેલ ચલો હંમેશા જીતે છે.

કાર્યકારી નિર્દેશિકા અન્ય કોઈની હોઈ શકે છે (ક્લોન કરેલ રીપોઝીટરી, એક અનપેક્ડ આર્કાઈવ), અને `omniroute serve` સર્વર પર અને સર્વર ચલાવતા દરેક ટૂલ પર CLI પર્યાવરણ પસાર કરે છે. તેથી ત્યાં એક `.env` ફક્ત આ જ કી સેટ કરી શકે છે, જે `bin/cli/utils/untrustedCwdEnv.mjs` માં સૂચિબદ્ધ છે:

| કી                              | સ્વીકૃત મૂલ્યો                                                   |
| ------------------------------- | ---------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` અથવા `yes` કોઈપણ સંજોગોમાં, સર્વર જે મૂલ્યો માને છે  |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 64 અક્ષરો, અંકો, `_`, `.`, `@` અથવા `-` સુધી                     |
| `LANGUAGE`                      | સમાન, વત્તા `:`                                                  |
| `TZ`                            | 64 અક્ષરો, અંકો, `_`, `+`, `-` અથવા `/` સુધી, `/` થી શરૂ થતા નથી |
| `NO_COLOR`, `FORCE_COLOR`       | 16 અક્ષરો અને અંકો સુધી                                          |

`REQUIRE_API_KEY` સ્વીકારે છે તે દરેક મૂલ્ય ચેકને ચાલુ કરે છે, તેથી ફાઇલ પોતે ચેકને બંધ કરી શકતી નથી. તે પરિણામ નક્કી કરતું નથી, તેમ છતાં: સર્વર પર્યાવરણ પહેલાં ડેટાબેઝમાં સંગ્રહિત `REQUIRE_API_KEY` ઓવરરાઇડ વાંચે છે, જ્યારે API કી વિના તમામ ઇન્ટરફેસ પર સાંભળવા વિશેની સ્ટાર્ટઅપ ચેતવણી ફક્ત પર્યાવરણને વાંચે છે. `false` ના સંગ્રહિત ઓવરરાઇડ સાથે, વર્કિંગ-ડિરેક્ટરી `REQUIRE_API_KEY=true` API ને ખુલ્લું છોડી દે છે અને તે ચેતવણીને છુપાવે છે. `TZ` નિયમ POSIX કરતા સાંકડો છે : તે `.`, `:`, `,` અને `<>` ને નકારે છે, તેથી `:Area/City` ફોર્મ અને `EST5EDT,M3.2.0,M11.1.0` જેવા નિયમો શેલમાં અથવા `<DATA_DIR>/.env` માં સેટ કરવાના રહેશે.

મોટા કિસ્સામાં, નામો બરાબર મેળ ખાતા હોવા જોઈએ. કોઈપણ અન્ય લાઇન, મૂલ્ય કે જે તેની તપાસમાં નિષ્ફળ જાય છે, અને નામ કે જે સાદા ASCII અક્ષરો, અંકો અને `_` નથી (ઉદાહરણ તરીકે NUL બાઈટ અથવા દેખાવ જેવા અક્ષર સાથેનું એક) છોડવામાં આવે છે. CLI એક ચેતવણી છાપે છે કે જે તે સેટ કરી શકતી નથી તે કીને નામ આપે છે અને એક કે જે તેને અવગણવામાં આવેલી મંજૂરી કીને નામ આપે છે, દરેકમાં શું બદલવું છે (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). ન તો મૂલ્યો છાપે છે. આ સંદેશાઓમાં ફાઇલ પાથ, અને `.env` પાથ `omniroute doctor` રિપોર્ટ્સ, જ્યારે તેમાં નિયંત્રણ અથવા બિડી અક્ષરો હોય ત્યારે તે છટકી જાય છે. જ્યારે વર્કિંગ ડિરેક્ટરી ડેટા ડિરેક્ટરી અથવા પેકેજ ડિરેક્ટરી હોય ત્યારે પ્રતિબંધ લાગુ થતો નથી.

`PORT`, `API_PORT` અને `DASHBOARD_PORT` સૂચિમાં નથી. ઉચ્ચ-અગ્રતા સ્ત્રોતમાંથી બેઝ URL વિના, CLI `localhost:<PORT>` સાથે વાત કરે છે, અને ત્યાં જે પણ સાંભળે છે તે CLI ની API કી, સંદર્ભ ટોકન અને CLI મશીન ટોકન (`x-omniroute-cli-token`, જુઓ [CLI_TOKEN.md](../security/CLI_TOKEN.md) ) મેળવે છે, જેને સ્થાનિક સર્વર મેનેજમેન્ટ loop કોલ્સ માટે સ્વીકારે છે. કાર્યકારી નિર્દેશિકામાંથી એક પોર્ટ તે ફાઇલને સાંભળનારને પસંદ કરવા દે છે, તેથી પોર્ટોને શેલમાં, `<DATA_DIR>/.env` માં અથવા આદેશોના `--port` વિકલ્પ સાથે સેટ કરો જેમાં એક (`serve`, `launch`, `run`) હોય.

પાર્સર પાસે કોઈ `export` સિન્ટેક્સ નથી. `export LD_PRELOAD=...` જેવી રેખા ચલ `export LD_PRELOAD` નામ આપે છે; કાર્યકારી નિર્દેશિકામાંથી તે છોડવામાં આવે છે, અને અન્ય `.env` ફાઇલોમાં તે તે શાબ્દિક નામ સેટ કરે છે, જે કંઈ વાંચતું નથી.

CLI એ સંદર્ભના સંગ્રહિત ટોકન (એક્સેસ ટોકન અથવા લેગસી API કી) ને ફક્ત તે સંદર્ભના પોતાના મૂળ સાથે જોડે છે: સ્કીમ, હોસ્ટ અને પોર્ટ, `URL.origin` ની સરખામણીમાં. આ CLI ના HTTP ક્લાયન્ટ (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) દ્વારા કરવામાં આવેલી વિનંતીઓ અને `launch`, `launch codex`, `configure` અને `setup-*` આદેશોને લાગુ પડે છે જે અન્ય ટૂલની રૂપરેખામાં આધાર URL અને કી લખે છે. `--remote` સાથે બીજા સર્વર પર નિર્દેશિત, તેઓ સ્પષ્ટ `--api-key` અથવા `OMNIROUTE_API_KEY` ઉપયોગ કરે છે જો એક સેટ હોય, અને કોઈ સંદર્ભ ટોકન નથી. સરખામણી સચોટ છે, તેથી `localhost` અને `127.0.0.1`, અથવા ટ્રેલિંગ ડોટ સાથે અને વગર હોસ્ટને અલગ સર્વર્સ તરીકે ગણો અને કોઈ સંદર્ભ ટોકન મેળવો નહીં. વપરાશકર્તા માહિતી સાથેનો URL, બેકસ્લેશ અથવા વ્હાઇટસ્પેસ ક્યારેય મેળ ખાતો નથી, કારણ કે અન્ય URL પાર્સર્સ (ઉદાહરણ તરીકે પાયથોનના `urllib` અને `httpx`) તેનાથી અલગ હોસ્ટ વાંચી શકે છે. વિનંતીઓ માટે CLI પોતે જ મોકલે છે, તે ચેક માત્ર સ્કીમ અને ઓથોરિટીને આવરી લે છે, તેથી પાથ અથવા ક્વેરી પર જગ્યા ધરાવતી આઈડી ટોકન રાખે છે.
