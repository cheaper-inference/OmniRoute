OmniRoute દરેક વિનંતીની કિંમતનો અંદાજ કેવી રીતે લગાવે છે, તેને રેકોર્ડ કરે છે અને તેનો અહેવાલ આપે છે — અને શા માટે
ડૅશબોર્ડ પરનો આંકડો બિલ નહીં, પરંતુ **બચત ટ્રૅકર** છે.

આ પણ જુઓ: [વપરાશકર્તા માર્ગદર્શિકા](./USER_GUIDE.md) · [સુવિધાઓની ગૅલેરી](./FEATURES.md)

## તે શું છે (અને શું નથી)

OmniRoute ટોકનની સંખ્યાને મોડેલના કિંમત દરો વડે ગુણાકાર કરીને દરેક પૂર્ણતા માટે
પ્રતિ-વિનંતી USD કિંમત નક્કી કરે છે. આ આંકડાઓ **ખર્ચ** ડૅશબોર્ડ,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON નિકાસો અને પ્રતિ-API-કી બજેટને આધાર આપે છે.

> **ડૅશબોર્ડ પરનો "ખર્ચ" બચત ટ્રૅકર છે, બિલ નહીં.** OmniRoute તમારી પાસેથી ક્યારેય શુલ્ક લેતું નથી
> — તે તમારી વિનંતીઓને તમે અગાઉથી કનેક્ટ કરેલા પ્રદાતાઓ તરફ રૂટ કરે છે (તમારા પોતાના
> સબ્સ્ક્રિપ્શન, મફત ટિયર અને API કીઓ). સંપૂર્ણપણે મફત મોડેલો પર એકત્ર થયેલો "$290 કુલ ખર્ચ"
> એટલે અંદાજે **$290 જે તમે કોઈ સશુલ્ક APIને ચૂકવ્યા _નથી_**. આ આંકડો એ જ ટ્રાફિક માટે
> માનક સૂચિ કિંમતો અનુસાર લાગ્યા હોત એવા ખર્ચનો _અંદાજ_ છે, જેથી તમે જોઈ શકો કે
> તમારો ઉપયોગ ક્યાં કેન્દ્રિત છે અને સસ્તા/મફત પ્રદાતાઓ તરફ રૂટિંગ કરવાથી તમને કેટલી બચત થઈ રહી છે.

આ અભિગમ પ્રોજેક્ટના [README](../../README.md)માં સીધો જણાવવામાં આવ્યો છે ("ડૅશબોર્ડ પરનો
'ખર્ચ' બચત ટ્રૅકર છે, બિલ નહીં").

આ આંકડો અંદાજ હોવાથી:

- તે દરેક મોડેલ માટે OmniRoute પાસે રહેલા કિંમત કોષ્ટક પર આધાર રાખે છે. જે મોડેલ માટે કિંમતની
  એન્ટ્રી નથી તે `0` ખર્ચ ઉમેરે છે (એક્સપ્લોરરમાં તે "લેગસી / મફત" પંક્તિ તરીકે દેખાય છે).
- મફત-ટિયર અને સબ્સ્ક્રિપ્શન ટ્રાફિક માટે પણ _અંદાજિત_ ખર્ચ ઉમેરાય છે — તે
  તમારી બચતની રકમ છે, ચૂકવવાની બાકી રકમ નહીં.

## કેવી રીતે ખર્ચ અંદાજવામાં આવે છે

### કિંમત નિર્ધારણ સ્ત્રોત

ખર્ચ [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) માં મર્જ કરેલ કિંમત નિર્ધારણ કોષ્ટકમાંથી આવે છે, આ અગ્રતાના ક્રમમાં (** સૌથી વધુ પ્રથમ** ):

1. **વપરાશકર્તા ઓવરરાઇડ કરે છે** ડેશબોર્ડમાં અથવા `PATCH /api/pricing` ( `pricing` નેમસ્પેસ) દ્વારા સેટ કરેલ — કિંમતો.
2. **models.dev સમન્વયન** — પ્રાઇસિંગ `https://models.dev/api.json` ( `models_dev_pricing` નેમસ્પેસ) માંથી મેળવેલ છે.
3. **LiteLLM સમન્વયન** — કિંમતો LiteLLM ના સાર્વજનિક `model_prices_and_context_window.json` ( `pricing_synced` નેમસ્પેસ)માંથી મેળવેલ છે.
4. **હાર્ડકોડેડ ડિફોલ્ટ્સ** — દરો [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) માં મોકલવામાં આવે છે.

સમાન provider/model માટે, ઉચ્ચ-અગ્રતા સ્તરોમાંથી મૂલ્યો નીચલા સ્તરોમાં મેળ ખાતા ક્ષેત્રોને ઓવરરાઇટ કરે છે; ઉપલા સ્તરમાંથી ગેરહાજર ક્ષેત્રો હજુ પણ નીચલા સ્તરમાંથી આવી શકે છે. બંને સ્વતંત્ર સમન્વયન જોબ એક જ સમયે ચાલે ત્યારે પણ ક્રમ નિશ્ચિત છે. `GET /api/pricing?includeSources=1` `pricing` અને `sourceMap` પરત કરે છે, જેના પ્રતિ-મૉડલ લેબલ્સ (`user`, `modelsDev`, `litellm`, `default`) તે મૉડલ ધરાવતું ઉચ્ચતમ અગ્રતા સ્તર ઓળખે છે.

**LiteLLM સમન્વયન** ઑપ્ટ-ઇન છે, ડિફૉલ્ટ રૂપે અક્ષમ છે. તેના પર્યાવરણ ચલો (જુઓ [`.env.example`](../../.env.example) ) છે:

| Env var                 | ડિફૉલ્ટ   | હેતુ                                                                     |
| ----------------------- | --------- | ------------------------------------------------------------------------ |
| `PRICING_SYNC_ENABLED`  | `false`   | પૃષ્ઠભૂમિ LiteLLM કિંમત સમન્વયન સક્ષમ કરો.                               |
| `PRICING_SYNC_INTERVAL` | `86400`   | સમન્વયન અંતરાલ સેકંડમાં (દૈનિક).                                         |
| `PRICING_SYNC_SOURCES`  | `litellm` | માત્ર આ સમન્વયન માટે સ્ત્રોત પસંદગી; હાલમાં માત્ર `litellm` સપોર્ટેડ છે. |

**models.dev સમન્વયન** LiteLLM સમન્વયનથી અલગ છે અને મૂળભૂત રીતે અક્ષમ પણ છે. તેને સેટિંગ્સમાં સક્ષમ કરો (models.dev sync) અથવા આ ચલોનો ઉપયોગ કરો:

| Env var                    | ડિફૉલ્ટ   | હેતુ                                                                                                                                        |
| -------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(અનસેટ)_ | અનસેટ સેટિંગ્સ ટૉગલને અનુસરે છે; `1/true/on/yes` ફોર્સ ચાલુ કરે છે અને `0/false/off/no` ફોર્સ ઑફ કરે છે (જો સેટિંગ્સ તેને સક્ષમ કરે તો પણ). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`   | ડિફૉલ્ટ models.dev સિંક અંતરાલ સેકંડમાં (દૈનિક).                                                                                            |

`PRICING_SYNC_SOURCES` કરે છે** નથી** models.dev સક્ષમ કરો; તે માત્ર LiteLLM સમન્વયનને નિયંત્રિત કરે છે. વપરાશકર્તા ઓવરરાઇડ કાઢી નાખવાથી સમન્વયિત નેમસ્પેસ સાફ થતું નથી; આગામી ઉપલબ્ધ ભાવ સ્તર અસરકારક બને છે. અમૂલ્ય મોડલ માટે, મેન્યુઅલ ઓવરરાઇડ ઉમેરતા પહેલા સિંક સેટિંગ્સ અને `sourceMap` બંને તપાસો.

### ખર્ચ સૂત્ર

[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`) માં ટોકન ગણતરીઓ અને પ્રતિ-મિલિયન-ટોકન દરોમાંથી વિનંતી દીઠ ખર્ચની ગણતરી કરવામાં આવે છે:

- **ઇનપુટ ટોકન્સ** (માઈનસ કેશ રીડ અને કેશ-ક્રિએશન ટોકન્સ) × `input` દર.
- **કેશ-રીડ ટોકન્સ** × `cached` દર (ઇનપુટ દર પર પાછા આવે છે).
- **કેશ-નિર્માણ ટોકન્સ** × `cache_creation` દર (ઇનપુટ દર પર પાછા આવે છે).
- **આઉટપુટ ટોકન્સ** × `output` દર.
- **રિઝનિંગ ટોકન્સ** × `reasoning` દર (આઉટપુટ દર પર પાછા પડે છે).

તમામ દરોને 1,000,000 ટોકન્સ દીઠ USD તરીકે અર્થઘટન કરવામાં આવે છે. એક Codex "ઝડપી"/"પ્રાયોરિટી" અથવા "ફ્લેક્સ" સર્વિસ ટાયર ખર્ચ ગુણક (`getCodexFastCostMultiplier`) — લાગુ કરે છે જેમ કે ફ્લેક્સને 50% ટોકન ડિસ્કાઉન્ટ પર બિલ આપવામાં આવે છે, જે સપાટી પર આવે છે** ફ્લેક્સ બચત** ડેશબોર્ડમાં.

મોડલના નામો પહેલા સામાન્ય કરવામાં આવે છે (પ્રોવાઇડર-પાથ ઉપસર્ગ જેમ કે `openai/` અથવા `accounts/fireworks/models/` છીનવાઈ જાય છે) તેથી ઐતિહાસિક પંક્તિઓ હજુ પણ કિંમત સાથે મેળ ખાતી હોય છે.

### ખર્ચ કેવી રીતે રેકોર્ડ કરવામાં આવે છે

- વિનંતી પૂર્ણ થવા પર પ્રતિ-વિનંતી ખર્ચની ગણતરી કરવામાં આવે છે. શેર્ડ-ક્વોટા વપરાશ આગામી ઇવેન્ટ-લૂપ ટિક પર [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) દ્વારા સુનિશ્ચિત થયેલ છે.
- API-કી ખર્ચ [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (ડિફોલ્ટ 60 ફ્લશ ઇન્ટરવલ, 1,000-એન્ટ્રી બફર) દ્વારા બફર કરવામાં આવે છે અને બેચેસમાં ફ્લશ કરવામાં આવે છે. આના દ્વારા ટ્યુનેબલ:

  | Env var                             | ડિફૉલ્ટ | હેતુ                             |
  | ----------------------------------- | ------- | -------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | મિલિસેકંડમાં ફ્લશ અંતરાલ.        |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | ફ્લશ પહેલાં મહત્તમ બફર એન્ટ્રીઓ. |

ખર્ચ ચોક્કસ પ્રદાતા-રિપોર્ટેડ ચાર્જ (`provider_cost_usd`), પછી કેટલોગ-કિંમતની વિનંતી સ્નેપશોટ (`calculated_cost_usd`), પછી વર્તમાન કેટલોગમાંથી ટોકન રિપ્રાઈસિંગ પસંદ કરે છે. સંગ્રહિત ખર્ચ તેમની ટોકન ગણતરીઓ દ્વારા ફરીથી લેવામાં આવતો નથી. લીગસી ટોકન-ઓન્લી પંક્તિઓ હજુ પણ બદલાય છે જ્યારે તેમની સૂચિની કિંમત બદલાય છે.

### OCR અને એમ્બેડિંગ્સ

- સફળ `/v1/ocr` વિનંતીઓ અપસ્ટ્રીમ `usage_info.pages_processed` ઉપયોગ કરે છે, વિનંતી કરેલ પૃષ્ઠ શ્રેણી અથવા પરત કરેલા પૃષ્ઠ ઑબ્જેક્ટ્સની સંખ્યાનો નહીં. અંદાજ એ પૃષ્ઠો છે × `ocr_cost_per_page` (સંપૂર્ણ USD/page,** નથી** USD/million).
- દસ્તાવેજ અથવા બાઉન્ડિંગ-બોક્સ એનોટેશન સાથેની વિનંતીઓને અલગ `ocr_cost_per_annotated_page` ટેરિફની જરૂર છે. તેના વિના, કિંમત અજ્ઞાત રહે છે; સામાન્ય OCR ટેરિફ શાંતિપૂર્વક અવેજી કરવામાં આવતો નથી.
- LiteLLM સમન્વયન તેના અપસ્ટ્રીમ `annotation_cost_per_page` ફીલ્ડને `ocr_cost_per_annotated_page` માં મેપ કરે છે, સ્પષ્ટ શૂન્ય સહિત સંપૂર્ણ USD/page મૂલ્ય અને ફક્ત ટીકા-એન્ટ્રીઝ જાળવી રાખે છે. પૂરા પાડવામાં આવેલ કેનોનિકલ ક્ષેત્ર અગ્રતા લે છે; અમાન્ય ઉપનામ મૂલ્યો અવગણવામાં આવે છે. વપરાશકર્તા કિંમત ઓવરરાઇડ્સ તેમની સામાન્ય પ્રાથમિકતા જાળવી રાખે છે. [LiteLLM ની OCR પ્રાઇસીંગ કીઝ](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) જુઓ.
- OCR વપરાશ પૃષ્ઠની સંખ્યા, એકમ કિંમત, ગણતરી કરેલ USD કિંમત, API કી અને પસંદ કરેલ જોડાણ સંગ્રહિત કરે છે. પૃષ્ઠો ક્યારેય ટોકન્સ તરીકે રજૂ થતા નથી. કૉલ લૉગમાં બિલિંગ મેટાડેટા હોય છે, દસ્તાવેજ URLs, PDF બાઇટ્સ અથવા એક્સટ્રેક્ટ કરેલ ટેક્સ્ટ નથી.
- સફળ `/v1/embeddings` વિનંતીઓ એ જ મિલિસેકન્ડમાં પૂર્ણ થયેલ અલગ બેચ સહિત, ભૌતિક બેચ દીઠ એક વપરાશ પંક્તિ રેકોર્ડ કરે છે. પ્રદાતા-અહેવાલિત શુલ્ક ટોકન અંદાજો પર અગ્રતા ધરાવે છે; કોમ્બો રેપર્સ ચાર્જ ઉમેરતા નથી.
- વપરાશ ઇતિહાસ, ખર્ચ વિશ્લેષણ, provider/account વિન્ડો, API-કી ખર્ચ મર્યાદા, વિનંતી-ખર્ચ ખાતાવહી અને દૈનિક વપરાશના રોલઅપ્સમાં આ શુલ્ક શામેલ છે. નો-લોગ કી સ્ત્રોત ટેક્સ્ટને જાળવી રાખ્યા વિના સંખ્યાત્મક એકાઉન્ટિંગ જાળવી રાખે છે.
- ગુમ થયેલ વપરાશ અથવા ટેરિફ છે** અજ્ઞાત** , મફત નથી: પ્રતિભાવ-કિંમત હેડર અવગણવામાં આવે છે, અને હાલની અમૂલ્ય-ઉપયોગ નીતિ મર્યાદિત API કી પર લાગુ થાય છે. સ્પષ્ટ રીતે રૂપરેખાંકિત શૂન્ય દરો માન્ય શૂન્ય-કિંમત વપરાશ રહે છે.

આ માત્ર ફોરવર્ડ એકાઉન્ટિંગ છે. જૂના OCR/embedding કૉલ્સ કે જેણે ક્યારેય ઉપયોગ ઇતિહાસ લખ્યો નથી તે આ સ્થળાંતરમાંથી પુનઃનિર્માણ કરી શકાતો નથી. કેટલોગ અંદાજ USD અંદાજો છે, ઇન્વૉઇસ નહીં, અને તેમાં ચલણ રૂપાંતર, કર અથવા ડિસ્કાઉન્ટ શામેલ નથી.

### ભાષણ અને છબીઓ

- સફળ `/v1/audio/transcriptions`, `/v1/audio/speech` અને ઇમેજ-જનરેશનના પ્રયાસો આંકડાકીય હિસાબ વહેંચે છે. ડાયરેક્ટ અને કોમ્બો કૉલ્સમાં કૉલરની API કી અને પસંદ કરેલ કનેક્શન હોય છે; કોમ્બો રેપર ક્યારેય બીજું ડેબિટ ઉમેરતું નથી.
- પ્રદાતા-અહેવાલ કરેલ USD સ્પષ્ટ શૂન્ય ચાર્જ સહિત કેટલોગ અંદાજ પર જીતે છે. OpenRouter ના JSON `usage.cost` `cost_usd` માં સામાન્ય કરવામાં આવે છે. નહિંતર, માપેલા ટોકન્સ ટોકન કિંમતોનો ઉપયોગ કરે છે, ટ્રાંસ્ક્રિપ્શન સેકન્ડ પ્રતિ-સેકન્ડ કિંમતોનો ઉપયોગ કરે છે, સ્પીચ ઇનપુટ યુનિકોડ અક્ષરોની ગણતરીનો ઉપયોગ કરે છે, અને ફ્લેટ-કિંમતની છબીઓ ખરેખર પરત કરેલ સંખ્યાનો ઉપયોગ કરે છે, વિનંતી કરેલ `n` નહીં.
- દ્વિસંગી OpenRouter TTS પાસે કોઈ JSON ઉપયોગ બોડી નથી. ઑડિઓ પૂર્ણ થયા પછી અથવા કૉલર રદ કરે છે, OmniRoute તેના જનરેશન ID ને પર ક્વેરી કરે છે** સમાન** રૂપરેખાંકિત OpenRouter મૂળ. EU વિનંતી ક્યારેય વૈશ્વિક મૂળ પર પાછી આવતી નથી. આ એક બાઉન્ડેડ, ફક્ત વાંચવા માટે લુકઅપ છે; એકાઉન્ટિંગ માટે સંશ્લેષણનો પુનઃપ્રયાસ કરવામાં આવતો નથી. ઑડિયો સમાપ્ત થયા પછી બિલિંગ રેકોર્ડ્સ દેખાઈ શકે છે: નેટવર્ક ડેડલાઈન સહિત લગભગ 52 સેકન્ડ સુધી લુકઅપના પુનઃપ્રયાસો બેકગ્રાઉન્ડમાં ચાલે છે.
- તે લુકઅપ દરમિયાન, ઑડિઓ પ્રતિસાદમાં `X-OmniRoute-Cost-Status: pending` અને કોઈ પ્રતિભાવ-ખર્ચ હેડર નથી. તેનો અંતિમ ચાર્જ ઉપયોગ ઇતિહાસ, વિશ્લેષણ અને સમાધાન પછી કી ખાતાવહીમાં દેખાય છે. જો મેટાડેટા અનુપલબ્ધ હોય, તો રૂપરેખાંકિત ટેરિફ સ્નેપશોટનો ઉપયોગ થાય છે; અન્યથા ખર્ચ અજ્ઞાત રહે છે.
- સેકન્ડ્સ, અક્ષરો અને ઇમેજ કાઉન્ટ્સમાં અલગ બિલિંગ-યુનિટ ફીલ્ડ હોય છે, ક્યારેય નકલી ટોકન કાઉન્ટ નથી. એકાઉન્ટિંગ માત્ર સંખ્યાત્મક ઉપયોગને જાળવી રાખે છે, ભાષણ ટેક્સ્ટ, ટ્રાંસ્ક્રિપ્ટ્સ અથવા ઇમેજ બાઇટ્સ નહીં. હાલની અમૂલ્ય-ઇમેજ મુક્તિ અપરિવર્તિત છે: ખરેખર ખૂટતી ઇમેજ ટેરિફ મર્યાદિત કીને નવી રીતે લૉક કરતી નથી, અને પ્રતિસાદ કૉલ ફ્રી જાહેર કરવાને બદલે ખર્ચ હેડરને છોડી દે છે. કિંમત નિર્ધારણ સ્ટોર નિષ્ફળતા હજુ પણ નિષ્ફળ-બંધ અમલીકરણ માટે ઉપયોગ પુરાવા જાળવી રાખે છે.

કોઈ ઐતિહાસિક speech/image ચાર્જની શોધ કે બેકફિલ નથી. પ્રદાતા બિલિંગ ઇન્વૉઇસ અને કૉલ્સ માટે સંદર્ભ રહે છે કે જેના ચાર્જની જાણ કરવામાં આવી ન હતી.

## ડૅશબોર્ડ: ખર્ચ પેજ

**ખર્ચ** પેજ `/dashboard/costs` પર આવેલું છે
(`src/app/(dashboard)/dashboard/costs/`).
તેનું મુખ્ય દૃશ્ય **ખર્ચ ઝાંખી** ટૅબ છે
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
જે `GET /api/usage/analytics` માંથી બધું લોડ કરે છે.

તે શું દર્શાવે છે:

- **ખર્ચ ટાઇલ્સ** — _આજે (1d)_, _7d_, _30d_ અને પસંદ કરેલી
  સમયમર્યાદા માટેનો અંદાજિત ખર્ચ. શ્રેણી પસંદગીકાર: `7d`, `30d`, `90d`, `all`.
- **મુખ્ય મેટ્રિક્સ** — સમયમર્યાદામાં વિનંતીઓ, સક્રિય પ્રદાતાઓ, સક્રિય મોડેલો અને પ્રતિ
  વિનંતી સરેરાશ ખર્ચ.
- **ખર્ચ એક્સપ્લોરર** — **પ્રદાતા**, **મોડેલ**,
  **API કી**, **એકાઉન્ટ** અથવા **સેવા સ્તર** પ્રમાણે જૂથબદ્ધ કરી શકાય તેવું, સૉર્ટ/ફિલ્ટર કરી શકાય એવું ટેબલ, જેમાં ખર્ચ, વિનંતીઓ, ટોકન્સ, સરેરાશ
  ખર્ચ/વિનંતી અને કુલ ખર્ચમાં ટકાવારી હિસ્સો હોય છે.
- **ટોકન વપરાશ** — કુલ / ઇનપુટ / આઉટપુટ ટોકન્સ અને ઇનપુટ:આઉટપુટ ગુણોત્તર.
- **રૂટિંગ કાર્યક્ષમતા** — ફૉલબૅક સંખ્યા, ફૉલબૅક દર અને વિનંતી કરાયેલા મોડેલનું કવરેજ.
- **માસિક પૂર્વાનુમાન** — તાજેતરની દૈનિક સરેરાશના આધારે મહિનાના અંત સુધીના ખર્ચનો અંદાજ લગાવે છે.
- **સમયગાળા સરખામણી** — સમયમર્યાદાના પહેલા અને બીજા અર્ધભાગ વચ્ચેનો % ફેરફાર.
- **ચાર્ટ્સ** — દૈનિક ખર્ચ વલણ, પ્રદાતા હિસ્સો (પાઇ), ટોચના પ્રદાતાઓ, ટોચના મોડેલો, API કી પ્રમાણે ખર્ચ, એકાઉન્ટ પ્રમાણે ખર્ચ, સાપ્તાહિક વપરાશ પેટર્ન અને પ્રવૃત્તિ હીટમૅપ.
- **નિકાસ** — વર્તમાન સમયમર્યાદાને **CSV** અથવા **JSON** તરીકે ડાઉનલોડ કરો (શૂન્ય કરતાં વધુ ખર્ચનો ડેટા હોય ત્યારે
  બટનો દેખાય છે).

જ્યારે કિંમત નિર્ધારિત ટ્રાફિક ન હોય, ત્યારે પંક્તિઓ `$0` ને બદલે "લેગસી / મફત" લેબલ તરીકે રેન્ડર થાય છે,
જે બચત-ટ્રૅકર મોડેલને પ્રતિબિંબિત કરે છે.

### ખર્ચ સંબંધિત ઉપપૃષ્ઠો

ખર્ચ વિભાગમાં આ પણ સામેલ છે (બધાં `/dashboard/costs/` હેઠળ):

- **કિંમત નિર્ધારણ** (`/dashboard/costs/pricing`) — પ્રતિ-મોડેલ કિંમતો જુઓ અને ઓવરરાઇડ કરો (શેર કરેલો Pricing ટૅબ
  રેન્ડર કરે છે).
- **બજેટ** (`/dashboard/costs/budget`) — પ્રતિ-સ્કોપ ખર્ચ મર્યાદાઓ સેટ કરો (શેર કરેલો
  Budget ટૅબ રેન્ડર કરે છે).
- **ક્વોટા શેર** (`/dashboard/costs/quota-share`) — શેર કરેલા ક્વોટા પૂલ્સ અને ખર્ચ-દર
  દૃશ્યો.

## API અંતિમ બિંદુઓ

આ બધાને મેનેજમેન્ટ ઓથ (loopback/JWT, `requireManagementAuth` દ્વારા) ની જરૂર છે સિવાય કે નોંધ ન કરવામાં આવે.

### ઉપયોગ અને ખર્ચ વિશ્લેષણ

| પદ્ધતિ | અંતિમ બિંદુ              | હેતુ                                                                                                                                                           |
| ------ | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/analytics`   | સંપૂર્ણ cost/usage એનાલિટિક્સ: સારાંશ, દૈનિક વલણ, provider/model/API key/account/tier. ક્વેરી દ્વારા: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET`  | `/api/usage/utilization` | સમય જતાં પ્રતિ-પ્રદાતા ક્વોટાનો ઉપયોગ. પ્રશ્ન: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                                    |
| `GET`  | `/api/usage/history`     | કાચો ઉપયોગ ઇતિહાસ પંક્તિઓ.                                                                                                                                     |
| `GET`  | `/api/usage/call-logs`   | પ્રતિ-વિનંતી કૉલ લૉગ્સ (મૉડલ, ટોકન્સ, કિંમત, લેટન્સી, સ્ટેટસ).                                                                                                 |
| `GET`  | `/api/usage/quota`       | પ્રદાતા ક્વોટા સ્થિતિ.                                                                                                                                         |
| `GET`  | `/api/usage/proxy-logs`  | પ્રોક્સી વિનંતી લૉગ્સ.                                                                                                                                         |

### બજેટ

| પદ્ધતિ | અંતિમ બિંદુ              | હેતુ                                                                        |
| ------ | ------------------------ | --------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | એક API કી માટે ખર્ચ સારાંશ + બજેટ તપાસો (`apiKeyId` ક્વેરી પરમ જરૂરી છે).   |
| `POST` | `/api/usage/budget`      | એક API કી માટે daily/weekly/monthly USD મર્યાદા + ચેતવણી થ્રેશોલ્ડ સેટ કરો. |
| `GET`  | `/api/usage/budget/bulk` | સમગ્ર API કી પર બલ્ક બજેટ સારાંશ.                                           |

> બજેટ API પ્રતિ સ્કોપ્ડ છે**API કી** (`apiKeyId`) `GET /api/usage/budget` દ્વારા પરત કરવામાં આવેલી મર્યાદાઓમાં `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`, a `warningThreshold` અને ચાલી રહેલ ટોટલ (`totalCostToday`, `totalCostMonth`, …) નો સમાવેશ થાય છે.

### કિંમત નિર્ધારણ

| પદ્ધતિ   | અંતિમ બિંદુ             | હેતુ                                                                                                                                               |
| -------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | મર્જ કરેલ ચાર-સ્તરની કિંમતો (વપરાશકર્તા, models.dev, LiteLLM, ડિફોલ્ટ્સ). `?includeSources=1` `pricing` + `sourceMap` પરત કરે છે.                  |
| `PATCH`  | `/api/pricing`          | `{ provider: { model: { input, output, cached, … } } }` માટે કિંમતોને ઓવરરાઇડ કરો.                                                                 |
| `DELETE` | `/api/pricing`          | વપરાશકર્તા કિંમત ઓવરરાઇડ્સને દૂર કરો (વૈકલ્પિક રીતે `?provider=&model=` દ્વારા સ્કોપ્ડ); સમન્વયિત દરો અથવા બિલ્ટ-ઇન ડિફોલ્ટ્સ ફોલબેક તરીકે રહે છે. |
| `GET`    | `/api/pricing/defaults` | ડિફોલ્ટ per-1M ફોલબેક દરો બતાવો.                                                                                                                   |
| `GET`    | `/api/pricing/models`   | મોડલ દ્વારા કીડ કિંમત.                                                                                                                             |
| `POST`   | `/api/pricing/sync`     | બાહ્ય સ્ત્રોતો (LiteLLM) થી મેન્યુઅલ સિંક ટ્રિગર કરો.                                                                                              |
| `GET`    | `/api/pricing/sync`     | વર્તમાન સમન્વયન સ્થિતિ.                                                                                                                            |
| `DELETE` | `/api/pricing/sync`     | ફક્ત LiteLLM-સમન્વયિત કિંમતો સાફ કરો (`pricing_synced`); models.dev ડેટા અલગ છે.                                                                   |

## CLI

OmniRouteનું CLI ખર્ચ, વપરાશ અને કિંમત નિર્ધારણના આદેશો ઉપલબ્ધ કરાવે છે (જે
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)માં નોંધાયેલા છે).

### `omniroute cost`

`/api/usage/analytics`માંથી એકત્રિત કરાયેલ ખર્ચ અહેવાલ.

```bash
omniroute cost                          # છેલ્લા 30d, provider પ્રમાણે જૂથીકૃત
omniroute cost --period 7d              # છેલ્લા 7 દિવસ
omniroute cost --group-by model         # provider | model | combo | api-key | day પ્રમાણે જૂથીકૃત કરો
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

કૉલમ: જૂથ, વિનંતીઓ, ઇનપુટ/આઉટપુટ ટોકન, ખર્ચ (USD) અને કુલના %. અંતે એકંદર કુલની પંક્તિ
છાપવામાં આવે છે (`--quiet` અથવા `--output json` વડે તેને દબાવી શકાય છે).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # provider-દીઠ ખર્ચનો સારાંશ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# બજેટ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`, `GET /api/pricing/defaults`માંથી માહિતી વાંચે છે. તેના બદલે વ્યક્તિગત modelની
> કિંમતો સંપાદિત કરવા માટે, **Pricing** dashboard પેજ અથવા `PATCH /api/pricing`નો ઉપયોગ કરો.

## સમસ્યાનિવારણ

- **તમામ ખર્ચ $0 / "Legacy / Free" દર્શાવે છે.** ઉપયોગમાં રહેલા models માટે કિંમતની કોઈ એન્ટ્રી નથી.
  બાહ્ય sync સક્ષમ કરો (`PRICING_SYNC_ENABLED=true`) અને `omniroute pricing sync` ચલાવો, અથવા
  Pricing પેજ / `PATCH /api/pricing` દ્વારા કિંમતો મેન્યુઅલી સેટ કરો.
- **ઐતિહાસિક modelની કિંમત ખોટી છે.** કિંમત સુધારો (override કરો અથવા ફરી sync કરો) — analytics વાંચવામાં આવે ત્યારે દર વખતે
  tokenની સંખ્યાના આધારે ખર્ચની ફરી ગણતરી થાય છે, તેથી અંદાજો ભૂતકાળ માટે પણ અપડેટ થાય છે.
- **ખર્ચ વાસ્તવિક સમય કરતાં પાછળ રહે છે.** કી-દીઠ ખર્ચ batchમાં પ્રક્રિયા થાય છે; જો તમને વધુ તાજા આંકડાની જરૂર હોય તો
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ઘટાડો.
