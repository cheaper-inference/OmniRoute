`@omniroute/opencode-plugin-v2` તમારા સમગ્ર OmniRoute કૅટલૉગ — મોડલ્સ, કોમ્બોઝ અને
ઑટો-કોમ્બોઝ — ને ડિસ્પ્લે નામો, કિંમત અને ફ્રી-ટિયર
બજેટ્સ સાથે OpenCode v2ના મોડલ પિકરમાં મૂકે છે.

તે `@omniroute/opencode-plugin`થી અલગ પૅકેજ છે, કારણ કે OpenCode v1 અને v2
પ્લગિન્સને અલગ કૉન્ટ્રાક્ટ દ્વારા લોડ કરે છે. તમારા OpenCodeના મુખ્ય વર્ઝન સાથે મેળ ખાતું પૅકેજ પસંદ કરો;
બંને વચ્ચે કંઈપણ શેર થતું નથી, તેથી એકને અપગ્રેડ કરવાથી બીજાને અપગ્રેડ કરવાની ફરજ પડતી નથી.

## આવશ્યકતાઓ

- OpenCode v2.
- ઍક્સેસ કરી શકાય તેવું OmniRoute ગેટવે (ડિફૉલ્ટરૂપે `http://localhost:20128`).
- Node.js 22 અથવા 24.

## ઇન્સ્ટૉલેશન

`opencode.json`માં પ્લગિન ઉમેરો:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

ત્યારબાદ મોડલ્સ `omniroute/<provider>/<model>` તરીકે દેખાય છે; `providerId` તે પ્રીફિક્સ અને
OpenCode જે ઇન્ટિગ્રેશન હેઠળ ક્રેડેન્શિયલ સંગ્રહે છે તેનો id નક્કી કરે છે.

## ક્રેડેન્શિયલ્સ

પ્લગિન નીચેના ત્રણ સ્થળે, આ ક્રમમાં, ગેટવે કી શોધે છે:

1. **તમે OpenCodeમાં કનેક્ટ કરેલું ક્રેડેન્શિયલ.** પ્લગિન એક ઇન્ટિગ્રેશન રજિસ્ટર કરે છે, જેથી
   OpenCodeનો પોતાનો ઑથ ફ્લો કી સંગ્રહી શકે છે. `opencode.json`માં કંઈપણ સંગ્રહાતું નથી — આ વિકલ્પને પ્રાધાન્ય આપો.
2. દરેક પ્રોજેક્ટ માટે ઓવરરાઇડ તરીકે પ્લગિન વિકલ્પોમાં `apiKey`. આ કીને એવી ફાઇલમાં મૂકે છે
   જેને તમે કમિટ કરી રહ્યા હોઈ શકો છો.
3. એન્વાયર્નમેન્ટમાં `OMNIROUTE_API_KEY`.

ત્રણમાંથી એકપણ ઉપલબ્ધ ન હોય તો કૅટલૉગ ખાલી રહે છે અને તમને નિઃશબ્દ ખાલી પિકર આપવાને બદલે
પ્લગિન સ્ટાર્ટઅપ સમયે એક વાર તેની જાણ કરે છે.

### મેનેજમેન્ટ ટોકન એક અલગ કી છે

કોમ્બોઝ, પ્રોવાઇડર હેલ્થ અને એનરિચમેન્ટ (ડિસ્પ્લે નામો, કિંમત, ફ્રી-ટિયર બજેટ્સ)
ગેટવેના `/api/*` એન્ડપૉઇન્ટ્સમાંથી આવે છે, જેને મોટાભાગનાં ડિપ્લોયમેન્ટ્સ ઇન્ફરન્સ કીને બદલે
**મેનેજમેન્ટ** ટોકન વડે સુરક્ષિત કરે છે:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

સેટ ન કરેલું હોય તો `managementReadToken`, `apiKey`નો ઉપયોગ કરે છે. જ્યારે ગેટવે આ ફૉલબૅકને નકારે છે
ત્યારે પણ કૅટલૉગ પ્રકાશિત થાય છે, પરંતુ ડિસ્પ્લે નામોને બદલે કાચા મોડલ ids સાથે, કૅનોનિકલ
ઍલિયસ ડિડુપ્લિકેશન વિના, કિંમત વિના અને કોમ્બોઝ વિના. આવું થાય ત્યારે પ્લગિન દરેક એન્ડપૉઇન્ટ માટે એક વાર ચેતવણી આપે છે,
જેમાં એન્ડપૉઇન્ટ અને શું ગુમ થયું તેનું નામ જણાવે છે — જેથી ક્ષીણ થયેલું પિકર ક્યારેય રહસ્ય ન રહે.

ડિફૉલ્ટ રૂપે વપરાશ મેમરી ચાલુ છે. મેનેજમેન્ટ ટોકન વિના તે નિષ્ક્રિય રહે છે (સ્ટાર્ટઅપ નોટિસ લોગ થયેલ છે) અને કંઈપણ પુનઃસ્થાપિત થતું નથી.

## કેટલોગ તાજી કેવી રીતે રહે છે

સૂચિ આળસપૂર્વક લાવવામાં આવે છે અને `modelCacheTtlMs` માટે કેશ કરવામાં આવે છે, અને જ્યારે ગેટવે — સુધી પહોંચી ન શકાય તેવું હોય ત્યારે ડિસ્ક સ્નેપશોટ છેલ્લો જાણીતો કેટલોગ ઉપલબ્ધ રાખે છે અને આઉટેજ તમને તાજગી સિવાય કંઈપણ ખર્ચ કરતું નથી. મોડલ અને કોમ્બો આવતાની સાથે જ પ્રકાશિત થાય છે; સ્વતઃ-કોમ્બોઝ, પ્રદાતાની સૂચિ અને સંવર્ધન ઓવરલે જ્યારે તેઓ ઉતરે છે ત્યારે તેમાં ફોલ્ડ થાય છે, તેથી એક ધીમો અંતબિંદુ સમગ્ર પીકરને બંધક બનાવી શકતો નથી.

નામો `Provider - Model[ (Editor)][ · budget][ (route)]` અનુસરે છે : પ્રદાતા બતાવવામાં આવે છે જ્યારે પણ id વહન કરે છે (ઉપસર્ગ વિના સ્લેશ-લેસ id રેન્ડર કરે છે), અગ્રણી `🆓` મફત એન્ટ્રીઓને ચિહ્નિત કરે છે અને તેમનું ફ્રી-ટાયર બજેટ `· 1M tokens/month` પ્રત્યય તરીકે રહે છે, સ્પષ્ટ `Editor: Model` નામના સંપાદક પાછળના ભાગમાં જાય છે અને અન્ય કૌંસમાંથી સંપાદિત નામ (કૌંસના સંપાદન) છે. મફત ચિહ્ન વિના `combo - <slug>` તરીકે. નામ શેર કરતી બે એન્ટ્રીઓને રૂટ પ્રત્યય — `(no-think)` — મળે છે જેથી તેઓ અલગ કરી શકાય. `providerTag` (ડિફૉલ્ટ `true`) પાછળના સંપાદક કૌંસને ટૉગલ કરે છે.

ત્યાં કોઈ મેન્યુઅલ રીફ્રેશ કમાન્ડ નથી: OpenCode v2 કમાન્ડ પ્રોમ્પ્ટ ટેમ્પ્લેટ્સ છે, કોલબેક નથી, તેથી પ્લગઈન તેને એક્સપોઝ કરી શકતું નથી. રિફ્રેશ TTL ને અનુસરે છે; હોસ્ટને ફક્ત ત્યારે જ ફરીથી લોડ કરવા માટે કહેવામાં આવે છે જ્યારે કેટેલોગ અથવા ઓવરલે ખરેખર બદલાયેલ હોય, રિફ્રેશ દીઠ એકવાર નહીં.

## Gemini પર ટૂલ કૉલિંગ

Gemini એવી આખી રિક્વેસ્ટને નકારે છે જેના ટૂલ ડિક્લેરેશન્સમાં `$schema` અથવા
`additionalProperties` હોય છે અને જવાબમાં `400 INVALID_ARGUMENT` આપે છે. પ્લગઇન આ પ્રદાતાના
Gemini મોડેલ માટે મોકલાતી ટૂલ સ્કીમામાંથી તે કીવર્ડ્સ દૂર કરે છે અને અન્ય દરેક રિક્વેસ્ટને અસ્પર્શિત રાખે છે.
`$ref` ધરાવતું ટૂલ દૂર કરવાની પ્રક્રિયા વિના અસ્પર્શિત રીતે ફૉર્વર્ડ કરવામાં આવે છે, કારણ કે
રેફરન્સ દૂર કરવાથી સ્કીમા "કંઈપણ સ્વીકારવા" જેટલી વ્યાપક બની જશે.
તેને બંધ કરવા માટે `"geminiSanitization": false` સેટ કરો.

## મુશ્કેલીનિવારણ

| લક્ષણ                                          | કારણ                                                                                                           |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| પીકર કોઈ OmniRoute મોડલ બતાવતો નથી             | કોઈ કી ઉકેલાઈ નથી (સ્ટાર્ટઅપ ચેતવણી તપાસો), અથવા ગેટવે અગમ્ય છે                                                |
| કાચો મોડલ આઈડી, કોઈ કોમ્બોઝ નથી, કોઈ કિંમત નથી | મેનેજમેન્ટ એન્ડપોઇન્ટે ટોકન — સેટ `managementReadToken` નો ઇનકાર કર્યો હતો                                     |
| ટૂંકી અથવા ખાલી `freeOnly` સૂચિ                | કોઈ મેનેજમેન્ટ ટોકન અથવા ઇનકાર કરેલ ટોકન — હોસ્ટ લોગમાં રીફ્રેશ સમરી લાઇન (`unmatched-free` કાઉન્ટ) વાંચતો નથી |
| `opencode-<id>/...` પર પિન કરેલ સત્ર           | v1 પ્લગઇન પ્રકાશિત `opencode-<id>`; v2 `<id>` બેર પ્રકાશિત કરે છે, તેથી `<id>/...` હેઠળ મોડલને ફરીથી પસંદ કરો  |

પર્યાવરણ ચલોએ ઓપનકોડ સર્વર પ્રક્રિયા સુધી પહોંચવું આવશ્યક છે: જ્યારે હોસ્ટ સેવા તરીકે ચાલે છે, ત્યારે શેલ જે `opencode models` ચલાવે છે અને સર્વર પર્યાવરણ અલગ છે, તેથી જ્યાં સર્વર તેને વાંચે છે ત્યાં કીની નિકાસ કરો.
