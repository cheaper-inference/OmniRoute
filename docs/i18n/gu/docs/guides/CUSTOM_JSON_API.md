કસ્ટમ JSON API નોડ JSON બિઝનેસ એન્ડપોઇન્ટને જોડે છે જે OpenAI અથવા Anthropic પ્રોટોકોલ બોલતા નથી. OmniRoute એક JSON વિનંતી ટેમ્પલેટ ભરે છે, તેને સંપૂર્ણ એન્ડપોઇન્ટ URL પર મોકલે છે, પ્રતિભાવ પાથમાંથી જવાબ વાંચે છે અને ક્લાયન્ટના પોતાના ફોર્મેટમાં (ચેટ પૂર્ણતાઓ, પ્રતિસાદો, સંદેશાઓ, ...) ક્લાયંટને પરત કરે છે.

તે `apiType: "custom-json"` સાથે OpenAI-સુસંગત નોડ છે; તેના id માં `openai-compatible-custom-json-<suffix>` ફોર્મ છે. ડેશબોર્ડ ફોર્મ હજી ઉપલબ્ધ નથી. નીચે આપેલા પ્રદાતા-નોડ API દ્વારા આ નોડ્સ બનાવો અને સંપાદિત કરો.

## નોડ બનાવો

`POST /api/provider-nodes` (મેનેજમેન્ટ ઓથ):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` છે** પૂર્ણ** એન્ડપોઇન્ટ URL. કંઈ ઉમેરાયેલ નથી (કોઈ `/chat/completions`, કોઈ `/models` નથી) અને, અન્ય OpenAI- સુસંગત નોડ્સથી વિપરીત, ત્યાં કોઈ ડિફોલ્ટ URL નથી. તે `http(s)` હોવું જોઈએ, એમ્બેડેડ ઓળખપત્રો અથવા `#fragment` વિના, અને તે દરેક પ્રદાતા નોડની જેમ જ આઉટબાઉન્ડ URL ગાર્ડ પસાર કરે છે, જ્યારે નોડ સાચવવામાં આવે ત્યારે અને દરેક વિનંતી પર.
- નોડ કે જે કનેક્શન કી મોકલે છે (`authType` `bearer` અથવા `api-key`, ડિફોલ્ટ સહિત) `https://` ઉપયોગ કરવો આવશ્યક છે. સાદો `http://` ફક્ત લૂપબેક હોસ્ટ (`localhost`, `127.0.0.0/8`, `::1`) અથવા `authType: "none"` સાથે સ્વીકારવામાં આવે છે, જે કોઈ કી મોકલતું નથી. ખાનગી LAN સરનામાં (`10.x`, `172.16-31.x`, `192.168.x`) મુક્ત નથી: તે નેટવર્ક પરની કોઈપણ વ્યક્તિ કી વાંચી શકે છે. આવા નોડને સાચવવાનું `400` સાથે નિષ્ફળ જાય છે, અને કોઈપણ વિનંતી મોકલવામાં આવે તે પહેલાં, સમાન સંદેશ સાથેની દરેક વિનંતી પર અગાઉ સંગ્રહિત નોડ નિષ્ફળ જાય છે. LAN પર કીડ એન્ડપોઇન્ટ માટે, તેને TLS પાછળ મૂકો (ઉદાહરણ તરીકે રિવર્સ પ્રોક્સી).
- `customJson` Zod સાથે માન્ય છે; અજ્ઞાત કીઓ નકારવામાં આવે છે. દરેક ક્ષેત્ર વૈકલ્પિક છે:

| ક્ષેત્ર           | મૂલ્યો                              | ડિફૉલ્ટ                                                |
| ----------------- | ----------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`              | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`         | `bearer`                                               |
| `authHeader`      | હેડર નામનો ઉપયોગ જ્યારે `api-key`   | `X-API-Key`                                            |
| `requestTemplate` | JSON ઑબ્જેક્ટ (≤ 64 KB, ઊંડાઈ ≤ 32) | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | ફીલ્ડ પાથ, અથવા સમગ્ર શરીર માટે `$` | `choices[0].message.content`                           |

- રહસ્ય કનેક્શનની API કીમાં રહે છે, નમૂનામાં ક્યારેય નહીં. `bearer` `Authorization: Bearer <key>` મોકલે છે; `api-key` `<authHeader>: <key>` મોકલે છે. પ્રમાણીકરણ હેડર `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` અથવા હોપ-બાય-હોપ હેડર હોઈ શકતું નથી. `none` સાથે, કનેક્શનને કોઈ કીની જરૂર નથી.
- વધારાના સ્ટેટિક હેડરો નોડના નિયમિત `customHeaders` નો ઉપયોગ કરે છે (દરેક અન્ય સુસંગત નોડની જેમ જ માન્યતા; ઓથ હેડરોને ત્યાં મંજૂરી નથી).

`PUT /api/provider-nodes/<id>` એ જ `customJson` સ્વીકારે છે અને નોડના દરેક હાલના જોડાણ પર `baseUrl` અને રૂપરેખાને ફરીથી લખે છે. `customJson` છોડી દેવાથી સંગ્રહિત રૂપરેખા જળવાઈ રહે છે; `apiType` ને `chat` અથવા `responses` પર સ્વિચ કરવાથી તે નોડ અને તેના જોડાણોમાંથી દૂર થાય છે.

પછી નોડમાં હંમેશની જેમ કનેક્શન ઉમેરો ( નોડ આઈડી સાથે`POST /api/providers` ) અને `<prefix>/<model>` વિનંતી કરો, ઉદાહરણ તરીકે `biz/assistant-v1`. એન્ડપૉઇન્ટ કોઈ મૉડલ સૂચિને પ્રગટ કરતું નથી, તેથી મૉડલ આઈડી હાથથી ઉમેરો.

## નમૂનાઓની વિનંતી કરો

નમૂનાઓ સાદા JSON છે. શબ્દમાળા મૂલ્યમાં `{{placeholder}}` માર્કર્સ હોઈ શકે છે; કંઈપણ મૂલ્યાંકન અથવા ચલાવવામાં આવતું નથી, અને ઑબ્જેક્ટ કી ક્યારેય બદલાતી નથી.

| પ્લેસહોલ્ડર          | મૂલ્ય                                                                    |
| -------------------- | ------------------------------------------------------------------------ |
| `{{prompt}}`         | નવીનતમ વપરાશકર્તા સંદેશનો ટેક્સ્ટ (ટેક્સ્ટ ભાગો નવી લાઇન સાથે જોડાયા છે) |
| `{{messages}}`       | OpenAI ચેટ ફોર્મેટમાં વાતચીત                                             |
| `{{model}}`          | પ્રદાતા ઉપસર્ગ વિના વિનંતી કરેલ મોડેલ id                                 |
| `{{stream}}`         | હંમેશા `false` — એક JSON દસ્તાવેજ સાથે એન્ડપોઇન્ટના જવાબો આપો            |
| `{{request.<path>}}` | અનુવાદિત (OpenAI ચેટ ફોર્મેટ) વિનંતીનું ક્ષેત્ર                          |

- એક મૂલ્ય કે જે બરાબર એક પ્લેસહોલ્ડર છે તે તેના JSON પ્રકારને રાખે છે (`"{{messages}}"` એરે બને છે); લાંબા સ્ટ્રિંગની અંદર પ્લેસહોલ્ડર ટેક્સ્ટ તરીકે દાખલ કરવામાં આવે છે.
- પ્લેસહોલ્ડર કે જે કંઈપણ ઉકેલે છે તે અપૂર્ણ પેલોડ મોકલવાને બદલે HTTP 400 સાથે વિનંતીને નિષ્ફળ કરે છે.
- પાથ ડોટ નોટેશન અને ન્યુમેરિક ઈન્ડેક્સ (`data.items[0].text`) નો ઉપયોગ કરે છે. `__proto__`, `prototype` અને `constructor` કી અને પાથમાં નકારવામાં આવે છે.

## પ્રતિભાવો

`responsePath` પરની કિંમત સહાયક જવાબ બની જાય છે: શબ્દમાળાઓ પસાર થાય છે, અન્ય JSON મૂલ્યો ક્રમાંકિત થાય છે. ગુમ થયેલ અથવા `null` ફીલ્ડ, અથવા બોડી કે જે JSON નથી, HTTP 502 પરત કરે છે. અપસ્ટ્રીમ ભૂલ સ્થિતિઓ પસાર થાય છે. સ્ટ્રીમિંગ ક્લાયન્ટ્સ માટે OmniRoute સમગ્ર JSON પ્રતિસાદની રાહ જુએ છે અને પછી તેને એક સામગ્રી ભાગ વત્તા સમાપ્ત ભાગ તરીકે બહાર કાઢે છે; આ ટોકન સ્ટ્રીમિંગ નથી. ટૂલ કૉલ્સ અને ઉપયોગ ક્ષેત્રો મેપ કરેલ નથી.

## ક્યારેય રિપ્લે કર્યું નથી

વ્યવસાયિક વિનંતી નિષ્ફળ જાય ત્યારે પણ તેની આડઅસર થઈ શકે છે. તેથી OmniRoute તેને એકવાર મોકલે છે:

- કોઈ પરિવહન પુનઃપ્રયત્ન નથી અને કોઈ રીડાયરેક્ટ નથી;
- અન્ય કનેક્શન (એકાઉન્ટ ફોલબેક) પર ફરીથી પ્રયાસ કરશો નહીં — નિષ્ફળતા જેમ છે તેમ પરત કરવામાં આવે છે અને કનેક્શન ઠંડું કરવામાં આવતું નથી;
- આગળના કોમ્બો લક્ષ્ય પર કોઈ ફોલબેક નહીં, ખાલી અથવા નિષ્ફળ જવાબ માટે પણ.

અલગ ક્લાયંટ વિનંતીઓ, અને ફ્યુઝન પેનલ્સ કે જે સ્પષ્ટપણે ઘણા મોડેલોને કૉલ કરે છે, હજુ પણ સ્વતંત્ર રીતે એન્ડપોઇન્ટને બોલાવે છે.

## નોડનું પરીક્ષણ

જોડાણ સાચવી રહ્યું છે, જોડાણ** ટેસ્ટ** બટન અને બેકગ્રાઉન્ડ હેલ્થ ચેક્સ ક્યારેય એન્ડપોઇન્ટને કોલ કરતા નથી: તેઓ માત્ર સ્ટોર કરેલ રૂપરેખાને માન્ય કરે છે અને કનેક્શનને ચકાસી શકાય તેવું નથી તરીકે જાણ કરે છે.

`POST /api/provider-nodes/validate` સાથે `"apiType": "custom-json"` અને નોડ ફીલ્ડ્સ (`baseUrl`, `apiKey`, `customJson`, વૈકલ્પિક `customHeaders` અને `modelId`) એકદમ એક વાસ્તવિક વિનંતી મોકલે છે, જેમાં `ping` નવીનતમ વપરાશકર્તા ટેક્સ્ટ તરીકે છે. તે `{ "valid": true }` અથવા અપસ્ટ્રીમ સ્ટેટસ (ક્યારેય અપસ્ટ્રીમ બોડી નહીં) નો જવાબ આપે છે.

## સંગ્રહ

રૂપરેખા `provider_nodes.custom_json_config_json` (માઇગ્રેશન `240_provider_node_custom_json_config.sql`) માં સંગ્રહિત થાય છે અને દરેક કનેક્શનના `providerSpecificData.customJson` માં નકલ કરવામાં આવે છે.

અમલીકરણ: `open-sse/utils/customJson.ts` (માન્યતા અને ટેમ્પ્લેટિંગ), `open-sse/executors/customJson.ts` (એક્ઝિક્યુટર), `open-sse/services/combo/noReplayLatch.ts` અને `src/sse/handlers/chat/responsePolicies.ts` (નો-રિપ્લે).
