## 🎯 ઉપયોગના કિસ્સાઓ

### કિસ્સો 1: "મારી પાસે Claude Pro સબ્સ્ક્રિપ્શન છે"

**સમસ્યા:** ક્વોટા વપરાયા વિના સમાપ્ત થઈ જાય છે, ભારે કોડિંગ દરમિયાન રેટ લિમિટ્સ આવે છે

```
કૉમ્બો: "maximize-claude"
  1. cc/claude-opus-4-7        (સબ્સ્ક્રિપ્શનનો સંપૂર્ણ ઉપયોગ કરો)
  2. glm/glm-4.7               (ક્વોટા પૂરો થાય ત્યારે સસ્તું બૅકઅપ)
  3. if/qwen3.8-max-preview       (કટોકટી માટે મફત ફૉલબૅક)

માસિક કિંમત: $20 (સબ્સ્ક્રિપ્શન) + ~$5 (બૅકઅપ) = કુલ $25
તેની સરખામણીમાં $20 + મર્યાદાઓ સુધી પહોંચી જવું = નિરાશા
```

### કિસ્સો 2: "મારે શૂન્ય ખર્ચ જોઈએ છે"

**સમસ્યા:** સબ્સ્ક્રિપ્શન પરવડી શકતું નથી, વિશ્વસનીય AI કોડિંગની જરૂર છે

```
કૉમ્બો: "zero-cost"
  1. if/kimi-k2.7-code          (મફત ઍક્સેસ તરીકે સૂચિબદ્ધ; રેટ લિમિટ્સ લાગુ પડી શકે છે)
  2. kr/qwen3-coder-next        (Kiroનો મફત ફૉલબૅક)

માસિક કિંમત: $0
ગુણવત્તા: તમારા વર્કલોડ માટે મોડેલ, મર્યાદાઓ, ગોપનીયતા અને SLA ચકાસો
```

### કિસ્સો 3: "મારે કોઈ વિક્ષેપ વિના 24/7 કોડિંગ જોઈએ છે"

**સમસ્યા:** સમયમર્યાદાઓ છે, ડાઉનટાઇમ પરવડી શકે તેમ નથી

```
કૉમ્બો: "always-on"
  1. cc/claude-opus-4-7        (શ્રેષ્ઠ ગુણવત્તા)
  2. cx/gpt-5.5                (બીજું સબ્સ્ક્રિપ્શન)
  3. glm/glm-4.7               (સસ્તું, દરરોજ રીસેટ થાય છે)
  4. minimax/MiniMax-M2.1      (સૌથી સસ્તું, 5 કલાકે રીસેટ)
  5. if/deepseek-v4-flash       (મફત ઍક્સેસ તરીકે સૂચિબદ્ધ; રેટ લિમિટ્સ લાગુ પડી શકે છે)

પરિણામ: 5 ફૉલબૅક સ્તરો સ્થિતિસ્થાપકતાને વિસ્તૃત કરે છે; અપસ્ટ્રીમ ઉપલબ્ધતાની ખાતરી નથી
માસિક કિંમત: $20-200 (સબ્સ્ક્રિપ્શન્સ) + $10-20 (બૅકઅપ)
```

### કિસ્સો 4: "મારે OpenClawમાં મફત AI જોઈએ છે"

**સમસ્યા:** મેસેજિંગ ઍપ્સમાં સંપૂર્ણપણે મફત AI સહાયકની જરૂર છે

## 🚀 ડિપ્લૉયમેન્ટ

### વૈશ્વિક npm ઇન્સ્ટૉલ (ભલામણ કરેલ)

```bash
npm install -g omniroute

# કૉન્ફિગ ડિરેક્ટરી બનાવો
mkdir -p ~/.omniroute

# .env ફાઇલ બનાવો (.env.example જુઓ)
cp .env.example ~/.omniroute/.env

# સર્વર શરૂ કરો
omniroute
# અથવા કસ્ટમ પોર્ટ સાથે:
omniroute --port 3000
```

CLI આપમેળે `~/.omniroute/.env` અથવા `./.env`માંથી `.env` લોડ કરે છે.

### ટ્રે મોડ

સિસ્ટમ ટ્રેમાં OmniRoute શરૂ કરો:

```bash
omniroute serve --tray
```

સર્વર અને ટ્રે તૈયાર થયા પછી આ કમાન્ડ પૂર્ણ થાય છે.

સર્વર ટર્મિનલ વિના પણ ચાલુ રહે છે.

ટ્રે મોડ macOS, Windows અને ગ્રાફિકલ Linux સેશન્સને સપોર્ટ કરે છે. ટ્રે મોડ ડૅશબોર્ડને આપમેળે ખોલતું નથી.

આ ક્રિયાઓ માટે ટ્રે મેનૂનો ઉપયોગ કરો:

- ડૅશબોર્ડ ખોલો.
- `/dashboard/logs` ખોલો.
- ઑટો-સ્ટાર્ટ બદલો.
- OmniRoute બંધ કરો.

આ વિકલ્પો સાથે `--tray`ને જોડશો નહીં:

- `--daemon`
- `--log`
- `--no-recovery`

આ મોડ્સ માટે અલગ પ્રોસેસ માલિકીની જરૂર પડે છે.

મશીનમાં આગામી લૉગિન વખતે સ્ટાર્ટઅપ સક્ષમ કરો:

```bash
omniroute autostart enable
```

ઑટો-સ્ટાર્ટ macOS, Windows અને ગ્રાફિકલ Linux સેશન્સ પર ટ્રે મોડનો ઉપયોગ કરે છે. હેડલેસ Linux હાલની systemd યુઝર સર્વિસનો ઉપયોગ કરે છે.

લૉગિન વખતે સ્ટાર્ટઅપ અક્ષમ કરો:

```bash
omniroute autostart disable
```

| `npm run uninstall:full` | ઍપ દૂર કરે છે અને **બધાં કૉન્ફિગરેશન્સ, કીઝ અને ડેટાબેસ કાયમ માટે ભૂંસી નાખે છે**.          |

> નોંધ: આ કમાન્ડ્સ ચલાવવા માટે OmniRoute પ્રોજેક્ટ ફોલ્ડર પર જાઓ (જો તમે તેને ક્લોન કર્યું હોય) અને તેમને ચલાવો. વૈકલ્પિક રીતે, જો વૈશ્વિક સ્તરે ઇન્સ્ટૉલ કર્યું હોય, તો તમે ફક્ત `npm uninstall -g omniroute` ચલાવી શકો છો.

## 🧩 અદ્યતન સુવિધાઓ

### કસ્ટમ મોડલ્સ

એપ અપડેટની રાહ જોયા વિના કોઈપણ પ્રોવાઇડરમાં કોઈપણ મોડલ ID ઉમેરો:

```bash
# Via API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# List: curl http://localhost:20128/api/provider-models?provider=openai
# Remove: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

અથવા Dashboard નો ઉપયોગ કરો: **Providers → [Provider] → Custom Models**.

નોંધો:

- OpenRouter અને OpenAI/Anthropic-સુસંગત પ્રોવાઇડર્સ ફક્ત **Available Models** માંથી જ મેનેજ થાય છે. મેન્યુઅલ ઉમેરો, ઇમ્પોર્ટ અને ઓટો-સિંક બધા એ જ available-model યાદીમાં જાય છે, તેથી તે પ્રોવાઇડર્સ માટે અલગ Custom Models વિભાગ હોતો નથી.
- **Custom Models** વિભાગ તે પ્રોવાઇડર્સ માટે બનાવેલ છે જે મેનેજ્ડ available-model ઇમ્પોર્ટ્સ પ્રદાન કરતા નથી.

### કસ્ટમ OpenAI-સુસંગત પ્રોવાઇડર્સ

OpenAI API બોલતું કોઈપણ ગેટવે (સેલ્ફ-હોસ્ટેડ પ્રોક્સી, vLLM, તૃતીય-પક્ષ એગ્રિગેટર) પોતાના પ્રોવાઇડર નોડ તરીકે ઉમેરી શકાય છે:

1. **Providers → Add OpenAI Compatible**.
2. **Name**: નોડ માટે ડિસ્પ્લે લેબલ.
3. **Prefix**: રૂટિંગ નામ. ક્લાયંટ્સ મોડલ્સને `<prefix>/<model>` તરીકે કૉલ કરે છે, તેથી `mygw` પ્રિફિક્સ ધરાવતું નોડ `mygw/gpt-4o-mini` સર્વ કરે છે. આવશ્યક છે; કોઈ અક્ષર પ્રતિબંધ નથી.
4. **API Type**: ગેટવે જે એન્ડપોઇન્ટ ફેમિલી સર્વ કરે છે તે (Chat Completions, Responses, Embeddings, audio, images).
5. **Base URL**: API રૂટ, `/v1` સુધી તેના સમાવેશ સાથે (ઉદાહરણ તરીકે `https://gateway.example.com/v1`), સંપૂર્ણ `/chat/completions` પાથ નહીં. બિન-પ્રમાણભૂત પાથ્સ ધરાવતા ગેટવે તેને **Advanced Settings** હેઠળ સેટ કરે છે (chat path, models path).
6. **API Key (for Check)** ફીલ્ડ ફક્ત કનેક્શન ટેસ્ટ કરે છે. નોડ બનાવ્યા પછી, તેને ખોલો અને રિક્વેસ્ટ્સ જે કી વાપરશે તે સંગ્રહવા માટે **Add Connection** નો ઉપયોગ કરો.

નોડને `openai-compatible-<apiType>-<uuid>` સ્વરૂપનો આંતરિક id મળે છે; તમારે તેને ક્યારેય ટાઇપ કરવાની જરૂર નથી, પ્રિફિક્સ જ જાહેર નામ છે.

#### અનામત પ્રિફિક્સ

પ્રિફિક્સ બિલ્ટ-ઇન પ્રોવાઇડરનો id કે એલિયાસ હોઈ શકતું નથી (ઉદાહરણ તરીકે `openai`, `cf`), કે નિવૃત્ત (retired) પ્રોવાઇડરનો id પણ નહીં. મોડલ રિઝોલ્વર કસ્ટમ નોડ્સ પહેલાં બિલ્ટ-ઇન id અને એલિયાસ તપાસે છે, તેથી તેમાંથી કોઈ એક પ્રિફિક્સ વાપરતું નોડ ક્યારેય ટ્રાફિક મેળવી શકશે નહીં: `<prefix>/model` તેના બદલે બિલ્ટ-ઇન પ્રોવાઇડર પાસે જશે, અથવા તે પ્રોવાઇડર નિવૃત્ત થયો હોય તો fail closed થશે. આવા પ્રિફિક્સ સાથે નોડ બનાવવા કે સંપાદિત કરવાનું નીચેના મેસેજ સાથે નકારવામાં આવે છે:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

અલગ પ્રિફિક્સ પસંદ કરો (`mygw`, `acme-proxy`). જો કસ્ટમ નોડ પરની રિક્વેસ્ટ્સ એવી એરર સાથે નિષ્ફળ જાય જે બિલ્ટ-ઇન પ્રોવાઇડર કે તેના ક્રેડેન્શિયલ્સનું નામ લે છે, તો નોડનું પ્રિફિક્સ અનામત છે કે નહીં તે તપાસો: આ નિયમ અસ્તિત્વમાં આવ્યા પહેલાં સેવ થયેલા નોડ્સ હજુ સંગ્રહિત છે, પરંતુ તેમનું પ્રિફિક્સ બિલ્ટ-ઇન પ્રોવાઇડર તરફ રૂટ થાય છે. નોડ સંપાદિત કરો અને તેને નવું પ્રિફિક્સ આપો.

#### પ્રતિ-કનેક્શન ગેટવે વિકલ્પો

આ કીઝ કનેક્શનના `providerSpecificData` માં જાય છે (ઉદાહરણ તરીકે `PUT /api/providers/{id}` દ્વારા):

- `toolNameMaxLength` (પૂર્ણાંક, 1–1024) — OpenAI chat-ફોર્મેટ સુસંગત કનેક્શન્સ માટે જેમનું ગેટવે લાંબા ટૂલ નામો નકારે છે. લાંબા નામો ટૂંકા એલિયાસ તરીકે મોકલવામાં આવે છે અને રિસ્પોન્સમાં પુનઃસ્થાપિત થાય છે.
- `quotaEndpoint` — ગેટવેનું quota/credits એન્ડપોઇન્ટ, જે ડેશબોર્ડ quota સ્ટ્રિપ અને quota-આધારિત રૂટિંગ માટે વાંચવામાં આવે છે. OpenAI- અને Anthropic-સુસંગત બંને કનેક્શન્સ પર કામ કરે છે; સંપૂર્ણ સ્વરૂપ `open-sse/services/usage/openaiCompatible.ts` માં દસ્તાવેજીકૃત છે.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### OmniRoute પીઅર્સની ચેઇનિંગ

બીજું OmniRoute ગેટવે **Custom OpenAI-compatible** પ્રોવાઇડર તરીકે ઉમેરી શકાય છે. પીઅરનો `/v1` બેઝ URL અને તે પીઅર દ્વારા ઇશ્યૂ કરાયેલી સમર્પિત, ન્યૂનતમ-વિશેષાધિકાર ધરાવતી API કી વાપરો.

પરસ્પર કે મલ્ટિ-હોપ ચેઇન્સ માટે, દરેક ગેટવે પર opt-in લૂપ ગાર્ડ સક્રિય કરો:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

ફક્ત સ્પષ્ટપણે allowlist કરેલા પીઅર URL પર મોકલવામાં આવેલી રિક્વેસ્ટ્સને જ `X-OmniRoute-Peer-Trace` હેડર મળે છે. ગેટવે પુનરાવર્તિત instance ID અથવા ખતમ થયેલો hop બજેટ HTTP `508 Loop Detected` સાથે નકારે છે; સામાન્ય અપસ્ટ્રીમ પ્રોવાઇડર્સને કોઈ પીઅર મેટાડેટા મળતો નથી.

પીઅર ચેઇનિંગ એ ડેટાબેઝ રેપ્લિકેશન કે હોસ્ટ ફેલઓવર નથી. દરેક ગેટવે સ્વતંત્ર SQLite સ્ટેટ, કેશ, રેટ કાઉન્ટર અને સેશન્સ રાખે છે. active/passive કે active/active ઉપલબ્ધતા માટે health-check થયેલ રિવર્સ પ્રોક્સી કે ક્લાયંટ ફેલઓવર વાપરો, અને એક જ SQLite ડેટાબેઝને ક્યારેય અનેક ચાલતા OmniRoute ઇન્સ્ટન્સમાં માઉન્ટ કરશો નહીં.

### ડેડિકેટેડ પ્રોવાઇડર રૂટ્સ

મોડલ વેલિડેશન સાથે રિક્વેસ્ટ્સને સીધી ચોક્કસ પ્રોવાઇડર પાસે રૂટ કરો:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

પ્રોવાઇડર પ્રિફિક્સ ગેરહાજર હોય તો ઓટો-ઉમેરવામાં આવે છે. બંધબેસતા ન હોય તેવા મોડલ્સ `400` પરત આપે છે.

### નેટવર્ક પ્રોક્સી કન્ફિગરેશન

```bash
# Set global proxy
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# Per-provider proxy
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# Test proxy
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**પ્રાથમિકતા ક્રમ:** કી-વિશિષ્ટ → કોમ્બો-વિશિષ્ટ → પ્રોવાઇડર-વિશિષ્ટ → વૈશ્વિક → એન્વાયરન્મેન્ટ.

### મોડેલ કેટલોગ API

```bash
curl http://localhost:20128/api/models/catalog
```

પ્રકારો (`chat`, `embedding`, `image`) સાથે પ્રોવાઇડર મુજબ જૂથબદ્ધ મોડેલ્સ પરત કરે છે.

### ક્લાઉડ સિંક

- ઉપકરણો વચ્ચે પ્રોવાઇડર્સ, કોમ્બો અને સેટિંગ્સ સિંક કરો
- ટાઇમઆઉટ + ફેલ-ફાસ્ટ સાથે આપોઆપ બેકગ્રાઉન્ડ સિંક
- પ્રોડક્શનમાં સર્વર-સાઇડ `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` ને પ્રાથમિકતા આપો

### Cloudflare Quick Tunnel

- Docker અને અન્ય સેલ્ફ-હોસ્ટેડ ડિપ્લોયમેન્ટ્સ માટે **Dashboard → Endpoints** માં ઉપલબ્ધ
- તમારા વર્તમાન OpenAI-સુસંગત `/v1` એન્ડપોઇન્ટ પર ફોરવર્ડ કરતું અસ્થાયી `https://*.trycloudflare.com` URL બનાવે છે
- પ્રથમ વખત સક્ષમ કરવાથી જરૂર પડે ત્યારે જ `cloudflared` ઇન્સ્ટોલ થાય છે; પછીના રીસ્ટાર્ટ્સ એ જ મેનેજ્ડ બાઇનરીનો ફરીથી ઉપયોગ કરે છે
- OmniRoute અથવા કન્ટેઇનર રીસ્ટાર્ટ પછી Quick Tunnels આપોઆપ પુનઃસ્થાપિત થતાં નથી; જરૂર પડે ત્યારે ડેશબોર્ડમાંથી ફરી સક્ષમ કરો
- ટનલ URLs અલ્પકાલિક છે અને તમે ટનલ બંધ/શરૂ કરો ત્યારે દર વખતે બદલાય છે
- મર્યાદિત કન્ટેઇનરોમાં વધુ પડતી QUIC UDP બફર ચેતવણીઓ ટાળવા માટે મેનેજ્ડ Quick Tunnels ડિફૉલ્ટ રૂપે HTTP/2 ટ્રાન્સપોર્ટ વાપરે છે
- મેનેજ્ડ ટ્રાન્સપોર્ટ પસંદગીને ઓવરરાઇડ કરવી હોય તો `CLOUDFLARED_PROTOCOL=quic` અથવા `auto` સેટ કરો
- મેનેજ્ડ ડાઉનલોડના બદલે પ્રીઇન્સ્ટોલ્ડ `cloudflared` બાઇનરી વાપરવી હોય તો `CLOUDFLARED_BIN` સેટ કરો
- Cloudflare Quick Tunnel, Tailscale Funnel અને ngrok Tunnel પેનલ્સ **Settings → Appearance** માં બતાવી અથવા છુપાવી શકાય છે. પેનલ છુપાવવાથી ચાલી રહેલી ટનલ બંધ થતી નથી.

### LLM ગેટવે ઇન્ટેલિજન્સ (ફેઝ 9)

- **સિમેન્ટિક કેશ** — નોન-સ્ટ્રીમિંગ, temperature=0 રિસ્પોન્સને આપોઆપ કેશ કરે છે (`X-OmniRoute-No-Cache: true` સાથે બાયપાસ કરો)
- **રિક્વેસ્ટ આઇડેમ્પોટેન્સી** — `Idempotency-Key` અથવા `X-Request-Id` હેડર દ્વારા 5 સેકન્ડની અંદર ડુપ્લિકેટ રિક્વેસ્ટ્સ દૂર કરે છે
- **પ્રગતિ ટ્રેકિંગ** — `X-OmniRoute-Progress: true` હેડર દ્વારા ઓપ્ટ-ઇન SSE `event: progress` ઇવેન્ટ્સ

### રાઉટિંગ વ્યૂહરચનાઓ

**Dashboard → Settings → Routing** દ્વારા કન્ફિગર કરો. ડેશબોર્ડ છ સૌથી વધુ વપરાતી વ્યૂહરચનાઓ બતાવે છે; કોમ્બો અને ઓટો-રાઉટર આંતરિક રૂપે વધુ વિશાળ સેટને સપોર્ટ કરે છે.

**ડેશબોર્ડમાં દેખાતી વ્યૂહરચનાઓ (એકાઉન્ટ-સ્તર રાઉટિંગ):**

| વ્યૂહરચના                      | વર્ણન                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| **Fill First**                 | પ્રાથમિકતા ક્રમમાં એકાઉન્ટ્સ વાપરે છે — પ્રાથમિક એકાઉન્ટ અનુપલબ્ધ ન થાય ત્યાં સુધી બધી રિક્વેસ્ટ્સ સંભાળે છે |
| **Round Robin**                | કન્ફિગર કરી શકાય એવી સ્ટિકી લિમિટ સાથે બધા એકાઉન્ટ્સ વચ્ચે ફરે છે (ડિફૉલ્ટ: પ્રતિ એકાઉન્ટ 3 કૉલ્સ)           |
| **P2C (Power of Two Choices)** | 2 રેન્ડમ એકાઉન્ટ્સ પસંદ કરીને વધુ તંદુરસ્ત એકાઉન્ટ પર રાઉટ કરે છે — હેલ્થની જાણકારી સાથે લોડ સંતુલિત કરે છે  |
| **Random**                     | Fisher-Yates શફલ વાપરીને દરેક રિક્વેસ્ટ માટે રેન્ડમ એકાઉન્ટ પસંદ કરે છે                                      |
| **Least Used**                 | સૌથી જૂની `lastUsedAt` ટાઇમસ્ટેમ્પ ધરાવતા એકાઉન્ટ પર રાઉટ કરે છે, ટ્રાફિક સમાન રીતે વહેંચે છે                |
| **Cost Optimized**             | સૌથી ઓછી પ્રાથમિકતા કિંમત ધરાવતા એકાઉન્ટ પર રાઉટ કરે છે, સૌથી ઓછી કિંમતના પ્રોવાઇડર્સ માટે ઑપ્ટિમાઇઝ કરે છે  |

**અદ્યતન કોમ્બો અને ઓટો વ્યૂહરચનાઓ** (પ્રતિ કોમ્બો અથવા `auto/*` પ્રીફિક્સ દ્વારા કન્ફિગર કરી શકાય છે — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) જુઓ):

- `priority` — કડક ક્રમ, ક્યારેય રાઉન્ડ-રોબિન કરતું નથી
- `weighted` — પ્રતિ-મોડેલ વેઇટ્સ મુજબ પ્રમાણસર ટ્રાફિક વિભાજન
- `fill-first` — લિમિટ પહોંચે ત્યાં સુધી પ્રથમ મોડેલનો સંપૂર્ણ ઉપયોગ કરે છે
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` અને `cost-optimized`
- `auto` — બધા ઉમેદવારોમાં સ્કોર-આધારિત પસંદગી
- `lkgp` (Last Known Good Provider) — છેલ્લા સફળ પ્રોવાઇડર પર પિન કરે છે, પછી નિયમો પર ફોલબેક કરે છે
- `context-optimized` — સૌથી મોટી ફ્રી કોન્ટેક્સ્ટ વિન્ડો ધરાવતું મોડેલ પસંદ કરે છે
- `context-relay` — ફોલો-અપ ટર્ન્સ માટે લાંબા-કોન્ટેક્સ્ટ મોડેલ્સને ચેઇન કરે છે

#### એક્સટર્નલ સ્ટિકી સેશન હેડર

એક્સટર્નલ સેશન એફિનિટી માટે (ઉદાહરણ તરીકે, રિવર્સ પ્રોક્સી પાછળના Claude Code/Codex એજન્ટ્સ), મોકલો:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id` પણ સ્વીકારે છે અને અસરકારક સેશન કી `X-OmniRoute-Session-Id` માં પરત કરે છે.

જો તમે Nginx વાપરો છો અને અંડરસ્કોર-ફોર્મ હેડર્સ મોકલો છો, તો સક્ષમ કરો:

```nginx
underscores_in_headers on;
```

#### વાઇલ્ડકાર્ડ મોડેલ એલિયાસ

મોડેલના નામ રીમેપ કરવા માટે વાઇલ્ડકાર્ડ પેટર્ન બનાવો:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

વાઇલ્ડકાર્ડ `*` (કોઈપણ અક્ષરો) અને `?` (એકલ અક્ષર) ને સપોર્ટ કરે છે.

#### ફોલબેક ચેઇન્સ

બધી રિક્વેસ્ટ્સ પર લાગુ પડતી વૈશ્વિક ફોલબેક ચેઇન્સ વ્યાખ્યાયિત કરો:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### સામાન્ય પ્રોવાઇડર સંયોજનો અને રાઉટિંગ પેટર્ન

OmniRoute માં અનેક પ્રોવાઇડર્સને સંયોજિત કરવા અને તેમની વચ્ચે રાઉટિંગ કરવા માટેના ઉદાહરણ પેટર્ન અહીં છે:

#### 1. કોડિંગ એજન્ટ કોમ્બો: કોસ્ટ/સ્પીડ ફોલબેક સાથે હાઇ-એન્ડ રીઝનિંગ

કોડિંગ એજન્ટો (OpenCode, Claude Code, Cursor, Cline) માટે આદર્શ. શરૂઆતમાં ફ્રન્ટિયર રીઝનિંગ મોડેલ્સ પર રૂટ કરે છે, ક્વોટા સમાપ્ત થવા પર અથવા ભૂલો પર ઝડપી કોડિંગ મોડેલ્સ પર ફોલબેક કરે છે.

- **ડેશબોર્ડ**: કોમ્બોસ → નવું કોમ્બો → નામ: `agent-coding` → વ્યૂહરચના: `Priority`
- **મોડેલ્સ**:
  1. `claude/claude-sonnet-4-6` (પ્રાથમિક કોડિંગ એજન્ટ)
  2. `openai/gpt-4o` (ગૌણ ઉચ્ચ-ક્ષમતા ફોલબેક)
  3. `deepseek/deepseek-v4-flash` (ઉચ્ચ-કાર્યક્ષમતા, ખર્ચ-અસરકારક ફોલબેક)

```bash
# API દ્વારા ઉદાહરણ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

#### 2. ફ્રી-ટિયર ઓટો ફેલઓવર કોમ્બો

API ખર્ચ વિના અપટાઇમ મહત્તમ કરવા માટે અનેક ફ્રી-ટિયર અને કીલેસ પ્રોવાઇડરોને ચેઇન કરે છે.

- **વ્યૂહરચના**: `Least Used` અથવા `Round Robin` (ક્વોટા પર લોડ વહેંચે છે)
- **મોડેલ્સ**:
  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

```bash
# CLI દ્વારા ઉદાહરણ
omniroute combo create free-stack \
  --models "groq/llama-3.3-70b-versatile,gemini/gemini-2.5-flash,cerebras/gpt-oss-120b" \
  --strategy round-robin
```

#### 3. મલ્ટિમોડલ / વિઝન અને ટેક્સ્ટ પાઇપલાઇન

ઇમેજ સમજ અને કોડ જનરેશન ધરાવતા વર્કફ્લો માટે વિશિષ્ટ વિઝન મોડેલ્સને હાઇ-સ્પીડ ટેક્સ્ટ જનરેશન સાથે જોડવું.

- **પેટર્ન**: એક `Priority` કોમ્બો જે પહેલા વિઝન-સક્ષમ મોડેલ્સ અને છેલ્લે હાઇ-થ્રુપુટ ટેક્સ્ટ/કોડ મોડેલ સૂચિબદ્ધ કરે છે.
- **મોડેલ્સ**:
  1. `gemini/gemini-2.5-pro` (મજબૂત ઇમેજ/મલ્ટિમોડલ સમજ)
  2. `openai/gpt-4o` (સંતુલિત વિઝન અને ટૂલ ઉપયોગ)
  3. `deepseek/deepseek-v4-flash` (ટેક્સ્ટ/કોડ જનરેશન)

### રેઝિલિયન્સ અને સર્કિટ બ્રેકર્સ

**ડેશબોર્ડ → સેટિંગ્સ → રેઝિલિયન્સ** દ્વારા ગોઠવો.

OmniRoute પાંચ ઘટકો સાથે પ્રોવાઇડર-સ્તરીય રેઝિલિયન્સ અમલમાં મૂકે છે:

1. **રિક્વેસ્ટ ક્યૂ અને પેસિંગ** — સિસ્ટમ-સ્તરીય રિક્વેસ્ટ શેપિંગ:
   - **રિક્વેસ્ટ પ્રતિ મિનિટ (RPM)** — દરેક એકાઉન્ટ માટે પ્રતિ મિનિટ મહત્તમ રિક્વેસ્ટ
   - **રિક્વેસ્ટ વચ્ચે લઘુત્તમ સમય** — રિક્વેસ્ટ વચ્ચે મિલિસેકન્ડમાં લઘુત્તમ તફાવત
   - **મહત્તમ સમકાલીન રિક્વેસ્ટ** — દરેક એકાઉન્ટ માટે મહત્તમ એકસાથે ચાલતી રિક્વેસ્ટ

2. **કનેક્શન કૂલડાઉન** — રીટ્રાય-કરી શકાય તેવી નિષ્ફળતાઓ પછી એક કનેક્શન માટે પ્રતિ-ઓથ-પ્રકાર ગોઠવણી:
   - **બેઝ કૂલડાઉન** — રીટ્રાય-કરી શકાય તેવી અપસ્ટ્રીમ નિષ્ફળતાઓ માટે ડિફોલ્ટ કૂલડાઉન વિન્ડો
   - **અપસ્ટ્રીમ રીટ્રાય હિન્ટ્સનો ઉપયોગ** — આપવામાં આવે ત્યારે અધિકૃત `Retry-After` અથવા રીસેટ હિન્ટ્સનું પાલન કરે છે
   - **મહત્તમ બેકઓફ સ્ટેપ્સ** — વારંવાર નિષ્ફળતાઓ માટે મહત્તમ એક્સપોનેન્શિયલ બેકઓફ સ્તર

3. **પ્રોવાઇડર સર્કિટ બ્રેકર** — એન્ડ-ટુ-એન્ડ પ્રોવાઇડર નિષ્ફળતાઓને ટ્રૅક કરે છે, ગોઠવેલ ચેતવણી થ્રેશોલ્ડ પર પ્રોવાઇડરને ડિગ્રેડેડ તરીકે ચિહ્નિત કરે છે, અને ગોઠવેલ નિષ્ફળતા થ્રેશોલ્ડ પહોંચાય ત્યારે બ્રેકર ઓપન કરે છે:
   - **ડિગ્રેડેશન થ્રેશોલ્ડ** — `DEGRADED` માં પ્રવેશતા પહેલા ક્રમિક પ્રોવાઇડર નિષ્ફળતાઓ
   - **ફેલ્યર થ્રેશોલ્ડ** — `OPEN` માં પ્રવેશતા પહેલા ક્રમિક પ્રોવાઇડર નિષ્ફળતાઓ
   - **રીસેટ ટાઇમઆઉટ** — પ્રોવાઇડરને ફરીથી ટેસ્ટ કરતા પહેલાની સમય વિન્ડો
   - **CLOSED** (તંદુરસ્ત) — રિક્વેસ્ટ સામાન્ય રીતે વહે છે
   - **DEGRADED** — વધેલી નિષ્ફળતાઓ ટ્રૅક થાય છે ત્યારે પણ રિક્વેસ્ટ વહેતી રહે છે
   - **OPEN** — વારંવાર નિષ્ફળતાઓ પછી પ્રોવાઇડર અસ્થાયી રીતે બ્લોક થાય છે
   - **HALF_OPEN** — પ્રોવાઇડર પુનઃપ્રાપ્ત થયો છે કે કેમ તે તપાસવું

   કનેક્શન-સ્કોપ્ડ `429` રેટ લિમિટ્સ **કનેક્શન કૂલડાઉન** માં રહે છે અને પ્રોવાઇડર બ્રેકર તરફ ગણાતી નથી.

   પ્રોવાઇડર બ્રેકર રનટાઇમ સ્થિતિ ફક્ત **ડેશબોર્ડ → હેલ્થ** પર બતાવવામાં આવે છે.

4. **કૂલડાઉન માટે રાહ જુઓ** — જો દરેક ઉમેદવાર કનેક્શન પહેલેથી કૂલિંગ ડાઉનમાં હોય, તો OmniRoute સૌથી વહેલા કૂલડાઉનની રાહ જોઈ શકે છે અને તે જ ક્લાયન્ટ રિક્વેસ્ટનો આપોઆપ ફરીથી પ્રયાસ કરી શકે છે.

5. **રેટ લિમિટ ઓટો-ડિટેક્શન** — જ્યારે અપસ્ટ્રીમ પ્રોવાઇડર સ્પષ્ટ રાહ જોવાની વિન્ડો પાછી આપે છે, ત્યારે સેટિંગ સક્ષમ હોય ત્યારે તે હિન્ટ્સ સ્થાનિક કનેક્શન કૂલડાઉનને ઓવરરાઇડ કરે છે.

**પ્રો ટિપ:** આઉટેજ પછી લાઇવ પ્રોવાઇડર બ્રેકર્સ ચકાસવા અને રીસેટ કરવા માટે **હેલ્થ** પેજનો ઉપયોગ કરો. રેઝિલિયન્સ પેજ ફક્ત ગોઠવણી બદલે છે.

### ડેટાબેઝ એક્સપોર્ટ / ઇમ્પોર્ટ

**ડેશબોર્ડ → સેટિંગ્સ → સિસ્ટમ અને સ્ટોરેજ** માં ડેટાબેઝ બેકઅપ મેનેજ કરો.

| ક્રિયા                           | વર્ણન                                                                                                                                              |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ડેટાબેઝ એક્સપોર્ટ કરો**        | વર્તમાન SQLite ડેટાબેઝને `.sqlite` ફાઇલ તરીકે ડાઉનલોડ કરે છે                                                                                       |
| **બધું એક્સપોર્ટ કરો (.tar.gz)** | સંપૂર્ણ બેકઅપ આર્કાઇવ ડાઉનલોડ કરે છે જેમાં સમાવેશ થાય છે: ડેટાબેઝ, સેટિંગ્સ, કોમ્બોસ, પ્રોવાઇડર કનેક્શન (કોઈ ક્રેડેન્શિયલ્સ નહીં), API કી મેટાડેટા |
| **ડેટાબેઝ ઇમ્પોર્ટ કરો**         | વર્તમાન ડેટાબેઝ બદલવા માટે `.sqlite` ફાઇલ અપલોડ કરો. `DISABLE_SQLITE_AUTO_BACKUP=true` ન હોય તો પ્રી-ઇમ્પોર્ટ બેકઅપ આપોઆપ બનાવવામાં આવે છે         |

```bash
# API: ડેટાબેઝ એક્સપોર્ટ કરો
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: બધું એક્સપોર્ટ કરો (સંપૂર્ણ આર્કાઇવ)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ડેટાબેઝ ઇમ્પોર્ટ કરો
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ઇમ્પોર્ટ વેલિડેશન:** ઇમ્પોર્ટ કરેલી ફાઇલની અખંડિતતા (SQLite pragma ચેક), જરૂરી ટેબલ (`provider_connections`, `provider_nodes`, `combos`, `api_keys`), અને કદ (મહત્તમ 100MB) માટે ચકાસણી કરવામાં આવે છે.

**ઉપયોગ કેસ:**

- મશીનો વચ્ચે OmniRoute માઇગ્રેટ કરો
- ડિઝાસ્ટર રિકવરી માટે બહારના બેકઅપ બનાવો
- ટીમ સભ્યો વચ્ચે ગોઠવણીઓ શેર કરો (બધું એક્સપોર્ટ કરો → આર્કાઇવ શેર કરો)

### સેટિંગ્સ ડેશબોર્ડ

સરળ નેવિગેશન માટે સેટિંગ્સ પેજ **7 ટેબ** માં વહેંચાયેલું છે:

| ટેબ            | સામગ્રી                                                                                                                                                         |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **સામાન્ય**    | સિસ્ટમ સ્ટોરેજ સાધનો, ડિફોલ્ટ વર્તન, એન્ડપોઇન્ટ ટનલ દૃશ્યતા                                                                                                     |
| **દેખાવ**      | થીમ નિયંત્રણો (લાઇટ/ડાર્ક/સિસ્ટમ), સાઇડબાર દૃશ્યતા, Cloudflare/Tailscale/ngrok ટનલ કાર્ડ્સ માટે પેનલ ટૉગલ્સ                                                     |
| **AI**         | થિંકિંગ બજેટ (પાસથ્રુ / ઓટો-સ્ટ્રિપ / કસ્ટમ / એડેપ્ટિવ — જુઓ [THINKING_BUDGET.md](./THINKING_BUDGET.md)), ગ્લોબલ સિસ્ટમ પ્રોમ્પ્ટ, પ્રોમ્પ્ટ કેશ આંકડા          |
| **સુરક્ષા**    | લોગિન/પાસવર્ડ સેટિંગ્સ, IP ઍક્સેસ નિયંત્રણ, `/models` માટે API ઓથ, પ્રોવાઇડર બ્લોકિંગ, પ્રોમ્પ્ટ-ઇન્જેક્શન ગાર્ડ                                                |
| **રાઉટિંગ**    | ગ્લોબલ રાઉટિંગ સ્ટ્રેટેજી (ફિલ ફર્સ્ટ / રાઉન્ડ રોબિન / P2C / રેન્ડમ / લીસ્ટ યુઝ્ડ / કોસ્ટ ઓપ્ટિમાઇઝ્ડ), વાઇલ્ડકાર્ડ મોડલ એલિયાસ, ફોલબેક ચેન્સ, કોમ્બો ડિફોલ્ટ્સ |
| **રેઝિલિયન્સ** | રિક્વેસ્ટ ક્યૂ, કનેક્શન કૂલડાઉન, પ્રોવાઇડર બ્રેકર કોન્ફિગ, અને વેટ-ફોર-કૂલડાઉન વર્તન                                                                            |
| **એડવાન્સ્ડ**  | ગ્લોબલ પ્રોક્સી કોન્ફિગરેશન (HTTP/SOCKS5), પ્રતિ-પ્રોવાઇડર પ્રોક્સી ઓવરરાઇડ્સ                                                                                   |

સામાન્ય ટેબ હવે ફક્ત-વાંચવાયોગ્ય લોગિંગ અને કેશ નોંધોનું પુનરાવર્તન કરતું નથી. ડેટાબેઝ રિટેન્શન અને
ઓપ્ટિમાઇઝેશન સેટિંગ્સ `/api/settings/database` દ્વારા સાચવવામાં આવે છે; મેન્યુઅલ કેશ ક્લિયરિંગ માટે
`DELETE /api/cache` નો ઉપયોગ થાય છે. રિક્વેસ્ટ અને પ્રોક્સી લોગ રો કેપ્સ
`CALL_LOGS_TABLE_MAX_ROWS` અને `PROXY_LOGS_TABLE_MAX_ROWS` દ્વારા નિયંત્રિત થાય છે.

### ખર્ચ અને બજેટ મેનેજમેન્ટ

**ડેશબોર્ડ → કોસ્ટ્સ** દ્વારા ઍક્સેસ કરો.

| ટેબ           | હेतુ                                                                                            |
| ------------- | ----------------------------------------------------------------------------------------------- |
| **બજેટ**      | દૈનિક/સાપ્તાહિક/માસિક બજેટ અને રીયલ-ટાઇમ ટ્રેકિંગ સાથે દરેક API કી માટે ખર્ચ મર્યાદા સેટ કરો    |
| **પ્રાઇસિંગ** | મોડલ પ્રાઇસિંગ એન્ટ્રીઓ જુઓ અને સંપાદિત કરો — દરેક પ્રોવાઇડર માટે 1K ઇનપુટ/આઉટપુટ ટોકન દીઠ ખર્ચ |

```bash
# API: બજેટ સેટ કરો
curl -X POST http://localhost:20128/api/usage/budget \
  -H "Content-Type: application/json" \
  -d '{"keyId": "key-123", "limit": 50.00, "period": "monthly"}'

# API: વર્તમાન બજેટ સ્થિતિ મેળવો
curl http://localhost:20128/api/usage/budget
```

**ખર્ચ ટ્રેકિંગ:** દરેક રિક્વેસ્ટ ટોકન વપરાશ લોગ કરે છે અને પ્રાઇસિંગ ટેબલનો ઉપયોગ કરીને ખર્ચની ગણતરી કરે છે. પ્રોવાઇડર, મોડલ અને API કી પ્રમાણે વિગતવાર breakdowns **ડેશબોર્ડ → યુસેજ** માં જુઓ.

### ઓડિયો ટ્રાન્સક્રિપ્શન

OmniRoute OpenAI-સુસંગત એન્ડપોઇન્ટ દ્વારા ઓડિયો ટ્રાન્સક્રિપ્શનને સપોર્ટ કરે છે:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# curl સાથે ઉદાહરણ
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

`deepgram/nova-3` એ નેટિવ Deepgram રાઉટ છે અને તેને Deepgram API કીની જરૂર છે.
જો ફક્ત OpenRouter કોન્ફિગર કરેલું હોય, તો `openrouter/deepgram/nova-3` વાપરો.

**સ્પીચ-ટુ-ટેક્સ્ટ (ટ્રાન્સક્રિપ્શન)** પ્રોવાઇડર્સ:

- `openai/` (whisper-સુસંગત)
- `groq/` (Groq Whisper Turbo)
- `deepgram/` (Nova ફેમિલી)
- `assemblyai/`
- `nvidia/` (Parakeet, Canary)
- `huggingface/` (whisper વેરિઅન્ટ્સ)
- `qwen/`

**ટેક્સ્ટ-ટુ-સ્પીચ (`POST /v1/audio/speech`)** પ્રોવાઇડર્સ:

- `openai/` (tts-1, tts-1-hd)
- `hyperbolic/`
- `deepgram/` (Aura)
- `nvidia/` (Magpie TTS)
- `elevenlabs/`
- `huggingface/`
- `inworld/`
- `cartesia/`
- `playht/`
- `kie/`
- `aws-polly/`
- `xiaomi-mimo/`
- `coqui/`, `tortoise/`
- `qwen/`

ટ્રાન્સક્રિપ્શન માટે સપોર્ટેડ ઓડિયો ફોર્મેટ્સ: `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`. TTS આઉટપુટ ફોર્મેટ્સ પ્રોવાઇડર પર આધાર રાખે છે (mp3, wav, opus, pcm, mulaw).

### કોમ્બો બેલેન્સિંગ સ્ટ્રેટેજીઝ

**ડેશબોર્ડ → કોમ્બોઝ → બનાવો/સંપાદિત કરો → સ્ટ્રેટેજી** માં પ્રતિ-કોમ્બો બેલેન્સિંગ કોન્ફિગર કરો.

| સ્ટ્રેટેજી            | વર્ણન                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------ |
| **રાઉન્ડ-રોબિન**      | મોડલ્સ વચ્ચે ક્રમવાર ફેરવે છે                                                              |
| **પ્રાયોરિટી**        | હંમેશા પ્રથમ મોડલ અજમાવે છે; ફક્ત ભૂલ પર જ ફોલબેક કરે છે                                   |
| **રેન્ડમ**            | દરેક રિક્વેસ્ટ માટે કોમ્બોમાંથી રેન્ડમ મોડલ પસંદ કરે છે                                    |
| **વેઇટેડ**            | દરેક મોડલને સોંપેલા વેઇટના આધારે પ્રમાણસર રાઉટ કરે છે                                      |
| **લીસ્ટ-યુઝ્ડ**       | સૌથી ઓછી તાજેતરની રિક્વેસ્ટ્સ ધરાવતા મોડલ પર રાઉટ કરે છે (કોમ્બો મેટ્રિક્સનો ઉપયોગ કરે છે) |
| **કોસ્ટ-ઓપ્ટિમાઇઝ્ડ** | સૌથી સસ્તું ઉપલબ્ધ મોડલ પર રાઉટ કરે છે (પ્રાઇસિંગ ટેબલનો ઉપયોગ કરે છે)                     |

ગ્લોબલ કોમ્બો ડિફોલ્ટ્સ **ડેશબોર્ડ → સેટિંગ્સ → રાઉટિંગ → કોમ્બો ડિફોલ્ટ્સ** માં સેટ કરી શકાય છે.
કોમ્બો ટાર્ગેટ ટાઇમઆઉટ્સ ડિફોલ્ટ રૂપે વર્તમાન રિક્વેસ્ટ ટાઇમઆઉટ ઇનહેરિટ કરે છે. જ્યારે ટૂંકી
પ્રતિ-ટાર્ગેટ મર્યાદાએ ઝડપી ફોલબેક ટ્રિગર કરવું જોઈએ ત્યારે જ કોમ્બો ડિફોલ્ટ્સ અથવા વ્યક્તિગત કોમ્બો
પર **ટાર્ગેટ ટાઇમઆઉટ (સેકન્ડ)** નો ઉપયોગ કરો.

ઝીરો-લેટન્સી કોમ્બો ઓપ્ટિમાઇઝેશન્સ ઓપ્ટ-ઇન છે. આ લેટન્સી ફીચર્સને ફોલબેક ટાર્ગેટ્સ સાથે રેસ કરવાથી,
TTFT હિસ્ટરીના આધારે ટાર્ગેટ્સ સ્કિપ કરવાથી, અથવા ફોલબેક રિક્વેસ્ટ્સ કોમ્પ્રેસ કરવાથી રોકવા માટે
**ઝીરો-લેટન્સી ઓપ્ટિમાઇઝેશન્સ**ને ડિસેબલ જ રાખો; તેને એનેબલ કરવાથી કોન્ફિગર કરેલી હેજિંગ, પ્રિડિક્ટિવ
TTFT સ્કિપ્સ અને પ્રોઍક્ટિવ ફોલબેક કોમ્પ્રેશનને ઓછી ટેલ લેટન્સી માટે રાઉટિંગ/રિક્વેસ્ટ ફિડેલિટીનો
સોદો કરવાની મંજૂરી મળે છે.

જ્યારે અપસ્ટ્રીમ પ્રોવાઇડર્સને સખત `max_tokens` / `maxOutputTokens` મર્યાદાઓની જરૂર હોય ત્યારે **રીઝનિંગ ટોકન બફર** અક્ષમ કરો. સક્ષમ કરેલ હોય ત્યારે, કોમ્બો રૂટિંગ ફક્ત જાણીતા આઉટપુટ કેપ ધરાવતા મોડલો માટે જ રીઝનિંગ-મોડલ હેડરૂમ ઉમેરે છે અને જ્યારે સુરક્ષિત બફર્ડ મૂલ્ય તે કેપને ઓળંગી જાય ત્યારે ક્લાયન્ટ ટોકન મર્યાદામાં ફેરફાર કર્યા વગર જેમ છે તેમ જ રાખે છે. જો ક્લાયન્ટ મર્યાદા પહેલેથી જ જાણીતા કેપથી ઉપર હોય, તો OmniRoute અપસ્ટ્રીમ વિનંતી મોકલતા પહેલાં તેને તે કેપ સુધી ઘટાડે છે.

## 🤖 ઑટો-રાઉટિંગ (શૂન્ય-કન્ફિગ)

OmniRoute એક **સ્કોર-આધારિત ઑટો-રાઉટર** સાથે આવે છે, જે દરેક કનેક્ટેડ પ્રદાતા પરની પ્રત્યેક વિનંતી માટે શ્રેષ્ઠ મોડલ પસંદ કરે છે — જાળવવા માટે કોઈ કોમ્બો નથી. ફક્ત `auto/*` પ્રીફિક્સમાંથી કોઈ એક સાથે વિનંતી મોકલો અને OmniRoute તરત જ વર્ચ્યુઅલ કોમ્બો તૈયાર કરશે, જેમાં વિલંબ, ખર્ચ, સફળતા દર, સંદર્ભ સુસંગતતા, કાર્ય માટે મોડલની યોગ્યતા, તાજેતરની નિષ્ફળતાઓ, ક્વોટા અને સર્કિટ-બ્રેકરની સ્થિતિના આધારે ઉમેદવારોને સ્કોર કરવામાં આવશે.

| પ્રીફિક્સ      | શેના માટે ઑપ્ટિમાઇઝ કરે છે                                                                |
| -------------- | ----------------------------------------------------------------------------------------- |
| `auto`         | સંતુલિત ડિફૉલ્ટ (વિલંબ × ખર્ચ × સફળતા દર)                                                 |
| `auto/coding`  | કોડિંગ કાર્યો: Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek કોડર્સને પ્રાધાન્ય આપે છે   |
| `auto/cheap`   | સૌથી ઓછો $/token, વધુ વિલંબ સ્વીકારે છે                                                   |
| `auto/fast`    | સૌથી ઓછો વિલંબ, ખર્ચને અવગણે છે                                                           |
| `auto/offline` | ફક્ત સ્થાનિક પ્રદાતાઓ (Ollama, vLLM, llama.cpp) — એર-ગૅપ્ડ સેટઅપ્સ માટે ઉપયોગી            |
| `auto/smart`   | રિઝનિંગ ગુણવત્તાને પ્રથમ પ્રાધાન્ય (Opus, GPT-5 xhigh, R1, GLM 5.1 રિઝનિંગ)               |
| `auto/lkgp`    | "છેલ્લો જાણીતો સારો પ્રદાતા" — છેલ્લા સફળ પ્રદાતા સાથે પિન કરે છે, પછી નિયમોનો આશરો લે છે |

ઉદાહરણ:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

ઑટો-રાઉટરનું સંપૂર્ણ વર્ણન [AUTO-COMBO.md](../routing/AUTO-COMBO.md)માં છે — જેમાં સ્કોરિંગ વેઇટ્સને કેવી રીતે ટ્યુન કરવા, પ્રદાતાઓને બ્લૅકલિસ્ટ કરવા અને **Dashboard → Auto Combo**માં રાઉટિંગ નિર્ણયોનું નિરીક્ષણ કરવા જેવી બાબતોનો સમાવેશ થાય છે.

## 🔌 MCP અને A2A એકીકરણ

OmniRoute એક **MCP સર્વર** (Model Context Protocol) અને એક **A2A સર્વર** (Agent-to-Agent JSON-RPC 2.0) બંને છે. કોઈપણ MCP-સુસંગત IDE અથવા એજન્ટ હોસ્ટ OmniRoute ટૂલ્સને સીધા કૉલ કરી શકે છે — કોઈ વધારાના રૅપરની જરૂર નથી.

### MCP ટ્રાન્સપોર્ટ્સ

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **સ્ટ્રીમ કરી શકાય તેવું HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (stdio પસંદ કરતા IDE પ્લગઇન્સ માટે)

### Claude Desktopને કનેક્ટ કરો

`~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) અથવા Windows/Linux પર તેની સમકક્ષ ફાઇલમાં ફેરફાર કરો:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCPને કનેક્ટ કરો

SSE URL `http://localhost:20128/api/mcp/sse` અને **Dashboard → API Keys**માં જનરેટ કરેલી Bearer API કીનો ઉપયોગ કરો.

### સ્કોપ્સ

MCP હાલમાં 32 નામિત સ્કોપ્સ વ્યાખ્યાયિત કરે છે. દરેક Bearer કીને ચોક્કસ સ્કોપ્સ સુધી મર્યાદિત કરી શકાય છે — અધિકૃત સ્કોપ અને ટૂલ ઇન્વેન્ટરી માટે [MCP-SERVER.md](../frameworks/MCP-SERVER.md) અને JSON-RPC સ્કીમા માટે [A2A-SERVER.md](../frameworks/A2A-SERVER.md) જુઓ.

## 🧠 કૌશલ્ય સિસ્ટમ

OmniRoute એક વિસ્તૃત કરી શકાય તેવું **કૌશલ્ય ફ્રેમવર્ક** (`src/lib/skills/`) પ્રદાન કરે છે, જેથી એજન્ટો અને A2A એન્ડપોઇન્ટ ડોમેન-વિશિષ્ટ રૂટિન્સ (દા.ત. `code-review`, `summarize`, `extract-facts`, `web-research`) ચલાવી શકે.

- **માર્કેટપ્લેસ UI** — **Dashboard → Skills**માંથી કૌશલ્યો બ્રાઉઝ અને ઇન્સ્ટૉલ કરો
- **પ્રતિ-કી સ્કોપ્સ** — કઈ API કીઓ કયા કૌશલ્યોને આમંત્રિત કરી શકે તે નિયંત્રિત કરો
- **કસ્ટમ કૌશલ્યો** — `src/lib/a2a/skills/`માં TypeScript ફાઇલ મૂકો, તેને રજિસ્ટર કરો અને તે તરત જ A2A મારફતે આમંત્રિત કરી શકાય તેવી બની જાય છે

સંપૂર્ણ સંદર્ભ: [SKILLS.md](../frameworks/SKILLS.md).

## 💾 મેમરી સિસ્ટમ

OmniRoute હાઇબ્રિડ રિટ્રીવલ સાથે **લાંબા ગાળાની સંવાદાત્મક મેમરી** જાળવી રાખે છે:

- અગાઉના સંવાદોમાં કીવર્ડ શોધ માટે **SQLite FTS5**
- અર્થ-આધારિત પુનઃસ્મરણ માટે **Qdrant vector store** (વૈકલ્પિક)
- **સ્વચાલિત હકીકત નિષ્કર્ષણ** — દરેક સત્ર પછી એન્ટિટીઝ, પસંદગીઓ અને નિર્ણયોનો સારાંશ બનાવીને `memory_facts` ટેબલમાં સંગ્રહિત કરવામાં આવે છે
- મેમરીઝને દરેક API કી અને દરેક સત્ર દીઠ અલગ સ્કોપ કરવામાં આવે છે

**Dashboard → Memory**માં મેમરીઝનું સંચાલન કરો (શોધો, સંપાદિત કરો, નિકાસ કરો, સાફ કરો). HTTP ઇન્ટરફેસ (`/api/memory/*`) એજન્ટોને પ્રોગ્રામેટિક રીતે હકીકતો પુશ કરવા અને ક્વેરી કરવાની સુવિધા આપે છે — [MEMORY.md](../frameworks/MEMORY.md) જુઓ.

## 🔔 વેબહુક્સ

રિયલ-ટાઇમ મોનિટરિંગ અને ઓટોમેશન માટે OmniRoute ઇવેન્ટ્સને સબ્સ્ક્રાઇબ કરો.

- લક્ષ્ય URL અને HMAC સાઇનિંગ સિક્રેટ સાથે **Dashboard → Webhooks**માં વેબહુક બનાવો
- ઉપલબ્ધ ઇવેન્ટ્સ: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- ચકાસણી માટે દરેક પેલોડમાં `X-OmniRoute-Signature` (HMAC-SHA256) સામેલ હોય છે
- પુનઃપ્રયાસ: એક્સપોનેન્શિયલ બૅકઑફ સાથે 3 પ્રયાસો, ત્યારબાદ ડેડ-લેટર કતાર

સંપૂર્ણ સ્કીમા [WEBHOOKS.md](../frameworks/WEBHOOKS.md)માં છે.

## 🛠️ પ્રોગ્રામેટિક સંચાલન

તમે **`manage` સ્કોપ ધરાવતી Bearer કી**નો ઉપયોગ કરીને HTTP મારફતે દરેક OmniRoute સંસાધન (પ્રોવાઇડર્સ, કોમ્બોઝ, કીઓ, સેટિંગ્સ)નું સંચાલન કરી શકો છો.

**Dashboard → API Keys → New Key → Scope: manage**માં કી જનરેટ કરો, ત્યારબાદ:

```bash
# પ્રોવાઇડર્સની યાદી મેળવો
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# પ્રોવાઇડર કનેક્શન ઉમેરો
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# કોમ્બો બનાવો
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API કીઓની યાદી મેળવો/બનાવો
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

સંપૂર્ણ એન્ડપોઇન્ટ કૅટલૉગ અને વિનંતી/પ્રતિસાદ સ્કીમા માટે [API_REFERENCE.md](../reference/API_REFERENCE.md) જુઓ.

## 💻 આંતરિક CLI

OmniRoute સેટઅપ, નિદાન અને રનટાઇમ નિયંત્રણ માટે આંતરિક CLI (`omniroute …`) સાથે આવે છે. આ **ડૅશબોર્ડમાંના "CLI Tools" પૃષ્ઠથી અલગ છે**, જે તૃતીય-પક્ષ CLI (Claude Code, Cursor, Codex, Cline, …) ને ગોઠવે છે જેથી તેઓ OmniRoute સાથે સંચાર કરી શકે.

```bash
omniroute setup                    # ઇન્ટરેક્ટિવ વિઝાર્ડ (પાસવર્ડ, પ્રોવાઇડર્સ, કોમ્બોઝ)
omniroute setup --non-interactive  # CI માટે અનુકૂળ
omniroute doctor                   # સ્વાસ્થ્ય નિદાન (ડેટા ડિરેક્ટરી, DB, પ્રોવાઇડર્સ, પોર્ટ્સ)
omniroute providers available      # સપોર્ટેડ પ્રોવાઇડર્સની યાદી
omniroute providers list           # ગોઠવેલા કનેક્શન્સની યાદી
omniroute providers test <id>      # પ્રોવાઇડર કનેક્શનનું લાઇવ પરીક્ષણ
omniroute combos list              # કોમ્બોઝની યાદી
omniroute combos switch <name>     # ડિફૉલ્ટ કોમ્બો સેટ કરો
omniroute models                   # ઉપલબ્ધ મોડલ્સની યાદી (--json, --search)
omniroute keys add | list | remove # ટર્મિનલમાંથી API કીઝનું સંચાલન કરો
omniroute backup                   # કન્ફિગ + DBનો સ્નૅપશૉટ
omniroute restore [<timestamp>]    # સ્નૅપશૉટમાંથી પુનઃસ્થાપિત કરો
omniroute health                   # વિગતવાર સ્વાસ્થ્ય (બ્રેકર્સ, કૅશ, મેમરી)
omniroute quota                    # પ્રોવાઇડર ક્વોટાનો વપરાશ
omniroute mcp status               # MCP સર્વરની સ્થિતિ
omniroute a2a status               # A2A સર્વરની સ્થિતિ
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok ટનલ્સ
omniroute reset-password           # એડમિન પાસવર્ડ રીસેટ કરો
omniroute --mcp                    # stdio પર MCP સર્વર શરૂ કરો
omniroute --port 3000              # કસ્ટમ પોર્ટ પર સર્વર શરૂ કરો
```

સૂચન: અસ્વસ્થ પ્રોવાઇડર કનેક્શન્સ વિશે ચેતવણી મેળવવા માટે `omniroute doctor --json` ને તમારા મોનિટરિંગ ટૂલ સાથે જોડો.

## 🖥️ ડેસ્કટૉપ એપ્લિકેશન (Electron)

OmniRoute Windows, macOS અને Linux માટે મૂળ ડેસ્કટૉપ એપ્લિકેશન તરીકે ઉપલબ્ધ છે.

### ઇન્સ્ટોલેશન

```bash
# electron ડિરેક્ટરીમાંથી:
cd electron
npm install

# ડેવલપમેન્ટ મોડ (ચાલતા Next.js ડેવ સર્વર સાથે કનેક્ટ કરો):
npm run dev

# પ્રોડક્શન મોડ (સ્ટૅન્ડઅલોન બિલ્ડનો ઉપયોગ કરે છે):
npm start
```

### ઇન્સ્ટોલર્સ બનાવવા

```bash
cd electron
npm run build          # વર્તમાન પ્લેટફોર્મ
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg યુનિવર્સલ)
npm run build:linux    # Linux (.AppImage)
```

આઉટપુટ → `electron/dist-electron/`
