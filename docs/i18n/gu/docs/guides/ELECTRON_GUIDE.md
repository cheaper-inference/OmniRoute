> **સત્યનો સ્ત્રોત:** `electron/` વર્કસ્પેસ** છેલ્લે અપડેટ કર્યું:** 2026-06-28 — v3.8.40

OmniRoute એક ક્રોસ-પ્લેટફોર્મ ડેસ્કટોપ એપ (Windows / macOS / Linux) પર બિલ્ટ**Electron 41** +** ઇલેક્ટ્રોન-બિલ્ડર 26.10** . ડેસ્કટોપ એપ બાળ પ્રક્રિયા તરીકે Next.js સ્ટેન્ડઅલોન સર્વરને બનાવે છે, તેના પર `BrowserWindow` નિર્દેશ કરે છે અને સિસ્ટમ ટ્રે, ઓટો-અપડેટર, IPC બ્રિજ અને ઝીરો-કોન્ફિગ સિક્રેટ બુટસ્ટ્રેપ ઉમેરે છે.

## આર્કિટેક્ચર

```
┌──────────────────────────────────────────────┐
│ Electron main process (electron/main.js)     │
│ ├─ Single-instance lock                       │
│ ├─ Child process: Next.js standalone server  │
│ │   (spawned with Electron's Node runtime)   │
│ ├─ BrowserWindow → http://localhost:PORT     │
│ ├─ System tray + context menu                │
│ ├─ Auto-update via electron-updater          │
│ ├─ Content Security Policy (session headers) │
│ └─ Secret bootstrap (JWT / API_KEY_SECRET)   │
└──────────────────────────────────────────────┘
            ↕ IPC bridge (electron/preload.js)
┌──────────────────────────────────────────────┐
│ Renderer (Next.js dashboard)                  │
│   window.electronAPI.* (contextIsolation)     │
└──────────────────────────────────────────────┘
```

| `npm run electron:dev`            | `npm run dev` શરૂ થાય છે + `localhost:20128` + Electron લોન્ચ થવાની રાહ જુએ છે     |
| `npm run electron:build`          | Next.js બનાવે છે પછી વર્તમાન OS માટે `electron-builder` ચલાવે છે                   |
| `npm run electron:build:win`      | Windows NSIS ઇન્સ્ટોલર + પોર્ટેબલ (x64) બનાવે છે                                   |
| `npm run electron:build:mac`      | macOS DMG બનાવે છે (Intel + Apple Silicon)                                         |

| `npm run electron:smoke:packaged` | પેકેજ્ડ બાઈનરી લોન્ચ કરે છે અને HTTP 200 માટે `/login` તપાસ કરે છે, પછી બંધ થાય છે |

`electron/` વર્કસ્પેસ પણ છતી કરે છે:

- `npm run prepare:bundle` — `scripts/build/prepare-electron-standalone.mjs` ચલાવે છે
- `npm run build:mac-x64` / `build:mac-arm64` — સિંગલ-કમાન macOS બિલ્ડ્સ
- સ્થાનિક પરીક્ષણ માટે`npm run pack` — ડિરેક્ટરી-માત્ર બિલ્ડ (કોઈ ઇન્સ્ટોલર નથી)

## વૈકલ્પિક રનટાઇમ પેક

ડેસ્કટોપ બિલ્ડ્સ તેમના ઇન્સ્ટોલર્સની સાથે વૈકલ્પિક રનટાઇમ આર્કાઇવ્સ પ્રકાશિત કરી શકે છે. ઇન્સ્ટોલ કરેલ સર્વર પેલોડમાં `optional-packs.index.json` ( Windows અને Linux પર `resources/app` હેઠળ) છે. `browser-runtime` એન્ટ્રી માટે, `packs[].tarball` વાંચો અને ડાઉનલોડ કરો** તે જ પ્રકાશનમાંથી ચોક્કસ ફાઇલનામ** . આર્કાઇવ નામોમાં SHA-256 ડાયજેસ્ટનો સમાવેશ થાય છે; વિવિધ બિલ્ડ્સને વિવિધ આર્કાઇવ્સની જરૂર પડી શકે છે. ડાઉનલોડ કરેલ ફાઇલનામને યથાવત રાખો.

ઇન્સ્ટોલ કરેલ એપ્લિકેશનની અનુક્રમણિકા અને પસંદ કરેલ આર્કાઇવને એક નિર્દેશિકામાં કૉપિ કરો, પછી સમાન પ્રકાશનમાંથી CLI ઉપયોગ કરો:

```bash
omniroute packs list --source /path/to/packs
omniroute packs install browser-runtime --source /path/to/packs
```

`packs list` સ્થાપન અને ચકાસણી સ્થિતિ દર્શાવે છે, આર્કાઇવ ફાઇલનામ નહીં. બંડલ કરેલ ઇન્ડેક્સ આર્કાઇવ પસંદ કરે છે. સ્થાપન નિષ્કર્ષણ પહેલાં તેના આર્કાઇવ ચેકસમ અને ઇન્સ્ટોલ કરેલ પેકને બદલતા પહેલા તેના પેકેજ ચેકસમની ચકાસણી કરે છે. તે સ્થાનિક ફાઇલો વાંચે છે; તે ગુમ થયેલ આર્કાઇવ્સ ડાઉનલોડ કરતું નથી. ઇન્સ્ટોલેશન પછી એપ્લિકેશનને ફરીથી પ્રારંભ કરો. જો રિલીઝમાં કોઈ મેળ ખાતી સંપત્તિ નથી, તો તે રિલીઝની સંપત્તિઓ દ્વારા વૈકલ્પિક પૅક ઉપલબ્ધ નથી.

## IPC બ્રિજ (`preload.js`)

પ્રીલોડ `contextIsolation: true` અને `nodeIntegration: false` સાથે `contextBridge` નો ઉપયોગ કરીને `window.electronAPI` પર વ્હાઇટલિસ્ટેડ API એક્સપોઝ કરે છે.

```javascript
const VALID_CHANNELS = {
  invoke: [
    "get-app-info",
    "open-external",
    "get-data-dir",
    "restart-server",
    "check-for-updates",
    "download-update",
    "install-update",
    "get-app-version",
  ],
  send: ["window-minimize", "window-maximize", "window-close"],
  receive: ["server-status", "port-changed", "update-status"],
};
```

ખુલ્લી પદ્ધતિઓ:

| રેન્ડરર કૉલ                                                       | પ્રકાર                        |
| ----------------------------------------------------------------- | ----------------------------- |
| `getAppInfo()` → `{ name, version, platform, isDev, port }`       | બોલાવવું                      |
| `openExternal(url)`                                               | બોલાવવું                      |
| `getDataDir()`                                                    | બોલાવવું                      |
| `restartServer()`                                                 | બોલાવવું                      |
| `getAppVersion()`                                                 | બોલાવવું                      |
| `checkForUpdates()` / `downloadUpdate()` / `installUpdate()`      | બોલાવવું                      |
| `minimizeWindow()` / `maximizeWindow()` / `closeWindow()`         | મોકલો                         |
| `onServerStatus(cb)` / `onPortChanged(cb)` / `onUpdateStatus(cb)` | પ્રાપ્ત કરો (રિટર્ન ડિસ્પોઝર) |

પ્રાપ્ત સહાયકો પરત કરે છે a** નિકાલ કરનાર કાર્ય** `removeAllListeners` — પર આધાર રાખવાને બદલે જ્યારે React ઘટકો ફરીથી માઉન્ટ થાય છે ત્યારે આ સાંભળનારને સંચય અટકાવે છે.

## સર્વર જીવનચક્ર

`main.js` સિસ્ટમ નોડ સાથે નેટિવ-મોડ્યુલ ABI મિસમેચ ટાળવા માટે Electron નોડ રનટાઇમ સાથે Next.js સ્ટેન્ડઅલોન બંડલને સીધું બનાવે છે:

```js
spawn(process.execPath, [serverScript], {
  cwd: NEXT_SERVER_PATH,
  env: { ...serverEnv, PORT, NODE_ENV: "production", ELECTRON_RUN_AS_NODE: "1", NODE_PATH },
  stdio: "pipe",
});
```

હાઇલાઇટ્સ:

- `waitForServer()` વિન્ડો બતાવતા પહેલા URL ને 30 સેકન્ડ સુધી પોલ કરે છે (કોલ્ડ સ્ટાર્ટ પર કોઈ ખાલી સ્ક્રીન નહીં).
- `stdio: "pipe"` stdout/stderr મેળવે છે; તૈયાર શબ્દસમૂહો (`Ready` / `listening`) IPC ઉપર `server-status: running` બહાર કાઢે છે.
- `before-quit` આકર્ષક SIGTERM (WAL ચેકપોઇન્ટ) માટે 5 સેકંડ સુધી રાહ જુએ છે પછી SIGKILL મોકલે છે.
- ટ્રેમાં પોર્ટ સ્વિચર (`20128`, `3000`, `8080`) અટકે છે અને સર્વરને પુનઃપ્રારંભ કરે છે, પછી BrowserWindow ને ફરીથી લોડ કરે છે.

## શૂન્ય-રૂપરેખા ગુપ્ત બુટસ્ટ્રેપ

પ્રથમ પ્રક્ષેપણ પર, મુખ્ય પ્રક્રિયા સ્વતઃ જનરેટ કરે છે અને ગુમ થયેલ રહસ્યોને ચાલુ રાખે છે:

| ગુપ્ત                    | સ્ત્રોત                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------ |
| `JWT_SECRET`             | `crypto.randomBytes(64).toString("hex")`                                                               |
| `STORAGE_ENCRYPTION_KEY` | `crypto.randomBytes(32).toString("hex")` (જો એન્ક્રિપ્ટેડ ક્રેડિટ પહેલેથી અસ્તિત્વમાં હોય તો નકારે છે) |
| `API_KEY_SECRET`         | `crypto.randomBytes(32).toString("hex")`                                                               |

`<DATA_DIR>/server.env` માટે ચાલુ રાખ્યું. `DATA_DIR` ઉકેલે છે:

- Windows: `%APPDATA%\omniroute`
- Linux: `$XDG_CONFIG_HOME/omniroute` અથવા `~/.omniroute`
- macOS: `~/.omniroute`

## પર્યાવરણ ફાઇલ લુકઅપ

સર્વર બનાવતા પહેલા, મુખ્ય પ્રક્રિયા (`getPreferredEnvFilePath()` in `electron/main.js`) પસંદ કરે છે** એક** `.env` ફાઇલ: આમાંથી પ્રથમ અસ્તિત્વમાં છે.

1. `$DATA_DIR/.env`, જ્યારે `DATA_DIR` પર્યાવરણમાં સેટ હોય ત્યારે એપ સાથે લોન્ચ કરવામાં આવી હતી.
2. `<resolved DATA_DIR>/.env`, ઉપરના સમાન ડિફોલ્ટનો ઉપયોગ કરીને: Windows પર `%APPDATA%\omniroute\.env`, `$XDG_CONFIG_HOME/omniroute/.env` અથવા Linux અને macOS પર `~/.omniroute/.env`.
3. પ્રક્રિયા વર્કિંગ ડિરેક્ટરીમાં`.env`.

મુખ્ય પ્રક્રિયા ફક્ત તે જ ફાઇલને વાંચે છે; પછીના ઉમેદવારોને મર્જ કરવામાં આવ્યાં નથી. સર્વર પર્યાવરણ પછી આ અગ્રતા સાથે બનાવવામાં આવે છે (સૌથી વધુ પ્રથમ):

1. Electron પ્રક્રિયા પર્યાવરણ (એપને જે કંઈપણ લોન્ચ કર્યું તેમાંથી વારસામાં મળેલ ચલ).
2. પસંદ કરેલ `.env` ફાઇલ.
3. `<DATA_DIR>/server.env` (ઉપરના બુટસ્ટ્રેપ રહસ્યો).

જ્યારે એપ શરૂ થાય છે ત્યારે પ્રોસેસ એન્વાયર્નમેન્ટ કેપ્ચર થાય છે, તેથી એપ ચાલી રહી હોય ત્યારે સિસ્ટમ અથવા યુઝર એન્વાયરમેન્ટ વેરીએબલ સેટ કરે છે (તેની વિન્ડો બંધ થયા પછી તે ટ્રેમાં બેસે છે તે સહિત) જ્યાં સુધી એપ સંપૂર્ણપણે બંધ ન થાય અને ફરીથી લોંચ ન થાય ત્યાં સુધી સર્વર સુધી પહોંચતું નથી. રનટાઇમ નોબ્સ જેમ કે `CONTEXT_LENGTH_<PROVIDER>` માટે ( [પર્યાવરણ વેરીએબલ્સ જુઓ: પ્રતિ-પ્રદાતા સંદર્ભ લંબાઈ](../reference/ENVIRONMENT.md#per-provider-context-length-context_length_provider) ), `.env` ફાઇલને પ્રાધાન્ય આપો, પછી સંપૂર્ણપણે બહાર નીકળો (ટ્રે,** છોડો** ) અને ફરીથી લોંચ કરો.

## વિન્ડો અને ટ્રે

- `BrowserWindow`: 1400 × 900 (મિનિટ 1024 × 700), `backgroundColor: "#0a0a0a"`.
- macOS: `titleBarStyle: "hiddenInset"`, `{ x: 16, y: 16 }` પર ટ્રાફિક-લાઇટ.
- Windows/Linux: મૂળ શીર્ષક પટ્ટી.
- બંધ કરો બટન ટ્રેમાં નાનું કરે છે; ટ્રે મેનુ છે** OmniRoute ખોલો** ,** ડેશબોર્ડ ખોલો** (બાહ્ય બ્રાઉઝર),** સર્વર પોર્ટ** સબમેનુ** અપડેટ્સ માટે તપાસો** ,** છોડો** .

## સામગ્રી સુરક્ષા નીતિ

`session.defaultSession.webRequest.onHeadersReceived` દ્વારા સેટ કરો. નોંધપાત્ર નિર્દેશો:

- `frame-ancestors 'none'`, `object-src 'none'`, `child-src 'none'`
- `connect-src 'self' http://localhost:* http://127.0.0.1:* ws://localhost:* ws://127.0.0.1:* https://*.omniroute.online https://*.omniroute.dev`
- દેવ મોડ ફક્ત `script-src` માં `'unsafe-eval'` ઉમેરે છે

## સ્વતઃ-અપડેટ

GitHub પ્રદાતા (`diegosouzapw/OmniRoute`) સાથે `electron-updater` ઉપયોગ કરે છે.

- `autoDownload = false`, `autoInstallOnAppQuit = true`
- `update-status` IPC દ્વારા રેન્ડરરને મોકલેલ ઇવેન્ટ્સ : `checking`, `available`, `not-available`, `downloading` ( `percent` સાથે), `downloaded`, `error`
- `installUpdate()` સર્વરને મારી નાખે છે પછી `autoUpdater.quitAndInstall()` ને કૉલ કરે છે
- દેવ મોડમાં છોડ્યું (`!app.isPackaged`)

## પાઇપલાઇન બનાવો

1. `.next/standalone` માં`npm run build` → Next.js સ્ટેન્ડઅલોન .
2. `prepare-electron-standalone.mjs` → `.next/electron-standalone` માં ફરીથી તબક્કામાં આવે છે અને `server.js` + `required-server-files.json` અંદર સંપૂર્ણ પાથને ફરીથી લખે છે જેથી બંડલ પુનઃસ્થાપિત કરી શકાય.
3. `electron-builder` પેકેજો `main.js`, `preload.js`, `node_modules`, અને `extraResources: { ../.next/electron-standalone → app }`.

### લક્ષ્યો બનાવો

| OS      | લક્ષ્યો                                   |
| ------- | ----------------------------------------- |
| Windows | NSIS ઇન્સ્ટોલર + પોર્ટેબલ (x64)           |
| macOS   | DMG (Intel + arm64, ડ્રેગ-ટુ-એપ્લિકેશન્સ) |
| Linux   | AppImage + DEB (x64 + arm64)              |

NSIS સેટિંગ્સ: `oneClick: false`, વપરાશકર્તાને ઇન્સ્ટોલ ડિરેક્ટરી પસંદ કરવા દે છે, ડેસ્કટોપ અને સ્ટાર્ટ-મેનુ શોર્ટકટ્સ બનાવે છે.

## સ્મોક ટેસ્ટિંગ પેકેજ્ડ બિલ્ડ

```bash
npm run electron:smoke:packaged
```

`scripts/dev/smoke-electron-packaged.mjs`:

- વર્તમાન પ્લેટફોર્મ માટે `electron/dist-electron/` માં પેકેજ્ડ બાઈનરી સ્વતઃ શોધે છે.
- આઇસોલેટેડ `HOME`/`APPDATA`/`XDG_*` ડિરેક્ટરીઓ સાથે લોન્ચ થાય છે જેથી તે ડેવલપર ડેટાને સ્પર્શતું નથી.
- 45 સે.ની અંદર HTTP 200 માટે મતદાન `http://127.0.0.1:20128/login`.
- ઘાતક પેટર્ન માટે ઘડિયાળો stderr/stdout (`Cannot find module`, `MODULE_NOT_FOUND`, `ERR_DLOPEN_FAILED`, `Failed to start server`, વગેરે).
- તત્પરતા પછી સ્થિર રનટાઇમની 2 સેકંડ રાહ જુએ છે, પછી SIGTERM જારી કરે છે અને પોર્ટ મુક્ત થવાની રાહ જુએ છે.
- CI માં, `--no-sandbox --disable-gpu` (અને Linux પર `--disable-dev-shm-usage` ) આપમેળે પસાર થાય છે.

Env ઓવરરાઇડ કરે છે: `ELECTRON_SMOKE_APP_EXECUTABLE`, `ELECTRON_SMOKE_URL`, `ELECTRON_SMOKE_TIMEOUT_MS`, `ELECTRON_SMOKE_SETTLE_MS`, `ELECTRON_SMOKE_DATA_DIR`, `ELECTRON_SMOKE_KEEP_DATA`, `ELECTRON_SMOKE_STREAM_LOGS`.

## કોડ સહી

`electron/package.json` કરે છે** નથી** વાયર હસ્તાક્ષર પ્રમાણપત્રો સીધા. તેમને env vars દ્વારા `electron-builder` પર પસાર કરો :

### macOS

```bash
export APPLE_ID=<email>
export APPLE_APP_SPECIFIC_PASSWORD=<password>
export APPLE_TEAM_ID=<id>
export CSC_LINK=path/to/cert.p12
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:mac
```

### Windows

```bash
export CSC_LINK=path/to/cert.pfx
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:win
```

### Linux

AppImage હસ્તાક્ષર વૈકલ્પિક છે — સેટ `LINUX_GPG_KEY` જો સહી કરી રહ્યા હોય.
