> ઑપ્ટ-ઇન, ડિફૉલ્ટ રૂપે બંધ કરો (`modelVisibilityAllowlist`/`modelVisibilityDenylist` બંને ખાલી `/v1/models` કૅટેલોગ AND દરેક `auto/*` ઉમેદવાર પૂલ બાઇટ-સમાન છોડે છે). ઓપરેટરો માટે `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`) ની એક બહેન કે જેઓ ખર્ચ સાથે કોઈ લેવાદેવા ન હોય તેવા કારણોસર ક્યુરેટેડ મોડલ યાદી ઈચ્છે છે.

## આ શા માટે અસ્તિત્વમાં છે

`hidePaidModels` જવાબ આપે છે "શું આ મોડેલ મફત છે?" અને `hideAutoCombos` જવાબ આપે છે "શું `auto/*` વર્ચ્યુઅલ આઈડીની જાહેરાત બિલકુલ કરવી જોઈએ?" — ન તો ઑપરેટરને મૉડલના મનસ્વી સબસેટને ક્યુરેટ કરવા દે છે (દા.ત. આપેલ Claude કોડ / OpenCode ક્લાયન્ટે જોવું જોઈએ, કિંમતોથી સ્વતંત્ર હોય તેવા મોડલને બરાબર રજૂ કરવા). #11481 ઉમેરે છે કે બે સ્વતંત્ર, ઑપ્ટ-ઇન સ્ટ્રિંગ-એરે સેટિંગ્સ તરીકે.

## સેટિંગ્સ

| કી                         | પ્રકાર     | ડિફૉલ્ટ | અર્થ                                                                         |
| -------------------------- | ---------- | ------- | ---------------------------------------------------------------------------- |
| `modelVisibilityDenylist`  | `string[]` | `[]`    | ઉમેદવાર સાથે મેળ ખાતી એન્ટ્રી તેને catalog/candidate પૂલથી છુપાવે છે.        |
| `modelVisibilityAllowlist` | `string[]` | `[]`    | જ્યારે ખાલી ન હોય ત્યારે, ઉમેદવાર સાથે મેળ ખાતી ONLY એન્ટ્રીઓ ખુલ્લી રહે છે. |

બંને 200 અક્ષરો સુધીની 500 જેટલી એન્ટ્રી સ્વીકારે છે ( `src/shared/validation/settingsSchemas.ts` માં Zod-માન્યતા). એન્ટ્રી ક્યાં તો છે:

- ચોક્કસ કેટલોગ id — `"gpt-4o"` (બેર મોડલ id) અથવા `"openai/gpt-4o"` (પ્રોવાઇડર-પ્રીફિક્સ્ડ), અથવા
- `*`/`?` — ઉપયોગ કરીને ગ્લોબ પેટર્ન દા.ત. `"openai/gpt-4*"` અથવા `"anthropic/*"` — સમાન શેર કરેલ `globToRegex()` મેચર (`src/shared/utils/globPattern.ts`) દ્વારા ઉકેલવામાં આવે છે જે `ModelRoutingSection` ના પ્રતિ-મોડલ કોમ્બો મેપિંગ્સ અને `freeModels.ts::matchesOnlyPaidModels` દ્વારા પહેલેથી ઉપયોગમાં લેવાય છે.

અગ્રતા: નામંજૂર કરનારને પહેલા ચકાસવામાં આવે છે (નકારેલી એન્ટ્રી હંમેશા છુપાયેલી હોય છે, પછી ભલે તે મંજૂર સૂચિ સાથે મેળ ખાતી હોય); જ્યારે મંજૂર સૂચિ બિન-ખાલી હોય, ત્યારે માત્ર તે મેળ ખાતી એન્ટ્રીઓ જ ટકી રહે છે.

## બે ચોકપોઇન્ટ, એક નહીં

#6512 નો પાઠ ( `hidePaidModels` -only કેટલોગ ફિલ્ટર હજુ પણ `auto/*` રૂટને પેઇડ મોડલ પર જવા દે છે, કારણ કે કોમ્બો ઉમેદવાર પૂલ સ્વતંત્ર રીતે બનાવવામાં આવ્યો હતો) અહીં સમાન રીતે લાગુ પડે છે. મેચિંગ પ્રિડિકેટ `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`) ને BOTH માંથી કહેવામાં આવે છે :

- `src/app/api/v1/models/catalog.ts` — `/v1/models` લિસ્ટિંગ પોતે, સમાન 5 પ્રતિ-સ્રોત ચોકપોઇન્ટ્સ પર `shouldHidePaid()` પહેલેથી જ ગેટ્સ (સ્થિર `PROVIDER_MODELS`, સમન્વયિત પ્રદાતા પંક્તિઓ, કસ્ટમ પંક્તિઓ, ઉપનામ-બેક્ડ પંક્તિઓ, મેનેજ-ફોલબેક પંક્તિઓ).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — `virtualFactory.ts::buildPreparedPool` માંથી બોલાવવામાં આવે છે , સમકક્ષ `filterPaidOnlyCandidates()` કૉલ પછી તરત જ, તેથી નકારેલ મોડેલને `auto/*` ઉમેદવાર પૂલમાં ક્યારેય પસંદ કરી શકાતું નથી.

## NOT ફિલ્ટર શું છે

મિરર્સ `hideAutoCombos` ની હાલની વર્તણૂક: એક મોડેલ આઈડી મોકલવામાં આવી છે** સ્પષ્ટપણે** ( `auto/*` દ્વારા નહીં, અને કેટલોગ સૂચિ દ્વારા શોધાયેલ નથી) ડિસ્પેચ પર ક્યારેય અવરોધિત નથી — માત્ર advertisement/candidate-pool સભ્યપદ ફિલ્ટર કરવામાં આવે છે. આ `hidePaidModels` થી સ્વતંત્ર છે; ઑપરેટરને ખર્ચ સાથે કોઈ લેવાદેવા ન હોય તેવા કારણોસર ક્યુરેટેડ સેટ જોઈએ છે, તેથી બંને સેટિંગ સ્વતંત્ર AND-ed ફિલ્ટર્સ તરીકે કંપોઝ કરે છે, જે `catalog.ts` માં હાલની મલ્ટિ-ફ્લેગ કમ્પોઝિશનની જેમ જ છે.

સેટિંગ્સ નિકાસ (`GET /api/settings/export-json`) માં બંને એરેનો શાબ્દિક સમાવેશ થાય છે, અન્ય કોઈપણ સેટિંગ્સ ફીલ્ડ — ની જેમ `hidePaidModels` ના કોમ્બો-સ્ટેપ એક્સપોર્ટ ફિલ્ટરથી વિપરીત, અહીં કોઈ રી-હાઈડ્રેશન જોખમ નથી: નિકાસ કરાયેલ કોમ્બો સ્ટેપમાં એમ્બેડ કરેલ નામંજૂર આઈડી ઓપરેટરની પોતાની સ્પષ્ટ રૂટીંગ પસંદગી છે, નિકાસ કરવા માટે કંઈક જરૂરી નથી.

## કોમ્બોઝ-ફક્ત સૂચિ (`exposeCombosOnly`)

એક અલગ બુલિયન, ડિફૉલ્ટ રૂપે ઑપ્ટ-ઇન અને `false`, જમાવટ માટે જ્યાં કોમ્બોઝ જાહેર મોડેલ સપાટી છે અને પ્રદાતાઓ માત્ર બેકએન્ડ છે. જ્યારે તે `true` હોય, ત્યારે સાર્વજનિક સૂચિ (`GET /v1/models`, `GET /v1`, અને `getUnifiedModelsResponse()` પર બનેલ અન્ય `/v1` શોધ રૂટ ) માત્ર `owned_by: "combo"` સાથેની પંક્તિઓ રાખે છે : વપરાશકર્તા કોમ્બો વત્તા બિલ્ટ-ઇન `auto/*` કોમ્બોઝ (સિવાય કે `hideAutoCombos` તેમને છુપાવે). તે પ્રતિ-કી `catalogScope: "combos"` તરીકે સમાન પંક્તિ પરીક્ષણનો ઉપયોગ કરે છે, અને કીના પોતાના allow/deny/scope ફિલ્ટર હજુ પણ ટોચ પર લાગુ થાય છે.

તેને ટૉગલ કરો** સેટિંગ્સ → રૂટીંગ → મોડલ્સ API યાદી** , અથવા `PATCH /api/settings {"exposeCombosOnly": true}` સાથે.

ઉપરની યાદીઓની જેમ, તે માત્ર જાહેરાતમાં ફેરફાર કરે છે:

- સ્પષ્ટ `provider/model` id હજુ પણ મોકલે છે, અને `GET /v1/models/{id}` હજુ પણ તેને ઉકેલે છે;
- ડેશબોર્ડ કેટલોગ (`GET /api/models/catalog`, જે મોડેલ પીકર્સ દ્વારા ઉપયોગમાં લેવાય છે) સંકુચિત નથી;
- તે `auto/*` ઉમેદવાર પૂલમાં પ્રતિબિંબિત નથી, તેથી `auto/*` કોમ્બોઝ તેમના સંપૂર્ણ પૂલને રાખે છે.
