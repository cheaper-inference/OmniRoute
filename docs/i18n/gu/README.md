## 💰 ~ 1.62B ટોકન્સ / મહિનો તૃતીય-પક્ષ મફત સ્તરોમાં

</div>

> **તમારા પોતાના પ્રદાતા એકાઉન્ટ્સ લાવો.** આ અલગથી પાત્ર તૃતીય-પક્ષ મફત સ્તરોમાં અંદાજિત એકંદર છે, OmniRoute તરફથી ટોકન અનુદાન નથી. સાઇન અપ કરો, જરૂરી હોય ત્યાં ઓળખપત્રો મેળવો અને તમે ઉપયોગ કરી શકો તે પ્રદાતાઓને કનેક્ટ કરો; દરેક પ્રદાતા તેની મર્યાદા, ઉપલબ્ધતા અને શરતોને નિયંત્રિત કરે છે.
>
> હાથથી ફ્રી ટાયર સ્ટેક કરવું એ પીડાદાયક છે — ડઝનેક SDKs, ડઝનેક દરની મર્યાદાઓ, અને તમારી પાસે ખરેખર કેટલું છે તેનો ખ્યાલ નથી. OmniRoute કેટલોગ **34 રિકરિંગ પૂલ કીમાં 466 ફ્રી-ટાયર એન્ટ્રીઓ** અને થી ટોકન હેડલાઇનની ગણતરી કરે છે**પ્રકાશિત હકારાત્મક માસિક બજેટ વત્તા પાંચ પ્રતિ-મૉડલ Groq કૅપ્સ સાથે 17 પૂલ** , વહેંચાયેલ પૂલ દ્વારા ડુપ્લિકેટ. પ્રાદેશિક ઓળખ ચકાસણી (આજે: ModelScope) પછી જ ખુલે છે તે ક્વોટા, પ્રાદેશિક ઓળખ ચકાસણીની પાછળ +~ 6M, અને હેડલાઇનમાં ક્યારેય સારાંશ નથી. પરિણામ ડેશબોર્ડ (`/dashboard/free-tiers`) પર દૃશ્યમાન રહે છે.

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute free-tier budget card: ~1.62B free tokens per month steady, up to ~2.22B in the first month with signup credits, from 34 documented recurring pool keys covering 466 cataloged free-tier entries behind one endpoint. Honest pool-deduped math — each shared pool counted once, including 17 recurring pools with a published positive monthly token budget plus five per-model Groq caps; 12 providers are marked avoid in the terms-risk catalog so you decide. Budget bar includes Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (five per-model caps) and smaller pools, plus first-month signup credits and permanently-free no-token-cap providers surfaced separately so they never inflate the headline. Live used/remaining on /dashboard/free-tiers."/>

> જીવંત `/dashboard/free-tiers` પૃષ્ઠનો એનિમેટેડ સારાંશ. સંપૂર્ણ પદ્ધતિ (પૂલ ડીડ્યુપ, ક્રેડિટ ટિયર્સ, પ્રદાતાની શરતો):**[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)** .
>
> <sub>આ આંકડાઓ લાઇવ કેટલોગ સામે દર બે અઠવાડિયે ફરીથી ઓડિટ કરવામાં આવે છે અને**બંને રીતે ખસેડો** — એક પ્રદાતા મફત સ્તર સમાપ્ત કરે છે અને સંખ્યા ઘટી જાય છે; એક નવું ઊતરે છે અને તે ચઢે છે. કેટલોગ વાસ્તવમાં જેની ગણતરી કરે છે તે અમે પ્રકાશિત કરીએ છીએ, ક્યારેય રાઉન્ડ-અપ શ્રેષ્ઠ કેસ નથી.</sub>

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute સ્થિતિસ્થાપકતા — 3 સ્વતંત્ર સ્વ-પુનઃસ્થાપન સ્તરો, યોગ્ય નિષ્ફળતા માટે યોગ્ય સ્તર. સ્તર 1 પ્રદાતા સર્કિટ બ્રેકર (આખો પ્રદાતા): ફક્ત 408/5xx પર જ ટ્રિપ થાય છે, થ્રેશોલ્ડ OAuth 8× / API-key 12× / local 2×, 60s/30s/15s પછી HALF-OPEN પ્રોબમાં રીસેટ થાય છે, આળસુ પુનઃપ્રાપ્તિ; OPEN હોય ત્યારે કોમ્બો આગલા પ્રદાતા તરફ પુનઃરૂટ કરે છે. સ્તર 2 કનેક્શન કૂલડાઉન (એક કી/એકાઉન્ટ): આધાર 5s OAuth / 3s API-key, એન્ટિ-થન્ડરિંગ-હર્ડ સુરક્ષા સાથે ઘાતાંકીય ×2 બેકઑફ, 429 Retry-Afterનું પાલન કરે છે, સફળતા બધી ભૂલ સ્થિતિ સાફ કરે છે; એક કૂલડાઉનમાં રહેલી કી અવગણાય છે જ્યારે સમકક્ષ કીઓ સેવા આપવાનું ચાલુ રાખે છે. સ્તર 3 મોડેલ લૉકઆઉટ (એક મોડેલ): પ્રતિ-મોડેલ 429, local 404 અથવા મોડ નકાર ફક્ત તે મોડેલને લૉક કરે છે — આખા કનેક્શનને ક્યારેય નહીં. અંતિમ સ્થિતિઓ (પ્રતિબંધિત, સમાપ્ત થયેલું, ક્રેડિટ ખતમ) ઓપરેટર માટે છે, કૂલડાઉન માટે નહીં."/>

## 📡 OmniRoute Radar

ઉપર દસ્તાવેજીકૃત, પૂલ-ડીડુપ્લિકેટેડ કૅટલૉગમાંથી મુખ્ય મફત-ટિયર મર્યાદા હજી પણ **~1.62B ટોકન્સ/મહિનો** છે. પ્રદાતાના અસ્થાયી સાઇનઅપ ક્રેડિટ્સ પ્રથમ મહિનાની મર્યાદાને અલગથી વધારીને **~2.22B** સુધી લઈ જઈ શકે છે. OmniRoute રિલીઝની વચ્ચે મફત-મૉડલની ઉપલબ્ધતા વિશે વધુ તાજી માહિતી ઇચ્છતા લોકો માટે Radar એક વૈકલ્પિક, હસ્તાક્ષરિત કૅટલૉગ ઓવરલે છે; સમુદાય કૅટલૉગ અને હાલની દરેક મફત સુવિધા મફત જ રહે છે.

સમર્થકો લાઇવ કૅટલૉગ અને પ્રદાતાઓની વધારાની તકો મેળવી શકે છે. પ્રદાતાની ઉપલબ્ધતાના આધારે, તેની અલગ અને પરિવર્તનશીલ મહત્તમ મર્યાદા **વધુમાં વધુ અંદાજે 3B ટોકન્સ/મહિનો** છે. આ મર્યાદા કોઈ બાંયધરી નથી: પ્રદાતાઓ કોઈપણ સમયે ક્વોટા, પાત્રતા, મૉડલ્સ અથવા પ્રદેશો બદલી શકે છે.

Radar વૈકલ્પિક છે અને માત્ર GET નો ઉપયોગ કરે છે. OmniRoute ક્લાયન્ટ પ્રોમ્પ્ટ્સ, ટ્રાફિક, પ્રદાતા કૉન્ફિગરેશન, ઉપયોગની ટેલિમેટ્રી અથવા સ્થાનિક જાહેરાત-બરતરફીની સ્થિતિ અપલોડ કરતું નથી. પાત્રતા અને વર્તમાન કૅટલૉગ વિશે **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)** પર જાણો.

- **🛂 અનુકૂલનશીલ પ્રવેશ અને ઓવરલોડ સુરક્ષા** — હેવીવેઇટ ચેટ વિનંતીઓ 503ing ને બદલે, કનેક્શન દીઠ અણુ RPM રોલિંગ લીઝ સાથે. → [સ્થિતિસ્થાપકતા માર્ગદર્શિકા](docs/architecture/RESILIENCE_GUIDE.md)
- **🗂️ કેનોનિકલ `/v1/models` ઓર્ડરિંગ** — પ્રદાતા દીઠ એક સંલગ્ન પ્રદાતા-જૂથબંધ બ્લોક (કોમ્બોઝ પ્રથમ પિન કરેલ), દરેક કેટલોગ સ્ત્રોતમાં સ્થિર. → [API સંદર્ભ](docs/reference/API_REFERENCE.md)
- **🗜️ કમ્પ્રેશન સખ્તાઇ** — ડિફોલ્ટ-ઓન ઇન્ફ્લેશન ગાર્ડ, DE / FR / JA + ચાઇનીઝ (wényán), Gradle અને RTK ફિલ્ટર્સ માટે કેવમેન પેક.NET. → [કમ્પ્રેશન](docs/compression/COMPRESSION_ENGINES.md)

- **⚖️ ક્વોટા-શેર રૂટીંગ** — એ શેર કરેલ એકાઉન્ટના ક્વોટાને સંપૂર્ણ રીતે પુલ કરેલી કી પર વિભાજિત કરે છે, કાર્ય-સંરક્ષણ કરે છે જેથી નિષ્ક્રિય સ્લાઇસેસ આપવામાં આવે. → [સ્થિતિસ્થાપકતા માર્ગદર્શિકા](docs/architecture/RESILIENCE_GUIDE.md)

- **🛰️ રિમોટ મોડ** — સ્કોપ ટોકન્સ (`connect` / `contexts` / `tokens`) + VPS ઇન્સ્ટોલ કરવા માટે `antigravity` OAuth સહાયક સાથે રિમોટ OmniRoute ચલાવે છે. → [રીમોટ મોડ](docs/guides/REMOTE-MODE.md)

- **🕵️ પારદર્શક MITM ડિક્રિપ્ટ (TPROXY)** — CLIs કેપ્ચર કરે છે જે પ્રોક્સી env vars ને અવગણે છે, પ્રતિ-SNI CA + ટ્રસ્ટ-સ્ટોર ઇન્સ્ટોલર સાથે. → [MITM/TPROXY](docs/security/MITM-TPROXY-DECRYPT.md)

- **🧩 બૉક્સમાં પણ** — પ્લગઇન ફ્રેમવર્ક + બજાર, Omni/Agent/GitHub કુશળતા ફ્રેમવર્ક, Obsidian વૉલ્ટ એકીકરણ (22 MCP ટૂલ્સ), OpenAI-સુસંગત બેચ અને ફાઇલો APIs, સિમેન્ટીક રિસ્પોન્સ કેશ, લીડરબોર્ડ્સ સાથે ગેમિફિકેશન, ACP એજન્ટ શોધ (15 બિલ્ટ-ઇન એજન્ટ્સ), શેડ્યૂલ કરેલ લોગ નિકાસ BigQuery, `auto/chaos` સમાંતર મલ્ટિ-મોડલ ફેન-આઉટ, એ Telegram બોટ બ્રિજ, એક ઇન-એપ વર્ઝન મેનેજર અને LMArena-ELO ફ્રી-પ્રોવાઇડર રેન્કિંગ. → [દસ્તાવેજ](docs/README.md)

પ્રતિ પ્રોસેસ ક્રેડેન્શિયલ્સ ઇન્જેક્ટ થાય છે, Qwen/Gemini માટે અલગ-થલગ હોમ બનાવાય છે:

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # OpenAI Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# અથવા પ્રોવાઇડર+મોડલ ઇન્ટરેક્ટિવ રીતે પસંદ કરો અને ટૂલનું પોતાનું કોનફિગ લખો:
omniroute configure codex          # આ માટે પણ: claude opencode qwen aider goose gemini cline continue kilo 5dive
```

દરેક કમાન્ડ સક્રિય રિમોટ કોન્ટેક્સ્ટનું પાલન કરે છે (`omniroute connect <host>`), `--dry-run`
ચોક્કસ env/argsનું પૂર્વદર્શન આપે છે વિના એક્ઝિક્યુટ કર્યા, અને `--api-key-env NAME` તમારા શેલ ઇતિહાસમાંથી સિક્રેટ્સ દૂર રાખે છે. → [CLI ઇન્ટિગ્રેશન્સ](docs/guides/CLI-INTEGRATIONS.md)

## 🔌 સંપૂર્ણ CLI + A2A અને MCP

</div>

> સર્વર ઉપરાંત, OmniRoute એ **80+ કમાન્ડ્સ** ધરાવતું **સંપૂર્ણ કમાન્ડ-લાઇન કૉકપિટ** છે, તેમજ ઓપન એજન્ટ પ્રોટોકોલ્સ પણ ધરાવે છે જેથી AI એજન્ટ તેને **જાતે જ** સંચાલિત કરી શકે.

### ⌨️ વાસ્તવિક CLI (માત્ર `start` નહીં)

```bash
omniroute               # ગેટવે + ડૅશબોર્ડ સર્વ કરો (પોર્ટ 20128)
omniroute chat          # ઇન્ટરેક્ટિવ TUI ચેટ ક્લાયન્ટ (સ્લેશ: /model /combo /skill /memory)
omniroute setup         # માર્ગદર્શિત પ્રથમ-રન વિઝાર્ડ
omniroute doctor        # પ્રોવાઇડર્સ, પોર્ટ્સ અને નેટિવ ડિપેન્ડન્સીઝનું નિદાન કરો
```

### 🛰️ રિમોટ મોડ — CLI અહીં ચલાવો, OmniRoute VPS પર

સર્વર પર OmniRoute છે? **એ જ CLI** વડે તેને તમારા લેપટોપ પરથી સંચાલિત કરો. સ્કોપ્ડ ઍક્સેસ ટોકન વડે એક વાર લૉગ ઇન કરો;
ત્યારબાદ દરેક કમાન્ડ રિમોટને લક્ષ્ય બનાવે છે.

```bash
omniroute connect 192.168.0.15            # પાસવર્ડ → સ્કોપ્ડ ટોકન, કોન્ટેક્સ્ટ તરીકે સાચવવામાં આવે છે
omniroute models                         # ← રિમોટ સર્વર સામે ચાલે છે
omniroute configure codex                 # ← રિમોટ મોડલ પસંદ કરે છે, સ્થાનિક Codex પ્રોફાઇલ લખે છે
omniroute tokens create --name ci --scope read   # અન્ય મશીનો માટે વધુ મર્યાદિત ટોકન્સ બનાવો
omniroute contexts use default            # ← સ્થાનિક સર્વર પર પાછા સ્વિચ કરો
```

ટોકન્સ `read` / `write` / `admin` સ્કોપ ધરાવે છે; પ્રોસેસ શરૂ કરતા રૂટ્સ માત્ર લૂપબૅક સુધી મર્યાદિત રહે છે.

### 📖 તે કેવી રીતે કામ કરે છે — પાઇપલાઇન, આર્કિટેક્ચર અને બચતનો ગણિત

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute કમ્પ્રેશન પાઇપલાઇન: એક દાખલા તરીકેની 10,000-ટોકન ક્લાયન્ટ રિક્વેસ્ટ 12 કમ્પોઝેબલ એન્જિનો — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra અને OmniGlyph — માંથી પસાર થાય છે અને દસ્તાવેજીકૃત સ્ટેક્ડ ઉદાહરણમાં આશરે 1,080 ટોકન સાથે પ્રોવાઇડર સુધી પહોંચી શકે છે. સ્ટ્રક્ચર્ડ કન્ટેન્ટ પ્રિઝર્વેશન ગાર્ડ્સ અને દરેક-સ્ટેપ ફિડેલિટી ગેટ્સ દ્વારા સુરક્ષિત છે; સ્પષ્ટ લોસી અથવા પ્રાયોગિક મોડ્સ લાયક કન્ટેન્ટને રૂપાંતરિત કરી શકે છે."/>

ડિફોલ્ટ સ્ટેક્ડ કોમ્બો `RTK → Caveman` ચલાવે છે. જ્યારે બંને એક જ ટૂલ/કોન્ટેક્સ્ટ પેલોડ પર કાર્ય કરે છે, ત્યારે બચત ચક્રવૃદ્ધિ થાય છે:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

કોડ બ્લોક્સ, URLs, JSON અને સ્ટ્રક્ચર્ડ ડેટા પ્રિઝર્વેશન એન્જિન દ્વારા **હંમેશા સુરક્ષિત** રહે છે.

> **જ્યારે થોડા ટોકન કામ ચલાવી શકે ત્યારે ઘણા ટોકન શા માટે વાપરવા?** દરેક રિક્વેસ્ટ OmniRoute ની કમ્પ્રેશન પાઇપલાઇનમાંથી **પારદર્શક રીતે** પસાર થાય છે — ક્લાયન્ટમાં કોઈ ફેરફાર વગર. તે હવે ક્રમ પ્રમાણે ચાલતી અને રાઉટિંગ કોમ્બો મુજબ મિક્સ એન્ડ મેચ થતી **12 કમ્પોઝેબલ એન્જિનોનો સ્ટેક** છે — [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K+), [LLMLingua-2](https://github.com/microsoft/LLMLingua), અને [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR) ના વિચારો પર આધારિત.

### 🎚️ એન્જિન — આઉટપુટ શૈલીઓ ઉપરાંત, અનુકૂલનશીલ ડાયલ અને પ્રતિ-વિનંતી નિયંત્રણ

ઉપરના 12 એન્જિન જે જાય છે તે સંકોચાય છે**માં** . ત્રણ વધુ સ્તરો આકાર **કેવી રીતે** ,**જ્યારે** , અને શું આવે છે**બહાર** :

- **🪄 આઉટપુટ શૈલીઓ** _(આઉટપુટ-અક્ષ સ્ટીયરિંગ)_ — ઇન્જેક્ટ નિર્ધારિત, કેશ-સલામત પ્રતિભાવ-આકારની સૂચનાઓ; સંયુક્ત, દરેક `lite` / `full` / `ultra` તીવ્રતા પર. શૈલી ઉમેરવી એ એક-લાઇન રજિસ્ટ્રી એન્ટ્રી છે:
  - **ટર્સ ગદ્ય** — ડ્રોપ ફિલર / લેખો / હેજિંગ; તકનીકી પદાર્થને ચોક્કસ રાખો.
  - **ઓછો કોડ** — "આળસુ વરિષ્ઠ દેવ" YAGNI: સૌથી નાનો કાર્યકારી ફેરફાર, કોઈ અનિચ્છનીય પાલખ નહીં.
  - **પોનીટેલ (આળસુ વરિષ્ઠ દેવ)** — YAGNI સીડી પર ચઢો, મૂળ કારણને ઠીક કરો, સૌથી નાનો કાર્યકારી તફાવત.
  - **મારી પાસે ADHD (એક્શન-પ્રથમ) છે** — નેક્સ્ટ એક્શન લીડ્સ, સ્ટેપ્સ ક્રમાંકિત, એક નક્કર આગલું પગલું, કોઈ પ્રસ્તાવના નથી.
  - **terse CJK (文言)** — ક્લાસિકલ-ચીની અલ્ટ્રા-ટર્સ શૈલી (લોકેલ-ગેટેડ ટુ `zh`).
- **🎯 અનુકૂલનશીલ સંદર્ભ-બજેટ** _(ડાયલ)_ — એક on/off ટોકન થ્રેશોલ્ડને બદલે, સૌથી સસ્તું, સૌથી વધુ-નુકસાન રહિત એન્જીનને માત્ર જરૂરી હોય ત્યાં સુધી વધારી દો**મોડેલની સંદર્ભ વિન્ડોને ફિટ કરો** . નીતિ: `reserve-output` (ડિફૉલ્ટ, મોડેલ-અવેર) · `percentage` · `absolute`. મોડ: `floor` (ગેરંટી ફિટ) · `replace-autotrigger` (તમારી સ્પષ્ટ પસંદગી જીતે છે) · `off` (લેગસી થ્રેશોલ્ડ).
- **🎛️ જ્યાં સંકોચન નક્કી કરવામાં આવે છે** _(અગ્રતા, ઉચ્ચ → નીચું)_ — પ્રતિ-વિનંતી `x-omniroute-compression` હેડર › રૂટીંગ-કોમ્બો ઓવરરાઇડ › સક્રિય નામવાળી પ્રોફાઇલ › અનુકૂલનશીલ / સ્વતઃ-ટ્રિગર › પેનલ ડિફોલ્ટ › બંધ. લાગુ કરેલ પ્લાન `X-OmniRoute-Compression: <mode>; source=<source>` પ્રતિભાવ હેડરમાં પાછો પડઘો પાડે છે.

ટોકન થ્રેશોલ્ડ દ્વારા સ્વતઃ ટ્રિગર કરો, અનુકૂલનશીલ ડાયલ પર ફ્લિપ કરો, નામવાળી પ્રોફાઇલને પિન કરો, વિનંતી દીઠ એક-ઓફ સેટ કરો અથવા રૂટીંગ કોમ્બો — દીઠ જે પણ વર્કલોડને બંધબેસે છે તે પાઇપલાઇન સોંપો. ઑફલાઇન ઑપ્ટ-ઇન **eval હાર્નેસ** (`npm run eval:compression`) તમે ફેરફારને પ્રોત્સાહન આપો તે પહેલાં પિન કરેલા કોર્પસ પર વફાદારી વિરુદ્ધ બચતનો સ્કોર કરે છે.

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` સૌથી ઊંચા **પ્રકાશિત** સ્થિર SemVerને અનુસરે છે. તે git `main`ને ટ્રૅક કરતું નથી. GitOps માટે `:X.Y.Z` પિન કરો. [Docker રિલીઝ ચૅનલ્સ](docs/guides/DOCKER_GUIDE.md#release-channels) જુઓ. ઇમેજમાં **`OMNIROUTE_MEMORY_MB=1024`** પિન કરેલું છે. તે ડૅશબોર્ડ અને હળવી ચૅટ માટે પૂરતું છે. **કોડિંગ એજન્ટ્સ** (Claude Code, Codex, Grok, … તરફથી `POST /v1/responses`)ને ઘણો મોટો V8 હીપ જોઈએ છે, નહીં તો બે ઓવરલેપ થતા લાંબા કોન્ટેક્સ્ટ હેઠળ આશરે 12 GiB પર પ્રોસેસમાં `FATAL ERROR` થાય છે. કન્ટેનરનું કદ હીપ કરતાં વધુ રાખો (નેટિવ બફર્સ V8ની બહાર રહે છે):

| વર્કલોડ                          | હીપ (`-e OMNIROUTE_MEMORY_MB`) | કન્ટેનર (`--memory`) |
| -------------------------------- | ------------------------------ | -------------------- |
| ડૅશબોર્ડ / હળવી ચૅટ              | `1024` (ઇમેજ ડિફૉલ્ટ)          | ≥2 g                 |
| એક કોડિંગ એજન્ટ                  | `8192`                         | ≥10 g                |
| બે સમકાલીન લાંબા `/v1/responses` | `10240`–`12288`                | ≥12–16 g             |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

સંપૂર્ણ કોષ્ટક: [Docker માર્ગદર્શિકા — રનટાઇમ RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

**🥟 Bun**

Bun રનટાઇમ ડિટેક્શન દ્વારા પ્રમાણભૂત `bun install` અને ગ્લોબલ ઇન્સ્ટોલેશન (`bun install -g omniroute`) સમર્થિત છે:

- **બિલ્ટ-ઇન `bun:sqlite`**: Bun હેઠળ ચાલતી વખતે OmniRoute, Bunના બિલ્ટ-ઇન `bun:sqlite` ડ્રાઇવરનો ઉપયોગ કરે છે અને Node.js પર `better-sqlite3` અથવા `sql.js` પર ફૉલબૅક કરે છે.
- **ડેવમાં સ્વચાલિત Webpack બંડલર પસંદગી**: ડેવલપમેન્ટ (`bun run dev`) આપમેળે Bunને ઓળખે છે અને નેટિવ V8 બાઇન્ડિંગ અસંગતતાઓ રોકવા માટે Webpackની તરફેણમાં Turbopackને અક્ષમ કરે છે. પ્રોડક્શન બિલ્ડ્સ (`bun run build`) Node પરની જેમ જ `OMNIROUTE_USE_TURBOPACK`ને ચોક્કસ રીતે અનુસરે છે: ડિફૉલ્ટ રૂપે Turbopack, Webpack વડે બિલ્ડ કરવા માટે `OMNIROUTE_USE_TURBOPACK=0` (`Dockerfile.bun` તેને `--build-arg` તરીકે ઉપલબ્ધ કરાવે છે).
- **સમર્પિત Bun Dockerfile**: નેટિવ Bun પ્રોડક્શન ડિપ્લોયમેન્ટ્સ માટે મલ્ટિ-સ્ટેજ `Dockerfile.bun` (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
bun install
bun run dev
```

નેટિવ SQLite એન્જિન (`better-sqlite3`) એક **વૈકલ્પિક** ડિપેન્ડન્સી છે, તેથી ગ્લોબલ
ઇન્સ્ટોલેશન સોર્સમાંથી કમ્પાઇલ થવાની રાહમાં ક્યારેય અટકતું નથી: તમારા પ્લેટફોર્મ/Node માટે
મેળ ખાતી પ્રીબિલ્ટ બાઇનરી હોય ત્યારે તે તેનો ઉપયોગ કરે છે અને અન્યથા કોઈપણ બિલ્ડ ટૂલ્સની
જરૂર વિના પારદર્શક રીતે શુદ્ધ-JS એન્જિન (Node 22+ પર `node:sqlite`, અન્યથા બંડલ કરેલું
`sql.js` WASM) પર ફૉલબૅક કરે છે.

ઇન્સ્ટોલેશન પછીનું **નેટિવ વૉર્મ-અપ** સંપૂર્ણપણે છોડવા માટે (CI, હેડલેસ અથવા ધીમા મશીનો).
નોંધ: આ માત્ર નેટિવ SQLite વૉર્મ-અપ સ્ટેપ (`scripts/postinstall.mjs`) છોડે છે;
બાઇનરી-કૉપી/રિપેર હૂક (`scripts/build/postinstall.mjs`) હજી પણ સામાન્ય રીતે ચાલે છે:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 પણ તેને છોડે છે
```

સૌથી ઝડપી ઇન્સ્ટોલેશન માટે **pnpm**ને પ્રાધાન્ય આપો (કન્ટેન્ટ-એડ્રેસ્ડ સ્ટોર + હાર્ડ લિંક્સ — ઉપર જુઓ).
ડૅશબોર્ડ-રહિત, હેડલેસ રનટાઇમ માટે Docker `base` પ્રોફાઇલ (ઉપર) અથવા
[Termux માર્ગદર્શિકા](docs/guides/TERMUX_GUIDE.md)નો ઉપયોગ કરો. CLI અને વેબ ડૅશબોર્ડ એક જ પોર્ટ પર
સમાન પ્રોસેસ દ્વારા સર્વ થાય છે, તેથી હાલમાં અલગ CLI-માત્ર પૅકેજ નથી.

### યોગદાન કેવી રીતે આપવું

1. repository fork કરો
2. **active** `release/vX.Y.Z` tip પરથી branch બનાવો (`main` પરથી નહીં) — [Branching & Release Model](docs/ops/BRANCHING_MODEL.md) જુઓ
3. તમારી feature branch બનાવો (`git checkout -b feat/amazing-feature`)
4. તમારા ફેરફારો commit કરો (`git commit -m 'feat: add amazing feature'`)
5. branch પર push કરો (`git push origin feat/amazing-feature`)
6. **base = તે `release/vX.Y.Z` branch** સાથે Pull Request ખોલો

વિગતવાર માર્ગદર્શિકા માટે [CONTRIBUTING.md](CONTRIBUTING.md) જુઓ.
