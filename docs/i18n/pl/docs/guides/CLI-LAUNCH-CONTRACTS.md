Neutralny kontrakt `config/cli-tools-manifest.json` deklaruje kanoniczny IDs, aliasy, kandydatów binarnych, przepisy konfiguracyjne, argumenty modelu i możliwości. Zwykły adapter Node w `bin/cli/cli-manifest.mjs` i adapter TypeScript w `src/shared/constants/cliIntegrationManifest.ts` odczytują ten sam plik. Środowisko wykonawcze, katalog, konfiguracja, zakończenie, generatory i rejestracja zaplecza są sprawdzane wspólnie przez `tests/unit/cli/cli-manifest-drift.test.ts`. Bycie skatalogowanym nie oznacza, że narzędzie można uruchomić lub skonfigurować. W szczególności 5dive pozostaje tylko do konfiguracji.

## Środowisko i cykl życia dziecka

`omniroute run`, `omniroute launch` i `omniroute launch-codex` dziedziczą listę dozwolonych zgodności OS/terminal i wstrzykują poświadczenia wybranego celu. Niepowiązane klucze tajne dostawcy i bazy danych nie są domyślnie dziedziczone. `--inherit-env` jawnie przywraca pełne dziedziczenie środowiska nadrzędnego; używaj go tylko wtedy, gdy wybrany proces strony trzeciej powinien otrzymać te wartości. To jest filtrowanie środowiska, a nie piaskownica OS : proces nadal działa z uprawnieniami systemu plików wywołującego.

Sygnały przerwania i zakończenia są przekazywane do dziecka. Program uruchamiający czeka na zdarzenie zamknięcia elementu podrzędnego przed usunięciem tymczasowej konfiguracji. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` kontroluje okres karencji przed wymuszonym zakończeniem (domyślnie 5000 milisekund).

## Gemini trwała konfiguracja

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

Pierwsze dwa polecenia konfigurują tę maszynę dla wybranego serwera lokalnego lub zdalnego. Instalator zachowuje niepowiązane ustawienia JSON, wybiera uwierzytelnianie klucza API Gemini i zapisuje punkt końcowy i poświadczenia w prywatnym pliku `.gemini/.env`. Zamiast go nadpisywać, odrzuca nieprawidłowy JSON. Punkt końcowy URLs musi być HTTP(S), bez osadzonych poświadczeń, parametrów zapytania ani fragmentów. Próbne uruchomienie drukuje ścieżki, a nie wartości poświadczeń.

`GEMINI_CLI_HOME` lub `--gemini-home` wybiera trwały katalog główny. Rzeczywisty `run gemini` tworzy, a później usuwa swój własny tymczasowy dom. Żaden tryb nie omija kontroli zaufania obszaru roboczego Gemini.

## profile Codex

`configure codex` zapisuje prywatny `<name>.config.toml` z modelem i punktem końcowym dostawcy OmniRoute. Do poświadczeń odwołuje się poprzez `OMNIROUTE_API_KEY`, nigdy nie są one osadzane. Polecenie uruchomienia ustawia wybrany model na kluczu `model` najwyższego poziomu, a nie wewnątrz `model_providers`.

Oddzielne pliki profili stanowią aktualną udokumentowaną umowę Codex ; nakładają się na konfigurację użytkownika, gdy zostaną wybrane za pomocą `codex --profile <name>`. Zobacz [oficjalne informacje o profilu](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) i [przewodnik OmniRoute Codex](./CODEX-CLI-CONFIGURATION.md).

## Hermetyczne wykonywanie poleceń

W przypadku jawnego `DATA_DIR` ustawienie `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` zapobiega przedostawaniu się uruchamiania do domyślnego środowiska danych uwierzytelniających katalogu danych użytkownika. Jest to przydatne w przypadku izolowanych testów. Nie wyłącza innych jawnie wybranych plików środowiska.

## Katalog roboczy `.env`

CLI czyta pliki `.env` w tej kolejności i wygrywa pierwszy plik, który ustawi klucz: jawny `DATA_DIR`, domyślny katalog danych, bieżący katalog roboczy, a następnie katalog pakietów. Zmienne powłoki zawsze wygrywają.

Katalog roboczy może należeć do kogoś innego (sklonowane repozytorium, rozpakowane archiwum), a `omniroute serve` przekazuje środowisko CLI na serwer i do każdego narzędzia, na którym serwer działa. Zatem `.env` może ustawić tylko te klucze wymienione w `bin/cli/utils/untrustedCwdEnv.mjs`:

| Klawisz                         | Akceptowane wartości                                                                         |
| ------------------------------- | -------------------------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | w każdym przypadku `true`, `1` lub `yes` są to wartości, które serwer traktuje jako włączone |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | do 64 liter, cyfr, `_`, `.`, `@` lub `-`                                                     |
| `LANGUAGE`                      | to samo, plus `:`                                                                            |
| `TZ`                            | do 64 liter, cyfr, `_`, `+`, `-` lub `/`, nie zaczynając od `/`                              |
| `NO_COLOR`, `FORCE_COLOR`       | maksymalnie 16 liter i cyfr                                                                  |

Każda wartość akceptowana `REQUIRE_API_KEY` włącza sprawdzanie, więc plik nie może sam wyłączyć zaznaczenia. Nie decyduje to jednak o wyniku: serwer odczytuje przesłonięcie `REQUIRE_API_KEY` zapisane w bazie danych przed środowiskiem, podczas gdy ostrzeżenie startowe o nasłuchiwaniu na wszystkich interfejsach bez klucza API odczytuje tylko środowisko. Po zapisanym zastąpieniu `false` katalog roboczy `REQUIRE_API_KEY=true` pozostawia API otwarty i ukrywa to ostrzeżenie. Reguła `TZ` jest węższa niż POSIX: odrzuca `.`, `:`, `,` i `<>`, więc forma `:Area/City` i reguły takie jak `EST5EDT,M3.2.0,M11.1.0` muszą być ustawione w powłoce lub w `<DATA_DIR>/.env`.

Nazwy muszą być dokładnie takie same, pisane wielkimi literami. Każda inna linia, wartość, która nie przeszła kontroli oraz nazwa, która nie jest zwykłymi literami, cyframi i `_` ASCII (na przykład z bajtem NUL lub literą wyglądającą) są pomijane. CLI wypisuje jedno ostrzeżenie z nazwami kluczy, których nie może ustawić, i jedno z nazwami dozwolonych kluczy, które jest ignorowane, każde z informacją, co należy zmienić (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Żadne z nich nie drukuje wartości. Ścieżki plików w tych komunikatach i raportach `.env` path `omniroute doctor` są oznaczone zmianą znaczenia, jeśli zawierają znaki kontrolne lub bidi. Ograniczenie nie ma zastosowania, gdy katalogiem roboczym jest katalog danych lub katalog pakietów.

`PORT`, `API_PORT` i `DASHBOARD_PORT` nie znajdują się na liście. Bez podstawowego URL ze źródła o wyższym priorytecie, CLI komunikuje się z `localhost:<PORT>`, a cokolwiek tam nasłuchuje, otrzymuje klucz API CLI, token kontekstu i token maszyny CLI (`x-omniroute-cli-token`, zobacz [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), które lokalny serwer akceptuje dla wywołań zarządzających z pętli zwrotnej. Port z katalogu roboczego pozwoliłby temu plikowi wybrać słuchacza, więc ustaw porty w powłoce, w `<DATA_DIR>/.env` lub za pomocą opcji `--port` poleceń, które je posiadają (`serve`, `launch`, `run`).

Parser nie ma składni `export`. Linia taka jak `export LD_PRELOAD=...` nazywa zmienną `export LD_PRELOAD`; z katalogu roboczego jest pomijany, a w innych plikach `.env` ustawia tę dosłowną nazwę, której nic nie czyta.

CLI łączy token przechowywany w kontekście (token dostępu lub starszy klucz API ) tylko z własnym pochodzeniem tego kontekstu: schematem, hostem i portem, w porównaniu z `URL.origin`. Dotyczy to żądań wysyłanych przez klienta HTTP CLI(`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) oraz poleceń `launch`, `launch codex`, `configure` i `setup-*`, które zapisują podstawowy URL i klucz do konfiguracji innego narzędzia. Wskazane na inny serwer za pomocą `--remote`, używają jawnego `--api-key` lub `OMNIROUTE_API_KEY` jeśli taki jest ustawiony, i bez tokena kontekstu. Porównanie jest dokładne, więc `localhost` i `127.0.0.1` lub host z kropką na końcu i bez niej liczą się jako różne serwery i nie otrzymują tokenu kontekstu. URL z informacjami o użytkowniku, ukośnikiem odwrotnym lub białymi znakami nigdy nie pasuje, ponieważ inne parsery URL (na przykład `urllib` i `httpx` w Pythonie) mogą odczytać z niego innego hosta. W przypadku żądań CLI wysyła sam siebie, sprawdzenie to obejmuje tylko schemat i uprawnienia, więc identyfikator ze spacją w ścieżce lub zapytaniu zachowuje token.
