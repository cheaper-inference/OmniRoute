# Claude Code CLI — konfiguracja z OmniRoute

Skieruj CLI **Claude Code** (`claude`) na OmniRoute — lokalnie lub na zdalny VPS —
z profilami per model, na wzór konfiguracji Codex.

---

## Szybki start

```bash
# Uruchom Claude Code z lokalnym OmniRoute (automatycznie wykrywa aktywny kontekst)
omniroute launch

# Z użyciem zdalnego OmniRoute (po wykonaniu `omniroute connect <host>` odbywa się to automatycznie)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Wygeneruj profile dla poszczególnych modeli, a następnie uruchom jeden z nich
omniroute setup-claude            # zapisuje ~/.claude/profiles/<name>/settings.json
omniroute launch --profile glm52  # Claude Code korzystający z glm/glm-5.2 za pośrednictwem OmniRoute
```

---

## Jak Claude Code łączy się z bramką

Claude Code korzysta z **Anthropic Messages API** i wskazuje niestandardowy
endpoint przez zmienne środowiskowe (nie ma flagi `--base-url`):

| Zmienna                                      | Przeznaczenie                                                                              |
| -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `ANTHROPIC_BASE_URL`                         | Główny URL bramki (Claude Code dopina `/v1/messages`). **Bez sufiksu `/v1`.**              |
| `ANTHROPIC_AUTH_TOKEN`                       | Wysyłany jako `Authorization: Bearer …` — użyj tokenu dostępu / klucza API OmniRoute       |
| `ANTHROPIC_API_KEY`                          | Alternatywa: wysyłany jako `x-api-key`. Gdy ustawione obie, wygrywa `ANTHROPIC_AUTH_TOKEN` |
| `ANTHROPIC_MODEL`                            | Wymusza konkretny model (nadpisuje domyślny wybór z pickera `/model`)                      |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → natywny picker `/model` listuje modele `claude*`/`anthropic*` z `/v1/models`         |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | Limit tokenów wyjściowych na odpowiedź (np. `65536`)                                       |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | Próg tokenów dla auto-kompaktowania                                                        |

> Zmienne środowiskowe są odczytywane **raz przy starcie** — po zmianie zrestartuj Claude Code.

`omniroute launch` ustawia to wszystko za Ciebie: rozwiązuje bazowy URL + token
z aktywnego kontekstu (więc `omniroute connect <vps>`, a potem `omniroute launch`
po prostu działa), sprawdza zdrowie serwera i execuje `claude`.

---

## Aliasy wykrywania — pokazywanie modeli innych niż Claude w selektorze `/model`

Wykrywanie modeli bramy w Claude Code wyświetla tylko identyfikatory zaczynające się od `claude` lub `anthropic`, więc przy ustawieniu `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` natywny selektor `/model` pokazuje zazwyczaj **tylko** modele Claude/Anthropic z OmniRoute — `kimi/kimi-k2.6` czy `glm/glm-5.2` nigdy się w nim nie pojawią, mimo że routing do nich działa bez problemu.

OmniRoute może odwzorować dowolny włączony model (oraz combo) pod identyfikatorem `claude/…`, dzięki czemu przechodzi on przez ten filtr i pojawia się w selektorze:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

Gdy wybierzesz jeden z nich w Claude Code, OmniRoute zdejmuje otoczkę `claude/`, przywracając przed routingiem właściwy identyfikator — autentyczny identyfikator `claude/<real-claude-model>` (rzeczywisty dostawca Claude OAuth) zawsze pozostaje nietknięty.

Domyślnie odwzorowywane są tylko podstawowe identyfikatory. Po włączeniu opcjonalnej flagi funkcji `CATALOG_MIRROR_REFINEMENTS_ENABLED` warianty poziomu nakładu rozumowania (reasoning effort), które katalog już zawiera (np. `codex/gpt-6-sol-high`), są odwzorowywane jak każdy inny identyfikator, dzięki czemu Claude Code może jawnie wybrać poziom nakładu, a wbudowane identyfikatory `auto/*`, których ścieżka żądania nie potrafi zmaterializować, nie są odwzorowywane. To, czy warianty nakładu są w ogóle wyświetlane, nadal reguluje `OMNIROUTE_DISABLE_THINKING_LEVEL_VARIANTS` — mechanizm odwzorowania nigdy nie dodaje wariantu, którego nie ma w katalogu podstawowym.

**Ta funkcja jest domyślnie wyłączona** i sterowana trójpoziomową bramką (najbardziej szczegółowy poziom ma pierwszeństwo), więc zwykła instalacja OmniRoute nigdy nie podwaja katalogu dla klientów, którzy nie korzystają z Claude Code:

| Poziom   | Gdzie                                                                                          |
| -------- | ---------------------------------------------------------------------------------------------- |
| Model    | Strona szczegółów dostawcy → przełącznik „Expose in Claude Code” dla danego modelu             |
| Dostawca | Strona szczegółów dostawcy → przełącznik na poziomie dostawcy (obejmuje wszystkie jego modele) |
| Globalny | Ustawienia → Feature Flags → `EXPOSE_CC_DISCOVERY_ALIASES` (domyślnie wyłączona)               |

Zmienna środowiskowa `EXPOSE_CC_DISCOVERY_ALIASES` wymusza włączenie poziomu globalnego i ma pierwszeństwo przed nadpisaniem z panelu (ekran Feature Flags pokazuje wówczas notatkę „active via environment variable”). Przełączniki na poziomie dostawcy i modelu precyzują ustawienia dalej — np. globalnie wyłączone + dostawca Kimi włączony udostępnia tylko modele Kimi.

> ⚠️ **Niezgodność okna kontekstu w modelach innych niż Claude.** Claude Code zakłada okno kontekstu 200K dla każdego identyfikatora, którego nie rozpoznaje (nie potrafi odczytać rzeczywistego okna z `/v1/models`). W przypadku modelu z większym oknem (np. 256K w Kimi K2) ustaw `CLAUDE_CODE_AUTO_COMPACT_WINDOW` na wartość poniżej rzeczywistego okna modelu, aby automatyczna kompaktyzacja nie uruchamiała się przedwcześnie. Wygenerowane powyżej profile robią to już dla każdego modelu.

## Blok wdrożeniowy na pulpicie

Karta narzędzia Claude (**Pulpit → Kod CLI**) wyświetla dokładny fragment pliku `settings.json`
dla tej instancji, obok przycisku informacji o aliasie wykrywania, wraz z przyciskiem kopiowania:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<Twój OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<Twój klucz API OmniRoute>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

Bazowy adres URL jest adresem ustalonym przez kartę (z uwzględnieniem wprowadzonego niestandardowego nadpisania) i jest już
znormalizowany — bez sufiksu `/v1` ani końcowego ukośnika. **Klucz nigdy nie jest wyświetlany**: blok zawiera
symbol zastępczy, dzięki czemu zrzut ekranu ani wklejony fragment nie ujawnią klucza. Zastąp go swoim kluczem.

Dodaj `CLAUDE_CODE_AUTO_COMPACT_WINDOW` w tym samym bloku `env` dla każdego modelu, którego rzeczywiste
okno kontekstu nie wynosi 200K — Claude Code zakłada wartość 200K dla każdego nierozpoznanego identyfikatora, przez co
automatyczna kompakcja jest w przeciwnym razie uruchamiana w niewłaściwym momencie (zobacz ostrzeżenie w poprzedniej sekcji).
Generator fragmentu również przyjmuje tę wartość, więc kod wywołujący, który zna rozmiar okna modelu docelowego,
może przekazać ją bezpośrednio.

Źródło: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (czysty
generator, objęty testami jednostkowymi), renderowany przez `ClaudeGatewayOnboardingBlock`.

### Przypnij jedno konto (opcjonalnie)

Aby wysyłać każde żądanie Claude Code przez jedno konkretne konto dostawcy, dodaj nagłówek
`x-omniroute-connection` za pośrednictwem `ANTHROPIC_CUSTOM_HEADERS` w tym samym bloku `env`:

```jsonc
"ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>"
```

Skopiuj identyfikator z etykiety `xxxxxxxx…` w wierszu połączenia na stronie dostawcy. Przypięcie
dotyczy tylko identyfikatorów pojedynczych modeli (`provider/model`), a nie kombinacji. Dokładne
zachowanie mechanizmu rezerwowego opisano w sekcji [Przypinanie konta dla każdego żądania](../reference/API_REFERENCE.md#account-pinning-per-request).

## Profile (`CLAUDE_CONFIG_DIR`)

Claude Code **nie ma natywnych plików profili** (w przeciwieństwie do `~/.codex/<name>.config.toml` w Codex).
Standardowym mechanizmem jest `CLAUDE_CONFIG_DIR` — osobny katalog konfiguracji dla każdego
profilu, każdy z własnymi ustawieniami `settings.json`, poświadczeniami, historią i pamięcią podręczną.

`omniroute setup-claude` pobiera aktualny katalog `/v1/models` i zapisuje po jednym
profilu dla każdego modelu w `~/.claude/profiles/<name>/settings.json`, używając
**tych samych nazw co `setup-codex`** (`glm52`, `kimi-k27`, `deepseek-pro`, …):

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **Token uwierzytelniający nigdy nie jest zapisywany w profilu.** Uruchom za pomocą
> `omniroute launch --profile <name>` (polecenie wstrzykuje `ANTHROPIC_AUTH_TOKEN` z
> aktywnego kontekstu) albo samodzielnie wyeksportuj `ANTHROPIC_AUTH_TOKEN` i uruchom
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`.

**Automatyczna synchronizacja po wykryciu modeli (opcjonalna).** OmniRoute może automatycznie ponownie generować te same
pliki `~/.claude/profiles/<name>/settings.json` za każdym razem, gdy synchronizacja modeli dostawcy
zmieni aktualny katalog — dzięki temu nowe modele lub modele o zmienionych nazwach otrzymają profile bez ponownego uruchamiania
polecenia. Funkcja jest **domyślnie wyłączona**: włącz ją w **panelu CLI Code** („Automatyczna
synchronizacja profili CLI” → Claude Code) albo ustaw `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` (uwzględnia również
`CLI_ALLOW_CONFIG_WRITES`, które jest domyślnie włączone). Po włączeniu funkcja zapisuje wyłącznie pliki profili; nigdy nie
zmienia aktywnej/domyślnej konfiguracji Claude, danych uwierzytelniających ani pliku `~/.claude/settings.json`.

### Generowanie i używanie profili

```bash
# Lokalny OmniRoute
omniroute setup-claude

# Zdalny VPS (osadza adres URL serwera VPS w każdym profilu)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Tylko niektórzy dostawcy
omniroute setup-claude --only glm,kimi

# Zapisz również profile dla lokalnych dostawców CLI (zcode, auggie, devin-cli-agentic,
# codex-app-server), których nie wykryto na tym hoście (domyślnie pomijane dla celu lokalnego)
omniroute setup-claude --include-local

# Podgląd bez zapisywania
omniroute setup-claude --dry-run

# Uruchom profil
omniroute launch --profile kimi-k27
```

## Poziomy modeli (opcjonalne)

Claude Code routuje do poziomów możliwości. Zmapuj każdy na model OmniRoute przez env /
ustawienia, jeśli chcesz innych providerów per poziom:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

W przeciwnym razie pojedynczy `ANTHROPIC_MODEL` (to, co ustawiają profile) jest używany do wszystkiego.

## Tryb zdalny

Po uruchomieniu `omniroute connect <host>` (zobacz
[Tryb zdalny](./REMOTE-MODE.md)), `omniroute launch` i `omniroute setup-claude`
automatycznie celują w ten zdalny serwer i używają jego scoped access token —
bez dodatkowych flag. Nadpisz per wywołanie przez `--remote` / `--api-key`.

## Rozwiązywanie problemów

**Claude Code ignoruje bramkę** — potwierdź, że `ANTHROPIC_BASE_URL` **nie ma
`/v1`**, i zrestartuj `claude` (env jest odczytywane raz przy starcie). `omniroute launch`
robi to za Ciebie.

**Picker `/model` jest pusty / brakuje modeli bramki** — wymaga Claude Code
v2.1.219+ oraz `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`. W pickerze pojawiają się tylko ID modeli
`claude*` / `anthropic*`; wymuś dowolny inny model przez
`ANTHROPIC_MODEL=<id>` (właśnie to robią profile).

**`400 Ambiguous model 'claude-…'`** — Claude Code zawsze wysyła **nieprefiksowane**
ID modeli (np. `claude-opus-4-8`), więc gdy podłączeni są zarówno provider Claude Code (`cc/…`), jak i
Claude (`claude/…`), gołe id pasuje do dwóch tras i
OmniRoute odmawia zgadywania. Napraw na jeden z dwóch sposobów: przypnij prefiksowane id przez
`ANTHROPIC_MODEL=cc/claude-opus-4-8` albo włącz **Prefer Claude Code for
unprefixed Claude models** — przełącznik na stronie providera Claude albo
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (domyślnie wyłączone;
zobacz [Environment](../reference/ENVIRONMENT.md)) — wtedy gołe ID `claude-*`
idą do Claude Code. Jawne prefiksy providerów zawsze wygrywają.

**Błędy auth** — profil nie przechowuje tokenu. Użyj `omniroute launch --profile`
(wstrzykuje go) albo wyeksportuj `ANTHROPIC_AUTH_TOKEN`.

**Profile nie izolują** — każdy profil to osobny `CLAUDE_CONFIG_DIR`;
sprawdź, że `echo $CLAUDE_CONFIG_DIR` w sesji wskazuje na
`~/.claude/profiles/<name>`.
