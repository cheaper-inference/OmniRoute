`devin-cli-agentic` umożliwia rzeczywistemu środowisku wykonawczemu Claude Code korzystanie z lokalnego
punktu końcowego Anthropic Messages w OmniRoute, podczas gdy oficjalne narzędzie Devin CLI dostarcza
odpowiedzi modelu przez ACP stdio. Nie modyfikuje ono istniejących dostawców Anthropic,
Claude OAuth, Claude Web ani `devin-cli`.

W przypadku wywołań narzędzi obsługiwanych przez klienta należy kierować żądania przez
`devin-cli-agentic` (alias `dva`), obsługującego narzędzia dostawcę w formacie Claude.
Starszy wykonawca ACP `devin-cli` (`dv`) obsługuje wyłącznie tekst: uruchamia mechanizm
podsumowujący Devin bez narzędzi i nie może zwracać wywołań narzędzi. Jego metadane modelu
są odpowiednio oznaczone, dzięki czemu routing kombinowany wymagający narzędzi będzie go pomijać.

> **Bieżący stan: przypięta wersja Claude Code `2.1.258`; ostatnia zarejestrowana walidacja
> offline i na żywo dotyczy wersji `2.1.220`.** Dla przypiętej wersji `2.1.220` ukończono trzy
> odizolowane scenariusze z użyciem Devin CLI `3000.2.17` i modelu `swe-1-7-lightning`;
> ostatnie uruchomienie na żywo potwierdziło obsługiwane przez klienta operacje `Read`,
> `Edit` i `Bash`, pomyślne wyniki `npm test`, wykrywanie poleceń i umiejętności projektu,
> routing wyłącznie przez Devin oraz brak ruchu wychodzącego do Claude. Następnie przypiętą
> wersję podniesiono do `2.1.258` (generacji CLI, pod którą podszywa się tożsamość Claude
> w OmniRoute, i pierwszej wersji natywnie dostarczającej poziom Fable 5.1). Dla nowej
> przypiętej wersji zweryfikowano warstwę instalacyjną i `claude --version` na przypiętym
> obrazie bazowym, a zestaw testów jednostkowych mostu, `compose config` i statyczny dowód
> izolacji przechodzą pomyślnie — jednak scenariusz z makietą offline oraz zestaw trzech
> scenariuszy na żywo nie zostały jeszcze uruchomione ponownie. Przed rozpoczęciem korzystania
> z mostu z tą przypiętą wersją należy uruchomić je ponownie (patrz „Aktualizowanie przypiętych narzędzi”).

## Architektura

```text
Claude Code 2.1.258 (odizolowany kontener Linux bez uprawnień roota)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (dostawca w formacie Claude, bez uwierzytelniania)
  -> devin acp --agent-type summarizer (oficjalne ACP stdio, bez narzędzi Devin)
  -> konto Devin w dedykowanym woluminie devin-auth
```

Domyślny agent ACP oficjalnego CLI może wykonywać własne narzędzia, dlatego ten most go nie
używa. Uruchamia on stałego agenta ACP `summarizer`, którego oficjalny tryb CLI nie ma
narzędzi, i ujmuje zserializowane żądanie Anthropic w ramy śladu wykonania. Gdy potrzebna
jest kolejna akcja obsługiwana przez Claude, odpowiedź musi zawierać dokładnie jedną
kopertę narzędzia klienta. Każde `tool_call` lub `tool_call_update` ACP jest odrzucane,
zanim odpowiedź będzie mogła zostać zgłoszona jako pomyślna.

Serializator w `open-sse/executors/devin-agentic/serializer.ts` zachowuje `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` oraz
narzędzia przekazane przez Claude Code. Obrazy i nieznane bloki powodują jawny błąd. Duże
wyniki narzędzi otrzymują widoczny znacznik obcięcia.

Parser akceptuje jedną samodzielną kopertę `<tool>{...}</tool>` na każdą turę modelu.
Sprawdza nazwę względem listy narzędzi z żądania, waliduje argumenty na podstawie schematu
JSON danego narzędzia, odrzuca połączenie narracji z akcjami i zezwala na jedną ograniczoną
próbę naprawy. Następnie Claude Code wykonuje lokalnie wynikowe `tool_use` Anthropic
i odsyła `tool_result` przez OmniRoute.

## Automatyczny routing

Dostawca kwalifikuje się do pul kandydatów `auto/*` w OmniRoute, o ile nie jest zablokowany.
Kwalifikacja kandydata nie gwarantuje jego wyboru: strategia routingu kombinacji (na przykład
ostatnia znana dobra konfiguracja) może preferować innego dostawcę. Użyj `dva/<model>` lub
kombinacji preferującej Devin, jeśli każde żądanie ma być kierowane przez Devin.

## Izolacja i model zagrożeń

Instalacja, konto i konfiguracja Claude na hoście pozostają poza zakresem i są traktowane jako
niedozwolone. Usługi Compose:

- działają jako UID/GID `10001:10001`, z głównym systemem plików tylko do odczytu, usuniętymi uprawnieniami i
  opcją `no-new-privileges`;
- używają prywatnego katalogu `/home/bridge`, dedykowanego woluminu konfiguracji Claude, odizolowanych danych OmniRoute
  oraz oddzielnego woluminu `devin-auth`;
- montują wyłącznie jednorazowe obszary robocze i dowody `.sandbox`;
- nie montują katalogu domowego hosta, Keychain, poświadczeń SSH ani chmurowych, ani gniazda Docker;
- tworzą jawnie zdefiniowane środowiska i usuwają zmienne API/OAuth/routingu Anthropic;
- kierują wnioskowanie Claude Code wyłącznie do `http://omniroute:20128` przy użyciu klucza dostępnego tylko lokalnie.

Profil offline korzysta z sieci wewnętrznej. W profilu aktywnym OmniRoute uzyskuje dostęp do
oficjalnych punktów końcowych Devin wyłącznie za pośrednictwem `network-guard`; dostęp do niepowiązanych miejsc docelowych jest blokowany.
Claude Code ma oddzielną blokadę całego ruchu wychodzącego i może łączyć się wyłącznie z lokalną usługą OmniRoute
za pośrednictwem `NO_PROXY`. Pliki audytu blokad są montowane wyłącznie przez odpowiedni proces blokady.
Skrypty sprawdzają właściciela pliku, tryb, liczbę dowiązań oraz każdą decyzję przed wyeksportowaniem
dowodów niezawierających tokenów.

Uruchom niezależnie weryfikację izolacji:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Weryfikuje ona topologię, nazwane punkty montowania, ustawienia użytkownika innego niż root i trybu tylko do odczytu, jawny routing lokalny,
brak poufnych zmiennych środowiskowych, brak gniazda Docker, zablokowany dostęp do
`api.anthropic.com` i `claude.ai`, wybór wyłącznie dostawcy Devin oraz jawny błąd, gdy
backend ACP jest niedostępny.

## Pierwsza konfiguracja i normalne użytkowanie

Zbuduj przypięty obraz:

```bash
./scripts/devin-bridge/build
```

Uwierzytelnij wyłącznie odizolowany wolumin Devin:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Polecenie logowania korzysta z oficjalnego przepływu ręcznego wprowadzania tokena przeznaczonego dla środowisk
zdalnych/kontenerowych. Wartość jest wprowadzana bezpośrednio w monicie CLI; nie jest przekazywana jako
argument procesu, zapisywana w Git ani kopiowana z hosta.

Uruchom odizolowane środowisko wykonawcze Claude Code:

```bash
./scripts/devin-bridge/launch
```

`launch` ponownie sprawdza izolację, uwierzytelnienie Devin i wykrywanie modeli przed uruchomieniem
Claude Code w kontenerze. Nigdy nie uruchamia pliku wykonywalnego Claude z hosta. Aliasy modeli można
ustawić w `.env.devin-bridge`; każda skonfigurowana wartość musi zachowywać
prefiks `devin-cli-agentic/`.

## Polecenia walidacyjne

Odtwarzalna ścieżka offline nie wymaga konta Devin i nie korzysta podczas działania z Internetu:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Opcjonalna, uwierzytelniona ścieżka aktywna to:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Moduł uruchamiający testy aktywne czeka między scenariuszami, aby uniknąć otwierania wielu sesji ACP naraz, i
weryfikuje ustrukturyzowane zdarzenia strumienia Claude zamiast ufać deklaracjom tekstowym. Jego trzy
scenariusze potwierdzają:

1. bezpośredni odczyt projektu i analizę defektów;
2. rzeczywistą operację `Edit`, należące do klienta polecenie `Bash` `npm test` oraz wynik końcowy;
3. wykrywanie `/bridge-check` i `bridge-proof`, odczyt projektu, kolejny zakończony powodzeniem
   test `npm test` należący do klienta oraz ukończenie bez oczekujących zadań.

Końcowa bramka sprawdza również audyt sieci Devin i wymaga, aby audyt ruchu wychodzącego Claude
pozostał pusty.

## Aktualizowanie przypiętych narzędzi

Obraz przypina wersje Node, Claude Code i Devin CLI w pliku
`docker/devin-bridge/Dockerfile`. Aby je zaktualizować:

1. zmień jawnie określone wersje;
2. zastąp sumy kontrolne archiwów Devin dla obu architektur wartościami odpowiadającymi oficjalnemu
   artefaktowi;
3. ponownie zbuduj obraz i uruchom każde polecenie walidacji offline;
4. potwierdź wersje wewnątrz obrazu;
5. ponownie uruchom uwierzytelniony zestaw testów na żywo obejmujący trzy scenariusze.

Nie instaluj żadnego z tych CLI globalnie na hoście ani nie zastępuj weryfikacji sum kontrolnych
niezweryfikowanym pobieraniem.

## Diagnostyka i czyszczenie

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  wyświetla lokalne trasowanie i oczyszczone błędy modułu wykonawczego.
- `.sandbox/evidence/mock-acp.jsonl` rejestruje deterministyczne działania pozorowanego ACP.
- `.sandbox/evidence/claude-stream.jsonl` rejestruje rzeczywiste uruchomienie Claude Code w trybie offline.
- `.sandbox/evidence/live-*.jsonl` rejestruje trzy zweryfikowane strumienie na żywo.
- `.sandbox/evidence/egress.jsonl` i `.sandbox/evidence/claude-egress.jsonl` to zweryfikowane,
  pozbawione tokenów kopie audytów ochrony ruchu wychodzącego.

Zatrzymaj kontenery i sieci należące do mostu, zachowując woluminy logowania/konfiguracji:

```bash
./scripts/devin-bridge/clean
```

Usuń całe środowisko należące do mostu, w tym nazwane woluminy:

```bash
./scripts/devin-bridge/clean --all
```

## Ograniczenia

- Most korzysta ze stałej roli `summarizer` bez narzędzi, ponieważ Devin CLI `3000.2.17`
  nie udostępnia neutralnego agenta ACP bez narzędzi. Adapter kompensuje pośrednie odpowiedzi
  mające formę podsumowania, ale jedna ograniczona próba naprawy nadal może jawnie zakończyć się niepowodzeniem.
- Wywołania ACP na żywo mogą zwracać przejściowe odpowiedzi `502`/`504`. Mechanizm testowy zachowuje
  odstępy między scenariuszami; trwałe niepowodzenie nadal powoduje bezpieczne przerwanie i nigdy nie wybiera innego dostawcy.
- Kontekst ACP jest rekonstruowany na podstawie każdego żądania Anthropic; nie ma powiązania
  z procesem ani sesją.
- Obsługiwane jest jedno wywołanie narzędzia na odpowiedź modelu; wywołania równoległe są odrzucane.
- Obrazy nie są jawnie obsługiwane. Funkcje wizyjne, dane wyjściowe procesu rozumowania, ustawienia wysiłku oraz okno kontekstu 1M
  nie są deklarowane jako dostępne.
- SSE używa prawidłowych zdarzeń cyklu życia Anthropic, ale są one emitowane po zebraniu ograniczonej tury ACP;
  fragmenty ACP nie są przekazywane przyrostowo.
