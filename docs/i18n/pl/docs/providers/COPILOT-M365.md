`copilot-m365-web` (alias `m365copilot`) wysyła żądania czatu w formacie OpenAI poprzez uwierzytelnioną sesję Microsoft 365 Copilot w `m365.cloud.microsoft/chat`. Jest to nieoficjalna integracja natywna: nie jest wymagany żaden oddzielny proces proxy ani serwer nadrzędny lokalnego hosta. Dostawca ID, alias i istniejące importowane połączenia pozostają niezmienione. `copilot-web` jest innym dostawcą usług konsumenckich w `copilot.microsoft.com`.

> **Jesteś nowy wśród dostawców internetowych plików cookie?**
>
> Czytać**`docs/getting-started/WEB-COOKIE-GUIDE.md`** aby zapoznać się z ogólnym procesem konfiguracji, wskazówkami dotyczącymi uwierzytelniania, ograniczeniami i rozwiązywaniem problemów, zanim zastosujesz się do tego przewodnika dla konkretnego dostawcy.
>
> **W przypadku starszego importu:** Poświadczenie tego dostawcy to** nie ciasteczko** . Nie kopiuj plików cookie z `m365.cloud.microsoft`. Poświadczenie to parametr zapytania WebSocket URL i segment ścieżki, oba odczytywane z karty Sieć DevTools.

## Warunki wstępne

- Konto Microsoft 365 z dostępem do Copilot w `m365.cloud.microsoft/chat`
- Przeglądarka oparta na Chromium (Chrome, Edge) do kontroli DevTools WebSocket
- Dostęp do żądanego modelu na tym koncie; dostępność różni się w zależności od najemcy i licencji

## Logowanie natywne (konta służbowe lub szkolne)

Wybierać**Microsoft 365 Copilot → Połącz** i przygotuj próbę logowania. Pulpit nawigacyjny wykorzystuje przepływ kodu autoryzacyjnego z PKCE; nie pyta o hasło do Microsoft ani kod MFA.

1. Otwórz** pusta karta przeglądarki** , a następnie otwórz**DevTools → Sieć** i włącz** Zachowaj dziennik** . Zrób to przed przejściem do Microsoft: Windows SSO może zakończyć się natychmiast.
2. Skopiuj URL autoryzacji pokazaną w oknie dialogowym połączenia i przejdź do niego w przygotowanej zakładce. Dokończ wybór konta Microsoft lub MFA jeśli jest to wymagane.
3. W zachowanym dzienniku sieci znajdź żądanie do `https://login.microsoftonline.com/common/oauth2/nativeclient` i skopiuj je w całości** Poproś o URL** .
4. Wklej ten URL do okna dialogowego połączenia i połącz się. Nie wklejaj surowego kodu ani końcowego paska adresu `wrongplace` URL: wymagane wywołanie zwrotne to tymczasowa nawigacja.

Każda próba wygasa po dziesięciu minutach i może zostać użyta tylko raz. Serwer sprawdza swój stan, weryfikator PKCE i cel ponownego uwierzytelnienia przed wymianą kodu. Po wygaśnięciu lub niepowodzeniu wymiany rozpocznij nową próbę. Próba nie może przetrwać ponownego uruchomienia serwera.

Tokeny korzystają z istniejącego magazynu poświadczeń połączenia i ścieżki odświeżania. Ponowne uwierzytelnienie połączenia wymaga tej samej tożsamości Microsoft tenant/object, a nie tylko tego samego adresu e-mail. Zachowuje operatora naming/settings i zastępuje przestarzałe zaimportowane poświadczenia. Logowanie natywne dotyczy kont work/school ; starsza ścieżka importu pozostaje dostępna dla istniejących połączeń i obsługiwanych konfiguracji warstw.

Pełne wywołanie zwrotne URL jest jednorazowym poświadczeniem. Nigdy nie dołączaj go do zrzutów ekranu, dzienników, wiadomości pomocy technicznej ani zatwierdzeń. Ten przepływ nie otwiera przeglądarki na serwerze, nie sprawdza historii przeglądarki ani nie uruchamia lokalnego serwera wywołania zwrotnego.

## Przechwytywanie danych uwierzytelniających (metoda WebSocket )

1. Zaloguj się na `https://m365.cloud.microsoft/chat` i rozpocznij rozmowę.
2. Otwarte**DevTools → Sieć** .
3. Filtruj według**WS** (WebSocket).
4. Kliknij połączenie Chathub WebSocket. Poszukaj URL zaczynającego się od `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Z jego** Poproś o URL** , skopiuj:
   - Wartość parametru zapytania `access_token` (krótkotrwała JWT).
   - Segment ścieżki Chathuba po `/Chathub/` (np. `<oid>@<tenant>`).

Pełna URL ma postać:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. W OmniRoute wybierz**Microsoft 365 Copilot** , wybierz starszą opcję API-key/import i wklej dane uwierzytelniające w formacie:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Trzask** Połączenie testowe** I** Ratować** .

## Przechwytywanie danych uwierzytelniających (import HAR )

Zamiast ręcznie kopiować wartości z WebSocket URL, możesz wyeksportować plik DevTools HAR :

1. Otwarte**DevTools → Sieć** .
2. Rozpocznij lub kontynuuj rozmowę Microsoft 365 Copilot (to wyzwala połączenie WebSocket ).
3. Kliknij prawym przyciskiem myszy panel Sieć i wybierz** Zapisz wszystko jako HAR z zawartością** .
4. W OmniRoute użyj** Zaimportuj plik .har** w oknie dialogowym połączenia z dostawcą.

OmniRoute skanuje HAR w poszukiwaniu Chathub WebSocket URL, wyodrębnia `access_token` i `chathubPath` i automatycznie wypełnia pola danych uwierzytelniających. Import HAR dekoduje wygaśnięcie JWT i pokazuje pozostały czas życia tokena.

> **Nigdy nie realizuj prawdziwego eksportu HAR, tokena dostępu ani tokena odświeżania.** Wartości testowe i dokumentacyjne muszą zawsze być symbolami zastępczymi.

## Czas życia i odświeżanie tokenu

`access_token` jest krótkotrwała (zwykle**~ 75 minut** ). Bez użytecznego tokena odświeżającego należy ponownie przechwycić dane uwierzytelniające po wygaśnięciu.

### Automatyczne odświeżanie za pomocą `refreshToken`

U dostawcy Microsoft 365** Dodaj połączenie** Lub** Edytuj połączenie** okno dialogowe, otwórz** Ustawienia zaawansowane → Odśwież token (opcjonalnie)** . Wklej token odświeżania Microsoft OAuth dla zakresu `substrate.office.com/sydney` i zapisz. Dane wejściowe są maskowane i nigdy nie są wstępnie wypełniane przechowywanym tokenem. Podczas edycji pozostaw to pole puste, aby zachować istniejący token; wklej nowy token, aby go zastąpić.

Natywne logowanie uzyskuje token odświeżania, gdy Microsoft go zwróci. W przypadku importów ze starszych wersji użyj istniejącego, kompatybilnego nadania kodu autoryzacyjnego Microsoft ; ten dostawca nie wdraża ani nie obiecuje przepływu kodu urządzenia. Po skonfigurowaniu tokena odświeżania OmniRoute sprawdza `access_token` przed żądaniami i odświeża go tylko wtedy, gdy wymaga odświeżenia. Pomyślne odświeżenie powoduje również utrwalenie obróconego tokena odświeżania, co pozwala uniknąć ręcznego ponownego przechwytywania, dopóki token odświeżania pozostaje ważny.

Jeśli `refreshToken` nie jest ustawione, po każdym wygaśnięciu należy ponownie przechwycić dane uwierzytelniające WebSocket ręcznie.

## Modele i routing

Natywny katalog zawiera wszystkie udokumentowane samodzielne IDs oraz cztery oryginalne natywne IDs. Katalog jest statyczny i niezależny od konta, a nie sonda uprawnień do konta: płatne trasy i aliasy zgodności pozostają na liście nawet wtedy, gdy połączone konto nie może z nich korzystać. W etykietach wyświetlanych modeli pominięto nazwę dostawcy i schemat dostępności poszczególnych modeli; dostawca pozostaje**Microsoft 365 Copilot** . Oznaczone etykiety** Alias** Lub** Dziedzictwo** zachowują swoje istniejące identyfikatory i mapowania protokołów, a nie gwarancję historycznej wersji modelu. Samodzielny serwer proxy** Importuj z /modele** instrukcje nie dotyczą tego natywnego dostawcy WebSocket.

| Rodzina modelowa  | Kanoniczne IDs                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| Automatyczny      | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| Wcześniej GPT     | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |

Rejestrowane są również aliasy, takie jak `auto`, `quick`, `think-deeper` i aliasy wersji. Istniejące `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` i `copilot-m365-gpt-5-5-chat` pozostają ważne. Udokumentowane IDs wymaga prefiksu dostawcy (`copilot-m365-web/claude-opus` lub `m365copilot/claude-opus`): wiele z nich to słowa ogólne lub nazwy modeli innych dostawców, więc sam `claude-opus` zachowuje routing tak samo, jak bez tego dostawcy. Rejestracja nie gwarantuje, że Microsoft będzie obsługiwał ten model dla każdego konta. Samodzielny IDs działa zgodnie z publicznym [katalogiem protokołów](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) (wyeksportowana mapa modelu do tonu i metadane scenariusza uwzględniającego model). Wszystkie profile natywne zachowują `availability: "unverified"`; umieszczenie w katalogu nie jest pomyślnym testem konta.

- Powraca wyraźna odmowa licencji na model** 403** `m365_model_not_licensed`, a nie 502. Routing blokuje tę parę connection/model, pozostawiając licencjonowane modele na połączeniu do użytku.
- `InvalidCopilotLicense` to odmowa licencji na poziomie konta, zgłaszana osobno jako `m365_account_not_licensed`.
- Powraca ograniczenie przepustowości dla poszczególnych użytkowników** 429** `m365_throttled` i schładza połączenie. Powraca wyczerpanie dostępu priorytetowego** 429** `priority_access_exhausted` i ma zasięg modelu. Wynik `OutOfCredits` ze zwrotami `errorCode: "ReasoningTurnExhausted"`** 429** zamiast tego `reasoning_turns_exhausted`, również o zasięgu modelu, bez deklarowanego czasu resetowania. Zgłoszono, że jeden z najemców pracy ograniczył tony „Myśl głębiej”, podczas gdy tony Szybkie nadal działały; ten zakres jest obserwacją konsumentów, a nie czymś, co odtworzyło to repozytorium. Dlatego też routing powoduje również wyłączenie rotacji innych udokumentowanych modeli `gpt-5.5` i `gpt-5.6` na tym połączeniu w celu uzyskania tego samego czasu odnowienia, a szybkie dźwięki i każdą inną awarię pozostawia w osobnym modelu. Dostarczone wskazówki dotyczące ponownej próby zostaną zachowane; brakujący reset nie jest ogłaszany jako znany czas resetowania.
- Powraca odmowa bezpieczeństwa Copilot (`Disengaged`).** 400** `provider_safety_rejection`, etykieta przystanku bezpieczeństwa udostępnionego dostawcy. To nigdy nie wlicza się do kondycji połączenia, klient SDKs nie próbuje ponownie wykonać 400, a przy włączonej funkcji `PROVIDER_SAFETY_STOPS_TERMINAL` routing combo zatrzymuje się tam, zamiast odtwarzać żądanie przeciwko innemu celowi.
- Żądania w ramach jednego połączenia są serializowane za pośrednictwem istniejącego semafora konta. Preferuj priorytetowe zastępowanie zamiast paneli równoległych; sama serializacja nie eliminuje limitów szybkości konwersacji Microsoft.

## Zapytaj o zachowanie i ograniczenia

- Narzędzia są** emulowany przez monit** , a nie natywne wywołania funkcji Microsoft. Żądanie z obsługą narzędzi wykorzystuje jedną generację buforowaną; nie spędza kolejnego pokolenia na wyborze narzędzi. Jako wywołania zwracane są tylko zadeklarowane narzędzia z prawidłowymi obsługiwanymi kształtami argumentów.
- Długa, ustrukturyzowana odpowiedź z jednym końcowym przykładem została zachowana w formie prozy. To jest heurystyka, a nie dowód zamiaru; aplikacje muszą nadal wymuszać własne uprawnienia narzędziowe.
- Wprowadzanie obrazu działa w sposób, w jaki wysyła go klient sieciowy. Każda część obrazu (`image_url` jako dane URL lub publiczne HTTPS URL lub Odpowiedzi `input_image`) jest przesyłana do `/m365Copilot/UploadFile` do konwersacji tury za pomocą tokena czatu, a wiadomość wskazuje na to z adnotacją `ImageFile` ; tekst wskazuje miejsce, w którym się znajdował (`[image 1]`,…). Nowa rozmowa przesyła wszystkie obrazy w historii, kontynuacja tylko obrazy nowych wiadomości. Do 10 obrazów PNG, JPEG, GIF lub WebP o wielkości maksymalnie 10 MiB każdy (40 MiB na żądanie); format jest odczytywany z bajtów. HTTPS URLs są pobierane przez publiczną, przypiętą do DNS, zdalną osłonę obrazu. Nieudane przesyłanie kończy się niepowodzeniem żądania (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` lub `m365_image_invalid`); zakręt nigdy nie przebiega bez obrazu, który został mu dany. Inne części nietekstowe (audio, pliki) są odrzucane jawnie, a nie dyskretnie odrzucane.
- Żądanie uzupełniające kontynuuje tę samą rozmowę nadrzędną i wysyła tylko wiadomości po poprzedniej odpowiedzi. Musi dokładnie rozszerzyć tę odpowiedź: to samo połączenie, profil modelu i zestaw narzędzi; niezmieniona historia (łańcuch sha256 nad każdą wiadomością); oraz identyfikatory wywołań narzędzi odpowiedzi lub jej tekst aż do białych znaków. Wszystko inne (edytowana historia, kolejna sesja z tą samą pierwszą wiadomością, inna odpowiedź, rozmowa bezczynna przez 30 minut lub bliska limitu 600 wiadomości Copilot, połączenie bez identyfikatora) rozpoczyna nową rozmowę z całą historią. Nieudana tura nigdy nie jest wznawiana, a `InternalError` bez zawartości jest wysyłane ponownie raz w nowej rozmowie (** 502** `m365_internal_error` jeśli ponownie się nie powiedzie). Kontynuacje są przechowywane w pamięci procesu: ponowne uruchomienie rozpoczyna nowe rozmowy.
- Każda tura odbywa się na tymczasowym czacie Copilot(`disableMemory=1`): rozmowa zachowuje swój kontekst podczas trwania i nigdy nie pojawia się w historii czatów konta. Testy modelowe, Testuj wszystko i testy kombi mogą zatem sondować tego dostawcę bez pozostawiania rozmów.
- Tura ma 120-sekundowy termin bezczynności i ograniczony ostateczny termin całkowity. Tylko ostateczne odpowiedzi, filtrowanie postępu i anulowanie są obsługiwane przez natywną transport/composer.
- Odpowiedzi oparte na Internecie zachowują swoje źródła. Copilot zaznacza cytat w linii ze znakami kontrolnymi do użytku prywatnego i wysyła źródła jako `references`; każdy znacznik staje się numerowanym łączem Markdown (`[1](https://…)` lub samym URL gdy Copilot użył znacznika jako celu łącza) z pasującą adnotacją `url_citation` (`message.annotations` lub `delta.annotations` na fragmencie niosącym łącze). Źródło, które nigdy nie dotrze, jest odrzucane, więc znaczniki nigdy nie docierają do klienta. Podczas przesyłania strumieniowego tekst po cytacie czeka na dotarcie źródła.
- Podsumowanie rozumowania Copilot(`ChainOfThoughtSummary`), gdy model je wysyła, jest zwracane jako `reasoning_content`, nigdy jako część odpowiedzi. Podsumowanie, które samo się zapisuje, zatrzymuje przesyłanie strumieniowe bez utraty tury.
- Przed jakąkolwiek treścią awarie licence/throttle zachowują HTTP 403/429 nawet wtedy, gdy zażądano przesyłania strumieniowego. Po rozpoczęciu zawartości awarie są zdarzeniami błędów SSE, a nigdy pomyślnym zakończeniem. Przepisanie w górę strumienia, którego nie można przedstawić za pomocą przesyłania strumieniowego z samym dopisywaniem, jest jawnym błędem strumienia; Niestrumieniowe i buforowane odpowiedzi narzędzi zachowują ostateczny tekst.
- Kiedy Copilot sama odmówi połączenia, odpowiedź jest zgłaszana w następującej postaci:** 401** `m365_unauthorized` w przypadku odrzuconego lub wygasłego logowania (zaloguj się ponownie),** 429** z `Retry-After` do dławienia i awarią uzgadniania w przeciwnym razie, nigdy nie jest to ogólna awaria połączenia.

## Generowanie obrazu

`POST /v1/images/generations` z `model: "copilot-m365-web/m365-copilot-image"` (alias `m365copilot/m365-copilot-image`) rysuje za pomocą wbudowanego narzędzia graficznego Copilot, tak jak robi to klient WWW. Każdy obraz to jeden obrót Copilot : wyraża zgodę z zestawami opcji obrazu klienta sieciowego i deklaruje `GenerateGraphicArt`, a obraz pojawia się we wpisie postępu wskazującym na artefakt w usłudze Designer Microsoft. Ten artefakt odrzuca token czatu, więc OmniRoute tworzy token Projektanta z tokena odświeżania połączenia i pobiera bajty; token jest zawsze wysyłany tylko do `designerapp.officeapps.live.com`.

- Wymaga natywnego połączenia logowania (token odświeżania); wklejony token kończy się niepowodzeniem** 400** zanim zakończy się jakakolwiek tura.
- `n` wynosi 1–4, po jednej turze na każdą. `size` steruje jedynie orientacją (szerszą, wyższą lub kwadratową), którą Copilot odczytuje z podpowiedzi; Copilot wybiera rozmiar renderowania.
- Obrazy są zwracane w formie inline: domyślnie `b64_json`, dane URL dla `response_format: "url"`.
- Wygenerowane obrazy korzystają z niewielkiego dziennego budżetu, niezależnego od czatu. Gdy zostanie wykorzystany, żądanie kończy się niepowodzeniem** 429** . Zakręt, który odpowiada bez obrazu, kończy się niepowodzeniem** 502** (Lub** 400** /** 503** gdy tekst Copilot brzmi jako odmowa lub problem z wydajnością); wiadomość mówi które.

## Model bezpieczeństwa

- **Nieoficjalna integracja.** Ten dostawca dokonuje inżynierii wstecznej protokołu BizChat WebSocket. Może się zepsuć bez powiadomienia, gdy Microsoft zmieni punkt końcowy.
- Flaga `subscriptionRisk: true` odzwierciedla, że integracja opiera się na nieudokumentowanym punkcie końcowym. Ograniczenia konta są możliwe, ale nie zostały potwierdzone.
- Token dostępu to krótkotrwały JWT. Traktuj je jak hasło: nie zatwierdzaj, nie rejestruj ani nie udostępniaj go.
- Token odświeżania zapewnia ciągły dostęp do powierzchni Microsoft 365. Przechowuj go z taką samą ostrożnością jak klucz API.

## Rozwiązywanie problemów

### Uwierzytelnianie kończy się natychmiastowym niepowodzeniem

- Sprawdź, czy skopiowałeś z**WebSocket URL** , a nie z żądania XHR/Fetch. Poświadczenie znajduje się w parametrze zapytania `access_token` połączenia Chathub WebSocket — a nie w nagłówku `Authorization: Bearer`.
- Upewnij się, że `chathubPath` zawiera pełny segment `<oid>@<tenant>` ze ścieżki URL.

### Token wygasa po 75 minutach ~

Tego się oczekuje. Bez `refreshToken` token dostępu jest krótkotrwały. Albo:

- Ponownie przechwyć poświadczenie z DevTools lub
- Skonfiguruj** Ustawienia zaawansowane → Odśwież token (opcjonalnie)** w oknie dialogowym Dodaj lub edytuj połączenie w celu automatycznego odświeżania.

### Połączenie testowe przebiega pomyślnie, ale czat zwraca błąd 401

Dla połączenia utworzonego za pomocą** Zaloguj się za pomocą Microsoft** , Połączenie testowe sprawdza wygaśnięcie tokenu dostępu i odnawia wygasły token za pomocą zapisanego tokena odświeżania, więc pozytywny test również udowadnia, że token odświeżania nadal działa.

W przypadku wklejonego poświadczenia połączenie testowe sprawdza kształt poświadczenia, a gdy token ma wygaśnięcie, czy token, którego użyłby dostawca, nie wygasł (przechowywany token połączenia wygrywa nieaktualną pastę; token odświeżenia liczy się jako odnawialny). Token unieważniony przed wygaśnięciem nadal przechodzi test; czat, a następnie wraca** 401** `m365_unauthorized`. Używać** Zaloguj się za pomocą Microsoft** ponownie lub ponownie zdobądź nowe dane uwierzytelniające.

### Copilot nie pojawia się na liście dostawców

Upewnij się, że `copilot-m365-web` jest włączona w** Panel kontrolny → Dostawcy** . Dostawca może być domyślnie ukryty na niektórych poziomach.
