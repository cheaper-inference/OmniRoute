`copilot-m365-web` (alias `m365copilot`) wysyła żądania czatu w formacie OpenAI za pośrednictwem
uwierzytelnionej sesji przeglądarkowej Microsoft 365 Copilot BizChat pod adresem
`m365.cloud.microsoft/chat`. Jest to nieoficjalna integracja.

> **Nie znasz jeszcze dostawców korzystających z plików cookie przeglądarki?**
>
> Przed wykonaniem instrukcji dotyczących tego dostawcy przeczytaj **`docs/getting-started/WEB-COOKIE-GUIDE.md`**, aby poznać ogólny proces konfiguracji, wskazówki dotyczące uwierzytelniania, ograniczenia i sposoby rozwiązywania problemów.
>
> **Ważne:** Dane uwierzytelniające dla tego dostawcy **nie są plikiem cookie**. Nie kopiuj
> plików cookie z `m365.cloud.microsoft`. Dane uwierzytelniające składają się z parametru zapytania adresu URL WebSocket
> oraz segmentu ścieżki — oba można odczytać na karcie Network w DevTools.

## Wymagania wstępne

- Konto Microsoft 365 z dostępem do BizChat pod adresem `m365.cloud.microsoft/chat`
- Przeglądarka oparta na Chromium (Chrome, Edge) umożliwiająca inspekcję połączeń WebSocket w DevTools
- Licencja M365 Copilot (dołączona do wielu planów Microsoft 365 Business/Enterprise)

## Przechwytywanie danych uwierzytelniających (metoda WebSocket)

1. Zaloguj się pod adresem `https://m365.cloud.microsoft/chat` i rozpocznij rozmowę.
2. Otwórz **DevTools → Network**.
3. Ustaw filtr **WS** (WebSocket).
4. Kliknij połączenie WebSocket Chathub. Poszukaj adresu URL zaczynającego się od
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Z pola **Request URL** skopiuj:
   - Wartość parametru zapytania `access_token` (krótkotrwały token JWT).
   - Segment ścieżki Chathub znajdujący się po `/Chathub/` (np. `<oid>@<tenant>`).

Pełny adres URL ma następującą postać:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. W OmniRoute przejdź do **Providers → Add Provider**, wybierz **Microsoft 365 Copilot
   (BizChat)** i wklej dane uwierzytelniające w następującym formacie:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Kliknij **Test Connection**, a następnie **Save**.

## Przechwytywanie danych uwierzytelniających (import pliku HAR)

Zamiast ręcznie kopiować wartości z adresu URL WebSocket możesz wyeksportować plik HAR
z DevTools:

1. Otwórz **DevTools → Network**.
2. Rozpocznij lub kontynuuj rozmowę w BizChat (spowoduje to nawiązanie połączenia WebSocket).
3. Kliknij prawym przyciskiem myszy w panelu Network i wybierz **Save all as HAR with content**.
4. W OmniRoute użyj przycisku **Import .har file** w oknie dialogowym połączenia z dostawcą.

OmniRoute skanuje plik HAR w poszukiwaniu adresu URL WebSocket Chathub, wyodrębnia
`access_token` oraz `chathubPath` i automatycznie wypełnia pola danych uwierzytelniających.
Podczas importowania pliku HAR dekodowana jest data wygaśnięcia tokenu JWT i wyświetlany jest pozostały czas jego ważności.

> **Nigdy nie zatwierdzaj w repozytorium rzeczywistego eksportu HAR, tokenu dostępu ani tokenu odświeżania.** W testach i
> dokumentacji należy zawsze używać wartości zastępczych.

## Okres ważności tokenu i odświeżanie

`access_token` jest krótkotrwały (zwykle **~75 minut**). Bez użytecznego tokenu
odświeżania po wygaśnięciu należy ponownie przechwycić dane uwierzytelniające.

### Automatyczne odświeżanie za pomocą `refreshToken`

W oknie dialogowym dostawcy Microsoft 365 **Dodaj połączenie** lub **Edytuj połączenie** otwórz
**Ustawienia zaawansowane → Token odświeżania (opcjonalnie)**. Wklej token odświeżania Microsoft OAuth
dla zakresu `substrate.office.com/sydney` i zapisz. Wprowadzone dane są maskowane i nigdy nie są
wstępnie wypełniane zapisanym tokenem. Podczas edycji pozostaw to pole puste, aby zachować istniejący token;
wklej nowy token, aby go zastąpić.

Uzyskaj token odświeżania za pomocą przepływu kodu urządzenia lub kodu autoryzacji Microsoft
z zakresem `substrate.office.com/sydney`; pulpit nawigacyjny nie uzyskuje go za Ciebie.
Po skonfigurowaniu tokenu odświeżania OmniRoute sprawdza `access_token` przed żądaniami
i odświeża go tylko wtedy, gdy jest to konieczne. Pomyślne odświeżenie zapisuje również
obrócony token odświeżania, dzięki czemu nie trzeba ponownie ręcznie przechwytywać danych,
dopóki token odświeżania pozostaje ważny.

Jeśli `refreshToken` nie jest ustawiony, po każdym wygaśnięciu należy ręcznie ponownie przechwycić
dane uwierzytelniające WebSocket.

### Wybór warstwy

| Warstwa      | Alias        | Środowisko               |
| ------------ | ------------ | ------------------------ |
| `individual` | _(domyślna)_ | Konsumencki M365 Copilot |
| `edu`        | `included`   | Edukacyjny M365 Copilot  |
| `enterprise` | `work`       | M365 Copilot dla firm    |

Ustaw warstwę w **Ustawienia zaawansowane → Warstwa Copilot**. Warstwa wpływa
na routing BizChat i dostęp do modeli.

## Model bezpieczeństwa

- **Nieoficjalna integracja.** Ten dostawca wykorzystuje protokół WebSocket BizChat, odtworzony metodą inżynierii wstecznej. Integracja może przestać działać bez ostrzeżenia, gdy Microsoft zmieni punkt końcowy.
- Flaga `subscriptionRisk: true` wskazuje, że integracja korzysta z nieudokumentowanego punktu końcowego. Ograniczenia konta są możliwe, ale nie zostały potwierdzone.
- Token dostępu jest krótkotrwałym tokenem JWT. Traktuj go jak hasło: nie zapisuj go w repozytorium, dziennikach ani nie udostępniaj go innym.
- Token odświeżania zapewnia długoterminowy dostęp do usługi BizChat. Przechowuj go z taką samą ostrożnością jak klucz API.

## Rozwiązywanie problemów

### Uwierzytelnianie kończy się niepowodzeniem natychmiast

- Sprawdź, czy skopiowano dane z **adresu URL WebSocket**, a nie z żądania XHR/Fetch. Dane uwierzytelniające znajdują się w parametrze zapytania `access_token` połączenia WebSocket Chathub — a nie w nagłówku `Authorization: Bearer`.
- Upewnij się, że `chathubPath` zawiera pełny segment `<oid>@<tenant>` ze ścieżki URL.

### Token wygasa po około 75 minutach

Jest to oczekiwane zachowanie. Bez `refreshToken` token dostępu ma krótki czas ważności. Wykonaj jedną z następujących czynności:

- Ponownie przechwyć dane uwierzytelniające w DevTools lub
- Skonfiguruj **Ustawienia zaawansowane → Token odświeżania (opcjonalny)** w oknie dialogowym dodawania lub edytowania połączenia, aby włączyć automatyczne odświeżanie.

### Testowanie połączenia kończy się powodzeniem, ale czat zwraca błąd 401

Token mógł wygasnąć między jego sprawdzeniem a pierwszym żądaniem. Ponownie przechwyć aktualne dane uwierzytelniające.

### Copilot nie pojawia się na liście dostawców

Upewnij się, że `copilot-m365-web` jest włączony w sekcji **Pulpit → Dostawcy**. W niektórych planach dostawca może być domyślnie ukryty.
