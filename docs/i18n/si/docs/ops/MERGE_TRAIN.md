## මුදා හැරීමේ ශාඛාවකට ගොඩබෑම

සර්ව පෝලිම `release/vX.Y.Z` වෙත ගොඩබෑම පාලනය කරයි. PR ගොඩබෑමට පෙර පෙරනිමි ශාඛාවේ `config/merge-queue/config.json` හි ඉහළ මට්ටමේ `mode` කියවන්න. [ඔම්නි පෝලිම](OMNI_QUEUE.md) බලන්න.

- **`shadow`** වලංගුකරණය ධාවනය කර අතින් ඒකාබද්ධ කිරීමකට ගොඩබෑම සිදු කරයි. එහි අවසාන ශීර්ෂයේ අනුමත PR වෙත `omni-queue` යොදන්න. `npm run queue -- why <PR>` සමඟ සුදුසුකම් පරීක්ෂා කරන්න. `npm run queue -- history --base <branch>` හි එම හිස සඳහා තීන්දුව එනතෙක් රැඳී සිටින්න. `would-land` මත ඉදිරියට යන්න. `culprit-found` හෝ `would-dequeue` මත, ඒකාබද්ධය අල්ලාගෙන හේතුව නිවැරදි කරන්න.
- **සෙවනැලි ව්යතිරේක.** වත්මන් මූලික ඉඟියට එරෙහිව හරිත සම්පූර්ණ CI සහිත දුම්රියකට වෙනම පෝලිම් තීන්දුවක් නොමැතිව ඉදිරියට යා හැක. PR හිසෙහි දැනටමත් වත්මන් මූලික ඉඟිය අඩංගු වන විට එම ව්යතිරේකය අදාළ වේ.
- **`live`** ගොඩබෑම අවුලුවාලීමට `omni-queue` ලේබලය භාවිතා කරයි. පෝලිම පමණක් PR ගොඩබසිනු ඇත. ඒකාබද්ධ විධාන සහ සෘජු තල්ලු පෝලිමට තබන්න.

සෑම ගොඩබෑමකටම හිමිකරුගේ අවසරය සහ අදාළ අවශ්‍ය චෙක්පත් අවශ්‍ය වේ. `omni-queue` යොදන්න හිමිකරු ගොඩබෑමට අවසර දුන් පසුව පමණි. පෝලිම්ගත PRs ස්පර්ශ වන ආරක්ෂිත මාර්ග සඳහා එම PR සඳහා හිමිකරුගේ `protected-approved` තීරණය ද අවශ්‍ය වේ.

"ක්‍රියාකාරී නිකුතුවේදී හරිත දොරටු අවශ්‍ය වේ" නීති මාලාවට හිස මත හරිත `Gate / CI` සහ `Gate / Quality` අවශ්‍ය වේ. රතු ගේට්ටුවක් මඟ හැරීමට කිසි විටෙක `--admin` භාවිතා නොකරන්න. නිකුතු කැටි කුට්ටි ශීත කළ ශාඛාවට ඒකාබද්ධ වේ. [දෘඪ රීතිය 21](HARD_RULES_DETAIL.md) බලන්න. වෙනත් සැසියක් ක්‍රියා කරන බවට කිසිවිටක ලේබල් කිරීම, ඒකාබද්ධ කිරීම හෝ ඇදීමේ ඉල්ලීමකට තල්ලු නොකරන්න. [දෘඪ රීතිය 22](HARD_RULES_DETAIL.md) බලන්න.

## දුම්රිය ඇදීමේ ඉල්ලීම

1. වත්මන් මුදා හැරීමේ මූලික ඉඟියේ දුම්රිය ශාඛාවක් ආරම්භ කරන්න. ඒකාබද්ධ කිරීමේ කැපවීම් භාවිතයෙන් නිශ්චිත අනුමත සාමාජික ප්‍රධානීන් ඒකාබද්ධ කරන්න. ස්කොෂ් සහ රිබේස් වළක්වා ගැනීමෙන් ඔවුන්ගේ කැපවීම් ඉතිහාසය ආරක්ෂා කරන්න.
2. දුම්රිය ශාඛාව සඳහා එක් ඇදීමේ ඉල්ලීමක් විවෘත කරන්න. එම PR වත්මන් පාදක ඉඟිය මත එහිම සම්පූර්ණ CI සමඟ වලංගු කරන්න. ගොඩබෑමට පෙර මූලික ඉඟිය සහ අනුමත සාමාජික ප්‍රධානීන් නැවත පරීක්ෂා කරන්න. වලංගු අපේක්ෂකයා වෙනස් වූ විට දුම්රිය සහ එහි CI නැවුම් කරන්න.
3. අදාළ පෝලිම් ප්‍රකාරය යටතේ ඒකාබද්ධ කිරීමේ වගකීමක් සමඟ දුම්රිය PR ගොඩබස්වන්න. සජීවී මාදිලියේදී, පෝලිමේ `merge-ff` ගොඩබෑමේ ක්‍රමය ඒකාබද්ධ කිරීම් ආරක්ෂා කරයි. මුල් සාමාජික ප්‍රධානීන් මුදා හැරීමේ ශාඛාවෙන් ළඟා විය හැකිය. GitHub PRs සාමාජිකයා ඒකාබද්ධ වූ ලෙස සලකුණු කරන අතර කැපවීම් ඔවුන්ගේ කර්තෘවරුන් රඳවා තබා ගනී.

පොදු උදාහරණයක් වන්නේ [PR #21071](https://github.com/cheaper-inference/OmniRoute/pull/21071). එය සාමාජිකයින් 18 දෙනෙකු PRs ඒකාබද්ධ කර 2026-11-24 දින ඒකාබද්ධ කිරීමේ වගකීමක් සමඟ ගොඩ බැස්සේය.

`main` සිට ඊළඟ නිකුතුවේ ශාඛාව වෙත සමමුහුර්ත කිරීමක් ද ඒකාබද්ධ කිරීමේ වගකීමක් හරහා ගොඩබසිනු ඇත. පසුකාලීන සමමුහුර්ත කිරීම් සඳහා `main` වංශය සංරක්ෂණය කිරීම අවශ්‍ය වේ. [වැඩ ගස් හුදකලා කිරීම](WORKTREE_ISOLATION.md#sync-back-landings-are-merge-commits-never-squash) බලන්න.

## දේශීය ඒකාබද්ධ-දුම්රිය වලංගුකාරකය

## `merge-train.sh` සඳහා නැවුම් පිරික්සුම් පූර්ව අවශ්‍යතා

වැඩ ගස් නිර්මාණය කිරීමට පෙර පූර්ව ගුවන් යානය ධාවනය වේ. `npm ci` සමඟ පරායත්තතා ස්ථාපනය කරන්න. `node_modules/.bin/tsc` ක්‍රියාත්මක කළ හැකි බවත් `node_modules/node_modules` නොමැති බවත් තහවුරු කරන්න. `node_modules/.bin/bun --version` සාර්ථක දැයි පරීක්ෂා කරන්න.

Bun postinstall මඟ හැරුනේ නම්, `(cd node_modules/bun && node install.js)` ධාවනය කරන්න. සපයන්නාගේ අනුකූලතාව සහ දන්නා-සංකේත චෙක්පත් Bun භාවිතා කරයි. වලංගුකාරකය අවහිර කිරීමේ දොරටුවක් ලෙස `npm run check:cycles:ratchet` ධාවනය කරයි. ස්වාධීන `npm run check:cycles` විධානය උපදෙස් වේ.
