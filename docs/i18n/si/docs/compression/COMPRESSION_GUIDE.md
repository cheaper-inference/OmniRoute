## දළ විශ්ලේෂණය

OmniRoute විසින් ඉල්ලීම් upstream සැපයුම්කරුවන් වෙත ළඟා වීමට **පෙර ක්රියාකාරීව** ධාවනය වන මොඩියුලර් prompt සම්පීඩන නල මාර්ගයක් ක්රියාත්මක කරයි. මෙයින් අදහස් වන්නේ ඔබේ token ඉතිරිකිරීම් විනිවිද පෙනෙන ආකාරයෙන් සිදුවන බවයි — ඔබේ කාර්ය ප්රවාහයට කිසිදු වෙනසක් අවශ්ය නොවේ.

```
සේවාලාභී ඉල්ලීම
  → සම්පීඩන උපායමාර්ග තේරීම්කරු
    → Combo අභිබවා යාමක්ද? → Combo සැකසුම භාවිත කරන්න
    → ස්වයංක්රීය-ප්රේරක සීමාවක්ද? → ස්වයංක්රීය ප්රකාරය භාවිත කරන්න
    → පෙරනිමි ප්රකාරයද? → ගෝලීය සැකසුම භාවිත කරන්න
    → ක්රියාවිරහිතද? → සම්පීඩනය මඟ හරින්න
  → තෝරාගත් සම්පීඩන ප්රකාරය
    → Off: සම්පීඩනයක් නැත
    → Lite: ආරක්ෂිත හිස් ඉඩ/ආකෘතිකරණ පිරිසිදු කිරීම (~15%)
    → Standard: Caveman-ශෛලියේ පිරවුම් වචන ඉවත් කිරීම (~30%)
    → Aggressive: ඉතිහාසය වයස්ගත කිරීම + සාරාංශකරණය (~50%)
    → Ultra: හියුරිස්ටික් කප්පාදු කිරීම + කේත-බ්ලොක් තුනී කිරීම (~75%)
    → RTK: විධාන-සංවේදී terminal/tool-output පෙරීම (upstream පරාසය 60-90%)
    → Stacked: අනුපිළිවෙළට සැකසූ බහු-engine නල මාර්ගය, සාමාන්යයෙන් RTK පසුව Caveman (සුදුසුකම් ලබන පරාසය 78-95%)
  → සම්පීඩිත ඉල්ලීම → සැපයුම්කරු
```

## සම්පීඩන මාදිලි

### අක්රිය

සම්පීඩනයක් යෙදිය නොමැත. සියලුම පණිවිඩ වෙනස් නොකර යවනු ලැබේ.

### ලයිට් මාදිලිය (~15% ඉතිරියක්, <1ms ප්රමාදය)

ආරක්ෂිතම මාදිලිය — හැඩතල පිරිසිදු කිරීම. මෙහි මෙවලම්-ප්රතිඵල කප්පාදුව දත්ත නැතිකරන බැවින්, පෙරනිමි
මාර්ගය (`allow-lossy`, `engine:lite` හෝ නම් කළ සංයෝජන සඳහා opt-in එකක් නොමැතිව) `compressToolResults: false` සමඟ
lite ක්රියාත්මක කරයි: පෙර මෙවලම් ප්රතිඵල වෙනස් නොකර provider වෙත ළඟා වේ.

| තාක්ෂණය                  | විස්තරය                                                                                   |
| ------------------------ | ----------------------------------------------------------------------------------------- |
| `collapseWhitespace`     | අඛණ්ඩ හිස් පේළි සහ අවසාන හිස්තැන් ඒකාබද්ධ කිරීම                                           |
| `dedupSystemPrompt`      | අනුපිටපත් පද්ධති පණිවිඩ ඉවත් කිරීම                                                        |
| `compressToolResults`    | පෙර මෙවලම් ප්රතිඵල lite සීමාවට කප්පාදු කිරීම (දත්ත නැතිවීම: ඉල්ලීම් opt-in එකක් සමඟ පමණි) |
| `removeRedundantContent` | නැවත නැවත ඇති උපදෙස් ඉවත් කිරීම                                                           |
| `replaceImageUrls`       | base64 රූප දත්ත URI කෙටි කිරීම                                                            |

**වඩාත් සුදුසු:** සැමවිටම සක්රිය භාවිතය, ආරක්ෂාව-තීරණාත්මක කාර්ය ප්රවාහ.

### සම්මත මාදිලිය (~30% ඉතිරියක්)

[Caveman](https://github.com/JuliusBrussee/caveman) මඟින් ආභාෂය ලැබූ — අර්ථය රඳවා ගනිමින් පිරවුම් වචන සහ දිගු වාක්ය ඛණ්ඩ ඉවත් කරයි:

- පිරවුම් වචන ඉවත් කරයි ("please", "I think", "basically", "actually")
- දිගු වාක්ය ඛණ්ඩ සංක්ෂිප්ත කරයි ("in order to" → "to", "as a result of" → "because")
- ආචාරශීලී අවිනිශ්චිත ප්රකාශ ඉවත් කරයි ("Would you mind...", "If you could possibly...")
- කේතීකරණ විමසුම් සඳහා සකස් කළ regex රීති 30කට වැඩි ප්රමාණයක්

**වඩාත් සුදුසු:** දෛනික කේතීකරණ කාර්ය ප්රවාහ, වියදම් පිළිබඳ සැලකිලිමත් කණ්ඩායම්.

### ආක්රමණශීලී මාදිලිය (~50% ඉතිරියක්)

දිගු සැසි සඳහා බුද්ධිමත් ඉතිහාස කළමනාකරණය:

- **පණිවිඩ වයස්ගත කිරීම** — පැරණි පණිවිඩ ක්රමයෙන් සම්පීඩනය කෙරේ
- **මෙවලම් ප්රතිඵල සම්පීඩනය** — දිගු මෙවලම් ප්රතිදාන කප්පාදු හෝ ඉවත් කෙරේ (පළමු/අවසාන පේළි,
  ගැළපෙන පේළි පෙරීම, JSON යතුරු සංක්ෂිප්ත කිරීම)
- **ව්යුහාත්මක අඛණ්ඩතා ආරක්ෂක** — `tool_use` + `tool_result` යුගල අඛණ්ඩව පවතින බව සහතික කරයි

එකිනෙක අතිච්ඡාදනය වන මෙවලම්/සන්දර්භ payload සඳහා, පෙරනිමි OmniRoute සංයෝජනය engine එක මත එක ලෙස යොදයි:

```txt
RTK -> Caveman
```

ඒකාබද්ධ ඉතිරිකිරීම් ආකලනීය නොව, ගුණාකාර වේ:

```txt
combined = 1 - (1 - RTK ඉතිරිකිරීම්) * (1 - Caveman ආදාන ඉතිරිකිරීම්)

පරාසය    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

RTK සහ Caveman යන දෙකටම එකම ආදාන/සන්දර්භ payload එක අඩු කළ හැකි විට එම `78-95%` අගය අදාළ වේ.
Caveman ප්රතිචාර ප්රතිදාන මාදිලිය වෙනම වේ: එය සක්රීය කර ඇති විට, Caveman හිම ප්රතිදාන ඉතිරිකිරීම් (සාමාන්යය `65%`,
ප්රධාන අගය `~75%`, පරාසය `22-87%`) භාවිත කරන්න. සමස්ත බිල්පත් ඉතිරිකිරීම් ඔබේ prompt/ප්රතිදාන මිශ්රණය මත රඳා පවතී.

පරාසයට සෘජුවම අයත් වේ. නමුත් සාමාන්ය, අතිරික්ත නොවන මෙවලම් ප්රතිදානයකට (පිරිසිදු `grep` ගැළපුම් ලැයිස්තුවක්,
කෙටි ගොනු කියවීමක්, සාමාන්ය සංවාද පාඨයක්) එරෙහිව එම pipeline එකම ධාවනය කළ විට නිවැරදිව **ශුන්යයට ආසන්න ඉතිරියක්** ලැබේ, මන්ද
ඉවත් කිරීමට පුනරාවර්තන කිසිවක් නොමැති අතර code block, URL, ශීර්ෂ, අනුවාද, හෝ ALL-CAPS නියත හඳුන්වනයන්
ඉවත් කරන හෝ වෙනස් කරන නැවත ලිවීමක් යැවීම `validateCompression()` (`validation.ts`) විසින් ප්රතික්ෂේප කරනු ලැබේ.

මෙය අපේක්ෂිත, ආරක්ෂිත හැසිරීමක් මිස දෝෂයක් නොවේ: සම්පීඩනය සම්පූර්ණයෙන් සක්රීය කර තිබුණද, බොහෝ විට පිරිසිදු ගොනු
කියවන/grep කරන coding සැසියකට මධ්යස්ථ සමස්ත ඉතිරියක් පෙනෙන අතර, අසාර්ථක වන loop එකකට හෝ අධික ලෙස පණිවිඩ නිකුත් කරන

යටින් පවතින මෙවලම් ප්රතිදානය සැබවින්ම අතිරික්තදැයි පරීක්ෂා කරන්න.

## වින්යාසය

### උපකරණ පුවරුව

`Dashboard → Context & Cache` වෙත යන්න:

- **Caveman** — මාදිලි තේරීම, භාෂා පැකේජ, පෙරදසුන සහ ගෝලීය පෙරනිමි
- **RTK** — විධාන-පෙරහන් පෙරදසුන, RTK ආරක්ෂණ සැකසුම් සහ පෙරහන් නාමාවලිය
- **Compression Combos** — routing combos වෙත පවරන ලද නම් කළ එන්ජින් pipeline
- **Auto-Trigger Threshold** — token ගණන සීමාව ඉක්මවූ විට සම්පීඩනය ස්වයංක්රීයව සක්රිය කිරීම

### එක් Combo එකකට අදාළ Override

`Dashboard → Context & Cache → Compression Combos` තුළ routing
combo එකකට compression combo එකක් පවරන්න:

```txt
Combo: "free-tier-fallback"
  Compression Combo: "coding-agent-stack"
  Pipeline: RTK -> Caveman
  Targets:
    1. if/kimi-k2.7-code
    2. if/qwen3.8-max-preview
```

මෙමගින් ගෙවන subscriptions සඳහා lite mode තබා ගනිමින්, නොමිලේ/coding providers මත stacked compression භාවිත කළ හැක.

මෙම "Per-Combo Override" පැවරීම, **routing-combo compression
mode** override (Default/Off/Lite/Standard/Aggressive/Ultra/Codex Responses — එම field හි schema එක `rtk`, `stacked` සහ `omniglyph` ද පිළිගනී) වෙතින් වෙනස් පාලනයකි — එම override එක නම් කළ compression-combo pipeline එකක් තෝරා නොගනී; එය `resolveCompressionPlan` විසින් පරීක්ෂා කරන `compressionMode` field එක පමණක් සකසයි. එය combo card එකේ (`Dashboard → Combos`) හෝ, #6760 සිට, `Dashboard → Context & Cache → Compression Combos` හි "Assign to routing" ලැයිස්තුව තුළ එක් routing combo එකකට, ඉහත ලේඛනගත කළ pipeline-assignment checkbox එකට යාබදව, සැකසිය හැක. මතුපිට දෙකම එකම `PUT /api/combos/{id}` endpoint එක හරහා සුරකී.

### එක් request එකකට අදාළ override

එක් request එකක් සඳහා compression plan එක override කිරීමට `x-omniroute-compression` request header එක යවන්න. එයට ඉහළම ප්රමුඛතාව ඇත — එය routing-combo override, සක්රිය profile, auto-trigger සහ panel Default යන සියල්ල අභිබවා යයි. නොදන්නා අගයන් නොසලකා හරිනු ලැබේ (request එක කිසිවිටෙක ප්රතික්ෂේප නොකෙරේ), එසේම ගෝලීය master switch එක සියල්ල පාලනය කරයි: compression ගෝලීයව අක්රිය විට, header එකට එය සක්රිය කළ නොහැක. අගයන්:

| Value         | Effect                                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `off`         | මෙම request එක සඳහා compression නොමැත.                                                                                     |
| `default`     | panel-derived Default profile එක (සක්රිය profile එක නොසලකා හරී). Lossy engines අක්රියව තබයි.                               |
| `safe`        | header එක නොයැවීම හා සමානයි.                                                                                               |
| `allow-lossy` | summaries, relevance filters සහ style rewrites ඇතුළුව, මෙම request හි operator plan එක තබා ගනී.                            |
| `engine:<id>` | සක්රිය කර ඇති විට එක් engine එකක් පමණක්, උදාහරණයක් ලෙස `engine:rtk`. එම engine සඳහා එක් request එකකට අදාළ opt-in එක මෙයයි. |
| `<combo>`     | නාමයෙන් ගැළපෙන named combo එකක් (පළමුව case-insensitive ලෙස, පසුව id මගින්).                                               |

`allow-lossy`, `engine:<id>` හෝ named combo එකක් නොමැති විට, lossy engines යෙදෙන්නේ නැත. Lossy Default, auto-trigger හෝ routing override එකක් downgrade කළ විට, OmniRoute වින්යාසගත stacked pipeline එකෙන් හඳුනාගත් lossless පියවර වින්යාසගත අනුපිළිවෙළට තබා ගනී. වින්යාසගත lossless පියවරක් නොනැසී පවතින විට පමණක් එය `session-dedup → lite` වෙත fallback වේ.

Settings panel හි **Effective pipeline** පෙරදසුන මඟින් සාමාන්ය at-rest plan එක පෙන්වයි. auto-trigger එකක් ධාවනය කළ හැකි විට, එම පෙරදසුන මඟින් එහි conditional effective pipeline එක ද පෙන්වයි; එමඟින් panel සහ header-රහිත runtime resolution එක සමානව පවතී.

යෙදූ plan එක `X-OmniRoute-Compression: <mode>; source=<source>` response
header එක තුළ නැවත ලබා දේ; මෙහි `<source>` යනු `request-header`, `routing-override`, `active-profile`,
`auto-trigger`, `default` හෝ `off` යන අගයන්ගෙන් එකකි.

```bash
# සම්පීඩන සැකසුම් ලබා ගන්න
curl http://localhost:20128/api/settings/compression

curl -X PUT http://localhost:20128/api/settings/compression \

  -d '{"defaultMode":"stacked","autoTriggerMode":"stacked","autoTriggerTokens":32000}'

  -H "Content-Type: application/json" \
  -d '{"mode":"rtk","messages":[{"role":"tool","content":"npm test output here"}]}'
```

## උසස් සම්පීඩන පද්ධති

ඉහත විස්තර කර ඇති මාතයන් 7 න් ඔබ්බට (මූලාශ්‍රය `codex-responses` සහ `omniglyph` මාතයන් ද පිළිගනී, මෙම මාර්ගෝපදේශය ආවරණය නොකෙරේ), පහත කොටස් එම මාතයන් ඇතුළත හෝ ඒ සමඟ ක්‍රියා කරන විශේෂාංග ආවරණය කරයි: මෙවලම් ප්‍රතිඵල සම්පීඩනය සහ ප්‍රගතිශීලී වයස්ගත වීම යනු ආක්‍රමණශීලී එන්ජිමේ පියවර 1 සහ 2 (ආක්‍රමණශීලී මාදිලිය සහ `aggressive` මාදිලිය ක්‍රියාත්මක වන ආකාරය), ගොඩගැසී ඇති ආකාරය Cache-Aware Compression සම්පීඩනය ක්‍රියාත්මක වන විට හැඹිලි සපයන්නන් සඳහා `aggressive` සහ `ultra` සිට `standard` දක්වා පහත හෙලනු ඇත, සහ Caveman Output Mode සහ Output Styles යනු ඉල්ලීම සම්පීඩනය කිරීම වෙනුවට ආකෘතියේ ප්‍රතිදානය හැඩගස්වන පෙරනිමියෙන් අක්‍රිය කරන පද්ධති-ක්ෂණික උපදෙස් වේ.

### හැඹිලි-දැනුවත් සම්පීඩනය

සමහර සපයන්නන් (ක්ෂණික හැඹිලි සහිත Anthropic වැනි) සහය දක්වයි** ක්ෂණික හැඹිලිගත කිරීම** , එමඟින් පිරිවැය සහ ප්‍රමාදය අඩු කිරීම සඳහා විමසුමේ කොටස් හැඹිලිගත කිරීමට ඔවුන්ට ඉඩ සලසයි. හැඹිලිගත කිරීම සක්රිය කර ඇති විට, ආක්රමණශීලී සම්පීඩනය ඇත්ත වශයෙන්ම කළ හැක** රිදෙනවා** කාර්ය සාධනය එය හැඹිලි ටෝකන වෙනස් කරයි, හැඹිලිය අවලංගු කරයි.

`cachingAware.ts` මොඩියුලය මෙය විසඳයි** හැඹිලි සන්දර්භය හඳුනා ගැනීම** සහ** සම්පීඩන උපාය මාර්ගය සකස් කිරීම** ඒ අනුව.

#### එය ක්රියා කරන ආකාරය

1. **හැඹිලි සන්දර්භය හඳුනා ගන්න** — `cache_control` සලකුණු සඳහා ඉල්ලීම් ශරීරය පරිලෝකනය කරයි
2. **හැඹිලි සපයන්නන් හඳුනා ගන්න** — ඉලක්ක සපයන්නා හැඹිලියට සහය දක්වන්නේ දැයි පරීක්ෂා කරයි
3. **උපාය මාර්ග සකස් කරන්න** — හැඹිලි සපයන්නන් සඳහා `aggressive`/`ultra` `standard` දක්වා පහත හෙළයි
4. **පද්ධති විමසුම මඟ හරින්න** — පද්ධති විමසීම් සාමාන්‍යයෙන් හැඹිලිගත වේ, එබැවින් ඒවා සම්පීඩනය නොකරන්න

උපාය මාර්ගික සහායකයා ද `deterministicOnly` ධජයක් ආපසු ලබා දෙයි, නමුත් සැලසුම් සාදන්නා — උපාය මාර්ගය පමණක් පරිභෝජනය කරයි, අද ධජය පහළට කිසිවක් නොකියයි.

#### කේත උදාහරණය

```ts
import {
  detectCachingContext,
  getCacheAwareStrategy,
} from "@omniroute/open-sse/services/compression/cachingAware";

const body = {
  model: "anthropic/claude-sonnet-4.5",
  messages: [{ role: "user", content: "Hello" }],
  cache_control: { type: "ephemeral" }, // ← Cache marker
};

const ctx = detectCachingContext(body, { provider: "anthropic" });
// → { hasCacheControl: true, provider: "anthropic", targetFormat: null, isCachingProvider: true }

const strategy = getCacheAwareStrategy("aggressive", ctx);
// → { strategy: "standard", skipSystemPrompt: true, deterministicOnly: true }
```

#### භාවිතා කළ යුත්තේ කවදාද

හැඹිලි-දැනුවත් සම්පීඩනය යනු** සෑම විටම මත** — වින්‍යාස කිරීම අවශ්‍ය නොවේ. සම්පීඩනය ක්‍රියාත්මක වන විට එය ක්‍රියාත්මක වන අතර ඉලක්ක සපයන්නා ක්ෂණික හැඹිලි සඳහා සහය දක්වයි (Anthropic, OpenAI, ආදිය); පැහැදිලි `cache_control` මාර්කර් අවශ්‍ය නොවේ — හැඹිලි සපයන්නා විසින් පමණක් පහත වැටීම ප්‍රේරණය කරයි, සහ මාර්කර් පමණක් කිසිවිටෙකත් සිදු නොකරයි (සලකුණු හඳුනාගැනීම හැඹිලි ටෙලිමෙට්‍රි පෝෂණය කරයි, උපාය තීරණය නොවේ).

OpenRouter හැඹිලි සපයන්නෙකු ලෙස ගණන් ගනු ලබන්නේ `anthropic/*` මාදිලි සඳහා පමණි: Claude කේත ඉල්ලීම් ඔවුන්ගේ `cache_control` බිඳුම් ලක්ෂ්‍ය (උපරිම වශයෙන් 4) තබා ගන්නා අතර ආරක්ෂකයා උපසර්ගය ආරක්ෂා කරයි, අනෙක් සෑම OpenRouter පවුලක්ම (`openai/`, `google/`, `qwen/`, …) ඉවත් කර අනාරක්ෂිතව පවතී.

### ප්රගතිශීලී වයසට යාම

දිගු සංවාද බොහෝ පණිවිඩ හැරීම් රැස් කරයි, නමුත් පැරණි හැරීම් අඩු අදාළ වේ. `progressiveAging.ts` මොඩියුලය** හැරවුම් දුර අනුව පණිවිඩ අඩු කරයි** (සංවාදයේ අවසානයේ සිට මනිනු ලබන දුර). නැව්ගත කළ පෙරනිමි (`verbatim: 2, light: 2, moderate: 3`) සමඟ:

- **අවසාන හැරීම් 2 (දුර ≤ 2)** : වාචිකව තබා ඇත
- **දුර 3** : Caveman සම්පීඩනය (පිරවුම් ඉවත් කිරීම)
- **දුර 4 +** : සහකාර පණිවිඩ සාරාංශගත කර ඇත; පරිශීලක පණිවිඩ ඔවුන්ගේ පළමු පේළියට අඩු කර, අක්ෂර 120 කින් සීමා කර ඇත; වෙනත් භූමිකාවන් ස්පර්ශ නොකළේය. පද්ධති විමසීම්, දැනටමත් වයස්ගත පණිවිඩ සහ නවතම පරිශීලක පණිවිඩය දුර නොතකා සෑම විටම වාචිකව තබා ඇත. කිසිවක් සම්පූර්ණයෙන්ම අත් නොහරින අතර, නැව්ගත කළ පෙරනිමියන් සමඟ `light` කලාපයට ළඟා විය නොහැක (`light` සමාන වේ `verbatim`).

#### කේත උදාහරණය

```ts
import { applyAging } from "@omniroute/open-sse/services/compression/progressiveAging";

const messages = [
  { role: "system", content: "You are a helpful assistant" },
  { role: "user", content: "What is 2+2?" },
  { role: "assistant", content: "4" },
  // ... 50 more turns ...
];

const { messages: aged, saved } = applyAging(messages, {
  verbatim: 3, // last 3 turns: verbatim
  light: 8, // distance <= 8: lite compression
  moderate: 20, // distance <= 20: caveman compression
  fullSummary: 5, // required by the type, not read by the banding code
  // distance > 20: summarized (assistant) / first line kept (user)
});

// saved = number of tokens saved
```

#### භාවිතා කළ යුත්තේ කවදාද

ප්‍රගතිශීලී වයසට යාමයි** සෑම විටම මත** `aggressive` මාදිලිය — සඳහා එය `compressAggressive()` හි 2 වන පියවර වේ. අල්ට්රා මාදිලිය එය ක්රියාත්මක නොවේ. එය විශේෂයෙන් ඵලදායී වේ:

- දිගුකාලීන කේතීකරණ සැසි
- බහු දින සංවාද
- බොහෝ මෙවලම් ඇමතුම් සමඟ නියෝජිත කාර්ය ප්‍රවාහයන්

### Caveman අවුට්පුට් මාදිලිය

Caveman ප්රතිදාන මාදිලිය එකතු කරයි** පද්ධති කඩිනම් උපදෙස්** — ආකෘතියෙන් terse output සඳහා අසන `lite` මට්ටම සම්පූර්ණ වාක්‍ය තබා ගන්නා සංක්ෂිප්ත පිළිතුරු ඉල්ලා සිටින අතර, `full` එය "ස්මාර්ට් කේව්මන් මෙන් ප්‍රතිචාර දැක්වීමට" අසයි, සහ `ultra` ටෙලිග්‍රාෆික් ප්‍රතිදානය සඳහා අසයි; උපදෙස් පමණක් අසයි, ඔවුන්ට එය සහතික කළ නොහැක. ඉල්ලීම් `applyOutputStyles()` (`open-sse/services/compression/outputStyles/apply.ts`) හරහා ඒවා ලබා ගනී: `open-sse/handlers/chatCore.ts` තෝරා ගැනීම මුලින්ම නිරාකරණය කරන්නේ back-compat shim (`resolveOutputStyleSelection()` හි `open-sse/services/compression/outputStyles/backCompat.ts`), එය `outputStyles` හිස් වන අතර, `cavemanOutputMode.intensity` හි `terse-prose` ප්‍රතිදාන විලාසයට සක්‍රීය `cavemanOutputMode` සිතියම්ගත කරයි (පහත Back-compat බලන්න); හිස් නොවන `outputStyles` තේරීමක් භාවිතා වන අතර, `cavemanOutputMode.enabled` සහ `intensity` කිසිදු බලපෑමක් නැත, එහි `autoClarity` ටොගලය තවමත් අදාළ වේ. `outputMode.ts` උපදෙස් පාඨ (`CAVEMAN_INSTRUCTION_BY_LANGUAGE`), අන්තර්ගත බයිපාස් සහ එන්නත් කිරීම භාවිතා කරන ස්ථානගත කිරීමේ සහායකයා දරයි; එහිම `applyCavemanOutputMode()` ඉන්ජෙක්ටරයට නිෂ්පාදන ඇමතුමක් නොමැත.

#### එය ක්රියා කරන ආකාරය

මෙම මාදිලිය ආදානය සම්පීඩනය නොකරයි. එය පද්ධති ප්‍රේරකයට උපදෙස් වාරණයක් එක් කරයි (එන්නත් කිරීම ක්‍රියා කරන ආකාරය පහත බලන්න), සහ ඉල්ලීම සඳහා තෝරාගත් ඕනෑම ආදාන සම්පීඩන මාදිලියක් දැන් අවහිරය ගෙන යන ශරීරය මත ක්‍රියාත්මක වේ. සෑම මට්ටමක්ම අවසන් වන හවුල් මායිම් වගන්තියට ඉදිරියෙන්, ඉංග්‍රීසි `full` මට්ටම මෙසේ කියවේ:

> "ස්මාර්ට් caveman මෙන් දැඩි ලෙස ප්‍රතිචාර දක්වන්න. ලිපි (a/an/the), ෆිලර් (just/really/basically/actually/simply), ප්‍රියජනක, හෙජිං. කොටස් OK. කෙටි සමාන පද (විශාල නොවේ, නිවැරදි කරන්න ක්‍රියාත්මක නොවේ. සියලුම තාක්ෂණික ද්‍රව්‍ය, කේතය, දෝෂ, URLs, හඳුනාගැනීම් නිවැරදිව තබා ගන්න."

මෙය විශේෂයෙන් හොඳින් ක්‍රියා කරන්නේ:

- කේත උත්පාදනය (terser output = අඩු ටෝකන)
- ඉක්මන් ප්‍රශ්නෝත්තර (විස්තරාත්මක පැහැදිලි කිරීම් අවශ්‍ය නොවේ)
- කණ්ඩායම් සැකසීම (ප්‍රතිදානය උපරිම කරන්න)

#### භාවිතා කළ යුත්තේ කවදාද

Caveman ප්රතිදාන මාදිලිය වේ** තේරීම** . සම්පීඩනය සමඟින් (`enabled: true`, සම්පීඩන සැකසුම් පිටුවේ ප්‍රධාන ටොගල්), `cavemanOutputMode.enabled` සමඟ එය ක්‍රියාත්මක කරන්න; `intensity` `lite`, `full` හෝ `ultra` තෝරා ගනී:

```json
{
  "enabled": true,
  "cavemanOutputMode": {
    "enabled": true,
    "intensity": "full"
  }
}
```

සම්පීඩන සංයෝජනයකි** ප්රතිදාන මාදිලිය** toggle (`outputMode`, level in `outputModeIntensity`) මගින් combo අදාළ වන ඉල්ලීම් සඳහා එකම ස්විචය සකසයි, සහ `omniroute_set_compression_engine` MCP මෙවලම එහි boolean `outputMode` තර්කය හරහා එය ලියයි. මෙම ස්විචයට වඩා හිස් නොවන `outputStyles` තේරීමක් ප්‍රමුඛත්වය ගනී. උපකරණ පුවරුව තුළ, සබල කරමින්** දැඩි ගද්ය** ප්‍රතිදාන විලාසය එම කොටසටම එන්නත් කරයි (පහත ප්‍රතිදාන විලාස බලන්න).

සෑම මෝස්තරයක්ම — `lite`, `full`, `ultra` — තීව්‍රතා මට්ටම් තුනක් නැව්ගත කරන අතර සෑම මට්ටමක්ම අවසන් වන්නේ කේත කුට්ටි, ගොනු මාර්ග, විධාන, දෝෂ සහ URLs නිරවද්‍යව තබා ගන්නා හවුල් මායිම් වගන්තියෙන් ( `outputMode.ts` හි`SHARED_BOUNDARIES` ) ය. `terse-prose` සහ `terse-cjk` මට්ටමේ පෙළ එම ලැයිස්තුවට හඳුනාගැනීම් එක් කරයි.

`terse-cjk` ස්ථාන දෙකකින් `zh` වෙත ස්ථානගත කර ඇත. සම්පීඩන සැකසීම් පිටුව එහි පේළිය ලැයිස්තුගත කරන්නේ උපකරණ පුවරුව UI භාෂාව චීන (`zh-CN` හෝ `zh-TW`) වන විට පමණක් වන අතර `applyOutputStyles()` එය එන්නත් කරන්නේ ඉල්ලීමේ විසඳන ලද භාෂාව (පහත භාෂා තේරීම බලන්න) `zh` වූ විට පමණි. පේළිය සැඟවීමෙන් සුරකින ලද `terse-cjk` තේරීමක් ඉවත් නොවේ: සැකසුම් API ඕනෑම මෝස්තර හැඳුනුම්පතක් පිළිගනී, සහ පිටුවේ වෙනත් මෝස්තර සුරැකීම එය තබා ගනී. ඉල්ලීම් වේලාවේදී, `applyOutputStyles()` භාෂා පරීක්ෂාව එකම ස්ථානීය ද්වාරය වේ.

#### එන්නත් කරන ආකාරය

`applyOutputStyles()` (`open-sse/services/compression/outputStyles/apply.ts`) නාමාවලියට එරෙහිව තේරීම විසඳයි (නොදන්නා ids සහ පෙදෙසි-නොගැලපෙන මෝස්තර අත්හරිනු ලැබේ, කිසි විටෙක දෝෂයක් නොවේ; කිසිදු විලාසිතාවක් විසඳන තේරීමක් ශරීරය නොවෙනස්ව තබයි, `no_styles` ලෙස මඟ හැරේ ), තෝරාගත් උපදෙස් නාමාවලි අනුපිළිවෙලට සංයුක්ත කරයි, මායිම් වගන්තිය එකතු කරයි** වරක්** ( `less-code` හෝ `ponytail` තෝරන විට ආරක්ෂිත වගන්තිය, `SAFETY_BOUNDARIES` හෝ එහි පරිවර්තනය), සහ තනි idempotency සලකුණකින් (`[OmniRoute Output Styles]`) අවහිර කිරීම ආරම්භ කරයි, එබැවින් නැවත අයදුම් කිරීම තහනම් නොවේ. විසඳන ලද භාෂාවට (පහත භාෂා තේරීම බලන්න) පරිවර්තනයක් ඇති විට, ඉංග්‍රීසි වෙනුවට දේශීය උපදෙස් එන්නත් කරනු ලැබේ.

හිස් නොවන `messages` අරාවක් සහිත ශරීරයක් මත, අන්තර්ගත මඟ හැරීමට පෙර idempotency පරීක්‍ෂණය ක්‍රියාත්මක වේ: `[OmniRoute Output Styles]` ලකුණුකරය දැනටමත් ඉහළ මට්ටමේ `system` ක්ෂේත්‍රයේ (තන්තුවක් හෝ අන්තර්ගත-වාරණයක් අරාවක්) හෝ තන්තු අන්තර්ගතයක් සහිත පද්ධති පණිවිඩයක ඇති විට, ශරීරය `already_applied` ලෙස නොවෙනස්ව පවතින අතර මූල පද පිරික්සුම් නැත. එසේ නොමැතිනම් අන්තර්ගත මග හැරීමක් (`shouldBypassCavemanOutputMode()` හි `open-sse/services/compression/outputMode.ts`) අවසාන පණිවිඩ තුනේ පෙළ පරීක්ෂා කරයි, ඒවායේ කාර්යභාරය කුමක් වුවත්, එම පෙළ එහි ආරක්ෂාව, ආපසු හැරවිය නොහැකි ක්‍රියාව හෝ `deploy` කිරීමේ මූල පද හෝ ඇණවුම් සංවේදී අනුපිළිවෙලක් `migrate` ගැළපෙන විට සම්පූර්ණ හැරීම සඳහා මෝස්තර මඟ හරියි: `first`, `then`, `after that` ඇතුළත `delete`, `before`, `drop`, `rollback` හෝ `backup` මගින් `release` 240 කි. බයිපාස් යන අතරතුර ධාවනය වේ** ස්වයංක්‍රීය පැහැදිලි බයිපාස්** ටොගල් (`cavemanOutputMode.autoClarity`, පෙරනිමියෙන් සක්‍රිය) ක්‍රියාත්මකයි; ටොගල් ක්‍රියා විරහිත කිරීමෙන් මූල පද පරීක්ෂාව මඟ හැරේ.

කිසි විටෙකත් නව `messages[0]` නිර්මාණය නොකරන `placeSystemInstruction()` (එකම ගොනුව) හරහා හැරවීමට බයිපාස් ඉඩ දෙන විට, එය සොයා ගන්නා මේවායින් පළමුවැන්නෙහි බ්ලොක් එක තබයි:

1. තන්තු අන්තර්ගතය සහිත ප්‍රමුඛ පද්ධති පණිවිඩයක්: බ්ලොක් එක එහි පෙළට පසුව එකතු කර ඇත.
2. ඉහළ මට්ටමේ `system` ක්ෂේත්‍රය: වාරණය තන්තුවක පෙළට පසුව එකතු කරනු ලැබේ, නැතහොත් අන්තර්ගත-වාරණ අරාවකට නව පෙළ වාරණයක් ලෙස එක් කෙරේ.
3. තන්තු අන්තර්ගතය සහිත පළමු පසුකාලීන පද්ධති පණිවිඩය: බ්ලොක් එක එහි පෙළට පසුව එකතු කර ඇත.
4. ඉහත කිසිවක් නොවේ: අවහිරය `messages` අවසානයේ නව පද්ධති පණිවිඩයක් වෙත යයි.

`messages` අරාවක් නොමැති (හෝ හිස් එකක් සහිත) ශරීරයක් මත, කිසිඳු අන්තර්ගත බයිපාස් ධාවනය නොවන අතර ඉහළ මට්ටමේ `system` ක්ෂේත්‍රයක් උපදේශනය නොකෙරේ. එම ක්‍ෂේත්‍රයේ දැනටමත් `[OmniRoute Output Styles]` මාර්කරය අඩංගු නොවේ නම්, `instructions` තන්තුවක පෙළට පසුව බ්ලොක් එක එකතු කරනු ලැබේ, මෙම අවස්ථාවෙහිදී ශරීරය `already_applied` ලෙස නොවෙනස්ව තබයි. ශරීරයට string `instructions` ක්ෂේත්‍රයක් නොමැති නමුත් `input` (තන්තුවක් හෝ අරාවක්) රැගෙන යන විට, බ්ලොක් එක `instructions` බවට පත් වන අතර, එම ක්ෂේත්‍රය රඳවාගෙන සිටින ඕනෑම නූල් නොවන අගයක් ප්‍රතිස්ථාපනය කරයි. string `instructions` ක්ෂේත්‍රයක් හෝ තන්තුවක් හෝ අරාවක් `input` නොමැති ශරීරයක් නොවෙනස්ව තබා `no_messages` ලෙස මඟ හරිනු ලැබේ.

#### සක්රිය කරන්නේ කෙසේද

උපකරණ පුවරුවේ:** සම්පීඩන සන්දර්භය → සම්පීඩන සැකසුම්** (`/dashboard/context/settings`), ප්‍රතිදාන මෝස්තර අංශය: on/off ටොගලයක් සහ මට්ටම් තේරීමක් සහිත ශෛලියකට එක් පේළියක්. සම්පීඩනය සක්‍රීයව පවතින විට මෝස්තර එන්නත් කරයි (පිටුවෙහි ප්‍රධාන ටොගලය, `enabled`). ද** ස්වයංක්‍රීය පැහැදිලි බයිපාස්** toggle මත ඇත** ගුහා මිනිසා** පිටුව (`/dashboard/context/caveman`), එහි** ප්රතිදාන මාදිලිය** කාඩ්පත. ක්‍රමලේඛනගතව, සම්පීඩන වින්‍යාසය තෝරා ගැනීම දිගටම පවතී:

```json
{
  "outputStyles": [
    { "id": "i-have-adhd", "level": "full" },
    { "id": "less-code", "level": "lite" }
  ]
}
```

Back-compat: `outputStyles` හිස් වන අතර, උරුම `cavemanOutputMode.enabled` `cavemanOutputMode.intensity` හිදී `terse-prose` වෙත සිතියම් සැකසීම. බ්ලොක් එක ආරම්භ වන්නේ `[OmniRoute Output Styles]` මාර්කර් එකෙන් වන අතර එහිදී ලෙගසි `applyCavemanOutputMode()` ඉන්ජෙක්ටරය `[OmniRoute Caveman Output Mode]` ලිවීය. සලකුණට පහළින්, පෙළ en, pt-BR, es, de, fr, it, ru, id සහ vi හි උරුම එන්නත් සමඟ ගැලපේ; ja සහ zh හි එය මායිම් වගන්තියට පෙර එක් අමතර ඉඩක් දරයි. `terse-prose` pt-BR, es, de, fr, it, ru, zh, ja, id සහ vi බවට පරිවර්තනය වේ, එබැවින් `hu` විසඳන ලද භාෂාවක් වන ඉල්ලීමකට ලෙගසි ඉන්ජෙක්ටරය එහි හංගේරියානු භාෂාව භාවිතා කළ ඉංග්‍රීසි පෙළ ලැබේ.

Output-style language selection (`resolveOutputStyleLanguage()` in `outputStyles/apply.ts`): with `languageConfig.enabled` on, `autoDetect` samples the latest user message in the request's `messages` array that has text (string content, or the `text` of its content parts) and runs the Caveman engine's detector (`detectCompressionLanguage()`) on it. The detector returns `zh` for text with Han characters and no kana; otherwise it returns whichever of `it`, `pt-BR`, `es`, `de`, `fr`, `ru`, `ja`, `hu` and `id` has the most hint matches, and `en` when none match — text it cannot classify gets English, never `defaultLanguage`, and `vi` is never detected although the styles ship `vi` text. A Responses API body keeps its turns in `input`, which is not sampled, so it gets `defaultLanguage`, then English. When no user message in `messages` has text, or with `autoDetect` off, `defaultLanguage` applies, then English. With `languageConfig.enabled` off, the language is English — unless a compression combo applies to the request (a combo assigned to the request's routing combo, or the default compression combo chatCore falls back to for the built-in stacked pipeline): applying a combo turns `languageConfig.enabled` on for that request and sets `defaultLanguage` from the combo's language packs (the saved value if it is one of the combo's packs, otherwise the combo's first pack, which defaults to `en`), while the saved `autoDetect` (on by default) still applies. The Caveman input engine picks its rule-pack language differently — per text part and, with auto-detect off, gated on `enabledPacks`.

උපාය මාර්ගයක් ගැලපීමෙන් පසුව, කිසිවක් ඉතිරි නොකරන එකක් වුවද, පසුකාලීන උපාය මාර්ග උත්සාහ නොකරයි. ගැළපෙන උපක්‍රමය ඇස්තමේන්තුගත ටෝකන ඉතිරි නොකරන විට (දිග ÷ 4, වටකුරු) — උදාහරණයක් ලෙස රේඛා 25 හෝ ඊට අඩු කේතයක් වැනි ගොනුවක් හෝ අයිතම 7ක් හෝ — අඩු අක්ෂර 2,000කට වැඩි JSON අරාවක් හෝ ආක්‍රමණශීලී එන්ජිම මුල් මෙවලම් ප්‍රතිඵලය තබා ගන්නා විට ( `compressAnthropicToolResultBlock()` මුල් මෙවලම් ප්‍රතිඵලය:`compressAggressive()` `saved` දෙකම) 0 හෝ පහළින්, `compressToolResult()` විසින්ම එම උපාය මාර්ගයේ ප්‍රතිදානය තවමත් ලබා දෙයි. මෙවලම්-ප්‍රතිඵල පියවර අවසාන වචනය නොවේ: එන්ජිමේ ෆෝල්බැක් සාරාංශයට තවමත් අක්ෂර 8,192 ට වඩා දිග `tool` හෝ `function` පණිවිඩයක් කෙටි කළ හැක (`maxTokensPerMessage`, 2,048, වාර 4).

#### භාවිතා කළ යුත්තේ කවදාද

මෙවලම් ප්‍රතිඵල සම්පීඩනය යනු ආක්‍රමණශීලී එන්ජිමේ (`compressAggressive()` හි `open-sse/services/compression/aggressive.ts`) පියවර 1 වේ, එබැවින් එය ආක්‍රමණශීලී ආකාරයෙන් සහ ගොඩගැසූ නල මාර්ගයක `aggressive` පියවරක් තුළ ක්‍රියාත්මක වේ. එය OpenAI-හැඩයේ `tool` සහ `function` පණිවිඩ සහ Anthropic `tool_result` කුට්ටි තුළ ඇති පෙළ සම්පීඩනය කරයි. සෑම උපාය මාර්ගයකටම `aggressive.toolStrategies` යටතේ තමන්ගේම ස්විචයක් ඇත, සියල්ල පෙරනිමියෙන් ක්‍රියාත්මක වේ. උපකරණ පුවරුවේ, ස්විචයන් Caveman පිටුවේ ඇත** උසස්** සම්පීඩනය ක්‍රියාත්මක වන විට බලන්න සහ පෙරනිමි මාදිලිය ආක්‍රමණශීලී වේ.

### ගොඩගැසූ නල මාර්ගය

ගොඩගැසූ මාදිලිය ක්‍රියාත්මක වේ** අනුපිළිවෙලින් බහු එන්ජින්** — සාමාන්‍යයෙන් RTK පළමුව (මෙවලම් ප්‍රතිදානය මත 60-90% ඉතුරුම්), පසුව ඉතිරි පෙළ මත Caveman (~ 46% ආදාන ඉතුරුම්). රචනා කරන ලද, එයයි** 78-95% සුදුසු පරාසය** (ඉහත Upstream Savings Math බලන්න): `1 - (1 - 0.60..0.90) × (1 - 0.46)` සාමාන්‍යය ≈ 89%.

#### එය ක්රියා කරන ආකාරය

```
Input (1000 tokens)
  → RTK (command-aware filter) → 200 tokens
    → Caveman (filler removal) → 108 tokens
  → Output (108 tokens, ~89% savings)
```

#### භාවිතා කළ යුත්තේ කවදාද

මේ සඳහා ගොඩගැසූ ආකාරය භාවිත කරන්න:

- මෙවලම් බර වැඩ ප්‍රවාහ (නියෝජිත කේතීකරණය, පර්යේෂණ)
- පිරිවැය-සංවේදී කණ්ඩායම් සැකසීම
- ඔබට උපරිම ටෝකන් ඉතුරුම් අවශ්‍ය වූ විට

ගොඩගැසී ඇති නල මාර්ග ගෝලීය `stackedPipeline` සම්පීඩන සැකසුම හරහා වින්‍යාස කර ඇත, නැතහොත් මාර්ගගත සංයෝජනයකට පවරා ඇති නම් කරන ලද සම්පීඩන සංයෝජනයක් හරහා (ඉහත එක්-කොම්බෝ ප්‍රතික්‍ෂේප කිරීම බලන්න) — ස්වයංක්‍රීය-කොම්බෝ `modePack` හරහා නොවේ (එම ක්ෂේත්‍රය ස්වයංක්‍රීය සංයුක්ත මාදිලි තේරීමක් පමණක් වන අතර, `stacked` වලංගු ඇසුරුම් නාමයක් නොවේ).

## සම්පීඩන සංයෝජන අභිබැවීම්

විවිධ භාවිත අවස්ථා සඳහා හැසිරීම සියුම්ව සකස් කිරීමට, ගෝලීය සම්පීඩන ප්රකාරය **එක් එක් සංයෝජනය සඳහා** අභිබවා යා හැකිය:

```json
{
  "id": "coding-combo",
  "strategy": "priority",
  "config": {
    "weights": { "taskFit": 0.5 },
    "modePack": "quality-first"
  },
  "compressionOverride": "aggressive"
}
```

මෙය පහත අවස්ථා සඳහා ප්රයෝජනවත් වේ:

- **කේතකරණ සංයෝජන**: දිගු සැසි සඳහා `aggressive` ප්රකාරය භාවිත කරන්න
- **ඉක්මන් ප්රශ්නෝත්තර සංයෝජන**: වේගවත් ප්රතිචාර සඳහා `lite` ප්රකාරය භාවිත කරන්න
- **මෙවලම් බහුල සංයෝජන**: උපරිම ඉතිරි කිරීම් සඳහා `stacked` ප්රකාරය භාවිත කරන්න
- **නිෂ්පාදන සංයෝජන**: හැඹිලිගත කිරීමේ සැපයුම්කරුවන් සඳහා අභිබැවීම අක්රියව තබන්න — සැමවිටම සක්රිය
  හැඹිලි-දැනුවත් ගැළපීම මඟින් `aggressive`/`ultra` ස්වයංක්රීයව `standard` දක්වා පහත හෙළයි
  (තෝරාගත හැකි `cache-aware` ප්රකාරයක් නොමැත)
