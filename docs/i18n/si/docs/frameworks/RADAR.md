## පොදු නිවේදන කියවනය

සාමාන්ය නිවේදන කියවනය Radar විශේෂාංග ධජයෙන් වෙන්ව පවතී. උපකරණ පුවරුවේ Home සහ
Changelog දර්ශකය සරල `GET` ඉල්ලීමක් හරහා ගබඩාවේ පොදු `news.json`,
`NEWS_JSON_URL` වෙතින් ලබා ගනී (`src/shared/utils/releaseNotes.ts`). ඒවා කිසිදු Radar සැකසුමක්, prompt එකක්, provider
වින්යාසයක්, භාවිත වාර්තාවක් හෝ දේශීයව ඉවත දැමීමේ තත්ත්වයක් යවන්නේ නැත.

`news.json`, `parseNewsPayload()` මඟින් ක්රියාත්මක කළ සංවෘත v2 schema එක භාවිත කරයි:

- `schemaVersion: 2` සහ සීමා කළ `items[]` එකතුවක්;
- ස්ථාවර, අනන්ය නිවේදන `id` අගයන්;
- පැහැදිලි `active` සහ ISO `publishedAt` ක්ෂේත්ර;
- විකල්ප ස්ථානීකරණය කළ පිටපත් සමඟ අනිවාර්ය ඉංග්රීසි පිටපතක්;
- විකල්ප, අක්තපත්ර අවශ්ය නොවන HTTPS සබැඳි සහ අවසර ලැයිස්තුගත icon එකක්;
- නවතම සක්රිය අයිතමයට ප්රමුඛත්වය දෙන තේරීම, locale එක නොමැති විට ඉංග්රීසිය භාවිත කිරීම, සහ එක් එක් ID සඳහා දේශීයව ඉවත දැමීම.

පැරණි forks වලට Changelog දසුන බිඳ වැටීමකින් තොරව සංක්රමණය වීමට හැකි වන පරිදි, parser එක කලින් භාවිත කළ ඒකවචන `{ active, title, message, ... }` ආකෘතිය තාවකාලිකව පිළිගනී. වලංගු නොවන feeds අක්රියව පවතී. ## ධජය: `RADAR_ENABLED` (පෙරනිමියෙන් අක්රියයි)

**ධජය අක්රියව ඇති විට, අතුරුමුහුණත නොපවතී:**

- දේශීය model-state කියවීම් සහ ලිවීම් ඇතුළු සියලු `/api/radar/*` endpoints,

  `/dashboard/radar/combos`, `/dashboard/radar/offers`, `/dashboard/radar/intel`)
  `notFound()` render කරයි.
- `getRadarCatalog()` (`src/lib/radar/index.ts`) වෙනස් නොකළ baseline එක ආපසු ලබා දෙයි —

  feed cache එක කියවන්නේ නැත.
- කිසිදු Radar ජාල ඇමතුමක් සිදු නොකෙරේ; සෑම sync module එකක්ම `fetch` ස්පර්ශ කිරීමට පෙර

මෙය දැඩි superset gate එකකි: ධජය සක්රිය කිරීමෙන් _තිර_ පමණක් අගුළු හැරේ,
වෙනත් කිසිවක් නොවේ. එය දත්ත upload නොකරයි, පසුබිම් sync එකක් ආරම්භ නොකරයි, එමෙන්ම

`RADAR_ENABLED` ක්‍රියාත්මක කිරීමෙන් සිදු වන්නේ UI අගුළු හැරීම පමණි. සංග්‍රහය සමමුහුර්ත කිරීම සඳහා `radar_settings.opt_in` (`src/lib/db/radar.ts`, migration `136_radar_cache_settings.sql`) තුළ ගබඩා කර ඇති දෙවන ස්වාධීන තේරීමක් අවශ්‍ය වේ. ඕනෑම ජාල ඇමතුමක් ගැනීමට පෙර `syncRadar()` ධජය _ සහ තේරීම පරීක්ෂා කරයි:

```
Flag off      → { status: "disabled" }   — no network call
Opt-in false  → { status: "opt_out" }    — no network call
```

දෙකම ක්‍රියාත්මක වන විට, සමමුහුර්ත කිරීමේ මාර්ගය වන්නේ:

1. `x-omniroute-radar-schema: 2` සමඟ `GET <feed base URL>/v1/catalog/latest` සහ විකල්ප `Authorization: Bearer <supporter key>` ශීර්ෂයක් (පහත බලන්න). ක්‍රම ශීර්ෂය නොමැති විට සේවාදායකයන් වෙන වෙනම අත්සන් කරන ලද v1 සංක්‍රාන්ති කෞතුක වස්තුවට පෙරනිමි වේ, එබැවින් පැරණි ස්ථාපිත සේවාලාභීන්ට යාවත්කාලීන කිරීම් දිගටම ලැබේ.
2. මෙය බාගත-පමණි යෙදුම් ප්‍රවාහයකි, නමුත් එය තවමත් HTTPS ඉල්ලීමකි. ධාරක යටිතල ව්‍යුහයට මූලාශ්‍ර IP වැනි සාමාන්‍ය සම්බන්ධතා පාරදත්ත ලැබේ. ආධාරක යතුරක් වින්‍යාස කර ඇති විට, සමමුහුර්ත කිරීම එම යතුර Bearer ශීර්ෂය තුළ යවන අතර එමඟින් සේවාවට හිමිකම විසඳිය හැකිය. ඉහත සාක්ෂි සීමාවේ හඳුනාගෙන ඇති නිශ්චිත පුද්ගලික-සේවාදායක සංශෝධනයේදී, පෝෂක ඉල්ලීම් ගිණුම්කරණය අතින් අපයෝජන සමාලෝචනය සඳහා ප්‍රධාන හෑෂ්, සමස්ථ භාවිතය සහ IP හි දෛනික භ්‍රමණය වන කප්පාදු කළ HMAC භාවිතා කරයි; එම වගු යතුර හෝ IP අමු ආකාරයෙන් නොපවතියි. යටිතල පහසුකම් ප්‍රවේශ ලොග සහ සංකේතාත්මක බෙදාහැරීමේ පිට පෙට්ටිය වෙනම මෙහෙයුම් සීමාවන් වේ.
3. OmniRoute කිසිවිටෙක රේඩාර් සේවාව වෙත විමසීම්, ප්‍රතිචාර, සංවාද, සැපයුම්කරු අක්තපත්‍ර, ආදර්ශ ගමනාගමනය, අතිකාල, ප්‍රමාදය, හෝ දේශීය සැපයුම්කරු වින්‍යාසය යවන්නේ නැත.
4. ප්‍රතිචාරය තහවුරු කර, වලංගු කර, සහ හැඹිලිගත කර ඇත ( [ආරක්ෂක ආකෘතිය](#security-model) බලන්න). රේඩාර් සතුව හරියටම සේවාදායක පාර්ශ්වීය ජාල මාර්ග හතරක් ඇත: නාමාවලිය සඳහා `syncRadar()`, යොමු කිරීම් සඳහා `syncRadarReferrals()`, සහ ආධාරකරුවන්ට පමණක් පිරිනැමීම් සහ Intel සඳහා `syncRadarOffers()` / `syncRadarIntel()`.

නාමාවලි පරීක්ෂාව සෑම පැය 24කට වරක්ම ක්‍රියාත්මක වේ. සත්‍යාපිත සංග්‍රහය තවමත් හැඹිලිගත අනුවාදය සහ ස්ථරය රැගෙන යන විට, සමමුහුර්ත කිරීම හැඹිලිගත පේලෝඩ් තබා ගනී, `fetchedAt` අලුත් කරයි, ඊළඟ චෙක්පත ඊළඟ පැයක ටික් එක වෙනුවට පැය 24කට පසුව පැමිණේ.

ද** ආධාරක යතුර** යනු වෛකල්පිත දරන්නා ටෝකනයකි (`radar_settings.supporter_key`) එය කුමන ස්ථරයට සේවය කළ යුතුද යන්න තීරණය කිරීමට සංග්‍රහ සේවාවට ඉඩ සලසයි ( [ස්ථර](#tiers-community-and-live) බලන්න). එය:

- ගබඩා කර ඇත** විවේකයේදී සංකේතනය කර ඇත** සපයන්නාගේ අක්තපත්‍ර සඳහා භාවිතා කරන එකම AES-256-GCM `encrypt()`/`decrypt()` සහායකයින් (`src/lib/db/encryption.ts`) සමඟ.
- `POST /api/radar/settings` (`{ supporterKey: "omr_" + 40 hex chars }`) හරහා සකසන්න සහ** කිසිදා ආපසු දෝංකාර දුන්නේ නැත** — ප්‍රතිචාරය වෙස් මුහුණු පෝරමයක් (`omr_****abcd`) ලබා දෙයි.
- එය පරමාණුකව වෙනස් කිරීම හෝ ඉවත් කිරීම නාමාවලිය, යොමු කිරීම්, පිරිනැමීම් සහ Intel හැඹිලි අවලංගු කරයි. මීළඟ sync/read නව හිමිකම් සේවාදායකයේ පැත්ත විසඳයි; යතුරක් සුරැකීමෙන් ජාල ඉල්ලීමක් හෝ තනි-භාවිත සක්‍රීය කිරීමේ යතුරක් පරිභෝජනය නොකරයි.
- GET — සමමුහුර්තකරණය මත දරන්නා ටෝකනයක් ලෙස සංග්‍රහ සේවාව වෙත යවන ලද යතුර ගැන වෙන කිසිවක් සේවාදායකයා හැර නොයයි.

### නැති වූ සහායක යතුරක් ප්රතිසාධනය කිරීම

සත්කාරක සේවාවේ ප්රතිසාධන පිවිසුම් ස්ථානය `https://radar.omniroute.online/recover` වේ; එය සැලසුම් පිටුවෙන් ද සබැඳි කර ඇත. දේශීය ස්ථාපනයට ගැනුම්කරුගේ/දායකයාගේ විද්යුත් තැපෑල කිසිවිටෙක නොලැබෙන අතර, එහි සංකේතනය කළ සැකසුම්වලින් අමු යතුරක් නැවත ගොඩනැගිය නොහැකි බැවින්, ප්රතිසාධනය සම්පූර්ණයෙන්ම OSS සේවාලාභියාට පිටතින් පවතී.

1. යතුරට සම්බන්ධ විද්යුත් තැපෑල ඉදිරිපත් කරන්න. ප්රතිසාධනය කළ හැකි බලපත්රයක් තිබුණත් නැතත් සේවාව එකම පිළිගත් පිටුව ආපසු ලබා දෙන බැවින්, පෝරමය ගිණුම් අනාවරණය නොකරයි.
2. සුදුසුකම් ඇත්නම්, බෙදාහැරීමේ worker එක කෙටි කාලීන, එක්වරක් පමණක් භාවිත කළ හැකි සබැඳියක් යවයි. එය විවෘත කිරීමෙන් token එක වහාම තාවකාලික සංකේතනය කළ `HttpOnly`/`Secure` cookie එකකට ගෙන ගොස් පිරිසිදු `/recover` URL එක වෙත හරවා යවයි; පිටුවේ token එකක්, විද්යුත් තැපෑලක්, පැරණි යතුරක් හෝ ප්රතිස්ථාපන යතුරක් අඩංගු නොවේ.
3. අවලංගු කිරීම තහවුරු කරන්න. පුද්ගලික සේවාව පෙර යතුර අවලංගු කර, එම සැලසුම/කල් ඉකුත්වීම සමඟ ප්රතිස්ථාපනයක් සාදා, එක් transaction එකකදී එය විද්යුත් තැපෑල සඳහා පෝලිම්ගත කරයි. ප්රතිස්ථාපනය කිසිවිටෙක browser එකට ආපසු ලබා නොදේ.
4. ප්රතිස්ථාපනය `/dashboard/radar` වෙත අලවන්න. පැරණි යතුර දැන් `community` වෙත පහත වැටිය යුතුය; ප්රතිස්ථාපනය සත්යාපිත `live` සමමුහුර්තකරණයක් ලබා දිය යුතුය. එම ප්රතිසාධන සබැඳියම නැවත විවෘත කිරීම සාමාන්ය අවලංගු/කල් ඉකුත් වූ ප්රතිචාරයක් සමඟ අසාර්ථක විය යුතුය.

1. දායකත්ව හිමිකම් ඉල්ලීම, plans/checkout, ප්රතිසාධන ක්රියාවලිය, හෝ බලයලත් පුද්ගලික සේවාදායක ක්රියාකරු වෙතින් අලුතින් නිකුත් කළ හෝ ප්රතිසාධනය කළ යතුරක් ලබා ගන්න. අමු යතුර ලොග්,
   තිර රූ, ගැටලු අදහස්, හෝ විධාන පේළි තර්ක තුළ අලවන්න එපා.
2. දේශීය OmniRoute ස්ථාපනයේ `RADAR_ENABLED` විශේෂාංග ධජය සක්රීය කරන්න. මෙය UI එක
   නිරාවරණය කරන නමුත්, වෙනම සහභාගී වීමේ කැමැත්ත සුරකින තෙක් ජාලය සම්බන්ධයෙන් අක්රීයව පවතී.
3. `/dashboard/radar` විවෘත කර, යතුර අලවා, සක්රීය කරන්න. බ්රවුසරය `{ optIn: true, supporterKey }` සමඟ එක් දේශීය
   `POST /api/radar/settings` ඉල්ලීමක් යවයි; යතුර දේශීයව සංකේතනය කෙරෙන අතර
   ප්රතිචාරයේ අඩංගු වන්නේ `omr_****<last4>` පමණි.
4. සක්රීය කිරීමේ තිරයට එහි නාමාවලි සමමුහුර්තකරණය ක්රියාත්මක කිරීමට ඉඩ දෙන්න, නැතහොත් **දැන් සමමුහුර්ත කරන්න** තෝරන්න. පිටුව
   `live`, සංග්රහ අනුවාදයක්, සහ ලබාගත් වේලාවක් වාර්තා කරන බව තහවුරු කරන්න. සත්යාපිත දේශීය රෝගනිශ්චයක් සඳහා,
   `GET /api/radar/status` යතුර ආපසු ලබා නොදෙමින් සහභාගී වීමේ කැමැත්ත/යතුර පවතින බව සහ කෑෂ් තත්ත්ව හතර වාර්තා කරයි.
   `POST /api/radar/sync-all` මඟින් නාමාවලිය, යොමු කිරීම්, දීමනා, සහ Intel පැහැදිලිව නැවුම් කළ හැක.
5. `/dashboard/radar/setup?provider=<provider>` විවෘත කරන්න. සැපයුම්කරුට අයත් අක්තපත්ර URL එක අනුගමනය කර,
   **API යතුර එක් කරන්න** තෝරා, සැබෑ සැපයුම්කරු පෝරමය හරහා සුරකින්න, මාර්ගෝපදේශයට ආපසු පැමිණ,
   **සම්බන්ධතාව පරීක්ෂා කරන්න** ක්රියාත්මක කරන්න. මාර්ගෝපදේශය සාමාන්ය `/api/providers` සහ
   `/api/providers/<connection-id>/test` මාර්ග භාවිත කරයි; එය සමාන්තර Radar අක්තපත්රයක් නිර්මාණය නොකරයි.
6. අවම වශයෙන් අනුකූල සැපයුම්කරු සම්බන්ධතා දෙකක් සක්රීය වූ පසු `/dashboard/radar/combos` විවෘත කරන්න.
   යෝජිත පවුල සමාලෝචනය කර, පවතින combo API හරහා සංයෝජනය සාදන්න. දීමනා සහ
   Intel වෙනම සජීවී-පමණක් අත්සන් කළ කෑෂ් ලෙස පවතින අතර ඒවායේ කැපවූ Radar පිටුවලින් පරීක්ෂා කළ හැක.
7. `/dashboard/radar` සහ සැකසුම් පිටුව නැවත පූරණය කරන්න. සහභාගී වීමේ කැමැත්ත, සැඟවූ-යතුරු තත්ත්වය, සත්යාපිත කෑෂ් එක, සුරැකි
   සැපයුම්කරු සම්බන්ධතාව, සහ පරීක්ෂණ ක්රියාව නැවත පූරණයෙන් පසුවත් පැවතිය යුතුය. අමු යතුර සහ සැපයුම්කරු අක්තපත්රය
   තවදුරටත් දෘශ්යමාන නොවන විට පමණක් සාක්ෂි ග්රහණය කරන්න.

`http://127.0.0.1:9351` වැනි loopback SSH යොමු කිරීමක් සඳහා පමණි; වෙනත් යෝජනා ක්රම, ඇතුළත් කළ අක්තපත්ර, විකෘති URL, සහ
දුරස්ථ HTTP ගමනාන්ත ආරක්ෂිතව අසාර්ථක වී සංචාලනය අක්රීයව තබයි.

## ආරක්ෂක ආකෘතිය

### Ed25519 නියම බයිට් වලට වඩා අත්සන

පෝෂක ගෙවීම Ed25519 සමඟ අත්සන් කර ඇත. `verifyFeedBytes()` (`src/lib/radar/verify.ts`) මගින් අත්සන තහවුරු කරයි** නිවැරදි ප්‍රතිචාර බයිට්** වයර් — හරහා ලැබුණු ගෙවීම් භාරය සත්‍යාපනයට පෙර කිසි විටෙක නැවත අනුක්‍රමික නොකරනු ඇත, එබැවින් byte-for-byte නැවත-කේතනයකට අත්සන් පරීක්ෂාව නිශ්ශබ්දව අවලංගු කිරීමට හෝ මඟ හැරිය නොහැක. සත්‍යාපන අසාර්ථකත්වය (`invalid_signature`) ගෙවීම් පැටවීම විග්‍රහ කිරීමට හෝ හැඹිලිගත කිරීමට පෙර සමමුහුර්ත කිරීම නවත්වයි.

### Pined public key + භ්‍රමණය

සත්‍යාපනය කරන පොදු යතුර `src/lib/radar/pinnedKeys.ts` (`PINNED_FEED_PUBLIC_KEYS`) තුළ අමුණා ඇත, එබැවින් නව යතුරක් භ්‍රමණයකට පෙර පෙරනිමිති කළ හැකි අතර පෙර යතුරකින් අත්සන් කරන ලද පැරණි හැඹිලි සංග්‍රහ නැවත සමමුහුර්ත වන තෙක් වලංගු වේ.

### ගෑරුප්පු-හිතකාමී env අභිබවා යයි

### අනුවාදය තට්ටුව

`syncRadar()` බාගත කළ සංග්‍රහයක් ප්‍රතික්ෂේප කරයි, එහි `version` දැනට හැඹිලිගත කර ඇති අනුවාදයට (`compareVersions()`, තිත් සහිත `YYYY.MM.DD.n` සංසන්දනය) — `{ status: "stale" }` ට වඩා අලුත් නොවේ. මෙය සම්මුතියකට ලක් වූ හෝ වැරදි ලෙස වින්‍යාස කර ඇති සංග්‍රහ අන්ත ලක්ෂ්‍යයක් සේවාදායකයෙකු පැරණි, වෙනස් ලෙස අත්සන් කරන ලද ගෙවීමකට පෙරළීම වළක්වයි.

### දින දෙකක්, සහ දෙකම තබා ඇත්තේ ඇයි

හැඹිලිගත සංග්‍රහයක් වෙනස් දින දෙකක් රැගෙන යන අතර, ඒවා ව්‍යාකූල කිරීම දෙකම තබා ගැනීමේ සම්පූර්ණ කාරණය වේ:

| ක්ෂේත්රය      | වෙතින් පැමිණේ        | පිළිතුරු                              |
| ------------- | -------------------- | ------------------------------------- |
| `generatedAt` | අත්සන් කළ ආහාර ශරීරය | කොපමණ පැරණි** දත්ත** වේ               |
| `fetchedAt`   | මෙම ස්ථාපනය ඔරලෝසුව  | මෙය ස්ථාපනය කරන විට** බාගත කර ඇත** එය |

මිනිත්තු ගණනකට පෙර ලබා ගත් සංග්‍රහයකට සති ගණනක් පැරණි රූප රැගෙන යා හැක, එබැවින් `fetchedAt` පමණක් ක්‍රියාකරුට උඩ තට්ටුව එහි ඇති මූලික රේඛාවට වඩා නැවුම්ද යන්න පැවසිය නොහැක. දෙකම `radar_feed_cache` හි පවතිනු ඇත, `getRadarCatalog().meta` මගින් ආපසු ලබා දෙනු ලැබේ, සහ `GET /api/radar/status` මගින් වෙන වෙනම වාර්තා කෙරේ. `generated_at` තීරුව පැවතීමට පෙර හැඹිලිගත කරන ලද පේළියක් (සංක්‍රමණය 163) `null` — නොදන්නා ලෙස නැවත කියවනු ලැබේ, ලබා ගැනීමේ කාලය ණයට ගැනීම වෙනුවට. `radar_referrals_cache` සංක්‍රමණය 142 සිට තමන්ගේම `generated_at` තබා ඇත.

ඉහත අනුවාද තට්ටුව `version` සංසන්දනය කරයි, එක්කෝ දිනය නොවේ.

හිඩැස් දෙකක් ඉතිරිව ඇත, දෙකම හිතාමතාම: උපකරණ පුවරුව තවමත් පෙන්වන්නේ `Last fetched` පමණි, එබැවින් එහි ගොඩනැගීමේ දිනය කියවීමට නව ලේබලයක් අවශ්‍ය වේ (සහ එහි ස්ථාන ඇතුළත් කිරීම් 41); සහ දීමනා සහ ඉන්ටෙල් හැඹිලි කිසිඳු ගොඩනැගීමේ දිනයක් තබා නොගනී, ඒවායේ සංග්‍රහ ක්‍රම එක් — `GET /api/radar/status` රැගෙන ගියද, එබැවින් "නොදන්නා" ලෙස කියවන `null` වාර්තා කිරීමට වඩා එම දෙක සඳහා ක්ෂේත්‍රය මඟ හැරේ.

### යෝජනා ක්රමය වලංගු කිරීම

බාගත් බයිට් `RadarFeedSchema` එරෙහිව විග්‍රහ කර වලංගු වේ (`src/lib/radar/feedSchema.ts`, a Zod schema)** පසු** අත්සන තහවුරු කිරීම. යෝජනා ක්‍රම නොගැලපීම `{ status: "invalid_schema" }` ආපසු ලබා දෙන අතර හැඹිලිය ස්පර්ශ නොවී ඉතිරි වේ. හැඹිලිගත පේලෝඩ් සෑම කියවන (`getRadarCatalog()`) — මත ආරක්ෂිතව නැවත වලංගු වේ.

### ප්‍රතිචාර ප්‍රමාණයේ තොප්පිය (10 MB)

`syncRadar()` බලාත්මක කරයි a** 10 MB දෘඩ තොප්පිය** සංග්‍රහ ප්‍රතිචාරයේ — හි අත්සන් කරන ලද සංග්‍රහය KB පරිමාණයේ JSON ලේඛනයක් වේ, එබැවින් මෙයින් පසු ඕනෑම දෙයක් වැරදි ලෙස වින්‍යාස කර ඇති හෝ සතුරු `RADAR_FEED_URL` (හෝ උඩුගං බලා සේවය කරන කසළ) වෙත යොමු කරයි, නීත්‍යානුකූල නාමාවලියක් නොවේ. බලාත්මක කිරීම ද්වි-ස්ථර වේ:

1. `Content-Length` පෙර පියාසර චෙක්පතක් ශීර්ෂකය දැනටමත් තොප්පියට ඉහළින් අගයක් ප්‍රකාශ කරන විට ශරීරය සම්පූර්ණයෙන්ම කියවීම මග හරියි.
2. `Content-Length` නොමැති විට හෝ ශීර්ෂකය කිසි විටෙක විශ්වාස නොකරන සැබෑ ප්‍රමාණය — අඩුවෙන් පෙන්වා දෙන විට පවා ශරීරය කියවන අතරතුර ධාවන-සම්පූර්ණ චෙක්පතක් තොප්පිය බලාත්මක කරයි. සමුච්චිත කුට්ටි එකතු කිරීමෙන් පසුව Ed25519 අත්සන් චෙක්පත සඳහා අවශ්‍ය නියම බයිට් ආරක්ෂා කරයි.

තොප්පිය ඉක්මවීම `{ status: "too_large" }` ආපසු ලබා දෙන අතර හැඹිලිය ස්පර්ශ නොකර ඉතිරි කරයි, අනෙක් සෑම සමමුහුර්ත කිරීමේ අසාර්ථකත්වය (`invalid_signature`, `invalid_schema`, `stale`) ලෙසම විනාශකාරී නොවන රටාවම අනුගමනය කරයි.

## ස්තර: `community` සහ `live`

feed schema එකෙහි `tier: "community" | "live"` ක්ෂේත්රයක් අඩංගු වන අතර, එය ඉල්ලීම මත පදනම්ව (supporter key එක තිබීම සහ එහි වලංගුභාවය)
feed සේවාව විසින් **server-side** තීරණය කරනු ලැබේ
— client එක කිසිවිටෙකත් තමන්ගේම ස්තරය තීරණය නොකරයි.

- **`community`** — නවතම දත්තවලට වඩා ආසන්න වශයෙන් දින 30ක් ප්රමාද වූ නොමිලේ catalog එක. සත්යාපනය නොකළ හෝ වලංගු නොවන key එකක් සහිත ඉල්ලීමකට ලැබෙන්නේ මෙයයි.
- **`live`** — වලංගු supporter key එකක් සහිත ඉල්ලීම් සඳහා සපයනු ලබන නවතම catalog එක.

**වලංගු නොවන හෝ කල් ඉකුත් වූ supporter key එකක් `community` වෙත පහත වැටෙයි — එය කිසිවිටෙකත්
දෝෂයක් නොවේ.** sync මාර්ගය වෙන්කර හඳුනාගන්නේ signature/schema/version අසාර්ථකවීම් (සියල්ල
යථා තත්ත්වයට පත් කළ හැකි සහ cached state එකට මාරාන්තික නොවන ඒවා) සහ සාර්ථක `{ status:
"updated", version, tier }` ප්රතිඵලයක් පමණි. client එකකට හැසිරවීමට අවශ්ය ස්තර-විශේෂිත දෝෂ මාර්ගයක් නොමැත.

### සපයනු ලබන ස්තරය පැමිණෙන්නේ response header එකකින් මිස signed body එකෙන් නොවේ

   servers ද ආවරණය කරයි).
2. පියවර 1 කිසිවක් ලබා නොදෙන විට පමණක් signed body එකේ `tier` ක්ෂේත්රය (සැමවිටම `"live"`) වෙත fallback කරන්න.

## කියවීමේ වේලාව උඩැතිරි ඒකාබද්ධ කිරීමේ නීති

`applyFeed()` (`src/lib/radar/applyFeed.ts`) හැඹිලි සංග්‍රහය ඒකාබද්ධ කරයි** ඉවරයි** ස්ථිතික පදනම** කියවීමේ කාලය** , `getRadarCatalog()` ඇතුළත. මූලික අරාව (`FREE_MODEL_BUDGETS`) කිසිවිටෙක විකෘති වී නැත — a `MergedEntry[]` සෑම ඇමතුමකදීම නැවුම් ලෙස ගණනය කෙරේ.

ප්‍රමුඛතාවය අනුව නීති හතරක්:

1. **සංග්‍රහය කිසිවිටෙක දේශීය ප්‍රතික්‍ෂේප කිරීමක් උඩින් ලියන්නේ නැත.** එක් ක්ෂේත්‍රයකට: ක්‍රියාකරු ප්‍රවේශයක් මත ක්ෂේත්‍රයක් අභිරුචිකරණය කර ඇත්නම් (`localOverrides` සිතියම, යතුරු `provider:modelId`), එම නිශ්චිත ක්ෂේත්‍රය සඳහා සංග්‍රහයේ අගය — මඟ හරිනු ලැබුවහොත් ක්‍රියාකරුගේ අගය ජය ගනී.
2. **`enabled: false` ප්‍රවේශය අක්‍රීය කරයි.** ප්‍රවේශයක් ක්‍රියාවිරහිත කරන සංග්‍රහ ප්‍රවේශයක් ඒකාබද්ධ කළ ප්‍රතිඵලය මත `enabled: false` සහ `disabledBy: "radar"` සකසයි, එබැවින් UI හට _ඇයි_ ප්‍රවේශයක් ලබා ගත හැකි සිට ආබාධිත වෙත ගියේද යන්න පැහැදිලි කළ හැක.
3. **සංග්‍රහයේ නොමැති පරිශීලක-එක් කළ ප්‍රවේශයක් නොනැසී පවතී.** මූලික වශයෙන් පමණක් පවතින (හෝ දේශීයව එකතු කරන ලද) සහ අනුරූප සංග්‍රහ ප්‍රවේශයක් නොවෙනස්ව ගමන් කරයි.
4. **සොහොන් ගලක් සහිත ප්‍රවේශයක් කිසි විටෙකත් නැවත නැඟිටුවනු නොලැබේ.** ක්‍රියාකරු විසින් ප්‍රවේශයක් (`tombstones` කට්ටලයක්) පැහැදිලිව මකා දැමුවහොත්, එම `provider:modelId` පසු අනුවාදයක නැවත එකතු කරන සංග්‍රහය එය නැවත ගෙන එන්නේ නැත.

සංස්කරණය කළ හැකි ක්ෂේත්‍ර සහ සොහොන් ගල් `radar_local_model_state` (සංක්‍රමණ `153_radar_local_model_state.sql`) තුළ පවතී. පොදු DB ඇඩැප්ටරය (`src/lib/db/radar.ts`) එම පේළි `localOverrides` සිතියම සහ `applyFeed()` විසින් භාවිතා කරන `tombstones` කට්ටලය බවට පරිවර්තනය කරයි; ධජය, හැඹිලිය සහ ක්‍රම ගේට්ටු පසු කළ පසු සඳහන් වන නිෂ්පාදන `getRadarCatalog()` පැටවීම්. ක්‍රියාකරු-සංස්කරණය කළ හැක්කේ `displayName` සහ `enabled` පමණි. Provider/model අනන්‍යතාවය, සංග්‍රහ ඔප්පුව, කෝටාව, හැකියාවන්, ToS, සහ සැකසුම් දත්ත මෙම මතුපිට හරහා ලිවිය නොහැක.

උපකරණ පුවරුව දේශීය ක්‍රියා හතරක් නිරාවරණය කරයි:

- **සංස්කරණය කරන්න** දේශීය සංදර්ශක නාමය සහ සක්‍රීය තත්වය වෙනස් කරයි.
- **දේශීය වෙනස්කම් යළි පිහිටුවන්න** සොහොන් ගලක් වෙනස් නොකර සංස්කරණය කළ හැකි ක්ෂේත්‍ර දෙකම හිස් කරයි.
- **සඟවන්න** සොහොන් ගලක් නිර්මාණය කරයි, එබැවින් පසු සංග්‍රහ යාවත්කාලීන කිරීම්වලට පේළිය ප්‍රතිනිර්මාණය කළ නොහැක.
- **ප්‍රතිෂ්ඨාපනය කරන්න** සොහොන් ගල ඉවත් කරයි; වෙන වෙනම සුරකින ලද ඕනෑම ප්‍රතික්‍රියාවක් ක්‍රියාත්මක වේ.

සංග්‍රහයක් `enabled: false` ආරක්ෂිත ව්‍යතිරේකයක් ලෙස පවතී: එය පරණ දේශීය `enabled: true` මත ජයග්‍රහණය කරයි, ඒකාබද්ධ ප්‍රවේශය අක්‍රියව තබා ගනී, සහ `disabledBy: "radar"` වාර්තා කරයි.

නාමාවලි ප්‍රකාශන `schemaVersion: 2` භාවිතා කරයි. `contextWindow` සහ එක් එක් `tools`, `vision`, සහ `thinking` ස්වාධීනව `number | null` / `boolean | null`: `null` යනු නොදන්නා අතර `false` යනු D16-confirmed නිල සැපයුම්කරු මූලාශ්‍රය පැහැදිලිවම පවසන්නේ හැකියාව නොමැති බවයි. අභ්‍යන්තර OmniRoute registry/model-spec කොඩි කිසි විටෙකත් කරුණු පෝෂණය කිරීමට සෘජුවම ප්‍රවර්ධනය නොකෙරේ. සේවාදායකයා තවමත් v1 ස්නැප්ෂොට් පිළිගනී; පැරණි තනන්නා `false` නොපැමිණීමේ ස්ථාන රඳවනයක් ලෙස භාවිතා කළ නිසා, v1 `false` නොදන්නා ලෙස සාමාන්‍යකරණය කර ඇති අතර v1 `true` සත්‍යව පවතී. නොදන්නා යෝජනා ක්‍රම අනුවාද අසාර්ථක වන අතර අවසන් වලංගු හැඹිලිය පවතී. ශුන්‍ය නොවන context/capability සහිත සෑම v2 මාදිලියක්ම අක්තපත්‍ර රහිත HTTPS `metadataEvidenceUrls[]` රැගෙන යා යුතුය ; එසේ නොමැතිනම් schema වලංගු කිරීම අසාර්ථක වන අතර හැඹිලිය ප්‍රතිස්ථාපනය නොවේ. නාමාවලි වගුව `✓`, `✕` සහ `?` ලෙස අවස්ථා තුනම ලබා දෙයි.

### මාර්ගෝපදේශ සංයෝජන සහ MCP ප්‍රවේශය

තහවුරු කරන ලද `familyId` අගයන් කියවීමේ කාල ආවරණයෙන් බේරී පිරිසිදු `buildRadarComboSuggestions()` මොඩියුලය (`src/lib/radar/comboSuggestions.ts`) ධාවනය කරයි. පවුලක් යෝජනා කරනු ලබන්නේ අවම වශයෙන් වෙනස් සපයන්නන් දෙදෙනෙකුට සක්‍රිය සම්බන්ධතා ඇති විට සහ නිශ්චිත සැකසූ මාදිලිය හෙළිදරව් කළ විට පමණි ID. ආබාධිත ආකෘති, අක්‍රිය සපයන්නන්, අතුරුදහන් වූ මාදිලි IDs, singleton පවුල්, සහ අපැහැදිලි alias/prefix ගැලපීම් අසාර්ථකයි. යෝජනා දැනට පවතින `priority` උපාය මාර්ගය භාවිතා කරයි, පළමුව විශාලතම පුනරාවර්තන මාසික අයවැය ඇණවුම් කරයි; UI ඒවා නිර්මාණය කරන්නේ `POST /api/combos` හරහා පමණි.

මඟ පෙන්වන UI ජීවත් වන්නේ `/dashboard/radar/combos` හි ය. එය දේශීය `GET /api/radar/catalog` සහ `GET /api/combos/builder/options` අන්ත ලක්ෂ්‍ය පමණක් කියවයි. එය කිසි විටෙක රේඩාර් සමමුහුර්ත කිරීම, සපයන්නන්ගේ අක්තපත්‍ර කියවීම හෝ කොම්බෝ දත්ත ගබඩාවට කෙලින්ම ලිවීම සිදු නොකරයි.

MCP සේවාදායකයන්ට `omniroute_radar_catalog` (`read:radar`) සමඟ එකම දේශීය ප්‍රක්ෂේපණය කියවිය හැකිය. විකල්ප `provider`, `familyId`, සහ `enabledOnly` පෙරහන් එක් දේශීය `GET /api/radar/catalog` කියවීමකින් පසුව ඇගයීමට ලක් කෙරේ. එහි සංවෘත ප්‍රතිදානයට නාමාවලි පාරදත්ත සහ provider/model, සංදර්ශක නම, `familyId`, කෝටාව, හැකියාවන්, සක්‍රීය තත්ත්වය, සම්භවය සහ `disabledBy` ඇතුළත් වේ; පිහිටුවීම් URLs, පියවර, සම්බන්ධතා, විද්‍යුත් තැපැල් ලිපින, යතුරු සහ යොමු දත්ත කිසිවිටෙක ආපසු ලබා නොදේ. මෙම මෙවලම කියවීමට පමණක් වන අතර කිසි විටෙක `/api/radar/sync` ඉල්ලා නොසිටියි. හැඹිලි සංග්‍රහය ස්ථාපිත නාමාවලියට පෙරාතුව විට, `meta.olderThanRelease` යනු `true` වන අතර මෙවලම දේශීය ප්‍රතික්‍රියා සහ සොහොන් ගල් යොදන ලද ස්ථාපිත නාමාවලියෙන් ආකෘති ලබා දෙයි.

### ප්‍රභව සලකුණු

සෑම ඒකාබද්ධ ප්‍රවේශයක්ම `origin` ක්ෂේත්‍රයක් දරයි UI ලාංඡනයක් ලෙස ලබා දෙයි:

- `"baseline"` — ස්ථිතික නිකුතු නාමාවලියෙන් ස්පර්ශ නොකළ.
- `"radar"` — ක්ෂේත්‍ර එකක් හෝ කිහිපයක් සංග්‍රහය මගින් නැවුම් කරන ලදී.
- `"local"` — මෙම ප්‍රවේශය මත ක්‍රියාකරුට අවම වශයෙන් එක් දේශීය අභිබවා යාමක් ඇත (සංග්‍රහය කුමක් කීවත්, දේශීය අභිබවා යාම සෑම විටම 1 රීතියට අනුව සංග්‍රහය ජය ගනී).

## සංග්රහයක් ස්වයං-සත්කාරකත්වය කරන්නේ කෙසේද

නාමාවලිය පිළිබඳ පූර්ණ පාලනය අවශ්ය fork එකකට හෝ ස්වයං-සත්කාරකයෙකුට client කේතය
වෙනස් නොකර තමන්ගේම සංග්රහ සේවාවක් ධාවනය කළ හැකිය:

1. `RadarFeedSchema` (`src/lib/radar/feedSchema.ts`) සපුරාලන JSON body එකක් ආපසු ලබා දෙන
   `GET /v1/catalog/latest` endpoint එකක් සපයන්න — ඉහළ මට්ටමේ `feed:
"omniroute-radar"`, `schemaVersion: 2`, `version`, `tier`, `providers`, `models`,
   `quirks`, සහ `totals`. `x-omniroute-radar-schema: 2` අනුගමනය කරන්න; සංක්රාන්ති-අනුකූල server එකක්
   එය නොමැති ඉල්ලීම් සඳහා වෙනම අත්සන් කළ v1 artifact එකක් පෙරනිමිය ලෙස භාවිත කළ යුතුය.
2. Ed25519 key pair එකකින් නිශ්චිත response bytes අත්සන් කර, base64
   signature එක `x-omniroute-feed-signature` response header එක තුළ ආපසු ලබා දෙන්න.
3. `RADAR_FEED_URL` නව base URL එකටද `RADAR_FEED_PUBKEY` ඊට ගැළපෙන
   public key එකටද (base64-DER SPKI හෝ PEM) සකසන්න —
   [env var යොමුව](../reference/ENVIRONMENT.md#27-radar-feed-self-hosting) බලන්න.
4. `RADAR_ENABLED` සක්රීය කර `POST /api/radar/settings`
   (`{ optIn: true }`) හරහා සහභාගී වීමට තෝරන්න.

වෙනත් කිසිදු කේත වෙනසක් අවශ්ය නොවේ — `verifyFeedBytes()` විසින් override එක
ස්වයංක්රීයව භාවිත කරයි (`src/lib/radar/pinnedKeys.ts` තුළ `getFeedPublicKeys()`), සහ version
සැසඳීම, schema වලංගුකරණය, සහ merge නීති ස්වයං-සත්කාරක සංග්රහයකටද සමාන ලෙස අදාළ වේ.

Referral links (ඉහත [Referral links (නොමිලේ credits)](#referral-links-free-credits)
බලන්න) වෙනම, විකල්ප artifact එකකි: `/v1/catalog/latest` පමණක් සපයන fork එකක්
තවමත් සම්පූර්ණයෙන් ක්රියා කරයි — `/v1/referrals/latest` වෙතින් `404` ලැබුණු විට
