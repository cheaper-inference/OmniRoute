## ටැබ්

### සෙවුම් පටිත්ත

පවතින `SearchForm` + `ResultsPanel` + `RerankPanel` ටැබ් එකක් බවට පරිණාමය කරයි:

- → ප්‍රතිඵල විමසන්න (මාතෘකාව, URL, ස්නිපට්, අදාළ ලකුණු).
- වින්‍යාස කවුළුව තුළ සැපයුම්කරු පාර-දත්ත (පිරිවැය, කෝටාව, තත්ත්වය).
- නැවත ශ්‍රේණිගත කිරීම කොටස: නැවත ශ්‍රේණිගත කිරීමේ ආකෘතියක් තෝරන්න, ප්‍රතිඵල නැවත ඇණවුම් කරන්න, `positionDelta` පෙන්වන්න.
- සෙවුම් සපයන්නන් වින්‍යාස කර නොමැති විට CTA සමඟ හිස් තත්ත්වය.
- `SearchHistory.tsx` හරහා සෙවුම් ඉතිහාසය.
- ඇමතුම් `POST /v1/search` (පවත්නා අවසන් ලක්ෂ්‍යය, කිසිදු වෙනසක් නැත).

### Scrape Tab

`POST /v1/web/fetch` හරහා URL වෙතින් අන්තර්ගතය උකහා ගැනීම සඳහා නව ටැබය (සැලසුම් 05 හි සාදන ලදී):

- ආදානය: URL + සම්පූර්ණ පිටුව ටොගල් + ආකෘති තේරීම (markdown / text / HTML).
- ඉදිරිපත් කරන්න → ලබා ගන්න → විදැහුම්කරණය `ScrapeResult.tsx`.
- `ScrapeResult` විසින් markdown පෙරදසුන + raw toggle විදැහුම් කරයි.
- තොප්පිය: ප්‍රතිචාර ශරීරය > නම්** 256 KB** , UI `(truncated, view raw)` පෙන්වන අතර මොනාකෝ මාදිලියේ (D21) අමු ලෙස විවෘත කරයි.
- පාරදත්ත පැනලය: සපයන්නා (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search), ප්‍රමාදය, පිරිවැය, ප්‍රතිචාර ප්‍රමාණය, සබැඳි ගණන.
- `useScrapeFetch.ts` කොක්කක් භාවිතා කරයි.

### ටැබ් සංසන්දනය කරන්න

දක්වා එකම query/URL ධාවනය කරයි** 4 සපයන්නන් සමාන්තරව** (D22):

- එක් සපයන්නාට පැත්තෙන් පැත්තෙන් තීරු.
- ප්‍රමිතික: ප්‍රමාදය, පිරිවැය, ප්‍රතිඵල ගණන, ප්‍රතිචාර ප්‍රමාණය.
- සෙවීම සඳහාURL අතිච්ඡාදනය ගණනය කිරීම (බෙදාගත් URLs ගණන එදිරිව ආරම්භක ප්‍රතිඵලය).
- එක් සැපයුම්කරුවෙකුට `POST /v1/search` (සෙවීම) හෝ `POST /v1/web/fetch` (scrape) ලෙස ඇමතුම්.

## සපයන්නාගේ නාමාවලිය

`ProviderCatalog.tsx` `GET /api/search/providers` වෙතින් සම්පූර්ණ සැපයුම්කරුවන්ගේ ලැයිස්තුව හෙළිදරව් කරයි (සපයන්නන් ඇතුළත් කිරීමට F4 හි දීර්ඝ කර ඇත):

| `kind` | `"search"` (සැපයුම්කරුවන් 24) හෝ `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search, parallel-search, keenable-search) |

තත්ත්වය වේ** ඉල්ලීම් වේලාවට ව්‍යුත්පන්න කර ඇත** අක්තපත්‍ර තිබේද සහ සියලුම යතුරු දැනට සිසිල් වී තිබේද යන්න පරීක්ෂා කිරීමෙන්.

`codex-search` (Codex Web Search) හට තමන්ගේම යතුරක් නොමැත: එය සම්බන්ධිත Codex (ChatGPT) ගිණුමක් නැවත භාවිතා කරයි, එබැවින් සෑම සෙවුමකටම ChatGPT දායක කෝටාව වැය වන අතර තත්පර 10-40ක් පමණ ගත වේ. ඉල්ලීමක් එය නම් කරන විට එය ක්රියාත්මක වේ; ස්වයංක්‍රීය තේරීමට `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` විශේෂාංග ධජය අවශ්‍ය වේ (පෙරනිමියෙන් අක්‍රිය).

## පසුබිම් වෙනස්කම්

මෙම විශේෂාංගය සඳහා එක් පසුබිමක වෙනසක් පමණක් අවශ්‍ය විය:

### දිගු කළ `GET /api/search/providers`

`src/app/api/search/providers/route.ts` දක්වා දීර්ඝ කර ඇත:

- අරාව තුළ සෑම ලබාගන්නා සැපයුම්කරුවෙකුම (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`, `keenable-search`) ඇතුළත් කරන්න.
- සෑම අයිතමයකටම `kind: "search" | "fetch"` එකතු කරන්න.
- සජීවී අක්තපත්‍ර තත්ත්වයෙන් ලබාගත් `status: "configured" | "missing" | "rate_limited"` එක් කරන්න.
- පසුගාමී ගැළපුම — පවතින ක්ෂේත්‍ර (`id`, `name`, ආදිය) නොවෙනස්ව පවත්වා ගන්න.
