අභිරුචි ප්‍රොක්සි සත්කාරක ක්ෂේත්‍රය V2Ray මූලාශ්‍ර සබැඳියක් ද පිළිගනී. තෝරන්න** ගායනා පෙට්ටිය** හෝ** Xray** පැහැදිලිවම, පසුව සුරකින්න ක්ලික් කරන්න. ටයිප් කිරීම කිසි විටක හරයක් බාගැනීම හෝ ආරම්භ නොවේ. සුරැකීම නිල නිකුතු ලේඛනාගාරය සත්‍යාපනය කරයි, ස්වදේශීය වින්‍යාසය වලංගු කරයි, වෙනස් දේශීය සත්කාරක SOCKS සවන්දෙන්නෙකු ආරම්භ කරයි, සහ පසුව පමණක් ප්‍රොක්සි රෙජිස්ට්‍රි පැවරුම ලියයි. අසාර්ථක සක්‍රිය කිරීම පෙර කළමනා කළ වින්‍යාසය සහ ක්‍රියාවලිය ප්‍රතිසාධනය කරයි. `STORAGE_ENCRYPTION_KEY` අවශ්ය වේ; මූලාශ්ර සබැඳි සංකේතනය කර ඇත.

කළමනාකරණය කළ ගොනු `DATA_DIR/services/managed-proxy/` යටතේ සජීවීව, TPROXY වලින් වෙන්ව. තෝරාගත් හරයකට, සවන්දෙන්නන් 100ක් දක්වා එක් හිමිකාරී ක්‍රියාවලියක් ඇත. ස්වයංක්‍රීය ආරම්භයක් හෝ ගෝලීය මාර්ගගත කිරීමේ පෙරනිමියක් වෙනස් නොවේ. මෙම කළමනාකරණය කළ හරය සඳහා පමණක් සක්‍රිය කිරීම සාර්ථක සුරැකීම මතක තබා ගනී; යෙදුම් ආරම්භය දැනටමත් සත්‍යාපිත ද්විමය භාවිතයෙන් සක්‍රීය සුරකින ලද හරයන් ප්‍රතිසාධනය කරයි, කිසි විටක ඇරඹුම් කාල බාගත කිරීම නොවේ. පැහැදිලි නැවතුම එම සක්‍රිය ධජය හිස් කරයි. නැතිවූ හෝ හානි වූ ද්විමය සඳහා මූලාශ්‍රයක් නැවත සුරැකීම අවශ්‍ය වේ. රෙජිස්ට්රි මකාදැමීම දේශීයව මූලාශ්රය සහ සවන්දෙන්නා ඉවත් කරයි; සාමාන්‍ය අන්ත ලක්ෂ්‍ය සංස්කරණ කළමනාකරණය කළ පේළි සඳහා ප්‍රතික්ෂේප කරනු ලැබේ, එබැවින් සුරකින ලද මූලාශ්‍රයට එහි මාර්ගගත ශ්‍රාවකයා වෙතින් නිහඬව ප්ලාවිත විය නොහැක.

`/api/services/managed-proxy` සත්‍යාපනය කර ඇති අතර ලූප්බැක්-පමණි: GET නැවත සකස් කරන ලද පාර-දත්ත ලැයිස්තුගත කරයි, POST `{core,name,sourceLink,id?,assignment?}` සුරකියි, PATCH `{core,action:"start"|"stop"}` පිළිගනී. ධාරකයාගේ විශ්වාසවන්ත සම-මුද්දර නල මාර්ගය තිබිය යුතුය. අක්තපත්‍ර අඩංගු විය හැකි බැවින් දේශීය මූලික රෝග විනිශ්චය යටපත් කරනු ලැබේ; ජීවන චක්‍ර සිදුවීම් මූලාශ්‍ර සබැඳි හෝ උඩුගත ගෙවීම් නොමැතිව පවතින ව්‍යුහගත යෙදුම් ගොනු ලොගර් භාවිතා කරයි. සහාය සඳහා සනීපාරක්ෂක යෙදුම් ලොග පමණක් අමුණන්න. නිල අනුවාද sing-box 1.14.3 සහ Xray 26.3.27 නිකුතු-වත්කම් SHA-256 මැනිෆෙස්ට් සමඟ අමුණා ඇත; අනාගත යාවත්කාලීන කිරීම් සඳහා අනුවාදය සහ සියලුම සත්‍යාපිත සංග්‍රහයන් එකට වෙනස් කිරීම අවශ්‍ය වේ.

`ServiceSupervisor` හි මතකය-තුළ තත්ත්වයෙහි ද පිළිබිඹු කෙරේ. ක්රියාත්මක වන
ක්රියාවලියක් සඳහා මතකය-තුළ තත්ත්වය බලධාරී මූලාශ්රය වේ; ආරම්භයේදී DB තත්ත්වය
ස්ථිර විකල්ප මූලාශ්රය වේ.

| `starting`      | සෞඛ්ය සම්පන්න වීමට පෙර ක්රියාවලිය පිටවේ | `error`                   |

### මෙහෙයුම් අගුල

`ServiceSupervisor`, async මෙහෙයුම් අගුලක් (`withLock()`) හරහා ජීවන චක්ර
මෙහෙයුම් අනුක්රමික කරයි. එකම supervisor එක මත සමගාමී `start()` ඇමතුම් සිදු කළ
විට හරියටම එක් ක්රියාවලි නිර්මාණයක් පමණක් සිදු වේ; දෙවන කැඳවුම්කරු රැඳී සිට
පවතින තත්ත්වය ආපසු ලබා දෙයි. උදාහරණයක් ලෙස, ස්වයංක්රීය ආරම්භය සහ UI බොත්තමක්
එකවර ක්රියාත්මක වන විට ඇති විය හැකි ධාවන තත්ත්ව ගැටුම් මෙය වළක්වයි.

## 4. API යොමුව

`/api/services/` යටතේ ඇති සියලුම මාර්ග වේ**LOCAL_ONLY** (ලූප්බැක් පමණි, දෘඪ රීතිය #17). ලූප්බැක් නොවන ඉල්ලීම් සත්‍යාපන ටෝකනය නොසලකා `403 LOCAL_ONLY` ලැබේ.

### 4.1 9රවුටර් අන්ත ලක්ෂ්‍ය (මාර්ග 11)

#### `POST /api/services/9router/install`

npm සිට 9Router ස්ථාපනය කරන්න. එහිම `package.json` සහ `node_modules/` සමඟ `DATA_DIR/services/9router/` නිර්මාණය කරයි. OmniRoute ගේම deps සමග ගැටෙන්නේ නැත.

**ශරීරය ඉල්ලන්න** (සියල්ල විකල්ප):

```json
{ "version": "latest" }
```

| ක්ෂේත්රය  | ටයිප් කරන්න | පෙරනිමිය   | විස්තරය                                  |
| --------- | ----------- | ---------- | ---------------------------------------- |
| `version` | `string`    | `"latest"` | ස්ථාපනය කිරීමට npm අනුවාද ටැගය හෝ semver |

**ප්‍රතිචාර:**

| තත්ත්වය | විස්තරය                                                      |
| ------- | ------------------------------------------------------------ |
| `200`   | `{ ok: true, installedVersion: "x.y.z", path: "..." }`       |
| `400`   | වලංගු නොවන ඉල්ලීම් අන්තර්ගතය (Zod වලංගු කිරීමේ අසාර්ථකත්වය)  |
| `409`   | දැනටමත් ස්ථාපනය කරමින් (අගුලු තබා ඇත)                        |
| `500`   | npm ස්ථාපනය අසාර්ථක — මිත්‍රශීලී දෝෂයක් සඳහා `message` බලන්න |

**සටහන්:** `execFile('npm', [...])` — කිසිඳු කවචයක්, මැදිහත්වීමක් නොමැත (දෘඪ රීතිය #13). EACCES දෝෂ මිත්‍රශීලී පණිවිඩ ලෙස මතු වේ.

#### `POST /api/services/9router/start`

9 රවුටරය ආරම්භ කරන්න. දැනටමත් ලියාපදිංචි වී නොමැති නම් අධීක්ෂකවරයෙකු ලියාපදිංචි කරයි, පසුව `supervisor.start()` අමතන්න. දැනටමත් ධාවනය වන විට Idempotent.

**ඉල්ලීම ශරීරය:** කිසිවක් නැත

**ප්‍රතිචාර:**

| තත්ත්වය | විස්තරය                                                  |
| ------- | -------------------------------------------------------- |
| `200`   | `ServiceStatus` වස්තුව (පහත යෝජනා ක්‍රමය බලන්න)          |
| `409`   | 9Router ස්ථාපනය කර නැත (`status: "not_installed"`)       |
| `503`   | ආරම්භය අසාර්ථක විය (ක්‍රියාවලි දෝෂය — බලන්න `lastError`) |

**ServiceStatus යෝජනා ක්රමය:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

#### `POST /api/services/9router/stop`

9 රවුටරය අලංකාර ලෙස නවත්වන්න. SIGTERM යවයි, තත්පර 15ක් බලා සිටී, පසුව ජීවතුන් අතර නම් SIGKILL. දැනටමත් නතර වූ විට Ideempotent.

**ඉල්ලීම ශරීරය:** කිසිවක් නැත

**ප්‍රතිචාර:**

| තත්ත්වය | විස්තරය                             |
| ------- | ----------------------------------- |
| `200`   | `ServiceStatus` (රාජ්ය: "නැවතුම්")  |
| `503`   | අනපේක්ෂිත ලෙස නතර කිරීම අසාර්ථක විය |

#### `POST /api/services/9router/restart`

**ඉල්ලීම ශරීරය:** කිසිවක් නැත

**ශරීරය ඉල්ලන්න** (සියල්ල විකල්ප):


| `200`   | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400`   | වලංගු නොවන ශරීරය                                                |
| `500`   | npm යාවත්කාලීන කිරීම අසාර්ථක විය                                |

#### `POST /api/services/9router/rotate-key`

| පරම      | ටයිප් කරන්න | පෙරනිමිය    | විස්තරය                                                     |

| `tail`   | `integer`   | 200         | මුලින්ම යැවිය යුතු ඓතිහාසික රේඛා කීයක් (උපරිම 1000)         |
| `filter` | `string`    | කිසිවක් නැත | කේස්-සංවේදී නොවන උප තන්තු පෙරහන (regex — ReDoS-ආරක්ෂිත නැත) |

**SSE සිදුවීම්:**

| `snapshot`  | `LogLine[]` | ආරම්භක ඓතිහාසික වලිගය                |

**LogLine යෝජනා ක්රමය:**

```json

```

**ප්‍රතිචාර:**

| තත්ත්වය | විස්තරය                                     |
| ------- | ------------------------------------------- |
| `200`   | `text/event-stream`                         |
| `400`   | `filter` පරාමිතිය දිග වැඩියි (> අක්ෂර 200)  |

### 4.2 CLIProxyAPI අන්ත ලක්ෂ්‍ය (මාර්ග 10)

CLIProxyAPI 9Router minus `rotate-key`, plus `accounts`, `provider-expose` සහ `auto-restart-adopted` වැනි අවසාන ලක්ෂ්‍ය හැඩයම ඇත. එයට දැන් ස්පාන් හිදී එන්නත් කරන ලද කැපවූ දත්ත-තලය API යතුරක් ලැබේ ( `bootstrap.ts` හි`needsApiKey: true`, ආකෘති සමමුහුර්ත කිරීම සඳහා භාවිතා කරයි); `status` අඩු ක්ෂේත්‍ර ඇතුළත් වේ.

| ක්රමය  | මාර්ගය                              | විස්තරය                                  |
| ------ | ----------------------------------- | ---------------------------------------- |
| `POST` | `/api/services/cliproxy/install`    | npm සිට CLIProxyAPI ස්ථාපනය කරන්න        |
| `POST` | `/api/services/cliproxy/start`      | CLIProxyAPI ආරම්භ කරන්න                  |
| `POST` | `/api/services/cliproxy/stop`       | CLIProxyAPI නවත්වන්න                     |
| `POST` | `/api/services/cliproxy/restart`    | CLIProxyAPI නැවත ආරම්භ කරන්න             |
| `POST` | `/api/services/cliproxy/update`     | නව අනුවාදයට යාවත්කාලීන කරන්න             |
| `GET`  | `/api/services/cliproxy/status`     | සජීවී + DB තත්ත්වය ( `apiKeyMasked` නැත) |
| `POST` | `/api/services/cliproxy/auto-start` | ස්වයංක්‍රීය ආරම්භය ටොගල් කරන්න           |

බෙදාගත් `GET /api/services/{name}/logs` අන්ත ලක්ෂ්‍යය (§4.1 බලන්න) `[name]` ගතික කොටස භාවිතා කරමින් සේවා හතරම සඳහා ක්‍රියා කරයි.

**සයිඩ්කාර් ගිවිසුම:** සේවාදායක ස්ක්‍රිප්ට් `GET /health` (ක්ෂණික — ආකෘතිය මත රැඳී නොසිටියි) සහ `POST /compress` (`{ text, rate }` → `{ text, compressed, ratio }`) නිරාවරණය කරයි. පළමු `/compress` ඇමතුමේදී ආකෘතිය කම්මැලි ලෙස පටවනු ලැබේ.

**සම්පීඩන රැහැන්:** `open-sse/services/compression/engines/llmlingua/index.ts` හි `httpSidecarBackend` `LLMLINGUA_BASE_URL` (පෙරනිමි `http://127.0.0.1:20135`) අමතයි සහ ආදානයට වඩා දැඩි ලෙස කෙටි වූ විට පමණක් පැති රථයේ ප්‍රතිචාරය පිළිගනී; කිසියම් අසාර්ථකත්වයක් (ධාවනය නොවීම, කල් ඉකුත්වීම, කිසිදු ප්‍රතිචාරයක් නොමැත) ක්‍රියාවලියේ සේවක-නූල් පසුපෙළ (`./worker.ts`) වෙත ආපසු වැටේ.

### 4.9 ප්‍රතිලෝම ප්‍රොක්සි (9 රවුටර උපකරණ පුවරුව කාවැද්දීම)

උපකරණ පුවරුව 9Router web UI අභ්‍යන්තර ප්‍රතිලෝම ප්‍රොක්සියක් හරහා iframe එකක් තුළට කාවැද්දුවේ:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

මෙම ප්‍රොක්සි:

- ඉල්ලීම `http://127.0.0.1:{port}/{path}` වෙත යොමු කරන්න (ලූප්බැක් පමණි)
- එන `cookie` සහ `authorization` ශීර්ෂ තීරු තීරු ( OmniRoute සැසිය කාන්දු නොවේ)
- 9Router සත්‍යාපනය සඳහා `Authorization: Bearer {apiKey}` එන්නත් කරයි
- ප්‍රතිචාරයෙන් `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` තීරු
- `<base href>` එන්නත් කිරීමට සහ නිරපේක්ෂ මාර්ග සාමාන්‍යකරණය කිරීමට HTML ප්‍රතිචාර නැවත ලියයි (`/foo` → `/dashboard/.../embed/foo`)

කාවැද්දූ උපකරණ පුවරුව සඳහාWebSocket උත්ශ්‍රේණිගත කිරීම් කැපවූ වරායක සහකාර සේවාදායකයක් විසින් හසුරුවනු ලැබේ ( `src/lib/services/embedWsProxy.ts` බලන්න).

**ආරක්ෂාව:** කාවැද්දූ ප්‍රොක්සි මාර්ග `LOCAL_ONLY_API_PREFIXES` යටතේ වර්ග කර ඇති අතර ලූප්බැක් වෙතින් පමණක් ළඟා විය හැක. Cloudflare/Ngrok උමං මාර්ගයක් හරහා JWT ලබා ගන්නා ප්‍රහාරකයෙකුට කාවැද්දූ සේවාවන් වෙත ප්‍රොක්සි විය නොහැක.

## 5. ආරක්ෂාව

### LOCAL_ONLY බලාත්මක කිරීම (දැඩි රීතිය #17)

`/api/services/` සහ `/dashboard/providers/services/*/embed/` යටතේ ඇති සියලුම routes,
`src/server/authz/routeGuard.ts` තුළ LOCAL_ONLY ලෙස වර්ගීකරණය කර ඇත. ඕනෑම auth
ශාඛාවකට පෙර loopback පරීක්ෂාව කොන්දේසි විරහිතව ක්රියාත්මක වේ:

```
ඉල්ලීම පැමිණේ
  → isLocalOnlyPath(path)?
      → loopback නොවේ → 403 LOCAL_ONLY (සෑම විටම, auth පරීක්ෂාවට පෙර)
      → loopback වේ   → සාමාන්ය auth වෙත ඉදිරියට යයි
```

මෙමගින් කාන්දු වූ JWT එකකට (උදා., tunnel එකක් හරහා) `npm install` හෝ
process spawning ක්රියාත්මක කිරීම වළක්වයි. සම්පූර්ණ tier matrix එක සඳහා
`docs/security/ROUTE_GUARD_TIERS.md` බලන්න.

### API key ඇතුළත් කිරීම

9Router සහ Mux හිම HTTP endpoints සඳහා API key/bearer token එකක් අවශ්ය වේ.
OmniRoute:

1. සේවාවට විශේෂිත prefix එකක් (`nr_` 9Router සඳහා, `mx_` Mux සඳහා) සමඟ
   `crypto.randomBytes(32).toString("base64url")` හරහා key එකක් ජනනය කරයි.
2. AES-256-GCM භාවිතයෙන් එය at-rest ආකාරයෙන් සංකේතනය කරයි (provider credentials
   සඳහා භාවිත කරන cipher එකම වේ).
3. spawn කරන අවස්ථාවේ එය විකේතනය කර environment variable එකක් ලෙස ඇතුළත් කරයි —
   9Router සඳහා `NINEROUTER_API_KEY`, Mux සඳහා `MUX_SERVER_AUTH_TOKEN` (කිසිවිටෙක CLI
   flag එකක් ලෙස නොවේ; එම නිසා token එක `ps`/process ලැයිස්තුගත කිරීම්වල කිසිවිටෙක
   නොපෙනේ).
4. කිසිදු HTTP response එකක plaintext key එක කිසිවිටෙක ආපසු ලබා නොදෙයි.

CLIProxyAPI වෙත spawn කරන විට ඇතුළත් කරන වෙන් කළ data-plane key එකක් ලැබේ
(`needsApiKey: true` — adapter එකට එරෙහි model sync කිරීම සඳහා භාවිත වේ).

### SSRF ආරක්ෂණය

Reverse HTTP proxy එක (`/dashboard/.../embed/[...path]`) ඉල්ලීම් ඉදිරියට යැවීමට
`http://127.0.0.1:{port}` පමණක් භාවිත වන ලෙස hardcode කර ඇත. එය loopback නොවන
ගමනාන්ත වෙත යන redirects කිසිවිටෙක අනුගමනය නොකරයි. Loopback පරාසයෙන් පිටතට resolve
වන ඕනෑම upstream URL එකක් ප්රතික්ෂේප කිරීමට `ssrf-req-filter` library එක භාවිත කරයි.

### Shell ආරක්ෂාව (දැඩි රීතිය #13)

`npm install` කැඳවනු ලබන්නේ `execFile('npm', ['install', pkg, '--prefix', dir])` හරහාය —
template literals, shell එකක්, හෝ command string එක තුළට බාහිර paths interpolate කිරීමක්
නොමැත. Runtime අගයන් (ports, API keys) child process එකේ `env` object එක හරහා යවනු ලැබේ.

### Error පිරිසිදු කිරීම (දැඩි රීතිය #12)

`/api/services/*` වෙතින් ලැබෙන සියලුම error responses, `buildErrorBody()` හෝ
`sanitizeErrorMessage()` හරහා යයි. අමු `err.stack` සහ `err.message` කිසිවිටෙක
caller වෙත ඒ ආකාරයෙන්ම ආපසු ලබා නොදෙයි.

## 6. නව embedded service එකක් එක් කිරීම

මෙම පියවර 8 අනුගමනය කරන්න. ප්රමිතිය ලෙස අනුගමනය කළ යුතු canonical reference එක
වශයෙන් `src/lib/services/installers/` සහ `src/app/api/services/` තුළ ඇති දැනට පවතින
implementations කියවන්න.

### පියවර 1 — Installer එක සාදන්න

`ninerouter.ts` ආදර්ශයට ගනිමින් `src/lib/services/installers/{name}.ts` සාදන්න:

```typescript
export const NAME_PACKAGE = "your-npm-package";
export const NAME_DEFAULT_PORT = 20132; // භාවිතයේ නොමැති port එකක් තෝරන්න

export async function install(version = "latest"): Promise<InstallResult> { ... }
export async function update(version = "latest"): Promise<InstallResult> { ... }
export async function uninstall(): Promise<void> { ... }
export function resolveSpawnArgs(apiKey: string, port: number): SpawnArgs { ... }
export async function getInstalledVersion(): Promise<string | null> { ... }
export async function getLatestVersion(): Promise<string | null> { ... }
```

`installers/utils.ts` වෙතින් `runNpm(['install', NAME_PACKAGE, '--prefix', dir])`
භාවිත කරන්න — `execSync` හෝ shell interpolation කිසිවිටෙක භාවිත නොකරන්න.

### පියවර 2 — Bootstrap තුළ ලියාපදිංචි කරන්න

`src/lib/services/bootstrap.ts` හි `SERVICES` array එකට `ServiceEntry` එකක් එක් කරන්න:

```typescript
{
  tool: "myservice",
  port: NAME_DEFAULT_PORT,
  healthPath: "/health",
  healthIntervalMs: 5_000,
  stopTimeoutMs: 15_000,
  logsBufferBytes: 5_242_880,
  needsApiKey: true, // API key එකක් අවශ්ය නොවේ නම් false
}
```

`cfg.tool === "myservice"` හසුරුවන ලෙස `buildSpawnArgsFactory()` පුළුල් කරන්න.

#### සම්බන්ධ කළ හැකි provider-plugin contract එක (Phase 1, #7333)

`src/lib/services/providerPlugins/` මඟින් backend එකක `bootstrap.ts` හි `ServiceEntry`
fields සහ `serviceBackends.ts` හි manifest-template fields, එකිනෙකට සම්බන්ධ නොවන files
දෙකක එකම backend එකේ ව්යුහය වෙන වෙනම ප්රකාශ කිරීම වෙනුවට, තනි object එකකට අසුරන
`ServiceProviderPlugin` contract එකක් හඳුන්වා දෙයි. මෙය ලියන අවස්ථාව වන විට
**`9router` පමණක් migrate කර ඇත** — `bootstrap.ts`, එහි `SERVICES[]` entry එක
`getServiceProviderPlugin("9router")` (`src/lib/services/providerPlugins/registry.ts`)
වෙතින් ලබා ගන්නා අතර plugin එක නොමැති වුවහොත් startup error එකක් throw කරයි.
`cliproxy`, `mux`, සහ `bifrost` වෙනස් කිරීමකින් තොරව පෙර පැවති inline `SERVICES[]`
literals මතම පවතී.

`open-sse/config/providerPluginManifest.ts` වෙත
`SERVICE_BACKEND_MANIFEST_TEMPLATE` entry එකකින් නිසි ලෙස සැකසූ
`ProviderPluginManifestEntry` එකක් ගොඩනඟන additive
`createServiceBackendManifestEntry(pluginId, template)` helper එකක්ද එක් කර ඇත —
එය තවමත් කිසිදු සජීවී request path එකකට සම්බන්ධ කර **නොමැත**
(`generateProviderPluginManifestFromRegistry()` හෝ `/v1/providers/[provider]/models`
යන දෙකටම නොවේ); දෙවන backend එකක් සඳහා contract එක තහවුරු කළ පසු එය follow-up
කාර්යයක් ලෙස පවතී.

Issue #7333 යටතේ නිරීක්ෂණය වන follow-up PRs වෙත කල් දැමූ කාර්යයන්: එකම registry එක
හරහා `cliproxyapi` migrate කිරීම, `mux`/`bifrost` `ServiceBackendPluginId` union එකට
සාමාන්යකරණය කිරීම, executor-routing සඳහා ඇති විශේෂ අවස්ථා හැසිරවීම
(`open-sse/executors/index.ts`, `open-sse/handlers/chatCore/executorProxy.ts`) plugin
contract එක තුළට ඒකාබද්ධ කිරීම, සහ `createServiceBackendManifestEntry()` සජීවී
manifest/models code path එකකට සම්බන්ධ කිරීම.

### පියවර 3 — Migration සහ DB seed එක එක් කරන්න

`src/lib/db/migrations/` හි migration එකක් හරහා සේවාවට `version_manager` තුළ row එකක්

### පියවර 4 — API endpoints 7 සාදන්න

`src/app/api/services/{name}/` යටතේ:

```
_lib.ts            getOrInitSupervisor() helper එක
install/route.ts   POST — installer.install() කැඳවයි
start/route.ts     POST — supervisor.start() කැඳවයි
stop/route.ts      POST — supervisor.stop() කැඳවයි
restart/route.ts   POST — supervisor.restart() කැඳවයි

status/route.ts    GET  — සජීවී + DB තත්ත්වය ඒකාබද්ධ කරයි
```

අවශ්ය නොවේ.

සියලු දෝෂ ප්රතිචාර `createErrorResponse()` / `buildErrorBody()` හරහා පවරන්න.

### පියවර 5 — LOCAL_ONLY_API_PREFIXES වෙත එක් කරන්න

`src/server/authz/routeGuard.ts` තුළ `/api/services/` දැනටමත් ලැයිස්තුගත කර ඇති බව තහවුරු කරන්න.
ඔබ නව prefix එකක් හඳුන්වා දෙන්නේ නම් (උදා., `/api/tools/`), එය
`LOCAL_ONLY_API_PREFIXES` වෙතත්, එය processes ආරම්භ කරන්නේ නම් `SPAWN_CAPABLE_PREFIXES` වෙතත් එක් කරන්න.
`tests/unit/authz/routeGuard.test.ts` තුළ test එකක් එක් කරන්න.

### පියවර 6 — UI tab එක එක් කරන්න

`src/app/(dashboard)/dashboard/providers/services/tabs/{Name}ServiceTab.tsx` සාදන්න.
හවුල් components නැවත භාවිත කරන්න:

### පියවර 7 — provider entry එක එක් කරන්න (service එක routing target එකක් නම්)

embedded service එක OpenAI-අනුකූල `/v1/chat/completions` endpoint එකක් සපයන්නේ නම්:

1. `src/shared/constants/providers.ts` තුළ `isEmbeddedService: true` සහිත provider entry එකක් එක් කරන්න.
2. `BaseExecutor` දිගු කරන `open-sse/executors/{name}.ts` සාදන්න. එක් එක් request එක සඳහා port එක සහ
   API key එක නැවත සොයන්න (constructor එක තුළ කිසිවිටෙක cache නොකරන්න). supervisor තත්ත්වය `"running"` නොවන විට
   `503 service_not_running` ප්රතිචාරයක් ලබා දෙන්න.
3. service prefix එක සමඟ `open-sse/config/providerRegistry.ts` තුළ models ලියාපදිංචි කරන්න
   (උදා., `myservice/sub/model`). `modelSync.ts` ඒවා යාවත්කාලීනව තබා ගනී.

## 7. දෝෂ නිරාකරණය

### සේවාව ආරම්භ නොවේ

**ලක්ෂණ:** ආරම්භ කිරීමේ බොත්තම 503 ප්රතිචාරයක් ලබා දෙයි, තත්ත්වය `"error"` හෝ `"starting"` ලෙසම පවතී.

**පිරික්සුම් ලැයිස්තුව:**

1. `GET /api/services/{name}/logs` පරීක්ෂා කරන්න (නැතහොත් උපකරණ පුවරුවේ Logs පැනලය). `Error: ENOENT`, `address already in use`, හෝ `Cannot find module` වැනි පේළි සොයන්න.
2. `npm` PATH තුළ ඇති බව තහවුරු කරන්න: OmniRoute ධාවනය කරන එම පරිශීලක ගිණුමෙන් `which npm` ධාවනය කරන්න.
3. සේවාව ස්ථාපනය කර ඇති බව තහවුරු කරන්න: `installedVersion` සඳහා `GET /api/services/{name}/status` පරීක්ෂා කරන්න. එය `null` නම්, පළමුව ස්ථාපනය ධාවනය කරන්න.
4. `DATA_DIR/services/{name}/node_modules/` පවතින බවත් එය හිස් නොවන බවත් පරීක්ෂා කරන්න.
5. පිරිසිදු කරන ලද පිටවීමේ හේතුව සඳහා තත්ත්ව ප්රතිචාරයේ `lastError` ක්ෂේත්රය පරීක්ෂා කරන්න.

### ශීත ආරම්භය මන්දගාමී වේ (`running` වෙත ළඟා වීමට > 10 s)

**ලක්ෂණ:** `"running"` හෝ `"error"` වෙත යාමට පෙර තත්ත්වය දිගු වේලාවක් `"starting"` ලෙසම පවතී.

**පැහැදිලි කිරීම:** 9Router හි ශීත ආරම්භයට විශාල පරායත්තතා වෘක්ෂ (DNS,
tunnel, MITM මොඩියුල) ආයාත කිරීම ඇතුළත් වේ. අධීක්ෂකය කාල සීමාව ඉක්මවා ගිය බව ප්රකාශ කිරීමට පෙර පෙරනිමි සෞඛ්ය පරීක්ෂණ අන්තරය 2 s වන අතර උත්සාහ 3ක් සිදු කරයි (නමුත් විමසීම දිගටම කරගෙන යයි).

**විසඳුම:** `healthIntervalMs` සහ `waitForHealthy` කාල සීමාව
(`healthIntervalMs * 3`) `bootstrap.ts` තුළ වින්යාස කළ හැකිය. දිගු ආරම්භක කාලයක් ඇති සේවා සඳහා,
`healthIntervalMs` 5000 දක්වාත් `stopTimeoutMs` 30 000 දක්වාත් වැඩි කරන්න.

### පෝට් ගැටීම (`EADDRINUSE`)

**ලක්ෂණ:** ලොග්වල `address already in use :::20130` පෙන්වයි.

**හේතු:**

- වෙනත් ක්රියාවලියක් දැනටමත් 20130 පෝට් එක භාවිත කරයි.
- පෙර 9Router ක්රියාවලියක් සම්පූර්ණයෙන් නතර කර නොමැත (zombie PID).

**විසඳුම:**

1. `.env` හි `NINEROUTER_PORT` පරිසර විචල්යය හරහා පෙරනිමි පෝට් එක වෙනස් කරන්න.
2. ගැටෙන ක්රියාවලිය සොයා අවසන් කරන්න: `lsof -ti :20130 | xargs kill -9`.
3. `port` ක්ෂේත්රය හරහා `bootstrap.ts` තුළ එක් එක් සේවාව සඳහා පෝට් එක වින්යාස කළ හැකිය.

**සටහන:** OmniRoute හි පෙරනිමි පෝට් එක වන 20128 සමඟ ගැටීම වැළැක්වීම සඳහා 9Router විශේෂයෙන් 20130 පෝට් එක පෙරනිමිය ලෙස භාවිත කරයි.

### ස්ථාපනයේදී අවසර ප්රතික්ෂේප වීම (EACCES)

**ලක්ෂණ:** ස්ථාපනය 500 ප්රතිචාරයක් ලබා දෙයි, ලොග්වල `EACCES` හෝ `permission denied` පෙන්වයි.

**හේතු:**

- `DATA_DIR` හෝ එහි මව් නාමාවලියට OmniRoute ක්රියාවලිය මඟින් ලිවිය නොහැක.
- සිතියම්ගත කළ වොලියුමයට ලිවීමේ ප්රවේශය නොමැතිව rootless Docker තුළ ධාවනය කිරීම.

**විසඳුම:**

1. `DATA_DIR` පරීක්ෂා කරන්න (පෙරනිමිය: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. OmniRoute ක්රියාවලියේ පරිශීලකයාට නාමාවලියේ හිමිකාරිත්වය ඇති බව තහවුරු කරන්න: `chown -R $USER ~/.omniroute/`
3. Docker තුළ, බහාලුම් පරිශීලකයා සඳහා වොලියුම් මවුන්ට් එකට නිවැරදි අවසර ඇති බව තහවුරු කරන්න.

### යාවත්කාලීන කිරීම අසාර්ථක වේ (`npm install` කාල සීමාව ඉක්මවීම හෝ ජාල දෝෂය)

**ලක්ෂණ:** යාවත්කාලීන කිරීම `InstallError` සමඟ 500 ප්රතිචාරයක් ලබා දෙයි, ලොග්වල ජාල කාල සීමාව ඉක්මවීමක් පෙන්වයි.

**පිරික්සුම් ලැයිස්තුව:**

1. npm registry වෙත ළඟා විය හැකි බව තහවුරු කරන්න: `npm ping`.
2. ආයතනික proxy එකක් තිබේදැයි පරීක්ෂා කරන්න: `npm config get proxy`, `npm config get https-proxy`.
3. ස්ථාපනය අතින් උත්සාහ කරන්න: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. air-gap එකක් පිටුපස සිටී නම්, tarball එක කලින් බාගත කර `npm install /path/to/tarball.tgz` භාවිත කරන්න.

### ආරම්භ කළ වහාම සේවාව `"error"` තත්ත්වය පෙන්වයි (වේගවත් බිඳවැටීම)

**ලක්ෂණ:** තත්ත්වය තත්පර 5කට අඩු කාලයකදී `"starting"` සිට `"error"` වෙත සංක්රමණය වේ.
`lastError` මඟින් `"Fast crash (exited with code 1)"` පෙන්වයි.

**පිරික්සුම් ලැයිස්තුව:**

1. සම්පූර්ණ ලොග් අවසාන කොටස කියවන්න: `GET /api/services/{name}/logs?tail=500`.
2. පොදු හේතුව: සේවාව අපේක්ෂා කරන පරිසර විචල්ය නොමැති වීම.
3. 9Router සඳහා: `NINEROUTER_DISABLE_MITM=true` සහ
   `NINEROUTER_DISABLE_TUNNEL=true` ක්රියාවලිය බිහි කරන විට ලබා දෙන env තුළ ඇති බව තහවුරු කරන්න (
   `installers/ninerouter.ts` හි `resolveSpawnArgs` බලන්න).

## 8. නිතර අසන ප්රශ්න

**ප්ර: කාවැද්දූ සේවාවල අන්ත ලක්ෂ්ය loopback නොවන සේවාලාභීන්ට නිරාවරණය කළ හැකිද?**

නැත. LOCAL_ONLY මට්ටම හිතාමතාම පනවා ඇත (දැඩි රීතිය #17). `npm install` ක්රියාත්මක කළ හැකි හෝ `node` ක්රියාවලි ආරම්භ කළ හැකි මාර්ග loopback නොවන ගමනාගමනයෙන් ප්රවේශ විය නොහැකි විය යුතුය. එසේ නොවුවහොත්, උමඟක් (Cloudflare, Ngrok, Tailscale) හරහා JWT එකක් කාන්දු වීමෙන් අත්තනෝමතික ක්රියාවලි ආරම්භ කිරීමට ඉඩ ලැබේ. `/api/services/` සඳහා මෙයින් බැහැර වීමේ විකල්පයක් නොමැත — `/api/mcp/` මෙන් නොව, එය manage-scope මඟහැරීමේ ලැයිස්තුවෙන් බැහැර කර ඇත. `docs/security/ROUTE_GUARD_TIERS.md` බලන්න.

ඔව්. සේවා දෙකම OmniRoute මෙන්ම local-first ආකෘතිය අනුගමනය කරයි. ඒවා එකම යන්ත්රයේ ක්රියාත්මක වන අතර loopback හරහා සන්නිවේදනය කරයි. මෙහි "නිෂ්පාදන" යන්නෙන් අදහස් කරන්නේ OmniRoute යොදවා ඇති VPS හෝ දේශීය සේවාදායකය මිස දුරස්ථ වලාකුළු සැපයුම්කරුවෙකු නොවේ.

---

**ප්ර: supervisor එක දෝෂහරණය කරන්නේ කෙසේද?**

1. SSE ලොග් ප්රවාහයේ අවසානය සජීවීව නිරීක්ෂණය කරන්න: `curl -N http://localhost:20128/api/services/9router/logs`.
2. `service:supervisor` namespace අනුව පෙරහන් කළ OmniRoute හි pino ප්රතිදානයේ ව්යුහගත ලොග් පරීක්ෂා කරන්න.
3. DB පේළිය පරීක්ෂා කරන්න: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. වත්මන් සජීවී තත්ත්වය, PID, සෞඛ්යය සහ `lastError` එකම ඇමතුමකින් බැලීමට `GET /api/services/9router/status` භාවිත කරන්න.

---

**ප්ර: supervisor එක `health: "degraded"` හෝ `health: "unknown"` පෙන්වන නමුත් තත්ත්වය `"running"` වේ. එය ගැටලුවක්ද?**

`"degraded"` යන්නෙන් අදහස් කරන්නේ සෞඛ්ය පරීක්ෂණයෙන් 200 නොවන ප්රතිචාරයක් ලැබුණු බවයි. `"unknown"` යන්නෙන් අදහස් කරන්නේ තවමත් කිසිදු පරීක්ෂණයක් සම්පූර්ණ වී නොමැති බවයි (පළමු poll කිරීම සමඟ ඇති race තත්ත්වයක්). ආරම්භයේදී මේ දෙකම තාවකාලික වේ. `"running"` වූ පසු `healthIntervalMs * 3` ms කට වඩා සෞඛ්ය තත්ත්වය `"degraded"` ලෙස පවතී නම්, කාවැද්දූ සේවාව ක්රියාත්මක වන නමුත් එහි HTTP API එක ප්රතිචාර නොදක්වයි. තත්ත්ව ප්රතිචාරයේ port එක නිවැරදිද සහ සේවාව සැබවින්ම එම port එකේ සවන්දෙමින් සිටීද යන්න පරීක්ෂා කරන්න.

---

**ප්ර: සම්පූර්ණයෙන් නැවත ආරම්භ කිරීමකින් තොරව 9Router API යතුර වෙනස් කළ හැකිද?**

නැත. API යතුර 9Router වෙත යවනු ලබන්නේ ක්රියාවලිය ආරම්භ කරන අවස්ථාවේ environment variable එකක් හරහාය. ක්රියාත්මක වෙමින් පවතින ක්රියාවලියක environment variables වෙනස් කළ නොහැක. නව යතුර යෙදීම සඳහා `POST .../rotate-key` ස්වයංක්රීයව සේවාව නවත්වා නැවත ආරම්භ කරයි. යතුරු මාරු කිරීම සේවාවේ `stopTimeoutMs` (පෙරනිමියෙන් 15 s) සහ එහි ආරම්භක කාලය ඇතුළත ක්රියාත්මක වේ.

**ප්ර: ring buffer සීමාව කුමක්ද, එය පිරුණු විට සිදු වන්නේ කුමක්ද?**

සෑම සේවාවකටම වෙන්වූ 5 MB ring buffer එකක් ඇත. buffer එක පිරුණු විට, නව ලොග් පේළි සඳහා ඉඩ සැලසීමට පැරණිතම ලොග් පේළි ඉවත් කරනු ලැබේ. SSE `snapshot` සිදුවීම `tail` සීමාව තුළ ඇති වඩාත්ම මෑත පේළි ආපසු ලබා දෙයි. DB පේළියේ `logsBufferPath` සකසා නොමැති නම් ලොග් තැටියට ස්ථිරව සුරැකෙන්නේ නැත.
