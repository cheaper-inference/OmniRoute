## දළ විශ්ලේෂණය

Quota Sharing Engine එකම සම්බන්ධතාව බෙදාගන්නා API යතුරු කිහිපයක් අතර සැපයුම්කරුවෙකුගේ කාලය මත පදනම් වූ කෝටාව (උදා: Codex
පැය 5 ක කවුළුව, Kimi පැයකට ඉල්ලීම් 1500) සාධාරණව බෙදාහරියි.

**එය විසඳන ගැටලුව:** OmniRoute එකම upstream සැපයුම්කරුගේ ගිණුමට එරෙහිව API යතුරු රැසක් ප්රොක්සි කරයි. බෙදාගැනීමේ තර්කනයක් නොමැතිව, A යතුරෙන් පැමිණෙන ඉල්ලීම් ප්රවාහයක් පැය සඳහා වූ සැපයුම්කරුගේ කෝටාව අවසන් කළ හැකි අතර, කවුළුව යළි සැකසෙන තෙක් B සහ C යතුරු අවහිර වී පවතී.
එන්ජිම මෙය වළක්වන්නේ:

1. එක් එක් මානය අනුව සෑම යතුරකම චලිත පරිභෝජනය (%, ඉල්ලීම්, ටෝකන, $) නිරීක්ෂණය කිරීමෙනි.
2. කාර්ය-සංරක්ෂණ සාධාරණ-කොටස් ඇල්ගොරිතමයක් යෙදීමෙනි: ගෝලීය සංචිතය සන්තෘප්ත වී නොමැති අතරතුර යතුරකට අක්රිය කොටස්වලින් ණයට ගත හැක.
3. ඉල්ලීම upstream ක්රියාත්මක කරන්නා වෙත ළඟාවීමට පෙර hot path එකෙහි (`chatCore.ts`) ප්රතිඵලය බලාත්මක කිරීමෙනි.

## ඇල්ගොරිතම: සාධාරණ-බෙදාගැනීමේ වැඩ-සංරක්‍ෂණය

`src/lib/quota/fairShare.ts` හි ක්රියාත්මක කර ඇත.

### මාදිලි

| තත්ත්වය                                    | මාදිලිය        | හැසිරීම                                                |
| ------------------------------------------ | -------------- | ------------------------------------------------------ |
| `globalUsedPercent < saturationThreshold`  | **නිර්ලෝභී ය** | යතුර මුළු පරිභෝජනයෙන් අඩු ගෝලීය සීමාව දක්වා ණයට ගත හැක |
| `globalUsedPercent >= saturationThreshold` | **දැඩි**       | පුද්ගල සාධාරණ කොටස දැඩි ලෙස බලාත්මක කරන්න              |

පෙරනිමි `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`).

මෙම මාතයන් දෙක පෙරනිමි ණය ගැනීමේ මාදිලියේ සංචිතයක් විස්තර කරයි, `saturation`. සංතෘප්තිය කුමක් වුවත්, `consent` මාදිලියේ සංචිතයක් සෑම විටම දැඩි නීති අදාළ කරයි. [එකඟ වූ ණය දීම බලන්න (එක් තටාකයකට තේරීමට)](#consented-lending-per-pool-opt-in).

### මානයන් තීරණය

තටාකයේ එක් එක් ක්‍රියාකාරී මානයන් සඳහා, එන්ජිම ගණනය කරන්නේ:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = current rolling value for this key (from QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

`percent` මානයන් සඳහා, `consumed` ඒ වෙනුවට ආරෝපණ පොතෙන් පැමිණේ ( [ප්‍රතිශතයේ මානයන් බලන්න: එක්-යතුරු ආරෝපණය](#percent-dimensions-per-key-attribution) ).

එවිට:

- **`policy = hard`** : `consumed > fairShareAllowed` සහ මාදිලිය දැඩි → නම්** අවහිර කරන්න** .
- **`policy = soft`** : `consumed > fairShareAllowed` සහ මාදිලිය දැඩි → නම්** දඬුවම් කරන්න** (combo දී deprioritize; කවදාවත් hard-block).
- **`policy = burst`** : සාධාරණ කොටස නොසලකා ගෝලීය ප්‍රධාන කාමරය පවතින අතරතුර ඉඩ දෙන්න.

### කැප් අබ්සොලූටෝ

වෙන් කිරීමක් මත `capValue` + `capUnit` යනු මාදිලියෙන් හෝ ප්‍රතිපත්තියෙන් ස්වාධීන දෘඪ සිවිලිමකි. `consumed >= capValue` සෑම විටම ඕනෑම මානයක්** කුට්ටි** ඉල්ලීම. `percent` cap සඳහා, `consumed` යනු යතුරට ආරෝපණය කර ඇති කොටස පමණි.

### බහු-මාන පරීක්ෂාව

ඉල්ලීමක් අවහිර කර තිබේ නම්** ඕනෑම** තටාකයේ මානය එය අවහිර කරනු ඇත. මානයන් ස්වාධීන — a 5h% වෙහෙස සතිපතා% මානයට බලපාන්නේ නැත.

### ණය ගන්නවා

ත්‍යාගශීලී ප්‍රකාරයේදී, අඩුවෙන් පරිභෝජනය කරන යතුරකට වෙනත් යතුරුවල වෙන් නොකළ කොටස්වලින් අතිරික්තය භාවිතා කළ හැක. සූත්රය යනු:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

කොහෙද `consumedByOtherKeys = consumedTotal - consumedByThisKey`. ටෙටෝ ගෝලීය (එම මානය සඳහා තටාකය `limit` ) සෑම විටම දෘඩ සිවිලිම වේ.

### එකඟ වූ ණය දීම (එක් තටාකයකට තෝරා ගැනීම)

සෑම සංචිතයකටම ණය ගැනීමේ මාදිලියක් ඇත. `saturation` පෙරනිමිය වන අතර ඉහත නීති රීති තබා ගනී. `consent` මාදිලියේදී `hard` යතුරක් එහි කොටස ලබා දෙන්නේ අනෙකුත් යතුරු ණයට දීමට එකඟ වූ ධාරිතාවය තුළ පමණි. පරිපාලක විසින් එක් එක් තටාකයේ මාදිලිය සකසයි. සෑම යතුරු දරන්නෙකුම [ණය දීමේ කැමැත්ත](#lending-consent) හරහා තමන්ගේම කැමැත්ත සකසයි.

කැමැත්තක් යනු 0 සිට 100 දක්වා ප්‍රතිශතයක් වන අතර යුග මිලි තත්පර වල විකල්ප කාල සීමාවකි. යතුර එහි නිෂ්ක්‍රීය කොටසේ එම ප්‍රතිශතය නියමිත කාලසීමාව අනාගතයේදී ලබා දෙයි.

එක් මානයක් සඳහා, `L` යනු ඵලදායි සීමාවයි: සැලැස්ම සීමාව සංචිතයේ ගිණුම් වාර ගණන. ඉල්ලන යතුර සඳහා ගේට්ටුව ගණනය කරයි:

```
share_k         = w_k / 100 × L
idle_k          = max(0, share_k − consumed_k)
lent            = Σ over the other keys of lend_k / 100 × idle_k
taken           = Σ over the other keys of max(0, consumed_k − share_k)
borrowAvailable = max(0, lent − taken)
```

`w_k` යනු යතුරේ බරයි, නැතහොත් 0ට වඩා වැඩි බරක් නොමැති විට සෑම යතුරක් සඳහාම `100 / n` `lend_k` යනු යතුරේ ක්‍රියාකාරී ප්‍රතිශතය වන අතර එහි කාලසීමාව පසු වූ පසු 0 වේ. ඉල්ලා සිටින යතුරගේම කැමැත්ත කිසිවිටෙක ගණන් නොගනී. `hard` යතුරක් එහි පරිභෝජනය එහි කොටස සහ `borrowAvailable` වෙත ළඟා වූ පසු එය ප්‍රතික්ෂේප කරනු ලැබේ.

කිසිදු ප්‍රතිපාදනයක් හිමිකම් නොකියන ධාරිතාව (බරවල එකතුවෙන් අඩු 100ක්) ණයට දිය නොහැක. එය ණයට දීමට කිසිදු යතුරක් එකඟ නොවීය.

**උදාහරණය.** `L` යනු 1000 කි.

| යතුර | බර  | බෙදාගන්න | පරිභෝජනය කළා | ණයට දෙයි |
| ---- | --- | -------- | ------------ | -------- |
| ඒ    | 50  | 500      | 530          | 0%       |
| බී   | 30  | 300      | 100          | 50%      |
| සී   | 0   | 0        | 60           | 0%       |

- B එහි නිෂ්ක්‍රීය 200න් 50%ක් ණයට දෙයි, එනම් 100. C දැනටමත් එහි කොටසට වඩා 60ක් ලබාගෙන ඇත. A 40ක් ණයට ගත හැක.
- A 530ට සේවය කරන අතර එහි පරිභෝජනය 540ට ළඟා වූ පසු එය ප්‍රතික්ෂේප කරයි.
- C ඕනෑම දෙයක් භාවිතා කිරීමට පෙර, A සමඟ එහි කොටසෙහි හෝ ඊට පහළින්, C 100 ණයට ගත හැකිය.
- C ඕනෑම දෙයක් භාවිතා කිරීමට පෙර, A සමඟ 530, C 70 ණයට ගත හැකිය.

**ශුන්ය බර.** බර 0 සහිත යතුරක කොටස 0 කි. එය සේවය කරනු ලබන්නේ එහි පරිභෝජනය අන් අය ණයට දෙන ප්‍රමාණයට වඩා අඩු වන විට පමණි. කිසිවකු ණය නොදෙන විට එය පළමු ඉල්ලීමෙන් ප්‍රතික්ෂේප වේ.

**නියමිත කාලසීමාවන්.** කිසිදු පසුබිම් කාර්යයක් කැමැත්තෙන් කල් ඉකුත් නොවේ. සෑම ඉල්ලීමක්ම නියමිත කාලසීමාව තමන්ගේම කාලය සමඟ සංසන්දනය කරන අතර එම කාලයට සමාන කාල සීමාවක් ගෙවී ඇත. පරිමිත සංඛ්‍යාවක් නොවන හෝ `Date` තබාගත හැකි විශාලතම දිනය පසුකර ඇති ගබඩා කරන ලද කාල සීමාවක් සම්මත වූ ලෙස ගණන් ගනී.

**`soft` සහ `burst`.** ණය දීම ඒවා සීමා නොකරයි. `soft` යතුරක් එහි කොටස ඉක්මවා ගිය පසු අහිමි වේ. තටාකයේ ඉඩ ඇති අතරතුර `burst` යතුරක් ගමන් කරයි. තටාකයේ මුළු සීමාව එහි සීමාවට ළඟා වූ පසු තටාක සිවිලිම තවමත් සෑම යතුරක්ම ප්‍රතික්ෂේප කරයි.

**ඉල්ලීම් මාර්ගයේ පිරිවැය.** `saturation` සංචිතයක් පෙරට වඩා වැඩි යමක් කියවන්නේ නැත. `consent` සංචිතයක, ගණන් කළ හැකි මානයක් අනෙක් යතුරු කියවනු ලබන්නේ එහි කොටසෙහි හෝ ඊට ඉහළින් ඇති `hard` යතුරක් සඳහා පමණක් වන අතර තවත් යතුරක් ණයට දෙයි. එවිට එය සමාන්තරව, අනෙක් යතුරට එකක් කියවීමට සලස්වයි. අසාර්ථක කියවීමක් එම යතුර සඳහා 0 පරිභෝජනයක් ලෙස ගණන් ගනී. `percent` මානයක් කියවීමක් එක් නොකරයි, මන්ද ආරෝපණ පොත සෑම යතුරක්ම දරයි.

**සංචිතයක් සංස්කරණය කිරීම.** සංස්කරණයක් රැඳී සිටින යතුරුවල කැමැත්ත තබා ගනී. මෙය ප්‍රතිපාදන සංස්කරණ, සමූහ-පුළුල් ප්‍රතිස්ථාපන සහ `ensure` ඇමතුම් සඳහා පවතී. ඉවත් කළ යතුරකට එහි කැමැත්ත අහිමි වන අතර, නැවත එකතු කරන ලද යතුරක් 0 න් ආරම්භ වේ. පරිපාලක මාර්ග එක් එක් යතුරේ කැමැත්ත ආපසු ලබා දෙන අතර එය කිසි විටෙක නොලියයි. සංචිතයක් නැවත `saturation` වෙත මාරු කිරීම ගබඩා කර ඇති සෑම කැමැත්තක්ම තබා ගනී, එය එම ප්‍රකාරයට බලපෑමක් නැත. සංචිතය `consent` වෙත මාරු කිරීම කාලසීමාව ඉක්මවා නොමැති ගබඩා කර ඇති කැමැත්ත නැවත සක්‍රිය කරයි. යතුරු දරන්නෙකුට ඕනෑම ආකාරයකින් ගබඩා කළ කැමැත්ත ඉවත් කළ හැකිය.

**උත්ශ්‍රේණි කිරීම.** `lending_percent` සහ `lending_until` තීරු දැනටමත් පවතී නම්, සංක්‍රමණය `borrow_mode` පමණක් එකතු කරයි, සහ ගබඩා කළ ප්‍රතිශත ඒවා පවතින ආකාරයටම පවතී. සෑම තටාකයක්ම `saturation` ආකාරයෙන් ආරම්භ වේ. තටාක විශාරදයේ එක් තටාකයකට `consent` ක්‍රියාත්මක කරන්න. ගබඩා කර ඇති අගයන්ගෙන් කිසිවක් අනුමාන නොකෙරේ.

**සීමාවන්.**

- ණය දෙන්නෙකුට තමාගේම කොටස භාවිතා කිරීමට පෙර එහි සිවිලිමේ තටාකය සොයාගත හැකිය. අනෙක් අය ණයට ගත් ධාරිතාව සංචිතයේ එකතුවට ගණන් ගනී.
- චෙක්පත ඉල්ලීමට පෙර ක්‍රියාත්මක වන අතර කිසිවක් වෙන් නොකරයි. සමගාමී ඉල්ලීම් කිසිවක් වාර්තා කිරීමට පෙර පරිභෝජනය කියවන අතර, එම නිසා ණයට ලබා දුන් ධාරිතාව පියාසර කිරීමේදී ඉල්ලීම්වලට සීමා වී එක් වරකට වඩා වැය කළ හැකිය. `saturation` මාදිලියේ කොටස් චෙක්පත එකම දේපල ඇත.

## ස්ලයිඩින් කවුළු ගණකය

`src/lib/quota/sqliteQuotaStore.ts` සහ `redisQuotaStore.ts` තුළ ක්රියාත්මක කර ඇත.

එක් එක් `(apiKeyId, dimensionKey)` සඳහා බකට් දෙකක් ඇත:

- `curr`: වත්මන් බකට් එක (`floor(nowMs / windowMs)`)
- `prev`: පෙර බකට් එක (`curr - 1`)

ඵලදායී චලිත අගය:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**නිරවද්යතාව**: ~99% ක් නිරවද්යයි. බකට් අතර සීමාවේදී දෝෂය උපරිම වශයෙන් කවුළු ප්රමාණයෙන් 1% කි (බකට් 2 ආසන්නකරණයට ආවේණිකය).

### සමකාලීනත්වය

SQLite ධාවකය: එක් එක් `(apiKeyId | dimensionKey)` යතුර සඳහා ඇති මතකය තුළ mutex එක, read-modify-write තරඟ තත්ත්වය වළක්වයි. රටාව `src/sse/services/auth.ts` හි anti-thundering-herd රටාව පිළිබිඹු කරයි.

Redis ධාවකය: පරමාණුක වර්ධනය සඳහා Lua EVAL ස්ක්රිප්ට් එකක් භාවිත කරයි — එය තනි Redis විධානයක් ලෙස ක්රියාත්මක වේ.

## ධාවක

### SQLite (පෙරනිමි, ස්ථාපනය අවශ්ය නොවේ)

- වගුව: `quota_consumption` (`073_quota_pools.sql` / `074_quota_consumption.sql` සංක්රමණ බලන්න).
- තනි-instance යෙදවීම් සඳහා වඩාත් සුදුසුය.
- සියලුම ස්ථායී දත්ත පවතින OmniRoute SQLite DB (`DATA_DIR/storage.sqlite`) තුළ ඇත.

### Redis (විකල්ප, බහු-instance)

- `ioredis` npm පැකේජය අවශ්ය වේ.
- ගණක Redis තුළ ගබඩා කෙරේ; පාරදත්ත (පූල්/වෙන් කිරීම්) තවමත් SQLite තුළ පවතී.
- ගණක හුවමාරු කරගත යුතු බහු-replica යෙදවීම් සඳහා වඩාත් සුදුසුය.

### ධාවක මාරු කිරීම

සැකසුම් UI (`/dashboard/settings` → කෝටා ගබඩාව) හරහා, හෝ env විචල්ය හරහා:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

DB සැකසුමට env සැකසුමට වඩා ප්රමුඛතාව ඇත. `driver=redis` නමුත් URL එක නොමැති නම් හෝ
`ioredis` ස්ථාපනය කර නොමැති නම්, factory එක SQLite වෙත ආපසු හැරී අනතුරු ඇඟවීමක් ලොග් කරයි.

ධාවක තේරීමේ අනුපිළිවෙළ:

1. DB සැකසුම `quotaStore.driver`
2. Env `QUOTA_STORE_DRIVER`
3. පෙරනිමිය: `sqlite`

## බහු-මාන

තටාකයකට බහු මානයන් තිබිය හැක. සෑම මානයක්ම ස්වාධීන වේ:

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // global pool ceiling for this dimension
}
```

**උදාහරණය: Codex සැලැස්ම** (5h% + සතිපතා%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

ඉල්ලීමක් අවසර දීමට සියලු මානයන් සපුරාලිය යුතුය.

6. **එකම රූපය:** රූපය, මූලික සහ ලකුණු රැඳී පවතී. පොතේ නොමැති නැවත සැකසීමේ කාලයක් පමණක් ලියා ඇත.
7. **පහළ රූපය:** පහත රූපයක් කිසි විටෙක යෙදෙන්නේ නැත. එය පොත පෙරළන්නේ කරුණු තුනක් රඳවා ගත් විට පමණි. එය අවසන් වරට යෙදූ කියවීමට වඩා අවම වශයෙන් මිනිත්තු දෙකක් අලුත් ය. කවුළුව එකම විවෘත එකක් බව කිසිවක් නොකියයි. එය එක් ලක්ෂයකට වඩා අඩුය.

කරුණු තුනක් අල්ලාගෙන සිටින විට කවුළුව එකම විවෘත එකක් ලෙස ගණන් ගනී. යළි පිහිටුවීමේ වේලාවන් දෙකම දනී. ඔවුන් එකිනෙකාගෙන් විනාඩි 30 ක් ඇතුළත. ගබඩා කළ එක තවමත් කියවීමට වඩා ඉදිරියෙන් සිටී. එම කවුළුව තුළ පහළ රූපයක් කිසිවක් වෙනස් නොකරයි.

යළි පිහිටුවීමේ වේලාවක් ගබඩා වන්නේ එය රැගෙන යන කියවීමේ දත්ත වේලාවට වඩා ඉදිරියෙන් සිටින විට පමණි. ඉහළ අගයක් එය භාවිතා කළ හැකි විට එහි කියවීමේ යළි පිහිටුවීමේ කාලය ගබඩා කරයි, සහ වෙනත් ආකාරයකින් ගබඩා කර තබා ගනී. සමාන රූපයක් එහි කියවීමේ නැවත සැකසීමේ වේලාව සටහන් කරන්නේ පොතේ කිසිවක් නොමැති විට පමණි. එය අන් කිසිවක් වෙනස් නොවේ. පොත පෙරළන්නේ නැති පහළ අගයක් යළි පිහිටුවීමේ වේලාවක් වාර්තා නොකරයි.

#### පොත භාවිතා කරන විට

කියවීමෙන් පසු, එහි ගබඩා කර ඇති යළි පිහිටුවීමේ කාලය වත්මන් වේලාවෙන් පසුව නොවේ නම් මිස පොත භාවිතා වේ. එම අවස්ථාව පැන නගින්නේ, යළි පිහිටුවීමට මොහොතකට පෙර ගත්, හැඹිලියෙන් සේවය කළ එකක් වැනි කියවීමක් ඊට පසුව නිරීක්ෂණය කළ විටය.

භාවිතා කළ හැකි කියවීමකින් තොරව, ගබඩා කර ඇති පොත භාවිතා කරනු ලබන්නේ එය වත්මන් කවුළුවේ පොත විය හැකි විට පමණි. එය අවස්ථා දෙකකදී පවතී:

- එහි යළි පිහිටුවීමේ කාලය දන්නා අතර තවමත් ඉදිරියෙන් ඇත
- එයට යළි පිහිටුවීමේ වේලාවක් නොමැති අතර, එය වෙනස් කළ අවසන් කියවීම උපරිම වශයෙන් මිනිත්තු 15ක් පැරණිය

එසේ නොමැති නම් පොතක් නොමැති විට මෙන් කිසිවක් ආරෝපණය නොකෙරේ. ගබඩා කළ යළි පිහිටුවීමේ කාලය ගෙවී ගිය පොතක් කිසිවිටෙක අය නොකෙරේ.

#### බලාත්මක කිරීම

සියයට මානයක යතුරක පරිභෝජනය එහි ආරෝපණය කරන ලද කොටස සහ බාහිර කොටසෙහි කොටසකි. බාහිර කොටස ප්‍රථමයෙන් ධාරිතාව ප්‍රතිපාදන හිමිකම් නොමැති (බරවල එකතුවෙන් අඩු 100) භාවිතා කරයි. අතිරික්තය පමණක් බර අනුව යතුරු අතර බෙදා ඇත.

එම පරිභෝජනය වෙනත් ඕනෑම මානයක් සඳහා යතුරේ සාධාරණ කොටස සමඟ සංසන්දනය කෙරේ. සංතෘප්ත සංඥාව `QUOTA_SATURATION_THRESHOLD` (පෙරනිමි 0.5) වෙත ළඟා වන විට දැඩි මාදිලිය තවමත් ආරම්භ වේ. සෑම සංඛ්‍යාවක්ම ඵලදායි සීමාවෙන් පරිමාණය කෙරේ: එක් ගිණුමකට සීමාව සංචිතයේ ඇති ගිණුම් සංඛ්‍යාව මෙන් වැඩි වේ.

`capUnit: "percent"` සහිත නිරපේක්ෂ තොප්පියක් ගණන් කරන්නේ යතුරට ආරෝපණය කර ඇති කොටස පමණක් වන අතර එය එකම ආකාරයකින් පරිමාණය කර ඇත. එක් ගිණුමකට 100 සහ k ගිණුම් සීමාවක් ගන්න. සේවා ගිණුමේ රූපයේ යතුරේ කොටස N/k ලක්ෂ්‍ය කරා ළඟා වූ විට N හි තොප්පියක් ළඟා වේ. සෑම ගිණුමක්ම තමන්ගේම පොතෙන් පරීක්ෂා කරනු ලැබේ. උදාහරණයක් ලෙස, ගිණුම් දෙකක් සමඟ, 10 ක සීමාවක් එක් ගිණුමක රූපයේ ලකුණු 5 ට ළඟා වේ.

ගබඩාව කියවිය නොහැකි විට, කිසිවක් ආරෝපණය නොකරන අතර සෑම යතුරක්ම එම මානය මත 0 ආරෝපණය වේ. පොතක් ලිවීම අසාර්ථක වූ විට, එම ආරෝපණය පොත කියවූ ආකාරයටම භාවිතා කරයි. අසාර්ථක වූ ටෝකනයක් ලිවීමෙන් එම ඉල්ලීමේ ටෝකන පොතෙන් ඉවත් වේ. මෙම අසාර්ථක කිසිවක් ඉල්ලීමක් අවහිර නොකරයි.

## නල මාර්ග ඒකාබද්ධ කිරීම

### PRE කොක්ක (`open-sse/handlers/chatCore.ts`)

සත්‍යාපනය සහ ප්‍රතිපත්ති පිරික්සුම් වලින් පසුව, upstream executorට පෙර ධාවනය වේ:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → getQuotaStore().peek() per dimension
      → fairShare.decideFairShare()
      → if block → return 429 (buildErrorBody, Hard Rule #12)
      → if allow + deprioritize → set quotaSoftPenalty=true on candidate
  → executor.execute()
```

**අසාර්ථක-විවෘත** : `enforceQuotaShare` විසි කරන්නේ නම්, ඉල්ලීම `pino.warn` ලොගයක් සමඟින් අවසර දෙනු ලැබේ. මෙය කෝටා-එන්ජින් දෝෂයක් සියලු ගමනාගමනය අවහිර කිරීමෙන් වළක්වයි.

**ධාරිතාව නැවත පැමිණෙන විට.** යතුරේ කොටසෙහි හෝ තටාකයේ සිවිලිමෙහි ප්‍රතික්ෂේප කිරීම, ණය ගැනීමේ ක්‍රම දෙකෙහිම වාක්‍ය දෙකෙන් එකකින් අවසන් වේ:

- `percent` කවුළුව: `. The <window> window resets at <time>.` සැපයුම්කරු වාර්තා යළි පිහිටුවීමේ වේලාව වේ.
- ගණන් කළ හැකි ඒකකය: `. Enough <window> usage is expected to clear by <time>.` යතුර වෙනත් කිසිවක් නොයවන්නේ නම්, කාලය ස්ලයිඩින් කවුළුවෙන් ඉහළ සීමාවකි.

`<time>` යනු UTC හි ISO 8601 ක්ෂණික වේ. ප්‍රතික්ෂේප කිරීම පසුව `Retry-After` දරයි : එම ක්ෂණික වන තෙක් මුළු තත්පරය, ප්ලස් එක. දිගු වේලාවක් බලා සිටින සේවාදායකයෙක් ක්ෂණිකව තත්පරයකට පසුව නැවත උත්සාහ කරයි. ක්ෂණිකව නොදන්නා විට, ප්‍රතික්ෂේප කිරීම වාක්‍යය හෝ ශීර්ෂය ගෙන නොයයි. නිරපේක්ෂ තොප්පිය ප්‍රතික්ෂේප කිරීම එකක්වත් ගෙන යන්නේ නැත. පොදු කේතය `quota_share_blocked` පවතී.

කොටස් ප්‍රතික්ෂේප කිරීමක් හවුල් සම්බන්ධතාවය ස්පර්ශ නොකරයි. එය සිසිල් කිරීමක්, ආදර්ශ අගුලක් සහ සැපයුම්කරු බ්‍රේකර් අසමත්වීමක් සකසන්නේ නැත, සහ තටාකයේ අනෙකුත් යතුරු දිගටම සේවය කරයි. කොම්බෝ එකක සෑම ඉලක්කයක්ම එහි කොටස සඳහා යතුර ප්‍රතික්ෂේප කරන විට, කොම්බෝ නොසිට 429 ට පිළිතුරු දෙයි. එහි පිළිතුර `Retry-After` ලෙස ඉඟිය දරයි. කාවැද්දීම් මාර්ගය එහි ප්‍රතික්ෂේප කිරීම එම වාක්‍යයෙන්ම අවසන් කරන අතර `Retry-After` නොයවයි.

### POST කොක්ක (වාර්තා පරිභෝජනය)

සාර්ථක ප්‍රතිචාරයකින් පසු:

```
executor returns success
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → getQuotaStore().consume() per dimension
      → fail-open: errors logged as pino.warn, never propagated to client
```

**ප්ලාවිත සටහන** : `consume` පසු ප්‍රතිචාරය අසාර්ථක වුවහොත්, රෝලිං කවුන්ටරය අඩුවෙන් ගණන් ගනී. සැපයුම්කරුගේ සන්තෘප්ත සංඥාව (උදා: `anthropic-ratelimit-unified-5h-utilization`) ඊළඟ ඉල්ලීම මත ගෝලීය ඇස්තමේන්තුව නිවැරදි කරයි.

### Combo soft penalty (`open-sse/services/combo.ts`)

`decision.deprioritize === true` විට:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // default 0.7
}
```

අනෙකුත් සියලුම ලකුණු සාධක වලට පසුව දඩුවම යොදනු ලැබේ. එය දැඩි අවහිරයකින් තොරව සංතෘප්ත යතුරක් තෝරාගැනීමේ ස්වයංක්‍රීය සංයෝජන සම්භාවිතාව අඩු කරයි.

## ස්වයං-සේවා කෝටාව API (තෝරාගැනීම)

`GET /api/v1/me/quota/{provider}` ( `/v1/me/quota/{provider}` හිදීද සේවය කර ඇත) API යතුරු දරන්නෙකුට තමන්ගේ යතුර සමඟ, හවුල් දායකත්වයක් කොපමණ ප්‍රමාණයක් ඔවුන්ගේද සහ ඒවා අවහිර කරන්නේ කුමක්ද යන්න කියවීමට ඉඩ දෙයි. මාර්ගය `src/server/selfService/quotaHandler.ts` ට වඩා තුනී කවචයකි; දර්ශනය `src/lib/quota/selfView.ts` විසින් ගොඩනගා ඇති අතර එහි ප්‍රතිචාර කොන්ත්‍රාත්තුව `src/shared/schemas/selfQuota.ts` (`SelfQuotaView` හි `docs/openapi.yaml`) වේ.

### සක්රීය කිරීම සහ සත්යාපනය

- විශේෂාංග කොඩිය `QUOTA_SELF_PANEL`, පෙරනිමි `false`. එය ක්‍රියාවිරහිතව තිබියදී, මාර්ගය වෙත ළඟා වන ඉල්ලීමකට 404 ලැබේ. `REQUIRE_API_KEY=true` සමඟින්, සේවාලාභියා API ප්‍රතිපත්තිය ධජය කුමක් වුවත්, මාර්ගය ධාවනය වීමට පෙර 401 සමඟ නැතිවූ හෝ අවලංගු යතුරක් ප්‍රතික්ෂේප කරයි. යතුරක් නොමැති නමුත් පුරනය වී ඇති උපකරණ පුවරු සැසියක් සහිත ඉල්ලීමක් එම ප්‍රතිපත්තිය සමත් වන අතර මාර්ගයේ ම පිළිතුර ලබා ගනී. ධජය අනෙකුත් සෑම ධජයක්ම මෙන් විසඳයි (උපකරණ පුවරුව හෝ REST ප්‍රතික්‍ෂේප කිරීම, පසුව එකම නමේ පරිසර විචල්‍යය); [`FEATURE_FLAGS.md`](../reference/FEATURE_FLAGS.md) බලන්න.

- `sharedQuotaProviders` යනු එක්-යතුරක් සැකසීමකි (`PUT /api/keys/[id]/self-service`): `null`, පෙරනිමිය, යතුර ළඟා වන සෑම සැපයුම්කරුවෙකුම අදහස් කරයි; `[]` යනු කිසිවක් නැත. එක් එක් තටාකයේ `accountVisible` පවසන්නේ කුමන දෘශ්‍යතාව එයට අදාළ වේද යන්නයි.
- ගිණුම් තීරු සහ ආකෘති කවුළු පෙන්වනු ලබන්නේ යතුර භාවිතා කළ හැකි සම්බන්ධතා ඇති ගිණුම් සඳහා පමණි. යතුරට අවසර දී ඇති සම්බන්ධතා ලැයිස්තුවක් ඇති විට, ඉන් පිටත ගිණුමක් එහි `Account N` ප්‍රවේශය `account` හෝ `modelWindows` නොමැතිව තබා ගනී. හිස් ලැයිස්තුවක් යන්නෙන් අදහස් කරන්නේ `/v1/me/status` සඳහා සීමාවක් නැත. සංචිතයේ එකතුව (`dimensions[].total`) එම ලැයිස්තුව මත රඳා නොපවතී.
- `self:usage` සමඟ පමණක් පෙන්වා ඇති රූප දෙකක් වෙනත් යතුරු භාවිතයෙන් පැමිණේ. කාලසටහන් අයවැයක `exhausted` එම කාලසටහන යටතේ ඇති සෑම යතුරකම පරිභෝජනය පිළිබිඹු කරයි. බර සියල්ල ශුන්‍ය වන තටාකයක, යතුරේ `weight` `100 / number of members` වේ. බලාත්මක කිරීම යතුරට අදාළ වන්නේ දෙකම ය.
- සංචිතයක් හඳුනාගනු ලබන්නේ ඇමතුම් යතුරට බැඳී ඇති පාරාන්ධ අගයක් වන `ref` මගින් පමණි. පරිපාලක විසින් ලියන ලද පරිදි එහි සංදර්ශක නාමය (`name`) ඇතුළත් වේ. `ref` යනු සේවාදායකයේ API-යතුරු රහස (`API_KEY_SECRET`) සමඟ යතුර සහ සංචිතයෙන් ව්‍යුත්පන්න වේ. ගනුදෙනුකරුවන් එය නොනැසී පැවතිය යුතුය: එම රහස කරකවන්නේ නම් එය වෙනස් වේ.
- ගිණුම් සංචිත අනුපිළිවෙලින් `Account 1`, `Account 2`, … ලෙස ලැයිස්තුගත කර ඇත. සංචිත හැඳුනුම්පතක්, සම්බන්ධතා හැඳුනුම්පතක්, ගිණුම් විද්‍යුත් තැපෑලක් හෝ ගිණුමේ නම ආපසු ලබා නොදෙන අතර, ප්‍රතිචාරය කොන්ත්‍රාත්තු යෝජනා ක්‍රමය හරහා ගමන් කරයි, එමඟින් එයින් පිටත ඕනෑම ක්ෂේත්‍රයක් පහත වැටේ.
- ගණන් කළ හැකි ඒකක (`requests`, `tokens`, `usd`) සංචිත බාල්දිය ලෙස වාර්තා වේ කෝටා ද්වාරය බලාත්මක කරයි: `limit` = සැලැස්ම සංචිතයේ × ගිණුම් සීමාව, `fairShare` = බර / 100 × `limit` (සමාන zq q) සෑම බරකම `consumed` = කවුන්ටරය සතු වන විට, කෝටා ගබඩාව, `remaining` = `fairShare` − `consumed`, 0 හි බිම් ඇත.
- `blocks.schedules` යතුරේ කාලසටහන් කවුළු ලැයිස්තුගත කරයි (`open`/`closed`, `blackout` හෝ `outside-window`, `retryAfterSeconds`, රක්ෂිත බිම්, සහ කවුළුවේ අයවැය වියදම් කරන්නේද යන්න); `blocks.modelCaps` එහි එක් මාදිලියේ පැයක සීමාවන් පරිභෝජනය සමඟ ලැයිස්තුගත කරයි.
- සපයන්නාගේ සෑම සංචිතයකින්ම පිටත යතුරක් `pools: []` සමඟ 200 ක් ලැබේ; `availableModels` (යතුර `/v1/models` හි දකින `qtSd/` ids), `expiresAt` සහ `apiBaseUrl` තවමත් පුරවා ඇත.
- `apiBaseUrl` යනු `OMNIROUTE_PUBLIC_API_BASE_URL`, පසුව `OMNIROUTE_PUBLIC_BASE_URL`, else `null`. එය කිසිවිටෙක ඉල්ලීමේ සම්භවයක් නොවේ.

කෝටා ගබඩාව කියවිය නොහැකි විට, `blocks` හි ගබඩා පිටුබලය සහිත ක්ෂේත්‍ර (කාලසටහන් අයවැයේ `exhausted`, ආදර්ශ තොප්පියක `consumed` සහ `reached`) `null` ද වේ.

### ණය දීමේ කැමැත්ත

`PATCH /api/v1/me/quota/{provider}` එක් සංචිතයක් සඳහා ඇමතුම් යතුරේ කැමැත්ත වාර්තා කරයි. එය `GET` හි ධජය, ශීර්ෂයන් සහ සැපයුම්කරුවන්ගේ නීති භාවිතා කරයි. `self:usage` විෂය පථය මෙය ලිවීමට අවසර දෙයි, නමුත් එහි නම කියවීමට පමණි.

```json
{
  "pool": "qpr_0123456789abcdef0123456789abcdef",
  "lendingPercent": 30,
  "lendingUntil": 1893456000000
}
```

- `pool` යනු එම සංචිතය සඳහා `GET` ආපසු ලබා දෙන `ref` වේ.
- `lendingPercent` යනු 0 සිට 100 දක්වා පූර්ණ සංඛ්‍යාවකි. 0 අගයක් කැමැත්ත සහ එහි කාලසීමාව ඉවත් කරයි. `lendingPercent` 0 සහිත ශරීරයක් ඕනෑම ආකාරයකින් පිළිගනු ලැබේ.
- `lendingUntil` වෛකල්පිත වේ: යුග මිලි තත්පර, හෝ `null` කාල සීමාවක් නැත. එය අනාගතයේ විය යුතු අතර වැඩිම වශයෙන් 8640000000000000. 100000000000 ට අඩු අගයක් තත්පර ලෙස කියවන අතර එය ප්‍රතික්ෂේප වේ.
- වෙනත් ඕනෑම ක්ෂේත්රයක් ප්රතික්ෂේප කරනු ලැබේ. බයිට් 4096 ට වඩා දිගු ශරීරයක් ප්රතික්ෂේප කරනු ලැබේ. කියවීම එම ප්‍රමාණයෙන් නතර වන බැවින් දිගු ශරීරයක් කිසිදා සම්පූර්ණයෙන් රඳවා නොගනී.

චෙක්පත් මෙම වගුවේ අනුපිළිවෙලට ක්රියාත්මක වේ. සෑම ප්‍රතික්ෂේප කිරීමක්ම ස්ථාවර පණිවිඩයක් සහිත සම්මත දෝෂ ශරීරය භාවිතා කරයි. මෙම චෙක්පත් වලින් එකක් ප්රතික්ෂේප කිරීම කිසිවක් ලියන්නේ නැත.

ගබඩා කළ කැමැත්ත වෙනස් කරන ඉල්ලීමක් එක් `quota.pool.lending.updated` විගණන වාර්තාවක් ලියයි. එය පැරණි සහ නව අගයන් සමඟ යතුර නම් කරයි. යවන ලද එකම ශරීරය වරක් දෙවරක් ලියන අතර එක් වරක් විගණනය කරයි. පිළිතුර සම්පූර්ණ `GET` දසුන සමඟ 200, ලිවීමෙන් පසුව ගොඩනගා ඇත.

`GET` view පහත පරිදි ණය දීම වාර්තා කරයි:

- සෑම සංචිතයක්ම `borrowMode` (`saturation` හෝ `consent`) සහ යතුරේ `lendingPercent` සහ `lendingUntil` දරයි.
- `lendingActive` යනු `true` යනු `consent` සංචිතයක පමණි, 0 ට වැඩි ප්‍රතිශතයක් සහ නියමිත දිනට ළඟා නොවීය.
- `consent` තටාකයක, එක් එක් ගණන් කළ හැකි `dimensions[].yourShare` `borrowAvailable` දරයි. යතුර දැන් එහි කොටසට ඉහලින් භාවිතා කළ හැකි දේ, අනෙකුත් යතුරු මගින් ලබා දී ඇත.
- `borrowAvailable` ද්වාර සූත්‍රය භාවිතා කරයි. එය අනෙක් සෑම යතුරක්ම කියවයි, යතුර එහි කොටස යටතේ තිබියදී. `hard` යතුරක් සඳහා තවත් යතුරකට එක් අමතර කියවීමක් සහ සමාන්තරව ගණන් කළ හැකි මානය.
- `borrowAvailable` යනු `soft` හෝ `burst` යතුරක් සඳහා `null` වන අතර, කියවීමක් අසාර්ථක වූ විට `null`.
- `borrowAvailable` යනු අනෙකුත් සියලුම යතුරු එකට එක් රූපයකි. යතුරු දෙකක සංචිතයක එය අනෙක් යතුරගේම රූපය වේ.
- `borrowAvailable` `percent` windows සඳහා හෝ `accounts[]` හි තවමත් වාර්තා වී නොමැත.
- `saturation` සංචිතයක් තුළ දර්ශනය ගබඩා කළ කැමැත්ත `lendingActive: false` සහ `borrowAvailable` නොමැතිව වාර්තා කරයි.

### දෝෂ

මෙම මාර්ගයේ සෑම ප්‍රතිචාරයක්ම, සාර්ථකත්වය හෝ දෝෂය, `Cache-Control: no-store` දරයි. මාර්ගය ධාවනය වීමට පෙර සිදු වන ප්‍රතික්ෂේප කිරීමක් එය රැගෙන නොයයි, උදාහරණයක් ලෙස සේවාදායක API ප්‍රතිපත්තියේ 401 හෝ IP ෆිල්ටරයේ 403. මාර්ගයේ දෝෂ ස්ථාවර පණිවිඩයක් සමඟ සම්මත දෝෂ ශරීරය භාවිතා කරයි: 400 (වලංගු නොවන සැපයුම්කරු), 401 (අතුරුදහන් හෝ අවලංගු යතුර), 403 (අතුරුදහන් හෝ අවලංගු `self:usage`(අතුරුදහන් 0) සහ 4zq4 `Failed to build quota view`). 500 මඟින් ඉල්ලීම් මාර්ගයට ළඟා වූ පසු, ප්‍රධාන සෙවීම ඇතුළුව කිසියම් අසාර්ථකත්වයක් ආවරණය කරයි; එහි හේතුව සේවාදායකයේ ලොග් වී ඇති අතර ආපසු නොපැමිණි. `PATCH` හි දෝෂ [ණය දීමේ කැමැත්තෙහි](#lending-consent) ලැයිස්තුගත කර ඇත.

- ගිණුම් කිහිපයක් සහිත සංචිතයක, එක් එක් ගිණුම් ඇතුළත් කිරීම් එම ගිණුමේ ම පොත සහ එක් ගිණුමක සීමාව භාවිතා කරයි. බලාත්මක කිරීම ගිණුම් ගණන අනුව දෙපැත්තම පරිමාණය කරයි, එබැවින් සමානුපාතිකය සමාන වේ.
- එක් මාදිලියේ කවුළු යතුර සඳහා කිසිදු කොටසක් ගෙන නොයයි. පොත එක් මාදිලියේ දත්ත තබා නොගනී.
- කාලසටහනක සංචිත තට්ටු දර්ශනය මගින් ඇගයීමට ලක් නොකෙරේ: `schedule-reserve` හේතුව සමඟ ඉල්ලීමක් ප්‍රතික්ෂේප කරන අතර කාලසටහනක් `open` ලෙස පෙන්විය හැක.
- එකම යතුරේ සංචිත දෙකක් සම්බන්ධතාවයක් බෙදා ගන්නා විට, බලාත්මක කිරීම ඒවායින් එකක් යොදන අතර, දසුන දෙකම ලැයිස්තුගත කරයි.
- අසාර්ථක වූ ප්‍රධාන උත්සාහයන් සඳහා එක් ලිපිනයකට සීමාවක් නොමැත: ප්‍රතිලෝම ප්‍රොක්සි ඇමතුම්කරුවන්ට එක් ලිපිනයක් බෙදා ගත හැකිය (එය යොමු කරන ලද සේවාදායක ලිපින විශ්වාසදායකද යන්න මත රඳා පවතී), එබැවින් අගුලු දැමීමක් මඟින් සෑම යතුරු දරන්නෙකුටම මාර්ගය ප්‍රතික්ෂේප කළ හැකිය. `REQUIRE_API_KEY=true` සමඟින්, මෙම මාර්ගය වෙනුවට එම ප්‍රතිපත්තියේ 401 ශරීරය සමඟින්, මාර්ගය ධාවනය වීමට පෙර සේවාදායක API ප්‍රතිපත්තිය විසින් අවලංගු යතුරක් ප්‍රතික්ෂේප කරනු ලැබේ.

### සාමාජික භාවිතය

කවුළුවක භාවිතය සංචිතයේ සාමාජිකයන් අතර බෙදී යන ආකාරය බැලීමට පරිපාලකයෙකුට යතුරු රඳවනයන්ට ඉඩ දිය හැක. විකල්පය වන්නේ සංචිතයේ `memberBreakdown`, පෙරනිමියෙන් අක්‍රියයි. එය තටාක විශාරදයේ හෝ `PATCH /api/quota/pools/{id}` සමඟ සකසා ඇත. `GET /api/quota/pools` සහ `GET /api/quota/pools/{id}` එය වාර්තා කරයි.

දර්ශනයේ මානයක් `members` රැගෙන යන්නේ මේ සියල්ල අල්ලාගෙන සිටින විට පමණි:

- සංචිතයේ විකල්පය ක්‍රියාත්මකයි
- සංචිතයේ උපරිම වශයෙන් වෙන් කර ඇති යතුරු 20 ක් ඇති අතර, අවම වශයෙන් ඒවායින් තිදෙනෙකුට ඉල්ලීම් කළ හැකිය: සක්‍රීය, අවලංගු නොකළ, තහනම් කර නැති සහ ඒවායේ කල් ඉකුත් නොවන
- සංචිතයේ `accountVisible` සත්‍ය ය: යතුරෙහි `self:account-quota` ඇති අතර සපයන්නා එහි `sharedQuotaProviders` හි සිටී
- `percent` කවුළුවක, ගිණුමේ සම්බන්ධතාවය යතුර භාවිතා කළ හැකි එකකි
- එම කවුළුවේ යතුරෙහිම කොටස කියවන ලදී: එහි `status` `unavailable` නොවේ

නැතිනම් `members` නොපවතී. එය කිසිවිටෙක හිස් ලැයිස්තුවක් නොවේ.

- සෑම පෙත්තක්ම `{ slot, consumed, isYou }` වේ. ප්‍රතිචාර යෝජනා ක්‍රමය පෙත්තක ඇති වෙනත් දේපලක් සහ පෙති 20කට වඩා වැඩි ලැයිස්තුවක් ප්‍රතික්ෂේප කරයි. පෙති තව් අනුපිළිවෙලට ලැයිස්තුගත කර ඇත.
- තව දුරටත් ඉල්ලීම් කළ නොහැකි යතුරක් ඇතුළුව, වෙන් කළ යතුරකට එක පෙත්තක් ඇත. කිසිම ප්‍රයෝජනයක් නැති සාමාජිකයෙක් නියම බිංදුවක් පෙන්වයි.
- `isYou` සත්‍ය සමඟින් Slot 1 සැමවිටම අසන යතුර වේ. අනෙක් slot numbers keyed hash එකක ranks වේ. එය `API_KEY_SECRET` සමඟ යතුරු කර ඇති අතර සංචිතය, ඉල්ලා සිටින යතුර සහ සාමාජිකයා ආවරණය කරයි.
- එබැවින් අංක දරන්නන් අතර පෙළ ගැසෙන්නේ නැත. එක් හිමිකරුවෙකු සඳහා ඔවුන් පැමිණීම් අතර එලෙසම පවතී. යතුරක් එකතු වන විට හෝ තටාකයෙන් පිටවන විට හෝ එම රහස කරකවන විට ඒවා වෙනස් විය හැක.
- ගණන් කළ හැකි කවුළුවක පෙත්තක් යනු කෝටා ගබඩාවේ සාමාජික කවුන්ටරය වන අතර එහිම `consumed` කවුන්ටරයම වේ.
- `percent` කවුළුවක පෙත්තක් යනු සාමාජිකයාගේ `attributed` කොටසයි, යතුරගේම කොටස ලෙස කියවන එකම පොතෙන්. තටාකයෙන් පිටත සිදු කරන ලද භාවිතය කිසි විටෙකත් පෙති වලට බෙදී නැත. එම ආරෝපණය බරින් බෙදී ඇත, එබැවින් එය රැගෙන ගිය පෙති බර පෙන්වයි.
- සෑම දසුනක්ම අනෙක් සාමාජිකයෙකුට එක් අගයක් සහ ගණන් කළ හැකි කවුළුවක් සමාන්තරව කියවයි. `percent` කවුළුවක කොටස්වල තමන්ගේම පොත කියවීමෙන් ඔබ්බට පෙති කියවීමට වැය නොවේ. එක් අගයක් කියවිය නොහැකි වූ විට, එම කවුළුවෙහි `members` නොමැති අතර, යතුරෙහිම කොටස පවතිනු ඇත.
- විකල්පය සහ භාවිත කළ හැකි යතුරු ගණන එක් තටාකයකට වරක් කියවන අතර, ගිණුම් දත්ත දැකිය හැකි යතුරක් සඳහා පමණි. විකල්පය හෝ භාවිත කළ හැකි යතුරු ගණන කියවීම අසාර්ථක වීම එම සංචිතය සඳහා තීරු අක්‍රිය කරයි. සේවාදායකය අනතුරු ඇඟවීමක් සටහන් කරයි, සහ ඉතිරි දර්ශනය ගොඩනගා ඇත.

බාර්වල නම් හෝ හැඳුනුම්පත් නොමැත. ඔවුන් තවමත් ප්‍රධාන දරන්නාට අනෙක් සාමාජිකයන් ගැන දේවල් කියයි:

- හිමිකරුවන්ට තවමත් ඒවායේ අගයන් අනුව පෙති ගැලපිය හැක.
- ස්ථාවර අංකනය මඟින් දරන්නාට කාලයත් සමඟ එක් සාමාජිකයෙකු අනුගමනය කිරීමට ඉඩ සලසයි.
- තටාකයේ යතුරු කීයක් වෙන් කර ඇත්දැයි පෙති ගණන පෙන්වයි.
- යතුරු තුනක සංචිතයක, එක් යතුරක් භාවිතා කළේ කුමක්දැයි දන්නා කෙනෙකුට අවසාන යතුර භාවිතා කළ දේ පැවසිය හැකිය.
- තටාකයක් භාවිතා කළ හැකි යතුරු තුනකට වඩා පහත වැටුණු විට, තීරු අතුරුදහන් වේ. කලින් ගත් බැලීම් තවමත් එක් එක් සාමාජිකයා භාවිතා කළ දේ පෙන්වයි.
- ගණන් කළ හැකි කවුළුවක, සංචිතයේ එකතුව පෙති අඩු කිරීමෙන් තවදුරටත් වෙන් කර නොමැති යතුරු භාවිතය පෙන්විය හැක.
- එක් ගිණුමක බිංදුව පෙන්වන සහ තවත් ගිණුමක භාවිතා කරන සාමාජිකයෙකුට කුමන ගිණුම භාවිතා කරන්නේද යන්න පෙන්විය හැක.
- `hard` ප්‍රතිපත්තිය සමඟ ගණන් කළ හැකි සංචිතයක, සාමාජිකයෙකුගේ සාධාරණ කොටසකින් වර්ධනය වීම නතර වන පෙත්තක් එම සාමාජිකයාගේ බර ඉඟි කරයි.

### භාවිත මාලාව (`GET /api/v1/me/usage`)

`GET /api/v1/me/usage?range=<range>` ( `/v1/me/usage` හිදී ද සේවය කරයි) ඇමතුම් යතුරේ ම ඉල්ලීම්වල භාවිතය සහ පිරිවැය ආපසු ලබා දෙයි: එකතුව, UTC දිනකට එක් ප්‍රවේශයක්, දිනකට සහ මාදිලියකට, ආකෘතියකට සහ එක් සැපයුම්කරුවෙකුට. එය ධජය, සත්‍යාපන රීති, `self:usage` විෂය පථය, `Cache-Control: no-store` සහ ඉහත කෝටා මාර්ගයේ දෝෂ හැසිරීම බෙදා ගනී. යතුර `range` ට පෙර පරීක්ෂා කර ඇත. දෝෂ 400 (`Invalid range`), 401, 403, 404 සහ 500 (`Failed to build usage`) වේ.

- `range` යනු `1d`, `7d`, `30d` (පෙරනිමිය) හෝ `90d` වලින් එකකි. වෙනත් ඕනෑම අගයක්, හිස් අගයක් හෝ පුනරාවර්තන පරාමිතියක් 400 වේ. ඇමතුමක පිරිවැය බැඳීමට කට්ටලය `90d` හි නතර වේ. දසුන කියවන්නේ අමු භාවිත ඉතිහාසය පමණි, කිසිවිටෙක යතුරක් රැගෙන නොයන දෛනික සාරාංශ නොවේ.
- ඇමතුම් යතුරේ හැඳුනුම්පත මඟින් පේළි තෝරා ගනු ලැබේ. ප්‍රධාන නාම තීරුව කිසිවිටෙක නොගැලපෙන අතර, යතුරු හැඳුනුම්පතක් නොමැතිව වාර්තා කර ඇති පේළි කිසිවිටෙක ගණන් නොගනී.
- මාලාවක් ගොඩනැගීම කවුළුවේ යතුරේ පේළි හරහා සමූහගත විමසුම් පහක් ධාවනය කරයි. ගොඩනඟන ලද ශ්‍රේණිය යතුරකට සහ පරාසයකට තත්පර 60ක් නැවත භාවිත කරන අතර නැවත භාවිත කළ ඇමතුමක් කිසිවක් ක්‍රියාත්මක නොවේ. එහි `generatedAt` එහි වයස ලබා දෙයි.
- මාලාව ගොඩනඟන විට කවුළුව අවසන් වේ. පසුව මුද්‍රා තැබූ පේළියක්, උදාහරණයක් ලෙස ඔරලෝසු වක්‍රයෙන්, ගණන් නොගනී.

"Claude Desktop" එහි තෙවන පාර්ශ්ව අනුමාන කවුළුව සඳහා අගයන් ලබා දෙයි. ආකෘති යනු එම සැපයුම්කරු සඳහා යතුර ඉල්ලා සිටිය හැකි කෝටා-බෙදාගැනීමේ ආකෘති වේ. යතුර සමඟ එවැනි ලැයිස්තුවක් නොපැමිණෙන විට, බ්ලොක් එක ඒ වෙනුවට ගේට්වේ ආකෘති සොයාගැනීම ක්‍රියාත්මක කරයි. ද්වාර ලිපිනය යනු සේවාදායකය වාර්තා කරන පොදු API මූලාරම්භයයි (`OMNIROUTE_PUBLIC_API_BASE_URL`, පසුව `OMNIROUTE_PUBLIC_BASE_URL`). එකක්වත් සකසා නොමැති විට, කාඩ්පත ස්ථාන දරන්නෙකු පෙන්වන අතර පරිපාලකගෙන් අසන ලෙස දරන්නාට කියයි. යතුර ස්ථාන රඳවනයක් ලෙස පෙන්වයි. "මගේ යතුර ඇතුළත් කරන්න" තිරයේ ඇති පෙළෙහි සහ පිටපත් බොත්තම පිටපත් කරන දෙයෙහි සම්පූර්ණ යතුර තබයි. එය කොටුව ඉවත් කරන තෙක්, යතුර අමතක වී හෝ ප්‍රතිස්ථාපනය වන තුරු හෝ පිටුව ඉතිරි වන තුරු පවතී. කාඩ්පත කිසිදු ඉල්ලීමක් නොයවන අතර ගොනු බාගත කිරීමක් ඉදිරිපත් නොකරයි.

API ලකුණු `stale` කියවීම සමහර විට යල් පැන ගිය එකක් ලෙස පෙන්වයි. එය `unavailable` ලකුණු කරන කියවීමක් එහි හේතුව සමඟ පෙන්වනු ලැබේ, කිසි විටෙකත් ශුන්‍ය නොවේ.

ප්‍රතිශත සැලසුම් මත API එය වාර්තා කරන විට පිටුව යතුරේ ම කොටස ලබා ගනී. එම සංඛ්‍යාව ඇස්තමේන්තුවක් බව පවසන අතර එහි කොටස් දෙක නම් කරයි. එක් මාදිලියේ සීමාවන් පෙන්වන්නේ ගිණුම පමණි.

කවුළුවක් `members` රැගෙන යන විට, එහි කාඩ්පත ද එක් සාමාජිකයෙකුට එක් කොටසක් සහිත තීරුවක්, තව් අනුපිළිවෙලින් පෙන්වයි. ඇසීමේ යතුරේ කොටස උච්චාරණ වර්ණය භාවිතා කරයි. අනෙක් කොටස් තේමාවේ ප්‍රස්ථාර වර්ණ හරහා ගමන් කරයි. පෙළ පුරාවෘත්තයක් සෑම කොටසක්ම එහි අගය සමඟ ලැයිස්තුගත කරයි, එබැවින් කිසිවක් වර්ණය මත රඳා නොපවතී. කොටස් `You` හෝ `Member N` ලෙස ලේබල් කර ඇත, මෙහි N යනු ස්ලට් වේ.

### පිටුව සඳහා කැප වූ වරාය

`QUOTA_PANEL_PORT` ස්වයං සේවා පිටුවට පමණක් සේවය කරන දෙවන සවන්දෙන්නෙකු විවෘත කරයි. විචල්‍යය සකසා නොමැති නම් එය අක්‍රියයි. `QUOTA_PANEL_HOST` යනු `127.0.0.1` වෙත බැඳුනු ලිපිනය වන අතර පෙරනිමි වේ.

සවන්දෙන්නා මෙම මාර්ග ප්‍රධාන තොටට රිලේ කරන අතර අනෙක් සෑම මාර්ගයකටම 404ට පිළිතුරු දෙයි:

| මාර්ගය                                                                   | සේවය කරයි                              |
| ------------------------------------------------------------------------ | -------------------------------------- |
| `/quota/{provider}`                                                      | පිටුව                                  |
| `/api/v1/me/quota/{provider}`, `/v1/me/quota/{provider}`                 | පිටුව කියවන කෝටාව බැලීම                |
| `/api/v1/me/usage`, `/v1/me/usage`                                       | පිටුව කියවන භාවිත මාලාව                |
| `/_next/static/`                                                         | ගොඩනැගීමේ ස්ක්‍රිප්ට්, මෝස්තර සහ අකුරු |
| `/favicon.ico`, `/favicon.svg`, `/icon-512.png`, `/apple-touch-icon.png` | අයිකන                                  |

`GET` සහ `HEAD` ශරීරයක් නොමැතිව ප්‍රතිවර්තනය වේ. ශරීරයක් සහිත එක් ඉල්ලීමක් ද ප්‍රකාශ කෙරේ: ණය දීමේ තේරීමක් සුරැකීමට පිටුව යවන කෝටාව බැලීමේ මාර්ගයේ `PATCH`. CONNECT ඉල්ලීමක් හැර වෙනත් ඕනෑම ක්‍රමයක් 404 ට පිළිතුරු සපයයි, එහි සම්බන්ධතාවය පිළිතුරක් නොමැතිව වසා ඇත. ශරීරයක් ප්‍රකාශ කරන වෙනත් ඕනෑම ඉල්ලීමක් 404ට පිළිතුරු දෙන අතර එහි සම්බන්ධතාවය වසා ඇත. උත්ශ්‍රේණි කිරීමේ ඉල්ලීම් ප්‍රතික්ෂේප කර ඇති අතර ඒවායේ සම්බන්ධතාවය වසා ඇත. API තොටේ මෙන් තිත් ඛණ්ඩයක් හෝ ඛණ්ඩ සලකුණක් සහිත මාර්ගයක් ප්‍රතික්ෂේප කරනු ලැබේ. මුද්‍රණය කළ හැකි ASCII පිටතින් අක්ෂරයක් සහිත ඉල්ලීම් ඉලක්කයක් ද එසේමය. ඉලක්කය තුළ ඇති raw control character එකක් HTTP parser මගින් 400 ට පිළිතුරු දෙනු ලැබේ, මෙම වරායේ ම චෙක්පතට පෙර. රාමුව තමන්ගේම භාවිතය සඳහා සංචිත කර ඇති ඉල්ලීම් ශීර්ෂයන්: `x-middleware-`, `x-invoke-`, `x-nextjs-`, `x-now-` හෝ `x-next-` වලින් ආරම්භ වන නම් සහ `x-matched-path` සහ `next-resume` නම් . ඔවුන් නොමැතිව ඉල්ලීම නිකුත් කෙරේ. උපකරණ පුවරුව, පිවිසුම් පිටුව, කළමනාකරණ API සහ අනුමාන මාර්ග මෙම වරාය හරහා ළඟා විය නොහැක.

`PATCH` පරාමිතියක් නොමැතිව හෝ `charset=utf-8` සමඟ පමණක් `Content-Type: application/json` රැගෙන යා යුතුය. එය සරල ඉලක්කම් ලෙස ලියා ඇති 1 සිට 4096 දක්වා `Content-Length` එකක් රැගෙන යා යුතු අතර `Transfer-Encoding` නැත. මෙම රීති වලින් එකක් කඩ කරන `PATCH` 404 ට පිළිතුරු දෙයි. අත්සන් කරන ලද හෝ නැවත නැවත කරන ලද එකක් වැනි සමහර විකෘති දිග, මෙම වරායේ ම චෙක්පතට පෙර HTTP විග්‍රහ කරන්නා විසින් 400 ට පිළිතුරු දෙනු ලැබේ. ප්‍රධාන තොට හා සම්බන්ධ වීමට පෙර ප්‍රකාශිත බයිට් කියවන අතර, ඒවා සඳහා උපරිම වශයෙන් තත්පර 5ක් බලා සිටියි. ඒ වන විට සම්පූර්ණ නොවූ ශරීරයක් 404 ට පිළිතුරු දෙන අතර එහි සම්බන්ධතාවය වසා ඇත. එම අවස්ථාවේ දී හෝ සේවාලාභියා මුලින්ම පිටව ගිය විට කිසිවක් ප්‍රධාන වරායට ළඟා නොවේ. වරාය ප්‍රකාශිත බයිට් හරියටම, එකම `Content-Length` සමඟ රිලේ කරයි. ඒවාට පසු බයිට් සම්බන්ධතාවයේ ඊළඟ ඉල්ලීම ලෙස කියවනු ලැබේ. ඉදිරියෙන් ඇති TLS ප්‍රතිලෝම ප්‍රොක්සියක් `Content-Length` ඉදිරියට යැවිය යුතු අතර ඉල්ලීම් කොටස නැවත කුට්ටි නොකළ යුතුය. ප්‍රධාන වරාය `GET` සඳහා වන පරිදි, `Authorization` ශීර්ෂයේ API යතුර පරීක්ෂා කරයි.

404 ශරීරය `{"error":"not_found","message":"Not found."}` වේ. අසාර්ථක රිලේ එකක් `detail` ක්ෂේත්‍රයක් නොමැතිව 502 (`api_bridge_unavailable`) හෝ 504 (`api_bridge_timeout`) පිළිතුරු සපයයි.

සවන්දෙන්නා `QUOTA_SELF_PANEL` කියවන්නේ නැත, එය පිටුව සක්‍රිය නොකරයි. ධජය ක්‍රියාවිරහිත කර ඇති අතර, පිටුව සහ එහි API ප්‍රධාන වරායේ 404 ට පිළිතුරු දෙන අතර, සවන්දෙන්නා එම පිළිතුර රිලේ කරයි.

සංවර්ධන සේවාදායකය (`next dev`) යටතේ, මෙම වරාය හරහා පිටුව අන්තර්ක්‍රියාකාරී නොවේ. සංවර්ධන hot-reload socket යනු උත්ශ්‍රේණිගත කිරීමේ ඉල්ලීමක් වන අතර, වරාය එය ප්‍රතික්ෂේප කරයි. සංවර්ධනය කිරීමේදී ප්‍රධාන වරාය භාවිතා කරන්න.

වරාය සරල HTTP සේවය කරන අතර පිටුව API යතුරු යවයි. default bind address එක තියාගෙන ඒක ඉස්සරහින් TLS තියෙන reverse proxy එකක් දාන්න. ලූප්බැක් හැර වෙනත් බන්ධන ලිපිනයක් මෙම දැනුම්දීම ලොග් කරයි:

```text
[Quota Panel] Bound to <host>. This port serves plain HTTP and the page sends API keys. Put a TLS reverse proxy in front of it.
```

ඉදිරියට යැවීමේ ශීර්ෂයක් නොයවන loopback peer එකක් ප්‍රධාන වරායේ දේශීය ලෙස ගණන් ගනී. එබැවින් එකම ධාරකයේ ප්‍රොක්සියක් `X-Forwarded-For` යැවිය යුතුය. පුද්ගලික ලිපිනයක ප්‍රොක්සියක් විශ්වාස කරන්නේ එම ශීර්ෂය සඳහා `OMNIROUTE_TRUST_PROXY=private` (හෝ `lan`) සමඟ පමණි. වෙනත් ඕනෑම සම වයසේ මිතුරෙකු එහි සම්බන්ධතාවයේ ලිපිනය මගින් වාර්තා කරනු ලබන අතර, එය එවන ලද ඉදිරියට යැවීමේ ශීර්ෂයන් අතහැර දමනු ලැබේ.

සවන්දෙන්නා වරකට සම්බන්ධතා 256ක් පමණ තබා ගනී. සේවාලාභියෙකුට ඉල්ලීම් ශීර්ෂ යැවීමට තත්පර 10ක් සහ සම්පූර්ණ ඉල්ලීම යැවීමට තත්පර 30ක් ඇත. නිෂ්ක්‍රීයව තබා ඇති සජීවී සම්බන්ධතාවයක් තත්පර 5කට පමණ පසු වැසී යයි. තත්පර 60 ක් සඳහා ක්‍රියාකාරකමක් නොමැති සම්බන්ධතාවයක් වසා ඇත. මෙම අගයන් ස්ථාවර වේ. ඉදිරිපස ඇති ප්‍රතිලෝම ප්‍රොක්සියේ සම්බන්ධතා සහ අනුපාත සීමාවන් සකසන්න. ඉදිරියෙන් ඇති ප්‍රතිලෝම ප්‍රොක්සියක් එහි අක්‍රිය උඩුගං සම්බන්ධතා තත්පර 5කට වඩා අඩු කාලයක් තබා ගත යුතුය, නැතහොත් ඒවා නැවත භාවිත නොකළ යුතුය. ප්‍රධාන තොට වෙත රිලේ කිරීම API port (`API_BRIDGE_*`) හි උඩුගත කාල සීමාවන් භාවිතා කරයි.

අසන්නා ද `API_PORT` සකසා නොමැති විට ආරම්භ වේ. `QUOTA_PANEL_PORT` 1 සිට 65535 දක්වා තොටක් විය යුතුය, ඉලක්කම් වලින් පමණක් ලියා ඇත. එය උපකරණ පුවරු වරායෙන් සහ API වරායෙන් වෙනස් විය යුතුය. සජීවී WebSocket සේවාදායකය ක්‍රියාත්මකව ඇති අතර, එය `LIVE_WS_PORT` වෙතින් ද වෙනස් විය යුතුය (පෙරනිමි 20132). වෙනත් ඕනෑම අගයක් කිසිවක් විවෘත නොකරන අතර අනතුරු ඇඟවීමක් ලොග් කරයි. ප්‍රතික්ෂේප කළ අගයක් පිළිබඳ අනතුරු ඇඟවීමක් විචල්‍යය නම් කරන අතර අගය නැවත සිදු නොකරයි. දැනටමත් භාවිතයේ පවතින වරායක් කිසිවක් විවෘත නොකරන අතර මෙම අනතුරු ඇඟවීම ලොග් කරයි:

```text
[Quota Panel] Port <port> is already in use. The quota panel port stays off.
```

`OMNIROUTE_BASE_PATH` කට්ටලය සමඟින්, අසන්නා එම උපසර්ගය යටතේ ඉහත සෑම මාර්ගයක්ම අපේක්ෂා කරයි. ගොඩනැගීමේ වේලාවේදී සහ ධාවන වේලාවේදී එකම `OMNIROUTE_BASE_PATH` භාවිතා කරන්න. එය ප්‍රමුඛ ස්ලෑෂ් එකකින් සහ පසුපසට යන ස්ලෑෂ් නොමැතිව ලියන්න, උදාහරණයක් ලෙස `/omniroute`. `/` සහ `/omniroute/` ඇතුළු තවත් හැඩයක් අනතුරු ඇඟවීමක් සමඟ වරායෙන් පිටව යයි, නමුත් ගොඩනැගීම එම ආකෘති පිළිගනී. පළමු කොටස යෙදුම් මාර්ගයක් නම් කරන මූලික මාර්ගයද එසේමය: `api`, `v1`, `v1beta`, `_next`, `quota`, `dashboard`, `docs`, `login`, `codex`, `responses`, `anthropic`, `openai`, `v0`, හෝ ඕනෑම අවස්ථාවක `connect`.

සීමාවන්:

- `/quota/{provider}/` ටේ්රලිං ස්ලෑෂ් එකක් සමඟ මෙම වරායේ 404 ට පිළිතුරු දෙයි.
- සේවා සේවකයා සහ වෙබ් යෙදුම් මැනිෆෙස්ටය මෙම තොටේ සේවය නොකෙරේ.
- උපකරණ පුවරුවේ අභිරුචි ෆේවිකොන් කට්ටලයක් මෙම තොටේ නොපෙන්වයි.
- යෙදුම මූලික මාර්ගයක් යටතේ ධාවනය වන විට අයිකන නොපෙන්වයි.
- වරාය සරල HTTP/1.1. කතා කරයි
- ක්‍රියාවලිය නැවත ආරම්භ වන තුරු අසාර්ථක වූ බැඳීමක් නැවත උත්සාහ නොකෙරේ.
- සවන්දෙන්නාට සේවාදායක ලිපිනයකට සම්බන්ධතාවක් හෝ ගාස්තු සීමාවක් නොමැත.
- බහාලුම් සැකසුම් මෙම කොටසෙන් ආවරණය නොවේ.

## දෝෂ නිරාකරණය

### Redis වින්යාස කර ඇති නමුත් සම්බන්ධ නොවේ

`ioredis` ස්ථාපනය කර ඇති බව (`npm ls ioredis`) සහ `QUOTA_STORE_REDIS_URL`
වෙත ළඟා විය හැකි බව පරීක්ෂා කරන්න. සම්බන්ධතාව අසාර්ථක වූ විට factory එක SQLite වෙත ආපසු හැරේ (`warn`
මට්ටමින් ලොග් කරනු ලැබේ).

### `peek` පැරණි දත්ත ලබා දෙයි / fail-open වේ

`peek` දෝෂයක් නිකුත් කළහොත්, `enforceQuotaShare` ප්රතිඵලය "අවසර දෙන්න" ලෙස සලකයි (fail-open).
මූලික හේතුව හඳුනාගැනීමට `quota:enforce` සහ `quota:factory` ඇතුළත් කිරීම් සඳහා

එකඟ වූ ණය දීම තීරු තුනක් එකතු කරයි: `quota_allocations.lending_percent` (පූර්ණ සංඛ්‍යාව, පෙරනිමි 0), `quota_allocations.lending_until` (යුග මිලි තත්පර, හෝ කාල සීමාවක් නොමැතිව `NULL` ) සහ `quota_pools.borrow_mode` (පෙරනිමි `saturation`). එහි සංක්‍රමණය මෙම තීරු එකතු කරන අතර පවතින පේළියක් ලියන්නේ නැත.
