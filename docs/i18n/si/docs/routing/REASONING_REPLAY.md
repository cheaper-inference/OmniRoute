## මෙය පවතින්නේ ඇයි

චින්තන මාදිලියේ සපයන්නන් කිහිප දෙනෙකු හැර පසු විපරම් හැරීමක් ප්‍රතික්ෂේප කරයි** පෙර සහකාර පණිවිඩයේ මුල් `reasoning_content` ඇතුළත් වේ** . උඩු ප්‍රවාහය මෙවැනි පණිවිඩ සමඟ 400 ලබා දෙයි:

```
Param Incorrect: The reasoning_content in the thinking mode must be passed back to the API.
```

නමුත් සාමාන්‍ය සේවාදායකයින් (Cursor, Cline, Roo Code, OpenAI SDK) ඔවුන් නැවත ධාවනය කරන ඉතිහාසයෙන් `reasoning_content` ඉවත් කරයි. OmniRoute එය සේවාදායක පැති හැඹිලියකින් ප්‍රතිසාධනය කරයි, එබැවින් උඩු ප්‍රවාහය දකින ඉල්ලීම අනුකූල වේ. නිකුතුව #1628 මගින් දෙමුහුන් memory/SQLite ස්ථීරභාවය හඳුන්වා දෙන ලදී, එබැවින් හැඹිලිය නොනැසී පවතින ක්‍රියාවලිය නැවත ආරම්භ වේ.

## ගෘහ නිර්මාණ ශිල්පය

```
Turn N (assistant generates):
  → response contains reasoning_content + tool_calls
  → if requiresReasoningReplay(provider, model): cacheReasoningFromAssistantMessage()
      writes (memory + DB), keyed by every tool_call.id
  → forward response to client (which may or may not retain reasoning)

Turn N+1 (client sends follow-up):
  → translator detects: requiresReasoningReplay(provider, model) === true
  → for each assistant message with tool_calls and no reasoning_content:
      lookupReasoning(toolCalls[0].id) → memory → DB
      hit  → msg.reasoning_content = cached; recordReplay()
      miss → msg.reasoning_content = "" (legacy fallback for older DeepSeek)
  → upstream sees consistent history → no 400
```

ග්‍රහණය කිරීම සිදු වන්නේ `open-sse/handlers/chatCore.ts` (අඩවි දෙකක්, `cacheReasoningFromAssistantMessage` ඇමතුම් අඩවි දෙකේදී). නැවත ධාවනය `open-sse/translator/index.ts` හි ක්‍රම බලහත්කාරයෙන් පසුව නමුත් යැවීමට පෙර සිදු වේ.

සරල (මෙවලම්-ඇමතුම් නොවන) සහකාර හැරීම් වෙනස් ලෙස යතුරු කර ඇත: `buildAssistantMessageCacheKey()` එම වාරය දක්වා සැසි විෂය පථය සහ සාමාන්‍යකරණය කළ OpenAI-ආකෘති පිටපත දිරවයි, මන්ද DeepSeek `tools` පවතින විට _every_ පෙර හැරීමේ තර්කනය අවශ්‍ය වන බැවිනි. ප්‍රතිචාර-API ඉලක්ක සඳහා (උදාහරණයක් ලෙස `opencode-go/deepseek-v4-flash`, `/responses` වෙත යොමු කර ඇත ) උඩුගංගත සිරුර `messages` නොව `input` දරයි, එබැවින් `translateRequest()` (`open-sse/translator/index.ts`) එය ආපසු කැඳවීමේ විකල්පය හරහා දිරවන ලද විවර්තන පිටපත වාර්තා කරන අතර ග්‍රහණ අඩවි එම පිටපතම දිරවයි. ප්‍රතිචාර නැවත ධාවනය කිරීමේ අවසර පත්‍රය සෑම මූලාශ්‍ර ආකෘතියක් සඳහාම OpenAI විවර්තනය මත ක්‍රියාත්මක වේ, එබැවින් Anthropic පණිවිඩ සේවාලාභීන් (Claude → OpenAI → ප්‍රතිචාර) ද නැවත ධාවනය වේ.

## ගබඩා — Hybrid Memory + SQLite

උණුසුම් මාර්ගය බිඳ වැටීම් ප්‍රතිසාධනය සහ උපකරණ පුවරු දෘශ්‍යතාව සඳහා SQLite වගුවකින් පිටුබලය ලබන මතකයේ ඇති `Map` (LRU-by-creation) භාවිතා කරයි.

| ස්ථරය | ක්රියාත්මක කිරීම                               | අරමුණ                                         |
| ----- | ---------------------------------------------- | --------------------------------------------- |
| මතකය  | `Map` හි `open-sse/services/reasoningCache.ts` | වේගවත් සෙවීම්, 200 දී පැරණිතම අයව ඉවත් කරයි   |
| DB    | `reasoning_cache` වගුව (`src/lib/db/`)         | නැවත ආරම්භ කිරීම්, ධාවක සංඛ්‍යාලේඛන හරහා පවතී |

ලිවීම් දෙකටම යයි. ප්‍රථමයෙන් මතකය පරිශීලනය කරයි, පසුව DB වෙත ආපසු යයි (DB පහරවල් නැවත මතකයට ප්‍රවර්ධනය කෙරේ). DB අසාර්ථක වීම මාරාන්තික නොවන — මතකයේ ඇති හැඹිලිය උණුසුම් මාර්ගයට දිගටම සේවය කරයි.

**පෙරනිමි:**

- TTL: `2h` (`TTL_MS = 2 * 60 * 60 * 1000`)
- උපරිම මතක සටහන්: `200` (`MAX_MEMORY_ENTRIES`)
- නෙරපා හැරීම: පැරණිතම `createdAt` පළමුව

## මෙහෙයුම් සටහන්

- **ඉවර කරන්න:** `cleanupReasoningCache()` කල් ඉකුත් වූ මතක සටහන් ඉවත් කර `DELETE FROM reasoning_cache WHERE expires_at <= unixepoch('now')` ධාවනය කරයි. සෞඛ්‍ය පරීක්ෂක සේවකයින් මෙය වරින් වර කැඳවයි.
- **බිඳ වැටීම් ප්‍රතිසාධනය:** නැවත ආරම්භ කිරීමෙන් පසුව, මතකය හිස් නමුත් DB තවමත් කල් ඉකුත් නොවූ ප්‍රවේශයන් දරයි. ලබා දී ඇති `tool_call_id` සඳහා පළමු සෙවීම DB පහරකි; පසුකාලීන සොයා බැලීම් මතක හිට්ස් වේ.
- **තර්කයක් නැත, හැඹිලියක් නැත:** සහායක පණිවිඩයේ `reasoning_content` / `reasoning` ක්ෂේත්‍රයක් නොමැති විට `cacheReasoningFromAssistantMessage` `0` ආපසු ලබා දෙයි, එබැවින් නොසිතන ප්‍රතිචාර සඳහා කිසිවක් වැය නොවේ.
- **ලියන්නත් ගේට්ටුයි:** `chatCore.ts` හි ඇමතුම් අඩවි දෙකම (ප්‍රවාහ නොවන සහ ප්‍රවාහය) `cacheReasoningFromAssistantMessage()` අමතන්න `requiresReasoningReplay(provider, model)` `true` — වන විට පමණක් කියවන්න පැති චෙක්පත් පුරෝකථනය කරයි. නැවත ධාවනය සපයන්නෙකු ස්පර්ශ නොකරන ස්ථාපනයන් සෑම තර්කනාත්මක ප්‍රතිචාරයක් සඳහාම ලිවීම, දර්ශක යාවත්කාලීන කිරීම සහ try/catch සඳහා ගෙවීම නතර කරයි.
- **දැඩි නොවන සපයන්නන්:** `requiresReasoningReplay` `false` සහ ඉලක්ක ආකෘතිය OpenAI වන විට, පරිවර්තකයා** තීරු** පිටතට යන පණිවිඩ වලින් ඕනෑම `reasoning_content` ක්ෂේත්‍රයක් — OpenAI Chat Completions එය පිළිගන්නේ නැත.

## Muse Opaque-Reasoning හිමිකාරිත්වය
