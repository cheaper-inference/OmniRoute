`copilot-m365-web` (`m365copilot` යන අන්වර්ථ නාමය සහිත) `m365.cloud.microsoft/chat` හි සත්යාපිත Microsoft 365 Copilot BizChat බ්රවුසර සැසියක් හරහා OpenAI-ආකෘතික චැට් ඉල්ලීම් යවයි. මෙය නිල නොවන ඒකාබද්ධ කිරීමකි.

> **Web Cookie සපයන්නන්ට අලුත්ද?**
>
> මෙම සපයන්නාට විශේෂිත මාර්ගෝපදේශය අනුගමනය කිරීමට පෙර, සාමාන්ය පිහිටුවීමේ ක්රියාවලිය, සත්යාපන මාර්ගෝපදේශ, සීමාවන් සහ දෝෂ නිරාකරණය සඳහා **`docs/getting-started/WEB-COOKIE-GUIDE.md`** කියවන්න.
>
> **වැදගත්:** මෙම සපයන්නා සඳහා අක්තපත්රය **cookie එකක් නොවේ**. `m365.cloud.microsoft` වෙතින් cookies පිටපත් නොකරන්න. අක්තපත්රය WebSocket URL විමසුම් පරාමිතියක් සහ මාර්ග ඛණ්ඩයක් වන අතර, ඒ දෙකම DevTools Network ටැබයෙන් කියවනු ලැබේ.

## පූර්ව අවශ්යතා

- `m365.cloud.microsoft/chat` හි BizChat වෙත ප්රවේශය සහිත Microsoft 365 ගිණුමක්
- DevTools WebSocket පරීක්ෂාව සඳහා Chromium-පාදක බ්රවුසරයක් (Chrome, Edge)
- M365 Copilot බලපත්රයක් (බොහෝ Microsoft 365 Business/Enterprise සැලසුම් සමඟ ඇතුළත් වේ)

## අක්තපත්ර ග්රහණය (WebSocket ක්රමය)

1. `https://m365.cloud.microsoft/chat` වෙත පුරනය වී සංවාදයක් ආරම්භ කරන්න.
2. **DevTools → Network** විවෘත කරන්න.
3. **WS** (WebSocket) අනුව පෙරහන් කරන්න.
4. Chathub WebSocket සම්බන්ධතාව ක්ලික් කරන්න. `wss://substrate.office.com/m365Copilot/Chathub/` යන්නෙන් ආරම්භ වන URL එකක් සොයන්න.
5. එහි **Request URL** වෙතින් පහත දෑ පිටපත් කරන්න:
   - `access_token` විමසුම් පරාමිති අගය (කෙටි කාලීන JWT එකක්).
   - `/Chathub/` ට පසුව ඇති Chathub මාර්ග ඛණ්ඩය (උදා. `<oid>@<tenant>`).

සම්පූර්ණ URL එකේ ආකෘතිය මෙසේය:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute තුළ **Providers → Add Provider** වෙත ගොස්, **Microsoft 365 Copilot
   (BizChat)** තෝරා, පහත ආකෘතියෙන් අක්තපත්රය අලවන්න:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** ක්ලික් කර **Save** ක්ලික් කරන්න.

## අක්තපත්ර ග්රහණය (HAR ආයාතය)

WebSocket URL එකෙන් අගයන් අතින් පිටපත් කිරීම වෙනුවට, ඔබට DevTools HAR ගොනුවක් නිර්යාත කළ හැක:

1. **DevTools → Network** විවෘත කරන්න.
2. BizChat සංවාදයක් ආරම්භ කරන්න හෝ දිගටම කරගෙන යන්න (මෙය WebSocket සම්බන්ධතාව සක්රිය කරයි).
3. Network පැනලය තුළ දකුණු-ක්ලික් කර **Save all as HAR with content** තෝරන්න.
4. OmniRoute තුළ, සපයන්නාගේ සම්බන්ධතා සංවාද කොටුවේ ඇති **Import .har file** බොත්තම භාවිත කරන්න.

OmniRoute විසින් Chathub WebSocket URL එක සඳහා HAR පරිලෝකනය කර, `access_token` සහ `chathubPath` උපුටාගෙන, අක්තපත්ර ක්ෂේත්ර ස්වයංක්රීයව පුරවයි. HAR ආයාතය JWT කල් ඉකුත්වීම විකේතනය කර ඉතිරි ටෝකන් ආයු කාලය පෙන්වයි.

> **සැබෑ HAR නිර්යාතයක්, ප්රවේශ ටෝකනයක් හෝ නැවුම් කිරීමේ ටෝකනයක් කිසිවිටෙක commit නොකරන්න.** පරීක්ෂණ සහ ප්රලේඛන අගයන් සැමවිටම ස්ථානධාරක විය යුතුය.

## ටෝකන වලංගු කාලය සහ නැවුම් කිරීම

`access_token` කෙටි කාලයක් සඳහා වලංගු වේ (සාමාන්යයෙන් **~මිනිත්තු 75**). භාවිත කළ හැකි refresh
ටෝකනයක් නොමැති නම්, කල් ඉකුත් වූ පසු ඔබ අක්තපත්රය නැවත ලබාගත යුතුය.

### `refreshToken` සමඟ ස්වයංක්රීය නැවුම් කිරීම

Microsoft 365 provider හි **සම්බන්ධතාව එක් කරන්න** හෝ **සම්බන්ධතාව සංස්කරණය කරන්න** සංවාද කොටුවේ,
**උසස් සැකසුම් → Refresh token (විකල්ප)** විවෘත කරන්න. `substrate.office.com/sydney` scope සඳහා
Microsoft OAuth refresh token එකක් අලවා සුරකින්න. ආදානය ආවරණය කර ඇති අතර ගබඩා කර ඇති token
එක කිසිවිටෙක පෙර පිරවෙන්නේ නැත. සංස්කරණය කරන විට, පවතින token එක තබා ගැනීමට එය හිස්ව තබන්න;
එය ප්රතිස්ථාපනය කිරීමට නව token එකක් අලවන්න.

`substrate.office.com/sydney` scope සඳහා Microsoft device-code හෝ authorization-code flow එකකින්
refresh token එක ලබාගන්න; dashboard එක එය ඔබ වෙනුවෙන් ලබා නොගනී. Refresh token එකක් වින්යාස කර
ඇති විට, OmniRoute ඉල්ලීම් කිරීමට පෙර `access_token` පරීක්ෂා කර, එය නැවුම් කළ යුතු අවස්ථාවකදී
පමණක් නැවුම් කරයි. සාර්ථක නැවුම් කිරීමකදී භ්රමණය වූ refresh token එකද සුරකින බැවින්, refresh
token එක වලංගුව පවතින තාක් අතින් නැවත ලබාගැනීම අවශ්ය නොවේ.

`refreshToken` සකසා නොමැති නම්, සෑම කල් ඉකුත්වීමකින් පසුම WebSocket අක්තපත්රය අතින් නැවත
ලබාගත යුතුය.

### ස්ථරය තේරීම

| Tier         | Alias       | Surface                |
| ------------ | ----------- | ---------------------- |
| `individual` | _(පෙරනිමි)_ | Consumer M365 Copilot  |
| `edu`        | `included`  | Education M365 Copilot |
| `enterprise` | `work`      | M365 Copilot for Work  |

**උසස් සැකසුම් → Copilot ස්ථරය** තුළ ස්ථරය සකසන්න. මෙම ස්ථරය
BizChat routing සහ model access වෙත බලපායි.

## ආරක්ෂක ආකෘතිය

- **නිල නොවන ඒකාබද්ධ කිරීමකි.** මෙම සපයන්නා BizChat WebSocket
  ප්රොටෝකෝලය ප්රති-ඉංජිනේරුකරණය කරයි. Microsoft විසින් endpoint එක වෙනස් කළ විට මෙය දැනුම්දීමකින් තොරව ක්රියා විරහිත විය හැක.
- `subscriptionRisk: true` ධජය මඟින් මෙම ඒකාබද්ධ කිරීම ලේඛනගත නොකළ
  endpoint එකක් මත රඳා පවතින බව දක්වයි. ගිණුම් සීමා කිරීම් සිදුවිය හැකි නමුත් ඒවා තහවුරු කර නොමැත.
- access token එක කෙටි කාලීන JWT එකකි. එය මුරපදයක් ලෙස සලකන්න: එය commit කිරීමෙන්,
  log කිරීමෙන් හෝ බෙදාගැනීමෙන් වළකින්න.
- refresh token එක BizChat අතුරුමුහුණත වෙත දිගුකාලීන ප්රවේශය ලබා දෙයි. එය
  API key එකක් මෙන්ම සැලකිල්ලෙන් ගබඩා කරන්න.

## දෝෂ නිරාකරණය

### සත්යාපනය වහාම අසාර්ථක වේ

- ඔබ XHR/Fetch ඉල්ලීමකින් නොව, **WebSocket URL** වෙතින් පිටපත් කළ බව තහවුරු කරන්න. අක්තපත්රය Chathub WebSocket සම්බන්ධතාවයේ `access_token` විමසුම් පරාමිතිය තුළ ඇත — `Authorization: Bearer` ශීර්ෂයක නොවේ.
- `chathubPath` තුළ URL මාර්ගයෙන් ලැබෙන සම්පූර්ණ `<oid>@<tenant>` කොටස ඇතුළත් බව තහවුරු කරන්න.

### ටෝකනය මිනිත්තු ~75කට පසු කල් ඉකුත් වේ

මෙය අපේක්ෂිත හැසිරීමකි. `refreshToken` එකක් නොමැති විට, ප්රවේශ ටෝකනය කෙටි කාලයක් පමණක් වලංගු වේ. පහත ක්රමවලින් එකක් භාවිත කරන්න:

- DevTools වෙතින් අක්තපත්රය නැවත ලබාගන්න, නැතහොත්
- ස්වයංක්රීය නැවුම් කිරීම සඳහා සම්බන්ධතාව එක් කිරීම හෝ සංස්කරණය කිරීමේ සංවාද කොටුවේ **උසස් සැකසුම් → නැවුම් ටෝකනය (විකල්ප)** වින්යාස කරන්න.

### සම්බන්ධතාව පරීක්ෂා කිරීම සාර්ථක වුවද කතාබහ 401 ලබා දෙයි

වලංගුකරණය සහ පළමු ඉල්ලීම අතරතුර ටෝකනය කල් ඉකුත් වී තිබිය හැක. නැවුම් අක්තපත්රයක් නැවත ලබාගන්න.
