## 3. `src/` — Next.js යෙදුම

```
src/
├── app/                  App Router pages + API routes
├── lib/                  Core libraries (DB, auth, OAuth, skills, memory, …)
├── domain/               Pure domain layer (policy, fallback, cost, lockout, …)
├── server/               Server-only modules (authz, cors, auth)
├── shared/               Types, constants, validation, contracts, utils (cross-boundary safe)
├── mitm/                 Man-in-the-middle proxy helpers for CLI integration
├── models/               Local model metadata / aliasing
├── sse/                  Legacy SSE handlers that still live under src/ (not open-sse/)
├── store/                Client-side state stores
├── middleware/           Route-level middleware utilities (not Next.js global middleware)
├── scripts/              In-tree scripts importable by app code
├── types/                Ambient and shared TS types
├── i18n/                 Locale bundles
├── instrumentation.ts    Next.js instrumentation hook
├── instrumentation-node.ts
└── proxy.ts              Top-level proxy bootstrap helper
```

### 3.1 `src/app/` — යෙදුම් රවුටරය

යෙදුම් රවුටරය උපකරණ පුවරුව UI සහ public/management HTTP API දෙකම නිරාවරණය කරයි. අර තියෙන්නේ** ගෝලීය මිඩ්ල්වෙයාර් නැත** — බාධා කිරීම් එක් මාර්ගයකට සිදු කෙරේ.

`src/app/` යටතේ ඉහළ මට්ටමේ කොටස්:

| ----------------------------------------------------------------------------- | ------------------------------------------------ |

- **ESLint**: සෑම තැනකම `no-eval`, `no-implied-eval`, `no-new-func` = `error`;
  `open-sse/` සහ `tests/` තුළ `no-explicit-any` = `warn`, අනෙක් ස්ථානවල error.
- **TypeScript**: `strict: false` (පැරණි ස්ථාවරය). modules අතර සීමා සඳහා
  inference වෙනුවට පැහැදිලි types භාවිත කිරීමට ප්රමුඛත්වය දෙන්න.
- **දත්ත සමුදාය**: routes හෝ handlers තුළ කිසිවිටෙක raw SQL නොලියන්න — සැමවිටම
  `src/lib/db/` modules හරහා යන්න. කිසිවිටෙක barrel-import නොකරන්න — නිශ්චිත `src/lib/db/*` modules සෘජුව භාවිත කරන්න.
- **DB-entity typing (#3512)**: DB table එකක row ආකෘතිය ලියන හෝ කියවන function එකක්,
  call site එකේ `any` හෝ inline anonymous type එකක් වෙනුවට, එම table එකේ
  columns 1:1 ලෙස පිළිබිඹු කරන නම් කළ TS interface එකක් ලබාගෙන/ආපසු ලබා දිය යුතුය.
  interface එක function එක අසල තබන්න (උදා. `saveRequestUsage` ට ඉහළින්
  `src/lib/usage/usageHistory.ts` තුළ `export interface UsageEntry`), විවිධ writers විසින් row එක
  ක්රමයෙන් පුරවන විට එක් එක් fields optional/nullable ලෙස තබන්න,
  සහ callers අතර ආකෘතිය වෙනස් වන field එකක් සඳහා `any` වෙනුවට `unknown` භාවිත කිරීමට ප්රමුඛත්වය දෙන්න
  (field එක මත එය ලේඛනගත කරන්න, උදා. `UsageEntry.tokens`
  raw provider-shaped usage සහ normalized shape යන දෙකම පිළිගනී). මේ ආකාරයෙන්
  file එකක `any` ගණන ශුන්යයට ළඟා වූ පසු, එය නැවත පිරිහිය නොහැකි වන සේ

  `maxAny: 0`) එක් කරන්න. මෙය first-slice සම්මුතියකි — පුළුල් "anonymous `any` නැත"
  පිරිසිදු කිරීම අනෙකුත් codebase එක පුරා පුනරාවර්තනීයව සිදු කෙරේ.
- **දෝෂ**: නිශ්චිත error types සමඟ try/catch භාවිත කර, pino context සමඟ log කරන්න. SSE streams තුළ

## 12. දැඩි නීති (CLAUDE.md වෙතින්)

1. කිසිවිටෙකත් රහස් හෝ අක්තපත්ර commit නොකරන්න.
2. කිසිවිටෙකත් barrel-import නොකරන්න — නිශ්චිත `src/lib/db/*` මොඩියුල සෘජුවම භාවිත කරන්න.
3. කිසිවිටෙකත් `eval()` / `new Function()` / ව්යංග eval භාවිත නොකරන්න.
4. කිසිවිටෙකත් `main` වෙත සෘජුවම commit නොකරන්න.
5. කිසිවිටෙකත් routes තුළ raw SQL නොලියන්න — සැමවිටම `src/lib/db/` මොඩියුල හරහා යන්න.
6. SSE streams තුළ දෝෂ නිහඬව නොසලකා නොහරින්න.
7. සැමවිටම Zod schemas මඟින් ආදාන වලංගු කරන්න.
8. production code වෙනස් කරන විට සැමවිටම පරීක්ෂණ ඇතුළත් කරන්න.
9. ආවරණය (statements, lines, functions, branches) ≥ 60% මට්ටමේ පවත්වාගත යුතුය.
