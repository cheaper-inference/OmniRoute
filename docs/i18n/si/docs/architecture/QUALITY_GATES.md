## ගේට් ඉන්වෙන්ටරි සහ ක්‍රියාත්මක කිරීමේ පැතිකඩ

### අපේක්ෂක ඇතුළත් කිරීම

CI සහ Quality Gates කාර්ය ප්‍රවාහයන් එක් එක් ස්ථාවර තීන්දුවක් නිකුත් කරයි: `Gate / CI` සහ `Gate / Quality`. ඔවුන්ගේ අනුවාදගත ඇතුළත් වීමේ ප්‍රතිපත්තිය අවශ්‍ය හෝ උපදේශන ලෙස සෑම ඉහළ ප්‍රවාහ රැකියාවක්ම ගණන් කරයි. අදාළ අවශ්‍ය රැකියාවක් සාර්ථක විය යුතුය: අතුරුදහන්, අවලංගු, මඟ හැරුණු, පොරොත්තු සහ නොදන්නා ප්‍රතිඵල PASS ස්ථාපිත කළ නොහැක. වලංගු ලේඛන-පමණක් හෝ නාමාවලිය-පමණක් වර්ගීකරණයක් කේත මංතීරුවක් අදාළ නොවන බවට පත් කළ හැක; සාමාන්‍ය කෙටුම්පතක් PR පිළිගත් අපේක්ෂකයෙකු නොවේ. `hotfix` ලේබලයක් සාක්ෂි අත්හරින්නේ නැත.

කාර්ය ප්‍රවාහ දෙකම PRs main/release ශාඛාවලට ආවරණය කරයි, `main` වෙත තල්ලු කරයි, අතින් යැවීම සහ සමූහ සිදුවීම් ඒකාබද්ධ කරයි. තල්ලු කිරීම, යැවීම සහ ඒකාබද්ධ-කණ්ඩායම සම්පූර්ණ තේරීම ධාවනය කරන්න. විශ්වාසදායී Mergify පෝලිම් කෙටුම්පතක් අදාළ `full-code`/`full-code-e2e` රැකියා ද ධාවනය කරයි; සාමාන්‍ය PRs ඒවා මඟ හරින්න. හස්තීය ඒකාබද්ධ කිරීමකට පෙර, නිශ්චිත අපේක්ෂකයා මත සම්පූර්ණ යැවීමක් ධාවනය කරන්න. `release/**` වෙත තල්ලු කිරීම් මෙම කාර්ය ප්‍රවාහයන් ආරම්භ නොකරයි; මුදා හැරීම-හරිත ඒකාබද්ධ කළ පදනම වෙන වෙනම නිරීක්ෂණය කරයි (`docs/ops/RUNNER_BOX.md` → සත්කාරක මංතීරුව). ගෑරුප්පු සහ ඒකාබද්ධ කණ්ඩායම් වෙනත් ආකාරයකින් ස්වයං-සත්කාරක ධාවකයන් තෝරා ගන්නා රැකියා සඳහා සත්කාරක ධාවකයන් භාවිතා කරයි; ප්‍රමාණවත් සත්කාරක ධාරිතාව ප්‍රචාරණයට පෙර සත්‍යාපනය කළ යුතුය.

සාමාන්‍ය PR වේගයෙන් තේරීම ක්‍රියාත්මක කරයි. ඇතුළත් වීමේ ප්‍රතිපත්තියේ `full-code` සහ `full-code-e2e` මංතීරු (E2E, ඒකාබද්ධ කිරීම, පැකේජ පුරාවස්තු, Electron දුම, Bun SQLite, පරිසර පද්ධතිය සහ ප්‍රොටෝකෝල සේවාලාභීන්) ධාවනය වන්නේ Mergify පෝලිම් කෙටුම්පතක් මත හෝ සම්පූර්ණ ධාවන කාලයකදී පමණි: `gh workflow run ci.yml --ref <branch>`.

සෑම JSON කුවිතාන්සියක්ම පරීක්ෂා කළ SHA, කාර්ය ප්‍රවාහ ධාවනය සහ උත්සාහය හඳුනා ගනී. CLI checkout/event SHA නොගැලපීම ප්‍රතික්ෂේප කරයි. කාර්ය ප්‍රවාහ පරීක්‍ෂණ මගින් ප්‍රතිපත්ති සාමාජිකත්වය විනිශ්චය කාර්යයේ `needs` ලැයිස්තුවට සම්බන්ධ කරයි, එබැවින් නව හෝ ඉවත් කරන ලද මංතීරුවක් නිහඬව අතුරුදහන් විය නොහැක. රිසිට්පත් ඔවුන්ගේම කාර්ය ප්‍රවාහය ආවරණය කරයි, ප්‍රකාශනය, යෙදවීම හෝ පවතින උපදේශක ස්කෑනරයක අභ්‍යන්තරය නොවේ. ශාඛා නීතිවල අවශ්‍ය අදාළ චෙක්පත් සිදු කිරීම වෙනම පරිපාලනමය වෙනසක් වේ; ඔවුන්ගේ රැකියා නිර්වචනය කිරීම ශාඛාවක් ආරක්ෂා නොකරයි.

`API Route Typecheck` යනු සමස්ථ තීන්දු සහ දේශීය පූර්ණ නිරීක්ෂකයාගේ ස්ථිතික පැතිකඩ යන දෙකින්ම පිටත ස්වාධීන කාර්ය ප්‍රවාහ පරීක්ෂාවකි. නිශ්චිත අපේක්ෂකයා සඳහා එහි ප්‍රතිඵලය වෙන වෙනම පරීක්ෂා කරන්න. `.github/workflows/api-route-typecheck.yml` PRs මත `main` හෝ `release/**` වෙත ධාවනය වේ, ශාඛා පවුල, අතින් යැවීම සහ `checks_requested` වර්ගයේ `merge_group` සිදුවීම් වෙත තල්ලු කරයි. එහි පාත් ෆිල්ටරයක් නොමැත. කණ්ඩායම් ඒකාබද්ධ කරන්න `merge_group.head_sha` පරීක්ෂා කරන්න ; අනෙකුත් සිදුවීම් `github.sha` පරීක්ෂා කරන්න. සියලුම සිදුවීම් එකම API රෝග විනිශ්චය ද්වාරය සහ ද්වාර ඒකක පරීක්ෂණ භාවිතා කරයි. PR පදනම් retargets නව චෙක්පතක් ඉල්ලා සිටී; body/title සංස්කරණයන් නිරීක්ෂණ-පමණක් `Admission not requested / API Route Typecheck` යන නම භාවිතා කරන අතර ඇතුළත් කිරීමේ චෙක්පත ප්‍රතිස්ථාපනය කළ නොහැක.

### පිළිගැනීම් අඩු කරන්නා තුළ රඳවා ගත් සාක්ෂි

`scripts/quality/validate-release-acceptance.mjs` සැපයූ සැලැස්මක් අඩු කරයි සහ එහි ප්‍රකාශනය; සැලැස්ම සම්පූර්ණ මුදා හැරීමේ නල මාර්ගය ආවරණය කරන බව තහවුරු නොවේ. එම සැලැස්ම `VERIFIED` වන විට පවා එහි වාර්තා පැහැදිලිවම `releaseAcceptance: false` ලෙස සකසා ඇත. `release-acceptance.yml` කාර්ය ප්‍රවාහය තවමත් සෙවනැලි සවිකිරීම් භාවිතා කරයි, සැබෑ ගොඩනැගීම, පැකේජය, ඇරඹුම් හෝ ප්‍රවර්ධන ලදුපත් නොවේ.

CLI හට රඳවා ඇති සාක්ෂි සත්‍යාපනය කිරීමට `--evidence-root` අවශ්‍ය වේ. ගොනු `<evidence-root>/<artifact_id>/<member>` ලෙස විසඳා SHA-256 ලෙස හැෂ් කර ඇත. සාක්ෂි නොමැති PASS වාර්තාවක්, නැතිවූ හෝ වෙනස් වූ ගොනුවක්, අනාරක්ෂිත මාර්ගයක් හෝ symlink එකක් සත්‍යාපනය වළක්වයි. නැතිවූ ගොනු හිස් සාර්ථක ලොගවලට සමාන නොවේ. පවතින SHA/run/attempt චෙක්පත් ස්වාධීනව පවතී: ගැළපෙන බයිටවලට පරණ ලදුපතක් සුරැකිය නොහැක. ගොනු අඛණ්ඩතාව ක්‍රියාත්මක කිරීමේ සත්‍යතාව හෝ කෞතුක භාණ්ඩ ප්‍රවර්ධනය පිළිබඳ සාක්ෂි නොවේ.

### DAST සත්‍යාපිත CI ගොඩනැගීම පරිභෝජනය කරයි

අවශ්‍ය `dast-smoke` CI රැකියාව `build` ට පසුව `.github/workflows/dast-smoke.yml` අමතයි. එය සහය දක්වන ෆෝක් PRs, මුදා හැරීමේ-ඉලක්ක PRs සහ කණ්ඩායම් ඒකාබද්ධ කිරීම ඇතුළුව ගොඩනැගීමේ එකම code/draft තේරීම අනුගමනය කරයි. අස්ථානගත වූ, අසාර්ථක වූ, අවලංගු වූ හෝ අනපේක්ෂිත ලෙස මඟ හරින ලද DAST කාර්යය `Gate / CI` අවහිර කරයි. නැවත භාවිත කළ හැකි කාර්ය ප්‍රවාහයට ස්වාධීන PR/dispatch ප්‍රේරකයක් නොමැත; අතින් වලංගු කිරීම CI හි යැවීම භාවිතා කරයි, එබැවින් ගොඩනැගීම සහ පාරිභෝගිකයා එක ධාවනයක පවතී.

### UI ක්‍රියාත්මක කිරීමේ ධාරිතාව

CI සම්පූර්ණ UI බඩු තොගය `test-vitest` matrix shards හතරක් ලෙස ක්‍රියාත්මක කරයි, ඒ සෑම එකක්ම එක shard එකකට වැඩිම කම්කරුවන් දෙදෙනෙකු සහ දැනට පවතින 15-මිනිත්තු රැකියා අවසන් දිනයයි. පළමු කොටස MCP/autoCombo Vitest කට්ටලය ද ධාවනය කරයි. අවශ්ය රැකියා ප්රතිඵලය සෑම matrix කකුලක්ම ආවරණය කරයි; එක් කැබැල්ලක් අසමත් වීම හෝ අවලංගු කිරීම අපේක්ෂකයින් ඇතුළත් කිරීම ස්ථාපිත කළ නොහැක.

රාත්‍රී නිරීක්ෂකයා පළමු රිසිට්පතේ MCP ක්‍රියාත්මක කිරීම ඇතුළුව, එක් එක් UI ෂාර්ඩ් සඳහා වෙනම නිශ්චිත-අපේක්‍ෂක ලදුපතක් තබා ගනී. සියලුම රිසිට්පත්, ලඝු-සටහන් සහ ගැලපෙන ක්‍රියාත්මක කිරීමේ අනන්‍යතා හතරම අවශ්‍ය වේ. දේශීය `npm run test:vitest:ui` තවමත් සම්පූර්ණ කට්ටලය තෝරා ගනී; එක් `--shard` ධාවනය අර්ධ සාක්ෂියක් පමණි.

### ඒකක ආවරණ එකතුව

ඒකක කැබලි දොළහ ඔවුන්ගේ පවතින පරීක්ෂණ ක්‍රියාත්මක කිරීමේදී V8 ආවරණය රැස් කරයි. සාර්ථක ෂාර්ඩ් එකක් අතරමැදි ඉස්තාන්බුල් වාර්තාවක් ජනනය නොකර මුල් ගොනු සම්පීඩනය කිරීමට `scripts/ci/compact-v8-coverage.mjs` ධාවනය කරයි. අවසාන ආවරණ කාර්යය SHA, ධාවන කාලය, මූලාශ්‍ර මූල සහ දත්ත හැෂ් අපේක්ෂකයාට එරෙහිව ප්‍රකාශන දොළහක්ම සත්‍යාපනය කරයි, පසුව c8 හි වාර්තාකරුවන් සහ පවතින ආවරණ සීමාවන් ධාවනය කරයි. ආදාන c8 හි ගෝලීය ගොනු නාම අනුපිළිවෙල රඳවා තබා ගනී; මිශ්‍ර function/block ආවරණය සඳහා per-shard පෙර ඒකාබද්ධ කිරීම අනාරක්ෂිත ය. අස්ථානගත වූ, විකෘති වූ හෝ නොගැලපෙන කැබලි ඇතුළත් කිරීම අසමත් වේ. අසාර්ථක පරීක්ෂණ කැබලි අමු රෝග විනිශ්චය ආවරණය වෙන වෙනම රඳවා තබා ගනී; එයට අවසාන ඒකාබද්ධයට ඇතුළු විය නොහැක.

### ඒකක ක්‍රියාත්මක කිරීමේ ප්‍රගතිය ලැබීම්

බෙදාගත් `test:unit:ci:shard` විධානය `scripts/ci/unit-progress-reporter.mjs` හරහා `primary`, `dashboard` සහ `serial` අදියරයන් වාර්තා කරයි. සාමාන්‍ය පරීක්ෂණ වාර්තාව තවමත් තිබේ. වෙනම පාර-දත්ත-පමණක් ලදුපතක් එක් එක් ගොනුවේ ආරම්භය සහ සම්පූර්ණ කිරීම වාර්තා කරයි, තත්පර 30 ක හෘද ස්පන්දනයක් ගොනු තවමත් සක්‍රියව සහ ඒවායේ ගත වූ කාලය ලැයිස්තුගත කරයි. එය වාර්තා කරන්නේ අවසර ලත් ක්‍රියාත්මක පාර-දත්ත පමණි; පරීක්ෂණ විස්තර, ප්‍රතිදානය, දෝෂ ශරීර සහ සම්පූර්ණ පරිසරය අනුක්‍රමික නොවේ.

CI JSONL ගොනු `unit-progress-ci-<run>-<attempt>-<shard>` ලෙස රඳවා ගනී. රැකියා කල් ඉකුත්වීම පසුව උඩුගත කිරීම වැළැක්විය හැකිය; දැනටමත් නිකුත් කර ඇති හෘද ස්පන්දන රෝග විනිශ්චය සාක්ෂි ලෙස පවතී. නැතිවූ හද ගැස්ම අවහිර වූ හෝ අවසන් වූ ධාවන ක්‍රියාවලියක් ද පිළිබිඹු කළ හැකිය. මෙම රිසිට්පත් දැනට පවතින පරීක්ෂණ තේරීම, සමගාමීත්වය, නියමිත කාලසීමාවන් සහ පිටවීමේ තත්ත්වය ආරක්ෂා කරයි; ඒවා අපේක්ෂකයන් ඇතුළත් කිරීමේ තීන්දු නොවේ.

### පෝලිම ඒකාබද්ධ කරන්න

`queue` ලේබලය Mergify පෝලිමට PR යවයි (`.mergify.yml`). Mergify `mergify/merge-queue/` ශාඛාවක් මත PR කෙටුම්පතක් විවෘත කරයි, CI එහි සම්පූර්ණ තේරීම ධාවනය කරයි, `Gate / CI`, `Gate / Quality` සහ `Merge integrity (changelog + generated skills)` සමත් වූ විට මුල් PR ඒකාබද්ධ වේ.

Mergify එහි පෝලිම් සාරාංශය කෙටුම්පතේ විස්තරයට ලියයි. Body/title-only `pull_request` `edited` සිදුවීම් ධාවන-විශේෂිත සමගාමී කණ්ඩායමක් භාවිතා කරන අතර වර්ගීකරණය, න්‍යාස පරීක්ෂා කිරීම, අඛණ්ඩතාව ඒකාබද්ධ කිරීම හෝ ඇතුළත් කිරීමේ තීන්දුව නැවත ක්‍රියාත්මක නොකරයි. නිරීක්ෂණ-පමණක් චෙක්පත් නම් `Gate / CI` හෝ `Gate / Quality` ආදේශ කළ නොහැක. ඉලක්ක පදනම වෙනස් කරන සංස්කරණයක් නැවුම් අපේක්ෂක වලංගු කිරීමක් ඉල්ලා සිටී.

dequeue එකකින් පසු, තල්ලුවක් සෑම විටම PR ඉල්ලන්නේ නැත. එය මත `@mergifyio queue` අදහස් දක්වන්න.

### ස්ථිතික ස්කෑන් ඉන්වෙන්ටරි

අනුවාදිත npm-අන්වර්ථ ඉන්වෙන්ටරි සහ ස්ථිතික-ස්කෑන් සාමාජිකත්වය `config/quality/gate-manifest.json` හි සජීවී වේ. `package.json` ට එරෙහිව ස්ක්‍රිප්ට් නම් සහ නියම විධාන වලංගු කිරීමට `npm run check:gate-manifest` ධාවනය කරන්න; එකතු කිරීම්, ඉවත් කිරීම් සහ විධාන ප්ලාවිතය CI හි දේශීය කොක්ක සහ වෙනස් කිරීමේ වර්ගීකරණ කාර්යයන් දෙකම අසාර්ථක වේ. අන්වර්ථයක් යනු කාර්ය ප්‍රවාහ කාර්යයක්, න්‍යාස අවස්ථාවක් හෝ පරීක්ෂණ අවස්ථාවක් නොවේ: මෙම ගණන් එකිනෙකට හුවමාරු කළ හැකි ලෙස ඉදිරිපත් නොකළ යුතුය.

තෝරාගත් අන්වර්ථ ක්‍රියාත්මක නොකර පරීක්ෂා කිරීමට `npm run quality:scan -- --list` හෝ `npm run quality:scan:fast -- --list` භාවිතා කරන්න. ධාවකය npm පිවිසුම් ලක්ෂ්‍යය ආයාචනා කරයි, එබැවින් එහි ධාවන කාලය (වින්‍යාස කර ඇති Bun ඇතුළුව) සංරක්ෂණය කර ඇත. මැනිෆෙස්ට් වාර්තා එම පැතිකඩවලින් පිටත අන්වර්ථ නාමයන් වෙන වෙනම ඉල්ලා ඇති අතර, කියවීමට පමණක් ස්කෑන් පැතිකඩවල නඩත්තු විධාන තහනම් වේ.

මෙම පැතිකඩ ස්ථිතික ස්කෑන් කිරීම පමණක් ආවරණය කරයි. ඔවුන් නිෂ්පාදන පරීක්ෂණ, ආවරණය, ඇසුරුම්කරණය, බාහිර චෙක්පත් හෝ අපේක්ෂකයෙකුගේ සම්පූර්ණ නිකුතුව පිළිගැනීම සහතික නොකරයි. කාර්ය ප්‍රවාහ ඇතුළත් කිරීම සම්බන්ධිත `config/quality/admission-policy.json` සහ `scripts/quality/admission-verdict.mjs` භාවිතා කරයි. නිකුතු-නිරීක්ෂක පැතිකඩ වෙන්ව පවතී; ඔවුන්ගේ අදාළ චෙක්පත් සහ රිසිට්පත් ස්වාධීනව පරීක්ෂා කරන්න. සම්පූර්ණ නිරීක්ෂකයාගේ ස්ථිතික විධාන `audit:deps`, විකෘති-පරීක්ෂණ තේරීම සහ පරිවර්තන චෙක්පත් ඇතුළුව `config/quality/release-green-static-profile.json` හි ප්‍රකාශ කර ඇත. පූරකය package.json සහ ආකෘතිගත CI/Quality ප්‍රකාශයන්ට එරෙහිව npm විධාන වලංගු කරයි; එය ෂෙල් ටෝකන තර්ක ලෙස ක්‍රියාත්මක කිරීම වෙනුවට ප්ලාවිතය ප්‍රතික්ෂේප කරයි. අවශ්ය ස්කෑනර් SKIP/INCOMPLETE ප්රතිදානය PASS ස්ථාපිත කළ නොහැක . පැතිකඩ එහි බාහිර බැහැර කිරීම් වාර්තා කරන අතර සත්කාරක ආවරණය, පරීක්ෂණ න්‍යාස, පැකේජය හෝ යෙදවීමේ සාක්ෂි ප්‍රතිස්ථාපනය නොකරයි. පහත ගද්‍ය ඉන්වෙන්ටරිය යොමුවකි, ගේට්ටුවක් සැබවින්ම ක්‍රියාත්මක වූ බවට සාක්ෂි නොවේ.

ස්ක්‍රිප්ට් `scripts/check/` (ප්‍රතිපත්ති දොරටු) සහ `scripts/quality/` (රැට්චෙට් එන්ජිම) යටතේ ජීවත් වේ. සත්‍යයේ CI මූලාශ්‍රය `.github/workflows/ci.yml` වේ.

### ප්රකාශිත-පාදක ලේඛන සෞඛ්යය

`.github/workflows/i18n-base-health.yml` `main` සහ `release/v*` වෙත තෝරාගත් තල්ලු කිරීම්වලින් පසුව සහ අතින් යැවීමේදී ලේඛන සෞඛ්‍යය නිරීක්ෂණය කරයි. එහි පෙරහන් ලේඛනගත කිරීම, root Markdown, `llm.txt`, පරිවර්තනය state/configuration සහ අදාළ i18n මෙවලම් ආවරණය කරයි. තනි `Published base documentation health` කාර්යය සත්කාරක උබුන්ටු සහ මිනිත්තු පහක කාල සීමාවක් භාවිතා කරයි. එය කියවීමට පමණක් වලංගුකරණයක් සිදු කරන අතර පරායත්ත ස්ථාපනයකින්, පරිවර්තනයකින් හෝ රාජ්‍ය සම්මත කිරීමකින් තොරව රෝග විනිශ්චය කුවිතාන්සියක් ලියයි.

`scripts/i18n/check-base-health.mjs` සඳහා ශුන්‍ය මූලාශ්‍ර-හැෂ්, අතුරුදහන්-ඉලක්කය, ඉලක්ක-හැෂ්, පරණ-පරිවර්තන සහ කොටස්-හැඹිලි නොගැලපීම් අවශ්‍ය වේ. එය වත්මන් මූලික document/locale විෂය පථය සහ එහි වාර්තාගත ප්‍රභවය ද වලංගු කරයි. වලංගු නොවන සන්දර්භය, අසම්පූර්ණ ආවරණයක් හෝ බාධා කළ පරීක්ෂකයක් `INCOMPLETE` නිෂ්පාදනය කරයි ; තහවුරු ප්ලාවිතය `FAIL` නිෂ්පාදනය කරයි. දෙකම අසාර්ථක පිටවීමේ තත්ත්වය ලබා දෙයි. කුවිතාන්සිය SHA, වැඩ ප්‍රවාහය, ධාවනය සහ උත්සාහය සඳහා බැඳී ඇති අතර `i18n-base-health-<sha>-<run>-<attempt>` ලෙස රඳවා තබා ගනී.

මෙය ප්‍රකාශිත පදනමේ ස්වාධීන නිරීක්ෂණයකි. එය PR හෝ ඒකාබද්ධ-කණ්ඩායම් සිදුවීමක්, අවශ්‍ය PR චෙක්පතක්, npm අන්වර්ථයක් හෝ ස්ථිතික ස්කෑන් පැතිකඩ සාමාජිකයෙකු එක් නොකරයි. යටින් පවතින පරීක්ෂකය නිරපේක්ෂ මාදිලියේ පන්ති පහම අවහිර කරයි. සාමාන්‍ය PR සූදානම ඇතුළත් වීමෙන් වෙන්ව පවතී. සාර්ථක උඩුගත කිරීමකින් අසාර්ථක සෞඛ්‍ය ප්‍රතිඵලයක් PASS බවට පත් කළ නොහැක.

සාමාන්‍ය PR එකක් `--baseline-evidence` මගින් ජනනය කරන ලද පාදක වාර්තාවක් සහිත `--preflight` භාවිතා කරයි. සම්පූර්ණ පරිවර්තන වාර්තාව සහ සත්‍ය ඉලක්ක බයිට් එම නිශ්චිත පදනමෙන් නොවෙනස්ව ඇති විට පමණක් එය ඉංග්‍රීසි මූලාශ්‍රයක් ඉතිරිව තිබිය හැක. නව ඉලක්ක හෝ කොටස්-හැඹිලි නොගැලපීම් තවමත් අවහිර වන අතර අසම්පූර්ණ සාක්ෂි වලට සූදානම් වීමට අවසර දිය නොහැක. වාර්තාව `preparationPending` සහ `mergeReady` වෙන වෙනම හෙළිදරව් කරයි: සාර්ථක ලෙස සකස් කිරීම පොරොත්තු පරිවර්තන ඒකාබද්ධ කිරීමට සූදානම් නොවේ. ඇතුළත් වීමට පෙර රචනා කළ අපේක්ෂකයාගේ බලපෑමට ලක් වූ දර්පණ නැවුම් කරන්න. විශ්වාසදායී Mergify පෝලිම් අපේක්ෂකයා, `merge_group`, ශාඛා තල්ලු කිරීම් සහ අතින් CI ධාවන `--warn` හෝ උරුම-අසාර්ථක සමාව නොමැතිව නිරපේක්ෂ පරීක්ෂකය භාවිතා කරයි. අස්ථානගත වූ ඉලක්ක හෑෂ් සහ මකා දැමූ වාර්තාගත හර ගොනු මඟින් අඩු කළ විෂය පථය සාර්ථක නිරපේක්ෂ තීන්දුවක් ලබා දිය නොහැක.

### PR වේගවත් මාවත (`quality.yml`) මුදා හරින්න

`.github/workflows/quality.yml` main/release PRs මත CI සම්පූර්ණ කරයි, `main` වෙත තල්ලු කරයි, කණ්ඩායම් යැවීම සහ ඒකාබද්ධ කිරීම. PRs මාර්ගයෙන් පෙරන ලද වේගවත් චෙක්පත් භාවිතා කරයි. ස්ථිරව අබල කළ අනුපිටපත් ගොඩනැගීම ඉවත් කරන ලදී; සැබෑ build/package/boot චෙක්පත් CI හි පවතී. ඒකක කට්ටලය සහ vitest ධාවනය වන්නේ CI (`Unit Tests (N/12)` සහ `Vitest`) තුළ පමණි.

#### අමතක වූ සහෝදර සහෝදරියන්ගේ පරීක්ෂණ වාර්තාව

`npm run check:forgotten-sibling-tests` `Fast Quality Gates` හි උපදේශන පියවරක් ලෙස ක්‍රියාත්මක වන අතර පරීක්ෂණ-බලපෑම් සිතියම පිටුපස ආයාත විසදුම නැවත භාවිතා කරයි. වෙනස් වූ සෑම නිෂ්පාදන මොඩියුලයක් සඳහාම, අපේක්ෂක පරීක්ෂණය අදින්න-ඉල්ලීමේ වෙනසෙන් නොමැති විට එය නියත `changed module/symbol -> static consumer -> candidate sibling test` දාමයන් වාර්තා කරයි. Markdown සාරාංශය සහ JSON ප්‍රතිඵලය ඕනෑම අවහිර කිරීමේ පෙරළියකට පෙර ක්‍රමාංකනය සඳහා `forgotten-sibling-tests` කාර්ය ප්‍රවාහ කෞතුක වස්තුව ලෙස රඳවා තබා ගනී.

බැරල් ප්‍රති-අපනයන සහ ගතික ආනයනයන් විභේදන රෝග විනිශ්චයන් පමණි; ඔවුන් කිසි විටෙකත් අවහිර සොයාගැනීමක් නිර්මාණය නොකරයි. සමාලෝචිත ව්‍යතිරේක සජීවීව `config/quality/forgotten-sibling-allowlist.json`. සෑම ප්‍රවේශයක්ම පාරිභෝගික සහ අපේක්ෂක පරීක්ෂණය නම් කළ යුතුය, නිශ්චිත තාර්කිකත්වයක් ලබා දිය යුතුය, සහ GitHub නිකුතුවක් හෝ අදින්න ඉල්ලීමක් සම්බන්ධ කළ යුතුය. විකෘති ඇතුළත් කිරීම් අසාර්ථකයි වසා ඇත. ව්‍යතිරේකවලට මකා දැමූ අපේක්ෂක පරීක්ෂණයක් හෝ `.skip`/`.todo` එකතු කරන වෙනස මැඩපැවැත්විය නොහැක ; ප්‍රකාශය දුර්වල කිරීම සහ වෙනත් ආවරණ ස්වාධීනව අවහිර කරන `check:test-masking` ගේට්ටුව සතු වේ.

#### ටයිප් චෙක් වැඩසටහන් දෙකක් වෙනස් ලෙස පිළිතුරු දෙයි

`typecheck:core` (`noImplicitAny: false`) / `typecheck:noimplicit:core` (`noImplicitAny: true`) සහ `check:build-typecheck` විවිධ විකල්ප යටතේ විවිධ වැඩසටහන් සම්පාදනය කරන අතර, එකම ගොනුව එකක පිරිසිදු විය හැකි අතර අනෙකෙහි දෝෂ වලින් පිරී ඇත.

`tsconfig.build.json` `"strict": false` සකසයි, එබැවින් `noImplicitAny` අක්‍රියයි. මූලික වින්‍යාසය දැඩි විකල්ප සමඟ සංක්‍ෂිප්ත ගොනු 27 අවසර ලැයිස්තුවක් සම්පාදනය කරන අතර එක් එක් ප්‍රවේශයේ ආයාත ප්‍රස්ථාරය අනුගමනය කරයි, එබැවින් ගොඩනැගීමේ වැඩසටහනේ කිසිදා නොපෙන්වන ගොනු තවමත් එහි පරීක්ෂා කෙරේ.

ගොනුවක් ටයිප් කර ඇත්ද යන්න විනිශ්චය කිරීමේදී ප්‍රතිවිපාකය වැදගත් වේ:**`check:build-typecheck` යටතේ zero diagnostics යන්නෙන් අදහස් වන්නේ ශුන්‍ය නොවේ** . ගොනු 26 කින් `@ts-nocheck` ඉවත් කිරීමෙන් ඒවායින් 23 ක් ගොඩනැගීමේ වැඩසටහනේ පිරිසිදු බව පෙන්නුම් කරයි; ඒවායින් 16ක් 120ක් පමණ මතු විය - දැඩි දෝෂයේ කිසියම් දෝෂයක් තිබේ. ගොනුවක් පිරිසිදු කිරීමට පෙර දෙකම පරීක්ෂා කරන්න.

- `sync-ui-keys` නැවත පිරවීමේ යතුරු පමණි**නොපැමිණීම** , කවදාවත් එහෙම නැති ඒවා**පරණයි** ;
- `check-ui-keys-coverage` යතුර _පැමිණීම_ ගණන් කරයි, එබැවින් පරණ පරිවර්තනයක් ආවරණය කර ඇති පරිදි ලකුණු කරයි;
- `check-translation-drift` `docs/i18n/<locale>/**.md` ප්‍රලේඛනය නිරීක්ෂණය කරයි — එය කිසි විටෙක `src/i18n/messages/*.json` කියවන්නේ නැත. 2026-09 නැවත සමමුහුර්ත කිරීමේ සිට `docs-sync-strict` රැකියාව අවහිර කිරීම: මූලික ලේඛනයක් → `npm run i18n:run -- --files=<doc>` සංස්කරණය කරන්න (අංශ මට්ටම, ලාභ).

**වෙනස්-දැනුවත්, මූලික පිටුබලය සහිත නොවේ.** එය වැඩ කරන ගසට එරෙහිව ඒකාබද්ධ පදනමේ `en.json` සංසන්දනය කරයි; ඉංග්‍රීසි අගය වෙනස් වූ සෑම යතුරක් සඳහාම, තවමත් ස්පර්ශ නොකළ පරිවර්තනයක් ඇති ඕනෑම පෙදෙසක් පරණ වේ. මෙය හිතාමතාම **පෙර පැවති ණය කැටි කරයි** — වෙනසකට දිගුකාලීන පරිවර්තනයක් පැමිණියේ කුමන පැරණි ඉංග්‍රීසියෙන්ද යන්න හෙළි කළ නොහැක, එබැවින් ගේට්ටුව විනිශ්චය කරන්නේ වත්මන් වෙනස ස්පර්ශ කරන දේ පමණි. විකල්පය (එක්-යතුර හෑෂ් මූලික රේඛාවක්) සඳහා ~ 600 KB ජනනය කරන ලද ගොනුවක්, 3 × දැනට පවතින විශාලතම මූලික රේඛාව වන අතර, සෑම i18n PR මතම වැය වේ.

එය තෘප්තිමත් කිරීමට ක්රම දෙකක්:

1. බලපෑමට ලක් වූ පරිවර්තන යාවත්කාලීන කරන්න, හෝ
2. ඒවා `__MISSING__:<new english>` — ලෙස සකසන්න ධාවන කාලය පසුව නිවැරදි කරන ලද ඉංග්‍රීසි (`src/i18n/request.ts::deepMergeFallback`, #7258) සහ පරිවර්තනය සඳහා ප්‍රධාන පෝලිම් සපයයි.

තන්තුව නම්**අර්ථය** වෙනස්, කැමති**යතුර නැවත නම් කිරීම** : නව යතුරකට පරණ පරිවර්තනයක් උරුම විය නොහැක. #8463 භාවිතා කරන රටාව එයයි.

```bash
npm run i18n:check-value-drift          # strict (what CI runs)
npm run i18n:check-value-drift:warn     # report only
BASE_REF=origin/release/vX.Y.Z npm run i18n:check-value-drift
```

අගය-ප්ලාවිතය සහ නව-යතුරු දොරටු `scripts/i18n/resolve-ui-diff-base.mjs` වෙතින් එක් වෙනස් කළ නොහැකි සංසන්දනයක් බෙදා ගනී. කාර්ය ප්‍රවාහය චෙක්පත් දෙකටම එකම පදනම, මූලික ඉඟිය සහ අපේක්ෂක SHAs පසු කරයි. PR/base-retarget, push සහ merge-group run ඔවුන්ගේ සිද්ධි සන්දර්භය භාවිතා කරයි. අපේක්ෂක ශාඛාවක් යැවීමට එහි නිශ්චිත විවෘත PR හෝ පැහැදිලි `i18n_base_sha` ආදානය අවශ්‍ය වේ. එම ආදානය නොමැතිව `main` හෝ `release/vX.Y.Z` යැවීම හෝ කාලසටහන්ගත නිරීක්ෂණය කිරීම එහි පළමු මාපියන් සමඟ අවසන් කැපවීම සංසන්දනය කරයි; එය සියලු උරුම පරිවර්තන ණය පිළිබඳ විගණනයක් නොවේ. දේශීය ආයාචනය සඳහා පැහැදිලි සංසන්දන පදනමක් අවශ්‍ය වේ, උදාහරණයක් ලෙස ඉහත `BASE_REF` විධානය.

නැතිවූ හෝ අපැහැදිලි සංසන්දනාත්මක සන්දර්භයක්, කියවිය නොහැකි හෝ වලංගු නොවන අවශ්‍ය නාමාවලියක් සහ වෙනස් වූ අපේක්ෂකයෙකු පිටවීමේ කේතය සමඟ `INCOMPLETE` නිෂ්පාදනය කරයි**2** , අනතුරු ඇඟවීමේ මාදිලිය ඇතුළුව. නාමාවලි කියවීම් `scripts/i18n/read-ui-catalog.mjs` භාවිතා කරයි; කියවීමේ අසාර්ථකත්වය හිස් වස්තූන් සමඟ ආදේශ නොකෙරේ. ලබා ගත නොහැකි පදනමක් හෝ අසම්පූර්ණ ආදානයක් PASS ස්ථාපිත නොකරයි.

## Ratchet මූලික රේඛාව (`quality-baseline.json`)

Ratchet එන්ජිම (`scripts/quality/check-quality-ratchet.mjs`) `quality-baseline.json` කියවා,
අලුතින් රැස් කළ `quality-metrics.json` සමඟ එය සසඳයි. එහි epsilon සීමාව ඉක්මවා
පසුබැසෙන ඕනෑම ප්රමිතිකයක් build එක අසාර්ථක කරයි.

දැනට නිරීක්ෂණය කරන ප්රමිතික:

| ප්රමිතිකය             | දිශාව  | අර්ථය                                     |
| --------------------- | ------ | ----------------------------------------- |
| `eslintWarnings`      | `down` | ESLint අනතුරු ඇඟවීම් ගණන වැඩි නොවිය යුතුය |
| `coverage.statements` | `up`   | Statement coverage අඩු නොවිය යුතුය        |
| `coverage.lines`      | `up`   | Line coverage අඩු නොවිය යුතුය             |
| `coverage.functions`  | `up`   | Function coverage අඩු නොවිය යුතුය         |
| `coverage.branches`   | `up`   | Branch coverage අඩු නොවිය යුතුය           |

සැබෑ වැඩිදියුණු කිරීමකින් පසු මූලික රේඛාව යාවත්කාලීන කිරීමට:

### CodeQL ratchet: අපේක්ෂකයින් ඇතුළත් කිරීම සහ ගබඩා තොගය

පෙරනිමි සැකසුම වින්‍යාස කර ඇති අතර උසස් කාර්ය ප්‍රවාහය ප්‍රකාශනය නොකළ යුතුය: GitHub එම සංයෝජනය ප්‍රතික්ෂේප කරයි. සමාලෝචනය කරන ලද පරිපාලන සංක්‍රාන්තිය නැවත කියවන තෙක් එහි අනුවාදිත ප්‍රතිපත්තිය පොරොත්තුවෙන් පවතී. ප්‍රකාශනය කිරීමට පෙර, ක්‍රියාකරු පින් නිධියක්, head/base/tree, policy/patch/rollback හෑෂ් සහ නිරීක්ෂිත සැකසුම් තත්ත්වය; `node scripts/quality/codeql-producer.mjs verify-admin-readback` සපයන ලද අපේක්ෂිත සහ සත්‍ය JSON වාර්තා පරීක්ෂා කරයි. මෙය තාක්‍ෂණික ආරක්‍ෂකයකි, ක්‍රියාකරුගේ අනුමැතිය හෝ නැවුම් කියවීම් ලබා ගැනීම සඳහා ආදේශකයක් නොවේ. PR ටෝකනය කිසි විටෙකත් පරිපාලන ප්‍රවේශය ඉල්ලා නොසිටියි. Rollout සහ ඕනෑම ස්කෑනර් වෙනසක් සඳහා වෙනම නැවත කියවීම සහ සැබෑ PR, දෙබලක සහ ඒකාබද්ධ-කණ්ඩායම් අනුකූලතා සාක්ෂි අවශ්‍ය වේ.

Forks විසින් සත්කාරක ධාවකයන් භාවිතා කරයි, නොනැසී පවතින අක්තපත්‍ර නොමැතිව පිටවීම, නිෂ්පාදකයා තුළ ව්‍යාපෘති install/build නැත, සහ උරුම වූ ගබඩා රහස් නොමැත. GitHub එහි අඩු කළ දෙබලක ටෝකනය සමඟ pull_request සිදුවීම සඳහා SARIF උඩුගත කිරීමට සහය දක්වයි; පළමු වරට දායකත්ව ක්‍රියාත්මක කිරීමේ අනුමැතිය GitHub ප්‍රතිපත්තිය ලෙස පවතී. විශ්වාස නොකළ කේතය ක්‍රියාත්මක කිරීමට කිසිවිටක pull_request_target භාවිතා නොකරන්න. සංක්‍රමණය සම්පූර්ණ කිරීම සලකා බැලීමට පෙර පාලිත කැනරි තුළ සත්‍ය ටෝකන් අවසර, විශ්ලේෂණ_යතුර සහ සියලුම ප්‍රවර්ග පරිසරයන් තහවුරු කරන්න. [ගෑරුප්පු උඩුගත කිරීමේ නීති](https://docs.github.com/en/code-security/reference/code-scanning/troubleshoot-analysis-errors/resource-not-accessible), [ගැටෙන සැකසුම් මාතයන්](https://docs.github.com/en/code-security/reference/code-scanning/troubleshoot-analysis-errors/two-codeql-workflows).

**සේවයෙන් පහ කිරීම යනු ක්‍රියාකරුගේ ඇමතුමයි (Hard Rule #14)** — කිසිවිටෙකත් සේවයෙන් පහකිරීමේ ප්‍රකාශයේ තාක්ෂණික සාධාරණීකරණය සටහන් නොකර CodeQL අනතුරු ඇඟවීමක් ඉවත නොදමනු ඇත: ඉහළ ප්‍රොටෝකෝල අවශ්‍යතාවයක් සඳහා `won't fix`, පරීක්ෂණ සවිකිරීමක් සඳහා `used in tests`, සනීපාරක්ෂක CodeQL සඳහා `false positive` නොපෙනේ (පූර්‍වාදර්ශය: `docs/security/ERROR_SANITIZATION.md`).

   යටපත් නොකරන යල් පැන ගිය ඇතුළත් කිරීමක් ද දෝෂයකි (6A.3 යල් පැන ගිය-බලාත්මක කිරීම
   ක්රියාත්මක කළ පසු, අනාථ අවසර ලැයිස්තු ඇතුළත් කිරීමක් මත gate එක අසමත් වනු ඇත).

අවසර ලැයිස්තුවක් සහිත හරිත gate එකක් ගුණාත්මකභාවය පිළිබඳ ව්යාජ විශ්වාසයකි.

### ඔබගේ PR එක මත gate එකක් අසමත් වූ විට

1. **gate ප්රතිදානය සැලකිල්ලෙන් කියවන්න** — රීතිය උල්ලංඝනය කළ ගොනුව හෝ සංකේතය කුමක්දැයි එය ඔබට නිශ්චිතවම
   පවසයි.
2. **උල්ලංඝනය නිවැරදි කරන්න** — බොහෝ gates යනු කේතය නිවැරදි වූ විගස සමත් වන නියතික ගොනු පද්ධති පරීක්ෂාවන්ය.
3. **උල්ලංඝනය පෙර සිට පවතින්නක් නම්** (එනම්, ඔබ එය හඳුන්වා නොදුන් නමුත් gate එක දැන්
   එය ආවරණය කරයි නම්): සාධාරණීකරණ අදහස් දැක්වීමක් සහ ලුහුබැඳීමේ issue එකක් සමඟ අවසර ලැයිස්තු ඇතුළත් කිරීමක් එක් කරන්න.
4. **gate එක ratchet එකක් නම්** (coverage, ESLint warnings, duplication, complexity):
   ඔබගේ වෙනස නිසා මිනුම නරක අතට හැරී ඇත. යටින් පවතින ගැටලුව නිවැරදි කරන්න, නැතහොත් (කලාතුරකින්) වෙනස හිතාමතා කළ එකක් සහ මිනුමේ
   පිරිහීම පිළිගත හැකි නම් `npm run quality:ratchet -- --update` ක්රියාත්මක කරන්න — නමුත් PR විස්තරය තුළ එයට හේතුව ලේඛනගත කරන්න.
5. **උපදේශාත්මක gates** (`continue-on-error: true`) තොරතුරු සැපයීම සඳහා පමණි — ඒවා merge කිරීම
   අවහිර නොකරන නමුත් CI සාරාංශයේ දිස් වේ. එසේ වුවත් ඒවා නිවැරදි කරන්න.

## නව Gate එකක් එක් කිරීම

1. `scripts/check/check-<name>.mjs` (හෝ `.ts`) සාදන්න. ප්රතිපත්ති gate 0/1 සමඟ පිටවෙයි.
   Ratchet-ආකාරයේ gate, `collect-metrics.mjs` හරහා `quality-metrics.json` වෙත metric එකක් නිකුත් කරයි.
2. `package.json` වෙත `"check:<name>": "node scripts/check/check-<name>.mjs"` එක් කර,
   අන්වර්ථ නාමය සහ එහි නිශ්චිත විධානය `config/quality/gate-manifest.json` තුළ සමමුහුර්ත කරන්න.
   පවතින වලංගුකරණ අන්වර්ථ නාමයක් වෙනස් කිරීමේදී හෝ ඉවත් කිරීමේදීද එම සමමුහුර්තකරණයම යොදන්න.
   `npm run check:gate-manifest` ධාවනය කරන්න; pre-commit hook එක සහ CI වෙනස්කම් වර්ගීකරණය
   මෙම ගිවිසුම බලාත්මක කරයි.
3. සුදුසු job එක යටතේ `.github/workflows/ci.yml` තුළ එය සම්බන්ධ කරන්න
   (ප්රතිපත්තිය → `lint` හෝ `docs-sync-strict`; ratchet → `quality-gate`).
4. එයට අවසර ලැයිස්තුවක් තිබේ නම්, යල්පැනගිය ඇතුළත් කිරීම් ස්වයංක්රීයව හඳුනාගැනීමට
   `scripts/check/lib/allowlist.mjs` වෙතින් `reportStaleEntries()` යොදන්න.
5. gate එකේ හඳුනාගැනීමේ තර්කය ආවරණය කරමින් `tests/unit/build/` තුළ පරීක්ෂණයක් ලියන්න.
6. මෙම ලේඛනය යාවත්කාලීන කරන්න (අදාළ job වගුවට පේළියක් එක් කරන්න).

### ඒකාබද්ධ කිරීම / අනුපිටපත් ඉවත් කිරීම (යාන්ත්රික, අඩු අවදානම)

සෑම අපේක්ෂකයෙකුම 2026-06-17 දින සජීවී ගේට්ටු තත්ත්වයට එරෙහිව වලංගු කරන ලදී (විශ්වාස කරන්න, නමුත් සත්යාපනය කරන්න);
“පැහැදිලි” ලෙස පෙනුණු ඒකාබද්ධ කිරීම් කිහිපයක් ණය සඟවා ඇති බව අනාවරණය වූ අතර ඒවා **පිරිසිදු සෘජු ආදේශන නොවේ**.

- **`check:docs-sync` දෙවරක් ධාවනය වේ** — `lint` කාර්යය තුළ ස්වාධීනව සහ `check:docs-all` (`docs-sync-strict`) තුළ නැවතත්, එමෙන්ම husky pre-commit hook එක තුළද. ✅ **සම්පූර්ණයි** — ස්වාධීන `lint` කැඳවීම ඉවත් කරන ලදී.
- **CVE ස්කෑන් කිරීම** — ❌ **පිරිසිදු ඒකාබද්ධ කිරීමක් නොවේ.** `audit:deps` මඟින් lockfile පහම හරහා බරපතළ උපදේශන සහ අසම්පූර්ණ විගණන අවහිර කරන අතර, වත්මන් ප්රතිපත්තිය යටතේ ඉහළ මට්ටමේ උපදේශන අනතුරු ඇඟවීම් ලෙස වාර්තා කරයි; `check:vuln-ratchet` (osv) අසමත් වන්නේ පරීක්ෂා කර ඇතුළත් කළ baseline එකට සාපේක්ෂව _පසුබෑමක්_ ඇති විට පමණක් වන අතර, අවශ්ය විට මිනුම් නොමැති නම් ඒවා ප්රතික්ෂේප කරයි. අර්ථකථන වෙනස්ය — `audit:deps` ඉවත් කිරීමෙන් නිරපේක්ෂ බරපතළ ගේට්ටුව සහ ස්වාධීන පැකේජ විගණන ලදුපත් අහිමි වනු ඇත. දෙකම තබා ගන්න.
- **චක්ර හඳුනාගැනීම** — ✅ **සම්පූර්ණයි** (#15159 G-01/G-02). මෙහි පැරණි පෙළ `check:cycles` “හරිත, තෝරාගත්” ගේට්ටුව ලෙස හැඳින්වූ අතර `check:circular-deps` (dpdm) චක්ර 91ක් වාර්තා කළ නිසා එය අවහිරකාරීව තබා ගැනීම සාධාරණීකරණය කළේය. එම හරිත තත්ත්වය **ව්යාජ හරිත තත්ත්වයක්** විය: `check:cycles` විසින් උපබහලුම් 5ක් (ගොනු 450ක්) ස්කෑන් කළ අතර, ස්ථිතික `import|export … from` පමණක් ගැළපූ අතර සෑම `@/` සහ `@omniroute/open-sse/` විශේෂකයක්ම ඉවත් කළ බැවින්, repo එකේ ප්රමුඛ වූ dynamic-import + alias චක්ර දැකිය නොහැකි විය. නිවැරදි කරන ලදී: ගේට්ටුව දැන් `src` + `open-sse` (ගොනු 5023ක්) හරහා ගමන් කර, TypeScript AST වෙතින් විශේෂක රැස් කරයි (එබැවින් `import("…")` ගණන් ගන්නා අතර type-position `typeof import("…")` ගණන් නොගනී), සහ tsconfig `paths` විසඳයි. එය 0ක් නොව චක්ර **14ක්** සොයා ගනී. ගේට්ටු PR එකක් තුළ පෙර සිට පවතින චක්ර 14ක් නිවැරදි කළ නොහැකි බැවින්, `check:cycles` දැන් **රැචට්** එකකි (`--ratchet`, `quality-baseline.json` තුළ සීමාව `metrics.cycles.value = 14`, `direction: down`) — එය ඕනෑම _පසුබෑමක්_ අවහිර කරන අතර ගණන අඩු විය හැක්කේ පමණි. CI විසින් `npm run check:cycles:ratchet` ධාවනය කරයි. ක්රමානුකූල අඩු කිරීම **A-01** සමඟ සිදු වේ. පුළුල් දෙවන මතය ලෙස `check:circular-deps` (dpdm) උපදේශනාත්මකව පවතී.
- **සංකීර්ණතාව** — ✅ **සම්පූර්ණයි** (`check:complexity-ratchets` / `eslint.complexity-ratchets.config.mjs`): එක් ESLint ගමනක්, ruleId අනුව ගණන් කරන බැවින් cyclomatic+max-lines සහ cognitive baselines ස්වාධීනව පවතී; තනි `check:complexity` / `check:cognitive-complexity` දේශීය `--update` සඳහා පවතී.
- **`/api` ප්රති-භ්රාන්තිකරණය** — ✅ **සම්පූර්ණයි** (`check:api-docs-refs` + `scripts/check/lib/apiRoutes.mjs`): `src/app/api` හි එක් FS ඉන්වෙන්ටරියක්, openapi-routes + docs-symbols තවදුරටත් ස්වාධීනව වාර්තා කරයි; තනි ඒවා දේශීය ධාවන සඳහා පවතී.
- **`check:node-runtime` කාර්ය 11ක ධාවනය වේ** — ⚠️ **අඩු ROI.** සෑම එකක්ම වෙනම runner එකක් වන අතර පරීක්ෂාව තත්පර 1කට අඩුය; ලාභදායක නොවන වෙනස්කම් සඳහා වැය වන උත්සාහයට සාපේක්ෂව සමස්ත ඉතිරිය තත්පර ~10කි, තවද සෑම කාර්යයකම ඇති ලාභදායී ආරක්ෂකයක් අහිමි වේ. එය එතරම් වටින්නේ නැත.
- **CI lint මත `typecheck:noimplicit:core`** — ✅ **lint කාර්යයෙන් ඉවත් කරන ලදී** (උපදේශනාත්මක `continue-on-error` ලෙස තිබුණි); අවහිරකාරී type මතුපිට වන්නේ `typecheck:core` + `check:type-coverage` ය. දේශීය script එක තබා ඇත.

### මාරු කිරීම / තීරණය කිරීම (ක්රියාකරු ප්රතිපත්තිය)

- `check:openapi-security-tiers` (උපදේශනාත්මක) — ❌ **පිරිසිදුව මාරු කළ නොහැක.** එය 0 සමඟ අවසන් වන නමුත් `LOCAL_ONLY_API_PREFIXES` යටතේ ඇති `traffic-inspector` routes කිහිපයක `x-loopback-only: true` annotation එක නොමැති බවට අනතුරු අඟවයි. එය බලාත්මක කිරීමට පළමුව එම annotations `openapi.yaml` වෙත එක් කළ යුතුය.
- `typecheck:noimplicit:core` (උපදේශනාත්මක) — අවහිරකාරී `check:type-coverage` රැචට් එකෙන් බොහෝ දුරට ආවරණය වේ. එය රැචට් එකකට මාරු කරන්න හෝ අතිරික්ත දෙවන `tsc` ගමන ඉවත් කරන්න.
- `test:vitest:ui` (දැන් **අවහිරකාරී**) — පෙර සිට පවතින අසමත්වීම් `vitest.config.ts` තුළ `// #8618` හඹායෑමේ අදහස් සමඟ පැහැදිලිව බැහැර කර ඇත; නව අසමත්වීම් කාර්යය අසමත් කරයි.
- `check:secrets` (gitleaks, අවහිරකාරී රැචට්) — වත්මන් සීමාව `quality-baseline.json` තුළ ඇති `metrics.secretFindings` ය. ඕනෑම ව්යතිරේකයකට සාධාරණීකරණය කළ `.gitleaks.toml` ඇතුළත් කිරීමක් අවශ්ය වේ; මිනුම නොලැබීම INCOMPLETE ලෙස සැලකේ. මෙම ස්කෑන් කිරීම GitHub ස්වදේශීය රහස් ස්කෑන් කිරීම සහ `check:public-creds` සඳහා අනුපූරක වේ.
- `check:pr-evidence` (අවහිරකාරී, PR-body ගද්යය grep කරයි) — ව්යාජ ධනාත්මක ප්රතිඵල ඇතිවීමේ ඉහළ අවදානමක් ඇත; එය ඉවත් කළහොත් දැඩි රීතිය #18 බලාත්මක කිරීම දුර්වල වන බැවින්, මෙය සැබෑ ප්රතිපත්තිමය තීරණයකි.
