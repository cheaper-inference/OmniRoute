### පද්ධති තැටි ප්රකාරය

පද්ධති තැටිය තුළ OmniRoute ආරම්භ කරන්න:

```bash
omniroute serve --tray
```

සේවාදායකය සහ පද්ධති තැටිය සූදානම් වූ පසු විධානය අවසන් වේ.

ටර්මිනලය නොමැතිව සේවාදායකය දිගටම ක්රියාත්මක වේ.

පද්ධති තැටි ප්රකාරය macOS, Windows සහ චිත්රක Linux සැසි සඳහා සහාය දක්වයි. පද්ධති තැටි ප්රකාරය උපකරණ පුවරුව ස්වයංක්රීයව විවෘත නොකරයි.

මෙම ක්රියා සඳහා පද්ධති තැටි මෙනුව භාවිත කරන්න:

- උපකරණ පුවරුව විවෘත කරන්න.
- `/dashboard/logs` විවෘත කරන්න.
- ස්වයංක්රීය ආරම්භය වෙනස් කරන්න.
- OmniRoute නවත්වන්න.

මෙම විකල්ප සමඟ `--tray` ඒකාබද්ධ නොකරන්න:

- `--daemon`
- `--log`
- `--no-recovery`

මෙම ප්රකාර සඳහා වෙනස් ක්රියාවලි හිමිකාරිත්වයක් අවශ්ය වේ.

යන්ත්රයට ඊළඟ වර පිවිසීමේදී ආරම්භ වීම සක්රීය කරන්න:

```bash
omniroute autostart enable
```

ස්වයංක්රීය ආරම්භය macOS, Windows සහ චිත්රක Linux සැසිවලදී පද්ධති තැටි ප්රකාරය භාවිත කරයි. තිර රහිත Linux විසින් පවතින systemd පරිශීලක සේවාව භාවිත කරයි.

පිවිසීමේදී ආරම්භ වීම අක්රීය කරන්න:

```bash
omniroute autostart disable
```

### PM2 යෙදවීම (අඩු මතකය)

සීමිත RAM සහිත සේවාදායක සඳහා, මතක සීමා විකල්පය භාවිත කරන්න:

```bash
# 512MB සීමාවක් සමඟ (පෙරනිමි)
pm2 start npm --name omniroute -- start

# නැතහොත් අභිරුචි මතක සීමාවක් සමඟ
OMNIROUTE_MEMORY_MB=512 pm2 start npm --name omniroute -- start

# නැතහොත් ecosystem.config.js භාවිතයෙන්
pm2 start ecosystem.config.js
```

`ecosystem.config.js` සාදන්න:

```javascript
module.exports = {
  apps: [
    {
      name: "omniroute",
      script: "npm",
      args: "start",
      env: {
        NODE_ENV: "production",
        OMNIROUTE_MEMORY_MB: "512",
        JWT_SECRET: "your-secret",
        INITIAL_PASSWORD: "your-password",
      },
      node_args: "--max-old-space-size=512",
      max_memory_restart: "300M",
    },
  ],
};
```

   එය විවෘත කර, ඉල්ලීම් භාවිතා කරන යතුර ගබඩා කිරීමට **Add Connection** භාවිතා කරන්න.

නෝඩ් එකට `openai-compatible-<apiType>-<uuid>` ආකාරයේ අභ්යන්තර id එකක් ලැබේ; ඔබට එය
කවදාවත් ටයිප් කිරීමට අවශ්ය නැත, උපසර්ගය මහජන නමයි.

#### වෙන් කළ උපසර්ග

උපසර්ගයක් බිල්ට්-ඉන් සැපයුම්කරුවෙකුගේ id හෝ alias එකක් විය නොහැක (උදාහරණයක් ලෙස `openai`, `cf`), හෝ
විශ්රාමික සැපයුම්කරුවෙකුගේ id එකක් විය නොහැක. ආකෘති විසඳුම්කරු අභිරුචි නෝඩ් වලට පෙර
බිල්ට්-ඉන් id සහ alias පරීක්ෂා කරන බැවින්, එම උපසර්ග වලින් එකක් භාවිතා කරන නෝඩ් එකක් කිසිවිටෙක
ගමනාගමනය නොලැබේ: `<prefix>/model` ඒ වෙනුවට බිල්ට්-ඉන් සැපයුම්කරු වෙත යයි, හෝ එම සැපයුම්කරු
විශ්රාමික නම් fail closed වේ. එවැනි උපසර්ගයක් සහිත නෝඩ් එකක් නිර්මාණය කිරීම හෝ සංස්කරණය කිරීම මෙලෙස ප්රතික්ෂේප වේ:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

වෙනස් උපසර්ගයක් තෝරන්න (`mygw`, `acme-proxy`). අභිරුචි නෝඩ් එකකට යන ඉල්ලීම් බිල්ට්-ඉන්
සැපයුම්කරුවෙකු හෝ එහි අක්තපත්ර නම් කරන දෝෂයකින් අසාර්ථක වුවහොත්, නෝඩ් එකේ උපසර්ගය වෙන් කළ
එකක්දැයි බලන්න: මෙම නීතිය පැවතිමට පෙර සුරකින ලද නෝඩ් තවමත් ගබඩා කර ඇත, නමුත් ඒවායේ
උපසර්ග බිල්ට්-ඉන් සැපයුම්කරු වෙත යොමු වේ. නෝඩ් එක සංස්කරණය කර එයට නව උපසර්ගයක් දෙන්න.

#### සම්බන්ධතාවය-අනුව ගේට්වේ විකල්ප

මෙම යතුරු සම්බන්ධතාවයක `providerSpecificData` තුළට යයි (උදාහරණයක් ලෙස
`PUT /api/providers/{id}` හරහා):

- `toolNameMaxLength` (පූර්ණ සංඛ්යාව, 1–1024) — දිගු මෙවලම් නම් ප්රතික්ෂේප කරන ගේට්වේ
  සහිත OpenAI chat-ආකෘති අනුකූල සම්බන්ධතා සඳහා. දිගු නම් කෙටි alias ලෙස යවන අතර
  ප්රතිචාරයේදී නැවත ප්රතිස්ථාපනය කෙරේ.
- `quotaEndpoint` — ගේට්වේ එකේ quota/credits endpoint එක; උපකරණ පුවරුවේ quota තීරුව සහ
  quota-දැනුවත් රවුටිං සඳහා කියවයි. OpenAI- සහ Anthropic-අනුකූල සම්බන්ධතා දෙකෙහිම ක්රියා කරයි;
  සම්පූර්ණ හැඩය `open-sse/services/usage/openaiCompatible.ts` හි ලේඛනගත කර ඇත.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### OmniRoute Peers දම්වැල්ගත කිරීම

තවත් OmniRoute ගේට්වේ එකක් **Custom OpenAI-compatible** සැපයුම්කරුවෙකු ලෙස එක් කළ හැක. එම
peer එකේ `/v1` base URL එක සහ එම peer විසින් නිකුත් කළ කැපවූ, අවම-වරප්රසාද API යතුරක්
භාවිතා කරන්න.

අන්යෝන්ය හෝ බහු-hop දම්වැල් සඳහා, සෑම ගේට්වේ එකකම opt-in ලූප් ආරක්ෂකය සක්රීය කරන්න:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

පැහැදිලිවම allowlist කළ peer URL එකකට යවන ඉල්ලීම් පමණක්
`X-OmniRoute-Peer-Trace` ශීර්ෂකය ලබා ගනී. ගේට්වේ එකක් නැවත නැවත එන instance ID එකක් හෝ
හිඟයැයූ hop අයවැයක් HTTP `508 Loop Detected` සමඟ ප්රතික්ෂේප කරයි; සාමාන්ය upstream
සැපයුම්කරුවන්ට කිසිදු peer metadata නොලැබේ.

Peer දම්වැල්ගත කිරීම දත්තසමුච්ඡය අනුපිටපත් කිරීම හෝ host failover නොවේ. සෑම ගේට්වේ එකක්ම
ස්වාධීන SQLite තත්ත්වයන්, caches, rate counters, සහ sessions තබා ගනී. active/passive හෝ
active/active ලබාගත-හැකි බව සඳහා health-checked reverse proxy එකක් හෝ client failover එකක්
භාවිතා කරන්න, සහ එකම SQLite දත්තසමුච්ඡයක් ක්රියාත්මක OmniRoute instances කිහිපයකට කවදාවත්
mount නොකරන්න.

### සැපයුම්කරු-විශේෂිත මාර්ග

ආකෘති වලංගුකරණය සමඟ ඉල්ලීම් නිශ්චිත සැපයුම්කරුවෙකු වෙත සෘජුවම යොමු කරන්න:

POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations

සැපයුම්කරු උපසර්ගය නොමැති විට ස්වයංක්රීයව එක් කෙරේ. නොගැලපෙන ආකෘති `400` ආපසු දෙයි.

### ජාල Proxy වින්යාසය

```bash
# ගෝලීය proxy සකසන්න
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# සැපයුම්කරු-අනුව proxy
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# proxy පරීක්ෂා කරන්න
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**ප්රමුඛතාවය:** යතුර-විශේෂිත → Combo-විශේෂිත → සැපයුම්කරු-විශේෂිත → ගෝලීය → පරිසරය.

### වලාකුළු සමමුහුර්තකරණය

- උපකරණ හරහා සැපයුම්කරුවන්, combos සහ සැකසුම් සමමුහුර්ත කරන්න
- timeout + fail-fast සමඟ ස්වයංක්රීය පසුබිම් සමමුහුර්තකරණය
- නිෂ්පාදන පරිසරයේදී සේවාදායක-පැත්තේ `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` භාවිතයට ප්රමුඛත්වය දෙන්න

### Cloudflare Quick Tunnel

- Docker සහ වෙනත් self-hosted යෙදවුම් සඳහා **Dashboard → Endpoints** හි ලබාගත හැක
- ඔබේ වත්මන් OpenAI-අනුකූල `/v1` endpoint එකට යොමු වන තාවකාලික `https://*.trycloudflare.com` URL එකක් සාදයි
- පළමු වරට සක්රීය කිරීමේදී අවශ්ය වූ විට පමණක් `cloudflared` ස්ථාපනය කරයි; පසුව නැවත ආරම්භයන්හිදී එම කළමනාකරණය කළ binary එකම නැවත භාවිත කරයි
- OmniRoute හෝ බහාලුම් (container) නැවත ආරම්භයකින් පසු Quick Tunnels ස්වයංක්රීයව ප්රතිස්ථාපනය නොවේ; අවශ්ය විට dashboard එකෙන් නැවත සක්රීය කරන්න
- Tunnel URL තාවකාලික වන අතර ඔබ උමග නැවැත්වීම/ආරම්භ කිරීම සිදු කරන සෑම විටම වෙනස් වේ
- සීමිත බහාලුම්වල ඇති වන කරදරකාරී QUIC UDP buffer අනතුරු ඇඟවීම් වළක්වා ගැනීම සඳහා කළමනාකරණය කළ Quick Tunnels පෙරනිමි ලෙස HTTP/2 transport භාවිත කරයි
- කළමනාකරණය කළ transport තේරීම අභිබවා යාමට අවශ්ය නම් `CLOUDFLARED_PROTOCOL=quic` හෝ `auto` ලෙස සකසන්න
- කළමනාකරණය කළ බාගැනීම වෙනුවට කලින් ස්ථාපනය කළ `cloudflared` binary එකක් භාවිත කිරීමට කැමති නම් `CLOUDFLARED_BIN` සකසන්න
- Cloudflare Quick Tunnel, Tailscale Funnel සහ ngrok Tunnel පැනල් **Settings → Appearance** හි පෙන්වීමට හෝ සැඟවීමට හැක. පැනලයක් සැඟවීමෙන් ධාවනය වෙමින් පවතින උමගක් නවතින්නේ නැත.

### LLM ගේට්වේ බුද්ධි (අදියර 9)

- **Semantic Cache** — non-streaming, temperature=0 ප්රතිචාර ස්වයංක්රීයව කැෂ් කරයි (`X-OmniRoute-No-Cache: true` සමඟ මඟහරින්න)
- **Request Idempotency** — `Idempotency-Key` හෝ `X-Request-Id` ශීර්ෂකය මඟින් තත්පර 5ක් ඇතුළත ද්විත්ව ඉල්ලීම් ඉවත් කරයි
- **Progress Tracking** — `X-OmniRoute-Progress: true` ශීර්ෂකය මඟින් සක්රීය කළ හැකි (opt-in) SSE `event: progress` සිදුවීම්

**Dashboard හි දැකිය හැකි උපාය මාර්ග (ගිණුම්-මට්ටමේ යොමුකිරීම):**

**උසස් combo සහ auto උපාය මාර්ග** (combo එකකට හෝ `auto/*` උපසර්ග මඟින් වින්යාසගත කළ හැක — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) බලන්න):

- `priority` — දැඩි පිළිවෙළ, කිසිවිටෙක round-robin නොකරයි
- `weighted` — ආදර්ශයකට-බර (per-model weights) අනුව සමානුපාතික ගමනාගමන බෙදීම
- `fill-first` — සීමා ළඟා වන තෙක් පළමු ආදර්ශය උපරිමයෙන් භාවිත කරයි
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` සහ `cost-optimized`
- `auto` — සියලු අපේක්ෂකයන් හරහා ලකුණු-මත පදනම් වූ (score-driven)
- `lkgp` (Last Known Good Provider) — අවසන් වරට සාර්ථක වූ සැපයුම්කරුට බැඳ සිට, පසුව නීති වෙත පසුබසියි
- `context-optimized` — විශාලතම නිදහස් context window එක ඇති ආදර්ශය තෝරයි
- `context-relay` — පසුව එන වාර (follow-up turns) සඳහා දිගු-context ආදර්ශ දම්වැල් ලෙස සම්බන්ධ කරයි

#### බාහිර Sticky Session ශීර්ෂකය

බාහිර සැසි affinity සඳහා (උදාහරණයක් ලෙස, reverse proxies පිටුපස සිටින Claude Code/Codex agents), යවන්න:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id` ද පිළිගන්න අතර, සක්රීය සැසි යතුර `X-OmniRoute-Session-Id` හි ආපසු ලබා දෙයි.

ඔබ Nginx භාවිත කර underscore ආකෘතියේ ශීර්ෂක යවන්නේ නම්, සක්රීය කරන්න:

```nginx
underscores_in_headers on;
```

#### Wildcard ආදර්ශ අන්වර්ථ

ආදර්ශ නම් නැවත සිතියම් කිරීමට wildcard රටා සාදන්න:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

Wildcards `*` (ඕනෑම අකුරු මාලාවක්) සහ `?` (තනි අකුරක්) සඳහා සහාය දෙයි.

4. **සිසිලනය සඳහා රැඳී සිටින්න** — සෑම අපේක්ෂක සම්බන්ධතාවක්ම දැනටමත් සිසිලනය වෙමින් තිබේ නම්, OmniRoute විට මුල්ම සිසිලනය සඳහා රැඳී සිට එම සේවාලාභී ඉල්ලීමම ස්වයංක්රීයව නැවත උත්සාහ කළ හැක.

5. **අනුපාත-සීමා ස්වයං-හඳුනාගැනීම** — අප්ස්ට්රීම් සපයන්නන් පැහැදිලි රැඳී-සිටීමේ කවුළු ලබා දුන් විට, සැකසීම සබල කර ඇති විට එම ඉඟි දේශීය සම්බන්ධතා සිසිලනය අභිබවා යයි.

**විශේෂ ඉඟිය:** ඇණහිටීමකින් පසු සජීවී සපයන්නා කඩනයන් පරීක්ෂා කර යළි පිහිටුවීමට **සෞඛ්යය** පිටුව භාවිත කරන්න. ප්රත්යාස්ථතා පිටුව වින්යාසය පමණක් වෙනස් කරයි.

### දත්ත සමුදාය නිර්යාත / ආයාත

**උපකරණ පුවරුව → සැකසීම් → පද්ධතිය සහ ගබඩාකිරීම** හි දත්ත සමුදාය උපස්ථ කළමනාකරණය කරන්න.

| ක්රියාව                            | විස්තරය                                                                                                                                                              |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **දත්ත සමුදාය නිර්යාත කරන්න**      | වත්මන් SQLite දත්ත සමුදාය `.sqlite` ගොනුවක් ලෙස බාගත කරයි                                                                                                            |
| **සියල්ල නිර්යාත කරන්න (.tar.gz)** | දත්ත සමුදාය, සැකසීම්, කොම්බෝ, සපයන්නා සම්බන්ධතා (අක්තපත්ර නොමැතිව), සහ API යතුරු පාර-දත්ත ඇතුළත් සම්පූර්ණ උපස්ථ ලේඛනාගාරයක් බාගත කරයි                                |
| **දත්ත සමුදාය ආයාත කරන්න**         | වත්මන් දත්ත සමුදාය ප්රතිස්ථාපනය කිරීමට `.sqlite` ගොනුවක් උඩුගත කරන්න. `DISABLE_SQLITE_AUTO_BACKUP=true` ලෙස සකසා නොමැති නම් ආයාත-පෙර උපස්ථයක් ස්වයංක්රීයව සාදනු ලැබේ |

```bash
# API: දත්ත සමුදාය නිර්යාත කරන්න
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: සියල්ල නිර්යාත කරන්න (සම්පූර්ණ ලේඛනාගාරය)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: දත්ත සමුදාය ආයාත කරන්න
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ආයාත වලංගුකරණය:** ආයාත කළ ගොනුව අඛණ්ඩතාව (SQLite pragma පරීක්ෂාව), අවශ්ය වගු (`provider_connections`, `provider_nodes`, `combos`, `api_keys`), සහ ප්රමාණය (උපරිම 100MB) සඳහා වලංගු කෙරේ.

**භාවිත අවස්ථා:**

- යන්ත්ර අතර OmniRoute සංක්රමණය කිරීම
- ආපදා යථා තත්ත්වයට පත්කිරීම සඳහා බාහිර උපස්ථ සාදන්න
- කණ්ඩායම් සාමාජිකයන් අතර වින්යාසයන් බෙදා ගන්න (සියල්ල නිර්යාත කරන්න → ලේඛනාගාරය බෙදා ගන්න)

### Combo සමතුලිත උපාය

**උපකරණ පුවරුව → Combos → සෑදීම/සංස්කරණය → උපායය** හි combo අනුව සමතුලිතය වින්යාස කරන්න.

| උපායය              | විස්තරය                                                                  |
| ------------------ | ------------------------------------------------------------------------ |
| **Round-Robin**    | Models හරහා අනුක්රමිකව භ්රමණය වේ                                         |
| **Priority**       | සෑම විටම පළමු model එක උත්සාහ කරයි; දෝෂයකදී පමණක් fallback වේ            |
| **Random**         | සෑම request එක සඳහාම combo එකෙන් අහඹු model එකක් තෝරයි                   |
| **Weighted**       | Model අනුව පැවරූ බර මත ප්රමාණානුකූලව යොමු කරයි                           |
| **Least-Used**     | මෑතකදී අඩුම requests ඇති model එකට යොමු කරයි (combo metrics භාවිතා කරයි) |
| **Cost-Optimized** | ලබාගත හැකි ලාභදායීම model එකට යොමු කරයි (මිල ගණන් වගුව භාවිතා කරයි)      |

ගෝලීය combo පෙරනිමි **උපකරණ පුවරුව → සැකසීම් → මාර්ගගත කිරීම → Combo පෙරනිමි** හි සැකසිය හැක.
Combo target timeouts පෙරනිමියෙන් වත්මන් request timeout එක උරුම කර ගනී. කෙටි per-target සීමාවක්
වේගවත් fallback එකක් අවුලුවාලිය යුතු විට පමණක් combo පෙරනිමි හෝ තනි combo එකක් මත **Target timeout
(seconds)** භාවිතා කරන්න.

Zero-latency combo ප්රශස්තිකරණයන් opt-in වේ. මෙම latency විශේෂාංග fallback targets සමඟ
තරඟ කිරීම, TTFT ඉතිහාසය මත targets මඟහැරීම, හෝ fallback requests සම්පීඩනය කිරීම
වැළැක්වීමට **Zero-latency optimizations** අක්රීය කර තබන්න; එය සක්රීය කිරීමෙන් වින්යාස කළ hedging,
predictive TTFT skips සහ proactive fallback compression වලට routing/request නිරවද්යතාවය අඩු tail
latency සඳහා හුවමාරු කිරීමට ඉඩ සැලසේ.

උඩුගංගා සැපයුම්කරුවන්ට දැඩි `max_tokens` / `maxOutputTokens` සීමාවන් අවශ්ය වන විට **Reasoning token buffer** අක්රීය කරන්න. සක්රීය කළ විට, දන්නා නිමැතුම් සීමාවක් (output cap) ඇති ආකෘති සඳහා පමණක් combo routing විසින් reasoning-model headroom එක් කරන අතර, ආරක්ෂිත buffered අගය එම සීමාව ඉක්මවා යා හැකි විට සේවාදායක token සීමාව වෙනස් නොකර තබයි. සේවාදායක සීමාව දැනටමත් දන්නා සීමාවකට වඩා ඉහළ නම්, උඩුගංගා ඉල්ලීම යැවීමට පෙර OmniRoute එය එම සීමාව දක්වා පහළට සීමා කරයි.

## 🛠️ ක්රමලේඛමය කළමනාකරණය

**`manage` විෂය පථය සහිත Bearer යතුරක්** භාවිතයෙන් ඔබට සෑම OmniRoute සම්පතක්ම (providers, combos, keys, settings) HTTP හරහා කළමනාකරණය කළ හැක.

**උපකරණ පුවරුව → API යතුරු → නව යතුර → විෂය පථය: manage** තුළ යතුර ජනනය කර, ඉන්පසු:

```bash
# Providers ලැයිස්තුගත කරන්න
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Provider සම්බන්ධතාවක් එක් කරන්න
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Combo එකක් සාදන්න
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API යතුරු ලැයිස්තුගත කරන්න/සාදන්න
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

පිහිටුවීම, රෝග නිර්ණය සහ ධාවනකාල පාලනය සඳහා OmniRoute අභ්යන්තර CLI එකක් (`omniroute …`) සමඟ පැමිණේ. මෙය තෙවන පාර්ශ්වීය CLI (Claude Code, Cursor, Codex, Cline, …) වලට OmniRoute සමඟ සන්නිවේදනය කළ හැකි වන පරිදි ඒවා වින්යාස කරන, උපකරණ පුවරුවේ ඇති **"CLI මෙවලම්" පිටුවෙන් වෙනස් වූවකි**.

```bash
omniroute setup                    # අන්තර්ක්රියාකාරී විශාරදය (මුරපදය, සපයන්නන්, සංයෝජන)
omniroute setup --non-interactive  # CI සඳහා හිතකරයි
omniroute doctor                   # සෞඛ්ය රෝග නිර්ණය (දත්ත නාමාවලිය, DB, සපයන්නන්, පෝට්)
omniroute providers available      # සහාය දක්වන සපයන්නන් ලැයිස්තුගත කරන්න
omniroute providers list           # වින්යාස කළ සම්බන්ධතා ලැයිස්තුගත කරන්න
omniroute providers test <id>      # සපයන්නෙකුගේ සම්බන්ධතාව සජීවීව පරීක්ෂා කරන්න
omniroute combos list              # සංයෝජන ලැයිස්තුගත කරන්න
omniroute combos switch <name>     # පෙරනිමි සංයෝජනය සකසන්න
omniroute models                   # ලබා ගත හැකි ආකෘති ලැයිස්තුගත කරන්න (--json, --search)
omniroute keys add | list | remove # ටර්මිනලයෙන් API යතුරු කළමනාකරණය කරන්න
omniroute backup                   # වින්යාසය + DB හි ස්නැප්ෂොට් එකක් ගන්න
omniroute restore [<timestamp>]    # ස්නැප්ෂොට් එකකින් ප්රතිසාධනය කරන්න
omniroute health                   # සවිස්තරාත්මක සෞඛ්ය තොරතුරු (බ්රේකර්, හැඹිලිය, මතකය)
omniroute quota                    # සපයන්නන්ගේ කෝටා භාවිතය
omniroute mcp status               # MCP සේවාදායකයේ තත්ත්වය
omniroute a2a status               # A2A සේවාදායකයේ තත්ත්වය
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok ටනල්
omniroute reset-password           # පරිපාලක මුරපදය යළි සකසන්න
omniroute --mcp                    # stdio හරහා MCP සේවාදායකය ආරම්භ කරන්න
omniroute --port 3000              # අභිරුචි පෝට් එකක සේවාදායකය ආරම්භ කරන්න
```

ඉඟිය: අසෞඛ්ය සපයන්නන්ගේ සම්බන්ධතා පිළිබඳ අනතුරු ඇඟවීම් ලබා ගැනීමට `omniroute doctor --json` ඔබගේ අධීක්ෂණ මෙවලම සමඟ යුගල කරන්න.

## 🖥️ ඩෙස්ක්ටොප් යෙදුම (Electron)

OmniRoute, Windows, macOS සහ Linux සඳහා ස්වදේශීය ඩෙස්ක්ටොප් යෙදුමක් ලෙස ලබා ගත හැකිය.

### ස්ථාපනය

```bash
# electron නාමාවලියෙන්:
cd electron
npm install

# සංවර්ධන ප්රකාරය (ධාවනය වන Next.js සංවර්ධන සේවාදායකයට සම්බන්ධ වේ):
npm run dev

# නිෂ්පාදන ප්රකාරය (ස්වාධීන ගොඩනැගීම භාවිත කරයි):
npm start
```

### ස්ථාපක ගොඩනැගීම

```bash
cd electron
npm run build          # වත්මන් වේදිකාව
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg universal)
npm run build:linux    # Linux (.AppImage)
```

ප්රතිදානය → `electron/dist-electron/`
