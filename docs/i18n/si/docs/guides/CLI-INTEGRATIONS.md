බෙදාගත් ක්‍රියාත්මක කළ හැකි මැනිෆෙස්ටය, සීමා කළ ළමා පරිසරයන් සහ නොනැසී පවතින Gemini පිහිටුවීම සඳහා, [CLI දියත් කිරීමේ ගිවිසුම්](./CLI-LAUNCH-CONTRACTS.md) බලන්න.

OmniRoute එහි පසුබිම් — ලෙස OmniRoute භාවිතා කිරීමට CLI (Codex, Claude කේතය, OpenCode, Cline, …) කේතීකරණ වින්‍යාස කරන `setup-*` විධාන පවුලක් යවයි, එබැවින් මෙවලම කතා කරයි.** එකක්** ස්වයංක්‍රීය පසුබෑමක් සමඟ නිවැරදි සැපයුම්කරු වෙත අවසන් ලක්ෂ්‍යය සහ OmniRoute මාර්ග. සැකසුම් විධාන ඔබගේ සක්‍රීය දේශීය හෝ දුරස්ථ OmniRoute සන්දර්භය භාවිතා කර මෙවලම වින්‍යාස කරන්න** ඔබගේ** යන්ත්රය. නාමාවලිය පදනම් වූ වට්ටෝරු සේවාදායකයෙන් ආකෘති ලබා ගනී; තනි-ආදර්ශ වට්ටෝරු `--model` පිළිගන්නවා හෝ ආකෘතියක් සඳහා විමසන්න ID. API යතුර මෙවලම සහාය දක්වන ඕනෑම තැනක පරිසර විචල්‍යයක් මගින් යොමු කෙරේ. මෙවලම්-දේශීය පරිසර ගොනුවක් පවතින විධාන පහත සටහන් කර ඇත.

ගණන් කිරීම් 2026-11-17 දින [මෙවලම් මැනිෆෙස්ටය](../../config/cli-tools-manifest.json) සහ [විධාන රෙජිස්ට්‍රිය](../../bin/cli/commands/registry.mjs) පිළිබිඹු කරයි. නාමාවලි ඇතුළත් කිරීමක් දියත් කිරීමේ ඇඩප්ටරයක් අදහස් නොකරයි. සම්පූර්ණ බඩු තොගය සඳහා [CLI මෙවලම් නාමාවලිය](../reference/CLI-TOOLS.md) බලන්න.

කිසිදු වින්‍යාසයක් ලිවීමෙන් තොරව, නිවැරදිව එන්නත් කර ඇති `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen`, `gemini` හෝ `whycodes` ඇති කරන සාමාන්‍ය දියත් කිරීමේ — `omniroute run <target>` — ද ඇත. ඉලක්ක සහ ඒවායේ අන්වර්ථයන් පැමිණෙන්නේ කැනොනිකල් මැනිෆෙස්ට් `bin/cli/cli-manifest.mjs` (`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`, `open-code`, `qwen-code`, `gemini-cli`, `why-codes|why`) වෙතින් වන අතර `omniroute completion` මඟින් එම මැනිෆෙස්ට් ව්‍යුත්පන්න ඉලක්ක වචන ඉදිරිපත් කරයි. `omniroute launch <tool>` එක් දියත් කිරීමේ සැසි ටෝකනයක් සහ ඔබ සම්බන්ධ කළ සැපයුම්කරුවන්ගෙන් සාදන ලද ආකෘති ලැයිස්තුවක් සමඟ සහය දක්වන කේතීකරණ මෙවලමක් ආරම්භ කරයි, සහ කිසිවක් ක්‍රියාත්මක නොවන විට දේශීය ද්වාරයක් ස්වයංක්‍රීයව ආරම්භ කරයි ( [LAUNCH.md](./LAUNCH.md) බලන්න). මෙවලම් නාමයක් (Claude කේතය) සහ `omniroute launch-codex` (Codex) — නොමැතිව ලෙගසි පර්-ටූල් දියත් කිරීම් — `omniroute launch` පවතී.

සපයන්නාගේ ඇතුල්වීම එකම local/remote සන්දර්භය වෙතින් ලබා ගත හැකිය. පහත API-පළමු විධාන මඟින් කළමනාකරණ සත්‍යාපනය සැපයුම්කරුගේ අක්තපත්‍රවලින් වෙන්ව තබා ගන්නා අතර ව්‍යුහගත ප්‍රතිදානයේ අක්තපත්‍රයක් කිසිවිටෙක මුද්‍රණය නොකරයි:

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

ස්ක්‍රිප්ට් සඳහා, කැමති `--credential-stdin` හෝ `--credential-env`; පාලනය කළ දේශීය භාවිතය සඳහා `--credential` රඳවා තබා ඇත. `providers remove` සඳහා අන්තර්ක්‍රියාකාරී නොවන පර්යන්තයක් මත `--yes` අවශ්‍ය වන අතර, විධාන පහම ක්‍රියාකාරී සන්දර්භයට හෝ ගෝලීය `--base-url`/`--api-key` විකල්පයන්ට ගරු කරයි.

සැපයුම්කරු තේරීම්කරුවන් අපැහැදිලි ID උපසර්ග, නම් හෝ සපයන්නන්ගේ නම් ප්‍රතික්ෂේප කරයි; සම්බන්ධතා කිහිපයක් ගැළපෙන විට සම්පූර්ණ සම්බන්ධතා ID භාවිතා කරන්න. විධාන සාදන්න සහ සංස්කරණය කරන්න සුරකින ලද සම්බන්ධතාවය නැවත කියවන්න, සහ ඉවත් කිරීමෙන් එය තවදුරටත් කියවිය නොහැකි බව තහවුරු කරයි. ආයාත කිරීමක් දැනට පවතින provider/name යුගලයක් මග හරියි. ආනයනය කරන ලද ප්‍රවේශයන් CLI වෙත සපයන ලද කළමනාකරණ අන්ත ලක්ෂ්‍යය, සන්දර්භය හෝ කළමනාකරණ අක්තපත්‍ර අභිබවා යා නොහැක.

- `--remote <url>` — දුරස්ථ OmniRoute භාවිතා කරයි ( `--port` සහ සක්‍රිය සන්දර්භය අභිබවා යයි). `--api-key <key>` එම සේවාදායකය සඳහා අක්තපත්‍ර සපයයි ( `OMNIROUTE_API_KEY` env var වෙත පෙරනිමිය, හෝ ක්‍රියාකාරී සන්දර්භයේ ටෝකනය).
- `--only <patterns>` — කොමාවෙන් වෙන් කරන ලද උපස්ථර; ගැලපෙන IDs ආකෘතිය පමණක් තබා ගන්න (උදා `--only glm,kimi`). `setup-codex`, `setup-claude`, `setup-opencode`, `setup-continue`, `setup-cursor`, `setup-crush`, `setup-zed` මත තිබේ.
- `--dry-run` — ගොනු පද්ධතිය ස්පර්ශ නොකර ලියන දේ හරියටම මුද්‍රණය කරන්න. සෑම `setup-*` විධානයකම පවතී** හැර** `setup-cursor` (කිසිවිටක ගොනුවක් ලියන්නේ නැත).
- ආකෘති ස්වයං-සොයාගැනීමක් නොමැති මෙවලම් සඳහා`--model <id>` — අවශ්‍ය වේ (හෝ අන්තර්ක්‍රියාකාරීව තෝරාගෙන ඇත): Cline, Kilo, Roo, Goose, Qwen, Gemini, Aider, 5dive, WhyCodes. එම මෙවලම් අන්තර්ක්‍රියාකාරී නොවන ධාවන සඳහා `--yes` ද පිළිගනී (එවිට `--model` අවශ්‍ය වේ). පෙරනිමි ඉහළ මට්ටමේ ආකෘතිය සැකසීමට `setup-opencode` `--model` ගනී.
- `--model <id>` මත `omniroute run` මැනිෆෙස්ටයේ එක්-ඉලක්ක රැහැන් (`bin/cli/cli-manifest.mjs`) අනුගමනය කරයි:** සහායකයා** `--model openai/<id>` සහ** විවෘත කේතය** `--model omniroute/<id>` (උපසර්ගය එකතු කරනු ලබන්නේ හැඳුනුම්පත දැනටමත් එය රැගෙන නොයන විට පමණි);** qwen** සහ** මිථුන ලග්නය** හැඳුනුම්පත වාචිකව ලබා ගන්න;** claude** එය `ANTHROPIC_MODEL` හරහා ලබා ගනී,** පාත්තයා** `GOOSE_MODEL` හරහා,** ඇයි කේත** `-P omniroute -m <id>` හරහා සහ** කෝඩෙක්ස්** `-c model_providers.omniroute.*` args හරහා.**Qwen යනු දැඩි ලෙස `--model` අවශ්‍ය වන එකම ධාවන ඉලක්කයයි** එය නොමැතිව — `omniroute run qwen` පැහැදිලි දෝෂයක් සහිතව `2` වෙතින් පිටවෙයි.
- `--port <port>` — දේශීය OmniRoute වරාය (පෙරනිමි `20128`, `--remote` සකසා ඇති විට නොසලකා හරිනු ලැබේ). සියලුම `setup-*` සහ දියත් කිරීම් දෙකෙහිම ඉදිරිපත් කරන්න.
- `omniroute run` පිටවීමේ කේත: දරුවාගේ CLI ගේම පිටවීමේ කේතය වාචිකව ප්‍රචාරය කරනු ලැබේ; `2` = වලංගු නොවන තර්ක (සහාය නොදක්වන ඉලක්කය, අවශ්‍ය `--model` අතුරුදහන් , බහාලුම් ආරක්ෂක); `127` = ඉලක්ක ද්විමය `PATH` හි නැත; `130`/`143`/`129` දියත් කිරීම `SIGINT`/`SIGTERM`/`SIGHUP` මගින් අවසන් වන විට; `1` = වෙනත් ධාවන කාල දියත් කිරීමේ අසාර්ථකත්වය.
- දියත් කරන්නන් දෙක (`launch`, `launch-codex`) `setup-claude` / `setup-codex` විසින් ලියන ලද පැතිකඩක් තේරීමට `--profile <name>` පිළිගන්නා අතර යටින් පවතින `claude` / `codex` ද්විමය සඳහා pass-through args.

අන්තර්ක්‍රියාකාරී පිකර් සැකසුම් වට්ටෝරු මගින් ද බෙදා ගනී:

```bash
# Pick from the active local or remote model catalog and configure the target.
omniroute configure claude
omniroute configure opencode --provider glm
omniroute configure qwen --model qwen/qwen3.8-max-preview --yes
omniroute configure gemini
omniroute configure whycodes
```

`configure` දැනට `codex`, `claude`, `opencode`, `qwen`, `gemini`, `aider`, `goose`, `cline`, `continue`, `kilo`, `5dive`, සහ `whycodes` සඳහා පරීක්ෂා කරන ලද වට්ටෝරු වෙත පැවරේ. IDE-පමණක්, MITM, සහ මාර්ගෝපදේශ-පමණක් නාමාවලි ඇතුළත් කිරීම් පැහැදිලි `setup-*`/ අතින් ප්‍රවාහයන් ලෙස පවතින අතර දියත් කළ හැකි ඉලක්ක ලෙස ඉදිරිපත් නොකෙරේ.

> `setup-opencode` යනු** සැහැල්ලු openai-අනුකූල** OpenCode ඒකාබද්ධ කිරීම. `@omniroute/opencode-plugin` ස්ථාපනය කරන — `omniroute setup opencode` — පොහොසත් ප්ලගින ඒකාබද්ධ කිරීමක් ද ඇත. ඒවා විවිධ විධාන; ඉහත වගුව ලේඛන `setup-opencode`.
>
> ප්ලගිනය පැකේජ දෙකකින් පැකේජ දෙකකින් පැමිණේ, OpenCode මේජර් එකකට එකක්, මක්නිසාද යත්, පූරණය කරන්නන් දෙදෙනා විවිධ ප්‍රවේශ ස්ථාන අපේක්ෂා කරන බැවිනි: OpenCode v1 සඳහා `@omniroute/opencode-plugin` සහ OpenCode v2 සඳහා `@omniroute/opencode-plugin-v2`. v2 පැකේජය අලුත් (`0.1.0`) වන අතර තවමත් චලනය වන සත්කාරක කොන්ත්‍රාත්තුවක් අනුගමනය කරයි, එබැවින් එය OpenCode බීජ වල හැඩයක් උපකල්පනය කරනවාට වඩා නාමාවලි කෙටුම්පතට කියවයි. `opencode.json` වෙත `plugins` ප්‍රවේශයක් එක් කිරීමෙන් එය ස්ථාපනය කරන්න; `omniroute setup opencode` තවමත් v1 පැකේජය ස්ථාපනය කරයි. විකල්ප සහ අක්තපත්‍ර බැලීමේ අනුපිළිවෙල README පැකේජයේ ඇත.

## දේශීය භාවිතය

OmniRoute `localhost:20128` මත ක්රියාත්මක වන විට, ඔබේ මෙවලම සඳහා සැකසුම් විධානය ක්රියාත්මක කරන්න. නාමාවලිය දේශීය සේවාදායකයෙන් ලබාගැනේ.

```bash
# Codex: ගැළපෙන සෑම ආකෘතියකටම පැතිකඩක් ~/.codex/ තුළ ලියන්න
omniroute setup-codex
codex --profile glm52            # ජනනය කළ පැතිකඩක් භාවිත කරන්න

# Claude Code: එක් එක් ආකෘතිය සඳහා පැතිකඩ ලියා, ඉන් එකක් දියත් කරන්න
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode: සියලු නාමාවලි ආකෘති සහිත openai-අනුකූල සැපයුම්කරු ලියන්න
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # {env:OMNIROUTE_API_KEY} හරහා යොමු කෙරේ, කිසිවිටෙකත් තැටියට නොලියයි
opencode -m omniroute/glm/glm-5.2 "..."

# ස්වයංක්රීය සොයාගැනීම නොමැති මෙවලම් සඳහා නිශ්චිත ආකෘතියක් අවශ්ය වේ:
omniroute setup-aider --model glm/glm-5.2
omniroute setup-qwen --model qwen/qwen3.8-max-preview

# කිසිවක් නොලියා පෙරදසුන් කරන්න:
omniroute setup-continue --dry-run
```

කිසිදු වින්යාසයක් නොලියා දියත් කරන්න (පරිසර-ආදේශනය පමණි):

```bash
omniroute launch                 # Claude Code → දේශීය OmniRoute

omniroute run qwen --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# නිශ්චිත විධාන මාර්ගය: -- ට පසුව එන ඕනෑම දෙයක් ඒ ආකාරයෙන්ම යොමු කරන්න
omniroute run claude -- --print-system-prompt "review this diff"
```

## දුරස්ථ භාවිතය

ඕනෑම සැකසුම් විධානයක් `--remote` + `--api-key` සමඟ දුරස්ථ OmniRoute එකකට යොමු කරන්න. නාමාවලිය දුරස්ථ පද්ධතියෙන් ලබාගෙන, වින්යාසය ඔබේ දේශීය යන්ත්රයේ ලියනු ලැබේ.

```bash
# දුරස්ථ VPS එකකට එරෙහිව OpenCode, glm/kimi ආකෘති පමණක් තබාගන්න
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx \
  --only glm,kimi
opencode -m omniroute/glm/glm-5.2 "..."   # පළමුව OMNIROUTE_API_KEY export කරන්න

# දුරස්ථ නාමාවලියකින් Codex පැතිකඩ
omniroute setup-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# CLI එකක් සෘජුවම දුරස්ථ පද්ධතියට එරෙහිව දියත් කරන්න
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

සෑම වරකම `--remote`/`--api-key` ලබාදීම වෙනුවට, එක් වරක් පුරනය වී ඒවා ස්වයංක්රීයව සැපයීමට **සක්රිය සන්දර්භයට** ඉඩ දෙන්න:

```bash
omniroute connect 192.168.0.15        # සීමා කළ ටෝකනයක් නිකුත් කර, සන්දර්භය ගබඩා කරයි
omniroute setup-codex                 # ← දැන් දුරස්ථ නාමාවලිය භාවිත කරයි
omniroute setup-opencode              # ← මෙයත් එසේමයි
omniroute launch                      # ← දුරස්ථ පද්ධතියට එරෙහිව Claude Code
```

සන්දර්භ, විෂයපථ සහ ටෝකන කළමනාකරණය සඳහා [දුරස්ථ ප්රකාරය](./REMOTE-MODE.md) බලන්න.

## 5 කිමිදුම් නියෝජිත බලඇණි

[5dive](https://5dive.ai) දිගුකාලීන කේතීකරණ නියෝජිතයන් සමූහයක් ධාවනය කරයි, ඒ සෑම එකක්ම තමන්ගේම Unix පරිශීලකයෙකු යටතේ systemd ඒකකයකි. එය CLI කේතනයක් නොවේ, එබැවින් `omniroute run` සඳහා — `5dive` දියත් කිරීමට කිසිවක් නැත.** වින්‍යාස කිරීමට පමණි** ඉලක්කය.

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

ආකෘති දෙකම එක් 5 ඩයිව් එකක් ලියන්න** auth පැතිකඩ** , සහ එම පැතිකඩට බැඳී ඇති සෑම `claude` ආසනයක්ම පසුව OmniRoute සමඟ කතා කරයි. මෙම ඉලක්කයට විශේෂිත වූ කරුණු තුනක්:

- **එය root ලෙස fleet host මත ධාවනය වේ.** 5dive හි ක්‍රියාපද දේශීය systemd ඒකක මත ක්‍රියා කරයි සහ root සතු රාජ්‍ය dir; දුරස්ථ මාදිලියක් නොමැත. වට්ටෝරුව දැනටමත් root නොමැති විට `sudo` හරහා නැවත ක්‍රියාත්මක වේ (`--no-sudo` එය අක්‍රිය කර ඒ වෙනුවට විධානය මුද්‍රණය කරයි).
- **එය loopback නම් මිස අවසාන ලක්ෂ්‍යය `https://` විය යුතුය.** නියෝජිතයාගේ API යතුර සෑම ඉල්ලීමකටම URL ධාවනය කරයි, සහ 5dive සාමාන්‍ය පෙළ නොබැඳි අන්ත ලක්ෂ්‍යයක් ප්‍රතික්ෂේප කරයි. පුද්ගලික LAN ලිපිනයක් ව්‍යතිරේකයක් නොවේ.
- **සෑම ආසනයකම තමන්ගේම ආදර්ශ පින් එක පැතිකඩ අභිබවා යයි.** පැතිකඩ `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` දරයි, නමුත් තවමත් කොටස් මාදිලි හැඳුනුම්පතකට අමුණා ඇති ආසනයක් _"තෝරාගත් මාදිලියේ ගැටලුවක් තිබේ"_ සමඟින් එහි පළමු හැරීම අසාර්ථක වේ. ආසන ද ඇමිණීමට `--agent <name>` (පුනරාවර්තනය කළ හැකි) පසු කරන්න; වට්ටෝරුව ඔබ නොකරන විට විධානය මුද්‍රණය කරයි.

API යතුර 5dive on වෙත භාර දෙනු ලැබේ** stdin** (`--api-key=-`), එබැවින් එය කිසි විටෙකත් `ps` ප්‍රතිදානයේ නොපෙන්වයි.

පැතිකඩ OmniRoute වෙත යොමු කිරීම** සංයෝජනය** තනි මාදිලියකට වඩා, ගුවන් යානා සපයන්නා අසමත් වන්නේ: ප්‍රාථමික අන්ත ලක්ෂ්‍යය [#11578](https://github.com/cheaper-inference/OmniRoute/issues/11578) හි වාර්තා කර ඇති ධාවනයේදී මධ්‍ය-පහළට තදින්-පහළට ගිය විට, නියෝජිතයා පසුබැසීම මත එහි ඉතිරි පියවර අවසන් කළ අතර කිසි විටෙකත් ඇනහිටීම මතු නොවීය.

## යාවත්කාලීන කිරීමේදී ස්වදේශීය පරායත්තතා රඳවා ගැනීම: `--include=optional`

ඔබ `omniroute update` මඟින් යාවත්කාලීන කරන විට (තහවුරු කිරීමෙන් පසු, හෝ `--apply` සමඟ),
OmniRoute විසින් ස්ථාපනය තුළ `--include=optional` පෙරනිමියෙන් ඇතුළත් කර ක්රියාත්මක කරයි:

```bash
npm install -g omniroute@latest --include=optional
```

මෙය ඔබ `omniroute update` වෙත ලබා දෙන ධජයක් **නොවේ** — යාවත්කාලීනකාරකය විසින් එය
සැමවිටම යොදනු ලැබේ. ඔබගේ npm වින්යාසයෙහි `omit=optional` සකසා තිබුණද
`optionalDependencies` (`better-sqlite3`, `keytar`, `tls-client`, LLMLingua SLM තොගය)
යාවත්කාලීනයෙන් පසුවත් පවතින බව මෙය සහතික කරයි; එසේ නොවුණහොත් ස්වදේශීය SQLite
ධාවකය සහ OS යතුරු-වළලු බැඳීම නිහඬව ඉවත් වනු ඇත. යෙදීමකින් තොරව නිශ්චිත විධානය පෙරදසුන් කිරීමට:

```bash
omniroute update --dry-run
# [වියළි ධාවනය] ක්රියාත්මක කිරීමට තිබුණේ: npm install -g omniroute@latest --include=optional
```

වෙනත් `omniroute update` ධජ (මූලාශ්රය තුළ සත්යාපනය කර ඇත): `--check` (යල්පැන ඇත්නම්
පිටවීමේ කේතය 1), `--apply` (විමසීමකින් තොරව ස්ථාපනය කරන්න), `--changelog`, `--no-backup`,
`--yes`.

## `omniroute run gemini` හරහා Google Gemini CLI

`@google/gemini-cli` 0.50.0 සමඟ ගිවිසුම සත්යාපනය කර ඇත: CLI විසින්
`GOOGLE_GEMINI_BASE_URL` පිළිපදින අතර එයට එරෙහිව
`POST /v1beta/models/<model>:generateContent` (සහ `:streamGenerateContent?alt=sse`)
නිකුත් කරයි — එය හරියටම OmniRoute හි ස්වදේශීය Gemini අතුරුමුහුණතයි (`/v1beta`).
`omniroute run gemini` එය ස්වයංක්රීයව සම්බන්ධ කරයි:

- `GOOGLE_GEMINI_BASE_URL` → සක්රිය OmniRoute මූලික URL එක (මූලය, `/v1` නොමැතිව);
- `GEMINI_API_KEY` → විසඳාගත් OmniRoute අක්තපත්රය (විකල්පය/පරිසරය/සන්දර්භය);
- `gemini-api-key` සත්යාපනය තෝරන `.gemini/settings.json` සහිත **තාවකාලික හුදකලා
  `GEMINI_CLI_HOME` එකක්**, එමඟින් ගබඩා කර ඇති Google OAuth සැසියක් (Code Assist)
  කිසිවිටෙක OmniRoute වෙත යොමු කළ දියත් කිරීම අභිබවා නොයයි — පිටවීමෙන් පසු ඉවත් කරනු ලැබේ;
- **පරිසර සනීපාරක්ෂාව**: උප-ක්රියාවලියේ පරිසරයෙන් `GOOGLE_API_KEY`,
  `GOOGLE_GENAI_USE_VERTEXAI` සහ `GOOGLE_GENAI_USE_GCA` (මේවා සත්යාපනය
  Vertex/Code Assist වෙත යළි යොමු කරනු ඇත) ඉවත් කරන අතර,
  අමතර ආරක්ෂිත විකල්පයක් ලෙස `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key` සකසයි —
  අනෙකුත් `run` ඉලක්කවලටද ඒවාටම අදාළ ගැටෙන විචල්යයන් සඳහා එකම
  සැලකීම ලැබේ;
- `--provider`/`--model` වෙතින් `--model <id>` ඇතුළු කිරීම.

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

Gemini හි වැඩබිම්-විශ්වාස ආරක්ෂකය තිර රහිත ප්රකාරයේදීද තවමත් අදාළ වේ — ඔබම
`--skip-trust` ලබා දෙන්න (හෝ අන්තර්ක්රියාකාරීව නාමාවලිය විශ්වාස කරන්න); දියත්කාරකය
හිතාමතාම එය මඟ නොහරියි. මෙම දියත්කාරකය **ACP ලියාපදිංචියෙන්**
(`src/lib/acp/registry.ts`, `gemini --acp`) වෙනස් වන අතර, එය
`/dashboard/acp-agents` සඳහා නියෝජිත-ප්රොටෝකෝල අනුකලනය ලෙස දිගටම පවතී.

## සත්ය smoke sweep පරීක්ෂාව (අභිමතයෙන් සක්රිය කළ හැකි)

නිර්ණායක launch-plan ප්රතිගමන පරීක්ෂණ CI තුළ ධාවනය වේ (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`). සත්ය OmniRoute සේවාදායකයකට එරෙහිව සත්ය
binary ගොනු වලංගු කිරීමට, අභිමතයෙන් සක්රිය කළ හැකි harness එකක්
`tests/integration/upstream-cli-smoke.int.test.ts` හි ඇත. එය කිසිවිටෙක ස්වයංක්රීයව
ධාවනය නොවේ (`RUN_CLI_SMOKE=1` නොමැති නම් සෑම උප-පරීක්ෂණයක්ම මඟ හරියි), අක්තපත්රය env-var
NAME එක මඟින් යවයි (කිසිවිටෙක එහි අගය මඟින් නොවේ), වාර්තා කළ ඕනෑම ප්රතිදානයකින්
යතුරු ආකාරයේ තන්තු වසන් කරයි, binary ගොනුව ස්ථාපනය කර නොමැති ඉලක්ක මඟ හරියි, සහ
අසාර්ථකවීම් හුදු boolean අගයක් වෙනුවට auth / upstream / config ලෙස වර්ගීකරණය කරයි:

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

විකල්ප: `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` මඟින් පරීක්ෂාව සීමා කරයි;
`OMNIROUTE_SMOKE_TIMEOUT_MS` මඟින් එක් ඉලක්කයකට ඇති 120s කල් ඉකුත්වීම ප්රතිස්ථාපනය කරයි.
