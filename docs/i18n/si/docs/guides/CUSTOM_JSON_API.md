අභිරුචි JSON API නෝඩයක් OpenAI හෝ Anthropic ප්‍රොටෝකෝලය කථා නොකරන JSON ව්‍යාපාරික අන්ත ලක්ෂ්‍යයක් සම්බන්ධ කරයි. OmniRoute JSON ඉල්ලීම් අච්චුවක් පුරවා, එය සම්පූර්ණ අන්ත ලක්ෂ්‍යයට යවයි URL ප්‍රතිචාර මාර්ගයකින් පිළිතුර කියවා සේවාලාභියාගේම ආකෘතියෙන් එය සේවාදායකයා වෙත ලබා දෙයි (කතාබස් සම්පූර්ණ කිරීම්, ප්‍රතිචාර, පණිවිඩ, ...).

එය `apiType: "custom-json"` සමඟ OpenAI-අනුකූල නෝඩයකි; එහි හැඳුනුම්පතේ `openai-compatible-custom-json-<suffix>` ආකෘතිය ඇත. උපකරණ පුවරු පෝරමය තවමත් නොමැත. පහත සැපයුම්කරු-node API හරහා මෙම නෝඩ් සාදන්න සහ සංස්කරණය කරන්න.

## නෝඩයක් සාදන්න

`POST /api/provider-nodes` (කළමනාකරණ auth):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` යනු** සම්පූර්ණයි** අන්ත ලක්ෂ්‍යය URL කිසිවක් එකතු කර නැත ( `/chat/completions`, `/models` නැත ) සහ අනෙකුත් OpenAI-අනුකූල නෝඩ් මෙන් නොව, පෙරනිමි URL නොමැත. එය කාවැද්දූ අක්තපත්‍ර හෝ `#fragment` නොමැතිව `http(s)` විය යුතු අතර, එය නෝඩය සුරකින විට සහ සෑම ඉල්ලීමකදීම සෑම සැපයුම්කරු නෝඩයක් ලෙසම එකම පිටතට යන URL ආරක්ෂකය පසු කරයි.
- සම්බන්ධතා යතුර යවන නෝඩයක් (`authType` `bearer` හෝ `api-key`, පෙරනිමිය ඇතුළුව) `https://` භාවිතා කළ යුතුය. ප්ලේන් `http://` පිළිගනු ලබන්නේ ලූප්බැක් සත්කාරක (`localhost`, `127.0.0.0/8`, `::1`) හෝ යතුරක් නොයවන `authType: "none"` සමඟ පමණි. පුද්ගලික LAN ලිපින (`10.x`, `172.16-31.x`, `192.168.x`) නිදහස් නොවේ: එම ජාලයේ ඕනෑම කෙනෙකුට යතුර කියවිය හැක. එවැනි නෝඩයක් සුරැකීම `400` සමඟ අසාර්ථක වන අතර, පෙර ගබඩා කර ඇති නෝඩයක් ඕනෑම ඉල්ලීමක් යැවීමට පෙර එකම පණිවිඩයක් සහිත සෑම ඉල්ලීමකදීම වසා දැමීම අසාර්ථක වේ. LAN මත යතුරු යෙදූ අන්ත ලක්ෂ්‍යයක් සඳහා, එය TLS පිටුපස තබන්න (උදාහරණයක් ලෙස ප්‍රතිලෝම ප්‍රොක්සියක්).
- `customJson` Zod සමඟ වලංගු වේ; නොදන්නා යතුරු ප්‍රතික්ෂේප වේ. සෑම ක්ෂේත්‍රයක්ම විකල්ප වේ:

| ක්ෂේත්රය          | වටිනාකම්                               | පෙරනිමිය                                               |
| ----------------- | -------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                 | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`            | `bearer`                                               |
| `authHeader`      | `api-key` විට භාවිතා කරන ශීර්ෂ නාමය    | `X-API-Key`                                            |
| `requestTemplate` | JSON වස්තුව (≤ 64 KB, ගැඹුර ≤ 32)      | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | ක්ෂේත්ර මාර්ගය, හෝ මුළු ශරීරය සඳහා `$` | `choices[0].message.content`                           |

- රහස පවතින්නේ සම්බන්ධතාවයේ API යතුරේ මිස කිසි විටෙක අච්චුවේ නොවේ. `bearer` යවයි `Authorization: Bearer <key>`; `api-key` `<authHeader>: <key>` යවයි. සත්‍යාපන ශීර්ෂය `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` හෝ hop-by-hop ශීර්ෂකය විය නොහැක. `none` සමඟ සම්බන්ධතා සඳහා යතුරක් අවශ්‍ය නොවේ.
- අමතර ස්ථිතික ශීර්ෂයන් නෝඩයේ සාමාන්‍ය `customHeaders` භාවිතා කරයි (අනෙක් සෑම අනුකූල නෝඩයකටම සමාන වලංගුකරණය; සත්‍යාපන ශීර්ෂයන් එහි ඉඩ නොදේ).

`PUT /api/provider-nodes/<id>` එකම `customJson` පිළිගෙන node හි පවතින සෑම සම්බන්ධතාවයකම `baseUrl` සහ config නැවත ලියයි. `customJson` මඟ හැරීම ගබඩා කළ වින්‍යාසය තබා ගනී; `apiType` `chat` හෝ `responses` වෙත මාරු කිරීම එය නෝඩයෙන් සහ එහි සම්බන්ධතා වලින් ඉවත් කරයි.

ඉන්පසු සාමාන්‍ය පරිදි node එකට සම්බන්ධතාවයක් එක් කරන්න (node id සමඟ `POST /api/providers` ) සහ `<prefix>/<model>` ඉල්ලන්න, උදාහරණයක් ලෙස `biz/assistant-v1`. අන්ත ලක්ෂ්‍යය ආදර්ශ ලැයිස්තුවක් නිරාවරණය නොකරයි, එබැවින් ආකෘති හැඳුනුම්පත අතින් එක් කරන්න.

## ආකෘති ඉල්ලන්න

සැකිලි සරල JSON වේ. තන්තු අගයක `{{placeholder}}` මාර්කර් අඩංගු විය හැක; කිසිවක් ඇගයීමට ලක් කර හෝ ක්‍රියාත්මක නොකරන අතර, වස්තුවේ යතුරු කිසි විටෙක ආදේශ නොකෙරේ.

| ස්ථාන දරන්නා         | වටිනාකම                                                            |
| -------------------- | ------------------------------------------------------------------ |
| `{{prompt}}`         | නවතම පරිශීලක පණිවිඩයේ පෙළ (නව රේඛා සමඟ සම්බන්ධ වූ පෙළ කොටස්)       |
| `{{messages}}`       | සංවාදය OpenAI කතාබස් ආකෘතියෙන්                                     |
| `{{model}}`          | ඉල්ලුම් කරන ලද ආකෘති හැඳුනුම්පත, සපයන්නාගේ උපසර්ගය නොමැතිව         |
| `{{stream}}`         | සෑම විටම `false` — අවසන් ලක්ෂ්‍යය එක් JSON ලේඛනයකින් පිළිතුරු දෙයි |
| `{{request.<path>}}` | පරිවර්තනය කළ (OpenAI චැට් ආකෘතිය) ඉල්ලීමේ ක්ෂේත්‍රයක්              |

- හරියටම එක් තැන් දරණ අගයක් එහි JSON වර්ගය තබා ගනී (`"{{messages}}"` අරාවක් බවට පත් වේ); දිගු තන්තුවක් තුළ ඇති ස්ථාන රඳවනයක් පෙළ ලෙස ඇතුළත් කර ඇත.
- අසම්පූර්ණ ගෙවීමක් යැවීම වෙනුවට HTTP 400 සමඟ ඇති ඉල්ලීම කිසිවක් නැති බව විසඳන තැන් දරණුවක් අසමත් වේ.
- මාර්ග තිත් අංකනය සහ සංඛ්‍යාත්මක දර්ශක (`data.items[0].text`) භාවිතා කරයි. `__proto__`, `prototype` සහ `constructor` යතුරු සහ මාර්ග වල ප්‍රතික්ෂේප වේ.

## ප්‍රතිචාර

`responsePath` හි අගය සහායක පිළිතුර බවට පත් වේ: නූල් හරහා ගමන් කරයි, අනෙකුත් JSON අගයන් අනුක්‍රමික වේ. නැතිවූ හෝ `null` ක්ෂේත්‍රයක් හෝ JSON නොවන සිරුරක් HTTP 502 ලබා දෙයි. Upstream දෝෂ තත්ත්වයන් හරහා යවනු ලැබේ. ප්‍රවාහ සේවාලාභීන් සඳහා OmniRoute සම්පූර්ණ JSON ප්‍රතිචාරය සඳහා රැඳී සිටින අතර පසුව එය එක් අන්තර්ගත කුට්ටියක් සහ අවසන් කොටස ලෙස විමෝචනය කරයි; මෙය සංකේත ප්‍රවාහයක් නොවේ. මෙවලම් ඇමතුම් සහ භාවිත ක්ෂේත්‍ර සිතියම්ගත කර නොමැත.

## කවදාවත් රිප්ලයි කළේ නැහැ

ව්‍යාපාරික ඉල්ලීමක් අසාර්ථක වූ විට පවා අතුරු ආබාධ ඇති විය හැක. එබැවින් OmniRoute එය වරක් යවයි:

- ප්‍රවාහනය නැවත උත්සාහයක් සහ නැවත හරවා යැවීමක් නොමැත;
- වෙනත් සම්බන්ධතාවයක් (ගිණුම් ආපසු හැරීම) නැවත උත්සාහ නොකරන්න — අසාර්ථකත්වය නැවත ලබා දෙන අතර සම්බන්ධතාවය සිසිල් නොවේ;
- හිස් හෝ අසාර්ථක පිළිතුරක් සඳහා වුවද, මීළඟ සංයෝජන ඉලක්කය වෙත ආපසු යාමක් නැත.

වෙනම සේවාලාභී ඉල්ලීම් සහ ආකෘති කිහිපයක් පැහැදිලිවම හඳුන්වන විලයන පැනල, තවමත් අන්ත ලක්ෂ්‍යය ස්වාධීනව ඉල්ලා සිටියි.

## නෝඩයක් පරීක්ෂා කිරීම

සම්බන්ධතාවයක් සුරැකීම, සම්බන්ධතාවය** පරීක්ෂණය** බොත්තම් සහ පසුබිම් සෞඛ්‍ය පරීක්‍ෂාවන් කිසිවිටෙකත් අන්ත ලක්ෂ්‍යය අමතන්නේ නැත: ඒවා ගබඩා කර ඇති වින්‍යාසය පමණක් වලංගු කරන අතර සම්බන්ධතාවය සත්‍යාපනය කළ නොහැකි ලෙස වාර්තා කරයි.

`"apiType": "custom-json"` සහ නෝඩ් ක්ෂේත්‍ර සහිත `POST /api/provider-nodes/validate` (`baseUrl`, `apiKey`, `customJson`, විකල්ප `customHeaders` සහ `modelId`) හරියටම එක් සැබෑ ඉල්ලීමක් යවයි, `ping` නවතම පරිශීලක පෙළ ලෙස යවයි. එය `{ "valid": true }` හෝ උඩුගං තත්ත්‍වයට පිළිතුරු දෙයි (කවදාවත් උඩුගං ශරීරය නොවේ).

## ගබඩා කිරීම

වින්‍යාසය `provider_nodes.custom_json_config_json` (සංක්‍රමණ `240_provider_node_custom_json_config.sql`) හි ගබඩා කර ඇති අතර එක් එක් සම්බන්ධතාවයේ `providerSpecificData.customJson` වෙත පිටපත් කරනු ලැබේ.

ක්‍රියාත්මක කිරීම: `open-sse/utils/customJson.ts` (වලංගුකරණය සහ සැකිලි), `open-sse/executors/customJson.ts` (ක්‍රියාත්මක කරන්නා), `open-sse/services/combo/noReplayLatch.ts` සහ `src/sse/handlers/chat/responsePolicies.ts` (නැවත ධාවනය නොවේ).
