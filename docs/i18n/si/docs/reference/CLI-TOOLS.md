```

Claude / Codex / OpenCode / Cline / KiloCode / Continue / Hermes Agent / Goose / ...
           │
           ▼  (සියල්ල OmniRoute වෙත යොමු වේ)
    http://YOUR_SERVER:20128/v1
           │
           ▼  (OmniRoute නිවැරදි provider වෙත route කරයි)
    Anthropic / OpenAI / Gemini / DeepSeek / Groq / Mistral / ...

ACP Agents (ප්රතිවිරුද්ධ ආරම්භක ප්රවාහය):
    Client ඉල්ලීම → OmniRoute → stdio/ACP හරහා CLI ආරම්භ කරයි → ප්රතිචාරය
```

## `setup-*` සමඟ ස්වයංක්‍රීයව වින්‍යාස කරන්න

ඔබ එක් එක් මෙවලම් වින්‍යාසය අතින් ලිවිය යුතු නැත. OmniRoute විසින් කියවන සහය දක්වන CLI එකකට `setup-*` විධානයක් යවයි** ජීවත් වෙනවා** ධාවනය වන OmniRoute (දේශීය හෝ දුරස්ථ) වෙතින් ආකෘති නාමාවලිය සහ ඔබේ යන්ත්‍රයේ මෙවලමෙහිම වින්‍යාසය ලියයි:

```bash
omniroute setup-codex        omniroute setup-claude       omniroute setup-opencode
omniroute setup-cline        omniroute setup-kilo         omniroute setup-continue
omniroute setup-cursor       omniroute setup-roo          omniroute setup-crush
omniroute setup-goose        omniroute setup-qwen         omniroute setup-aider
omniroute setup-5dive        omniroute setup-zed
omniroute setup-whycodes
```

සෑම එකක්ම `--remote <url> --api-key <key>` (දුරස්ථ OmniRoute එරෙහිව දේශීය මෙවලමක් වින්‍යාස කරන්න), `--dry-run` (ලිවීමකින් තොරව පෙරදසුන) සහ `--port` පිළිගනී. ආකෘති ස්වයං-සොයාගැනීමක් නොමැති මෙවලම් (Cline, Kilo, Roo, Goose, Aider, Qwen, 5dive, WhyCodes) `--model <id>` (සහ අන්තර්ක්‍රියාකාරී නොවන ධාවන සඳහා `--yes` ) ගනී. `setup-5dive` යනු `$HOME` යටතේ නොලියන එක් වට්ටෝරුවකි : එය fleet host මත root හිමි auth පැතිකඩක් ලිවීමෙන් 5dive නියෝජිත සමූහයක් වින්‍යාස කරයි, එබැවින් එය `sudo` හරහා නැවත ක්‍රියාත්මක වන අතර එහිම දුරස්ථ මාදිලියක් නොමැත. නිවැරදි env එන්නත් කර කිසිදු වින්‍යාසයක් ලියා නොමැති CLI දියත් කිරීමට, සාමාන්‍ය `omniroute run <target>` දියත් කිරීම භාවිතා කරන්න (claude, codex, aider, goose, opencode, qwen, gemini, Whycodes — targets and aliases එන්න `bin/cli/cli-manifest.mjs`); ලෙගසි පර්-ටූල් දියත් කිරීම් `omniroute launch` (Claude කේතය) සහ `omniroute launch-codex` (Codex) පවතී. Gemini CLI දියත් කිරීමට පමණි: එය `omniroute run` ඉලක්කයක් වන නමුත් `setup-*`/`configure` වට්ටෝරුවක් නොමැත.

> **සම්පූර්ණ යොමුව:** ප්‍රධාන වගුව - සෑම විධානයක්ම ලියන දේ, සෑම ධජයක්ම, ප්‍රාදේශීය එදිරිව දුරස්ථ, සහ කුමන මෙවලම් සඳහා `/v1` උපසර්ගයක් අවශ්‍යද - ජීවත් වේ** [CLI ඒකාබද්ධ කිරීම්](../guides/CLI-INTEGRATIONS.md)** .

### කන්ටේනරයක් ඇතුලේ මේවා දුවනවා

OmniRoute කන්ටේනරය තුළ ක්‍රියාත්මක කරන ලද `setup-*` විධානයක් බහාලුම්කරුගේම නිවසට ලියයි, එය කිසිදු ධාරකයක් CLI කියවා නැති අතර එය බහාලුම සමඟ අතුරුදහන් වේ. OmniRoute එය හඳුනාගෙන ලිවීමට වඩා උපදෙස් සමඟ `2` වෙතින් පිටවෙයි. සහය දක්වන ක්‍රම දෙකක් ඉදිරියට - ධාරකයේ CLI ස්ථාපනය කර බහාලුමට `omniroute connect` ස්ථාපනය කරන්න, නැතහොත් වින්‍යාසය සවිකර `CLI_CONFIG_HOME` සකසන්න ( `host` පැතිකඩ රචනා කරන්න). සෑම `setup-*` විධානයක්ම, සහ `omniroute configure` සහ `omniroute config set`, බහාලුම්වලම CLIs වින්‍යාස කිරීමේදී `--allow-container-write` පිළිගන්නේ ඔබ සැබවින්ම අදහස් කළේ කුමක්ද යන්නයි; `OMNIROUTE_ALLOW_CONTAINER_CONFIG_WRITE=true` සේවාදායකය සඳහාද එයම කරයි. [Docker මාර්ගෝපදේශය බලන්න → සත්කාරක CLI මෙවලම් වින්‍යාස කිරීම](../guides/DOCKER_GUIDE.md#configuring-host-cli-tools-when-omniroute-runs-in-docker).

උපකරණ පුවරුව** අන්ත ලක්ෂ්‍යය යොදන්න** (`POST /api/cli-tools/apply`) එකම ආරක්‍ෂාව බලාත්මක කරයි: කන්ටේනරයක, ධාරක පිළිතුරු වලින් බන්ධනය නොවූ ඉලක්කයක් ලිවීම**`422`** `containerEphemeralTarget: true` සමඟ ආරක්ෂිත දෝෂ පෙළ සහ - සත්කාරක වට්ටෝරුවක් සහිත මෙවලම් සඳහා (ක්ලෝඩ්, කෝඩෙක්ස්, ඕපන්කෝඩ්, ක්ලයින්, කිලෝ, දිගටම) - ඒ වෙනුවට ධාරකය මත ධාවනය කිරීමට `hostSetupCommand` (උදා: `omniroute setup-opencode`); කිසිවක් ලියා නැත. `dryRun: true` බහාලුම් ආකාරයෙන් ක්‍රියා කරන අතර තැටිය ස්පර්ශ නොකර නැවත සකස් කරන ලද පෙරදසුන + ඉලක්ක මාර්ගයක් ලබා දෙයි. පෙරදසුන් අන්තර්ගතය පිටපත් කිරීමට හෝ ආයාත කිරීමට අක්තපත්‍ර සහිත වින්‍යාස කිරීමක් නොවේ. ධාරකයේ මුල් tool/base URL/API key/model යෙදවුම් සමඟ යොදන්න, නැතහොත් සඳහන් කර ඇති සත්කාරක පැත්තේ සැකසුම් විධානය භාවිතා කරන්න. පෙරදසුන් ශීර්ෂය සහ ඉල්ලීම් කොන්ත්‍රාත්තු සඳහා [CLI වින්‍යාස ආරක්ෂණය](../security/CLI-CONFIGURATION.md) බලන්න. මෙම හැසිරීම චේතනාන්විත වන අතර `tests/unit/api/cli-tools/apply-container-guard.test.ts` මගින් ප්‍රතිගාමී-ආරක්ෂා කරයි - කිසි විටෙක ආරක්ෂකයා ඉවත් කිරීමෙන් 422 "සවිකර" නොකරන්න.

## 5. සමූහ හඳුනාගැනීමේ API

සියලුම මෙවලම් හඳුනාගැනීම් තනි අන්ත ලක්ෂ්යයක් හරහා ඒකාබද්ධ කර ඇත:

**`GET /api/cli-tools/all-statuses`**

- සත්යාපනය: `requireCliToolsAuth(request)` (අනෙකුත් `/api/cli-tools/` මාර්ගවලට සමානයි)
- ආපසු ලබාදෙන්නේ: `Record<toolId, ToolBatchStatus>` (වර්ගය: `src/shared/types/cliBatchStatus.ts`)
- උපායමාර්ගය: සියලු මෙවලම් මත `Promise.all`, එක් මෙවලමකට තත්පර 5ක කල් ඉකුත්වීමක්
- හැඹිලිය: වින්යාස ගොනුවේ `mtime` අනුව සුචිගත කළ මතකය-තුළ LRU. mtime වෙනස් වූ විට හැඹිලිය අවලංගු වේ. සේවාදායකය යළි ආරම්භ කළ විට යළි සකසයි.

එක් මෙවලමකට ප්රතිචාරයේ ව්යුහය:

```ts
interface ToolBatchStatus {
  detection: {
    installed: boolean;
    runnable: boolean;
    version?: string;
    command?: string;
    commandPath?: string;
    reason?: string;
  };
  config: {
    status: "configured" | "not_configured" | "not_installed" | "unknown" | "other";
    endpoint?: string | null;
    lastConfiguredAt?: string | null;
  };
  error?: string; // පිරිසිදු කර ඇත, stack traces නොමැත
}
```

VS Code Insiders අභිරුචි අන්ත ලක්ෂ්ය ආකෘති සඳහා වින්යාස කර ඇති විට සහ අභිරුචි ශීර්ෂ ක්ෂේත්රයක් නොමැතිව OmniRoute ක්රියා කරවීමට අවශ්ය විට මෙය භාවිත කරන්න.

**නිර්දේශිත පිහිටීම:**

- Linux: `~/.config/Code - Insiders/User/chatLanguageModels.json`
- Windows: `%APPDATA%/Code - Insiders/User/chatLanguageModels.json`

**ටෝකනීකරණය කළ OmniRoute අන්වර්ථ නාමය භාවිත කරන උදාහරණය:**

```json
[
  {
    "vendor": "customendpoint",
    "id": "auto",
    "name": "OmniRoute Auto",
    "family": "gpt-4",
    "version": "1.0.0",
    "url": "http://localhost:20128/api/v1/vscode/sk-your-omniroute-key/chat/completions",
    "modelsUrl": "http://localhost:20128/api/v1/vscode/sk-your-omniroute-key/models",
    "requestFormat": "openai-chat-completions",
    "contextWindow": 256000,
    "maxOutputTokens": 32768,
    "auth": {
      "type": "none"
    }
  }
]
```

**සටහන්:**

- `sk-your-omniroute-key` වෙනුවට OmniRoute තුළ සාදන ලද API යතුරක් යොදන්න.
- `url` ක්ෂේත්රය `/api/v1/vscode/{token}/chat/completions` වෙත යොමු විය යුතුය.
- `modelsUrl` ක්ෂේත්රය `/api/v1/vscode/{token}/models` වෙත යොමු විය යුතුය.
- සේවාලාභියා අභිරුචි ශීර්ෂක සඳහා සහාය දක්වන විට සාමාන්ය `/v1` + Bearer ශීර්ෂක ප්රවාහය භාවිත කිරීම වඩාත් සුදුසුය.
- URL තුළ අන්තර්ගත කළ ටෝකන ගැළපුම සඳහා වන විකල්ප ක්රමයක් වන අතර, ඒවා සංස්කාරක ලොග්වල හෝ ප්රොක්සි ඉතිහාසයේ දිස් විය හැක.

## 10. අභ්යන්තර OmniRoute CLI

`omniroute` ද්විමය ගොනුව මඟින් සේවාදායක ජීවන චක්රය, පිහිටුවීම, රෝග විනිශ්චය සහ සැපයුම්කරු කළමනාකරණය සඳහා විධාන සපයයි. ප්රවේශ ස්ථානය: `bin/omniroute.mjs`.

```bash
omniroute                              # සේවාදායකය ආරම්භ කරන්න (පෙරනිමි පෝර්ට් එක 20128)
omniroute setup                        # අන්තර්ක්රියාකාරී පිහිටුවීම් විශාරදය
omniroute doctor                       # වින්යාසය, DB, පෝර්ට් සහ ධාවන පරිසරය පරීක්ෂා කරන්න
omniroute providers list               # වින්යාස කර ඇති සැපයුම්කරු සම්බන්ධතා
omniroute providers test-all           # සෑම සක්රිය සම්බන්ධතාවක්ම පරීක්ෂා කරන්න
omniroute reset-password               # පරිපාලක මුරපදය යළි සකසන්න
omniroute logs                         # ඉල්ලීම් ලොග් ප්රවාහ කරන්න
omniroute health                       # සවිස්තරාත්මක සෞඛ්ය තත්ත්වය (බ්රේකර්, හැඹිලිය, මතකය)
omniroute --version                    # අනුවාදය මුද්රණය කරන්න
omniroute --help                       # සියලු විධාන පෙන්වන්න
```

### පිහිටුවීම සහ ආරම්භ කිරීම

```bash
omniroute setup                        # අන්තර්ක්රියාකාරී පිහිටුවීම් විශාරදය
omniroute setup --non-interactive      # CI/ස්වයංක්රීයකරණ ප්රකාරය (පරිසර විචල්ය + ධජ කියවයි)
omniroute setup --password '<value>'   # පරිපාලක මුරපදය සෘජුවම සකසන්න
omniroute setup --add-provider \
  --provider openai \
  --api-key '<value>' \
  --test-provider                      # එක් පියවරකින් සැපයුම්කරුවෙකු එක් කර පරීක්ෂා කරන්න
```

අන්තර්ක්රියාකාරී නොවන පිහිටුවීම සඳහා හඳුනාගන්නා පරිසර විචල්ය:

| විචල්යය             | අරමුණ                                                              |
| ------------------- | ------------------------------------------------------------------ |
| `OMNIROUTE_API_KEY` | සැපයුම්කරු API යතුර (Commander `.env()` හරහා `--api-key` වෙත බැඳේ) |
| `DATA_DIR`          | OmniRoute දත්ත නාමාවලිය අභිබවා සකසන්න                              |

අනෙකුත් සියලු අන්තර්ක්රියාකාරී නොවන ආදාන පරිසර විචල්ය ලෙස නොව ධජ ලෙස ලබා දෙයි:
`--password`, `--provider`, `--provider-name`, `--provider-base-url`, `--default-model`
(ඉහත `omniroute setup` විකල්ප බලන්න).

### රෝග විනිශ්චය

```bash
omniroute doctor                       # වින්යාසය, DB, පෝර්ට්, ධාවන පරිසරය, මතකය සහ සජීවී බව පරීක්ෂා කරන්න
omniroute doctor --json                # යන්ත්රයකට කියවිය හැකි JSON
omniroute doctor --no-liveness         # HTTP සෞඛ්ය පිරික්සුම මඟ හරින්න
omniroute doctor --host 0.0.0.0        # සජීවීතා සත්කාරකය අභිබවා සකසන්න
omniroute doctor --liveness-url <url>  # සම්පූර්ණ සෞඛ්ය අන්ත ලක්ෂ්ය URL එක අභිබවා සකසන්න
```

doctor පහත පරීක්ෂා ක්රියාත්මක කරයි: `Config`, `Database`, `Storage/encryption`,
`Port availability`, `Node runtime`, `Native binary` (better-sqlite3),
`Memory`, සහ `Server liveness`. කිසියම් පරීක්ෂාවක් `fail` නම්, එය ශූන්ය නොවන කේතයකින් පිටවෙයි.

### සැපයුම්කරු කළමනාකරණය

```bash
omniroute providers available                       # OmniRoute සැපයුම්කරු නාමාවලිය
omniroute providers available --search openai       # id/name/alias/category අනුව නාමාවලිය පෙරහන් කරන්න
omniroute providers available --category api-key    # ප්රවර්ගය අනුව පෙරහන් කරන්න (api-key, oauth, free, ...)
omniroute providers available --json                # යන්ත්රයකට කියවිය හැකි JSON

omniroute providers list                            # වින්යාස කර ඇති සැපයුම්කරු සම්බන්ධතා
omniroute providers list --json

omniroute providers test <id|name>                  # වින්යාස කර ඇති එක් සම්බන්ධතාවක් පරීක්ෂා කරන්න
omniroute providers test-all                        # සෑම සක්රිය සම්බන්ධතාවක්ම පරීක්ෂා කරන්න
omniroute providers validate                        # දේශීය-පමණක් ව්යුහාත්මක වලංගුකරණය
omniroute providers add <provider> --credential-env PROVIDER_KEY
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth <provider>                 # පවතින OAuth ප්රවාහය
omniroute providers edit <id|name> --default-model <model>
omniroute providers remove <id|name> --yes
```

`providers add/import/auth/edit/remove` API-ප්රමුඛ වන අතර, එබැවින් ඒවා සක්රිය දේශීය හෝ දුරස්ථ සන්දර්භයට එරෙහිව ක්රියා කරයි. අක්තපත්ර ආදානය සඳහා
`--credential-stdin` හෝ `--credential-env` භාවිත කළ යුතුය; `--dry-run --json` වාර්තා කරන්නේ
සංස්කරණය කර සඟවන ලද පැවැත්ම/හැඩය පමණි. `providers available` OmniRoute නාමාවලිය කියවයි;
`providers list/test/test-all/validate` ඒවායේ දේශීය SQLite හැසිරීම පවත්වාගෙන යන අතර
සේවාදායකය ක්රියාත්මකව තිබීම අවශ්ය නොවේ.

අභිරුචි OpenAI-අනුකූල හෝ Anthropic-අනුකූල නෝඩයක් සඳහා, `omniroute nodes add` මඟින් ලබා දෙන නෝඩ් ID එකට
`omniroute keys add "$NODE_ID" --stdin` භාවිතයෙන් අක්තපත්ර අමුණන්න.
මේ සඳහා ක්රියාත්මක සේවාදායකයක් සහ සක්රිය සන්දර්භය සඳහා කළමනාකරණ සත්යාපනය අවශ්ය වේ.
CLI එක `POST /api/providers` භාවිත කරයි; එය නෝඩය වලංගු කර එහි අන්ත ලක්ෂ්ය
සැකසුම් සම්බන්ධතාවයට පිටපත් කරයි. නෝඩයක් නොමැති වීම, අවසර දීම අසාර්ථක වීම හෝ සේවාදායකය
ලබාගත නොහැකි වීම, දේශීය විකල්ප අක්තපත්රයක් නොසාදා දෝෂයක් ආපසු ලබා දෙයි.

`nodes add --base-url` නෝඩ් අන්ත ලක්ෂ්යය සකසයි; එය `OMNIROUTE_BASE_URL` හි ඇති සේවාදායක ලිපිනයෙන්
වෙනස් වේ. OpenAPI ගොනු සඳහා,
`omniroute openapi dump --format json --out ./openapi.json` භාවිත කරන්න; ගෝලීය `--output`
ගමනාන්ත ගොනු නාමයක් නොව, CLI දර්ශන ආකෘතිකරණය තෝරයි.

### ප්රතිසාධනය සහ යළි සැකසීම

```bash
omniroute reset-password                # පරිපාලක මුරපදය යළි සකසන්න (මෙලෙසද: omniroute-reset-password)
omniroute reset-encrypted-columns       # සංකේතනය කළ අක්තපත්ර යළි සැකසීම සඳහා අනතුරු ඇඟවීම + අත්හදා බැලීම පෙන්වන්න
omniroute reset-encrypted-columns --force  # SQLite තුළ සංකේතනය කළ අක්තපත්ර සැබවින්ම null කරන්න
```

### අක්තපත්ර අපනයනය (⚠ ප්රවේශමෙන් හසුරුවන්න)

```bash
omniroute auth export                                 # අනතුරු ඇඟවීම + තහවුරු කිරීමේ ද්වාරය පෙන්වන්න — DB ප්රවේශයක් නැත
omniroute auth export --force                          # සියලු සම්බන්ධතාවල විකේතනය කළ අක්තපත්ර JSON ලෙස stdout වෙත අපනයනය කරන්න
omniroute auth export --force --id <id>                 # ගැළපෙන සම්බන්ධතාව පමණක් අපනයනය කරන්න
omniroute auth export --force --format env               # OMNIROUTE_<PROVIDER>_<FIELD>=<value> පේළි නිකුත් කරන්න
omniroute auth export --force --out creds.json           # ගොනුවකට ලියන්න (0600 අවසර සමඟ සාදනු ලැබේ)
```

`auth export` යනු **දේශීය-පමණක්** ක්රියාත්මක වන විශේෂාංගයකි (සෘජු SQLite කියවීමක්, HTTP route එකක් නොවේ) සහ එය හිතාමතාම
**සරල පෙළ** `apiKey`/`accessToken`/`refreshToken`/`idToken` අගයන් මුද්රණය කරයි/ලියයි — එය දෝෂයක් නොව,
අදාළ විශේෂාංගයයි. `--force` නොමැතිව දත්ත සමුදායෙන් කිසිවක් කියවන්නේවත්, කිසිවක් විකේතනය කරන්නේවත් නැත. කිසියම් සරල පෙළක් නිකුත් කිරීමට පෙර සෑම විටම stderr
අනතුරු ඇඟවීමේ බැනරයක් මුද්රණය වේ. `STORAGE_ENCRYPTION_KEY` සකසා තිබීම
අවශ්ය වේ. විකේතනය කිරීමට අසමත් වන ක්ෂේත්රයක් (කල් ඉකුත් වූ යතුරක්, දූෂිත කේතාංක පෙළක්) සම්පූර්ණ export ක්රියාවලිය නතර කිරීම හෝ යටින් පවතින දෝෂය හෙළි කිරීම වෙනුවට
`<field>DecryptFailed: true` ලෙස වාර්තා කෙරේ.

### අනෙකුත් උපවිධාන

වෙනත් ආකාරයකින් සඳහන් කර නොමැති නම්, මේවා ක්රියාත්මක වන OmniRoute server එකක් පවතින බව උපකල්පනය කරයි:

```bash
omniroute status                       # සම්පූර්ණ runtime තත්ත්වය
omniroute logs                         # ඉල්ලීම් ලොග් ප්රවාහ කරන්න (--json, --search, --follow)
omniroute config list                  # වින්යාස කළ CLI මෙවලම් පෙන්වන්න

omniroute provider list                # පවතින providers ලැයිස්තුගත කරන්න (providers list සඳහා අන්වර්ථ නාමයකි)
omniroute provider add                 # මෙවලමක provider එකක් ලෙස OmniRoute ලියාපදිංචි කරන්න
omniroute keys add | list | remove     # API keys කළමනාකරණය කරන්න
omniroute models [provider]            # models ලැයිස්තුගත කරන්න (--json, --search)
omniroute combo list | switch | create | delete

omniroute backup                       # config + DB snapshot එකක් සාදන්න
omniroute restore                      # පෙර snapshot එකකින් ප්රතිසාධනය කරන්න

omniroute health                       # සවිස්තරාත්මක සෞඛ්ය තත්ත්වය (breakers, cache, memory)
omniroute quota                        # Provider quota භාවිතය
omniroute cache                        # Cache තත්ත්වය
omniroute cache clear                  # semantic + signature caches හිස් කරන්න

omniroute mcp status | restart         # MCP server තත්ත්වය / නැවත ආරම්භ කිරීම
omniroute a2a status | card            # A2A server තත්ත්වය / agent card

omniroute tunnel list | create | stop  # tunnels කළමනාකරණය කරන්න (cloudflare/tailscale/ngrok)
omniroute env show | get <k> | set <k> <v>  # env vars පරීක්ෂා කරන්න / සකසන්න (තාවකාලික)

omniroute test                         # Provider සම්බන්ධතාව සඳහා smoke test එකක්
omniroute update                       # යාවත්කාලීන තිබේදැයි පරීක්ෂා කරන්න
omniroute completion                   # shell completion ජනනය කරන්න
```

## OmniRoute CLI සමඟ inference-key ප්රතිපත්තිය කළමනාකරණය කරන්න

දැනට පවතින inference යතුරක් එහි ID මඟින් පරීක්ෂා කිරීමට හෝ යාවත්කාලීන කිරීමට සත්යාපිත කළමනාකරණ සන්දර්භයක් භාවිත කරන්න ([දුරස්ථ ප්රකාරය](../guides/REMOTE-MODE.md) බලන්න):

```bash
omniroute --output json keys policy show KEY_ID
omniroute keys policy set KEY_ID --unrestricted
omniroute --output json keys policy show KEY_ID
```

`--unrestricted` යනු `--model-access-mode all` සඳහා අන්වර්ථයකි. යාවත්කාලීනය ආකෘති අවසර ලැයිස්තුව හිස් කරයි. එය විෂය පථ, සම්බන්ධතා නීති, අවහිර කළ ආකෘති, අනුපාත සීමා සහ පිරිවැය සීමා රඳවා ගනී; එම නිසා එම අනෙකුත් පාලනවලට තවමත් ඉල්ලීමක් ප්රතික්ෂේප කළ හැකිය. පැහැදිලි `--allowed-models ""` එකක් ද `all` තෝරයි; අවසර දුන් ආකෘති නොමැති සීමා කළ යතුරක් පවත්වා ගැනීමට එය `--model-access-mode restricted` සමඟ ඒකාබද්ධ කරන්න. පැහැදිලිව වෙනත් ආකාරයකින් සඳහන් කර නොමැති නම්, හිස් නොවන කොමාවලින් වෙන් කළ ලැයිස්තුවක් `restricted` තෝරයි. හිස් නොවන අවසර ලැයිස්තුවක් සමඟ පරස්පර `all` එකක් ඉල්ලීමක් යැවීමට පෙර ප්රතික්ෂේප කරනු ලැබේ.

`--rate-limit 30` මිනිත්තුවකට ඉල්ලීම් ගණන සකසන අතර අනෙකුත් කාල කවුළු සඳහා නීති රඳවා ගනී. `--max-cost 5` සතිපතා සීමාව වෙනස් නොකර දෛනික USD සීමාව සක්රීය කරයි; `--max-cost 0` දෛනික සීමාව ඉවත් කර පවතින භාවිත-සීමා ටොගලය සහ සතිපතා සීමාව රඳවා ගනී. ඉවත් කර ඇති ප්රතිපත්ති ක්ෂේත්ර නොවෙනස්ව පවතී. අනුපාත වෙනස්කම් පළමුව වත්මන් ප්රතිපත්තිය කියවයි; එකම යතුරේ අනුපාත-සීමා අරාවට සමගාමී සංස්කරණ කිරීමෙන් වළකින්න.

ප්රතිපත්ති විධාන සත්යාපිත `GET`/`PATCH /api/keys/{id}` භාවිත කරන අතර සක්රිය සන්දර්භයට සහ ගෝලීය `--api-key` විකල්පයට අනුකූල වේ. JSON ප්රතිදානයේ ගබඩා කළ යතුර හෝ එහි ආවරණය කළ නිරූපණය නොමැතිව, ප්රතිපත්ති ක්ෂේත්ර පමණක් අඩංගු වේ. inference සඳහා පමණක් වූ අක්තපත්රයකට කළමනාකරණ වෙනස්කම් අනුමත කළ නොහැක. 401/403 එකක් සඳහා කළමනාකරණ අක්තපත්රය සහ සන්දර්භය පරීක්ෂා කිරීම අවශ්ය වේ; එය දේශීය CLI ටෝකන හෝ salt අසමත් වීමක් තහවුරු නොකරයි. වෙනම දේශීය සත්යාපන ගිවිසුම සඳහා [CLI ටෝකනය](../security/CLI_TOKEN.md) බලන්න.
