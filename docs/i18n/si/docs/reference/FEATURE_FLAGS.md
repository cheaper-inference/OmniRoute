## විශේෂාංග ෆ්ලෑග් යනු මොනවාද

විශේෂාංග ෆ්ලෑගයක් යනු ධාවනකාලයේදී අගය වෙනස් කර දත්ත සමුදායේ සුරැකිය හැකි,
ක්රියාවලිය නැවත යෙදවීමක් අවශ්ය නොවන, නමක් සහිත ටොගලයකි (boolean හෝ enum).
සෑම ෆ්ලෑගයක්ම `key`, `label`, `description`, `category`, `defaultValue`,
`type`, සහ `requiresRestart` ඉඟියක් සහිත `FeatureFlagDefinition` එකකින් විස්තර කෙරේ.

### නිරාකරණ අනුපිළිවෙළ

ෆ්ලෑගයක **බලපැවැත්වෙන අගය**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) මඟින් පහත
ප්රමුඛතා අනුපිළිවෙළට අනුව නිරාකරණය කෙරේ (ඉහළම ප්රමුඛතාව ජය ගනී):

1. **DB අතික්රමණය** — `feature_flags` නාම අවකාශය යටතේ `key_value` වගුවේ
   ගබඩා කර ඇති අගයක් (උපකරණ පුවරුව හෝ REST API එක හරහා සකසා ඇත).
2. **පරිසර විචල්යය** — සකසා ඇති සහ හිස් නොවන විට `process.env[<KEY>]`.
3. **අර්ථ දැක්වීමේ පෙරනිමිය** — `featureFlagDefinitions.ts` හි `defaultValue`.

boolean ෆ්ලෑගයක බලපැවැත්වෙන අගය `"true"`, `"1"`, හෝ `"yes"` වන විට එය
**සක්රීය** ලෙස සැලකේ (`isFeatureFlagEnabled()` බලන්න).

> [!NOTE]
> බොහෝ ෆ්ලෑග් සඳහා [`ENVIRONMENT.md`](./ENVIRONMENT.md) හි ලේඛනගත කර ඇති
> **එම නමින්ම** යුත් ගැළපෙන පරිසර විචල්යයක් ද ඇත. ෆ්ලෑගයේ DB අතික්රමණයට
> එම පරිසර විචල්යයට වඩා ප්රමුඛතාව ලැබේ. `requiresRestart: true` සහිත
> ෆ්ලෑගයක් වහාම සුරැකෙන නමුත් එය නැවත කියවනු ලබන්නේ ක්රියාවලිය ආරම්භ වන
> අවස්ථාවේදී පමණි — එය ටොගල් කිරීමෙන් උපකරණ පුවරුවේ **"සේවාදායකය නැවත අරඹන්න"**
> බැනරයක් දිස් වේ.

### උපකරණ පුවරුව

**උපකරණ පුවරුව → සැකසුම් → විශේෂාංග ධජ**
(`/dashboard/settings/feature-flags`) වෙත යන්න. ජාලකය
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
පහත දෑ සඳහා සහාය දක්වයි:

- යතුර හෝ විස්තරය අනුව **සෙවීම**, සහ ප්රවර්ගය අනුව **පෙරීම** (කෘත්රිම
  **නැවත ආරම්භ කිරීම අවශ්යයි** දසුනක් ද ඇතුළුව).
- boolean ධජ සඳහා **ටොගලයක්** සහ enum ධජ සඳහා **පතන ලැයිස්තුවක්**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- එක් එක් ධජය සඳහා — `DB`, `ENV`, හෝ `DEF` — ඵලදායී අගය පැමිණියේ කොතැනින්දැයි
  පෙන්වන **මූලාශ්ර ලාංඡනයක්**.
- අතික්රමණය ඉවත් කිරීමට **යළි සකසන්න** බොත්තමක් (`DB` මූලාශ්ර කරගත් ධජ සඳහා
  පමණක් පෙන්වයි), සහ පහළින් **සියලු අතික්රමණ යළි සකසන්න** බොත්තමක්.
- `requiresRestart` ධජයක් වෙනස් කළ විට **සේවාදායකය නැවත ආරම්භ කරන්න** බැනරයක්.

`OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`, `OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS`,
`MITM_DISABLE_TLS_VERIFY`, `OMNIROUTE_MCP_ENFORCE_SCOPES` සහ
`SKILLS_SANDBOX_NETWORK_ENABLED` (`protectedFeatureFlags.ts` හි
`isProtectedFeatureFlag()`). ඒවායින් එකක් මත `PUT` ක්රියාවක් සහ ඒවායින් එකකට

සහිත `oma_` ප්රවේශ ටෝකනයක්, නැතහොත් loopback වෙතින් යවන CLI ටෝකනය හෝ
අභ්යන්තර-සේවා ටෝකනය අවශ්ය වේ. එම කට්ටලය පිවිසීම සක්රියව ඇති අවස්ථාවට වඩා

තනි අතික්රමණයක් සකසන්න හෝ ඉවත් කරන්න. ඉල්ලීම් අන්තර්ගතය:
`{ key: string; value?: string }`.
`value` අත්හැරීමෙන් අතික්රමණය ඉවත් වේ (env / පෙරනිමි අගය ප්රතිසාධනය කරමින්).

```bash
# DB අතික්රමණයක් සකසන්න
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# අතික්රමණය ඉවත් කරන්න ("value" නොමැතිව)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

ප්රතිචාරය නව `effectiveValue`/`source`, `previousValue`/
`previousSource`, සහ `requiresRestart` නැවත ප්රතිරාවය කරයි. නොදන්නා යතුරු සහ
පරාසයෙන් පිටත enum අගයන් `400` සමඟ ප්රතික්ෂේප කෙරේ.

#### `DELETE /api/settings/feature-flags`

සියලුම DB අතික්රමණ එකවර ඉවත් කර, සෑම ධජයක්ම එහි env / පෙරනිමි අගයට
ප්රතිසාධනය කරයි. `{ cleared: <count>, message: "..." }` ආපසු ලබා දෙයි.

> [!NOTE]
> `requiresRestart: true` සහිත ධජ බලපැවැත්වෙන්නේ ක්රියාවලිය නැවත පූරණය කිරීමෙන්
> පසුව පමණි.
> උපකරණ පුවරුවේ නැවත ආරම්භ කිරීමේ ප්රවාහය `POST /api/restart` අමතා, අනතුරුව
> සේවාදායකය නැවත ක්රියාත්මක වන තෙක් `GET /api/health/ping` විමසයි.

## හදිසි අයවැය විකල්ප මාර්ගය

`OMNIROUTE_EMERGENCY_FALLBACK` (`runtime` ප්රවර්ගය, පෙරනිමිය `true`) මඟින්
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts) හි
හදිසි නොමිලේ විකල්ප මාර්ගය පාලනය කරයි.
එය සක්රීය කර ඇති විට, තම අයවැය අවසන් වන ඉල්ලීම් සම්පූර්ණයෙන්ම අසාර්ථක වීම වෙනුවට නොමිලේ විකල්ප
සපයන්නෙකු/මාදිලියක් වෙත යොමු කෙරේ. මෙම හැසිරීම අක්රීය කර අයවැය අවසන් වූ ඉල්ලීම්
අසාර්ථක වීමට ඉඩ දීම සඳහා, උපකරණ පුවරුවේ ටොගලය, DB අතික්රමණයක්, හෝ
`OMNIROUTE_EMERGENCY_FALLBACK` පරිසර විචල්යය හරහා එය `false` (හෝ `0`) ලෙස සකසන්න.
(PR #3741 / #3752 හි උපකරණ පුවරු ටොගලයක් ලෙස ඉදිරිපත් කර ඇත.)

මෙම විකල්ප මාර්ගය මඟින් සපයන ප්රතිචාරයක
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` අඩංගු වන බැවින්,
සේවාලාභියෙකුට තම ඉල්ලීම සමඟ `X-OmniRoute-Provider` සසඳා වෙනස්කම් සෙවීමකින් තොරව එය නැවත යොමු කර ඇති බව හඳුනාගත හැක.
අනෙකුත් සෑම ප්රතිචාරයකම මෙම ශීර්ෂකය නොපවතී.
