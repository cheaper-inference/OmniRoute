## කතාබස් සම්පූර්ණ කිරීම්

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### අභිරුචි ශීර්ෂක

| ශීර්ෂකය                  | දිශාව     | විස්තරය                                                                                                                                                                                                                    |
| ------------------------ | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | ඉල්ලීම    | හැඹිලිය මඟහැරීමට `true` ලෙස සකසන්න                                                                                                                                                                                         |
| `x-omniroute-no-memory`  | ඉල්ලීම    | මෙම ඉල්ලීම සඳහා මතකය + කුසලතා ඇතුළත් කිරීම මඟහැරීමට `true` ලෙස සකසන්න (හැඹිලිය භාවිත නොකිරීම පිළිබිඹු කරයි; එක් එක් ඇමතුමට අදාළ ටෝකන/පිරිවැය අතිරේකය වළක්වයි)                                                              |
| `X-OmniRoute-Progress`   | ඉල්ලීම    | ප්රගති සිදුවීම් සඳහා `true` ලෙස සකසන්න                                                                                                                                                                                     |

#### එක් එක් ඉල්ලීම සඳහා ගිණුමක් pin කිරීම

සපයන්නෙකුට සම්බන්ධතා කිහිපයක් (ගිණුම් හෝ keys) ඇති විට, OmniRoute සාමාන්යයෙන් එහි
ගිණුම්-තේරීමේ ක්රමෝපාය හරහා එකක් තෝරා ගනී. ඒ වෙනුවට, ඉල්ලීමකට
`x-omniroute-connection` header එක භාවිතයෙන් නිශ්චිත සම්බන්ධතාවක් pin කළ හැක:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **id එක සොයාගත හැකි ස්ථානය.** dashboard එකේ සපයන්නාගේ පිටුව විවෘත කර
  (**Dashboard → Providers → <provider>**) සම්බන්ධතා පේළියක ඇති `xxxxxxxx…` id chip එක ක්ලික්
  කරන්න — එවිට සම්පූර්ණ connection id එක පිටපත් වේ.
- **එය පිළිපදින ඉල්ලීම්.** `/v1/chat/completions`, `/v1/messages` සහ
  `/v1/responses` සඳහා වන තනි-model ඉල්ලීම් (`provider/model`). Combos විසින් මෙම header එක නොසලකා හරියි: ඒ වෙනුවට
  එක් එක් combo පියවර සඳහා, එම පියවරේම සම්බන්ධතාව හරහා ගිණුමක් pin කරන්න.
- **මෙම pin කිරීම අභිරුචියක් නොව දැඩි නියමයකි.** Pin කළ සම්බන්ධතාව පමණක් භාවිත වේ.
  ඉල්ලීම තුළ සිදුවන අසාර්ථකත්වයක් ගිණුමේ cooldown එක වාර්තා කරන නමුත්, එම සපයන්නාගේ
  වෙනත් ගිණුමකට මාරු **නොවේ**.
- **Cooldown සහ quota මඟින් pin එක නිදහස් කරයි.** Pin කළ සම්බන්ධතාව cooldown තත්ත්වයේ පවතින විට,
  quota අවසන් වී ඇති විට, හෝ quota policy එකක් මඟින් අවහිර කර ඇති විට, පසුව ලැබෙන ඉල්ලීම් pin නොකළ traffic මෙන්ම
  සපයන්නාගේ වෙනත් සම්බන්ධතා වෙත fallback වේ.
- **නොදන්නා හෝ අක්රීය කළ ids අසාර්ථක වේ.** සපයන්නාගේ සක්රීය pool එකේ නොමැති id එකක් (මකා දැමූ,
  අක්රීය කළ, හෝ වෙනත් සපයන්නෙකුට අයත් එකක්) සුදුසු ගිණුමක් ඉතිරි නොකරන බැවින්, වෙනත් තැනකට
  නිහඬව route කිරීම වෙනුවට ඉල්ලීම අසාර්ථක වේ.

Claude Code විසින් අභිරුචි headers `ANTHROPIC_CUSTOM_HEADERS` හරහා යවයි. එය `~/.claude/settings.json` හි
`env` block එක තුළ තබන්න, නැතහොත් එක් එක් project එක සඳහා වෙනස් ගිණුමක් pin කිරීමට project-level
`.claude/settings.json` එකක තබන්න:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

මූලාශ්රය: `src/sse/handlers/chat.ts` (header කියවීම), `src/sse/services/auth.ts` සහ
`src/sse/services/sessionAffinityPin.ts` (pin එක නිදහස් කිරීම සහ pool එකේ නොමැතිදැයි පරීක්ෂා කිරීම).

> **පිරිවැය telemetry headers:** streaming නොවන සාර්ථක ප්රතිචාරවල `X-OmniRoute-*` පිරිවැය-telemetry කට්ටලයද අඩංගු වේ — `X-OmniRoute-Response-Cost` (USD, ස්ථාවර දශමස්ථාන 10ක්; නොමිලේ/මිල නියම නොකළ ඒවා සඳහා `0.0000000000`), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, සහ `X-OmniRoute-Fallback-Attempts` (> 0 වූ විට පමණි), ඊට අමතරව `X-OmniRoute-Request-Id` සහ `X-OmniRoute-Version`. මේවා chat completions, `/v1/responses`, `/v1/messages`, **සහ media endpoints** මඟින් නිකුත් කරනු ලැබේ — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations`, සහ `/v1/moderations` (පිරිවැය සැමවිටම `0`). මිලකරණය තිබෙන විට media පිරිවැය එක් එක් modality එක අනුව (රූපයකට, තත්පරයකට, අක්ෂරයකට, search-unit එකකට) ගණනය කරන අතර, එසේ නොමැති නම් `0` වේ (fail-open).

> **Cache-hit පිරිවැය අර්ථ නිරූපණය:** semantic-cache HIT එකකදී (`X-OmniRoute-Cache-Hit: true`) upstream call එකක් සිදු නොවන බැවින්, `X-OmniRoute-Response-Cost` යනු `0.0000000000` වේ (එම hit එක සපයන විට ඇතිවන **වර්ධක** පිරිවැය). මුල්/සිදුවීමට ඉඩ තිබූ පිරිවැය `X-OmniRoute-Cost-Saved` තුළ වෙනම වාර්තා කෙරේ. Billing භාවිත කරන්නන් `X-OmniRoute-Response-Cost` එකතු කළ යුතුය (hits සඳහා පිරිවැයක් නොමැත); cache analytics සඳහා `X-OmniRoute-Cost-Saved` සමස්ත කළ හැක.

## විශේෂ කළමනාකරණ සැසි බදු

විශේෂ කළමනාකරණ සැසි බදු දීම යනු තෝරා භාවිත කළ හැකි, සේවාලාභියාගෙන් ස්වාධීන මාර්ගගත කිරීමේ ගිවිසුමකි: එක් සක්රිය හිමිකරුවෙකු
සුදුසු OmniRoute සම්බන්ධතාවක් රඳවා ගනී. එය ආකෘතියක් බදු නොදෙයි, OAuth අවශ්ය නොකරයි, නිශ්චිත
සේවාලාභියෙකු හඳුනා නොගනී, හෝ නිශ්චිත සැපයුම්කරුවෙකු අවශ්ය නොකරයි.

සත්යාපනය කරන API යතුරට `lease:exclusive` විෂය පථය සහ පැහැදිලිව දක්වා ඇති හිස් නොවන
`allowedConnections` ලැයිස්තුවක් තිබිය යුතුය. යතුර සෑදීමේදී සහ අර්ධ යාවත්කාලීනවලදී දත්ත සමුදා විකරණ සීමාව
මෙම ක්ෂේත්ර දෙකම එකට බලාත්මක කරයි.

`generation` අගය හෙළි කරයි, නමුත් තෝරාගත් සම්බන්ධතාව හෝ අක්තපත්ර කිසි විටෙක හෙළි නොකරයි. අලුත් කිරීම සහ මුදාහැරීම සඳහා
JSON අන්තර්ගතය තුළ generation අගය සපයයි:

සක්රිය generation අගය මඟින් ආරක්ෂිතව සීමා කර ඇත. `displayName` යනු හිස් ඉඩ කපාහැර සකස් කළ
සම්බන්ධතා නාමය පමණි; ආරක්ෂිතව සකස් කළ නාමයක් නොමැති විට එය `null` වේ. OmniRoute කිසි විටෙක
විද්යුත් තැපැල් ලිපිනයක් හෝ ජනනය කළ ගිණුම් අනන්යතාවක් ආදේශ නොකරයි. සැපයුම්කරුගේ අගය සංවේදී නොවන දර්ශන ලේබලයක් වන අතර කිසි විටෙක
ජනනය කළ අනුකූල-සැපයුම්කරු හඳුනාගැනීමක් නොවේ. අක්තපත්ර, ටෝකන, කුකීස්, අමු සම්බන්ධතා හෝ API
යතුරු id, හිමිකරු hash, සීමාකරණ රහස්, සහ අභ්යන්තර මාර්ගගත කිරීමේ දත්ත බැහැර කර ඇත.

වැරදි යතුර, වැරදි හිමිකරු, යල්පැන ගිය generation අගය, නොමැති, කල් ඉකුත් වූ, මුදාහැරුණු සහ අවලංගු කළ සෙවීම් සියල්ල
සම්බන්ධතා පාරදත්ත නොමැතිව එකම `409 LEASE_FENCE_STALE` දෝෂය ආපසු ලබා දෙයි. ධාරිතාව සඳහා රැඳී සිටීමේ ප්රතිචාරය ලැබූ සේවාලාභියෙකුට පරීක්ෂා කිරීමට සක්රිය බැඳීමක් නොමැත. මාර්ගගත කිරීම සක්රිය බද්දක් සංක්රමණය කරන විට,
එම generation අගයම වලංගුව පවතින අතර තත්ත්වය පැරණි බැඳීම නොව නව බැඳීම පරමාණුකව ආපසු ලබා දෙයි.
අත්පත් කරගැනීම, අලුත් කිරීම, මුදාහැරීම සහ රැඳී සිටීමේ ප්රතිචාර ඒවායේ පෙර හැඩයන් රඳවාගන්නා බැවින් පවතින සේවාලාභීන්
වෙනස් නොවේ.

සැපයුම්කරු ගිණුම් පාරදත්ත නිරූපණය නොකරයි; පසුකාලීන සේවාලාභී අනුකලනයක් මෙම ක්රියාව කැඳවා


සෑම සහාය දක්වන upstream උත්සාහයකටම වහාම පෙර නිශ්චිත හිමිකරු, generation අගය, සක්රිය සම්බන්ධතාව, සහ සත්යාපිත API යතුර
ආරක්ෂිතව සීමා කෙරේ. වෙනත් යතුරක් සමඟ හිමිකරු සහ generation අගය නැවත භාවිත කිරීම, එම යතුර එකම සම්බන්ධතාවට ඉඩ දුන්නද
අසාර්ථක වේ. අමු හිමිකරු අගයන් ස්ථිරව ගබඩා කිරීම, ලොග් කිරීම, ඉල්ලීම් snapshot තුළ රඳවාගැනීම, හෝ upstream වෙත යොමු කිරීම සිදු නොවේ.

තාවකාලික තරගකාරීත්වය `Retry-After` සමඟ HTTP `429` සහ පහත දෑ ආපසු ලබා දෙයි:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

මෙම ප්රතිචාරයෙන් අදහස් වන්නේ සාමාන්ය සුදුසු කට්ටලය හිස් නොවූ අතර සෑම නිදහස් අපේක්ෂකයෙකුම
වෙනත් පාර්ශ්වයක සක්රිය බද්දක් මඟින් රඳවාගෙන තිබූ බව පමණි. සහාය නොදක්වන ආකෘති/සැපයුම්කරුවන්, ප්රතිපත්ති නොගැළපීම, cooldown, quota,
සෞඛ්යය, සහ අනෙකුත් සාමාන්ය සුදුසුකම් අසාර්ථකවීම් ඒවායේ පවතින OmniRoute ප්රතිචාර රඳවා ගනී.

### `x-omniroute-compression`

සම්පීඩන සැලැස්ම සඳහා එක් එක් ඉල්ලීම අනුව අභිබවා යන සැකසුම. ඉහළම ප්රමුඛතාවය — routing-combo
අභිබවා යාම, සක්රිය profile, auto-trigger, සහ පැනලයේ පෙරනිමිය ඉක්මවා ක්රියා කරයි. අගයන්:

| අගය           | බලපෑම                                                                                                               |
| ------------- | ------------------------------------------------------------------------------------------------------------------- |
| `off`         | මෙම ඉල්ලීම සඳහා සම්පීඩනයක් නොමැත.                                                                                   |
| `default`     | පැනලයෙන් ව්යුත්පන්න වූ පෙරනිමි profile එක (සක්රිය profile එක නොසලකා හරියි). තොරතුරු අහිමි කරන engines අක්රියව තබයි. |
| `safe`        | අනුපිටපත් ඉවත් කිරීම සහ හිස් ඉඩ හැකිලීම පමණි.                                                                       |
| `allow-lossy` | සාරාංශ සහ style නැවත ලිවීම් ඇතුළුව, මෙම ඉල්ලීම සඳහා operator සැලැස්ම තබාගනී.                                        |
| `engine:<id>` | සක්රීය කර ඇති විට තනි engine එකක්, උදා. `engine:rtk`. එම engine සඳහා එක් එක් ඉල්ලීම අනුව තෝරාගැනීමකි.               |
| `<combo>`     | නමින් හඳුනාගන්නා නම් කළ combo එකක් (අකුරු ප්රමාණයට සංවේදී නොවේ), ඉන්පසු id අනුව හඳුනාගනී.                           |

සටහන්:

- නොදන්නා අගයන් නොසලකා හැරේ (ඉල්ලීම කිසි විටෙක ප්රතික්ෂේප නොවේ); නිරාකරණය සාමාන්ය operator ප්රමුඛතා අනුපිළිවෙළ වෙත යොමු වේ.
- combos කිහිපයකට එකම නම තිබේ නම්, නිශ්චිතව තීරණය කළ හැකි ගැළපීමක් සඳහා combo **id** එක ලබා දෙන්න.
- නම `off` හෝ `default` වන combo එකක් නමින් තෝරාගත නොහැක (එම මූලපද පළමුව අර්ථකථනය කෙරේ); එවැනි combo එකක් එහි id එකෙන් යොමු කරන්න.
- ප්රධාන සම්පීඩන ස්විචය දැඩි බාධකයකි: සම්පීඩනය සමස්ත පද්ධතිය පුරා අක්රිය කර ඇති විට, මෙම ශීර්ෂයට එය සක්රීය කළ නොහැක.

යෙදූ සැලැස්ම ප්රතිචාර ශීර්ෂය තුළ නැවත ලබා දෙයි:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

මෙහි `<source>` යනු `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, හෝ `off` යන ඒවායින් එකකි.

## Embeddings

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

ලබා ගත හැකි සපයන්නන්: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

නාමාවලි හැඳුනුම් `provider/model` ආකෘතියෙන් ඇත (උදාහරණය: `jina-ai/jina-embeddings-v5-omni-small`). රෙජිස්ට්රියේ දිස්වන සපයන්නා සඳහන් නොකළ Jina ආකෘති හැඳුනුම් ද (උදාහරණයක් ලෙස `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) නිරාකරණය වේ. Jina embed/rerank/classify/segment පළමුව උපකරණ පුවරුවේ `jina-ai` අක්තපත්ර භාවිත කරයි; උපකරණ පුවරුවේ යතුරක් නොමැති විට පමණක් `JINA_AI_API_KEY` පසුබැසි විකල්පයක් ලෙස භාවිත වේ. `jina-reader` කාඩ්පත Reader / `r.jina.ai` සඳහා පමණක් වන අතර (`POST /v1/web/fetch`), එය කිසිවිටෙක embeddings හෝ rerank සේවා සපයන්නේ නැත.

බහුමාධ්ය සහාය දක්වන බව සඳහන් කරන රෙජිස්ට්රි ආකෘති, සපයන්නාගෙන් ස්වාධීන ව්යුහගත
අයිතම 32ක් දක්වා ද පිළිගනී. මාධ්ය අයිතම වර්ග වන්නේ `text`, `image`, `audio`, `video`, සහ `document` ය. ඒවායේ මාධ්ය `source`
යනු `{"type":"url","url":"https://..."}` හෝ
`{"type":"base64","data":"...","media_type":"..."}` වේ.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
සහ පවුල් අන්වර්ථ නාමය `jina-ai/jina-embeddings-v5-omni` → omni-small) Jina හි ස්වදේශීය
EmbeddingsV5Request ලේඛන ද පිළිගෙන, ඒවා `https://api.jina.ai/v1/embeddings` වෙත **වෙනස් නොකරම යොමු කරයි**:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

ස්වදේශීය `{ image | audio | video | pdf }` අගයන් පොදු HTTPS URL එකක්, `data:` URI එකක්, හෝ අමු
base64 විය හැක. OmniRoute එම වස්තු තන්තු බවට පත් නොකරන අතර ස්වදේශීය රූප URL ලබාගැනීම ද නොකරයි — Jina විසින්ම
පොදු මාධ්ය ලබාගනී. අතිරේක Jina ක්ෂේත්ර (`task`, `normalized`, `truncate`, `embedding_type`)
යොමු කරනු ලැබේ. පෙළ-පමණක් වන Jina SKU තවමත් පෙළ නොවන ලේඛන ප්රතික්ෂේප කරයි.

ආරක්ෂාව සහ ප්රවාහන සීමා:

- දුරස්ථ මාධ්ය URL පොදු HTTPS විය යුතුය. සම්මත `{type,source:url}` අයිතම
  සේවාදායක පාර්ශ්වයෙන් ලබාගෙන (යළි-යොමු නැවත වලංගු කිරීම, කාල සීමාව, ප්රමාණ සීමා, පොදු DNS, සම්බන්ධතා ස්ථිර කිරීම)
  සපයන්නා ඇමතීමට පෙර පේළිගත කෙරේ. Jina-ස්වදේශීය `{image:"https://..."}` අයිතම
  එම පොදු-HTTPS පරීක්ෂාවෙන් පසු එලෙසම යොමු කෙරේ; Jina විසින් URL එක ලබාගනී.
- පේළිගත base64 මාධ්ය එක් අයිතමයකට විකේතනය කළ 8 MiBකට සහ සමස්ත ඉල්ලීම පුරා විකේතනය කළ 16 MiBකට සීමා වේ.

සපයන්නාට අනුව පරිවර්තනය (සම්මත අයිතම කිසිවිටෙක වෙනස් නොකර යොමු නොකෙරේ):

- Jina බහුමාධ්ය ආකෘති: සෑම ඉහළ-මට්ටමේ අයිතමයක්ම එක් මාධ්යතා-යතුරුගත වස්තුවක් බවට පත්වේ
  (`text` / `image` / `audio` / `video` / `pdf`), පේළිගත මාධ්ය සඳහා data URI භාවිත කරමින්; එක්
  ඉහළ-මට්ටමේ අයිතමයකට එක් දෛශිකයක්.
- Gemini Embedding 2 පවුල: එක් ඉහළ-මට්ටමේ අරාවක් `content.parts` (`text` හෝ `inline_data`) සහිත තනි ස්වදේශීය
  `models/{model}:embedContent` ඉල්ලීමක් බවට පත්වේ.
- llama.cpp (`llama-cpp/<model>`, දේශීය සේවාදායකය පූරණය කළ ඕනෑම ආකෘතියක්): සම්මත `text` අයිතම
  සරල තන්තු බවට පත්වන අතර, `image` / `audio` / `video` අයිතම එක් එක්
  `{"content": [part]}` වස්තුවක් බවට පත්වේ. මෙහිදී පේළිගත දත්ත සමඟ llama-server හි කතාබස් අන්තර්ගත කොටස් (`image_url`,
  `input_audio`, `wav` / `mp3` / `flac` ආකෘති සමඟ, `input_video`) භාවිත වේ; එක්
  ඉහළ-මට්ටමේ අයිතමයකට එක් දෛශිකයක්. සේවාදායකය `--embedding --mmproj …` සමඟ ධාවනය විය යුතුය; ප්රක්ෂේපකයක් නොමැතිව එය
  මාධ්ය ස්වයංක්රීයව ප්රතික්ෂේප කරයි. `document` සඳහා සහාය නොදක්වයි.
- පැහැදිලි මාධ්යතා පාරදත්ත නොමැති නොදන්නා/ගතික ආකෘති, HTTP 400 සමඟ ව්යුහගත ආදානය ප්රතික්ෂේප කරයි.

**එක් එක් ඉල්ලීම සඳහා** එය අභිබවා සැකසිය හැක — අනෙක් සියලු දෙනා සඳහා server-wide
සැකසුම වෙනස් නොකර පිරිසිදු ලැයිස්තුවක් අවශ්ය සේවාලාභියෙකුට මෙය ප්රයෝජනවත් වේ:

```bash
GET /v1/models?prefix=alias        # මාදිලියකට එක් id එකක් — කෙටි අන්වර්ථ උපසර්ගය
GET /v1/models?prefix=dual         # ආකාර දෙකම (server පෙරනිමිය)
GET /v1/models?prefix=canonical    # සම්පූර්ණ provider-id උපසර්ගය පමණි
```

| ප්රකාරය     | නිකුත් කරන්නේ                                            | සටහන්                                                                                                                                                                                                |
| ----------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **සහ** `claude/claude-sonnet-4-6` | **පෙරනිමිය.** ids දෙකම එකම මාදිලියට route වේ; ආකාර දෙකෙන් එකක් hardcode කළ සේවාලාභී config දිගටම ක්රියා කරන ලෙස තබා ඇත. catalog එක ආසන්න වශයෙන් දෙගුණ කරයි.                                          |
| `alias`     | `cc/claude-sonnet-4-6`                                   | මාදිලියකට එක් ඇතුළත් කිරීමක්. වෙනස් අන්වර්ථයක් නොමැති සැපයුම්කරුවන් තවමත් ඔවුන්ගේ ඇතුළත් කිරීම නිකුත් කරන බැවින් කිසිවක් අහිමි නොවේ.                                                                 |
| `canonical` | `claude/claude-sonnet-4-6`                               | සම්පූර්ණ provider-id උපසර්ගය යටතේ මාදිලියකට එක් ඇතුළත් කිරීමක්. වෙනස් අන්වර්ථයක් නොමැති සැපයුම්කරුවන් (උදා. `antigravity/…`, `agy/…`) ද ඔවුන්ගේ තනි id එක මෙහි නිකුත් කරන බැවින් කිසිවක් අහිමි නොවේ. |

`dual`-ප්රකාර mirror එකක් query parameter එක නොමැතිවද හඳුනාගත හැක: එහි ප්රධාන id වෙත යොමු කරන `parent`
ක්ෂේත්රයක් අඩංගු වේ.

මාදිලි තේරීම්කාරකයක් render කරන සේවාලාභීන් `?prefix=alias` ඉල්ලා සිටිය යුතුය —
[OmniCopilot VS Code extension](../guides/VSCODE-COPILOT.md) කරන්නේද මෙයයි.

### Discovery පෙරහන් (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` තෝරා සක්රිය කළ හැකි discovery පෙරහන් පිළිගනී. ඒවා කිසිවක් නොමැතිව ප්රතිචාරය
වෙනස් නොවේ. ඒවා අමතන්නාට දැනටමත් පෙනෙන catalog එක සීමා කරයි (API-key අවසර පළමුව යෙදේ),
එමෙන්ම ඒවා OpenAI-ආකාරයේ `limit` / `after` පිටුකරණයට පෙර ක්රියාත්මක වේ:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # ලැයිස්තුගත සෑම හැකියාවක්ම true විය යුතුය
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # catalog `type`; එකක් නොමැති පේළි `chat` වේ
GET /v1/models?q=sonnet&limit=10                           # id හෝ නම මත අකුරු ප්රමාණය නොසලකා ගැළපීම
```

| පරාමිතිය      | අගයන්                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | ඍණ නොවන පූර්ණ සංඛ්යාවක්, `context_length` සමඟ සසඳනු ලැබේ                                            |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | අක්ෂර 1–200ක්                                                                                       |

නොදන්නා අගයක් හෝ ඍණ නොවන පූර්ණ සංඛ්යාවක් නොවන `min_context` අගයක් (උදාහරණයක් ලෙස `1.5`),
HTTP `400` ආපසු ලබා දෙන අතර පණිවිඩයේ වලංගු අගයන් ලැයිස්තුගත කරයි. ක්රියාත්මක කිරීම:
`src/app/api/v1/models/catalogFilters.ts`.

### ආකෘති කෙටි ලැයිස්තුව (`POST /v1/models/query`)

`POST /v1/models/query`, `GET /v1/models` සඳහා ඇති සත්යාපනය හා එක් එක් යතුරට අදාළ දෘශ්යතාවම භාවිත කරමින්,
එම නාමාවලියෙන්ම කෙටි, නියත ලැයිස්තුවක් ආපසු ලබා දෙයි:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

සෑම ක්ෂේත්රයක්ම විකල්ප වේ. `capabilities` සහ `exclude` සඳහා අරාවක් හෝ කොමාවලින් වෙන් කළ තන්තුවක් ලබා දිය හැක;
`max_output`, `max_output_tokens` සමඟ සසඳයි. ප්රතිඵල පළමුව `owned_by` අනුවත්, ඉන්පසු `id` අනුවත් අනුපිළිවෙළට සකසයි.
`limit` හි පෙරනිමි අගය `20` වන අතර `100` ඉක්මවන අගයන් `100` දක්වා සීමා කෙරේ. වලංගු නොවන JSON, නොදන්නා
ක්ෂේත්රයක් හෝ වලංගු නොවන අගයක් HTTP `400` ආපසු ලබා දෙයි.

### තනි තනිව සැඟවූ කතාබස් ආකෘති

එහි සපයන්නාගේ පිටුවේ **සැඟවූ** ලෙස සලකුණු කර ඇති ආකෘතියක් නාමාවලියෙන් ඉවත් කරන අතර එය පැහැදිලිව
ඉල්ලා සිටින විට HTTP `404` / `model_not_found` සමඟ ප්රතික්ෂේප කරයි. මෙම පරීක්ෂාව විසඳන ලද
සපයන්නා සහ ආකෘතිය භාවිත කරන අතර, එයට සපයන්නාගේ අන්වර්ථ නාම, අනුකූල-සපයන්නාගේ නෝඩ් උපසර්ග සහ
සම්බන්ධතා පෙරනිමිද ඇතුළත් වේ. සංයෝජනයක් සැඟවූ ඉලක්ක මඟ හැර දෘශ්ය සහෝදර ඉලක්කයක් භාවිත කළ හැක; ක්රියාත්මක කළ හැකි
ඉලක්කයක් ඉතිරිව නොමැති විට එය එම දෝෂ කේතයම ආපසු ලබා දෙයි. සැඟවීම ඉවත් කිරීම ඊළඟ
ඉල්ලීමේදී ක්රියාත්මක වේ. රූප සඳහා පමණක් වන දෘශ්යතා අභිබවා යෑම්, එකම ID සහිත කතාබස් ආකෘතිය සඟවන්නේ නැත.

මෙම තනි ආකෘති සැකසුම, පැහැදිලි යොමු කිරීම රඳවා ගනිමින් නාමාවලි
ප්රචාරණය සහ ස්වයංක්රීය-මාර්ගගත කිරීමේ අපේක්ෂකයන් පෙරහන් කරන

අවසර ස්වාධීනව දිගටම අදාළ වේ. පෙරනිමි නාමාවලි උපසර්ග ප්රකාරය `dual` ලෙසම පවතී.

### සිතීම්-රහිත ආකෘති ප්රභේද

සිතීමේ හැකියාව ඇති Claude ආකෘති සඳහා, `/v1/models` විසින් `claude-3-omniroute-no-thinking/` උපසර්ගය සහිත id එකක් ඇති **සිතීම්-රහිත** ප්රභේදයක්ද ප්රචාරණය කරයි:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

මෙම id එක තේරීමෙන් (උදාහරණයක් ලෙස, සැමවිටම `thinking` බ්ලොක් එකක් අමුණන Claude Code වින්යාසයකදී), තර්කනය යටපත් කර සැබෑ `<provider>/<model>` වෙත නැවත විසඳයි — `/v1/messages` මාර්ගයේ `thinking:{type:"disabled"}` භාවිතයෙන් හෝ `/v1/chat/completions` මාර්ගයේ `reasoning`/`reasoning_effort` ක්ෂේත්ර ඉවත් කිරීමෙන්. මෙම ප්රභේදය ලැයිස්තුගත කරන්නේ සිතීමට සහය දක්වන **සහ** `disabled` පිළිගන්නා Claude-පවුලේ ආකෘති සඳහා පමණි (එබැවින්, උදාහරණයක් ලෙස `disabled` ප්රතික්ෂේප කරන අනුවර්තනීය-පමණක් ආකෘති බැහැර කෙරේ). ක්රියාකරුවන්ට `ModelSpec.noThinkingAlias` හරහා එක් එක් ආකෘතිය සඳහා ප්රභේදය බලහත්කාරයෙන් සක්රිය හෝ අක්රිය කළ හැක.

## සැපයුම්කරු ප්ලගිනයේ මැනිෆෙස්ටය

```bash
GET /api/v1/provider-plugin-manifest
```

Bifrost, CLIProxyAPI සහ අනාගත sidecar රවුටර විසින් භාවිත කරන JSON-ආරක්ෂිත සැපයුම්කරු ප්ලගින මැනිෆෙස්ටය ආපසු ලබා දෙයි. ප්රතිචාරය TypeScript සැපයුම්කරු රෙජිස්ට්රියෙන් ජනනය කරන අතර OAuth සේවාලාභී රහස්, ධාවනකාල පරිසර විභේදනය, ක්රියාත්මක කිරීමේ ශ්රිත, ඉල්ලීම් ශීර්ෂ සහ ගිණුම් දත්ත හිතාමතාම බැහැර කරයි.

sidecar එකක් ක්රියාවලියෙන් පිටත ධාවනය වන විට සහ එයට
`open-sse/config/providerPluginManifestRegistry.ts` සෘජුව import කළ නොහැකි විට මෙම endpoint එක භාවිත කරන්න.

## ElevenLabs ශ්රව්ය ජනනය

ඔබේ ElevenLabs API යතුර සමඟ OmniRoute තුළ `elevenlabs` සැපයුම්කරු සම්බන්ධතාවක් වින්යාස කරන්න.
සේවාලාභීන් තම **OmniRoute** යතුරෙන් (`Authorization: Bearer $OMNIROUTE_API_KEY`) සත්යාපනය කරයි;
ගේට්වේ එක ගබඩා කළ සැපයුම්කරු යතුර `xi-api-key` ලෙස සපයයි. කිසි විටෙකත් ElevenLabs යතුරක්
ගේට්වේ bearer ටෝකනය ලෙස නොයවන්න.

| ක්රමය | මාර්ගය                      | ප්රතිචාරය                                   | API යතුරු endpoint ප්රවර්ගය |
| ----- | --------------------------- | ------------------------------------------- | --------------------------- |
| POST  | `/v1/sound-generation`      | ස්වදේශීය ශ්රව්ය බයිට්                       | `elevenlabs`                |
| POST  | `/v1/music`                 | ස්වදේශීය ශ්රව්ය බයිට්                       | `music`                     |
| POST  | `/v1/music/stream`          | ප්රවාහ ශ්රව්ය බයිට්                         | `music`                     |
| POST  | `/v1/music/detailed`        | ස්වදේශීය multipart ශ්රව්ය සහ සංයෝජන සැලැස්ම | `music`                     |
| POST  | `/v1/music/detailed/stream` | ස්වදේශීය SSE පාරදත්ත සහ ශ්රව්ය කොටස්        | `music`                     |
| POST  | `/v1/music/plan`            | JSON සංයෝජන සැලැස්ම                         | `music`                     |

මෙම endpoints දැනට පවතින `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` සහ `/v1/speech-to-text` මාර්ගවලට අනුපූරක වේ. `output_format` සහ `enable_logging` වැනි ස්වදේශීය JSON ක්ෂේත්ර
සහ විමසුම් පරාමිති නොවෙනස්ව තබා ගනී.
`/v1/music/detailed` ප්රතිචාර ඒවායේ multipart සීමා රඳවා ගනී; ඒවා multipart ලෙස විග්රහ කරන්න.
`/v1/music/detailed/stream` මඟින් සංයෝජන පාරදත්ත සහ
SSE සිදුවීම් තුළ base64 ශ්රව්ය කොටස් සහිත `text/event-stream` ආපසු ලබා දෙයි. මාර්ග හයම CORS preflight සඳහා සහාය දක්වයි.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# කෙටි ශබ්ද ප්රයෝගයක්. කාලසීමාව: තත්පර 0.5 සිට 30 දක්වා.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# සංගීත කාලසීමාව මිලි තත්පරවලින් ප්රකාශ කෙරේ: 3000 සිට 600000 දක්වා.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

වර්ධනාත්මක ශ්රව්ය බෙදාහැරීම සඳහා එකම JSON body එක සමඟ `/v1/music/stream` භාවිත කරන්න. සංයෝජනය
`prompt` හෝ `composition_plan` යන දෙකෙන් නිශ්චිතව එකක් පමණක් පිළිගනී; `/v1/music/plan` සඳහා `prompt`
අවශ්ය වන අතර විකල්පයක් ලෙස `source_composition_plan` පිළිගනී. සංයෝජන-සැලසුම් අනුවාද සහ සියුම්-සුසර කිරීමේ විකල්ප ElevenLabs වෙත ළඟා වන පරිදි ස්වදේශීය schema අමතර සැපයුම්කරු ක්ෂේත්ර රඳවා ගනී.

ඒකාබද්ධ `/v1/music/generations` endpoint එක `elevenlabs/music_v1`,
`elevenlabs/music_v2` සහ `elevenlabs/music_v2_5` ද පිළිගනී. සක්රිය ElevenLabs සම්බන්ධතාවක් සමඟ,
මෙම models සංගීත නාමාවලිය හරහා නිරාවරණය කෙරේ. මෙම endpoint එක
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}` ආපසු ලබා දෙයි. එහි `duration` ක්ෂේත්රය
තත්පරවලින් වන අතර `music_length_ms` වෙත අනුරූප වේ; පැහැදිලිව දක්වා ඇති `music_length_ms` එකකට ප්රමුඛත්වය ලැබේ.
`instrumental` යන්න `force_instrumental` වෙත අනුරූප වන අතර, ස්වදේශීය ක්ෂේත්රයට ප්රමුඛත්වය ලැබේ.
ප්රවාහනය සඳහා ස්වදේශීය streaming endpoints ද, සංයෝජන සැලැස්මකින් පමණක් මෙහෙයවන ඉල්ලීම් සඳහා ස්වදේශීය සංයෝජන endpoint එක ද භාවිත කරන්න.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

upstream ඇමතුමකට පෙර endpoint, model, අයවැය සහ සම්බන්ධතා සීමා අදාළ වේ. ස්වදේශීය
මාර්ග, සැලසුම් සීමාවක් සඳහා වන `402` සහ කෝටා සීමාවක් සඳහා වන `429` ඇතුළුව, upstream තත්ව කේත සහ දෝෂ body නොවෙනස්ව ආපසු ලබා දෙයි. පවතින විට `character-cost`, `song-id`, `request-id` සහ `retry-after`
ශීර්ෂ රඳවා ගනී. නොමිලේ ණය ශේෂයක් තිබීම සෑම
සංගීත model එකකටම, ප්රතිදාන ආකෘතියකටම හෝ API විශේෂාංගයකටම ප්රවේශය සහතික නොකරයි: එක් එක් ඉල්ලීම සඳහා හිමිකම ElevenLabs තීරණය කරයි.

`Authorization: Bearer ...` ඇමිණිය නොහැකි clients සඳහා, query-string අනුකූලතාව (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`) හෝ පහත ලේඛනගත කර ඇති කැප වූ `/api/v1/vscode/{token}/...` අන්ත ලක්ෂ්ය හරහා URL එක තුළ API keys ද OmniRoute පිළිගනී.

```bash
# නැවත ශ්රේණිගත කිරීම (cloud registry provider එකක්, හෝ "<prefix>/<model>" ලෙස OpenAI-අනුකූල provider node එකක්)
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Jina වර්ගීකරණය (Foundation API අක්තපත්ර)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Jina කොටස්කාරකය
POST /v1/segment     { "content": "...", "return_chunks": true }

# Jina සෙවීම (s.jina.ai; provider අන්වර්ථ නාම: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# අන්තර්ගත පාලනය
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — audio/mpeg (හෝ ඉල්ලා ඇති ආකෘතියේ) body එක ලබා දෙයි

# හඬක් හෝ OpenAI සම්මත හඬ නාමයක් (alloy, nova, …) "Adrian" බවට පත් වේ
```

> (උදා. `http://reranker:8080/v1` වැනි Docker/Compose සේවා නාමයක්; මේවා `HTTP(S)_PROXY`

| සපයන්නා | ඉහළ මට්ටමේ ක්ෂේත්ර                                                                                                                                                                                                                                                                                                                                                        | කූඩු කළා                                                                                                                                  |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Exa     | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (පැතලි ප්‍රාථමික), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                              | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` පෙරනිමි `{ text: true, highlights: true }` හරහා ඒකාබද්ධ විය |

සාමාන්‍ය ක්ෂේත්‍ර සැමවිටම ජය ගනී: `query`, `max_results`, `filters` (වසම්), `country` සහ `search_type` වෙතින් ව්‍යුත්පන්න වූ මාතෘකාව. Exa හි, `search_type: "news"` `category: "news"` තබා ගනී. Tavily `search_type: "finance"` (`topic: "finance"`) ද පිළිගනී.

ෆයර්ක්‍රෝල් සෙවුම් පිරිවැය වාර්තා කරන ලද ප්‍රතිඵල 10කින් ආරම්භ කරන ලද කොටසකට, වාරිකයකට ඩොලර් 0.002 (බැර 2) සහ ඇමතුමකට අවම වශයෙන් එක් වාරණ ( [ෆයර්ක්‍රෝල් බිල්පත්](https://docs.firecrawl.dev/billing) ): 11 ප්‍රතිඵල සඳහා ඩොලර් 0.004ක් වැය වේ.

(HTTP 429 සැමවිටම; Firecrawl/Tavily/TinyFish හි කෝටා-ආකාරයේ නොමිලේ මට්ටම් සඳහා 402/403 —

තත්ත්වය).

## WebSocket ප්රවාහනය

```bash
GET /v1/ws?handshake=1
```

WebSocket upgrade handshake එකක් වලංගු කර wire protocol උදාහරණ පණිවිඩ (`request`, `cancel`) ආපසු ලබා දෙයි. සැබෑ WS frames, Next.js route table එකෙන් පිටත ඇති බණ්ඩල් කළ WS server එක මඟින් හසුරුවනු ලැබේ.

**සත්යාපනය:** handshake අවස්ථාවේදී Bearer API යතුර.

```toml
model = "gpt-5.5"                 # මූලික id එක — "codex/gpt-5.5" නොවේ

env_key = "OMNIROUTE_API_KEY"             # OmniRoute API යතුර (Bearer) රඳවා ගනී
```

```bash
export OMNIROUTE_API_KEY=sk-...           # OmniRoute API යතුරක් (REQUIRE_API_KEY=false නම් ඕනෑම යතුරක්)
```

තෝරාගත් codex OAuth සම්බන්ධතාව වෙත tunnel කරයි. දේශීය
server එක සමඟ අන්තයේ සිට අන්තය දක්වා වලංගු කර ඇත: ChatGPT, `codex.rate_limits` + `response.created` ආපසු ලබා දී
completion එක stream කරයි.

## ස්වයං-සේවා භාවිතය (`/api/usage/om-usage`)

ඕනෑම API යතුරකට කළමනාකරණ සත්යාපනයකින් තොරව **තමන්ගේම** භාවිතය සහ කෝටා කියවිය හැක. යතුරු හිමියෙකුට තම වියදම පෙන්වීමට
සේවාලාභියෙකු (CLI, OmniCopilot පැනලය) භාවිත කරන අන්ත ලක්ෂ්යය මෙයයි.

```bash
# පෙළ ආකෘතිය (ඓතිහාසික ගිවිසුම — ටර්මිනලයක් සඳහා සරල පෙළ)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# ව්යුහගත ආකෘතිය — UI එකක් භාවිත කරන්නේ මෙයයි
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

යතුර සඳහා **`allowUsageCommand`** සක්රීය කර තිබිය යුතුය (පෙරනිමියෙන් අක්රීයයි — උපකරණ පුවරුවේ API-යතුරු
කළමනාකරු එක් එක් යතුර සඳහා එය මාරු කරයි). එය නොමැතිව අන්ත ලක්ෂ්යය `403` පිළිතුර ලබා දෙයි.

`?format=json` වෙනස්කම් හඳුනාගත හැකි ව්යුහයක් ආපසු ලබා දෙන බැවින්, කැඳවුම්කරුවෙකු කිසි විටෙකත්
ප්රතික්ෂේප කිරීමකින් දත්ත ක්ෂේත්රයක් කියවන්නේ නැත. සාර්ථක වූ විට:

```jsonc
{
  "allowed": true,
  // යතුර එක් එක් යතුරට අදාළ භාවිත සීමා (දෛනික/සතිපතා USD) තෝරාගෙන ඇති විට පමණක් පවතී:
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // තෝරාගත් සපයන්නාගේ කෝටා සැණරුව, හෝ තවම කිසිවක් හැඹිලිගත කර නොමැති විට null:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // සෑම සම්බන්ධතාවකම සැණරුව, එබැවින් UI එකකට සපයන්නන් කිහිපයක් පැත්තෙන් පැත්තට නිරූපණය කළ හැක:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

ප්රතික්ෂේප කළ විට (`401` වලංගු නොවන යතුර / `403` අවසර නැත), එම මාර්ගයම
`{ "allowed": false, "error": { "message": "…" } }` ආපසු ලබා දෙයි — පවතින නමුත් හිස් `personal`/`provider`
(යතුරට අවසර ඇත, තවම කිසිවක් දැනගෙන නැත) යනු ප්රතික්ෂේප කිරීමකට වඩා වෙනස් තත්ත්වයක් වන අතර, ඒවා වෙන්කර හඳුනාගන්නේ JSON ආකෘතිය
පමණි.

**සත්යාපනය:** `isValidApiKey` සමඟ වලංගු කරන ලද කැඳවුම්කරුගේම Bearer API යතුර — මෙය
කළමනාකරණ මතුපිට (`/api/keys/…`) _නොවේ_; එය තවදුරටත් `requireManagementAuth` පිටුපස පවතී.

### අමු සහ කඩඉමට ගැළපූ කෝටා ප්රතිශත

ප්රතිශත අතර වෙනස කැඳවුම්කරුවන් සැලකිල්ලට ගත යුතුය:

| අංගය                   | සරල-පෙළ ආකෘතිය (`/api/usage/om-usage` / `@@om-usage`)                                       | JSON ආකෘතිය (`?format=json`)                                                         |

| **මිනුම**              | **කඩඉමට ගැළපූ භාවිත කළ හැකි දීමනාව**: කඩඉම් සීමාවට ඉහළින් ඉතිරිව ඇති ධාරිතාව                | **අමු ඉහළ-ප්රවාහ කෝටාව**: ගැළපීම් නොකළ සපයන්නාගේ මිනුම                               |
| **කඩඉම් පරිමාණනය**     | ආරක්ෂිත සංචිතය `0% left` ලෙස දිස්වන පරිදි `effectiveRemainingPercent()` හරහා පරිමාණනය කර ඇත | කිසිවක් නැත (සපයන්නා වාර්තා කළ පරිදි අමු සැණරුම් අගයන්)                              |
| **සීමා දත්ත**          | පෙන්වන ප්රතිශතයට ඇතුළත් කර ඇත                                                               | එක් එක් සම්බන්ධතාව සඳහා `quotaWindowThresholds` තුළ ගබඩා කර ඇත (හෝ සේවාදායක පෙරනිමි) |

#### කඩඉම් ගැළපීමේ සූත්රය

ඉහළ-ප්රවාහ ධාරිතාව අවසන් වීම වැළැක්වීම සඳහා OmniRoute සක්රිය කෝටා කඩඉම් සඳහා සහය දක්වයි (සම්බන්ධතාවේ
`quotaWindowThresholds`, සපයන්නාගේ පෙරනිමි, හෝ ගෝලීය ප්රතිසාධන සැකසුම් හරහා වින්යාස කර ඇත). කෝටා කවුළුවක කඩඉම් සීමාවක්
(උදා., `cutoff = 25%`) සක්රීයව ඇති විට, පෙළ නිරූපකය ඉතිරි දීමනාව පහත පරිදි ගණනය කරයි:

- `remaining <= cutoff` නම්: `0%` ආපසු ලබා දෙයි.
- `remaining > cutoff` නම්: `((remaining - cutoff) / (100 - cutoff)) * 100` ආපසු ලබා දෙයි.

ආකෘතිගත කළ පෙළ ප්රතිදානය මෙය ආසන්නතම පූර්ණ සංඛ්යාවට වට කරයි (`Math.round(...)`).

#### නිදර්ශනාත්මක උදාහරණය

**60% අමු භාවිතයක්** (එබැවින් **40% අමු ඉතිරි කෝටාවක්**) සහ වින්යාස කළ
**25% ඉතිරි-කෝටා කඩඉම්** සීමාවක් සහිත සපයන්නාගේ කවුළුවක් සලකා බලන්න:

| නිරූපණය                       | ගණනය                                               | ඉතිරිය  |         ව්යංගයෙන් භාවිත කළ ප්රමාණය          |
| :---------------------------- | :------------------------------------------------- | :-----: | :-----------------------------------------: |
| **අමු JSON (`?format=json`)** | ඉහළ-ප්රවාහ සැණරුව (`quotas[window]`)               | **40%** |                   **60%**                   |
| **පෙළ ආකෘතිය (`NN% left`)**   | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (`100 - remaining` ගණනය කරන්නේ නම්) |

- **පෙළෙහි 20% ක් ඉතිරි බව පෙන්වන්නේ ඇයි:** ගිණුමේ භෞතික කෝටාවෙන් ඉතිරි 40% අතරින්, 25% ක්
  කඩඉම් ප්රතිපත්තිය මඟින් වෙන් කර ඇත. රවුටරය මෙම සම්බන්ධතාව වෙත මාර්ගගත කිරීම නවත්වන තෙක්, කැඳවුම්කරුට භාවිත කළ හැකි 75% ක ඉඩෙන්
  ඉතිරිව ඇත්තේ 15% ක් පමණි. මාර්ගගත කිරීම නතර වන මොහොතේම සම්බන්ධතාව අවසන් වී ඇති බවට (`0% left`) සංඥා කිරීම
  පරිමාණනය මඟින් සහතික කරයි.
- **JSON අමු අගයන් රඳවා ගන්නේ ඇයි:** JSON ගෙවුම නිශ්චිත සපයන්නාගේ සැණරුව (`UsageSnapshot`)
  ආපසු ලබා දෙන බැවින්, බාහිර මෙවලම්වලට සත්ය ඉහළ-ප්රවාහ භාවිතය සහ සම්බන්ධතා-මට්ටමේ
  `quotaWindowThresholds` වෙත සේවාදායක-පාර්ශ්වීය තොරතුරු-හානිකර පරිමාණනයකින් තොරව ප්රවේශ විය හැක.

#### පාරිභෝගික සංක්රමණ මාර්ගෝපදේශය

බාහිර ඒකාබද්ධ කිරීමක් (සංස්කාරක ප්ලගිනයක් හෝ නියෝජිත දිගුවක් වැනි) මීට පෙර පෙළ
අන්ත ලක්ෂ්යය (`NN% left`) වෙතින් දත්ත උකහාගෙන භාවිත කළ ප්රතිශතය `100 - NN` ලෙස ගණනය කළේ නම්, `?format=json` වෙත සංක්රමණය වීමෙන් අදහස් වන්නේ:

- අමු JSON අගයන් කියවීමෙන් **සැබෑ ඉහළ-මට්ටමේ පරිභෝජනය** පිළිබිඹු වනු ඇත (ඉහත උදාහරණයේ 60%ක් භාවිත කර ඇත).
- ඒකාබද්ධ කිරීම පෙළ අන්ත ලක්ෂ්යයේ භාවිත කළ හැකි දීමනා අර්ථවිචාරය සුරැකීමට කැමති නම්, සම්බන්ධතා-මට්ටමේ අභිබැවීම් සඳහා `quotaWindowThresholds` භාවිත කරමින්
  ඵලදායී ඉතිරි ප්රමාණයේ සූත්රය සේවාලාභී පාර්ශ්වයේදී ඇගයීමට එයට හැකිය.

### ප්රමාදයට ඇති බලපෑම

අර්ථාන්විත හැඹිලි HIT එකක් ප්රතිචාරය **ඉහළ ප්රවාහ ඇමතුමකින් තොරව**
හැඹිලියෙන් සපයන බැවින්, වාර්තා කරන `X-OmniRoute-Response-Latency` අගය
(මුල් ඉහළ ප්රවාහ ප්රමාදය කුමක් වුවත්) ශූන්යයට ආසන්න වේ. ප්රමාදයට සංවේදී
සේවාලාභීන් (මිණුම්කරණය, p50/p99 අධීක්ෂණය) `X-OmniRoute-Cache-Latency`
ප්රතිචාර ශීර්ෂකය පරීක්ෂා කළ යුතුය:

| අගය         | අර්ථය                                                           |
| ----------- | --------------------------------------------------------------- |
| `synthetic` | ප්රතිචාරය හැඹිලියෙන් සපයා ඇත; ප්රමාදය සැබෑ ඉහළ ප්රවාහ කාලය නොවේ |
| _(නොමැති)_  | සැබෑ ඉහළ ප්රවාහ ඇමතුමකින් ලැබුණු ප්රතිචාරය                      |

### යතුරකට වෙන් වූ හැඹිලි මඟහැරීම

API යතුරුවලට `cacheDefaultMode` හරහා අර්ථාන්විත හැඹිලි කියවීම්වලින් ඉවත් විය හැක:

| අගය      | හැසිරීම                                                        |
| -------- | -------------------------------------------------------------- |
| `legacy` | සාමාන්ය හැඹිලි හැසිරීම (පෙරනිමි)                               |
| `bypass` | හැඹිලි සෙවීම සම්පූර්ණයෙන්ම මඟහරින්න; සැමවිටම ඉහළ ප්රවාහයට යන්න |

යතුර නිර්මාණය කිරීමේදී (`POST /api/keys`) සකසන්න හෝ (`PATCH /api/keys/[id]`) යාවත්කාලීන කරන්න:

```json
{ "cacheDefaultMode": "bypass" }
```

### API යතුරු අවසර

`PATCH /api/keys/{id}` මඟින් පවතින යතුරක අවසර යාවත්කාලීන කරයි. සෑම `/api/keys*` මාර්ගයක් මෙන්ම, මෙයට අනුමාන යතුරක් නොව කළමනාකරණ අවසර දීම අවශ්ය වේ ([කළමනාකරණ සත්යාපනය](../guides/MANAGEMENT-AUTH.md) බලන්න). ඔබට වෙනස් කිරීමට අවශ්ය ක්ෂේත්ර පමණක් යවන්න; ඒවායින් කිසිවක් නොමැති ඉල්ලීමක් `No valid fields to update` යනුවෙන් ප්රතික්ෂේප කෙරේ. පිළිගනු ලබන ක්ෂේත්ර `src/shared/validation/schemas/keys.ts` හි `updateKeyPermissionsSchema` මඟින් අර්ථ දක්වා ඇත.

```bash
# අයවැයක් සකසන්න හෝ යාවත්කාලීන කරන්න

  "apiKeyId": "key-123",
  "dailyLimitUsd": 5.00,
  "weeklyLimitUsd": 30.00,

  "warningThreshold": 0.8,
  "resetInterval": "monthly"
}
```

> **යෝජනාක්රම සටහන්** (`setBudgetSchema`): `apiKeyId` අවශ්ය වේ; `dailyLimitUsd`, `weeklyLimitUsd`, හෝ `monthlyLimitUsd` යන ඒවායින් අවම වශයෙන් එකක්වත් බිංදුවට වඩා වැඩි විය යුතුය. විකල්ප ක්ෂේත්ර: `warningThreshold` (0–1), `resetInterval` (`daily` | `weekly` | `monthly`), `resetTime` (`HH:MM`). පැරණි `{keyId, limit, period}` ව්යුහය `400 Bad Request` ආපසු ලබා දෙයි.

## ටෝකන සීමා

එක් එක් API යතුර සඳහා වන **ටෝකන** අයවැය (ඉහත USD මත පදනම් වූ අයවැයෙන් වෙනස් වේ). ඉල්ලීම් මාර්ගයේදීම බලාත්මක කෙරේ: යතුරක වත්මන් කාල කවුළුවේ භාවිතය එහි සීමාවට ළඟා වූ විට, ඉල්ලීම් `429 Too Many Requests` සමඟ ප්රතික්ෂේප කෙරේ. සීමා නිශ්චිත `model` එකකට හෝ `provider` එකකට සීමා කළ හැකිය, නැතහොත් යතුර පුරා `global` ලෙස යෙදිය හැකිය; සීමා කිහිපයක් ඉල්ලීමකට ගැළපෙන විට, වඩාත් සීමාකාරී එක බලපැවැත්වේ.

```bash

# ටෝකන සීමාවක් සාදන්න හෝ යාවත්කාලීන කරන්න

Content-Type: application/json

  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",

  "resetInterval": "monthly",
  "enabled": true

# id අනුව ටෝකන සීමාවක් මකන්න
DELETE /api/usage/token-limits?id=tl-abc
```

> **යෝජනා ක්රම සටහන්** (`setTokenLimitSchema`): `apiKeyId` සහ `scopeType` (`model` | `provider` | `global`) අවශ්ය වේ. `scopeType` යනු `global` නොවේ නම් `scopeValue` අවශ්ය වේ (උදා: `model` විෂය පථය සඳහා ආකෘති id එකක්, `provider` විෂය පථය සඳහා සපයන්නාගේ id එකක්). `tokenLimit` ධන පූර්ණ සංඛ්යාවක් විය යුතුය (තන්තුවකින් පරිවර්තනය කෙරේ). විකල්ප: `id` (සෑදීම සඳහා මඟ හරින්න, යාවත්කාලීන කිරීම සඳහා සපයන්න), `resetInterval` (`daily` | `weekly` | `monthly`, පෙරනිමිය `monthly`), `resetTime` (`HH:MM`), `enabled` (පෙරනිමිය `true`). `GET` ප්රතිචාර සෑම සීමාවකටම `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, සහ `nextResetAt` එක් කර වැඩිදියුණු කරයි. මෙය කළමනාකරණ පන්තියේ අන්ත ලක්ෂ්යයකි (සත්යාපනය authz නල මාර්ගය මඟින් මධ්යගතව බලාත්මක කෙරේ).

### අනුපාත-සීමා පෝලිම සහ ස්වයංක්රීය-සක්රීය ආරක්ෂණ ජාලය

- **සහාය දක්වන ලිවීම් මාර්ගය**: `{"connectionId": "<id>", "enabled": true|false}` දේහය සමඟ `POST /api/rate-limits` යනු සම්බන්ධතාවක් සඳහා අනුපාත-සීමා ආරක්ෂණය මාරු කිරීමට සහාය දක්වන කළමනාකරණ අන්ත ලක්ෂ්යයයි. `PUT /api/providers/[id]` හිතාමතාම `rateLimitProtection` වෙනස් කිරීම හෝ මාරු කිරීම නොකරයි (#11278).
- **`enabled: false` හි අර්ථ නිරූපණය**: `enabled: false` ලෙස සැකසීමෙන් සම්බන්ධතාව සඳහා ඇති පැහැදිලි ආරක්ෂණය ඉවත් කෙරේ, නමුත් එය සක්රීය API-යතුරු සම්බන්ධතාවක් ගෝලීය ස්වයංක්රීය-සක්රීය ආරක්ෂණ ජාලයෙන් (`autoEnableApiKeyProviders = true`) ඉවත් **නොකරයි**. `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) තුළ `false` සහ `undefined` සමාන වේ; පැහැදිලි ආරක්ෂණයක් නොමැති සක්රීය API-යතුරු සම්බන්ධතා ස්වයංක්රීය-සක්රීය ආරක්ෂණ ජාලය යටතේ තවදුරටත් ආරක්ෂා වේ.
- **ගෝලීයව අක්රීය කිරීම**: අනුපාත-සීමා පෝලිම් නොමැතිව API-යතුරු සම්බන්ධතා ධාවනය කිරීමට, `RATE_LIMIT_AUTO_ENABLE=false` (පරිසර විචල්යය) හෝ `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Settings → Resilience / `PATCH /api/resilience`) හරහා ආරක්ෂණ ජාලය ගෝලීයව අක්රීය කරන්න.

## MCP සේවාදායකය

OmniRoute විෂය පථගත මෙවලම් සහිත ප්රවාහන 3කින් (stdio, SSE, streamable-http) යුත් අන්තර්ගත Model Context Protocol සේවාදායකයක් සපයයි. පහත dashboard endpoints මඟින් තත්ත්ව/විගණන දත්ත කියවා HTTP ප්රවාහන proxy කරයි.

## A2A සේවාදායකය

OmniRoute විසින් A2A (Agent-to-Agent) JSON-RPC 2.0 අන්ත ලක්ෂ්යයක් සහ පරීක්ෂා කිරීම/උපකරණ පුවරු භාවිතය සඳහා REST ආවරණයක් සපයයි.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # OMNIROUTE_API_KEY සකසා නොමැති නම් විකල්ප වේ
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

සහාය දක්වන ක්රම (සියල්ල `settings.a2aEnabled` මඟින් පාලනය වේ):

| ක්රමය            | විස්තරය                                                                        |
| ---------------- | ------------------------------------------------------------------------------ |
| `message/send`   | සමමුහුර්ත කුසලතා ක්රියාත්මක කිරීම; `{task, artifacts, metadata}` ආපසු ලබා දෙයි |
| `message/stream` | එම කුසලතා කට්ටලයේ ප්රවාහක SSE ක්රියාත්මක කිරීම                                 |
| `tasks/get`      | `taskId` අනුව කාර්යයක් ලබා ගනී                                                 |
| `tasks/cancel`   | `taskId` අනුව කාර්යයක් අවලංගු කරයි                                             |

අන්තර්ගත කුසලතා: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### නියෝජිත කාඩ්පත

```bash
GET /.well-known/agent.json
```

පොදු A2A නියෝජිත කාඩ්පත (නම, විස්තරය, හැකියා, කුසලතා නාමාවලිය, සත්යාපන ක්රමය) ආපසු ලබා දෙයි — පැය 1ක් සඳහා පොදුවේ හැඹිලිගත කර ඇත. සත්යාපනය අවශ්ය නොවේ.

### REST උපකාරක

| ක්රමය | මාර්ගය                       | විස්තරය                                                                                                                    |
| ----- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| GET   | `/api/a2a/status`            | A2A සක්රීය තත්ත්වය + කාර්ය සංඛ්යාලේඛන + හැඹිලිගත නියෝජිත කාඩ්පත් සාරාංශය                                                   |
| GET   | `/api/a2a/tasks`             | කාර්ය ලැයිස්තුගත කරයි — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST  | `/api/a2a/tasks`             | (REST උපකාරකයක් ලෙස ක්රියාත්මක කර නැත — JSON-RPC `message/send` හරහා සාදන්න)                                               |
| GET   | `/api/a2a/tasks/[id]`        | එක් කාර්යයක් ලබා ගනී                                                                                                       |
| POST  | `/api/a2a/tasks/[id]/cancel` | කාර්යයක් අවලංගු කරයි                                                                                                       |

**සත්යාපනය:** REST උපකාරක කළමනාකරණ සත්යාපනයකින් තොරව ක්රියාත්මක වේ (උපකරණ පුවරුවෙන් කියවිය හැක); JSON-RPC `/a2a` මාර්ගය වින්යාස කර ඇත්නම් Bearer `OMNIROUTE_API_KEY` භාවිත කරයි.

## ACP (Agent Client Protocol) කළමනාකරණය

අනු ක්රියාවලි ලෙස. මෙම අන්ත ලක්ෂ්ය ACP නියෝජිත හඳුනාගැනීම සහ අභිරුචි නියෝජිත
ලියාපදිංචිය කළමනාකරණය කරයි.

| ක්රමය  | මාර්ගය            | විස්තරය                                                                                                                                                                  |
| ------ | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| GET    | `/api/acp/agents` | ස්ථාපන තත්ත්වය, අනුවාදය සහ ද්විමය සමඟ දන්නා සියලුම CLI නියෝජිතයන් (ගොඩනඟා ඇති + අභිරුචි) ලැයිස්තුගත කරයි                                                                 |
| POST   | `/api/acp/agents` | අභිරුචි ACP නියෝජිතයෙකු ලියාපදිංචි කරයි හෝ හැඹිලිය නැවුම් කරයි — body: `{id, name, binary, versionCommand, providerAlias, spawnArgs, protocol}` හෝ `{action: "refresh"}` |
| DELETE | `/api/acp/agents` | අභිරුචි ACP නියෝජිතයෙකු ඉවත් කරයි — query param: `?id=<agentId>`                                                                                                         |

## සත්යාපනය

අක්තපත්ර වර්ග හතර (උපකරණ පුවරු සැසිය, දේශීය CLI ටෝකනය, `oma_live_…` ප්රවේශ ටෝකනය, කළමනාකරණ විෂයපථයක් සහිත API යතුර) සහ ඒවා අනුමාන යතුරුවලින් වෙනස් වන ආකාරය පිළිබඳව [කළමනාකරණ සත්යාපනය](../guides/MANAGEMENT-AUTH.md) බලන්න.

- උපකරණ පුවරු මාර්ග (`/dashboard/*`) `auth_token` කුකිය භාවිත කරයි
- පිවිසීම සඳහා සුරකින ලද මුරපද හැෂය භාවිත කරයි; එය නොමැති විට `INITIAL_PASSWORD` භාවිත කරයි
- `requireLogin`, `/api/settings/require-login` හරහා සක්රිය හෝ අක්රිය කළ හැක
- `REQUIRE_API_KEY=true` වන විට `/v1/*` මාර්ග සඳහා විකල්ප ලෙස Bearer API යතුරක් අවශ්ය වේ
- මෙම යොමුවේ "කළමනාකරණ ටෝකනය" / "කළමනාකරණ විෂයපථයක් සහිත API යතුර" යන්නෙන් අදහස් වන්නේ එම මාර්ගෝපදේශයේ සඳහන් වර්ගවලින් එකකි — නිර්වචනය නොකළ අමතර රහස් වර්ගයක් නොවේ

> **පසුගාමී අනුකූලතාව බිඳ දමන වෙනස (v3.8.0)** — `/api/v1/agents/tasks/*` සහ විරාම කාල කළමනාකරණ අන්ත ලක්ෂ්ය සඳහා දැන් **කළමනාකරණ සත්යාපනය** (උපකරණ පුවරුවේ `auth_token` කුකිය හෝ කළමනාකරණ විෂයපථයක් සහිත API යතුරක්) අවශ්ය වේ. මීට පෙර සත්යාපනයකින් තොරව මෙම මාර්ග ඇමතූ සේවාලාභීන්ට `401 Unauthorized` ලැබෙනු ඇත. `588a0333` කමිටුව බලන්න (`fix(auth): require management auth for agent and cooldown APIs`).
