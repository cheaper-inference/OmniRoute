## TLS ඇඟිලි සලකුණු ස්තරය

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

ස්ථාවර `wreq-js` සැසි, එක් එක් ගිණුම් විෂය පථය සහ නිරාකරණය කළ ප්රොක්සිය අනුව අවශ්ය වූ විට පමණක් සාදනු ලැබේ. ක්රියාවලි-ව්යාප්ත `TlsClient` එක, Cloudflare පිටුපස ඇති upstream සඳහා **macOS මත Chrome 124** ලෙස පෙනී සිටින සැසි උපරිම වශයෙන් 128ක් pool කරයි. ස්වදේශීය runtime එක නොමැති විට `TlsClient.fetch()` ආරක්ෂිතව අසාර්ථක වේ; මෙම wrapper එකෙන් පිටත fallback එකක් caller කෙනෙකුට පැහැදිලිව තෝරාගත හැක.

- සැසි profile එක: `browser: "chrome_124", os: "macos"`
- ප්රොක්සි නිරාකරණය (ප්රමුඛතාව): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (කුඩා අකුරු ප්රභේද ද ඇතුළුව)
- කල් ඉකුත්වීම: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS` වෙතින් උරුම වේ, පෙරනිමිය 600000)
- `wreq-js` Response එක fetch සමඟ අනුකූල වේ (`headers`, `text()`, `json()`, `clone()`, `body`).
- පළමු-byte watchdog එක (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): upstream headers පැමිණි වහාම `TlsClient.fetch()`
  නිරාකරණය වන බැවින්, කිසිදා පළමු byte එක ලබා නොදෙන body එකක් `TLS_CLIENT_TIMEOUT_MS` මඟින් පමණක් සීමා කළ නොහැක.
  `guardTlsFirstByte()` මඟින් body එකේ පළමු `read()` එක `TLS_FIRST_BYTE_WATCHDOG_MS` (පෙරනිමිය `10000`, `0` එය අක්රිය කරයි) සමඟ
  තරග කරවයි; සෞඛ්ය සම්පන්න body එකකට බලපෑමක් නොවන අතර, ඇණහිටි body එකක් wreq reader එක අවලංගු කර
  `proxyFetch` හි පවතින TLS-fallback තර්කනයට සෘජු/ප්රොක්සි dispatcher එක වෙත ඉදිරියට යාමට ඉඩ සලසයි
  (නැවත ධාවනයට ආරක්ෂිත නොවන request එකක්, උදා. body එකක් සහිත POST එකක්, නිහඬව නැවත උත්සාහ කිරීම වෙනුවට තවමත් exception එකක් නිකුත් කරයි).

### Web-cookie සපයන්නාගේ ප්රවාහනය — wreq-js 3.2.0

  `WreqTransportCapacityError` (හවුල් session-capacity error code එක) ලැබේ.

ඉහත generic `TlsClient` session එක ස්ථාවර browser-backed cookie තත්ත්වය සඳහා විශේෂිතව පවතී. මාර්ග දෙකම cache කළ එක් wreq module loader එකක් සහ process lifecycle hook එකක් නැවත භාවිත කරයි; ඒවායේ cookie ආයුකාල හිතාමතාම වෙනස් බැවින් ඒවායේ pools වෙන වෙනම පවතී.

## CLI ඇඟිලි සලකුණු රෙජිස්ට්රිය — `open-sse/config/cliFingerprints.ts`

නිල CLI මෙවලම්වල mitmproxy ලුහුබැඳීම්වලින් ග්රහණය කරගත් **නිශ්චිත** ශීර්ෂක අනුපිළිවෙළ සහ JSON අන්තර්ගත ක්ෂේත්ර අනුපිළිවෙළ ස්ථාවර කරන, සපයන්නෙකුට එක බැගින් වන වගුවකි. දැනට ලියාපදිංචි කර ඇත්තේ: `codex`, `claude`, සහ `antigravity` හා `github` සඳහා `providerHeaderProfiles.ts` තුළ ඇති ධාවන කාලයේදී ව්යුත්පන්න කළ පැතිකඩවල්ය.

```ts
interface CliFingerprint {
  headerOrder: string[]; // අක්ෂර ප්රමාණයට සංවේදීය
  bodyFieldOrder: string[]; // ඉහළ-මට්ටමේ JSON යතුරු
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

පරිසර විචල්ය හරහා එක් එක් සපයන්නා සඳහා සක්රිය හෝ අක්රිය කරන්න (පහත බලන්න). අක්රිය කර ඇති විට, ශීර්ෂක/අන්තර්ගත යතුරු Node/JSON විසින් ලබා දුන් ඕනෑම අනුපිළිවෙළකට දිස් වේ — එම නිසා පහසුවෙන් ඇඟිලි සලකුණු කළ හැකිය.

## MITM ප්රොක්සිය (Antigravity, Linux/macOS/Windows)

`OPENAI_BASE_URL` හරහා හරවා යැවිය නොහැකි ද්විමය ගොනු සහිත CLI මෙවලම් සඳහා, OmniRoute දේශීය TLS-අවසන්කරණ ප්රොක්සියක් ධාවනය කරයි. අන්ත ලක්ෂ්ය `src/app/api/cli-tools/antigravity-mitm/` යටතේ පිහිටා ඇත.

| ක්රමය  | අන්ත ලක්ෂ්යය                            | අරමුණ                                                        |
| ------ | --------------------------------------- | ------------------------------------------------------------ |
| GET    | `/api/cli-tools/antigravity-mitm`       | තත්ත්වය — ධාවනය වෙමින් පවතීද, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM ආරම්භ කරන්න (`apiKey` + `sudoPassword` අවශ්යයි)         |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM නවත්වන්න                                                |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | ආකෘති අන්වර්ථ නාම ලැයිස්තුගත කරන්න                           |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | මෙවලමක් සඳහා ආකෘති අන්වර්ථ නාම සුරකින්න                      |

බාධනය කරනු ලබන ඉලක්ක ධාරකය: **`daily-cloudcode-pa.googleapis.com`** (Antigravity හි ඉහළ ධාරාව).

### ආරම්භක අනුක්රමය (`src/mitm/manager.ts::startMitm`)

1. `selfsigned` හරහා ස්වයං-අත්සන් කළ සහතිකයක් ජනනය කරන්න (RSA-2048, SHA-256, වසර 1ක්) — `cert/generate.ts`
2. පද්ධති විශ්වාස ගබඩාවට සහතිකය ස්ථාපනය කරන්න — `cert/install.ts`
3. `127.0.0.1 daily-cloudcode-pa.googleapis.com` ධාරක සටහන එක් කරන්න — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (පෙරනිමිය `443`) සමඟ `src/mitm/server.cjs` ක්රියාවලියක් ආරම්භ කරන්න
5. PID එක `<DATA_DIR>/mitm/.mitm.pid` වෙත ස්ථිරව සුරකින්න

### Linux ගතික විශ්වාස-ගබඩා හඳුනාගැනීම — `cert/install.ts`

`getLinuxCertConfig()` ප්රමුඛතා ලැයිස්තුවක් ඔස්සේ ගොස්, පවතින පළමු නාමාවලිය තෝරාගනී:

| බෙදාහැරීම් පවුල          | නාමාවලිය                                    | යාවත්කාලීන විධානය        |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

සහතික ගොනු නාමය: `omniroute-mitm.crt`. `getCertFingerprint()` හරහා ඇඟිලි සලකුණු ගැළපීම සිදු වේ (DER හි SHA-1).

මීට අමතරව, `certutil` පවතින විට `updateNssDatabases()` එක් එක් පරිශීලකයාගේ NSS DB තුළ ස්ථාපනය කරයි: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, සහ සියලු Firefox පැතිකඩවල් (snap ඇතුළුව), **`OmniRoute MITM Root CA`** යන අන්වර්ථ නාමය යටතේ.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** උසස් වරප්රසාද සහිත PowerShell → `certutil -addstore Root`

### සත්යාපනය

සියලු MITM අන්ත ලක්ෂ්ය සඳහා කළමනාකරණ සත්යාපනය (`requireCliToolsAuth`) අවශ්ය වේ. sudo මුරපදය මොඩියුල පරාසය තුළ හැඹිලිගත කරනු ලැබේ (කිසිවිටෙක `globalThis` තුළ නොවේ) සහ `stopMitm()` ක්රියාත්මක කළ විට ඉවත් කෙරේ.

## සපයන්නෙකු මාරු කරන විට ඇඟිලි සලකුණු යාවත්කාලීන කිරීම

1. `mitmproxy` සමඟ නිල CLI තදබදය ග්රහණය කරන්න (TLS අතරමැදි කිරීම + ඩම්ප් කිරීම)
2. JA3/JA4 සහ සත්ය ශීර්ෂ අනුපිළිවෙළ උපුටා ගන්න
3. අදාළ `CLI_FINGERPRINTS[...]` ප්රවේශය යාවත්කාලීන කරන්න
4. `.env.example` තුළ ගැළපෙන `*_USER_AGENT` පෙරනිමිය වැඩි කරන්න
5. TLS හෑන්ඩ්ෂේක් එකම වෙනස් වී ඇත්නම්, අදාළ සපයන්නාගේ රැපරය හෝ wreq-js `browser:` විකල්පය යාවත්කාලීන කරන්න
