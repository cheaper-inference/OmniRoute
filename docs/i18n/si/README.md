## 💰 ~1.62B ටෝකන / මාසිකව තෙවන පාර්ශවීය නොමිලේ මට්ටම් හරහා

> **ඔබේම සපයන්නන්ගේ ගිණුම් ගෙන එන්න.** මෙය වෙන වෙනම සුදුසුකම් ලැබූ තෙවන පාර්ශවීය නොමිලේ මට්ටම් හරහා අනුමානිත එකතුවකි, OmniRoute වෙතින් ලබාදෙන ටෝකන ප්රදානයක් නොවේ. ලියාපදිංචි වන්න, අවශ්ය නම් අක්තපත්ර ලබාගන්න, සහ ඔබට භාවිතා කළ හැකි සපයන්නන් සම්බන්ධ කරන්න; සෑම සපයන්නෙකුම තම සීමා, ලබාදීම සහ නියමයන් පාලනය කරයි.
>
> නොමිලේ මට්ටම් අතින් එකතු කිරීම වේදනාකාරීයි — SDK දහස් ගණනක්, අනුපාතික සීමා දහස් ගණනක්, සහ ඔබට ඇත්තටම තිබෙන ප්රමාණය ගැන කිසිදු අදහසක් නැහැ. OmniRoute විසින් **34 නැවත නැවත පාවිච්චි කළ හැකි pool යතුරු හරහා 485 නොමිලේ මට්ටම් ඇතුළත් කිරීම්** නාමාවලියට එක් කරයි සහ **පොසිටිව් මාසික අයවැය පළකර ඇති pool 17ක් සහ මොඩලය අනුව Groq සීමා පහක්** මත පදනම්ව ටෝකන ප්රධාන සංඛ්යාව ගණනය කරයි, හවුල් pool එකකට එක වරක් පමණක් ගණනය කරයි. ප්රාදේශීය හැඳුනුම් පරීක්ෂාවෙන් පසුව පමණක් විවෘත වන කොටස් (අද: ModelScope) වෙනම පෙන්වයි, +~6Mක් ප්රාදේශීය හැඳුනුම් සත්යාපනයෙන් පසු, සහ කිසිවිටෙකත් ප්රධාන සංඛ්යාවට එකතු නොකරයි. ප්රතිඵලය පුවරුවේ දිස්වෙයි (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute නොමිලේ මට්ටම් අයවැය කාඩ්පත: මාසිකව ~1.62B නොමිලේ ටෝකන ස්ථාවරව, ලියාපදිංචි වීමේ ණය සමඟ පළමු මාසයේදී ~2.22B දක්වා, pool යතුරු 34ක් හරහා ලේඛනය කළ නොමිලේ මට්ටම් ඇතුළත් කිරීම් 485ක් එකම අවසන් ලක්ෂ්යයකට. අවංක pool එකතු කිරීමේ ගණිතය — සෑම හවුල් pool එකක්ම එක වරක් ගණනය කරයි, පොසිටිව් මාසික ටෝකන අයවැය පළකර ඇති pool 17ක් සහ මොඩලය අනුව Groq සීමා පහක් ඇතුළුව; සපයන්නන් 12ක් නියමයන් අවදානම් නාමාවලියෙන් "ඉවතලන්න" ලෙස සලකුණු කර ඇත, ඔබ තීරණය කරන්න. අයවැය තීරුවේ Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (මොඩලය අනුව සීමා පහක්) සහ කුඩා pool, පළමු මාසයේ ලියාපදිංචි ණය සහ ස්ථිරව නොමිලේ ටෝකන සීමාවක් නැති සපයන්නන් වෙනම පෙන්වයි, එය කිසිවිටෙකත් ප්රධාන සංඛ්යාව වැඩි නොකරයි. /dashboard/free-tiers හි සජීවී භාවිතා/ඉතිරි ප්රමාණය."/>

## 📡 OmniRoute Radar

ඉහත ලේඛනගත කර ඇති, සංචිතය අනුව අනුපිටපත් ඉවත් කළ නාමාවලියෙන් ලැබෙන ප්රධාන නොමිලේ-ස්ථර අගය **මසකට ටෝකන ~1.62B** ලෙසම පවතී. තාවකාලික සැපයුම්කරු ලියාපදිංචි වීමේ බැර මඟින් පළමු මාසයේ අගය වෙනමම **~2.22B** දක්වා ඉහළ නැංවිය හැක. Radar යනු OmniRoute නිකුතු අතරතුර නොමිලේ මාදිලි පිළිබඳ වඩාත් නවතම ලබාගත හැකි තොරතුරු අවශ්ය අය සඳහා වන, විකල්ප සහ අත්සන් කළ නාමාවලි අතිරේකයකි; ප්රජා නාමාවලිය සහ දැනට පවතින සෑම නොමිලේ විශේෂාංගයක්ම නොමිලේම පවතී.

සහායකයින්ට සජීවී නාමාවලිය සහ අතිරේක සැපයුම්කරු අවස්ථා ලබාගත හැක. එහි වෙනම, වෙනස් විය හැකි උපරිම සීමාව සැපයුම්කරුවන්ගේ ලබාගත හැකිභාවය මත පදනම්ව **උපරිම වශයෙන් මසකට ටෝකන බිලියන 3ක් පමණ** වේ. එම සීමාව සහතිකයක් නොවේ: සැපයුම්කරුවන්ට ඕනෑම වේලාවක කෝටා, සුදුසුකම්, මාදිලි හෝ කලාප වෙනස් කළ හැක.

Radar භාවිතය තෝරාගත හැකි අතර එය GET සඳහා පමණි. OmniRoute සේවාලාභියා ප්රේරක, ගමනාගමනය, සැපයුම්කරු වින්යාසය, භාවිත දුරමිතිය හෝ දේශීය නිවේදන-ඉවතලීමේ තත්ත්වය උඩුගත නොකරයි. සුදුසුකම් සහ වත්මන් නාමාවලිය පිළිබඳව **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)** වෙතින් දැනගන්න.

පෙරනිමි stacked combo එක `RTK → Caveman` ක්රියාත්මක කරයි. දෙකම එකම tool/context payload එක මත ක්රියා කරන විට, ඉතිරිකිරීම් සංයුක්ත වේ:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

කේත කොටස්, URLs, JSON සහ ව්යුහාත්මක දත්ත සංරක්ෂණ එන්ජිම මගින් **සැමවිටම ආරක්ෂා කර ඇත**.

> **ටෝකන ස්වල්පයකින් වැඩේ යන විට ඇයි ටෝකන ගොඩක් භාවිතා කරන්නේ?** සෑම ඉල්ලීමක්ම OmniRoute හි සම්පීඩන pipeline එක හරහා **විනිවිද පෙනෙන ලෙස** ගමන් කරයි — සේවාලාභී වෙනස්කම් අවශ්ය නැත. එය දැන් අනුපිළිවෙළින් ක්රියාත්මක වී එක් එක් routing combo එකට mix & match කළ හැකි **සංයුක්ත කළ හැකි එන්ජින් 12ක stack එකකි** — [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K+), [LLMLingua-2](https://github.com/microsoft/LLMLingua), සහ [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR) යන අදහස් මත පදනම් වී ඇත.

- **🪄 ප්රතිදාන ශෛලීන්** _(ප්රතිදාන-අක්ෂ මෙහෙයවීම)_ — නිර්ණායක, කෑෂ්-ආරක්ෂිත ප්රතිචාර-හැඩගැස්වීමේ උපදෙස් එන්නත් කරයි; ඒකාබද්ධ කළ හැක, සෑම එකක්ම `lite` / `full` / `ultra` තීව්රතාවයකින්. ශෛලියක් එකතු කිරීම එක්-පේළි ලේඛන සටහනකි:
  - **සංක්ෂිප්ත ගද්ය** — පිරවුම් / නිපාත / පැකිලීම් ඉවත් කරයි; තාක්ෂණික සාරය නිවැරදිව තබයි.
  - **අඩු කේතය** — "කම්මැලි ජ්යෙෂ්ඨ dev" YAGNI: කුඩාම වැඩ කරන වෙනස, ඉල්ලා නැති scaffolding නැත.
  - **Ponytail (කම්මැලි ජ්යෙෂ්ඨ dev)** — YAGNI ඉනිමඟ නගින්න, මූලික හේතුව සකසන්න, කුඩාම වැඩ කරන diff.
  - **මට ADHD ඇත (ක්රියාව-පළමු)** — ඊළඟ ක්රියාව පෙරට, පියවර අංකිත, එක් ස්ථාවර ඊළඟ පියවරක්, පෙරවදන නැත.
  - **සංක්ෂිප්ත CJK (文言)** — සම්භාව්ය-චීන අති-සංක්ෂිප්ත ශෛලිය (`zh` වෙත locale-සීමිත).
- **🎯 අනුවර්තී සන්දර්භ-අයවැය** _(ඩයලය)_ — එක් on/off ටෝකන සීමාවක් වෙනුවට, **මාදිලියේ සන්දර්භ කවුළුවට ගැලපීමට** අවශ්ය තරම් පමණක් ලාභම, වඩාත්ම අලාභ-රහිත එන්ජින් ඉහළ දමන්න. ප්රතිපත්තිය: `reserve-output` (පෙරනිමි, මාදිලිය-දැනුම්වත්) · `percentage` · `absolute`. ආකාරය: `floor` (ගැලපීම සහතික කරයි) · `replace-autotrigger` (ඔබේ පැහැදිලි තේරීම ජය ගනී) · `off` (පැරණි සීමාව).
- **🎛️ සම්පීඩනය තීරණය වන ස්ථානය** _(ප්රමුඛතාවය, ඉහළ → පහළ)_ — ඉල්ලීම-අනුව `x-omniroute-compression` ශීර්ෂකය › routing-combo අභිබවා යාම › සක්රිය නම්-කළ පැතිකඩ › අනුවර්තී / ස්වයං-ප්රේරණය › පැනල් පෙරනිමි › off. යොදන ලද සැලැස්ම `X-OmniRoute-Compression: <mode>; source=<source>` ප්රතිචාර ශීර්ෂකයෙන් නැවත ප්රතිද්වනි වේ.

ටෝකන සීමාව අනුව ස්වයං-ප්රේරණය, අනුවර්තී ඩයලය සක්රිය කිරීම, නම්-කළ පැතිකඩයක් ඇමුණීම, ඉල්ලීමකට එක්-වරක් සැකසීම, හෝ routing combo එකකට pipeline එකක් පැවරීම — වැඩබරට ගැලපෙන එක. වෙනසක් ප්රවර්ධනය කිරීමට පෙර, opt-in නොබැඳි **eval harness** එකක් (`npm run eval:compression`) ඇමුණූ කෝපස් එකක් මත විශ්වාසදායකත්වය එදිරිව ඉතිරිකිරීම් ලකුණු කරයි.

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` ඉහළම **ප්රකාශිත** ස්ථාවර SemVer අනුව යාවත්කාලීන වේ. එය git `main` අනුගමනය නොකරයි. GitOps සඳහා `:X.Y.Z` නිශ්චිතව සඳහන් කරන්න. [Docker නිකුතු නාලිකා](docs/guides/DOCKER_GUIDE.md#release-channels) බලන්න.මෙම image එකෙහි **`OMNIROUTE_MEMORY_MB=1024`** නිශ්චිතව සකසා ඇත. එය dashboard එක සහ සැහැල්ලු chat එකක් සඳහා ප්රමාණවත් වේ. **Coding agents** (Claude Code, Codex, Grok, … වෙතින් `POST /v1/responses`) සඳහා වඩා විශාල V8 heap එකක් අවශ්ය වේ; එසේ නොමැතිව දිගු contexts දෙකක් එකිනෙක අතිච්ඡාදනය වන විට ~12 GiB දී process එක `FATAL ERROR` සමඟ අසාර්ථක වේ. Container එක heap එකට වඩා විශාල ලෙස සකසන්න (native buffers V8 වලින් පිටත පවතී):

| කාර්යභාරය                          | Heap (`-e OMNIROUTE_MEMORY_MB`) | Container (`--memory`) |
| ---------------------------------- | ------------------------------- | ---------------------- |
| Dashboard / සැහැල්ලු chat          | `1024` (image පෙරනිමිය)         | ≥2 g                   |
| එක් coding agent එකක්              | `8192`                          | ≥10 g                  |
| සමකාලීන දිගු `/v1/responses` දෙකක් | `10240`–`12288`                 | ≥12–16 g               |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
```

**🥟 Bun**

Bun runtime හඳුනාගැනීම හරහා සම්මත `bun install` සහ global ස්ථාපනය (`bun install -g omniroute`) සඳහා සහය දක්වයි:

- **අන්තර්ගත `bun:sqlite`**: Bun යටතේ ක්රියාත්මක වන විට OmniRoute විසින් Bun හි අන්තර්ගත `bun:sqlite` driver එක භාවිත කරන අතර, Node.js මතදී `better-sqlite3` හෝ `sql.js` වෙත යොමු වේ.
- **dev හි ස්වයංක්රීය Webpack bundler තේරීම**: Development (`bun run dev`) විසින් Bun ස්වයංක්රීයව හඳුනාගෙන native V8 binding නොගැළපීම් වැළැක්වීම සඳහා Turbopack අක්රිය කර Webpack භාවිත කරයි. Production builds (`bun run build`) Node මත මෙන්ම `OMNIROUTE_USE_TURBOPACK` නිශ්චිතවම අනුගමනය කරයි: පෙරනිමියෙන් Turbopack ද, Webpack සමඟ build කිරීමට `OMNIROUTE_USE_TURBOPACK=0` ද භාවිත වේ (`Dockerfile.bun` එය `--build-arg` එකක් ලෙස නිරාවරණය කරයි).
- **කැපවූ Bun Dockerfile**: Native Bun production deployments සඳහා බහු-අදියර `Dockerfile.bun` (`docker build -f Dockerfile.bun -t omniroute:bun .`).

### දායක වන්නේ කෙසේද

1. නිධිය Fork කරන්න
2. **ක්රියාකාරී** `release/vX.Y.Z` ටිප් එකෙන් (`main` වෙතින් නොවේ) බ්රාන්ච් එකක් සාදන්න — [බ්රාන්ච් කිරීමේ සහ නිකුත් කිරීමේ ආකෘතිය](docs/ops/BRANCHING_MODEL.md) බලන්න
3. ඔබේ විශේෂාංග බ්රාන්ච් එක සාදන්න (`git checkout -b feat/amazing-feature`)
4. ඔබේ වෙනස්කම් කමිට් කරන්න (`git commit -m 'feat: add amazing feature'`)
5. බ්රාන්ච් එකට push කරන්න (`git push origin feat/amazing-feature`)
6. **base = එම `release/vX.Y.Z` බ්රාන්ච් එක** ලෙස Pull Request එකක් විවෘත කරන්න
