## Kostenlose Token pro Monat: 11,3 Mrd. ~, während andere zählen · 90 Mio. ~ Real

</div>

> **~ 11,3 Milliarden kostenlose Token/Monat**<br/> <sub> zählte wie andere Kataloge: jede Zeile wurde addiert, abgeschlossene Angebote inklusive </sub>
>
> **~ 90M real heute**<br/> <sub> Jedes freigegebene Kontingent wird einmal gezählt: Was Sie tatsächlich verwenden können </sub>
>
> **Hier ist alles kostenlos. Keine Paywall.**<br/> ★ [Gefällt es? Star uns auf GitHub](https://github.com/cheaper-inference/OmniRoute)

Andere Kataloge verlangen zwischen 19 US und 49 US pro Jahr für den lebenslangen Zugriff auf Live-Daten. Hier ist alles kostenlos. <sub> Preise geprüft am 18.11.2026.</sub>

<sub>Der Katalog wurde zuletzt am 23.11.2026 geprüft. [Wie wir → zählen](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **Bringen Sie Ihre eigenen Anbieterkonten mit.** Hierbei handelt es sich um kostenlose Stufen von Drittanbietern, nicht um eine Token-Zuteilung von OmniRoute. Melden Sie sich an, erhalten Sie Zugangsdaten, wenn ein Anbieter sie verlangt, und verbinden Sie diejenigen, die Sie verwenden können. Jeder Anbieter legt seine eigenen Limits, Verfügbarkeiten und Bedingungen fest.
>
> Das manuelle Stapeln kostenloser Stufen bedeutet Dutzende SDKs, Dutzende Ratenlimits und keine klare Vorstellung davon, was Ihnen noch bleibt. OmniRoute behält 214 Katalogzeilen mit freiem Zugriff und berechnet die tatsächliche Zahl aus 12 Pools mit einer veröffentlichten Quote, wobei jeder gemeinsam genutzte Pool einmal gezählt wird. Kontingente, die erst nach einer regionalen Identitätsprüfung (heute ModelScope) geöffnet werden, werden getrennt ausgewiesen, +~ 6M hinter der regionalen Identitätsprüfung und nie zur tatsächlichen Zahl addiert. Was übrig bleibt, wird im Dashboard (`/dashboard/free-tiers`) angezeigt.

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

## Combos: das Flaggschiff

1. **Beginnen Sie mit `auto`.** Legen Sie das Modell in Ihrem OpenAI-kompatiblen Client fest. OmniRoute stellt eine virtuelle Kombination aus angeschlossenen Anbietern zusammen und bewertet Kandidaten live.
2. **Speichern Sie eine Combo für mehr Kontrolle.** Wählen Sie einen Namen, eine Zielliste und eine Strategie und verwenden Sie diesen Namen dann als Modell. Die Strategie legt fest, welches Ziel zuerst erreicht wird und wie der Rest ausprobiert wird.

Eine Kombination leitet automatisch zwischen Modellen weiter. Bei Erschöpfung des Kontingents, Anbieterausfall oder Modellsperrung wird das nächste geeignete, fehlerfreie Ziel versucht.

### Nullkonfiguration: Verwenden Sie einfach `auto`

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

Varianten stimmen die Gewichte ab. Das zuletzt als funktionierend bekannte Routing bleibt beim letzten erfolgreichen Anbieter, bis es fehlschlägt, und führt dann eine Neubewertung durch. `auto/fast` und `auto/cheap` drücken Präferenzen aus, ohne das schnellste oder günstigste Modell zu garantieren.

| Modell ID           | Verhalten                                                                                                                                                                                                                                                                                                                   |
| :------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Ausgewogene Standardgewichte.                                                                                                                                                                                                                                                                                               |
| `auto/fast`         | Begünstigt niedrige Latenz und Anbietergesundheit.                                                                                                                                                                                                                                                                          |
| `auto/cheap`        | Bevorzugt niedrigere Katalogpreise.                                                                                                                                                                                                                                                                                         |
| `auto/coding`       | Qualität-erste Gewichte für die Codegenerierung.                                                                                                                                                                                                                                                                            |
| `auto/smart`        | Qualität steht an erster Stelle, Gewichtung mit 10 % Exploration (Standard 5 %).                                                                                                                                                                                                                                            |
| `auto/lkgp`         | Explizites Last-known-good-Routing mit den gleichen Gewichtungen wie `auto`.                                                                                                                                                                                                                                                |
| `auto/subscription` | Verwendet nur live verifizierte Plankontingente. Gibt HTTP 503 zurück, wenn keines verfügbar ist, und vermeidet einen in Rechnung gestellten Fallback.                                                                                                                                                                      |
| `auto/thrifty`      | Planen Sie → Keyless → Free → Cheap → Premium. Kann abgerechnete Modelle erreichen und zum Plan zurückkehren, wenn Kontingent und Abklingzeit dies zulassen.                                                                                                                                                                |
| `auto/offline`      | Begünstigt Quoten- und Ratenlimit-Spielraum. Anfragen gehen weiterhin an Ihre Anbieter.                                                                                                                                                                                                                                     |
| `auto/chaos`        | Ein Modell pro Anbieter parallel, standardmäßig bis zu fünf oder bei Konfiguration zehn. Ein Upstream-Anruf pro Modell. Gibt die Antwort mit dem höchsten Rang oder die letzte erfolgreiche Panel-Antwort zurück, wenn das Top-Modell fehlschlägt. Verwenden Sie `fusion`, um Antworten mit einem Richter zusammenzufassen. |

Beispiele für Kategorien und optionale Ebenen sind `auto/coding:fast`, `auto/coding:free`, `auto/reasoning:pro` und `auto/vision`. Wenn kein verbundener Kandidat übereinstimmt, gibt die Anfrage HTTP 503 zurück und der Pool bleibt eng. [Auto-Combo-Anleitung](./docs/routing/AUTO-COMBO.md) · [Abonnement-First-Routing](./docs/routing/SUBSCRIPTION_LADDER.md)

### Oder erstellen Sie Ihre eigene: 22 Routing-Strategien

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

Die CLI akzeptiert 15 von 22 Strategien. Das Dashboard und die Combos API akzeptieren alle 22.

| Strategie           | Verhalten                                                                                                                                                                                                                                                |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | Ranglistenkandidaten live mit dem 16-Faktor-Auto-Combo-Scorer.                                                                                                                                                                                           |
| `cache-optimized`   | Bevorzugen Sie das Konto, das wahrscheinlich das Eingabeaufforderungspräfix im Cache enthält.                                                                                                                                                            |
| `context-optimized` | Probieren Sie zunächst das größte bekannte Kontextfenster aus.                                                                                                                                                                                           |
| `context-relay`     | Behalten Sie Ihre Bestellung bei und geben Sie bei einem Kontowechsel eine Gesprächszusammenfassung weiter.                                                                                                                                              |
| `cost-optimized`    | Sortieren nach Katalogeingabe-Token-Preis, Unbekannte zuletzt. Die endgültigen Kosten für die Anfrage können unterschiedlich sein.                                                                                                                       |
| `expiry-first`      | Das Ausgabenkontingent läuft wahrscheinlich ab, der höchste verbleibende Betrag pro Stunde, bis es zuerst zurückgesetzt wird.                                                                                                                            |
| `fill-first`        | Bleiben Sie beim ersten verfügbaren Ziel, bis es aufgebraucht ist oder ausfällt, und machen Sie dann weiter.                                                                                                                                             |
| `fusion`            | Befragen Sie parallel ein Gremium und lassen Sie einen Richter eine Antwort zusammenfassen.                                                                                                                                                              |
| `headroom`          | Wählen Sie die größtmögliche freie Kapazität in 5-Stunden- und Wochenfenstern.                                                                                                                                                                           |
| `jev`               | TypeSafe Jev wählt aus, welche Einträge in Ihrer Rangliste laufen. Aktivieren Sie `COMBO_JEV_STRATEGY_ENABLED`, um pro Anfrage einen Auszug zu senden und kostenpflichtige TypeSafe -Anrufe zu verwenden. Wenn es deaktiviert ist, gilt Ihre Bestellung. |

| `p2c`               | Probieren Sie zwei Ziele aus und wählen Sie sie anhand der Erfolgsrate und Latenz aus.                                                                                                                                                                   |
| `pipeline`          | Leiten Sie die Ausgabe jedes Schritts nacheinander in das nächste Ziel ein und geben Sie nur die endgültige Antwort zurück.                                                                                                                              |

### Die Widerstandsfähigkeit ist eingebaut: 3 unabhängige Schichten

Fehler werden in drei Bereichen behandelt, sodass ein fehlerhaftes Modell sein Konto nicht deaktiviert und ein fehlerhaftes Konto seinen Anbieter nicht deaktiviert.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### Wenn ein ganzer Anbieter ausfällt

Der** Leistungsschalter Ihres Anbieters** Wird nach 8 (OAuth) oder 12 (API key) Fehlern mit dem Status 408, 500, 502, 503 oder 504 geöffnet. Combos überspringen diesen Anbieter, während er geöffnet ist. Nach 60 s bzw. 30 s entscheidet eine Probe-Anfrage über das Schließen.

#### Wenn ein Schlüssel oder Konto gebührenbegrenzt ist

Der** Verbindungsabklingzeit** Banks nur diese Verbindung, mit exponentiellem Backoff von 5 s (OAuth) oder 3 s (API -Taste). Andere Schlüssel für denselben Anbieter werden weiterhin bereitgestellt.

#### Wenn ein Modell abgelehnt wird

Der** Modellsperre** Blockiert nur dieses Modell auf dieser Verbindung nach einer modellspezifischen 429, 404 oder Zugriffsverweigerung. Andere Modelle mit derselben Verbindung bedienen weiterhin.

Gesperrte, abgelaufene und nicht mehr verfügbare Verbindungen sind Endzustände und keine Abklingzeiten: Sie warten darauf, dass Sie sie beheben.

## Vollständig CLI, MCP und A2A

> OmniRoute liefert einen Befehlszeilen-Client mit** 91 Befehle und Befehlsgruppen der obersten Ebene** (754 Befehle zählen Unterbefehle), an**MCP Server mit 110 Tools und 33 Scopes** , und ein**A2A Agent mit 6 Fähigkeiten** . Skripte, Terminals und AI -Agenten können alle dasselbe Gateway betreiben.

### Ein echter CLI, nicht nur `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

Das globale `--output table|json|jsonl|csv` Flag macht die gleichen Befehle aus Skripten und CI nutzbar.

### Remote-Modus: CLI auf Ihrem Laptop, OmniRoute auf einem Server

Melden Sie sich einmal bei einem Remote-Server an. Die CLI speichert es als** Kontext** und spätere Befehle werden auf diesem Server ausgeführt, bis Sie zurückwechseln.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

| Token-Geltungsbereich | <img width="2000" height="0" alt=""> Was es erlaubt                            |
| --------------------- | ------------------------------------------------------------------------------ |
| `read`                | Auflisten und prüfen: Modelle, Status, Protokolle, Nutzung                     |
| `write`               | `read` plus konfigurieren und anwenden: Client-Setup, Schlüssel, Konfiguration |
| `admin`               | `write` plus verwalten: Token, Anbieter, Dienste, Richtlinien                  |

### Verbinden Sie einen Agenten

Ein Agent oder Ihr eigener Code kann Routing, Anbieter, Kombinationen, Cache, Komprimierung und Speicher über jede dieser Schnittstellen steuern. HTTP -Pfade werden vom Gateway bereitgestellt, standardmäßig unter `http://localhost:20128`.

| Schnittstelle            | Endpunkt oder Befehl       | Benutze es für                                                                                    |
| ------------------------ | -------------------------- | ------------------------------------------------------------------------------------------------- |
| MCP über stdio           | `omniroute --mcp`          | Claude Desktop, Cursor und andere lokale MCP Clients                                              |
| MCP über Streamable HTTP | `/api/mcp/stream`          | Remote- MCP Clients: 110 Tools, 33 Bereiche, jeder Aufruf wird in das Audit-Protokoll geschrieben |
| MCP über SSE             | `/api/mcp/sse`             | Clients, die weiterhin den SSE Transport verwenden                                                |
| A2A -Entdeckung          | `/.well-known/agent.json`  | Agentenkarte: teilt anderen Agenten mit, was OmniRoute tun kann                                   |
| A2A -Ausführung          | `POST /a2a`                | JSON-RPC 2.0-Aufgaben, synchron oder über SSE gestreamt, über 6 Fähigkeiten hinweg                |
| REST API                 | `/v1/*`                    | OpenAI-kompatibler Chat, Antworten, Einbettungen, Bilder, Audio und OCR                           |
| Webhooks                 | `/api/webhooks`            | Ereignisse für Slack, Discord, Telegram oder einen beliebigen URL mit HMAC -Signatur              |
| Remote- CLI              | `omniroute connect <host>` | Steuern Sie eine Remote-Instanz mit bereichsbezogenen Zugriffstokens                              |

Die sechs A2A Fähigkeiten sind `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` und `list-capabilities`.

**Bevor Sie eine Verbindung herstellen:**

- **MCP über HTTP startet deaktiviert.** Aktivieren Sie es mit `omniroute mcp enable --transport streamable-http` oder über die Seite „Endpunkte“ des Dashboards. Es ist immer nur ein HTTP Transport aktiv: `streamable-http` bedient `/api/mcp/stream`, `sse` bedient `/api/mcp/sse`.
- **A2A startet deaktiviert.** Aktivieren Sie es auf der Seite „Endpunkte“ des Dashboards. `POST /a2a` folgt dann denselben API-Schlüsselregeln wie `/v1`.
- **Remote MCP benötigt einen passenden Schlüssel.** `/api/mcp/*` antwortet standardmäßig nur mit Loopback. Senden Sie von einem anderen Host einen Schlüssel mit `manage` oder `admin` (alle Tools) oder mit `mcp:connect` plus den Bereichen der benötigten Tools. Für Schlüssel ohne `manage`/`admin` werden Werkzeugbereiche immer erzwungen.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

## Sparen — automatisch 15–95 % Token

### Wie es funktioniert, — -Pipeline, Architektur und Sparmathematik

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

Die gestapelte Standardkombination führt `RTK → Caveman` aus. Wenn beide auf die gleiche tool/context Nutzlast einwirken, ergeben sich folgende Einsparungen:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Codeblöcke, URLs, JSON und strukturierte Daten sind** immer geschützt** durch die Konservierungsmaschine.

> **Warum viele Token verwenden, wenn wenige Token ausreichen?** Jede Anfrage durchläuft die Komprimierungspipeline von OmniRoute** transparent** — keine Clientänderungen. Es ist jetzt ein** Stapel von 12 zusammensetzbaren Motoren** die in der richtigen Reihenfolge ausgeführt werden und pro Routing-Combo — gemischt und angepasst werden, basierend auf Ideen von [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) und [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

### Der 12-Motoren-Stack

### Über die — Ausgabestile der Engines hinaus gibt es die adaptive Wähl- und Steuerung auf Anfrage

Gestalten Sie die Antwort, zielen Sie auf das Kontextfenster des Modells ab oder wählen Sie pro Anfrage einen Komprimierungsplan aus.

#### Ausgabestile

| Stil                                     | <img width="2000" height="0" alt=""> Was es tut                                                              |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Knappe Prosa                             | Reduziert Spachtelmasse und Hecken und bewahrt gleichzeitig die technischen Details.                         |
| Weniger Code                             | Fordert die kleinste funktionierende Änderung an und verwendet vorhandenen Code wieder.                      |
| Pferdeschwanz (fauler Senior-Entwickler) | Überprüft, was wiederverwendet oder entfernt werden kann und fordert eine Fehlerbehebung für die Ursache an. |
| Ich habe ADHD (Action-First)             | Leitet mit der Aktion ein, nummeriert die Schritte und endet mit einem konkreten nächsten Schritt.           |
| Terse CJK (文言)                         | Verwendet prägnantes klassisches Chinesisch. Verfügbar für `zh`.                                             |

Jeder Stil verfügt über die Intensitäten `lite`, `full` und `ultra`. Fügen Sie einen Stil mit einem Eintrag in der Ausgabestil-Registrierung hinzu.

#### Adaptives Kontextbudget

| Einstellung | Optionen                                                                                                                                                                                                                            |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Politik     | `reserve-output` (Standard) sieht Platz für die Antwort und einen Sicherheitsspielraum vor. `percentage` nutzt einen Anteil des Kontextfensters. `absolute` legt ein festes Token-Ziel fest.                                        |
| Modus       | `floor` kann den ausgewählten Plan so eskalieren, dass er in das Kontextfenster passt. `replace-autotrigger` nutzt das Budget für die automatische Eskalation. `off` behält den automatischen Trigger des Token-Schwellenwerts bei. |

#### Wo die Komprimierung entschieden wird

| Befehl | <img width="2000" height="0" alt=""> Quelle                            |
| ------ | ---------------------------------------------------------------------- |
| 1      | Erkannter `x-omniroute-compression` -Anfrageheader                     |
| 2      | Routing-Combo-Überschreibung                                           |
| 3      | Aktives benanntes Profil                                               |
| 4      | Adaptives Kontextbudget oder automatischer Token-Schwellenwert-Trigger |
| 5      | Standardeinstellung für das Komprimierungsfeld                         |
| 6      | Aus, wenn kein Plan gilt                                               |

Der globale Komprimierungsschalter hat Vorrang vor dieser Tabelle. Der `X-OmniRoute-Compression` Antwortheader meldet `<mode>; source=<source>`.

[Kompressionsanleitung](docs/compression/COMPRESSION_GUIDE.md) · [RTK -Kompression](docs/compression/RTK_COMPRESSION.md) · [Kompressionsmotoren](docs/compression/COMPRESSION_ENGINES.md)

Das Opt-in-Evaluierungs-Harness (`npm run eval:compression`) vergleicht Antworttreue und Token-Einsparungen auf einem festen Korpus.

```txt
Model:    auto            (routes among eligible connections — or choose provider/model)
```

## Weitere Installationsmethoden — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` folgt dem Höchsten** veröffentlicht** stabiles SemVer. Es verfolgt nicht git `main`. Pin `:X.Y.Z` für GitOps. Siehe [Docker Release-Kanäle](docs/guides/DOCKER_GUIDE.md#release-channels). Die Bild-Pins**`OMNIROUTE_MEMORY_MB=1024`** . Das reicht für das Dashboard und einen leichten Chat.** Kodiermittel** (`POST /v1/responses` aus Claude Code, Codex, Grok, …) benötigen einen viel größeren V8-Heap oder der Prozess `FATAL ERROR` s bei ~ 12 GiB unter zwei überlappenden langen Kontexten. Dimensionieren Sie den Container über dem Heap (native Puffer befinden sich außerhalb von V8):

| <img width="2000" height="0" alt=""> Arbeitsbelastung | Haufen (`-e OMNIROUTE_MEMORY_MB`) | Container (`--memory`) |
| ----------------------------------------------------- | --------------------------------- | ---------------------- |
| Dashboard / leichter Chat                             | `1024` (Bildstandard)             | ≥ 2 g                  |
| Ein Codierungsagent                                   | `8192`                            | ≥ 10 g                 |
| Zwei gleichzeitige lange `/v1/responses`              | `10240`–`12288`                   | ≥ 12–16 g              |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

Vollständige Tabelle: [Docker Guide — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Docker -Kanal vor der Veröffentlichung:** `diegosouzapw/omniroute:next` und `diegosouzapw/omniroute:next-web` folgen dem aktuellen Standard- `release/v*` Zweig. Diese veränderlichen Tags sind nur zum Testen unveröffentlichter Fixes gedacht und sind es auch** nicht für die Produktion unterstützt** . Siehe [Docker Release-Kanäle](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

Standard- `bun install` und globale Installation (`bun install -g omniroute`) werden über Bun Laufzeiterkennung unterstützt:

- **Eingebauter `bun:sqlite`** : OmniRoute verwendet den integrierten `bun:sqlite` -Treiber von Bun, wenn es unter Bun ausgeführt wird, und greift bei Node.js oder `sql.js` auf `better-sqlite3` zurück.
- **Automatische Webpack-Bundler-Auswahl in Dev** : Development (`bun run dev`) erkennt Bun automatisch und deaktiviert Turbopack zugunsten von Webpack, um Inkompatibilitäten mit der nativen V8-Bindung zu verhindern. Produktions-Builds (`bun run build`) folgen `OMNIROUTE_USE_TURBOPACK` genau wie auf Node: Turbopack standardmäßig, `OMNIROUTE_USE_TURBOPACK=0` zum Erstellen mit Webpack (`Dockerfile.bun` macht es als `--build-arg` verfügbar).
- **Dedizierte Bun Docker-Datei** : Mehrstufiges `Dockerfile.bun` für native Bun Produktionsbereitstellungen (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
bun install
bun run dev
```

**⚡ Schnellere / schlankere Installation (nativen Build überspringen)**

Die native SQLite Engine (`better-sqlite3`) ist eine** optional** Abhängigkeit, sodass eine globale Installation niemals das Kompilieren aus der Quelle blockiert: Sie verwendet eine vorgefertigte Binärdatei, wenn eine mit Ihrem platform/Node übereinstimmt, und greift ansonsten transparent auf eine reine JS-Engine zurück (`node:sqlite` auf Knoten 22 +, andernfalls das gebündelte `sql.js` WASM). — keine Build-Tools erforderlich.

Um die Nachinstallation zu überspringen** natives Aufwärmen** vollständig (CI, kopflose oder langsame Maschinen). Hinweis: Dadurch wird nur der native SQLite -Aufwärmschritt (`scripts/postinstall.mjs`) übersprungen. Der binary-copy/repair Hook (`scripts/build/postinstall.mjs`) läuft weiterhin normal:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

Für die schnellste Installation bevorzugen Sie** pnpm** (Content-Adressed Store + Hardlinks — siehe oben). Für eine Dashboard-freie, kopflose Laufzeit verwenden Sie das Docker `base` Profil (oben) oder den [Termux-Leitfaden](docs/guides/TERMUX_GUIDE.md). Das CLI und das Web-Dashboard werden von demselben Prozess auf einem Port bedient, daher gibt es heute kein separates reines CLI-Paket.

### So können Sie einen Beitrag leisten

1. Forken Sie das Repository
2. Zweig von der** aktiv** `release/vX.Y.Z` Tipp (nicht `main`) — siehe [Branching- und Release-Modell](docs/ops/BRANCHING_MODEL.md)
3. Erstellen Sie Ihren Feature-Branch (`git checkout -b feat/amazing-feature`)
4. Übernehmen Sie Ihre Änderungen (`git commit -m 'feat: add amazing feature'`)
5. Push zum Zweig (`git push origin feat/amazing-feature`)
6. Öffnen Sie eine Pull-Anfrage mit** Basis =, `release/vX.Y.Z` Zweig**

Ausführliche Richtlinien finden Sie unter [CONTRIBUTING.md](CONTRIBUTING.md).

### Veröffentlichung einer neuen Version

```bash
# Create a release — npm publish happens automatically
VERSION=x.y.z
gh release create "v${VERSION}" --title "v${VERSION}" --generate-notes
```

## Danksagungen

OmniRoute steht auf den Schultern von Riesen. Es begann als eine Abzweigung von** [9router](https://github.com/decolua/9router)** und ein TypeScript Port des Go-Projekts** [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)** — und von da an wurde jedes Subsystem unten von einem Open-Source-Projekt inspiriert, das zuerst dort ankam. Jeder formte ein konkretes Stück OmniRoute. Dafür möchten wir uns bei allen bedanken. 🙏

> Die Anzahl ⭐ -Sterne wurde vom REST API von GitHub am 16. November 2026 bestätigt. — go gibt diesen Projekten einen Stern. Die Zählungen sind eine genau datierte Momentaufnahme und können sich natürlich ändern. GrokBridge hat an diesem Datum HTTP 404 zurückgegeben; Die Namensnennung bleibt erhalten.
