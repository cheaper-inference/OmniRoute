> **Kurz gesagt**: Installieren → Einen berechtigten Anbieter verbinden → Ihre IDE auf OmniRoute verweisen. Fertig.

---

## Schritt 1: OmniRoute installieren

Wählen Sie Ihre bevorzugte Methode:

### Option A: npm (empfohlen)

```bash
npm install -g omniroute
```

### Option B: Docker

```bash
docker run -d --name omniroute -p 20128:20128 diegosouzapw/omniroute:latest
```

`:latest` ist die höchste **veröffentlichte** stabile SemVer-Version. Das Tag folgt **nicht** dem Git-Branch `main`. Verwenden Sie für GitOps eine feste Version wie `diegosouzapw/omniroute:X.Y.Z`. Siehe [Image-Tags/Release-Kanäle](../guides/DOCKER_GUIDE.md#release-channels).

### Option C: Aus dem Quellcode

```bash
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
npm install
npm run dev
```

---

## Schritt 2: OmniRoute starten

```bash
omniroute
```

OmniRoute startet unter `http://localhost:20128`. Das Dashboard wird automatisch geöffnet.

---

## Schritt 3: Einen geeigneten Anbieter verbinden

Wählen Sie einen Anbieter, dessen Bedingungen und Kontingent Ihren Anforderungen entsprechen. Verbinden Sie unter **Dashboard → Providers** Ihr eigenes Konto oder Ihren API-Schlüssel und testen Sie anschließend die Verbindung. Kostenloser Zugriff und eine Verfügbarkeit ohne Schlüssel sind nicht garantiert.

`auto` schließt Anbieter, die mit `tos: avoid` gekennzeichnet sind, darunter Kiro, standardmäßig aus. Das Verbinden eines Kontos ändert diese Richtlinie nicht. Die Einwilligung unter **Dashboard → Combos** gilt für alle automatischen Kombinationen. Lesen Sie den [Leitfaden zu kostenlosen Kontingenten](./FREE-TIERS-GUIDE.md), bevor Sie einen Anbieter auswählen.

---

## Schritt 4: Funktion überprüfen

Erstellen Sie unter [API-Schlüssel](http://localhost:20128/dashboard/api-manager) einen neuen Schlüssel. Speichern Sie diesen Schlüssel, da er später nicht erneut angezeigt wird. Beachten Sie, dass dieser Schlüssel Tools den Zugriff auf OmniRoute ermöglicht und nicht für den Zugriff auf vorgelagerte Anbieter bestimmt ist.

```bash
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"
```

Ihre verbundenen Modelle sollten nun aufgelistet werden.

---

## Schritt 5: Ihre IDE oder CLI auf OmniRoute verweisen

Legen Sie in Ihrer IDE oder Ihrem CLI-Tool Folgendes fest:

```
Basis-URL:    http://localhost:20128/v1
API-Schlüssel: [aus Dashboard → Endpunkte kopieren]
Modell:        auto
```

Das war's! Ihre IDE verwendet nun OmniRoute mit automatischer Anbieterauswahl.

### IDE-Beispiel: VSCode/Continue.dev

1. Installieren Sie in VSCode die Erweiterung [Continue.dev](https://marketplace.visualstudio.com/items?itemName=Continue.continue).
2. Aktualisieren Sie Ihre Datei `~/.continue/config.yaml`, indem Sie die folgenden Zeilen hinzufügen:

```
  - name: OmniRoute - Auto
    provider: openai
    model: auto
    apiBase: http://localhost:20128/v1
    apiKey: <YOUR_KEY>
```

3. Wählen Sie im Chatbereich von Continue.dev `OmniRoute - Auto` aus, um Anfragen an OmniRoute zu senden.
4. (Optional) Übung für die Leser: Lassen Sie Ihre IDE die Datei `config.yaml` mit allen anderen vorkonfigurierten Konfigurationen aktualisieren 😊

### CLI-Beispiel: Codex CLI

1. Legen Sie die Umgebungsvariable dauerhaft in Ihrem Betriebssystem fest.
   Für macOS/Linux (zu Ihrer `~/.bashrc` oder `~/.zshrc` hinzufügen):

```bash
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

Für Windows (Eingabeaufforderung):

```
setx OMNIROUTE_API_KEY <YOUR_KEY>
```

2. Starten wir nun Codex, allerdings für OmniRoute konfiguriert. Führen Sie Folgendes aus:

```
omniroute launch-codex --model auto
```

Sie können dies manuell über `codex` und Befehlszeilenparameter erledigen, um Endpunkt und API-Schlüssel anzugeben. Mit dem obigen Befehl übernimmt OmniRoute jedoch alles für Sie.

Der Start mit einem einzigen Befehl funktioniert über den generischen Launcher auch für andere CLIs: `omniroute run <target>` unterstützt `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen` und `gemini` (siehe [CLI-Integrationen](../guides/CLI-INTEGRATIONS.md)).

3. Die CLI sollte nun Anfragen an OmniRoute senden.

### Prüfen, ob Ihr Tool Anfragen an OmniRoute weiterleitet

Sie können die Details der Anfrage einsehen, indem Sie in der linken Seitenleiste auf [Überwachung/Protokolle](http://localhost:20128/dashboard/logs) klicken. Durch Anklicken der Einträge werden weitere Details angezeigt. Nebenbei können Sie sehen, welche Informationen von Ihrem bevorzugten Tool übertragen werden. Dies ist sowohl zu Lern- als auch zu Debugging-Zwecken hilfreich.

## Häufig gestellte Fragen

### „Benötige ich einen API-Schlüssel?“

Der OmniRoute-API-Schlüssel authentifiziert Ihre Tools. Die Anmeldedaten für vorgelagerte Dienste hängen vom jeweiligen Anbieter ab: Einige erfordern einen API-Schlüssel oder eine Kontoanmeldung. Ein kostenloser Zugriff ist nicht garantiert.

### „Was ist `auto`?“

`auto` weist OmniRoute an, für jede Anfrage automatisch den besten Anbieter auszuwählen. Dabei werden Geschwindigkeit, Kosten, Qualität und Verfügbarkeit berücksichtigt. Weitere Informationen finden Sie im [Auto-Combo-Leitfaden](./AUTO-COMBO-GUIDE.md).

### „Wie viel kostet es?“

OmniRoute selbst ist **kostenlos und quelloffen**. Sie zahlen nur für die Anbieter, die Sie nutzen. Viele Anbieter bieten kostenlose Tarife an – siehe den [Leitfaden zu kostenlosen Tarifen](./FREE-TIERS-GUIDE.md).

### „Kann ich es mit Claude Code / Cursor / Copilot verwenden?“

**Ja!** OmniRoute funktioniert mit jedem Tool, das das OpenAI-Format unterstützt. Setzen Sie einfach die Basis-URL auf `http://localhost:20128/v1`. Konkrete Einrichtungsanweisungen finden Sie im [Leitfaden für CLI-Tools](../reference/CLI-TOOLS.md).

### „Was passiert, wenn ein Anbieter ausfällt?“

OmniRoute überspringt fehlgeschlagene Anbieter automatisch und versucht es mit dem nächsten. Sie müssen nichts tun. Weitere Informationen finden Sie im [Auto-Combo-Leitfaden](./AUTO-COMBO-GUIDE.md).
