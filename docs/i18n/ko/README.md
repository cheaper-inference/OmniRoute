## 월별 무료 토큰: ~ 11.3B(다른 사람도 포함) · ~ 90M Real

</div>

> **~ 113억 개의 무료 토큰/월**<br/> <sub> 다른 카탈로그가 계산되는 방식으로 계산됩니다. 모든 행이 합산되고 종료된 제안이 포함됩니다 </sub>
>
> **오늘 ~ 90M 진짜야**<br/> <sub> 각 공유 할당량은 한 번만 계산됩니다. 실제로 </sub> 사용할 수 있는 것
>
> **여기에 있는 모든 것은 무료입니다. 페이월이 없습니다.**<br/> ★ [마음에 드시나요? GitHub 에서 우리를 스타로 만들어주세요](https://github.com/cheaper-inference/OmniRoute)

다른 카탈로그에서는 라이브 데이터에 대한 평생 액세스 비용을 연간 US$ 19부터 US$ 49까지 청구합니다. 여기에서는 모든 것이 무료입니다. <sub> 가격은 2026-11-18에 확인되었습니다.</sub>

<sub>카탈로그는 2026년 11월 23일에 마지막으로 감사되었습니다. [→ 계산하는 방법](docs/reference/FREE_TIERS.md#how-we-count)</sub>

> **자신의 제공업체 계정을 가져오세요.** 이는 OmniRoute 의 토큰 부여가 아닌 타사 무료 계층입니다. 가입하고 공급자가 요구하는 자격 증명을 받고 사용할 수 있는 자격 증명을 연결하세요. 각 공급자는 자체 제한, 가용성 및 조건을 설정합니다.
>
> 무료 계층을 직접 쌓는 것은 수십 개의 SDKs, 수십 개의 속도 제한을 의미하며 남은 것이 무엇인지 명확하게 알 수 없습니다. OmniRoute 무료 액세스가 가능한 214개의 카탈로그 행을 유지하고 할당량이 게시된 12개의 풀에서 실제 수치를 계산합니다. 각 공유 풀은 한 번씩 계산됩니다. 지역 신원 확인(현재 ModelScope) 후에만 열리는 할당량은 지역 신원 확인 뒤에 +~ 6M이 표시되며 실제 수치에 추가되지 않습니다. 남은 것은 대시보드(`/dashboard/free-tiers`)에 표시됩니다.

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute free-tier budget card. Free tokens a month: ~11.3B as others count · ~90M real. Up to ~153M in your first month with one-time signup credits. 12 pools with a published quota and 214 catalog rows with free access behind one endpoint, catalog audited 2026-11-23. The bar shows where the real figure comes from, one segment per pool. Signup credits and free providers without a token cap are listed apart and never added to it. Live used and remaining tokens on /dashboard/free-tiers."/>

> 라이브 `/dashboard/free-tiers` 페이지의 애니메이션 요약입니다. 각 수치 계산 방법:** [docs/reference/FREE_TIERS.md#우리가계산하는방법](docs/reference/FREE_TIERS.md#how-we-count)** .
>
> <sub> 카탈로그는 2026년 11월 23일에 마지막으로 감사되었습니다. 수치는 양방향으로 움직입니다. 공급자가 무료 등급을 종료하면 실제 숫자가 줄어듭니다. 새로운 것이 착륙하고 올라갑니다. 우리는 카탈로그가 계산한 내용을 게시하며, 결코 최상의 사례를 모아서 게시하지 않습니다.</sub>

## 공급자를 설치하고 연결한 다음 하나의 엔드포인트를 통해 라우팅합니다.

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Four steps to use OmniRoute. Install with npm install -g omniroute, run omniroute, connect a provider and create an API key in the dashboard, then call http://localhost:20128/v1 with model auto."/>

```bash
# After connecting a provider, create your OmniRoute key in Dashboard → API Keys:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>`auto` 적합한 경로가 필요합니다. 새로 설치하면 적합한 키 없는 대상이 없을 수 있으며, 키 없는 공급자는 타사 클라이언트를 거부할 수 있습니다. `tos: avoid` 를 포함하여 Kiro 로 표시된 공급자는 기본적으로 자동 라우팅에서 제외됩니다. 계정을 연결해도 해당 설정이 재정의되지 않습니다. 공급자를 선택하기 전에 [무료 계층 가이드를](docs/getting-started/FREE-TIERS-GUIDE.md) 참조하세요.</sub>

<sub>빠른 시작 스크립트를 복사하여 붙여넣으세요.** 파이썬, Node.js, PHP 및 cURL** : [`examples/quickstart/`](examples/quickstart/). 단계별 버전: [빠른 시작](#quick-start).</sub>

## 콤보: 기함

1. **`auto` 로 시작하세요.** OpenAI 호환 클라이언트에서 모델을 설정합니다. OmniRoute 연결된 공급자로부터 가상 콤보를 구축하고 후보자를 실시간으로 채점합니다.
2. **더 많은 제어를 위해 콤보를 저장하세요.** 이름, 대상 목록 및 전략을 선택한 다음 해당 이름을 모델로 사용하십시오. 전략은 어떤 목표가 먼저 진행되고 나머지 목표는 어떻게 시도되는지를 설정합니다.

콤보는 모델 간에 자동으로 라우팅됩니다. 할당량 소진, 공급자 실패 또는 모델 잠금이 발생하는 경우 다음 적격하고 정상적인 대상을 시도합니다.

### 제로 구성: 그냥 `auto` 사용하세요

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your-omniroute-key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

변형은 가중치를 조정합니다. 마지막으로 알려진 양호한 라우팅은 실패할 때까지 마지막으로 성공한 공급자와 함께 유지된 후 다시 점수를 매깁니다. `auto/fast` 및 `auto/cheap` 가장 빠르거나 가장 저렴한 모델을 보장하지 않고 선호도를 표현합니다.

| 모델 ID             | 행동                                                                                                                                                                                                                           |
| :------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`              | 균형 잡힌 기본 가중치.                                                                                                                                                                                                         |
| `auto/fast`         | 낮은 대기 시간과 공급자 상태를 선호합니다.                                                                                                                                                                                     |
| `auto/cheap`        | 낮은 카탈로그 가격을 선호합니다.                                                                                                                                                                                               |
| `auto/coding`       | 코드 생성을 위한 품질 우선 가중치.                                                                                                                                                                                             |
| `auto/smart`        | 탐색이 10%인 품질 우선 가중치(기본값 5%)                                                                                                                                                                                       |
| `auto/lkgp`         | `auto` 와 동일한 가중치를 갖는 명시적인 마지막으로 알려진 양호한 라우팅.                                                                                                                                                       |
| `auto/subscription` | 실시간으로 검증된 계획 할당량만 사용합니다. 사용할 수 있는 것이 없으면 HTTP 503을 반환하고 청구 대체를 방지합니다.                                                                                                             |
| `auto/thrifty`      | → 키리스 → 무료 → 저렴한 → 프리미엄을 계획하세요. 할당량 및 휴지 기간이 허용되면 청구 모델에 도달하고 계획으로 돌아갈 수 있습니다.                                                                                             |
| `auto/offline`      | 할당량 및 속도 제한 헤드룸을 선호합니다. 요청은 계속해서 제공업체로 전달됩니다.                                                                                                                                                |
| `auto/chaos`        | 병렬로 공급자당 모델 1개, 기본적으로 최대 5개, 구성 시 10개. 모델당 하나의 업스트림 호출. 상위 모델이 실패한 경우 최상위 응답 또는 마지막으로 성공한 패널 응답을 반환합니다. 심사위원의 답변을 종합하려면 `fusion` 사용하세요. |

범주 및 선택적 계층의 예로는 `auto/coding:fast`, `auto/coding:free`, `auto/reasoning:pro` 및 `auto/vision` 있습니다. 연결된 후보가 일치하지 않으면 요청은 HTTP 503을 반환하고 풀은 좁은 상태로 유지됩니다. [자동 콤보 가이드](./docs/routing/AUTO-COMBO.md) · [구독 우선 라우팅](./docs/routing/SUBSCRIPTION_LADDER.md)

### 또는 직접 구축: 22가지 라우팅 전략

```bash
omniroute combo create my-pool --strategy fill-first \
  --models "provider-a/model-1,provider-b/model-2"
```

CLI 22가지 전략 중 15가지 전략을 허용합니다. 대시보드와 콤보 API 22개를 모두 허용합니다.

| 전략                | 행동                                                                                                                                                                                  |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`              | 순위 후보자는 16가지 요소 자동 콤보 득점 장치와 함께 생활합니다.                                                                                                                      |
| `cache-optimized`   | 캐시에 프롬프트 접두어를 보유할 가능성이 있는 계정을 선호합니다.                                                                                                                      |
| `context-optimized` | 먼저 알려진 가장 큰 컨텍스트 창을 사용해 보세요.                                                                                                                                      |
| `context-relay`     | 계정을 전환할 때 주문을 유지하고 대화 요약을 전달하세요.                                                                                                                              |
| `cost-optimized`    | 카탈로그 입력 토큰 가격을 기준으로 정렬합니다. 알 수 없는 항목은 마지막에 표시됩니다. 최종 요청 비용은 다를 수 있습니다.                                                              |
| `expiry-first`      | 만료될 가능성이 있는 지출 할당량입니다. 먼저 재설정될 때까지 시간당 남은 금액이 가장 높습니다.                                                                                        |
| `fill-first`        | 사용 가능한 첫 번째 대상이 소진되거나 실패할 때까지 유지한 다음 계속 진행하세요.                                                                                                      |
| `fusion`            | 패널을 병렬로 쿼리하고 심사위원이 하나의 답변을 종합하도록 합니다.                                                                                                                    |
| `headroom`          | 5시간 및 주간 기간 중에서 가장 많은 무료 용량을 선택하세요.                                                                                                                           |
| `jev`               | TypeSafe Jev는 순위 목록에서 어떤 항목이 실행되는지 선택합니다. 요청별로 발췌문을 보내고 유료 TypeSafe 호출을 사용하려면 `COMBO_JEV_STRATEGY_ENABLED` 켜세요. 끄면 주문이 적용됩니다. |
| `least-used`        | 이 콤보에서 기록된 요청이 가장 적은 대상을 선택하세요.                                                                                                                                |
| `lkgp`              | 마지막으로 성공한 공급자를 먼저 시도하고 그렇지 않으면 주문을 유지하십시오.                                                                                                           |
| `p2c`               | 두 개의 대상을 샘플링하고 성공률과 대기 시간을 기준으로 선택합니다.                                                                                                                   |
| `pipeline`          | 각 단계의 출력을 다음 대상에 순차적으로 공급하고 최종 답변만 반환합니다.                                                                                                              |
| `priority`          | 순서대로 타겟을 시도해 보세요. 세션 고정성은 이를 유지합니다.                                                                                                                         |
| `quota-weighted`    | 소진된 계정을 건너뛰고 남은 할당량 및 기내 부하로 추첨합니다.                                                                                                                         |
| `random`            | 각 요청을 섞습니다. 동일한 첫 번째 대상이 반복될 수 있습니다.                                                                                                                         |
| `reset-aware`       | 세션 및 주간 기간에 걸쳐 남은 할당량과 재설정 시간을 평가하세요.                                                                                                                      |
| `reset-window`      | 할당량이 가장 빨리 재설정되는 계정을 사용해 보세요.                                                                                                                                   |
| `round-robin`       | 순서대로 회전합니다. 기본적으로 대상당 3번의 성공이 가능합니다.                                                                                                                       |
| `strict-random`     | 각 대상이 반복되기 전에 한 번 앞서도록 섞인 덱에서 처리합니다.                                                                                                                        |
| `weighted`          | 가중치를 기준으로 첫 번째 대상을 그리고 나머지는 대체 대상으로 유지합니다. 분할은 통계적입니다. 엄격한 회전을 위해서는 `round-robin` 사용하세요.                                      |

할당량 전략은 5시간 및 주간 구독 창을 포함하여 공급자가 보고하는 실시간 데이터를 사용합니다. `fusion` 및 `pipeline` 요청당 여러 업스트림 호출을 수행합니다.

### 탄력성이 내장되어 있습니다: 3개의 독립된 레이어

오류는 세 가지 범위에서 처리되므로 하나의 잘못된 모델은 해당 계정을 중단하지 않고 하나의 잘못된 계정은 해당 공급자를 중단하지 않습니다.

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute resilience: 3 independent self-healing layers, the right layer for the right failure. Layer 1, provider circuit breaker (whole provider): trips only on 408/500/502/503/504, opens after 8 failures for OAuth providers or 12 for API-key providers, resets after 60s or 30s into a HALF-OPEN probe, lazy recovery; while OPEN the combo reroutes to the next provider. Layer 2, connection cooldown (one key or account): base 5s OAuth or 3s API-key, exponential backoff with an anti-thundering-herd guard, success clears the error state; one cooling key is skipped while sibling keys keep serving. Layer 3, model lockout (one model): per-model 429, 404 or access denials lock just that model, never the whole connection. Terminal states (banned, expired, credits exhausted) wait for the operator; they are not cooldowns."/>

#### 공급자 전체가 다운된 경우

그만큼** 공급자 회로 차단기** 상태 408, 500, 502, 503 또는 504에서 8(OAuth) 또는 12(API 키) 실패 후에 열립니다. 콤보는 해당 공급자가 열려 있는 동안 건너뜁니다. 60초 또는 30초 후에 하나의 프로브 요청이 닫힐지 여부를 결정합니다.

#### 하나의 키 또는 계정에 속도가 제한된 경우

그만큼** 연결 쿨타임** 5초(OAuth) 또는 3초(API 키)의 지수 백오프를 사용하여 해당 연결만 벤치에 둡니다. 동일한 제공업체의 다른 키가 계속 제공됩니다.

#### 한 모델이 거절된 경우

그만큼** 모델 잠금** 모델별 429, 404 또는 액세스 거부 후 해당 연결에서 해당 모델만 차단합니다. 동일한 연결에 있는 다른 모델은 계속 서비스를 제공합니다.

금지, 만료 및 신용 부족 연결은 대기 시간이 아닌 종료 상태입니다. 연결은 사용자가 문제를 해결할 때까지 기다립니다.

## OmniRoute 레이더

Radar는 위의 무료 계층 카탈로그의 서명된 라이브 사본이며 모든 사람에게 무료로 제공됩니다. 페이월이나 대기 기간이 없습니다. 선택형이며 GET 전용입니다. OmniRoute 클라이언트는 프롬프트, 트래픽, 공급자 구성 또는 사용 원격 측정 등 아무 것도 Radar에 보내지 않습니다.

위의 숫자는 이번 릴리스와 함께 제공된 카탈로그에서 나온 것입니다. 레이더는 릴리스 간에 최신 데이터를 표시할 수 있습니다. 매주 새로운 무료 혜택과 프로모션이 추가됩니다. 레이더에서 실제 숫자가 늘어나는 것을 지켜보세요.

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2

omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"
omniroute setup-whycodes && omniroute run whycodes --model glm/glm-5.2
```

## 프라이빗 & 로컬 우선

<img src="./docs/diagrams/privacy-local.svg" width="100%" alt="Private and local-first — OmniRoute's gateway and control plane run on your machine. ## 전체 CLI, MCP 및 A2A

> OmniRoute 는 다음과 같은 명령줄 클라이언트를 제공합니다.** 91개의 최상위 명령 및 명령 그룹** (하위 명령을 세는 754개의 명령),** 110개의 도구와 33개의 범위를 갖춘 MCP 서버** , 그리고** 6가지 기술을 갖춘 A2A 에이전트** . 스크립트, 터미널 및 AI 에이전트는 모두 동일한 게이트웨이를 작동할 수 있습니다.

### CLI 뿐만 아니라 실제 `start`

```bash
omniroute                 # start the gateway and dashboard (port 20128)
omniroute setup           # guided first-run wizard
omniroute repl            # interactive chat in the terminal (/model /combo /skill /memory)
omniroute chat "hello"    # one-shot prompt; also reads --file or --stdin
omniroute doctor          # check config, database, ports, Node runtime and native deps
```

전역 `--output table|json|jsonl|csv` 플래그를 사용하면 스크립트와 CI 에서 동일한 명령을 사용할 수 있습니다.

### 원격 모드: 노트북의 CLI, 서버의 OmniRoute

원격 서버에 한 번 로그인하십시오. CLI 그것을 다음과 같이 저장합니다.** 문맥** , 이후 명령은 다시 전환할 때까지 해당 서버에 대해 실행됩니다.

```bash
omniroute connect omniroute.example.com          # asks for the password, saves a scoped token as a context
omniroute models                                 # runs against the remote server
omniroute configure codex                        # picks a remote model, writes a local Codex profile
omniroute tokens create --name ci --scope read   # mint a narrower token for another machine
omniroute contexts use default                   # switch back to the local server
```

### 에이전트 연결

에이전트 또는 자체 코드는 이러한 인터페이스를 통해 라우팅, 공급자, 콤보, 캐시, 압축 및 메모리를 구동할 수 있습니다. HTTP 경로는 기본적으로 `http://localhost:20128` 에서 게이트웨이에 의해 제공됩니다.

| 인터페이스                    | 엔드포인트 또는 명령       | 다음 용도로 사용하세요.                                                    |
| ----------------------------- | -------------------------- | -------------------------------------------------------------------------- |
| stdio를 통한 MCP              | `omniroute --mcp`          | Claude 데스크탑, Cursor 및 기타 로컬 MCP 클라이언트                        |
| 스트리밍 가능한 HTTP 통한 MCP | `/api/mcp/stream`          | 원격 MCP 클라이언트: 110개 도구, 33개 범위, 감사 로그에 기록된 모든 호출   |
| MCP 대신 SSE                  | `/api/mcp/sse`             | 여전히 SSE 전송을 사용하는 클라이언트                                      |
| A2A 발견                      | `/.well-known/agent.json`  | 에이전트 카드: OmniRoute 무엇을 할 수 있는지 다른 에이전트에게 알려줍니다. |
| A2A 실행                      | `POST /a2a`                | 6가지 기술에 걸쳐 SSE 통해 동기식 또는 스트리밍되는 JSON-RPC 2.0 작업      |
| REST API                      | `/v1/*`                    | OpenAI 호환 채팅, 응답, 임베딩, 이미지, 오디오 및 OCR                      |
| 웹훅                          | `/api/webhooks`            | Slack, Discord, Telegram 또는 HMAC 서명이 있는 모든 URL 에 대한 이벤트     |
| 원격 CLI                      | `omniroute connect <host>` | 범위가 지정된 액세스 토큰을 사용하여 원격 인스턴스 구동                    |

6가지 A2A 기술은 `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report` 및 `list-capabilities` 입니다.

**연결하기 전에:**

- **HTTP 통한 MCP 비활성화되어 시작됩니다.** `omniroute mcp enable --transport streamable-http` 사용하거나 대시보드의 엔드포인트 페이지에서 활성화하세요. 한 번에 하나의 HTTP 전송이 활성화됩니다. `streamable-http` `/api/mcp/stream` 제공하고, `sse` `/api/mcp/sse` 제공합니다.
- **A2A 비활성화되어 시작됩니다.** 대시보드의 엔드포인트 페이지에서 활성화하세요. 그런 다음 `POST /a2a` `/v1` 와 동일한 API 키 규칙을 따릅니다.
- **원격 MCP 적합한 키가 필요합니다.** `/api/mcp/*` 기본적으로 루프백에만 응답합니다. 다른 호스트에서 `manage` 또는 `admin` (모든 도구) 또는 `mcp:connect` 와 필요한 도구 범위를 사용하여 키를 보냅니다. `manage`/`admin` 없는 키의 경우 도구 범위가 항상 적용됩니다.

```bash
# Give Claude Code the OmniRoute toolset over MCP:
omniroute mcp enable --transport streamable-http
claude mcp add --transport http omniroute http://localhost:20128/api/mcp/stream \
  --header "Authorization: Bearer <api-key-with-manage-scope>"
```

### 작동 방식 — 파이프라인, 아키텍처 및 저축 수학

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: an illustrative 10,000-token client request passes through 12 composable engines — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra and OmniGlyph — and can reach the provider at about 1,080 tokens in the documented stacked example. Structured content is protected by preservation guards and per-step fidelity gates; explicit lossy or experimental modes may transform eligible content."/>

기본 스택 콤보는 `RTK → Caveman` 실행합니다. 둘 다 동일한 tool/context 페이로드에서 작동하면 비용 절감 효과는 다음과 같습니다.

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

코드 블록, URLs, JSON 및 구조화된 데이터는** 항상 보호됨** 보존 엔진에 의해.

> **소수의 토큰으로 효과를 발휘할 수 있는데 왜 많은 토큰을 사용합니까?** 모든 요청은 OmniRoute 의 압축 파이프라인을 통과합니다.** 투명하게** — 클라이언트가 변경되지 않습니다. 지금은** 12개의 컴포저블 엔진 스택** [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K +), [LLMLingua-2](https://github.com/microsoft/LLMLingua) 및 [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR)의 아이디어를 기반으로 구축된 라우팅 콤보 — 별로 순서대로 실행되고 혼합 및 일치됩니다.

#### 출력 스타일

| 스타일                                  | <img width="2000" height="0" alt=""> 그것이 하는 일                      |
| --------------------------------------- | ------------------------------------------------------------------------ |
| 간결한 산문                             | 기술적 세부 사항을 유지하면서 필러와 헤징을 잘라냅니다.                  |

#### 적응형 컨텍스트 예산

| 환경 | 옵션                                                                                                                                                                               |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 정책 | `reserve-output` (기본값)는 응답을 위한 공간과 안전 여유를 따로 설정합니다. `percentage` 컨텍스트 창의 공유를 사용합니다. `absolute` 고정 토큰 대상을 설정합니다.                  |
| 방법 | `floor` 선택한 계획을 컨텍스트 창에 맞게 에스컬레이션할 수 있습니다. `replace-autotrigger` 자동 에스컬레이션을 위해 예산을 사용합니다. `off` 토큰 임계값 자동 트리거를 유지합니다. |

#### 압축이 결정되는 곳

| 주문하다 | <img width="2000" height="0" alt=""> 소스         |
| -------- | ------------------------------------------------- |
| 1        | 인식된 `x-omniroute-compression` 요청 헤더        |
| 2        | 라우팅 콤보 재정의                                |
| 3        | 활성 명명된 프로필                                |
| 4        | 적응형 컨텍스트 예산 또는 토큰 임계값 자동 트리거 |
| 5        | 압축 패널 기본값                                  |
| 6        | 요금제가 적용되지 않으면 꺼짐                     |

전역 압축 스위치는 이 테이블보다 우선순위가 높습니다. `X-OmniRoute-Compression` 응답 헤더는 `<mode>; source=<source>` 보고합니다.

[압축 가이드](docs/compression/COMPRESSION_GUIDE.md) · [RTK 압축](docs/compression/RTK_COMPRESSION.md) · [압축 엔진](docs/compression/COMPRESSION_ENGINES.md)

옵트인 평가 하네스(`npm run eval:compression`)는 고정 코퍼스의 응답 충실도와 토큰 절약을 비교합니다.

## 추가 설치 방법 — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

`:latest` 가장 높은 것을 따릅니다** 출판됨** 안정적인 SemVer. git `main` 는 추적하지 않습니다. GitOps 에 `:X.Y.Z` 고정하세요. [Docker 릴리스 채널을](docs/guides/DOCKER_GUIDE.md#release-channels) 참조하십시오. 이미지 핀**`OMNIROUTE_MEMORY_MB=1024`** . 대시보드와 가벼운 대화에는 충분합니다.** 코딩 에이전트** ( Claude 코드의 `POST /v1/responses`, Codex, Grok, …)에는 훨씬 더 큰 V8 힙이 필요하거나 두 개의 겹치는 긴 컨텍스트에서 ~ 12 GiB 의 프로세스 `FATAL ERROR` s가 필요합니다. 힙 위의 컨테이너 크기를 조정합니다(네이티브 버퍼는 V8 외부에 있음).

| <img width="2000" height="0" alt=""> 워크로드 | 힙(`-e OMNIROUTE_MEMORY_MB`) | 컨테이너(`--memory`) |
| --------------------------------------------- | ---------------------------- | -------------------- |
| 대시보드/간단한 채팅                          | `1024` (이미지 기본값)       | ≥ 2g                 |
| 하나의 코딩 에이전트                          | `8192`                       | ≥ 10g                |
| 두 개의 동시 긴 `/v1/responses`               | `10240`–`12288`              | ≥ 12~16g             |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data cheaperinference/omniroute:latest
```

전체 표: [Docker 가이드 — 런타임 RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **시험판 Docker 채널:** `diegosouzapw/omniroute:next` 및 `diegosouzapw/omniroute:next-web` 현재 기본 `release/v*` 분기를 따릅니다. 이러한 변경 가능한 태그는 아직 출시되지 않은 수정 사항을 테스트하는 용도로만 사용되며** 프로덕션에서는 지원되지 않습니다.** . [Docker 릴리스 채널을](docs/guides/DOCKER_GUIDE.md#release-channels) 참조하세요.

**🥟 Bun**

표준 `bun install` 및 전역 설치(`bun install -g omniroute`)는 Bun 런타임 감지를 통해 지원됩니다.

- **내장 `bun:sqlite`** : OmniRoute Bun 에서 실행될 때 Bun 의 내장 `bun:sqlite` 드라이버를 사용하고 Node.js 또는 `sql.js` 에서는 `better-sqlite3` 로 돌아갑니다.
- **개발 시 자동 Webpack 번들러 선택** : 개발(`bun run dev`)은 기본 V8 바인딩 비호환성을 방지하기 위해 자동으로 Bun 감지하고 Webpack을 위해 Turbopack 비활성화합니다. 프로덕션 빌드(`bun run build`)는 Node에서와 똑같이 `OMNIROUTE_USE_TURBOPACK` 따릅니다. 기본적으로 Turbopack Webpack으로 빌드하기 위해 `OMNIROUTE_USE_TURBOPACK=0` (`Dockerfile.bun` 이를 `--build-arg` 로 노출합니다).
- **전용 Bun Dockerfile** : 기본 Bun 프로덕션 배포를 위한 다단계 `Dockerfile.bun` (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Install and run with Bun
bun install
bun run dev
```

**⚡ 더 빠르고 간결한 설치(기본 빌드 건너뛰기)**

기본 SQLite 엔진(`better-sqlite3`)은** 선택 과목** 따라서 전역 설치는 소스에서 컴파일하는 것을 차단하지 않습니다. platform/Node 와 일치하는 경우 미리 빌드된 바이너리를 사용하고, 그렇지 않으면 순수 JS 엔진(노드 22의 `node:sqlite` + 그렇지 않으면 번들로 제공되는 `sql.js` WASM) — 로 투명하게 대체됩니다. 빌드 도구가 필요하지 않습니다.

설치 후 단계를 건너뛰려면** 네이티브 워밍업** 완전히(CI, 헤드리스 또는 느린 머신). 참고: 이는 기본 SQLite 준비 단계(`scripts/postinstall.mjs`)만 건너뜁니다. binary-copy/repair 후크(`scripts/build/postinstall.mjs`)는 여전히 정상적으로 실행됩니다.

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 also skips it
```

가장 빠른 설치를 원하시면** pnpm** (컨텐츠 주소 지정 저장소 + 하드 링크 — 위 참조) 대시보드가 없고 헤드리스 런타임의 경우 Docker `base` 프로필(위) 또는 [Termux 가이드를](docs/guides/TERMUX_GUIDE.md) 사용하세요. CLI 와 웹 대시보드는 하나의 포트에서 동일한 프로세스로 제공되므로 현재 별도의 CLI 전용 패키지는 없습니다.

### 기여하는 방법

1. 저장소 포크
2. 에서 지점** 활동적인** `release/vX.Y.Z` 팁 ( `main` 아님 ) — [분기 및 릴리스 모델](docs/ops/BRANCHING_MODEL.md) 참조
3. 기능 브랜치 생성(`git checkout -b feat/amazing-feature`)
4. 변경 사항 커밋(`git commit -m 'feat: add amazing feature'`)
5. 지점으로 푸시(`git push origin feat/amazing-feature`)
6. 다음으로 끌어오기 요청을 엽니다.** 기본 =, `release/vX.Y.Z` 분기**

자세한 지침은 [CONTRIBUTING.md](CONTRIBUTING.md) 참조하세요.

## 감사의 말

OmniRoute 거인의 어깨 위에 서 있습니다. 그것은 포크로 시작되었습니다** [9라우터](https://github.com/decolua/9router)** Go 프로젝트의 TypeScript 포트** [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)** — 와 거기에서 아래의 모든 하위 시스템은 먼저 도착한 오픈 소스 프로젝트에서 영감을 얻었습니다. 각각은 OmniRoute 의 콘크리트 조각을 형성했습니다. 이것은 그들 모두에게 감사하는 마음입니다. 🙏

> ⭐ 별 수는 2026년 11월 16일 GitHub 의 REST API 에서 확인되었습니다. — go는 이 프로젝트에 별을 부여합니다. 개수는 정확한 날짜의 스냅샷이며 자연스럽게 변경됩니다. GrokBridge 해당 날짜에 HTTP 404를 반환했습니다. 그 속성은 유지됩니다.
