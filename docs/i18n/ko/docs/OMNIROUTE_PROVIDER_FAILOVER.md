재시도 결정이 내려지기 전에 실패가 분류됩니다.

시간 초과, 네트워크 오류, 속도 제한 및 공급자 5xx 응답과 같은 일시적인 오류는 장애 조치될 수 있습니다. 소진된 할당량 또는 크레딧(할당량 429 또는 402 지불 필요)은 동일한 공급자에서 결코 재시도되지 않지만 할당량이 별도인 다른 공급자로 장애 조치됩니다. 인증 오류, 권한 오류, 유효하지 않은 요청, 사용할 수 없는 모델 및 알 수 없는 오류는 맹목적으로 재시도되지 않습니다.

기본 교차 공급자 정책은 최대 3번의 공급자 시도, 재시도 속도 제한 및 시간 초과를 허용하고 소진된 할당량에 대한 장애 조치를 허용하며 임시 회로 상태와 별도로 관리 비활성화를 유지합니다.

## 적용되는 곳

- **콤보** 콤보 자체의 전략과 설정에 따라 대상 간 장애 조치를 수행합니다.
- **베어 모델 ID** ( `provider/` 접두사 없음) 여러 활성 공급자가 제공하는 정확한 이름의 조합 없이 먼저 공급자 추론 선택으로 전송됩니다. 해당 시도가 정책 장애 조치 방식으로 실패하면 해당 ID를 제공하는 다음 활성 공급자에게 동일한 요청이 전송됩니다. 응답에는 응답하기 전에 시도한 공급자 수와 함께 `x-omniroute-fallback-attempts` 포함됩니다.
  - 각 대체 항목은 추론이 선택한 것처럼 정확하게 인증됩니다. API 키가 차단하거나 허용하지 않는 대상은 업스트림 호출 없이 건너뛰고 클라이언트는 이름을 지정하지 않은 대상에 대한 정책 거부가 아니라 실제 업스트림 오류를 수신합니다.
  - 실패한 응답만 계속 진행됩니다. 첫 번째 스트리밍 바이트 이후에는 아무것도 장애 조치되지 않습니다.
  - 긴급 대체 모델 교체는 요청한 모델의 모든 공급자가 실패한 후에만 적용됩니다.
  - 연결(`x-omniroute-connection`)에 고정된 요청은 그대로 유지됩니다.
  - 접두사가 붙은 ID(`provider/model`)는 다른 공급자로 다시 라우팅되지 않습니다.

회로 상태는 `closed`, `open` 및 `half_open` 입니다. 쿨다운은 제한된 프로브를 예약합니다. 성공적인 프로브는 회로를 닫고 실패한 프로브는 회로를 다시 엽니다.
