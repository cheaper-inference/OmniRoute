`copilot-m365-web` (별칭 `m365copilot`)는 `m365.cloud.microsoft/chat` 에서 인증된 Microsoft 365 Copilot 세션을 통해 OpenAI 형식 채팅 요청을 보냅니다. 이는 비공식 기본 통합이므로 별도의 프록시 프로세스나 로컬 호스트 업스트림이 필요하지 않습니다. 공급자 ID, 별칭 및 기존 가져온 연결은 변경되지 않습니다. `copilot-web` 는 `copilot.microsoft.com` 의 소비자 서비스를 제공하는 다른 공급자입니다.

> **웹 쿠키 제공업체를 처음 사용하시나요?**
>
> 읽다**`docs/getting-started/WEB-COOKIE-GUIDE.md`** 이 공급자별 가이드를 따르기 전에 일반 설정 프로세스, 인증 지침, 제한 사항 및 문제 해결에 대해 알아보세요.
>
> **레거시 가져오기의 경우:** 이 공급자의 자격 증명은 다음과 같습니다.** 쿠키가 아니야** . `m365.cloud.microsoft` 에서 쿠키를 복사하지 마세요. 자격 증명은 WebSocket URL 쿼리 매개변수 및 경로 세그먼트이며 둘 다 DevTools 네트워크 탭에서 읽습니다.

## 전제 조건

- `m365.cloud.microsoft/chat` 에서 Copilot 에 액세스할 수 있는 Microsoft 365 계정
- DevTools WebSocket 검사를 위한 Chromium 기반 브라우저(Chrome, Edge)
- 해당 계정에서 요청된 모델에 대한 액세스 가용성은 테넌트 및 라이선스에 따라 다릅니다.

## 기본 로그인(회사 또는 학교 계정)

선택하다**Microsoft 365 Copilot → 연결** 로그인 시도를 준비합니다. 대시보드는 PKCE 와 함께 인증 코드 흐름을 사용합니다. Microsoft 비밀번호나 MFA 코드를 묻지 않습니다.

1. 열기** 빈 브라우저 탭** , 그런 다음 엽니다.**DevTools → 네트워크** 그리고 활성화** 로그 보존** . Microsoft 로 이동하기 전에 이 작업을 수행하십시오. Windows SSO 즉시 완료될 수 있습니다.
2. 연결 대화 상자에 표시된 인증 URL 복사하고 준비된 탭에서 탐색하세요. Microsoft 의 계정 선택을 완료하거나 요청 시 MFA 완료하세요.
3. 보존된 네트워크 로그에서 `https://login.microsoftonline.com/common/oauth2/nativeclient` 에 대한 요청을 찾아 전체 복사** URL 요청** .
4. 해당 URL 연결 대화 상자에 붙여넣고 연결하세요. 원시 코드나 최종 `wrongplace` 주소 표시줄 URL 붙여넣지 마십시오. 필요한 콜백은 임시 탐색입니다.

각 시도는 10분 후에 만료되며 한 번만 사용할 수 있습니다. 서버는 코드를 교환하기 전에 상태, PKCE 검증자 및 재인증 대상을 확인합니다. 만료 또는 교환 실패 후 새로운 시도를 시작하십시오. 서버를 다시 시작한 후에는 시도가 유지될 수 없습니다.

토큰은 기존 연결 자격 증명 저장소와 새로 고침 경로를 사용합니다. 연결을 재인증하려면 단순히 동일한 이메일이 아닌 동일한 Microsoft tenant/object ID가 필요합니다. 운영자 naming/settings 유지하고 더 이상 사용되지 않는 가져온 자격 증명을 대체합니다. 기본 로그인은 work/school 계정용입니다. 레거시 가져오기 경로는 기존 연결 및 지원되는 계층 구성에 계속 사용할 수 있습니다.

전체 콜백 URL 는 일회성 자격 증명입니다. 스크린샷, 로그, 지원 메시지 또는 커밋에 이를 포함하지 마십시오. 이 흐름은 서버에서 브라우저를 열거나, 브라우저 기록을 검사하거나, 로컬 콜백 서버를 시작하지 않습니다.

## 자격 증명 캡처(WebSocket 방법)

1. `https://m365.cloud.microsoft/chat` 에 로그인하고 대화를 시작하세요.
2. 열려 있는**DevTools → 네트워크** .
3. 필터링 기준**WS** (WebSocket).
4. Chathub WebSocket 연결을 클릭합니다. `wss://substrate.office.com/m365Copilot/Chathub/` 로 시작하는 URL 찾으세요.
5. 그로부터** URL 요청** , 복사:
   - `access_token` 쿼리 매개변수 값(단기간 JWT).
   - `/Chathub/` 뒤의 Chathub 경로 세그먼트(예: `<oid>@<tenant>`).

전체 URL 의 형식은 다음과 같습니다.

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute 에서 다음을 선택하세요.**Microsoft Copilot** , 레거시 API-key/import 옵션을 선택하고 자격 증명을 다음 형식으로 붙여넣습니다.

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. 딸깍 하는 소리** 연결 테스트** 그리고** 구하다** .

## 자격 증명 캡처(HAR 가져오기)

WebSocket URL 에서 값을 수동으로 복사하는 대신 DevTools HAR 파일을 내보낼 수 있습니다.

1. 열려 있는**DevTools → 네트워크** .
2. Microsoft 365 Copilot 대화를 시작하거나 계속합니다(이렇게 하면 WebSocket 연결이 트리거됩니다).
3. 네트워크 패널을 마우스 오른쪽 버튼으로 클릭하고** 콘텐츠와 함께 모두 HAR 로 저장** .
4. OmniRoute 에서는 다음을 사용합니다.** .har 파일 가져오기** 공급자 연결 대화 상자의 버튼입니다.

OmniRoute HAR 에서 Chathub WebSocket URL 검색하고, `access_token` 및 `chathubPath` 를 추출하고, 자격 증명 필드를 자동으로 채웁니다. HAR 가져오기는 JWT 만료를 디코딩하고 남은 토큰 수명을 표시합니다.

> **실제 HAR 내보내기, 액세스 토큰 또는 새로 고침 토큰을 커밋하지 마세요.** 테스트 및 문서 값은 항상 자리 표시자여야 합니다.

## 토큰 수명 및 새로 고침

`access_token` 는 수명이 짧습니다(일반적으로**~ 75분** ). 사용 가능한 새로 고침 토큰이 없으면 만료 후 자격 증명을 다시 캡처해야 합니다.

### `refreshToken` 사용한 자동 새로 고침

Microsoft 365 공급자의 경우** 연결 추가** 또는** 연결 수정** 대화 상자, 열기** 고급 설정 → 새로 고침 토큰(선택 사항)** . `substrate.office.com/sydney` 범위에 대한 Microsoft OAuth 새로 고침 토큰을 붙여넣고 저장합니다. 입력은 마스크되어 있으며 저장된 토큰으로 미리 채워지지 않습니다. 편집할 때 기존 토큰을 유지하려면 공백으로 남겨두세요. 교체하려면 새 토큰을 붙여넣으세요.

기본 로그인은 Microsoft 새로 고침 토큰을 반환할 때 새로 고침 토큰을 획득합니다. 레거시 가져오기의 경우 기존 호환 가능한 Microsoft 인증 코드 부여를 사용하세요. 이 공급자는 장치 코드 흐름을 구현하거나 약속하지 않습니다. 새로 고침 토큰이 구성되면 OmniRoute 요청 전에 `access_token` 를 확인하고 새로 고침이 필요할 때만 새로 고칩니다. 또한 성공적인 새로 고침은 교체된 새로 고침 토큰을 유지하여 새로 고침 토큰이 유효한 상태로 유지되는 동안 수동으로 다시 캡처하는 것을 방지합니다.

`refreshToken` 설정되지 않은 경우 만료될 때마다 WebSocket 자격 증명을 수동으로 다시 캡처해야 합니다.

### 계층 선택

| 층           | 별명       | 표면                |
| ------------ | ---------- | ------------------- |
| `individual` | _(기본)_   | 소비자 M365 Copilot |
| `edu`        | `included` | 교육용 M365 Copilot |
| `enterprise` | `work`     | 업무용 M365 Copilot |

계층을 설정하세요.** 고급 설정 → Copilot 계층** . 기본 로그인에서는 이를 설정하지 않으므로 문서화된 모델 IDs 사용할 때 업무용 계정은 `enterprise` (별칭 `work`) 및 교육 계정 `edu` 선택해야 합니다. 이러한 계정은 자체 톤, 시나리오 및 라이선스 유형을 선택하지만 에이전트 및 호출 옵션은 여전히 계층에서 제공되며 업무 테넌트에서 개별 기본값이 실패할 수 있습니다. 등급을 변경해도 모델 라이선스가 부여되지는 않습니다. 명시적인 고급 프로토콜 재정의가 우선하며 필요한 연결 값을 알고 있는 경우에만 사용해야 합니다.

## 모델 및 라우팅

기본 카탈로그에는 문서화된 모든 독립형 IDs 와 4개의 원래 기본 IDs 포함되어 있습니다. 카탈로그는 계정 자격 조사가 아닌 정적이고 계정 독립적입니다. 유료 경로 및 호환성 별칭은 연결된 계정에서 사용할 수 없는 경우에도 계속 나열됩니다. 모델 표시 라벨에는 공급자 이름과 모델별 가용성 상용구가 생략되어 있습니다. 공급자는 남아있다**Microsoft Copilot** . 표시된 라벨** 별명** 또는** 유산** 과거 모델 버전을 보장하지 않고 기존 식별자와 프로토콜 매핑을 유지합니다. 독립형 프록시** /models에서 가져오기** 이 기본 WebSocket 공급자에는 지침이 적용되지 않습니다.

| 모델 패밀리       | 정식 IDs                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| 오토매틱          | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| 이전 GPT          | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude 소네트     | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude 오퍼스     | `claude-opus`, `claude-opus-4.8`                                                                 |

`auto`, `quick`, `think-deeper` 와 같은 별칭 및 버전 별칭도 등록됩니다. 기존 `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` 및 `copilot-m365-gpt-5-5-chat` 계속 유효합니다. 문서화된 IDs 제공자 접두어(`copilot-m365-web/claude-opus` 또는 `m365copilot/claude-opus`)가 필요합니다. 대부분은 일반 단어이거나 다른 공급업체의 모델 이름이므로 베어 `claude-opus` 이 제공자 없이 라우팅을 계속합니다. 등록은 Microsoft 모든 계정에 해당 모델을 제공한다는 약속이 아닙니다. 독립형 IDs 공개 [프로토콜 카탈로그](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) (내보낸 모델-톤 맵 및 해당 모델 인식 시나리오 메타데이터)를 따릅니다. 모든 기본 프로필은 `availability: "unverified"` 유지합니다. 카탈로그에 포함한다고 해서 성공적인 계정 테스트가 아닙니다.

- 명시적인 모델 라이센스 거부 반환** 403** 502가 아닌 `m365_model_not_licensed`. 라우팅은 connection/model 쌍을 잠그고 연결에 라이선스가 있는 모델을 사용할 수 있게 합니다.
- `InvalidCopilotLicense` 는 계정 수준 라이선스 거부이며 `m365_account_not_licensed` 로 별도로 보고됩니다.
- 사용자별 제한이 반환됩니다.** 429** `m365_throttled` 사용하여 연결을 식힙니다. 우선 접근 소진 반환** 429** `priority_access_exhausted` 이며 모델 범위입니다. `errorCode: "ReasoningTurnExhausted"` 사용한 `OutOfCredits` 의 결과 반환** 429** 대신 `reasoning_turns_exhausted` 는 모델 범위에 적용되며 재설정 시간이 요구되지 않습니다. 빠른 톤이 계속 제공되는 동안 "더 깊이 생각해 보세요" 톤을 제한하는 작업 세입자가 보고되었습니다. 그 범위는 소비자 관찰이며 이 저장소가 재현한 것이 아닙니다. 따라서 라우팅은 동일한 쿨타임 동안 해당 연결에서 `gpt-5.5` 및 `gpt-5.6` 의 다른 문서화된 Think deep 모델을 회전에서 제외하고 빠른 신호음 및 기타 모든 실패를 자체 모델에 남겨 둡니다. 제공된 재시도 힌트는 유지됩니다. 누락된 재설정은 알려진 재설정 시간으로 광고되지 않습니다.
- Copilot 안전 거부(`Disengaged`)가 반환됩니다.** 400** `provider_safety_rejection`, 공유 제공자 안전 중지 라벨입니다. 이는 연결 상태에 영향을 주지 않으며, 클라이언트 SDKs 400을 재시도하지 않으며, `PROVIDER_SAFETY_STOPS_TERMINAL` 활성화된 콤보 라우팅은 다른 대상에 대해 요청을 재생하는 대신 거기서 중지됩니다.
- 한 연결에 대한 요청은 기존 계정 세마포를 통해 직렬화됩니다. 병렬 패널보다 우선순위 대체를 선호합니다. 직렬화만으로는 Microsoft 의 대화 속도 제한이 제거되지 않습니다.

## 요청 동작 및 제한

- 도구는** 프롬프트 에뮬레이션** , 기본 Microsoft 함수 호출이 아닙니다. 도구 지원 요청은 하나의 버퍼링된 생성을 사용합니다. 도구를 선택하는 데 또 다른 세대를 소비하지 않습니다. 지원되는 유효한 인수 형태가 있는 선언된 도구만 호출로 반환됩니다.
- 단일 후행 예가 포함된 긴 구조화된 답변은 산문으로 보존됩니다. 이는 의도의 증거가 아닌 경험적 방법입니다. 애플리케이션은 여전히 자체 도구 권한을 적용해야 합니다.
- 이미지 입력은 웹 클라이언트가 보내는 방식으로 작동합니다. 각 이미지 부분(데이터 URL 인 `image_url` 또는 공개 HTTPS URL 또는 응답 `input_image`)은 채팅 토큰을 사용하여 차례의 대화에 `/m365Copilot/UploadFile` 에 업로드되고 메시지는 `ImageFile` 주석으로 이를 가리킵니다. 텍스트는 해당 위치를 표시합니다(`[image 1]`, …). 새로운 대화는 기록의 모든 이미지를 업로드하고, 계속되는 대화는 새 메시지의 이미지만 업로드합니다. 각각 최대 10 MiB 의 PNG, JPEG, GIF 또는 WebP 이미지 최대 10개(요청당 40 MiB ) 형식은 바이트에서 읽혀집니다. HTTPS URLs 는 공개 전용 DNS 고정 원격 이미지 가드를 통해 가져옵니다. 업로드가 실패하면 요청이 실패합니다(** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` 또는 `m365_image_invalid`); 주어진 이미지 없이는 회전이 진행되지 않습니다. 텍스트가 아닌 다른 부분(오디오, 파일)은 자동으로 삭제되지 않고 명시적으로 거부됩니다.
- 후속 요청은 동일한 업스트림 대화를 계속하고 이전 응답 이후의 메시지만 보냅니다. 해당 응답을 정확하게 확장해야 합니다. 동일한 연결, 모델 프로필 및 도구 세트; 변경되지 않은 기록(모든 메시지에 대한 sha256 체인) 그리고 응답의 도구 호출 ID 또는 해당 텍스트(최대 공백)입니다. 다른 것(편집된 기록, 동일한 첫 번째 메시지가 있는 다른 세션, 다른 응답, 30분 동안 유휴 상태이거나 Copilot 의 600개 메시지 한도에 가까운 대화, ID가 없는 연결)은 전체 기록과 함께 새로운 대화를 시작합니다. 실패한 차례는 결코 재개되지 않으며 내용이 없는 `InternalError` 새로운 대화에서 한 번 다시 전송됩니다(** 502** 다시 실패하면 `m365_internal_error` ). 계속되는 내용은 프로세스 메모리에 보관됩니다. 다시 시작하면 새로운 대화가 시작됩니다.
- 모든 차례는 Copilot 의 임시 채팅(`disableMemory=1`)에서 실행됩니다. 대화는 실행되는 동안 컨텍스트를 유지하며 계정의 채팅 기록에는 전혀 표시되지 않습니다. 따라서 모델 테스트, 모두 테스트 및 콤보 테스트는 대화를 중단하지 않고 이 공급자를 조사할 수 있습니다.
- 턴에는 120초의 유휴 기한과 제한된 전체 기한이 있습니다. 최종 답변, 진행 필터링 및 취소는 기본 transport/composer. 에서 처리됩니다.
- 웹 기반 답변은 소스를 유지합니다. Copilot 개인용 제어 문자로 인용을 인라인으로 표시하고 소스를 `references` 로 보냅니다. 각 마커는 일치하는 `url_citation` 주석(링크를 전달하는 Copilot 의 `message.annotations` 또는 `delta.annotations` )과 함께 번호가 매겨진 Markdown 링크(`[1](https://…)` 또는 zqe가 마커를 링크 대상으로 사용한 경우 기본 URL )가 됩니다. 도착하지 않는 소스는 삭제되므로 마커가 클라이언트에 도달하지 않습니다. 스트리밍할 때 인용 후의 텍스트는 소스가 도착할 때까지 기다립니다.
- Copilot 의 추론 요약(`ChainOfThoughtSummary`)은 모델이 하나를 보낼 때 `reasoning_content` 로 반환되며 결코 답변의 일부로 반환되지 않습니다. 자체적으로 다시 작성되는 요약은 차례를 실패하지 않고 스트리밍을 중지합니다.
- 콘텐츠 이전에 licence/throttle 실패는 스트리밍이 요청된 경우에도 HTTP 403/429 를 유지합니다. 콘텐츠가 시작된 후 실패는 SSE 오류 이벤트이며 결코 성공적인 완료가 아닙니다. 추가 전용 스트리밍으로 표현할 수 없는 업스트림 재작성은 명시적인 스트림 오류입니다. 비스트리밍 및 버퍼링된 도구 응답은 최종 텍스트를 유지합니다.
- Copilot 연결 자체를 거부하면 해당 응답은 다음과 같이 보고됩니다.** 401** 거부되거나 만료된 로그인의 경우 `m365_unauthorized` (다시 로그인)** 429** 조절을 위한 `Retry-After` 사용하고 그렇지 않은 경우 핸드셰이크 실패는 일반적인 연결 실패가 아닙니다.

## 이미지 생성

`model: "copilot-m365-web/m365-copilot-image"` 가 포함된 `POST /v1/images/generations` (별칭 `m365copilot/m365-copilot-image`)는 웹 클라이언트와 마찬가지로 Copilot 의 내장 이미지 도구를 사용하여 그립니다. 각 이미지는 Copilot 한 차례입니다. 웹 클라이언트의 이미지 옵션 세트를 선택하고 `GenerateGraphicArt` 선언하며, 이미지는 Microsoft 의 Designer 서비스에 있는 아티팩트를 가리키는 진행 항목에 도착합니다. 해당 아티팩트는 채팅 토큰을 거부하므로 OmniRoute 연결의 새로 고침 토큰에서 디자이너 토큰을 생성하고 바이트를 다운로드합니다. 토큰은 `designerapp.officeapps.live.com` 로만 전송됩니다.

- 기본 로그인 연결(새로 고침 토큰)이 필요합니다. 붙여넣은 토큰이 실패합니다.** 400** 턴이 끝나기 전에.
- `n` 는 1~4이며 각각 한 턴입니다. `size` 방향(넓음, 높음 또는 사각형)만 조정하며 Copilot 는 프롬프트에서 이를 읽습니다. Copilot 렌더링 크기를 선택합니다.
- 이미지는 인라인으로 반환됩니다. 기본적으로 `b64_json` `response_format: "url"` 에 대한 데이터 URL.
- 생성된 이미지는 채팅과 별개로 작은 일일예산을 사용합니다. 모두 사용하면 요청이 실패합니다.** 429** . 이미지 없이 대답하는 차례는 다음과 같이 실패합니다.** 502** (또는** 400** /** 503** Copilot 의 텍스트가 거절 또는 용량 문제로 읽힐 때); 메시지에는 어느 것이 있는지 나와 있습니다.

## 보안 모델

- **비공식 통합.** 이 공급자는 BizChat WebSocket 프로토콜을 리버스 엔지니어링합니다. Microsoft 엔드포인트를 변경하면 예고 없이 중단될 수 있습니다.
- `subscriptionRisk: true` 플래그는 통합이 문서화되지 않은 엔드포인트에 의존한다는 것을 반영합니다. 계정 제한이 가능하지만 확인되지 않았습니다.
- 액세스 토큰은 수명이 짧은 JWT 입니다. 암호처럼 취급하십시오. 커밋, 기록 또는 공유하지 마십시오.
- 새로 고침 토큰은 Microsoft 365 표면에 대한 지속적인 액세스 권한을 부여합니다. API 키와 마찬가지로 주의해서 보관하세요.

## 문제 해결

### 인증이 즉시 실패합니다.

- 다음에서 복사했는지 확인하세요.**WebSocket URL** , XHR/Fetch 요청이 아닙니다. 자격 증명은 `Authorization: Bearer` 헤더가 아닌 Chathub WebSocket 연결 — 의 `access_token` 쿼리 매개 변수에 있습니다.
- `chathubPath` URL 경로의 전체 `<oid>@<tenant>` 세그먼트가 포함되어 있는지 확인하세요.

### 토큰은 ~ 75분 후에 만료됩니다.

이것은 예상됩니다. `refreshToken` 없으면 액세스 토큰의 수명이 짧습니다. 어느 하나:

- DevTools 에서 자격 증명을 다시 캡처하거나
- 구성** 고급 설정 → 새로 고침 토큰(선택 사항)** 자동 새로 고침을 위해 연결 추가 또는 편집 대화 상자에서

### 연결 테스트에 성공했지만 채팅이 401을 반환합니다.

다음으로 생성된 연결의 경우** Microsoft 로 로그인** , 테스트 연결은 액세스 토큰의 만료를 확인하고 저장된 새로 고침 토큰으로 만료된 토큰을 갱신하므로 통과한 테스트는 새로 고침 토큰이 여전히 작동함을 증명합니다.

붙여넣은 자격 증명의 경우 연결 테스트는 자격 증명의 모양을 확인하고 토큰이 만료되면 공급자가 사용할 토큰이 만료되지 않았는지 확인합니다(연결에 저장된 토큰은 오래된 붙여넣기를 획득하며 새로 고침 토큰은 갱신 가능한 것으로 간주됩니다). 만료되기 전에 취소된 토큰은 여전히 테스트를 통과합니다. 채팅 후 돌아옴** 401** `m365_unauthorized`. 사용** Microsoft 로 로그인** 다시 클릭하거나 새로운 자격 증명을 다시 캡처하세요.

### Copilot 공급자 목록에 나타나지 않습니다

`copilot-m365-web` 활성화되어 있는지 확인하세요** 대시보드 → 공급자** . 일부 계층에서는 기본적으로 공급자가 숨겨질 수 있습니다.
