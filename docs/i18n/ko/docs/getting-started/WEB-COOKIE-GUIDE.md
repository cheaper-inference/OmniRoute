Web Cookie 공급자를 사용하면 OmniRoute가 API 키 대신 기존 브라우저 세션을 통해 AI 서비스를 이용할 수 있습니다. 웹사이트를 통해 이미 서비스에 액세스할 수 있으며 OmniRoute에서도 동일한 인증 세션을 사용하려는 경우 유용합니다.

API 키 공급자와 달리 Web Cookie 공급자는 브라우저가 웹사이트로 전송하는 자격 증명을 사용하여 인증합니다.

---

# 시작하기 전에

> **중요:** 자격 증명은 항상 브라우저의 쿠키 저장소가 **아닌**, **실시간 네트워크 요청**에서 복사하세요.

많은 인증 문제는 잘못된 위치에서 쿠키를 복사하여 발생합니다.

## 쿠키 저장소에서 복사하지 마세요

대부분의 브라우저에서는 다음 경로를 통해 저장된 쿠키를 확인할 수 있습니다.

```
개발자 도구
→ 애플리케이션(또는 저장소)
→ 쿠키
```

이러한 쿠키는 올바르게 보일 수 있지만 다음과 같은 상태일 수 있습니다.

- 오래됨
- 불완전함
- 인증된 요청에서만 전송되는 쿠키가 누락됨

이러한 값을 사용하면 유효해 보이더라도 인증에 실패할 수 있습니다.

## 실시간 요청에서 복사하기

대신 성공한 요청의 쿠키를 사용하세요.

```
개발자 도구
→ 네트워크
→ 페이지 새로고침
→ 채팅 또는 대화 요청 열기
→ 요청 헤더
→ Cookie
```

`Cookie` 요청 헤더에는 브라우저가 성공적으로 사용한 정확한 인증 정보가 포함되어 있습니다.

대부분의 Web Cookie 공급자에서는 이 값을 OmniRoute에 붙여 넣어야 합니다.

---

# 일반 설정

설정 과정은 대부분의 Web Cookie 공급자에서 동일합니다.

1. 공급자의 웹사이트에 로그인합니다.
2. 브라우저의 개발자 도구를 엽니다.
3. **네트워크** 탭을 엽니다.
4. 페이지를 새로고침합니다.
5. 인증된 채팅 또는 대화 요청을 엽니다.
6. 필요한 인증 자격 증명을 복사합니다.
7. OmniRoute를 엽니다.
8. **공급자 → 공급자 추가**로 이동합니다.
9. Web Cookie 공급자를 선택합니다.
10. 자격 증명을 붙여 넣습니다.
11. **연결 테스트**를 클릭합니다.
12. 공급자를 저장합니다.

필요한 정확한 자격 증명은 공급자에 따라 다릅니다.

| 공급자                          | 자격 증명 형식                | 공급자 가이드                    |
| ------------------------------- | ----------------------------- | -------------------------------- |
| Claude Web                      | 전체 Cookie 요청 헤더         | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | 전체 Cookie 헤더              | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(확인 필요)_                 |                                  |
| Copilot Web                     | _(확인 필요)_                 | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(확인 필요)_                 |                                  |
| ...                             | ...                           | ...                              |

> 새로운 Web Cookie 공급자가 추가되거나 기존 공급자의 인증 요구 사항이 변경되면 이 표를 업데이트하세요.

## NoTrack (notrack-web)

NoTrack([notrack.ai](https://notrack.ai))는 가입 없이 사용할 수 있는 무료 소비자용 채팅 플랫폼입니다. 첫 방문 시 익명으로 세션이 생성되며 `uid`, `si_usr_id`, `si_ses_id`라는 세 가지 쿠키를 통해 유지됩니다. OmniRoute는 단일 모델 ID(`notrack-c`, 별칭 `ntw`)를 통해 동일한 `/api/dispatch` 엔드포인트를 프록시합니다.

### 연결 단계

1. 브라우저에서 [notrack.ai](https://notrack.ai)를 열고 익명 세션 쿠키가 설정되도록 합니다.
2. **개발자 도구 → 네트워크**를 열고 페이지를 새로 고친 다음 `/api` 요청 중 하나를 클릭합니다.
3. **요청 헤더**에서 전체 `Cookie` 헤더 값을 복사합니다.
4. OmniRoute에서 **제공자 → 제공자 추가 → NoTrack Web (무료)**로 이동합니다.
5. 쿠키 문자열을 `apiKey` 필드에 붙여 넣고 **저장**합니다.

OmniRoute는 붙여 넣은 문자열에서 `uid`, `si_usr_id`, `si_ses_id`를 추출한 후 해당 키-값 쌍만 포함하는 깔끔한 `Cookie` 헤더를 다시 구성합니다. 로그인한 계정에 설정되는 `nt_session`(`ntk_…` 토큰)이 존재하는 경우에는 이 값도 포함됩니다. 세 값 중 하나라도 누락되면 운영자가 다른 형식을 실험할 수 있도록 붙여 넣은 원본 문자열을 변경 없이 전달합니다.

### 모델 ID

| 모델 ID     | 표시 이름 | 참고                                             |
| ----------- | --------- | ------------------------------------------------ |
| `notrack-c` | NoTrack C | 기본값 — 업스트림 디스패치 모델 `C`.             |
| `C`         | NoTrack C | `notrack-c`의 별칭(원시 업스트림 디스패치 코드). |
| `notrack`   | NoTrack C | `notrack-c`의 별칭.                              |
| `ntw`       | NoTrack C | `notrack-c`의 짧은 별칭.                         |

네 가지 모델 ID는 모두 동일한 업스트림 디스패치 모델(`C`)에 매핑됩니다.

### 요청 옵션

실행기는 요청 본문에서 다음과 같은 선택적 필드를 허용합니다.

| 본문 필드             | 기본값  | 용도                                                           |
| --------------------- | ------- | -------------------------------------------------------------- |
| `notrack_mode`        | `usual` | 디스패치 모드(자유 형식 문자열, 업스트림은 `usual` 등을 허용). |
| `notrack_max_turns`   | `6`     | 업스트림이 응답하기 전 수행할 수 있는 내부 턴 수.              |
| `notrack_chat_id`     | `null`  | 기존 업스트림 채팅 재개(새 채팅의 경우 생략).                  |
| `notrack_attachments` | `[]`    | 업스트림 첨부 파일 설명자의 패스스루 배열.                     |
| `notrack_regenerate`  | `false` | 이전 턴의 답변을 다시 생성하도록 요청하려면 `true`로 설정.     |

### 기능

- **스트리밍 및 비스트리밍** 채팅 완성.
- **도구 호출** — 요청에 `tools: [...]`를 설정합니다. 실행기는 이를 도구 호출 봉투 계약으로 직렬화하고 모델의 응답을 다시 OpenAI `tool_calls`로 파싱합니다.
- **`response_format`** — `json_object`와 `json_schema`가 지원됩니다. 실행기는 모델 응답에서 첫 번째 JSON 객체를 추출하고 문자열로 변환한 후 반환합니다.
- **추론 힌트** — 업스트림에서 `thinking` 이벤트를 전송하면 실행기가 `reasoning` 델타를 내보냅니다.

### 제한 사항

- 업스트림은 익명 사용량 할당량을 적용합니다. 할당량을 초과하면 실행기는 이해하기 쉬운 메시지와 함께 429를 반환합니다.
- 모든 모델 ID는 동일한 업스트림 디스패치 모델로 해석되며, 모델별 전환 기능은 없습니다.
- 실행기는 업스트림의 `/api/chats` 엔드포인트를 호출하지 않으므로 채팅 기록/세션이 자동으로 관리되지 않습니다. 기존 업스트림 채팅을 재개하려면 `notrack_chat_id`를 사용하세요.

# 웹 쿠키 제공자가 할 수 있는 것과 할 수 없는 것

웹 쿠키 제공자는 웹사이트의 채팅 인터페이스를 재사용합니다. 공식 API와 동일한 기능을 제공하는 것은 **아닙니다**.

## 지원됨

- 기존 브라우저 세션을 사용한 인증
- 계정에서 사용 가능한 모델에 액세스
- 채팅 응답 스트리밍
- API 키 불필요

## 지원되지 않음

- 함수 호출
- 도구 호출
- 자동 파일 편집
- 에이전트형 IDE 워크플로
- API 전용 기능

이는 예상된 동작이며 **버그가 아닙니다**.

도구 실행, 자동 파일 편집 또는 기타 에이전트 워크플로가 필요한 경우 Web Cookie 제공자 대신 **API 키 제공자**를 사용하세요.

# 검증 관련 주의 사항

**Test Connection** 또는 쿠키 검증에 성공했다는 것은 제공된 자격 증명이 예상된 형식인 것으로 보인다는 점만 확인합니다.

Issue #7857이 해결될 때까지는 검증에 성공해도 제공자의 인증 성공이 **보장되지 않습니다**.

인증이 계속 실패하면 브라우저 쿠키 저장소가 아닌 실제 네트워크 요청에서 자격 증명을 복사했는지 확인하세요.

# 문제 해결

## 인증 실패

자격 증명을 다음 위치에서 복사했는지 확인하세요.

```
Network
→ Request Headers
→ Cookie
```

다음 위치에서 복사하면 **안 됩니다**.

```
Application
→ Cookies
```

---

## 브라우저에서는 쿠키가 작동하지만 OmniRoute에서는 작동하지 않음

일부 제공자는 인증된 요청 중에만 전송되는 쿠키를 포함합니다.

대화를 성공적으로 연 후 새 네트워크 요청에서 자격 증명을 다시 복사하세요.

---

## 세션 만료

Web Cookie 제공자는 기존 브라우저 세션을 사용합니다.

브라우저 세션이 만료되거나 로그아웃하면 새로운 자격 증명 세트를 복사해야 합니다. 지원되는 웹 제공자의 쿠키 갱신을 자동화하려면 함께 제공되는 [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) 도구를 참조하세요.

---

## Test Connection은 통과하지만 요청 실패

Issue #7857이 해결될 때까지는 검증을 통과해도 인증 요청의 성공이 보장되지 않습니다.

추가 문제 해결을 진행하기 전에 인증된 새 요청에서 자격 증명을 다시 복사하세요.

## ChatGPT Web에서 "Unsupported ChatGPT integrity dependency" 오류 발생

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

자격 증명에는 문제가 없습니다. 해당 오류는 세션이 아닌 브리지에서 발생합니다. chatgpt.com은 배포마다
모듈 ID를 할당하며, 이전에는 브리지가 인스턴스화하는 Sentinel 헬퍼의 ID를 고정했기 때문에
chatgpt.com을 재빌드하면서 헬퍼의 이름이 변경되면 쿠키는 여전히 유효하더라도 모든 턴이 중단되었습니다. 연결을
재승인해도 이 문제는 해결되지 않습니다.

페이지 자체 런타임을 통해 모듈을 확인하는 빌드는 ID를 고정하지 않으므로 이 문제가 발생하지 않습니다. 이
오류가 표시되면 OmniRoute를 업그레이드하고 연결 검사를 다시 실행하세요.
