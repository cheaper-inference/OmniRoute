## 개요

할당량 공유 엔진은 동일한 연결을 공유하는 여러 API 키에 공급자의 시간 기반 할당량(예: Codex
5시간 윈도우, Kimi 1500 req/h)을 공정하게 분배합니다.

**해결하는 문제:** OmniRoute는 동일한 업스트림 공급자 계정에 여러 API 키를 프록시합니다.
공유 로직이 없으면 키 A에서 발생한 요청 급증으로 해당 시간의 공급자 할당량이 소진되어,
윈도우가 재설정될 때까지 키 B와 C가 차단될 수 있습니다.
엔진은 다음과 같은 방식으로 이를 방지합니다.

1. 각 차원(%, 요청 수, 토큰 수, $)에 대한 각 키의 롤링 사용량을 추적합니다.
2. 작업 보존형 공정 분배 알고리즘을 적용합니다. 글로벌 풀이 포화되지 않은 동안에는 키가
   유휴 지분을 빌려 사용할 수 있습니다.
3. 요청이 업스트림 실행기에 도달하기 전에 핫 패스(`chatCore.ts`)에서 결과를 적용합니다.

## 알고리즘: 공정한 공유 작업 보존

`src/lib/quota/fairShare.ts` 에서 구현되었습니다.

### 모드

| 상태                                       | 방법       | 행동                                                              |
| ------------------------------------------ | ---------- | ----------------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **관대한** | 키는 전역 한도에서 총 소비량을 뺀 최대 한도까지 빌릴 수 있습니다. |
| `globalUsedPercent >= saturationThreshold` | **엄격한** | 개인별 공평한 분배를 엄격하게 시행하세요.                         |

기본 `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`).

이 두 모드는 기본 빌림 모드인 `saturation` 의 풀을 설명합니다. `consent` 모드의 풀은 포화도에 상관없이 항상 엄격한 규칙을 적용합니다. [동의된 대출(풀별 선택)을](#consented-lending-per-pool-opt-in) 참조하세요.

### 차원별 결정

풀의 각 활성 차원에 대해 엔진은 다음을 계산합니다.

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = current rolling value for this key (from QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

`percent` 차원의 경우 `consumed` 대신 속성 책에서 가져옵니다( [퍼센트 차원: 키별 속성](#percent-dimensions-per-key-attribution) 참조).

그 다음에:

- **`policy = hard`** : `consumed > fairShareAllowed` 및 모드가 엄격한 → 인 경우** 차단하다** .
- **`policy = soft`** : `consumed > fairShareAllowed` 및 모드가 엄격한 → 인 경우** 처벌하다** (콤보에서 우선순위를 낮추고 절대 하드블로킹하지 마세요).
- **`policy = burst`** : 공정한 분배에 관계없이 글로벌 헤드룸이 존재하는 동안 허용됩니다.

### 캡 앱솔루토

할당에 대한 `capValue` + `capUnit` 는 모드나 정책에 관계없이 엄격한 한도입니다. `consumed >= capValue` 항상 존재하는 모든 차원** 블록** 요청. `percent` 캡의 경우 `consumed` 키에 해당하는 부분일 뿐입니다.

### 다차원 검사

다음과 같은 경우 요청이 차단됩니다.** 어느** 풀의 차원이 이를 차단합니다. 차원은 독립적 — 5시간% 소진은 주간 % 차원에 영향을 미치지 않습니다.

### 차용

관대 모드에서는 할당량이 덜 소모된 키가 다른 키의 할당되지 않은 공유에서 잉여분을 사용할 수 있습니다. 공식은 다음과 같습니다.

```
maxAllowed = globalLimit - consumedByOtherKeys
```

어디 `consumedByOtherKeys = consumedTotal - consumedByThisKey`. teto 전역(해당 차원에 대한 풀 `limit` )은 항상 엄격한 천장입니다.

### 동의된 대출(풀별 선택)

각 풀에는 대여 모드가 있습니다. `saturation` 가 기본값이며 위의 규칙을 유지합니다. `consent` 모드에서 `hard` 키는 다른 키가 빌려주기로 동의한 용량 내에서만 공유를 전달합니다. 관리자는 각 풀의 모드를 설정합니다. 각 키 보유자는 [대출 동의를](#lending-consent) 통해 자체 동의를 설정합니다.

동의는 0에서 100 사이의 백분율이며 선택적인 기한은 에포크 밀리초 단위입니다. 키는 기한이 미래인 동안 유휴 공유의 해당 비율을 빌려줍니다.

한 차원의 경우 `L` 는 유효 한도입니다. 즉, 계획 한도에 풀의 계정을 곱한 값입니다. 게이트는 요청 키에 대해 다음을 계산합니다.

```
share_k         = w_k / 100 × L
idle_k          = max(0, share_k − consumed_k)
lent            = Σ over the other keys of lend_k / 100 × idle_k
taken           = Σ over the other keys of max(0, consumed_k − share_k)
borrowAvailable = max(0, lent − taken)
```

`w_k` 는 키의 가중치이거나 0보다 큰 가중치가 없을 때 모든 키에 대한 `100 / n` 입니다. `lend_k` 는 키의 활성 백분율이고 기한이 지나면 0이 됩니다. 요청하는 키의 자체 동의는 계산에 포함되지 않습니다. `hard` 키는 소비량이 해당 공유에 `borrowAvailable` 더한 값에 도달하면 거부됩니다.

할당이 요구되지 않는 용량(100에서 가중치의 합을 뺀 값)은 대여할 수 없습니다. 빌려주겠다고 동의한 키가 없습니다.

**예.** `L` 는 1000입니다.

| 키   | 무게 | 공유하다 | 소비됨 | 대출 |
| ---- | ---- | -------- | ------ | ---- |
| 에이 | 50   | 500      | 530    | 0%   |
| 비   | 30   | 300      | 100    | 50%  |
| 기음 | 0    | 0        | 60     | 0%   |

- B는 유휴 200, 즉 100의 50%를 빌려줍니다. C는 이미 자신의 몫보다 60을 가져갔습니다. A는 40을 빌릴 수 있습니다.
- A는 530에 서비스를 받고 소비량이 540에 도달하면 거부됩니다.
- C가 무언가를 사용하기 전에는 A의 지분 또는 그 이하로 C는 100을 빌릴 수 있었습니다.
- C가 무엇이든 사용하기 전에는 A가 530이었으므로 C는 70을 빌릴 수 있었습니다.

**무게가 0입니다.** 가중치가 0인 키의 점유율은 0입니다. 소비량이 다른 사람이 빌려주는 것보다 적을 때만 제공됩니다. 아무도 빌려주지 않으면 첫 번째 요청부터 거부됩니다.

**마감일.** 동의가 만료되는 백그라운드 작업은 없습니다. 각 요청은 기한을 자체 시간과 비교하고 해당 시간과 동일한 기한이 지났습니다. 유한한 숫자가 아니거나 `Date` 보유할 수 있는 최대 날짜를 지난 저장된 기한은 통과된 것으로 간주됩니다.

**`soft` 및 `burst`.** 대출은 이를 제한하지 않습니다. `soft` 키는 해당 공유를 초과하면 우선순위가 낮아집니다. 풀에 공간이 있는 동안 `burst` 키가 전달됩니다. 수영장 천장은 수영장의 총액이 한도에 도달하면 모든 키를 거부합니다.

**요청 경로의 비용입니다.** `saturation` 풀은 이전보다 더 많은 것을 읽지 않습니다. `consent` 풀에서 계산 가능한 차원은 다른 키가 빌려주는 동안 해당 공유 이상의 `hard` 키에 대해서만 다른 키를 읽습니다. 그런 다음 다른 키당 하나의 읽기를 병렬로 수행합니다. 실패한 읽기는 해당 키에 대한 소비 0으로 계산됩니다. 속성 북이 모든 키를 보유하므로 `percent` 차원은 읽기를 추가하지 않습니다.

**풀 편집.** 편집하면 유지되는 키의 동의가 유지됩니다. 이는 할당 편집, 그룹 전체 교체 및 `ensure` 호출에 적용됩니다. 제거된 키는 동의를 잃고 다시 추가된 키는 0에서 시작합니다. 관리자 경로는 각 키의 동의를 반환하고 절대 쓰지 않습니다. 풀을 `saturation` 로 다시 전환하면 저장된 모든 동의가 유지되며 해당 모드에서는 효과가 없습니다. 풀을 `consent` 로 다시 전환하면 기한이 지나지 않은 저장된 동의가 다시 활성화됩니다. 키 보유자는 어느 모드에서든 저장된 동의를 지울 수 있습니다.

**업그레이드 중입니다.** `lending_percent` 및 `lending_until` 열이 이미 존재하는 경우 마이그레이션에서는 `borrow_mode` 만 추가하고 저장된 백분율은 그대로 유지됩니다. 모든 풀은 `saturation` 모드에서 시작됩니다. 풀 마법사에서 풀당 `consent` 활성화합니다. 저장된 값에서는 아무것도 추론되지 않습니다.

**제한 사항.**

- 대출 기관은 자체 지분을 사용하기 전에 한도에서 풀을 찾을 수 있습니다. 다른 사람이 빌린 용량은 풀의 총 용량에 포함됩니다.
- 확인은 요청 전에 실행되며 아무것도 예약하지 않습니다. 동시 요청은 기록되기 전에 읽기 소비를 요청하므로 전송 중인 요청에 따라 대여 용량을 두 번 이상 사용할 수 있습니다. `saturation` 모드의 공유 확인에도 동일한 속성이 있습니다.

## 슬라이딩 윈도우 카운터

`src/lib/quota/sqliteQuotaStore.ts`와 `redisQuotaStore.ts`에 구현되어 있습니다.

각 `(apiKeyId, dimensionKey)`에 대해 두 개의 버킷을 사용합니다.

- `curr`: 현재 버킷(`floor(nowMs / windowMs)`)
- `prev`: 이전 버킷(`curr - 1`)

유효 롤링 값:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**정밀도**: 약 99%의 정확도를 제공합니다. 버킷 경계에서 오차는 최대 윈도우 크기의
1%입니다(2버킷 근사 방식의 고유한 특성).

### 동시성

SQLite 드라이버: `(apiKeyId | dimensionKey)` 키별 인메모리 뮤텍스가
읽기-수정-쓰기 경쟁을 방지합니다. 이 패턴은 `src/sse/services/auth.ts`의 요청 폭주 방지 방식을 따릅니다.

Redis 드라이버: 원자적 증가를 위해 Lua EVAL 스크립트를 사용하며, 단일 Redis 명령으로 실행됩니다.

## 드라이버

### SQLite (기본값, 설치 불필요)

- 테이블: `quota_consumption`(마이그레이션 `073_quota_pools.sql` / `074_quota_consumption.sql` 참조).
- 단일 인스턴스 배포에 가장 적합합니다.
- 모든 영구 데이터는 기존 OmniRoute SQLite DB(`DATA_DIR/storage.sqlite`)에 저장됩니다.

### Redis (선택 사항, 다중 인스턴스)

- `ioredis` npm 패키지가 필요합니다.
- 카운터는 Redis에 저장되며, 메타데이터(풀/할당)는 계속 SQLite에 저장됩니다.
- 카운터를 공유해야 하는 다중 복제본 배포에 가장 적합합니다.

### 드라이버 전환

설정 UI(`/dashboard/settings` → 할당량 저장소) 또는 환경 변수를 통해 전환할 수 있습니다.

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

DB 설정이 환경 변수보다 우선합니다. `driver=redis`이지만 URL이 없거나
`ioredis`가 설치되어 있지 않으면 팩토리는 SQLite로 대체하고 경고를 기록합니다.

드라이버 선택 순서:

1. DB 설정 `quotaStore.driver`
2. 환경 변수 `QUOTA_STORE_DRIVER`
3. 기본값: `sqlite`

## 다차원

풀은 여러 차원을 가질 수 있습니다. 각 차원은 독립적입니다.

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // global pool ceiling for this dimension
}
```

**예: Codex 계획** (5h% + 주간%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

요청이 허용되려면 모든 차원을 충족해야 합니다.

### 백분율 차원: 키별 기여

백분율 계획은 계정 및 계획 창당 하나의 사용량 수치를 보고합니다. 공급자는 API 키당 카운터를 제공하지 않습니다.

해당 수치를 키 간에 분할하기 위해 각 풀은 계정 및 계획 창별로 속성 장부를 유지합니다. `src/lib/quota/percentLedger.ts` 책의 규칙을 유지합니다. `src/lib/quota/percentAttribution.ts` 책을 집행이 사용하는 숫자로 바꿉니다. 결과는 각 주요 경로의 토큰으로 구성된 추정치입니다.

#### 책을 움직이는 독서

책은 요청한 계획 창에 대해 공급자 자체 그림으로만 이동합니다. 이러한 연결은 다음 중 하나를 보고합니다.

| 공급자                    | 계획 창        |
| ------------------------- | -------------- |
| Claude, OAuth 연결을 통해 | `5h`, `weekly` |
| Codex                     | `5h`, `weekly` |

다음은 독서로 간주되지 않습니다.

- 공급자 클라이언트가 오래된 것으로 표시한 응답
- 공급자가 보고하지 않은 비율의 Claude 창
- 다른 창의 그림 또는 창 전체의 최악의 경우
- 속도 제한 헤더 폴백
- 실패한 읽기

API 키가 있는 Claude 포함한 다른 제공업체에는 책이 없습니다. 이 변경 전과 마찬가지로 각 키에는 백분율 차원에서 0이 청구됩니다.

판독값은 포화 신호의 30초 캐시를 공유합니다. Claude 판독값은 응답 헤더에서 수치가 관찰되거나 사용 끝점에서 읽혀진 시간을 기준으로 날짜가 지정됩니다. 다른 판독값은 해당 캐시 항목이 작성된 날짜를 기준으로 날짜가 지정됩니다.

#### 책이 담고 있는 것

기록된 각 요청은 풀, 계정 및 키당 카운터에 해당 토큰을 한 번 추가합니다. 카운터만 늘어납니다. 이 책은 세 가지를 담고 있습니다.

- 기준선: 책이 열렸을 때나 창문이 마지막으로 회전했을 때의 수치
- 마지막으로 적용된 수치
- 키당, 동시에 마크라고 불리는 토큰 카운터

시행 또는 사용 경로가 속성을 계산할 때 책이 업데이트됩니다. 쓰기는 개정 번호에 대해 비교 및 설정됩니다. 새로 읽은 재시도에서 한 번 실패한 작성자입니다.

#### 키 부분이 계산되는 방식

각 키의 부분은 책을 읽을 때 계산됩니다. 기준선 이후 수치의 성장은 마크 이후 라우팅된 각 토큰에 비례하여 키 사이에 분할됩니다.

Together, 해당 토큰은 `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` 토큰당 최대 한 지점(기본값 1,000)을 설명합니다. 그들이 설명하지 않는 성장은 외부적인 것입니다. 기준선도 외부입니다.

예를 들어, 책은 0시에 열립니다. 그런 다음 키 A는 900,000개의 토큰을 라우팅하고 키 B는 100,000개의 토큰을 라우팅합니다. 60점에서 A부분은 54점, B부분은 6점입니다.

키 표시 아래의 카운터가 다시 시작되어 전체 계산됩니다. 창 중앙에서 풀에 합류하는 키와 같이 표시가 없는 키는 모든 토큰을 계산합니다. 토큰보다 뒤처지는 수치는 다음 판독 시 사라지는 오류를 발생시킵니다. 누적되지 않습니다.

`QUOTA_PERCENT_MIN_TOKENS_PER_POINT` 는 모든 속성에서 읽혀집니다. 1 이상의 유한수가 아닌 값은 1,000으로 돌아갑니다.

#### 독서가 책을 어떻게 변화시키는가

첫 번째 일치 규칙이 적용됩니다.

1. **아직 책이 없습니다:** 독서가 책을 펼친다. 그 수치는 기준선이며 모든 카운터가 표시됩니다.
2. **이전 읽기:** 마지막으로 적용된 날짜 이전의 판독값은 무시됩니다. 재설정 시간이 저장된 값보다 30분 이상 빠른 판독값도 마찬가지입니다.
3. **새로운 제공업체 창:** 재설정 시간이 저장된 시간보다 30분 이상 늦을 경우 책을 넘깁니다. 그 수치가 기준선이 되고 모든 카운터가 다시 표시됩니다. 카운터가 없는 키는 책에서 나옵니다.
4. **종료된 기간:** 판독값의 데이터 시간 이후가 아닌 저장된 재설정 시간은 기간이 종료되었음을 의미합니다. 독서는 그 모습이 무엇이든 책을 변화시킵니다.
5. **더 높은 수치:** 마지막 숫자만 움직입니다. 기준선과 표시는 그대로 유지됩니다.
6. **같은 그림:** 그림, 기준선 및 표시가 그대로 유지됩니다. 책에 부족한 재설정 시간만 기록됩니다.
7. **낮은 그림:** 더 낮은 수치는 절대로 적용되지 않습니다. 세 가지가 유지될 때만 책을 뒤집습니다. 마지막으로 적용된 판독값보다 최소 2분 이후입니다. 창문이 똑같이 열려 있다는 말은 없습니다. 1포인트 이상 낮습니다.

세 가지가 유지되면 창은 동일한 열린 창으로 간주됩니다. 두 가지 재설정 시간이 모두 알려져 있습니다. 그들은 서로 30분 이내의 거리에 있습니다. 저장된 것은 여전히 읽기보다 앞서 있습니다. 해당 창 안의 아래쪽 그림은 아무것도 변경하지 않습니다.

재설정 시간은 이를 수행하는 판독값의 데이터 시간보다 앞서 있는 동안에만 저장됩니다. 더 높은 숫자는 해당 값을 사용할 수 있을 때 판독값의 재설정 시간을 저장하고 그렇지 않은 경우 저장된 값을 유지합니다. 동일한 숫자는 책에 아무것도 없는 경우에만 읽기 재설정 시간을 기록합니다. 그것은 아무것도 바꾸지 않습니다. 책을 돌리지 않는 아래 그림에는 재설정 시간이 기록되지 않습니다.

#### 책을 사용할 때

책을 읽은 후에는 저장된 재설정 시간이 현재 시간 이후가 아닌 한 책을 사용합니다. 이러한 경우는 캐시에서 제공되는 것과 같이 재설정 직전에 수행된 읽기가 바로 직후에 관찰될 때 발생합니다.

사용할 수 있는 읽기가 없으면 저장된 책은 현재 창의 책일 수 있는 동안에만 사용됩니다. 이는 두 가지 경우에 적용됩니다.

- 재설정 시간이 알려져 있고 아직 앞서 있습니다.
- 재설정 시간이 없으며 이를 변경한 마지막 판독값은 최대 15분입니다.

그렇지 않으면 책이 없는 것처럼 아무 것도 귀속되지 않습니다. 저장된 재설정 시간이 지난 책은 요금이 청구되지 않습니다.

#### 시행

백분율 차원에서 키의 소비량은 해당 속성 부분과 외부 부분의 공유량을 합한 것입니다. 외부 부분은 먼저 할당 없음 클레임 용량(100에서 가중치 합계를 뺀 값)을 사용합니다. 초과분만 무게에 따라 키 간에 공유됩니다.

해당 소비는 다른 모든 차원과 마찬가지로 키의 공정한 분배와 비교됩니다. 포화 신호가 `QUOTA_SATURATION_THRESHOLD` (기본값 0.5)에 도달하면 엄격 모드가 계속 시작됩니다. 모든 숫자는 유효 한도에 따라 조정됩니다. 즉, 계정당 한도에 풀의 계정 수를 곱한 값입니다.

`capUnit: "percent"` 사용한 절대 상한은 동일한 방식으로 크기가 조정된 키에 해당하는 부분만 계산합니다. 계정당 제한은 100개 및 k개 계정입니다. 그런 다음 제공 계정 수치 중 키 부분이 N/k 포인트에 도달하면 N의 한도에 도달합니다. 각 계정은 자체 장부와 비교하여 확인됩니다. 예를 들어, 두 개의 계정이 있는 경우 한 계정 수치의 5포인트에서 최대 10개에 도달합니다.

저장소를 읽을 수 없으면 아무 것도 귀속되지 않으며 해당 차원에 대해 모든 키에 0이 청구됩니다. 책 쓰기가 실패하면 해당 속성은 책을 읽은 대로 사용합니다. 토큰 쓰기에 실패하면 해당 요청의 토큰이 책에서 제외됩니다. 이러한 실패 중 어느 것도 요청을 차단하지 않습니다.

`consent` 풀에서 대출 공식은 위에서 설명한 대로 백분율 차원에서 각 키의 소비를 사용합니다. 다른 키를 빌려주면 책을 한 번 읽고 모든 키에 귀속됩니다. 사용할 수 있는 책이 없으면 모든 키에는 0이 부과됩니다. 무게가 있는 키는 통과되고, 무게가 0인 키는 다른 키가 빌려줄 때만 통과됩니다.

#### 사용경로

`GET /api/quota/pools/{id}/usage` 동일한 기능을 통해 동일한 숫자를 보고합니다. 백분율 차원에는 `accounts` 의 풀 연결당 하나의 항목이 있습니다. 최상위 수준 `consumedTotal` 및 `perKey` 는 첫 번째 항목을 미러링합니다.

경로는 현재 읽기에도 적용되므로 요청에 따라 책을 진행할 수 있습니다. `internal + external` 사용할 수 있는 판독값이 없거나 더 낮은 수치가 적용되지 않는 경우 `consumedTotal` 와 다를 수 있습니다.

#### 보관 및 보관

두 할당량 상점 모두 책을 보관합니다. SQLite 에서 자동 데이터베이스 정리를 활성화하면 60일 동안 업데이트되지 않은 행이 제거됩니다. Redis 에서는 풀 연결의 장부와 카운터가 하나의 키를 공유합니다. 마지막 토큰 쓰기 또는 도서 변경 후 60일이 지나면 만료됩니다. 변경되지 않는 책은 다시 작성되지 않으므로 컷오프는 가장 긴 계획 창 위에 설정됩니다. 수동 사용 내역 재설정은 SQLite 의 책도 지웁니다(제한 사항 참조).

#### 제한사항

- 기준선 이후 계정 수치의 모든 성장은 그 이후로 라우팅된 각 키의 토큰으로 분할됩니다. 그 성장이 언제 일어 났는지는 중요하지 않습니다.
- 따라서 OmniRoute 외부에서 이루어진 사용량은 해당 토큰이 허용하는 한도 내에서 키에 요금이 부과됩니다. 여기에는 책이 이미 열려 있을 때 창에 대한 키의 첫 번째 요청 이전에 이루어진 사용이 포함됩니다.
- 예를 들어 외부 사용은 주요 경로가 없는 동안 계정 60 포인트를 높입니다. 그런 다음 키는 30,000개의 토큰을 라우팅하고 그 수치는 60.6에 도달합니다.
- 사용하기 전에 책이 열려 있었다면 키 부분은 30점입니다. 또한 무게 25의 키 4개와 함께 7.65의 외부 사용을 수행합니다.
- 해당 사용 후 책을 열었다면 60점이 기준점입니다. 키 부분은 0.6포인트이며, 외부 사용량은 15입니다.
- 사용 경로를 요청하거나 방문하면 책이 열립니다. 따라서 그러한 사용이 기준으로 간주되는지 여부는 책이 언제 열렸는지에 따라 다릅니다.
- 기본 층을 사용하면 외부에서 사용하는 동안 60,000개의 토큰을 라우팅하는 키는 계정 60포인트를 자체 부분으로 모두 가져옵니다.
- 바닥이 50,000이면 자체 부분은 1.2포인트입니다. 나머지 58.8은 외부 사용과 마찬가지로 외부용이며 무게에 따라 요금이 부과됩니다.
- 귀하의 계획에서 1포인트 비용에 가깝게 `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` 설정하십시오. 외부 사용에는 풀 외부 키에서 발생하는 동일한 계정의 트래픽이 포함됩니다.
- 모든 모드에는 백분율 한도가 적용됩니다. 계정이 포화 임계값보다 훨씬 낮으면 제한 키가 거부될 수 있습니다.
- 창 초반에 외부 사용 포인트를 10점과 12점으로 제한합니다. 그러면 20,000개의 토큰을 라우팅하는 키가 12.4%의 계정 수치로 거부됩니다.
- 분할은 토큰 볼륨에 따른 추정치입니다. 요청은 프롬프트 토큰과 완료 토큰으로 계산됩니다. 캐시 할인 및 모델 가격은 해당 개수를 변경하지 않습니다.
- 상태 200으로 끝나지 않는 요청은 토큰을 기록하지 않습니다. 클라이언트가 연결을 끊는 스트림과 사용량이 소비된 후 업스트림 오류를 예로 들 수 있습니다.
- 이러한 요청으로 인한 사용량은 토큰이 허용하는 한도 내에서 토큰을 기록하는 키에 청구됩니다. 나머지는 외부입니다. 뒤로 이동하지 않습니다. 토큰 사용을 보고하지 않는 응답은 토큰도 기록하지 않습니다.
- 진행 중인 요청의 사용은 전체 요청에 대한 다른 활성 키 부분에 표시될 수 있습니다. 요청이 상태 200으로 끝나는 경우에만 뒤로 이동합니다.
- 책이 열렸을 때 계정에 이미 사용된 사용량은 외부 사용량으로 계산됩니다. 여기에는 업그레이드, 새 풀 및 새 계정이 포함됩니다. 처음 읽기 전에 새 창에서 사용하는 것도 외부로 간주됩니다.
- 각 키는 용량이 할당되지 않은 후 해당 사용량의 가중치 공유로 시작됩니다. 하나의 계정이 85%이고 가중치가 20인 키 5개를 사용하면 각 키는 20개 중 17개를 사용하는 것으로 시작됩니다.
- 여러 계정이 있는 풀에서는 게재 계정의 수치가 합산된 예산에 적용됩니다. 이 책은 변함이 없습니다.
- 공급자가 열린 것으로 보고하는 창 내부의 아래쪽 그림은 적용되지 않습니다. 30분 이상 뒤로 이동하는 재설정 시간은 이전 판독값으로 처리됩니다.
- 두 경우 모두 책은 저장된 재설정 시간이 지날 때까지 해당 상태를 유지합니다. 그 후에는 책을 읽을 때까지 책이 청구되지 않습니다.
- 해결 방법은 수동 사용 내역 재설정(`POST /api/settings/purge-usage-history`)입니다. SQLite 데이터베이스에서 속성 책과 해당 토큰 카운터를 지웁니다.
- `all` 기간은 모든 책과 카운터를 지웁니다. 짧은 기간은 먼저 그 안에 기록되지 않은 책을 지웁니다. 그런 다음 그 안에 기록되지 않은 카운터를 지우지만 책이 남아 있지 않은 풀 연결에 대해서만 지워집니다. 보관된 책은 여전히 각 키를 카운터에 표시합니다.
- 그림이 이동되지 않은 책은 다시 쓰지 않으므로 기간이 짧아도 현재 창의 책을 지울 수 있습니다. 다음 읽기에서는 현재 그림에 대한 새로운 책이 열립니다.
- 재설정은 Redis 할당량 저장소에 영향을 미치지 않습니다. 책은 창으로 끝나거나 마지막으로 쓴 후 60일이 지나면 만료됩니다.
- 공급자가 재설정 시간을 보내지 않으면 두 판독값 사이의 이전 수치보다 높게 재설정되고 다시 채워지는 창은 더 높은 수치처럼 보입니다. 책은 기존의 기준선과 표시를 유지합니다.
- 판독값은 현지 시계를 기준으로 날짜가 지정됩니다. 공급자보다 앞서 실행되거나 소스가 재설정 시간을 조금 일찍 보고하면 책이 그 차이를 일찍 드러낼 수 있습니다.
- 짧은 기간의 성장은 그 안에 라우팅된 토큰으로 나뉩니다. 다음 창의 첫 번째 읽기가 이를 수정합니다. 뒤집힌 책에 재설정 시간이 없으면 해당 수정에는 마지막으로 적용된 판독값보다 최소 2분 이후의 더 낮은 수치가 필요합니다.
- Redis 매장 날짜 판독값을 자체 시계와 공유하는 인스턴스이므로 해당 시계를 동기화 상태로 유지하세요. 시계가 뒤쳐지는 인스턴스의 판독값은 더 오래되어 무시됩니다.
- 저장된 재설정 시간 이후에 사용 가능한 판독값이 도착하지 않으면 판독값이 반환될 때까지 키별 백분율 공유 및 백분율 상한이 적용되지 않습니다. 재설정 시간이 없으면 책을 변경한 마지막 읽기로부터 15분 후에 시작됩니다.
- Redis 스토어에서 60일 동안 유휴 상태인 책은 작가 수표와 쓰기 사이에 만료될 수 있습니다. 그런 다음 유효한 상태인 1 이상의 개정에서 다시 생성됩니다.

## 파이프라인 통합

### PRE 후크(`open-sse/handlers/chatCore.ts`)

인증 및 정책 확인 후 업스트림 실행자 이전에 실행됩니다.

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → getQuotaStore().peek() per dimension
      → fairShare.decideFairShare()
      → if block → return 429 (buildErrorBody, Hard Rule #12)
      → if allow + deprioritize → set quotaSoftPenalty=true on candidate
  → executor.execute()
```

**페일오픈** : `enforceQuotaShare` 가 발생하면 `pino.warn` 로그를 통해 요청이 허용됩니다. 이렇게 하면 할당량 엔진 버그로 인해 모든 트래픽이 차단되는 것을 방지할 수 있습니다.

**용량이 돌아올 때.** 키 몫이나 풀 한도에 대한 거부는 두 가지 차용 모드 모두에서 두 문장 중 하나로 끝납니다.

- `percent` 창: `. The <window> window resets at <time>.` 이 시간은 공급자가 보고하는 재설정 시간입니다.
- 셀 수 있는 단위: `. Enough <window> usage is expected to clear by <time>.` 키가 아무 것도 보내지 않는 경우 시간은 슬라이딩 창의 상한입니다.

`<time>` 는 UTC 의 ISO 8601 인스턴스입니다. 그러면 거절에는 `Retry-After` 전달됩니다. 해당 순간까지의 전체 초에 1을 더한 것입니다. 그 긴 시간을 기다린 클라이언트는 순간 이후 최대 1초 동안 재시도합니다. 순간을 알 수 없는 경우 거절에는 문장도 헤더도 포함되지 않습니다. 절대 한도 거부는 어느 쪽도 포함하지 않습니다. 공개 코드는 `quota_share_blocked` 유지됩니다.

공유 거부는 공유 연결에 영향을 미치지 않습니다. 쿨다운, 모델 잠금, 공급자 차단기 실패를 설정하지 않으며 풀의 다른 키는 계속 제공됩니다. 콤보의 모든 대상이 해당 공유에 대한 키를 거부하면 콤보는 기다리지 않고 429에 응답합니다. 그 대답은 힌트를 `Retry-After` 로 전달합니다. 임베딩 경로는 거부를 동일한 문장으로 끝내고 `Retry-After` 보내지 않습니다.

### POST 후크(기록 소비)

성공적인 응답 후:

```
executor returns success
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → getQuotaStore().consume() per dimension
      → fail-open: errors logged as pino.warn, never propagated to client
```

**드리프트 노트** : `consume` 응답 후 실패하면 롤링 카운터가 과소 계산됩니다. 공급자(예: `anthropic-ratelimit-unified-5h-utilization`)의 포화 신호는 다음 요청에 대한 전역 추정치를 수정합니다.

### 콤보 소프트 페널티(`open-sse/services/combo.ts`)

`decision.deprioritize === true` 때 :

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // default 0.7
}
```

페널티는 다른 모든 점수 요소 다음에 적용됩니다. 하드 차단 없이 포화된 키를 선택하는 자동 콤보 확률을 낮춥니다.

## 셀프 서비스 할당량 API (선택)

`GET /api/v1/me/quota/{provider}` ( `/v1/me/quota/{provider}` 에서도 제공됨)를 사용하면 API 키 보유자가 자신의 키를 사용하여 자신의 공유 구독이 얼마나 되는지, 무엇이 이를 차단하는지 읽을 수 있습니다. 경로는 `src/server/selfService/quotaHandler.ts` 에 대한 얇은 쉘입니다. 뷰는 `src/lib/quota/selfView.ts` 에 의해 구축되고 해당 응답 계약은 `src/shared/schemas/selfQuota.ts` (`SelfQuotaView` in `docs/openapi.yaml`)입니다.

### 활성화 및 인증

- 기능 플래그 `QUOTA_SELF_PANEL`, 기본값 `false`. 꺼져 있는 동안 경로에 도달하는 요청은 404를 얻습니다. `REQUIRE_API_KEY=true` 사용하면 클라이언트 API 정책은 플래그에 관계없이 경로가 실행되기 전에 401로 누락되거나 잘못된 키를 거부합니다. 키는 없지만 로그인된 대시보드 세션이 있는 요청은 해당 정책을 전달하고 경로의 자체 응답을 얻습니다. 플래그는 다른 모든 플래그(dashboard 또는 REST 재정의, 동일한 이름의 환경 변수)와 마찬가지로 확인됩니다. [`FEATURE_FLAGS.md`](../reference/FEATURE_FLAGS.md) 참조하세요.
- 각 풀의 표시 이름과 각 일정의 레이블은 관리자가 작성한 그대로 풀의 키 보유자에게 반환됩니다. 깃발을 켜기 전에 해당 키 보유자가 읽을 수 있는지 확인하십시오.
- 키는 헤더 `Authorization: Bearer <key>` 또는 `x-api-key: <key>` 에서만 읽혀집니다. 둘 다 전송되면 유효성을 검사한 첫 번째 항목이 사용됩니다. 쿼리 문자열의 키나 쿠키는 무시됩니다. 서버의 환경 키가 거부되었습니다(401).
- 키에는 `self:usage` 범위(이 없이는 403)가 필요합니다.
- 공급자 세그먼트는 잘리고 소문자로 처리되며 `^[a-z0-9][a-z0-9._-]{0,63}$` (그렇지 않으면 400)에 대해 검사된 다음 공급자 레지스트리를 통해 확인되므로 `cc` 와 같은 별칭은 `claude` 풀을 읽습니다. `claude` 와 `anthropic` 동일한 풀을 읽습니다.

### 각 공개 상태에 표시되는 내용

| 시계      | 필요하다                                                                          | 전지                                                                                                                                                                                                                                           |
| --------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 자기 지분 | `self:usage`                                                                      | `pools[]` (참조, 이름, 공급자, 정책, 무게, 캡), `dimensions[].yourShare`, `accounts[]` 포함된 `yourShare` ( `attributed` 및 `external` 없는 `percent` 창에서), `blocks`, `availableModels`, `expiresAt`, `apiBaseUrl`                          |
| 계정 수준 | `self:usage` + `self:account-quota` 및 키의 `sharedQuotaProviders` 에 있는 공급자 | `percent` 창의 `yourShare` 에 `dimensions[].total`, `accounts[].dimensions[].account` 및 `accounts[].modelWindows`, `attributed` 및 `external` 를 추가하고 멤버 사용량이 설정된 풀에 `members` 추가합니다( [멤버 사용량](#member-usage) 참조). |

- `sharedQuotaProviders` 는 키별 설정(`PUT /api/keys/[id]/self-service`)입니다. 기본값인 `null` 키가 도달하는 모든 공급자를 의미합니다. `[]` 없음을 의미합니다. 각 풀의 `accountVisible` 어떤 가시성이 적용되었는지 알려줍니다.
- 계정 표시줄과 모델 창은 키 연결을 사용할 수 있는 계정에 대해서만 표시됩니다. 키에 허용된 연결 목록이 있으면 외부 계정은 `account` 또는 `modelWindows` 없이 `Account N` 항목을 유지합니다. 빈 목록은 `/v1/me/status` 와 마찬가지로 제한이 없음을 의미합니다. 풀 합계(`dimensions[].total`)는 해당 목록에 의존하지 않습니다.
- `self:usage` 만으로 표시된 두 수치는 다른 키를 사용하여 나온 것입니다. 일정 예산의 `exhausted` 해당 일정에 따른 모든 키의 소비를 반영합니다. 가중치가 모두 0인 풀에서 키의 `weight` `100 / number of members` 입니다. 둘 다 키에 적용되는 적용입니다.
- 풀은 호출 키에 바인딩된 불투명 값인 `ref` 로만 식별됩니다. 표시 이름(`name`)은 관리자가 작성한 대로 포함됩니다. `ref` 는 서버의 API 키 비밀(`API_KEY_SECRET`)이 있는 키와 풀에서 파생됩니다. 클라이언트는 이를 유지해서는 안 됩니다. 해당 비밀이 교체되면 변경됩니다.
- 계정은 풀 순서대로 `Account 1`, `Account 2`, …로 나열됩니다. 풀 ID, 연결 ID, 계정 이메일 또는 계정 이름은 반환되지 않으며 응답은 외부 필드를 삭제하는 계약 스키마를 통과합니다.
- 셀 수 있는 단위(`requests`, `tokens`, `usd`)는 할당량 게이트가 적용하는 풀 버킷으로 보고됩니다. 풀의 `limit` = 계획 제한 × 계정, `fairShare` = 가중치 / 100 × `limit` (모든 가중치가 0일 때 동일 분할), `consumed` = 할당량 저장소의 키 자체 카운터, `remaining` = `fairShare` − `consumed`, Floored 0에.
- `blocks.schedules` 키의 일정 기간(`open`/`closed`, `blackout` 또는 `outside-window`, `retryAfterSeconds`, 예비 층 및 기간의 예산 지출 여부)을 나열합니다. `blocks.modelCaps` 소비량과 함께 모델별 시간당 한도를 나열합니다.
- 공급자의 모든 풀 외부에 있는 키는 `pools: []` 사용하여 200을 얻습니다. `availableModels` (키가 `/v1/models` 에서 보는 `qtSd/` ID), `expiresAt` 및 `apiBaseUrl` 여전히 채워져 있습니다.
- `apiBaseUrl` 는 `OMNIROUTE_PUBLIC_API_BASE_URL` 이고, 다음은 `OMNIROUTE_PUBLIC_BASE_URL`, 그렇지 않으면 `null`. 이는 요청 자체의 출처가 아닙니다.

### `status` 와 `reason`

| `status`      | 의미                                                                                                                                                                                                                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ok`          | 현재 독서.                                                                                                                                                                                                                                                                                 |
| `stale`       | 오래된 것으로 표시된 캐시된 계정 읽기 또는 읽은 후 재설정 시간이 지난 계정입니다. 숫자가 유지됩니다. 재설정 시간이 지난 모델 창 하나는 전체 `modelWindows` 그룹 `stale` 표시합니다. `percent` 창의 키 자체 공유의 경우: 이를 확인하기 위해 게이트의 캐시를 읽는 계정 없이 책을 읽었습니다. |
| `unavailable` | 읽지 마세요. 숫자는 `null` 이고 절대 `0` 입니다. `reason` 그 이유를 말해줍니다.                                                                                                                                                                                                            |

| `reason`                          | 언제                                                                                                            |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `store_unavailable`               | 할당량 저장소를 읽을 수 없거나 속성 책을 읽을 수 없습니다.                                                      |
| `percent_attribution_unavailable` | `percent` 창의 키 자체 공유: 해당 계정 및 창에 대한 귀속 책이 아직 존재하지 않거나 책에 키가 나열되지 않습니다. |
| `percent_window_ended`            | `percent` 창의 키 자체 공유: 책은 종료된 계획 창에 속합니다.                                                    |
| `account_not_used_by_key`         | `percent` 창의 키 자체 공유: 계정의 연결이 키의 허용된 연결 외부에 있습니다. 그 책은 읽히지 않습니다.           |
| `window_not_reported`             | 공급자 제한 캐시에는 해당 계획 창에 대한 읽기가 없습니다.                                                       |
| `connection_lookup_failed`        | 계정 연결을 읽을 수 없습니다.                                                                                   |
| `not_supported`                   | OmniRoute 계정 공급자의 사용 제한을 읽을 수 없습니다.                                                           |
| `fetch_failed`                    | 캐시된 읽기를 사용할 수 없으며 공급자 제한 새로 고침에 실패했습니다.                                            |
| `not_available`                   | 읽기에 사용 기간이 없거나 계정에 읽기가 전혀 없습니다.                                                          |

할당량 저장소를 읽을 수 없는 경우 `blocks` 의 저장소 지원 필드(일정 예산의 `exhausted`, 모델 한도의 `consumed` 및 `reached`)도 `null` 입니다.

### 대출 동의

`PATCH /api/v1/me/quota/{provider}` 하나의 풀에 대한 호출 키의 자체 동의를 기록합니다. 이는 `GET` 의 플래그, 헤더 및 공급자 규칙을 사용합니다. `self:usage` 범위는 이름이 읽기 전용으로 읽혀도 이 한 번의 쓰기를 승인합니다.

```json
{
  "pool": "qpr_0123456789abcdef0123456789abcdef",
  "lendingPercent": 30,
  "lendingUntil": 1893456000000
}
```

- `pool` 는 해당 풀에 대해 `GET` 반환하는 `ref` 입니다.
- `lendingPercent` 는 0에서 100 사이의 정수입니다. 값이 0이면 동의와 기한이 지워집니다. `lendingPercent` 0이 있는 본문은 어느 모드에서나 허용됩니다.
- `lendingUntil` 는 선택 사항입니다. 에포크 밀리초 또는 기한이 없는 경우 `null`. 미래여야 하며 최대 8640000000000000이어야 합니다. 100000000000 미만의 값은 초로 읽혀 거부됩니다.
- 다른 필드는 거부됩니다. 4096바이트보다 긴 본문은 거부됩니다. 읽기는 해당 크기에서 중지되므로 더 긴 본문은 전체로 유지되지 않습니다.

검사는 이 테이블의 순서대로 실행됩니다. 모든 거부에는 고정된 메시지와 함께 표준 오류 본문이 사용됩니다. 이러한 수표 중 하나가 거부되면 아무 것도 기록되지 않습니다.

| 상태 | 메시지                                                                                             | 언제                                                           |
| ---- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 404  | `Not found`                                                                                        | `QUOTA_SELF_PANEL` 플래그가 꺼져 있습니다.                     |
| 401  | `Valid API key required`                                                                           | 키가 누락되었거나 유효하지 않거나 서버의 환경 키입니다.        |
| 403  | `API key lacks the self:usage scope`                                                               | 키에 `self:usage` 가 없습니다.                                 |
| 400  | `Invalid provider`                                                                                 | 공급자 세그먼트가 잘못되었습니다.                              |
| 429  | `Too many lending changes. Retry later.`                                                           | 키가 한도를 초과했습니다. 대답은 `Retry-After` 입니다.         |
| 400  | `Body must be { pool, lendingPercent, lendingUntil }. lendingPercent is an integer from 0 to 100.` | 본문이 JSON 아니거나, 너무 길거나, 스키마와 일치하지 않습니다. |
| 400  | `lendingUntil must be a Unix time in milliseconds`                                                 | 기한은 초로 표시됩니다.                                        |
| 400  | `lendingUntil must be in the future`                                                               | 마감일은 요청 시간 또는 그 이전입니다.                         |
| 404  | `Pool not found`                                                                                   | `ref` 는 이 공급자에 대해 이 키의 풀을 지정하지 않습니다.      |
| 403  | `Lending is not enabled for this pool`                                                             | 풀은 `saturation` 모드이고 `lendingPercent` 는 0보다 높습니다. |
| 500  | `Failed to build quota view`                                                                       | 기타 오류. 그 원인은 서버에 기록됩니다.                        |

각 키에 대한 요청 한도는 60초당 20개입니다. 공급자 확인을 통과한 모든 요청은 나중에 거부되거나 아무것도 변경되지 않는 요청이라도 포함됩니다. 키의 요청 속도 제한과는 별개로 자체 카운터가 있습니다.

저장된 동의를 변경하는 요청은 하나의 `quota.pool.lending.updated` 감사 레코드를 작성합니다. 이전 값과 새 값을 사용하여 키 이름을 지정합니다. 두 번 전송된 동일한 본문은 한 번 쓰고 한 번 감사합니다. 쓰기 후에 구축된 전체 `GET` 보기의 대답은 200입니다.

`GET` 보기는 다음과 같이 대출을 보고합니다.

- 각 풀은 `borrowMode` (`saturation` 또는 `consent`)와 키 자체의 `lendingPercent` 및 `lendingUntil` 전달합니다.
- `lendingActive` 는 `consent` 풀에서만 `true` 이며 백분율이 0을 초과하고 마감일에 도달하지 않았습니다.
- `consent` 풀에서 각 셀 수 있는 `dimensions[].yourShare` `borrowAvailable` 전달합니다. 이는 현재 다른 키가 빌려준 공유량 이상으로 키가 사용할 수 있는 것입니다.
- `borrowAvailable` 게이트의 공식을 사용합니다. 키가 공유되어 있는 동안에도 다른 모든 키를 읽습니다. 다른 키와 셀 수 있는 차원당 하나의 추가 읽기가 병렬로 수행되는 `hard` 키의 경우.
- `borrowAvailable` `soft` 또는 `burst` 키의 경우 `null` 이고 읽기가 실패한 경우 `null` 입니다.
- `borrowAvailable` 는 다른 모든 키를 합친 하나의 숫자입니다. 두 개의 키 풀에서는 다른 키 자체의 모습입니다.
- `borrowAvailable` 아직 `percent` 창이나 `accounts[]` 에 대해 보고되지 않습니다.
- `saturation` 풀에서 보기는 `lendingActive: false` 및 `borrowAvailable` 없이 저장된 동의를 보고합니다.

### 오류

이 경로의 모든 응답(성공 또는 오류)에는 `Cache-Control: no-store` 포함됩니다. 경로가 실행되기 전에 발생하는 거부(예: 클라이언트 API 정책의 401 또는 IP 필터의 403)는 이를 전달하지 않습니다. 경로 오류는 고정된 메시지와 함께 표준 오류 본문을 사용합니다: 400(잘못된 공급자), 401(누락 또는 잘못된 키), 403(누락 `self:usage`), 404(플래그 꺼짐) 및 500(`Failed to build quota view`). 500은 요청이 경로에 도달한 후 키 조회 자체를 포함하여 모든 실패를 처리합니다. 그 원인은 서버에 기록되고 결코 반환되지 않습니다. `PATCH` 의 오류는 [대출 동의](#lending-consent) 에 나열되어 있습니다.

### 제한사항

- `remaining` 사용되지 않은 키의 공정한 몫의 일부입니다. 이는 보증이 아닙니다. 수영장에 공간이 있는 동안에는 그 너머에 키가 제공될 수 있습니다. 풀의 합계가 `limit` 에 도달하면 풀의 모든 키는 자체 `remaining` 에 관계없이 거부되며 `self:account-quota` 없는 키는 해당 합계를 볼 수 없습니다.
- `remaining` 할당의 절대 `cap` 고려하지 않습니다. 시행은 캡 단위의 창에서 자체 소비가 캡 값에 도달하면 키를 거부합니다.
- 계정 수준 표시줄은 공급자 제한 캐시에서 가져오며 시행 결정을 몇 분 정도 지연시킬 수 있습니다. 재설정 시간이 지난 판독값은 `stale` 로 보고됩니다.
- 모델별 창(`modelWindows`)은 계획 창 매핑이 있는 공급자(현재 Claude 및 Codex 에 대해서만 보고됩니다. 다른 공급자의 경우 계정 데이터가 표시될 때 빈 `windows` 목록과 함께 `modelWindows` 여전히 존재합니다.
- `percent` 창의 키 자체 점유율은 추정치입니다. 이는 속성 책에서 나온 것이며 위의 "퍼센트 차원: 키별 속성"에 나열된 모든 제한 사항을 전달합니다.
- `consumed` 는 공정한 점유율과 비교되는 시행 수치입니다. 정확히는 `attributed` 더하기 `external` 입니다. `attributed` 는 책에서 라우팅된 토큰에 대한 키를 제공하는 부분입니다. `external` 는 풀의 키가 설명하지 않는 계정 사용의 키 부분입니다.
- 두 부분 모두 풀의 `accountVisible` true인 경우에만 전송됩니다. 키에는 `self:account-quota` 있고 공급자는 해당 `sharedQuotaProviders` 에 있습니다. 그것이 없는 키는 동일한 `status` 및 `reason` 사용하여 `consumed` 만 얻습니다.
- 부품과 자체 무게를 모두 사용하여 홀더는 수영장 키로 청구되는 수영장 외부 사용을 계산할 수 있습니다. 계정 범위를 가진 보유자는 이미 계정 총액을 볼 수 있습니다.
- 창에서 아무것도 라우팅하지 않은 키는 속성 부분이 0이기 때문에 `consumed` 에서 외부 전하를 계속 읽을 수 있습니다.
- 예를 들어 책은 0에서 열리고 키 A와 B의 무게는 각각 50입니다. 키 A는 900,000개의 토큰을 라우팅하고 키 B는 100,000개의 토큰을 라우팅합니다. 그런 다음 계정은 한도 100의 60%에 도달합니다. 그런 다음 `attributed` 는 키 A의 경우 54, 키 B의 경우 6이고 `external` 둘 다 0입니다.
- 뷰는 책을 읽고 상태를 기록하지 않습니다. 책을 펴지도 않으며, 제공자에게 독서를 요청하지도 않습니다. Redis 저장소를 사용하면 게이트 읽기와 마찬가지로 읽기가 백그라운드에서 대체된 개정 필드를 제거합니다.
- 게이트의 캐시가 계정 읽기를 보유하는 동안에만 공유가 `ok` 입니다. 하나도 없으면 `stale` 이므로 최근 요청이 없는 풀에서는 오래된 것으로 표시될 수 있습니다.
- 요청이 풀을 통과할 때까지 공유를 사용할 수 없습니다. 그 요청으로 장부가 열리고, 그 순간의 계좌 수치는 풀 밖에서 사용된 것으로 계산됩니다.
- 여러 계정이 있는 풀에서 각 계정 항목은 해당 계정의 장부와 한 계정의 한도를 사용합니다. 시행은 계정 수에 따라 양쪽을 확장하므로 비율은 동일합니다.
- 모델별 창에는 키에 대한 공유가 없습니다. 이 책은 모델별 데이터를 보관하지 않습니다.
- 일정의 예약 층은 보기에서 평가되지 않습니다. 일정은 `open` 로 표시될 수 있지만 요청은 이유 `schedule-reserve` 로 거부됩니다.
- 동일한 키의 두 풀이 연결을 공유하는 경우 그 중 하나가 적용되고 보기에는 둘 다 나열됩니다.
- 실패한 키 시도에는 주소별 제한이 없습니다. 역방향 프록시 호출자는 하나의 주소를 공유할 수 있으므로(전달된 클라이언트 주소를 신뢰할 수 있는지 여부에 따라 다름) 잠금으로 인해 모든 키 보유자에 대한 경로가 거부될 수 있습니다. `REQUIRE_API_KEY=true` 사용하면 경로가 실행되기 전에 이 경로 대신 해당 정책의 401 본문을 사용하여 클라이언트 API 정책에 의해 잘못된 키가 거부됩니다.

### 회원 이용

관리자는 키 보유자가 창 사용이 풀 구성원 간에 어떻게 분할되는지 볼 수 있도록 할 수 있습니다. 옵션은 풀의 `memberBreakdown` 이며 기본적으로 꺼져 있습니다. 이는 풀 마법사 또는 `PATCH /api/quota/pools/{id}` 사용하여 설정됩니다. `GET /api/quota/pools` 와 `GET /api/quota/pools/{id}` 이를 보고합니다.

뷰의 차원은 다음 사항이 모두 유지되는 경우에만 `members` 전달합니다.

- 수영장 옵션이 켜져 있어요
- 풀에는 최대 20개의 할당된 키가 있으며 그 중 최소 3개 이상이 요청을 할 수 있습니다(활성, 취소되지 않음, 금지되지 않음, 만료되지 않음).
- 풀의 `accountVisible` true입니다. 키에는 `self:account-quota` 가 있고 공급자는 `sharedQuotaProviders` 에 있습니다.
- `percent` 창에서 계정 연결은 키가 사용할 수 있는 연결입니다.
- 해당 창의 키 자체 공유를 읽었습니다. `status` 는 `unavailable` 아닙니다.

그렇지 않으면 `members` 가 없습니다. 결코 빈 목록이 아닙니다.

- 각 슬라이스는 `{ slot, consumed, isYou }` 입니다. 응답 스키마는 조각의 다른 속성과 20개가 넘는 조각 목록을 거부합니다. 슬라이스는 슬롯 순서대로 나열됩니다.
- 더 이상 요청할 수 없는 키를 포함하여 할당된 키당 하나의 조각이 있습니다. 사용하지 않는 멤버는 실제 0을 표시합니다.
- 슬롯 1은 항상 요청 키이며 `isYou` true입니다. 다른 슬롯 번호는 키 해시의 순위입니다. 이는 `API_KEY_SECRET` 로 키가 지정되며 풀, 요청 키 및 멤버를 포함합니다.
- 따라서 보유자 간에 숫자가 정렬되지 않습니다. 한 명의 보유자의 경우 방문 간에 동일하게 유지됩니다. 키가 풀에 합류하거나 풀에서 나갈 때 또는 해당 비밀이 순환될 때 변경될 수 있습니다.
- 셀 수 있는 창에서 슬라이스는 할당량 저장소에 있는 구성원의 카운터이며 자체 `consumed` 와 동일한 카운터입니다.
- `percent` 창에서 슬라이스는 키의 자체 공유로 읽혀진 동일한 책의 구성원의 `attributed` 부분입니다. 풀 외부에서 이루어진 사용량은 조각으로 분할되지 않습니다. 해당 전하는 무게로 분할되므로 이를 운반하는 조각에 무게가 표시됩니다.
- 각 뷰는 다른 멤버 및 셀 수 있는 창당 하나의 값을 병렬로 읽습니다. `percent` 창에서 슬라이스는 공유 자체 책 읽기 외에 읽기 비용이 들지 않습니다. 하나의 값을 읽을 수 없으면 해당 창에는 `members` 가 없으며 키 자체 공유는 그대로 유지됩니다.
- 옵션 및 사용 가능한 키 수는 풀당 한 번 읽혀지며, 계정 데이터를 볼 수 있는 키에 대해서만 읽혀집니다. 옵션이나 사용 가능한 키 수를 읽지 못하면 해당 풀에 대한 막대가 꺼집니다. 서버는 경고를 기록하고 나머지 뷰가 구축됩니다.

막대에는 이름이나 ID가 없습니다. 그들은 여전히 키 보유자에게 다른 멤버에 대해 다음과 같이 말합니다.

- 보유자는 여전히 해당 값에 따라 슬라이스를 일치시킬 수 있습니다.
- 안정적인 번호 지정을 통해 보유자는 시간이 지남에 따라 한 회원을 따라갈 수 있습니다.
- 슬라이스 수는 풀에 할당된 키 수를 나타냅니다.
- 세 개의 키 풀에서 하나의 키가 무엇인지 아는 사람은 마지막 키가 무엇을 사용했는지 알 수 있습니다.
- 풀이 사용 가능한 키 3개 미만으로 떨어지면 막대가 사라집니다. 이전에 찍은 보기에는 여전히 각 구성원이 사용한 내용이 표시됩니다.
- 계산 가능한 창에서 풀 합계에서 조각을 뺀 값은 더 이상 할당되지 않은 키의 사용을 표시할 수 있습니다.
- 한 계정에서 0을 표시하고 다른 계정에서 사용하는 회원은 어떤 회원이 어떤 계정을 사용하는지 알 수 있습니다.
- `hard` 정책이 적용된 셀 수 있는 풀에서 구성원의 공평한 몫으로 성장이 멈추는 조각은 해당 구성원의 가중치를 암시합니다.

### 사용법 시리즈(`GET /api/v1/me/usage`)

`GET /api/v1/me/usage?range=<range>` ( `/v1/me/usage` 에서도 제공됨)는 호출 키 자체 요청의 사용량과 비용을 반환합니다. 즉, 총계, UTC 일당, 일별 및 모델별, 모델별 및 공급자별 항목 1개를 반환합니다. 이는 플래그, 인증 규칙, `self:usage` 범위, `Cache-Control: no-store` 및 위 할당량 경로의 오류 동작을 공유합니다. 키는 `range` 전에 확인됩니다. 오류는 400(`Invalid range`), 401, 403, 404 및 500(`Failed to build usage`)입니다.

- `range` `1d`, `7d`, `30d` (기본값) 또는 `90d` 중 하나입니다. 다른 값, 빈 값 또는 반복되는 매개변수는 400입니다. 세트는 호출 비용을 제한하기 위해 `90d` 에서 중지됩니다. 보기는 원시 사용 내역만 읽으며 키가 없는 일일 요약은 읽지 않습니다.
- 행은 호출 키의 ID로 선택됩니다. 키 이름 열은 일치하지 않으며 키 ID 없이 기록된 행은 계산되지 않습니다.
- 시리즈를 작성하면 창의 키 행에 대해 5개의 그룹화된 쿼리가 실행됩니다. 구축된 시리즈는 키 및 범위당 60초 동안 재사용되며 재사용된 호출은 아무 것도 실행하지 않습니다. `generatedAt` 는 나이를 알려줍니다.
- 시리즈가 구축되면 기간이 종료됩니다. 예를 들어 시계 왜곡으로 인해 나중에 스탬프가 찍힌 행은 계산되지 않습니다.
- `coverage.retentionDays` 는 운영자의 원시 사용 내역 보존 설정입니다(데이터베이스 설정의 `retention.usageHistory` ). 요청된 범위가 해당 설정보다 길면 `coverage.truncatedByRetention` 는 true입니다. 두 숫자를 비교하고 행이 실제로 누락되었는지 여부는 확인하지 않습니다.
- 공급자는 키 자체 요청에 대해 기록된 대로 반환됩니다. Model은 마지막 `/` 다음에 기록된 이름이며 행은 이를 기준으로 그룹화됩니다. 모든 대상이 거부된 콤보 요청은 라우팅 레이블을 공급자(콤보 이름, `auto` 또는 `combo`)로, 클라이언트가 보낸 모델 문자열과 함께 기록됩니다. 개방형 회로 차단기, 모델 휴지 기간 또는 할당량 지정 건너뛰기로 인해 거부된 기타 요청은 대상 공급자와 모델을 유지합니다.
- 개수와 비용 외에도 응답에는 평균 대기 시간, 성공률, 첫 번째 요청과 마지막 요청 시간이 포함됩니다.
- `byModel` 요청이 가장 많은 공급자-모델 쌍 50개를 나열합니다. 더 많은 쌍을 사용하면 해당 항목이 `summary` 까지 합산되지 않으며 `summary.uniqueModels` 기록된 모든 모델 철자를 계산합니다. 그런 다음 `byModelTruncated` 는 참이고 쌍이 컷의 양쪽에 있는 모델은 부분 합계를 표시합니다.
- 두 가지 비용이 보고됩니다. `costUsd` 는 사용량 분석에 표시된 대로 청구 비용입니다. Claude Code 플랜과 같은 정액 구독 제공업체에서는 $0를 계산합니다. `listPriceUsd` 구독이 포함된 정가로 가격이 책정된 동일한 사용량입니다. 모델에 가격 행이 없는 요청은 저장된 비용(공급자가 보고한 비용 또는 요청이 기록될 때 계산된 비용)을 계산합니다. 개수가 0이 아니고 마커가 없는 요청만 있으므로 총계가 부분적일 수 있습니다.
- 응답 계약은 `src/shared/schemas/selfUsage.ts` ( `docs/openapi.yaml` 의 `SelfUsageSeries` )입니다.

### 셀프 서비스 페이지

`QUOTA_SELF_PANEL` 켜면 `/quota/{provider}` 는 공개 페이지가 됩니다. 키 보유자는 거기에 API 키를 입력하고 공급자에 대한 해당 키 풀을 확인합니다. 각 풀은 풀 창당 하나의 카드를 표시하며, 풀은 모든 사람이 사용할 수 있고 키는 자체 공유됩니다. 풀의 각 계정에는 계정 사용 및 키 공유가 포함된 자체 카드가 있습니다. 계정 사용은 키가 계정 데이터를 볼 수 있는 경우에만 나타납니다. 이 페이지에는 각 계정의 모델별 제한과 키 자체 사용량도 나열되어 있습니다. 현재 일정에 따라 키가 차단되면 알림이 표시됩니다. 카드에는 모델별 키 사용 한도가 모두 나열되고 도달한 한도가 표시됩니다. `{provider}` 는 공급자 ID 또는 별칭(`/quota/claude`, `/quota/cc`)입니다. 알 수 없는 공급자와 플래그가 꺼져 있는 동안 모든 `/quota/*` 경로는 404로 응답합니다. 사용자 정의 OpenAI 또는 Anthropic 호환 노드의 풀에는 페이지가 없습니다. API 는 여전히 그들에게 대답합니다.

페이지에 세션이 없습니다. 키는 `GET /api/v1/me/quota/{provider}`, `PATCH /api/v1/me/quota/{provider}` 및 `GET /api/v1/me/usage` 의 `Authorization` 헤더로만 전송되며 URL 에서는 전송되지 않습니다. 서버가 받아들이는 키는 탭의 `sessionStorage` 에 보관됩니다. "이 장치에 기억하기"를 사용하면 대신 `localStorage` 에 보관되고 "키 잊어버리기"를 사용하면 둘 다에서 제거됩니다. 서버가 거부한 키는 저장소에서 제거됩니다.

`consent` 모드의 풀에는 대출 카드가 표시됩니다. 여기서 키 보유자는 대여할 키 유휴 지분의 전체 백분율을 0에서 100까지 설정합니다. 보유자는 또한 동의가 지속되는 기간(해제될 때까지, 1시간, 8시간, 24시간, 7일 또는 30일)을 선택합니다. 기간은 저장한 순간부터 계산됩니다. 마감일이 유효한 동안 보유자는 이를 대신 유지할 수 있습니다. 저장하기 전에 해당 기한이 지나면 카드는 아무 것도 보내지 않고 다른 선택을 요청합니다. 0%이면 마감일이 전송되지 않습니다. 카드에는 저장된 기한과 해당 시간대가 표시됩니다. 기한이 지난 동의는 종료된 것으로 표시됩니다.

`hard` 키의 경우 카드에는 풀 창별로 현재 키에 제공되는 다른 키도 나열됩니다. 각 행은 다른 모든 키에 대한 하나의 숫자입니다. 두 개의 키 풀에서는 다른 키 자체의 모습입니다. 뷰가 보고하지 않는 수치는 0이 아니라 사용할 수 없는 것으로 읽혀집니다. `soft` 또는 `burst` 키의 경우 카드에 숫자가 적용되지 않는다고 표시됩니다.

키가 0보다 큰 백분율을 저장하는 `saturation` 모드의 풀은 인출만 표시합니다. 저장된 백분율은 아무런 영향을 미치지 않는다고 말합니다. 출금 버튼은 기한 없이 0을 보냅니다. 0이 저장된 `saturation` 모드의 풀에는 대출 카드가 표시되지 않습니다. 저장 후 반환된 보기에 더 이상 필요하지 않은 카드는 페이지 보기가 다시 변경될 때까지 메시지와 함께 유지됩니다.

보유자가 저장 또는 철회를 누를 때까지 아무것도 저장되지 않습니다. 각 누를 때마다 하나의 `PATCH /api/v1/me/quota/{provider}` 요청이 전송되고 두 번째 누를 때마다 첫 번째 요청이 보류되는 동안 아무 것도 보내지 않습니다. 본문은 뷰, 백분율 및 마감일에서 풀의 불투명한 `ref` 전달합니다. 대답은 다시 작성된 할당량 보기이며, 페이지에는 두 번째 읽기 없이 이를 표시합니다. 두 개의 저장이 겹치는 경우 페이지는 마지막 답변 이후에 할당량을 한 번 읽습니다. 페이지는 브라우저 저장 공간에 동의를 유지하지 않습니다.

거부된 변경 사항은 HTTP 상태에서 선택한 텍스트로 카드에 설명되어 있습니다. 오류 본문을 읽을 수 없습니다. 401은 키가 승인되지 않았음을 나타내며 할당량을 다시 로드합니다. 403은 풀이 대출 변경을 받아들이지 않는다고 말하고, 404는 풀이 사라졌다는 것을 의미합니다. 둘 다 할당량을 다시 로드하는 버튼을 제공합니다. 400 또는 다른 4xx 답변은 보유자에게 백분율과 마감일을 확인하도록 요청합니다. 429는 소유자에게 응답이 제공될 때 `Retry-After` 의 초와 함께 기다리라고 요청합니다. 5xx 응답, 408 또는 네트워크 오류는 변경 사항이 저장되지 않았을 수 있으며 입력된 값을 유지한다는 의미입니다. 계약 외부의 답변은 할당량을 다시 로드합니다. 저장에 실패해도 키 자체가 제거되지는 않습니다. 다시 로드가 거부된 후 페이지는 거부된 읽기와 마찬가지로 키를 제거합니다.

키가 승인되면 페이지에 세 개의 탭이 있는 '도구 설정' 카드도 표시됩니다. "Claude Code"는 `~/.claude/settings.json` 에 대한 `env` 블록을 제공합니다. "Shell"은 `export` 라인과 동일한 변수를 제공합니다. "Claude Desktop"은 타사 추론 창에 대한 값을 제공합니다. 모델은 키가 해당 공급자에 대해 호출할 수 있는 할당량 공유 모델입니다. 키와 함께 해당 목록이 제공되지 않으면 블록은 대신 게이트웨이 모델 검색을 켭니다. 게이트웨이 주소는 서버가 보고하는 공개 API 원본입니다(`OMNIROUTE_PUBLIC_API_BASE_URL`, 그 다음 `OMNIROUTE_PUBLIC_BASE_URL`). 둘 다 설정되지 않은 경우 카드에는 자리 표시자가 표시되고 소유자에게 관리자에게 문의하라는 메시지가 표시됩니다. 키는 자리 표시자로 표시됩니다. "내 키 포함"은 화면의 텍스트와 복사 버튼이 복사하는 내용에 전체 키를 넣습니다. 이는 상자를 치울 때까지, 키를 잊어버리거나 교체할 때, 또는 페이지를 떠날 때까지 지속됩니다. 카드는 요청을 보내지 않으며 파일 다운로드를 제공하지 않습니다.

API 표시 `stale` 읽으면 아마도 오래된 것으로 표시됩니다. `unavailable` 표시하는 판독값은 그 이유와 함께 표시되며 결코 0으로 표시되지 않습니다.

백분율 계획에서 페이지는 API 보고할 때 키의 자체 공유를 가져옵니다. 숫자는 추정치이며 두 부분의 이름을 지정합니다. 모델별 한도에는 계정만 표시됩니다.

창이 `members` 전달하는 경우 해당 카드에는 슬롯 순서대로 멤버당 하나의 세그먼트가 있는 막대도 표시됩니다. 묻는 키의 세그먼트는 강조 색상을 사용합니다. 다른 세그먼트는 테마의 차트 색상을 순환합니다. 텍스트 범례에는 모든 세그먼트가 해당 값과 함께 나열되므로 색상에 따라 달라지는 것은 없습니다. 세그먼트에는 `You` 또는 `Member N` 레이블이 지정됩니다. 여기서 N은 슬롯입니다.

### 페이지 전용 포트

`QUOTA_PANEL_PORT` 셀프 서비스 페이지만 제공하는 두 번째 리스너를 엽니다. 변수가 설정되지 않으면 꺼져 있습니다. `QUOTA_PANEL_HOST` 는 바인드 주소이고 기본값은 `127.0.0.1` 입니다.

리스너는 이러한 경로를 기본 포트에 전달하고 다른 모든 경로에 대해 404로 응답합니다.

| 길                                                                       | 서브                            |
| ------------------------------------------------------------------------ | ------------------------------- |
| `/quota/{provider}`                                                      | 페이지                          |
| `/api/v1/me/quota/{provider}`, `/v1/me/quota/{provider}`                 | 페이지가 읽는 할당량 보기       |
| `/api/v1/me/usage`, `/v1/me/usage`                                       | 페이지에서 읽는 사용법 시리즈   |
| `/_next/static/`                                                         | 빌드의 스크립트, 스타일 및 글꼴 |
| `/favicon.ico`, `/favicon.svg`, `/icon-512.png`, `/apple-touch-icon.png` | 아이콘                          |

`GET` 및 `HEAD` 는 본문 없이 전달됩니다. 본문이 포함된 요청 하나도 전달됩니다. 즉, 페이지에서 대출 선택 사항을 저장하기 위해 보내는 할당량 보기 경로의 `PATCH`. 응답 없이 연결이 닫히는 CONNECT 요청을 제외하고 다른 모든 방법은 404에 응답합니다. 본문을 선언하는 다른 요청은 404로 응답하고 연결이 닫힙니다. 업그레이드 요청이 거부되고 연결이 종료됩니다. API 포트에서처럼 도트 세그먼트나 조각 마커가 있는 경로는 거부됩니다. 인쇄 가능한 ASCII 외부 문자가 있는 요청 대상도 마찬가지입니다. 대상의 원시 제어 문자는 이 포트 자체 검사 전에 HTTP 파서에 의해 400으로 응답됩니다. 프레임워크가 자체 사용을 위해 예약한 요청 헤더( `x-middleware-`, `x-invoke-`, `x-nextjs-`, `x-now-` 또는 `x-next-` 로 시작하는 이름과 `x-matched-path` 및 `next-resume` 이름)는 릴레이되지 않습니다. 요청은 해당 항목 없이 전달됩니다. 대시보드, 로그인 페이지, 관리 API 및 추론 경로는 이 포트를 통해 연결할 수 없습니다.

`PATCH` 매개변수가 없거나 `charset=utf-8` 만 있는 `Content-Type: application/json` 전달해야 합니다. 1부터 4096까지의 `Content-Length` 중 하나를 일반 숫자로 작성해야 하며 `Transfer-Encoding` 포함하지 않아야 합니다. 이러한 규칙 중 하나를 위반하는 `PATCH` 404로 응답합니다. 서명된 길이 또는 반복된 길이와 같은 일부 잘못된 길이는 이 포트 자체 검사 전에 HTTP 파서에서 400으로 응답합니다. 포트는 기본 포트에 연결하기 전에 선언된 바이트를 읽고 최대 5초 동안 기다립니다. 그때까지 완성되지 않은 몸체는 404라고 응답하고 연결이 닫힙니다. 이 경우 또는 클라이언트가 먼저 떠날 때 아무것도 기본 포트에 도달하지 않습니다. 포트는 동일한 `Content-Length` 사용하여 선언된 바이트를 정확하게 릴레이합니다. 그 뒤의 바이트는 연결의 다음 요청으로 읽혀집니다. 앞에 있는 TLS 역방향 프록시는 `Content-Length` 전달해야 하며 요청 본문을 다시 청크해서는 안 됩니다. 기본 포트는 `GET` 과 마찬가지로 `Authorization` 헤더의 API 키를 확인합니다.

404 본문은 `{"error":"not_found","message":"Not found."}` 입니다. 실패한 릴레이는 `detail` 필드 없이 502(`api_bridge_unavailable`) 또는 504(`api_bridge_timeout`)로 응답합니다.

리스너는 `QUOTA_SELF_PANEL` 읽지 않으며 페이지를 켜지도 않습니다. 플래그가 꺼져 있는 동안 페이지와 해당 API 기본 포트에서 404로 응답하고 리스너는 해당 응답을 중계합니다.

개발 서버(`next dev`)에서는 페이지가 이 포트를 통해 대화형이 되지 않습니다. 개발용 핫 리로드 소켓은 업그레이드 요청이며 포트에서 이를 거부합니다. 개발하는 동안 기본 포트를 사용하십시오.

포트는 일반 HTTP 제공하고 페이지는 API 키를 보냅니다. 기본 바인드 주소를 유지하고 앞에 TLS 있는 역방향 프록시를 배치합니다. 루프백 이외의 바인드 주소는 다음 알림을 기록합니다.

```text
[Quota Panel] Bound to <host>. This port serves plain HTTP and the page sends API keys. Put a TLS reverse proxy in front of it.
```

전달 헤더를 보내지 않는 루프백 피어는 기본 포트에서 로컬로 간주됩니다. 따라서 동일한 호스트의 프록시는 `X-Forwarded-For` 보내야 합니다. 개인 주소의 프록시는 `OMNIROUTE_TRUST_PROXY=private` (또는 `lan`)를 통해서만 해당 헤더에 대해 신뢰됩니다. 다른 모든 피어는 해당 연결 주소로 보고되며 전송된 전달 헤더는 삭제됩니다.

수신기는 한 번에 최대 256개의 연결을 보유합니다. 클라이언트는 요청 헤더를 보내는 데 10초가 걸리고 전체 요청을 보내는 데 30초가 걸립니다. 유휴 상태 유지 연결은 약 5초 후에 닫힙니다. 60초 동안 활동이 없으면 연결이 닫힙니다. 이 값은 고정되어 있습니다. 앞의 역방향 프록시에도 연결 및 속도 제한을 설정합니다. 앞의 역방향 프록시는 5초 미만 동안 유휴 업스트림 연결을 유지하거나 재사용하지 않아야 합니다. 기본 포트에 대한 릴레이는 API 포트(`API_BRIDGE_*`)의 업스트림 시간 초과를 사용합니다.

`API_PORT` 설정되지 않은 경우에도 리스너가 시작됩니다. `QUOTA_PANEL_PORT` 1부터 65535까지의 포트여야 하며 숫자로만 작성됩니다. 대시보드 포트 및 API 포트와 달라야 합니다. 라이브 WebSocket 서버가 켜져 있는 동안에는 `LIVE_WS_PORT` 와도 달라야 합니다(기본값 20132). 다른 값은 아무것도 열리지 않고 경고를 기록합니다. 거부된 값에 대한 경고는 변수 이름을 지정하고 해당 값을 반복하지 않습니다. 이미 사용 중인 포트는 아무것도 열리지 않으며 다음 경고를 기록합니다.

```text
[Quota Panel] Port <port> is already in use. The quota panel port stays off.
```

`OMNIROUTE_BASE_PATH` 설정하면 리스너는 해당 접두사 아래의 모든 경로를 예상합니다. 빌드 타임과 런타임에 동일한 `OMNIROUTE_BASE_PATH` 사용하십시오. 선행 슬래시를 사용하고 후행 슬래시 없이 작성합니다(예: `/omniroute`). `/` 및 `/omniroute/` 포함한 다른 형태는 빌드가 해당 양식을 허용하더라도 경고와 함께 포트를 꺼둡니다. 첫 번째 세그먼트가 애플리케이션 경로를 명명하는 기본 경로( `api`, `v1`, `v1beta`, `_next`, `quota`, `dashboard`, `docs`, `login`, `codex`, `responses`, `anthropic`, `openai`, `v0` 또는 `connect`)도 마찬가지입니다.

제한사항:

- 뒤에 슬래시가 있는 `/quota/{provider}/` 이 포트에서 404로 응답합니다.
- 서비스 워커와 웹 앱 매니페스트는 이 포트에서 제공되지 않습니다.
- 대시보드에 설정된 사용자 정의 파비콘은 이 포트에 표시되지 않습니다.
- 애플리케이션이 기본 경로에서 실행되는 경우 아이콘이 표시되지 않습니다.
- 포트는 일반 HTTP/1.1. 말합니다.
- 실패한 바인드는 프로세스가 다시 시작될 때까지 재시도되지 않습니다.
- 리스너에는 클라이언트 주소당 연결이나 속도 제한이 없습니다.
- 컨테이너 설정은 이 섹션에서 다루지 않습니다.

## 문제 해결

### Redis가 구성되었지만 연결되지 않는 경우

`ioredis`가 설치되어 있고(`npm ls ioredis`) `QUOTA_STORE_REDIS_URL`에 접근할 수 있는지 확인하세요. 연결에 실패하면 팩토리는 SQLite로 대체됩니다(`warn` 수준으로 기록됨).

### `peek`가 오래된 결과를 반환하거나 장애 허용 방식으로 동작하는 경우

`peek`에서 예외가 발생하면 `enforceQuotaShare`는 결과를 "허용"으로 처리합니다(장애 허용 방식). 근본 원인을 파악하려면 `pino` 로그에서 `quota:enforce` 및 `quota:factory` 항목을 확인하세요.

### 소비 카운터 편차

실제 제공자 사용량이 카운터와 다르더라도 이는 예상된 동작입니다. 2버킷 슬라이딩 윈도우는 윈도우 경계에서 약 1%의 오차가 있으며, `consume`은 응답 후 비동기 실행 방식으로 처리됩니다. 포화 신호(`saturationSignals.ts`)는 30초 TTL로 실제 제공자 사용률을 읽고 그에 따라 `globalUsedPercent`를 조정합니다.

### 풀의 소진율에 "데이터 없음"이 표시되는 경우

`computeBurnRate`에는 최소 2개의 과거 샘플이 필요합니다. 이전 `consume` 호출이 없는 새 풀에는 `tokensPerSecond: 0` 및 `timeToExhaustionMs: null`이 표시됩니다.

## DB 스키마 요약

`078`, `079` 및 `085` 마이그레이션으로 추가된 세 개의 테이블:

- `quota_pools` + `quota_allocations` — 풀 정의 및 키별 할당.
- `quota_consumption` — `(apiKeyId, dimensionKey)` 2버킷 카운터 롤링.
- `provider_plans` — 수동 공급자 계획이 재정의됩니다( JSON 당 connectionId 차원).

멱등성 `CREATE TABLE IF NOT EXISTS` 마이그레이션을 통해 추가된 모든 테이블.

동의된 대출에는 `quota_allocations.lending_percent` (정수, 기본값 0), `quota_allocations.lending_until` (에포크 밀리초 또는 기한이 없는 경우 `NULL` ) 및 `quota_pools.borrow_mode` (기본값 `saturation`)의 세 가지 열이 추가됩니다. 마이그레이션에서는 이러한 열만 추가하고 기존 행은 쓰지 않습니다.

백분율 속성 책에는 `quota_percent_ledger` (풀, 계정 및 계획 창당 하나의 행) 및 `quota_percent_ledger_tokens` (풀, 계정 및 API 키당 하나의 토큰 카운터)가 추가됩니다. `src/lib/db/quotaPercentLedger.ts` 이를 읽고 씁니다.
