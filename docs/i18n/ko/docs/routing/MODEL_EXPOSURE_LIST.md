> 옵트인, 기본적으로 꺼짐(`modelVisibilityAllowlist`/`modelVisibilityDenylist` 둘 다 비어 있으면 `/v1/models` 카탈로그 AND 모든 `auto/*` 후보 풀 바이트와 동일하게 유지됩니다). 비용과 관련이 없는 이유로 선별된 모델 목록을 원하는 운영자를 위한 `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`)의 형제입니다.

## 이것이 존재하는 이유

`hidePaidModels` "이 모델은 무료인가요?"라고 대답합니다. 그리고 `hideAutoCombos` " `auto/*` 가상 ID를 전혀 광고해야 합니까?"라고 대답합니다. — 운영자가 임의의 모델 하위 집합을 선별하는 것을 허용하지 않습니다(예: 가격과 관계없이 특정 Claude 코드/ OpenCode 클라이언트가 봐야 하는 모델을 정확히 제시함). #11481은 이를 두 개의 독립적인 옵트인 문자열 배열 설정으로 추가합니다.

## 설정

| 키                         | 유형       | 기본 | 의미                                                                    |
| -------------------------- | ---------- | ---- | ----------------------------------------------------------------------- |
| `modelVisibilityDenylist`  | `string[]` | `[]` | 후보자와 일치하는 항목은 catalog/candidate 풀에서 해당 항목을 숨깁니다. |
| `modelVisibilityAllowlist` | `string[]` | `[]` | 비어 있지 않으면 후보와 일치하는 ONLY 항목이 계속 노출됩니다.           |

둘 다 각각 최대 200자로 구성된 최대 500개의 항목을 허용합니다( `src/shared/validation/settingsSchemas.ts` 에서 Zod 검증됨). 항목은 다음 중 하나입니다.

- 정확한 카탈로그 ID — `"gpt-4o"` (기본 모델 ID) 또는 `"openai/gpt-4o"` (제공자 접두사) 또는
- `*`/`?` — 사용하는 glob 패턴(예: `"openai/gpt-4*"` 또는 `"anthropic/*"` — 은 `ModelRoutingSection` 의 모델별 콤보 매핑 및 `freeModels.ts::matchesOnlyPaidModels` 에서 이미 사용하는 동일한 공유 `globToRegex()` 일치자(`src/shared/utils/globPattern.ts`)를 통해 확인됩니다.

우선순위: 거부 목록이 먼저 확인됩니다(거부된 항목은 허용 목록과 일치하더라도 항상 숨겨집니다). 허용 목록이 비어 있지 않으면 일치하는 항목만 유지됩니다.

## 하나가 아닌 두 개의 관문

#6512(콤보 후보 풀이 독립적으로 구축되었기 때문에 `hidePaidModels` -only 카탈로그 필터는 여전히 `auto/*` 유료 모델로 라우팅할 수 있음)의 교훈이 여기에 동일하게 적용됩니다. 일치하는 조건자 `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`)는 BOTH 에서 호출됩니다.

- `src/app/api/v1/models/catalog.ts` — `/v1/models` 목록 자체는 `shouldHidePaid()` 이미 게이트하고 있는 소스별 초크포인트 5개(정적 `PROVIDER_MODELS`, 동기화된 공급자 행, 사용자 정의 행, 별칭 지원 행, 관리형 대체 행)에 있습니다.
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — 동등한 `filterPaidOnlyCandidates()` 호출 직후에 `virtualFactory.ts::buildPreparedPool` 에서 호출되므로 거부된 모델은 결코 `auto/*` 후보 풀로 선택될 수 없습니다.

## NOT 필터링이란 무엇입니까?

`hideAutoCombos` 의 기존 동작을 미러링합니다. 모델 ID가 전송되었습니다.** 명시적으로** ( `auto/*` 통하지 않고 카탈로그 목록을 통해 발견되지 않음) — 디스패치 시 절대 차단되지 않습니다. advertisement/candidate-pool 멤버십만 필터링됩니다. 이는 `hidePaidModels` 와 무관합니다. 운영자는 비용과 관련이 없는 이유로 선별된 세트를 원할 수 있으므로 두 설정 모두 `catalog.ts` 의 기존 다중 플래그 구성과 마찬가지로 독립적인 AND 필터로 구성됩니다.

설정 내보내기(`GET /api/settings/export-json`)에는 `hidePaidModels` 의 콤보 단계 내보내기 필터와 달리 다른 설정 필드 — 와 마찬가지로 두 배열이 그대로 포함되며 여기에는 재수화 위험이 없습니다. 내보낸 콤보 단계에 포함된 거부된 ID는 내보내기 경계를 제거해야 하는 것이 아니라 운영자 자신의 명시적인 라우팅 선택입니다.

## 콤보 전용 목록(`exposeCombosOnly`)

콤보가 공개 모델 표면이고 공급자가 백엔드인 배포를 위한 별도의 부울(기본적으로 옵트인 및 `false` 입니다. `true` 인 경우 공개 목록(`GET /v1/models`, `GET /v1` 및 `getUnifiedModelsResponse()` 에 구축된 다른 `/v1` 검색 경로)은 `owned_by: "combo"`: 사용자 콤보와 내장 `auto/*` 콤보( `hideAutoCombos` 숨기지 않는 한)가 있는 행만 유지합니다. 이는 키별 `catalogScope: "combos"` 와 동일한 행 테스트를 사용하며 키 자체의 allow/deny/scope 필터는 여전히 맨 위에 적용됩니다.

그것을 전환** 설정 → 라우팅 → 모델 API 목록** , 또는 `PATCH /api/settings {"exposeCombosOnly": true}`.

위 목록과 마찬가지로 광고만 변경됩니다.

- 명시적인 `provider/model` ID는 여전히 전달되고 `GET /v1/models/{id}` 여전히 이를 해결합니다.
- 대시보드 카탈로그( 모델 선택기에서 사용되는 `GET /api/models/catalog`)는 좁혀지지 않습니다.
- `auto/*` 후보 풀에 미러링되지 않으므로 `auto/*` 콤보는 전체 풀을 유지합니다.
