OmniRoute는 npm + Docker 아티팩트를 게시합니다. 이러한 게이트는 오픈 소스(OSS) 기반으로, 릴리스 워크플로에 통합되어 출처(provenance), 인벤토리(SBOM) 및 CVE 스캐닝을 제공합니다. **권고 우선(Advisory-first)** 접근 방식 — 현재는 보고만 하며, 첫 번째 성공적인 릴리스 이후 차단으로 전환됩니다.

| 게이트                | 도구                                           | 위치                          | 차단 여부?       | 출력                                         |
| :-------------------- | :--------------------------------------------- | :---------------------------- | :--------------- | :------------------------------------------- |
| SLSA 출처 (npm)       | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | 게시 실패 시에만 | 뱃지 npmjs / `npm audit signatures`          |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | 생성 실패 시에만 | 릴리스 자산 + 아티팩트                       |
| SBOM 이미지           | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (병합)   | 권고             | CycloneDX 아티팩트                           |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (병합)   | 권고             | SARIF (HIGH+CRITICAL) → 보안 탭              |
| Trivy CRITICAL 게이트 | `aquasecurity/trivy-action`                    | `docker-publish.yml` (병합)   | **차단**         | 수정 가능한 CRITICAL에 대해 `exit-code: '1'` |
| osv 취약점 수         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **차단**         | `metrics.vulnCount`를 래칫합니다 (방향:하향) |
| OpenSSF 스코어카드    | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | 권고             | SARIF → 보안 + 뱃지                          |

이미지 CVE 래칫은 `docker-publish.yml`에서 **두 단계**를 사용합니다. SARIF 단계(`HIGH,CRITICAL`, `exit-code: 0`)는 HIGH+CRITICAL을 차단 없이 보안 탭에 표시합니다. _CRITICAL 게이트_ 단계(`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`)는 **수정 가능한** CRITICAL CVE에 대해 릴리스를 실패시킵니다. `ignore-unfixed`는 업스트림 패치가 없는 기본 이미지 CVE로 인해 릴리스가 차단되는 것을 방지합니다.

## ⚠️ CVE 변동성(차단형 osv/Trivy 게이트)

osv와 Trivy는 **지속적으로 증가하는** CVE 데이터베이스를 기준으로 의존성을 비교합니다. **의존성을 전혀 변경하지 않은** PR도 기존 의존성에서 새로운 CVE가 공개되면 갑자기 실패 상태가 될 수 있습니다(osv: 측정된 `vulnCount` > 기준선, Trivy: 이미지에서 수정 가능한 새로운 CRITICAL 발견). **이는 차단형 CVE 게이트에서 예상되는 운영 동작이며, 제품 회귀가 아닙니다.**

새로 공개된 CVE로 인해 osv 또는 Trivy가 실패하면 다음과 같이 조치합니다.

1. **영향받는 의존성 버전 상향**(권장) — `package.json`의 `overrides`(전이 의존성)를 통해 패치된 버전으로 업그레이드하거나, 패치된 베이스를 사용해 이미지를 다시 빌드합니다.
2. **해결 방법을 사용할 수 없는 경우:** 측정된 결과를 유지하고 영향을 받은 종속성 또는 이미지를 추적합니다. 실패한 후보를 통과시키기 위해 취약성 기준을 높이지 마십시오. Trivy의 `ignore-unfixed: true` 는 업스트림 패치 없이 이미 이미지 취약점을 제외합니다. 모든 예외에는 검토된 취약점 ID, 정확한 패키지 경로, 정책의 만료 및 추적 문제가 필요합니다. 이는 스캔 실패로 인해 자동으로 발생하는 결과가 아닙니다.

필수 OSV 실행(`check:vuln-ratchet -- --ratchet`)에서는 스캐너, 보고서 또는 기준선을 검증할 수 없는 경우 `INCOMPLETE`와 종료 코드 2로 폐쇄형 실패가 발생합니다. 측정된 회귀의 종료 코드는 1입니다. 권고 실행은 여전히 종료 코드 0과 함께 `SKIP`을 보고할 수 있지만, 이는 의존성이 스캔을 통과했음을 입증하지 않습니다. 차단형 Trivy 단계에서도 성공적인 측정이 필요합니다. 사용할 수 없는 도구, 실패한 작업, 이미지 증거 누락으로는 이미지가 안전하다고 인증할 수 없습니다.

## 이미지 스캔 정책

현재 `.trivyignore.yaml` 에는 취약점 예외가 없습니다. `npm run check:trivy-ignore-policy` 로컬 스캔 프로필, CI 및 품질의 구조화된 정책을 검증합니다. 알 수 없는 IDs, 더 넓은 경로, 중복된 항목 및 만료된 예외는 거부됩니다. 레거시 `.trivyignore` 마이그레이션된 스캔에 대한 입력이 아닙니다.

Docker `github.workflow_sha` 의 정책 도구와 빌드와 동일한 소스 선택기를 사용하여 이미지 소스 정책을 확인합니다. 정책 선택기는 호환되지 않는 범위를 거부하고 두 Trivy 스캔에 대해 하나의 파일을 준비합니다. 구조화된 정책이 없는 기록 소스는 예외를 받지 않습니다. 두 스캔 모두 Trivy `v0.70.0` 고정합니다. 정책 검증을 통해 구성 일관성이 입증됩니다. 이미지를 성공적으로 스캔해야 합니다.

## 은퇴 의존성 위험

고정된 Promptfoo 개발 도구를 업그레이드한 후 루트 잠금 파일에는 더 이상 `extract-zip` 또는 종속성 에지가 포함되지 않습니다. 이는 #14482 에서 추적된 이전에 허용된 `promptfoo` → `@openai/codex-security` → `extract-zip` 체인을 폐기합니다. `tests/unit/extract-zip-14482-exposure.test.ts` 의 회귀 검사는 재도입을 거부하고 프로덕션 코드에서 가져오기를 금지합니다.

또한 현재 종속성 복구는 Azure ID의 MSAL 클라이언트 및 get-uri의 FTP 클라이언트에 대한 호환성 재정의 범위를 지정합니다. Azure 토큰 획득 및 FTP 검색은 제어된 전송을 통해 테스트됩니다. 두 OpenCode 패키지 모두 자체 빌드 및 테스트 스위트를 실행합니다. 레지스트리 권고 개수는 특정 시점의 측정값이며 잠금 파일이 커밋된 후에 변경될 수 있습니다.
