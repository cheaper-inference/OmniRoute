OmniRoute는 비공식 클라이언트를 능동적으로 지문 식별하는 엣지(TLS JA3/JA4, 헤더 순서, JSON 본문 형태, 무결성 토큰)를 사용하는 제공자와 통합됩니다. 이 페이지에서는 OmniRoute가 노출하는 스텔스 영역과 그 구현 위치를 설명합니다.

## 법적 및 윤리적 고지

스텔스 기능은 OmniRoute가 사용자가 소유한 공식 계정(Claude Code CLI, Codex, Antigravity, Cursor 등)과 OmniRoute의 통합 API 사이에서 호환성 계층으로 작동할 수 있도록 제공됩니다. 이 기능은 사기 탐지를 회피하거나, 자격 증명을 공유하거나, 제공자의 서비스 약관을 위반하기 위한 것이 **아닙니다**. 유지관리자는 운영자가 계정을 생성할 때 동의한 업스트림 서비스 약관을 준수할 것으로 기대합니다.

## TLS 핑거프린팅 계층

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

영구 `wreq-js` 세션은 계정 범위와 확인된 프록시별로 지연 생성됩니다. 프로세스 전역 `TlsClient`는 Cloudflare 뒤에 있는 업스트림을 위해 **macOS의 Chrome 124**를 가장하는 세션을 최대 128개까지 풀링합니다. 네이티브 런타임을 사용할 수 없으면 `TlsClient.fetch()`는 실패 시 차단되며, 호출자는 이 래퍼 외부에서 폴백을 명시적으로 선택할 수 있습니다.

- 세션 프로필: `browser: "chrome_124", os: "macos"`
- 프록시 확인(우선순위): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (소문자 형식도 포함)
- 타임아웃: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS`에서 상속, 기본값 600000)
- `wreq-js` Response는 fetch와 호환됩니다(`headers`, `text()`, `json()`, `clone()`, `body`).
- 첫 바이트 감시 타이머(`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`는 업스트림 헤더가 도착하는 즉시 완료되므로, `TLS_CLIENT_TIMEOUT_MS`만으로는 첫 바이트를 전혀 생성하지 않는 본문의 시간을 제한할 수 없습니다. `guardTlsFirstByte()`는 본문의 첫 번째 `read()`와 `TLS_FIRST_BYTE_WATCHDOG_MS`(기본값 `10000`, `0`이면 비활성화)를 경합시킵니다. 정상적인 본문에는 영향을 주지 않지만, 본문이 중단되면 wreq 리더를 취소하고 `proxyFetch`의 기존 TLS 폴백 로직이 직접/프록시 디스패처로 넘어가도록 합니다(예: 본문이 있는 POST처럼 재실행이 안전하지 않은 요청은 자동으로 재시도되지 않고 여전히 예외를 발생시킵니다).

### 웹 쿠키 제공자 전송 계층 — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts`는 아래의 특수 웹 쿠키 전송 계층 5개에서 공유하는 어댑터입니다. 각 경량 제공자 래퍼는 브라우저/OS 프로필을 선택합니다. 이 어댑터는 `open-sse/utils/tlsClient.ts`의 단일 wreq 런타임 로더와 전송 풀을 사용하며, 프로필 + OS + 확인된 프록시를 키로 사용합니다. 한편 모든 요청은 `cookieMode: "ephemeral"`을 사용합니다. 따라서 계정과 요청은 전송 계층 연결을 공유하지만, wreq 세션이나 쿠키 저장소는 절대 공유하지 않습니다.

| 제공자     | 프로필        | 에뮬레이션 OS | 스트림 EOF 정책                   |
| ---------- | ------------- | ------------- | --------------------------------- |
| Claude     | `chrome_146`  | Linux         | `[DONE]` 포함                     |
| Perplexity | `firefox_151` | macOS         | `event: end_of_stream` 포함       |
| Grok       | `chrome_146`  | Linux         | `[DONE]` 제외                     |
| Notion     | `chrome_146`  | Windows       | `[DONE]` 포함                     |
| LMArena    | `chrome_146`  | Windows       | 센티널 없음, 네이티브 EOF 시 닫기 |

- 스트리밍은 네이티브 응답 `ReadableStream`을 직접 사용하며, 임시 파일이나 사이드카를 생성하지 않습니다.
- 스트림을 노출하기 전에 초기 바이트를 최대 256개까지 검사합니다. SSE 제공자는 SSE가 아닌 오류를 버퍼링하며, Grok/LMArena는 Cloudflare 챌린지를 `403`으로, HTML 중간 페이지를 `502`로 매핑합니다.
- 네이티브 요청 타임아웃은 절대적인 JS 하드 데드라인으로 계속 래핑됩니다. 중단이 발생하면 영향을 받은 프로필/OS/프록시 전송 계층만 무효화하고 닫으며, 다음 요청이 이를 다시 생성합니다.
- 프록시 확인 우선순위는 호출별 `proxyUrl` → 요청 범위의 계정/대시보드 컨텍스트 → `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY`(소문자 형식 포함)입니다. 확인 오류가 발생하면 직접 연결이 유출되지 않도록 실패 시 차단됩니다. LMArena는 의도적으로 `arena.ai`를 기준으로 확인합니다.
- `byteResponse`는 UTF-8 손상 없이 콘텐츠 유형이 지정된 `data:` URL을 반환합니다.
- 오류는 `TlsClientUnavailableError`(패키지/애드온을 사용할 수 없음), `TlsClientHangError`(데드라인 초과), 그리고 제한된 128개의 프로필/OS/프록시 슬롯이 모두 활성 상태이거나 닫히는 중일 때 발생하는 `WreqTransportCapacityError`(공유 세션 용량 오류 코드)입니다.

위의 범용 `TlsClient` 세션은 브라우저 기반의 영구 쿠키 상태에 특화된 상태로 유지됩니다. 두 경로는 하나의 캐시된 wreq 모듈 로더와 프로세스 수명 주기 훅을 재사용하지만, 의도적으로 쿠키 수명이 다르므로 각 풀은 분리된 상태로 유지됩니다.

해당 프로필은 고정된 패키지에서 지원되지만, 실제 WAF 허용 여부는 로컬 계약 테스트와 무관하게 변경될 수 있습니다. 업스트림 브라우저와 동등하다고 주장하기 전에 명시적으로 승인된 실제 계정에서 핑거프린트 변경 사항을 검증하십시오.

## Claude Code 스텔스 번들

`cliCompatMode`가 켜져 있으면 OmniRoute는 발신 Claude 요청을 `claude-cli` 트래픽과 구별할 수 없도록 재구성합니다. 세 모듈이 함께 작동합니다.

### `claudeCodeFingerprint.ts`

결제 헤더에 포함되는 3자 `cc_version` 지문을 계산합니다.

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"`(하드코딩됨, 공식 클라이언트와 일치)
- 입력: 첫 번째 사용자 메시지 텍스트의 인덱스 4, 7, 20에 있는 문자 + 버전 문자열
- 출력: 3자의 16진수 접두사

### `claudeCodeCCH.ts` (클라이언트 콘텐츠 해시)

공식 Claude Code CLI가 Bun/Zig를 통해 계산하는 서버 측 무결성 검사입니다. OmniRoute는 이를 `xxhash-wasm`으로 재구현합니다.

1. `cch=00000;` 자리표시자를 사용하여 본문 직렬화
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. 0으로 채운 5자의 소문자 16진수
4. `cch=00000;`을 계산된 토큰으로 교체

상수:

- 시드: `0x6e52736ac806831e`
- 패턴: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

업스트림 필터가 "민감한" 클라이언트 이름을 grep으로 검색하지 못하도록 해당 이름의 첫 번째 문자 뒤에 유니코드 **폭 없는 결합자**(`U+200D`)를 삽입합니다. 기본 단어 목록:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

적용 대상: `system` 블록, 모든 `messages[].content`, 그리고 `tools[].description` / `tools[].function.description`. 운영자는 `setSensitiveWords()`를 통해 재정의할 수 있습니다.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` 제공자

"실제 Claude Code" 트래픽만 허용하는 서드파티 Anthropic 릴레이용입니다.

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- 기본적으로 `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- 연결별 "Enable redact-thinking beta" 토글은 CC Compatible 업스트림에서 수정된 사고 스트림이 특별히 필요한 경우 `redact-thinking-2026-02-12`를 추가합니다.
- 연결별 "Enable summarized thinking display" 토글은 `providerSpecificData.requestDefaults.summarizeThinking`을 저장하고, 아직 표시 모드가 설정되지 않은 CC Compatible 사고 요청에 `display: "summarized"`를 추가합니다.
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"`(Opus/Sonnet 4.x 제품군)
- 기본 경로: `/v1/messages?beta=true`

동일한 번들에 포함된 관련 모듈:

- `claudeCodeConstraints.ts` — temperature + cache-control 규칙
- `claudeCodeToolRemapper.ts` — 도구 이름 재매핑
- `claudeCodeExtraRemap.ts` — 추가 페이로드 정규화

## Antigravity 스텔스

Antigravity 요청은 호출자 텍스트를 바이트 단위로 보존합니다. OmniRoute IDE 클라이언트를 모방하기 위해 프롬프트나 rename/inject 도구에 너비가 0인 문자를 삽입하지 않습니다.

### `antigravityHeaderScrub.ts`

전달하기 전에 스테인리스 SDK 마커(`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`)를 제거합니다.

### ⚠️ 위험: `ANTIGRAVITY_CREDITS=always` (계정 금지 핫스팟)

`ANTIGRAVITY_CREDITS=always` ( `open-sse/executors/antigravity.ts` 에서 사용) 경로 **모든** Google 의 무료 계층 할당량을 제한하는 대신 Antigravity AI 크레딧 초과(유료 Google 크레딧)를 통해 요청하세요. 이는 기능으로 문서화되어 있지만 **우리가 볼 수 있는 가장 일반적인 ToS 위반 보고서** — 여러 Google Ultra 계정이 `=always` 로 몇 시간 동안 실행된 후 `403 / "service disabled for ToS violation" / insufficient_quota` 로 금지되었습니다.

업스트림 시행이 켜져 있습니다.**Google 측** , OmniRoute 막을 수 있는 것은 아무것도 없습니다. env var 이름과 기존 문서를 보면 뒤집기에 안전한 손잡이처럼 들립니다. 그렇지 않습니다.

**이것이 무료 계층 전용 사용보다 남용 감지를 더 적극적으로 유도하는 이유는 다음과 같습니다.**

- 단일 Google 계정에 대한 지속적인 자동 지출은 무료 계층 히트 할당량 및 중지와 다르게 플래그를 지정합니다.
- 신용 초과에는 비율 상한선이 없으므로 잘못 구성된 클라이언트는 몇 분 만에 수백 개의 USD 소모하여 API 키 재판매 또는 봇 트래픽처럼 보일 수 있습니다.
- 여러 OmniRoute 사용자가 동일한 외부 IP 에서 동시에 초과 크레딧에 도달하면 신호가 합성됩니다.

**권장 자세:**

1. 운영자가 유료 신용 및 계정 집행 위험을 명시적으로 수락하지 않는 한 기본 `ANTIGRAVITY_CREDITS=off` 유지합니다. `retry` 먼저 일반 요청을 보내고 적격 할당량 429 이후 최대 한 번 크레딧을 주입합니다. `always` 첫 번째 요청에 크레딧을 주입합니다.
2. **자동 콤보를 통해 공급자 간에 부하 분산** (`model: "auto"` 또는 `kr/glm/etc` -combo) 단일 Antigravity 계정을 포화시키는 대신.
3. **연결당 RPM 제한 설정** Antigravity 공급자의 편집 페이지(대시보드 → 공급자 → Antigravity → 연결 → 속도 제한)에서. 30-60 RPM 는 지속적인 사용을 위한 방어 가능한 상한선입니다.
4. **안정적인 운영자 제어 업스트림 네트워킹 사용** 관련 없는 사용자나 작업 부하 간에 하나의 계정을 공유하지 마세요.
5. **금지된 경우** : 정확한 `quota_exceeded` / `service disabled` 응답 본문 Google 전송된 `support.google.com` → " Workspace/Account 액세스 복원"을 통해 항소합니다. 복원이 보장되지 않습니다.

환경 참조에는 각 크레딧 모드의 계정 및 지출 의미가 문서화되어 있습니다.

#### `=always` 뿐만 아니라 Antigravity OAuth 라우팅 전반

정지는 신용 초과에만 국한되지 않습니다. 2026년 11월 보고서(#19223, #19266)에서는 `antigravity` 및 `agy` (Antigravity CLI) 제공업체를 통해 라우팅하는 동안 정지된 여러 Google 계정에 대해 다음과 같이 설명합니다.

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

두 공급자 모두 Antigravity 제품 OAuth 세션으로 인증합니다. 이는 연결이 추가되기 전에 대시보드의 위험 알림("이 공급자는 proxy/router 사용이 승인되지 않은 공식 제품 session/OAuth 사용합니다.")에서 경고하는 경우입니다. 위의 권장 사항 중 어느 것도 해당 사용을 승인하지 않습니다. 하나의 계정이 전달하는 트래픽의 양만 줄입니다.

**Gemini 모델용으로 승인된 API 인터페이스.** Google APIs 통해 Gemini 에 대한 프로그래밍 방식의 액세스를 제공하며, OmniRoute 이를 일반 API 키 공급자로 지원합니다.

| 제공자 ID | 대시보드 이름               | 신임장                                                                 |
| --------- | --------------------------- | ---------------------------------------------------------------------- |
| `gemini`  | Gemini (Google AI 스튜디오) | Google AI Studio의 Gemini API 키(무료 등급 사용 가능)                  |
| `vertex`  | 버텍스 AI                   | 서비스 계정 JSON, OAuth 액세스 토큰 또는 Vertex Express API 키(Gemini) |

이러한 공급자는 Antigravity 제품 세션과 달리 API 액세스를 위해 자격 증명 Google 문제를 사용합니다. 모든 사용을 규정에 맞게 만들거나 시행 위험을 제거하지는 않습니다. 각각은 자체 조건에 따라 관리되며 운영자는 배포를 확인해야 합니다. 예를 들어, [Gemini API 추가 서비스 약관은](https://ai.google.dev/gemini-api/terms) API 클라이언트가 유럽 경제 지역, 스위스 또는 영국의 사용자에게 제공되고 무료 서비스로 전송된 콘텐츠가 Google 제품을 개선하는 데 사용될 수 있는 경우 유료 서비스만 허용합니다. Vertex AI 대신 Google Cloud 약관( [서비스별 약관](https://cloud.google.com/terms/service-terms) )을 따릅니다. 가격과 할당량은 Antigravity 구독이 아닌 API 조건을 따릅니다.

위에 설명된 Antigravity 정지를 피하려는 운영자는 해당 서비스의 사용이 공급자의 조건에 맞는지 확인한 후 `antigravity` / `agy` 대신 이러한 공급자 중 하나를 통해 Gemini 트래픽을 라우팅해야 합니다.

터치 포인트:

- `open-sse/executors/antigravity.ts` — `process.env.ANTIGRAVITY_CREDITS` 를 읽습니다.
- `src/lib/oauth/providers/antigravity.ts` — 자격 증명 배관
- 사건 보고서 원본: 토론 [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## CLI 핑거프린트 레지스트리 — `open-sse/config/cliFingerprints.ts`

공식 CLI의 mitmproxy 트레이스에서 캡처한 **정확한** 헤더 순서와 JSON 본문 필드 순서를 고정하는 공급자별 테이블입니다. 현재 등록된 항목은 `codex`, `claude`이며, `antigravity`와 `github`의 경우 `providerHeaderProfiles.ts`에서 런타임에 파생된 프로필도 포함됩니다.

```ts
interface CliFingerprint {
  headerOrder: string[]; // 대소문자 구분
  bodyFieldOrder: string[]; // 최상위 JSON 키
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

환경 변수를 통해 공급자별로 전환합니다(아래 참조). 비활성화하면 헤더/본문 키는 Node/JSON이 제공한 순서대로 표시되므로 핑거프린팅하기 쉽습니다.

## MITM 프록시(Antigravity, Linux/macOS/Windows)

바이너리를 `OPENAI_BASE_URL`을 통해 리디렉션할 수 없는 CLI를 위해 OmniRoute는 로컬 TLS 종단 프록시를 실행합니다. 엔드포인트는 `src/app/api/cli-tools/antigravity-mitm/` 아래에 있습니다.

| 메서드 | 엔드포인트                              | 용도                                             |
| ------ | --------------------------------------- | ------------------------------------------------ |
| GET    | `/api/cli-tools/antigravity-mitm`       | 상태 — 실행 여부, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM 시작(`apiKey` + `sudoPassword` 필요)        |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM 중지                                        |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | 모델 별칭 목록 조회                              |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | 도구의 모델 별칭 저장                            |

가로채기 대상 호스트: **`daily-cloudcode-pa.googleapis.com`**(Antigravity의 업스트림).

### 시작 순서(`src/mitm/manager.ts::startMitm`)

1. `selfsigned`를 통해 자체 서명 인증서 생성(RSA-2048, SHA-256, 1년) — `cert/generate.ts`
2. 시스템 신뢰 저장소에 인증서 설치 — `cert/install.ts`
3. hosts 항목 `127.0.0.1 daily-cloudcode-pa.googleapis.com` 추가 — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT`(기본값 `443`)를 사용하여 `src/mitm/server.cjs` 실행
5. PID를 `<DATA_DIR>/mitm/.mitm.pid`에 영구 저장

### Linux 동적 신뢰 저장소 감지 — `cert/install.ts`

`getLinuxCertConfig()`는 우선순위 목록을 순회하며 처음으로 존재하는 디렉터리를 선택합니다.

| 배포판 계열              | 디렉터리                                    | 업데이트 명령            |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

인증서 파일명: `omniroute-mitm.crt`. `getCertFingerprint()`를 통해 핑거프린트를 일치시킵니다(DER의 SHA-1).

또한 `certutil`을 사용할 수 있는 경우 `updateNssDatabases()`는 사용자별 NSS DB인 `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, 모든 Firefox 프로필(snap 포함)에 **`OmniRoute MITM Root CA`**라는 별칭으로 설치합니다.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** 관리자 권한 PowerShell → `certutil -addstore Root`

### 인증

모든 MITM 엔드포인트에는 관리 인증(`requireCliToolsAuth`)이 필요합니다. sudo 비밀번호는 모듈 범위에 캐시되며(`globalThis`에는 저장되지 않음), `stopMitm()` 호출 시 삭제됩니다.

## 인바운드 헤더 정리

OmniRoute는 요청을 전달하기 전에 인바운드 클라이언트 헤더를 제거하여, Cursor에서 들어온 요청의 `User-Agent: Cursor/X.Y.Z`가 Claude 업스트림에 노출되지 않도록 합니다. Zod 스키마 및 단위 테스트와 동기화된 거부 목록은 `src/shared/constants/upstreamHeaders.ts`를 참조하세요.

## 공급자가 핑거프린트를 변경할 때 업데이트하기

1. `mitmproxy`로 공식 CLI 트래픽 캡처(TLS 가로채기 + 덤프)
2. JA3/JA4 및 실제 헤더 순서 추출
3. 관련 `CLI_FINGERPRINTS[...]` 항목 업데이트
4. `.env.example`에서 일치하는 `*_USER_AGENT` 기본값 올리기
5. TLS 핸드셰이크 자체가 변경된 경우 관련 공급자 래퍼 또는 wreq-js `browser:` 옵션 업데이트
6. 공급자별 TLS 테스트를 실행하고 실제 공급자를 대상으로 수동 카나리아 테스트 수행
7. 패치 릴리스로 배포하고 `CHANGELOG.md`에 문서화
