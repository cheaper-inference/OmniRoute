## 아동 환경과 생애주기

`omniroute run`, `omniroute launch` 및 `omniroute launch-codex` OS/terminal 호환성 허용 목록을 상속하고 선택한 대상의 자격 증명을 삽입합니다. 관련되지 않은 공급자 및 데이터베이스 비밀은 기본적으로 상속되지 않습니다. `--inherit-env` 전체 상위 환경 상속을 명시적으로 복원합니다. 선택한 타사 프로세스가 해당 값을 받아야 하는 경우에만 사용하세요. 이것은 OS 샌드박스가 아닌 환경 필터링입니다. 프로세스는 여전히 호출자의 파일 시스템 권한으로 실행됩니다.

인터럽트 및 종료 신호가 하위 항목으로 전달됩니다. 실행 프로그램은 임시 구성을 제거하기 전에 하위 항목의 닫기 이벤트를 기다립니다. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` 강제 종료 전 유예 기간을 제어합니다(기본값 5000밀리초).

`omniroute launch <tool>` ( [LAUNCH.md](./LAUNCH.md) 참조)는 동일한 환경 규칙과 신호 전달을 따르고 다음을 추가합니다.

- **게이트웨이 자동 시작.** 로컬 대상의 경우 포트에서 게이트웨이가 응답하지 않으면 실행 프로그램은 분리된 reaper 프로세스에서 `127.0.0.1` 에 바인딩된 `omniroute serve --headless --no-open` 시작합니다. 실행 중인 각 실행은 `DATA_DIR/launch/leases/` 에서 임대를 보유합니다(15초마다 하트비트, 45초 이후 또는 해당 프로세스가 사라진 경우 무효화됨). 유휴 유예 기간(`OMNIROUTE_LAUNCH_IDLE_GRACE_MS`, 기본값은 10000밀리초) 동안 임대가 활성화되지 않으면 reaper는 시작한 게이트웨이를 중지합니다. 사용자가 시작한 게이트웨이가 사용되지만 중지되지는 않습니다. `--keep-gateway` 또는 `omniroute gateway keep` 런처 게이트웨이를 일반 게이트웨이로 바꿉니다. `--no-start` 이전의 Fail-If-Down 동작을 복원합니다. 원격 대상은 프로브만 됩니다.
- **세션을 시작하세요.** 시작할 때마다 상위 자격 증명(`POST /api/launch/sessions`)에서 단기 `olx_` 세션 토큰을 생성하고, 도구가 실행되는 동안 이를 하트비트하고, 사용 요약을 읽고, 도구가 종료된 후 이를 취소합니다. 토큰은 동일한 권한, 동일하거나 더 좁은 카탈로그, 더 짧은 수명 등 상위 항목의 엄격한 하위 집합이며 대시보드 자격 증명이 아닙니다. 도구는 상위 자격 증명이 아닌 세션 토큰을 수신하며 `--tag` 제공되지 않는 한 요청에는 `launch:<tool>:<sessionId>` 태그가 지정됩니다. 세션 API 없는 게이트웨이는 범위가 지정되지 않은 실행으로 돌아가는 대신 `GatewayTooOld` 와 함께 실패합니다.
- **출시별 구성.** 도구 구성 파일은 개인 임시 디렉터리(모드 0700, 접두사 `omnirouter-`)에 기록되고 하위 항목이 종료된 후 제거됩니다. 런처의 `SIGKILL` 디렉토리를 뒤에 둡니다. `omniroute launch --cleanup` 해당 디렉토리가 하루보다 오래되면 제거합니다.

## Gemini 영구 설정

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

처음 두 명령은 선택한 로컬 또는 원격 서버에 대해 이 시스템을 구성합니다. 설정은 관련되지 않은 JSON 설정을 유지하고, Gemini API 키 인증을 선택하고, 엔드포인트와 자격 증명을 개인 `.gemini/.env` 파일에 기록합니다. 덮어쓰는 대신 유효하지 않은 JSON 거부합니다. 엔드포인트 URLs 내장된 자격 증명, 쿼리 매개변수 또는 조각이 없는 HTTP(S)여야 합니다. 테스트 실행에서는 자격 증명 값이 아닌 경로를 인쇄합니다.

`GEMINI_CLI_HOME` 또는 `--gemini-home` 영구 홈 루트를 선택합니다. 실제 `run gemini` 자체 임시 홈을 생성하고 나중에 제거합니다. 두 모드 모두 Gemini 의 작업 공간 신뢰 검사를 우회하지 않습니다.

## Codex 프로필

`configure codex` 모델과 해당 OmniRoute 공급자 끝점을 사용하여 비공개 `<name>.config.toml` 작성합니다. 자격 증명은 `OMNIROUTE_API_KEY` 통해 참조되며 포함되지 않습니다. launch 명령은 선택한 모델을 `model_providers` 내부가 아닌 최상위 `model` 키에 설정합니다.

별도의 프로필 파일은 현재 문서화된 Codex 계약입니다. `codex --profile <name>` 로 선택하면 사용자 구성이 오버레이됩니다. [공식 프로필 참조](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) 및 [OmniRoute Codex 가이드를](./CODEX-CLI-CONFIGURATION.md) 참조하세요.

## 밀폐형 명령 실행

명시적인 `DATA_DIR` 사용하여 `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` 설정하면 시작이 기본 사용자 데이터 디렉터리의 자격 증명 환경으로 떨어지는 것을 방지할 수 있습니다. 이는 격리된 테스트에 유용합니다. 명시적으로 선택된 다른 환경 파일은 비활성화되지 않습니다.

## 작업 디렉토리 `.env`

CLI 는 `.env` 파일을 이 순서대로 읽고 키를 설정한 첫 번째 파일이 우선합니다. 명시적 `DATA_DIR`, 기본 데이터 디렉터리, 현재 작업 디렉터리, 패키지 디렉터리 순입니다. 쉘 변수는 항상 승리합니다.

작업 디렉토리는 다른 사람(복제된 저장소, 압축이 풀린 아카이브)에 속할 수 있으며 `omniroute serve` CLI 환경을 서버와 서버가 실행하는 모든 도구에 전달합니다. 따라서 `.env` `bin/cli/utils/untrustedCwdEnv.mjs` 에 나열된 다음 키만 설정할 수 있습니다.

| 키                              | 허용되는 값                                                          |
| ------------------------------- | -------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` 또는 `yes` 어떤 경우든 서버가 처리하는 값                |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 최대 64개의 문자, 숫자, `_`, `.`, `@` 또는 `-`                       |
| `LANGUAGE`                      | 똑같고 게다가 `:`                                                    |
| `TZ`                            | 최대 64개의 문자, 숫자, `_`, `+`, `-` 또는 `/`, `/` 로 시작하지 않음 |
| `NO_COLOR`, `FORCE_COLOR`       | 최대 16개의 문자 및 숫자                                             |

`REQUIRE_API_KEY` 허용하는 모든 값은 검사를 활성화하므로 파일 자체는 검사를 해제할 수 없습니다. 하지만 결과를 결정하지는 않습니다. 서버는 환경 이전에 데이터베이스에 저장된 `REQUIRE_API_KEY` 재정의를 읽는 반면, API 키 없이 모든 인터페이스에서 수신 대기에 대한 시작 경고는 환경만 읽습니다. `false` 의 저장된 대체를 사용하여 작업 디렉토리 `REQUIRE_API_KEY=true` API 를 열어두고 해당 경고를 숨깁니다. `TZ` 규칙은 POSIX 보다 좁습니다. 즉, `.`, `:`, `,` 및 `<>` 거부하므로 `EST5EDT,M3.2.0,M11.1.0` 과 같은 `:Area/City` 형식과 규칙은 셸이나 `<DATA_DIR>/.env` 에서 설정해야 합니다.

이름은 대문자로 정확하게 일치해야 합니다. 다른 줄, 검사에 실패한 값, 일반 ASCII 문자, 숫자 및 `_` 가 아닌 이름(예: NUL 바이트 또는 유사한 문자가 있는 이름)은 건너뜁니다. CLI 는 설정할 수 없는 키의 이름을 지정하는 경고 하나와 무시할 수 있는 키의 이름을 지정하는 경고를 인쇄합니다. 각 경고에는 변경할 항목(`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`)이 포함됩니다. 둘 다 값을 인쇄하지 않습니다. 이러한 메시지의 파일 경로와 `.env` 경로 `omniroute doctor` 보고서는 제어 또는 bidi 문자가 포함된 경우 이스케이프됩니다. 작업 디렉터리가 데이터 디렉터리 또는 패키지 디렉터리인 경우에는 제한이 적용되지 않습니다.

`PORT`, `API_PORT` 및 `DASHBOARD_PORT` 목록에 없습니다. 우선 순위가 높은 소스의 기본 URL 없으면 CLI 는 `localhost:<PORT>` 와 통신하고 거기에서 수신하는 모든 것은 CLI 의 API 키, 컨텍스트 토큰 및 CLI 머신 토큰(`x-omniroute-cli-token`, [CLI_TOKEN.md](../security/CLI_TOKEN.md) 참조)을 수신합니다. 이는 로컬 서버가 루프백의 관리 호출을 허용합니다. 작업 디렉토리의 포트를 사용하면 해당 파일이 리스너를 선택할 수 있으므로 쉘, `<DATA_DIR>/.env` 또는 포트가 있는 명령(`serve`, `launch`, `run`)의 `--port` 옵션을 사용하여 포트를 설정하십시오.

파서에는 `export` 구문이 없습니다. `export LD_PRELOAD=...` 와 같은 줄은 변수 이름을 `export LD_PRELOAD` 지정합니다. 작업 디렉토리에서는 건너뛰고 다른 `.env` 파일에서는 아무것도 읽지 않는 리터럴 이름을 설정합니다.

CLI 는 컨텍스트의 저장된 토큰(액세스 토큰 또는 레거시 API 키)을 해당 컨텍스트의 자체 원본(구성표, 호스트 및 포트)과만 쌍으로 구성합니다 `URL.origin` 와 비교). 이는 CLI 의 HTTP 클라이언트(`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`)를 통해 이루어진 요청과 기본 URL 및 키를 다른 도구의 구성에 쓰는 `launch`, `launch codex`, `configure` 및 `setup-*` 명령에 적용됩니다. `--remote` 사용하여 다른 서버를 가리키면 명시적인 `--api-key` 또는 `OMNIROUTE_API_KEY` 설정된 경우 이를 사용하고 컨텍스트 토큰은 사용하지 않습니다. 비교는 정확하므로 `localhost` 및 `127.0.0.1` 또는 후행 점이 있는 호스트와 없는 호스트는 다른 서버로 간주되며 컨텍스트 토큰을 얻지 못합니다. 사용자 정보, 백슬래시 또는 공백이 포함된 URL 절대 일치하지 않습니다. 왜냐하면 다른 URL 파서(예: Python의 `urllib` 및 `httpx`)가 다른 호스트를 읽을 수 있기 때문입니다. 요청의 경우 CLI 는 자체적으로 전송하며 해당 검사는 체계와 권한만 다루므로 경로나 쿼리에 공백이 있는 ID가 토큰을 유지합니다.
