OmniRoute가 모든 요청의 비용을 추정하고, 기록하고, 보고하는 방식과 대시보드에
표시되는 숫자가 청구 금액이 아니라 **절감액 추적기**인 이유를 설명합니다.

함께 보기: [사용자 가이드](./USER_GUIDE.md) · [기능 갤러리](./FEATURES.md)

---

## 비용의 의미와 그렇지 않은 것

OmniRoute는 토큰 수에 모델의 요금 단가를 곱하여 모든 완료 요청에 요청별 USD
비용을 할당합니다. 이 수치는 **비용** 대시보드, `omniroute cost` / `omniroute usage`
CLI, CSV/JSON 내보내기, API 키별 예산에 사용됩니다.

> **대시보드의 "비용"은 청구 금액이 아니라 절감액 추적기입니다.** OmniRoute는
> 사용자에게 비용을 청구하지 않습니다. 사용자가 이미 연결한 제공업체(자체 구독,
> 무료 등급 및 API 키)로 요청을 라우팅할 뿐입니다. 무료 모델에서만 누적된
> "$290 총비용"은 유료 API에 대략 **$290를 지불하지 *않았다***는 의미입니다.
> 이 수치는 동일한 트래픽을 표준 정가로 처리했다면 발생했을 비용의 _추정치_이므로,
> 사용량이 어디에 집중되는지와 더 저렴하거나 무료인 제공업체로 라우팅하여 얼마나
> 절약하고 있는지 확인할 수 있습니다.

이러한 설명은 프로젝트 [README](../../README.md)에도 직접 명시되어 있습니다
("대시보드의 '비용'은 청구 금액이 아니라 절감액 추적기입니다").

이 수치는 추정치이므로 다음 사항이 적용됩니다.

- 각 모델에 대해 OmniRoute가 보유한 가격표에 따라 달라집니다. 가격 정보가 없는
  모델은 비용에 `0`만큼 기여합니다(탐색기에서 "레거시 / 무료" 행으로 표시됨).
- 무료 등급과 구독을 통한 트래픽에도 _추정_ 비용이 계속 누적됩니다. 이는
  지불해야 할 금액이 아니라 절약 중인 금액입니다.

## 비용 추정 방법

### 가격 소스

비용은 다음 우선순위에 따라 [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) 의 병합된 가격표에서 나옵니다(**가장 높은 것부터** ):

1. **사용자 재정의** — 가격은 대시보드나 `PATCH /api/pricing` ( `pricing` 네임스페이스)를 통해 설정됩니다.
2. **models.dev 동기화** `https://models.dev/api.json` ( `models_dev_pricing` 네임스페이스)에서 가져온 — 가격입니다.
3. **LiteLLM 동기화** LiteLLM 의 공개 `model_prices_and_context_window.json` ( `pricing_synced` 네임스페이스)에서 가져온 — 가격입니다.
4. **하드코딩된 기본값** — 요율은 [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) 로 배송됩니다.

동일한 provider/model 의 경우 우선순위가 높은 레이어의 값이 하위 레이어의 일치하는 필드를 덮어씁니다. 상위 레이어에 없는 필드가 하위 레이어에서 나올 수도 있습니다. 두 개의 독립적인 동기화 작업이 동시에 실행되는 경우에도 순서는 고정됩니다. `GET /api/pricing?includeSources=1` 모델별 레이블(`user`, `modelsDev`, `litellm`, `default`)이 해당 모델을 포함하는 우선순위가 가장 높은 레이어를 식별하는 `pricing` 및 `sourceMap` 반환합니다.

**LiteLLM 동기화** 선택되어 있으며 기본적으로 비활성화되어 있습니다. 환경 변수( [`.env.example`](../../.env.example) 참조)는 다음과 같습니다.

| 환경변수                | 기본      | 목적                                                            |
| ----------------------- | --------- | --------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | 백그라운드 LiteLLM 가격 동기화를 활성화합니다.                  |
| `PRICING_SYNC_INTERVAL` | `86400`   | 동기화 간격(초)(매일)                                           |
| `PRICING_SYNC_SOURCES`  | `litellm` | 이 동기화에 대해서만 소스 선택. 현재는 `litellm` 만 지원됩니다. |

**models.dev 동기화** LiteLLM 동기화와 별개이며 기본적으로 비활성화되어 있습니다. 설정(models.dev sync)에서 활성화하거나 다음 변수를 사용하세요.

| 환경변수                   | 기본              | 목적                                                                                                                                   |
| -------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `MODELS_DEV_SYNC_ENABLED`  | _(설정되지 않음)_ | 설정 해제는 설정 토글을 따릅니다. `1/true/on/yes` 강제로 켜지고 `0/false/off/no` 강제로 꺼집니다(설정에서 활성화한 경우에도 마찬가지). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`           | 기본 models.dev 동기화 간격(초)(매일)                                                                                                  |

`PRICING_SYNC_SOURCES` 는** ~ 아니다** models.dev를 활성화합니다. LiteLLM 동기화만 제어합니다. 사용자 재정의를 삭제해도 동기화된 네임스페이스는 지워지지 않습니다. 사용 가능한 다음 가격 책정 계층이 적용됩니다. 가격이 책정되지 않은 모델의 경우 수동 재정의를 추가하기 전에 동기화 설정과 `sourceMap` 모두 확인하세요.

### 비용 공식

비용은 [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`)의 토큰 수 및 백만 개당 토큰 요율을 사용하여 요청별로 계산됩니다.

- **입력 토큰** (캐시 읽기 및 캐시 생성 토큰 제외) × `input` 속도.
- **캐시 읽기 토큰** × `cached` 속도(입력 속도로 폴백).
- **캐시 생성 토큰** × `cache_creation` 속도(입력 속도로 폴백).
- **출력 토큰** × `output` 환율.
- **추론 토큰** × `reasoning` 속도(출력 속도로 폴백).

모든 요율은 1,000,000개 토큰당 USD 로 해석됩니다. Codex "빠른"/"우선순위" 또는 "플렉스" 서비스 계층은 비용 승수(`getCodexFastCostMultiplier`)를 적용합니다. — 예를 들어 플렉스는 50% 토큰 할인으로 청구되며 다음과 같이 표시됩니다.**플렉스 저축** 대시보드에서.

모델 이름이 먼저 정규화되므로( `openai/` 또는 `accounts/fireworks/models/` 와 같은 공급자 경로 접두사는 제거됨) 기록 행이 여전히 가격과 일치합니다.

### 지출이 기록되는 방식

- 요청당 비용은 요청 완료 시 계산됩니다. 공유 할당량 소비는 [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) 통해 다음 이벤트 루프 틱에 예약됩니다.
- API 키 지출은 [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) 에 의해 일괄적으로 버퍼링되고 플러시됩니다(기본값 60초 플러시 간격, 1,000개 항목 버퍼). 다음을 통해 조정 가능:

  | 환경변수                            | 기본    | 목적                              |
  | ----------------------------------- | ------- | --------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | 플러시 간격(밀리초)입니다.        |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | 플러시 전 최대 버퍼링 항목입니다. |

비용은 공급자가 보고한 정확한 요금(`provider_cost_usd`), 카탈로그 가격 요청 스냅샷(`calculated_cost_usd`), 현재 카탈로그의 토큰 가격 조정을 선호합니다. 저장된 비용은 토큰 수를 통해 다시 청구되지 않습니다. 레거시 토큰 전용 행은 카탈로그 가격이 변경되면 계속 변경됩니다.

### OCR 및 임베딩

- 성공적인 `/v1/ocr` 요청은 요청된 페이지 범위나 반환된 페이지 개체 수가 아닌 업스트림 `usage_info.pages_processed` 사용합니다. 추정치는 페이지 × `ocr_cost_per_page` (절대 USD/page,** ~ 아니다** USD/million).
- 문서 또는 경계 상자 주석이 포함된 요청에는 별도의 `ocr_cost_per_annotated_page` 관세가 필요합니다. 그것이 없으면 비용은 알 수 없습니다. 일반 OCR 관세는 자동으로 대체되지 않습니다.
- LiteLLM 동기화는 업스트림 `annotation_cost_per_page` 필드를 `ocr_cost_per_annotated_page` 에 매핑하여 절대 USD/page 값과 명시적 0을 포함한 주석 전용 항목을 유지합니다. 제공된 표준 필드가 우선합니다. 잘못된 별칭 값은 무시됩니다. 사용자 가격 재정의는 일반적인 우선순위를 유지합니다. [LiteLLM 의 OCR 가격 책정 키를](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) 참조하세요.
- OCR 사용에는 페이지 수, 단가, 계산된 USD 비용, API 키 및 선택한 연결이 저장됩니다. 페이지는 토큰으로 표시되지 않습니다. 통화 기록에는 문서 URLs, PDF 바이트 또는 추출된 텍스트가 아닌 청구 메타데이터가 포함됩니다.
- 성공적인 `/v1/embeddings` 요청은 동일한 밀리초 내에 완료된 별도의 배치를 포함하여 물리적 배치당 하나의 사용 행을 기록합니다. 공급자가 보고한 요금은 토큰 견적보다 우선합니다. 콤보 래퍼에는 요금이 추가되지 않습니다.
- 사용 내역, 비용 분석, provider/account 창, API 키 지출 한도, 요청 비용 원장 및 일일 사용량 롤업에는 이러한 요금이 포함됩니다. 로그 없는 키는 소스 텍스트를 유지하지 않고 숫자 계산을 유지합니다.
- 누락된 사용량 또는 관세는 다음과 같습니다.**알려지지 않은** , 무료 아님: response-cost 헤더가 생략되고 기존의 unpriced-usage 정책이 제한된 API 키에 적용됩니다. 명시적으로 구성된 제로 요율은 유효한 제로 비용 사용량으로 유지됩니다.

이는 전방 전용 회계입니다. 사용 내역을 작성하지 않은 이전 OCR/embedding 호출은 이 마이그레이션에서 재구성할 수 없습니다. 카탈로그 견적은 송장이 아닌 USD 견적이며 통화 변환, 세금 또는 할인을 포함하지 않습니다.

### 음성 및 이미지

- 성공적인 `/v1/audio/transcriptions`, `/v1/audio/speech` 및 이미지 생성 시도는 수치 계산을 공유합니다. 직접 및 콤보 통화는 발신자의 API 키와 선택한 연결을 전달합니다. 콤보 래퍼는 두 번째 직불금을 추가하지 않습니다.
- 공급자가 보고한 USD 명시적인 무료 요금을 포함하여 카탈로그 견적을 이겼습니다. OpenRouter 의 JSON `usage.cost` 는 `cost_usd` 로 정규화됩니다. 그렇지 않으면 측정된 토큰은 토큰 가격을 사용하고, 전사 초는 초당 가격을 사용하고, 음성 입력은 유니코드 문자 수를 사용하고, 균일 가격 이미지는 요청된 `n` 아닌 실제로 반환된 숫자를 사용합니다.
- 바이너리 OpenRouter TTS 에는 JSON 사용 본문이 없습니다. 오디오가 완료되거나 발신자가 취소한 후 OmniRoute 해당 세대 ID 쿼리합니다.**같은** OpenRouter 오리진을 구성했습니다. EU 요청은 글로벌 원본으로 돌아가지 않습니다. 이는 제한된 읽기 전용 조회입니다. 회계처리를 위해 합성을 재시도하지 않습니다. 청구 기록은 오디오가 완료된 후에 나타날 수 있습니다. 조회 재시도는 네트워크 기한을 포함하여 최대 약 52초 동안 백그라운드에서 실행됩니다.
- 해당 조회 중에 오디오 응답에는 `X-OmniRoute-Cost-Status: pending` 있고 응답 비용 헤더가 없습니다. 최종 요금은 조정 후 사용 내역, 분석 및 주요 원장에 표시됩니다. 메타데이터를 사용할 수 없는 경우 구성된 관세 스냅샷이 사용됩니다. 그렇지 않으면 비용을 알 수 없습니다.
- 초, 문자 및 이미지 수에는 별도의 청구 단위 필드가 있으며 가짜 토큰 수는 없습니다. 회계에는 음성 텍스트, 기록 또는 이미지 바이트가 아닌 숫자 사용만 유지됩니다. 기존의 무료 이미지 면제는 변경되지 않습니다. 실제로 누락된 이미지 요금은 제한된 키를 새로 잠그지 않으며 응답은 통화 무료를 선언하는 대신 비용 헤더를 생략합니다. 가격 책정 저장소 오류에도 오류 종료 적용을 위한 사용 증거가 계속 유지됩니다.

과거의 speech/image 요금은 새로 만들어지거나 채워지지 않습니다. 공급자 청구는 청구서 및 요금이 보고되지 않은 통화에 대한 참조로 남아 있습니다.

## 대시보드: 비용 페이지

**비용** 페이지는 `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`)에 있습니다.
기본 화면은 **비용 개요** 탭
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`)이며,
`GET /api/usage/analytics`에서 모든 데이터를 불러옵니다.

표시되는 내용:

- **지출 타일** — _오늘(1일)_, _7일_, _30일_ 및 선택한 기간의 예상 지출입니다.
  기간 선택기: `7d`, `30d`, `90d`, `all`.
- **주요 지표** — 기간 내 요청 수, 활성 제공자 수, 활성 모델 수, 요청당 평균
  비용입니다.
- **비용 탐색기** — **제공자**, **모델**, **API 키**, **계정** 또는 **서비스 티어**별로
  그룹화된 정렬 및 필터링 가능한 테이블로, 비용, 요청 수, 토큰 수, 요청당 평균
  비용 및 전체 대비 비율(%)을 표시합니다.
- **토큰 사용량** — 전체 / 입력 / 출력 토큰 및 입력:출력 비율입니다.
- **라우팅 효율성** — 폴백 횟수, 폴백 비율 및 요청 모델 적용률입니다.
- **월간 예측** — 최근 일평균을 기반으로 월말 지출을 예측합니다.
- **기간 비교** — 기간의 전반부와 후반부 사이의 변화율(%)입니다.
- **차트** — 일별 비용 추이, 제공자 비중(원형), 상위 제공자, 상위 모델, API 키별
  비용, 계정별 비용, 주간 사용 패턴 및 활동 히트맵입니다.
- **내보내기** — 현재 기간의 데이터를 **CSV** 또는 **JSON**으로 다운로드합니다(비용
  데이터가 0이 아닌 경우 버튼이 표시됨).

가격이 책정된 트래픽이 없는 경우 절감액 추적기 모델을 반영하여 행에 `$0` 대신
"레거시 / 무료" 레이블이 표시됩니다.

### 관련 비용 하위 페이지

비용 영역에는 다음 페이지도 있습니다(모두 `/dashboard/costs/` 아래에 위치):

- **가격** (`/dashboard/costs/pricing`) — 모델별 가격을 확인하고 재정의합니다(공유
  가격 탭을 렌더링).
- **예산** (`/dashboard/costs/budget`) — 범위별 지출 한도를 설정합니다(공유
  예산 탭을 렌더링).
- **할당량 공유** (`/dashboard/costs/quota-share`) — 공유 할당량 풀 및 소진율
  보기입니다.

## API 엔드포인트

별도 언급이 없는 한, 다음 엔드포인트는 모두 관리 인증(`requireManagementAuth`를
통한 루프백/JWT)이 필요합니다.

### 사용량 및 비용 분석

| 메서드 | 엔드포인트               | 용도                                                                                                                                          |
| ------ | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/analytics`   | 전체 비용/사용량 분석: 요약, 일별 추이, 제공자/모델/API 키/계정/티어별 데이터. 쿼리: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET`  | `/api/usage/utilization` | 시간대별 제공자별 할당량 사용률. 쿼리: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                           |
| `GET`  | `/api/usage/history`     | 원시 사용량 기록 행.                                                                                                                          |
| `GET`  | `/api/usage/call-logs`   | 요청별 호출 로그(모델, 토큰, 비용, 지연 시간, 상태).                                                                                          |
| `GET`  | `/api/usage/quota`       | 제공자 할당량 상태.                                                                                                                           |
| `GET`  | `/api/usage/proxy-logs`  | 프록시 요청 로그.                                                                                                                             |

### 예산

| 메서드 | 엔드포인트               | 용도                                                                      |
| ------ | ------------------------ | ------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | API 키 하나에 대한 비용 요약 및 예산 확인(`apiKeyId` 쿼리 매개변수 필수). |
| `POST` | `/api/usage/budget`      | API 키의 일간/주간/월간 USD 한도 및 경고 임계값 설정.                     |
| `GET`  | `/api/usage/budget/bulk` | 여러 API 키의 예산 요약 일괄 조회.                                        |

> 예산 API의 범위는 **API 키**(`apiKeyId`)별로 지정됩니다.
> `GET /api/usage/budget`에서 반환되는 한도에는 `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> `warningThreshold` 및 누적 합계(`totalCostToday`, `totalCostMonth`, …)가 포함됩니다.

### 가격

| 메서드   | 엔드포인트              | 용도                                                                                                                                               |
| -------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | 네 계층을 병합한 가격(사용자, models.dev, LiteLLM, 기본값). `?includeSources=1`은 `pricing` + `sourceMap`을 반환합니다.                            |
| `PATCH`  | `/api/pricing`          | `{ provider: { model: { input, output, cached, … } } }`의 가격을 재정의합니다.                                                                     |
| `DELETE` | `/api/pricing`          | 사용자 가격 재정의를 제거합니다. 선택적으로 `?provider=&model=`로 범위를 제한할 수 있으며, 동기화된 요금이나 내장 기본값은 대체 계층으로 남습니다. |
| `GET`    | `/api/pricing/defaults` | 100만 개당 기본 폴백 요율을 표시합니다.                                                                                                            |
| `GET`    | `/api/pricing/models`   | 모델을 키로 사용하는 가격 정보입니다.                                                                                                              |
| `POST`   | `/api/pricing/sync`     | 외부 소스(LiteLLM)에서 수동 동기화를 시작합니다.                                                                                                   |
| `GET`    | `/api/pricing/sync`     | 현재 동기화 상태입니다.                                                                                                                            |
| `DELETE` | `/api/pricing/sync`     | LiteLLM에서 동기화한 가격(`pricing_synced`)만 지웁니다. models.dev 데이터는 별개입니다.                                                            |

### 기타 비용 관련 엔드포인트

| 메서드 | 엔드포인트                    | 용도                                                           |
| ------ | ----------------------------- | -------------------------------------------------------------- |
| `GET`  | `/api/free-tier/summary`      | 무료 모델의 총 토큰, 이번 달 사용량 및 남은 무료 할당량입니다. |
| `GET`  | `/api/quota/pools/[id]/usage` | 공유 할당량 풀의 사용량입니다.                                 |

## CLI

OmniRoute의 CLI는 비용, 사용량 및 가격 명령어를 제공합니다([`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)에 등록됨).

### `omniroute cost`

`/api/usage/analytics`에서 집계된 비용 보고서입니다.

```bash
omniroute cost                          # 최근 30일, 제공업체별 그룹화
omniroute cost --period 7d              # 최근 7일
omniroute cost --group-by model         # provider | model | combo | api-key | day 기준으로 그룹화
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

열: 그룹, 요청 수, 입력/출력 토큰, 비용(USD), 전체 대비 비율(%). 마지막에는 총합 행이 출력됩니다(`--quiet` 또는 `--output json`을 사용하면 출력되지 않음).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # 제공업체별 비용 요약
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# 예산
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`는 `GET /api/pricing/defaults`를 조회합니다. 대신 개별 모델의
> 가격을 편집하려면 **Pricing** 대시보드 페이지 또는 `PATCH /api/pricing`을 사용하세요.

## 문제 해결

- **모든 비용이 $0 / "Legacy / Free"로 표시됩니다.** 사용 중인 모델에 가격 항목이 없습니다.
  외부 동기화를 활성화하고(`PRICING_SYNC_ENABLED=true`) `omniroute pricing sync`를 실행하거나,
  Pricing 페이지 / `PATCH /api/pricing`을 통해 가격을 수동으로 설정하세요.
- **과거 모델의 가격이 잘못 책정되었습니다.** 가격을 수정하세요(재정의 또는 재동기화). 비용은
  분석 데이터를 조회할 때마다 토큰 수를 기준으로 다시 계산되므로 예상치가 소급하여 업데이트됩니다.
- **지출액이 실시간보다 늦게 반영됩니다.** 키별 지출액은 일괄 처리됩니다. 더 최신 수치가 필요하면
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` 값을 낮추세요.
