> **TL;DR**: OmniRoute는 **Arena AI
> (LMArena 스타일) ELO 점수**를 사용하여 모델 품질에 따라 **무료** 제공업체의 순위를 매깁니다.
> 대시보드에서 **무료 제공업체 순위** 페이지를 열어 작업에 가장 강력한 모델을 제공하는
> 무료 제공업체를 확인하세요. 전체 순위를 보거나 카테고리(코딩, 리뷰, 문서화, 디버깅)별로 필터링할 수 있습니다.

---

## 개요

OmniRoute는 376개의 프로바이더를 등록하며, 그중 155개의 카탈로그 항목이 **free/no-auth**(무료/무인증)로
표시되어 있습니다
(무인증,
무료 티어 OAuth, 또는 무료 티어 API 키 —
[무료 티어 가이드](../getting-started/FREE-TIERS-GUIDE.md)와 전체
[무료 티어 디렉터리](../reference/FREE_TIERS.md) 참조). 문제는 무료 프로바이더마다
모델 품질이 천차만별이라는 점입니다. 프론티어 모델을 제공하는 무인증 프로바이더는
소형 레거시 모델을 제공하는 프로바이더보다 훨씬 유용합니다.

**무료 프로바이더 랭킹(Free Provider Rankings)**은 각 무료 프로바이더의 카탈로그를
**Arena AI 리더보드**의 **크라우드소싱 품질 점수**(인간 선호도 ELO, LMArena
챗봇 아레나와 동일한 개념)와 결합하여 "**어느 무료 프로바이더가 최고의 모델을
제공하는가?**"라는 질문에 답합니다. 프로바이더는 각자의 **최고 무료 모델**의
성능을 기준으로 순위가 매겨집니다.

이 랭킹은 세 가지 실제 소스로부터 계산됩니다:

1. 무료 프로바이더 목록 — `NOAUTH_PROVIDERS`와 `hasFree`로 플래그된
   `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` 항목
   (`src/shared/constants/providers.ts`).
2. 프로바이더 레지스트리의 각 프로바이더 모델 카탈로그
   (`open-sse/config/providerRegistry.ts`).
3. Arena ELO 동기화 엔진(`src/lib/arenaEloSync.ts`)이 `model_intelligence` DB 테이블에
   저장하는 ELO 기반 작업 적합도(task-fit) 점수.

조인 로직은 `src/lib/freeProviderRankings.ts`에 있습니다.

## 액세스 방법

### 대시보드 페이지

대시보드를 열고 **비용 → 무료 제공업체 순위**로 이동하거나 다음 경로로 직접 이동하세요.

```
/dashboard/free-provider-rankings
```

이 페이지(`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`)에는 다음이 표시됩니다.

- 순위가 가장 높은 무료 제공업체의 **상위 3개 시상대**(🥇 🥈 🥉).
- **순위**, **제공업체**, **최고 모델**,
  **점수**, **평균 점수**, **모델**, **유형** 열이 포함된 전체 **순위표**.
- **카테고리 필터 버튼**: _모든 카테고리_, _기본_, _코딩_, _리뷰_,
  _문서화_, _디버깅_.

각 제공업체의 **유형** 배지는 무료 제공 방식이 무엇인지 나타냅니다.

| 배지     | 의미                                        |
| -------- | ------------------------------------------- |
| `NOAUTH` | 항상 무료이며 자격 증명이 필요하지 않음     |
| `OAUTH`  | 무료 등급(`hasFree`)이 있는 OAuth 제공업체  |
| `APIKEY` | 무료 등급(`hasFree`)이 있는 API 키 제공업체 |

기반 값은 백분율이 아니라 상대적인 순위 품질이므로 점수는 원시 숫자 대신
사람이 읽기 쉬운 레이블(예: _최상급_, _탁월함_, _매우 좋음_,
_좋음_, _보통_)로 표시됩니다.

### API 엔드포인트

이 페이지는 공개 읽기 엔드포인트
(`src/app/api/free-provider-rankings/route.ts`)를 기반으로 합니다.

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

쿼리 매개변수(Zod로 검증):

| 매개변수   | 유형   | 기본값 | 참고                                                                                             |
| ---------- | ------ | ------ | ------------------------------------------------------------------------------------------------ |
| `category` | string | (없음) | `default`, `coding`, `review`, `documentation`, `debugging` 중 하나. 통합 순위에서는 생략합니다. |
| `limit`    | number | `50`   | `1–100` 범위로 제한됩니다.                                                                       |

응답 형식:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw`는 원래 Arena ELO 값이고, `score`는 정규화된 작업 적합도 값입니다
(아래 참조). 점수가 산정된 모델이 없는 제공업체는 응답에서 제외됩니다.

## 점수 작동 방식

### 소스: Arena AI 리더보드

Arena ELO 동기화 엔진(`src/lib/arenaEloSync.ts`)은 Arena AI 리더보드 API(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`)에서 `text`와 `code` 두 개의 리더보드를 가져옵니다. 해당 API가 사용 가능한 보드를 반환하지 않으면, 엔진은 Hugging Face datasets-server의 공식 `lmarena-ai/leaderboard-dataset`으로 폴백합니다(`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`, `coding` → `code`). `GET /api/intelligence/sync`는 `activeSource`, `lastError`, `lastFailedAt`을 보고합니다. 각 리더보드 항목에는 모델 이름, 벤더, ELO `score`, 신뢰 구간, 투표 수가 포함됩니다.

리더보드 카테고리는 OmniRoute 작업 카테고리에 매핑됩니다:

| Arena 리더보드 | OmniRoute 작업 카테고리                           |
| -------------- | ------------------------------------------------- |
| `text`         | `default`, `review`, `documentation`, `debugging` |
| `code`         | `coding`                                          |

### 정규화(작업 적합도 점수)

원시 ELO 점수는 리더보드별로 **`[0.4, 0.98]` 범위의 작업 적합도(task-fit) 값**으로 정규화됩니다:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

점수는 `0`이나 `1`에 도달하지 않아 사용자 재정의를 위한 여유 공간이 남습니다. 이 값은 API 응답에서 볼 수 있는 `score` 필드이자 대시보드에 표시되는 라벨입니다.

### 신뢰도

각 항목에는 Arena 투표 수를 기반으로 한 신뢰도 수준이 부여됩니다:

| 신뢰도   | 투표 수 |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### 저장 및 데이터 최신성

정규화된 항목은 `source = "arena_elo"`와 함께 `model_intelligence` DB 테이블에 기록됩니다(`src/lib/db/modelIntelligence.ts`). 항목은 **7일 후 만료**되므로, 동기화가 중단된 제공업체는 오래된 데이터를 계속 제공하는 대신 결국 목록에서 제외됩니다.

동기화는 **기본적으로 활성화**되어 있습니다:

- 서버 시작 시 한 번 실행된 후 주기적인 타이머로 실행됩니다
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts`에서 연결됨).
- **논블로킹이며 절대 치명적인 오류를 일으키지 않습니다** — 업스트림 가져오기가 실패해도 OmniRoute는 계속 실행되며, 순위는 마지막으로 정상적으로 가져온 데이터(또는 빈 상태)를 표시할 뿐입니다.

두 개의 환경 변수가 이를 제어합니다([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)에 문서화됨):

| 변수                      | 기본값        | 용도                                                 |
| ------------------------- | ------------- | ---------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | 아웃바운드 동기화를 거부하려면 `false`로 설정합니다. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | 동기화 간격(초).                                     |

### 수동 동기화 / 상태 / 삭제

운영자를 위해 인증된 관리 엔드포인트가 수동 제어 기능을 제공합니다
(`src/app/api/intelligence/sync/route.ts` — 관리 인증 필요):

```
GET    /api/intelligence/sync          # 현재 동기화 상태 (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # 수동 동기화 트리거; 본문: { "dryRun": true }로 쓰기 없이 미리보기
DELETE /api/intelligence/sync          # 동기화된 모든 arena_elo 인텔리전스 항목 삭제
```

순위 페이지가 비어 있다면, 수동으로 `POST /api/intelligence/sync`를 호출하거나(또는 단순히 서버를 재시작하여) 다시 채울 수 있습니다.

### 모델을 리더보드와 매칭하기

레지스트리 모델 ID와 Arena 모델 이름이 항상 정확히 일치하는 것은 아닙니다. 순위 지정에는 유연한 매칭이 사용됩니다(`src/lib/freeProviderRankings.ts`의 `findMatchingIntelligence`):

1. 정규화된 모델 ID의 정확한 일치.
2. 끝의 버전 접미사를 제거한 후 일치(예: `kimi-k2.6` → `kimi-k2`).
3. 접두사 일치(리더보드 모델 이름이 레지스트리 ID의 접두사인 경우).

동기화 측에서는 알려진 벤더 접두사(`anthropic/`, `openai/`, `google/`, …)가 제거되고, 작은 별칭 맵이 정규 이름을 OmniRoute가 내부적으로 사용하는 변형으로 확장하므로, 모델은 어떤 이름으로도 찾을 수 있습니다.

### 제공업체 순위 지정 방식

각 무료 제공업체에 대해 엔진은 카탈로그의 모든 모델에 점수를 매긴 후:

- **Top Model(최상위 모델)** = 해당 제공업체에서 가장 점수가 높은 모델.
- **Avg Score(평균 점수)** = 해당 제공업체의 점수가 매겨진 모든 모델의 평균 점수.
- **Models(모델 수)** = 해당 제공업체의 모델 중 Arena 점수가 있는 모델의 수.

제공업체는 먼저 **최상위 모델 점수**로, 그다음 평균 점수로 정렬됩니다. 이는 최소 하나의 강력한 무료 모델을 제공하는 제공업체에 유리한 방식입니다.

## 무료 제공업체를 선택하는 데 활용하기

1. **적절한 카테고리를 선택하세요.** 에이전트형/코딩 워크로드에는 **Coding** 필터를 사용하고, 일반 채팅에는 **All Categories** / **Default**로 두세요. 리더보드마다 최상위 모델이 다르기 때문에 동일한 제공업체라도 카테고리에 따라 순위가 달라질 수 있습니다.
2. **한 번에 구성하려면 최상위권을 우선하세요.** 무료 제공업체를 한두 개만 연결하려면 해당 카테고리에서 순위가 가장 높은 제공업체부터 시작하세요.
3. **Type 배지를 확인하세요.** `NOAUTH` 제공업체는 자격 증명이 필요 없어 가장 빠르게 연결할 수 있습니다. `OAUTH` / `APIKEY` 무료 티어는 간단한 가입이 필요하지만, 더 강력한 모델을 제공하는 경우가 많습니다. 연결 단계는 [무료 티어 가이드](../getting-started/FREE-TIERS-GUIDE.md)를 참조하세요.
4. **여러 제공업체를 연결하고 Auto-Combo가 결정하도록 하세요.** 이 페이지를 구동하는 것과 동일한 Arena ELO 데이터가 Auto-Combo 점수 산정 엔진의 **작업 적합성 요소**에도 사용됩니다(`open-sse/services/autoCombo/taskFitness.ts`, 결정 우선순위: `user_override → arena_elo → models_dev_tier → static table`). 따라서 상위 무료 제공업체를 연결한 후 `model: "auto"`(예: `auto/coding`)로 라우팅하면 요청별로 품질이 더 높은 무료 모델이 자동으로 우선 선택됩니다. 전체 16개 요소의 점수 산정 방식은 [Auto-Combo](../routing/AUTO-COMBO.md)를 참조하세요.
