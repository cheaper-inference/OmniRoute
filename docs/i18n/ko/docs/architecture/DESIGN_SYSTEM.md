> **상태:** 대시보드는 **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), 작업 공간 `packages/ui-kit` (`@omniroute/ui-kit`, 업스트림 스냅샷은 `packages/ui-kit/UPSTREAM.md` 에 고정되고 `npm run check:ui-kit-snapshot` 에 의해 보호됨)로 이 저장소에 포함됩니다. 빛은 표준적인 주제입니다. 기본 설정은 `system` 입니다. 기본 팔레트는 키트의 팔레트입니다.**Editions** 외관(따뜻한 종이 중립 및 구리 액센트 `#e5ac82`, `packages/ui-kit/src/ci-editions.css`); 설정 → 모양 → 색상 팔레트 제공 **Classic** , 라임 악센트가 있는 키트의 기본 토큰입니다. Switzer 은 UI 의 기본 제품군이며 텍스트를 표시합니다(`--ci-font-ui`, `--ci-font-display` 및 `--ci-font-mono` 이를 해결함). 키트 자체에서 자체 호스팅됩니다(`packages/ui-kit/src/ci-fonts.css`, `ci-tokens.css` 에서 가져옴). 모든 아이콘은 Lucide 문자 모양입니다.
>
> Inter 는 Switzer 에서 누락된 글리프에 대한 대체입니다. `--font-mono` 시스템 고정폭 스택 `--ci-font-code` 에 매핑됩니다.
>
> `src/app/globals.css` `Switzer` 에 글리프가 없을 때 글리프당 대체 글꼴을 선택합니다. 키릴 문자, 그리스어 및 베트남어의 경우 `Inter`, `html[dir="rtl"]` 아래의 아랍어 스크립트의 경우 `Vazirmatn`.

`src/app/globals.css`:

```css
:root,
.ci-theme {
  --ci-font-ui:
    "Switzer", "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif;
  --ci-font-code: ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace;
  --font-mono: var(--ci-font-code);
```

## 1. 물건이 사는 곳

- **전부.** `packages/ui-kit/src` 는 `packages/ui-kit/UPSTREAM.md` 에 고정된 커밋에서 업스트림 `src/` 의 바이트 단위 복사본입니다(라이센스 인증도 기록함). `PATCHES.md` 로컬 패치를 나열합니다. 빌드 없이 소스로 사용됩니다. `next.config.mjs` 이를 트랜스파일하고 `tsconfig.json` `@omniroute/ui-kit` → `packages/ui-kit/src` 및 `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` 매핑합니다(`vitest.config.ts` 및 `vitest.mcp.config.ts` 동일한 별칭을 갖습니다). `@omniroute/ui-kit` 배럴을 통하지 않고 하위 경로(`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…)로 키트 구성 요소를 가져옵니다. 배럴은 모든 구성 요소(날짜 선택기 포함)를 각 가져오기 도구로 가져옵니다. 키트 스타일시트는 `src/app/globals.css` (`@import "../../packages/ui-kit/src/ci-styles.css"`, 전체 시트: 핵심 `ci-ui.css` 와 모든 패턴 계열)을 통해 들어갑니다.
- **토큰.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` 토큰을 선언합니다. `src/app/globals.css` 이를 레거시 OmniRoute 이름(`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`)에 연결하므로 기존 `var(--color-*)` 읽기 및 Tailwind 유틸리티는 계속 작동합니다. 새 코드는 Tailwind 유틸리티(`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…)를 사용하거나 키트 클래스 — 16진수 값을 사용하지 않습니다(`tests/unit/design-kit-bridge.test.ts` 브리지를 적용합니다). `text-primary` `--text-color-primary` 통해 `--color-primary-ink` 로 해석되므로 `bg-primary`/`border-primary` 악센트 표면을 유지하는 동안 기본 텍스트는 계속 읽을 수 있습니다. Editions 아래에서는 키트의 `--ci-color-accent-active` 입니다(밝은 경우 깊은 구리 `#99562f`, 어두운 경우 구리 악센트). Classic 아래에서, 밝은 곳에서는 lime-800, 어두운 곳에서는 라임 악센트가 있습니다. 차트 시리즈는 `--color-chart-1` … `--color-chart-8` 사용하며, 각각은 키트 시리즈 순서(`ciChartSeriesOrder`)에 할당된 텍스트 안전 `--color-chart-N-ink` 및 불투명 `--color-chart-N-subtle` 칩 색조를 갖습니다.
- **테마.** `<html className="ci-theme">` (`src/app/layout.tsx`)는 문서를 키트 테마로 선택합니다. 선호하는 방식은 `light`, `dark` 또는 `system` ( `src/shared/constants/appConfig.ts` 의 `THEME_CONFIG.defaultTheme = "system"`, `system` `prefers-color-scheme` 뒤에 옴)입니다. `src/store/themeStore.ts` 의 `applyTheme()` ( `THEME_BOOT_SCRIPT` 에 의해 미러링되고 `src/app/layout.tsx` 에 인라인되어 하이드레이션 전에 실행됨)는 `data-theme="dark"|"light"` 설정하고 `<html>` 의 `.dark` 클래스를 함께 토글합니다. 키트의 다크 토큰 세트는 `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`)에 맞춰져 있습니다. OmniRoute 자체의 다크 오버라이드( `globals.css` 의 `.dark` 블록) 및 `.dark` 클래스의 레거시 Tailwind `dark:` 유틸리티 키. 강조 색상 사전 설정은 없습니다. 강조 색상은 항상 키트에서 가져오고, 이전 빌드의 지속 사전 설정은 스토어가 로드될 때 삭제됩니다.
- **팔레트.** 두 번째는 둘 다 키트(`src/shared/constants/appearancePalette.ts`)의 것입니다: `editions`, 기본값 및 `classic`. Editions `ci-editions.css` ( `ci-ui.css` 에서 가져옴)가 `data-theme` 와 결합된 `<html>` 에 있는 키트의 `data-ci-appearance="editions"` 속성입니다. Classic 는 속성이 없습니다. 루트 레이아웃 서버는 속성을 렌더링하므로 아무것도 저장되지 않은(또는 JS 없는) 방문자는 모든 표면 — 대시보드, 로그인, `/status`, 오류 페이지, `/docs` 및 PWA 에서 Editions 얻습니다. 선택 사항은 동일한 `theme` 저장소(`palette`, `setPalette()`, `applyPalette()` in `src/store/themeStore.ts`)의 테마 옆에 유지되고 `THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`, 레이아웃의 `<head>` 에 인라인됨)에 의해 페인트되기 전에 적용됩니다. 이는 저장된 팔레트가 `"classic"` 일 때만 속성을 제거합니다. 루트 레이아웃 외부의 `src/app/global-error.tsx` 는 동일한 저장소에서 이를 적용합니다. `data-ci-appearance` 다른 요소에 배치하지 마십시오. 키트는 이를 `html:root:has([data-ci-appearance="editions"])` 와 일치시키므로 한 하위 요소가 전체 문서를 전환합니다. Editions `data-ci-editions-variant="landing"` 변형은 대시보드가 아닌 마케팅 페이지용입니다. 브라우저 크롬: 서버는 `viewport.themeColor` ( `prefers-color-scheme` 당 하나의 태그)에서 기본 Editions 렌더링하고 zqbp에 의해 `src/shared/constants/pwaThemeColors.ts` 에 고정 Editions `--ci-color-background` (`#f3f1e9` / `#11120f`)의 하나의 미러인 `tests/unit/pwa-theme-colors.test.ts` 에서 웹 매니페스트 — `ci-editions.css` `PWA_THEME_COLORS` 합니다. 그런 다음 라이브 `<meta name="theme-color">` 저장된 팔레트와 모드를 따릅니다. `THEME_BOOT_SCRIPT` 페인트 전에 태그를 다시 작성하고 테마 저장소의 작업은 모든 변경 시 이를 수행합니다( `src/shared/utils/themeColorMeta.ts` 의 `resolveThemeColor()` / `applyThemeColor()`, 키트의 `ciTokens` 에서 `CLASSIC_PAGE_BACKGROUND` 읽음). 명시적인 light/dark 테마는 모든 태그를 해당 모드로 설정합니다. `system` 구성표당 하나의 색상을 유지합니다. 매니페스트는 Editions 유지됩니다. 기본 설정 없이 설치당 한 번 가져옵니다. 모나코는 프로브(`monacoKitTheme.ts`)에서 색상을 읽습니다. Editions 에서 프로브 읽기는 하나의 동기 패스에 대해 루트 `data-theme` 뒤집습니다. 왜냐하면 키트가 루트에서 Editions light/dark 확인하기 때문입니다.
- **구성 요소(어댑터).** `src/shared/components/index.tsx` OmniRoute 구성요소 API (동일한 이름, 기본 내보내기 및 소품)를 유지하며 그 뒤에 있는 기본 요소는 키트에 대한 어댑터입니다: 양식(`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), 오버레이 및 피드백(`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`), 구조(`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) 및 테이블(`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). 어댑터는 `Button variant="primary"` 경로로 키트 `--ci-color-accent-foreground` 요소 `--ci-button-primary-*` `danger` `destructive` `default` props를 — 에 `warning` `warning`. `Badge` 상태 변형은 키트 톤이고, `<option>` 하위 항목이 있는 `Select` 은 키트 `NativeSelect` 렌더링합니다. `tests/unit/ui/adapters/*.test.tsx` 핀 각 어댑터.
- **껍데기.** `src/app/(dashboard)/layout.tsx` `src/shared/components/layouts/DashboardShell.tsx` 렌더링하는 `DashboardLayout` 렌더링합니다. `src/shared/components/Sidebar.tsx` 에 OmniRoute 의 탐색 로직이 포함된 키트 `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`). `#main-content` 에 대한 "콘텐츠로 건너뛰기" 링크는 포커스 가능한 첫 번째 요소입니다. `src/shared/components/Header.tsx` 키트 `SidebarTrigger` (셸의 유일한 사이드바 토글), Keak `ProductSwitcher` 및 명령 팔레트 오프너가 포함되어 있습니다. `#main-content` 내부에 키트 `PageHeader` (`.ci-page-header`)이 마운트되어 있지 않은 동안에만 경로 제목을 표시하므로 자체 `PageHeader` 있는 페이지에는 단일 `h1` 있습니다. `src/shared/components/CommandPalette.tsx` `Dialog` 키트입니다.
- **아이콘.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`)는 `ICON_MAP` (`src/shared/constants/iconMap.ts`)를 통해 이름(화면에서 사용하는 머티리얼 기호 어휘)을 Lucide 문자로 해석합니다. Material Symbols 글꼴 및 패키지가 사라졌습니다. 맵에서 이름이 누락되어 중립 자리 표시자 문자 모양(`data-icon-missing="true"`)이 렌더링되고 프로덕션 외부에 콘솔 경고가 기록됩니다. `npm run gen:icon-map` 지도에서 누락된 사용 중인 이름을 인쇄합니다(`tests/unit/icon-map-coverage.test.ts` Lucide 아이콘이 없는 모든 이름에서는 실패합니다. `tests/unit/icon-map-object-values.test.ts` 조회 개체에 저장된 이름을 다룹니다). `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` 리터럴 `<span className="material-symbols-outlined">` 범위를 `<Icon>` 으로 다시 작성합니다.
- **상표.** `src/shared/components/OmniRouteLogo.tsx` 키트를 래핑합니다. 기본 내보내기 `OmniRouteLogo` `ProductIcon product="omniroute" variant="glyph"` (인라인 SVG, `basePath` -safe)를 렌더링하고 `OmniRouteLockup` `ProductLockup product="omniroute"` (액세스 가능한 이름 "Keak OmniRoute")를 렌더링하거나 화이트 라벨 연산자의 경우 자체 `name`/`logoSrc` 렌더링합니다. 제품 전환 대상은 `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`)에 있습니다. 독립형 화면 — `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` 및 `src/shared/components/ErrorPageScaffold.tsx` — 잠금을 보여줍니다. `tests/unit/brand-pages-static.test.ts` 그것을 보호합니다.

## 2. 규칙

1. 토큰은 리터럴이 아닙니다. 의도적으로 유지되는 예외: 항상 어두운 콘솔 터미널과 문자 그대로의 16진수가 필요한 호출자를 위한 키트 상태 팔레트의 확인된 16진수 미러 `STATUS_HEX` (`src/shared/constants/statusColors.ts`). 범주형 팔레트는 더 이상 예외가 아닙니다. 키트의 8개 차트 토큰(`--color-chart-1..8` 및 `-ink`/`-subtle`)을 키트 시리즈 순서로 `src/shared/utils/categoricalPalette.ts` 통해, 라우팅 전략의 경우 `src/app/(dashboard)/dashboard/combos/strategyPalette.ts` 통해 사용합니다. ReactFlow 가장자리와 오케스트레이션 캔버스는 테마 인식 `--orch-status-*` 변수(`src/shared/components/flow/edgeStyles.ts`)를 읽습니다.
2. `packages/ui-kit/src` 직접 패치하지 마세요. `scripts/dev/sync-ui-kit.sh <commit>` 와 동기화하세요. 사전 커밋 게이트 `npm run check:ui-kit-snapshot` (`.husky/pre-commit`)는 고정된 업스트림 커밋과 다른 바이트에서 실패합니다(업스트림 클론 `UI_KIT_CLONE` 또는 `_references/cheaper-inference-ui-kit` 없으면 경고와 함께 건너뜁니다). 키트에 부족한 부분이 있으면 어댑터나 화면에서 문제를 해결하고 업스트림에 요청하세요.
3. 키트 텍스트 기본값은 영어(`label = "Loading"`, `loadingLabel = "Loading table"`…)입니다. — 키트 구성 요소가 텍스트를 렌더링할 때마다 `useTranslations(...)` 에서 번역된 문자열을 전달합니다.
4. Tailwind 유틸리티는 키트 구성 요소 클래스를 압도합니다(키트는 `@layer theme, base, components, utilities` 선언하고 해당 규칙은 `components` 에 있음). — 키트 구성 요소의 색상을 다시 지정하는 것이 아니라 간격 및 레이아웃을 위해 유틸리티를 사용합니다.
5. 제목: 페이지 및 섹션 제목의 경우 `.ci-heading` ; 오류 페이지 상태 코드와 같은 크고 희박한 표시 텍스트에만 `.ci-dashboard-display` 사용합니다. 둘 다 Switzer를 사용합니다.
6. `tests/unit/dashboard-kit-sweep.test.ts` 키트 채택을 보호합니다. `src/app` 또는 `src/shared/components` 아래에 자료 합자 범위가 없습니다. 대시보드 트리(`src/app/(dashboard)` 및 `src/shared/components`)에는 원시 `<select>`, `<textarea>` 또는 `<table>` 없고 나열된 예외( `Select` 어댑터의 기본 분기, `RequestLoggerDetail`) 외부에 직접 롤링된 `role="dialog"` 없습니다. 모든 원시 `<button>` 또는 `<input>` 에는 최대 3줄 위로 끝나는 `kit-exception:` (이유 포함)을 포함하는 주석이 필요합니다. 팔레트 색상과 `dark:` 변형은 테스트 목록에 있는 파일에만 있습니다.
7. PR (스크린샷) 전에 테마와 390px 뷰포트를 모두 확인하세요. `tests/e2e/a11y.spec.ts` 도끼를 실행합니다.

## 5. kit 업데이트

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` 에 고정된 버전을 업스트림 저장소의 최신 `v*` 태그와 비교하고 릴리스가 출시되면 sync 명령을 인쇄합니다.

일일 `UI Kit upstream watch` 작업 흐름(`.github/workflows/ui-kit-upstream-watch.yml`)은 동일한 검사를 실행합니다. 핀이 뒤에 있는 동안 `scripts/ci/ui-kit-sync-pr.sh` 롤링 분기 `chore/ui-kit-sync-latest` 에서 가장 높은 `release/vX.Y.Z` 분기에 대해 하나의 동기화 PR 열린 상태로 유지합니다. 병합되지 않습니다. 모든 키트 릴리스에는 여전히 로컬 VPS 에 대한 시각적 확인이 필요합니다. 최신 릴리스가 출시되면 브랜치가 다시 빌드되고 그렇지 않으면 그대로 유지됩니다. 수동으로 푸시된 커밋이 포함된 공개 PR 덮어쓰여지지 않으며, 관리자가 병합하지 않고 닫은 버전의 PR 최신 릴리스가 나올 때까지 닫힌 상태로 유지됩니다.

PR 열 수 없는 경우(대상 릴리스가 고정되었거나, PR 수동으로 푸시된 커밋이 있거나, PR 가 닫혔거나, PR 토큰이 설정되지 않은 경우) 워크플로는 이유를 설명하는 하나의 추적 문제를 열린 상태로 유지합니다.

워크플로에서는 두 가지 비밀을 사용합니다.

- `secrets.UI_KIT_READ_TOKEN`: 개인 업스트림 저장소에 대한 읽기 전용 토큰입니다. 업스트림 검사에서 데이터를 읽을 수 없는 경우(토큰 없음, 작동이 중지된 토큰 또는 GitHub 에 연결할 수 없음) `unknown` 보고하고 코드 `0` 와 함께 종료됩니다. 워크플로는 경고를 작성하고 별도의 추적 문제 하나를 열어두려고 합니다. 나중에 성공적으로 실행되면 액세스가 반환된 후 닫힙니다. GitHub 문제 API 실패하면 작업이 실패합니다.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: 콘텐츠 및 풀 요청 쓰기 액세스 권한이 있는 이 저장소의 세분화된 토큰입니다. 이 워크플로는 전용 토큰이 구성된 경우에만 동기화 PRs 열거나 업데이트합니다. 이것이 없으면 워크플로는 분기를 푸시하고 PR 열리지 않았다고 보고합니다.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` 해당 커밋(`latest` = 최신 `v*` 태그)에서 업스트림 `src/` `packages/ui-kit/src` 로 복사하고, 허용되는 단일 변환을 적용하고(상대 가져오기에서 `.js` 접미사를 삭제함), `packages/ui-kit/package.json` 및 `package-lock.json` 의 작업 공간 버전을 업스트림 버전으로 설정합니다. 그런 다음 `git diff packages/ui-kit` 검토하고, 두 테마 모두에서 공급자, 설정, 콤보, 사용법 및 끝점에 대한 화면을 확인하고, `npm run check:ui-kit-snapshot` 및 `npm run test:vitest:ui` 실행하고, 업스트림 변경 로그가 있는 PR 엽니다.

## 6. README 다이어그램

루트 `README.md`에 포함된 열두 다이어그램(`docs/diagrams/*.svg`)은 키트를 정적 이미지에 적용한 것입니다. 손으로 그리지 않고 생성합니다. `scripts/docs/gen-readme-*.mjs`에 13개 생성기 파일(열두 다이어그램과 드라이버 `gen-readme-diagrams.mjs`), `tests/unit/docs/readme-*-svg.test.ts`에 다이어그램당 하나씩 12개 최신성 테스트가 있으며, 각 테스트는 커밋된 파일과 생성기 출력을 바이트 단위로 비교합니다(작업 `test-unit`).

- **토큰.** `scripts/docs/readme-diagram-theme.mjs` `packages/ui-kit/src/ci-editions.css` 에서 Editions 팔레트(기본 모양)를 복사합니다( `tests/unit/docs/readme-diagram-theme.test.ts` 에 의해 해당 파일에 고정되어 두 구성표의 모든 표면에 있는 모든 텍스트 색상에 대해 WCAG AA 도 확인합니다. 한 가지 예외인 light `warn` 는 키트 값이 캔버스에서 4.46:1이기 때문에 10% 어둡게 표시되는 키트 경고입니다). 그리고 키트 유형 척도(`ci-tokens.css`)에서 텍스트 역할을 정의합니다. (400/500/600, 500에 표시) 및 IBM Plex Mono이고 명령, URLs, 식별자 및 터미널 화면에만 사용되는 코드 역할(`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`)을 제외한 모든 항목을 추적합니다. 파일 내에서 밝은 값은 `:root` 에 있고 어두운 값은 `prefers-color-scheme: dark` 뒤에 있으므로 각 이미지는 GitHub 에 있는 뷰어의 구성표를 따릅니다.
- **글꼴.** GitHub Markdown은 CSS 전달하지 않으며 camo 프록시는 모든 외부 가져오기를 차단하므로 키트 유형은 파일 내부로 이동해야 합니다. 모든 생성기의 마지막 단계인 `scripts/docs/readme-outline.mjs` HarfBuzz 사용하여 Switzer 역할을 형성하고 이를 벡터 윤곽선(`<defs>` 경로 및 `<use>`)으로 그립니다. Switzer에 부족한 화살표와 기하학적 기호는 자체 메트릭에 그려집니다. 개요, 포함된 글꼴 없음: Switzer 라이센스(`packages/ui-kit/src/fonts/FFL.txt`)는 서면 동의 없이 하위 집합 및 형식 변환을 금지하고 벡터 드로잉을 허용하므로 Switzer `@font-face` 또는 `data:` URI 를 다시 도입하지 마십시오. 파일에 남아 있는 글꼴 중 하나는 해당 문자로 구성된 실제 코드 텍스트(`scripts/docs/readme-fonts.mjs`)를 유지하는 OFL IBM Plex Mono 하위 집합입니다. 포함할 수 없는 모든 글리프는 던집니다.
- **재생성.** `npm run docs:readme-diagrams` 12개 모두를 README 순서로 다시 작성하고 해당 크기와 함께 파일당 한 줄씩 인쇄합니다. 단일 생성기도 자체적으로 실행됩니다(`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` 에는 해당 수치가 `open-sse/config/freeModelCatalog.ts` 의 라이브 카탈로그 로더에서 나오므로 `node --import tsx/esm` 필요합니다. 카탈로그 변경의 CI 결과는 `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict` 에 있습니다). 생성기와 SVG 함께 커밋합니다.
- **증거.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>`는 로컬 프로브에서 파일을 렌더링하고(`<img>` 태그, 제한적인 `Content-Security-Policy`, `image/svg+xml` 응답), 밝은 프레임과 어두운 프레임을 캡처하며 페이지의 외부 글꼴 요청을 보고합니다. 요청 수는 0이어야 합니다.

- **예산.** 파일당 200 KB 미만(각 비활성 테스트에서 이를 확인함) 500 KB 는 모든 README 이미지의 하드 캡입니다( SVG 스튜디오 유효성 검사기 규칙).
- **공유 문구, 수치는 gate에서.** 각 생성기는 그려진 텍스트이자 개요 단계의 입력인 `*_COPY` 상수로 다이어그램의 복사본을 전달합니다(또는 라이브 카탈로그에서 빌드합니다). 정식 수치는 `<text>` 노드(한 번 설명하면 보이지 않음, `fill-opacity:0`)에 유지되며 `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`)가 읽습니다. 게이트가 읽는 다이어그램의 부실 테스트도 생성된 파일에 대해 유효성 검사기를 실행하므로 코드에서 표류하는 그림은 테스트에 실패합니다. — 게이트가 읽는 소스를 수정하며 생성기의 숫자는 수정하지 않습니다.
