> **상태:** 대시보드는** Keak CI UI 키트** (`@keak/cheaper-inference-ui-kit`), 작업 공간 `packages/ui-kit` (`@omniroute/ui-kit`; 업스트림 스냅샷은 `packages/ui-kit/UPSTREAM.md` 에 고정되고 `npm run check:ui-kit-snapshot` 에 의해 보호됨)로 판매됩니다. 빛은 표준적인 주제입니다. 기본 설정은 `system` 입니다. 악센트는 Keak 라임(`--ci-color-accent`)입니다. Switzer는 UI, 디스플레이 및 코드 텍스트(`--ci-font-ui`, `--ci-font-display` 및 `--ci-font-mono` 이를 해결함)에 대한 단일 제품군이며 키트 자체(`packages/ui-kit/src/ci-fonts.css`, `ci-tokens.css` 에서 가져옴)에 의해 자체 호스팅됩니다. 모든 아이콘은 Lucide 문자 모양입니다.

## 1. 각 요소의 위치

- **키트.** `packages/ui-kit/src`는 `packages/ui-kit/UPSTREAM.md`에 고정된 커밋 시점의 업스트림 `src/`를 바이트 단위로 그대로 복사한 것입니다(해당 파일에는 라이선스 승인 내용도 기록되어 있습니다). `PATCHES.md`에는 로컬 패치가 나열되어 있습니다(현재 없음). 빌드 없이 소스 그대로 사용됩니다: `next.config.mjs`가 이를 트랜스파일하고, `tsconfig.json`은 `@omniroute/ui-kit` → `packages/ui-kit/src`, `@omniroute/ui-kit/*` → `packages/ui-kit/src/*`로 매핑합니다(`vitest.config.ts`와 `vitest.mcp.config.ts`도 동일한 별칭을 사용합니다). 키트 컴포넌트는 서브패스(`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…)로 임포트하고, `@omniroute/ui-kit` 배럴(barrel)을 통해서는 절대 임포트하지 마세요. 배럴은 모든 컴포넌트(데이트 피커 포함)를 각 임포터로 끌어들입니다. 키트 스타일시트는 `src/app/globals.css`를 통해 로드됩니다(`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **토큰.** `packages/ui-kit/src/ci-tokens.css`가 `--ci-*` 토큰을 선언하고, `src/app/globals.css`가 이를 레거시 OmniRoute 이름(`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`)으로 브리지하므로, 기존 `var(--color-*)` 참조와 Tailwind 유틸리티가 계속 동작합니다. 새 코드는 Tailwind 유틸리티(`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…)나 키트 클래스를 사용하며, 16진수 값은 절대 사용하지 않습니다(`tests/unit/design-kit-bridge.test.ts`가 이 브리지를 강제합니다). `text-primary`는 `--text-color-primary`를 통해 `--color-primary-ink`로 해석되므로(라이트에서는 lime-800, 다크에서는 라임 액센트) `bg-primary`/`border-primary`가 라임 서피스를 유지하는 동안에도 primary 텍스트의 가독성이 보장됩니다. 차트 시리즈는 `--color-chart-1` … `--color-chart-5`를 사용합니다.
- **테마.** `<html className="ci-theme">`(`src/app/layout.tsx`)가 문서를 키트 테마에 옵트인합니다. 설정값은 `light`, `dark` 또는 `system`입니다(`src/shared/constants/appConfig.ts`의 `THEME_CONFIG.defaultTheme = "system"`; `system`은 `prefers-color-scheme`을 따릅니다). `src/store/themeStore.ts`의 `applyTheme()`(하이드레이션 전에 실행되는 `src/app/layout.tsx`의 인라인 부트스트랩 스크립트에 미러링됨)는 `data-theme="dark"|"light"`를 설정하고 `<html>`의 `.dark` 클래스를 함께 토글합니다. 키트의 다크 토큰 세트는 `data-theme="dark"`를 기준으로 하고(`packages/ui-kit/src/ci-tokens.css`), OmniRoute 자체의 다크 오버라이드(`globals.css`의 `.dark` 블록)와 레거시 Tailwind `dark:` 유틸리티는 `.dark` 클래스를 기준으로 합니다. 액센트 색상 프리셋은 없습니다: 액센트는 항상 키트에서 가져오며, 이전 빌드에서 저장된 프리셋은 스토어 로드 시 폐기됩니다.
- **컴포넌트(어댑터).** `src/shared/components/index.tsx`는 OmniRoute 컴포넌트 API(동일한 이름, 기본 내보내기, props)를 유지하며, 그 이면의 프리미티브는 키트 위에 구축된 어댑터입니다: 폼(`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), 오버레이 및 피드백(`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`), 구조(`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`), 테이블(`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). 어댑터는 키트 컴포넌트를 서브패스로 임포트하고 레거시 props를 그에 매핑합니다. 예를 들어 `Button variant="primary"`는 키트의 `default` 버튼(`--ci-button-primary-*`: 라이트에서는 반전 서피스, 다크에서는 `--ci-color-accent-foreground` 잉크가 적용된 액센트)이고, `danger`는 `destructive`, `warning`은 `outline`에 `.ci-button--warning` 확장을 더한 것입니다. `globals.css` 끝부분(`@layer components`)의 `.ci-button--warning` 및 `.ci-badge[data-tone]` 규칙은 키트 클래스 위에 추가된 OmniRoute 확장입니다. `tests/unit/ui/adapters/*.test.tsx`가 각 어댑터를 고정합니다.
- **셸.** `src/app/(dashboard)/layout.tsx`는 `DashboardLayout`을 렌더링하고, 이는 다시 `src/shared/components/layouts/DashboardShell.tsx`를 렌더링합니다: 키트의 `SidebarProvider` / `Sidebar` / `SidebarInset`(`packages/ui-kit/src/sidebar.tsx`)이며, OmniRoute의 내비게이션 로직은 `src/shared/components/Sidebar.tsx`에 있습니다. `#main-content`로 연결되는 "본문으로 건너뛰기" 링크가 첫 번째 포커스 가능 요소입니다. `src/shared/components/Header.tsx`는 키트의 `SidebarTrigger`(셸의 유일한 사이드바 토글), Keak `ProductSwitcher`, 명령 팔레트 오프너를 포함합니다. 라우트 제목은 `#main-content` 내부에 키트 `PageHeader`(`.ci-page-header`)가 마운트되어 있지 않을 때만 표시되므로, 자체 `PageHeader`를 사용하는 페이지에는 `h1`이 하나만 존재합니다. `src/shared/components/CommandPalette.tsx`는 키트 `Dialog`입니다.
- **아이콘.** `<Icon name="material_name">`(`src/shared/components/Icon.tsx`)은 `ICON_MAP`(`src/shared/constants/iconMap.ts`)을 통해 이름(화면에서 사용하는 Material Symbols 어휘)을 Lucide 글리프로 해석합니다. Material Symbols 폰트와 패키지는 제거되었습니다: 맵에 없는 이름은 중립적인 플레이스홀더 글리프(`data-icon-missing="true"`)를 렌더링하고, 프로덕션 이외 환경에서는 콘솔 경고를 기록합니다. `npm run gen:icon-map`은 사용 중이지만 맵에 누락된 이름을 출력합니다(`tests/unit/icon-map-coverage.test.ts`는 Lucide 아이콘이 없는 이름이 하나라도 있으면 실패하고, `tests/unit/icon-map-object-values.test.ts`는 룩업 객체에 저장된 이름을 검사합니다). `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]`는 리터럴 `<span className="material-symbols-outlined">` 스팬을 `<Icon>`으로 재작성합니다.
- **브랜드.** `src/shared/components/OmniRouteLogo.tsx`는 키트를 래핑합니다: 기본 내보내기 `OmniRouteLogo`는 `ProductIcon product="omniroute" variant="glyph"`(인라인 SVG, `basePath` 안전)를 렌더링하고, `OmniRouteLockup`은 `ProductLockup product="omniroute"`(접근 가능한 이름 "Keak OmniRoute") 또는 화이트라벨 운영자의 경우 자체 `name`/`logoSrc`를 렌더링합니다. 제품 전환기의 대상은 `src/shared/constants/keakProducts.ts`(`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`)에 정의되어 있습니다. 독립 실행형 화면 — `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx`, `src/shared/components/ErrorPageScaffold.tsx` — 은 락업을 표시하며, `tests/unit/brand-pages-static.test.ts`가 이를 보장합니다.

## 2. 규칙

1. 토큰은 리터럴이 아닙니다. 의도적으로 유지되는 예외: 항상 어두운 콘솔 터미널과 문자 그대로의 16진수가 필요한 호출자를 위한 키트 상태 팔레트의 확인된 16진수 미러 `STATUS_HEX` (`src/shared/constants/statusColors.ts`). 범주형 팔레트는 더 이상 예외가 아닙니다. 이는 키트의 5개 차트 토큰(`--color-chart-1..5`)을 통해 `src/shared/utils/categoricalPalette.ts` 및 라우팅 전략의 경우 `src/app/(dashboard)/dashboard/combos/strategyPalette.ts` 사용합니다. ReactFlow edge 및 오케스트레이션 캔버스는 테마 인식 `--orch-status-*` 변수(`src/shared/components/flow/edgeStyles.ts`)를 읽습니다.
2. `packages/ui-kit/src` 직접 패치하지 마세요. `scripts/dev/sync-ui-kit.sh <commit>` 와 동기화하세요. 사전 커밋 게이트 `npm run check:ui-kit-snapshot` (`.husky/pre-commit`)는 고정된 업스트림 커밋과 다른 바이트에서 실패합니다(업스트림 클론 `UI_KIT_CLONE` 또는 `_references/cheaper-inference-ui-kit` 없으면 경고와 함께 건너뜁니다). 키트에 부족한 부분이 있으면 어댑터나 화면에서 문제를 해결하고 업스트림에 요청하세요.
3. 키트 텍스트 기본값은 영어(`label = "Loading"`, `loadingLabel = "Loading table"`…)입니다. 키트 구성 요소가 텍스트를 렌더링할 때마다 `useTranslations(...)` 에서 번역된 문자열을 전달합니다.
4. Tailwind 유틸리티는 키트 구성 요소 클래스를 압도합니다(키트는 `@layer theme, base, components, utilities` 및 해당 규칙을 `components` 에 선언함). 키트 구성 요소의 색상을 다시 지정하는 것이 아니라 간격 및 레이아웃을 위해 유틸리티를 사용합니다.
5. 제목: 페이지 및 섹션 제목의 경우 `.ci-heading` ; 오류 페이지 상태 코드와 같은 크고 희박한 표시 텍스트에만 `.ci-dashboard-display` 사용합니다. 둘 다 Switzer를 사용합니다.
6. `tests/unit/dashboard-kit-sweep.test.ts` 키트 채택을 보호합니다. `src/app` 또는 `src/shared/components` 아래에 자료 합자 범위가 없습니다. 대시보드 트리(`src/app/(dashboard)` 및 `src/shared/components`)에는 원시 `<select>`, `<textarea>` 또는 `<table>` 없고 나열된 예외( `Select` 어댑터의 기본 분기, `RequestLoggerDetail`) 외부에 직접 롤링된 `role="dialog"` 없습니다. 모든 원시 `<button>` 또는 `<input>` 에는 최대 3줄 위로 끝나는 `kit-exception:` (이유 포함)을 포함하는 주석이 필요합니다. 팔레트 색상과 `dark:` 변형은 테스트 목록에 있는 파일에만 있습니다.
7. PR (스크린샷) 전에 테마와 390px 뷰포트를 모두 확인하세요. `tests/e2e/a11y.spec.ts` 도끼를 실행합니다.

## 3. 화면 추가하기

1. kit `PageHeader`(`@omniroute/ui-kit/page-header`, 대시보드 내부에서는 `compact`)로 페이지를
   시작합니다 — title, description, `actions`를 지정합니다. 그러면 셸 헤더는 자체 제목을 생략합니다.
2. `@/shared/components`(어댑터)로 컨트롤을 구성하고, 어댑터가 없는 경우 서브패스로 kit 컴포넌트를
   사용합니다(`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`,
   `Slider`…).
3. 아이콘: `<Icon name="…" />`. 새 이름은 의미상 일치하는 Lucide 컴포넌트와 함께 `ICON_MAP`에
   추가합니다. `npm run gen:icon-map`이 아직 누락된 이름을 나열합니다.
4. 색상: 시맨틱 유틸리티(`text-success`, `bg-warning-bg`, `border-border`…)와 차트 시리즈용
   `var(--color-chart-N)`을 사용합니다. hex 값이나 색상을 그대로 반복하기만 하는 `dark:` 변형은
   사용하지 않습니다.
5. 텍스트: kit 컴포넌트에 전달하는 라벨을 포함한 모든 문자열은 `useTranslations`에서 가져옵니다.
   새 키는 `src/i18n/messages/en.json`, `pt-BR.json`, `vi.json`에 추가합니다(베트남어 패리티 테스트가

## 4. 어댑터 추가 또는 변경

1. `src/shared/components/index.tsx`의 공개 API를 유지합니다: 동일한 export 이름, default export 및
   허용되는 props. 어댑터 내부에서 레거시 props를 kit에 매핑합니다 (`Button.tsx` 참조: `VARIANT_TO_KIT`,
   `SIZE_TO_KIT`).
2. kit은 서브패스로 import합니다 (`@omniroute/ui-kit/<component>`).
3. kit의 부족한 부분에 대한 해결책은 어댑터에 둡니다 (수정 사항이 스타일인 경우 `globals.css`의
   `@layer components`에). 절대 `packages/ui-kit/src`에 두지 않습니다.
4. `tests/unit/ui/adapters/<name>.test.tsx`를 추가하거나 업데이트합니다. 호출자가 많은 어댑터의 경우,
   변경 전후의 렌더링된 마크업을 비교하세요 — 패딩이나 래퍼 변경이 모든 화면으로 퍼져나갑니다.

## 5. 키트 업데이트

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` 에 고정된 버전을 업스트림 저장소의 최신 `v*` 태그와 비교하고 릴리스가 출시되면 sync 명령을 인쇄합니다. 주간 `UI Kit upstream watch` 작업 흐름(`.github/workflows/ui-kit-upstream-watch.yml`)은 동일한 검사를 실행하고 핀이 뒤에 있는 동안 하나의 추적 문제를 열어 둡니다. 업스트림 저장소는 비공개이므로 워크플로는 `UI_KIT_READ_TOKEN` 비밀에 읽기 전용 토큰이 필요하며 토큰 없이는 비활성 상태를 유지합니다.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` 해당 커밋(최신 `v*` 태그 `latest` = )에서 업스트림 `src/` `packages/ui-kit/src` 로 복사하고, 허용되는 단일 변환을 적용하고(상대 가져오기에서 `.js` 접미사를 삭제함), `packages/ui-kit/package.json` 및 `package-lock.json` 의 작업 공간 버전을 업스트림 버전으로 설정합니다. 그런 다음 `git diff packages/ui-kit` 검토하고, 두 테마 모두에서 공급자, 설정, 콤보, 사용법 및 끝점에 대한 시각적 전달을 수행하고, `npm run check:ui-kit-snapshot` 및 `npm run test:vitest:ui` 실행하고, 업스트림 변경 로그가 있는 PR 엽니다.

## 6. README 다이어그램

루트 `README.md` 가 포함하는 12개의 다이어그램(`docs/diagrams/*.svg`)은 정적 이미지에 적용되는 키트이며 손으로 그리는 것이 아니라 생성됩니다. `scripts/docs/gen-readme-*.mjs` 의 13개 생성기 파일(12개 다이어그램과 `gen-readme-diagrams.mjs` 드라이버) 및 `tests/unit/docs/readme-*-svg.test.ts` 의 12개 비활성 테스트(다이어그램당 하나씩), 각 바이트는 커밋된 파일을 생성기의 출력(작업 `test-unit`)과 비교합니다.

- **토큰.** `scripts/docs/readme-diagram-theme.mjs` `packages/ui-kit/src/ci-tokens.css` 에서 팔레트를 복사하고( `tests/unit/docs/readme-diagram-theme.test.ts` 에 의해 해당 파일에 고정됨) `@fontsource` 패키지에서 키트의 이전 표면(디스플레이용 Instrument Serif, UI 텍스트용 Inter, 그림 및 코드용 IBM Plex Mono)에 대한 텍스트 역할을 정의합니다(대시보드 자체는 키트 0.0.66부터 키트의 Switzer를 사용합니다). 파일 내에서 밝은 값은 `:root` 에 있고 어두운 값은 `prefers-color-scheme: dark` 뒤에 있으므로 각 이미지는 GitHub 에서 보는 사람의 구성표를 따릅니다.
- **글꼴.** `scripts/docs/readme-fonts.mjs` 해당 woff2 파일을 각 다이어그램이 그리는 문자 모양으로 하위 집합하고 이를 `@font-face` `data:` URIs 로 포함합니다. 이는 키트 타이포그래피가 README 이미지에 도달하는 유일한 방법입니다. GitHub Markdown은 CSS 전달하지 않고 camo 프록시는 모든 외부 가져오기를 차단하기 때문입니다. 하위 집합은 라틴어로만 구성됩니다. 시스템 스택으로 돌아가는 기호 글리프는 `SYMBOL_FALLBACKS` 에서 하나씩 허용되며, 다른 발견되지 않은 글리프는 발생합니다.
- **재생성.** `npm run docs:readme-diagrams` 12개 모두를 README 순서로 다시 작성하고 해당 크기와 함께 파일당 한 줄씩 인쇄합니다. 단일 생성기도 자체적으로 실행됩니다(`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` 에는 해당 수치가 `open-sse/config/freeModelCatalog.ts` 의 라이브 카탈로그 로더에서 나오므로 `node --import tsx/esm` 필요합니다. 카탈로그 변경의 CI 결과는 `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict` 에 있습니다). 생성기와 SVG 함께 커밋합니다.
- **증거.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` GitHub 제공하는 방식( `<img>` 태그, camo의 `Content-Security-Policy`, `image/svg+xml`)으로 파일을 렌더링하고, 밝은 프레임과 어두운 프레임을 캡처하고, 페이지에서 요청한 외부 글꼴을 보고합니다(0이어야 함).
- **예산.** 파일당 200 KB 미만(각 비활성 테스트에서 이를 확인함) 500 KB 는 모든 README 이미지의 하드 캡입니다( SVG 스튜디오 유효성 검사기 규칙).
- **변경 없이 복사하고 게이트부터 계산합니다.** 브랜드 변경은 단어가 아닌 유형과 팔레트를 변경했습니다. 각 생성기는 그려진 텍스트와 글꼴 하위 집합 입력인 `*_COPY` 상수로 다이어그램의 복사본을 전달합니다(또는 라이브 카탈로그에서 빌드합니다). 표준 수치는 `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`)가 읽는 `<text>` 노드에 유지됩니다. 게이트가 읽는 다이어그램의 부실 테스트도 생성된 파일에 대해 유효성 검사기를 실행하므로 코드에서 표류하는 그림은 테스트에 실패합니다. 게이트가 읽는 소스를 수정하고 생성기의 숫자는 수정하지 마세요.
