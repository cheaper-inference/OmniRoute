`devin-cli-agentic`를 사용하면 실제 Claude Code 런타임이 OmniRoute의 로컬 Anthropic
Messages 엔드포인트를 사용하는 동시에 공식 Devin CLI가 ACP stdio를 통해 모델 응답을
제공할 수 있습니다. 기존 Anthropic, Claude OAuth, Claude Web 또는 `devin-cli` 공급자는
변경하지 않습니다.

클라이언트 소유 도구 호출의 경우, Claude 형식의 도구 지원 공급자인
`devin-cli-agentic`(별칭 `dva`)을 통해 라우팅하십시오. 기존 `devin-cli`(`dv`) ACP
실행기는 텍스트 전용입니다. 이 실행기는 Devin의 도구 미지원 요약기를 실행하며 도구 호출을
반환할 수 없습니다. 도구가 필요한 콤보 라우팅에서 이를 피하도록 모델 메타데이터도 이에
맞게 표시되어 있습니다.

> **현재 상태: Claude Code `2.1.258`에 고정됨. 오프라인 및 라이브 검증이 마지막으로
> 기록된 버전은 `2.1.220`입니다.** `2.1.220` 고정 버전은 Devin CLI
> `3000.2.17` 및 모델 `swe-1-7-lightning`을 통해 격리된 세 가지 시나리오를
> 완료했습니다. 해당 최종 라이브 실행에서는 클라이언트 소유 `Read`, `Edit`, `Bash`
> 턴, 성공적인 `npm test` 결과, 프로젝트 명령 및 스킬 검색, Devin 전용 라우팅,
> 그리고 Claude 외부 송신 0건이 입증되었습니다. 이후 고정 버전은 `2.1.258`로
> 상향되었습니다. 이 버전은 OmniRoute의 Claude ID가 가장하는 CLI 세대이며 Fable 5.1
> 티어를 기본으로 제공하는 최초의 릴리스 라인입니다. 새 고정 버전에서는 고정된 기본
> 이미지에서 설치 계층과 `claude --version`이 검증되었으며, 브리지 단위 테스트 모음,
> `compose config`, 정적 격리 증명이 모두 통과했습니다. 하지만 오프라인 모의 시나리오와
> 라이브 세 가지 시나리오 테스트 모음은 아직 다시 실행되지 않았습니다. 이 고정 버전으로
> 브리지를 사용하기 전에 해당 테스트를 다시 실행하십시오("고정된 도구 업데이트" 참조).

## 아키텍처

```text
Claude Code 2.1.258 (격리된 비루트 Linux 컨테이너)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude 형식, 인증 불필요 공급자)
  -> devin acp --agent-type summarizer (공식 ACP stdio, Devin 도구 없음)
  -> 전용 devin-auth 볼륨의 Devin 계정
```

공식 CLI의 기본 ACP 에이전트는 자체 도구를 실행할 수 있으므로 이 브리지는 이를 사용하지
않습니다. 대신 도구가 없는 공식 CLI 모드인 고정 `summarizer` ACP 에이전트를 시작하고,
직렬화된 Anthropic 요청을 실행 추적으로 프레이밍합니다. Claude 소유의 다른 작업이 필요한
경우 응답에는 클라이언트 도구 봉투가 정확히 하나 포함되어야 합니다. 응답을 성공으로
보고하기 전에 모든 ACP `tool_call` 또는 `tool_call_update`가 거부됩니다.

`open-sse/executors/devin-agentic/serializer.ts`의 직렬 변환기는 `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`,
그리고 Claude Code가 제공한 도구를 보존합니다. 이미지와 알 수 없는 블록은 명시적으로
실패 처리됩니다. 큰 도구 결과에는 눈에 보이는 잘림 마커가 사용됩니다.

파서는 모델 턴당 독립된 `<tool>{...}</tool>` 봉투 하나를 허용합니다. 요청의 도구 목록과
이름을 대조하고, 해당 도구의 JSON 스키마에 따라 인수를 검증하며, 설명과 작업이 혼합된
응답을 거부하고, 제한된 한 번의 복구 시도를 허용합니다. 그런 다음 Claude Code는 생성된
Anthropic `tool_use`를 로컬에서 실행하고 `tool_result`를 OmniRoute를 통해 다시
전송합니다.

## 자동 라우팅

차단되지 않은 경우 이 공급자는 OmniRoute의 `auto/*` 후보 풀에 포함될 수 있습니다.
후보 자격이 선택을 보장하지는 않습니다. 콤보의 라우팅 전략(예: 마지막으로 정상 작동한
공급자)이 다른 공급자를 우선할 수 있습니다. 모든 요청을 Devin을 통해 보내야 한다면
`dva/<model>` 또는 Devin 우선 콤보를 사용하십시오.

## 격리 및 위협 모델

호스트의 Claude 설치, 계정 및 구성은 범위에서 제외되며 접근 금지 대상으로
취급됩니다. Compose 서비스는 다음과 같습니다.

- UID/GID `10001:10001`로 실행되며, 읽기 전용 루트 파일 시스템, 제거된 capabilities 및
  `no-new-privileges`를 사용합니다.
- 비공개 `/home/bridge`, 전용 Claude 구성 볼륨, 격리된 OmniRoute 데이터 및
  별도의 `devin-auth` 볼륨을 사용합니다.
- 폐기 가능한 `.sandbox` 작업 공간/증거만 마운트합니다.
- 호스트 홈, Keychain, SSH, 클라우드 자격 증명 또는 Docker 소켓을 마운트하지 않습니다.
- 명시적인 환경을 구성하고 Anthropic API/OAuth/라우팅 변수를 제거합니다.
- 로컬 전용 키를 사용하여 Claude Code 추론을 `http://omniroute:20128`로만 전달합니다.

오프라인 프로필은 내부 네트워크를 사용합니다. 라이브 프로필에서 OmniRoute는
`network-guard`를 통해서만 공식 Devin 엔드포인트에 접근하며, 관련 없는 대상은 거부됩니다.
Claude Code에는 별도의 모든 이그레스 거부 가드가 있으며, `NO_PROXY`를 통해 로컬 OmniRoute
서비스에만 접근할 수 있습니다. 가드 감사 파일은 해당 가드 프로세스에만 마운트됩니다.
스크립트는 토큰이 제거된 증거를 내보내기 전에 파일 소유권, 모드, 링크 수 및 모든 결정을
검증합니다.

격리 증명을 독립적으로 실행합니다.

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

이 명령은 토폴로지, 명명된 마운트, 비루트/읽기 전용 설정, 명시적인 로컬 라우팅,
민감한 환경 변수의 부재, Docker 소켓의 부재, `api.anthropic.com` 및 `claude.ai`에 대한
접근 차단, Devin 전용 공급자 선택, 그리고 ACP 백엔드를 사용할 수 없을 때 명시적으로
실패하는지를 검증합니다.

## 최초 설정 및 일반적인 사용

고정된 이미지를 빌드합니다.

```bash
./scripts/devin-bridge/build
```

격리된 Devin 볼륨만 인증합니다.

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

로그인 명령은 원격/컨테이너 환경을 위한 공식 수동 토큰 흐름을 사용합니다. 값은 CLI
프롬프트에 직접 입력되며, 프로세스 인수로 전달되거나 Git에 기록되거나 호스트에서
복사되지 않습니다.

격리된 Claude Code 런타임을 시작합니다.

```bash
./scripts/devin-bridge/launch
```

`launch`는 컨테이너화된 Claude Code를 시작하기 전에 격리, Devin 인증 및 모델 검색을
다시 확인합니다. 호스트의 Claude 실행 파일은 절대 실행하지 않습니다. 모델 별칭은
`.env.devin-bridge`에서 설정할 수 있으며, 구성된 모든 값은
`devin-cli-agentic/` 접두사를 유지해야 합니다.

## 검증 명령

재현 가능한 오프라인 경로에는 Devin 계정이 필요하지 않으며 런타임 인터넷 연결도
사용하지 않습니다.

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

인증이 필요한 옵트인 라이브 경로는 다음과 같습니다.

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

라이브 실행기는 ACP 세션이 한꺼번에 열리지 않도록 시나리오 사이에 대기하며, 텍스트로
표현된 주장을 신뢰하는 대신 구조화된 Claude 스트림 이벤트를 검증합니다. 다음 세 가지
시나리오를 증명합니다.

1. 프로젝트 직접 읽기 및 결함 분석
2. 실제 `Edit`, 클라이언트가 소유한 `Bash` `npm test` 및 최종 결과
3. `/bridge-check`와 `bridge-proof` 검색, 프로젝트 읽기, 클라이언트가 소유한 또 다른
   성공적인 `npm test`, 그리고 대기 중인 작업 없이 완료

최종 게이트는 Devin 네트워크 감사도 확인하며 Claude 이그레스 감사가 비어 있는 상태로
유지될 것을 요구합니다.

## 고정된 도구 업데이트

이미지는 `docker/devin-bridge/Dockerfile`에서 Node, Claude Code 및 Devin CLI 버전을 고정합니다. 업데이트하려면:

1. 명시된 버전을 변경합니다.
2. 아키텍처별 Devin 아카이브 체크섬을 모두 공식 아티팩트의 값으로 교체합니다.
3. 다시 빌드하고 모든 오프라인 검증 명령을 실행합니다.
4. 이미지 내부에서 버전을 확인합니다.
5. 인증된 세 가지 시나리오의 라이브 제품군을 다시 실행합니다.

호스트에 두 CLI 중 어느 것도 전역으로 설치하거나 체크섬 검증을 검증되지 않은 다운로드로 대체하지 마십시오.

## 진단 및 정리

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  는 로컬 라우팅 및 민감 정보가 제거된 실행기 오류를 표시합니다.
- `.sandbox/evidence/mock-acp.jsonl`은 결정론적 모의 ACP 작업을 기록합니다.
- `.sandbox/evidence/claude-stream.jsonl`은 실제 Claude Code 오프라인 실행을 기록합니다.
- `.sandbox/evidence/live-*.jsonl`은 검증된 세 가지 라이브 스트림을 기록합니다.
- `.sandbox/evidence/egress.jsonl`과 `.sandbox/evidence/claude-egress.jsonl`은 검증되었으며
  토큰이 제거된 가드 감사 사본입니다.

로그인/구성 볼륨을 보존하면서 소유한 컨테이너와 네트워크를 중지합니다.

```bash
./scripts/devin-bridge/clean
```

명명된 볼륨을 포함하여 브리지가 소유한 전체 환경을 제거합니다.

```bash
./scripts/devin-bridge/clean --all
```

## 제한 사항

- Devin CLI `3000.2.17`은 도구를 사용하지 않는 중립적인 ACP 에이전트를 제공하지 않으므로 브리지는 도구가 없는 고정 `summarizer` 역할에 의존합니다. 어댑터는 요약 형태의 중간 응답을 보정하지만, 범위가 제한된 단 한 번의 복구 시도도 여전히 명시적으로 실패할 수 있습니다.
- 라이브 ACP 호출은 일시적인 `502`/`504` 응답을 반환할 수 있습니다. 하네스는 시나리오 간에 간격을 두지만, 지속적인 실패가 발생하면 차단된 상태를 유지하며 다른 제공자를 선택하지 않습니다.
- ACP 컨텍스트는 각 Anthropic 요청으로부터 재구성되며, 프로세스/세션 고정성은 없습니다.
- 모델 응답당 하나의 도구 호출이 지원되며, 병렬 호출은 거부됩니다.
- 이미지는 명시적으로 지원되지 않습니다. 비전, 사고 출력, 노력 수준 제어 및 1M 컨텍스트 창은 지원 대상으로 명시되지 않습니다.
- SSE는 유효한 Anthropic 수명 주기 이벤트를 사용하지만, 범위가 제한된 ACP 턴이 수집된 후에 전송됩니다. ACP 청크는 점진적으로 전달되지 않습니다.
