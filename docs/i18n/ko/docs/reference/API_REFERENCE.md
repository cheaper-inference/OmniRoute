OmniRoute API의 핵심 레퍼런스입니다. 공개 `/v1` 표면과 가장 많이 사용되는 관리 엔드포인트를 다룹니다. 전체 내용을 확인하려면 기계 판독이 가능한 [`docs/openapi.yaml`](../openapi.yaml) 및 `src/app/api/` 아래의 라우트 트리를 참조하세요.

OpenAI 호환 프로토콜과 제공업체 기능 매트릭스에 초점을 맞춘 내용은
[`OPENAI_COMPATIBILITY.md`](./OPENAI_COMPATIBILITY.md)를 참조하세요.

각 배포는 빌드 중 `docs/openapi.yaml`에서 생성된 사양의 자체 사본을 `/openapi.yaml`에서 제공합니다. 이 사양에는 해당 빌드의 버전과 상대 서버 URL(`./`)이 포함되므로 요청은 문서를 제공한 호스트에서 계속 처리됩니다. 다운로드한 파일을 가져오는 도구에는 이러한 호스트 정보가 없으므로 기본 URL을 수동으로 설정해야 합니다.

## 채팅 완성

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### 사용자 지정 헤더

| Header                   | 방향 | 설명                                                                                                                                                                                 |
| ------------------------ | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `X-OmniRoute-No-Cache`   | 요청 | 캐시를 우회하려면 `true`로 설정                                                                                                                                                      |
| `x-omniroute-no-memory`  | 요청 | 이 요청에 대한 메모리 + 스킬 주입을 건너뛰려면 `true`로 설정 (no-cache를 미러링하며 호출별 토큰/비용 오버헤드를 방지)                                                                |
| `X-OmniRoute-Progress`   | 요청 | 진행률 이벤트를 사용하려면 `true`로 설정                                                                                                                                             |
| `X-Session-Id`           | 요청 | 외부 세션 어피니티를 위한 고정 세션 키                                                                                                                                               |
| `x_session_id`           | 요청 | 밑줄 변형도 허용됨 (직접 HTTP)                                                                                                                                                       |
| `X-OmniRoute-Session-Id` | 요청 | 호출자가 제공하는 세션/대화 태그 (메모리에도 전달됨). 값이 있으면 세션별 비용 귀속을 위해 `call_logs.session_tag`에 있는 그대로 영속화됨 (#8249) — 값이 없을 때는 절대 생성되지 않음 |
| `Idempotency-Key`        | 요청 | 중복 제거 키 (5초 윈도우)                                                                                                                                                            |
| `X-Request-Id`           | 요청 | 대체 중복 제거 키                                                                                                                                                                    |
| `x-omniroute-connection` | 요청 | ID를 기준으로 단일 모델 요청을 하나의 공급자 연결(계정)에 고정 — [요청별 계정 고정](#account-pinning-per-request) 참조                                                               |
| `X-OmniRoute-Cache`      | 응답 | `HIT` 또는 `MISS` (스트리밍하지 않는 경우)                                                                                                                                           |
| `X-OmniRoute-Idempotent` | 응답 | 중복 제거된 경우 `true`                                                                                                                                                              |
| `X-OmniRoute-Progress`   | 응답 | 진행률 추적이 활성화된 경우 `enabled`                                                                                                                                                |
| `X-OmniRoute-Session-Id` | 응답 | OmniRoute에서 사용한 유효 세션 ID                                                                                                                                                    |
| `X-OmniRoute-Request-Id` | 응답 | 요청 상관관계 ID (확인 가능한 경우)                                                                                                                                                  |
| `X-OmniRoute-Version`    | 응답 | OmniRoute 빌드 버전 (항상 포함됨)                                                                                                                                                    |
| `X-OmniRoute-Cost-Saved` | 응답 | 캐시가 `HIT`일 때 캐시로 절감된 USD (캐시 적중 시에만)                                                                                                                               |
| `X-OmniRoute-Decision`   | 응답 | 라우팅 추적: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>`은 조합 전략이며, 조합이 아닌 요청에서는 `single`) — 완료 응답에 항상 포함됨                               |

> Nginx 참고: 밑줄이 포함된 헤더(예: `x_session_id`)에 의존하는 경우 `underscores_in_headers on;`을 활성화하세요.

#### 요청별 계정 고정

공급자에 여러 연결(계정 또는 키)이 있는 경우 OmniRoute는 일반적으로 계정 선택 전략을
통해 하나를 선택합니다. 대신 요청에서 `x-omniroute-connection` 헤더를 사용하여 특정 연결 하나를
고정할 수 있습니다.

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **id를 찾는 위치.** 대시보드의 프로바이더 페이지
  (**대시보드 → 프로바이더 → <provider>**)를 열고 연결 행에서 `xxxxxxxx…` id 칩을 클릭하세요
  — 전체 connection id가 복사됩니다.
- **이를 적용하는 요청.** `/v1/chat/completions`, `/v1/messages` 및 `/v1/responses`의 단일 모델 요청(`provider/model`)입니다. 콤보는 헤더를 무시합니다. 대신 각 콤보 단계의 자체 connection을 통해 단계별로 계정을 고정하세요.
- **고정은 선호가 아니라 엄격하게 적용됩니다.** 고정된 connection만 사용됩니다. 요청 내부에서 오류가 발생하면 해당 계정의 cooldown이 기록되지만, 같은 프로바이더의 다른 계정으로 전환하지는 않습니다.
- **Cooldown과 quota가 고정을 해제합니다.** 고정된 connection이 cooldown 중이거나 quota를 모두 소진했거나 quota 정책에 의해 차단된 동안에는, 이후 요청이 고정되지 않은 트래픽과 동일하게 프로바이더의 다른 connection으로 fallback됩니다.
- **알 수 없거나 비활성화된 id는 실패합니다.** 프로바이더의 활성 풀에 없는 id(삭제되었거나, 비활성화되었거나, 다른 프로바이더에 속한 id)는 사용 가능한 계정을 남기지 않으므로, 요청이 다른 곳으로 자동 라우팅되지 않고 실패합니다.

Claude Code는 `ANTHROPIC_CUSTOM_HEADERS`를 통해 사용자 지정 헤더를 전송합니다. 이를
`~/.claude/settings.json`의 `env` 블록에 추가하거나, 프로젝트별로 다른 계정을 고정하려면 프로젝트 수준의 `.claude/settings.json`에 추가하세요:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

소스: `src/sse/handlers/chat.ts` (헤더 읽기), `src/sse/services/auth.ts` 및
`src/sse/services/sessionAffinityPin.ts` (고정 해제 및 풀에서 누락된 항목 확인).

> **비용 텔레메트리 헤더:** 스트리밍하지 않는 성공 응답에도 `X-OmniRoute-*` 비용 텔레메트리 세트가 포함됩니다 — `X-OmniRoute-Response-Cost` (USD, 소수점 이하 10자리 고정; 무료/가격 미책정인 경우 `0.0000000000`), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, `X-OmniRoute-Fallback-Attempts` (0보다 큰 경우에만), 그리고 `X-OmniRoute-Request-Id` 및 `X-OmniRoute-Version`입니다. 이러한 헤더는 chat completions, `/v1/responses`, `/v1/messages`, **그리고 미디어 엔드포인트** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` 및 `/v1/moderations` (항상 비용 `0`) — 에서 생성됩니다. 미디어 비용은 가격 정보가 제공되는 경우 모달리티별(이미지당, 초당, 문자당, 검색 단위당)로 계산되며, 그렇지 않으면 `0`입니다(fail-open).

> **캐시 적중 비용 의미:** 시맨틱 캐시 적중(`X-OmniRoute-Cache-Hit: true`)에서는 upstream 호출이 수행되지 않으므로 `X-OmniRoute-Response-Cost`는 `0.0000000000`입니다(적중 결과를 제공하는 데 드는 **증분** 비용). 원래 비용/발생했을 비용은 `X-OmniRoute-Cost-Saved`에 별도로 보고됩니다. 결제 처리 소비자는 `X-OmniRoute-Response-Cost`를 합산해야 하며(적중 비용은 없음), 캐시 분석에서는 `X-OmniRoute-Cost-Saved`를 집계할 수 있습니다.

## 독점 관리 세션 임대

독점 관리 세션 임대는 옵트인 방식의 클라이언트 중립적 라우팅 계약입니다. 하나의 활성 소유자가
하나의 적격 OmniRoute 연결을 보유합니다. 이는 모델을 임대하거나, OAuth를 요구하거나, 특정
클라이언트를 식별하거나, 특정 provider를 요구하지 않습니다.

인증에 사용되는 API 키에는 `lease:exclusive` 스코프와 명시적인 비어 있지 않은
`allowedConnections` 목록이 있어야 합니다. 데이터베이스 변경 경계에서는 키 생성 및 부분 업데이트
시 두 필드를 함께 적용합니다.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

성공한 acquire, renew, release 응답에는 타임스탬프, `state`, 정확한 양의
`generation`이 노출되지만, 선택된 연결이나 자격 증명은 절대 노출되지 않습니다. renew 및 release는
JSON 본문에 generation을 제공합니다.

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

활성 임대 소유자는 현재 바인딩에 대한 개인정보 보호형 표시 메타데이터를 명시적으로 요청할 수 있습니다.

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

이 옵트인 status 작업은 하나의 데이터베이스 트랜잭션에서 불투명한 소유자, 인증된 관리형 API 키,
정확한 활성 generation에 의해 펜싱됩니다. `displayName`은 설정된 연결 이름을 trim한 값일 뿐이며,
안전하게 사용할 수 있는 설정 이름이 없으면 `null`입니다. OmniRoute는 이메일이나 생성된 계정
식별자를 대신 사용하지 않습니다. provider 값은 민감하지 않은 표시 레이블이며, 생성된 호환 provider
식별자가 아닙니다. 자격 증명, 토큰, 쿠키, 원시 연결 또는 API 키 ID, 소유자 해시, 펜싱 시크릿 및
내부 라우팅 데이터는 제외됩니다.

잘못된 키, 잘못된 소유자, 오래된 generation, 존재하지 않는 항목, 만료된 항목, 해제된 항목 및
무효화된 조회는 모두 연결 메타데이터 없이 동일한 `409 LEASE_FENCE_STALE` 오류를 반환합니다. 용량
대기 응답을 받은 클라이언트에는 검사할 활성 바인딩이 없습니다. 라우팅이 활성 임대를 전환할 때에도
동일한 generation은 유효하게 유지되며, status는 원자적으로 새 바인딩을 반환하고 이전 바인딩은
절대 반환하지 않습니다. acquire, renew, release 및 대기 응답이 이전 형태를 유지하므로 기존
클라이언트는 변경되지 않습니다.

이 서버 계약은 기본 OpenAI Codex `/status`를 변경하지 않습니다. 기본 Codex는 현재 모델 provider와
내장 인증/계정 상태를 보고하지만, 임의의 사용자 지정 provider 계정 메타데이터를 렌더링하지는
않습니다. 이후의 클라이언트 통합에서는 이 작업을 호출하고 `connection.displayName`을 표시하는
방법을 결정해야 합니다.

이후 모든 관리형 추론 요청은 두 제어 헤더를 모두 제공합니다.

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

지원되는 각 upstream 시도 직전에 정확한 소유자, generation, 활성 연결 및 인증된 API 키가 즉시
펜싱됩니다. 다른 키로 동일한 연결을 허용하는 경우에도 소유자와 generation을 다른 키로 재생하면
실패합니다. 원시 소유자는 저장, 로깅, 요청 스냅샷 보존 또는 upstream 전달이 이루어지지 않습니다.

일시적인 경합은 `Retry-After`가 포함된 HTTP `429`와 다음 응답을 반환합니다.

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

이 응답은 일반적인 적격 집합이 비어 있지 않았고, 사용 가능한 모든 후보가 다른 활성 임대에 의해
점유되었다는 의미일 뿐입니다. 지원되지 않는 모델/provider, 정책 불일치, 쿨다운, 할당량, 상태 및
기타 일반적인 적격성 실패는 기존 OmniRoute 응답을 그대로 유지합니다.

### `x-omniroute-compression`

요청별 압축 계획 재정의입니다. 우선순위가 가장 높으며, 라우팅 조합 재정의, 활성 프로필,
자동 트리거 및 패널 Default보다 우선합니다. 값:

| 값            | 효과                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------- |
| `off`         | 이 요청에서는 압축하지 않습니다.                                                              |
| `default`     | 패널에서 파생된 Default 프로필입니다(활성 프로필 무시). 손실 엔진은 비활성 상태로 유지됩니다. |
| `safe`        | 중복 제거와 공백 접기만 수행합니다.                                                           |
| `allow-lossy` | 요약 및 스타일 재작성 등을 포함하여 이 요청에 운영자 계획을 유지합니다.                       |
| `engine:<id>` | 활성화된 단일 엔진입니다(예: `engine:rtk`). 해당 엔진에 대한 요청별 옵트인입니다.             |
| `<combo>`     | 이름으로 먼저 대소문자를 구분하지 않고 일치시킨 다음 ID로 일치시키는 명명된 조합입니다.       |

참고:

- 알 수 없는 값은 무시됩니다(요청은 절대 거부되지 않음). 해결 과정은 일반 운영자 우선순위로 넘어갑니다.
- 여러 조합이 동일한 이름을 공유하는 경우 결정적인 일치를 위해 조합 **id**를 전달합니다.
- 이름이 `off` 또는 `default`인 조합은 이름으로 선택할 수 없습니다(해당 키워드가 먼저 해석됨). 이러한 조합은 ID로 참조합니다.
- 마스터 압축 스위치는 강제 게이트입니다. 압축이 전역적으로 비활성화된 경우 이 헤더로 압축을 활성화할 수 없습니다.

적용된 계획은 응답 헤더에 다시 표시됩니다.

```
X-OmniRoute-Compression: <mode>; source=<source>
```

여기서 `<source>`는 `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` 또는
`off` 중 하나입니다.

## 임베딩

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

사용 가능한 제공업체: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

카탈로그 ID는 `provider/model` 형식입니다(예: `jina-ai/jina-embeddings-v5-omni-small`). 레지스트리에 표시되는 Jina 모델 ID(예: `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`)도 그대로 확인됩니다. Jina 임베드/리랭크/분류/세그먼트는 대시보드의 `jina-ai` 인증 정보를 먼저 사용하며, 대시보드 키가 없는 경우에만 `JINA_AI_API_KEY`를 대체 수단으로 사용합니다. `jina-reader` 카드는 Reader / `r.jina.ai` 전용이며(`POST /v1/web/fetch`), 임베딩이나 리랭크를 제공하지 않습니다.

멀티모달 지원을 광고하는 레지스트리 모델은 최대 32개의 제공업체 중립적인 구조화된 항목도 허용합니다. 미디어 항목 유형은 `text`, `image`, `audio`, `video`, `document`입니다. 미디어 `source`는 `{"type":"url","url":"https://..."}` 또는 `{"type":"base64","data":"...","media_type":"..."}` 중 하나입니다.

Jina v5 Omni(`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano` 및 제품군 별칭 `jina-ai/jina-embeddings-v5-omni` → omni-small)는 Jina의 네이티브 EmbeddingsV5Request 문서도 허용하며, 이를 수정 없이 `https://api.jina.ai/v1/embeddings`로 **전달합니다**:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

네이티브 `{ image | audio | video | pdf }` 값은 공개 HTTPS URL, `data:` URI 또는 원시 base64일 수 있습니다. OmniRoute는 해당 객체를 문자열로 변환하거나 네이티브 이미지 URL을 가져오지 않으며, Jina가 공개 미디어를 직접 가져옵니다. 추가 Jina 필드(`task`, `normalized`, `truncate`, `embedding_type`)는 전달됩니다. 텍스트 전용 Jina SKU는 여전히 텍스트가 아닌 문서를 거부합니다.

보안 및 전송 제한:

- 원격 미디어 URL은 공개 HTTPS URL이어야 합니다. 표준 `{type,source:url}` 항목은 서버 측에서 가져오며(리디렉션 재검증, 시간 초과, 크기 제한, 공개 DNS, 연결 고정), 제공업체 호출 전에 인라인됩니다. Jina 네이티브 `{image:"https://..."}` 항목은 동일한 공개 HTTPS 검사를 거친 후 있는 그대로 전달되며, URL은 Jina가 가져옵니다.
- 인라인 base64 미디어는 항목당 디코딩 후 8 MiB, 요청 전체에서 디코딩 후 16 MiB로 제한됩니다.

제공업체 변환(표준 항목은 수정 없이 전달되지 않음):

- Jina 멀티모달 모델: 각 최상위 항목은 데이터 URI를 사용해 하나의 modality 키 객체(`text` / `image` / `audio` / `video` / `pdf`)가 되며, 최상위 항목마다 벡터 하나가 생성됩니다.
- Gemini Embedding 2 제품군: 하나의 최상위 배열은 `content.parts`(`text` 또는 `inline_data`)를 포함하는 단일 네이티브 `models/{model}:embedContent` 요청이 됩니다.
- llama.cpp(`llama-cpp/<model>`, 로컬 서버가 로드한 모든 모델): 표준 `text` 항목은 일반 문자열이 되고, `image` / `audio` / `video`는 각각 하나의 `{"content": [part]}` 객체가 됩니다. 이때 인라인 데이터와 함께 llama-server의 채팅 콘텐츠 파트(`image_url`, `format`이 `wav` / `mp3` / `flac`인 `input_audio`, `input_video`)를 사용하며, 최상위 항목마다 벡터 하나가 생성됩니다. 서버는 `--embedding --mmproj …`로 실행되어야 하며, 프로젝터가 없으면 미디어 자체를 거부합니다. `document`는 지원되지 않습니다.
- 명시적인 modality 메타데이터가 없는 알 수 없는/동적 모델은 구조화된 입력을 HTTP 400으로 거부합니다.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

지원되지 않는 모델/모달리티 조합은 항목을 강제 변환하는 대신 HTTP 400을 반환합니다. 레거시 문자열/토큰 요청의 입력이 아닌 확장 필드는 계속 수정 없이 전달됩니다.

```bash
# 모든 임베딩 모델 나열
GET /v1/embeddings
```

## 이미지 생성

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

사용 가능한 공급자에는 OpenAI (GPT 이미지 2), xAI (Grok 이미지), Together AI (FLUX), Fireworks AI, Nebius(FLUX), Hyperbolic, NanoBanana,**OpenRouter** ,**ZenMux** , SD WebUI (로컬), ComfyUI (로컬).

`n` `data[]` 에 `n` 이미지를 반환합니다. 업스트림 API 호출당 하나의 이미지를 반환하는 제공자(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik, NVIDIA NIM, Cloudflare Workers AI)는 최대 4개의 `n` 별도 업스트림 호출을 수신합니다. 고정된 `seed` 은 호출 인덱스(`seed`, `seed + 1`, …)에 의해 오프셋되므로 이미지는 다르지만 재현 가능합니다. `n` 는 10으로 제한됩니다. 호출이 실패하면 요청이 전체적으로 실패합니다. 팬아웃 형식 목록은 `open-sse/handlers/imageGeneration/fanOut.ts` 의 `SINGLE_IMAGE_FANOUT_FORMATS` 입니다.

ZenMux 기존 API 키 연결을 재사용하고 `zenmux/` 또는 `zm/` 접두사를 허용합니다.

- `zenmux/openai/gpt-image-2` ZenMux 의 OpenAI 이미지 API 사용합니다. 옵션에는 `size`, `quality`, `n`, `output_format`, `output_compression`, `background` 및 `response_format` 포함됩니다.
- `zm/meta/muse-image-1.0` 와 같은 다른 게시자는 ZenMux 의 Vertex AI `:predict` 엔드포인트를 사용합니다. `n` `sampleCount`, `aspect_ratio` `aspectRatio`, `image_size` (`1K`, `2K`, `4K`)는 `sampleImageSize` 에 매핑됩니다. 픽셀 `size` 보장된 픽셀 크기가 아닌 종횡비만 제공합니다. 지원되는 비율, 해상도 및 개수는 모델에 따라 다릅니다.
- `zm/inclusionai/ming-image-0.1-design` 자체 차원을 선택합니다. `size`, `aspect_ratio` 및 `image_size` 생략합니다. 명시적 값은 HTTP 400을 반환합니다. PNG, JPEG 및 WebP `output_format` 로 요청할 수 있습니다.

이 통합은 참조 이미지 편집이 아닌 텍스트-이미지 생성을 지원합니다. 정점 출력은 `data[].b64_json` 로 정규화됩니다. `response_format: "url"` 이미지 바이트만 사용할 수 있는 경우 업스트림 HTTPS URL 또는 base64 데이터 URL 반환합니다. Empty/filtered 출력은 빈 성공이 아닌 오류를 반환합니다. 모델 액세스는 ZenMux 계정에 따라 다릅니다. [ZenMux 의 정점 API](https://docs.zenmux.ai/api/vertexai/generate-images) 및 [OpenAI 이미지 API](https://docs.zenmux.ai/api/openai/generate-an-image) 참조하세요.

Microsoft 365 Copilot 로그인 연결은 Copilot 의 내장 이미지 도구를 통해 `copilot-m365-web/m365-copilot-image` 제공합니다. 즉, 이미지당 하나의 Copilot 회전(`n` 1–4), `size` 방향만 조정하고 인라인으로 반환된 이미지(`b64_json` 또는 `response_format: "url"` 의 경우 데이터 URL )입니다. [Microsoft 365 Copilot](../providers/COPILOT-M365.md#image-generation) 참조하세요.

```bash
# List all image models
GET /v1/images/generations
```

## 문서 OCR

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model`은 `provider/model` 접두사를 통해 OCR 제공업체를 선택합니다. 접두사가 없는 모델 ID(예:
`mistral-ocr-latest`)는 등록된 제공업체로 확인되며, `model`을 생략하면 Mistral
(`mistral-ocr-latest`)이 기본값으로 사용됩니다. 등록된 제공업체(`open-sse/config/ocrRegistry.ts`):

| 제공업체 ID                   | 모델 ID              | `model` 값                                                           | 참고                                                                                                   |
| ----------------------------- | -------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (또는 접두사 없는 `mistral-ocr-latest`) | 동기식 — 단일 업스트림 호출의 응답이 직접 반환됩니다.                                                  |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                          | 비동기식 업스트림(`analyze` + 폴링) — 아래를 참조하세요.                                               |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                              | Vertex AI의 `openapi/chat/completions` 파트너 엔드포인트를 통한 동기식 — 인증/URL은 아래를 참조하세요. |

세 제공업체 모두 동일한 Mistral 형식의 본문으로 응답합니다.

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Azure Document Intelligence 폴링 흐름

Azure Document Intelligence의 `analyze` API는 비동기식입니다. 초기 요청은 본문 대신
`Operation-Location` 헤더를 반환하며, 결과를 폴링해야 합니다. 핸들러
(`open-sse/handlers/ocr.ts`)는 최대 30회 시도 동안 매초 해당 URL을 폴링하고, `ok`가 아닌 폴링
응답이나 `"failed"` 상태가 반환되면 즉시 실패하며(폴링을 계속하지 않음), 시도 예산이 소진된 후에도
작업이 계속 실행 중이면 `504`를 반환합니다. 최종 Azure 응답은 호출자에게 반환되기 전에 Mistral에서
사용하는 것과 동일한 `pages`/`markdown` 형식으로 정규화되므로, 클라이언트 코드는 제공업체별
예외 처리를 별도로 수행할 필요가 없습니다.

### Vertex AI DeepSeek OCR 인증 및 엔드포인트 확인

`vertex-deepseek-ocr`은 OmniRoute가 이미 채팅/이미지 트래픽에 지원하는 것과 동일한 Vertex AI 인증
(`open-sse/executors/vertex.ts`)을 재사용합니다. 연결의 API 키는 서비스 계정 JSON 자격 증명일 수
있으며(JWT 전달자 흐름을 통해 단기 OAuth 액세스 토큰으로 교환됨), 이미 발급된 OAuth 액세스 토큰일
수도 있습니다. 이 경우 토큰을 그대로 사용합니다. 업스트림 엔드포인트 URL은 연결의 프로젝트와
리전을 기반으로 구성되는 Vertex의 일반 `openapi/chat/completions` 파트너 엔드포인트입니다.
명시적인 `providerSpecificData.project`/`providerSpecificData.region`이 항상 우선하며, 그렇지
않으면 프로젝트는 서비스 계정 JSON의 `project_id`에서 파생되고 리전은 기본적으로
`us-central1`로 설정됩니다. 두 확인 작업은 모두 `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`)에서 수행되며,
`src/app/api/v1/ocr/route.ts`가 `handleOcr`로 디스패치하기 전에 이를 사용합니다.

### 모델 가격 (`pricing`)

OmniRoute가 모델 가격을 알고 있는 경우 항목에 `pricing` 객체가 포함됩니다. 가격은 비용
계산에 사용되는 가격표에서 가져옵니다. 여기에는 기본 제공 기본값, 동기화된 가격, 그리고
`/api/pricing`을 통해 설정한 재정의가 포함됩니다. 이는 표시 가격이므로 구독 제공업체에도
토큰당 가격이 표시됩니다.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| 필드                                                            | 단위                      | 참고                                                                                                                                       |
| --------------------------------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | 토큰당 USD, 십진수 문자열 | OpenRouter와 호환되며, 지수 표기법은 사용하지 않습니다. 두 캐시 필드는 캐시 가격이 있는 경우에만 표시됩니다.                               |
| `input`, `output`, `cached`, `cache_creation`                   | 1M 토큰당 USD, 숫자       | 이전 카탈로그 버전의 필드이며, 기존 클라이언트를 위해 유지됩니다. 가격 행에 해당 항목이 있으면 `reasoning` 및 `long_context`도 표시됩니다. |

- **조합**은 첫 번째로 표시되는 대상의 가격을 가집니다. 기본 제공 `auto/*` 조합은 요청 시점에
  대상을 선택하므로 `pricing`이 없습니다.
- **무료 모델**은 가격이 0인 경우 `"0"`(및 `0`)으로 표시됩니다. 가격 행이 없는 모델도
  카탈로그에서 무료로 표시되거나(`free: true`) 기본 제공 무료 모델 카탈로그에 등록되어
  있으면 `"0"`으로 표시됩니다.
- **알 수 없는 가격:** 항목에 `pricing` 키가 없습니다.
- **크레딧 단위로 과금되는 제공업체**(예: Kiro)는 토큰당이 아니라 요청당 과금합니다. 해당
  항목에는 이전에 있던 1M 토큰당 숫자 필드가 유지되며, 토큰당 문자열 필드는 포함되지 않습니다.
- **변형**(추론 수준 ID, no-thinking 별칭, 검색 및 게이트웨이 미러)은 라우팅되는 모델의
  가격을 복사합니다.
- 필드는 기본 요율만 포함합니다. 긴 컨텍스트 등급(숫자 `long_context` 필드)과 서비스
  등급 배수(예: Codex fast 또는 flex)는 `prompt` 또는 `completion`을 변경하지 않습니다.
- 객체는 `x-api-key` 및 `anthropic-version`을 사용하는 Anthropic 스타일 요청을 포함하여 모든
  인증 방식에서 동일합니다(응답은 `{ "object": "list",
"data": [...] }`로 유지됩니다). 구현: `src/app/api/v1/models/catalogPricing.ts`.

### 모델 ID 접두사 (`?prefix=`)

대부분의 모델은 **제공업체 접두사** 아래에 표시됩니다. 어떤 접두사를 받을지는
`MODELS_CATALOG_PREFIX_MODE` 기능 플래그로 제어되며, 요청별로 쿼리 매개변수를 사용해
재정의할 수 있습니다. 이를 통해 서버 전체 설정을 변경하지 않고 깔끔한 목록을 원하는
클라이언트에 유용합니다.

```bash
GET /v1/models?prefix=alias        # 모델당 하나의 ID — 짧은 별칭 접두사
GET /v1/models?prefix=dual         # 두 형식 모두 표시(서버 기본값)
GET /v1/models?prefix=canonical    # 전체 제공업체 ID 접두사만 표시
```

| 모드        | 출력되는 항목                                            | 참고                                                                                                                                                                     |
| ----------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `dual`      | `cc/claude-sonnet-4-6` **및** `claude/claude-sonnet-4-6` | **기본값.** 두 ID 모두 동일한 모델로 라우팅되며, 어느 형식을 하드코딩한 클라이언트 설정도 계속 작동하도록 유지됩니다. 카탈로그 크기는 대략 두 배가 됩니다.               |
| `alias`     | `cc/claude-sonnet-4-6`                                   | 모델당 하나의 항목입니다. 고유한 별칭이 없는 제공업체도 해당 항목을 출력하므로 누락되는 항목이 없습니다.                                                                 |
| `canonical` | `claude/claude-sonnet-4-6`                               | 전체 제공업체 ID 접두사 아래 모델당 하나의 항목입니다. 고유한 별칭이 없는 제공업체(예: `antigravity/…`, `agy/…`)도 여기에 단일 ID를 출력하므로 누락되는 항목이 없습니다. |

`dual` 모드 미러는 쿼리 매개변수 없이도 식별할 수 있습니다. 기본 ID를 가리키는 `parent`
필드를 포함하기 때문입니다.

모델 선택기를 렌더링하는 클라이언트는 `?prefix=alias`를 요청해야 합니다. 이는
[OmniCopilot VS Code 확장](../guides/VSCODE-COPILOT.md)이 사용하는 방식입니다.

### 검색 필터 (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models`는 선택적으로 사용할 수 있는 검색 필터를 지원합니다. 필터를 사용하지
않으면 응답은 변경되지 않습니다. 이 필터는 호출자가 이미 볼 수 있는 카탈로그를
좁히며(API 키 권한이 먼저 적용됨), OpenAI 스타일의 `limit` / `after` 페이지 매김보다
먼저 실행됩니다.

```bash
GET /v1/models?capability=vision&capability=tool_calling   # 나열된 모든 기능이 true여야 함
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # 카탈로그의 `type`; 없는 행은 `chat`
GET /v1/models?q=sonnet&limit=10                           # ID 또는 이름에서 대소문자를 구분하지 않고 일치
```

| 매개변수      | 값                                                                                                  |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | 음이 아닌 정수이며 `context_length`와 비교됨                                                        |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200자                                                                                             |

알 수 없는 값이 지정되었거나 `min_context`가 음이 아닌 정수가 아닌 경우(예: `1.5`),
HTTP `400`을 반환하며 메시지에 유효한 값이 나열됩니다. 구현:
`src/app/api/v1/models/catalogFilters.ts`.

### 모델 간략 목록 (`POST /v1/models/query`)

`POST /v1/models/query`는 `GET /v1/models`와 동일한 카탈로그에서 동일한
인증 및 키별 표시 범위를 적용하여 결정론적인 짧은 목록을 반환합니다.

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

모든 필드는 선택 사항입니다. `capabilities` 및 `exclude`에는 배열 또는 쉼표로 구분된 문자열을
사용할 수 있으며, `max_output`은 `max_output_tokens`와 비교됩니다. 결과는 `owned_by`를 기준으로
정렬한 다음 `id`를 기준으로 정렬합니다. `limit`의 기본값은 `20`이며 `100`을 초과하는 값은
`100`으로 제한됩니다. 잘못된 JSON, 알 수 없는 필드 또는 잘못된 값이 지정되면 HTTP `400`을
반환합니다.

### 개별적으로 숨겨진 채팅 모델

공급자 페이지에서 **숨김**으로 표시된 모델은 카탈로그에서 제외되며, 명시적으로 요청하면
HTTP `404` / `model_not_found`를 반환합니다. 이 검사는 공급자 별칭, 호환 공급자 노드 접두사 및
연결 기본값을 포함하여 확인된 공급자와 모델을 사용합니다. 콤보는 숨겨진 대상을 건너뛰고 표시된
형제 모델을 사용할 수 있으며, 실행 가능한 대상이 더 이상 없으면 동일한 오류 코드를 반환합니다.
숨김 해제는 다음 요청부터 적용됩니다. 이미지 전용 표시 재정의는 동일한 ID를 가진 채팅 모델을
숨기지 않습니다.

이 개별 모델 설정은
[모델 노출 허용/거부 목록](../routing/MODEL_EXPOSURE_LIST.md)과 별개입니다. 해당 목록은 명시적
디스패치는 유지하면서 카탈로그 광고 및 자동 라우팅 후보를 필터링합니다. API 키 모델 권한은
계속 독립적으로 적용됩니다. 기본 카탈로그 접두사 모드는 `dual`로 유지됩니다.

### 사고 기능이 없는 모델 변형

사고 기능을 지원하는 Claude 모델의 경우 `/v1/models`는 ID가
`claude-3-omniroute-no-thinking/`으로 시작하는 **사고 기능 없음** 변형도 광고합니다.

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

이 ID를 선택하면(예: 항상 `thinking` 블록을 추가하는 Claude Code 구성에서)
실제 `<provider>/<model>`로 다시 확인되며 추론이 억제됩니다. `/v1/messages` 경로에서는
`thinking:{type:"disabled"}`가 적용되고, `/v1/chat/completions` 경로에서는
`reasoning`/`reasoning_effort` 필드가 삭제됩니다. 이 변형은 사고 기능을 지원하면서
`disabled`도 적용하는 Claude 제품군 모델에만 나열됩니다. 따라서 `disabled`를 거부하는
적응형 전용 모델 등은 제외됩니다. 운영자는 `ModelSpec.noThinkingAlias`를 통해 모델별로
이 변형을 강제로 활성화하거나 비활성화할 수 있습니다.

## ElevenLabs 오디오 생성

ElevenLabs API 키를 사용하여 OmniRoute에서 `elevenlabs` 프로바이더 연결을 구성하세요.
클라이언트는 **OmniRoute** 키(`Authorization: Bearer $OMNIROUTE_API_KEY`)로 인증하며,
게이트웨이는 저장된 프로바이더 키를 `xi-api-key`로 제공합니다. ElevenLabs 키를 게이트웨이
Bearer 토큰으로 절대 전송하지 마세요.

| 메서드 | 경로                        | 응답                               | API 키 엔드포인트 카테고리 |
| ------ | --------------------------- | ---------------------------------- | -------------------------- |
| POST   | `/v1/sound-generation`      | 기본 오디오 바이트                 | `elevenlabs`               |
| POST   | `/v1/music`                 | 기본 오디오 바이트                 | `music`                    |
| POST   | `/v1/music/stream`          | 스트리밍 오디오 바이트             | `music`                    |
| POST   | `/v1/music/detailed`        | 기본 멀티파트 오디오 및 구성 계획  | `music`                    |
| POST   | `/v1/music/detailed/stream` | 기본 SSE 메타데이터 및 오디오 청크 | `music`                    |
| POST   | `/v1/music/plan`            | JSON 구성 계획                     | `music`                    |

이러한 엔드포인트는 기존 `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` 및 `/v1/speech-to-text` 라우트를 보완합니다. 기본
JSON 필드와 `output_format`, `enable_logging` 같은 쿼리 매개변수는 그대로 유지됩니다.
`/v1/music/detailed` 응답은 멀티파트 경계를 유지하므로 멀티파트로 파싱하세요.
`/v1/music/detailed/stream`은 구성 메타데이터와 SSE 이벤트의 base64 오디오 청크를 포함하는
`text/event-stream`을 반환합니다. 여섯 개 라우트 모두 CORS 프리플라이트를 지원합니다.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# 짧은 사운드 효과입니다. 지속 시간: 0.5~30초.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# 음악 지속 시간은 밀리초로 지정합니다: 3000~600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

증분 오디오 전달에는 동일한 JSON 본문과 함께 `/v1/music/stream`을 사용하세요. 구성은
`prompt` 또는 `composition_plan` 중 정확히 하나를 허용하며, `/v1/music/plan`에는 `prompt`가
필수이고 `source_composition_plan`을 선택적으로 지정할 수 있습니다. 기본 스키마는 추가
프로바이더 필드를 유지하므로 구성 계획 버전과 미세 조정 옵션이 ElevenLabs에 전달됩니다.

통합 `/v1/music/generations` 엔드포인트는 `elevenlabs/music_v1`,
`elevenlabs/music_v2` 및 `elevenlabs/music_v2_5`도 허용합니다. 활성 ElevenLabs 연결이
있으면 이러한 모델이 음악 카탈로그에 노출됩니다. 이 엔드포인트는
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`를 반환합니다. `duration` 필드는
초 단위이며 `music_length_ms`에 매핑됩니다. 명시적인 `music_length_ms`가 있으면 해당
값이 우선합니다. `instrumental`은 `force_instrumental`에 매핑되며, 기본 필드가 우선합니다.
스트리밍에는 기본 스트리밍 엔드포인트를 사용하고, 구성 계획만으로 요청하는 경우에는 기본
구성 엔드포인트를 사용하세요.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

엔드포인트, 모델, 예산 및 연결 제한은 업스트림 호출 전에 적용됩니다. 기본 라우트는
`402` 플랜 제한 및 할당량 제한을 나타내는 `429`를 포함하여 업스트림 상태 코드와 오류 본문을
변경 없이 반환합니다. `character-cost`, `song-id`, `request-id` 및 `retry-after` 헤더가
존재하는 경우 유지됩니다. 무료 크레딧 잔액이 있다고 해서 모든 음악 모델, 출력 형식 또는 API
기능에 액세스할 수 있는 것은 아닙니다. 각 요청에 대한 권한은 ElevenLabs가 결정합니다.
통합 엔드포인트는 OmniRoute의 정규화된 오류 봉투에서 오류 상태 코드를 유지합니다.

업스트림 계약: [사운드 효과](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[음악 구성](https://elevenlabs.io/docs/api-reference/music/compose) 및
[스트리밍 음악 세부 정보](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

`Authorization: Bearer ...`를 첨부할 수 없는 클라이언트의 경우, OmniRoute는 쿼리 문자열 호환 방식 (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`) 또는 아래에 문서화된 전용 `/api/v1/vscode/{token}/...` 엔드포인트를 통해서도 URL에서 API 키를 허용합니다.

```bash
# 재순위 지정 (클라우드 레지스트리 제공자 또는 "<prefix>/<model>" 형식의 OpenAI 호환 제공자 노드)
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Jina 분류 (Foundation API 자격 증명)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Jina 세그먼트 분할기
POST /v1/segment     { "content": "...", "return_chunks": true }

# Jina 검색 (s.jina.ai; 제공자 별칭: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# 조정
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — audio/mpeg (또는 요청한 형식) 본문 반환
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS에는 언어와 음성이 필요합니다: `language`의 기본값은 "en"이며, 음성이 없거나
# OpenAI 기본 음성 이름(alloy, nova, …)인 경우 "Adrian"이 됩니다.
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# 이미지 편집 (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# 동영상 / 음악 생성 (제공자 접두사가 포함된 모델 ID)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **Provider 노드 재순위 지정:** `POST /v1/rerank`는 `<node-prefix>/<model>`로 지정된 OpenAI 호환 provider 노드(oMLX, vLLM, Infinity, 게이트웨이 뒤의 TEI 등)로도 라우팅됩니다. 루프백 노드(`localhost`, `127.0.0.1`, `172.16.0.0/12`)는 항상 사용 가능하며, 운영자가 `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS`에 나열한 호스트 이름(예: `http://reranker:8080/v1`과 같은 Docker/Compose 서비스 이름)도 사용 가능합니다. 이러한 노드는 직접 호출되며 `HTTP(S)_PROXY` 또는 연결에 고정된 프록시를 절대 거치지 않습니다. 다른 호스트(예: LAN 장치 또는 Tailscale 피어)의 노드는 운영자가 `RERANK_REMOTE_PROVIDER_NODES` 기능 플래그를 활성화하고 해당 노드의 기본 URL이 provider 아웃바운드 URL 정책(`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`)을 통과하는 경우에만 사용할 수 있습니다. 메모리 엔진의 재순위 지정 단계는 루프백을 통해 이 경로를 호출하므로, Memory 설정의 `rerankProviderModel`에도 동일한 규칙이 적용됩니다.
>
> **로컬 서버 형식:** 노드는 `<base>/v1/rerank`에서 호출되며, 404가 반환되면 `<base>/rerank`(Infinity, TEI)에서 호출됩니다. 업스트림 본문에는 Cohere/OpenAI 표기(`documents`, `return_documents`)와 TEI 표기(`texts`, `return_text`)가 모두 포함됩니다. 또한 업스트림 응답은 Cohere 엔벌로프로 정규화됩니다. TEI의 단순 `[{index, score, text}]`, 얇은 게이트웨이의 `{results: [{index, score}]}`, Voyage 형식의 `{data: [...]}`는 모두 클라이언트에 `{results: [{index, relevance_score, document?}]}` 형식으로 반환되며, 점수순으로 정렬되고 `top_n`으로 제한됩니다.

> **Provider 노드 검색:** OpenAI 호환 provider 노드의 모델은 노드 접두사 아래의 `GET /v1/models`에 표시됩니다. 엔드포인트 메타데이터가 없는 행(일반적인 로컬 `/v1/models` 목록의 경우)은 노드의 `apiType`을 상속합니다. 따라서 `embeddings` 노드의 모델은 기본적으로 chat으로 처리되지 않고 `type: "embedding"`으로, `rerank` 노드의 모델은 `type: "rerank"`으로 처리됩니다. 동기화되었거나 수동으로 추가된 행에 `supportedEndpoints`가 명시되어 있으면 해당 값이 계속 우선합니다.

### 전용 Provider 경로

```bash
POST /v1/providers/{provider}/embeddings
POST /v1/providers/{provider}/images/generations
```

Provider 접두사가 없으면 자동으로 추가됩니다. 일치하지 않는 모델은 `400`을 반환합니다.

## Files API

배치 입력/출력 및 파일 용도 업로드를 위한 OpenAI 호환 파일 엔드포인트입니다.

| Method | Path                     | Description                                                                                                 |
| ------ | ------------------------ | ----------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/files`              | 파일 업로드 (멀티파트: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — 최대 512 MiB |
| GET    | `/v1/files`              | 인증된 API 키의 파일 목록 조회                                                                              |
| GET    | `/v1/files/[id]`         | 파일 메타데이터 조회                                                                                        |
| DELETE | `/v1/files/[id]`         | 파일 삭제                                                                                                   |
| GET    | `/v1/files/[id]/content` | 원시 파일 본문 스트리밍                                                                                     |

**인증:** Bearer API 키 — 파일은 `getApiKeyRequestScope`를 통해 API 키별로 범위가 지정됩니다. 키는
자신의 파일만 조회, 다운로드 및 삭제할 수 있습니다. 키가 없는 대시보드 세션은
전체 인스턴스를 조회하며, 소유자가 없는 파일(익명 또는 대시보드 세션에서 업로드한 파일)은
세션이 아닌 모든 호출자에게 거부됩니다. `GET /v1/files`는 익명 호출자와 확인되지 않는 키가
제시된 호출자를 `REQUIRE_API_KEY=false`인 경우에도 `401`로 거부하며, 모든 테넌트의 파일을
나열하지 않습니다(GHSA-m3hp-hq9g-fpmv, GHSA-2jm2-mpx8-6523).

## Batches API

OpenAI 호환 배치 처리입니다.

| Method | Path                      | Description                                                                                          |
| ------ | ------------------------- | ---------------------------------------------------------------------------------------------------- |
| POST   | `/v1/batches`             | 배치 생성 — 본문은 `v1BatchCreateSchema`로 검증됨 (`input_file_id`, `endpoint`, `completion_window`) |
| GET    | `/v1/batches`             | 배치 목록 조회                                                                                       |
| GET    | `/v1/batches/[id]`        | 배치 상태 및 `request_counts` 조회                                                                   |

**인증:** Bearer API 키. 배치는 파일과 동일한 세 가지 규칙에 따라 API 키별로 범위가
지정됩니다. 즉, 자신의 키에 해당하는 항목만 허용되며, 대시보드 세션은 인스턴스 전체에
접근할 수 있고, 소유자가 null인 레코드는 세션이 아닌 모든 호출자에게 거부됩니다(조회, 삭제,
취소 및 생성 시 `input_file_id` 확인 포함). `GET /v1/batches`는 `REQUIRE_API_KEY=false`인
경우에도 익명 호출자를 `401`로 거부합니다.

## API 검색

Web/search 공급자 추상화(Tavily, Brave, Exa, Serper 등).

| 방법 | 길                     | 설명                                                                                  |
| ---- | ---------------------- | ------------------------------------------------------------------------------------- |
| GET  | `/v1/search`           | 구성된 검색 공급자 + 기능 나열                                                        |
| POST | `/v1/search`           | `v1SearchSchema` 로 검증된 — 본문 검색 쿼리를 실행하고 caching/coalescing 지원합니다. |
| GET  | `/v1/search/analytics` | 공급자별 hit/latency/cache 통계                                                       |

**인증:** 베어러 API 키(`extractApiKey` + `isValidApiKey`). `enforceApiKeyPolicy` 통해 시행되는 검색 정책.

**자동 선택:** `provider` 없으면 연결이 구성된 가장 저렴한 공급자가 먼저 실행되고 다음으로 가장 저렴한 공급자가 장애 조치입니다. 무료 최후의 수단 공급자(`duckduckgo-free`)는 아무것도 구성되지 않은 경우에만 사용됩니다. 자체 호스팅 SearXNG 연결이 실제 `baseUrl` (카탈로그 기본값 `http://localhost:8888/search` 아님)를 저장하면 구성된 것으로 계산됩니다. 그런 다음 SearXNG 400, 401, 403 또는 404로 응답하는 경우를 포함하여 가장 저렴한 키 공급자를 장애 조치로 사용하여 키 공급자보다 $0 공급자로 순위를 매깁니다. 유효한 `http(s)` URL 아니거나 클라우드 메타데이터 주소를 가리키는 `baseUrl` 는 계산되지 않습니다. 토큰을 저장하는 SearXNG 연결은 `https://` 또는 루프백 `http://` 에 대해서만 이러한 방식으로 순위를 매깁니다. 원격 일반 `http://` 에서는 결코 장애 조치가 아니며 최후의 수단으로 유지되며 다른 공급자가 구성되지 않거나 이름으로 요청될 때만 사용되므로 이 두 경우에 일반 텍스트로 토큰을 보냅니다.

### Exa 및 Tavily `provider_options`

Exa와 Tavily는 네임스페이스가 지정된 백에서 제공업체별 필드를 읽습니다:
`provider_options.exa`(또는 `provider_options["exa-search"]`) 및 `provider_options.tavily`
(또는 `provider_options["tavily-search"]`). 아래의 키만 전달됩니다. 각 키는
`open-sse/handlers/search/providerOptionsPassthrough.ts`의 자체 Zod 스키마에 대해
검사되며, 타입이 잘못된 키는 삭제됩니다. 인증, 기본 URL, `stream`, `outputSchema`를
포함한 그 외 모든 키는 무시됩니다. 다른 제공업체에서 사용하는 평면 키(`cx`, `depth` ...)
는 이전과 동일하게 작동합니다.

| Provider | Top-level fields                                                                                                                                                                                                                                                                                                                                                          | Nested                                                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Exa      | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (flat primitives), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                              | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}`가 기본값 `{ text: true, highlights: true }` 위에 병합됨 |
| Tavily   | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                     |

일반 필드는 항상 우선합니다: `query`, `max_results`, `filters`(도메인), `country`, 그리고
`search_type`에서 파생된 주제가 해당합니다. Exa에서는 `search_type: "news"`일 때
`category: "news"`가 유지됩니다. Tavily는 `search_type: "finance"`도 허용하며
(`topic: "finance"`), 이 경우 주제는 `"finance"`입니다.

Firecrawl 검색 비용은 반환된 결과 10개 단위로 시작된 블록마다 $0.002(2 크레딧)로
기록되며, 호출당 최소 한 블록이 적용됩니다
([Firecrawl billing](https://docs.firecrawl.dev/billing)): 결과 11개는 $0.004의 비용이 듭니다.

일반 `time_range`는 이제 두 제공업체 모두에 전달됩니다. Exa에는 `startPublishedDate`
(ISO 타임스탬프)로, Tavily에는 `start_date`(`YYYY-MM-DD`)로 전달됩니다.
`provider_options`에 날짜가 명시되어 있으면 매핑된 날짜보다 우선합니다.

Exa 결과는 `id`, `highlights`(`snippet`에 사용된 첫 번째 항목뿐 아니라 모든
하이라이트), `highlight_scores`, `summary`, `subpages`, `entities`, `extras`를
`provider_raw`에 유지합니다. Tavily 결과는 `images` 및 `favicon`을 유지합니다.

Linkup 검색 비용은 `depth`가 `fast` 및 `standard`일 때 $0.005, `deep`일 때 $0.05로
기록됩니다([Linkup pricing](https://docs.linkup.so/pages/documentation/development/pricing)).
`depth`가 `provider_options`에서 제공되었는지 연결 설정에서 제공되었는지와 관계없이
동일합니다.

Exa `type: "lite"`(Exa 3.0)는 더 적은 수의 필드를 허용하며, 다른 필드가 하나라도
설정되면 전체 요청을 거부합니다. lite의 경우 호출 전에 `additionalQueries`,
`systemPrompt`, 그리고 `contents`의 `text` 및 `highlights`를 제외한 모든 키가
삭제됩니다. 더 이상 사용되지 않는 `subpages`, `subpageTarget`,
`highlights.numSentences`, `highlights.highlightsPerUrl`은 더 이상 전달되지 않습니다.

Exa: `auto` (및 레거시 `fast`)의 경우 호출당 $0.007, `lite` (및 레거시 `instant`)의 경우 $0.004, 10개 결과 포함. 추가 결과당 $0.001; `contents.summary` 설정된 경우 반환된 결과당 $0.001입니다. Tavily는 `search_depth` `basic`, `fast` 및 `ultra-fast` 에 대해 1 크레딧($0.008), `advanced` ( [Tavily API 크레딧](https://docs.tavily.com/documentation/api-credits) )에 대해 2 크레딧($0.016)으로 기록됩니다. Tavily가 고급으로 업그레이드한 `auto_parameters: true` 사용한 통화는 여전히 1크레딧으로 기록됩니다.

## Web Fetch API

구성된 웹 가져오기 제공자(Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract)를 통해 URL에서 콘텐츠를 추출합니다.

Parallel Extract(`parallel-search`, Parallel Search와 동일한 API 키 사용)는 Markdown만 반환합니다. 다른 `format`은 모두 `400`이 되며, 콘텐츠는 100,000자로 제한됩니다. 대상 페이지 자체를 추출할 수 없는 경우 upstream은 이를 HTTP 200 내부에 보고하고, OmniRoute는 고정 메시지와 함께 이를 `422`로 표시합니다.

| Method | Path            | Description                                              |
| ------ | --------------- | -------------------------------------------------------- |
| POST   | `/v1/web/fetch` | URL 가져오기/스크랩 — 본문은 `v1WebFetchSchema`로 검증됨 |

**인증:** Bearer API 키(`extractApiKey` + `isValidApiKey`). 정책은 `enforceApiKeyPolicy`를 통해 적용됩니다.

**쿼터 인식 대체 처리 (#8297):** 명시적인 `provider`가 지정되지 않은 경우, 풀
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`)은 고정된
우선순위 순서로(선착순 방식) 순회됩니다. 요청 시 속도 제한 상태이지만 구성된 제공자는 요청을 중단하는 대신 건너뛰며, 재시도 가능한 upstream/쿼터 실패(HTTP 429는 항상 해당하며, Firecrawl/Tavily/TinyFish의 쿼터 방식 무료 티어에서는 402/403도 해당 — Jina Reader에는 해당하지 않고, 일반적인 잘못된 요청인 400에는 절대 해당하지 않음)는 요청 시 아직 시도하지 않은 인증된 다음 제공자로 전달됩니다. 풀의 모든 제공자가 소진되면 엔드포인트는 이전의 일반적인 `400` 대신 단일 `429`( `Retry-After` 헤더 포함)를 반환합니다. 명시적인 `provider`가 요청된 경우에는 자동 대체 처리가 없습니다. 속도 제한 또는 실패한 명시적 제공자는 자체 오류를 표시합니다(속도 제한이면 `429`, 그 외에는 upstream 상태 코드).

## WebSocket Streaming

```bash
GET /v1/ws?handshake=1
```

WebSocket 업그레이드 핸드셰이크를 검증하고 와이어 프로토콜 예시 메시지(`request`, `cancel`)를 반환합니다. 실제 WS 프레임은 Next.js 라우트 테이블 외부에서 번들된 WS 서버가 처리합니다.

**인증:** 핸드셰이크 중 Bearer API 키.

### Responses API over WebSocket (codex only)

```bash
# HTTP API와 동일한 호스트:포트(기본값 20128); 연결을 업그레이드합니다:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (또는: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# 첫 번째 프레임은 반드시 response.create여야 합니다:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Responses-API-over-WebSocket 프록시는 **`codex`에만** 독점적으로 연결됩니다(ChatGPT 백엔드). API/대시보드와 동일한 포트에서 경로 `/v1/responses`, `/responses`, `/api/v1/responses`를 수신합니다. 첫 번째 `response.create` 프레임에서 내부 `codex-responses-ws` 브리지를 통해 인증 및 준비를 수행하고, codex OAuth 연결을 선택한 뒤 `wreq-js` 전송을 통해 `wss://chatgpt.com/backend-api/codex/responses`로 터널링합니다. **codex가 아닌 모델은 거부됩니다**(`codex_ws_provider_required`). 쿼터 공유 라우팅을 사용하려면 `model: "qtSd/<group>/codex/<model>"`을 사용합니다. `app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`에 구현되어 있습니다.

**인증:** 핸드셰이크 중 Bearer API 키. 번들된 HTTP 서버(`server-ws.mjs`)가 활성 엔트리포인트여야 합니다(`app/server-ws.mjs`가 존재할 때 기본값).

#### Model id: use the bare ChatGPT id (no `codex/` prefix)

OpenAI **Codex CLI**는 `supports_websockets = true`인 경우 클라이언트 측에서 모델 이름을 검증하며, `codex/gpt-5.5`와 같은 제공자 접두사가 붙은 ID를 거부합니다(`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). 접두사가 없는 ID(예: `gpt-5.5`)를 전송합니다. OmniRoute의 브리지는 codex 전용이므로, HTTP를 통해서는 접두사가 없는 `gpt-5.5`가 다른 제공자로 라우팅되더라도 터널링 전에 접두사가 없는 ID를 codex 모델로 다시 확인합니다(`resolveCodexWsModelInfo`).

#### Configuring the OpenAI Codex CLI

WebSocket 지원이 포함된 사용자 지정 제공자를 `~/.codex/config.toml`에 추가하여 Codex CLI가 OmniRoute를 사용하도록 설정합니다(기존 구성에 영향을 주지 않도록 별도의 `CODEX_HOME`을 사용).

```toml
model = "gpt-5.5"                 # 접두사가 없는 ID — "codex/gpt-5.5"가 아님
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # 후행 슬래시 없음; WS URL은 여기서 파생됨(프로덕션에서는 https/wss 사용)
wire_api = "responses"                    # 2026년 2월 이후 지원되는 유일한 값
supports_websockets = true                # Responses-over-WS 전송을 활성화
env_key = "OMNIROUTE_API_KEY"             # OmniRoute API 키(Bearer)를 저장
```

```bash
export OMNIROUTE_API_KEY=sk-...           # OmniRoute API 키(REQUIRE_API_KEY=false인 경우 모든 키 사용 가능)
codex exec "Responda apenas: PONG"
```

CLI는 `base_url + /responses`를 WebSocket으로 업그레이드하고, OmniRoute는 이를 선택된 codex OAuth 연결로 터널링합니다. 로컬 서버에 대해 엔드투엔드 검증되었으며, ChatGPT는 `codex.rate_limits` + `response.created`를 반환하고 완료 응답을 스트리밍합니다.

## 할당량 및 문제 보고

| 방법 | 길                  | 설명                                                                                 |
| ---- | ------------------- | ------------------------------------------------------------------------------------ |
| GET  | `/v1/quotas/check`  | 등록된 키를 발급하기 전에 `provider` + `accountId` 에 대한 할당량을 사전 검증합니다. |
| POST | `/v1/issues/report` | quota/key 발급 실패를 GitHub 에 보고합니다( `GITHUB_ISSUES_REPO` + 토큰 필요)        |

**인증:** `/v1/quotas/check` Bearer API 키(`isAuthenticated`)를 사용합니다. `/v1/issues/report` 는 `/api/v1/registered-keys` 와 같이 관리 전용(`requireManagementAuth`)입니다. 대시보드 세션, 로컬 CLI 토큰 또는 `manage`/`admin` 범위가 있는 API 키입니다. 추론 전용 API 키는 `403` 얻습니다.

### 할당량 세션 복구 (선택 사항)

터미널 할당량 오류(`402`/`429`/`503`이며 본문에 할당량 또는 크레딧이 소진되었다고 표시됨)로
실패한 비스트리밍 `POST /v1/chat/completions` 또는 `POST /v1/responses` 요청은 오류를
반환하는 대신 보류한 후 나중에 재생할 수 있습니다. 호출자는 요청별로 다음 세 헤더를 사용하여
옵트인합니다.

| Header                       | Value                                  |
| ---------------------------- | -------------------------------------- |
| `x-omniroute-quota-recovery` | `auto`                                 |
| `x-omniroute-session`        | 세션 ID, `[A-Za-z0-9._:-]{1,128}`      |
| `x-omniroute-recovery-turn`  | 세션 내에서 고유한 턴 ID (동일한 규칙) |

`stream: false`이고 도구, 도구 기록 또는 `previous_response_id`가 없으며
`x-omniroute-connection` 고정이 없는 턴만 대상이 됩니다. 또한 `STORAGE_ENCRYPTION_KEY`가
설정되어 있어야 합니다(요청은 최대 24시간 동안 암호화된 상태로 저장됨). 이후 응답은
`202` 및 `recovery.poll`이 되며, 폴링은 `GET /v1/quota-recoveries/{id}`를 사용합니다
(대기 중에는 `202`, 완료되면 복구된 본문과 함께 `200`). 또는 `DELETE`로 취소할 수 있습니다.
티켓은 해당 티켓을 생성한 API 키에만 표시됩니다. 결과가 불확실한 재생은 두 번 전송되는 대신
`needs_confirmation` 상태로 종료됩니다. 출처: `src/lib/quota/quotaSessionRecovery.ts`.

## 셀프 서비스 사용(`/api/usage/om-usage`)

모든 API 키는 읽을 수 있습니다.**그 자체의** 사용량 및 할당량 — 관리 인증 없음. 이는 클라이언트(CLI, OmniCopilot 패널)가 키 보유자에게 지출 내역을 보여주기 위해 사용하는 엔드포인트입니다.

```bash
# Text form (the historical contract — plain text for a terminal)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Structured form — what a UI consumes
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

키에는 다음이 있어야 합니다.**`allowUsageCommand`** 활성화됩니다(기본적으로 꺼져 있는 — 대시보드의 API 키 관리자가 키별로 토글합니다). 이것이 없으면 엔드포인트는 `403` 응답합니다.

`?format=json` 식별된 모양을 반환하므로 발신자는 거부 시 데이터 필드를 읽지 않습니다. 성공 시:

```jsonc
{
  "allowed": true,
  // present only when the key opted into per-key usage limits (daily/weekly/5-hour USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // the selected provider quota snapshot, or null when nothing is cached yet:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // every connection's snapshot, so a UI can render several providers side by side:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

거부 시(`401` 잘못된 키/ `403` 허용되지 않음) 동일한 경로는 `{ "allowed": false, "error": { "message": "…" } }` — 반환하지만 존재하지만 비어 있는 `personal`/`provider` (키 허용됨, 아직 학습된 항목 없음)는 거부와 다른 상태이며 JSON 형식만 이를 구별합니다.

**인증:** `isValidApiKey` — 로 검증된 호출자 자신의 Bearer API 키는 `requireManagementAuth` 뒤에 있는 관리 표면(`/api/keys/…`)이 _아닙니다_.

### 원시 할당량 백분율과 기준선 조정 할당량 백분율

`/api/usage/om-usage`를 사용할 때 호출자는 **일반 텍스트 출력**과 구조화된
**JSON 출력**에 표시되는 백분율의 차이를 확인해야 합니다.

| Aspect            | 일반 텍스트 형식 (`/api/usage/om-usage` / `@@om-usage`)                               | JSON 형식 (`?format=json`)                                |
| :---------------- | :------------------------------------------------------------------------------------ | :-------------------------------------------------------- |
| **출력 필드**     | `NN% left` (예: `20% left`)                                                           | `provider.quotas` / `providers[].quotas`                  |
| **측정값**        | **기준선 조정 사용 가능 허용량**: 기준선 임계값을 초과하여 남은 용량                  | **원시 업스트림 할당량**: 조정되지 않은 제공자 측정값     |
| **기준선 조정**   | `effectiveRemainingPercent()`를 통해 조정되므로 보호된 예약 용량은 `0% left`로 표시됨 | 없음 (제공자가 보고한 원시 스냅샷 값)                     |
| **임계값 데이터** | 표시되는 백분율에 반영됨                                                              | 연결별 `quotaWindowThresholds`(또는 서버 기본값)에 저장됨 |
| **주요 소비자**   | 대화형 CLI, 터미널 프롬프트, 운영자                                                   | 프로그래밍 방식 통합, 대시보드, 분석, 결제 추적기         |

#### 기준선 조정 공식

OmniRoute는 업스트림 소진을 방지하기 위한 사전 예방적 할당량 기준선을 지원합니다(연결의
`quotaWindowThresholds`, 제공자 기본값 또는 전역 복원력 설정으로 구성). 할당량 윈도우에
기준선 임계값(예: `cutoff = 25%`)이 활성화되면 텍스트 렌더러는 다음과 같이 남은 허용량을
계산합니다.

- `remaining <= cutoff`인 경우: `0%`를 반환합니다.
- `remaining > cutoff`인 경우: `((remaining - cutoff) / (100 - cutoff)) * 100`을 반환합니다.

형식이 지정된 텍스트 출력은 이를 가장 가까운 정수로 반올림합니다(`Math.round(...)`).

#### 예시

제공업체 윈도우의 **원시 사용량이 60%**(따라서 **원시 잔여 할당량은 40%**)이고, 구성된
**잔여 할당량 컷오프** 임계값이 **25%**라고 가정합니다:

| 표현                           | 계산                                               | 잔여량  |            암시된 사용량            |
| :----------------------------- | :------------------------------------------------- | :-----: | :---------------------------------: |
| **원시 JSON (`?format=json`)** | 업스트림 스냅샷 (`quotas[window]`)                 | **40%** |               **60%**               |
| **텍스트 형식 (`NN% left`)**   | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (계산 시 `100 - remaining`) |

- **텍스트에 20%가 남은 것으로 표시되는 이유:** 계정에 물리적으로 남아 있는 할당량 40% 중 25%는
  컷오프 정책에 의해 예약됩니다. 라우터가 이 연결로의 라우팅을 중지하기 전까지 호출자가 사용할 수 있는
  여유 공간은 75% 중 15%뿐입니다. 이 스케일링을 적용하면 라우팅이 중단되는 시점에 연결이 정확히
  소진 상태(`0% left`)를 표시합니다.
- **JSON이 원시 값을 유지하는 이유:** JSON 페이로드는 정확한 제공업체 스냅샷(`UsageSnapshot`)을
  반환하므로, 외부 도구는 서버 측의 손실 스케일링 없이 실제 업스트림 사용량과 연결 수준의
  `quotaWindowThresholds`에 액세스할 수 있습니다.

#### 소비자 마이그레이션 지침

외부 통합(예: 편집기 플러그인 또는 에이전트 확장)이 이전에 텍스트 엔드포인트
(`NN% left`)를 스크랩하고 사용률을 `100 - NN`으로 계산했다면, `?format=json`으로 마이그레이션할 때:

- 원시 JSON 값을 읽으면 **실제 업스트림 사용량**(위 예시에서는 사용량 60%)이 반영됩니다.
- 통합에서 텍스트 엔드포인트의 사용 가능한 허용량 의미 체계를 유지하려는 경우, 연결 수준 오버라이드에
  `quotaWindowThresholds`를 사용하여 유효 잔여량 공식을 클라이언트 측에서 계산할 수 있습니다.

```bash
GET /api/cache/stats

# 모든 캐시 지우기
DELETE /api/cache/stats
```

```json
{

    "memoryMaxSize": 500,

  },

  }

```

### 지연 시간 영향

시맨틱 캐시의 **HIT**는 **업스트림 호출 없이** 캐시에서 응답을 제공하므로, 보고되는 `X-OmniRoute-Response-Latency`는 (원래 업스트림 지연 시간과 관계없이) 거의 0에 가깝습니다. 지연 시간에 민감한 클라이언트(벤치마킹, p50/p99 모니터링)는 `X-OmniRoute-Cache-Latency` 응답 헤더를 확인해야 합니다.

| 값          | 의미                                                                  |
| ----------- | --------------------------------------------------------------------- |
| `synthetic` | 캐시에서 제공된 응답입니다. 지연 시간은 실제 업스트림 시간이 아닙니다 |
| _(absent)_  | 실제 업스트림 호출의 응답입니다                                       |

### 키별 캐시 우회

API 키는 `cacheDefaultMode`를 통해 시맨틱 캐시 읽기를 선택적으로 비활성화할 수 있습니다.

| 값       | 동작                                             |
| -------- | ------------------------------------------------ |
| `legacy` | 일반적인 캐시 동작(기본값)                       |
| `bypass` | 캐시 조회를 완전히 건너뛰고 항상 업스트림에 도달 |

키 생성(`POST /api/keys`) 또는 업데이트(`PATCH /api/keys/[id]`) 시 설정합니다.

```json
{ "cacheDefaultMode": "bypass" }
```

### 요청별 우회

키 설정과 관계없이 모든 요청에서 캐시를 우회할 수 있습니다.

```
X-OmniRoute-No-Cache: true
```

## CLIProxyAPI 관리 호환성

OmniRoute는 사용량 대시보드가 Claude 및 Codex 구독 한도를 읽기 위해 호출하는 세 가지 [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) 관리 엔드포인트에 응답합니다(예: T3 Code의 `cliproxy` 사용량 제한 소스). 클라이언트의 기본 URL을 OmniRoute로 지정하고 `manage` 범위가 있는 API 키를 관리 키로 사용합니다. 경로는 `/v0/management/*` 및 `/api/v0/management/*`에서 제공됩니다.

| 메서드 | 경로                         | 설명                                                                                                                                         |
| ------ | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/v0/management/auth-files`  | `{ files: [{ id, auth_index, provider, email, disabled, id_token }] }` 형식의 Claude 및 Codex OAuth 연결입니다. 토큰은 포함되지 않습니다     |
| POST   | `/v0/management/api-call`    | 본문 `{ auth_index, method, url, header?, data? }`. 계정의 토큰으로 허용 목록에 있는 요청 하나를 보내고 `{ status_code, body }`를 반환합니다 |
| POST   | `/v0/management/reset-quota` | 본문 `{ auth_index }`. 한 계정의 연결 쿨다운, 모델 잠금 및 Codex 범위별 쿨다운을 지웁니다                                                    |

- `auth_index`는 OmniRoute 연결 ID입니다. `provider`는 `claude` 또는 `codex`입니다(OAuth 연결만 포함하며, API 키 제공자 `anthropic`는 나열하지 않음). Codex에서 `id_token.chatgpt_account_id`는 저장된 워크스페이스 ID이며 `plan_type`는 저장된 요금제입니다.
- `api-call`는 범용 프록시가 아닙니다. Claude `GET
https://api.anthropic.com/api/oauth/usage`와 Codex `GET
https://chatgpt.com/backend-api/wham/usage`, `GET .../wham/rate-limit-reset-credits`, `POST .../wham/rate-limit-reset-credits/consume`만 허용하며 각각 해당 제공자의 계정에서만 사용할 수 있습니다. 그 외에는 업스트림에 연결하지 않고 `403`를 반환합니다. 호출자의 `Authorization` 헤더(`$TOKEN$` 자리표시자 포함)는 무시됩니다. OmniRoute는 연결의 액세스 토큰을 삽입하며, 만료가 가까우면 먼저 갱신합니다. 전달하는 헤더는 허용 목록에 있는 것뿐입니다(`anthropic-beta`; `OpenAI-Beta`, `Originator`, `Chatgpt-Account-Id`; `Accept`, `Content-Type`). `Chatgpt-Account-Id`가 없으면 저장된 워크스페이스 ID를 기본값으로 사용합니다. 첫 업스트림 응답이 `401`이면 한 번 갱신한 뒤 액세스 토큰이 바뀐 경우에만 다시 시도합니다. 업스트림의 각 시도는 15초 후 시간 초과되며 연결의 프록시를 사용합니다.
- `reset-quota`는 최종 상태(banned, expired, credits_exhausted)를 그대로 둡니다. 알 수 없는 `auth_index`는 `404`를 반환합니다.

**인증:** 로그인 세션 또는 `manage` 범위의 API 키가 필요하며, 로그인 기능이 비활성화된 경우에도 필수입니다(경로가 `ALWAYS_PROTECTED_API_PATHS`에 포함되어 있습니다). 추론 전용 키는 `403`을 반환합니다. 소스:
`src/lib/cliproxyCompat/managementApi.ts`.

| ----------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/api/auth/login`             | POST     | 로그인                                                                                                                                                                                                                                                                         |
| `/api/auth/logout`            | POST     | 로그아웃                                                                                                                                                                                                                                                                       |
| `/api/settings/require-login` | GET/POST | 로그인 상태(GET은 공개). POST는 비밀번호를 설정하거나 로그인을 전환합니다. 비밀번호가 존재하면 운영자 전용입니다(대시보드 세션, 로컬 CLI 또는 로그인 비활성화 상태 — API 키와 `oma_` 토큰은 `403`을 받음). 대시보드 세션은 비밀번호를 변경할 때 `currentPassword`를 전송합니다 |

| 엔드포인트                              | 메서드                    | 설명                                                                                                                                       |
| --------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |

| `/api/providers/[id]/models`            | GET                       | 공급자 모델 목록 조회                                                                                                                      |
| `/api/providers/validate`               | POST                      | 공급자 구성 검증                                                                                                                           |
| `/api/providers/bulk`                   | POST                      | 하나의 공급자에 대한 API 키 일괄 추가                                                                                                      |
| `/api/providers/import`                 | POST                      | 구문 분석된 CSV/JSON 파일에서 서로 다른 공급자 목록 가져오기(#6836); 행별 부분 실패 결과 제공                                              |
| `/api/provider-nodes*`                  | 다양함                    | 공급자 노드 관리                                                                                                                           |
| `/api/provider-models`                  | GET/POST/PUT/PATCH/DELETE | 사용자 지정 모델 및 모델별 재정의(추가, 업데이트, 숨기기/표시, 삭제)                                                                       |
| `/api/provider-models/validate-and-add` | POST                      | 관리 인증을 기반으로 선택적으로 수행하는 엄격한 연결 검증 및 원자적 사용자 지정 모델 등록. [모델 검증](../guides/MODEL-VALIDATION.md) 참조 |

동기화되거나 가져온 모델의 경우 `PUT /api/provider-models`는 `provider`, `modelId` 및
`maxOutputTokenOverride`를 허용합니다. 양의 정수는 수동 출력 토큰 상한을 설정하고, `null`은
기본값으로 복원하도록 상한을 해제합니다. `GET /api/provider-models?provider=<provider>`는 사용자 지정 모델 행이 없는 모델을 포함하여 이러한 값을 `modelOutputOverrides`로 반환합니다. 이 재정의는 런타임 `max_output_tokens` 기능을 사용하며 모델을 다시 동기화한 후에도 유지됩니다. OpenAI 호환
공급자 페이지에서도 동일한 편집/해제 컨트롤을 제공하며, 명시적인 비전 지원이 있는 모델을 표시합니다.

호환 가능한 공급자 노드에서 쓰기 경로(`POST`, `PUT`, `PATCH`, `DELETE` 및
`/api/provider-models/validate-and-add`)는 모델 ID를 기본 업스트림 ID로 저장합니다. 접두사가 붙은 목록에서 붙여넣은 ID의 경우 노드 자체 접두사의 앞쪽 연속 부분이 하나로 축약되며,
응답에는 저장된 ID가 그대로 반환됩니다. 정식 공급자의 슬래시가 포함된 ID(예: `nvidia/nemotron-…`)는
있는 그대로 저장됩니다. `/v1/models`는 중복된 `<prefix>/<prefix>/<model>` ID를 출력하지 않습니다.

사용자 지정 Chat Completions 노드는 명시적인 추론 옵트아웃을 업스트림 백엔드에 맞게 조정합니다. 성공적인 연결 테스트는 `/models` 항목에서 인식된 `owned_by` 값인 `vllm`, `sglang` 또는 `llamacpp` 중 하나를 확인한 각 정확한 모델 ID에 대해 채팅 템플릿 제어를 자동으로 선택합니다. 투명한 OpenAI 호환 래퍼는 중첩된 `openai` 객체 내부에 원래 모델 항목을 보존할 수 있으며, 감지는 이러한 봉투를 최대 3개까지 따릅니다. 소유 정보가 없거나, 알 수 없거나, 서로 충돌하는 모델은 일반적인 OpenAI 동작을 유지합니다. 감지는 기존 카탈로그 요청을 재사용하고 완료 토큰을 생성하지 않으며, 연결 엔드포인트가 변경되면 무효화됩니다.

해당 메타데이터를 노출하지 않는 백엔드에 동작을 고정하려면 기존 부분 제공자 업데이트 API를 사용합니다:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

해당 본문을 `PUT /api/providers/<connection-id>`와 함께 전송합니다. 해당 연결에서는 명시적인 추론 수준 `none`이 `chat_template_kwargs.thinking=false` 및 `chat_template_kwargs.enable_thinking=false`로 전송됩니다. 명시적인 네이티브 템플릿 값은 서버 측 추론 규칙이 추론 수준을 강제하지 않는 한 계속 우선합니다. 이 설정은 사용자 지정 OpenAI 호환 연결이 Chat Completions 본문을 디스패치하는 경우에만 적용되며, Responses 요청과 일반 제공자는 네이티브 요청 형식을 유지합니다. 일반적인 OpenAI `reasoning_effort` 패스스루를 강제하려면 `reasoningControl`을 `openai`로 설정하고, 자동 감지를 사용하려면 생략하거나 `null`로 설정합니다.

Claude Code 자동 모드 분류기 요청은 명시적인 추론 제어가 포함되지 않은 경우 기본적으로 네이티브 사고 기능을 비활성화합니다. 감지는 모델 이름이나 완료 제한이 아니라 Claude 형식 요청의 분류기 시스템 마커를 사용합니다. 명시적인 본문 제어, 지원되는 effort/thinking 헤더, 라우팅 규칙 및 확인된 모델 effort는 기존 우선순위를 유지합니다. 두 분류기 단계 모두 프롬프트, 완료 제한, 중지 시퀀스 및 실제 업스트림 권한 판정을 유지하며, 두 번째 단계는 요청된 표시 추론을 일반 텍스트로 계속 생성할 수 있습니다.

#### 모델 제한 출처

`GET /api/models?withLimits=1` (또한 `true`; `0`/`false` 또는 생략하면 기본 페이로드가 변경되지 않음)은 모든 모델 행에 `contextWindow`, `maxInputTokens`, `maxOutputTokens` 및 `capsSource` 객체를 추가합니다. `capsSource`는 각 제한을 제공한 규칙을 나타내므로, 예상치 못한 제한(예: 1M 모델에 적용된 128k)을 그 출처까지 추적할 수 있습니다. 확인된 값은 라우팅에서 사용하는 값과 동일하며, 이 플래그는 필드만 추가하고 값을 변경하지 않습니다. 그 외의 `withLimits` 값은 `400`으로 거부됩니다.

| `capsSource` value                           | Origin                                                           |
| -------------------------------------------- | ---------------------------------------------------------------- |
| `override:context`                           | 영구 저장된 컨텍스트 윈도우 재정의 (`model_context_overrides`)   |
| `override:max_input` / `override:max_output` | 영구 저장된 `max_input_tokens` / `max_output_tokens` 기능 재정의 |
| `static-authoritative:<provider>/<model>`    | 정적 권위 컨텍스트 윈도우 테이블                                 |
| `synced:<provider>/<model>`                  | models.dev에서 동기화된 기능 행                                  |

### 비디오 프레임 드릴다운

`GET /api/v1/video-bridge/drilldown` 명시적으로 동의된 Video Bridge 요청 후 `x-omniroute-video-drilldown` 에 반환된 테넌트 바인딩 불투명 핸들을 읽습니다. 읽기와 `DELETE` 모두 항상 유효한 API 키와 운영자의 독립적인 `modalityBridgeVideoDrilldownRemoteEnabled` 권한이 필요합니다. 생산 유지에는 추가로 `modalityBridgeVideoDrilldownEnabled` 및 엄격한 부품별 `drilldown: true` 필요합니다. 키에 비어 있지 않은 엔드포인트 허용 목록이 있는 경우 호출자가 `/v1` 또는 `/api/v1` 사용하는지 여부에 관계없이 GET 및 DELETE 모두에 대해 `video` 포함해야 합니다.

GET 쿼리: 필수 `handle`; 선택적 `variant` (`preview`, `standard`, `detail`), `limit` (1–8; 레거시 `frames` 는 허용되지만 `limit` 와 결합될 수 없음), 0부터 시작하는 `page` 및 `start`/`end` 초. 두 포커스 범위가 모두 제공되면 `end` `start` 보다 커야 합니다. Duplicate/unknown 쿼리 키가 거부됩니다. 성공적인 응답에는 `derivation`, `durationSeconds`, `frames`, `hasMore`, `page`, `variant` 및 선택적 `focusWindow` 포함됩니다. 무점포 JSON 는 Base64를 포함하여 32 MiB 로 제한됩니다. 대형 출력은 413을 반환합니다. 더 적은 수의 프레임을 요청하세요.

`DELETE /api/v1/video-bridge/drilldown?handle=...` `{ "removed": 0|1 }` 반환합니다. 알 수 없음, 만료됨 및 크로스 키 GETs 는 구별할 수 없는 404 응답입니다. 크로스 키 DELETE 소유자 항목을 제거할 수 없습니다. 비활성화된 액세스는 403, missing/invalid 인증 401, 잘못된 쿼리 400, 취소 499 및 임시 오류 503을 반환합니다. 핸들은 프로세스 로컬이며 10분 후에 만료되며 다시 시작해도 유지되지 않습니다. 새로운 핸들은 `v1.` 와 32바이트 임의 Base64URL 토큰을 사용합니다. 토큰 해시만 유지됩니다. 레거시 64-16진수 토큰은 호환성을 위해 구문적으로 읽을 수 있는 상태로 유지됩니다. 동의, 할당량 및 변형 파생 세부 정보는 [Video Bridge 가드레일을](../security/GUARDRAILS.md#video-bridge-videobridgets-videobridgepipelinets) 참조하세요.

### 버전 및 릴리스 채널

```bash
GET /api/system/version
```

루프백 전용 관리 라우트(admin auth)입니다. 실행 중인 버전, 최신
게시 버전 및 자동 업데이트 상태를 반환합니다. `releaseChannel` 및 `channels`는 추가된
필드(rail 3.8.54)이며, `channel`은 대시보드 업데이터가 사용하는 배포 모드
(`npm`, `source` 또는 `docker-compose`)라는 기존 의미를 유지합니다.

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — 실행 중인 빌드의 npm 채널입니다. `-nightly.*` 버전에는 `nightly`를,
  기타 프리릴리스(`-rc.*`, `-beta.*`, `-alpha.*`)에는 `next`를, `channels.latest`보다
  이전 메이저 버전의 안정 버전에는 `lts`를 사용하며, 그 외에는 `latest`를 사용합니다.
  게시 시 npm dist-tag를 선택하는 `scripts/release/dist-tag.mjs`와 동일한 규칙입니다.
- `channels` — `npm view omniroute dist-tags`(레지스트리 HTTP 폴백)의 각 dist-tag에
  게시된 최신 버전입니다. `latest`와 동일한 10분 TTL로 캐시됩니다. `latest`는 항상
  존재하며(`latest` 필드로 폴백한 후 `"unavailable"`로 폴백), `next`, `nightly` 및
  `lts`는 해당 dist-tag가 존재할 때만 표시됩니다. `Cache-Control: no-cache` 요청은 두
  조회를 모두 새로 고칩니다.

채널 모델(`latest` = 4.0 GA 전까지의 v3, `next` = rc, `nightly` = `develop` 빌드,
`lts` = 4.0 GA 이후의 v3 패치)은 `docs/ops/RELEASE_STRATEGY.md`에 설명되어 있습니다.

## 오디오 전사

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data
```

구성된 STT 제공업체를 사용하여 오디오 파일을 전사합니다. 첫 번째 경로
세그먼트는 네이티브 제공업체(`openai/…`, `deepgram/…`)를 선택합니다. 다른
벤더의 모델을 다시 내보내는 게이트웨이는 정규화된 ID를 사용합니다
(`openrouter/deepgram/nova-3`).

**요청:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**응답:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**모델 ID 예시:** `openai/whisper-1` (OpenAI 키 필요),
`openrouter/deepgram/nova-3` (OpenRouter 키 필요),
`deepgram/nova-3` (네이티브 Deepgram 키 필요). 단독으로 사용하는
`deepgram/nova-3` 요청은 OpenRouter를 사용하지 않습니다.

**지원 형식:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`.

**Gemini Live (`gemini/gemini-3.5-transcribe-live`):** Gemini Live
WebSocket을 통한 파일 모드 전사입니다(Gemini API 키 필요). 업로드된 파일은 `ffmpeg`를 사용하여
16 kHz 모노 PCM으로 변환됩니다(`PATH`에 있어야 하며, 파일이 이미 16 kHz 모노 PCM WAV인 경우는
예외). 변환된 파일은 세션으로 스트리밍되고 최종 텍스트는 `{ "text": "..." }`로 반환됩니다. 선택적
`language` 및 `prompt` 양식 필드는 그대로 전달됩니다. 제한 사항: 25 MiB를 초과하는 업로드 또는
디코딩된 오디오가 10분을 초과하는 경우 `413`이 반환됩니다. 변환이 60초보다 오래 실행되면
프로세스가 종료되고 `504`가 반환됩니다. API 키는 `x-goog-api-key` 헤더로만 전송되며 WebSocket URL에는
절대 포함되지 않습니다.

## 토큰화된 VS Code / 헤더 없는 별칭

통합 환경에서 `Authorization` 헤더를 주입할 수 없고 API 키를 기본 URL에 포함해야 하는 경우 이러한 별칭을 사용합니다.

```bash
# OpenAI 스타일 카탈로그 별칭
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# OpenAI 스타일 채팅 별칭
POST /api/v1/vscode/{token}/chat/completions
POST /api/v1/vscode/{token}/responses

# Ollama 스타일 별칭
POST /api/v1/vscode/{token}/api/chat
GET /api/v1/vscode/{token}/api/tags
```

예시:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'
```

참고:

- 토큰화된 별칭은 `/v1/*` 및 `/api/tags`와 동일한 핸들러를 재사용하며, 응답 형태는 동일하게 유지됩니다.
- 클라이언트가 사용자 지정 헤더를 지원하는 경우 항상 `Authorization: Bearer ...`를 우선 사용하세요.
- URL 기반 토큰은 OmniRoute 외부의 리버스 프록시 로그, 브라우저 기록 및 원격 측정 데이터에 나타날 수 있습니다. 이를 기본 인증 방식이 아닌 호환성 옵션으로 취급하세요.

```bash
# 모든 API 키의 예산 상태 가져오기
GET /api/usage/budget

# 예산 설정 또는 업데이트
POST /api/usage/budget
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "dailyLimitUsd": 5.00,
  "weeklyLimitUsd": 30.00,
  "monthlyLimitUsd": 100.00,
  "warningThreshold": 0.8,
  "resetInterval": "monthly"
}
```

> **스키마 참고** (`setBudgetSchema`): `apiKeyId`는 필수이며, `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd` 중 하나 이상이 0보다 커야 합니다. 선택적 필드: `warningThreshold` (0–1), `resetInterval` (`daily` | `weekly` | `monthly`), `resetTime` (`HH:MM`). 기존 `{keyId, limit, period}` 형식은 `400 Bad Request`를 반환합니다.

## 토큰 제한

API 키별 **토큰** 예산(위의 USD 기반 예산과는 별개)입니다. 요청 경로에서 인라인으로 적용됩니다. 키의 현재 윈도우 사용량이 한도에 도달하면 `429 Too Many Requests`와 함께 요청이 거부됩니다. 한도는 특정 `model`, `provider`로 범위를 지정하거나 키 전체에 걸쳐 `global`로 적용할 수 있습니다. 여러 한도가 요청과 일치하는 경우 가장 제한적인 한도가 적용됩니다.

```bash
# 키의 토큰 한도 나열(실시간 윈도우 사용량 포함)
GET /api/usage/token-limits?apiKeyId=key-123

# 토큰 한도 생성 또는 업데이트
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# ID로 토큰 한도 삭제
DELETE /api/usage/token-limits?id=tl-abc
```

> **스키마 참고** (`setTokenLimitSchema`): `apiKeyId` 및 `scopeType`(`model` | `provider` | `global`)은 필수입니다. `scopeType`이 `global`이 아닌 경우 `scopeValue`가 필요합니다(`model` 범위에서는 모델 ID, `provider` 범위에서는 프로바이더 ID 등). `tokenLimit`은 양의 정수여야 합니다(문자열에서 강제 변환됨). 선택 사항: `id`(생성 시 생략, 업데이트 시 제공), `resetInterval`(`daily` | `weekly` | `monthly`, 기본값 `monthly`), `resetTime`(`HH:MM`), `enabled`(기본값 `true`). `GET` 응답은 각 한도에 `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, `nextResetAt`을 추가합니다. 이 엔드포인트는 관리 클래스 엔드포인트입니다(인증은 authz 파이프라인에서 중앙적으로 적용됨).

## 요청 처리

1. 클라이언트가 `/v1/*`로 요청을 전송합니다.
2. 라우트 핸들러가 `handleChat`, `handleEmbedding`, `handleAudioTranscription` 또는 `handleImageGeneration`을 호출합니다.
3. 모델이 확인됩니다(직접 프로바이더/모델 또는 별칭/콤보).
4. 계정 가용성 필터링을 사용하여 로컬 DB에서 자격 증명을 선택합니다.
5. 채팅의 경우 `handleChatCore`가 의미/서명 캐시를 확인하고 콤보 압축 설정을 확인합니다.
6. 활성화된 경우 프로바이더 변환 전에 사전 예방적 압축이 실행됩니다(`lite`, Caveman, RTK 또는 스택 방식).
7. 프로바이더 실행기가 업스트림 요청을 전송합니다.
8. 응답이 클라이언트 형식으로 다시 변환되거나(채팅), 있는 그대로 반환됩니다(임베딩/이미지/오디오).
9. 사용량, 압축 분석 및 요청 로그가 기록됩니다.
10. 콤보 규칙에 따라 오류 발생 시 폴백이 적용됩니다.

전체 아키텍처 참조: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## 복원력 (확장)

OmniRoute는 서로 독립적인 세 가지 임시 실패 메커니즘을 제공합니다. 아래 관리 엔드포인트를 통해 운영자는 해당 메커니즘을 조회하고 재정의할 수 있습니다.

| 범위            | 상태 저장소                           | 조회                                      | 재설정 / 삭제                                         |
| --------------- | ------------------------------------- | ----------------------------------------- | ----------------------------------------------------- |
| 제공자 브레이커 | `domain_circuit_breakers` + 메모리 내 | `/api/monitoring/health`                  | `POST /api/resilience/reset`                          |
| 연결 쿨다운     | 제공자 연결의 `rateLimitedUntil`      | `/api/rate-limits`, `/api/providers/[id]` | (지연 방식으로 다시 활성화됨; 제공자 PUT을 통해 삭제) |
| 모델 잠금       | 메모리 내 모델 가용성 레지스트리      | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`              |

`PATCH /api/resilience`는 `providerBreaker.oauth` 및 `providerBreaker.apikey` 아래에서 제공자 브레이커 재정의를 허용합니다. 각 프로필은 `degradationThreshold`, `failureThreshold`, `resetTimeoutMs`를 지원하며, 동일한 필드는 Dashboard → Settings → Resilience에도 노출됩니다.

```bash
# 단일 모델 잠금 삭제
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# 모든 잠금 삭제
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

전체 개념 참조 및 브레이커 기본값은 [`CLAUDE.md`](../../CLAUDE.md) → "복원력 런타임 상태" 및 [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md)를 참조하세요.

### 속도 제한 큐 및 자동 활성화 안전망

- **지원되는 쓰기 경로**: `POST /api/rate-limits`에 본문 `{"connectionId": "<id>", "enabled": true|false}`를 전달하는 방식이 연결에 대한 속도 제한 보호를 전환하는 지원 관리 엔드포인트입니다. `PUT /api/providers/[id]`는 의도적으로 `rateLimitProtection`을 수정하거나 전환하지 않습니다(#11278).
- **`enabled: false`의 의미**: `enabled: false`로 설정하면 연결에 대한 명시적 보호가 제거되지만, 활성 API 키 연결이 전역 자동 활성화 안전망(`autoEnableApiKeyProviders = true`)에서 제외되지는 **않습니다**. `reconcileEnabledConnections`(`open-sse/services/rateLimitManager.ts`)에서는 `false`와 `undefined`가 동일하게 처리됩니다. 명시적 보호가 없는 활성 API 키 연결은 자동 활성화 안전망에 따라 계속 보호됩니다.
- **전역 비활성화**: 속도 제한 큐 없이 API 키 연결을 실행하려면 `RATE_LIMIT_AUTO_ENABLE=false`(env)를 설정하거나 `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false`(Settings → Resilience / `PATCH /api/resilience`)로 전역 안전망을 비활성화하세요.

## MCP 서버

OmniRoute는 3개의 전송 방식(stdio, SSE, streamable-http)과 범위가 지정된 도구를 지원하는 내장 Model Context Protocol 서버를 제공합니다. 아래 대시보드 엔드포인트는 상태/감사 데이터를 읽고 HTTP 전송을 프록시합니다.

| Method | Path                   | Description                                                                                                             |
| ------ | ---------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/mcp/status`      | 하트비트, 전송 방식, 온라인 상태, 마지막 호출, 주요 도구, 24시간 성공률                                                 |
| GET    | `/api/mcp/tools`       | `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints`를 포함하는 MCP 도구 목록                      |
| GET    | `/api/mcp/sse`         | SSE 전송을 위한 SSE 스트림 열기(MCP가 비활성화되었거나 전송 방식이 일치하지 않으면 `503` 반환)                          |
| POST   | `/api/mcp/sse`         | SSE 전송에서 JSON-RPC 프레임 전송                                                                                       |
| GET    | `/api/mcp/stream`      | Streamable HTTP 전송의 SSE 측면 열기(서버가 시작한 메시지)                                                              |
| POST   | `/api/mcp/stream`      | Streamable HTTP 전송에서 JSON-RPC 프레임 전송                                                                           |
| DELETE | `/api/mcp/stream`      | Streamable HTTP 세션 종료                                                                                               |
| GET    | `/api/mcp/audit`       | 감사 로그 쿼리 — `?limit=`, `?offset=`, `?tool=`, `?success=true                                \| false`, `?apiKeyId=` |
| GET    | `/api/mcp/audit/stats` | 집계된 감사 통계(총계, 성공률, 평균 기간, 주요 도구)                                                                    |

**인증:** `sse`/`stream` 전송은 MCP 전용 인증 영역(`mcp` 범위가 포함된 Bearer API 키)을 따릅니다. `status`/`tools`/`audit*` 경로는 대시보드에서 읽을 수 있습니다(대시보드 호스트에 접근하는 것 외에 추가 인증 필요 없음).

> 두 HTTP 전송 방식은 `settings.mcpEnabled` 및 `settings.mcpTransport`에 의해 제한됩니다 — 전송 방식이 일치하지 않으면 `400`, MCP가 비활성화된 상태이면 `503`을 반환합니다.

## A2A 서버

OmniRoute는 검사/대시보드 용도를 위한 A2A(에이전트 간) JSON-RPC 2.0 엔드포인트와 REST 래퍼를 제공합니다.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # OMNIROUTE_API_KEY가 설정된 경우를 제외하면 선택 사항
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "이 코딩 작업을 라우팅하세요"}]
  }
}
```

지원되는 메서드(`settings.a2aEnabled`가 활성화된 경우에만 사용 가능):

| Method           | Description                                          |
| ---------------- | ---------------------------------------------------- |
| `message/send`   | 동기식 스킬 실행; `{task, artifacts, metadata}` 반환 |
| `message/stream` | 동일한 스킬 세트의 스트리밍 SSE 실행                 |
| `tasks/get`      | `taskId`로 작업 가져오기                             |
| `tasks/cancel`   | `taskId`로 작업 취소                                 |

기본 제공 스킬: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### 에이전트 카드

```bash
GET /.well-known/agent.json
```

공개 A2A 에이전트 카드(이름, 설명, 기능, 스킬 카탈로그, 인증 체계)를 반환하며, 1시간 동안 공개적으로 캐시됩니다. 인증이 필요하지 않습니다.

### REST 헬퍼

| Method | Path                         | Description                                                                                                    |
| ------ | ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | A2A 활성화 여부 + 작업 통계 + 캐시된 에이전트 카드 요약                                                        |
| GET    | `/api/a2a/tasks`             | 작업 목록 — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (REST 헬퍼로는 구현되지 않음 — JSON-RPC `message/send`를 통해 생성)                                            |
| GET    | `/api/a2a/tasks/[id]`        | 작업 하나 가져오기                                                                                             |
| POST   | `/api/a2a/tasks/[id]/cancel` | 작업 취소                                                                                                      |

**인증:** REST 헬퍼는 관리 인증 없이 실행되며(대시보드에서 읽을 수 있음), JSON-RPC `/a2a` 라우트는 구성된 경우 Bearer `OMNIROUTE_API_KEY`를 사용합니다.

## 가드레일

런타임 가드레일(개인 식별 정보(PII) 감지, 프롬프트 인젝션 감지, 비전 브리징)을 검사합니다. 가드레일은 모든 요청에서 실행되며, 호출별 비활성화는 `x-omniroute-disabled-guardrails` 요청 헤더를 통해 수행합니다. 저장되는 활성화/비활성화 인터페이스는 없습니다.

| Method | Path                   | Description                                                                            |
| ------ | ---------------------- | -------------------------------------------------------------------------------------- |
| GET    | `/api/guardrails`      | 등록된 가드레일 및 상태(이름 / 활성화 여부 / 우선순위) 목록                            |
| POST   | `/api/guardrails/test` | 샘플 입력에 대해 호출 전 파이프라인을 시험 실행 — 본문: `{input, disabledGuardrails?}` |

자세한 내용은 [보안 > 가드레일](../security/GUARDRAILS.md)을 참조하세요.

## 인증

네 가지 자격 증명 계열(대시보드 세션, 로컬 CLI 토큰, `oma_live_…` 액세스 토큰, 관리 범위 API 키)과 이들이 추론 키와 어떻게 다른지는 [관리 인증](../guides/MANAGEMENT-AUTH.md)을 참조하세요.

- 대시보드 라우트(`/dashboard/*`)는 `auth_token` 쿠키를 사용합니다.
- 로그인에는 저장된 비밀번호 해시가 사용되며, 없으면 `INITIAL_PASSWORD`를 사용합니다.
- `/api/settings/require-login`을 통해 `requireLogin`을 전환할 수 있습니다.
- `/v1/*` 라우트는 `REQUIRE_API_KEY=true`인 경우 Bearer API 키를 요구할 수 있습니다.
- 이 참조에서 "관리 토큰" / "관리 범위 API 키"는 해당 가이드에 설명된 계열 중 하나를 의미하며, 정의되지 않은 추가 비밀 유형을 의미하지 않습니다.

> **호환성이 깨지는 변경 사항(v3.8.0)** — 이제 `/api/v1/agents/tasks/*` 및 쿨다운 관리 엔드포인트에는 **관리 인증**(대시보드 `auth_token` 쿠키 또는 관리 범위 API 키)이 필요합니다. 이전에 이러한 라우트를 인증 없이 호출하던 클라이언트는 `401 Unauthorized`를 수신합니다. 커밋 `588a0333`(`fix(auth): require management auth for agent and cooldown APIs`)을 참조하세요.
