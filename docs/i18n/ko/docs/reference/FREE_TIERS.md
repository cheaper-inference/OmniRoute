## TL;DR — OmniRoute가 실제로 통합하는 무료 추론량은 얼마인가요?

이 수치들은 카탈로그 전반의 서로 독립된 서드파티 계정과 자격 조건을 나타냅니다. OmniRoute 자체가 이 예산을 제공하는 것은 아닙니다. 필요한 계정 또는 자격 증명을 확보하고, 자격을 갖춘 제공업체를 연결하며, 각 제공업체의 제한을 준수해야 합니다. 적격 경로가 없는 새 설치 환경에서는 용량이 0일 수 있는 등 실제 사용 가능한 용량은 더 적을 수 있습니다. `tos: avoid`로 표시된 제공업체는 기본적으로 자동 라우팅에서 제외됩니다.

**2026-10-08 확인:** [Cerebras](https://www.cerebras.ai/pricing)는 결제 수단 등록이 필요하며 30일 후 만료되는 일회성 $5 프로모션 크레딧을 제공합니다. [Gemini](https://ai.google.dev/gemini-api/docs/rate-limits)는 프로젝트/모델/티어별 속도 제한을 공개하지만, 정량화된 월간 주요 수치에는 계속 포함되지 않습니다.

**정직한 주요 수치:** _OmniRoute는 34개의 무료 티어 풀에서 **월간 약 1.62B개의 문서화된 무료 토큰**을 통합하며(가입 크레딧을 포함하면 첫 달에는 최대 약 2.22B), 여기에 영구 무료이면서 한도가 없는 여러 제공업체가 추가됩니다. 또한 RTK + Caveman 압축(토큰 15–95% 절감)을 통해 이를 더욱 효율적으로 활용할 수 있습니다._

> **이 수치가 이전의 약 1.94B에서 감소한 이유.** 2026-06-17 갱신은 손실이 아니라 정직성을 위한 수정입니다. 이제 `gemini`는 풀 기준으로 중복 제거되며(이전에는 각 Flash 변형을 별도로 계산해 462M → 60M으로 부풀려짐), `cloudflare-ai`는 실제 한도인 일일 10k-Neurons에 맞게 수정되었고(122M → 30M), `doubao`는 반복 제공이 아닌 일회성 가입 크레딧으로 재분류되었으며, 종료된 티어(`chutes`/`phind`/`kluster` 중단)는 제거되었습니다. 이는 `llm7`의 수정(정확한 일일 5M → 150M)과 새로운 무료 제공업체(Kilo, OpenCode Zen, Z.AI GLM-Flash)의 추가로 일부 상쇄되었습니다.
>
> **v3.8.42에서 약 1.37B로 추가 수정:** `longcat`은 무료 프리뷰가 종료된 후 월 150M의 반복 제공량에서 일회성 10M 가입 크레딧으로 재분류되었습니다. 동일한 정직성 원칙이 적용되었으며, 실수로 누락된 제공업체는 없습니다.
>
> **Felo Web 사용 중단 후 2026-08-26에 갱신:** Felo Web은 GPL 파생 출처/라이선스가 보류 상태인 동안 제외됩니다. 당시 소스에는 38개의 풀 키가 보고되어 있었습니다. 풀 개수는 실시간으로 계산되고 CI의 검증을 받습니다(`check:docs-counts`는 위 수치가 `computeFreeModelTotals()`와 달라지면 빌드를 실패시킵니다).
>
> **2026-09-02에 제공업체 자체 페이지를 기준으로 재감사됨**(출처: `open-sse/config/freeModelCatalog.data.ts`에서 재감사된 각 항목 옆의 `// evidence:` 주석): `gemini`와 `ollama-cloud`는 더 이상 토큰 수치를 공개하지 않으므로(Google은 2025-12-23에 모델별 무료 표를 삭제했고, Ollama의 Free 플랜은 "starter usage credits"임) 이제 **무제한**으로 표시되며 합산되지 않습니다(−80M). `groq`에는 모델별로 각각 적용되는 200K-TPD 한도 5개(각 6M, +15M)가 있으며, 지원 종료된 ID 3개는 삭제되었습니다. `nara`는 일일 7M 버킷 하나입니다(+60M, 210M). `mistral`의 1B는 계정 콘솔에서만 확인할 수 있습니다. 방법론 아래의 _증거 등급_을 참조하세요.
>
> **2026-09-03에 수정됨(#11773):** `cerebras`는 월 30M의 반복 제공량(이전의 카드 불필요 일일 1M 토큰 체험판)에서 결제 수단이 필요한 일회성 $5 가입 크레딧으로 재분류되었습니다. LongCat과 동일한 정직성 원칙이 적용되었습니다.
>
> **추가된 xKiro(2026-09-03):** 새로운 `xkiro-free` 풀(월 150M)이 35번째 반복 풀 키로 추가되었습니다. Felo Web은 GPL 파생 출처/라이선스가 보류 상태인 동안 계속 제외됩니다. 이제 소스에서는 **34개의 반복 풀 키**와 **약 1.62B의 안정적 제공량**을 보고합니다. 이는 실시간으로 계산되고 CI의 검증을 받는 수치입니다(`check:docs-counts`는 이 수치가 `computeFreeModelTotals()`와 달라지면 빌드를 실패시킵니다).

가장 큰 **문서화된** 기여 항목: `mistral` 1.00B, `nara` 210M, `llm7` 150M, `xkiro` 150M, `groq` 30M(모델별 한도 5개), `cloudflare-ai` 30M, `api-airforce` 24M. (`longcat`은 제외됩니다. LongCat-2.0의 10M 제공량은 반복되는 월간 예산이 아니라 KYC가 필요한 일회성 가입 크레딧입니다.)

> ⚠️ 이론적 상한(약 10B)은 **공개된 토큰 한도가 없는** 속도 제한 전용 제공업체(`tencent`, `nvidia`, `baidu`, `glm-cn`, `sparkdesk`)로 인해 부풀려져 있습니다. 이들의 수치는 `RPM/TPM × 24/7 × 30d`로 계산되지만, 이는 단일 계정으로는 지속할 수 없는 이론적 최댓값입니다. 따라서 방어 가능한 수치에서는 **제외**됩니다(대신 "영구 무료, 한도 없음" 행에 표시됨). 이는 경쟁사의 수십억 단위 주장을 신뢰하기 어렵게 만드는 것과 동일한 수치 부풀리기입니다.

## 2026-06-17 갱신 — 2026-06-05 이후 변경 사항

50개 에이전트 웹 리서치 패스(공식 문서 + 지난 7일간의 뉴스, 적대적 검증 완료)를 통해 전체 카탈로그를 갱신했습니다. 주요 내용:

- **제거됨 / 무료 티어 없음 (2026):** `chutes` (무료 티어 2026-03 종료), `phind` (2026-01 회사 폐업), `kluster` (2026-06-09 서비스 종료 → MITO), `gitlawb` + `gitlawb-gmi` (MiMo 무료 제공 2026-05-24 철회, Nemotron 프로모션 2026-06 종료 — 2026-06-18 재검증), `aimlapi` (무료 티어 일시 중단 — 2026-06-18 재검증), `yi` (Yi-Light 폐기, 종량제 전환 — 2026-06-18 재검증), `featherless-ai` (현재 무료 티어 없음), `chipotle` (Chipotle의 "Pepper AI" — 프로바이더가 통신하던 리버스 엔지니어링된 `amelia.chipotle.com` Amelia 채팅 위젯이 이제 루트를 포함한 모든 경로에서 404를 반환; 백엔드 폐기/이전됨, 2026-09-15 확인 — 카탈로그에서 완전히 제거, #13131/#4037). `iflytek` / `sparkdesk`는 목록에 유지되지만 ToS 주의 안내가 추가되었습니다 (Spark Lite는 무료이지만, ToS가 프록시/릴레이 사용을 제한함).

## 두 가지 체계 — 집계와 판단

OmniRoute는 의도적으로 서로 다른 소스를 읽는 두 가지 체계를 통해 "무료인가?"에
답합니다.

| 체계            | 기준 데이터                                                                                                                                           | 적용 영역                                                                                                           |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **집계 / 표시** | 해석된 카탈로그 — 배포된 기준 데이터에 Radar 피드(`getRadarCatalog`)를 오버레이                                                                       | 무료 티어 총합, 예산 카드, 대시보드                                                                                 |
| **판단**        | 배포된 카탈로그(`open-sse/config/freeModelCatalog.data.ts`의 `FREE_MODEL_BUDGETS`)와 로컬 휴리스틱(`:free` 접미사, 0 가격, `grantsFreeAccess`)만 사용 | `src/shared/utils/freeModels.ts`의 모든 소비자: 모델 가져오기, `auto/*` 라우팅, `GET /v1/models`, 브라우저 미리보기 |

피드를 사용할 수 있을 때마다 집계 결과는 개선될 수 있습니다. 판단은
릴리스 아티팩트만 사용하므로 브라우저와 서버에서 결과가 동일하고,
오프라인에서도 재현할 수 있으며 데이터베이스 없이 테스트할 수 있습니다. 브라우저
미리보기와 서버의 가져오기가 서로 다른 소스를 읽도록 허용하면
미리보기와 클릭 후 실제 결과가 일치하지 않게 됩니다. 따라서 이러한 분리는
의도적으로 유지됩니다.

## 방법론 및 주의사항

- 수치는 웹 조사를 통해 수집한 각 제공업체의 문서화된 무료 티어 한도를 기준으로 한 **상한 추정치**이며, 기준일은 **2026-06-17**입니다. 무료 티어는 계속 변경되므로 수치에 의존하기 전에 다시 확인하세요.
- **각 항목이 실제로 보증하는 것.** 어떤 항목에도 행별 신뢰도 등급이 없으며 API에서도 이를 제공하지 않습니다. 위의 모든 수치를 동일한, 명시되지 않은 품질의 추정치로 취급하세요. 두 가지 사실은 수동으로 선별된 것이므로 추론된 것이 아닙니다. 44개 항목에는 독립적으로 문서화된 하드 스톱이 있으며(이 중 39개는 모두 하나의 일일 허용량을 공유하는 xKiro 행), 21개 항목에는 프롬프트 학습 공개가 있습니다. `hardStopGuaranteed`는 제공업체 자체 약관에 무료 허용량을 초과할 경우 자동으로 청구를 시작하지 않고 요청을 거부한다고 명시되어 있을 때만 설정되며, 해당 출처는 항목 옆의 주석에 있습니다. 기본값으로 `true`가 설정되는 일은 없으며, 아무도 검증하지 않은 항목은 설정되지 않은 상태로 남습니다. 따라서 하드 스톱 플래그가 없다는 것은 "확인되지 않음"을 의미하지, "청구되는 것으로 알려짐"을 의미하지 않습니다. **STRICT 모드**(옵트인 방식의 `freeAccessPolicy=strict` 라우팅 가드)는 해당 플래그가 있는 항목만 신뢰합니다. 그 외의 모든 무료 티어는 `no-hard-stop`으로 제외됩니다(`open-sse/services/autoCombo/strictZeroCostFilter.ts` 참조). 가드가 풀을 필터링하면 운영자에게 표시되는 로그에 제외 수와 그중 `no-hard-stop` 비율이 모두 기록됩니다.
- `estMonthlyFreeTokens` = 반복적으로 제공되는 월간 토큰만을 의미합니다. **일회성 가입 크레딧은 반복되지 않으므로** 0으로 계산합니다. 중단된 티어도 0입니다.
- 일일 토큰 한도 → `monthly = daily × 30`. RPD만 문서화된 경우 → `RPD × ~800 output tokens × 30`. RPM/TPM만 있고 일일 한도가 없는 경우 → **무제한**(아래 참조).
- **영구적으로 무료이지만 공개된 토큰 한도가 없는 경우**(`glm-cn`, `tencent`, `baidu`, `kilo-gateway`, `opencode-zen`, `gemini`, `ollama-cloud`): 이는 실제로 반복되는 무료 액세스이지만 속도/동시성 제한이 있습니다. 이를 `recurring-uncapped`로 분류하며 **절대 합산하지 않습니다**. `RPM × 24/7 × 30d`를 곱하면 현실과 동떨어진 상한(우리가 배제하는 부풀리기)이 산출되기 때문입니다. 이러한 항목은 존재한다는 사실을 알 수 있도록 목록에 포함되어 있습니다.
- **예치금 잠금 해제 부스트:** 무료 할당량을 영구적으로 늘리는 일회성 소액 충전(OpenRouter: $10 → 일일 1000회 요청 ≈ 월 +24M). 별도의 수치로 보고하며, 안정적인 헤드라인 수치에서는 제외합니다.
- **자격 요건이 적용되는 할당량**(`eligibilityGate: "regional-identity"`): 지역에 연계된 신원 확인(현재는 중국 본토 실명 인증)을 완료한 후에만 활성화되는 실제 반복 할당량입니다. 동일한 풀 중복 제거 규칙에 따라 별도의 수치(`gatedRecurringTokens`)로 계산하며, 안정적인 헤드라인 수치에는 포함하지 않습니다. 제도(`freeType`)는 변경되지 않으므로 라우팅도 변경되지 않습니다.
- **근거의 분류.** 규칙은 다음과 같습니다. 카탈로그의 수치는 항목 옆의 `// evidence:` 주석에 출처를 기록합니다. `public-page`는 누구나 읽을 수 있는 제공업체 페이지, `api-public`은 제공업체의 인증되지 않은 엔드포인트(예: router.bynara.id에 있는 NaraRouter의 공개 요금제 엔드포인트), `console-verified <date> por <who>`는 계정 콘솔 내부에서만 확인할 수 있는 수치입니다. 후자의 경우 주석에는 해당 수치를 언제 누가 확인했는지와 한도가 존재한다고 설명하는 공개 페이지가 기록됩니다. 현재 상태는 다음과 같습니다. 2026-09-02에 다시 감사한 다섯 블록(`gemini`, `groq`, `mistral`, `ollama-cloud`, `nara`)에는 해당 정보가 있으며, 2026-09-02 재감사 이전에 작성된 항목은 수정될 때까지 이전 조사 결과를 상속합니다. **새로 추가되거나 변경된** 수치에 근거 주석이 없다면 버그입니다. 현재 `mistral`만 콘솔 검증을 거쳤습니다.

## 당사의 수치가 다른 애그리게이터보다 작은 이유

이 분야에서 제시되는 대부분의 "월간 무료 토큰" 수치는 모델별 표시량을 합산한 것입니다. 당사는 의도적으로 그렇게 계산하지 않습니다:

- **각 공유 풀은 한 번만 계산합니다.** Mistral의 무료 플랜은 조직당 월 1B의 단일 할당량입니다. 이를 5개 모델 아래에 나열한다고 해서 5B가 되지는 않습니다. 모델별로 합산하면 당사 자체 카탈로그도 **~7.4B**로 표시될 것입니다(2026-09-03에 재계산됨. 이 수치는 CI로 검증되지 않으므로 카탈로그가 변경될 때마다 다시 측정해야 합니다). 하지만 각 제공업체의 계정 하나로 실제 사용할 수 있는 양은 **~1.47B**이므로 헤드라인에는 이 수치를 표시합니다.
- **일일 한도는 환산하지만, 속도 제한은 환산하지 않습니다.** 문서화된 일일 토큰 한도는 `× 30`으로 계산하고, 문서화된 일일 요청 한도는 `RPD × ~800 tokens × 30`으로 계산합니다. 분당 요청 수만 공개하는 제공업체에는 월간 수치를 부여하지 않고 _무제한_으로 표시하며, 합계에도 포함하지 않습니다. 속도 제한에 24/7을 곱해 수치를 부풀리는 방식은 사용하지 않습니다.
- **지역 신원 확인이 필요한 할당량은 별도로 표시합니다** (`+~6M behind regional identity verification`). 대부분의 독자는 이를 사용할 수 없기 때문입니다.
- **가입 크레딧은 첫 달에만 제공**되므로 별도의 두 번째 수치로 보고하며, 지속적으로 제공되는 수치에 절대 합산하지 않습니다.
- **이 수치는 CI로 검증됩니다.** `npm run check:docs-counts`는 카탈로그에서 합계를 다시 계산하며, 이 파일이나 README 또는 예산 카드의 수치가 해당 합계와 달라지면 빌드를 실패 처리합니다.

## ToS 주의 표
