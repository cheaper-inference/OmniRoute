## 1. ವಿಷಯಗಳು ಎಲ್ಲಿವೆ

- **ಕಿಟ್.** `packages/ui-kit/src` ಎಂಬುದು `packages/ui-kit/UPSTREAM.md` ನಲ್ಲಿ ಪಿನ್ ಮಾಡಲಾದ ಕಮಿಟ್ನಲ್ಲಿರುವ ಅಪ್ಸ್ಟ್ರೀಮ್ `src/` ನ ಬೈಟ್-ಟು-ಬೈಟ್ ನಕಲಾಗಿದೆ (ಅದು ಪರವಾನಗಿ ಅಧಿಕೃತಗೊಳಿಸುವಿಕೆಯನ್ನೂ ದಾಖಲಿಸುತ್ತದೆ); `PATCHES.md` ಸ್ಥಳೀಯ ಪ್ಯಾಚ್ಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ (ಯಾವುದೂ ಇಲ್ಲ). ಇದನ್ನು ಬಿಲ್ಡ್ ಇಲ್ಲದೆ ಸೋರ್ಸ್ ಆಗಿ ಬಳಸಲಾಗುತ್ತದೆ: `next.config.mjs` ಅದನ್ನು ಟ್ರಾನ್ಸ್ಪೈಲ್ ಮಾಡುತ್ತದೆ, ಮತ್ತು `tsconfig.json` `@omniroute/ui-kit` ಅನ್ನು `packages/ui-kit/src` ಗೆ ಹಾಗೂ `@omniroute/ui-kit/*` ಅನ್ನು `packages/ui-kit/src/*` ಗೆ ಮ್ಯಾಪ್ ಮಾಡುತ್ತದೆ (`vitest.config.ts` ಮತ್ತು `vitest.mcp.config.ts` ಅದೇ alias ಅನ್ನು ಹೊಂದಿರುತ್ತವೆ). ಕಿಟ್ ಕಾಂಪೋನೆಂಟ್ ಅನ್ನು ಅದರ ಸಬ್ಪಾತ್ ಮೂಲಕ ಇಂಪೋರ್ಟ್ ಮಾಡಿ (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), ಎಂದಿಗೂ `@omniroute/ui-kit` ಬ್ಯಾರೆಲ್ ಮೂಲಕ ಅಲ್ಲ: ಬ್ಯಾರೆಲ್ ಪ್ರತಿ ಇಂಪೋರ್ಟರ್ಗೆ ಎಲ್ಲಾ ಕಾಂಪೋನೆಂಟ್ಗಳನ್ನು (ಡೇಟ್ ಪಿಕರ್ ಸೇರಿದಂತೆ) ಎಳೆದುಕೊಂಡು ಬರುತ್ತದೆ. ಕಿಟ್ ಸ್ಟೈಲ್ಶೀಟ್ `src/app/globals.css` ಮೂಲಕ ಪ್ರವೇಶಿಸುತ್ತದೆ (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **ಟೋಕನ್ಗಳು.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` ಟೋಕನ್ಗಳನ್ನು ಘೋಷಿಸುತ್ತದೆ; `src/app/globals.css` ಅವುಗಳನ್ನು ಹಳೆಯ OmniRoute ಹೆಸರುಗಳಿಗೆ (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) ಸೇತುವೆಯಾಗಿ ಜೋಡಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ `var(--color-*)` ಓದುಗಿಕೆಗಳು ಮತ್ತು Tailwind ಯೂಟಿಲಿಟಿಗಳು ಕೆಲಸ ಮಾಡುತ್ತಲೇ ಇರುತ್ತವೆ. ಹೊಸ ಕೋಡ್ Tailwind ಯೂಟಿಲಿಟಿಗಳನ್ನು (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) ಅಥವಾ ಕಿಟ್ ಕ್ಲಾಸ್ಗಳನ್ನು ಬಳಸುತ್ತದೆ — ಎಂದಿಗೂ hex ಮೌಲ್ಯವನ್ನು ಅಲ್ಲ (`tests/unit/design-kit-bridge.test.ts` ಸೇತುವೆಯನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತದೆ). `text-primary` `--text-color-primary` ಮೂಲಕ `--color-primary-ink` ಗೆ ಪರಿಹರಿಸುತ್ತದೆ (ಲೈಟ್ನಲ್ಲಿ lime-800, ಡಾರ್ಕ್ನಲ್ಲಿ lime ಆಕ್ಸೆಂಟ್), ಆದ್ದರಿಂದ `bg-primary`/`border-primary` lime ಸರ್ಫೇಸ್ ಅನ್ನು ಇರಿಸಿಕೊಂಡರೂ ಪ್ರೈಮರಿ ಟೆಕ್ಸ್ಟ್ ಓದಲು ಯೋಗ್ಯವಾಗಿರುತ್ತದೆ. ಚಾರ್ಟ್ ಸರಣಿಗಳು `--color-chart-1` … `--color-chart-5` ಬಳಸುತ್ತವೆ.
- **ಥೀಮ್ಗಳು.** `<html className="ci-theme">` (`src/app/layout.tsx`) ಡಾಕ್ಯುಮೆಂಟ್ ಅನ್ನು ಕಿಟ್ ಥೀಮ್ಗೆ ಆಪ್ಟ್-ಇನ್ ಮಾಡುತ್ತದೆ. ಆದ್ಯತೆಯು `light`, `dark` ಅಥವಾ `system` ಆಗಿದೆ (`src/shared/constants/appConfig.ts` ನಲ್ಲಿ `THEME_CONFIG.defaultTheme = "system"`; `system` `prefers-color-scheme` ಅನ್ನು ಅನುಸರಿಸುತ್ತದೆ). `src/store/themeStore.ts` ನಲ್ಲಿರುವ `applyTheme()` (`src/app/layout.tsx` ನಲ್ಲಿನ ಇನ್ಲೈನ್ ಬೂಟ್ಸ್ಟ್ರ್ಯಾಪ್ ಸ್ಕ್ರಿಪ್ಟ್ನಿಂದ ಮಿರರ್ ಆಗಿದೆ, ಅದು ಹೈಡ್ರೇಶನ್ಗೆ ಮೊದಲು ಓಡುತ್ತದೆ) `data-theme="dark"|"light"` ಅನ್ನು ಸೆಟ್ ಮಾಡುತ್ತದೆ ಮತ್ತು `<html>` ಮೇಲಿನ `.dark` ಕ್ಲಾಸ್ ಅನ್ನು ಒಟ್ಟಿಗೆ ಟಾಗಲ್ ಮಾಡುತ್ತದೆ. ಕಿಟ್ನ ಡಾರ್ಕ್ ಟೋಕನ್ ಸೆಟ್ `data-theme="dark"` ಅನ್ನು ಕೀಲಿಯಾಗಿ ಬಳಸುತ್ತದೆ (`packages/ui-kit/src/ci-tokens.css`); OmniRoute ನ ಸ್ವಂತ ಡಾರ್ಕ್ ಓವರ್ರೈಡ್ಗಳು (`globals.css` ನಲ್ಲಿನ `.dark` ಬ್ಲಾಕ್) ಮತ್ತು ಹಳೆಯ Tailwind `dark:` ಯೂಟಿಲಿಟಿಗಳು `.dark` ಕ್ಲಾಸ್ ಅನ್ನು ಕೀಲಿಯಾಗಿ ಬಳಸುತ್ತವೆ. ಆಕ್ಸೆಂಟ್ ಬಣ್ಣದ ಪ್ರೀಸೆಟ್ಗಳು ಯಾವುದೂ ಇಲ್ಲ: ಆಕ್ಸೆಂಟ್ ಯಾವಾಗಲೂ ಕಿಟ್ನಿಂದ ಬರುತ್ತದೆ, ಮತ್ತು ಹಳೆಯ ಬಿಲ್ಡ್ನಿಂದ ಪರ್ಸಿಸ್ಟ್ ಆದ ಪ್ರೀಸೆಟ್ ಅನ್ನು ಸ್ಟೋರ್ ಲೋಡ್ ಆದಾಗ ತ್ಯಜಿಸಲಾಗುತ್ತದೆ.
- **ಕಾಂಪೋನೆಂಟ್ಗಳು (ಅಡಾಪ್ಟರ್ಗಳು).** `src/shared/components/index.tsx` OmniRoute ಕಾಂಪೋನೆಂಟ್ API ಅನ್ನು ಕಾಪಾಡುತ್ತದೆ (ಅದೇ ಹೆಸರುಗಳು, ಡಿಫಾಲ್ಟ್ ಎಕ್ಸ್ಪೋರ್ಟ್ಗಳು ಮತ್ತು ಪ್ರಾಪ್ಗಳು), ಮತ್ತು ಅದರ ಹಿಂದಿರುವ ಪ್ರಿಮಿಟಿವ್ಗಳು ಕಿಟ್ ಮೇಲಿನ ಅಡಾಪ್ಟರ್ಗಳಾಗಿವೆ: ಫಾರ್ಮ್ಗಳು (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), ಓವರ್ಲೇಗಳು ಮತ್ತು ಫೀಡ್ಬ್ಯಾಕ್ (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`), ರಚನೆ (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) ಮತ್ತು ಟೇಬಲ್ಗಳು (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). ಒಂದು ಅಡಾಪ್ಟರ್ ಕಿಟ್ ಕಾಂಪೋನೆಂಟ್ ಅನ್ನು ಸಬ್ಪಾತ್ ಮೂಲಕ ಇಂಪೋರ್ಟ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಹಳೆಯ ಪ್ರಾಪ್ಗಳನ್ನು ಅದಕ್ಕೆ ಮ್ಯಾಪ್ ಮಾಡುತ್ತದೆ — ಉದಾಹರಣೆಗೆ `Button variant="primary"` ಎಂಬುದು ಕಿಟ್ನ `default` ಬಟನ್ (`--ci-button-primary-*`: ಲೈಟ್ನಲ್ಲಿ ಇನ್ವರ್ಸ್ ಸರ್ಫೇಸ್, ಡಾರ್ಕ್ನಲ್ಲಿ ಅದರ `--ci-color-accent-foreground` ಇಂಕ್ನೊಂದಿಗೆ ಆಕ್ಸೆಂಟ್), `danger` ಎಂಬುದು `destructive`, ಮತ್ತು `warning` ಎಂಬುದು `outline` ಜೊತೆಗೆ `.ci-button--warning` ಎಕ್ಸ್ಟೆನ್ಷನ್. `globals.css` ನ ಕೊನೆಯಲ್ಲಿರುವ `.ci-button--warning` ಮತ್ತು `.ci-badge[data-tone]` ರೂಲ್ಗಳು (`@layer components`) ಕಿಟ್ ಕ್ಲಾಸ್ಗಳ ಮೇಲಿನ OmniRoute ಎಕ್ಸ್ಟೆನ್ಷನ್ಗಳಾಗಿವೆ. `tests/unit/ui/adapters/*.test.tsx` ಪ್ರತಿ ಅಡಾಪ್ಟರ್ ಅನ್ನು ಪಿನ್ ಮಾಡುತ್ತದೆ.
- **ಶೆಲ್.** `src/app/(dashboard)/layout.tsx` `DashboardLayout` ಅನ್ನು ರೆಂಡರ್ ಮಾಡುತ್ತದೆ, ಅದು `src/shared/components/layouts/DashboardShell.tsx` ಅನ್ನು ರೆಂಡರ್ ಮಾಡುತ್ತದೆ: ಕಿಟ್ `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), ಜೊತೆಗೆ `src/shared/components/Sidebar.tsx` ನಲ್ಲಿ OmniRoute ನ ನ್ಯಾವಿಗೇಶನ್ ಲಾಜಿಕ್. `#main-content` ಗೆ ತೆರಳುವ "skip to content" ಲಿಂಕ್ ಮೊದಲ ಫೋಕಸ್ ಮಾಡಬಹುದಾದ ಎಲಿಮೆಂಟ್ ಆಗಿದೆ. `src/shared/components/Header.tsx` ಕಿಟ್ `SidebarTrigger` (ಶೆಲ್ನ ಏಕೈಕ ಸೈಡ್ಬಾರ್ ಟಾಗಲ್), Keak `ProductSwitcher` ಮತ್ತು ಕಮಾಂಡ್-ಪ್ಯಾಲೆಟ್ ಓಪನರ್ ಅನ್ನು ಹೊಂದಿದೆ; `#main-content` ಒಳಗೆ ಯಾವುದೇ ಕಿಟ್ `PageHeader` (`.ci-page-header`) ಮೌಂಟ್ ಆಗಿಲ್ಲದಿರುವವರೆಗೆ ಮಾತ್ರ ಇದು ರೂಟ್ ಟೈಟಲ್ ಅನ್ನು ತೋರಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ತನ್ನದೇ `PageHeader` ಹೊಂದಿರುವ ಪೇಜ್ ಒಂದೇ `h1` ಅನ್ನು ಹೊಂದಿರುತ್ತದೆ. `src/shared/components/CommandPalette.tsx` ಒಂದು ಕಿಟ್ `Dialog` ಆಗಿದೆ.

   ಪ್ಯಾರಿಟಿ ಟೆಸ್ಟ್ ಪ್ರತಿಯೊಂದು ಇಂಗ್ಲಿಷ್ ಕೀಯನ್ನು ಪಿನ್ ಮಾಡುತ್ತದೆ); ಉಳಿದ ಲೊಕೇಲ್ಗಳನ್ನು i18n ಸಿಂಕ್ ಭರ್ತಿ ಮಾಡುತ್ತದೆ.
6. PR ಗೆ ಮೊದಲು ಗಾರ್ಡ್ಗಳನ್ನು ಚಲಾಯಿಸಿ: `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (`iconMap.ts` ನಲ್ಲಿ ಡುಪ್ಲಿಕೇಟ್ ಇಂಪೋರ್ಟ್ ಅನ್ನು ಹಿಡಿಯುವ ಏಕೈಕ ಚೆಕ್),
   `npm run check:ui-icu`, ಮತ್ತು ಆ ಸ್ಕ್ರೀನ್ನ ಸ್ವಂತ ಟೆಸ್ಟ್ಗಳು.

## 4. ಅಡಾಪ್ಟರ್ ಸೇರಿಸುವುದು ಅಥವಾ ಬದಲಾಯಿಸುವುದು

1. `src/shared/components/index.tsx` ನ ಸಾರ್ವಜನಿಕ API ಅನ್ನು ಹಾಗೆಯೇ ಇರಿಸಿ: ಅದೇ export ಹೆಸರುಗಳು, default exports ಮತ್ತು ಸ್ವೀಕರಿಸಲಾದ props. ಹಳೆಯ props ಅನ್ನು ಅಡಾಪ್ಟರ್ನೊಳಗೆ ಕಿಟ್ಗೆ ಮ್ಯಾಪ್ ಮಾಡಿ (`Button.tsx` ನೋಡಿ: `VARIANT_TO_KIT`, `SIZE_TO_KIT`).
2. ಸಬ್ಪಾತ್ ಮೂಲಕ ಕಿಟ್ ಅನ್ನು ಇಂಪೋರ್ಟ್ ಮಾಡಿ (`@omniroute/ui-kit/<component>`).
3. ಕಿಟ್ನ ಕೊರತೆಗಳಿಗಾಗಿ ತಾತ್ಕಾಲಿಕ ಪರಿಹಾರಗಳು (workarounds) ಅಡಾಪ್ಟರ್ನಲ್ಲಿ ಇರಲಿ (ಫಿಕ್ಸ್ ಸ್ಟೈಲ್ ಆಗಿದ್ದಾಗ `globals.css` ನ `@layer components` ನಲ್ಲಿ), ಎಂದಿಗೂ `packages/ui-kit/src` ನಲ್ಲಿ ಅಲ್ಲ.
4. `tests/unit/ui/adapters/<name>.test.tsx` ಅನ್ನು ಸೇರಿಸಿ ಅಥವಾ ನವೀಕರಿಸಿ. ಅನೇಕ ಕಾಲರ್ಗಳನ್ನು ಹೊಂದಿರುವ ಅಡಾಪ್ಟರ್ಗೆ, ಬದಲಾವಣೆಯ ಮೊದಲು ಮತ್ತು ನಂತರದ ರೆಂಡರ್ ಮಾಡಲಾದ ಮಾರ್ಕಪ್ ಅನ್ನು ಹೋಲಿಕೆ ಮಾಡಿ — ಪ್ಯಾಡಿಂಗ್ ಅಥವಾ ರ್ಯಾಪರ್ ಬದಲಾವಣೆಗಳು ಪ್ರತಿಯೊಂದು ಸ್ಕ್ರೀನ್ಗೂ ಹಬ್ಬುತ್ತವೆ.

## 5. ಕಿಟ್ ಅನ್ನು ನವೀಕರಿಸುವುದು

`scripts/dev/sync-ui-kit.sh <commit> [clone]` ಆ ಕಮಿಟ್ನಲ್ಲಿರುವ ಅಪ್ಸ್ಟ್ರೀಮ್ `src/` ಅನ್ನು `packages/ui-kit/src` ಗೆ ನಕಲಿಸುತ್ತದೆ ಮತ್ತು ಅನುಮತಿಸಲಾದ ಏಕೈಕ ಪರಿವರ್ತನೆಯನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ (ಇದು ಸಂಬಂಧಿತ ಇಂಪೋರ್ಟ್ಗಳಿಂದ `.js` ಪ್ರತ್ಯಯವನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ). ನಂತರ: `git diff packages/ui-kit` ಅನ್ನು ಪರಿಶೀಲಿಸಿ, ಎರಡೂ ಥೀಮ್ಗಳಲ್ಲಿ providers, settings, combos, usage ಮತ್ತು endpoint ಗಳನ್ನು ದೃಶ್ಯವಾಗಿ ಪರಿಶೀಲಿಸಿ, `npm run check:ui-kit-snapshot` ಮತ್ತು `npm run test:vitest:ui` ಅನ್ನು ಚಲಾಯಿಸಿ, ಮತ್ತು ಅಪ್ಸ್ಟ್ರೀಮ್ changelog ಸಹಿತ PR ಅನ್ನು ತೆರೆಯಿರಿ.
