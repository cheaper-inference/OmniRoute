> **ಸ್ಥಿತಿ:** ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅನ್ನು ನಿರ್ಮಿಸಲಾಗಿದೆ**Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), ಈ ರೆಪೊಸಿಟರಿಯಲ್ಲಿ ಕಾರ್ಯಸ್ಥಳ `packages/ui-kit` (`@omniroute/ui-kit`; ಅಪ್ಸ್ಟ್ರೀಮ್ ಸ್ನ್ಯಾಪ್ಶಾಟ್ ಅನ್ನು `packages/ui-kit/UPSTREAM.md` ನಲ್ಲಿ ಪಿನ್ ಮಾಡಲಾಗಿದೆ ಮತ್ತು `npm run check:ui-kit-snapshot` ನಿಂದ ರಕ್ಷಿಸಲಾಗಿದೆ) ಎಂದು ಸೇರಿಸಲಾಗಿದೆ. ಬೆಳಕು ಅಂಗೀಕೃತ ವಿಷಯವಾಗಿದೆ; ಡೀಫಾಲ್ಟ್ ಆದ್ಯತೆಯು `system` ಆಗಿದೆ. ಡೀಫಾಲ್ಟ್ ಪ್ಯಾಲೆಟ್ ಕಿಟ್ ಆಗಿದೆ**Editions** ನೋಟ (ಬೆಚ್ಚಗಿನ ಕಾಗದದ ನ್ಯೂಟ್ರಲ್ಗಳು ಮತ್ತು ತಾಮ್ರದ ಉಚ್ಚಾರಣೆ `#e5ac82`, `packages/ui-kit/src/ci-editions.css`); ಸೆಟ್ಟಿಂಗ್ಗಳು → ಗೋಚರತೆ → ಬಣ್ಣದ ಪ್ಯಾಲೆಟ್ ಕೊಡುಗೆಗಳು**Classic** , ಸುಣ್ಣದ ಉಚ್ಚಾರಣೆಯೊಂದಿಗೆ ಕಿಟ್ನ ಮೂಲ ಟೋಕನ್ಗಳು. Switzer ಎಂಬುದು UI ಮತ್ತು ಪ್ರದರ್ಶನ ಪಠ್ಯಕ್ಕಾಗಿ ಪ್ರಾಥಮಿಕ ಕುಟುಂಬವಾಗಿದೆ (`--ci-font-ui`; `--ci-font-display` ಮತ್ತು `--ci-font-mono` ಅದಕ್ಕೆ ಪರಿಹಾರ), ಕಿಟ್ನಿಂದ ಸ್ವಯಂ-ಹೋಸ್ಟ್ ಮಾಡಲಾಗಿದೆ (`packages/ui-kit/src/ci-fonts.css`, `ci-tokens.css` ನಿಂದ ಆಮದು ಮಾಡಿಕೊಳ್ಳಲಾಗಿದೆ). ಪ್ರತಿ ಐಕಾನ್ ಒಂದು Lucide ಗ್ಲಿಫ್ ಆಗಿದೆ.
>
> Inter ಎಂಬುದು Switzer ನಿಂದ ಕಾಣೆಯಾದ ಗ್ಲಿಫ್ಗಳಿಗೆ ಫಾಲ್ಬ್ಯಾಕ್ ಆಗಿದೆ; `--font-mono` ಸಿಸ್ಟಂಗೆ ನಕ್ಷೆಗಳು ಮಾನೋಸ್ಪೇಸ್ ಸ್ಟಾಕ್ `--ci-font-code`.
>
> `Switzer` ಗ್ಲಿಫ್ ಇಲ್ಲದಿದ್ದಾಗ `src/app/globals.css` ಪ್ರತಿ ಗ್ಲಿಫ್ಗೆ ಫಾಲ್ಬ್ಯಾಕ್ ಫಾಂಟ್ಗಳನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ: ಸಿರಿಲಿಕ್, ಗ್ರೀಕ್ ಮತ್ತು ವಿಯೆಟ್ನಾಮೀಸ್ಗೆ `Inter` ಮತ್ತು ಅರೇಬಿಕ್ ಲಿಪಿಗಾಗಿ `Vazirmatn` `html[dir="rtl"]` ಅಡಿಯಲ್ಲಿ ಮಾತ್ರ.

`src/app/globals.css`:

```css
:root,
.ci-theme {
  --ci-font-ui:
    "Switzer", "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif;
  --ci-font-code: ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace;
  --font-mono: var(--ci-font-code);
}
```

## 1. ವಿಷಯಗಳು ಎಲ್ಲಿವೆ

- **ಕಿಟ್.** `packages/ui-kit/src` ಎಂಬುದು
  `packages/ui-kit/UPSTREAM.md` ನಲ್ಲಿ ಪಿನ್ ಮಾಡಲಾದ ಕಮಿಟ್ನ ಅಪ್ಸ್ಟ್ರೀಮ್ `src/` ನ ಬೈಟ್-ಫಾರ್-ಬೈಟ್ ನಕಲು (ಇದು ಪರವಾನಗಿ ದೃಢೀಕರಣವನ್ನೂ ದಾಖಲಿಸುತ್ತದೆ); `PATCHES.md` ಸ್ಥಳೀಯ
  ಪ್ಯಾಚ್ಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ. ಇದನ್ನು ಯಾವುದೇ ಬಿಲ್ಡ್ ಇಲ್ಲದೆ ಮೂಲವಾಗಿಯೇ ಬಳಸಲಾಗುತ್ತದೆ: `next.config.mjs` ಇದನ್ನು ಟ್ರಾನ್ಸ್ಪೈಲ್ ಮಾಡುತ್ತದೆ ಮತ್ತು
  `tsconfig.json` ನಲ್ಲಿ `@omniroute/ui-kit` → `packages/ui-kit/src` ಹಾಗೂ `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` ಎಂದು ಮ್ಯಾಪ್ ಮಾಡಲಾಗಿದೆ (`vitest.config.ts` ಮತ್ತು `vitest.mcp.config.ts` ಕೂಡ ಇದೇ ಅಲಿಯಾಸ್ ಹೊಂದಿವೆ). ಕಿಟ್ ಕಾಂಪೊನೆಂಟ್ ಅನ್ನು ಅದರ
  ಉಪಪಥದ ಮೂಲಕ (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) ಇಂಪೋರ್ಟ್ ಮಾಡಿ; `@omniroute/ui-kit` ಬ್ಯಾರೆಲ್ ಮೂಲಕ ಎಂದಿಗೂ
  ಮಾಡಬೇಡಿ: ಬ್ಯಾರೆಲ್ ಪ್ರತಿ ಕಾಂಪೊನೆಂಟ್ನ್ನೂ (ದಿನಾಂಕ ಪಿಕರ್ ಸೇರಿದಂತೆ)
  ಪ್ರತಿ ಇಂಪೋರ್ಟರ್ಗೆ ಎಳೆದುಕೊಳ್ಳುತ್ತದೆ. ಕಿಟ್ ಸ್ಟೈಲ್ಶೀಟ್ `src/app/globals.css` ಮೂಲಕ ಪ್ರವೇಶಿಸುತ್ತದೆ
  (`@import "../../packages/ui-kit/src/ci-styles.css"`, ಸಂಪೂರ್ಣ ಶೀಟ್: ಕೋರ್ `ci-ui.css` ಜೊತೆಗೆ ಪ್ರತಿಯೊಂದು ಪ್ಯಾಟರ್ನ್ ಕುಟುಂಬ).
- **ಟೋಕನ್ಗಳು.** `packages/ui-kit/src/ci-tokens.css` ನಲ್ಲಿ `--ci-*` ಟೋಕನ್ಗಳನ್ನು ಘೋಷಿಸಲಾಗಿದೆ; `src/app/globals.css`
  ಅವುಗಳನ್ನು ಹಳೆಯ OmniRoute ಹೆಸರುಗಳಿಗೆ (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`) ಸೇತುವೆ ಮಾಡುತ್ತದೆ, ಆದ್ದರಿಂದ ಈಗಿರುವ `var(--color-*)` ಓದುಗಳು ಮತ್ತು Tailwind
  ಯುಟಿಲಿಟಿಗಳು ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಲೇ ಇರುತ್ತವೆ. ಹೊಸ ಕೋಡ್ Tailwind ಯುಟಿಲಿಟಿಗಳನ್ನು (`bg-surface`, `text-text-muted`,
  `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) ಅಥವಾ ಕಿಟ್ ಕ್ಲಾಸ್ಗಳನ್ನು ಬಳಸುತ್ತದೆ — ಹೆಕ್ಸ್ ಮೌಲ್ಯವನ್ನು ಎಂದಿಗೂ ಬಳಸುವುದಿಲ್ಲ
  (`tests/unit/design-kit-bridge.test.ts` ಈ ಸೇತುವೆಯನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತದೆ). `text-primary` ಎಂಬುದು
  `--text-color-primary` ಮೂಲಕ `--color-primary-ink` ಗೆ ರೆಸಾಲ್ವ್ ಆಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಪ್ರಾಥಮಿಕ ಪಠ್ಯ ಓದಲು ಸುಲಭವಾಗಿಯೇ ಉಳಿಯುತ್ತದೆ; ಇದೇ ವೇಳೆ
  `bg-primary`/`border-primary` ಆಕ್ಸೆಂಟ್ ಮೇಲ್ಮೈಯನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ: Editions ಅಡಿಯಲ್ಲಿ ಇದು ಕಿಟ್ನ
  `--ci-color-accent-active` (ಲೈಟ್ನಲ್ಲಿ ಗಾಢ ತಾಮ್ರ ಬಣ್ಣದ `#99562f`, ಡಾರ್ಕ್ನಲ್ಲಿ ತಾಮ್ರದ ಆಕ್ಸೆಂಟ್); Classic ಅಡಿಯಲ್ಲಿ,
  ಲೈಟ್ನಲ್ಲಿ lime-800 ಮತ್ತು ಡಾರ್ಕ್ನಲ್ಲಿ ಲೈಮ್ ಆಕ್ಸೆಂಟ್. ಚಾರ್ಟ್ ಸರಣಿಗಳು
  `--color-chart-1` … `--color-chart-5` ಅನ್ನು ಬಳಸುತ್ತವೆ.
- **ಥೀಮ್ಗಳು.** `<html className="ci-theme">` (`src/app/layout.tsx`) ಡಾಕ್ಯುಮೆಂಟ್ ಅನ್ನು ಕಿಟ್ ಥೀಮ್ಗೆ ಸೇರಿಸುತ್ತದೆ.
  ಆದ್ಯತೆಯು `light`, `dark` ಅಥವಾ `system` ಆಗಿರುತ್ತದೆ (`src/shared/constants/appConfig.ts` ನಲ್ಲಿ `THEME_CONFIG.defaultTheme = "system"`;
  `system`, `prefers-color-scheme` ಅನ್ನು ಅನುಸರಿಸುತ್ತದೆ). `src/store/themeStore.ts` ನಲ್ಲಿರುವ `applyTheme()` ಅನ್ನು
  (`src/app/layout.tsx` ನಲ್ಲಿ ಇನ್ಲೈನ್ ಮಾಡಲಾದ ಮತ್ತು ಹೈಡ್ರೇಷನ್ಗೆ ಮೊದಲು ರನ್ ಆಗುವ `THEME_BOOT_SCRIPT` ಕೂಡ ಇದೇ ರೀತಿ ಪ್ರತಿಬಿಂಬಿಸುತ್ತದೆ)
  `data-theme="dark"|"light"` ಅನ್ನು ಸೆಟ್ ಮಾಡಿ, ಅದೇ ಸಮಯದಲ್ಲಿ `<html>` ನಲ್ಲಿರುವ `.dark` ಕ್ಲಾಸ್ ಅನ್ನು ಟಾಗಲ್ ಮಾಡುತ್ತದೆ.
  ಕಿಟ್ನ ಡಾರ್ಕ್ ಟೋಕನ್ ಸೆಟ್ `data-theme="dark"` ಆಧಾರಿತವಾಗಿದೆ (`packages/ui-kit/src/ci-tokens.css`);
  OmniRoute ನ ಸ್ವಂತ ಡಾರ್ಕ್ ಓವರ್ರೈಡ್ಗಳು (`globals.css` ನಲ್ಲಿರುವ `.dark` ಬ್ಲಾಕ್) ಮತ್ತು ಹಳೆಯ Tailwind `dark:`
  ಯುಟಿಲಿಟಿಗಳು `.dark` ಕ್ಲಾಸ್ ಆಧಾರಿತವಾಗಿವೆ. ಯಾವುದೇ ಆಕ್ಸೆಂಟ್ ಬಣ್ಣದ ಪ್ರಿಸೆಟ್ಗಳಿಲ್ಲ: ಆಕ್ಸೆಂಟ್ ಯಾವಾಗಲೂ
  ಕಿಟ್ನಿಂದ ಬರುತ್ತದೆ ಮತ್ತು ಹಳೆಯ ಬಿಲ್ಡ್ನಿಂದ ಉಳಿಸಿಕೊಂಡ ಪ್ರಿಸೆಟ್ ಅನ್ನು ಸ್ಟೋರ್ ಲೋಡ್ ಆಗುವಾಗ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ.
- **ಪ್ಯಾಲೆಟ್ಗಳು.** ಎರಡು ಇವೆ ಮತ್ತು ಎರಡೂ ಕಿಟ್ನಿಂದಲೇ ಬಂದಿವೆ (`src/shared/constants/appearancePalette.ts`): ಡೀಫಾಲ್ಟ್ ಆದ `editions` ಮತ್ತು
  `classic`. Editions ಎಂಬುದು `<html>` ನಲ್ಲಿರುವ ಕಿಟ್ನ `data-ci-appearance="editions"` ಅಟ್ರಿಬ್ಯೂಟ್ ಆಗಿದ್ದು,
  `ci-editions.css` (`ci-ui.css` ಮೂಲಕ ಇಂಪೋರ್ಟ್ ಮಾಡಲಾಗಿದೆ) ಅದನ್ನು `data-theme` ಜೊತೆಗೆ ಸಂಯೋಜಿಸುತ್ತದೆ; Classic ಎಂದರೆ ಆ ಅಟ್ರಿಬ್ಯೂಟ್ನ
  ಅನುಪಸ್ಥಿತಿ. ರೂಟ್ ಲೇಔಟ್ ಸರ್ವರ್ನಲ್ಲೇ ಅಟ್ರಿಬ್ಯೂಟ್ ಅನ್ನು ರೆಂಡರ್ ಮಾಡುತ್ತದೆ, ಆದ್ದರಿಂದ ಏನನ್ನೂ ಸಂಗ್ರಹಿಸದ (ಅಥವಾ JS ಇಲ್ಲದ) ಸಂದರ್ಶಕರಿಗೆ
  ಪ್ರತಿಯೊಂದು ಮೇಲ್ಮೈಯಲ್ಲೂ Editions ದೊರೆಯುತ್ತದೆ — ಡ್ಯಾಶ್ಬೋರ್ಡ್, ಲಾಗಿನ್, `/status`, ದೋಷ ಪುಟಗಳು, `/docs` ಮತ್ತು PWA. ಆಯ್ಕೆಯನ್ನು
  ಥೀಮ್ ಪಕ್ಕದಲ್ಲೇ ಅದೇ `theme` ಸ್ಟೋರ್ನಲ್ಲಿ (`src/store/themeStore.ts` ನಲ್ಲಿರುವ `palette`, `setPalette()`, `applyPalette()`)
  ಉಳಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಪೇಂಟ್ ಆಗುವ ಮೊದಲು `THEME_BOOT_SCRIPT`

## 3. ಸ್ಕ್ರೀನ್ ಸೇರಿಸುವುದು

   ಸಬ್ಪಾತ್ ಮೂಲಕ ಕಿಟ್ ಕಾಂಪೋನೆಂಟ್ಗಳನ್ನು ಬಳಸಿ (`Table`/`TableScrollArea`/`DataTableShell`, `Field`,

## 4. ಅಡಾಪ್ಟರ್ ಸೇರಿಸುವುದು ಅಥವಾ ಬದಲಾಯಿಸುವುದು

1. `src/shared/components/index.tsx` ನ ಸಾರ್ವಜನಿಕ API ಅನ್ನು ಹಾಗೆಯೇ ಇರಿಸಿ: ಅದೇ ಎಕ್ಸ್ಪೋರ್ಟ್ ಹೆಸರುಗಳು, ಡಿಫಾಲ್ಟ್ ಎಕ್ಸ್ಪೋರ್ಟ್ಗಳು ಮತ್ತು
   ಸ್ವೀಕರಿಸಲಾದ props. ಅಡಾಪ್ಟರ್ ಒಳಗೆ ಲೆಗಸಿ props ಅನ್ನು ಕಿಟ್ಗೆ ಮ್ಯಾಪ್ ಮಾಡಿ (`Button.tsx` ನೋಡಿ: `VARIANT_TO_KIT`,
   `SIZE_TO_KIT`).
2. ಸಬ್ಪಾತ್ ಮೂಲಕ ಕಿಟ್ ಅನ್ನು ಇಂಪೋರ್ಟ್ ಮಾಡಿ (`@omniroute/ui-kit/<component>`).
3. ಕಿಟ್ನಲ್ಲಿನ ಕೊರತೆಗಳ ವರ್ಕ್ಎರೌಂಡ್ಗಳು ಅಡಾಪ್ಟರ್ನಲ್ಲಿ ಇರಬೇಕು (ಫಿಕ್ಸ್ ಸ್ಟೈಲ್ ಆಗಿದ್ದಾಗ `globals.css` `@layer components`
   ನಲ್ಲಿ), ಎಂದಿಗೂ `packages/ui-kit/src` ನಲ್ಲಿ ಅಲ್ಲ.
4. `tests/unit/ui/adapters/<name>.test.tsx` ಅನ್ನು ಸೇರಿಸಿ ಅಥವಾ ನವೀಕರಿಸಿ. ಅನೇಕ ಕಾಲರ್ಗಳನ್ನು ಹೊಂದಿರುವ ಅಡಾಪ್ಟರ್ಗಾಗಿ,
   ಬದಲಾವಣೆಯ ಮೊದಲು ಮತ್ತು ನಂತರದ ರೆಂಡರ್ ಆದ ಮಾರ್ಕಪ್ ಅನ್ನು ಹೋಲಿಕೆ ಮಾಡಿ — ಪ್ಯಾಡಿಂಗ್ ಅಥವಾ ರ್ಯಾಪರ್ ಬದಲಾವಣೆಗಳು ಪ್ರತಿ ಸ್ಕ್ರೀನ್ಗೆ ಹಬ್ಬುತ್ತವೆ.

## 5. ಕಿಟ್ ಅನ್ನು ನವೀಕರಿಸುವುದು

`npm run check:ui-kit-upstream` ಅಪ್ಸ್ಟ್ರೀಮ್ ರೆಪೊದ ಹೊಸ `v*` ಟ್ಯಾಗ್ನೊಂದಿಗೆ `packages/ui-kit/UPSTREAM.md` ನಲ್ಲಿ ಪಿನ್ ಮಾಡಲಾದ ಆವೃತ್ತಿಯನ್ನು ಹೋಲಿಸುತ್ತದೆ ಮತ್ತು ಬಿಡುಗಡೆಯಾದಾಗ ಸಿಂಕ್ ಆಜ್ಞೆಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ.

ದೈನಂದಿನ `UI Kit upstream watch` ವರ್ಕ್ಫ್ಲೋ (`.github/workflows/ui-kit-upstream-watch.yml`) ಅದೇ ಚೆಕ್ ಅನ್ನು ನಡೆಸುತ್ತದೆ. ಪಿನ್ ಹಿಂದೆ ಇರುವಾಗ, `scripts/ci/ui-kit-sync-pr.sh` ರೋಲಿಂಗ್ ಬ್ರಾಂಚ್ `chore/ui-kit-sync-latest` ನಲ್ಲಿ, ಅತ್ಯುನ್ನತ `release/vX.Y.Z` ಶಾಖೆಯ ವಿರುದ್ಧ ಒಂದು ಸಿಂಕ್ PR ತೆರೆದಿರುತ್ತದೆ. ಇದು ಎಂದಿಗೂ ವಿಲೀನಗೊಳ್ಳುವುದಿಲ್ಲ: ಪ್ರತಿ ಕಿಟ್ ಬಿಡುಗಡೆಗೆ ಇನ್ನೂ ಸ್ಥಳೀಯ VPS ನಲ್ಲಿ ದೃಶ್ಯ ಪರಿಶೀಲನೆ ಅಗತ್ಯವಿದೆ. ಹೊಸ ಬಿಡುಗಡೆಯಾದಾಗ ಶಾಖೆಯನ್ನು ಮರುನಿರ್ಮಾಣ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು ಇಲ್ಲದಿದ್ದರೆ ಏಕಾಂಗಿಯಾಗಿ ಬಿಡಲಾಗುತ್ತದೆ. ಕೈಯಿಂದ ತಳ್ಳಲ್ಪಟ್ಟ ಕಮಿಟ್ಗಳೊಂದಿಗಿನ ತೆರೆದ PR ತಿದ್ದಿ ಬರೆಯಲಾಗುವುದಿಲ್ಲ ಮತ್ತು ನಿರ್ವಾಹಕರು ಮುಚ್ಚಿದ ಆವೃತ್ತಿಗೆ ಒಂದು PR ಹೊಸ ಬಿಡುಗಡೆಯವರೆಗೂ ಮುಚ್ಚದೇ ಇರುತ್ತದೆ.

ಯಾವುದೇ PR ತೆರೆಯಲು ಸಾಧ್ಯವಾಗದಿದ್ದಾಗ (ಗುರಿ ಬಿಡುಗಡೆಯನ್ನು ಫ್ರೀಜ್ ಮಾಡಲಾಗಿದೆ, PR ಕೈಯಿಂದ ತಳ್ಳಲ್ಪಟ್ಟಿದೆ, PR ಅನ್ನು ಮುಚ್ಚಲಾಗಿದೆ, ಅಥವಾ ಯಾವುದೇ PR ಟೋಕನ್ ಅನ್ನು ಹೊಂದಿಸಲಾಗಿಲ್ಲ) ವರ್ಕ್ಫ್ಲೋ ಒಂದು ಟ್ರ್ಯಾಕಿಂಗ್ ಸಮಸ್ಯೆಯನ್ನು ಏಕೆ ತೆರೆಯುತ್ತದೆ ಎಂದು ಹೇಳುತ್ತದೆ.

ಕೆಲಸದ ಹರಿವು ಎರಡು ರಹಸ್ಯಗಳನ್ನು ಬಳಸುತ್ತದೆ:

- `secrets.UI_KIT_READ_TOKEN`: ಖಾಸಗಿ ಅಪ್ಸ್ಟ್ರೀಮ್ ರೆಪೊಗೆ ಓದಲು-ಮಾತ್ರ ಟೋಕನ್. ಅಪ್ಸ್ಟ್ರೀಮ್ ಪರಿಶೀಲನೆಯು ಡೇಟಾವನ್ನು ಓದಲು ಸಾಧ್ಯವಾಗದಿದ್ದಾಗ (ಯಾವುದೇ ಟೋಕನ್, ಕೆಲಸ ಮಾಡುವುದನ್ನು ನಿಲ್ಲಿಸಿದ ಟೋಕನ್, ಅಥವಾ GitHub ತಲುಪಲಾಗುವುದಿಲ್ಲ), ಅದು `unknown` ವರದಿ ಮಾಡುತ್ತದೆ ಮತ್ತು `0` ಕೋಡ್ನೊಂದಿಗೆ ನಿರ್ಗಮಿಸುತ್ತದೆ. ಕೆಲಸದ ಹರಿವು ಎಚ್ಚರಿಕೆಯನ್ನು ಬರೆಯುತ್ತದೆ ಮತ್ತು ಒಂದು ಪ್ರತ್ಯೇಕ ಟ್ರ್ಯಾಕಿಂಗ್ ಸಮಸ್ಯೆಯನ್ನು ತೆರೆದಿಡಲು ಪ್ರಯತ್ನಿಸುತ್ತದೆ; ನಂತರದ ಯಶಸ್ವಿ ಓಟವು ಪ್ರವೇಶವನ್ನು ಹಿಂದಿರುಗಿಸಿದ ನಂತರ ಅದನ್ನು ಮುಚ್ಚುತ್ತದೆ. GitHub ಸಂಚಿಕೆ API ನ ವೈಫಲ್ಯವು ಕೆಲಸವನ್ನು ವಿಫಲಗೊಳಿಸುತ್ತದೆ.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: ಈ ರೆಪೊಸಿಟರಿಯಲ್ಲಿ ಪರಿವಿಡಿ ಮತ್ತು ಪುಲ್ ವಿನಂತಿಗಳನ್ನು ಬರೆಯುವ ಪ್ರವೇಶದೊಂದಿಗೆ ಉತ್ತಮ-ಧಾನ್ಯದ ಟೋಕನ್. ಮೀಸಲಾದ ಟೋಕನ್ ಅನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಿದಾಗ ಮಾತ್ರ ಈ ವರ್ಕ್ಫ್ಲೋ ಸಿಂಕ್ರೊನೈಸೇಶನ್ PRs ತೆರೆಯುತ್ತದೆ ಅಥವಾ ನವೀಕರಿಸುತ್ತದೆ; ಅದು ಇಲ್ಲದೆ, ಕೆಲಸದ ಹರಿವು ಶಾಖೆಯನ್ನು ತಳ್ಳುತ್ತದೆ ಮತ್ತು ಯಾವುದೇ PR ತೆರೆಯಲಾಗಿಲ್ಲ ಎಂದು ವರದಿ ಮಾಡುತ್ತದೆ.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` ಅಪ್ಸ್ಟ್ರೀಮ್ `src/` ಆ ಕಮಿಟ್ನಲ್ಲಿ (`latest` = ಹೊಸ `v*` ಟ್ಯಾಗ್) `packages/ui-kit/src` ಗೆ ನಕಲಿಸುತ್ತದೆ, ಏಕ ಅನುಮತಿಸಿದ ರೂಪಾಂತರವನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ (ಇದು ಸಂಬಂಧಿತ ಆಮದುಗಳಿಂದ `.js` ಪ್ರತ್ಯಯವನ್ನು ಬಿಡುತ್ತದೆ), ಮತ್ತು ಕಾರ್ಯಸ್ಥಳದ ಆವೃತ್ತಿಯನ್ನು `packages/ui-kit/package.json` ಮತ್ತು `package-lock.json` ನಲ್ಲಿ ಅಪ್ಸ್ಟ್ರೀಮ್ ಒಂದಕ್ಕೆ ಹೊಂದಿಸುತ್ತದೆ. ನಂತರ: `git diff packages/ui-kit` ಪರಿಶೀಲಿಸಿ, ಪೂರೈಕೆದಾರರು, ಸೆಟ್ಟಿಂಗ್ಗಳು, ಕಾಂಬೊಗಳು, ಬಳಕೆ ಮತ್ತು ಎರಡೂ ಥೀಮ್ಗಳಲ್ಲಿನ ಅಂತಿಮ ಬಿಂದುಗಳ ಮೇಲೆ ದೃಶ್ಯ ಪಾಸ್ ಮಾಡಿ, `npm run check:ui-kit-snapshot` ಮತ್ತು `npm run test:vitest:ui` ರನ್ ಮಾಡಿ ಮತ್ತು ಅಪ್ಸ್ಟ್ರೀಮ್ ಚೇಂಜ್ಲಾಗ್ನೊಂದಿಗೆ PR ಅನ್ನು ತೆರೆಯಿರಿ.

## 6. README ರೇಖಾಚಿತ್ರಗಳು

ಮೂಲ `README.md` ಎಂಬೆಡ್ ಮಾಡುವ ಹನ್ನೆರಡು ರೇಖಾಚಿತ್ರಗಳು (`docs/diagrams/*.svg`) ಸ್ಥಿರ ಚಿತ್ರಕ್ಕೆ ಅನ್ವಯಿಸಲಾದ ಕಿಟ್ ಆಗಿವೆ ಮತ್ತು ಅವುಗಳನ್ನು ಕೈಯಿಂದ ಚಿತ್ರಿಸದೆ ರಚಿಸಲಾಗುತ್ತದೆ: `scripts/docs/gen-readme-*.mjs` ನಲ್ಲಿ 13 ಜನರೇಟರ್ ಫೈಲ್ಗಳು (ಹನ್ನೆರಡು ರೇಖಾಚಿತ್ರಗಳು ಮತ್ತು `gen-readme-diagrams.mjs` ಡ್ರೈವರ್) ಹಾಗೂ `tests/unit/docs/readme-*-svg.test.ts` ನಲ್ಲಿ 12 ಹಳತಾಗಿರುವಿಕೆ ಪರೀಕ್ಷೆಗಳು, ಪ್ರತಿ ರೇಖಾಚಿತ್ರಕ್ಕೆ ಒಂದು; ಪ್ರತಿಯೊಂದೂ ಕಮಿಟ್ ಮಾಡಿದ ಫೈಲ್ ಅನ್ನು ಅದರ ಜನರೇಟರ್ನ ಔಟ್ಪುಟ್ನೊಂದಿಗೆ ಬೈಟ್ ಮಟ್ಟದಲ್ಲಿ ಹೋಲಿಸುತ್ತದೆ (ಜಾಬ್ `test-unit`).

- **ಟೋಕನ್ಗಳು.** `scripts/docs/readme-diagram-theme.mjs`, Editions ಪ್ಯಾಲೆಟ್ ಅನ್ನು (ಡೀಫಾಲ್ಟ್ ನೋಟ) `packages/ui-kit/src/ci-editions.css` ನಿಂದ ನಕಲಿಸುತ್ತದೆ (`tests/unit/docs/readme-diagram-theme.test.ts` ಮೂಲಕ ಆ ಫೈಲ್ಗೆ ಪಿನ್ ಮಾಡಲಾಗಿದೆ; ಇದು ಎರಡೂ ಸ್ಕೀಮ್ಗಳಲ್ಲಿ ಪ್ರತಿಯೊಂದು ಮೇಲ್ಮೈ ಮೇಲಿನ ಪ್ರತಿಯೊಂದು ಪಠ್ಯ ಬಣ್ಣಕ್ಕೆ WCAG AA ಅನ್ನೂ ಪರಿಶೀಲಿಸುತ್ತದೆ; ಏಕೈಕ ವಿನಾಯಿತಿ, ಲೈಟ್ `warn`, ಕ್ಯಾನ್ವಾಸ್ನಲ್ಲಿ ಕಿಟ್ನ ಮೌಲ್ಯವು 4.46:1 ಆಗಿರುವುದರಿಂದ 10 % ಗಾಢಗೊಳಿಸಲಾದ ಕಿಟ್ ಎಚ್ಚರಿಕೆಯಾಗಿದೆ) ಮತ್ತು ಕಿಟ್ನ ಟೈಪ್ ಸ್ಕೇಲ್ನಲ್ಲಿ (`ci-tokens.css`) ಪಠ್ಯ ಪಾತ್ರಗಳನ್ನು ವ್ಯಾಖ್ಯಾನಿಸುತ್ತದೆ: ಎಲ್ಲದಕ್ಕೂ ಕಿಟ್ನ ತೂಕಗಳಲ್ಲಿ (400/500/600, ಡಿಸ್ಪ್ಲೇಗೆ 500) ಮತ್ತು ಟ್ರ್ಯಾಕಿಂಗ್ನೊಂದಿಗೆ Switzer, ಆದರೆ ಕೋಡ್ ಪಾತ್ರಗಳು (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`) ಮಾತ್ರ IBM Plex Mono ಆಗಿದ್ದು, ಅವುಗಳನ್ನು ಕಮಾಂಡ್ಗಳು, URLಗಳು, ಐಡೆಂಟಿಫೈಯರ್ಗಳು ಮತ್ತು ಟರ್ಮಿನಲ್ ಪರದೆಗಳಿಗೆ ಮಾತ್ರ ಬಳಸಲಾಗುತ್ತದೆ.
  ಲೈಟ್ ಮೌಲ್ಯಗಳು `:root` ನಲ್ಲಿ, ಡಾರ್ಕ್ ಮೌಲ್ಯಗಳು ಫೈಲ್ನೊಳಗೆ `prefers-color-scheme: dark` ಹಿಂದೆ ಇರುತ್ತವೆ; ಆದ್ದರಿಂದ ಪ್ರತಿ ಚಿತ್ರವೂ GitHub ನಲ್ಲಿ ವೀಕ್ಷಕರ ಸ್ಕೀಮ್ ಅನ್ನು ಅನುಸರಿಸುತ್ತದೆ.
- **ಫಾಂಟ್ಗಳು.** GitHub Markdown ಯಾವುದೇ CSS ಅನ್ನು ಹೊಂದಿರುವುದಿಲ್ಲ ಮತ್ತು camo ಪ್ರಾಕ್ಸಿಯು ಪ್ರತಿಯೊಂದು ಬಾಹ್ಯ ಫೆಚ್ ಅನ್ನು ನಿರ್ಬಂಧಿಸುತ್ತದೆ; ಆದ್ದರಿಂದ ಕಿಟ್ ಟೈಪ್ ಫೈಲ್ನೊಳಗೇ ಸಾಗಬೇಕು. ಪ್ರತಿಯೊಂದು ಜನರೇಟರ್ನ ಕೊನೆಯ ಹಂತವಾದ `scripts/docs/readme-outline.mjs`, HarfBuzz ಬಳಸಿ Switzer ಪಾತ್ರಗಳಿಗೆ ಆಕಾರ ನೀಡಿ, ಅವುಗಳನ್ನು ವೆಕ್ಟರ್ ಔಟ್ಲೈನ್ಗಳಾಗಿ (`<defs>` ಪಾತ್ಗಳು ಮತ್ತು `<use>`) ಚಿತ್ರಿಸುತ್ತದೆ; Switzer ನಲ್ಲಿ ಇಲ್ಲದ ಬಾಣಗಳು ಮತ್ತು ಜ್ಯಾಮಿತೀಯ ಸಂಕೇತಗಳನ್ನು ಅದರ ಸ್ವಂತ ಮೆಟ್ರಿಕ್ಗಳ ಆಧಾರದಲ್ಲಿ ಚಿತ್ರಿಸಲಾಗುತ್ತದೆ. ಯಾವಾಗಲೂ ಔಟ್ಲೈನ್ಗಳೇ, ಎಂಬೆಡ್ ಮಾಡಿದ ಫಾಂಟ್ ಎಂದಿಗೂ ಅಲ್ಲ: Switzer ನ ಪರವಾನಗಿ (`packages/ui-kit/src/fonts/FFL.txt`) ಲಿಖಿತ ಒಪ್ಪಿಗೆಯಿಲ್ಲದೆ ಸಬ್ಸೆಟ್ಟಿಂಗ್ ಮತ್ತು ಫಾರ್ಮ್ಯಾಟ್ ಪರಿವರ್ತನೆಯನ್ನು ನಿಷೇಧಿಸುತ್ತದೆ ಹಾಗೂ ವೆಕ್ಟರ್ ಚಿತ್ರಗಳಿಗೆ ಅನುಮತಿ ನೀಡುತ್ತದೆ; ಆದ್ದರಿಂದ Switzer `@font-face` ಅಥವಾ `data:` URI ಅನ್ನು ಮತ್ತೆ ಸೇರಿಸಬೇಡಿ. ಫೈಲ್ನಲ್ಲಿ ಉಳಿದಿರುವ ಏಕೈಕ ಫಾಂಟ್, ನೈಜ ಕೋಡ್ ಪಠ್ಯವಾಗಿಯೇ ಉಳಿಯುವ ವಿಷಯಕ್ಕಾಗಿ ಬಳಸುವ OFL IBM Plex Mono ಸಬ್ಸೆಟ್ (`scripts/docs/readme-fonts.mjs`); ಅದನ್ನು ಆ ಅಕ್ಷರಗಳಿಂದ ನಿರ್ಮಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಅದು ಎಂಬೆಡ್ ಮಾಡಲು ಸಾಧ್ಯವಾಗದ ಯಾವುದೇ ಗ್ಲಿಫ್ ದೋಷವನ್ನು ಉಂಟುಮಾಡುತ್ತದೆ.
- **ಮರುರಚನೆ.** `npm run docs:readme-diagrams` README ಕ್ರಮದಲ್ಲಿ ಎಲ್ಲಾ ಹನ್ನೆರಡನ್ನೂ ಮರುಬರೆದು, ಪ್ರತಿ ಫೈಲ್ಗೆ ಅದರ ಗಾತ್ರದೊಂದಿಗೆ ಒಂದು ಸಾಲನ್ನು ಮುದ್ರಿಸುತ್ತದೆ. ಒಂದೇ ಜನರೇಟರ್ ಅನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿಯೂ ಚಲಾಯಿಸಬಹುದು (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` ಗೆ `node --import tsx/esm` ಅಗತ್ಯವಿದೆ, ಏಕೆಂದರೆ ಅದರ ಅಂಕಿಅಂಶಗಳು `open-sse/config/freeModelCatalog.ts` ನಲ್ಲಿರುವ ಲೈವ್ ಕ್ಯಾಟಲಾಗ್ ಲೋಡರ್ನಿಂದ ಬರುತ್ತವೆ; ಕ್ಯಾಟಲಾಗ್ ಬದಲಾವಣೆಯ CI ಪರಿಣಾಮವು `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict` ನಲ್ಲಿದೆ). ಜನರೇಟರ್ ಮತ್ತು SVG ಅನ್ನು ಒಟ್ಟಿಗೆ ಕಮಿಟ್ ಮಾಡಿ.
- **ಪುರಾವೆ.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` ಸ್ಥಳೀಯ ಪರೀಕ್ಷೆಯಲ್ಲಿ ಕಡತವನ್ನು ರೆಂಡರ್ ಮಾಡುತ್ತದೆ (`<img>` ಟ್ಯಾಗ್, ನಿರ್ಬಂಧಿತ `Content-Security-Policy` ಮತ್ತು `image/svg+xml` ಪ್ರತಿಕ್ರಿಯೆ), ತಿಳಿ ಹಾಗೂ ಗಾಢ ಫ್ರೇಮ್ ಸೆರೆಹಿಡಿಯುತ್ತದೆ ಮತ್ತು ಪುಟದ ಹೊರಗಿನ ಫಾಂಟ್ ವಿನಂತಿಗಳನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ; ಅವುಗಳ ಸಂಖ್ಯೆ 0 ಆಗಿರಬೇಕು.

- **ಮಿತಿ.** ಪ್ರತಿ ಫೈಲ್ 200 KB ಗಿಂತ ಕಡಿಮೆ ಇರಬೇಕು (ಪ್ರತಿಯೊಂದು ಹಳತಾಗಿರುವಿಕೆ ಪರೀಕ್ಷೆಯೂ ಇದನ್ನು ದೃಢಪಡಿಸುತ್ತದೆ); ಯಾವುದೇ README ಚಿತ್ರಕ್ಕೆ 500 KB ಕಠಿಣ ಗರಿಷ್ಠ ಮಿತಿಯಾಗಿದೆ (SVG ಸ್ಟುಡಿಯೊ ವ್ಯಾಲಿಡೇಟರ್ನ ನಿಯಮ).
- **ಹಂಚಿಕೊಂಡ ಪಠ್ಯ, ಎಣಿಕೆಗಳು gate ನಿಂದ.** ಪ್ರತಿಯೊಂದು ಜನರೇಟರ್ ತನ್ನ ರೇಖಾಚಿತ್ರದ copy ಅನ್ನು `*_COPY` constant ನಲ್ಲಿ ಹೊಂದಿರುತ್ತದೆ (ಅಥವಾ live catalog ನಿಂದ ನಿರ್ಮಿಸುತ್ತದೆ); ಇದು ಬಿಡಿಸಲಾದ ಪಠ್ಯವೂ ಆಗಿದೆ ಮತ್ತು outlining ಹಂತದ input ಕೂಡ ಆಗಿದೆ. Canonical figures `<text>` nodes ನಲ್ಲಿ ಉಳಿಯುತ್ತವೆ (outlining ಆದ ನಂತರ `fill-opacity:0` ಕಾರಣದಿಂದ ಕಾಣಿಸುವುದಿಲ್ಲ), ಮತ್ತು ಅವುಗಳನ್ನು `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) ಓದುತ್ತದೆ; reads ಅನ್ನು gate ಮಾಡುವ ರೇಖಾಚಿತ್ರಗಳ ಹಳೆಯತನ ಪರೀಕ್ಷೆಗಳು, ರಚಿಸಲಾದ ಫೈಲ್ನಲ್ಲಿ ಅದರ validators ಅನ್ನು ಸಹ ನಡೆಸುತ್ತವೆ, ಆದ್ದರಿಂದ code ನಿಂದ ಬೇರ್ಪಡುವ figure ಪರೀಕ್ಷೆಯಲ್ಲಿ ವಿಫಲವಾಗುತ್ತದೆ — generatorನಲ್ಲಿರುವ ಸಂಖ್ಯೆಯನ್ನು ಎಂದಿಗೂ ಸರಿಪಡಿಸದೆ, gate ಓದುವ source ಅನ್ನು ಸರಿಪಡಿಸಿ.
