## 3. `src/` — Next.js ಅಪ್ಲಿಕೇಶನ್

```
src/
├── app/                  App Router pages + API routes
├── lib/                  Core libraries (DB, auth, OAuth, skills, memory, …)
├── domain/               Pure domain layer (policy, fallback, cost, lockout, …)
├── server/               Server-only modules (authz, cors, auth)

├── models/               Local model metadata / aliasing

├── store/                Client-side state stores
├── middleware/           Route-level middleware utilities (not Next.js global middleware)
```

### 3.1 `src/app/` — ಅಪ್ಲಿಕೇಶನ್ ರೂಟರ್

ಅಪ್ಲಿಕೇಶನ್ ರೂಟರ್ ಡ್ಯಾಶ್ಬೋರ್ಡ್ UI ಮತ್ತು public/management HTTP API ಎರಡನ್ನೂ ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ. ಇದೆ** ಜಾಗತಿಕ ಮಿಡಲ್ವೇರ್ ಇಲ್ಲ** ಪ್ರತಿ-ಮಾರ್ಗಕ್ಕೆ — ಪ್ರತಿಬಂಧವನ್ನು ಮಾಡಲಾಗುತ್ತದೆ.

`src/app/` ಅಡಿಯಲ್ಲಿ ಉನ್ನತ ಮಟ್ಟದ ವಿಭಾಗಗಳು:

| ಮಾರ್ಗ                                                                         | ಉದ್ದೇಶ                                               |
| ----------------------------------------------------------------------------- | ---------------------------------------------------- |
| `api/`                                                                        | ಎಲ್ಲಾ HTTP API ಮಾರ್ಗಗಳು (ಕೆಳಗಿನ ಸ್ಥಗಿತವನ್ನು ನೋಡಿ)    |
| `a2a/`                                                                        | A2A JSON-RPC 2.0 ಅಂತ್ಯಬಿಂದು (`POST /a2a`)            |
| `.well-known/agent.json/`                                                     | A2A ಏಜೆಂಟ್ ಕಾರ್ಡ್ ಡಿಸ್ಕವರಿ ಡಾಕ್ಯುಮೆಂಟ್               |
| `(dashboard)/`                                                                | ಡ್ಯಾಶ್ಬೋರ್ಡ್ UI (ಮಾರ್ಗ ಗುಂಪು, URL ಪೂರ್ವಪ್ರತ್ಯಯವಿಲ್ಲ) |
| `auth/`, `login/`, `forgot-password/`, `callback/`                            | ದೃಢೀಕರಣವು ಹರಿಯುತ್ತದೆ                                 |

| `status/`, `maintenance/`, `offline/`                                         | ಕಾರ್ಯಾಚರಣಾ ಪುಟಗಳು                                    |
| `privacy/`, `terms/`                                                          | ಕಾನೂನು ಪುಟಗಳು                                        |
| `400/`, `401/`, `403/`, `408/`, `429/`, `500/`, `502/`, `503/`                | ಸ್ಥಿರ ದೋಷ ಪುಟಗಳು                                     |

| `layout.tsx`, `page.tsx`, `globals.css`, `manifest.ts`                        | ರೂಟ್ ಶೆಲ್                                            |

2. ಕಸ್ಟಮ್ ತರ್ಕ ಅಗತ್ಯವಿದ್ದರೆ `open-sse/executors/` ನಲ್ಲಿ executor ಅನ್ನು ಸೇರಿಸಿ
   (`BaseExecutor` ಅನ್ನು ವಿಸ್ತರಿಸಿ).
3. ಅದು OpenAI ಸ್ವರೂಪವನ್ನು ಬಳಸದೇ ಇದ್ದರೆ `open-sse/translator/` ನಲ್ಲಿ translator ಅನ್ನು ಸೇರಿಸಿ.
4. OAuth-ಆಧಾರಿತವಾಗಿದ್ದರೆ, `src/lib/oauth/providers/` ಮತ್ತು
   `src/lib/oauth/services/` ಅಡಿಯಲ್ಲಿ config ಸೇರಿಸಿ.
5. `open-sse/config/providerRegistry.ts` ನಲ್ಲಿ (ಅಥವಾ `open-sse/config/` ಅಡಿಯಲ್ಲಿರುವ
   ಸ್ವರೂಪ-ನಿರ್ದಿಷ್ಟ registry ಯಲ್ಲಿ) models ಅನ್ನು ನೋಂದಾಯಿಸಿ.
6. `tests/unit/` ಅಡಿಯಲ್ಲಿ ಪರೀಕ್ಷೆಗಳನ್ನು ಬರೆಯಿರಿ.

### ಹೊಸ API route ಅನ್ನು ಸೇರಿಸಿ

1. `src/app/api/your-route/route.ts` ರಚಿಸಿ.
2. ಈ ಮಾದರಿಯನ್ನು ಅನುಸರಿಸಿ: CORS → Zod body ಮೌಲ್ಯೀಕರಣ → auth → handler ನಿಯೋಜನೆ.
3. ಹೊಸ request shape ಇದ್ದರೆ: `src/shared/validation/schemas.ts` ನಲ್ಲಿ Zod schema ಅನ್ನು ಸೇರಿಸಿ.
4. ನಿರ್ವಹಣೆಗೆ ಮಾತ್ರ ಸಂಬಂಧಿಸಿದ್ದರೆ: `src/shared/constants/publicApiRoutes.ts` ಗೆ path ಅನ್ನು ಸೇರಿಸಿ
   (ಸಾರ್ವಜನಿಕ API ಮೇಲ್ಮೈಗಾಗಿ denylist).
5. `tests/unit/` ಅಡಿಯಲ್ಲಿ ಪರೀಕ್ಷೆಗಳನ್ನು ಸೇರಿಸಿ.
6. `docs/reference/API_REFERENCE.md` ಮತ್ತು `docs/openapi.yaml` ಅನ್ನು ನವೀಕರಿಸಿ.

### ಹೊಸ DB module ಅನ್ನು ಸೇರಿಸಿ

1. `src/lib/db/yourModule.ts` ರಚಿಸಿ ಮತ್ತು `./core.ts` ನಿಂದ `getDbInstance()` ಅನ್ನು import ಮಾಡಿ.
2. ನಿಮ್ಮ domain ಗಾಗಿ CRUD functions ಅನ್ನು export ಮಾಡಿ.
3. ಹೊಸ tables ಇದ್ದರೆ: `src/lib/db/migrations/` ಅಡಿಯಲ್ಲಿ migration ಅನ್ನು ಸೇರಿಸಿ; ಅದು
   ಅನುಕ್ರಮವಾಗಿ ಸಂಖ್ಯೆ ಹೊಂದಿರಬೇಕು, idempotent ಆಗಿರಬೇಕು ಮತ್ತು transactional ಆಗಿರಬೇಕು.
4. Importers ಗಳು `@/lib/db/yourModule` ನಿಂದ ನೇರ imports ಅನ್ನು ಬಳಸಬೇಕು (barrel ಬೇಡ — ಹಳೆಯ `localDb.ts` re-export layer ಅನ್ನು ತೆಗೆದುಹಾಕಲಾಗಿದೆ).
5. `tests/unit/` ಅಡಿಯಲ್ಲಿ ಪರೀಕ್ಷೆಗಳನ್ನು ಸೇರಿಸಿ.

### ಹೊಸ MCP tool ಅನ್ನು ಸೇರಿಸಿ

1. `open-sse/mcp-server/tools/` ಅಡಿಯಲ್ಲಿ tool definition ಅನ್ನು ಸೇರಿಸಿ (ಅಥವಾ
   `open-sse/mcp-server/schemas/tools.ts` ಅನ್ನು ವಿಸ್ತರಿಸಿ).
2. `src/shared/constants/mcpScopes.ts` ನಲ್ಲಿ ಸೂಕ್ತ scope(ಗಳನ್ನು) ನಿಯೋಜಿಸಿ.
3. `open-sse/mcp-server/server.ts` ನಲ್ಲಿ tool ಅನ್ನು ನೋಂದಾಯಿಸಿ.
4. `open-sse/mcp-server/__tests__/` ಅಡಿಯಲ್ಲಿ ಪರೀಕ್ಷೆಗಳನ್ನು ಸೇರಿಸಿ.
5. [MCP-SERVER.md](../frameworks/MCP-SERVER.md) ಅನ್ನು ನವೀಕರಿಸಿ.

### ಹೊಸ A2A skill ಅನ್ನು ಸೇರಿಸಿ

[A2A-SERVER.md § ಹೊಸ Skill ಸೇರಿಸುವುದು](../frameworks/A2A-SERVER.md) ನೋಡಿ. Skills ಗಳು
`src/lib/a2a/skills/` ನಲ್ಲಿ ಇರುತ್ತವೆ ಮತ್ತು A2A task manager ಮೂಲಕ ನೋಂದಾಯಿಸಲ್ಪಡುತ್ತವೆ.

## 11. ಸಂಪ್ರದಾಯಗಳು

- **Code style**: 2-space indent, double quotes, 100 char width, semicolons,
  `es5` trailing commas — `lint-staged` ಮೂಲಕ Prettier ಇದನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತದೆ.
- **Imports**: external → internal (`@/`, `@omniroute/open-sse`) → relative.
- **Naming**: files `camelCase` ಅಥವಾ `kebab-case`, components `PascalCase`,
  constants `UPPER_SNAKE`.
- **ESLint**: ಎಲ್ಲೆಡೆ `no-eval`, `no-implied-eval`, `no-new-func` = `error`;
  `open-sse/` ಮತ್ತು `tests/` ನಲ್ಲಿ `no-explicit-any` = `warn`, ಇತರೆಡೆ error.
- **TypeScript**: `strict: false` (legacy ನಿಲುವು). Cross-module boundaries ಗಾಗಿ
  inference ಗಿಂತ explicit types ಗೆ ಆದ್ಯತೆ ನೀಡಿ.
- **Database**: routes ಅಥವಾ handlers ನಲ್ಲಿ raw SQL ಅನ್ನು ಎಂದಿಗೂ ಬರೆಯಬೇಡಿ — ಯಾವಾಗಲೂ
  `src/lib/db/` modules ಮೂಲಕವೇ ಕಾರ್ಯನಿರ್ವಹಿಸಿ. Barrel-import ಅನ್ನು ಎಂದಿಗೂ ಮಾಡಬೇಡಿ — ನಿರ್ದಿಷ್ಟ `src/lib/db/*` modules ಅನ್ನು ನೇರವಾಗಿ ಬಳಸಿ.
- **DB-entity typing (#3512)**: DB table ನ row shape ಅನ್ನು ಬರೆಯುವ ಅಥವಾ ಓದುವ
  function, ಆ table ನ columns ಅನ್ನು 1:1 ಪ್ರತಿಬಿಂಬಿಸುವ ಹೆಸರಿಸಲಾದ TS interface ಅನ್ನು
  ತೆಗೆದುಕೊಳ್ಳಬೇಕು/ಹಿಂತಿರುಗಿಸಬೇಕು; call site ನಲ್ಲಿ `any` ಅಥವಾ inline anonymous type ಅನ್ನು ಬಳಸಬಾರದು. Interface ಅನ್ನು
  function ನ ಪಕ್ಕದಲ್ಲೇ ಇರಿಸಿ (ಉದಾ. `saveRequestUsage` ಮೇಲಿನ
  `src/lib/usage/usageHistory.ts` ನಲ್ಲಿ `export interface UsageEntry`), ವಿಭಿನ್ನ writers ಗಳು row ಅನ್ನು
  ಹಂತ ಹಂತವಾಗಿ ತುಂಬುವಾಗ ಪ್ರತ್ಯೇಕ fields ಅನ್ನು optional/nullable ಆಗಿರಿಸಿ, ಮತ್ತು callers ಗಳಾದ್ಯಂತ shape
  ಬದಲಾಗುವ field ಗೆ `any` ಬದಲು `unknown` ಗೆ ಆದ್ಯತೆ ನೀಡಿ (field ಮೇಲೆ ಇದನ್ನು ದಾಖಲಿಸಿ, ಉದಾ. `UsageEntry.tokens`
  raw provider-shaped usage ಮತ್ತು normalized shape ಎರಡನ್ನೂ ಸ್ವೀಕರಿಸುತ್ತದೆ). ಈ ರೀತಿಯಲ್ಲಿ
  file ನ `any` count ಶೂನ್ಯಕ್ಕೆ ತಲುಪಿದ ನಂತರ, regression ಆಗದಂತೆ ಅದನ್ನು
  `check:any-budget:t11` allowlist ಗೆ (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`) ಸೇರಿಸಿ. ಇದು first-slice ಸಂಪ್ರದಾಯವಾಗಿದೆ — ವಿಶಾಲವಾದ "anonymous `any` ಬೇಡ" cleanup ಅನ್ನು ಉಳಿದ
  codebase ನಾದ್ಯಂತ ಪುನರಾವರ್ತಿತವಾಗಿ ನಡೆಸಲಾಗುತ್ತದೆ.
- **Errors**: ನಿರ್ದಿಷ್ಟ error types ಜೊತೆ try/catch ಬಳಸಿ, pino context ಜೊತೆ log ಮಾಡಿ. SSE streams ನಲ್ಲಿ errors ಅನ್ನು
  ಎಂದಿಗೂ ಮೌನವಾಗಿ ನಿರ್ಲಕ್ಷಿಸಬೇಡಿ; cleanup ಗಾಗಿ abort signals ಬಳಸಿ.
- **Security**: `eval()` / `new Function()` / implied eval ಅನ್ನು ಎಂದಿಗೂ ಬಳಸಬೇಡಿ. ಎಲ್ಲಾ
  inputs ಅನ್ನು Zod ಮೂಲಕ ಮೌಲ್ಯೀಕರಿಸಿ. ಸಂಗ್ರಹಿತ credentials ಅನ್ನು encrypt ಮಾಡಿ (AES-256-GCM).
  `src/shared/constants/upstreamHeaders.ts` denylist ಅನ್ನು sanitize/validation layer ಜೊತೆ ಹೊಂದಾಣಿಕೆಯಲ್ಲಿ ಇರಿಸಿ.
- **Commits**: Conventional Commits — `feat(scope): subject`. ಅನುಮತಿಸಲಾದ scopes:
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`.
- **Branches**: prefixes `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`. `main` ಗೆ ಎಂದಿಗೂ ನೇರವಾಗಿ commit ಮಾಡಬೇಡಿ.
- **Husky**: pre-commit ವೇಳೆ `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11` ರನ್ ಆಗುತ್ತವೆ; pre-push ವೇಳೆ `check:any-budget:t11` + `check:tracked-artifacts` ರನ್ ಆಗುತ್ತವೆ (ವೇಗದ gates; `test:unit` ಅನ್ನು ಹೊರತುಪಡಿಸುತ್ತದೆ).

## 12. ಕಠಿಣ ನಿಯಮಗಳು (CLAUDE.md ನಿಂದ)

1. ರಹಸ್ಯಗಳು ಅಥವಾ ರುಜುವಾತುಗಳನ್ನು ಎಂದಿಗೂ ಕಮಿಟ್ ಮಾಡಬೇಡಿ.
2. ಬ್ಯಾರೆಲ್-ಇಂಪೋರ್ಟ್ ಅನ್ನು ಎಂದಿಗೂ ಬಳಸಬೇಡಿ — ನಿರ್ದಿಷ್ಟ `src/lib/db/*` ಮಾಡ್ಯೂಲ್ಗಳನ್ನು ನೇರವಾಗಿ ಬಳಸಿ.
3. `eval()` / `new Function()` / ಪರೋಕ್ಷ eval ಅನ್ನು ಎಂದಿಗೂ ಬಳಸಬೇಡಿ.
4. `main` ಗೆ ಎಂದಿಗೂ ನೇರವಾಗಿ ಕಮಿಟ್ ಮಾಡಬೇಡಿ.
5. ರೂಟ್ಗಳಲ್ಲಿ ಕಚ್ಚಾ SQL ಅನ್ನು ಎಂದಿಗೂ ಬರೆಯಬೇಡಿ — ಯಾವಾಗಲೂ `src/lib/db/` ಮಾಡ್ಯೂಲ್ಗಳ ಮೂಲಕವೇ ಬಳಸಿ.
6. SSE ಸ್ಟ್ರೀಮ್ಗಳಲ್ಲಿನ ದೋಷಗಳನ್ನು ಎಂದಿಗೂ ಮೌನವಾಗಿ ನಿರ್ಲಕ್ಷಿಸಬೇಡಿ.
7. ಇನ್ಪುಟ್ಗಳನ್ನು ಯಾವಾಗಲೂ Zod ಸ್ಕೀಮಾಗಳೊಂದಿಗೆ ಮೌಲ್ಯೀಕರಿಸಿ.
8. ಪ್ರೊಡಕ್ಷನ್ ಕೋಡ್ ಅನ್ನು ಬದಲಾಯಿಸುವಾಗ ಯಾವಾಗಲೂ ಪರೀಕ್ಷೆಗಳನ್ನು ಸೇರಿಸಿ.
9. ವ್ಯಾಪ್ತಿಯು (ಸ್ಟೇಟ್ಮೆಂಟ್ಗಳು, ಸಾಲುಗಳು, ಫಂಕ್ಷನ್ಗಳು, ಬ್ರಾಂಚ್ಗಳು) ≥ 60% ಆಗಿಯೇ ಉಳಿಯಬೇಕು.
