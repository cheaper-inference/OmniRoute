## ಬಿಡುಗಡೆ ಶಾಖೆಯ ಮೇಲೆ ಇಳಿಯುವುದು

ಓಮ್ನಿ-ಕ್ಯೂ `release/vX.Y.Z` ಗೆ ಇಳಿಯುವಿಕೆಯನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ. PR ಇಳಿಸುವ ಮೊದಲು ಡೀಫಾಲ್ಟ್ ಶಾಖೆಯಲ್ಲಿ ಉನ್ನತ ಮಟ್ಟದ `mode` `config/merge-queue/config.json` ನಲ್ಲಿ ಓದಿ. [ಓಮ್ನಿ-ಕ್ಯೂ](OMNI_QUEUE.md) ನೋಡಿ.

- **`shadow`** ಊರ್ಜಿತಗೊಳಿಸುವಿಕೆಯನ್ನು ರನ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಹಸ್ತಚಾಲಿತ ವಿಲೀನಕ್ಕೆ ಇಳಿಯುವಿಕೆಯನ್ನು ಬಿಡುತ್ತದೆ. `omni-queue` ಅದರ ಅಂತಿಮ ತಲೆಯಲ್ಲಿರುವ ಅನುಮೋದಿತ PR ಗೆ ಅನ್ವಯಿಸಿ. `npm run queue -- why <PR>` ನೊಂದಿಗೆ ಅರ್ಹತೆಯನ್ನು ಪರಿಶೀಲಿಸಿ. `npm run queue -- history --base <branch>` ನಲ್ಲಿ ಆ ತಲೆಯ ತೀರ್ಪಿಗಾಗಿ ಕಾಯಿರಿ. `would-land` ನಲ್ಲಿ ಮುಂದುವರಿಯಿರಿ. `culprit-found` ಅಥವಾ `would-dequeue` ನಲ್ಲಿ, ವಿಲೀನವನ್ನು ಹಿಡಿದುಕೊಳ್ಳಿ ಮತ್ತು ಕಾರಣವನ್ನು ಸರಿಪಡಿಸಿ.
- **ನೆರಳು ವಿನಾಯಿತಿಗಳು.** ಪ್ರಸ್ತುತ ಮೂಲ ತುದಿಗೆ ವಿರುದ್ಧವಾಗಿ ಹಸಿರು ಪೂರ್ಣ CI ಹೊಂದಿರುವ ರೈಲು ಪ್ರತ್ಯೇಕ ಸರತಿ ತೀರ್ಪು ಇಲ್ಲದೆ ಮುಂದುವರಿಯಬಹುದು. PR ಹೆಡ್ ಈಗಾಗಲೇ ಪ್ರಸ್ತುತ ಮೂಲ ತುದಿಯನ್ನು ಹೊಂದಿರುವಾಗ ಅದೇ ವಿನಾಯಿತಿ ಅನ್ವಯಿಸುತ್ತದೆ.
- **`live`** ಲ್ಯಾಂಡಿಂಗ್ ಅನ್ನು ಪ್ರಚೋದಿಸಲು `omni-queue` ಲೇಬಲ್ ಅನ್ನು ಬಳಸುತ್ತದೆ. ಕ್ಯೂ ಮಾತ್ರ PR ಅನ್ನು ಇಳಿಸುತ್ತದೆ. ಸರದಿಯಲ್ಲಿ ವಿಲೀನಗೊಳಿಸುವ ಆಜ್ಞೆಗಳು ಮತ್ತು ನೇರ ತಳ್ಳುವಿಕೆಗಳನ್ನು ಬಿಡಿ.

ಪ್ರತಿ ಲ್ಯಾಂಡಿಂಗ್ಗೆ ಮಾಲೀಕರ ದೃಢೀಕರಣ ಮತ್ತು ಅನ್ವಯವಾಗುವ ಅಗತ್ಯವಿರುವ ಚೆಕ್ಗಳ ಅಗತ್ಯವಿದೆ. ಮಾಲೀಕರು ಲ್ಯಾಂಡಿಂಗ್ ಅನ್ನು ಅಧಿಕೃತಗೊಳಿಸಿದ ನಂತರ ಮಾತ್ರ `omni-queue` ಅನ್ವಯಿಸಿ. ಸಂರಕ್ಷಿತ ಮಾರ್ಗಗಳನ್ನು ಸ್ಪರ್ಶಿಸುವ ಸರತಿಯಲ್ಲಿರುವ PRs ಆ PR ಗಾಗಿ ಮಾಲೀಕರ `protected-approved` ನಿರ್ಧಾರದ ಅಗತ್ಯವಿರುತ್ತದೆ.

"ಸಕ್ರಿಯ ಬಿಡುಗಡೆಯಲ್ಲಿ ಹಸಿರು ಗೇಟ್ಸ್ ಅಗತ್ಯವಿದೆ" ನಿಯಮಾವಳಿಗೆ ತಲೆಯ ಮೇಲೆ ಹಸಿರು `Gate / CI` ಮತ್ತು `Gate / Quality` ಅಗತ್ಯವಿದೆ. ಕೆಂಪು ಗೇಟ್ ಅನ್ನು ಬೈಪಾಸ್ ಮಾಡಲು ಎಂದಿಗೂ `--admin` ಬಳಸಬೇಡಿ. ಬಿಡುಗಡೆಯ ಫ್ರೀಜ್ ಬ್ಲಾಕ್ಗಳು ಹೆಪ್ಪುಗಟ್ಟಿದ ಶಾಖೆಯಲ್ಲಿ ವಿಲೀನಗೊಳ್ಳುತ್ತದೆ. [ಕಠಿಣ ನಿಯಮ 21 ಅನ್ನು](HARD_RULES_DETAIL.md) ನೋಡಿ. ಮತ್ತೊಂದು ಸೆಷನ್ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿದೆ ಎಂದು ಎಂದಿಗೂ ಲೇಬಲ್ ಮಾಡಬೇಡಿ, ವಿಲೀನಗೊಳಿಸಬೇಡಿ ಅಥವಾ ಪುಲ್ ವಿನಂತಿಯನ್ನು ತಳ್ಳಬೇಡಿ. [ಕಠಿಣ ನಿಯಮ 22](HARD_RULES_DETAIL.md) ನೋಡಿ.

## ರೈಲು ಎಳೆಯಲು ವಿನಂತಿ

1. ಪ್ರಸ್ತುತ ಬಿಡುಗಡೆಯ ಮೂಲ ತುದಿಯಲ್ಲಿ ರೈಲು ಶಾಖೆಯನ್ನು ಪ್ರಾರಂಭಿಸಿ. ವಿಲೀನ ಕಮಿಟ್ಗಳನ್ನು ಬಳಸಿಕೊಂಡು ನಿಖರವಾದ ಅನುಮೋದಿತ ಸದಸ್ಯ ಮುಖ್ಯಸ್ಥರನ್ನು ಸಂಯೋಜಿಸಿ. ಸ್ಕ್ವ್ಯಾಷ್ ಮತ್ತು ರಿಬೇಸ್ ಅನ್ನು ತಪ್ಪಿಸುವ ಮೂಲಕ ಅವರ ಬದ್ಧತೆಯ ಇತಿಹಾಸವನ್ನು ಸಂರಕ್ಷಿಸಿ.
2. ರೈಲು ಶಾಖೆಗಾಗಿ ಒಂದು ಪುಲ್ ವಿನಂತಿಯನ್ನು ತೆರೆಯಿರಿ. ಪ್ರಸ್ತುತ ಮೂಲ ತುದಿಯಲ್ಲಿ ತನ್ನದೇ ಆದ ಪೂರ್ಣ CI ನೊಂದಿಗೆ ಆ PR ಮೌಲ್ಯೀಕರಿಸಿ. ಇಳಿಯುವ ಮೊದಲು ಬೇಸ್ ಟಿಪ್ ಮತ್ತು ಅನುಮೋದಿತ ಸದಸ್ಯ ಮುಖ್ಯಸ್ಥರನ್ನು ಮರುಪರಿಶೀಲಿಸಿ. ಮೌಲ್ಯೀಕರಿಸಿದ ಅಭ್ಯರ್ಥಿ ಬದಲಾದಾಗ ರೈಲು ಮತ್ತು ಅದರ CI ರಿಫ್ರೆಶ್ ಮಾಡಿ.
3. ಅನ್ವಯವಾಗುವ ಕ್ಯೂ ಮೋಡ್ ಅಡಿಯಲ್ಲಿ ವಿಲೀನ ಬದ್ಧತೆಯೊಂದಿಗೆ ರೈಲು PR ಇಳಿಸಿ. ಲೈವ್ ಮೋಡ್ನಲ್ಲಿ, ಸರದಿಯ `merge-ff` ಲ್ಯಾಂಡಿಂಗ್ ವಿಧಾನವು ವಿಲೀನದ ಕಮಿಟ್ಗಳನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ. ಮೂಲ ಸದಸ್ಯ ಮುಖ್ಯಸ್ಥರು ಬಿಡುಗಡೆ ಶಾಖೆಯಿಂದ ತಲುಪಬಹುದು. GitHub ಸದಸ್ಯ PRs ವಿಲೀನಗೊಳಿಸಲಾಗಿದೆ ಎಂದು ಗುರುತಿಸುತ್ತದೆ ಮತ್ತು ಕಮಿಟ್ಗಳು ತಮ್ಮ ಲೇಖಕರನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ.

ಸಾರ್ವಜನಿಕ ಉದಾಹರಣೆಯೆಂದರೆ [PR #21071](https://github.com/cheaper-inference/OmniRoute/pull/21071). ಇದು 18 ಸದಸ್ಯರ PRs ಸಂಯೋಜಿಸಿತು ಮತ್ತು 2026-11-24 ರಂದು ವಿಲೀನ ಬದ್ಧತೆಯೊಂದಿಗೆ ಇಳಿಯಿತು.

`main` ನಿಂದ ಮುಂದಿನ ಬಿಡುಗಡೆ ಶಾಖೆಗೆ ಸಿಂಕ್-ಬ್ಯಾಕ್ ಕೂಡ ವಿಲೀನ ಬದ್ಧತೆಯ ಮೂಲಕ ಇಳಿಯುತ್ತದೆ. ನಂತರದ ಸಿಂಕ್-ಬ್ಯಾಕ್ಗಳಿಗೆ `main` ವಂಶಾವಳಿಯನ್ನು ಸಂರಕ್ಷಿಸುವ ಅಗತ್ಯವಿದೆ. [ವರ್ಕ್ಟ್ರೀ ಪ್ರತ್ಯೇಕತೆಯನ್ನು](WORKTREE_ISOLATION.md#sync-back-landings-are-merge-commits-never-squash) ನೋಡಿ.

## ಸ್ಥಳೀಯ ವಿಲೀನ-ರೈಲು ವ್ಯಾಲಿಡೇಟರ್

```bash
scripts/release/merge-train.sh [--plan] [--fast] <base-branch> <PR#> [<PR#>...]
```

ವ್ಯಾಲಿಡೇಟರ್ ಬೇಸ್ ಮತ್ತು PR ಹೆಡ್ಗಳನ್ನು ಪಡೆಯುತ್ತದೆ ಮತ್ತು ಅವುಗಳನ್ನು ಬಿಸಾಡಬಹುದಾದ ವರ್ಕ್ಟ್ರೀನಲ್ಲಿ ಸಂಯೋಜಿಸುತ್ತದೆ. ಇದು ಪರಿಣಾಮವಾಗಿ ಮರದ ಮೇಲೆ ಒಮ್ಮೆ ತನ್ನ ಪ್ಯಾರಿಟಿ ಸೂಟ್ ಅನ್ನು ರನ್ ಮಾಡುತ್ತದೆ. ವಿಫಲವಾದ ತಲೆ ಪಡೆಯುವಿಕೆ ಅಥವಾ ವಿಲೀನ ಸಂಘರ್ಷವು PR ಅನ್ನು ಹೊರಹಾಕುತ್ತದೆ ಮತ್ತು ಸ್ಕ್ರಿಪ್ಟ್ ಉಳಿದ PRs ನೊಂದಿಗೆ ಮುಂದುವರಿಯುತ್ತದೆ.

- **`--plan`** ಆಯ್ಕೆಮಾಡಿದ ಮೋಡ್ನ ಹಂತಗಳನ್ನು ಮುದ್ರಿಸುತ್ತದೆ ಮತ್ತು ವರ್ಕ್ಟ್ರೀಯನ್ನು ರಚಿಸದೆ ಅಥವಾ ರಿಮೋಟ್ ಅನ್ನು ಸಂಪರ್ಕಿಸದೆ ನಿರ್ಗಮಿಸುತ್ತದೆ. ವೇಗದ ಯೋಜನೆಯನ್ನು ಪರಿಶೀಲಿಸಲು ಅದನ್ನು `--fast` ನೊಂದಿಗೆ ಸಂಯೋಜಿಸಿ.
- **`--fast`** ಸಾಮಾನ್ಯ ಸ್ಥಿರ ಗೇಟ್ಗಳನ್ನು ರನ್ ಮಾಡುತ್ತದೆ, `tests/unit/`, ಮತ್ತು `npm run test:vitest` ಅಡಿಯಲ್ಲಿ ಆಯ್ಕೆಮಾಡಿದ ಬದಲಾದ `node:test` ಫೈಲ್ಗಳು. ವೇಗದ ಮೋಡ್ ಅನ್ನು ಬಳಸುವಾಗ ಸಂಗ್ರಹವಾದ ತುದಿಯಲ್ಲಿ ದಿನಕ್ಕೆ ಒಮ್ಮೆಯಾದರೂ ಪೂರ್ಣ ಸ್ಥಳೀಯ ಮೌಲ್ಯೀಕರಣವನ್ನು ರನ್ ಮಾಡಿ.
- **ಪೂರ್ಣ ಮೋಡ್** ಪೂರ್ಣ-ಮಾತ್ರ ಸ್ಥಿರ ಗೇಟ್ಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ ಮತ್ತು `npm run test:unit` ಮತ್ತು `npm run test:vitest` ರನ್ ಮಾಡುತ್ತದೆ.

ಬೇಸ್ ಪ್ರೋಬ್ ಲಭ್ಯವಿದ್ದಲ್ಲಿ ವಿಫಲವಾದ ಸ್ಥಿರ ಗೇಟ್ ಅನ್ನು ಸ್ಪರ್ಶಿಸದ ತಳದಲ್ಲಿ ಮರುರನ್ ಮಾಡಲಾಗುತ್ತದೆ. ಸ್ಕ್ರಿಪ್ಟ್ ಅನುವಂಶಿಕ ವೈಫಲ್ಯಗಳನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ ಮತ್ತು ಪ್ರತಿ ಗುರುತಿಸಲಾದ ಉಲ್ಲಂಘನೆ ರೇಖೆಯು ತಳದಲ್ಲಿ ಕಾಣಿಸಿಕೊಂಡಾಗ ಮತ್ತು ಒಟ್ಟು ಎಣಿಕೆಯು ಬೆಳೆಯದಿದ್ದಾಗ ಮುಂದುವರಿಯುತ್ತದೆ.

| `0`       | ಯೋಜನೆಯನ್ನು ಮುದ್ರಿಸಲಾಗಿದೆ ಅಥವಾ ಸೂಟ್ ಅನ್ನು ಪೂರ್ಣಗೊಳಿಸಿದೆ. ಸೂಟ್ ಸಾರಾಂಶವು ಯಾವುದೇ ಆನುವಂಶಿಕ ಸ್ಥಿರ ವೈಫಲ್ಯಗಳು ಮತ್ತು ಹೊರಹಾಕಲ್ಪಟ್ಟ PRs ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ.    |

ಸ್ಥಳೀಯ ಪಾಸ್ ಮಾಲೀಕರ ದಸ್ತಾವೇಜಿಗೆ ಮಾತ್ರ ರೋಗನಿರ್ಣಯದ ಸಾಕ್ಷ್ಯವನ್ನು ಒದಗಿಸುತ್ತದೆ. ಪ್ರತಿ ಲ್ಯಾಂಡಿಂಗ್ಗೆ ಇನ್ನೂ ಮಾಲೀಕರ ದೃಢೀಕರಣದ ಅಗತ್ಯವಿರುತ್ತದೆ, ಅದರ ಸ್ವಂತ ಅಗತ್ಯ ಪರಿಶೀಲನೆಗಳು ಮತ್ತು ಅನ್ವಯಿಸಿದಾಗ ನೆರಳು ಸರತಿ ತೀರ್ಪು ಅಗತ್ಯವಿರುತ್ತದೆ.

## ಶ್ರೇಣೀಕರಣ

- **ಪ್ರತಿ PR** ಬದಲಾದ ಮಾರ್ಗಗಳ ಆಧಾರದ ಮೇಲೆ CI ಮತ್ತು ಗುಣಮಟ್ಟವನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತದೆ. ಕೋಡ್ PRs ವೇಗದ ಗುಣಮಟ್ಟದ ಗೇಟ್ಗಳು ಮತ್ತು ಪ್ರಭಾವಿತ ಪರೀಕ್ಷೆಗಳನ್ನು ನಡೆಸುತ್ತದೆ, CI ನಲ್ಲಿ ಪ್ರತ್ಯೇಕ ಘಟಕ ಮತ್ತು Vitest ಉದ್ಯೋಗಗಳು.
- **ಪ್ರತಿ ಸರತಿ ಅಭ್ಯರ್ಥಿಗೆ.** CI ಮತ್ತು ಗುಣಮಟ್ಟವು ಸಂಯೋಜನೆಗೊಂಡ ಅಭ್ಯರ್ಥಿಯ ಸಂಪೂರ್ಣ ಪ್ರೊಫೈಲ್ ಅನ್ನು ಅದರ ಕ್ಯೂ ರೆಫರೆನ್ಸ್ನಲ್ಲಿ ರನ್ ಮಾಡುತ್ತದೆ.
- **ಪ್ರತಿ ಬಿಡುಗಡೆಯ ಸಲಹೆ.** ಬಿಡುಗಡೆ-ಹಸಿರು ಅದರ ಮಾರ್ಗ ಫಿಲ್ಟರ್ಗಳಿಗೆ ಹೊಂದಿಕೆಯಾಗುವ ಪುಶ್ಗಳಲ್ಲಿ ತ್ವರಿತ ಹಾರ್ಡ್ ಗೇಟ್ಗಳನ್ನು ರನ್ ಮಾಡುತ್ತದೆ. ದಿನಕ್ಕೆ ಮೂರು ನಿಗದಿತ ರನ್ಗಳು ಬಿಡುಗಡೆಯ ಶಾಖೆಗಾಗಿ ಪೂರ್ಣ ಸ್ವೀಪ್ ಅನ್ನು ಬಳಸುತ್ತವೆ.
- **ಪ್ರತಿ ಬಿಡುಗಡೆಗೆ.** ಪೂರ್ಣ CI ಮ್ಯಾಟ್ರಿಕ್ಸ್ನಲ್ಲಿ E2E ಚೂರುಗಳು, ಪ್ಯಾಕೇಜ್ ಮೌಲ್ಯೀಕರಣ, ಟಾರ್ಬಾಲ್ ಬೂಟ್ ಸ್ಮೋಕ್ ಮತ್ತು ಕವರೇಜ್ ಚೆಕ್ಗಳು ಸೇರಿವೆ. [ಬಿಡುಗಡೆ ಪರಿಶೀಲನಾಪಟ್ಟಿಯನ್ನು](RELEASE_CHECKLIST.md) ನೋಡಿ.

## `merge-train.sh` ಗಾಗಿ ತಾಜಾ-ಚೆಕ್ಔಟ್ ಪೂರ್ವಾಪೇಕ್ಷಿತಗಳು

ವರ್ಕ್ಟ್ರೀಗಳನ್ನು ರಚಿಸುವ ಮೊದಲು ಪ್ರಿಫ್ಲೈಟ್ ಸಾಗುತ್ತದೆ. `npm ci` ನೊಂದಿಗೆ ಅವಲಂಬನೆಗಳನ್ನು ಸ್ಥಾಪಿಸಿ. `node_modules/.bin/tsc` ಕಾರ್ಯಗತಗೊಳಿಸಬಲ್ಲದು ಮತ್ತು `node_modules/node_modules` ಗೈರುಹಾಜವಾಗಿದೆ ಎಂದು ಖಚಿತಪಡಿಸಿ. `node_modules/.bin/bun --version` ಯಶಸ್ವಿಯಾಗಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ.

Bun postinstall ಅನ್ನು ಬಿಟ್ಟುಬಿಟ್ಟರೆ, `(cd node_modules/bun && node install.js)` ರನ್ ಮಾಡಿ. ಪೂರೈಕೆದಾರರ ಸ್ಥಿರತೆ ಮತ್ತು ತಿಳಿದಿರುವ-ಚಿಹ್ನೆ ಪರಿಶೀಲನೆಗಳು Bun ಬಳಸುತ್ತವೆ. ವ್ಯಾಲಿಡೇಟರ್ `npm run check:cycles:ratchet` ತಡೆಯುವ ಗೇಟ್ ಆಗಿ ರನ್ ಮಾಡುತ್ತದೆ. ಸ್ವತಂತ್ರ `npm run check:cycles` ಆಜ್ಞೆಯು ಸಲಹೆಯಾಗಿದೆ.
