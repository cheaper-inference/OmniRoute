OmniRoute runnerಗೆ **ಒಂದು ಪಾತ್ರ**, ಒಂದು label ಮತ್ತು ಅದರ workloadನಲ್ಲಿ ಅಳೆಯಲಾದ ಬಳಕೆಗೆ ಅನುಗುಣವಾದ memory/CPU
ಬಜೆಟ್ ಇದೆ. Turbopack slotಗೆ buildಗೆ ಅಗತ್ಯವಿರುವಷ್ಟು ಸಂಪನ್ಮೂಲಗಳು ದೊರೆಯುತ್ತವೆ; ಇತರ slotಗಳನ್ನು ಅವುಗಳ

webpack build ಮತ್ತು lint job ಒಂದೇ ಸಮಯದಲ್ಲಿ ನಡೆದಾಗ ಮಾತ್ರ ಬಾಕ್ಸ್ ಸಂಪನ್ಮೂಲಗಳನ್ನು ಮಿತಿಮೀರಿ ಹಂಚುತ್ತದೆ;

ಮಿತಿಗಳು ಪ್ರತಿ unitನ `/etc/systemd/system/actions.runner.<…>.service.d/override.conf`ನಲ್ಲಿ

`systemctl set-property --runtime … MemoryHigh=… MemoryMax=… CPUQuota=…` ಮೂಲಕ ಚಾಲನೆಯಲ್ಲಿರುವಾಗಲೇ ಅನ್ವಯಿಸಲಾಗಿದೆ — restart ಮಾಡಿಲ್ಲ, ಆದ್ದರಿಂದ ಚಾಲನೆಯಲ್ಲಿದ್ದ
ಯಾವುದೇ job ಮೇಲೆ ಪರಿಣಾಮ ಬೀರಿಲ್ಲ. Labelಗಳನ್ನು runners API ಮೂಲಕ (`gh api -X DELETE repos/<repo>/actions/runners/<id>/labels/<label>` /
`gh api -X POST repos/<repo>/actions/runners/<id>/labels -f 'labels[]=<label>'`) ಚಾಲನೆಯಲ್ಲಿರುವಾಗಲೇ ಬದಲಾಯಿಸಲಾಗುತ್ತದೆ.

## ಜಾನಿಟರ್ ಅನ್ನು ಸ್ಥಾಪಿಸಿ (ಒಮ್ಮೆ ಮಾತ್ರ, ಯಂತ್ರದಲ್ಲಿ)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ಪ್ರತಿ 30 ನಿಮಿಷಕ್ಕೆ, /var/log/runner-janitor.log ಗೆ ಲಾಗ್ ಮಾಡಿ
*/30 * * * * MAX_ACTIVE_RUNNERS=8 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` ಅಗತ್ಯವಿದೆ: ಜಾನಿಟರ್ ಪಥವನ್ನು ತೆಗೆದುಹಾಕುವ ಮೊದಲು ತೆರೆದಿರುವ ಫೈಲ್ಗಳ ಒಂದು
ಸ್ನ್ಯಾಪ್ಶಾಟ್ನೊಂದಿಗೆ ಅದು ನಿಷ್ಕ್ರಿಯವಾಗಿದೆ ಎಂದು ಖಚಿತಪಡಿಸುತ್ತದೆ; ಈ ಪರಿಕರ ಇಲ್ಲದಿದ್ದರೆ ಅದು ಏನನ್ನೂ
ತೆಗೆದುಹಾಕುವುದಿಲ್ಲ ಮತ್ತು ಅದನ್ನು ತಿಳಿಸುತ್ತದೆ (exit 1). ಯಾವುದೇ ಬದಲಾವಣೆಯನ್ನು ಮೊದಲು `--dry-run`
ನೊಂದಿಗೆ ಪ್ರಯತ್ನಿಸಿ — ಅದು ಏನು ಮಾಡಲಿದೆ ಎಂಬುದನ್ನು ನಿಖರವಾಗಿ ಮುದ್ರಿಸುತ್ತದೆ ಮತ್ತು ಯಾವುದನ್ನೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ.

ಪ್ರತಿ ಚಾಲನೆಯಲ್ಲಿ ಅದು ಮಾಡುವ ಕೆಲಸ: **tmpfs ನಲ್ಲಿ 3 ಗಂ.** ಮತ್ತು ಡಿಸ್ಕ್ನ
`_work/_temp` ನಲ್ಲಿ 24 ಗಂ. ಕಳೆದ ನಂತರ ನಮ್ಮದೇ ಉಳಿಕೆಗಳನ್ನು (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) ತೆರವುಗೊಳಿಸುತ್ತದೆ; 75 ನಿಮಿಷಗಳಿಗಿಂತ ಹಳೆಯದಾದ
`next-build` ಅನ್ನು ಕೊನೆಗೊಳಿಸುತ್ತದೆ (ಯಾವುದೇ ಜಾಬ್ ಅಷ್ಟು ದೀರ್ಘವಾಗಿ ಚಾಲನೆಯಾಗುವುದಿಲ್ಲ — 2026-08-27 ರಂದು
GitHub ತನ್ನ ಜಾಬ್ ಕಳೆದುಹೋಗಿದೆ ಎಂದು ಘೋಷಿಸಿದ ನಂತರವೂ ಒಂದು ಜಾಬ್ 70 ನಿಮಿಷ ಚಾಲನೆಯಾಗಿತ್ತು);
ಯೂನಿಟ್ **ನಿಂತಿರುವ** ರನ್ನರ್ಗಳ 48 ಗಂ. ಹಳೆಯ ಚೆಕ್ಔಟ್ಗಳನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ; ಡಿಸ್ಕ್ ≥ 85 %,
ಮೆಮೊರಿ PSI `full/avg60` ≥ 10 %, ಮತ್ತು `MAX_ACTIVE_RUNNERS` ಗಿಂತ ಹೆಚ್ಚಿನ ಲಿಸನರ್ಗಳು
ಇದ್ದಾಗ ಎಚ್ಚರಿಸುತ್ತದೆ (omniroute/ಇತರೆ ಎಂಬ ವಿಭಾಗೀಕರಣದೊಂದಿಗೆ). Exit 1 = ಗಮನ ಅಗತ್ಯ;
ಲಾಗ್ ಅನ್ನು ಓದಿ.

GitHub ಈಗಾಗಲೇ ಕೈಬಿಟ್ಟಿರುವ ಜಾಬ್ನ ಬಿಲ್ಡ್ ಅನ್ನು 75-ನಿಮಿಷದ ನಿಯಮ ಪತ್ತೆಮಾಡುವುದಿಲ್ಲ.
`Runner.Listener` ತನ್ನ ಜಾಬ್ ಅನ್ನು ನವೀಕರಿಸಲು ಸಾಧ್ಯವಾಗದಿದ್ದಾಗ, `_diag/Runner_*.log` ನಲ್ಲಿ
`POST request to …/renewjob timed out after 100 seconds` ಕಾಣಿಸುತ್ತದೆ, ಕೊನೆಯ ಯಶಸ್ವಿ ನವೀಕರಣದ
ಸುಮಾರು ಹತ್ತು ನಿಮಿಷಗಳ ನಂತರ API ಜಾಬ್ ಅನ್ನು `completed` (ವಿಫಲ) ಎಂದು ವರದಿ ಮಾಡುತ್ತದೆ, ಮತ್ತು
ಯಾವುದೇ ಜಾಬ್ ಲಗತ್ತಿಸದೇ `next-build` ಚಾಲನೆಯಲ್ಲೇ ಇರುತ್ತದೆ (2026-10-18: #17066 ರ ಬಿಲ್ಡ್
19:43 ಕ್ಕೆ ವಿಫಲವಾಗಿತ್ತು ಮತ್ತು ಐದು ನಿಮಿಷಗಳ ನಂತರವೂ ಅದರ ಬಿಲ್ಡ್ 40 GB ಅನ್ನು ಹಿಡಿದಿಟ್ಟುಕೊಂಡಿತ್ತು).
ಹೊಸ `_diag/Worker_*.log` ನಲ್ಲಿ ರೆಫ್ ಅನ್ನು ಖಚಿತಪಡಿಸಿ, ನಂತರ PID ಮೂಲಕ ಬಿಲ್ಡ್ ಟ್ರೀಗೆ ಮಾತ್ರ
SIGTERM ಕಳುಹಿಸಿ — `next-build`, `npm run build`, `build-next-isolated.mjs` ಮತ್ತು
`_work` ವರ್ಕರ್ಗಳು. `Runner.Listener`, `RunnerService.js` ಅಥವಾ `Runner.Worker` ಅನ್ನು
ಎಂದಿಗೂ ಮುಟ್ಟಬೇಡಿ: ವರ್ಕರ್ ಜಾಬ್ ಅನ್ನು ರದ್ದುಗೊಳಿಸಲಾಗಿದೆ ಎಂದು ವರದಿ ಮಾಡುತ್ತದೆ ಮತ್ತು ಲಿಸನರ್
ಸ್ವತಃ ಮತ್ತೆ ಆನ್ಲೈನ್ಗೆ ಬರುತ್ತದೆ.

## ರನ್ನರ್ ಯೂನಿಟ್ಗಳು: KillMode

ರನ್ನರ್ನ ಡೀಫಾಲ್ಟ್ `KillMode=process`, ಯೂನಿಟ್ ಅನ್ನು ನಿಲ್ಲಿಸಿದಾಗ ಅಥವಾ ಮರುಪ್ರಾರಂಭಿಸಿದಾಗ
`Runner.Worker → npm → next-build` ಅನ್ನು ಚಾಲನೆಯಲ್ಲೇ ಬಿಡುತ್ತದೆ — ಲಗತ್ತಿಸಲಾದ ಜಾಬ್ ಇಲ್ಲದ
ಅನಾಥ ಬಿಲ್ಡ್ RAM ಮತ್ತು CPU ಅನ್ನು ಬಳಸುತ್ತಲೇ ಇರುತ್ತದೆ. ಪ್ರತಿಯೊಂದು OmniRoute ಯೂನಿಟ್
`KillMode=mixed` ಹೊಂದಿರುವ ಡ್ರಾಪ್-ಇನ್
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
ಅನ್ನು ಹೊಂದಿದೆ: ಮೊದಲು ಲಿಸನರ್ಗೆ SIGTERM, ನಂತರ `TimeoutStop` ನಲ್ಲಿ ಸಂಪೂರ್ಣ cgroup ಗೆ
SIGKILL. ಯೂನಿಟ್ನ ಮುಂದಿನ ಮರುಪ್ರಾರಂಭದಲ್ಲಿ ಇದು ಜಾರಿಗೆ ಬರುತ್ತದೆ — **ಒಮ್ಮೆಗೆ ಒಂದು ರನ್ನರ್ ಅನ್ನು
ಮಾತ್ರ, ಅದು ನಿಷ್ಕ್ರಿಯವಾಗಿರುವಾಗ ಮಾತ್ರ** ಮರುಪ್ರಾರಂಭಿಸಿ; ನಿಷ್ಕ್ರಿಯತೆ ಪರಿಶೀಲನೆ ಮತ್ತು ಮರುಪ್ರಾರಂಭವನ್ನು
ಒಂದೇ ಕಮಾಂಡ್ನಲ್ಲಿ ಮಾಡಿ.
