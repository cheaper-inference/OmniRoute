ಬಿಡುಗಡೆ-ಹಸಿರು ನಿರ್ದಿಷ್ಟ ಬದ್ಧತೆಯನ್ನು ಗಮನಿಸುತ್ತದೆ ಮತ್ತು ಅದರ ಮೌಲ್ಯಮಾಪನ ಫಲಿತಾಂಶಗಳನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ. [ಕ್ವಾಲಿಟಿ ಗೇಟ್ಸ್ ಉಲ್ಲೇಖವು](../architecture/QUALITY_GATES.md) ಪ್ರಸ್ತುತ CI ಪ್ರೊಫೈಲ್ಗಳು, ಅಗತ್ಯವಿರುವ ಚೆಕ್ಗಳು ಮತ್ತು ಸ್ವೀಕಾರ ನೀತಿಯನ್ನು ವ್ಯಾಖ್ಯಾನಿಸುತ್ತದೆ. `config/quality/admission-policy.json` ನಲ್ಲಿನ ಆವೃತ್ತಿಯ ಪ್ರವೇಶ ನೀತಿಯು `Gate / CI` ಮತ್ತು `Gate / Quality` ಗಾಗಿ ಕಾರ್ಯಗತಗೊಳಿಸಬಹುದಾದ ಒಪ್ಪಂದವಾಗಿದೆ.

## CI ಮತ್ತು ವೀಕ್ಷಕರ ವ್ಯಾಪ್ತಿ

`ci.yml` ಮತ್ತು `quality.yml` ಕವರ್ ವಿನಂತಿಗಳನ್ನು ಮುಖ್ಯ ಮತ್ತು ಬಿಡುಗಡೆ ಶಾಖೆಗಳಿಗೆ ಎಳೆಯುತ್ತದೆ. ಆಯ್ಕೆಮಾಡಿದ ಪ್ರೊಫೈಲ್ ಯಾವ ಉದ್ಯೋಗಗಳು ಅನ್ವಯಿಸುತ್ತವೆ ಎಂಬುದನ್ನು ನಿರ್ಧರಿಸುತ್ತದೆ. ಪೂರ್ಣ CI ಸಹ ಸಾಮಾನ್ಯ ಪುಲ್ ವಿನಂತಿಯನ್ನು ಕಾರ್ಯಗತಗೊಳಿಸದ ಲೇನ್ಗಳನ್ನು ಒಳಗೊಂಡಿದೆ. ತ್ವರಿತ ವೀಕ್ಷಕ ಫಲಿತಾಂಶವು ಆ ಉದ್ಯೋಗಗಳನ್ನು ಬದಲಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ, ಮತ್ತು ಪೂರ್ಣಗೊಂಡ ವರ್ಕ್ಫ್ಲೋ ಹೊದಿಕೆಯು ಅದರ ರಸೀದಿಗಳನ್ನು ಬದಲಾಯಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ.

ಉತ್ಪಾದನಾ ನಿರ್ಮಾಣವು CI ಗೆ ಸೇರಿದೆ. `quality.yml` ನಲ್ಲಿ ಯಾವುದೇ ನಕಲಿ ಸಲಹಾ ನಿರ್ಮಾಣವಿಲ್ಲ. ಕಾಣೆಯಾದ ಕಲಾಕೃತಿಗಳು, ರದ್ದಾದ ಕೆಲಸ ಮತ್ತು ಅಪೂರ್ಣ ಅಳತೆಗಳು ಯಶಸ್ವಿ ಅಗತ್ಯವಿರುವ ಚೆಕ್ ಅನ್ನು ಸ್ಥಾಪಿಸುವುದಿಲ್ಲ. ಫಲಿತಾಂಶಗಳನ್ನು ಸ್ವೀಕರಿಸುವ ಮೊದಲು ಪ್ರಸ್ತುತ ಮೂಲ, ತಲೆ ಮತ್ತು ಸಂಯೋಜಿತ ಅಭ್ಯರ್ಥಿಯನ್ನು ದೃಢೀಕರಿಸಿ.

## ಸ್ಥಳೀಯ ದೃಢೀಕರಣ

ಅದರ ಅವಲಂಬನೆಗಳನ್ನು ಸಿದ್ಧಪಡಿಸಿದ ನಂತರ ಒಡೆತನದ ವರ್ಕ್ಟ್ರೀಯಲ್ಲಿ ವೀಕ್ಷಕರನ್ನು ರನ್ ಮಾಡಿ. ಭಾರೀ ಮೌಲ್ಯೀಕರಣದ ಮೊದಲು `docs/ops/WORKTREE_ISOLATION.md` ನಲ್ಲಿ ವರ್ಕ್ಟ್ರೀ ಮತ್ತು ಸಂಪನ್ಮೂಲ ಪ್ರೋಟೋಕಾಲ್ ಅನ್ನು ಅನುಸರಿಸಿ.

```bash
npm run check:release-green -- --quick --json
npm run check:release-green -- --with-build --full-ci --json
```

ತ್ವರಿತ ಪ್ರೊಫೈಲ್ ಭಾಗಶಃ ಆಗಿದೆ. ಪೂರ್ಣ ಪ್ರೊಫೈಲ್ ಅದರ ಮಾದರಿಯ ಅವಶ್ಯಕತೆಗಳನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು ಕಮಾಂಡ್ ರಸೀದಿಗಳನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ; ಇದು ನಿಯೋಜನೆಯನ್ನು ಪ್ರಮಾಣೀಕರಿಸುವುದಿಲ್ಲ ಅಥವಾ ಅನ್ವಯಿಸುವ ಹೋಸ್ಟ್ ಮಾಡಿದ ಚೆಕ್ಗಳಿಗೆ ಬದಲಿಯಾಗಿಲ್ಲ. ವರದಿಯು ಮೆಟ್ರಿಕ್ ಡ್ರಿಫ್ಟ್ನಿಂದ ಮರಣದಂಡನೆ ವೈಫಲ್ಯವನ್ನು ಪ್ರತ್ಯೇಕಿಸುತ್ತದೆ. ಆಯ್ಕೆಮಾಡಿದ ನೀತಿಯ ಪ್ರಕಾರ ಅಗತ್ಯವಿರುವ ರಾಟ್ಚೆಟ್ಗಳು ನಿರ್ಬಂಧಿಸುತ್ತಲೇ ಇರುತ್ತವೆ. ಉತ್ತೀರ್ಣ ಫಲಿತಾಂಶವನ್ನು ಪಡೆಯಲು ಬೇಸ್ಲೈನ್ ಅನ್ನು ಹೆಚ್ಚಿಸಬೇಡಿ.

## ರಾತ್ರಿ ಮತ್ತು ಹಸ್ತಚಾಲಿತ ಸ್ವೀಪ್ಗಳು

ರಾತ್ರಿಯ ಬಿಡುಗಡೆ ಮತ್ತು ಹೊಂದಾಣಿಕೆ ಪರಿಹಾರಕಾರರು ಅಂಗೀಕೃತ ಬಿಡುಗಡೆ ಶಾಖೆಯನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತಾರೆ. ಆ ಆಯ್ಕೆಯು ವರ್ಕ್ಫ್ಲೋ ಅನ್ನು ಪ್ರಚೋದಿಸಿದ ಶಾಖೆಗೆ ಹೊಂದಿಕೆಯಾಗಬೇಕು ಮತ್ತು ಸೂಟ್ಗಳು ಈವೆಂಟ್ನ ಬದಲಾಗದ SHA ಬಳಸುತ್ತವೆ. ಹಸ್ತಚಾಲಿತ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಗಾಗಿ, `release_branch` ನಲ್ಲಿ ಉದ್ದೇಶಿತ ಬಿಡುಗಡೆಯನ್ನು ಆಯ್ಕೆಮಾಡಿ ಮತ್ತು ಅದೇ ಉಲ್ಲೇಖದಲ್ಲಿ ರವಾನಿಸಿ:

```bash
gh workflow run nightly-release-green.yml --ref "$release_branch" -f branch="$release_branch"
gh workflow run nightly-compat.yml --ref "$release_branch" -f branch="$release_branch"
```

ಆಯ್ದ ಕೋಡ್ ಅನ್ನು ಕಾರ್ಯಗತಗೊಳಿಸುವ ಮೊದಲು ಕ್ರಾಸ್-ಬ್ರಾಂಚ್ ರವಾನೆಯನ್ನು ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ. ಹೋಸ್ಟ್ ಮಾಡಲಾದ ಮುಖ್ಯ ಸೂಟ್ಗಳು `main` ಚೆಕ್ಔಟ್ ಮಾಡಿ ಮತ್ತು ಅದರ SHA ಇನ್ನೂ ಅನುಸ್ಥಾಪನೆಯ ಮೊದಲು ಪರಿಹರಿಸಲಾದ ಗುರಿಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ ಎಂದು ಪರಿಶೀಲಿಸಿ. ರೆಸಲ್ಯೂಶನ್ ಸಮಯದಲ್ಲಿ ಮುಖ್ಯ ಚಲಿಸಿದರೆ, ಹೊಸ ಕಮಿಟ್ನಲ್ಲಿ ಅಪೂರ್ಣ ಸ್ವೀಪ್ ಅನ್ನು ಮರುರನ್ ಮಾಡಿ. ವಿವಿಧ ಅಭ್ಯರ್ಥಿಗಳಿಂದ ಸೂಟ್ ರಸೀದಿಗಳನ್ನು ಸಂಯೋಜಿಸಬೇಡಿ.

## ವೈಫಲ್ಯ ಚಿಕಿತ್ಸೆಯ ಸರದಿ ನಿರ್ಧಾರ ಮತ್ತು ಚೇತರಿಕೆ

ಘಟನೆಯನ್ನು ರೋಗನಿರ್ಣಯದ ಸೂಚ್ಯಂಕವಾಗಿ ಬಳಸಿ, ನಂತರ ನಿಖರವಾದ ರನ್, ಪ್ರಯತ್ನ, ವಿಫಲ ಹಂತ ಮತ್ತು ಕಲಾಕೃತಿಯನ್ನು ಪರೀಕ್ಷಿಸಿ. ಕೊಡುಗೆದಾರರಿಗೆ ವೈಫಲ್ಯವನ್ನು ಆರೋಪಿಸುವ ಮೊದಲು ಸಮಾನ ಆಧಾರ ಮತ್ತು ಅಭ್ಯರ್ಥಿ ಪುರಾವೆಗಳನ್ನು ಹೋಲಿಕೆ ಮಾಡಿ. ಮೂಲಸೌಕರ್ಯ ದೋಷಗಳು, ಆನುವಂಶಿಕ ದೋಷಗಳು, ಅಭ್ಯರ್ಥಿಗಳ ಹಿನ್ನಡೆಗಳು ಮತ್ತು ಬಾಕಿ ಇರುವ ಅನುಮೋದನೆಗಳಿಗೆ ವಿಭಿನ್ನ ಪರಿಹಾರಗಳು ಬೇಕಾಗುತ್ತವೆ.

`/green-prs`, `/sweep-reds`, `/validate-release-green` ಮತ್ತು `/babysit` ಕೌಶಲ್ಯಗಳು ಸಾಕ್ಷ್ಯವನ್ನು ಸಂಗ್ರಹಿಸುತ್ತವೆ ಮತ್ತು ಅವುಗಳ ದಾಖಲಿತ ವ್ಯಾಪ್ತಿಯ ಅಡಿಯಲ್ಲಿ ಪರಿಹಾರಗಳನ್ನು ಸಿದ್ಧಪಡಿಸುತ್ತವೆ. ಕೊಡುಗೆದಾರರ ಕ್ರೆಡಿಟ್ ಅನ್ನು ಇರಿಸಿಕೊಳ್ಳಿ, ಪ್ರತ್ಯೇಕವಾದ ದುರಸ್ತಿ ಶಾಖೆಗಳನ್ನು ಬಳಸಿ ಮತ್ತು ಅಧಿಕೃತ ವಿಲೀನದ ಮೊದಲು ಅಗತ್ಯವಿರುವ ಎಲ್ಲಾ ಚೆಕ್ಗಳನ್ನು ಪರಿಶೀಲಿಸಿ. ಪ್ರಸ್ತುತ ಉತ್ತೀರ್ಣರಾಗಿರುವ ಅಭ್ಯರ್ಥಿಗೆ ಯಾವುದೇ ಸ್ವಯಂಚಾಲಿತ ಮರುಬೇಸ್ಲೈನ್ ಅಥವಾ ಘಟನೆಯ ಮುಚ್ಚುವಿಕೆಯ ಪರ್ಯಾಯಗಳಿಲ್ಲ.
