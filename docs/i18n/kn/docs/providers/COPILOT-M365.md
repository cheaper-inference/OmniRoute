`copilot-m365-web` (ಅಲಿಯಾಸ್ `m365copilot`) `m365.cloud.microsoft/chat` ನಲ್ಲಿ ದೃಢೀಕೃತ Microsoft 365 Copilot ಅಧಿವೇಶನದ ಮೂಲಕ OpenAI- ಫಾರ್ಮ್ಯಾಟ್ ಚಾಟ್ ವಿನಂತಿಗಳನ್ನು ಕಳುಹಿಸುತ್ತದೆ. ಇದು ಅನಧಿಕೃತ ಸ್ಥಳೀಯ ಏಕೀಕರಣವಾಗಿದೆ: ಯಾವುದೇ ಪ್ರತ್ಯೇಕ ಪ್ರಾಕ್ಸಿ ಪ್ರಕ್ರಿಯೆ ಅಥವಾ ಸ್ಥಳೀಯ ಹೋಸ್ಟ್ ಅಪ್ಸ್ಟ್ರೀಮ್ ಅಗತ್ಯವಿಲ್ಲ. ಪೂರೈಕೆದಾರ ID, ಅಲಿಯಾಸ್ ಮತ್ತು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಆಮದು ಮಾಡಿದ ಸಂಪರ್ಕಗಳು ಬದಲಾಗಿಲ್ಲ. `copilot-web` ಗ್ರಾಹಕ ಸೇವೆಗೆ `copilot.microsoft.com` ನಲ್ಲಿ ವಿಭಿನ್ನ ಪೂರೈಕೆದಾರ.

> **ವೆಬ್ ಕುಕಿ ಪೂರೈಕೆದಾರರಿಗೆ ಹೊಸಬರೇ?**
>
> ಓದು**`docs/getting-started/WEB-COOKIE-GUIDE.md`** ಈ ಪೂರೈಕೆದಾರ-ನಿರ್ದಿಷ್ಟ ಮಾರ್ಗದರ್ಶಿಯನ್ನು ಅನುಸರಿಸುವ ಮೊದಲು ಸಾಮಾನ್ಯ ಸೆಟಪ್ ಪ್ರಕ್ರಿಯೆ, ದೃಢೀಕರಣ ಮಾರ್ಗದರ್ಶನ, ಮಿತಿಗಳು ಮತ್ತು ದೋಷನಿವಾರಣೆಗಾಗಿ.
>
> **ಪರಂಪರೆಯ ಆಮದುಗಳಿಗಾಗಿ:** ಈ ಪೂರೈಕೆದಾರರಿಗೆ ರುಜುವಾತು** ಕುಕೀ ಅಲ್ಲ** . `m365.cloud.microsoft` ನಿಂದ ಕುಕೀಗಳನ್ನು ನಕಲಿಸಬೇಡಿ. ರುಜುವಾತು ಒಂದು WebSocket URL ಕ್ವೆರಿ ಪ್ಯಾರಾಮೀಟರ್ ಮತ್ತು ಪಾಥ್ ಸೆಗ್ಮೆಂಟ್ ಆಗಿದೆ, ಇವೆರಡನ್ನೂ DevTools ನೆಟ್ವರ್ಕ್ ಟ್ಯಾಬ್ನಿಂದ ಓದಲಾಗುತ್ತದೆ.

## ಪೂರ್ವಾಪೇಕ್ಷಿತಗಳು

- `m365.cloud.microsoft/chat` ನಲ್ಲಿ Copilot ಗೆ ಪ್ರವೇಶವನ್ನು ಹೊಂದಿರುವ Microsoft 365 ಖಾತೆ
- DevTools WebSocket ತಪಾಸಣೆಗಾಗಿ Chromium-ಆಧಾರಿತ ಬ್ರೌಸರ್ (Chrome, Edge).
- ಆ ಖಾತೆಯಲ್ಲಿ ವಿನಂತಿಸಿದ ಮಾದರಿಗೆ ಪ್ರವೇಶ; ಬಾಡಿಗೆದಾರ ಮತ್ತು ಪರವಾನಗಿಯಿಂದ ಲಭ್ಯತೆ ಬದಲಾಗುತ್ತದೆ

## ಸ್ಥಳೀಯ ಸೈನ್-ಇನ್ (ಕೆಲಸ ಅಥವಾ ಶಾಲಾ ಖಾತೆಗಳು)

ಆಯ್ಕೆ ಮಾಡಿ**Microsoft 365 Copilot → ಸಂಪರ್ಕ** ಮತ್ತು ಸೈನ್ ಇನ್ ಪ್ರಯತ್ನವನ್ನು ಸಿದ್ಧಪಡಿಸಿ. ಡ್ಯಾಶ್ಬೋರ್ಡ್ PKCE ಜೊತೆಗೆ ದೃಢೀಕರಣ-ಕೋಡ್ ಹರಿವನ್ನು ಬಳಸುತ್ತದೆ; ಇದು ನಿಮ್ಮ Microsoft ಪಾಸ್ವರ್ಡ್ ಅಥವಾ MFA ಕೋಡ್ ಅನ್ನು ಕೇಳುವುದಿಲ್ಲ.

1. ತೆರೆಯಿರಿ a** ಖಾಲಿ ಬ್ರೌಸರ್ ಟ್ಯಾಬ್** , ನಂತರ ತೆರೆಯಿರಿ**DevTools → ನೆಟ್ವರ್ಕ್** ಮತ್ತು ಸಕ್ರಿಯಗೊಳಿಸಿ** ಲಾಗ್ ಅನ್ನು ಸಂರಕ್ಷಿಸಿ** . Microsoft ಗೆ ನ್ಯಾವಿಗೇಟ್ ಮಾಡುವ ಮೊದಲು ಇದನ್ನು ಮಾಡಿ : Windows SSO ತಕ್ಷಣವೇ ಮುಕ್ತಾಯವಾಗಬಹುದು.
2. ಸಂಪರ್ಕ ಸಂವಾದದಿಂದ ತೋರಿಸಿರುವ ದೃಢೀಕರಣ URL ನಕಲಿಸಿ ಮತ್ತು ಆ ಸಿದ್ಧಪಡಿಸಿದ ಟ್ಯಾಬ್ನಲ್ಲಿ ನ್ಯಾವಿಗೇಟ್ ಮಾಡಿ. ವಿನಂತಿಸಿದರೆ Microsoft ಖಾತೆ ಆಯ್ಕೆ ಅಥವಾ MFA ಪೂರ್ಣಗೊಳಿಸಿ.
3. ಸಂರಕ್ಷಿತ ನೆಟ್ವರ್ಕ್ ಲಾಗ್ನಲ್ಲಿ, `https://login.microsoftonline.com/common/oauth2/nativeclient` ಗೆ ವಿನಂತಿಯನ್ನು ಹುಡುಕಿ ಮತ್ತು ಅದರ ಪೂರ್ಣವನ್ನು ನಕಲಿಸಿ** URL ವಿನಂತಿಸಿ** .
4. ಆ URL ಸಂಪರ್ಕ ಸಂವಾದದಲ್ಲಿ ಅಂಟಿಸಿ ಮತ್ತು ಸಂಪರ್ಕಪಡಿಸಿ. ಕಚ್ಚಾ ಕೋಡ್ ಅಥವಾ ಅಂತಿಮ `wrongplace` ವಿಳಾಸ-ಪಟ್ಟಿ URL ಅಂಟಿಸಬೇಡಿ : ಅಗತ್ಯವಿರುವ ಕಾಲ್ಬ್ಯಾಕ್ ಅಸ್ಥಿರ ನ್ಯಾವಿಗೇಷನ್ ಆಗಿದೆ.

ಪ್ರತಿ ಪ್ರಯತ್ನವು ಹತ್ತು ನಿಮಿಷಗಳ ನಂತರ ಮುಕ್ತಾಯಗೊಳ್ಳುತ್ತದೆ ಮತ್ತು ಒಮ್ಮೆ ಮಾತ್ರ ಬಳಸಬಹುದು. ಕೋಡ್ ಅನ್ನು ವಿನಿಮಯ ಮಾಡಿಕೊಳ್ಳುವ ಮೊದಲು ಸರ್ವರ್ ತನ್ನ ಸ್ಥಿತಿ, PKCE ಪರಿಶೀಲಕ ಮತ್ತು ಮರುದೃಢೀಕರಣ ಗುರಿಯನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ. ಅವಧಿ ಮುಗಿದ ನಂತರ ಅಥವಾ ವಿನಿಮಯ ವೈಫಲ್ಯದ ನಂತರ, ಹೊಸ ಪ್ರಯತ್ನವನ್ನು ಪ್ರಾರಂಭಿಸಿ. ಒಂದು ಪ್ರಯತ್ನವು ಸರ್ವರ್ ಮರುಪ್ರಾರಂಭದಿಂದ ಉಳಿಯಲು ಸಾಧ್ಯವಿಲ್ಲ.

ಟೋಕನ್ಗಳು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಸಂಪರ್ಕದ ರುಜುವಾತು ಅಂಗಡಿ ಮತ್ತು ರಿಫ್ರೆಶ್ ಮಾರ್ಗವನ್ನು ಬಳಸುತ್ತವೆ. ಸಂಪರ್ಕವನ್ನು ಮರುದೃಢೀಕರಿಸಲು ಅದೇ Microsoft tenant/object ಗುರುತಿನ ಅಗತ್ಯವಿರುತ್ತದೆ, ಕೇವಲ ಒಂದೇ ಇಮೇಲ್ ಅಲ್ಲ. ಇದು ಆಪರೇಟರ್ naming/settings ಸಂರಕ್ಷಿಸುತ್ತದೆ ಮತ್ತು ಬಳಕೆಯಲ್ಲಿಲ್ಲದ ಆಮದು ಮಾಡಿದ ರುಜುವಾತುಗಳನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ. ಸ್ಥಳೀಯ ಸೈನ್-ಇನ್ work/school ಖಾತೆಗಳಿಗೆ ಆಗಿದೆ; ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಸಂಪರ್ಕಗಳು ಮತ್ತು ಬೆಂಬಲಿತ ಶ್ರೇಣಿಯ ಕಾನ್ಫಿಗರೇಶನ್ಗಳಿಗೆ ಪರಂಪರೆಯ ಆಮದು ಮಾರ್ಗವು ಲಭ್ಯವಿರುತ್ತದೆ.

ಪೂರ್ಣ ಕಾಲ್ಬ್ಯಾಕ್ URL ಒಂದು-ಬಾರಿ ರುಜುವಾತು ಆಗಿದೆ. ಅದನ್ನು ಎಂದಿಗೂ ಸ್ಕ್ರೀನ್ಶಾಟ್ಗಳು, ಲಾಗ್ಗಳು, ಬೆಂಬಲ ಸಂದೇಶಗಳು ಅಥವಾ ಕಮಿಟ್ಗಳಲ್ಲಿ ಸೇರಿಸಬೇಡಿ. ಈ ಹರಿವು ಸರ್ವರ್ನಲ್ಲಿ ಬ್ರೌಸರ್ ಅನ್ನು ತೆರೆಯುವುದಿಲ್ಲ, ನಿಮ್ಮ ಬ್ರೌಸರ್ ಇತಿಹಾಸವನ್ನು ಪರಿಶೀಲಿಸುವುದಿಲ್ಲ ಅಥವಾ ಸ್ಥಳೀಯ ಕಾಲ್ಬ್ಯಾಕ್ ಸರ್ವರ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸುವುದಿಲ್ಲ.

## ರುಜುವಾತು ಸೆರೆಹಿಡಿಯುವಿಕೆ (WebSocket ವಿಧಾನ)

1. `https://m365.cloud.microsoft/chat` ನಲ್ಲಿ ಸೈನ್ ಇನ್ ಮಾಡಿ ಮತ್ತು ಸಂವಾದವನ್ನು ಪ್ರಾರಂಭಿಸಿ.
2. ತೆರೆಯಿರಿ**DevTools → ನೆಟ್ವರ್ಕ್** .
3. ಇದರ ಮೂಲಕ ಫಿಲ್ಟರ್ ಮಾಡಿ**WS** (WebSocket)
4. Chathub WebSocket ಸಂಪರ್ಕವನ್ನು ಕ್ಲಿಕ್ ಮಾಡಿ. `wss://substrate.office.com/m365Copilot/Chathub/` ಯಿಂದ ಪ್ರಾರಂಭವಾಗುವ URL ನೋಡಿ.
5. ಅದರಿಂದ** URL ವಿನಂತಿಸಿ** , ನಕಲು:
   - `access_token` ಪ್ರಶ್ನೆ ಪ್ಯಾರಾಮೀಟರ್ ಮೌಲ್ಯ (ಅಲ್ಪಾವಧಿಯ JWT).
   - `/Chathub/` ನಂತರದ ಚಾತುಬ್ ಪಥ ವಿಭಾಗ (ಉದಾ `<oid>@<tenant>`).

ಪೂರ್ಣ URL ರೂಪವನ್ನು ಹೊಂದಿದೆ:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute ನಲ್ಲಿ, ಆಯ್ಕೆಮಾಡಿ**Microsoft 365 Copilot** , ಲೆಗಸಿ API-key/import ಆಯ್ಕೆಯನ್ನು ಆರಿಸಿ ಮತ್ತು ರುಜುವಾತುಗಳನ್ನು ಫಾರ್ಮ್ಯಾಟ್ನಲ್ಲಿ ಅಂಟಿಸಿ:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. ಕ್ಲಿಕ್ ಮಾಡಿ** ಪರೀಕ್ಷಾ ಸಂಪರ್ಕ** ಮತ್ತು** ಉಳಿಸಿ** .

## ರುಜುವಾತು ಸೆರೆಹಿಡಿಯುವಿಕೆ (HAR ಆಮದು)

WebSocket URL ನಿಂದ ಮೌಲ್ಯಗಳನ್ನು ಹಸ್ತಚಾಲಿತವಾಗಿ ನಕಲಿಸುವ ಬದಲು, ನೀವು DevTools HAR ಫೈಲ್ ಅನ್ನು ರಫ್ತು ಮಾಡಬಹುದು:

1. ತೆರೆಯಿರಿ**DevTools → ನೆಟ್ವರ್ಕ್** .
2. Microsoft 365 Copilot ಸಂಭಾಷಣೆಯನ್ನು ಪ್ರಾರಂಭಿಸಿ ಅಥವಾ ಮುಂದುವರಿಸಿ (ಇದು WebSocket ಸಂಪರ್ಕವನ್ನು ಪ್ರಚೋದಿಸುತ್ತದೆ).
3. ನೆಟ್ವರ್ಕ್ ಪ್ಯಾನೆಲ್ನಲ್ಲಿ ರೈಟ್-ಕ್ಲಿಕ್ ಮಾಡಿ ಮತ್ತು ಆಯ್ಕೆಮಾಡಿ** ವಿಷಯದೊಂದಿಗೆ ಎಲ್ಲವನ್ನೂ HAR ಆಗಿ ಉಳಿಸಿ** .
4. OmniRoute ನಲ್ಲಿ, ಬಳಸಿ** .har ಫೈಲ್ ಅನ್ನು ಆಮದು ಮಾಡಿ** ಒದಗಿಸುವವರ ಸಂಪರ್ಕ ಸಂವಾದದಲ್ಲಿನ ಬಟನ್.

OmniRoute Chathub WebSocket URL ಗಾಗಿ HAR ಅನ್ನು ಸ್ಕ್ಯಾನ್ ಮಾಡುತ್ತದೆ, `access_token` ಮತ್ತು `chathubPath` ಅನ್ನು ಹೊರತೆಗೆಯುತ್ತದೆ ಮತ್ತು ರುಜುವಾತು ಕ್ಷೇತ್ರಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಜನಪ್ರಿಯಗೊಳಿಸುತ್ತದೆ. HAR ಆಮದು JWT ಮುಕ್ತಾಯವನ್ನು ಡಿಕೋಡ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಉಳಿದ ಟೋಕನ್ ಜೀವಿತಾವಧಿಯನ್ನು ತೋರಿಸುತ್ತದೆ.

> **ನಿಜವಾದ HAR ರಫ್ತು, ಪ್ರವೇಶ ಟೋಕನ್ ಅಥವಾ ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಅನ್ನು ಎಂದಿಗೂ ಮಾಡಬೇಡಿ.** ಪರೀಕ್ಷೆ ಮತ್ತು ದಾಖಲಾತಿ ಮೌಲ್ಯಗಳು ಯಾವಾಗಲೂ ಪ್ಲೇಸ್ಹೋಲ್ಡರ್ಗಳಾಗಿರಬೇಕು.

## ಟೋಕನ್ ಜೀವಿತಾವಧಿ ಮತ್ತು ರಿಫ್ರೆಶ್

`access_token` ಅಲ್ಪಾವಧಿಯದ್ದಾಗಿದೆ (ಸಾಮಾನ್ಯವಾಗಿ**~ 75 ನಿಮಿಷಗಳು** ) ಬಳಸಬಹುದಾದ ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಇಲ್ಲದೆ, ಅವಧಿ ಮುಗಿದ ನಂತರ ನೀವು ರುಜುವಾತುಗಳನ್ನು ಮರು-ಹಿಡಿಯಬೇಕು.

### `refreshToken` ನೊಂದಿಗೆ ಸ್ವಯಂಚಾಲಿತ ರಿಫ್ರೆಶ್

Microsoft 365 ಪೂರೈಕೆದಾರರಲ್ಲಿ** ಸಂಪರ್ಕವನ್ನು ಸೇರಿಸಿ** ಅಥವಾ** ಸಂಪರ್ಕವನ್ನು ಸಂಪಾದಿಸಿ** ಸಂವಾದ, ತೆರೆಯಿರಿ** ಸುಧಾರಿತ ಸೆಟ್ಟಿಂಗ್ಗಳು → ರಿಫ್ರೆಶ್ ಟೋಕನ್ (ಐಚ್ಛಿಕ)** . `substrate.office.com/sydney` ಸ್ಕೋಪ್ಗಾಗಿ Microsoft OAuth ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಅನ್ನು ಅಂಟಿಸಿ ಮತ್ತು ಉಳಿಸಿ. ಇನ್ಪುಟ್ ಅನ್ನು ಮಾಸ್ಕ್ ಮಾಡಲಾಗಿದೆ ಮತ್ತು ಸಂಗ್ರಹಿಸಿದ ಟೋಕನ್ನೊಂದಿಗೆ ಎಂದಿಗೂ ಪೂರ್ವ ತುಂಬಿಲ್ಲ. ಸಂಪಾದಿಸುವಾಗ, ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಟೋಕನ್ ಅನ್ನು ಇರಿಸಿಕೊಳ್ಳಲು ಅದನ್ನು ಖಾಲಿ ಬಿಡಿ; ಅದನ್ನು ಬದಲಿಸಲು ಹೊಸ ಟೋಕನ್ ಅನ್ನು ಅಂಟಿಸಿ.

Microsoft ಒಂದನ್ನು ಹಿಂತಿರುಗಿಸಿದಾಗ ಸ್ಥಳೀಯ ಸೈನ್-ಇನ್ ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಅನ್ನು ಪಡೆದುಕೊಳ್ಳುತ್ತದೆ. ಪರಂಪರೆಯ ಆಮದುಗಳಿಗಾಗಿ, ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಹೊಂದಾಣಿಕೆಯ Microsoft ದೃಢೀಕರಣ-ಕೋಡ್ ಅನುದಾನವನ್ನು ಬಳಸಿ; ಈ ಪೂರೈಕೆದಾರರು ಸಾಧನ-ಕೋಡ್ ಹರಿವನ್ನು ಕಾರ್ಯಗತಗೊಳಿಸುವುದಿಲ್ಲ ಅಥವಾ ಭರವಸೆ ನೀಡುವುದಿಲ್ಲ. ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಕಾನ್ಫಿಗರ್ ಮಾಡುವುದರೊಂದಿಗೆ, OmniRoute ವಿನಂತಿಗಳ ಮೊದಲು `access_token` ಅನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು ರಿಫ್ರೆಶ್ ಮಾಡಬೇಕಾದಾಗ ಮಾತ್ರ ಅದನ್ನು ರಿಫ್ರೆಶ್ ಮಾಡುತ್ತದೆ. ಯಶಸ್ವಿ ರಿಫ್ರೆಶ್ ಕೂಡ ತಿರುಗಿದ ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಅನ್ನು ಮುಂದುವರೆಸುತ್ತದೆ, ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಮಾನ್ಯವಾಗಿ ಉಳಿದಿರುವಾಗ ಹಸ್ತಚಾಲಿತ ಮರು-ಕ್ಯಾಪ್ಚರ್ ಅನ್ನು ತಪ್ಪಿಸುತ್ತದೆ.

`refreshToken` ಹೊಂದಿಸದಿದ್ದರೆ, ಪ್ರತಿ ಅವಧಿ ಮುಗಿದ ನಂತರ ನೀವು WebSocket ರುಜುವಾತುಗಳನ್ನು ಹಸ್ತಚಾಲಿತವಾಗಿ ಮರು-ಹಿಡಿಯಬೇಕು.

### ಶ್ರೇಣಿ ಆಯ್ಕೆ

| ಶ್ರೇಣಿ       | ಅಲಿಯಾಸ್      | ಮೇಲ್ಮೈ                  |
| ------------ | ------------ | ----------------------- |
| `individual` | _(ಡೀಫಾಲ್ಟ್)_ | ಗ್ರಾಹಕ M365 Copilot     |
| `edu`        | `included`   | ಶಿಕ್ಷಣ M365 Copilot     |
| `enterprise` | `work`       | ಕೆಲಸಕ್ಕಾಗಿ M365 Copilot |

ಶ್ರೇಣಿಯನ್ನು ಹೊಂದಿಸಿ** ಸುಧಾರಿತ ಸೆಟ್ಟಿಂಗ್ಗಳು → Copilot ಶ್ರೇಣಿ** . ಸ್ಥಳೀಯ ಸೈನ್-ಇನ್ ಇದನ್ನು ಹೊಂದಿಸುವುದಿಲ್ಲ, ಆದ್ದರಿಂದ ಕೆಲಸದ ಖಾತೆಯು `enterprise` (ಅಲಿಯಾಸ್ `work`) ಮತ್ತು ಶಿಕ್ಷಣ ಖಾತೆ `edu` ಆಯ್ಕೆಮಾಡಬೇಕು, ಡಾಕ್ಯುಮೆಂಟ್ ಮಾಡಲಾದ ಮಾದರಿ IDs ಬಳಸುವಾಗಲೂ ಸಹ: ಅವುಗಳು ತಮ್ಮದೇ ಆದ ಸ್ವರ, ಸನ್ನಿವೇಶ ಮತ್ತು ಪರವಾನಗಿ ಪ್ರಕಾರವನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತವೆ, ಆದರೆ ಏಜೆಂಟ್ ಮತ್ತು ಆಹ್ವಾನದ ಆಯ್ಕೆಗಳು ಇನ್ನೂ ಶ್ರೇಣಿಯಿಂದ ಬರುತ್ತವೆ, ಮತ್ತು ವೈಯಕ್ತಿಕ ಡೀಫಾಲ್ಟ್ಗಳು ಕೆಲಸದ ಬಾಡಿಗೆದಾರರಲ್ಲಿ ವಿಫಲವಾಗಬಹುದು. ಶ್ರೇಣಿಯನ್ನು ಬದಲಾಯಿಸುವುದು ಮಾದರಿ ಪರವಾನಗಿಯನ್ನು ನೀಡುವುದಿಲ್ಲ. ಸ್ಪಷ್ಟವಾದ ಸುಧಾರಿತ ಪ್ರೋಟೋಕಾಲ್ ಅತಿಕ್ರಮಣಗಳು ಆದ್ಯತೆಯನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತವೆ ಮತ್ತು ಅಗತ್ಯವಿರುವ ತಂತಿ ಮೌಲ್ಯಗಳನ್ನು ನೀವು ತಿಳಿದಾಗ ಮಾತ್ರ ಬಳಸಬೇಕು.

## ಮಾದರಿಗಳು ಮತ್ತು ರೂಟಿಂಗ್

ಸ್ಥಳೀಯ ಕ್ಯಾಟಲಾಗ್ ಎಲ್ಲಾ ದಾಖಲಿತ ಸ್ವತಂತ್ರ IDs ಜೊತೆಗೆ ನಾಲ್ಕು ಮೂಲ ಸ್ಥಳೀಯ IDs ಒಳಗೊಂಡಿದೆ. ಕ್ಯಾಟಲಾಗ್ ಸ್ಥಿರ ಮತ್ತು ಖಾತೆ-ಸ್ವತಂತ್ರವಾಗಿದೆ, ಖಾತೆಯ ಅರ್ಹತೆಯ ತನಿಖೆಯಲ್ಲ: ಸಂಪರ್ಕಿತ ಖಾತೆಯು ಅವುಗಳನ್ನು ಬಳಸಲಾಗದಿದ್ದರೂ ಪಾವತಿಸಿದ ಮಾರ್ಗಗಳು ಮತ್ತು ಹೊಂದಾಣಿಕೆಯ ಅಲಿಯಾಸ್ಗಳು ಪಟ್ಟಿ ಮಾಡಲ್ಪಡುತ್ತವೆ. ಮಾದರಿ ಪ್ರದರ್ಶನ ಲೇಬಲ್ಗಳು ಒದಗಿಸುವವರ ಹೆಸರು ಮತ್ತು ಪ್ರತಿ ಮಾದರಿಯ ಲಭ್ಯತೆಯ ಬಾಯ್ಲರ್ಪ್ಲೇಟ್ ಅನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತವೆ; ಒದಗಿಸುವವರು ಉಳಿದಿದ್ದಾರೆ**Microsoft 365 Copilot** . ಲೇಬಲ್ಗಳನ್ನು ಗುರುತಿಸಲಾಗಿದೆ** ಅಲಿಯಾಸ್** ಅಥವಾ** ಪರಂಪರೆ** ತಮ್ಮ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಗುರುತಿಸುವಿಕೆಗಳು ಮತ್ತು ಪ್ರೋಟೋಕಾಲ್ ಮ್ಯಾಪಿಂಗ್ಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳಿ, ಐತಿಹಾಸಿಕ ಮಾದರಿಯ ಆವೃತ್ತಿಯ ಗ್ಯಾರಂಟಿ ಅಲ್ಲ. ಸ್ವತಂತ್ರ ಪ್ರಾಕ್ಸಿಗಳು** /ಮಾದರಿಗಳಿಂದ ಆಮದು ಮಾಡಿಕೊಳ್ಳಿ** ಸೂಚನೆಗಳು ಈ ಸ್ಥಳೀಯ WebSocket ಪೂರೈಕೆದಾರರಿಗೆ ಅನ್ವಯಿಸುವುದಿಲ್ಲ.

| ಮಾದರಿ ಕುಟುಂಬ      | ಅಂಗೀಕೃತ IDs                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| ಸ್ವಯಂಚಾಲಿತ        | `m365-copilot`                                                                                   |
| GPT-5.5 / GPT-5.6 | `gpt-5.5`, `gpt-5.5-think-deeper`, `gpt-5.6`, `gpt-5.6-think-deeper`                             |
| ಹಿಂದಿನ GPT        | `gpt-5.4`, `gpt-5.4-quick`, `gpt-5.3`, `gpt-5.3-think-deeper`, `gpt-5.2`, `gpt-5.2-think-deeper` |
| GPT-6             | `gpt-6-think-deeper`, `gpt-6-sol`, `gpt-6.1-sol`                                                 |
| Claude ಸಾನೆಟ್     | `claude-sonnet`, `claude-sonnet-think-deeper`, `claude-sonnet-5`, `claude-sonnet-5.5`            |
| Claude ಓಪಸ್       | `claude-opus`, `claude-opus-4.8`                                                                 |

`auto`, `quick`, `think-deeper`, ಮತ್ತು ಆವೃತ್ತಿ ಅಲಿಯಾಸ್ಗಳಂತಹ ಅಲಿಯಾಸ್ಗಳನ್ನು ಸಹ ನೋಂದಾಯಿಸಲಾಗಿದೆ. ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ `copilot-m365`, `copilot-m365-claude-opus`, `copilot-m365-gpt-5-6-reasoning` ಮತ್ತು `copilot-m365-gpt-5-5-chat` ಮಾನ್ಯವಾಗಿರುತ್ತವೆ. ದಾಖಲಿತ IDs ಗೆ ಒದಗಿಸುವವರ ಪೂರ್ವಪ್ರತ್ಯಯ ಅಗತ್ಯವಿದೆ (`copilot-m365-web/claude-opus` ಅಥವಾ `m365copilot/claude-opus`): ಹಲವು ಸಾಮಾನ್ಯ ಪದಗಳು ಅಥವಾ ಇತರ ಮಾರಾಟಗಾರರ ಮಾದರಿ ಹೆಸರುಗಳು, ಆದ್ದರಿಂದ ಬೇರ್ `claude-opus` ಈ ಪೂರೈಕೆದಾರರಿಲ್ಲದೆ ರೂಟಿಂಗ್ ಮಾಡುತ್ತದೆ. ನೋಂದಣಿಯು ಪ್ರತಿ ಖಾತೆಗೆ Microsoft ಆ ಮಾದರಿಯನ್ನು ಒದಗಿಸುತ್ತದೆ ಎಂಬ ಭರವಸೆಯಲ್ಲ. ಸ್ವತಂತ್ರ IDs ಸಾರ್ವಜನಿಕ [ಪ್ರೋಟೋಕಾಲ್ ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು](https://github.com/cramt/m365-copilot-proxy/blob/main/packages/core/src/copilot.ts) ಅನುಸರಿಸುತ್ತದೆ (ರಫ್ತು ಮಾಡಲಾದ ಮಾಡೆಲ್-ಟು-ಟೋನ್ ಮ್ಯಾಪ್ ಮತ್ತು ಅದರ ಮಾದರಿ-ಅರಿವಿನ ಸನ್ನಿವೇಶ ಮೆಟಾಡೇಟಾ). ಎಲ್ಲಾ ಸ್ಥಳೀಯ ಪ್ರೊಫೈಲ್ಗಳು `availability: "unverified"` ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ; ಕ್ಯಾಟಲಾಗ್ನಲ್ಲಿ ಸೇರಿಸುವಿಕೆಯು ಯಶಸ್ವಿ ಖಾತೆ ಪರೀಕ್ಷೆಯಲ್ಲ.

- ಸ್ಪಷ್ಟ ಮಾದರಿ ಪರವಾನಗಿ ನಿರಾಕರಣೆ ಹಿಂತಿರುಗಿಸುತ್ತದೆ** 403** `m365_model_not_licensed`, 502 ಅಲ್ಲ. connection/model ಜೋಡಿಯಾಗಿರುವ ರೂಟಿಂಗ್ ಲಾಕ್ಗಳು, ಸಂಪರ್ಕದಲ್ಲಿ ಪರವಾನಗಿ ಪಡೆದ ಮಾದರಿಗಳನ್ನು ಬಳಸಬಹುದಾಗಿದೆ.
- `InvalidCopilotLicense` ಎನ್ನುವುದು ಖಾತೆ ಮಟ್ಟದ ಪರವಾನಗಿ ನಿರಾಕರಣೆಯಾಗಿದ್ದು, `m365_account_not_licensed` ಎಂದು ಪ್ರತ್ಯೇಕವಾಗಿ ವರದಿ ಮಾಡಲಾಗಿದೆ.
- ಪ್ರತಿ ಬಳಕೆದಾರರ ಥ್ರೊಟಲ್ ಹಿಂತಿರುಗಿಸುತ್ತದೆ** 429** `m365_throttled` ಮತ್ತು ಸಂಪರ್ಕವನ್ನು ತಂಪಾಗಿಸುತ್ತದೆ. ಆದ್ಯತೆ-ಪ್ರವೇಶದ ಬಳಲಿಕೆ ಮರಳುತ್ತದೆ** 429** `priority_access_exhausted` ಮತ್ತು ಮಾದರಿ-ವ್ಯಾಪ್ತಿ ಹೊಂದಿದೆ. `errorCode: "ReasoningTurnExhausted"` ರಿಟರ್ನ್ಗಳೊಂದಿಗೆ `OutOfCredits` ಫಲಿತಾಂಶ** 429** `reasoning_turns_exhausted` ಬದಲಿಗೆ, ಮಾಡೆಲ್-ಸ್ಕೋಪ್ಡ್, ಯಾವುದೇ ಮರುಹೊಂದಿಸುವ ಸಮಯವನ್ನು ಕ್ಲೈಮ್ ಮಾಡಿಲ್ಲ. ಕ್ವಿಕ್ ಟೋನ್ಗಳು ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿರುವಾಗ "ಆಳವಾಗಿ ಯೋಚಿಸಿ" ಟೋನ್ಗಳನ್ನು ಕ್ಯಾಪ್ ಮಾಡಲು ಒಬ್ಬ ಕೆಲಸದ ಬಾಡಿಗೆದಾರರ ಮೇಲೆ ವರದಿ ಮಾಡಲಾಗಿದೆ; ವ್ಯಾಪ್ತಿಯು ಗ್ರಾಹಕರ ವೀಕ್ಷಣೆಯಾಗಿದೆ, ಈ ಭಂಡಾರವು ಪುನರುತ್ಪಾದಿಸಿದ ವಿಷಯವಲ್ಲ. ಆದ್ದರಿಂದ ರೂಟಿಂಗ್ ಇತರ ದಾಖಲಿತ ಥಿಂಕ್ ಆಳವಾದ ಮಾದರಿಗಳಾದ `gpt-5.5` ಮತ್ತು `gpt-5.6` ಅನ್ನು ಅದೇ ಕೂಲ್ಡೌನ್ಗಾಗಿ ಆ ಸಂಪರ್ಕದ ಮೇಲೆ ತಿರುಗುವಿಕೆಯಿಂದ ಹೊರಕ್ಕೆ ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ ಮತ್ತು ಕ್ವಿಕ್ ಟೋನ್ಗಳು ಮತ್ತು ಪ್ರತಿಯೊಂದು ವೈಫಲ್ಯವನ್ನು ತನ್ನದೇ ಆದ ಮಾದರಿಯಲ್ಲಿ ಬಿಡುತ್ತದೆ. ಸರಬರಾಜು ಮಾಡಿದ ಮರುಪ್ರಯತ್ನದ ಸುಳಿವುಗಳನ್ನು ಸಂರಕ್ಷಿಸಲಾಗಿದೆ; ಕಾಣೆಯಾದ ಮರುಹೊಂದಿಕೆಯನ್ನು ತಿಳಿದಿರುವ ಮರುಹೊಂದಿಸುವ ಸಮಯ ಎಂದು ಪ್ರಚಾರ ಮಾಡಲಾಗಿಲ್ಲ.
- ಒಂದು Copilot ಸುರಕ್ಷತೆ ನಿರಾಕರಣೆ (`Disengaged`) ಹಿಂದಿರುಗಿಸುತ್ತದೆ** 400** `provider_safety_rejection`, ಹಂಚಿದ ಪೂರೈಕೆದಾರರ ಸುರಕ್ಷತೆ-ನಿಲುಗಡೆ ಲೇಬಲ್. ಇದು ಸಂಪರ್ಕದ ಆರೋಗ್ಯದ ವಿರುದ್ಧ ಎಂದಿಗೂ ಎಣಿಸುವುದಿಲ್ಲ, ಕ್ಲೈಂಟ್ SDKs 400 ಅನ್ನು ಮರುಪ್ರಯತ್ನಿಸಬೇಡಿ, ಮತ್ತು `PROVIDER_SAFETY_STOPS_TERMINAL` ಸಕ್ರಿಯಗೊಳಿಸಿದ ಕಾಂಬೊ ರೂಟಿಂಗ್ ಮತ್ತೊಂದು ಗುರಿಯ ವಿರುದ್ಧ ವಿನಂತಿಯನ್ನು ಮರುಪಂದ್ಯ ಮಾಡುವ ಬದಲು ಅಲ್ಲಿಯೇ ನಿಲ್ಲುತ್ತದೆ.
- ಒಂದು ಸಂಪರ್ಕದ ಮೇಲಿನ ವಿನಂತಿಗಳು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಖಾತೆ ಸೆಮಾಫೋರ್ ಮೂಲಕ ಸರಣಿಯಾಗಿವೆ. ಸಮಾನಾಂತರ ಫಲಕಗಳಿಗಿಂತ ಆದ್ಯತೆಯ ಫಾಲ್ಬ್ಯಾಕ್ಗೆ ಆದ್ಯತೆ ನೀಡಿ; ಧಾರಾವಾಹಿ ಮಾತ್ರ Microsoft ನ ಸಂಭಾಷಣೆ-ದರ ಮಿತಿಗಳನ್ನು ತೆಗೆದುಹಾಕುವುದಿಲ್ಲ.

## ನಡವಳಿಕೆ ಮತ್ತು ಮಿತಿಗಳನ್ನು ವಿನಂತಿಸಿ

- ಪರಿಕರಗಳು** ಪ್ರಾಂಪ್ಟ್-ಎಮ್ಯುಲೇಟೆಡ್** , ಸ್ಥಳೀಯ Microsoft ಫಂಕ್ಷನ್ ಕರೆಗಳಲ್ಲ. ಪರಿಕರ-ಸಕ್ರಿಯಗೊಳಿಸಿದ ವಿನಂತಿಯು ಒಂದು ಬಫರ್ಡ್ ಪೀಳಿಗೆಯನ್ನು ಬಳಸುತ್ತದೆ; ಇದು ಉಪಕರಣಗಳನ್ನು ಆಯ್ಕೆಮಾಡಲು ಮತ್ತೊಂದು ಪೀಳಿಗೆಯನ್ನು ಕಳೆಯುವುದಿಲ್ಲ. ಮಾನ್ಯವಾದ ಬೆಂಬಲಿತ ಆರ್ಗ್ಯುಮೆಂಟ್ ಆಕಾರಗಳೊಂದಿಗೆ ಡಿಕ್ಲೇರ್ಡ್ ಪರಿಕರಗಳನ್ನು ಮಾತ್ರ ಕರೆಗಳಾಗಿ ಹಿಂತಿರುಗಿಸಲಾಗುತ್ತದೆ.
- ಒಂದೇ ಹಿಂದುಳಿದ ಉದಾಹರಣೆಯೊಂದಿಗೆ ದೀರ್ಘ ರಚನಾತ್ಮಕ ಉತ್ತರವನ್ನು ಗದ್ಯವಾಗಿ ಸಂರಕ್ಷಿಸಲಾಗಿದೆ. ಇದು ಹ್ಯೂರಿಸ್ಟಿಕ್ ಆಗಿದೆ, ಉದ್ದೇಶದ ಪುರಾವೆ ಅಲ್ಲ; ಅಪ್ಲಿಕೇಶನ್ಗಳು ಇನ್ನೂ ತಮ್ಮದೇ ಆದ ಟೂಲ್ ಅನುಮತಿಗಳನ್ನು ಜಾರಿಗೊಳಿಸಬೇಕು.
- ಇಮೇಜ್ ಇನ್ಪುಟ್ ವೆಬ್ ಕ್ಲೈಂಟ್ ಕಳುಹಿಸುವ ರೀತಿಯಲ್ಲಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ. ಪ್ರತಿಯೊಂದು ಚಿತ್ರದ ಭಾಗ (`image_url` ಡೇಟಾ URL ಅಥವಾ ಸಾರ್ವಜನಿಕ HTTPS URL, ಅಥವಾ ಪ್ರತಿಕ್ರಿಯೆಗಳು `input_image`) ಅನ್ನು `/m365Copilot/UploadFile` ಗೆ ಚಾಟ್ ಟೋಕನ್ನೊಂದಿಗೆ ಟರ್ನ್ನ ಸಂಭಾಷಣೆಗೆ ಅಪ್ಲೋಡ್ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು ಸಂದೇಶವು `ImageFile` ಟಿಪ್ಪಣಿಯೊಂದಿಗೆ ಅದನ್ನು ಸೂಚಿಸುತ್ತದೆ; ಪಠ್ಯವು ಎಲ್ಲಿ ಕುಳಿತಿದೆ ಎಂಬುದನ್ನು ಗುರುತಿಸುತ್ತದೆ (`[image 1]`, ...). ಹೊಸ ಸಂಭಾಷಣೆಯು ಇತಿಹಾಸದಲ್ಲಿ ಪ್ರತಿ ಚಿತ್ರವನ್ನು ಅಪ್ಲೋಡ್ ಮಾಡುತ್ತದೆ, ಹೊಸ ಸಂದೇಶಗಳ ಚಿತ್ರಗಳನ್ನು ಮಾತ್ರ ಮುಂದುವರಿಸಲಾಗುತ್ತದೆ. 10 PNG ವರೆಗೆ , JPEG, GIF ಅಥವಾ WebP ಪ್ರತಿ 10 MiB ಚಿತ್ರಗಳು (ಪ್ರತಿ ವಿನಂತಿಗೆ 40 MiB ); ಸ್ವರೂಪವನ್ನು ಬೈಟ್ಗಳಿಂದ ಓದಲಾಗುತ್ತದೆ. HTTPS URLs ಅನ್ನು ಸಾರ್ವಜನಿಕ-ಮಾತ್ರ, DNS-ಪಿನ್ ಮಾಡಿದ ರಿಮೋಟ್ ಇಮೇಜ್ ಗಾರ್ಡ್ ಮೂಲಕ ಪಡೆಯಲಾಗುತ್ತದೆ. ವಿಫಲವಾದ ಅಪ್ಲೋಡ್ ವಿನಂತಿಯನ್ನು ವಿಫಲಗೊಳಿಸುತ್ತದೆ (** 502** `m365_image_upload_failed`,** 400** `m365_image_rejected` ಅಥವಾ `m365_image_invalid`); ನೀಡಿದ ಚಿತ್ರವಿಲ್ಲದೆ ತಿರುವು ಎಂದಿಗೂ ಮುಂದಕ್ಕೆ ಹೋಗುವುದಿಲ್ಲ. ಇತರ ಪಠ್ಯೇತರ ಭಾಗಗಳನ್ನು (ಆಡಿಯೋ, ಫೈಲ್ಗಳು) ಸ್ಪಷ್ಟವಾಗಿ ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ, ಮೌನವಾಗಿ ಕೈಬಿಡುವುದಿಲ್ಲ.
- ಫಾಲೋ-ಅಪ್ ವಿನಂತಿಯು ಅದೇ ಅಪ್ಸ್ಟ್ರೀಮ್ ಸಂಭಾಷಣೆಯನ್ನು ಮುಂದುವರೆಸುತ್ತದೆ ಮತ್ತು ಹಿಂದಿನ ಪ್ರತ್ಯುತ್ತರದ ನಂತರ ಸಂದೇಶಗಳನ್ನು ಮಾತ್ರ ಕಳುಹಿಸುತ್ತದೆ. ಇದು ನಿಖರವಾಗಿ ಉತ್ತರವನ್ನು ವಿಸ್ತರಿಸಬೇಕು: ಅದೇ ಸಂಪರ್ಕ, ಮಾದರಿ ಪ್ರೊಫೈಲ್ ಮತ್ತು ಟೂಲ್ ಸೆಟ್; ಬದಲಾಗದ ಇತಿಹಾಸ (ಪ್ರತಿ ಸಂದೇಶದ ಮೇಲೆ sha256 ಸರಣಿ); ಮತ್ತು ಪ್ರತ್ಯುತ್ತರದ ಟೂಲ್-ಕಾಲ್ ಐಡಿಗಳು, ಅಥವಾ ಅದರ ಪಠ್ಯವನ್ನು ವೈಟ್ಸ್ಪೇಸ್ವರೆಗೆ. ಬೇರೆ ಯಾವುದಾದರೂ (ಸಂಪಾದಿತ ಇತಿಹಾಸ, ಅದೇ ಮೊದಲ ಸಂದೇಶದೊಂದಿಗೆ ಮತ್ತೊಂದು ಸೆಶನ್, ವಿಭಿನ್ನ ಪ್ರತ್ಯುತ್ತರ, 30 ನಿಮಿಷಗಳ ಕಾಲ ನಿಷ್ಫಲವಾಗಿರುವ ಸಂಭಾಷಣೆ ಅಥವಾ Copilot ನ 600-ಸಂದೇಶದ ಕ್ಯಾಪ್ ಹತ್ತಿರ, ಐಡಿ ಇಲ್ಲದ ಸಂಪರ್ಕ) ಇಡೀ ಇತಿಹಾಸದೊಂದಿಗೆ ಹೊಸ ಸಂಭಾಷಣೆಯನ್ನು ಪ್ರಾರಂಭಿಸುತ್ತದೆ. ವಿಫಲವಾದ ತಿರುವು ಎಂದಿಗೂ ಪುನರಾರಂಭಿಸಲ್ಪಡುವುದಿಲ್ಲ ಮತ್ತು ತಾಜಾ ಸಂಭಾಷಣೆಯಲ್ಲಿ ಒಂದು ವಿಷಯ-ಕಡಿಮೆ `InternalError` ಮರು-ಕಳುಹಿಸಲಾಗುತ್ತದೆ (** 502** `m365_internal_error` ಮತ್ತೆ ವಿಫಲವಾದರೆ). ಮುಂದುವರಿಕೆಗಳನ್ನು ಪ್ರಕ್ರಿಯೆಯ ಸ್ಮರಣೆಯಲ್ಲಿ ಇರಿಸಲಾಗುತ್ತದೆ: ಮರುಪ್ರಾರಂಭವು ತಾಜಾ ಸಂಭಾಷಣೆಗಳನ್ನು ಪ್ರಾರಂಭಿಸುತ್ತದೆ.
- ಪ್ರತಿ ತಿರುವು Copilot ನ ತಾತ್ಕಾಲಿಕ ಚಾಟ್ನಲ್ಲಿ ಚಲಿಸುತ್ತದೆ (`disableMemory=1`): ಸಂಭಾಷಣೆಯು ಚಾಲನೆಯಲ್ಲಿರುವಾಗ ಅದರ ಸಂದರ್ಭವನ್ನು ಇರಿಸುತ್ತದೆ ಮತ್ತು ಖಾತೆಯ ಚಾಟ್ ಇತಿಹಾಸದಲ್ಲಿ ಎಂದಿಗೂ ಕಾಣಿಸುವುದಿಲ್ಲ. ಮಾದರಿ ಪರೀಕ್ಷೆಗಳು, ಎಲ್ಲವನ್ನೂ ಪರೀಕ್ಷಿಸಿ ಮತ್ತು ಕಾಂಬೊ ಪರೀಕ್ಷೆಗಳು ಆದ್ದರಿಂದ ಸಂಭಾಷಣೆಗಳನ್ನು ಬಿಡದೆಯೇ ಈ ಪೂರೈಕೆದಾರರನ್ನು ತನಿಖೆ ಮಾಡಬಹುದು.
- ಒಂದು ತಿರುವು 120-ಸೆಕೆಂಡ್ ಐಡಲ್ ಡೆಡ್ಲೈನ್ ಮತ್ತು ಮಿತಿಯ ಒಟ್ಟಾರೆ ಗಡುವನ್ನು ಹೊಂದಿದೆ. ಅಂತಿಮ-ಮಾತ್ರ ಉತ್ತರಗಳು, ಪ್ರಗತಿ ಫಿಲ್ಟರಿಂಗ್ ಮತ್ತು ರದ್ದತಿಯನ್ನು ಸ್ಥಳೀಯ transport/composer. ನಿರ್ವಹಿಸುತ್ತದೆ
- ವೆಬ್-ಆಧಾರಿತ ಉತ್ತರಗಳು ತಮ್ಮ ಮೂಲಗಳನ್ನು ಇಟ್ಟುಕೊಳ್ಳುತ್ತವೆ. Copilot ಖಾಸಗಿ ಬಳಕೆಯ ನಿಯಂತ್ರಣ ಅಕ್ಷರಗಳೊಂದಿಗೆ ಒಂದು ಉಲ್ಲೇಖವನ್ನು ಗುರುತಿಸುತ್ತದೆ ಮತ್ತು ಮೂಲಗಳನ್ನು `references` ಎಂದು ಕಳುಹಿಸುತ್ತದೆ; ಪ್ರತಿ ಮಾರ್ಕರ್ ಒಂದು ಸಂಖ್ಯೆಯ ಮಾರ್ಕ್ಡೌನ್ ಲಿಂಕ್ ಆಗುತ್ತದೆ (`[1](https://…)`, ಅಥವಾ Copilot ಮಾರ್ಕರ್ ಅನ್ನು ಲಿಂಕ್ ಗುರಿಯಾಗಿ ಬಳಸಿದಾಗ ಬೇರ್ URL ) ಹೊಂದಾಣಿಕೆಯ `url_citation` ಟಿಪ್ಪಣಿಯೊಂದಿಗೆ (`message.annotations`, ಅಥವಾ ಲಿಂಕ್ ಅನ್ನು ಹೊಂದಿರುವ ಭಾಗದ ಮೇಲೆ `delta.annotations` ). ಎಂದಿಗೂ ಆಗಮಿಸದ ಮೂಲವನ್ನು ಕೈಬಿಡಲಾಗಿದೆ, ಆದ್ದರಿಂದ ಮಾರ್ಕರ್ಗಳು ಎಂದಿಗೂ ಕ್ಲೈಂಟ್ ಅನ್ನು ತಲುಪುವುದಿಲ್ಲ. ಸ್ಟ್ರೀಮಿಂಗ್ ಮಾಡುವಾಗ, ಉಲ್ಲೇಖದ ನಂತರ ಪಠ್ಯವು ಅದರ ಮೂಲವು ಬರುವವರೆಗೆ ಕಾಯುತ್ತದೆ.
- Copilot ನ ತಾರ್ಕಿಕ ಸಾರಾಂಶ (`ChainOfThoughtSummary`), ಮಾದರಿಯು ಒಂದನ್ನು ಕಳುಹಿಸಿದಾಗ, `reasoning_content` ಎಂದು ಹಿಂತಿರುಗಿಸಲಾಗುತ್ತದೆ, ಉತ್ತರದ ಭಾಗವಾಗಿ ಎಂದಿಗೂ. ಸ್ವತಃ ಪುನಃ ಬರೆಯುವ ಸಾರಾಂಶವು ತಿರುವು ವಿಫಲಗೊಳ್ಳದೆ ಸ್ಟ್ರೀಮಿಂಗ್ ಅನ್ನು ನಿಲ್ಲಿಸುತ್ತದೆ.
- ಯಾವುದೇ ವಿಷಯದ ಮೊದಲು, ಸ್ಟ್ರೀಮಿಂಗ್ ಅನ್ನು ವಿನಂತಿಸಿದಾಗಲೂ licence/throttle ವೈಫಲ್ಯಗಳು HTTP 403/429 ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ. ವಿಷಯ ಪ್ರಾರಂಭವಾದ ನಂತರ, ವೈಫಲ್ಯಗಳು SSE ದೋಷ ಘಟನೆಗಳು, ಎಂದಿಗೂ ಯಶಸ್ವಿ ಮುಕ್ತಾಯವಾಗುವುದಿಲ್ಲ. ಅನುಬಂಧ-ಮಾತ್ರ ಸ್ಟ್ರೀಮಿಂಗ್ ಮೂಲಕ ಪ್ರತಿನಿಧಿಸಲಾಗದ ಅಪ್ಸ್ಟ್ರೀಮ್ ಪುನಃ ಬರೆಯುವಿಕೆಯು ಸ್ಪಷ್ಟವಾದ ಸ್ಟ್ರೀಮ್ ದೋಷವಾಗಿದೆ; ಸ್ಟ್ರೀಮಿಂಗ್ ಅಲ್ಲದ ಮತ್ತು ಬಫರ್ ಟೂಲ್ ಪ್ರತಿಕ್ರಿಯೆಗಳು ಅಂತಿಮ ಪಠ್ಯವನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ.
- Copilot ಸಂಪರ್ಕವನ್ನು ನಿರಾಕರಿಸಿದಾಗ, ಅದರ ಉತ್ತರವನ್ನು ವರದಿ ಮಾಡಲಾಗಿದೆ:** 401** ತಿರಸ್ಕರಿಸಿದ ಅಥವಾ ಅವಧಿ ಮೀರಿದ ಸೈನ್-ಇನ್ಗಾಗಿ `m365_unauthorized` (ಮತ್ತೆ ಸೈನ್ ಇನ್ ಮಾಡಿ),** 429** ಥ್ರೊಟ್ಲಿಂಗ್ಗಾಗಿ ಅದರ `Retry-After` ಜೊತೆಗೆ, ಮತ್ತು ಹ್ಯಾಂಡ್ಶೇಕ್ ವಿಫಲವಾದರೆ, ಎಂದಿಗೂ ಸಾಮಾನ್ಯ ಸಂಪರ್ಕ ವೈಫಲ್ಯವಲ್ಲ.

## ಚಿತ್ರ ರಚನೆ

`model: "copilot-m365-web/m365-copilot-image"` ನೊಂದಿಗೆ`POST /v1/images/generations` (ಅಲಿಯಾಸ್ `m365copilot/m365-copilot-image`) ವೆಬ್ ಕ್ಲೈಂಟ್ ಮಾಡುವಂತೆ Copilot ನ ಅಂತರ್ನಿರ್ಮಿತ ಇಮೇಜ್ ಟೂಲ್ನೊಂದಿಗೆ ಸೆಳೆಯುತ್ತದೆ. ಪ್ರತಿ ಚಿತ್ರವು ಒಂದು Copilot ತಿರುವು: ಇದು ವೆಬ್ ಕ್ಲೈಂಟ್ನ ಇಮೇಜ್ ಆಯ್ಕೆಯೊಂದಿಗೆ ಆಯ್ಕೆಮಾಡುತ್ತದೆ ಮತ್ತು `GenerateGraphicArt` ಘೋಷಿಸುತ್ತದೆ ಮತ್ತು Microsoft ನ ಡಿಸೈನರ್ ಸೇವೆಯಲ್ಲಿನ ಕಲಾಕೃತಿಯನ್ನು ಸೂಚಿಸುವ ಪ್ರಗತಿಯ ಪ್ರವೇಶದಲ್ಲಿ ಚಿತ್ರವು ಆಗಮಿಸುತ್ತದೆ. ಆ ಕಲಾಕೃತಿಯು ಚಾಟ್ ಟೋಕನ್ ಅನ್ನು ನಿರಾಕರಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ OmniRoute ಸಂಪರ್ಕದ ರಿಫ್ರೆಶ್ ಟೋಕನ್ನಿಂದ ಡಿಸೈನರ್ ಟೋಕನ್ ಅನ್ನು ಮುದ್ರಿಸುತ್ತದೆ ಮತ್ತು ಬೈಟ್ಗಳನ್ನು ಡೌನ್ಲೋಡ್ ಮಾಡುತ್ತದೆ; ಟೋಕನ್ ಅನ್ನು `designerapp.officeapps.live.com` ಗೆ ಮಾತ್ರ ಕಳುಹಿಸಲಾಗುತ್ತದೆ.

- ಸ್ಥಳೀಯ ಸೈನ್-ಇನ್ ಸಂಪರ್ಕದ ಅಗತ್ಯವಿದೆ (ರಿಫ್ರೆಶ್ ಟೋಕನ್); ಅಂಟಿಸಿದ ಟೋಕನ್ ವಿಫಲಗೊಳ್ಳುತ್ತದೆ** 400** ಯಾವುದೇ ತಿರುವು ಕಳೆಯುವ ಮೊದಲು.
- `n` 1-4, ಪ್ರತಿ ಒಂದು ತಿರುವು. `size` ಮಾತ್ರ ಓರಿಯಂಟೇಶನ್ (ಅಗಲ, ಎತ್ತರ ಅಥವಾ ಚದರ), Copilot ಪ್ರಾಂಪ್ಟ್ನಿಂದ ಓದುತ್ತದೆ; Copilot ರೆಂಡರ್ ಗಾತ್ರವನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ.
- ಚಿತ್ರಗಳನ್ನು ಇನ್ಲೈನ್ಗೆ ಹಿಂತಿರುಗಿಸಲಾಗುತ್ತದೆ: `b64_json` ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ, `response_format: "url"` ಗಾಗಿ ಡೇಟಾ URL.
- ರಚಿಸಿದ ಚಿತ್ರಗಳು ಚಾಟ್ನಿಂದ ಪ್ರತ್ಯೇಕವಾದ ಸಣ್ಣ ದೈನಂದಿನ ಬಜೆಟ್ನಲ್ಲಿ ಸೆಳೆಯುತ್ತವೆ. ಅದನ್ನು ಬಳಸಿದಾಗ ವಿನಂತಿಯು ವಿಫಲಗೊಳ್ಳುತ್ತದೆ** 429** . ಚಿತ್ರವಿಲ್ಲದೆ ಉತ್ತರಿಸುವ ತಿರುವು ವಿಫಲಗೊಳ್ಳುತ್ತದೆ** 502** (ಅಥವಾ** 400** /** 503** Copilot ನ ಪಠ್ಯವು ನಿರಾಕರಣೆ ಅಥವಾ ಸಾಮರ್ಥ್ಯದ ಸಮಸ್ಯೆ ಎಂದು ಓದಿದಾಗ); ಸಂದೇಶವು ಹೇಳುತ್ತದೆ.

## ಭದ್ರತಾ ಮಾದರಿ

- **ಅನಧಿಕೃತ ಏಕೀಕರಣ.** ಈ ಪೂರೈಕೆದಾರರು BizChat WebSocket ಪ್ರೋಟೋಕಾಲ್ ಅನ್ನು ರಿವರ್ಸ್-ಎಂಜಿನಿಯರ್ ಮಾಡುತ್ತಾರೆ. Microsoft ಅಂತಿಮ ಬಿಂದುವನ್ನು ಬದಲಾಯಿಸಿದಾಗ ಅದು ಸೂಚನೆಯಿಲ್ಲದೆ ಮುರಿಯಬಹುದು.
- `subscriptionRisk: true` ಧ್ವಜವು ಏಕೀಕರಣವು ದಾಖಲೆರಹಿತ ಅಂತ್ಯಬಿಂದುವನ್ನು ಅವಲಂಬಿಸಿದೆ ಎಂಬುದನ್ನು ಪ್ರತಿಬಿಂಬಿಸುತ್ತದೆ. ಖಾತೆ ನಿರ್ಬಂಧಗಳು ಸಾಧ್ಯ ಆದರೆ ದೃಢೀಕರಿಸಲಾಗಿಲ್ಲ.
- ಪ್ರವೇಶ ಟೋಕನ್ ಅಲ್ಪಾವಧಿಯ JWT ಆಗಿದೆ. ಇದನ್ನು ಪಾಸ್ವರ್ಡ್ನಂತೆ ಪರಿಗಣಿಸಿ: ಅದನ್ನು ಒಪ್ಪಿಸಬೇಡಿ, ಲಾಗ್ ಮಾಡಬೇಡಿ ಅಥವಾ ಹಂಚಿಕೊಳ್ಳಬೇಡಿ.
- ರಿಫ್ರೆಶ್ ಟೋಕನ್ Microsoft 365 ಮೇಲ್ಮೈಗೆ ನಡೆಯುತ್ತಿರುವ ಪ್ರವೇಶವನ್ನು ನೀಡುತ್ತದೆ. API ಕೀಲಿಯಂತೆ ಅದೇ ಕಾಳಜಿಯೊಂದಿಗೆ ಅದನ್ನು ಸಂಗ್ರಹಿಸಿ.

## ದೋಷನಿವಾರಣೆ

### ದೃಢೀಕರಣವು ತಕ್ಷಣವೇ ವಿಫಲಗೊಳ್ಳುತ್ತದೆ

- ನಿಂದ ನೀವು ನಕಲಿಸಿರುವಿರಿ ಎಂದು ಪರಿಶೀಲಿಸಿ**WebSocket URL** , XHR/Fetch ವಿನಂತಿಯಿಂದ ಅಲ್ಲ. ರುಜುವಾತು ಚತುಬ್ WebSocket ಸಂಪರ್ಕದ `access_token` ಪ್ರಶ್ನೆ ಪ್ಯಾರಾಮೀಟರ್ನಲ್ಲಿದೆ `Authorization: Bearer` ಹೆಡರ್ನಲ್ಲಿ —.
- `chathubPath` URL ಮಾರ್ಗದಿಂದ ಪೂರ್ಣ `<oid>@<tenant>` ವಿಭಾಗವನ್ನು ಒಳಗೊಂಡಿದೆ ಎಂದು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ.

### 75 ನಿಮಿಷಗಳ ನಂತರ ~ ಅವಧಿ ಮುಗಿಯುತ್ತದೆ

ಇದನ್ನು ನಿರೀಕ್ಷಿಸಲಾಗಿದೆ. `refreshToken` ಇಲ್ಲದೆ, ಪ್ರವೇಶ ಟೋಕನ್ ಅಲ್ಪಕಾಲಿಕವಾಗಿರುತ್ತದೆ. ಒಂದೋ:

- DevTools ನಿಂದ ರುಜುವಾತುಗಳನ್ನು ಮರು-ಕ್ಯಾಪ್ಚರ್ ಮಾಡಿ , ಅಥವಾ
- ಕಾನ್ಫಿಗರ್ ಮಾಡಿ** ಸುಧಾರಿತ ಸೆಟ್ಟಿಂಗ್ಗಳು → ರಿಫ್ರೆಶ್ ಟೋಕನ್ (ಐಚ್ಛಿಕ)** ಸ್ವಯಂಚಾಲಿತ ರಿಫ್ರೆಶ್ಗಾಗಿ ಸಂಪರ್ಕವನ್ನು ಸೇರಿಸಿ ಅಥವಾ ಸಂಪಾದಿಸು ಸಂವಾದದಲ್ಲಿ.

### ಪರೀಕ್ಷಾ ಸಂಪರ್ಕವು ಹಾದುಹೋಗುತ್ತದೆ ಆದರೆ ಚಾಟ್ 401 ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ

ಇದರೊಂದಿಗೆ ರಚಿಸಲಾದ ಸಂಪರ್ಕಕ್ಕಾಗಿ** Microsoft ನೊಂದಿಗೆ ಸೈನ್ ಇನ್ ಮಾಡಿ** , ಪರೀಕ್ಷಾ ಸಂಪರ್ಕವು ಪ್ರವೇಶ ಟೋಕನ್ನ ಮುಕ್ತಾಯವನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು ಸಂಗ್ರಹಿಸಿದ ರಿಫ್ರೆಶ್ ಟೋಕನ್ನೊಂದಿಗೆ ಅವಧಿ ಮೀರಿದ ಟೋಕನ್ ಅನ್ನು ನವೀಕರಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಪಾಸಿಂಗ್ ಪರೀಕ್ಷೆಯು ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಇನ್ನೂ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ ಎಂದು ಸಾಬೀತುಪಡಿಸುತ್ತದೆ.

ಅಂಟಿಸಲಾದ ರುಜುವಾತುಗಳಿಗಾಗಿ, ಪರೀಕ್ಷಾ ಸಂಪರ್ಕವು ರುಜುವಾತುಗಳ ಆಕಾರವನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು ಟೋಕನ್ ಅವಧಿ ಮೀರಿದಾಗ, ಒದಗಿಸುವವರು ಬಳಸುವ ಟೋಕನ್ ಅವಧಿ ಮುಗಿದಿಲ್ಲ (ಸಂಪರ್ಕದಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾದ ಟೋಕನ್ ಹಳೆಯ ಪೇಸ್ಟ್ ಅನ್ನು ಗೆಲ್ಲುತ್ತದೆ; ರಿಫ್ರೆಶ್ ಟೋಕನ್ ನವೀಕರಿಸಬಹುದಾದಂತೆ ಎಣಿಕೆಯಾಗುತ್ತದೆ). ಅವಧಿ ಮುಗಿಯುವ ಮೊದಲು ಹಿಂತೆಗೆದುಕೊಳ್ಳಲಾದ ಟೋಕನ್ ಇನ್ನೂ ಪರೀಕ್ಷೆಯಲ್ಲಿ ಉತ್ತೀರ್ಣವಾಗುತ್ತದೆ; ಚಾಟ್ ನಂತರ ಹಿಂತಿರುಗುತ್ತದೆ** 401** `m365_unauthorized` ಬಳಸಿ** Microsoft ನೊಂದಿಗೆ ಸೈನ್ ಇನ್ ಮಾಡಿ** ಮತ್ತೊಮ್ಮೆ, ಅಥವಾ ಹೊಸ ರುಜುವಾತುಗಳನ್ನು ಪುನಃ ವಶಪಡಿಸಿಕೊಳ್ಳಿ.

### Copilot ಒದಗಿಸುವವರ ಪಟ್ಟಿಯಲ್ಲಿ ಕಾಣಿಸುವುದಿಲ್ಲ

`copilot-m365-web` ಸಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ ಎಂದು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ** ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಪೂರೈಕೆದಾರರು** . ಪೂರೈಕೆದಾರರನ್ನು ಕೆಲವು ಶ್ರೇಣಿಗಳಲ್ಲಿ ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಮರೆಮಾಡಬಹುದು.
