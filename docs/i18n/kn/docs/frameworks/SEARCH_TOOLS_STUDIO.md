## ಟ್ಯಾಬ್ಗಳು

### ಹುಡುಕಾಟ ಟ್ಯಾಬ್

ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ `SearchForm` + `ResultsPanel` + `RerankPanel` ಅನ್ನು ಟ್ಯಾಬ್ಗೆ ವಿಕಸನಗೊಳಿಸುತ್ತದೆ:

- ಪ್ರಶ್ನೆ → ಫಲಿತಾಂಶಗಳು (ಶೀರ್ಷಿಕೆ, URL, ತುಣುಕು, ಪ್ರಸ್ತುತತೆ ಸ್ಕೋರ್).
- ಸಂರಚನಾ ಫಲಕದಲ್ಲಿ ಒದಗಿಸುವವರ ಮೆಟಾಡೇಟಾ (ವೆಚ್ಚ, ಕೋಟಾ, ಸ್ಥಿತಿ).
- ರೀರ್ಯಾಂಕ್ ವಿಭಾಗ: ರೀರ್ಯಾಂಕ್ ಮಾಡೆಲ್ ಅನ್ನು ಆರಿಸಿ, ಫಲಿತಾಂಶಗಳನ್ನು ಮರುಕ್ರಮಗೊಳಿಸಿ, `positionDelta` ತೋರಿಸಿ .
- ಯಾವುದೇ ಹುಡುಕಾಟ ಪೂರೈಕೆದಾರರನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡದಿದ್ದಾಗ CTA ನೊಂದಿಗೆ ಖಾಲಿ ಸ್ಥಿತಿ.
- `SearchHistory.tsx` ಮೂಲಕ ಇತಿಹಾಸವನ್ನು ಹುಡುಕಿ.
- `POST /v1/search` ಕರೆಗಳು (ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಅಂತಿಮ ಬಿಂದು, ಯಾವುದೇ ಬದಲಾವಣೆಗಳಿಲ್ಲ).

### ಸ್ಕ್ರಾಪ್ ಟ್ಯಾಬ್

`POST /v1/web/fetch` ಮೂಲಕ URL ನಿಂದ ವಿಷಯವನ್ನು ಹೊರತೆಗೆಯಲು ಹೊಸ ಟ್ಯಾಬ್ (ಯೋಜನೆ 05 ರಲ್ಲಿ ರಚಿಸಲಾಗಿದೆ):

- ಇನ್ಪುಟ್: URL + ಪೂರ್ಣ-ಪುಟ ಟಾಗಲ್ + ಫಾರ್ಮ್ಯಾಟ್ ಸೆಲೆಕ್ಟರ್ (ಮಾರ್ಕ್ಡೌನ್ / ಪಠ್ಯ / HTML).
- ಸಲ್ಲಿಸಿ → ಪಡೆದುಕೊಳ್ಳಿ → ಸಲ್ಲಿಸಿ `ScrapeResult.tsx`.
- `ScrapeResult` ಮಾರ್ಕ್ಡೌನ್ ಪೂರ್ವವೀಕ್ಷಣೆ + ರಾ ಟಾಗಲ್ ಅನ್ನು ನೀಡುತ್ತದೆ.
- ಕ್ಯಾಪ್: ಪ್ರತಿಕ್ರಿಯೆ ದೇಹದ > ವೇಳೆ** 256 KB** , UI `(truncated, view raw)` ತೋರಿಸುತ್ತದೆ ಮತ್ತು ಮೊನಾಕೊ ಮಾದರಿಯಲ್ಲಿ (D21) ಕಚ್ಚಾ ತೆರೆಯುತ್ತದೆ.
- ಮೆಟಾಡೇಟಾ ಫಲಕ: ಒದಗಿಸುವವರು (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search/parallel-search/keenable-search), ಸುಪ್ತತೆ, ವೆಚ್ಚ, ಪ್ರತಿಕ್ರಿಯೆ ಗಾತ್ರ, ಲಿಂಕ್ಗಳ ಎಣಿಕೆ.
- `useScrapeFetch.ts` ಹುಕ್ ಅನ್ನು ಬಳಸುತ್ತದೆ.

### ಟ್ಯಾಬ್ ಅನ್ನು ಹೋಲಿಕೆ ಮಾಡಿ

ವರೆಗೆ ಒಂದೇ query/URL ರನ್ ಮಾಡುತ್ತದೆ** ಸಮಾನಾಂತರವಾಗಿ 4 ಪೂರೈಕೆದಾರರು** (D22):

- ಪ್ರತಿ ಪೂರೈಕೆದಾರರಿಗೆ ಅಕ್ಕಪಕ್ಕದ ಕಾಲಮ್ಗಳು.
- ಮೆಟ್ರಿಕ್ಸ್: ಲೇಟೆನ್ಸಿ, ವೆಚ್ಚ, ಫಲಿತಾಂಶ ಎಣಿಕೆ, ಪ್ರತಿಕ್ರಿಯೆ ಗಾತ್ರ.
- ಹುಡುಕಾಟಕ್ಕಾಗಿURL ಅತಿಕ್ರಮಣ ಲೆಕ್ಕಾಚಾರ (ಹಂಚಿಕೊಂಡ URLs ಸಂಖ್ಯೆ ಮತ್ತು ಆರಂಭಿಕ ಫಲಿತಾಂಶ).
- ಪ್ರತಿ ಪೂರೈಕೆದಾರರಿಗೆ `POST /v1/search` (ಹುಡುಕಾಟ) ಅಥವಾ `POST /v1/web/fetch` (ಸ್ಕ್ರೇಪ್) ಕರೆಗಳು.

## ಪೂರೈಕೆದಾರರ ಕ್ಯಾಟಲಾಗ್

`ProviderCatalog.tsx` `GET /api/search/providers` ನಿಂದ ಸಂಪೂರ್ಣ ಪೂರೈಕೆದಾರರ ಪಟ್ಟಿಯನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ (ಪಡೆಯುವ ಪೂರೈಕೆದಾರರನ್ನು ಸೇರಿಸಲು F4 ನಲ್ಲಿ ವಿಸ್ತರಿಸಲಾಗಿದೆ):

| `kind` | `"search"` (24 ಪೂರೈಕೆದಾರರು) ಅಥವಾ `"fetch"` (ಫೈರ್ಕ್ರಾಲ್, ಜಿನಾ-ರೀಡರ್, ಟವಿಲಿ-ಸರ್ಚ್, ಟೈನಿಫಿಶ್, ವೇಗವುಳ್ಳ-ಹುಡುಕಾಟ, ಯಾವುದೇ ಹುಡುಕಾಟ-ಹುಡುಕಾಟ, ಸಮಾನಾಂತರ-ಹುಡುಕಾಟ, ಕೀನಬಲ್-ಹುಡುಕಾಟ) |

ಸ್ಥಿತಿಯಾಗಿದೆ** ವಿನಂತಿಯ ಸಮಯದಲ್ಲಿ ಪಡೆಯಲಾಗಿದೆ** ರುಜುವಾತುಗಳು ಅಸ್ತಿತ್ವದಲ್ಲಿವೆಯೇ ಮತ್ತು ಎಲ್ಲಾ ಕೀಗಳು ಪ್ರಸ್ತುತ ಕೂಲ್ಡೌನ್ನಲ್ಲಿವೆಯೇ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸುವ ಮೂಲಕ.

`codex-search` (Codex ವೆಬ್ ಹುಡುಕಾಟ) ತನ್ನದೇ ಆದ ಯಾವುದೇ ಕೀಲಿಯನ್ನು ಹೊಂದಿಲ್ಲ: ಇದು ಸಂಪರ್ಕಿತ Codex (ChatGPT) ಖಾತೆಯನ್ನು ಮರುಬಳಕೆ ಮಾಡುತ್ತದೆ, ಆದ್ದರಿಂದ ಪ್ರತಿ ಹುಡುಕಾಟವು ChatGPT ಚಂದಾದಾರಿಕೆ ಕೋಟಾವನ್ನು ಕಳೆಯುತ್ತದೆ ಮತ್ತು ಸುಮಾರು 10-40 ಸೆಕೆಂಡುಗಳನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ. ವಿನಂತಿಯು ಅದನ್ನು ಹೆಸರಿಸಿದಾಗ ಅದು ಚಲಿಸುತ್ತದೆ; ಸ್ವಯಂಚಾಲಿತ ಆಯ್ಕೆಗೆ `CODEX_SEARCH_AUTO_FALLBACK_ENABLED` ವೈಶಿಷ್ಟ್ಯದ ಫ್ಲ್ಯಾಗ್ ಅಗತ್ಯವಿದೆ (ಡೀಫಾಲ್ಟ್ ಆಗಿ ಆಫ್).

## ಬ್ಯಾಕೆಂಡ್ ಬದಲಾವಣೆಗಳು

ಈ ವೈಶಿಷ್ಟ್ಯಕ್ಕಾಗಿ ಕೇವಲ ಒಂದು ಬ್ಯಾಕೆಂಡ್ ಬದಲಾವಣೆಯ ಅಗತ್ಯವಿದೆ:

### ವಿಸ್ತೃತ `GET /api/search/providers`

`src/app/api/search/providers/route.ts` ಗೆ ವಿಸ್ತರಿಸಲಾಗಿದೆ:

- ಅರೇಯಲ್ಲಿ ಪ್ರತಿ ಪಡೆಯುವ ಪೂರೈಕೆದಾರರನ್ನು (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`, `parallel-search`, `keenable-search`) ಸೇರಿಸಿ.
- ಪ್ರತಿ ಐಟಂಗೆ `kind: "search" | "fetch"` ಸೇರಿಸಿ.
- ಲೈವ್ ರುಜುವಾತು ಸ್ಥಿತಿಯಿಂದ ಪಡೆದ `status: "configured" | "missing" | "rate_limited"` ಸೇರಿಸಿ.
- ಹಿಂದುಳಿದ ಹೊಂದಾಣಿಕೆಯ — ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಕ್ಷೇತ್ರಗಳನ್ನು (`id`, `name`, ಇತ್ಯಾದಿ) ಬದಲಾಗದೆ ನಿರ್ವಹಿಸಿ.
