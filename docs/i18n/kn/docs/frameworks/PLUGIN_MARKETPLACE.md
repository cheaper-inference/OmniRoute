> **ಸತ್ಯದ ಮೂಲ:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, ಮತ್ತು
> `src/app/(dashboard)/dashboard/plugins/`
> **ಕೊನೆಯದಾಗಿ ನವೀಕರಿಸಿದ್ದು:** 2026-06-28 — v3.8.40

OmniRoute, WordPress-ಶೈಲಿಯ ಪ್ಲಗಿನ್ ವ್ಯವಸ್ಥೆಯೊಂದಿಗೆ ಬರುತ್ತದೆ. ಪ್ಲಗಿನ್ಗಳು ಸ್ವಯಂಪೂರ್ಣ
ಡೈರೆಕ್ಟರಿಗಳಾಗಿವೆ — ಪ್ರತಿಯೊಂದೂ `plugin.json` ಮ್ಯಾನಿಫೆಸ್ಟ್ ಮತ್ತು ಪ್ರವೇಶ ಕಡತವನ್ನು ಹೊಂದಿರುತ್ತದೆ — ಇವು
ವಿನಂತಿ ಪೈಪ್ಲೈನ್ಗೆ (`onRequest` / `onResponse` / `onError`) ಮತ್ತು
ಜೀವನಚಕ್ರದ ಈವೆಂಟ್ಗಳಿಗೆ (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
ಹುಕ್ ಆಗುತ್ತವೆ.

**ಪ್ಲಗಿನ್ ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್** ಆ ವ್ಯವಸ್ಥೆಯ ಮೇಲಿರುವ ಅನ್ವೇಷಣಾ ಪದರವಾಗಿದೆ. ಇದು
ಸ್ಥಾಪಿಸಬಹುದಾದ ಪ್ಲಗಿನ್ಗಳ ಬ್ರೌಸ್ ಮಾಡಬಹುದಾದ ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ಒದಗಿಸುತ್ತದೆ. ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಕ್ಯಾಟಲಾಗ್
ಚಿಕ್ಕ ಅಂತರ್ನಿರ್ಮಿತ ಸೀಡ್ ರಿಜಿಸ್ಟ್ರಿಯಾಗಿದೆ; ನಿರ್ವಾಹಕರು ಅದನ್ನು ಕಸ್ಟಮ್ ದೂರಸ್ಥ
ರಿಜಿಸ್ಟ್ರಿ URL ಕಡೆಗೆ ನಿರ್ದೇಶಿಸಬಹುದು. ಅಂತಹ ಸಂದರ್ಭದಲ್ಲಿ ಫೆಚ್ ಅನ್ನು DNS-ಪರಿಹರಿಸುವ SSRF ಗಾರ್ಡ್ ಮೂಲಕ
ಬಲಪಡಿಸಲಾಗುತ್ತದೆ ([ಭದ್ರತೆ](#security) ನೋಡಿ).

ಪ್ರತಿಯೊಂದು ಪ್ಲಗಿನ್ ರೂಟ್ **ಲೂಪ್ಬ್ಯಾಕ್ಗೆ ಮಾತ್ರ ಸೀಮಿತವಾಗಿದೆ** (ಶ್ರೇಣಿ 1 — `LOCAL_ONLY`): ಪ್ಲಗಿನ್ಗಳು
ಚೈಲ್ಡ್ ಪ್ರೊಸೆಸ್ಗಳಲ್ಲಿ ಕೋಡ್ ಅನ್ನು ಲೋಡ್ ಮಾಡಿ ಕಾರ್ಯಗತಗೊಳಿಸುತ್ತವೆ, ಆದ್ದರಿಂದ ದೃಢೀಕರಣವಿದ್ದರೂ
ಲೂಪ್ಬ್ಯಾಕ್ ಅಲ್ಲದ ಮೂಲದಿಂದ ಈ ರೂಟ್ಗಳನ್ನು ತಲುಪಲಾಗುವುದಿಲ್ಲ. ನೋಡಿ:
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md).

## ಇದು Together ಹೇಗೆ ಹೊಂದಿಕೊಳ್ಳುತ್ತದೆ

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **ರಿಜಿಸ್ಟ್ರಿ ಲೇಯರ್** — `src/lib/plugins/marketplace.ts`: ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ / ಹುಡುಕುತ್ತದೆ, ಯಾವುದೇ ವೈಫಲ್ಯದಲ್ಲಿ ಬೀಜ ನೋಂದಣಿಗೆ ಹಿಂತಿರುಗುತ್ತದೆ.
- **ಜೀವನಚಕ್ರ ಪದರ** — `src/lib/plugins/manager.ts` (`pluginManager` singleton): ಸ್ಥಾಪಿಸಿ, ಅಪ್ಗ್ರೇಡ್ ಮಾಡಿ, ಸಕ್ರಿಯಗೊಳಿಸಿ, ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ, ಅನ್ಇನ್ಸ್ಟಾಲ್ ಮಾಡಿ, ಸ್ಕ್ಯಾನ್ ಮಾಡಿ, ಆರಂಭಿಕ ಲೋಡ್ ಮಾಡಿ.
- **ಮ್ಯಾನಿಫೆಸ್ಟ್ ಲೇಯರ್** — `src/lib/plugins/manifest.ts`: `plugin.json` ಗಾಗಿ Zod ಸ್ಕೀಮಾ + ಡಿಫಾಲ್ಟ್ಗಳು.
- **ಸ್ಕ್ಯಾನರ್** — `src/lib/plugins/scanner.ts`: ಪ್ಲಗಿನ್ ಡೈರೆಕ್ಟರಿ ಅಡಿಯಲ್ಲಿ ಡಿಸ್ಕ್ನಲ್ಲಿ ಪ್ಲಗಿನ್ಗಳನ್ನು ಕಂಡುಹಿಡಿಯುತ್ತದೆ.
- **ಲೋಡರ್** — `src/lib/plugins/loader.ts`: ಪ್ರತ್ಯೇಕ Node.js ಚೈಲ್ಡ್ ಪ್ರಕ್ರಿಯೆಯಲ್ಲಿ ಪ್ರತಿ ಪ್ಲಗಿನ್ ಅನ್ನು ಹುಟ್ಟುಹಾಕುತ್ತದೆ ಮತ್ತು ದಲ್ಲಾಳಿಗಳು IPC ಮೂಲಕ ಕರೆಗಳನ್ನು ಹುಕ್ ಮಾಡುತ್ತಾರೆ. ಮಗು ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಅಲ್ಲ (ಕೆಳಗಿನ "ಪ್ಲಗಿನ್ ಎಕ್ಸಿಕ್ಯೂಶನ್ ಐಸೋಲೇಶನ್" ಅನ್ನು ನೋಡಿ).

## ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ಕ್ಯಾಟಲಾಗ್

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`), `MarketplaceEntry`
ಆಬ್ಜೆಕ್ಟ್ಗಳ ಪಟ್ಟಿಯನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ:

| ಕ್ಷೇತ್ರ       | ಪ್ರಕಾರ   | ಟಿಪ್ಪಣಿಗಳು                                   |
| ------------- | -------- | -------------------------------------------- |
| `name`        | string   | kebab-case ಪ್ಲಗಿನ್ ಹೆಸರು                     |
| `version`     | string   | semver                                       |
| `description` | string   | ಸಂಕ್ಷಿಪ್ತ ಸಾರಾಂಶ                             |
| `author`      | string   | ಲೇಖಕರು / ಸಂಸ್ಥೆ                              |
| `license`     | string   | SPDX-ಶೈಲಿಯ ಪರವಾನಗಿ ಐಡಿ                       |
| `downloadUrl` | string   | ಮೂಲ ಡೌನ್ಲೋಡ್ URL (ಖಾಲಿಯಾಗಿರಬಹುದು)            |
| `repository`  | string?  | ಐಚ್ಛಿಕ ರೆಪೊಸಿಟರಿ URL                         |
| `tags`        | string[] | ಹುಡುಕಾಟ/ಫಿಲ್ಟರ್ ಟ್ಯಾಗ್ಗಳು                    |
| `downloads`   | number   | ಡೌನ್ಲೋಡ್ಗಳ ಸಂಖ್ಯೆ                            |
| `rating`      | number   | 0–5                                          |
| `verified`    | boolean  | ನಮೂದನ್ನು ಪರಿಶೀಲಿಸಲಾಗಿದೆ ಎಂದು ಗುರುತಿಸಲಾಗಿದೆಯೇ |
| `lastUpdated` | string   | ISO-ರೀತಿಯ ದಿನಾಂಕ ಸ್ಟ್ರಿಂಗ್                   |

ಯಾವುದೇ ಕಸ್ಟಮ್ ರಿಜಿಸ್ಟ್ರಿ URL ಅನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡದಿದ್ದಾಗ, ಕ್ಯಾಟಲಾಗ್ ಅಂತರ್ನಿರ್ಮಿತ
`SEED_REGISTRY` ಆಗಿರುತ್ತದೆ (ಪ್ರಸ್ತುತ `request-logger`, `rate-limiter`, `cost-tracker`, ಮತ್ತು
`theme-manager`). ಸೀಡ್ ರಿಜಿಸ್ಟ್ರಿ ಯಾವಾಗಲೂ ಲಭ್ಯವಿರುತ್ತದೆ — ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ದೂರಸ್ಥ
ರಿಜಿಸ್ಟ್ರಿಯನ್ನು ತಲುಪಲು ಸಾಧ್ಯವಾಗದಿದ್ದರೆ, ಅದು `200` ಅಲ್ಲದ ಸ್ಥಿತಿಯನ್ನು ಹಿಂದಿರುಗಿಸಿದರೆ ಅಥವಾ ಗುರುತಿಸಲಾಗದ
ಬಾಡಿಯನ್ನು ಹಿಂದಿರುಗಿಸಿದರೆ, `listMarketplacePlugins()` ಎಚ್ಚರಿಕೆಯನ್ನು ಲಾಗ್ ಮಾಡಿ ಸೀಡ್ ಪಟ್ಟಿಗೆ ಹಿಂತಿರುಗುತ್ತದೆ.

> ಗಮನಿಸಿ: ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ **ಕ್ಯಾಟಲಾಗ್** (ಬ್ರೌಸ್/ಹುಡುಕಾಟ) ಆರಂಭದಿಂದ ಅಂತ್ಯದವರೆಗೆ ಸಂಪರ್ಕಿಸಲಾಗಿದೆ, ಆದರೆ
> ಕ್ಯಾಟಲಾಗ್ನಿಂದ ಒಂದು ಕ್ಲಿಕ್ನ ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ **ಸ್ಥಾಪನೆ** ಇನ್ನೂ ಅನುಷ್ಠಾನಗೊಂಡಿಲ್ಲ — ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ನಮೂದಿನ
> ಮೇಲಿರುವ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ "ಸ್ಥಾಪಿಸು" ಬಟನ್ ಪ್ರಸ್ತುತ "ಶೀಘ್ರದಲ್ಲೇ ಬರಲಿದೆ" ಎಂಬ ಸೂಚನೆಯನ್ನು
> ತೋರಿಸುತ್ತದೆ. ಪ್ರಸ್ತುತ ಸ್ಥಾಪನೆಯು ಸ್ಥಳೀಯ-ಪಥದ ಸ್ಥಾಪನಾ ಹರಿವು (`POST /api/plugins`) ಮತ್ತು
> ಡಿಸ್ಕ್ನಲ್ಲಿನ ಅನ್ವೇಷಣೆ (`POST /api/plugins/scan`) ಮೂಲಕ ನಡೆಯುತ್ತದೆ.

## REST API

ಎಲ್ಲಾ ಅಂತಿಮ ಬಿಂದುಗಳಿಗೆ ನಿರ್ವಹಣಾ ದೃಢೀಕರಣದ ಅಗತ್ಯವಿದೆ (`requireManagementAuth`)** ಮತ್ತು** ಲೂಪ್ಬ್ಯಾಕ್-ಮಾತ್ರ — `/api/plugins` ಮತ್ತು `/api/plugins/` `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) ನಲ್ಲಿ ಪಟ್ಟಿ ಮಾಡಲಾಗಿದೆ.

| ಅಂತ್ಯಬಿಂದು                       | ವಿಧಾನ  | ವಿವರಣೆ                                                                 |
| -------------------------------- | ------ | ---------------------------------------------------------------------- |
| `/api/plugins`                   | GET    | ಸ್ಥಾಪಿಸಲಾದ ಪ್ಲಗಿನ್ಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ (ಐಚ್ಛಿಕ `?status=` ಫಿಲ್ಟರ್)        |
| `/api/plugins`                   | POST   | ಪ್ಲಗಿನ್ ಮೂಲಗಳ ಡೈರೆಕ್ಟರಿಯಿಂದ ಪ್ಲಗಿನ್ ಅನ್ನು ಸ್ಥಾಪಿಸಿ                     |
| `/api/plugins/scan`              | POST   | ಪ್ಲಗಿನ್ ಡೈರೆಕ್ಟರಿಯನ್ನು ಸ್ಕ್ಯಾನ್ ಮಾಡಿ ಮತ್ತು ಹೊಸ ಪ್ಲಗಿನ್ಗಳನ್ನು ನೋಂದಾಯಿಸಿ |
| `/api/plugins/marketplace`       | GET    | ಮಾರುಕಟ್ಟೆಯ ಕ್ಯಾಟಲಾಗ್ ನಮೂದುಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ                            |
| `/api/plugins/[name]`            | GET    | ಸ್ಥಾಪಿಸಲಾದ ಪ್ಲಗಿನ್ ವಿವರಗಳನ್ನು ಪಡೆಯಿರಿ                                  |
| `/api/plugins/[name]`            | DELETE | ಪ್ಲಗಿನ್ ಅನ್ನು ಅಸ್ಥಾಪಿಸಿ                                                |
| `/api/plugins/[name]/activate`   | POST   | ಸಕ್ರಿಯಗೊಳಿಸಿ ( + ರಿಜಿಸ್ಟರ್ ಕೊಕ್ಕೆಗಳನ್ನು ಲೋಡ್ ಮಾಡಿ)                     |
| `/api/plugins/[name]/deactivate` | POST   | ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ (ಫೈರ್ `onDeactivate`, ಕೊಕ್ಕೆಗಳನ್ನು ನೋಂದಾಯಿಸಬೇಡಿ)       |
| `/api/plugins/[name]/config`     | GET    | ಪ್ಲಗಿನ್ ಕಾನ್ಫಿಗರ್ + ಕಾನ್ಫಿಗರ್ ಸ್ಕೀಮಾವನ್ನು ಪಡೆಯಿರಿ                      |
| `/api/plugins/[name]/config`     | PUT    | ಪ್ಲಗಿನ್ ಸಂರಚನೆಯನ್ನು ನವೀಕರಿಸಿ (ಸ್ಕೀಮಾ ವಿರುದ್ಧ ಮೌಲ್ಯೀಕರಿಸಲಾಗಿದೆ)         |

`GET /api/plugins` `status` ಫಿಲ್ಟರ್ `installed` / `active` / `inactive` / `error` ಗಳಲ್ಲಿ ಒಂದನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ. ಅಮಾನ್ಯ ಮೌಲ್ಯವು `400` ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

### ಸ್ಥಾಪಿಸಲಾದ ಪ್ಲಗಿನ್ಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### ಸ್ಥಳೀಯ ಮಾರ್ಗದಿಂದ ಸ್ಥಾಪಿಸಿ

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` ಒಂದು ಇರಬೇಕು** ಸಂಪೂರ್ಣ** ಡೈರೆಕ್ಟರಿಗೆ ಮಾರ್ಗ** ಪ್ಲಗಿನ್ ಮೂಲಗಳ ಡೈರೆಕ್ಟರಿ ಒಳಗೆ** : ಪ್ಲಗಿನ್ ರೂಟ್ನ ಪಕ್ಕದಲ್ಲಿ `plugin-sources`, ಆದ್ದರಿಂದ ಡಿಫಾಲ್ಟ್ ಆಗಿ `~/.omniroute/plugin-sources/`, ಅಥವಾ ಆ ವೇರಿಯೇಬಲ್ ಅನ್ನು ಹೊಂದಿಸಿದಾಗ `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` (`getPluginSourcesDir()` ನಲ್ಲಿ `src/lib/plugins/installSource.ts`). ಅಲ್ಲಿ ಪ್ಲಗಿನ್ ಅನ್ನು ಮೊದಲು ನಕಲಿಸಿ ಅಥವಾ ಕ್ಲೋನ್ ಮಾಡಿ. ಮಾರ್ಗವು `..` ಅಥವಾ ಶೂನ್ಯ ಬೈಟ್ ಅನ್ನು ಹೊಂದಿರುವಾಗ, ಆ ಡೈರೆಕ್ಟರಿಯ ಹೊರಗೆ ಇರುವಾಗ, ಸಿಮ್ಲಿಂಕ್ ಮೂಲಕ ಅದರ ಹೊರಗೆ ಪರಿಹರಿಸಿದಾಗ, ಅದರ ಹೊರಗಿರುವ ಗುರಿಯ ಸಿಮ್ಲಿಂಕ್ ಅನ್ನು ಹೊಂದಿರುವಾಗ ಅಥವಾ ಡೈರೆಕ್ಟರಿ ಅಸ್ತಿತ್ವದಲ್ಲಿಲ್ಲದಿದ್ದಾಗ ಅನುಸ್ಥಾಪನೆಯನ್ನು `400` ನೊಂದಿಗೆ ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ. ಮೂಲ ಡೈರೆಕ್ಟರಿಯು ಮಾನ್ಯವಾದ `plugin.json` ಅನ್ನು ಹೊಂದಿರಬೇಕು (ಅಥವಾ ಒಬ್ಬರ ಪೋಷಕರಾಗಿರಬೇಕು). ಯಶಸ್ಸಿನ ನಂತರ ಪ್ರತಿಕ್ರಿಯೆಯು ಸ್ಥಾಪಿಸಲಾದ ಪ್ಲಗಿನ್ ಸಾಲಿನೊಂದಿಗೆ `201` ಆಗಿದೆ.

ಇತರ ಪ್ಲಗಿನ್ ಮಾರ್ಗಗಳಿಗಿಂತ ಭಿನ್ನವಾಗಿ, ಲಾಗಿನ್ ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿದಾಗಲೂ (`requireLogin=false`) ನಿರ್ವಹಣೆಯ ರುಜುವಾತು (ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಸೆಷನ್ ಅಥವಾ ಮ್ಯಾನೇಜ್-ಸ್ಕೋಪ್ಡ್ API ಕೀ) ಅಗತ್ಯವಿರುತ್ತದೆ: ಕೋಡ್ ಅನ್ನು ಸ್ಥಾಪಿಸುವುದು ಎಂದಿಗೂ ಅನಾಮಧೇಯ ಕ್ರಿಯೆಯಲ್ಲ.

### ಮಾರುಕಟ್ಟೆಯನ್ನು ಬ್ರೌಸ್ ಮಾಡಿ

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### ಪ್ಲಗಿನ್ ಸಂರಚನೆಯನ್ನು ನವೀಕರಿಸಿ

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` ಪ್ರತಿ ಒದಗಿಸಿದ ಮೌಲ್ಯವನ್ನು ಪ್ಲಗಿನ್ನ `configSchema` (ಮ್ಯಾನಿಫೆಸ್ಟ್ನಲ್ಲಿ ಘೋಷಿಸಲಾಗಿದೆ) ವಿರುದ್ಧ ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ: `number` ಕ್ಷೇತ್ರಗಳು ಗೌರವ `min`/`max`, `select` ಕ್ಷೇತ್ರಗಳು ಡಿಕ್ಲೇರ್ಡ್ `enum` ಗೆ ಹೊಂದಿಕೆಯಾಗಬೇಕು. ಸ್ಕೀಮಾದಲ್ಲಿ ಇಲ್ಲದಿರುವ ಕೀಗಳನ್ನು ಅನುಮತಿಸಲಾಗಿದೆ.

## ಕಾನ್ಫಿಗರೇಶನ್

### ಪ್ಲಗಿನ್ ಡೈರೆಕ್ಟರಿ

ಪ್ಲಗಿನ್ಗಳು OmniRoute ಡೇಟಾ ಡೈರೆಕ್ಟರಿಯ ಅಡಿಯಲ್ಲಿ ಇರುತ್ತವೆ:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (ಅಥವಾ manifest.main ಯಾವುದನ್ನು ಸೂಚಿಸುತ್ತದೆಯೋ ಅದು)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ಆ ಡೈರೆಕ್ಟರಿಯನ್ನು
ಮೂರು ಹಂತಗಳಲ್ಲಿ ನಿರ್ಧರಿಸುತ್ತದೆ:

1. **`OMNIROUTE_PLUGINS_DIR`**, ಹೊಂದಿಸಿದಾಗ — `HOME` ಏನು ಹೇಳುತ್ತದೆ ಎಂಬುದನ್ನು ಲೆಕ್ಕಿಸದೆ, ಯಥಾವತ್ತಾಗಿ ಬಳಸಲಾಗುತ್ತದೆ. ಇದು
   Docker/K8s ಗಾಗಿ ಇರುವ ಸ್ಪಷ್ಟ ನಿಯಂತ್ರಣವಾಗಿದೆ; ಅಲ್ಲಿ ಪ್ಲಗಿನ್ ಟ್ರೀಯನ್ನು ಸಾಮಾನ್ಯವಾಗಿ ಕಂಟೇನರ್ನ ಹೋಮ್ ಡೈರೆಕ್ಟರಿಯೊಂದಿಗೆ
   ಯಾವುದೇ ಸಂಬಂಧವಿಲ್ಲದ ಪಥದಲ್ಲಿ ಬೈಂಡ್-ಮೌಂಟ್ ಮಾಡಲಾಗುತ್ತದೆ (#11827).
2. `<home>/.omniroute/plugins`, ಇಲ್ಲಿ `<home>` ಅನ್ನು `HOME` / `USERPROFILE`
   ಪರಿಸರ ವೇರಿಯಬಲ್ಗಳಿಂದ ಪಡೆಯಲಾಗುತ್ತದೆ.
3. `/tmp/.omniroute/plugins`, ಪ್ರಕ್ರಿಯೆಯು ಯಾವುದೇ ಹೋಮ್ ಅನ್ನು ಎಕ್ಸ್ಪೋರ್ಟ್ ಮಾಡದಿದ್ದಾಗ.

ನಿರ್ಧರಿಸಲಾದ ಡೈರೆಕ್ಟರಿಯನ್ನು ಸ್ಟಾರ್ಟ್ಅಪ್ ವೇಳೆ `scanner.dir_resolved` ಎಂದು ಒಮ್ಮೆ ಲಾಗ್ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು
ಆಯ್ಕೆಯಾದ ಇನ್ಪುಟ್ನ ಹೆಸರನ್ನು (`OMNIROUTE_PLUGINS_DIR`, `home`, ಅಥವಾ `no-home-fallback`) ನಮೂದಿಸಲಾಗುತ್ತದೆ — ಹೀಗಾಗಿ ಯಾವುದಾದರೂ ಇಮೇಜ್
ಮೌನವಾಗಿ ಹಂತ 3ಕ್ಕೆ ತಲುಪಿದರೆ, ಕೇವಲ ಖಾಲಿ ಪ್ಲಗಿನ್ ಪಟ್ಟಿಯನ್ನು ವರದಿ ಮಾಡುವ ಬದಲು ಅದನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ತಿಳಿಸುತ್ತದೆ.
`POST /api/plugins/scan` ಅಲ್ಲಿ ಮಾನ್ಯವಾದ
`plugin.json` ಹೊಂದಿರುವ ಯಾವುದೇ ಉಪಡೈರೆಕ್ಟರಿಯನ್ನು ಪತ್ತೆಹಚ್ಚಿ ನೋಂದಾಯಿಸುತ್ತದೆ; ಅದೇ ಡೈರೆಕ್ಟರಿಯು
`pluginManager.install()` ಪ್ಲಗಿನ್ಗಳನ್ನು ನಕಲಿಸುವ ರೂಟ್ ಕೂಡ ಆಗಿರುವುದರಿಂದ, ಓವರ್ರೈಡ್ ಡಿಸ್ಕವರಿ ಮತ್ತು
ಸ್ಥಾಪನೆ ಎರಡನ್ನೂ ಒಟ್ಟಿಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ.

> **`OMNIROUTE_PLUGINS_DIR`, `OMNIROUTE_PLUGIN_PATH` ಅಲ್ಲ.** ಎರಡನೆಯದನ್ನು
> CLI ಕಮಾಂಡ್-ಪ್ಲಗಿನ್ ಲೋಡರ್ (`bin/cli/plugins.mjs`) ಮಾತ್ರ `omniroute` ಉಪಕಮಾಂಡ್ಗಳನ್ನು ಸೇರಿಸುವ `omniroute-cmd-*` npm
> ಪ್ಯಾಕೇಜ್ಗಳನ್ನು ಹುಡುಕಲು ಓದುತ್ತದೆ — ಇಲ್ಲಿ ವಿವರಿಸಲಾದ ರನ್ಟೈಮ್ ಸ್ಕ್ಯಾನರ್ ಮೇಲೆ ಅದು ಯಾವುದೇ ಪರಿಣಾಮ ಬೀರುವುದಿಲ್ಲ.
> ಆ ಭಾಗಕ್ಕಾಗಿ [PLUGINS.md](./PLUGINS.md) ನೋಡಿ.

### ಕಸ್ಟಮ್ ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ರಿಜಿಸ್ಟ್ರಿ URL

ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ಕ್ಯಾಟಲಾಗ್ ಮೂಲವನ್ನು `pluginMarketplaceUrl` ಸೆಟ್ಟಿಂಗ್ನಿಂದ
ಓದಲಾಗುತ್ತದೆ (`src/lib/plugins/marketplace.ts` ನಲ್ಲಿ `settings.pluginMarketplaceUrl` ಅನ್ನು ಓದಲಾಗುತ್ತದೆ).
ಇದನ್ನು `http(s)` URL ಗೆ ಹೊಂದಿಸಿದಾಗ, `listMarketplacePlugins()` ಆ URL ಅನ್ನು ಫೆಚ್ ಮಾಡುತ್ತದೆ ಮತ್ತು
ಎಂಟ್ರಿಗಳ ಟಾಪ್-ಲೆವೆಲ್ JSON ಅರೇ ಅಥವಾ `plugins` ಅರೇ ಹೊಂದಿರುವ ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು
ಸ್ವೀಕರಿಸುತ್ತದೆ; ಸ್ಟ್ರಿಂಗ್ `name` ಇಲ್ಲದ ಎಂಟ್ರಿಗಳನ್ನು ಫಿಲ್ಟರ್ ಮಾಡಲಾಗುತ್ತದೆ. ಇದನ್ನು ಹೊಂದಿಸದಿದ್ದಾಗ (ಅಥವಾ ಫೆಚ್
SSRF ಗಾರ್ಡ್ನಲ್ಲಿ ವಿಫಲವಾದಾಗ / ಕೆಟ್ಟ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಹಿಂತಿರುಗಿಸಿದಾಗ), ಅಂತರ್ನಿರ್ಮಿತ ಸೀಡ್ ರಿಜಿಸ್ಟ್ರಿಯನ್ನು
ಬಳಸಲಾಗುತ್ತದೆ.

ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ "Marketplace" ಟ್ಯಾಬ್ ಈ URL ಗಾಗಿ ಒಂದು ಫೀಲ್ಡ್ ಅನ್ನು ಒದಗಿಸುತ್ತದೆ (`GET /api/settings` ನಿಂದ
ಮತ್ತೆ ಓದಲಾಗುತ್ತದೆ).

> ಅನುಷ್ಠಾನ ಟಿಪ್ಪಣಿ: ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ "Save" ಕ್ರಿಯೆಯು
> `pluginMarketplaceUrl` ಅನ್ನು `PATCH /api/settings` ಗೆ ಕಳುಹಿಸುತ್ತದೆ. ಇದನ್ನು ಬರೆಯುವ ಸಮಯದಲ್ಲಿ ಈ
> ಕೀಯನ್ನು `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) ನಲ್ಲಿ ಘೋಷಿಸಲಾಗಿಲ್ಲ, ಆದ್ದರಿಂದ ಇದನ್ನು ಅವಲಂಬಿಸುವ ಮೊದಲು ನಿಮ್ಮ
> ಬಿಡುಗಡೆಯಲ್ಲಿ ಪರ್ಸಿಸ್ಟೆನ್ಸ್ ಅನ್ನು ಪರಿಶೀಲಿಸಿ — ಸೆಟ್ಟಿಂಗ್ಸ್
> ಸ್ಟೋರ್ನಲ್ಲಿ ಕೀ ಒಮ್ಮೆ ಅಸ್ತಿತ್ವದಲ್ಲಿದ್ದರೆ **ರೀಡ್** ಪಥವು (`getSettings()` →
> `listMarketplacePlugins()`) ಅದನ್ನು ಗೌರವಿಸುತ್ತದೆ.

## ಭದ್ರತೆ

### ಮಾರ್ಗ ಶ್ರೇಣಿ — ಲೂಪ್ಬ್ಯಾಕ್ ಮಾತ್ರ

ಪ್ಲಗಿನ್ಗಳು ಮೊಟ್ಟೆಯಿಟ್ಟ ಮಕ್ಕಳ ಪ್ರಕ್ರಿಯೆಗಳಲ್ಲಿ ಕೋಡ್ ಅನ್ನು ಕಾರ್ಯಗತಗೊಳಿಸುತ್ತವೆ, ಆದ್ದರಿಂದ ಸಂಪೂರ್ಣ `/api/plugins` ಮೇಲ್ಮೈಯನ್ನು `LOCAL_ONLY` (ಶ್ರೇಣಿ 1) ವರ್ಗೀಕರಿಸಲಾಗಿದೆ. ಲೂಪ್ಬ್ಯಾಕ್ ಜಾರಿ ಬೇಷರತ್ತಾಗಿ ಸಾಗುತ್ತದೆ** ಮೊದಲು** ಯಾವುದೇ ದೃಢೀಕರಣ ಪರಿಶೀಲನೆ, ಆದ್ದರಿಂದ ಸೋರಿಕೆಯಾದ ನಿರ್ವಹಣಾ ಟೋಕನ್ ಸುರಂಗದ ಮೂಲಕ ಬಾಕ್ಸ್ ಅನ್ನು ತಲುಪಲು ಇನ್ನೂ ಪ್ಲಗಿನ್ ಅನ್ನು ಸ್ಥಾಪಿಸಲು, ಸಕ್ರಿಯಗೊಳಿಸಲು ಅಥವಾ ಅನ್ಇನ್ಸ್ಟಾಲ್ ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ. [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) ಮತ್ತು ಹಾರ್ಡ್ ರೂಲ್ಸ್ #15 / #17 ನೋಡಿ.

### ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ರಿಜಿಸ್ಟ್ರಿ SSRF ಗಾರ್ಡ್

ಕಸ್ಟಮ್ ರಿಜಿಸ್ಟ್ರಿ URL ಆಕ್ರಮಣಕಾರರ-ಪ್ರಭಾವದ ಕಾನ್ಫಿಗರೇಶನ್ ಆಗಿದೆ, ಆದ್ದರಿಂದ ಅದನ್ನು ಪಡೆಯುವ ಮೊದಲು `listMarketplacePlugins()` ಅದನ್ನು ಎರಡು ಪದರಗಳ ಮೂಲಕ ನಡೆಸುತ್ತದೆ:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` ಅಲ್ಲದ ಯಾವುದನ್ನಾದರೂ ತಿರಸ್ಕರಿಸುತ್ತದೆ.
   - ಅಕ್ಷರಶಃ private/loopback/link-local/ULA ಹೋಸ್ಟ್ಗಳನ್ನು ತಿರಸ್ಕರಿಸುತ್ತದೆ (IPv4** ಮತ್ತು** IPv6, IPv4-mapped ಸೇರಿದಂತೆ) ಅಂಗೀಕೃತ `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) ಮೂಲಕ.
   - ಪರಿಹರಿಸುತ್ತದೆ** ಎರಡೂ** `A` ಮತ್ತು `AAAA` ದಾಖಲೆಗಳು ಮತ್ತು ವೇಳೆ ತಿರಸ್ಕರಿಸುತ್ತದೆ** ಯಾವುದೇ** ಪರಿಹರಿಸಲಾದ ವಿಳಾಸವು ಖಾಸಗಿ — ಆಗಿದೆ ಸಾರ್ವಜನಿಕ-ಹೋಸ್ಟ್ಹೆಸರು → ಖಾಸಗಿ-IP ಬೈಪಾಸ್ ಅನ್ನು ಮುಚ್ಚುತ್ತದೆ.
   - **ವಿಫಲವಾಗಿದೆ ಮುಚ್ಚಲಾಗಿದೆ** : DNS ರೆಸಲ್ಯೂಶನ್ ವೈಫಲ್ಯವು URL ಅನ್ನು ತಿರಸ್ಕರಿಸುತ್ತದೆ.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): ಪಡೆಯುವ ಸಮಯದಲ್ಲಿ ಸಾರ್ವಜನಿಕ-ಮಾತ್ರ URL ಗಾರ್ಡ್ ಅನ್ನು ಮರು-ಅನ್ವಯಿಸುತ್ತದೆ ಮತ್ತು** ಮರುನಿರ್ದೇಶನಗಳನ್ನು ನಿರ್ಬಂಧಿಸುತ್ತದೆ** (ಸಾರ್ವಜನಿಕ → ಖಾಸಗಿ `30x` ಪಿವೋಟ್ ಇಲ್ಲ).

ಎರಡೂ ಪದರಗಳಲ್ಲಿ ವಿಫಲವಾದ URL ವಿನಂತಿಯನ್ನು ಸ್ಥಗಿತಗೊಳಿಸುವುದಿಲ್ಲ — ಮಾರುಕಟ್ಟೆ ಸ್ಥಳವು ಮೌನವಾಗಿ ಅಂತರ್ನಿರ್ಮಿತ ಬೀಜ ನೋಂದಣಿಗೆ ಹಿಂತಿರುಗುತ್ತದೆ ಮತ್ತು ಎಚ್ಚರಿಕೆಯನ್ನು ಲಾಗ್ ಮಾಡುತ್ತದೆ.

> ಈ ಸಿಬ್ಬಂದಿಯನ್ನು PR #3774 ನಲ್ಲಿ ನಿರ್ದಿಷ್ಟವಾಗಿ A + AAAA ಪರಿಹರಿಸಲು ಮತ್ತು IPv4-only ಚೆಕ್ ಬದಲಿಗೆ ಅಂಗೀಕೃತ `isPrivateHost` ಬಳಸಲು ಗಟ್ಟಿಗೊಳಿಸಲಾಗಿದೆ.

### ಪ್ಲಗಿನ್ ಎಕ್ಸಿಕ್ಯೂಶನ್ ಪ್ರತ್ಯೇಕತೆ

> **ಪ್ಲಗಿನ್ಗಳನ್ನು ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಮಾಡಲಾಗಿಲ್ಲ.** ಮಗುವು OmniRoute ಬಳಕೆದಾರರಂತೆ ಚಾಲನೆಯಲ್ಲಿರುವ ಸಾಮಾನ್ಯ Node.js ಪ್ರಕ್ರಿಯೆಯಾಗಿದೆ, ಯಾವುದೇ VM ಸಂದರ್ಭ ಮತ್ತು ಯಾವುದೇ Node.js ಅನುಮತಿ ಫ್ಲ್ಯಾಗ್ಗಳಿಲ್ಲ, ಆದ್ದರಿಂದ ಪ್ಲಗಿನ್ ಕೋಡ್ ಬಳಕೆದಾರರು ಮಾಡಬಹುದಾದ ಯಾವುದೇ ಫೈಲ್ ಅನ್ನು ಓದಬಹುದು ಮತ್ತು ಬರೆಯಬಹುದು, ಪ್ರೋಗ್ರಾಂಗಳನ್ನು ರನ್ ಮಾಡಬಹುದು ಮತ್ತು ನೆಟ್ವರ್ಕ್ ಅನ್ನು ತಲುಪಬಹುದು. ಮಗು ಯಾವ ಪರಿಸರದ ಅಸ್ಥಿರಗಳನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ ಎಂಬುದನ್ನು ಮಾತ್ರ `requires.permissions` ನಿರ್ಧರಿಸುತ್ತದೆ; ಇತರ ಅನುಮತಿಗಳನ್ನು ಜಾರಿಗೊಳಿಸಲಾಗಿಲ್ಲ. ನೀವು ನಂಬುವ ಪ್ಲಗಿನ್ಗಳನ್ನು ಮಾತ್ರ ಸ್ಥಾಪಿಸಿ. ಕೆಳಗಿನ ಪ್ರಕ್ರಿಯೆಯ ಗಡಿಯು ಕ್ರ್ಯಾಶ್ಗಳು ಮತ್ತು ಹ್ಯಾಂಗ್ಗಳನ್ನು ಒಳಗೊಂಡಿದೆ; ಇದು ಭದ್ರತಾ ಗಡಿ ಅಲ್ಲ.

- **ಪ್ರಕ್ರಿಯೆ ಪ್ರತ್ಯೇಕತೆ** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ಪ್ರತಿ ಪ್ಲಗಿನ್ ಅನ್ನು ಪ್ರತ್ಯೇಕ Node.js ಚೈಲ್ಡ್ ಪ್ರಕ್ರಿಯೆಯಲ್ಲಿ ಹುಟ್ಟುಹಾಕುತ್ತದೆ ಮತ್ತು IPC ಮೂಲಕ ಸಂವಹನ ನಡೆಸುತ್ತದೆ. ಹುಕ್ ಕರೆಗಳು `SIGTERM` → `SIGKILL` ಹೆಚ್ಚಳದೊಂದಿಗೆ ಸಮಯ ಮೀರಿದೆ.
- **ಎನ್ವಿ ಅನುಮತಿ ಪಟ್ಟಿ** — ಮಗುವು ಅನುಮತಿಸಲಾದ ಪರಿಸರ ವೇರಿಯಬಲ್ಗಳ ಗುಂಪನ್ನು ಮಾತ್ರ ಪಡೆಯುತ್ತದೆ; ಮ್ಯಾನಿಫೆಸ್ಟ್ `env` ಅನುಮತಿಯನ್ನು ಕೋರಿದಾಗ ಮಾತ್ರ ವಿಶಾಲವಾದ ಸೆಟ್ ಅನ್ನು ನೀಡಲಾಗುತ್ತದೆ.
- **ಮೂಲ ಧಾರಕವನ್ನು ಸ್ಥಾಪಿಸಿ** — `POST /api/plugins` ಪ್ಲಗಿನ್ ಮೂಲಗಳ ಡೈರೆಕ್ಟರಿಯಿಂದ ಮಾತ್ರ ಓದುತ್ತದೆ ("ಸ್ಥಳೀಯ ಮಾರ್ಗದಿಂದ ಸ್ಥಾಪಿಸಿ" ನೋಡಿ): ಮಾರ್ಗವು `realpath` ನೊಂದಿಗೆ ಅಂಗೀಕೃತವಾಗಿದೆ, ಆ ಡೈರೆಕ್ಟರಿಯೊಳಗೆ ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಇರಬೇಕು ಮತ್ತು ಯಾವುದನ್ನಾದರೂ ನಕಲಿಸುವ ಮೊದಲು ಅದನ್ನು ತಪ್ಪಿಸುವ ಸಿಮ್ಲಿಂಕ್ ಅನ್ನು ಹೊಂದಿರುವ ಮೂಲ ಮರವನ್ನು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ.
- **ಮಾರ್ಗ ನಿಯಂತ್ರಣ** — install/upgrade/uninstall ಪ್ಲಗಿನ್ ಡೈರೆಕ್ಟರಿ ಮತ್ತು `manifest.main` ಪರಿಹರಿಸುತ್ತದೆ ಎಂದು ಪ್ರತಿಪಾದಿಸುತ್ತದೆ** ಒಳಗೆ** ಯಾವುದೇ ನಕಲು ಅಥವಾ ಪುನರಾವರ್ತಿತ ಅಳಿಸುವಿಕೆಯ ಮೊದಲು ನಿರ್ವಹಿಸಲಾದ ಪ್ಲಗಿನ್ ರೂಟ್ (ಟ್ಯಾಂಪರ್ಡ್ DB ಮಾರ್ಗಗಳ ವಿರುದ್ಧ ಕಾವಲುಗಾರರು ಮತ್ತು `manifest.main` ನಲ್ಲಿ `../` ಟ್ರಾವರ್ಸಲ್). ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆಯು `realpath` ಮೂಲಕ ಸಿಮ್ಲಿಂಕ್ಗಳನ್ನು ಪರಿಹರಿಸುತ್ತದೆ ಮತ್ತು ಪ್ಲಗಿನ್ ಡೈರೆಕ್ಟರಿಯಿಂದ ತಪ್ಪಿಸಿಕೊಳ್ಳುವ ಪ್ರವೇಶ ಬಿಂದುವನ್ನು ಲೋಡ್ ಮಾಡಲು ನಿರಾಕರಿಸುತ್ತದೆ.
- **ಐಚ್ಛಿಕ ಸಮಗ್ರತೆಯ ಪಿನ್** — a ಮ್ಯಾನಿಫೆಸ್ಟ್ `integrity` (`sha256-<base64>`, SRI ಫಾರ್ಮ್ಯಾಟ್) ಕ್ಷೇತ್ರವನ್ನು ಘೋಷಿಸಬಹುದು. ಇರುವಾಗ, ಲೋಡರ್ ಪ್ರವೇಶ ಫೈಲ್ ಹ್ಯಾಶ್ ಅನ್ನು ಲೋಡ್ ಸಮಯದಲ್ಲಿ ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು ಹೊಂದಿಕೆಯಾಗದಿರುವಾಗ ಸಕ್ರಿಯಗೊಳಿಸಲು ನಿರಾಕರಿಸುತ್ತದೆ. ಇದು ಆಪ್ಟ್-ಇನ್ ಟ್ಯಾಂಪರ್-ಡಿಟೆಕ್ಷನ್ ಆಗಿದೆ,** ಅಲ್ಲ** ಭದ್ರತಾ ಗಡಿ: ಲೋಡ್ ಮಾಡಲಾದ ಪ್ಲಗಿನ್ ಏನು ಮಾಡಬಹುದು ಎಂಬುದನ್ನು ಇದು ಮಿತಿಗೊಳಿಸುವುದಿಲ್ಲ.
- **ಕೊಕ್ಕೆಗಳಲ್ಲಿ ಯಾವುದೇ ಕ್ಲೈಂಟ್ ರುಜುವಾತುಗಳಿಲ್ಲ** — `onRequest`, `onResponse` ಮತ್ತು `onError` ಗೆ ರವಾನಿಸಲಾದ ಸಂದರ್ಭವು `authorization`, `x-api-key`, `proxy-authorization` ಮತ್ತು `cookie` ಹೆಡರ್ಗಳನ್ನು ತೆಗೆದುಹಾಕಿದೆ ಮತ್ತು API ಕೀ ದಾಖಲೆಯು ಯಾವುದೇ ಪ್ರಮುಖ ಮೌಲ್ಯವನ್ನು ಹೊಂದಿರುವುದಿಲ್ಲ ( `src/lib/plugins/hooks.ts` ನಲ್ಲಿ`redactPluginContext()` ).

## ಜೀವನಚಕ್ರದ ಹರಿವು

```
ಸ್ಥಾಪನೆ (POST /api/plugins, ಪಥ)
  → ಮ್ಯಾನಿಫೆಸ್ಟ್ ಸ್ಕ್ಯಾನ್/ಮೌಲ್ಯೀಕರಣ → ಸ್ಟೇಜಿಂಗ್ಗೆ ನಕಲಿಸಿ → main ಡೈರೆಕ್ಟರಿಯೊಳಗಿದೆ ಎಂದು ಖಚಿತಪಡಿಸಿ
  → ~/.omniroute/plugins/<name> ಗೆ ಅಟಾಮಿಕ್ ಮರುಹೆಸರಿಕೆ → DB ಸಾಲನ್ನು ಸೇರಿಸಿ
  → onInstall ಅನ್ನು ಪ್ರಚೋದಿಸಿ → enabledByDefault ಆಗಿದ್ದರೆ: ಸಕ್ರಿಯಗೊಳಿಸಿ

ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ (POST /api/plugins/{name}/activate)
  → realpath ಒಳಗೊಳ್ಳುವಿಕೆ ಪರಿಶೀಲನೆ → loadPlugin() (ಚೈಲ್ಡ್ ಪ್ರೊಸೆಸ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ)
  → ಘೋಷಿತ ಹುಕ್ಗಳನ್ನು ನೋಂದಾಯಿಸಿ → ಸ್ಥಿತಿ = "active" → onActivate ಅನ್ನು ಪ್ರಚೋದಿಸಿ

ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವಿಕೆ (POST /api/plugins/{name}/deactivate)
  → onDeactivate ಅನ್ನು ಪ್ರಚೋದಿಸಿ (ನೋಂದಣಿ ರದ್ದುಗೊಳಿಸುವುದಕ್ಕೆ ಮೊದಲು) → ಹುಕ್ಗಳ ನೋಂದಣಿ ರದ್ದುಗೊಳಿಸಿ
  → ಚೈಲ್ಡ್ ಪ್ರೊಸೆಸ್ ಅನ್ನು ಸ್ಥಗಿತಗೊಳಿಸಿ → ಸ್ಥಿತಿ = "inactive"

ಅಸ್ಥಾಪನೆ (DELETE /api/plugins/{name})
  → ಸಕ್ರಿಯವಾಗಿದ್ದರೆ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ → onUninstall ಅನ್ನು ಪ್ರಚೋದಿಸಿ
  → ಒಳಗೊಳ್ಳುವಿಕೆ ಪರಿಶೀಲಿಸಿದ plugin ಡೈರೆಕ್ಟರಿಯನ್ನು ಪುನರಾವರ್ತಿತವಾಗಿ ಅಳಿಸಿ → DB ಸಾಲನ್ನು ಅಳಿಸಿ
```

ಸ್ಥಾಪಿತ ಆವೃತ್ತಿಗಿಂತ ಮ್ಯಾನಿಫೆಸ್ಟ್ ಆವೃತ್ತಿಯು **ಕಟ್ಟುನಿಟ್ಟಾಗಿ
ಹೊಸದಾಗಿರುವ** ಡೈರೆಕ್ಟರಿಯ ವಿರುದ್ಧ `install` ಅನ್ನು ಮರು-ಚಲಾಯಿಸುವುದು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಅಪ್ಗ್ರೇಡ್ ಮಾಡುತ್ತದೆ (ಸ್ವಚ್ಛ ಮರುಸ್ಥಾಪನೆ; ಕಾನ್ಫಿಗ್
ಡೀಫಾಲ್ಟ್ಗಳಿಗೆ ಮರುಹೊಂದಿಸಲಾಗುತ್ತದೆ). ಅದೇ ಅಥವಾ ಹಳೆಯ ಆವೃತ್ತಿಯನ್ನು ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ.

## ಡ್ಯಾಶ್ಬೋರ್ಡ್

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) ನಲ್ಲಿನ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಪುಟವು ಎರಡು ಟ್ಯಾಬ್ಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ:

- **ಸ್ಥಾಪಿಸಲಾಗಿದೆ** — ಸ್ಥಾಪಿಸಲಾದ ಪ್ಲಗಿನ್ಗಳನ್ನು ಅವುಗಳ ಡಿಕ್ಲೇರ್ಡ್ ಕೊಕ್ಕೆಗಳು, activate/deactivate ಟಾಗಲ್, ಅನ್ಇನ್ಸ್ಟಾಲ್ ಬಟನ್ ಮತ್ತು "ಪ್ಲಗ್ಇನ್ಗಳಿಗಾಗಿ ಸ್ಕ್ಯಾನ್" ಕ್ರಿಯೆಯೊಂದಿಗೆ ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ (`POST /api/plugins/scan`).
- **ಮಾರುಕಟ್ಟೆ** — ಕಸ್ಟಮ್ ರಿಜಿಸ್ಟ್ರಿ URL ಅನ್ನು ಹೊಂದಿಸಲು ಕ್ಷೇತ್ರದೊಂದಿಗೆ `GET /api/plugins/marketplace` ನಿಂದ ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ತೋರಿಸುತ್ತದೆ.

OmniRoute ಪ್ರಕ್ರಿಯೆಯ ಸಂಪೂರ್ಣ ಸವಲತ್ತುಗಳೊಂದಿಗೆ ಪ್ಲಗಿನ್ಗಳು ರನ್ ಆಗುತ್ತವೆ ಎಂಬ ಎಚ್ಚರಿಕೆಯನ್ನು ಪುಟವು ಯಾವಾಗಲೂ ತೋರಿಸುತ್ತದೆ.

ಪ್ರತಿ-ಪ್ಲಗಿನ್ ಸಂರಚನಾ ಪುಟವು `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) ನಲ್ಲಿ ವಾಸಿಸುತ್ತದೆ.
