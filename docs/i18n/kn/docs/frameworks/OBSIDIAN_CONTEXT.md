## ಇದು ಏನು

OmniRoute ಒಂದು **Obsidian** ವಾಲ್ಟ್ಗೆ **ಸಂದರ್ಭ ಮೂಲವಾಗಿ** ಸಂಪರ್ಕಿಸುತ್ತದೆ — ಇದು
ಅಂತರ್ನಿರ್ಮಿತ MCP ಸರ್ವರ್ ಮೂಲಕ ಏಜೆಂಟ್ಗಳು ಓದುವ ಮತ್ತು ಬರೆಯುವ ಸ್ಥಳೀಯ Markdown ಜ್ಞಾನ
ಭಂಡಾರವಾಗಿದೆ. ಈ ಏಕೀಕರಣವು ಡೆಸ್ಕ್ಟಾಪ್ ಆ್ಯಪ್ನಲ್ಲಿ ಚಾಲನೆಯಲ್ಲಿರುವ **Obsidian Local REST API**
ಸಮುದಾಯ ಪ್ಲಗಿನ್ನೊಂದಿಗೆ ಸಂವಹನ ನಡೆಸುತ್ತದೆ. ಆದ್ದರಿಂದ ಏಜೆಂಟ್ಗಳು ಟಿಪ್ಪಣಿಗಳನ್ನು ಹುಡುಕಬಹುದು,
ಫೈಲ್ಗಳನ್ನು ಓದಬಹುದು/ಬರೆಯಬಹುದು/ಪ್ಯಾಚ್ ಮಾಡಬಹುದು, ವಾಲ್ಟ್ ಅನ್ನು ಪಟ್ಟಿ ಮಾಡಬಹುದು, ದೈನಂದಿನ/ಸಾಪ್ತಾಹಿಕ
ಆವರ್ತಕ ಟಿಪ್ಪಣಿಗಳೊಂದಿಗೆ ಕೆಲಸ ಮಾಡಬಹುದು, ಟ್ಯಾಗ್ಗಳನ್ನು ನಿರ್ವಹಿಸಬಹುದು, Obsidian ಕಮಾಂಡ್ಗಳನ್ನು
ಚಲಾಯಿಸಬಹುದು ಮತ್ತು (ಐಚ್ಛಿಕವಾಗಿ) ದ್ವಿಮುಖ ಡೆಸ್ಕ್ಟಾಪ್↔ಮೊಬೈಲ್ ವಾಲ್ಟ್ ಸಿಂಕ್ ಅನ್ನು ಸಂಯೋಜಿಸಬಹುದು.

ಕ್ಲೈಂಟ್ (`src/lib/obsidian/api.ts`) Local REST APIಯನ್ನು ಈ ವೈಶಿಷ್ಟ್ಯಗಳೊಂದಿಗೆ ಆವರಿಸುತ್ತದೆ:

- ತಾತ್ಕಾಲಿಕ `5xx` ದೋಷಗಳಿಗೆ **ಹಿನ್ನಡೆ ಅವಧಿಯೊಂದಿಗೆ ಮರುಪ್ರಯತ್ನ**, `AbortController` ಮೂಲಕ **30-ಸೆಕೆಂಡ್ ಕಾಲಮಿತಿ**.
- **ಟೈಪ್ ಮಾಡಿದ ದೋಷ ವರ್ಗೀಕರಣ** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- ಸಾಮಾನ್ಯ ಪೋರ್ಟ್ ತಪ್ಪನ್ನು ಸೂಚಿಸುವ ಸ್ನೇಹಪರ **"Obsidian ಅನ್ನು ತಲುಪಲು ಸಾಧ್ಯವಿಲ್ಲ" ಸಲಹೆ**
  (HTTP `27123`ನಲ್ಲಿ, `27124`ನಲ್ಲಿರುವ MCP ಎಂಡ್ಪಾಯಿಂಟ್ನಲ್ಲಿ **ಅಲ್ಲ**) ಮತ್ತು Tailscale ಸ್ವರೂಪ.
- ಸ್ಪೇಸ್ಗಳು/ಸ್ಲ್ಯಾಶ್ಗಳನ್ನು ಹೊಂದಿರುವ ಟಿಪ್ಪಣಿ ಪಥಗಳು ಸುರಕ್ಷಿತವಾಗಿರುವಂತೆ ವಾಲ್ಟ್ಗೆ ಸಂಬಂಧಿತ
  **ಪಥ ಎನ್ಕೋಡಿಂಗ್**.

## ಸೆಟಪ್

Obsidian ಟೋಕನ್ ಅಥವಾ ಮೂಲ URLಗಾಗಿ **ಯಾವುದೇ ಪರಿಸರ ಚರಾಂಶವಿಲ್ಲ** — ಎರಡನ್ನೂ
`src/lib/db/obsidian.ts` ಮೂಲಕ SQLite `key_value` ಕೋಷ್ಟಕದಲ್ಲಿ (`obsidian` ನೇಮ್ಸ್ಪೇಸ್)
ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ. ಟೋಕನ್ ಅನ್ನು **ಸಂಗ್ರಹಿತ ಸ್ಥಿತಿಯಲ್ಲಿ ಎನ್ಕ್ರಿಪ್ಟ್ ಮಾಡಲಾಗುತ್ತದೆ**
(AES-256-GCM, ಸರಳಪಠ್ಯ ಹಿಮ್ಮುಖ-ಹೊಂದಾಣಿಕೆ ಫಾಲ್ಬ್ಯಾಕ್ನೊಂದಿಗೆ). Endpoint ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ
**Context Sources** ಟ್ಯಾಬ್ನಿಂದ (`ObsidianSourceCard`) ಅಥವಾ ಸೆಟ್ಟಿಂಗ್ಗಳ REST API ಮೂಲಕ
ಕಾನ್ಫಿಗರ್ ಮಾಡಿ.

> [!IMPORTANT]
> **Obsidian Local REST API** ಪ್ಲಗಿನ್ ಅನ್ನು ಸ್ಥಾಪಿಸಿ ಚಾಲನೆಯಲ್ಲಿರಿಸಬೇಕು. ಅದರ REST
> ಇಂಟರ್ಫೇಸ್ **HTTP `127.0.0.1:27123`** ನಲ್ಲಿ ಆಲಿಸುತ್ತದೆ (ಡೀಫಾಲ್ಟ್ ಮೂಲ URL). ಪೋರ್ಟ್ `27124`
> ಒಂದು _ಪ್ರತ್ಯೇಕ_ MCP/HTTPS ಎಂಡ್ಪಾಯಿಂಟ್ ಆಗಿದ್ದು, ಸೆಟ್ಟಿಂಗ್ಗಳ ರೂಟ್ ಅದನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ತಿರಸ್ಕರಿಸುತ್ತದೆ.
> ಮತ್ತೊಂದು ಸಾಧನದಿಂದ ಸಂಪರ್ಕಿಸುತ್ತಿದ್ದರೆ, `http://<tailscale-ip>:27123` ಬಳಸಿ.

### ಕಾನ್ಫಿಗರೇಶನ್ ಕೀಗಳು (SQLite `key_value`, ನೇಮ್ಸ್ಪೇಸ್ `obsidian`)

| ಕೀ                | ಉದ್ದೇಶ                                           | ಎನ್ಕ್ರಿಪ್ಟ್ ಮಾಡಲಾಗಿದೆಯೇ |
| ----------------- | ------------------------------------------------ | ----------------------- |
| `api_key`         | Local REST API ಬೇರರ್ ಟೋಕನ್                       | ಹೌದು                    |
| `base_url`        | REST ಮೂಲ URL (ಡೀಫಾಲ್ಟ್ `http://127.0.0.1:27123`) | ಇಲ್ಲ                    |
| `vault_path`      | ವಾಲ್ಟ್ ಡೈರೆಕ್ಟರಿಗೆ ನಿರಪೇಕ್ಷ ಪಥ (ಸಿಂಕ್ಗಾಗಿ)       | ಇಲ್ಲ                    |
| `webdav_username` | ರಚಿಸಲಾದ WebDAV ಬಳಕೆದಾರಹೆಸರು (ವಾಲ್ಟ್ ಸಿಂಕ್)       | ಇಲ್ಲ                    |
| `webdav_password` | ರಚಿಸಲಾದ WebDAV ಪಾಸ್ವರ್ಡ್ (ವಾಲ್ಟ್ ಸಿಂಕ್)          | ಹೌದು                    |
| `webdav_enabled`  | WebDAV ವಾಲ್ಟ್ ಸಿಂಕ್ ಸಕ್ರಿಯವಾಗಿದೆಯೇ ಎಂಬುದು        | ಇಲ್ಲ                    |

### REST ಮೂಲಕ ಕಾನ್ಫಿಗರ್ ಮಾಡಿ

```bash
# Local REST API ಟೋಕನ್ ಅನ್ನು ಉಳಿಸಿ + ಮೌಲ್ಯೀಕರಿಸಿ (POST ಸ್ಥಿತಿ ಪರಿಶೀಲನೆಯ ಮೂಲಕ ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# ಸಂಪರ್ಕದ ಸ್ಥಿತಿಯನ್ನು ಪರಿಶೀಲಿಸಿ (connected, hasToken, baseUrl, vaultPath ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ)
curl http://localhost:20128/api/settings/obsidian

# ಸಂಪರ್ಕ ಕಡಿತಗೊಳಿಸಿ (ಸಂಗ್ರಹಿಸಿದ ಟೋಕನ್ ಅನ್ನು ತೆರವುಗೊಳಿಸುತ್ತದೆ)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

ಎಲ್ಲಾ ವಿಧಾನಗಳಿಗೂ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ದೃಢೀಕರಣದ ಅಗತ್ಯವಿದೆ. `POST`, ಪೋರ್ಟ್ `27124` ನಲ್ಲಿರುವ
ಯಾವುದೇ URL ಅನ್ನು ತಿರಸ್ಕರಿಸುತ್ತದೆ ಮತ್ತು ಉಳಿಸುವ ಮೊದಲು Local REST API ಸ್ಥಿತಿ ಎಂಡ್ಪಾಯಿಂಟ್ಗೆ
ಕರೆ ಮಾಡುವ ಮೂಲಕ ಟೋಕನ್ ಅನ್ನು ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ.

### WebDAV ವಾಲ್ಟ್ ಸಿಂಕ್

`src/app/api/settings/obsidian/webdav/route.ts`, ಐಚ್ಛಿಕ WebDAV-ಆಧಾರಿತ
ವಾಲ್ಟ್ ಸಿಂಕ್ ಅನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ (`src/lib/obsidianSync.ts` ಮೂಲಕ ಚಾಲಿತವಾಗುತ್ತದೆ). ಇದನ್ನು
ಸಕ್ರಿಯಗೊಳಿಸಿದಾಗ OmniRoute ಅನ್ನು ಸ್ಥಳೀಯ ವಾಲ್ಟ್ ಡೈರೆಕ್ಟರಿಗೆ ಸೂಚಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಯಾದೃಚ್ಛಿಕ
WebDAV ಬಳಕೆದಾರಹೆಸರು/ಪಾಸ್ವರ್ಡ್ ಜೋಡಿಯನ್ನು ರಚಿಸಲಾಗುತ್ತದೆ:

```bash
# ವಾಲ್ಟ್ ಡೈರೆಕ್ಟರಿಗಾಗಿ WebDAV ಸಿಂಕ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ (ಬಳಕೆದಾರಹೆಸರು/ಪಾಸ್ವರ್ಡ್ ರಚಿಸುತ್ತದೆ)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV ಸಿಂಕ್ ಸ್ಥಿತಿಯನ್ನು ಪಡೆಯಿರಿ (ಸಕ್ರಿಯವಾಗಿರುವಾಗ ಮಾತ್ರ ರುಜುವಾತುಗಳನ್ನು ಹಿಂದಿರುಗಿಸಲಾಗುತ್ತದೆ)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV ಸಿಂಕ್ ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ (ರುಜುವಾತುಗಳು + ನಿರ್ವಹಿತ .stignore ಅನ್ನು ತೆರವುಗೊಳಿಸುತ್ತದೆ)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### ಭದ್ರತೆ ಮತ್ತು ಸಾರಿಗೆ

WebDAV ದೃಢೀಕರಣವು ಪ್ರತಿ-IP ವೈಫಲ್ಯ ಟ್ರ್ಯಾಕಿಂಗ್ ಮತ್ತು ಲಾಕ್ಔಟ್ ಅನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತದೆ (60-ಸೆಕೆಂಡ್ ವಿಂಡೋದಲ್ಲಿ 10 ವಿಫಲ ಪ್ರಯತ್ನಗಳು `429 Too Many Requests` ಮತ್ತು `Retry-After` ನೊಂದಿಗೆ 5-ನಿಮಿಷದ ಲಾಕ್ಔಟ್ ಅನ್ನು ಪ್ರಚೋದಿಸುತ್ತದೆ). WebDAV ಮೂಲಭೂತ ದೃಢೀಕರಣ ರುಜುವಾತುಗಳನ್ನು ರವಾನಿಸುವುದರಿಂದ, ಲೂಪ್ಬ್ಯಾಕ್ನ ಹೊರಗಿನ WebDAV ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಪ್ರವೇಶಿಸುವಾಗ TLS ಕೊನೆಗೊಳಿಸುವುದನ್ನು (ಅಥವಾ Tailscale ಅಥವಾ Cloudflare Tunnel ನಂತಹ ಸುರಕ್ಷಿತ ಸುರಂಗದ ಮೂಲಕ ರೂಟಿಂಗ್) ಬಲವಾಗಿ ಶಿಫಾರಸು ಮಾಡಲಾಗುತ್ತದೆ.

### ಪ್ರತಿ-API-ಕೀ ಸಂದರ್ಭ ಮೂಲ (ಐಚ್ಛಿಕ)

Obsidian ಕಾನ್ಫಿಗರೇಶನ್ ಅನ್ನು `api_key_context_sources` ಕೋಷ್ಟಕದ ಮೂಲಕ
**ಪ್ರತಿ API ಕೀಗೆ** ಸೀಮಿತಗೊಳಿಸಬಹುದು (`src/lib/db/apiKeyContextSources.ts`). MCP ಕರೆಯೊಂದು
ದೃಢೀಕರಿಸಿದ API ಕೀ id ಅನ್ನು ಹೊಂದಿರುವಾಗ, `getObsidianConfigForApiKey()` ಆ ಕೀಗೆ ಸೇರಿದ ಸ್ವಂತ
ಟೋಕನ್/ಮೂಲ-URL/ವಾಲ್ಟ್-ಪಥಕ್ಕೆ (`source: "api_key"`) ಆದ್ಯತೆ ನೀಡುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ ಜಾಗತಿಕ
ಕಾನ್ಫಿಗರೇಶನ್ಗೆ (`source: "global"`) ಫಾಲ್ಬ್ಯಾಕ್ ಆಗುತ್ತದೆ.

ಸಿಂಕ್ಗೆ ಸಂಬಂಧಿಸದ MCP ಪರಿಕರಗಳು ಈ ಕಾನ್ಫಿಗರೇಶನ್ ಅನ್ನು ಓದುವ ಮೊದಲು ಪರಿಹರಿಸಲಾದ ಕರೆಗಾರರ
ಗುರುತನ್ನು ಹೊಂದಿರಬೇಕು. ಗುರುತು ಇಲ್ಲದ ಕರೆಗಾರರು `Obsidian API token not configured` ಅನ್ನು
ಸ್ವೀಕರಿಸುತ್ತಾರೆ ಮತ್ತು ಯಾವುದೇ ವಾಲ್ಟ್ ವಿನಂತಿಯನ್ನು ಕಳುಹಿಸಲಾಗುವುದಿಲ್ಲ. HTTP ಕರೆಗಾರರನ್ನು ಅವರ
ವಿನಂತಿಯ ರುಜುವಾತುಗಳ ಮೂಲಕ ಪರಿಹರಿಸಲಾಗುತ್ತದೆ; stdio ಕರೆಗಾರರನ್ನು `OMNIROUTE_API_KEY` ಅಥವಾ
`ROUTER_API_KEY` ಮೂಲಕ ಪರಿಹರಿಸಬಹುದು. ಪರಿಹರಿಸಲಾಗದ HTTP ಕರೆಗಾರರು ಸರ್ವರ್ನ ಪರಿಸರ ಗುರುತನ್ನು
ಪಡೆಯಲು ಸಾಧ್ಯವಿಲ್ಲ. ಪ್ಲೇಸ್ಹೋಲ್ಡರ್ IDಗಳು ಮಾತ್ರ ಪ್ರವೇಶವನ್ನು ಅಧಿಕೃತಗೊಳಿಸುವುದಿಲ್ಲ; `env-key` ಗೆ
ಪರಿಹಾರವಾಗುವ ಮಾನ್ಯ ಪರಿಸರ ರುಜುವಾತಿಗೆ ಬೆಂಬಲ ಮುಂದುವರಿಯುತ್ತದೆ. ಪ್ರತಿ-ಕೀ Obsidian ಕಾನ್ಫಿಗರೇಶನ್
ಇಲ್ಲದ ದೃಢೀಕರಿಸಿದ ಕೀಗಳಿಗೆ ಜಾಗತಿಕ ಫಾಲ್ಬ್ಯಾಕ್ ಉಳಿಯುತ್ತದೆ. ನಾಲ್ಕು `obsidian_sync_*` ಪರಿಕರಗಳು
ತಮ್ಮ ಪ್ರತ್ಯೇಕ ಸಿಂಕ್-ಟೋಕನ್ ನಡವಳಿಕೆಯನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ.

## MCP ಉಪಕರಣಗಳು (22)

`open-sse/mcp-server/tools/obsidianTools.ts` ನಲ್ಲಿ ವ್ಯಾಖ್ಯಾನಿಸಲಾಗಿದೆ. token/base-URL ಅನ್ನು ಪ್ರತಿ ಕರೆಗೆ ಪರಿಹರಿಸಲಾಗುತ್ತದೆ (ಪ್ರತಿ-API-ಕೀಗೆ ಮೊದಲು, ನಂತರ ಜಾಗತಿಕ). OmniRoute ಅನ್ನು ಹೊಡೆಯುವ ಪರಿಕರಗಳು** ಸಿಂಕ್ ಸರ್ವರ್** (ನಾಲ್ಕು `obsidian_sync_*` ಪರಿಕರಗಳು) ಹೆಚ್ಚುವರಿಯಾಗಿ OmniRoute ಸೆಟ್ಟಿಂಗ್ಗಳಲ್ಲಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ ಸಿಂಕ್ ದೃಢೀಕರಣ ಟೋಕನ್ ಅಗತ್ಯವಿರುತ್ತದೆ.

### ವ್ಯಾಪ್ತಿಗಳು

[MCP-SERVER.md](./MCP-SERVER.md) ನೋಡಿ.

- **ಟಿಪ್ಪಣಿ ರಚನೆ / ದಿನಚರಿ ಬರವಣಿಗೆ** — ಏಜೆಂಟ್ ಔಟ್ಪುಟ್, ಸಾರಾಂಶಗಳು ಅಥವಾ ದೈನಂದಿನ ಟಿಪ್ಪಣಿಗಳನ್ನು
  (`obsidian_get_periodic_note`) ವಾಲ್ಟ್ಗೆ ದಾಖಲಿಸಲು `obsidian_write_note`, `obsidian_append_note`, ಅಥವಾ
  ನಿಖರವಾದ `obsidian_patch_note`.
- **ವಾಲ್ಟ್ ನ್ಯಾವಿಗೇಶನ್** — ಓದುವ/ಬರೆಯುವ ಮೊದಲು ರಚನೆಯನ್ನು ಅನ್ವೇಷಿಸಲು `obsidian_list_vault`, `obsidian_get_document_map`, ಮತ್ತು
  `obsidian_get_tags`.
- **Obsidian ಸ್ವಯಂಚಾಲನೆ** — ಏಜೆಂಟ್ನಿಂದ ಪ್ಲಗಿನ್ಗಳು/ಕಮಾಂಡ್ಗಳನ್ನು ಚಾಲನೆ ಮಾಡಲು `obsidian_list_commands` + `obsidian_execute_command`;
  UI ಯಲ್ಲಿ ಟಿಪ್ಪಣಿಯನ್ನು ಪ್ರದರ್ಶಿಸಲು `obsidian_open_file`.
- **ಮೊಬೈಲ್ ಸಿಂಕ್** — WebDAV ಸಿಂಕ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ, ನಂತರ ಡೆಸ್ಕ್ಟಾಪ್↔ಮೊಬೈಲ್ ಅನ್ನು ಸಮನ್ವಯಗೊಳಿಸಲು ಮತ್ತು ಸಂಘರ್ಷಗಳನ್ನು ಪರಿಹರಿಸಲು
  `obsidian_sync_trigger` / `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`.
