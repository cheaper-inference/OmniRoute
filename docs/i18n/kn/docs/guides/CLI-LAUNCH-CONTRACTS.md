ತಟಸ್ಥ `config/cli-tools-manifest.json` ಒಪ್ಪಂದವು ಅಂಗೀಕೃತ IDs, ಅಲಿಯಾಸ್, ಬೈನರಿ ಅಭ್ಯರ್ಥಿಗಳು, ಸೆಟಪ್ ಪಾಕವಿಧಾನಗಳು, ಮಾದರಿ ವಾದಗಳು ಮತ್ತು ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಘೋಷಿಸುತ್ತದೆ. `bin/cli/cli-manifest.mjs` ನಲ್ಲಿನ ಸಾದಾ ನೋಡ್ ಅಡಾಪ್ಟರ್ ಮತ್ತು `src/shared/constants/cliIntegrationManifest.ts` ನಲ್ಲಿನ TypeScript ಅಡಾಪ್ಟರ್ ಒಂದೇ ಫೈಲ್ ಅನ್ನು ಓದುತ್ತವೆ. ರನ್ಟೈಮ್, ಕ್ಯಾಟಲಾಗ್, ಕಾನ್ಫಿಗರ್, ಪೂರ್ಣಗೊಳಿಸುವಿಕೆ, ಜನರೇಟರ್ಗಳು ಮತ್ತು ಬ್ಯಾಕೆಂಡ್ ನೋಂದಣಿಯನ್ನು `tests/unit/cli/cli-manifest-drift.test.ts` ನಿಂದ ಒಟ್ಟಿಗೆ ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ. ಪಟ್ಟಿ ಮಾಡಿರುವುದು ಎಂದರೆ ಉಪಕರಣವನ್ನು ಪ್ರಾರಂಭಿಸಬಹುದು ಅಥವಾ ಕಾನ್ಫಿಗರ್ ಮಾಡಬಹುದು ಎಂದು ಅರ್ಥವಲ್ಲ. ನಿರ್ದಿಷ್ಟವಾಗಿ, 5dive ಕಾನ್ಫಿಗರ್-ಮಾತ್ರ ಉಳಿದಿದೆ.

## ಮಕ್ಕಳ ಪರಿಸರ ಮತ್ತು ಜೀವನಚಕ್ರ

`omniroute run`, `omniroute launch` ಮತ್ತು `omniroute launch-codex` OS/terminal ಹೊಂದಾಣಿಕೆಯ ಅನುಮತಿ ಪಟ್ಟಿಯನ್ನು ಪಡೆದುಕೊಳ್ಳುತ್ತವೆ ಮತ್ತು ಆಯ್ಕೆಮಾಡಿದ ಗುರಿಯ ರುಜುವಾತುಗಳನ್ನು ಇಂಜೆಕ್ಟ್ ಮಾಡಿ. ಸಂಬಂಧವಿಲ್ಲದ ಪೂರೈಕೆದಾರರು ಮತ್ತು ಡೇಟಾಬೇಸ್ ರಹಸ್ಯಗಳನ್ನು ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಆನುವಂಶಿಕವಾಗಿ ಪಡೆಯಲಾಗುವುದಿಲ್ಲ. `--inherit-env` ಪೂರ್ಣ ಪೋಷಕ-ಪರಿಸರದ ಉತ್ತರಾಧಿಕಾರವನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಮರುಸ್ಥಾಪಿಸುತ್ತದೆ; ಆಯ್ಕೆಮಾಡಿದ ಮೂರನೇ ವ್ಯಕ್ತಿಯ ಪ್ರಕ್ರಿಯೆಯು ಆ ಮೌಲ್ಯಗಳನ್ನು ಸ್ವೀಕರಿಸಿದಾಗ ಮಾತ್ರ ಅದನ್ನು ಬಳಸಿ. ಇದು ಪರಿಸರ ಫಿಲ್ಟರಿಂಗ್ ಆಗಿದೆ, OS ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಅಲ್ಲ: ಪ್ರಕ್ರಿಯೆಯು ಇನ್ನೂ ಕರೆ ಮಾಡುವವರ ಫೈಲ್ಸಿಸ್ಟಮ್ ಅನುಮತಿಗಳೊಂದಿಗೆ ಚಲಿಸುತ್ತದೆ.

ಅಡಚಣೆ ಮತ್ತು ಮುಕ್ತಾಯದ ಸಂಕೇತಗಳನ್ನು ಮಗುವಿಗೆ ರವಾನಿಸಲಾಗುತ್ತದೆ. ತಾತ್ಕಾಲಿಕ ಕಾನ್ಫಿಗರೇಶನ್ ಅನ್ನು ತೆಗೆದುಹಾಕುವ ಮೊದಲು ಲಾಂಚರ್ ಮಗುವಿನ ನಿಕಟ ಘಟನೆಗಾಗಿ ಕಾಯುತ್ತದೆ. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` ಬಲವಂತದ ಮುಕ್ತಾಯದ ಮೊದಲು ಗ್ರೇಸ್ ಅವಧಿಯನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ (ಡೀಫಾಲ್ಟ್ 5000 ಮಿಲಿಸೆಕೆಂಡುಗಳು).

## Gemini ನಿರಂತರ ಸೆಟಪ್

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

ಮೊದಲ ಎರಡು ಆಜ್ಞೆಗಳು ಆಯ್ದ ಸ್ಥಳೀಯ ಅಥವಾ ದೂರಸ್ಥ ಸರ್ವರ್ಗಾಗಿ ಈ ಯಂತ್ರವನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡುತ್ತದೆ. ಸೆಟಪ್ ಸಂಬಂಧವಿಲ್ಲದ JSON ಸೆಟ್ಟಿಂಗ್ಗಳನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ, Gemini API-ಕೀ ದೃಢೀಕರಣವನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ ಮತ್ತು ಖಾಸಗಿ `.gemini/.env` ಫೈಲ್ಗೆ ಅಂತಿಮ ಬಿಂದು ಮತ್ತು ರುಜುವಾತುಗಳನ್ನು ಬರೆಯುತ್ತದೆ. ಇದು ಅಮಾನ್ಯವಾದ JSON ತಿದ್ದಿ ಬರೆಯುವ ಬದಲು ನಿರಾಕರಿಸುತ್ತದೆ. ಎಂಬೆಡೆಡ್ ರುಜುವಾತುಗಳು, ಪ್ರಶ್ನೆ ಪ್ಯಾರಾಮೀಟರ್ಗಳು ಅಥವಾ ತುಣುಕುಗಳಿಲ್ಲದೆ ಎಂಡ್ಪಾಯಿಂಟ್ URLs HTTP(S) ಆಗಿರಬೇಕು. ಡ್ರೈ-ರನ್ ಪ್ರಿಂಟ್ಸ್ ಪಥಗಳು, ರುಜುವಾತು ಮೌಲ್ಯಗಳಲ್ಲ.

`GEMINI_CLI_HOME` ಅಥವಾ `--gemini-home` ನಿರಂತರ ಮನೆ ಮೂಲವನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ. ನಿಜವಾದ `run gemini` ತನ್ನದೇ ಆದ ತಾತ್ಕಾಲಿಕ ಮನೆಯನ್ನು ರಚಿಸುತ್ತದೆ ಮತ್ತು ನಂತರ ತೆಗೆದುಹಾಕುತ್ತದೆ. ಯಾವುದೇ ಮೋಡ್ Gemini ನ ಕಾರ್ಯಸ್ಥಳ-ಟ್ರಸ್ಟ್ ಪರಿಶೀಲನೆಗಳನ್ನು ಬೈಪಾಸ್ ಮಾಡುವುದಿಲ್ಲ.

## Codex ಪ್ರೊಫೈಲ್ಗಳು

`configure codex` ಒಂದು ಖಾಸಗಿ `<name>.config.toml` ಮಾದರಿ ಮತ್ತು ಅದರ OmniRoute ಪೂರೈಕೆದಾರರ ಅಂತಿಮ ಬಿಂದುದೊಂದಿಗೆ ಬರೆಯುತ್ತದೆ. ರುಜುವಾತುಗಳನ್ನು `OMNIROUTE_API_KEY` ಮೂಲಕ ಉಲ್ಲೇಖಿಸಲಾಗಿದೆ, ಎಂದಿಗೂ ಎಂಬೆಡ್ ಮಾಡಲಾಗಿಲ್ಲ. ಉಡಾವಣಾ ಆಜ್ಞೆಯು ಆಯ್ದ ಮಾದರಿಯನ್ನು ಉನ್ನತ ಮಟ್ಟದ `model` ಕೀಲಿಯಲ್ಲಿ ಹೊಂದಿಸುತ್ತದೆ, `model_providers` ಒಳಗೆ ಅಲ್ಲ.

ಪ್ರತ್ಯೇಕ ಪ್ರೊಫೈಲ್ ಫೈಲ್ಗಳು ಪ್ರಸ್ತುತ ದಾಖಲಿತ Codex ಒಪ್ಪಂದವಾಗಿದೆ; `codex --profile <name>` ನೊಂದಿಗೆ ಆಯ್ಕೆ ಮಾಡಿದಾಗ ಅವರು ಬಳಕೆದಾರ ಸಂರಚನೆಯನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತಾರೆ. [ಅಧಿಕೃತ ಪ್ರೊಫೈಲ್ ಉಲ್ಲೇಖ](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) ಮತ್ತು [OmniRoute Codex ಮಾರ್ಗದರ್ಶಿ](./CODEX-CLI-CONFIGURATION.md) ನೋಡಿ.

## ಹರ್ಮೆಟಿಕ್ ಕಮಾಂಡ್ ಎಕ್ಸಿಕ್ಯೂಶನ್

ಸ್ಪಷ್ಟವಾದ `DATA_DIR` ನೊಂದಿಗೆ, `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` ಹೊಂದಿಸುವುದು ಪ್ರಾರಂಭವನ್ನು ಡೀಫಾಲ್ಟ್ ಬಳಕೆದಾರ ಡೇಟಾ ಡೈರೆಕ್ಟರಿಯ ರುಜುವಾತು ಪರಿಸರಕ್ಕೆ ಬೀಳದಂತೆ ತಡೆಯುತ್ತದೆ. ಪ್ರತ್ಯೇಕ ಪರೀಕ್ಷೆಗಳಿಗೆ ಇದು ಉಪಯುಕ್ತವಾಗಿದೆ. ಇದು ಇತರ ಸ್ಪಷ್ಟವಾಗಿ ಆಯ್ಕೆಮಾಡಿದ ಪರಿಸರ ಫೈಲ್ಗಳನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವುದಿಲ್ಲ.

## ವರ್ಕಿಂಗ್-ಡೈರೆಕ್ಟರಿ `.env`

CLI ಈ ಕ್ರಮದಲ್ಲಿ `.env` ಫೈಲ್ಗಳನ್ನು ಓದುತ್ತದೆ ಮತ್ತು ಕೀಲಿಯನ್ನು ಹೊಂದಿಸುವ ಮೊದಲ ಫೈಲ್ ಗೆಲ್ಲುತ್ತದೆ: ಸ್ಪಷ್ಟವಾದ `DATA_DIR`, ಡೀಫಾಲ್ಟ್ ಡೇಟಾ ಡೈರೆಕ್ಟರಿ, ಪ್ರಸ್ತುತ ಕಾರ್ಯನಿರ್ವಹಿಸುವ ಡೈರೆಕ್ಟರಿ, ನಂತರ ಪ್ಯಾಕೇಜ್ ಡೈರೆಕ್ಟರಿ. ಶೆಲ್ ಅಸ್ಥಿರ ಯಾವಾಗಲೂ ಗೆಲ್ಲುತ್ತದೆ.

ಕೆಲಸ ಮಾಡುವ ಡೈರೆಕ್ಟರಿಯು ಬೇರೆಯವರಿಗೆ ಸೇರಿರಬಹುದು (ಕ್ಲೋನ್ ಮಾಡಿದ ರೆಪೊಸಿಟರಿ, ಅನ್ಪ್ಯಾಕ್ ಮಾಡಲಾದ ಆರ್ಕೈವ್), ಮತ್ತು `omniroute serve` ಸರ್ವರ್ಗೆ ಮತ್ತು ಸರ್ವರ್ ರನ್ ಮಾಡುವ ಪ್ರತಿಯೊಂದು ಸಾಧನಕ್ಕೂ CLI ಪರಿಸರವನ್ನು ರವಾನಿಸುತ್ತದೆ. ಆದ್ದರಿಂದ ಅಲ್ಲಿ `.env` ಈ ಕೀಗಳನ್ನು ಮಾತ್ರ ಹೊಂದಿಸಬಹುದು, `bin/cli/utils/untrustedCwdEnv.mjs` ನಲ್ಲಿ ಪಟ್ಟಿ ಮಾಡಲಾಗಿದೆ:

| ಕೀ                              | ಸ್ವೀಕರಿಸಿದ ಮೌಲ್ಯಗಳು                                                           |
| ------------------------------- | ----------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` ಅಥವಾ `yes` ಯಾವುದೇ ಸಂದರ್ಭದಲ್ಲಿ, ಸರ್ವರ್ ಪರಿಗಣಿಸುವ ಮೌಲ್ಯಗಳು          |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 64 ಅಕ್ಷರಗಳು, ಅಂಕೆಗಳು, `_`, `.`, `@` ಅಥವಾ `-` ವರೆಗೆ                            |
| `LANGUAGE`                      | ಅದೇ, ಜೊತೆಗೆ `:`                                                               |
| `TZ`                            | 64 ಅಕ್ಷರಗಳವರೆಗೆ, ಅಂಕೆಗಳು, `_`, `+`, `-` ಅಥವಾ `/`, `/` ಯಿಂದ ಪ್ರಾರಂಭವಾಗುವುದಿಲ್ಲ |
| `NO_COLOR`, `FORCE_COLOR`       | 16 ಅಕ್ಷರಗಳು ಮತ್ತು ಅಂಕೆಗಳವರೆಗೆ                                                 |

`REQUIRE_API_KEY` ಸ್ವೀಕರಿಸುವ ಪ್ರತಿಯೊಂದು ಮೌಲ್ಯವು ಚೆಕ್ ಅನ್ನು ಆನ್ ಮಾಡುತ್ತದೆ, ಆದ್ದರಿಂದ ಫೈಲ್ ಸ್ವತಃ ಚೆಕ್ ಅನ್ನು ಆಫ್ ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ. ಇದು ಫಲಿತಾಂಶವನ್ನು ನಿರ್ಧರಿಸುವುದಿಲ್ಲ, ಆದರೂ: ಪರಿಸರದ ಮೊದಲು ಡೇಟಾಬೇಸ್ನಲ್ಲಿ ಸಂಗ್ರಹವಾಗಿರುವ `REQUIRE_API_KEY` ಓವರ್ರೈಡ್ ಅನ್ನು ಸರ್ವರ್ ಓದುತ್ತದೆ, ಆದರೆ API ಕೀ ಇಲ್ಲದೆ ಎಲ್ಲಾ ಇಂಟರ್ಫೇಸ್ಗಳಲ್ಲಿ ಆಲಿಸುವ ಬಗ್ಗೆ ಆರಂಭಿಕ ಎಚ್ಚರಿಕೆಯು ಪರಿಸರವನ್ನು ಮಾತ್ರ ಓದುತ್ತದೆ. `false` ಯ ಸಂಗ್ರಹಿತ ಅತಿಕ್ರಮಣದೊಂದಿಗೆ, ವರ್ಕಿಂಗ್-ಡೈರೆಕ್ಟರಿ `REQUIRE_API_KEY=true` API ಅನ್ನು ತೆರೆದಿರುತ್ತದೆ ಮತ್ತು ಆ ಎಚ್ಚರಿಕೆಯನ್ನು ಮರೆಮಾಡುತ್ತದೆ. `TZ` ನಿಯಮವು POSIX ಗಿಂತ ಕಿರಿದಾಗಿದೆ: ಇದು `.`, `:`, `,` ಮತ್ತು `<>` ತಿರಸ್ಕರಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ `:Area/City` ರೂಪ ಮತ್ತು `EST5EDT,M3.2.0,M11.1.0` ನಂತಹ ನಿಯಮಗಳನ್ನು ಶೆಲ್ನಲ್ಲಿ ಅಥವಾ `<DATA_DIR>/.env` ನಲ್ಲಿ ಹೊಂದಿಸಬೇಕಾಗುತ್ತದೆ.

ದೊಡ್ಡ ಪ್ರಕರಣದಲ್ಲಿ ಹೆಸರುಗಳು ನಿಖರವಾಗಿ ಹೊಂದಿಕೆಯಾಗಬೇಕು. ಯಾವುದೇ ಇತರ ಸಾಲು, ಅದರ ಪರಿಶೀಲನೆ ವಿಫಲವಾದ ಮೌಲ್ಯ, ಮತ್ತು ಸರಳ ASCII ಅಕ್ಷರಗಳು, ಅಂಕೆಗಳು ಮತ್ತು `_` ಅಲ್ಲದ ಹೆಸರನ್ನು (ಉದಾಹರಣೆಗೆ NUL ಬೈಟ್ ಅಥವಾ ನೋಟ-ಅಲೈಕ್ ಅಕ್ಷರದೊಂದಿಗೆ) ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ. CLI ಒಂದು ಎಚ್ಚರಿಕೆಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ, ಅದು ಹೊಂದಿಸಲಾಗದ ಕೀಗಳನ್ನು ಹೆಸರಿಸುತ್ತದೆ ಮತ್ತು ಅದು ನಿರ್ಲಕ್ಷಿಸಿದ ಅನುಮತಿಸಲಾದ ಕೀಗಳನ್ನು ಹೆಸರಿಸುತ್ತದೆ, ಪ್ರತಿಯೊಂದೂ ಏನನ್ನು ಬದಲಾಯಿಸಬೇಕು (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). ಮೌಲ್ಯಗಳನ್ನು ಮುದ್ರಿಸುವುದಿಲ್ಲ. ಈ ಸಂದೇಶಗಳಲ್ಲಿನ ಫೈಲ್ ಪಾತ್ಗಳು ಮತ್ತು `.env` ಮಾರ್ಗ `omniroute doctor` ವರದಿಗಳು ನಿಯಂತ್ರಣ ಅಥವಾ ಬೀಡಿ ಅಕ್ಷರಗಳನ್ನು ಹೊಂದಿರುವಾಗ ತಪ್ಪಿಸಿಕೊಳ್ಳಲಾಗುತ್ತದೆ. ಕೆಲಸದ ಡೈರೆಕ್ಟರಿಯು ಡೇಟಾ ಡೈರೆಕ್ಟರಿ ಅಥವಾ ಪ್ಯಾಕೇಜ್ ಡೈರೆಕ್ಟರಿಯಾಗಿದ್ದಾಗ ನಿರ್ಬಂಧವು ಅನ್ವಯಿಸುವುದಿಲ್ಲ.

`PORT`, `API_PORT` ಮತ್ತು `DASHBOARD_PORT` ಪಟ್ಟಿಯಲ್ಲಿಲ್ಲ. ಹೆಚ್ಚಿನ ಪ್ರಾಶಸ್ತ್ಯದ ಮೂಲದಿಂದ ಬೇಸ್ URL ಇಲ್ಲದೆ, CLI `localhost:<PORT>` ನೊಂದಿಗೆ ಮಾತನಾಡುತ್ತದೆ ಮತ್ತು ಅಲ್ಲಿ ಕೇಳುವ ಯಾವುದಾದರೂ CLI ನ API ಕೀ, ಸಂದರ್ಭ ಟೋಕನ್ ಮತ್ತು CLI ಯಂತ್ರ ಟೋಕನ್ (`x-omniroute-cli-token`, ನೋಡಿ [CLI_TOKEN.md](../security/CLI_TOKEN.md) ) ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ, ಇದನ್ನು ಸ್ಥಳೀಯ ಸರ್ವರ್ ಲೂಪ್ಬ್ಯಾಕ್ನಿಂದ ಮ್ಯಾನೇಜ್ಮೆಂಟ್ ಕರೆಗಳನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ. ವರ್ಕಿಂಗ್ ಡೈರೆಕ್ಟರಿಯಿಂದ ಬಂದ ಪೋರ್ಟ್ ಆ ಫೈಲ್ ಕೇಳುಗರನ್ನು ಆಯ್ಕೆ ಮಾಡಲು ಅನುಮತಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಶೆಲ್ನಲ್ಲಿ ಪೋರ್ಟ್ಗಳನ್ನು ಹೊಂದಿಸಿ, `<DATA_DIR>/.env` ಅಥವಾ `--port` ಆಯ್ಕೆಯನ್ನು ಹೊಂದಿರುವ ಕಮಾಂಡ್ಗಳನ್ನು (`serve`, `launch`, `run`).

ಪಾರ್ಸರ್ ಯಾವುದೇ `export` ಸಿಂಟ್ಯಾಕ್ಸ್ ಅನ್ನು ಹೊಂದಿಲ್ಲ. `export LD_PRELOAD=...` ನಂತಹ ಒಂದು ಸಾಲು ವೇರಿಯಬಲ್ `export LD_PRELOAD` ಅನ್ನು ಹೆಸರಿಸುತ್ತದೆ; ವರ್ಕಿಂಗ್ ಡೈರೆಕ್ಟರಿಯಿಂದ ಅದನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ ಮತ್ತು ಇತರ `.env` ಫೈಲ್ಗಳಲ್ಲಿ ಅದು ಅಕ್ಷರಶಃ ಹೆಸರನ್ನು ಹೊಂದಿಸುತ್ತದೆ, ಅದು ಏನನ್ನೂ ಓದುವುದಿಲ್ಲ.

CLI ಒಂದು ಸಂದರ್ಭದ ಸಂಗ್ರಹಿತ ಟೋಕನ್ (ಪ್ರವೇಶ ಟೋಕನ್ ಅಥವಾ ಲೆಗಸಿ API ಕೀ) ಅನ್ನು ಆ ಸಂದರ್ಭದ ಸ್ವಂತ ಮೂಲದೊಂದಿಗೆ ಮಾತ್ರ ಜೋಡಿಸುತ್ತದೆ: ಸ್ಕೀಮ್, ಹೋಸ್ಟ್ ಮತ್ತು ಪೋರ್ಟ್, `URL.origin` ನಂತೆ ಹೋಲಿಸಿದರೆ. ಇದು CLI ನ HTTP ಕ್ಲೈಂಟ್ (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) ಮೂಲಕ ಮಾಡಿದ ವಿನಂತಿಗಳಿಗೆ ಮತ್ತು ಬೇಸ್ URL ಮತ್ತು ಕೀಲಿಯನ್ನು ಮತ್ತೊಂದು ಉಪಕರಣದ ಸಂರಚನೆಗೆ ಬರೆಯುವ `launch`, `launch codex`, `configure` ಮತ್ತು `setup-*` ಆಜ್ಞೆಗಳಿಗೆ ಅನ್ವಯಿಸುತ್ತದೆ. `--remote` ನೊಂದಿಗೆ ಮತ್ತೊಂದು ಸರ್ವರ್ಗೆ ಸೂಚಿಸಲಾಗಿದೆ, ಒಂದನ್ನು ಹೊಂದಿಸಿದ್ದರೆ ಅವರು ಸ್ಪಷ್ಟವಾದ `--api-key` ಅಥವಾ `OMNIROUTE_API_KEY` ಅನ್ನು ಬಳಸುತ್ತಾರೆ ಮತ್ತು ಯಾವುದೇ ಸಂದರ್ಭ ಟೋಕನ್ ಇಲ್ಲ. ಹೋಲಿಕೆಯು ನಿಖರವಾಗಿದೆ, ಆದ್ದರಿಂದ `localhost` ಮತ್ತು `127.0.0.1`, ಅಥವಾ ಟ್ರೇಲಿಂಗ್ ಡಾಟ್ ಹೊಂದಿರುವ ಮತ್ತು ಇಲ್ಲದೆ ಹೋಸ್ಟ್, ವಿಭಿನ್ನ ಸರ್ವರ್ಗಳಾಗಿ ಎಣಿಸಿ ಮತ್ತು ಯಾವುದೇ ಸಂದರ್ಭ ಟೋಕನ್ ಅನ್ನು ಪಡೆಯುವುದಿಲ್ಲ. ಬಳಕೆದಾರರ ಮಾಹಿತಿಯೊಂದಿಗೆ URL, ಬ್ಯಾಕ್ಸ್ಲ್ಯಾಶ್ ಅಥವಾ ವೈಟ್ಸ್ಪೇಸ್ ಎಂದಿಗೂ ಹೊಂದಿಕೆಯಾಗುವುದಿಲ್ಲ, ಏಕೆಂದರೆ ಇತರ URL ಪಾರ್ಸರ್ಗಳು (ಪೈಥಾನ್ನ `urllib` ಮತ್ತು `httpx`, ಉದಾಹರಣೆಗೆ) ಅದರಿಂದ ಬೇರೆ ಹೋಸ್ಟ್ ಅನ್ನು ಓದಬಹುದು. ವಿನಂತಿಗಳಿಗಾಗಿ CLI ಸ್ವತಃ ಕಳುಹಿಸುತ್ತದೆ, ಆ ಚೆಕ್ ಸ್ಕೀಮ್ ಮತ್ತು ಅಧಿಕಾರವನ್ನು ಮಾತ್ರ ಒಳಗೊಳ್ಳುತ್ತದೆ, ಆದ್ದರಿಂದ ಪಥ ಅಥವಾ ಪ್ರಶ್ನೆಯಲ್ಲಿ ಜಾಗವನ್ನು ಹೊಂದಿರುವ ಐಡಿ ಟೋಕನ್ ಅನ್ನು ಇರಿಸುತ್ತದೆ.
