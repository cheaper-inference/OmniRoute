ಹಂಚಿದ ಕಾರ್ಯಗತಗೊಳಿಸಬಹುದಾದ ಮ್ಯಾನಿಫೆಸ್ಟ್, ನಿರ್ಬಂಧಿತ ಮಕ್ಕಳ ಪರಿಸರಗಳು ಮತ್ತು ನಿರಂತರ Gemini ಸೆಟಪ್ಗಾಗಿ, [CLI ಉಡಾವಣಾ ಒಪ್ಪಂದಗಳನ್ನು](./CLI-LAUNCH-CONTRACTS.md) ನೋಡಿ.

OmniRoute ships a family of `setup-*` commands that configure a coding CLI (Codex, Claude Code, OpenCode, Cline, …) to use OmniRoute as its backend — so the tool talks to **one** endpoint and OmniRoute routes to the right provider with auto-fallback. Setup commands use your active local or remote OmniRoute context and configure the tool on **your** machine. Catalog-based recipes fetch models from the server; single-model recipes accept `--model` or prompt for a model ID. The API key is referenced by an environment variable wherever the tool supports it. Commands that persist a tool-local environment file are noted below.

ಕ್ಯಾಟಲಾಗ್ ಮತ್ತು ಯಾಂತ್ರೀಕೃತಗೊಂಡ ಆಜ್ಞೆಗಳು ವಿವಿಧ ಸಾಧನಗಳ ಸೆಟ್ಗಳನ್ನು ಒಳಗೊಂಡಿವೆ:

| ಮೇಲ್ಮೈ                         | ಎಣಿಸಿ | ಇದರ ಅರ್ಥವೇನು                                                                        |
| ------------------------------ | ----- | ----------------------------------------------------------------------------------- |
| ಟೂಲ್ ಕ್ಯಾಟಲಾಗ್                 | 39    | ಹಸ್ತಚಾಲಿತ ಮತ್ತು IDE ಸಂಯೋಜನೆಗಳನ್ನು ಒಳಗೊಂಡಂತೆ ದಾಖಲಿತ ಕೋಡಿಂಗ್ ಪರಿಕರಗಳು ಮತ್ತು ಏಜೆಂಟ್ಗಳು |
| `omniroute run <target>`       | 8     | ಗುರಿಯ ಅಂತಿಮ ಬಿಂದು, ರುಜುವಾತುಗಳು ಮತ್ತು ಮಾದರಿಯನ್ನು ಪೂರೈಸುವ ಅಡಾಪ್ಟರುಗಳನ್ನು ಪ್ರಾರಂಭಿಸಿ   |
| `omniroute configure <target>` | 12    | `setup-*` ಆಜ್ಞೆಗಳಿಂದ ಬೆಂಬಲಿತವಾದ ಸಂವಾದಾತ್ಮಕ ಕಾನ್ಫಿಗರೇಶನ್ ಪಾಕವಿಧಾನಗಳು                 |
| `setup-*` ಆಜ್ಞೆಗಳು             | 16    | guided/manual ಎಡಿಟರ್ ಸೆಟಪ್ ಸೇರಿದಂತೆ ನೋಂದಾಯಿತ ಸೆಟಪ್ ಆಜ್ಞೆಗಳು                         |

ಎಣಿಕೆಗಳು 2026-11-17 ರಂದು [ಟೂಲ್ ಮ್ಯಾನಿಫೆಸ್ಟ್](../../config/cli-tools-manifest.json) ಮತ್ತು [ಕಮಾಂಡ್ ರಿಜಿಸ್ಟ್ರಿಯನ್ನು](../../bin/cli/commands/registry.mjs) ಪ್ರತಿಬಿಂಬಿಸುತ್ತವೆ. ಕ್ಯಾಟಲಾಗ್ ನಮೂದು ಲಾಂಚ್ ಅಡಾಪ್ಟರ್ ಅನ್ನು ಸೂಚಿಸುವುದಿಲ್ಲ. ಪೂರ್ಣ ದಾಸ್ತಾನುಗಳಿಗಾಗಿ [CLI ಟೂಲ್ ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು](../reference/CLI-TOOLS.md) ನೋಡಿ.

ಜೆನೆರಿಕ್ ಲಾಂಚರ್ — `omniroute run <target>` — ಸಹ ಇದೆ, ಅದು `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen`, `gemini` ಅಥವಾ `whycodes` ಅನ್ನು ಯಾವುದೇ ಸಂರಚನೆಯನ್ನು ಬರೆಯದೆಯೇ ಸರಿಯಾದ env ಇಂಜೆಕ್ಟ್ನೊಂದಿಗೆ ಹುಟ್ಟುಹಾಕುತ್ತದೆ. ಗುರಿಗಳು ಮತ್ತು ಅವುಗಳ ಅಲಿಯಾಸ್ಗಳು ಕ್ಯಾನೊನಿಕಲ್ ಮ್ಯಾನಿಫೆಸ್ಟ್ `bin/cli/cli-manifest.mjs` (`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`, `open-code`, `qwen-code`, `gemini-cli`, `why-codes|why`) ನಿಂದ ಬರುತ್ತವೆ ಮತ್ತು `omniroute completion` ಅದೇ ಮ್ಯಾನಿಫೆಸ್ಟ್-ಪಡೆದ ಗುರಿ ಪದಗಳನ್ನು ನೀಡುತ್ತದೆ. `omniroute launch <tool>` ಪ್ರತಿ ಲಾಂಚ್ ಸೆಷನ್ ಟೋಕನ್ ಮತ್ತು ನೀವು ಸಂಪರ್ಕಪಡಿಸಿದ ಪೂರೈಕೆದಾರರಿಂದ ನಿರ್ಮಿಸಲಾದ ಮಾದರಿ ಪಟ್ಟಿಯೊಂದಿಗೆ ಬೆಂಬಲಿತ ಕೋಡಿಂಗ್ ಟೂಲ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸುತ್ತದೆ ಮತ್ತು ಯಾವುದೂ ರನ್ ಆಗದೇ ಇದ್ದಾಗ ಸ್ಥಳೀಯ ಗೇಟ್ವೇ ಅನ್ನು ಸ್ವಯಂ-ಪ್ರಾರಂಭಿಸುತ್ತದೆ ( [LAUNCH.md](./LAUNCH.md) ನೋಡಿ). ಲೆಗಸಿ ಪರ್-ಟೂಲ್ ಲಾಂಚರ್ಗಳು — `omniroute launch` ಟೂಲ್ ಹೆಸರಿಲ್ಲದೆ (Claude ಕೋಡ್) ಮತ್ತು `omniroute launch-codex` (Codex) — ಲಭ್ಯವಿವೆ.

ಅದೇ local/remote ಸಂದರ್ಭದಿಂದ ಒದಗಿಸುವವರ ಆನ್ಬೋರ್ಡಿಂಗ್ ಲಭ್ಯವಿದೆ. ಕೆಳಗಿನ API-ಮೊದಲ ಆಜ್ಞೆಗಳು ನಿರ್ವಹಣಾ ದೃಢೀಕರಣವನ್ನು ಒದಗಿಸುವವರ ರುಜುವಾತುಗಳಿಂದ ಪ್ರತ್ಯೇಕವಾಗಿರಿಸುತ್ತದೆ ಮತ್ತು ರಚನಾತ್ಮಕ ಔಟ್ಪುಟ್ನಲ್ಲಿ ರುಜುವಾತುಗಳನ್ನು ಎಂದಿಗೂ ಮುದ್ರಿಸುವುದಿಲ್ಲ:

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

ಸ್ಕ್ರಿಪ್ಟ್ಗಳಿಗಾಗಿ, `--credential-stdin` ಅಥವಾ `--credential-env` ಆದ್ಯತೆ ನೀಡಿ; ನಿಯಂತ್ರಿತ ಸ್ಥಳೀಯ ಬಳಕೆಗಾಗಿ `--credential` ಉಳಿಸಿಕೊಳ್ಳಲಾಗಿದೆ. `providers remove` ಸಂವಾದಾತ್ಮಕವಲ್ಲದ ಟರ್ಮಿನಲ್ನಲ್ಲಿ `--yes` ಅಗತ್ಯವಿದೆ, ಮತ್ತು ಎಲ್ಲಾ ಐದು ಆಜ್ಞೆಗಳು ಸಕ್ರಿಯ ಸಂದರ್ಭ ಅಥವಾ ಜಾಗತಿಕ `--base-url`/`--api-key` ಆಯ್ಕೆಗಳನ್ನು ಗೌರವಿಸುತ್ತವೆ.

ಪೂರೈಕೆದಾರ ಆಯ್ಕೆದಾರರು ಅಸ್ಪಷ್ಟ ID ಪೂರ್ವಪ್ರತ್ಯಯಗಳು, ಹೆಸರುಗಳು ಅಥವಾ ಪೂರೈಕೆದಾರರ ಹೆಸರುಗಳನ್ನು ತಿರಸ್ಕರಿಸುತ್ತಾರೆ; ಹಲವಾರು ಸಂಪರ್ಕಗಳು ಹೊಂದಿಕೆಯಾದಾಗ ಪೂರ್ಣ ಸಂಪರ್ಕ ID ಅನ್ನು ಬಳಸಿ. ಕಮಾಂಡ್ಗಳನ್ನು ರಚಿಸಿ ಮತ್ತು ಎಡಿಟ್ ಮಾಡಿ ಉಳಿಸಿದ ಸಂಪರ್ಕವನ್ನು ಮತ್ತೆ ಓದುತ್ತದೆ ಮತ್ತು ತೆಗೆದುಹಾಕುವಿಕೆಯು ಅದನ್ನು ಇನ್ನು ಮುಂದೆ ಓದಲಾಗುವುದಿಲ್ಲ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ. ಆಮದು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ provider/name ಜೋಡಿಯನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ. ಆಮದು ಮಾಡಲಾದ ನಮೂದುಗಳು CLI ಗೆ ಒದಗಿಸಲಾದ ನಿರ್ವಹಣೆಯ ಅಂತ್ಯಬಿಂದು, ಸಂದರ್ಭ ಅಥವಾ ನಿರ್ವಹಣೆಯ ರುಜುವಾತುಗಳನ್ನು ಅತಿಕ್ರಮಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ.

## ಮಾಸ್ಟರ್ ಟೇಬಲ್

ಪ್ರತಿಯೊಂದು ಆಜ್ಞೆಯು ಗೌರವಿಸುತ್ತದೆ** ಸಕ್ರಿಯ ಸಂದರ್ಭ** ( `omniroute connect` ನೊಂದಿಗೆ ಹೊಂದಿಸಿ, [ರಿಮೋಟ್ ಮೋಡ್](./REMOTE-MODE.md) ನೋಡಿ) ಅಥವಾ ಸ್ಪಷ್ಟ `--remote <url> --api-key <key>` ಫ್ಲ್ಯಾಗ್ಗಳು. ಕೆಳಗಿನ "ಲೋಕಲ್ ವರ್ಸಸ್ ರಿಮೋಟ್" ಎಂದರೆ: ಯಾವುದೇ ಫ್ಲ್ಯಾಗ್ಗಳಿಲ್ಲದೆ ಅದು `http://localhost:20128` ಗುರಿಪಡಿಸುತ್ತದೆ ; `--remote` (ಅಥವಾ ಸಕ್ರಿಯ ದೂರಸ್ಥ ಸಂದರ್ಭ) ನೊಂದಿಗೆ ಇದು ಆ ಸರ್ವರ್ ಅನ್ನು ಬ್ಯಾಕೆಂಡ್ ಆಗಿ ಕಾನ್ಫಿಗರ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಸ್ಥಳೀಯವಾಗಿ ಕಾನ್ಫಿಗರ್ ಅನ್ನು ಬರೆಯುತ್ತದೆ. ಕ್ಯಾಟಲಾಗ್-ಆಧಾರಿತ ಪಾಕವಿಧಾನಗಳು ಆ ಸರ್ವರ್ನಿಂದ ಮಾದರಿಗಳನ್ನು ಸಹ ಪಡೆಯುತ್ತವೆ.

| ಆಜ್ಞೆ                      | ಉಪಕರಣ                          | ಅದು ಏನು ಬರೆಯುತ್ತದೆ                                                                                                                                                                       | ಪ್ರಮುಖ ಧ್ವಜಗಳು                                                                                                                             | ಸ್ಥಳೀಯ vs ರಿಮೋಟ್ |
| -------------------------- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------- |

ಧ್ವಜಗಳ ಮೇಲಿನ ಟಿಪ್ಪಣಿಗಳು (ಕಮಾಂಡ್ ಮೂಲದಲ್ಲಿ ಪರಿಶೀಲಿಸಲಾಗಿದೆ):

- `--remote <url>` — ರಿಮೋಟ್ OmniRoute ಅನ್ನು ಬಳಸುತ್ತದೆ ( `--port` ಮತ್ತು ಸಕ್ರಿಯ ಸಂದರ್ಭವನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತದೆ). `--api-key <key>` ಆ ಸರ್ವರ್ಗೆ ರುಜುವಾತುಗಳನ್ನು ಪೂರೈಸುತ್ತದೆ ( `OMNIROUTE_API_KEY` env var ಗೆ ಡೀಫಾಲ್ಟ್, ಅಥವಾ ಸಕ್ರಿಯ ಸಂದರ್ಭದ ಟೋಕನ್).
- `--only <patterns>` — ಅಲ್ಪವಿರಾಮದಿಂದ ಬೇರ್ಪಡಿಸಿದ ಸಬ್ಸ್ಟ್ರಿಂಗ್ಗಳು; ಹೊಂದಿಕೆಯಾಗುವ ಮಾದರಿ IDs ಮಾತ್ರ ಇರಿಸಿಕೊಳ್ಳಿ (ಉದಾ `--only glm,kimi`). `setup-codex`, `setup-claude`, `setup-opencode`, `setup-continue`, `setup-cursor`, `setup-crush`, `setup-zed` ನಲ್ಲಿ ಲಭ್ಯವಿದೆ.
- `--dry-run` — ಫೈಲ್ಸಿಸ್ಟಮ್ ಅನ್ನು ಮುಟ್ಟದೆ ನಿಖರವಾಗಿ ಏನು ಬರೆಯಲಾಗುವುದು ಎಂಬುದನ್ನು ಮುದ್ರಿಸುತ್ತದೆ. ಪ್ರತಿ `setup-*` ಕಮಾಂಡ್ನಲ್ಲಿ ಲಭ್ಯವಿದೆ** ಹೊರತುಪಡಿಸಿ** `setup-cursor` (ಇದು ಎಂದಿಗೂ ಫೈಲ್ ಅನ್ನು ಬರೆಯುವುದಿಲ್ಲ).
- ಯಾವುದೇ ಮಾದರಿ ಸ್ವಯಂ-ಶೋಧನೆಯನ್ನು ಹೊಂದಿರದ ಪರಿಕರಗಳಿಗೆ`--model <id>` — ಅಗತ್ಯವಿದೆ (ಅಥವಾ ಸಂವಾದಾತ್ಮಕವಾಗಿ ಆಯ್ಕೆಮಾಡಲಾಗಿದೆ): Cline, Kilo, Roo, Goose, Qwen, Gemini, Aider, 5dive, WhyCodes. ಆ ಉಪಕರಣಗಳು ಸಂವಾದಾತ್ಮಕವಲ್ಲದ ರನ್ಗಳಿಗಾಗಿ `--yes` ಸಹ ಸ್ವೀಕರಿಸುತ್ತವೆ (ಅದಕ್ಕೆ ನಂತರ `--model` ಅಗತ್ಯವಿರುತ್ತದೆ). ಡಿಫಾಲ್ಟ್ ಉನ್ನತ ಮಟ್ಟದ ಮಾದರಿಯನ್ನು ಹೊಂದಿಸಲು `setup-opencode` `--model` ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ.
- `omniroute run` ನಲ್ಲಿನ `--model <id>` ಮ್ಯಾನಿಫೆಸ್ಟ್ನ ಪ್ರತಿ-ಟಾರ್ಗೆಟ್ ವೈರಿಂಗ್ (`bin/cli/cli-manifest.mjs`) ಅನ್ನು ಅನುಸರಿಸುತ್ತದೆ:** ಸಹಾಯಕ** `--model openai/<id>` ಪಡೆಯುತ್ತದೆ ಮತ್ತು** ಓಪನ್ಕೋಡ್** `--model omniroute/<id>` (ಐಡಿ ಈಗಾಗಲೇ ಅದನ್ನು ಸಾಗಿಸದಿದ್ದಾಗ ಮಾತ್ರ ಪೂರ್ವಪ್ರತ್ಯಯವನ್ನು ಸೇರಿಸಲಾಗುತ್ತದೆ);** ಕ್ವೆನ್** ಮತ್ತು** ಮಿಥುನ ರಾಶಿ** ಐಡಿಯನ್ನು ಅಕ್ಷರಶಃ ಸ್ವೀಕರಿಸಿ;** ಕ್ಲಾಡ್** `ANTHROPIC_MODEL` ಮೂಲಕ ಪಡೆಯುತ್ತದೆ,** ಹೆಬ್ಬಾತು** `GOOSE_MODEL` ಮೂಲಕ,** ಏಕೆ ಸಂಕೇತಗಳು** `-P omniroute -m <id>` ಮೂಲಕ, ಮತ್ತು** ಕೋಡೆಕ್ಸ್** `-c model_providers.omniroute.*` args ಮೂಲಕ.**Qwen ಎಂಬುದು `--model`-ಅಗತ್ಯವಿರುವ ಏಕೈಕ ರನ್ ಗುರಿಯಾಗಿದೆ** ಇದು ಇಲ್ಲದೆ — `omniroute run qwen` ಸ್ಪಷ್ಟ ದೋಷದೊಂದಿಗೆ `2` ನಿಂದ ನಿರ್ಗಮಿಸುತ್ತದೆ.
- `--port <port>` — ಸ್ಥಳೀಯ OmniRoute ಪೋರ್ಟ್ (ಡೀಫಾಲ್ಟ್ `20128`, `--remote` ಅನ್ನು ಹೊಂದಿಸಿದಾಗ ನಿರ್ಲಕ್ಷಿಸಲಾಗಿದೆ). ಎಲ್ಲಾ `setup-*` ಮತ್ತು ಎರಡೂ ಲಾಂಚರ್ಗಳಲ್ಲಿ ಪ್ರಸ್ತುತಪಡಿಸಿ.
- `omniroute run` ನಿರ್ಗಮನ ಕೋಡ್ಗಳು: ಮಗುವಿನ CLI ನ ಸ್ವಂತ ನಿರ್ಗಮನ ಕೋಡ್ ಅನ್ನು ಮೌಖಿಕವಾಗಿ ಪ್ರಚಾರ ಮಾಡಲಾಗುತ್ತದೆ; `2` = ಅಮಾನ್ಯವಾದ ಆರ್ಗ್ಯುಮೆಂಟ್ಗಳು (ಬೆಂಬಲವಿಲ್ಲದ ಗುರಿ, ಕಾಣೆಯಾದ ಅಗತ್ಯವಿರುವ `--model`, ಕಂಟೈನರ್ ಗಾರ್ಡ್); `127` = ಗುರಿ ಬೈನರಿ `PATH` ನಲ್ಲಿಲ್ಲ; `130`/`143`/`129` ಉಡಾವಣೆಯು `SIGINT`/`SIGTERM`/`SIGHUP` ನಿಂದ ಕೊನೆಗೊಂಡಾಗ; `1` = ಇತರೆ ರನ್ಟೈಮ್ ಲಾಂಚ್ ವೈಫಲ್ಯ.
- ಎರಡು ಲಾಂಚರ್ಗಳು (`launch`, `launch-codex`) `setup-claude` / `setup-codex` ಬರೆದ ಪ್ರೊಫೈಲ್ ಅನ್ನು ಆಯ್ಕೆ ಮಾಡಲು `--profile <name>` ಸ್ವೀಕರಿಸುತ್ತವೆ, ಜೊತೆಗೆ ಆಧಾರವಾಗಿರುವ `claude` / `codex` ಬೈನರಿಗಾಗಿ ಪಾಸ್-ಥ್ರೂ ಆರ್ಗ್ಗಳು.

ಸಂವಾದಾತ್ಮಕ ಪಿಕ್ಕರ್ ಅನ್ನು ಸೆಟಪ್ ರೆಸಿಪಿಗಳ ಮೂಲಕವೂ ಹಂಚಿಕೊಳ್ಳಲಾಗಿದೆ:

```bash
# Pick from the active local or remote model catalog and configure the target.
omniroute configure claude
omniroute configure opencode --provider glm
omniroute configure qwen --model qwen/qwen3.8-max-preview --yes
omniroute configure gemini
omniroute configure whycodes
```

`configure` ಪ್ರಸ್ತುತ `codex`, `claude`, `opencode`, `qwen`, `gemini`, `aider`, `goose`, `cline`, `continue`, `kilo`, `5dive` ಮತ್ತು `whycodes` ಗಾಗಿ ಪರೀಕ್ಷಿತ ಪಾಕವಿಧಾನಗಳನ್ನು ಪ್ರತಿನಿಧಿಸುತ್ತದೆ. IDE-ಮಾತ್ರ, MITM, ಮತ್ತು ಮಾರ್ಗದರ್ಶಿ-ಮಾತ್ರ ಕ್ಯಾಟಲಾಗ್ ನಮೂದುಗಳು ಸ್ಪಷ್ಟವಾದ `setup-*`/ ಹಸ್ತಚಾಲಿತ ಹರಿವುಗಳಾಗಿ ಉಳಿದಿವೆ ಮತ್ತು ಅವುಗಳನ್ನು ಪ್ರಾರಂಭಿಸಬಹುದಾದ ಗುರಿಗಳಾಗಿ ಪ್ರಸ್ತುತಪಡಿಸಲಾಗಿಲ್ಲ.

> `setup-opencode` ಆಗಿದೆ** ಹಗುರವಾದ ತೆರೆದ-ಹೊಂದಾಣಿಕೆ** OpenCode ಏಕೀಕರಣ. `@omniroute/opencode-plugin` ಸ್ಥಾಪಿಸುವ ಉತ್ಕೃಷ್ಟ ಪ್ಲಗಿನ್ ಏಕೀಕರಣ — `omniroute setup opencode` — ಸಹ ಇದೆ. ಅವು ವಿಭಿನ್ನ ಆಜ್ಞೆಗಳು; ದಾಖಲೆಗಳ ಮೇಲಿನ ಕೋಷ್ಟಕವು `setup-opencode`.
>
> ಪ್ಲಗಿನ್ ಎರಡು ಪ್ಯಾಕೇಜುಗಳಲ್ಲಿ ಬರುತ್ತದೆ, ಪ್ರತಿ OpenCode ಮೇಜರ್ಗೆ ಒಂದು, ಏಕೆಂದರೆ ಎರಡು ಲೋಡರ್ಗಳು ವಿಭಿನ್ನ ಪ್ರವೇಶ ಬಿಂದುಗಳನ್ನು ನಿರೀಕ್ಷಿಸುತ್ತವೆ: OpenCode v1 ಗಾಗಿ `@omniroute/opencode-plugin` ಮತ್ತು OpenCode v2 ಗಾಗಿ `@omniroute/opencode-plugin-v2`. v2 ಪ್ಯಾಕೇಜ್ ಹೊಸದು (`0.1.0`) ಮತ್ತು ಹೋಸ್ಟ್ ಒಪ್ಪಂದವನ್ನು ಅನುಸರಿಸುತ್ತದೆ, ಅದು ಇನ್ನೂ ಚಲಿಸುತ್ತಿದೆ, ಆದ್ದರಿಂದ ಇದು ಆಕಾರ OpenCode ಬೀಜಗಳನ್ನು ಕ್ಯಾಟಲಾಗ್ ಡ್ರಾಫ್ಟ್ನಲ್ಲಿ ಒಂದನ್ನು ಊಹಿಸುವ ಬದಲು ಓದುತ್ತದೆ. `opencode.json` ಗೆ `plugins` ನಮೂದನ್ನು ಸೇರಿಸುವ ಮೂಲಕ ಅದನ್ನು ಸ್ಥಾಪಿಸಿ; `omniroute setup opencode` ಇನ್ನೂ v1 ಪ್ಯಾಕೇಜ್ ಅನ್ನು ಸ್ಥಾಪಿಸುತ್ತದೆ. ಆಯ್ಕೆಗಳು ಮತ್ತು ರುಜುವಾತು ಲುಕಪ್ ಆದೇಶವು ಪ್ಯಾಕೇಜ್ README ನಲ್ಲಿದೆ.

## ಸ್ಥಳೀಯ ಬಳಕೆ

OmniRoute ಅನ್ನು `localhost:20128` ನಲ್ಲಿ ಚಾಲನೆಯಲ್ಲಿಟ್ಟುಕೊಂಡು, ನಿಮ್ಮ ಉಪಕರಣಕ್ಕಾಗಿ ಸೆಟಪ್ ಕಮಾಂಡ್ ಅನ್ನು
ಚಲಾಯಿಸಿ. ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ಸ್ಥಳೀಯ ಸರ್ವರ್ನಿಂದ ಪಡೆಯಲಾಗುತ್ತದೆ.

```bash
# Codex: ಹೊಂದಿಕೆಯಾಗುವ ಪ್ರತಿ ಮಾಡೆಲ್ಗೆ ಒಂದು ಪ್ರೊಫೈಲ್ ಅನ್ನು ~/.codex/ ಒಳಗೆ ಬರೆಯಿರಿ
omniroute setup-codex
codex --profile glm52            # ರಚಿಸಲಾದ ಪ್ರೊಫೈಲ್ ಬಳಸಿ

# Claude Code: ಪ್ರತಿ ಮಾಡೆಲ್ಗೆ ಪ್ರೊಫೈಲ್ಗಳನ್ನು ಬರೆದು, ನಂತರ ಒಂದನ್ನು ಪ್ರಾರಂಭಿಸಿ
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode: ಎಲ್ಲಾ ಕ್ಯಾಟಲಾಗ್ ಮಾಡೆಲ್ಗಳೊಂದಿಗೆ openai-ಹೊಂದಾಣಿಕೆಯ ಪ್ರೊವೈಡರ್ ಅನ್ನು ಬರೆಯಿರಿ
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # {env:OMNIROUTE_API_KEY} ಮೂಲಕ ಉಲ್ಲೇಖಿಸಲಾಗುತ್ತದೆ, ಡಿಸ್ಕ್ನಲ್ಲಿ ಎಂದಿಗೂ ಅಲ್ಲ
opencode -m omniroute/glm/glm-5.2 "..."

# ಸ್ವಯಂ-ಪತ್ತೆ ಇಲ್ಲದ ಉಪಕರಣಗಳಿಗೆ ಸ್ಪಷ್ಟವಾದ ಮಾಡೆಲ್ ಅಗತ್ಯ:
omniroute setup-aider --model glm/glm-5.2
omniroute setup-qwen --model qwen/qwen3.8-max-preview

# ಏನನ್ನೂ ಬರೆಯದೆ ಪೂರ್ವವೀಕ್ಷಿಸಿ:
omniroute setup-continue --dry-run
```

ಯಾವುದೇ ಕಾನ್ಫಿಗ್ ಬರೆಯದೆಯೇ ಪ್ರಾರಂಭಿಸಿ (env-ಇಂಜೆಕ್ಷನ್ ಮಾತ್ರ):

```bash
omniroute launch                 # Claude Code → ಸ್ಥಳೀಯ OmniRoute
omniroute launch-codex           # Codex CLI → ಸ್ಥಳೀಯ OmniRoute
omniroute launch-codex --profile glm52
omniroute run claude --model openai/gpt-5.4
omniroute run codex --model openai/gpt-5.4 --dry-run --json
omniroute run aider --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# ಸ್ಪಷ್ಟವಾದ ಕಮಾಂಡ್ ಪಥ: -- ನಂತರ ಬರುವುದೆಲ್ಲವನ್ನೂ ಹಾಗೆಯೇ ರವಾನಿಸಿ
omniroute run claude -- --print-system-prompt "review this diff"
```

## ದೂರಸ್ಥ ಬಳಕೆ

ಯಾವುದೇ ಸೆಟಪ್ ಕಮಾಂಡ್ ಅನ್ನು `--remote` + `--api-key` ಬಳಸಿ ದೂರಸ್ಥ OmniRoute ಕಡೆಗೆ ನಿರ್ದೇಶಿಸಿ.
ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ದೂರಸ್ಥ ಸರ್ವರ್ನಿಂದ ಪಡೆಯಲಾಗುತ್ತದೆ; ಕಾನ್ಫಿಗ್ ಅನ್ನು ನಿಮ್ಮ ಸ್ಥಳೀಯ ಯಂತ್ರದಲ್ಲಿ ಬರೆಯಲಾಗುತ್ತದೆ.

```bash
# ದೂರಸ್ಥ VPS ವಿರುದ್ಧ OpenCode, glm/kimi ಮಾಡೆಲ್ಗಳನ್ನು ಮಾತ್ರ ಉಳಿಸಿ
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx \
  --only glm,kimi
opencode -m omniroute/glm/glm-5.2 "..."   # ಮೊದಲು OMNIROUTE_API_KEY ಅನ್ನು export ಮಾಡಿ

# ದೂರಸ್ಥ ಕ್ಯಾಟಲಾಗ್ನಿಂದ Codex ಪ್ರೊಫೈಲ್ಗಳು
omniroute setup-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# ದೂರಸ್ಥ ಸರ್ವರ್ ವಿರುದ್ಧ ನೇರವಾಗಿ CLI ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

ಪ್ರತಿ ಬಾರಿ `--remote`/`--api-key` ರವಾನಿಸುವ ಬದಲು, ಒಮ್ಮೆ ಲಾಗಿನ್ ಮಾಡಿ ಮತ್ತು
**ಸಕ್ರಿಯ ಸಂದರ್ಭ** ಅವುಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಒದಗಿಸಲು ಬಿಡಿ:

```bash
omniroute connect 192.168.0.15        # ವ್ಯಾಪ್ತಿ-ನಿರ್ಬಂಧಿತ ಟೋಕನ್ ರಚಿಸಿ, ಸಂದರ್ಭವನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ
omniroute setup-codex                 # ← ಈಗ ದೂರಸ್ಥ ಕ್ಯಾಟಲಾಗ್ ಬಳಸುತ್ತದೆ
omniroute setup-opencode              # ← ಇದೇ ರೀತಿ
omniroute launch                      # ← ದೂರಸ್ಥ ಸರ್ವರ್ ವಿರುದ್ಧ Claude Code
```

ಸಂದರ್ಭಗಳು, ವ್ಯಾಪ್ತಿಗಳು ಮತ್ತು ಟೋಕನ್ ನಿರ್ವಹಣೆಗಾಗಿ [ದೂರಸ್ಥ ಮೋಡ್](./REMOTE-MODE.md) ನೋಡಿ.

## 5 ಡೈವ್ ಏಜೆಂಟ್ ಫ್ಲೀಟ್ಗಳು

[5dive](https://5dive.ai) ದೀರ್ಘಾವಧಿಯ ಕೋಡಿಂಗ್ ಏಜೆಂಟ್ಗಳ ಸಮೂಹವನ್ನು ನಡೆಸುತ್ತದೆ, ಪ್ರತಿಯೊಂದೂ ತನ್ನದೇ ಆದ Unix ಬಳಕೆದಾರರ ಅಡಿಯಲ್ಲಿ systemd ಘಟಕವಾಗಿದೆ. ಇದು ಕೋಡಿಂಗ್ CLI ಅಲ್ಲ, ಆದ್ದರಿಂದ `omniroute run` ಗೆ — `5dive` ಅನ್ನು ಪ್ರಾರಂಭಿಸಲು ಏನೂ ಇಲ್ಲ** ಕಾನ್ಫಿಗರ್-ಮಾತ್ರ** ಗುರಿ.

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

ಎರಡೂ ರೂಪಗಳು ಒಂದು 5 ಡೈವ್ ಅನ್ನು ಬರೆಯುತ್ತವೆ** ದೃಢೀಕರಣ ಪ್ರೊಫೈಲ್** , ಮತ್ತು ಆ ಪ್ರೊಫೈಲ್ಗೆ ಬದ್ಧವಾಗಿರುವ ಪ್ರತಿಯೊಂದು `claude` ಸ್ಥಾನವು ನಂತರ OmniRoute ನೊಂದಿಗೆ ಮಾತನಾಡುತ್ತದೆ. ಈ ಗುರಿಗೆ ಮೂರು ವಿಷಯಗಳು ನಿರ್ದಿಷ್ಟವಾಗಿವೆ:

- **ಇದು ಫ್ಲೀಟ್ ಹೋಸ್ಟ್ನಲ್ಲಿ ರೂಟ್ ಆಗಿ ಚಲಿಸುತ್ತದೆ.** 5dive ನ ಕ್ರಿಯಾಪದಗಳು ಸ್ಥಳೀಯ systemd ಘಟಕಗಳು ಮತ್ತು ರೂಟ್-ಮಾಲೀಕತ್ವದ ರಾಜ್ಯ ಡಿರ್ ಮೇಲೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ; ರಿಮೋಟ್ ಮೋಡ್ ಇಲ್ಲ. ಪಾಕವಿಧಾನವು ಈಗಾಗಲೇ ರೂಟ್ ಆಗಿರದಿದ್ದಾಗ `sudo` ಮೂಲಕ ಮರು-ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ (`--no-sudo` ಅದನ್ನು ಆಫ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಬದಲಿಗೆ ಆಜ್ಞೆಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ).
- **ಲೂಪ್ಬ್ಯಾಕ್ ಆಗದ ಹೊರತು ಅಂತಿಮ ಬಿಂದುವು `https://` ಆಗಿರಬೇಕು.** ಏಜೆಂಟ್ನ API ಕೀ ಪ್ರತಿ ವಿನಂತಿಯ ಮೇಲೆ URL ಅನ್ನು ಸವಾರಿ ಮಾಡುತ್ತದೆ ಮತ್ತು 5dive ಸರಳ ಪಠ್ಯ ಆಫ್-ಬಾಕ್ಸ್ ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ನಿರಾಕರಿಸುತ್ತದೆ. ಖಾಸಗಿ LAN ವಿಳಾಸವು ಇದಕ್ಕೆ ಹೊರತಾಗಿಲ್ಲ.
- **ಪ್ರತಿ ಸೀಟಿನ ಸ್ವಂತ ಮಾದರಿಯ ಪಿನ್ ಪ್ರೊಫೈಲ್ ಅನ್ನು ಮೀರಿಸುತ್ತದೆ.** ಪ್ರೊಫೈಲ್ `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` ಒಯ್ಯುತ್ತದೆ, ಆದರೆ ಸ್ಟಾಕ್ ಮಾಡೆಲ್ ಐಡಿಗೆ ಇನ್ನೂ ಪಿನ್ ಮಾಡಲಾದ ಆಸನವು _"ಆಯ್ದ ಮಾಡೆಲ್ನಲ್ಲಿ ಸಮಸ್ಯೆ ಇದೆ"_ ನೊಂದಿಗೆ ಅದರ ಮೊದಲ ತಿರುವು ವಿಫಲಗೊಳ್ಳುತ್ತದೆ. ಆಸನಗಳನ್ನು ಪಿನ್ ಮಾಡಲು `--agent <name>` (ಪುನರಾವರ್ತಿಸಬಹುದಾದ) ಪಾಸ್ ಮಾಡಿ; ನೀವು ಮಾಡದಿದ್ದಾಗ ಪಾಕವಿಧಾನವು ಆಜ್ಞೆಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ.

API ಕೀಯನ್ನು 5 ಡೈವ್ಗೆ ಹಸ್ತಾಂತರಿಸಲಾಗಿದೆ** stdin** (`--api-key=-`), ಆದ್ದರಿಂದ ಇದು ಎಂದಿಗೂ `ps` ಔಟ್ಪುಟ್ನಲ್ಲಿ ಕಾಣಿಸುವುದಿಲ್ಲ.

OmniRoute ನಲ್ಲಿ ಪ್ರೊಫೈಲ್ ಅನ್ನು ತೋರಿಸಲಾಗುತ್ತಿದೆ** ಸಂಯೋಜನೆ** ಒಂದೇ ಮಾದರಿಗಿಂತ ಹೆಚ್ಚಾಗಿ ಫ್ಲೀಟ್ ಪ್ರೊವೈಡರ್ ವೈಫಲ್ಯವನ್ನು ಪಡೆಯುತ್ತದೆ: [#11578](https://github.com/cheaper-inference/OmniRoute/issues/11578) ನಲ್ಲಿ ರೆಕಾರ್ಡ್ ಮಾಡಲಾದ ರನ್ನಲ್ಲಿ ಪ್ರಾಥಮಿಕ ಎಂಡ್ಪಾಯಿಂಟ್ ಹಾರ್ಡ್-ಡೌನ್ ಮಿಡ್-ಟರ್ನ್ಗೆ ಹೋದಾಗ, ಏಜೆಂಟ್ ತನ್ನ ಉಳಿದ ಹಂತಗಳನ್ನು ಫಾಲ್ಬ್ಯಾಕ್ನಲ್ಲಿ ಪೂರ್ಣಗೊಳಿಸಿದನು ಮತ್ತು ಎಂದಿಗೂ ಸ್ಥಗಿತಗೊಳ್ಳಲಿಲ್ಲ.

## ನವೀಕರಣದ ವೇಳೆ ಸ್ಥಳೀಯ ಅವಲಂಬನೆಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳುವುದು: `--include=optional`

ನೀವು `omniroute update` ಮೂಲಕ ನವೀಕರಿಸಿದಾಗ (ದೃಢೀಕರಿಸಿದ ನಂತರ ಅಥವಾ `--apply` ಜೊತೆಗೆ),
OmniRoute ಅನುಸ್ಥಾಪನೆಯನ್ನು ಅಂತರ್ನಿರ್ಮಿತ `--include=optional` ಜೊತೆಗೆ ಚಾಲನೆ ಮಾಡುತ್ತದೆ:

```bash
npm install -g omniroute@latest --include=optional
```

ಇದು `omniroute update` ಗೆ ನೀವು ರವಾನಿಸುವ ಫ್ಲ್ಯಾಗ್ **ಅಲ್ಲ** — ನವೀಕರಣಕಾರವು ಇದನ್ನು
ಯಾವಾಗಲೂ ಅನ್ವಯಿಸುತ್ತದೆ. ನಿಮ್ಮ npm ಸಂರಚನೆಯಲ್ಲಿ `omit=optional` ಹೊಂದಿಸಿದ್ದರೂ
`optionalDependencies` (`better-sqlite3`, `keytar`, `tls-client`, LLMLingua SLM
ಸ್ಟ್ಯಾಕ್) ನವೀಕರಣದ ನಂತರವೂ ಉಳಿಯುವುದನ್ನು ಇದು ಖಚಿತಪಡಿಸುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ ಸ್ಥಳೀಯ SQLite
ಡ್ರೈವರ್ ಮತ್ತು OS-ಕೀರಿಂಗ್ ಬೈಂಡಿಂಗ್ ಯಾವುದೇ ಸೂಚನೆಯಿಲ್ಲದೆ ತೆಗೆದುಹಾಕಲ್ಪಡುತ್ತವೆ. ಅನ್ವಯಿಸದೆ
ನಿಖರವಾದ ಆದೇಶವನ್ನು ಪೂರ್ವವೀಕ್ಷಿಸಲು:

```bash
omniroute update --dry-run
# [ಪ್ರಾಯೋಗಿಕ ಚಾಲನೆ] ಚಾಲನೆಯಾಗಲಿರುವುದು: npm install -g omniroute@latest --include=optional
```

ಇತರ `omniroute update` ಫ್ಲ್ಯಾಗ್ಗಳು (ಮೂಲದಲ್ಲಿ ಪರಿಶೀಲಿಸಲಾಗಿದೆ): `--check` (ಹಳೆಯದಾಗಿದ್ದರೆ
ನಿರ್ಗಮನ 1), `--apply` (ಕೇಳದೆ ಅನುಸ್ಥಾಪಿಸಿ), `--changelog`, `--no-backup`,
`--yes`.

## `omniroute run gemini` ಮೂಲಕ Google Gemini CLI

`@google/gemini-cli` 0.50.0 ವಿರುದ್ಧ ಒಪ್ಪಂದವನ್ನು ಪರಿಶೀಲಿಸಲಾಗಿದೆ: CLI,
`GOOGLE_GEMINI_BASE_URL` ಅನ್ನು ಗೌರವಿಸುತ್ತದೆ ಮತ್ತು ಅದರ ವಿರುದ್ಧ
`POST /v1beta/models/<model>:generateContent` (ಹಾಗೂ
`:streamGenerateContent?alt=sse`) ವಿನಂತಿಗಳನ್ನು ಕಳುಹಿಸುತ್ತದೆ — ಇದು ನಿಖರವಾಗಿ
OmniRoute ನ ಸ್ಥಳೀಯ Gemini ಮೇಲ್ಮೈ (`/v1beta`) ಆಗಿದೆ. `omniroute run gemini` ಅದನ್ನು
ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಜೋಡಿಸುತ್ತದೆ:

- `GOOGLE_GEMINI_BASE_URL` → ಸಕ್ರಿಯ OmniRoute ಮೂಲ URL (ಮೂಲ, `/v1` ಇಲ್ಲ);
- `GEMINI_API_KEY` → ಪರಿಹರಿಸಲಾದ OmniRoute ರುಜುವಾತು (ಆಯ್ಕೆ/env/ಸಂದರ್ಭ);
- `gemini-api-key` ದೃಢೀಕರಣವನ್ನು ಆಯ್ಕೆಮಾಡುವ `.gemini/settings.json` ಹೊಂದಿರುವ
  **ತಾತ್ಕಾಲಿಕ ಪ್ರತ್ಯೇಕಿತ `GEMINI_CLI_HOME`**, ಇದರಿಂದ ಸಂಗ್ರಹಿತ Google OAuth ಅಧಿವೇಶನವು
  (Code Assist) OmniRoute-ನಿರ್ದೇಶಿತ ಪ್ರಾರಂಭವನ್ನು ಎಂದಿಗೂ ಅತಿಕ್ರಮಿಸುವುದಿಲ್ಲ —
  ನಿರ್ಗಮನದ ನಂತರ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ;
- **env ಸ್ವಚ್ಛತೆ**: ಉಪಪ್ರಕ್ರಿಯೆಯ env ನಿಂದ `GOOGLE_API_KEY`,
  `GOOGLE_GENAI_USE_VERTEXAI` ಮತ್ತು `GOOGLE_GENAI_USE_GCA` ಅನ್ನು ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ
  (ಇವು ದೃಢೀಕರಣವನ್ನು Vertex/Code Assist ಕಡೆಗೆ ಮರುನಿರ್ದೇಶಿಸುತ್ತವೆ), ಮತ್ತು ಹೆಚ್ಚುವರಿ
  ಸುರಕ್ಷತಾ ಪರ್ಯಾಯವಾಗಿ `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key` ಅನ್ನು ಹೊಂದಿಸಲಾಗುತ್ತದೆ
  — ಇತರ `run` ಗುರಿಗಳಿಗೂ ಅವುಗಳದೇ ಸಂಘರ್ಷಕಾರಿ ಚರಗಳಿಗೆ ಇದೇ ರೀತಿಯ ನಿರ್ವಹಣೆ ದೊರೆಯುತ್ತದೆ;
- `--provider`/`--model` ನಿಂದ `--model <id>` ಸೇರಿಸುವಿಕೆ.

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

ಹೆಡ್ಲೆಸ್ ಮೋಡ್ನಲ್ಲಿಯೂ Gemini ಯ ಕಾರ್ಯಸ್ಥಳ-ವಿಶ್ವಾಸ ರಕ್ಷಣೆ ಅನ್ವಯಿಸುತ್ತದೆ — ನೀವೇ
`--skip-trust` ಅನ್ನು ರವಾನಿಸಿ (ಅಥವಾ ಡೈರೆಕ್ಟರಿಯನ್ನು ಸಂವಾದಾತ್ಮಕವಾಗಿ ವಿಶ್ವಾಸಾರ್ಹವೆಂದು
ಗುರುತಿಸಿ); ಪ್ರಾರಂಭಕವು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಅದನ್ನು ಬಿಟ್ಟುಹೋಗುವುದಿಲ್ಲ. ಈ ಪ್ರಾರಂಭಕವು
**ACP ನೋಂದಣಿ** (`src/lib/acp/registry.ts`, `gemini --acp`) ಗಿಂತ ಭಿನ್ನವಾಗಿದೆ;
ಅದು `/dashboard/acp-agents` ಗಾಗಿ ಏಜೆಂಟ್-ಪ್ರೋಟೋಕಾಲ್ ಏಕೀಕರಣವಾಗಿಯೇ ಉಳಿಯುತ್ತದೆ.

## ನೈಜ ಸ್ಮೋಕ್ ಸ್ವೀಪ್ (ಆಪ್ಟ್-ಇನ್)

ನಿರ್ಣಾಯಕ ಲಾಂಚ್-ಪ್ಲಾನ್ ರಿಗ್ರೆಷನ್ ಪರೀಕ್ಷೆಗಳು CIಯಲ್ಲಿ ನಡೆಯುತ್ತವೆ (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`). ನೈಜ OmniRoute ಸರ್ವರ್ನೊಂದಿಗೆ ನೈಜ
ಬೈನರಿಗಳನ್ನು ಪರಿಶೀಲಿಸಲು, ಆಪ್ಟ್-ಇನ್ ಹಾರ್ನೆಸ್
`tests/integration/upstream-cli-smoke.int.test.ts`ನಲ್ಲಿ ಲಭ್ಯವಿದೆ. ಇದು ಎಂದಿಗೂ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ರನ್ ಆಗುವುದಿಲ್ಲ
(`RUN_CLI_SMOKE=1` ಇಲ್ಲದಿದ್ದರೆ ಪ್ರತಿಯೊಂದು ಉಪ-ಪರೀಕ್ಷೆಯನ್ನೂ ಬಿಟ್ಟುಬಿಡುತ್ತದೆ), ರುಜುವಾತಿನ ಮೌಲ್ಯವನ್ನು ಅಲ್ಲದೆ ಅದರ ಪರಿಸರ-ಚರದ
ಹೆಸರನ್ನು ರವಾನಿಸುತ್ತದೆ, ದಾಖಲಿಸಲಾದ ಯಾವುದೇ ಔಟ್ಪುಟ್ನಿಂದ ಕೀಲಿಯ ಮಾದರಿಯ ಸ್ಟ್ರಿಂಗ್ಗಳನ್ನು ಮರೆಮಾಡುತ್ತದೆ,
ಬೈನರಿ ಇನ್ಸ್ಟಾಲ್ ಆಗಿರದ ಗುರಿಗಳನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ ಮತ್ತು ವೈಫಲ್ಯಗಳನ್ನು ಕೇವಲ ಬೂಲಿಯನ್ ಆಗಿ ನೀಡುವ ಬದಲು
auth / upstream / config ಎಂದು ವರ್ಗೀಕರಿಸುತ್ತದೆ:

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

ಐಚ್ಛಿಕ: `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` ಸ್ವೀಪ್ ಅನ್ನು ನಿರ್ದಿಷ್ಟ ಗುರಿಗಳಿಗೆ ಸೀಮಿತಗೊಳಿಸುತ್ತದೆ;
`OMNIROUTE_SMOKE_TIMEOUT_MS` ಪ್ರತಿ ಗುರಿಗೆ ಇರುವ 120s ಕಾಲಾವಧಿ ಮಿತಿಯನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತದೆ.
