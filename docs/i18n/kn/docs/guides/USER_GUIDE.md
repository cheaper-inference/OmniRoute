## 🎯 ಬಳಕೆಯ ಸಂದರ್ಭಗಳು

### ಸಂದರ್ಭ 1: "ನನ್ನ ಬಳಿ Claude Pro ಚಂದಾದಾರಿಕೆ ಇದೆ"

**ಸಮಸ್ಯೆ:** ಕೋಟಾ ಬಳಕೆಯಾಗದೆ ಅವಧಿ ಮುಗಿಯುತ್ತದೆ, ತೀವ್ರ ಕೋಡಿಂಗ್ ಸಮಯದಲ್ಲಿ ದರ ಮಿತಿಗಳು ಎದುರಾಗುತ್ತವೆ

```
ಸಂಯೋಜನೆ: "maximize-claude"
  1. cc/claude-opus-4-7        (ಚಂದಾದಾರಿಕೆಯನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಬಳಸಿ)
  2. glm/glm-4.7               (ಕೋಟಾ ಮುಗಿದಾಗ ಅಗ್ಗದ ಬ್ಯಾಕಪ್)
  3. if/qwen3.8-max-preview       (ತುರ್ತು ಪರಿಸ್ಥಿತಿಗಾಗಿ ಉಚಿತ ಪರ್ಯಾಯ)

ಮಾಸಿಕ ವೆಚ್ಚ: $20 (ಚಂದಾದಾರಿಕೆ) + ~$5 (ಬ್ಯಾಕಪ್) = ಒಟ್ಟು $25
ಇದಕ್ಕೆ ಹೋಲಿಸಿದರೆ, $20 + ಮಿತಿಗಳನ್ನು ತಲುಪುವುದು = ಹತಾಶೆ
```

### ಸಂದರ್ಭ 2: "ನನಗೆ ಶೂನ್ಯ ವೆಚ್ಚ ಬೇಕು"

**ಸಮಸ್ಯೆ:** ಚಂದಾದಾರಿಕೆಗಳನ್ನು ಪಡೆಯಲು ಸಾಧ್ಯವಿಲ್ಲ, ವಿಶ್ವಾಸಾರ್ಹ AI ಕೋಡಿಂಗ್ ಅಗತ್ಯವಿದೆ

```
ಸಂಯೋಜನೆ: "zero-cost"
  1. if/kimi-k2.7-code          (ಉಚಿತ ಪ್ರವೇಶವೆಂದು ಪಟ್ಟಿಮಾಡಲಾಗಿದೆ; ದರ ಮಿತಿಗಳು ಅನ್ವಯಿಸಬಹುದು)
  2. kr/qwen3-coder-next        (ಉಚಿತ Kiro ಪರ್ಯಾಯ)

ಮಾಸಿಕ ವೆಚ್ಚ: $0
ಗುಣಮಟ್ಟ: ನಿಮ್ಮ ಕಾರ್ಯಭಾರಕ್ಕಾಗಿ ಮಾದರಿ, ಮಿತಿಗಳು, ಗೌಪ್ಯತೆ ಮತ್ತು SLA ಅನ್ನು ಪರಿಶೀಲಿಸಿ
```

### ಸಂದರ್ಭ 3: "ನನಗೆ ಯಾವುದೇ ಅಡಚಣೆಗಳಿಲ್ಲದೆ 24/7 ಕೋಡಿಂಗ್ ಬೇಕು"

**ಸಮಸ್ಯೆ:** ಗಡುವುಗಳಿವೆ, ಸೇವೆ ಲಭ್ಯವಿಲ್ಲದ ಸಮಯವನ್ನು ಸಹಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ

```
ಸಂಯೋಜನೆ: "always-on"
  1. cc/claude-opus-4-7        (ಅತ್ಯುತ್ತಮ ಗುಣಮಟ್ಟ)
  2. cx/gpt-5.5                (ಎರಡನೇ ಚಂದಾದಾರಿಕೆ)
```

### ಟ್ರೇ ಮೋಡ್

ಸಿಸ್ಟಮ್ ಟ್ರೇಯಲ್ಲಿ OmniRoute ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ:

```bash
omniroute serve --tray
```

ಸರ್ವರ್ ಮತ್ತು ಟ್ರೇ ಸಿದ್ಧವಾದ ನಂತರ ಕಮಾಂಡ್ ಹಿಂತಿರುಗುತ್ತದೆ.

ಟರ್ಮಿನಲ್ ಇಲ್ಲದೆಯೂ ಸರ್ವರ್ ಕಾರ್ಯನಿರ್ವಹಿಸುವುದನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ.

ಟ್ರೇ ಮೋಡ್ macOS, Windows ಮತ್ತು ಗ್ರಾಫಿಕಲ್ Linux ಸೆಷನ್ಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ. ಟ್ರೇ ಮೋಡ್ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ತೆರೆಯುವುದಿಲ್ಲ.

ಈ ಕ್ರಿಯೆಗಳಿಗಾಗಿ ಟ್ರೇ ಮೆನು ಬಳಸಿ:

- ಡ್ಯಾಶ್ಬೋರ್ಡ್ ತೆರೆಯಿರಿ.
- `/dashboard/logs` ತೆರೆಯಿರಿ.
- ಸ್ವಯಂ-ಪ್ರಾರಂಭವನ್ನು ಬದಲಾಯಿಸಿ.
- OmniRoute ನಿಲ್ಲಿಸಿ.

ಈ ಆಯ್ಕೆಗಳೊಂದಿಗೆ `--tray` ಅನ್ನು ಸಂಯೋಜಿಸಬೇಡಿ:

- `--daemon`
- `--log`
- `--no-recovery`

ಈ ಮೋಡ್ಗಳಿಗೆ ವಿಭಿನ್ನ ಪ್ರಕ್ರಿಯೆ ಮಾಲೀಕತ್ವದ ಅಗತ್ಯವಿದೆ.

ಯಂತ್ರಕ್ಕೆ ಮುಂದಿನ ಬಾರಿ ಲಾಗಿನ್ ಮಾಡಿದಾಗ ಪ್ರಾರಂಭಿಸುವುದನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ:

```bash
omniroute autostart enable
```

macOS, Windows ಮತ್ತು ಗ್ರಾಫಿಕಲ್ Linux ಸೆಷನ್ಗಳಲ್ಲಿ ಸ್ವಯಂ-ಪ್ರಾರಂಭವು ಟ್ರೇ ಮೋಡ್ ಅನ್ನು ಬಳಸುತ್ತದೆ. ಹೆಡ್ಲೆಸ್ Linux ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ systemd ಬಳಕೆದಾರ ಸೇವೆಯನ್ನು ಬಳಸುತ್ತದೆ.

ಲಾಗಿನ್ ಸಮಯದಲ್ಲಿ ಪ್ರಾರಂಭಿಸುವುದನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ:

```bash
omniroute autostart disable
```

### ಅಸ್ಥಾಪಿಸುವುದು

ನಿಮಗೆ ಇನ್ನು OmniRoute ಅಗತ್ಯವಿಲ್ಲದಾಗ, ಸ್ವಚ್ಛವಾಗಿ ತೆಗೆದುಹಾಕಲು ನಾವು ಎರಡು ತ್ವರಿತ ಸ್ಕ್ರಿಪ್ಟ್ಗಳನ್ನು ಒದಗಿಸುತ್ತೇವೆ:

| ಕಮಾಂಡ್                   | ಕ್ರಿಯೆ                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | ಸಿಸ್ಟಮ್ ಆ್ಯಪ್ ಅನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ, ಆದರೆ `~/.omniroute` ನಲ್ಲಿರುವ **ನಿಮ್ಮ DB ಮತ್ತು ಕಾನ್ಫಿಗರೇಶನ್ಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ**. |
| `npm run uninstall:full` | ಆ್ಯಪ್ ಅನ್ನು ತೆಗೆದುಹಾಕುವುದರ ಜೊತೆಗೆ **ಎಲ್ಲಾ ಕಾನ್ಫಿಗರೇಶನ್ಗಳು, ಕೀಗಳು ಮತ್ತು ಡೇಟಾಬೇಸ್ಗಳನ್ನು ಶಾಶ್ವತವಾಗಿ ಅಳಿಸುತ್ತದೆ**.            |

> ಗಮನಿಸಿ: ಈ ಕಮಾಂಡ್ಗಳನ್ನು ಚಲಾಯಿಸಲು, OmniRoute ಪ್ರಾಜೆಕ್ಟ್ ಫೋಲ್ಡರ್ಗೆ ಹೋಗಿ (ನೀವು ಅದನ್ನು ಕ್ಲೋನ್ ಮಾಡಿದ್ದರೆ) ಮತ್ತು ಅವುಗಳನ್ನು ಚಲಾಯಿಸಿ. ಪರ್ಯಾಯವಾಗಿ, ಜಾಗತಿಕವಾಗಿ ಸ್ಥಾಪಿಸಿದ್ದರೆ, ನೀವು ಸರಳವಾಗಿ `npm uninstall -g omniroute` ಅನ್ನು ಚಲಾಯಿಸಬಹುದು.

### Void Linux (xbps-src)

Void Linux ಬಳಕೆದಾರರು `xbps-src` ಕ್ರಾಸ್-ಕಂಪೈಲೇಶನ್ ಫ್ರೇಮ್ವರ್ಕ್ ಬಳಸಿ OmniRoute ಅನ್ನು ನೇಟಿವ್ ಆಗಿ ಪ್ಯಾಕೇಜ್ ಮಾಡಿ ಸ್ಥಾಪಿಸಬಹುದು. ಇದು ಅಗತ್ಯವಿರುವ `better-sqlite3` ನೇಟಿವ್ ಬೈಂಡಿಂಗ್ಗಳೊಂದಿಗೆ Node.js ಸ್ವತಂತ್ರ ಬಿಲ್ಡ್ ಅನ್ನು ಸ್ವಯಂಚಾಲಿತಗೊಳಿಸುತ್ತದೆ.

```bash

export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# node-gyp ಗಾಗಿ ಗುರಿ CPU ಆರ್ಕಿಟೆಕ್ಚರ್ ನಿರ್ಧರಿಸಿ
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) ಎಲ್ಲಾ ಡಿಪೆಂಡೆನ್ಸಿಗಳನ್ನು ಸ್ಥಾಪಿಸಿ – ಸ್ಕ್ರಿಪ್ಟ್ಗಳನ್ನು ಬಿಟ್ಟುಬಿಡಿ
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Next.js ಸ್ವತಂತ್ರ ಬಂಡಲ್ ನಿರ್ಮಿಸಿ
	npm run build

	# 3) ಸ್ಥಿರ ಅಸೆಟ್ಗಳನ್ನು ಸ್ವತಂತ್ರ ಬಂಡಲ್ಗೆ ನಕಲಿಸಿ
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) better-sqlite3 ನೇಟಿವ್ ಬೈಂಡಿಂಗ್ ಕಂಪೈಲ್ ಮಾಡಿ
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) ಕಂಪೈಲ್ ಮಾಡಿದ ಬೈಂಡಿಂಗ್ ಅನ್ನು ಸ್ವತಂತ್ರ ಬಂಡಲ್ನಲ್ಲಿ ಇರಿಸಿ
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) ಆರ್ಕಿಟೆಕ್ಚರ್-ನಿರ್ದಿಷ್ಟ sharp ಬಂಡಲ್ಗಳನ್ನು ತೆಗೆದುಹಾಕಿ
	rm -rf .next/standalone/node_modules/@img

	# 7) Next.js ಸ್ಥಿರ ವಿಶ್ಲೇಷಣೆಯಿಂದ ಬಿಟ್ಟುಹೋಗಿರುವ pino ರನ್ಟೈಮ್ ಡಿಪೆಂಡೆನ್ಸಿಗಳನ್ನು ನಕಲಿಸಿ:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone
```

## 🧩 ಸುಧಾರಿತ ವೈಶಿಷ್ಟ್ಯಗಳು

### ಕಸ್ಟಮ್ ಮಾಡಲ್ಗಳು

ಆ್ಯಪ್ ನವೀಕರಣಕ್ಕಾಗಿ ಕಾಯದೆ ಯಾವುದೇ ಪ್ರೊವೈಡರ್ಗೆ ಯಾವುದೇ ಮಾಡಲ್ ID ಅನ್ನು ಸೇರಿಸಿ:

```bash
# API ಮೂಲಕ
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# ಪಟ್ಟಿ: curl http://localhost:20128/api/provider-models?provider=openai
# ತೆಗೆದುಹಾಕಿ: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

ಅಥವಾ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಬಳಸಿ: **Providers → [Provider] → Custom Models**.

ಟಿಪ್ಪಣಿಗಳು:

- OpenRouter ಮತ್ತು OpenAI/Anthropic-ಹೊಂದಾಣಿಕೆಯ ಪ್ರೊವೈಡರ್ಗಳನ್ನು **Available Models** ನಿಂದ ಮಾತ್ರ ನಿರ್ವಹಿಸಲಾಗುತ್ತದೆ. ಹಸ್ತಚಾಲಿತ ಸೇರ್ಪಡೆ, ಆಮದು ಮತ್ತು ಸ್ವಯಂ-ಸಮನ್ವಯ ಎಲ್ಲವೂ ಒಂದೇ ಲಭ್ಯವಿರುವ-ಮಾಡಲ್ ಪಟ್ಟಿಗೆ ಸೇರುತ್ತವೆ, ಆದ್ದರಿಂದ ಆ ಪ್ರೊವೈಡರ್ಗಳಿಗೆ ಪ್ರತ್ಯೇಕ Custom Models ವಿಭಾಗವಿಲ್ಲ.
- **Custom Models** ವಿಭಾಗವು ನಿರ್ವಹಿತ ಲಭ್ಯವಿರುವ-ಮಾಡಲ್ ಆಮದುಗಳನ್ನು ಒದಗಿಸದ ಪ್ರೊವೈಡರ್ಗಳಿಗಾಗಿ ಉದ್ದೇಶಿಸಲಾಗಿದೆ.

### ಕಸ್ಟಮ್ OpenAI-ಹೊಂದಾಣಿಕೆಯ ಪ್ರೊವೈಡರ್ಗಳು

OpenAI API ಯನ್ನು ಮಾತನಾಡುವ ಯಾವುದೇ ಗೇಟ್ವೇ (ಸ್ವಯಂ-ಹೋಸ್ಟ್ ಮಾಡಲಾದ ಪ್ರಾಕ್ಸಿ, vLLM, ಮೂರನೇ ಪಕ್ಷದ ಅಗ್ರಿಗೇಟರ್)
ಅನ್ನು ಅದರ ಸ್ವಂತ ಪ್ರೊವೈಡರ್ ನೋಡ್ ಆಗಿ ಸೇರಿಸಬಹುದು:

1. **Providers → Add OpenAI Compatible**.
2. **Name**: ನೋಡ್ಗಾಗಿ ಪ್ರದರ್ಶನ ಲೇಬಲ್.
3. **Prefix**: ರೂಟಿಂಗ್ ಹೆಸರು. ಕ್ಲೈಂಟ್ಗಳು ಮಾಡಲ್ಗಳನ್ನು `<prefix>/<model>` ಎಂದು ಕರೆಯುತ್ತಾರೆ, ಆದ್ದರಿಂದ
   `mygw` ಪ್ರಿಫಿಕ್ಸ್ ಹೊಂದಿರುವ ನೋಡ್ `mygw/gpt-4o-mini` ಅನ್ನು ಸರ್ವ್ ಮಾಡುತ್ತದೆ. ಕಡ್ಡಾಯ; ಯಾವುದೇ ಅಕ್ಷರ ನಿರ್ಬಂಧವಿಲ್ಲ.
4. **API Type**: ಗೇಟ್ವೇ ಸರ್ವ್ ಮಾಡುವ ಎಂಡ್ಪಾಯಿಂಟ್ ಕುಟುಂಬ (Chat Completions, Responses,
   Embeddings, ಆಡಿಯೋ, ಚಿತ್ರಗಳು).
5. **Base URL**: `/v1` ಸೇರಿದಂತೆ API ಮೂಲ (ಉದಾಹರಣೆಗೆ
   `https://gateway.example.com/v1`), ಪೂರ್ಣ `/chat/completions` ಪಾತ್ ಅಲ್ಲ. ಪ್ರಮಾಣಿತವಲ್ಲದ
   ಪಾತ್ಗಳನ್ನು ಹೊಂದಿರುವ ಗೇಟ್ವೇಗಳು ಅವುಗಳನ್ನು **Advanced Settings** ಅಡಿಯಲ್ಲಿ ಹೊಂದಿಸುತ್ತವೆ (ಚಾಟ್ ಪಾತ್, ಮಾಡಲ್ಗಳ ಪಾತ್).
6. **API Key (for Check)** ಫೀಲ್ಡ್ ಕೇವಲ ಸಂಪರ್ಕವನ್ನು ಪರೀಕ್ಷಿಸುತ್ತದೆ. ನೋಡ್ ಅನ್ನು ರಚಿಸಿದ ನಂತರ,
   ಅದನ್ನು ತೆರೆಯಿರಿ ಮತ್ತು ವಿನಂತಿಗಳು ಬಳಸುವ ಕೀಯನ್ನು ಸಂಗ್ರಹಿಸಲು **Add Connection** ಬಳಸಿ.

ನೋಡ್ `openai-compatible-<apiType>-<uuid>` ರೂಪದ ಆಂತರಿಕ id ಅನ್ನು ಪಡೆಯುತ್ತದೆ; ನೀವು
ಅದನ್ನು ಎಂದಿಗೂ ಟೈಪ್ ಮಾಡಬೇಕಾಗಿಲ್ಲ, ಪ್ರಿಫಿಕ್ಸ್ ಸಾರ್ವಜನಿಕ ಹೆಸರು.

#### ಕಾಯ್ದಿರಿಸಿದ ಪ್ರಿಫಿಕ್ಸ್ಗಳು

ಪ್ರಿಫಿಕ್ಸ್ ಅಂತರ್ನಿರ್ಮಿತ ಪ್ರೊವೈಡರ್ನ id ಅಥವಾ ಅಲಿಯಾಸ್ ಆಗಿರಲಾಗದು (ಉದಾಹರಣೆಗೆ `openai`, `cf`), ಅಥವಾ
ನಿವೃತ್ತ ಪ್ರೊವೈಡರ್ನ id ಆಗಿರಲಾಗದು. ಮಾಡಲ್ ರಿಸಾಲ್ವರ್ ಕಸ್ಟಮ್ ನೋಡ್ಗಳಿಗೆ ಮೊದಲು
ಅಂತರ್ನಿರ್ಮಿತ id ಗಳು ಮತ್ತು ಅಲಿಯಾಸ್ಗಳನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಆ ಪ್ರಿಫಿಕ್ಸ್ಗಳಲ್ಲಿ ಒಂದನ್ನು ಬಳಸುವ ನೋಡ್
ಎಂದಿಗೂ ಟ್ರಾಫಿಕ್ ಅನ್ನು ಸ್ವೀಕರಿಸುವುದಿಲ್ಲ: `<prefix>/model` ಬದಲಿಗೆ ಅಂತರ್ನಿರ್ಮಿತ ಪ್ರೊವೈಡರ್ಗೆ
ಹೋಗುತ್ತದೆ, ಅಥವಾ ಆ ಪ್ರೊವೈಡರ್ ನಿವೃತ್ತವಾದರೆ ಫೇಲ್ ಕ್ಲೋಸ್ಡ್ ಆಗುತ್ತದೆ. ಅಂತಹ ಪ್ರಿಫಿಕ್ಸ್ನೊಂದಿಗೆ ನೋಡ್ ಅನ್ನು ರಚಿಸುವುದು
ಅಥವಾ ಸಂಪಾದಿಸುವುದು ಈ ಮೆಸೇಜ್ನೊಂದಿಗೆ ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

ವಿಶಿಷ್ಟ ಪ್ರಿಫಿಕ್ಸ್ ಆಯ್ಕೆಮಾಡಿ (`mygw`, `acme-proxy`). ಕಸ್ಟಮ್ ನೋಡ್ಗೆ ವಿನಂತಿಗಳು
ಅಂತರ್ನಿರ್ಮಿತ ಪ್ರೊವೈಡರ್ ಅಥವಾ ಅದರ ರುಜುವಾತುಗಳನ್ನು ಹೆಸರಿಸುವ
ದೋಷದೊಂದಿಗೆ ವಿಫಲವಾದರೆ, ನೋಡ್ನ ಪ್ರಿಫಿಕ್ಸ್ ಕಾಯ್ದಿರಿಸಲಾಗಿದೆಯೇ ಎಂದು
ಪರಿಶೀಲಿಸಿ: ಈ ನಿಯಮ ಅಸ್ತಿತ್ವಕ್ಕೆ ಬರುವ ಮೊದಲು ಉಳಿಸಿದ ನೋಡ್ಗಳು ಇನ್ನೂ ಸಂಗ್ರಹವಾಗಿವೆ, ಆದರೆ
ಅವುಗಳ ಪ್ರಿಫಿಕ್ಸ್ ಅಂತರ್ನಿರ್ಮಿತ ಪ್ರೊವೈಡರ್ಗೆ ರೂಟ್ ಆಗುತ್ತದೆ. ನೋಡ್ ಅನ್ನು ಸಂಪಾದಿಸಿ ಮತ್ತು ಹೊಸ ಪ್ರಿಫಿಕ್ಸ್ ನೀಡಿ.

#### ಪ್ರತಿ-ಸಂಪರ್ಕ ಗೇಟ್ವೇ ಆಯ್ಕೆಗಳು

ಈ ಕೀಗಳು ಸಂಪರ್ಕದ `providerSpecificData` ನಲ್ಲಿ ಹೋಗುತ್ತವೆ (ಉದಾಹರಣೆಗೆ
`PUT /api/providers/{id}` ಮೂಲಕ):

- `toolNameMaxLength` (ಪೂರ್ಣಾಂಕ, 1–1024) — ಉದ್ದನೆಯ ಟೂಲ್ ಹೆಸರುಗಳನ್ನು ಗೇಟ್ವೇ
  ತಿರಸ್ಕರಿಸುವ OpenAI ಚಾಟ್-ಫಾರ್ಮ್ಯಾಟ್ ಹೊಂದಾಣಿಕೆಯ ಸಂಪರ್ಕಗಳಿಗಾಗಿ. ಉದ್ದನೆಯ ಹೆಸರುಗಳನ್ನು
  ಸಣ್ಣ ಅಲಿಯಾಸ್ಗಳಾಗಿ ಕಳುಹಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆಯಲ್ಲಿ ಮರುಸ್ಥಾಪಿಸಲಾಗುತ್ತದೆ.
- `quotaEndpoint` — ಗೇಟ್ವೇಯ ಕೋಟಾ/ಕ್ರೆಡಿಟ್ಗಳ ಎಂಡ್ಪಾಯಿಂಟ್, ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಕೋಟಾ ಸ್ಟ್ರಿಪ್ ಮತ್ತು
  ಕೋಟಾ-ಅರಿವುಳುವಂಥ ರೂಟಿಂಗ್ಗಾಗಿ ಓದಲಾಗುತ್ತದೆ. OpenAI- ಮತ್ತು Anthropic-ಹೊಂದಾಣಿಕೆಯ ಎರಡೂ
  ಸಂಪರ್ಕಗಳಲ್ಲಿ ಕೆಲಸ ಮಾಡುತ್ತದೆ; ಪೂರ್ಣ ಆಕಾರವನ್ನು
  `open-sse/services/usage/openaiCompatible.ts` ನಲ್ಲಿ ದಾಖಲಿಸಲಾಗಿದೆ.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### OmniRoute ಪೀಯರ್ಗಳನ್ನು ಚೇನಿಂಗ್ ಮಾಡುವುದು

ಮತ್ತೊಂದು OmniRoute ಗೇಟ್ವೇ ಅನ್ನು **Custom OpenAI-compatible** ಪ್ರೊವೈಡರ್ ಆಗಿ ಸೇರಿಸಬಹುದು.
ಪೀಯರ್ನ `/v1` ಬೇಸ್ URL ಮತ್ತು ಆ ಪೀಯರ್ ನೀಡಿದ ಮೀಸಲಾದ, ಕನಿಷ್ಠ-ಸವಲತ್ತು API ಕೀಯನ್ನು ಬಳಸಿ.

ಪರಸ್ಪರ ಅಥವಾ ಮಲ್ಟಿ-ಹಾಪ್ ಚೇನ್ಗಳಿಗಾಗಿ, ಪ್ರತಿ ಗೇಟ್ವೇಯಲ್ಲಿ ಆಪ್ಟ್-ಇನ್ ಲೂಪ್ ಗಾರ್ಡ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

ಸ್ಪಷ್ಟವಾಗಿ ಅಲೋಲಿಸ್ಟ್ ಮಾಡಲಾದ ಪೀಯರ್ URL ಗೆ ಕಳುಹಿಸಿದ ವಿನಂತಿಗಳು ಮಾತ್ರ
`X-OmniRoute-Peer-Trace` ಹೆಡರ್ ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತವೆ. ಗೇಟ್ವೇ ಪುನರಾವರ್ತಿತ ಇನ್ಸ್ಟನ್ಸ್ ID ಅಥವಾ
ಖಾಲಿಯಾದ ಹಾಪ್ ಬಜೆಟ್ ಅನ್ನು HTTP `508 Loop Detected` ನೊಂದಿಗೆ ತಿರಸ್ಕರಿಸುತ್ತದೆ; ಸಾಮಾನ್ಯ ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರೊವೈಡರ್ಗಳು
ಯಾವುದೇ ಪೀಯರ್ ಮೆಟಾಡೇಟಾವನ್ನು ಸ್ವೀಕರಿಸುವುದಿಲ್ಲ.

ಪೀಯರ್ ಚೇನಿಂಗ್ ಡೇಟಾಬೇಸ್ ರೆಪ್ಲಿಕೇಶನ್ ಅಥವಾ ಹೋಸ್ಟ್ ಫೇಲ್ಓವರ್ ಅಲ್ಲ. ಪ್ರತಿ ಗೇಟ್ವೇ
ಸ್ವತಂತ್ರ SQLite ಸ್ಥಿತಿ, ಕ್ಯಾಶೆಗಳು, ರೇಟ್ ಕೌಂಟರ್ಗಳು ಮತ್ತು ಸೆಷನ್ಗಳನ್ನು ಇರಿಸಿಕೊಳ್ಳುತ್ತದೆ.
ಆಕ್ಟಿವ್/ಪ್ಯಾಸಿವ್ ಅಥವಾ ಆಕ್ಟಿವ್/ಆಕ್ಟಿವ್ ಲಭ್ಯತೆಗಾಗಿ ಹೆಲ್ತ್-ಚೆಕ್ ಮಾಡಲಾದ ರಿವರ್ಸ್ ಪ್ರಾಕ್ಸಿ ಅಥವಾ ಕ್ಲೈಂಟ್
ಫೇಲ್ಓವರ್ ಬಳಸಿ, ಮತ್ತು ಒಂದು SQLite ಡೇಟಾಬೇಸ್ ಅನ್ನು ಚಾಲನೆಯಲ್ಲಿರುವ ಬಹು
OmniRoute ಇನ್ಸ್ಟನ್ಸ್ಗಳಿಗೆ ಎಂದಿಗೂ ಮೌಂಟ್ ಮಾಡಬೇಡಿ.

### ಮೀಸಲಾದ ಪ್ರೊವೈಡರ್ ರೂಟ್ಗಳು

ಮಾಡಲ್ ಮೌಲ್ಯೀಕರಣದೊಂದಿಗೆ ವಿನಂತಿಗಳನ್ನು ನೇರವಾಗಿ ನಿರ್ದಿಷ್ಟ ಪ್ರೊವೈಡರ್ಗೆ ರೂಟ್ ಮಾಡಿ:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

ಪ್ರೊವೈಡರ್ ಪ್ರಿಫಿಕ್ಸ್ ಕಾಣೆಯಾದರೆ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಸೇರಿಸಲಾಗುತ್ತದೆ. ಹೊಂದಾಣಿಕೆಯಾಗದ ಮಾಡಲ್ಗಳು `400` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತವೆ.

### ನೆಟ್ವರ್ಕ್ ಪ್ರಾಕ್ಸಿ ಕಾನ್ಫಿಗರೇಶನ್

```bash
# ಗ್ಲೋಬಲ್ ಪ್ರಾಕ್ಸಿ ಹೊಂದಿಸಿ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# ಪ್ರತಿ-ಪ್ರೊವೈಡರ್ ಪ್ರಾಕ್ಸಿ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# ಪ್ರಾಕ್ಸಿ ಪರೀಕ್ಷಿಸಿ
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**ಪ್ರಾಥಾನ್ಯತೆ:** ಕೀ-ನಿರ್ದಿಷ್ಟ → ಕಾಂಬೊ-ನಿರ್ದಿಷ್ಟ → ಪ್ರೊವೈಡರ್-ನಿರ್ದಿಷ್ಟ → ಜಾಗತಿಕ → ಪರಿಸರ.

### ಮಾಡೆಲ್ ಕ್ಯಾಟಲಾಗ್ API

```bash
curl http://localhost:20128/api/models/catalog
```

ಪ್ರಕಾರಗಳೊಂದಿಗೆ (`chat`, `embedding`, `image`) ಪ್ರೊವೈಡರ್ ಮೂಲಕ ಗುಂಪುಮಾಡಲಾದ ಮಾಡೆಲ್ಗಳನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ.

### ಕ್ಲೌಡ್ ಸಿಂಕ್

- ಸಾಧನಗಳಾದ್ಯಂತ ಪ್ರೊವೈಡರ್ಗಳು, ಕಾಂಬೊಗಳು ಮತ್ತು ಸೆಟ್ಟಿಂಗ್ಗಳನ್ನು ಸಿಂಕ್ ಮಾಡಿ
- ಟೈಮ್ಔಟ್ + ಫೇಲ್-ಫಾಸ್ಟ್ನೊಂದಿಗೆ ಸ್ವಯಂಚಾಲಿತ ಹಿನ್ನೆಲೆ ಸಿಂಕ್
- ಪ್ರೊಡಕ್ಷನ್ನಲ್ಲಿ ಸರ್ವರ್-ಸೈಡ್ `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` ಅನ್ನು ಆದ್ಯತೆ ನೀಡಿ

### Cloudflare ಕ್ವಿಕ್ ಟನೆಲ್

- Docker ಮತ್ತು ಇತರ ಸ್ವಯಂ-ಹೋಸ್ಟ್ ಮಾಡಿದ ಡಿಪ್ಲಾಯ್ಮೆಂಟ್ಗಳಿಗೆ **Dashboard → Endpoints** ನಲ್ಲಿ ಲಭ್ಯವಿದೆ
- ನಿಮ್ಮ ಪ್ರಸ್ತುತ OpenAI-ಹೊಂದಾಣಿಕೆಯ `/v1` ಎಂಡ್ಪಾಯಿಂಟ್ಗೆ ಫಾರ್ವರ್ಡ್ ಮಾಡುವ ತಾತ್ಕಾಲಿಕ `https://*.trycloudflare.com` URL ಅನ್ನು ರಚಿಸುತ್ತದೆ
- ಮೊದಲ ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆಯು ಅಗತ್ಯವಿದ್ದಾಗ ಮಾತ್ರ `cloudflared` ಅನ್ನು ಇನ್ಸ್ಟಾಲ್ ಮಾಡುತ್ತದೆ; ನಂತರದ ರೀಸ್ಟಾರ್ಟ್ಗಳು ಅದೇ ನಿರ್ವಹಿಸಲಾದ ಬೈನರಿಯನ್ನು ಮರುಬಳಸುತ್ತವೆ
- OmniRoute ಅಥವಾ ಕಂಟೈನರ್ ರೀಸ್ಟಾರ್ಟ್ ನಂತರ ಕ್ವಿಕ್ ಟನೆಲ್ಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮರುಸ್ಥಾಪಿಸಲಾಗುವುದಿಲ್ಲ; ಅಗತ್ಯವಿದ್ದಾಗ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಿಂದ ಅವುಗಳನ್ನು ಮತ್ತೆ ಸಕ್ರಿಯಗೊಳಿಸಿ
- ಟನೆಲ್ URL ಗಳು ಕ್ಷಣಭಂಗುರವಾಗಿವೆ ಮತ್ತು ನೀವು ಟನೆಲ್ ಅನ್ನು ನಿಲ್ಲಿಸಿದಾಗ/ಪ್ರಾರಂಭಿಸಿದಾಗ ಪ್ರತಿಬಾರಿಯೂ ಬದಲಾಗುತ್ತವೆ
- ನಿರ್ವಹಿಸಲಾದ ಕ್ವಿಕ್ ಟನೆಲ್ಗಳು ನಿರ್ಬಂಧಿತ ಕಂಟೈನರ್ಗಳಲ್ಲಿ ಶಬ್ದಯುಕ್ತ QUIC UDP ಬಫರ್ ಎಚ್ಚರಿಕೆಗಳನ್ನು ತಪ್ಪಿಸಲು ಡೀಫಾಲ್ಟ್ ಆಗಿ HTTP/2 ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್ ಅನ್ನು ಬಳಸುತ್ತವೆ
- ನಿರ್ವಹಿಸಲಾದ ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್ ಆಯ್ಕೆಯನ್ನು ಓವರ್ರೈಡ್ ಮಾಡಲು ಬಯಸಿದರೆ `CLOUDFLARED_PROTOCOL=quic` ಅಥವಾ `auto` ಅನ್ನು ಹೊಂದಿಸಿ
- ನಿರ್ವಹಿಸಲಾದ ಡೌನ್ಲೋಡ್ ಬದಲಿಗೆ ಪೂರ್ವ-ಇನ್ಸ್ಟಾಲ್ ಮಾಡಿದ `cloudflared` ಬೈನರಿಯನ್ನು ಬಳಸಲು ಬಯಸಿದರೆ `CLOUDFLARED_BIN` ಅನ್ನು ಹೊಂದಿಸಿ
- Cloudflare ಕ್ವಿಕ್ ಟನೆಲ್, Tailscale Funnel ಮತ್ತು ngrok ಟನೆಲ್ ಪ್ಯಾನೆಲ್ಗಳನ್ನು **Settings → Appearance** ನಲ್ಲಿ ತೋರಿಸಬಹುದು ಅಥವಾ ಮರೆಮಾಚಬಹುದು. ಪ್ಯಾನೆಲ್ ಅನ್ನು ಮರೆಮಾಚುವುದು ಚಾಲ್ತಿಯಲ್ಲಿರುವ ಟನೆಲ್ ಅನ್ನು ನಿಲ್ಲಿಸುವುದಿಲ್ಲ.

### LLM ಗೇಟ್ವೇ ಇಂಟೆಲಿಜೆನ್ಸ್ (ಫೇಜ್ 9)

- **ಸೆಮಾಂಟಿಕ್ ಕ್ಯಾಶೆ** — ಸ್ಟ್ರೀಮಿಂಗ್ ಅಲ್ಲದ, temperature=0 ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಕ್ಯಾಶೆ ಮಾಡುತ್ತದೆ (`X-OmniRoute-No-Cache: true` ನೊಂದಿಗೆ ಬೈಪಾಸ್ ಮಾಡಿ)
- **ರಿಕ್ವೆಸ್ಟ್ ಐಡೆಂಪೊಟೆನ್ಸಿ** — `Idempotency-Key` ಅಥವಾ `X-Request-Id` ಹೆಡರ್ ಮೂಲಕ 5 ಸೆಕೆಂಡುಗಳೊಳಗೆ ರಿಕ್ವೆಸ್ಟ್ಗಳನ್ನು ಡೆಡುಪ್ಲಿಕೇಟ್ ಮಾಡುತ್ತದೆ
- **ಪ್ರಗತಿ ಟ್ರ್ಯಾಕಿಂಗ್** — `X-OmniRoute-Progress: true` ಹೆಡರ್ ಮೂಲಕ ಆಪ್ಟ್-ಇನ್ SSE `event: progress` ಈವೆಂಟ್ಗಳು

| ಮೋಡ್             | ಉದ್ದೇಶ                                                                                                  |

| **ಚಾಟ್ ಟೆಸ್ಟರ್** | ಪ್ರಾಕ್ಸಿ ಮೂಲಕ ಲೈವ್ ಚಾಟ್ ಸಂದೇಶಗಳನ್ನು ಕಳುಹಿಸಿ ಮತ್ತು ಸಂಪೂರ್ಣ ರಿಕ್ವೆಸ್ಟ್/ರೆಸ್ಪಾನ್ಸ್ ಸೈಕಲ್ ಅನ್ನು ಪರಿಶೀಲಿಸಿ   |

- ಥಿಂಕಿಂಗ್ ಟ್ಯಾಗ್ಗಳು, ಟೂಲ್ ಕಾಲ್ಗಳು ಮತ್ತು ಸಿಸ್ಟಮ್ ಪ್ರಾಂಪ್ಟ್ಗಳು ಸರಿಯಾಗಿ ಭಾಷಾಂತರಗೊಳ್ಳುತ್ತವೆ ಎಂದು ಪರಿಶೀಲಿಸಿ
- OpenAI, Claude, Gemini ಮತ್ತು Responses API ಫಾರ್ಮ್ಯಾಟ್ಗಳ ನಡುವಿನ ಫಾರ್ಮ್ಯಾಟ್ ವ್ಯತ್ಯಾಸಗಳನ್ನು ಹೋಲಿಕೆ ಮಾಡಿ

### ರೂಟಿಂಗ್ ಕಾರ್ಯತಂತ್ರಗಳು

**Dashboard → Settings → Routing** ಮೂಲಕ ಕಾನ್ಫಿಗರ್ ಮಾಡಿ. ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಆರು ಹೆಚ್ಚು ಬಳಸಲಾಗುವ ಕಾರ್ಯತಂತ್ರಗಳನ್ನು ಒಡ್ಡುತ್ತದೆ; ಕಾಂಬೊಗಳು ಮತ್ತು ಆಟೋ-ರೂಟರ್ ಆಂತರಿಕವಾಗಿ ವಿಶಾಲವಾದ ಸೆಟ್ ಅನ್ನು ಬೆಂಬಲಿಸುತ್ತವೆ.

**ಡ್ಯಾಶ್ಬೋರ್ಡ್-ಗೋಚರ ಕಾರ್ಯತಂತ್ರಗಳು (ಅಕೌಂಟ್-ಮಟ್ಟದ ರೂಟಿಂಗ್):**

| ಕಾರ್ಯತಂತ್ರ                   | ವಿವರಣೆ                                                                                                                                 |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **ಫಿಲ್ ಫಸ್ಟ್**               | ಪ್ರಾಥಾನ್ಯತೆ ಕ್ರಮದಲ್ಲಿ ಅಕೌಂಟ್ಗಳನ್ನು ಬಳಸುತ್ತದೆ — ಲಭ್ಯವಿಲ್ಲದ ತನಕ ಪ್ರಾಥಮಿಕ ಅಕೌಂಟ್ ಎಲ್ಲಾ ರಿಕ್ವೆಸ್ಟ್ಗಳನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ                    |
| **ರೌಂಡ್ ರಾಬಿನ್**             | ಕಾನ್ಫಿಗರೆಬಲ್ ಸ್ಟಿಕ್ಕಿ ಮಿತಿಯೊಂದಿಗೆ ಎಲ್ಲಾ ಅಕೌಂಟ್ಗಳ ಮೂಲಕ ಸೈಕಲ್ ಮಾಡುತ್ತದೆ (ಡೀಫಾಲ್ಟ್: ಪ್ರತಿ ಅಕೌಂಟ್ಗೆ 3 ಕಾಲ್ಗಳು)                             |
| **P2C (ಪವರ್ ಆಫ್ ಟು ಚಾಯಸಸ್)** | 2 ಯಾದೃಚ್ಛಿಕ ಅಕೌಂಟ್ಗಳನ್ನು ಆರಿಸುತ್ತದೆ ಮತ್ತು ಹೆಚ್ಚು ಆರೋಗ್ಯಕರವಾದದ್ದಕ್ಕೆ ರೂಟ್ ಮಾಡುತ್ತದೆ — ಆರೋಗ್ಯದ ಅರಿವಿನೊಂದಿಗೆ ಲೋಡ್ ಅನ್ನು ಸಮತೋಲನಗೊಳಿಸುತ್ತದೆ |
| **ರಾಂಡಮ್**                   | Fisher-Yates ಶಫಲ್ ಬಳಸಿ ಪ್ರತಿ ರಿಕ್ವೆಸ್ಟ್ಗೆ ಯಾದೃಚ್ಛಿಕವಾಗಿ ಅಕೌಂಟ್ ಅನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತದೆ                                                    |
| **ಲೀಸ್ಟ್ ಯೂಸ್ಡ್**            | ಹಳೆಯ `lastUsedAt` ಟೈಮ್ಸ್ಟಾಂಪ್ ಹೊಂದಿರುವ ಅಕೌಂಟ್ಗೆ ರೂಟ್ ಮಾಡುತ್ತದೆ, ಟ್ರಾಫಿಕ್ ಅನ್ನು ಸಮಾನವಾಗಿ ಹಂಚುತ್ತದೆ                                      |
| **ಕಾಸ್ಟ್ ಆಪ್ಟಿಮೈಜ್ಡ್**       | ಅತ್ಯಂತ ಕಡಿಮೆ ಪ್ರಾಥಾನ್ಯತೆ ಮೌಲ್ಯವನ್ನು ಹೊಂದಿರುವ ಅಕೌಂಟ್ಗೆ ರೂಟ್ ಮಾಡುತ್ತದೆ, ಕಡಿಮೆ-ವೆಚ್ಚದ ಪ್ರೊವೈಡರ್ಗಳಿಗೆ ಆಪ್ಟಿಮೈಜ್ ಮಾಡುತ್ತದೆ                  |

**ಸುಧಾರಿತ ಕಾಂಬೊ ಮತ್ತು ಆಟೋ ಕಾರ್ಯತಂತ್ರಗಳು** (ಪ್ರತಿ ಕಾಂಬೊಗೆ ಅಥವಾ `auto/*` ಪ್ರಿಫಿಕ್ಸ್ಗಳ ಮೂಲಕ ಕಾನ್ಫಿಗರೆಬಲ್ — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ನೋಡಿ):

- `priority` — ಕಟ್ಟುನಿಟ್ಟಾದ ಕ್ರಮ, ಎಂದಿಗೂ ರೌಂಡ್-ರಾಬಿನ್ ಆಗುವುದಿಲ್ಲ
- `weighted` — ಪ್ರತಿ-ಮಾಡೆಲ್ ತೂಕಗಳ ಮೂಲಕ ಅನುಪಾತ ಟ್ರಾಫಿಕ್ ವಿಭಜನೆ
- `fill-first` — ಮಿತಿಗಳು ತಲುಪುವವರೆಗೆ ಮೊದಲ ಮಾಡೆಲ್ ಅನ್ನು ಡ್ರೈನ್ ಮಾಡಿ
- `round-robin` / `strict-random` / `random`
- `p2c` (ಪವರ್ ಆಫ್ ಟು ಚಾಯಸಸ್)
- `least-used` ಮತ್ತು `cost-optimized`
- `auto` — ಎಲ್ಲಾ ಅಭ್ಯರ್ಥಿಗಳಾದ್ಯಂತ ಸ್ಕೋರ್-ಚಾಲಿತ
- `lkgp` (ಲಾಸ್ಟ್ ನೋನ್ ಗುಡ್ ಪ್ರೊವೈಡರ್) — ಕೊನೆಯ ಯಶಸ್ವಿ ಪ್ರೊವೈಡರ್ಗೆ ಪಿನ್ ಮಾಡುತ್ತದೆ, ನಂತರ ನಿಯಮಗಳಿಗೆ ಫಾಲ್ಬ್ಯಾಕ್ ಆಗುತ್ತದೆ
- `context-optimized` — ಅತಿದೊಡ್ಡ ಮುಕ್ತ ಕಾಂಟೆಕ್ಸ್ಟ್ ವಿಂಡೋ ಹೊಂದಿರುವ ಮಾಡೆಲ್ ಅನ್ನು ಆರಿಸುತ್ತದೆ
- `context-relay` — ಫಾಲೋ-ಅಪ್ ಟರ್ನ್ಗಳಿಗೆ ಲಾಂಗ್-ಕಾಂಟೆಕ್ಸ್ಟ್ ಮಾಡೆಲ್ಗಳನ್ನು ಚೈನ್ ಮಾಡುತ್ತದೆ

#### ಎಕ್ಸ್ಟರ್ನಲ್ ಸ್ಟಿಕ್ಕಿ ಸೆಷನ್ ಹೆಡರ್

ಎಕ್ಸ್ಟರ್ನಲ್ ಸೆಷನ್ ಅಫಿನಿಟಿಗಾಗಿ (ಉದಾಹರಣೆಗೆ, ರಿವರ್ಸ್ ಪ್ರಾಕ್ಸಿಗಳ ಹಿಂದಿರುವ Claude Code/Codex ಏಜೆಂಟ್ಗಳು), ಕಳುಹಿಸಿ:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id` ಅನ್ನು ಸಹ ಸ್ವೀಕರಿಸುತ್ತದೆ ಮತ್ತು ಪರಿಣಾಮಕಾರಿ ಸೆಷನ್ ಕೀಯನ್ನು `X-OmniRoute-Session-Id` ನಲ್ಲಿ ಹಿಂದಿರುಗಿಸುತ್ತದೆ.

ನೀವು Nginx ಅನ್ನು ಬಳಸಿ ಅಂಡರ್ಸ್ಕೋರ್-ಫಾರ್ಮ್ ಹೆಡರ್ಗಳನ್ನು ಕಳುಹಿಸಿದರೆ, ಸಕ್ರಿಯಗೊಳಿಸಿ:

```nginx
underscores_in_headers on;
```

#### ವೈಲ್ಡ್ಕಾರ್ಡ್ ಮಾಡೆಲ್ ಅಲಿಯಾಸ್ಗಳು

ಮಾಡೆಲ್ ಹೆಸರುಗಳನ್ನು ರೀಮ್ಯಾಪ್ ಮಾಡಲು ವೈಲ್ಡ್ಕಾರ್ಡ್ ಪ್ಯಾಟರ್ನ್ಗಳನ್ನು ರಚಿಸಿ:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

ವೈಲ್ಡ್ಕಾರ್ಡ್ಗಳು `*` (ಯಾವುದೇ ಅಕ್ಷರಗಳು) ಮತ್ತು `?` (ಏಕ ಅಕ್ಷರ) ಅನ್ನು ಬೆಂಬಲಿಸುತ್ತವೆ.

#### ಫಾಲ್ಬ್ಯಾಕ್ ಚೈನ್ಗಳು

ಎಲ್ಲಾ ರಿಕ್ವೆಸ್ಟ್ಗಳಿಗೆ ಅನ್ವಯಿಸುವ ಜಾಗತಿಕ ಫಾಲ್ಬ್ಯಾಕ್ ಚೈನ್ಗಳನ್ನು ವ್ಯಾಖ್ಯಾನಿಸಿ:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### ಸಾಮಾನ್ಯ ಪ್ರೊವೈಡರ್ ಸಂಯೋಜನೆಗಳು ಮತ್ತು ರೂಟಿಂಗ್ ಪ್ಯಾಟರ್ನ್ಗಳು

OmniRoute ನಲ್ಲಿ ಬಹು ಪ್ರೊವೈಡರ್ಗಳನ್ನು ಸಂಯೋಜಿಸುವ ಮತ್ತು ಅವುಗಳ ನಡುವೆ ರೂಟಿಂಗ್ ಮಾಡುವ ಉದಾಹರಣೆ ಪ್ಯಾಟರ್ನ್ಗಳು ಇಲ್ಲಿವೆ:

#### 1. ಕೋಡಿಂಗ್ ಏಜೆಂಟ್ ಕಾಂಬೊ: ವೆಚ್ಚ/ವೇಗದ ಫಾಲ್ಬ್ಯಾಕ್ನೊಂದಿಗೆ ಉನ್ನತ-ಮಟ್ಟದ ತಾರ್ಕಿಕತೆ

ಕೋಡಿಂಗ್ ಏಜೆಂಟ್ಗಳಿಗೆ (OpenCode, Claude Code, Cursor, Cline) ಸೂಕ್ತ. ಆರಂಭದಲ್ಲಿ ಫ್ರಂಟಿಯರ್ ತಾರ್ಕಿಕ ಮಾದರಿಗಳಿಗೆ ರೂಟ್ ಮಾಡುತ್ತದೆ, ಕೋಟಾ ಮೀರಿದಾಗ ಅಥವಾ ದೋಷಗಳ ಸಂದರ್ಭದಲ್ಲಿ ವೇಗದ ಕೋಡಿಂಗ್ ಮಾದರಿಗಳಿಗೆ ಫಾಲ್ಬ್ಯಾಕ್ ಆಗುತ್ತದೆ.

- **ಡ್ಯಾಶ್ಬೋರ್ಡ್**: ಕಾಂಬೊಗಳು → ಹೊಸ ಕಾಂಬೊ → ಹೆಸರು: `agent-coding` → ಕಾರ್ಯತಂತ್ರ: `Priority`
- **ಮಾದರಿಗಳು**:
  1. `claude/claude-sonnet-4-6` (ಪ್ರಾಥಮಿಕ ಕೋಡಿಂಗ್ ಏಜೆಂಟ್)
  2. `openai/gpt-4o` (ದ್ವಿತೀಯಕ ಹೈ-ಕ್ಯಾಪಾಸಿಟಿ ಫಾಲ್ಬ್ಯಾಕ್)
  3. `deepseek/deepseek-v4-flash` (ಹೆಚ್ಚು ದಕ್ಷ, ವೆಚ್ಚ-ಪರಿಣಾಮಕಾರಿ ಫಾಲ್ಬ್ಯಾಕ್)

```bash
# API ಮೂಲಕ ಉದಾಹರಣೆ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

#### 2. ಉಚಿತ-ಶ್ರೇಣಿ ಸ್ವಯಂ ಫೈಲ್ಓವರ್ ಕಾಂಬೊ

API ವೆಚ್ಚವಿಲ್ಲದೆ ಅಪ್ಟೈಮ್ ಅನ್ನು ಗರಿಷ್ಠಗೊಳಿಸಲು ಬಹು ಉಚಿತ-ಶ್ರೇಣಿ ಮತ್ತು ಕೀ ರಹಿತ ಪ್ರೊವೈಡರ್ಗಳನ್ನು ಸರಪಳಿಯಂತೆ ಜೋಡಿಸುತ್ತದೆ.

- **ಕಾರ್ಯತಂತ್ರ**: `Least Used` ಅಥವಾ `Round Robin` (ಕೋಟಾಗಳಲ್ಲಿ ಲೋಡ್ ಹಂಚುತ್ತದೆ)

  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

### ಸ್ಥಿತಿಸ್ಥಾಪಕತೆ & ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್ಗಳು

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಸೆಟ್ಟಿಂಗ್ಸ್ → ಸ್ಥಿತಿಸ್ಥಾಪಕತೆ** ಮೂಲಕ ಕಾನ್ಫಿಗರ್ ಮಾಡಿ.

OmniRoute ಐದು ಘಟಕಗಳೊಂದಿಗೆ ಪ್ರೊವೈಡರ್-ಮಟ್ಟದ ಸ್ಥಿತಿಸ್ಥಾಪಕತೆಯನ್ನು ಅಳವಡಿಸುತ್ತದೆ:

1. **ವಿನಂತಿ ಕ್ಯೂ & ಪೇಸಿಂಗ್** — ವ್ಯವಸ್ಥಾ-ಮಟ್ಟದ ವಿನಂತಿ ಆಕಾರ ನೀಡುವಿಕೆ:
   - **ನಿಮಿಷಕ್ಕೆ ವಿನಂತಿಗಳು (RPM)** — ಪ್ರತಿ ಖಾತೆಗೆ ನಿಮಿಷಕ್ಕೆ ಗರಿಷ್ಠ ವಿನಂತಿಗಳು
   - **ವಿನಂತಿಗಳ ನಡುವಿನ ಕನಿಷ್ಠ ಸಮಯ** — ವಿನಂತಿಗಳ ನಡುವಿನ ಮಿಲಿಸೆಕೆಂಡುಗಳಲ್ಲಿನ ಕನಿಷ್ಠ ಅಂತರ
   - **ಗರಿಷ್ಠ ಸಮವರ್ತಿ ವಿನಂತಿಗಳು** — ಪ್ರತಿ ಖಾತೆಗೆ ಗರಿಷ್ಠ ಏಕಕಾಲಿಕ ವಿನಂತಿಗಳು

2. **ಸಂಪರ್ಕ ಕೂಲ್ಡೌನ್** — ಮರುಪ್ರಯತ್ನಿಸಬಹುದಾದ ವೈಫಲ್ಯಗಳ ನಂತರ ಏಕ ಸಂಪರ್ಕಕ್ಕೆ ಪ್ರತಿ-ದೃಢೀಕರಣ-ಪ್ರಕಾರದ ಕಾನ್ಫಿಗರೇಶನ್:
   - **ಮೂಲ ಕೂಲ್ಡೌನ್** — ಮರುಪ್ರಯತ್ನಿಸಬಹುದಾದ ಅಪ್ಸ್ಟ್ರೀಮ್ ವೈಫಲ್ಯಗಳಿಗೆ ಡೀಫಾಲ್ಟ್ ಕೂಲ್ಡೌನ್ ಅವಧಿ
   - **ಅಪ್ಸ್ಟ್ರೀಮ್ ಮರುಪ್ರಯತ್ನ ಸೂಚನೆಗಳನ್ನು ಬಳಸಿ** — ಒದಗಿಸಿದಾಗ ಅಧಿಕೃತ `Retry-After` ಅಥವಾ ಮರುಹೊಂದಿಸುವ ಸೂಚನೆಗಳನ್ನು ಗೌರವಿಸುತ್ತದೆ
   - **ಗರಿಷ್ಠ ಬ್ಯಾಕ್ಆಫ್ ಹಂತಗಳು** — ಪುನರಾವರ್ತಿತ ವೈಫಲ್ಯಗಳಿಗೆ ಗರಿಷ್ಠ ಘಾತೀಯ ಬ್ಯಾಕ್ಆಫ್ ಮಟ್ಟ

3. **ಪ್ರೊವೈಡರ್ ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್** — ಎಂಡ್-ಟು-ಎಂಡ್ ಪ್ರೊವೈಡರ್ ವೈಫಲ್ಯಗಳನ್ನು ಟ್ರ್ಯಾಕ್ ಮಾಡುತ್ತದೆ, ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಎಚ್ಚರಿಕೆ ಮಿತಿಯಲ್ಲಿ ಪ್ರೊವೈಡರ್ ಅನ್ನು ಅವನತಿಗೊಂಡಂತೆ ಗುರುತಿಸುತ್ತದೆ, ಮತ್ತು ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ವೈಫಲ್ಯ ಮಿತಿಯನ್ನು ತಲುಪಿದಾಗ ಬ್ರೇಕರ್ ಅನ್ನು ತೆರೆಯುತ್ತದೆ:
   - **ಅವನತಿ ಮಿತಿ** — `DEGRADED` ಸ್ಥಿತಿಗೆ ಪ್ರವೇಶಿಸುವ ಮೊದಲು ಸತತ ಪ್ರೊವೈಡರ್ ವೈಫಲ್ಯಗಳು
   - **ವೈಫಲ್ಯ ಮಿತಿ** — `OPEN` ಸ್ಥಿತಿಗೆ ಪ್ರವೇಶಿಸುವ ಮೊದಲು ಸತತ ಪ್ರೊವೈಡರ್ ವೈಫಲ್ಯಗಳು
   - **ಮರುಹೊಂದಿಸುವ ಟೈಮ್ಔಟ್** — ಪ್ರೊವೈಡರ್ ಅನ್ನು ಮತ್ತೆ ಪರೀಕ್ಷಿಸುವ ಮೊದಲಿನ ಸಮಯದ ಅವಧಿ
   - **CLOSED** (ಆರೋಗ್ಯಕರ) — ವಿನಂತಿಗಳು ಸಾಮಾನ್ಯವಾಗಿ ಹರಿಯುತ್ತವೆ
   - **DEGRADED** — ಹೆಚ್ಚಿದ ವೈಫಲ್ಯಗಳನ್ನು ಟ್ರ್ಯಾಕ್ ಮಾಡುವಾಗಲೂ ವಿನಂತಿಗಳು ಹರಿಯುತ್ತವೆ
   - **OPEN** — ಪುನರಾವರ್ತಿತ ವೈಫಲ್ಯಗಳ ನಂತರ ಪ್ರೊವೈಡರ್ ಅನ್ನು ತಾತ್ಕಾಲಿಕವಾಗಿ ನಿರ್ಬಂಧಿಸಲಾಗುತ್ತದೆ
   - **HALF_OPEN** — ಪ್ರೊವೈಡರ್ ಚೇತರಿಸಿಕೊಂಡಿದೆಯೇ ಎಂದು ಪರೀಕ್ಷಿಸುತ್ತಿದೆ

   ಸಂಪರ್ಕ-ವ್ಯಾಪ್ತಿಯ `429` ರೇಟ್ ಲಿಮಿಟ್ಗಳು **ಸಂಪರ್ಕ ಕೂಲ್ಡೌನ್**ನಲ್ಲೇ ಉಳಿಯುತ್ತವೆ ಮತ್ತು ಪ್ರೊವೈಡರ್ ಬ್ರೇಕರ್ಗೆ ಎಣಿಕೆಯಾಗುವುದಿಲ್ಲ.

   ಪ್ರೊವೈಡರ್ ಬ್ರೇಕರ್ ರನ್ಟೈಮ್ ಸ್ಥಿತಿಯನ್ನು **ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಆರೋಗ್ಯ**ದಲ್ಲಿ ಮಾತ್ರ ತೋರಿಸಲಾಗುತ್ತದೆ.

4. **ಕೂಲ್ಡೌನ್ಗಾಗಿ ಕಾಯಿರಿ** — ಪ್ರತಿ ಅಭ್ಯರ್ಥಿ ಸಂಪರ್ಕವು ಈಗಾಗಲೇ ಕೂಲ್ಡೌನ್ ಆಗುತ್ತಿದ್ದರೆ, OmniRoute ಮೊದಲ ಕೂಲ್ಡೌನ್ಗಾಗಿ ಕಾಯಬಹುದು ಮತ್ತು ಅದೇ ಕ್ಲೈಂಟ್ ವಿನಂತಿಯನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮರುಪ್ರಯತ್ನಿಸಬಹುದು.

5. **ರೇಟ್ ಲಿಮಿಟ್ ಸ್ವಯಂ-ಪತ್ತೆ** — ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರೊವೈಡರ್ಗಳು ಸ್ಪಷ್ಟ ಕಾಯುವ ಅವಧಿಗಳನ್ನು ಹಿಂತಿರುಗಿಸಿದಾಗ, ಸೆಟ್ಟಿಂಗ್ ಸಕ್ರಿಯಗೊಳಿಸಿದಾಗ ಆ ಸೂಚನೆಗಳು ಸ್ಥಳೀಯ ಸಂಪರ್ಕ ಕೂಲ್ಡೌನ್ ಅನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತವೆ.

**ಪ್ರೊ ಟಿಪ್:** ಔಟೇಜ್ ನಂತರ ಲೈವ್ ಪ್ರೊವೈಡರ್ ಬ್ರೇಕರ್ಗಳನ್ನು ಪರಿಶೀಲಿಸಲು ಮತ್ತು ಮರುಹೊಂದಿಸಲು **ಆರೋಗ್ಯ** ಪುಟವನ್ನು ಬಳಸಿ. ಸ್ಥಿತಿಸ್ಥಾಪಕತೆ ಪುಟವು ಕೇವಲ ಕಾನ್ಫಿಗರೇಶನ್ ಅನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ.

### ಡೇಟಾಬೇಸ್ ರಫ್ತು / ಆಮದು

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಸೆಟ್ಟಿಂಗ್ಸ್ → ಸಿಸ್ಟಮ್ & ಸ್ಟೋರೇಜ್**ನಲ್ಲಿ ಡೇಟಾಬೇಸ್ ಬ್ಯಾಕಪ್ಗಳನ್ನು ನಿರ್ವಹಿಸಿ.

| ಕ್ರಿಯೆ                             | ವಿವರಣೆ                                                                                                                                                             |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **ಡೇಟಾಬೇಸ್ ರಫ್ತು ಮಾಡಿ**            | ಪ್ರಸ್ತುತ SQLite ಡೇಟಾಬೇಸ್ ಅನ್ನು `.sqlite` ಫೈಲ್ ಆಗಿ ಡೌನ್ಲೋಡ್ ಮಾಡುತ್ತದೆ                                                                                               |
| **ಎಲ್ಲವನ್ನೂ ರಫ್ತು ಮಾಡಿ (.tar.gz)** | ಈ ಕೆಳಗಿನವುಗಳನ್ನು ಒಳಗೊಂಡ ಪೂರ್ಣ ಬ್ಯಾಕಪ್ ಆರ್ಕೈವ್ ಅನ್ನು ಡೌನ್ಲೋಡ್ ಮಾಡುತ್ತದೆ: ಡೇಟಾಬೇಸ್, ಸೆಟ್ಟಿಂಗ್ಸ್, ಕಾಂಬೊಗಳು, ಪ್ರೊವೈಡರ್ ಸಂಪರ್ಕಗಳು (ರುಜುವಾತುಗಳಿಲ್ಲದೆ), API ಕೀ ಮೆಟಾಡೇಟಾ   |
| **ಡೇಟಾಬೇಸ್ ಆಮದು ಮಾಡಿ**             | ಪ್ರಸ್ತುತ ಡೇಟಾಬೇಸ್ ಅನ್ನು ಬದಲಾಯಿಸಲು `.sqlite` ಫೈಲ್ ಅನ್ನು ಅಪ್ಲೋಡ್ ಮಾಡಿ. `DISABLE_SQLITE_AUTO_BACKUP=true` ಆಗಿರದಿದ್ದರೆ ಪೂರ್ವ-ಆಮದು ಬ್ಯಾಕಪ್ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ರಚಿಸಲಾಗುತ್ತದೆ |

```bash
# API: ಡೇಟಾಬೇಸ್ ರಫ್ತು ಮಾಡಿ
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: ಎಲ್ಲವನ್ನೂ ರಫ್ತು ಮಾಡಿ (ಪೂರ್ಣ ಆರ್ಕೈವ್)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ಡೇಟಾಬೇಸ್ ಆಮದು ಮಾಡಿ
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ಆಮದು ಮಾನ್ಯತೆ:** ಆಮದು ಮಾಡಿದ ಫೈಲ್ ಅನ್ನು ಸಮಗ್ರತೆ (SQLite pragma ಪರಿಶೀಲನೆ), ಅಗತ್ಯ ಟೇಬಲ್ಗಳು (`provider_connections`, `provider_nodes`, `combos`, `api_keys`), ಮತ್ತು ಗಾತ್ರಕ್ಕೆ (ಗರಿಷ್ಠ 100MB) ಮಾನ್ಯತೆ ಪಡೆಯಲಾಗುತ್ತದೆ.

**ಉಪಯೋಗ ಪ್ರಕರಣಗಳು:**

- ಯಂತ್ರಗಳ ನಡುವೆ OmniRoute ಅನ್ನು ವಲಸೆ ಮಾಡಿ
- ವಿಪತ್ತು ಮರುಪಡೆಯುವಿಕೆಗಾಗಿ ಬಾಹ್ಯ ಬ್ಯಾಕಪ್ಗಳನ್ನು ರಚಿಸಿ
- ತಂಡದ ಸದಸ್ಯರ ನಡುವೆ ಕಾನ್ಫಿಗರೇಶನ್ಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳಿ (ಎಲ್ಲವನ್ನೂ ರಫ್ತು ಮಾಡಿ → ಆರ್ಕೈವ್ ಹಂಚಿಕೊಳ್ಳಿ)

| **ರೂಟಿಂಗ್**         | ಗ್ಲೋಬಲ್ ರೂಟಿಂಗ್ ಕಾರ್ಯತಂತ್ರ (ಫಿಲ್ ಫಸ್ಟ್ / ರೌಂಡ್ ರಾಬಿನ್ / P2C / ರ್ಯಾಂಡಮ್ / ಲೀಸ್ಟ್ ಯೂಸ್ಡ್ / ಕಾಸ್ಟ್ ಆಪ್ಟಿಮೈಜ್ಡ್), ವೈಲ್ಡ್ಕಾರ್ಡ್ ಮಾಡೆಲ್ ಅಲಿಯಾಸ್ಗಳು, ಫಾಲ್ಬ್ಯಾಕ್ ಚೈನ್ಗಳು, ಕಾಂಬೊ ಡೀಫಾಲ್ಟ್ಗಳು |
| **ಸ್ಥಿತಿಸ್ಥಾಪಕತ್ವ** | ರಿಕ್ವೆಸ್ಟ್ ಕ್ಯೂ, ಕನೆಕ್ಷನ್ ಕೂಲ್ಡೌನ್, ಪ್ರೊವೈಡರ್ ಬ್ರೇಕರ್ ಕಾನ್ಫಿಗ್, ಮತ್ತು wait-for-cooldown ನಡವಳಿಕೆ                                                                                     |
| **ಸುಧಾರಿತ**         | ಗ್ಲೋಬಲ್ ಪ್ರಾಕ್ಸಿ ಕಾನ್ಫಿಗರೇಶನ್ (HTTP/SOCKS5), ಪ್ರತಿ-ಪ್ರೊವೈಡರ್ ಪ್ರಾಕ್ಸಿ ಓವರ್ರೈಡ್ಗಳು                                                                                                   |

ಸಾಮಾನ್ಯವು ಈಗ ಓದು-ಮಾತ್ರದ ಲಾಗಿಂಗ್ ಮತ್ತು ಕ್ಯಾಶೆ ಟಿಪ್ಪಣಿಗಳನ್ನು ನಕಲಿಸುವುದಿಲ್ಲ. ಡೇಟಾಬೇಸ್ ರಿಟೆನ್ಷನ್ ಮತ್ತು
ಆಪ್ಟಿಮೈಜೇಶನ್ ಸೆಟ್ಟಿಂಗ್ಗಳನ್ನು `/api/settings/database` ಮೂಲಕ ಶೇಖರಿಸಲಾಗುತ್ತದೆ; ಹಸ್ತಚಾಲಿತ ಕ್ಯಾಶೆ
ತೆರವುಗೊಳಿಸುವಿಕೆಯು `DELETE /api/cache` ಅನ್ನು ಬಳಸುತ್ತದೆ. ರಿಕ್ವೆಸ್ಟ್ ಮತ್ತು ಪ್ರಾಕ್ಸಿ ಲಾಗ್ ಸಾಲು ಮಿತಿಗಳನ್ನು
`CALL_LOGS_TABLE_MAX_ROWS` ಮತ್ತು `PROXY_LOGS_TABLE_MAX_ROWS` ನಿಯಂತ್ರಿಸುತ್ತವೆ.

### ವೆಚ್ಚಗಳು ಮತ್ತು ಬಜೆಟ್ ನಿರ್ವಹಣೆ

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ವೆಚ್ಚಗಳು** ಮೂಲಕ ಪ್ರವೇಶಿಸಿ.

| ಟ್ಯಾಬ್    | ಉದ್ದೇಶ                                                                                                        |
| --------- | ------------------------------------------------------------------------------------------------------------- |
| **ಬಜೆಟ್** | ದೈನಂದಿನ/ಸಾಪ್ತಾಹಿಕ/ಮಾಸಿಕ ಬಜೆಟ್ಗಳು ಮತ್ತು ನೈಜ-ಸಮಯ ಟ್ರ್ಯಾಕಿಂಗ್ನೊಂದಿಗೆ ಪ್ರತಿ API ಕೀಲಿಗೆ ಖರ್ಚಿನ ಮಿತಿಗಳನ್ನು ಹೊಂದಿಸಿ  |
| **ಬೆಲೆ**  | ಮಾಡೆಲ್ ಬೆಲೆ ನಮೂದುಗಳನ್ನು ವೀಕ್ಷಿಸಿ ಮತ್ತು ಸಂಪಾದಿಸಿ — ಪ್ರತಿ ಪ್ರೊವೈಡರ್ಗೆ ಪ್ರತಿ 1K ಇನ್ಪುಟ್/ಔಟ್ಪುಟ್ ಟೋಕನ್ಗಳಿಗೆ ವೆಚ್ಚ |

```bash
# API: ಬಜೆಟ್ ಹೊಂದಿಸಿ
curl -X POST http://localhost:20128/api/usage/budget \
  -H "Content-Type: application/json" \
  -d '{"keyId": "key-123", "limit": 50.00, "period": "monthly"}'

# API: ಪ್ರಸ್ತುತ ಬಜೆಟ್ ಸ್ಥಿತಿಯನ್ನು ಪಡೆಯಿರಿ
curl http://localhost:20128/api/usage/budget
```

**ವೆಚ್ಚ ಟ್ರ್ಯಾಕಿಂಗ್:** ಪ್ರತಿಯೊಂದು ರಿಕ್ವೆಸ್ಟ್ ಟೋಕನ್ ಬಳಕೆಯನ್ನು ಲಾಗ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಬೆಲೆ ಪಟ್ಟಿಯನ್ನು ಬಳಸಿಕೊಂಡು ವೆಚ್ಚವನ್ನು ಲೆಕ್ಕಹಾಕುತ್ತದೆ. ಪ್ರೊವೈಡರ್, ಮಾಡೆಲ್ ಮತ್ತು API ಕೀಲಿ ಮೂಲಕ **ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಬಳಕೆ** ಯಲ್ಲಿ ವಿಭಜನೆಗಳನ್ನು ವೀಕ್ಷಿಸಿ.

```bash
Content-Type: multipart/form-data
```

### ಕಾಂಬೊ ಬ್ಯಾಲೆನ್ಸಿಂಗ್ ಕಾರ್ಯತಂತ್ರಗಳು

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಕಾಂಬೊಗಳು → ರಚಿಸಿ/ಸಂಪಾದಿಸಿ → ಕಾರ್ಯತಂತ್ರ** ದಲ್ಲಿ ಪ್ರತಿ-ಕಾಂಬೊ ಬ್ಯಾಲೆನ್ಸಿಂಗ್ ಅನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಿ.

| ಕಾರ್ಯತಂತ್ರ             | ವಿವರಣೆ                                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------------- |
| **ರೌಂಡ್-ರಾಬಿನ್**       | ಮಾಡೆಲ್ಗಳ ಮೂಲಕ ಕ್ರಮವಾಗಿ ತಿರುಗುತ್ತದೆ                                                                   |
| **ಪ್ರಾಯೊರిటಿ**         | ಯಾವಾಗಲೂ ಮೊದಲ ಮಾಡೆಲ್ ಅನ್ನು ಪ್ರಯತ್ನಿಸುತ್ತದೆ; ದೋಷದಲ್ಲಿಯೇ ಮಾತ್ರ ಫಾಲ್ಬ್ಯಾಕ್ ಆಗುತ್ತದೆ                      |
| **ರ್ಯಾಂಡಮ್**           | ಪ್ರತಿ ರಿಕ್ವೆಸ್ಟ್ಗಾಗಿ ಕಾಂಬೊದಿಂದ ಯಾದೃಚ್ಛಿಕ ಮಾಡೆಲ್ ಅನ್ನು ಆರಿಸುತ್ತದೆ                                     |
| **ವೆಯ್ಟెಡ್**           | ಪ್ರತಿ ಮಾಡೆಲ್ಗೆ ನಿಯೋಜಿಸಲಾದ ತೂಕಗಳ ಆಧಾರದ ಮೇಲೆ ಅನುಪಾತದಲ್ಲಿ ರೂಟ್ ಮಾಡುತ್ತದೆ                                |
| **ಲೀಸ್ಟ್-ಯೂಸ್ಡ್**      | ಅತ್ಯಂತ ಕಡಿಮೆ ಇತ್ತೀಚಿನ ರಿಕ್ವೆಸ್ಟ್ಗಳನ್ನು ಹೊಂದಿರುವ ಮಾಡೆಲ್ಗೆ ರೂಟ್ ಮಾಡುತ್ತದೆ (ಕಾಂಬೊ ಮೆಟ್ರಿಕ್ಸ್ ಬಳಸುತ್ತದೆ) |
| **ಕಾಸ್ಟ್-ಆಪ್ಟಿಮೈಜ್ಡ್** | ಅಗ್ಗದ ಲಭ್ಯವಿರುವ ಮಾಡೆಲ್ಗೆ ರೂಟ್ ಮಾಡುತ್ತದೆ (ಬೆಲೆ ಪಟ್ಟಿಯನ್ನು ಬಳಸುತ್ತದೆ)                                  |

ಗ್ಲೋಬಲ್ ಕಾಂಬೊ ಡೀಫಾಲ್ಟ್ಗಳನ್ನು **ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಸೆಟ್ಟಿಂಗ್ಗಳು → ರೂಟಿಂಗ್ → ಕಾಂಬೊ ಡೀಫಾಲ್ಟ್ಗಳು** ನಲ್ಲಿ ಹೊಂದಿಸಬಹುದು.
ಕಾಂಬೊ ಟಾರ್ಗೆಟ್ ಟೈಮ್ಔಟ್ಗಳು ಡೀಫಾಲ್ಟ್ ಆಗಿ ಪ್ರಸ್ತುತ ರಿಕ್ವೆಸ್ಟ್ ಟೈಮ್ಔಟ್ ಅನ್ನು ಅನುವಂಶಿಸುತ್ತವೆ. ಕಡಿಮೆ ಪ್ರತಿ-ಟಾರ್ಗೆಟ್
ಮಿತಿಯು ವೇಗವಾಗಿ ಫಾಲ್ಬ್ಯಾಕ್ ಅನ್ನು ಪ್ರಚೋದಿಸಬೇಕಾದಾಗ ಮಾತ್ರ ಕಾಂಬೊ ಡೀಫಾಲ್ಟ್ಗಳಲ್ಲಿ ಅಥವಾ ವೈಯಕ್ತಿಕ ಕಾಂಬೊದಲ್ಲಿ **ಟಾರ್ಗೆಟ್ ಟೈಮ್ಔಟ್
(ಸೆಕೆಂಡುಗಳು)** ಅನ್ನು ಬಳಸಿ.

ಝೀರೋ-ಲೇಟೆನ್ಸಿ ಕಾಂಬೊ ಆಪ್ಟಿಮೈಜೇಶನ್ಗಳು ಆಪ್ಟ್-ಇನ್ ಆಗಿವೆ. ಈ ಲೇಟೆನ್ಸಿ ವೈಶಿಷ್ಟ್ಯಗಳು ಫಾಲ್ಬ್ಯಾಕ್ ಟಾರ್ಗೆಟ್ಗಳನ್ನು
ರೇಸ್ ಮಾಡುವುದನ್ನು, TTFT ಇತಿಹಾಸದ ಆಧಾರದ ಮೇಲೆ ಟಾರ್ಗೆಟ್ಗಳನ್ನು ಸ್ಕಿಪ್ ಮಾಡುವುದನ್ನು, ಅಥವಾ ಫಾಲ್ಬ್ಯಾಕ್ ರಿಕ್ವೆಸ್ಟ್ಗಳನ್ನು
ಸಂಕುಚಿತಗೊಳಿಸುವುದನ್ನು ತಡೆಯಲು **ಝೀರೋ-ಲೇಟೆನ್ಸಿ ಆಪ್ಟಿಮೈಜೇಶನ್ಗಳು** ಅನ್ನು ನಿಷ್ಕ್ರಿಯವಾಗಿಡಿ; ಅದನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿದರೆ,
ಕಡಿಮೆ ಟೇಲ್ ಲೇಟೆನ್ಸಿಗಾಗಿ ರೂಟಿಂಗ್/ರಿಕ್ವೆಸ್ಟ್ ನಿಖರತೆಯನ್ನು ತ್ಯಾಗ ಮಾಡಲು ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಹೆಡ್ಜಿಂಗ್, ಊಹಾತ್ಮಕ TTFT
ಸ್ಕಿಪ್ಗಳು ಮತ್ತು ಪೂರ್ವಸಕ್ರಿಯ ಫಾಲ್ಬ್ಯಾಕ್ ಕಂಪ್ರೆಶನ್ ಅನ್ನು ಅನುಮತಿಸುತ್ತದೆ.

ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರೊವೈಡರ್ಗಳು ಕಟ್ಟುನಿಟ್ಟಾದ `max_tokens` / `maxOutputTokens` ಮಿತಿಗಳನ್ನು ಬಯಸಿದಾಗ **ರೀಸನಿಂಗ್ ಟೋಕನ್ ಬಫರ್** ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ. ಸಕ್ರಿಯಗೊಳಿಸಿದಾಗ, ಕಾಂಬೊ ರೂಟಿಂಗ್ ತಿಳಿದಿರುವ ಔಟ್ಪುಟ್ ಕ್ಯಾಪ್ ಹೊಂದಿರುವ ಮಾಡೆಲ್ಗಳಿಗೆ ಮಾತ್ರ ರೀಸನಿಂಗ್-ಮಾಡೆಲ್ ಹೆಡ್ರೂಮ್ ಅನ್ನು ಸೇರಿಸುತ್ತದೆ ಮತ್ತು ಸುರಕ್ಷಿತ ಬಫರ್ ಮೌಲ್ಯವು ಆ ಕ್ಯಾಪ್ ಅನ್ನು ಮೀರಿದಾಗ ಕ್ಲೈಂಟ್ ಟೋಕನ್ ಮಿತಿಯನ್ನು ಬದಲಾಯಿಸದೆ ಬಿಡುತ್ತದೆ. ಕ್ಲೈಂಟ್ ಮಿತಿಯು ಈಗಾಗಲೇ ತಿಳಿದಿರುವ ಕ್ಯಾಪ್ಗಿಂತ ಮೇಲಿದ್ದರೆ, ಅಪ್ಸ್ಟ್ರೀಮ್ ವಿನಂತಿಯನ್ನು ಕಳುಹಿಸುವ ಮೊದಲು OmniRoute ಅದನ್ನು ಆ ಕ್ಯಾಪ್ಗೆ ಇಳಿಸುತ್ತದೆ.

### ಆರೋಗ್ಯ ಡ್ಯಾಶ್ಬೋರ್ಡ್

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಆರೋಗ್ಯ** ಮೂಲಕ ಪ್ರವೇಶಿಸಿ. 6 ಕಾರ್ಡ್ಗಳೊಂದಿಗೆ ನೈಜ-ಸಮಯದ ಸಿಸ್ಟಮ್ ಆರೋಗ್ಯ ಅವಲೋಕನ:

| ಕಾರ್ಡ್                  | ಇದು ಏನನ್ನು ತೋರಿಸುತ್ತದೆ                                         |
| ----------------------- | -------------------------------------------------------------- |
| **ಸಿಸ್ಟಮ್ ಸ್ಥಿತಿ**      | ಅಪ್ಟೈಮ್, ಆವೃತ್ತಿ, ಮೆಮೊರಿ ಬಳಕೆ, ಡೇಟಾ ಡೈರೆಕ್ಟರಿ                  |
| **ಪ್ರೊವೈಡರ್ ಆರೋಗ್ಯ**    | ಜಾಗತಿಕ ಪ್ರೊವೈಡರ್ ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್ ರನ್ಟೈಮ್ ಸ್ಥಿತಿ              |
| **ರೇಟ್ ಮಿತಿಗಳು**        | ಉಳಿದ ಸಮಯದೊಂದಿಗೆ ಪ್ರತಿ ಖಾತೆಯ ಸಕ್ರಿಯ ಕನೆಕ್ಷನ್ ಕೂಲ್ಡೌನ್ಗಳು        |
| **ಸಕ್ರಿಯ ಲಾಕ್ಔಟ್ಗಳು**   | ಸಕ್ರಿಯ ಮಾಡೆಲ್-ಸ್ಕೋಪ್ ಲಾಕ್ಔಟ್ಗಳು ಮತ್ತು ತಾತ್ಕಾಲಿಕ ಹೊರಗಿಡುವಿಕೆಗಳು |
| **ಸಿಗ್ನೇಚರ್ ಕ್ಯಾಶೆ**    | ಡಿಡುಪ್ಲಿಕೇಶನ್ ಕ್ಯಾಶೆ ಅಂಕಿಅಂಶಗಳು (ಸಕ್ರಿಯ ಕೀಗಳು, ಹಿಟ್ ದರ)        |
| **ಲೇಟೆನ್ಸಿ ಟೆಲಿಮೆಟ್ರಿ** | ಪ್ರತಿ ಪ್ರೊವೈಡರ್ಗೆ p50/p95/p99 ಲೇಟೆನ್ಸಿ ಏಕೀಕರಣ                  |

**ಪ್ರೊ ಟಿಪ್:** ಆರೋಗ್ಯ ಪುಟವು ಪ್ರತಿ 10 ಸೆಕೆಂಡುಗಳಿಗೆ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ರಿಫ್ರೆಶ್ ಆಗುತ್ತದೆ. ಯಾವ ಪ್ರೊವೈಡರ್ಗಳು ಸಮಸ್ಯೆಗಳನ್ನು ಎದುರಿಸುತ್ತಿದ್ದಾರೆ ಎಂಬುದನ್ನು ಗುರುತಿಸಲು ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್ ಕಾರ್ಡ್ ಅನ್ನು ಬಳಸಿ.

## 🤖 ಸ್ವಯಂ-ರೂಟಿಂಗ್ (ಶೂನ್ಯ-ಕಾನ್ಫಿಗ್)

OmniRoute ಪ್ರತಿ ಸಂಪರ್ಕಿತ ಪೂರೈಕೆದಾರನಾದ್ಯಂತ ಪ್ರತಿಯೊಂದು ವಿನಂತಿಗೂ ಅತ್ಯುತ್ತಮ ಮಾದರಿಯನ್ನು ಆಯ್ಕೆಮಾಡುವ **ಸ್ಕೋರ್-ಆಧಾರಿತ ಸ್ವಯಂ-ರೂಟರ್** ಜೊತೆಗೆ ಬರುತ್ತದೆ — ನಿರ್ವಹಿಸಲು ಯಾವುದೇ ಕಾಂಬೊ ಅಗತ್ಯವಿಲ್ಲ. `auto/*` ಪೂರ್ವಪ್ರತ್ಯಯಗಳಲ್ಲಿ ಒಂದನ್ನು ಬಳಸಿ ವಿನಂತಿಯನ್ನು ಕಳುಹಿಸಿ; OmniRoute ವಿಳಂಬ, ವೆಚ್ಚ, ಯಶಸ್ಸಿನ ಪ್ರಮಾಣ, ಸಂದರ್ಭದ ಹೊಂದಾಣಿಕೆ, ಕಾರ್ಯಕ್ಕೆ ಮಾದರಿಯ ಸೂಕ್ತತೆ, ಇತ್ತೀಚಿನ ವೈಫಲ್ಯಗಳು, ಕೋಟಾ ಮತ್ತು ಸರ್ಕ್ಯೂಟ್-ಬ್ರೇಕರ್ ಸ್ಥಿತಿಯ ಆಧಾರದ ಮೇಲೆ ಅಭ್ಯರ್ಥಿಗಳಿಗೆ ಸ್ಕೋರ್ ನೀಡಿ, ತಕ್ಷಣವೇ ಒಂದು ವರ್ಚುವಲ್ ಕಾಂಬೊವನ್ನು ರಚಿಸುತ್ತದೆ.

| ಪೂರ್ವಪ್ರತ್ಯಯ   | ಯಾವುದಕ್ಕಾಗಿ ಆಪ್ಟಿಮೈಸ್ ಮಾಡುತ್ತದೆ                                                                                  |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| `auto`         | ಸಮತೋಲಿತ ಡೀಫಾಲ್ಟ್ (ವಿಳಂಬ × ವೆಚ್ಚ × ಯಶಸ್ಸಿನ ಪ್ರಮಾಣ)                                                                |
| `auto/coding`  | ಕೋಡಿಂಗ್ ಕಾರ್ಯಗಳು: Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek ಕೋಡರ್ಗಳಿಗೆ ಆದ್ಯತೆ ನೀಡುತ್ತದೆ                     |
| `auto/cheap`   | ಕನಿಷ್ಠ $/ಟೋಕನ್, ಹೆಚ್ಚಿನ ವಿಳಂಬವನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ                                                                |
| `auto/fast`    | ಕನಿಷ್ಠ ವಿಳಂಬ, ವೆಚ್ಚವನ್ನು ನಿರ್ಲಕ್ಷಿಸುತ್ತದೆ                                                                        |

| `auto/smart`   | ತಾರ್ಕಿಕ ಗುಣಮಟ್ಟಕ್ಕೆ ಮೊದಲ ಆದ್ಯತೆ (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)                                       |
| `auto/lkgp`    | "ಕೊನೆಯದಾಗಿ ಯಶಸ್ವಿಯಾಗಿದ್ದ ಪೂರೈಕೆದಾರ" — ಕೊನೆಯ ಯಶಸ್ವಿ ಪೂರೈಕೆದಾರನಿಗೆ ಸ್ಥಿರಗೊಳಿಸಿ, ನಂತರ ನಿಯಮಗಳಿಗೆ ಫಾಲ್ಬ್ಯಾಕ್ ಆಗುತ್ತದೆ |

## 🔌 MCP ಮತ್ತು A2A ಏಕೀಕರಣ

OmniRoute ಒಂದು **MCP ಸರ್ವರ್** (Model Context Protocol) ಮತ್ತು **A2A ಸರ್ವರ್** (Agent-to-Agent JSON-RPC 2.0) ಎರಡೂ ಆಗಿದೆ. ಯಾವುದೇ MCP-ಹೊಂದಾಣಿಕೆಯ IDE ಅಥವಾ ಏಜೆಂಟ್ ಹೋಸ್ಟ್ OmniRoute ಪರಿಕರಗಳನ್ನು ನೇರವಾಗಿ ಕರೆಯಬಹುದು — ಹೆಚ್ಚುವರಿ ರ್ಯಾಪರ್ ಅಗತ್ಯವಿಲ್ಲ.

### MCP ಸಾರಿಗೆ ವಿಧಾನಗಳು

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **ಸ್ಟ್ರೀಮ್ ಮಾಡಬಹುದಾದ HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (stdio ಅನ್ನು ಆದ್ಯತೆ ನೀಡುವ IDE ಪ್ಲಗಿನ್ಗಳಿಗಾಗಿ)

### Claude Desktop ಅನ್ನು ಸಂಪರ್ಕಿಸಿ

`~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) ಅಥವಾ Windows/Linux ನಲ್ಲಿನ ಸಮಾನ ಫೈಲ್ ಅನ್ನು ಸಂಪಾದಿಸಿ:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCP ಅನ್ನು ಸಂಪರ್ಕಿಸಿ

SSE URL `http://localhost:20128/api/mcp/sse` ಮತ್ತು **Dashboard → API Keys** ನಲ್ಲಿ ರಚಿಸಿದ Bearer API ಕೀಲಿಯನ್ನು ಬಳಸಿ.

### ವ್ಯಾಪ್ತಿಗಳು

MCP ಪ್ರಸ್ತುತ ಹೆಸರಿಸಲಾದ 32 ವ್ಯಾಪ್ತಿಗಳನ್ನು ವ್ಯಾಖ್ಯಾನಿಸುತ್ತದೆ. ಪ್ರತಿಯೊಂದು Bearer ಕೀಲಿಯನ್ನು ನಿರ್ದಿಷ್ಟ ವ್ಯಾಪ್ತಿಗಳಿಗೆ ಸೀಮಿತಗೊಳಿಸಬಹುದು — ಅಧಿಕೃತ ವ್ಯಾಪ್ತಿ ಮತ್ತು ಪರಿಕರಗಳ ಪಟ್ಟಿಗಾಗಿ [MCP-SERVER.md](../frameworks/MCP-SERVER.md) ಹಾಗೂ JSON-RPC ಸ್ಕೀಮಾಕ್ಕಾಗಿ [A2A-SERVER.md](../frameworks/A2A-SERVER.md) ನೋಡಿ.

## 💾 ಮೆಮೊರಿ ವ್ಯವಸ್ಥೆ

OmniRoute ಹೈಬ್ರಿಡ್ ರಿಟ್ರೀವಲ್ನೊಂದಿಗೆ **ದೀರ್ಘಕಾಲೀನ ಸಂಭಾಷಣಾ ಮೆಮೊರಿ**ಯನ್ನು ಉಳಿಸುತ್ತದೆ:

- ಹಿಂದಿನ ಸಂಭಾಷಣಾ ತಿರುವುಗಳಾದ್ಯಂತ ಕೀವರ್ಡ್ ಹುಡುಕಾಟಕ್ಕಾಗಿ **SQLite FTS5**
- ಅರ್ಥಾಧಾರಿತ ಮರುಸ್ಮರಣೆಗಾಗಿ **Qdrant ವೆಕ್ಟರ್ ಸ್ಟೋರ್** (ಐಚ್ಛಿಕ)
- **ಸ್ವಯಂಚಾಲಿತ ಸಂಗತಿ ಹೊರತೆಗೆಯುವಿಕೆ** — ಪ್ರತಿ ಸೆಷನ್ನ ನಂತರ ಘಟಕಗಳು, ಆದ್ಯತೆಗಳು ಮತ್ತು ನಿರ್ಧಾರಗಳನ್ನು ಸಾರಾಂಶಗೊಳಿಸಿ `memory_facts` ಟೇಬಲ್ನಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ
- ಮೆಮೊರಿಗಳನ್ನು ಪ್ರತಿ API ಕೀ ಮತ್ತು ಪ್ರತಿ ಸೆಷನ್ಗೆ ಪ್ರತ್ಯೇಕವಾಗಿ ಸ್ಕೋಪ್ ಮಾಡಲಾಗುತ್ತದೆ

**Dashboard → Memory** ನಲ್ಲಿ ಮೆಮೊರಿಗಳನ್ನು ನಿರ್ವಹಿಸಿ (ಹುಡುಕಿ, ಸಂಪಾದಿಸಿ, ರಫ್ತು ಮಾಡಿ, ಸಂಪೂರ್ಣವಾಗಿ ಅಳಿಸಿ). HTTP ಇಂಟರ್ಫೇಸ್ (`/api/memory/*`) ಏಜೆಂಟ್ಗಳಿಗೆ ಪ್ರೋಗ್ರಾಮ್ಯಾಟಿಕ್ ಆಗಿ ಸಂಗತಿಗಳನ್ನು ಕಳುಹಿಸಲು ಮತ್ತು ಪ್ರಶ್ನಿಸಲು ಅವಕಾಶ ನೀಡುತ್ತದೆ — [MEMORY.md](../frameworks/MEMORY.md) ನೋಡಿ.

## 🔔 ವೆಬ್ಹುಕ್ಗಳು

ನೈಜ-ಸಮಯದ ಮೇಲ್ವಿಚಾರಣೆ ಮತ್ತು ಸ್ವಯಂಚಾಲನೆಗಾಗಿ OmniRoute ಈವೆಂಟ್ಗಳಿಗೆ ಚಂದಾದಾರರಾಗಿ.

- ಗುರಿ URL ಮತ್ತು HMAC ಸಹಿ ಸೀಕ್ರೆಟ್ನೊಂದಿಗೆ **Dashboard → Webhooks** ನಲ್ಲಿ ವೆಬ್ಹುಕ್ ರಚಿಸಿ

- ಮರುಪ್ರಯತ್ನಗಳು: ಎಕ್ಸ್ಪೊನೆನ್ಷಿಯಲ್ ಬ್ಯಾಕ್ಆಫ್ನೊಂದಿಗೆ 3 ಪ್ರಯತ್ನಗಳು, ನಂತರ ಡೆಡ್-ಲೆಟರ್ ಕ್ಯೂ

## 🛠️ ಪ್ರೋಗ್ರಾಮ್ಯಾಟಿಕ್ ನಿರ್ವಹಣೆ

**`manage` ಸ್ಕೋಪ್ ಹೊಂದಿರುವ Bearer ಕೀ** ಬಳಸಿ HTTP ಮೂಲಕ ಪ್ರತಿಯೊಂದು OmniRoute ಸಂಪನ್ಮೂಲವನ್ನು (ಪ್ರೊವೈಡರ್ಗಳು, ಕಾಂಬೊಗಳು, ಕೀಗಳು, ಸೆಟ್ಟಿಂಗ್ಗಳು) ನಿರ್ವಹಿಸಬಹುದು.

**Dashboard → API Keys → New Key → Scope: manage** ನಲ್ಲಿ ಕೀಯನ್ನು ರಚಿಸಿ, ನಂತರ:

```bash
# ಪ್ರೊವೈಡರ್ಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# ಪ್ರೊವೈಡರ್ ಸಂಪರ್ಕವನ್ನು ಸೇರಿಸಿ
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# ಕಾಂಬೊ ರಚಿಸಿ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API ಕೀಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ/ರಚಿಸಿ
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

ಸಂಪೂರ್ಣ ಎಂಡ್ಪಾಯಿಂಟ್ ಕ್ಯಾಟಲಾಗ್ ಮತ್ತು ವಿನಂತಿ/ಪ್ರತಿಕ್ರಿಯೆ ಸ್ಕೀಮಾಗಳಿಗಾಗಿ [API_REFERENCE.md](../reference/API_REFERENCE.md) ನೋಡಿ.

## 💻 ಆಂತರಿಕ CLI

ಸೆಟಪ್, ಡಯಾಗ್ನೋಸ್ಟಿಕ್ಸ್ ಮತ್ತು ರನ್ಟೈಮ್ ನಿಯಂತ್ರಣಕ್ಕಾಗಿ OmniRoute ಆಂತರಿಕ CLI (`omniroute …`) ಅನ್ನು ಒದಗಿಸುತ್ತದೆ. ಇದು ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿರುವ **"CLI ಪರಿಕರಗಳು" ಪುಟದಿಂದ ಪ್ರತ್ಯೇಕವಾಗಿದೆ**; ಆ ಪುಟವು ತೃತೀಯ-ಪಕ್ಷದ CLI ಗಳನ್ನು (Claude Code, Cursor, Codex, Cline, …) OmniRoute ಜೊತೆಗೆ ಸಂವಹನ ನಡೆಸುವಂತೆ ಕಾನ್ಫಿಗರ್ ಮಾಡುತ್ತದೆ.

```bash
omniroute setup                    # ಸಂವಾದಾತ್ಮಕ ವಿಝಾರ್ಡ್ (ಪಾಸ್ವರ್ಡ್, ಪೂರೈಕೆದಾರರು, ಕಾಂಬೊಗಳು)
omniroute setup --non-interactive  # CIಗೆ ಸೂಕ್ತವಾಗಿದೆ
omniroute doctor                   # ಸ್ಥಿತಿಗತಿ ಡಯಾಗ್ನೋಸ್ಟಿಕ್ಸ್ (ಡೇಟಾ ಡೈರೆಕ್ಟರಿ, DB, ಪೂರೈಕೆದಾರರು, ಪೋರ್ಟ್ಗಳು)
omniroute providers available      # ಬೆಂಬಲಿತ ಪೂರೈಕೆದಾರರನ್ನು ಪಟ್ಟಿ ಮಾಡಿ
omniroute providers list           # ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಸಂಪರ್ಕಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ
omniroute providers test <id>      # ಪೂರೈಕೆದಾರರ ಸಂಪರ್ಕವನ್ನು ಲೈವ್ ಆಗಿ ಪರೀಕ್ಷಿಸಿ
omniroute combos list              # ಕಾಂಬೊಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ
omniroute combos switch <name>     # ಡೀಫಾಲ್ಟ್ ಕಾಂಬೊವನ್ನು ಹೊಂದಿಸಿ
omniroute models                   # ಲಭ್ಯವಿರುವ ಮಾಡೆಲ್ಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ (--json, --search)
omniroute keys add | list | remove # ಟರ್ಮಿನಲ್ನಿಂದ API ಕೀಗಳನ್ನು ನಿರ್ವಹಿಸಿ
omniroute backup                   # ಕಾನ್ಫಿಗ್ + DB ಸ್ನ್ಯಾಪ್ಶಾಟ್ ತೆಗೆದುಕೊಳ್ಳಿ
omniroute restore [<timestamp>]    # ಸ್ನ್ಯಾಪ್ಶಾಟ್ನಿಂದ ಮರುಸ್ಥಾಪಿಸಿ
omniroute health                   # ವಿವರವಾದ ಸ್ಥಿತಿಗತಿ (ಬ್ರೇಕರ್ಗಳು, ಕ್ಯಾಶ್, ಮೆಮೊರಿ)
omniroute quota                    # ಪೂರೈಕೆದಾರರ ಕೋಟಾ ಬಳಕೆ
omniroute mcp status               # MCP ಸರ್ವರ್ ಸ್ಥಿತಿ
omniroute a2a status               # A2A ಸರ್ವರ್ ಸ್ಥಿತಿ
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok ಟನಲ್ಗಳು
omniroute reset-password           # ನಿರ್ವಾಹಕರ ಪಾಸ್ವರ್ಡ್ ಮರುಹೊಂದಿಸಿ
omniroute --mcp                    # stdio ಮೂಲಕ MCP ಸರ್ವರ್ ಪ್ರಾರಂಭಿಸಿ
omniroute --port 3000              # ಕಸ್ಟಮ್ ಪೋರ್ಟ್ನಲ್ಲಿ ಸರ್ವರ್ ಪ್ರಾರಂಭಿಸಿ
```

ಸಲಹೆ: ಅನಾರೋಗ್ಯಕರ ಪೂರೈಕೆದಾರರ ಸಂಪರ್ಕಗಳ ಕುರಿತು ಎಚ್ಚರಿಕೆ ಪಡೆಯಲು `omniroute doctor --json` ಅನ್ನು ನಿಮ್ಮ ಮೇಲ್ವಿಚಾರಣಾ ಪರಿಕರದೊಂದಿಗೆ ಜೋಡಿಸಿ.

## 🖥️ ಡೆಸ್ಕ್ಟಾಪ್ ಅಪ್ಲಿಕೇಶನ್ (Electron)

OmniRoute Windows, macOS ಮತ್ತು Linux ಗಾಗಿ ಸ್ಥಳೀಯ ಡೆಸ್ಕ್ಟಾಪ್ ಅಪ್ಲಿಕೇಶನ್ ಆಗಿ ಲಭ್ಯವಿದೆ.

### ಸ್ಥಾಪನೆ

```bash
# electron ಡೈರೆಕ್ಟರಿಯಿಂದ:
cd electron
npm install

# ಡೆವಲಪ್ಮೆಂಟ್ ಮೋಡ್ (ಚಾಲನೆಯಲ್ಲಿರುವ Next.js ಡೆವ್ ಸರ್ವರ್ಗೆ ಸಂಪರ್ಕಿಸುತ್ತದೆ):
npm run dev

# ಪ್ರೊಡಕ್ಷನ್ ಮೋಡ್ (ಸ್ವತಂತ್ರ ಬಿಲ್ಡ್ ಬಳಸುತ್ತದೆ):
npm start
```

### ಇನ್ಸ್ಟಾಲರ್ಗಳನ್ನು ಬಿಲ್ಡ್ ಮಾಡುವುದು

```bash
cd electron
npm run build          # ಪ್ರಸ್ತುತ ಪ್ಲಾಟ್ಫಾರ್ಮ್
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg ಯುನಿವರ್ಸಲ್)
npm run build:linux    # Linux (.AppImage)
```

ಔಟ್ಪುಟ್ → `electron/dist-electron/`
