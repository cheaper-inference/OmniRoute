**Claude Code** CLI (`claude`) ಅನ್ನು OmniRoute ಕಡೆಗೆ ಪಾಯಿಂಟ್ ಮಾಡಿ — ಸ್ಥಳೀಯ ಅಥವಾ ರಿಮೋಟ್ VPS —
Codex ಸೆಟಪ್ ಅನ್ನು ಪ್ರತಿಬಿಂಬಿಸುವ ಪ್ರತಿ-ಮಾದರಿ ಪ್ರೊಫೈಲ್ಗಳೊಂದಿಗೆ.

---

## ತ್ವರಿತ ಪ್ರಾರಂಭ

```bash
# ಸಕ್ರಿಯ ಕಾಂಟೆಕ್ಸ್ಟ್ ಅನ್ನು ಸ್ವಯಂ-ಪತ್ತೆಮಾಡಿ, ಸ್ಥಳೀಯ OmniRoute ವಿರುದ್ಧ Claude Code ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ
omniroute launch

# ರಿಮೋಟ್ OmniRoute ವಿರುದ್ಧ (`omniroute connect <host>` ನಂತರ, ಇದು ಸ್ವಯಂಚಾಲಿತವಾಗಿರುತ್ತದೆ)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# ಪ್ರತಿ-ಮಾದರಿ ಪ್ರೊಫೈಲ್ಗಳನ್ನು ರಚಿಸಿ, ನಂತರ ಒಂದನ್ನು ಪ್ರಾರಂಭಿಸಿ
omniroute setup-claude            # ~/.claude/profiles/<name>/settings.json ಗೆ ಬರೆಯುತ್ತದೆ
omniroute launch --profile glm52  # OmniRoute ಮೂಲಕ glm/glm-5.2 ಬಳಸುವ Claude Code
```

## Claude ಕೋಡ್ ಗೇಟ್ವೇಗೆ ಹೇಗೆ ಸಂಪರ್ಕಿಸುತ್ತದೆ

Claude ಕೋಡ್ ಮಾತನಾಡುತ್ತದೆ**Anthropic ಸಂದೇಶಗಳು API** ಮತ್ತು ಪರಿಸರ ವೇರಿಯಬಲ್ಗಳೊಂದಿಗೆ ಕಸ್ಟಮ್ ಎಂಡ್ಪಾಯಿಂಟ್ನಲ್ಲಿ ಸೂಚಿಸಲಾಗಿದೆ (ಇದು ಯಾವುದೇ `--base-url` ಫ್ಲ್ಯಾಗ್ ಅನ್ನು ಹೊಂದಿಲ್ಲ):

| ವೇರಿಯಬಲ್                                     | ಉದ್ದೇಶ                                                                                           |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `ANTHROPIC_BASE_URL`                         | ಗೇಟ್ವೇ ರೂಟ್ URL (Claude ಕೋಡ್ `/v1/messages` ಅನ್ನು ಸೇರಿಸುತ್ತದೆ).** `/v1` ಪ್ರತ್ಯಯವಿಲ್ಲ.**          |
| `ANTHROPIC_AUTH_TOKEN`                       | `Authorization: Bearer …` — ಆಗಿ ಕಳುಹಿಸಲಾಗಿದೆ ನಿಮ್ಮ OmniRoute ಪ್ರವೇಶ ಟೋಕನ್ / API ಕೀ ಬಳಸಿ          |
| `ANTHROPIC_API_KEY`                          | ಪರ್ಯಾಯ: `x-api-key` ಎಂದು ಕಳುಹಿಸಲಾಗಿದೆ. ಎರಡೂ ಹೊಂದಿಸಿದರೆ, `ANTHROPIC_AUTH_TOKEN` ಗೆಲ್ಲುತ್ತದೆ       |
| `ANTHROPIC_MODEL`                            | ನಿರ್ದಿಷ್ಟ ಮಾದರಿಯನ್ನು ಒತ್ತಾಯಿಸಿ ( `/model` ಪಿಕರ್ ಡೀಫಾಲ್ಟ್ ಅನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತದೆ)                  |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → ಸ್ಥಳೀಯ `/model` ಪಿಕರ್ `/v1/models` ನಿಂದ `claude*`/`anthropic*` ಮಾದರಿಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | ಪ್ರತಿ ಪ್ರತಿಕ್ರಿಯೆಗೆ ಕ್ಯಾಪ್ ಔಟ್ಪುಟ್ ಟೋಕನ್ಗಳು (ಉದಾ `65536`)                                        |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | ಸ್ವಯಂ ಸಂಕೋಚನಕ್ಕಾಗಿ ಟೋಕನ್ ಥ್ರೆಶೋಲ್ಡ್                                                              |

> Env vars ಅನ್ನು ಓದಲಾಗುತ್ತದೆ** ಒಮ್ಮೆ ಪ್ರಾರಂಭದಲ್ಲಿ** — ಅವುಗಳನ್ನು ಬದಲಾಯಿಸಿದ ನಂತರ Claude ಕೋಡ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ.

ಸ್ಥಿರ ಸ್ಟ್ರಿಂಗ್ ಬದಲಿಗೆ ತಿರುಗುವ ರುಜುವಾತುಗಳಿಗಾಗಿ, ಪ್ರಸ್ತುತ ರುಜುವಾತುಗಳನ್ನು stdout ಗೆ ಮುದ್ರಿಸುವ ಆಜ್ಞೆಗೆ `~/.claude/settings.json` ನಲ್ಲಿ `apiKeyHelper` ಹೊಂದಿಸಿ. Claude ಕೋಡ್ ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಐದು ನಿಮಿಷಗಳ ಕಾಲ ಅದರ ಔಟ್ಪುಟ್ ಅನ್ನು ಕ್ಯಾಶ್ ಮಾಡುತ್ತದೆ (`CLAUDE_CODE_API_KEY_HELPER_TTL_MS` ಅದನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತದೆ) ಮತ್ತು ಮೌಲ್ಯವನ್ನು `Authorization: Bearer` ಮತ್ತು `x-api-key` ಎರಡರಲ್ಲೂ ಕಳುಹಿಸುತ್ತದೆ. ಸ್ಕ್ರಿಪ್ಟ್ ರುಜುವಾತುಗಳನ್ನು ಮುದ್ರಿಸಬೇಕು ಮತ್ತು ಬೇರೆ ಯಾವುದೂ — ಜೊತೆಗೆ ಬ್ಯಾನರ್ v2.1.227 + ನಲ್ಲಿ ಸಹಾಯಕ ವಿಫಲಗೊಳ್ಳುತ್ತದೆ.

Entra ID SSO ಈ ರೀತಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ: API ಕೀಯ ಬದಲಿಗೆ OmniRoute ಪರಿಶೀಲಿಸುವ ಅಲ್ಪಾವಧಿಯ Entra ಪ್ರವೇಶ ಟೋಕನ್ ಅನ್ನು `scripts/cli/omniroute-sso.mjs token` ಮುದ್ರಿಸುತ್ತದೆ. [`docs/security/ENTRA_SSO.md`](../security/ENTRA_SSO.md) ನೋಡಿ.

`omniroute launch` ಇವೆಲ್ಲವನ್ನೂ ನಿಮಗಾಗಿ ಹೊಂದಿಸುತ್ತದೆ: ಇದು ಸಕ್ರಿಯ ಸಂದರ್ಭದಿಂದ ಬೇಸ್ URL + ಟೋಕನ್ ಅನ್ನು ಪರಿಹರಿಸುತ್ತದೆ (ಆದ್ದರಿಂದ `omniroute connect <vps>` ನಂತರ `omniroute launch` ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ), ಸರ್ವರ್ ಅನ್ನು ಆರೋಗ್ಯ-ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು `claude` ಕಾರ್ಯಗತಗೊಳಿಸುತ್ತದೆ.

## ಬಳಕೆಯ ಗುಣಲಕ್ಷಣ: ಅವಧಿಗಳು ಮತ್ತು ಯೋಜನೆಗಳು

OmniRoute ಗುಂಪುಗಳು ಪ್ರತಿ API ಕೀಲಿಯ ವಿನಂತಿಗಳನ್ನು ಒಳಗೆ** ಏಜೆಂಟ್ ಅವಧಿಗಳು** ಮತ್ತು ದಾಖಲೆಗಳು** ಯೋಜನೆ** ಪ್ರತಿ ಸೆಶನ್ನಲ್ಲಿ (`agent_sessions` ಟೇಬಲ್) ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಪ್ರತಿ ತಂಡದ ಸದಸ್ಯರಿಗೆ, ಪ್ರತಿ ಯೋಜನೆಗೆ ಮತ್ತು ಪ್ರತಿ ಸೆಷನ್ಗೆ ಬಳಕೆ ಮತ್ತು ವೆಚ್ಚವನ್ನು ವರದಿ ಮಾಡಬಹುದು.

ಯಾವುದೇ ಕ್ಲೈಂಟ್ ಸೆಟಪ್ ಇಲ್ಲದೆ ಏನು ರೆಕಾರ್ಡ್ ಮಾಡಲಾಗಿದೆ:

| ಕ್ಷೇತ್ರ | ಮೂಲ                                                                                                                                                                   |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ಅಧಿವೇಶನ | `x-claude-code-session-id` ಹೆಡರ್ ( `metadata.user_id.session_id` ಯಂತೆಯೇ ಅದೇ ಮೌಲ್ಯ), ಪ್ರತಿ ಸೆಷನ್ಗೆ ಸ್ಥಿರವಾಗಿರುತ್ತದೆ                                                    |
| ಯೋಜನೆ   | `Primary working directory:` ಲೈನ್ Claude ಕೋಡ್ ತನ್ನ ಪರಿಸರ ಸಂದೇಶದಲ್ಲಿ ಕಳುಹಿಸುತ್ತದೆ; `.claude/worktrees/` ಅಡಿಯಲ್ಲಿ ವರ್ಕ್ಟ್ರೀ ಫೋಲ್ಡರ್ಗಳು ರೆಪೊಸಿಟರಿ ಹೆಸರನ್ನು ಪರಿಹರಿಸುತ್ತವೆ |
| ಶಾಖೆ    | git ಸ್ಥಿತಿ Claude ಕೋಡ್ನಿಂದ `Current branch:` ಮೊದಲ ಸಂದೇಶದೊಂದಿಗೆ ಕಳುಹಿಸುತ್ತದೆ                                                                                           |
| ಗ್ರಾಹಕ  | `user-agent` (`claude-cli/<version>`)                                                                                                                                 |

Codex (`<environment_context><cwd>`) ಮತ್ತು OpenCode (`x-opencode-session`) ಅನ್ನು ಅದೇ ರೀತಿಯಲ್ಲಿ ಗುರುತಿಸಲಾಗಿದೆ. ಜೊತೆ ಕೀಲಿಗಳು** ನೋ-ಲಾಗ್** ಸೆಷನ್ ಐಡಿ ಮತ್ತು ಹೆಡರ್-ಸರಬರಾಜು ಪ್ರಾಜೆಕ್ಟ್ ಕ್ಷೇತ್ರಗಳನ್ನು ಮಾತ್ರ ಸಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ; ಪ್ರಾಂಪ್ಟ್ನಿಂದ ಓದಿದ ಯಾವುದನ್ನೂ (ಮಾರ್ಗ, ಶಾಖೆ) ಸಂಗ್ರಹಿಸಲಾಗಿಲ್ಲ.

### ಯೋಜನೆಯನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಹೆಸರಿಸುವುದು (ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ)

ಕೆಲಸ ಮಾಡುವ ಡೈರೆಕ್ಟರಿಯು ಯಂತ್ರಗಳ ನಡುವೆ ಭಿನ್ನವಾಗಿರುತ್ತದೆ, ಆದ್ದರಿಂದ ಒಂದೇ ರೆಪೊಸಿಟರಿಯು ವಿಭಿನ್ನ ಮಾರ್ಗಗಳ ಅಡಿಯಲ್ಲಿ ತೋರಿಸಬಹುದು. ಬದಲಿಗೆ ಪ್ರಾಜೆಕ್ಟ್ ಅನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಕಳುಹಿಸಿ: Claude ಕೋಡ್ ಪ್ರತಿ ಮಾದರಿ ವಿನಂತಿಗೆ `ANTHROPIC_CUSTOM_HEADERS` ನಲ್ಲಿ ಪಟ್ಟಿ ಮಾಡಲಾದ ಯಾವುದೇ ಹೆಡರ್ಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ ಮತ್ತು OmniRoute ಅವುಗಳಲ್ಲಿ ಎರಡನ್ನು ಓದುತ್ತದೆ:

| ಶಿರೋಲೇಖ                    | ಮೌಲ್ಯ                                                         |
| -------------------------- | ------------------------------------------------------------- |
| `x-omniroute-project`      | ಯೋಜನೆಯ ಹೆಸರು, ಉದಾ `omniroute`                                 |
| `x-omniroute-project-repo` | ಸಾಧಾರಣಗೊಳಿಸಿದ ರಿಮೋಟ್, ಉದಾ `github.com/diegosouzapw/OmniRoute` |

ಎರಡನ್ನೂ ಗುಣಲಕ್ಷಣಕ್ಕಾಗಿ ಮಾತ್ರ ಓದಲಾಗುತ್ತದೆ; ಅವುಗಳನ್ನು ಎಂದಿಗೂ ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರಿಗೆ ರವಾನಿಸಲಾಗುವುದಿಲ್ಲ.

`ANTHROPIC_CUSTOM_HEADERS` ಅನ್ನು ಪ್ರಾರಂಭದಲ್ಲಿ ಒಮ್ಮೆ ಓದಲಾಗುತ್ತದೆ ಮತ್ತು ಸೆಟ್ಟಿಂಗ್ಗಳ ಫೈಲ್ಗಳು ಅಕ್ಷರಶಃ ಮೌಲ್ಯಗಳನ್ನು ಸಂಗ್ರಹಿಸುತ್ತವೆ, ಆದ್ದರಿಂದ Claude ಕೋಡ್ ಪ್ರಾರಂಭವಾದಾಗ ಅದನ್ನು ಲೆಕ್ಕಾಚಾರ ಮಾಡಿ. ಇದನ್ನು `~/.zshrc` ಅಥವಾ `~/.bashrc` ಗೆ ಸೇರಿಸಿ ಮತ್ತು ಪ್ರಾಜೆಕ್ಟ್ ಫೋಲ್ಡರ್ನಿಂದ `claude` ಪ್ರಾರಂಭಿಸಿ:

```bash
claude() {
  local common name repo
  if common=$(git rev-parse --path-format=absolute --git-common-dir 2>/dev/null); then
    name=$(basename "$(dirname "$common")")  # repository name, also inside worktrees
    repo=$(git remote get-url origin 2>/dev/null \
      | sed -E 's#^[a-zA-Z][a-zA-Z0-9+.-]*://([^@/]*@)?##; s#^[^@/]+@([^:]+):#\1/#; s#\.git$##')
  else
    name=$(basename "$PWD")                  # not a git repository: folder name
  fi
  ANTHROPIC_CUSTOM_HEADERS="x-omniroute-project: ${name}${repo:+
x-omniroute-project-repo: ${repo}}" command claude "$@"
}
```

ರಿಮೋಟ್ URL ನಲ್ಲಿ ಹುದುಗಿರುವ ಯಾವುದೇ ರುಜುವಾತುಗಳನ್ನು `sed` ಅಭಿವ್ಯಕ್ತಿ ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ. IDE ವಿಸ್ತರಣೆಗಳು ನಿಮ್ಮ ಶೆಲ್ ಇಲ್ಲದೆಯೇ Claude ಕೋಡ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸುತ್ತವೆ, ಆದ್ದರಿಂದ ಅವುಗಳ ಅವಧಿಗಳು ಕಾರ್ಯನಿರ್ವಹಿಸುವ ಡೈರೆಕ್ಟರಿಗೆ ಹಿಂತಿರುಗುತ್ತವೆ.

## ಡಿಸ್ಕವರಿ ಅಲಿಯಾಸ್ಗಳು — `/model` ಪಿಕ್ಕರ್ನಲ್ಲಿ Claude ಅಲ್ಲದ ಮಾಡೆಲ್ಗಳನ್ನು ತೋರಿಸುವುದು

Claude Code ನ ಗೇಟ್ವೇ ಮಾಡೆಲ್ ಡಿಸ್ಕವರಿಯು `claude` ಅಥವಾ `anthropic` ದಿಂದ ಪ್ರಾರಂಭವಾಗುವ id ಗಳನ್ನು ಮಾತ್ರ ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ. ಆದ್ದರಿಂದ `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` ಆಗಿದ್ದರೂ, ನಿಜವಾದ `/model` ಪಿಕ್ಕರ್ ಸಾಮಾನ್ಯವಾಗಿ OmniRoute ನ Claude/Anthropic ಮಾಡೆಲ್ಗಳನ್ನು **ಮಾತ್ರ** ತೋರಿಸುತ್ತದೆ — `kimi/kimi-k2.6` ಅಥವಾ `glm/glm-5.2` ಸರಿಯಾಗಿ ರೂಟ್ ಆಗುತ್ತಿದ್ದರೂ ಎಂದಿಗೂ ಕಾಣಿಸುವುದಿಲ್ಲ.

OmniRoute ಯಾವುದೇ ಸಕ್ರಿಯಗೊಳಿಸಿದ ಮಾಡೆಲ್ (ಮತ್ತು ಕಾಂಬೊ) ವನ್ನು `claude/…` id ಅಡಿಯಲ್ಲಿ ಮಿರರ್ ಮಾಡಬಹುದು, ಇದರಿಂದ ಅದು ಆ ಫಿಲ್ಟರ್ ಅನ್ನು ದಾಟಿ ಪಿಕ್ಕರ್ನಲ್ಲಿ ಕಾಣಿಸುತ್ತದೆ:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

Claude Code ನಲ್ಲಿ ನೀವು ಇವುಗಳಲ್ಲಿ ಒಂದನ್ನು ಆಯ್ದಾಗ, OmniRoute ರೂಟಿಂಗ್ ಮಾಡುವ ಮೊದಲು `claude/` ಹೊರಭಾಗವನ್ನು ತೆಗೆದು ನಿಜವಾದ id ಗೆ ಹಿಂತಿರುಗಿಸುತ್ತದೆ — ನಿಜವಾದ `claude/<real-claude-model>` id (ನಿಜವಾದ Claude OAuth ಪ್ರೊವೈಡರ್) ಯಾವಾಗಲೂ ಮುಟ್ಟದಂತೆ ಬಿಡಲಾಗುತ್ತದೆ.

ಡೀಫಾಲ್ಟ್ ಆಗಿ ಬೇಸ್ id ಗಳನ್ನು ಮಾತ್ರ ಮಿರರ್ ಮಾಡಲಾಗುತ್ತದೆ. ಆಪ್ಟ್-ಇನ್ `CATALOG_MIRROR_REFINEMENTS_ENABLED` ಫೀಚರ್ ಫ್ಲ್ಯಾಗ್ ಆನ್ ಆಗಿದ್ದರೆ, ಕ್ಯಾಟಲಾಗ್ ಈಗಾಗಲೇ ಪಟ್ಟಿ ಮಾಡಿರುವ ರೀಸನಿಂಗ್-ಎಫರ್ಟ್ ವೇರಿಯಂಟ್ಗಳು (ಉದಾ. `codex/gpt-6-sol-high`) ಬೇರೆ ಯಾವುದೇ id ನಂತೆ ಮಿರರ್ ಆಗುತ್ತವೆ, ಆದ್ದರಿಂದ Claude Code ಸ್ಪಷ್ಟ ಎಫರ್ಟ್ ಹಂತವನ್ನು ಆಯ್ಕೆ ಮಾಡಬಹುದು. ರಿಕ್ವೆಸ್ಟ್ ಪಾತ್ ರೂಪಿಸಲಾಗದ ಬಿಲ್ಟ್-ಇನ್ `auto/*` id ಗಳನ್ನು ಮಿರರ್ ಮಾಡಲಾಗುವುದಿಲ್ಲ. ಎಫರ್ಟ್ ವೇರಿಯಂಟ್ಗಳು ಪಟ್ಟಿ ಆಗುತ್ತವೆಯೇ ಎಂಬುದನ್ನು ಇನ್ನೂ `OMNIROUTE_DISABLE_THINKING_LEVEL_VARIANTS` ನಿಯಂತ್ರಿಸುತ್ತದೆ — ಬೇಸ್ ಕ್ಯಾಟಲಾಗ್ನಲ್ಲಿ ಇಲ್ಲದ ವೇರಿಯಂಟ್ ಅನ್ನು ಮಿರರ್ ಎಂದಿಗೂ ಸೇರಿಸುವುದಿಲ್ಲ.

**ಇದು ಡೀಫಾಲ್ಟ್ ಆಗಿ ಆಫ್ ಆಗಿದೆ** ಮತ್ತು ಮೂರು-ಹಂತದ ಗೇಟ್ (ಹೆಚ್ಚು ನಿರ್ದಿಷ್ಟವಾದದ್ದು ಗೆಲುತ್ತದೆ) ಮೂಲಕ ನಿಯಂತ್ರಿಸಲಾಗುತ್ತದೆ. ಆದ್ದರಿಂದ Claude Code ಬಳಸದ ಕ್ಲೈಂಟ್ಗಳಿಗೆ ಸಾಧಾರಣ OmniRoute ತನ್ನ ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ಎರಡರಷ್ಟು ಮಾಡುವುದಿಲ್ಲ:

| ಹಂತ       | ಎಲ್ಲಿ                                                                              |
| --------- | ---------------------------------------------------------------------------------- |
| ಮಾಡೆಲ್    | ಪ್ರೊವೈಡರ್ ವಿವರ ಪುಟ → ಪ್ರತಿ-ಮಾಡೆಲ್ "Expose in Claude Code" ಟಾಗಲ್                    |
| ಪ್ರೊವೈಡರ್ | ಪ್ರೊವೈಡರ್ ವಿವರ ಪುಟ → ಪ್ರೊವೈಡರ್-ಮಟ್ಟದ ಟಾಗಲ್ (ಅದರ ಎಲ್ಲಾ ಮಾಡೆಲ್ಗಳನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ) |
| ಜಾಗತಿಕ    | Settings → Feature Flags → `EXPOSE_CC_DISCOVERY_ALIASES` (ಡೀಫಾಲ್ಟ್ ಆಫ್)            |

`EXPOSE_CC_DISCOVERY_ALIASES` ಎನ್ವಿರಾನ್ಮೆಂಟ್ ವೇರಿಯಬಲ್ ಜಾಗತಿಕ ಮಟ್ಟವನ್ನು ಒತ್ತಾಯದಿಂದ ಆನ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಓವರ್ರೈಡ್ಗಿಂತ ಹೆಚ್ಚಿನ ಪ್ರಾಥಮ್ಯತೆ ಪಡೆಯುತ್ತದೆ (ಅಂತಹ ಸಂದರ್ಭದಲ್ಲಿ Feature Flags ಪರದೆಯು "active via environment variable" ಟಿಪ್ಪಣಿಯನ್ನು ತೋರಿಸುತ್ತದೆ). ಪ್ರತಿ-ಪ್ರೊವೈಡರ್ ಮತ್ತು ಪ್ರತಿ-ಮಾಡೆಲ್ ಟಾಗಲ್ಗಳು ಅಲ್ಲಿಂದ ಪರಿಷ್ಕರಿಸುತ್ತವೆ — ಉದಾ. ಜಾಗತಿಕ ಆಫ್ + Kimi ಪ್ರೊವೈಡರ್ ಆನ್ ಆಗಿದ್ದರೆ Kimi ಯ ಮಾಡೆಲ್ಗಳನ್ನು ಮಾತ್ರ ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ.

> ⚠️ **Claude ಅಲ್ಲದ ಮಾಡೆಲ್ಗಳಲ್ಲಿ ವಿಂಡೋ ಹೊಂದಾಣಿಕೆಯಿಲ್ಲದಿರುವಿಕೆ.** Claude Code ತಾನು ಗುರುತಿಸದ ಯಾವುದೇ id ಗೆ 200K ಕಾಂಟೆಕ್ಸ್ಟ್ ವಿಂಡೋವನ್ನು ಊಹಿಸುತ್ತದೆ (ಅದು `/v1/models` ನಿಂದ ನಿಜವಾದ ವಿಂಡೋವನ್ನು ಓದಲಾಗುವುದಿಲ್ಲ). ದೊಡ್ಡ ವಿಂಡೋ ಹೊಂದಿರುವ ಮಾಡೆಲ್ಗೆ (ಉದಾ. Kimi K2 ಯ 256K), `CLAUDE_CODE_AUTO_COMPACT_WINDOW` ಅನ್ನು ಮಾಡೆಲ್ನ ನಿಜವಾದ ವಿಂಡೋಗಿಂತ ಕಡಿಮೆ ಮೌಲ್ಯಕ್ಕೆ ಹೊಂದಿಸಿ, ಇದರಿಂದ ಆಟೋ-ಕಾಂಪ್ಯಾಕ್ಷನ್ ಮುಂಚಿತವಾಗಿ ಸಕ್ರಿಯಗೊಳ್ಳುವುದಿಲ್ಲ. ಮೇಲಿನ ಜನರೇಟ್ ಮಾಡಿದ ಪ್ರೊಫೈಲ್ಗಳು ಇದನ್ನು ಈಗಾಗಲೇ ಪ್ರತಿ-ಮಾಡೆಲ್ ಮಟ್ಟದಲ್ಲಿ ಮಾಡುತ್ತವೆ.

## ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿನ ಆನ್ಬೋರ್ಡಿಂಗ್ ಬ್ಲಾಕ್

Claude ಟೂಲ್ ಕಾರ್ಡ್ (**Dashboard → CLI Code**) ಈ ಇನ್ಸ್ಟನ್ಸ್ಗಾಗಿ ನಿಖರವಾದ `settings.json` ತುಣುಕನ್ನು ಡಿಸ್ಕವರಿ-ಅಲಿಯಾಸ್ ಮಾಹಿತಿ ಬಟನ್ನ ಪಕ್ಕದಲ್ಲಿ, ಕಾಪಿ ಬಟನ್ನೊಂದಿಗೆ ಪ್ರದರ್ಶಿಸುತ್ತದೆ:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<ನಿಮ್ಮ OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<ನಿಮ್ಮ OmniRoute API ಕೀ>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

ಮೂಲ URL ಎಂಬುದು ಕಾರ್ಡ್ ಪರಿಹರಿಸಿದ URL ಆಗಿರುತ್ತದೆ (ನೀವು ನಮೂದಿಸಿದ ಕಸ್ಟಮ್ ಓವರ್ರೈಡ್ ಸೇರಿದಂತೆ), ಮತ್ತು ಈಗಾಗಲೇ ಸಾಮಾನ್ಯೀಕರಿಸಲ್ಪಟ್ಟಿರುತ್ತದೆ — `/v1` ಪ್ರತ್ಯಯವಿಲ್ಲ, ಕೊನೆಯಲ್ಲಿ ಸ್ಲ್ಯಾಶ್ ಇಲ್ಲ. **ಕೀ ಅನ್ನು ಎಂದಿಗೂ ಪ್ರದರ್ಶಿಸಲಾಗುವುದಿಲ್ಲ**: ಬ್ಲಾಕ್ ಪ್ಲೇಸ್ಹೋಲ್ಡರ್ನೊಂದಿಗೆ ಬರುತ್ತದೆ, ಆದ್ದರಿಂದ ಸ್ಕ್ರೀನ್ಶಾಟ್ ಅಥವಾ ಅಂಟಿಸಲಾದ ತುಣುಕು ಕೀ ಅನ್ನು ಸೋರಿಕೆ ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ. ಅದರ ಜಾಗದಲ್ಲಿ ನಿಮ್ಮ ಕೀ ಅನ್ನು ಅಂಟಿಸಿ.

ನೈಜ ಕಾಂಟೆಕ್ಸ್ಟ್ ವಿಂಡೋ 200K ಅಲ್ಲದ ಯಾವುದೇ ಮಾಡೆಲ್ಗಾಗಿ ಅದೇ `env` ಬ್ಲಾಕ್ನ ಅಡಿಯಲ್ಲಿ `CLAUDE_CODE_AUTO_COMPACT_WINDOW` ಸೇರಿಸಿ — Claude Code ತಾನು ಗುರುತಿಸದ ಪ್ರತಿಯೊಂದು id ಗೂ 200K ಎಂದು ಊಹಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಇಲ್ಲದಿದ್ದರೆ ಸ್ವಯಂ-ಕಾಂಪ್ಯಾಕ್ಷನ್ ತಪ್ಪಾದ ಹಂತದಲ್ಲಿ ಪ್ರಾರಂಭವಾಗುತ್ತದೆ (ಹಿಂದಿನ ವಿಭಾಗದಲ್ಲಿನ ಎಚ್ಚರಿಕೆಯನ್ನು ನೋಡಿ). ತುಣುಕು ಬಿಲ್ಡರ್ ಆ ಮೌಲ್ಯವನ್ನೂ ಸ್ವೀಕರಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಗುರಿ ಮಾಡೆಲ್ನ ವಿಂಡೋ ತಿಳಿದಿರುವ ಕಾಲರ್ ಅದನ್ನು ನೇರವಾಗಿ ಹೊರಸೂಸಬಹುದು.

ಮೂಲ: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (ಪ್ಯೂರ್ ಬಿಲ್ಡರ್, ಯೂನಿಟ್-ಪರೀಕ್ಷಿತ), ಇದನ್ನು `ClaudeGatewayOnboardingBlock` ಪ್ರದರ್ಶಿಸುತ್ತದೆ.

### ಒಂದು ಖಾತೆಯನ್ನು ಪಿನ್ ಮಾಡಿ (ಐಚ್ಛಿಕ)

ಪ್ರತಿಯೊಂದು Claude Code ವಿನಂತಿಯನ್ನೂ ಒಂದು ನಿರ್ದಿಷ್ಟ ಪ್ರೊವೈಡರ್ ಖಾತೆಯ ಮೂಲಕ ಕಳುಹಿಸಲು, ಅದೇ `env` ಬ್ಲಾಕ್ನಲ್ಲಿ `ANTHROPIC_CUSTOM_HEADERS` ಮೂಲಕ `x-omniroute-connection` ಹೆಡರ್ ಸೇರಿಸಿ:

```jsonc
"ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>"
```

ಪ್ರೊವೈಡರ್ ಪುಟದ ಕನೆಕ್ಷನ್ ಸಾಲಿನಲ್ಲಿರುವ `xxxxxxxx…` ಚಿಪ್ನಿಂದ id ಅನ್ನು ನಕಲಿಸಿ. ಪಿನ್ ಏಕ-ಮಾಡೆಲ್ id ಗಳಿಗೆ (`provider/model`) ಮಾತ್ರ ಅನ್ವಯಿಸುತ್ತದೆ, ಕಾಂಬೊಗಳಿಗೆ ಅಲ್ಲ. ನಿಖರವಾದ ಫಾಲ್ಬ್ಯಾಕ್ ನಡವಳಿಕೆಗಾಗಿ [ಪ್ರತಿ ವಿನಂತಿಗೆ ಖಾತೆ ಪಿನ್ನಿಂಗ್](../reference/API_REFERENCE.md#account-pinning-per-request) ನೋಡಿ.

## ಪ್ರೊಫೈಲ್ಗಳು (`CLAUDE_CONFIG_DIR`)

Claude Code ನಲ್ಲಿ **ಸ್ಥಳೀಯ ಪ್ರೊಫೈಲ್ ಫೈಲ್ಗಳಿಲ್ಲ** (Codex ನ `~/.codex/<name>.config.toml` ಗಿಂತ ಭಿನ್ನವಾಗಿ).
ರೂಢಿಗತ ಕಾರ್ಯವಿಧಾನವೆಂದರೆ `CLAUDE_CONFIG_DIR` — ಪ್ರತಿ ಪ್ರೊಫೈಲ್ಗೆ ಪ್ರತ್ಯೇಕ ಕಾನ್ಫಿಗ್ ಡೈರೆಕ್ಟರಿ,
ಪ್ರತಿಯೊಂದೂ ತನ್ನದೇ ಆದ `settings.json`, ರುಜುವಾತುಗಳು, ಇತಿಹಾಸ ಮತ್ತು ಕ್ಯಾಶ್ ಹೊಂದಿರುತ್ತದೆ.

`omniroute setup-claude` ಲೈವ್ `/v1/models` ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ಪಡೆದು, ಪ್ರತಿ ಮಾಡೆಲ್ಗೆ
ಒಂದು ಪ್ರೊಫೈಲ್ ಅನ್ನು `~/.claude/profiles/<name>/settings.json` ನಲ್ಲಿ ಬರೆಯುತ್ತದೆ ಮತ್ತು
**`setup-codex` ನಲ್ಲಿರುವ ಅದೇ ಹೆಸರುಗಳನ್ನು** (`glm52`, `kimi-k27`, `deepseek-pro`, …) ಮರುಬಳಕೆ ಮಾಡುತ್ತದೆ:

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **ದೃಢೀಕರಣ ಟೋಕನ್ ಅನ್ನು ಪ್ರೊಫೈಲ್ಗೆ ಎಂದಿಗೂ ಬರೆಯಲಾಗುವುದಿಲ್ಲ.** `omniroute launch --profile <name>`
> ಮೂಲಕ ಪ್ರಾರಂಭಿಸಿ (ಇದು ಸಕ್ರಿಯ ಕಾಂಟೆಕ್ಸ್ಟ್ನಿಂದ `ANTHROPIC_AUTH_TOKEN` ಅನ್ನು ಸೇರಿಸುತ್ತದೆ), ಅಥವಾ
> `ANTHROPIC_AUTH_TOKEN` ಅನ್ನು ನೀವೇ ಎಕ್ಸ್ಪೋರ್ಟ್ ಮಾಡಿ
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude` ಅನ್ನು ಚಲಾಯಿಸಿ.

**ಮಾಡೆಲ್ ಅನ್ವೇಷಣೆಯ ನಂತರ ಸ್ವಯಂ-ಸಿಂಕ್ (ಐಚ್ಛಿಕ).** ಪ್ರೊವೈಡರ್ ಮಾಡೆಲ್ ಸಿಂಕ್ ಲೈವ್
ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ಬದಲಾಯಿಸಿದಾಗಲೆಲ್ಲ OmniRoute ಇದೇ `~/.claude/profiles/<name>/settings.json`
ಫೈಲ್ಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮರುರಚಿಸಬಹುದು — ಇದರಿಂದ ಕಮಾಂಡ್ ಅನ್ನು ಪುನಃ ಚಲಾಯಿಸದೆಯೇ ಹೊಸ/ಮರುಹೆಸರಿಸಲಾದ
ಮಾಡೆಲ್ಗಳಿಗೆ ಪ್ರೊಫೈಲ್ಗಳು ದೊರೆಯುತ್ತವೆ. ಇದು **ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಆಫ್ ಆಗಿರುತ್ತದೆ**: ಇದನ್ನು
**CLI Code ಡ್ಯಾಶ್ಬೋರ್ಡ್**ನಿಂದ ("CLI ಪ್ರೊಫೈಲ್ ಸ್ವಯಂ-ಸಿಂಕ್" → Claude Code) ಟಾಗಲ್ ಮಾಡಿ, ಅಥವಾ
`OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` ಅನ್ನು ಹೊಂದಿಸಿ (ಇದು ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಆನ್ ಆಗಿರುವ
`CLI_ALLOW_CONFIG_WRITES` ಅನ್ನೂ ಗೌರವಿಸುತ್ತದೆ). ಸಕ್ರಿಯಗೊಳಿಸಿದಾಗ ಇದು ಪ್ರೊಫೈಲ್ ಫೈಲ್ಗಳನ್ನು ಮಾತ್ರ
ಬರೆಯುತ್ತದೆ; ನಿಮ್ಮ ಸಕ್ರಿಯ/ಪೂರ್ವನಿಯೋಜಿತ Claude ಕಾನ್ಫಿಗ್, ದೃಢೀಕರಣ ಅಥವಾ `~/.claude/settings.json`
ಅನ್ನು ಎಂದಿಗೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ.

### ಪ್ರೊಫೈಲ್ಗಳನ್ನು ರಚಿಸುವುದು + ಬಳಸುವುದು

```bash
# ಸ್ಥಳೀಯ OmniRoute
omniroute setup-claude

# ರಿಮೋಟ್ VPS (ಪ್ರತಿ ಪ್ರೊಫೈಲ್ನಲ್ಲಿ VPS URL ಅನ್ನು ಅಳವಡಿಸುತ್ತದೆ)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# ಕೆಲವು ಪ್ರೊವೈಡರ್ಗಳು ಮಾತ್ರ
omniroute setup-claude --only glm,kimi

# ಈ ಹೋಸ್ಟ್ನಲ್ಲಿ ಪತ್ತೆಯಾಗದ ಸ್ಥಳೀಯ-CLI ಪ್ರೊವೈಡರ್ಗಳಿಗೂ (zcode, auggie, devin-cli-agentic,
# codex-app-server) ಪ್ರೊಫೈಲ್ಗಳನ್ನು ಬರೆಯಿರಿ (ಸ್ಥಳೀಯ ಗುರಿಗಾಗಿ ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ)
omniroute setup-claude --include-local

# ಬರೆಯದೆಯೇ ಪೂರ್ವವೀಕ್ಷಿಸಿ
omniroute setup-claude --dry-run

# ಪ್ರೊಫೈಲ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ
omniroute launch --profile kimi-k27
```

## ಮಾದರಿ ಹಂತಗಳು (ಐಚ್ಛಿಕ)

Claude Code ಸಾಮರ್ಥ್ಯದ ಹಂತಗಳಿಗೆ ವಿನಂತಿಗಳನ್ನು ರವಾನಿಸುತ್ತದೆ. ಪ್ರತಿ ಹಂತಕ್ಕೂ ವಿಭಿನ್ನ ಪೂರೈಕೆದಾರರನ್ನು ಬಳಸಲು ಬಯಸಿದರೆ, env /
settings ಮೂಲಕ ಪ್ರತಿಯೊಂದನ್ನೂ OmniRoute ಮಾದರಿಗೆ ಮ್ಯಾಪ್ ಮಾಡಿ:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

ಇಲ್ಲದಿದ್ದರೆ, ಒಂದೇ `ANTHROPIC_MODEL` (ಪ್ರೊಫೈಲ್ಗಳು ಹೊಂದಿಸುವುದು) ಎಲ್ಲದಕ್ಕೂ ಬಳಸಲಾಗುತ್ತದೆ.

## ರಿಮೋಟ್ ಮೋಡ್

ನೀವು `omniroute connect <host>` ಅನ್ನು ಚಲಾಯಿಸಿದ ನಂತರ ([ರಿಮೋಟ್ ಮೋಡ್](./REMOTE-MODE.md) ನೋಡಿ), `omniroute launch` ಮತ್ತು `omniroute setup-claude`
ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಆ ರಿಮೋಟ್ ಸರ್ವರ್ ಅನ್ನು ಗುರಿಯಾಗಿಸಿಕೊಂಡು, ಅದರ ವ್ಯಾಪ್ತಿ-ನಿರ್ಬಂಧಿತ ಪ್ರವೇಶ ಟೋಕನ್ ಅನ್ನು ಬಳಸುತ್ತವೆ — ಯಾವುದೇ
ಹೆಚ್ಚುವರಿ ಫ್ಲ್ಯಾಗ್ಗಳ ಅಗತ್ಯವಿಲ್ಲ. ಪ್ರತಿ ಆಹ್ವಾನಕ್ಕೆ `--remote` / `--api-key` ಮೂಲಕ ಇದನ್ನು ಅತಿಕ್ರಮಿಸಿ.

## ಸಮಸ್ಯೆ ನಿವಾರಣೆ

**Claude Code ಗೇಟ್ವೇಯನ್ನು ನಿರ್ಲಕ್ಷಿಸುತ್ತದೆ** — `ANTHROPIC_BASE_URL` ನಲ್ಲಿ **`/v1`
ಇಲ್ಲ** ಎಂಬುದನ್ನು ಖಚಿತಪಡಿಸಿಕೊಂಡು, `claude` ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ (env ಅನ್ನು ಪ್ರಾರಂಭದ ಸಮಯದಲ್ಲಿ ಒಮ್ಮೆ ಮಾತ್ರ ಓದಲಾಗುತ್ತದೆ). `omniroute launch`
ಇದನ್ನು ನಿಮಗಾಗಿ ನಿರ್ವಹಿಸುತ್ತದೆ.

**`/model` ಆಯ್ಕೆಪಟ್ಟಿ ಖಾಲಿಯಾಗಿದೆ / ಗೇಟ್ವೇ ಮಾದರಿಗಳು ಕಾಣೆಯಾಗಿವೆ** — Claude Code
v2.1.219+ ಮತ್ತು `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` ಅಗತ್ಯವಿದೆ. `claude*` /
`anthropic*` ಮಾದರಿ IDಗಳು ಮಾತ್ರ ಆಯ್ಕೆಪಟ್ಟಿಯಲ್ಲಿ ಕಾಣಿಸುತ್ತವೆ; ಇತರ ಯಾವುದೇ ಮಾದರಿಯನ್ನು
`ANTHROPIC_MODEL=<id>` ಮೂಲಕ ಬಲವಂತವಾಗಿ ಬಳಸಿ (ಪ್ರೊಫೈಲ್ಗಳು ಮಾಡುವುದು ಇದನ್ನೇ).

**`400 Ambiguous model 'claude-…'`** — Claude Code ಯಾವಾಗಲೂ **ಪೂರ್ವಪ್ರತ್ಯಯವಿಲ್ಲದ**
ಮಾದರಿ IDಗಳನ್ನು ಕಳುಹಿಸುತ್ತದೆ (ಉದಾ. `claude-opus-4-8`), ಆದ್ದರಿಂದ Claude Code (`cc/…`) ಮತ್ತು
Claude (`claude/…`) ಪೂರೈಕೆದಾರರಿಬ್ಬರೂ ಸಂಪರ್ಕಗೊಂಡಿರುವಾಗ, ಪೂರ್ವಪ್ರತ್ಯಯವಿಲ್ಲದ id ಎರಡು ಮಾರ್ಗಗಳಿಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ ಮತ್ತು
OmniRoute ಊಹಿಸಲು ನಿರಾಕರಿಸುತ್ತದೆ. ಇದನ್ನು ಎರಡರಲ್ಲಿ ಯಾವುದಾದರೂ ರೀತಿಯಲ್ಲಿ ಸರಿಪಡಿಸಿ: `ANTHROPIC_MODEL=cc/claude-opus-4-8` ಮೂಲಕ
ಪೂರ್ವಪ್ರತ್ಯಯವಿರುವ id ಅನ್ನು ನಿಗದಿಪಡಿಸಿ, ಅಥವಾ **ಪೂರ್ವಪ್ರತ್ಯಯವಿಲ್ಲದ Claude ಮಾದರಿಗಳಿಗೆ Claude Code ಅನ್ನು
ಆದ್ಯತೆ ನೀಡಿ** ಎಂಬುದನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ — Claude ಪೂರೈಕೆದಾರರ ಪುಟದಲ್ಲಿನ ಟಾಗಲ್, ಅಥವಾ
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ನಿಷ್ಕ್ರಿಯ;
[ಪರಿಸರ](../reference/ENVIRONMENT.md) ನೋಡಿ) — ಇದು ಪೂರ್ವಪ್ರತ್ಯಯವಿಲ್ಲದ `claude-*`
IDಗಳನ್ನು ಬದಲಾಗಿ Claude Code ಗೆ ರವಾನಿಸುತ್ತದೆ. ಸ್ಪಷ್ಟ ಪೂರೈಕೆದಾರ ಪೂರ್ವಪ್ರತ್ಯಯಗಳಿಗೆ ಯಾವಾಗಲೂ ಆದ್ಯತೆ ಇರುತ್ತದೆ.

**ದೃಢೀಕರಣ ದೋಷಗಳು** — ಪ್ರೊಫೈಲ್ ಯಾವುದೇ ಟೋಕನ್ ಹೊಂದಿರುವುದಿಲ್ಲ. `omniroute launch --profile`
ಬಳಸಿ (ಅದು ಟೋಕನ್ ಅನ್ನು ಸೇರಿಸುತ್ತದೆ) ಅಥವಾ `ANTHROPIC_AUTH_TOKEN` ಅನ್ನು export ಮಾಡಿ.

**ಪ್ರೊಫೈಲ್ಗಳು ಪ್ರತ್ಯೇಕವಾಗಿಲ್ಲ** — ಪ್ರತಿಯೊಂದು ಪ್ರೊಫೈಲ್ ಪ್ರತ್ಯೇಕ `CLAUDE_CONFIG_DIR` ಆಗಿದೆ;
ಸೆಷನ್ನೊಳಗೆ `echo $CLAUDE_CONFIG_DIR` ಅನ್ನು ಚಲಾಯಿಸಿ, ಅದು
`~/.claude/profiles/<name>` ಅನ್ನು ಸೂಚಿಸುತ್ತಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ.
