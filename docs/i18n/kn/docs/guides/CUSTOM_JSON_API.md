ಕಸ್ಟಮ್ JSON API ನೋಡ್ OpenAI ಅಥವಾ Anthropic ಪ್ರೋಟೋಕಾಲ್ ಅನ್ನು ಮಾತನಾಡದ JSON ವ್ಯಾಪಾರದ ಅಂತಿಮ ಬಿಂದುವನ್ನು ಸಂಪರ್ಕಿಸುತ್ತದೆ. OmniRoute JSON ವಿನಂತಿಯ ಟೆಂಪ್ಲೇಟ್ ಅನ್ನು ತುಂಬುತ್ತದೆ, ಅದನ್ನು ಸಂಪೂರ್ಣ ಅಂತಿಮ ಬಿಂದು URL ಗೆ ಕಳುಹಿಸುತ್ತದೆ, ಪ್ರತಿಕ್ರಿಯೆ ಮಾರ್ಗದಿಂದ ಉತ್ತರವನ್ನು ಓದುತ್ತದೆ ಮತ್ತು ಕ್ಲೈಂಟ್ನ ಸ್ವಂತ ಸ್ವರೂಪದಲ್ಲಿ ಅದನ್ನು ಕ್ಲೈಂಟ್ಗೆ ಹಿಂತಿರುಗಿಸುತ್ತದೆ (ಚಾಟ್ ಪೂರ್ಣಗೊಳಿಸುವಿಕೆಗಳು, ಪ್ರತಿಕ್ರಿಯೆಗಳು, ಸಂದೇಶಗಳು, ...).

ಇದು `apiType: "custom-json"` ನೊಂದಿಗೆ OpenAI-ಹೊಂದಾಣಿಕೆಯ ನೋಡ್ ಆಗಿದೆ; ಅದರ ಐಡಿ `openai-compatible-custom-json-<suffix>` ರೂಪವನ್ನು ಹೊಂದಿದೆ. ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಫಾರ್ಮ್ ಇನ್ನೂ ಲಭ್ಯವಿಲ್ಲ. ಕೆಳಗಿನ ಪ್ರೊವೈಡರ್-ನೋಡ್ API ಮೂಲಕ ಈ ನೋಡ್ಗಳನ್ನು ರಚಿಸಿ ಮತ್ತು ಸಂಪಾದಿಸಿ.

## ನೋಡ್ ಅನ್ನು ರಚಿಸಿ

`POST /api/provider-nodes` (ನಿರ್ವಹಣೆ ದೃಢೀಕರಣ):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` ಆಗಿದೆ** ಸಂಪೂರ್ಣ** ಅಂತಿಮ ಬಿಂದು URL. ಯಾವುದನ್ನೂ ಸೇರಿಸಲಾಗಿಲ್ಲ ( `/chat/completions` ಇಲ್ಲ, `/models` ಇಲ್ಲ) ಮತ್ತು ಇತರ OpenAI-ಹೊಂದಾಣಿಕೆಯ ನೋಡ್ಗಳಂತೆ, ಯಾವುದೇ ಡೀಫಾಲ್ಟ್ URL ಇಲ್ಲ. ಇದು ಎಂಬೆಡೆಡ್ ರುಜುವಾತುಗಳು ಅಥವಾ `#fragment` ಇಲ್ಲದೆಯೇ `http(s)` ಆಗಿರಬೇಕು ಮತ್ತು ನೋಡ್ ಅನ್ನು ಉಳಿಸಿದಾಗ ಮತ್ತು ಪ್ರತಿ ವಿನಂತಿಯ ಮೇರೆಗೆ ಪ್ರತಿ ಪೂರೈಕೆದಾರ ನೋಡ್ನಂತೆ ಅದೇ ಹೊರಹೋಗುವ URL ಗಾರ್ಡ್ ಅನ್ನು ಇದು ಹಾದುಹೋಗುತ್ತದೆ.
- ಸಂಪರ್ಕ ಕೀಲಿಯನ್ನು ಕಳುಹಿಸುವ ನೋಡ್ (`authType` `bearer` ಅಥವಾ `api-key`, ಡೀಫಾಲ್ಟ್ ಸೇರಿದಂತೆ) `https://` ಬಳಸಬೇಕು. ಸರಳ `http://` ಲೂಪ್ಬ್ಯಾಕ್ ಹೋಸ್ಟ್ (`localhost`, `127.0.0.0/8`, `::1`) ಅಥವಾ `authType: "none"` ನೊಂದಿಗೆ ಮಾತ್ರ ಸ್ವೀಕರಿಸಲಾಗುತ್ತದೆ, ಅದು ಯಾವುದೇ ಕೀಲಿಯನ್ನು ಕಳುಹಿಸುವುದಿಲ್ಲ. ಖಾಸಗಿ LAN ವಿಳಾಸಗಳು (`10.x`, `172.16-31.x`, `192.168.x`) ವಿನಾಯಿತಿ ಹೊಂದಿಲ್ಲ: ಆ ನೆಟ್ವರ್ಕ್ನಲ್ಲಿರುವ ಯಾರಾದರೂ ಕೀಲಿಯನ್ನು ಓದಬಹುದು. ಅಂತಹ ನೋಡ್ ಅನ್ನು ಉಳಿಸುವುದು `400` ನೊಂದಿಗೆ ವಿಫಲಗೊಳ್ಳುತ್ತದೆ ಮತ್ತು ಯಾವುದೇ ವಿನಂತಿಯನ್ನು ಕಳುಹಿಸುವ ಮೊದಲು ಅದೇ ಸಂದೇಶದೊಂದಿಗೆ ಪ್ರತಿ ವಿನಂತಿಯ ಮೇಲೆ ಹಿಂದೆ ಸಂಗ್ರಹಿಸಿದ ನೋಡ್ ವಿಫಲಗೊಳ್ಳುತ್ತದೆ. LAN ನಲ್ಲಿ ಕೀಲಿಸಲಾದ ಎಂಡ್ಪಾಯಿಂಟ್ಗಾಗಿ, ಅದನ್ನು TLS ಹಿಂದೆ ಇರಿಸಿ (ಉದಾಹರಣೆಗೆ ರಿವರ್ಸ್ ಪ್ರಾಕ್ಸಿ).
- `customJson` Zod ನೊಂದಿಗೆ ಮೌಲ್ಯೀಕರಿಸಲಾಗಿದೆ; ಅಜ್ಞಾತ ಕೀಲಿಗಳನ್ನು ತಿರಸ್ಕರಿಸಲಾಗಿದೆ. ಪ್ರತಿಯೊಂದು ಕ್ಷೇತ್ರವು ಐಚ್ಛಿಕವಾಗಿರುತ್ತದೆ:

| ಕ್ಷೇತ್ರ           | ಮೌಲ್ಯಗಳು                                | ಡೀಫಾಲ್ಟ್                                               |
| ----------------- | --------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                  | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`             | `bearer`                                               |
| `authHeader`      | `api-key` ಮಾಡಿದಾಗ ಹೆಡರ್ ಹೆಸರು ಬಳಸಲಾಗಿದೆ | `X-API-Key`                                            |
| `requestTemplate` | JSON ವಸ್ತು (≤ 64 KB, ಆಳ ≤ 32)           | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | ಕ್ಷೇತ್ರ ಮಾರ್ಗ, ಅಥವಾ ಇಡೀ ದೇಹಕ್ಕೆ `$`     | `choices[0].message.content`                           |

- ರಹಸ್ಯವು ಸಂಪರ್ಕದ API ಕೀಲಿಯಲ್ಲಿ ಉಳಿಯುತ್ತದೆ, ಎಂದಿಗೂ ಟೆಂಪ್ಲೇಟ್ನಲ್ಲಿಲ್ಲ. `bearer` `Authorization: Bearer <key>` ಕಳುಹಿಸುತ್ತದೆ; `api-key` `<authHeader>: <key>` ಕಳುಹಿಸುತ್ತದೆ. ದೃಢೀಕರಣ ಹೆಡರ್ `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` ಅಥವಾ ಹಾಪ್-ಬೈ-ಹಾಪ್ ಹೆಡರ್ ಆಗಿರಬಾರದು. `none` ನೊಂದಿಗೆ, ಸಂಪರ್ಕಗಳಿಗೆ ಯಾವುದೇ ಕೀ ಅಗತ್ಯವಿಲ್ಲ.
- ಹೆಚ್ಚುವರಿ ಸ್ಥಿರ ಹೆಡರ್ಗಳು ನೋಡ್ನ ನಿಯಮಿತ `customHeaders` ಬಳಸುತ್ತವೆ (ಪ್ರತಿ ಇತರ ಹೊಂದಾಣಿಕೆಯ ನೋಡ್ನಂತೆ ಅದೇ ಮೌಲ್ಯೀಕರಣ; ದೃಢೀಕರಣ ಹೆಡರ್ಗಳನ್ನು ಅಲ್ಲಿ ಅನುಮತಿಸಲಾಗುವುದಿಲ್ಲ).

`PUT /api/provider-nodes/<id>` ಅದೇ `customJson` ಸ್ವೀಕರಿಸುತ್ತದೆ ಮತ್ತು ನೋಡ್ನ ಪ್ರತಿಯೊಂದು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಸಂಪರ್ಕದಲ್ಲಿ `baseUrl` ಮತ್ತು ಸಂರಚನೆಯನ್ನು ಪುನಃ ಬರೆಯುತ್ತದೆ. `customJson` ಬಿಟ್ಟುಬಿಡುವುದು ಸಂಗ್ರಹಿತ ಸಂರಚನೆಯನ್ನು ಇರಿಸುತ್ತದೆ; `apiType` `chat` ಅಥವಾ `responses` ಗೆ ಬದಲಾಯಿಸುವುದು ನೋಡ್ ಮತ್ತು ಅದರ ಸಂಪರ್ಕಗಳಿಂದ ಅದನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ.

ನಂತರ ಎಂದಿನಂತೆ ನೋಡ್ಗೆ ಸಂಪರ್ಕವನ್ನು ಸೇರಿಸಿ (ನೋಡ್ ಐಡಿಯೊಂದಿಗೆ`POST /api/providers` ) ಮತ್ತು `<prefix>/<model>` ವಿನಂತಿಸಿ, ಉದಾಹರಣೆಗೆ `biz/assistant-v1`. ಎಂಡ್ಪಾಯಿಂಟ್ ಯಾವುದೇ ಮಾದರಿ ಪಟ್ಟಿಯನ್ನು ಬಹಿರಂಗಪಡಿಸುವುದಿಲ್ಲ, ಆದ್ದರಿಂದ ಮಾದರಿ ಐಡಿಗಳನ್ನು ಕೈಯಿಂದ ಸೇರಿಸಿ.

## ಟೆಂಪ್ಲೇಟ್ಗಳನ್ನು ವಿನಂತಿಸಿ

ಟೆಂಪ್ಲೇಟ್ಗಳು ಸರಳ JSON. ಸ್ಟ್ರಿಂಗ್ ಮೌಲ್ಯವು `{{placeholder}}` ಮಾರ್ಕರ್ಗಳನ್ನು ಒಳಗೊಂಡಿರಬಹುದು; ಯಾವುದನ್ನೂ ಮೌಲ್ಯಮಾಪನ ಮಾಡಲಾಗುವುದಿಲ್ಲ ಅಥವಾ ಕಾರ್ಯಗತಗೊಳಿಸಲಾಗುವುದಿಲ್ಲ ಮತ್ತು ಆಬ್ಜೆಕ್ಟ್ ಕೀಗಳನ್ನು ಎಂದಿಗೂ ಬದಲಿಸಲಾಗುವುದಿಲ್ಲ.

| ಪ್ಲೇಸ್ಹೋಲ್ಡರ್        | ಮೌಲ್ಯ                                                                   |
| -------------------- | ----------------------------------------------------------------------- |
| `{{prompt}}`         | ಇತ್ತೀಚಿನ ಬಳಕೆದಾರ ಸಂದೇಶದ ಪಠ್ಯ (ಪಠ್ಯ ಭಾಗಗಳು ಹೊಸ ಸಾಲುಗಳೊಂದಿಗೆ ಸೇರಿಕೊಂಡಿವೆ) |
| `{{messages}}`       | OpenAI ಚಾಟ್ ಸ್ವರೂಪದಲ್ಲಿ ಸಂಭಾಷಣೆ                                         |
| `{{model}}`          | ವಿನಂತಿಸಿದ ಮಾದರಿ ಐಡಿ, ಒದಗಿಸುವವರ ಪೂರ್ವಪ್ರತ್ಯಯವಿಲ್ಲದೆ                      |
| `{{stream}}`         | ಯಾವಾಗಲೂ `false` — ಒಂದು JSON ಡಾಕ್ಯುಮೆಂಟ್ನೊಂದಿಗೆ ಅಂತ್ಯಬಿಂದು ಉತ್ತರಿಸುತ್ತದೆ |
| `{{request.<path>}}` | ಅನುವಾದಿಸಿದ (OpenAI ಚಾಟ್ ಫಾರ್ಮ್ಯಾಟ್) ವಿನಂತಿಯ ಕ್ಷೇತ್ರ                     |

- ನಿಖರವಾಗಿ ಒಂದು ಪ್ಲೇಸ್ಹೋಲ್ಡರ್ ಆಗಿರುವ ಮೌಲ್ಯವು ಅದರ JSON ಪ್ರಕಾರವನ್ನು ಇರಿಸುತ್ತದೆ (`"{{messages}}"` ಒಂದು ಶ್ರೇಣಿಯಾಗುತ್ತದೆ); ಉದ್ದವಾದ ಸ್ಟ್ರಿಂಗ್ನೊಳಗೆ ಪ್ಲೇಸ್ಹೋಲ್ಡರ್ ಅನ್ನು ಪಠ್ಯವಾಗಿ ಸೇರಿಸಲಾಗುತ್ತದೆ.
- ಅಪೂರ್ಣ ಪೇಲೋಡ್ ಅನ್ನು ಕಳುಹಿಸುವ ಬದಲು HTTP 400 ನೊಂದಿಗೆ ವಿನಂತಿಯನ್ನು ವಿಫಲಗೊಳಿಸುತ್ತದೆ ಎಂದು ಪರಿಹರಿಸುವ ಪ್ಲೇಸ್ಹೋಲ್ಡರ್.
- ಪಥಗಳು ಡಾಟ್ ಸಂಕೇತ ಮತ್ತು ಸಂಖ್ಯಾತ್ಮಕ ಸೂಚಿಕೆಗಳನ್ನು (`data.items[0].text`) ಬಳಸುತ್ತವೆ. `__proto__`, `prototype` ಮತ್ತು `constructor` ಅನ್ನು ಕೀಗಳು ಮತ್ತು ಮಾರ್ಗಗಳಲ್ಲಿ ತಿರಸ್ಕರಿಸಲಾಗಿದೆ.

## ಪ್ರತಿಕ್ರಿಯೆಗಳು

`responsePath` ನಲ್ಲಿನ ಮೌಲ್ಯವು ಸಹಾಯಕ ಪ್ರತ್ಯುತ್ತರವಾಗುತ್ತದೆ: ತಂತಿಗಳು ಹಾದು ಹೋಗುತ್ತವೆ, ಇತರ JSON ಮೌಲ್ಯಗಳು ಸರಣಿಯಾಗಿವೆ. ಕಾಣೆಯಾದ ಅಥವಾ `null` ಕ್ಷೇತ್ರ, ಅಥವಾ JSON ಅಲ್ಲದ ದೇಹವು HTTP 502 ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ. ಅಪ್ಸ್ಟ್ರೀಮ್ ದೋಷ ಸ್ಥಿತಿಗಳನ್ನು ರವಾನಿಸಲಾಗುತ್ತದೆ. ಸ್ಟ್ರೀಮಿಂಗ್ ಕ್ಲೈಂಟ್ಗಳಿಗಾಗಿ OmniRoute ಸಂಪೂರ್ಣ JSON ಪ್ರತಿಕ್ರಿಯೆಗಾಗಿ ಕಾಯುತ್ತದೆ ಮತ್ತು ನಂತರ ಅದನ್ನು ಒಂದು ಕಂಟೆಂಟ್ ಚಂಕ್ ಜೊತೆಗೆ ಫಿನಿಶ್ ಚಂಕ್ ಆಗಿ ಹೊರಸೂಸುತ್ತದೆ; ಇದು ಟೋಕನ್ ಸ್ಟ್ರೀಮಿಂಗ್ ಅಲ್ಲ. ಟೂಲ್ ಕರೆಗಳು ಮತ್ತು ಬಳಕೆಯ ಕ್ಷೇತ್ರಗಳನ್ನು ಮ್ಯಾಪ್ ಮಾಡಲಾಗಿಲ್ಲ.

## ಎಂದಿಗೂ ರಿಪ್ಲೇ ಮಾಡಿಲ್ಲ

ವ್ಯಾಪಾರ ವಿನಂತಿಯು ವಿಫಲವಾದಾಗಲೂ ಅಡ್ಡ ಪರಿಣಾಮಗಳನ್ನು ಉಂಟುಮಾಡಬಹುದು. ಆದ್ದರಿಂದ OmniRoute ಅದನ್ನು ಒಮ್ಮೆ ಕಳುಹಿಸುತ್ತದೆ:

- ಯಾವುದೇ ಸಾರಿಗೆ ಮರುಪ್ರಯತ್ನವಿಲ್ಲ ಮತ್ತು ಮರುನಿರ್ದೇಶನವನ್ನು ಅನುಸರಿಸುವುದಿಲ್ಲ;
- ಮತ್ತೊಂದು ಸಂಪರ್ಕವನ್ನು ಮರುಪ್ರಯತ್ನಿಸಬೇಡಿ (ಖಾತೆ ಫಾಲ್ಬ್ಯಾಕ್) — ವೈಫಲ್ಯವನ್ನು ಹಿಂತಿರುಗಿಸಲಾಗಿದೆ ಮತ್ತು ಸಂಪರ್ಕವು ತಂಪಾಗಿಲ್ಲ;
- ಖಾಲಿ ಅಥವಾ ವಿಫಲವಾದ ಪ್ರತ್ಯುತ್ತರಕ್ಕೆ ಸಹ, ಮುಂದಿನ ಕಾಂಬೊ ಗುರಿಗೆ ಹಿಂತಿರುಗುವುದಿಲ್ಲ.

ಪ್ರತ್ಯೇಕ ಕ್ಲೈಂಟ್ ವಿನಂತಿಗಳು ಮತ್ತು ಹಲವಾರು ಮಾದರಿಗಳನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಕರೆಯುವ ಫ್ಯೂಷನ್ ಪ್ಯಾನೆಲ್ಗಳು ಇನ್ನೂ ಸ್ವತಂತ್ರವಾಗಿ ಅಂತ್ಯಬಿಂದುವನ್ನು ಆಹ್ವಾನಿಸುತ್ತವೆ.

## ನೋಡ್ ಅನ್ನು ಪರೀಕ್ಷಿಸಲಾಗುತ್ತಿದೆ

ಸಂಪರ್ಕ, ಸಂಪರ್ಕವನ್ನು ಉಳಿಸಲಾಗುತ್ತಿದೆ** ಪರೀಕ್ಷೆ** ಬಟನ್ ಮತ್ತು ಹಿನ್ನೆಲೆ ಆರೋಗ್ಯ ತಪಾಸಣೆಗಳು ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಎಂದಿಗೂ ಕರೆಯುವುದಿಲ್ಲ: ಅವು ಸಂಗ್ರಹಿಸಿದ ಸಂರಚನೆಯನ್ನು ಮಾತ್ರ ಮೌಲ್ಯೀಕರಿಸುತ್ತವೆ ಮತ್ತು ಸಂಪರ್ಕವನ್ನು ಪರಿಶೀಲಿಸಲಾಗುವುದಿಲ್ಲ ಎಂದು ವರದಿ ಮಾಡುತ್ತವೆ.

`"apiType": "custom-json"` ಮತ್ತು ನೋಡ್ ಕ್ಷೇತ್ರಗಳೊಂದಿಗೆ`POST /api/provider-nodes/validate` (`baseUrl`, `apiKey`, `customJson`, ಐಚ್ಛಿಕ `customHeaders` ಮತ್ತು `modelId`) ನಿಖರವಾಗಿ ಒಂದು ನೈಜ ವಿನಂತಿಯನ್ನು ಕಳುಹಿಸುತ್ತದೆ, `ping` ಇತ್ತೀಚಿನ ಬಳಕೆದಾರ ಪಠ್ಯವಾಗಿದೆ. ಇದು `{ "valid": true }` ಅಥವಾ ಅಪ್ಸ್ಟ್ರೀಮ್ ಸ್ಥಿತಿಗೆ ಉತ್ತರಿಸುತ್ತದೆ (ಎಂದಿಗೂ ಅಪ್ಸ್ಟ್ರೀಮ್ ಬಾಡಿ ಅಲ್ಲ).

## ಸಂಗ್ರಹಣೆ

ಸಂರಚನೆಯನ್ನು `provider_nodes.custom_json_config_json` (ವಲಸೆ `240_provider_node_custom_json_config.sql`) ನಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾಗಿದೆ ಮತ್ತು ಪ್ರತಿ ಸಂಪರ್ಕದ `providerSpecificData.customJson` ಗೆ ನಕಲಿಸಲಾಗುತ್ತದೆ.

ಅನುಷ್ಠಾನ: `open-sse/utils/customJson.ts` (ಮೌಲ್ಯಮಾಪನ ಮತ್ತು ಟೆಂಪ್ಲೇಟಿಂಗ್), `open-sse/executors/customJson.ts` (ಕಾರ್ಯನಿರ್ವಾಹಕ), `open-sse/services/combo/noReplayLatch.ts` ಮತ್ತು `src/sse/handlers/chat/responsePolicies.ts` (ನೋ-ರಿಪ್ಲೇ).
