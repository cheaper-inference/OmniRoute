## ಇದು ಏನು (ಮತ್ತು ಏನಲ್ಲ)

OmniRoute ಟೋಕನ್ಗಳ ಸಂಖ್ಯೆಯನ್ನು ಮಾದರಿಯ ಬೆಲೆ ದರಗಳಿಂದ ಗುಣಿಸುವ ಮೂಲಕ ಪ್ರತಿ completionಗೆ
ಪ್ರತಿ-ವಿನಂತಿಯ USD ವೆಚ್ಚವನ್ನು ನಿಗದಿಪಡಿಸುತ್ತದೆ. ಈ ಸಂಖ್ಯೆಗಳು **ವೆಚ್ಚಗಳು** ಡ್ಯಾಶ್ಬೋರ್ಡ್,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON ರಫ್ತುಗಳು ಮತ್ತು ಪ್ರತಿ-API-key ಬಜೆಟ್ಗಳಿಗೆ
ಆಧಾರವಾಗಿವೆ.

> **ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ "ವೆಚ್ಚ" ಒಂದು ಉಳಿತಾಯ ಟ್ರ್ಯಾಕರ್, ಬಿಲ್ ಅಲ್ಲ.** OmniRoute ನಿಮಗೆ ಎಂದಿಗೂ
> ಶುಲ್ಕ ವಿಧಿಸುವುದಿಲ್ಲ — ನೀವು ಈಗಾಗಲೇ ಸಂಪರ್ಕಿಸಿರುವ ಪೂರೈಕೆದಾರರಿಗೆ (ನಿಮ್ಮ ಸ್ವಂತ
> ಚಂದಾದಾರಿಕೆಗಳು, ಉಚಿತ ಶ್ರೇಣಿಗಳು ಮತ್ತು API ಕೀಲಿಗಳು) ಅದು ನಿಮ್ಮ ವಿನಂತಿಗಳನ್ನು ರೂಟ್ ಮಾಡುತ್ತದೆ.
> ಸಂಪೂರ್ಣವಾಗಿ ಉಚಿತ ಮಾದರಿಗಳಲ್ಲಿ ಸಂಚಿತವಾದ "$290 ಒಟ್ಟು ವೆಚ್ಚ" ಎಂದರೆ, ಪಾವತಿಸಬೇಕಾದ API ಒಂದಕ್ಕೆ
> ನೀವು ಸರಿಸುಮಾರು **$290 ಪಾವತಿಸಿಲ್ಲ** ಎಂದರ್ಥ. ಈ ಅಂಕಿಯು ಅದೇ ಟ್ರಾಫಿಕ್ಗೆ ಪ್ರಮಾಣಿತ ಪಟ್ಟಿ
> ಬೆಲೆಗಳ ಪ್ರಕಾರ ಎಷ್ಟು ವೆಚ್ಚವಾಗುತ್ತಿತ್ತು ಎಂಬುದರ _ಅಂದಾಜು_ ಆಗಿದೆ; ಇದರಿಂದ ನಿಮ್ಮ ಬಳಕೆ ಎಲ್ಲಿ
> ಕೇಂದ್ರೀಕೃತವಾಗಿದೆ ಮತ್ತು ಕಡಿಮೆ-ವೆಚ್ಚದ/ಉಚಿತ ಪೂರೈಕೆದಾರರಿಗೆ ರೂಟ್ ಮಾಡುವುದರಿಂದ ನೀವು ಎಷ್ಟು
> ಉಳಿಸುತ್ತಿದ್ದೀರಿ ಎಂಬುದನ್ನು ನೋಡಬಹುದು.

ಈ ವಿವರಣೆಯನ್ನು ಯೋಜನೆಯ [README](../../README.md) ನಲ್ಲಿಯೂ ನೇರವಾಗಿ ಹೇಳಲಾಗಿದೆ ("ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ
'ವೆಚ್ಚ' ಒಂದು ಉಳಿತಾಯ ಟ್ರ್ಯಾಕರ್, ಬಿಲ್ ಅಲ್ಲ").

ಈ ಸಂಖ್ಯೆಯು ಅಂದಾಜಾಗಿರುವುದರಿಂದ:

- ಇದು ಪ್ರತಿ ಮಾದರಿಗಾಗಿ OmniRoute ಹೊಂದಿರುವ ಬೆಲೆ ಪಟ್ಟಿಯನ್ನು ಅವಲಂಬಿಸಿದೆ. ಬೆಲೆ ನಮೂದು ಇಲ್ಲದ
  ಮಾದರಿಯು `0` ವೆಚ್ಚವನ್ನು ನೀಡುತ್ತದೆ (ಎಕ್ಸ್ಪ್ಲೋರರ್ನಲ್ಲಿ ಅದು "ಹಳೆಯದು / ಉಚಿತ" ಸಾಲಾಗಿ ಕಾಣಿಸುತ್ತದೆ).
- ಉಚಿತ-ಶ್ರೇಣಿ ಮತ್ತು ಚಂದಾದಾರಿಕೆ ಟ್ರಾಫಿಕ್ಗೂ _ಅಂದಾಜಿತ_ ವೆಚ್ಚ ಸಂಚಿತವಾಗುತ್ತದೆ — ಅದು ನೀವು
  ಉಳಿಸುತ್ತಿರುವ ಮೊತ್ತವೇ ಹೊರತು ಪಾವತಿಸಬೇಕಾದ ಮೊತ್ತವಲ್ಲ.

## ವೆಚ್ಚವನ್ನು ಹೇಗೆ ಅಂದಾಜಿಸಲಾಗಿದೆ

### ಬೆಲೆ ಮೂಲ

[`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) ನಲ್ಲಿ ವಿಲೀನಗೊಂಡ ಬೆಲೆ ಪಟ್ಟಿಯಿಂದ ವೆಚ್ಚಗಳು ಬರುತ್ತವೆ, ಈ ಆದ್ಯತೆಯ ಕ್ರಮದಲ್ಲಿ (**ಮೊದಲ ಅತ್ಯಧಿಕ** ):

1. **ಬಳಕೆದಾರ ಅತಿಕ್ರಮಿಸುತ್ತದೆ** — ಬೆಲೆಗಳನ್ನು ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ಅಥವಾ `PATCH /api/pricing` ( `pricing` ನೇಮ್ಸ್ಪೇಸ್) ಮೂಲಕ ಹೊಂದಿಸಲಾಗಿದೆ.
2. **models.dev ಸಿಂಕ್** — ಬೆಲೆಯನ್ನು `https://models.dev/api.json` ( `models_dev_pricing` ನೇಮ್ಸ್ಪೇಸ್) ನಿಂದ ಪಡೆಯಲಾಗಿದೆ.
3. **LiteLLM ಸಿಂಕ್** — ಬೆಲೆಗಳನ್ನು LiteLLM ಯ ಸಾರ್ವಜನಿಕ `model_prices_and_context_window.json` ( `pricing_synced` ನೇಮ್ಸ್ಪೇಸ್) ನಿಂದ ಪಡೆಯಲಾಗಿದೆ.
4. **ಹಾರ್ಡ್ಕೋಡ್ ಮಾಡಿದ ಡೀಫಾಲ್ಟ್ಗಳು** — ದರಗಳನ್ನು [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) ನಲ್ಲಿ ರವಾನಿಸಲಾಗಿದೆ.

ಅದೇ provider/model ಗಾಗಿ, ಹೆಚ್ಚಿನ ಆದ್ಯತೆಯ ಲೇಯರ್ಗಳಿಂದ ಮೌಲ್ಯಗಳು ಕೆಳಗಿನ ಲೇಯರ್ಗಳಲ್ಲಿ ಹೊಂದಾಣಿಕೆಯ ಕ್ಷೇತ್ರಗಳನ್ನು ಓವರ್ರೈಟ್ ಮಾಡುತ್ತದೆ; ಮೇಲಿನ ಪದರದಿಂದ ಇಲ್ಲದ ಕ್ಷೇತ್ರಗಳು ಇನ್ನೂ ಕೆಳ ಪದರದಿಂದ ಬರಬಹುದು. ಎರಡೂ ಸ್ವತಂತ್ರ ಸಿಂಕ್ ಕೆಲಸಗಳು ಒಂದೇ ಸಮಯದಲ್ಲಿ ರನ್ ಆಗುವಾಗಲೂ ಆದೇಶವನ್ನು ನಿಗದಿಪಡಿಸಲಾಗಿದೆ. `GET /api/pricing?includeSources=1` `pricing` ಮತ್ತು `sourceMap` ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ, ಅದರ ಪ್ರತಿ-ಮಾದರಿ ಲೇಬಲ್ಗಳು (`user`, `modelsDev`, `litellm`, `default`) ಆ ಮಾದರಿಯನ್ನು ಹೊಂದಿರುವ ಹೆಚ್ಚಿನ ಆದ್ಯತೆಯ ಪದರವನ್ನು ಗುರುತಿಸುತ್ತದೆ.

**LiteLLM ಸಿಂಕ್** ಆಯ್ಕೆಮಾಡಲಾಗಿದೆ, ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ. ಇದರ ಪರಿಸರದ ಅಸ್ಥಿರಗಳು (ನೋಡಿ [`.env.example`](../../.env.example) ):

| ಎನ್ವಿ ವರ್               | ಡೀಫಾಲ್ಟ್  | ಉದ್ದೇಶ                                                             |
| ----------------------- | --------- | ------------------------------------------------------------------ |
| `PRICING_SYNC_ENABLED`  | `false`   | ಹಿನ್ನೆಲೆ LiteLLM ಬೆಲೆ ಸಿಂಕ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ.                    |
| `PRICING_SYNC_INTERVAL` | `86400`   | ಸೆಕೆಂಡುಗಳಲ್ಲಿ ಸಿಂಕ್ ಮಧ್ಯಂತರ (ದೈನಂದಿನ).                             |
| `PRICING_SYNC_SOURCES`  | `litellm` | ಈ ಸಿಂಕ್ಗೆ ಮಾತ್ರ ಮೂಲ ಆಯ್ಕೆ; ಪ್ರಸ್ತುತ `litellm` ಮಾತ್ರ ಬೆಂಬಲಿತವಾಗಿದೆ. |

**models.dev ಸಿಂಕ್** LiteLLM ಸಿಂಕ್ನಿಂದ ಪ್ರತ್ಯೇಕವಾಗಿದೆ ಮತ್ತು ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ. ಇದನ್ನು ಸೆಟ್ಟಿಂಗ್ಗಳಲ್ಲಿ ಸಕ್ರಿಯಗೊಳಿಸಿ (models.dev ಸಿಂಕ್) ಅಥವಾ ಈ ವೇರಿಯೇಬಲ್ಗಳನ್ನು ಬಳಸಿ:

| ಎನ್ವಿ ವರ್                  | ಡೀಫಾಲ್ಟ್          | ಉದ್ದೇಶ                                                                                                                                                       |
| -------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `MODELS_DEV_SYNC_ENABLED`  | _(ಹೊಂದಿಸಲಾಗಿಲ್ಲ)_ | ಹೊಂದಿಸದಿರುವುದು ಸೆಟ್ಟಿಂಗ್ಗಳ ಟಾಗಲ್ ಅನ್ನು ಅನುಸರಿಸುತ್ತದೆ; `1/true/on/yes` ಫೋರ್ಸ್ ಆನ್ ಮತ್ತು `0/false/off/no` ಫೋರ್ಸ್ ಆಫ್ (ಸೆಟ್ಟಿಂಗ್ಗಳು ಅದನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿದರೂ ಸಹ). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`           | ಡೀಫಾಲ್ಟ್ models.dev ಸೆಕೆಂಡುಗಳಲ್ಲಿ ಸಿಂಕ್ ಮಧ್ಯಂತರ (ದೈನಂದಿನ).                                                                                                   |

`PRICING_SYNC_SOURCES` ಮಾಡುತ್ತದೆ**ಅಲ್ಲ** models.dev ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ; ಇದು LiteLLM ಸಿಂಕ್ ಅನ್ನು ಮಾತ್ರ ನಿಯಂತ್ರಿಸುತ್ತದೆ. ಬಳಕೆದಾರ ಅತಿಕ್ರಮಣವನ್ನು ಅಳಿಸುವುದರಿಂದ ಸಿಂಕ್ ಮಾಡಿದ ನೇಮ್ಸ್ಪೇಸ್ ಅನ್ನು ತೆರವುಗೊಳಿಸುವುದಿಲ್ಲ; ಮುಂದಿನ ಲಭ್ಯವಿರುವ ಬೆಲೆ ಲೇಯರ್ ಪರಿಣಾಮಕಾರಿಯಾಗುತ್ತದೆ. ಬೆಲೆಯಿಲ್ಲದ ಮಾದರಿಗಾಗಿ, ಹಸ್ತಚಾಲಿತ ಅತಿಕ್ರಮಣವನ್ನು ಸೇರಿಸುವ ಮೊದಲು ಸಿಂಕ್ ಸೆಟ್ಟಿಂಗ್ಗಳು ಮತ್ತು `sourceMap` ಎರಡನ್ನೂ ಪರಿಶೀಲಿಸಿ.

### ವೆಚ್ಚದ ಸೂತ್ರ

[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`) ನಲ್ಲಿ ಟೋಕನ್ ಎಣಿಕೆಗಳು ಮತ್ತು ಪ್ರತಿ ಮಿಲಿಯನ್ ಟೋಕನ್ ದರಗಳಿಂದ ವಿನಂತಿಯ ಪ್ರತಿ ವೆಚ್ಚವನ್ನು ಲೆಕ್ಕಹಾಕಲಾಗುತ್ತದೆ:

- **ಇನ್ಪುಟ್ ಟೋಕನ್ಗಳು** (ಮೈನಸ್ ಕ್ಯಾಶ್ ರೀಡ್ಗಳು ಮತ್ತು ಕ್ಯಾಶ್-ಕ್ರಿಯೇಷನ್ ಟೋಕನ್ಗಳು) × `input` ದರ.
- **ಸಂಗ್ರಹ-ಓದಿದ ಟೋಕನ್ಗಳು** × `cached` ದರ (ಇನ್ಪುಟ್ ದರಕ್ಕೆ ಹಿಂತಿರುಗುತ್ತದೆ).
- **ಸಂಗ್ರಹ-ಸೃಷ್ಟಿ ಟೋಕನ್ಗಳು** × `cache_creation` ದರ (ಇನ್ಪುಟ್ ದರಕ್ಕೆ ಹಿಂತಿರುಗುತ್ತದೆ).
- **ಔಟ್ಪುಟ್ ಟೋಕನ್ಗಳು** × `output` ದರ.
- **ತಾರ್ಕಿಕ ಟೋಕನ್ಗಳು** × `reasoning` ದರ (ಔಟ್ಪುಟ್ ದರಕ್ಕೆ ಹಿಂತಿರುಗುತ್ತದೆ).

ಎಲ್ಲಾ ದರಗಳನ್ನು 1,000,000 ಟೋಕನ್ಗಳಿಗೆ USD ಎಂದು ಅರ್ಥೈಸಲಾಗುತ್ತದೆ. Codex "ವೇಗದ"/"ಆದ್ಯತೆ" ಅಥವಾ "ಫ್ಲೆಕ್ಸ್" ಸೇವೆಯ ಶ್ರೇಣಿಯು ವೆಚ್ಚ ಗುಣಕವನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ (`getCodexFastCostMultiplier`) — ಉದಾ ಫ್ಲೆಕ್ಸ್ ಅನ್ನು 50% ಟೋಕನ್ ರಿಯಾಯಿತಿಯಲ್ಲಿ ಬಿಲ್ ಮಾಡಲಾಗುತ್ತದೆ, ಇದು ಮೇಲ್ಮುಖವಾಗಿದೆ**ಫ್ಲೆಕ್ಸ್ ಉಳಿತಾಯ** ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ.

ಮಾದರಿಯ ಹೆಸರುಗಳನ್ನು ಮೊದಲು ಸಾಮಾನ್ಯೀಕರಿಸಲಾಗುತ್ತದೆ ( `openai/` ಅಥವಾ `accounts/fireworks/models/` ನಂತಹ ಪೂರೈಕೆದಾರ-ಮಾರ್ಗ ಪೂರ್ವಪ್ರತ್ಯಯಗಳನ್ನು ತೆಗೆದುಹಾಕಲಾಗಿದೆ) ಆದ್ದರಿಂದ ಐತಿಹಾಸಿಕ ಸಾಲುಗಳು ಇನ್ನೂ ಬೆಲೆಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತವೆ.

### ಖರ್ಚು ಹೇಗೆ ದಾಖಲಾಗಿದೆ

- ವಿನಂತಿಯ ಪೂರ್ಣಗೊಂಡ ನಂತರ ಪ್ರತಿ ವಿನಂತಿಯ ವೆಚ್ಚವನ್ನು ಲೆಕ್ಕಹಾಕಲಾಗುತ್ತದೆ. [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) ಮೂಲಕ ಮುಂದಿನ ಈವೆಂಟ್-ಲೂಪ್ ಟಿಕ್ನಲ್ಲಿ ಹಂಚಿಕೆಯ-ಕೋಟಾ ಬಳಕೆಯನ್ನು ನಿಗದಿಪಡಿಸಲಾಗಿದೆ.
- API-ಕೀ ಖರ್ಚು [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (ಡೀಫಾಲ್ಟ್ 60 ರ ಫ್ಲಶ್ ಮಧ್ಯಂತರ, 1,000-ಪ್ರವೇಶ ಬಫರ್) ಮೂಲಕ ಬ್ಯಾಚ್ಗಳಲ್ಲಿ ಬಫರ್ ಮಾಡಲಾಗಿದೆ ಮತ್ತು ಫ್ಲಶ್ ಮಾಡಲಾಗಿದೆ. ಇದರ ಮೂಲಕ ಟ್ಯೂನ್ ಮಾಡಬಹುದು:

  | ಎನ್ವಿ ವರ್                           | ಡೀಫಾಲ್ಟ್ | ಉದ್ದೇಶ                                  |
  | ----------------------------------- | -------- | --------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`  | ಮಿಲಿಸೆಕೆಂಡುಗಳಲ್ಲಿ ಫ್ಲಶ್ ಮಧ್ಯಂತರ.        |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`   | ಫ್ಲಶ್ ಮಾಡುವ ಮೊದಲು ಗರಿಷ್ಠ ಬಫರ್ ನಮೂದುಗಳು. |

ವೆಚ್ಚಗಳು ನಿಖರವಾದ ಪೂರೈಕೆದಾರ-ವರದಿ ಮಾಡಿದ ಶುಲ್ಕವನ್ನು ಆದ್ಯತೆ ನೀಡುತ್ತವೆ (`provider_cost_usd`), ನಂತರ ಕ್ಯಾಟಲಾಗ್-ಬೆಲೆಯ ವಿನಂತಿಯ ಸ್ನ್ಯಾಪ್ಶಾಟ್ (`calculated_cost_usd`), ನಂತರ ಪ್ರಸ್ತುತ ಕ್ಯಾಟಲಾಗ್ನಿಂದ ಟೋಕನ್ ಮರುಪಾವತಿ. ಸಂಗ್ರಹಿಸಿದ ವೆಚ್ಚವನ್ನು ಅವುಗಳ ಟೋಕನ್ ಎಣಿಕೆಗಳ ಮೂಲಕ ಮತ್ತೆ ವಿಧಿಸಲಾಗುವುದಿಲ್ಲ. ತಮ್ಮ ಕ್ಯಾಟಲಾಗ್ ಬೆಲೆ ಬದಲಾದಾಗ ಲೆಗಸಿ ಟೋಕನ್-ಮಾತ್ರ ಸಾಲುಗಳು ಇನ್ನೂ ಬದಲಾಗುತ್ತವೆ.

### OCR ಮತ್ತು ಎಂಬೆಡಿಂಗ್ಗಳು

- ಯಶಸ್ವಿ `/v1/ocr` ವಿನಂತಿಗಳು ಅಪ್ಸ್ಟ್ರೀಮ್ `usage_info.pages_processed` ಬಳಸುತ್ತವೆ, ವಿನಂತಿಸಿದ ಪುಟ ಶ್ರೇಣಿ ಅಥವಾ ಹಿಂತಿರುಗಿಸಿದ ಪುಟ ವಸ್ತುಗಳ ಸಂಖ್ಯೆ ಅಲ್ಲ. ಅಂದಾಜು ಪುಟಗಳು × `ocr_cost_per_page` (ಸಂಪೂರ್ಣ USD/page,**ಅಲ್ಲ** USD/million).
- ಡಾಕ್ಯುಮೆಂಟ್ ಅಥವಾ ಬೌಂಡಿಂಗ್-ಬಾಕ್ಸ್ ಟಿಪ್ಪಣಿಗಳೊಂದಿಗೆ ವಿನಂತಿಗಳಿಗೆ ಪ್ರತ್ಯೇಕ `ocr_cost_per_annotated_page` ಸುಂಕದ ಅಗತ್ಯವಿದೆ. ಅದು ಇಲ್ಲದೆ, ವೆಚ್ಚವು ತಿಳಿದಿಲ್ಲ; ಸಾಮಾನ್ಯ OCR ಸುಂಕವನ್ನು ಮೌನವಾಗಿ ಬದಲಿಸಲಾಗಿಲ್ಲ.
- LiteLLM ಸಿಂಕ್ ತನ್ನ ಅಪ್ಸ್ಟ್ರೀಮ್ `annotation_cost_per_page` ಕ್ಷೇತ್ರವನ್ನು `ocr_cost_per_annotated_page` ಗೆ ಮ್ಯಾಪ್ ಮಾಡುತ್ತದೆ, ಸಂಪೂರ್ಣ USD/page ಮೌಲ್ಯ ಮತ್ತು ಸ್ಪಷ್ಟ ಶೂನ್ಯ ಸೇರಿದಂತೆ ಟಿಪ್ಪಣಿ-ಮಾತ್ರ ನಮೂದುಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ. ಸರಬರಾಜು ಮಾಡಿದ ಅಂಗೀಕೃತ ಕ್ಷೇತ್ರವು ಆದ್ಯತೆಯನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ; ಅಮಾನ್ಯ ಅಲಿಯಾಸ್ ಮೌಲ್ಯಗಳನ್ನು ನಿರ್ಲಕ್ಷಿಸಲಾಗಿದೆ. ಬಳಕೆದಾರರ ಬೆಲೆ ಅತಿಕ್ರಮಣಗಳು ತಮ್ಮ ಸಾಮಾನ್ಯ ಆದ್ಯತೆಯನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ. [LiteLLM ನ OCR ಬೆಲೆ ಕೀಗಳನ್ನು](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) ನೋಡಿ.
- OCR ಬಳಕೆಯು ಪುಟದ ಎಣಿಕೆ, ಯುನಿಟ್ ಬೆಲೆ, ಲೆಕ್ಕಹಾಕಿದ USD ವೆಚ್ಚ, API ಕೀ ಮತ್ತು ಆಯ್ಕೆಮಾಡಿದ ಸಂಪರ್ಕವನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ. ಪುಟಗಳನ್ನು ಎಂದಿಗೂ ಟೋಕನ್ಗಳಾಗಿ ಪ್ರತಿನಿಧಿಸುವುದಿಲ್ಲ. ಕರೆ ಲಾಗ್ಗಳು ಬಿಲ್ಲಿಂಗ್ ಮೆಟಾಡೇಟಾವನ್ನು ಒಳಗೊಂಡಿರುತ್ತವೆ, ಡಾಕ್ಯುಮೆಂಟ್ URLs, PDF ಬೈಟ್ಗಳು ಅಥವಾ ಹೊರತೆಗೆದ ಪಠ್ಯವಲ್ಲ.
- ಯಶಸ್ವಿ `/v1/embeddings` ವಿನಂತಿಗಳು ಒಂದೇ ಮಿಲಿಸೆಕೆಂಡ್ನಲ್ಲಿ ಪೂರ್ಣಗೊಂಡ ಪ್ರತ್ಯೇಕ ಬ್ಯಾಚ್ಗಳನ್ನು ಒಳಗೊಂಡಂತೆ ಪ್ರತಿ ಭೌತಿಕ ಬ್ಯಾಚ್ಗೆ ಒಂದು ಬಳಕೆಯ ಸಾಲನ್ನು ದಾಖಲಿಸುತ್ತದೆ. ಟೋಕನ್ ಅಂದಾಜುಗಳಿಗಿಂತ ಒದಗಿಸುವವರು-ವರದಿ ಮಾಡಿದ ಶುಲ್ಕಗಳು ಆದ್ಯತೆಯನ್ನು ಪಡೆಯುತ್ತವೆ; ಕಾಂಬೊ ಹೊದಿಕೆಗಳು ಶುಲ್ಕವನ್ನು ಸೇರಿಸುವುದಿಲ್ಲ.
- ಬಳಕೆಯ ಇತಿಹಾಸ, ವೆಚ್ಚಗಳ ವಿಶ್ಲೇಷಣೆ, provider/account ವಿಂಡೋಗಳು, API-ಕೀ ಖರ್ಚು ಮಿತಿಗಳು, ವಿನಂತಿ-ವೆಚ್ಚದ ಲೆಡ್ಜರ್ ಮತ್ತು ದೈನಂದಿನ ಬಳಕೆಯ ರೋಲ್ಅಪ್ಗಳು ಈ ಶುಲ್ಕಗಳನ್ನು ಒಳಗೊಂಡಿವೆ. ನೋ-ಲಾಗ್ ಕೀಗಳು ಮೂಲ ಪಠ್ಯವನ್ನು ಉಳಿಸಿಕೊಳ್ಳದೆ ಸಂಖ್ಯಾತ್ಮಕ ಲೆಕ್ಕಪತ್ರವನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ.
- ಕಾಣೆಯಾದ ಬಳಕೆ ಅಥವಾ ಸುಂಕಗಳು**ಅಜ್ಞಾತ** , ಉಚಿತವಲ್ಲ: ಪ್ರತಿಕ್ರಿಯೆ-ವೆಚ್ಚದ ಹೆಡರ್ ಅನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗಿದೆ ಮತ್ತು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಬೆಲೆಯಿಲ್ಲದ-ಬಳಕೆಯ ನೀತಿಯು ಸೀಮಿತ API ಕೀಗಳಿಗೆ ಅನ್ವಯಿಸುತ್ತದೆ. ಸ್ಪಷ್ಟವಾಗಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ ಶೂನ್ಯ ದರಗಳು ಮಾನ್ಯವಾದ ಶೂನ್ಯ-ವೆಚ್ಚದ ಬಳಕೆಯಾಗಿ ಉಳಿಯುತ್ತವೆ.

ಇದು ಫಾರ್ವರ್ಡ್-ಓನ್ಲಿ ಅಕೌಂಟಿಂಗ್ ಆಗಿದೆ. ಬಳಕೆಯ ಇತಿಹಾಸವನ್ನು ಎಂದಿಗೂ ಬರೆಯದ ಹಳೆಯ OCR/embedding ಕರೆಗಳನ್ನು ಈ ವಲಸೆಯಿಂದ ಮರುನಿರ್ಮಾಣ ಮಾಡಲಾಗುವುದಿಲ್ಲ. ಕ್ಯಾಟಲಾಗ್ ಅಂದಾಜುಗಳು USD ಅಂದಾಜುಗಳಾಗಿವೆ, ಸರಕುಪಟ್ಟಿ ಅಲ್ಲ, ಮತ್ತು ಕರೆನ್ಸಿ ಪರಿವರ್ತನೆ, ತೆರಿಗೆ ಅಥವಾ ರಿಯಾಯಿತಿಗಳನ್ನು ಒಳಗೊಂಡಿರುವುದಿಲ್ಲ.

### ಮಾತು ಮತ್ತು ಚಿತ್ರಗಳು

- ಯಶಸ್ವಿ `/v1/audio/transcriptions`, `/v1/audio/speech` ಮತ್ತು ಇಮೇಜ್-ಜನರೇಷನ್ ಪ್ರಯತ್ನಗಳು ಸಂಖ್ಯಾತ್ಮಕ ಲೆಕ್ಕಪತ್ರವನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ. ನೇರ ಮತ್ತು ಕಾಂಬೊ ಕರೆಗಳು ಕರೆ ಮಾಡುವವರ API ಕೀ ಮತ್ತು ಆಯ್ದ ಸಂಪರ್ಕವನ್ನು ಒಯ್ಯುತ್ತವೆ; ಕಾಂಬೊ ಹೊದಿಕೆಯು ಎಂದಿಗೂ ಎರಡನೇ ಡೆಬಿಟ್ ಅನ್ನು ಸೇರಿಸುವುದಿಲ್ಲ.
- ಒದಗಿಸುವವರು-ವರದಿ ಮಾಡಿದ USD ಸ್ಪಷ್ಟವಾದ ಶೂನ್ಯ ಶುಲ್ಕವನ್ನು ಒಳಗೊಂಡಂತೆ ಕ್ಯಾಟಲಾಗ್ ಅಂದಾಜಿನ ಮೇಲೆ ಗೆಲ್ಲುತ್ತದೆ. OpenRouter ನ JSON `usage.cost` ಅನ್ನು `cost_usd` ಗೆ ಸಾಮಾನ್ಯಗೊಳಿಸಲಾಗಿದೆ. ಇಲ್ಲದಿದ್ದರೆ, ಅಳತೆ ಮಾಡಿದ ಟೋಕನ್ಗಳು ಟೋಕನ್ ಬೆಲೆಗಳನ್ನು ಬಳಸುತ್ತವೆ, ಪ್ರತಿ ಸೆಕೆಂಡ್ಗೆ ಪ್ರತಿಲೇಖನದ ಬೆಲೆಗಳನ್ನು ಬಳಸುತ್ತವೆ, ಸ್ಪೀಚ್ ಇನ್ಪುಟ್ ಯುನಿಕೋಡ್ ಅಕ್ಷರ ಎಣಿಕೆಗಳನ್ನು ಬಳಸುತ್ತದೆ ಮತ್ತು ಫ್ಲಾಟ್-ಬೆಲೆಯ ಚಿತ್ರಗಳು ವಿನಂತಿಸಿದ `n` ಅಲ್ಲ, ವಾಸ್ತವವಾಗಿ ಹಿಂತಿರುಗಿಸಿದ ಸಂಖ್ಯೆಯನ್ನು ಬಳಸುತ್ತವೆ.
- ಬೈನರಿ OpenRouter TTS ಯಾವುದೇ JSON ಬಳಕೆಯ ದೇಹವನ್ನು ಹೊಂದಿಲ್ಲ. ಆಡಿಯೋ ಪೂರ್ಣಗೊಂಡ ನಂತರ ಅಥವಾ ಕರೆ ಮಾಡಿದವರು ರದ್ದುಗೊಳಿಸಿದ ನಂತರ, OmniRoute ಅದರ ಪೀಳಿಗೆಯ ID ಅನ್ನು ಪ್ರಶ್ನಿಸುತ್ತದೆ**ಅದೇ** OpenRouter ಮೂಲವನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗಿದೆ. EU ವಿನಂತಿಯು ಎಂದಿಗೂ ಜಾಗತಿಕ ಮೂಲಕ್ಕೆ ಹಿಂತಿರುಗುವುದಿಲ್ಲ. ಇದು ಸೀಮಿತವಾದ, ಓದಲು-ಮಾತ್ರ ಲುಕ್ಅಪ್ ಆಗಿದೆ; ಲೆಕ್ಕಪರಿಶೋಧನೆಗಾಗಿ ಸಂಶ್ಲೇಷಣೆಯನ್ನು ಮರುಪ್ರಯತ್ನಿಸಲಾಗಿಲ್ಲ. ಆಡಿಯೊ ಮುಗಿದ ನಂತರ ಬಿಲ್ಲಿಂಗ್ ದಾಖಲೆಗಳು ಕಾಣಿಸಿಕೊಳ್ಳಬಹುದು: ನೆಟ್ವರ್ಕ್ ಡೆಡ್ಲೈನ್ಗಳನ್ನು ಒಳಗೊಂಡಂತೆ ಸುಮಾರು 52 ಸೆಕೆಂಡುಗಳವರೆಗೆ ಹಿನ್ನೆಲೆಯಲ್ಲಿ ಲುಕಪ್ ಮರುಪ್ರಯತ್ನಗಳು ರನ್ ಆಗುತ್ತವೆ.
- ಆ ಲುಕಪ್ ಸಮಯದಲ್ಲಿ, ಆಡಿಯೊ ಪ್ರತಿಕ್ರಿಯೆಯು `X-OmniRoute-Cost-Status: pending` ಹೊಂದಿದೆ ಮತ್ತು ಯಾವುದೇ ಪ್ರತಿಕ್ರಿಯೆ-ವೆಚ್ಚದ ಹೆಡರ್ ಇಲ್ಲ. ಇದರ ಅಂತಿಮ ಶುಲ್ಕವು ಬಳಕೆಯ ಇತಿಹಾಸ, ವಿಶ್ಲೇಷಣೆ ಮತ್ತು ಸಮನ್ವಯದ ನಂತರ ಕೀ ಲೆಡ್ಜರ್ನಲ್ಲಿ ಕಾಣಿಸಿಕೊಳ್ಳುತ್ತದೆ. ಮೆಟಾಡೇಟಾ ಲಭ್ಯವಿಲ್ಲದಿದ್ದರೆ, ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ ಸುಂಕದ ಸ್ನ್ಯಾಪ್ಶಾಟ್ ಅನ್ನು ಬಳಸಲಾಗುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ ವೆಚ್ಚವು ತಿಳಿದಿಲ್ಲ.
- ಸೆಕೆಂಡುಗಳು, ಅಕ್ಷರಗಳು ಮತ್ತು ಇಮೇಜ್ ಎಣಿಕೆಗಳು ಪ್ರತ್ಯೇಕ ಬಿಲ್ಲಿಂಗ್-ಯೂನಿಟ್ ಕ್ಷೇತ್ರಗಳನ್ನು ಹೊಂದಿವೆ, ಎಂದಿಗೂ ನಕಲಿ ಟೋಕನ್ ಎಣಿಕೆಗಳು. ಅಕೌಂಟಿಂಗ್ ಕೇವಲ ಸಂಖ್ಯಾತ್ಮಕ ಬಳಕೆಯನ್ನು ಮಾತ್ರ ಉಳಿಸಿಕೊಂಡಿದೆ, ಭಾಷಣ ಪಠ್ಯ, ಪ್ರತಿಗಳು ಅಥವಾ ಇಮೇಜ್ ಬೈಟ್ಗಳನ್ನು ಅಲ್ಲ. ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಬೆಲೆಯಿಲ್ಲದ-ಇಮೇಜ್ ವಿನಾಯಿತಿಗಳು ಬದಲಾಗುವುದಿಲ್ಲ: ನಿಜವಾದ ಕಾಣೆಯಾದ ಇಮೇಜ್ ಸುಂಕವು ಹೊಸದಾಗಿ ಸೀಮಿತ ಕೀಲಿಯನ್ನು ಲಾಕ್ ಮಾಡುವುದಿಲ್ಲ ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆಯು ಕರೆಯನ್ನು ಉಚಿತ ಎಂದು ಘೋಷಿಸುವ ಬದಲು ವೆಚ್ಚದ ಹೆಡರ್ ಅನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ. ಬೆಲೆ ಅಂಗಡಿಯ ವೈಫಲ್ಯವು ವಿಫಲ-ಮುಚ್ಚಿದ ಜಾರಿಗಾಗಿ ಬಳಕೆಯ ಪುರಾವೆಗಳನ್ನು ಇನ್ನೂ ಉಳಿಸಿಕೊಂಡಿದೆ.

ಯಾವುದೇ ಐತಿಹಾಸಿಕ speech/image ಚಾರ್ಜ್ ಅನ್ನು ಕಂಡುಹಿಡಿಯಲಾಗಿಲ್ಲ ಅಥವಾ ಬ್ಯಾಕ್ಫಿಲ್ ಮಾಡಲಾಗಿಲ್ಲ. ಇನ್ವಾಯ್ಸ್ಗಳಿಗೆ ಮತ್ತು ಶುಲ್ಕವನ್ನು ವರದಿ ಮಾಡದ ಕರೆಗಳಿಗೆ ಪೂರೈಕೆದಾರರ ಬಿಲ್ಲಿಂಗ್ ಉಲ್ಲೇಖವಾಗಿ ಉಳಿದಿದೆ.

## ಡ್ಯಾಶ್ಬೋರ್ಡ್: ವೆಚ್ಚಗಳ ಪುಟ

**ವೆಚ್ಚಗಳು** ಪುಟವು `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`) ನಲ್ಲಿ ಇದೆ.
ಇದರ ಮುಖ್ಯ ನೋಟವು **ವೆಚ್ಚದ ಅವಲೋಕನ** ಟ್ಯಾಬ್
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`) ಆಗಿದ್ದು,
ಇದು `GET /api/usage/analytics` ನಿಂದ ಎಲ್ಲವನ್ನೂ ಲೋಡ್ ಮಾಡುತ್ತದೆ.

ಇದು ತೋರಿಸುವ ವಿಷಯಗಳು:

- **ವೆಚ್ಚದ ಟೈಲ್ಗಳು** — _ಇಂದು (1d)_, _7d_, _30d_ ಮತ್ತು ಆಯ್ಕೆಮಾಡಿದ
  ಅವಧಿಯ ಅಂದಾಜು ವೆಚ್ಚ. ವ್ಯಾಪ್ತಿ ಆಯ್ಕೆಗಾರ: `7d`, `30d`, `90d`, `all`.
- **ಪ್ರಮುಖ ಮೆಟ್ರಿಕ್ಗಳು** — ಅವಧಿಯಲ್ಲಿನ ವಿನಂತಿಗಳು, ಸಕ್ರಿಯ ಪೂರೈಕೆದಾರರು, ಸಕ್ರಿಯ ಮಾದರಿಗಳು, ಪ್ರತಿ
  ವಿನಂತಿಯ ಸರಾಸರಿ ವೆಚ್ಚ.
- **ವೆಚ್ಚ ಅನ್ವೇಷಕ** — **ಪೂರೈಕೆದಾರ**, **ಮಾದರಿ**,
  **API ಕೀ**, **ಖಾತೆ**, ಅಥವಾ **ಸೇವಾ ಶ್ರೇಣಿ** ಆಧಾರದಲ್ಲಿ ಗುಂಪು ಮಾಡಲಾದ, ವಿಂಗಡಿಸಬಹುದಾದ/ಫಿಲ್ಟರ್ ಮಾಡಬಹುದಾದ ಕೋಷ್ಟಕ; ಇದರಲ್ಲಿ ವೆಚ್ಚ, ವಿನಂತಿಗಳು, ಟೋಕನ್ಗಳು, ಪ್ರತಿ
  ವಿನಂತಿಯ ಸರಾಸರಿ ವೆಚ್ಚ ಮತ್ತು ಒಟ್ಟು ವೆಚ್ಚದಲ್ಲಿನ ಪಾಲಿನ % ಇರುತ್ತವೆ.
- **ಟೋಕನ್ ಬಳಕೆ** — ಒಟ್ಟು / ಇನ್ಪುಟ್ / ಔಟ್ಪುಟ್ ಟೋಕನ್ಗಳು ಮತ್ತು ಇನ್ಪುಟ್:ಔಟ್ಪುಟ್ ಅನುಪಾತ.
- **ರೂಟಿಂಗ್ ದಕ್ಷತೆ** — ಫಾಲ್ಬ್ಯಾಕ್ ಎಣಿಕೆ, ಫಾಲ್ಬ್ಯಾಕ್ ದರ ಮತ್ತು ವಿನಂತಿಸಿದ-ಮಾದರಿಯ ವ್ಯಾಪ್ತಿ.
- **ಮಾಸಿಕ ಮುನ್ಸೂಚನೆ** — ಇತ್ತೀಚಿನ ದೈನಂದಿನ ಸರಾಸರಿಯಿಂದ ತಿಂಗಳ ಅಂತ್ಯದ ವೆಚ್ಚವನ್ನು ಅಂದಾಜಿಸುತ್ತದೆ.
- **ಅವಧಿ ಹೋಲಿಕೆ** — ಅವಧಿಯ ಮೊದಲ ಮತ್ತು ಎರಡನೇ ಅರ್ಧದ ನಡುವಿನ % ಬದಲಾವಣೆ.
- **ಚಾರ್ಟ್ಗಳು** — ದೈನಂದಿನ ವೆಚ್ಚದ ಪ್ರವೃತ್ತಿ, ಪೂರೈಕೆದಾರರ ಪಾಲು (ಪೈ), ಪ್ರಮುಖ ಪೂರೈಕೆದಾರರು, ಪ್ರಮುಖ ಮಾದರಿಗಳು, API ಕೀ
  ಪ್ರಕಾರ ವೆಚ್ಚ, ಖಾತೆ ಪ್ರಕಾರ ವೆಚ್ಚ, ವಾರದ ಬಳಕೆಯ ಮಾದರಿ ಮತ್ತು ಚಟುವಟಿಕೆಯ ಹೀಟ್ಮ್ಯಾಪ್.
- **ರಫ್ತು** — ಪ್ರಸ್ತುತ ಅವಧಿಯನ್ನು **CSV** ಅಥವಾ **JSON** ಆಗಿ ಡೌನ್ಲೋಡ್ ಮಾಡಿ (ಶೂನ್ಯಕ್ಕಿಂತ ಹೆಚ್ಚಿನ ವೆಚ್ಚದ ಡೇಟಾ
  ಇದ್ದಾಗ ಬಟನ್ಗಳು ಕಾಣಿಸಿಕೊಳ್ಳುತ್ತವೆ).

ಬೆಲೆ ನಿಗದಿಪಡಿಸಿದ ಟ್ರಾಫಿಕ್ ಇಲ್ಲದಿದ್ದಾಗ, ಉಳಿತಾಯ-ಟ್ರ್ಯಾಕರ್ ಮಾದರಿಯನ್ನು ಪ್ರತಿಬಿಂಬಿಸುವಂತೆ ಸಾಲುಗಳು `$0`
ಬದಲಿಗೆ "ಹಳೆಯದು / ಉಚಿತ" ಲೇಬಲ್ನೊಂದಿಗೆ ಪ್ರದರ್ಶಿಸಲ್ಪಡುತ್ತವೆ.

### ಸಂಬಂಧಿತ ವೆಚ್ಚಗಳ ಉಪ-ಪುಟಗಳು

ವೆಚ್ಚಗಳ ಪ್ರದೇಶವು ಇವುಗಳನ್ನೂ ಒಳಗೊಂಡಿದೆ (ಎಲ್ಲವೂ `/dashboard/costs/` ಅಡಿಯಲ್ಲಿ):

- **ಬೆಲೆ ನಿಗದಿ** (`/dashboard/costs/pricing`) — ಪ್ರತಿ-ಮಾದರಿಯ ಬೆಲೆಗಳನ್ನು ವೀಕ್ಷಿಸಿ ಮತ್ತು ಅತಿಕ್ರಮಿಸಿ (ಹಂಚಿಕೆಯ
  ಬೆಲೆ ನಿಗದಿ ಟ್ಯಾಬ್ ಅನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ).
- **ಬಜೆಟ್** (`/dashboard/costs/budget`) — ಪ್ರತಿ-ವ್ಯಾಪ್ತಿಯ ವೆಚ್ಚ ಮಿತಿಗಳನ್ನು ಹೊಂದಿಸಿ (ಹಂಚಿಕೆಯ
  ಬಜೆಟ್ ಟ್ಯಾಬ್ ಅನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ).
- **ಕೋಟಾ ಹಂಚಿಕೆ** (`/dashboard/costs/quota-share`) — ಹಂಚಿಕೆಯ-ಕೋಟಾ ಪೂಲ್ಗಳು ಮತ್ತು ಬಳಕೆ-ದರದ
  ನೋಟಗಳು.

| `PATCH`  | `/api/pricing`          | `{ provider: { model: { input, output, cached, … } } }` ಗಾಗಿ ಬೆಲೆ ನಿಗದಿಯನ್ನು ಅತಿಕ್ರಮಿಸಿ.                                                                                             |
| `DELETE` | `/api/pricing`          | ಬಳಕೆದಾರರ ಬೆಲೆ ಓವರ್‌ರೈಡ್‌ಗಳನ್ನು ತೆಗೆದುಹಾಕಿ; ಬೇಕಿದ್ದರೆ `?provider=&model=` ಮೂಲಕ ವ್ಯಾಪ್ತಿಯನ್ನು ಮಿತಿಗೊಳಿಸಬಹುದು. ಸಿಂಕ್ ಮಾಡಿದ ದರಗಳು ಅಥವಾ ಅಂತರ್ನಿರ್ಮಿತ ಡೀಫಾಲ್ಟ್‌ಗಳು ಪರ್ಯಾಯಗಳಾಗಿ ಉಳಿಯುತ್ತವೆ. |
| `GET`    | `/api/pricing/defaults` | ಡೀಫಾಲ್ಟ್ ಪ್ರತಿ-1M ಫಾಲ್ಬ್ಯಾಕ್ ದರಗಳನ್ನು ತೋರಿಸಿ.                                                                                                                                        |
| `GET`    | `/api/pricing/models`   | ಮಾದರಿಯ ಪ್ರಕಾರ ಕೀ ಮಾಡಲಾದ ಬೆಲೆ ನಿಗದಿ.                                                                                                                                                  |
| `POST`   | `/api/pricing/sync`     | ಬಾಹ್ಯ ಮೂಲಗಳಿಂದ (LiteLLM) ಹಸ್ತಚಾಲಿತ ಸಿಂಕ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ.                                                                                                                           |
| `GET`    | `/api/pricing/sync`     | ಪ್ರಸ್ತುತ ಸಿಂಕ್ ಸ್ಥಿತಿ.                                                                                                                                                               |
| `DELETE` | `/api/pricing/sync`     | LiteLLM ನಿಂದ ಸಿಂಕ್ ಮಾಡಿದ ಬೆಲೆಗಳನ್ನು (`pricing_synced`) ಮಾತ್ರ ತೆರವುಗೊಳಿಸಿ; models.dev ಡೇಟಾ ಪ್ರತ್ಯೇಕವಾಗಿದೆ.                                                                            |

## CLI

OmniRoute ನ CLI ವೆಚ್ಚ, ಬಳಕೆ ಮತ್ತು ಬೆಲೆ ನಿಗದಿ ಆದೇಶಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ (ಇವುಗಳನ್ನು
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) ನಲ್ಲಿ ನೋಂದಾಯಿಸಲಾಗಿದೆ).

### `omniroute cost`

`/api/usage/analytics` ನಿಂದ ಒಟ್ಟುಗೂಡಿಸಿದ ವೆಚ್ಚದ ವರದಿ.

```bash
omniroute cost                          # ಕಳೆದ 30d, ಪೂರೈಕೆದಾರರ ಪ್ರಕಾರ ಗುಂಪು ಮಾಡಲಾಗಿದೆ
omniroute cost --period 7d              # ಕಳೆದ 7 ದಿನಗಳು
omniroute cost --group-by model         # provider | model | combo | api-key | day ಪ್ರಕಾರ ಗುಂಪು ಮಾಡಿ
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ಕಾಲಮ್ಗಳು: ಗುಂಪು, ವಿನಂತಿಗಳು, ಇನ್/ಔಟ್ ಟೋಕನ್ಗಳು, ವೆಚ್ಚ (USD), ಮತ್ತು ಒಟ್ಟು ಮೊತ್ತದ %. ಕೊನೆಯಲ್ಲಿ
ಒಟ್ಟಾರೆ ಮೊತ್ತದ ಸಾಲನ್ನು ಮುದ್ರಿಸಲಾಗುತ್ತದೆ (`--quiet` ಅಥವಾ `--output json` ಬಳಸಿದಾಗ ಇದನ್ನು ತೋರಿಸಲಾಗುವುದಿಲ್ಲ).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ಪ್ರತಿ ಪೂರೈಕೆದಾರರ ವೆಚ್ಚದ ಸಾರಾಂಶ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ಬಜೆಟ್ಗಳು
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` ಆದೇಶವು `GET /api/pricing/defaults` ಅನ್ನು ಓದುತ್ತದೆ. ಇದರ ಬದಲಿಗೆ ಪ್ರತ್ಯೇಕ ಮಾದರಿಗಳ
> ಬೆಲೆಗಳನ್ನು ಸಂಪಾದಿಸಲು, **ಬೆಲೆ ನಿಗದಿ** ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಪುಟ ಅಥವಾ `PATCH /api/pricing` ಬಳಸಿ.

## ಸಮಸ್ಯೆ ಪರಿಹಾರ

- **ಎಲ್ಲಾ ವೆಚ್ಚಗಳು $0 / "Legacy / Free" ಎಂದು ತೋರಿಸುತ್ತವೆ.** ಬಳಕೆಯಲ್ಲಿರುವ ಮಾದರಿಗಳಿಗೆ ಬೆಲೆ ನಿಗದಿ ನಮೂದು ಇಲ್ಲ.
  ಬಾಹ್ಯ ಸಿಂಕ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ (`PRICING_SYNC_ENABLED=true`) ಮತ್ತು `omniroute pricing sync` ಚಲಾಯಿಸಿ, ಅಥವಾ
  ಬೆಲೆ ನಿಗದಿ ಪುಟ / `PATCH /api/pricing` ಮೂಲಕ ಬೆಲೆಗಳನ್ನು ಹಸ್ತಚಾಲಿತವಾಗಿ ಹೊಂದಿಸಿ.
- **ಐತಿಹಾಸಿಕ ಮಾದರಿಯ ಬೆಲೆ ತಪ್ಪಾಗಿದೆ.** ಬೆಲೆಯನ್ನು ಸರಿಪಡಿಸಿ (ಅತಿಕ್ರಮಿಸಿ ಅಥವಾ ಮರು-ಸಿಂಕ್ ಮಾಡಿ) — ಪ್ರತಿ ವಿಶ್ಲೇಷಣಾ ಓದುವಿಕೆಯಲ್ಲೂ
  ಟೋಕನ್ ಎಣಿಕೆಗಳಿಂದ ವೆಚ್ಚವನ್ನು ಮರುಲೆಕ್ಕಾಚಾರ ಮಾಡಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಅಂದಾಜುಗಳು ಹಿಂದಿನ ಅವಧಿಗಳಿಗೂ ಅನ್ವಯಿಸುವಂತೆ ನವೀಕರಣಗೊಳ್ಳುತ್ತವೆ.
- **ವೆಚ್ಚದ ಮಾಹಿತಿ ನೈಜ ಸಮಯಕ್ಕಿಂತ ವಿಳಂಬವಾಗಿರುತ್ತದೆ.** ಪ್ರತಿ ಕೀಗೆ ಸಂಬಂಧಿಸಿದ ವೆಚ್ಚವನ್ನು ಬ್ಯಾಚ್ಗಳಲ್ಲಿ ಸಂಸ್ಕರಿಸಲಾಗುತ್ತದೆ; ಹೆಚ್ಚು ನವೀನ ಅಂಕಿಗಳು
  ಬೇಕಿದ್ದರೆ `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ಅನ್ನು ಕಡಿಮೆ ಮಾಡಿ.
