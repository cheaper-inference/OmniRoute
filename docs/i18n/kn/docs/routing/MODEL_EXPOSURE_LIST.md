> ಆಪ್ಟ್-ಇನ್, ಡೀಫಾಲ್ಟ್ ಆಗಿ ಆಫ್ (`modelVisibilityAllowlist`/`modelVisibilityDenylist` ಎರಡೂ ಖಾಲಿ `/v1/models` ಕ್ಯಾಟಲಾಗ್ AND ಪ್ರತಿ `auto/*` ಅಭ್ಯರ್ಥಿ ಪೂಲ್ ಬೈಟ್-ಸಮಾನವಾಗಿದೆ). ವೆಚ್ಚದೊಂದಿಗೆ ಯಾವುದೇ ಸಂಬಂಧವಿಲ್ಲದ ಕಾರಣಗಳಿಗಾಗಿ ಕ್ಯುರೇಟೆಡ್ ಮಾಡೆಲ್ ಪಟ್ಟಿಯನ್ನು ಬಯಸುವ ನಿರ್ವಾಹಕರಿಗೆ `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`) ನ ಒಡಹುಟ್ಟಿದವರು.

## ಇದು ಏಕೆ ಅಸ್ತಿತ್ವದಲ್ಲಿದೆ

`hidePaidModels` ಉತ್ತರಿಸುತ್ತಾನೆ "ಈ ಮಾದರಿಯು ಉಚಿತವೇ?" ಮತ್ತು `hideAutoCombos` ಉತ್ತರಗಳು " `auto/*` ವರ್ಚುವಲ್ ಐಡಿಗಳನ್ನು ಜಾಹೀರಾತು ಮಾಡಬೇಕೇ?" — ಅಥವಾ ನಿರ್ವಾಹಕರು ಮಾದರಿಗಳ ಅನಿಯಂತ್ರಿತ ಉಪವಿಭಾಗವನ್ನು ಕ್ಯುರೇಟ್ ಮಾಡಲು ಅನುಮತಿಸುವುದಿಲ್ಲ (ಉದಾಹರಣೆಗೆ, ನಿರ್ದಿಷ್ಟಪಡಿಸಿದ Claude ಕೋಡ್ / OpenCode ಕ್ಲೈಂಟ್ ನೋಡಬೇಕಾದ ಮಾದರಿಗಳನ್ನು ನಿಖರವಾಗಿ ಪ್ರಸ್ತುತಪಡಿಸುವುದು, ಬೆಲೆಯಿಂದ ಸ್ವತಂತ್ರವಾಗಿರುತ್ತದೆ). #11481 ಎರಡು ಸ್ವತಂತ್ರ, ಆಪ್ಟ್-ಇನ್ ಸ್ಟ್ರಿಂಗ್-ಅರೇ ಸೆಟ್ಟಿಂಗ್ಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ.

## ಸೆಟ್ಟಿಂಗ್ಗಳು

| ಕೀ                         | ಟೈಪ್ ಮಾಡಿ  | ಡೀಫಾಲ್ಟ್ | ಅರ್ಥ                                                                             |
| -------------------------- | ---------- | -------- | -------------------------------------------------------------------------------- |
| `modelVisibilityDenylist`  | `string[]` | `[]`     | ಅಭ್ಯರ್ಥಿಗೆ ಹೊಂದಿಕೆಯಾಗುವ ನಮೂದುಗಳು ಅದನ್ನು catalog/candidate ಪೂಲ್ನಿಂದ ಮರೆಮಾಡುತ್ತವೆ. |
| `modelVisibilityAllowlist` | `string[]` | `[]`     | ಖಾಲಿ ಇಲ್ಲದಿದ್ದಾಗ, ಅಭ್ಯರ್ಥಿಗೆ ಹೊಂದಿಕೆಯಾಗುವ ONLY ನಮೂದುಗಳು ಬಹಿರಂಗವಾಗಿ ಉಳಿಯುತ್ತವೆ.   |

ಎರಡೂ 200 ಅಕ್ಷರಗಳವರೆಗೆ 500 ನಮೂದುಗಳನ್ನು ಸ್ವೀಕರಿಸುತ್ತವೆ ( `src/shared/validation/settingsSchemas.ts` ನಲ್ಲಿ Zod-ಮೌಲ್ಯೀಕರಿಸಲಾಗಿದೆ). ಒಂದು ನಮೂದು ಹೀಗಿದೆ:

- ನಿಖರವಾದ ಕ್ಯಾಟಲಾಗ್ ಐಡಿ — `"gpt-4o"` (ಬೇರ್ ಮಾಡೆಲ್ ಐಡಿ) ಅಥವಾ `"openai/gpt-4o"` (ಒದಗಿಸುವವರು-ಪೂರ್ವಪ್ರತ್ಯಯ), ಅಥವಾ
- `*`/`?` — ಬಳಸಿ ಗ್ಲೋಬ್ ಮಾದರಿಯನ್ನು ಉದಾ `"openai/gpt-4*"` ಅಥವಾ `"anthropic/*"` — ಅದೇ ಹಂಚಿಕೆಯ `globToRegex()` ಮ್ಯಾಚರ್ (`src/shared/utils/globPattern.ts`) ಮೂಲಕ ಪರಿಹರಿಸಲಾಗಿದೆ `ModelRoutingSection` ನ ಪ್ರತಿ-ಮಾದರಿ ಕಾಂಬೊ ಮ್ಯಾಪಿಂಗ್ಗಳು ಮತ್ತು `freeModels.ts::matchesOnlyPaidModels` ಈಗಾಗಲೇ ಬಳಸಲಾಗಿದೆ.

ಪ್ರಾಶಸ್ತ್ಯ: ನಿರಾಕರಣೆದಾರರನ್ನು ಮೊದಲು ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ (ನಿರಾಕರಿಸಿದ ನಮೂದನ್ನು ಯಾವಾಗಲೂ ಮರೆಮಾಡಲಾಗಿದೆ, ಅದು ಅನುಮತಿಪಟ್ಟಿಗೆ ಹೊಂದಿಕೆಯಾಗಿದ್ದರೂ ಸಹ); ಅನುಮತಿ ಪಟ್ಟಿಯು ಖಾಲಿಯಾಗಿಲ್ಲದಿದ್ದಾಗ, ಅದು ಹೊಂದಿಕೆಯಾಗುವ ನಮೂದುಗಳು ಮಾತ್ರ ಉಳಿದುಕೊಳ್ಳುತ್ತವೆ.

## ಎರಡು ಚಾಕ್ಪಾಯಿಂಟ್ಗಳು, ಒಂದಲ್ಲ

#6512 (ಒಂದು `hidePaidModels` -only ಕ್ಯಾಟಲಾಗ್ ಫಿಲ್ಟರ್ ಇನ್ನೂ ಪಾವತಿಸಿದ ಮಾದರಿಗೆ `auto/*` ಮಾರ್ಗವನ್ನು ಅನುಮತಿಸುತ್ತದೆ, ಏಕೆಂದರೆ ಕಾಂಬೊ ಅಭ್ಯರ್ಥಿ ಪೂಲ್ ಅನ್ನು ಸ್ವತಂತ್ರವಾಗಿ ನಿರ್ಮಿಸಲಾಗಿದೆ) ಇಲ್ಲಿ ಒಂದೇ ರೀತಿಯಲ್ಲಿ ಅನ್ವಯಿಸುತ್ತದೆ. ಹೊಂದಾಣಿಕೆಯ ಮುನ್ಸೂಚನೆ `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`) ಅನ್ನು BOTH ನಿಂದ ಕರೆಯಲಾಗುತ್ತದೆ:

- `src/app/api/v1/models/catalog.ts` — ಸ್ವತಃ `/v1/models` ಪಟ್ಟಿಯನ್ನು ಹೊಂದಿದೆ, ಅದೇ 5 ಪ್ರತಿ-ಮೂಲದ ಚೋಕ್ಪಾಯಿಂಟ್ಗಳಲ್ಲಿ `shouldHidePaid()` ಈಗಾಗಲೇ ಗೇಟ್ಗಳು (ಸ್ಥಿರ `PROVIDER_MODELS`, ಸಿಂಕ್ ಮಾಡಿದ ಪೂರೈಕೆದಾರರ ಸಾಲುಗಳು, ಕಸ್ಟಮ್ ಸಾಲುಗಳು, ಅಲಿಯಾಸ್-ಬೆಂಬಲಿತ ಸಾಲುಗಳು, ನಿರ್ವಹಿಸಿದ-ಫಾಲ್ಬ್ಯಾಕ್ ಸಾಲುಗಳು).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — ಸಮಾನವಾದ `filterPaidOnlyCandidates()` ಕರೆ ಮಾಡಿದ ತಕ್ಷಣ `virtualFactory.ts::buildPreparedPool` ಯಿಂದ ಕರೆಯಲಾಗಿದೆ, ಆದ್ದರಿಂದ ನಿರಾಕರಿಸಿದ ಮಾದರಿಯನ್ನು ಎಂದಿಗೂ `auto/*` ಅಭ್ಯರ್ಥಿ ಪೂಲ್ಗೆ ಆಯ್ಕೆ ಮಾಡಲಾಗುವುದಿಲ್ಲ.

## NOT ಅನ್ನು ಏನು ಫಿಲ್ಟರ್ ಮಾಡಲಾಗಿದೆ

ಕನ್ನಡಿಗಳು `hideAutoCombos` ನ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ನಡವಳಿಕೆ: ಮಾದರಿ ಐಡಿ ಕಳುಹಿಸಲಾಗಿದೆ** ಸ್ಪಷ್ಟವಾಗಿ** ( `auto/*` ಮೂಲಕ ಅಲ್ಲ, ಮತ್ತು ಕ್ಯಾಟಲಾಗ್ ಪಟ್ಟಿಯ ಮೂಲಕ ಕಂಡುಹಿಡಿಯಲಾಗಿಲ್ಲ) ರವಾನೆಯಲ್ಲಿ ಎಂದಿಗೂ ನಿರ್ಬಂಧಿಸಲಾಗಿಲ್ಲ — ಮಾತ್ರ advertisement/candidate-pool ಸದಸ್ಯತ್ವವನ್ನು ಫಿಲ್ಟರ್ ಮಾಡಲಾಗುತ್ತದೆ. ಇದು `hidePaidModels` ನಿಂದ ಸ್ವತಂತ್ರವಾಗಿದೆ; ನಿರ್ವಾಹಕರು ವೆಚ್ಚದೊಂದಿಗೆ ಯಾವುದೇ ಸಂಬಂಧವಿಲ್ಲದ ಕಾರಣಗಳಿಗಾಗಿ ಕ್ಯುರೇಟೆಡ್ ಸೆಟ್ ಅನ್ನು ಬಯಸಬಹುದು, ಆದ್ದರಿಂದ ಎರಡೂ ಸೆಟ್ಟಿಂಗ್ಗಳು ಸ್ವತಂತ್ರ AND-ed ಫಿಲ್ಟರ್ಗಳಾಗಿ ಸಂಯೋಜನೆಗೊಳ್ಳುತ್ತವೆ, `catalog.ts` ನಲ್ಲಿ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಬಹು-ಧ್ವಜ ಸಂಯೋಜನೆಯಂತೆಯೇ.

ಸೆಟ್ಟಿಂಗ್ಗಳ ರಫ್ತು (`GET /api/settings/export-json`) ಎರಡೂ ಅರೇಗಳನ್ನು ಅಕ್ಷರಶಃ ಒಳಗೊಂಡಿದೆ, ಯಾವುದೇ ಇತರ ಸೆಟ್ಟಿಂಗ್ಗಳ ಕ್ಷೇತ್ರದಂತೆ — `hidePaidModels` ನ ಕಾಂಬೊ-ಸ್ಟೆಪ್ ರಫ್ತು ಫಿಲ್ಟರ್ನಂತೆ, ಇಲ್ಲಿ ಯಾವುದೇ ಮರು-ಜಲೀಕರಣದ ಅಪಾಯವಿಲ್ಲ: ರಫ್ತು ಮಾಡಿದ ಕಾಂಬೊ ಹಂತದಲ್ಲಿ ಎಂಬೆಡ್ ಮಾಡಲಾದ ನಿರಾಕರಿಸಿದ ಐಡಿಯು ನಿರ್ವಾಹಕರ ಸ್ವಂತ ಸ್ಪಷ್ಟ ರೂಟಿಂಗ್ ಆಯ್ಕೆಯಾಗಿದೆ, ರಫ್ತು ಮಾಡಲು ಅಗತ್ಯವಿಲ್ಲ.

## ಕಾಂಬೊಸ್-ಮಾತ್ರ ಪಟ್ಟಿ (`exposeCombosOnly`)

ಕಾಂಬೊಗಳು ಸಾರ್ವಜನಿಕ ಮಾದರಿಯ ಮೇಲ್ಮೈ ಮತ್ತು ಪೂರೈಕೆದಾರರು ಕೇವಲ ಬ್ಯಾಕೆಂಡ್ಗಳಾಗಿರುವ ನಿಯೋಜನೆಗಳಿಗಾಗಿ ಪ್ರತ್ಯೇಕ ಬೂಲಿಯನ್, ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಆಯ್ಕೆ ಮತ್ತು `false`. ಇದು `true` ಆಗಿರುವಾಗ, ಸಾರ್ವಜನಿಕ ಪಟ್ಟಿಯು (`GET /v1/models`, `GET /v1`, ಮತ್ತು `getUnifiedModelsResponse()` ನಲ್ಲಿ ನಿರ್ಮಿಸಲಾದ ಇತರ `/v1` ಅನ್ವೇಷಣೆ ಮಾರ್ಗಗಳು ) `owned_by: "combo"` ನೊಂದಿಗೆ ಸಾಲುಗಳನ್ನು ಮಾತ್ರ ಇರಿಸುತ್ತದೆ : ಬಳಕೆದಾರ ಜೋಡಿಗಳು ಮತ್ತು ಅಂತರ್ನಿರ್ಮಿತ `auto/*` ಕಾಂಬೊಗಳು ( `hideAutoCombos` ಅವುಗಳನ್ನು ಮರೆಮಾಡದ ಹೊರತು). ಇದು ಪ್ರತಿ-ಕೀ `catalogScope: "combos"` ನಂತೆ ಅದೇ ಸಾಲಿನ ಪರೀಕ್ಷೆಯನ್ನು ಬಳಸುತ್ತದೆ ಮತ್ತು ಕೀಲಿಯ ಸ್ವಂತ allow/deny/scope ಫಿಲ್ಟರ್ಗಳು ಇನ್ನೂ ಮೇಲ್ಭಾಗದಲ್ಲಿ ಅನ್ವಯಿಸುತ್ತವೆ.

ಅದನ್ನು ಟಾಗಲ್ ಮಾಡಿ** ಸೆಟ್ಟಿಂಗ್ಗಳು → ರೂಟಿಂಗ್ → ಮಾದರಿಗಳ API ಪಟ್ಟಿ** , ಅಥವಾ `PATCH /api/settings {"exposeCombosOnly": true}` ಜೊತೆಗೆ.

ಮೇಲಿನ ಪಟ್ಟಿಗಳಂತೆ, ಇದು ಜಾಹೀರಾತನ್ನು ಮಾತ್ರ ಬದಲಾಯಿಸುತ್ತದೆ:

- ಒಂದು ಸ್ಪಷ್ಟವಾದ `provider/model` id ಇನ್ನೂ ರವಾನೆಯಾಗುತ್ತದೆ ಮತ್ತು `GET /v1/models/{id}` ಇನ್ನೂ ಅದನ್ನು ಪರಿಹರಿಸುತ್ತದೆ;
- ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಕ್ಯಾಟಲಾಗ್ (`GET /api/models/catalog`, ಮಾದರಿ ಪಿಕ್ಕರ್ಗಳು ಬಳಸುತ್ತಾರೆ) ಕಿರಿದಾಗಿಲ್ಲ;
- ಇದನ್ನು `auto/*` ಅಭ್ಯರ್ಥಿ ಪೂಲ್ಗಳಲ್ಲಿ ಪ್ರತಿಬಿಂಬಿಸಲಾಗಿಲ್ಲ, ಆದ್ದರಿಂದ `auto/*` ಕಾಂಬೊಗಳು ತಮ್ಮ ಪೂರ್ಣ ಪೂಲ್ ಅನ್ನು ಇರಿಸುತ್ತವೆ.
