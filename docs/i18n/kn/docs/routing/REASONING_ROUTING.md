ತಾರ್ಕಿಕ ರೂಟಿಂಗ್ ನಿಯಮಗಳು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಮಾದರಿ ಮತ್ತು ಕಾಂಬೊ ರೂಟಿಂಗ್ ಅನ್ನು ವಿಸ್ತರಿಸುತ್ತವೆ. ಯಾವುದೇ ಸಕ್ರಿಯ ನಿಯಮವು ಹೊಂದಿಕೆಯಾಗದಿದ್ದಾಗ,
ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಚಿಂತನೆ, ಸಫಿಕ್ಸ್, ಸಂಪರ್ಕ-ಡೀಫಾಲ್ಟ್ ಮತ್ತು ಪೂರೈಕೆದಾರ-ಅನುವಾದದ ನಡವಳಿಕೆ
ಬದಲಾಗದೆ ಉಳಿಯುತ್ತದೆ.

## ನಿರ್ವಹಣೆ

ನಿಯಮಗಳ ನಿರ್ವಹಣೆಯು **Settings → Global Routing** ಅಡಿಯಲ್ಲಿ ಲಭ್ಯವಿದೆ. API-ಕೀ ಎಡಿಟರ್ ಆಯ್ಕೆಮಾಡಿದ ಕೀಗೆ
ಫಿಲ್ಟರ್ ಮಾಡಲಾದ ಅದೇ ನಿರ್ವಹಣಾ UI ಅನ್ನು ಒದಗಿಸುತ್ತದೆ.

ನಿರ್ವಹಣಾ API ಅನ್ನು ಈ ರೂಟ್ಗಳ ಮೂಲಕ ಒದಗಿಸಲಾಗಿದೆ:

- `/api/settings/reasoning-routing-rules` ನಲ್ಲಿ `GET` ಮತ್ತು `POST`
- `/api/settings/reasoning-routing-rules/[id]` ನಲ್ಲಿ `GET`, `PATCH`, ಮತ್ತು `DELETE`
- `/api/settings/reasoning-routing-rules/simulate` ನಲ್ಲಿ `POST`

ಎಲ್ಲಾ ರೂಟ್ಗಳು `requireManagementAuth` ಅನ್ನು ಬಳಸುತ್ತವೆ. ಇನ್ಪುಟ್ಗಳನ್ನು
`src/shared/validation/schemas/reasoningRouting.ts` ನಲ್ಲಿರುವ ಸ್ಕೀಮಾಗಳ ಮೂಲಕ ಮೌಲ್ಯೀಕರಿಸಲಾಗುತ್ತದೆ. ಸಿಮ್ಯುಲೇಟರ್ ಎಂದಿಗೂ ಅಪ್ಸ್ಟ್ರೀಮ್ ಕರೆಯನ್ನು ಮಾಡುವುದಿಲ್ಲ.

## ನಿಯಮ ಪರಿಹಾರ

ಆರಂಭಿಕ ಮೌಲ್ಯಮಾಪನವು ನಿಖರವಾಗಿ ಒಂದು ನಿಯಮವನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತದೆ. ಸ್ಕೋಪ್ಗಳನ್ನು ಈ ಕ್ರಮದಲ್ಲಿ ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ:

1. `apiKey`
2. `combo`
3. `model`
4. `global`

ಒಂದು ಸ್ಕೋಪ್ನೊಳಗೆ, ಮೊದಲು ಹೆಚ್ಚಿನ `priority` ಗೆಲುವು ಸಾಧಿಸುತ್ತದೆ, ನಂತರ ಗ್ಲಾಬ್ ಮಾದರಿಗಿಂತ ನಿಖರವಾದ ಮಾದರಿ ಹೊಂದಾಣಿಕೆಗೆ ಆದ್ಯತೆ ನೀಡಲಾಗುತ್ತದೆ,
ಅದರ ನಂತರ ಸ್ಥಿರವಾದ `createdAt` ಮತ್ತು `id` ಕ್ರಮವನ್ನು ಅನುಸರಿಸಲಾಗುತ್ತದೆ. `requestTags` ಅನ್ನು `metadata.tags`
ನಿಂದ ಮಾತ್ರ ಓದಲಾಗುತ್ತದೆ ಮತ್ತು `any` ಅಥವಾ `all` ಹೊಂದಾಣಿಕೆಯನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ.

ಯಾವುದೇ ಆರಂಭಿಕ ನಿಯಮ ಗೆಲ್ಲದಿದ್ದಾಗ ಮತ್ತು ನಿರ್ದಿಷ್ಟ ಪೂರೈಕೆದಾರ ಸಂಪರ್ಕವನ್ನು
ಈಗಾಗಲೇ ಆಯ್ಕೆಮಾಡಿರುವಾಗ ಮಾತ್ರ `connection` ನಿಯಮವನ್ನು ಮೌಲ್ಯಮಾಪನ ಮಾಡಲಾಗುತ್ತದೆ. ಇದು ಪ್ರಯತ್ನದ ಮಟ್ಟ ಮತ್ತು ಬಜೆಟ್ ಅನ್ನು ಮಾತ್ರ ಬದಲಾಯಿಸಬಹುದು.

## ಪ್ರಯತ್ನ ಮತ್ತು ಬಜೆಟ್

`sourceEffort` `any`, `missing`, `none`, `low`, `medium`, `high`, `xhigh`, `max` ಮತ್ತು `ultra` ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ. `missing` ಎಂದರೆ ವಿನಂತಿಯು ಪ್ರತ್ಯೇಕ ಪ್ರಯತ್ನ ಅಥವಾ ಚಿಂತನೆಯ ಟಾಗಲ್ ಅಥವಾ ಚಿಂತನೆಯ ಬಜೆಟ್ ಅನ್ನು ಹೊಂದಿರುವುದಿಲ್ಲ. ಆದ್ದರಿಂದ ಬಜೆಟ್-ಮಾತ್ರ ಸಂಕೇತವು `any` ನಿಂದ ಮಾತ್ರ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ.

`effortMode` ಮೂರು ರೂಪಾಂತರಗಳನ್ನು ಹೊಂದಿದೆ:

- `inherit` ಕ್ಲೈಂಟ್ ಪ್ರಯತ್ನವನ್ನು ಇನ್ನೂ ಮಾಡೆಲ್ ಅಥವಾ ಕಾಂಬೊವನ್ನು ಬದಲಾಯಿಸಲು ಅನುಮತಿಸುತ್ತದೆ.
- ಯಾವುದೇ ಸ್ಪಷ್ಟವಾದ ತಾರ್ಕಿಕ ಸಂಕೇತ ಇಲ್ಲದಿದ್ದಾಗ ಮಾತ್ರ `default` `targetEffort` ಹೊಂದಿಸುತ್ತದೆ.
- `force` ಪ್ರತ್ಯೇಕ ಪ್ರಯತ್ನವನ್ನು `targetEffort` ನೊಂದಿಗೆ ಬದಲಾಯಿಸುತ್ತದೆ.

ಸ್ವತಂತ್ರವಾಗಿ, `budgetAction` `preserve`, `remove`, ಅಥವಾ `set` ಆಗಿರಬಹುದು. `none` ನೊಂದಿಗೆ `force` ಎಲ್ಲಾ ಮಾನ್ಯತೆ ಪಡೆದ ಪ್ರಯತ್ನ ಮತ್ತು ಬಜೆಟ್ ಕ್ಷೇತ್ರಗಳನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ, ನಂತರ `reasoning_effort: "none"` ಹೊಂದಿಸುತ್ತದೆ, ಏಕೆಂದರೆ ಕೆಲವು ಪೂರೈಕೆದಾರರು ಕ್ಷೇತ್ರವು ಇಲ್ಲದಿರುವಾಗ ಆಲೋಚನೆಯನ್ನು ಆನ್ ಮಾಡುತ್ತಾರೆ. ಅಕ್ಷರಶಃ `none` ತಿರಸ್ಕರಿಸುವ ಪೂರೈಕೆದಾರರನ್ನು `open-sse/executors/base/reasoningEffort.ts` ನಲ್ಲಿ ಕಳುಹಿಸುವಾಗ ಸರಿಹೊಂದಿಸಲಾಗುತ್ತದೆ. ಕಮಾಂಡ್ ಕೋಡ್ ಅದನ್ನು `low` ಗೆ ಮ್ಯಾಪ್ ಮಾಡುತ್ತದೆ, ಪ್ರತಿಕ್ರಿಯೆಗಳ ಆಕಾರದ ವಿನಂತಿಗಳನ್ನು ಹೊರತುಪಡಿಸಿ (`input` ಇಲ್ಲದೆ `messages`), ಅಲ್ಲಿ ಅದು `none` ಇರಿಸುತ್ತದೆ. Cloudflare ವರ್ಕರ್ಸ್ AI (`cloudflare-ai`) ನಲ್ಲಿ, `none` ತಿರಸ್ಕರಿಸುವ ಮಾದರಿಗಳು (gpt-oss, qwen3.8, nemotron-3, glm-4.7-ಫ್ಲಾಶ್) `low` ಪಡೆಯುತ್ತವೆ; ಇತರ ಕೆಲಸಗಾರರ AI ಮಾದರಿಗಳು `none` ಇರಿಸುತ್ತವೆ. ಕ್ಷೇತ್ರವನ್ನು ಬಿಡುವುದು ಅಲ್ಲಿ ಒಂದು ಆಯ್ಕೆಯಾಗಿಲ್ಲ, ಏಕೆಂದರೆ ಗೈರುಹಾಜರಿಯ ಪ್ರಯತ್ನವು ಮಾದರಿಯ ಡೀಫಾಲ್ಟ್ ಶ್ರೇಣಿಯನ್ನು ರನ್ ಮಾಡುತ್ತದೆ. `set` ಜೊತೆಗೆ `none` ಅಮಾನ್ಯವಾಗಿದೆ.

ತಿಳಿದಿರುವ-ಹೊಂದಾಣಿಕೆಯಾಗದ ಮಾದರಿಗಳನ್ನು ಗುರಿಪಡಿಸುವ ವಿನಂತಿಗಳನ್ನು ಅಪ್ಸ್ಟ್ರೀಮ್ ಕರೆಯ ಮೊದಲು ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ. ಕಾಂಬೊ ಗುರಿಗಳಿಗಾಗಿ, ಹೊಂದಾಣಿಕೆಯಾಗದ ನಮೂದುಗಳನ್ನು ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ; ಯಾವುದೂ ಉಳಿಯದಿದ್ದರೆ, ವಿನಂತಿಯು ಸ್ಥಿತಿ `400` ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ. ಅಜ್ಞಾತ ಸಾಮರ್ಥ್ಯದ ಡೇಟಾವು ಎಚ್ಚರಿಕೆಯನ್ನು ನೀಡುತ್ತದೆ ಮತ್ತು ನಿಯಮವನ್ನು ಸಕ್ರಿಯವಾಗಿ ಬಿಡುತ್ತದೆ.

## ಭದ್ರತೆ ಮತ್ತು ಸಾರಿಗೆಗಳು

ಮೂಲ ಮತ್ತು ಗುರಿ ಮಾದರಿ, ಅಥವಾ ಮೂಲ ಮತ್ತು ಗುರಿ ಕಾಂಬೊ, ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ API-ಕೀ
ನೀತಿಗೆ ಒಳಪಟ್ಟೇ ಇರುತ್ತವೆ. ತಾರ್ಕಿಕ ನಿಯಮವು ಮಾದರಿ, ಕಾಂಬೊ ಅಥವಾ ಕೋಟಾ ಅನುಮತಿಗಳನ್ನು ಎಂದಿಗೂ ವಿಸ್ತರಿಸುವುದಿಲ್ಲ.

ಎಂಜಿನ್ ಅನ್ನು Chat Completions, Responses, Anthropic Messages, ಮತ್ತು ಆಂತರಿಕ
Codex WebSocket ಪಥದೊಂದಿಗೆ ಸಂಯೋಜಿಸಲಾಗಿದೆ. WebSocket ಪಥವು Codex ಗುರಿ ಮಾದರಿಗಳನ್ನು ಮಾತ್ರ ಸ್ವೀಕರಿಸುತ್ತದೆ; ಕಾಂಬೊ ಗುರಿಗಳನ್ನು ಅಲ್ಲಿ
ಕಾರ್ಯಗತಗೊಳಿಸಲಾಗುವುದಿಲ್ಲ. ನಿಯಮದ ನಿರ್ಧಾರವನ್ನು ರಹಸ್ಯಗಳಿಲ್ಲದೆ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ರೂಟ್ ಟ್ರೇಸ್ನಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ.

## ಶಾಶ್ವತ ಸಂಗ್ರಹಣೆ

`src/lib/db/migrations/126_reasoning_routing_rules.sql` ಮೈಗ್ರೇಷನ್
`reasoning_routing_rules` ಕೋಷ್ಟಕವನ್ನು ರಚಿಸುತ್ತದೆ. ನಿಯಮಗಳು ಸಂಗ್ರಹಿಸಲಾದ API ಕೀಗಳು, ಕಾಂಬೊಗಳು ಮತ್ತು ಪೂರೈಕೆದಾರ ಸಂಪರ್ಕಗಳನ್ನು ಉಲ್ಲೇಖಿಸುತ್ತವೆ.
