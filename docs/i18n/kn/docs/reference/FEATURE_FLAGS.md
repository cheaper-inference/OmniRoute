## ಫೀಚರ್ ಫ್ಲ್ಯಾಗ್ಗಳು ಎಂದರೇನು

ಫೀಚರ್ ಫ್ಲ್ಯಾಗ್ ಎಂದರೆ ಹೆಸರಿಸಲಾದ ಟಾಗಲ್ (boolean ಅಥವಾ enum); ಅದರ ಮೌಲ್ಯವನ್ನು
ರನ್ಟೈಮ್ನಲ್ಲಿ ಬದಲಾಯಿಸಿ ಡೇಟಾಬೇಸ್ನಲ್ಲಿ ಶಾಶ್ವತವಾಗಿ ಉಳಿಸಬಹುದು ಮತ್ತು ಇದಕ್ಕಾಗಿ ಪ್ರಕ್ರಿಯೆಯನ್ನು
ಮರುನಿಯೋಜಿಸುವ ಅಗತ್ಯವಿಲ್ಲ. ಪ್ರತಿಯೊಂದು ಫ್ಲ್ಯಾಗ್ ಅನ್ನು `key`, `label`,
`description`, `category`, `defaultValue`, `type`, ಮತ್ತು `requiresRestart` ಸೂಚನೆಯನ್ನು ಹೊಂದಿರುವ `FeatureFlagDefinition` ಮೂಲಕ ವಿವರಿಸಲಾಗುತ್ತದೆ.

### ಪರಿಹಾರ ಕ್ರಮ

ಫ್ಲ್ಯಾಗ್ನ **ಪರಿಣಾಮಕಾರಿ ಮೌಲ್ಯವನ್ನು**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ಈ ಕೆಳಗಿನ
ಆದ್ಯತಾಕ್ರಮದ ಪ್ರಕಾರ ನಿರ್ಧರಿಸುತ್ತದೆ (ಅತಿ ಹೆಚ್ಚಿನ ಆದ್ಯತೆಯದು ಅನ್ವಯಿಸುತ್ತದೆ):

1. **DB ಅತಿಕ್ರಮಣ** — `feature_flags` ನೇಮ್ಸ್ಪೇಸ್ನ ಅಡಿಯಲ್ಲಿ `key_value`
   ಕೋಷ್ಟಕದಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾದ ಮೌಲ್ಯ (ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅಥವಾ REST API ಮೂಲಕ ಹೊಂದಿಸಲಾಗುತ್ತದೆ).
2. **ಪರಿಸರ ವೇರಿಯಬಲ್** — ಹೊಂದಿಸಲಾಗಿದ್ದು ಖಾಲಿಯಾಗಿಲ್ಲದಿದ್ದರೆ `process.env[<KEY>]`.
3. **ವ್ಯಾಖ್ಯಾನದ ಡೀಫಾಲ್ಟ್** — `featureFlagDefinitions.ts` ನಲ್ಲಿರುವ `defaultValue`.

boolean ಫ್ಲ್ಯಾಗ್ನ ಪರಿಣಾಮಕಾರಿ ಮೌಲ್ಯವು `"true"`, `"1"`, ಅಥವಾ `"yes"` ಆಗಿದ್ದರೆ ಅದನ್ನು
**ಸಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ** ಎಂದು ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ (`isFeatureFlagEnabled()` ನೋಡಿ).

> [!NOTE]
> ಹೆಚ್ಚಿನ ಫ್ಲ್ಯಾಗ್ಗಳು **ಅದೇ ಹೆಸರಿನ** ಹೊಂದಾಣಿಕೆಯ ಪರಿಸರ ವೇರಿಯಬಲ್ ಅನ್ನು ಸಹ ಹೊಂದಿವೆ;
> ಇದನ್ನು [`ENVIRONMENT.md`](./ENVIRONMENT.md) ನಲ್ಲಿ ದಾಖಲಿಸಲಾಗಿದೆ. ಫ್ಲ್ಯಾಗ್ನ DB ಅತಿಕ್ರಮಣವು
> ಆ ಪರಿಸರ ವೇರಿಯಬಲ್ಗಿಂತ ಆದ್ಯತೆ ಪಡೆಯುತ್ತದೆ. `requiresRestart: true` ಹೊಂದಿರುವ ಫ್ಲ್ಯಾಗ್ ಅನ್ನು
> ತಕ್ಷಣವೇ ಶಾಶ್ವತವಾಗಿ ಉಳಿಸಲಾಗುತ್ತದೆ, ಆದರೆ ಪ್ರಕ್ರಿಯೆ ಪ್ರಾರಂಭವಾಗುವಾಗ ಮಾತ್ರ ಪುನಃ ಓದಲಾಗುತ್ತದೆ
> — ಅದನ್ನು ಟಾಗಲ್ ಮಾಡಿದಾಗ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ **"ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ"** ಬ್ಯಾನರ್ ಕಾಣಿಸುತ್ತದೆ.

`UNPRICED_USAGE_BUDGET_POLICY` ಅನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಿದಾಗ (ಪರಿಸರದಿಂದ ಓದುವ ಮೊದಲು DB ಓವರ್ರೈಡ್),
ಅದು `USAGE_LIMIT_IGNORE_UNPRICED` ಗಿಂತ ಆದ್ಯತೆ ಪಡೆಯುತ್ತದೆ. ಯಾವುದೇ ಸ್ಪಷ್ಟ enum ಮೌಲ್ಯವಿಲ್ಲದಿದ್ದರೆ,
ಅಪ್ಸ್ಟ್ರೀಮ್ ಬೂಲಿಯನ್ ಆಪ್ಟ್-ಔಟ್ `count_as_zero` ಅನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ ಡೀಫಾಲ್ಟ್
`fail_closed` ಆಗಿರುತ್ತದೆ. ಅಮಾನ್ಯ enum ಮೌಲ್ಯಗಳು ಮತ್ತು ಓದಲು ಸಾಧ್ಯವಾಗದ ಫೀಚರ್-ಫ್ಲ್ಯಾಗ್ ಸಂಗ್ರಹಣೆ
ಫೇಲ್-ಕ್ಲೋಸ್ ಆಗುತ್ತವೆ. ಯಾವುದೇ ಆಪ್ಟ್-ಔಟ್ ಬೆಲೆಯುಳ್ಳ ಖರ್ಚಿನ ಮಿತಿಯನ್ನು ಅಥವಾ ವಿಫಲವಾದ ಬೆಲೆ
ಹುಡುಕಾಟವನ್ನು ಸಡಿಲಿಸುವುದಿಲ್ಲ. ಜಾರಿ ವ್ಯವಸ್ಥೆ ಮತ್ತು ನಿರ್ವಾಹಕರ ವರದಿ ಒಂದೇ ಪರಿಣಾಮಕಾರಿ ನೀತಿಯನ್ನು
ನಿರ್ಧರಿಸುತ್ತವೆ.

## ಫ್ಲ್ಯಾಗ್ಗಳನ್ನು ಟಾಗಲ್ ಮಾಡುವುದು

### ಡ್ಯಾಶ್ಬೋರ್ಡ್

**Dashboard → Settings → Feature Flags** ಗೆ
(`/dashboard/settings/feature-flags`) ನ್ಯಾವಿಗೇಟ್ ಮಾಡಿ. ಗ್ರಿಡ್
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
ಈ ಕೆಳಗಿನವುಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ:

- ಕೀ ಅಥವಾ ವಿವರಣೆಯ ಮೂಲಕ **ಹುಡುಕಾಟ**, ಮತ್ತು ವರ್ಗದ ಮೂಲಕ **ಫಿಲ್ಟರ್** ಮಾಡುವುದು (ಹಾಗೆಯೇ ಕೃತಕ
  **ಮರುಪ್ರಾರಂಭ ಅಗತ್ಯ** ವೀಕ್ಷಣೆ).
- ಬೂಲಿಯನ್ ಫ್ಲ್ಯಾಗ್ಗಳಿಗಾಗಿ ಒಂದು **ಟಾಗಲ್**, ಮತ್ತು enum ಫ್ಲ್ಯಾಗ್ಗಳಿಗಾಗಿ ಒಂದು **ಡ್ರಾಪ್ಡೌನ್**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- ಪ್ರತಿ ಫ್ಲ್ಯಾಗ್ಗೆ ಒಂದು **ಮೂಲ ಬ್ಯಾಡ್ಜ್** — `DB`, `ENV`, ಅಥವಾ `DEF` — ಪರಿಣಾಮಕಾರಿ ಮೌಲ್ಯವು ಎಲ್ಲಿಂದ ಬಂದಿದೆ ಎಂಬುದನ್ನು ತೋರಿಸುತ್ತದೆ.
- ಓವರ್ರೈಡ್ ತೆಗೆದುಹಾಕಲು (ಕೇವಲ `DB` ಮೂಲದ ಫ್ಲ್ಯಾಗ್ಗಳಿಗೆ ಮಾತ್ರ ತೋರಿಸಲಾಗುತ್ತದೆ) ಒಂದು **ಮರುಹೊಂದಿಸು** ಬಟನ್, ಮತ್ತು ಕೆಳಭಾಗದಲ್ಲಿ ಒಂದು **ಎಲ್ಲಾ ಓವರ್ರೈಡ್ಗಳನ್ನು ಮರುಹೊಂದಿಸು** ಬಟನ್.
- `requiresRestart` ಫ್ಲ್ಯಾಗ್ ಬದಲಾದಾಗ ಒಂದು **ಸರ್ವರ್ ಮರುಪ್ರಾರಂಭಿಸಿ** ಬ್ಯಾನರ್.

### REST API

ಎಲ್ಲಾ ಕಾರ್ಯಾಚರಣೆಗಳು ಒಂದೇ ರೂಟ್ ಮೂಲಕ ನಡೆಯುತ್ತವೆ:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
ಪ್ರತಿ ವಿಧಾನಕ್ಕೂ ದೃಢೀಕೃತ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಸೆಷನ್ ಅಗತ್ಯವಿದೆ (`401` ಇಲ್ಲದಿದ್ದರೆ).

#### `GET /api/settings/feature-flags`

ಪ್ರತಿ ಫ್ಲ್ಯಾಗ್ನ ಪರಿಣಾಮಕಾರಿ ಮೌಲ್ಯ, ಮೂಲ ಮತ್ತು ಸಾರಾಂಶವನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 119 flags
  ],
  "summary": {
    "total": 119,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ಒಂದು ಓವರ್ರೈಡ್ ಅನ್ನು ಹೊಂದಿಸಿ ಅಥವಾ ತೆಗೆದುಹಾಕಿ. ಬಾಡಿ: `{ key: string; value?: string }`.
`value` ಅನ್ನು ಬಿಟ್ಟುಬಿಟ್ಟರೆ ಓವರ್ರೈಡ್ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ (env / default ಅನ್ನು ಮರುಸ್ಥಾಪಿಸಲಾಗುತ್ತದೆ).

```bash
# DB override ಅನ್ನು ಹೊಂದಿಸಿ
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ಓವರ್ರೈಡ್ ತೆಗೆದುಹಾಕಿ ("value" ಇಲ್ಲ)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

ಪ್ರತಿಕ್ರಿಯೆಯು ಹೊಸ `effectiveValue`/`source`, `previousValue`/
`previousSource`, ಮತ್ತು `requiresRestart` ಅನ್ನು ಪ್ರತಿಬಿಂಬಿಸುತ್ತದೆ. ತಿಳಿಯದ ಕೀಗಳು ಮತ್ತು ವ್ಯಾಪ್ತಿಯ
ಹೊರಗಿನ enum ಮೌಲ್ಯಗಳನ್ನು `400` ಜೊತೆಗೆ ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ.

#### `DELETE /api/settings/feature-flags`

ಎಲ್ಲಾ DB ಓವರ್ರೈಡ್ಗಳನ್ನು ಒಂದೇ ಬಾರಿ ತೆರವುಗೊಳಿಸಿ, ಪ್ರತಿ ಫ್ಲ್ಯಾಗ್ ಅನ್ನು ಅದರ env / default
ಮೌಲ್ಯಕ್ಕೆ ಮರುಸ್ಥಾಪಿಸುತ್ತದೆ. `{ cleared: <count>, message: "..." }` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

> [!NOTE]
> `requiresRestart: true` ಹೊಂದಿರುವ ಫ್ಲ್ಯಾಗ್ಗಳು ಪ್ರಕ್ರಿಯೆಯನ್ನು ಮರುಲೋಡ್ ಮಾಡಿದ ನಂತರವೇ ಪರಿಣಾಮ ಬೀರುತ್ತವೆ.
> ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ ಮರುಪ್ರಾರಂಭದ ಪ್ರವಾಹವು `POST /api/restart` ಅನ್ನು ಕರೆದು, ನಂತರ ಸರ್ವರ್ ಮತ್ತೆ ಕಾರ್ಯನಿರ್ವಹಿಸುವವರೆಗೆ
> `GET /api/health/ping` ಅನ್ನು ಪೋಲ್ ಮಾಡುತ್ತದೆ.

## ತುರ್ತು ಬಜೆಟ್ ಫಾಲ್ಬ್ಯಾಕ್

`OMNIROUTE_EMERGENCY_FALLBACK` (`runtime` ವರ್ಗ, ಡೀಫಾಲ್ಟ್ `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
ನಲ್ಲಿರುವ ತುರ್ತು ಉಚಿತ-ಫಾಲ್ಬ್ಯಾಕ್ ಮಾರ್ಗವನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ.
ಇದನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿದಾಗ, ತಮ್ಮ ಬಜೆಟ್ ಖಾಲಿ ಮಾಡಿಕೊಂಡ ವಿನಂತಿಗಳು ಸಂಪೂರ್ಣವಾಗಿ ವಿಫಲಗೊಳ್ಳುವ ಬದಲು ಉಚಿತ ಫಾಲ್ಬ್ಯಾಕ್
ಪೂರೈಕೆದಾರ/ಮಾದರಿಗೆ ರವಾನೆಯಾಗುತ್ತವೆ. ಈ ವರ್ತನೆಯನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ, ಬಜೆಟ್ ಖಾಲಿಯಾದ ವಿನಂತಿಗಳು
ವಿಫಲಗೊಳ್ಳಲು ಅನುಮತಿಸಲು, ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಟಾಗಲ್, DB ಓವರ್ರೈಡ್, ಅಥವಾ
`OMNIROUTE_EMERGENCY_FALLBACK` ಪರಿಸರ ವೇರಿಯೇಬಲ್ ಮೂಲಕ ಅದನ್ನು `false` (ಅಥವಾ `0`) ಗೆ ಹೊಂದಿಸಿ.
