> ಇಲ್ಲಿ ಪಟ್ಟಿ ಮಾಡಲಾದ ಪ್ರತಿಯೊಂದು ಫ್ಲ್ಯಾಗ್ ಅನ್ನು

> ಆ ಫೈಲ್ನಿಂದ ಓದುತ್ತವೆ, ಆದ್ದರಿಂದ ಕೆಳಗಿನ ಕೋಷ್ಟಕವನ್ನು ಅದಕ್ಕೆ 1:1 ಅನುಗುಣವಾಗುವಂತೆ ರಚಿಸಲಾಗಿದೆ.

## ಫೀಚರ್ ಫ್ಲ್ಯಾಗ್ಗಳು ಎಂದರೇನು

ಫೀಚರ್ ಫ್ಲ್ಯಾಗ್ ಎಂದರೆ ಹೆಸರಿಸಲಾದ ಟಾಗಲ್ (boolean ಅಥವಾ enum); ಅದರ ಮೌಲ್ಯವನ್ನು
ರನ್ಟೈಮ್ನಲ್ಲಿ ಬದಲಾಯಿಸಿ ಡೇಟಾಬೇಸ್ನಲ್ಲಿ ಶಾಶ್ವತವಾಗಿ ಉಳಿಸಬಹುದು ಮತ್ತು ಇದಕ್ಕಾಗಿ ಪ್ರಕ್ರಿಯೆಯನ್ನು
ಮರುನಿಯೋಜಿಸುವ ಅಗತ್ಯವಿಲ್ಲ. ಪ್ರತಿಯೊಂದು ಫ್ಲ್ಯಾಗ್ ಅನ್ನು `key`, `label`,
`description`, `category`, `defaultValue`, `type`, ಮತ್ತು `requiresRestart` ಸೂಚನೆಯನ್ನು ಹೊಂದಿರುವ `FeatureFlagDefinition` ಮೂಲಕ ವಿವರಿಸಲಾಗುತ್ತದೆ.

### ಪರಿಹಾರ ಕ್ರಮ

ಫ್ಲ್ಯಾಗ್ನ **ಪರಿಣಾಮಕಾರಿ ಮೌಲ್ಯವನ್ನು**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ಈ ಕೆಳಗಿನ
ಆದ್ಯತಾಕ್ರಮದ ಪ್ರಕಾರ ನಿರ್ಧರಿಸುತ್ತದೆ (ಅತಿ ಹೆಚ್ಚಿನ ಆದ್ಯತೆಯದು ಅನ್ವಯಿಸುತ್ತದೆ):

1. **DB ಅತಿಕ್ರಮಣ** — `feature_flags` ನೇಮ್ಸ್ಪೇಸ್ನ ಅಡಿಯಲ್ಲಿ `key_value`
   ಕೋಷ್ಟಕದಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾದ ಮೌಲ್ಯ (ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅಥವಾ REST API ಮೂಲಕ ಹೊಂದಿಸಲಾಗುತ್ತದೆ).
2. **ಪರಿಸರ ವೇರಿಯಬಲ್** — ಹೊಂದಿಸಲಾಗಿದ್ದು ಖಾಲಿಯಾಗಿಲ್ಲದಿದ್ದರೆ `process.env[<KEY>]`.
3. **ವ್ಯಾಖ್ಯಾನದ ಡೀಫಾಲ್ಟ್** — `featureFlagDefinitions.ts` ನಲ್ಲಿರುವ `defaultValue`.

boolean ಫ್ಲ್ಯಾಗ್ನ ಪರಿಣಾಮಕಾರಿ ಮೌಲ್ಯವು `"true"`, `"1"`, ಅಥವಾ `"yes"` ಆಗಿದ್ದರೆ ಅದನ್ನು
**ಸಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ** ಎಂದು ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ (`isFeatureFlagEnabled()` ನೋಡಿ).

> [!NOTE]
> ಹೆಚ್ಚಿನ ಫ್ಲ್ಯಾಗ್ಗಳು **ಅದೇ ಹೆಸರಿನ** ಹೊಂದಾಣಿಕೆಯ ಪರಿಸರ ವೇರಿಯಬಲ್ ಅನ್ನು ಸಹ ಹೊಂದಿವೆ;
> ಇದನ್ನು [`ENVIRONMENT.md`](./ENVIRONMENT.md) ನಲ್ಲಿ ದಾಖಲಿಸಲಾಗಿದೆ. ಫ್ಲ್ಯಾಗ್ನ DB ಅತಿಕ್ರಮಣವು
> ಆ ಪರಿಸರ ವೇರಿಯಬಲ್ಗಿಂತ ಆದ್ಯತೆ ಪಡೆಯುತ್ತದೆ. `requiresRestart: true` ಹೊಂದಿರುವ ಫ್ಲ್ಯಾಗ್ ಅನ್ನು
> ತಕ್ಷಣವೇ ಶಾಶ್ವತವಾಗಿ ಉಳಿಸಲಾಗುತ್ತದೆ, ಆದರೆ ಪ್ರಕ್ರಿಯೆ ಪ್ರಾರಂಭವಾಗುವಾಗ ಮಾತ್ರ ಪುನಃ ಓದಲಾಗುತ್ತದೆ
> — ಅದನ್ನು ಟಾಗಲ್ ಮಾಡಿದಾಗ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ **"ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ"** ಬ್ಯಾನರ್ ಕಾಣಿಸುತ್ತದೆ.

`UNPRICED_USAGE_BUDGET_POLICY` ಸ್ಪಷ್ಟವಾಗಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಿದಾಗ (ಪರಿಸರದ ಮೊದಲುDB ಅತಿಕ್ರಮಣ), ಇದು `USAGE_LIMIT_IGNORE_UNPRICED` ಗಿಂತ ಆದ್ಯತೆಯನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ. ಯಾವುದೇ ಸ್ಪಷ್ಟವಾದ enum ಮೌಲ್ಯವಿಲ್ಲದೆ, ಅಪ್ಸ್ಟ್ರೀಮ್ ಬೂಲಿಯನ್ ಆಯ್ಕೆಯಿಂದ ಹೊರಗುಳಿಯುವಿಕೆಯು `count_as_zero` ಆಯ್ಕೆಮಾಡುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ ಡೀಫಾಲ್ಟ್ `fail_closed` ಆಗಿದೆ. ಅಮಾನ್ಯವಾದ enum ಮೌಲ್ಯಗಳು ಮತ್ತು ಓದಲಾಗದ ವೈಶಿಷ್ಟ್ಯ-ಫ್ಲ್ಯಾಗ್ ಸಂಗ್ರಹಣೆ ವಿಫಲವಾಗಿದೆ ಮುಚ್ಚಲಾಗಿದೆ. ಆಯ್ಕೆಯಿಂದ ಹೊರಗುಳಿಯುವ ಬೆಲೆಯ ಖರ್ಚು ಅಥವಾ ವಿಫಲವಾದ ಬೆಲೆ ಲುಕಪ್ ಅನ್ನು ಸಡಿಲಿಸುವುದಿಲ್ಲ. ಜಾರಿ ಮತ್ತು ನಿರ್ವಾಹಕರ ವರದಿಯು ಅದೇ ಪರಿಣಾಮಕಾರಿ ನೀತಿಯನ್ನು ಪರಿಹರಿಸುತ್ತದೆ.

## ಧ್ವಜಗಳನ್ನು ಟಾಗಲ್ ಮಾಡಲಾಗುತ್ತಿದೆ

### ಡ್ಯಾಶ್ಬೋರ್ಡ್

ಗೆ ನ್ಯಾವಿಗೇಟ್ ಮಾಡಿ** ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಸೆಟ್ಟಿಂಗ್ಗಳು → ವೈಶಿಷ್ಟ್ಯ ಫ್ಲ್ಯಾಗ್ಗಳು** (`/dashboard/settings/feature-flags`) ಗ್ರಿಡ್ (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) ಬೆಂಬಲಿಸುತ್ತದೆ:

- **ಹುಡುಕು** ಕೀ ಅಥವಾ ವಿವರಣೆಯ ಮೂಲಕ, ಮತ್ತು** ಫಿಲ್ಟರ್** ವರ್ಗದಿಂದ (ಜೊತೆಗೆ ಸಿಂಥೆಟಿಕ್** ಮರುಪ್ರಾರಂಭದ ಅಗತ್ಯವಿದೆ** ವೀಕ್ಷಿಸಿ).
- ಎ** ಟಾಗಲ್** ಬೂಲಿಯನ್ ಧ್ವಜಗಳಿಗೆ ಮತ್ತು ಎ** ಡ್ರಾಪ್ಡೌನ್** enum ಧ್ವಜಗಳಿಗೆ (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- ಎ** ಮೂಲ ಬ್ಯಾಡ್ಜ್** ಪ್ರತಿ ಫ್ಲ್ಯಾಗ್ — `DB`, `ENV`, ಅಥವಾ `DEF` — ಪರಿಣಾಮಕಾರಿ ಮೌಲ್ಯವು ಎಲ್ಲಿಂದ ಬಂದಿದೆ ಎಂಬುದನ್ನು ತೋರಿಸುತ್ತದೆ.
- ಎ** ಮರುಹೊಂದಿಸಿ** ಅತಿಕ್ರಮಣವನ್ನು ಬಿಡಲು ಬಟನ್ ( `DB` -sourced ಫ್ಲ್ಯಾಗ್ಗಳಿಗೆ ಮಾತ್ರ ತೋರಿಸಲಾಗಿದೆ) ಮತ್ತು a** ಎಲ್ಲಾ ಅತಿಕ್ರಮಣಗಳನ್ನು ಮರುಹೊಂದಿಸಿ** ಕೆಳಭಾಗದಲ್ಲಿ ಬಟನ್.
- ಎ** ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ** `requiresRestart` ಧ್ವಜವನ್ನು ಬದಲಾಯಿಸಿದಾಗ ಬ್ಯಾನರ್.

### REST API

ಎಲ್ಲಾ ಕಾರ್ಯಾಚರಣೆಗಳು ಒಂದೇ ಮಾರ್ಗದ ಮೂಲಕ ಹೋಗುತ್ತವೆ: [`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts). ಪ್ರತಿ ವಿಧಾನಕ್ಕೂ ದೃಢೀಕೃತ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಸೆಷನ್ ಅಗತ್ಯವಿದೆ (ಇಲ್ಲದಿದ್ದರೆ`401` ).

ಲಾಗಿನ್ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವುದರೊಂದಿಗೆ (`requireLogin=false`) ಸಂರಕ್ಷಿತ ಧ್ವಜಗಳನ್ನು ಹೊರತುಪಡಿಸಿ ಮಾರ್ಗವು ತೆರೆದಿರುತ್ತದೆ: ಭದ್ರತಾ ವರ್ಗದಲ್ಲಿ ಪ್ರತಿ ಫ್ಲ್ಯಾಗ್ ಜೊತೆಗೆ `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`, `OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS`, `MITM_DISABLE_TLS_VERIFY`, `OMNIROUTE_MCP_ENFORCE_SCOPES` ಮತ್ತು `SKILLS_SANDBOX_NETWORK_ENABLED` (`isProtectedFeatureFlag()` ನಲ್ಲಿ `protectedFeatureFlags.ts`). ಅವುಗಳಲ್ಲಿ ಒಂದು `PUT`, ಮತ್ತು ಅವುಗಳಲ್ಲಿ ಒಂದು DB ಅತಿಕ್ರಮಣವನ್ನು ಹೊಂದಿರುವಾಗ `DELETE` ಇನ್ನೂ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಸೆಷನ್, `manage` -scope API ಕೀ, ಬರೆಯುವ ಸ್ಕೋಪ್ ಅಥವಾ ಹೆಚ್ಚಿನದರೊಂದಿಗೆ `oma_` ಪ್ರವೇಶ ಟೋಕನ್ ಅಥವಾ ಲೂಪ್ಬ್ಯಾಕ್ನಿಂದ ಕಳುಹಿಸಲಾದ CLI ಟೋಕನ್ ಅಥವಾ ಆಂತರಿಕ-ಸೇವಾ ಟೋಕನ್ ಅಗತ್ಯವಿದೆ. ಆ ಸೆಟ್ ಲಾಗಿನ್ ಆನ್ಗಿಂತ ವಿಸ್ತಾರವಾಗಿದೆ, ಅಲ್ಲಿ ಮಾರ್ಗವು ಸೆಷನ್ ಅಥವಾ `manage` -scope ಕೀಯನ್ನು ಮಾತ್ರ ಸ್ವೀಕರಿಸುತ್ತದೆ.

#### `PUT /api/settings/feature-flags`

ಒಂದೇ ಅತಿಕ್ರಮಣವನ್ನು ಹೊಂದಿಸಿ ಅಥವಾ ತೆಗೆದುಹಾಕಿ. ದೇಹ: `{ key: string; value?: string }`. `value` ಬಿಟ್ಟುಬಿಡುವುದು ಅತಿಕ್ರಮಣವನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ (env / ಡೀಫಾಲ್ಟ್ ಅನ್ನು ಮರುಸ್ಥಾಪಿಸುವುದು).

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

ಪ್ರತಿಕ್ರಿಯೆಯು ಹೊಸ `effectiveValue`/`source`, `previousValue`/ `previousSource` ಮತ್ತು `requiresRestart` ಅನ್ನು ಪ್ರತಿಧ್ವನಿಸುತ್ತದೆ. ಅಜ್ಞಾತ ಕೀಗಳು ಮತ್ತು ವ್ಯಾಪ್ತಿಯ ಹೊರಗಿನ enum ಮೌಲ್ಯಗಳನ್ನು `400` ನೊಂದಿಗೆ ತಿರಸ್ಕರಿಸಲಾಗಿದೆ.

#### `DELETE /api/settings/feature-flags`

ತೆರವುಗೊಳಿಸುತ್ತದೆ** ಎಲ್ಲಾ** DB ಒಮ್ಮೆಗೇ ಅತಿಕ್ರಮಿಸುತ್ತದೆ, ಪ್ರತಿ ಫ್ಲ್ಯಾಗ್ ಅನ್ನು ಅದರ env / ಡೀಫಾಲ್ಟ್ ಮೌಲ್ಯಕ್ಕೆ ಮರುಸ್ಥಾಪಿಸುತ್ತದೆ. `{ cleared: <count>, message: "..." }` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

> [!NOTE]
> `requiresRestart: true` ನೊಂದಿಗೆ ಧ್ವಜಗಳು ಪ್ರಕ್ರಿಯೆಯ ಮರುಲೋಡ್ ನಂತರ ಮಾತ್ರ ಪರಿಣಾಮ ಬೀರುತ್ತವೆ. ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ ಮರುಪ್ರಾರಂಭದ ಹರಿವು `POST /api/restart` ಕರೆಯುತ್ತದೆ ಮತ್ತು ಸರ್ವರ್ ಬ್ಯಾಕ್ ಅಪ್ ಆಗುವವರೆಗೆ `GET /api/health/ping` ಪೋಲ್ ಮಾಡುತ್ತದೆ.

## ತುರ್ತು ಬಜೆಟ್ ಫಾಲ್ಬ್ಯಾಕ್

`OMNIROUTE_EMERGENCY_FALLBACK` (`runtime` ವರ್ಗ, ಡೀಫಾಲ್ಟ್ `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
ನಲ್ಲಿರುವ ತುರ್ತು ಉಚಿತ-ಫಾಲ್ಬ್ಯಾಕ್ ಮಾರ್ಗವನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ.
ಇದನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿದಾಗ, ತಮ್ಮ ಬಜೆಟ್ ಖಾಲಿ ಮಾಡಿಕೊಂಡ ವಿನಂತಿಗಳು ಸಂಪೂರ್ಣವಾಗಿ ವಿಫಲಗೊಳ್ಳುವ ಬದಲು ಉಚಿತ ಫಾಲ್ಬ್ಯಾಕ್
ಪೂರೈಕೆದಾರ/ಮಾದರಿಗೆ ರವಾನೆಯಾಗುತ್ತವೆ. ಈ ವರ್ತನೆಯನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ, ಬಜೆಟ್ ಖಾಲಿಯಾದ ವಿನಂತಿಗಳು
ವಿಫಲಗೊಳ್ಳಲು ಅನುಮತಿಸಲು, ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಟಾಗಲ್, DB ಓವರ್ರೈಡ್, ಅಥವಾ
`OMNIROUTE_EMERGENCY_FALLBACK` ಪರಿಸರ ವೇರಿಯೇಬಲ್ ಮೂಲಕ ಅದನ್ನು `false` (ಅಥವಾ `0`) ಗೆ ಹೊಂದಿಸಿ.
(PRs #3741 / #3752 ನಲ್ಲಿ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಟಾಗಲ್ ಆಗಿ ಪ್ರದರ್ಶಿಸಲಾಗಿದೆ.)

ಈ ಫಾಲ್ಬ್ಯಾಕ್ ಮೂಲಕ ಒದಗಿಸಲಾದ ಪ್ರತಿಕ್ರಿಯೆಯು
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` ಅನ್ನು ಹೊಂದಿರುತ್ತದೆ, ಆದ್ದರಿಂದ ಕ್ಲೈಂಟ್ ತನ್ನ
ವಿನಂತಿಯೊಂದಿಗೆ `X-OmniRoute-Provider` ಅನ್ನು ಹೋಲಿಸಿ ವ್ಯತ್ಯಾಸ ಕಂಡುಹಿಡಿಯದೆಯೇ ಅದು ಮರುರವಾನೆಯಾಗಿದೆ ಎಂದು ತಿಳಿಯಬಹುದು.
ಬೇರೆ ಎಲ್ಲಾ ಪ್ರತಿಕ್ರಿಯೆಗಳಲ್ಲಿ ಈ ಹೆಡರ್ ಇರುವುದಿಲ್ಲ.
