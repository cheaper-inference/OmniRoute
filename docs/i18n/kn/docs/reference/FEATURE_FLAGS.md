## ಫೀಚರ್ ಫ್ಲ್ಯಾಗ್ಗಳು ಎಂದರೇನು

ಫೀಚರ್ ಫ್ಲ್ಯಾಗ್ ಎಂದರೆ ಹೆಸರಿಸಲಾದ ಟಾಗಲ್ (boolean ಅಥವಾ enum); ಅದರ ಮೌಲ್ಯವನ್ನು
ರನ್ಟೈಮ್ನಲ್ಲಿ ಬದಲಾಯಿಸಿ ಡೇಟಾಬೇಸ್ನಲ್ಲಿ ಶಾಶ್ವತವಾಗಿ ಉಳಿಸಬಹುದು ಮತ್ತು ಇದಕ್ಕಾಗಿ ಪ್ರಕ್ರಿಯೆಯನ್ನು
ಮರುನಿಯೋಜಿಸುವ ಅಗತ್ಯವಿಲ್ಲ. ಪ್ರತಿಯೊಂದು ಫ್ಲ್ಯಾಗ್ ಅನ್ನು `key`, `label`,
`description`, `category`, `defaultValue`, `type`, ಮತ್ತು `requiresRestart` ಸೂಚನೆಯನ್ನು ಹೊಂದಿರುವ `FeatureFlagDefinition` ಮೂಲಕ ವಿವರಿಸಲಾಗುತ್ತದೆ.

### ಪರಿಹಾರ ಕ್ರಮ

ಫ್ಲ್ಯಾಗ್ನ **ಪರಿಣಾಮಕಾರಿ ಮೌಲ್ಯವನ್ನು**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ಈ ಕೆಳಗಿನ
ಆದ್ಯತಾಕ್ರಮದ ಪ್ರಕಾರ ನಿರ್ಧರಿಸುತ್ತದೆ (ಅತಿ ಹೆಚ್ಚಿನ ಆದ್ಯತೆಯದು ಅನ್ವಯಿಸುತ್ತದೆ):

1. **DB ಅತಿಕ್ರಮಣ** — `feature_flags` ನೇಮ್ಸ್ಪೇಸ್ನ ಅಡಿಯಲ್ಲಿ `key_value`
   ಕೋಷ್ಟಕದಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾದ ಮೌಲ್ಯ (ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅಥವಾ REST API ಮೂಲಕ ಹೊಂದಿಸಲಾಗುತ್ತದೆ).
2. **ಪರಿಸರ ವೇರಿಯಬಲ್** — ಹೊಂದಿಸಲಾಗಿದ್ದು ಖಾಲಿಯಾಗಿಲ್ಲದಿದ್ದರೆ `process.env[<KEY>]`.
3. **ವ್ಯಾಖ್ಯಾನದ ಡೀಫಾಲ್ಟ್** — `featureFlagDefinitions.ts` ನಲ್ಲಿರುವ `defaultValue`.

boolean ಫ್ಲ್ಯಾಗ್ನ ಪರಿಣಾಮಕಾರಿ ಮೌಲ್ಯವು `"true"`, `"1"`, ಅಥವಾ `"yes"` ಆಗಿದ್ದರೆ ಅದನ್ನು
**ಸಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ** ಎಂದು ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ (`isFeatureFlagEnabled()` ನೋಡಿ).

> [!NOTE]
> ಹೆಚ್ಚಿನ ಫ್ಲ್ಯಾಗ್ಗಳು **ಅದೇ ಹೆಸರಿನ** ಹೊಂದಾಣಿಕೆಯ ಪರಿಸರ ವೇರಿಯಬಲ್ ಅನ್ನು ಸಹ ಹೊಂದಿವೆ;
> ಇದನ್ನು [`ENVIRONMENT.md`](./ENVIRONMENT.md) ನಲ್ಲಿ ದಾಖಲಿಸಲಾಗಿದೆ. ಫ್ಲ್ಯಾಗ್ನ DB ಅತಿಕ್ರಮಣವು
> ಆ ಪರಿಸರ ವೇರಿಯಬಲ್ಗಿಂತ ಆದ್ಯತೆ ಪಡೆಯುತ್ತದೆ. `requiresRestart: true` ಹೊಂದಿರುವ ಫ್ಲ್ಯಾಗ್ ಅನ್ನು
> ತಕ್ಷಣವೇ ಶಾಶ್ವತವಾಗಿ ಉಳಿಸಲಾಗುತ್ತದೆ, ಆದರೆ ಪ್ರಕ್ರಿಯೆ ಪ್ರಾರಂಭವಾಗುವಾಗ ಮಾತ್ರ ಪುನಃ ಓದಲಾಗುತ್ತದೆ
> — ಅದನ್ನು ಟಾಗಲ್ ಮಾಡಿದಾಗ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ **"ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ"** ಬ್ಯಾನರ್ ಕಾಣಿಸುತ್ತದೆ.

## ಫ್ಲ್ಯಾಗ್ಗಳನ್ನು ಟಾಗಲ್ ಮಾಡುವುದು

### ಡ್ಯಾಶ್ಬೋರ್ಡ್

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಸೆಟ್ಟಿಂಗ್ಗಳು → ವೈಶಿಷ್ಟ್ಯ ಫ್ಲ್ಯಾಗ್ಗಳು** ಇಲ್ಲಿಗೆ ನ್ಯಾವಿಗೇಟ್ ಮಾಡಿ
(`/dashboard/settings/feature-flags`). ಗ್ರಿಡ್
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
ಈ ಕೆಳಗಿನವುಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ:

- ಕೀ ಅಥವಾ ವಿವರಣೆಯ ಮೂಲಕ **ಹುಡುಕಾಟ**, ಮತ್ತು ವರ್ಗದ ಮೂಲಕ **ಫಿಲ್ಟರ್** ಮಾಡುವುದು (ಜೊತೆಗೆ ಕೃತಕ
  **ಮರುಪ್ರಾರಂಭದ ಅಗತ್ಯವಿದೆ** ವೀಕ್ಷಣೆ).
- ಬೂಲಿಯನ್ ಫ್ಲ್ಯಾಗ್ಗಳಿಗಾಗಿ **ಟಾಗಲ್** ಮತ್ತು enum ಫ್ಲ್ಯಾಗ್ಗಳಿಗಾಗಿ **ಡ್ರಾಪ್ಡೌನ್**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- ಪ್ರತಿ ಫ್ಲ್ಯಾಗ್ಗೆ ಒಂದು **ಮೂಲ ಬ್ಯಾಡ್ಜ್** — `DB`, `ENV`, ಅಥವಾ `DEF` — ಪರಿಣಾಮಕಾರಿ
  ಮೌಲ್ಯವು ಎಲ್ಲಿಂದ ಬಂದಿದೆ ಎಂಬುದನ್ನು ತೋರಿಸುತ್ತದೆ.
- ಓವರ್ರೈಡ್ ಅನ್ನು ತೆಗೆದುಹಾಕಲು **ಮರುಹೊಂದಿಸಿ** ಬಟನ್ (`DB` ಮೂಲದ ಫ್ಲ್ಯಾಗ್ಗಳಿಗೆ ಮಾತ್ರ ತೋರಿಸಲಾಗುತ್ತದೆ),
  ಮತ್ತು ಕೆಳಭಾಗದಲ್ಲಿ **ಎಲ್ಲಾ ಓವರ್ರೈಡ್ಗಳನ್ನು ಮರುಹೊಂದಿಸಿ** ಬಟನ್.
- `requiresRestart` ಫ್ಲ್ಯಾಗ್ ಬದಲಾದಾಗ **ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ** ಬ್ಯಾನರ್.

### REST API

ಎಲ್ಲಾ ಕಾರ್ಯಾಚರಣೆಗಳು ಒಂದೇ ಮಾರ್ಗದ ಮೂಲಕ ನಡೆಯುತ್ತವೆ:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
ಪ್ರತಿಯೊಂದು ವಿಧಾನಕ್ಕೂ ದೃಢೀಕರಿಸಿದ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಸೆಷನ್ ಅಗತ್ಯವಿದೆ (ಇಲ್ಲದಿದ್ದರೆ `401`).

#### `GET /api/settings/feature-flags`

ಪ್ರತಿಯೊಂದು ಫ್ಲ್ಯಾಗ್ ಅನ್ನು ಅದರ ಪರಿಣಾಮಕಾರಿ ಮೌಲ್ಯ, ಮೂಲ ಮತ್ತು ಸಾರಾಂಶದೊಂದಿಗೆ ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... ಎಲ್ಲಾ 111 ಫ್ಲ್ಯಾಗ್ಗಳು
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ಒಂದು ಓವರ್ರೈಡ್ ಅನ್ನು ಹೊಂದಿಸಿ ಅಥವಾ ತೆಗೆದುಹಾಕಿ. ವಿನಂತಿಯ ದೇಹ: `{ key: string; value?: string }`.
`value` ಅನ್ನು ಬಿಟ್ಟರೆ ಓವರ್ರೈಡ್ ತೆಗೆದುಹಾಕಲ್ಪಡುತ್ತದೆ (env / ಡೀಫಾಲ್ಟ್ ಅನ್ನು ಮರುಸ್ಥಾಪಿಸುತ್ತದೆ).

```bash
# DB ಓವರ್ರೈಡ್ ಅನ್ನು ಹೊಂದಿಸಿ
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ಓವರ್ರೈಡ್ ಅನ್ನು ತೆಗೆದುಹಾಕಿ ("value" ಇಲ್ಲದೆ)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

ಪ್ರತಿಕ್ರಿಯೆಯು ಹೊಸ `effectiveValue`/`source`, `previousValue`/
`previousSource`, ಮತ್ತು `requiresRestart` ಅನ್ನು ಪ್ರತಿಧ್ವನಿಸುತ್ತದೆ. ಅಜ್ಞಾತ ಕೀಗಳು ಮತ್ತು ವ್ಯಾಪ್ತಿಯಿಂದ ಹೊರಗಿನ enum
ಮೌಲ್ಯಗಳನ್ನು `400` ಜೊತೆಗೆ ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ.

#### `DELETE /api/settings/feature-flags`

ಎಲ್ಲಾ DB ಓವರ್ರೈಡ್ಗಳನ್ನು ಒಂದೇ ಬಾರಿಗೆ ತೆರವುಗೊಳಿಸಿ, ಪ್ರತಿಯೊಂದು ಫ್ಲ್ಯಾಗ್ ಅನ್ನು ಅದರ env / ಡೀಫಾಲ್ಟ್
ಮೌಲ್ಯಕ್ಕೆ ಮರುಸ್ಥಾಪಿಸುತ್ತದೆ. `{ cleared: <count>, message: "..." }` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

> [!NOTE]
> `requiresRestart: true` ಹೊಂದಿರುವ ಫ್ಲ್ಯಾಗ್ಗಳು ಪ್ರಕ್ರಿಯೆಯನ್ನು ಮರುಲೋಡ್ ಮಾಡಿದ ನಂತರವೇ ಪರಿಣಾಮ ಬೀರುತ್ತವೆ.
> ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ ಮರುಪ್ರಾರಂಭ ಹರಿವು `POST /api/restart` ಅನ್ನು ಕರೆದು, ನಂತರ ಸರ್ವರ್ ಮತ್ತೆ ಕಾರ್ಯನಿರ್ವಹಿಸುವವರೆಗೆ
> `GET /api/health/ping` ಅನ್ನು ಪೋಲ್ ಮಾಡುತ್ತದೆ.

## ತುರ್ತು ಬಜೆಟ್ ಫಾಲ್ಬ್ಯಾಕ್

`OMNIROUTE_EMERGENCY_FALLBACK` (`runtime` ವರ್ಗ, ಡೀಫಾಲ್ಟ್ `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
ನಲ್ಲಿರುವ ತುರ್ತು ಉಚಿತ-ಫಾಲ್ಬ್ಯಾಕ್ ಮಾರ್ಗವನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ.
ಇದನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿದಾಗ, ತಮ್ಮ ಬಜೆಟ್ ಖಾಲಿ ಮಾಡಿಕೊಂಡ ವಿನಂತಿಗಳು ಸಂಪೂರ್ಣವಾಗಿ ವಿಫಲಗೊಳ್ಳುವ ಬದಲು ಉಚಿತ ಫಾಲ್ಬ್ಯಾಕ್
ಪೂರೈಕೆದಾರ/ಮಾದರಿಗೆ ರವಾನೆಯಾಗುತ್ತವೆ. ಈ ವರ್ತನೆಯನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ, ಬಜೆಟ್ ಖಾಲಿಯಾದ ವಿನಂತಿಗಳು
ವಿಫಲಗೊಳ್ಳಲು ಅನುಮತಿಸಲು, ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಟಾಗಲ್, DB ಓವರ್ರೈಡ್, ಅಥವಾ
`OMNIROUTE_EMERGENCY_FALLBACK` ಪರಿಸರ ವೇರಿಯೇಬಲ್ ಮೂಲಕ ಅದನ್ನು `false` (ಅಥವಾ `0`) ಗೆ ಹೊಂದಿಸಿ.
(PRs #3741 / #3752 ನಲ್ಲಿ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಟಾಗಲ್ ಆಗಿ ಪ್ರದರ್ಶಿಸಲಾಗಿದೆ.)

ಈ ಫಾಲ್ಬ್ಯಾಕ್ ಮೂಲಕ ಒದಗಿಸಲಾದ ಪ್ರತಿಕ್ರಿಯೆಯು
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` ಅನ್ನು ಹೊಂದಿರುತ್ತದೆ, ಆದ್ದರಿಂದ ಕ್ಲೈಂಟ್ ತನ್ನ
ವಿನಂತಿಯೊಂದಿಗೆ `X-OmniRoute-Provider` ಅನ್ನು ಹೋಲಿಸಿ ವ್ಯತ್ಯಾಸ ಕಂಡುಹಿಡಿಯದೆಯೇ ಅದು ಮರುರವಾನೆಯಾಗಿದೆ ಎಂದು ತಿಳಿಯಬಹುದು.
ಬೇರೆ ಎಲ್ಲಾ ಪ್ರತಿಕ್ರಿಯೆಗಳಲ್ಲಿ ಈ ಹೆಡರ್ ಇರುವುದಿಲ್ಲ.
