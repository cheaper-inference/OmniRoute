> **ಸತ್ಯದ ಮೂಲ:** `src/lib/guardrails/`
> **ಕೊನೆಯ ನವೀಕರಣ:** 2026-10-17 — v3.8.52 ([ವ್ಯಾಪ್ತಿ ಮತ್ತು ಮಿತಿಗಳು](#coverage-and-limits) ಸೇರಿಸಲಾಗಿದೆ:
> hooks ಯಾವ routes ಮತ್ತು response pathಗಳನ್ನು ತಲುಪುತ್ತವೆ, ವಿಲೀನಗೊಂಡ disable headers (#16412), ಕಡ್ಡಾಯ
> ಗಡಿಯಾಗಿ injection block mode (#16413), ಮತ್ತು post-call ಮೊದಲು response ಅನ್ನು ಏನು ನೋಡುತ್ತದೆ)

ಗಾರ್ಡ್ರೇಲ್ಗಳು OmniRoute ಮತ್ತು upstream ಪೂರೈಕೆದಾರರ ನಡುವಿನ ಗಡಿಯಲ್ಲಿ ಸುರಕ್ಷತೆ, ನೀತಿ ಮತ್ತು ವಿಷಯ
ರೂಪಾಂತರಣಗಳನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತವೆ. ಪ್ರತಿ ಗಾರ್ಡ್ರೇಲ್ request payloadಗಳನ್ನು (`preCall`) ಮತ್ತು
upstream responseಗಳನ್ನು (`postCall`) ಪರಿಶೀಲಿಸಬಹುದು (ಮತ್ತು ಐಚ್ಛಿಕವಾಗಿ ತಿರಸ್ಕರಿಸಬಹುದು,
ರೂಪಾಂತರಿಸಬಹುದು ಅಥವಾ ಟಿಪ್ಪಣಿ ಸೇರಿಸಬಹುದು).

ಈ ವ್ಯವಸ್ಥೆ **fail-open**: ಗಾರ್ಡ್ರೇಲ್ ಕಾರ್ಯನಿರ್ವಹಣೆಯ ವೇಳೆ error ಎಸೆದರೆ, registry ದೋಷವನ್ನು
ದಾಖಲಿಸುತ್ತದೆ ಮತ್ತು request ಅನ್ನು ವಿಫಲಗೊಳಿಸುವ ಬದಲು ಮುಂದಿನ ಗಾರ್ಡ್ರೇಲ್ನೊಂದಿಗೆ ಮುಂದುವರಿಯುತ್ತದೆ.
ನಿರ್ಬಂಧವು ಸ್ಪಷ್ಟವಾದ ನಿರ್ಧಾರ (`block: true`), ಎಂದಿಗೂ ಆಕಸ್ಮಿಕವಲ್ಲ. ಒಂದೇ ಅಪವಾದವೆಂದರೆ ಸ್ಥಗಿತಗೊಂಡ
request: ಕರೆಗಾರರ `signal` ಅನ್ನು ಸ್ಥಗಿತಗೊಳಿಸಿದಾಗ, error ಎಸೆಯುವ ಗಾರ್ಡ್ರೇಲ್ skip ಆಗುವ ಬದಲು
hook run ಅನ್ನು reject ಮಾಡುತ್ತದೆ.

ಈ hooks ಪ್ರತಿ route ಅಥವಾ ಪ್ರತಿ response ಮೇಲೂ **ರನ್ ಆಗುವುದಿಲ್ಲ**. ಗಾರ್ಡ್ರೇಲ್ ಅನ್ನು ಭದ್ರತಾ
ನಿಯಂತ್ರಣವಾಗಿ ಅವಲಂಬಿಸುವ ಮೊದಲು [ವ್ಯಾಪ್ತಿ ಮತ್ತು ಮಿತಿಗಳು](#coverage-and-limits) ಓದಿ.

## ಅಂತರ್ನಿರ್ಮಿತ ಗಾರ್ಡ್ರೈಲ್ಗಳು

ರಿಜಿಸ್ಟ್ರಿಯು ಆಮದು ಮೇಲೆ ಆದ್ಯತೆಯ ಕ್ರಮದಲ್ಲಿ ಆರು ಗಾರ್ಡ್ರೈಲ್ಗಳನ್ನು ಸ್ವಯಂ-ಲೋಡ್ ಮಾಡುತ್ತದೆ ( `registry.ts` → `registerDefaultGuardrails()` ನೋಡಿ):

| ಆದ್ಯತೆ | ಹೆಸರು               | ಹಂತ(ಗಳು)       | ಫೈಲ್                  |
| ------ | ------------------- | -------------- | --------------------- |
| `5`    | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`    | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`    | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`   | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`   | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`   | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

ಕಡಿಮೆ ಆದ್ಯತೆಯ ಸಂಖ್ಯೆಗಳು ರನ್ ಆಗುತ್ತವೆ** ಮೊದಲು** .

### ವಿಷನ್ ಬ್ರಿಡ್ಜ್ (`visionBridge.ts`) — ಮಾಡಾಲಿಟಿ ಸೇತುವೆ PR-1

GLM 5.3 ಮೂಲ ಮಾದರಿ ಮತ್ತು `glm-5.3-{low,high,max}` ಸ್ಪಷ್ಟವಾದ `supportsVision:false` registry/spec ಮೆಟಾಡೇಟಾವನ್ನು ಹೊಂದಿವೆ. GLM 5.3 ಫ್ಲ್ಯಾಶ್ ರೂಪಾಂತರಗಳು ಸ್ಥಳೀಯ ದೃಷ್ಟಿ ಮಾದರಿಗಳಾಗಿ ಉಳಿದಿವೆ. Claude ಕೋಡ್ನ `/v1/messages` ಮಾರ್ಗವು ಹಂಚಿದ `handleChat` ಪೂರ್ವ-ಕರೆ ಗಾರ್ಡ್ರೈಲ್ ಸರಪಳಿಯನ್ನು ಪ್ರವೇಶಿಸುತ್ತದೆ** ಮೊದಲು** ಕ್ಲೌಡ್-ಟು-ಓಪನ್ಎಐ ಅನುವಾದ; ನೆಸ್ಟೆಡ್ `Read` ಟೂಲ್-ಫಲಿತಾಂಶ ಚಿತ್ರಗಳನ್ನು ಅನುವಾದವು OpenAI `image_url` ವಿಷಯಕ್ಕೆ (#17069) ಎತ್ತುವ ಮೊದಲು ಅವುಗಳನ್ನು ವಿವರಿಸಬೇಕು ಅಥವಾ ನಿರ್ವಹಿಸಬೇಕು.

ಗುರಿಯನ್ನು ಹೊಂದಿರುವ ಚಿತ್ರ-ಬೇರಿಂಗ್ ವಿನಂತಿಗಳನ್ನು ಪ್ರತಿಬಂಧಿಸುತ್ತದೆ** ದೃಷ್ಟಿಹೀನ ಮಾದರಿಗಳು** ಮತ್ತು ಸಂಪೂರ್ಣ ವಿನಂತಿಯನ್ನು ದೃಷ್ಟಿ-ಸಾಮರ್ಥ್ಯದ ಮಾದರಿಗೆ ಮರುಮಾರ್ಗಗೊಳಿಸುತ್ತದೆ ಅಥವಾ ಅಪ್ಸ್ಟ್ರೀಮ್ ಕರೆಗೆ ಮೊದಲು ಕಾನ್ಫಿಗರ್ ಮಾಡಬಹುದಾದ ದೃಷ್ಟಿ ಮಾದರಿಯಿಂದ ರಚಿಸಲಾದ ಪಠ್ಯ ವಿವರಣೆಗಳೊಂದಿಗೆ ಚಿತ್ರದ ಭಾಗಗಳನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ. ಇದು ಪಠ್ಯ-ಮಾತ್ರ ಪೂರೈಕೆದಾರರಿಗೆ ಮಲ್ಟಿಮೋಡಲ್ ಪೇಲೋಡ್ಗಳನ್ನು ಪಾರದರ್ಶಕವಾಗಿ ನಿರ್ವಹಿಸಲು ಅನುಮತಿಸುತ್ತದೆ.

ಹರಿವು:

1. ಟಾರ್ಗೆಟ್ ಮಾಡೆಲ್ ಈಗಾಗಲೇ ದೃಷ್ಟಿಯನ್ನು ಬೆಂಬಲಿಸಿದರೆ ಬಿಟ್ಟುಬಿಡಿ (ಇದು ಬಲವಂತದ-ಸೇತುವೆ ಪಟ್ಟಿ `isVisionBridgeForcedModel` ನಲ್ಲಿ ಕಾಣಿಸದ ಹೊರತು).
2. ಗೆ ಪ್ರತಿನಿಧಿಸುವ `extractImageParts(messages)` (`visionBridgeHelpers.ts`) ಮೂಲಕ ಚಿತ್ರದ ಭಾಗಗಳನ್ನು ಹೊರತೆಗೆಯಿರಿ** ಏಕೀಕೃತ ಮಾಧ್ಯಮ ಶೋಧಕ** `detectMediaParts()` `open-sse/utils/mediaParts.ts` ನಲ್ಲಿ — ಕಾಂಬೊ ಹೊಂದಾಣಿಕೆ ಫಿಲ್ಟರ್ನೊಂದಿಗೆ ಹಂಚಿಕೊಳ್ಳಲಾದ ಸತ್ಯದ ಏಕೈಕ ಮೂಲವಾಗಿದೆ. ಹೊರತೆಗೆಯುವಿಕೆಯನ್ನು `replaceImageParts` ಸ್ಪ್ಲೈಸ್ ಬ್ಯಾಕ್ ಮಾಡಬಹುದಾದ ಆಕಾರಗಳಿಗೆ ಅನುಮತಿಸಲಾಗಿದೆ (ಉದ್ಧರಣ ↔ ಒಪ್ಪಂದವನ್ನು ಬದಲಿಸುತ್ತದೆ): OpenAI `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"`, ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆಗಳು API `input_image`. Claude ಕೋಡ್ `tool_result.content` ಒಳಗೆ ಹೊಂದಿಸಲಾದ ಹೊಂದಾಣಿಕೆಯ ಚಿತ್ರಗಳು ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆಗಳ ಉಪಕರಣದ ಔಟ್ಪುಟ್ಗಳನ್ನು ಸಹ ಹೊರತೆಗೆಯಲಾಗುತ್ತದೆ ಮತ್ತು ಅವುಗಳ ಮೂಲ ಮಾರ್ಗಗಳಲ್ಲಿ ಬದಲಾಯಿಸಲಾಗುತ್ತದೆ; ಸೂಚಕ-ಮಾತ್ರ ಆಕಾರಗಳು ಕಾಂಬೊ-ಫಿಲ್ಟರ್ ವಸ್ತುಗಳಾಗಿವೆ ಮತ್ತು ಅವುಗಳನ್ನು ಹೊರತೆಗೆಯಲಾಗುವುದಿಲ್ಲ. ಯಾವುದೂ ಸಿಗದಿದ್ದರೆ ಬಿಟ್ಟುಬಿಡಿ.
3. `resolveVisionBridgeRuntimeSettings()` (`src/shared/constants/modalityBridgeDefaults.ts`) ಮೂಲಕ ರನ್ಟೈಮ್ ಸಂರಚನೆಯನ್ನು ಪರಿಹರಿಸಿ: ಹೊಸ `modalityBridge*` ಸೆಟ್ಟಿಂಗ್ಗಳ ಕೀಗಳು ಗೆಲುವು; ಲೆಗಸಿ `visionBridge*` ಕೀಗಳು ಉಳಿಯುತ್ತವೆ a** ಒಂದು-ಚಕ್ರದ ಹಿನ್ನಡೆ** (ರೋಲ್ಬ್ಯಾಕ್ ವಿಂಡೋ). ಸೇತುವೆಯನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿದಾಗ ಯಾವುದೇ ಮಾಧ್ಯಮದ ಪ್ರಯಾಣದ ಮೊದಲು ಸ್ಕಿಪ್ ಮಾಡಿ.
4. ಮೋಡ್ ಸೆಲೆಕ್ಟರ್ (`modalityBridgeVisionMode`, ಕೆಳಗಿನ ಕೋಷ್ಟಕವನ್ನು ನೋಡಿ) ಮರುಮಾರ್ಗ vs ವಿವರಿಸುವುದನ್ನು ನಿರ್ಧರಿಸುತ್ತದೆ. ಮರುಮಾರ್ಗವು `modifiedPayload` ಕೇವಲ `model` ವಿನಿಮಯದೊಂದಿಗೆ ಹಿಂದಿರುಗಿಸುತ್ತದೆ, ಜೊತೆಗೆ ಮೆಟಾ `{ rerouted, fromModel, toModel, imagesKept }`.
5. ಮಾರ್ಗವನ್ನು ವಿವರಿಸಿ: `maxImages` ನಲ್ಲಿ ಚಿತ್ರಗಳನ್ನು ಕ್ಯಾಪ್ ಮಾಡಿ, ಟಾಸ್ಕ್-ಅವೇರ್ ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು ರಚಿಸಿ, ಕ್ಯಾಶ್ ಅನ್ನು ವಿವರಿಸಿ, ದೃಷ್ಟಿ ಮಾದರಿಯನ್ನು ಕರೆ ಮಾಡಿ** ಸಮಾನಾಂತರವಾಗಿ** (`Promise.allSettled`), ಮತ್ತು ಅವುಗಳ ಸ್ಥಳದಲ್ಲಿ `[Image N]: <description>` ಪಠ್ಯ ಭಾಗಗಳನ್ನು ಚುಚ್ಚಲಾಗುತ್ತದೆ. ಇಳುವರಿಯನ್ನು ವಿವರಿಸಲು ವಿಫಲವಾಗಿದೆ `null`: ಕಚ್ಚಾ ಚಿತ್ರವನ್ನು unknown/vision-capable ಗುರಿಗಳಿಗಾಗಿ ಸಂರಕ್ಷಿಸಲಾಗಿದೆ (#4012), ಆದರೆ a** ದೃಢೀಕರಿಸಿದ ಪಠ್ಯ-ಮಾತ್ರ ನೇರ ಗುರಿ** ಅಥವಾ ಶೂನ್ಯ ದೃಷ್ಟಿ ಸಂಯೋಜನೆಯು ಪ್ರತಿ ವಿವರಿಸದ ಚಿತ್ರಕ್ಕಾಗಿ ಸ್ಪಷ್ಟವಾದ `(unavailable — no vision-capable provider connected)` ಪಠ್ಯ ಸ್ಟಬ್ ಅನ್ನು ಪಡೆಯುತ್ತದೆ, ಇದರಲ್ಲಿ ಭಾಗಶಃ ವೈಫಲ್ಯಗಳು ಮತ್ತು ವಿವರಿಸುವ-ಕರೆ ಕ್ಯಾಪ್ (#17069) ಮೀರಿದ ಚಿತ್ರಗಳು ಸೇರಿವೆ. ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಎಲ್ಲಾ ವಿಫಲವಾದ ಕಾಂಬೊ ಫಾಲ್ಬ್ಯಾಕ್ ಅನ್ನು ವಿವರಿಸುತ್ತದೆ (#8430).
6. `modifiedPayload` + ಮೆಟಾ (`imagesProcessed`, `descriptions`, `processingTimeMs`, `visionModel`) ಹಿಂತಿರುಗಿ

| ---------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`     | ✔        | ಲೆಗಸಿ ಹ್ಯೂರಿಸ್ಟಿಕ್, ಅಸ್ಪೃಶ್ಯ (#6640/#7204): ಮೂಲ ಮಾದರಿಯು ಈಗಾಗಲೇ ಬಳಸಬಹುದಾದ ರುಜುವಾತುಗಳನ್ನು ಹೊಂದಿಲ್ಲದಿದ್ದರೆ (ನಂತರ ವಿವರಿಸಿ) ಕಾಂಬೋ ಅಲ್ಲದ/`auto/` ಮಾದರಿಗಳು ಉತ್ತಮ ದೃಷ್ಟಿ ಮಾದರಿಗೆ ಮರುಮಾರ್ಗ ಮಾಡುತ್ತವೆ; ಕಾಂಬೊ ಗುರಿಗಳು ಯಾವಾಗಲೂ ವಿವರಿಸುತ್ತವೆ.                                                                            |
| `describe` |          | ಯಾವಾಗಲೂ — ವಿವರಿಸಿ ಮರುಮಾರ್ಗ ಬ್ಲಾಕ್ ಅನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಬಿಟ್ಟುಬಿಡಲಾಗಿದೆ; ಬಳಕೆದಾರರ ಆಯ್ಕೆ ಮಾಡೆಲ್ ಯಾವಾಗಲೂ ಉತ್ತರಿಸುತ್ತದೆ.                                                                                                                                                                                           |
| `reroute`  |          | ಮರುಮಾರ್ಗವನ್ನು ಒತ್ತಾಯಿಸಿ: ಕೀಪ್-ರುಜುವಾತು-ಮಾದರಿ ಗಾರ್ಡ್ ಅನ್ನು ಬೈಪಾಸ್ ಮಾಡಲಾಗಿದೆ. ಮರುಮಾರ್ಗ -** ಗುರಿ** ಯಾವುದೇ ಬಳಸಬಹುದಾದ ದೃಷ್ಟಿ ಗುರಿಯು ಅಸ್ತಿತ್ವದಲ್ಲಿಲ್ಲದಿದ್ದಾಗ ರುಜುವಾತು ಸಿಬ್ಬಂದಿ ಇನ್ನೂ — ಅನ್ವಯಿಸುತ್ತದೆ, ಪಠ್ಯ-ಮಾತ್ರ ಗುರಿಗೆ ಕಚ್ಚಾ ಚಿತ್ರಗಳನ್ನು ವಿವರಿಸುವ ಅಥವಾ ಕಳುಹಿಸುವ ಬದಲು ಸೇತುವೆಯು ಸ್ಪಷ್ಟ ದೋಷದೊಂದಿಗೆ ನಿರ್ಬಂಧಿಸುತ್ತದೆ. |

ಬಲವಂತದ ವಿಧಾನಗಳು ಶಾರ್ಟ್-ಸರ್ಕ್ಯೂಟ್** ಮೊದಲು** ಸ್ವಯಂ ಹ್ಯೂರಿಸ್ಟಿಕ್ ರನ್ಗಳು; `auto` ನಡವಳಿಕೆಯು pre-PR-1 ಗಾರ್ಡ್ರೈಲ್ಗೆ ಬೈಟ್-ಸಮಾನವಾಗಿದೆ.

#### API-ಕೀ ಸ್ಕೋಪ್ (`visionBridgeKeyScope.ts`)

ಕರೆ ಮಾಡುವವರ API ಕೀಯು `allowedConnections`, ಕೋಟಾ ಪೂಲ್ಗಳು (`allowedQuotas`) ಅಥವಾ ಮಾದರಿಗಳನ್ನು (`allowedModels` / `blockedModels` / `modelAccessMode: "restricted"` / `disableNonPublicModels`) ನಿರ್ಬಂಧಿಸಿದಾಗ, ಸೇತುವೆಯು ಮರುಮಾರ್ಗವನ್ನು ಮಾತ್ರ ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ ಮತ್ತು ಕೀಲಿಯು ಬಳಸಬಹುದಾದ ಸಂಪರ್ಕಗಳ ಮೇಲೆ ಬಳಸಬಹುದಾದ ಮಾದರಿಗಳನ್ನು ವಿವರಿಸುತ್ತದೆ. ವಿವರಿಸುವ ಕರೆ ಯಾವಾಗಲೂ `x-omniroute-self-loop-key-id` ಹೆಡರ್ನೊಂದಿಗೆ OmniRoute ಸ್ವಯಂ-ಲೂಪ್ ಮೂಲಕ ಹೋಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಸ್ವೀಕರಿಸುವ ಚಾಟ್ ವಿನಂತಿಯು ಆ ಕೀಯ ಸಂಪರ್ಕ ಮತ್ತು ಮಾದರಿ ನೀತಿಯನ್ನು ಮತ್ತೊಮ್ಮೆ ಜಾರಿಗೊಳಿಸುತ್ತದೆ. `enforceApiKeyPolicy()` ಸೆಲ್ಫ್-ಲೂಪ್ ಬೇರರ್ನೊಂದಿಗೆ ಮಾತ್ರ ಹೆಡರ್ ಅನ್ನು ಗೌರವಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಅದು ಪ್ರವೇಶವನ್ನು ಕಿರಿದಾಗಿಸುತ್ತದೆ ಮತ್ತು ಪರಿಹರಿಸದ ಐಡಿಯನ್ನು ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ.

ಕೀಲಿಗಾಗಿ ಯಾವುದೇ ದೃಷ್ಟಿ ಮಾದರಿಯನ್ನು ಅನುಮತಿಸದಿದ್ದರೆ, a** ದೃಢೀಕರಿಸಿದ ಪಠ್ಯ-ಮಾತ್ರ ಗುರಿ** ಇಮೇಜ್ ಬೈಟ್ಗಳನ್ನು ಅಸಮರ್ಥವಾದ ಅಪ್ಸ್ಟ್ರೀಮ್ಗೆ ಫಾರ್ವರ್ಡ್ ಮಾಡುವ ಬದಲು ಸ್ಪಷ್ಟ HTTP 400 ನೊಂದಿಗೆ ಚಿತ್ರ ವಿನಂತಿಯನ್ನು ಸ್ಥಳೀಯವಾಗಿ ತಿರಸ್ಕರಿಸುತ್ತದೆ (#17069). ಅಜ್ಞಾತ ಅಥವಾ ಸ್ಥಳೀಯ ದೃಷ್ಟಿ ಸಾಮರ್ಥ್ಯವನ್ನು ಹೊಂದಿರುವ ಗುರಿಗಳಿಗಾಗಿ, ವಿವರಿಸುವ ಮಾರ್ಗವು ಅದರ ಹಿಂದಿನ ವಿಫಲ-ತೆರೆದ ನಡವಳಿಕೆಯನ್ನು (ಮೆಟಾ `{ skipped: true, reason: "no_permitted_vision_model" }`) ಉಳಿಸಿಕೊಂಡಿದೆ. ಕೀ ಇಲ್ಲದ ವಿನಂತಿಗಳು ಮತ್ತು ಈ ನಿರ್ಬಂಧಗಳಿಲ್ಲದ ಕೀಗಳು ಮೊದಲಿನಂತೆಯೇ ವರ್ತಿಸುತ್ತವೆ.

#### ಟಾಸ್ಕ್-ಅವೇರ್ ವಿವರಿಸುವ ಪ್ರಾಂಪ್ಟ್ (`modalityBridgeVisionTaskAware`)

ಡೀಫಾಲ್ಟ್** ನಿಜ** . `composeVisionPrompt()` (`visionBridgeHelpers.ts`) ನ ಪಠ್ಯವನ್ನು ಸೇರಿಸುತ್ತದೆ** ಕೊನೆಯ ಬಳಕೆದಾರ ಸಂದೇಶ** (500 ಅಕ್ಷರಗಳಿಗೆ ಮೊಟಕುಗೊಳಿಸಲಾಗಿದೆ) ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು ಬೇಸ್ಗೆ ವಿವರಿಸುತ್ತದೆ, ಬಳಕೆದಾರರು ನಿಜವಾಗಿ ಏನು ಕೇಳಿದರು (ಕೋಡೆಕ್ಸ್-ವಿಷನ್-ಪ್ರಾಕ್ಸಿ ಪ್ಯಾಟರ್ನ್) ಮತ್ತು ಗೋಚರ ಪಠ್ಯವನ್ನು ಲಿಪ್ಯಂತರ ಮಾಡಲು ದೃಷ್ಟಿ ಮಾದರಿಯನ್ನು ಕೇಳುತ್ತದೆ. ಫ್ಲ್ಯಾಗ್ ಆಫ್ — ಅಥವಾ ಯಾವುದೇ ಬಳಕೆದಾರ ಪಠ್ಯ — ಜೊತೆಗೆ ಬೇಸ್ ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು ಬದಲಾಗದೆ ಬಳಸಲಾಗುತ್ತದೆ.

ಸ್ವಯಂ-ಲೂಪ್ನ ಸ್ವಂತ OpenAI-ಹೊಂದಾಣಿಕೆಯ ವಿನಂತಿಯನ್ನು ವಿವರಿಸುತ್ತದೆ ( `visionBridgeHelpers.ts` ನಲ್ಲಿ`callVisionModelSingle()` ) ಯಾವಾಗಲೂ `image_url.detail: "high"` — ಬೇಷರತ್ತಾಗಿ ವಿನಂತಿಸುತ್ತದೆ, ಪ್ರತಿ caller/provider ಗಾಗಿ, ಯಾವುದೇ ಕ್ಲೈಂಟ್ ಸಿಗ್ನಲ್ನಲ್ಲಿ ಗೇಟ್ ಮಾಡಲಾಗಿಲ್ಲ. ಈ ಪ್ರಾಂಪ್ಟ್ ಕೇಳುವ ಪಠ್ಯ-ಪ್ರತಿಲೇಖನ ಕಾರ್ಯಕ್ಕಾಗಿ ಕಡಿಮೆ-ವಿವರ ಮಾದರಿಯು OCR ನಿಖರತೆಯನ್ನು ಕುಗ್ಗಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಮೂಲ ಒಳಬರುವ ವಿನಂತಿಯನ್ನು ಯಾವ ವಿವರವನ್ನು ಬಳಸಿದರೂ ವಿವರಿಸುವ ಕರೆ ಯಾವಾಗಲೂ ಹೆಚ್ಚಿನ ವಿವರಗಳನ್ನು ಕೇಳುತ್ತದೆ. ಇದು ಆಂತರಿಕ ವಿವರಣೆ ವಿನಂತಿಯ ದೇಹದ ಮೇಲೆ ಮಾತ್ರ ಪರಿಣಾಮ ಬೀರುತ್ತದೆ; ಡಿಫಾಲ್ಟ್ ಅನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ ಅನ್ವಯಿಸಲಾಗುತ್ತದೆ ಮತ್ತು `defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`) ನಲ್ಲಿ ಪತ್ತೆಯಾದ OpenCode ಕ್ಲೈಂಟ್ಗಳಿಗೆ ಮಾತ್ರ ಪ್ರಾಥಮಿಕ ವಿನಂತಿಯ — ನಲ್ಲಿ OmniRoute ಕರೆ ಮಾಡುವವರ ಸ್ವಂತ `image_url.detail` ಹೇಗೆ ಫಾರ್ವರ್ಡ್ ಮಾಡುತ್ತದೆ ಎಂಬುದನ್ನು ಇದು ಬದಲಾಯಿಸುವುದಿಲ್ಲ. ವಿವರಿಸುವ ಸ್ವಯಂ-ಲೂಪ್ನ Anthropic ವೈರ್-ಫಾರ್ಮ್ಯಾಟ್ ಶಾಖೆಯು ಯಾವುದೇ `detail` ಕ್ಷೇತ್ರವನ್ನು ಹೊಂದಿಲ್ಲ ಮತ್ತು ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಯಾವುದೇ ಪರಿಣಾಮ ಬೀರುವುದಿಲ್ಲ.

`0` (ಡೀಫಾಲ್ಟ್) ಎಂದರೆ** ಕ್ಯಾಪ್ ಇಲ್ಲ** — `callVisionModel()` ನಿಂದ ಹಿಂತಿರುಗಿಸಲಾದ ವಿವರಣೆಯು ಮಾರ್ಪಡಿಸದ ಮೂಲಕ ಹಾದುಹೋಗುತ್ತದೆ, ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ನಡವಳಿಕೆಯನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ. 100–50000 ಶ್ರೇಣಿಯಲ್ಲಿನ ಯಾವುದೇ ಮೌಲ್ಯವು ವಿವರಣೆಯನ್ನು `…` ಪ್ರತ್ಯಯದೊಂದಿಗೆ ಮೊಟಕುಗೊಳಿಸುತ್ತದೆ, ಅದನ್ನು ಮತ್ತೆ `[Image N]: <description>` ( `src/lib/guardrails/visionBridge.ts` ನಲ್ಲಿ`VisionBridgeGuardrail.preCall()` ) ಎಂದು ವಿಭಜಿಸಲಾಗುತ್ತದೆ. ಡೌನ್ಸ್ಟ್ರೀಮ್ ಮಾಡೆಲ್ಗೆ ಪೂರ್ಣ ಪ್ರತಿಲೇಖನದ ಅಗತ್ಯವಿರುವಲ್ಲಿ ವಿವರ-ಭಾರೀ OCR ಕಾರ್ಯಗಳಿಗಾಗಿ ಇದನ್ನು ಹೆಚ್ಚಿಸಿ; ಚಾಟಿ ವಿಷನ್ ಮಾದರಿಗಳಲ್ಲಿ ಬೌಂಡ್ ಟೋಕನ್ ಬಳಕೆಗೆ ಅದನ್ನು ಕಡಿಮೆ ಮಾಡಿ. ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಕ್ಷೇತ್ರವು ವಿಷನ್ ಟ್ಯಾಬ್ನ ಸುಧಾರಿತ ಪ್ಯಾನೆಲ್ನಲ್ಲಿ ವಾಸಿಸುತ್ತದೆ (`modality-bridge-max-chars` ನಲ್ಲಿ `ModalityBridgeVisionTab.tsx`) ಮತ್ತು 1 ಮತ್ತು 99 ರ ನಡುವಿನ ಯಾವುದೇ ಮೌಲ್ಯವನ್ನು 100 ಮಹಡಿಯವರೆಗೆ ಕ್ಲ್ಯಾಂಪ್ ಮಾಡುತ್ತದೆ ಆದರೆ ಸ್ಪಷ್ಟವಾದ `0` ಸ್ಪರ್ಶಿಸದ — `0` ತನ್ನದೇ ಆದ ಮಾನ್ಯವಾದ Zod ಮೌಲ್ಯವಾಗಿದೆ (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), ಕೇವಲ "ಡಿಫಾಲ್ಟ್" ಅನ್ನು ಹೊಂದಿಸದೆ ".

#### ಸಂಗ್ರಹವನ್ನು ವಿವರಿಸಿ (`modalityBridge/bridgeCache.ts`)

ಔಟ್ಪುಟ್ಗಳನ್ನು ವಿವರಿಸಲು ಇನ್-ಮೆಮೊರಿ LRU + TTL ಸಂಗ್ರಹ, ಪ್ರಕ್ರಿಯೆಯಾದ್ಯಂತ ಹಂಚಿಕೊಳ್ಳಲಾಗಿದೆ. ಉದ್ದ-ಪೂರ್ವಪ್ರತ್ಯಯ ಚೌಕಟ್ಟಿನೊಂದಿಗೆ ಕೀ = `sha256(imageRef + composedPrompt + configuredBridgeModel)` (ಯಾವುದೇ ಕ್ಷೇತ್ರ-ಬೌಂಡರಿ ಘರ್ಷಣೆಗಳಿಲ್ಲ). ಮಾದರಿ ಘಟಕವಾಗಿದೆ** ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗಿದೆ** ಸೇತುವೆಯ ಮಾದರಿ, — `callVisionModel` ಉತ್ತರಿಸಿದ ಮಾದರಿಯು ಆಂತರಿಕವಾಗಿ ಹಿಂತಿರುಗಬಹುದು ಮತ್ತು ಪ್ರತಿ ಪ್ರಯತ್ನಕ್ಕೆ ಕೀಯಿಂಗ್ ಸಂಗ್ರಹವನ್ನು ವಿಭಜಿಸುತ್ತದೆ. ವಿಫಲವಾದ ವಿವರಣೆಗಳು ಎಂದಿಗೂ ಸಂಗ್ರಹವಾಗುವುದಿಲ್ಲ. ಸೆಟ್ಟಿಂಗ್ಗಳು:

| ಕೀ                              | ಡೀಫಾಲ್ಟ್ | ಶ್ರೇಣಿ  |
| ------------------------------- | -------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`   | —       |
| `modalityBridgeCacheTtlMinutes` | `60`     | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`    | 10–5000 |

#### ರಿಮೋಟ್ ಇಮೇಜ್ ಸಾಮಾನ್ಯೀಕರಣ (ಸ್ವಯಂ-ಲೂಪ್ describe/base64 ಪಡೆಯುವಿಕೆ)

ಸೇತುವೆಯನ್ನು ಪಡೆದಾಗ ಎ** ದೂರಸ್ಥ** ಚಿತ್ರವು ಸ್ವತಃ — Anthropic ಸ್ವಯಂ-ಕರೆ ಮತ್ತು ಕ್ಲಾಡ್-ವೈರ್-ಫಾರ್ಮ್ಯಾಟ್ ಬೇಸ್64 ಪರಿವರ್ತನೆ (`ensureBase64ImagesForClaudeWire`) ಅನ್ನು ವಿವರಿಸುತ್ತದೆ, ಎರಡೂ `visionBridgeHelpers.ts` — ನಲ್ಲಿ `fetchRemoteImageAsDataUri()` ಮೂಲಕ ಫಲಿತಾಂಶದ ಡೇಟಾ URI ದೃಷ್ಟಿ-ಮಾದರಿ ವಿನಂತಿಯಲ್ಲಿ ಎಂಬೆಡ್ ಮಾಡುವ ಮೊದಲು `normalizeDataUri()` (`open-sse/utils/imageNormalize.ts`) ಮೂಲಕ ರವಾನಿಸಲಾಗುತ್ತದೆ. ಗಾತ್ರದ ಚಿತ್ರಗಳನ್ನು a ಗೆ ಇಳಿಸಲಾಗಿದೆ** 2048px ಉದ್ದದ ಅಂಚು** (ರೆಸೈಜ್ ಕ್ಯಾಪ್ OpenAI/Anthropic ಗೆ ಹೊಂದಿಕೆಯಾಗುವುದು ಈಗಾಗಲೇ ಸರ್ವರ್-ಸೈಡ್ ಅನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ), ಇದು ದೃಷ್ಟಿ ಮಾದರಿಯು ಏನನ್ನು ನೋಡುತ್ತದೆ ಎಂಬುದನ್ನು ಬದಲಾಯಿಸದೆಯೇ ಅಪ್ಲೋಡ್ bytes/latency ಕಡಿತಗೊಳಿಸುತ್ತದೆ. ಮರುಗಾತ್ರಗೊಳಿಸುವಿಕೆಯು ಡೈನಾಮಿಕ್ ಆಮದು ಮೂಲಕ ಲೋಡ್ ಮಾಡಲಾದ `sharp` ಬಳಸುತ್ತದೆ: ಅದರ ಸ್ಥಳೀಯ ಬೈನರಿ ಲೋಡ್ ಮಾಡಲು ವಿಫಲವಾದ ವೇದಿಕೆಯಲ್ಲಿ, `normalizeDataUri()`** ಎಂದಿಗೂ ಎಸೆಯುವುದಿಲ್ಲ** — ಇದು ಮೂಲ ಬೈಟ್ಗಳ ಪಾಸ್ಥ್ರೂಗೆ ಹಿಂತಿರುಗುತ್ತದೆ, ಆದ್ದರಿಂದ describe/base64-conversion ಮಾರ್ಗವು ಯಾವಾಗಲೂ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿರುತ್ತದೆ. ಚಿತ್ರ-ಅಲ್ಲದ ಬೈಟ್ಗಳು (ಡಿಕೋಡ್ ಮಾಡಬಹುದಾದ ಚಿತ್ರವನ್ನು ಹಿಂತಿರುಗಿಸದ ಪಡೆಯುವಿಕೆ) ಸಹ ಅಸ್ಪೃಶ್ಯವಾಗಿ ರವಾನಿಸಲಾಗಿದೆ. ಈ ಸಾಮಾನ್ಯೀಕರಣವು ಸೇತುವೆಯು ತನ್ನದೇ ಆದ ಸ್ವಯಂ-ಕರೆ — ಗಾಗಿ ಪಡೆಯುವ ಚಿತ್ರಗಳಿಗೆ ಸ್ಕೋಪ್ ಮಾಡಲ್ಪಟ್ಟಿದೆ, ಇದು ಕರೆ ಮಾಡುವವರ ಕಚ್ಚಾ ಪಾಸ್ಥ್ರೂ ಪೇಲೋಡ್ಗೆ ಎಂದಿಗೂ ಅನ್ವಯಿಸುವುದಿಲ್ಲ, ಆಯ್ಕೆ-ಮಾತ್ರ ರೂಪಾಂತರ ತತ್ವಕ್ಕೆ (ಹಾರ್ಡ್ ರೂಲ್ #20) ಸ್ಥಿರವಾಗಿದೆ.

#### ಸ್ಕೀಮಾ + ವಲಸೆಯ ಸೆಟ್ಟಿಂಗ್ಗಳು

ಹೊಸ `modalityBridge*` ಕೀಗಳನ್ನು `updateSettingsSchema` (`src/shared/validation/settingsSchemas.ts`) ನಲ್ಲಿ Zod-ಮೌಲ್ಯೀಕರಿಸಲಾಗಿದೆ: `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCache*` ಟ್ರಿಯೊ, ಮತ್ತು ಆಡಿಯೊ ಬ್ರಿಡ್ಜ್ ಬಳಸುವ `modalityBridgeAudio*` ಗುಂಪು. ವಲಸೆ `141_modality_bridge_settings.sql` ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಲೆಗಸಿ `visionBridge*` ಮೌಲ್ಯಗಳನ್ನು ಹೊಂದಿಕೆಯಾಗುವ ಹೊಸ ಕೀಗಳಿಗೆ ನಕಲಿಸುತ್ತದೆ (idempotent, ಆಪರೇಟರ್-ಸೆಟ್ `modalityBridge*` ಮೌಲ್ಯವನ್ನು ಎಂದಿಗೂ ಓವರ್ರೈಟ್ ಮಾಡುವುದಿಲ್ಲ); ಪಾರಂಪರಿಕ ಕೀಲಿಗಳು ಒಂದು ಬಿಡುಗಡೆಯ ಚಕ್ರಕ್ಕೆ ರೀಡ್ ಫಾಲ್ಬ್ಯಾಕ್ ಆಗಿ ಸ್ವೀಕರಿಸಲ್ಪಡುತ್ತವೆ.

#### ಪಾರದರ್ಶಕತೆ ಹೆಡರ್ + ಅಂಕಿಅಂಶಗಳು

ವಿವರಿಸಿ-ರೂಪಾಂತರಗೊಂಡ ಪ್ರತಿಕ್ರಿಯೆಗಳು `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` ಒಯ್ಯುತ್ತವೆ ( `modalityBridge/bridgeStats.ts` ನಲ್ಲಿ `buildModalityBridgeHeader()` ನಿಂದ ನಿರ್ಮಿಸಲಾಗಿದೆ, `src/sse/handlers/chatHelpers.ts` ನಲ್ಲಿ `withModalityBridgeHeader()` ನಿಂದ ಸ್ಟ್ಯಾಂಪ್ ಮಾಡಲಾಗಿದೆ). ಮರುಮಾರ್ಗ ಮಾಡಲಾದ ವಿನಂತಿಗಳು ಸಿಗುತ್ತವೆ** ಇಲ್ಲ** ಹೆಡರ್ — ಪೇಲೋಡ್ ಅನ್ನು ಸ್ಪರ್ಶಿಸಲಾಗಿಲ್ಲ ಮತ್ತು ಮಾದರಿ ಸ್ವಾಪ್ ಈಗಾಗಲೇ ಪ್ರತಿಕ್ರಿಯೆ ದೇಹದ `model` ಕ್ಷೇತ್ರದಲ್ಲಿ ಗೋಚರಿಸುತ್ತದೆ.

`GET /api/modality-bridge/stats` (ನಿರ್ವಹಣೆ ದೃಢೀಕರಣ, `GET /api/settings` ಯಂತೆಯೇ ಅದೇ ಶ್ರೇಣಿ) `vision`, `audio`, ಮತ್ತು `video` ಗಾಗಿ ಇನ್-ಮೆಮೊರಿ ಪರ್-ಮೊಡಲಿಟಿ ಕೌಂಟರ್ಗಳ `{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs, latencySamples, averageLatencyMs, lastUsedAt }` ಹಿಂತಿರುಗಿಸುತ್ತದೆ. `averageLatencyMs` `latencySamples` ಬಳಸುತ್ತದೆ, ಎಲ್ಲಾ ಪ್ರಯತ್ನಗಳಲ್ಲ, ಅದರ ಛೇದವಾಗಿ; ಸಮಯವಿಲ್ಲದ ಕಾರ್ಯಾಚರಣೆಯು ಶೂನ್ಯ-ಮಿಲಿಸೆಕೆಂಡ್ ಮಾದರಿಯನ್ನು ರೂಪಿಸುವುದಿಲ್ಲ. `bridged` ಯಶಸ್ವಿ ಪರಿವರ್ತನೆಗಳಿಗಾಗಿ ಹಿಂದುಳಿದ-ಹೊಂದಾಣಿಕೆಯ ಅಲಿಯಾಸ್ ಆಗಿ ಉಳಿದಿದೆ; ವಿಫಲ ಪ್ರಯತ್ನಗಳು ಅದನ್ನು ಹೆಚ್ಚಿಸುವುದಿಲ್ಲ. ವಿನ್ಯಾಸದ ಮೂಲಕ ಪ್ರಕ್ರಿಯೆ ಮರುಪ್ರಾರಂಭದಲ್ಲಿ ಕೌಂಟರ್ಗಳನ್ನು ಮರುಹೊಂದಿಸಿ (ಟೆಲಿಮೆಟ್ರಿ, ಲೆಕ್ಕಪತ್ರ ನಿರ್ವಹಣೆ ಅಲ್ಲ).

#### ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಕಾನ್ಫಿಗರೇಶನ್

ಮೀಸಲಾದ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಪುಟವು `/dashboard/settings/modality-bridge` ಆಗಿದೆ. ಅದರ URL-ವಿಳಾಸ ಮಾಡಬಹುದಾದ `Vision`, `Audio`, ಮತ್ತು `Video` ಟ್ಯಾಬ್ಗಳು `tab` ಮೌಲ್ಯವನ್ನು ಬದಲಾಯಿಸುವಾಗ ಪ್ರಶ್ನೆ ನಿಯತಾಂಕಗಳನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ. ವಿಷನ್ ಟ್ಯಾಬ್ ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ, ಮೋಡ್, ಮಾದರಿ ಆಯ್ಕೆ (ಸ್ವಯಂಚಾಲಿತ ಡೀಫಾಲ್ಟ್ ಸೇರಿದಂತೆ), ಟಾಸ್ಕ್-ಅವೇರ್ ಪ್ರಾಂಪ್ಟಿಂಗ್, ಸುಧಾರಿತ timeout/image/description-length/cache ಮಿತಿಗಳು, ರನ್ಟೈಮ್ ಕೌಂಟರ್ಗಳು ಮತ್ತು ರಕ್ಷಣಾತ್ಮಕ ಮಾದರಿ ವಿನಂತಿಯನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ. ಆಡಿಯೊ ಟ್ಯಾಬ್ ಸಹ ಲೈವ್ ಆಗಿದೆ: ಇದು ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ, ಆಟೋ, timeout/max-clip ಮಿತಿಗಳು, ಆಡಿಯೊ ಕೌಂಟರ್ಗಳು ಮತ್ತು `input_audio` ಮಾದರಿ ಪರೀಕ್ಷೆಯೊಂದಿಗೆ STT-ಮಾತ್ರ ಮಾದರಿ ಪಿಕ್ಕರ್ ಅನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ. ವೀಡಿಯೊ ಟ್ಯಾಬ್ ಕ್ರಿಯಾತ್ಮಕವಾಗಿದೆ: ಇದು FFmpeg/ffprobe ರನ್ಟೈಮ್ ಸ್ಟೇಟ್ — ನಾಲ್ಕು ಸ್ಪಷ್ಟ UI ಸ್ಟೇಟ್ಗಳಲ್ಲಿ ಒಂದನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ (ತನಿಖೆಯು ಹಾರುತ್ತಿರುವಾಗ ಅಥವಾ ಪೂರ್ಣಗೊಳ್ಳದಿರುವಾಗ `unknown`, ಲೂಪ್ಬ್ಯಾಕ್ ಅಲ್ಲದ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಹೋಸ್ಟ್ನಲ್ಲಿ `restricted`, ಅಲ್ಲಿ ಪ್ರೋಬ್ ಅನ್ನು ಕ್ಲೈಂಟ್-ಸೈಡ್ ಸ್ಕಿಪ್ ಮಾಡಲಾಗಿದೆ, `unavailable` ಒಮ್ಮೆ ಪರೀಕ್ಷಿಸಿ ಮತ್ತು ದೃಢೀಕರಿಸಿದ FFmpeg/ffprobe ಆವೃತ್ತಿಗಳು, ಅಥವಾ `available` per — enable/model/frame/video/timeout ಮಿತಿಗೊಳಿಸುತ್ತದೆ, ಮಾದರಿ ಪಿಕ್ಕರ್ ಅನ್ನು ದೃಷ್ಟಿ ಸಾಮರ್ಥ್ಯದ ಮಾದರಿಗಳಿಗೆ ಫಿಲ್ಟರ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ವೀಡಿಯೊ ಕೌಂಟರ್ಗಳನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ.

AI ಸೆಟ್ಟಿಂಗ್ಗಳ ಅಡಿಯಲ್ಲಿ ಹಿಂದಿನ ವಿಷನ್ ಬ್ರಿಡ್ಜ್ ಕಾರ್ಡ್ ಹೊಸ ಪುಟಕ್ಕೆ ಹೊಂದಾಣಿಕೆಯ ಲಿಂಕ್ ಆಗಿದೆ; ಇದು ಇನ್ನು ಮುಂದೆ ಫಾರ್ಮ್ನ ಎರಡನೇ ಪ್ರತಿಯನ್ನು ಹೊಂದಿಲ್ಲ. ಮಾಧ್ಯಮ ಪೂರೈಕೆದಾರರು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಸ್ಪೀಚ್-ಟು-ಟೆಕ್ಸ್ಟ್ ಪ್ಲೇಗ್ರೌಂಡ್ ಅನ್ನು ತೆಗೆದುಹಾಕದೆಯೇ ಇಮೇಜ್-ಟು-ಟೆಕ್ಸ್ಟ್ ಮತ್ತು ಸ್ಪೀಚ್-ಟು-ಟೆಕ್ಸ್ಟ್ ವರ್ಕ್ಫ್ಲೋಗಳನ್ನು ಅನುಗುಣವಾದ ಮೊಡಲಿಟಿ ಬ್ರಿಡ್ಜ್ ಟ್ಯಾಬ್ಗಳಿಗೆ ಲಿಂಕ್ ಮಾಡುತ್ತಾರೆ.

**ಸ್ವಯಂ-ಲೂಪ್ ಪ್ರವೇಶ ಬೈಪಾಸ್:** OmniRoute ನ ಸ್ವಂತ `/v1` ಸ್ವಯಂ-ಲೂಪ್ (ಪ್ರಮಾಣಿತವಲ್ಲದ ಪೂರೈಕೆದಾರರ ಮಾದರಿ) ಮೂಲಕ ಕರೆ ಮಾರ್ಗಗಳನ್ನು ವಿವರಿಸಿದಾಗ, ಉಪ-ವಿನಂತಿಯು `x-omniroute-admission-bypass: internal` ಕಳುಹಿಸುತ್ತದೆ ಮತ್ತು ಪರಿಹರಿಸಿದ ಸ್ವಯಂ-ಲೂಪ್ ರುಜುವಾತು — ಸ್ಥಳೀಯ ಕ್ರಮದಲ್ಲಿ ಸ್ಥಳೀಯ `sk_omniroute` ಸೆಂಟಿನೆಲ್ ಅಥವಾ ಆಪರೇಟರ್-ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ `OMNIROUTE_API_KEY` ಕೀಲಿಯೊಂದಿಗೆ ದೃಢೀಕರಿಸಲಾಗುತ್ತದೆ (#1gzqf / `ROUTER_API_KEY` ) `REQUIRE_API_KEY=true` ಇನ್ನೂ ವಿವರಿಸುವ ಕರೆಯನ್ನು ರನ್ ಮಾಡಬಹುದು. ಬೈಪಾಸ್ ಅನ್ನು ಆ ನಿಖರವಾದ ರುಜುವಾತುಗಳಿಗೆ ಮಾತ್ರ ಗೌರವಿಸಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಬಾಹ್ಯ ಗ್ರಾಹಕರು ಪ್ರವೇಶವನ್ನು ಬಿಟ್ಟುಬಿಡಲು ಹೆಡರ್ ಅನ್ನು ಬಳಸಲಾಗುವುದಿಲ್ಲ. (#1350)

ಲೆಗಸಿ ಡೀಫಾಲ್ಟ್ಗಳು `src/shared/constants/visionBridgeDefaults.ts` ನಲ್ಲಿ ವಾಸಿಸುತ್ತವೆ; ಹೊಸ mode/task-aware/cache ಡೀಫಾಲ್ಟ್ಗಳು ಮತ್ತು ಸೆಟ್ಟಿಂಗ್ಗಳ ಪರಿಹಾರಕವು `src/shared/constants/modalityBridgeDefaults.ts` ನಲ್ಲಿ ಲೈವ್ ಆಗಿದೆ. ಗಾರ್ಡ್ರೈಲ್ `deps` ಕನ್ಸ್ಟ್ರಕ್ಟರ್ ಆಯ್ಕೆಯನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ ಆದ್ದರಿಂದ ಪರೀಕ್ಷೆಗಳು ನಕಲಿ `getSettings` ಮತ್ತು `callVisionModel` ಅಳವಡಿಕೆಗಳನ್ನು ಚುಚ್ಚಬಹುದು.

### ಆಡಿಯೋ ಬ್ರಿಡ್ಜ್ (`audioBridge.ts`) — ಮಾಡಾಲಿಟಿ ಸೇತುವೆ PR-3

ಆಡಿಯೊ ಇನ್ಪುಟ್ ಅನ್ನು ಸ್ವೀಕರಿಸಲು ತಿಳಿದಿಲ್ಲದ ಗುರಿಯನ್ನು ತಲುಪುವ ಮೊದಲು ಆಡಿಯೊ-ಬೇರಿಂಗ್ ಚಾಟ್ ವಿನಂತಿಗಳನ್ನು ಪ್ರತಿಬಂಧಿಸುತ್ತದೆ. ಇದು ಚಾಟ್ ವಿನಂತಿಯನ್ನು ಎಂದಿಗೂ ಮರುಹೊಂದಿಸುವುದಿಲ್ಲ: ಆಡಿಯೊ ಭಾಗಗಳನ್ನು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ OpenAI-ಹೊಂದಾಣಿಕೆಯ ಮಲ್ಟಿಪಾರ್ಟ್ ಎಂಡ್ಪಾಯಿಂಟ್ ಮೂಲಕ ಲಿಪ್ಯಂತರ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು ಆಯ್ಕೆಮಾಡಿದ ಚಾಟ್ ಮಾದರಿಯು ಪಠ್ಯ ಪ್ರತಿಲೇಖನಗಳೊಂದಿಗೆ ಮುಂದುವರಿಯುತ್ತದೆ.

ಹರಿವು:

1. `supportsAudio` `getResolvedModelCapabilities()` ಮೂಲಕ ಪರಿಹರಿಸಿ. ಸ್ಪಷ್ಟ ಪೂರೈಕೆದಾರ-ರಿಜಿಸ್ಟ್ರಿ ಮೆಟಾಡೇಟಾ ಗೆಲ್ಲುತ್ತದೆ, ನಂತರ ಸ್ಥಿರ ಮಾದರಿ ಮೆಟಾಡೇಟಾ, ನಂತರ ಸಿಂಕ್ ಮಾಡಲಾದ `modalities_input`. `audio` ಇಲ್ಲದೆ ಡಿಕ್ಲೇರ್ಡ್ ಇನ್ಪುಟ್ ಪಟ್ಟಿ `false` ಆಗಿದೆ; ಯಾವುದೇ ಸಾಮರ್ಥ್ಯದ ಪುರಾವೆಗಳು `null` ಉಳಿದಿಲ್ಲ. `false` ಮತ್ತು `null` ಎರಡೂ ಸಂಪ್ರದಾಯವಾದಿ ಸೇತುವೆಯನ್ನು ಸಕ್ರಿಯಗೊಳಿಸುತ್ತವೆ, ಆದರೆ `true` ಅದನ್ನು ಬೈಪಾಸ್ ಮಾಡುತ್ತದೆ.
2. `modalityBridgeAudio*` ಸೆಟ್ಟಿಂಗ್ಗಳನ್ನು ಪರಿಹರಿಸಿ ಮತ್ತು ಹಂಚಿಕೊಂಡ `detectMediaParts()` ಡಿಟೆಕ್ಟರ್ ಮೂಲಕ ಪ್ರತಿ ಸಂದೇಶದಿಂದ ಸ್ಪ್ಲೈಸ್ ಮಾಡಬಹುದಾದ ಉನ್ನತ ಮಟ್ಟದ ಆಡಿಯೊ ಭಾಗಗಳನ್ನು ಹೊರತೆಗೆಯಿರಿ. ಬೆಂಬಲಿತ ತಂತಿ ಆಕಾರಗಳೆಂದರೆ OpenAI `input_audio`, `audio_url` ಮತ್ತು `source.media_type: "audio/*"`. ನೆಸ್ಟೆಡ್ ಆಡಿಯೊವನ್ನು ರೂಟಿಂಗ್ಗಾಗಿ ಪತ್ತೆಹಚ್ಚಲಾಗಿದೆ ಆದರೆ ಸ್ಪ್ಲೈಸ್ ಮಾರ್ಗದಿಂದ ತೆಗೆದುಹಾಕಲಾಗಿಲ್ಲ. ಕೆಲಸವು `modalityBridgeAudioMaxClips` ನಿಂದ ಮುಚ್ಚಲ್ಪಟ್ಟಿದೆ; ನಂತರದ ಭಾಗಗಳು ಅಸ್ಪೃಶ್ಯವಾಗಿರುತ್ತವೆ.
3. ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ `provider/model` ಅನ್ನು ಗೌರವಿಸಿ, ಅಥವಾ `selectAudioBridgeModel()` ಸ್ಥಿರ ಕ್ಯಾಟಲಾಗ್ ಕ್ರಮದಲ್ಲಿ `AUDIO_TRANSCRIPTION_PROVIDERS` ನಡೆಯಲು ಅವಕಾಶ ಮಾಡಿಕೊಡಿ ಮತ್ತು ಬಳಸಬಹುದಾದ ಸಕ್ರಿಯ ಪೂರೈಕೆದಾರರ ರುಜುವಾತುಗಳೊಂದಿಗೆ ಮೊದಲ ಮಾದರಿಯನ್ನು ಆಯ್ಕೆ ಮಾಡಿ.
4. `callAudioTranscription()` base64/data-URI ಆಡಿಯೊವನ್ನು ಮಲ್ಟಿಪಾರ್ಟ್ `file` ಗೆ ಪರಿವರ್ತಿಸುತ್ತದೆ ಅಥವಾ DNS ಪಿನ್ನಿಂಗ್ ಮತ್ತು 25 MB ಬೌಂಡ್ನೊಂದಿಗೆ ಸಾರ್ವಜನಿಕ-ಮಾತ್ರ ಹೊರಹೋಗುವ ಗಾರ್ಡ್ ಮೂಲಕ ರಿಮೋಟ್ `audio_url` ಡೌನ್ಲೋಡ್ ಮಾಡುತ್ತದೆ. ಇದು ನಂತರ ಫೈಲ್ ಅನ್ನು POSTs ಮತ್ತು ಸ್ಥಳೀಯ `/v1/audio/transcriptions` ಸ್ವಯಂ-ಲೂಪ್ಗೆ ಆಯ್ಕೆ ಮಾಡೆಲ್ ಅನ್ನು `resolveSelfLoopBearer()` ನೊಂದಿಗೆ ಪ್ರಮಾಣೀಕರಿಸುತ್ತದೆ. ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಪ್ರತಿಲೇಖನ ಮಾರ್ಗವು ಸಾಮಾನ್ಯ ರುಜುವಾತು ಲುಕಪ್, cooldown/rate-limit ನಿರ್ವಹಣೆ ಮತ್ತು ಪೂರೈಕೆದಾರರ ರವಾನೆಯನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ.
5. ಯಶಸ್ವಿ ಕರೆಗಳು ತಮ್ಮ ಭಾಗಗಳನ್ನು `[Audio N]: <transcript>` ನೊಂದಿಗೆ ಬದಲಾಯಿಸುತ್ತವೆ. `Promise.allSettled` ನೊಂದಿಗೆ ಕರೆಗಳು ರನ್ ಆಗುತ್ತವೆ : ವೈಯಕ್ತಿಕ ವೈಫಲ್ಯವು ಮೂಲ ಆಡಿಯೊ ಭಾಗವನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ (#4012 ಒಪ್ಪಂದ). ಪ್ರತಿ ಕರೆ ವಿಫಲವಾದರೆ ಮತ್ತು ಗುರಿಯು `supportsAudio === false` ಸಾಬೀತಾದರೆ, ಭಾಗಗಳು `[Audio N]: (unavailable — no STT provider connected)` ಆಗುತ್ತವೆ (#8430 ಒಪ್ಪಂದ). ಅಜ್ಞಾತ ಗುರಿಗಾಗಿ (`null`), ಎಲ್ಲಾ ವೈಫಲ್ಯದ ಫಲಿತಾಂಶವು ಅಸ್ಪೃಶ್ಯವಾಗಿ ಉಳಿಯುತ್ತದೆ. ಬಳಸಬಹುದಾದ STT ರುಜುವಾತುಗಳಿಲ್ಲದ ಸಾಬೀತಾದ ಪಠ್ಯ-ಮಾತ್ರ ಗುರಿಯು ನೆಟ್ವರ್ಕ್ ಕರೆಯನ್ನು ನೀಡದೆ ಅದೇ ಸ್ಪಷ್ಟವಾದ ಸ್ಟಬ್ ಅನ್ನು ಪಡೆಯುತ್ತದೆ.

ಯಶಸ್ವಿ ಪ್ರತಿಲೇಖನಗಳು ಪ್ರಕ್ರಿಯೆ-ವ್ಯಾಪಕ ಮಾಡಾಲಿಟಿ ಬ್ರಿಡ್ಜ್ LRU/TTL ಸಂಗ್ರಹವನ್ನು ಬಳಸುತ್ತವೆ. ಕೀಲಿಯು ಆಡಿಯೊ ಉಲ್ಲೇಖ, ಸ್ಥಿರವಾದ `audio-transcription` ಕಾರ್ಯಾಚರಣೆಯ ಲೇಬಲ್ ಮತ್ತು ಆಯ್ದ STT ಮಾದರಿಯನ್ನು ಸಂಯೋಜಿಸುತ್ತದೆ; ವೈಫಲ್ಯಗಳನ್ನು ಎಂದಿಗೂ ಸಂಗ್ರಹಿಸಲಾಗುವುದಿಲ್ಲ. ಆಡಿಯೋ ಪ್ರಯತ್ನಗಳು ಹಂಚಿದ `bridged`, `cacheHits`, `failures`, ಮತ್ತು `lastUsedAt` ಕೌಂಟರ್ಗಳನ್ನು ನವೀಕರಿಸುತ್ತವೆ. ರೂಪಾಂತರಗೊಂಡ ಪ್ರತಿಕ್ರಿಯೆಗಳು `x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ಅನ್ನು ಒಯ್ಯುತ್ತವೆ; ಮುಟ್ಟದ ವಿನಂತಿಗಳು ಆಡಿಯೊ ಬ್ರಿಡ್ಜ್ ವಿಭಾಗವನ್ನು ಸ್ವೀಕರಿಸುವುದಿಲ್ಲ.

ಚಾಲನಾಸಮಯದ ಸೆಟ್ಟಿಂಗ್ಗಳು DB-ಬೆಂಬಲಿತ ಮತ್ತು Zod-ಮೌಲ್ಯೀಕರಿಸಲಾಗಿದೆ:

| ಕೀ                            | ಡೀಫಾಲ್ಟ್ | ಶ್ರೇಣಿ            |
| ----------------------------- | -------- | ----------------- |
| `modalityBridgeAudioEnabled`  | `true`   | —                 |
| `modalityBridgeAudioModel`    | `""`     | ಸ್ವಯಂ ಅಥವಾ STT ID |
| `modalityBridgeAudioTimeout`  | `60000`  | 1000–300000       |
| `modalityBridgeAudioMaxClips` | `3`      | 1–10              |

ಹಂಚಿದ ಸಂಗ್ರಹವು `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes` ಮತ್ತು `modalityBridgeCacheMaxEntries` ನಿಂದ ನಿಯಂತ್ರಿಸಲ್ಪಡುತ್ತದೆ.

### ವೀಡಿಯೊ ಸೇತುವೆ (`videoBridge.ts`, `videoBridgePipeline.ts`)

ತಿಳಿದಿರುವ ಸ್ಥಳೀಯ ವೀಡಿಯೊ ಬೆಂಬಲವಿಲ್ಲದ ಗುರಿಯನ್ನು ಕರೆಯುವ ಮೊದಲು ಚಾಟ್ ಪೂರ್ಣಗೊಳಿಸುವಿಕೆ `messages` ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆಗಳು API `input` ನಲ್ಲಿ ಉನ್ನತ ಮಟ್ಟದ ವೀಡಿಯೊ ಭಾಗಗಳನ್ನು ಪ್ರತಿಬಂಧಿಸುತ್ತದೆ. ಬೆಂಬಲಿತ ಆಕಾರಗಳೆಂದರೆ `input_video`, `video_url`, `video_source`, HTTPS URLs, ಮತ್ತು `data:video/*;base64,...` ಡೇಟಾ URIs. ಪಠ್ಯದಲ್ಲಿನ ಸರಳ ಫೈಲ್ ಹೆಸರುಗಳನ್ನು ವೀಡಿಯೊ ಎಂದು ಪರಿಗಣಿಸಲಾಗುವುದಿಲ್ಲ.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) ವಿನಂತಿಯ ಟ್ರಾವರ್ಸಲ್, capability/policy ಚೆಕ್, ಪ್ರತಿ ವಿನಂತಿಯ ಒಟ್ಟುಗೂಡಿಸುವಿಕೆ ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆ ಪೇಲೋಡ್ ಅನ್ನು ಹೊಂದಿದೆ. ಪರ್-ವೀಡಿಯೊ ವರ್ಕ್ — ಸ್ವಾಧೀನ, ಸಂಪೂರ್ಣ-ಫಲಿತಾಂಶ ಸಂಗ್ರಹ, ಫ್ರೇಮ್ ಅನುಕ್ರಮವನ್ನು ವಿವರಿಸುತ್ತದೆ (ಇದು ಯಾವುದೇ ಕಾಲರ್-ಘೋಷಿತ ಆಡಿಯೊ ಟ್ರಾನ್ಸ್ಕ್ರಿಪ್ಟ್ ಅನ್ನು ಬೆಸೆಯುತ್ತದೆ), ಮತ್ತು ಪ್ರತಿ ಪ್ರಯತ್ನದ metrics/abort/cleanup — `videoBridgePipeline.ts` ನಲ್ಲಿ `processVideoPart` ಹಿಂದೆ ಮರೆಮಾಡಲಾಗಿದೆ, `preCall` ನ ಲೂಪ್ನಲ್ಲಿ ಪ್ರತಿ ವೀಡಿಯೊ ಭಾಗಕ್ಕೆ ಒಮ್ಮೆ ಕರೆಯಲಾಗುತ್ತದೆ. ಆ ಮಾಡ್ಯೂಲ್ ಸ್ಪಷ್ಟವಾದ ಪೋರ್ಟ್ ಗಡಿಗಳನ್ನು `VideoMediaBrokerPort` (ಬೈಟ್ಗಳನ್ನು ಪಡೆದುಕೊಳ್ಳುವುದು ಮತ್ತು ಮಾದರಿ ಫ್ರೇಮ್ಗಳನ್ನು ಹೊರತೆಗೆಯುವುದು), `VideoAudioTranscriptionPort` (ಮಾದರಿ ಶೀರ್ಷಿಕೆಗಳೊಂದಿಗೆ ಕಾಲರ್-ಘೋಷಿತ ಆಡಿಯೊ ಟ್ರಾನ್ಸ್ಕ್ರಿಪ್ಟ್ ಅನ್ನು ಬೆಸೆಯುವುದು), ಮತ್ತು `VideoDrilldownPort` (ಫ್ರೇಮ್ ಡ್ರಿಲ್-ಡೌನ್ ಪರ್ಸಿಸ್ಟೆನ್ಸ್ ಬೌಂಡರಿ; ಇನ್ನೂ `processVideoPart` — `/api/modality-bridge/video/drilldown` ಪ್ರತ್ಯೇಕವಾದ ಮಾರ್ಗಗಳನ್ನು ಬರೆಯಲಾಗಿಲ್ಲ) ಅನ್ನು ವ್ಯಾಖ್ಯಾನಿಸುತ್ತದೆ.

ಸಾರ್ವಜನಿಕ `/v1` ವಿನಂತಿ ಮಾರ್ಗವು ಎಂದಿಗೂ ಆಮದು ಮಾಡಿಕೊಳ್ಳುವುದಿಲ್ಲ ಅಥವಾ ಉಪಪ್ರಕ್ರಿಯೆಯನ್ನು ಆಹ್ವಾನಿಸುವುದಿಲ್ಲ. ರಿಮೋಟ್ ವೀಡಿಯೊಗಳನ್ನು 50 MiB ಬೌಂಡ್ ಅಡಿಯಲ್ಲಿ ಡೌನ್ಲೋಡ್ ಮಾಡಲಾಗುತ್ತದೆ; ಇನ್ಲೈನ್ ಬೇಸ್64 ವೀಡಿಯೋಗಳು ಕನ್ಸರ್ವೇಟಿವ್ 36 MiB ಡೀಕೋಡ್ ಪ್ರತಿ-ವೀಡಿಯೊ ಕ್ಯಾಪ್ ಅನ್ನು ಹೊಂದಿವೆ ಆದ್ದರಿಂದ model/messages/framing ಹೊದಿಕೆಯು ಸಾರ್ವಜನಿಕ JSON ವಿನಂತಿಯ ಪ್ರವೇಶ ಮಿತಿ 50 MiB ಒಳಗೆ ಉಳಿಯಬಹುದು. ಇನ್ಲೈನ್ ಉದ್ದ ಮತ್ತು ಡಿಕೋಡ್ ಮಾಡಿದ ಗಾತ್ರದ ಅಂದಾಜುಗಳನ್ನು ಹಂಚಿಕೆಗೆ ಮೊದಲು ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ. DNS ಪಿನ್ನಿಂಗ್ನೊಂದಿಗೆ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಸಾರ್ವಜನಿಕ-ಮಾತ್ರ ಹೊರಹೋಗುವ ಗಾರ್ಡ್ ಅನ್ನು ಬಳಸಿಕೊಂಡು ಆರಂಭಿಕ ರಿಮೋಟ್ URL ಮತ್ತು ಪ್ರತಿ ಮರುನಿರ್ದೇಶನದಲ್ಲಿ HTTPS ಅಗತ್ಯವಿದೆ. ಬೈಟ್ಗಳು ನಂತರ ನಿಖರವಾದ ಆಂತರಿಕ `POST /api/modality-bridge/video/extract` ಬ್ರೋಕರ್ ಗಡಿಯನ್ನು ದಾಟುತ್ತವೆ. ಆ ಮಾರ್ಗವು `LOCAL_ONLY` ಮತ್ತು `SPAWN_CAPABLE` ಎರಡೂ ಆಗಿದೆ, ಪ್ರತಿ ಪ್ರಕ್ರಿಯೆಗೆ ದೃಢೀಕರಿಸಿದ, ವಿಶ್ವಾಸಾರ್ಹ-ಲೂಪ್ಬ್ಯಾಕ್ ವಿನಂತಿಯನ್ನು ಮಾತ್ರ ಸ್ವೀಕರಿಸುತ್ತದೆ ಮತ್ತು URL, ಫೈಲ್ಸಿಸ್ಟಮ್ ಮಾರ್ಗ, ಕಾರ್ಯಗತಗೊಳಿಸಬಹುದಾದ ಅಥವಾ ಆರ್ಗ್ಯುಮೆಂಟ್ ಪಟ್ಟಿಯನ್ನು ಎಂದಿಗೂ ಸ್ವೀಕರಿಸುವುದಿಲ್ಲ. API ದೇಹದ ಗಾತ್ರದ ಪೈಪ್ಲೈನ್ ಮತ್ತು ಹ್ಯಾಂಡ್ಲರ್ನ ಇನ್ಕ್ರಿಮೆಂಟಲ್ ಬಾಡಿ ರೀಡರ್ ಸ್ವತಂತ್ರವಾಗಿ 50 MiB ಬ್ರೋಕರ್ ಇನ್ಪುಟ್ ಕ್ಯಾಪ್ ಅನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತದೆ. ಅದರ ಬೌಂಡೆಡ್ ಕ್ಯೂ ಒಂದು ಸಮಯದಲ್ಲಿ ಒಂದು ಹೊರತೆಗೆಯುವಿಕೆಯನ್ನು ನಡೆಸುತ್ತದೆ, ನಾಲ್ಕು ಬಾಕಿಯಿರುವ ಕೆಲಸಗಳನ್ನು ಅನುಮತಿಸುತ್ತದೆ ಮತ್ತು 100 MiB ನಲ್ಲಿ ಬಾಕಿ ಉಳಿದಿರುವ ಇನ್ಪುಟ್ಗಳನ್ನು ಮುಚ್ಚುತ್ತದೆ.

ಬ್ರೋಕರ್ ಒಳಗೆ, `ffprobe` ಖಾಸಗಿ ಸ್ಥಳೀಯ ಫೈಲ್ ಅನ್ನು ಓದುತ್ತದೆ; ಸ್ಥಿರ ಸ್ವರೂಪದ ಅನುಮತಿ ಪಟ್ಟಿಯು ಪ್ಲೇಪಟ್ಟಿ ಮತ್ತು ಮ್ಯಾನಿಫೆಸ್ಟ್ ಸ್ವರೂಪಗಳನ್ನು ಹೊರತುಪಡಿಸುತ್ತದೆ. ಅನುಮತಿಸಲಾದ MOV-ಕುಟುಂಬ ಕಂಟೈನರ್ಗಳಿಗಾಗಿ, ಬಾಹ್ಯ MOV ಡೇಟಾ ಉಲ್ಲೇಖಗಳು ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ನಿಷ್ಕ್ರಿಯವಾಗಿರುತ್ತವೆ ಮತ್ತು ಸ್ಥಿರ ಆಜ್ಞೆಯು ಅವುಗಳನ್ನು ಆಯ್ಕೆ ಮಾಡುವುದಿಲ್ಲ. `ffprobe` ಮತ್ತು `ffmpeg` ಎರಡೂ `file` -only ಪ್ರೋಟೋಕಾಲ್ ಶ್ವೇತಪಟ್ಟಿ, ಒಂದು ಥ್ರೆಡ್, ಸ್ಥಿರ ಆರ್ಗ್ಯುಮೆಂಟ್ ಅರೇಗಳು, ಯಾವುದೇ ಶೆಲ್ ಮತ್ತು `PATH` ನಿಂದ ಪರಿಹರಿಸಲಾದ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಯನ್ನು ಬಳಸುತ್ತವೆ. ಲಗತ್ತಿಸಲಾದ-ಚಿತ್ರದ ಕವರ್ ಸ್ಟ್ರೀಮ್ಗಳು ಪ್ಲೇ ಮಾಡಬಹುದಾದ ಅಭ್ಯರ್ಥಿಗಳಲ್ಲ. ಎಲ್ಲಾ ಪ್ಲೇ ಮಾಡಬಹುದಾದ ಸ್ಟ್ರೀಮ್ಗಳು ಮಿತಿಗಳನ್ನು ಪೂರೈಸಬೇಕು ಮತ್ತು ನಿರ್ಣಾಯಕ ಕಡಿಮೆ-ಸೂಚ್ಯಂಕ ಫಾಲ್ಬ್ಯಾಕ್ಗೆ ಮೊದಲು ಸ್ಪಷ್ಟವಾದ ಡೀಫಾಲ್ಟ್ ಸ್ಟ್ರೀಮ್ ಅನ್ನು ಆದ್ಯತೆ ನೀಡಲಾಗುತ್ತದೆ. ವೀಡಿಯೊಗಳನ್ನು 600 ಸೆಕೆಂಡುಗಳು, ಪ್ರತಿ ಆಯಾಮಕ್ಕೆ 8,192 ಪಿಕ್ಸೆಲ್ಗಳು ಮತ್ತು 33,554,432 ಮೂಲ ಪಿಕ್ಸೆಲ್ಗಳಿಗೆ ಸೀಮಿತಗೊಳಿಸಲಾಗಿದೆ. FFmpeg ಮಾದರಿಗಳು 1–16 ಮಧ್ಯಬಿಂದು JPEG ಚೌಕಟ್ಟುಗಳು, ಸಣ್ಣ ಇನ್ಪುಟ್ಗಳನ್ನು ಹೆಚ್ಚಿಸದೆ ಉದ್ದದ ಅಂಚಿನಿಂದ 1,024 ಪಿಕ್ಸೆಲ್ಗಳಿಗೆ ಮಾಪಕಗಳು ಮತ್ತು ಎಂದಿಗೂ URL ಅನ್ನು ಸ್ವೀಕರಿಸುವುದಿಲ್ಲ. ಮಾದರಿಯು ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ `uniform` ಆಗಿದೆ. ಐಚ್ಛಿಕ `scene_aware` ಮತ್ತು ಪ್ರಾಯೋಗಿಕ `segment_aware` ನೀತಿಗಳು ಈಗಾಗಲೇ ಮೌಲ್ಯೀಕರಿಸಿದ ಸ್ಥಳೀಯ ಸ್ಟ್ರೀಮ್ನಲ್ಲಿ ಒಂದು ಹೆಚ್ಚುವರಿ ಸ್ಥಿರ FFmpeg ಪಾಸ್ ಅನ್ನು ನಿರ್ವಹಿಸುತ್ತವೆ, ಬೌಂಡೆಡ್ `showinfo` ದೃಶ್ಯ ಸಮಯಸ್ಟ್ಯಾಂಪ್ಗಳನ್ನು ಆಯ್ಕೆಮಾಡಿ, ಮತ್ತು ಡಿಟೆಕ್ಟರ್ ವೈಫಲ್ಯ, ಸಮಯ ಮೀರುವಿಕೆ, ಅಸಮರ್ಪಕ ಔಟ್ಪುಟ್ ಅಥವಾ ಖಾಲಿ ಅಭ್ಯರ್ಥಿ ಸೆಟ್ನಲ್ಲಿ ಅದೇ ಏಕರೂಪದ ಮಧ್ಯಬಿಂದುಗಳಿಗೆ ನಿರ್ಣಾಯಕವಾಗಿ ಹಿಂತಿರುಗುತ್ತವೆ. ಸೆಗ್ಮೆಂಟ್-ಅವೇರ್ ಮೋಡ್ ಮೌಲ್ಯೀಕರಿಸಿದ ದೃಶ್ಯ ಮಧ್ಯಂತರಗಳಿಗೆ ಅನುಗುಣವಾಗಿ ಮಧ್ಯಬಿಂದು ಮಾದರಿಗಳನ್ನು ನಿಯೋಜಿಸುತ್ತದೆ; ವಿಭಾಗದ ಅರಿವು ಪುರಾವೆಗಳು ಮತ್ತು ಹಿನ್ನಡೆ ನಡವಳಿಕೆಯನ್ನು ಕೆಳಗೆ ವಿವರಿಸಲಾಗಿದೆ. ಪ್ರತಿ ನೀತಿಯಲ್ಲಿ ಆಯ್ಕೆಯ ನಂತರ ಹಾರ್ಡ್ 16-ಫ್ರೇಮ್ ಕ್ಯಾಪ್ ಅನ್ನು ಅನ್ವಯಿಸಲಾಗುತ್ತದೆ. ದೃಶ್ಯ-ಅರಿವಿನ ವಿನಂತಿಯು ಕೇವಲ ಒಂದು-ಫ್ರೇಮ್ ಬಜೆಟ್ ಅನ್ನು ಹೊಂದಿರುವಾಗ, ಅದು ಸಕ್ರಿಯ ಪೂರ್ಣ-ವೀಡಿಯೊ ಅಥವಾ ಫೋಕಸ್ ವಿಂಡೋದ ಏಕರೂಪದ ಮಧ್ಯಬಿಂದುವನ್ನು ಬಳಸುತ್ತದೆ ಮತ್ತು `policyEffective: uniform` ವರದಿ ಮಾಡುತ್ತದೆ : ಒಂದೇ ಆಯ್ಕೆಮಾಡಿದ ದೃಶ್ಯ ಫ್ರೇಮ್ ಎರಡೂ ತಾತ್ಕಾಲಿಕ ತುದಿಗಳನ್ನು ಸಂರಕ್ಷಿಸುವುದಿಲ್ಲ. ಕರೆ ಮಾಡುವವರು ಐಚ್ಛಿಕವಾಗಿ ಸೀಮಿತ ಫೋಕಸ್ ವಿಂಡೋವನ್ನು ಒದಗಿಸಬಹುದು (`start`/`end` ಸೆಕೆಂಡುಗಳು); ಮಿತಿಗಳನ್ನು ಮಾಧ್ಯಮದ ಅವಧಿಗೆ ಕ್ಲ್ಯಾಂಪ್ ಮಾಡಲಾಗುತ್ತದೆ, ಹಿಮ್ಮುಖ ಅಥವಾ ಸೀಮಿತವಲ್ಲದ ವಿಂಡೋಗಳನ್ನು ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಎಲ್ಲಾ ಮಾದರಿ ನೀತಿಗಳನ್ನು ಸಾಮಾನ್ಯ ಮಧ್ಯಂತರದಲ್ಲಿ ಮಾತ್ರ ನಿರ್ವಹಿಸಲಾಗುತ್ತದೆ. ಫಲಿತಾಂಶದ ವಿಂಡೋವನ್ನು ಮಾದರಿ ಮೆಟಾಡೇಟಾದಲ್ಲಿ ಮತ್ತು ವಿಶ್ವಾಸಾರ್ಹವಲ್ಲದ ವಿವರಣೆ ಪೂರ್ವಪ್ರತ್ಯಯದಲ್ಲಿ ಸೇರಿಸಲಾಗಿದೆ ಆದ್ದರಿಂದ ಡೌನ್ಸ್ಟ್ರೀಮ್ ಮಾದರಿಗಳು ಪೂರ್ಣ ಟೈಮ್ಲೈನ್ನಿಂದ ಕೇಂದ್ರೀಕೃತ ಆಯ್ದ ಭಾಗವನ್ನು ಪ್ರತ್ಯೇಕಿಸಬಹುದು.

ಸೆಮ್ಯಾಂಟಿಕ್ ಶೀರ್ಷಿಕೆ ಫೋಕಸ್ ಪ್ರತ್ಯೇಕ, ಸ್ಪಷ್ಟ ಸೆಟ್ಟಿಂಗ್ ಆಗಿದೆ. ಡೀಫಾಲ್ಟ್ `full` ವಿಶ್ಲೇಷಣೆ ಮೋಡ್ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಫ್ರೇಮ್ ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ ಮತ್ತು ಶೀರ್ಷಿಕೆ ಮಾದರಿಗೆ ವಿನಂತಿ ಪಠ್ಯವನ್ನು ಎಂದಿಗೂ ಫಾರ್ವರ್ಡ್ ಮಾಡುವುದಿಲ್ಲ. `focused` ಮೋಡ್ನಲ್ಲಿ, ಸೇತುವೆಯು ಅದೇ ಚಾಟ್ ಅಥವಾ ರೆಸ್ಪಾನ್ಸ್ ಕಂಟೇನರ್ನಿಂದ ಇತ್ತೀಚಿನ ಖಾಲಿ-ಅಲ್ಲದ ಬಳಕೆದಾರ-ಲೇಖಿತ `text`/`input_text` ಅನ್ನು ಮಾತ್ರ ಓದುತ್ತದೆ, ಅದನ್ನು NFC ಗೆ ಸಾಮಾನ್ಯಗೊಳಿಸುತ್ತದೆ, ನಿಯಂತ್ರಣ ಅಕ್ಷರಗಳು ಮತ್ತು ವೈಟ್ಸ್ಪೇಸ್ ಅನ್ನು ಕುಗ್ಗಿಸುತ್ತದೆ ಮತ್ತು ಅದನ್ನು 500 ಯುನಿಕೋಡ್ ಕೋಡ್ ಪಾಯಿಂಟ್ಗಳಿಗೆ ಸೀಮಿತಗೊಳಿಸುತ್ತದೆ. ಖಾಲಿ ಫಲಿತಾಂಶವು ನಿಖರವಾದ `full` ಪ್ರಾಂಪ್ಟ್ಗೆ ಹಿಂತಿರುಗುತ್ತದೆ. ಬಳಸಬಹುದಾದ ಸುಳಿವನ್ನು ಮೀಸಲಾದ ವಿಶ್ವಾಸಾರ್ಹವಲ್ಲದ-ಬಳಕೆದಾರ-ಸಂದರ್ಭದ ಬ್ಲಾಕ್ನಲ್ಲಿ JSON ಎಂದು ಧಾರಾವಾಹಿ ಮಾಡಲಾಗಿದೆ ಮತ್ತು ಗಮನಿಸಬಹುದಾದ ವಿವರಗಳಿಗೆ ಮಾತ್ರ ಆದ್ಯತೆ ನೀಡಬಹುದು; ಇದು ಮಾಧ್ಯಮದಲ್ಲಿ ಗೋಚರಿಸುವ ಅಥವಾ ಕೇಳಬಹುದಾದ ಕೆಳಗಿನ ಸೂಚನೆಗಳ ವಿರುದ್ಧ ಪ್ರತ್ಯೇಕ ಎಚ್ಚರಿಕೆಯನ್ನು ಅತಿಕ್ರಮಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ. ಪಠ್ಯದ ಗಮನವು ಎಂದಿಗೂ `start`/`end` ಅನ್ನು ನಿರ್ಣಯಿಸುವುದಿಲ್ಲ ಅಥವಾ ತಾತ್ಕಾಲಿಕ ಮಾದರಿಯನ್ನು ಬದಲಾಯಿಸುವುದಿಲ್ಲ.

#### FU-07 ರಚನಾತ್ಮಕ ವಿಭಾಗದ ಪುರಾವೆ

`segment_aware` ಈಗಾಗಲೇ ಮೌಲ್ಯೀಕರಿಸಿದ ಸ್ಥಳೀಯ ವೀಡಿಯೊ ಸ್ಟ್ರೀಮ್ನಲ್ಲಿ ಒಂದು ಸೀಮಿತ ಪೂರ್ವ-ವಿಶ್ಲೇಷಣೆ ಪಾಸ್ ಅನ್ನು ಬಳಸುತ್ತದೆ. ಸ್ಥಿರ ಫಿಲ್ಟರ್ ಸರಪಳಿಯು ಮೊದಲು ಗರಿಷ್ಠ 320 ಪಿಕ್ಸೆಲ್ಗಳ ಅಗಲಕ್ಕೆ ಮಾಪಕವಾಗುತ್ತದೆ, ದೃಶ್ಯ ಬದಲಾವಣೆಗಳು ಮತ್ತು ಘನೀಕೃತ ಮಧ್ಯಂತರಗಳನ್ನು ಪತ್ತೆ ಮಾಡುತ್ತದೆ, ನಂತರ ಮಸುಕು, ಸರಾಸರಿ ಲುಮಾ ಮತ್ತು spatial/temporal ಮಾಹಿತಿಗಾಗಿ ಪ್ರತಿ ಸೆಕೆಂಡಿಗೆ 1 ಫ್ರೇಮ್ನಲ್ಲಿ ಮಾದರಿಗಳನ್ನು ನೀಡುತ್ತದೆ. ಪಾಸ್ 600 ರಚನಾತ್ಮಕ ಮಾದರಿಗಳಿಗೆ ಸೀಮಿತವಾಗಿದೆ, ಒಂದು FFmpeg/filter ಥ್ರೆಡ್, ಅದೇ `file` -only ಪ್ರೋಟೋಕಾಲ್ ಮತ್ತು ಕಂಟೈನರ್ ಅನುಮತಿ ಪಟ್ಟಿಗಳು, 1 MiB ಪ್ರಕ್ರಿಯೆ-ಔಟ್ಪುಟ್ ಬೌಂಡ್, ಮತ್ತು ಬ್ರೋಕರ್ನ ಹಂಚಿಕೆಯ abort/deadline. ಒಳಗೆ ಹೆಚ್ಚೆಂದರೆ 30 ಸೆಕೆಂಡುಗಳು ಇದು ವಿನಂತಿಯಿಂದ ಆಜ್ಞೆ, ಫಿಲ್ಟರ್, ಮಾರ್ಗ ಅಥವಾ URL ಎಂದಿಗೂ ಸ್ವೀಕರಿಸುವುದಿಲ್ಲ.

ರಚನಾತ್ಮಕ ಮೌಲ್ಯಗಳು ನಿರ್ಣಾಯಕ ಮಾದರಿ ಸಾಕ್ಷ್ಯಗಳಾಗಿವೆ, ಶಬ್ದಾರ್ಥದ ವೀಡಿಯೊ ತಿಳುವಳಿಕೆ ಅಲ್ಲ. ಅವರು ವಿಷಯಗಳು, ಕ್ರಿಯೆಗಳು, ಶೀರ್ಷಿಕೆಗಳು, ಮಾತು ಅಥವಾ ಬಳಕೆದಾರರ ಉದ್ದೇಶವನ್ನು ಊಹಿಸುವುದಿಲ್ಲ. ದೃಶ್ಯ ಮತ್ತು ಫ್ರೀಜ್ ಗಡಿಗಳು ಭಾಗಗಳನ್ನು ರೂಪಿಸುತ್ತವೆ; ಫ್ರೀಜ್ ಕವರೇಜ್, ಮಸುಕು, ಮಾನ್ಯತೆ, ಪ್ರಾದೇಶಿಕ ವಿವರ ಮತ್ತು ತಾತ್ಕಾಲಿಕ ಬದಲಾವಣೆಯು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ 1–16 ಫ್ರೇಮ್ ಬಜೆಟ್ ಅನ್ನು ಹೇಗೆ ನಿಗದಿಪಡಿಸಲಾಗಿದೆ ಎಂಬುದನ್ನು ಮಾತ್ರ ಪ್ರಭಾವಿಸುತ್ತದೆ. ಸಂಪೂರ್ಣ ಹೆಪ್ಪುಗಟ್ಟಿದ ವಿಭಾಗವನ್ನು ಒಂದು ಚೌಕಟ್ಟಿನಲ್ಲಿ ಮುಚ್ಚಲಾಗುತ್ತದೆ, ಆದರೆ ಫ್ರೀಜ್ ಅಲ್ಲದ ವಿಭಾಗಗಳು ಉಳಿದ ಬಜೆಟ್ಗಾಗಿ ಸ್ಪರ್ಧಿಸುತ್ತವೆ. ಗಡಿಗಳು ಚೌಕಟ್ಟುಗಳನ್ನು ಮೀರಿದಾಗ, ಏಕರೂಪದ ಟೈಮ್ಲೈನ್ ಕವರೇಜ್ ಅನ್ನು ಉಳಿಸಿಕೊಳ್ಳಲಾಗುತ್ತದೆ ಆದ್ದರಿಂದ ತ್ವರಿತ ಆರಂಭಿಕ ಕಡಿತಗಳು ದೀರ್ಘವಾದ ಹಿಂದುಳಿದ ಭಾಗವನ್ನು ಮರೆಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ. ಫ್ರೀಜ್ ಬೌಂಡರಿಯ 1-ಸೆಕೆಂಡ್ ವಿಶ್ಲೇಷಣಾ ರೆಸಲ್ಯೂಶನ್ನೊಳಗೆ ದೃಶ್ಯದ ಗಡಿಗಳನ್ನು ಒಟ್ಟುಗೂಡಿಸಲಾಗುತ್ತದೆ.

ಕಾಣೆಯಾದ ಫಿಲ್ಟರ್ಗಳು, malformed/empty ಪುರಾವೆಗಳು, ಡಿಟೆಕ್ಟರ್ ದೋಷ ಅಥವಾ ಬೌಂಡೆಡ್ ಪೂರ್ವ-ವಿಶ್ಲೇಷಣೆಯ ಅವಧಿಯು ನಿಖರವಾದ ಏಕರೂಪದ ಮಧ್ಯಬಿಂದು ನೀತಿಗೆ ತೆರೆದುಕೊಳ್ಳಲು ವಿಫಲವಾಗಿದೆ. ಕರೆ ಮಾಡುವವರ ಸ್ಥಗಿತ ಅಥವಾ ಬ್ರೋಕರ್ ಗಡುವು ತೆರೆಯಲು ವಿಫಲವಾಗುವುದಿಲ್ಲ: ಇದು ವಿಮಾನದಲ್ಲಿನ ಉಪಪ್ರಕ್ರಿಯೆಯನ್ನು ಕೊನೆಗೊಳಿಸುತ್ತದೆ, ನಂತರ ಫ್ರೇಮ್ ಹೊರತೆಗೆಯುವುದನ್ನು ತಡೆಯುತ್ತದೆ ಮತ್ತು ಖಾಸಗಿ ತಾತ್ಕಾಲಿಕ ಮರವನ್ನು `finally` ನಲ್ಲಿ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ.

`scripts/perf/video-bridge-fu07-eval.ts` ಪೋಸ್ಟ್-ಡೆಡಪ್ ಶೀರ್ಷಿಕೆ-ಕರೆ ಉಳಿತಾಯ, ದಟ್ಟ-ಚಲನೆಯ ಬಜೆಟ್ ಹಂಚಿಕೆ, blur/exposure/SI-TI ಪುರಾವೆಗಳು, ಉದ್ದನೆಯ ಬಾಲದೊಂದಿಗೆ ಕ್ಷಿಪ್ರ ಕಡಿತ ಮತ್ತು ಕ್ರಮೇಣ-ಫೇಡ್ ತಪ್ಪು ಧನಾತ್ಮಕತೆಗಳಿಗಾಗಿ ನಿರ್ಣಾಯಕ ನೈಜ FFmpeg ಫಿಕ್ಚರ್ಗಳನ್ನು ಉತ್ಪಾದಿಸುತ್ತದೆ. ಇದು ಪೂರ್ವ-ವಿಶ್ಲೇಷಣೆಯ ಗೋಡೆಯ ಸಮಯವನ್ನು ದಾಖಲಿಸುತ್ತದೆ ಮತ್ತು `/usr/bin/time` ಲಭ್ಯವಿರುವಲ್ಲಿ, ಚೈಲ್ಡ್ CPU ಮತ್ತು ಪೀಕ್ RSS. ಇದರ ಗುಣಮಟ್ಟದ ಪರಿಶೀಲನೆಗಳು ರಚನಾತ್ಮಕ ಒರಾಕಲ್ಗಳು ಮಾತ್ರ. ನಿಜವಾದ ಶೀರ್ಷಿಕೆ-ಮಾದರಿ ಗುಣಮಟ್ಟವು `HOLD` ಉಳಿದಿದೆ ಏಕೆಂದರೆ ಈ ಸರಂಜಾಮು ಯಾವುದೇ ಅಧಿಕೃತ ಅಂತ್ಯಬಿಂದು ಅಥವಾ ಫ್ರೀಜ್ ಜಡ್ಜ್ ಅನ್ನು ಹೊಂದಿಲ್ಲ. `--caption-cost-per-call-usd` ಪ್ರತಿ ಕರೆಗೆ ಸ್ಪಷ್ಟವಾದ ಧನಾತ್ಮಕ ಅಂದಾಜನ್ನು ಒದಗಿಸದ ಹೊರತು ವಿತ್ತೀಯ ಉಳಿತಾಯವು `HOLD` ಆಗಿರುತ್ತದೆ; ಸ್ಕ್ರಿಪ್ಟ್ ಎಂದಿಗೂ ಫಲಿತಾಂಶವನ್ನು ರೂಪಿಸುವುದಿಲ್ಲ.

ಪ್ರತಿ ಫ್ರೇಮ್ 4 MiB ಗೆ ಸೀಮಿತವಾಗಿದೆ, ಎಲ್ಲಾ ಕಚ್ಚಾ ಚೌಕಟ್ಟುಗಳು ಒಟ್ಟಿಗೆ 23 MiB ಗೆ ಮತ್ತು 32 MiB ಗೆ ಸರಣಿ ಬ್ರೋಕರ್ ಪ್ರತಿಕ್ರಿಯೆ. ಖಾಸಗಿ ತಾತ್ಕಾಲಿಕ ಡೈರೆಕ್ಟರಿಯನ್ನು `finally` ನಲ್ಲಿ ತೆಗೆದುಹಾಕಲಾಗಿದೆ. OmniRoute FFmpeg ಬಂಡಲ್ ಮಾಡುವುದಿಲ್ಲ ಮತ್ತು ಕಸ್ಟಮ್ ಕಾರ್ಯಗತಗೊಳಿಸಬಹುದಾದ ಮಾರ್ಗವನ್ನು ಸ್ವೀಕರಿಸುವುದಿಲ್ಲ. ಶೀರ್ಷಿಕೆ ನೀಡುವ ಮೊದಲು, ಸೇತುವೆಯು ಒಂದು ಸಂಪ್ರದಾಯವಾದಿ ದೃಶ್ಯ ಡೀಪ್ಲಿಕೇಶನ್ ಪಾಸ್ ಅನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ: ಪ್ರತಿ JPEG 16 × 16 ಗ್ರೇಸ್ಕೇಲ್ ಬಫರ್ಗೆ ಇಳಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಕೊನೆಯ ಫ್ರೇಮ್ ಉಳಿಸಿಕೊಂಡಿರುವುದರೊಂದಿಗೆ ಮಾತ್ರ ಹೋಲಿಸಲಾಗುತ್ತದೆ. ಒಂದು ಚೌಕಟ್ಟಿನ ಮೇಲಿರುವ ವಿನಂತಿಸಿದ ಶೀರ್ಷಿಕೆ ಬಜೆಟ್ಗಾಗಿ, ಹೊರತೆಗೆಯುವಿಕೆಯು ಬಜೆಟ್ಗಿಂತ ಎರಡು ಪಟ್ಟು ಮಿತಿಮೀರಿದ ಅಭ್ಯರ್ಥಿ ಪೂಲ್ ಅನ್ನು ಪೂರೈಸುತ್ತದೆ ಮತ್ತು 16 ಫ್ರೇಮ್ಗಳಿಗಿಂತ ಹೆಚ್ಚಿಲ್ಲ. ವಿನಂತಿಸಿದ ಕ್ಯಾಪ್ ಅನ್ನು ನಕಲು ಮಾಡಿದ ನಂತರ ಮಾತ್ರ ಅನ್ವಯಿಸಲಾಗುತ್ತದೆ, ಬಜೆಟ್ ಕನಿಷ್ಠ ಎರಡು ಆಗಿರುವಾಗ ಅಂತಿಮ ತೆಳುಗೊಳಿಸುವಿಕೆಯ ಸಮಯದಲ್ಲಿ ಮೊದಲ ಮತ್ತು ಅಂತಿಮ ಆಯ್ಕೆ ಮಾಡಿದ ಅಭ್ಯರ್ಥಿಗಳನ್ನು ಸಂರಕ್ಷಿಸಲಾಗುತ್ತದೆ. ಆವೃತ್ತಿಯ `grayscale-16x16-mean-cells-v2` ನೀತಿಯು ದೊಡ್ಡದಾದ ಸರಾಸರಿ ಲುಮಾ ಡೆಲ್ಟಾ ಮತ್ತು ಥಂಬ್ನೇಲ್ ಕೋಶಗಳ ಅನುಪಾತವನ್ನು ಬಳಸುತ್ತದೆ, ಅದರ ಸಾಮಾನ್ಯ ಡೆಲ್ಟಾ ಕನಿಷ್ಠ 0.05 ಆಗಿದೆ. ನಕಲು ಥ್ರೆಶೋಲ್ಡ್ ಸ್ಥಿರ 0.04 ಆಗಿದ್ದು, ರನ್ಟೈಮ್ ಸೆಟ್ಟಿಂಗ್ನಂತೆ ಬಹಿರಂಗಪಡಿಸುವ ಬದಲು ಊಹಿಸಲು ಆಯ್ಕೆಮಾಡಲಾಗಿದೆ. ಈ ಸೆಕೆಂಡರಿ ಹೈ-ಕಾಂಟ್ರಾಸ್ಟ್ ಸಿಗ್ನಲ್ ಸಣ್ಣ ಚಲನೆ ಮತ್ತು ಗೋಚರ-ಪಠ್ಯ ಬದಲಾವಣೆಗಳನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ, ಅದು ಸರಾಸರಿ-ಮಾತ್ರ ಹೋಲಿಕೆ ಮರೆಮಾಡಬಹುದು. ಹೋಲಿಕೆದಾರ ಅಥವಾ ಡಿಕೋಡರ್ ದೋಷಗಳು ವಿಫಲಗೊಳ್ಳುತ್ತವೆ ಮತ್ತು ಕವರೇಜ್ ಅನ್ನು ಇರಿಸುತ್ತವೆ. ಔಟ್ಪುಟ್ ಮೆಟಾಡೇಟಾ ಬೇರ್ಪಡಿಸಿದ ಅಭ್ಯರ್ಥಿಗಳನ್ನು ಪ್ರತ್ಯೇಕಿಸುತ್ತದೆ, ಯಶಸ್ವಿಯಾಗಿ ಬಳಸಿದ ಫ್ರೇಮ್ಗಳು ಮತ್ತು ದೃಶ್ಯ ನಕಲುಗಳನ್ನು ಕೈಬಿಡಲಾಗಿದೆ.

ಸ್ಪಷ್ಟವಾಗಿ ಗುರುತಿಸಲಾದ ವೀಡಿಯೊ ಭಾಗವು ಟೈಮ್ಸ್ಟ್ಯಾಂಪ್ ಮಾಡಿದ ಸಂಪರ್ಕ ಹಾಳೆಯನ್ನು ವಿನಂತಿಸಬಹುದು. ಸೇತುವೆಯು ಹೆಚ್ಚೆಂದರೆ 4-ಕಾಲಮ್, 16-ಫ್ರೇಮ್ JPEG ಗ್ರಿಡ್ ಅನ್ನು ನಿರ್ಮಿಸುತ್ತದೆ. ಪ್ರತಿ 512-ಪಿಕ್ಸೆಲ್ ಸೆಲ್ ತನ್ನ ಮೂಲ ಟೈಮ್ಸ್ಟ್ಯಾಂಪ್ ಅನ್ನು ಹೈ-ಕಾಂಟ್ರಾಸ್ಟ್ ಬಾಟಮ್ ಬ್ಯಾಂಡ್ಗೆ ಬರ್ನ್ ಮಾಡುತ್ತದೆ, ಅದೇ ಟೈಮ್ಸ್ಟಾಂಪ್ಗಳು ಡೌನ್ಸ್ಟ್ರೀಮ್ ಅಸೋಸಿಯೇಷನ್ ಮತ್ತು ಆಡಿಟ್ಗಾಗಿ ಪಠ್ಯ ಮೆಟಾಡೇಟಾದಲ್ಲಿ ಉಳಿಯುತ್ತವೆ. ಸಂಪೂರ್ಣ JPEG 32 MiB ನಲ್ಲಿ ಮುಚ್ಚಲ್ಪಟ್ಟಿದೆ. `sharp` ಗ್ರಿಡ್ ಅನ್ನು ಡಿಕೋಡ್ ಮಾಡಲು ಅಥವಾ ಸಂಯೋಜಿಸಲು ಸಾಧ್ಯವಾಗದಿದ್ದರೆ, ಸೇತುವೆಯು ಪ್ರತ್ಯೇಕ JPEG ಫ್ರೇಮ್ಗಳಿಗೆ ಹಿಂತಿರುಗುತ್ತದೆ; ಕ್ಲೈಂಟ್ ಸ್ಥಗಿತಗೊಳಿಸುವಿಕೆಯು ಇನ್ನೂ ಶೀಟ್ ಕಾರ್ಯಾಚರಣೆಯ ಮೂಲಕ ಹರಡುತ್ತದೆ.

ಪ್ರಚಾರದ ಸಾಕ್ಷ್ಯವು ಸಂಶ್ಲೇಷಿತ ಸಂಯೋಜನೆಯ ಮೈಕ್ರೋಬೆಂಚ್ಮಾರ್ಕ್ನಿಂದ ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಪ್ರತ್ಯೇಕವಾಗಿದೆ. `scripts/perf/video-bridge-contact-sheet-eval.ts` ನೈಜ OpenAI-ಹೊಂದಾಣಿಕೆಯ ದೃಷ್ಟಿ ಮಾದರಿಗಳಿಗಾಗಿ ಸ್ಕೀಮಾ-ಆವೃತ್ತಿಯ A/B ಸರಂಜಾಮುಗಳನ್ನು ವ್ಯಾಖ್ಯಾನಿಸುತ್ತದೆ. ಇದು ಒದಗಿಸುವವರು-ವರದಿ ಮಾಡಿದ ಟೋಕನ್ಗಳು, ಎಂಡ್-ಟು-ಎಂಡ್ ವಾಲ್ ಲೇಟೆನ್ಸಿ (ಶೀಟ್ ಸಂಯೋಜನೆ ಸೇರಿದಂತೆ), ಮಾದರಿ-ಕರೆ ಎಣಿಕೆ ಮತ್ತು ಮ್ಯಾನಿಫೆಸ್ಟ್-ವ್ಯಾಖ್ಯಾನಿತ ಸತ್ಯ ಧಾರಣವನ್ನು ಅಳೆಯುತ್ತದೆ. ಕಚ್ಚಾ ಮಾದರಿಯ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ವರದಿಗೆ ಬರೆಯಲಾಗಿಲ್ಲ; ಕೇವಲ SHA-256 ಡೈಜೆಸ್ಟ್ಗಳು ಮತ್ತು ಹೊಂದಾಣಿಕೆಯ ಫ್ಯಾಕ್ಟ್ IDs ಅನ್ನು ಉಳಿಸಿಕೊಳ್ಳಲಾಗಿದೆ. `--execute-real` ರವಾನಿಸದ ಹೊರತು ಮತ್ತು `--model`, `OMNIROUTE_BASE_URL`, ಮತ್ತು `OMNIROUTE_API_KEY` ಕಾನ್ಫಿಗರ್ ಮಾಡದ ಹೊರತು ಸರಂಜಾಮು ಯಾವುದೇ ನೆಟ್ವರ್ಕ್ ಅಥವಾ ಪಾವತಿಸಿದ ಮಾದರಿ ಕರೆಯನ್ನು ಮಾಡುವುದಿಲ್ಲ. ಸ್ಪಷ್ಟವಾದ ನೈಜ ಓಟವಿಲ್ಲದೆ, ಅದರ ಯಂತ್ರ-ಓದಬಲ್ಲ ತೀರ್ಪು `HOLD` ಆಗಿ ಉಳಿಯುತ್ತದೆ; ಸಂಶ್ಲೇಷಿತ payload/call-count ಮಾಪನಗಳು ಮಾತ್ರ ಪ್ರಚಾರದ ಸಾಕ್ಷ್ಯವಲ್ಲ.

ಕರೆದಾರರು ಈಗಾಗಲೇ ಜೋಡಿಸಲಾದ ಪಠ್ಯವನ್ನು ಹೊಂದಿರುವಾಗ ಬೆಂಬಲಿತ ವೀಡಿಯೊ ಭಾಗಕ್ಕೆ ಐಚ್ಛಿಕ `transcript.cues` ರಚನೆಯನ್ನು ಲಗತ್ತಿಸಬಹುದು. ಪ್ರತಿ ಕ್ಯೂ `text` ಹೊಂದಿರಬೇಕು, ತನಿಖೆಯ ಅವಧಿಯೊಳಗೆ ಒಂದು ಸೀಮಿತ `start`/`end` ಮಧ್ಯಂತರ, ಮತ್ತು ಶ್ವೇತಪಟ್ಟಿ ಮಾಡಲಾದ `source` (`client`, `embedded`, ಅಥವಾ `audio-bridge`); `confidence` ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ `1` ಮತ್ತು `0` ಮತ್ತು `1` ನಡುವೆ ಉಳಿಯಬೇಕು. ನಿಖರವಾದ ನಕಲು ಸೂಚನೆಗಳನ್ನು ಕುಗ್ಗಿಸಲಾಗಿದೆ. OmniRoute ಈ ಮೆಟಾಡೇಟಾದಿಂದ ಪ್ರತಿಲೇಖನವನ್ನು ಎಂದಿಗೂ ಪ್ರಾರಂಭಿಸುವುದಿಲ್ಲ: ಮೌಲ್ಯೀಕರಿಸಿದ ಸೂಚನೆಗಳನ್ನು ವಿವರಿಸಿದ ಫಲಿತಾಂಶಕ್ಕೆ ಮೂಲ, ವಿಶ್ವಾಸ ಮತ್ತು ಮಧ್ಯಂತರದೊಂದಿಗೆ ನಕಲಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಫ್ರೇಮ್ ಶೀರ್ಷಿಕೆಗಳ ಜೊತೆಗೆ ವಿಶ್ವಾಸಾರ್ಹವಲ್ಲದ ವೀಕ್ಷಣೆಗಳಾಗಿ ಸಲ್ಲಿಸಲಾಗುತ್ತದೆ. ಶೀರ್ಷಿಕೆ ಸ್ಟ್ರೀಮ್ನಲ್ಲಿ ಬೆರೆಸುವ ಬದಲು ಅಮಾನ್ಯ, ವ್ಯಾಪ್ತಿಯಿಂದ ಹೊರಗಿರುವ ಅಥವಾ ಮೂಲ-ಮುಕ್ತ ಪಠ್ಯವನ್ನು ತಿರಸ್ಕರಿಸಲಾಗಿದೆ. ಎರಡೂ ವಿನಂತಿ-ದೇಹ ಪ್ರತಿಲೇಖನ ಚಾನಲ್ಗಳು ಸ್ವಯಂ-ದೃಢೀಕರಿಸಿದ `embedded` ಅಥವಾ `audio-bridge` ಲೇಬಲ್ಗಳನ್ನು ಒಳಗೊಂಡಂತೆ `client` ಗೆ ಸರಬರಾಜು ಮಾಡಿದ ಮೂಲವನ್ನು ಸಾಮಾನ್ಯಗೊಳಿಸುತ್ತವೆ. ಕೋಡ್-ಮಾತ್ರ `trustedSource` ಆರ್ಗ್ಯುಮೆಂಟ್ ಮೂಲಕ ಸರ್ವರ್-ಮಾಲೀಕತ್ವದ ಅಡಾಪ್ಟರ್ ಮಾತ್ರ ಆ ವಿಶ್ವಾಸಾರ್ಹ ಲೇಬಲ್ಗಳನ್ನು ನಿಯೋಜಿಸಬಹುದು; ವಿನಂತಿಯ JSON ಕ್ಷೇತ್ರವು ಆ ವಾದವನ್ನು ತಲುಪಲು ಸಾಧ್ಯವಿಲ್ಲ. ಪ್ರತಿಲೇಖನ ಪಠ್ಯವು ಅದರ ಮೂಲವನ್ನು ಲೆಕ್ಕಿಸದೆಯೇ ವಿಶ್ವಾಸಾರ್ಹವಲ್ಲದ ಮಾಧ್ಯಮದಿಂದ ಪಡೆದ ವಿಷಯವಾಗಿ ಉಳಿದಿದೆ ಮತ್ತು ದೃಢೀಕರಣವನ್ನು ಎಂದಿಗೂ ನಿರ್ಧರಿಸಬಾರದು.

ಮುಂದುವರಿದ ಕರೆ ಮಾಡುವವರು ಅದೇ ವೀಡಿಯೊಗಾಗಿ `audioTranscript` ಟ್ರ್ಯಾಕ್ ಅನ್ನು ಒದಗಿಸಬಹುದು; ಇದನ್ನು ಕ್ಲೈಂಟ್ ಒದಗಿಸಿದ ಪಠ್ಯವೆಂದು ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ, ಸರ್ವರ್ ಪ್ರತಿಲೇಖನದ ಪುರಾವೆಯಾಗಿಲ್ಲ. ಸಮ್ಮಿಳನ ಸೀಮ್ ಒಂದು ಗಡುವಿನ ಅಡಿಯಲ್ಲಿ ದೃಶ್ಯ ಮತ್ತು ಆಡಿಯೊ ವೀಕ್ಷಣೆಗಳನ್ನು ನಡೆಸುತ್ತದೆ ಮತ್ತು ಸಿಗ್ನಲ್ ಅನ್ನು ಸ್ಥಗಿತಗೊಳಿಸುತ್ತದೆ, ಅವುಗಳನ್ನು ಸಾಮಾನ್ಯ ಟೈಮ್ಲೈನ್ನಲ್ಲಿ ಆದೇಶಿಸುತ್ತದೆ, ನಿಖರವಾದ ನಕಲುಗಳನ್ನು ಕುಗ್ಗಿಸುತ್ತದೆ ಮತ್ತು ಒಂದು ಕಡೆ ಮಾತ್ರ ಯಶಸ್ವಿಯಾದಾಗ ಭಾಗಶಃ ಫಲಿತಾಂಶವನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ. ಅಮಾನ್ಯವಾದ `audioTranscript` ಆ ಭಾಗಶಃ ಫಲಿತಾಂಶವನ್ನು — ಗೆ ಡಿಗ್ರೇಡ್ ಮಾಡುತ್ತದೆ ದೃಶ್ಯ ವಿವರಣೆಯನ್ನು ಇರಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಆಡಿಯೊ ಶಾಖೆಯು ಸಂಪೂರ್ಣ ವೀಡಿಯೊವನ್ನು ವಿಫಲಗೊಳಿಸುವ ಬದಲು ಸ್ಯಾನಿಟೈಸ್ ಮಾಡಿದ ವೈಫಲ್ಯ ಕೋಡ್ — ಅನ್ನು ರೆಕಾರ್ಡ್ ಮಾಡುತ್ತದೆ. ಪ್ರತಿ ಶಾಖೆಯ ಲಭ್ಯತೆ, ಭಾಗಶಃ ಧ್ವಜ ಮತ್ತು ಶುಚಿಗೊಳಿಸಲಾದ ವೈಫಲ್ಯ ಸಂಕೇತಗಳನ್ನು ವಿವರಿಸಿದ ಫಲಿತಾಂಶದಲ್ಲಿ, ಗಾರ್ಡ್ರೈಲ್ ಮೆಟಾಡೇಟಾದಲ್ಲಿ (`audioFusionRuns`/`audioFusionPartials`/ `audioFusionFailureCodes`), ಫಲಿತಾಂಶ-ಕ್ಯಾಶ್ ಮೆಟಾಡೇಟಾದಲ್ಲಿ ಮತ್ತು ಸೇತುವೆಯ ಫ್ಯೂಷನ್ ಕೌಂಟರ್ಗಳಲ್ಲಿ ಸಂರಕ್ಷಿಸಲಾಗಿದೆ. ಡೀಫಾಲ್ಟ್ ವೀಡಿಯೊ ಸೇತುವೆ ಮಾರ್ಗವು ಭಾಷಣದಿಂದ ಪಠ್ಯವನ್ನು ಆಹ್ವಾನಿಸುವುದಿಲ್ಲ ಅಥವಾ ಎರಡನೇ ಮಾಧ್ಯಮ ನಕಲನ್ನು ಡೌನ್ಲೋಡ್ ಮಾಡುವುದಿಲ್ಲ; ಸ್ಪಷ್ಟವಾದ ಟ್ರ್ಯಾಕ್ ಇಲ್ಲದೆ, ಅದು ವೀಡಿಯೊ-ಮಾತ್ರವಾಗಿ ಉಳಿದಿದೆ.

**ಪ್ರತಿಲೇಖನ ಧಾರಣ (#12150 P1).** ವೀಡಿಯೊ ಬ್ರಿಡ್ಜ್ (ಸ್ವತಃ ಆಪ್ಟ್-ಇನ್) ಟ್ರಾನ್ಸ್ಕ್ರಿಪ್ಟ್ ಕ್ಯೂ — ಸಲ್ಲಿಸಿದಾಗ ಇದು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಅನ್ವಯಿಸುತ್ತದೆ ಯಾವುದೇ ಪ್ರತ್ಯೇಕ ಧಾರಣ ಫ್ಲ್ಯಾಗ್ ಇಲ್ಲ. ವಿನಂತಿಯು ಯಾವುದೇ ಪ್ರತಿಲೇಖನ ಕ್ಯೂ ಅನ್ನು ಸಲ್ಲಿಸಿದಾಗ (ಕಾಲರ್-ಘೋಷಿತ `transcript` ಅಥವಾ ಸಮ್ಮಿಳನಗೊಂಡ `audioTranscript`), ಗಾರ್ಡ್ರೈಲ್ ಅದನ್ನು `videoBridgeObserved` ಗುರುತಿಸುತ್ತದೆ ಮತ್ತು ವೀಡಿಯೊ ವಿವರಣೆಯ — ನ ಮರುರೂಪಿಸಲಾದ ನೆರಳು ಉತ್ಪಾದಿಸುತ್ತದೆ, ಇದರಲ್ಲಿ ಪ್ರತಿ ಕ್ಯೂನ ಉಚಿತ-ಪಠ್ಯ ದೇಹವನ್ನು `[redacted-video-transcript]` ರಚನೆಯ ಮೊದಲು ನಿರ್ಮಿಸಿದ ರಚನೆಯಿಂದ ಬದಲಾಯಿಸಲಾಗುತ್ತದೆ. ಜೋಡಿಸಲಾಗಿದೆ (ಚಪ್ಪಟೆಯಾದ ಪಠ್ಯವನ್ನು ಪಾರ್ಸ್ ಮಾಡುವ ಮೂಲಕ ಎಂದಿಗೂ, ಆದ್ದರಿಂದ `[inaudible]`/`[music]` — ನಂತಹ `]` ಹೊಂದಿರುವ ದೇಹಗಳನ್ನು ಒಳಗೊಂಡಂತೆ ಯಾವುದೇ ಕ್ಯೂ ವಿಷಯ — ಎದುರಾಳಿ ಅಥವಾ ಸಾಮಾನ್ಯ ಉಳಿಯುವುದಿಲ್ಲ). ನಿರಂತರ ಕರೆ-ಲಾಗ್ ವಿನಂತಿಯ ದೇಹವು ಪ್ರತಿ ವೀಡಿಯೊ-ಉತ್ಪನ್ನ ಪಠ್ಯ ಭಾಗವನ್ನು ಆ ಪರಿಷ್ಕೃತ ನೆರಳುಗೆ ಬದಲಾಯಿಸುತ್ತದೆ, ವಿಷಯ ಸಮಾನತೆಯಿಂದ ಹೊಂದಾಣಿಕೆಯಾಗುತ್ತದೆ; `fullText` ಆಂಕರ್ ಅನ್ನು ಮುಗಿದ ಪೂರ್ವ-ಕಾಲ್ ಗಾರ್ಡ್ರೈಲ್ ಪೇಲೋಡ್ನಿಂದ ಮರು-ಓದಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ನಂತರದ ಚೈನ್ ಗಾರ್ಡ್ರೈಲ್ಗಳು ( PII ಮತ್ತು ರುಜುವಾತು ಮಾಸ್ಕರ್ಗಳು, ಆದ್ಯತೆಗಳು 10/95) ವಿವರಣೆ ಪಠ್ಯವನ್ನು ಸ್ಥಳದಲ್ಲಿ ಪುನಃ ಬರೆಯುವ ನಂತರ ಮತ್ತು system-prompt/handoff/memory ಇಂಜೆಕ್ಷನ್ ನಂತರ ಸಂದೇಶ ರಚನೆಯನ್ನು ಮರುರೂಪಿಸಿದ ನಂತರ ಪಂದ್ಯವು ಯಶಸ್ವಿಯಾಗುತ್ತದೆ. ಮಾದರಿಗೆ ಅಪ್ಸ್ಟ್ರೀಮ್ಗೆ ಕಳುಹಿಸಲಾದ ದೇಹವು ಬದಲಾಗಿಲ್ಲ. ಗಮನಿಸಿದ ವಿನಂತಿಯು ಯಾವುದೇ ಬಾಳಿಕೆ ಬರುವ ಮೆಮೊರಿಯನ್ನು ಸಹ ಜನಪ್ರಿಯಗೊಳಿಸುವುದಿಲ್ಲ (ವಿನಂತಿ- ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆ-ಪಡೆದ ಹೊರತೆಗೆಯುವಿಕೆ ಎರಡನ್ನೂ ಬಿಟ್ಟುಬಿಡಲಾಗಿದೆ), ಆದ್ದರಿಂದ ಮಾದರಿಯ ಸ್ವಂತ ಉತ್ತರವು ಪ್ರತಿಲೇಖನ ಪಠ್ಯವನ್ನು ಮೆಮೊರಿಗೆ ಪ್ರತಿಧ್ವನಿಸುವುದಿಲ್ಲ.

**ಕಚ್ಚಾ ವೀಡಿಯೊ ಕ್ಷೇತ್ರಗಳು (#12430).** ಸೇತುವೆಯನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿದಾಗ ಮತ್ತು ಸ್ಥಳೀಯ ವೀಡಿಯೊ ಬೆಂಬಲವು ಅಜ್ಞಾತ ಅಥವಾ ಇಲ್ಲದಿದ್ದಾಗ, ವ್ಯಾಖ್ಯಾನಿಸಲಾದ `transcript`/`audioTranscript` ಕ್ಷೇತ್ರಗಳು ಸಹ `videoBridgeObserved` ಸಕ್ರಿಯಗೊಳಿಸುತ್ತವೆ, ವಿವರಣೆ ವೈಫಲ್ಯ ಅಥವಾ `maxVideos` ಮಿತಿಯ ನಂತರವೂ ಸಹ. `null` ಮತ್ತು ಖಾಲಿ ತಂತಿಗಳ ಎಣಿಕೆ; ಗೈರು ಕ್ಷೇತ್ರಗಳು ಮತ್ತು ವೀಡಿಯೊ ಅಲ್ಲದ ಮೆಟಾಡೇಟಾ ಇಲ್ಲ. ಉಳಿಸಿಕೊಂಡಿರುವ ನಕಲುಗಳು ಈ ಕ್ಷೇತ್ರಗಳನ್ನು ಸರಿಪಡಿಸುತ್ತವೆ ಅಥವಾ ವಿನಂತಿಯನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತವೆ ಮತ್ತು caches/Memory ಬೈಪಾಸ್ ಮಾಡಲಾಗುತ್ತದೆ.

ಆ ಫಾಲ್ಬ್ಯಾಕ್ ಪಥಗಳಲ್ಲಿ, ಮಾನ್ಯ ಕಾಲರ್ ಸೂಚನೆಗಳು ಪ್ರಮಾಣಿತವಲ್ಲದ ಪೂರೈಕೆದಾರರ ಕ್ಷೇತ್ರಗಳಿಗಿಂತ ಹೆಚ್ಚಾಗಿ ಬೆಂಬಲಿತ `text`/`input_text` ಭಾಗಗಳಾಗಿವೆ. ಎರಡೂ ವಿನಂತಿ-ಸರಬರಾಜು ಮಾಡಿದ ಟ್ರ್ಯಾಕ್ಗಳು ವಿಶ್ವಾಸಾರ್ಹವಲ್ಲದ `client` ಅವಲೋಕನಗಳಾಗಿ ಉಳಿದಿವೆ, ವೀಡಿಯೊವನ್ನು ವಿವರಿಸಲಾಗಿಲ್ಲ ಮತ್ತು ಮಾಧ್ಯಮದ ವಿರುದ್ಧ ಟೈಮ್ಸ್ಟ್ಯಾಂಪ್ಗಳನ್ನು ಪರಿಶೀಲಿಸಲಾಗಿಲ್ಲ ಎಂಬ ಸ್ಪಷ್ಟ ಎಚ್ಚರಿಕೆಯೊಂದಿಗೆ. ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ 256-cue/64-KiB ಒಟ್ಟು ಮತ್ತು ಪ್ರತಿ ಕ್ಯೂ ಬಜೆಟ್ಗಳು ಎರಡು ಟ್ರ್ಯಾಕ್ಗಳಲ್ಲಿ ಒಟ್ಟಿಗೆ ಅನ್ವಯಿಸುತ್ತವೆ; ಟೈಮ್ಸ್ಟ್ಯಾಂಪ್ಗಳು ಬ್ರೋಕರ್ನ 600-ಸೆಕೆಂಡ್ ಸೀಲಿಂಗ್ ಮತ್ತು ಯಾವುದೇ ಸರಬರಾಜು ಮಾಡಿದ ಫೋಕಸ್ ವಿಂಡೋಗೆ ಸರಿಹೊಂದಬೇಕು. ಅಮಾನ್ಯವಾದ ಟ್ರ್ಯಾಕ್ಗಳನ್ನು ತಿರಸ್ಕರಿಸಲಾಗಿದೆ, ಅನಿಯಂತ್ರಿತ ಪಠ್ಯವಾಗಿ ಫಾರ್ವರ್ಡ್ ಮಾಡಲಾಗಿಲ್ಲ; ಅವರ ಸಂಯೋಜಿತ ಬಜೆಟ್ ಮೀರದ ಹೊರತು ಮಾನ್ಯ ಒಡಹುಟ್ಟಿದವರನ್ನು ಇನ್ನೂ ಬಳಸಬಹುದು. Null/empty ಕ್ಷೇತ್ರಗಳು ಯಾವುದೇ ಪಠ್ಯವನ್ನು ಸೇರಿಸುವುದಿಲ್ಲ. ಈ ಫಾಲ್ಬ್ಯಾಕ್ನಿಂದ ಯಾವುದೇ ಮಾಧ್ಯಮ ಪಡೆಯುವಿಕೆ ಅಥವಾ ಪ್ರತಿಲೇಖನವನ್ನು ಸೇರಿಸಲಾಗಿಲ್ಲ. ಫಾಲ್ಬ್ಯಾಕ್ ವೀಡಿಯೊ ಕ್ಯಾರಿಯರ್ ಮತ್ತು ಅದರ `video_url`/`source` ಆಬ್ಜೆಕ್ಟ್ಗಳಿಂದ ಪ್ರತಿಲೇಖನ ವಿಸ್ತರಣೆ ಕ್ಷೇತ್ರಗಳನ್ನು ತೆಗೆದುಹಾಕಲಾಗಿದೆ. OpenAI ವೈರ್ ಅನುಮತಿ ಪಟ್ಟಿಯು ಕಟ್ಟುನಿಟ್ಟಾಗಿರುತ್ತದೆ; ಅಜ್ಞಾತ-ಸ್ಥಳೀಯ ವೀಡಿಯೊ ವಾಹಕಗಳು ಲಭ್ಯವಿರುತ್ತವೆ ಮತ್ತು ತಿಳಿದಿರುವ ಪಠ್ಯ-ಮಾತ್ರ ಗುರಿಗಳು ಸುರಕ್ಷಿತ ಗುರುತುಗಳನ್ನು ಇರಿಸುತ್ತವೆ. ರಚನಾತ್ಮಕ ರಿಡಕ್ಷನ್ ನೆರಳುಗಳು ಲಗತ್ತಿಸಲಾದ ಪ್ರತಿಲೇಖನ ಪಠ್ಯವನ್ನು ರಕ್ಷಿಸುತ್ತವೆ, ಆದರೆ ಮೂಲ ಕರೆ ಮಾಡುವವರ ಮಾಲೀಕತ್ವದ ವಿನಂತಿಯು ಬದಲಾಗದೆ ಉಳಿಯುತ್ತದೆ. ಸ್ಥಳೀಯ-ಬೆಂಬಲಿತ ಗುರಿಗಳು ಮತ್ತು ಅಂಗವಿಕಲ ಸೇತುವೆಗಳು ತಮ್ಮ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಬೈಪಾಸ್ ನಡವಳಿಕೆಯನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ.

ಹೆಚ್ಚುವರಿ ಉಳಿಸಿಕೊಂಡಿರುವ ಪ್ರತಿಗಳು ಅದೇ ಗಮನಿಸಿದ-ವಿನಂತಿ ಸಂಕೇತವನ್ನು ಬಳಸುತ್ತವೆ. ಕಚ್ಚಾ ಪ್ರಿ-ಗಾರ್ಡ್ರೈಲ್ ಕ್ಲೈಂಟ್-ವಿನಂತಿಯ ಸ್ನ್ಯಾಪ್ಶಾಟ್, ಇನ್-ಮೆಮೊರಿ ಬಾಕಿ ಉಳಿದಿರುವ ವಿನಂತಿ ಮತ್ತು ಆರಂಭಿಕ ತಿರಸ್ಕರಿಸಿದ ವಿನಂತಿ ಲಾಗ್ ವೀಡಿಯೊ ಭಾಗಗಳಲ್ಲಿ ಪ್ರತಿಲೇಖನ ಕ್ಷೇತ್ರಗಳನ್ನು ರಚನಾತ್ಮಕವಾಗಿ ಬದಲಾಯಿಸುತ್ತದೆ; ಪೈಪ್ಲೈನ್ ಹಂತಗಳಿಂದ ಸಂಶ್ಲೇಷಿಸಲಾದ ಸ್ಟ್ರಿಂಗ್ ಪ್ರಾಂಪ್ಟ್ಗಳು ಮತ್ತು ಕಾಂಟೆಕ್ಸ್ಟ್ ಹ್ಯಾಂಡ್ಆಫ್ ಅನ್ನು ನಿರಂತರ ವಿನಂತಿ-ಬಾಡಿ ಸಿಂಕ್ನಲ್ಲಿ ಮರುರೂಪಿಸಲಾಗುತ್ತದೆ. ನಿರಂತರವಾದ `video_content_removed` ಮಾರ್ಕರ್ ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ತಿರಸ್ಕರಿಸಿದ ಪಠ್ಯವನ್ನು ಮರುನಿರ್ಮಾಣ ಮಾಡುವ ಬದಲು `previous_response_id` ಮುಂದುವರಿಕೆ ವಿಫಲಗೊಳ್ಳುತ್ತದೆ. ಗಮನಿಸಿದ ವಿನಂತಿಯು ಲಾಗಿಂಗ್ ಮಾಡುವ ಮೊದಲು ಅದರ ಪ್ರತಿ-ಭಾಗದ ರಿಡಕ್ಷನ್ ನೆರಳು ಕಳೆದುಕೊಂಡರೆ ಅಥವಾ ನಂತರದ ವಿನಂತಿಯ ರೂಪಾಂತರಗಳ ನಂತರ ಹಲವಾರು ವೀಡಿಯೊ ನೆರಳುಗಳು ಹೊಂದಿಕೆಯಾಗಲು ವಿಫಲವಾದರೆ, ಭಾಗಶಃ ಪರಿಷ್ಕರಿಸಿದ ಪ್ರತಿಲೇಖನವನ್ನು ಉಳಿಸಿಕೊಳ್ಳುವ ಬದಲು ಉಳಿಸಿದ ವಿನಂತಿಯ ದೇಹವನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ.

ಗಮನಿಸಿದ ವಿನಂತಿಗಾಗಿ, ಮಾದರಿಯ ಪ್ರತಿಕ್ರಿಯೆಯು ರಚನಾತ್ಮಕ ಕ್ಯೂ ಗಡಿರೇಖೆಯಿಲ್ಲದೆ ಪ್ರತಿಲೇಖನದ ಯಾವುದೇ ಭಾಗವನ್ನು ಉಲ್ಲೇಖಿಸಬಹುದು. ಆದ್ದರಿಂದ ಅದರ ನಿರಂತರ ಕರೆ-ಲಾಗ್ `responseBody` ಅನ್ನು ಲೋಪ ಮಾರ್ಕರ್ನಿಂದ ಬದಲಾಯಿಸಲಾಗುತ್ತದೆ; ವಿವರವಾದ ಪೈಪ್ಲೈನ್ ಕಲಾಕೃತಿಯನ್ನು (ಇದು upstream/client ದೇಹಗಳು ಮತ್ತು ಸ್ಟ್ರೀಮ್ ಭಾಗಗಳನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ) ಉಳಿಸಿಕೊಂಡಿಲ್ಲ. ಸೆಮ್ಯಾಂಟಿಕ್, ಐಡೆಂಪೊಟೆನ್ಸಿ ಮತ್ತು ತಾರ್ಕಿಕ-ಮರುಪಂದ್ಯ ಸಂಗ್ರಹಗಳು ಆ ವಿನಂತಿಗಾಗಿ ಓದುವುದನ್ನು ಮತ್ತು ಬರೆಯುವುದನ್ನು ಬೈಪಾಸ್ ಮಾಡುತ್ತವೆ. ಪೂರೈಕೆದಾರರ ವಿನಂತಿ ಮತ್ತು ಕ್ಲೈಂಟ್-ಗೋಚರ ಪ್ರತಿಕ್ರಿಯೆಯು ಬದಲಾಗದೆ ಉಳಿಯುತ್ತದೆ. ವಿವರವಾದ ಕಲಾಕೃತಿಯನ್ನು ಬಿಟ್ಟುಬಿಟ್ಟಾಗ ತಾತ್ಕಾಲಿಕ ಬಫರ್ನಿಂದ ಆರಂಭಿಕ ಕೀಪಲೈವ್ ಬೈಟ್ಗಳನ್ನು ಬರಿದುಮಾಡಲಾಗುತ್ತದೆ. Kiro ನ ದೋಷಪೂರಿತ EventStream ಎಚ್ಚರಿಕೆಯು ಪೇಲೋಡ್ ಬೈಟ್ ಎಣಿಕೆಯನ್ನು ಮಾತ್ರ ವರದಿ ಮಾಡುತ್ತದೆ, ಅದರ ವಿಷಯಗಳು ಅಥವಾ JSON ಪಾರ್ಸರ್ನ ಕಚ್ಚಾ ದೋಷವನ್ನು ಎಂದಿಗೂ ವರದಿ ಮಾಡುವುದಿಲ್ಲ. ಪ್ರತಿ ಸಂಬಂಧವಿಲ್ಲದ provider/plugin ರೋಗನಿರ್ಣಯವನ್ನು ಆಡಿಟ್ ಮಾಡಲಾಗಿದೆ ಎಂದು ಇದು ಹೇಳಿಕೊಳ್ಳುವುದಿಲ್ಲ; ವಿಶಾಲವಾದ ಉಳಿಸಿಕೊಂಡಿರುವ-ಸಿಂಕ್ ಸ್ವೀಪ್ ಅನ್ನು #11658 ರಲ್ಲಿ ಟ್ರ್ಯಾಕ್ ಮಾಡಲಾಗಿದೆ.

ಆಂತರಿಕ `/api/modality-bridge/video/drilldown` ಜೀವನಚಕ್ರವು ಪ್ರತ್ಯೇಕ, loopback/token-authenticated ಸಂಗ್ರಹ ತಲಾಧಾರವಾಗಿದೆ. ಪ್ರತಿ ಕಾರ್ಯಾಚರಣೆಗೆ ಅಂಗೀಕೃತ ಅಪಾರದರ್ಶಕ ಪ್ರಧಾನ ID ಅಗತ್ಯವಿರುತ್ತದೆ. ಪ್ರೊಡಕ್ಷನ್ ಕಾಲರ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸುವ ಮೊದಲು, ಅದು ಆ ID ದೃಢೀಕರಿಸಿದ ಹಿಡುವಳಿದಾರರಿಂದ ಪಡೆಯಬೇಕು ಮತ್ತು ಕ್ಲೈಂಟ್-ಆಯ್ಕೆ ಮಾಡಿದ ಮೌಲ್ಯವನ್ನು ಎಂದಿಗೂ ಫಾರ್ವರ್ಡ್ ಮಾಡಬಾರದು. ಕ್ಯಾಶ್ ಕೀಗಳು ಆ ಪ್ರಿನ್ಸಿಪಾಲ್ ಅನ್ನು ಕ್ಯಾನೊನಿಕಲ್ ಸೆಶನ್ ಮತ್ತು ವೀಡಿಯೋ-ರೆಫರೆನ್ಸ್ IDs ಗೆ ಬಂಧಿಸುತ್ತವೆ, ಅವುಗಳ SHA-256-derived ಕೀಗಳನ್ನು ಮಾತ್ರ ಸಂಗ್ರಹಿಸುತ್ತವೆ ಮತ್ತು ಅದೇ ಪ್ರಿನ್ಸಿಪಲ್ಗೆ ಓದುವಿಕೆ ಮತ್ತು ಅಳಿಸುವಿಕೆ ಎರಡನ್ನೂ ಸ್ಕೋಪ್ ಮಾಡುತ್ತದೆ. ಸಂಗ್ರಹವು ಪ್ರತಿ ಪ್ರವೇಶಕ್ಕೆ 16 ವ್ಯುತ್ಪನ್ನ JPEG ಫ್ರೇಮ್ಗಳನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ, ಹತ್ತು ನಿಮಿಷಗಳ ನಂತರ ಅವುಗಳನ್ನು ಮುಕ್ತಾಯಗೊಳಿಸುತ್ತದೆ ಮತ್ತು ಮಿತಿಗೊಳಿಸಿದ `start`/`end` ರೀಡ್ಗಳು ಅಥವಾ ಸ್ಪಷ್ಟವಾದ ಅಧಿವೇಶನ ಅಳಿಸುವಿಕೆಯನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ.

ಪ್ರತಿ ಪ್ರಧಾನವು 16 ನಮೂದುಗಳಿಗೆ ಮತ್ತು 64 MiB ಅಂಗೀಕೃತ JPEG ಡೇಟಾಗೆ ಸೀಮಿತವಾಗಿದೆ. ಆ ಮಿತಿಗಳು ಜಾಗತಿಕ 64-entry/256 MiB ಸೀಲಿಂಗ್ನಿಂದ ಸ್ವತಂತ್ರವಾಗಿವೆ: ಜಾಗತಿಕ LRU ಹೊರಹಾಕುವ ಮೊದಲು ಪ್ರಿನ್ಸಿಪಾಲ್ನ ಕನಿಷ್ಠ-ಇತ್ತೀಚೆಗೆ ಬಳಸಿದ ನಮೂದುಗಳನ್ನು ಮಾತ್ರ ಪ್ರಧಾನ ಕೋಟಾ ಒತ್ತಡವು ಹೊರಹಾಕುತ್ತದೆ. ಅವಧಿ ಮೀರಿದ ನಮೂದುಗಳನ್ನು ಕ್ಯಾಶ್ ಚಟುವಟಿಕೆಯ ಮೇಲೆ ಪ್ರಧಾನ ಮತ್ತು ಜಾಗತಿಕ ಲೆಕ್ಕಪತ್ರ ನಿರ್ವಹಣೆ ಎರಡರಿಂದಲೂ ಸ್ವೀಪ್ ಮಾಡಲಾಗುತ್ತದೆ, ಆದರೆ ರದ್ದುಗೊಳಿಸುವಿಕೆ ಮತ್ತು ಮೌಲ್ಯೀಕರಣದ ವೈಫಲ್ಯವು ಭಾಗಶಃ ಬದಲಿಯನ್ನು ಮಾಡುವುದಿಲ್ಲ.

ಕ್ಯಾನೊನಿಕಲ್ ಅಲ್ಲದ Base64, ಹೆಚ್ಚುವರಿ ಪ್ಯಾಡಿಂಗ್, JPEG ಅಲ್ಲದ ಮಾಧ್ಯಮ, ಅಸಮರ್ಪಕ ಅಥವಾ ಮೊಟಕುಗೊಳಿಸಿದ JPEGs, ಮತ್ತು JPEGs ಅನ್ನು ತಿರಸ್ಕರಿಸುತ್ತದೆ ಅದು ಬೌಂಡಡ್ ಪೂರ್ಣ-ಇಮೇಜ್ `sharp` ಡಿಕೋಡ್ ಸಮಯದಲ್ಲಿ ಎಚ್ಚರಿಕೆಯನ್ನು ನೀಡುತ್ತದೆ. ಇದು ಪ್ರತಿ ಸ್ವೀಕರಿಸಿದ ಚಿತ್ರವನ್ನು ಅಂಗೀಕೃತ JPEG ಎಂದು ಮರು-ಎನ್ಕೋಡ್ ಮಾಡುತ್ತದೆ, ಕಾಲರ್ ಕ್ಷೇತ್ರಗಳನ್ನು ನಂಬುವ ಬದಲು ಡಿಕೋಡ್ ಮಾಡಿದ ಬೈಟ್ಗಳಿಂದ ಅಗಲ ಮತ್ತು ಎತ್ತರವನ್ನು ಪಡೆಯುತ್ತದೆ ಮತ್ತು ಅವುಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳುವ ಬದಲು ಯಾವುದೇ ಹಿಂದುಳಿದ ಪಾಲಿಗ್ಲಾಟ್ ಬೈಟ್ಗಳನ್ನು ತಿರಸ್ಕರಿಸುತ್ತದೆ. ಬೌಂಡೆಡ್ ಕ್ಯಾನೊನಿಕಲ್ ಸಂಕುಚಿತ ಬಫರ್ ಅನ್ನು ಮಾತ್ರ ಎರಡೂ ಕೋಟಾಗಳಿಗೆ ವಿಧಿಸಲಾಗುತ್ತದೆ. JSON ವೈರ್ ಮಿತಿಯು 32 MiB ಡಿಕೋಡ್-ಇನ್ಪುಟ್ ಸೀಲಿಂಗ್ಗಾಗಿ Base64 ಓವರ್ಹೆಡ್ ಅನ್ನು ಒಳಗೊಂಡಿದೆ. ಪ್ರತಿ ಸಂಗ್ರಹಿಸಲಾದ ವ್ಯುತ್ಪನ್ನವು ಅದರ ಮೌಲ್ಯೀಕರಿಸಿದ JPEG format/resolution, ಮಾದರಿ ನೀತಿ, ವ್ಯುತ್ಪನ್ನ ಆವೃತ್ತಿ, ರಚನೆಯ ಸಮಯ, ಸರ್ವರ್-ಕಂಪ್ಯೂಟೆಡ್ ವಿಷಯ ಹ್ಯಾಶ್, ಮತ್ತು ಹ್ಯಾಶ್ಡ್ ಪೋಷಕ ಉಲ್ಲೇಖ ಮತ್ತು ವಿಶ್ವಾಸಾರ್ಹ ಕರೆ ಮಾಡುವವರ ಪೋಷಕ-ವಿಷಯ ಹ್ಯಾಶ್ ಅನ್ನು ದಾಖಲಿಸುತ್ತದೆ. ಪರಮಾಣು ಸಂಗ್ರಹದ ಮೊದಲು ಅಸಮಕಾಲಿಕ decode/hash ಹಂತಗಳ ನಡುವೆ ರದ್ದುಗೊಳಿಸುವಿಕೆಯನ್ನು ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ.

ಈ ಭಾಗವು ಇನ್ನೂ ಉತ್ಪಾದನಾ ನಿರ್ಮಾಪಕರನ್ನು ಮಾರ್ಗಕ್ಕೆ ಸಂಪರ್ಕಿಸಿಲ್ಲ ಮತ್ತು ಬಹು-ರೆಸಲ್ಯೂಶನ್ ರೂಪಾಂತರದ ಆಯ್ಕೆಯನ್ನು ಒದಗಿಸುವುದಿಲ್ಲ. ಆದ್ದರಿಂದ ಪಾರದರ್ಶಕ ವೀಡಿಯೋ ಬ್ರಿಡ್ಜ್ ವಿನಂತಿ ಮಾರ್ಗವು ಯಾವುದೇ ಸೇರ್ಪಡೆ ಕಾರ್ಯವನ್ನು ಹೊಂದಿರುವುದಿಲ್ಲ, ಆದರೆ ಬಾಡಿಗೆದಾರ-ಬೌಂಡ್ ಪ್ರಿನ್ಸಿಪಲ್ ವ್ಯುತ್ಪನ್ನ ಮತ್ತು ಪೂರ್ಣ FU-08 ಬಹು-ರೆಸಲ್ಯೂಶನ್ ಜೀವನಚಕ್ರವು ಸಂಪೂರ್ಣ ನಡವಳಿಕೆಯಾಗಿ ದಾಖಲಿಸಲ್ಪಡುವ ಬದಲು ಸ್ಪಷ್ಟವಾದ ಅನುಸರಣಾ ಕೆಲಸವಾಗಿ ಉಳಿಯುತ್ತದೆ.

Frames are captioned sequentially with the configured Video model. An empty Video override inherits the Vision setting; if both are empty, the Vision auto-router selects the effective vision-capable model. Successful captions replace the original part with a stable `[Video description:` prefix that also marks the text as an untrusted media-derived observation and tells downstream models not to follow instructions found in the media. Frame-caption cache keys include the JPEG bytes, prompt, timestamp, and effective model; only successful captions are cached. Cache entries retain the actual successful producer model, including a fallback model; the bridge reports `mixed` when different frames were produced by different models. A cache hit reuses that producer identity instead of relabeling it as the requested routing plan. The whole-video result cache is keyed on every input that changes the output — prompt, effective model, sampling policy, frame count, semantic analysis mode, the SHA-256 fingerprint of the normalized focus hint, focus window, `transcript`, `audioTranscript`, and the contact-sheet flag — so changing any of those dimensions is a cache miss, never a stale reuse. The visual dedup policy version, threshold, and bounded candidate-frame count are also explicit in the result-cache key and metadata; a policy change therefore cannot reuse a stale whole-video description. Result-cache v4 metadata keeps the mode and fingerprint, never the raw user task. Guardrail metadata reports both the requested and effective analysis modes; a requested `focused` mode without usable user text is reported as effectively `full`.

Guardrail ಪ್ರತಿ ಬೆಂಬಲಿತ ವೀಡಿಯೊ ಭಾಗವನ್ನು ಹೊರತೆಗೆಯುತ್ತದೆ ಆದರೆ `modalityBridgeVideoMaxVideos` ಗಿಂತ ಹೆಚ್ಚಿನದನ್ನು ವಿವರಿಸುವುದಿಲ್ಲ. `supportsVideo === false` ಎಂದು ಸಾಬೀತಾಗಿರುವ ಗುರಿಗಾಗಿ, ವಿಫಲವಾದ ಮತ್ತು ಮಿತಿಮೀರಿದ ವೀಡಿಯೊಗಳು ಸ್ಪಷ್ಟವಾದ ಸುರಕ್ಷಿತ ಪಠ್ಯ ಗುರುತುಗಳಾಗುತ್ತವೆ ಆದ್ದರಿಂದ ಯಾವುದೇ ಕಚ್ಚಾ ವೀಡಿಯೊ ಉಳಿದಿಲ್ಲ. ಸಾಮರ್ಥ್ಯ ತಿಳಿದಿಲ್ಲದಿದ್ದಾಗ, ಆ ಭಾಗಗಳು ತಮ್ಮ ವೀಡಿಯೊ ವಾಹಕವನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ; ಯಾವುದೇ ಫಾಲ್ಬ್ಯಾಕ್ ಪ್ರತಿಲೇಖನವು ಮೇಲಿನ ಬೌಂಡೆಡ್ ಪಠ್ಯ ಪರಿವರ್ತನೆಯನ್ನು ಅನುಸರಿಸುತ್ತದೆ. `supportsVideo === true` ಯೊಂದಿಗಿನ ಗುರಿಗಳು ಸೇತುವೆಯನ್ನು ಬೈಪಾಸ್ ಮಾಡುತ್ತದೆ. ಕ್ಲೈಂಟ್ ವಿನಂತಿಯು ಸ್ಥಗಿತಗೊಳಿಸುವ ಸಂಕೇತವನ್ನು ಡೌನ್ಲೋಡ್, ಬ್ರೋಕರ್ ಕ್ಯೂ, ಉಪಪ್ರಕ್ರಿಯೆಗಳು ಮತ್ತು ಶೀರ್ಷಿಕೆ ಕರೆಗಳ ಮೂಲಕ ಪ್ರಚಾರ ಮಾಡುತ್ತದೆ; ಸ್ಥಗಿತಗೊಳಿಸುವಿಕೆಗಳು ವೀಡಿಯೊಗಳ ನಡುವೆ ನಿಲ್ಲುತ್ತವೆ ಮತ್ತು ಕಚ್ಚಾ ಮಾಧ್ಯಮಕ್ಕೆ ಎಂದಿಗೂ ವಿಫಲವಾಗುವುದಿಲ್ಲ.

ಲೆಗಸಿ ನಿರಂತರ ವೀಡಿಯೊ 120 ಸೆಕೆಂಡ್ಗಳಿಗಿಂತ ಹೆಚ್ಚಿನ ಅವಧಿ ಮೀರುವ ಮೌಲ್ಯಗಳನ್ನು ಬ್ರೋಕರ್ ಡೆಡ್ಲೈನ್ಗೆ ಕ್ಲ್ಯಾಂಪ್ ಮಾಡಲಾಗಿದೆ; ಆ ಮಿತಿಗಿಂತ ಹೆಚ್ಚಿನ ಹೊಸ ಸೆಟ್ಟಿಂಗ್ಗಳನ್ನು ಬರೆಯುವುದನ್ನು ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ. `GET /api/modality-bridge/video/runtime` ದೃಢೀಕರಣ ಅಥವಾ ರನ್ಟೈಮ್ ಪ್ರೋಬಿಂಗ್ ಮೊದಲು ವಿಶ್ವಾಸಾರ್ಹ ಸ್ಟ್ಯಾಂಪ್ಡ್ ಲೂಪ್ಬ್ಯಾಕ್ ಸ್ಥಳದ ಅಗತ್ಯವಿದೆ, ನಂತರ ನಿರ್ವಹಣೆ ದೃಢೀಕರಣದ ಅಗತ್ಯವಿರುತ್ತದೆ. ಇದು `available`, ಸ್ಯಾನಿಟೈಸ್ ಮಾಡಿದ FFmpeg/ffprobe ಆವೃತ್ತಿಗಳು ಮತ್ತು ರನ್ಟೈಮ್ ಲಭ್ಯವಿಲ್ಲದಿದ್ದಾಗ ಸ್ಥಿರ ಕಾರಣವನ್ನು ಮಾತ್ರ ಹಿಂತಿರುಗಿಸುತ್ತದೆ. ಆಂತರಿಕ ಹೊರತೆಗೆಯುವಿಕೆಯ ಅಂತಿಮ ಬಿಂದುವು ಸಾರ್ವಜನಿಕ ಅಪ್ಲೋಡ್ API ಅಲ್ಲ: ಕ್ಯೂ ಸ್ಯಾಚುರೇಶನ್ `503` ಜೊತೆಗೆ `Retry-After` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ, ಕರೆ ಮಾಡುವವರು `499` ಹಿಂದಿರುಗಿಸುತ್ತದೆ ಮತ್ತು ಸ್ಥಿರ ಬ್ರೋಕರ್ ಗಡುವು `504` ಹಿಂದಿರುಗಿಸುತ್ತದೆ. ಪರಿವರ್ತಿತ ಪ್ರತಿಕ್ರಿಯೆಗಳು ದೃಷ್ಟಿ ಅಥವಾ ಆಡಿಯೊ ವಿಭಾಗಗಳನ್ನು ತೆಗೆದುಹಾಕದೆಯೇ ಕೇಂದ್ರ `x-omniroute-modality-bridge` ಹೆಡರ್ಗೆ `video->text;model=<visionModel>;parts=<videos>` ಸೇರಿಸುತ್ತವೆ.

### PII ಮಾಸ್ಕರ್ (`piiMasker.ts`)

ಚಾಲನೆಯಲ್ಲಿದೆ** ಎರಡೂ** ಹಂತಗಳು.

- **`preCall`** ಪೇಲೋಡ್ ಅನ್ನು ಕ್ಲೋನ್ ಮಾಡುತ್ತದೆ, `system`, `messages`, `input`, ಮತ್ತು `prompt` (ಸಾದಾ ಸ್ಟ್ರಿಂಗ್ ಐಟಂಗಳನ್ನು ಒಳಗೊಂಡಂತೆ), ಮತ್ತು `processPII()` ( `@/shared/utils/inputSanitizer` ನಿಂದ) ಸ್ಟ್ರಿಂಗ್ `content`/`text` ಕ್ಷೇತ್ರಗಳಿಗೆ ಅನ್ವಯಿಸುತ್ತದೆ. ಯಾವಾಗ `PII_REDACTION_ENABLED=true`, ಪತ್ತೆಯಾದ PII ಅನ್ನು ಹೊರಹೋಗುವ ಪೇಲೋಡ್ನಲ್ಲಿ ಮರುರೂಪಿಸಲಾಗುತ್ತದೆ. ಇದು `INPUT_SANITIZER_MODE` ನಿಂದ ಸ್ವತಂತ್ರವಾಗಿದೆ (ಇದು ಪ್ರಾಂಪ್ಟ್-ಇಂಜೆಕ್ಷನ್ ನೀತಿಯನ್ನು ಮಾತ್ರ ನಿಯಂತ್ರಿಸುತ್ತದೆ). ರಿಡಕ್ಷನ್ ಆಫ್ ಆಗಿರುವಾಗ, ಕರೆ ರೆಕಾರ್ಡ್ ಡಿಟೆಕ್ಷನ್ ಎಣಿಕೆಗಳು ವಿಷಯವನ್ನು ಪುನಃ ಬರೆಯದೆಯೇ.
- **`postCall`** ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಆಳವಾಗಿ ತದ್ರೂಪುಗೊಳಿಸುತ್ತದೆ, `sanitizePIIResponse()` ಜೊತೆಗೆ ಪ್ರತಿಕ್ರಿಯೆಗಳು-API-ಆಕಾರದ ಮಾಸ್ಕರ್ ಅನ್ನು ರನ್ ಮಾಡುತ್ತದೆ (`maskResponsesOutput` — `output_text` ಮತ್ತು `output[].content[].text` ಅನ್ನು ಆವರಿಸುತ್ತದೆ). ಯಾವುದೇ ಕಡಿತ ಸಂಭವಿಸಿದಲ್ಲಿ, ಮಾರ್ಪಡಿಸಿದ ಪ್ರತಿಕ್ರಿಯೆಯು ಮೂಲವನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ.

ಗಾರ್ಡ್ರೈಲ್ ಎಂದಿಗೂ ನಿರ್ಬಂಧಿಸುವುದಿಲ್ಲ; ಇದು ಕೇವಲ ಟಿಪ್ಪಣಿಗಳನ್ನು (`meta.detections`, `meta.redacted`) ಅಥವಾ ಪುನಃ ಬರೆಯುತ್ತದೆ.

#### ಪ್ರತಿ-ಪ್ರಕಾರದ ಆಯ್ಕೆ, ಕಸ್ಟಮ್ ಮಾದರಿಗಳು ಮತ್ತು ಪತ್ತೆ ಕೌಂಟರ್ಗಳು

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಸೆಟ್ಟಿಂಗ್ಗಳು → ಭದ್ರತೆ → PII ಮರೆಮಾಚುವಿಕೆ** _ಯಾವುದು_ ಮುಖವಾಡವನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತದೆ. ಇದು ಮರೆಮಾಚುವಿಕೆಯನ್ನು ಆನ್ ಮಾಡುವುದಿಲ್ಲ: ಅದು ಇನ್ನೂ `PII_REDACTION_ENABLED` (ವಿನಂತಿ) ಮತ್ತು `PII_RESPONSE_SANITIZATION` (ಪ್ರತಿಕ್ರಿಯೆ + SSE), ಎರಡೂ ಡೀಫಾಲ್ಟ್ ಆಗಿ ಆಫ್ ಆಗಿದೆ.

- **ಪ್ರತಿ ಪ್ರಕಾರದ ಆಯ್ಕೆ** — ಅಂತರ್ನಿರ್ಮಿತ ಐಡಿಗಳನ್ನು `src/shared/constants/piiTypes.ts` (`PII_BUILTIN_TYPES`) ನಲ್ಲಿ ಪಟ್ಟಿ ಮಾಡಲಾಗಿದೆ. ಹೊಂದಿಸದಿರುವುದು ಎಂದರೆ ಪ್ರತಿ ಪ್ರಕಾರ (ಈ ಸೆಟ್ಟಿಂಗ್ ಅಸ್ತಿತ್ವದಲ್ಲಿದ್ದ ಹಿಂದಿನ ನಡವಳಿಕೆ). ವಿನಂತಿ ಎಂಜಿನ್ನ `ssn_us` ಮಾದರಿಯು `ssn` ಗೆ ನಕ್ಷೆ ಮಾಡುತ್ತದೆ. ಟೆಂಪ್ಲೇಟ್ಗಳು (ಕನಿಷ್ಠ, ಪ್ರಮಾಣಿತ, ಹಣಕಾಸು, ಬ್ರೆಜಿಲಿಯನ್, USA, GDPR, POPIA, ಪೂರ್ಣ) UI ನಲ್ಲಿ ಚೆಕ್ಬಾಕ್ಸ್ಗಳನ್ನು ಮಾತ್ರ ತುಂಬುತ್ತವೆ.
- **GDPR ಮತ್ತು POPIA ಗುರುತಿಸುವಿಕೆಗಳು** EU ಮತ್ತು ದಕ್ಷಿಣ ಆಫ್ರಿಕಾದ ವೈಯಕ್ತಿಕ ಗುರುತಿಸುವಿಕೆಗಳನ್ನು ಒಳಗೊಂಡಿರುವ — ಹನ್ನೆರಡು ಅಂತರ್ನಿರ್ಮಿತ ಐಡಿಗಳು (ಕೆಳಗಿನ ಕೋಷ್ಟಕ). ಅವರ ರಿಜೆಕ್ಸ್ಗಳು, ವ್ಯಾಲಿಡೇಟರ್ಗಳು ಮತ್ತು ನ್ಯಾಯವ್ಯಾಪ್ತಿಯ ಟ್ಯಾಗ್ಗಳು ಒಂದು ಟೇಬಲ್ನಲ್ಲಿ ವಾಸಿಸುತ್ತವೆ, `src/shared/utils/piiPatterns.ts`, ಇದು ಪ್ರತಿಕ್ರಿಯೆ ಸ್ಯಾನಿಟೈಸರ್ (`src/lib/piiSanitizer.ts`) ಮತ್ತು ವಿನಂತಿಯ ಮಾಸ್ಕರ್ (`src/shared/utils/inputSanitizer.ts`) ಎರಡೂ ಸೇವಿಸುತ್ತದೆ. ಅದರ ಮೌಲ್ಯಮಾಪಕರು ಅದನ್ನು ಸ್ವೀಕರಿಸಿದಾಗ ಮಾತ್ರ ಹೊಂದಾಣಿಕೆಯನ್ನು ಮರುರೂಪಿಸಲಾಗುತ್ತದೆ; ಅಂಕೆಗಳ ಬೇರ್ ರನ್ ಎಂದಿಗೂ ಸಾಕಾಗುವುದಿಲ್ಲ. ಈ ಐಡಿಗಳು ಅಸ್ತಿತ್ವಕ್ಕೆ ಬರುವ ಮೊದಲು ಸಂಕುಚಿತ ಆಯ್ಕೆಯನ್ನು ಉಳಿಸಿದ ಆಪರೇಟರ್ ಹೊಸ ಐಡಿಗಳನ್ನು ಟಿಕ್ ಮಾಡುವವರೆಗೆ ಅದು ಹೊಂದಿದ್ದ ನಡವಳಿಕೆಯನ್ನು ಇರಿಸುತ್ತದೆ.
- **ಕಸ್ಟಮ್ ಮಾದರಿಗಳು** — ವರೆಗೆ 20 regex ಅಥವಾ ವೈಲ್ಡ್ಕಾರ್ಡ್ ಮಾದರಿಗಳು (`*` = ವರೆಗೆ 64 ವೈಟ್ಸ್ಪೇಸ್ ಅಲ್ಲದ ಅಕ್ಷರಗಳು, `?` = ಒಂದು). ಪಂದ್ಯಗಳು `[CUSTOM_REDACTED]` ಆಗುತ್ತವೆ. ಪ್ರತಿಯೊಂದು ನಮೂನೆಯು `compilePiiCustomPattern()` (`src/shared/utils/piiCustomPatterns.ts`): ಹೆಚ್ಚೆಂದರೆ 500 ಅಕ್ಷರಗಳು, `g i m s u` ಗೆ ಸೀಮಿತವಾಗಿರುವ ಫ್ಲ್ಯಾಗ್ಗಳು, ಕಂಪೈಲ್ ಮಾಡಬೇಕು, `safe-regex` (ದುರಂತ ಬ್ಯಾಕ್ಟ್ರ್ಯಾಕಿಂಗ್) ಅನ್ನು ರವಾನಿಸಬೇಕು ಮತ್ತು ಖಾಲಿ ಸ್ಟ್ರಿಂಗ್ ಅಥವಾ ರಿಡಕ್ಷನ್ ಪ್ಲೇಸ್ಹೋಲ್ಡರ್ಗೆ ಹೊಂದಿಕೆಯಾಗಬಾರದು. ವಿಫಲಗೊಳ್ಳುವ ಮಾದರಿಯನ್ನು ಉಳಿಸಿದಾಗ ಮತ್ತು ಪರೀಕ್ಷಿಸಿದಾಗ ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ವಿಫಲವಾದ ಸಂಗ್ರಹವಾದ ಸಾಲನ್ನು ಕಂಪೈಲ್ ಮಾಡುವ ಬದಲು ರನ್ಟೈಮ್ನಲ್ಲಿ ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ. ಮಾಸ್ಕಿಂಗ್ ಆನ್ ಆಗಿರುವಾಗ ಮಾತ್ರ ಕಸ್ಟಮ್ ಮಾದರಿಗಳು ರನ್ ಆಗುತ್ತವೆ.
- **ಪತ್ತೆ ಕೌಂಟರ್ಗಳು** — ಪ್ರತಿ-ಪ್ರಕಾರದ ಎಣಿಕೆಗಳು (ಎಂದಿಗೂ ಹೊಂದಿಕೆಯಾಗದ ಮೌಲ್ಯಗಳು), ಮೆಮೊರಿಯಲ್ಲಿ ಇರಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಮರುಪ್ರಾರಂಭಿಸಿದಾಗ ಮರುಹೊಂದಿಸಿ (`src/lib/pii/piiDetectionStats.ts`). ಮರೆಮಾಚುವಿಕೆ ಆನ್ ಆಗಿರುವಾಗ ಮಾತ್ರ ಅವು ಹೆಚ್ಚಾಗುತ್ತವೆ.

ಸೆಟ್ಟಿಂಗ್ಗಳು `key_value` ಕೋಷ್ಟಕದಲ್ಲಿ ವಾಸಿಸುತ್ತವೆ (ನೇಮ್ಸ್ಪೇಸ್ `pii_settings`, `src/lib/db/piiSettings.ts`) ಮತ್ತು 1 ಸೆ ಸಂಗ್ರಹದ ಮೂಲಕ ಓದಲಾಗುತ್ತದೆ. API:

| ವಿಧಾನ  | ಮಾರ್ಗ                    | ಉದ್ದೇಶ                                                                 |
| ------ | ------------------------ | ---------------------------------------------------------------------- |
| `GET`  | `/api/settings/pii`      | ಫ್ಲ್ಯಾಗ್ ಸ್ಟೇಟ್, `enabledTypes`, `customPatterns`, ಪತ್ತೆ ಕೌಂಟರ್ಗಳು     |
| `PUT`  | `/api/settings/pii`      | `enabledTypes` (`null` = all) and/or `customPatterns` ಅನ್ನು ಬದಲಾಯಿಸಿ   |
| `POST` | `/api/settings/pii/test` | ಗರಿಷ್ಠ 8 KB ಮಾದರಿಯ ವಿರುದ್ಧ ಡ್ರೈ-ರನ್ ಒಂದು ಮಾದರಿ; ಏನನ್ನೂ ಸಂಗ್ರಹಿಸಲಾಗಿಲ್ಲ |

ಮೂವರಿಗೂ ನಿರ್ವಹಣೆ ದೃಢೀಕರಣದ ಅಗತ್ಯವಿರುತ್ತದೆ ಮತ್ತು ದೇಹವನ್ನು Zod (`src/shared/validation/schemas/piiSettings.ts`) ನೊಂದಿಗೆ ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ.

### ಪ್ರಾಂಪ್ಟ್ ಇಂಜೆಕ್ಷನ್ (`promptInjection.ts`)

ಬಳಕೆದಾರ-ಸರಬರಾಜು ಮಾಡಿದ ವಿಷಯದಲ್ಲಿ ಪ್ರತಿಕೂಲ ರಚನೆಗಳನ್ನು ಪತ್ತೆ ಮಾಡುತ್ತದೆ ಮತ್ತು ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ ನೀತಿಯನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತದೆ. ನಡವಳಿಕೆಯು ಪರಿಸರ ವೇರಿಯಬಲ್ಗಳು ಮತ್ತು ಕನ್ಸ್ಟ್ರಕ್ಟರ್ ಆಯ್ಕೆಗಳಿಂದ ನಡೆಸಲ್ಪಡುತ್ತದೆ:

| ಸೆಟ್ಟಿಂಗ್         | ಎನ್ವಿ ವರ್                                                                                              | ಡೀಫಾಲ್ಟ್ | ಪರಿಣಾಮ                                                                                                                                                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------ | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ಸಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ | `INPUT_SANITIZER_ENABLED`                                                                              | `true`   | ಯಾವಾಗ `false`, ಗಾರ್ಡ್ರೈಲ್ ಶಾರ್ಟ್-ಸರ್ಕ್ಯೂಟ್ಗಳು.                                                                                                                                                                              |
| ಮೋಡ್              | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                        | `warn`   | ಇಂಜೆಕ್ಷನ್ ನೀತಿ: `block`, `warn`, ಅಥವಾ `log`. (`redact` ಬ್ಯಾಕ್-ಕಂಪ್ಯಾಟ್ಗಾಗಿ ಸ್ವೀಕರಿಸಲಾಗಿದೆ ಆದರೆ ಮಾಡುತ್ತದೆ** ಅಲ್ಲ** ಸ್ಟ್ರಿಪ್ ಇಂಜೆಕ್ಷನ್ ಪಠ್ಯ; ವಿನಂತಿ PII ಪುನಃ ಬರೆಯುವಿಕೆಯನ್ನು `PII_REDACTION_ENABLED` ನಿಂದ ನಿಯಂತ್ರಿಸಲಾಗುತ್ತದೆ.) |
| ಬ್ಲಾಕ್ ಥ್ರೆಶೋಲ್ಡ್ | `blockThreshold` ಆಯ್ಕೆ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (ಅಲಿಯಾಸ್ `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`   | ನಿರ್ಬಂಧಿಸಲು ಕನಿಷ್ಠ ತೀವ್ರತೆಯ ಅಗತ್ಯವಿದೆ. ಮಧ್ಯಮವು ಡೀಫಾಲ್ಟ್ನಲ್ಲಿ ವೀಕ್ಷಿಸಲು ಮಾತ್ರ.                                                                                                                                               |

**ಮೋಡ್ ಆದ್ಯತೆ** (`getMode`): ಕಾಲರ್ `options.mode` → `INJECTION_GUARD_MODE`**DB ವೈಶಿಷ್ಟ್ಯ-ಧ್ವಜ ಅತಿಕ್ರಮಣ** (ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಸೆಟ್ಟಿಂಗ್ಗಳು → ವೈಶಿಷ್ಟ್ಯ ಫ್ಲ್ಯಾಗ್ಗಳು) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env → `warn`. ಆದ್ದರಿಂದ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅತಿಕ್ರಮಣವು env vars ಅನ್ನು ಗೆಲ್ಲುತ್ತದೆ, ಆದ್ದರಿಂದ ಫೀಚರ್ ಫ್ಲ್ಯಾಗ್ಗಳು UI ಚಾಲನೆಯಲ್ಲಿರುವ ಗಾರ್ಡ್ ಲೈವ್ ಅನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ (ಮರುಪ್ರಾರಂಭವಿಲ್ಲ). DB ರೀಡ್ ವಿಫಲ-ಸುರಕ್ಷಿತವಾಗಿದೆ: ಅದು ದೋಷಗಳಾದರೆ, ಸಿಬ್ಬಂದಿ env-ಆಧಾರಿತ ನಡವಳಿಕೆಗೆ ಹಿಂತಿರುಗುತ್ತಾರೆ ಮತ್ತು ಯಾವುದೇ ಅತಿಕ್ರಮಣವನ್ನು ಹೊಂದಿಸದಿದ್ದಾಗ ವರ್ತನೆಯು env-ಮಾತ್ರ ನಿರ್ಣಯಕ್ಕೆ ಹೋಲುತ್ತದೆ.

ಪತ್ತೆ ಮೂಲಗಳು:

1. `@/shared/utils/inputSanitizer` ನಿಂದ `sanitizeRequest()` (ಪೈಪ್ಲೈನ್ನಲ್ಲಿ ಬೇರೆಡೆ ಬಳಸಲಾದ ಹಂಚಿಕೆಯ ಡಿಟೆಕ್ಟರ್ ಸೆಟ್).
2. ಅಂತರ್ನಿರ್ಮಿತ `DEFAULT_GUARD_PATTERNS` (ಪ್ರಸ್ತುತ `system_override_inline` ಮತ್ತು `markdown_system_block`, ಎರಡೂ `high` ತೀವ್ರತೆ).
3. ಐಚ್ಛಿಕ `customPatterns` ಕನ್ಸ್ಟ್ರಕ್ಟರ್ ಆಯ್ಕೆಗಳ ಮೂಲಕ ರವಾನಿಸಲಾಗಿದೆ (ಸ್ಟ್ರಿಂಗ್ಗಳು, ರಿಜೆಕ್ಸ್, ಅಥವಾ `{ name, pattern, severity }` ದಾಖಲೆಗಳು).

ಯಾವಾಗ `mode === "block"`** ಮತ್ತು** ಕನಿಷ್ಠ ಒಂದು ಪತ್ತೆಯು ತೀವ್ರತೆಯ ಮಿತಿಯನ್ನು ಪೂರೈಸುತ್ತದೆ, `preCall` `{ block: true, message: "Request rejected: suspicious content detected" }` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ. `warn`/`log` ಮೋಡ್ಗಳಲ್ಲಿ ಗಾರ್ಡ್ರೈಲ್ ಲಾಗ್ ಆಗುತ್ತದೆ ಆದರೆ ಕರೆಯನ್ನು ಅನುಮತಿಸುತ್ತದೆ. ನೋಂದಾವಣೆಯ ಮೂಲಕ ಹೋಗದೆಯೇ ಪ್ರಾಂಪ್ಟ್ಗಳನ್ನು ಮೌಲ್ಯಮಾಪನ ಮಾಡುವ ಅಗತ್ಯವಿರುವ ಕರೆ ಮಾಡುವವರಿಗೆ ಹಂಚಿದ ಸಹಾಯಕ `evaluatePromptInjection()` ಅನ್ನು ರಫ್ತು ಮಾಡಲಾಗುತ್ತದೆ.

**ಸ್ಕ್ಯಾನ್ ಬೌಂಡ್ (v3.8.20):** ಡಿಟೆಕ್ಟರ್ ಮಾತ್ರ ಪರಿಶೀಲಿಸುತ್ತದೆ** ಮೊದಲ 16 KB** `src/shared/utils/inputSanitizer.ts` ನಲ್ಲಿ ಸೇರಿಕೊಂಡ ಪ್ರಾಂಪ್ಟ್ ಪಠ್ಯ — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ಬೈಟ್ಗಳು) . ಪ್ಯಾಟರ್ನ್ ಲೂಪ್ ಅನ್ನು ಚಲಾಯಿಸುವ ಮೊದಲು `detectInjection()` ಮತ್ತು `evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` ಎರಡೂ. ಇಂಜೆಕ್ಷನ್ ನಿರ್ದೇಶನಗಳು ಇನ್ಪುಟ್ನ ಮೇಲ್ಭಾಗದಲ್ಲಿ ಇರುತ್ತವೆ, ಆದ್ದರಿಂದ ಇದು ಪತ್ತೆಹಚ್ಚುವಿಕೆಯನ್ನು ದುರ್ಬಲಗೊಳಿಸದೆಯೇ ಬಹು-ನೂರು-KB ಪೇಲೋಡ್ಗಳಲ್ಲಿ ರಿಜೆಕ್ಸ್ CPU/GC ಮುಚ್ಚುತ್ತದೆ (cf. #3932, #4041).

### ರುಜುವಾತು ಮಾಸ್ಕರ್ (`credentialMasker.ts`)

ಚಾಲನೆಯಲ್ಲಿದೆ** ಎರಡೂ** ಹಂತಗಳು, ಡೀಫಾಲ್ಟ್ ಸರಪಳಿಯಲ್ಲಿ ಕೊನೆಯದು (ಆದ್ಯತೆ `95`). ಹೊರಹೋಗುವ ಪೇಲೋಡ್ನಿಂದ (ಸಂದೇಶದ ವಿಷಯ, ಟೂಲ್-ಕರೆ ಆರ್ಗ್ಯುಮೆಂಟ್ಗಳು, ಟೂಲ್ ಫಲಿತಾಂಶಗಳು) ಸುಪ್ರಸಿದ್ಧ API-ಕೀ / ರಹಸ್ಯ-ಟೋಕನ್ ಮಾದರಿಗಳನ್ನು ಪರಿಷ್ಕರಿಸುತ್ತದೆ** ಮತ್ತು** ಒದಗಿಸುವವರ ಪ್ರತಿಕ್ರಿಯೆ, ಆದ್ದರಿಂದ ಪ್ರಾಂಪ್ಟ್ಗೆ ಅಂಟಿಸಲಾದ ರುಜುವಾತು (ಅಥವಾ ಟೂಲ್ ಫಲಿತಾಂಶದಿಂದ ಪ್ರತಿಧ್ವನಿಸುತ್ತದೆ) ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರಿಗೆ ಅಥವಾ ಕ್ಲೈಂಟ್ಗೆ ಹಿಂತಿರುಗುವುದಿಲ್ಲ.

- **ಆಯ್ಕೆ ಮಾತ್ರ** , PII ರಿಡಕ್ಷನ್ನಂತೆಯೇ ಅದೇ ಸಂಪ್ರದಾಯ (ಹಾರ್ಡ್ ರೂಲ್ #20-ಪಕ್ಕದ): `settings.credentialRedactionEnabled === true` ಹೊರತು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ** ಅಥವಾ** `CREDENTIAL_REDACTION_ENABLED=true` ಅದನ್ನು ಆಫ್ ಮಾಡಿದಾಗ, ಗಾರ್ಡ್ರೈಲ್ ಯಾವುದೇ-ಆಪ್ — ಆಗಿದ್ದು ಅದು ಎಂದಿಗೂ ನಿರ್ಬಂಧಿಸುವುದಿಲ್ಲ ಮತ್ತು ಮತ್ತೆ ಬರೆಯುವುದಿಲ್ಲ.
- `redactCredentials()` ಪೂರ್ಣ payload/response ಟ್ರೀ (`walkValue()`, ಮೂಲಮಾದರಿ-ಮಾಲಿನ್ಯ-ಸುರಕ್ಷಿತ, ಸೈಕಲ್-ಸುರಕ್ಷಿತ `WeakSet` ಮೂಲಕ) ಮತ್ತು ಮ್ಯಾಚ್ಗಳನ್ನು `[REDACTED:<type>]` ಪ್ಲೇಸ್ಹೋಲ್ಡರ್ನೊಂದಿಗೆ ಬದಲಾಯಿಸುತ್ತದೆ, ವಾಸ್ತವವಾಗಿ ಬದಲಾದ ಶಾಖೆಗಳನ್ನು ಮಾತ್ರ ಕ್ಲೋನಿಂಗ್ ಮಾಡುತ್ತದೆ.
- `CREDENTIAL_PATTERNS` LLM ಪೂರೈಕೆದಾರರ ಕೀಗಳನ್ನು ಒಳಗೊಂಡಿದೆ (OpenAI, OpenAI-proj, Anthropic, Google, ಹಗ್ಗಿಂಗ್ ಫೇಸ್, ರೆಪ್ಲಿಕೇಟ್), VCS/SaaS ಟೋಕನ್ಗಳು (GitHub, Slack, ಲೀನಿಯರ್, Notion, npm, ಪೋಸ್ಟ್ಮ್ಯಾನ್, Discord), ಪಾವತಿ ಕೀಗಳು, ಕ್ಲೌಡ್AWS, ಕ್ಲೌಡ್ ಕೀಗಳು Twilio, SendGrid, Mailgun), ಖಾಸಗಿ ಕೀಲಿಗಳು / JWTs, ರುಜುವಾತು-ಬೇರಿಂಗ್ ಸಂಪರ್ಕ ತಂತಿಗಳು (`mongodb://user:pass@...`, ಇತ್ಯಾದಿ), ಮತ್ತು ಜೆನೆರಿಕ್ `Authorization`/`x-api-key`/`api-key`/`apikey` ಹೆಡರ್-ಮೌಲ್ಯದ ಮಾದರಿ. ಹೆಡರ್-ಆಕಾರದ ಕೀಗಳನ್ನು (`authorization`, `x-api-key`, `api-key`, `apikey`) ರಚನಾತ್ಮಕವಾಗಿ ಮರುರೂಪಿಸಲಾಗಿದೆ (ಮೌಲ್ಯ ಮಾತ್ರ, `Bearer `/`Basic ` ನಂತಹ ಸ್ಕೀಮ್ ಪೂರ್ವಪ್ರತ್ಯಯವನ್ನು ಸಂರಕ್ಷಿಸಲಾಗಿದೆ) ಬದಲಿಗೆ ಜೆನೆರಿಕ್ ಟೆಕ್ಸ್ಟ್ ರಿಜೆಕ್ಸ್ ಮೂಲಕ.
- ಗಾರ್ಡ್ರೈಲ್ ಎಂದಿಗೂ ನಿರ್ಬಂಧಿಸುವುದಿಲ್ಲ; ಇದು ಪುನಃ ಬರೆಯುತ್ತದೆ (`modifiedPayload` / `modifiedResponse`) ಮತ್ತು ಟಿಪ್ಪಣಿಗಳು (`meta.credentialsRedacted`, `meta.count`).

ರಿಗ್ರೆಶನ್ ಗಾರ್ಡ್: `tests/unit/credential-masker-guardrail.test.ts`.

## ಮೂಲ ಒಪ್ಪಂದ (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true ಸರಣಿಯನ್ನು ಶಾರ್ಟ್-ಸರ್ಕ್ಯೂಟ್ ಮಾಡುತ್ತದೆ
  message?: string; // ನಿರ್ಬಂಧಿಸುವಾಗ ತೋರಿಸಲಾಗುತ್ತದೆ
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // ವಿನಂತಿಯನ್ನು ಮರುಬರೆಯಲು preCall ಹಿಂದಿರುಗಿಸುತ್ತದೆ
  modifiedResponse?: TValue; // ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಮರುಬರೆಯಲು postCall ಹಿಂದಿರುಗಿಸುತ್ತದೆ
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ಗಾರ್ಡ್ರೈಲ್ ಒಂದು `void`, `{}` ಅಥವಾ `{ block: false }` ಹಿಂದಿರುಗಿಸುವ ಮೂಲಕ "ಬದಲಾವಣೆ ಇಲ್ಲ" ಎಂದು ಸೂಚಿಸುತ್ತದೆ. `modifiedPayload`/`modifiedResponse` ಹಿಂದಿರುಗಿಸುವುದು ಕೆಳಹರಿವಿನ ಗಾರ್ಡ್ರೈಲ್ಗಳಿಗಾಗಿ ಸರಣಿಯ ಮೂಲಕ ಹರಿಯುವ ಮೌಲ್ಯವನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ. `signal?: AbortSignal` ಕರೆಮಾಡುವವರ ಜೀವನಚಕ್ರವನ್ನು ಗಾರ್ಡ್ರೈಲ್ಗಳೊಳಗೆ ಸಾಗಿಸುತ್ತದೆ. ವಿನಂತಿ ರದ್ದತಿಯು ಉದ್ದೇಶಪೂರ್ವಕ ಫೇಲ್-ಓಪನ್ ಹೊರತಾಗಿದೆ: ಮೀಡಿಯಾ ಬ್ರಿಡ್ಜ್ಗಳು ಕೆಲಸ ಮತ್ತು ಸ್ವಚ್ಛಗೊಳಿಸುವಿಕೆಯನ್ನು ನಿಲ್ಲಿಸುತ್ತವೆ, ಅದನ್ನು ಬೆಂಬಲಿಸುವುದಿಲ್ಲ ಎಂದು ತಿಳಿದಿರುವ ಗುರಿಗೆ ಕಚ್ಚಾ ಮೀಡಿಯಾವನ್ನು ಮರುಸ್ಥಾಪಿಸದೆ.

## ರಿಜಿಸ್ಟ್ರಿ (`registry.ts`)

ಸಿಂಗಲ್ಟನ್ `guardrailRegistry` ಈ ಕೆಳಗಿನವುಗಳನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ:

- `register(guardrail)` — ಗಾರ್ಡ್ರೈಲ್ ಅನ್ನು ಸೇರಿಸುತ್ತದೆ (ಅಥವಾ ಸಾಮಾನ್ಯೀಕೃತ ಹೆಸರಿನಿಂದ
  ಬದಲಾಯಿಸುತ್ತದೆ) ಮತ್ತು ಏರಿಕೆ `priority` ಪ್ರಕಾರ ಮರು-ವಿಂಗಡಿಸುತ್ತದೆ.
- `clear()` / `list()` — ಆಡಳಿತಾತ್ಮಕ ಸಹಾಯಕಗಳು.
- `runPreCallHooks(payload, context)` — ಸಕ್ರಿಯ ಗಾರ್ಡ್ರೈಲ್ಗಳ ಮೂಲಕ ಪುನರಾವರ್ತಿಸುತ್ತದೆ,
  ಪೇಲೋಡ್ ಅನ್ನು `modifiedPayload` ಮೂಲಕ ಸಾಗಿಸುತ್ತದೆ, ಮತ್ತು ಮೊದಲ `block: true` ನಲ್ಲಿ ನಿಲ್ಲಿಸುತ್ತದೆ.
- `runPostCallHooks(response, context)` — ಪ್ರತಿಕ್ರಿಯೆಯ ಬದಿಯಲ್ಲಿಯೂ ಅದೇ ಹರಿವು.
- `resetGuardrailsForTests({ registerDefaults })` — ಸ್ಥಿತಿಯನ್ನು ತೆರವುಗೊಳಿಸುತ್ತದೆ ಮತ್ತು
  ಸ್ವಚ್ಛ ಪರೀಕ್ಷಾ ಪ್ರತ್ಯೇಕತೆಗಾಗಿ ಬಯಸಿದರೆ ಡೀಫಾಲ್ಟ್ಗಳನ್ನು ಮರು-ನೋಂದಾಯಿಸುತ್ತದೆ.

ಎರಡೂ ರನ್ನರ್ಗಳು `{ blocked, payload|response, results, guardrail?, message? }` ಹಿಂದಿರುಗಿಸುತ್ತವೆ; ಇಲ್ಲಿ `results` ಎಂಬುದು `GuardrailExecutionResult` ದಾಖಲೆಗಳ ಶ್ರೇಣಿಯಾಗಿದ್ದು, ಪ್ರತಿ-ಗಾರ್ಡ್ರೈಲ್ `blocked`, `skipped`, `modified`, `error` ಮತ್ತು `meta` ಕ್ಷೇತ್ರಗಳನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ — ಇದು ಟ್ರೇಸಿಂಗ್ಗೆ ಉಪಯುಕ್ತ.

### ಪ್ರತಿ-ವಿನಂತಿಗೆ ಗಾರ್ಡ್ರೈಲ್ಗಳನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವುದು

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` ಪ್ರಸ್ತುತ ವಿನಂತಿಗೆ ಬಿಟ್ಟುಬಿಡಬೇಕಾದ ಗಾರ್ಡ್ರೈಲ್ ಹೆಸರುಗಳ ನಕಲು-ತೆಗೆದ ಪಟ್ಟಿಯನ್ನು ಒಂದುಗೂಡಿಸುತ್ತದೆ. ಐದು ಚಾನೆಲ್ಗಳಿವೆ; ಅವುಗಳನ್ನು ಈ ಕ್ರಮದಲ್ಲಿ ಓದಲಾಗುತ್ತದೆ ಮತ್ತು ಒಂದೇ ಪಟ್ಟಿಯಾಗಿ ವಿಲೀನಗೊಳಿಸಲಾಗುತ್ತದೆ (ನಕಲು-ತೆಗೆಯುವಾಗ ಮೊದಲ ಆಗಮನವೇ ಗೆಲ್ಲುತ್ತದೆ):

1. `apiKeyInfo.disabledGuardrails`
2. ವಿನಂತಿ ಬಾಡಿಯ `disabledGuardrails` (ಮೇಲ್ಮಟ್ಟ)
3. ವಿನಂತಿ ಬಾಡಿಯ `metadata.disabledGuardrails` (`metadata` ಆಬ್ಜೆಕ್ಟ್ ಆಗಿರುವಾಗ ಮಾತ್ರ)
4. ಹೆಡರ್ `x-omniroute-disabled-guardrails`
5. ಲೆಗಸಿ ಹೆಡರ್ `x-disabled-guardrails`

ಎಲ್ಲಾ ಐದು ಚಾನೆಲ್ಗಳು ವಿಲೀನಗೊಳ್ಳುತ್ತವೆ — ಎರಡು ಹೆಡರ್ಗಳೂ ಸೇರಿದಂತೆ: `x-omniroute-disabled-guardrails` ಮತ್ತು `x-disabled-guardrails` ಎರಡನ್ನೂ ಕಳುಹಿಸಿದರೆ ಅವುಗಳ ಪಟ್ಟಿಗಳ ಯೂನಿಯನ್ ಅನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ, ಮತ್ತು ಖಾಲಿ ಆಧುನಿಕ ಹೆಡರ್ ಇನ್ನುಮುಂದೆ ಲೆಗಸಿ ಹೆಡರ್ ಅನ್ನು ಮರೆಮಾಚುವುದಿಲ್ಲ ([#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412), [#16805](https://github.com/diegosouzapw/OmniRoute/pull/16805) ನಲ್ಲಿ ಸರಿಪಡಿಸಲಾಗಿದೆ).

ಮೌಲ್ಯಗಳು ಸ್ಟ್ರಿಂಗ್ಗಳ ಶ್ರೇಣಿಗಳಾಗಿರಬಹುದು ಅಥವಾ ಕಾಮಾ-ಬೇರ್ಪಡಿಸಿದ ಸ್ಟ್ರಿಂಗ್ ಆಗಿರಬಹುದು; ಹೆಸರುಗಳನ್ನು ಟ್ರಿಮ್ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು ಚಿಕ್ಕಕ್ಷರ kebab-case ಗೆ ಸಾಮಾನ್ಯೀಕರಿಸಲಾಗುತ್ತದೆ (`pii_masker` → `pii-masker`), ಮತ್ತು ಖಾಲಿ ನಮೂದುಗಳನ್ನು ಕೈಬಿಡಲಾಗುತ್ತದೆ. ಫಲಿತಾಂಶವನ್ನು `context.disabledGuardrails` ಮೂಲಕ ರಿಜಿಸ್ಟ್ರಿಗೆ ರವಾನಿಸಲಾಗುತ್ತದೆ; ಅದು ಹೊಂದಿಕೆಯಾಗುವ ಗಾರ್ಡ್ರೈಲ್ಗಳನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ (`results` ನಲ್ಲಿ `skipped: true`).

ನಿಷ್ಕ್ರಿಯ ಪಟ್ಟಿಯು ಕೇವಲ **ರಿಜಿಸ್ಟ್ರಿ**ಯನ್ನು ಮಾತ್ರ ಪರಿಣಾಮ ಬೀರುತ್ತದೆ. ಪ್ರಾಂಪ್ಟ್-ಇಂಜೆಕ್ಷನ್ `block` ಮೋಡ್ ಕಡ್ಡಾಯ ಗಡಿಯಾಗಿದೆ: ಇಂಜೆಕ್ಷನ್-ಗಾರ್ಡ್ ಮಿಡಲ್ವೇರ್ (`src/middleware/promptInjectionGuard.ts`) ಯಾವುದೇ ಕರೆಮಾಡುವವರ-ನಿಯಂತ್ರಿತ ನಿಷ್ಕ್ರಿಯ ಪಟ್ಟಿಯಿಲ್ಲದೆ `evaluatePromptInjection()` ಅನ್ನು ಕರೆಯುತ್ತದೆ (ಅದು ಹಿಂದೆ ಮಾಡುತ್ತಿದ್ದ ನಿಷ್ಪ್ರಯೋಜಕ `resolveDisabledGuardrails({ body })` ಕರೆಯನ್ನು [#16934](https://github.com/diegosouzapw/OmniRoute/pull/16934) ನಲ್ಲಿ ತೆಗೆದುಹಾಕಲಾಗಿದೆ), ಆದ್ದರಿಂದ `prompt-injection` ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವ ವಿನಂತಿಯನ್ನು `block` ಮೋಡ್ನಲ್ಲಿಯೂ ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ. ಇದು ಉದ್ದೇಶಪೂರ್ವಕ ವಿನ್ಯಾಸ. ನಿಷ್ಕ್ರಿಯ ಚಾನೆಲ್ಗಳು ಕರೆಮಾಡುವವರ ನಿಯಂತ್ರಣದಲ್ಲಿವೆ (ವಿನಂತಿ ಬಾಡಿ, metadata, ಹೆಡರ್ಗಳು), ಮತ್ತು ಆಪರೇಟರ್ ಹೊಂದಿಸಿದ ಭದ್ರತಾ ನಿಯಂತ್ರಣವನ್ನು ಕರೆಮಾಡುವವರು ಆಫ್ ಮಾಡಲು ಸಾಧ್ಯವಾಗಬಾರದು ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)). [#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412) ರ ಹೆಡರ್ ಯೂನಿಯನ್ ಯಾವ ರಿಜಿಸ್ಟ್ರಿ ಗಾರ್ಡ್ರೈಲ್ಗಳನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ ಎಂಬುದನ್ನು ಮಾತ್ರ ಬದಲಾಯಿಸುತ್ತದೆ; ಅದು ಕ್ಲಯಂಟ್ಗೆ ಮಿಡಲ್ವೇರ್ ಅನ್ನು bypass ಮಾಡಲು ಅನುಮತಿಸುವುದಿಲ್ಲ. ಕಡ್ಡಾಯ ಪ್ರತಿ-ಕೀ ಮತ್ತು ಪ್ರತಿ-ಗುಂಪು ಗಾರ್ಡ್ರೈಲ್ ನೀತಿಗಳನ್ನು v4 RFC [#16417](https://github.com/diegosouzapw/OmniRoute/issues/16417) ನಲ್ಲಿ ಟ್ರ್ಯಾಕ್ ಮಾಡಲಾಗುತ್ತಿದೆ. [ವ್ಯಾಪ್ತಿ ಮತ್ತು ಮಿತಿಗಳು](#coverage-and-limits) ನೋಡಿ.

## ಕಾರ್ಯನಿರ್ವಹಣೆಯ ಕ್ರಮ

`src/sse/handlers/chat.ts` ಮತ್ತು `open-sse/handlers/chatCore.ts` ಮೂಲಕ ಹರಿದುಬರುವ ಪ್ರತಿ ವಿನಂತಿಗಾಗಿ
([ವ್ಯಾಪ್ತಿ ಮತ್ತು ಮಿತಿಗಳು](#coverage-and-limits) ಅಡಿಯಲ್ಲಿ ಪಟ್ಟಿ ಮಾಡಲಾದ ಚಾಟ್-ಕುಟುಂಬದ ರೂಟ್ಗಳು):

1. `resolveDisabledGuardrails(...)` API ಕೀ, ಬಾಡಿ ಮತ್ತು ಹೆಡರ್ಗಳಿಂದ ಸ್ಕಿಪ್ ಪಟ್ಟಿಯನ್ನು ನಿರ್ಮಿಸುತ್ತದೆ.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ಏರಿಕೆ ಆದ್ಯತಾ ಕ್ರಮದಲ್ಲಿ ಗಾರ್ಡ್ರೈಲ್ಗಳನ್ನು ಚಲಾಯಿಸುತ್ತದೆ:
   - ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾದ ಗಾರ್ಡ್ರೈಲ್ಗಳನ್ನು `skipped` ಎಂದು ದಾಖಲಿಸಲಾಗುತ್ತದೆ.
   - ಪ್ರತಿ ಗಾರ್ಡ್ರೈಲ್ನ `preCall` `modifiedPayload` ಮೂಲಕ ಪೇಲೋಡ್ ಅನ್ನು ಮರುಬರೆಯಬಹುದು.
   - ಮೊದಲ `block: true` ಸರಪಳಿಯನ್ನು ಶಾರ್ಟ್-ಸರ್ಕ್ಯೂಟ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಹ್ಯಾಂಡ್ಲರ್ ಗಾರ್ಡ್ರೈಲ್ ತಿರಸ್ಕಾರ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.
3. (ಬಹುಷಃ ಮರುಬರೆಯಲಾದ) ಪೇಲೋಡ್ ಕಾಂಬೊ ರೂಟಿಂಗ್ ಮತ್ತು ಅಪ್ಸ್ಟ್ರೀಮ್ ಡಿಸ್ಪ್ಯಾಚ್ಗೆ ಹರಿಯುತ್ತದೆ.
4. **ಸ್ಟ್ರೀಮಿಂಗ್ ಅಲ್ಲದವು ಮಾತ್ರ:** ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಜೋಡಿಸಿದ ನಂತರ,
   `guardrailRegistry.runPostCallHooks(...)` ಪ್ರತಿಕ್ರಿಯೆಯ ಮೇಲೆ ಅದೇ ಸರಪಳಿಯನ್ನು ಚಲಾಯಿಸುತ್ತದೆ.
   ಇಲ್ಲಿ `block: true` ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಕೈಬಿಡುತ್ತದೆ ಮತ್ತು HTTP 400 ಹಿಂತಿರುಗಿಸುತ್ತದೆ. ಸ್ಟ್ರೀಮ್ ಮಾಡಲಾದ ಪ್ರತಿಕ್ರಿಯೆಗಳು ಈ ಹಂತವನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಬಿಟ್ಟುಬಿಡುತ್ತವೆ.

ಥ್ರೋ ಮಾಡುವ ಗಾರ್ಡ್ರೈಲ್ಗಳನ್ನು `error: <message>` ನೊಂದಿಗೆ ದಾಖಲಿಸಲಾಗುತ್ತದೆ ಮತ್ತು
`logger.warn` ಮೂಲಕ ಲಾಗ್ ಮಾಡಲಾಗುತ್ತದೆ, ಆದರೆ ಸರಪಳಿ ಮುಂದುವರಿಯುತ್ತದೆ — ವಿನ್ಯಾಸದ ಪ್ರಕಾರ ಫೆಯಿಲ್-ಓಪನ್.

### ಯಾವುದು ವ್ಯಾಪ್ತಿಯಲ್ಲಿಲ್ಲ

- **ಮೀಡಿಯಾ, ಎಂಬೆಡಿಂಗ್ಗಳು ಮತ್ತು ಡೇಟಾ ರೂಟ್ಗಳು** (`/v1/images/*`, `/v1/embeddings`,
  `/v1/audio/*`, `/v1/videos/generations`, `/v1/music/generations`,
  `/v1/rerank`, `/v1/search`, `/v1/moderations`) ಎಂದಿಗೂ ರಿಜಿಸ್ಟ್ರಿಯನ್ನು ತಲುಪುವುದಿಲ್ಲ. ಅಲ್ಲಿ
  PII ಮಾಸ್ಕಿಂಗ್, ಕ್ರೆಡೆನ್ಷಿಯಲ್ ಮಾಸ್ಕಿಂಗ್ ಅಥವಾ ಮೊಡಾಲಿಟಿ ಬ್ರಿಡ್ಜ್ ಓಡುವುದಿಲ್ಲ. ಅವುಗಳ
  ಏಕೈಕ ಪರಿಶೀಲನೆ ಲೆಗಸಿ ಇಂಜೆಕ್ಷನ್-ಗಾರ್ಡ್ ಮಿಡಲ್ವೇರ್ ಆಗಿದೆ.
- **ಸ್ಟ್ರೀಮ್ ಮಾಡಲಾದ ಪ್ರತಿಕ್ರಿಯೆಗಳು** ಯಾವುದೇ ಪೋಸ್ಟ್-ಕಾಲ್ ಗಾರ್ಡ್ರೈಲ್ಗಳನ್ನು ಪಡೆಯುವುದಿಲ್ಲ: `pii-masker` ಅಥವಾ
  `credential-masker` ಪೋಸ್ಟ್-ಕಾಲ್ ಇಲ್ಲ, ಮತ್ತು ಪೋಸ್ಟ್-ಕಾಲ್ ಬ್ಲಾಕ್ ಇಲ್ಲ. ಸ್ಟ್ರೀಮಿಂಗ್ PII
  ಟ್ರಾನ್ಸ್ಫಾರ್ಮ್ ಮಾತ್ರ ಅನ್ವಯಿಸುತ್ತದೆ (`PII_RESPONSE_SANITIZATION` ಆನ್ ಆಗಿರುವಾಗ). ಸ್ಟ್ರೀಮ್ ಮಾಡಲಾದ
  ಪ್ರತಿಕ್ರಿಯೆಯಲ್ಲಿ ಮರುಪ್ರತಿಧ್ವನಿಸಿದ ಕ್ರೆಡೆನ್ಷಿಯಲ್ ಅನ್ನು ಮರೆಮಾಚಲಾಗುವುದಿಲ್ಲ.
- **ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವ ಚಾನೆಲ್ಗಳು ವಿರುದ್ಧ ಮಿಡಲ್ವೇರ್ (ವಿನ್ಯಾಸದ ಪ್ರಕಾರ):** ಮಿಡಲ್ವೇರ್
  ಯಾವುದೇ ಕಾಲರ್-ನಿಯಂತ್ರಿತ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವ ಪಟ್ಟಿಯನ್ನು ರವಾನಿಸದೆ, `evaluatePromptInjection()` ಗೆ ತನ್ನದೇ ಆದ
  ಕರೆಯೊಂದಿಗೆ ಪ್ರಾಂಪ್ಟ್ ಇಂಜೆಕ್ಷನ್ ಅನ್ನು ಮೌಲ್ಯಮಾಪನ ಮಾಡುತ್ತದೆ. `block` ಮೋಡ್ ಕಡ್ಡಾಯ
  ಗಡಿಯಾಗಿದ್ದು, ಚಾಟ್-ಕುಟುಂಬ ರೂಟ್ಗಳು ಸೇರಿದಂತೆ ಕಾಲರ್-ನಿಯಂತ್ರಿತ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವಿಕೆಗಳು
  ಅದನ್ನು ಬೈಪಾಸ್ ಮಾಡಲಾಗುವುದಿಲ್ಲ
  ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)). `prompt-injection` ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವುದು
  ರಿಜಿಸ್ಟ್ರಿ ಗಾರ್ಡ್ರೈಲ್ ಅನ್ನು ಮಾತ್ರ ಬಿಟ್ಟುಬಿಡುತ್ತದೆ.

### ಪೋಸ್ಟ್-ಕಾಲ್ಗೆ ಮೊದಲು ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಯಾವುದು ನೋಡುತ್ತದೆ

ಸ್ಟ್ರೀಮಿಂಗ್ ಅಲ್ಲದ ಮಾರ್ಗದಲ್ಲಿ ಕ್ರಮವು ಹೀಗಿರುತ್ತದೆ: ಮೆಮರಿ ಹೊರತೆಗೆಯುವಿಕೆ → ಅಂತರ್ನಿರ್ಮಿತ ಟೂಲ್
ಎಕ್ಸಿಕ್ಯೂಶನ್ → ಪೋಸ್ಟ್-ಕಾಲ್ ಗಾರ್ಡ್ರೈಲ್ಗಳು → ಪೋಸ್ಟ್-ಕಾಲ್ ಬ್ಲಾಕ್ ನಿರ್ಗಮನ → ಸೆಮಾಂಟಿಕ್-ಕ್ಯಾಶೆ ಸ್ಟೋರ್.

- **ಮೆಮೊರಿ ಹೊರತೆಗೆಯುವಿಕೆ** ಮತ್ತು **ಟೂಲ್ ಎಕ್ಸಿಕ್ಯೂಷನ್** ಪೋಸ್ಟ್-ಕಾಲ್
  ಗಾರ್ಡ್ರೇಲ್ಗಳು ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಮರುಬರೆಯುವ ಅಥವಾ ನಿರ್ಬಂಧಿಸುವ ಮೊದಲೇ ಅದನ್ನು
  ನೋಡುತ್ತವೆ.
  [#16401](https://github.com/diegosouzapw/OmniRoute/pull/16401) ರಿಂದ, ಮೆಮೊರಿ
  ಹೊರತೆಗೆಯುವಿಕೆಯು `PII_RESPONSE_SANITIZATION` ಆನ್ ಆಗಿರುವಾಗ ಹೊರತೆಗೆದ ಪಠ್ಯವನ್ನು
  `sanitizePII` ಮೂಲಕ ಚಲಾಯಿಸುತ್ತದೆ (ಸ್ಟ್ರೀಮಿಂಗ್ ಮತ್ತು ನಾನ್-ಸ್ಟ್ರೀಮಿಂಗ್
  ಎರಡರಲ್ಲೂ), ಆದರೆ ಪೋಸ್ಟ್-ಕಾಲ್ ನಂತರ ನಿರ್ಬಂಧಿಸಲಾದ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಆಗಸ್ಟಕ್ಕೂ
  ಮೆಮೊರಿ ಮತ್ತು ಟೂಲ್ಗಳಿಗೆ ನೀಡಲಾಗಿರುತ್ತದೆ.
- **ಸೆಮಾಂಟಿಕ್ ಕ್ಯಾಶೆ** ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಪೋಸ್ಟ್-ಕಾಲ್ ನಂತರ ಸಂಗ್ರಹಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಅದು
  ಮರುಬರೆದ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ, ಮತ್ತು ನಿರ್ಬಂಧಿಸಲಾದ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಎಂದಿಗೂ
  ಕ್ಯಾಶೆ ಮಾಡಲಾಗುವುದಿಲ್ಲ. ಕ್ಯಾಶೆ ಎಂಟ್ರಿಗಳು ಪ್ರತಿ API ಕೀಯ ಪ್ರಕಾರ ಕೀಲಿ ಮಾಡಲಾಗುತ್ತವೆ.

## ಸಂರಚನೆ

ಅಂತರ್ನಿರ್ಮಿತ ಗಾರ್ಡ್ರೇಲ್ಗಳು ಓದುವ ಪರಿಸರ ವೇರಿಯೇಬಲ್ಗಳು:

| ವೇರಿಯೇಬಲ್                             | ಬಳಸುವುದು                    | ಪರಿಣಾಮ                                                                                                    |
| ------------------------------------- | --------------------------- | --------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`          | ಪತ್ತೆಹಚ್ಚುವಿಕೆಯನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲು `false` ಎಂದು ಹೊಂದಿಸಿ.                                    |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`          | ಇಂಜೆಕ್ಷನ್ ನೀತಿ: `warn`, `block`, ಅಥವಾ `log`. ಪಾರಂಪರಿಕ ಮೌಲ್ಯ `redact` ಇಂಜೆಕ್ಷನ್ ಪಠ್ಯವನ್ನು ಮರುಬರೆಯುವುದಿಲ್ಲ. |
| `INJECTION_GUARD_MODE`                | `prompt-injection`          | ಇಂಜೆಕ್ಷನ್ ಗಾರ್ಡ್ಗಾಗಿ ಮೋಡ್; ಎನ್ವಿ ವೇರಿಯೇಬಲ್ಗಳನ್ನು **ಅತಿಕ್ರಮಿಸುವ** DB ಫೀಚರ್ ಫ್ಲ್ಯಾಗ್ ಕೂಡ ಆಗಿದೆ (DB > ENV).  |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`          | `MODE=block` ತಿರಸ್ಕರಿಸುವ ಕನಿಷ್ಠ ತೀವ್ರತೆ: `high` (ಡೀಫಾಲ್ಟ್), `medium`, ಅಥವಾ `low`.                         |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`          | `INPUT_SANITIZER_BLOCK_THRESHOLD` ಗಾಗಿ ಪಾರಂपರिक ಅಲಿಯಾಸ್.                                                  |
| `PII_REDACTION_ENABLED`               | `pii-masker`                | `true` ಆಗಿದ್ದಾಗ, ವಿನಂತಿಯ PII ಅನ್ನು ಮರ್ಜನೆ ಮಾಡಲಾಗುತ್ತದೆ (ಇಂಜೆಕ్షನ್ ಮೋಡ್ಗೆ ಸ್ವತಂತ್ರವಾಗಿ).                   |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (ಡೌನ್ಸ್ಟ್ರೀಮ್) | ಪ್ರತಿಕ್ರಿಯೆ-ಭಾಗದ ಮಾಸ್ಕರ್ ವರ್ತನೆಯನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ.                                                     |

ಅಲ್ಲದೆ, DB-ಬೆಂಬಲಿತ ಸೆಟ್ಟಿಂಗ್ಸ್ ಸ್ಟೋರ್ (`getSettings()`) ನಿಂದ ಓದುತ್ತವೆ. ವಿಷನ್ನ
ಪ್ರಾಥಮಿಕ ಕೀಲಿಗಳು
`modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`,
`modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`,
`modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`,
`modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`,
`modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, ಮತ್ತು
`modalityBridgeCacheMaxEntries`. ಪಾರಂपरिक
`visionBridge*` ಕೀಲಿಗಳನ್ನು ದಾಖಲೀकृत ಏಕ-ಚಕ್ರ ಓದು ಫಾಲ್ಬ್ಯಾಕ್ ಆಗಿ ಮಾತ್ರ

## ಕಸ್ಟಮ್ ಗಾರ್ಡ್ರೈಲ್ಗಳು

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ಹಂತಗಳು:

1. `BaseGuardrail` ಅನ್ನು ವಿಸ್ತರಿಸುವ `src/lib/guardrails/myGuardrail.ts` ಅನ್ನು ರಚಿಸಿ.
2. `preCall` ಮತ್ತು/ಅಥವಾ `postCall` ಅನ್ನು ಅನುಷ್ಠಾನಗೊಳಿಸಿ.
3. ಇಂಪೋರ್ಟ್ ಸಮಯದಲ್ಲಿ ನೋಂದಾಯಿಸಿ (`registerDefaultGuardrails` ನಿಂದ ಪುಶ್ ಮಾಡಿ) ಅಥವಾ
   ರನ್ಟೈಮ್ನಲ್ಲಿ `guardrailRegistry.register(...)` ಅನ್ನು ಕರೆಯಿರಿ — ರಿಜಿಸ್ಟ್ರಿಯು ಒಂದೇ
   ಸಾಮಾನ್ಯೀಕೃತ ಹೆಸರಿನ ಹಿಂದಿನ ಯಾವುದೇ ಗಾರ್ಡ್ರೈಲ್ ಅನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ.
4. `tests/unit/` ಅಡಿಯಲ್ಲಿ ಪರೀಕ್ಷೆಗಳನ್ನು ಸೇರಿಸಿ (ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಉದಾಹರಣೆಗಳು:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`).

## ಪರೀಕ್ಷಣ

ಪರೀಕ್ಷೆಗಳ ನಡುವೆ ತಿಳಿದಿರುವ ಸ್ಥಿತಿಯಿಂದ ಪ್ರಾರಂಭಿಸಲು `resetGuardrailsForTests()` ಬಳಸಿ.
ಖಾಲಿ ರಿಜಿಸ್ಟ್ರಿಯೊಂದಿಗೆ ಪ್ರಾರಂಭಿಸಲು ಮತ್ತು ಪರೀಕ್ಷೆಯಲ್ಲಿರುವ ಗಾರ್ಡ್ರೈಲ್ಗಳನ್ನು ಮಾತ್ರ
ನೋಂದಾಯಿಸಲು `{ registerDefaults: false }` ಅನ್ನು ರವಾನಿಸಿ. Vision Bridge ಡಿಪೆಂಡೆನ್ಸಿ
ಇಂಜೆಕ್ಷನ್ ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ (`deps.getSettings`, `deps.callVisionModel`); Audio Bridge
ಸೆಟ್ಟಿಂಗ್ಗಳು, ಸಾಮರ್ಥ್ಯಗಳು, STT ಮಾದರಿ ಆಯ್ಕೆ, ರುಜುವಾತು ಪರಿಶೀಲನೆಗಳು ಮತ್ತು
ಟ್ರಾನ್ಸ್ಕ್ರಿಪ್ಶನ್ಗಾಗಿ ಸಮಾನ ಸೀಮ್ಗಳನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ. ಆದ್ದರಿಂದ ಪರೀಕ್ಷೆಗಳು DB ಅಥವಾ
ನೆಟ್ವರ್ಕ್ ಪ್ರವೇಶವಿಲ್ಲದೆ ಎರಡೂ ಹರಿವುಗಳನ್ನು ಚಾಲನೆ ಮಾಡಬಹುದು.

## ಇಂಜೆಕ್ಷನ್-ಗಾರ್ಡ್ ರೂಟ್ ಕವರೇಜ್ ಮತ್ತು ರೆಡ್-ಟೀಮ್ (ಹಂತ 8 · ಬ್ಲಾಕ್ D)

ಇಂಜೆಕ್ಷನ್-ಗಾರ್ಡ್ (`createInjectionGuard` / `withInjectionGuard`) ಬಳಕೆದಾರ ಪ್ರಾಂಪ್ಟ್ಗಳನ್ನು
ಸ್ವೀಕರಿಸುವ ಎಲ್ಲಾ ರೂಟ್ಗಳನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ. ಇದು `INJECTION_GUARD_MODE` ಅನ್ನು ಗೌರವಿಸುತ್ತದೆ
(ಡೀಫಾಲ್ಟ್ `warn` = ಲಾಗ್ ಮಾತ್ರ; `block` = HTTP 400 `SECURITY_001` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ).

| ಪ್ರಕಾರ                      | ರೂಟ್ಗಳು                                                                                                                                              | ಡೀಫಾಲ್ಟ್ ಮೋಡ್ |

ಟೆಕ್ಸ್ಟ್ ಎಕ್ಸ್ಟ್ರಾಕ್ಷನ್ (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ.

**ರೆಡ್-ಟೀಮ್ (ರಾತ್ರಿಕಾಲದ, `nightly-llm-security.yml`):** promptfoo ಪ್ರತಿ ರೂಟ್
`INJECTION_GUARD_MODE=block` ನಲ್ಲಿ OWASP-LLM ಕಾರ್ಪಸ್ ಅನ್ನು ನಿರ್ಬಂಧಿಸುತ್ತದೆ ಎಂದು
ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ; garak ಪ್ರೋಬ್ಗಳನ್ನು ಚಲಾಯಿಸುತ್ತದೆ (ಸೀಕ್ರೆಟ್ ಇಲ್ಲದಿದ್ದರೆ ಬಿಟ್ಟುಬಿಡುತ್ತದೆ).
ಸ್ಥಿರತೆಗಾಗಿ `moderations` ಅನ್ನು ಸೇರಿಸಲಾಗಿದೆ. ಬ್ಲಾಕ್ ಮೋಡ್ ಕಡ್ಡಾಯ ಗಡಿಯಾಗಿದೆ:
`evaluatePromptInjection()` ಮಿಡಲ್ವೇರ್ ಅದಕ್ಕೆ ರವಾನಿಸುವ ಪ್ರತಿ-ವಿನಂತಿಯ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವ
ಪಟ್ಟಿಯನ್ನು ನಿರ್ಲಕ್ಷಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ `disabledGuardrails` ರೂಟ್ ಅನ್ನು ಇದರಿಂದ ವಿನಾಯಿತಿ
ನೀಡುವುದಿಲ್ಲ ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)).

ರಾತ್ರಿಕಾಲದ ವರ್ಕ್ಫ್ಲೋ (`.github/workflows/nightly-llm-security.yml`, cron + ಮ್ಯಾನುಯಲ್
ಡಿಸ್ಪ್ಯಾಚ್) ಎರಡು ಜಾಬ್ಗಳನ್ನು ಹೊಂದಿದೆ:

- **`promptfoo-guard` (ಬ್ಲಾಕಿಂಗ್)** — `INJECTION_GUARD_MODE=block` ನೊಂದಿಗೆ
  `promptfoo eval -c promptfooconfig.yaml` ಅನ್ನು ಚಲಾಯಿಸುತ್ತದೆ. ಪ್ರತಿ ಎಡ್ವರ್ಸರಿಯಲ್
  ಕೇಸ್ (ಉದಾ. "ignore all previous instructions…", DAN-ಶೈಲಿಯ ಜೈಲ್ಬ್ರೇಕ್ಗಳು)
  ಪ್ರತಿಕ್ರಿಯೆಯು `error.code === "SECURITY_001"` ಅನ್ನು ಹೊಂದಿರುತ್ತದೆ ಎಂದು
  ಖಚಿತಪಡಿಸುತ್ತದೆ, ಅಂದರೆ ಗಾರ್ಡ್ ನಿಜವಾಗಿಯೂ ವಿನಂತಿಯನ್ನು ತಿರಸ್ಕರಿಸಿದೆ ಎಂದು.
- **`garak` (ಅಡ್ವೈಸರಿ)** — ಸ್ಥಳೀಯ OmniRoute ಇನ್ಸ್ಟನ್ಸ್
  (`http://localhost:20128/v1`) ವಿರುದ್ಧ garak `--probes promptinject,dan,leakreplay`
  ಅನ್ನು ಚಲಾಯಿಸುತ್ತದೆ. ಪ್ರೊವೈಡರ್ ಸೀಕ್ರೆಟ್ (`PROMPTFOO_PROVIDER_KEY`) ಮೇಲೆ ಗೇಟ್ ಆಗಿದೆ;
  ಸುಗಮವಾಗಿ ಬಿಟ್ಟುಬಿಡುತ್ತದೆ ಮತ್ತು `|| true` ಪ್ರತ್ಯಯವನ್ನು ಹೊಂದಿದೆ, ಆದ್ದರಿಂದ CI ಅನ್ನು
  ವಿಫಲಗೊಳಿಸದೆ ವರದಿ ಮಾಡುತ್ತದೆ.

ಗಾರ್ಡ್ ಹೆಲ್ಪರ್ (`createInjectionGuard` / `withInjectionGuard`) ಕವರೇಜ್ ಪ್ರಾಂಪ್ಟ್ ಹೊಂದಿರುವ
ಪ್ರತಿ `/v1` ರೂಟ್ ಅನ್ನು ವ್ಯಾಪಿಸುತ್ತದೆ; `src/shared/utils/inputSanitizer.ts` ನಲ್ಲಿರುವ
`extractMessageContents()` ಮೂಲಕ `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`
ನಿಂದ ಪ್ರಾಂಪ್ಟ್ ಟೆಕ್ಸ್ಟ್ ಅನ್ನು ತೆಗೆಯಲಾಗುತ್ತದೆ.
