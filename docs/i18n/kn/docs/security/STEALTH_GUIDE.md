ಅಧಿಕೃತವಲ್ಲದ ಕ್ಲೈಂಟ್ಗಳನ್ನು ಸಕ್ರಿಯವಾಗಿ ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಮಾಡುವ ಎಡ್ಜ್ಗಳನ್ನು ಹೊಂದಿರುವ ಪೂರೈಕೆದಾರರೊಂದಿಗೆ OmniRoute ಏಕೀಕರಿಸುತ್ತದೆ (TLS JA3/JA4, ಹೆಡರ್ ಕ್ರಮ, JSON ಬಾಡಿ ಆಕಾರ, ಸಮಗ್ರತಾ ಟೋಕನ್ಗಳು). OmniRoute ಬಹಿರಂಗಪಡಿಸುವ ಸ್ಟೆಲ್ತ್ ಮೇಲ್ಮೈಗಳು ಮತ್ತು ಅವುಗಳನ್ನು ಎಲ್ಲಿ ಅಳವಡಿಸಲಾಗಿದೆ ಎಂಬುದನ್ನು ಈ ಪುಟ ದಾಖಲಿಸುತ್ತದೆ.

## ಕಾನೂನು ಮತ್ತು ನೈತಿಕ ಸೂಚನೆ

ಬಳಕೆದಾರರ ಸ್ವಂತ ಅಧಿಕೃತ ಖಾತೆಗಳು (Claude Code CLI, Codex, Antigravity, Cursor, ಇತ್ಯಾದಿ) ಮತ್ತು OmniRoute ನ ಏಕೀಕೃತ API ನಡುವೆ OmniRoute ಹೊಂದಾಣಿಕೆ ಪದರವಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸಲು ಸ್ಟೆಲ್ತ್ ವೈಶಿಷ್ಟ್ಯಗಳು ಅಸ್ತಿತ್ವದಲ್ಲಿವೆ. ಅವು ವಂಚನೆ ಪತ್ತೆಹಚ್ಚುವಿಕೆಯಿಂದ ತಪ್ಪಿಸಿಕೊಳ್ಳಲು, ರುಜುವಾತುಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳಲು ಅಥವಾ ಪೂರೈಕೆದಾರರ ಸೇವಾ ನಿಯಮಗಳನ್ನು ಉಲ್ಲಂಘಿಸಲು **ಅಲ್ಲ**. ಖಾತೆಗಳನ್ನು ರಚಿಸುವಾಗ ತಾವು ಒಪ್ಪಿಕೊಂಡ ಅಪ್ಸ್ಟ್ರೀಮ್ ToS ಅನ್ನು ನಿರ್ವಾಹಕರು ಪಾಲಿಸಬೇಕೆಂದು ನಿರ್ವಹಣಾಕಾರರು ನಿರೀಕ್ಷಿಸುತ್ತಾರೆ.

## TLS ಫಿಂಗರ್ಪ್ರಿಂಟಿಂಗ್ ಲೇಯರ್

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

ಪ್ರತಿ ಖಾತೆಯ ವ್ಯಾಪ್ತಿ ಮತ್ತು ಪರಿಹರಿಸಲಾದ ಪ್ರಾಕ್ಸಿಗಾಗಿ ನಿರಂತರ `wreq-js` ಸೆಷನ್ಗಳನ್ನು ಅಗತ್ಯವಿದ್ದಾಗ ಮಾತ್ರ ರಚಿಸಲಾಗುತ್ತದೆ. ಪ್ರಕ್ರಿಯೆ-ವ್ಯಾಪಿ `TlsClient`, Cloudflare ಹಿಂದಿರುವ ಅಪ್ಸ್ಟ್ರೀಮ್ಗಳಿಗಾಗಿ **macOS ನಲ್ಲಿನ Chrome 124** ಅನ್ನು ಅನುಕರಿಸುವ ಗರಿಷ್ಠ 128 ಸೆಷನ್ಗಳನ್ನು ಪೂಲ್ ಮಾಡುತ್ತದೆ. ಸ್ಥಳೀಯ ರನ್ಟೈಮ್ ಲಭ್ಯವಿಲ್ಲದಿದ್ದಾಗ `TlsClient.fetch()` ಸುರಕ್ಷಿತವಾಗಿ ವಿಫಲಗೊಳ್ಳುತ್ತದೆ; ಕರೆ ಮಾಡುವವರು ಈ ರ್ಯಾಪರ್ನ ಹೊರಗೆ ಫಾಲ್ಬ್ಯಾಕ್ ಅನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಆಯ್ಕೆ ಮಾಡಬಹುದು.

- ಸೆಷನ್ ಪ್ರೊಫೈಲ್: `browser: "chrome_124", os: "macos"`
- ಪ್ರಾಕ್ಸಿ ಪರಿಹಾರ (ಆದ್ಯತೆ): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (ಲೋವರ್-ಕೇಸ್ ರೂಪಗಳೂ ಸಹ)
- ಕಾಲಮಿತಿ: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS` ನಿಂದ ಪಡೆಯುತ್ತದೆ, ಡೀಫಾಲ್ಟ್ 600000)
- `wreq-js` Response, fetch-ಹೊಂದಾಣಿಕೆಯಾಗಿದೆ (`headers`, `text()`, `json()`, `clone()`, `body`).
- ಮೊದಲ-byte ವಾಚ್ಡಾಗ್ (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): ಅಪ್ಸ್ಟ್ರೀಮ್ ಹೆಡರ್ಗಳು ಬಂದ ತಕ್ಷಣ `TlsClient.fetch()`
  ಪರಿಹಾರಗೊಳ್ಳುತ್ತದೆ, ಆದ್ದರಿಂದ `TLS_CLIENT_TIMEOUT_MS` ಮಾತ್ರ ಮೊದಲ byte ಅನ್ನು ಎಂದಿಗೂ ಒದಗಿಸದ
  ಪ್ರತಿಕ್ರಿಯೆಯ body ಅನ್ನು ಮಿತಿಗೊಳಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ. `guardTlsFirstByte()` body ಯ ಮೊದಲ `read()`
  ಅನ್ನು `TLS_FIRST_BYTE_WATCHDOG_MS` (ಡೀಫಾಲ್ಟ್ `10000`, `0` ಅದನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುತ್ತದೆ) ವಿರುದ್ಧ ಸ್ಪರ್ಧೆಗೆ ಇಡುತ್ತದೆ; ಆರೋಗ್ಯಕರ body ಮೇಲೆ
  ಯಾವುದೇ ಪರಿಣಾಮವಾಗುವುದಿಲ್ಲ, ಆದರೆ ಸ್ಥಗಿತಗೊಂಡ body wreq ರೀಡರ್ ಅನ್ನು ರದ್ದುಗೊಳಿಸಿ `proxyFetch` ನ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ
  TLS-ಫಾಲ್ಬ್ಯಾಕ್ ತರ್ಕವು ನೇರ/ಪ್ರಾಕ್ಸಿ ಡಿಸ್ಪ್ಯಾಚರ್ಗೆ ಮುಂದುವರಿಯುವಂತೆ ಮಾಡುತ್ತದೆ (ರೀಪ್ಲೇಗೆ ಸುರಕ್ಷಿತವಲ್ಲದ ವಿನಂತಿ, ಉದಾ.
  body ಹೊಂದಿರುವ POST, ಮೌನವಾಗಿ ಮರುಪ್ರಯತ್ನಿಸುವ ಬದಲು ಇನ್ನೂ ದೋಷವನ್ನು ಎಸೆಯುತ್ತದೆ).

### ವೆಬ್-cookie ಪೂರೈಕೆದಾರ ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್ — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` ಕೆಳಗಿನ ಐದು ವಿಶೇಷೀಕೃತ
ವೆಬ್-cookie ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್ಗಳಿಗಾಗಿ ಹಂಚಿದ ಅಡಾಪ್ಟರ್ ಆಗಿದೆ. ಪ್ರತಿ ಹಗುರವಾದ ಪೂರೈಕೆದಾರ ರ್ಯಾಪರ್ ಒಂದು ಬ್ರೌಸರ್/OS ಪ್ರೊಫೈಲ್ ಅನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ. ಅಡಾಪ್ಟರ್
`open-sse/utils/tlsClient.ts` ನಲ್ಲಿರುವ ಏಕೈಕ wreq ರನ್ಟೈಮ್ ಲೋಡರ್ ಮತ್ತು ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್ ಪೂಲ್ ಅನ್ನು ಬಳಸುತ್ತದೆ; ಇದು
ಪ್ರೊಫೈಲ್ + OS + ಪರಿಹರಿಸಲಾದ ಪ್ರಾಕ್ಸಿ ಆಧಾರದ ಮೇಲೆ ಕೀ ಮಾಡಲ್ಪಟ್ಟಿರುತ್ತದೆ, ಹಾಗೆಯೇ ಪ್ರತಿ ವಿನಂತಿಯೂ `cookieMode: "ephemeral"` ಅನ್ನು ಬಳಸುತ್ತದೆ. ಆದ್ದರಿಂದ ಖಾತೆಗಳು ಮತ್ತು
ವಿನಂತಿಗಳು ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್-ಮಟ್ಟದ ಸಂಪರ್ಕಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ, ಆದರೆ wreq ಸೆಷನ್ ಅಥವಾ cookie jar ಅನ್ನು ಎಂದಿಗೂ ಹಂಚಿಕೊಳ್ಳುವುದಿಲ್ಲ.

| ಪೂರೈಕೆದಾರ  | ಪ್ರೊಫೈಲ್      | ಅನುಕರಿಸಲಾದ OS | ಸ್ಟ್ರೀಮ್ EOF ನೀತಿ                           |
| ---------- | ------------- | ------------- | ------------------------------------------- |
| Claude     | `chrome_146`  | Linux         | `[DONE]` ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ               |
| Perplexity | `firefox_151` | macOS         | `event: end_of_stream` ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ |
| Grok       | `chrome_146`  | Linux         | `[DONE]` ಅನ್ನು ಹೊರತುಪಡಿಸುತ್ತದೆ              |
| Notion     | `chrome_146`  | Windows       | `[DONE]` ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ               |
| LMArena    | `chrome_146`  | Windows       | ಸೆಂಟಿನಲ್ ಇಲ್ಲ; ಸ್ಥಳೀಯ EOF ನಲ್ಲಿ ಮುಚ್ಚುತ್ತದೆ |

- ಸ್ಟ್ರೀಮಿಂಗ್ ಸ್ಥಳೀಯ ಪ್ರತಿಕ್ರಿಯೆಯ `ReadableStream` ಅನ್ನು ನೇರವಾಗಿ ಬಳಸುತ್ತದೆ; ಯಾವುದೇ ತಾತ್ಕಾಲಿಕ ಫೈಲ್ ಅಥವಾ ಸೈಡ್ಕಾರ್ ಅನ್ನು
  ರಚಿಸಲಾಗುವುದಿಲ್ಲ.
- ಸ್ಟ್ರೀಮ್ ಅನ್ನು ಬಹಿರಂಗಪಡಿಸುವ ಮೊದಲು ಗರಿಷ್ಠ 256 ಆರಂಭಿಕ byte ಗಳನ್ನು ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ. SSE ಪೂರೈಕೆದಾರರು SSE ಅಲ್ಲದ
  ದೋಷಗಳನ್ನು ಬಫರ್ ಮಾಡುತ್ತಾರೆ; Grok/LMArena, Cloudflare ಚಾಲೆಂಜ್ಗಳನ್ನು `403` ಗೆ ಮತ್ತು HTML ಮಧ್ಯಂತರ ಪುಟಗಳನ್ನು `502` ಗೆ ಮ್ಯಾಪ್ ಮಾಡುತ್ತವೆ.
- ಸ್ಥಳೀಯ ವಿನಂತಿಯ ಕಾಲಮಿತಿಯು ನಿರಪೇಕ್ಷ JS ಹಾರ್ಡ್ ಡೆಡ್ಲೈನ್ನಿಂದ ರ್ಯಾಪ್ ಆಗಿರುತ್ತದೆ. ಹ್ಯಾಂಗ್ ಸಂಭವಿಸಿದಾಗ,
  ಮುಂದಿನ ವಿನಂತಿಯು ಅದನ್ನು ಮರುರಚಿಸುವ ಮೊದಲು ಪರಿಣಾಮಕ್ಕೊಳಗಾದ ಪ್ರೊಫೈಲ್/OS/ಪ್ರಾಕ್ಸಿ ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್ ಅನ್ನು ಮಾತ್ರ ಅಮಾನ್ಯಗೊಳಿಸಿ ಮುಚ್ಚಲಾಗುತ್ತದೆ.
- ಪ್ರಾಕ್ಸಿ ಪರಿಹಾರದ ಆದ್ಯತೆಯು ಪ್ರತಿ-ಕರೆ `proxyUrl` → ವಿನಂತಿ-ವ್ಯಾಪ್ತಿಯ ಖಾತೆ/ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಸಂದರ್ಭ →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (ಲೋವರ್ಕೇಸ್ ರೂಪಗಳನ್ನೂ ಒಳಗೊಂಡಂತೆ) ಆಗಿದೆ. ಪರಿಹಾರ ದೋಷಗಳು
  ನೇರ ಸಂಪರ್ಕವನ್ನು ಸೋರಿಕೆ ಮಾಡುವ ಬದಲು ಸುರಕ್ಷಿತವಾಗಿ ವಿಫಲಗೊಳ್ಳುತ್ತವೆ. LMArena ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ `arena.ai` ವಿರುದ್ಧ ಪರಿಹರಿಸುತ್ತದೆ.
- `byteResponse`, UTF-8 ಹಾನಿಯಿಲ್ಲದ, ವಿಷಯದ ಪ್ರಕಾರ ಹೊಂದಿಸಲಾದ `data:` URL ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ.
- ಎಲ್ಲಾ 128 ಮಿತಿಗೊಳಿಸಲಾದ ಪ್ರೊಫೈಲ್/OS/ಪ್ರಾಕ್ಸಿ ಸ್ಲಾಟ್ಗಳು ಸಕ್ರಿಯವಾಗಿರುವಾಗ ಅಥವಾ ಮುಚ್ಚುತ್ತಿರುವಾಗ ದೋಷಗಳು
  `TlsClientUnavailableError` (ಪ್ಯಾಕೇಜ್/ಆಡ್ಆನ್ ಲಭ್ಯವಿಲ್ಲ), `TlsClientHangError`
  (ಡೆಡ್ಲೈನ್ ಮೀರಿದೆ), ಮತ್ತು `WreqTransportCapacityError` (ಹಂಚಿದ ಸೆಷನ್-ಸಾಮರ್ಥ್ಯದ ದೋಷ ಕೋಡ್)
  ಆಗಿರುತ್ತವೆ.

ಮೇಲಿನ ಸಾಮಾನ್ಯ `TlsClient` ಸೆಷನ್ ನಿರಂತರ ಬ್ರೌಸರ್-ಬೆಂಬಲಿತ cookie
ಸ್ಥಿತಿಗಾಗಿ ವಿಶೇಷೀಕೃತವಾಗಿಯೇ ಉಳಿಯುತ್ತದೆ. ಎರಡೂ ಮಾರ್ಗಗಳು ಒಂದೇ ಕ್ಯಾಶ್ ಮಾಡಲಾದ wreq ಮಾಡ್ಯೂಲ್ ಲೋಡರ್ ಮತ್ತು ಪ್ರಕ್ರಿಯೆಯ ಜೀವನಚಕ್ರದ ಹೂಕ್ ಅನ್ನು ಮರುಬಳಕೆ ಮಾಡುತ್ತವೆ; ಅವುಗಳ cookie ಜೀವಿತಾವಧಿಗಳು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ವಿಭಿನ್ನವಾಗಿರುವುದರಿಂದ ಅವುಗಳ ಪೂಲ್ಗಳು
ಪ್ರತ್ಯೇಕವಾಗಿಯೇ ಉಳಿಯುತ್ತವೆ.

ಪಿನ್ ಮಾಡಲಾದ ಪ್ಯಾಕೇಜ್ ಈ ಪ್ರೊಫೈಲ್ಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ, ಆದರೆ ನೈಜ WAF ಸ್ವೀಕಾರವು ಸ್ಥಳೀಯ
ಒಪ್ಪಂದ ಪರೀಕ್ಷೆಗಳಿಂದ ಸ್ವತಂತ್ರವಾಗಿ ಬದಲಾಗಬಹುದು. ಅಪ್ಸ್ಟ್ರೀಮ್ ಬ್ರೌಸರ್ಗೆ ಸಮಾನತೆಯನ್ನು ಪ್ರತಿಪಾದಿಸುವ ಮೊದಲು,
ಸ್ಪಷ್ಟವಾಗಿ ಅಧಿಕೃತಗೊಳಿಸಲಾದ ಲೈವ್ ಖಾತೆಯ ವಿರುದ್ಧ ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಬದಲಾವಣೆಗಳನ್ನು ಮೌಲ್ಯೀಕರಿಸಿ.

## Claude Code ಸ್ಟೆಲ್ತ್ ಬಂಡಲ್

`cliCompatMode` ಆನ್ ಆಗಿರುವಾಗ, OmniRoute ಹೊರಹೋಗುವ Claude ವಿನಂತಿಗಳನ್ನು `claude-cli` ಟ್ರಾಫಿಕ್ನಿಂದ ಪ್ರತ್ಯೇಕಿಸಲು ಸಾಧ್ಯವಾಗದಂತೆ ಮರುರೂಪಿಸುತ್ತದೆ. ಮೂರು ಮಾಡ್ಯೂಲ್ಗಳು ಒಟ್ಟಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ:

### `claudeCodeFingerprint.ts`

ಬಿಲ್ಲಿಂಗ್ ಹೆಡರ್ನಲ್ಲಿ ಎಂಬೆಡ್ ಮಾಡಲಾದ 3-ಅಕ್ಷರಗಳ `cc_version` ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಅನ್ನು ಲೆಕ್ಕಹಾಕುತ್ತದೆ:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (ಹಾರ್ಡ್ಕೋಡ್ ಮಾಡಲಾಗಿದೆ; ಅಧಿಕೃತ ಕ್ಲೈಂಟ್ಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ)
- ಇನ್ಪುಟ್ಗಳು: ಮೊದಲ ಬಳಕೆದಾರ ಸಂದೇಶದ ಪಠ್ಯದಲ್ಲಿನ ಸೂಚ್ಯಂಕ 4, 7, 20ರ ಅಕ್ಷರಗಳು + ಆವೃತ್ತಿ ಸ್ಟ್ರಿಂಗ್
- ಔಟ್ಪುಟ್: 3-ಅಕ್ಷರಗಳ ಹೆಕ್ಸ್ ಪೂರ್ವಪ್ರತ್ಯಯ

### `claudeCodeCCH.ts` (ಕ್ಲೈಂಟ್ ವಿಷಯ ಹ್ಯಾಶ್)

ಅಧಿಕೃತ Claude Code CLI, Bun/Zig ಮೂಲಕ ಲೆಕ್ಕಹಾಕುವ ಸರ್ವರ್-ಸೈಡ್ ಸಮಗ್ರತಾ ಪರಿಶೀಲನೆ. OmniRoute ಇದನ್ನು `xxhash-wasm` ಬಳಸಿ ಮರುಅನುಷ್ಠಾನಗೊಳಿಸುತ್ತದೆ:

1. `cch=00000;` ಪ್ಲೇಸ್ಹೋಲ್ಡರ್ನೊಂದಿಗೆ ಬಾಡಿಯನ್ನು ಸೀರಿಯಲೈಸ್ ಮಾಡಿ
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. ಸೊನ್ನೆಗಳಿಂದ ಪ್ಯಾಡ್ ಮಾಡಲಾದ 5-ಅಕ್ಷರಗಳ ಲೋವರ್ಕೇಸ್ ಹೆಕ್ಸ್
4. `cch=00000;` ಅನ್ನು ಲೆಕ್ಕಹಾಕಿದ ಟೋಕನ್ನಿಂದ ಬದಲಾಯಿಸಿ

ಸ್ಥಿರಾಂಕಗಳು:

- ಸೀಡ್: `0x6e52736ac806831e`
- ಪ್ಯಾಟರ್ನ್: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

ಅಪ್ಸ್ಟ್ರೀಮ್ ಫಿಲ್ಟರ್ಗಳು ಅವುಗಳನ್ನು grep ಮಾಡದಂತೆ, "ಸೂಕ್ಷ್ಮ" ಕ್ಲೈಂಟ್ ಹೆಸರುಗಳ ಮೊದಲ ಅಕ್ಷರದ ನಂತರ Unicode **ಶೂನ್ಯ-ಅಗಲದ ಜಾಯಿನರ್** (`U+200D`) ಅನ್ನು ಸೇರಿಸುತ್ತದೆ. ಡೀಫಾಲ್ಟ್ ಪದಗಳ ಪಟ್ಟಿ:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

ಇವುಗಳಿಗೆ ಅನ್ವಯಿಸಲಾಗುತ್ತದೆ: `system` ಬ್ಲಾಕ್ಗಳು, ಎಲ್ಲಾ `messages[].content`, ಮತ್ತು `tools[].description` / `tools[].function.description`. `setSensitiveWords()` ಮೂಲಕ ಆಪರೇಟರ್ ಇದನ್ನು ಅತಿಕ್ರಮಿಸಬಹುದು.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` ಪೂರೈಕೆದಾರರು

"ನೈಜ Claude Code" ಟ್ರಾಫಿಕ್ ಅನ್ನು ಮಾತ್ರ ಸ್ವೀಕರಿಸುವ ತೃತೀಯ-ಪಕ್ಷ Anthropic ರಿಲೇಗಳಿಗಾಗಿ:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.280 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- ಡೀಫಾಲ್ಟ್ ಆಗಿ `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- ಪ್ರತಿಯೊಂದು ಸಂಪರ್ಕದ "Enable redact-thinking beta" ಟಾಗಲ್, CC Compatible ಅಪ್ಸ್ಟ್ರೀಮ್ಗೆ ನಿರ್ದಿಷ್ಟವಾಗಿ ರಿಡ್ಯಾಕ್ಟ್ ಮಾಡಿದ ಥಿಂಕಿಂಗ್ ಸ್ಟ್ರೀಮ್ಗಳು ಅಗತ್ಯವಿದ್ದಾಗ `redact-thinking-2026-02-12` ಅನ್ನು ಸೇರಿಸುತ್ತದೆ
- ಪ್ರತಿಯೊಂದು ಸಂಪರ್ಕದ "Enable summarized thinking display" ಟಾಗಲ್, `providerSpecificData.requestDefaults.summarizeThinking` ಅನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ ಮತ್ತು ಈಗಾಗಲೇ ಡಿಸ್ಪ್ಲೇ ಮೋಡ್ ಹೊಂದಿಸದ CC Compatible ಥಿಂಕಿಂಗ್ ವಿನಂತಿಗಳಿಗೆ `display: "summarized"` ಅನ್ನು ಸೇರಿಸುತ್ತದೆ
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x ಕುಟುಂಬ)
- ಡೀಫಾಲ್ಟ್ ಪಥ: `/v1/messages?beta=true`

ಅದೇ ಬಂಡಲ್ನಲ್ಲಿರುವ ಸಂಬಂಧಿತ ಮಾಡ್ಯೂಲ್ಗಳು:

- `claudeCodeConstraints.ts` — ಟೆಂಪರೇಚರ್ + ಕ್ಯಾಶ್-ಕಂಟ್ರೋಲ್ ನಿಯಮಗಳು
- `claudeCodeToolRemapper.ts` — ಟೂಲ್-ಹೆಸರು ಮರುಮ್ಯಾಪಿಂಗ್
- `claudeCodeExtraRemap.ts` — ಹೆಚ್ಚುವರಿ ಪೇಲೋಡ್ ಸಾಮಾನ್ಯೀಕರಣ

## Antigravity ಸ್ಟೆಲ್ತ್

Antigravity ವಿನಂತಿಗಳು ಕಾಲರ್ ಪಠ್ಯ ಬೈಟ್-ಫಾರ್-ಬೈಟ್ ಅನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ. IDE ಕ್ಲೈಂಟ್ ಅನ್ನು ಅನುಕರಿಸಲು OmniRoute ಪ್ರಾಂಪ್ಟ್ಗಳು ಅಥವಾ rename/inject ಪರಿಕರಗಳಲ್ಲಿ ಶೂನ್ಯ-ಅಗಲ ಅಕ್ಷರಗಳನ್ನು ಸೇರಿಸುವುದಿಲ್ಲ.

### `antigravityHeaderScrub.ts`

ಫಾರ್ವರ್ಡ್ ಮಾಡುವ ಮೊದಲು ಸ್ಟೇನ್ಲೆಸ್ SDK ಮಾರ್ಕರ್ಗಳನ್ನು (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) ಪಟ್ಟಿ ಮಾಡಿ.

### ⚠️ ಅಪಾಯ: `ANTIGRAVITY_CREDITS=always` (ಖಾತೆ-ನಿಷೇಧ ಹಾಟ್ ಸ್ಪಾಟ್)

`ANTIGRAVITY_CREDITS=always` ( `open-sse/executors/antigravity.ts` ನಿಂದ ಸೇವಿಸಲಾಗುತ್ತದೆ) ಮಾರ್ಗಗಳು**ಪ್ರತಿ** Google ನ ಉಚಿತ-ಶ್ರೇಣಿಯ ಕೋಟಾ ಗೇಟ್ ವಿಷಯಗಳನ್ನು ಅನುಮತಿಸುವ ಬದಲು Antigravity AI ಕ್ರೆಡಿಟ್ ಓವರ್ಗಳು (ಪಾವತಿಸಿದ Google ಕ್ರೆಡಿಟ್ಗಳು) ಮೂಲಕ ವಿನಂತಿಸಿ. ಇದನ್ನು ವೈಶಿಷ್ಟ್ಯವಾಗಿ ದಾಖಲಿಸಲಾಗಿದೆ, ಆದರೆ ಅದು**ನಾವು ನೋಡುವ ಏಕೈಕ ಸಾಮಾನ್ಯ ToS ಉಲ್ಲಂಘನೆ ವರದಿ** `=always` ನೊಂದಿಗೆ ಕೆಲವು ಗಂಟೆಗಳ ಕಾಲ ಓಡಿದ ನಂತರ `403 / "service disabled for ToS violation" / insufficient_quota` ನೊಂದಿಗೆ — ಬಹು Google ಅಲ್ಟ್ರಾ ಖಾತೆಗಳನ್ನು ನಿಷೇಧಿಸಲಾಗಿದೆ.

ಅಪ್ಸ್ಟ್ರೀಮ್ ಜಾರಿ ಆನ್ ಆಗಿದೆ**Google ಕಡೆ** , OmniRoute ಯಾವುದನ್ನೂ ತಡೆಯಲು ಸಾಧ್ಯವಿಲ್ಲ. env var ಹೆಸರು ಮತ್ತು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಡಾಕ್ಸ್ ಫ್ಲಿಪ್ ಮಾಡಲು ಸುರಕ್ಷಿತ ನಾಬ್ನಂತೆ ಧ್ವನಿಸುತ್ತದೆ; ಅದು ಅಲ್ಲ.

**ಇದು ಉಚಿತ-ಶ್ರೇಣಿಯ-ಮಾತ್ರ ಬಳಕೆಗಿಂತ ಹೆಚ್ಚು ಆಕ್ರಮಣಕಾರಿಯಾಗಿ ನಿಂದನೆ ಪತ್ತೆಹಚ್ಚುವಿಕೆಯನ್ನು ಏಕೆ ಸೆಳೆಯುತ್ತದೆ:**

- ಉಚಿತ-ಶ್ರೇಣಿಯ ಹಿಟ್ಗಳು-ಕೋಟಾ-ಮತ್ತು-ನಿಲುಗಡೆಗಳಿಗಿಂತ ವಿಭಿನ್ನವಾಗಿ ಒಂದೇ Google ಖಾತೆ ಫ್ಲ್ಯಾಗ್ಗಳಲ್ಲಿ ನಿರಂತರವಾದ ಸ್ವಯಂಚಾಲಿತ ಖರ್ಚು.
- ಕ್ರೆಡಿಟ್ ಮಿತಿಮೀರಿದ ಯಾವುದೇ ದರದ ಸೀಲಿಂಗ್ ಅನ್ನು ಹೊಂದಿಲ್ಲ, ಆದ್ದರಿಂದ ತಪ್ಪಾಗಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ ಕ್ಲೈಂಟ್ ಹಲವಾರು ನೂರು USD ಮೂಲಕ ನಿಮಿಷಗಳಲ್ಲಿ ಬರ್ನ್ ಮಾಡಬಹುದು ಮತ್ತು API-ಕೀ ಮರುಮಾರಾಟ ಅಥವಾ ಬೋಟ್ ಟ್ರಾಫಿಕ್ನಂತೆ ಕಾಣಿಸಬಹುದು.
- ಬಹು OmniRoute ಬಳಕೆದಾರರು ಅದೇ ಬಾಹ್ಯ IP ಸಂಯುಕ್ತಗಳಿಂದ ಸಮಾನಾಂತರವಾಗಿ ಮಿತಿಮೀರಿದ ಕ್ರೆಡಿಟ್ಗಳನ್ನು ಹೊಡೆಯುತ್ತಾರೆ.

**ಶಿಫಾರಸು ಮಾಡಲಾದ ಭಂಗಿ:**

1. ಆಪರೇಟರ್ ಸ್ಪಷ್ಟವಾಗಿ ಪಾವತಿಸಿದ-ಕ್ರೆಡಿಟ್ ಮತ್ತು ಖಾತೆಯನ್ನು ಜಾರಿಗೊಳಿಸುವ ಅಪಾಯವನ್ನು ಸ್ವೀಕರಿಸದ ಹೊರತು ಡೀಫಾಲ್ಟ್ `ANTIGRAVITY_CREDITS=off` ಇರಿಸಿಕೊಳ್ಳಿ. `retry` ಮೊದಲು ಸಾಮಾನ್ಯ ವಿನಂತಿಯನ್ನು ಕಳುಹಿಸುತ್ತದೆ ಮತ್ತು ಅರ್ಹ ಕೋಟಾ 429 ರ ನಂತರ ಒಮ್ಮೆ ಕ್ರೆಡಿಟ್ಗಳನ್ನು ಚುಚ್ಚುತ್ತದೆ; `always` ಮೊದಲ ವಿನಂತಿಯ ಮೇಲೆ ಕ್ರೆಡಿಟ್ಗಳನ್ನು ಚುಚ್ಚುತ್ತದೆ.
2. **ಆಟೋ-ಕಾಂಬೋ ಮೂಲಕ ಪೂರೈಕೆದಾರರಾದ್ಯಂತ ಲೋಡ್ ಅನ್ನು ಹರಡಿ** (`model: "auto"` ಅಥವಾ `kr/glm/etc` -combo) ಒಂದೇ Antigravity ಖಾತೆಯನ್ನು ಸ್ಯಾಚುರೇಟ್ ಮಾಡುವ ಬದಲು.
3. **ಪ್ರತಿ ಸಂಪರ್ಕಕ್ಕೆ RPM ಮಿತಿಗಳನ್ನು ಹೊಂದಿಸಿ** Antigravity ಪೂರೈಕೆದಾರರ ಸಂಪಾದನೆ ಪುಟದಲ್ಲಿ (ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಪೂರೈಕೆದಾರರು → Antigravity → ಸಂಪರ್ಕ → ದರ ಮಿತಿ). 30-60 RPM ನಿರಂತರ ಬಳಕೆಗಾಗಿ ರಕ್ಷಣಾತ್ಮಕ ಮೇಲ್ಬೌಂಡ್ ಆಗಿದೆ.
4. **ಸ್ಥಿರ, ಆಪರೇಟರ್-ನಿಯಂತ್ರಿತ ಅಪ್ಸ್ಟ್ರೀಮ್ ನೆಟ್ವರ್ಕಿಂಗ್ ಬಳಸಿ** ಮತ್ತು ಸಂಬಂಧವಿಲ್ಲದ ಬಳಕೆದಾರರು ಅಥವಾ ಕೆಲಸದ ಹೊರೆಗಳಾದ್ಯಂತ ಒಂದು ಖಾತೆಯನ್ನು ಹಂಚಿಕೊಳ್ಳುವುದನ್ನು ತಪ್ಪಿಸಿ.
5. **ನಿಷೇಧಿಸಿದರೆ** : ನಿಖರವಾದ `quota_exceeded` / `service disabled` ಪ್ರತಿಕ್ರಿಯೆ ದೇಹದ Google ಕಳುಹಿಸುವುದರೊಂದಿಗೆ `support.google.com` → " Workspace/Account ಪ್ರವೇಶವನ್ನು ಮರುಸ್ಥಾಪಿಸಿ" ಮೂಲಕ ಮನವಿ ಮಾಡಿ. ಪುನಃಸ್ಥಾಪನೆ ಖಾತರಿಯಿಲ್ಲ.

ಪರಿಸರದ ಉಲ್ಲೇಖವು ಪ್ರತಿ ಕ್ರೆಡಿಟ್ ಮೋಡ್ನ ಖಾತೆ ಮತ್ತು ಖರ್ಚು ಪರಿಣಾಮಗಳನ್ನು ದಾಖಲಿಸುತ್ತದೆ.

#### `=always` ಮಾತ್ರವಲ್ಲ : ಸಾಮಾನ್ಯವಾಗಿ Antigravity OAuth ರೂಟಿಂಗ್

ಅಮಾನತುಗಳು ಕ್ರೆಡಿಟ್ ಮಿತಿಮೀರಿದವುಗಳಿಗೆ ಸೀಮಿತವಾಗಿಲ್ಲ. ನವೆಂಬರ್ 2026 ರಲ್ಲಿನ ವರದಿಗಳು (#19223, #19266) `antigravity` ಮತ್ತು `agy` (Antigravity CLI) ಪೂರೈಕೆದಾರರ ಮೂಲಕ ರೂಟಿಂಗ್ ಮಾಡುವಾಗ ಹಲವಾರು Google ಖಾತೆಗಳನ್ನು ಅಮಾನತುಗೊಳಿಸಲಾಗಿದೆ, ಜೊತೆಗೆ:

```
403: This service has been disabled in this account for violation of Terms of Service.
Please submit an appeal to continue using this product.
```

ಎರಡೂ ಪೂರೈಕೆದಾರರು Antigravity ಉತ್ಪನ್ನ OAuth ಸೆಶನ್ನೊಂದಿಗೆ ಪ್ರಮಾಣೀಕರಿಸುತ್ತಾರೆ, ಇದು ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ ಅಪಾಯದ ಸೂಚನೆ ("ಈ ಪೂರೈಕೆದಾರರು ನಿಮ್ಮ ಅಧಿಕೃತ ಉತ್ಪನ್ನ session/OAuth ಅನ್ನು ಬಳಸುತ್ತಾರೆ, ಇದು proxy/router ಬಳಕೆಗೆ ಅಧಿಕೃತವಾಗಿಲ್ಲ") ಸಂಪರ್ಕವನ್ನು ಸೇರಿಸುವ ಮೊದಲು ಎಚ್ಚರಿಕೆ ನೀಡುತ್ತದೆ. ಮೇಲಿನ ಯಾವುದೇ ಶಿಫಾರಸುಗಳು ಆ ಬಳಕೆಯನ್ನು ಅಧಿಕೃತಗೊಳಿಸುವುದಿಲ್ಲ; ಒಂದು ಖಾತೆಯು ಎಷ್ಟು ಟ್ರಾಫಿಕ್ ಅನ್ನು ಸಾಗಿಸುತ್ತದೆ ಎಂಬುದನ್ನು ಮಾತ್ರ ಅವರು ಕಡಿಮೆ ಮಾಡುತ್ತಾರೆ.

**Gemini ಮಾದರಿಗಳಿಗಾಗಿ ಅಧಿಕೃತ API ಇಂಟರ್ಫೇಸ್ಗಳು.** Google ತನ್ನ APIs ಮೂಲಕ Gemini ಗೆ ಪ್ರೋಗ್ರಾಮ್ಯಾಟಿಕ್ ಪ್ರವೇಶವನ್ನು ನೀಡುತ್ತದೆ, ಇದನ್ನು OmniRoute ಸಾಮಾನ್ಯ API-ಕೀ ಪೂರೈಕೆದಾರರಾಗಿ ಬೆಂಬಲಿಸುತ್ತದೆ:

| ಪೂರೈಕೆದಾರರ ಐಡಿ | ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಹೆಸರು          | ರುಜುವಾತು                                                                      |
| -------------- | --------------------------- | ----------------------------------------------------------------------------- |
| `gemini`       | Gemini (Google AI ಸ್ಟುಡಿಯೋ) | Google AI ಸ್ಟುಡಿಯೋದಿಂದ Gemini API ಕೀ (ಉಚಿತ ಶ್ರೇಣಿ ಲಭ್ಯವಿದೆ)                   |
| `vertex`       | ವರ್ಟೆಕ್ಸ್ AI                | ಸೇವಾ ಖಾತೆ JSON, OAuth ಪ್ರವೇಶ ಟೋಕನ್ ಅಥವಾ ವರ್ಟೆಕ್ಸ್ ಎಕ್ಸ್ಪ್ರೆಸ್ API ಕೀ (Gemini) |

ಈ ಪೂರೈಕೆದಾರರು API ಪ್ರವೇಶಕ್ಕಾಗಿ ರುಜುವಾತುಗಳ Google ಸಮಸ್ಯೆಗಳನ್ನು ಬಳಸುತ್ತಾರೆ, Antigravity ಉತ್ಪನ್ನ ಸೆಷನ್ಗಿಂತ ಭಿನ್ನವಾಗಿ. ಅವರು ಪ್ರತಿ ಬಳಕೆಯನ್ನು ಅನುಸರಣೆ ಮಾಡುವುದಿಲ್ಲ ಅಥವಾ ಜಾರಿಗೊಳಿಸುವ ಅಪಾಯವನ್ನು ತೆಗೆದುಹಾಕುವುದಿಲ್ಲ: ಪ್ರತಿಯೊಂದೂ ತನ್ನದೇ ಆದ ನಿಯಮಗಳಿಂದ ನಿಯಂತ್ರಿಸಲ್ಪಡುತ್ತದೆ, ಅದರ ನಿಯೋಜನೆಯನ್ನು ಆಪರೇಟರ್ ಪರಿಶೀಲಿಸಬೇಕಾಗುತ್ತದೆ. ಉದಾಹರಣೆಗೆ, [Gemini API ಹೆಚ್ಚುವರಿ ಸೇವಾ ನಿಯಮಗಳು](https://ai.google.dev/gemini-api/terms) API ಕ್ಲೈಂಟ್ಗಳು ಯುರೋಪಿಯನ್ ಎಕನಾಮಿಕ್ ಏರಿಯಾ, ಸ್ವಿಟ್ಜರ್ಲೆಂಡ್ ಅಥವಾ ಯುನೈಟೆಡ್ ಕಿಂಗ್ಡಮ್ನಲ್ಲಿರುವ ಬಳಕೆದಾರರಿಗೆ ಲಭ್ಯವಾದಾಗ ಪಾವತಿಸಿದ ಸೇವೆಗಳನ್ನು ಮಾತ್ರ ಅನುಮತಿಸುತ್ತವೆ ಮತ್ತು ಪಾವತಿಸದ ಸೇವೆಗಳಿಗೆ ಕಳುಹಿಸಲಾದ ವಿಷಯವನ್ನು Google ನ ಉತ್ಪನ್ನಗಳನ್ನು ಸುಧಾರಿಸಲು ಬಳಸಬಹುದು. ವರ್ಟೆಕ್ಸ್ AI ಬದಲಿಗೆ Google ಕ್ಲೌಡ್ ನಿಯಮಗಳ ಅಡಿಯಲ್ಲಿ ಬರುತ್ತದೆ ( [ಸೇವಾ ನಿರ್ದಿಷ್ಟ ನಿಯಮಗಳು](https://cloud.google.com/terms/service-terms) ). ಬೆಲೆ ಮತ್ತು ಕೋಟಾಗಳು Antigravity ಚಂದಾದಾರಿಕೆಯ ಬದಲಿಗೆ API ನಿಯಮಗಳನ್ನು ಅನುಸರಿಸುತ್ತವೆ.

ಮೇಲೆ ವಿವರಿಸಿದ Antigravity ಅಮಾನತುಗಳನ್ನು ತಪ್ಪಿಸಲು ಬಯಸುವ ನಿರ್ವಾಹಕರು `antigravity` / `agy` ಬದಲಿಗೆ ಈ ಪೂರೈಕೆದಾರರಲ್ಲಿ ಒಬ್ಬರ ಮೂಲಕ Gemini ಟ್ರಾಫಿಕ್ ಅನ್ನು ರೂಟ್ ಮಾಡಬೇಕು, ಅವರ ಬಳಕೆಯು ಪೂರೈಕೆದಾರರ ನಿಯಮಗಳಿಗೆ ಸರಿಹೊಂದುತ್ತದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿದ ನಂತರ.

ಸ್ಪರ್ಶ ಬಿಂದುಗಳು:

- `open-sse/executors/antigravity.ts` — `process.env.ANTIGRAVITY_CREDITS` ಓದುತ್ತದೆ
- `src/lib/oauth/providers/antigravity.ts` — ರುಜುವಾತು ಕೊಳಾಯಿ
- ಮೂಲ ಘಟನೆ ವರದಿ: ಚರ್ಚೆ [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## CLI ಫಿಂಗರ್ಪ್ರಿಂಟ್ ರಿಜಿಸ್ಟ್ರಿ — `open-sse/config/cliFingerprints.ts`

ಅಧಿಕೃತ CLIಗಳ mitmproxy ಟ್ರೇಸ್ಗಳಿಂದ ಸೆರೆಹಿಡಿದ **ನಿಖರವಾದ** ಹೆಡರ್ ಕ್ರಮ ಮತ್ತು JSON ಬಾಡಿ ಫೀಲ್ಡ್ ಕ್ರಮವನ್ನು ಪ್ರತಿ ಪೂರೈಕೆದಾರರ ಆಧಾರದಲ್ಲಿ ಸ್ಥಿರಗೊಳಿಸುವ ಕೋಷ್ಟಕ. ಪ್ರಸ್ತುತ ನೋಂದಾಯಿತವಾಗಿರುವವು: `codex`, `claude`, ಜೊತೆಗೆ `antigravity` ಮತ್ತು `github`ಗಾಗಿ `providerHeaderProfiles.ts`ನಲ್ಲಿರುವ ರನ್ಟೈಮ್ನಿಂದ ಪಡೆದ ಪ್ರೊಫೈಲ್ಗಳು.

```ts
interface CliFingerprint {
  headerOrder: string[]; // ಕೇಸ್-ಸೆನ್ಸಿಟಿವ್
  bodyFieldOrder: string[]; // ಉನ್ನತ-ಮಟ್ಟದ JSON ಕೀಗಳು
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

ಪ್ರತಿ ಪೂರೈಕೆದಾರರಿಗಾಗಿ env ಮೂಲಕ ಟಾಗಲ್ ಮಾಡಿ (ಕೆಳಗೆ ನೋಡಿ). ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿದಾಗ, ಹೆಡರ್ಗಳು/ಬಾಡಿ ಕೀಗಳು Node/JSON ನೀಡಿದ ಯಾವುದೇ ಕ್ರಮದಲ್ಲಿ ಕಾಣಿಸಿಕೊಳ್ಳುತ್ತವೆ — ಸುಲಭವಾಗಿ ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಮಾಡಬಹುದು.

## MITM ಪ್ರಾಕ್ಸಿ (Antigravity, Linux/macOS/Windows)

`OPENAI_BASE_URL` ಮೂಲಕ ಬೈನರಿಗಳನ್ನು ಮರುನಿರ್ದೇಶಿಸಲಾಗದ CLIಗಳಿಗಾಗಿ, OmniRoute ಸ್ಥಳೀಯ TLS-ಟರ್ಮಿನೇಟಿಂಗ್ ಪ್ರಾಕ್ಸಿಯನ್ನು ಚಲಾಯಿಸುತ್ತದೆ. ಎಂಡ್ಪಾಯಿಂಟ್ಗಳು `src/app/api/cli-tools/antigravity-mitm/` ಅಡಿಯಲ್ಲಿ ಇವೆ.

| ವಿಧಾನ  | ಎಂಡ್ಪಾಯಿಂಟ್                             | ಉದ್ದೇಶ                                                  |
| ------ | --------------------------------------- | ------------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | ಸ್ಥಿತಿ — ಚಾಲನೆಯಲ್ಲಿದೆಯೇ, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM ಪ್ರಾರಂಭಿಸಿ (`apiKey` + `sudoPassword` ಅಗತ್ಯವಿದೆ)   |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM ನಿಲ್ಲಿಸಿ                                           |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | ಮಾಡೆಲ್ ಅಲಿಯಾಸ್ಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ                         |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | ಸಾಧನಕ್ಕಾಗಿ ಮಾಡೆಲ್ ಅಲಿಯಾಸ್ಗಳನ್ನು ಉಳಿಸಿ                   |

ಪ್ರತಿಬಂಧಿಸಲಾಗುವ ಗುರಿ ಹೋಸ್ಟ್: **`daily-cloudcode-pa.googleapis.com`** (Antigravityಯ ಅಪ್ಸ್ಟ್ರೀಮ್).

### ಪ್ರಾರಂಭದ ಅನುಕ್ರಮ (`src/mitm/manager.ts::startMitm`)

1. `selfsigned` ಮೂಲಕ ಸ್ವಯಂ-ಸಹಿ ಮಾಡಿದ ಪ್ರಮಾಣಪತ್ರವನ್ನು ರಚಿಸಿ (RSA-2048, SHA-256, 1y) — `cert/generate.ts`
2. ಸಿಸ್ಟಂ ಟ್ರಸ್ಟ್ ಸ್ಟೋರ್ಗೆ ಪ್ರಮಾಣಪತ್ರವನ್ನು ಸ್ಥಾಪಿಸಿ — `cert/install.ts`
3. `127.0.0.1 daily-cloudcode-pa.googleapis.com` ಹೋಸ್ಟ್ಸ್ ನಮೂದನ್ನು ಸೇರಿಸಿ — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (ಡೀಫಾಲ್ಟ್ `443`) ಜೊತೆಗೆ `src/mitm/server.cjs` ಅನ್ನು ಸ್ಪಾನ್ ಮಾಡಿ
5. PID ಅನ್ನು `<DATA_DIR>/mitm/.mitm.pid`ಗೆ ಶಾಶ್ವತವಾಗಿ ಉಳಿಸಿ

### Linux ಡೈನಾಮಿಕ್ ಟ್ರಸ್ಟ್-ಸ್ಟೋರ್ ಪತ್ತೆ — `cert/install.ts`

`getLinuxCertConfig()` ಆದ್ಯತಾ ಪಟ್ಟಿಯ ಮೂಲಕ ಪರಿಶೀಲಿಸಿ, ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಮೊದಲ ಡೈರೆಕ್ಟರಿಯನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತದೆ:

| ಡಿಸ್ಟ್ರೋ ಕುಟುಂಬ          | ಡೈರೆಕ್ಟರಿ                                   | ಅಪ್ಡೇಟ್ ಕಮಾಂಡ್           |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

ಪ್ರಮಾಣಪತ್ರದ ಫೈಲ್ ಹೆಸರು: `omniroute-mitm.crt`. `getCertFingerprint()` ಮೂಲಕ ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಹೊಂದಾಣಿಕೆ (DERನ SHA-1).

ಹೆಚ್ಚುವರಿಯಾಗಿ, `certutil` ಲಭ್ಯವಿರುವಾಗ `updateNssDatabases()` ಪ್ರತಿ ಬಳಕೆದಾರರ NSS DBಗಳಲ್ಲಿ ಸ್ಥಾಪಿಸುತ್ತದೆ: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, ಎಲ್ಲಾ Firefox ಪ್ರೊಫೈಲ್ಗಳು (snap ಸೇರಿದಂತೆ), **`OmniRoute MITM Root CA`** ಎಂಬ ಅಡ್ಡಹೆಸರಿನ ಅಡಿಯಲ್ಲಿ.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** ಎಲಿವೇಟೆಡ್ PowerShell → `certutil -addstore Root`

### ದೃಢೀಕರಣ

ಎಲ್ಲಾ MITM ಎಂಡ್ಪಾಯಿಂಟ್ಗಳಿಗೆ ನಿರ್ವಹಣಾ ದೃಢೀಕರಣ (`requireCliToolsAuth`) ಅಗತ್ಯವಿದೆ. sudo ಪಾಸ್ವರ್ಡ್ ಅನ್ನು ಮಾಡ್ಯೂಲ್ ಸ್ಕೋಪ್ನಲ್ಲಿ ಕ್ಯಾಶ್ ಮಾಡಲಾಗುತ್ತದೆ (`globalThis`ನಲ್ಲಿ ಎಂದಿಗೂ ಅಲ್ಲ) ಮತ್ತು `stopMitm()`ನಲ್ಲಿ ತೆರವುಗೊಳಿಸಲಾಗುತ್ತದೆ.

## ಒಳಬರುವ ಹೆಡರ್ಗಳ ಶುದ್ಧೀಕರಣ

Cursor ನಿಂದ ಬರುವ ವಿನಂತಿಯು Claude ಅಪ್ಸ್ಟ್ರೀಮ್ಗೆ `User-Agent: Cursor/X.Y.Z` ಅನ್ನು ಸೋರಿಕೆ ಮಾಡದಂತೆ, ಫಾರ್ವರ್ಡ್ ಮಾಡುವ ಮೊದಲು OmniRoute ಒಳಬರುವ ಕ್ಲೈಂಟ್ ಹೆಡರ್ಗಳನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ. Zod ಸ್ಕೀಮಾಗಳು ಮತ್ತು ಯುನಿಟ್ ಪರೀಕ್ಷೆಗಳೊಂದಿಗೆ ಏಕಕಾಲದಲ್ಲಿ ನಿರ್ವಹಿಸಲಾಗುವ ನಿರಾಕರಣಾ ಪಟ್ಟಿಗಾಗಿ `src/shared/constants/upstreamHeaders.ts` ಅನ್ನು ನೋಡಿ.

## ಪೂರೈಕೆದಾರರು ಬದಲಾಯಿಸಿದಾಗ ಫಿಂಗರ್ಪ್ರಿಂಟ್ಗಳನ್ನು ನವೀಕರಿಸುವುದು

1. `mitmproxy` ಬಳಸಿ ಅಧಿಕೃತ CLI ಟ್ರಾಫಿಕ್ ಅನ್ನು ಸೆರೆಹಿಡಿಯಿರಿ (TLS ಪ್ರತಿಬಂಧಿಸುವಿಕೆ + ಡಂಪ್)
2. JA3/JA4 ಮತ್ತು ಅಕ್ಷರಶಃ ಹೆಡರ್ ಕ್ರಮವನ್ನು ಹೊರತೆಗೆಯಿರಿ
3. ಸಂಬಂಧಿತ `CLI_FINGERPRINTS[...]` ನಮೂದನ್ನು ನವೀಕರಿಸಿ
4. `.env.example` ನಲ್ಲಿ ಹೊಂದಿಕೆಯಾಗುವ `*_USER_AGENT` ಡೀಫಾಲ್ಟ್ ಅನ್ನು ಪರಿಷ್ಕರಿಸಿ
5. TLS ಹ್ಯಾಂಡ್ಶೇಕ್ ಸ್ವತಃ ಬದಲಾಗಿದ್ದರೆ, ಸಂಬಂಧಿತ ಪೂರೈಕೆದಾರ ರ್ಯಾಪರ್ ಅಥವಾ wreq-js `browser:` ಆಯ್ಕೆಯನ್ನು ನವೀಕರಿಸಿ
6. ಪೂರೈಕೆದಾರ-ನಿರ್ದಿಷ್ಟ TLS ಪರೀಕ್ಷೆಗಳನ್ನು ಮತ್ತು ಲೈವ್ ಪೂರೈಕೆದಾರರ ವಿರುದ್ಧ ಹಸ್ತಚಾಲಿತ ಕ್ಯಾನರಿ ಪರೀಕ್ಷೆಯನ್ನು ಚಲಾಯಿಸಿ
7. ಪ್ಯಾಚ್ ಬಿಡುಗಡೆಯಲ್ಲಿ ರವಾನಿಸಿ; `CHANGELOG.md` ನಲ್ಲಿ ದಾಖಲಿಸಿ
