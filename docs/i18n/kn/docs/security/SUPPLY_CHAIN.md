OmniRoute npm + Docker ಆರ್ಟಿಫ್ಯಾಕ್ಟ್ಗಳನ್ನು ಪ್ರಕಟಿಸುತ್ತದೆ. ಈ ಗೇಟ್ಗಳು ಪ್ರಾವೆನೆನ್ಸ್, ಇನ್ವೆಂಟರಿ (SBOM) ಮತ್ತು CVE ಸ್ಕ್ಯಾನಿಂಗ್ ಅನ್ನು ಒದಗಿಸುತ್ತವೆ, ಇವೆಲ್ಲವೂ OSS ಆಗಿದ್ದು, ಬಿಡುಗಡೆ ವರ್ಕ್ಫ್ಲೋಗಳಿಗೆ ಸಂಪರ್ಕಗೊಂಡಿವೆ. **ಸಲಹಾ-ಮೊದಲ** ನಿಲುವು — ಅವು ಈಗ ವರದಿ ಮಾಡುತ್ತವೆ, ಮೊದಲ ಹಸಿರು ಬಿಡುಗಡೆಯ ನಂತರ ನಿರ್ಬಂಧಿಸಲು ಪ್ರಚಾರ ಮಾಡುತ್ತವೆ.

| ಗೇಟ್                  | ಟೂಲ್                                           | ಎಲ್ಲಿದೆ                       | ನಿರ್ಬಂಧಿಸುತ್ತದೆಯೇ?       | ಔಟ್ಪುಟ್                                                     |
| --------------------- | ---------------------------------------------- | ----------------------------- | ------------------------ | ----------------------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | ಪ್ರಕಟಣೆ ವಿಫಲವಾದರೆ ಮಾತ್ರ  | ಬ್ಯಾಡ್ಜ್ npmjs / `npm audit signatures`                     |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | ಉತ್ಪಾದನೆ ವಿಫಲವಾದರೆ ಮಾತ್ರ | ಬಿಡುಗಡೆ ಆಸ್ತಿ + ಆರ್ಟಿಫ್ಯಾಕ್ಟ್                               |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | ಸಲಹಾ                     | CycloneDX ಆರ್ಟಿಫ್ಯಾಕ್ಟ್                                     |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | ಸಲಹಾ                     | SARIF (HIGH+CRITICAL) → ಭದ್ರತಾ ಟ್ಯಾಬ್                       |
| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **ನಿರ್ಬಂಧಿಸುವಿಕೆ**       | ಸರಿಪಡಿಸಬಹುದಾದ CRITICAL ನಲ್ಲಿ `exit-code: '1'`               |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ನಿರ್ಬಂಧಿಸುವಿಕೆ**       | `metrics.vulnCount` ಅನ್ನು ರಾಚೆಟ್ ಮಾಡುತ್ತದೆ (direction:down) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | ಸಲಹಾ                     | SARIF → ಭದ್ರತೆ + ಬ್ಯಾಡ್ಜ್                                   |

ಇಮೇಜ್ CVE ರಾಚೆಟ್ `docker-publish.yml` ನಲ್ಲಿ **ಎರಡು ಹಂತಗಳನ್ನು** ಬಳಸುತ್ತದೆ: SARIF ಹಂತ (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL ಅನ್ನು ನಿರ್ಬಂಧಿಸದೆ ಭದ್ರತಾ ಟ್ಯಾಬ್ನಲ್ಲಿ ಗೋಚರಿಸುವಂತೆ ಮಾಡುತ್ತದೆ; _CRITICAL ಗೇಟ್_ ಹಂತ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) **ಪರಿಹಾರ ಲಭ್ಯವಿರುವ** CRITICAL CVE ಯಲ್ಲಿ ಬಿಡುಗಡೆಯನ್ನು ವಿಫಲಗೊಳಿಸುತ್ತದೆ. `ignore-unfixed` ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ಯಾಚ್ ಇಲ್ಲದೆ ಬೇಸ್-ಇಮೇಜ್ CVE ಗಾಗಿ ಬಿಡುಗಡೆಯನ್ನು ನಿರ್ಬಂಧಿಸುವುದನ್ನು ತಡೆಯುತ್ತದೆ.

## ⚠️ CVE ವ್ಯತ್ಯಾಸ (ನಿರ್ಬಂಧಿಸುವ osv/Trivy ಗೇಟ್ಗಳು)

osv ಮತ್ತು Trivy ಅವಲಂಬನೆಗಳನ್ನು **ನಿರಂತರವಾಗಿ ಬೆಳೆಯುವ** CVE ಡೇಟಾಬೇಸ್ಗಳೊಂದಿಗೆ ಹೋಲಿಸುತ್ತವೆ. **ಯಾವುದೇ ಅವಲಂಬನೆಗಳನ್ನು ಬದಲಾಯಿಸದ** PR ಕೂಡ, ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಅವಲಂಬನೆಯಲ್ಲಿ ಹೊಸ CVE ಬಹಿರಂಗಗೊಂಡ ಕಾರಣದಿಂದಾಗಿ ಇದ್ದಕ್ಕಿದ್ದಂತೆ ಕೆಂಪಾಗಬಹುದು (osv: ಮಾಪನ ಮಾಡಿದ `vulnCount` > ಬೇಸ್ಲೈನ್; Trivy: ಇಮೇಜ್ನಲ್ಲಿ ಸರಿಪಡಿಸಬಹುದಾದ ಹೊಸ CRITICAL). **ಇದು ನಿರ್ಬಂಧಿಸುವ CVE ಗೇಟ್ನ ನಿರೀಕ್ಷಿತ ಕಾರ್ಯಾಚರಣೆಯ ನಡವಳಿಕೆಯೇ ಹೊರತು, ಉತ್ಪನ್ನದ ಹಿಂಜರಿತವಲ್ಲ.**

ಹೊಸದಾಗಿ ಬಹಿರಂಗಗೊಂಡ CVE ಕಾರಣದಿಂದ osv ಅಥವಾ Trivy ಕೆಂಪಾದಾಗ, ಪರಿಹಾರ ಹೀಗಿದೆ:

1. **ಪರಿಣಾಮಕ್ಕೊಳಗಾದ ಅವಲಂಬನೆಯ ಆವೃತ್ತಿಯನ್ನು ಹೆಚ್ಚಿಸಿ** (ಆದ್ಯತೆ) — `package.json` ನಲ್ಲಿನ
   `overrides` (ಪರೋಕ್ಷ ಅವಲಂಬನೆಗಳು) ಮೂಲಕ ಪ್ಯಾಚ್ ಮಾಡಿದ ಆವೃತ್ತಿಗೆ ಅಪ್ಗ್ರೇಡ್ ಮಾಡಿ ಅಥವಾ ಪ್ಯಾಚ್ ಮಾಡಿದ ಬೇಸ್ನಲ್ಲಿ ಇಮೇಜ್ ಅನ್ನು ಮರುನಿರ್ಮಿಸಿ.
2. **ಅಪ್ಸ್ಟ್ರೀಮ್ ಪರಿಹಾರ ಇಲ್ಲದಿದ್ದರೆ:**
   - **osv:** ಸಮರ್ಥನೆಯ ಟಿಪ್ಪಣಿ + ಟ್ರ್ಯಾಕಿಂಗ್ ಇಶ್ಯೂ ಜೊತೆಗೆ `config/quality/quality-baseline.json` ನಲ್ಲಿ `metrics.vulnCount` ಗೆ ಮರು-ಬೇಸ್ಲೈನ್ ನಿಗದಿಪಡಿಸಿ
     (`npm run quality:ratchet -- --update` ಮೀಸಲಾದ ಗೇಟ್ಗಳನ್ನು ಒಳಗೊಳ್ಳುವುದಿಲ್ಲ — ಮೌಲ್ಯವನ್ನು ಕೈಯಿಂದ ಸಂಪಾದಿಸಿ,
     `direction:down`).
   - **Trivy:** ಸಮರ್ಥನೆಯ ಕಾಮೆಂಟ್ + ಟ್ರ್ಯಾಕಿಂಗ್ ಇಶ್ಯೂ ಜೊತೆಗೆ `.trivyignore` ನಲ್ಲಿ ಒಂದು ನಮೂದನ್ನು ಸೇರಿಸಿ (ಪ್ರತಿ ಸಾಲಿಗೆ ಒಂದು CVE-ID). ಪ್ಯಾಚ್ಗಳಿಲ್ಲದ CVEಗಳನ್ನು `ignore-unfixed: true` ಈಗಾಗಲೇ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಒಳಗೊಳ್ಳುತ್ತದೆ.

ಸ್ಕ್ಯಾನರ್, ವರದಿ ಅಥವಾ ಬೇಸ್ಲೈನ್ ಅನ್ನು ಮೌಲ್ಯೀಕರಿಸಲು ಸಾಧ್ಯವಾಗದಿದ್ದಾಗ, ಅಗತ್ಯವಿರುವ OSV ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಗಳು (`check:vuln-ratchet -- --ratchet`) `INCOMPLETE` ಜೊತೆಗೆ ವಿಫಲವಾಗಿ ಮುಚ್ಚುತ್ತವೆ ಮತ್ತು ನಿರ್ಗಮನ ಕೋಡ್ 2 ಅನ್ನು ನೀಡುತ್ತವೆ. ಮಾಪನ ಮಾಡಿದ ಹಿಂಜರಿತವು ನಿರ್ಗಮನ ಕೋಡ್ 1 ಅನ್ನು ನೀಡುತ್ತದೆ. ಸಲಹಾತ್ಮಕ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಯು ಇನ್ನೂ ನಿರ್ಗಮನ ಕೋಡ್ 0 ಜೊತೆಗೆ `SKIP` ಅನ್ನು ವರದಿ ಮಾಡಬಹುದು; ಇದರಿಂದ ಅವಲಂಬನೆಗಳು ಸ್ಕ್ಯಾನ್ನಲ್ಲಿ ಉತ್ತೀರ್ಣವಾಗಿವೆ ಎಂಬುದು ಸ್ಥಾಪನೆಯಾಗುವುದಿಲ್ಲ. ನಿರ್ಬಂಧಿಸುವ Trivy ಹಂತಕ್ಕೂ ಯಶಸ್ವಿ ಮಾಪನದ ಅಗತ್ಯವಿದೆ: ಲಭ್ಯವಿಲ್ಲದ ಪರಿಕರಗಳು, ವಿಫಲವಾದ ಜಾಬ್ಗಳು ಮತ್ತು ಕಾಣೆಯಾದ ಇಮೇಜ್ ಪುರಾವೆಗಳು ಇಮೇಜ್ ಸ್ವಚ್ಛವಾಗಿದೆ ಎಂದು ಪ್ರಮಾಣೀಕರಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ.

## ನಿವೃತ್ತಗೊಳಿಸಲಾದ ಅವಲಂಬನೆಯ ಅಪಾಯ

ಪಿನ್ ಮಾಡಲಾದ promptfoo ಅಭಿವೃದ್ಧಿ ಸಾಧನವನ್ನು ಅಪ್ಗ್ರೇಡ್ ಮಾಡಿದ ನಂತರ, ಮೂಲ ಲಾಕ್ಫೈಲ್ ಇನ್ನು ಮುಂದೆ `extract-zip` ಅಥವಾ ಅದಕ್ಕೆ ಸಂಪರ್ಕಿಸುವ ಅವಲಂಬನೆ ಅಂಚನ್ನು ಒಳಗೊಂಡಿಲ್ಲ. ಇದರಿಂದ #14482ರಲ್ಲಿ ಟ್ರ್ಯಾಕ್ ಮಾಡಲಾದ, ಹಿಂದೆ ಸ್ವೀಕರಿಸಿದ್ದ `promptfoo` → `@openai/codex-security` → `extract-zip` ಸರಪಳಿಯನ್ನು ನಿವೃತ್ತಗೊಳಿಸಲಾಗಿದೆ. `tests/unit/extract-zip-14482-exposure.test.ts`ನಲ್ಲಿರುವ ರಿಗ್ರೆಷನ್ ಪರಿಶೀಲನೆಗಳು ಅದನ್ನು ಮರುಪರಿಚಯಿಸುವುದನ್ನು ತಿರಸ್ಕರಿಸುತ್ತವೆ ಮತ್ತು ಪ್ರೊಡಕ್ಷನ್ ಕೋಡ್ನಿಂದ ಅದನ್ನು ಆಮದು ಮಾಡುವುದರ ಮೇಲಿನ ನಿಷೇಧವನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ.

ಪ್ರಸ್ತುತ ಅವಲಂಬನೆ ದುರಸ್ತಿಯು ಹೊಂದಾಣಿಕೆ ಅತಿಕ್ರಮಣಗಳನ್ನು Azure identityಯ MSAL ಕ್ಲೈಂಟ್, get-uriಯ FTP ಕ್ಲೈಂಟ್ ಮತ್ತು OpenCode v1 SDKಯ Zod ಅವಲಂಬನೆಗೆ ಮಾತ್ರ ಸೀಮಿತಗೊಳಿಸುತ್ತದೆ. Azure ಟೋಕನ್ ಪಡೆಯುವಿಕೆ ಮತ್ತು FTP ಮರುಪಡೆಯುವಿಕೆಯನ್ನು ನಿಯಂತ್ರಿತ ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್ಗಳೊಂದಿಗೆ ಪರೀಕ್ಷಿಸಲಾಗಿದೆ; ಎರಡೂ OpenCode ಪ್ಯಾಕೇಜ್ಗಳು ತಮ್ಮದೇ ಬಿಲ್ಡ್ ಮತ್ತು ಪರೀಕ್ಷಾ ಸೂಟ್ಗಳನ್ನು ಚಲಾಯಿಸುತ್ತವೆ. ರಿಜಿಸ್ಟ್ರಿ ಸಲಹಾ ಎಣಿಕೆಗಳು ನಿರ್ದಿಷ್ಟ ಸಮಯದ ಮಾಪನಗಳಾಗಿದ್ದು, ಲಾಕ್ಫೈಲ್ ಕಮಿಟ್ ಮಾಡಿದ ನಂತರ ಬದಲಾಗಬಹುದು.

## ಬ್ಯಾಕ್ಲಾಗ್: ಸ್ಕೋರ್ಕಾರ್ಡ್ ಸಲಹೆ → ನಿರ್ಬಂಧಿಸುವುದು

ಸ್ಕೋರ್ಕಾರ್ಡ್ ವರದಿ ಮಾಡುವಿಕೆಯೊಂದಿಗೆ 1 ನೇ ಹಸಿರು ಬಿಡುಗಡೆಯ ನಂತರ:

- ಸ್ಕೋರ್ಕಾರ್ಡ್: ಸ್ಕೋರ್ ರಾಟ್ಚೆಟ್ (ಅಳತೆ ಮಾಡಿದ ಸ್ಕೋರ್ ಅನ್ನು ಸ್ಥಿರಗೊಳಿಸುತ್ತದೆ; ಕಡಿಮೆಯಾಗಲು ಸಾಧ್ಯವಿಲ್ಲ).

ಫೇಸ್ 7 ಗೇಟ್ಗಳನ್ನು (osv-scanner, gitleaks, actionlint+zizmor) ಪೂರೈಸುತ್ತದೆ: zizmor ವರ್ಕ್ಫ್ಲೋಗಳನ್ನು ಆಡಿಟ್ ಮಾಡುತ್ತದೆ; ಸ್ಕೋರ್ಕಾರ್ಡ್ ರೆಪೊ ಭಂಗಿಯನ್ನು ಒಟ್ಟಾರೆಯಾಗಿ ಅಳೆಯುತ್ತದೆ.
