Kompletný návod na používanie Codex CLI nasmerovaného na OmniRoute ako backend kompatibilný s OpenAI.

---

> **TOML je jediný funkčný formát.** Moderný Codex načítava výhradne
> `~/.codex/config.toml` (overené s codex-cli 0.147.0: `codex --help` uvádza,
> že prepísania `-c/--config` sa „načítavajú z `~/.codex/config.toml`“). Starý
> `~/.codex/config.yaml` patril k staršiemu npm CLI a je bez upozornenia ignorovaný.
> Generátor na ovládacom paneli (`/api/cli-tools/apply`, nástroj `codex`) zapisuje TOML
> s konzervatívnym zlúčením — existujúce kľúče a bloky ostatných poskytovateľov sa
> zachovajú, kľúč API zostane v `OMNIROUTE_API_KEY` (nikdy nie v súbore) a prípadný
> pozostatok staršieho súboru `config.yaml` sa uvedie v poznámke k migrácii bez toho,
> aby sa zmenil.

## config.toml pripravený na vloženie

Nahraďte `<YOUR_HOST>` a `<YOUR_KEY>` svojimi hodnotami:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # limit ukladania histórie na jedno volanie nástroja

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc alebo ~/.zshrc — skutočná hodnota kľúča, nikdy nie v config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex zabalený v aplikácii ChatGPT

Ak ste Codex nainštalovali prostredníctvom desktopovej aplikácie ChatGPT, binárny
súbor `codex` sa môže nachádzať iba v balíku aplikácie a zatiaľ nemusí byť vo vašej
premennej `PATH` shellu. Pridajte adresár zdrojov do spúšťacieho súboru shellu:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Otvorte nový shell a potom overte:

```bash
command -v codex
codex --version
```

### Lokálny OmniRoute bez overovania: stačí zástupný kľúč

Codex overuje, či premenná prostredia určená hodnotou `env_key` existuje,
**predtým**, než prvá požiadavka opustí CLI. Ak vaša **lokálna** inštancia
OmniRoute nevyžaduje overovanie, postačí akákoľvek neprázdna zástupná hodnota:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Ak je váš server OmniRoute chránený alebo vzdialený, použite namiesto nej skutočný kľúč.

> **Bežné možnosti hostiteľa**
>
> | Prístup      | URL                           |
> | ------------ | ----------------------------- |
> | Lokálna sieť | `http://192.168.0.1:20128/v1` |
> | Tailscale    | `http://100.x.x.x:20128/v1`   |
> | Slučka       | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — prečo funguje pre všetky modely

Codex CLI vo februári 2026 označil `wire_api = "chat"` (Chat Completions) za zastarané a teraz **vyžaduje** `wire_api = "responses"` (OpenAI Responses API). Nastavenie `wire_api = "chat"` spôsobuje od verzie v0.138 okamžité zlyhanie pri spustení.

Mnohí poskytovatelia vrátane GLM a Kimi stále ponúkajú iba koncový bod Chat Completions. DeepSeek V4 teraz ponúka natívne Responses API, ako aj koncový bod kompatibilný s Anthropic; OmniRoute predvolene používa Responses a každému pripojeniu DeepSeek umožňuje vybrať kompatibilitu s Anthropic.

**OmniRoute to rieši transparentne:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute vyberie natívny protokol poskytovateľa a v prípade potreby ho preloží
    → POST /responses (DeepSeek V4) alebo /chat/completions (Mistral / GLM / Kimi / ostatné)
```

Pri používaní OmniRoute nikdy nepotrebujete samostatný prekladový proxy server. **Všetky modely používajú `wire_api = "responses"`** — OmniRoute sa postará o zvyšok.

> **`wire_api` je predvolené nastavenie** — predvolená hodnota poľa je `"responses"` a z `config.toml` ho možno úplne vynechať. Explicitne ho nastavte iba vtedy, ak chcete zdokumentovať zámer.

## Kontextové okno a kompakcia

### Polia konfigurácie tokenov

| Pole                             | Popis                                                                                                                                                                                                    |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Celkový rozpočet tokenov pre aktívny model. Nastavte ho na limit uvádzaný pre daný model.                                                                                                                |
| `model_auto_compact_token_limit` | Prahová hodnota, ktorá spustí automatickú kompakciu histórie. **Maximum: 90 % z `model_context_window`** — hodnoty nad 90 % sa bez upozornenia ignorujú.                                                 |
| `tool_output_token_limit`        | Limit tokenov uložených v histórii pre výstup každého volania nástroja. Zabraňuje tomu, aby jediná veľká odpoveď nástroja zaplnila okno. **Nejde o maximálny výstup** — je to limit uloženia v histórii. |
| `compact_prompt`                 | Priame prepísanie systémovej výzvy použitej počas kompakcie (v0.138+).                                                                                                                                   |

> **Poznámka k `model_max_output_tokens`**: Toto pole **nie je súčasťou konfiguračnej schémy Codex CLI** (v kódovej báze Codex Rust sa nenachádza). Ak ho nastavíte, bez upozornenia sa ignoruje. Nespoliehajte sa naň — na riadenie množstva výstupu nástroja uloženého v histórii použite `tool_output_token_limit`.

## Prefix modelu: `cx/`

Všetky modely Codex v OmniRoute používajú prefix `cx/`:

| Názov v Codex CLI       | Model OmniRoute    |
| ----------------------- | ------------------ |
| `cx/gpt-5.5`            | GPT-5.5 štandardný |
| `cx/gpt-5.4`            | GPT-5.4 štandardný |
| `cx/gpt-5.4-mini`       | GPT-5.4 mini       |
| `cx/gpt-5.1-codex-mini` | GPT-5.1 Codex mini |

Ostatní poskytovatelia používajú vlastný prefix (`kmc/`, `glm/`, `ds/`, `ollamacloud/`, `opencode-go/`, `mistral/`) — prefix zodpovedá aliasu poskytovateľa v OmniRoute.

## Intenzita uvažovania

Určuje, koľko model pred odpoveďou „premýšľa“.

| Hodnota  | Použite na                                          |
| -------- | --------------------------------------------------- |
| `none`   | Bez uvažovania — priama odpoveď                     |
| `low`    | Triviálne úlohy (premenovanie, formátovanie)        |
| `medium` | **Predvolené nastavenie servera**, ak nie je určené |
| `high`   | Stredne náročné úlohy (refaktoring, ladenie)        |
| `xhigh`  | Architektúra, hĺbková analýza, komplexné problémy   |

```bash
# Prepísanie nastavenia pre jednotlivé spustenie
codex -c model_reasoning_effort=low "premenuj premennú x na count"
codex -c model_reasoning_effort=xhigh "navrhni autentifikačný modul"
```

Nastavte tiež **súhrn** uvažovania, aby Desktop dokázal zobraziť text premýšľania (nielen šifrované bloky):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # alebo ultra, ak je podporované
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### Rozpočet uvažovania OmniRoute (nastavenie servera)

Na hostiteľovi OmniRoute musí byť položka **Settings → AI → Thinking Budget** nastavená na **`passthrough`**, aby sa intenzita a súhrn uvažovania Codex preniesli k upstream poskytovateľovi. Režim **`auto` odstraňuje** všetky klientske polia `reasoning` / `reasoning_effort` a spôsobí, že panely uvažovania zostanú prázdne, aj keď je Codex nakonfigurovaný správne.

Úplná príručka: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Kompresia a vyrovnávacia pamäť promptov sú nezávislé a v režime `passthrough` naďalej fungujú.

## Profily — pomenované konfigurácie pre jednotlivé modely/pracovné postupy

Profily umožňujú prepínať model a kontextové okno pomocou jediného prepínača. Každý profil je samostatný súbor
`~/.codex/<name>.config.toml`, ktorého nastavenia sa aplikujú na základný súbor `config.toml`.

> **Pravidlo pomenovania (Codex CLI v0.137+):** súbor musí mať názov `~/.codex/<name>.config.toml` — **bez prefixu `profile-`**.
> CLI preloží `-p kimi-k27` na `~/.codex/kimi-k27.config.toml`. Ak súbor nenájde, bez upozornenia použije predvolené nastavenie.

```bash
codex --profile kimi-k27 "analyzuj 10-tisíc riadkov tejto kódovej základne"
codex -p glm52 "posúď architektúru"
codex --profile deepseek-flash "premenuj premennú"   # rýchly, lacný
```

### Profily intenzity (rovnaký model, odlišná intenzita)

```bash
codex -p low      # cx/gpt-5.5, intenzita=low
codex -p medium   # cx/gpt-5.5, intenzita=medium
codex -p high     # cx/gpt-5.5, intenzita=high
codex -p xhigh    # cx/gpt-5.5, intenzita=xhigh (predvolené)
codex -p chat     # cx/gpt-5.5, intenzita nie je nastavená (predvolené nastavenie servera)
```

## Automatické generovanie profilov pomocou `omniroute setup-codex`

Ak prevádzkujete OmniRoute na VPS, môžete automaticky generovať súbory profilov zo živého katalógu modelov:

```bash
# Z VPS (používa lokálny OmniRoute na porte 20128)
omniroute setup-codex

# Z ľubovoľného počítača — zadajte adresu svojho VPS
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Náhľad bez zapisovania súborov
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Generovať iba profily GLM a Kimi
omniroute setup-codex --only glm,kimi

# Zapísať do vlastného adresára
omniroute setup-codex --codex-home /path/to/.codex
```

Príkaz načíta `/v1/models`, použije vyladené profily pre známe modely, pri ostatných kompatibilných textových modeloch použije ako náhradné riešenie metadáta katalógu a pre každý z nich zapíše `~/.codex/<name>.config.toml`. Je idempotentný — možno ho bezpečne spúšťať opakovane.

Ak základný súbor `config.toml` neobsahuje definíciu `model_providers.omniroute`, explicitné
spustenie `setup-codex` zahrnie túto definíciu do každého vygenerovaného prekrývajúceho
súboru s použitím vybraného lokálneho alebo vzdialeného koncového bodu. Základný súbor
ponechá nezmenený. Existujúca definícia poskytovateľa sa zdedí vrátane nastavení jej
koncového bodu a autentifikácie. Neplatný základný súbor TOML zastaví generovanie ešte
pred zápisom profilov.

Keď zadáte `--api-key` alebo `OMNIROUTE_API_KEY`, novovytvorená definícia poskytovateľa odkazuje na
`env_key = "OMNIROUTE_API_KEY"`; samotný kľúč sa nikdy neuloží ani nevypíše v
náhľade. Nastavte túto premennú v prostredí, v ktorom spúšťate Codex. Bez
zadaného kľúča nová definícia nevyžaduje kľúč, čo je určené pre inštanciu OmniRoute
nakonfigurovanú tak, aby prijímala neautentifikované požiadavky.

Voliteľná automatická synchronizácia katalógu opísaná nižšie zachová definície poskytovateľov, ktoré sa už
nachádzajú v prekrývajúcom súbore, ale nezavádza nové nastavenia poskytovateľa; poskytovateľa
najskôr nakonfigurujte explicitným nastavením alebo prostredníctvom ovládacieho panela. Existujúce nastavenia poskytovateľa sa
v náhľadoch skúšobného spustenia vynechávajú, pretože môžu obsahovať prihlasovacie údaje spravované prevádzkovateľom.

OmniRoute môže tieto isté súbory profilov aj **automaticky synchronizovať** po tom, ako úspešné zisťovanie/import modelov poskytovateľa zmení živý katalóg. Táto funkcia je **voliteľná a predvolene vypnutá**: zapnite ju na **ovládacom paneli CLI Code** („Automatická synchronizácia profilov CLI“ → Codex) alebo nastavte `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (rešpektuje aj `CLI_ALLOW_CONFIG_WRITES`, ktoré je predvolene zapnuté). Keď je povolená, zapisuje iba samostatné súbory profilov `~/.codex/*.config.toml`; nikdy nemení aktívny/predvolený súbor `~/.codex/config.toml`, nastavenia Codex-lb, autentifikáciu ani výber poskytovateľa.

## Dlhodobé úlohy

Dve predvolené hodnoty OmniRoute môžu ticho sabotovať viachodinové relácie Codex CLI. Ani nastavenie Codex CLI — je živé na strane OmniRoute. Používatelia, ktorí migrujú konfiguráciu z upstream serverov proxy, ktoré pripájajú účty a deaktivujú prerušenia nečinnosti, často zasiahnu oboje a dospejú k záveru, OmniRoute „nedokáže udržať dlhú reláciu“.

| Symptóm                                                                                      | Pravdepodobná príčina                                                                          | Gombík                   |
| -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------ |
| Relácia neustále prepína účty / medzi ťahmi sa stráca kontinuita rýchlej vyrovnávacej pamäte | Afinita relácie TTL je `0` (zakázané)                                                          | `sessionAffinityTtlMs`   |
| Pripojenie zanikne uprostred dôvodov bez výzvy na strane klienta                             | Po 10 minútach sa spustil sledovací program nečinnosti streamu bez toho, aby došlo k upstreamu | `STREAM_IDLE_TIMEOUT_MS` |

Súvisiace diskusie: [#7126](https://github.com/cheaper-inference/OmniRoute/discussions/7126) (dlhá úloha klesá), [#5718](https://github.com/cheaper-inference/OmniRoute/discussions/5718) (prečo je afinita predvolene vypnutá). Sledovanie: [#7287](https://github.com/cheaper-inference/OmniRoute/issues/7287).

### 1. Príbuznosť relácie — pripne jednu konverzáciu k jednému účtu

**Predvolená hodnota:** `sessionAffinityTtlMs = 0` (zakázané).

**Kde to nastaviť**

- Prístrojová doska →** Nastavenia → Smerovanie** →** Afinita relácie** →** Afinita TTL (sekundy)** (`ComboDefaultsTab`)
- Alebo nastavenia PATCH so vstupom `sessionAffinityTtlMs`** milisekúnd** ( rozsah Zod `0`–`86_400_000`, teda do 24 hodín)

> Premenovaný v #7274 z kódexu `codexSessionAffinityTtlMs`. Starý kľúč je stále akceptovaný ako alias iba na čítanie; nové konfigurácie by mali používať `sessionAffinityTtlMs`. Afinita sa teraz vzťahuje na** akékoľvek** poskytovateľ, keď je TTL nad `0`, nielen Codex — pozri [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → afinitu relácie.

**Čo sa zlomí, keď zostane na 0**

Každé otočenie viacotáčkovej konverzácie Codex je smerované nezávisle aktívnou kombinovanou stratégiou a môže pristáť na a** iný účet za ťah** . To preruší kontinuitu upstream relácie / rýchlej vyrovnávacej pamäte. OmniRoute konzultuje iba hlavičky relácie Codex (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) a polia tela, ako napríklad `prompt_cache_key` / `session_id` keď je TTL väčšie ako `0` (`extractSessionAffinityKey` v `src/sse/services/auth.ts`).

**Odporúča sa pre jednu viachodinovú úlohu**

Nastavte TTL** nad očakávanú dĺžku úlohy** (max.UI je** 86 400 sekúnd** = 24 hodín):

| Očakávaná dĺžka úlohy | Afinita TTL (UI, sekundy)     | `sessionAffinityTtlMs` |
| --------------------- | ----------------------------- | ---------------------- |
| Pár hodín             | `14400` (4 h)                 | `14400000`             |
| Prenocovanie / ~ 12h  | `43200` (12 h)                | `43200000`             |
| Celý deň              | `86400` (24 hodín, maximálne) | `86400000`             |

Prihlásenie je zámerné: zakázanie afinity uprednostňuje vyrovnávanie zaťaženia medzi účtami; jeho aktivácia uprednostňuje kontinuitu jednej dlhej relácie agenta. Tento návod áno** nie** zmeniť predvolené operátory — spúšťajúce dlhé úlohy Codex, ktoré sa musia prihlásiť.

### 2. Časový limit nečinnosti streamu — nezabíja tiché uvažovanie

**Predvolená hodnota:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 minút). Keď nie je nastavené, dedí sa z `REQUEST_TIMEOUT_MS` ; zdieľaná základná línia je tiež 600 000. Pozrite si časové limity [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) →.

**Čo sa pokazí pri predvolenom nastavení**

Codex uvažovanie / otáčanie nástroja, ktoré zostane tiché viac ako 10 minút** žiadny skutočný upstream kus** je násilne zatvorený strážnym psom SSE nečinnosti (`open-sse/utils/stream.ts`). Klient často vidí, že sa holé spojenie — zhoduje „automaticky zastavené bez akéhokoľvek upozornenia“.

Kritický detail: syntetický SSE OmniRoute** tep sa neresetuje** nečinné hodiny. `lastChunkTime` aktualizuje iba skutočný upstream časti tela. Tichý model, ktorý stále „premýšľa“, vyzerá z pohľadu strážneho psa identicky so zaseknutým proti prúdu.

Súvisiaca nečinnosť tela Undici: `FETCH_BODY_TIMEOUT_MS` (tiež predvolene na rovnakú 10-minútovú základnú líniu; `0` ju zakáže). Pri streamovaní sa `FETCH_TIMEOUT_MS` vzťahuje iba na nastavenie pripojenia / prvé hlavičky — keď je stream aktívny, zastavenia sa riadia `STREAM_IDLE_TIMEOUT_MS` a `FETCH_BODY_TIMEOUT_MS`.

**Odporúča sa pre jednu viachodinovú úlohu**

V prostredí procesu OmniRoute (`.env` / compose / systemd):

```bash
# Disable stream idle + body inactivity cutoffs for long reasoning turns
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Alebo ich zvýšte nad najdlhšiu tichú medzeru, ktorú očakávate (hodnoty sú milisekundy):

```bash
# Example: allow up to 2 hours of silence between upstream chunks
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Po zmene týchto premenných prostredia reštartujte OmniRoute.

### Konkrétny recept — viachodinová úloha Codex

1. **Pripnúť účet:** Ovládací panel → Nastavenia → Smerovanie → Afinita relácie → Afinita TTL = `43200` (12 h) alebo `86400` (max. 24 h).
2. **Zvýšte / zakážte vypnutie voľnobehu** v prostredí OmniRoute:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Ponechajte zvyčajné Codex `config.toml` (`wire_api = "responses"`, správne `base_url`, `OMNIROUTE_API_KEY`) — pre tieto dve správania neexistujú žiadne gombíky affinity/idle na strane Codexu.
4. Reštartujte OmniRoute a potom spustite dlhú úlohu Codex.

### Predvolené rozhodnutie (#7287)

| Gombík                   | Predvolená odoslanie | Zmeniť túto príručku?                                                                               |
| ------------------------ | -------------------- | --------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (vypnuté)        | **Nie** — zostáva opt-in (vyvažovanie záťaže vs. kontinuita; pozri diskusiu #5718)                  |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min)    | **Nie** — zostáva 10 minút pre všeobecnú premávku; operátori long Codex ho zvyšujú alebo deaktivujú |

Globálne prevrátenie oboch predvolených nastavení by zmenilo správanie každého klienta inštancie, nielen Codex. Zdokumentujte gombíky; ponechajte predvolené nastavenia, kým výslovné rozhodnutie operátora nepovie inak.

### Diagnostika nečinných rezov

Keď sa spustí strážny pes nečinnosti, OmniRoute zaznamená čiaru v tvare:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Grep pre `Idle timeout: no data from` (alebo kód `stream_idle_timeout` / názov chyby `StreamIdleTimeoutError`). Segment poskytovateľa je akýkoľvek OmniRoute použitý pre danú požiadavku (`codex`, id iného poskytovateľa alebo `provider`, ak je neznámy) — to nie je vždy doslovný reťazec `codex`.

## Riešenie problémov

**`Error: wire_api = "chat" is no longer supported`** Odstráňte `wire_api = "chat"` z vašej konfigurácie. Nastavte `wire_api = "responses"` alebo vynechajte pole (predvolené je `"responses"` od verzie 0.138).

**`Error: model not found`** Overte, či model existuje v OmniRoute so správnou predponou. Použite `omniroute models list` alebo otvorte `/dashboard/providers/<provider>`.

**`Authentication error`** Potvrdenie exportu `OMNIROUTE_API_KEY` : `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`** Codex pred vykonaním prvej požiadavky overí, že env var existuje. Exportujte skutočný kľúč pre chránené servery alebo neprázdny zástupný symbol, napríklad `OMNIROUTE_API_KEY=local` keď je váš** miestne** inštancia OmniRoute nevyžaduje autorizáciu. Reštartujte shell, ak ste ho pridali do `~/.bashrc` alebo `~/.zshrc`.

**`Connection refused`** Skontrolujte, či je spustené OmniRoute a či je `base_url` host/port správne pre vašu sieť (lokálna vs. Tailscale vs VPS).

**Relácia zlyhá v blízkosti limitu kontextu** Explicitne nastavte `model_context_window` a `model_auto_compact_token_limit`. Pozrite si tabuľku kontextového okna vyššie.

**Zhutňovanie sa spúšťa príliš neskoro** Znížte `model_auto_compact_token_limit` na 80 – 85 % okna. Nikdy nenastavujte nad 90 %.

**Profil sa nenačítava (`-p <name>` ticho ignorované)** Potvrďte, že súbor existuje na `~/.codex/<name>.config.toml` (bez predpony `profile-` ). Spustite `ls ~/.codex/*.config.toml`.

**Dlhá úloha Codex klesá uprostred behu / prepína účty medzi ťahmi** Pozrite si tému [Dlhodobé úlohy](#long-running-tasks). Povoľte afinitu relácie (TTL nad dĺžkou úlohy) a zvýšte alebo zakážte `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. Grep OmniRoute protokoly pre `Idle timeout: no data from`.
