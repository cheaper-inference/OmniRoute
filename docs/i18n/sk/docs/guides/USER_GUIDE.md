## 🎯 Prípady použitia

### Prípad 1: „Mám predplatné Claude Pro“

**Problém:** Kvóta vyprší nevyužitá, pri intenzívnom programovaní sa uplatňujú obmedzenia rýchlosti

```
Kombinácia: "maximize-claude"
  1. cc/claude-opus-4-7        (plné využitie predplatného)
  2. glm/glm-4.7               (lacná záloha po vyčerpaní kvóty)
  3. if/qwen3.8-max-preview       (bezplatná núdzová záložná možnosť)

Mesačné náklady: $20 (predplatné) + ~$5 (záloha) = spolu $25
oproti $20 + dosiahnutie limitov = frustrácia
```

### Prípad 2: „Nechcem platiť nič“

**Problém:** Nemôžem si dovoliť predplatné a potrebujem spoľahlivú AI na programovanie

```
Kombinácia: "zero-cost"
  1. if/kimi-k2.7-code          (uvádzaný bezplatný prístup; môžu platiť obmedzenia rýchlosti)
  2. kr/qwen3-coder-next        (bezplatná záloha Kiro)

Mesačné náklady: $0
Kvalita: overte model, limity, ochranu súkromia a SLA pre vaše pracovné zaťaženie
```

### Prípad 3: „Potrebujem programovať nepretržite, bez prerušení“

**Problém:** Termíny, nemôžem si dovoliť výpadky

```
Kombinácia: "always-on"
  1. cc/claude-opus-4-7        (najlepšia kvalita)
  2. cx/gpt-5.5                (druhé predplatné)
  3. glm/glm-4.7               (lacné, obnovuje sa denne)
  4. minimax/MiniMax-M2.1      (najlacnejšie, obnovenie po 5 hod.)
  5. if/deepseek-v4-flash       (uvádzaný bezplatný prístup; môžu platiť obmedzenia rýchlosti)

Výsledok: 5 záložných vrstiev zvyšuje odolnosť; dostupnosť služieb vyššej úrovne nie je zaručená
Mesačné náklady: $20-200 (predplatné) + $10-20 (záloha)
```

### Prípad 4: „Chcem BEZPLATNÚ AI v OpenClaw“

**Problém:** Potrebujem asistenta AI v komunikačných aplikáciách úplne zadarmo

```
Kombinácia: "openclaw-free"
  1. if/qwen3.8-max-preview     (uvádzaný bezplatný prístup; môžu platiť obmedzenia rýchlosti)
  2. if/deepseek-v4-flash       (uvádzaný bezplatný prístup; môžu platiť obmedzenia rýchlosti)
  3. if/kimi-k2.7-code          (uvádzaný bezplatný prístup; môžu platiť obmedzenia rýchlosti)

Mesačné náklady: $0
Prístup cez: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 Nastavenie poskytovateľov

Ak chcete hromadne pridať pripojenia s API kľúčmi zo súboru CSV alebo JSON, použite **Dashboard → Providers → Import from file**. Stĺpce sú pozičné (`provider,name,apiKey,baseUrl,priority`); `provider` už musí existovať ako spravovaný poskytovateľ alebo kompatibilný uzol. Pozrite si [Import poskytovateľov zo súboru CSV alebo JSON](../providers/CSV-IMPORT.md).

### 🔐 Poskytovatelia s predplatným

#### Claude Code (Pro/Max)

```bash
Dashboard → Providers → Connect Claude Code
→ Prihlásenie cez OAuth → Automatické obnovenie tokenu
→ Sledovanie 5-hodinovej a týždennej kvóty

Modely:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**Profesionálny tip:** Opus používajte na komplexné úlohy a Sonnet na rýchlosť. OmniRoute sleduje kvótu pre každý model!

Na hostiteľovi OmniRoute nie je prehliadač? Spustite `claude setup-token` kdekoľvek, kde ste prihlásení do Claude Code, a vložte jednoročný token na kartu **Setup Token**. Pozrite si [Claude Code s nastavovacím tokenom](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

Trasy kompatibilné s Claude a Claude Code zachovávajú úroveň úsilia pri uvažovaní `max` pre modely Opus a Sonnet. Modely Haiku nepodporujú úroveň úsilia `max`, preto OmniRoute pred odoslaním požiadavky nadradenému poskytovateľovi zmení túto požiadavku na vysoký rozpočet na uvažovanie.

#### OpenAI Codex (Plus/Pro)

```bash
Dashboard → Providers → Connect Codex
→ Prihlásenie cez OAuth (port 1455)
→ Obnovenie po 5 hodinách a po týždni

Modely:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
Dashboard → Providers → Connect GitHub
→ OAuth cez GitHub
→ Mesačné obnovenie (1. deň v mesiaci)

Modely:
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview
```

### 💰 Lacní poskytovatelia

#### GLM-4.7 (denné obnovenie, $0.6/1M)

1. Zaregistrujte sa: [Zhipu AI](https://open.bigmodel.cn)
2. Získajte API kľúč z plánu Coding Plan
3. Dashboard → Add API Key: Poskytovateľ: `glm`, API kľúč: `your-key`

**Použitie:** `glm/glm-4.7` — **Profesionálny tip:** Coding Plan ponúka 3-násobnú kvótu za 1/7 ceny! Obnovuje sa denne o 10:00.

#### MiniMax M2.1 (obnovenie po 5 h, $0.20/1M)

1. Zaregistrujte sa: [MiniMax](https://www.minimax.io)
2. Získajte API kľúč → Dashboard → Add API Key

**Použitie:** `minimax/MiniMax-M2.1` — **Profesionálny tip:** Najlacnejšia možnosť pre dlhý kontext (1M tokenov)!

#### Kimi K2 (pevne $9/mesiac)

1. Predplaťte si službu: [Moonshot AI](https://platform.kimi.ai?aff=omniroute)
2. Získajte API kľúč → Dashboard → Add API Key

**Použitie:** `kimi/kimi-k2.5` — **Profesionálny tip:** Pevných $9/mesiac za 10M tokenov = efektívna cena $0.90/1M!

#### Baidu Qianfan / ERNIE

1. Zaregistrujte sa: [Baidu AI Cloud Qianfan](https://cloud.baidu.com/product/wenxinworkshop)
2. Vytvorte API kľúč Qianfan → Dashboard → Add API Key: Poskytovateľ: `qianfan`

**Použitie:** `qianfan/ernie-5.1`, `qianfan/ernie-x1.1` alebo iné ID modelu Qianfan kompatibilného s OpenAI.

### 🆓 BEZPLATNÍ poskytovatelia

Bezplatní poskytovatelia bez overenia majú na svojej stránke prepínač vedľa položky **No authentication required**.
Jeho vypnutím daného poskytovateľa deaktivujete, odstránite ho z nakonfigurovaného/kompaktného zobrazenia poskytovateľov
a jeho modely odstránite z `/v1/models`.

#### Qoder (9 BEZPLATNÝCH modelov)

```bash
Dashboard → Connect Qoder → Prihlásenie cez OAuth → Prístup podlieha aktuálnym limitom poskytovateľa

Modely: if/qwen3.8-max-preview, if/qwen3.7-max, if/qwen3.7-plus, if/kimi-k3, if/kimi-k2.7-code, if/glm-5.2, if/deepseek-v4-pro, if/deepseek-v4-flash, if/minimax-m3
```

#### Kiro (Claude BEZPLATNE)

```bash
Dashboard → Connect Kiro → AWS Builder ID alebo Google/GitHub → ~50 kreditov/mesiac

Modely: kr/claude-sonnet-4.5, kr/claude-haiku-4.5
```

## 🎨 Kombinácie

Karty kombinácií môžete meniť priamo v časti **Ovládací panel → Kombinácie** potiahnutím rukoväti na každej karte. Poradie sa uloží v SQLite a po opätovnom načítaní sa obnoví.

### Príklad 1: Maximalizácia predplatného → Lacná záloha

```
Ovládací panel → Kombinácie → Vytvoriť novú

Názov: premium-coding
Modely:
  1. cc/claude-opus-4-7 (Primárny model z predplatného)
  2. glm/glm-4.7 (Lacná záloha, $0.6/1M)
  3. minimax/MiniMax-M2.7 (Najlacnejšia núdzová možnosť, $0.3/1M)

Použitie v CLI: premium-coding
```

### Príklad 2: Iba bezplatné modely (nulové náklady)

```
Názov: free-combo
Modely:
  1. if/kimi-k2.7-code (uvedený bezplatný prístup; môžu platiť obmedzenia poskytovateľa)
  2. kr/qwen3-coder-next (bezplatná záloha Kiro)

Náklady: momentálne uvedené ako $0; podmienky a dostupnosť sa môžu zmeniť
```

## 🚀 Nasadenie

### Globálna inštalácia cez npm (odporúčané)

```bash
npm install -g omniroute

```

CLI automaticky načíta súbor `.env` z `~/.omniroute/.env` alebo `./.env`.

### Režim systémovej lišty

Spustite OmniRoute v systémovej lište:

```bash
omniroute serve --tray
```

Príkaz sa ukončí po pripravení servera a systémovej lišty.

Server naďalej beží bez terminálu.

Režim systémovej lišty podporuje macOS, Windows a grafické relácie Linuxu. V režime systémovej lišty sa ovládací panel neotvorí automaticky.

Ponuku systémovej lišty použite na tieto akcie:

- Otvorenie ovládacieho panela.
- Otvorenie `/dashboard/logs`.
- Zmenu automatického spúšťania.
- Zastavenie OmniRoute.

Nekombinujte `--tray` s týmito možnosťami:

- `--daemon`
- `--log`
- `--no-recovery`

Tieto režimy vyžadujú odlišné vlastníctvo procesu.

Povoľte spustenie pri nasledujúcom prihlásení do počítača:

```bash
omniroute autostart enable
```

Automatické spúšťanie používa režim systémovej lišty v systémoch macOS, Windows a grafických reláciách Linuxu. Linux bez grafického rozhrania používa existujúcu používateľskú službu systemd.

Zakážte spúšťanie pri prihlásení:

```bash
omniroute autostart disable
```

Používatelia Void Linuxu môžu OmniRoute zostaviť do balíka a natívne nainštalovať pomocou frameworku `xbps-src` na krížovú kompiláciu. Tento proces automatizuje samostatné zostavenie Node.js spolu s požadovanými natívnymi väzbami `better-sqlite3`.

```bash

version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"

system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# Určenie cieľovej architektúry CPU pre node-gyp
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) Inštalácia všetkých závislostí – preskočenie skriptov
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Zostavenie samostatného balíka Next.js
	npm run build

	# 3) Skopírovanie statických prostriedkov do samostatného balíka
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) Kompilácia natívnej väzby better-sqlite3
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) Umiestnenie skompilovanej väzby do samostatného balíka
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) Odstránenie balíkov sharp špecifických pre jednotlivé architektúry
	rm -rf .next/standalone/node_modules/@img

	# 7) Skopírovanie runtime závislostí pino vynechaných statickou analýzou Next.js:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# Zabránenie odstráneniu prázdnych adresárov smerovača aplikácie Next.js hookom po inštalácii
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"

exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

### Vlastné modely

Pridajte akýkoľvek model ID k akémukoľvek poskytovateľovi bez čakania na aktualizáciu aplikácie:

```bash
# Via API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# Remove: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

Alebo použite Dashboard:** Poskytovatelia → [Poskytovateľ] → Vlastné modely** .

Poznámky:

- Poskytovatelia OpenRouter a OpenAI/Anthropic-compatible sú spravovaní z** Dostupné modely** iba. Manuálne pridávanie, import a automatická synchronizácia všetkých pozemkov v rovnakom zozname dostupných modelov, takže pre týchto poskytovateľov neexistuje samostatná sekcia vlastných modelov.
- The** Vlastné modely** časť je určená pre poskytovateľov, ktorí nevystavujú importy spravovaných dostupných modelov.

### Vlastní poskytovatelia kompatibilní s OpenAI

Akákoľvek brána, ktorá hovorí OpenAI API (samohostiteľná proxy, vLLM, agregátor tretej strany), môže byť pridaná ako jej vlastný uzol poskytovateľa:

1. **Poskytovatelia → Pridať OpenAI kompatibilné** .
2. **Meno** : zobrazovaný štítok pre uzol.
3. **Predpona** : názov smerovania. Klienti nazývajú modely ako `<prefix>/<model>`, takže uzol s predponou `mygw` slúži `mygw/gpt-4o-mini`. Povinné; neexistuje žiadne obmedzenie charakteru.
4. **Typ API** : rodina koncových bodov, ktoré brána obsluhuje (dokončenia rozhovoru, odpovede, vloženia, zvuk, obrázky).
5. **Základňa URL** : koreň API až po `/v1` vrátane (napríklad `https://gateway.example.com/v1`), nie úplná cesta `/chat/completions`. Brány s neštandardnými cestami ich nastavia pod** Rozšírené nastavenia** (cesta chatu, cesta modelov).
6. The**API kľúč (pre kontrolu)** pole iba testuje pripojenie. Po vytvorení uzla ho otvorte a použite** Pridať pripojenie** na uloženie kľúča, ktorý budú požiadavky používať.

Uzol dostane interné ID vo forme `openai-compatible-<apiType>-<uuid>`; nikdy ho nemusíte písať, predpona je verejné meno.

#### Vyhradené predpony

Predpona nemôže byť id alebo alias vstavaného poskytovateľa (napríklad `openai`, `cf`), ani id vyradeného poskytovateľa. Prekladač modelov kontroluje vstavané identifikátory a aliasy pred vlastnými uzlami, takže uzol používajúci jednu z týchto predpôn by nikdy neprijímal prenos: `<prefix>/model` by namiesto toho prešiel k vstavanému poskytovateľovi alebo by zlyhal, ak by bol poskytovateľ vyradený. Vytvorenie alebo úprava uzla s takouto predponou sa odmietne s:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

Vyberte odlišnú predponu (`mygw`, `acme-proxy`). Ak požiadavky na vlastný uzol zlyhajú s chybou, ktorá pomenúva vstavaného poskytovateľa alebo jeho poverenia, skontrolujte, či je predpona uzla rezervovaná: uzly uložené pred existenciou tohto pravidla sú stále uložené, ale ich predpona smeruje k vstavanému poskytovateľovi. Upravte uzol a dajte mu novú predponu.

#### Možnosti brány podľa pripojenia

Tieto kľúče idú do `providerSpecificData` pripojenia (napríklad cez `PUT /api/providers/{id}`):

- `toolNameMaxLength` (celé číslo, 1–1024) — pre pripojenia kompatibilné s formátom chatu OpenAI, ktorých brána odmieta dlhé názvy nástrojov. Dlhšie mená sa odošlú ako krátke aliasy a obnovia sa v odpovedi.
- `quotaEndpoint` — koncový bod quota/credits brány, čítaný pre pásik kvót dashboardu a smerovanie s ohľadom na kvóty. Funguje na pripojeniach kompatibilných s OpenAI aj Anthropic; plný tvar je doložený v `open-sse/services/usage/openaiCompatible.ts`.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### Reťazenie OmniRoute Peers

Ďalšia brána OmniRoute môže byť pridaná ako a** Vlastná kompatibilita s OpenAI** poskytovateľa. Použite základ `/v1` URL partnera a vyhradený kľúč API s najnižším oprávnením vydaný týmto partnerom.

Pre recipročné alebo multi-hop reťazce povoľte voliteľnú ochranu slučky na každej bráne:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

Hlavičku `X-OmniRoute-Peer-Trace` dostanú iba žiadosti odoslané priamo na zozname povolených partnerov URL. Brána odmietne opakovanú inštanciu ID alebo vyčerpaný skokový rozpočet s HTTP `508 Loop Detected`; bežní upstream poskytovatelia nedostávajú žiadne rovnocenné metadáta.

Reťazenie rovnocenných partnerov nie je replikácia databázy alebo núdzové prepnutie hostiteľa. Každá brána uchováva nezávislý stav SQLite, vyrovnávacie pamäte, počítadlá rýchlosti a relácie. Pre dostupnosť active/passive alebo active/active použite reverzný proxy server s kontrolou stavu alebo zlyhanie klienta a nikdy nepripájajte jednu databázu SQLite do viacerých spustených inštancií OmniRoute.

### Cloudflare Rýchly tunel

- Dostupné v** Dashboard → Endpoints** pre Docker a iné nasadenia s vlastným hosťovaním
- Vytvorí dočasný `https://*.trycloudflare.com` URL, ktorý prepošle váš aktuálny koncový bod `/v1` kompatibilný s OpenAI
- Najprv povoľte inštaláciu `cloudflared` iba v prípade potreby; neskoršie reštarty znova použijú rovnaký spravovaný binárny súbor
- Rýchle tunely sa po reštarte OmniRoute alebo kontajnera automaticky neobnovia; v prípade potreby ich znova povoľte z palubnej dosky
- Tunelové URLs sú efemérne a menia sa zakaždým, keď stop/start tunelom
- Spravované rýchle tunely predvolene používajú transport HTTP/2, aby sa predišlo hlučným upozorneniam QUIC UDP vyrovnávacej pamäte v obmedzených kontajneroch
- Ak chcete prepísať výber riadeného prenosu, nastavte `CLOUDFLARED_PROTOCOL=quic` alebo `auto`
- Nastavte `CLOUDFLARED_BIN`, ak uprednostňujete použitie predinštalovaného binárneho súboru `cloudflared` namiesto riadeného sťahovania
- Panely Cloudflare Quick Tunnel, Tailscale Funnel a ngrok Tunnel je možné zobraziť alebo skryť v** Nastavenia → Vzhľad** . Skrytie panelu nezastaví bežiaci tunel.

### LLM Gateway Intelligence (9. fáza)

- **Sémantická vyrovnávacia pamäť** — Automatické ukladanie do vyrovnávacej pamäte bez streamovania, odozvy teploty = 0 (premostenie pomocou `X-OmniRoute-No-Cache: true`)

### Stratégie smerovania

Konfigurovať cez** Dashboard → Nastavenia → Smerovanie** . Prístrojová doska odhaľuje šesť najpoužívanejších stratégií; kombá a automatický smerovač interne podporujú širšiu sadu.

**Stratégie viditeľné na informačnom paneli (smerovanie na úrovni účtu):**

| Stratégia                     | Popis                                                                                                |
| ----------------------------- | ---------------------------------------------------------------------------------------------------- |
| **Najprv vyplniť**            | Používa účty v poradí priority – primárny účet spracováva všetky požiadavky, kým nie je dostupný     |
| **Round Robin**               | Cyklicky prechádza všetkými účtami s konfigurovateľným fixným limitom (predvolené: 3 hovory na účet) |
| **P2C (Sila dvoch možností)** | Vyberie 2 náhodné účty a cesty k zdravšiemu — vyrovnáva záťaž s uvedomením si zdravia                |
| **Náhodný**                   | Náhodne vyberie účet pre každú požiadavku pomocou Fisher-Yates shuffle                               |
| **Najmenej používané**        | Smeruje na účet s najstaršou časovou pečiatkou `lastUsedAt`, čím sa návštevnosť rozdeľuje rovnomerne |
| **Optimalizované náklady**    | Smeruje na účet s najnižšou prioritou, optimalizuje sa pre poskytovateľov s najnižšou cenou          |

**Pokročilé kombinované a automatické stratégie** (konfigurovateľné pre kombináciu alebo cez predpony `auto/*` – pozri [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ):

- `priority` — prísny poriadok, nikdy nie okrúhle
- `weighted` — proporcionálna návštevnosť rozdelená podľa váh jednotlivých modelov
- `fill-first` — vypustite prvý model, kým nedosiahnu limity
- `round-robin` / `strict-random` / `random`
- `p2c` (Sila dvoch možností)
- `least-used` a `cost-optimized`
- `auto` — na základe skóre u všetkých kandidátov
- `lkgp` (Posledný známy dobrý poskytovateľ) — pripne posledného úspešného poskytovateľa, potom sa vráti k pravidlám
- `context-optimized` — vyberie model s najväčším voľným kontextovým oknom
- `context-relay` — reťaze modely s dlhým kontextom pre následné obraty

#### Hlavička externej lepivej relácie

Pre externú príbuznosť relácie (napríklad agenti Claude Code/Codex za reverznými proxy servermi) odošlite:

```http

```

```nginx

```

### Odolnosť a ističe

Konfigurovať cez** Dashboard → Settings → Resilience** .

OmniRoute implementuje odolnosť na úrovni poskytovateľa s piatimi komponentmi:

1. **Zoznam žiadostí a tempo** — Tvarovanie požiadavky na úrovni systému:
   - **Počet žiadostí za minútu (RPM)** — Maximálny počet žiadostí za minútu na účet
   - **Minimálny čas medzi žiadosťami** — Minimálna medzera v milisekundách medzi požiadavkami
   - **Maximálny počet súbežných požiadaviek** — Maximálny počet simultánnych žiadostí na účet

2. **Ochladenie pripojenia** — Konfigurácia typu perauth pre jedno pripojenie po opakovaných zlyhaniach:
   - **Ochladzovanie základne** — Predvolené chladiace okno pre opakovateľné zlyhania upstreamu
   - **Použite Upstream Retry Hints** — Oceňuje autoritatívne `Retry-After` alebo resetovacie rady, ak sú poskytnuté
   - **Maximálny počet krokov na ústup** — Maximálna exponenciálna úroveň stiahnutia pri opakovaných zlyhaniach

3. **Istič poskytovateľa** — Sleduje zlyhania koncového poskytovateľa, označí poskytovateľa za zníženého na nakonfigurovanom prahu varovania a otvorí istič, keď sa dosiahne nakonfigurovaný prah zlyhania:
   - **Prah degradácie** — Po sebe idúce zlyhania poskytovateľa pred vstupom `DEGRADED`
   - **Prah zlyhania** — Po sebe idúce zlyhania poskytovateľa pred vstupom `OPEN`
   - **Resetovať časový limit** — Časové okno pred opätovným testovaním poskytovateľa
   - **CLOSED** (Zdravé) — Požiadavky prebiehajú normálne
   - **DEGRADED** — Požiadavky stále prúdia, kým sa sledujú zvýšené zlyhania
   - **OPEN** — Poskytovateľ je po opakovaných poruchách dočasne zablokovaný
   - **HALF_OPEN** — Testovanie, či sa poskytovateľ zotavil

   Limity rýchlosti `429` v rozsahu pripojenia zostávajú v platnosti** Ochladenie pripojenia** a nezapočítavajú sa do poskytovateľa ističa.

   Stav spustenia prerušovača poskytovateľa je zobrazený na** Dashboard → Health** iba.

4. **Počkajte na vychladnutie** — Ak sa každé pripojenie kandidáta už ochladzuje, OmniRoute môže počkať na najskoršie ochladenie a automaticky zopakovať rovnakú požiadavku klienta.

5. **Automatická detekcia limitu rýchlosti** — Keď upstream poskytovatelia vrátia explicitné čakacie okná, tieto rady prepíšu chladenie lokálneho pripojenia, keď je toto nastavenie povolené.

**Tip pre profesionálov:** Použite** Zdravie** stránku na kontrolu a resetovanie aktívnych ističov poskytovateľa po výpadku. Stránka Odolnosť mení iba konfiguráciu.

Nastavenia uchovávania a optimalizácie databázy sú zachované prostredníctvom `/api/settings/database`; manuálne vymazanie vyrovnávacej pamäte používa `DELETE /api/cache`. Obmedzenia riadkov protokolu požiadaviek a proxy sú riadené `CALL_LOGS_TABLE_MAX_ROWS` a `PROXY_LOGS_TABLE_MAX_ROWS`.

### Kombinované stratégie vyvažovania

Nakonfigurujte vyváženie pre jednotlivé kombinácie** Prístrojová doska → Combos → Create/Edit → Stratégia** .

| Stratégia                    | Popis                                                                                   |
| ---------------------------- | --------------------------------------------------------------------------------------- |
| **Round-Robin**              | Postupne rotuje medzi modelmi                                                           |
| **Priorita**                 | Vždy vyskúšajte prvý model; vracia sa len pri chybe                                     |
| **Náhodný**                  | Vyberie náhodný model z kombinácie pre každú požiadavku                                 |
| **Vážené**                   | Trasy proporcionálne na základe priradených váh na model                                |
| **Najmenej používané**       | Smeruje k modelu s najmenším počtom nedávnych požiadaviek (používa kombinované metriky) |
| **Nákladovo optimalizované** | Trasy na najlacnejší dostupný model (používa cenovú tabuľku)                            |

Je možné nastaviť globálne predvolené hodnoty komb** Dashboard → Settings → Routing → Combo Defaults** . Časové limity kombinovaného cieľa predvolene dedia aktuálny časový limit požiadavky. Použite** Cieľový časový limit (sekundy)** pri predvolených nastaveniach komba alebo pri individuálnom kombe iba vtedy, keď kratší limit na cieľ by mal spustiť rýchlejší návrat.

Kombinované optimalizácie s nulovou latenciou sú voliteľné. Odísť** Optimalizácia s nulovou latenciou** deaktivované, aby sa zabránilo týmto funkciám latencie pretekať s záložnými cieľmi, preskakovať ciele na základe histórie TTFT alebo komprimovať záložné požiadavky; umožňuje nakonfigurované hedging, prediktívne preskoky TTFT a proaktívnu núdzovú kompresiu na výmenu vernosti routing/request za nižšiu latenciu chvosta.

Zakázať** Vyrovnávacia pamäť tokenov odôvodnenia** keď upstream poskytovatelia vyžadujú prísne limity `max_tokens` / `maxOutputTokens`. Ak je povolené, kombinované smerovanie iba pridáva priestor pre model uvažovania pre modely so známym výstupným limitom a ponecháva limit klientskeho tokenu nezmenený, keď by bezpečná hodnota vo vyrovnávacej pamäti prekročila tento limit. Ak je limit klienta už nad známym limitom, OmniRoute ho pred odoslaním upstream požiadavky zníži na tento limit.

## 🤖 Automatické smerovanie (bez konfigurácie)

OmniRoute obsahuje **automatický smerovač riadený skóre**, ktorý pre každú požiadavku vyberie najlepší model spomedzi všetkých pripojených poskytovateľov — bez potreby udržiavať kombinácie. Stačí odoslať požiadavku s jednou z predpôn `auto/*` a OmniRoute priebežne zostaví virtuálnu kombináciu, pričom kandidátov hodnotí podľa latencie, nákladov, úspešnosti, vhodnosti kontextu, vhodnosti modelu pre danú úlohu, nedávnych zlyhaní, kvóty a stavu ističa.

| Predpona       | Optimalizuje pre                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `auto`         | Vyvážené predvolené nastavenie (latencia × náklady × úspešnosť)                                                                   |
| `auto/coding`  | Programátorské úlohy: uprednostňuje Claude, GPT-5, GLM, Kimi, Qwen Coder a modely DeepSeek pre programovanie                      |
| `auto/cheap`   | Najnižšia cena za token, akceptuje vyššiu latenciu                                                                                |
| `auto/fast`    | Najnižšia latencia, ignoruje náklady                                                                                              |
| `auto/offline` | Iba lokálni poskytovatelia (Ollama, vLLM, llama.cpp) — užitočné pre izolované prostredia                                          |
| `auto/smart`   | Na prvom mieste je kvalita uvažovania (Opus, GPT-5 xhigh, R1, uvažovanie GLM 5.1)                                                 |
| `auto/lkgp`    | „Posledný známy funkčný poskytovateľ“ — pripne posledného úspešného poskytovateľa a následne použije pravidlá záložného prepnutia |

Príklad:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

Automatický smerovač je podrobne opísaný v dokumente [AUTO-COMBO.md](../routing/AUTO-COMBO.md) — vrátane postupu úpravy váh hodnotenia, pridávania poskytovateľov na čiernu listinu a kontroly rozhodnutí smerovania v časti **Ovládací panel → Automatická kombinácia**.

## 🔌 Integrácia MCP a A2A

OmniRoute je zároveň **server MCP** (Model Context Protocol) aj **server A2A** (Agent-to-Agent JSON-RPC 2.0). Ľubovoľné IDE alebo hostiteľ agenta kompatibilný s MCP môže priamo volať nástroje OmniRoute — nie je potrebná žiadna ďalšia obálka.

### Transporty MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **Streamovateľné HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (pre zásuvné moduly IDE, ktoré uprednostňujú stdio)

### Pripojenie Claude Desktop

Upravte súbor `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) alebo jeho ekvivalent v systéme Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Pripojenie Cursor / Continue / VS Code MCP

Použite adresu URL SSE `http://localhost:20128/api/mcp/sse` a kľúč Bearer API vygenerovaný v časti **Ovládací panel → Kľúče API**.

### Rozsahy

MCP v súčasnosti definuje 32 pomenovaných rozsahov. Každý kľúč Bearer možno obmedziť na konkrétne rozsahy — autoritatívny zoznam rozsahov a nástrojov nájdete v dokumente [MCP-SERVER.md](../frameworks/MCP-SERVER.md) a schému JSON-RPC v dokumente [A2A-SERVER.md](../frameworks/A2A-SERVER.md).

## 💾 Systém pamäte

OmniRoute uchováva **dlhodobú konverzačnú pamäť** s hybridným vyhľadávaním:

- **SQLite FTS5** na vyhľadávanie podľa kľúčových slov v predchádzajúcich interakciách
- **Vektorové úložisko Qdrant** (voliteľné) na sémantické vyhľadávanie

- Pamäte sú oddelené podľa API kľúča a relácie

Pamäte môžete spravovať cez **Dashboard → Memory** (vyhľadávanie, úpravy, export, vymazanie). Rozhranie HTTP (`/api/memory/*`) umožňuje agentom programovo odosielať fakty a vyhľadávať ich — pozrite si [MEMORY.md](../frameworks/MEMORY.md).

## 🛠️ Programová správa

Každý prostriedok OmniRoute (poskytovateľov, kombinácie, kľúče, nastavenia) môžete spravovať cez HTTP pomocou **kľúča Bearer s rozsahom `manage`**.

Vygenerujte kľúč cez **Dashboard → API Keys → New Key → Scope: manage** a potom:

```bash
# Zobrazenie zoznamu poskytovateľov
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Pridanie pripojenia k poskytovateľovi
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Vytvorenie kombinácie
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Zobrazenie zoznamu/vytvorenie API kľúčov
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

Kompletný katalóg koncových bodov a schémy požiadaviek/odpovedí nájdete v [API_REFERENCE.md](../reference/API_REFERENCE.md).

## 💻 Interné CLI

OmniRoute obsahuje interné CLI (`omniroute …`) na nastavenie, diagnostiku a riadenie za behu. Je **oddelené od stránky „Nástroje CLI“ v ovládacom paneli**, ktorá konfiguruje CLI nástroje tretích strán (Claude Code, Cursor, Codex, Cline, …), aby mohli komunikovať s OmniRoute.

```bash
omniroute setup                    # Interaktívny sprievodca (heslo, poskytovatelia, kombinácie)
omniroute setup --non-interactive  # Vhodné pre CI
omniroute doctor                   # Diagnostika stavu (dátový adresár, DB, poskytovatelia, porty)
omniroute providers available      # Zoznam podporovaných poskytovateľov
omniroute providers list           # Zoznam nakonfigurovaných pripojení
omniroute providers test <id>      # Test pripojenia k poskytovateľovi v reálnom čase
omniroute combos list              # Zoznam kombinácií
omniroute combos switch <name>     # Nastavenie predvolenej kombinácie
omniroute models                   # Zoznam dostupných modelov (--json, --search)
omniroute keys add | list | remove # Správa kľúčov API z terminálu
omniroute backup                   # Snímka konfigurácie + DB
omniroute restore [<timestamp>]    # Obnovenie zo snímky
omniroute health                   # Podrobný stav (ističe, vyrovnávacia pamäť, pamäť)
omniroute quota                    # Využitie kvót poskytovateľov
omniroute mcp status               # Stav servera MCP
omniroute a2a status               # Stav servera A2A
omniroute tunnel list|create|stop  # Tunely Cloudflare/Tailscale/ngrok
omniroute reset-password           # Obnovenie hesla správcu
omniroute --mcp                    # Spustenie servera MCP cez stdio
omniroute --port 3000              # Spustenie servera na vlastnom porte
```

Tip: prepojte `omniroute doctor --json` so svojím monitorovacím nástrojom, aby vás upozornil na nefunkčné pripojenia k poskytovateľom.
