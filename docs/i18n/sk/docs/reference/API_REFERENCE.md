## Dokončenia chatu

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

| `X-OmniRoute-Session-Id` | Požiadavka | Značka relácie/konverzácie zadaná volajúcim (používa sa aj pre pamäť). Ak je prítomná, uloží sa bez zmien do `call_logs.session_tag` na priradenie nákladov jednotlivým reláciám (#8249) — ak chýba, nikdy sa nevytvára |

| `x-omniroute-connection` | Požiadavka | Pripne požiadavku na jeden model k jednému pripojeniu poskytovateľa (účtu) podľa jeho ID — pozrite si [Pripnutie účtu pre jednotlivé požiadavky](#account-pinning-per-request)                                          |

#### Pripnutie účtu pre jednotlivé požiadavky

Keď má poskytovateľ viacero pripojení (účtov alebo kľúčov), OmniRoute zvyčajne jedno z nich vyberie
pomocou svojej stratégie výberu účtu. Požiadavka však môže pripnúť konkrétne pripojenie
pomocou hlavičky `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Kde nájsť id.** Otvorte stránku poskytovateľa v ovládacom paneli
  (**Ovládací panel → Poskytovatelia → <provider>**) a kliknite na štítok id `xxxxxxxx…` v riadku
  pripojenia — tým sa skopíruje celé id pripojenia.
- **Ktoré požiadavky ho rešpektujú.** Požiadavky s jedným modelom (`provider/model`) na
  `/v1/chat/completions`, `/v1/messages` a `/v1/responses`. Kombinácie túto hlavičku ignorujú: účet
  pre každý krok kombinácie pripnite prostredníctvom vlastného pripojenia daného kroku.
- **Pripnutie je striktné, nejde len o preferenciu.** Pripnuté pripojenie sa používa výhradne. Zlyhanie
  v rámci požiadavky zaznamená obdobie čakania účtu, ale **neprepne** na
  iný účet toho istého poskytovateľa.
- **Obdobie čakania a kvóta pripnutie uvoľnia.** Kým je pripnuté pripojenie v období čakania,
  má vyčerpanú kvótu alebo je zablokované pravidlami kvóty, neskoršie požiadavky prejdú na ostatné
  pripojenia poskytovateľa presne tak ako nepripnutá prevádzka.
- **Neznáme alebo zakázané id spôsobia zlyhanie.** Ak id nie je v aktívnom fonde poskytovateľa (bolo
  odstránené, deaktivované alebo patrí inému poskytovateľovi), nezostane žiadny vhodný účet, takže požiadavka
  zlyhá namiesto toho, aby bola bez upozornenia smerovaná inam.

Claude Code odosiela vlastné hlavičky prostredníctvom `ANTHROPIC_CUSTOM_HEADERS`. Vložte ho do bloku `env`
v súbore `~/.claude/settings.json` alebo do projektového súboru `.claude/settings.json`, ak chcete pre každý projekt
pripnúť iný účet:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Zdroj: `src/sse/handlers/chat.ts` (čítanie hlavičky), `src/sse/services/auth.ts` a
`src/sse/services/sessionAffinityPin.ts` (uvoľnenie pripnutia a kontrola neprítomnosti vo fonde).

> **Hlavičky telemetrie nákladov:** úspešné odpovede bez streamovania obsahujú aj súpravu telemetrie nákladov `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, presne 10 desatinných miest; `0.0000000000` pre bezplatné položky alebo položky bez stanovenej ceny), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` a `X-OmniRoute-Fallback-Attempts` (iba keď > 0), ako aj `X-OmniRoute-Request-Id` a `X-OmniRoute-Version`. Generujú ich dokončenia chatu, `/v1/responses`, `/v1/messages` **aj koncové body médií** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` a `/v1/moderations` (náklady vždy `0`). Náklady na médiá sa počítajú podľa modality (za obrázok, za sekundu, za znak, za vyhľadávaciu jednotku), ak sú dostupné cenové údaje; v opačnom prípade sú `0` (prístup fail-open).

> **Sémantika nákladov pri zásahu do vyrovnávacej pamäte:** pri zásahu do sémantickej vyrovnávacej pamäte (`X-OmniRoute-Cache-Hit: true`) sa nevykoná žiadne volanie nadradenej služby, takže `X-OmniRoute-Response-Cost` je `0.0000000000` (**prírastkové** náklady na obslúženie zásahu). Pôvodné/predpokladané náklady sa vykazujú samostatne v `X-OmniRoute-Cost-Saved`. Systémy spracúvajúce fakturáciu by mali sčítavať `X-OmniRoute-Response-Cost` (zásahy nič nestoja); analytické systémy vyrovnávacej pamäte môžu agregovať `X-OmniRoute-Cost-Saved`.

## Exkluzívne spravované prenájmy relácií

Exkluzívny spravovaný prenájom relácie je voliteľná smerovacia zmluva nezávislá od klienta: jeden aktívny vlastník
drží jedno oprávnené pripojenie OmniRoute. Neprenajíma model, nevyžaduje OAuth, neidentifikuje
konkrétneho klienta ani nevyžaduje konkrétneho poskytovateľa.

Overujúci API kľúč musí mať rozsah oprávnenia `lease:exclusive` a explicitný neprázdny
zoznam `allowedConnections`. Hranica databázových mutácií vynucuje obe polia spoločne pri vytváraní
kľúča aj pri čiastočných aktualizáciách.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Úspešné odpovede na získanie, obnovenie a uvoľnenie uvádzajú časové pečiatky, `state` a presnú kladnú
hodnotu `generation`, nikdy však vybrané pripojenie ani prihlasovacie údaje. Pri obnovení a uvoľnení sa
generácia uvádza v tele JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Vlastník aktívneho prenájmu si môže explicitne vyžiadať zobrazované metadáta chrániace súkromie pre svoju aktuálnu väzbu:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Táto voliteľná akcia stavu je v rámci jednej databázovej transakcie ohraničená nepriehľadným vlastníkom, overeným spravovaným API kľúčom a presnou
aktívnou generáciou. `displayName` obsahuje iba nakonfigurovaný názov
pripojenia bez okolitých medzier; ak neexistuje žiadny bezpečný nakonfigurovaný názov, má hodnotu `null`. OmniRoute ho nikdy nenahrádza
e-mailom ani vygenerovanou identitou účtu. Hodnota poskytovateľa je necitlivý zobrazovaný názov a nikdy
nejde o vygenerovaný identifikátor kompatibilného poskytovateľa. Prihlasovacie údaje, tokeny, súbory cookie, nespracované ID pripojení alebo API
kľúčov, haše vlastníkov, tajné údaje ohraničenia a interné smerovacie údaje sú vylúčené.

Vyhľadania s nesprávnym kľúčom, nesprávnym vlastníkom, zastaranou generáciou, ako aj chýbajúce, exspirované, uvoľnené a zneplatnené vyhľadania
vracajú rovnakú chybu `409 LEASE_FENCE_STALE` bez metadát pripojenia. Klient, ktorý dostal odpoveď o čakaní na kapacitu, nemá žiadnu aktívnu väzbu, ktorú by bolo možné preskúmať. Keď smerovanie prepne aktívny prenájom,
rovnaká generácia zostáva platná a stav atomicky vráti novú väzbu, nikdy nie starú.
Existujúci klienti zostávajú nezmenení, pretože odpovede na získanie, obnovenie, uvoľnenie a čakanie si zachovávajú
svoje predchádzajúce formáty.

Táto zmluva servera nemení štandardný príkaz OpenAI Codex `/status`. Štandardný Codex momentálne uvádza svojho
poskytovateľa modelu a vstavaný stav overenia/účtu, ale nezobrazuje ľubovoľné vlastné
metadáta účtu poskytovateľa; budúca integrácia klienta musí zavolať túto akciu a rozhodnúť, ako
zobraziť `connection.displayName`.

Každá spravovaná požiadavka na inferenciu potom uvádza obe riadiace hlavičky:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Presný vlastník, generácia, aktívne pripojenie a overený API kľúč sa ohraničia bezprostredne
pred každým podporovaným pokusom smerom k nadradenej službe. Opätovné použitie vlastníka a generácie s iným kľúčom zlyhá aj
vtedy, keď tento kľúč povoľuje rovnaké pripojenie. Nespracované hodnoty vlastníkov sa neukladajú, nezaznamenávajú do protokolov, neuchovávajú v
snímke požiadavky ani neposielajú nadradenej službe.

Dočasný konflikt vracia HTTP `429` s `Retry-After` a:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Táto odpoveď znamená iba to, že bežná množina oprávnených pripojení nebola prázdna a každý voľný kandidát bol
držaný cudzím aktívnym prenájmom. Nepodporované modely/poskytovatelia, nesúlad so zásadami, čakacia lehota, kvóta,
stav služby a ďalšie bežné zlyhania oprávnenosti si zachovávajú svoje existujúce odpovede OmniRoute.

### `x-omniroute-compression`

Prepísanie plánu kompresie pre konkrétnu požiadavku. Má najvyššiu prioritu — prevažuje nad prepísaním kombinácie
smerovania, aktívnym profilom, automatickým spustením aj predvoleným nastavením panela. Hodnoty:

| Hodnota       | Účinok                                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------------------------- |
| `off`         | Bez kompresie pre túto požiadavku.                                                                              |
| `default`     | Predvolený profil odvodený od panela (ignoruje aktívny profil). Stratové mechanizmy zostávajú vypnuté.          |
| `safe`        | Iba deduplikácia a zlučovanie bielych znakov.                                                                   |
| `allow-lossy` | Zachová plán operátora pre túto požiadavku vrátane súhrnov a prepisovania štýlu.                                |
| `engine:<id>` | Jeden mechanizmus, ak je povolený, napr. `engine:rtk`. Voliteľná aktivácia tohto mechanizmu pre požiadavku.     |
| `<combo>`     | Pomenovaná kombinácia, ktorá sa najprv porovná podľa názvu (bez rozlišovania veľkosti písmen) a potom podľa ID. |

Poznámky:

- Neznáme hodnoty sa ignorujú (požiadavka sa nikdy neodmietne); vyhodnocovanie pokračuje podľa bežného poradia priorít operátora.
- Ak má viacero kombinácií rovnaký názov, na jednoznačné priradenie odovzdajte **id** kombinácie.
- Kombináciu s názvom `off` alebo `default` nemožno vybrať podľa názvu (tieto kľúčové slová sa interpretujú ako prvé); na takúto kombináciu odkazujte pomocou jej ID.
- Hlavný prepínač kompresie predstavuje neprekročiteľnú podmienku: keď je kompresia globálne zakázaná, táto hlavička ju nemôže povoliť.

Použitý plán sa zopakuje v hlavičke odpovede:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

kde `<source>` je jedna z hodnôt `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` alebo `off`.

## Vektorové reprezentácie

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Dostupní poskytovatelia: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Identifikátory katalógu majú formát `provider/model` (príklad: `jina-ai/jina-embeddings-v5-omni-small`). Samostatné identifikátory modelov Jina, ktoré sa nachádzajú v registri (napríklad `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`), sa tiež rozpoznajú. Operácie embed/rerank/classify/segment služby Jina najprv používajú prihlasovacie údaje `jina-ai` z ovládacieho panela; `JINA_AI_API_KEY` sa použije ako záložná možnosť iba vtedy, keď v ovládacom paneli neexistuje žiadny kľúč. Karta `jina-reader` je určená iba pre Reader / `r.jina.ai` (`POST /v1/web/fetch`) a nikdy neposkytuje vektorové reprezentácie ani zmenu poradia.

Modely v registri, ktoré deklarujú podporu multimodality, prijímajú aj najviac 32 štruktúrovaných
položiek nezávislých od poskytovateľa. Typy multimediálnych položiek sú `text`, `image`, `audio`, `video` a `document`. Ich multimediálny `source`
má buď podobu `{"type":"url","url":"https://..."}`, alebo
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
a alias rodiny `jina-ai/jina-embeddings-v5-omni` → omni-small) prijíma aj natívne dokumenty
EmbeddingsV5Request služby Jina a **bez zmeny ich preposiela** na `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Natívne hodnoty `{ image | audio | video | pdf }` môžu byť verejná adresa URL HTTPS, URI `data:` alebo nespracované
dáta base64. OmniRoute tieto objekty neprevádza na reťazce ani nenačítava natívne adresy URL obrázkov — verejné
médiá načíta samotná služba Jina. Dodatočné polia Jina (`task`, `normalized`, `truncate`, `embedding_type`) sa
preposielajú. SKU Jina určené iba pre text naďalej odmietajú netextové dokumenty.

Bezpečnostné a prenosové obmedzenia:

- Vzdialené adresy URL médií musia byť verejné adresy HTTPS. Kanonické položky `{type,source:url}` sa načítavajú
  na strane servera (opätovné overenie presmerovaní, časový limit, obmedzenia veľkosti, verejný DNS, pripnutie pripojenia) a
  pred volaním poskytovateľa sa vložia priamo do požiadavky. Natívne položky Jina `{image:"https://..."}` sa preposielajú bez zmien
  po rovnakej kontrole verejnej adresy HTTPS; adresu URL načíta služba Jina.
- Multimédiá base64 vložené priamo v požiadavke sú obmedzené na 8 MiB dekódovaných dát na položku a 16 MiB dekódovaných dát v rámci celej požiadavky.

Prevod pre poskytovateľov (kanonické položky sa nikdy nepreposielajú bez zmien):

- Multimodálne modely Jina: každá položka najvyššej úrovne sa zmení na jeden objekt s kľúčom modality
  (`text` / `image` / `audio` / `video` / `pdf`), pričom pre médiá vložené priamo v požiadavke sa použijú URI dát; pre každú
  položku najvyššej úrovne sa vytvorí jeden vektor.
- Rodina Gemini Embedding 2: jedno pole najvyššej úrovne sa zmení na jednu natívnu
  požiadavku `models/{model}:embedContent` s `content.parts` (`text` alebo `inline_data`).
- llama.cpp (`llama-cpp/<model>`, ľubovoľný model načítaný lokálnym serverom): kanonické položky `text`
  sa zmenia na obyčajné reťazce a položky `image` / `audio` / `video` sa zmenia každá na jeden
  objekt `{"content": [part]}`, pričom sa použijú časti konverzačného obsahu llama-server (`image_url`,
  `input_audio` s formátom `wav` / `mp3` / `flac`, `input_video`) s priamo vloženými dátami; pre každú
  položku najvyššej úrovne sa vytvorí jeden vektor. Server musí byť spustený s `--embedding --mmproj …`; bez projektora
  sám odmietne médiá. Typ `document` nie je podporovaný.
- Neznáme/dynamické modely bez explicitných metadát modality odmietnu štruktúrovaný vstup s kódom HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Nepodporované kombinácie modelov a modalít vrátia HTTP 400 namiesto konverzie položky. Rozširujúce polia
mimo vstupu v starších požiadavkách s reťazcami/tokenmi sa naďalej preposielajú bez zmien.

```bash
# Zobrazenie všetkých modelov vektorových reprezentácií
GET /v1/embeddings
```

## Generovanie obrázkov

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Medzi dostupných poskytovateľov patria OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (lokálny) a ComfyUI (lokálny).

`n` vráti `n` obrázkov v `data[]`. Pri poskytovateľoch, ktorých nadradené API vracia jeden obrázok na volanie
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI), sa vykoná `n` samostatných nadradených volaní, pričom súčasne môžu prebiehať najviac 4. Pevná
hodnota `seed` sa posunie o index volania (`seed`, `seed + 1`, …), takže obrázky sa líšia, ale zostávajú
reprodukovateľné. Hodnota `n` je obmedzená na 10. Ak zlyhá ktorékoľvek volanie, zlyhá celá požiadavka. Zoznam
formátov s rozdelením na viacero volaní je `SINGLE_IMAGE_FANOUT_FORMATS` v súbore
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux opätovne používa existujúce pripojenie s kľúčom API a prijíma predpony `zenmux/` alebo `zm/`:

- `zenmux/openai/gpt-image-2` používa OpenAI Images API od ZenMux. Medzi možnosti patria `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` a `response_format`.
- Ostatní vydavatelia, napríklad `zm/meta/muse-image-1.0`, používajú koncový bod Vertex AI `:predict`
  od ZenMux. `n` sa mapuje na `sampleCount`, `aspect_ratio` na `aspectRatio` a `image_size`
  (`1K`, `2K`, `4K`) na `sampleImageSize`. Hodnota `size` v pixeloch určuje iba pomer strán,
  nie zaručené rozmery v pixeloch. Podporované pomery strán, rozlíšenia a počty sa líšia podľa modelu.
- `zm/inclusionai/ming-image-0.1-design` si vyberá vlastné rozmery. Vynechajte `size`,
  `aspect_ratio` a `image_size`; explicitné hodnoty vrátia HTTP 400. Formáty PNG, JPEG a WebP
  možno vyžiadať pomocou `output_format`.

Táto integrácia podporuje generovanie obrázkov z textu, nie úpravu referenčných obrázkov. Výstup Vertex
sa normalizuje do `data[].b64_json`; `response_format: "url"` vráti nadradenú
adresu URL HTTPS alebo dátovú adresu URL base64, ak sú k dispozícii iba bajty obrázka. Prázdne alebo odfiltrované výstupy
vrátia chybu namiesto prázdnej úspešnej odpovede. Prístup k modelom závisí od účtu ZenMux.
Pozrite si [Vertex API od ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) a
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# Zobrazenie všetkých obrazových modelov
GET /v1/images/generations
```

## OCR dokumentov

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
```

`model` vyberá poskytovateľa OCR pomocou predpony `provider/model`; samotný identifikátor modelu (napr.
`mistral-ocr-latest`) sa priradí k jeho registrovanému poskytovateľovi a pri vynechaní `model` sa predvolene použije
Mistral (`mistral-ocr-latest`). Registrovaní poskytovatelia (`open-sse/config/ocrRegistry.ts`):

| ID poskytovateľa              | ID modelu            | Hodnota `model`                                                   | Poznámky                                                                                                                                           |
| ----------------------------- | -------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (alebo samotné `mistral-ocr-latest`) | Synchrónne — odpoveď sa vráti priamo z jediného nadradeného volania.                                                                               |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                       | Asynchrónne nadradené rozhranie (`analyze` + dopytovanie) — pozrite nižšie.                                                                        |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                           | Synchrónne, prostredníctvom partnerského koncového bodu Vertex AI `openapi/chat/completions` — informácie o overovaní a adrese URL nájdete nižšie. |

Všetci traja poskytovatelia odpovedajú rovnakým telom v tvare Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Priebeh dopytovania Azure Document Intelligence

API `analyze` služby Azure Document Intelligence je asynchrónne: počiatočná požiadavka vráti hlavičku
`Operation-Location` namiesto tela a výsledok sa musí získavať opakovaným dopytovaním. Obslužný program
(`open-sse/handlers/ocr.ts`) sa na túto adresu URL dopytuje každú sekundu, najviac však 30-krát; okamžite zlyhá (nepokračuje
v dopytovaní) pri odpovedi na dopyt, ktorá nie je `ok`, alebo pri stave `"failed"`, a vráti `504`, ak
operácia stále prebieha po vyčerpaní limitu pokusov. Konečná odpoveď Azure sa
pred vrátením volajúcemu normalizuje do rovnakého tvaru `pages`/`markdown`, aký používa Mistral,
takže klientsky kód nemusí poskytovateľa spracovávať osobitne.

### Overovanie a rozpoznanie koncového bodu Vertex AI DeepSeek OCR

`vertex-deepseek-ocr` opätovne používa rovnaké overovanie Vertex AI, ktoré OmniRoute už podporuje pre
chatovú a obrazovú komunikáciu (`open-sse/executors/vertex.ts`): kľúč API pripojenia je buď
poverenie Service Account JSON (vymenené za krátkodobý prístupový token OAuth prostredníctvom toku JWT bearer),
alebo už vydaný prístupový token OAuth použitý bez zmeny. Nadradená adresa URL koncového bodu je všeobecný
partnerský koncový bod Vertex `openapi/chat/completions`, zostavený z projektu a regiónu pripojenia
— explicitná hodnota `providerSpecificData.project`/`providerSpecificData.region` má vždy prednosť;
inak sa projekt odvodí z `project_id` v Service Account JSON a ako predvolený región
sa použije `us-central1`. Obe rozpoznania prebiehajú v `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) a používa ich
`src/app/api/v1/ocr/route.ts` pred odoslaním do `handleOcr`.

### Ceny modelov (`pricing`)

Položka obsahuje objekt `pricing`, keď OmniRoute pozná cenu modelu. Cena pochádza
z cenovej tabuľky používanej na účtovanie nákladov: vstavané predvolené hodnoty, synchronizované ceny a
prepísania nastavené prostredníctvom `/api/pricing`. Ide o cenníkové ceny, takže poskytovatelia predplatného tiež
zobrazujú cenu za token.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Polia                                                           | Jednotka                        | Poznámky                                                                                                                                                  |
| --------------------------------------------------------------- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | USD za token, desatinný reťazec | Kompatibilné s OpenRouter, nikdy nie v exponenciálnom zápise. Dve polia vyrovnávacej pamäte sa zobrazia iba vtedy, keď existuje cena vyrovnávacej pamäte. |
| `input`, `output`, `cached`, `cache_creation`                   | USD za 1 mil. tokenov, číslo    | Polia zo starších verzií katalógu, zachované pre existujúcich klientov. `reasoning` a `long_context` sa tiež zobrazia, keď ich cenový riadok obsahuje.    |

- **Kombinácie** obsahujú cenu svojho prvého viditeľného cieľa. Vstavané kombinácie `auto/*` vyberajú
  cieľ v čase požiadavky, takže nemajú `pricing`.
- **Bezplatné modely** zobrazujú `"0"` (a `0`), keď je ich cena nulová. Model bez cenového riadka
  tiež zobrazuje `"0"`, keď ho katalóg označuje ako bezplatný (`free: true`) alebo keď sa nachádza vo vstavanom katalógu
  bezplatných modelov.
- **Neznáma cena:** položka nemá kľúč `pricing`.
- **Poskytovatelia účtujúci kredity** (napríklad Kiro) účtujú za požiadavku, nie za token. Ich
  položky si zachovávajú číselné polia ceny za 1 milión tokenov, ktoré mali predtým, a neobsahujú reťazcové polia ceny za token.
- **Varianty** (id intenzity uvažovania, aliasy bez uvažovania, vyhľadávacie a bránové zrkadlá)
  kopírujú cenu modelu, na ktorý smerujú.
- Polia obsahujú iba základné sadzby. Úrovne pre dlhý kontext (číselné pole `long_context`) a
  násobitele úrovne služby (napríklad Codex fast alebo flex) nemenia `prompt` ani
  `completion`.
- Objekt je rovnaký pre každý spôsob autentifikácie vrátane požiadavky v štýle Anthropic
  s `x-api-key` a `anthropic-version` (odpoveď zostáva `{ "object": "list",
"data": [...] }`). Implementácia: `src/app/api/v1/models/catalogPricing.ts`.

### Predpony id modelov (`?prefix=`)

Väčšina modelov sa zobrazuje pod **predponou poskytovateľa**. To, ktorú predponu dostanete, riadi
príznak funkcie `MODELS_CATALOG_PREFIX_MODE` a možno ho prepísať **pre každú požiadavku** pomocou
parametra dopytu — je to užitočné pre klienta, ktorý chce prehľadný zoznam bez zmeny celoserverového
nastavenia pre všetkých ostatných:

```bash
GET /v1/models?prefix=alias        # jedno id na model — krátka predpona aliasu
GET /v1/models?prefix=dual         # obe formy (predvolené nastavenie servera)
GET /v1/models?prefix=canonical    # iba úplná predpona id poskytovateľa
```

| Režim       | Poskytuje                                               | Poznámky                                                                                                                                                                                        |
| ----------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **a** `claude/claude-sonnet-4-6` | **Predvolené.** Obe id smerujú na rovnaký model; zachované, aby konfigurácie klientov, ktoré majú napevno nastavenú ktorúkoľvek formu, naďalej fungovali. Približne zdvojnásobuje katalóg.      |
| `alias`     | `cc/claude-sonnet-4-6`                                  | Jedna položka na model. Poskytovatelia bez samostatného aliasu stále poskytujú svoju položku, takže sa nič nestratí.                                                                            |
| `canonical` | `claude/claude-sonnet-4-6`                              | Jedna položka na model pod úplnou predponou id poskytovateľa. Poskytovatelia bez samostatného aliasu (napr. `antigravity/…`, `agy/…`) tu tiež poskytujú svoje jediné id, takže sa nič nestratí. |

Zrkadlo režimu `dual` možno rozpoznať aj bez parametra dopytu: obsahuje pole `parent`
odkazujúce na primárne id.

Klienti, ktorí zobrazujú výber modelu, by mali požadovať `?prefix=alias` — takto to robí
[rozšírenie OmniCopilot pre VS Code](../guides/VSCODE-COPILOT.md).

### Filtre vyhľadávania (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` podporuje voliteľné filtre vyhľadávania. Bez ktoréhokoľvek z nich zostáva odpoveď
nezmenená. Zužujú katalóg, ktorý už volajúci vidí (najskôr sa uplatnia oprávnenia kľúča API),
a spúšťajú sa pred stránkovaním v štýle OpenAI pomocou `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # každá uvedená schopnosť musí byť pravdivá
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # katalógové `type`; riadky bez neho sú `chat`
GET /v1/models?q=sonnet&limit=10                           # zhoda bez rozlišovania veľkosti písmen v id alebo názve
```

| Parameter     | Hodnoty                                                                                             |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | nezáporné celé číslo porovnávané s `context_length`                                                 |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 znakov                                                                                        |

Neznáma hodnota alebo `min_context`, ktorý nie je nezáporným celým číslom (napríklad `1.5`),
vráti HTTP `400` a správa uvedie platné hodnoty. Implementácia:
`src/app/api/v1/models/catalogFilters.ts`.

### Užší výber modelov (`POST /v1/models/query`)

`POST /v1/models/query` vráti krátky, deterministický zoznam z rovnakého katalógu s rovnakým
overovaním a viditeľnosťou pre jednotlivé kľúče ako `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Každé pole je voliteľné. `capabilities` a `exclude` prijímajú pole alebo reťazec s hodnotami
oddelenými čiarkami; `max_output` sa porovnáva s `max_output_tokens`. Výsledky sú zoradené podľa
`owned_by` a následne podľa `id`. Predvolená hodnota `limit` je `20` a hodnoty nad `100` sú
obmedzené na `100`. Neplatný JSON, neznáme pole alebo neplatná hodnota vrátia HTTP `400`.

### Individuálne skryté četové modely

Model označený na stránke svojho poskytovateľa ako **Skrytý** je vylúčený z katalógu a pri
explicitnom vyžiadaní odmietnutý s HTTP `404` / `model_not_found`. Kontrola používa určeného
poskytovateľa a model vrátane aliasov poskytovateľov, prefixov uzlov kompatibilných
poskytovateľov a predvolených nastavení pripojenia. Kombinácia preskočí skryté ciele a môže
použiť viditeľný súvisiaci model; ak nezostane žiadny spustiteľný cieľ, vráti rovnaký chybový
kód. Zrušenie skrytia sa prejaví pri nasledujúcej požiadavke. Nastavenia viditeľnosti iba pre
obrázky neskryjú četový model s rovnakým ID.

Toto individuálne nastavenie modelu je oddelené od
[zoznamov povolených a zakázaných modelov](../routing/MODEL_EXPOSURE_LIST.md), ktoré filtrujú
zverejnenie v katalógu a kandidátov na automatické smerovanie, pričom zachovávajú explicitné
odoslanie. Oprávnenia modelov pre API kľúče sa naďalej uplatňujú nezávisle. Predvolený režim
prefixov katalógu zostáva `dual`.

### Varianty modelov bez premýšľania

Pre modely Claude podporujúce premýšľanie `/v1/models` propaguje aj variant **bez premýšľania**,
ktorého ID má prefix `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Výber tohto ID (napr. v konfigurácii Claude Code, ktorá vždy pripája blok `thinking`) sa preloží
späť na skutočný `<provider>/<model>` s potlačeným uvažovaním — `thinking:{type:"disabled"}` na
ceste `/v1/messages` alebo s vynechanými poľami `reasoning`/`reasoning_effort` na ceste
`/v1/chat/completions`. Variant sa uvádza iba pre modely z rodiny Claude, ktoré podporujú
premýšľanie **a zároveň** rešpektujú `disabled` (takže napr. modely výhradne s adaptívnym režimom,
ktoré odmietajú `disabled`, sú vylúčené). Prevádzkovatelia môžu variant pre jednotlivé modely
vynútene zapnúť alebo vypnúť pomocou `ModelSpec.noThinkingAlias`.

## Generovanie zvuku pomocou ElevenLabs

Nakonfigurujte v OmniRoute pripojenie poskytovateľa `elevenlabs` pomocou svojho kľúča API ElevenLabs.
Klienti sa autentifikujú pomocou svojho kľúča **OmniRoute** (`Authorization: Bearer $OMNIROUTE_API_KEY`);
brána poskytne uložený kľúč poskytovateľa ako `xi-api-key`. Nikdy neposielajte kľúč ElevenLabs
ako bearer token brány.

| Metóda | Cesta                       | Odpoveď                                  | Kategória koncového bodu kľúča API |
| ------ | --------------------------- | ---------------------------------------- | ---------------------------------- |
| POST   | `/v1/sound-generation`      | Natívne zvukové bajty                    | `elevenlabs`                       |
| POST   | `/v1/music`                 | Natívne zvukové bajty                    | `music`                            |
| POST   | `/v1/music/stream`          | Streamované zvukové bajty                | `music`                            |
| POST   | `/v1/music/detailed`        | Natívny multipart zvuk a plán kompozície | `music`                            |
| POST   | `/v1/music/detailed/stream` | Natívne metadáta SSE a zvukové bloky     | `music`                            |
| POST   | `/v1/music/plan`            | Plán kompozície vo formáte JSON          | `music`                            |

Tieto koncové body dopĺňajú existujúce trasy `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` a `/v1/speech-to-text`. Natívne polia JSON
a parametre dopytu, ako napríklad `output_format` a `enable_logging`, sa zachovávajú.
Odpovede `/v1/music/detailed` si zachovávajú svoje multipart hranice; spracujte ich ako multipart.
`/v1/music/detailed/stream` vracia `text/event-stream` s metadátami kompozície a
zvukovými blokmi base64 v udalostiach SSE. Všetkých šesť trás podporuje predbežné požiadavky CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Krátky zvukový efekt. Trvanie: 0,5 až 30 sekúnd.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Trvanie hudby sa vyjadruje v milisekundách: 3000 až 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Na postupné doručovanie zvuku použite `/v1/music/stream` s rovnakým telom JSON. Kompozícia
prijíma presne jedno z `prompt` alebo `composition_plan`; `/v1/music/plan` vyžaduje `prompt`
a voliteľne prijíma `source_composition_plan`. Natívne schémy zachovávajú ďalšie
polia poskytovateľa, takže verzie plánu kompozície a možnosti dolaďovania sa prenesú do ElevenLabs.

Zjednotený koncový bod `/v1/music/generations` tiež prijíma `elevenlabs/music_v1`,
`elevenlabs/music_v2` a `elevenlabs/music_v2_5`. Pri aktívnom pripojení ElevenLabs
sú tieto modely dostupné v hudobnom katalógu. Tento koncový bod vracia
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Jeho pole `duration` je uvedené
v sekundách a mapuje sa na `music_length_ms`; explicitné `music_length_ms` má prednosť.
`instrumental` sa mapuje na `force_instrumental`, pričom natívne pole má prednosť.
Na streamovanie používajte natívne streamovacie koncové body a na požiadavky riadené
iba plánom kompozície použite natívny koncový bod kompozície.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Pred volaním nadradenej služby sa uplatnia obmedzenia koncového bodu, modelu, rozpočtu a pripojenia. Natívne
trasy vracajú stavové kódy a telá chýb nadradenej služby bez zmien vrátane `402` pri obmedzení
plánu a `429` pri prekročení kvóty. Hlavičky `character-cost`, `song-id`, `request-id` a `retry-after`
sa zachovajú, ak sú prítomné. Bezplatný zostatok kreditu nezaručuje prístup ku každému
hudobnému modelu, výstupnému formátu ani funkcii API: o oprávnení pre každú požiadavku rozhoduje ElevenLabs.
Zjednotený koncový bod zachováva stavové kódy chýb v normalizovanej chybovej obálke OmniRoute.

Zmluvy nadradenej služby: [zvukové efekty](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[kompozícia hudby](https://elevenlabs.io/docs/api-reference/music/compose) a
[podrobnosti streamovania hudby](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

Všetky trasy POST majú rovnakú štruktúru: `Bearer your-api-key` + telo JSON overené pomocou Zod (`v1RerankSchema`, `v1ModerationSchema`, `v1AudioSpeechSchema` atď.; pozrite si `src/shared/validation/schemas.ts`). Pri zlyhaní overenia schémy sa vráti stavový kód 4xx.

Klientom, ktoré nedokážu pripojiť `Authorization: Bearer ...`, umožňuje OmniRoute odovzdať kľúče API aj v adrese URL, a to buď prostredníctvom kompatibilných parametrov reťazca dopytu (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`), alebo cez vyhradené koncové body `/api/v1/vscode/{token}/...` zdokumentované nižšie.

```bash
# Preusporiadanie výsledkov (poskytovateľ z cloudového registra alebo uzol poskytovateľa kompatibilného s OpenAI vo forme "<prefix>/<model>")
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Klasifikácia Jina (prihlasovacie údaje Foundation API)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Segmentátor Jina
POST /v1/segment     { "content": "...", "return_chunks": true }

# Vyhľadávanie Jina (s.jina.ai; aliasy poskytovateľa: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# Moderovanie
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — vracia telo vo formáte audio/mpeg (alebo v požadovanom formáte)
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS vyžaduje jazyk a hlas: predvolená hodnota `language` je "en"; chýbajúci
# hlas alebo názov štandardného hlasu OpenAI (alloy, nova, …) sa zmení na "Adrian"
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# Úprava obrázka (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# Generovanie videa/hudby (ID modelu s predponou poskytovateľa)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **Uzly poskytovateľov pre preradenie:** `POST /v1/rerank` smeruje požiadavky aj na uzly poskytovateľov kompatibilné s OpenAI
> (oMLX, vLLM, Infinity, TEI za bránou, …), ktoré sú adresované ako `<node-prefix>/<model>`. Uzly spätnej slučky
> (`localhost`, `127.0.0.1`, `172.16.0.0/12`) sú vždy oprávnené, rovnako ako názvy hostiteľov, ktoré
> operátor uvedie v `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (napr. názov služby Docker/Compose, ako
> `http://reranker:8080/v1`; tieto sa volajú priamo, nikdy nie cez `HTTP(S)_PROXY` ani pripnutý proxy server
> pripojenia). Uzly na akomkoľvek inom
> hostiteľovi — zariadenie v sieti LAN alebo partnerské zariadenie Tailscale — sú oprávnené iba vtedy, keď operátor povolí
> príznak funkcie `RERANK_REMOTE_PROVIDER_NODES` **a zároveň** základná URL adresa uzla spĺňa pravidlá
> odchádzajúcich URL adries poskytovateľa (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Krok preradenia pamäťového mechanizmu volá túto trasu cez
> spätnú slučku, takže rovnaké pravidlo sa vzťahuje na `rerankProviderModel` v nastaveniach pamäte.
>
> **Podoby lokálnych serverov:** uzol sa volá na adrese `<base>/v1/rerank` a pri odpovedi 404 na adrese `<base>/rerank`
> (Infinity, TEI). Telo požiadavky upstreamu obsahuje pravopis variantu Cohere/OpenAI (`documents`,
> `return_documents`) aj variantu TEI (`texts`, `return_text`) a odpoveď upstreamu sa
> normalizuje do obálky Cohere: holé pole TEI `[{index, score, text}]`, `{results: [{index, score}]}`
> z jednoduchých brán aj formát Voyage `{data: [...]}` sa klientovi vrátia ako
> `{results: [{index, relevance_score, document?}]}`, zoradené podľa skóre a obmedzené hodnotou `top_n`.

> **Vyhľadávanie uzlov poskytovateľov:** modely na uzle poskytovateľa kompatibilnom s OpenAI sa zobrazujú v `GET /v1/models`
> pod prefixom uzla. Riadky, ktoré neobsahujú metadáta koncového bodu (typické pre lokálne výpisy `/v1/models`),
> dedia `apiType` uzla, takže modely uzla `embeddings` majú `type: "embedding"` a modely
> uzla `rerank` majú `type: "rerank"` namiesto predvoleného nastavenia na chat; explicitná hodnota
> `supportedEndpoints` v synchronizovanom alebo manuálne pridanom riadku má naďalej prednosť.

## Files API

Koncový bod súborov kompatibilný s OpenAI na dávkový vstup/výstup a nahrávanie súborov podľa účelu.

| Metóda | Cesta                    | Popis                                                                                                            |
| ------ | ------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/files`              | Nahranie súboru (multipart: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — max. 512 MiB |
| GET    | `/v1/files`              | Zoznam súborov pre overený kľúč API                                                                              |
| GET    | `/v1/files/[id]`         | Získanie metadát súboru                                                                                          |
| DELETE | `/v1/files/[id]`         | Odstránenie súboru                                                                                               |
| GET    | `/v1/files/[id]/content` | Odoslanie nespracovaného obsahu súboru späť formou streamu                                                       |

**Autorizácia:** Kľúč API typu Bearer — rozsah súborov je obmedzený podľa kľúča API prostredníctvom `getApiKeyRequestScope`. Kľúč
vidí, sťahuje a odstraňuje iba vlastné súbory; relácia ovládacieho panela bez kľúča má prístup na čítanie v rámci
celej inštancie; prístup k súboru bez vlastníka (anonymné nahranie alebo nahranie prostredníctvom relácie ovládacieho panela) je zamietnutý každému
volajúcemu bez relácie. `GET /v1/files` odmietne anonymného volajúceho — aj poskytnutý kľúč, ktorý

## API Web Fetch

Extrahuje obsah z URL prostredníctvom nakonfigurovaného poskytovateľa webového načítania (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, rovnaký kľúč API ako Parallel Search) vracia iba Markdown
— akýkoľvek iný `format` vedie k odpovedi `400` — a obmedzuje obsah na 100 000 znakov. Keď
samotnú cieľovú stránku nemožno extrahovať, nadradená služba to oznámi v rámci HTTP 200;
OmniRoute to sprístupní ako `422` s pevne stanovenou správou.

| Metóda | Cesta           | Opis                                                           |
| ------ | --------------- | -------------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Načíta/extrahuje URL — telo overené pomocou `v1WebFetchSchema` |

**Autentifikácia:** Kľúč API typu Bearer (`extractApiKey` + `isValidApiKey`). Zásady sa vynucujú prostredníctvom `enforceApiKeyPolicy`.

**Záložný mechanizmus zohľadňujúci kvóty (#8297):** keď nie je uvedený explicitný `provider`, fond
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) sa
prechádza v pevnom
poradí priorít (najprv sa naplní prvý) — nakonfigurovaný poskytovateľ s obmedzenou frekvenciou požiadaviek sa preskočí
namiesto okamžitého ukončenia požiadavky a opakovateľné zlyhanie nadradenej služby alebo zlyhanie pre vyčerpanú kvótu
(HTTP 429 vždy; 402/403 pre bezplatné úrovne služieb Firecrawl/Tavily/TinyFish s kvótami —
nie pre Jina Reader a nikdy nie pre obyčajnú chybnú požiadavku 400) spôsobí počas spracovania požiadavky prechod na
ďalšieho doteraz nevyskúšaného poskytovateľa s nakonfigurovanými prihlasovacími údajmi. Keď sú všetci poskytovatelia vo
fonde vyčerpaní, koncový bod vráti jednu odpoveď `429` (s hlavičkou `Retry-After`)
namiesto predchádzajúcej všeobecnej odpovede `400`. Keď sa požaduje explicitný `provider`,
**nepoužije sa žiadny** tichý záložný mechanizmus — explicitný poskytovateľ s obmedzenou frekvenciou požiadaviek alebo so zlyhaním
sprístupní svoju vlastnú chybu (`429`, ak je obmedzená frekvencia požiadaviek, inak stav nadradenej
služby).

## Streamovanie cez WebSocket

```bash
GET /v1/ws?handshake=1
```

Overí inicializačnú požiadavku na prechod na WebSocket a vráti vzorové správy drôtového protokolu (`request`, `cancel`). Skutočné rámce WS spracúva pribalený server WS mimo tabuľky trás Next.js.

**Autentifikácia:** Kľúč API typu Bearer počas inicializácie spojenia.

### Responses API cez WebSocket (iba codex)

```bash
# Rovnaký hostiteľ a port ako API HTTP (predvolene 20128); prepnite pripojenie:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (alebo: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Prvým rámcom MUSÍ byť response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proxy Responses API cez WebSocket je napojené **výhradne na `codex`** (backend ChatGPT).
Počúva na rovnakom porte ako API/ovládací panel na cestách `/v1/responses`,
`/responses` a `/api/v1/responses`. Pri prvom rámci `response.create`
vykoná autentifikáciu a prípravu prostredníctvom interného mosta `codex-responses-ws`, vyberie
pripojenie codex OAuth a vytvorí tunel k `wss://chatgpt.com/backend-api/codex/responses`
prostredníctvom transportu `wreq-js`. **Modely iné ako codex sa odmietnu** (`codex_ws_provider_required`).
Na smerovanie s podielom kvóty použite `model: "qtSd/<group>/codex/<model>"`. Implementované v
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Autentifikácia:** Kľúč API typu Bearer počas inicializácie spojenia. Pribalený server HTTP (`server-ws.mjs`)
musí byť aktívnym vstupným bodom (predvolene ním je, keď existuje `app/server-ws.mjs`).

#### ID modelu: použite základné ID ChatGPT (bez predpony `codex/`)

OpenAI **Codex CLI** overuje názov modelu na strane klienta, keď je
`supports_websockets = true`, a **odmieta ID s predponou poskytovateľa**, ako je
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Odošlite **základné** ID (napr. `gpt-5.5`). Most OmniRoute je
určený iba pre codex, preto pred vytvorením tunela k nadradenej službe znova vyhodnotí základné ID ako model codex
(`resolveCodexWsModelInfo`) — aj keď by sa základné
`gpt-5.5` cez HTTP inak smerovalo k inému poskytovateľovi.

#### Konfigurácia OpenAI Codex CLI

Nasmerujte Codex CLI na OmniRoute pridaním vlastného poskytovateľa s podporou WebSocket
do `~/.codex/config.toml` (použite samostatný `CODEX_HOME`, aby ste neovplyvnili
existujúcu konfiguráciu):

```toml
model = "gpt-5.5"                 # základné ID — NIE „codex/gpt-5.5“
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # bez koncovej lomky; URL WS sa odvodí (v produkcii použite https/wss)
wire_api = "responses"                    # jediná podporovaná hodnota od februára 2026
supports_websockets = true                # povoľuje transport Responses cez WS
env_key = "OMNIROUTE_API_KEY"             # obsahuje kľúč API OmniRoute (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # kľúč API OmniRoute (ľubovoľný kľúč, ak REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI prepne `base_url + /responses` na WebSocket a OmniRoute ho tuneluje
k vybranému pripojeniu codex OAuth. Overené komplexne voči lokálnemu
serveru: ChatGPT vráti `codex.rate_limits` + `response.created` a streamuje
dokončenie.

## Samoobslužné používanie (`/api/usage/om-usage`)

Ľubovoľný API kľúč môže čítať **svoje vlastné** využitie a kvóty — bez autentifikácie na správu. Toto je koncový bod, ktorý
klient (CLI, panel OmniCopilot) používa na zobrazenie výdavkov držiteľovi kľúča.

```bash
# Textová forma (historický kontrakt — obyčajný text pre terminál)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Štruktúrovaná forma — používaná používateľským rozhraním
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Kľúč musí mať povolené **`allowUsageCommand`** (predvolene je vypnuté — správca API kľúčov na ovládacom paneli
ho prepína pre každý kľúč samostatne). Bez tohto povolenia koncový bod odpovie stavom `403`.

`?format=json` vracia rozlíšiteľnú štruktúru, takže volajúci nikdy nečíta dátové pole z
odmietnutej odpovede. Pri úspechu:

```jsonc
{
  "allowed": true,
  // prítomné iba vtedy, keď má kľúč zapnuté limity využitia pre konkrétny kľúč (denné/týždenné v USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // snímka kvóty vybraného poskytovateľa alebo null, ak zatiaľ nie je nič vo vyrovnávacej pamäti:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // snímka každého pripojenia, aby používateľské rozhranie mohlo vykresliť viacero poskytovateľov vedľa seba:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Pri odmietnutí (`401` neplatný kľúč / `403` nepovolené) tá istá trasa vráti
`{ "allowed": false, "error": { "message": "…" } }` — prítomné, ale prázdne `personal`/`provider`
(kľúč je povolený, ale zatiaľ neboli získané žiadne údaje) predstavuje iný stav než odmietnutie a rozlišuje ich
iba forma JSON.

**Autentifikácia:** vlastný Bearer API kľúč volajúceho, overený pomocou `isValidApiKey` — toto _nie je_
rozhranie na správu (`/api/keys/…`), ktoré zostáva chránené pomocou `requireManagementAuth`.

### Nespracované percentá kvót verzus percentá upravené podľa hraničnej hodnoty

Pri používaní `/api/usage/om-usage` by volajúci mali brať do úvahy rozdiel medzi
percentami uvádzanými vo **výstupe obyčajného textu** a štruktúrovanom **výstupe JSON**:

| Aspekt                 | Formát obyčajného textu (`/api/usage/om-usage` / `@@om-usage`)                                    | Formát JSON (`?format=json`)                                                              |
| :--------------------- | :------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------------------------- |
| **Výstupné pole**      | `NN% left` (napr. `20% left`)                                                                     | `provider.quotas` / `providers[].quotas`                                                  |
| **Meranie**            | **Použiteľná kapacita upravená podľa hraničnej hodnoty**: zostávajúca kapacita nad prahom         | **Nespracovaná upstreamová kvóta**: neupravené meranie poskytovateľa                      |
| **Úprava podľa prahu** | Upravené pomocou `effectiveRemainingPercent()`, takže chránená rezerva sa zobrazuje ako `0% left` | Žiadna (nespracované hodnoty snímky nahlásené poskytovateľom)                             |
| **Údaje o prahu**      | Zahrnuté do zobrazeného percenta                                                                  | Uložené v `quotaWindowThresholds` pre každé pripojenie (alebo predvolené hodnoty servera) |
| **Hlavný používateľ**  | Interaktívne CLI, terminálové výzvy, ľudskí operátori                                             | Programové integrácie, ovládacie panely, analytika, nástroje na sledovanie fakturácie     |

#### Vzorec úpravy podľa hraničnej hodnoty

OmniRoute podporuje proaktívne hraničné hodnoty kvót, ktoré zabraňujú vyčerpaniu upstreamových zdrojov (konfigurované prostredníctvom
`quotaWindowThresholds` pripojenia, predvolených hodnôt poskytovateľa alebo globálnych nastavení odolnosti). Keď je v intervale kvóty aktívny hraničný prah
(napr. `cutoff = 25%`), textový renderer vypočíta zostávajúcu kapacitu takto:

- Ak `remaining <= cutoff`: vráti `0%`.
- Ak `remaining > cutoff`: vráti `((remaining - cutoff) / (100 - cutoff)) * 100`.

Formátovaný textový výstup túto hodnotu zaokrúhli na najbližšie celé číslo (`Math.round(...)`).

#### Ilustračný príklad

Predstavte si interval poskytovateľa so **60 % nespracovaného využitia** (teda **40 % nespracovanej zostávajúcej kvóty**) a nakonfigurovaným
prahom **25 % zostávajúcej kvóty**:

| Reprezentácia                          | Výpočet                                            | Zostáva  |            Odvodené využitie             |
| :------------------------------------- | :------------------------------------------------- | :------: | :--------------------------------------: |
| **Nespracovaný JSON (`?format=json`)** | Upstreamová snímka (`quotas[window]`)              | **40 %** |                 **60 %**                 |
| **Textový formát (`NN% left`)**        | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20 %** | **80 %** (pri výpočte `100 - remaining`) |

- **Prečo text zobrazuje 20 % zostávajúcej kapacity:** Z 40 % fyzickej kvóty zostávajúcej na účte je 25 % rezervovaných
  zásadou hraničnej hodnoty. Volajúcemu zostáva len 15 % zo 75 % použiteľnej rezervy predtým, ako smerovač prestane
  smerovať požiadavky na toto pripojenie. Úprava zabezpečuje, že pripojenie signalizuje vyčerpanie (`0% left`) presne vtedy, keď
  sa smerovanie ukončí.
- **Prečo JSON zachováva nespracované hodnoty:** Obsah JSON vracia presnú snímku poskytovateľa (`UsageSnapshot`),
  takže externé nástroje majú prístup k skutočnému upstreamovému využitiu a hodnotám
  `quotaWindowThresholds` na úrovni pripojenia bez stratovej úpravy na strane servera.

#### Pokyny na migráciu používateľov

Ak externá integrácia (napríklad doplnok editora alebo rozšírenie agenta) predtým získavala údaje z textového
koncového bodu (`NN% left`) a vypočítavala použité percento ako `100 - NN`, prechod na `?format=json` znamená:

- Čítanie nespracovaných hodnôt JSON bude odrážať **skutočnú spotrebu v nadradenom systéme** (v príklade vyššie je použitých 60 %).
- Ak chce integrácia zachovať sémantiku použiteľného zostávajúceho limitu textového koncového bodu, môže vzorec
  efektívneho zostávajúceho limitu vyhodnotiť na strane klienta pomocou `quotaWindowThresholds` pre prepísania na úrovni pripojenia.

### Vplyv na latenciu

Pri ZÁSAHU do sémantickej vyrovnávacej pamäte sa odpoveď poskytne z vyrovnávacej pamäte **bez volania nadradenej služby**, takže hlásená hodnota `X-OmniRoute-Response-Latency` je takmer nulová (bez ohľadu na pôvodnú latenciu nadradenej služby). Klienti citliví na latenciu (porovnávacie testovanie, monitorovanie p50/p99) by mali kontrolovať hlavičku odpovede `X-OmniRoute-Cache-Latency`:

| Hodnota     | Význam                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------- |
| `synthetic` | Odpoveď poskytnutá z vyrovnávacej pamäte; latencia nie je skutočným časom nadradenej služby |
| _(chýba)_   | Odpoveď zo skutočného volania nadradenej služby                                             |

### Obídenie vyrovnávacej pamäte pre jednotlivé kľúče

Kľúče API môžu zrušiť používanie čítania zo sémantickej vyrovnávacej pamäte prostredníctvom `cacheDefaultMode`:

| Hodnota  | Správanie                                                                               |
| -------- | --------------------------------------------------------------------------------------- |
| `legacy` | Bežné správanie vyrovnávacej pamäte (predvolené)                                        |
| `bypass` | Úplné preskočenie vyhľadávania vo vyrovnávacej pamäti; vždy sa použije nadradená služba |

Nastavte pri vytváraní kľúča (`POST /api/keys`) alebo aktualizácii (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### Obídenie pre jednotlivé požiadavky

Ľubovoľná požiadavka môže obísť vyrovnávaciu pamäť bez ohľadu na nastavenia kľúča:

```
X-OmniRoute-No-Cache: true
```

Pre synchronizované/importované modely prijíma `PUT /api/provider-models` hodnoty `provider`, `modelId` a
`maxOutputTokenOverride`: kladné celé číslo nastaví manuálny limit výstupných tokenov a hodnota `null`
ho zruší, čím sa obnoví predvolené nastavenie. `GET /api/provider-models?provider=<provider>` vracia tieto
hodnoty v `modelOutputOverrides` vrátane modelov bez riadka vlastného modelu. Prepísanie
používa runtime schopnosť `max_output_tokens` a zachová sa aj po opätovnej synchronizácii modelu. Stránka
poskytovateľa kompatibilného s OpenAI ponúka rovnaké ovládacie prvky na úpravu/zrušenie a označuje modely s explicitnou podporou obrazu.

Vlastné uzly Chat Completions prispôsobujú explicitné vypnutie uvažovania nadradenému backendu. Úspešný
test pripojenia automaticky vyberie ovládacie prvky šablóny chatu pre každé presné ID modelu,
ktorého položka `/models` preukazuje rozpoznanú hodnotu `owned_by`: `vllm`, `sglang` alebo `llamacpp`.
Transparentné obalové vrstvy kompatibilné s OpenAI môžu zachovať pôvodnú položku modelu vo vnorenom
objekte `openai`; detekcia prechádza až tromi takýmito obálkami. Modely s chýbajúcim, neznámym alebo
konfliktným vlastníctvom si zachovajú bežné správanie OpenAI. Detekcia opätovne využíva existujúcu požiadavku na katalóg,
negeneruje žiadne tokeny dokončenia a zneplatní sa pri zmene koncového bodu pripojenia.

Ak chcete toto správanie pevne nastaviť pre backend, ktorý tieto metadáta neposkytuje, použite existujúce rozhranie API
na čiastočnú aktualizáciu poskytovateľa:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Toto telo odošlite pomocou `PUT /api/providers/<connection-id>`. Pri danom pripojení sa explicitná
intenzita uvažovania `none` odošle ako `chat_template_kwargs.thinking=false` a
`chat_template_kwargs.enable_thinking=false`. Explicitné hodnoty natívnej šablóny zostávajú rozhodujúce,
pokiaľ pravidlo uvažovania na strane servera nevynúti určitú intenzitu. Nastavenie sa uplatňuje iba vtedy, keď vlastné
pripojenie kompatibilné s OpenAI odosiela telo Chat Completions; požiadavky Responses a bežní
poskytovatelia si zachovávajú svoj natívny tvar požiadavky. Nastavte `reasoningControl` na `openai`, ak chcete vynútiť bežné odovzdanie
`reasoning_effort` do OpenAI, alebo ho vynechajte/nastavte na `null`, ak chcete použiť automatickú detekciu.

Požiadavky klasifikátora automatického režimu Claude Code predvolene nastavujú natívne premýšľanie ako vypnuté, ak neobsahujú
žiadne explicitné ovládacie prvky uvažovania. Detekcia používa systémovú značku klasifikátora v požiadavkách vo formáte Claude,
nie názvy modelov ani limity dokončenia. Explicitné ovládacie prvky tela, podporované hlavičky intenzity/premýšľania,
pravidlá smerovania a vyriešená intenzita modelu si zachovávajú svoju existujúcu prioritu. Obe fázy klasifikátora
si zachovávajú svoje prompty, limity dokončenia, sekvencie zastavenia a skutočné rozhodnutia nadradeného systému
o oprávneniach; druhá fáza môže naďalej vytvárať požadované viditeľné uvažovanie ako bežný text.

### Verzia a kanál vydania

```bash
GET /api/system/version
```

Trasa na správu dostupná iba cez loopback (overenie správcu). Vráti spustenú verziu, najnovšiu
publikovanú verziu a stav automatických aktualizácií. `releaseChannel` a `channels` sú pridané
polia (vetva 3.8.54); `channel` si zachováva svoj význam — režim nasadenia, ktorý používa nástroj
na aktualizáciu ovládacieho panela (`npm`, `source` alebo `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — npm kanál spustenej zostavy: `nightly` pre verzie `-nightly.*`,
  `next` pre ostatné predbežné vydania (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` pre stabilnú verziu
  staršej hlavnej verzie než `channels.latest`, inak `latest`. Rovnaké pravidlá ako v
  `scripts/release/dist-tag.mjs`, ktorý pri publikovaní vyberá npm dist-tag.
- `channels` — najnovšia publikovaná verzia každého dist-tagu získaná pomocou `npm view omniroute dist-tags` (s použitím
  registra HTTP ako záložnej možnosti), uložená vo vyrovnávacej pamäti s rovnakou 10-minútovou dobou platnosti ako `latest`. `latest` je vždy prítomné
  (ako záložná hodnota sa použije pole `latest` a následne `"unavailable"`); `next`, `nightly` a `lts` sa zobrazia
  iba vtedy, keď daný dist-tag existuje. Požiadavka `Cache-Control: no-cache` obnoví obe vyhľadávania.

Model kanálov (`latest` = v3 až do všeobecnej dostupnosti verzie 4.0, `next` = rc, `nightly` = zostavy z vetvy `develop`,
`lts` = opravy v3 po všeobecnej dostupnosti verzie 4.0) je opísaný v `docs/ops/RELEASE_STRATEGY.md`.

```bash
# Aliasy chatu v štýle OpenAI
```


## Limity tokenov

Rozpočty **tokenov** pre jednotlivé API kľúče (odlišné od rozpočtu založeného na USD uvedeného vyššie). Vynucujú sa priamo pri spracovaní požiadavky: keď využitie kľúča v aktuálnom časovom okne dosiahne svoj limit, požiadavky sa odmietnu s chybou `429 Too Many Requests`. Limity možno obmedziť na konkrétny `model`, `provider` alebo ich použiť globálne pre celý kľúč (`global`); keď požiadavke zodpovedá viacero limitov, použije sa najprísnejší.

```bash
# Zobrazenie limitov tokenov kľúča (vrátane aktuálneho využitia okna)
GET /api/usage/token-limits?apiKeyId=key-123

# Vytvorenie alebo aktualizácia limitu tokenov
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Odstránenie limitu tokenov podľa id
DELETE /api/usage/token-limits?id=tl-abc
```

> **Poznámky k schéme** (`setTokenLimitSchema`): `apiKeyId` a `scopeType` (`model` | `provider` | `global`) sú povinné. `scopeValue` je povinné, pokiaľ `scopeType` nie je `global` (napr. ID modelu pre rozsah `model`, ID poskytovateľa pre rozsah `provider`). `tokenLimit` musí byť kladné celé číslo (konvertované z reťazca). Voliteľné: `id` (vynechajte pri vytváraní, zadajte pri aktualizácii), `resetInterval` (`daily` | `weekly` | `monthly`, predvolená hodnota `monthly`), `resetTime` (`HH:MM`), `enabled` (predvolená hodnota `true`). Odpovede `GET` dopĺňajú každý limit o `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` a `nextResetAt`. Ide o koncový bod triedy správy (autentifikácia sa vynucuje centrálne prostredníctvom autorizačného reťazca).

## Spracovanie požiadaviek

1. Klient odošle požiadavku na `/v1/*`
2. Obslužná rutina trasy zavolá `handleChat`, `handleEmbedding`, `handleAudioTranscription` alebo `handleImageGeneration`
3. Model sa rozpozná (priamy poskytovateľ/model alebo alias/kombinácia)
4. Z lokálnej databázy sa vyberú prihlasovacie údaje s filtrovaním podľa dostupnosti účtu
5. Pre konverzáciu: `handleChatCore` skontroluje sémantickú/signatúrnu vyrovnávaciu pamäť a určí nastavenia kompresie kombinácie
6. Ak je povolená, pred prekladom pre poskytovateľa sa spustí proaktívna kompresia (`lite`, Caveman, RTK alebo ich kombinácia)
7. Vykonávací modul poskytovateľa odošle požiadavku nadradenej službe
8. Odpoveď sa preloží späť do formátu klienta (konverzácia) alebo sa vráti bez zmien (vektorové reprezentácie/obrázky/zvuk)
9. Zaznamená sa využitie, analytika kompresie a protokoly požiadaviek
10. Pri chybách sa podľa pravidiel kombinácie použije záložné riešenie

Úplný prehľad architektúry: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Odolnosť (rozšírené)

OmniRoute poskytuje tri nezávislé mechanizmy dočasného zlyhania; nižšie uvedené koncové body správy umožňujú operátorom čítať a prepisovať ich stav:

| Rozsah                  | Ukladanie stavu                                  | Čítanie                                   | Resetovanie / vymazanie                                      |
| ----------------------- | ------------------------------------------------ | ----------------------------------------- | ------------------------------------------------------------ |
| Istič poskytovateľa     | `domain_circuit_breakers` + v pamäti             | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                 |
| Časový limit pripojenia | `rateLimitedUntil` v pripojeniach poskytovateľov | `/api/rate-limits`, `/api/providers/[id]` | (opätovne sa povolí lenivo; vymaže sa cez PUT poskytovateľa) |
| Uzamknutie modelu       | Register dostupnosti modelov v pamäti            | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                     |

`PATCH /api/resilience` prijíma prepísania ističov poskytovateľov v `providerBreaker.oauth` a `providerBreaker.apikey`. Každý profil podporuje `degradationThreshold`, `failureThreshold` a `resetTimeoutMs`; rovnaké polia sú dostupné v Ovládací panel → Nastavenia → Odolnosť.

```bash
# Vymazanie uzamknutia jedného modelu
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Vymazanie všetkých uzamknutí
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Úplnú koncepčnú referenciu a predvolené hodnoty ističov nájdete v [`CLAUDE.md`](../../CLAUDE.md) → „Stav modulu odolnosti počas behu“ a [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Front požiadaviek s obmedzením frekvencie a poistka automatického povolenia

- **Podporovaný spôsob zápisu**: `POST /api/rate-limits` s telom `{"connectionId": "<id>", "enabled": true|false}` je podporovaný koncový bod správy na prepínanie ochrany pripojenia pred obmedzením frekvencie. `PUT /api/providers/[id]` zámerne neupravuje ani neprepína `rateLimitProtection` (#11278).
- **Sémantika `enabled: false`**: Nastavenie `enabled: false` odstráni explicitnú ochranu pripojenia, ale **nevyradí** aktívne pripojenie s API kľúčom z globálnej poistky automatického povolenia (`autoEnableApiKeyProviders = true`). V `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) sú hodnoty `false` a `undefined` ekvivalentné; aktívne pripojenia s API kľúčom bez explicitnej ochrany zostávajú chránené globálnou poistkou automatického povolenia.
- **Globálne vypnutie**: Ak chcete používať pripojenia s API kľúčom bez frontov požiadaviek s obmedzením frekvencie, globálne vypnite túto poistku pomocou `RATE_LIMIT_AUTO_ENABLE=false` (premenná prostredia) alebo `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Nastavenia → Odolnosť / `PATCH /api/resilience`).

OmniRoute obsahuje vstavaný server Model Context Protocol s 3 transportmi (stdio, SSE, streamable-http) a nástrojmi s obmedzeným rozsahom. Nižšie uvedené koncové body ovládacieho panela načítavajú údaje o stave/audite a zastupujú transporty HTTP.

| Metóda | Cesta | Popis |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |

| POST | `/api/mcp/sse` | Odoslanie rámca JSON-RPC prostredníctvom transportu SSE |
| GET | `/api/mcp/stream` | Otvorenie strany SSE transportu Streamable HTTP (správy iniciované serverom) |

| DELETE | `/api/mcp/stream` | Ukončenie relácie Streamable HTTP |

## Server A2A

OmniRoute poskytuje koncový bod A2A (Agent-to-Agent) JSON-RPC 2.0 spolu s obalom REST na účely kontroly a použitia v ovládacom paneli.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # voliteľné, pokiaľ nie je nastavené OMNIROUTE_API_KEY
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Podporované metódy (všetky závisia od `settings.a2aEnabled`):

| Metóda           | Popis                                                                |
| ---------------- | -------------------------------------------------------------------- |
| `message/send`   | Synchrónne vykonanie zručnosti; vracia `{task, artifacts, metadata}` |
| `message/stream` | Streamované vykonanie rovnakej množiny zručností cez SSE             |
| `tasks/get`      | Načíta úlohu podľa `taskId`                                          |
| `tasks/cancel`   | Zruší úlohu podľa `taskId`                                           |

Vstavané zručnosti: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Karta agenta

```bash
GET /.well-known/agent.json
```

Vracia verejnú kartu agenta A2A (názov, popis, možnosti, katalóg zručností, schéma autentifikácie) — verejne uloženú vo vyrovnávacej pamäti na 1 hodinu. Nevyžaduje sa autentifikácia.

### Pomocné rozhrania REST

| Metóda | Cesta                        | Popis                                                                                                            |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | Stav povolenia A2A + štatistiky úloh + súhrn karty agenta z vyrovnávacej pamäte                                  |
| GET    | `/api/a2a/tasks`             | Zoznam úloh — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Nie je implementované ako pomocné rozhranie REST — vytvárajte prostredníctvom JSON-RPC `message/send`)          |
| GET    | `/api/a2a/tasks/[id]`        | Načíta jednu úlohu                                                                                               |
| POST   | `/api/a2a/tasks/[id]/cancel` | Zruší úlohu                                                                                                      |

**Autentifikácia:** pomocné rozhrania REST fungujú bez autentifikácie na správu (sú čitateľné ovládacím panelom); trasa JSON-RPC `/a2a` používa nosný token `OMNIROUTE_API_KEY`, ak je nakonfigurovaný.

## Ochranné mechanizmy

Kontrolujte ochranné mechanizmy za behu (detekcia osobných údajov, detekcia vloženia promptu, premostenie počítačového videnia). Ochranné mechanizmy sa spúšťajú pri každej požiadavke; odhlásenie pre jednotlivé volania sa vykonáva prostredníctvom hlavičky požiadavky `x-omniroute-disabled-guardrails` — neexistuje trvalé rozhranie na ich povolenie alebo zakázanie.

| Metóda | Cesta                  | Popis                                                                                               |
| ------ | ---------------------- | --------------------------------------------------------------------------------------------------- |
| GET    | `/api/guardrails`      | Zoznam registrovaných ochranných mechanizmov a ich stavov (názov / povolené / priorita)             |
| POST   | `/api/guardrails/test` | Skúšobné spustenie postupu pred volaním nad vzorovým vstupom — telo: `{input, disabledGuardrails?}` |

**Autorizácia:** Vyžaduje reláciu správy.

Úplné podrobnosti nájdete v dokumente [Zabezpečenie > Ochranné mechanizmy](../security/GUARDRAILS.md).

## Autentifikácia

Informácie o štyroch skupinách prihlasovacích údajov (relácia ovládacieho panela, lokálny token CLI, prístupový token `oma_live_…`, kľúč API s rozsahom správy) a o tom, ako sa líšia od kľúčov na inferenciu, nájdete v časti [Autentifikácia správy](../guides/MANAGEMENT-AUTH.md).

- Trasy ovládacieho panela (`/dashboard/*`) používajú súbor cookie `auth_token`
- Prihlásenie používa uložený hash hesla; ako záložná možnosť sa používa `INITIAL_PASSWORD`
- Nastavenie `requireLogin` možno prepínať prostredníctvom `/api/settings/require-login`
- Trasy `/v1/*` môžu voliteľne vyžadovať kľúč API typu Bearer, keď je `REQUIRE_API_KEY=true`
- „token správy“ / „kľúč API s rozsahom správy“ v tejto referenčnej príručke označuje jednu zo skupín uvedených v danej príručke — nejde o nedefinovaný dodatočný typ tajného údaja

> **Nekompatibilná zmena (v3.8.0)** — `/api/v1/agents/tasks/*` a koncové body správy časového obmedzenia teraz vyžadujú **autentifikáciu správy** (súbor cookie `auth_token` ovládacieho panela alebo kľúč API s rozsahom správy). Klienti, ktorí predtým volali tieto trasy bez autentifikácie, dostanú odpoveď `401 Unauthorized`. Pozrite si commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
