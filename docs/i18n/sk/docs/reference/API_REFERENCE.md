## Chat Completions

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

| Hlavička                 | Smer       | Popis                                                                                                                                                                                                                      |
| ------------------------ | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `x-omniroute-no-memory`  | Požiadavka | Nastavte na `true`, aby sa pri tejto požiadavke preskočila injekcia pamäte a schopností (zodpovedá no-cache; zabraňuje réžii tokenov/nákladov pri každom volaní)                                                           |
| `X-OmniRoute-Progress`   | Požiadavka | Nastavte na `true` pre udalosti priebehu                                                                                                                                                                                   |
| `X-Session-Id`           | Požiadavka | Kľúč trvalej relácie pre afinitu k externej relácii                                                                                                                                                                        |
| `x_session_id`           | Požiadavka | Akceptuje sa aj variant s podčiarkovníkom (pri priamom HTTP)                                                                                                                                                               |
| `X-OmniRoute-Session-Id` | Požiadavka | Značka relácie/konverzácie zadaná volajúcim (používa sa aj v pamäti). Ak je uvedená, uloží sa doslovne do `call_logs.session_tag` na účely priradenia nákladov podľa relácie (#8249) — pri jej absencii sa nikdy nevytvára |
| `Idempotency-Key`        | Požiadavka | Kľúč na odstránenie duplicít (časové okno 5 s)                                                                                                                                                                             |
| `X-Request-Id`           | Požiadavka | Alternatívny kľúč na odstránenie duplicít                                                                                                                                                                                  |
| `x-omniroute-connection` | Požiadavka | Pripne požiadavku pre jeden model k jednému pripojeniu poskytovateľa (účtu) podľa jeho ID — pozrite si [Pripnutie účtu podľa požiadavky](#account-pinning-per-request)                                                     |
| `X-OmniRoute-Cache`      | Odpoveď    | `HIT` alebo `MISS` (bez streamovania)                                                                                                                                                                                      |
| `X-OmniRoute-Idempotent` | Odpoveď    | `true`, ak bola požiadavka deduplikovaná                                                                                                                                                                                   |
| `X-OmniRoute-Progress`   | Odpoveď    | `enabled`, ak je sledovanie priebehu zapnuté                                                                                                                                                                               |
| `X-OmniRoute-Session-Id` | Odpoveď    | Efektívne ID relácie použité službou OmniRoute                                                                                                                                                                             |
| `X-OmniRoute-Request-Id` | Odpoveď    | Korelačné ID požiadavky (ak je známe)                                                                                                                                                                                      |

#### Pripnutie účtu podľa požiadavky

Keď má poskytovateľ viacero pripojení (účtov alebo kľúčov), OmniRoute zvyčajne vyberie jedno
prostredníctvom stratégie výberu účtu. Požiadavka môže namiesto toho pripnúť jedno konkrétne pripojenie
pomocou hlavičky `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Kde nájsť id.** Otvorte stránku poskytovateľa na dashboarde
  (**Dashboard → Providers → <provider>**) a kliknite na čip s id `xxxxxxxx…` v riadku pripojenia —
  skopíruje sa celé id pripojenia.
- **Ktoré požiadavky ho rešpektujú.** Požiadavky na jeden model (`provider/model`) na
  `/v1/chat/completions`, `/v1/messages` a `/v1/responses`. Kombinácie hlavičku ignorujú: pripnite
  účet pre každý krok kombinácie prostredníctvom vlastného pripojenia daného kroku.
- **Pripnutie je striktne určené, nejde o preferenciu.** Pripnuté pripojenie sa používa výhradne. Ak
  v rámci požiadavky dôjde k zlyhaniu, zaznamená sa cooldown účtu, ale požiadavka sa
  nepresmeruje na súrodenecký účet toho istého poskytovateľa.
- **Cooldown a kvóta pripnutie uvoľnia.** Kým je pripnuté pripojenie v cooldown režime,
  vyčerpá kvótu alebo je zablokované politikou kvót, neskoršie požiadavky sa vrátia k ostatným
  pripojeniam poskytovateľa, presne ako pri nepripnutom prenos e.
- **Neznáme alebo deaktivované id zlyhajú.** Id, ktoré nie je v aktívnom poole poskytovateľa (bolo
  odstránené, deaktivované alebo patrí inému poskytovateľovi), nezanechá žiadny oprávnený účet, takže
  požiadavka zlyhá namiesto tichého presmerovania inam.

Claude Code odosiela vlastné hlavičky prostredníctvom `ANTHROPIC_CUSTOM_HEADERS`. Umiestnite ho do bloku
`env` v súbore `~/.claude/settings.json` alebo do projektového súboru `.claude/settings.json`, aby ste mohli
pripnúť iný účet pre každý projekt:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Zdroj: `src/sse/handlers/chat.ts` (čítanie hlavičky), `src/sse/services/auth.ts` a
`src/sse/services/sessionAffinityPin.ts` (uvoľnenie pripnutia a kontrola chýbania v poole).

> **Hlavičky telemetrie nákladov:** odpovede úspešných ne-streamovaných požiadaviek obsahujú aj súpravu telemetrie nákladov `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, pevne 10 desatinných miest; `0.0000000000` pre bezplatné alebo neocenené požiadavky), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` a `X-OmniRoute-Fallback-Attempts` (iba ak > 0), plus `X-OmniRoute-Request-Id` a `X-OmniRoute-Version`. Tieto hlavičky sa odosielajú pri completionoch chatu, `/v1/responses`, `/v1/messages` **a mediálnych endpointoch** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` a `/v1/moderations` (vždy s nákladom `0`). Náklady na médiá sa počítajú podľa modality (za obrázok, za sekundu, za znak, za vyhľadávaciu jednotku), ak je k dispozícii oceňovanie; v opačnom prípade je hodnota `0` (fail-open).

> **Sémantika nákladov pri zásahu z cache:** pri zásahu (`HIT`) sémantickej cache (`X-OmniRoute-Cache-Hit: true`) sa neuskutoční žiadne volanie upstreamu, takže `X-OmniRoute-Response-Cost` je `0.0000000000` (**inkrementálny** náklad na obslúženie zásahu). Pôvodný alebo hypotetický náklad sa uvádza samostatne v `X-OmniRoute-Cost-Saved`. Spotrebitelia fakturačných údajov by mali sčítavať `X-OmniRoute-Response-Cost` (zásahy nič nestoja); analytika cache môže agregovať `X-OmniRoute-Cost-Saved`.

## Exkluzívne prenájmy spravovaných relácií

Exkluzívny prenájom spravovaných relácií je voliteľný, na klientovi nezávislý smerovací kontrakt: jeden
aktívny vlastník drží jedno oprávnené pripojenie OmniRoute. Neprenajíma model, nevyžaduje OAuth,
neurčuje konkrétneho klienta ani nevyžaduje konkrétneho poskytovateľa.

Autentifikačný kľúč API musí mať rozsah `lease:exclusive` a explicitný neprázdny zoznam
`allowedConnections`. Hranica mutácie databázy vynucuje obe polia spoločne pri vytváraní kľúča
aj pri čiastočných aktualizáciách.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Úspešné odpovede na získanie, obnovenie a uvoľnenie prenájmu sprístupňujú časové pečiatky, `state`
a presnú kladnú hodnotu `generation`, nikdy však vybrané pripojenie ani prihlasovacie údaje.
Obnovenie a uvoľnenie poskytujú hodnotu generation v tele JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Aktívny vlastník prenájmu môže explicitne požiadať o metadáta zobrazované s ohľadom na ochranu
súkromia pre svoju aktuálnu väzbu:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Táto voliteľná akcia status je chránená nepriehľadným vlastníkom, autentifikovaným spravovaným
kľúčom API a presnou aktívnou generáciou v rámci jednej databázovej transakcie. `displayName` je
iba orezaný nakonfigurovaný názov pripojenia; ak nie je k dispozícii žiadny bezpečný nakonfigurovaný
názov, jeho hodnota je `null`. OmniRoute nikdy nenahrádza tento názov e-mailom ani vygenerovanou
identitou účtu. Hodnota provider je necitlivý zobrazovaný štítok a nikdy nie je vygenerovaným
identifikátorom kompatibilného poskytovateľa. Vylúčené sú prihlasovacie údaje, tokeny, súbory
cookie, nespracované identifikátory pripojení alebo kľúčov API, heše vlastníkov, tajomstvá na
vynucovanie a interné smerovacie údaje.

Vyhľadávania s nesprávnym kľúčom, nesprávnym vlastníkom, zastaranou generáciou, chýbajúcim,
expirovaným, uvoľneným alebo zneplatneným prenájmom všetky vracajú rovnakú chybu
`409 LEASE_FENCE_STALE` bez metadát pripojenia. Klient, ktorý dostal odpoveď o čakaní na kapacitu,
nemá žiadnu aktívnu väzbu, ktorú by mohol preskúmať. Keď smerovanie prechádza na aktívny prenájom,
rovnaká generácia zostáva platná a status atómovo vráti novú väzbu, nikdy starú. Existujúci klienti
zostávajú nezmenení, pretože odpovede na získanie, obnovenie, uvoľnenie a čakanie si zachovávajú
svoje predchádzajúce tvary.

Tento serverový kontrakt nemení štandardný OpenAI Codex `/status`. Štandardný Codex v súčasnosti
uvádza svojho poskytovateľa modelu a vstavaný stav autentifikácie/účtu, nezobrazuje však ľubovoľné
metadáta účtu vlastného poskytovateľa; neskoršia integrácia klienta musí zavolať túto akciu
a rozhodnúť, ako zobraziť `connection.displayName`.

Každá spravovaná požiadavka na inferenciu potom poskytuje obe riadiace hlavičky:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Presný vlastník, generácia, aktívne pripojenie a autentifikovaný kľúč API sa kontrolujú bezprostredne
pred každým podporovaným pokusom o komunikáciu s upstreamom. Opätovné použitie vlastníka a generácie
s iným kľúčom zlyhá aj vtedy, keď tento kľúč povoľuje rovnaké pripojenie. Nespracovaní vlastníci sa
neukladajú, nezapisujú do protokolov, neuchovávajú v snímke požiadavky ani neodosielajú upstreamu.

Dočasná kolízia vracia HTTP `429` s hlavičkou `Retry-After` a:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Táto odpoveď znamená iba to, že bežná množina oprávnených možností nebola prázdna a každý voľný
kandidát bol držaný cudzím aktívnym prenájmom. Nepodporované modely/poskytovatelia, nesúlad
zásad, čas ochladzovania, kvóta, stav a ďalšie bežné zlyhania oprávnenosti si zachovávajú svoje
existujúce odpovede OmniRoute.

### `x-omniroute-compression`

Prepísanie plánu kompresie pre jednotlivú požiadavku. Má najvyššiu prioritu — prekonáva prepísanie
kombinácie smerovania, aktívny profil, automatický spúšťač aj Predvolené nastavenie panela.
Hodnoty:

| Value         | Effect                                                                                                               |
| ------------- | -------------------------------------------------------------------------------------------------------------------- |
| `off`         | Žiadna kompresia pre túto požiadavku.                                                                                |
| `default`     | Predvolený profil odvodený z panela (ignoruje aktívny profil). Stratové nástroje zostanú vypnuté.                    |
| `safe`        | Iba deduplikácia a zlučovanie bielych znakov.                                                                        |
| `allow-lossy` | Ponechá plán operátora pre túto požiadavku vrátane súhrnov a prepisov štýlu.                                         |
| `engine:<id>` | Jeden nástroj, keď je povolený, napr. `engine:rtk`. Opt-in pre tento nástroj na úrovni požiadavky.                   |
| `<combo>`     | Pomenovaná kombinácia, ktorá sa najprv porovná podľa názvu (bez rozlíšenia veľkých a malých písmen), potom podľa ID. |

Poznámky:

- Neznáme hodnoty sa ignorujú (požiadavka sa nikdy nezamietne); vyhodnocovanie pokračuje podľa bežnej priority operátora.
- Ak má viacero kombinácií rovnaký názov, odovzdajte **id** kombinácie, aby bolo zhodovanie deterministické.
- Kombináciu, ktorej názov je `off` alebo `default`, nemožno vybrať podľa názvu (tieto kľúčové slová sa interpretujú ako prvé); na odkazovanie na takúto kombináciu použite jej ID.
- Hlavný prepínač kompresie je pevnou podmienkou: keď je kompresia globálne vypnutá, táto hlavička ju nemôže povoliť.

Použitý plán sa vracia v hlavičke odpovede:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

kde `<source>` je jedna z hodnôt `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` alebo `off`.

## Embeddingy

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Dostupní poskytovatelia: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

ID katalógu majú formát `provider/model` (príklad: `jina-ai/jina-embeddings-v5-omni-small`). Rozpoznávajú sa aj samostatné ID modelov Jina, ktoré sa nachádzajú v registri (napríklad `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`). Modely Jina pre embeddingy, reranking, klasifikáciu a segmentáciu najprv používajú prihlasovacie údaje `jina-ai` z dashboardu; `JINA_AI_API_KEY` je záložná možnosť iba v prípade, že neexistuje kľúč z dashboardu. Karta `jina-reader` je určená iba pre Reader / `r.jina.ai` (`POST /v1/web/fetch`) a nikdy neposkytuje embeddingy ani reranking.

Modely v registri, ktoré deklarujú podporu multimodality, prijímajú aj najviac 32 štruktúrovaných položiek nezávislých od poskytovateľa. Typy mediálnych položiek sú `text`, `image`, `audio`, `video` a `document`. Ich `source` je buď `{"type":"url","url":"https://..."}`, alebo
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
a alias rodiny `jina-ai/jina-embeddings-v5-omni` → omni-small) prijíma aj natívne dokumenty
EmbeddingsV5Request od Jina a **odosiela ich bez zmien** na `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Natívne hodnoty `{ image | audio | video | pdf }` môžu byť verejná HTTPS URL, URI `data:`
alebo nespracovaný base64. OmniRoute tieto objekty nekonvertuje na reťazce ani nenačítava natívne URL obrázkov — verejné médiá načíta samotná Jina. Ďalšie polia Jina (`task`, `normalized`, `truncate`, `embedding_type`) sa odosielajú ďalej. Textové SKU Jina naďalej odmietajú dokumenty, ktoré nie sú textové.

Bezpečnostné a transportné limity:

- Vzdialené mediálne URL musia byť verejné HTTPS. Kanonické položky `{type,source:url}` sa načítavajú na strane servera (opätovná validácia presmerovaní, časové limity, limity veľkosti, verejný DNS, pripnutie pripojenia) a pred volaním poskytovateľa sa vložia priamo do požiadavky. Natívne položky Jina `{image:"https://..."}` sa po rovnakej kontrole verejného HTTPS odosielajú tak, ako sú; URL načíta Jina.
- Vložené médiá base64 sú obmedzené na 8 MiB po dekódovaní na položku a 16 MiB po dekódovaní v rámci celej požiadavky.

Preklad pre poskytovateľov (kanonické položky sa nikdy neodosielajú bez zmien):

- Multimodálne modely Jina: každá položka najvyššej úrovne sa zmení na jeden objekt s kľúčom modality
  (`text` / `image` / `audio` / `video` / `pdf`), pričom pre vložené médiá sa použijú URI data; jeden vektor na položku najvyššej úrovne.
- Rodina Gemini Embedding 2: jedno pole najvyššej úrovne sa zmení na jednu natívnu požiadavku
  `models/{model}:embedContent` s `content.parts` (`text` alebo `inline_data`).
- llama.cpp (`llama-cpp/<model>`, ľubovoľný model načítaný lokálnym serverom): kanonické položky
  `text` sa zmenia na obyčajné reťazce a položky `image` / `audio` / `video` sa každá zmení na jeden objekt `{"content": [part]}` s použitím častí obsahu chatu llama-servera (`image_url`, `input_audio` s formátom `wav` / `mp3` / `flac`, `input_video`) s vloženými údajmi; jeden vektor na položku najvyššej úrovne. `document` nie je podporovaný. Server musí byť spustený s parametrom `--embedding --mmproj …`; bez projektora server samotné médium odmietne.
- Neznáme/dynamické modely bez explicitných metadát modality odmietnu štruktúrovaný vstup s HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Nepodporované kombinácie modelu a modality vracajú HTTP 400 namiesto vynútenej konverzie položky. Polia rozšírení, ktoré nie sú vstupom, sa pri starších požiadavkách s reťazcami/tokenmi naďalej odosielajú bez zmien.

```bash
# Vypíše všetky modely embeddingov
GET /v1/embeddings
```

## Generovanie obrázkov

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Medzi dostupných poskytovateľov patria OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (lokálne), ComfyUI (lokálne).

`n` vráti `n` obrázkov v `data[]`. Poskytovatelia, ktorých nadradené API vracia jeden obrázok na volanie
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI), vykonajú `n` samostatných volaní nadradeného API, pričom súčasne
prebiehajú najviac 4 volania. Pevná hodnota `seed` sa posúva podľa indexu volania
(`seed`, `seed + 1`, …), takže obrázky sa líšia, ale zostávajú reprodukovateľné. Hodnota `n` je
obmedzená na 10. Ak zlyhá ktorékoľvek volanie, požiadavka zlyhá ako celok. Zoznam formátov pre
fan-out je `SINGLE_IMAGE_FANOUT_FORMATS` v
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux opätovne používa existujúce pripojenie s kľúčom API a akceptuje predpony `zenmux/` alebo `zm/`:

- `zenmux/openai/gpt-image-2` používa OpenAI Images API od ZenMux. Možnosti zahŕňajú `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` a `response_format`.
- Ostatní vydavatelia, napríklad `zm/meta/muse-image-1.0`, používajú koncový bod Vertex AI
  `:predict` od ZenMux. `n` sa mapuje na `sampleCount`, `aspect_ratio` na `aspectRatio` a `image_size`
  (`1K`, `2K`, `4K`) na `sampleImageSize`. Pixelová hodnota `size` poskytuje iba pomer strán,
  nie zaručené rozmery v pixeloch. Podporované pomery strán, rozlíšenia a počty sa líšia podľa modelu.
- `zm/inclusionai/ming-image-0.1-design` si vyberá vlastné rozmery. Vynechajte `size`,
  `aspect_ratio` a `image_size`; explicitné hodnoty vracajú HTTP 400. Pomocou `output_format`
  možno vyžiadať PNG, JPEG alebo WebP.

Táto integrácia podporuje generovanie obrázkov z textu, nie úpravu referenčných obrázkov. Výstup
z Vertexu sa normalizuje na `data[].b64_json`; `response_format: "url"` vracia nadradenú
HTTPS URL alebo URL s údajmi kódovanými v base64, ak sú k dispozícii iba bajty obrázka. Prázdne alebo
filtrované výstupy vracajú chybu namiesto úspešnej odpovede s prázdnym obsahom. Prístup k modelom
závisí od účtu ZenMux. Pozrite si [Vertex API od ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) a
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

Pripojenie na prihlásenie do Microsoft 365 Copilot poskytuje `copilot-m365-web/m365-copilot-image`
prostredníctvom vstavaného nástroja na prácu s obrázkami v Copilote: jedno kolo Copilota na obrázok
(`n` 1–4), pričom `size` ovplyvňuje iba orientáciu a obrázky sa vracajú priamo (`b64_json` alebo
dátová URL pre `response_format: "url"`). Pozrite si [Microsoft 365 Copilot](../providers/COPILOT-M365.md#image-generation).

```bash

GET /v1/images/generations
```

## OCR dokumentov

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model` vyberá poskytovateľa OCR pomocou prefixu `provider/model`; samotný identifikátor modelu (napr.
`mistral-ocr-latest`) sa priradí k jeho registrovanému poskytovateľovi a ak sa `model` neuvedie, použije sa
Mistral (`mistral-ocr-latest`). Registrovaní poskytovatelia (`open-sse/config/ocrRegistry.ts`):

| ID poskytovateľa              | ID modelu            | Hodnota `model`                                                   | Poznámky                                                                                                                                         |
| ----------------------------- | -------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (alebo samotné `mistral-ocr-latest`) | Synchrónne — odpoveď sa vracia priamo z jediného upstreamového volania.                                                                          |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                       | Asynchrónne upstreamové spracovanie (`analyze` + poll) — pozri nižšie.                                                                           |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                           | Synchrónne, prostredníctvom partnerského koncového bodu Vertex AI `openapi/chat/completions` — informácie o autentifikácii a URL nájdete nižšie. |

Všetci traja poskytovatelia odpovedajú rovnakým telom v tvare Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Postup dotazovania Azure Document Intelligence

API `analyze` služby Azure Document Intelligence je asynchrónne: počiatočná požiadavka vráti
hlavičku `Operation-Location` namiesto tela a výsledok je potrebné získavať dotazovaním. Obslužná
rutina (`open-sse/handlers/ocr.ts`) sa dotazuje na túto URL každú sekundu, najviac počas 30 pokusov,
pri neúspešnej odpovedi dotazu s hodnotou odlišnou od `ok` alebo pri stave `"failed"` okamžite zlyhá
(a nepokračuje v dotazovaní) a ak operácia po vyčerpaní rozpočtu pokusov stále prebieha, vráti `504`.
Konečná odpoveď Azure sa pred vrátením volajúcemu normalizuje do rovnakého tvaru
`pages`/`markdown`, aký používa Mistral, takže klientsky kód nemusí poskytovateľa spracúvať osobitne.

### Autentifikácia a rozlíšenie koncového bodu Vertex AI DeepSeek OCR

`vertex-deepseek-ocr` opätovne používa rovnakú autentifikáciu Vertex AI, ktorú OmniRoute už podporuje
pre chat a obrázkovú komunikáciu (`open-sse/executors/vertex.ts`): API kľúč pripojenia je buď
poverenie Service Account vo formáte JSON (vymenené za krátkodobý prístupový token OAuth prostredníctvom
toku JWT-bearer), alebo už vydaný prístupový token OAuth, ktorý sa použije bez úprav. URL upstreamového
koncového bodu je partnerský koncový bod Vertex s generickým rozhraním
`openapi/chat/completions`, vytvorený z projektu a regiónu pripojenia — explicitné hodnoty
`providerSpecificData.project`/`providerSpecificData.region` majú vždy prednosť;
v opačnom prípade sa projekt odvodí z `project_id` v JSON poverení Service Account a región
predvolene používa `us-central1`. Obe rozlíšenia prebiehajú v `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) a používa ich
`src/app/api/v1/ocr/route.ts` pred odoslaním požiadavky do `handleOcr`.

## Zoznam modelov

```bash
GET /v1/models
Authorization: Bearer your-api-key

→ Vráti všetky chatové, embeddingové a obrazové modely + kombinácie vo formáte OpenAI
```

### Ceny modelov (`pricing`)

Položka obsahuje objekt `pricing`, keď OmniRoute pozná cenu modelu. Cena pochádza
z tabuľky cien, ktorú používa účtovanie nákladov: vstavané predvolené hodnoty, synchronizované ceny a
prepísania nastavené prostredníctvom `/api/pricing`. Ide o katalógové ceny, takže aj poskytovatelia
predplatného zobrazujú cenu za token.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Polia                                                           | Jednotka                        | Poznámky                                                                                                                                                  |
| --------------------------------------------------------------- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | USD za token, desatinný reťazec | Kompatibilné s OpenRouter, nikdy nie v exponenciálnom zápise. Obe polia vyrovnávacej pamäte sa zobrazia iba vtedy, keď existuje cena vyrovnávacej pamäte. |
| `input`, `output`, `cached`, `cache_creation`                   | USD za 1 mil. tokenov, číslo    | Polia zo starších verzií katalógu, zachované pre existujúcich klientov. `reasoning` a `long_context` sa tiež zobrazia, keď ich cenový riadok obsahuje.    |

- **Kombinácie** obsahujú cenu svojho prvého viditeľného cieľa. Vstavané kombinácie `auto/*`
  vyberajú cieľ v čase požiadavky, takže nemajú `pricing`.
- **Bezplatné modely** zobrazujú `"0"` (a `0`), keď je ich cena nulová. Model bez cenového riadka
  tiež zobrazuje `"0"`, keď ho katalóg označuje ako bezplatný (`free: true`) alebo ho uvádza vstavaný
  katalóg bezplatných modelov.
- **Neznáma cena:** položka nemá kľúč `pricing`.
- **Poskytovatelia účtujúci podľa kreditov** (napríklad Kiro) účtujú za požiadavku, nie za token.
  Ich položky si zachovávajú číselné polia za 1 mil. tokenov, ktoré mali predtým, a neobsahujú
  reťazcové polia ceny za token.
- **Varianty** (identifikátory s úrovňou uvažovania, aliasy bez uvažovania, zrkadlá zisťovania a
  gateway zrkadlá) kopírujú cenu modelu, na ktorý smerujú.
- Polia obsahujú iba základné sadzby. Úrovne pre dlhý kontext (číselné pole `long_context`) a
  násobitele servisnej úrovne (napríklad Codex fast alebo flex) nemenia hodnoty `prompt` ani
  `completion`.
- Objekt je rovnaký pre každý spôsob autentifikácie vrátane požiadavky v štýle Anthropic s
  `x-api-key` a `anthropic-version` (odpoveď zostáva `{ "object": "list",
"data": [...] }`). Implementácia: `src/app/api/v1/models/catalogPricing.ts`.

### Predpony ID modelov (`?prefix=`)

Väčšina modelov sa inzeruje pod **predponou poskytovateľa**. Ktorú predponu získate, riadi
príznak funkcie `MODELS_CATALOG_PREFIX_MODE` a možno ho prepísať **pre každú požiadavku** pomocou
parametra dotazu — užitočné pre klienta, ktorý chce čistý zoznam bez zmeny nastavenia platného pre
celý server a všetkých ostatných:

```bash
GET /v1/models?prefix=alias        # jedno id na model — predpona krátkeho aliasu
GET /v1/models?prefix=dual         # oba tvary (predvolené nastavenie servera)
GET /v1/models?prefix=canonical    # iba úplná predpona id poskytovateľa
```

| Režim       | Vypisuje                                                | Poznámky                                                                                                                                                                                                 |
| ----------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **a** `claude/claude-sonnet-4-6` | **Predvolené.** Obe ID smerujú na ten istý model; zachované preto, aby konfigurácie klientov, ktoré natvrdo obsahovali ktorýkoľvek z týchto tvarov, naďalej fungovali. Katalóg sa približne zdvojnásobí. |
| `alias`     | `cc/claude-sonnet-4-6`                                  | Jedna položka na model. Poskytovatelia bez odlišného aliasu svoju položku stále zobrazia, takže sa nič nestratí.                                                                                         |
| `canonical` | `claude/claude-sonnet-4-6`                              | Jedna položka na model pod úplnou predponou ID poskytovateľa. Poskytovatelia bez odlišného aliasu (napr. `antigravity/…`, `agy/…`) tu tiež zobrazia svoje jediné ID, takže sa nič nestratí.              |

Zrkadlo v režime `dual` možno rozpoznať aj bez parametra dotazu: obsahuje pole `parent`
odkazujúce na primárne ID.

Klienti, ktorí vykresľujú výber modelu, by mali požadovať `?prefix=alias` — robí to
[rozšírenie OmniCopilot pre VS Code](../guides/VSCODE-COPILOT.md).

### Filtre zisťovania (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` akceptuje voliteľné filtre zisťovania. Bez ktoréhokoľvek z nich zostáva odpoveď
nezmenená. Zúžia katalóg, ktorý volajúci už vidí (oprávnenia API kľúča sa uplatnia ako prvé),
a spustia sa pred stránkovaním v štýle OpenAI pomocou `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # každá uvedená schopnosť musí byť true
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` katalógu; riadky bez neho sú `chat`
GET /v1/models?q=sonnet&limit=10                           # zhoda bez rozlišovania veľkosti písmen v id alebo názve
```

| Parameter     | Hodnoty                                                                                             |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | nezáporné celé číslo, porovnávané s `context_length`                                                |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1 – 200 znakov                                                                                      |

Neznáma hodnota alebo `min_context`, ktoré nie je nezáporným celým číslom (napríklad `1.5`),
vracia HTTP `400` a správa obsahuje platné hodnoty. Implementácia:
`src/app/api/v1/models/catalogFilters.ts`.

### Krátky zoznam modelov (`POST /v1/models/query`)

`POST /v1/models/query` vracia krátky deterministický zoznam z rovnakého katalógu s rovnakým
overením a viditeľnosťou podľa kľúča ako `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Každé pole je voliteľné. `capabilities` a `exclude` prijímajú pole alebo reťazec oddelený čiarkami;
`max_output` sa porovnáva s `max_output_tokens`. Výsledky sú zoradené podľa `owned_by` a potom
podľa `id`. `limit` má predvolenú hodnotu `20` a hodnoty vyššie ako `100` sa obmedzia na `100`.
Neplatný JSON, neznáme pole alebo neplatná hodnota vracia HTTP `400`.

### Individuálne skryté chatové modely

Model označený ako **Skrytý** na stránke svojho poskytovateľa je vylúčený z katalógu a pri
explicitnom vyžiadaní odmietnutý s HTTP `404` / `model_not_found`. Kontrola používa vyriešeného
poskytovateľa a model vrátane aliasov poskytovateľov, predpôn uzlov kompatibilných poskytovateľov
a predvolených nastavení pripojenia. Kombinácia preskočí skryté ciele a môže použiť viditeľný
súrodenecký model; ak nezostane žiadny spustiteľný cieľ, vráti rovnaký kód chyby. Zrušenie
skrytia sa prejaví pri nasledujúcej požiadavke. Prepisy viditeľnosti platné iba pre obrázky
neskrývajú chatový model s rovnakým ID.

Toto individuálne nastavenie modelu je oddelené od
[zoznamov povolených/zakázaných modelov](../routing/MODEL_EXPOSURE_LIST.md) na vystavenie modelov,
ktoré filtrujú propagáciu v katalógu a kandidátov automatického smerovania, pričom zachovávajú
explicitné odosielanie. Povolenia modelov pre kľúče API sa naďalej uplatňujú nezávisle. Predvolený
režim predpôn katalógu zostáva `dual`.

### Varianty modelov bez uvažovania

Pre modely Claude podporujúce uvažovanie `/v1/models` tiež propaguje variant **bez uvažovania**,
ktorého id má predponu `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Výber tohto id (napr. v konfigurácii Claude Code, ktorá vždy pripája blok `thinking`) sa vyrieši
späť na skutočný `<provider>/<model>` s potlačeným uvažovaním — `thinking:{type:"disabled"}` na
ceste `/v1/messages` alebo sa polia `reasoning`/`reasoning_effort` odstránia na ceste
`/v1/chat/completions`. Variant sa uvádza iba pre modely rodiny Claude, ktoré podporujú uvažovanie
**a** rešpektujú `disabled` (takže napr. modely iba s adaptívnym režimom, ktoré odmietajú
`disabled`, sú vylúčené). Prevádzkovatelia môžu vynútiť zapnutie alebo vypnutie variantu pre
jednotlivé modely prostredníctvom `ModelSpec.noThinkingAlias`.

## Generovanie zvuku ElevenLabs

V OmniRoute nakonfigurujte pripojenie poskytovateľa `elevenlabs` s vaším kľúčom API ElevenLabs.
Klienti sa autentifikujú pomocou svojho kľúča **OmniRoute**
(`Authorization: Bearer $OMNIROUTE_API_KEY`); brána poskytne uložený kľúč poskytovateľa ako
`xi-api-key`. Kľúč ElevenLabs nikdy neposielajte ako bearer token brány.

| Metóda | Cesta                       | Odpoveď                                  | Kategória endpointu kľúča API |
| ------ | --------------------------- | ---------------------------------------- | ----------------------------- |
| POST   | `/v1/sound-generation`      | Natívne zvukové bajty                    | `elevenlabs`                  |
| POST   | `/v1/music`                 | Natívne zvukové bajty                    | `music`                       |
| POST   | `/v1/music/stream`          | Streamované zvukové bajty                | `music`                       |
| POST   | `/v1/music/detailed`        | Natívny multipart zvuk a kompozičný plán | `music`                       |
| POST   | `/v1/music/detailed/stream` | Natívne SSE metadáta a zvukové časti     | `music`                       |
| POST   | `/v1/music/plan`            | JSON kompozičný plán                     | `music`                       |

Tieto endpointy dopĺňajú existujúce trasy `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` a `/v1/speech-to-text`. Natívne polia JSON
a parametre dotazu, ako napríklad `output_format` a `enable_logging`, sa zachovávajú.
Odpovede `/v1/music/detailed` si zachovávajú svoje multipart hranice; analyzujte ich ako multipart.
`/v1/music/detailed/stream` vracia `text/event-stream` s metadátami kompozície a zvukovými časťami
kódovanými v base64 v udalostiach SSE. Všetkých šesť trás podporuje predbežnú kontrolu CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Krátky zvukový efekt. Trvanie: 0,5 až 30 sekúnd.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Trvanie hudby sa uvádza v milisekundách: 3000 až 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Použite `/v1/music/stream` s rovnakým telom JSON na priebežné doručovanie zvuku. Kompozícia
prijíma presne jednu z možností `prompt` alebo `composition_plan`; `/v1/music/plan` vyžaduje
`prompt` a voliteľne prijíma `source_composition_plan`. Natívne schémy zachovávajú ďalšie
polia poskytovateľa, takže verzie kompozičných plánov a možnosti jemného doladenia sa dostanú
do ElevenLabs.

Jednotný endpoint `/v1/music/generations` tiež prijíma `elevenlabs/music_v1`,
`elevenlabs/music_v2` a `elevenlabs/music_v2_5`. Pri aktívnom pripojení ElevenLabs sú tieto
modely sprístupnené v hudobnom katalógu. Tento endpoint vracia
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Jeho pole `duration` je v
sekundách a mapuje sa na `music_length_ms`; explicitné `music_length_ms` má prednosť.
`instrumental` sa mapuje na `force_instrumental`, pričom natívne pole má prednosť.
Na streamovanie použite natívne streamovacie endpointy a na požiadavky riadené výhradne
kompozičným plánom použite natívny endpoint kompozície.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Obmedzenia endpointu, modelu, rozpočtu a pripojenia sa uplatnia pred volaním upstreamu. Natívne
trasy vracajú stavové kódy a telá chýb upstreamu nezmenené vrátane `402` pre obmedzenie plánu a
`429` pre limit kvóty. Hlavičky `character-cost`, `song-id`, `request-id` a `retry-after`
sa zachovávajú, ak sú prítomné. Kladný zostatok bezplatných kreditov nezaručuje prístup ku každému
hudobnému modelu, výstupnému formátu ani funkcii API: ElevenLabs rozhoduje o oprávneniach pre každú
požiadavku. Jednotný endpoint zachováva stavové kódy chýb v normalizovanom obale chýb OmniRoute.

Zmluvy upstreamu: [zvukové efekty](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[kompozícia hudby](https://elevenlabs.io/docs/api-reference/music/compose) a
[podrobnosti streamovania hudby](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

Všetky trasy POST používajú rovnaký tvar: `Bearer your-api-key` + JSON telo overené pomocou Zod (`v1RerankSchema`, `v1ModerationSchema`, `v1AudioSpeechSchema` atď., pozrite si `src/shared/validation/schemas.ts`). Pri zlyhaní schémy sa vracia stav 4xx.

Pre klientov, ktorí nemôžu pripojiť `Authorization: Bearer ...`, OmniRoute prijíma kľúče API aj v URL, a to buď prostredníctvom kompatibility s query reťazcom (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`), alebo prostredníctvom vyhradených koncových bodov `/api/v1/vscode/{token}/...` zdokumentovaných nižšie.

```bash
# Preusporiadanie (poskytovateľ z cloudového registra alebo uzol poskytovateľa kompatibilného s OpenAI ako "<prefix>/<model>")
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Klasifikácia Jina (poverenia Foundation API)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Segmentátor Jina
POST /v1/segment     { "content": "...", "return_chunks": true }

# Vyhľadávanie Jina (s.jina.ai; aliasy poskytovateľa: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# Moderovanie
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — vracia telo audio/mpeg (alebo požadovaného formátu)
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS vyžaduje jazyk a hlas: `language` má predvolenú hodnotu "en"; chýbajúci
# hlas alebo štandardný názov hlasu OpenAI (alloy, nova, …) sa zmení na "Adrian"
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# Úprava obrázka (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# Generovanie videa/hudby (ID modelu s prefixom poskytovateľa)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **Uzly poskytovateľov rerankingu:** `POST /v1/rerank` tiež smeruje na uzly poskytovateľov kompatibilné s OpenAI
> (oMLX, vLLM, Infinity, TEI za bránou, …) adresované ako `<node-prefix>/<model>`. Uzly loopback
> (`localhost`, `127.0.0.1`, `172.16.0.0/12`) sú vždy oprávnené, rovnako ako názvy hostiteľov,
> ktoré operátor uvedie v `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (napr. názov služby Docker/Compose,
> ako napríklad `http://reranker:8080/v1`; k týmto sa pristupuje priamo, nikdy cez `HTTP(S)_PROXY` ani
> cez pripnutý proxy server pripojenia). Uzly na akomkoľvek inom
> hostiteľovi — počítač v lokálnej sieti alebo partner Tailscale — sú oprávnené iba vtedy, keď operátor povolí
> príznak funkcie `RERANK_REMOTE_PROVIDER_NODES` **a** základná URL adresa uzla prejde politikou odchádzajúcich
> URL adries poskytovateľa (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Krok rerankingu pamäťového nástroja volá túto trasu cez
> loopback, takže rovnaké pravidlo platí pre `rerankProviderModel` v nastaveniach pamäte.
>
> **Tvary lokálneho servera:** uzol sa volá na `<base>/v1/rerank` a pri odpovedi 404 na `<base>/rerank`
> (Infinity, TEI). Telo požiadavky smerom k upstreamu obsahuje obe označenia Cohere/OpenAI
> (`documents`, `return_documents`) aj označenia TEI (`texts`, `return_text`) a odpoveď upstreamu
> sa normalizuje na obálku Cohere: holé pole TEI `[{index, score, text}]`, `{results: [{index, score}]}`
> z jednoduchých brán a odpoveď v štýle Voyage `{data: [...]}` sa klientovi vždy vracajú ako
> `{results: [{index, relevance_score, document?}]}`, zoradené podľa skóre a obmedzené na `top_n`.

> **Vyhľadávanie uzlov poskytovateľov:** modely na uzle poskytovateľa kompatibilnom s OpenAI sa zobrazujú v `GET /v1/models`
> pod prefixom uzla. Riadky bez metadát koncového bodu (typické pre lokálne zoznamy `/v1/models`)
> preberajú `apiType` uzla, takže modely uzla `embeddings` majú
> `type: "embedding"` a modely uzla `rerank` majú `type: "rerank"` namiesto predvoleného typu chat; explicitná hodnota
> `supportedEndpoints` v synchronizovanom alebo manuálne pridanom riadku má stále prednosť.

## API súborov

Koncový bod súborov kompatibilný s OpenAI na dávkový vstup/výstup a nahrávanie súborov na konkrétny účel.

| Metóda | Cesta                    | Popis                                                                                                            |
| ------ | ------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/files`              | Nahrať súbor (multipart: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — maximum 512 MiB |
| GET    | `/v1/files`              | Zobraziť zoznam súborov pre autentifikovaný kľúč API                                                             |
| GET    | `/v1/files/[id]`         | Načítať metadáta súboru                                                                                          |
| DELETE | `/v1/files/[id]`         | Odstrániť súbor                                                                                                  |
| GET    | `/v1/files/[id]/content` | Streamovať späť nespracované telo súboru                                                                         |

### Pomenované kombinácie search/fetch

`POST /v1/search` aj `POST /v1/web/fetch` akceptujú `model` ako uložený kombinovaný názov. Použite buď `model` alebo explicitné `provider`; odoslanie oboch návratov `400`. Bez žiadneho poľa zostane existujúci automatický výber poskytovateľa nezmenený.

Combo Builder aj jeho katalóg Pridať model odhaľujú natívne položky webovej prevádzky pre pripojených poskytovateľov, aj keď nemajú žiadny zoznam modelov LLM. Serper ukazuje** vyhľadávanie na webe** ; Tavily ukazuje** Vyhľadávanie na webe / extrakcia stránok** , a zobrazujú sa iba poskytovatelia na načítanie** Extrakcia stránky** . Zvoľte záznam a účet ako obvykle. Jeden záznam Tavily obsluhuje oba webové koncové body; tieto položky operácií sa nepridávajú do selektorov klienta iba pre chat alebo do testov modelu chatu.

Napríklad vytvorte a** prioritou** combo s názvom `shared-free` s týmito usporiadanými cieľmi:

1. `openai/gpt-4o`
2. `tavily-search/web`
3. `serper-search/web`
4. `jina-reader/fetch`

Potom použite rovnaký názov na každom povrchu:

```json
{ "model": "shared-free", "query": "Open source speech recognition", "max_results": 5 }
```

```json
{ "model": "shared-free", "url": "https://example.com", "format": "markdown" }
```

Vyhľadávanie zvažuje Tavily a potom Serpera; aport zvažuje Tavily a potom Jina Reader; chat preskočí špecializovaných poskytovateľov search/fetch a zvažuje OpenAI. Kompatibilita pochádza z registrov vykonávateľov search/fetch, nie zo slov v názve modelu. Filtrovanie predchádza výberu a odoslaniu poverení a nikdy neupravuje uloženú kombináciu.

Trasy bez četovania podporujú `priority`, `fill-first`, `round-robin`, `weighted`, `random`, `strict-random`, `least-used` a `p2c`. Stratégie syntézy iba prostredníctvom četu, ako sú `fusion`, `pipeline` a `context-relay` sú odmietnuté na cestách bez četu, namiesto toho, aby sa v tichosti použili na vyhľadávanie alebo generovanie médií. Existujúci kombinovaný nástroj spracováva objednané záložné riešenia, vrátane zlyhaní upstream kvót, a zachováva krok IDs, piny účtu, zoznamy povolených účtov pre jednotlivé kroky, vnorené referencie, rozsahy connection/quota volajúceho a politiku kombinovaného prístupu. Výsledky si zachovajú svoju natívnu schému search/fetch vrátane skutočného poskytovateľa; `X-OmniRoute-Combo-Trace` identifikuje rozhodnutie o smerovaní. Neznáme kombá return `404`; neaktívne kombá a kombinácie bez kompatibilných cieľov vrátia `400`.

Každý kombinovaný pokus používa jedného explicitného poskytovateľa. Nemôže vyvolať natívny automatický fond poskytovateľov za chrbtom komba. Explicitné požiadavky poskytovateľa si zachovávajú svoje existujúce správanie jedného poskytovateľa. Priame žiadosti o rozhovor zacielené na špecializovaných poskytovateľov search/fetch vrátia použiteľný JSON `400` namiesto toho, aby prepadli spúšťaču v štýle OpenAI.

### Kombinované trasy špecifické pre schopnosti

Uložené kombá môžu obsahovať objekt `routes`, ktorého kľúče sú schopnosti API. Každá trasa má svoj cieľový zoznam, stratégiu a konfiguráciu runtime. Najvyššia úroveň `models`, `strategy` a `config` zostáva plánom chatu kompatibilným so staršími verziami; staré kombá bez `routes` naďalej fungujú bez zmeny.

Podporované smerové kľúče sú `chat`, `search`, `web-fetch`, `embeddings`, `rerank`, `images`, `image-edits`, `videos`, `music`, `ocr`, `audio-speech`, `audio-transcriptions`, `audio-translations` a `audio-generation`. Projekcia koncového bodu prebieha pred výberom poverení, hodnotením alebo odoslaním. Vnorené kombá referencie vyberajú trasu podriadeného komba pre rovnakú schopnosť.

`POST /v1/music/generations` a `POST /v1/ocr` akceptujú kombinovaný názov v `model`. Natívny `POST /v1/music` kompatibilný s ElevenLabs tiež akceptuje názov komba v `model_id`, ale každý použiteľný cieľ na tomto natívnom koncovom bode musí byť hudobný model ElevenLabs, aby sa zachovala jeho binárna zmluva odozvy. `POST /v1/sound-generation` akceptuje kombináciu `audio-generation` v `model_id` pod rovnakým natívnym binárnym obmedzením. Použite `/v1/music/generations` pre heterogénnych poskytovateľov hudby.

**Automatický výber:** bez `provider`, najlacnejší poskytovateľ s nakonfigurovaným pripojením beží ako prvý a ďalší najlacnejší je failover. Bezplatní poskytovatelia poslednej inštancie (`duckduckgo-free`) sa používajú iba vtedy, keď nie je nakonfigurované nič iné. Samohostený SearXNG sa počíta ako nakonfigurovaný, keď jeho pripojenie uloží skutočný `baseUrl` (nie predvolené `http://localhost:8888/search` v katalógu): potom sa zaradí ako poskytovateľ s 0 USD pred kľúčovanými, pričom najlacnejší kľúčovaný poskytovateľ má funkciu núdzového prepnutia, a to aj vtedy, keď SearXNG odpovie na 400, 401, 403 alebo 404. `baseUrl`, ktoré nie je platnou adresou v cloude, alebo URL neukazuje na `http(s)`. Pripojenie SearXNG, ktoré ukladá token, sa takto radí iba cez `https://` alebo loopback `http://`. Cez vzdialený obyčajný `http://` to nikdy nie je núdzové prepnutie a zostáva poslednou možnosťou, používa sa iba vtedy, keď nie je nakonfigurovaný žiadny iný poskytovateľ alebo keď je to požadované podľa názvu, takže v týchto dvoch prípadoch token posiela ako čistý text.

### Exa a Tavily `provider_options`

Exa a Tavily čítajú polia špecifické pre poskytovateľa z vrecka s menným priestorom: `provider_options.exa` (alebo `provider_options["exa-search"]`) a `provider_options.tavily` (alebo `provider_options["tavily-search"]`). Preposielajú sa iba nižšie uvedené klávesy. Každý z nich je porovnaný so svojou vlastnou schémou Zod v `open-sse/handlers/search/providerOptionsPassthrough.ts` a kľúč s nesprávnym typom je vypustený. Všetky ostatné kľúče sú ignorované, vrátane auth, base URL, `stream` a `outputSchema`. Ploché klávesy používané inými poskytovateľmi (`cx`, `depth`, ...) fungujú ako predtým.

| Poskytovateľ | Polia najvyššej úrovne                                                                                                                                                                                                                                                                                                                                                    | Vnorené                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Exa          | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (ploché primitívy), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                             | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` zlúčený cez predvolený `{ text: true, highlights: true }` |
| Tavily       | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                       |

Vždy vyhrávajú všeobecné polia: `query`, `max_results`, `filters` (domény), `country` a téma odvodená od `search_type`. Na Exa `search_type: "news"` ponechá `category: "news"`. Tavily akceptuje `search_type: "finance"` (`topic: "finance"`).

Náklady na vyhľadávanie Firecrawl sa zaznamenávajú na začatý blok 10 vrátených výsledkov, pri 0,002 USD (2 kredity) blok a aspoň jeden blok na hovor ( [účtovanie Firecrawl](https://docs.firecrawl.dev/billing) ): 11 výsledkov stojí 0,004 USD.

Všeobecná `time_range` sa teraz dostáva k obom poskytovateľom: Exa získa `startPublishedDate` (časová značka ISO ) a Tavily získa `start_date` (`YYYY-MM-DD`). Explicitný dátum v `provider_options` prepíše mapovaný dátum.

Výsledky Exa ponechávajú `id`, `highlights` (každé zvýraznenie, nielen prvé použité ako `snippet`), `highlight_scores`, `summary`, `subpages`, `entities` a `extras` v `provider_raw`. Tavily výsledky zachovať `images` a `favicon`.

Náklady na vyhľadávanie prepojenia sú zaznamenané vo výške 0,005 USD pre `depth` `fast` a `standard` a 0,05 USD pre `deep` ( [cena za prepojenie](https://docs.linkup.so/pages/documentation/development/pricing) ), či už `depth` pochádza zo `provider_options` alebo z nastavení pripojenia.

Exa `type: "lite"` (Exa 3.0) akceptuje menšiu množinu polí a odmietne celú požiadavku, keď je nastavené akékoľvek iné pole. Pre lite sa pred hovorom zrušia `additionalQueries`, `systemPrompt` a všetky klávesy `contents` okrem `text` a `highlights`. Zastarané `subpages`, `subpageTarget`, `highlights.numSentences` a `highlights.highlightsPerUrl` sa už neposielajú ďalej.

Účtovanie nákladov je plochý register `costPerQuery`, s výnimkou Exa, ktorý sa riadi vlastnou cenou Exa: 0,007 USD za hovor pre `auto` (a starší `fast`) alebo 0,004 USD pre `lite` (a starý `instant`), pokrývajúci 10 výsledkov; 0,001 USD za každý ďalší výsledok; a 0,001 USD za vrátený výsledok, keď je nastavené `contents.summary`. Tavily je zaznamenaný vo výške 1 kreditu (0,008 USD) za `search_depth` `basic`, `fast` a `ultra-fast` a 2 kredity (0,016 USD) za `advanced` ( [kredity Tavily API](https://docs.tavily.com/documentation/api-credits) ). Hovor so `auto_parameters: true`, ktorý Tavily upgraduje na pokročilý, je stále zaznamenaný s 1 kreditom.

## Web Fetch API

Extrahujte obsah zo URL prostredníctvom nakonfigurovaného poskytovateľa webového načítania (Firecrawl, Jina Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract, Keenable Fetch).

Parallel Extract (`parallel-search`, rovnaký kľúč API ako Parallel Search) vráti iba Markdown — akékoľvek iné `format` je `400` — a obsah obmedzí na 100 000 znakov. Keď nemožno extrahovať samotnú cieľovú stránku, upstream to ohlási v HTTP 200; OmniRoute sa zobrazí ako `422` s pevnou správou.

Keenable Fetch (`keenable-search`) tiež vráti iba Markdown (akýkoľvek iný `format` je `400`) a obmedzí obsah na 100 000 znakov. Funguje to bez kľúča: explicitná požiadavka `provider: "keenable-search"` bez pripojenia používa bezkľúčový koncový bod Keenable (limity rýchlosti na IP). Nakonfigurovaný kľúč iba ruší tieto limity; automatický výber používa Keenable iba vtedy, keď je nakonfigurovaný kľúč.

| Metóda | Cesta           | Popis                                           |
| ------ | --------------- | ----------------------------------------------- |
| POST   | `/v1/web/fetch` | Fetch/scrape a URL — overené `v1WebFetchSchema` |

**Auth:** Nosič API kľúč (`extractApiKey` + `isValidApiKey`). Politika presadzovaná prostredníctvom `enforceApiKeyPolicy`.

Pomenované kombinácie používajú [zmluvu o smerovaní `model`](#named-searchfetch-combinations) vyššie, pričom zachovávajú možnosti a odpovede špecifické pre načítanie.

**Záložné opatrenie s ohľadom na kvóty (#8297):** keď nie je zadané ani `provider` ani `model`, skupina (`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` → `parallel-search` → `keenable-search`) sa prechádza v poradí s pevnou prioritou (naplniť-najskôr) — poskytovateľ s obmedzenou rýchlosťou, ale nakonfigurovaný, je preskočený namiesto skratu a retryable/quota vždy vyššie; 402/403 pre bezplatnú úroveň kvót v štýle HTTP — nie pre Firecrawl/Tavily/TinyFish Reader a nikdy pre obyčajnú chybnú požiadavku 400) spadne na ďalšieho nevyskúšaného povereného poskytovateľa v čase vyžiadania. Keď sa vyčerpá každý poskytovateľ v oblasti, koncový bod vráti jeden `429` (s hlavičkou `Retry-After` ) namiesto predchádzajúceho generického `400`. Keď sa požaduje explicitné `provider`, existuje** č** tichý záložný — rýchlostne obmedzený alebo zlyhávajúci explicitný poskytovateľ zobrazí svoju vlastnú chybu (`429`, ak je rýchlosť obmedzená, inak stav upstream).

## Streamovanie cez WebSocket

```bash
GET /v1/ws?handshake=1
```

Overí handshake pri aktualizácii na WebSocket a vráti príklad správ wire protokolu (`request`, `cancel`). Skutočné rámce WS spracúva pribalený WS server mimo tabuľky trás Next.js.

**Autentifikácia:** Bearer API kľúč počas handshaku.

### Responses API cez WebSocket (iba codex)

```bash
# Rovnaký host:port ako HTTP API (predvolene 20128); aktualizujte pripojenie:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (alebo: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Prvý rámec MUSÍ byť response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proxy Responses-API-cez-WebSocket je pripojené **výhradne ku `codex`** (backend ChatGPT). Počúva na rovnakom porte ako API/dashboard na cestách `/v1/responses`,
`/responses` a `/api/v1/responses`. Pri prvom rámci `response.create` vykoná autentifikáciu a prípravu prostredníctvom interného mostíka `codex-responses-ws`, vyberie pripojenie OAuth codex a tuneluje na
`wss://chatgpt.com/backend-api/codex/responses`
prostredníctvom transportu `wreq-js`. **Modely iné ako codex sa odmietnu** (`codex_ws_provider_required`).
Na smerovanie zdieľania kvóty použite `model: "qtSd/<group>/codex/<model>"`. Implementované v
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Autentifikácia:** Bearer API kľúč počas handshaku. Pribalený HTTP server (`server-ws.mjs`)
musí byť aktívnym vstupným bodom (štandardne ním je, keď existuje `app/server-ws.mjs`).

#### ID modelu: použite holé ID ChatGPT (bez predpony `codex/`)

OpenAI **Codex CLI** overuje názov modelu na strane klienta, keď
`supports_websockets = true`, a **odmieta ID s predponou poskytovateľa**, ako napríklad
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Odošlite **holé** ID (napr. `gpt-5.5`). Most OmniRoute je určený iba pre codex, takže pred tunelovaním upstreamu znova vyrieši holé ID ako model codex
(`resolveCodexWsModelInfo`) — hoci holé `gpt-5.5` by sa inak cez HTTP smerovalo k inému poskytovateľovi.

#### Konfigurácia OpenAI Codex CLI

Nasmerujte Codex CLI na OmniRoute pridaním vlastného poskytovateľa s podporou WebSocket do súboru `~/.codex/config.toml` (použite samostatný `CODEX_HOME`, aby ste nezasiahli existujúcu konfiguráciu):

```toml
model = "gpt-5.5"                 # holé ID — NIE "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # bez koncovej lomky; URL WS sa odvodí (v produkcii použite https/wss)
wire_api = "responses"                    # jediná podporovaná hodnota od februára 2026
supports_websockets = true                # povolí transport Responses cez WS
env_key = "OMNIROUTE_API_KEY"             # obsahuje kľúč API OmniRoute (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # kľúč API OmniRoute (ľubovoľný kľúč, ak je REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI aktualizuje `base_url + /responses` na WebSocket a OmniRoute ho tuneluje
k vybranému pripojeniu OAuth codex. Funkčnosť bola overená od začiatku do konca na lokálnom
serveri: ChatGPT vracia `codex.rate_limits` + `response.created` a streamuje dokončenie.

### Obnovenie relácie kvóty (prihlásenie)

Nestreamovaný `POST /v1/chat/completions` alebo `POST /v1/responses`, ktorý zlyhá s chybou terminálnej kvóty (`402`/`429`/`503` ktorého telo hovorí, že kvóta alebo kredity sú vyčerpané), možno namiesto vrátenia chyby zaparkovať a prehrať neskôr. Volajúci sa prihlási na žiadosť s tromi hlavičkami:

| Hlavička                     | Hodnota                                              |
| ---------------------------- | ---------------------------------------------------- |
| `x-omniroute-quota-recovery` | `auto`                                               |
| `x-omniroute-session`        | ID relácie, `[A-Za-z0-9._:-]{1,128}`                 |
| `x-omniroute-recovery-turn`  | turn id jedinečné v rámci relácie (rovnaké pravidlo) |

Vhodné sú iba otáčky `stream: false` bez nástrojov, histórie nástroja alebo `previous_response_id` a bez kolíka `x-omniroute-connection` a musí byť nastavené `STORAGE_ENCRYPTION_KEY` (požiadavka je uložená zašifrovaná až 24 hodín). Odpoveď je potom `202` s `recovery.poll`; anketa `GET /v1/quota-recoveries/{id}` (`202` zatiaľ čo čaká, `200` s obnoveným telom po dokončení) alebo zrušte pomocou `DELETE`. Lístky sú viditeľné iba pre kľúč API, ktorý ich vytvoril. Opakované prehrávanie, ktorého výsledok je neistý, končí v `needs_confirmation` namiesto toho, aby bol odoslaný dvakrát. Zdroj: `src/lib/quota/quotaSessionRecovery.ts`.

```bash
# Structured form — what a UI consumes
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Kľúč musí mať**`allowUsageCommand`** povolená (v predvolenom nastavení vypnutá — správca kľúčov API dashboardu prepína podľa klávesu). Bez neho koncový bod odpovedá `403`.

`?format=json` vracia diskriminovaný tvar, takže volajúci nikdy nečíta dátové pole z odmietnutia. O úspechu:

```jsonc
{
  "allowed": true,
  // present only when the key opted into per-key usage limits (daily/weekly/5-hour USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // the selected provider quota snapshot, or null when nothing is cached yet:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // every connection's snapshot, so a UI can render several providers side by side:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Pri odmietnutí (`401` zlý kľúč / `403` nie je povolený) tá istá cesta vráti `{ "allowed": false, "error": { "message": "…" } }` — prítomný, ale prázdny `personal`/`provider` (kľúč povolený, zatiaľ sa nič nenaučilo) je odlišný stav od odmietnutia a rozlišuje ich iba forma JSON.

**Auth:** vlastný kľúč nositeľa API volajúceho, overený pomocou `isValidApiKey` — toto _nie je_ riadiaci povrch (`/api/keys/…`), ktorý zostáva za `requireManagementAuth`.

### Percento nespracovaných a upravených kvót

Pri konzumácii `/api/usage/om-usage` by si volajúci mali všimnúť rozdiel medzi percentami prezentovanými v** výstup vo formáte čistého textu** a štruktúrované** výstup JSON** :

| Aspekt                   | Formát obyčajného textu (`/api/usage/om-usage` / `@@om-usage`)                            | formát JSON (`?format=json`)                                                           |
| :----------------------- | :---------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------- |
| **Výstupné pole**        | `NN% left` (napr. `20% left`)                                                             | `provider.quotas` / `providers[].quotas`                                               |
| **Meranie**              | **Použiteľný prídavok upravený na hranicu** : zostávajúca kapacita nad hraničným prahom   | **Neupravená kvóta proti prúdu** : neupravené meranie poskytovateľa                    |
| **Medzné škálovanie**    | Škálované cez `effectiveRemainingPercent()`, takže chránená rezerva sa číta ako `0% left` | Žiadne (nespracované hodnoty snímky, ako ich nahlásil poskytovateľ)                    |
| **Prahové údaje**        | Zahrnuté do zobrazených percent                                                           | Uložené v `quotaWindowThresholds` na pripojenie (alebo predvolené nastavenia servera)  |
| **Primárny spotrebiteľ** | Interaktívna CLIs, terminálové výzvy, ľudská obsluha                                      | Programové integrácie, informačné panely, analytika, nástroje na sledovanie fakturácie |

#### Vzorec na úpravu medznej hodnoty

OmniRoute podporuje proaktívne obmedzenia kvót, aby sa zabránilo vyčerpaniu upstream (konfigurované prostredníctvom pripojenia `quotaWindowThresholds`, predvolených nastavení poskytovateľa alebo globálnych nastavení odolnosti). Keď je v okne kvóty aktívny limit (napr. `cutoff = 25%`), vykresľovač textu vypočíta zostávajúcu povolenú hodnotu ako:

- Ak `remaining <= cutoff`: vráti `0%`.
- Ak `remaining > cutoff`: vráti `((remaining - cutoff) / (100 - cutoff)) * 100`.

Formátovaný textový výstup to zaokrúhli na najbližšie celé číslo (`Math.round(...)`).

#### Ilustračný príklad

Zvážte okno poskytovateľa s** 60% surová spotreba** (preto** Zvyšná kvóta 40 % v surovom stave** ) a nakonfigurovaný** 25 % zvyšných kvót** prahová hodnota:

| zastupovanie                  | Výpočet                                            | Zostávajúce |           Implicitne použité            |
| :---------------------------- | :------------------------------------------------- | :---------: | :-------------------------------------: |
| **Raw JSON (`?format=json`)** | Snímka proti prúdu (`quotas[window]`)              |   **40%**   |                 **60%**                 |
| **Formát textu (`NN% left`)** | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` |   **20%**   | **80 %** (ak počítam `100 - remaining`) |

- **Prečo text zobrazuje 20 % zostávajúcich:** Zo 40 % fyzickej kvóty, ktorá zostala na účte, je 25 % rezervovaných na základe zásady prerušenia. Volajúcemu zostáva len 15 % zo 75 % využiteľného priestoru, kým router prestane smerovať na toto spojenie. Škálovanie zaisťuje vyčerpanie signálov spojenia (`0% left`) presne vtedy, keď sa ukončí smerovanie.
- **Prečo JSON zachováva nespracované hodnoty:** Užitočné zaťaženie JSON vracia presnú snímku poskytovateľa (`UsageSnapshot`), takže externé nástroje majú prístup k základnému upstreamu a `quotaWindowThresholds` na úrovni pripojenia bez straty škálovania na strane servera.

#### Usmernenie k migrácii spotrebiteľov

Ak externá integrácia (napríklad doplnok editora alebo rozšírenie agenta) predtým zoškrabala koncový bod textu (`NN% left`) a vypočítala použité percento ako `100 - NN`, migrácia na `?format=json` znamená:

- Čítanie nespracovaných hodnôt JSON sa prejaví** skutočnej spotreby** (60 % použitých v príklade vyššie).
- Ak si integrácia želá zachovať sémantiku použiteľných povolení koncového bodu textu, môže vyhodnotiť efektívny zostávajúci vzorec na strane klienta pomocou `quotaWindowThresholds` na prepísanie na úrovni pripojenia.

## Sémantická vyrovnávacia pamäť

```bash
# Získanie štatistík vyrovnávacej pamäte
GET /api/cache/stats

# Vymazanie všetkých vyrovnávacích pamätí
DELETE /api/cache/stats
```

Príklad odpovede:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### Vplyv na latenciu

HIT sémantickej vyrovnávacej pamäte obslúži odpoveď z vyrovnávacej pamäte **bez volania upstreamu**, takže nahlásená hodnota `X-OmniRoute-Response-Latency` je takmer nulová
(bez ohľadu na pôvodnú latenciu upstreamu). Klienti citliví na latenciu
(benchmarking, monitorovanie p50/p99) by mali kontrolovať hlavičku odpovede
`X-OmniRoute-Cache-Latency`:

| Hodnota     | Význam                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------- |
| `synthetic` | Odpoveď bola obslúžená z vyrovnávacej pamäte; latencia nepredstavuje skutočný čas upstreamu |
| _(absent)_  | Odpoveď zo skutočného volania upstreamu                                                     |

### Obídenie vyrovnávacej pamäte pre konkrétny kľúč

Kľúče API môžu vypnúť čítanie zo sémantickej vyrovnávacej pamäte prostredníctvom `cacheDefaultMode`:

| Hodnota  | Správanie                                                                    |
| -------- | ---------------------------------------------------------------------------- |
| `legacy` | Bežné správanie vyrovnávacej pamäte (predvolené)                             |
| `bypass` | Úplne preskočí vyhľadávanie vo vyrovnávacej pamäti; vždy kontaktuje upstream |

Nastavte pri vytváraní kľúča (`POST /api/keys`) alebo jeho aktualizácii (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### Obídenie vyrovnávacej pamäte pre konkrétnu požiadavku

Každá požiadavka môže obísť vyrovnávaciu pamäť bez ohľadu na nastavenia kľúča:

```
X-OmniRoute-No-Cache: true
```

## Kompatibilita správy CLIProxyAPI

OmniRoute odpovedá na tri koncové body správy [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI),
ktoré informačné panely používania volajú na načítanie limitov predplatného Claude a Codex
(napríklad zdroja limitu používania `cliproxy` v T3 Code). Nasmerujte základnú URL klienta na
OmniRoute a ako kľúč správy použite kľúč API s rozsahom `manage`. Trasy sú dostupné na adresách
`/v0/management/*` a `/api/v0/management/*`.

| Metóda | Cesta                        | Popis                                                                                                                                         |
| ------ | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/v0/management/auth-files`  | Pripojenia OAuth pre Claude a Codex vo formáte `{ files: [{ id, auth_index, provider, email, disabled, id_token }] }`. Žiadne tokeny          |
| POST   | `/v0/management/api-call`    | Telo `{ auth_index, method, url, header?, data? }`. Odošle jednu požiadavku na povolený zoznam s tokenom účtu a vráti `{ status_code, body }` |
| POST   | `/v0/management/reset-quota` | Telo `{ auth_index }`. Vymaže časový limit pripojenia, blokovania modelov a časové limity Codexu podľa rozsahu pre jeden účet                 |

- `auth_index` je ID pripojenia OmniRoute. `provider` je `claude` alebo `codex` (iba pripojenia
  OAuth; poskytovateľ API kľúča `anthropic` sa neuvádza). V prípade Codexu je
  `id_token.chatgpt_account_id` uložené ID pracovného priestoru a `plan_type` uložený plán.
- `api-call` nie je generické proxy. Akceptuje iba Claude `GET
https://api.anthropic.com/api/oauth/usage` a Codex `GET
https://chatgpt.com/backend-api/wham/usage`, `GET .../wham/rate-limit-reset-credits` a
  `POST .../wham/rate-limit-reset-credits/consume`, pričom každý z nich iba pre účet zodpovedajúceho
  poskytovateľa. Čokoľvek iné vráti `403` bez kontaktovania upstreamu. Hlavička
  `Authorization` volajúceho (vrátane zástupného symbolu `$TOKEN$`) sa ignoruje: OmniRoute vloží
  prístupový token pripojenia, najprv ho obnoví, ak sa blíži jeho skončenie platnosti, a prepošle iba
  hlavičky povolené zo zoznamu (`anthropic-beta`; `OpenAI-Beta`, `Originator`, `Chatgpt-Account-Id`;
  `Accept`, `Content-Type`). Ak `Chatgpt-Account-Id` chýba, predvolene sa použije uložené ID
  pracovného priestoru. Časový limit požiadaviek je 15 sekúnd a použije sa proxy pripojenia.
- `reset-quota` ponechá koncové stavy (banned, expired, credits_exhausted) nezmenené. Neznámy
  `auth_index` vráti `404`.

**Autentifikácia:** relácia informačného panela alebo kľúč API s rozsahom `manage`, vyžadované aj v prípade, že je prihlasovanie vypnuté
(cesty sa nachádzajú v `ALWAYS_PROTECTED_API_PATHS`). Kľúče určené iba na inferenciu dostanú `403`. Zdroj:
`src/lib/cliproxyCompat/managementApi.ts`.

Pre modely synced/imported `PUT /api/provider-models` akceptuje `provider`, `modelId` a `maxOutputTokenOverride`: kladné celé číslo nastavuje manuálne obmedzenie výstupného tokenu a `null` ho vymaže, aby sa obnovilo predvolené nastavenie. `GET /api/provider-models?provider=<provider>` vráti tieto hodnoty v `modelOutputOverrides`, vrátane modelov bez riadku vlastného modelu. Prepísanie používa schopnosť runtime `max_output_tokens` a prežije opätovnú synchronizáciu modelu. Stránka poskytovateľa kompatibilná s OpenAI ponúka rovnaké ovládacie prvky a značky edit/clear s explicitnou podporou zraku.

V uzle kompatibilného poskytovateľa cesty zápisu (`POST`, `PUT`, `PATCH`, `DELETE` a `/api/provider-models/validate-and-add`) ukladajú id modelu ako holé upstream id: id prilepený zo zoznamu s predponou má zbalený akýkoľvek úvodný zásobník vlastnej predpony uzla a odpovede odrážajú uložené id. Zlomené id kanonických poskytovateľov (napr. `nvidia/nemotron-…`) sa ukladajú doslovne. `/v1/models` nikdy nevysiela stohované `<prefix>/<prefix>/<model>` id.

Uzly Custom Chat Completions prispôsobujú explicitné uvažovanie odhlásenia na upstream backend. Úspešný test pripojenia automaticky vyberie ovládacie prvky šablóny chatu pre každý presný model ID ktorého vstup `/models` dokazuje rozpoznanú hodnotu `owned_by` : `vllm`, `sglang` alebo `llamacpp`. Transparentné obaly kompatibilné s OpenAI môžu zachovať pôvodný záznam modelu vo vnútri vnoreného objektu `openai` ; detekcia sleduje až tri takéto obálky. Modely s chýbajúcim, neznámym alebo konfliktným vlastníctvom si zachovávajú bežné správanie OpenAI. Detekcia opätovne používa existujúcu požiadavku na katalóg, negeneruje žiadne tokeny dokončenia a pri zmene koncového bodu pripojenia sa zruší.

Ak chcete pripnúť správanie pre backend, ktorý nezverejňuje tieto metadáta, použite existujúcu čiastočnú aktualizáciu poskytovateľa API:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Pošlite to telo s `PUT /api/providers/<connection-id>`. V tomto spojení sa explicitné uvažovanie `none` posiela ako `chat_template_kwargs.thinking=false` a `chat_template_kwargs.enable_thinking=false`. Explicitné hodnoty natívnej šablóny zostávajú smerodajné, pokiaľ si pravidlo uvažovania na strane servera nevynúti úsilie. Toto nastavenie sa použije iba vtedy, keď vlastné pripojenie kompatibilné s OpenAI odošle telo dokončenia rozhovoru; Žiadosti o odpovede a bežní poskytovatelia si zachovávajú svoj pôvodný tvar žiadosti. Nastavte `reasoningControl` na `openai`, aby ste vynútili bežný prechod OpenAI `reasoning_effort`, alebo ho vynechajte it/set na `null`, aby ste použili automatickú detekciu.

Klasifikátor automatického režimu kódu Claude požaduje predvolené natívne myslenie na vypnuté, keď neobsahujú žiadne explicitné ovládacie prvky uvažovania. Detekcia používa systémovú značku klasifikátora v požiadavkách vo formáte Claude, nie názvy modelov alebo limity dokončenia. Explicitné ovládacie prvky tela, podporované hlavičky effort/thinking, pravidlá smerovania a vyriešené modelové úsilie si zachovávajú svoju existujúcu prioritu. Obidva stupne klasifikátora si zachovajú svoje výzvy, limity dokončenia, sekvencie zastavenia a skutočné verdikty oprávnenia smerom hore; druhá fáza môže stále produkovať požadované viditeľné odôvodnenie ako obyčajný text.

#### Limitná proveniencia modelu

`GET /api/models?withLimits=1` (tiež `true`; `0`/`false` alebo vynechaním ponechá predvolenú užitočnú záťaž nezmenenú) pridá do každého riadku modelu objekt `contextWindow`, `maxInputTokens`, `maxOutputTokens` a `capsSource`. `capsSource` pomenúva pravidlo, ktoré dodalo každý limit, takže prekvapivý limit (napríklad 128k na 1M modeli) možno vysledovať k jeho pôvodu. Vyriešené hodnoty sú tie isté, ktoré používa smerovanie; príznak iba pridáva polia a nikdy nemení hodnotu. Akákoľvek iná hodnota `withLimits` je odmietnutá pomocou `400`.

| hodnota `capsSource`                         | Pôvod                                                                 |
| -------------------------------------------- | --------------------------------------------------------------------- |
| `override:context`                           | Trvalé prepísanie kontextového okna (`model_context_overrides`)       |
| `override:max_input` / `override:max_output` | Trvalé prepísanie schopnosti `max_input_tokens` / `max_output_tokens` |
| `static-authoritative:<provider>/<model>`    | Statická autoritatívna tabuľka kontextového okna                      |
| `synced:<provider>/<model>`                  | models.dev riadok synchronizovaných schopností                        |
| `registry:<provider>/<model>`                | Záznam v registri poskytovateľa                                       |
| `spec:<model>`                               | Špecifikácia statického modelu                                        |
| predpona `effort-base:`                      | Riadok požičaný zo základného modelu variantu s príponou úsilia       |
| `none`                                       | Žiadny zdroj nedeklaruje limit (hodnota je `null`)                    |

Implementácia: `getResolvedModelCapabilitiesWithLimitSources()` v `src/lib/modelCapabilities.ts` a reťazce prednosti v `src/lib/modelCapabilityLimits.ts`.

### Rozbalenie rámčeka videa

`GET /api/v1/video-bridge/drilldown` číta nepriehľadný popisovač viazaný na nájomcu vrátený v `x-omniroute-video-drilldown` po explicitne schválenej požiadavke Video Bridge. Čítanie aj `DELETE` vždy vyžadujú platný kľúč API a nezávislé povolenie `modalityBridgeVideoDrilldownRemoteEnabled` operátora. Udržanie výroby navyše vyžaduje `modalityBridgeVideoDrilldownEnabled` a prísne `drilldown: true` na časť. Ak má kľúč neprázdny zoznam povolených koncových bodov, musí obsahovať `video` pre GET aj DELETE, či už volajúci používa `/v1` alebo `/api/v1`.

dotaz GET : požadované `handle`; voliteľné `variant` (`preview`, `standard`, `detail`), `limit` (1–8; staré `frames` je akceptované, ale nemožno ho kombinovať so `limit`), `page` s nulovým základom a `start`/`end` sekúnd. Keď sú zadané obe hranice ohniska, `end` musí byť väčšie ako `start`. Duplicate/unknown dopytové kľúče sú odmietnuté. Úspešné odpovede obsahujú `derivation`, `durationSeconds`, `frames`, `hasMore`, `page`, `variant` a voliteľné `focusWindow`; JSON no-store je obmedzená na 32 MiB vrátane Base64. Nadrozmerné výstupné výnosy 413; požadovať menej rámov.

`DELETE /api/v1/video-bridge/drilldown?handle=...` vráti `{ "removed": 0|1 }`. Neznáme, exspirované a krížové GETs sú na nerozoznanie 404 odpovede; krížový kľúč DELETE nemôže odstrániť záznam vlastníka. Zakázaný prístup vracia 403, autentifikácia missing/invalid 401, neplatné dotazy 400, zrušenie 499 a dočasné chyby 503. Rukoväte sú lokálne, ich platnosť vyprší po desiatich minútach a neprežijú reštart. Nové rukoväte používajú `v1.` plus 32-bajtový náhodný token Base64URL ; zachovajú sa iba hodnoty hash tokenov. Staršie 64-hex tokeny zostávajú syntakticky čitateľné kvôli kompatibilite. Súhlas, kvóty a podrobnosti odvodenia variantov nájdete v [časti Ochranné zábradlia Video Bridge](../security/GUARDRAILS.md#video-bridge-videobridgets-videobridgepipelinets).

### Verzia a kanál vydania

```bash
GET /api/system/version
```

Cesta správy len so spätnou väzbou (autorizácia správcu). Vráti spustenú verziu, najnovšiu publikovanú verziu a stav automatických aktualizácií. `releaseChannel` a `channels` sú aditívne polia (koľajnica 3.8.54); `channel` si zachováva svoj význam — režim nasadenia, ktorý používa aktualizátor dashboardu (`npm`, `source` alebo `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — npm kanál spustenej zostavy: `nightly` pre verzie `-nightly.*`, `next` pre ostatné predbežné vydania (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` pre stabilnú verziu staršej major ako `channels.latest`, inak `latest`. Rovnaké pravidlá ako `scripts/release/dist-tag.mjs`, ktorý vyberie npm dist-tag v čase zverejnenia.
- `channels` — zverejnila hlavičku každého dist-tagu zo `npm view omniroute dist-tags` (záložný register HTTP ), uloženú do vyrovnávacej pamäte s rovnakým 10-minútovým TTL ako `latest`. `latest` je vždy prítomný (spadne späť do poľa `latest`, potom `"unavailable"`); `next`, `nightly` a `lts` sa objavia iba vtedy, keď existuje tento dist-tag. Požiadavka `Cache-Control: no-cache` obnoví obe vyhľadávania.

Model kanála (`latest` = v3 až do zostavenia 4,0 GA, `next` = rc, `nightly` = `develop`, `lts` = v3 záplat po 4,0 GA) je opísaný v `docs/ops/RELEASE_STRATEGY.md`.

```bash
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**Odpoveď:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**Príklady identifikátorov modelov:** `openai/whisper-1` (vyžaduje kľúč OpenAI),
`openrouter/deepgram/nova-3` (vyžaduje kľúč OpenRouter),
`deepgram/nova-3` (vyžaduje natívny kľúč Deepgram). Samostatná požiadavka
`deepgram/nova-3` **nepoužíva OpenRouter**.

**Podporované formáty:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`.

**Gemini Live (`gemini/gemini-3.5-transcribe-live`):** prepis v režime súboru cez WebSocket
Gemini Live (vyžaduje kľúč API Gemini). Nahraný súbor sa skonvertuje na 16 kHz mono PCM pomocou `ffmpeg`
(`ffmpeg` musí byť v premennej `PATH`, pokiaľ súbor už nie je vo formáte 16 kHz mono PCM WAV), odošle sa
do relácie a finalizovaný text sa vráti ako `{ "text": "..." }`. Voliteľné polia formulára `language` a `prompt`
sa preposielajú ďalej. Limity: pri nahraných súboroch väčších ako 25 MiB alebo dekódovanom zvuku dlhšom než 10 minút sa vráti
`413`; konverzia, ktorá trvá dlhšie než 60 s, sa ukončí a vráti sa
`504`. Kľúč API sa odosiela iba v hlavičke `x-goog-api-key`, nikdy nie v URL WebSocketu.

## Tokenizované aliasy VS Code / aliasy bez hlavičky

Tieto aliasy použite v prípade, že integrácia nedokáže vložiť hlavičku `Authorization` a potrebuje mať kľúč API vložený v základnej URL.

```bash

GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# Chatové aliasy v štýle OpenAI
POST /api/v1/vscode/{token}/chat/completions

# Aliasy v štýle Ollama
POST /api/v1/vscode/{token}/api/chat
```

Príklad:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
```

Poznámky:

- Tokenizované aliasy používajú rovnaké obslužné rutiny ako `/v1/*` a `/api/tags`; tvary odpovedí zostávajú identické.
- Vždy, keď klient podporuje vlastné hlavičky, uprednostnite `Authorization: Bearer ...`.
- Tokeny v URL sa môžu objaviť v protokoloch reverzného proxy servera, histórii prehliadača a telemetrii mimo OmniRoute. Považujte ich za možnosť kompatibility, nie za predvolený režim autentifikácie.

## Tokenové limity

Limity **tokenov** pre jednotlivé kľúče API (odlišné od rozpočtu založeného na USD uvedeného vyššie). Vynucujú sa priamo na ceste požiadavky: keď aktuálne využitie okna pre daný kľúč dosiahne jeho limit, požiadavky sa zamietnu s chybou `429 Too Many Requests`. Limity možno nastaviť pre konkrétny `model`, `provider` alebo ich uplatniť `global`ne naprieč kľúčom; ak sa na požiadavku vzťahuje viacero limitov, použije sa najprísnejší z nich.

```bash
# Zoznam tokenových limitov kľúča (vrátane aktuálneho využitia okna)
GET /api/usage/token-limits?apiKeyId=key-123

# Vytvorenie alebo aktualizácia tokenového limitu
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Odstránenie tokenového limitu podľa id
DELETE /api/usage/token-limits?id=tl-abc
```

> **Poznámky k schéme** (`setTokenLimitSchema`): `apiKeyId` a `scopeType` (`model` | `provider` | `global`) sú povinné. `scopeValue` je povinné, pokiaľ `scopeType` nie je `global` (napr. id modelu pre rozsah `model`, id poskytovateľa pre rozsah `provider`). `tokenLimit` musí byť kladné celé číslo (konvertované z reťazca). Voliteľné: `id` (pri vytváraní vynechať, pri aktualizácii zadať), `resetInterval` (`daily` | `weekly` | `monthly`, predvolene `monthly`), `resetTime` (`HH:MM`), `enabled` (predvolene `true`). Odpovede `GET` rozšíria každý limit o `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` a `nextResetAt`. Ide o koncový bod triedy správy (autentifikácia sa centrálne vynucuje v autorizačnom kanáli).

## Spracovanie požiadaviek

1. Klient odošle požiadavku na `/v1/*`
2. Obslužná rutina trasy zavolá `handleChat`, `handleEmbedding`, `handleAudioTranscription` alebo `handleImageGeneration`
3. Vyrieši sa model (priamy poskytovateľ/model alebo alias/kombinácia)
4. Poverenia sa vyberú z lokálnej databázy s filtrovaním dostupnosti účtu
5. Pre chat: `handleChatCore` skontroluje sémantickú/podpisovú vyrovnávaciu pamäť a vyrieši nastavenia kompresie kombinácie
6. Pred prekladom pre poskytovateľa sa pri povolení spustí proaktívna kompresia (`lite`, Caveman, RTK alebo vrstvená)
7. Exekútor poskytovateľa odošle požiadavku upstream
8. Odpoveď sa preloží späť do formátu klienta (chat) alebo sa vráti bez zmien (embeddingy/obrázky/zvuk)
9. Zaznamenajú sa údaje o využití, analytika kompresie a protokoly požiadaviek
10. Pri chybách sa podľa pravidiel kombinácie použije záložný mechanizmus

Úplný odkaz na architektúru: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Odolnosť (rozšírené)

OmniRoute poskytuje tri nezávislé mechanizmy dočasných zlyhaní; nižšie uvedené koncové body na správu umožňujú operátorom ich čítať a prepisovať:

| Rozsah                   | Ukladanie stavu                                 | Čítanie                                   | Obnovenie / vymazanie                                         |
| ------------------------ | ----------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------- |
| Prerušovač poskytovateľa | `domain_circuit_breakers` + pamäť               | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                  |
| Chladenie pripojenia     | `rateLimitedUntil` v pripojeniach poskytovateľa | `/api/rate-limits`, `/api/providers/[id]` | (znovu sa povolí oneskorene; vymaže sa cez PUT poskytovateľa) |
| Blokovanie modelu        | Register dostupnosti modelov v pamäti           | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                      |

`PATCH /api/resilience` prijíma prepísania prerušovača poskytovateľa pod `providerBreaker.oauth` a `providerBreaker.apikey`. Každý profil podporuje položky `degradationThreshold`, `failureThreshold` a `resetTimeoutMs`; rovnaké položky sú dostupné v Ovládací panel → Nastavenia → Odolnosť.

```bash
# Vymazať blokovanie jedného modelu
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Vymazať všetky blokovania
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Úplný koncepčný referenčný materiál a predvolené nastavenia prerušovačov nájdete v [`CLAUDE.md`](../../CLAUDE.md) → „Stav odolnosti za behu“ a v [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Front obmedzení rýchlosti a ochranná sieť automatického povolenia

- **Podporovaný zápis**: `POST /api/rate-limits` s telom `{"connectionId": "<id>", "enabled": true|false}` je podporovaný koncový bod na správu prepínania ochrany pred obmedzením rýchlosti pre pripojenie. `PUT /api/providers/[id]` zámerne neupravuje ani neprepína `rateLimitProtection` (#11278).
- **Sémantika `enabled: false`**: Nastavenie `enabled: false` odstráni explicitnú ochranu pre pripojenie, ale **nevylúči** aktívne pripojenie s kľúčom API z globálnej ochrannej siete automatického povolenia (`autoEnableApiKeyProviders = true`). V `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) sú `false` a `undefined` ekvivalentné; aktívne pripojenia s kľúčom API bez explicitnej ochrany zostávajú chránené v rámci ochrannej siete automatického povolenia.
- **Globálne vypnutie**: Ak chcete spúšťať pripojenia s kľúčom API bez frontov obmedzenia rýchlosti, vypnite ochrannú sieť globálne prostredníctvom `RATE_LIMIT_AUTO_ENABLE=false` (prostredie) alebo `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Nastavenia → Odolnosť / `PATCH /api/resilience`).

| GET | `/api/mcp/sse` | Otvoriť stream SSE pre transport SSE (vráti `503` ak je MCP vypnutý alebo nesúlad transportu) |
| POST | `/api/mcp/sse` | Pošlite rámec JSON-RPC na transport SSE |
| GET | `/api/mcp/stream` | Open SSE side of the Streamable HTTP transport (server-initiated messages) |
| POST | `/api/mcp/stream` | Odošlite rámec JSON-RPC na prenos HTTP s možnosťou streamovania |
| DELETE | `/api/mcp/stream` | Ukončite streamovateľnú reláciu HTTP |
| GET | `/api/mcp/audit` | Denník auditu dotazu — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |

## Server A2A

OmniRoute sprístupňuje koncový bod A2A (Agent-to-Agent) JSON-RPC 2.0 a tiež obálku REST na účely kontroly a používania dashboardu.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # voliteľné, pokiaľ nie je nastavené OMNIROUTE_API_KEY
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Podporované metódy (všetky sú podmienené nastavením `settings.a2aEnabled`):

| Method           | Description                                                          |
| ---------------- | -------------------------------------------------------------------- |
| `message/send`   | Synchrónne vykonanie zručnosti; vracia `{task, artifacts, metadata}` |
| `message/stream` | Streamované vykonanie SSE rovnakej množiny zručností                 |
| `tasks/get`      | Načíta úlohu podľa `taskId`                                          |
| `tasks/cancel`   | Zruší úlohu podľa `taskId`                                           |

Vstavané zručnosti: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Karta agenta

```bash
GET /.well-known/agent.json
```

Vráti verejnú kartu agenta A2A (názov, popis, možnosti, katalóg zručností, schéma autentifikácie) — verejne uloženú v cache na 1 hodinu. Autentifikácia nie je potrebná.

### Pomocné REST rozhrania

| Method | Path                         | Description                                                                                                      |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | Informácie o povolení A2A + štatistiky úloh + súhrn karty agenta uložený v cache                                 |
| GET    | `/api/a2a/tasks`             | Zoznam úloh — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Nie je implementované ako pomocné REST rozhranie — vytvorte pomocou JSON-RPC `message/send`)                    |
| GET    | `/api/a2a/tasks/[id]`        | Načíta jednu úlohu                                                                                               |
| POST   | `/api/a2a/tasks/[id]/cancel` | Zruší úlohu                                                                                                      |

**Autentifikácia:** pomocné REST rozhrania fungujú bez autentifikácie správy (sú čitateľné z dashboardu); trasa JSON-RPC `/a2a` používa Bearer `OMNIROUTE_API_KEY`, ak je nakonfigurovaný.

## Autentifikácia

Pozrite si [Autentifikácia správy](../guides/MANAGEMENT-AUTH.md), kde nájdete štyri
rodiny poverení (relácia na informačnom paneli, lokálny token CLI, prístupový token `oma_live_…`, kľúč API s rozsahom manage) a informácie o tom, ako sa líšia od inferenčných kľúčov.

- Trasy informačného panela (`/dashboard/*`) používajú cookie `auth_token`
- Prihlásenie používa uložený hash hesla; záložná možnosť je `INITIAL_PASSWORD`
- Prepínač `requireLogin` možno meniť prostredníctvom `/api/settings/require-login`
- Trasy `/v1/*` voliteľne vyžadujú kľúč API Bearer, keď je `REQUIRE_API_KEY=true`
- „management token“ / „management-scoped API key“ v tejto referencii znamená jednu z rodín uvedených v tejto príručke — nie nedefinovaný dodatočný typ tajného údaja

> **Nekompatibilná zmena (v3.8.0)** — `/api/v1/agents/tasks/*` a koncové body správy cooldownu teraz vyžadujú **autentifikáciu správy** (cookie informačného panela `auth_token` alebo kľúč API s rozsahom manage). Klienti, ktorí predtým volali tieto trasy bez autentifikácie, dostanú `401 Unauthorized`. Pozrite si commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
