`copilot-m365-web` (alias `m365copilot`) odosiela požiadavky chatu vo formáte OpenAI prostredníctvom
overenej relácie prehliadača Microsoft 365 Copilot BizChat na adrese
`m365.cloud.microsoft/chat`. Ide o neoficiálnu integráciu.

> **Začínate s poskytovateľmi používajúcimi webové súbory cookie?**
>
> Pred použitím tejto príručky špecifickej pre poskytovateľa si prečítajte dokument **`docs/getting-started/WEB-COOKIE-GUIDE.md`**, ktorý obsahuje všeobecný postup nastavenia, pokyny k overeniu, obmedzenia a riešenie problémov.
>
> **Dôležité:** Prihlasovací údaj pre tohto poskytovateľa **nie je súbor cookie**. Nekopírujte
> súbory cookie z `m365.cloud.microsoft`. Prihlasovací údaj tvorí parameter dopytu adresy URL WebSocketu
> a segment cesty, ktoré sa získavajú z karty Network v DevTools.

## Predpoklady

- Konto Microsoft 365 s prístupom k BizChat na adrese `m365.cloud.microsoft/chat`
- Prehliadač založený na Chromiu (Chrome, Edge) na kontrolu WebSocketov v DevTools
- Licencia M365 Copilot (je súčasťou mnohých plánov Microsoft 365 Business/Enterprise)

## Získanie prihlasovacieho údaja (metóda WebSocket)

1. Prihláste sa na adrese `https://m365.cloud.microsoft/chat` a začnite konverzáciu.
2. Otvorte **DevTools → Network**.
3. Filtrujte podľa **WS** (WebSocket).
4. Kliknite na pripojenie WebSocket Chathub. Vyhľadajte adresu URL začínajúcu na
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Z jej položky **Request URL** skopírujte:
   - Hodnotu parametra dopytu `access_token` (JWT s krátkou platnosťou).
   - Segment cesty Chathub za `/Chathub/` (napr. `<oid>@<tenant>`).

Úplná adresa URL má tento formát:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. V OmniRoute prejdite na **Providers → Add Provider**, vyberte **Microsoft 365 Copilot
   (BizChat)** a vložte prihlasovací údaj v tomto formáte:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Kliknite na **Test Connection** a **Save**.

## Získanie prihlasovacieho údaja (import HAR)

Namiesto manuálneho kopírovania hodnôt z adresy URL WebSocketu môžete exportovať súbor HAR
z DevTools:

1. Otvorte **DevTools → Network**.
2. Začnite konverzáciu BizChat alebo v nej pokračujte (tým sa aktivuje pripojenie WebSocket).
3. Kliknite pravým tlačidlom myši na panel Network a vyberte **Save all as HAR with content**.
4. V OmniRoute použite tlačidlo **Import .har file** v dialógovom okne pripojenia poskytovateľa.

OmniRoute vyhľadá v súbore HAR adresu URL WebSocketu Chathub, extrahuje
`access_token` a `chathubPath` a automaticky vyplní polia prihlasovacích údajov. Pri
importe HAR sa dekóduje čas vypršania platnosti JWT a zobrazí sa zostávajúca doba platnosti tokenu.

> **Nikdy neukladajte skutočný export HAR, prístupový token ani obnovovací token do systému na správu verzií.** Testovacie
> a dokumentačné hodnoty musia byť vždy zástupné hodnoty.

## Životnosť tokenu a obnovenie

`access_token` má krátku životnosť (zvyčajne **~75 minút**). Bez použiteľného tokenu obnovenia
musíte po jeho vypršaní poverenie znova zachytiť.

### Automatické obnovenie pomocou `refreshToken`

V dialógovom okne poskytovateľa Microsoft 365 **Pridať pripojenie** alebo **Upraviť pripojenie** otvorte
**Rozšírené nastavenia → Token obnovenia (voliteľné)**. Vložte token obnovenia Microsoft OAuth pre
rozsah `substrate.office.com/sydney` a uložte ho. Vstupné pole je maskované a uložený token sa doň nikdy
automaticky nepredvyplní. Pri úprave ho nechajte prázdne, ak chcete zachovať existujúci token;
vložením nového tokenu ho nahradíte.

Token obnovenia získate z toku Microsoft device-code alebo authorization-code
s rozsahom `substrate.office.com/sydney`; dashboard ho za vás nezíska.
Ak je nakonfigurovaný token obnovenia, OmniRoute pred požiadavkami kontroluje
`access_token` a obnoví ho iba vtedy, keď je potrebné jeho obnovenie. Úspešné obnovenie tiež
uloží rotovaný token obnovenia, takže nie je potrebné manuálne opätovné zachytenie, kým token obnovenia zostáva platný.

Ak `refreshToken` nie je nastavený, po každom vypršaní musíte poverenie WebSocket
manuálne znova zachytiť.

### Výber úrovne

| Úroveň       | Alias          | Prostredie             |
| ------------ | -------------- | ---------------------- |
| `individual` | _(predvolené)_ | Consumer M365 Copilot  |
| `edu`        | `included`     | Education M365 Copilot |
| `enterprise` | `work`         | M365 Copilot for Work  |

Úroveň nastavte v časti **Rozšírené nastavenia → Úroveň Copilota**. Úroveň ovplyvňuje
smerovanie BizChat a prístup k modelom.

## Bezpečnostný model

- **Neoficiálna integrácia.** Tento poskytovateľ využíva spätne analyzovaný protokol
  BizChat WebSocket. Keď Microsoft zmení koncový bod, môže bez upozornenia prestať fungovať.
- Príznak `subscriptionRisk: true` vyjadruje, že integrácia využíva
  nezdokumentovaný koncový bod. Obmedzenia účtu sú možné, ale neboli potvrdené.
- Prístupový token je krátkodobý JWT. Zaobchádzajte s ním ako s heslom: nevkladajte
  ho do repozitára, nezaznamenávajte ho do protokolov ani ho nezdieľajte.
- Obnovovací token poskytuje dlhodobý prístup k rozhraniu BizChat. Uchovávajte ho
  rovnako bezpečne ako kľúč API.

## Riešenie problémov

### Overenie zlyhá okamžite

- Skontrolujte, či ste skopírovali z **WebSocket URL**, nie z požiadavky XHR/Fetch. Poverenie sa nachádza v parametri dotazu `access_token` pripojenia Chathub WebSocket — nie v hlavičke `Authorization: Bearer`.
- Uistite sa, že `chathubPath` obsahuje celý segment `<oid>@<tenant>` z cesty URL.

### Platnosť tokenu vyprší po približne 75 minútach

Je to očakávané. Bez `refreshToken` má prístupový token krátku platnosť. Buď:

- Znova zachyťte poverenie z nástrojov DevTools, alebo
- V dialógovom okne na pridanie alebo úpravu pripojenia nakonfigurujte **Rozšírené nastavenia → Token obnovenia (voliteľné)** na automatické obnovenie.

### Test pripojenia prejde, ale chat vráti chybu 401

Platnosť tokenu mohla vypršať medzi overením a prvou požiadavkou. Znova zachyťte aktuálne poverenie.

### Copilot sa nezobrazuje v zozname poskytovateľov

Uistite sa, že `copilot-m365-web` je povolený v časti **Dashboard → Providers**. V niektorých úrovniach môže byť poskytovateľ predvolene skrytý.
