> **Накратко**: OmniRoute класира своите **безплатни** доставчици според качеството на моделите чрез **ELO оценки от Arena AI
> (в стила на LMArena)**. Отворете страницата **Класация на безплатните доставчици** в
> таблото, за да видите кои безплатни доставчици предлагат най-добрите модели за вашата задача —
> общо или филтрирани по категория (програмиране, преглед, документация, отстраняване на грешки).

---

## Какво представлява

OmniRoute регистрира 376 доставчика, включително 155 записа в каталога, обозначени като **безплатни/без удостоверяване**
(без удостоверяване,
OAuth с безплатен план или API ключ с безплатен план — вижте
[Ръководството за безплатните планове](../getting-started/FREE-TIERS-GUIDE.md) и пълната
[директория с безплатни планове](../reference/FREE_TIERS.md)). Уловката: безплатните доставчици се различават
значително по качество на моделите. Доставчик без удостоверяване, който предлага модел от най-ново поколение, е много по-полезен
от доставчик, който предлага малък остарял модел.

**Класацията на безплатните доставчици** отговаря на въпроса „**кой безплатен доставчик ми предоставя най-добрия модел?**“, като
свързва каталога на всеки безплатен доставчик с **колективно събрани оценки за качество** от
**класацията Arena AI** (ELO въз основа на човешки предпочитания — същата концепция, която стои зад
арената за чатботове LMArena). След това доставчиците се класират според възможностите на своя **най-добър безплатен модел**.

Класацията се изчислява въз основа на три реални източника:

1. Списъците с безплатни доставчици — `NOAUTH_PROVIDERS`, както и записите в `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS`, маркирани с `hasFree`
   (`src/shared/constants/providers.ts`).
2. Каталогът с модели на всеки доставчик от регистъра на доставчиците
   (`open-sse/config/providerRegistry.ts`).
3. Изведени от ELO оценки за пригодност към задачи, съхранявани в DB таблицата `model_intelligence` от
   механизма за синхронизиране на Arena ELO (`src/lib/arenaEloSync.ts`).

Логиката за свързване се намира в `src/lib/freeProviderRankings.ts`.

## Как да получите достъп

### Страница в таблото

Отворете таблото и отидете на **Разходи → Класация на безплатните доставчици** или преминете директно към:

```
/dashboard/free-provider-rankings
```

Страницата (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) показва:

- **Подиум с първите 3 места** (🥇 🥈 🥉) за най-високо класираните безплатни доставчици.
- Пълна **таблица с класирането** с колони: **Позиция**, **Доставчик**, **Най-добър модел**,
  **Оценка**, **Средна оценка**, **Модели**, **Тип**.
- **Бутони за филтриране по категория**: _Всички категории_, _По подразбиране_, _Програмиране_, _Преглед_,
  _Документация_, _Отстраняване на грешки_.

Значката **Тип** на всеки доставчик показва по какъв начин той е безплатен:

| Значка   | Значение                                                  |
| -------- | --------------------------------------------------------- |
| `NOAUTH` | Винаги безплатен, не са необходими идентификационни данни |
| `OAUTH`  | OAuth доставчик с безплатно ниво (`hasFree`)              |
| `APIKEY` | Доставчик с API ключ и безплатно ниво (`hasFree`)         |

Оценките се показват като разбираеми за хората етикети (напр. _Елитен_, _Отличен_, _Много добър_,
_Добър_, _Среден_), а не като необработени числа, защото базовата стойност представлява относителна
оценка на качеството в класацията, а не процент.

### API крайна точка

Страницата използва публична крайна точка за четене
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

Параметри на заявката (валидирани със Zod):

| Параметър  | Тип    | По подразбиране | Бележки                                                                                                                |
| ---------- | ------ | --------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `category` | string | (няма)          | Една от стойностите `default`, `coding`, `review`, `documentation`, `debugging`. Пропуснете за комбинираната класация. |
| `limit`    | number | `50`            | Ограничава се до диапазона `1–100`.                                                                                    |

Структура на отговора:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` е оригиналната ELO стойност от Arena; `score` е нормализираната стойност за пригодност към задачата
(вижте по-долу). Доставчиците без оценени модели не се включват в отговора.

## Как работят оценките

### Източник: класацията Arena AI

Модулът за синхронизация на Arena ELO (`src/lib/arenaEloSync.ts`) извлича две класации — `text`
и `code` — от API на класацията Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). Когато този API не върне
използваема класация, модулът преминава към официалния `lmarena-ai/leaderboard-dataset` в
datasets-server на Hugging Face (`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` докладва `activeSource`, `lastError` и
`lastFailedAt`. Всеки запис в класацията
съдържа име на модел, производител, ELO `score`, доверителен интервал и брой гласове.

Категориите от класацията се съпоставят с категориите задачи в OmniRoute:

| Класация Arena | Категории задачи в OmniRoute                      |
| -------------- | ------------------------------------------------- |
| `text`         | `default`, `review`, `documentation`, `debugging` |
| `code`         | `coding`                                          |

### Нормализация (оценка за съответствие към задачата)

Суровите ELO оценки се нормализират за всяка класация до **стойност за съответствие към задачата (task-fit) в `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

Оценката никога не достига `0` или `1`, което оставя пространство за потребителски корекции. Това е
полето `score`, което виждате в отговора на API, и етикетът, показван на таблото.

### Увереност

Всеки запис получава ниво на увереност според броя гласове в Arena:

| Увереност | Гласове |
| --------- | ------- |
| `high`    | ≥ 5,000 |
| `medium`  | ≥ 1,000 |
| `low`     | < 1,000 |

### Съхранение и актуалност

Нормализираните записи се записват в таблицата `model_intelligence` в базата данни със
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). Записите **изтичат след
7 дни**, така че доставчик, който спре да се синхронизира, в крайна сметка отпада, вместо да
обслужва остарели данни.

Синхронизацията е **включена по подразбиране**:

- Изпълнява се веднъж при стартиране на сървъра и след това по периодичен таймер
  (`src/lib/arenaEloSync.ts`, свързан от `src/instrumentation-node.ts`).
- Тя е **неблокираща и никога не е фатална** — ако изтеглянето от външния източник се провали,
  OmniRoute продължава да работи, а класиранията просто показват последните валидни данни
  (или празно състояние).

Две променливи на средата я управляват (документирани в
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| Променлива                | По подразбиране | Предназначение                                                  |
| ------------------------- | --------------- | --------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`          | Задайте `false`, за да се откажете от изходящата синхронизация. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24 ч)  | Интервал на синхронизация, в секунди.                           |

### Ръчна синхронизация / статус / изчистване

За операторите е налична удостоверена управленска крайна точка за ръчен контрол
(`src/app/api/intelligence/sync/route.ts` — изисква управленско удостоверяване):

```
GET    /api/intelligence/sync          # текущ статус на синхронизацията (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # задейства ръчна синхронизация; тяло: { "dryRun": true } за преглед без запис
DELETE /api/intelligence/sync          # изчиства всички синхронизирани записи с източник arena_elo
```

Ако страницата с класирания е празна, ръчна заявка `POST /api/intelligence/sync` (или просто
рестартиране на сървъра) я попълва отново.

### Съпоставяне на моделите с класацията

Идентификаторите на моделите в регистъра и имената на моделите в Arena не винаги съвпадат
точно. Класирането използва гъвкаво съпоставяне (`findMatchingIntelligence` в
`src/lib/freeProviderRankings.ts`):

1. Точно съвпадение по нормализирания идентификатор на модела.
2. Съвпадение след премахване на завършващ версиен суфикс (напр. `kimi-k2.6` → `kimi-k2`).
3. Съвпадение по префикс (името на модела от класацията е префикс на идентификатора в регистъра).

От страната на синхронизацията известните префикси на производители (`anthropic/`, `openai/`,
`google/`, …) се премахват, а малка таблица с псевдоними разширява каноничните имена до
вариантите, които OmniRoute използва вътрешно, така че моделите остават откриваеми под всяко име.

### Как се класира доставчик

За всеки безплатен доставчик модулът оценява всеки модел в каталога му, след което:

- **Топ модел** = моделът на доставчика с най-висока оценка.
- **Средна оценка** = средната оценка на всички оценени модели на този доставчик.
- **Модели** = колко от моделите на доставчика имат оценка в Arena.

Доставчиците се подреждат първо по **оценка на топ модела**, след това по средна оценка. Това
възнаграждава доставчик, който предлага поне един силен безплатен модел.

## Използване за избор на безплатни доставчици

1. **Изберете правилната категория.** Използвайте филтъра **Coding** за агентни задачи/задачи с код или
   оставете **All Categories** / **Default** за общ чат. Един и същ доставчик може да
   има различно класиране в отделните категории, тъй като водещият му модел се различава според класацията.
2. **Предпочитайте челната тройка за еднократни конфигурации.** Ако искате да свържете само един или два безплатни
   доставчика, започнете с най-високо класираните за вашата категория.
3. **Проверете значката Type.** Доставчиците с `NOAUTH` се свързват най-бързо (без
   идентификационни данни). Безплатните нива с `OAUTH` / `APIKEY` изискват бърза регистрация, но често предоставят
   по-мощни модели. Вижте [Ръководството за безплатните нива](../getting-started/FREE-TIERS-GUIDE.md) за
   стъпките за свързване.
4. **Свържете няколко доставчика и оставете Auto-Combo да избере.** Същите данни от Arena ELO, които захранват
   тази страница, се използват и за **коефициента за пригодност към задачата** на механизма за оценяване Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`, ред за определяне:
   `user_override → arena_elo → models_dev_tier → static table`). Следователно, след като свържете
   водещите безплатни доставчици, маршрутизирането с `model: "auto"` (напр. `auto/coding`) ще
   предпочита автоматично безплатните модели с по-високо качество за всяка заявка. Вижте
   [Auto-Combo](../routing/AUTO-COMBO.md) за пълното оценяване по 16 фактора.
