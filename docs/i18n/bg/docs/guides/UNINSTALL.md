## Възстановяване на конфигурацията на клиента

Програмата за деинсталиране спира OmniRoute процеса, управляван от PM2, ако има такъв, и оставя клиентската конфигурация на място. Клиентите, които все още сочат към OmniRoute губят връзката си, след като тя спре. Пълното премахване също така изтрива директорията с данни, `~/.omniroute` по подразбиране, заедно с резервните копия на конфигурацията на клиента.

### 1. Използвайте таблото за управление, докато OmniRoute работи

Отворете**CLI код** (`/dashboard/cli-code`) в таблото за управление и намерете**Claude код** карта.** Кандидатствайте** записва във файла с настройки на Claude кода на OmniRoute хоста, `~/.claude/settings.json` по подразбиране. Ако имате резервно копие от преди прилагането на настройките OmniRoute, отворете** Архивиране** и го възстановите. В противен случай изберете** Нулиране** за премахване на настройките на шлюза от `env`. Първо приложете и нулирайте архивирайте съществуващия файл. Резервните копия се съхраняват под `<DATA_DIR>/backups`.

Ако `CLI_ALLOW_CONFIG_WRITES=false` или таблото за управление не са достъпни, върнете файла на ръка. Ако OmniRoute работи в Docker и клиентът работи на хоста, върнете конфигурацията на хоста. Файловете в немонтиран начален контейнер нямат ефект върху хост клиента.

### 2. Върнете останалите промени на ръка

За Claude код проверете `~/.claude/settings.json`, `settings.json` в `CLAUDE_CONFIG_DIR`, ако е зададено, и `.claude/settings.json` на проекта. Reset премахва следните ключове от `env`. Премахнете стойностите, които сте добавили за OmniRoute, или възстановете предишните си стойности.

- `"ANTHROPIC_BASE_URL"`, `"ANTHROPIC_AUTH_TOKEN"` и `"ANTHROPIC_API_KEY"`
- `"ANTHROPIC_DEFAULT_OPUS_MODEL"`, `"ANTHROPIC_DEFAULT_SONNET_MODEL"` и `"ANTHROPIC_DEFAULT_HAIKU_MODEL"`
- `"API_TIMEOUT_MS"`

Reset оставя `ANTHROPIC_MODEL` в `env` и настройките на `model` и `apiKeyHelper` от най-високо ниво на място. Премахнете или възстановете тези на ръка, ако изберат OmniRoute модел или идентификационни данни. Спрете да използвате всеки OmniRoute профил, създаден от `omniroute setup-claude` под `~/.claude/profiles/<name>/`, или върнете неговия `settings.json`. Командата за настройка записва профила, без да променя файла с настройки по подразбиране или да записва токен. Премахнете или възстановете съвпадащите експорти във вашите стартиращи файлове на обвивката и изчистете старите стойности от текущата обвивка. `omniroute launch` и `omniroute run claude` задават шлюза URL и токена само за дъщерния процес.

За Codex възстановете предишния доставчик и модел в `~/.codex/config.toml`, ако съдържа `model_provider = "omniroute"`. Премахнете `[model_providers.omniroute]` ако е добавен за този шлюз. Възстановете или премахнете `openai_base_url`, ако сочи към OmniRoute. За клиенти, съвместими с OpenAI, възстановете или изчистете `OPENAI_BASE_URL` където и да го зададете за OmniRoute.

### 3. Проверете дали клиентът работи със спрян OmniRoute

Проверете настройките на Claude кода по подразбиране и текущата среда на обвивката.

```bash
grep -n ANTHROPIC ~/.claude/settings.json
env | grep ANTHROPIC
```

Нито една проверка не трябва да показва `ANTHROPIC_BASE_URL` сочеща към OmniRoute. Ако използвате профил или настройки на проект, проверете и тези файлове. След като OmniRoute е спрян и обичайното ви удостоверяване е възстановено, стартирайте Claude кода директно.

```bash
claude -p "say hello"
```

Claude кодът трябва да отговори, използвайки възстановената конфигурация. Ако все още сочи към спрения шлюз, заявката е неуспешна с грешка при свързване.

## Бързо деинсталиране (v3.6.2 +)

> Първо [върнете конфигурацията на клиента](#revert-client-configuration), докато OmniRoute все още работи.

OmniRoute предоставя два вградени скрипта за чисто премахване:

### Пазете данните си

```bash
npm run uninstall
```

Това премахва приложението OmniRoute но** консерви** вашата база данни, конфигурации, API ключове и настройки на доставчика в `~/.omniroute/`. Използвайте това, ако планирате да преинсталирате по-късно и искате да запазите настройката си.

### Пълно премахване

```bash
npm run uninstall:full
```

Това премахва приложението** и изтрива завинаги** всички данни:

- База данни (`storage.sqlite`)
- Конфигурации на доставчик и API ключове
- Архивиране на файлове
- Регистрационни файлове
- Всички файлове в директорията `~/.omniroute/`

> ⚠️** Предупреждение:** `npm run uninstall:full` е необратимо. Всички ваши връзки с доставчици, комбинации, API ключове и хронология на използването ще бъдат изтрити за постоянно.

## Ръчно деинсталиране

> Първо [върнете конфигурацията на клиента](#revert-client-configuration), докато OmniRoute все още работи.

### NPM Global Install

```bash
# Remove the global package
npm uninstall -g omniroute

# (Optional) Remove data directory
rm -rf ~/.omniroute
```

### pnpm Глобална инсталация

```bash
pnpm uninstall -g omniroute
rm -rf ~/.omniroute
```

### Docker

```bash
# Stop and remove the container
docker stop omniroute
docker rm omniroute

# Remove the volume (deletes all data)
docker volume rm omniroute-data

# (Optional) Remove the image
docker rmi cheaperinference/omniroute:latest
# Older installs pulled the legacy name:
docker rmi diegosouzapw/omniroute:latest
```

### Docker Съставяне

```bash
# Stop and remove containers
docker compose down

# Also remove volumes (deletes all data)
docker compose down -v
```

### Electron настолно приложение

**Windows:**

- Отворете `Settings → Apps → OmniRoute → Uninstall`
- Или стартирайте програмата за деинсталиране NSIS от инсталационната директория

**macOS:**

- Плъзнете `OmniRoute.app` от `/Applications` в кошчето
- Премахване на данни: `rm -rf ~/Library/Application Support/omniroute`

**Linux:**

- Премахнете AppImage файла
- Премахване на данни: `rm -rf ~/.omniroute`

### Инсталиране на източника (git клонинг)

```bash
# Remove the cloned directory
rm -rf /path/to/omniroute

# (Optional) Remove data directory
rm -rf ~/.omniroute
```

## Директории с данни

По подразбиране OmniRoute съхранява данни на следните места:

| Платформа      | Път по подразбиране           | Замяна                                  |
| -------------- | ----------------------------- | --------------------------------------- |
| Linux          | `~/.omniroute/`               | променлива на средата `DATA_DIR`        |
| macOS          | `~/.omniroute/`               | променлива на средата `DATA_DIR`        |
| Windows        | `%APPDATA%/omniroute/`        | променлива на средата `DATA_DIR`        |
| Docker         | `/app/data/` (монтиран том)   | променлива на средата `DATA_DIR`        |
| XDG-съвместима | `$XDG_CONFIG_HOME/omniroute/` | променлива на средата `XDG_CONFIG_HOME` |

### Файлове в директорията с данни

| Файл/директория      | Описание                                                        |
| -------------------- | --------------------------------------------------------------- |
| `storage.sqlite`     | Основна база данни (доставчици, комбинации, настройки, ключове) |
| `storage.sqlite-wal` | Журнал за предварителен запис на SQLite (временен)              |
| `storage.sqlite-shm` | Споделена памет на SQLite (временна)                            |
| `call_logs/`         | Архиви на съдържанието на заявките                              |
| `backups/`           | Автоматични резервни копия на базата данни                      |
| `log.txt`            | Остарял регистър на заявките (незадължителен)                   |

## Проверка за пълно премахване

След деинсталирането проверете дали няма останали файлове:

```bash
# Проверка за глобален npm пакет
npm list -g omniroute 2>/dev/null

# Проверка за директорията с данни
ls -la ~/.omniroute/ 2>/dev/null

# Проверка за работещи процеси
pgrep -f omniroute
```

Ако някой процес все още работи, спрете го:

```bash
pkill -f omniroute
```
