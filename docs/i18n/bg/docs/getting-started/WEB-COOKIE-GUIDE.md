Доставчиците с уеб бисквитки позволяват на OmniRoute да използва услуга с изкуствен интелект чрез съществуващата ви сесия в браузъра вместо чрез API ключ. Те са полезни, когато вече имате достъп до дадена услуга чрез нейния уебсайт и искате OmniRoute да използва същата удостоверена сесия.

За разлика от доставчиците с API ключове, доставчиците с уеб бисквитки извършват удостоверяване чрез идентификационните данни, които браузърът ви изпраща към уебсайта.

---

# Преди да започнете

> **Важно:** Винаги копирайте идентификационните данни от **активна мрежова заявка**, а **не** от хранилището за бисквитки на браузъра.

Много проблеми с удостоверяването възникват поради копиране на бисквитки от неправилното място.

## НЕ копирайте от хранилището за бисквитки

Повечето браузъри показват съхранените бисквитки чрез:

```
DevTools
→ Приложение (или Хранилище)
→ Бисквитки
```

Въпреки че тези бисквитки изглеждат правилни, те може да са:

- остарели
- непълни
- без бисквитки, които се изпращат само при удостоверени заявки

Използването на тези стойности може да доведе до неуспешно удостоверяване дори ако изглеждат валидни.

## Копирайте от активна заявка

Вместо това използвайте бисквитките от успешна заявка:

```
DevTools
→ Мрежа
→ Обновете страницата
→ Отворете заявка за чат или разговор
→ Заглавки на заявката
→ Cookie
```

Заглавката `Cookie` на заявката съдържа точната информация за удостоверяване, която браузърът ви е използвал успешно.

За повечето доставчици с уеб бисквитки това е стойността, която трябва да бъде поставена в OmniRoute.

# Обща настройка

Процесът на настройване е еднакъв за повечето доставчици с уеб бисквитки.

1. Влезте в уебсайта на доставчика.
2. Отворете инструментите за разработчици на браузъра.
3. Отворете раздела **Мрежа**.
4. Обновете страницата.
5. Отворете удостоверена заявка за чат или разговор.
6. Копирайте необходимите идентификационни данни за удостоверяване.
7. Отворете OmniRoute.
8. Отидете на **Доставчици → Добавяне на доставчик**.
9. Изберете своя доставчик с уеб бисквитки.
10. Поставете идентификационните данни.
11. Щракнете върху **Тестване на връзката**.
12. Запазете доставчика.

Точните необходими идентификационни данни зависят от доставчика.

# Формати на идентификационните данни на доставчиците

Различните уебсайтове съхраняват данните за удостоверяване по различен начин. Някои изискват само бисквитки, докато други може да изискват допълнителни заглавки или токени.

| Доставчик                       | Формат на идентификационните данни | Ръководство за доставчика        |
| ------------------------------- | ---------------------------------- | -------------------------------- |
| Claude Web                      | Пълна заглавка Cookie на заявката  | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | Пълна заглавка Cookie              | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(за проверка)_                    |                                  |
| Copilot Web                     | _(за проверка)_                    | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath      | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(за проверка)_                    |                                  |
| ...                             | ...                                | ...                              |

> Актуализирайте тази таблица при добавянето на нови доставчици с уеб бисквитки или при промяна на изискванията за удостоверяване на съществуващите доставчици.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) е безплатна потребителска чат платформа, която не изисква регистрация — сесията се създава анонимно при първото посещение и се запазва чрез три бисквитки: `uid`, `si_usr_id` и `si_ses_id`. OmniRoute препраща същата крайна точка `/api/dispatch` чрез един идентификатор на модел (`notrack-c`, псевдоним `ntw`).

### Стъпки за свързване

1. Отворете [notrack.ai](https://notrack.ai) в браузъра си и изчакайте да бъде зададена бисквитката за анонимна сесия.
2. Отворете **Инструменти за разработчици → Мрежа**, обновете страницата и щракнете върху която и да е заявка към `/api`.
3. В **Заглавки на заявката** копирайте пълната стойност на заглавката `Cookie`.
4. В OmniRoute отидете на **Доставчици → Добавяне на доставчик → NoTrack Web (безплатно)**.
5. Поставете низа с бисквитките в полето `apiKey` и изберете **Запазване**.

OmniRoute извлича `uid`, `si_usr_id` и `si_ses_id` от поставения низ и изгражда наново изчистена заглавка `Cookie`, съдържаща само тези двойки — както и `nt_session` (токена `ntk_…`, задаван за влезли в профил потребители), когато присъства. Ако някоя от трите липсва, необработеният поставен низ се препраща непроменен, така че операторите да могат да експериментират с алтернативни формати.

### Идентификатори на модели

| Идентификатор на модел | Показвано име | Бележки                                                                |
| ---------------------- | ------------- | ---------------------------------------------------------------------- |
| `notrack-c`            | NoTrack C     | По подразбиране — моделът за диспечиране `C` на отсрещната услуга.     |
| `C`                    | NoTrack C     | Псевдоним на `notrack-c` (необработен код за диспечиране на услугата). |
| `notrack`              | NoTrack C     | Псевдоним на `notrack-c`.                                              |
| `ntw`                  | NoTrack C     | Кратък псевдоним на `notrack-c`.                                       |

И четирите идентификатора на модели сочат към един и същ модел за диспечиране на отсрещната услуга (`C`).

### Опции на заявката

Изпълнителят приема следните незадължителни полета в тялото на заявката:

| Поле в тялото         | По подразбиране | Предназначение                                                                      |
| --------------------- | --------------- | ----------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`         | Режим на диспечиране (низ със свободен формат; отсрещната услуга приема `usual`, …) |
| `notrack_max_turns`   | `6`             | Брой вътрешни стъпки, които отсрещната услуга може да изпълни, преди да отговори.   |
| `notrack_chat_id`     | `null`          | Продължаване на съществуващ чат в отсрещната услуга (пропуснете за нов чат).        |
| `notrack_attachments` | `[]`            | Масив за директно предаване на дескриптори на прикачени файлове към услугата.       |
| `notrack_regenerate`  | `false`         | Задайте `true`, за да поискате повторно генериран отговор за предишната стъпка.     |

### Възможности

- **Поточно и непоточно** генериране на отговори в чат.
- **Извикване на инструменти** — задайте `tools: [...]` в заявката; изпълнителят ги сериализира според договор за обвивка на извикванията на инструменти и анализира отговорите на модела обратно във формат OpenAI `tool_calls`.
- **`response_format`** — поддържат се `json_object` и `json_schema`. Изпълнителят извлича първия JSON обект от отговора на модела и го преобразува в низ, преди да го върне.
- **Подсказка за разсъждение** — изпълнителят подава делта `reasoning`, когато отсрещната услуга изпрати събитие `thinking`.

### Ограничения

- Отсрещната услуга налага квоти за анонимно използване — когато те бъдат достигнати, изпълнителят връща грешка 429 с разбираемо съобщение.
- Всички идентификатори на модели сочат към един и същ модел за диспечиране на отсрещната услуга; няма превключване за отделните модели.
- Изпълнителят не извиква крайната точка `/api/chats` на отсрещната услуга, затова историята на чатовете и сесиите не се управляват автоматично. Използвайте `notrack_chat_id`, за да продължите съществуващ чат в отсрещната услуга.

# Какво могат и какво не могат доставчиците с уеб бисквитки

Доставчиците с уеб бисквитки използват повторно чат интерфейса на даден уебсайт. Те **не** предоставят същите възможности като официалните API интерфейси.

## Поддържа се

- Удостоверяване чрез съществуващата ви сесия в браузъра
- Достъп до моделите, налични чрез вашия акаунт
- Поточно предаване на отговорите в чата
- Не се изисква API ключ

## Не се поддържа

- Извикване на функции
- Извикване на инструменти
- Автоматично редактиране на файлове
- Агентни работни процеси в IDE
- Функции, достъпни само чрез API

Това е очаквано поведение и **не** е грешка.

Ако се нуждаете от изпълнение на инструменти, автоматично редактиране на файлове или други агентни работни процеси, използвайте **доставчик с API ключ** вместо доставчик с Web Cookie.

# Уточнение относно валидирането

Успешната **проверка на връзката** или валидирането на бисквитките само потвърждава, че предоставените идентификационни данни изглеждат в очаквания формат.

Докато проблем №7857 не бъде разрешен, успешното валидиране **не гарантира**, че доставчикът ще се удостовери успешно.

Ако удостоверяването все още е неуспешно, проверете дали сте копирали идентификационните данни от активна мрежова заявка, а не от хранилището за бисквитки на браузъра.

---

# Отстраняване на проблеми

## Удостоверяването е неуспешно

Проверете дали идентификационните данни са копирани от:

```
Network
→ Request Headers
→ Cookie
```

а **не** от:

```
Application
→ Cookies
```

---

## Бисквитката работи в браузъра, но не и в OmniRoute

Някои доставчици включват бисквитки, които се изпращат само по време на удостоверени заявки.

Копирайте отново идентификационните данни от нова мрежова заявка, след като успешно отворите разговор.

---

## Сесията е изтекла

Доставчиците с Web Cookie използват съществуващата ви сесия в браузъра.

Ако сесията в браузъра ви изтече или излезете от профила си, трябва да копирате нов набор от идентификационни данни. За да автоматизирате подновяването на бисквитките за поддържаните уеб доставчици, вижте допълващия инструмент [Разширение за синхронизиране на сесията на браузъра](../guides/SESSION-SYNC-EXTENSION.md).

---

## Проверката на връзката е успешна, но заявките са неуспешни

Докато проблем №7857 не бъде разрешен, успешното валидиране не гарантира, че заявката за удостоверяване ще бъде успешна.

Копирайте отново идентификационните си данни от нова удостоверена заявка, преди да продължите с отстраняването на проблема.

---

## ChatGPT Web е неуспешен с "Unsupported ChatGPT integrity dependency"

```
[502] ChatGPT Web first-party bridge module failed to load:
pageerror: Unsupported ChatGPT integrity dependency: DD
```

Идентификационните данни са наред — тази грешка идва от моста, а не от сесията. chatgpt.com задава своите
идентификатори на модули при всяко внедряване, а мостът преди фиксираше идентификатора на помощния компонент Sentinel, който създава, така че
повторно изграждане на chatgpt.com, което преименува помощния компонент, прекъсваше всяка заявка, докато бисквитката оставаше валидна. Повторното упълномощаване
на връзката не може да реши проблема.

Версиите, които намират модула чрез собствената среда за изпълнение на страницата, не фиксират идентификатор и не се сблъскват с този проблем. Ако видите
грешката, надстройте OmniRoute и изпълнете отново проверката на връзката.

# Добри практики

- Копирайте идентификационните данни от нова удостоверена заявка.
- Избягвайте повторното използване на стари бисквитки.
- Поддържайте сесията в браузъра си активна, докато използвате доставчици с Web Cookie.
- Третирайте копираните бисквитки като чувствителни идентификационни данни.
- Използвайте доставчици с API ключ, когато се нуждаете от извикване на функции или агентни работни процеси.
