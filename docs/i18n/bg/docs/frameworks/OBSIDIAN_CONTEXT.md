## Какво представлява

OmniRoute се свързва с хранилище на **Obsidian** като **източник на контекст** — локална
база от знания в Markdown, която агентите четат и променят чрез вградения MCP сървър.
Интеграцията комуникира с общностната добавка **Obsidian Local REST API**, работеща в
настолното приложение, така че агентите могат да търсят бележки, да четат/записват/актуализират
файлове, да извеждат съдържанието на хранилището, да работят с ежедневни/седмични периодични
бележки, да управляват етикети, да изпълняват команди на Obsidian и (по избор) да
координират двупосочна синхронизация на хранилището между настолно и мобилно устройство.

Клиентът (`src/lib/obsidian/api.ts`) обвива Local REST API със:

- **Повторни опити с изчакване** при временни грешки `5xx`, **30-секундно прекъсване**
  чрез `AbortController`.
- **Типизирано класифициране на грешките** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- **Разбираемо указание „Obsidian не може да бъде достигнат“**, което посочва често срещаната
  грешка с порта (HTTP на `27123`, **а не** MCP крайната точка на `27124`) и формата за Tailscale.
- **Кодиране на пътищата** спрямо хранилището, така че пътищата до бележки с интервали/наклонени
  черти да бъдат безопасни.

## Настройка

Няма **променлива на средата** за токена или базовия URL адрес на Obsidian — и двете се
съхраняват в SQLite таблицата `key_value` (пространство от имена `obsidian`) чрез
`src/lib/db/obsidian.ts`. Токенът е **криптиран при съхранение** (AES-256-GCM, с
резервен режим за обратна съвместимост с некриптиран текст). Конфигурирайте от раздела
**Източници на контекст** на таблото за управление на Endpoint (`ObsidianSourceCard`)
или чрез REST API за настройки.

> [!IMPORTANT]
> Плъгинът **Obsidian Local REST API** трябва да е инсталиран и да работи. Неговият REST
> интерфейс слуша на **HTTP `127.0.0.1:27123`** (базовият URL адрес по подразбиране). Порт `27124`
> е _отделна_ MCP/HTTPS крайна точка и изрично се отхвърля от маршрута за настройки.
> Ако се свързвате от друго устройство, използвайте `http://<tailscale-ip>:27123`.

### Конфигурационни ключове (SQLite `key_value`, пространство от имена `obsidian`)

| Ключ              | Предназначение                                                      | Криптиран |
| ----------------- | ------------------------------------------------------------------- | --------- |
| `api_key`         | Bearer токен за Local REST API                                      | да        |
| `base_url`        | Базов REST URL адрес (по подразбиране `http://127.0.0.1:27123`)     | не        |
| `vault_path`      | Абсолютен път до директорията на хранилището (за синхронизиране)    | не        |
| `webdav_username` | Генерирано WebDAV потребителско име (синхронизиране на хранилището) | не        |
| `webdav_password` | Генерирана WebDAV парола (синхронизиране на хранилището)            | да        |
| `webdav_enabled`  | Дали WebDAV синхронизирането на хранилището е активирано            | не        |

### Конфигуриране чрез REST

```bash
# Запазване и валидиране на токена за Local REST API (POST валидира чрез проверка на състоянието)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Проверка на състоянието на връзката (връща connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Прекъсване на връзката (изчиства съхранения токен)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Всички методи изискват удостоверяване за таблото за управление. `POST` отхвърля всеки URL адрес на порт `27124`
и валидира токена чрез извикване на крайната точка за състояние на Local REST API, преди да го съхрани.

### WebDAV синхронизиране на хранилището

`src/app/api/settings/obsidian/webdav/route.ts` управлява незадължително синхронизиране
на хранилището чрез WebDAV (задвижвано от `src/lib/obsidianSync.ts`). Активирането му насочва OmniRoute към
локална директория на хранилище и генерира произволна двойка WebDAV потребителско име/парола:

```bash
# Активиране на WebDAV синхронизирането за директория на хранилище (генерира потребителско име/парола)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Получаване на състоянието на WebDAV синхронизирането (идентификационните данни се връщат само докато е активирано)
curl http://localhost:20128/api/settings/obsidian/webdav

# Деактивиране на WebDAV синхронизирането (изчиства идентификационните данни + управлявания .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Сигурност и транспорт

WebDAV автентификацията налага проследяване и блокиране на грешки за IP адрес (10 неуспешни опита в рамките на 60-секунден прозорец задействат 5-минутно блокиране с `429 Too Many Requests` и `Retry-After`). Тъй като WebDAV предава идентификационни данни за базово удостоверяване, силно се препоръчва прекратяване на TLS (или маршрутизиране през защитен тунел като Tailscale или Cloudflare Tunnel) при достъп до WebDAV крайната точка извън loopback.

### Източник на контекст за отделен API ключ (незадължително)

Конфигурацията на Obsidian може да бъде зададена **за всеки API ключ поотделно** чрез таблицата
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Когато MCP извикване съдържа идентификатор
на удостоверен API ключ, `getObsidianConfigForApiKey()` предпочита собствения токен/базов URL адрес/път до хранилището
на този ключ (`source: "api_key"`), а в противен случай използва глобалната конфигурация (`source: "global"`).

MCP инструментите, които не са за синхронизиране, изискват определена самоличност на извикващия, преди да прочетат тази конфигурация.
Извикващ без самоличност получава `Obsidian API token not configured` и не се изпраща заявка към хранилището.
HTTP извикващите се идентифицират чрез идентификационните данни в заявката си; извикващите чрез stdio
могат да се идентифицират чрез `OMNIROUTE_API_KEY` или `ROUTER_API_KEY`. Неидентифициран HTTP извикващ
не може да наследи самоличността от средата на сървъра. Самостоятелните идентификатори заместители не разрешават
достъп; валидни идентификационни данни от средата, които се разрешават до `env-key`, продължават да се поддържат.
Удостоверените ключове без индивидуална конфигурация на Obsidian запазват резервното използване на глобалната конфигурация.
Четирите инструмента `obsidian_sync_*` запазват отделното си поведение за токени за синхронизиране.

## MCP инструменти (22)

Дефинирано в `open-sse/mcp-server/tools/obsidianTools.ts`. token/base-URL се разрешават на повикване (първо за ключ на API, след това глобално). Инструменти, които удрят OmniRoute** синхронизиращ сървър** (четирите `obsidian_sync_*` инструмента) допълнително изискват токен за удостоверяване на синхронизиране, конфигуриран в настройките OmniRoute.

### Инструменти за четене (`read:obsidian`)

| Инструмент                   | Описание                                                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Проверете дали локалният REST API е достъпен и удостоверен.                                                                |
| `obsidian_search_simple`     | Пълнотекстово търсене на съдържанието на бележката; връща фрагменти с файлови пътища.                                      |
| `obsidian_search_structured` | Търсете с помощта на JSON логически израз (and/or/regex/path филтри).                                                      |
| `obsidian_read_note`         | Прочетете бележка по път, относителен към трезора; по избор специфичен heading/block/frontmatter.                          |
| `obsidian_list_vault`        | Списък на файлове и директории в трезора (дърво на записи).                                                                |
| `obsidian_get_document_map`  | Вземете структурата на заглавията на бележката като карта на заглавията → номерата на редовете.                            |
| `obsidian_get_note_metadata` | Вземете frontmatter, етикети, връзки, брой char/word без пълното съдържание.                                               |
| `obsidian_get_active_file`   | Вземете съдържанието на пътя + на текущия активен файл в Obsidian.                                                         |
| `obsidian_get_periodic_note` | Вземете периодичната бележка daily/weekly/monthly за дата (днес, ако е пропусната).                                        |
| `obsidian_get_tags`          | Избройте всички тагове на трезора с техните честоти.                                                                       |
| `obsidian_list_commands`     | Избройте наличната команда Obsidian IDs (използвайте с `obsidian_execute_command`).                                        |
| `obsidian_sync_status`       | състояние на сървъра за синхронизиране OmniRoute : работи, име на трезора, порт, време на работа, последно синхронизиране. |
| `obsidian_sync_conflicts`    | Избройте неразрешените конфликти при синхронизиране (път, път на конфликт, открит-при).                                    |

### Инструменти за писане (`write:obsidian`)

| Инструмент                       | Описание                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `obsidian_write_note`            | Създайте или презапишете бележка с дадено съдържание на Markdown.                                      |
| `obsidian_append_note`           | Добавяне на съдържание към бележка; по избор към конкретен heading/block.                              |
| `obsidian_patch_note`            | Хирургично append/prepend/replace в поле на заглавие, блок или предна материя.                         |
| `obsidian_delete_note`           | Изтриване за постоянно на бележка от трезора.                                                          |
| `obsidian_move_note`             | Преместете или преименувайте бележка в трезора.                                                        |
| `obsidian_execute_command`       | Изпълнете Obsidian команда чрез нейната команда ID.                                                    |
| `obsidian_open_file`             | Отворете файл в Obsidian (създава го, ако не съществува).                                              |
| `obsidian_sync_trigger`          | Задействайте незабавно двупосочно десктоп ↔ мобилно синхронизиране на трезора.                         |
| `obsidian_sync_resolve_conflict` | Разрешете конфликт при синхронизиране: запазете `local` (мобилен), `remote` (десктоп) или `keep-both`. |

> [!NOTE]
> `obsidian_patch_note` целите приемат `targetType` от `heading | block | frontmatter` и `operation` от `append | prepend | replace`, с незадължителен `createTargetIfMissing`. Четирите `obsidian_sync_*` инструмента общуват с локалния сървър за синхронизиране (`http://127.0.0.1:27781` по подразбиране) и изискват токена за синхронизиране.

### Обхвати

Инструментите за четене изискват `read:obsidian`; инструментите за писане изискват `write:obsidian`. Изпълнението е идентично на Notion — обработвано от `withScopeEnforcement()` в `open-sse/mcp-server/server.ts`, затворено на `OMNIROUTE_MCP_ENFORCE_SCOPES=true` и принудително включено за HTTP/SSE повикващите, чийто API ключ липсва `manage`/`admin`, с разрешени обхвати, произхождащи от `OMNIROUTE_MCP_SCOPES` или контекста на обхвата на ключа API. Вижте [MCP-SERVER.md](./MCP-SERVER.md).

## Крайни точки

| Метод    | Път                             | Предназначение                                                                       |
| -------- | ------------------------------- | ------------------------------------------------------------------------------------ |
| `GET`    | `/api/settings/obsidian`        | Връща `{ connected, hasToken, baseUrl, vaultPath }`.                                 |
| `POST`   | `/api/settings/obsidian`        | Запазва и валидира токена (отхвърля порт `27124`).                                   |
| `DELETE` | `/api/settings/obsidian`        | Прекъсва връзката (изчиства съхранения токен).                                       |
| `GET`    | `/api/settings/obsidian/webdav` | Състояние на WebDAV синхронизирането и идентификационни данни (докато е активирано). |
| `POST`   | `/api/settings/obsidian/webdav` | Активира WebDAV синхронизиране за директория на хранилище.                           |
| `DELETE` | `/api/settings/obsidian/webdav` | Деактивира WebDAV синхронизирането.                                                  |

> Това са маршрути за настройки на таблото за управление. Самото хранилище е достъпно чрез Obsidian
> Local REST API (конфигурирания `base_url`) и чрез MCP инструментите по-горе — няма
> публична Obsidian прокси крайна точка `/v1`.

## Случаи на употреба

- **Отговори, базирани на хранилището** — `obsidian_search_simple` / `obsidian_search_structured`,
  следвани от `obsidian_read_note`, така че агентът да отговаря въз основа на действителните ви бележки.
- **Създаване на бележки / водене на дневник** — `obsidian_write_note`, `obsidian_append_note` или
  прецизният `obsidian_patch_note` за записване на изходни данни от агента, обобщения или ежедневни бележки
  (`obsidian_get_periodic_note`) в хранилището.
- **Навигация в хранилището** — `obsidian_list_vault`, `obsidian_get_document_map` и
  `obsidian_get_tags` за проучване на структурата преди четене/писане.
- **Автоматизация на Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` за
  управление на приставки/команди чрез агент; `obsidian_open_file` за показване на бележка в потребителския интерфейс.
- **Мобилно синхронизиране** — активирайте WebDAV синхронизирането, след което използвайте `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`,
  за да координирате настолен компютър↔мобилно устройство и да разрешавате конфликти.
