> Превключватели по време на изпълнение, които променят поведението на OmniRoute **без повторно внедряване**.
> Всеки флаг, посочен тук, е дефиниран във
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — единствения източник на достоверна информация. Както таблото за управление, така и REST API четат от
> този файл, затова таблицата по-долу е генерирана така, че да съответства на съдържанието му 1:1.

---

## Какво представляват флаговете за функции

Флагът за функция е именуван превключвател (булев или изброим), чиято стойност може да бъде променяна по
време на изпълнение и съхранявана в базата данни, без да е необходимо повторно внедряване на процеса. Всеки
флаг е описан чрез `FeatureFlagDefinition` с `key`, `label`,
`description`, `category`, `defaultValue`, `type` и указание `requiresRestart`.

### Ред на определяне

**Ефективната стойност** на даден флаг се определя чрез
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) със следния
приоритет (по-високият има предимство):

1. **Замяна от БД** — стойност, съхранена в таблицата `key_value` в пространството от имена
   `feature_flags` (зададена чрез таблото за управление или REST API).
2. **Променлива на средата** — `process.env[<KEY>]`, ако е зададена и не е празна.
3. **Стойност по подразбиране от дефиницията** — `defaultValue` от `featureFlagDefinitions.ts`.

Булев флаг се счита за **активиран**, когато ефективната му стойност е `"true"`,
`"1"` или `"yes"` (вижте `isFeatureFlagEnabled()`).

> [!NOTE]
> Повечето флагове имат и съответстваща променлива на средата със **същото име**,
> документирана в [`ENVIRONMENT.md`](./ENVIRONMENT.md). Замяната от БД на флага
> има предимство пред тази променлива на средата. Флаг с
> `requiresRestart: true` се съхранява незабавно, но се прочита отново едва при стартиране на процеса
> — превключването му показва банер **„Рестартиране на сървъра“** в таблото за управление.

околната среда), тя има предимство пред `USAGE_LIMIT_IGNORE_UNPRICED`. Ако няма изрично зададена
стойност на enum, булевата настройка за отказ от по-горното ниво избира `count_as_zero`; в противен
случай стойността по подразбиране е `fail_closed`. Невалидните стойности на enum и недостъпното хранилище
за feature flags водят до отказ по подразбиране. Нито една от настройките за отказ не облекчава
ограничението за таксувани разходи или неуспешното търсене на ценообразуване. Прилагането и отчетът
за администратора определят една и съща ефективна политика.

## Превключване на флагове

### Табло

Отидете на **Табло → Настройки → Функционални флагове**
(`/dashboard/settings/feature-flags`). Решетката
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
поддържа:

- **Търсене** по ключ или описание и **филтриране** по категория (плюс синтетичен изглед **Изисква рестартиране**).
- **Превключвател** за булеви флагове и **падащо меню** за enum флагове
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- **Значка за източника** за всеки флаг — `DB`, `ENV` или `DEF` — показваща откъде идва ефективната стойност.
- Бутон **Нулиране** (показва се само за флагове с източник `DB`) за премахване на заместването и бутон **Нулиране на всички замествания** в долната част.
- Банер **Рестартиране на сървъра**, когато бъде променен флаг `requiresRestart`.

### REST API

Всички операции преминават през един маршрут:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Всеки метод изисква удостоверена сесия на таблото (`401` в противен случай).

#### `GET /api/settings/feature-flags`

Връща всеки флаг с ефективната му стойност, източника и обобщение.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... всички 115 флага
  ],
  "summary": {
    "total": 115,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Задава или премахва едно заместване. Тяло: `{ key: string; value?: string }`.
Пропускането на `value` премахва заместването (възстановявайки env / стойността по подразбиране).

```bash
# Задаване на заместване в DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Премахване на заместването (без "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Отговорът повтаря новите `effectiveValue`/`source`, `previousValue`/
`previousSource` и `requiresRestart`. Непознати ключове и enum стойности
извън допустимия диапазон се отхвърлят с `400`.

#### `DELETE /api/settings/feature-flags`

Изчиства **всички** замествания в DB едновременно, като възстановява всеки флаг до неговата env / стойност по подразбиране. Връща `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Флаговете с `requiresRestart: true` влизат в сила едва след презареждане на процеса.
> Потокът за рестартиране на таблото извиква `POST /api/restart` и след това извършва периодични заявки към
> `GET /api/health/ping`, докато сървърът отново заработи.

## Авариен резервен режим при изчерпан бюджет

`OMNIROUTE_EMERGENCY_FALLBACK` (категория `runtime`, стойност по подразбиране `true`) управлява
аварийния безплатен резервен механизъм в
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Когато е активиран, заявките, които изчерпят бюджета си, се насочват към безплатен резервен
доставчик/модел, вместо да завършат директно с неуспех. Задайте го на `false` (или `0`) — чрез
превключвателя в таблото за управление, заместваща настройка в БД или променливата на средата
`OMNIROUTE_EMERGENCY_FALLBACK` — за да деактивирате това поведение и да позволите на заявките
с изчерпан бюджет да завършат с неуспех. (Представено като превключвател в таблото за управление в PR-и #3741 / #3752.)

Отговор, обслужен чрез този резервен механизъм, съдържа
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, така че
клиентът може да установи, че заявката е била пренасочена, без да сравнява `X-OmniRoute-Provider` със своята
заявка. Заглавката липсва във всеки друг отговор.
