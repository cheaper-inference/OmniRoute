OmniRoute ले npm + Docker आर्टिफ्याक्टहरू प्रकाशित गर्दछ। यी गेटहरूले प्रोभेनान्स, इन्भेन्टरी (SBOM) र CVE स्क्यानिङ प्रदान गर्दछ, सबै OSS हुन्, र रिलिज वर्कफ्लोहरूमा प्लग गरिएका छन्। **परामर्श-पहिलो** दृष्टिकोण — तिनीहरूले अहिले रिपोर्ट गर्छन्, पहिलो सफल रिलिज पछि ब्लक गर्न प्रमोट गर्छन्।

| गेट                   | उपकरण                                          | कहाँ                          | ब्लक गर्छ?              | आउटपुट                                          |
| --------------------- | ---------------------------------------------- | ----------------------------- | ----------------------- | ----------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | प्रकाशन असफल भएमा मात्र | badge npmjs / `npm audit signatures`            |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | उत्पादन असफल भएमा मात्र | Release asset + artifact                        |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | सल्लाहकार               | CycloneDX artifact                              |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | सल्लाहकार               | SARIF (HIGH+CRITICAL) → Security tab            |
| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **ब्लक गर्ने**          | `exit-code: '1'` on fixable CRITICAL            |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ब्लक गर्ने**          | `metrics.vulnCount` लाई र्याचेट गर्छ (दिशा: तल) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | सल्लाहकार               | SARIF → Security + badge                        |

इमेज CVE र्याचेटले `docker-publish.yml` मा **दुई चरणहरू** प्रयोग गर्दछ: SARIF चरण (`HIGH,CRITICAL`, `exit-code: 0`) ले HIGH+CRITICAL लाई सुरक्षा ट्याबमा ब्लक नगरी देखिने राख्छ; _CRITICAL गेट_ चरण (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) ले **उपलब्ध समाधान सहितको** CRITICAL CVE मा रिलिज असफल बनाउँछ। `ignore-unfixed` ले अपस्ट्रिम प्याच नभएको बेस-इमेज CVE को लागि रिलिज ब्लक हुनबाट रोक्छ।

## ⚠️ CVE भिन्नता (osv/Trivy गेटहरू ब्लक गर्दै)

osv र Trivy ले **निरन्तर बढ्दै जाने** CVE डेटाबेसहरू विरुद्ध deps तुलना गर्छन्। **कुनै पनि निर्भरता नछुने** PR अचानक रातो हुन सक्छ किनभने अवस्थित dep मा नयाँ CVE खुलासा भयो (osv: मापन गरिएको `vulnCount` > बेसलाइन; Trivy: इमेजमा नयाँ समाधान गर्न सकिने CRITICAL)। **यो ब्लक गर्ने CVE गेटको अपेक्षित परिचालन व्यवहार हो, उत्पादन प्रतिगमन होइन।**

जब osv वा Trivy नयाँ खुलासा भएको CVE को कारण रातो हुन्छन्, यसको समाधान हो:

1.  **प्रभावित dep लाई बम्प गर्नुहोस्** (रुचाइएको) — `package.json` `overrides` (ट्रान्जिटिभ deps) मार्फत प्याच गरिएको संस्करणमा अपग्रेड गर्नुहोस् वा प्याच गरिएको आधारमा इमेज पुन: निर्माण गर्नुहोस्।
2.  **यदि कुनै अपस्ट्रिम समाधान छैन भने:**
    - **osv:** `config/quality/quality-baseline.json` मा `metrics.vulnCount` लाई पुन: बेसलाइन गर्नुहोस् (`npm run quality:ratchet -- --update` ले समर्पित गेटहरू कभर गर्दैन — मानलाई हातले सम्पादन गर्नुहोस्, `direction:down`) औचित्य नोट + ट्र्याकिङ मुद्दा सहित।
    - **Trivy:** `.trivyignore` मा एउटा प्रविष्टि थप्नुहोस् (प्रति लाइन CVE-ID) औचित्य टिप्पणी + ट्र्याकिङ मुद्दा सहित। `ignore-unfixed: true` ले प्याच नभएका CVE हरूलाई स्वचालित रूपमा कभर गर्दछ।

दुवै गेटहरूले उपकरण अनुपस्थित हुँदा वा मापन असफल हुँदा (PATH मा osv-scanner छैन, osv.dev/network पहुँचयोग्य छैन, अवैध JSON) **सुरुचिपूर्ण रूपमा SKIP** (exit 0) गर्छन् — एक **मापन** विफलताले कहिल्यै ब्लक गर्दैन, केवल एक **मापन गरिएको** प्रतिगमनले ब्लक गर्छ।

## हटाइएको निर्भरताको जोखिम

पिन गरिएको promptfoo विकास उपकरण अपग्रेड गरेपछि मूल lockfile मा अब `extract-zip`
वा त्यसतर्फ जाने निर्भरता किनारा समावेश छैन। यसले #14482 मा ट्र्याक गरिएको पहिले स्वीकार्य
`promptfoo` → `@openai/codex-security` → `extract-zip` शृङ्खलालाई हटाउँछ।
`tests/unit/extract-zip-14482-exposure.test.ts` मा भएका रिग्रेसन जाँचहरूले यसको
पुनः समावेशलाई अस्वीकार गर्छन् र उत्पादन कोडबाट import गर्न नपाइने नियम कायम राख्छन्।

हालको निर्भरता सुधारले अनुकूलता override हरूलाई Azure identity को
MSAL client, get-uri को FTP client, र OpenCode v1 SDK को Zod निर्भरतामा पनि सीमित गर्छ। Azure token
प्राप्ति र FTP पुनर्प्राप्तिलाई नियन्त्रित transport हरूसँग परीक्षण गरिएको छ; दुवै OpenCode
package ले आफ्नै build र test suite चलाउँछन्। Registry advisory का सङ्ख्याहरू
निश्चित समयबिन्दुका मापन हुन् र lockfile commit गरिएपछि परिवर्तन हुन सक्छन्।
