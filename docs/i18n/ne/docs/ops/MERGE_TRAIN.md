## रिलीज शाखामा अवतरण

ओम्नी-क्युले `release/vX.Y.Z` मा अवतरणलाई नियन्त्रण गर्दछ। PR अवतरण गर्नु अघि पूर्वनिर्धारित शाखामा `config/merge-queue/config.json` मा शीर्ष-स्तर `mode` पढ्नुहोस्। [Omni-Lueue](OMNI_QUEUE.md) हेर्नुहोस्।

- **`shadow`** प्रमाणीकरण चलाउँछ र म्यानुअल मर्जमा अवतरण छोड्छ। स्वीकृत PR लाई यसको अन्तिम हेडमा `omni-queue` लागू गर्नुहोस्। `npm run queue -- why <PR>` मार्फत योग्यता जाँच गर्नुहोस्। `npm run queue -- history --base <branch>` मा त्यो टाउकोको लागि फैसला पर्खनुहोस्। `would-land` मा अगाडि बढ्नुहोस्। `culprit-found` वा `would-dequeue` मा, मर्ज होल्ड गर्नुहोस् र कारण ठीक गर्नुहोस्।
- **छाया अपवाद।** हालको आधार टिपको विरुद्धमा हरियो फुल CI भएको ट्रेन छुट्टै लामको निर्णय बिना अगाडि बढ्न सक्छ। उही अपवाद लागू हुन्छ जब PR हेड पहिले नै हालको आधार टिप समावेश गर्दछ।
- **`live`** अवतरण ट्रिगर गर्न `omni-queue` लेबल प्रयोग गर्दछ। लाम एक्लैले PR लाई अवतरण गर्छ। मर्ज आदेशहरू छोड्नुहोस् र लाममा सीधा धक्काहरू।

प्रत्येक अवतरणलाई मालिकको प्राधिकरण र लागू आवश्यक जाँचहरू आवश्यक पर्दछ। मालिकले अवतरणको अनुमति दिएपछि मात्र `omni-queue` लागू गर्नुहोस्। लामबद्ध PRs छुने सुरक्षित मार्गहरूलाई पनि त्यो PR को लागि मालिकको `protected-approved` निर्णय चाहिन्छ।

"सक्रिय विमोचनमा हरियो गेटहरू आवश्यक छ" नियमहरूको लागि टाउकोमा हरियो `Gate / CI` र `Gate / Quality` आवश्यक छ। रातो ढोका बाइपास गर्न `--admin` कहिल्यै प्रयोग नगर्नुहोस्। एक रिलीज फ्रिज ब्लकहरू जमेको शाखामा मर्ज हुन्छ। [कडा नियम 21](HARD_RULES_DETAIL.md) हेर्नुहोस्। अर्को सत्र काम गरिरहेको छ भनेर पुल अनुरोधमा कहिल्यै लेबल, मर्ज वा पुश नगर्नुहोस्। [कडा नियम 22](HARD_RULES_DETAIL.md) हेर्नुहोस्।

## ट्रेन तान्न अनुरोध

1. हालको रिलीज आधार टिपमा रेल शाखा सुरु गर्नुहोस्। मर्ज कमिटहरू प्रयोग गरेर सही स्वीकृत सदस्य हेडहरू एकीकृत गर्नुहोस्। स्क्वास र रिबेसलाई बेवास्ता गरेर तिनीहरूको प्रतिबद्ध इतिहास सुरक्षित गर्नुहोस्।
2. रेल शाखाको लागि एक पुल अनुरोध खोल्नुहोस्। त्यो PR हालको आधार टिपमा यसको आफ्नै पूर्ण CI सँग प्रमाणित गर्नुहोस्। अवतरण गर्नु अघि आधार टिप र अनुमोदित सदस्य हेडहरू पुन: जाँच गर्नुहोस्। मान्य उम्मेद्वार परिवर्तन हुँदा ट्रेन र यसको CI रिफ्रेस गर्नुहोस्।
3. लागू हुने लाइन मोड अन्तर्गत मर्ज कमिटको साथ ट्रेन PR ल्यान्ड गर्नुहोस्। लाइभ मोडमा, लामको `merge-ff` अवतरण विधिले मर्ज कमिटहरू सुरक्षित गर्दछ। मूल सदस्य प्रमुखहरू रिलीज शाखाबाट पहुँचयोग्य हुन्छन्। GitHub सदस्य PRs मर्ज भएको रूपमा चिन्ह लगाउँदछ र कमिटहरूले आफ्ना लेखकहरूलाई राख्छन्।

सार्वजनिक उदाहरण [PR #21071](https://github.com/cheaper-inference/OmniRoute/pull/21071) हो। यसले 18 सदस्यीय PRs जोड्यो र 2026-11-24 मा मर्ज कमिटको साथ अवतरण गर्यो।

`main` बाट अर्को रिलीज शाखामा सिंक-ब्याक पनि मर्ज कमिट मार्फत अवतरण हुन्छ। पछि सिंक-ब्याकहरूको लागि `main` पूर्वजहरू संरक्षण गर्न आवश्यक छ। [Worktree Isolation](WORKTREE_ISOLATION.md#sync-back-landings-are-merge-commits-never-squash) हेर्नुहोस्।

## स्थानीय मर्ज-ट्रेन प्रमाणिकरणकर्ता

```bash
scripts/release/merge-train.sh [--plan] [--fast] <base-branch> <PR#> [<PR#>...]
```

प्रमाणीकरणकर्ताले आधार र PR हेडहरू ल्याउँछ र तिनीहरूलाई डिस्पोजेबल वर्कट्रीमा जोड्छ। यसले परिणामस्वरूप रूखमा एक पटक यसको समानता सुइट चलाउँछ। असफल हेड फेच वा मर्ज द्वन्द्वले PR लाई बाहिर निकाल्छ र लिपि बाँकी PRs सँग जारी रहन्छ।

- **`--plan`** चयन गरिएको मोडको चरणहरू प्रिन्ट गर्दछ र worktree सिर्जना नगरी वा रिमोटलाई सम्पर्क नगरी बाहिर निस्कन्छ। द्रुत योजनाको निरीक्षण गर्न यसलाई `--fast` सँग जोड्नुहोस्।
- **`--fast`** साझा स्थिर गेटहरू चलाउँछ, `tests/unit/`, र `npm run test:vitest` अन्तर्गत चयन गरिएका `node:test` फाइलहरू। द्रुत मोड प्रयोग गर्दा कम्तिमा दिनमा एक पटक संचित टिपमा पूर्ण स्थानीय प्रमाणीकरण चलाउनुहोस्।
- **पूर्ण मोड** पूर्ण-मात्र स्थिर गेटहरू थप्छ र `npm run test:unit` र `npm run test:vitest` चलाउँछ।

यदि आधार प्रोब उपलब्ध छ भने अटच गरिएको आधारमा असफल स्थिर गेट पुन: चलाइन्छ। लिपिले वंशानुगत विफलताहरू रिपोर्ट गर्दछ र जारी रहन्छ जब प्रत्येक मान्यता प्राप्त उल्लङ्घन रेखा पनि आधारमा देखा पर्दछ र कुल गणना बढेको छैन।

| बाहिर निस्कनुहोस् | अर्थ                                                                                                                  |
| ----------------- | --------------------------------------------------------------------------------------------------------------------- |
| `0`               | योजना छापियो वा सूट पूरा भयो। सुइट सारांशले कुनै पनि वंशानुगत स्थिर विफलताहरू र निकालिएको PRs सूचीबद्ध गर्दछ।         |
| `1`               | अमान्य तर्कहरू, कुनै Git चेकआउट, असफल प्रीफ्लाइट, वा कुनै PR बोर्ड गरिएको छैन।                                        |
| `2`               | सुइट जाँच असफल भयो र वंशानुगत रूपमा योग्य भएन। अपरेटरले ब्याचलाई विभाजित गर्न, अपमानजनक PR निकाल्न र पुन: चलाउन सक्छ। |

स्थानीय पासले मालिकको डोजियरको लागि मात्र निदान प्रमाण प्रदान गर्दछ। प्रत्येक अवतरणलाई अझै पनि मालिकको प्राधिकरण, यसको आफ्नै आवश्यक जाँचहरू, र लागू हुँदा छाया लाम निर्णय आवश्यक छ।

## टायरिङ

- **प्रति PR।** CI र परिवर्तन गरिएका मार्गहरूमा आधारित गुणस्तर चयन जाँचहरू। कोड PRs CI मा छुट्टै एकाइ र Vitest कार्यहरूको साथ, द्रुत गुणस्तरका गेटहरू र प्रभावित परीक्षणहरू चलाउँछ।
- **प्रति कतार उम्मेदवार।** CI र क्वालिटीले यसको क्यु रेफमा रचना गरिएको उम्मेद्वारको लागि पूर्ण प्रोफाइल चलाउँछ।
- **प्रति रिलीज टिप।** रिलीज-ग्रीनले यसको मार्ग फिल्टरहरूसँग मेल खाने पुशहरूमा द्रुत हार्ड गेटहरू चलाउँछ। प्रति दिन तीन अनुसूचित रनहरू रिलीज शाखाको लागि पूर्ण स्वीप प्रयोग गर्नुहोस्।
- **प्रति रिलीज।** पूर्ण CI म्याट्रिक्समा E2E शार्डहरू, प्याकेज प्रमाणीकरण, टारबल बुट स्मोक, र कभरेज जाँचहरू समावेश छन्। [जारी चेकलिस्ट](RELEASE_CHECKLIST.md) हेर्नुहोस्।

## `merge-train.sh` को लागि ताजा-चेकआउट पूर्व शर्तहरू

worktrees बनाउन अघि preflight चल्छ। `npm ci` सँग निर्भरताहरू स्थापना गर्नुहोस्। पुष्टि गर्नुहोस् कि `node_modules/.bin/tsc` कार्यान्वयन योग्य छ र त्यो `node_modules/node_modules` अनुपस्थित छ। जाँच गर्नुहोस् कि `node_modules/.bin/bun --version` सफल हुन्छ।

यदि Bun postinstall छोडियो भने, `(cd node_modules/bun && node install.js)` चलाउनुहोस्। प्रदायक स्थिरता र ज्ञात-प्रतीक जाँचहरूले Bun प्रयोग गर्दछ। मान्यकर्ताले `npm run check:cycles:ratchet` अवरुद्ध गेटको रूपमा चलाउँछ। स्ट्यान्डअलोन `npm run check:cycles` आदेश सल्लाहकार छ।

Mergify मर्ज कतार 2026-11-19 मा सेवानिवृत्त भएको थियो।
