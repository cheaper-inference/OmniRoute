> यहाँ सूचीबद्ध प्रत्येक फ्ल्याग
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> मा परिभाषित छ — सत्यको एकल स्रोत। ड्यासबोर्ड र REST API दुवैले
> त्यही फाइलबाट पढ्छन्, त्यसैले तलको तालिका त्यससँग 1:1 मिल्ने गरी उत्पन्न गरिएको छ।

## फिचर फ्ल्यागहरू के हुन्

फिचर फ्ल्याग एउटा नाम दिइएको टगल (बुलियन वा इनम) हो जसको मान रनटाइममा
परिवर्तन गरी डेटाबेसमा स्थायी रूपमा भण्डारण गर्न सकिन्छ, र यसका लागि प्रक्रिया पुनः डिप्लोय गर्नु पर्दैन। प्रत्येक
फ्ल्यागलाई `key`, `label`, `description`, `category`, `defaultValue`, `type`,
र `requiresRestart` सङ्केत भएको `FeatureFlagDefinition` द्वारा वर्णन गरिन्छ।

### समाधान प्राथमिकता क्रम

फ्ल्यागको **प्रभावकारी मान**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) द्वारा निम्न
प्राथमिकताअनुसार समाधान गरिन्छ (सबैभन्दा उच्च प्राथमिकता विजयी हुन्छ):

1. **DB ओभरराइड** — `feature_flags` नेमस्पेसअन्तर्गत `key_value` तालिकामा
   भण्डारण गरिएको मान (ड्यासबोर्ड वा REST API मार्फत सेट गरिएको)।
2. **वातावरण चर** — सेट गरिएको र खाली नभएको अवस्थामा `process.env[<KEY>]`।
3. **परिभाषाको पूर्वनिर्धारित मान** — `featureFlagDefinitions.ts` बाट प्राप्त `defaultValue`।

कुनै बुलियन फ्ल्यागको प्रभावकारी मान `"true"`,
`"1"`, वा `"yes"` हुँदा त्यसलाई **सक्षम** मानिन्छ (`isFeatureFlagEnabled()` हेर्नुहोस्)।

> [!NOTE]
> अधिकांश फ्ल्यागहरूसँग [`ENVIRONMENT.md`](./ENVIRONMENT.md) मा दस्तावेजीकृत
> **उही नामको** मिल्दो वातावरण चर पनि हुन्छ। फ्ल्यागको DB ओभरराइडले
> उक्त वातावरण चरभन्दा प्राथमिकता पाउँछ। `requiresRestart: true` भएको फ्ल्याग
> तुरुन्तै स्थायी रूपमा भण्डारण हुन्छ, तर प्रक्रिया सुरु हुँदा मात्र पुनः पढिन्छ —
> यसलाई टगल गर्दा ड्यासबोर्डमा **"सर्भर पुनः सुरु गर्नुहोस्"** ब्यानर देखिन्छ।

> `INPUT_SANITIZER_BLOCK_THRESHOLD` र यसको लिगेसी उपनाम `INJECTION_GUARD_BLOCK_THRESHOLD` `INJECTION_GUARD_MODE` को `block` मोडलाई ट्युन गर्दछ, तर तिनीहरू [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts) द्वारा पढिएका सादा वातावरणीय चर हुन्, फिचर फ्ल्यागहरू होइनन्: तिनीहरूसँग कुनै DB ओभरराइड छैन र ड्यासबोर्ड टगल छैन। [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication) हेर्नुहोस्।

> [!NOTE]
> `Restart` स्तम्भले `requiresRestart: true` — सँग झण्डा चिन्ह लगाउँछ मान तुरुन्तै कायम रहन्छ तर प्रक्रिया पुन: लोड भएपछि मात्र प्रभाव पार्छ। Enum फ्ल्यागहरूले तिनीहरूको अनुमति दिइएको सेट बाहिर कुनै पनि मान अस्वीकार गर्दछ ( `setFeatureFlagOverride()` र REST `PUT` ह्यान्डलर दुवैमा मान्य सर्भर-साइड)।

## झण्डा टगल गर्दै

### ड्यासबोर्ड

मा नेभिगेट गर्नुहोस्** ड्यासबोर्ड → सेटिङहरू → सुविधा झण्डा** (`/dashboard/settings/feature-flags`)। ग्रिड (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) ले समर्थन गर्दछ:

- **खोज्नुहोस्** कुञ्जी वा विवरण द्वारा, र** फिल्टर** श्रेणी द्वारा (प्लस एक सिंथेटिक** पुन: सुरु गर्न आवश्यक छ** दृश्य)।
- ए** टगल गर्नुहोस्** बुलियन झण्डा र ए को लागि** ड्रपडाउन** enum झण्डा (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`) को लागी।
- ए** स्रोत ब्याज** प्रति झण्डा — `DB`, `ENV`, वा `DEF` — प्रभावकारी मान कहाँबाट आयो देखाउँदै।
- ए** रिसेट गर्नुहोस्** ओभरराइड ड्रप गर्न बटन ( `DB` -sourced फ्ल्यागका लागि मात्र देखाइएको छ) र ए** सबै ओभरराइडहरू रिसेट गर्नुहोस्** तलको बटन।
- ए** सर्भर पुन: सुरु गर्नुहोस्** ब्यानर जब `requiresRestart` झण्डा परिवर्तन हुन्छ।

### REST API

सबै कार्यहरू एउटै मार्गबाट जान्छन्: [`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts) । प्रत्येक विधिलाई एक प्रमाणीकृत ड्यासबोर्ड सत्र आवश्यक छ (अन्यथा`401` )।

लगइन असक्षम (`requireLogin=false`) संग मार्ग खुला छ, सुरक्षित झण्डाहरू बाहेक: सुरक्षा कोटीमा प्रत्येक झण्डा प्लस `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`, `OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS`, `MITM_DISABLE_TLS_VERIFY`, `OMNIROUTE_MCP_ENFORCE_SCOPES` र `SKILLS_SANDBOX_NETWORK_ENABLED` ( `protectedFeatureFlags.ts` मा`isProtectedFeatureFlag()` )। ती मध्ये एकमा `PUT`, र `DELETE` मा एक DB ओभरराइड हुँदा, अझै पनि ड्यासबोर्ड सत्र, `manage` -scope API कुञ्जी, लेखन स्कोप वा माथिको `oma_` पहुँच टोकन, वा लुपब्याकबाट पठाइएको CLI टोकन वा आन्तरिक-सेवा टोकन आवश्यक छ। त्यो सेट लगइन अन भएको भन्दा फराकिलो छ, जहाँ मार्गले सत्र वा `manage` -scope कुञ्जी मात्र स्वीकार गर्दछ।

#### `GET /api/settings/feature-flags`

प्रत्येक झण्डालाई यसको प्रभावकारी मान, स्रोत र सारांशको साथ फर्काउँछ।

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 121 flags
  ],
  "summary": {
    "total": 121,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

एकल ओभरराइड सेट वा हटाउनुहोस्। शरीर: `{ key: string; value?: string }`। `value` हटाउनाले ओभरराइड हटाउँछ (env / पूर्वनिर्धारित पुनर्स्थापना)।

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

प्रतिक्रियाले नयाँ `effectiveValue`/`source`, `previousValue`/ `previousSource`, र `requiresRestart` प्रतिध्वनित गर्दछ। अज्ञात कुञ्जीहरू र दायरा बाहिरका enum मानहरू `400` सँग अस्वीकार गरिन्छ।

#### `DELETE /api/settings/feature-flags`

खाली गर्छ** सबै** DB एकैचोटि ओभरराइड गर्दछ, प्रत्येक झण्डालाई यसको env / पूर्वनिर्धारित मानमा पुनर्स्थापित गर्दै। `{ cleared: <count>, message: "..." }` फर्काउँछ।

> [!NOTE]
> `requiresRestart: true` सँग झण्डाहरू प्रक्रिया पुन: लोड पछि मात्र प्रभावकारी हुन्छन्। ड्यासबोर्डको रिस्टार्ट फ्लोले `POST /api/restart` कल गर्छ र सर्भर ब्याकअप नभएसम्म `GET /api/health/ping` पोल गर्छ।

## आपतकालीन बजेट फलब्याक

`OMNIROUTE_EMERGENCY_FALLBACK` (श्रेणी `runtime`, पूर्वनिर्धारित `true`) ले
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
मा रहेको आपतकालीन निःशुल्क फलब्याक मार्गलाई नियन्त्रण गर्छ।
यो सक्षम हुँदा, आफ्नो बजेट समाप्त गरेका अनुरोधहरू पूर्ण रूपमा असफल हुनुको सट्टा
निःशुल्क फलब्याक प्रदायक/मोडेलमा रुट गरिन्छन्। यो व्यवहार असक्षम पार्न र बजेट
समाप्त भएका अनुरोधहरूलाई असफल हुन दिन ड्यासबोर्ड टगल, DB ओभरराइड वा
`OMNIROUTE_EMERGENCY_FALLBACK` वातावरण चरमार्फत यसलाई `false` (वा `0`) मा
सेट गर्नुहोस्। (PRs #3741 / #3752 मा ड्यासबोर्ड टगलका रूपमा उपलब्ध गराइएको।)

यस फलब्याकद्वारा प्रदान गरिएको प्रतिक्रियामा
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` हुन्छ,
जसले गर्दा क्लाइन्टले आफ्नो अनुरोधसँग `X-OmniRoute-Provider` को भिन्नता तुलना
नगरीकनै अनुरोध पुनः रुट गरिएको थियो भनेर थाहा पाउन सक्छ। अन्य प्रत्येक
प्रतिक्रियामा यो हेडर अनुपस्थित हुन्छ।
