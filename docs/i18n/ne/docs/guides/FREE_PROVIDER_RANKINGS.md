> **छोटकरीमा**: OmniRoute ले आफ्ना **निःशुल्क** प्रदायकहरूलाई मोडेलको गुणस्तरका आधारमा **Arena AI
> (LMArena-शैलीका) ELO स्कोरहरू** प्रयोग गरेर क्रमबद्ध गर्छ। आफ्नो कार्यका लागि सबैभन्दा शक्तिशाली मोडेलहरू
> उपलब्ध गराउने निःशुल्क प्रदायकहरू हेर्न ड्यासबोर्डको **निःशुल्क प्रदायक क्रमाङ्कन** पृष्ठ खोल्नुहोस् —
> समग्रमा वा वर्गअनुसार फिल्टर गरेर (कोडिङ, समीक्षा, दस्तावेजीकरण, डिबगिङ)।

## यो के हो

OmniRoute 377 प्रदायकहरू दर्ता गर्दछ, जसमा 155 क्याटलग प्रविष्टिहरू चिन्ह लगाइएका छन्**free/no-auth** (no-auth, free-tier OAuth, वा free-tier API कुञ्जी — [Free Tiers Guide](../getting-started/FREE-TIERS-GUIDE.md) र पूर्ण [Free Tiers डाइरेक्टरी](../reference/FREE_TIERS.md) हेर्नुहोस्)। क्याच: नि: शुल्क प्रदायकहरू मोडेल गुणस्तरमा बेग्लै रूपमा भिन्न हुन्छन्। एउटा सानो विरासत मोडेलको सेवा गर्ने भन्दा एक फ्रन्टियर मोडेल सेवा गर्ने नो-ऑथ प्रदायक धेरै उपयोगी छ।

**नि: शुल्क प्रदायक रैंकिंग** जवाफ"** कुन नि: शुल्क प्रदायकले मलाई उत्तम मोडेल दिन्छ?** "प्रत्येक नि:शुल्क प्रदायकको सूचीमा सामेल भएर** भीड-स्रोत गुणस्तर स्कोर** देखि** एरेना AI लिडरबोर्ड** (मानव-प्राथमिकता ELO, LMArena च्याटबोट एरेना पछाडि उही विचार)। त्यसपछि प्रदायकहरूलाई तिनीहरूको शक्तिद्वारा क्रमबद्ध गरिन्छ** उत्तम नि: शुल्क मोडेल** ।

रैंकिंग तीन वास्तविक स्रोतहरूबाट गणना गरिएको छ:

1. नि:शुल्क प्रदायक सूचीहरू — `NOAUTH_PROVIDERS`, प्लस `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` प्रविष्टिहरू फ्ल्याग गरिएको `hasFree` (`src/shared/constants/providers.ts`)।
2. प्रदायक रजिस्ट्री (`open-sse/config/providerRegistry.ts`) बाट प्रत्येक प्रदायकको मोडेल क्याटलग।
3. एरेना ELO सिंक इन्जिन (`src/lib/arenaEloSync.ts`) द्वारा `model_intelligence` DB तालिकामा भण्डारण गरिएको ELO-व्युत्पन्न कार्य-फिट स्कोरहरू।

जोड्ने तर्क `src/lib/freeProviderRankings.ts` मा रहन्छ।

## कसरी पहुँच गर्ने

### ड्यासबोर्ड पृष्ठ

ड्यासबोर्ड खोल्नुहोस् र **लागतहरू → निःशुल्क प्रदायक क्रमाङ्कन** मा जानुहोस्, वा सिधै यहाँ जानुहोस्:

```
/dashboard/free-provider-rankings
```

पृष्ठ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) ले निम्न देखाउँछ:

- उत्कृष्ट क्रमाङ्कन भएका निःशुल्क प्रदायकहरूको **शीर्ष-3 पोडियम** (🥇 🥈 🥉)।
- यी स्तम्भहरू भएको पूर्ण **क्रमाङ्कन तालिका**: **स्थान**, **प्रदायक**, **शीर्ष मोडेल**,
  **स्कोर**, **औसत स्कोर**, **मोडेलहरू**, **प्रकार**।
- **वर्ग फिल्टर बटनहरू**: _सबै वर्गहरू_, _पूर्वनिर्धारित_, _कोडिङ_, _समीक्षा_,
  _दस्तावेजीकरण_, _डिबगिङ_।

प्रत्येक प्रदायकको **प्रकार** ब्याजले त्यो कसरी निःशुल्क छ भन्ने बताउँछ:

| ब्याज    | अर्थ                                              |
| -------- | ------------------------------------------------- |
| `NOAUTH` | सधैँ निःशुल्क, कुनै प्रमाणपत्र आवश्यक पर्दैन      |
| `OAUTH`  | निःशुल्क स्तर (`hasFree`) भएको OAuth प्रदायक      |
| `APIKEY` | निःशुल्क स्तर (`hasFree`) भएको API-कुञ्जी प्रदायक |

स्कोरहरू कच्चा सङ्ख्याको सट्टा मानिसले सजिलै बुझ्न सक्ने लेबलहरू (जस्तै _विशिष्ट_, _उत्कृष्ट_, _धेरै राम्रो_,
_राम्रो_, _औसत_) का रूपमा देखाइन्छन्, किनभने अन्तर्निहित मान प्रतिशत नभई सापेक्ष
क्रमाङ्कन गुणस्तर हो।

### API अन्तिम-बिन्दु

यो पृष्ठ सार्वजनिक पठन अन्तिम-बिन्दुद्वारा समर्थित छ
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

क्वेरी प्यारामिटरहरू (Zod मार्फत प्रमाणीकरण गरिएका):

| प्यारामिटर | प्रकार | पूर्वनिर्धारित | टिप्पणी                                                                                                     |
| ---------- | ------ | -------------- | ----------------------------------------------------------------------------------------------------------- |
| `category` | string | (कुनै छैन)     | `default`, `coding`, `review`, `documentation`, `debugging` मध्ये एउटा। संयुक्त क्रमाङ्कनका लागि नदिनुहोस्। |
| `limit`    | number | `50`           | `1–100` को दायरामा सीमित गरिन्छ।                                                                            |

प्रतिक्रियाको संरचना:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` मूल Arena ELO मान हो; `score` सामान्यीकृत कार्य-अनुकूलता मान हो
(तल हेर्नुहोस्)। स्कोर प्राप्त गरेका मोडेलहरू नभएका प्रदायकहरू प्रतिक्रियाबाट हटाइन्छन्।

## स्कोरहरू कसरी काम गर्छन्

### स्रोत: Arena AI लीडरबोर्ड

Arena ELO सिङ्क इन्जिन (`src/lib/arenaEloSync.ts`) ले Arena AI लीडरबोर्ड API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) बाट दुईवटा लीडरबोर्ड — `text`
र `code` — ल्याउँछ। त्यो API ले प्रयोगयोग्य बोर्ड नफर्काएमा, इन्जिनले
Hugging Face datasets-server मा रहेको आधिकारिक `lmarena-ai/leaderboard-dataset` तर्फ
फलब्याक गर्छ (`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` ले `activeSource`, `lastError` र
`lastFailedAt` रिपोर्ट गर्छ। प्रत्येक लीडरबोर्ड प्रविष्टिमा
मोडेलको नाम, भेन्डर, ELO `score`, कन्फिडेन्स अन्तराल, र भोट संख्या हुन्छ।

लीडरबोर्ड श्रेणीहरू OmniRoute कार्य श्रेणीहरूसँग म्याप हुन्छन्:

| Arena लीडरबोर्ड | OmniRoute कार्य श्रेणीहरू                         |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### नर्मलाइजेसन (task-fit स्कोर)

कच्चा ELO स्कोरहरू प्रत्येक लीडरबोर्डका आधारमा **`[0.4, 0.98]` भित्रको task-fit मान**मा नर्मलाइज गरिन्छन्:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

स्कोर कहिल्यै `0` वा `1` सम्म पुग्दैन, जसले प्रयोगकर्ता ओभरराइडहरूका लागि ठाउँ छोड्छ। यो नै
API प्रतिक्रियामा देखिने `score` फिल्ड हो र ड्यासबोर्डमा देखाइने लेबल हो।

### कन्फिडेन्स

प्रत्येक प्रविष्टिले Arena भोट संख्याका आधारमा कन्फिडेन्स स्तर पाउँछ:

| कन्फिडेन्स | भोटहरू  |
| ---------- | ------- |
| `high`     | ≥ 5,000 |
| `medium`   | ≥ 1,000 |
| `low`      | < 1,000 |

### भण्डारण र ताजापन

नर्मलाइज गरिएका प्रविष्टिहरू `source = "arena_elo"` साथ `model_intelligence` DB तालिकामा
लेखिन्छन् (`src/lib/db/modelIntelligence.ts`)। प्रविष्टिहरू **7 दिनपछि
समाप्त हुन्छन्**, त्यसैले सिङ्क गर्न बन्द गरेको प्रदायक पुरानो डेटा दिँदै बस्नुको सट्टा
बिस्तारै सूचीबाट हट्छ।

सिङ्क **पूर्वनिर्धारित रूपमा चालू** हुन्छ:

- यो सर्भर स्टार्टअपमा एक पटक चल्छ र त्यसपछि आवधिक टाइमरमा चल्छ
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` बाट जडान गरिएको)।
- यो **नन-ब्लकिङ र कहिल्यै घातक हुँदैन** — यदि अपस्ट्रिम फेच असफल भयो भने, OmniRoute
  चलिरहन्छ र र्याङ्किङहरूले अन्तिम राम्रो डेटा (वा खाली स्थिति) मात्र देखाउँछन्।

यसलाई दुईवटा वातावरण चरहरूले नियन्त्रण गर्छन्
([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) मा दस्तावेज गरिएको):

| चर                        | पूर्वनिर्धारित | उद्देश्य                                          |
| ------------------------- | -------------- | ------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`         | आउटबाउन्ड सिङ्कबाट बाहिरिन `false` सेट गर्नुहोस्। |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h)  | सिङ्क अन्तराल, सेकेन्डमा।                         |

### म्यानुअल सिङ्क / स्थिति / खाली गर्ने

अपरेटरहरूका लागि, प्रमाणित व्यवस्थापन एन्डपोइन्टले म्यानुअल नियन्त्रण उपलब्ध गराउँछ
(`src/app/api/intelligence/sync/route.ts` — व्यवस्थापन प्रमाणीकरण आवश्यक):

```
GET    /api/intelligence/sync          # हालको सिङ्क स्थिति (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # म्यानुअल सिङ्क ट्रिगर गर्नुहोस्; body: { "dryRun": true } नलेखीकन पूर्वावलोकन गर्न
DELETE /api/intelligence/sync          # सिङ्क गरिएका सबै arena_elo इन्टेलिजेन्स प्रविष्टिहरू खाली गर्नुहोस्
```

यदि र्याङ्किङ पृष्ठ खाली छ भने, म्यानुअल `POST /api/intelligence/sync` (वा सर्भर
पुनः सुरु गर्नु मात्र) ले यसलाई फेरि भर्छ।

### मोडेलहरूलाई लीडरबोर्डसँग मिलान गर्ने

रजिस्ट्री मोडेल ID र Arena मोडेल नामहरू सधैँ ठीक मिल्दैनन्। र्याङ्किङले
लचिलो मिलान प्रयोग गर्छ (`src/lib/freeProviderRankings.ts` मा रहेको `findMatchingIntelligence`):

1. नर्मलाइज गरिएको मोडेल ID मा ठीक मिलान।
2. अन्तिम संस्करण प्रत्यय हटाएपछि मिलान (जस्तै `kimi-k2.6` → `kimi-k2`)।
3. उपसर्ग मिलान (लीडरबोर्ड मोडेल नाम रजिस्ट्री ID को उपसर्ग हो)।

सिङ्क तर्फ, चिनिएका भेन्डर उपसर्गहरू (`anthropic/`, `openai/`, `google/`, …)
हटाइन्छन् र एउटा सानो उपनाम म्यापले क्यानोनिकल नामहरूलाई OmniRoute ले
आन्तरिक रूपमा प्रयोग गर्ने भेरिएन्टहरूमा विस्तार गर्छ, जसले मोडेलहरूलाई कुनै पनि
नाममा फेला पार्न मिल्ने बनाउँछ।

### प्रदायकलाई कसरी र्याङ्क गरिन्छ

प्रत्येक निःशुल्क प्रदायकका लागि, इन्जिनले यसको क्याटलगमा रहेका सबै मोडेलहरूलाई स्कोर गर्छ, त्यसपछि:

- **शीर्ष मोडेल** = प्रदायकको सबैभन्दा उच्च स्कोर गरेको मोडेल।
- **औसत स्कोर** = त्यस प्रदायकका स्कोर गरिएका सबै मोडेलहरूको औसत स्कोर।
- **मोडेलहरू** = प्रदायकका कति मोडेलहरूमा Arena स्कोर थियो।

प्रदायकहरूलाई पहिले **शीर्ष-मोडेल स्कोर** अनुसार, त्यसपछि औसत स्कोर अनुसार
क्रमबद्ध गरिन्छ। यसले कम्तीमा एउटा बलियो निःशुल्क मोडेल दिने प्रदायकलाई पुरस्कृत गर्छ।

## निःशुल्क प्रदायकहरू छनोट गर्न यसको प्रयोग

1. **सही श्रेणी छान्नुहोस्।** एजेन्टिक/कोड कार्यभारहरूका लागि **Coding** फिल्टर प्रयोग गर्नुहोस्, वा
   सामान्य च्याटका लागि यसलाई **All Categories** / **Default** मै छोड्नुहोस्। एउटै प्रदायकको
   स्थान विभिन्न श्रेणीमा फरक हुन सक्छ, किनकि प्रत्येक लिडरबोर्डअनुसार यसको शीर्ष मोडेल फरक हुन्छ।
2. **एक-पटकको सेटअपका लागि शीर्ष तीनलाई प्राथमिकता दिनुहोस्।** यदि तपाईं एक वा दुईवटा निःशुल्क
   प्रदायक मात्र जडान गर्न चाहनुहुन्छ भने, आफ्नो श्रेणीमा शीर्ष स्थानमा रहेका प्रदायकबाट सुरु गर्नुहोस्।
3. **Type ब्याज जाँच गर्नुहोस्।** `NOAUTH` प्रदायकहरू जडान गर्न सबैभन्दा छिटो हुन्छन् (कुनै
   प्रमाणपत्र आवश्यक पर्दैन)। `OAUTH` / `APIKEY` का निःशुल्क टियरहरूका लागि छोटो साइन-अप आवश्यक पर्छ, तर तिनले प्रायः
   अझ शक्तिशाली मोडेलहरू उपलब्ध गराउँछन्। जडानका चरणहरूका लागि
   [निःशुल्क टियर मार्गदर्शिका](../getting-started/FREE-TIERS-GUIDE.md) हेर्नुहोस्।
4. **धेरैवटा जडान गर्नुहोस् र Auto-Combo लाई निर्णय गर्न दिनुहोस्।** यस पृष्ठलाई सञ्चालन गर्ने उही Arena ELO डेटाले
   Auto-Combo स्कोरिङ इन्जिनको **कार्य-उपयुक्तता कारक** लाई पनि डेटा प्रदान गर्छ
   (`open-sse/services/autoCombo/taskFitness.ts`, रिजोल्युसन क्रम
   `user_override → arena_elo → models_dev_tier → static table`)। त्यसैले शीर्ष निःशुल्क प्रदायकहरू जडान गरेपछि,
   `model: "auto"` (जस्तै `auto/coding`) प्रयोग गरी राउटिङ गर्दा प्रत्येक अनुरोधका लागि
   उच्च गुणस्तरका निःशुल्क मोडेलहरू स्वतः प्राथमिकतामा पर्छन्। पूर्ण १६-कारक स्कोरिङका लागि
   [Auto-Combo](../routing/AUTO-COMBO.md) हेर्नुहोस्।
