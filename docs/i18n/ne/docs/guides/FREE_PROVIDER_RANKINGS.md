> **छोटकरीमा**: OmniRoute ले आफ्ना **निःशुल्क** प्रदायकहरूलाई मोडेलको गुणस्तरका आधारमा **Arena AI
> (LMArena-शैलीका) ELO स्कोरहरू** प्रयोग गरेर क्रमबद्ध गर्छ। आफ्नो कार्यका लागि सबैभन्दा शक्तिशाली मोडेलहरू
> उपलब्ध गराउने निःशुल्क प्रदायकहरू हेर्न ड्यासबोर्डको **निःशुल्क प्रदायक क्रमाङ्कन** पृष्ठ खोल्नुहोस् —
> समग्रमा वा वर्गअनुसार फिल्टर गरेर (कोडिङ, समीक्षा, दस्तावेजीकरण, डिबगिङ)।

## यो के हो

OmniRoute ले 376 प्रदायकहरू दर्ता गर्छ, जसमा **निःशुल्क/प्रमाणीकरण-रहित** का रूपमा चिन्ह लगाइएका 155 क्याटलग प्रविष्टिहरू समावेश छन्
(प्रमाणीकरण-रहित,
निःशुल्क-टियर OAuth, वा निःशुल्क-टियर API कुञ्जी —
[निःशुल्क टियर मार्गदर्शिका](../getting-started/FREE-TIERS-GUIDE.md) र पूर्ण
[निःशुल्क टियर डाइरेक्टरी](../reference/FREE_TIERS.md) हेर्नुहोस्)। तर समस्या के छ भने: निःशुल्क प्रदायकहरूको
मोडेल गुणस्तरमा अत्यधिक भिन्नता हुन्छ। फ्रन्टियर मोडेल उपलब्ध गराउने प्रमाणीकरण-रहित प्रदायक,
सानो पुरानो मोडेल उपलब्ध गराउने प्रदायकभन्दा धेरै उपयोगी हुन्छ।

**निःशुल्क प्रदायक श्रेणीकरण** ले प्रत्येक निःशुल्क प्रदायकको क्याटलगलाई
**Arena AI लिडरबोर्ड** का **क्राउड-सोर्स गरिएका गुणस्तर स्कोरहरू** सँग जोडेर
"**कुन निःशुल्क प्रदायकले मलाई उत्कृष्ट मोडेल दिन्छ?**" भन्ने प्रश्नको उत्तर दिन्छ (मानवीय-प्राथमिकतामा आधारित ELO, जुन LMArena
च्याटबट एरिनाको आधारमा रहेको उही अवधारणा हो)। त्यसपछि प्रदायकहरूलाई तिनीहरूको **उत्कृष्ट निःशुल्क मोडेल** को क्षमताका आधारमा श्रेणीबद्ध गरिन्छ।

यो श्रेणीकरण तीन वास्तविक स्रोतहरूबाट गणना गरिन्छ:

1. निःशुल्क प्रदायकका सूचीहरू — `NOAUTH_PROVIDERS`, साथै `hasFree` ले चिन्ह लगाइएका `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` प्रविष्टिहरू
   (`src/shared/constants/providers.ts`)।
2. प्रदायक रजिस्ट्रीबाट प्रत्येक प्रदायकको मोडेल क्याटलग
   (`open-sse/config/providerRegistry.ts`)।
3. Arena ELO सिंक इन्जिन (`src/lib/arenaEloSync.ts`) द्वारा `model_intelligence` DB तालिकामा
   भण्डारण गरिएका ELO-व्युत्पन्न कार्य-अनुकूलता स्कोरहरू।

जोड्ने तर्क `src/lib/freeProviderRankings.ts` मा रहेको छ।

## कसरी पहुँच गर्ने

### ड्यासबोर्ड पृष्ठ

ड्यासबोर्ड खोल्नुहोस् र **लागतहरू → निःशुल्क प्रदायक क्रमाङ्कन** मा जानुहोस्, वा सिधै यहाँ जानुहोस्:

```
/dashboard/free-provider-rankings
```

पृष्ठ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) ले निम्न देखाउँछ:

- उत्कृष्ट क्रमाङ्कन भएका निःशुल्क प्रदायकहरूको **शीर्ष-3 पोडियम** (🥇 🥈 🥉)।
- यी स्तम्भहरू भएको पूर्ण **क्रमाङ्कन तालिका**: **स्थान**, **प्रदायक**, **शीर्ष मोडेल**,
  **स्कोर**, **औसत स्कोर**, **मोडेलहरू**, **प्रकार**।
- **वर्ग फिल्टर बटनहरू**: _सबै वर्गहरू_, _पूर्वनिर्धारित_, _कोडिङ_, _समीक्षा_,
  _दस्तावेजीकरण_, _डिबगिङ_।

प्रत्येक प्रदायकको **प्रकार** ब्याजले त्यो कसरी निःशुल्क छ भन्ने बताउँछ:

| ब्याज    | अर्थ                                              |
| -------- | ------------------------------------------------- |
| `NOAUTH` | सधैँ निःशुल्क, कुनै प्रमाणपत्र आवश्यक पर्दैन      |
| `OAUTH`  | निःशुल्क स्तर (`hasFree`) भएको OAuth प्रदायक      |
| `APIKEY` | निःशुल्क स्तर (`hasFree`) भएको API-कुञ्जी प्रदायक |

स्कोरहरू कच्चा सङ्ख्याको सट्टा मानिसले सजिलै बुझ्न सक्ने लेबलहरू (जस्तै _विशिष्ट_, _उत्कृष्ट_, _धेरै राम्रो_,
_राम्रो_, _औसत_) का रूपमा देखाइन्छन्, किनभने अन्तर्निहित मान प्रतिशत नभई सापेक्ष
क्रमाङ्कन गुणस्तर हो।

### API अन्तिम-बिन्दु

यो पृष्ठ सार्वजनिक पठन अन्तिम-बिन्दुद्वारा समर्थित छ
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

क्वेरी प्यारामिटरहरू (Zod मार्फत प्रमाणीकरण गरिएका):

| प्यारामिटर | प्रकार | पूर्वनिर्धारित | टिप्पणी                                                                                                     |
| ---------- | ------ | -------------- | ----------------------------------------------------------------------------------------------------------- |
| `category` | string | (कुनै छैन)     | `default`, `coding`, `review`, `documentation`, `debugging` मध्ये एउटा। संयुक्त क्रमाङ्कनका लागि नदिनुहोस्। |
| `limit`    | number | `50`           | `1–100` को दायरामा सीमित गरिन्छ।                                                                            |

प्रतिक्रियाको संरचना:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` मूल Arena ELO मान हो; `score` सामान्यीकृत कार्य-अनुकूलता मान हो
(तल हेर्नुहोस्)। स्कोर प्राप्त गरेका मोडेलहरू नभएका प्रदायकहरू प्रतिक्रियाबाट हटाइन्छन्।

## स्कोरहरू कसरी काम गर्छन्

### स्रोत: Arena AI लिडरबोर्ड

Arena ELO सिङ्क इन्जिन (`src/lib/arenaEloSync.ts`) ले Arena AI लिडरबोर्ड API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) बाट दुई वटा लिडरबोर्डहरू — `text`
र `code` — ल्याउँछ। जब उक्त API ले कुनै प्रयोगयोग्य बोर्ड फर्काउँदैन, इन्जिनले Hugging Face
datasets-server मा रहेको आधिकारिक `lmarena-ai/leaderboard-dataset` तर्फ फर्कन्छ
(`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` ले `activeSource`, `lastError` र
`lastFailedAt` रिपोर्ट गर्छ। प्रत्येक लिडरबोर्ड प्रविष्टिले मोडेल नाम, भेन्डर, ELO `score`,
कन्फिडेन्स अन्तराल, र भोट गणना बोक्छ।

लिडरबोर्ड श्रेणीहरू OmniRoute कार्य श्रेणीहरूसँग म्याप हुन्छन्:

| Arena लिडरबोर्ड | OmniRoute कार्य श्रेणीहरू                         |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### नर्मलाइजेसन (task-fit स्कोर)

कच्चा ELO स्कोरहरू प्रत्येक लिडरबोर्डमा **`[0.4, 0.98]` भित्रको task-fit मान** मा नर्मलाइज गरिन्छन्:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

स्कोर कहिल्यै `0` वा `1` सम्म पुग्दैन, जसले प्रयोगकर्ता ओभरराइडहरूका लागि ठाउँ छोड्छ। यही नै
`score` फिल्ड हो जुन तपाईंले API प्रतिक्रियामा देख्नुहुन्छ र ड्यासबोर्डमा देखाइने लेबल हो।

### कन्फिडेन्स

प्रत्येक प्रविष्टिले Arena भोट गणनाको आधारमा कन्फिडेन्स स्तर पाउँछ:

| कन्फिडेन्स | भोटहरू  |
| ---------- | ------- |
| `high`     | ≥ 5,000 |
| `medium`   | ≥ 1,000 |
| `low`      | < 1,000 |

### भण्डारण र ताजापन

नर्मलाइज गरिएका प्रविष्टिहरू `source = "arena_elo"` सहित `model_intelligence` DB तालिकामा
लेखिन्छन् (`src/lib/db/modelIntelligence.ts`)। प्रविष्टिहरू **७ दिनपछि समाप्त
हुन्छन्**, त्यसैले सिङ्क गर्न बन्द गरेको प्रोभाइडरले पुरानो डेटा दिइरहनुको सट्टा
अन्ततः सूचीबाट हट्छ।

सिङ्क **डिफल्ट रूपमा चालू** हुन्छ:

- यो सर्भर स्टार्टअपमा एक पटक चल्छ र त्यसपछि आवधिक टाइमरमा चल्छ
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` बाट जोडिएको)।
- यो **नन-ब्लकिङ छ र कहिल्यै घातक हुँदैन** — यदि अपस्ट्रिम फेच असफल भयो भने, OmniRoute
  चलिरहन्छ र र्याङ्किङहरूले केवल अन्तिम राम्रो डेटा (वा खाली अवस्था) देखाउँछन्।

दुई वटा एनभायरनमेन्ट भेरिएबलहरूले यसलाई नियन्त्रण गर्छन्
([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) मा दस्तावेजीकृत):

| भेरिएबल                   | डिफल्ट        | उद्देश्य                                          |
| ------------------------- | ------------- | ------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | आउटबाउन्ड सिङ्कबाट बाहिरिन `false` सेट गर्नुहोस्। |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | सिङ्क अन्तराल, सेकेन्डमा।                         |

### म्यानुअल सिङ्क / स्थिति / खाली गर्ने

अपरेटरहरूका लागि, एक प्रमाणित व्यवस्थापन एन्डपोइन्टले म्यानुअल नियन्त्रण उपलब्ध गराउँछ
(`src/app/api/intelligence/sync/route.ts` — व्यवस्थापन प्रमाणीकरण आवश्यक):

```
GET    /api/intelligence/sync          # हालको सिङ्क स्थिति (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # म्यानुअल सिङ्क ट्रिगर गर्नुहोस्; body: { "dryRun": true } नलेखीकन पूर्वावलोकन गर्न
DELETE /api/intelligence/sync          # सबै सिङ्क गरिएका arena_elo intelligence प्रविष्टिहरू खाली गर्नुहोस्
```

यदि र्याङ्किङ पृष्ठ खाली छ भने, म्यानुअल `POST /api/intelligence/sync` (वा सर्भरलाई केवल
पुनः सुरु गर्नु) ले यसलाई फेरि भर्छ।

### मोडेलहरूलाई लिडरबोर्डसँग मिलाउने

रजिस्ट्री मोडेल ID हरू र Arena मोडेल नामहरू सधैं ठीक मिल्दैनन्। र्याङ्किङले
लचिलो मिलान प्रयोग गर्छ (`src/lib/freeProviderRankings.ts` मा रहेको `findMatchingIntelligence`):

1. नर्मलाइज गरिएको मोडेल ID मा ठीक मिलान।
2. अन्त्यको संस्करण सफिक्स हटाएपछि मिलान (जस्तै `kimi-k2.6` → `kimi-k2`)।
3. प्रिफिक्स मिलान (लिडरबोर्ड मोडेल नाम रजिस्ट्री ID को प्रिफिक्स हो)।

सिङ्क तर्फ, चिनिएका भेन्डर प्रिफिक्सहरू (`anthropic/`, `openai/`, `google/`, …) हटाइन्छन्
र एउटा सानो alias नक्साले क्यानोनिकल नामहरूलाई OmniRoute ले आन्तरिक रूपमा प्रयोग गर्ने
भेरियन्टहरूमा विस्तार गर्छ, जसले गर्दा मोडेलहरू जुनसुकै नाममा पनि भेट्न सकिन्छ।

### प्रोभाइडर कसरी र्याङ्क हुन्छ

प्रत्येक निःशुल्क प्रोभाइडरका लागि, इन्जिनले यसको क्याटालगमा भएका सबै मोडेलहरूलाई स्कोर गर्छ, त्यसपछि:

- **Top Model** = प्रोभाइडरको सबैभन्दा उच्च स्कोर भएको मोडेल।
- **Avg Score** = उक्त प्रोभाइडरका सबै स्कोर गरिएका मोडेलहरूको औसत स्कोर।
- **Models** = प्रोभाइडरका कति वटा मोडेलहरूमा Arena स्कोर थियो।

प्रोभाइडरहरू पहिले **शीर्ष-मोडेल स्कोर** अनुसार, त्यसपछि औसत स्कोर अनुसार क्रमबद्ध गरिन्छन्।
यसले कम्तीमा एउटा बलियो निःशुल्क मोडेल उपलब्ध गराउने प्रोभाइडरलाई पुरस्कृत गर्छ।

## निःशुल्क प्रदायकहरू छनोट गर्न यसको प्रयोग

1. **सही श्रेणी छान्नुहोस्।** एजेन्टिक/कोड कार्यभारहरूका लागि **Coding** फिल्टर प्रयोग गर्नुहोस्, वा
   सामान्य च्याटका लागि यसलाई **All Categories** / **Default** मै छोड्नुहोस्। एउटै प्रदायकको
   स्थान विभिन्न श्रेणीमा फरक हुन सक्छ, किनकि प्रत्येक लिडरबोर्डअनुसार यसको शीर्ष मोडेल फरक हुन्छ।
2. **एक-पटकको सेटअपका लागि शीर्ष तीनलाई प्राथमिकता दिनुहोस्।** यदि तपाईं एक वा दुईवटा निःशुल्क
   प्रदायक मात्र जडान गर्न चाहनुहुन्छ भने, आफ्नो श्रेणीमा शीर्ष स्थानमा रहेका प्रदायकबाट सुरु गर्नुहोस्।
3. **Type ब्याज जाँच गर्नुहोस्।** `NOAUTH` प्रदायकहरू जडान गर्न सबैभन्दा छिटो हुन्छन् (कुनै
   प्रमाणपत्र आवश्यक पर्दैन)। `OAUTH` / `APIKEY` का निःशुल्क टियरहरूका लागि छोटो साइन-अप आवश्यक पर्छ, तर तिनले प्रायः
   अझ शक्तिशाली मोडेलहरू उपलब्ध गराउँछन्। जडानका चरणहरूका लागि
   [निःशुल्क टियर मार्गदर्शिका](../getting-started/FREE-TIERS-GUIDE.md) हेर्नुहोस्।
4. **धेरैवटा जडान गर्नुहोस् र Auto-Combo लाई निर्णय गर्न दिनुहोस्।** यस पृष्ठलाई सञ्चालन गर्ने उही Arena ELO डेटाले
   Auto-Combo स्कोरिङ इन्जिनको **कार्य-उपयुक्तता कारक** लाई पनि डेटा प्रदान गर्छ
   (`open-sse/services/autoCombo/taskFitness.ts`, रिजोल्युसन क्रम
   `user_override → arena_elo → models_dev_tier → static table`)। त्यसैले शीर्ष निःशुल्क प्रदायकहरू जडान गरेपछि,
   `model: "auto"` (जस्तै `auto/coding`) प्रयोग गरी राउटिङ गर्दा प्रत्येक अनुरोधका लागि
   उच्च गुणस्तरका निःशुल्क मोडेलहरू स्वतः प्राथमिकतामा पर्छन्। पूर्ण १६-कारक स्कोरिङका लागि
   [Auto-Combo](../routing/AUTO-COMBO.md) हेर्नुहोस्।
