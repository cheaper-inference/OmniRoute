अनुकूलन JSON API नोडले OpenAI वा Anthropic प्रोटोकल नबोल्ने JSON व्यापारको अन्तिम बिन्दु जोड्छ। OmniRoute JSON अनुरोध टेम्प्लेट भर्छ, यसलाई पूर्ण अन्त्य बिन्दु URL मा पठाउँछ, प्रतिक्रिया पथबाट जवाफ पढ्छ र ग्राहकको आफ्नै ढाँचामा ग्राहकलाई फर्काउँछ (च्याट पूरा, प्रतिक्रियाहरू, सन्देशहरू, ...)।

यो `apiType: "custom-json"` सँग OpenAI- संगत नोड हो; यसको id मा `openai-compatible-custom-json-<suffix>` फारम छ। ड्यासबोर्ड फारम अझै उपलब्ध छैन। तलको प्रदायक-नोड API मार्फत यी नोडहरू सिर्जना गर्नुहोस् र सम्पादन गर्नुहोस्।

## नोड सिर्जना गर्नुहोस्

`POST /api/provider-nodes` (व्यवस्थापन प्राधिकरण):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` हो** पूरा** अन्तिम बिन्दु URL। केहि पनि जोडिएको छैन ( `/chat/completions` छैन, `/models` छैन) र, अन्य OpenAI- संगत नोडहरूको विपरीत, त्यहाँ कुनै पूर्वनिर्धारित URL छैन। यो इम्बेडेड प्रमाणहरू वा `#fragment` बिना `http(s)` हुनुपर्छ, र यसले प्रत्येक प्रदायक नोडको रूपमा उही आउटबाउन्ड URL गार्ड पास गर्दछ, दुबै नोड बचत हुँदा र प्रत्येक अनुरोधमा।
- जडान कुञ्जी (`authType` `bearer` वा `api-key`, पूर्वनिर्धारित सहित) पठाउने नोडले `https://` प्रयोग गर्नुपर्छ। प्लेन `http://` लुपब्याक होस्ट (`localhost`, `127.0.0.0/8`, `::1`) वा `authType: "none"` सँग मात्र स्वीकार गरिन्छ, जसले कुनै कुञ्जी पठाउँदैन। निजी LAN ठेगानाहरू (`10.x`, `172.16-31.x`, `192.168.x`) छुट छैन: त्यो नेटवर्कमा जो कोहीले कुञ्जी पढ्न सक्छ। यस्तो नोड बचत `400` सँग असफल हुन्छ, र पहिले भण्डारण गरिएको नोड असफल हुन्छ प्रत्येक अनुरोधमा एउटै सन्देशको साथ, कुनै अनुरोध पठाउनु अघि। LAN मा कुञ्जी अन्त्य बिन्दुको लागि, यसलाई TLS पछाडि राख्नुहोस् (उदाहरणका लागि रिभर्स प्रोक्सी)।
- `customJson` Zod सँग मान्य छ; अज्ञात कुञ्जीहरू अस्वीकार गरिएका छन्। प्रत्येक क्षेत्र वैकल्पिक छ:

| क्षेत्र           | मानहरू                                     | पूर्वनिर्धारित                                         |
| ----------------- | ------------------------------------------ | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                     | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                | `bearer`                                               |
| `authHeader`      | हेडर नाम प्रयोग गर्दा `api-key`            | `X-API-Key`                                            |
| `requestTemplate` | JSON वस्तु (≤ 64 KB, गहिराई ≤ 32)          | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | क्षेत्र मार्ग, वा सम्पूर्ण शरीरको लागि `$` | `choices[0].message.content`                           |

- गोप्य जडानको API कुञ्जीमा रहन्छ, टेम्प्लेटमा कहिल्यै हुँदैन। `bearer` ले `Authorization: Bearer <key>` पठाउँछ; `api-key` `<authHeader>: <key>` पठाउँछ। प्रमाणीकरण हेडर `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` वा हप-बाइ-हप हेडर हुन सक्दैन। `none` को साथ, जडानहरूलाई कुनै कुञ्जी आवश्यक पर्दैन।
- अतिरिक्त स्थिर हेडरहरूले नोडको नियमित `customHeaders` प्रयोग गर्दछ (प्रत्येक अन्य उपयुक्त नोडको रूपमा समान प्रमाणीकरण; प्रमाणीकरण हेडरहरू त्यहाँ अनुमति छैन)।

`PUT /api/provider-nodes/<id>` उही `customJson` स्वीकार गर्दछ र `baseUrl` र कन्फिगलाई नोडको प्रत्येक अवस्थित जडानमा पुन: लेख्दछ। `customJson` छोड्दा भण्डार गरिएको कन्फिगरेसन राख्छ; `apiType` लाई `chat` वा `responses` मा स्विच गर्नाले यसलाई नोड र यसको जडानहरूबाट हटाउँछ।

त्यसपछि सामान्य रूपमा नोडमा जडान थप्नुहोस् (नोड आईडीको साथ `POST /api/providers` ) र `<prefix>/<model>` अनुरोध गर्नुहोस्, उदाहरणका लागि `biz/assistant-v1`। अन्तिम बिन्दुले कुनै मोडेल सूची प्रकट गर्दैन, त्यसैले हातले मोडेल आईडीहरू थप्नुहोस्।

## टेम्प्लेटहरू अनुरोध गर्नुहोस्

टेम्प्लेटहरू सादा JSON हुन्। स्ट्रिङ मानमा `{{placeholder}}` मार्करहरू हुन सक्छन्; केहि पनि मूल्याङ्कन वा कार्यान्वयन हुँदैन, र वस्तु कुञ्जीहरू कहिल्यै प्रतिस्थापित हुँदैनन्।

| प्लेसहोल्डर          | मूल्य                                                                 |
| -------------------- | --------------------------------------------------------------------- |
| `{{prompt}}`         | भर्खरको प्रयोगकर्ता सन्देशको पाठ (पाठ भागहरू नयाँ लाइनहरूसँग जोडिएको) |
| `{{messages}}`       | OpenAI च्याट ढाँचामा कुराकानी                                         |
| `{{model}}`          | अनुरोध गरिएको मोडेल आईडी, प्रदायक उपसर्ग बिना                         |
| `{{stream}}`         | सधैं `false` — अन्तिम बिन्दु एक JSON कागजात संग जवाफ दिनुहोस्         |
| `{{request.<path>}}` | अनुवादित (OpenAI च्याट ढाँचा) अनुरोधको क्षेत्र                        |

- ठ्याक्कै एउटा प्लेसहोल्डर भएको मानले यसको JSON प्रकार राख्छ (`"{{messages}}"` एरे हुन्छ); लामो स्ट्रिङ भित्र एउटा प्लेसहोल्डर पाठको रूपमा सम्मिलित हुन्छ।
- कुनै पनि कुराको समाधान गर्ने प्लेसहोल्डरले अपूर्ण पेलोड पठाउनुको सट्टा HTTP 400 सँग अनुरोधलाई असफल पार्छ।
- पथहरूले डट नोटेशन र संख्यात्मक अनुक्रमणिकाहरू (`data.items[0].text`) प्रयोग गर्दछ। `__proto__`, `prototype` र `constructor` कुञ्जी र पथहरूमा अस्वीकार गरिएको छ।

## प्रतिक्रियाहरू

`responsePath` मा मान सहायक जवाफ बन्छ: स्ट्रिङहरू पास हुन्छन्, अन्य JSON मानहरू क्रमबद्ध हुन्छन्। छुटेको वा `null` फिल्ड, वा JSON नभएको बडीले HTTP 502 फर्काउँछ। अपस्ट्रीम त्रुटि स्थितिहरू पार गरिन्छ। स्ट्रिमिङ क्लाइन्टहरूका लागि OmniRoute सम्पूर्ण JSON प्रतिक्रियाको लागि पर्खन्छ र त्यसपछि यसलाई एउटा सामग्रीको टुक्रा र फिनिश खण्डको रूपमा उत्सर्जन गर्दछ; यो टोकन स्ट्रिमिङ होइन। उपकरण कल र उपयोग क्षेत्रहरू म्याप गरिएको छैन।

## कहिल्यै रिप्ले गरिएन

व्यापार अनुरोध असफल हुँदा पनि साइड इफेक्ट हुन सक्छ। OmniRoute त्यसैले यसलाई एक पटक पठाउँछ:

- कुनै यातायात पुन: प्रयास र कुनै पुन: निर्देशित निम्न;
- अर्को जडानमा पुन: प्रयास नगर्नुहोस् (खाता फलब्याक) — असफलता यथा-यस्तै फर्काइन्छ र जडान चिसो छैन;
- अर्को कम्बो लक्ष्यमा कुनै फलब्याक छैन, खाली वा असफल जवाफको लागि पनि।

अलग क्लाइन्ट अनुरोधहरू, र फ्यूजन प्यानलहरू जसले स्पष्ट रूपमा धेरै मोडेलहरू कल गर्दछ, अझै पनि स्वतन्त्र रूपमा अन्त्य बिन्दुलाई आह्वान गर्दछ।

## नोड परीक्षण गर्दै

जडान बचत गर्दै, जडान** परीक्षण** बटन र पृष्ठभूमि स्वास्थ्य जाँचहरूले कहिले पनि अन्तिम बिन्दुलाई कल गर्दैनन्: तिनीहरूले भण्डार गरिएको कन्फिगरेसनलाई मात्र प्रमाणित गर्छन् र जडानलाई प्रमाणिकरणयोग्य नभएको रूपमा रिपोर्ट गर्छन्।

`POST /api/provider-nodes/validate` `"apiType": "custom-json"` र नोड फिल्डहरू (`baseUrl`, `apiKey`, `customJson`, वैकल्पिक `customHeaders` र `modelId`) ले एक वास्तविक अनुरोध पठाउँछ, `ping` पछिल्लो प्रयोगकर्ता पाठको रूपमा। यसले `{ "valid": true }` वा अपस्ट्रीम स्थितिको जवाफ दिन्छ (अपस्ट्रीम शरीर कहिल्यै होइन)।

## भण्डारण

कन्फिगरेसन `provider_nodes.custom_json_config_json` (माइग्रेसन `240_provider_node_custom_json_config.sql`) मा भण्डार गरिएको छ र प्रत्येक जडानको `providerSpecificData.customJson` मा प्रतिलिपि गरिएको छ।

कार्यान्वयन: `open-sse/utils/customJson.ts` (मान्यता र टेम्प्लेटिंग), `open-sse/executors/customJson.ts` (कार्यान्वयनकर्ता), `open-sse/services/combo/noReplayLatch.ts` र `src/sse/handlers/chat/responsePolicies.ts` (नो-रिप्ले)।
