> **स्थिति:** ड्यासबोर्ड **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`) मा निर्मित छ, जसलाई
> workspace `packages/ui-kit` को रूपमा vendor गरिएको छ (`@omniroute/ui-kit`; upstream snapshot
> `packages/ui-kit/UPSTREAM.md` मा pin गरिएको छ र `npm run check:ui-kit-snapshot` द्वारा जाँचिएको छ)।
> Light canonical theme हो; डिफल्ट प्राथमिकता `system` हो। Accent Keak lime हो (`--ci-color-accent`)।
> Inter (letter-spacing 0, `--ci-letter-spacing-ui`) UI परिवार हो, Instrument Serif केवल ठूला विरल
> display text का लागि (`.ci-dashboard-display`), IBM Plex Mono कोडका लागि — सबै `src/app/globals.css`
> को शीर्षमा रहेका `@fontsource/*` imports मार्फत self-hosted छन्। हरेक icon Lucide glyph हो।

## १. चीजहरू कहाँ रहेका छन्

- **किट।** `packages/ui-kit/src` भनेको `packages/ui-kit/UPSTREAM.md` मा पिन गरिएको कमिटमा रहेको अपस्ट्रिम `src/` को बाइट-दर-बाइट प्रतिलिपि हो (जसले लाइसेन्स प्राधिकरण पनि रेकर्ड गर्छ); `PATCHES.md` ले स्थानीय प्याचहरूको सूची राख्छ (कुनै पनि छैन)। यो स्रोतका रूपमा उपभोग गरिन्छ, कुनै बिल्ड बिना: `next.config.mjs` ले यसलाई ट्रान्सपाइल गर्छ, र `tsconfig.json` ले `@omniroute/ui-kit` → `packages/ui-kit/src` र `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` म्याप गर्छ (`vitest.config.ts` र `vitest.mcp.config.ts` मा पनि उही एलियस छ)। किट कम्पोनेन्टलाई यसको सबपाथबाट इम्पोर्ट गर्नुहोस् (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), कहिल्यै पनि `@omniroute/ui-kit` ब्यारेलबाट होइन: ब्यारेलले हरेक कम्पोनेन्ट (डेट पिकर सहित) लाई प्रत्येक इम्पोर्टरमा तान्छ। किट स्टाइलसिट `src/app/globals.css` बाट प्रवेश गर्छ (`@import "../../packages/ui-kit/src/ci-ui.css"`)।
- **टोकनहरू।** `packages/ui-kit/src/ci-tokens.css` ले `--ci-*` टोकनहरू घोषणा गर्छ; `src/app/globals.css` ले तिनीहरूलाई लेगासी OmniRoute नामहरूसँग ब्रिज गर्छ (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`), त्यसैले अवस्थित `var(--color-*)` रिडहरू र Tailwind युटिलिटीहरू काम गरिरहन्छन्। नयाँ कोडले Tailwind युटिलिटीहरू (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) वा किट क्लासहरू प्रयोग गर्छ — कहिल्यै हेक्स मान होइन (`tests/unit/design-kit-bridge.test.ts` ले ब्रिजलाई इन्फोर्स गर्छ)। `text-primary` ले `--text-color-primary` मार्फत `--color-primary-ink` मा रिजोल्भ गर्छ (लाइटमा lime-800, डार्कमा लाइम एक्सेन्ट), त्यसैले प्राइमरी टेक्स्ट पढ्नयोग्य रहन्छ जबकि `bg-primary`/`border-primary` ले लाइम सतह कायम राख्छ। चार्ट शृङ्खलाहरूले `--color-chart-1` … `--color-chart-5` प्रयोग गर्छन्।
- **थिमहरू।** `<html className="ci-theme">` (`src/app/layout.tsx`) ले डकुमेन्टलाई किट थिममा अप्ट-इन गर्छ। प्राथमिकता `light`, `dark` वा `system` हुन्छ (`src/shared/constants/appConfig.ts` मा `THEME_CONFIG.defaultTheme = "system"`; `system` ले `prefers-color-scheme` पालना गर्छ)। `src/store/themeStore.ts` मा रहेको `applyTheme()` (जसलाई `src/app/layout.tsx` को इनलाइन बुटस्ट्र्याप स्क्रिप्टले मिरर गर्छ, जुन हाइड्रेसनअघि चल्छ) ले `data-theme="dark"|"light"` सेट गर्छ र `<html>` मा `.dark` क्लास एकैसाथ टगल गर्छ। किटको डार्क टोकन सेट `data-theme="dark"` मा आधारित छ (`packages/ui-kit/src/ci-tokens.css`); OmniRoute का आफ्नै डार्क ओभरराइडहरू (`globals.css` को `.dark` ब्लक) र लेगासी Tailwind `dark:` युटिलिटीहरू `.dark` क्लासमा आधारित छन्। कुनै एक्सेन्ट रङ प्रिसेटहरू छैनन्: एक्सेन्ट सधैं किटबाट आउँछ, र पुरानो बिल्डबाट पर्सिस्ट गरिएको प्रिसेट स्टोर लोड हुँदा हटाइन्छ।
- **कम्पोनेन्टहरू (एडाप्टरहरू)।** `src/shared/components/index.tsx` ले OmniRoute कम्पोनेन्ट API कायम राख्छ (उही नामहरू, डिफल्ट एक्सपोर्टहरू र प्रपहरू), र यसको पछाडि रहेका प्रिमिटिभहरू किटमाथिका एडाप्टरहरू हुन्: फारमहरू (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), ओभरले र फिडब्याक (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`), संरचना (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) र तालिकाहरू (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`)। एडाप्टरले किट कम्पोनेन्टलाई सबपाथबाट इम्पोर्ट गर्छ र लेगासी प्रपहरूलाई त्यसमा म्याप गर्छ — उदाहरणका लागि `Button variant="primary"` भनेको किट `default` बटन हो (`--ci-button-primary-*`: लाइटमा इन्भर्स सतह, डार्कमा यसको `--ci-color-accent-foreground` इङ्क सहितको एक्सेन्ट), `danger` भनेको `destructive` हो, र `warning` भनेको `outline` प्लस `.ci-button--warning` एक्सटेन्सन हो। `globals.css` को अन्त्यमा रहेका `.ci-button--warning` र `.ci-badge[data-tone]` नियमहरू (`@layer components`) किट क्लासहरूमाथिका OmniRoute एक्सटेन्सनहरू हुन्। `tests/unit/ui/adapters/*.test.tsx` ले प्रत्येक एडाप्टरलाई पिन गर्छ।
- **सेल।** `src/app/(dashboard)/layout.tsx` ले `DashboardLayout` रेन्डर गर्छ, जसले `src/shared/components/layouts/DashboardShell.tsx` रेन्डर गर्छ: किट `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), जसमा OmniRoute को नेभिगेसन लजिक `src/shared/components/Sidebar.tsx` मा रहन्छ। `#main-content` तर्फको "सामग्रीमा जानुहोस्" लिङ्क पहिलो फोकसयोग्य तत्व हो। `src/shared/components/Header.tsx` मा किट `SidebarTrigger` (सेलको एकमात्र साइडबार टगल), Keak `ProductSwitcher` र कमान्ड-प्यालेट ओपनर हुन्छन्; यसले रूट शीर्षक तब मात्र देखाउँछ जब `#main-content` भित्र कुनै किट `PageHeader` (`.ci-page-header`) माउन्ट भएको हुँदैन, त्यसैले आफ्नै `PageHeader` भएको पेजमा एउटै `h1` हुन्छ। `src/shared/components/CommandPalette.tsx` भनेको किट `Dialog` हो।
- **आइकनहरू।** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) ले नामलाई (स्क्रिनहरूले प्रयोग गर्ने Material Symbols शब्दावली) `ICON_MAP` (`src/shared/constants/iconMap.ts`) मार्फत Lucide ग्लिफमा रिजोल्भ गर्छ। Material Symbols फन्ट र प्याकेज हटाइएका छन्: नक्सामा नभएको नामले तटस्थ प्लेसहोल्डर ग्लिफ रेन्डर गर्छ (`data-icon-missing="true"`) र प्रोडक्सन बाहिर कन्सोल चेतावनी लग गर्छ। `npm run gen:icon-map` ले प्रयोगमा रहेका तर नक्सामा नभएका नामहरू प्रिन्ट गर्छ (`tests/unit/icon-map-coverage.test.ts` Lucide आइकन नभएको कुनै पनि नाममा फेल हुन्छ; `tests/unit/icon-map-object-values.test.ts` ले लुकअप अब्जेक्टहरूमा भण्डारण गरिएका नामहरू कभर गर्छ); `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` ले लिटरल `<span className="material-symbols-outlined">` स्प्यानहरूलाई `<Icon>` मा रिराइट गर्छ।
- **ब्रान्ड।** `src/shared/components/OmniRouteLogo.tsx` ले किटलाई र्याप गर्छ: डिफल्ट एक्सपोर्ट `OmniRouteLogo` ले `ProductIcon product="omniroute" variant="glyph"` (इनलाइन SVG, `basePath`-सेफ) रेन्डर गर्छ र `OmniRouteLockup` ले `ProductLockup product="omniroute"` (पहुँचयोग्य नाम "Keak OmniRoute") वा, ह्वाइट-लेबल अपरेटरहरूका लागि, तिनीहरूको आफ्नै `name`/`logoSrc` रेन्डर गर्छ। प्रोडक्ट-स्विचर गन्तव्यहरू `src/shared/constants/keakProducts.ts` मा रहन्छन् (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`)। स्ट्यान्डअलोन स्क्रिनहरू — `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`, `src/app/offline/page.tsx`, `src/app/not-found.tsx` र `src/shared/components/ErrorPageScaffold.tsx` — ले लकअप देखाउँछन्; `tests/unit/brand-pages-static.test.ts` ले यसलाई गार्ड गर्छ।

## २. नियमहरू

1. टोकनहरू, कहिल्यै लिटरलहरू होइनन्। जानाजान राखिएका अपवादहरू: सधैँ-गाढा रहने कन्सोल टर्मिनल, `STATUS_HEX` (`src/shared/constants/statusColors.ts`) मार्फत ReactFlow SVG स्ट्रोकहरू, र श्रेणीगत पालेटहरू `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) तथा `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`)।
2. `packages/ui-kit/src` लाई कहिल्यै हातले प्याच नगर्नुहोस्: `scripts/dev/sync-ui-kit.sh <commit>` बाट सिङ्क गर्नुहोस्; प्रि-कमिट गेट `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) पिन गरिएको अपस्ट्रिम कमिटबाट फरक हुने कुनै पनि बाइटमा फेल हुन्छ (अपस्ट्रिम क्लोन, `UI_KIT_CLONE` वा `_references/cheaper-inference-ui-kit`, उपलब्ध छैन भने चेतावनीसाथ स्किप गर्छ)। किटमा केही कुरा छैन भने, एडाप्टर वा स्क्रिनमा वर्कअराउन्ड गर्नुहोस् र त्यसका लागि अपस्ट्रिमलाई अनुरोध गर्नुहोस्।
3. किट टेक्स्ट डिफल्टहरू अङ्ग्रेजी हुन् (`label = "Loading"`, `loadingLabel = "Loading table"`…) — किट कम्पोनेन्टले टेक्स्ट रेन्डर गर्ने हरेक ठाउँमा `useTranslations(...)` बाट अनुवादित स्ट्रिङहरू पास गर्नुहोस्।
4. Tailwind युटिलिटीहरू किट कम्पोनेन्ट क्लासहरूभन्दा माथि पर्छन् (किटले `@layer theme, base, components, utilities` घोषणा गर्छ र यसका नियमहरू `components` मा बस्छन्) — स्पेसिङ र लेआउटका लागि युटिलिटीहरू प्रयोग गर्नुहोस्, किट कम्पोनेन्टहरूलाई पुनः रङ दिनका लागि होइन।
5. शीर्षकहरू: पेज तथा सेक्सन शीर्षकहरूका लागि `.ci-heading` (Inter, ट्र्याकिङ बिना); एरर-पेज स्ट्याटस कोडजस्ता ठूला, विरल डिस्प्ले टेक्स्टका लागि मात्र `.ci-dashboard-display` (Instrument Serif)।
6. `tests/unit/dashboard-kit-sweep.test.ts` ले किट अपनाइएको कुराको निगरानी गर्छ: `src/app` वा `src/shared/components` मुनि कुनै Material ligature स्पान हुनु हुँदैन; ड्यासबोर्ड ट्री (`src/app/(dashboard)` र `src/shared/components`) भित्र कुनै कच्चा `<select>`, `<textarea>` वा `<table>` हुनु हुँदैन र सूचीबद्ध अपवादहरू (`Select` एडाप्टरको नेटिभ ब्रान्च, `RequestLoggerDetail`) बाहिर हातले बनाइएको `role="dialog"` पनि हुनु हुँदैन; त्यहाँको हरेक कच्चा `<button>` वा `<input>` माथि बढीमा ३ लाइनको दूरीमा सकिएको, `kit-exception:` (कारणसहित) भएको कमेन्ट चाहिन्छ; पालेट ह्युहरू र `dark:` भेरियन्टहरू परीक्षणले सूचीबद्ध गरेका फाइलहरूमा मात्र।
7. PR अघि दुवै थीमहरू र 390 px भ्युपोर्ट प्रमाणित गर्नुहोस् (स्क्रिनसटहरू); `tests/e2e/a11y.spec.ts` ले axe चलाउँछ।

## ३. स्क्रिन थप्ने तरिका

1. पेजलाई किट `PageHeader` (`@omniroute/ui-kit/page-header`, ड्यासबोर्ड भित्र `compact`) बाट सुरु गर्नुहोस् — शीर्षक, विवरण र `actions`। त्यसपछि शेल हेडरले आफ्नै शीर्षक हटाउँछ।
2. `@/shared/components` (एडाप्टरहरू) बाट कन्ट्रोलहरू बनाउनुहोस् र एडाप्टर नभएको ठाउँमा सबपाथबाट किट कम्पोनेन्टहरू प्रयोग गर्नुहोस् (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`, `RadioGroup`, `Slider`…)।
3. आइकनहरू: `<Icon name="…" />`। नयाँ नाम अर्थअनुसार मिल्ने Lucide कम्पोनेन्टसँग `ICON_MAP` मा राखिन्छ; `npm run gen:icon-map` ले अझै छुटेका नामहरूको सूची दिन्छ।
4. रङहरू: सिम्यान्टिक युटिलिटीहरू (`text-success`, `bg-warning-bg`, `border-border`…) र चार्ट सिरिजका लागि `var(--color-chart-N)`; कुनै hex मानहरू होइनन् र रङलाई मात्र दोहोर्याउने `dark:` भेरियन्टहरू पनि होइनन्।
5. टेक्स्ट: किट कम्पोनेन्टहरूमा पास गर्ने लेबलहरूसहित हरेक स्ट्रिङ `useTranslations` बाट आउँछ। नयाँ कुञ्जीहरू `src/i18n/messages/en.json`, `pt-BR.json` र `vi.json` मा राखिन्छन् (भियतनामी पारिटी परीक्षणले हरेक अङ्ग्रेजी कुञ्जीलाई पिन गर्छ); बाँकी लोकेलहरू i18n सिङ्कले भरिदिन्छ।
6. PR अघि गार्डहरू चलाउनुहोस्: `tests/unit/dashboard-kit-sweep.test.ts`, `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`, `npm run check:dashboard-typecheck` (`iconMap.ts` मा दोहोरिएको इम्पोर्ट समात्ने एकमात्र जाँच), `npm run check:ui-icu`, र स्क्रिनका आफ्नै परीक्षणहरू।

## 4. एडाप्टर थप्ने वा परिवर्तन गर्ने

1. `src/shared/components/index.tsx` को सार्वजनिक API उही राख्नुहोस्: उही export नामहरू, default exports र
   स्वीकार गरिने props। Adapter भित्र legacy props लाई kit मा म्याप गर्नुहोस् (`Button.tsx` हेर्नुहोस्: `VARIANT_TO_KIT`,
   `SIZE_TO_KIT`)।
2. Kit लाई subpath (`@omniroute/ui-kit/<component>`) बाट import गर्नुहोस्।
3. Kit का कमीहरूका workaround हरू adapter मा राख्नुहोस् (वा समाधान style भएमा `globals.css` को `@layer components`
   मा), कहिल्यै पनि `packages/ui-kit/src` मा होइन।
4. `tests/unit/ui/adapters/<name>.test.tsx` थप्नुहोस् वा अपडेट गर्नुहोस्। धेरै callers भएको adapter का लागि,
   परिवर्तनअघि र परिवर्तनपछिको rendered markup तुलना गर्नुहोस् — padding वा wrapper परिवर्तनहरू हरेक screen सम्म फैलिन्छन्।

## 5. Kit अपडेट गर्ने

`scripts/dev/sync-ui-kit.sh <commit> [clone]` ले त्यस commit को upstream `src/` लाई
`packages/ui-kit/src` मा कपी गर्छ र अनुमति दिइएको एकल रूपान्तरण लागू गर्छ (यसले
relative imports बाट `.js` suffix हटाउँछ)। त्यसपछि: `git diff packages/ui-kit` को समीक्षा गर्नुहोस्, दुवै themes मा providers, settings, combos,
usage र endpoint को visual जाँच गर्नुहोस्, `npm run check:ui-kit-snapshot` र `npm run test:vitest:ui` चलाउनुहोस्, र
upstream changelog सहित PR खोल्नुहोस्।
