`devin-cli-agentic` ले वास्तविक Claude Code runtime लाई OmniRoute को स्थानीय Anthropic
Messages endpoint प्रयोग गर्न दिन्छ, जबकि आधिकारिक Devin CLI ले ACP stdio मार्फत मोडेलका
प्रतिक्रियाहरू उपलब्ध गराउँछ। यसले विद्यमान Anthropic, Claude OAuth, Claude Web वा
`devin-cli` प्रदायकहरूलाई परिमार्जन गर्दैन।

क्लाइन्ट-स्वामित्वका tool call हरूका लागि, Claude-format को tool-सक्षम प्रदायक
`devin-cli-agentic` (उपनाम `dva`) मार्फत route गर्नुहोस्। पुरानो `devin-cli` (`dv`) ACP
executor text-only हो: यसले Devin को no-tools summarizer चलाउँछ र tool call हरू फर्काउन
सक्दैन। यसको मोडेल metadata पनि सोहीअनुसार चिन्हित गरिएको छ, जसले गर्दा tool आवश्यक पर्ने
combo routing ले यसलाई बेवास्ता गर्नेछ।

> **हालको स्थिति: Claude Code `2.1.258` मा pin गरिएको; पछिल्लो offline र live validation
> `2.1.220` मा अभिलेख गरिएको थियो।** `2.1.220` pin ले Devin CLI `3000.2.17` र मोडेल
> `swe-1-7-lightning` मार्फत तीनवटा अलग-अलग scenario पूरा गर्यो; उक्त अन्तिम live run ले
> क्लाइन्ट-स्वामित्वका `Read`, `Edit`, र `Bash` turn, सफल `npm test` परिणाम, project command
> र skill discovery, Devin-only routing, तथा शून्य Claude egress प्रमाणित गर्यो। त्यसपछि pin
> लाई `2.1.258` मा बढाइयो (OmniRoute को Claude identity ले प्रतिरूपण गर्ने CLI generation,
> र Fable 5.1 tier लाई native रूपमा उपलब्ध गराउने पहिलो संस्करण-शृंखला)। नयाँ pin मा pinned
> base image माथि install layer र `claude --version` प्रमाणित गरिए, र bridge unit suite,
> `compose config` तथा static isolation proof पास हुन्छन् — तर offline mock scenario र live
> three-scenario suite अझै पुनः चलाइएका छैनन्। यो pin सँग bridge मा निर्भर हुनुअघि तिनलाई
> पुनः चलाउनुहोस् ("Updating pinned tools" हेर्नुहोस्)।

## आर्किटेक्चर

```text
Claude Code 2.1.258 (अलग गरिएको non-root Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format, प्रमाणीकरण नचाहिने प्रदायक)
  -> devin acp --agent-type summarizer (आधिकारिक ACP stdio, Devin tools रहित)
  -> समर्पित devin-auth volume मा रहेको Devin account
```

आधिकारिक CLI को default ACP agent ले आफ्नै tools चलाउन सक्छ, त्यसैले यो bridge ले त्यसलाई
प्रयोग गर्दैन। यसले tools नभएको आधिकारिक CLI mode सहितको निश्चित `summarizer` ACP agent
सुरु गर्छ र serialized Anthropic request लाई execution trace का रूपमा frame गर्छ। Claude
कै स्वामित्वमा रहेको अर्को action आवश्यक हुँदा, response मा ठ्याक्कै एउटा client tool
envelope हुनुपर्छ। कुनै पनि ACP `tool_call` वा `tool_call_update` लाई response सफल भएको
रिपोर्ट गर्नुअघि अस्वीकार गरिन्छ।

`open-sse/executors/devin-agentic/serializer.ts` मा रहेको serializer ले `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, र Claude
Code ले उपलब्ध गराएका tools लाई जस्ताको तस्तै राख्छ। Images र अज्ञात blocks स्पष्ट रूपमा
असफल हुन्छन्। ठूला tool results ले देखिने truncation marker प्रयोग गर्छन्।

Parser ले प्रत्येक model turn मा एउटा मात्र standalone `<tool>{...}</tool>` envelope
स्वीकार गर्छ। यसले request को tool list सँग name जाँच गर्छ, उक्त tool को JSON Schema
अनुसार arguments validate गर्छ, narrative र actions को मिश्रण अस्वीकार गर्छ, र एउटा
सीमित repair प्रयास अनुमति दिन्छ। त्यसपछि Claude Code ले नतिजास्वरूप प्राप्त Anthropic
`tool_use` लाई स्थानीय रूपमा execute गर्छ र `tool_result` लाई OmniRoute मार्फत फिर्ता
पठाउँछ।

## स्वचालित routing

यो प्रदायक block नगरिएको अवस्थामा OmniRoute का `auto/*` candidate pools का लागि योग्य
हुन्छ। Candidate eligibility ले चयनको सुनिश्चितता गर्दैन: combo को routing strategy (उदाहरणका
लागि, last-known-good) ले अर्को प्रदायकलाई प्राथमिकता दिन सक्छ। प्रत्येक request Devin
मार्फत नै जानुपर्ने भए `dva/<model>` वा Devin-first combo प्रयोग गर्नुहोस्।

## पृथकीकरण र जोखिम मोडेल

होस्टको Claude स्थापना, खाता र कन्फिगरेसन कार्यक्षेत्रबाहिर छन् र तिनलाई
निषेधित मानिन्छ। Compose सेवाहरूले:

- UID/GID `10001:10001` का रूपमा, पढ्न-मात्र मिल्ने मूल फाइल प्रणाली, हटाइएका क्षमताहरू र
  `no-new-privileges` सहित सञ्चालन गर्छन्;
- निजी `/home/bridge`, समर्पित Claude कन्फिगरेसन भोल्युम, पृथक OmniRoute डेटा
  र छुट्टै `devin-auth` भोल्युम प्रयोग गर्छन्;
- प्रयोगपछि हटाउन मिल्ने `.sandbox` कार्यक्षेत्र/प्रमाण मात्र माउन्ट गर्छन्;
- होस्टको होम, Keychain, SSH, क्लाउड प्रमाणपत्र वा Docker socket माउन्ट गर्दैनन्;
- स्पष्ट वातावरणहरू निर्माण गर्छन् र Anthropic API/OAuth/राउटिङ चरहरू हटाउँछन्;
- Claude Code अनुमानलाई स्थानीय-मात्र कुञ्जीसहित `http://omniroute:20128` मा मात्र निर्देशित गर्छन्।

अफलाइन प्रोफाइलले आन्तरिक नेटवर्क प्रयोग गर्छ। लाइभ प्रोफाइलमा, OmniRoute ले
`network-guard` मार्फत मात्र आधिकारिक Devin एन्डपोइन्टहरूमा पहुँच गर्छ; असम्बन्धित गन्तव्यहरू अस्वीकार गरिन्छन्।
Claude Code सँग छुट्टै सबै बहिर्गमन अस्वीकार गर्ने गार्ड छ र त्यसले `NO_PROXY` मार्फत स्थानीय OmniRoute
सेवामा मात्र पहुँच गर्न सक्छ। गार्ड अडिट फाइलहरू तिनको गार्ड प्रक्रियाद्वारा मात्र माउन्ट गरिन्छन्।
स्क्रिप्टहरूले टोकन-रहित प्रमाण निर्यात गर्नुअघि फाइल स्वामित्व, मोड, लिङ्क सङ्ख्या र प्रत्येक निर्णय
प्रमाणित गर्छन्।

पृथकीकरणको प्रमाण स्वतन्त्र रूपमा चलाउनुहोस्:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

यसले टोपोलोजी, नाम दिइएका माउन्टहरू, non-root/पढ्न-मात्र सेटिङहरू, स्पष्ट स्थानीय राउटिङ,
संवेदनशील वातावरणीय चरहरूको अनुपस्थिति, Docker socket को अनुपस्थिति,
`api.anthropic.com` र `claude.ai` मा रोकिएको पहुँच, Devin-मात्र प्रदायक चयन, र
ACP ब्याकएन्ड अनुपलब्ध हुँदा हुने स्पष्ट विफलता प्रमाणित गर्छ।

## पहिलो पटकको सेटअप र सामान्य प्रयोग

पिन गरिएको इमेज निर्माण गर्नुहोस्:

```bash
./scripts/devin-bridge/build
```

पृथक Devin भोल्युमलाई मात्र प्रमाणीकरण गर्नुहोस्:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

लगइन कमान्डले रिमोट/कन्टेनर वातावरणका लागि बनाइएको आधिकारिक म्यानुअल-टोकन प्रवाह
प्रयोग गर्छ। मान सिधै CLI प्रम्प्टमा प्रविष्ट गरिन्छ; यसलाई प्रक्रिया आर्गुमेन्टका रूपमा
पठाइँदैन, Git मा लेखिँदैन वा होस्टबाट प्रतिलिपि गरिँदैन।

पृथक Claude Code रनटाइम सुरु गर्नुहोस्:

```bash
./scripts/devin-bridge/launch
```

`launch` ले कन्टेनरमा रहेको Claude Code सुरु गर्नुअघि पृथकीकरण, Devin प्रमाणीकरण र मोडेल
खोज पुनः जाँच गर्छ। यसले होस्टको Claude executable कहिल्यै चलाउँदैन। मोडेल उपनामहरू
`.env.devin-bridge` मा सेट गर्न सकिन्छ; कन्फिगर गरिएको प्रत्येक मानमा
`devin-cli-agentic/` उपसर्ग कायमै हुनुपर्छ।

## प्रमाणीकरण कमान्डहरू

पुनरुत्पादनयोग्य अफलाइन मार्गलाई Devin खाता आवश्यक पर्दैन र यसमा रनटाइम इन्टरनेट हुँदैन:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

प्रमाणीकरण गरिएको, स्वेच्छाले सक्षम गर्नुपर्ने लाइभ मार्ग यस्तो छ:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

लाइभ रनरले एकैचोटि धेरै ACP सत्रहरू नखोलियोस् भनेर परिदृश्यहरूबीच प्रतीक्षा गर्छ र
पाठ्य दाबीहरूमा विश्वास गर्नुको सट्टा संरचित Claude स्ट्रिम घटनाहरू प्रमाणित गर्छ। यसका तीन
परिदृश्यहरूले निम्न कुरा प्रमाणित गर्छन्:

1. प्रत्यक्ष परियोजना पढाइ र त्रुटि विश्लेषण;
2. वास्तविक `Edit`, क्लाइन्ट-स्वामित्वको `Bash` `npm test`, र अन्तिम परिणाम;
3. `/bridge-check` साथै `bridge-proof` खोज, परियोजना पढाइ, अर्को सफल
   क्लाइन्ट-स्वामित्वको `npm test`, र बाँकी कामविना पूर्णता।

अन्तिम गेटले Devin नेटवर्क अडिट पनि जाँच गर्छ र Claude बहिर्गमन अडिट खाली नै रहनु
आवश्यक ठान्छ।

## पिन गरिएका उपकरणहरू अद्यावधिक गर्ने

इमेजले Node, Claude Code र Devin CLI लाई
`docker/devin-bridge/Dockerfile` मा पिन गर्छ। अद्यावधिक गर्न:

1. स्पष्ट रूपमा तोकिएका संस्करणहरू परिवर्तन गर्नुहोस्;
2. दुवै आर्किटेक्चर-विशिष्ट Devin अभिलेखका चेकसमहरू आधिकारिक
   आर्टिफ्याक्टका मानहरूले प्रतिस्थापन गर्नुहोस्;
3. पुनः निर्माण गर्नुहोस् र प्रत्येक अफलाइन प्रमाणीकरण कमान्ड चलाउनुहोस्;
4. इमेजभित्रका संस्करणहरू पुष्टि गर्नुहोस्;
5. प्रमाणीकरण आवश्यक पर्ने तीन-परिदृश्यको लाइभ सुइट पुनः चलाउनुहोस्।

कुनै पनि CLI लाई होस्टमा विश्वव्यापी रूपमा स्थापना नगर्नुहोस् वा चेकसम प्रमाणीकरणलाई
अप्रमाणित डाउनलोडले प्रतिस्थापन नगर्नुहोस्।

## निदान र सफाइ

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  ले स्थानीय राउटिङ र संवेदनशील विवरण हटाइएका एक्जिक्युटर त्रुटिहरू देखाउँछ।


## सीमाहरू

- ब्रिज निश्चित no-tools `summarizer` भूमिकामा निर्भर हुन्छ, किनभने Devin CLI `3000.2.17`
  ले तटस्थ no-tools ACP एजेन्ट उपलब्ध गराउँदैन। एडाप्टरले सारांश-जस्ता मध्यवर्ती
  प्रतिक्रियाहरूको क्षतिपूर्ति गर्छ, तर एउटा सीमित मर्मत अझै पनि स्पष्ट रूपमा असफल हुन सक्छ।
- लाइभ ACP कलहरूले अस्थायी `502`/`504` प्रतिक्रियाहरू फर्काउन सक्छन्। हार्नेसले परिदृश्यहरूबीच
  अन्तराल राख्छ; निरन्तर विफलतामा प्रणाली सुरक्षित रूपमा बन्द रहन्छ र कहिल्यै अर्को प्रदायक चयन गर्दैन।
- ACP सन्दर्भ प्रत्येक Anthropic अनुरोधबाट पुनर्निर्माण गरिन्छ; कुनै प्रक्रिया/सेसन
  आबद्धता छैन।
- प्रत्येक मोडेल प्रतिक्रियामा एउटा उपकरण कल समर्थित छ; समानान्तर कलहरू अस्वीकार गरिन्छन्।
- इमेजहरू स्पष्ट रूपमा असमर्थित छन्। भिजन, थिङ्किङ आउटपुट, प्रयास नियन्त्रण र 1M
  सन्दर्भ विन्डोको विज्ञापन गरिँदैन।
- SSE ले मान्य Anthropic जीवनचक्र इभेन्टहरू प्रयोग गर्छ, तर सीमित ACP टर्न सङ्कलन भएपछि
  मात्र उत्सर्जित हुन्छ; ACP खण्डहरू क्रमिक रूपमा फर्वार्ड गरिँदैनन्।
