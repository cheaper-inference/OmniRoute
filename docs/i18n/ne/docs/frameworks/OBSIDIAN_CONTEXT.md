## यो के हो

OmniRoute ले **Obsidian** भल्टलाई **सन्दर्भ स्रोत** का रूपमा जडान गर्छ — यो स्थानीय Markdown
ज्ञानकोष हो, जसलाई एजेन्टहरूले अन्तर्निर्मित MCP सर्भरमार्फत पढ्न र लेख्न सक्छन्। यो
एकीकरणले डेस्कटप एपभित्र चलिरहेको **Obsidian Local REST API** सामुदायिक प्लगइनसँग
सञ्चार गर्छ, जसले एजेन्टहरूलाई नोट खोज्न, फाइलहरू पढ्न/लेख्न/प्याच गर्न, भल्टको सूची हेर्न,
दैनिक/साप्ताहिक आवधिक नोटहरूसँग काम गर्न, ट्यागहरू व्यवस्थापन गर्न, Obsidian कमान्डहरू
चलाउन, र (वैकल्पिक रूपमा) द्विदिशात्मक डेस्कटप↔मोबाइल भल्ट सिंक समन्वय गर्न दिन्छ।

क्लाइन्ट (`src/lib/obsidian/api.ts`) ले Local REST API लाई निम्न सुविधासहित र्याप गर्छ:

- अस्थायी `5xx` का लागि **ब्याकअफसहित पुनः प्रयास**, `AbortController` मार्फत **30-सेकेन्ड टाइमआउट**।
- **टाइप गरिएको त्रुटि वर्गीकरण** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`।
- सामान्य पोर्टसम्बन्धी गल्ती (HTTP `27123` मा, `27124` को MCP एन्डपोइन्टमा **होइन**) र
  Tailscale ढाँचा औँल्याउने प्रयोगकर्तामैत्री **"Obsidian सम्म पुग्न सकिएन" सङ्केत**।
- खाली ठाउँ/स्ल्यास भएका नोट पथहरू सुरक्षित राख्न भल्ट-सापेक्ष **पथ इन्कोडिङ**।

## सेटअप

Obsidian टोकन वा आधार URL का लागि **कुनै environment variable छैन** — दुवैलाई
`src/lib/db/obsidian.ts` मार्फत SQLite को `key_value` तालिका (namespace `obsidian`) मा
भण्डारण गरिन्छ। टोकनलाई **भण्डारण अवस्थामा एन्क्रिप्ट गरिएको हुन्छ** (AES-256-GCM,
plaintext backward-compat fallback सहित)। Endpoint dashboard को **Context Sources**
ट्याब (`ObsidianSourceCard`) बाट वा settings REST API मार्फत कन्फिगर गर्नुहोस्।

> [!IMPORTANT]
> **Obsidian Local REST API** plugin स्थापना गरिएको र चलिरहेको हुनुपर्छ। यसको REST
> interface ले **HTTP `127.0.0.1:27123`** (पूर्वनिर्धारित आधार URL) मा सुन्छ। पोर्ट `27124`
> एउटा _छुट्टै_ MCP/HTTPS endpoint हो र settings route द्वारा स्पष्ट रूपमा अस्वीकार गरिन्छ।
> अर्को device बाट जडान गर्दा `http://<tailscale-ip>:27123` प्रयोग गर्नुहोस्।

### कन्फिगरेसन कुञ्जीहरू (SQLite `key_value`, namespace `obsidian`)

| कुञ्जी            | उद्देश्य                                                | एन्क्रिप्टेड |
| ----------------- | ------------------------------------------------------- | ------------ |
| `api_key`         | Local REST API bearer token                             | हो           |
| `base_url`        | REST आधार URL (पूर्वनिर्धारित `http://127.0.0.1:27123`) | होइन         |
| `vault_path`      | vault directory को absolute path (sync का लागि)         | होइन         |
| `webdav_username` | उत्पन्न गरिएको WebDAV username (vault sync)             | होइन         |
| `webdav_password` | उत्पन्न गरिएको WebDAV password (vault sync)             | हो           |
| `webdav_enabled`  | WebDAV vault sync सक्षम छ कि छैन                        | होइन         |

### REST मार्फत कन्फिगर गर्नुहोस्

```bash
# Local REST API टोकन सुरक्षित गर्नुहोस् र प्रमाणीकरण गर्नुहोस् (POST ले status check मार्फत प्रमाणीकरण गर्छ)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# connection status जाँच गर्नुहोस् (connected, hasToken, baseUrl, vaultPath फर्काउँछ)
curl http://localhost:20128/api/settings/obsidian

# जडान विच्छेद गर्नुहोस् (भण्डारण गरिएको टोकन हटाउँछ)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

सबै विधिहरूलाई dashboard authentication आवश्यक पर्छ। `POST` ले पोर्ट `27124` मा भएको
कुनै पनि URL अस्वीकार गर्छ र भण्डारण गर्नुअघि Local REST API status endpoint लाई call
गरेर टोकन प्रमाणीकरण गर्छ।

### WebDAV vault sync

`src/app/api/settings/obsidian/webdav/route.ts` ले वैकल्पिक WebDAV-backed vault sync
व्यवस्थापन गर्छ (`src/lib/obsidianSync.ts` द्वारा सञ्चालित)। यसलाई सक्षम गर्दा OmniRoute
लाई local vault directory तर्फ निर्देशित गरिन्छ र एउटा random WebDAV username/password
जोडी सिर्जना गरिन्छ:

```bash
# vault directory का लागि WebDAV sync सक्षम गर्नुहोस् (username/password सिर्जना गर्छ)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV sync status प्राप्त गर्नुहोस् (सक्षम हुँदा मात्र credentials फर्काइन्छ)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV sync असक्षम गर्नुहोस् (credentials + व्यवस्थित .stignore हटाउँछ)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### सुरक्षा र यातायात

WebDAV प्रमाणीकरणले प्रति-IP असफलता ट्र्याकिङ र लकआउट लागू गर्दछ (60-सेकेन्ड विन्डो भित्र 10 असफल प्रयासहरूले `429 Too Many Requests` र `Retry-After` सँग 5-मिनेट लकआउट ट्रिगर गर्दछ)। WebDAV आधारभूत प्रमाणीकरण प्रमाणहरू प्रसारण गरेको हुनाले, लुपब्याक बाहिर WebDAV अन्तिम बिन्दुमा पहुँच गर्दा TLS (वा सुरक्षित सुरुङ जस्तै Tailscale वा Cloudflare Tunnel माथि राउटिङ) बन्द गर्न सिफारिस गरिन्छ।

### प्रति-API-key context source (वैकल्पिक)

Obsidian config लाई `api_key_context_sources` तालिका
(`src/lib/db/apiKeyContextSources.ts`) मार्फत **प्रत्येक API key अनुसार** सीमित गर्न सकिन्छ।
जब MCP call मा प्रमाणीकृत API key id हुन्छ, `getObsidianConfigForApiKey()` ले त्यो key को
आफ्नै token/base-URL/vault-path (`source: "api_key"`) लाई प्राथमिकता दिन्छ र अन्यथा global
config (`source: "global"`) प्रयोग गर्छ।

Non-sync MCP tools लाई यो कन्फिगरेसन पढ्नुअघि समाधान गरिएको caller identity आवश्यक पर्छ।
identity नभएको caller ले `Obsidian API token not configured` प्राप्त गर्छ र कुनै पनि vault
request पठाइँदैन। HTTP callers आफ्ना request credentials मार्फत समाधान हुन्छन्; stdio callers
लाई `OMNIROUTE_API_KEY` वा `ROUTER_API_KEY` मार्फत समाधान गर्न सकिन्छ। समाधान नभएको HTTP
caller ले server को environment identity प्रयोग गर्न सक्दैन। Placeholder IDs मात्रले access
authorize गर्दैनन्; `env-key` मा समाधान हुने मान्य environment credential अझै समर्थित छ।
प्रति-key Obsidian configuration नभएका प्रमाणीकृत keys ले global fallback कायम राख्छन्।
चारवटा `obsidian_sync_*` tools ले आफ्ना छुट्टै sync-token behavior कायम राख्छन्।

## MCP उपकरण (22)

`open-sse/mcp-server/tools/obsidianTools.ts` मा परिभाषित। token/base-URL प्रति कल समाधान गरिन्छ (प्रति-एपीआई-कुञ्जी पहिले, त्यसपछि विश्वव्यापी)। OmniRoute लाई हिट गर्ने उपकरणहरू** सिंक सर्भर** (चार `obsidian_sync_*` उपकरणहरू) थप रूपमा OmniRoute सेटिङहरूमा कन्फिगर गरिएको सिङ्क प्रमाणीकरण टोकन आवश्यक छ।

| `obsidian_move_note`             | भल्ट भित्र एउटा नोट सार्नुहोस् वा पुन: नामाकरण गर्नुहोस्।                                     |
| `obsidian_execute_command`       | यसको आदेश ID द्वारा Obsidian आदेश कार्यान्वयन गर्नुहोस्।                                      |
| `obsidian_open_file`             | Obsidian मा फाइल खोल्नुहोस् (यदि यो अवस्थित छैन भने सिर्जना गर्दछ)।                           |
| `obsidian_sync_trigger`          | तत्काल द्विदिशात्मक डेस्कटप ↔ मोबाइल भल्ट सिंक ट्रिगर गर्नुहोस्।                              |
| `obsidian_sync_resolve_conflict` | सिंक विवाद समाधान गर्नुहोस्: `local` (मोबाइल), `remote` (डेस्कटप), वा `keep-both` राख्नुहोस्। |

> [!NOTE]
> `obsidian_patch_note` लक्ष्यहरूले `heading | block | frontmatter` को `targetType` र `append | prepend | replace` को `operation` स्वीकार गर्दछ, वैकल्पिक `createTargetIfMissing` संग। चार `obsidian_sync_*` उपकरणहरूले स्थानीय सिङ्क सर्भरसँग कुरा गर्छ (पूर्वनिर्धारित रूपमा`http://127.0.0.1:27781` ) र सिङ्क टोकन आवश्यक छ।

### स्कोपहरू

पढ्ने उपकरणहरूलाई `read:obsidian` चाहिन्छ; लेखन उपकरणहरू `write:obsidian` चाहिन्छ। प्रवर्तन `open-sse/mcp-server/server.ts` मा `withScopeEnforcement()` द्वारा ह्यान्डल गरिएको Notion — सँग मिल्दोजुल्दो छ, `OMNIROUTE_MCP_ENFORCE_SCOPES=true` मा गेट गरिएको छ र API कुञ्जीमा `manage`/`admin` छैन, `OMNIROUTE_MCP_SCOPES` वा API कुञ्जीको स्कोप सन्दर्भबाट प्राप्त अनुमति स्कोपहरू सहित HTTP/SSE कलरहरूका लागि जबरजस्ती। [MCP-SERVER.md](./MCP-SERVER.md) हेर्नुहोस्।

## प्रयोगका अवस्थाहरू

- **भल्टमा आधारित उत्तरहरू** — `obsidian_search_simple` / `obsidian_search_structured`
  र त्यसपछि `obsidian_read_note`, जसले गर्दा एजेन्टले तपाईंका वास्तविक नोटहरूबाट उत्तर दिन्छ।
- **नोट लेखन / जर्नलिङ** — एजेन्टको आउटपुट, सारांश वा दैनिक नोटहरू
  (`obsidian_get_periodic_note`) भल्टमा अभिलेख गर्न `obsidian_write_note`, `obsidian_append_note`, वा
  सूक्ष्म सम्पादनका लागि `obsidian_patch_note`।
- **भल्ट नेभिगेसन** — पढ्नु/लेख्नुअघि संरचना अन्वेषण गर्न `obsidian_list_vault`, `obsidian_get_document_map`, र
  `obsidian_get_tags`।
- **Obsidian स्वचालन** — एजेन्टबाट प्लगइन/कमाण्डहरू सञ्चालन गर्न `obsidian_list_commands` + `obsidian_execute_command`;
  UI मा नोट देखाउन `obsidian_open_file`।
- **मोबाइल सिंक** — WebDAV सिंक सक्षम गर्नुहोस्, त्यसपछि डेस्कटप↔मोबाइल समन्वय गर्न र द्वन्द्वहरू समाधान गर्न
  `obsidian_sync_trigger` / `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`।
