Traffic Inspector ir OmniRoute iebūvētais HTTPS datplūsmas atkļūdotājs — Charles Proxy / mitmweb / HTTP Toolkit līdzīgs rīks, kas **izprot LLM** un **aģentus**. Tas atrodas `/dashboard/tools/traffic-inspector` un saņem datplūsmu reāllaikā no līdz pat 5 vienlaicīgiem tveršanas avotiem.

**Atrašanās vieta informācijas panelī:** `/dashboard/tools/traffic-inspector`
**Sānjoslas grupa:** Rīki (pēc AgentBridge)
**Skatiet arī:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge ir 1. tveršanas režīms.

### Arhitektūra vienā rindkopā

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) ir koplietots atmiņā glabāts gredzenbuferis (pēc noklusējuma 1000 ierakstu; konfigurējams, izmantojot `INSPECTOR_BUFFER_SIZE`). Visi tveršanas avoti tajā raksta, izmantojot `push()`. Bufera klase klasificē katru ierakstu, izmantojot `kindDetector.ts` (nosaka, vai tas ir LLM pieprasījums), aprēķina `contextKey` (sistēmas uzvednes SHA-256 digitālnospiedumu) un veic apraidi visiem WebSocket abonentiem, izmantojot `globalTrafficBuffer.subscribe()`. Informācijas panelis izveido savienojumu, izmantojot `GET /api/tools/traffic-inspector/ws`, savienojuma izveides brīdī saņem momentuzņēmumu un pēc tam — `new`/`update`/`clear` notikumus.

## §2 Tveršanas režīmi

Traffic Inspector atbalsta **5 vienlaicīgus tveršanas avotus**. Katru no tiem var neatkarīgi ieslēgt un izslēgt. Katra `InterceptedRequest` (`src/mitm/inspector/types.ts`) lauks `source` ir `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"` vai `"tproxy"`.

### 1. režīms — AgentBridge (noklusējuma, vienmēr ieslēgts)

**Avots:** AgentBridge apstrādātāji (`src/mitm/handlers/base.ts`)
**Mehānisms:** Katrs `intercept()` izsaukums klasē `MitmHandlerBase` pirms pārsūtīšanas izsauc `hookBufferStart()`, bet pēc pabeigšanas — `hookBufferUpdate()`. Nav nepieciešama papildu konfigurācija — darbojas, tiklīdz ir palaists AgentBridge.
**Tvērums:** 9 IDE aģenti, kas konfigurēti AgentBridge
**Piezīme:** `source` lauks objektā `InterceptedRequest` = `"agent-bridge"`

### 2. režīms — pielāgoti resursdatori (DNS novirzīšana)

**Avots:** Lietotāja definēts resursdatoru saraksts (`inspector_custom_hosts` tabula)
**Mehānisms:** Pievienojot resursdatoru lietotāja saskarnē, ieraksts `127.0.0.1 <host>` tiek pievienots failam `/etc/hosts` (nepieciešams sudo). Esošais AgentBridge MITM serveris (ports 443) jaunajam resursdatoram dinamiski ģenerē SNI sertifikātu.
**Tvērums:** Jebkura lietotne, kas izmanto pievienoto resursdatoru — lietotnes konfigurācija nav jāmaina
**Piezīme:** `source` = `"custom-host"`

Lietošanas piemēri:

- Pārraudzīt `api.openai.com` no Python skriptiem
- Atkļūdot `my-internal-llm.company.com`
- Tvert datplūsmu no mobilajām ierīcēm tajā pašā tīklā (izmantojot ARP viltošanu — pieredzējušiem lietotājiem)

### 3. režīms — HTTP_PROXY klausītājs (ports 8080)

**Avots:** Lietotnes, kas izmanto `HTTP_PROXY`/`HTTPS_PROXY` vides mainīgos
**Mehānisms:** Sekundārs klausītājs portā 8080 (`src/mitm/inspector/httpProxyServer.ts`), kas darbojas kā standarta tiešais HTTP/HTTPS starpniekserveris. Pieņem `CONNECT` tuneļus (HTTPS) un tiešus HTTP pieprasījumus.
**Tvērums:** Jebkura lietotne, kas ievēro `HTTP_PROXY` vides mainīgo — nav jāmaina DNS, nav nepieciešams sudo
**Piezīme:** `source` = `"http-proxy"`

```bash
# Vienas komandas ātrā tveršana:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# Pastāvīga tveršana čaulas sesijā:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS ierobežojums:** HTTPS tiek pārsūtīts caur vienkāršu `CONNECT` tuneli: klausītājs pārsūta šifrētos baitus nemainītus un reģistrē tikai metadatus (resursdatoru, portu, laika informāciju). Tas nekad neatšifrē HTTPS, un šim režīmam nav iestatījuma, ar kuru varētu ieslēgt atšifrēšanu. Lai tvertu HTTPS saturu, novirziet resursdatoru caur 1. režīmu (AgentBridge), 2. režīmu (pielāgoti resursdatori) vai 5. režīmu (TPROXY atšifrēšana).

**Porta konflikts:** Ja ports 8080 tiek izmantots, AgentBridge atgriež 409 ar strukturētu kļūdu. Mainiet portu, izmantojot vides mainīgo `INSPECTOR_HTTP_PROXY_PORT`.

### 4. režīms — sistēmas mēroga starpniekserveris (pieredzējušiem lietotājiem, pēc izvēles)

**Avots:** Operētājsistēmas līmeņa starpniekservera iestatījumi (attiecas uz visām lietotnēm datorā)
**Mehānisms:** Izmanto operētājsistēmas API, lai visu HTTP/HTTPS datplūsmu novirzītu caur HTTP_PROXY klausītāju:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **Tvērums:** Visas datorā esošās lietotnes, kas ievēro sistēmas starpniekservera iestatījumus
  **Piezīme:** `source` = `"system-proxy"`

**Drošības mehānismi:**

- Automātiskās atspējošanas taimeris (pēc noklusējuma 30 min, konfigurējams ar `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES`)
- Iepriekšējais sistēmas starpniekservera stāvoklis tiek saglabāts DB un atjaunots, veicot atsaukšanu
- Ja lietotājs dodas prom, kamēr šis režīms ir aktīvs, informācijas panelī tiek rādīts aicinājums „Notiek sistēmas starpniekservera iestatījumu atsaukšana”
- Lietotāja saskarnē tiek rādīta emblēma `⚠ Papildu` un nepārprotama apstiprinājuma izvēles rūtiņa

### 5. režīms — TPROXY caurspīdīgā atšifrēšana (Linux, root, pēc izvēles)

**Avots:** Kodola TPROXY + uz politikām balstīta maršrutēšana (`src/mitm/tproxy/`)
**Mehānisms:** Jaunie lokālie izejošie TCP savienojumi ar mērķa portu (pēc noklusējuma `443`) tiek marķēti ķēdē `mangle OUTPUT`, `ip rule` pāradresē marķētās paketes lokālai piegādei, un ķēdes `mangle PREROUTING` mērķis `TPROXY` tās nodod caurspīdīgam (**IP_TRANSPARENT**) klausītājam (pēc noklusējuma ports `8443`). Klausītājs pabeidz TLS savienojumu, izmantojot dinamiskas CA **pēc pieprasījuma katram SNI resursdatora nosaukumam izsniegtu** gala sertifikātu, tver atšifrēto apmaiņu un atkārtoti šifrētu pieprasījumu pārsūta sākotnējam galamērķim.
**Tvērums:** **Patvaļīgi** galamērķa resursdatori mērķa portā — bez `/etc/hosts` viltošanas, bez `HTTP_PROXY` vides mainīgā un bez sistēmas mēroga starpniekservera izmaiņām. Pārtvertā procesa konfigurācija nav jāmaina, taču tam ir jāuzticas dinamiskajai CA.
**Piezīme:** `source` = `"tproxy"`

**Prasības:** Tikai Linux (**IP_TRANSPARENT** ir pieejams tikai Linux), iespēja **CAP_NET_ADMIN** (root) un vietējais N-API papildinājums, kas jābūvē ar C rīku ķēdi (`npm run build:native:tproxy`). Ja tas nav pieejams, informācijas paneļa pārslēgs ir atspējots un tiek rādīts rīka padoms „TPROXY atšifrēšanai ir nepieciešams Linux + root + vietējais papildinājums”. Ugunsmūra kārtulas tiek lietotas/atsauktas transakcionāli (avārija nekad neatstāj `mangle` kārtulu) un restartēšanas laikā tiek notīrītas. Uz SO_MARK balstīta cilpu novēršana nepieļauj paša starpniekservera atkārtoti šifrētās pārsūtīšanas atkārtotu pārtveršanu.

Šī ir apjomīga apakšsistēma ar atsevišķu operatora rokasgrāmatu — pilnu ugunsmūra konfigurācijas aprakstu, dinamisko CA katram SNI un uzticamības krātuves instalētāju, tikai lokālo maršrutu, informāciju par cilpu novēršanu un konfigurācijas shēmu skatiet failā `docs/security/MITM-TPROXY-DECRYPT.md` (git; netiek kompilēts direktorijā `/docs`). Pārslēgu vada `GET / POST / DELETE /api/tools/agent-bridge/tproxy` (piezīme: maršruts atrodas zem AgentBridge prefiksa, nevis Traffic Inspector prefiksa).

### 3.2 Pieprasījumu saraksts (kreisais panelis)

- **Virtualizēts** (`useVirtualList` + `ResizeObserver`): apstrādā 1000 vienumu bez saskarnes sastingšanas
- **Automātiska ritināšana** ar pārslēgu, lai pārbaudes laikā to apturētu
- **Ar krāsām kodēts statuss**: zaļš (2xx), dzeltens (3xx), sarkans (4xx/5xx), pelēks (izpildē)
- **Aģenta emocijzīme**: 🔵 Antigravity, 🟢 Copilot, 🟠 Kiro, 🟣 Codex, 🔷 Cursor, 🟤 Zed, 🟡 Claude Code, ⚫ Open Code, 🌐 pielāgots resursdators
- **Konteksta krāsu josla**: 1px kreisā apmale, kas iekrāsota atbilstoši `contextKey` (sistēmas uzvednes SHA-256) — vizuāli grupē saistītās sarunas
- **Atliktā pamatdaļas ielāde**: detalizētās informācijas cilnēs tiek materializēta tikai atlasītā pieprasījuma pamatdaļa (novērš 1000 × 1MB pamatdaļu renderēšanu)

| **Statistika**      | Recharts: latentuma laika skala, marķieru joslu diagramma, rīku izsaukumu izkliedes diagramma       | Tiek rādīts tikai tad, kad ir ielādēta ierakstīta sesija                                                      |

### 3.4 Rīkjoslas vadīklas

| Vadīkla               | Darbība                                                                                 |
| --------------------- | --------------------------------------------------------------------------------------- |
| ⎉ Pauzēt              | Pārtrauc jaunu pieprasījumu renderēšanu; uzkrājas emblēma „X jauni”                     |
| 🗑 Notīrīt             | Notīra lietotāja saskarnes sarakstu (servera buferis netiek ietekmēts)                  |
| ⬇ Eksportēt .har      | Lejupielādē pašreiz filtrēto sarakstu kā HAR failu                                      |

| Statusa filtrs        | Visi / 2xx / 3xx / 4xx / 5xx / kļūda                                                    |

## §4 LLM apzinātas funkcijas

### 4.1 Veida noteicējs (`src/mitm/inspector/kindDetector.ts`)

Klasificē katru pieprasījumu kā `"llm"`, `"app"` vai `"unknown"`, izmantojot 4 signālus:

1. **Resursdatoru reģistrs** — ~18 zināmi LLM API resursdatoru nosaukumi (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot u.c.)
2. **Ceļu paraugi** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses` u.c.
3. **Pamatteksta struktūra** — nosaka laukus `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input`
4. **Lietotāja aģenta norādes** — `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor` UA virknē

Pielāgoti resursdatori, kas pievienoti, izmantojot 2. režīmu, pārmanto savu `kind` no veidlapas ievades (pēc noklusējuma `"custom"`).

### 4.2 SSE apvienotājs (`src/mitm/inspector/sseMerger.ts`)

**Neatkarīga tīrtelpas implementācija.** Notikumu parsēšana atbilst
[WHATWG servera sūtīto notikumu algoritmam](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream),
savukārt rekonstrukcija atbilst publiskajām [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming) un
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
straumēšanas shēmām.

Rekonstruē galīgo asistenta ziņojumu no neapstrādātiem SSE izmaiņu notikumiem:

- **Anthropic**: uzkrāj `content_block_delta` pēc indeksa; apstrādā `text_delta`, `input_json_delta` (rīku izsaukumus), `thinking_delta`
- **OpenAI**: uzkrāj Chat Completions izvēles/rīku izsaukumus un Responses API izvades elementus
  pēc indeksa
- **Gemini**: uzkrāj `candidates[i].content.parts`
- **Nezināms**: atgriež neapstrādātos notikumus bez izmaiņām

Cilnē Response tiek rādīts pārslēgs: **"Neapstrādāti notikumi ↔ Apvienoti"**.

### 4.3 Sarunas normalizētājs (`src/mitm/inspector/conversationNormalizer.ts`)

**Neatkarīga tīrtelpas implementācija.** Normalizāciju nosaka lokāli melnās kastes
kontrakti un publiskās OpenAI, Anthropic un Gemini ziņojumu shēmas; netiek izmantots
neviens augšupstraumes implementācijas pirmkods.

Pirms renderēšanas pārveido OpenAI, Anthropic un Gemini ziņojumu formātus vienotā `NormalizedConversation`:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // ziņojumi / saturs / uzvedne no pieprasījuma pamatteksta
  response: NormalizedTurn[]; // asistenta atbilde (apvienota, izmantojot sseMerger)
  contextKey: string | null; // sistēmas uzvednes SHA-256 digitālnospiedums
}
```

Bloku veidi: `text`, `tool_use`, `tool_result`. Cilne Conversation izmanto šo struktūru neatkarīgi no pakalpojumu sniedzēja.

### 4.4 Konteksta atslēgas iekrāsošana (`src/mitm/inspector/contextKey.ts`)

- Aprēķina sistēmas uzvednes `SHA-256` (pirmais ziņojums ar `role:system`, lauks `system` vai Gemini `systemInstruction`)
- Atgriež 12 rakstzīmju heksadecimālu prefiksu (`"a3f9c2..."`)
- Priekšgals kartē atslēgu uz deterministisku HSL krāsu kreisās malas joslai
- **Filtrs "tas pats konteksts"**: noklikšķinot uz `ctx #a3f` mikroshēmas, tiek pievienots filtrs, lai rādītu tikai pieprasījumus ar tādu pašu digitālnospiedumu

Tas ļauj viegli vizuāli atšķirt dažādas "personas" vai uzdevumus, kas darbojas vienā un tajā pašā aģenta sesijā.

### 4.5 LLM metadatu izgūšana

LLM pieprasījumiem cilne LLM Details izgūst:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // no pieprasījuma pamatteksta vai atbildes
  messages: number; // dialoga kārtu skaits
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // true, ja tā ir SSE atbilde
  mappedTo: string | null; // x-omniroute-mapped galvene
  costEstimateUsd: number | null; // aprēķinātās izmaksas, pamatojoties uz OmniRoute cenām
}
```

### 4.6 Aktīvo pieprasījumu filtrs reāllaikā

Pieprasījuma `status` lauks ir `number | "in-flight" | "error"` — ieraksts tiek
pievienots kā `"in-flight"` pieprasījuma sākšanas brīdī un **atjaunināts turpat**,
kad tiek saņemta atbilde (vai kļūda). Rīkjoslas pārslēgs **"Reāllaiks"**
(`liveOnly`, i18n atslēga `trafficInspector.liveOnly`) ierobežo sarakstu līdz ierakstiem,
kuru `status === "in-flight"`, ļaujot reāllaikā vērot atvērtos savienojumus.

Filtrs ir tīrs klienta puses predikāts failā
`src/lib/inspector/matchesTrafficFilter.ts`:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

Pārslēga stāvoklis atrodas `useTrafficFilters` (inspektora informācijas paneļa āķos) un
tiek kombinēts ar pārējiem filtriem (profils, resursdators, aģents, avots, statuss, konteksts).

### 4.7 Procesa attiecināšana (Linux)

Linux sistēmā katru pārtverto pieprasījumu var attiecināt uz **vietējo procesu,
kas to iniciējis**. `InterceptedRequest` tiek pievienoti divi neobligāti lauki:

```ts
pid?: number;          // iniciējošā procesa identifikators (tikai Linux)
processName?: string;  // iniciējošā procesa nosaukums (tikai Linux)
```

`src/mitm/inspector/processAttribution.ts` kartē savienojuma _klienta_
īslaicīgo portu uz PID un nosaukumu, veicot šādas darbības:

1. Nolasa `/proc/net/tcp` un `/proc/net/tcp6`, lai atrastu porta ligzdas inode
   (`parseProcNetTcpForInode` — tīrs parsētājs, ko var testēt ar testa datiem).
2. Pārmeklē `/proc/<pid>/fd/`, meklējot simbolisku saiti uz `socket:[<inode>]`.
3. Nolasa procesa nosaukumu no `/proc/<pid>/comm`.

Kešatmiņa ar 1 sekundes TTL ierobežo procfs skenēšanas izmaksas slodzes apstākļos. Attiecināšana tiek veikta,
izmantojot **labāko iespējamo pieeju** — jebkuras kļūmes gadījumā tiek atgriezts `null`, un tveršana nekad netiek bloķēta.
macOS/Windows sistēmās funkcija atgriež `null` (aizstājējimplementācija; `lsof`/`GetExtendedTcpTable`
atbalsts tiks pievienots turpmāk).

## §6 Drošība

Traffic Inspector rāda **visu pārtverto HTTPS datplūsmu**, tostarp autorizācijas galvenes un pieprasījumu pamattekstus. Ir ieviesti šādi kontroles mehānismi:

| Kontroles mehānisms                           | Informācija                                                                                                                                                                                                                   |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                                | Visi maršruti un WebSocket galapunkts ir pieejami tikai lokālajā atgriezeniskajā saskarnē (tas tiek nodrošināts failā `routeGuard.ts` pirms autentifikācijas)                                                                 |
| **Noslēpumu maskēšana**                       | Lineārais `maskSecret()` skeneris pirms `TrafficBuffer.push()` aizklāj RFC 6750 Bearer akreditācijas datus, ar pakalpojumu sniedzēja prefiksu apzīmētas atslēgas un garus necaurspīdīgus marķierus                            |
| **Pamatteksta izmēra ierobežojums**           | Pamatteksti, kuru izmērs pārsniedz `INSPECTOR_MAX_BODY_KB` (pēc noklusējuma 1024 KB), tiek saīsināti, pievienojot paziņojumu `"(saīsināts veiktspējas dēļ)"`                                                                  |
| **Galveņu sanitizēšana**                      | Nosaukumi tiek pārveidoti par mazajiem burtiem; kadrēšanas, posmu līmeņa un starpniekservera autentifikācijas galvenes tiek atmestas; sīkfaili tiek pilnībā aizklāti; akreditācijas datu vērtības tiek nodotas `maskSecret()` |
| **CSP**                                       | Traffic Inspector lapās tiek izmantota stingra satura drošības politika, lai novērstu XSS, ko var izraisīt ievadīti atbilžu pamatteksti                                                                                       |
| **Pēc noklusējuma bez pastāvīgas glabāšanas** | `TrafficBuffer` tiek glabāts atmiņā un zaudēts pēc servera restartēšanas. Sesijas tiek pastāvīgi saglabātas tikai tad, ja tās tiek nepārprotami ierakstītas                                                                   |

### Piemērotie stingrie noteikumi

| Noteikums                         | Piemērojums                                                                                        |
| --------------------------------- | -------------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Visas HTTP kļūdu atbildes no Traffic Inspector maršrutiem tiek sanitizētas                         |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` ir LOCAL_ONLY + SPAWN_CAPABLE (sistēmas starpniekservera komandas) |

### Zināmie ierobežojumi

- **Sistēmas mēroga starpniekservera režīms** ietekmē visas datorā esošās lietojumprogrammas, tostarp VPN klientus un SSO. Vienmēr izmantojiet to kopā ar automātiskās atspējošanas taimeri. Neizmantojiet koplietojamos datoros.
- **CONNECT tuneļa HTTPS**: 3. režīms (HTTP_PROXY) HTTPS galamērķiem tver tikai tuneļa metadatus un nekad tos neatšifrē. Tas ir paredzēti — atšifrēšanai būtu nepieciešams, lai katrs klients uzticētos MITM sertifikātam, tāpēc klausītājs saglabā pilnīgu HTTPS šifrēšanu no gala līdz galam. Izmantojiet AgentBridge, Custom Hosts vai TPROXY atšifrēšanu, ja nepieciešami HTTPS pamatteksti.
- **Dažos komponentos ir cietkodētas virknes**: dažos UI komponentos (F7/F8) ir neliels skaits cietkodētu virkņu, kuras vēl neaptver i18n atslēgas. Tās ir dokumentētas kā zināms ierobežojums i18n nepilnību pārskatā; tās tiks migrētas nākamajā posmā. Ietekmētās virknes ir UI dekoratīvās etiķetes, kuru tulkošana nav nepieciešama funkcionālai lietošanai.

## §7 Problēmu novēršana

### WebSocket savienojuma pārtraukums

Ja tiešraides plūsmā tiek rādīts "Atvienots":

1. Pārbaudiet, vai serveris joprojām darbojas: `GET /api/tools/traffic-inspector/capture-modes`
2. Pārlādējiet lapu — WebSocket atkārtoti izveido savienojumu un saņem jaunu momentuzņēmumu
3. Ja serveris tika restartēts, atmiņas buferis tika iztīrīts — vecie ieraksti ir zuduši, ja vien netika ierakstīta sesija

### Porta 8080 konflikts

Ja HTTP_PROXY režīmu neizdodas palaist:

```bash
lsof -i :8080    # atrast procesu
```

Mainiet portu:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### Sistēmas starpniekservera iestatījumi netika atjaunoti

Ja OmniRoute avarē, kamēr ir aktīvs visas sistēmas starpniekservera režīms:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

Nākamajā ielādes reizē informācijas panelis piedāvās arī opciju "Atjaunot sistēmas starpniekservera iestatījumus", ja tas konstatēs, ka DB stāvoklis norāda uz iepriekš aktīvu starpniekserveri.

### Buferis ir pilns

Kad buferis sasniedz `INSPECTOR_BUFFER_SIZE` (noklusējuma vērtība ir 1000), jaunie ieraksti izspiež vecākos. Ja svarīgi pieprasījumi tiek zaudēti:

- Palieliniet `INSPECTOR_BUFFER_SIZE` (piemēram, līdz 5000) — lielāks atmiņas patēriņš apmaiņā pret ilgāku saglabāšanu
- Ierakstiet sesiju, lai saglabātu attiecīgo laika intervālu DB
