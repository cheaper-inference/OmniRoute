`copilot-m365-web` (aizstājvārds `m365copilot`) nosūta OpenAI formāta tērzēšanas pieprasījumus, izmantojot
autentificētu Microsoft 365 Copilot BizChat pārlūkprogrammas sesiju vietnē
`m365.cloud.microsoft/chat`. Šī ir neoficiāla integrācija.

> **Vai Web Cookie nodrošinātāji jums ir jaunums?**
>
> Pirms šīs nodrošinātājam specifiskās rokasgrāmatas izpildes izlasiet **`docs/getting-started/WEB-COOKIE-GUIDE.md`**, lai uzzinātu par vispārīgo iestatīšanas procesu, autentifikācijas norādījumiem, ierobežojumiem un problēmu novēršanu.
>
> **Svarīgi:** Šī nodrošinātāja akreditācijas dati **nav sīkfails**. Nekopējiet
> sīkfailus no `m365.cloud.microsoft`. Akreditācijas datus veido WebSocket URL vaicājuma
> parametrs un ceļa segments, kas abi ir nolasāmi DevTools cilnē Network.

## Priekšnosacījumi

- Microsoft 365 konts ar piekļuvi BizChat vietnē `m365.cloud.microsoft/chat`
- Chromium balstīta pārlūkprogramma (Chrome, Edge) WebSocket pārbaudei rīkā DevTools
- M365 Copilot licence (iekļauta daudzos Microsoft 365 Business/Enterprise plānos)

## Akreditācijas datu iegūšana (WebSocket metode)

1. Pierakstieties vietnē `https://m365.cloud.microsoft/chat` un sāciet sarunu.
2. Atveriet **DevTools → Network**.
3. Filtrējiet pēc **WS** (WebSocket).
4. Noklikšķiniet uz Chathub WebSocket savienojuma. Meklējiet URL, kas sākas ar
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. No tā **Request URL** nokopējiet:
   - Vaicājuma parametra `access_token` vērtību (īslaicīgu JWT).
   - Chathub ceļa segmentu pēc `/Chathub/` (piemēram, `<oid>@<tenant>`).

Pilnajam URL ir šāds formāts:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Rīkā OmniRoute dodieties uz **Providers → Add Provider**, atlasiet **Microsoft 365 Copilot
   (BizChat)** un ielīmējiet akreditācijas datus šādā formātā:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Noklikšķiniet uz **Test Connection** un **Save**.

## Akreditācijas datu iegūšana (HAR importēšana)

Tā vietā, lai manuāli kopētu vērtības no WebSocket URL, varat eksportēt DevTools HAR
failu:

1. Atveriet **DevTools → Network**.
2. Sāciet vai turpiniet BizChat sarunu (tas izveido WebSocket savienojumu).
3. Ar peles labo pogu noklikšķiniet panelī Network un atlasiet **Save all as HAR with content**.
4. Rīka OmniRoute nodrošinātāja savienojuma dialoglodziņā izmantojiet pogu **Import .har file**.

OmniRoute HAR failā meklē Chathub WebSocket URL, izgūst
`access_token` un `chathubPath` un automātiski aizpilda akreditācijas datu laukus. HAR
importēšanas laikā tiek dekodēts JWT derīguma termiņš un parādīts atlikušais marķiera derīguma laiks.

> **Nekad neiekļaujiet repozitorijā īstu HAR eksportu, piekļuves marķieri vai atsvaidzināšanas marķieri.** Testu un
> dokumentācijas vērtībām vienmēr jābūt vietturiem.

## Pilnvaras darbības laiks un atsvaidzināšana

`access_token` ir īslaicīgs (parasti **~75 minūtes**). Ja nav izmantojama atsvaidzināšanas
pilnvaras, pēc tās derīguma termiņa beigām pilnvara ir jāiegūst atkārtoti.

### Automātiska atsvaidzināšana ar `refreshToken`

Microsoft 365 nodrošinātāja dialoglodziņā **Pievienot savienojumu** vai **Rediģēt savienojumu** atveriet
**Papildu iestatījumi → Atsvaidzināšanas pilnvara (neobligāti)**. Ielīmējiet Microsoft OAuth atsvaidzināšanas pilnvaru
`substrate.office.com/sydney` tvērumam un saglabājiet. Ievade ir maskēta, un saglabātā pilnvara nekad netiek
automātiski aizpildīta. Rediģēšanas laikā atstājiet lauku tukšu, lai saglabātu esošo pilnvaru;
ielīmējiet jaunu pilnvaru, lai to aizstātu.

Iegūstiet atsvaidzināšanas pilnvaru, izmantojot Microsoft ierīces koda vai autorizācijas koda plūsmu,
kas ierobežota ar `substrate.office.com/sydney` tvērumu; informācijas panelis to neiegūst jūsu vietā.
Ja ir konfigurēta atsvaidzināšanas pilnvara, OmniRoute pirms pieprasījumu veikšanas pārbauda
`access_token` un atsvaidzina to tikai tad, kad tas ir nepieciešams. Veiksmīga atsvaidzināšana saglabā arī
rotēto atsvaidzināšanas pilnvaru, novēršot nepieciešamību to manuāli iegūt atkārtoti, kamēr atsvaidzināšanas pilnvara ir derīga.

Ja `refreshToken` nav iestatīts, pēc katras derīguma termiņa beigām WebSocket pilnvara
ir jāiegūst atkārtoti manuāli.

### Līmeņa izvēle

| Līmenis      | Aizstājvārds    | Virsma                  |
| ------------ | --------------- | ----------------------- |
| `individual` | _(noklusējuma)_ | Patērētāju M365 Copilot |
| `edu`        | `included`      | Izglītības M365 Copilot |
| `enterprise` | `work`          | M365 Copilot darbam     |

Iestatiet līmeni sadaļā **Papildu iestatījumi → Copilot līmenis**. Līmenis ietekmē
BizChat maršrutēšanu un piekļuvi modeļiem.

## Drošības modelis

- **Neoficiāla integrācija.** Šis nodrošinātājs izmanto reverso inženieriju BizChat WebSocket
  protokolam. Tas var pārstāt darboties bez iepriekšēja brīdinājuma, ja Microsoft maina galapunktu.
- Karodziņš `subscriptionRisk: true` norāda, ka integrācija izmanto
  nedokumentētu galapunktu. Konta ierobežojumi ir iespējami, taču nav apstiprināti.
- Piekļuves pilnvara ir īslaicīgs JWT. Izturieties pret to kā pret paroli: neiekļaujiet to versiju kontrolē,
  nereģistrējiet žurnālos un nekopīgojiet.
- Atsvaidzināšanas pilnvara nodrošina ilgtermiņa piekļuvi BizChat saskarnei. Glabājiet to ar
  tādu pašu rūpību kā API atslēgu.

## Problēmu novēršana

### Autentifikācija neizdodas nekavējoties

- Pārbaudiet, vai kopējāt no **WebSocket URL**, nevis no XHR/Fetch pieprasījuma. Akreditācijas dati atrodas Chathub WebSocket savienojuma `access_token` vaicājuma parametrā — nevis `Authorization: Bearer` galvenē.
- Pārliecinieties, ka `chathubPath` ietver pilno `<oid>@<tenant>` segmentu no URL ceļa.

### Pilnvara beidzas pēc aptuveni 75 minūtēm

Tas ir paredzēts. Bez `refreshToken` piekļuves pilnvaras darbības laiks ir īss. Varat:

- Vēlreiz iegūt akreditācijas datus no DevTools, vai
- Dialogā Add or Edit connection konfigurēt **Papildu iestatījumi → Atsvaidzināšanas pilnvara (neobligāti)**, lai nodrošinātu automātisku atjaunināšanu.

### Savienojuma pārbaude ir veiksmīga, bet tērzēšana atgriež 401

Iespējams, pilnvaras derīguma termiņš beidzās starp validāciju un pirmo pieprasījumu. Vēlreiz iegūstiet jaunus akreditācijas datus.

### Copilot neparādās nodrošinātāju sarakstā

Pārliecinieties, ka **Dashboard → Providers** ir iespējots `copilot-m365-web`. Dažos līmeņos nodrošinātājs pēc noklusējuma var būt paslēpts.
