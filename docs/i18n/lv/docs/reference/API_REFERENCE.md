## Tērzēšanas pabeigšana

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

| Galvene                  | Virziens     | Apraksts                                                                                                                                                                                                                                               |
| ------------------------ | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| `x-omniroute-no-memory`  | Pieprasījums | Iestatiet uz `true`, lai šim pieprasījumam izlaistu atmiņas un prasmju ievietošanu (atbilst kešatmiņas apiešanai; novērš katra izsaukuma marķieru/izmaksu papildu slogu)                                                                               |
| `X-OmniRoute-Progress`   | Pieprasījums | Iestatiet uz `true`, lai saņemtu progresa notikumus                                                                                                                                                                                                    |
| `X-Session-Id`           | Pieprasījums | Piesaistītās sesijas atslēga ārējai sesijas piesaistei                                                                                                                                                                                                 |
| `x_session_id`           | Pieprasījums | Tiek pieņemts arī variants ar pasvītrojumu (tiešam HTTP savienojumam)                                                                                                                                                                                  |
| `X-OmniRoute-Session-Id` | Pieprasījums | Izsaucēja norādīta sesijas/sarunas atzīme (tiek izmantota arī atmiņai). Ja tā ir norādīta, tā tiek saglabāta nemainītā veidā laukā `call_logs.session_tag`, lai attiecinātu izmaksas uz konkrētu sesiju (#8249) — ja tās nav, tā nekad netiek ģenerēta |

| `X-Request-Id`           | Pieprasījums | Alternatīva dublēšanās novēršanas atslēga                                                                                                                                                                                                              |
| `x-omniroute-connection` | Pieprasījums | Piesaistiet viena modeļa pieprasījumu vienam pakalpojumu sniedzēja savienojumam (kontam), izmantojot tā ID — skatiet [Konta piesaiste katram pieprasījumam](#account-pinning-per-request)                                                              |
| `X-OmniRoute-Cache`      | Atbilde      | `HIT` vai `MISS` (bez straumēšanas)                                                                                                                                                                                                                    |
| `X-OmniRoute-Idempotent` | Atbilde      | `true`, ja dublikāts ir novērsts                                                                                                                                                                                                                       |
| `X-OmniRoute-Progress`   | Atbilde      | `enabled`, ja ir ieslēgta progresa izsekošana                                                                                                                                                                                                          |
| `X-OmniRoute-Session-Id` | Atbilde      | Faktiskais sesijas ID, ko izmanto OmniRoute                                                                                                                                                                                                            |
| `X-OmniRoute-Request-Id` | Atbilde      | Pieprasījuma korelācijas ID (ja zināms)                                                                                                                                                                                                                |

#### Konta piesaiste katram pieprasījumam

Ja pakalpojumu sniedzējam ir vairāki savienojumi (konti vai atslēgas), OmniRoute parasti izvēlas vienu,
izmantojot savu kontu atlases stratēģiju. Tā vietā pieprasījumu var piesaistīt vienam konkrētam savienojumam,
izmantojot galveni `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Kur atrast ID.** Informācijas panelī atveriet pakalpojumu sniedzēja lapu
  (**Informācijas panelis → Pakalpojumu sniedzēji → <provider>**) un savienojuma rindā noklikšķiniet uz `xxxxxxxx…` ID elementa —
  tādējādi tiek nokopēts pilnais savienojuma ID.
- **Kuri pieprasījumi to ņem vērā.** Viena modeļa pieprasījumi (`provider/model`) galapunktos
  `/v1/chat/completions`, `/v1/messages` un `/v1/responses`. Kombinācijas ignorē šo galveni: piesaistiet
  kontu katram kombinācijas solim, izmantojot paša soļa savienojumu.
- **Piesaiste ir stingra, nevis tikai priekšroka.** Tiek izmantots tikai piesaistītais savienojums. Kļūme
  pieprasījuma izpildes laikā reģistrē konta nogaidīšanas periodu, taču **nepārslēdz** pieprasījumu uz
  citu tā paša pakalpojumu sniedzēja kontu.
- **Nogaidīšanas periods un kvota atceļ piesaisti.** Kamēr piesaistītajam savienojumam ir aktīvs nogaidīšanas periods,
  ir izsmelta kvota vai to bloķē kvotas politika, turpmākie pieprasījumi atkāpjas uz citiem pakalpojumu sniedzēja
  savienojumiem — tieši tāpat kā nepiesaistīta datplūsma.
- **Nezināmi vai atspējoti ID izraisa kļūmi.** ID, kas neatrodas pakalpojumu sniedzēja aktīvajā kopā (ir dzēsts,
  deaktivizēts vai pieder citam pakalpojumu sniedzējam), neatstāj nevienu piemērotu kontu, tāpēc pieprasījums
  neizdodas, nevis tiek nemanāmi maršrutēts citur.

Claude Code nosūta pielāgotas galvenes, izmantojot `ANTHROPIC_CUSTOM_HEADERS`. Ievietojiet to faila
`~/.claude/settings.json` blokā `env` vai projekta līmeņa failā `.claude/settings.json`, lai katram projektam
piesaistītu citu kontu:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Avots: `src/sse/handlers/chat.ts` (galvenes nolasīšana), `src/sse/services/auth.ts` un
`src/sse/services/sessionAffinityPin.ts` (piesaistes atcelšana un pārbaude, vai savienojuma nav aktīvajā kopā).

> **Izmaksu telemetrijas galvenes:** arī veiksmīgās atbildēs bez straumēšanas tiek iekļauts `X-OmniRoute-*` izmaksu telemetrijas komplekts — `X-OmniRoute-Response-Cost` (USD, fiksētas 10 zīmes aiz komata; `0.0000000000` bezmaksas gadījumā vai tad, ja cena nav norādīta), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` un `X-OmniRoute-Fallback-Attempts` (tikai tad, ja > 0), kā arī `X-OmniRoute-Request-Id` un `X-OmniRoute-Version`. Tās tiek pievienotas tērzēšanas pabeigšanas atbildēm, `/v1/responses`, `/v1/messages`, **kā arī multivides galapunktu atbildēm** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` un `/v1/moderations` (izmaksas vienmēr ir `0`). Multivides izmaksas tiek aprēķinātas atbilstoši modalitātei (par attēlu, sekundi, rakstzīmi vai meklēšanas vienību), ja ir pieejama cenu informācija; pretējā gadījumā tās ir `0` (kļūmes gadījumā darbība tiek atļauta).

> **Kešatmiņas trāpījuma izmaksu semantika:** semantiskās kešatmiņas TRĀPĪJUMA gadījumā (`X-OmniRoute-Cache-Hit: true`) augšupstraumes izsaukums netiek veikts, tāpēc `X-OmniRoute-Response-Cost` vērtība ir `0.0000000000` (trāpījuma apkalpošanas **papildu** izmaksas). Sākotnējās jeb potenciālās izmaksas tiek norādītas atsevišķi galvenē `X-OmniRoute-Cost-Saved`. Norēķinu sistēmām jāsumē `X-OmniRoute-Response-Cost` (trāpījumi neko nemaksā); kešatmiņas analītikā var apkopot `X-OmniRoute-Cost-Saved`.

## Ekskluzīvas pārvaldīto sesiju nomas

Ekskluzīva pārvaldīto sesiju noma ir izvēles, no klienta neatkarīgs maršrutēšanas līgums: viens aktīvs īpašnieks
tur vienu piemērotu OmniRoute savienojumu. Tā nenomā modeli, nepieprasa OAuth, neidentificē
konkrētu klientu un nepieprasa konkrētu pakalpojumu sniedzēju.

Autentificējošajai API atslēgai ir jābūt tvērumam `lease:exclusive` un skaidri norādītam netukšam
`allowedConnections` sarakstam. Datubāzes izmaiņu robeža atslēgas izveides un daļēju atjauninājumu
laikā nodrošina abu lauku vienlaicīgu izpildi.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Veiksmīgas iegūšanas, atjaunošanas un atbrīvošanas atbildes atklāj laikspiedolus, `state` un precīzu pozitīvu
`generation`, bet nekad neatklāj izvēlēto savienojumu vai akreditācijas datus. Atjaunošanas un atbrīvošanas pieprasījumos
paaudze tiek norādīta JSON pamattekstā:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Aktīvas nomas īpašnieks var nepārprotami pieprasīt privātumu aizsargājošus attēlojuma metadatus par savu pašreizējo piesaisti:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Šo izvēles statusa darbību vienā datubāzes transakcijā ierobežo necaurredzamais īpašnieks, autentificētā pārvaldītā API atslēga un precīza
aktīvā paaudze. `displayName` ir tikai apgriezts konfigurētais
savienojuma nosaukums; tas ir `null`, ja nav droša konfigurēta nosaukuma. OmniRoute nekad neaizstāj to ar
e-pasta adresi vai ģenerētu konta identitāti. Pakalpojumu sniedzēja vērtība ir nekonfidenciāla attēlojuma etiķete un nekad nav
ģenerēts saderīga pakalpojumu sniedzēja identifikators. Akreditācijas dati, pilnvaras, sīkfaili, neapstrādāti savienojumu vai API
atslēgu ID, īpašnieku jaucējvērtības, ierobežošanas noslēpumi un iekšējie maršrutēšanas dati netiek iekļauti.

Meklējumi ar nepareizu atslēgu, nepareizu īpašnieku, novecojušu paaudzi, kā arī neesoši, noilguši, atbrīvoti un anulēti meklējumi
visi atgriež vienu un to pašu `409 LEASE_FENCE_STALE` kļūdu bez savienojuma metadatiem. Klientam, kurš saņēma kapacitātes gaidīšanas atbildi, nav aktīvas piesaistes, ko pārbaudīt. Kad maršrutēšana maina aktīvu nomu,
tā pati paaudze paliek derīga, un statuss atomāri atgriež jauno piesaisti, bet nekad veco.
Esošie klienti paliek nemainīti, jo iegūšanas, atjaunošanas, atbrīvošanas un gaidīšanas atbildes saglabā
iepriekšējo struktūru.

Šis servera līgums nemaina standarta OpenAI Codex `/status`. Standarta Codex pašlaik ziņo par savu
modeļa pakalpojumu sniedzēju un iebūvēto autentifikācijas/konta stāvokli, bet neatveido patvaļīgus pielāgota
pakalpojumu sniedzēja konta metadatus; turpmākai klienta integrācijai ir jāizsauc šī darbība un jāizlemj, kā
attēlot `connection.displayName`.

Katrs pārvaldītais secināšanas pieprasījums pēc tam norāda abas vadības galvenes:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Precīzais īpašnieks, paaudze, aktīvais savienojums un autentificētā API atslēga tiek ierobežoti tieši
pirms katra atbalstītā augšupstraumes mēģinājuma. Īpašnieka un paaudzes atkārtota izmantošana ar citu atslēgu neizdodas pat
tad, ja šī atslēga atļauj to pašu savienojumu. Neapstrādāti īpašnieki netiek saglabāti, reģistrēti žurnālos, paturēti
pieprasījuma momentuzņēmumā vai pārsūtīti augšupstraumē.

Īslaicīgas konkurences gadījumā tiek atgriezts HTTP `429` ar `Retry-After` un:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Šī atbilde nozīmē tikai to, ka parastā piemēroto savienojumu kopa nebija tukša un visus brīvos kandidātus
turēja ārēja aktīva noma. Neatbalstīti modeļi/pakalpojumu sniedzēji, neatbilstība politikai, atdzišanas periods, kvota,
veselības stāvoklis un citas parastās piemērotības kļūmes saglabā esošās OmniRoute atbildes.

### `x-omniroute-compression`

Katra pieprasījuma kompresijas plāna pārrakstīšana. Augstākā prioritāte — tā ir pārāka par maršrutēšanas kombinācijas
pārrakstīšanu, aktīvo profilu, automātisko aktivizētāju un paneļa noklusējumu. Vērtības:

| Vērtība       | Ietekme                                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------------------------- |
| `off`         | Šim pieprasījumam kompresija netiek veikta.                                                                           |
| `default`     | No paneļa atvasinātais noklusējuma profils (ignorē aktīvo profilu). Zudumradošie dzinēji paliek izslēgti.             |
| `safe`        | Tikai dublikātu noņemšana un atstarpju sapludināšana.                                                                 |
| `allow-lossy` | Šim pieprasījumam saglabā operatora plānu, tostarp kopsavilkumus un stila pārrakstīšanu.                              |
| `engine:<id>` | Viens dzinējs, ja tas ir iespējots, piemēram, `engine:rtk`. Izvēles iespējošana šim dzinējam konkrētajā pieprasījumā. |
| `<combo>`     | Nosaukta kombinācija, kas vispirms tiek salīdzināta pēc nosaukuma (reģistrnejutīgi), pēc tam pēc ID.                  |

Piezīmes:

- Nezināmas vērtības tiek ignorētas (pieprasījums nekad netiek noraidīts); noteikšana pāriet uz parasto operatora prioritāšu secību.
- Ja vairākām kombinācijām ir vienāds nosaukums, determinētai atbilstībai norādiet kombinācijas **ID**.
- Kombināciju, kuras nosaukums ir `off` vai `default`, nevar atlasīt pēc nosaukuma (šie atslēgvārdi tiek interpretēti vispirms); atsaucieties uz šādu kombināciju, izmantojot tās ID.
- Galvenais kompresijas slēdzis ir stingrs ierobežojums: ja kompresija ir globāli atspējota, šī galvene nevar to iespējot.

Piemērotais plāns tiek atgriezts atbildes galvenē:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

kur `<source>` ir viena no šīm vērtībām: `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` vai `off`.

## Iegultnes

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Pieejamie nodrošinātāji: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Kataloga identifikatori ir `provider/model` (piemērs: `jina-ai/jina-embeddings-v5-omni-small`). Tiek atpazīti arī Jina modeļu identifikatori bez nodrošinātāja prefiksa, ja tie ir iekļauti reģistrā (piemēram, `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`). Jina iegulšanas/pārkārtošanas/klasificēšanas/segmentēšanas darbības vispirms izmanto informācijas paneļa `jina-ai` akreditācijas datus; `JINA_AI_API_KEY` tiek izmantota kā rezerves iespēja tikai tad, ja informācijas paneļa atslēgas nav. `jina-reader` kartīte ir paredzēta tikai Reader / `r.jina.ai` (`POST /v1/web/fetch`) un nekad nenodrošina iegulšanu vai pārkārtošanu.

Reģistra modeļi, kas norāda uz multimodālu atbalstu, pieņem arī līdz 32 no nodrošinātāja neatkarīgiem strukturētiem
elementiem. Multivides elementu tipi ir `text`, `image`, `audio`, `video` un `document`. To multivides `source`
ir vai nu `{"type":"url","url":"https://..."}`, vai
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
un saimes aizstājvārds `jina-ai/jina-embeddings-v5-omni` → omni-small) pieņem arī Jina vietējā
EmbeddingsV5Request formāta dokumentus un **pārsūta tos nemainītus** uz `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Vietējā formāta `{ image | audio | video | pdf }` vērtības var būt publisks HTTPS URL, `data:` URI vai neapstrādāti
base64 dati. OmniRoute nepārvērš šos objektus virknēs un neielādē vietējā formāta attēlu URL — Jina pati izgūst
publisko multividi. Papildu Jina lauki (`task`, `normalized`, `truncate`, `embedding_type`) tiek
pārsūtīti. Tikai tekstam paredzētie Jina SKU joprojām noraida dokumentus, kas nav teksts.

Drošības un transportēšanas ierobežojumi:

- Attālo multivides resursu URL jābūt publiskiem HTTPS URL. Kanoniskie `{type,source:url}` elementi tiek izgūti
  servera pusē (atkārtota novirzīšanas pārbaude, taimauts, izmēra ierobežojumi, publisks DNS, savienojuma piesaiste) un
  iegulti pirms nodrošinātāja izsaukuma. Jina vietējā formāta `{image:"https://..."}` elementi pēc tās pašas
  publiskā HTTPS pārbaudes tiek pārsūtīti nemainīti; Jina izgūst URL saturu.
- Iekļautās base64 multivides apjoms ir ierobežots līdz 8 MiB atkodētu datu katram elementam un 16 MiB atkodētu datu visam pieprasījumam.

Pārveidošana atbilstoši nodrošinātājam (kanoniskie elementi nekad netiek pārsūtīti nemainīti):

- Jina multimodālie modeļi: katrs augstākā līmeņa elements kļūst par vienu modalitātes atslēgas objektu
  (`text` / `image` / `audio` / `video` / `pdf`), iekļautajai multividei izmantojot datu URI; viens vektors katram
  augstākā līmeņa elementam.
- Gemini Embedding 2 saime: viens augstākā līmeņa masīvs kļūst par vienu vietējā formāta
  `models/{model}:embedContent` pieprasījumu ar `content.parts` (`text` vai `inline_data`).
- llama.cpp (`llama-cpp/<model>`, jebkurš vietējā servera ielādētais modelis): kanoniskie `text` elementi
  kļūst par vienkāršām virknēm, savukārt `image` / `audio` / `video` katrs kļūst par vienu
  `{"content": [part]}` objektu, izmantojot llama-server tērzēšanas satura daļas (`image_url`,
  `input_audio` ar formātu `wav` / `mp3` / `flac`, `input_video`) un iekļautus datus; viens vektors
  katram augstākā līmeņa elementam. Serverim jādarbojas ar `--embedding --mmproj …`; bez projektora tas
  pats noraida multividi. `document` netiek atbalstīts.
- Nezināmi/dinamiski modeļi bez skaidriem modalitāšu metadatiem noraida strukturētu ievadi ar HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Neatbalstītas modeļa/modalitātes kombinācijas atgriež HTTP 400, nevis pārveido elementu piespiedu kārtā. Ar ievadi nesaistītie
paplašinājumu lauki mantotajos virkņu/marķieru pieprasījumos joprojām tiek pārsūtīti nemainīti.

```bash
# Uzskaitīt visus iegulšanas modeļus
GET /v1/embeddings
```

## Attēlu ģenerēšana

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Pieejamie nodrošinātāji ietver OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (lokāli), ComfyUI (lokāli).

`n` atgriež `n` attēlus masīvā `data[]`. Nodrošinātājiem, kuru augšupējā API vienā izsaukumā atgriež vienu attēlu
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI), tiek veikti `n` atsevišķi augšupējie izsaukumi, vienlaikus izpildot ne vairāk kā 4. Fiksēta
`seed` vērtība tiek palielināta par izsaukuma indeksu (`seed`, `seed + 1`, …), tādēļ attēli atšķiras, taču saglabājas
reproducējami. `n` maksimālā vērtība ir 10. Ja kāds izsaukums neizdodas, viss pieprasījums tiek uzskatīts par neizdevušos. Izvēršanas
formātu saraksts ir `SINGLE_IMAGE_FANOUT_FORMATS` failā
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux atkārtoti izmanto esošo API atslēgas savienojumu un pieņem prefiksus `zenmux/` vai `zm/`:

- `zenmux/openai/gpt-image-2` izmanto ZenMux OpenAI Images API. Opcijas ietver `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` un `response_format`.
- Citi izdevēji, piemēram, `zm/meta/muse-image-1.0`, izmanto ZenMux Vertex AI `:predict`
  galapunktu. `n` atbilst `sampleCount`, `aspect_ratio` — `aspectRatio`, bet `image_size`
  (`1K`, `2K`, `4K`) — `sampleImageSize`. Pikseļos norādīts `size` nosaka tikai malu attiecību,
  nevis garantētus izmērus pikseļos. Atbalstītās malu attiecības, izšķirtspējas un attēlu skaits katram modelim atšķiras.
- `zm/inclusionai/ming-image-0.1-design` pats izvēlas savus izmērus. Nenorādiet `size`,
  `aspect_ratio` un `image_size`; skaidri norādītas vērtības izraisa HTTP 400 atbildi. PNG, JPEG un WebP
  formātus var pieprasīt, izmantojot `output_format`.

Šī integrācija atbalsta attēlu ģenerēšanu no teksta, nevis atsauces attēlu rediģēšanu. Vertex
izvade tiek normalizēta uz `data[].b64_json`; `response_format: "url"` atgriež augšupējā pakalpojuma
HTTPS URL vai base64 datu URL, ja ir pieejami tikai attēla baiti. Tukša vai filtrēta izvade
izraisa kļūdu, nevis tukšu veiksmīgu atbildi. Piekļuve modeļiem ir atkarīga no ZenMux konta.
Skatiet [ZenMux Vertex API](https://docs.zenmux.ai/api/vertexai/generate-images) un
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# Uzskaitīt visus attēlu modeļus
GET /v1/images/generations
```

## Dokumentu OCR

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
```

`model` atlasa OCR nodrošinātāju, izmantojot prefiksu `provider/model`; modeļa ID bez prefiksa (piem.,
`mistral-ocr-latest`) tiek sasaistīts ar tā reģistrēto nodrošinātāju, bet, ja `model` nav norādīts, pēc noklusējuma
tiek izmantots Mistral (`mistral-ocr-latest`). Reģistrētie nodrošinātāji (`open-sse/config/ocrRegistry.ts`):

| Nodrošinātāja ID              | Modeļa ID            | `model` vērtība                                                      | Piezīmes                                                                                                           |
| ----------------------------- | -------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (vai `mistral-ocr-latest` bez prefiksa) | Sinhrons — atbilde tiek atgriezta tieši no vienīgā augšupējā izsaukuma.                                            |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                          | Asinhrons augšupējais pakalpojums (`analyze` + aptauja) — skatiet tālāk.                                           |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                              | Sinhrons, izmantojot Vertex AI `openapi/chat/completions` partnera galapunktu — autentifikāciju/URL skatiet tālāk. |

Visi trīs nodrošinātāji atbild ar vienādu Mistral formas pamattekstu:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Azure Document Intelligence aptaujas plūsma

Azure Document Intelligence `analyze` API ir asinhrona: sākotnējais pieprasījums pamatteksta vietā atgriež
`Operation-Location` galveni, un rezultāts ir periodiski jāaptaujā. Apstrādātājs
(`open-sse/handlers/ocr.ts`) aptaujā šo URL katru sekundi, veicot ne vairāk kā 30 mēģinājumus, nekavējoties pārtrauc darbu (neturpinot
aptauju), ja aptaujas atbilde nav `ok` vai statuss ir `"failed"`, un atgriež `504`, ja
darbība joprojām tiek izpildīta pēc mēģinājumu limita izsmelšanas. Galīgā Azure atbilde pirms atgriešanas
izsaucējam tiek normalizēta tādā pašā `pages`/`markdown` formā, kādu izmanto Mistral,
tādēļ klienta kodam nav nepieciešams atsevišķi apstrādāt katru nodrošinātāju.

### Vertex AI DeepSeek OCR autentifikācija un galapunkta noteikšana

`vertex-deepseek-ocr` atkārtoti izmanto to pašu Vertex AI autentifikāciju, ko OmniRoute jau atbalsta
tērzēšanas/attēlu datplūsmai (`open-sse/executors/vertex.ts`): savienojuma API atslēga ir vai nu
pakalpojuma konta JSON akreditācijas dati (kas JWT nesēja
plūsmā tiek apmainīti pret īslaicīgu OAuth piekļuves pilnvaru), vai jau izveidota OAuth piekļuves pilnvara, kas tiek izmantota bez izmaiņām. Augšupējā galapunkta URL ir Vertex
vispārīgais `openapi/chat/completions` partnera galapunkts, kas izveidots no savienojuma projekta un
reģiona — skaidri norādītam `providerSpecificData.project`/`providerSpecificData.region` vienmēr ir prioritāte;
pretējā gadījumā projekts tiek iegūts no pakalpojuma konta JSON lauka `project_id`, bet noklusējuma reģions
ir `us-central1`. Abas vērtības tiek noteiktas failā `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) un izmantotas
`src/app/api/v1/ocr/route.ts` pirms pieprasījuma nosūtīšanas uz `handleOcr`.

### Modeļu cenas (`pricing`)

Ierakstā ir objekts `pricing`, ja OmniRoute zina modeļa cenu. Cena tiek iegūta
no cenu tabulas, ko izmanto izmaksu uzskaitei: iebūvētās noklusējuma vērtības, sinhronizētās cenas un
ignorēšanas vērtības, kas iestatītas, izmantojot `/api/pricing`. Tās ir cenrāža cenas, tāpēc arī abonementu nodrošinātāji
rāda cenu par marķieri.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Lauki                                                           | Mērvienība                         | Piezīmes                                                                                                                                                    |
| --------------------------------------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | USD par marķieri, decimālvirkne    | Saderīgi ar OpenRouter, nekad netiek izmantota eksponentpieraksta forma. Abi kešatmiņas lauki tiek parādīti tikai tad, ja ir norādīta kešatmiņas cena.      |
| `input`, `output`, `cached`, `cache_creation`                   | USD par 1 milj. marķieru, skaitlis | Lauki no iepriekšējām kataloga versijām, kas saglabāti esošajiem klientiem. `reasoning` un `long_context` arī tiek parādīti, ja cenu rindā tie ir norādīti. |

- **Kombinācijām** tiek izmantota to pirmā redzamā mērķa cena. Iebūvētās `auto/*` kombinācijas izvēlas
  mērķi pieprasījuma izpildes laikā, tāpēc tām nav `pricing`.
- **Bezmaksas modeļiem** tiek rādīts `"0"` (un `0`), ja to cena ir nulle. Modelim bez cenu rindas
  arī tiek rādīts `"0"`, ja katalogā tas ir atzīmēts kā bezmaksas (`free: true`) vai arī tas ir norādīts iebūvētajā bezmaksas modeļu
  katalogā.
- **Nezināma cena:** ierakstam nav atslēgas `pricing`.
- **Pakalpojumu sniedzēji ar kredītu uzskaiti** (piemēram, Kiro) izraksta rēķinu par katru pieprasījumu, nevis marķieri. To
  ieraksti saglabā iepriekš izmantotos skaitliskos laukus par 1 milj. marķieru, un tiem nav virkņu lauku ar cenu par marķieri.
- **Varianti** (spriešanas intensitātes identifikatori, aizstājvārdi bez domāšanas, atklāšanas un vārtejas spoguļi)
  kopē tā modeļa cenu, uz kuru tie maršrutē.
- Laukos ir norādītas tikai pamatlikmes. Gara konteksta līmeņi (skaitliskais lauks `long_context`) un
  pakalpojuma līmeņa reizinātāji (piemēram, Codex fast vai flex) nemaina `prompt` vai
  `completion`.
- Objekts ir vienāds visiem autentifikācijas veidiem, tostarp Anthropic stila
  pieprasījumam ar `x-api-key` un `anthropic-version` (atbilde paliek `{ "object": "list",
"data": [...] }`). Implementācija: `src/app/api/v1/models/catalogPricing.ts`.

### Modeļu identifikatoru prefiksi (`?prefix=`)

Lielākā daļa modeļu tiek piedāvāti ar **pakalpojumu sniedzēja prefiksu**. To, kurš prefikss tiek izmantots, nosaka
funkcionalitātes karodziņš `MODELS_CATALOG_PREFIX_MODE`, un to var ignorēt **katram pieprasījumam atsevišķi**, izmantojot
vaicājuma parametru — tas ir noderīgi klientam, kurš vēlas tīru sarakstu, nemainot servera mēroga
iestatījumu visiem pārējiem:

```bash
GET /v1/models?prefix=alias        # viens identifikators katram modelim — īsais aizstājvārda prefikss
GET /v1/models?prefix=dual         # abas formas (servera noklusējums)
GET /v1/models?prefix=canonical    # tikai pilnais pakalpojumu sniedzēja identifikatora prefikss
```

| Režīms      | Izvada                                                   | Piezīmes                                                                                                                                                                                                                                          |
| ----------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **un** `claude/claude-sonnet-4-6` | **Noklusējums.** Abi identifikatori maršrutē uz vienu un to pašu modeli; tie saglabāti, lai turpinātu darboties klientu konfigurācijas, kurās kāda no formām ir iekodēta tieši. Katalogs kļūst aptuveni divreiz lielāks.                          |
| `alias`     | `cc/claude-sonnet-4-6`                                   | Viens ieraksts katram modelim. Pakalpojumu sniedzēji bez atsevišķa aizstājvārda joprojām izvada savu ierakstu, tāpēc nekas netiek zaudēts.                                                                                                        |
| `canonical` | `claude/claude-sonnet-4-6`                               | Viens ieraksts katram modelim ar pilno pakalpojumu sniedzēja identifikatora prefiksu. Pakalpojumu sniedzēji bez atsevišķa aizstājvārda (piem., `antigravity/…`, `agy/…`) arī šeit izvada savu vienīgo identifikatoru, tāpēc nekas netiek zaudēts. |

`dual` režīma spoguli var atpazīt arī bez vaicājuma parametra: tam ir lauks `parent`,
kas norāda uz primāro identifikatoru.

Klientiem, kas attēlo modeļu izvēlni, jāpieprasa `?prefix=alias` — tā dara
[OmniCopilot VS Code paplašinājums](../guides/VSCODE-COPILOT.md).

### Atklāšanas filtri (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` pieņem neobligātus atklāšanas filtrus. Ja neviens no tiem netiek izmantots, atbilde
nemainās. Tie sašaurina katalogu, ko izsaucējs jau redz (vispirms tiek piemērotas API atslēgas atļaujas),
un tie tiek izpildīti pirms OpenAI stila lapošanas ar `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # katrai norādītajai iespējai jābūt patiesai
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # kataloga `type`; rindas bez tā ir `chat`
GET /v1/models?q=sonnet&limit=10                           # reģistrnejutīga atbilstība identifikatoram vai nosaukumam
```

| Parametrs     | Vērtības                                                                                            |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | nenegatīvs vesels skaitlis, kas tiek salīdzināts ar `context_length`                                |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 rakstzīmes                                                                                    |

Nezināmas vērtības vai tādas `min_context` vērtības gadījumā, kas nav nenegatīvs vesels skaitlis (piemēram, `1.5`),
tiek atgriezts HTTP `400`, un ziņojumā ir uzskaitītas derīgās vērtības. Realizācija:
`src/app/api/v1/models/catalogFilters.ts`.

### Modeļu īsais saraksts (`POST /v1/models/query`)

`POST /v1/models/query` atgriež īsu, deterministisku sarakstu no tā paša kataloga, izmantojot tādu pašu
autentifikāciju un katras atslēgas redzamību kā `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Katrs lauks ir neobligāts. `capabilities` un `exclude` var norādīt kā masīvu vai ar komatiem atdalītu virkni;
`max_output` tiek salīdzināts ar `max_output_tokens`. Rezultāti tiek kārtoti pēc `owned_by` un pēc tam pēc `id`.
`limit` noklusējuma vērtība ir `20`, un vērtības virs `100` tiek ierobežotas līdz `100`. Nederīga JSON, nezināma
lauka vai nederīgas vērtības gadījumā tiek atgriezts HTTP `400`.

### Atsevišķi paslēpti tērzēšanas modeļi

Modelis, kas pakalpojumu sniedzēja lapā atzīmēts kā **Paslēpts**, tiek izslēgts no kataloga un noraidīts
ar HTTP `404` / `model_not_found`, ja tas tiek pieprasīts tieši. Pārbaudē tiek izmantots noteiktais
pakalpojumu sniedzējs un modelis, tostarp pakalpojumu sniedzēju aizstājvārdi, saderīgo pakalpojumu sniedzēju mezglu prefiksi un
savienojuma noklusējuma vērtības. Kombinācija izlaiž paslēptos mērķus un var izmantot redzamu radniecīgu mērķi; ja neviens
izpildāms mērķis nav palicis, tā atgriež to pašu kļūdas kodu. Paslēpšanas atcelšana stājas spēkā nākamajā
pieprasījumā. Tikai attēliem paredzēti redzamības iestatījumu pārraksti nepaslēpj tērzēšanas modeli ar tādu pašu ID.

Šis individuālais modeļa iestatījums ir nodalīts no
[modeļu pieejamības atļaušanas/aizliegšanas sarakstiem](../routing/MODEL_EXPOSURE_LIST.md), kas filtrē modeļu
rādīšanu katalogā un automātiskās maršrutēšanas kandidātus, vienlaikus saglabājot tiešu nosūtīšanu. API atslēgu modeļu
atļaujas joprojām tiek piemērotas neatkarīgi. Kataloga prefiksu noklusējuma režīms joprojām ir `dual`.

### Modeļu varianti bez domāšanas

Claude modeļiem, kas atbalsta domāšanu, `/v1/models` reklamē arī **bezdomāšanas** variantu, kura ID priekšā ir `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Atlasot šo ID (piemēram, Claude Code konfigurācijā, kas vienmēr pievieno `thinking` bloku), tas tiek pārveidots atpakaļ uz īsto `<provider>/<model>`, nomācot spriešanu — `thinking:{type:"disabled"}` ceļā `/v1/messages` vai izlaižot laukus `reasoning`/`reasoning_effort` ceļā `/v1/chat/completions`. Variants tiek uzskaitīts tikai Claude saimes modeļiem, kas atbalsta domāšanu **un** ievēro `disabled` (tādēļ, piemēram, modeļi, kas atbalsta tikai adaptīvo režīmu un noraida `disabled`, tiek izslēgti). Operatori var piespiedu kārtā ieslēgt vai izslēgt šo variantu katram modelim, izmantojot `ModelSpec.noThinkingAlias`.

## ElevenLabs audio ģenerēšana

Konfigurējiet `elevenlabs` pakalpojumu sniedzēja savienojumu OmniRoute, izmantojot savu ElevenLabs API atslēgu.
Klienti autentificējas ar savu **OmniRoute** atslēgu (`Authorization: Bearer $OMNIROUTE_API_KEY`);
vārteja nodod saglabāto pakalpojumu sniedzēja atslēgu kā `xi-api-key`. Nekad nesūtiet ElevenLabs atslēgu
kā vārtejas nesēja pilnvaru.

| Metode | Ceļš                        | Atbilde                                              | API atslēgas galapunkta kategorija |
| ------ | --------------------------- | ---------------------------------------------------- | ---------------------------------- |
| POST   | `/v1/sound-generation`      | Sākotnējie audio baiti                               | `elevenlabs`                       |
| POST   | `/v1/music`                 | Sākotnējie audio baiti                               | `music`                            |
| POST   | `/v1/music/stream`          | Straumēti audio baiti                                | `music`                            |
| POST   | `/v1/music/detailed`        | Sākotnējais vairāku daļu audio un kompozīcijas plāns | `music`                            |
| POST   | `/v1/music/detailed/stream` | Sākotnējie SSE metadati un audio fragmenti           | `music`                            |
| POST   | `/v1/music/plan`            | JSON kompozīcijas plāns                              | `music`                            |

Šie galapunkti papildina esošos maršrutus `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` un `/v1/speech-to-text`. Sākotnējie JSON lauki
un vaicājuma parametri, piemēram, `output_format` un `enable_logging`, tiek saglabāti.
`/v1/music/detailed` atbildēs tiek saglabātas vairāku daļu robežas; parsējiet tās kā vairāku daļu saturu.
`/v1/music/detailed/stream` atgriež `text/event-stream` ar kompozīcijas metadatiem un
base64 audio fragmentiem SSE notikumos. Visi seši maršruti atbalsta CORS priekšpārbaudi.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Īss skaņas efekts. Ilgums: no 0,5 līdz 30 sekundēm.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Mūzikas ilgums tiek izteikts milisekundēs: no 3000 līdz 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Izmantojiet `/v1/music/stream` ar to pašu JSON pamattekstu pakāpeniskai audio piegādei. Kompozīcija
pieņem tieši vienu no `prompt` vai `composition_plan`; `/v1/music/plan` pieprasa `prompt`
un pēc izvēles pieņem `source_composition_plan`. Sākotnējās shēmas saglabā pakalpojumu sniedzēja papildu
laukus, lai kompozīcijas plāna versijas un precīzās pielāgošanas opcijas sasniegtu ElevenLabs.

Vienotais galapunkts `/v1/music/generations` pieņem arī `elevenlabs/music_v1`,
`elevenlabs/music_v2` un `elevenlabs/music_v2_5`. Ja ir aktīvs ElevenLabs savienojums,
šie modeļi tiek parādīti mūzikas katalogā. Šis galapunkts atgriež
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Tā lauks `duration` ir norādīts
sekundēs un tiek kartēts uz `music_length_ms`; skaidri norādītam `music_length_ms` ir prioritāte.
`instrumental` tiek kartēts uz `force_instrumental`, un sākotnējam laukam ir prioritāte.
Straumēšanai izmantojiet sākotnējos straumēšanas galapunktus, bet pieprasījumiem, kuru pamatā ir tikai
kompozīcijas plāns, izmantojiet sākotnējo kompozīcijas galapunktu.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Galapunkta, modeļa, budžeta un savienojuma ierobežojumi tiek piemēroti pirms ārējā izsaukuma. Sākotnējie
maršruti atgriež ārējā pakalpojuma statusa kodus un kļūdu pamattekstus bez izmaiņām, tostarp `402` plāna
ierobežojuma gadījumā un `429` kvotas ierobežojuma gadījumā. Galvenes `character-cost`, `song-id`, `request-id` un `retry-after`
tiek saglabātas, ja tās ir pieejamas. Bezmaksas kredīta atlikums negarantē piekļuvi ikvienam
mūzikas modelim, izvades formātam vai API funkcijai: ElevenLabs nosaka tiesības katram pieprasījumam.
Vienotais galapunkts saglabā kļūdu statusa kodus OmniRoute normalizētajā kļūdu aploksnē.

Ārējā pakalpojuma līgumi: [skaņas efekti](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[mūzikas kompozīcija](https://elevenlabs.io/docs/api-reference/music/compose) un
[straumētās mūzikas informācija](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

Visiem POST maršrutiem ir vienāda struktūra: `Bearer your-api-key` + ar Zod validēts JSON ķermenis (`v1RerankSchema`, `v1ModerationSchema`, `v1AudioSpeechSchema` utt.; skatiet `src/shared/validation/schemas.ts`). Shēmas validācijas kļūmes gadījumā tiek atgriezts 4xx.

Klientiem, kuri nevar pievienot `Authorization: Bearer ...`, OmniRoute pieņem API atslēgas arī vietrādī URL, izmantojot vai nu saderību ar vaicājuma virkni (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`), vai tālāk dokumentētos īpašos `/api/v1/vscode/{token}/...` galapunktus.

```bash
# Pārkārtošana (mākoņa reģistra nodrošinātājs vai ar OpenAI saderīga nodrošinātāja mezgls formā "<prefix>/<model>")
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Jina klasificēšana (Foundation API akreditācijas dati)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Jina segmentētājs
POST /v1/segment     { "content": "...", "return_chunks": true }

# Jina meklēšana (s.jina.ai; nodrošinātāja aizstājvārdi: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# Moderācija
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — atgriež audio/mpeg (vai pieprasītā formāta) ķermeni
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS nepieciešama valoda un balss: `language` noklusējuma vērtība ir "en"; ja
# voice nav norādīts vai ir izmantots OpenAI standarta balss nosaukums (alloy, nova, …), tas tiek aizstāts ar "Adrian"
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# Attēla rediģēšana (vairākdaļu)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# Video/mūzikas ģenerēšana (modeļa ID ar nodrošinātāja prefiksu)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **Pārkārtošanas nodrošinātāju mezgli:** `POST /v1/rerank` arī maršrutē pieprasījumus uz OpenAI saderīgiem nodrošinātāju mezgliem
> (oMLX, vLLM, Infinity, TEI aiz vārtejas, …), kas adresēti kā `<node-prefix>/<model>`. Atgriezeniskās cilpas
> mezgli (`localhost`, `127.0.0.1`, `172.16.0.0/12`) vienmēr ir izmantojami, tāpat kā resursdatoru nosaukumi, kurus
> operators norāda mainīgajā `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (piemēram, Docker/Compose pakalpojuma nosaukums,
> tāds kā `http://reranker:8080/v1`; tie tiek izsaukti tieši, nekad neizmantojot `HTTP(S)_PROXY` vai
> savienojumam piesaistītu starpniekserveri). Mezglus jebkurā citā
> resursdatorā — lokālā tīkla datorā vai Tailscale vienādranga mezglā — var izmantot tikai tad, ja operators iespējo
> funkcijas karodziņu `RERANK_REMOTE_PROVIDER_NODES` **un** mezgla bāzes URL atbilst nodrošinātāja
> izejošo URL politikai (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Atmiņas dzinēja pārkārtošanas posms izsauc šo maršrutu, izmantojot
> atgriezenisko cilpu, tāpēc tas pats noteikums attiecas uz `rerankProviderModel` atmiņas iestatījumos.
>
> **Lokālo serveru formāti:** mezgls tiek izsaukts adresē `<base>/v1/rerank` un, saņemot 404, adresē `<base>/rerank`
> (Infinity, TEI). Augšupstraumes pieprasījuma ķermenī ir gan Cohere/OpenAI rakstība (`documents`,
> `return_documents`), gan TEI rakstība (`texts`, `return_text`), un augšupstraumes atbilde tiek
> normalizēta Cohere aploksnes formātā: TEI vienkāršais `[{index, score, text}]`, `{results: [{index, score}]}`
> no vienkāršām vārtejām un Voyage stila `{data: [...]}` tiek atgriezti klientam kā
> `{results: [{index, relevance_score, document?}]}`, sakārtoti pēc vērtējuma un ierobežoti līdz `top_n`.

> **Nodrošinātāju mezglu atklāšana:** OpenAI saderīgā nodrošinātāja mezgla modeļi parādās `GET /v1/models`
> zem mezgla prefiksa. Ieraksti bez galapunktu metadatiem (raksturīgi lokāliem `/v1/models` sarakstiem)
> pārmanto mezgla `apiType`, tāpēc `embeddings` mezgla modeļiem ir `type: "embedding"`, bet
> `rerank` mezgla modeļiem ir `type: "rerank"`, nevis pēc noklusējuma tērzēšanas tips; sinhronizētā vai manuāli
> pievienotā ierakstā skaidri norādītajam `supportedEndpoints` joprojām ir priekšroka.

### Īpašie nodrošinātāju maršruti

```bash
POST /v1/providers/{provider}/chat/completions
POST /v1/providers/{provider}/embeddings
POST /v1/providers/{provider}/images/generations
```

Ja nodrošinātāja prefiksa trūkst, tas tiek pievienots automātiski. Neatbilstoši modeļi atgriež `400`.

## Meklēt API

Web/search sniedzēja abstrakcija (Tavily, Brave, Exa, Serper utt.).

| Metode | Ceļš                   | Apraksts                                                                                              |
| ------ | ---------------------- | ----------------------------------------------------------------------------------------------------- |
| GET    | `/v1/search`           | Uzskaitiet konfigurēto meklēšanas pakalpojumu sniedzēju + iespējas                                    |
| POST   | `/v1/search`           | Palaidiet meklēšanas vaicājumu — body, ko apstiprinājis `v1SearchSchema`, atbalsta caching/coalescing |
| GET    | `/v1/search/analytics` | hit/latency/cache statistika katram pakalpojumu sniedzējam                                            |

**Auth:** Nesēja API atslēga (`extractApiKey` + `isValidApiKey`). Meklēšanas politika tiek īstenota, izmantojot `enforceApiKeyPolicy`.

### Exa un Tavily `provider_options`

Exa un Tavily nolasa pakalpojumu sniedzējam raksturīgus laukus no nosaukumiem sadalīta maisa: `provider_options.exa` (vai `provider_options["exa-search"]`) un `provider_options.tavily` (vai `provider_options["tavily-search"]`). Tiek pārsūtītas tikai tālāk norādītās atslēgas. Katrs no tiem tiek pārbaudīts, salīdzinot ar savu Zod shēmu `open-sse/handlers/search/providerOptionsPassthrough.ts`, un tiek atmesta atslēga ar nepareizu veidu. Jebkura cita atslēga tiek ignorēta, tostarp auth, base URL, `stream` un `outputSchema`. Plakanie taustiņi, ko izmanto citi pakalpojumu sniedzēji (`cx`, `depth`, ...) darbojas tāpat kā iepriekš.

| Pakalpojumu sniedzējs | Augstākā līmeņa lauki                                                                                                                                                                                                                                                                                                                                                     | Ligzdotas                                                                                                                                    |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Piem                  | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (plakanie primitīvie), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                          | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` ir apvienots ar noklusējuma `{ text: true, highlights: true }` |
| Tavilijs              | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                            |

Vienmēr uzvar vispārīgie lauki: `query`, `max_results`, `filters` (domēni), `country` un tēma, kas iegūta no `search_type`. Uz Exa `search_type: "news"` saglabā `category: "news"`. Tavilijs pieņem arī `search_type: "finance"` (`topic: "finance"`).

Firecrawl meklēšanas izmaksas tiek reģistrētas par katru sākto 10 atgriezto rezultātu bloku — 0,002 ASV dolāri (2 kredīti) par bloku un vismaz viens bloks par zvanu ( [Firecrawl norēķini](https://docs.firecrawl.dev/billing) ): 11 rezultāti maksā 0,004 ASV dolārus.

Vispārējais `time_range` tagad sasniedz abus pakalpojumu sniedzējus: Exa iegūst `startPublishedDate` (ISO laikspiedolu), bet Tavily iegūst `start_date` (`YYYY-MM-DD`). Precīzs datums `provider_options` ignorē kartēto datumu.

Eksāmenu rezultāti saglabā `id`, `highlight_scores`, `summary`, `subpages`, `entities` un `extras` `provider_raw`. Tavily rezultāti saglabā `images` un `favicon`.

Saites meklēšanas izmaksas tiek reģistrētas USD 0,005 par `depth` `fast` un `standard` un USD 0,05 par `deep` ( [Saistīšanas cenas](https://docs.linkup.so/pages/documentation/development/pricing) ) neatkarīgi no tā, vai `depth` nāk no `provider_options` vai savienojuma iestatījumiem.

Exa `type: "lite"` (Exa 3.0) pieņem mazāku lauku kopu un noraida visu pieprasījumu, ja ir iestatīts kāds cits lauks. Lite versijai `additionalQueries`, `systemPrompt` un visi `contents` taustiņi, izņemot `text` un `highlights` tiek atmesti pirms izsaukuma. Novecojušie `subpages`, `subpageTarget`, `highlights.numSentences` un `highlights.highlightsPerUrl` vairs netiek pārsūtīti.

Izmaksu uzskaite ir vienotā reģistra `costPerQuery`, izņemot Exa, kas atbilst Exa pašas cenām: USD 0,007 par zvanu `auto` (un mantotā `fast`) vai USD 0,004 par `lite` (un mantoto `instant`), aptverot 10 rezultātus; 0,001 USD par katru nākamo rezultātu; un USD 0,001 par katru atgriezto rezultātu, ja ir iestatīts `contents.summary`. Tavily ir reģistrēts ar 1 kredītu ($ 0,008) par `search_depth` `basic`, `fast` un `ultra-fast` un par 2 kredītiem ($ 0,016) par `advanced` ( [Tavily API credits](https://docs.tavily.com/documentation/api-credits) ). Zvans ar `auto_parameters: true`, ko Tavily jaunina uz uzlaboto, joprojām tiek ierakstīts 1 kredīta apmērā.

## Web Fetch API

Izgūstiet saturu no URL, izmantojot konfigurētu tīmekļa izgūšanas nodrošinātāju (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, tā pati API atslēga, kas Parallel Search) atgriež tikai Markdown
— jebkurš cits `format` izraisa `400` — un ierobežo saturu līdz 100 000 rakstzīmēm. Ja
pašu mērķa lapu nevar izgūt, augšupējais pakalpojums par to ziņo HTTP 200 atbildē;
OmniRoute to atgriež kā `422` ar fiksētu ziņojumu.

| Metode | Ceļš            | Apraksts                                                         |
| ------ | --------------- | ---------------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Izgūst/nolasa URL — ķermenis tiek validēts ar `v1WebFetchSchema` |

**Autentifikācija:** Bearer API atslēga (`extractApiKey` + `isValidApiKey`). Politika tiek piemērota, izmantojot `enforceApiKeyPolicy`.

**Kvotu ņemoša vērā atkāpšanās (#8297):** ja nav norādīts konkrēts `provider`, kopa
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) tiek
pārskatīta fiksētā
prioritāšu secībā (vispirms pilnībā izmantojot augstākas prioritātes nodrošinātāju) — ātruma ierobežojumu sasniedzis, bet konfigurēts nodrošinātājs tiek izlaists,
nevis nekavējoties pārtrauc pieprasījumu, un atkārtojama/kvotas izraisīta augšupējā pakalpojuma kļūme
(HTTP 429 vienmēr; 402/403 Firecrawl/Tavily/TinyFish kvotām raksturīgajos bezmaksas līmeņos —
ne Jina Reader gadījumā un nekad vienkārša 400 nederīga pieprasījuma gadījumā) pieprasījuma izpildes laikā pāriet pie
nākamā vēl neizmēģinātā nodrošinātāja ar akreditācijas datiem. Kad visi kopas nodrošinātāji ir
izsmelti, galapunkts atgriež vienu `429` (ar `Retry-After`
galveni), nevis iepriekšējo vispārīgo `400`. Ja tiek pieprasīts konkrēts `provider`,
**klusas atkāpšanās nav** — ātruma ierobežojumu sasniedzis vai kļūmīgs konkrētais
nodrošinātājs atgriež savu kļūdu (`429`, ja sasniegts ātruma ierobežojums, citādi augšupējā pakalpojuma
statusu).

## WebSocket straumēšana

```bash
GET /v1/ws?handshake=1
```

Validē WebSocket jaunināšanas rokasspiedienu un atgriež vadu protokola ziņojumu piemērus (`request`, `cancel`). Faktiskos WS kadrus apstrādā komplektācijā iekļautais WS serveris ārpus Next.js maršrutu tabulas.

**Autentifikācija:** Bearer API atslēga rokasspiediena laikā.

### Responses API, izmantojot WebSocket (tikai codex)

```bash
# Tas pats resursdators:ports, kas HTTP API (pēc noklusējuma 20128); jauniniet savienojumu:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (vai: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Pirmajam kadram OBLIGĀTI jābūt response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Responses-API-over-WebSocket starpniekserveris ir savienots **tikai ar `codex`** (ChatGPT
aizmugursistēmu). Tas klausās tajā pašā portā, kur API/informācijas panelis, ceļos `/v1/responses`,
`/responses` un `/api/v1/responses`. Saņemot pirmo `response.create` kadru, tas
veic autentifikāciju un sagatavošanu, izmantojot iekšējo `codex-responses-ws` tiltu, atlasa
codex OAuth savienojumu un tunelē uz `wss://chatgpt.com/backend-api/codex/responses`,
izmantojot `wreq-js` transportu. **Modeļi, kas nav codex, tiek noraidīti** (`codex_ws_provider_required`).
Kvotu koplietošanas maršrutēšanai izmantojiet `model: "qtSd/<group>/codex/<model>"`. Ieviests
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Autentifikācija:** Bearer API atslēga rokasspiediena laikā. Komplektācijā iekļautajam HTTP serverim (`server-ws.mjs`)
jābūt aktīvajam ieejas punktam (tas tāds ir pēc noklusējuma, ja pastāv `app/server-ws.mjs`).

#### Modeļa ID: izmantojiet vienkāršo ChatGPT ID (bez `codex/` prefiksa)

OpenAI **Codex CLI** validē modeļa nosaukumu klienta pusē, ja
`supports_websockets = true`, un **noraida ar nodrošinātāja prefiksu papildinātus ID**, piemēram,
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Nosūtiet **vienkāršo** ID (piemēram, `gpt-5.5`). OmniRoute tilts ir
paredzēts tikai codex, tāpēc pirms tunelēšanas uz augšupējo pakalpojumu tas atkārtoti nosaka vienkāršo ID kā codex modeli
(`resolveCodexWsModelInfo`) — kaut gan vienkāršs
`gpt-5.5`, izmantojot HTTP, citādi tiktu maršrutēts uz citu nodrošinātāju.

#### OpenAI Codex CLI konfigurēšana

Novirziet Codex CLI uz OmniRoute, pievienojot pielāgotu nodrošinātāju ar WebSocket
atbalstu failā `~/.codex/config.toml` (izmantojiet atsevišķu `CODEX_HOME`, lai nemainītu
esošo konfigurāciju):

```toml
model = "gpt-5.5"                 # vienkāršs ID — NEVIS "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # bez beigu slīpsvītras; WS URL tiek atvasināts (produkcijā izmantojiet https/wss)
wire_api = "responses"                    # vienīgā atbalstītā vērtība kopš 2026. gada februāra
supports_websockets = true                # iespējo Responses-over-WS transportu
env_key = "OMNIROUTE_API_KEY"             # satur OmniRoute API atslēgu (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # OmniRoute API atslēga (jebkura atslēga, ja REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI jaunina `base_url + /responses` uz WebSocket, un OmniRoute to tunelē
uz atlasīto codex OAuth savienojumu. Pilnībā validēts, izmantojot lokālo
serveri: ChatGPT atgriež `codex.rate_limits` + `response.created` un straumē
pabeigto atbildi.

## Pašapkalpošanās lietojuma dati (`/api/usage/om-usage`)

Jebkura API atslēga var skatīt **savu** lietojumu un kvotas — pārvaldības autentifikācija nav nepieciešama. Šo galapunktu
klients (CLI, OmniCopilot panelis) izmanto, lai parādītu atslēgas turētājam tā izdevumus.

```bash
# Teksta forma (vēsturiskais līgums — vienkāršs teksts terminālim)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Strukturēta forma — paredzēta lietotāja saskarnei
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Atslēgai jābūt iespējotam iestatījumam **`allowUsageCommand`** (pēc noklusējuma tas ir izslēgts — informācijas paneļa API atslēgu
pārvaldnieks to pārslēdz katrai atslēgai atsevišķi). Ja tas nav iespējots, galapunkts atbild ar `403`.

`?format=json` atgriež diskriminētu struktūru, lai izsaucējs nekad nemēģinātu nolasīt datu lauku no
atteikuma. Veiksmīgas atbildes gadījumā:

```jsonc
{
  "allowed": true,
  // pieejams tikai tad, ja atslēgai ir iespējoti individuāli lietojuma ierobežojumi (dienas/nedēļas USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // atlasītā nodrošinātāja kvotas momentuzņēmums vai null, ja nekas vēl nav saglabāts kešatmiņā:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // katra savienojuma momentuzņēmums, lai lietotāja saskarne varētu attēlot vairākus nodrošinātājus līdzās:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Atteikuma gadījumā (`401` nederīga atslēga / `403` nav atļauts) tas pats maršruts atgriež
`{ "allowed": false, "error": { "message": "…" } }` — esošs, bet tukšs `personal`/`provider`
(atslēga ir atļauta, taču dati vēl nav iegūti) ir cits stāvoklis nekā atteikums, un tikai JSON forma
ļauj tos atšķirt.

**Autentifikācija:** izsaucēja paša Bearer API atslēga, kas validēta ar `isValidApiKey` — šī _nav_
pārvaldības saskarne (`/api/keys/…`), kuru joprojām aizsargā `requireManagementAuth`.

### Neapstrādāti un robežvērtības koriģēti kvotu procenti

Izmantojot `/api/usage/om-usage`, izsaucējiem jāņem vērā atšķirība starp procentiem, kas parādīti
**vienkārša teksta izvadē**, un strukturēto **JSON izvadi**:

| Aspekts                      | Vienkārša teksta formāts (`/api/usage/om-usage` / `@@om-usage`)                                        | JSON formāts (`?format=json`)                                                          |
| :--------------------------- | :----------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------- |
| **Izvades lauks**            | `NN% left` (piemēram, `20% left`)                                                                      | `provider.quotas` / `providers[].quotas`                                               |
| **Mērījums**                 | **Pēc robežvērtības koriģēts izmantojamais apjoms**: atlikusī kapacitāte virs robežvērtības            | **Neapstrādāta augšupējā kvota**: nekoriģēts nodrošinātāja mērījums                    |
| **Robežvērtības mērogošana** | Mērogots, izmantojot `effectiveRemainingPercent()`, lai aizsargātā rezerve tiktu attēlota kā `0% left` | Nav (neapstrādātas momentuzņēmuma vērtības, kā tās ziņojis nodrošinātājs)              |
| **Sliekšņa dati**            | Iekļauti parādītajā procentuālajā vērtībā                                                              | Glabāti `quotaWindowThresholds` katram savienojumam (vai servera noklusējuma vērtībās) |
| **Galvenais patērētājs**     | Interaktīvas CLI, termināļa uzvednes, cilvēki-operatori                                                | Programmatiskas integrācijas, informācijas paneļi, analītika, norēķinu uzskaites rīki  |

#### Robežvērtības korekcijas formula

OmniRoute atbalsta proaktīvas kvotu robežvērtības, lai novērstu augšupējo resursu izsmelšanu (konfigurētas, izmantojot savienojuma
`quotaWindowThresholds`, nodrošinātāja noklusējuma vērtības vai globālos noturības iestatījumus). Kad kvotas logam ir aktīva robežvērtība
(piemēram, `cutoff = 25%`), teksta renderētājs aprēķina atlikušo pieejamo apjomu šādi:

- Ja `remaining <= cutoff`: atgriež `0%`.
- Ja `remaining > cutoff`: atgriež `((remaining - cutoff) / (100 - cutoff)) * 100`.

Formatētā teksta izvade to noapaļo līdz tuvākajam veselajam skaitlim (`Math.round(...)`).

#### Ilustratīvs piemērs

Apsveriet nodrošinātāja logu ar **60% neapstrādātu lietojumu** (tātad **40% neapstrādātas atlikušās kvotas**) un konfigurētu
**25% atlikušās kvotas robežvērtību**:

| Attēlojums                             | Aprēķins                                           | Atlikums |           Netieši izmantots           |
| :------------------------------------- | :------------------------------------------------- | :------: | :-----------------------------------: |
| **Neapstrādāts JSON (`?format=json`)** | Augšupējais momentuzņēmums (`quotas[window]`)      | **40%**  |                **60%**                |
| **Teksta formāts (`NN% left`)**        | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%**  | **80%** (aprēķinot `100 - remaining`) |

- **Kāpēc tekstā tiek rādīts 20% atlikums:** No kontā atlikušās 40% fiziskās kvotas 25% ir rezervēti saskaņā ar
  robežvērtības politiku. Izsaucējam ir atlikuši tikai 15% no 75% izmantojamās rezerves, pirms maršrutētājs pārtrauc
  maršrutēšanu uz šo savienojumu. Mērogošana nodrošina, ka savienojums signalizē par izsmelšanu (`0% left`) tieši tad, kad
  maršrutēšana tiks pārtraukta.
- **Kāpēc JSON saglabā neapstrādātās vērtības:** JSON lietderīgā slodze atgriež precīzu nodrošinātāja momentuzņēmumu (`UsageSnapshot`),
  lai ārējiem rīkiem būtu pieejami patiesie augšupējā lietojuma dati un savienojuma līmeņa
  `quotaWindowThresholds` bez servera pusē veiktas informāciju zaudējošas mērogošanas.

#### Norādījumi patērētāju migrācijai

Ja ārējā integrācija (piemēram, redaktora spraudnis vai aģenta paplašinājums) iepriekš ieguva datus no teksta
galapunkta (`NN% left`) un aprēķināja izmantoto procentuālo daļu kā `100 - NN`, migrācija uz `?format=json` nozīmē:

- Neapstrādāto JSON vērtību nolasīšana atspoguļos **faktisko augšupējā avota patēriņu** (iepriekš minētajā piemērā izmantoti 60%).
- Ja integrācija vēlas saglabāt teksta galapunkta izmantojamā atlikuma semantiku, tā klienta pusē var aprēķināt
  faktisko atlikumu, izmantojot `quotaWindowThresholds` savienojuma līmeņa pārrakstījumiem.

Sinhronizētiem/importētiem modeļiem `PUT /api/provider-models` pieņem `provider`, `modelId` un
`maxOutputTokenOverride`: pozitīvs vesels skaitlis iestata manuālu izvades tokenu ierobežojumu, bet `null`

vērtības laukā `modelOutputOverrides`, tostarp modeļiem bez pielāgota modeļa rindas. Pārrakstītā vērtība
izmanto izpildlaika `max_output_tokens` iespēju un saglabājas pēc atkārtotas modeļa sinhronizācijas. Ar OpenAI saderīga
pakalpojumu sniedzēja lapa piedāvā tādas pašas rediģēšanas/notīrīšanas vadīklas un atzīmē modeļus ar tieši norādītu attēlu atbalstu.

Pielāgotie Chat Completions mezgli pielāgo tiešu atteikšanos no spriešanas augšupstraumes aizmugursistēmai.
Veiksmīga savienojuma pārbaude automātiski atlasa tērzēšanas veidnes vadīklas katram precīzam modeļa ID,
kura `/models` ieraksts apliecina atpazītu `owned_by` vērtību: `vllm`, `sglang` vai `llamacpp`.
Caurspīdīgi ar OpenAI saderīgi aplauzēji var saglabāt sākotnējo modeļa ierakstu ligzdotā
`openai` objektā; noteikšana pārbauda līdz trim šādiem aplauzējiem. Modeļi ar trūkstošu, nezināmu vai
pretrunīgu īpašnieka informāciju saglabā parasto OpenAI darbību. Noteikšana atkārtoti izmanto esošo kataloga pieprasījumu,
neģenerē pabeigšanas tokenus un tiek anulēta, kad mainās savienojuma galapunkts.

Lai fiksētu darbību aizmugursistēmai, kas neatklāj šos metadatus, izmantojiet esošo daļējas
pakalpojumu sniedzēja atjaunināšanas API:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Nosūtiet šo ķermeni ar `PUT /api/providers/<connection-id>`. Šajā savienojumā tieši norādīta
spriešanas intensitāte `none` tiek nosūtīta kā `chat_template_kwargs.thinking=false` un
`chat_template_kwargs.enable_thinking=false`. Tieši norādītās vietējās veidnes vērtības saglabā prioritāti,
ja vien servera puses spriešanas kārtula neuzspiež noteiktu intensitāti. Iestatījums tiek lietots tikai tad, ja pielāgots
ar OpenAI saderīgs savienojums nosūta Chat Completions ķermeni; Responses pieprasījumi un parastie
pakalpojumu sniedzēji saglabā savu vietējo pieprasījuma struktūru. Iestatiet `reasoningControl` uz `openai`, lai piespiestu parasto OpenAI
`reasoning_effort` vērtības pārsūtīšanu, vai izlaidiet to/iestatiet uz `null`, lai izmantotu automātisko noteikšanu.

Claude Code automātiskā režīma klasifikatora pieprasījumiem vietējā domāšana pēc noklusējuma tiek atspējota, ja tajos
nav tiešu spriešanas vadīklu. Noteikšana izmanto klasifikatora sistēmas marķieri Claude formāta
pieprasījumos, nevis modeļu nosaukumus vai pabeigšanas ierobežojumus. Tiešajām ķermeņa vadīklām, atbalstītajām intensitātes/domāšanas
galvenēm, maršrutēšanas kārtulām un atrisinātajai modeļa intensitātei saglabājas esošā prioritāte. Abi klasifikatora
posmi saglabā savas uzvednes, pabeigšanas ierobežojumus, apturēšanas secības un reālos augšupstraumes atļauju
spriedumus; otrais posms joprojām var izveidot pieprasīto redzamo spriešanu kā parastu tekstu.

### Versija un laidiena kanāls

```bash
GET /api/system/version
```

Pārvaldības maršruts, kas pieejams tikai no lokālās atgriezeniskās cilpas (administratora autentifikācija). Atgriež pašreizējo versiju, jaunāko
publicēto versiju un automātiskās atjaunināšanas statusu. `releaseChannel` un `channels` ir papildinoši
lauki (atzars 3.8.54); `channel` saglabā savu nozīmi — izvietošanas režīmu, ko izmanto vadības paneļa atjauninātājs
(`npm`, `source` vai `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — darbojošās būvējuma versijas npm kanāls: `nightly` versijām ar `-nightly.*`,
  `next` citiem pirmsizlaides laidieniem (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` stabilai versijai, kuras
  galvenā versija ir vecāka par `channels.latest`, bet visos citos gadījumos — `latest`. Tie paši noteikumi, kas izmantoti
  `scripts/release/dist-tag.mjs`, kurš publicēšanas laikā izvēlas npm dist-tag.
- `channels` — katra dist-tag jaunākā publicētā versija no `npm view omniroute dist-tags` (ar rezerves
  HTTP reģistra pieprasījumu), kas tiek kešota ar tādu pašu 10 minūšu TTL kā `latest`. `latest` vienmēr ir pieejams
  (rezerves variantā izmanto lauku `latest`, pēc tam `"unavailable"`); `next`, `nightly` un `lts` tiek parādīti
  tikai tad, ja attiecīgais dist-tag pastāv. Pieprasījums ar `Cache-Control: no-cache` atsvaidzina abus vaicājumus.

Kanālu modelis (`latest` = v3 līdz 4.0 GA laidienam, `next` = rc, `nightly` = `develop` būvējumi,
`lts` = v3 labojumlaidieni pēc 4.0 GA laidiena) ir aprakstīts failā `docs/ops/RELEASE_STRATEGY.md`.

## Tokenu ierobežojumi

Katras API atslēgas **tokenu** budžeti (atšķirīgi no iepriekš minētā uz USD balstītā budžeta). Tie tiek piemēroti tieši pieprasījuma apstrādes ceļā: kad atslēgas lietojums pašreizējā periodā sasniedz ierobežojumu, pieprasījumi tiek noraidīti ar `429 Too Many Requests`. Ierobežojumus var attiecināt uz konkrētu `model`, `provider` vai piemērot `global` mērogā visai atslēgai; ja pieprasījumam atbilst vairāki ierobežojumi, tiek izmantots visstingrākais.

```bash
# Uzskaitīt atslēgas tokenu ierobežojumus (ietver pašreizējā perioda lietojumu)
GET /api/usage/token-limits?apiKeyId=key-123

# Izveidot vai atjaunināt tokenu ierobežojumu
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Dzēst tokenu ierobežojumu pēc identifikatora
DELETE /api/usage/token-limits?id=tl-abc
```

> **Shēmas piezīmes** (`setTokenLimitSchema`): `apiKeyId` un `scopeType` (`model` | `provider` | `global`) ir obligāti. `scopeValue` ir obligāts, izņemot gadījumus, kad `scopeType` ir `global` (piemēram, modeļa identifikators `model` tvērumam vai nodrošinātāja identifikators `provider` tvērumam). `tokenLimit` jābūt pozitīvam veselam skaitlim (virkne tiek pārveidota). Neobligāti: `id` (izlaidiet, lai izveidotu, norādiet, lai atjauninātu), `resetInterval` (`daily` | `weekly` | `monthly`, noklusējums `monthly`), `resetTime` (`HH:MM`), `enabled` (noklusējums `true`). `GET` atbildēs katrs ierobežojums tiek papildināts ar `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` un `nextResetAt`. Šis ir pārvaldības klases galapunkts (autentifikācija tiek centralizēti īstenota autorizācijas konveijerā).

## Pieprasījumu apstrāde

1. Klients nosūta pieprasījumu uz `/v1/*`
2. Maršruta apstrādātājs izsauc `handleChat`, `handleEmbedding`, `handleAudioTranscription` vai `handleImageGeneration`
3. Tiek noteikts modelis (tiešs nodrošinātājs/modelis vai aizstājvārds/kombinācija)
4. Akreditācijas dati tiek atlasīti no lokālās datubāzes, filtrējot pēc konta pieejamības
5. Tērzēšanai: `handleChatCore` pārbauda semantisko/paraksta kešatmiņu un nosaka kombinācijas saspiešanas iestatījumus
6. Ja iespējota proaktīvā saspiešana, tā tiek veikta pirms pārveidošanas nodrošinātāja formātā (`lite`, Caveman, RTK vai vairāku metožu secīga kombinācija)
7. Nodrošinātāja izpildītājs nosūta pieprasījumu ārējam pakalpojumam
8. Atbilde tiek pārveidota atpakaļ klienta formātā (tērzēšanai) vai atgriezta bez izmaiņām (iegultnēm/attēliem/audio)
9. Tiek reģistrēts lietojums, saspiešanas analītika un pieprasījumu žurnāli
10. Kļūdu gadījumā saskaņā ar kombinācijas noteikumiem tiek izmantots rezerves variants

Pilna arhitektūras atsauce: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Noturība (paplašināti)

OmniRoute nodrošina trīs neatkarīgus īslaicīgu kļūmju apstrādes mehānismus; tālāk norādītie pārvaldības galapunkti ļauj operatoriem nolasīt un pārrakstīt to iestatījumus:

| Tvērums                                 | Stāvokļa glabāšana                                    | Nolasīšana                                | Atiestatīšana / notīrīšana                                                  |
| --------------------------------------- | ----------------------------------------------------- | ----------------------------------------- | --------------------------------------------------------------------------- |
| Pakalpojumu sniedzēja ķēdes pārtraucējs | `domain_circuit_breakers` + atmiņā                    | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                                |
| Savienojuma nogaidīšanas periods        | `rateLimitedUntil` pakalpojumu sniedzēja savienojumos | `/api/rate-limits`, `/api/providers/[id]` | (atkārtoti iespējo atlikti; notīriet, izmantojot pakalpojumu sniedzēja PUT) |
| Modeļa bloķēšana                        | Atmiņā esošs modeļu pieejamības reģistrs              | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                                    |

`PATCH /api/resilience` pieņem pakalpojumu sniedzēja ķēdes pārtraucēja pārrakstīšanas iestatījumus zem `providerBreaker.oauth` un `providerBreaker.apikey`. Katrs profils atbalsta `degradationThreshold`, `failureThreshold` un `resetTimeoutMs`; tie paši lauki ir pieejami sadaļā Informācijas panelis → Iestatījumi → Noturība.

```bash
# Notīrīt viena modeļa bloķēšanu
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Notīrīt visas bloķēšanas
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Pilnu konceptuālo atsauci un ķēdes pārtraucēja noklusējuma iestatījumus skatiet [`CLAUDE.md`](../../CLAUDE.md) → „Noturības izpildlaika stāvoklis” un [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Ātruma ierobežojumu rinda un automātiskās iespējošanas drošības tīkls

- **Atbalstītais rakstīšanas ceļš**: `POST /api/rate-limits` ar pamattekstu `{"connectionId": "<id>", "enabled": true|false}` ir atbalstītais pārvaldības galapunkts, lai savienojumam ieslēgtu vai izslēgtu ātruma ierobežojumu aizsardzību. `PUT /api/providers/[id]` apzināti nemaina un nepārslēdz `rateLimitProtection` (#11278).
- **`enabled: false` semantika**: Iestatot `enabled: false`, savienojumam tiek noņemta tiešā aizsardzība, taču aktīvs API atslēgas savienojums **netiek** izslēgts no globālā automātiskās iespējošanas drošības tīkla (`autoEnableApiKeyProviders = true`). Funkcijā `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) vērtības `false` un `undefined` ir līdzvērtīgas; aktīvie API atslēgas savienojumi bez tieši norādītas aizsardzības joprojām tiek aizsargāti ar automātiskās iespējošanas drošības tīklu.
- **Globāla atspējošana**: Lai izmantotu API atslēgas savienojumus bez ātruma ierobežojumu rindām, globāli atspējojiet drošības tīklu, izmantojot `RATE_LIMIT_AUTO_ENABLE=false` (vides mainīgais) vai `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Iestatījumi → Noturība / `PATCH /api/resilience`).

## A2A serveris

OmniRoute nodrošina A2A (aģents–aģents) JSON-RPC 2.0 galapunktu, kā arī REST ietvaru pārbaudes un informācijas paneļa vajadzībām.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # neobligāts, ja vien nav iestatīts OMNIROUTE_API_KEY
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Atbalstītās metodes (visas ir atkarīgas no `settings.a2aEnabled`):

| Metode           | Apraksts                                                        |
| ---------------- | --------------------------------------------------------------- |
| `message/send`   | Sinhrona prasmes izpilde; atgriež `{task, artifacts, metadata}` |
| `message/stream` | Tās pašas prasmju kopas straumēta SSE izpilde                   |
| `tasks/get`      | Iegūst uzdevumu pēc `taskId`                                    |
| `tasks/cancel`   | Atceļ uzdevumu pēc `taskId`                                     |

Iebūvētās prasmes: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Aģenta karte

```bash
GET /.well-known/agent.json
```

Atgriež publisko A2A aģenta karti (nosaukumu, aprakstu, iespējas, prasmju katalogu, autentifikācijas shēmu) — publiski kešota 1 stundu. Autentifikācija nav nepieciešama.

### REST palīgfunkcijas

| Metode | Ceļš                         | Apraksts                                                                                                               |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | A2A iespējots statuss + uzdevumu statistika + kešotās aģenta kartes kopsavilkums                                       |
| GET    | `/api/a2a/tasks`             | Uzdevumu saraksts — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Nav ieviests kā REST palīgfunkcija — izveidojiet, izmantojot JSON-RPC `message/send`)                                 |
| GET    | `/api/a2a/tasks/[id]`        | Iegūst vienu uzdevumu                                                                                                  |
| POST   | `/api/a2a/tasks/[id]/cancel` | Atceļ uzdevumu                                                                                                         |

**Autentifikācija:** REST palīgfunkcijas darbojas bez pārvaldības autentifikācijas (pieejamas informācijas paneļa lasīšanai); JSON-RPC maršruts `/a2a` izmanto Bearer `OMNIROUTE_API_KEY`, ja tas ir konfigurēts.

## Autentifikācija

Skatiet [pārvaldības autentifikācijas](../guides/MANAGEMENT-AUTH.md) ceļvedi, lai uzzinātu par četrām
akreditācijas datu saimēm (informācijas paneļa sesiju, lokālo CLI pilnvaru, `oma_live_…` piekļuves
pilnvaru, API atslēgu ar pārvaldības tvērumu) un to atšķirībām no inferenču atslēgām.

- Informācijas paneļa maršruti (`/dashboard/*`) izmanto `auth_token` sīkfailu
- Pieteikšanās izmanto saglabāto paroles jaucējvērtību; kā rezerves variants tiek izmantots `INITIAL_PASSWORD`
- `requireLogin` var ieslēgt vai izslēgt, izmantojot `/api/settings/require-login`
- `/v1/*` maršruti var pieprasīt Bearer API atslēgu, ja `REQUIRE_API_KEY=true`
- Šajā atsaucē „pārvaldības pilnvara” / „API atslēga ar pārvaldības tvērumu” nozīmē kādu no šajā ceļvedī aprakstītajām saimēm, nevis kādu nedefinētu papildu slepenā noslēpuma veidu

> **Nesaderīga izmaiņa (v3.8.0)** — `/api/v1/agents/tasks/*` un atdzišanas perioda pārvaldības galapunktiem tagad ir nepieciešama **pārvaldības autentifikācija** (informācijas paneļa `auth_token` sīkfails vai API atslēga ar pārvaldības tvērumu). Klienti, kuri iepriekš izsauca šos maršrutus bez autentifikācijas, saņems `401 Unauthorized`. Skatiet komitu `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
