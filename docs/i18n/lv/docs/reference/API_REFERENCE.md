## Tērzēšanas pabeigšanas

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Pielāgotas galvenes

| Header                   | Direction | Description                                                                                                                                                                                                                                  |
| ------------------------ | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | Request   | Iestatiet uz `true`, lai apietu kešatmiņu                                                                                                                                                                                                    |
| `x-omniroute-no-memory`  | Request   | Iestatiet uz `true`, lai šim pieprasījumam izlaistu atmiņas un prasmju ievietošanu (atspoguļo no-cache; novērš katra izsaukuma marķieru/izmaksu pieskaitījumu)                                                                               |
| `X-OmniRoute-Progress`   | Request   | Iestatiet uz `true`, lai aktivizētu norises notikumus                                                                                                                                                                                        |
| `X-Session-Id`           | Request   | Noturīgas sesijas atslēga ārējai sesijas piesaistes nodrošināšanai                                                                                                                                                                           |
| `x_session_id`           | Request   | Tiek pieņemts arī variants ar pasvītrojumu (tiešajam HTTP)                                                                                                                                                                                   |
| `X-OmniRoute-Session-Id` | Request   | Izsaucēja nodrošināta sesijas/sarunas atzīme (tiek izmantota arī atmiņā). Ja tā ir norādīta, tā tiek saglabāta `call_logs.session_tag` nemainītā veidā sesijas izmaksu attiecināšanai (#8249) — ja tā nav norādīta, tā nekad netiek ģenerēta |
| `Idempotency-Key`        | Request   | Dublēšanas novēršanas atslēga (5 sekunžu logs)                                                                                                                                                                                               |
| `X-Request-Id`           | Request   | Alternatīva dublēšanas novēršanas atslēga                                                                                                                                                                                                    |
| `x-omniroute-connection` | Request   | Piesaista viena modeļa pieprasījumu vienam nodrošinātāja savienojumam (kontam) pēc tā ID — skatiet [Konta piesaiste katram pieprasījumam](#account-pinning-per-request)                                                                      |
| `X-OmniRoute-Cache`      | Response  | `HIT` vai `MISS` (ne straumēšanas režīmā)                                                                                                                                                                                                    |
| `X-OmniRoute-Idempotent` | Response  | `true`, ja dublēšana ir novērsta                                                                                                                                                                                                             |
| `X-OmniRoute-Progress`   | Response  | `enabled`, ja norises izsekošana ir aktivizēta                                                                                                                                                                                               |
| `X-OmniRoute-Session-Id` | Response  | Efektīvais sesijas ID, ko izmanto OmniRoute                                                                                                                                                                                                  |
| `X-OmniRoute-Request-Id` | Response  | Pieprasījuma korelācijas ID (ja zināms)                                                                                                                                                                                                      |
| `X-OmniRoute-Version`    | Response  | OmniRoute būvējuma versija (vienmēr ir pieejama)                                                                                                                                                                                             |
| `X-OmniRoute-Cost-Saved` | Response  | USD summa, ko kešatmiņa ietaupīja `HIT` gadījumā (tikai kešatmiņas trāpījumiem)                                                                                                                                                              |
| `X-OmniRoute-Decision`   | Response  | Maršrutēšanas izsekojums: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` ir kombinētā stratēģija vai `single` pieprasījumam, kas nav kombinēts) — vienmēr ir pieejams pabeigšanas atbildēs                                    |

> Nginx piezīme: ja izmantojat galvenes ar pasvītrojumiem (piemēram, `x_session_id`), iespējojiet `underscores_in_headers on;`.

#### Konta piesaiste katram pieprasījumam

Ja nodrošinātājam ir vairāki savienojumi (konti vai atslēgas), OmniRoute parasti izvēlas vienu,
izmantojot sava konta atlases stratēģiju. Tā vietā pieprasījums var piesaistīt vienu konkrētu savienojumu,
izmantojot galveni `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Kur atrast ID.** Atveriet pakalpojumu sniedzēja lapu informācijas panelī
  (**Informācijas panelis → Pakalpojumu sniedzēji → <provider>**) un savienojuma rindā noklikšķiniet uz `xxxxxxxx…` ID elementa — tas nokopēs pilno savienojuma ID.
- **Kuri pieprasījumi to ievēro.** Viena modeļa pieprasījumi (`provider/model`) uz
  `/v1/chat/completions`, `/v1/messages` un `/v1/responses`. Kombinācijas galveni ignorē: piesaistiet kontu katram kombinācijas solim, izmantojot paša soļa savienojumu.
- **Piesaistīšana ir obligāta, nevis tikai ieteikums.** Piesaistītais savienojums tiek izmantots tikai un vienīgi. Kļūme pieprasījuma laikā reģistrē konta dīkstāves periodu, bet **nepārslēdzas** uz citu tā paša pakalpojumu sniedzēja kontu.
- **Dīkstāves periods un kvota atceļ piesaisti.** Kamēr piesaistītais savienojums atrodas dīkstāves periodā, ir izsmēlis kvotu vai kvotas politika to bloķē, nākamie pieprasījumi tiek novirzīti uz citiem pakalpojumu sniedzēja savienojumiem — tieši tāpat kā nepiesaistītas datplūsmas gadījumā.
- **Nezināmi vai atspējoti ID izraisa kļūmi.** ID, kas neatrodas pakalpojumu sniedzēja aktīvajā kopā (ir dzēsts, deaktivizēts vai pieder citam pakalpojumu sniedzējam), neatstāj nevienu piemērotu kontu, tāpēc pieprasījums neizdodas, nevis tiek nemanāmi novirzīts citur.

Claude Code nosūta pielāgotās galvenes, izmantojot `ANTHROPIC_CUSTOM_HEADERS`. Ievietojiet to
`~/.claude/settings.json` blokā `env` vai projekta līmeņa failā `.claude/settings.json`, lai katram projektam piesaistītu citu kontu:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Avots: `src/sse/handlers/chat.ts` (galvenes nolasīšana), `src/sse/services/auth.ts` un
`src/sse/services/sessionAffinityPin.ts` (piesaistes atbrīvošana un pārbaude, vai savienojums trūkst kopā).

> **Izmaksu telemetrijas galvenes:** sekmīgas atbildes bez straumēšanas ietver arī `X-OmniRoute-*` izmaksu telemetrijas kopu — `X-OmniRoute-Response-Cost` (USD, fiksētas 10 zīmes aiz komata; `0.0000000000` bezmaksas vai nenovērtētam pieprasījumam), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` un `X-OmniRoute-Fallback-Attempts` (tikai tad, ja vērtība ir > 0), kā arī `X-OmniRoute-Request-Id` un `X-OmniRoute-Version`. Tās tiek izvadītas tērzēšanas pabeigšanas pieprasījumos, `/v1/responses`, `/v1/messages` un **multivides galapunktos** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` un `/v1/moderations` (vienmēr ar izmaksām `0`). Multivides izmaksas tiek aprēķinātas atbilstoši modalitātei (par attēlu, sekundi, rakstzīmi vai meklēšanas vienību), ja ir pieejama cenu informācija; pretējā gadījumā tās ir `0` (fail-open).

> **Kešatmiņas trāpījuma izmaksu semantika:** semantiskās kešatmiņas trāpījuma gadījumā (`X-OmniRoute-Cache-Hit: true`) netiek veikts augšupējs izsaukums, tāpēc `X-OmniRoute-Response-Cost` vērtība ir `0.0000000000` (trāpījuma apkalpošanas **inkrementālās** izmaksas). Sākotnējās vai paredzamās izmaksas tiek norādītas atsevišķi laukā `X-OmniRoute-Cost-Saved`. Norēķinu patērētājiem jāsumē `X-OmniRoute-Response-Cost` (trāpījumi neko nemaksā); kešatmiņas analītikā var apkopot `X-OmniRoute-Cost-Saved`.

## Ekskluzīvas pārvaldītu sesiju nomas

Ekskluzīva pārvaldītu sesiju noma ir pēc izvēles aktivizējams, no klienta neatkarīgs maršrutēšanas līgums: viens aktīvs īpašnieks tur vienu piemērotu OmniRoute savienojumu. Tas nenomā modeli, neprasa OAuth, neidentificē konkrētu klientu un neprasa konkrētu nodrošinātāju.

Autentificējošajai API atslēgai ir jābūt tvērumam `lease:exclusive` un skaidri norādītam sarakstam `allowedConnections`, kas nav tukšs. Datubāzes mutācijas robeža nodrošina abu lauku izmantošanu kopā atslēgas izveides un daļēju atjauninājumu laikā.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Veiksmīgas iegūšanas, atjaunošanas un atbrīvošanas atbildes atklāj laika zīmogus, `state` un precīzu pozitīvu `generation`, bet nekad neizpauž atlasīto savienojumu vai akreditācijas datus. Atjaunošana un atbrīvošana JSON pamattekstā nosūta paaudzi:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Aktīvs nomas īpašnieks var skaidri pieprasīt privātumu aizsargājošus parādāmos metadatus par savu pašreizējo piesaisti:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Šī pēc izvēles aktivizējamā statusa darbība vienā datubāzes transakcijā tiek norobežota ar necaurspīdīgo īpašnieku, autentificēto pārvaldīto API atslēgu un precīzu aktīvo paaudzi. `displayName` ir tikai apgriezts konfigurētais savienojuma nosaukums; ja nav droša konfigurēta nosaukuma, tā vērtība ir `null`. OmniRoute nekad neaizstāj šo vērtību ar e-pastu vai ģenerētu konta identitāti. Nodrošinātāja vērtība ir nesensitīva parādāmā etiķete, nevis ģenerēts ar saderīgu nodrošinātāju saistīts identifikators. Akreditācijas dati, marķieri, sīkdatnes, neapstrādāti savienojumu vai API atslēgu ID, īpašnieku jaucējvērtības, norobežošanas noslēpumi un iekšējie maršrutēšanas dati netiek iekļauti.

Nepareizas atslēgas, nepareiza īpašnieka, novecojušas paaudzes, neesošas, beigušās, atbrīvotas un anulētas meklēšanas darbības visas atgriež vienu un to pašu `409 LEASE_FENCE_STALE` kļūdu bez savienojuma metadatiem. Klientam, kurš saņēmis atbildi par gaidīšanu uz kapacitāti, nav aktīvas piesaistes, ko pārbaudīt. Kad maršrutēšana pāriet uz aktīvu nomu, tā pati paaudze paliek derīga, un statuss atomiski atgriež jauno piesaisti, nekad ne veco. Esošie klienti paliek nemainīti, jo iegūšanas, atjaunošanas, atbrīvošanas un gaidīšanas atbildes saglabā iepriekšējās struktūras.

Šis servera līgums nemaina standarta OpenAI Codex `/status`. Standarta Codex pašlaik ziņo par sava modeļa nodrošinātāju un iebūvēto autentifikācijas/konta stāvokli, bet nerāda patvaļīgus pielāgotu nodrošinātāju konta metadatus; vēlākai klienta integrācijai būs jāizsauc šī darbība un jāizlemj, kā parādīt `connection.displayName`.

Katrs pārvaldītais secināšanas pieprasījums pēc tam nosūta abas vadības galvenes:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Precīzais īpašnieks, paaudze, aktīvais savienojums un autentificētā API atslēga tiek norobežoti tieši pirms katra atbalstītā augšupējā mēģinājuma. Īpašnieka un paaudzes atkārtota izmantošana ar citu atslēgu neizdodas pat tad, ja šī atslēga atļauj to pašu savienojumu. Neapstrādāti īpašnieki netiek saglabāti, reģistrēti, paturēti pieprasījuma momentuzņēmumā vai pārsūtīti augšupēji.

Īslaicīga konkurence atgriež HTTP `429` ar `Retry-After` un:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Šī atbilde nozīmē tikai to, ka parastais piemēroto vienību kopums nebija tukšs un katru brīvo kandidātu turēja ārvalstīgs aktīvs nomas īpašnieks. Neatbalstīti modeļi/nodrošinātāji, politikas neatbilstība, atdzišanas periods, kvota, veselības stāvoklis un citas parastās piemērotības kļūmes saglabā savas esošās OmniRoute atbildes.

### `x-omniroute-compression`

Pieprasījuma līmeņa saspiešanas plāna aizstājējs. Augstākā prioritāte — pārspēj maršrutēšanas kombinācijas aizstājēju, aktīvo profilu, automātisko aktivizēšanu un paneļa Default. Vērtības:

| Vērtība       | Ietekme                                                                                                   |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| `off`         | Šim pieprasījumam saspiešana netiek izmantota.                                                            |
| `default`     | No paneļa atvasinātais Default profils (ignorē aktīvo profilu). Dzinēji ar zudumiem paliek izslēgti.      |
| `safe`        | Tikai dublikātu noņemšana un atstarpju apvienošana.                                                       |
| `allow-lossy` | Šim pieprasījumam tiek saglabāts operatora plāns, tostarp kopsavilkumi un stila pārrakstīšana.            |
| `engine:<id>` | Viens iespējots dzinējs, piemēram, `engine:rtk`. Šī dzinēja aktivizēšana konkrētajam pieprasījumam.       |
| `<combo>`     | Nosaukta kombinācija, kas vispirms tiek sameklēta pēc nosaukuma (neatkarīgi no reģistra), pēc tam pēc ID. |

Piezīmes:

- Nezināmas vērtības tiek ignorētas (pieprasījums nekad netiek noraidīts); izvēle pāriet uz parasto operatora prioritātes secību.
- Ja vairākām kombinācijām ir viens nosaukums, deterministiskai atlasei nododiet kombinācijas **id**.
- Kombināciju, kuras nosaukums ir `off` vai `default`, nevar atlasīt pēc nosaukuma (šie atslēgvārdi tiek interpretēti vispirms); šādu kombināciju norādiet pēc tās ID.
- Galvenais saspiešanas slēdzis ir stingrs vārtsargs: ja saspiešana ir globāli atspējota, šī galvene to nevar iespējot.

Piemērotais plāns tiek atgriezts atbildes galvenē:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

kur `<source>` ir viena no vērtībām `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` vai `off`.

## Iegulumi

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Pieejamie nodrošinātāji: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Kataloga ID ir `provider/model` (piemērs: `jina-ai/jina-embeddings-v5-omni-small`). Arī neizgreznotie Jina modeļu ID, kas parādās reģistrā (piemēram, `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`), tiek atpazīti. Jina iegulšanas/pārkārtošanas/klasificēšanas/segmentēšanas modeļi vispirms izmanto informācijas paneļa `jina-ai` akreditācijas datus; `JINA_AI_API_KEY` ir rezerves variants tikai tad, ja informācijas panelī nav atslēgas. `jina-reader` kartīte ir paredzēta tikai Reader / `r.jina.ai` (`POST /v1/web/fetch`) un nekad nenodrošina iegulšanu vai pārkārtošanu.

Reģistra modeļi, kas norāda uz multimodālā satura atbalstu, pieņem arī līdz 32 no nodrošinātāja neatkarīgiem strukturētiem elementiem. Multivides elementu tipi ir `text`, `image`, `audio`, `video` un `document`. To multivides `source` ir vai nu `{"type":"url","url":"https://..."}`, vai
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
un saimes aizstājvārds `jina-ai/jina-embeddings-v5-omni` → omni-small) pieņem arī Jina vietējo
EmbeddingsV5Request dokumentāciju un **nemainītā veidā pārsūta to** uz
`https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Vietējās `{ image | audio | video | pdf }` vērtības var būt publisks HTTPS URL, `data:` URI vai neapstrādāts
base64. OmniRoute nepārvērš šos objektus par virknēm un neiegūst vietējos attēlu URL — Jina
pati iegūst publisko multividi. Papildu Jina lauki (`task`, `normalized`, `truncate`, `embedding_type`) tiek
pārsūtīti. Jina SKU, kas paredzēti tikai tekstam, joprojām noraida dokumentus, kas nav teksta dokumenti.

Drošības un transportēšanas ierobežojumi:

- Attālās multivides URL ir jābūt publiskiem HTTPS URL. Kanoniskie `{type,source:url}` elementi tiek iegūti
  servera pusē (novirzīšanas atkārtota validācija, taimauts, izmēra ierobežojumi, publiskais DNS, savienojuma piesaiste) un
  iegulti pirms izsaukuma pie nodrošinātāja. Jina vietējie `{image:"https://..."}` elementi tiek pārsūtīti kā ir
  pēc tādas pašas publiskā HTTPS pārbaudes; Jina iegūst URL.
- Iekļautās base64 multivides apjoms ir ierobežots līdz 8 MiB dekodētā veidā katram elementam un 16 MiB dekodētā veidā visam pieprasījumam.

Nodrošinātāja tulkošana (kanoniskie elementi nekad netiek pārsūtīti nemainīti):

- Jina multimodālie modeļi: katrs augstākā līmeņa elements kļūst par vienu modalitātes atslēgai piesaistītu objektu
  (`text` / `image` / `audio` / `video` / `pdf`), izmantojot datu URI iekļautajai multividei; viens vektors katram
  augstākā līmeņa elementam.
- Gemini Embedding 2 saime: viens augstākā līmeņa masīvs kļūst par vienu vietējo
  `models/{model}:embedContent` pieprasījumu ar `content.parts` (`text` vai `inline_data`).
- llama.cpp (`llama-cpp/<model>`, jebkurš modelis, ko ielādējis lokālais serveris): kanoniskie `text` elementi
  kļūst par vienkāršām virknēm, bet `image` / `audio` / `video` kļūst par vienu
  `{"content": [part]}` objektu katrs, izmantojot llama-server tērzēšanas satura daļas (`image_url`,
  `input_audio` ar formātu `wav` / `mp3` / `flac`, `input_video`) ar iekļautiem datiem; viens vektors katram
  augstākā līmeņa elementam. Serverim jādarbojas ar `--embedding --mmproj …`; bez projektora tas pats noraida multividi.
  `document` netiek atbalstīts.
- Nezināmi/dinamiski modeļi bez skaidri norādītiem modalitātes metadatiem noraida strukturētu ievadi ar HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Neatbalstītas modeļa/modalitātes kombinācijas atgriež HTTP 400, nevis piespiež elementu pārveidošanu. Neievades
paplašinājuma lauki mantotajos virkņu/marķieru pieprasījumos joprojām tiek pārsūtīti nemainīti.

```bash
# Uzskaitīt visus iegulumu modeļus
GET /v1/embeddings
```

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Pieejamie pakalpojumu sniedzēji ietver OpenAI (GPT Image 2 ), xAI (Grok Image ), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana,**OpenRouter** ,**ZenMux** , SD WebUI (lokālais), ComfyUI (lokālais).

`n` atgriež `n` attēlus `data[]`. Pakalpojumu sniedzēji, kuru augšējais API atgriež vienu attēlu katrā izsaukumā (Black Forest Labs, Stabilitātes AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik, NVIDIA NIM, Cloudflare Workers AI), saņem `n` atsevišķus augšupējus zvanus, ne vairāk kā 4 lidojuma laikā. Fiksētais `seed` tiek kompensēts ar izsaukuma indeksu (`seed`, `seed + 1`, …), tāpēc attēli atšķiras, bet joprojām ir reproducējami. `n` ierobežojums ir 10. Ja kāds zvans neizdodas, pieprasījums kopumā neizdodas. Fan-out formātu saraksts ir `SINGLE_IMAGE_FANOUT_FORMATS` formātā `open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux atkārtoti izmanto esošo API atslēgas savienojumu un pieņem `zenmux/` vai `zm/` prefiksus:

- `zenmux/openai/gpt-image-2` izmanto ZenMuxOpenAI attēlus API. Iespējas ietver `size`, `quality`, `n`, `output_format`, `output_compression`, `background` un `response_format`.
- Citi izdevēji, piemēram, `zm/meta/muse-image-1.0`, izmanto ZenMux galapunktu Vertex AI `:predict`. `n` kartē uz `sampleCount`, `aspect_ratio` uz `aspectRatio` un `image_size` (`1K`, `2K`, `4K`) uz `sampleImageSize`. Pikseļu `size` nodrošina tikai malu attiecību, nevis garantētus pikseļu izmērus. Atbalstītās proporcijas, izšķirtspējas un skaitļi atšķiras atkarībā no modeļa.
- `zm/inclusionai/ming-image-0.1-design` izvēlas savus izmērus. Izlaist `size`, `aspect_ratio` un `image_size`; skaidras vērtības atgriež HTTP 400. PNG, JPEG un WebP var pieprasīt ar `output_format`.

Šī integrācija atbalsta teksta pārveidošanu attēlā, nevis atsauces attēlu rediģēšanu. Virsotnes izvade tiek normalizēta uz `data[].b64_json`; `response_format: "url"` atgriež augšējo HTTPS URL vai base64 datu URL ja ir pieejami tikai attēla baiti. Empty/filtered izvadi atgriež kļūdu, nevis tukšu panākumu. Modeļa piekļuve ir atkarīga no ZenMux konta. Skatiet [ZenMux virsotnes API](https://docs.zenmux.ai/api/vertexai/generate-images) un [OpenAI attēlus API](https://docs.zenmux.ai/api/openai/generate-an-image).

Skatiet [Microsoft 365 Copilot](../providers/COPILOT-M365.md#image-generation).

```json
  "usage_info": { "pages_processed": 1 }
}
```

### Azure Document Intelligence aptaujas plūsma

Azure Document Intelligence `analyze` API ir asinhrona: sākotnējais pieprasījums pamatteksta vietā atgriež
`Operation-Location` galveni, un rezultāts ir jāiegūst, veicot aptauju. Apdarinātājs
(`open-sse/handlers/ocr.ts`) aptaujā šo URL reizi sekundē, veicot ne vairāk kā 30 mēģinājumus, nekavējoties pārtrauc darbu (nepārtrauc aptauju)
ja aptaujas atbilde nav `ok` vai tās statuss ir `"failed"`, un atgriež `504`, ja pēc mēģinājumu limita beigām darbība joprojām tiek izpildīta. Galīgā Azure atbilde tiek
normalizēta tajā pašā `pages`/`markdown` formā, ko izmanto Mistral, pirms tā tiek atgriezta
izsaucējam, tāpēc klienta kodam nav īpaši jāapstrādā konkrētais nodrošinātājs.

### Vertex AI DeepSeek OCR autentifikācija un galapunkta atrisināšana

`vertex-deepseek-ocr` atkārtoti izmanto to pašu Vertex AI autentifikāciju, ko OmniRoute jau atbalsta
tērzēšanas/attēlu datplūsmai (`open-sse/executors/vertex.ts`): savienojuma API atslēga ir vai nu
Service Account JSON akreditācijas dati (apmainīti pret īslaicīgu OAuth piekļuves pilnvaru, izmantojot JWT-bearer
plūsmu), vai jau izveidota OAuth piekļuves pilnvara, kas tiek izmantota bez izmaiņām. Augšupējā galapunkta URL ir Vertex vispārīgais
`openapi/chat/completions` partnera galapunkts, kas izveidots no savienojuma projekta un reģiona — tieši norādīts
`providerSpecificData.project`/`providerSpecificData.region` vienmēr ir prioritārs;
pretējā gadījumā projekts tiek iegūts no Service Account JSON `project_id`, bet reģiona noklusējuma vērtība ir
`us-central1`. Abas atrisināšanas darbības notiek failā `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), un tās izmanto
`src/app/api/v1/ocr/route.ts` pirms nosūtīšanas uz `handleOcr`.

### Modeļu cenas (`pricing`)

Ieraksts satur objektu `pricing`, ja OmniRoute zina modeļa cenu. Cena tiek iegūta no cenu
tabulas, ko izmanto izmaksu uzskaite: iebūvētajām noklusējuma cenām, sinhronizētajām cenām un
ignorētajām vērtībām, kas iestatītas, izmantojot `/api/pricing`. Tās ir kataloga cenas, tāpēc
arī abonēšanas pakalpojumu sniedzējiem tiek rādīta cena par tokenu.

```json
"pricing": {
  "prompt": "0.000005",
  "completion": "0.000025",
  "input_cache_read": "0.0000005",
  "input_cache_write": "0.00000625",
  "input": 5,
  "output": 25,
  "cached": 0.5,
  "cache_creation": 6.25
}
```

| Lauki                                                           | Vienība                       | Piezīmes                                                                                                                                                      |
| --------------------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`, `completion`, `input_cache_read`, `input_cache_write` | USD par tokenu, decimālvirkne | Saderīgi ar OpenRouter, nekad eksponentnotācijā. Abi kešatmiņas lauki tiek rādīti tikai tad, ja ir pieejama kešatmiņas cena.                                  |
| `input`, `output`, `cached`, `cache_creation`                   | USD par 1M tokeniem, skaitlis | Lauki no iepriekšējām kataloga versijām, kas saglabāti esošajiem klientiem. `reasoning` un `long_context` tiek rādīti arī tad, ja cenu rindā tie ir norādīti. |

- **Kombinācijām** tiek norādīta to pirmā redzamā mērķa cena. Iebūvētās `auto/*` kombinācijas
  izvēlas mērķi pieprasījuma izpildes laikā, tāpēc tām nav `pricing`.
- **Bezmaksas modeļiem** tiek rādīts `"0"` (un `0`), ja to cena ir nulle. Modelim, kuram nav cenu
  rindas, tiek rādīts arī `"0"`, ja katalogs to atzīmē kā bezmaksas (`free: true`) vai tas ir
  iekļauts iebūvētajā bezmaksas modeļu katalogā.
- **Nezināma cena:** ierakstam nav atslēgas `pricing`.
- **Pakalpojumu sniedzēji, kuru maksa tiek aprēķināta pēc kredītiem** (piemēram, Kiro), maksu
  aprēķina par pieprasījumu, nevis par tokenu. To ierakstos tiek saglabāti iepriekš lietotie
  skaitliskie lauki par 1M tokeniem, un tajos nav virkņu lauku par tokenu.
- **Varianti** (pamatojuma intensitātes identifikatori, aizstājvārdi bez domāšanas, atklāšanas un
  vārtejas spoguļi) pārkopē tā modeļa cenu, uz kuru tie maršrutē.
- Lauki satur tikai bāzes likmes. Ilga konteksta līmeņi (skaitliskais lauks `long_context`) un
  pakalpojumu līmeņu reizinātāji (piemēram, Codex fast vai flex) nemaina `prompt` vai
  `completion`.
- Objekts ir vienāds visiem autentifikācijas veidiem, tostarp Anthropic stila pieprasījumam ar
  `x-api-key` un `anthropic-version` (atbilde paliek `{ "object": "list",
"data": [...] }`). Implementācija: `src/app/api/v1/models/catalogPricing.ts`.

### Modeļa ID prefiksi (`?prefix=`)

Lielākā daļa modeļu tiek reklamēti ar **pakalpojumu sniedzēja prefiksu**. To, kādu prefiksu
saņemat, kontrolē funkcionalitātes karodziņš `MODELS_CATALOG_PREFIX_MODE`, un to var pārrakstīt
**katram pieprasījumam** ar vaicājuma parametru — tas ir noderīgi klientam, kas vēlas tīru
sarakstu, nemainot servera iestatījumu visiem pārējiem:

```bash
GET /v1/models?prefix=alias        # viens ID katram modelim — īsais aizstājvārda prefikss
GET /v1/models?prefix=dual         # abas formas (servera noklusējums)
GET /v1/models?prefix=canonical    # tikai pilnais pakalpojuma sniedzēja ID prefikss
```

| Režīms      | Izvada                                                   | Piezīmes                                                                                                                                                                                                                              |
| ----------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **un** `claude/claude-sonnet-4-6` | **Noklusējums.** Abi ID maršrutē uz vienu un to pašu modeli; saglabāti, lai klientu konfigurācijas, kurās cietkodēta kāda no formām, turpinātu darboties. Katalogs aptuveni dubultojas.                                               |
| `alias`     | `cc/claude-sonnet-4-6`                                   | Viens ieraksts katram modelim. Pakalpojumu sniedzēji, kuriem nav atsevišķa aizstājvārda, joprojām izvada savu ierakstu, tāpēc nekas netiek zaudēts.                                                                                   |
| `canonical` | `claude/claude-sonnet-4-6`                               | Viens ieraksts katram modelim ar pilno pakalpojuma sniedzēja ID prefiksu. Pakalpojumu sniedzēji, kuriem nav atsevišķa aizstājvārda (piemēram, `antigravity/…`, `agy/…`), arī šeit izvada savu vienīgo ID, tāpēc nekas netiek zaudēts. |

`dual` režīma spoguli var atpazīt arī bez vaicājuma parametra: tas satur lauku `parent`, kas
norāda uz primāro ID.

Klientiem, kas attēlo modeļu izvēlni, jāpieprasa `?prefix=alias` — tieši tā rīkojas
[OmniCopilot VS Code paplašinājums](../guides/VSCODE-COPILOT.md).

### Atklāšanas filtri (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` atbalsta izvēles atklāšanas filtrus. Ja neviens no tiem netiek izmantots,
atbilde nemainās. Tie sašaurina katalogu, ko izsaucējs jau redz (API atslēgas atļaujas tiek
piemērotas vispirms), un tiek izpildīti pirms OpenAI stila `limit` / `after` lappušu ielādes:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # katrai uzskaitītajai iespējai jābūt true
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # kataloga `type`; rindām bez tā tiek izmantots `chat`
GET /v1/models?q=sonnet&limit=10                           # reģistrjutīga atbilstība ID vai nosaukumā
```

| Param         | Values                                                                                              |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | nenegatīvs vesels skaitlis, salīdzināts ar `context_length`                                         |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 rakstzīmes                                                                                    |

Nezināma vērtība vai `min_context`, kas nav nenegatīvs vesels skaitlis (piemēram, `1.5`),
atgriež HTTP `400`, un ziņojumā tiek uzskaitītas derīgās vērtības. Implementācija:
`src/app/api/v1/models/catalogFilters.ts`.

### Modeļu izlase (`POST /v1/models/query`)

`POST /v1/models/query` atgriež īsu, deterministisku sarakstu no tā paša kataloga ar tādu pašu
autentifikāciju un katrai atslēgai piemērojamu redzamību kā `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Visi lauki nav obligāti. `capabilities` un `exclude` pieņem masīvu vai ar komatiem atdalītu virkni;
`max_output` tiek salīdzināts ar `max_output_tokens`. Rezultāti tiek kārtoti pēc `owned_by` un pēc tam
pēc `id`. `limit` noklusējuma vērtība ir `20`, bet vērtības virs `100` tiek ierobežotas līdz `100`. Nederīgs JSON,
nezināms lauks vai nederīga vērtība atgriež HTTP `400`.

### Atsevišķi paslēpti tērzēšanas modeļi

Modelis, kas tā nodrošinātāja lapā atzīmēts kā **Paslēpts**, tiek izslēgts no kataloga un, ja tas tiek
tieši pieprasīts, tiek noraidīts ar HTTP `404` / `model_not_found`. Pārbaudē tiek izmantots atrisinātais
nodrošinātājs un modelis, tostarp nodrošinātāju aizstājvārdi, ar saderīgo nodrošinātāju saistītie mezglu
prefiksi un savienojuma noklusējuma vērtības. Kombinētais modelis izlaiž paslēptos mērķus un var izmantot
redzamu ekvivalentu; ja izpildāmu mērķu vairs nav, tas atgriež to pašu kļūdas kodu. Paslēpšanas atcelšana
stājas spēkā nākamajā pieprasījumā. Attēliem paredzēti redzamības ignorējumi nepaslēpj tērzēšanas modeli
ar tādu pašu ID.

Šis atsevišķā modeļa iestatījums nav saistīts ar
[modeļu eksponēšanas atļaušanas/noraidīšanas sarakstiem](../routing/MODEL_EXPOSURE_LIST.md), kas filtrē kataloga
reklamēšanu un automātiskās maršrutēšanas kandidātus, vienlaikus saglabājot tiešu nosūtīšanu. API atslēgas
modeļu atļaujas joprojām tiek piemērotas neatkarīgi. Noklusējuma kataloga prefiksu režīms joprojām ir `dual`.

### Modeļu varianti bez domāšanas

Modeļiem Claude, kas atbalsta domāšanu, `/v1/models` reklamē arī **bez domāšanas** variantu, kura ID
ir ar prefiksu `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Izvēloties šo ID (piemēram, Claude Code konfigurācijā, kas vienmēr pievieno `thinking` bloku), tas tiek
atrisināts uz īsto `<provider>/<model>`, apspiežot spriešanu — `thinking:{type:"disabled"}` ceļā
`/v1/messages` vai arī atmetot laukus `reasoning`/`reasoning_effort` ceļā
`/v1/chat/completions`. Variants tiek uzskaitīts tikai Claude saimes modeļiem, kas atbalsta domāšanu
**un** ievēro `disabled` (tāpēc, piemēram, adaptīvie modeļi, kas noraida `disabled`, tiek izslēgti).
Operatori var katram modelim piespiedu kārtā ieslēgt vai izslēgt variantu, izmantojot
`ModelSpec.noThinkingAlias`.

## ElevenLabs audio ģenerēšana

Konfigurējiet `elevenlabs` nodrošinātāja savienojumu OmniRoute ar savu ElevenLabs API atslēgu.
Klienti autentificējas ar savu **OmniRoute** atslēgu (`Authorization: Bearer $OMNIROUTE_API_KEY`);
vārteja nodrošina saglabāto nodrošinātāja atslēgu kā `xi-api-key`. Nekad nesūtiet ElevenLabs atslēgu
kā vārtejas bearer pilnvaru.

| Metode | Ceļš                        | Atbilde                                         | API atslēgas galapunkta kategorija |
| ------ | --------------------------- | ----------------------------------------------- | ---------------------------------- |
| POST   | `/v1/sound-generation`      | Vietējie audio baiti                            | `elevenlabs`                       |
| POST   | `/v1/music`                 | Vietējie audio baiti                            | `music`                            |
| POST   | `/v1/music/stream`          | Straumēti audio baiti                           | `music`                            |
| POST   | `/v1/music/detailed`        | Vietējais multipart audio un kompozīcijas plāns | `music`                            |
| POST   | `/v1/music/detailed/stream` | Vietējie SSE metadati un audio fragmenti        | `music`                            |
| POST   | `/v1/music/plan`            | JSON kompozīcijas plāns                         | `music`                            |

Šie galapunkti papildina esošos `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` un `/v1/speech-to-text` maršrutus. Vietējie JSON lauki
un vaicājuma parametri, piemēram, `output_format` un `enable_logging`, tiek saglabāti.
`/v1/music/detailed` atbildes saglabā savas multipart robežvērtības; parsējiet tās kā multipart.
`/v1/music/detailed/stream` atgriež `text/event-stream` ar kompozīcijas metadatiem un
base64 audio fragmentiem SSE notikumos. Visi seši maršruti atbalsta CORS pirmsizsaukumu.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Īss skaņas efekts. Ilgums: no 0,5 līdz 30 sekundēm.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Mūzikas ilgums tiek izteikts milisekundēs: no 3000 līdz 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Izmantojiet `/v1/music/stream` ar to pašu JSON pamattekstu pakāpeniskai audio piegādei. Kompozīcija
pieņem tieši vienu no `prompt` vai `composition_plan`; `/v1/music/plan` pieprasa `prompt`
un pēc izvēles pieņem `source_composition_plan`. Vietējās shēmas saglabā papildu
nodrošinātāja laukus, lai kompozīcijas plāna versijas un precīzās pielāgošanas opcijas sasniegtu ElevenLabs.

Vienotais `/v1/music/generations` galapunkts pieņem arī
`elevenlabs/music_v1`, `elevenlabs/music_v2` un `elevenlabs/music_v2_5`. Ja ir aktīvs ElevenLabs savienojums,
šie modeļi tiek atklāti mūzikas katalogā. Šis galapunkts atgriež
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Tā `duration` lauks ir izteikts
sekundēs un tiek kartēts uz `music_length_ms`; skaidri norādītam `music_length_ms` ir prioritāte.
`instrumental` tiek kartēts uz `force_instrumental`, un vietējam laukam ir prioritāte.
Straumēšanai izmantojiet vietējos straumēšanas galapunktus, bet pieprasījumiem, kurus vada tikai
kompozīcijas plāns, izmantojiet vietējo kompozīcijas galapunktu.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Galapunkta, modeļa, budžeta un savienojuma ierobežojumi tiek piemēroti pirms augšupējā izsaukuma. Vietējie
maršruti atgriež augšupējā pakalpojuma statusa kodus un kļūdu pamattekstus bez izmaiņām, tostarp `402`
plāna ierobežojumam un `429` kvotas ierobežojumam. Galvenes `character-cost`, `song-id`, `request-id` un `retry-after`
tiek saglabātas, ja tās ir pieejamas. Bezmaksas kredīta atlikums negarantē piekļuvi katram
mūzikas modelim, izvades formātam vai API funkcijai: ElevenLabs nosaka tiesības katram pieprasījumam.
Vienotais galapunkts saglabā kļūdu statusa kodus OmniRoute normalizētajā kļūdu aploksnē.

Augšupējā pakalpojuma līgumi: [skaņas efekti](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[mūzikas kompozīcija](https://elevenlabs.io/docs/api-reference/music/compose) un
[mūzikas straumēšanas informācija](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> **Pārkārtošanas nodrošinātāja mezgli:** `POST /v1/rerank` arī maršrutē pie OpenAI saderīgu nodrošinātāju mezgliem
> (oMLX, vLLM, Infinity, TEI aiz vārtejas, …), kas adresēti kā `<node-prefix>/<model>`. Atgriezeniskās cilpas
> mezgli (`localhost`, `127.0.0.1`, `172.16.0.0/12`) vienmēr ir izmantojami, tāpat arī resursdatoru nosaukumi, ko
> operators norāda `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (piemēram, Docker/Compose pakalpojuma nosaukums, piemēram,
> `http://reranker:8080/v1`; šie mezgli tiek izsaukti tieši, nekad neizmantojot `HTTP(S)_PROXY` vai
> savienojumam piesaistīto starpniekserveri). Mezglus jebkurā citā
> resursdatorā — LAN datorā vai Tailscale partnerī — var izmantot tikai tad, ja operators iespējo
> `RERANK_REMOTE_PROVIDER_NODES` funkcionalitātes karodziņu **un** mezgla pamata URL atbilst nodrošinātāja
> izejošo URL politikas prasībām (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Atmiņas programma pārkārtošanas darbību izsauc caur atgriezenisko cilpu, tāpēc tas pats noteikums attiecas uz
> `rerankProviderModel` Atmiņas iestatījumos.
>
> **Lokālā servera formas:** mezgls tiek izsaukts vietnē `<base>/v1/rerank` un pēc 404 kļūdas vietnē `<base>/rerank`
> (Infinity, TEI). Augšupvērstā pieprasījuma pamattekstā ir gan Cohere/OpenAI rakstība (`documents`,
> `return_documents`), gan TEI rakstība (`texts`, `return_text`), un augšupvērstā atbilde tiek
> normalizēta uz Cohere aploksni: TEI neietvertie dati `[{index, score, text}]`, `{results: [{index, score}]}`
> no vienkāršām vārtejām un Voyage stila `{data: [...]}` klientam tiek atgriezti kā
> `{results: [{index, relevance_score, document?}]}`, sakārtoti pēc rezultāta un ierobežoti līdz `top_n`.

> **Nodrošinātāja mezglu atklāšana:** modeļi OpenAI saderīgā nodrošinātāja mezglā tiek parādīti `GET /v1/models`
> sadaļā ar mezgla prefiksu. Ieraksti, kuriem nav galapunkta metadatu (raksturīgi lokāliem `/v1/models` sarakstiem),
> manto mezgla `apiType`, tāpēc `embeddings` mezgla modeļiem ir `type: "embedding"` un
> `rerank` mezgla modeļiem ir `type: "rerank"`, nevis noklusējuma tērzēšanas tips; skaidri norādīts
> `supportedEndpoints` sinhronizētā vai manuāli pievienotā ierakstā joprojām ir prioritārs.

### Īpašie nodrošinātāju maršruti

```bash
POST /v1/providers/{provider}/chat/completions
POST /v1/providers/{provider}/embeddings
POST /v1/providers/{provider}/images/generations
```

Nodrošinātāja prefikss tiek automātiski pievienots, ja tā trūkst. Neatbilstoši modeļi atgriež `400`.

## Meklēt API

Web/search sniedzēja abstrakcija (Tavily, Brave, Exa, Serper utt.).

| Metode | Ceļš                   | Apraksts                                                                                              |
| ------ | ---------------------- | ----------------------------------------------------------------------------------------------------- |
| GET    | `/v1/search`           | Uzskaitiet konfigurēto meklēšanas pakalpojumu sniedzēju + iespējas                                    |
| POST   | `/v1/search`           | Palaidiet meklēšanas vaicājumu — body, ko apstiprinājis `v1SearchSchema`, atbalsta caching/coalescing |
| GET    | `/v1/search/analytics` | hit/latency/cache statistika katram pakalpojumu sniedzējam                                            |

**Auth:** Nesēja API atslēga (`extractApiKey` + `isValidApiKey`). Meklēšanas politika tiek īstenota, izmantojot `enforceApiKeyPolicy`.

**Automātiskā atlase:** bez `provider` lētākais pakalpojumu sniedzējs ar konfigurētu savienojumu darbojas pirmais, un nākamais lētākais ir kļūmjpārlēce. Bezmaksas pēdējās iespējas nodrošinātāji (`duckduckgo-free`) tiek izmantoti tikai tad, ja nekas cits nav konfigurēts. Pašmitinātais SearXNG tiek uzskatīts par konfigurētu, tiklīdz tā savienojumā tiek saglabāts īsts `baseUrl` (nevis kataloga noklusējuma `http://localhost:8888/search`): pēc tam tas tiek ierindots kā 0 dolāru nodrošinātājs, apsteidzot atslēgas nodrošinātājus, bet lētākais nodrošinātājs ar atslēgām ir kļūmjpārlēce, tostarp gadījumos, `baseUrl` SearXNG atbild uz 400, 401, 403 vai 404. Tas nav derīgs `http(s)` vai 404 punktos URL mākoņa metadatu adrese netiek skaitīta. SearXNG savienojums, kurā tiek glabāts marķieris, šādā veidā tiek ierindots tikai `https://` vai loopback `http://` vietā. Izmantojot attālo vienkāršu `http://` tas nekad nav kļūmjpārlēce un ir pēdējais līdzeklis, ko izmanto tikai tad, ja nav konfigurēts neviens cits pakalpojumu sniedzējs vai kad tas tiek pieprasīts pēc nosaukuma, tāpēc šajos divos gadījumos tas nosūta pilnvaru skaidrā tekstā.

### Exa un Tavily `provider_options`

Exa un Tavily nolasa pakalpojumu sniedzējam raksturīgus laukus no nosaukumiem sadalīta maisa: `provider_options.exa` (vai `provider_options["exa-search"]`) un `provider_options.tavily` (vai `provider_options["tavily-search"]`). Tiek pārsūtītas tikai tālāk norādītās atslēgas. Katrs no tiem tiek pārbaudīts, salīdzinot ar savu Zod shēmu `open-sse/handlers/search/providerOptionsPassthrough.ts`, un tiek atmesta atslēga ar nepareizu veidu. Jebkura cita atslēga tiek ignorēta, tostarp auth, base URL, `stream` un `outputSchema`. Plakanie taustiņi, ko izmanto citi pakalpojumu sniedzēji (`cx`, `depth`, ...) darbojas tāpat kā iepriekš.

| Pakalpojumu sniedzējs | Augstākā līmeņa lauki                                                                                                                                                                                                                                                                                                                                                     | Ligzdotas                                                                                                                                    |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Piem                  | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (plakanie primitīvie), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                          | `contents.{text, highlights, summary, extras, livecrawlTimeout, maxAgeHours}` ir apvienots ar noklusējuma `{ text: true, highlights: true }` |
| Tavilijs              | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                            |

Vienmēr uzvar vispārīgie lauki: `query`, `max_results`, `filters` (domēni), `country` un tēma, kas iegūta no `search_type`. Uz Exa `search_type: "news"` saglabā `category: "news"`. Tavilijs pieņem arī `search_type: "finance"` (`topic: "finance"`).

Firecrawl meklēšanas izmaksas tiek reģistrētas par katru sākto 10 atgriezto rezultātu bloku — 0,002 ASV dolāri (2 kredīti) par bloku un vismaz viens bloks par zvanu ( [Firecrawl norēķini](https://docs.firecrawl.dev/billing) ): 11 rezultāti maksā 0,004 ASV dolārus.

Vispārējais `time_range` tagad sasniedz abus pakalpojumu sniedzējus: Exa iegūst `startPublishedDate` (ISO laikspiedolu), bet Tavily iegūst `start_date` (`YYYY-MM-DD`). Precīzs datums `provider_options` ignorē kartēto datumu.

Exa rezultāti saglabā `id`, `highlights` (katrs izcēlums, ne tikai pirmais, kas izmantots kā `snippet`), `highlight_scores`, `summary`, `subpages`, `entities` un `extras` `provider_raw`. Tavily rezultāti saglabā `images` un `favicon`.

Saites meklēšanas izmaksas tiek reģistrētas USD 0,005 par `depth` `fast` un `standard` un USD 0,05 par `deep` ( [Saistīšanas cenas](https://docs.linkup.so/pages/documentation/development/pricing) ) neatkarīgi no tā, vai `depth` nāk no `provider_options` vai savienojuma iestatījumiem.

Exa `type: "lite"` (Exa 3.0) pieņem mazāku lauku kopu un noraida visu pieprasījumu, ja ir iestatīts kāds cits lauks. Lite versijai `additionalQueries`, `systemPrompt` un visi `contents` taustiņi, izņemot `text` un `highlights` tiek atmesti pirms izsaukuma. Novecojušie `subpages`, `subpageTarget`, `highlights.numSentences` un `highlights.highlightsPerUrl` vairs netiek pārsūtīti.

Izmaksu uzskaite ir vienotais reģistrs `costPerQuery`, izņemot Exa, kas atbilst Exa pašas cenām: USD 0,007 par zvanu `auto` (un mantotajam `fast`) vai USD 0,004 par `lite` (un mantoto `instant`), aptverot 10 rezultātus; 0,001 USD par katru nākamo rezultātu; un USD 0,001 par katru atgriezto rezultātu, ja ir iestatīts `contents.summary`. Tavily ir reģistrēts ar 1 kredītu ($ 0,008) par `search_depth` `basic`, `fast` un `ultra-fast` un par 2 kredītiem ($ 0,016) par `advanced` ( [Tavily API credits](https://docs.tavily.com/documentation/api-credits) ). Zvans ar `auto_parameters: true`, ko Tavily jaunina uz uzlaboto, joprojām tiek ierakstīts 1 kredīta apmērā.

## Web Fetch API

Izgūt saturu no URL, izmantojot konfigurētu tīmekļa izgūšanas nodrošinātāju (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, tā pati API atslēga kā Parallel Search) atgriež tikai Markdown
— jebkura cita `format` vērtība izraisa `400`, un satura ierobežojums ir 100 000 rakstzīmes. Ja
pašu mērķa lapu nevar izgūt, augšupstraume par to ziņo HTTP 200 atbildē;
OmniRoute to parāda kā `422` ar fiksētu ziņojumu.

| Method | Path            | Description                                               |
| ------ | --------------- | --------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Izgūt/nokasīt URL — pamattekstu validē `v1WebFetchSchema` |

**Autentifikācija:** Bearer API atslēga (`extractApiKey` + `isValidApiKey`). Politika tiek
piemērota, izmantojot `enforceApiKeyPolicy`.

**Kvotas apzinoša atkāpšanās (#8297):** ja nav norādīts `provider`, kopa
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) tiek
izstaigāta fiksētā
prioritātes secībā (vispirms aizpildot) — konfigurēts, bet ātruma ierobežojumu sasniedzis nodrošinātājs
tiek izlaists, nevis pieprasījums tiek pārtraukts, un atkārtojama/kvotas augšupstraumes kļūme
(HTTP 429 vienmēr; 402/403 Firecrawl/Tavily/TinyFish kvotas tipa bezmaksas līmeņiem —
nevis Jina Reader un nekad vienkāršam 400 nederīgam pieprasījumam) pieprasījuma izpildes laikā
tiek nodota nākamajam neizmēģinātajam nodrošinātājam ar akreditācijas datiem. Ja visi kopas
nodrošinātāji ir izsmelti, galapunkts iepriekšējā vispārīgā `400` vietā atgriež vienu
`429` (ar `Retry-After`
galveni). Ja tiek pieprasīts konkrēts `provider`, **klusā atkāpšanās nenotiek** — ātruma ierobežojumu
sasniegušais vai kļūmains norādītais nodrošinātājs parāda savu kļūdu (`429`, ja sasniegts ātruma
ierobežojums, citādi augšupstraumes statusu).

## WebSocket straumēšana

```bash
GET /v1/ws?handshake=1
```

Validē WebSocket jaunināšanas rokasspiedienu un atgriež vadu protokola piemēra ziņojumus (`request`, `cancel`). Faktiskos WS kadrus apstrādā komplektācijā iekļautais WS serveris ārpus Next.js maršrutu tabulas.

**Autentifikācija:** Bearer API atslēga rokasspiediena laikā.

### Responses API, izmantojot WebSocket (tikai codex)

```bash
# Tas pats resursdators:ports, kas HTTP API (noklusējums 20128); jaunināt savienojumu:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (vai: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Pirmajam kadram OBLIGĀTI JĀBŪT response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Responses-API, izmantojot WebSocket, starpniekserveris ir piesaistīts **tikai `codex`** (ChatGPT
aizmugursistēmai). Tas klausās tajā pašā portā, kur API informācijas panelis, šādos ceļos:
`/v1/responses`, `/responses` un `/api/v1/responses`. Saņemot pirmo `response.create` kadru, tas
autentificē un sagatavo savienojumu, izmantojot iekšējo `codex-responses-ws` tiltu, atlasa codex
OAuth savienojumu un, izmantojot `wreq-js` transportu, tunelē savienojumu uz
`wss://chatgpt.com/backend-api/codex/responses`. **Modeļi, kas nav codex, tiek noraidīti**
(`codex_ws_provider_required`). Kvotas koplietošanas maršrutēšanai izmantojiet
`model: "qtSd/<group>/codex/<model>"`. Ieviests failos
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Autentifikācija:** Bearer API atslēga rokasspiediena laikā. Komplektācijā iekļautajam HTTP serverim (`server-ws.mjs`)
jābūt aktīvajam ieejas punktam (pēc noklusējuma tas tā ir, ja pastāv `app/server-ws.mjs`).

#### Modeļa ID: izmantojiet neizvērsto ChatGPT ID (bez `codex/` prefiksa)

OpenAI **Codex CLI** klienta pusē validē modeļa nosaukumu, kad
`supports_websockets = true`, un noraida ar nodrošinātāju prefiksētus ID, piemēram,
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Nosūtiet **neizvērsto** ID (piemēram, `gpt-5.5`). OmniRoute tilts darbojas
tikai ar codex, tāpēc pirms tunelēšanas augšupstraumē tas atkārtoti atrisina neizvērstu ID kā codex
modeli (`resolveCodexWsModelInfo`) — lai gan neizvērsts `gpt-5.5` citādi, izmantojot HTTP, tiktu
maršrutēts pie cita nodrošinātāja.

#### OpenAI Codex CLI konfigurēšana

Norādiet Codex CLI uz OmniRoute, pievienojot pielāgotu nodrošinātāju ar WebSocket atbalstu failā
`~/.codex/config.toml` (izmantojiet atsevišķu `CODEX_HOME`, lai nepārveidotu esošu konfigurāciju):

```toml
model = "gpt-5.5"                 # neizvērsts ID — NEVIS "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # bez beigu slīpsvītras; WS URL tiek atvasināts (produkcijā izmantojiet https/wss)
wire_api = "responses"                    # vienīgā atbalstītā vērtība kopš 2026. gada februāra
supports_websockets = true                # iespējo Responses, izmantojot WS, transportu
env_key = "OMNIROUTE_API_KEY"             # satur OmniRoute API atslēgu (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # OmniRoute API atslēga (jebkura atslēga, ja REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI pārveido `base_url + /responses` par WebSocket savienojumu, un OmniRoute to tunelē uz
atlasīto codex OAuth savienojumu. Darbība pārbaudīta no sākuma līdz beigām pret lokālo serveri:
ChatGPT atgriež `codex.rate_limits` + `response.created` un straumē pabeigto atbildi.

### Kvotas sesijas atkopšana (pēc izvēles)

terminālu kvotas kļūdu (`402`/`429`/`503`), kuras pamatteksts norāda, ka kvota vai kredīti ir izsmelti,

| Galvene                      | Vērtība                                                    |
| ---------------------------- | ---------------------------------------------------------- |
| `x-omniroute-quota-recovery` | `auto`                                                     |
| `x-omniroute-session`        | sesijas ID, `[A-Za-z0-9._:-]{1,128}`                       |

kā arī bez `x-omniroute-connection` piesaistes, un ir jābūt iestatītam `STORAGE_ENCRYPTION_KEY`
(pieprasījums tiek glabāts šifrētā veidā līdz 24 stundām). Pēc tam atbilde ir `202` ar
`recovery.poll`; veiciet aptauju, izmantojot `GET /v1/quota-recoveries/{id}` (`202`, kamēr gaida,
`200` ar atkoptu pamattekstu pēc pabeigšanas), vai atceliet, izmantojot `DELETE`. Biļetes ir redzamas tikai
API atslēgai, kas tās izveidoja. Ja atkārtojuma iznākums ir neskaidrs, tas beidzas stāvoklī
`needs_confirmation`, nevis tiek nosūtīts divreiz. Avots: `src/lib/quota/quotaSessionRecovery.ts`.

## Pašapkalpošanās lietojums (`/api/usage/om-usage`)

Jebkura API atslēga var nolasīt **savu** lietojumu un kvotas — pārvaldības autentifikācija nav nepieciešama.
Šo galapunktu klients (CLI, OmniCopilot panelis) izmanto, lai atslēgas turētājam parādītu viņa izdevumus.

```bash
# Teksta forma (vēsturiskais līgums — vienkāršs teksts terminālim)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Strukturēta forma — to patērē lietotāja saskarne
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Atslēgai jābūt iespējotai **`allowUsageCommand`** (pēc noklusējuma atspējots — informācijas paneļa
API atslēgu pārvaldnieks to pārslēdz katrai atslēgai). Ja tas nav iespējots, galapunkts atbild ar `403`.

`?format=json` atgriež diferencētu struktūru, lai izsaucējam nekad nebūtu jālasa datu lauks no atteikuma.
Veiksmīga rezultāta gadījumā:

```jsonc
{
  "allowed": true,
  // pieejams tikai tad, ja atslēga ir izvēlējusies katras atslēgas lietojuma ierobežojumus (dienas/nedēļas USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // atlasītā nodrošinātāja kvotas momentuzņēmums vai null, ja nekas vēl nav saglabāts kešatmiņā:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // katra savienojuma momentuzņēmums, lai lietotāja saskarne varētu attēlot vairākus nodrošinātājus līdzās:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Atteikuma gadījumā (`401` nederīga atslēga / `403` nav atļauts) tas pats maršruts atgriež
`{ "allowed": false, "error": { "message": "…" } }` — esošs, bet tukšs `personal`/`provider`
(atslēga ir atļauta, taču vēl nekas nav noskaidrots) ir atšķirīgs stāvoklis no atteikuma, un tikai JSON forma
tos nošķir.

**Autentifikācija:** izsaucēja paša Bearer API atslēga, kas tiek validēta ar `isValidApiKey` — tas _nav_
pārvaldības interfeiss (`/api/keys/…`), kas joprojām ir aiz `requireManagementAuth`.

### Neapstrādāti un sliekšņa koriģēti kvotu procenti

Izmantojot `/api/usage/om-usage`, izsaucējiem jāņem vērā atšķirība starp procentiem, kas parādīti
**vienkāršā teksta izvadē**, un strukturētajā **JSON izvadē**:

| Aspekts                  | Vienkāršā teksta formāts (`/api/usage/om-usage` / `@@om-usage`)                                            | JSON formāts (`?format=json`)                                                                |
| :----------------------- | :--------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------- |
| **Izvades lauks**        | `NN% left` (piem., `20% left`)                                                                             | `provider.quotas` / `providers[].quotas`                                                     |
| **Mērījums**             | **Sliekšņa koriģēta izmantojamā kvota**: atlikusī ietilpība virs sliekšņa                                  | **Neapstrādāta augšupējā kvota**: nekoriģēts nodrošinātāja mērījums                          |
| **Sliekšņa mērogošana**  | Mērogota, izmantojot `effectiveRemainingPercent()`, tādējādi aizsargātā rezerve tiek attēlota kā `0% left` | Nav (neapstrādātas momentuzņēmuma vērtības, ko ziņojis nodrošinātājs)                        |
| **Sliekšņa dati**        | Iekļauti parādītajā procentuālajā vērtībā                                                                  | Saglabāti `quotaWindowThresholds` katram savienojumam (vai servera noklusējuma iestatījumos) |
| **Galvenais patērētājs** | Interaktīvi CLI, termināļa uzvednes, cilvēki-operatori                                                     | Programmatiska integrācija, informācijas paneļi, analītika, norēķinu uzskaite                |

#### Sliekšņa korekcijas formula

OmniRoute atbalsta proaktīvus kvotu sliekšņus, lai novērstu augšupējās sistēmas izsmelšanu (konfigurē, izmantojot savienojuma
`quotaWindowThresholds`, nodrošinātāja noklusējuma iestatījumus vai globālos noturības iestatījumus). Ja kvotas logam
ir aktīvs sliekšņa iestatījums (piem., `cutoff = 25%`), teksta renderētājs aprēķina atlikušo kvotu šādi:

- Ja `remaining <= cutoff`: atgriež `0%`.
- Ja `remaining > cutoff`: atgriež `((remaining - cutoff) / (100 - cutoff)) * 100`.

Formatētā teksta izvade to noapaļo līdz tuvākajam veselajam skaitlim (`Math.round(...)`).

#### Ilustratīvs piemērs

Apsveriet pakalpojumu sniedzēja logu ar **60% neapstrādātu izlietojumu** (tādējādi **40% neapstrādātas atlikušās kvotas**) un konfigurētu
**25% atlikušās kvotas** sliekšņa vērtību:

| Atveidojums                            | Aprēķins                                           | Atlikums |            Netieši izmantots            |
| :------------------------------------- | :------------------------------------------------- | :------: | :-------------------------------------: |
| **Neapstrādāts JSON (`?format=json`)** | Augšupējais momentuzņēmums (`quotas[window]`)      | **40%**  |                 **60%**                 |
| **Teksta formāts (`NN% left`)**        | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%**  | **80%** (ja aprēķina `100 - remaining`) |

- **Kāpēc tekstā tiek rādīti 20% atlikuma:** No kontā fiziski atlikušās 40% kvotas 25% ir rezervēti
  nogriešanas politikai. Izsaucējam pirms maršrutētājs pārtrauc maršrutēt pieprasījumus uz šo savienojumu, ir
  pieejami tikai 15% no 75% izmantojamās rezerves. Mērogošana nodrošina, ka savienojums signalizē par izsmelšanu (`0% left`) tieši tad, kad maršrutēšana tiks pārtraukta.
- **Kāpēc JSON saglabā neapstrādātās vērtības:** JSON lietderīgā slodze atgriež precīzu pakalpojumu sniedzēja momentuzņēmumu (`UsageSnapshot`),
  tādējādi ārējiem rīkiem nodrošinot piekļuvi faktiskajai augšupējai izmantošanai un savienojuma līmeņa
  `quotaWindowThresholds` bez servera puses informācijas zudumiem mērogošanas dēļ.

#### Norādījumi patērētāju migrācijai

Ja ārēja integrācija (piemēram, redaktora spraudnis vai aģenta paplašinājums) iepriekš nolasīja teksta
galapunktu (`NN% left`) un aprēķināja izmantoto procentuālo daļu kā `100 - NN`, pāreja uz `?format=json` nozīmē:

- Nolasot neapstrādātās JSON vērtības, tiks atspoguļots **faktiskais augšupējais patēriņš** (iepriekš minētajā piemērā izmantoti 60%).
- Ja integrācija vēlas saglabāt teksta galapunkta izmantojamās atļautās daļas semantiku, tā var
  klienta pusē aprēķināt efektīvo atlikušo vērtību, izmantojot `quotaWindowThresholds` savienojuma līmeņa pārrakstīšanai.

### Latences ietekme

Semantiskās kešatmiņas HIT atgriež atbildi no kešatmiņas **bez augšupējošā
izsaukuma**, tāpēc norādītā `X-OmniRoute-Response-Latency` vērtība ir gandrīz nulle
(neatkarīgi no sākotnējās augšupējās latences). Klientiem, kuriem svarīga latence
(etalona testēšanai, p50/p99 uzraudzībai), jāpārbauda atbildes galvene
`X-OmniRoute-Cache-Latency`:

| Value       | Meaning                                                                       |
| ----------- | ----------------------------------------------------------------------------- |
| `synthetic` | Atbilde tiek nodrošināta no kešatmiņas; latence nav reālais augšupējais laiks |
| _(absent)_  | Atbilde no reāla augšupējā izsaukuma                                          |

### Kešatmiņas apiešana katrai atslēgai

API atslēgas var atteikties no semantiskās kešatmiņas nolasīšanas, izmantojot `cacheDefaultMode`:

| Value    | Behavior                                                                    |
| -------- | --------------------------------------------------------------------------- |
| `legacy` | Parasta kešatmiņas darbība (noklusējums)                                    |
| `bypass` | Izlaist kešatmiņas meklēšanu pilnībā; vienmēr izsaukt augšupējo pakalpojumu |

```json
{ "cacheDefaultMode": "bypass" }
```

### Kešatmiņas apiešana katram pieprasījumam

Jebkurš pieprasījums var apiet kešatmiņu neatkarīgi no atslēgas iestatījumiem:

```
X-OmniRoute-No-Cache: true
```

## CLIProxyAPI pārvaldības saderība

OmniRoute atbild uz trim [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)
pārvaldības galapunktiem, kurus lieto izmantošanas informācijas paneļi, lai nolasītu Claude un Codex abonementu limitus
(piemēram, T3 Code `cliproxy` izmantošanas limita avots). Norādiet klienta pamata URL
uz OmniRoute un izmantojiet API atslēgu ar `manage` tvērumu kā tās pārvaldības atslēgu. Maršruti tiek
apkalpoti vietnē `/v0/management/*` un `/api/v0/management/*`.

| Method | Path                         | Description                                                                                                                                    |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/v0/management/auth-files`  | Claude un Codex OAuth savienojumi kā `{ files: [{ id, auth_index, provider, email, disabled, id_token }] }`. Nav marķieru                      |
| POST   | `/v0/management/api-call`    | Ķermenis `{ auth_index, method, url, header?, data? }`. Nosūta vienu atļauto pieprasījumu ar konta marķieri un atgriež `{ status_code, body }` |
| POST   | `/v0/management/reset-quota` | Ķermenis `{ auth_index }`. Notīra viena konta savienojuma gaidīšanas periodu, modeļu bloķējumus un Codex tvēruma gaidīšanas periodus           |

- `auth_index` ir OmniRoute savienojuma ID. `provider` ir `claude` vai `codex` (tikai OAuth
  savienojumiem; `anthropic` API atslēgas nodrošinātājs netiek uzrādīts). Codex gadījumā
  `id_token.chatgpt_account_id` ir saglabātais darbvietas ID, bet `plan_type` — saglabātais plāns.
- `api-call` nav vispārīgs starpniekserveris. Tas pieņem tikai Claude `GET
https://api.anthropic.com/api/oauth/usage` un Codex `GET https://chatgpt.com/backend-api/wham/usage`, `GET .../wham/rate-limit-reset-credits` un
  `POST .../wham/rate-limit-reset-credits/consume`, katru tikai atbilstošā
  nodrošinātāja kontam. Jebkurš cits pieprasījums atgriež `403`, nesazinoties ar augšupējo pakalpojumu. Izsaucēja
  `Authorization` galvene (tostarp `$TOKEN$` vietturis) tiek ignorēta: OmniRoute ievieto
  savienojuma piekļuves marķieri, vispirms to atsvaidzinot, ja tas ir tuvu derīguma beigām, un pārsūta tikai
  atļautās galvenes (`anthropic-beta`; `OpenAI-Beta`, `Originator`, `Chatgpt-Account-Id`;
  `Accept`, `Content-Type`). Ja `Chatgpt-Account-Id` nav norādīts, pēc noklusējuma tiek izmantots saglabātais darbvietas ID.
  Pieprasījumiem iestājas noildze pēc 15 sekundēm, un tie izmanto savienojuma starpniekserveri.
- `reset-quota` nemaina gala stāvokļus (`banned`, `expired`, `credits_exhausted`). Nezināms
  `auth_index` atgriež `404`.

**Autentifikācija:** informācijas paneļa sesija vai API atslēga ar `manage` tvērumu — nepieciešama pat tad, ja pieteikšanās ir atspējota
(šie ceļi atrodas `ALWAYS_PROTECTED_API_PATHS`). Atslēgas, kas paredzētas tikai secināšanai, saņem `403`. Avots:
`src/lib/cliproxyCompat/managementApi.ts`.

synced/imported modeļiem `PUT /api/provider-models` pieņem `provider`, `modelId` un `maxOutputTokenOverride`: pozitīvs vesels skaitlis iestata manuālo izvades marķiera vāciņu, un `null` to notīra, lai atjaunotu noklusējuma vērtību. `GET /api/provider-models?provider=<provider>` atgriež šīs vērtības `modelOutputOverrides`, ieskaitot modeļus bez pielāgota modeļa rindas. Ignorēšana izmanto izpildlaika `max_output_tokens` iespēju un izdzīvo modeļa atkārtotu sinhronizāciju. Ar OpenAI saderīgā nodrošinātāja lapa piedāvā tās pašas edit/clear vadīklas un atzīmē modeļus ar skaidru redzes atbalstu.

Saderīgā nodrošinātāja mezglā rakstīšanas ceļi (`POST`, `PUT`, `PATCH`, `DELETE` un `/api/provider-models/validate-and-add`) saglabā modeļa ID kā tukšu augšupvērsto ID: ID, kas ielīmēts no prefiksa saraksta, ir sakļauta jebkura mezgla prefiksa galvenā kaudzīte, un atbildes atbalso saglabāto ID. Kanonisko pakalpojumu sniedzēju samazinātie ID (piemēram, `nvidia/nemotron-…`) tiek saglabāti burtiski. `/v1/models` nekad neizstaro stacked `<prefix>/<prefix>/<model>` id.

Pielāgotas tērzēšanas pabeigšanas mezgli pielāgo precīzas argumentācijas atteikšanos augšupējai aizmugursistēmai. Veiksmīga savienojuma pārbaude automātiski atlasa tērzēšanas veidnes vadīklas katram precīzam modelim ID kura `/models` ieraksts pierāda atpazītu `owned_by` vērtību: `vllm`, `sglang` vai `llamacpp`. Caurspīdīgi ar OpenAI saderīgi iesaiņojumi var saglabāt oriģinālo modeļa ierakstu ligzdotā `openai` objektā; noteikšana seko līdz trim šādām aploksnēm. Modeļi ar trūkstošām, nezināmām vai konfliktējošām īpašumtiesībām saglabā parasto OpenAI darbību. Atklāšana atkārtoti izmanto esošo kataloga pieprasījumu, neģenerē pabeigšanas pilnvaras un tiek anulēta, mainoties savienojuma galapunktam.

Lai piespraustu aizmugursistēmas darbību, kas neatklāj šos metadatus, izmantojiet esošo daļējo nodrošinātāja atjauninājumu API:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Nosūtiet to ķermeni ar `PUT /api/providers/<connection-id>`. Šajā savienojumā `none` precīzs argumentācijas mēģinājums tiek nosūtīts kā `chat_template_kwargs.thinking=false` un `chat_template_kwargs.enable_thinking=false`. Skaidras vietējās veidnes vērtības paliek autoritatīvas, ja vien servera puses argumentācijas kārtula nepiespiež pūles. Iestatījums ir spēkā tikai tad, ja pielāgots ar OpenAI saderīgs savienojums nosūta tērzēšanas pabeigšanas pamattekstu; Atbilžu pieprasījumi un parastie pakalpojumu sniedzēji saglabā savu sākotnējo pieprasījumu formu. Iestatiet `reasoningControl` uz `openai`, lai piespiestu parasto OpenAI `reasoning_effort` caurlaidi, vai izlaidiet it/set to uz `null` lai izmantotu automātisko noteikšanu.

Claude koda automātiskā režīma klasifikators pieprasa noklusējuma sākotnējo domāšanu atspējot, ja tajās nav skaidru argumentācijas vadīklu. Atklāšana izmanto klasifikatora sistēmas marķieri Kloda formāta pieprasījumos, nevis modeļu nosaukumus vai pabeigšanas ierobežojumus. Skaidras ķermeņa vadīklas, atbalstītās effort/thinking galvenes, maršrutēšanas kārtulas un atrisinātais modeļa darbs saglabā savu esošo prioritāti. Abi klasifikatora posmi saglabā uzvednes, pabeigšanas ierobežojumus, apturēšanas secības un reālus augšpuses atļauju spriedumus; otrais posms joprojām var radīt prasīto redzamo pamatojumu kā parastu tekstu.

### API atslēgas atļaujas

`PATCH /api/keys/{id}` atjaunina esošās atslēgas atļaujas. Tāpat kā katram `/api/keys*` maršrutam, tam ir nepieciešama pārvaldības atļauja (skatiet [Pārvaldības autentifikācija](../guides/MANAGEMENT-AUTH.md) ), nevis secinājuma atslēga. ### Video kadra urbšana

`GET /api/v1/video-bridge/drilldown` nolasa nomnieka necaurredzamu rokturi, kas tika atgriezts `x-omniroute-video-drilldown` pēc nepārprotamas piekrišanas Video Bridge pieprasījuma. Gan lasīšanai, gan `DELETE` vienmēr ir nepieciešama derīga API atslēga un operatora neatkarīga `modalityBridgeVideoDrilldownRemoteEnabled` atļauja. Ražošanas saglabāšanai papildus ir nepieciešams `modalityBridgeVideoDrilldownEnabled` un stingrs katrai daļai `drilldown: true`. Ja atslēgai ir tukšs beigu punktu atļaušanas saraksts, tajā ir jāietver `video` gan GET, gan DELETE neatkarīgi no tā, vai zvanītājs izmanto `/v1` vai `/api/v1`.

GET vaicājums: nepieciešams `handle`; neobligāts `variant` (`preview`, `standard`, `detail`), `limit` (1–8; mantotais `frames` ir pieņemts, taču to nevar apvienot ar `limit`), nulles `page` un `start`/`end` sekundes. Ja tiek nodrošinātas abas fokusa robežas, `end` ir jābūt lielākam par `start`. Duplicate/unknown vaicājuma atslēgas tiek noraidītas. Veiksmīgās atbildes satur `derivation`, `durationSeconds`, `frames`, `hasMore`, `page`, `variant` un izvēles `focusWindow`; JSON bez veikala ir 32 MiB, ieskaitot Base64. Negabarīta produkcija atgriež 413; pieprasīt mazāk kadru.

`DELETE /api/v1/video-bridge/drilldown?handle=...` atgriež `{ "removed": 0|1 }`. Nezināmas, beidzies derīguma termiņš un krusteniskās atslēgas GETs ir neatšķiramas 404 atbildes; krusteniskā atslēga DELETE nevar noņemt īpašnieka ierakstu. Atspējota piekļuve atgriež 403, missing/invalid autentifikāciju 401, nederīgus vaicājumus 400, atcelšanu 499 un pagaidu kļūdas 503. Rokturi ir procesa lokāli, to derīguma termiņš beidzas pēc desmit minūtēm, un tie neiztur restartēšanu. Jaunajos rokturos tiek izmantots `v1.` plus 32 baitu izlases Base64URL marķieris; tiek saglabātas tikai marķieru jaucējzīmes. Mantotie 64 heksu marķieri joprojām ir sintaktiski lasāmi saderības nodrošināšanai. Skatiet [Video Bridge aizsargmargas,](../security/GUARDRAILS.md#video-bridge-videobridgets-videobridgepipelinets) lai iegūtu informāciju par piekrišanu, kvotām un variantu atvasināšanu.

### Versija un izlaišanas kanāls

```bash
GET /api/system/version
```

Tikai cilpas pārvaldības maršruts (admin auth). Atgriež darbojošos versiju, jaunāko publicēto versiju un automātiskās atjaunināšanas statusu. `releaseChannel` un `channels` ir aditīvi lauki (sliede 3.8.54); `channel` saglabā savu nozīmi — izvietošanas režīms, ko izmanto informācijas paneļa atjauninātājs (`npm`, `source` vai `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — npm kanāls darbinātajai versijai: `nightly` `-nightly.*` versijām, `next` citām pirmsizlaidumiem (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` vecākas galvenās versijas stabilai versijai nekā `channels.latest`, pretējā gadījumā `latest`. Tie paši noteikumi kā `scripts/release/dist-tag.mjs`, kas publicēšanas laikā izvēlas npm dist-tagu.
- `channels` — publicēja katra dist-taga galveni no `npm view omniroute dist-tags` (reģistra HTTP atkāpšanās), kas saglabāta kešatmiņā ar tādu pašu 10 minūšu TTL kā `latest`. `latest` vienmēr ir klāt (atgriežas laukā `latest`, pēc tam `"unavailable"`); `next`, `nightly` un `lts` parādās tikai tad, ja pastāv šis dist-tags. `Cache-Control: no-cache` pieprasījums atsvaidzina abus meklējumus.

Kanāla modelis (`latest` = v3 līdz 4.0 GA, `next` = rc, `nightly` = `develop` būvējumiem, `lts` = v3 ielāpi pēc 4.0 GA) ir aprakstīts `docs/ops/RELEASE_STRATEGY.md`.

## Audio transkripcija

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data
```

Transkribējiet audio failus, izmantojot jebkuru konfigurētu STT pakalpojumu sniedzēju. Pirmais ceļa
segments atlasa vietējo pakalpojumu sniedzēju (`openai/…`, `deepgram/…`). Vārtejas, kas
atkārtoti eksportē cita piegādātāja modeli, izmanto kvalificētu ID
(`openrouter/deepgram/nova-3`).

**Pieprasījums:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**Atbilde:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**Piemēru modeļu ID:** `openai/whisper-1` (nepieciešama OpenAI atslēga),
`openrouter/deepgram/nova-3` (nepieciešama OpenRouter atslēga),
`deepgram/nova-3` (nepieciešama vietējā Deepgram atslēga). Pieprasījums ar vienkāršu
`deepgram/nova-3` **neizmanto** OpenRouter.

**Atbalstītie formāti:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`.

**Gemini Live (`gemini/gemini-3.5-transcribe-live`):** failu režīma transkripcija, izmantojot Gemini Live
WebSocket (nepieciešama Gemini API atslēga). Augšupielāde tiek pārveidota par 16 kHz mono PCM, izmantojot `ffmpeg`
(jābūt pieejamam mainīgajā `PATH`, ja vien fails jau nav 16 kHz mono PCM WAV formātā), straumēta uz sesiju, un
pabeigtais teksts tiek atgriezts kā `{ "text": "..." }`. Neobligātie `language` un `prompt` veidlapas lauki tiek
pārsūtīti. Ierobežojumi: augšupielādes, kas pārsniedz 25 MiB, vai dekodētais audio, kas ir garāks par 10 minūtēm,
saņem atbildi `413`; ja pārveidošana ilgst vairāk nekā 60 s, process tiek pārtraukts un tiek atgriezta atbilde
`504`. API atslēga tiek nosūtīta tikai `x-goog-api-key` galvenē, nekad WebSocket URL.

## Tokenu ierobežojumi

Par katru API atslēgu noteikti **tokenu** budžeti (atšķiras no iepriekš aprakstītā budžeta USD). Tie tiek piemēroti tieši pieprasījuma apstrādes ceļā: kad atslēgas pašreizējais lietojums logā sasniedz ierobežojumu, pieprasījumi tiek noraidīti ar `429 Too Many Requests`. Ierobežojumus var attiecināt uz konkrētu `model`, `provider` vai piemērot `global` līmenī visai atslēgai; ja pieprasījumam atbilst vairāki ierobežojumi, tiek izmantots visstingrākais.

```bash
# Uzskaitīt atslēgas tokenu ierobežojumus (ietver aktuālo lietojumu logā)
GET /api/usage/token-limits?apiKeyId=key-123

# Izveidot vai atjaunināt tokenu ierobežojumu
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Dzēst tokenu ierobežojumu pēc ID
DELETE /api/usage/token-limits?id=tl-abc
```

> **Shēmas piezīmes** (`setTokenLimitSchema`): `apiKeyId` un `scopeType` (`model` | `provider` | `global`) ir obligāti. `scopeValue` ir obligāts, ja vien `scopeType` nav `global` (piemēram, modeļa ID `model` tvērumam vai nodrošinātāja ID `provider` tvērumam). `tokenLimit` ir jābūt pozitīvam veselam skaitlim (tiek pārveidots no virknes). Neobligāti: `id` (izlaist, lai izveidotu, norādīt, lai atjauninātu), `resetInterval` (`daily` | `weekly` | `monthly`, noklusējums: `monthly`), `resetTime` (`HH:MM`), `enabled` (noklusējums: `true`). `GET` atbildes katru ierobežojumu papildina ar `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` un `nextResetAt`. Šis ir pārvaldības klases galapunkts (autentifikācija tiek centralizēti nodrošināta authz konveijerā).

## Pieprasījumu apstrāde

1. Klients nosūta pieprasījumu uz `/v1/*`
2. Maršruta apstrādātājs izsauc `handleChat`, `handleEmbedding`, `handleAudioTranscription` vai `handleImageGeneration`
3. Modelis tiek atrisināts (tiešais nodrošinātājs/modelis vai aizstājvārds/kombinācija)
4. Akreditācijas dati tiek atlasīti no lokālās datubāzes, filtrējot pēc konta pieejamības
5. Tērzēšanai: `handleChatCore` pārbauda semantisko/paraksta kešatmiņu un atrisina kombinācijas saspiešanas iestatījumus
6. Ja tas ir iespējots, pirms tulkošanas uz nodrošinātāja formātu tiek veikta proaktīva saspiešana (`lite`, Caveman, RTK vai kombinēta)
7. Nodrošinātāja izpildītājs nosūta augšupēju pieprasījumu
8. Atbilde tiek pārtulkota atpakaļ klienta formātā (tērzēšanai) vai atgriezta bez izmaiņām (iegulšanai/attēliem/audio)
9. Tiek reģistrēti lietojuma dati, saspiešanas analītika un pieprasījumu žurnāli
10. Kļūdu gadījumā tiek piemērota atkāpšanās procedūra atbilstoši kombinācijas noteikumiem

Pilna arhitektūras atsauce: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Noturība (paplašināta)

OmniRoute nodrošina trīs neatkarīgus pagaidu kļūmju mehānismus; tālāk norādītie pārvaldības galapunkti ļauj operatoriem tos nolasīt un pārrakstīt:

| Tvērums                   | Stāvokļa glabātuve                            | Nolasīšana                                | Atiestatīšana / notīrīšana                                           |
| ------------------------- | --------------------------------------------- | ----------------------------------------- | -------------------------------------------------------------------- |
| Nodrošinātāja pārtraucējs | `domain_circuit_breakers` + atmiņā            | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                         |
| Savienojuma atdzišana     | `rateLimitedUntil` nodrošinātāja savienojumos | `/api/rate-limits`, `/api/providers/[id]` | (atkārtoti iespējojas slinki; notīrīt, izmantojot nodrošinātāja PUT) |
| Modeļa bloķēšana          | Atmiņā esošs modeļu pieejamības reģistrs      | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                             |

`PATCH /api/resilience` pieņem nodrošinātāja pārtraucēja pārrakstījumus sadaļās `providerBreaker.oauth` un `providerBreaker.apikey`. Katrs profils atbalsta `degradationThreshold`, `failureThreshold` un `resetTimeoutMs`; tie paši lauki ir pieejami arī Dashboard → Settings → Resilience.

```bash
# Notīrīt viena modeļa bloķēšanu

  -H "Cookie: auth_token=..." \

  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Notīrīt visas bloķēšanas

  -d '{"all":true}'
```

Pilnu konceptuālo atsauci un pārtraucēja noklusējuma vērtības skatiet [`CLAUDE.md`](../../CLAUDE.md) → “Resilience Runtime State” un [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Ātruma ierobežojumu rinda un automātiskās iespējošanas drošības tīkls

- **Atbalstītais rakstīšanas ceļš**: `POST /api/rate-limits` ar pamattekstu `{"connectionId": "<id>", "enabled": true|false}` ir atbalstītais pārvaldības galapunkts, lai pārslēgtu ātruma ierobežojumu aizsardzību savienojumam. `PUT /api/providers/[id]` apzināti nemaina un nepārslēdz `rateLimitProtection` (#11278).
- **`enabled: false` semantika**: Iestatot `enabled: false`, savienojumam tiek noņemta tieši norādītā aizsardzība, taču **aktīvs API atslēgas savienojums netiek izslēgts no globālā automātiskās iespējošanas drošības tīkla (`autoEnableApiKeyProviders = true`)**. `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) ietvaros `false` un `undefined` ir līdzvērtīgi; aktīvi API atslēgas savienojumi bez tieši norādītas aizsardzības joprojām tiek aizsargāti, izmantojot automātiskās iespējošanas drošības tīklu.
- **Globāla atspējošana**: Lai palaistu API atslēgas savienojumus bez ātruma ierobežojumu rindām, globāli atspējojiet drošības tīklu, izmantojot `RATE_LIMIT_AUTO_ENABLE=false` (env) vai `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Settings → Resilience / `PATCH /api/resilience`).

| Metode | Ceļš                   | Apraksts                                                                                                                  |                      |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| GET    | `/api/mcp/status`      | Sirdsdarbības signāls, transports, tiešsaistes statuss, pēdējais izsaukums, populārākie rīki, 24 stundu veiksmes rādītājs |

| GET    | `/api/mcp/stream`      | Atvērt Streamable HTTP transporta SSE pusi (servera iniciētiem ziņojumiem)                                                |

## A2A serveris

OmniRoute nodrošina A2A (aģents–aģentam) JSON-RPC 2.0 galapunktu, kā arī REST ietvaru pārbaudes un informācijas paneļa vajadzībām.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # neobligāts, izņemot gadījumu, kad ir iestatīts OMNIROUTE_API_KEY
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Atbalstītās metodes (visām nepieciešams `settings.a2aEnabled`):

| Metode           | Apraksts                                                        |
| ---------------- | --------------------------------------------------------------- |
| `message/send`   | Sinhrona prasmes izpilde; atgriež `{task, artifacts, metadata}` |
| `message/stream` | Tās pašas prasmju kopas straumējoša SSE izpilde                 |
| `tasks/get`      | Iegūt uzdevumu pēc `taskId`                                     |
| `tasks/cancel`   | Atcelt uzdevumu pēc `taskId`                                    |

Iebūvētās prasmes: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Aģenta karte

```bash
GET /.well-known/agent.json
```

Atgriež publisko A2A aģenta karti (nosaukumu, aprakstu, iespējas, prasmju katalogu, autentifikācijas shēmu) — publiski kešota 1 stundu. Autentifikācija nav nepieciešama.

### REST palīgmetodes

| Metode | Ceļš                         | Apraksts                                                                                                                 |
| ------ | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| GET    | `/api/a2a/status`            | A2A statuss, uzdevumu statistika un kešotās aģenta kartes kopsavilkums                                                   |
| GET    | `/api/a2a/tasks`             | Uzskaitīt uzdevumus — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Nav ieviesta kā REST palīgmetode — izveidojiet, izmantojot JSON-RPC `message/send`)                                     |
| GET    | `/api/a2a/tasks/[id]`        | Iegūt vienu uzdevumu                                                                                                     |
| POST   | `/api/a2a/tasks/[id]/cancel` | Atcelt uzdevumu                                                                                                          |

**Autentifikācija:** REST palīgmetodes darbojas bez pārvaldības autentifikācijas (pieejamas informācijas panelim); JSON-RPC maršruts `/a2a` izmanto Bearer `OMNIROUTE_API_KEY`, ja tas ir konfigurēts.

## Autentifikācija

Skatiet [Pārvaldības autentifikācija](../guides/MANAGEMENT-AUTH.md), lai uzzinātu par četrām akreditācijas datu saimēm (informācijas paneļa sesija, lokāls CLI marķieris, `oma_live_…` piekļuves marķieris, ar manage tvēruma API atslēga) un to atšķirībām no secināšanas atslēgām.

- Informācijas paneļa maršruti (`/dashboard/*`) izmanto `auth_token` sīkfailu
- Pieteikšanās izmanto saglabāto paroles jaucējkodu; rezerves variants ir `INITIAL_PASSWORD`
- `requireLogin` slēdzi var mainīt, izmantojot `/api/settings/require-login`
- `/v1/*` maršrutiem pēc izvēles var būt nepieciešama Bearer API atslēga, ja `REQUIRE_API_KEY=true`
- “management token” / “management-scoped API key” šajā atsaucē nozīmē vienu no šajā rokasgrāmatā aprakstītajām saimēm — nevis nedefinētu papildu slepeno tipu

> **Būtiskas izmaiņas (v3.8.0)** — `/api/v1/agents/tasks/*` un atdzišanas perioda pārvaldības galapunktiem tagad nepieciešama **pārvaldības autentifikācija** (informācijas paneļa `auth_token` sīkfails vai ar pārvaldības tvērumu saistīta API atslēga). Klienti, kas iepriekš izsauca šos maršrutus bez autentifikācijas, saņems `401 Unauthorized`. Skatiet komitu `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
