Neitrālajā `config/cli-tools-manifest.json` līgumā ir deklarēti kanoniskie IDs, aizstājvārdi, binārie kandidāti, iestatīšanas receptes, modeļa argumenti un iespējas. Vienkāršais mezgla adapteris `bin/cli/cli-manifest.mjs` un TypeScript adapteris `src/shared/constants/cliIntegrationManifest.ts` lasa vienu un to pašu failu. Izpildlaiku, katalogu, konfigurēšanu, pabeigšanu, ģeneratorus un aizmugursistēmas reģistrāciju kopā pārbauda `tests/unit/cli/cli-manifest-drift.test.ts`. Katalogs nenozīmē, ka rīku var palaist vai konfigurēt. Jo īpaši 5dive paliek tikai konfigurēta.

## Bērna vide un dzīves cikls

`omniroute run`, `omniroute launch` un `omniroute launch-codex` manto OS/terminal saderības atļaušanas sarakstu un ievada atlasītā mērķa akreditācijas datus. Nesaistītie pakalpojumu sniedzēja un datu bāzes noslēpumi pēc noklusējuma netiek mantoti. `--inherit-env` nepārprotami atjauno pilnīgu vecāku vides mantojumu; izmantojiet to tikai tad, kad atlasītajam trešās puses procesam ir jāsaņem šīs vērtības. Šī ir vides filtrēšana, nevis OS smilškaste: process joprojām darbojas ar zvanītāja failu sistēmas atļaujām.

Pārtraukšanas un izbeigšanas signāli tiek pārsūtīti bērnam. Pirms pagaidu konfigurācijas noņemšanas palaišanas programma gaida bērna aizvēršanas notikumu. `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` kontrolē labvēlības periodu pirms piespiedu pārtraukšanas (noklusējuma 5000 milisekundes).

## Gemini pastāvīga iestatīšana

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

Pirmās divas komandas konfigurē šo iekārtu atlasītajam lokālajam vai attālajam serverim. Iestatīšana saglabā nesaistītos JSON iestatījumus, atlasa Gemini API atslēgas autentifikāciju un ieraksta beigu punktu un akreditācijas datus privātā `.gemini/.env` failā. Tas atsakās no nederīga JSON, nevis to pārraksta. Galapunktam URLs ir jābūt HTTP(S), bez iegultiem akreditācijas datiem, vaicājuma parametriem vai fragmentiem. Sausā darbība drukā ceļus, nevis akreditācijas vērtības.

`GEMINI_CLI_HOME` vai `--gemini-home` atlasa pastāvīgo sākuma sakni. Faktiskais `run gemini` izveido un vēlāk noņem savu pagaidu māju. Neviens režīms neapiet Gemini darbvietas uzticamības pārbaudes.

## Codex profili

`configure codex` raksta privātu `<name>.config.toml` ar modeli un tā OmniRoute nodrošinātāja galapunktu. Uz akreditācijas datiem atsaucas, izmantojot `OMNIROUTE_API_KEY`, un tie nekad netiek iegulti. Palaišanas komanda iestata atlasīto modeli augstākā līmeņa `model` taustiņā, nevis `model_providers` iekšpusē.

Atsevišķi profila faili ir pašreizējais dokumentētais Codex līgums; kad tie ir atlasīti ar `codex --profile <name>`, tie pārklāj lietotāja konfigurāciju. Skatiet [oficiālo profila atsauci](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) un [OmniRoute Codex rokasgrāmatu](./CODEX-CLI-CONFIGURATION.md).

## Hermētiska komandas izpilde

Izmantojot skaidru `DATA_DIR`, `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` iestatīšana novērš startēšanas nokļūšanu noklusējuma lietotāja datu direktorija akreditācijas datu vidē. Tas ir noderīgi izolētiem testiem. Tas neatspējo citus skaidri atlasītus vides failus.

## Darba direktorijs `.env`

CLI nolasa `.env` failus šādā secībā, un uzvar pirmais fails, kurā ir iestatīta atslēga: tiešais `DATA_DIR`, noklusējuma datu direktorijs, pašreizējais darba direktorijs, pēc tam pakotņu direktorijs. Shell mainīgie vienmēr uzvar.

Darba direktorijs var piederēt kādam citam (klonētai krātuvei, neizpakotam arhīvam), un `omniroute serve` nodod CLI vidi serverim un katram servera darbinātajam rīkam. Tātad `.env` var iestatīt tikai šos taustiņus, kas uzskaitīti `bin/cli/utils/untrustedCwdEnv.mjs`:

| Atslēga                         | Pieņemtās vērtības                                                                       |
| ------------------------------- | ---------------------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | `true`, `1` vai `yes` jebkurā gadījumā ir vērtības, kuras serveris apstrādā kā ieslēgtas |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | līdz 64 burtiem, cipariem, `_`, `.`, `@` vai `-`                                         |
| `LANGUAGE`                      | tas pats, plus `:`                                                                       |
| `TZ`                            | līdz 64 burtiem, cipariem, `_`, `+`, `-` vai `/`, nesākas ar `/`                         |
| `NO_COLOR`, `FORCE_COLOR`       | līdz 16 burtiem un cipariem                                                              |

Katra vērtība, ko `REQUIRE_API_KEY` pieņem, ieslēdz pārbaudi, tāpēc fails pats nevar izslēgt pārbaudi. Tomēr tas nenosaka rezultātu: serveris nolasa datubāzē saglabāto `REQUIRE_API_KEY` ignorēšanu pirms vides, savukārt starta brīdinājums par klausīšanos visās saskarnēs bez API atslēgas nolasa tikai vidi. Ja ir saglabāta `false` ignorēšana, darba direktorijs `REQUIRE_API_KEY=true` atstāj API atvērtu un paslēpj šo brīdinājumu. `TZ` noteikums ir šaurāks nekā POSIX: tas noraida `.`, `:`, `,` un `<>`, tāpēc `:Area/City` forma un tādi noteikumi kā `EST5EDT,M3.2.0,M11.1.0` ir jāiestata apvalkā vai `<DATA_DIR>/.env`.

Nosaukumiem precīzi jāsakrīt ar lielajiem burtiem. Visas citas rindas, vērtība, kas nav pārbaudīta, un nosaukums, kas nav vienkārši ASCII burti, cipari un `_` (piemēram, ar NUL baitu vai līdzīgu burtu), tiek izlaistas. CLI izdrukā vienu brīdinājumu, kurā tiek nosaukti taustiņi, kurus tā nevar iestatīt, un viens, kurā tiek nosaukti atļautie taustiņi, kurus tā ignorēja, katram norādot, ko mainīt (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). Neviens nedrukā vērtības. Failu ceļi šajos ziņojumos un `.env` ceļš `omniroute doctor` pārskatos tiek izspiesti, ja tajos ir ietvertas vadības vai divdimensiju rakstzīmes. Ierobežojums neattiecas uz gadījumiem, kad darba direktorijs ir datu direktorijs vai pakotņu direktorijs.

`PORT`, `API_PORT` un `DASHBOARD_PORT` nav sarakstā. Ja nav pamata URL no augstākas prioritātes avota, CLI runā ar `localhost:<PORT>`, un tas, kas tur klausās, saņem CLIAPI atslēgu, konteksta pilnvaru un CLI mašīnas pilnvaru (`x-omniroute-cli-token`, skatiet [CLI_TOKEN.md](../security/CLI_TOKEN.md) ), ko vietējais serveris pieņem pārvaldības izsaukumiem no loopback. Ports no darba direktorija ļautu šim failam izvēlēties klausītāju, tāpēc iestatiet portus čaulā, `<DATA_DIR>/.env` vai ar komandu opciju `--port`, kurām tāda ir (`serve`, `launch`, `run`).

Parsētājam nav `export` sintakses. Tāda rinda kā `export LD_PRELOAD=...` nosauc mainīgo `export LD_PRELOAD`; no darba direktorija tas tiek izlaists, un citos `.env` failos tas nosaka šo burtisko nosaukumu, kuru nekas nelasa.

CLI savieno pārī konteksta saglabāto pilnvaru (piekļuves pilnvaru vai mantoto API atslēgu) tikai ar šī konteksta izcelsmi: shēmu, resursdatoru un portu, salīdzinot ar `URL.origin`. Tas attiecas uz pieprasījumiem, kas veikti, izmantojot CLIHTTP klientu (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`), un komandām `launch`, `launch codex`, `configure` un `setup-*`, kas ieraksta URL bāzes un atslēgu cita rīka konfigurācijā. Norādīti uz citu serveri ar `--remote`, tie izmanto skaidru `--api-key` vai `OMNIROUTE_API_KEY` ja tāds ir iestatīts, un bez konteksta pilnvaras. Salīdzinājums ir precīzs, tāpēc `localhost` un `127.0.0.1` vai resursdators ar un bez beigu punkta tiek uzskatīti par dažādiem serveriem un nesaņem konteksta pilnvaru. URL ar lietotāja informāciju, atpakaļvērstā slīpsvītra vai atstarpe nekad nesakrīt, jo citi URL parsētāji (piemēram, Python `urllib` un `httpx`) var no tā nolasīt citu resursdatoru. Pieprasījumiem CLI nosūta pats, šī pārbaude attiecas tikai uz shēmu un autoritāti, tāpēc ID ar atstarpi ceļā vai vaicājumā saglabā marķieri.
