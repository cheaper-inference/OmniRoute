> **Īsumā**: Instalējiet → Pievienojiet piemērotu pakalpojumu sniedzēju → Norādiet IDE izmantot OmniRoute. Gatavs.

---

## 1. darbība: instalējiet OmniRoute

Izvēlieties vēlamo metodi:

### A variants: npm (ieteicams)

```bash
npm install -g omniroute
```

### B variants: Docker

```bash
docker run -d --name omniroute -p 20128:20128 cheaperinference/omniroute:latest
```

`:latest` ir jaunākā **publicētā** stabilā SemVer versija. Tā **neseko** git `main` zaram. GitOps vajadzībām piesaistiet konkrētu `cheaperinference/omniroute:X.Y.Z` versiju. Skatiet sadaļu [Attēlu tagi / laidienu kanāli](../guides/DOCKER_GUIDE.md#release-channels).

### C variants: no pirmkoda

```bash
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
npm install
npm run dev
```

---

## 2. darbība: palaidiet OmniRoute

```bash
omniroute
```

OmniRoute tiek palaists adresē `http://localhost:20128`. Informācijas panelis tiek atvērts automātiski.

---

## 3. darbība: Pievienojiet piemērotu pakalpojumu sniedzēju

Izvēlieties pakalpojumu sniedzēju, kura noteikumi un kvota atbilst jūsu vajadzībām. Sadaļā **Informācijas panelis → Pakalpojumu sniedzēji** pievienojiet savu kontu vai API atslēgu un pēc tam pārbaudiet savienojumu. Bezmaksas piekļuve un pieejamība bez atslēgas netiek garantēta.

`auto` pēc noklusējuma izslēdz pakalpojumu sniedzējus, kas atzīmēti ar `tos: avoid`, tostarp Kiro. Konta pievienošana nemaina šo politiku. Piekrišana sadaļā **Informācijas panelis → Kombinācijas** attiecas uz visām automātiskajām kombinācijām. Pirms pakalpojumu sniedzēja izvēles izlasiet [Bezmaksas līmeņu ceļvedi](./FREE-TIERS-GUIDE.md).

---

## 4. darbība: pārbaudiet, vai viss darbojas

Sadaļā [API atslēgas](http://localhost:20128/dashboard/api-manager) izveidojiet jaunu atslēgu. Saglabājiet šo atslēgu, jo tā vairs netiks parādīta. Ņemiet vērā, ka šī atslēga ir paredzēta rīku piekļuvei OmniRoute, nevis augšupējo pakalpojumu sniedzēju piekļuvei.

```bash
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"
```

Jums vajadzētu redzēt pievienoto modeļu sarakstu.

---

## 5. darbība. Norādiet savu IDE vai CLI uz OmniRoute

Savā IDE vai CLI rīkā iestatiet:

```
Base URL: http://localhost:20128/v1
API Key:  [the key you created in Step 4 (Dashboard → API Keys)]
Model:    auto
```

Tas arī viss! Jūsu IDE tagad izmanto OmniRoute ar automātisku pakalpojumu sniedzēja atlasi.

### IDE Piemērs: VSCode/Continue.dev

1. Programmā VSCode instalējiet paplašinājumu [Continue.dev](https://marketplace.visualstudio.com/items?itemName=Continue.continue).
2. Atjauniniet savu `~/.continue/config.yaml`, lai pievienotu šādas rindas:

```
  - name: OmniRoute - Auto
    provider: openai
    model: auto
    apiBase: http://localhost:20128/v1
    apiKey: <YOUR_KEY>
```

3. Tērzēšanas rūtī Continue.dev atlasiet `OmniRoute - Auto`, un jūs veiksit pieprasījumus OmniRoute.
4. (Pēc izvēles) Vingrinājums lasītājam — lieciet savam IDE atjaunināt `config.yaml` ar visām pārējām iepriekš iebūvētajām konfigurācijām 😊

### CLI Piemērs: Codex CLI

1. Operētājsistēmā pastāvīgi iestatiet vides mainīgo. macOS/Linux (pievienojiet savam `~/.bashrc` vai `~/.zshrc`):

```bash
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

Windows (komandrinda):

```
setx OMNIROUTE_API_KEY <YOUR_KEY>
```

2. Tagad palaidīsim Codex, bet konfigurēts OmniRoute. Palaist:

```
omniroute launch-codex --model auto
```

To var izdarīt manuāli, izmantojot `codex` un komandrindas parametrus, lai norādītu beigu punktu un api atslēgu, taču ar iepriekš minēto komandu OmniRoute parūpēsies par visu jūsu vietā.

Tā pati vienas komandas palaišana darbojas arī citiem CLIs, izmantojot vispārējo palaidēju — `omniroute run <target>` atbalsta `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen` un `gemini` (skatiet [CLI Integrācijas](../guides/CLI-INTEGRATIONS.md) ).

3. CLI tagad vajadzētu sūtīt pieprasījumus uz OmniRoute.

### Apstipriniet, ka jūsu rīks tiek maršrutēts uz OmniRoute

Detalizētu informāciju par pieprasījumu varat skatīt, kreisajā sānjoslā noklikšķinot [Monitoring/Logs](http://localhost:20128/dashboard/logs). Noklikšķinot, tiek parādīta sīkāka informācija. Kā sānu piezīmi, varat redzēt, kāda informācija tiek nosūtīta no jūsu iecienītākās siksnas. Tas ir noderīgi no izglītības un atkļūdošanas viedokļa.

## Biežāk uzdotie jautājumi

### "Vai man ir nepieciešama API atslēga?"

OmniRoute API atslēga autentificē jūsu rīkus. Ārējo pakalpojumu piekļuves dati ir atkarīgi no pakalpojumu sniedzēja: daži pieprasa API atslēgu vai pieteikšanos kontā. Bezmaksas piekļuve netiek garantēta.

### "Kas ir `auto`?"

`auto` norāda OmniRoute automātiski izvēlēties labāko pakalpojumu sniedzēju katram pieprasījumam. Tas ņem vērā ātrumu, izmaksas, kvalitāti un pieejamību. Plašāku informāciju skatiet [automātiskās kombinēšanas ceļvedī](./AUTO-COMBO-GUIDE.md).

### "Cik tas maksā?"

Pats OmniRoute ir **bezmaksas un atvērtā pirmkoda** risinājums. Jūs maksājat tikai par izmantotajiem pakalpojumu sniedzējiem. Daudzi pakalpojumu sniedzēji piedāvā bezmaksas līmeņus — skatiet [bezmaksas līmeņu ceļvedi](./FREE-TIERS-GUIDE.md).

### "Vai varu to izmantot ar Claude Code / Cursor / Copilot?"

**Jā!** OmniRoute darbojas ar jebkuru rīku, kas atbalsta OpenAI formātu. Vienkārši iestatiet pamata URL uz `http://localhost:20128/v1`. Konkrētas iestatīšanas instrukcijas skatiet [CLI rīku ceļvedī](../reference/CLI-TOOLS.md).

### "Kas notiek, ja pakalpojumu sniedzējs pārtrauc darboties?"

OmniRoute automātiski izlaiž pakalpojumu sniedzējus, kuru darbība neizdodas, un mēģina nākamo. Jums nekas nav jādara. Plašāku informāciju skatiet [automātiskās kombinēšanas ceļvedī](./AUTO-COMBO-GUIDE.md).
