> **Statuss:** informācijas panelis ir veidots uz **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`), kas iekļauts (vendored) kā workspace `packages/ui-kit` (`@omniroute/ui-kit`; augšupes momentuzņēmums ir nofiksēts `packages/ui-kit/UPSTREAM.md` un to kontrolē `npm run check:ui-kit-snapshot`). Gaišā ir kanoniskā
> tēma; noklusējuma preference ir `system`. Akcents ir Keak laima krāsa (`--ci-color-accent`). Inter
> (burtu attālums 0, `--ci-letter-spacing-ui`) ir saskarnes fontu saime, Instrument Serif — tikai lielam,
> reti lietojamam virsrakstu tekstam (`.ci-dashboard-display`), IBM Plex Mono — kodam; visi fonti ir
> pašhostēti, izmantojot `@fontsource/*` importus `src/app/globals.css` augšdaļā. Katra ikona ir Lucide glifs.

## 1. Kur kas atrodas

- **Kit.** `packages/ui-kit/src` ir baitu līmenī identiska upstream `src/` kopija pie tā commit, kas nofiksēts
  `packages/ui-kit/UPSTREAM.md` (kurā reģistrēta arī licences autorizācija); `PATCHES.md` uzskaita lokālos
  patch (to nav). Tas tiek lietots kā avotkods, bez būvēšanas: `next.config.mjs` to transpile, bet
  `tsconfig.json` kartē `@omniroute/ui-kit` → `packages/ui-kit/src` un `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` (`vitest.config.ts` un `vitest.mcp.config.ts` satur to pašu alias). Kit
  komponenti importē pēc tā apakšceļa (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), nekad
  caur `@omniroute/ui-kit` barrel failu: barrel fails ierauj visas komponentes (ieskaitot datuma atlasītāju)
  katrā importētājā. Kit stilu lapa nonāk projektā caur `src/app/globals.css`
  (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **Tokeni.** `packages/ui-kit/src/ci-tokens.css` deklarē `--ci-*` tokenus; `src/app/globals.css`
  izveido tiltu no tiem uz mantotajiem OmniRoute nosaukumiem (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`,
  `--table-*`, `--orch-status-*`, `--color-fd-*`), tāpēc esošie `var(--color-*)` nolasījumi un Tailwind
  utilītas turpina darboties. Jaunais kods izmanto Tailwind utilītas (`bg-surface`, `text-text-muted`,
  `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) vai kit klases — nekad hex vērtību
  (`tests/unit/design-kit-bridge.test.ts` nodrošina šī tilta ievērošanu). `text-primary` tiek atrisināts uz
  `--color-primary-ink` caur `--text-color-primary` (lime-800 gaišajā režīmā, laima akcents tumšajā), tāpēc
  primārais teksts paliek lasāms, bet `bg-primary`/`border-primary` saglabā laima virsmu. Diagrammu sērijas
  izmanto `--color-chart-1` … `--color-chart-5`.
- **Tēmas.** `<html className="ci-theme">` (`src/app/layout.tsx`) pieslēdz dokumentu kit tēmai.
  Tēmas izvēle ir `light`, `dark` vai `system` (`THEME_CONFIG.defaultTheme = "system"` failā
  `src/shared/constants/appConfig.ts`; `system` seko `prefers-color-scheme`). `applyTheme()` failā
  `src/store/themeStore.ts` (ko dublē inline bootstrap skripts failā `src/app/layout.tsx`, kas izpildās
  pirms hidratācijas) vienlaikus iestata `data-theme="dark"|"light"` un pārslēdz `.dark` klasi elementā
  `<html>`. Kit tumšo tokenu kopa ir saistīta ar `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`);
  OmniRoute pašu tumšā režīma pārdefinējumi (`.dark` bloks failā `globals.css`) un mantotās Tailwind `dark:`
  utilītas ir saistītas ar `.dark` klasi. Akcenta krāsas priekšiestatījumu nav: akcents vienmēr nāk no kit,
  un priekšiestatījums, kas saglabāts no vecākas būves, tiek atmests, ielādējoties store.
- **Komponentes (adapteri).** `src/shared/components/index.tsx` saglabā OmniRoute komponenšu API (tos pašus
  nosaukumus, noklusējuma eksportus un props), un primitīvi aiz tā ir adapteri virs kit: formas
  (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), pārklājumi un atgriezeniskā
  saite (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`),
  struktūra (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) un tabulas
  (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). Adapteris importē kit
  komponenti pēc apakšceļa un kartē uz to mantotos props — piemēram, `Button variant="primary"` ir kit
  `default` poga (`--ci-button-primary-*`: inversā virsma gaišajā režīmā, akcents ar savu
  `--ci-color-accent-foreground` tinti tumšajā), `danger` ir `destructive`, bet `warning` ir `outline` plus
  `.ci-button--warning` paplašinājums. `.ci-button--warning` un `.ci-badge[data-tone]` noteikumi
  `globals.css` beigās (`@layer components`) ir OmniRoute paplašinājumi virs kit klasēm.
  `tests/unit/ui/adapters/*.test.tsx` fiksē katru adapteri.
- **Apvalks.** `src/app/(dashboard)/layout.tsx` renderē `DashboardLayout`, kas renderē
  `src/shared/components/layouts/DashboardShell.tsx`: kit `SidebarProvider` / `Sidebar` /
  `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), ar OmniRoute navigācijas loģiku
  `src/shared/components/Sidebar.tsx`. Saite "skip to content" ("pāriet uz saturu") uz `#main-content` ir
  pirmais fokusējamais elements. `src/shared/components/Header.tsx` ietver kit `SidebarTrigger` (apvalka
  vienīgo sānjoslas pārslēdzēju), Keak `ProductSwitcher` un komandu paletes atvērēju; tas parāda maršruta
  virsrakstu tikai tik ilgi, kamēr `#main-content` iekšpusē nav uzmontēts kit `PageHeader`
  (`.ci-page-header`), tāpēc lapai ar savu `PageHeader` ir viens `h1`.
  `src/shared/components/CommandPalette.tsx` ir kit `Dialog`.
- **Ikonas.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) atrisina nosaukumu (Material
  Symbols vārdu krājumu, ko ekrāni izmanto) caur `ICON_MAP` (`src/shared/constants/iconMap.ts`) uz Lucide
  glifu. Material Symbols fonts un pakotne ir aizvākti: nosaukums, kura nav kartē, renderē neitrālu viettura
  glifu (`data-icon-missing="true"`) un ārpus produkcijas reģistrē konsolē brīdinājumu.
  `npm run gen:icon-map` izdrukā lietojumā esošos nosaukumus, kuru nav kartē
  (`tests/unit/icon-map-coverage.test.ts` neizdodas, ja kādam nosaukumam nav Lucide ikonas;
  `tests/unit/icon-map-object-values.test.ts` aptver nosaukumus, kas glabājas uzmeklēšanas objektos);
  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` pārraksta burtiskos
  `<span className="material-symbols-outlined">` spanus par `<Icon>`.
- **Zīmols.** `src/shared/components/OmniRouteLogo.tsx` ietin kit: noklusējuma eksports `OmniRouteLogo`
  renderē `ProductIcon product="omniroute" variant="glyph"` (inline SVG, `basePath`-drošs), bet
  `OmniRouteLockup` renderē `ProductLockup product="omniroute"` (pieejamais nosaukums "Keak OmniRoute") vai,
  white-label operatoriem, viņu pašu `name`/`logoSrc`. Produktu pārslēdzēja galamērķi atrodas
  `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`). Atsevišķie
  ekrāni — `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`,
  `src/app/offline/page.tsx`, `src/app/not-found.tsx` un `src/shared/components/ErrorPageScaffold.tsx`
  — parāda lockup (zīmola salikumu); `tests/unit/brand-pages-static.test.ts` to uzrauga.

## 2. Noteikumi

1. Žetoni, nekad literāļi. Izņēmumi atstāti apzināti: vienmēr tumšais konsoles terminālis, ReactFlow SVG
   svītras caur `STATUS_HEX` (`src/shared/constants/statusColors.ts`) un kategoriju paletes
   `STRATEGY_COLORS` (`src/app/(dashboard)/dashboard/combos/live/nodes/StrategyNode.tsx`) un
   `LAYER_COLORS` (`src/app/(dashboard)/dashboard/compression/studio/nodes/EngineNode.tsx`).
2. Nekad nelabojiet `packages/ui-kit/src` ar roku: sinhronizējiet ar `scripts/dev/sync-ui-kit.sh <commit>`;
   pre-commit pārbaude `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) neizdodas pie jebkura baita,
   kas atšķiras no piespraustā upstream commit (tā izlaiž ar brīdinājumu, kad upstream klons,
   `UI_KIT_CLONE` vai `_references/cheaper-inference-ui-kit`, nav pieejams). Ja komplektam kaut kas trūkst,
   apiet to adapterī vai ekrānā un pieprasiet to no upstream.
3. Komplekta teksta noklusējumi ir angļu valodā (`label = "Loading"`, `loadingLabel = "Loading table"`…) —
   nododiet tulkotās virknes no `useTranslations(...)`, ikreiz, kad komplekta komponents attēlo tekstu.
4. Tailwind utilītklases uzvar komplekta komponentu klases (komplekts deklarē
   `@layer theme, base, components, utilities`, un tā noteikumi atrodas `components`) — izmantojiet
   utilītklases atstarpu un izkārtojuma vajadzībām, nevis komplekta komponentu pārkrāsošanai.
5. Virsraksti: `.ci-heading` (Inter, bez izsekošanas) lapas un sadaļu virsrakstiem; `.ci-dashboard-display`
   (Instrument Serif) tikai lielam, reti lietotam displeja tekstam, piemēram, kļūdas lapas statusa kodam.
6. `tests/unit/dashboard-kit-sweep.test.ts` sargā komplekta ieviešanu: neviena Material ligatūras span
   elementa zem `src/app` vai `src/shared/components`; informācijas paneļa kokā (`src/app/(dashboard)` un
   `src/shared/components`) neviena tīra `<select>`, `<textarea>` vai `<table>` un neviena pašu rokām
   darināta `role="dialog"` ārpus uzskaitītajiem izņēmumiem (`Select` adaptera natīvais zars,
   `RequestLoggerDetail`); katram tīram `<button>` vai `<input>` tur nepieciešams komentārs, kas satur
   `kit-exception:` (ar iemeslu) un beidzas ne vairāk kā 3 rindas virs tā; paletes toņi un `dark:` varianti
   tikai failos, kurus tests uzskaita.
7. Pirms PR pārbaudiet abas tēmas un 390 px skatlogu (ekrānuzņēmumi); `tests/e2e/a11y.spec.ts` palaiž axe.

## 3. Ekrāna pievienošana

1. Atveriet lapu ar komplekta `PageHeader` (`@omniroute/ui-kit/page-header`, `compact` informācijas paneļa
   iekšpusē) — virsraksts, apraksts un `actions`. Apvalka galvene tad atmet savu virsrakstu.
2. Veidojiet vadības elementus no `@/shared/components` (adapteru) un lietojiet komplekta komponentus pa
   apakšceļu, kur adaptera nav (`Table`/`TableScrollArea`/`DataTableShell`, `Field`, `Alert`, `Tabs`,
   `RadioGroup`, `Slider`…).
3. Ikonas: `<Icon name="…" />`. Jauns nosaukums ievietojams `ICON_MAP` ar semantiski atbilstošu Lucide
   komponentu; `npm run gen:icon-map` uzskaita vēl trūkstošos nosaukumus.
4. Krāsas: semantiskās utilītklases (`text-success`, `bg-warning-bg`, `border-border`…) un
   `var(--color-chart-N)` diagrammu sērijām; nekādas heksadecimālās vērtības un nekādi `dark:` varianti,
   kas tikai atkārto krāsu.
5. Teksts: katra virkne, tostarp etiķetes, ko nododat komplekta komponentiem, nāk no `useTranslations`.
   Jaunas atslēgas nonāk `src/i18n/messages/en.json`, `pt-BR.json` un `vi.json` (vjetnamiešu paritātes
   tests piesprauž katru angļu atslēgu); pārējās lokales aizpilda i18n sinhronizācija.
6. Pirms PR palaidiet aizsargus: `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (vienīgā pārbaude, kas noķer dublētu importu `iconMap.ts` failā),
   `npm run check:ui-icu` un ekrāna paša testus.

## 4. Adaptera pievienošana vai maiņa

1. Saglabājiet `src/shared/components/index.tsx` publisko API nemainīgu: tos pašus eksporta nosaukumus,
   noklusējuma eksportus un pieņemtās īpašības (props). Mantotās īpašības kartējiet uz komplektu adaptera
   iekšpusē (skatiet `Button.tsx`: `VARIANT_TO_KIT`, `SIZE_TO_KIT`).
2. Importējiet komplektu pa apakšceļu (`@omniroute/ui-kit/<component>`).
3. Apvedceļi komplekta trūkumiem atrodas adapterī (vai `globals.css` `@layer components`, ja labojums ir
   stils), nekad `packages/ui-kit/src`.
4. Pievienojiet vai atjauniniet `tests/unit/ui/adapters/<name>.test.tsx`. Adapterim ar daudz izsaucējiem
   salīdziniet atveidoto iezīmējumu pirms un pēc izmaiņas — atkāpju vai iesaiņotāju izmaiņas izplatās uz
   katru ekrānu.

## 5. Komplekta atjaunināšana

`scripts/dev/sync-ui-kit.sh <commit> [clone]` nokopē augšupes `src/` pie attiecīgā komita uz
`packages/ui-kit/src` un piemēro vienīgo atļauto pārveidojumu (tas noņem `.js` sufiksu no relatīvajiem
importiem). Pēc tam: pārskatiet `git diff packages/ui-kit`, vizuāli pārbaudiet pakalpojumu sniedzēju,
iestatījumu, kombināciju, lietojuma un galapunkta ekrānus abās tēmās, palaidiet
`npm run check:ui-kit-snapshot` un `npm run test:vitest:ui` un atveriet PR ar augšupes izmaiņu žurnālu.
