## ഇത് എങ്ങനെ പ്രവർത്തിക്കുന്നു

```
CLI Code's / CLI Agents (ഉപഭോഗ പ്രവാഹം):
Claude / Codex / OpenCode / Cline / KiloCode / Continue / Hermes Agent / Goose / ...
           │
           ▼  (എല്ലാം OmniRoute-ലേക്ക് ചൂണ്ടുന്നു)
    http://YOUR_SERVER:20128/v1
           │
           ▼  (OmniRoute ശരിയായ പ്രൊവൈഡറിലേക്ക് റൂട്ട് ചെയ്യുന്നു)
    Anthropic / OpenAI / Gemini / DeepSeek / Groq / Mistral / ...

ACP Agents (വിപരീത സ്പോൺ പ്രവാഹം):
    ക്ലയന്റ് അഭ്യർത്ഥന → OmniRoute → stdio/ACP വഴി CLI സ്പോൺ ചെയ്യുന്നു → പ്രതികരണം
```

**പ്രയോജനങ്ങൾ:**

- എല്ലാ ടൂളുകളും നിയന്ത്രിക്കാൻ ഒരൊറ്റ API കീ
- ഡാഷ്ബോർഡിൽ എല്ലാ CLI-കളിലെയും ചെലവ് ട്രാക്കുചെയ്യൽ
- ഓരോ ടൂളും വീണ്ടും കോൺഫിഗർ ചെയ്യാതെ മോഡൽ മാറാനുള്ള സൗകര്യം
- ലോക്കലായും റിമോട്ട് സെർവറുകളിലും പ്രവർത്തിക്കുന്നു (VPS, Docker, Akamai, Cloudflare Tunnel)

## `setup-*` ഉപയോഗിച്ച് സ്വയമേ കോൺഫിഗർ ചെയ്യുക

നിങ്ങൾ ഓരോ ഉപകരണത്തിൻ്റെയും കോൺഫിഗറേഷൻ കൈകൊണ്ട് എഴുതേണ്ടതില്ല. പിന്തുണയ്ക്കുന്ന ഓരോ CLI നും OmniRoute ഒരു `setup-*` കമാൻഡ് ഷിപ്പ് ചെയ്യുന്നു, അത് വായിക്കുന്നു** ജീവിക്കുക** പ്രവർത്തിക്കുന്ന OmniRoute ൽ നിന്നുള്ള മോഡൽ കാറ്റലോഗ് (ലോക്കൽ അല്ലെങ്കിൽ റിമോട്ട്) കൂടാതെ നിങ്ങളുടെ മെഷീനിൽ ഉപകരണത്തിൻ്റെ സ്വന്തം കോൺഫിഗറേഷൻ എഴുതുന്നു:

```bash
omniroute setup-codex        omniroute setup-claude       omniroute setup-opencode
omniroute setup-cline        omniroute setup-kilo         omniroute setup-continue
omniroute setup-cursor       omniroute setup-roo          omniroute setup-crush
omniroute setup-goose        omniroute setup-qwen         omniroute setup-aider
omniroute setup-5dive        omniroute setup-zed
omniroute setup-whycodes
```

ഓരോന്നും `--remote <url> --api-key <key>` (ഒരു റിമോട്ട് OmniRoute എതിരായി ഒരു പ്രാദേശിക ഉപകരണം കോൺഫിഗർ ചെയ്യുക), `--dry-run` (എഴുതാതെയുള്ള പ്രിവ്യൂ), `--port` എന്നിവ സ്വീകരിക്കുന്നു. മോഡൽ സ്വയമേവ കണ്ടെത്താത്ത ഉപകരണങ്ങൾ (Cline, കിലോ, റൂ, ഗൂസ്, എയ്ഡർ, Qwen, 5dive, WhyCodes) `--model <id>` (ഇൻ്ററാക്ടീവ് അല്ലാത്ത റണ്ണുകൾക്ക് `--yes` ) എടുക്കുന്നു. `$HOME` കീഴിൽ എഴുതാത്ത ഒരു പാചകക്കുറിപ്പാണ് `setup-5dive` : ഫ്ലീറ്റ് ഹോസ്റ്റിൽ റൂട്ട് ഉടമസ്ഥതയിലുള്ള ഓത്ത് പ്രൊഫൈൽ എഴുതി ഒരു 5dive ഏജൻ്റ് ഫ്ലീറ്റ് കോൺഫിഗർ ചെയ്യുന്നു, അതിനാൽ ഇത് `sudo` വഴി വീണ്ടും പ്രവർത്തിക്കുന്നു, കൂടാതെ സ്വന്തമായി റിമോട്ട് മോഡ് ഇല്ല. വലത് എൻവി ഇൻജക്റ്റ് ചെയ്തതും കോൺഫിഗറൊന്നും എഴുതാത്തതുമായ ഒരു CLI സമാരംഭിക്കുന്നതിന്, ജനറിക് `omniroute run <target>` ലോഞ്ചർ ഉപയോഗിക്കുക (ക്ലോഡ്, കോഡെക്സ്, എയ്ഡർ, ഗൂസ്, ഓപ്പൺകോഡ്, ക്വെൻ, ജെമിനി, വൈകോഡുകൾ - ടാർഗെറ്റുകളും അപരനാമങ്ങളും `bin/cli/cli-manifest.mjs` യിൽ നിന്നാണ് വരുന്നത്); ലെഗസി പെർ ടൂൾ ലോഞ്ചറുകൾ `omniroute launch` (Claude കോഡ്), `omniroute launch-codex` (Codex) എന്നിവ ലഭ്യമാണ്. Gemini CLI ലോഞ്ച്-മാത്രം: ഇത് ഒരു `omniroute run` ടാർഗെറ്റാണ്, പക്ഷേ `setup-*`/`configure` പാചകക്കുറിപ്പ് ഇല്ല.

> **പൂർണ്ണ റഫറൻസ്:** മാസ്റ്റർ ടേബിൾ - ഓരോ കമാൻഡും എന്താണ് എഴുതുന്നത്, ഓരോ ഫ്ലാഗും, ലോക്കൽ vs റിമോട്ട്, ഏത് ടൂളുകൾക്കാണ് `/v1` സഫിക്സ് വേണ്ടത് - ജീവിക്കുന്നത്** [CLI സംയോജനങ്ങൾ](../guides/CLI-INTEGRATIONS.md)** .

### ഒരു കണ്ടെയ്നറിനുള്ളിൽ ഇവ പ്രവർത്തിപ്പിക്കുന്നു

OmniRoute കണ്ടെയ്നറിനുള്ളിൽ നടപ്പിലാക്കിയ ഒരു `setup-*` കമാൻഡ് കണ്ടെയ്നറിൻ്റെ സ്വന്തം വീട്ടിലേക്ക് എഴുതുന്നു, അത് ഒരു ഹോസ്റ്റും CLI വായിക്കുന്നില്ല, അത് കണ്ടെയ്നറിനൊപ്പം അപ്രത്യക്ഷമാകും. OmniRoute അത് കണ്ടെത്തി എഴുതുന്നതിനുപകരം നിർദ്ദേശങ്ങളോടെ `2` നിന്ന് പുറത്തുകടക്കുന്നു. പിന്തുണയ്ക്കുന്ന രണ്ട് വഴികൾ മുന്നോട്ട് - ഹോസ്റ്റിൽ CLI ഇൻസ്റ്റാൾ ചെയ്യുക, കണ്ടെയ്നറിലേക്ക് `omniroute connect` ഇൻസ്റ്റാൾ ചെയ്യുക, അല്ലെങ്കിൽ കോൺഫിഗറേഷൻ dirs ബൈൻഡ്-മൌണ്ട് ചെയ്ത് `CLI_CONFIG_HOME` സജ്ജമാക്കുക ( `host` പ്രൊഫൈൽ കമ്പോസ് ചെയ്യുക). ഓരോ `setup-*` കമാൻഡും, കൂടാതെ `omniroute configure`, `omniroute config set`, കണ്ടെയ്നറിൻ്റെ സ്വന്തം CLIs കോൺഫിഗർ ചെയ്യുമ്പോൾ നിങ്ങൾ യഥാർത്ഥത്തിൽ ഉദ്ദേശിച്ചത് `--allow-container-write` സ്വീകരിക്കുന്നു; `OMNIROUTE_ALLOW_CONTAINER_CONFIG_WRITE=true` സെർവറിനും ഇതുതന്നെ ചെയ്യുന്നു. [Docker ഗൈഡ് കാണുക → ഹോസ്റ്റ് CLI ടൂളുകൾ ക്രമീകരിക്കുന്നു](../guides/DOCKER_GUIDE.md#configuring-host-cli-tools-when-omniroute-runs-in-docker).

ഡാഷ്ബോർഡിൻ്റെ** അന്തിമ പോയിൻ്റ് പ്രയോഗിക്കുക** (`POST /api/cli-tools/apply`) ഒരേ ഗാർഡ് നടപ്പിലാക്കുന്നു: ഒരു കണ്ടെയ്നറിൽ, ഹോസ്റ്റ് ഉത്തരങ്ങളിൽ നിന്ന് ബൈൻഡ്-മൗണ്ട് ചെയ്യാത്ത ടാർഗെറ്റ് എഴുതുക**`422`** `containerEphemeralTarget: true` ഉപയോഗിച്ച്, സുരക്ഷിതമായ പിശക് ടെക്സ്റ്റ് കൂടാതെ - ഒരു ഹോസ്റ്റ് പാചകക്കുറിപ്പുള്ള ഉപകരണങ്ങൾക്ക് (ക്ലോഡ്, കോഡെക്സ്, ഓപ്പൺകോഡ്, ക്ലൈൻ, കിലോ, തുടരുക) - പകരം ഹോസ്റ്റിൽ പ്രവർത്തിപ്പിക്കുന്നതിന് ഒരു `hostSetupCommand` (ഉദാ `omniroute setup-opencode`); ഒന്നും എഴുതിയിട്ടില്ല. `dryRun: true` കണ്ടെയ്നർ മോഡിൽ പ്രവർത്തിക്കുന്നത് തുടരുകയും ഡിസ്കിൽ തൊടാതെ തന്നെ തിരുത്തിയ പ്രിവ്യൂ + ടാർഗെറ്റ് പാത്ത് നൽകുകയും ചെയ്യുന്നു. പ്രിവ്യൂ ഉള്ളടക്കം പകർത്താനോ ഇറക്കുമതി ചെയ്യാനോ ഉള്ള ഒരു ക്രെഡൻഷ്യൽ-ബെയറിംഗ് കോൺഫിഗറേഷനല്ല. ഹോസ്റ്റിൽ യഥാർത്ഥ tool/base URL/API key/model ഇൻപുട്ടുകൾ ഉപയോഗിച്ച് പ്രയോഗിക്കുക, അല്ലെങ്കിൽ സൂചിപ്പിച്ചിരിക്കുന്ന ഹോസ്റ്റ്-സൈഡ് സെറ്റപ്പ് കമാൻഡ് ഉപയോഗിക്കുക. പ്രിവ്യൂ ഹെഡറിനും അഭ്യർത്ഥന കരാറിനുമായി [CLI കോൺഫിഗറേഷൻ സുരക്ഷ](../security/CLI-CONFIGURATION.md) കാണുക. ഈ പെരുമാറ്റം മനപ്പൂർവ്വം, `tests/unit/api/cli-tools/apply-container-guard.test.ts` വഴി റിഗ്രഷൻ-ഗാർഡ് ചെയ്യുന്നു - ഗാർഡ് നീക്കം ചെയ്തുകൊണ്ട് 422 ഒരിക്കലും "പരിഹരിക്കാൻ" പാടില്ല.

ഓരോ എൻട്രിക്കും ഈ ഫീൽഡുകളുണ്ട് (`src/shared/schemas/cliCatalog.ts`-ൽ നിർവചിച്ചിരിക്കുന്നു):

| ഫീൽഡ്                                           | തരം                                                          | വിവരണം                                                                   |
| ----------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------ |
| `category`                                      | `"code" \| "agent"`                                          | ടൂൾ ദൃശ്യമാകുന്ന പേജ്                                                    |
| `vendor`                                        | `string`                                                     | ടൂളിന്റെ ഉറവിടം ("Anthropic", "OSS (P. Gauthier)")                       |

| `baseUrlSupport`                                | `"full" \| "partial" \| "none"`                              | ഇഷ്ടാനുസൃത എൻഡ്പോയിന്റിനുള്ള പിന്തുണയുടെ നില. `"none"` = MITM ബാക്ക്ലോഗ് |
| `configType`                                    | `"env" \| "custom" \| "guide" \| "custom-builder" \| "mitm"` | കോൺഫിഗറേഷൻ സംവിധാനം                                                      |

`baseUrlSupport: "none"` ഉള്ള എൻട്രികൾ ഡാഷ്ബോർഡ് പേജുകളിൽ **കാണിക്കില്ല** — അവ പ്ലാൻ 11-നുള്ള MITM ബാക്ക്ലോഗിൽ രജിസ്റ്റർ ചെയ്തിരിക്കുന്നു (`_tasks/features-v3.8.6/refactorpages/_orchestration/_plan11-mitm-backlog.md` കാണുക).

### ശേഷി തലങ്ങൾ (കാറ്റലോഗ് ചെയ്തത് × കണ്ടെത്താവുന്നത് × കോൺഫിഗർ ചെയ്യാവുന്നത് × പ്രവർത്തിപ്പിക്കാവുന്നത്)

കാറ്റലോഗ് ചെയ്ത എല്ലാ ടൂളുകളും കണ്ടെത്താനോ കോൺഫിഗർ ചെയ്യാനോ പ്രവർത്തിപ്പിക്കാനോ കഴിയണമെന്നില്ല. ഓരോ തലത്തിനും അത് പ്രഖ്യാപിക്കുന്ന ഒരൊറ്റ ഉറവിടമുണ്ട്, കൂടാതെ അവ പരസ്പരം പൊരുത്തപ്പെട്ടിരിക്കുന്നുവെന്ന് ഒരു ഡ്രിഫ്റ്റ് ടെസ്റ്റ് ഉറപ്പാക്കുന്നു:

| തലം                          | അർത്ഥം                                                                                   | പ്രഖ്യാപിച്ചിരിക്കുന്നത്                                          |
| ---------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **കാറ്റലോഗ് ചെയ്തത്**        | ഡാഷ്ബോർഡ് കാറ്റലോഗിൽ ദൃശ്യമാകുന്നു (പേര്, വെൻഡർ, ഡോക്സ്, കോൺഫിഗറേഷൻ തരം)                 | `src/shared/constants/cliTools.ts` (`CLI_TOOLS`)                  |
| **കണ്ടെത്താവുന്നത്**         | ബൈനറി/കോൺഫിഗറേഷൻ കണ്ടെത്തൽ, ഹെൽത്ത് ചെക്കുകൾ, കോൺഫിഗറേഷൻ പാത്തുകൾ                        | `src/shared/services/cliRuntime.ts` (`CLI_TOOLS` റൺടൈം കാറ്റലോഗ്) |
| **കോൺഫിഗർ ചെയ്യാവുന്നത്**    | `omniroute configure <cli>` പിന്തുണയ്ക്കുന്നു (സജ്ജീകരണ റെസിപ്പി നിലവിലുണ്ട്)            | `bin/cli/cli-manifest.mjs` (`configure: true`)                    |
| **പ്രവർത്തിപ്പിക്കാവുന്നത്** | `omniroute run <target>` പിന്തുണയ്ക്കുന്നു (env/ആർഗ്യുമെന്റ് ഇൻജക്ഷൻ നിർവചിച്ചിട്ടുണ്ട്) | `bin/cli/cli-manifest.mjs` (`run: true`)                          |

CLI കമാൻഡ് സർഫേസുകൾക്കുള്ള ആധികാരിക എക്സിക്യൂട്ടബിൾ മാനിഫെസ്റ്റാണ് `bin/cli/cli-manifest.mjs`: `run`, `configure`, ഷെൽ-കംപ്ലീഷൻ ജനറേറ്ററുകൾ എന്നിവയെല്ലാം അവയുടെ ടാർഗറ്റ് ലിസ്റ്റുകൾ, അപരനാമ പരിഹാരം (ഉദാഹരണത്തിന് `kilocode`/`kilo-code`/`kilo_cli` → `kilo`), `--model` ഫ്ലാഗ് വയറിങ് എന്നിവ ഇതിൽനിന്നാണ് നിർണ്ണയിക്കുന്നത്. മാനിഫെസ്റ്റ്, റൺടൈം കാറ്റലോഗ്, UI കാറ്റലോഗ്, എല്ലാ കൺസ്യൂമർ സർഫേസുകളും പരസ്പരം സമന്വയത്തിൽ തുടരുന്നുവെന്ന് ഡ്രിഫ്റ്റ് ഗാർഡായ `tests/unit/cli/cli-manifest-drift.test.ts` ഉറപ്പാക്കുന്നു — മറ്റ് സർഫേസുകളിൽ ചേർക്കാതെ ഒരു സർഫേസിൽ മാത്രം ചേർക്കുന്ന ടാർഗറ്റ് നിശ്ശബ്ദമായി വ്യതിചലിക്കുന്നതിനുപകരം ടെസ്റ്റ് സ്യൂട്ട് പരാജയപ്പെടാൻ കാരണമാകും.

## 5. ബാച്ച് ഡിറ്റക്ഷൻ API

എല്ലാ ടൂൾ ഡിറ്റക്ഷനും ഒരൊറ്റ എൻഡ്പോയിന്റ് വഴി സംയോജിപ്പിച്ചിരിക്കുന്നു:

**`GET /api/cli-tools/all-statuses`**

- ഓതന്റിക്കേഷൻ: `requireCliToolsAuth(request)` (മറ്റ് `/api/cli-tools/` റൂട്ടുകളിലേതിന് സമാനം)
- തിരികെ നൽകുന്നത്: `Record<toolId, ToolBatchStatus>` (ടൈപ്പ്: `src/shared/types/cliBatchStatus.ts`)
- തന്ത്രം: എല്ലാ ടൂളുകളിലും `Promise.all`, ഓരോ ടൂളിനും 5s ടൈംഔട്ട്
- കാഷ്: കോൺഫിഗ് ഫയലിന്റെ `mtime` അനുസരിച്ച് ഇൻഡക്സ് ചെയ്ത ഇൻ-മെമ്മറി LRU. mtime മാറുമ്പോൾ കാഷ് അസാധുവാക്കപ്പെടും. സെർവർ പുനരാരംഭിക്കുമ്പോൾ റീസെറ്റ് ചെയ്യും.

ഓരോ ടൂളിനുമുള്ള റെസ്പോൺസ് ഘടന:

```ts
interface ToolBatchStatus {
  detection: {
    installed: boolean;
    runnable: boolean;
    version?: string;
    command?: string;
    commandPath?: string;
    reason?: string;
  };
  config: {
    status: "configured" | "not_configured" | "not_installed" | "unknown" | "other";
    endpoint?: string | null;
    lastConfiguredAt?: string | null;
  };
  error?: string; // ശുദ്ധീകരിച്ചത്, സ്റ്റാക്ക് ട്രെയ്സുകൾ ഇല്ല
}
```

#### Cline (CLI അല്ലെങ്കിൽ VS Code)

**CLI മോഡ്:**

```bash
mkdir -p ~/.cline/data && cat > ~/.cline/data/globalState.json << EOF
{
  "apiProvider": "openai",
  "openAiBaseUrl": "http://localhost:20128/v1",
  "openAiApiKey": "sk-your-omniroute-key"
}
EOF
```

**VS Code മോഡ്:**
Cline എക്സ്റ്റെൻഷൻ ക്രമീകരണങ്ങൾ → API Provider: `OpenAI Compatible` → Base URL: `http://localhost:20128/v1`

അല്ലെങ്കിൽ OmniRoute ഡാഷ്ബോർഡ് ഉപയോഗിക്കുക → **CLI ടൂളുകൾ → Cline → കോൺഫിഗ് പ്രയോഗിക്കുക**.

അല്ലെങ്കിൽ OmniRoute ഡാഷ്ബോർഡ് ഉപയോഗിക്കുക → **CLI ടൂളുകൾ → KiloCode → കോൺഫിഗ് പ്രയോഗിക്കുക**.

#### VS Code Insiders (`chatLanguageModels.json`)

കസ്റ്റം എൻഡ്പോയിന്റ് മോഡലുകൾക്കായി VS Code Insiders കോൺഫിഗർ ചെയ്തിരിക്കുമ്പോഴും, ഒരു കസ്റ്റം ഹെഡർ ഫീൽഡ് ഇല്ലാതെ OmniRoute പ്രവർത്തിക്കണമെന്ന് നിങ്ങൾ ആഗ്രഹിക്കുമ്പോഴും ഇത് ഉപയോഗിക്കുക.

**ശുപാർശ ചെയ്യുന്ന സ്ഥാനം:**

- Linux: `~/.config/Code - Insiders/User/chatLanguageModels.json`
- Windows: `%APPDATA%/Code - Insiders/User/chatLanguageModels.json`

**ടോക്കൺ ഉൾപ്പെടുത്തിയ OmniRoute അപരനാമം ഉപയോഗിച്ചുള്ള ഉദാഹരണം:**

```json
[
  {
    "vendor": "customendpoint",
    "id": "auto",
    "name": "OmniRoute Auto",
    "family": "gpt-4",
    "version": "1.0.0",
    "url": "http://localhost:20128/api/v1/vscode/sk-your-omniroute-key/chat/completions",
    "modelsUrl": "http://localhost:20128/api/v1/vscode/sk-your-omniroute-key/models",
    "requestFormat": "openai-chat-completions",
    "contextWindow": 256000,
    "maxOutputTokens": 32768,
    "auth": {
      "type": "none"
    }
  }
]
```

**കുറിപ്പുകൾ:**

- `sk-your-omniroute-key` എന്നത് OmniRoute-ൽ സൃഷ്ടിച്ച ഒരു API കീ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുക.
- `url` ഫീൽഡ് `/api/v1/vscode/{token}/chat/completions` എന്നതിലേക്ക് ചൂണ്ടണം.
- `modelsUrl` ഫീൽഡ് `/api/v1/vscode/{token}/models` എന്നതിലേക്ക് ചൂണ്ടണം.
- ക്ലയന്റ് ഇഷ്ടാനുസൃത ഹെഡറുകൾ പിന്തുണയ്ക്കുമ്പോൾ സാധാരണ `/v1` + Bearer ഹെഡർ പ്രവാഹത്തിന് മുൻഗണന നൽകുക.
- URL-ൽ ഉൾപ്പെടുത്തിയ ടോക്കണുകൾ അനുയോജ്യതയ്ക്കായുള്ള ഒരു പകരം മാർഗമാണ്; അവ എഡിറ്റർ ലോഗുകളിലോ പ്രോക്സി ചരിത്രത്തിലോ ദൃശ്യമായേക്കാം.

## 10. ആന്തരിക OmniRoute CLI

സെർവർ ലൈഫ്സൈക്കിൾ, സജ്ജീകരണം, ഡയഗ്നോസ്റ്റിക്സ്, ദാതാവ് മാനേജ്മെന്റ് എന്നിവയ്ക്കുള്ള കമാൻഡുകൾ `omniroute` ബൈനറി നൽകുന്നു. എൻട്രി പോയിന്റ്: `bin/omniroute.mjs`.

```bash
omniroute                              # സെർവർ ആരംഭിക്കുക (ഡിഫോൾട്ട് പോർട്ട് 20128)
omniroute setup                        # ഇന്ററാക്ടീവ് സജ്ജീകരണ വിസാർഡ്
omniroute doctor                       # കോൺഫിഗറേഷൻ, DB, പോർട്ടുകൾ, റൺടൈം എന്നിവ പരിശോധിക്കുക
omniroute providers list               # കോൺഫിഗർ ചെയ്ത ദാതാവ് കണക്ഷനുകൾ
omniroute providers test-all           # സജീവമായ എല്ലാ കണക്ഷനുകളും പരിശോധിക്കുക
omniroute reset-password               # അഡ്മിൻ പാസ്വേഡ് പുനഃസജ്ജമാക്കുക
omniroute logs                         # അഭ്യർത്ഥനാ ലോഗുകൾ സ്ട്രീം ചെയ്യുക
omniroute health                       # വിശദമായ ആരോഗ്യനില (ബ്രേക്കറുകൾ, കാഷെ, മെമ്മറി)
omniroute --version                    # പതിപ്പ് പ്രിന്റ് ചെയ്യുക
omniroute --help                       # എല്ലാ കമാൻഡുകളും കാണിക്കുക
```

### സജ്ജീകരണവും ആരംഭിക്കലും

```bash
omniroute setup                        # ഇന്ററാക്ടീവ് സജ്ജീകരണ വിസാർഡ്
omniroute setup --non-interactive      # CI/ഓട്ടോമേഷൻ മോഡ് (env വേരിയബിളുകളും ഫ്ലാഗുകളും വായിക്കുന്നു)
omniroute setup --password '<value>'   # അഡ്മിൻ പാസ്വേഡ് നേരിട്ട് സജ്ജമാക്കുക
omniroute setup --add-provider \
  --provider openai \
  --api-key '<value>' \
  --test-provider                      # ഒറ്റ ഘട്ടത്തിൽ ഒരു ദാതാവിനെ ചേർത്ത് പരിശോധിക്കുക
```

നോൺ-ഇന്ററാക്ടീവ് സജ്ജീകരണത്തിനായി തിരിച്ചറിയുന്ന എൻവയോൺമെന്റ് വേരിയബിളുകൾ:

| വേരിയബിൾ            | ഉദ്ദേശ്യം                                                                    |
| ------------------- | ---------------------------------------------------------------------------- |
| `OMNIROUTE_API_KEY` | ദാതാവിന്റെ API കീ (Commander `.env()` വഴി `--api-key`-യുമായി ബന്ധിപ്പിച്ചത്) |
| `DATA_DIR`          | OmniRoute ഡാറ്റ ഡയറക്ടറി അസാധുവാക്കി മറ്റൊന്ന് ഉപയോഗിക്കുക                   |

മറ്റെല്ലാ നോൺ-ഇന്ററാക്ടീവ് ഇൻപുട്ടുകളും എൻവയോൺമെന്റ് വേരിയബിളുകളായല്ല, ഫ്ലാഗുകളായാണ് നൽകുന്നത്:
`--password`, `--provider`, `--provider-name`, `--provider-base-url`, `--default-model`
(മുകളിലുള്ള `omniroute setup` ഓപ്ഷനുകൾ കാണുക).

### ഡയഗ്നോസ്റ്റിക്സ്

```bash
omniroute doctor                       # കോൺഫിഗറേഷൻ, DB, പോർട്ടുകൾ, റൺടൈം, മെമ്മറി, ലൈവ്നെസ് എന്നിവ പരിശോധിക്കുക
omniroute doctor --json                # മെഷീൻ വായിക്കാവുന്ന JSON
omniroute doctor --no-liveness         # HTTP ആരോഗ്യനില പ്രോബ് ഒഴിവാക്കുക
omniroute doctor --host 0.0.0.0        # ലൈവ്നെസ് ഹോസ്റ്റ് അസാധുവാക്കി മറ്റൊന്ന് ഉപയോഗിക്കുക
omniroute doctor --liveness-url <url>  # പൂർണ്ണ ആരോഗ്യനില എൻഡ്പോയിന്റ് URL അസാധുവാക്കി മറ്റൊന്ന് ഉപയോഗിക്കുക
```

doctor ഇനിപ്പറയുന്ന പരിശോധനകൾ നടത്തുന്നു: `Config`, `Database`, `Storage/encryption`,
`Port availability`, `Node runtime`, `Native binary` (better-sqlite3),
`Memory`, `Server liveness`. ഏതെങ്കിലും പരിശോധന `fail` ആണെങ്കിൽ ഇത് പൂജ്യമല്ലാത്ത എക്സിറ്റ് കോഡോടെ അവസാനിക്കും.

### ദാതാവ് മാനേജ്മെന്റ്

```bash
omniroute providers available                       # OmniRoute ദാതാവ് കാറ്റലോഗ്
omniroute providers available --search openai       # id/name/alias/category അനുസരിച്ച് കാറ്റലോഗ് ഫിൽട്ടർ ചെയ്യുക
omniroute providers available --category api-key    # വിഭാഗമനുസരിച്ച് ഫിൽട്ടർ ചെയ്യുക (api-key, oauth, free, ...)
omniroute providers available --json                # മെഷീൻ വായിക്കാവുന്ന JSON

omniroute providers list                            # കോൺഫിഗർ ചെയ്ത ദാതാവ് കണക്ഷനുകൾ
omniroute providers list --json

omniroute providers test <id|name>                  # കോൺഫിഗർ ചെയ്ത ഒരു കണക്ഷൻ പരിശോധിക്കുക
omniroute providers test-all                        # സജീവമായ എല്ലാ കണക്ഷനുകളും പരിശോധിക്കുക
omniroute providers validate                        # ലോക്കൽ മാത്രമുള്ള ഘടനാപരമായ സാധൂകരണം
omniroute providers add <provider> --credential-env PROVIDER_KEY
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth <provider>                 # നിലവിലുള്ള OAuth ഫ്ലോ
omniroute providers edit <id|name> --default-model <model>
omniroute providers remove <id|name> --yes
```

`providers add/import/auth/edit/remove` API-പ്രഥമമായതിനാൽ സജീവമായ
ലോക്കൽ അല്ലെങ്കിൽ റിമോട്ട് കോൺടെക്സ്റ്റിൽ പ്രവർത്തിക്കുന്നു. ക്രെഡൻഷ്യൽ ഇൻപുട്ടിനായി
`--credential-stdin` അല്ലെങ്കിൽ `--credential-env` ഉപയോഗിക്കണം; `--dry-run --json`
റെഡാക്റ്റ് ചെയ്ത സാന്നിധ്യം/ഘടന മാത്രമേ റിപ്പോർട്ട് ചെയ്യൂ. `providers available` OmniRoute കാറ്റലോഗ് വായിക്കുന്നു;
`providers list/test/test-all/validate` അവയുടെ ലോക്കൽ SQLite പ്രവർത്തനരീതി നിലനിർത്തുകയും
സെർവർ പ്രവർത്തിച്ചുകൊണ്ടിരിക്കണമെന്ന് ആവശ്യപ്പെടാതിരിക്കുകയും ചെയ്യുന്നു.

ഇഷ്ടാനുസൃതമായ OpenAI-അനുയോജ്യ അല്ലെങ്കിൽ Anthropic-അനുയോജ്യ നോഡിനായി,
`omniroute nodes add` നൽകുന്ന നോഡ് ID-യിലേക്ക് `omniroute keys add "$NODE_ID" --stdin` ഉപയോഗിച്ച് ക്രെഡൻഷ്യലുകൾ ചേർക്കുക.
ഇതിന് പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന സെർവറും സജീവ കോൺടെക്സ്റ്റിനുള്ള മാനേജ്മെന്റ് ഓതന്റിക്കേഷനും ആവശ്യമാണ്.
CLI `POST /api/providers` ഉപയോഗിക്കുന്നു; ഇത് നോഡ് സാധൂകരിക്കുകയും അതിന്റെ എൻഡ്പോയിന്റ്
ക്രമീകരണങ്ങൾ കണക്ഷനിലേക്ക് പകർത്തുകയും ചെയ്യുന്നു. നോഡ് ലഭ്യമല്ലാത്തത്, ഓതറൈസേഷൻ പരാജയം, അല്ലെങ്കിൽ സെർവർ
ലഭ്യമല്ലാത്തത് എന്നിവയുണ്ടെങ്കിൽ ലോക്കൽ ഫാൾബാക്ക് ക്രെഡൻഷ്യൽ സൃഷ്ടിക്കാതെ ഒരു പിശക് തിരികെ നൽകും.

`nodes add --base-url` നോഡ് എൻഡ്പോയിന്റ് സജ്ജമാക്കുന്നു; ഇത്
`OMNIROUTE_BASE_URL`-ലെ സെർവർ വിലാസത്തിൽ നിന്ന് വ്യത്യസ്തമാണ്. OpenAPI ഫയലുകൾക്കായി,
`omniroute openapi dump --format json --out ./openapi.json` ഉപയോഗിക്കുക; ആഗോള `--output`
ഒരു ലക്ഷ്യസ്ഥാന ഫയൽനാമമല്ല, CLI പ്രദർശന ഫോർമാറ്റിങ്ങാണ് തിരഞ്ഞെടുക്കുന്നത്.

### വീണ്ടെടുക്കലും പുനഃസജ്ജീകരണവും

```bash
omniroute reset-password                # അഡ്മിൻ പാസ്വേഡ് പുനഃസജ്ജമാക്കുക (ഇതും ഉപയോഗിക്കാം: omniroute-reset-password)
omniroute reset-encrypted-columns       # എൻക്രിപ്റ്റ് ചെയ്ത ക്രെഡൻഷ്യൽ പുനഃസജ്ജീകരണത്തിനുള്ള മുന്നറിയിപ്പും ഡ്രൈ-റണ്ണും കാണിക്കുക
omniroute reset-encrypted-columns --force  # SQLite-ലെ എൻക്രിപ്റ്റ് ചെയ്ത ക്രെഡൻഷ്യലുകൾ യഥാർത്ഥത്തിൽ null ആക്കുക
```

### ക്രെഡൻഷ്യൽ എക്സ്പോർട്ട് (⚠ ശ്രദ്ധയോടെ കൈകാര്യം ചെയ്യുക)

```bash
omniroute auth export                                 # മുന്നറിയിപ്പും സ്ഥിരീകരണ ഘട്ടവും കാണിക്കുക — DB ആക്സസ് ഇല്ല
omniroute auth export --force                          # എല്ലാ കണക്ഷനുകളുടെയും ഡീക്രിപ്റ്റ് ചെയ്ത ക്രെഡൻഷ്യലുകൾ JSON ആയി stdout-ലേക്ക് എക്സ്പോർട്ട് ചെയ്യുക
omniroute auth export --force --id <id>                 # പൊരുത്തപ്പെടുന്ന കണക്ഷൻ മാത്രം എക്സ്പോർട്ട് ചെയ്യുക
omniroute auth export --force --format env               # OMNIROUTE_<PROVIDER>_<FIELD>=<value> വരികൾ ഔട്ട്പുട്ട് ചെയ്യുക
omniroute auth export --force --out creds.json           # ഒരു ഫയലിലേക്ക് എഴുതുക (0600 അനുമതികളോടെ സൃഷ്ടിക്കും)
```

`auth export` **ലോക്കൽ-മാത്രമാണ്** (നേരിട്ടുള്ള SQLite റീഡ്, HTTP റൂട്ട് ഇല്ല), കൂടാതെ ഇത് മനഃപൂർവം
**പ്ലെയിൻടെക്സ്റ്റ്** `apiKey`/`accessToken`/`refreshToken`/`idToken` മൂല്യങ്ങൾ പ്രിന്റ് ചെയ്യുന്നു/എഴുതുന്നു — അത് ഒരു സവിശേഷതയാണ്,
ബഗ് അല്ല. `--force` ഇല്ലാതെ ഡാറ്റാബേസിൽ നിന്ന് ഒന്നും വായിക്കുകയോ ഡീക്രിപ്റ്റ് ചെയ്യുകയോ ഇല്ല. ഏതെങ്കിലും പ്ലെയിൻടെക്സ്റ്റ് പുറത്തുവിടുന്നതിന് മുമ്പ് stderr-ൽ
ഒരു മുന്നറിയിപ്പ് ബാനർ എല്ലായ്പ്പോഴും പ്രിന്റ് ചെയ്യും. `STORAGE_ENCRYPTION_KEY` സജ്ജമാക്കിയിരിക്കണം.
ഡീക്രിപ്റ്റ് ചെയ്യുന്നതിൽ പരാജയപ്പെടുന്ന ഒരു ഫീൽഡ് (കാലഹരണപ്പെട്ട കീ, കേടായ സൈഫർടെക്സ്റ്റ്), മുഴുവൻ എക്സ്പോർട്ടും നിർത്തുകയോ അടിസ്ഥാനത്തിലുള്ള പിശക് വെളിപ്പെടുത്തുകയോ ചെയ്യുന്നതിന് പകരം
`<field>DecryptFailed: true` എന്ന് റിപ്പോർട്ട് ചെയ്യും.

### മറ്റ് ഉപകമാൻഡുകൾ

മറ്റുവിധത്തിൽ സൂചിപ്പിച്ചിട്ടില്ലെങ്കിൽ, പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന ഒരു OmniRoute സെർവർ ഉണ്ടെന്ന് ഇവ അനുമാനിക്കുന്നു:

```bash
omniroute status                       # സമഗ്രമായ റൺടൈം നില
omniroute logs                         # അഭ്യർത്ഥനാ ലോഗുകൾ സ്ട്രീം ചെയ്യുക (--json, --search, --follow)
omniroute config list                  # കോൺഫിഗർ ചെയ്ത CLI ടൂളുകൾ പ്രദർശിപ്പിക്കുക

omniroute provider list                # ലഭ്യമായ പ്രൊവൈഡറുകളെ പട്ടികപ്പെടുത്തുക (providers list-ന്റെ അപരനാമം)
omniroute provider add                 # ഒരു ടൂളിൽ OmniRoute-നെ പ്രൊവൈഡറായി രജിസ്റ്റർ ചെയ്യുക
omniroute keys add | list | remove     # API കീകൾ നിയന്ത്രിക്കുക
omniroute models [provider]            # മോഡലുകളെ പട്ടികപ്പെടുത്തുക (--json, --search)
omniroute combo list | switch | create | delete

omniroute backup                       # കോൺഫിഗറേഷന്റെയും DB-യുടെയും സ്നാപ്പ്ഷോട്ട് എടുക്കുക
omniroute restore                      # മുമ്പത്തെ ഒരു സ്നാപ്പ്ഷോട്ടിൽ നിന്ന് പുനഃസ്ഥാപിക്കുക

omniroute health                       # വിശദമായ ആരോഗ്യനില (ബ്രേക്കറുകൾ, കാഷ്, മെമ്മറി)
omniroute quota                        # പ്രൊവൈഡർ ക്വോട്ട ഉപയോഗം
omniroute cache                        # കാഷ് നില
omniroute cache clear                  # സെമാന്റിക് + സിഗ്നേച്ചർ കാഷുകൾ മായ്ക്കുക

omniroute mcp status | restart         # MCP സെർവർ നില / പുനരാരംഭിക്കൽ
omniroute a2a status | card            # A2A സെർവർ നില / ഏജന്റ് കാർഡ്

omniroute tunnel list | create | stop  # ടണലുകൾ നിയന്ത്രിക്കുക (cloudflare/tailscale/ngrok)
omniroute env show | get <k> | set <k> <v>  # എൻവയോൺമെന്റ് വേരിയബിളുകൾ പരിശോധിക്കുക / സജ്ജമാക്കുക (താൽക്കാലികം)

omniroute test                         # പ്രൊവൈഡർ കണക്റ്റിവിറ്റി സ്മോക്ക് ടെസ്റ്റ്
omniroute update                       # അപ്ഡേറ്റുകൾ പരിശോധിക്കുക
omniroute completion                   # ഷെൽ കംപ്ലീഷൻ സൃഷ്ടിക്കുക
```

## OmniRoute CLI ഉപയോഗിച്ച് inference-key നയം നിയന്ത്രിക്കുക

നിലവിലുള്ള ഒരു inference key അതിന്റെ ID ഉപയോഗിച്ച് പരിശോധിക്കാനോ അപ്ഡേറ്റ് ചെയ്യാനോ പ്രാമാണീകരിച്ച മാനേജ്മെന്റ് കോൺടെക്സ്റ്റ് ഉപയോഗിക്കുക ([Remote Mode](../guides/REMOTE-MODE.md) കാണുക):

```bash
omniroute --output json keys policy show KEY_ID
omniroute keys policy set KEY_ID --unrestricted
omniroute --output json keys policy show KEY_ID
```

`--unrestricted` എന്നത് `--model-access-mode all` എന്നതിന്റെ ഒരു അപരനാമമാണ്. ഈ അപ്ഡേറ്റ്
മോഡൽ അനുവദനീയ പട്ടിക മായ്ക്കുന്നു. ഇത് സ്കോപ്പുകൾ, കണക്ഷൻ നിയമങ്ങൾ, ബ്ലോക്ക് ചെയ്ത മോഡലുകൾ, നിരക്ക് പരിധികൾ,
ചെലവ് പരിധികൾ എന്നിവ നിലനിർത്തുന്നതിനാൽ, ആ മറ്റ് നിയന്ത്രണങ്ങൾക്ക് തുടർന്നും ഒരു അഭ്യർത്ഥന നിരസിക്കാനാകും. വ്യക്തമായി
നൽകുന്ന `--allowed-models ""`-ഉം `all` തിരഞ്ഞെടുക്കുന്നു; അനുവദനീയമായ മോഡലുകളൊന്നുമില്ലാത്ത നിയന്ത്രിത കീ നിലനിർത്താൻ
അത് `--model-access-mode restricted`-നൊപ്പം ചേർത്ത് ഉപയോഗിക്കുക.
ശൂന്യമല്ലാത്ത, കോമ ഉപയോഗിച്ച് വേർതിരിച്ച പട്ടിക, വ്യക്തമായി മറ്റൊന്ന് നൽകിയിട്ടില്ലെങ്കിൽ `restricted` തിരഞ്ഞെടുക്കുന്നു.
പരസ്പരവിരുദ്ധമായ `all`-ഉം ശൂന്യമല്ലാത്ത അനുവദനീയ പട്ടികയും ഒരുമിച്ച് നൽകിയാൽ അഭ്യർത്ഥന അയയ്ക്കുന്നതിന് മുമ്പ് നിരസിക്കപ്പെടും.

`--rate-limit 30` മിനിറ്റിലെ അഭ്യർത്ഥനകളുടെ എണ്ണം സജ്ജമാക്കുകയും മറ്റ് സമയ
വിൻഡോകൾക്കുള്ള നിയമങ്ങൾ നിലനിർത്തുകയും ചെയ്യുന്നു. `--max-cost 5` പ്രതിവാര പരിധിയിൽ മാറ്റം വരുത്താതെ പ്രതിദിന USD പരിധി പ്രവർത്തനക്ഷമമാക്കുന്നു;
`--max-cost 0` പ്രതിദിന പരിധി നീക്കം ചെയ്യുകയും നിലവിലുള്ള ഉപയോഗ-പരിധി ടോഗിളും
പ്രതിവാര പരിധിയും നിലനിർത്തുകയും ചെയ്യുന്നു. ഒഴിവാക്കിയ നയ ഫീൽഡുകൾ മാറ്റമില്ലാതെ തുടരും. നിരക്കിലെ മാറ്റങ്ങൾ ആദ്യം
നിലവിലെ നയം വായിക്കുന്നു; ഒരേ കീയുടെ rate-limit അറേയിൽ ഒരേസമയം തിരുത്തലുകൾ നടത്തുന്നത് ഒഴിവാക്കുക.

നയ കമാൻഡുകൾ പ്രാമാണീകരിച്ച `GET`/`PATCH /api/keys/{id}` ഉപയോഗിക്കുകയും സജീവമായ
കോൺടെക്സ്റ്റും ഗ്ലോബൽ `--api-key` ഓപ്ഷനും മാനിക്കുകയും ചെയ്യുന്നു. JSON ഔട്ട്പുട്ടിൽ നയ ഫീൽഡുകൾ മാത്രമേ ഉണ്ടാകൂ;
സംഭരിച്ച കീ അല്ലെങ്കിൽ അതിന്റെ മാസ്ക് ചെയ്ത രൂപം അതിൽ ഉൾപ്പെടില്ല. inference-ന് മാത്രമുള്ള ക്രെഡൻഷ്യലിന്
മാനേജ്മെന്റ് മാറ്റങ്ങൾക്ക് അംഗീകാരം നൽകാനാവില്ല. 401/403 ലഭിച്ചാൽ മാനേജ്മെന്റ്
ക്രെഡൻഷ്യലും കോൺടെക്സ്റ്റും പരിശോധിക്കേണ്ടതുണ്ട്; അത് ലോക്കൽ CLI-token അല്ലെങ്കിൽ salt പരാജയം സ്ഥിരീകരിക്കുന്നില്ല.
പ്രത്യേക ലോക്കൽ പ്രാമാണീകരണ കരാറിനായി [CLI Token](../security/CLI_TOKEN.md) കാണുക.
