> OmniRoute-ൻ്റെ സ്വഭാവം **പുനർവിന്യാസം കൂടാതെ** മാറ്റുന്ന റൺടൈം ടോഗിളുകൾ.
> ഇവിടെ ലിസ്റ്റ് ചെയ്തിട്ടുള്ള എല്ലാ ഫ്ലാഗുകളും
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> എന്ന ഫയലിൽ നിർവചിച്ചിരിക്കുന്നു — ഇത് വിവരങ്ങളുടെ ഏക ഉറവിടമാണ്. ഡാഷ്ബോർഡും REST API-യും ഈ ഫയലിൽ നിന്നാണ് വായിക്കുന്നത്, അതിനാൽ താഴെയുള്ള പട്ടിക 1:1 എന്ന രീതിയിൽ അതിനോട് യോജിപ്പിച്ച് ജനറേറ്റ് ചെയ്തിരിക്കുന്നു.

## ഫീച്ചർ ഫ്ലാഗുകൾ എന്തൊക്കെയാണ്

ഒരു ഫീച്ചർ ഫ്ലാഗ് എന്നത് പേരുള്ള ഒരു ടോഗിൾ (ബൂളിയൻ അല്ലെങ്കിൽ എനം) ആണ്, അതിൻ്റെ മൂല്യം റൺടൈമിൽ മാറ്റാനും ഡാറ്റാബേസിൽ നിലനിർത്താനും കഴിയും, ഇതിന് പ്രോസസ്സ് പുനർവിന്യാസം ആവശ്യമില്ല. ഓരോ ഫ്ലാഗും ഒരു `FeatureFlagDefinition` ഉപയോഗിച്ച് വിവരിക്കുന്നു, അതിന് ഒരു `key`, `label`, `description`, `category`, `defaultValue`, `type`, കൂടാതെ ഒരു `requiresRestart` സൂചനയും ഉണ്ട്.

### റെസല്യൂഷൻ ഓർഡർ

ഒരു ഫ്ലാഗിൻ്റെ **ഫലപ്രദമായ മൂല്യം** [`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ഉപയോഗിച്ച് ഈ മുൻഗണനയോടെ (ഏറ്റവും ഉയർന്നത് വിജയിക്കുന്നു) പരിഹരിക്കുന്നു:

1. **DB ഓവർറൈഡ്** — `key_value` പട്ടികയിൽ `feature_flags` നെയിംസ്പേസിന് കീഴിൽ സംഭരിച്ചിരിക്കുന്ന ഒരു മൂല്യം (ഡാഷ്ബോർഡ് വഴിയോ REST API വഴിയോ സജ്ജീകരിച്ചിരിക്കുന്നു).
2. **പരിസ്ഥിതി വേരിയബിൾ** — `process.env[<KEY>]`, സജ്ജീകരിച്ചിട്ടുണ്ടെങ്കിൽ, ശൂന്യമല്ലെങ്കിൽ.
3. **നിർവചന ഡിഫോൾട്ട്** — `featureFlagDefinitions.ts`-ൽ നിന്നുള്ള `defaultValue`.

ഒരു ബൂളിയൻ ഫ്ലാഗ് **പ്രവർത്തനക്ഷമമാക്കിയിരിക്കുന്നു** എന്ന് കണക്കാക്കുന്നത് അതിൻ്റെ ഫലപ്രദമായ മൂല്യം `"true"`, `"1"`, അല്ലെങ്കിൽ `"yes"` ( `isFeatureFlagEnabled()` കാണുക) ആയിരിക്കുമ്പോഴാണ്.

> [!NOTE]
> മിക്ക ഫ്ലാഗുകൾക്കും [`ENVIRONMENT.md`](./ENVIRONMENT.md) എന്നതിൽ രേഖപ്പെടുത്തിയിട്ടുള്ള **അതേ പേരിൽ** ഒരു അനുയോജ്യമായ പരിസ്ഥിതി വേരിയബിളും ഉണ്ട്. ഫ്ലാഗിൻ്റെ DB ഓവർറൈഡ് ആ പരിസ്ഥിതി വേരിയബിളിന് മുൻഗണന നൽകുന്നു. `requiresRestart: true` ഉള്ള ഒരു ഫ്ലാഗ് ഉടനടി നിലനിർത്തുന്നു, പക്ഷേ പ്രോസസ്സ് ആരംഭിക്കുമ്പോൾ മാത്രമേ വീണ്ടും വായിക്കുകയുള്ളൂ — ഇത് ടോഗിൾ ചെയ്യുന്നത് ഡാഷ്ബോർഡിൽ ഒരു **"സെർവർ പുനരാരംഭിക്കുക"** ബാനർ കാണിക്കുന്നു.

## ഫ്ലാഗ് കാറ്റലോഗ്

| `CREDENTIAL_GATE_AUTH_DIAGNOSES_ONLY`     | boolean | `false`     | കാഷ് ചെയ്ത പരാജയപ്പെട്ട ക്രെഡൻഷ്യൽ പരിശോധനയുടെ രോഗനിർണയം മോശം ക്രെഡൻഷ്യലുകൾ തെളിയിക്കുമ്പോൾ മാത്രം ഒരു കണക്ഷനെ തടയുന്ന തരത്തിൽ കോംബോ ക്രെഡൻഷ്യൽ ഗേറ്റ് പരിമിതപ്പെടുത്തുക (`upstream_auth_error`, `auth_missing`, `token_expired`, `token_refresh_failed`, `reauth_required`, `account_deactivated`, `auth_required`). ട്രാൻസ്പോർട്ട് രോഗനിർണയങ്ങൾ (`network_error`, `upstream_unavailable`, `upstream_rate_limited`) എല്ലായ്പ്പോഴും അനിശ്ചിതമായി തുടരും, ഈ ഫ്ലാഗ് ഓഫ് ആയിരിക്കുമ്പോഴും ഡിസ്പാച്ച് തടയില്ല. പ്രവർത്തനക്ഷമമാക്കിയാൽ, മറ്റ് അനിശ്ചിത രോഗനിർണയങ്ങളും (അവ്യക്തമായ പിശകുകൾ, പിന്തുണയ്ക്കാത്ത പരിശോധനകൾ, ടൈപ്പ് നൽകിയിട്ടില്ലാത്ത ഷെഡ്യൂളർ പിശകുകൾ) അജ്ഞാതമായി കണക്കാക്കുകയും ട്രാഫിക് അനുവദിക്കുകയും ചെയ്യും. ഡീഫോൾട്ടായി ഓഫ്: മറ്റ് കാഷ് ചെയ്ത പരിശോധനാ പിശകുകൾ കാഷെ TTL (5 മിനിറ്റ്) കാലയളവിൽ ഡിസ്പാച്ച് തടയും. |

> [!NOTE]
> `INPUT_SANITIZER_BLOCK_THRESHOLD` ഉം അതിന്റെ ലെഗസി അപരനാമമായ
> `INJECTION_GUARD_BLOCK_THRESHOLD` ഉം `INJECTION_GUARD_MODE`-ന്റെ
> `block` മോഡ് ക്രമീകരിക്കുന്നു, എന്നാൽ അവ ഫീച്ചർ ഫ്ലാഗുകളല്ല, സാധാരണ പരിസ്ഥിതി വേരിയബിളുകളാണ്
> [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts)-ൽ നിന്ന് വായിക്കുന്നത്:
> അവയ്ക്ക് DB ഓവർറൈഡോ ഡാഷ്ബോർഡ് ടോഗിളോ ഇല്ല. [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication) കാണുക.

> [!NOTE]
> `Restart` കോളം `requiresRestart: true` ഉള്ള ഫ്ലാഗുകളെ അടയാളപ്പെടുത്തുന്നു — മൂല്യം
> ഉടൻ തന്നെ സംരക്ഷിക്കപ്പെടും, എന്നാൽ പ്രോസസ് റീലോഡ് ചെയ്തതിന് ശേഷമേ പ്രാബല്യത്തിൽ വരൂ. Enum
> ഫ്ലാഗുകൾ അവയ്ക്ക് അനുവദിച്ച സെറ്റിന് പുറത്തുള്ള ഏത് മൂല്യവും നിരസിക്കും (സെർവർ-സൈഡിൽ
> `setFeatureFlagOverride()`-ലും REST `PUT` ഹാൻഡ്ലറിലും സാധൂകരിക്കുന്നു).

## ഫ്ലാഗുകൾ ടോഗിൾ ചെയ്യൽ

### ഡാഷ്ബോർഡ്

**Dashboard → Settings → Feature Flags**
(`/dashboard/settings/feature-flags`) എന്നതിലേക്ക് നാവിഗേറ്റ് ചെയ്യുക. ഗ്രിഡ്
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
ഇനിപ്പറയുന്നവ പിന്തുണയ്ക്കുന്നു:

- കീ അല്ലെങ്കിൽ വിവരണം ഉപയോഗിച്ചുള്ള **തിരയൽ**, വിഭാഗം അനുസരിച്ചുള്ള **ഫിൽട്ടർ** (കൂടാതെ സിന്തറ്റിക് **Requires Restart** കാഴ്ചയും).
- ബൂളിയൻ ഫ്ലാഗുകൾക്കുള്ള **ടോഗിൾ**, enum ഫ്ലാഗുകൾക്കുള്ള **ഡ്രോപ്പ്ഡൗൺ**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- ഓരോ ഫ്ലാഗിനും ഒരു **source badge** — `DB`, `ENV`, അല്ലെങ്കിൽ `DEF` — ഫലപ്രദമായ മൂല്യം എവിടെ നിന്നാണ് വന്നതെന്ന് കാണിക്കുന്നു.
- ഓവർറൈഡ് നീക്കം ചെയ്യാനുള്ള **Reset** ബട്ടൺ (`DB`-സ്രോതസ്സുള്ള ഫ്ലാഗുകൾക്ക് മാത്രമേ കാണിക്കൂ), കൂടാതെ താഴെ ഒരു **Reset All Overrides** ബട്ടണും.
- `requiresRestart` ഫ്ലാഗ് മാറ്റുമ്പോൾ ഒരു **Restart Server** ബാനർ.

### REST API

എല്ലാ പ്രവർത്തനങ്ങളും ഒരൊറ്റ റൂട്ടിലൂടെ നടക്കുന്നു:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
ഓരോ രീതിക്കും ഒരു authenticated dashboard session ആവശ്യമാണ് (അല്ലെങ്കിൽ `401`).

#### `GET /api/settings/feature-flags`

ഓരോ ഫ്ലാഗിന്റെയും ഫലപ്രദമായ മൂല്യം, സ്രോതസ്സ്, ഒരു സംഗ്രഹം എന്നിവ തിരികെ നൽകുന്നു.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... എല്ലാ 114 ഫ്ലാഗുകളും
  ],
  "summary": {
    "total": 114,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ഒരു ഓവർറൈഡ് സജ്ജമാക്കുകയോ നീക്കം ചെയ്യുകയോ ചെയ്യുക. ബോഡി: `{ key: string; value?: string }`.
`value` ഒഴിവാക്കിയാൽ ഓവർറൈഡ് നീക്കം ചെയ്യപ്പെടും (env / default പുനഃസ്ഥാപിക്കും).

```bash
# ഒരു DB ഓവർറൈഡ് സജ്ജമാക്കുക
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ഓവർറൈഡ് നീക്കം ചെയ്യുക ("value" ഇല്ല)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

പ്രതികരണത്തിൽ പുതിയ `effectiveValue`/`source`, `previousValue`/
`previousSource`, `requiresRestart` എന്നിവ പ്രതിഫലിക്കും. അറിയാത്ത കീകളും പരിധിക്ക് പുറത്തുള്ള enum
മൂല്യങ്ങളും `400` ഉപയോഗിച്ച് നിരസിക്കും.

#### `DELETE /api/settings/feature-flags`

എല്ലാ DB ഓവർറൈഡുകളും ഒരേസമയം നീക്കം ചെയ്യുകയും ഓരോ ഫ്ലാഗിനെയും അതിന്റെ env / default
മൂല്യത്തിലേക്ക് പുനഃസ്ഥാപിക്കുകയും ചെയ്യുന്നു. `{ cleared: <count>, message: "..." }` തിരികെ നൽകുന്നു.

> [!NOTE]
> `requiresRestart: true` ഉള്ള ഫ്ലാഗുകൾ പ്രോസസ് റീലോഡ് ചെയ്തതിന് ശേഷമേ പ്രാബല്യത്തിൽ വരൂ.
> ഡാഷ്ബോർഡിലെ റീസ്റ്റാർട്ട് പ്രവാഹം `POST /api/restart` വിളിക്കുകയും സെർവർ വീണ്ടും പ്രവർത്തനക്ഷമമാകുന്നതുവരെ
> `GET /api/health/ping` പോൾ ചെയ്യുകയും ചെയ്യുന്നു.

## അടിയന്തര ബജറ്റ് ഫാൾബാക്ക്

`OMNIROUTE_EMERGENCY_FALLBACK` (`runtime` വിഭാഗം, ഡിഫോൾട്ട് `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)-ലെ
അടിയന്തര സൗജന്യ ഫാൾബാക്ക് പാതയെ നിയന്ത്രിക്കുന്നു. ഇത് പ്രവർത്തനക്ഷമമാക്കിയിരിക്കുമ്പോൾ, ബജറ്റ്
തീർന്ന അഭ്യർത്ഥനകൾ പൂർണ്ണമായും പരാജയപ്പെടുന്നതിനു പകരം ഒരു സൗജന്യ ഫാൾബാക്ക്
പ്രൊവൈഡർ/മോഡലിലേക്ക് റൂട്ട് ചെയ്യപ്പെടും. ഈ പ്രവർത്തനം പ്രവർത്തനരഹിതമാക്കാനും ബജറ്റ് തീർന്ന
അഭ്യർത്ഥനകൾ പരാജയപ്പെടാൻ അനുവദിക്കാനും ഡാഷ്ബോർഡ് ടോഗിൾ, ഒരു DB ഓവർറൈഡ്, അല്ലെങ്കിൽ
`OMNIROUTE_EMERGENCY_FALLBACK` എൻവയോൺമെന്റ് വേരിയബിൾ എന്നിവ വഴി ഇത് `false`
(അല്ലെങ്കിൽ `0`) ആയി സജ്ജീകരിക്കുക. (PR-കൾ #3741 / #3752-ൽ ഡാഷ്ബോർഡ് ടോഗിളായി
ലഭ്യമാക്കിയിരിക്കുന്നു.)

ഈ ഫാൾബാക്ക് നൽകുന്ന ഒരു പ്രതികരണത്തിൽ
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` ഉണ്ടായിരിക്കും,
അതിനാൽ ഒരു ക്ലയന്റിന് അതിന്റെ അഭ്യർത്ഥനയുമായി `X-OmniRoute-Provider` താരതമ്യം ചെയ്യാതെതന്നെ
അത് വീണ്ടും റൂട്ട് ചെയ്യപ്പെട്ടതായി തിരിച്ചറിയാനാകും. മറ്റെല്ലാ പ്രതികരണങ്ങളിലും ഈ ഹെഡർ
ഉണ്ടായിരിക്കില്ല.
