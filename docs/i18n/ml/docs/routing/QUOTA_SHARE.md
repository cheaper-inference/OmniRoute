## അവലോകനം

Quota Sharing Engine, ഒരേ കണക്ഷൻ പങ്കിടുന്ന ഒന്നിലധികം API കീകൾക്കിടയിൽ ഒരു പ്രൊവൈഡറുടെ സമയാധിഷ്ഠിത ക്വോട്ട (ഉദാ. Codex
5-മണിക്കൂർ വിൻഡോ, Kimi 1500 req/h) ന്യായമായി വിതരണം ചെയ്യുന്നു.

**ഇത് പരിഹരിക്കുന്ന പ്രശ്നം:** OmniRoute, ഒരേ അപ്സ്ട്രീം പ്രൊവൈഡർ അക്കൗണ്ടിനെതിരെ നിരവധി API കീകൾ പ്രോക്സി ചെയ്യുന്നു.
പങ്കിടൽ ലോജിക് ഇല്ലെങ്കിൽ, കീ A-യിൽ നിന്നുള്ള പെട്ടെന്നുള്ള അഭ്യർത്ഥനാവർധന ആ മണിക്കൂറിലേക്കുള്ള
പ്രൊവൈഡർ ക്വോട്ട മുഴുവൻ ഉപയോഗിച്ചുതീർക്കാം; വിൻഡോ റീസെറ്റ് ചെയ്യുന്നതുവരെ കീകൾ B, C എന്നിവ ബ്ലോക്ക് ചെയ്യപ്പെടും.
എഞ്ചിൻ ഇത് തടയുന്നത് ഇപ്രകാരമാണ്:

1. ഓരോ ഡൈമെൻഷനിലും (%, അഭ്യർത്ഥനകൾ, ടോക്കണുകൾ, $) ഓരോ കീയുടെയും റോളിംഗ് ഉപഭോഗം ട്രാക്ക് ചെയ്യുന്നു.
2. വർക്കിനെ സംരക്ഷിക്കുന്ന ഫെയർ-ഷെയർ അൽഗോരിതം പ്രയോഗിക്കുന്നു: ഗ്ലോബൽ പൂൾ സാച്ചുറേറ്റ് ആയിട്ടില്ലെങ്കിൽ ഒരു കീക്ക് ഉപയോഗത്തിലില്ലാത്ത
   ഷെയറുകളിൽനിന്ന് കടമെടുക്കാം.
3. അഭ്യർത്ഥന അപ്സ്ട്രീം എക്സിക്യൂട്ടറിൽ എത്തുന്നതിനുമുമ്പ് ഹോട്ട് പാത്തിൽ (`chatCore.ts`) ഫലം നടപ്പിലാക്കുന്നു.

## അൽഗോരിതം: ഫെയർ-ഷെയർ വർക്ക്-കൺസർവിംഗ്

`src/lib/quota/fairShare.ts` യിൽ നടപ്പിലാക്കി.

### മോഡുകൾ

| അവസ്ഥ                                      | മോഡ്        | പെരുമാറ്റം                                             |
| ------------------------------------------ | ----------- | ------------------------------------------------------ |
| `globalUsedPercent < saturationThreshold`  | **ഉദാരമതി** | താക്കോൽ ആഗോള പരിധി വരെ കടമെടുത്തേക്കാം - മൊത്തം ഉപഭോഗം |
| `globalUsedPercent >= saturationThreshold` | **കർശനമായ** | വ്യക്തിഗത ന്യായമായ വിഹിതം കർശനമായി നടപ്പിലാക്കുക       |

ഡിഫോൾട്ട് `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`).

ഈ രണ്ട് മോഡുകളും ഡിഫോൾട്ട് ബോറോ മോഡിൽ ഒരു പൂളിനെ വിവരിക്കുന്നു, `saturation`. `consent` മോഡിലുള്ള ഒരു പൂൾ എപ്പോഴും സാച്ചുറേഷൻ എന്തുതന്നെയായാലും കർശനമായ നിയമങ്ങൾ പ്രയോഗിക്കുന്നു. [സമ്മതമുള്ള വായ്പ (ഓപ്-പൂൾ ഓപ്റ്റ്-ഇൻ)](#consented-lending-per-pool-opt-in) കാണുക.

### ഓരോ അളവിലുള്ള തീരുമാനം

കുളത്തിലെ ഓരോ സജീവ അളവുകൾക്കും, എഞ്ചിൻ കണക്കുകൂട്ടുന്നു:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = current rolling value for this key (from QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

`percent` അളവുകൾക്ക്, പകരം ആട്രിബ്യൂഷൻ ബുക്കിൽ നിന്നാണ് `consumed` വരുന്നത് ( [ശതമാനം അളവുകൾ കാണുക: ഓരോ കീ ആട്രിബ്യൂഷൻ](#percent-dimensions-per-key-attribution) ).

അപ്പോൾ:

- **`policy = hard`** : `consumed > fairShareAllowed` ഉം മോഡും കർശനമായ → ആണെങ്കിൽ** തടയുക** .
- **`policy = soft`** : `consumed > fairShareAllowed` ഉം മോഡും കർശനമായ → ആണെങ്കിൽ** ശിക്ഷിക്കുക** (കോംബോയിൽ മുൻഗണന നൽകരുത്; ഒരിക്കലും ഹാർഡ്-ബ്ലോക്ക്).
- **`policy = burst`** : ന്യായമായ വിഹിതം പരിഗണിക്കാതെ ആഗോള ഹെഡ്റൂം നിലനിൽക്കുമ്പോൾ അനുവദിക്കുക.

### ക്യാപ് അബ്സൊലൂട്ടോ

ഒരു അലോക്കേഷനിലെ`capValue` + `capUnit` എന്നത് മോഡ് അല്ലെങ്കിൽ പോളിസി എന്നിവയിൽ നിന്ന് സ്വതന്ത്രമായ ഒരു ഹാർഡ് സീലിംഗ് ആണ്. `consumed >= capValue` എപ്പോഴും ഉള്ള ഏത് അളവും** ബ്ലോക്കുകൾ** അഭ്യർത്ഥന. ഒരു `percent` ക്യാപ്പിനായി, കീയിൽ ആട്രിബ്യൂട്ട് ചെയ്ത ഭാഗം മാത്രമാണ് `consumed`.

### മൾട്ടി-ഡൈമൻഷൻ പരിശോധന

എങ്കിൽ ഒരു അഭ്യർത്ഥന തടഞ്ഞിരിക്കുന്നു** ഏതെങ്കിലും** കുളത്തിലെ അളവ് അതിനെ തടയും. അളവുകൾ സ്വതന്ത്രമാണ് — a 5h% ക്ഷീണം പ്രതിവാര% അളവിനെ ബാധിക്കില്ല.

### കടം വാങ്ങുന്നു

ഉദാരമായ മോഡിൽ, അലോക്കേഷൻ കുറവായ ഒരു കീയ്ക്ക് മറ്റ് കീകളുടെ അൺലോക്കേറ്റ് ചെയ്യാത്ത ഷെയറുകളിൽ നിന്ന് മിച്ചം ഉപയോഗിക്കാം. ഫോർമുല ഇതാണ്:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

എവിടെ `consumedByOtherKeys = consumedTotal - consumedByThisKey`. ടെറ്റോ ഗ്ലോബൽ (ആ അളവിനുള്ള പൂൾ `limit` ) എല്ലായ്പ്പോഴും ഹാർഡ് സീലിംഗ് ആണ്.

### സമ്മതമുള്ള വായ്പ (ഓപ്-പൂൾ ഓപ്റ്റ്-ഇൻ)

ഓരോ കുളത്തിനും ഒരു ലോൺ മോഡ് ഉണ്ട്. `saturation` സ്ഥിരസ്ഥിതിയാണ്, മുകളിലുള്ള നിയമങ്ങൾ സൂക്ഷിക്കുന്നു. `consent` മോഡിൽ, മറ്റ് കീകൾ കടം കൊടുക്കാൻ സമ്മതിച്ച ശേഷിയിൽ മാത്രമേ `hard` കീ അതിൻ്റെ പങ്ക് കൈമാറുകയുള്ളൂ. അഡ്മിനിസ്ട്രേറ്റർ ഓരോ പൂളിൻ്റെയും മോഡ് സജ്ജമാക്കുന്നു. ഓരോ കീ ഹോൾഡറും അവരുടെ സ്വന്തം സമ്മതം [ലെൻഡിംഗ് സമ്മതത്തിലൂടെ](#lending-consent) സജ്ജമാക്കുന്നു.

സമ്മതം എന്നത് 0 മുതൽ 100 വരെയുള്ള ശതമാനവും എപ്പോച്ച് മില്ലിസെക്കൻഡിലെ ഓപ്ഷണൽ ഡെഡ്ലൈനുമാണ്. സമയപരിധി ഭാവിയിലായിരിക്കുമ്പോൾ കീ അതിൻ്റെ നിഷ്ക്രിയ വിഹിതത്തിൻ്റെ ശതമാനം നൽകുന്നു.

ഒരു മാനത്തിന്, `L` ഫലപ്രദമായ പരിധിയാണ്: പ്ലാൻ പരിധി പൂളിലെ അക്കൗണ്ടുകളുടെ തവണ. അഭ്യർത്ഥിക്കുന്ന കീക്കായി ഗേറ്റ് കണക്കാക്കുന്നു:

```
share_k         = w_k / 100 × L
idle_k          = max(0, share_k − consumed_k)
lent            = Σ over the other keys of lend_k / 100 × idle_k
taken           = Σ over the other keys of max(0, consumed_k − share_k)
borrowAvailable = max(0, lent − taken)
```

`w_k` എന്നത് കീയുടെ ഭാരമാണ്, അല്ലെങ്കിൽ 0 ന് മുകളിലല്ലാത്തപ്പോൾ എല്ലാ കീയുടെയും `100 / n` `lend_k` എന്നത് കീയുടെ സജീവ ശതമാനമാണ്, അതിൻ്റെ സമയപരിധി കഴിഞ്ഞാൽ 0 ആണ്. അഭ്യർത്ഥിക്കുന്ന കീയുടെ സ്വന്തം സമ്മതം ഒരിക്കലും കണക്കാക്കില്ല. ഒരു `hard` കീ അതിൻ്റെ ഉപഭോഗം അതിൻ്റെ ഷെയറും `borrowAvailable` എത്തിയാൽ നിരസിക്കപ്പെടും.

ഒരു വിഹിതവും ക്ലെയിം ചെയ്യാത്ത ശേഷി (ഭാരത്തിൻ്റെ ആകെത്തുക 100 മൈനസ്) വായ്പ നൽകാനാവില്ല. ഒരു താക്കോലും കടം കൊടുക്കാൻ സമ്മതിച്ചില്ല.

**ഉദാഹരണം.** `L` 1000 ആണ്.

| താക്കോൽ | ഭാരം | പങ്കിടുക | ദഹിപ്പിച്ചു | കടം കൊടുക്കുന്നു |
| ------- | ---- | -------- | ----------- | ---------------- |
| എ       | 50   | 500      | 530         | 0%               |
| ബി      | 30   | 300      | 100         | 50%              |
| സി      | 0    | 0        | 60          | 0%               |

- B അതിൻ്റെ നിഷ്ക്രിയമായ 200-ൻ്റെ 50% കടം കൊടുക്കുന്നു, അതായത് 100. C ഇതിനകം തന്നെ അതിൻ്റെ വിഹിതത്തിന് മുകളിൽ 60 എടുത്തു. എ 40 കടം വാങ്ങാം.
- A 530-ന് നൽകുകയും അതിൻ്റെ ഉപഭോഗം 540-ൽ എത്തിയാൽ നിരസിക്കുകയും ചെയ്യുന്നു.
- C എന്തെങ്കിലും ഉപയോഗിക്കുന്നതിന് മുമ്പ്, A അതിൻ്റെ ഓഹരിയിലോ അതിന് താഴെയോ ഉള്ളത്, C ന് 100 കടം വാങ്ങാമായിരുന്നു.
- സി എന്തെങ്കിലും ഉപയോഗിക്കുന്നതിന് മുമ്പ്, എ 530-ൽ, സിക്ക് 70 കടം വാങ്ങാമായിരുന്നു.

**പൂജ്യം ഭാരം.** 0 ഭാരമുള്ള ഒരു കീക്ക് 0 ൻ്റെ ഒരു വിഹിതമുണ്ട്. മറ്റുള്ളവർ കടം കൊടുക്കുന്നതിലും താഴെയാണ് അതിൻ്റെ ഉപഭോഗം. ആരും കടം കൊടുക്കാത്തപ്പോൾ, അതിൻ്റെ ആദ്യ അഭ്യർത്ഥനയിൽ നിന്ന് അത് നിരസിക്കപ്പെടും.

**സമയപരിധി.** ഒരു പശ്ചാത്തല ടാസ്ക്കിൻ്റെയും സമ്മതം കാലഹരണപ്പെടുന്നില്ല. ഓരോ അഭ്യർത്ഥനയും സമയപരിധിയെ അതിൻ്റേതായ സമയവുമായി താരതമ്യം ചെയ്യുന്നു, ആ സമയത്തിന് തുല്യമായ ഒരു സമയപരിധി കഴിഞ്ഞു. ഒരു പരിമിത സംഖ്യയല്ലാത്ത, അല്ലെങ്കിൽ ഒരു `Date` കൈവശം വയ്ക്കാൻ കഴിയുന്ന ഏറ്റവും വലിയ തീയതി കഴിഞ്ഞ ഒരു സംഭരിച്ച സമയപരിധി കഴിഞ്ഞതായി കണക്കാക്കുന്നു.

**`soft`, `burst`.** കടം കൊടുക്കുന്നത് അവരെ പരിമിതപ്പെടുത്തുന്നില്ല. ഒരു `soft` കീ അതിൻ്റെ വിഹിതം കഴിഞ്ഞാൽ മുൻഗണന ഇല്ലാതാക്കുന്നു. കുളത്തിന് ഇടമുള്ളപ്പോൾ ഒരു `burst` കീ കടന്നുപോകുന്നു. പൂളിൻ്റെ ആകെത്തുക അതിൻ്റെ പരിധിയിൽ എത്തിയാൽ പൂൾ സീലിംഗ് ഇപ്പോഴും എല്ലാ കീയും നിരസിക്കുന്നു.

**അഭ്യർത്ഥന പാതയിലെ ചെലവ്.** ഒരു `saturation` പൂൾ മുമ്പത്തേതിനേക്കാൾ കൂടുതൽ ഒന്നും വായിക്കുന്നില്ല. ഒരു `consent` പൂളിൽ, മറ്റൊരു കീ കടം കൊടുക്കുമ്പോൾ അതിൻ്റെ ഷെയറിലോ അതിനു മുകളിലോ ഉള്ള ഒരു `hard` കീയ്ക്കായി മാത്രം കണക്കാക്കാവുന്ന അളവ് മറ്റ് കീകൾ വായിക്കുന്നു. അത് പിന്നീട് സമാന്തരമായി ഒരു കീ ഓരോന്നും വായിക്കുന്നു. പരാജയപ്പെട്ട വായന ആ കീയുടെ ഉപഭോഗം 0 ആയി കണക്കാക്കുന്നു. ഒരു `percent` ഡൈമൻഷൻ റീഡ് ചേർക്കുന്നില്ല, കാരണം ആട്രിബ്യൂഷൻ ബുക്കിൽ എല്ലാ കീകളും ഉണ്ട്.

**ഒരു കുളം എഡിറ്റുചെയ്യുന്നു.** ഒരു എഡിറ്റ് തുടരുന്ന കീകളുടെ സമ്മതം നിലനിർത്തുന്നു. ഇത് അലോക്കേഷൻ എഡിറ്റുകൾക്കും ഗ്രൂപ്പ്-വൈഡ് റീപ്ലേസ്മെൻ്റുകൾക്കും `ensure` കോളുകൾക്കും ബാധകമാണ്. നീക്കംചെയ്ത ഒരു കീ അതിൻ്റെ സമ്മതം നഷ്ടപ്പെടുത്തുന്നു, തിരികെ ചേർത്ത ഒരു കീ 0-ൽ ആരംഭിക്കുന്നു. അഡ്മിൻ റൂട്ടുകൾ ഓരോ കീയുടെയും സമ്മതം തിരികെ നൽകില്ല, അത് ഒരിക്കലും എഴുതുകയില്ല. ഒരു പൂൾ തിരികെ `saturation` ലേക്ക് മാറ്റുന്നത് സംഭരിച്ചിരിക്കുന്ന എല്ലാ സമ്മതവും നിലനിർത്തുന്നു, അത് ആ മോഡിൽ യാതൊരു ഫലവുമില്ല. പൂൾ `consent` ലേക്ക് മാറ്റുന്നത്, സമയപരിധി കഴിഞ്ഞിട്ടില്ലാത്ത സംഭരിച്ച സമ്മതങ്ങളെ വീണ്ടും സജീവമാക്കുന്നു. ഒരു കീ ഹോൾഡർക്ക് രണ്ട് മോഡിലും സംഭരിച്ച സമ്മതം മായ്ക്കാൻ കഴിയും.

**നവീകരിക്കുന്നു.** `lending_percent`, `lending_until` എന്നീ നിരകൾ നിലവിലുണ്ടെങ്കിൽ, മൈഗ്രേഷൻ `borrow_mode` മാത്രമേ ചേർക്കൂ, സംഭരിച്ച ശതമാനങ്ങൾ അതേപടി നിലനിൽക്കും. എല്ലാ പൂളും `saturation` മോഡിൽ ആരംഭിക്കുന്നു. പൂൾ വിസാർഡിൽ ഓരോ കുളത്തിനും `consent` ഓണാക്കുക. സംഭരിച്ച മൂല്യങ്ങളിൽ നിന്ന് ഒന്നും അനുമാനിക്കുന്നില്ല.

**പരിമിതികൾ.**

- ഒരു കടം കൊടുക്കുന്നയാൾക്ക് അതിൻ്റെ സ്വന്തം ഷെയർ ഉപയോഗിക്കുന്നതിന് മുമ്പ് അതിൻ്റെ സീലിംഗിൽ പൂൾ കണ്ടെത്താനാകും. മറ്റുള്ളവർ കടമെടുത്ത കപ്പാസിറ്റി പൂളിൻ്റെ മൊത്തത്തിൽ കണക്കാക്കുന്നു.
- ചെക്ക് അഭ്യർത്ഥനയ്ക്ക് മുമ്പായി പ്രവർത്തിക്കുന്നു, ഒന്നും റിസർവ് ചെയ്യുന്നില്ല. കൺകറൻ്റ് അഭ്യർത്ഥനകൾ എന്തെങ്കിലും രേഖപ്പെടുത്തുന്നതിന് മുമ്പ് ഉപഭോഗം വായിക്കുന്നു, അതിനാൽ ഫ്ലൈറ്റിലെ അഭ്യർത്ഥനകളാൽ പരിമിതപ്പെടുത്തി വായ്പയുടെ ശേഷി ഒന്നിലധികം തവണ ചെലവഴിക്കാൻ കഴിയും. `saturation` മോഡിൻ്റെ ഷെയർ ചെക്കിന് സമാന പ്രോപ്പർട്ടി ഉണ്ട്.

## സ്ലൈഡിംഗ് വിൻഡോ കൗണ്ടർ

`src/lib/quota/sqliteQuotaStore.ts`, `redisQuotaStore.ts` എന്നിവയിൽ നടപ്പിലാക്കിയിരിക്കുന്നു.

ഓരോ `(apiKeyId, dimensionKey)`-നും രണ്ട് ബക്കറ്റുകൾ:

- `curr`: നിലവിലെ ബക്കറ്റ് (`floor(nowMs / windowMs)`)
- `prev`: മുമ്പത്തെ ബക്കറ്റ് (`curr - 1`)

ഫലപ്രദമായ റോളിംഗ് മൂല്യം:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**കൃത്യത**: ~99% കൃത്യം. ബക്കറ്റുകൾക്കിടയിലെ അതിർത്തിയിൽ പിശക് വിൻഡോ വലുപ്പത്തിന്റെ പരമാവധി 1% മാത്രമാണ്
(2-ബക്കറ്റ് ഏകദേശീകരണത്തിന്റെ അന്തർലീനമായ സവിശേഷത).

### കൺകറൻസി

SQLite ഡ്രൈവർ: ഓരോ `(apiKeyId | dimensionKey)` കീയ്ക്കുമുള്ള ഇൻ-മെമ്മറി മ്യൂട്ടക്സ്
read-modify-write റേസ് തടയുന്നു. ഈ പാറ്റേൺ `src/sse/services/auth.ts`-ലെ anti-thundering-herd മാതൃക പിന്തുടരുന്നു.

Redis ഡ്രൈവർ: അറ്റോമിക് ഇൻക്രിമെന്റിനുള്ള Lua EVAL സ്ക്രിപ്റ്റ് — ഒറ്റ Redis കമാൻഡായി പ്രവർത്തിക്കുന്നു.

## ഡ്രൈവറുകൾ

### SQLite (ഡിഫോൾട്ട്, ഇൻസ്റ്റാളേഷൻ ആവശ്യമില്ല)

- പട്ടിക: `quota_consumption` (മൈഗ്രേഷൻ `073_quota_pools.sql` / `074_quota_consumption.sql` കാണുക).
- ഒറ്റ ഇൻസ്റ്റൻസ് വിന്യാസങ്ങൾക്ക് ഏറ്റവും അനുയോജ്യം.
- എല്ലാ സ്ഥിരസംഭരണവും നിലവിലുള്ള OmniRoute SQLite DB-യിലാണ് (`DATA_DIR/storage.sqlite`).

### Redis (ഐച്ഛികം, മൾട്ടി-ഇൻസ്റ്റൻസ്)

- `ioredis` npm പാക്കേജ് ആവശ്യമാണ്.
- കൗണ്ടറുകൾ Redis-ൽ സംഭരിക്കുന്നു; മെറ്റാഡാറ്റ (പൂളുകൾ/അലോക്കേഷനുകൾ) തുടർന്നും SQLite-ൽ സൂക്ഷിക്കുന്നു.
- കൗണ്ടറുകൾ പങ്കിടേണ്ട മൾട്ടി-റെപ്ലിക്ക വിന്യാസങ്ങൾക്ക് ഏറ്റവും അനുയോജ്യം.

### ഡ്രൈവറുകൾ മാറുന്നത്

ക്രമീകരണ UI (`/dashboard/settings` → Quota Store) വഴിയോ env vars വഴിയോ:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

env-നേക്കാൾ DB ക്രമീകരണത്തിനാണ് മുൻഗണന. `driver=redis` ആയിരിക്കെ URL ഇല്ലെങ്കിലോ
`ioredis` ഇൻസ്റ്റാൾ ചെയ്തിട്ടില്ലെങ്കിലോ, ഫാക്ടറി SQLite-ലേക്ക് തിരികെ മാറുകയും ഒരു മുന്നറിയിപ്പ് ലോഗ് ചെയ്യുകയും ചെയ്യും.

ഡ്രൈവർ തിരഞ്ഞെടുക്കുന്ന ക്രമം:

1. DB ക്രമീകരണം `quotaStore.driver`
2. Env `QUOTA_STORE_DRIVER`
3. ഡിഫോൾട്ട്: `sqlite`

## മൾട്ടി-ഡൈമൻഷൻ

ഒരു കുളത്തിന് ഒന്നിലധികം അളവുകൾ ഉണ്ടാകും. ഓരോ അളവും സ്വതന്ത്രമാണ്:

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // global pool ceiling for this dimension
}
```

**ഉദാഹരണം: Codex പ്ലാൻ** (5h% + പ്രതിവാര%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

ഒരു അഭ്യർത്ഥന അനുവദിക്കുന്നതിന് എല്ലാ അളവുകളും തൃപ്തിപ്പെടുത്തണം.

### ശതമാനം അളവുകൾ: ഓരോ കീ ആട്രിബ്യൂഷൻ

ഒരു ശതമാനം പ്ലാൻ ഒരു അക്കൗണ്ടിനും പ്ലാൻ വിൻഡോയ്ക്കും ഒരു ഉപയോഗ കണക്ക് റിപ്പോർട്ട് ചെയ്യുന്നു. ദാതാവ് ഓരോ API കീയ്ക്കും കൗണ്ടർ നൽകുന്നില്ല.

കീകൾക്കിടയിൽ ആ കണക്ക് വിഭജിക്കാൻ, ഓരോ പൂളും ഓരോ അക്കൗണ്ടിനും പ്ലാൻ വിൻഡോയ്ക്കും ഒരു ആട്രിബ്യൂഷൻ ബുക്ക് സൂക്ഷിക്കുന്നു. `src/lib/quota/percentLedger.ts` പുസ്തകത്തിൻ്റെ നിയമങ്ങൾ പാലിക്കുന്നു. `src/lib/quota/percentAttribution.ts` പുസ്തകത്തെ എൻഫോഴ്സ്മെൻ്റ് ഉപയോഗിക്കുന്ന സംഖ്യകളാക്കി മാറ്റുന്നു. ഓരോ പ്രധാന റൂട്ടുകളുടെയും ടോക്കണുകളിൽ നിന്ന് നിർമ്മിച്ച ഒരു എസ്റ്റിമേറ്റ് ആണ് ഫലം.

#### പുസ്തകത്തെ ചലിപ്പിക്കുന്ന വായനകൾ

അഭ്യർത്ഥിച്ച പ്ലാൻ വിൻഡോയ്ക്കായി ദാതാവിൻ്റെ സ്വന്തം ചിത്രത്തിൽ മാത്രം പുസ്തകം നീങ്ങുന്നു. ഈ കണക്ഷനുകൾ ഒന്ന് റിപ്പോർട്ട് ചെയ്യുന്നു:

| ദാതാവ്                        | വിൻഡോകൾ ആസൂത്രണം ചെയ്യുക |
| ----------------------------- | ------------------------ |
| Claude, ഒരു OAuth കണക്ഷനിലൂടെ | `5h`, `weekly`           |
| Codex                         | `5h`, `weekly`           |

ഇവ ഒരു വായനയായി കണക്കാക്കില്ല:

- ഒരു പ്രതികരണം ദാതാവ് ക്ലയൻ്റ് പഴയതായി അടയാളപ്പെടുത്തുന്നു
- ദാതാവ് റിപ്പോർട്ട് ചെയ്യാത്ത ഒരു Claude വിൻഡോ
- മറ്റൊരു വിൻഡോയുടെ ചിത്രം, അല്ലെങ്കിൽ ജാലകങ്ങളിലുടനീളമുള്ള ഏറ്റവും മോശം കേസ്
- നിരക്ക്-പരിധി തലക്കെട്ട് ഫാൾബാക്ക്
- ഒരു പരാജയപ്പെട്ട വായന

API കീ ഉള്ള Claude ഉൾപ്പെടെയുള്ള മറ്റ് ദാതാക്കൾക്ക് പുസ്തകമില്ല. ഈ മാറ്റത്തിന് മുമ്പുള്ളതുപോലെ, ഓരോ കീയും അവയുടെ ശതമാനം അളവുകളിൽ 0 ചാർജ് ചെയ്യുന്നു.

ഒരു വായന സാച്ചുറേഷൻ സിഗ്നലിൻ്റെ 30 സെക്കൻഡ് കാഷെ പങ്കിടുന്നു. പ്രതികരണ തലക്കെട്ടുകളിൽ ചിത്രം നിരീക്ഷിച്ചപ്പോഴോ ഉപയോഗ എൻഡ്പോയിൻ്റിൽ നിന്ന് വായിച്ചപ്പോഴോ, ആ സമയം അറിയുമ്പോൾ ഒരു Claude റീഡിംഗ് തീയതി കണക്കാക്കുന്നു. ആ കാഷെ എൻട്രി നിർമ്മിച്ചത് എപ്പോഴാണ് മറ്റ് റീഡിംഗുകൾ കണക്കാക്കുന്നത്.

#### പുസ്തകം എന്താണ് സൂക്ഷിക്കുന്നത്

റെക്കോർഡുചെയ്ത ഓരോ അഭ്യർത്ഥനയും അതിൻ്റെ ടോക്കണുകൾ ഒരിക്കൽ, ഓരോ പൂളിലും അക്കൗണ്ടിലും കീയിലും ഒരു കൗണ്ടറിലേക്ക് ചേർക്കുന്നു. ഒരു കൗണ്ടർ മാത്രം വളരുന്നു. പുസ്തകം മൂന്ന് കാര്യങ്ങൾ സൂക്ഷിക്കുന്നു:

- അടിസ്ഥാനരേഖ: പുസ്തകം തുറന്നപ്പോഴോ വിൻഡോ അവസാനം തിരിയുമ്പോഴോ ഉള്ള ചിത്രം
- അവസാനം പ്രയോഗിച്ച ചിത്രം
- ഒരു കീ, അതേ നിമിഷത്തിൽ അതിൻ്റെ ടോക്കൺ കൗണ്ടർ, അതിൻ്റെ അടയാളം എന്ന് വിളിക്കുന്നു

എൻഫോഴ്സ്മെൻ്റ് അല്ലെങ്കിൽ ഉപയോഗ റൂട്ട് ആട്രിബ്യൂഷൻ കണക്കാക്കുമ്പോൾ പുസ്തകം അപ്ഡേറ്റ് ചെയ്യപ്പെടും. ഒരു റിവിഷൻ നമ്പറിൽ റൈറ്റുകൾ താരതമ്യം ചെയ്ത് സജ്ജീകരിച്ചിരിക്കുന്നു. നഷ്ടപ്പെടുന്ന ഒരു എഴുത്തുകാരൻ വീണ്ടും വീണ്ടും വായിക്കാൻ ശ്രമിക്കുന്നു.

#### ഒരു കീയുടെ ഭാഗം എങ്ങനെയാണ് കണക്കാക്കുന്നത്

പുസ്തകം വായിക്കുമ്പോൾ ഓരോ കീയുടെയും ഭാഗങ്ങൾ കണക്കാക്കുന്നു. ടോക്കണുകൾക്ക് ആനുപാതികമായി കീകൾക്കിടയിൽ ബേസ്ലൈൻ വിഭജിക്കുമ്പോൾ, ഓരോന്നിനും അതിൻ്റെ അടയാളം മുതൽ റൂട്ട് ചെയ്തിരിക്കുന്നതിനാൽ ചിത്രത്തിൻ്റെ വളർച്ച.

Together, ആ ടോക്കണുകൾ ഓരോ `QUOTA_PERCENT_MIN_TOKENS_PER_POINT` ടോക്കണുകളുടെയും കണക്കിൻ്റെ പരമാവധി ഒരു പോയിൻ്റിൽ വിശദീകരിക്കുന്നു (സ്ഥിരസ്ഥിതി 1,000). അവർ വിശദീകരിക്കാത്ത വളർച്ച ബാഹ്യമാണ്. അടിസ്ഥാനവും ബാഹ്യമാണ്.

ഉദാഹരണത്തിന്, ഒരു പുസ്തകം 0-ൽ തുറക്കുന്നു. കീ എ തുടർന്ന് 900,000 ടോക്കണുകളും കീ ബി റൂട്ടുകൾ 100,000 ഉം റൂട്ട് ചെയ്യുന്നു. 60 എന്ന കണക്കിൽ A യുടെ ഭാഗം 54 പോയിൻ്റും B യുടെ ഭാഗം 6 ഉം ആണ്.

അതിൻ്റെ കീയുടെ മാർക്കിന് താഴെയുള്ള ഒരു കൗണ്ടർ പുനരാരംഭിക്കുകയും പൂർണ്ണമായി കണക്കാക്കുകയും ചെയ്തു. ഒരു ജാലകത്തിൻ്റെ നടുവിലുള്ള കുളത്തിൽ ചേരുന്ന ഒരു താക്കോൽ പോലെ ഒരു അടയാളം ഇല്ലാത്ത ഒരു കീ, അതിൻ്റെ എല്ലാ ടോക്കണുകളും കണക്കാക്കുന്നു. ടോക്കണുകളെ പിന്നിലാക്കിയ ഒരു കണക്ക് അടുത്ത വായനയിൽ ഒരു പിശകിന് കാരണമാകുന്നു. അത് കുമിഞ്ഞുകൂടുന്നില്ല.

എല്ലാ ആട്രിബ്യൂഷനിലും`QUOTA_PERCENT_MIN_TOKENS_PER_POINT` വായിക്കുന്നു. ചുരുങ്ങിയത് 1 ൻ്റെ പരിമിത സംഖ്യയല്ലാത്ത ഒരു മൂല്യം 1,000 ആയി കുറയുന്നു.

#### ഒരു വായന പുസ്തകത്തെ എങ്ങനെ മാറ്റുന്നു

ആദ്യ പൊരുത്തപ്പെടുത്തൽ നിയമം ബാധകമാണ്:

1. **ഇതുവരെ ഒരു പുസ്തകവുമില്ല:** വായന പുസ്തകം തുറക്കുന്നു. അതിൻ്റെ ചിത്രം അടിസ്ഥാനരേഖയാണ്, ഓരോ കൗണ്ടറും അടയാളപ്പെടുത്തിയിരിക്കുന്നു.
2. **പഴയ വായന:** അവസാനം പ്രയോഗിച്ചതിന് മുമ്പുള്ള ഒരു വായന അവഗണിക്കപ്പെടും. അതുപോലെ റീസെറ്റ് സമയം സംഭരിച്ചതിനേക്കാൾ 30 മിനിറ്റിലധികം മുമ്പുള്ള ഒരു വായനയാണ്.
3. **പുതിയ ദാതാവിൻ്റെ വിൻഡോ:** സംഭരിച്ച സമയം പുസ്തകം തിരിയുന്നതിനേക്കാൾ 30 മിനിറ്റിലധികം കഴിഞ്ഞ് പുനഃസജ്ജമാക്കൽ സമയം. ചിത്രം അടിസ്ഥാനമായി മാറുകയും ഓരോ കൗണ്ടറും വീണ്ടും അടയാളപ്പെടുത്തുകയും ചെയ്യുന്നു. കൗണ്ടറില്ലാത്ത കീകൾ പുസ്തകം വിടുന്നു.
4. **അവസാനിച്ച വിൻഡോ:** റീഡിംഗ് ഡാറ്റാ സമയത്തിന് ശേഷമല്ല സംഭരിച്ച റീസെറ്റ് സമയം അർത്ഥമാക്കുന്നത് വിൻഡോ അവസാനിച്ചു എന്നാണ്. വായന പുസ്തകത്തെ അതിൻ്റെ രൂപമെന്തായാലും തിരിയുന്നു.
5. **ഉയർന്ന കണക്ക്:** അവസാന ചിത്രം മാത്രം ചലിക്കുന്നു. അടിസ്ഥാനരേഖയും മാർക്കുകളും നിലനിൽക്കും.
6. **അതേ ചിത്രം:** കണക്കും അടിസ്ഥാനരേഖയും അടയാളങ്ങളും നിലനിൽക്കും. പുസ്തകം ഇല്ലാത്ത ഒരു റീസെറ്റ് സമയം മാത്രമേ എഴുതിയിട്ടുള്ളൂ.
7. **താഴത്തെ ചിത്രം:** ഒരു താഴ്ന്ന കണക്ക് ഒരിക്കലും പ്രയോഗിക്കില്ല. മൂന്ന് കാര്യങ്ങൾ പിടിക്കുമ്പോൾ മാത്രമാണ് അത് പുസ്തകം തിരിക്കുന്നത്. അവസാനം പ്രയോഗിച്ച വായനയേക്കാൾ കുറഞ്ഞത് രണ്ട് മിനിറ്റെങ്കിലും ഇത് പുതിയതാണ്. ജാലകം തുറന്നത് തന്നെയാണെന്ന് ഒന്നും പറയുന്നില്ല. ഇത് ഒരു പോയിൻ്റിൽ കൂടുതൽ കുറവാണ്.

മൂന്ന് കാര്യങ്ങൾ പിടിക്കുമ്പോൾ വിൻഡോ ഒരേ തുറന്നതായി കണക്കാക്കുന്നു. രണ്ട് റീസെറ്റ് സമയങ്ങളും അറിയാം. അവർ പരസ്പരം 30 മിനിറ്റിനുള്ളിൽ. സംഭരിച്ചവ ഇപ്പോഴും വായനയിൽ മുന്നിലാണ്. ആ ജാലകത്തിനുള്ളിലെ ഒരു താഴ്ന്ന രൂപം ഒന്നും മാറ്റുന്നില്ല.

റീസെറ്റ് സമയം അത് വഹിക്കുന്ന വായനയുടെ ഡാറ്റാ സമയത്തിന് മുന്നിലായിരിക്കുമ്പോൾ മാത്രമേ അത് സംഭരിക്കപ്പെടുകയുള്ളൂ. ഒരു ഉയർന്ന കണക്ക് അതിൻ്റെ റീഡിംഗ് റീസെറ്റ് സമയം സംഭരിക്കുന്നു, അത് ഉപയോഗിക്കാനാകുമ്പോൾ, അല്ലെങ്കിൽ സംഭരിച്ചിരിക്കുന്നതിനെ സൂക്ഷിക്കുന്നു. പുസ്തകത്തിൽ ഒന്നുമില്ലാത്തപ്പോൾ മാത്രമാണ് തുല്യമായ ഒരു കണക്ക് അതിൻ്റെ വായനയുടെ റീസെറ്റ് സമയം രേഖപ്പെടുത്തുന്നത്. അത് മറ്റൊന്നും മാറ്റുന്നില്ല. പുസ്തകം തിരിയാത്ത ഒരു താഴ്ന്ന കണക്ക് റീസെറ്റ് സമയം രേഖപ്പെടുത്തുന്നില്ല.

#### പുസ്തകം ഉപയോഗിക്കുമ്പോൾ

ഒരു വായനയ്ക്ക് ശേഷം, സംഭരിച്ച റീസെറ്റ് സമയം നിലവിലെ സമയത്തിന് ശേഷമല്ലെങ്കിൽ പുസ്തകം ഉപയോഗിക്കും. റീസെറ്റ് ചെയ്യുന്നതിന് തൊട്ടുമുമ്പ് എടുത്ത ഒരു റീഡിംഗ്, കാഷെയിൽ നിന്ന് നൽകിയത് പോലെ, അതിന് തൊട്ടുപിന്നാലെ നിരീക്ഷിക്കുമ്പോൾ ആ സാഹചര്യം ഉണ്ടാകുന്നു.

ഉപയോഗയോഗ്യമായ വായന കൂടാതെ, സംഭരിച്ച പുസ്തകം നിലവിലെ വിൻഡോയുടെ പുസ്തകം ആയിരിക്കുമ്പോൾ മാത്രമേ ഉപയോഗിക്കൂ. ഇത് രണ്ട് കേസുകളിൽ നിലനിൽക്കുന്നു:

- അതിൻ്റെ പുനഃസജ്ജീകരണ സമയം അറിയാം, ഇപ്പോഴും മുന്നിലാണ്
- ഇതിന് പുനഃസജ്ജീകരണ സമയമില്ല, അവസാനമായി അത് മാറ്റിയ വായനയ്ക്ക് പരമാവധി 15 മിനിറ്റ് പഴക്കമുണ്ട്

അല്ലാത്തപക്ഷം പുസ്തകമില്ലാത്തതുപോലെ ഒന്നും ആരോപിക്കപ്പെടുന്നില്ല. സംഭരിച്ച റീസെറ്റ് സമയം കഴിഞ്ഞ ഒരു പുസ്തകത്തിന് ഒരിക്കലും നിരക്ക് ഈടാക്കില്ല.

#### എൻഫോഴ്സ്മെൻ്റ്

ഒരു ശതമാനം അളവിലുള്ള കീയുടെ ഉപഭോഗം അതിൻ്റെ ആട്രിബ്യൂട്ട് ചെയ്ത ഭാഗവും ബാഹ്യ ഭാഗത്തിൻ്റെ ഒരു വിഹിതവുമാണ്. ബാഹ്യ ഭാഗം ആദ്യം കപ്പാസിറ്റി നോ അലോക്കേഷൻ ക്ലെയിമുകൾ ഉപയോഗിക്കുന്നു (ഭാരത്തിൻ്റെ ആകെത്തുക 100 മൈനസ്). ഭാരം അനുസരിച്ച് കീകൾക്കിടയിൽ അധികമായത് മാത്രമേ പങ്കിടൂ.

ആ ഉപഭോഗത്തെ മറ്റേതൊരു മാനത്തേയും പോലെ കീയുടെ ന്യായമായ വിഹിതവുമായി താരതമ്യം ചെയ്യുന്നു. സാച്ചുറേഷൻ സിഗ്നൽ `QUOTA_SATURATION_THRESHOLD` എത്തുമ്പോൾ കർശനമായ മോഡ് ഇപ്പോഴും ആരംഭിക്കുന്നു (സ്ഥിരസ്ഥിതി 0.5). ഓരോ സംഖ്യയും ഫലപ്രദമായ പരിധി കൊണ്ടാണ് സ്കെയിൽ ചെയ്യുന്നത്: ഓരോ അക്കൗണ്ടിൻ്റെയും പരിധി പൂളിലെ അക്കൗണ്ടുകളുടെ എണ്ണത്തിൻ്റെ ഇരട്ടിയാണ്.

`capUnit: "percent"` ഉള്ള ഒരു സമ്പൂർണ്ണ തൊപ്പി, അതേ രീതിയിൽ സ്കെയിൽ ചെയ്ത കീയിലേക്ക് ആട്രിബ്യൂട്ട് ചെയ്ത ഭാഗം മാത്രമേ കണക്കാക്കൂ. ഓരോ അക്കൗണ്ടിനും 100, കെ അക്കൗണ്ടുകളുടെ പരിധി എടുക്കുക. സെർവിംഗ് അക്കൗണ്ടിൻ്റെ കണക്കിൻ്റെ കീയുടെ ഭാഗം N/k പോയിൻ്റിൽ എത്തുമ്പോൾ N ൻ്റെ ഒരു പരിധി എത്തുന്നു. ഓരോ അക്കൗണ്ടും അതിൻ്റെ സ്വന്തം പുസ്തകത്തിൽ നിന്ന് പരിശോധിക്കുന്നു. ഉദാഹരണത്തിന്, രണ്ട് അക്കൗണ്ടുകൾക്കൊപ്പം, ഒരു അക്കൗണ്ടിൻ്റെ കണക്കിൻ്റെ 5 പോയിൻ്റിൽ 10 എന്ന പരിധി എത്തുന്നു.

സ്റ്റോർ റീഡ് ചെയ്യാൻ കഴിയാത്തപ്പോൾ, ഒന്നും ആട്രിബ്യൂട്ട് ചെയ്യപ്പെടില്ല, ഓരോ കീയും ആ അളവിൽ 0 ആയി ചാർജ് ചെയ്യുന്നു. ഒരു പുസ്തക രചന പരാജയപ്പെടുമ്പോൾ, ആ ആട്രിബ്യൂഷൻ പുസ്തകം വായിച്ചതുപോലെ ഉപയോഗിക്കുന്നു. പരാജയപ്പെട്ട ഒരു ടോക്കൺ റൈറ്റിൻ്റെ അഭ്യർത്ഥനയുടെ ടോക്കണുകൾ പുസ്തകത്തിൽ നിന്ന് പുറത്തെടുക്കുന്നു. ഈ പരാജയങ്ങളൊന്നും ഒരു അഭ്യർത്ഥനയെ തടയുന്നില്ല.

ഒരു `consent` പൂളിൽ, വായ്പാ സൂത്രവാക്യം മുകളിൽ വിവരിച്ചതുപോലെ ശതമാനം അളവിലുള്ള ഓരോ കീയുടെയും ഉപഭോഗം ഉപയോഗിക്കുന്നു. മറ്റൊരു താക്കോൽ നൽകുമ്പോൾ, പുസ്തകം ഒരിക്കൽ വായിക്കുകയും എല്ലാ താക്കോലുകളും ആട്രിബ്യൂട്ട് ചെയ്യുകയും ചെയ്യുന്നു. ഉപയോഗയോഗ്യമായ ഒരു പുസ്തകം കൂടാതെ, ഓരോ കീയും ചാർജ്ജ് ചെയ്യപ്പെടും. ഭാരമുള്ള ഒരു താക്കോൽ പിന്നീട് കടന്നുപോകുന്നു, 0 ഭാരമുള്ള ഒരു താക്കോൽ മറ്റൊരു താക്കോൽ കടം കൊടുക്കുമ്പോൾ മാത്രം കടന്നുപോകുന്നു.

#### ഉപയോഗ റൂട്ട്

`GET /api/quota/pools/{id}/usage` ഒരേ ഫംഗ്ഷനിലൂടെ ഒരേ നമ്പറുകൾ റിപ്പോർട്ട് ചെയ്യുന്നു. ഒരു ശതമാനം അളവിന് `accounts` ൽ ഓരോ പൂൾ കണക്ഷനും ഒരു എൻട്രി ഉണ്ട്. അതിൻ്റെ ഉയർന്ന തലത്തിലുള്ള `consumedTotal`, `perKey` എന്നിവ ആദ്യ എൻട്രിയെ പ്രതിഫലിപ്പിക്കുന്നു.

റൂട്ട് നിലവിലെ വായനയ്ക്കും ബാധകമാണ്, അതിനാൽ ഒരു അഭ്യർത്ഥന പോലെ ഇതിന് പുസ്തകം മുന്നോട്ട് കൊണ്ടുപോകാനാകും. ഉപയോഗയോഗ്യമായ വായന ഇല്ലാത്തപ്പോൾ അല്ലെങ്കിൽ താഴ്ന്ന കണക്ക് പ്രയോഗിക്കാത്തപ്പോൾ `internal + external` `consumedTotal` ൽ നിന്ന് വ്യത്യാസപ്പെടാം.

#### സംഭരണവും നിലനിർത്തലും

രണ്ട് ക്വാട്ട സ്റ്റോറുകളും പുസ്തകം സൂക്ഷിക്കുന്നു. SQLite യിൽ, സ്വയമേവയുള്ള ഡാറ്റാബേസ് ക്ലീനപ്പ്, പ്രവർത്തനക്ഷമമാക്കുമ്പോൾ, 60 ദിവസത്തേക്ക് അപ്ഡേറ്റ് ചെയ്യാത്ത വരികൾ നീക്കംചെയ്യുന്നു. Redis ൽ, ഒരു പൂൾ കണക്ഷൻ്റെ പുസ്തകങ്ങളും കൗണ്ടറുകളും ഒരു കീ പങ്കിടുന്നു. അതിൻ്റെ അവസാനത്തെ ടോക്കൺ എഴുത്ത് അല്ലെങ്കിൽ പുസ്തകം മാറ്റത്തിന് ശേഷം 60 ദിവസത്തിന് ശേഷം അത് കാലഹരണപ്പെടും. മാറ്റമില്ലാത്ത ഒരു പുസ്തകം മാറ്റിയെഴുതില്ല, അതിനാൽ ഏറ്റവും ദൈർഘ്യമേറിയ പ്ലാൻ വിൻഡോയ്ക്ക് മുകളിലാണ് കട്ട്ഓഫ് സജ്ജീകരിച്ചിരിക്കുന്നത്. മാനുവൽ യൂസേജ്-ഹിസ്റ്ററി റീസെറ്റ് SQLite ലെ പുസ്തകങ്ങളും മായ്ക്കുന്നു (പരിമിതികൾ കാണുക).

#### പരിമിതികൾ

- അന്നുമുതൽ റൂട്ട് ചെയ്ത ഓരോ കീയും ടോക്കണുകളാൽ ബേസ്ലൈൻ വിഭജിച്ചതു മുതൽ അക്കൗണ്ട് കണക്കിൻ്റെ എല്ലാ വളർച്ചയും. ആ വളർച്ച എപ്പോൾ ഉണ്ടായി എന്നത് പ്രശ്നമല്ല.

- ഒരു Redis സ്റ്റോർ തീയതി റീഡിംഗുകൾ അവരുടെ സ്വന്തം ക്ലോക്കുകളുമായി പങ്കിടുന്ന സന്ദർഭങ്ങൾ, അതിനാൽ ആ ക്ലോക്കുകൾ സമന്വയത്തിൽ സൂക്ഷിക്കുക. ക്ലോക്ക് പിന്നിൽ ഓടുന്ന ഒരു ഉദാഹരണത്തിൻ്റെ വായനകൾ പഴയതായി കാണപ്പെടുകയും അവഗണിക്കപ്പെടുകയും ചെയ്യുന്നു.
- സംഭരിച്ച പുനഃസജ്ജീകരണ സമയത്തിന് ശേഷം ഉപയോഗയോഗ്യമായ റീഡിംഗൊന്നും വരാത്തപ്പോൾ, ഒരു റീഡിംഗ് റിട്ടേൺ വരെ ഓരോ കീ ശതമാനം ഷെയറുകളും ശതമാനം ക്യാപ്സും നിർബന്ധമാക്കപ്പെടുന്നില്ല. റീസെറ്റ് സമയമില്ലാതെ, പുസ്തകം മാറ്റിയ അവസാന വായന കഴിഞ്ഞ് 15 മിനിറ്റിന് ശേഷം ഇത് ആരംഭിക്കുന്നു.
- Redis സ്റ്റോറിൽ, 60 ദിവസത്തേക്ക് നിഷ്ക്രിയമായ ഒരു പുസ്തകം ഒരു എഴുത്തുകാരൻ്റെ ചെക്കിനും അതിൻ്റെ റൈറ്റിനുമിടയിൽ കാലഹരണപ്പെടും. 1-ന് മുകളിലുള്ള ഒരു പുനരവലോകനത്തിൽ ഇത് വീണ്ടും സൃഷ്ടിക്കപ്പെടുന്നു, ഇത് ഒരു സാധുവായ അവസ്ഥയാണ്.

## പൈപ്പ്ലൈൻ സംയോജനം

### PRE ഹുക്ക് (`open-sse/handlers/chatCore.ts`)

ഓത്ത്, പോളിസി പരിശോധനകൾക്ക് ശേഷം അപ്സ്ട്രീം എക്സിക്യൂട്ടറിന് മുമ്പായി പ്രവർത്തിക്കുന്നു:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → getQuotaStore().peek() per dimension
      → fairShare.decideFairShare()
      → if block → return 429 (buildErrorBody, Hard Rule #12)
      → if allow + deprioritize → set quotaSoftPenalty=true on candidate
  → executor.execute()
```

**പരാജയം-ഓപ്പൺ** : `enforceQuotaShare` എറിയുകയാണെങ്കിൽ, ഒരു `pino.warn` ലോഗ് ഉപയോഗിച്ച് അഭ്യർത്ഥന അനുവദിക്കും. ഇത് എല്ലാ ട്രാഫിക്കും തടയുന്നതിൽ നിന്ന് ഒരു ക്വാട്ട-എഞ്ചിൻ ബഗ് തടയുന്നു.

**ശേഷി തിരികെ വരുമ്പോൾ.** കീയുടെ ഷെയറിലോ പൂൾ സീലിംഗിലോ ഉള്ള വിസമ്മതം രണ്ട് വാചകങ്ങളിൽ ഒന്നിൽ അവസാനിക്കുന്നു, രണ്ട് വായ്പാ രീതികളിലും:

- `percent` വിൻഡോ: `. The <window> window resets at <time>.` ദാതാവിൻ്റെ റിപ്പോർട്ടുകൾ പുനഃസജ്ജമാക്കാനുള്ള സമയമാണ്.
- എണ്ണാവുന്ന യൂണിറ്റ്: `. Enough <window> usage is expected to clear by <time>.` കീ മറ്റൊന്നും അയയ്ക്കുന്നില്ലെങ്കിൽ, സ്ലൈഡിംഗ് വിൻഡോയിൽ നിന്നുള്ള ഒരു മുകൾ പരിധിയാണ് സമയം.

`<time>` എന്നത് UTC ൽ ഒരു ISO 8601 തൽക്ഷണമാണ്. നിരസിക്കൽ പിന്നീട് `Retry-After` വഹിക്കുന്നു : ആ തൽക്ഷണം വരെയുള്ള മുഴുവൻ സെക്കൻഡുകളും പ്ലസ് വൺ. ദീർഘനേരം കാത്തിരിക്കുന്ന ഒരു ക്ലയൻ്റ് തൽക്ഷണത്തിന് ശേഷം പരമാവധി ഒരു സെക്കൻഡ് വീണ്ടും ശ്രമിക്കും. തൽക്ഷണം അറിയാത്തപ്പോൾ, നിരസിക്കൽ വാക്യമോ തലക്കെട്ടോ വഹിക്കുന്നില്ല. ഒരു സമ്പൂർണ്ണ തൊപ്പി നിരസിക്കൽ രണ്ടും വഹിക്കുന്നില്ല. പൊതു കോഡ് `quota_share_blocked` തുടരുന്നു.

ഒരു ഷെയർ നിരസനം പങ്കിട്ട കണക്ഷനെ സ്പർശിക്കില്ല. ഇത് കൂൾഡൗണും മോഡൽ ലോക്കും പ്രൊവൈഡർ ബ്രേക്കർ പരാജയവും സജ്ജീകരിക്കുന്നില്ല, കൂടാതെ പൂളിൻ്റെ മറ്റ് കീകൾ സേവനം തുടരുന്നു. ഒരു കോംബോയുടെ ഓരോ ലക്ഷ്യവും അതിൻ്റെ ഷെയറിനുള്ള താക്കോൽ നിരസിക്കുമ്പോൾ, കോംബോ കാത്തിരിക്കാതെ 429 ഉത്തരം നൽകുന്നു. അതിൻ്റെ ഉത്തരത്തിൽ `Retry-After` എന്ന സൂചനയുണ്ട്. എംബെഡിംഗ്സ് പാത്ത് അതേ വാക്യത്തിൽ അതിൻ്റെ നിരസനം അവസാനിപ്പിക്കുകയും `Retry-After` അയയ്ക്കാതിരിക്കുകയും ചെയ്യുന്നു.

### POST ഹുക്ക് (റെക്കോർഡ് ഉപഭോഗം)

വിജയകരമായ പ്രതികരണത്തിന് ശേഷം:

```
executor returns success
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → getQuotaStore().consume() per dimension
      → fail-open: errors logged as pino.warn, never propagated to client
```

**ഡ്രിഫ്റ്റ് നോട്ട്** : പ്രതികരണത്തിന് ശേഷം `consume` പരാജയപ്പെടുകയാണെങ്കിൽ, റോളിംഗ് കൗണ്ടർ എണ്ണത്തിൽ താഴെയാകും. ദാതാവിൽ നിന്നുള്ള സാച്ചുറേഷൻ സിഗ്നൽ (ഉദാ `anthropic-ratelimit-unified-5h-utilization`) അടുത്ത അഭ്യർത്ഥനയിൽ ആഗോള എസ്റ്റിമേറ്റ് ശരിയാക്കുന്നു.

### കോംബോ സോഫ്റ്റ് പെനാൽറ്റി (`open-sse/services/combo.ts`)

എപ്പോൾ `decision.deprioritize === true`:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // default 0.7
}
```

മറ്റെല്ലാ സ്കോറിംഗ് ഘടകങ്ങൾക്കും ശേഷമാണ് പെനാൽറ്റി പ്രയോഗിക്കുന്നത്. ഇത് ഹാർഡ്-ബ്ലോക്ക് ചെയ്യാതെ ഒരു പൂരിത കീ തിരഞ്ഞെടുക്കുന്നതിനുള്ള ഓട്ടോ-കോംബോ പ്രോബബിലിറ്റി കുറയ്ക്കുന്നു.

- `usePoolUsage` — ആവശ്യാനുസരണം `GET /api/quota/pools/[id]/usage` ലഭ്യമാക്കുന്നു.
- ലെഗസി LS ഡാറ്റ മൈഗ്രേറ്റ് ചെയ്യുന്നതിന്`useLocalStoragePoolMigration` — മൗണ്ടിൽ ഒരിക്കൽ പ്രവർത്തിക്കുന്നു.

പൂൾ വിസാർഡിൻ്റെ കീ സ്റ്റെപ്പിൽ ഒരു `Show usage by member to key holders` ബോക്സ് ഉണ്ട്. ഇത് പൂളിൻ്റെ `memberBreakdown` ഓപ്ഷൻ സജ്ജമാക്കുന്നു ( [അംഗങ്ങളുടെ ഉപയോഗം](#member-usage) കാണുക). അതിന് താഴെ, ഒരു കീ എന്താണ് ഉപയോഗിച്ചതെന്ന് അറിയാവുന്ന ഒരാൾക്ക് ആ കീയുമായി ഒരു ബാർ പൊരുത്തപ്പെടുത്താൻ കഴിയുമെന്ന് വിസാർഡ് മുന്നറിയിപ്പ് നൽകുന്നു. ബോക്സ് ടിക്ക് ചെയ്താൽ, സ്റ്റെപ്പ് മൂന്നിൽ താഴെയോ 20-ൽ കൂടുതൽ കീകളോ ലിസ്റ്റ് ചെയ്യുമ്പോൾ ബാറുകൾ മറഞ്ഞിരിക്കുന്നതിനാൽ അത് പറയുന്നു. ഇത് സ്റ്റെപ്പിലെ കീകൾ കണക്കാക്കുന്നു, അവയിൽ ഏതാണ് അഭ്യർത്ഥനകൾ നടത്താൻ കഴിയുക എന്ന് പറയാൻ കഴിയില്ല.

### `/dashboard/costs/quota-share/plans` — പ്രൊവൈഡർ പ്ലാൻ കോൺഫിഗറേഷൻ

- `ProviderPlanConfigClient.tsx`: ഒരു ദാതാവിനെ തിരഞ്ഞെടുക്കുന്നതിനും പരിഹരിച്ച പ്ലാൻ കാണുന്നതിനും (കാറ്റലോഗിൽ നിന്നോ മാനുവൽ ഓവർറൈഡിൽ നിന്നോ സ്വയമേവ), അളവുകൾ എഡിറ്റുചെയ്യുന്നതിന് ഡ്രോപ്പ്ഡൗൺ ചെയ്യുക.
- മാറ്റങ്ങൾ `PUT /api/quota/plans/[connectionId]` ലേക്ക് എഴുതുന്നു.
- ഇല്ലാതാക്കൽ കാറ്റലോഗിലേക്കോ ശൂന്യമായ പ്ലാനിലേക്കോ മടങ്ങുന്നു.

## സ്വയം-സേവന ക്വാട്ട API (ഓപ്റ്റ്-ഇൻ)

`GET /api/v1/me/quota/{provider}` ( `/v1/me/quota/{provider}` യിലും നൽകുന്നു) ഒരു API കീ ഹോൾഡറെ അവരുടെ സ്വന്തം കീ ഉപയോഗിച്ച്, എത്രത്തോളം പങ്കിട്ട സബ്സ്ക്രിപ്ഷൻ അവരുടേതാണെന്നും എന്താണ് അവരെ തടയുന്നതെന്നും വായിക്കാൻ അനുവദിക്കുന്നു. റൂട്ട് `src/server/selfService/quotaHandler.ts` ന് മുകളിൽ ഒരു നേർത്ത ഷെൽ ആണ്; കാഴ്ച നിർമ്മിച്ചിരിക്കുന്നത് `src/lib/quota/selfView.ts` ആണ്, അതിൻ്റെ പ്രതികരണ കരാർ `src/shared/schemas/selfQuota.ts` ആണ് (`SelfQuotaView` in `docs/openapi.yaml`).

### പ്രവർത്തനക്ഷമമാക്കലും പ്രാമാണീകരണവും

- ഫീച്ചർ ഫ്ലാഗ് `QUOTA_SELF_PANEL`, ഡിഫോൾട്ട് `false`. ഇത് ഓഫായിരിക്കുമ്പോൾ, റൂട്ടിൽ എത്തുന്ന ഒരു അഭ്യർത്ഥനയ്ക്ക് 404 ലഭിക്കും. `REQUIRE_API_KEY=true` ഉപയോഗിച്ച്, ക്ലയൻ്റ് API നയം ഫ്ലാഗ് എന്തായാലും റൂട്ട് ഓടുന്നതിന് മുമ്പ് 401 ഉള്ള ഒരു നഷ്ടമായതോ അസാധുവായതോ ആയ കീ നിരസിക്കുന്നു. സൈൻ ഇൻ ചെയ്ത ഡാഷ്ബോർഡ് സെഷനുള്ള കീ ഇല്ലാത്ത ഒരു അഭ്യർത്ഥന ആ നയം പാസാക്കുകയും റൂട്ടിൻ്റെ സ്വന്തം ഉത്തരം നേടുകയും ചെയ്യുന്നു. മറ്റെല്ലാ ഫ്ലാഗും പോലെ ഫ്ലാഗ് പരിഹരിക്കുന്നു (ഡാഷ്ബോർഡ് അല്ലെങ്കിൽ REST അസാധുവാക്കൽ, തുടർന്ന് അതേ പേരിലുള്ള എൻവയോൺമെൻ്റ് വേരിയബിൾ); [`FEATURE_FLAGS.md`](../reference/FEATURE_FLAGS.md) കാണുക.
- ഓരോ പൂളിൻ്റെയും പ്രദർശന നാമവും ഓരോ ഷെഡ്യൂളിൻ്റെ ലേബലും അഡ്മിനിസ്ട്രേറ്റർ എഴുതിയതുപോലെ തന്നെ പൂളിൻ്റെ കീ ഹോൾഡർമാർക്ക് തിരികെ നൽകും. ഫ്ലാഗ് ഓണാക്കുന്നതിന് മുമ്പ്, ആ കീ ഹോൾഡർമാർക്ക് അവ വായിക്കാൻ അനുയോജ്യമാണോയെന്ന് പരിശോധിക്കുക.
- കീ തലക്കെട്ടുകളിൽ നിന്ന് മാത്രം വായിക്കുന്നു: `Authorization: Bearer <key>` അല്ലെങ്കിൽ `x-api-key: <key>`. രണ്ടും അയയ്ക്കുമ്പോൾ, സാധൂകരിക്കുന്ന ആദ്യത്തേത് ഉപയോഗിക്കും. അന്വേഷണ സ്ട്രിംഗിലെ ഒരു കീ അല്ലെങ്കിൽ ഒരു കുക്കി അവഗണിക്കപ്പെട്ടു. സെർവറിൻ്റെ പരിസ്ഥിതി കീ നിരസിക്കപ്പെട്ടു (401).
- കീയ്ക്ക് `self:usage` സ്കോപ്പ് ആവശ്യമാണ് (അത് കൂടാതെ 403).
- പ്രൊവൈഡർ സെഗ്മെൻ്റ് ട്രിം ചെയ്യുകയും ലോവർ കെയ്സ് ചെയ്യുകയും `^[a-z0-9][a-z0-9._-]{0,63}$` പരിശോധിക്കുകയും ചെയ്യുന്നു (അല്ലെങ്കിൽ 400), തുടർന്ന് ദാതാവിൻ്റെ രജിസ്ട്രി വഴി പരിഹരിക്കുന്നു, അതിനാൽ `cc` പോലുള്ള ഒരു അപരനാമം `claude` പൂളുകൾ വായിക്കുന്നു. `claude`, `anthropic` ഒരേ പൂളുകൾ വായിക്കുന്നു.

### ഓരോ ദൃശ്യപരതയും എന്താണ് കാണിക്കുന്നത്

| ദൃശ്യപരത      | ആവശ്യമാണ്                                                                 | വയലുകൾ                                                                                                                                                                                                                                                            |
| ------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| സ്വന്തം പങ്ക് | `self:usage`                                                              | `pools[]` (ref, പേര്, ദാതാവ്, നയം, ഭാരം, തൊപ്പി), `dimensions[].yourShare`, `accounts[]` `yourShare` ( `attributed` ഉം `external` ഉം ഇല്ലാത്ത ഒരു `percent` വിൻഡോയിൽ), `blocks`, `availableModels`, `expiresAt`, `apiBaseUrl`                                     |
| അക്കൗണ്ട് നില | `self:usage` + `self:account-quota`, കീയുടെ `sharedQuotaProviders` ദാതാവ് | ഒരു `percent` വിൻഡോയുടെ `yourShare` ൽ `dimensions[].total`, `accounts[].dimensions[].account`, `accounts[].modelWindows`, `attributed`, `external` എന്നിവയും അംഗങ്ങളുടെ ഉപയോഗമുള്ള ഒരു പൂളിൽ `members` ഉം ചേർക്കുന്നു ( [അംഗങ്ങളുടെ ഉപയോഗം](#member-usage) കാണുക) |

- `sharedQuotaProviders` എന്നത് ഓരോ കീ ക്രമീകരണമാണ് (`PUT /api/keys/[id]/self-service`): `null`, ഡിഫോൾട്ട്, കീ എത്തുന്ന എല്ലാ ദാതാക്കളെയും അർത്ഥമാക്കുന്നു; `[]` എന്നാൽ ഒന്നുമില്ല. ഓരോ പൂളിൻ്റെയും `accountVisible` അതിന് ഏത് ദൃശ്യപരതയാണ് ബാധകമാക്കിയതെന്ന് പറയുന്നു.
- കീ ഉപയോഗിച്ചേക്കാവുന്ന കണക്ഷനുള്ള അക്കൗണ്ടുകൾക്ക് മാത്രമാണ് അക്കൗണ്ട് ബാറുകളും മോഡൽ വിൻഡോകളും കാണിക്കുന്നത്. കീയിൽ അനുവദനീയമായ കണക്ഷനുകളുടെ ഒരു ലിസ്റ്റ് ഉണ്ടെങ്കിൽ, അതിന് പുറത്തുള്ള ഒരു അക്കൗണ്ട് അതിൻ്റെ `Account N` എൻട്രി `account` അല്ലെങ്കിൽ `modelWindows` ഇല്ലാതെ സൂക്ഷിക്കുന്നു. ഒരു ശൂന്യമായ ലിസ്റ്റ് അർത്ഥമാക്കുന്നത്, `/v1/me/status` പോലെ യാതൊരു നിയന്ത്രണവുമില്ല എന്നാണ്. പൂൾ മൊത്തം (`dimensions[].total`) ആ പട്ടികയെ ആശ്രയിക്കുന്നില്ല.
- `self:usage` ഉപയോഗിച്ച് മാത്രം കാണിച്ചിരിക്കുന്ന രണ്ട് അക്കങ്ങൾ മറ്റ് കീകളുടെ ഉപയോഗത്തിൽ നിന്നാണ് വരുന്നത്. ഒരു ഷെഡ്യൂൾ ബജറ്റിൻ്റെ `exhausted` ആ ഷെഡ്യൂളിന് കീഴിലുള്ള ഓരോ കീയുടെയും ഉപഭോഗത്തെ പ്രതിഫലിപ്പിക്കുന്നു. ഭാരങ്ങളെല്ലാം പൂജ്യമായ ഒരു കുളത്തിൽ, കീയുടെ `weight` `100 / number of members` ആണ്. രണ്ടും എൻഫോഴ്സ്മെൻ്റ് കീക്ക് ബാധകമാണ്.
- കോളിംഗ് കീയുമായി ബന്ധിപ്പിച്ചിരിക്കുന്ന അതാര്യമായ മൂല്യമായ `ref` കൊണ്ടാണ് ഒരു പൂൾ തിരിച്ചറിയുന്നത്. അഡ്മിനിസ്ട്രേറ്റർ എഴുതിയതുപോലെ അതിൻ്റെ പ്രദർശന നാമം (`name`) ഉൾപ്പെടുത്തിയിട്ടുണ്ട്. സെർവറിൻ്റെ API-കീ രഹസ്യം (`API_KEY_SECRET`) ഉള്ള കീയിൽ നിന്നും പൂളിൽ നിന്നും ഒരു `ref` ഉരുത്തിരിഞ്ഞതാണ്. ഉപഭോക്താക്കൾ ഇത് തുടരരുത്: ആ രഹസ്യം തിരിക്കുകയാണെങ്കിൽ അത് മാറുന്നു.
- പൂൾ ക്രമത്തിൽ അക്കൗണ്ടുകൾ `Account 1`, `Account 2`, … എന്നിങ്ങനെ ലിസ്റ്റ് ചെയ്തിരിക്കുന്നു. പൂൾ ഐഡിയോ കണക്ഷൻ ഐഡിയോ അക്കൗണ്ട് ഇ-മെയിലോ അക്കൗണ്ടിൻ്റെ പേരോ തിരികെ നൽകുന്നില്ല, പ്രതികരണം കരാർ സ്കീമയിലൂടെ കടന്നുപോകുന്നു, അത് അതിന് പുറത്തുള്ള ഏതെങ്കിലും ഫീൽഡ് ഒഴിവാക്കുന്നു.
- ക്വാട്ട ഗേറ്റ് നടപ്പിലാക്കുന്ന പൂൾ ബക്കറ്റായി കണക്കാക്കാവുന്ന യൂണിറ്റുകൾ (`requests`, `tokens`, `usd`) റിപ്പോർട്ട് ചെയ്യപ്പെടുന്നു: `limit` = പ്ലാൻ പൂളിലെ × അക്കൗണ്ടുകൾ പരിധി, `fairShare` = ഭാരം / 100 × `limit` (തുല്യമായി വിഭജിക്കുക), ഓരോ ഭാരവും കീയിൽ സ്വന്തമാകുമ്പോൾ ക്വാട്ട സ്റ്റോർ, `remaining` = `consumed` `fairShare` = `consumed` 0 − ൽ നിലയുറപ്പിച്ചിരിക്കുന്നു.
- `blocks.schedules` കീയുടെ ഷെഡ്യൂൾ വിൻഡോകൾ പട്ടികപ്പെടുത്തുന്നു (`open`/`closed`, `blackout` അല്ലെങ്കിൽ `outside-window`, `retryAfterSeconds`, റിസർവ് നിലകൾ, കൂടാതെ വിൻഡോയുടെ ബജറ്റ് ചെലവഴിച്ചിട്ടുണ്ടോ); `blocks.modelCaps` അതിൻ്റെ ഓരോ-മോഡൽ മണിക്കൂർ ക്യാപ്സ് ഉപഭോഗത്തിനൊപ്പം ലിസ്റ്റ് ചെയ്യുന്നു.
- ദാതാവിൻ്റെ എല്ലാ പൂളിന് പുറത്തുള്ള ഒരു കീയ്ക്കും `pools: []` ഉപയോഗിച്ച് 200 ലഭിക്കുന്നു; `availableModels` ( `qtSd/` ൽ കീ കാണുന്ന `/v1/models` ഐഡികൾ), `expiresAt`, `apiBaseUrl` ഇപ്പോഴും നിറഞ്ഞിരിക്കുന്നു.
- `apiBaseUrl` `OMNIROUTE_PUBLIC_API_BASE_URL` ആണ്, പിന്നെ `OMNIROUTE_PUBLIC_BASE_URL`, else `null`. ഇത് ഒരിക്കലും അഭ്യർത്ഥനയുടെ സ്വന്തം ഉത്ഭവമല്ല.

### വായ്പ സമ്മതം

ഒരു പൂളിനുള്ള കോളിംഗ് കീയുടെ സ്വന്തം സമ്മതം`PATCH /api/v1/me/quota/{provider}` രേഖപ്പെടുത്തുന്നു. ഇത് `GET` യുടെ ഫ്ലാഗ്, ഹെഡറുകൾ, പ്രൊവൈഡർ നിയമങ്ങൾ എന്നിവ ഉപയോഗിക്കുന്നു. `self:usage` സ്കോപ്പ് ഇത് എഴുതുന്നതിന് അംഗീകാരം നൽകുന്നു, എന്നിരുന്നാലും അതിൻ്റെ പേര് വായിക്കാൻ മാത്രമായി വായിക്കുന്നു.

```json
{
  "pool": "qpr_0123456789abcdef0123456789abcdef",
  "lendingPercent": 30,
  "lendingUntil": 1893456000000
}
```

- `pool` എന്നത് `ref` ആണ്, ആ പൂളിനായി `GET` തിരികെ നൽകുന്നു.
- `lendingPercent` എന്നത് 0 മുതൽ 100 വരെയുള്ള ഒരു പൂർണ്ണസംഖ്യയാണ്. 0 ൻ്റെ മൂല്യം സമ്മതവും അതിൻ്റെ സമയപരിധിയും മായ്ക്കുന്നു. `lendingPercent` 0 ഉള്ള ഒരു ബോഡി രണ്ട് മോഡിലും സ്വീകരിക്കപ്പെടും.
- `lendingUntil` ഓപ്ഷണൽ ആണ്: എപ്പോച്ച് മില്ലിസെക്കൻഡ്, അല്ലെങ്കിൽ സമയപരിധിയില്ലാത്ത `null`. ഇത് ഭാവിയിലായിരിക്കണം, പരമാവധി 8640000000000000. 1000000000000 എന്ന മൂല്യത്തിൽ താഴെയുള്ള മൂല്യം സെക്കൻഡുകളായി വായിക്കുകയും നിരസിക്കുകയും ചെയ്യുന്നു.
- മറ്റേതെങ്കിലും മേഖല നിരസിക്കപ്പെട്ടു. 4096 ബൈറ്റുകളിൽ കൂടുതൽ നീളമുള്ള ഒരു ബോഡി നിരസിക്കപ്പെട്ടു. ആ വലുപ്പത്തിൽ വായന നിർത്തുന്നു, അതിനാൽ നീളമുള്ള ശരീരം ഒരിക്കലും മുഴുവനായി പിടിക്കില്ല.

ഈ പട്ടികയുടെ ക്രമത്തിലാണ് പരിശോധനകൾ പ്രവർത്തിക്കുന്നത്. ഓരോ നിരസിക്കലും ഒരു നിശ്ചിത സന്ദേശത്തോടുകൂടിയ സാധാരണ പിശക് ബോഡി ഉപയോഗിക്കുന്നു. ഈ ചെക്കുകളിൽ ഒന്ന് നിരസിക്കുന്നത് ഒന്നും എഴുതുന്നില്ല.

| നില | സന്ദേശം                                                                                            | എപ്പോൾ                                                                        |
| --- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 404 | `Not found`                                                                                        | `QUOTA_SELF_PANEL` ഫ്ലാഗ് ഓഫ് ചെയ്തു.                                          |
| 401 | `Valid API key required`                                                                           | കീ കാണുന്നില്ല അല്ലെങ്കിൽ അസാധുവാണ്, അല്ലെങ്കിൽ സെർവറിൻ്റെ പരിസ്ഥിതി കീ ആണ്.   |
| 403 | `API key lacks the self:usage scope`                                                               | കീയിൽ `self:usage` ഇല്ല.                                                       |
| 400 | `Invalid provider`                                                                                 | ദാതാവിൻ്റെ സെഗ്മെൻ്റ് അസാധുവാണ്.                                               |
| 429 | `Too many lending changes. Retry later.`                                                           | കീ അതിൻ്റെ പരിധി കടന്നു. ഉത്തരം `Retry-After` വഹിക്കുന്നു.                     |
| 400 | `Body must be { pool, lendingPercent, lendingUntil }. lendingPercent is an integer from 0 to 100.` | ശരീരം JSON അല്ല, ദൈർഘ്യമേറിയതാണ്, അല്ലെങ്കിൽ സ്കീമയുമായി പൊരുത്തപ്പെടുന്നില്ല. |
| 400 | `lendingUntil must be a Unix time in milliseconds`                                                 | സമയപരിധി സെക്കൻഡുകളായി വായിക്കുന്നു.                                           |
| 400 | `lendingUntil must be in the future`                                                               | അഭ്യർത്ഥന സമയത്തോ അതിന് മുമ്പോ ആണ് സമയപരിധി.                                   |
| 404 | `Pool not found`                                                                                   | ഈ ദാതാവിനായി `ref` ഈ കീയുടെ ഒരു പൂളിനും പേരിടുന്നില്ല.                         |
| 403 | `Lending is not enabled for this pool`                                                             | പൂൾ `saturation` മോഡിലും `lendingPercent` 0-ന് മുകളിലുമാണ്.                    |
| 500 | `Failed to build quota view`                                                                       | മറ്റേതെങ്കിലും പരാജയം. അതിൻ്റെ കാരണം സെർവറിൽ ലോഗിൻ ചെയ്തിരിക്കുന്നു.           |

ഓരോ കീയ്ക്കും 60 സെക്കൻഡിൽ 20 അഭ്യർത്ഥനകളാണ് പരിധി. പ്രൊവൈഡർ ചെക്ക് പാസ്സാകുന്ന എല്ലാ അഭ്യർത്ഥനകളും കണക്കാക്കുന്നു, ഒന്ന് പോലും പിന്നീട് നിരസിച്ചതോ അല്ലെങ്കിൽ ഒന്നും മാറ്റാത്തതോ ആണ്. കീയുടെ അഭ്യർത്ഥന നിരക്ക് പരിധി കൂടാതെ ഇതിന് അതിൻ്റേതായ കൗണ്ടർ ഉണ്ട്.

സംഭരിച്ച സമ്മതം മാറ്റുന്ന ഒരു അഭ്യർത്ഥന ഒരു `quota.pool.lending.updated` ഓഡിറ്റ് റെക്കോർഡ് എഴുതുന്നു. ഇത് പഴയതും പുതിയതുമായ മൂല്യങ്ങൾ ഉപയോഗിച്ച് കീയെ നാമകരണം ചെയ്യുന്നു. ഒരേ ബോഡി രണ്ടുതവണ അയച്ചു, ഒരിക്കൽ എഴുതുകയും ഒരു തവണ ഓഡിറ്റ് ചെയ്യുകയും ചെയ്യുന്നു. എഴുതിയതിന് ശേഷം നിർമ്മിച്ച മുഴുവൻ `GET` കാഴ്ചയ്ക്കൊപ്പം 200 എന്നാണ് ഉത്തരം.

വായ്പ നൽകുന്നതിനെ `GET` വ്യൂ ഇനിപ്പറയുന്ന രീതിയിൽ റിപ്പോർട്ട് ചെയ്യുന്നു:

- ഓരോ പൂളിലും `borrowMode` (`saturation` അല്ലെങ്കിൽ `consent`), കീയുടെ സ്വന്തം `lendingPercent`, `lendingUntil` എന്നിവയുണ്ട്.
- `lendingActive` എന്നത് `true` ആണ്, ഒരു `consent` പൂളിൽ മാത്രമാണ്, 0-ന് മുകളിലുള്ള ശതമാനവും സമയപരിധിയിൽ എത്തിയിട്ടില്ല.
- ഒരു `consent` പൂളിൽ, ഓരോ എണ്ണാവുന്ന `dimensions[].yourShare` `borrowAvailable` വഹിക്കുന്നു. കീ അതിൻ്റെ ഷെയറിന് മുകളിൽ ഇപ്പോൾ ഉപയോഗിച്ചേക്കാവുന്നത് ഇതാണ്, മറ്റ് കീകൾ നൽകിയത്.
- `borrowAvailable` ഗേറ്റിൻ്റെ ഫോർമുല ഉപയോഗിക്കുന്നു. കീ അതിൻ്റെ ഷെയറിനു കീഴിലായിരിക്കുമ്പോൾ, അത് മറ്റെല്ലാ കീയും വായിക്കുന്നു. ഒരു `hard` കീയ്ക്ക്, മറ്റൊരു കീയ്ക്ക് ഒരു അധിക റീഡും കണക്കാക്കാവുന്ന അളവും സമാന്തരമായി.
- `borrowAvailable` എന്നത് ഒരു `soft` അല്ലെങ്കിൽ `burst` കീയുടെ `null` ആണ്, ഒരു റീഡ് പരാജയപ്പെടുമ്പോൾ `null`.
- `borrowAvailable` എന്നത് മറ്റെല്ലാ കീകൾക്കും ഒരുമിച്ച് ഒരു സംഖ്യയാണ്. രണ്ട് കീകളുള്ള ഒരു പൂളിൽ അത് മറ്റേ കീയുടെ സ്വന്തം രൂപമാണ്.
- `percent` വിൻഡോകൾക്കോ `accounts[]` യിലോ ഇതുവരെ`borrowAvailable` റിപ്പോർട്ട് ചെയ്തിട്ടില്ല.
- ഒരു `saturation` പൂളിൽ, `lendingActive: false` കൂടാതെ `borrowAvailable` ഇല്ലാതെ സംഭരിച്ച സമ്മതം കാഴ്ച റിപ്പോർട്ട് ചെയ്യുന്നു.

### പിശകുകൾ

ഈ റൂട്ടിൻ്റെ ഓരോ പ്രതികരണവും, വിജയമോ പിശകോ, `Cache-Control: no-store` വഹിക്കുന്നു. റൂട്ട് റൺ ചെയ്യുന്നതിനുമുമ്പ് സംഭവിക്കുന്ന ഒരു നിരസിക്കൽ അത് വഹിക്കില്ല, ഉദാഹരണത്തിന് ക്ലയൻ്റ് API പോളിസിയുടെ 401 അല്ലെങ്കിൽ IP ഫിൽട്ടറിൻ്റെ 403. റൂട്ടിലെ പിശകുകൾ ഒരു നിശ്ചിത സന്ദേശത്തോടൊപ്പം സ്റ്റാൻഡേർഡ് പിശക് ബോഡി ഉപയോഗിക്കുന്നു: 400 (അസാധുവായ ദാതാവ്), 401 (കാണാതായതോ അസാധുവായതോ ആയ കീ), 403 (നഷ്ടമായതോ അസാധുവായതോ ആയ `self:usage`), 403 (അഗ്ഫ്ലഡ്, 40, 40)`Failed to build quota view`). അഭ്യർത്ഥന റൂട്ടിൽ എത്തിക്കഴിഞ്ഞാൽ, കീ ലുക്ക്അപ്പ് ഉൾപ്പെടെ ഏത് പരാജയവും 500 കവർ ചെയ്യുന്നു; അതിൻ്റെ കാരണം സെർവറിൽ ലോഗിൻ ചെയ്തിരിക്കുന്നു, ഒരിക്കലും തിരികെ വന്നില്ല. `PATCH` ൻ്റെ പിശകുകൾ [ലെൻഡിംഗ് സമ്മതത്തിൽ](#lending-consent) ലിസ്റ്റ് ചെയ്തിരിക്കുന്നു.

### പരിമിതികൾ

- കീയുടെ ഫെയർ ഷെയറിൻ്റെ ഭാഗമാണ്`remaining` അത് ഉപയോഗിച്ചിട്ടില്ല. അത് ഒരു ഗ്യാരണ്ടി അല്ല. കുളത്തിന് ഇടമുള്ളപ്പോൾ അതിനപ്പുറം താക്കോൽ നൽകാം. പൂളിൻ്റെ ആകെത്തുക `limit` എത്തിയാൽ, പൂളിൻ്റെ ഓരോ കീയും നിരസിക്കപ്പെടും, സ്വന്തം `remaining` എന്തായാലും, `self:account-quota` ഇല്ലാത്ത ഒരു കീക്ക് ആ ആകെത്തുക കാണാൻ കഴിയില്ല.
- `remaining` അലോക്കേഷൻ്റെ സമ്പൂർണ്ണ `cap` കണക്കിലെടുക്കുന്നില്ല. തൊപ്പിയുടെ യൂണിറ്റിൻ്റെ ഒരു വിൻഡോയിലെ സ്വന്തം ഉപഭോഗം തൊപ്പിയുടെ മൂല്യത്തിൽ എത്തിയാൽ എൻഫോഴ്സ്മെൻ്റ് കീ നിരസിക്കുന്നു.
- അക്കൌണ്ട്-ലെവൽ ബാർ ദാതാവിൻ്റെ പരിധി കാഷെയിൽ നിന്നാണ് വരുന്നത്, ഇത് നടപ്പാക്കൽ തീരുമാനത്തെ കുറച്ച് മിനിറ്റ് വൈകിപ്പിക്കും. റീസെറ്റ് സമയം കഴിഞ്ഞ ഒരു റീഡിങ്ങ് `stale` ആയി റിപ്പോർട്ട് ചെയ്യപ്പെടുന്നു.
- ഒരു പ്ലാൻ-വിൻഡോ മാപ്പിംഗ് ഉള്ള ദാതാക്കൾക്കായി മാത്രമാണ് ഓരോ മോഡൽ വിൻഡോകൾ (`modelWindows`) റിപ്പോർട്ട് ചെയ്യുന്നത്: Claude, Codex ഇന്ന്. മറ്റ് ദാതാക്കൾക്കായി, ശൂന്യമായ `windows` ലിസ്റ്റിൽ അക്കൗണ്ട് ഡാറ്റ കാണിക്കുമ്പോൾ `modelWindows` നിലവിലുണ്ട്.
- ഒരു `percent` വിൻഡോയുടെ കീയുടെ സ്വന്തം പങ്ക് ഒരു എസ്റ്റിമേറ്റ് ആണ്. ഇത് ആട്രിബ്യൂഷൻ ബുക്കിൽ നിന്നാണ് വരുന്നത് കൂടാതെ മുകളിലുള്ള "ശതമാനം അളവുകൾ: ഓരോ കീ ആട്രിബ്യൂഷനും" എന്നതിന് കീഴിൽ ലിസ്റ്റ് ചെയ്തിരിക്കുന്ന എല്ലാ പരിമിതികളും വഹിക്കുന്നു.
- ഫെയർ ഷെയറുമായി താരതമ്യം ചെയ്യുന്ന സംഖ്യ എൻഫോഴ്സ്മെൻ്റാണ്`consumed`. ഇത് `attributed` പ്ലസ് `external` ആണ്, കൃത്യമായി. പുസ്തകം റൂട്ട് ചെയ്ത ടോക്കണുകളുടെ താക്കോൽ നൽകുന്ന ഭാഗമാണ് `attributed`. പൂളിൻ്റെ കീകൾ കണക്കിലെടുക്കാത്ത അക്കൗണ്ടിൻ്റെ ഉപയോഗത്തിൻ്റെ കീയുടെ ഭാഗമാണ് `external`.
- പൂളിൻ്റെ `accountVisible` സത്യമായിരിക്കുമ്പോൾ മാത്രമേ രണ്ട് ഭാഗങ്ങളും അയയ്ക്കുകയുള്ളൂ: കീയിൽ `self:account-quota` ഉണ്ട്, ദാതാവ് അതിൻ്റെ `sharedQuotaProviders`. അതില്ലാത്ത ഒരു കീയ്ക്ക് ഒരേ `status`, `reason` എന്നിവ ഉപയോഗിച്ച് `consumed` മാത്രം ലഭിക്കും.
- രണ്ട് ഭാഗങ്ങളും അതിൻ്റെ സ്വന്തം ഭാരവും ഉപയോഗിച്ച്, ഒരു ഹോൾഡർക്ക് പൂളിൻ്റെ കീകളിലേക്ക് ചാർജ് ചെയ്യപ്പെടുന്ന പൂളിന് പുറത്ത് ഉണ്ടാക്കിയ ഉപയോഗം പ്രവർത്തിക്കാൻ കഴിയും. അക്കൗണ്ട് സ്കോപ്പുള്ള ഒരു ഹോൾഡർ ഇതിനകം തന്നെ അക്കൗണ്ട് മൊത്തത്തിൽ കാണുന്നു.
- ജാലകത്തിൽ ഒന്നും റൂട്ട് ചെയ്യാത്ത ഒരു കീക്ക് ഇപ്പോഴും `consumed` യിൽ നിന്ന് അതിൻ്റെ ബാഹ്യ ചാർജ് വായിക്കാൻ കഴിയും, കാരണം അതിൻ്റെ ആട്രിബ്യൂട്ട് ഭാഗം 0 ആണ്.
- ഉദാഹരണത്തിന്, ഒരു പുസ്തകം 0-ൽ തുറക്കുന്നു, A, B എന്നീ കീകൾ 50 വീതം ഭാരത്തിൽ. കീ എ റൂട്ടുകൾ 900,000 ടോക്കണുകളും കീ ബി 100,000 ഉം. അക്കൗണ്ട് അപ്പോൾ 100 എന്ന പരിധിയുടെ 60% എത്തുന്നു. അപ്പോൾ കീ A-യ്ക്ക് `attributed` 54 ഉം കീ B-യ്ക്ക് 6 ഉം `external` രണ്ടിനും 0 ഉം ആണ്.
- കാഴ്ച പുസ്തകം വായിക്കുന്നു, ഒരിക്കലും അതിൻ്റെ അവസ്ഥ എഴുതുന്നില്ല. അത് ഒരു പുസ്തകം തുറക്കുന്നില്ല, അത് ദാതാവിനോട് ഒരിക്കലും വായന ആവശ്യപ്പെടുന്നില്ല. Redis സ്റ്റോർ ഉപയോഗിച്ച്, ഗേറ്റിൻ്റെ റീഡുകൾ ചെയ്യുന്നതുപോലെ, പശ്ചാത്തലത്തിലുള്ള പുനരവലോകന ഫീൽഡുകൾ ഒരു റീഡ് നീക്കംചെയ്യുന്നു.
- ഗേറ്റിൻ്റെ കാഷെയിൽ അക്കൗണ്ടിൻ്റെ ഒരു റീഡിംഗ് ഉള്ളപ്പോൾ മാത്രമാണ് ഷെയർ `ok`. ഒന്നില്ലാതെ ഇത് `stale` ആണ്, അതിനാൽ സമീപകാല അഭ്യർത്ഥനകളില്ലാത്ത ഒരു പൂളിൽ ഇത് കാലഹരണപ്പെട്ടതായി കാണിക്കുന്നു.
- ഒരു അഭ്യർത്ഥന പൂളിലൂടെ കടന്നുപോകുന്നതുവരെ, പങ്കിടൽ ലഭ്യമല്ല. ആ അഭ്യർത്ഥന പുസ്തകം തുറക്കുന്നു, ആ നിമിഷത്തെ അക്കൗണ്ടിൻ്റെ കണക്ക് പൂളിന് പുറത്തുള്ള ഉപയോഗമായി കണക്കാക്കുന്നു.
- നിരവധി അക്കൗണ്ടുകളുള്ള ഒരു പൂളിൽ, ഓരോ അക്കൗണ്ട് എൻട്രിയും ആ അക്കൗണ്ടിൻ്റെ സ്വന്തം പുസ്തകവും ഒരു അക്കൗണ്ടിൻ്റെ പരിധിയും ഉപയോഗിക്കുന്നു. എൻഫോഴ്സ്മെൻ്റ് അക്കൗണ്ടുകളുടെ എണ്ണം അനുസരിച്ച് ഇരുവശങ്ങളെയും സ്കെയിൽ ചെയ്യുന്നു, അതിനാൽ അനുപാതം ഒന്നുതന്നെയാണ്.
- ഓരോ മോഡൽ ജാലകങ്ങളിലും കീയ്ക്ക് ഒരു പങ്കുമില്ല. പുസ്തകം ഓരോ മോഡൽ ഡാറ്റയും സൂക്ഷിക്കുന്നില്ല.
- ഒരു ഷെഡ്യൂളിൻ്റെ റിസർവ് നിലകൾ കാഴ്ചയാൽ വിലയിരുത്തപ്പെടുന്നില്ല: ഒരു അഭ്യർത്ഥന നിരസിക്കപ്പെടുമ്പോൾ ഒരു ഷെഡ്യൂളിന് `open` ആയി കാണിക്കാനാകും `schedule-reserve`.
- ഒരേ കീയുടെ രണ്ട് പൂളുകൾ ഒരു കണക്ഷൻ പങ്കിടുമ്പോൾ, എൻഫോഴ്സ്മെൻ്റ് അവയിലൊന്ന് പ്രയോഗിക്കുന്നു, കാഴ്ച രണ്ടും ലിസ്റ്റുചെയ്യുന്നു.
- പരാജയപ്പെട്ട കീ ശ്രമങ്ങൾക്ക് ഓരോ വിലാസത്തിനും പരിധിയില്ല: ഒരു റിവേഴ്സ് പ്രോക്സി കോളർമാർക്ക് ഒരു വിലാസം പങ്കിടാൻ കഴിയും (അത് ഫോർവേഡ് ചെയ്ത ക്ലയൻ്റ് വിലാസങ്ങൾ വിശ്വസനീയമാണോ എന്നതിനെ ആശ്രയിച്ചിരിക്കുന്നു), അതിനാൽ ലോക്കൗട്ട് എല്ലാ കീ ഹോൾഡർക്കും റൂട്ട് നിരസിച്ചേക്കാം. `REQUIRE_API_KEY=true` ഉപയോഗിച്ച്, റൂട്ട് പ്രവർത്തിക്കുന്നതിന് മുമ്പ് ക്ലയൻ്റ് API നയം ഒരു അസാധുവായ കീ നിരസിക്കുന്നു, ഈ റൂട്ടിന് പകരം ആ നയത്തിൻ്റെ 401 ബോഡി.

### അംഗങ്ങളുടെ ഉപയോഗം

പൂളിലെ അംഗങ്ങൾക്കിടയിൽ ഒരു വിൻഡോയുടെ ഉപയോഗം എങ്ങനെ വിഭജിക്കുന്നു എന്ന് കാണാൻ ഒരു അഡ്മിനിസ്ട്രേറ്റർക്ക് കീ ഹോൾഡർമാരെ അനുവദിക്കാനാകും. പൂളിൻ്റെ `memberBreakdown` ആണ് ഓപ്ഷൻ, ഡിഫോൾട്ടായി ഓഫ്. ഇത് പൂൾ വിസാർഡിലോ `PATCH /api/quota/pools/{id}` ഉപയോഗിച്ചോ സജ്ജീകരിച്ചിരിക്കുന്നു. `GET /api/quota/pools`, `GET /api/quota/pools/{id}` റിപ്പോർട്ട് ചെയ്യുന്നു.

ഇവയെല്ലാം പിടിക്കുമ്പോൾ മാത്രമേ കാഴ്ചയുടെ ഒരു മാനം `members` വഹിക്കുന്നുള്ളൂ:

- പൂളിൻ്റെ ഓപ്ഷൻ ഓണാണ്
- പൂളിന് പരമാവധി 20 അനുവദിച്ച കീകൾ ഉണ്ട്, അവയിൽ മൂന്നെണ്ണത്തിനെങ്കിലും അഭ്യർത്ഥനകൾ നടത്താം: സജീവമായത്, അസാധുവാക്കിയിട്ടില്ല, നിരോധിച്ചിട്ടില്ല, കാലഹരണപ്പെട്ടിട്ടില്ല
- പൂളിൻ്റെ `accountVisible` ശരിയാണ്: കീയിൽ `self:account-quota` ഉണ്ട്, ദാതാവ് അതിൻ്റെ `sharedQuotaProviders` ലാണ്
- ഒരു `percent` വിൻഡോയിൽ, കീ ഉപയോഗിച്ചേക്കാവുന്ന ഒന്നാണ് അക്കൗണ്ടിൻ്റെ കണക്ഷൻ
- ആ ജാലകത്തിൻ്റെ കീയുടെ സ്വന്തം പങ്ക് വായിച്ചു: അതിൻ്റെ `status` `unavailable` അല്ല

അല്ലെങ്കിൽ `members` ഇല്ല. ഇത് ഒരിക്കലും ഒരു ശൂന്യമായ പട്ടികയല്ല.

- ഓരോ സ്ലൈസും `{ slot, consumed, isYou }` ആണ്. പ്രതികരണ സ്കീമ ഒരു സ്ലൈസിലെ മറ്റേതെങ്കിലും പ്രോപ്പർട്ടി നിരസിക്കുന്നു, കൂടാതെ 20-ലധികം സ്ലൈസുകളുടെ ലിസ്റ്റും. സ്ലോട്ട് ക്രമത്തിൽ സ്ലൈസുകൾ പട്ടികപ്പെടുത്തിയിരിക്കുന്നു.
- ഇനി അഭ്യർത്ഥനകൾ നടത്താൻ കഴിയാത്ത ഒരു കീ ഉൾപ്പെടെ, അനുവദിച്ച ഒരു കീയിൽ ഒരു സ്ലൈസ് ഉണ്ട്. ഉപയോഗമില്ലാത്ത അംഗം യഥാർത്ഥ പൂജ്യം കാണിക്കുന്നു.
- സ്ലോട്ട് 1 എപ്പോഴും ചോദിക്കുന്ന കീ ആണ്, `isYou` true കൂടെ. മറ്റ് സ്ലോട്ട് നമ്പറുകൾ ഒരു കീഡ് ഹാഷിൻ്റെ റാങ്കുകളാണ്. ഇത് `API_KEY_SECRET` ഉപയോഗിച്ച് കീ ചെയ്ത് പൂൾ, ചോദിക്കുന്ന കീ, അംഗം എന്നിവ ഉൾക്കൊള്ളുന്നു.
- അതിനാൽ അക്കങ്ങൾ ഹോൾഡറുകൾക്കിടയിൽ ലൈൻ ചെയ്യുന്നില്ല. ഒരു ഹോൾഡർക്ക്, സന്ദർശനങ്ങൾക്കിടയിൽ അവ ഒരേ നിലയിലായിരിക്കും. ഒരു താക്കോൽ പൂളിൽ ചേരുമ്പോഴോ പുറത്തുപോകുമ്പോഴോ ആ രഹസ്യം തിരിക്കുമ്പോഴോ അവ മാറാം.
- എണ്ണാവുന്ന വിൻഡോയിൽ, ക്വാട്ട സ്റ്റോറിലെ അംഗത്തിൻ്റെ കൗണ്ടറാണ് സ്ലൈസ്, സ്വന്തം `consumed` യുടെ അതേ കൗണ്ടർ.
- ഒരു `percent` വിൻഡോയിൽ ഒരു സ്ലൈസ് എന്നത് അംഗത്തിൻ്റെ `attributed` ഭാഗമാണ്, അതേ പുസ്തകത്തിൽ നിന്ന് കീയുടെ സ്വന്തം ഷെയറായി വായിക്കുന്നു. കുളത്തിന് പുറത്ത് ഉണ്ടാക്കുന്ന ഉപയോഗം ഒരിക്കലും സ്ലൈസുകളായി വിഭജിക്കില്ല. ആ ചാർജ് ഭാരം കൊണ്ട് വിഭജിക്കപ്പെടുന്നു, അതിനാൽ അത് വഹിക്കുന്ന സ്ലൈസുകൾ ഭാരം കാണിക്കും.
- ഓരോ കാഴ്ചയും ഓരോ അംഗത്തിനും ഒരു മൂല്യവും കണക്കാക്കാവുന്ന വിൻഡോയും സമാന്തരമായി വായിക്കുന്നു. ഒരു `percent` വിൻഡോയിൽ, ഷെയറിൻ്റെ സ്വന്തം പുസ്തകം വായിച്ചതിനപ്പുറം സ്ലൈസുകൾക്ക് വായിക്കാൻ ചിലവില്ല. ഒരു മൂല്യം വായിക്കാൻ കഴിയാത്തപ്പോൾ, ആ ജാലകത്തിന് `members` ഇല്ല , കീയുടെ സ്വന്തം പങ്ക് നിലനിൽക്കും.
- ഉപയോഗിക്കാവുന്ന കീകളുടെ ഓപ്ഷനും എണ്ണവും ഒരു പൂളിൽ ഒരിക്കൽ റീഡുചെയ്യുന്നു, അക്കൗണ്ട് ഡാറ്റ കണ്ടേക്കാവുന്ന ഒരു കീക്ക് മാത്രം. ഓപ്ഷൻ്റെയോ ഉപയോഗയോഗ്യമായ-കീ എണ്ണത്തിൻ്റെയോ വായന പരാജയപ്പെട്ടാൽ ആ പൂളിൻ്റെ ബാറുകൾ ഓഫാകും. സെർവർ ഒരു മുന്നറിയിപ്പ് ലോഗ് ചെയ്യുന്നു, ബാക്കിയുള്ള കാഴ്ച നിർമ്മിച്ചു.

ബാറുകളിൽ പേരുകളോ ഐഡികളോ ഇല്ല. മറ്റ് അംഗങ്ങളെക്കുറിച്ച് അവർ ഇപ്പോഴും ഒരു പ്രധാന ഉടമയോട് കാര്യങ്ങൾ പറയുന്നു:

- ഹോൾഡർമാർക്ക് ഇപ്പോഴും സ്ലൈസുകളെ അവയുടെ മൂല്യങ്ങൾ ഉപയോഗിച്ച് പൊരുത്തപ്പെടുത്താനാകും.
- സ്ഥിരതയുള്ള നമ്പറിംഗ്, കാലക്രമേണ ഒരു അംഗത്തെ പിന്തുടരാൻ ഹോൾഡറെ അനുവദിക്കുന്നു.
- പൂളിൽ എത്ര കീകൾ അനുവദിച്ചിട്ടുണ്ടെന്ന് സ്ലൈസുകളുടെ എണ്ണം കാണിക്കുന്നു.
- മൂന്ന് കീകളുള്ള ഒരു പൂളിൽ, ഒരു കീ എന്താണ് ഉപയോഗിച്ചതെന്ന് അറിയാവുന്ന ഒരാൾക്ക് അവസാനം ഉപയോഗിച്ച കീ എന്താണെന്ന് പറയാൻ കഴിയും.
- ഉപയോഗയോഗ്യമായ മൂന്ന് കീകൾക്ക് താഴെയായി ഒരു പൂൾ താഴുമ്പോൾ, ബാറുകൾ അപ്രത്യക്ഷമാകുന്നു. നേരത്തെ എടുത്ത കാഴ്ചകൾ ഇപ്പോഴും ഓരോ അംഗവും എന്താണ് ഉപയോഗിച്ചതെന്ന് കാണിക്കുന്നു.
- എണ്ണാവുന്ന ജാലകത്തിൽ, പൂളിൻ്റെ ആകെ മൈനസ് സ്ലൈസുകൾക്ക് ഇനി അനുവദിച്ചിട്ടില്ലാത്ത കീകളുടെ ഉപയോഗം കാണിക്കാനാകും.
- ഒരു അക്കൗണ്ടിൽ പൂജ്യം കാണിക്കുകയും മറ്റൊന്നിൽ ഉപയോഗിക്കുകയും ചെയ്യുന്ന അംഗത്തിന് ഏത് അക്കൗണ്ട് ഏത് അംഗമാണ് ഉപയോഗിക്കുന്നതെന്ന് കാണിക്കാൻ കഴിയും.
- `hard` പോളിസിയിൽ കണക്കാക്കാവുന്ന ഒരു പൂളിൽ, ഒരു അംഗത്തിൻ്റെ ഫെയർ ഷെയറിൽ വളരുന്നത് നിർത്തുന്ന ഒരു സ്ലൈസ് ആ അംഗത്തിൻ്റെ ഭാരം സൂചിപ്പിക്കുന്നു.

### ഉപയോഗ പരമ്പര (`GET /api/v1/me/usage`)

കോളിംഗ് കീയുടെ സ്വന്തം അഭ്യർത്ഥനകളുടെ ഉപയോഗവും വിലയും`GET /api/v1/me/usage?range=<range>` ( `/v1/me/usage` ലും നൽകുന്നു) നൽകുന്നു: മൊത്തത്തിൽ, ഒരു UTC ദിവസത്തിൽ ഒരു എൻട്രി, ഓരോ ദിവസവും മോഡലും, ഓരോ മോഡലിനും ഓരോ ദാതാവിനും. ഇത് ഫ്ലാഗ്, പ്രാമാണീകരണ നിയമങ്ങൾ, `self:usage` സ്കോപ്പ്, `Cache-Control: no-store`, മുകളിലുള്ള ക്വാട്ട റൂട്ടിൻ്റെ പിശക് സ്വഭാവം എന്നിവ പങ്കിടുന്നു. `range` ന് മുമ്പ് കീ പരിശോധിച്ചു. 400 (`Invalid range`), 401, 403, 404, 500 (`Failed to build usage`) എന്നിവയാണ് പിശകുകൾ.

- `range` എന്നത് `1d`, `7d`, `30d` (സ്ഥിരസ്ഥിതി) അല്ലെങ്കിൽ `90d` എന്നിവയിൽ ഒന്നാണ്. മറ്റേതെങ്കിലും മൂല്യം, ഒരു ശൂന്യമായ മൂല്യം അല്ലെങ്കിൽ ആവർത്തിച്ചുള്ള പാരാമീറ്റർ ഒരു 400 ആണ്. ഒരു കോളിൻ്റെ വിലയെ ബന്ധിപ്പിക്കുന്നതിന് സെറ്റ് `90d` ൽ നിർത്തുന്നു. കാഴ്ച അസംസ്കൃത ഉപയോഗ ചരിത്രം മാത്രം വായിക്കുന്നു, ഒരിക്കലും താക്കോൽ ഇല്ലാത്ത ദൈനംദിന സംഗ്രഹങ്ങൾ.
- കോളിംഗ് കീയുടെ ഐഡി ഉപയോഗിച്ചാണ് വരികൾ തിരഞ്ഞെടുക്കുന്നത്. കീ നെയിം കോളം ഒരിക്കലും പൊരുത്തപ്പെടുന്നില്ല, കൂടാതെ ഒരു കീ ഐഡി ഇല്ലാതെ റെക്കോർഡ് ചെയ്ത വരികൾ ഒരിക്കലും കണക്കാക്കില്ല.
- ഒരു സീരീസ് നിർമ്മിക്കുന്നത് വിൻഡോയിലെ കീയുടെ വരികളിൽ അഞ്ച് ഗ്രൂപ്പുചെയ്ത ചോദ്യങ്ങൾ പ്രവർത്തിപ്പിക്കുന്നു. ബിൽറ്റ് സീരീസ് ഒരു കീയ്ക്കും ശ്രേണിയ്ക്കും 60 സെക്കൻഡ് വീതമാണ് വീണ്ടും ഉപയോഗിക്കുന്നത്, വീണ്ടും ഉപയോഗിച്ച കോൾ ഒന്നും പ്രവർത്തിക്കുന്നില്ല. അതിൻ്റെ `generatedAt` അതിൻ്റെ പ്രായം നൽകുന്നു.
- പരമ്പര നിർമ്മിക്കുമ്പോൾ വിൻഡോ അവസാനിക്കുന്നു. പിന്നീട് സ്റ്റാമ്പ് ചെയ്ത ഒരു വരി, ഉദാഹരണത്തിന് ക്ലോക്ക് സ്ക്യൂ ഉപയോഗിച്ച്, കണക്കാക്കില്ല.
- `coverage.retentionDays` എന്നത് ഓപ്പറേറ്ററുടെ റോ യൂസേജ്-ഹിസ്റ്ററി നിലനിർത്തൽ ക്രമീകരണമാണ് (ഡാറ്റാബേസ് ക്രമീകരണങ്ങളിൽ `retention.usageHistory` ). അഭ്യർത്ഥിച്ച ശ്രേണി ആ ക്രമീകരണത്തേക്കാൾ ദൈർഘ്യമേറിയതാണെങ്കിൽ `coverage.truncatedByRetention` ശരിയാണ്. ഇത് രണ്ട് സംഖ്യകളെ താരതമ്യം ചെയ്യുന്നു, കൂടാതെ വരികൾ യഥാർത്ഥത്തിൽ നഷ്ടമാണോ എന്ന് പരിശോധിക്കുന്നില്ല.
- താക്കോലിൻ്റെ സ്വന്തം അഭ്യർത്ഥനകൾക്കായി രേഖപ്പെടുത്തിയിരിക്കുന്നതായി ദാതാവ് തിരികെ നൽകുന്നു. മോഡൽ എന്നത് അതിൻ്റെ അവസാനത്തെ `/` ശേഷം രേഖപ്പെടുത്തിയിരിക്കുന്ന പേരാണ്, കൂടാതെ വരികൾ അതിനെ വർഗ്ഗീകരിച്ചിരിക്കുന്നു. ഓരോ ലക്ഷ്യവും നിരസിക്കപ്പെട്ട ഒരു കോംബോ അഭ്യർത്ഥന, റൂട്ടിംഗ് ലേബൽ പ്രൊവൈഡർ (കോംബോ പേര്, `auto` അല്ലെങ്കിൽ `combo`) കൂടാതെ ക്ലയൻ്റ് അയച്ച മോഡൽ സ്ട്രിംഗും ഉപയോഗിച്ച് രേഖപ്പെടുത്തുന്നു. മറ്റ് നിരസിച്ച അഭ്യർത്ഥനകൾ, ഉദാഹരണത്തിന് ഒരു ഓപ്പൺ സർക്യൂട്ട് ബ്രേക്കർ, ഒരു മോഡൽ കൂൾഡൗൺ അല്ലെങ്കിൽ ക്വാട്ട പാർക്ക് ചെയ്ത സ്കിപ്പ്, ടാർഗെറ്റ് ദാതാവിനെയും മോഡലിനെയും നിലനിർത്തുക.
- എണ്ണവും ചെലവും കൂടാതെ, പ്രതികരണം ശരാശരി ലേറ്റൻസി, വിജയ നിരക്കുകൾ, ആദ്യത്തേയും അവസാനത്തേയും അഭ്യർത്ഥനയുടെ സമയവും ഉൾക്കൊള്ളുന്നു.
- ഏറ്റവുമധികം അഭ്യർത്ഥനകളുള്ള 50 പ്രൊവൈഡർ ആൻഡ് മോഡൽ ജോഡികളെ`byModel` ലിസ്റ്റ് ചെയ്യുന്നു. കൂടുതൽ ജോഡികൾക്കൊപ്പം അതിൻ്റെ എൻട്രികൾ `summary` വരെ ചേർക്കില്ല, കൂടാതെ `summary.uniqueModels` എല്ലാ റെക്കോർഡ് ചെയ്ത മോഡൽ സ്പെല്ലിംഗും കണക്കാക്കുന്നു. `byModelTruncated` അപ്പോൾ ശരിയാണ്, കൂടാതെ കട്ടിൻ്റെ ഇരുവശത്തും ജോഡികൾ വീഴുന്ന ഒരു മോഡൽ ഭാഗിക മൊത്തങ്ങൾ കാണിക്കുന്നു.
- രണ്ട് ചെലവുകൾ റിപ്പോർട്ട് ചെയ്യുന്നു. ഉപയോഗ അനലിറ്റിക്സ് കാണിക്കുന്നത് പോലെ, `costUsd` ബില്ല് ചെയ്ത ചെലവാണ്. Claude കോഡ് പ്ലാൻ പോലുള്ള ഫ്ലാറ്റ്-റേറ്റ് സബ്സ്ക്രിപ്ഷൻ ദാതാക്കൾ അവിടെ $0 ആയി കണക്കാക്കുന്നു. `listPriceUsd` ലിസ്റ്റ് വിലയിൽ വിലയുള്ള അതേ ഉപയോഗമാണ്, സബ്സ്ക്രിപ്ഷനുകൾ ഉൾപ്പെടുത്തിയിട്ടുണ്ട്. മോഡലിന് വില നിരകളില്ലാത്ത ഒരു അഭ്യർത്ഥന അതിൻ്റെ സംഭരിച്ച ചെലവ് കണക്കാക്കുന്നു: ദാതാവ് റിപ്പോർട്ട് ചെയ്ത വില, അല്ലെങ്കിൽ അഭ്യർത്ഥന റെക്കോർഡ് ചെയ്യുമ്പോൾ കണക്കാക്കിയ ഒന്ന്. മാർക്കർ ഇല്ലാത്ത, 0 എണ്ണമില്ലാത്ത ഒരു അഭ്യർത്ഥന മാത്രം, അതിനാൽ ആകെ ഭാഗികമാകാം.
- പ്രതികരണ കരാർ `src/shared/schemas/selfUsage.ts` ആണ് (`SelfUsageSeries` ൽ `docs/openapi.yaml`).

### സ്വയം സേവന പേജ്

`QUOTA_SELF_PANEL` ഓണായിരിക്കുമ്പോൾ, `/quota/{provider}` ഒരു പൊതു പേജാണ്. ഒരു കീ ഹോൾഡർ അവിടെ ഒരു API കീ ടൈപ്പ് ചെയ്യുകയും ദാതാവിനായി ആ കീയുടെ പൂളുകൾ കാണുകയും ചെയ്യുന്നു. ഓരോ പൂളും ഓരോ പൂൾ വിൻഡോയിലും ഒരു കാർഡ് കാണിക്കുന്നു, എല്ലാവർക്കുമായി പൂളിൻ്റെ ഉപയോഗവും കീയുടെ സ്വന്തം പങ്കും. പൂളിൻ്റെ ഓരോ അക്കൗണ്ടിനും അക്കൗണ്ടിൻ്റെ ഉപയോഗവും കീയുടെ ഷെയറും ഉൾപ്പെടെ അതിൻ്റേതായ കാർഡുകളുണ്ട്. കീ അക്കൗണ്ട് ഡാറ്റ കാണുമ്പോൾ മാത്രമേ അക്കൗണ്ടിൻ്റെ ഉപയോഗം ദൃശ്യമാകൂ. ഓരോ അക്കൗണ്ടിൻ്റെയും ഓരോ മോഡൽ പരിധികളും കീയുടെ സ്വന്തം ഉപയോഗവും പേജ് പട്ടികപ്പെടുത്തുന്നു. ഒരു ഷെഡ്യൂൾ ഇപ്പോൾ കീ തടയുമ്പോൾ ഒരു അറിയിപ്പ് ദൃശ്യമാകുന്നു. ഒരു കാർഡ് അതിൻ്റെ ഉപയോഗത്തോടൊപ്പം കീയുടെ ഓരോ മോഡൽ തൊപ്പിയും പട്ടികപ്പെടുത്തുന്നു, ഒപ്പം എത്തിയവയെ അടയാളപ്പെടുത്തുന്നു. `{provider}` എന്നത് ഒരു ദാതാവിൻ്റെ ഐഡി അല്ലെങ്കിൽ അതിൻ്റെ അപരനാമമാണ് (`/quota/claude`, `/quota/cc`). ഒരു അജ്ഞാത ദാതാവ്, ഫ്ലാഗ് ഓഫ് ആയിരിക്കുമ്പോൾ എല്ലാ `/quota/*` പാതയും ഉത്തരം 404. ഒരു ഇഷ്ടാനുസൃത OpenAI- അല്ലെങ്കിൽ ആന്ത്രോപിക്-അനുയോജ്യമായ നോഡിലെ പൂളുകൾക്ക് പേജില്ല. API ഇപ്പോഴും അവർക്ക് ഉത്തരം നൽകുന്നു.

പേജിന് സെഷനൊന്നുമില്ല. കീ അയയ്ക്കുന്നത് `GET /api/v1/me/quota/{provider}`, `PATCH /api/v1/me/quota/{provider}`, `GET /api/v1/me/usage` എന്നിവയുടെ `Authorization` ഹെഡറിൽ മാത്രമാണ്, ഒരിക്കലും ഒരു URL ൽ അല്ല. സെർവർ സ്വീകരിക്കുന്ന ഒരു കീ ടാബിൻ്റെ `sessionStorage` ൽ സൂക്ഷിച്ചിരിക്കുന്നു. "ഈ ഉപകരണത്തിൽ ഓർമ്മിക്കുക" എന്നതിനൊപ്പം അത് `localStorage` ൽ സൂക്ഷിക്കുന്നു, കൂടാതെ "കീ മറക്കുക" അത് രണ്ടിൽ നിന്നും നീക്കം ചെയ്യുന്നു. സെർവർ നിരസിക്കുന്ന ഒരു കീ സ്റ്റോറേജിൽ നിന്ന് നീക്കം ചെയ്തു.

`consent` മോഡിലുള്ള ഒരു പൂൾ ഒരു ലെൻഡിംഗ് കാർഡ് കാണിക്കുന്നു. അവിടെ കീ ഹോൾഡർ കടം കൊടുക്കാൻ കീയുടെ നിഷ്ക്രിയ ഓഹരിയുടെ 0 മുതൽ 100 വരെ ഒരു മുഴുവൻ ശതമാനവും സജ്ജീകരിക്കുന്നു. സമ്മതം എത്രത്തോളം നീണ്ടുനിൽക്കുമെന്നും ഉടമ തിരഞ്ഞെടുക്കുന്നു: ഓഫാക്കുന്നതുവരെ, 1 മണിക്കൂർ, 8 മണിക്കൂർ, 24 മണിക്കൂർ, 7 ദിവസം അല്ലെങ്കിൽ 30 ദിവസം. സംരക്ഷിക്കുന്ന നിമിഷം മുതൽ ഒരു ദൈർഘ്യം കണക്കാക്കുന്നു. ഒരു സമയപരിധി പ്രാബല്യത്തിലായിരിക്കുമ്പോൾ, ഉടമയ്ക്ക് പകരം അത് നിലനിർത്താം. സംരക്ഷിക്കുന്നതിന് മുമ്പ് ആ സമയപരിധി കടന്നുപോകുകയാണെങ്കിൽ, കാർഡ് ഒന്നും അയയ്ക്കില്ല, മറ്റൊരു ചോയ്സ് ആവശ്യപ്പെടും. 0% ഉപയോഗിച്ച് സമയപരിധിയൊന്നും അയച്ചിട്ടില്ല. കാർഡ് അതിൻ്റെ ടൈം സോൺ എന്ന് പേരിട്ടിരിക്കുന്ന സംഭരിച്ച സമയപരിധി കാണിക്കുന്നു. കാലാവധി കഴിഞ്ഞ ഒരു സമ്മതം അവസാനിച്ചതായി കാണിക്കുന്നു.

ഒരു `hard` കീയ്ക്കായി, ഒരു പൂൾ വിൻഡോയ്ക്ക്, മറ്റ് കീകൾ ഇപ്പോൾ കീയ്ക്ക് എന്താണ് നൽകുന്നതെന്ന് കാർഡ് ലിസ്റ്റുചെയ്യുന്നു. ഓരോ വരിയും മറ്റെല്ലാ കീകൾക്കും ഒരുമിച്ച് ഒരു അക്കമാണ്. രണ്ട് കീകളുള്ള ഒരു പൂളിൽ അത് മറ്റേ കീയുടെ സ്വന്തം രൂപമാണ്. കാഴ്ച റിപ്പോർട്ട് ചെയ്യാത്ത ഒരു കണക്ക് ലഭ്യമല്ല, പൂജ്യമായിട്ടല്ല വായിക്കുന്നത്. ഒരു `soft` അല്ലെങ്കിൽ `burst` കീയ്ക്ക് ഒരു കണക്കും ബാധകമല്ലെന്ന് കാർഡ് പറയുന്നു.

`saturation` മോഡിലെ ഒരു പൂൾ, അതിൻ്റെ കീ സംഭരിക്കുന്ന 0-ന് മുകളിലുള്ള ഒരു ശതമാനം പിൻവലിക്കൽ മാത്രം കാണിക്കുന്നു. സംഭരിച്ചിരിക്കുന്ന ശതമാനത്തിന് അവിടെ യാതൊരു ഫലവുമില്ലെന്ന് പറയുന്നു. അതിൻ്റെ പിൻവലിക്കൽ ബട്ടൺ സമയപരിധിയില്ലാതെ 0 അയയ്ക്കുന്നു. സംഭരിച്ച 0 ഉള്ള `saturation` മോഡിലുള്ള ഒരു പൂൾ ലെൻഡിംഗ് കാർഡ് കാണിക്കുന്നില്ല. ഒരു സംരക്ഷിച്ചതിന് ശേഷം, മടങ്ങിയ കാഴ്ചയ്ക്ക് ഇനി ആവശ്യമില്ലാത്ത ഒരു കാർഡ്, പേജിൻ്റെ കാഴ്ച വീണ്ടും മാറുന്നത് വരെ അതിൻ്റെ സന്ദേശത്തോടൊപ്പം നിലനിൽക്കും.

ഹോൾഡർ സേവ് ചെയ്യുകയോ പിൻവലിക്കുകയോ ചെയ്യുന്നതുവരെ ഒന്നും സംരക്ഷിക്കപ്പെടുന്നില്ല. ഓരോ പ്രസ്സും ഒരു `PATCH /api/v1/me/quota/{provider}` അഭ്യർത്ഥന അയയ്ക്കുന്നു, ആദ്യത്തേത് തീർച്ചപ്പെടുത്താതെയിരിക്കുമ്പോൾ രണ്ടാമത്തെ പ്രസ്സ് ഒന്നും അയയ്ക്കുന്നില്ല. കാഴ്ച, ശതമാനം, സമയപരിധി എന്നിവയിൽ നിന്ന് ബോഡി പൂളിൻ്റെ അതാര്യമായ `ref` വഹിക്കുന്നു. പുനർനിർമ്മിച്ച ക്വാട്ട കാഴ്ചയാണ് ഉത്തരം, രണ്ടാമത് വായിക്കാതെ പേജ് അത് കാണിക്കുന്നു. രണ്ട് സേവുകൾ ഓവർലാപ്പ് ചെയ്യുമ്പോൾ, അവസാന ഉത്തരത്തിന് ശേഷം പേജ് ക്വാട്ട ഒരിക്കൽ വായിക്കുന്നു. പേജ് സമ്മതം ബ്രൗസർ സ്റ്റോറേജിൽ സൂക്ഷിക്കുന്നില്ല.

നിരസിച്ച മാറ്റം HTTP സ്റ്റാറ്റസിൽ നിന്ന് തിരഞ്ഞെടുത്ത ഒരു വാചകം വഴി കാർഡിൽ വിശദീകരിക്കുന്നു. പിശക് ബോഡി വായിച്ചിട്ടില്ല. എ 401 കീ സ്വീകരിച്ചിട്ടില്ലെന്നും ക്വാട്ട വീണ്ടും ലോഡുചെയ്യുന്നുവെന്നും പറയുന്നു. ഒരു 403, പൂൾ വായ്പാ മാറ്റങ്ങൾ എടുക്കുന്നില്ലെന്ന് പറയുന്നു, ഒരു 404 കുളം പോയി എന്ന് പറയുന്നു. രണ്ടും ക്വാട്ട വീണ്ടും ലോഡുചെയ്യുന്ന ഒരു ബട്ടൺ വാഗ്ദാനം ചെയ്യുന്നു. 400 അല്ലെങ്കിൽ മറ്റൊരു 4xx ഉത്തരം, ശതമാനവും സമയപരിധിയും പരിശോധിക്കാൻ ഉടമയോട് ആവശ്യപ്പെടുന്നു. A 429 ഹോൾഡറോട് കാത്തിരിക്കാൻ ആവശ്യപ്പെടുന്നു, ഉത്തരം നൽകുമ്പോൾ `Retry-After` സെക്കൻഡുകൾ. ഒരു 5xx ഉത്തരം, ഒരു 408 അല്ലെങ്കിൽ നെറ്റ്വർക്ക് പരാജയം, മാറ്റം സംരക്ഷിച്ചിട്ടില്ലെന്ന് പറയുന്നു, കൂടാതെ ടൈപ്പ് ചെയ്ത മൂല്യങ്ങൾ നിലനിർത്തുന്നു. കരാറിന് പുറത്തുള്ള ഉത്തരം ക്വാട്ട വീണ്ടും ലോഡുചെയ്യുന്നു. ഒരു പരാജയപ്പെട്ട സേവ് കീ സ്വയം നീക്കം ചെയ്യുന്നില്ല. നിരസിച്ചതിന് ശേഷം വീണ്ടും ലോഡുചെയ്യുമ്പോൾ, വായിക്കാൻ നിരസിച്ചതുപോലെ പേജ് കീ നീക്കംചെയ്യുന്നു.

ഒരു കീ സ്വീകരിച്ചുകഴിഞ്ഞാൽ, പേജ് മൂന്ന് ടാബുകളുള്ള ഒരു "നിങ്ങളുടെ ഉപകരണങ്ങൾ സജ്ജമാക്കുക" കാർഡും കാണിക്കുന്നു. "Claude കോഡ്" `~/.claude/settings.json` ന് `env` ബ്ലോക്ക് നൽകുന്നു. "ഷെൽ" `export` ലൈനുകളുടെ അതേ വേരിയബിളുകൾ നൽകുന്നു. "Claude ഡെസ്ക്ടോപ്പ്" അതിൻ്റെ മൂന്നാം കക്ഷി അനുമാന വിൻഡോയുടെ മൂല്യങ്ങൾ നൽകുന്നു. ആ ദാതാവിനായി കീ വിളിച്ചേക്കാവുന്ന ക്വാട്ട-ഷെയർ മോഡലുകളാണ് മോഡലുകൾ. കീയ്ക്കൊപ്പം അത്തരത്തിലുള്ള ഒരു ലിസ്റ്റും വരുമ്പോൾ, പകരം ബ്ലോക്ക് ഗേറ്റ്വേ മോഡൽ കണ്ടെത്തൽ ഓണാക്കുന്നു. സെർവർ റിപ്പോർട്ട് ചെയ്യുന്ന പൊതു API ഉത്ഭവമാണ് ഗേറ്റ്വേ വിലാസം (`OMNIROUTE_PUBLIC_API_BASE_URL`, തുടർന്ന് `OMNIROUTE_PUBLIC_BASE_URL`). ഒന്നും സജ്ജീകരിക്കാത്തപ്പോൾ, കാർഡ് ഒരു പ്ലെയ്സ്ഹോൾഡർ കാണിക്കുകയും അഡ്മിനിസ്ട്രേറ്ററോട് ചോദിക്കാൻ ഹോൾഡറോട് പറയുകയും ചെയ്യുന്നു. കീ ഒരു പ്ലെയ്സ്ഹോൾഡറായി കാണിച്ചിരിക്കുന്നു. "എൻ്റെ കീ ഉൾപ്പെടുത്തുക" എന്നത് സ്ക്രീനിലെ ടെക്സ്റ്റിലും ഒരു കോപ്പി ബട്ടൺ പകർത്തുന്നവയിലും മുഴുവൻ കീയും ഇടുന്നു. ബോക്സ് മായ്ക്കുന്നതുവരെയോ കീ മറക്കുകയോ മാറ്റിസ്ഥാപിക്കുകയോ പേജ് അവശേഷിക്കുന്നത് വരെ ഇത് നീണ്ടുനിൽക്കും. കാർഡ് ഒരു അഭ്യർത്ഥനയും അയയ്ക്കുന്നില്ല കൂടാതെ ഫയൽ ഡൗൺലോഡ് വാഗ്ദാനം ചെയ്യുന്നില്ല.

API മാർക്ക് `stale` എന്നത് കാലഹരണപ്പെട്ടതായി കാണിക്കുന്നു. `unavailable` എന്ന് അടയാളപ്പെടുത്തുന്ന ഒരു വായന അതിൻ്റെ കാരണത്തോടൊപ്പം കാണിക്കുന്നു, ഒരിക്കലും പൂജ്യമല്ല.

ശതമാനം പ്ലാനുകളിൽ, API റിപ്പോർട്ടുചെയ്യുമ്പോൾ പേജ് കീയുടെ സ്വന്തം പങ്ക് എടുക്കുന്നു. സംഖ്യ ഒരു എസ്റ്റിമേറ്റ് ആണെന്നും അതിൻ്റെ രണ്ട് ഭാഗങ്ങൾക്ക് പേരിടുകയും ചെയ്യുന്നു. ഓരോ മോഡൽ പരിധികൾ അക്കൗണ്ട് മാത്രം കാണിക്കുന്നു.

ഒരു വിൻഡോ `members` വഹിക്കുമ്പോൾ, അതിൻ്റെ കാർഡ് സ്ലോട്ട് ക്രമത്തിൽ ഓരോ അംഗത്തിനും ഒരു സെഗ്മെൻ്റ് ഉള്ള ഒരു ബാറും കാണിക്കുന്നു. ചോദിക്കുന്ന കീയുടെ സെഗ്മെൻ്റ് ആക്സൻ്റ് കളർ ഉപയോഗിക്കുന്നു. മറ്റ് സെഗ്മെൻ്റുകൾ തീമിൻ്റെ ചാർട്ട് നിറങ്ങളിലൂടെ സഞ്ചരിക്കുന്നു. ഒരു ടെക്സ്റ്റ് ലെജൻഡ് ഓരോ സെഗ്മെൻ്റിനെയും അതിൻ്റെ മൂല്യം ഉപയോഗിച്ച് ലിസ്റ്റുചെയ്യുന്നു, അതിനാൽ ഒന്നും നിറത്തെ ആശ്രയിക്കുന്നില്ല. സെഗ്മെൻ്റുകൾ `You` അല്ലെങ്കിൽ `Member N` എന്ന് ലേബൽ ചെയ്തിരിക്കുന്നു, ഇവിടെ N എന്നത് സ്ലോട്ട് ആണ്.

### പേജിനായി സമർപ്പിത പോർട്ട്

സെൽഫ് സർവീസ് പേജ് മാത്രം നൽകുന്ന രണ്ടാമത്തെ ശ്രോതാവിനെ`QUOTA_PANEL_PORT` തുറക്കുന്നു. വേരിയബിൾ സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ അത് ഓഫാണ്. `QUOTA_PANEL_HOST` എന്നത് ബൈൻഡ് വിലാസവും സ്ഥിരസ്ഥിതിയും `127.0.0.1` ആണ്.

ശ്രോതാവ് ഈ പാതകൾ പ്രധാന തുറമുഖത്തേക്ക് റിലേ ചെയ്യുകയും മറ്റെല്ലാ പാതകൾക്കും 404 ഉത്തരം നൽകുകയും ചെയ്യുന്നു:

| പാത                                                                      | സേവിക്കുന്നു                               |
| ------------------------------------------------------------------------ | ------------------------------------------ |
| `/quota/{provider}`                                                      | പേജ്                                       |
| `/api/v1/me/quota/{provider}`, `/v1/me/quota/{provider}`                 | പേജ് വായിക്കുന്ന ക്വാട്ട കാഴ്ച             |
| `/api/v1/me/usage`, `/v1/me/usage`                                       | പേജ് വായിക്കുന്ന ഉപയോഗ പരമ്പര              |
| `/_next/static/`                                                         | ബിൽഡിൻ്റെ സ്ക്രിപ്റ്റുകൾ, ശൈലികൾ, ഫോണ്ടുകൾ |
| `/favicon.ico`, `/favicon.svg`, `/icon-512.png`, `/apple-touch-icon.png` | ഐക്കണുകൾ                                   |

`GET`, `HEAD` ശരീരമില്ലാതെ റിലേ ചെയ്യുന്നു. ഒരു ബോഡിയുള്ള ഒരു അഭ്യർത്ഥനയും റിലേ ചെയ്യപ്പെടുന്നു: ക്വാട്ട വ്യൂ പാതയുടെ ഒരു `PATCH`, ഒരു വായ്പാ ചോയ്സ് സംരക്ഷിക്കാൻ പേജ് അയയ്ക്കുന്നു. ഒരു CONNECT അഭ്യർത്ഥന ഒഴികെ മറ്റേതെങ്കിലും രീതി 404-ന് ഉത്തരം നൽകുന്നു, അതിൻ്റെ കണക്ഷൻ ഉത്തരമില്ലാതെ അടച്ചിരിക്കുന്നു. ഒരു ബോഡി പ്രഖ്യാപിക്കുന്ന മറ്റേതെങ്കിലും അഭ്യർത്ഥന 404-ന് ഉത്തരം നൽകുകയും അതിൻ്റെ കണക്ഷൻ അടച്ചു. അപ്ഗ്രേഡ് അഭ്യർത്ഥനകൾ നിരസിക്കുകയും അവയുടെ കണക്ഷൻ അവസാനിപ്പിക്കുകയും ചെയ്യുന്നു. API പോർട്ടിലെ പോലെ ഡോട്ട് സെഗ്മെൻ്റോ ഫ്രാഗ്മെൻ്റ് മാർക്കറോ ഉള്ള ഒരു പാത നിരസിക്കുന്നു. അച്ചടിക്കാവുന്ന ASCII പുറത്തുള്ള ഒരു പ്രതീകമുള്ള ഒരു അഭ്യർത്ഥന ടാർഗെറ്റും അങ്ങനെയാണ്. ഈ പോർട്ടിൻ്റെ സ്വന്തം പരിശോധനയ്ക്ക് മുമ്പ്, ടാർഗെറ്റിലെ ഒരു റോ കൺട്രോൾ പ്രതീകത്തിന് HTTP പാഴ്സർ 400 എന്ന് ഉത്തരം നൽകുന്നു. ചട്ടക്കൂട് സ്വന്തം ഉപയോഗത്തിനായി കരുതിവച്ചിരിക്കുന്ന തലക്കെട്ടുകൾ റിലേ ചെയ്യരുത്: `x-middleware-`, `x-invoke-`, `x-nextjs-`, `x-now-` അല്ലെങ്കിൽ `x-next-` എന്നിവയിൽ ആരംഭിക്കുന്ന പേരുകൾ കൂടാതെ `x-matched-path`, `next-resume` എന്നീ പേരുകളും. അവരില്ലാതെയാണ് അഭ്യർത്ഥന റിലേ ചെയ്യുന്നത്. ഡാഷ്ബോർഡ്, ലോഗിൻ പേജ്, മാനേജ്മെൻ്റ് API, അനുമാന റൂട്ടുകൾ എന്നിവ ഈ പോർട്ടിലൂടെ എത്തിച്ചേരാനാകില്ല.

`PATCH` `Content-Type: application/json` വഹിക്കണം, ഒരു പാരാമീറ്ററും ഇല്ലാതെ അല്ലെങ്കിൽ `charset=utf-8` മാത്രം. ഇത് 1 മുതൽ 4096 വരെ ഒരു `Content-Length` വഹിക്കണം, പ്ലെയിൻ അക്കങ്ങളായി എഴുതിയിരിക്കണം, കൂടാതെ `Transfer-Encoding` ഇല്ല. ഈ നിയമങ്ങളിലൊന്ന് ലംഘിക്കുന്ന ഒരു `PATCH` ഉത്തരം 404. ഒപ്പിട്ടതോ ആവർത്തിച്ചതോ ആയ ചില വികലമായ ദൈർഘ്യങ്ങൾക്ക് ഈ പോർട്ടിൻ്റെ സ്വന്തം ചെക്കിന് മുമ്പ് HTTP പാഴ്സർ 400 എന്ന് ഉത്തരം നൽകുന്നു. പ്രധാന പോർട്ടുമായി ബന്ധപ്പെടുന്നതിന് മുമ്പ് പോർട്ട് പ്രഖ്യാപിത ബൈറ്റുകൾ വായിക്കുകയും അവയ്ക്കായി പരമാവധി 5 സെക്കൻഡ് കാത്തിരിക്കുകയും ചെയ്യുന്നു. അപ്പോഴേക്കും പൂർണ്ണമല്ലാത്ത ഒരു ബോഡി 404-ന് ഉത്തരം നൽകി, അതിൻ്റെ കണക്ഷൻ അടച്ചു. ആ സാഹചര്യത്തിലോ ക്ലയൻ്റ് ആദ്യം പോകുമ്പോഴോ ഒന്നും പ്രധാന പോർട്ടിൽ എത്തില്ല. അതേ `Content-Length` ഉപയോഗിച്ച് പോർട്ട് പ്രഖ്യാപിത ബൈറ്റുകൾ കൃത്യമായി റിലേ ചെയ്യുന്നു. അവയ്ക്ക് ശേഷമുള്ള ബൈറ്റുകൾ കണക്ഷനിലെ അടുത്ത അഭ്യർത്ഥനയായി വായിക്കുന്നു. മുന്നിലുള്ള ഒരു TLS റിവേഴ്സ് പ്രോക്സി `Content-Length` ഫോർവേഡ് ചെയ്യണം, അഭ്യർത്ഥന ബോഡി വീണ്ടും ചങ്ക് ചെയ്യരുത്. പ്രധാന പോർട്ട്, `GET` ൻ്റെ പോലെ, `Authorization` ഹെഡറിലെ API കീ പരിശോധിക്കുന്നു.

404 ശരീരം `{"error":"not_found","message":"Not found."}` ആണ്. പരാജയപ്പെട്ട ഒരു റിലേ, `detail` ഫീൽഡ് ഇല്ലാതെ 502 (`api_bridge_unavailable`) അല്ലെങ്കിൽ 504 (`api_bridge_timeout`) ഉത്തരങ്ങൾ നൽകുന്നു.

ശ്രോതാവ് `QUOTA_SELF_PANEL` വായിക്കുന്നില്ല, അത് പേജ് ഓണാക്കുന്നില്ല. ഫ്ലാഗ് ഓഫ് ആയിരിക്കുമ്പോൾ, പ്രധാന പോർട്ടിൽ പേജും അതിൻ്റെ API ഉത്തരം 404, ശ്രോതാവ് ആ ഉത്തരം റിലേ ചെയ്യുന്നു.

ഡെവലപ്മെൻ്റ് സെർവറിന് കീഴിൽ (`next dev`), ഈ പോർട്ട് വഴി പേജ് സംവേദനാത്മകമാകില്ല. ഡെവലപ്മെൻ്റ് ഹോട്ട്-റീലോഡ് സോക്കറ്റ് ഒരു അപ്ഗ്രേഡ് അഭ്യർത്ഥനയാണ്, പോർട്ട് അത് നിരസിക്കുന്നു. വികസിപ്പിക്കുമ്പോൾ പ്രധാന പോർട്ട് ഉപയോഗിക്കുക.

പോർട്ട് പ്ലെയിൻ HTTP നൽകുന്നു, പേജ് API കീകൾ അയയ്ക്കുന്നു. ഡിഫോൾട്ട് ബൈൻഡ് വിലാസം സൂക്ഷിക്കുക, അതിനു മുന്നിൽ TLS ഉള്ള ഒരു റിവേഴ്സ് പ്രോക്സി ഇടുക. ലൂപ്പ്ബാക്ക് ഒഴികെയുള്ള ഒരു ബൈൻഡ് വിലാസം ഈ അറിയിപ്പ് രേഖപ്പെടുത്തുന്നു:

```text
[Quota Panel] Bound to <host>. This port serves plain HTTP and the page sends API keys. Put a TLS reverse proxy in front of it.
```

ഫോർവേഡിംഗ് ഹെഡർ അയയ്ക്കാത്ത ഒരു ലൂപ്പ്ബാക്ക് പിയർ പ്രധാന പോർട്ടിൽ ലോക്കൽ ആയി കണക്കാക്കുന്നു. അതിനാൽ അതേ ഹോസ്റ്റിലെ ഒരു പ്രോക്സി `X-Forwarded-For` അയയ്ക്കണം. `OMNIROUTE_TRUST_PROXY=private` (അല്ലെങ്കിൽ `lan`) ഉള്ള ഒരു സ്വകാര്യ വിലാസത്തിലെ ഒരു പ്രോക്സി ആ തലക്കെട്ടിന് മാത്രമേ വിശ്വസനീയമായിട്ടുള്ളൂ. മറ്റേതെങ്കിലും പിയർ അതിൻ്റെ കണക്ഷൻ്റെ വിലാസം വഴി റിപ്പോർട്ട് ചെയ്യുന്നു, അത് അയച്ച ഫോർവേഡിംഗ് ഹെഡറുകൾ ഒഴിവാക്കപ്പെടും.

ശ്രോതാവിന് ഒരു സമയം പരമാവധി 256 കണക്ഷനുകൾ ഉണ്ട്. അഭ്യർത്ഥന തലക്കെട്ടുകൾ അയയ്ക്കാൻ ഒരു ക്ലയൻ്റിന് 10 സെക്കൻഡും മുഴുവൻ അഭ്യർത്ഥനയും അയയ്ക്കാൻ 30 സെക്കൻഡും ഉണ്ട്. നിഷ്ക്രിയമായി സൂക്ഷിച്ചിരിക്കുന്ന ഒരു കണക്ഷൻ ഏകദേശം 5 സെക്കൻഡിന് ശേഷം ക്ലോസ് ചെയ്യുന്നു. 60 സെക്കൻഡ് പ്രവർത്തനങ്ങളില്ലാത്ത ഒരു കണക്ഷൻ അടച്ചു. ഈ മൂല്യങ്ങൾ നിശ്ചിതമാണ്. മുന്നിലുള്ള റിവേഴ്സ് പ്രോക്സിയിലും കണക്ഷനും നിരക്ക് പരിധിയും സജ്ജമാക്കുക. മുന്നിലുള്ള ഒരു റിവേഴ്സ് പ്രോക്സി അതിൻ്റെ നിഷ്ക്രിയ അപ്സ്ട്രീം കണക്ഷനുകൾ 5 സെക്കൻഡിൽ താഴെ സൂക്ഷിക്കണം, അല്ലെങ്കിൽ അവ വീണ്ടും ഉപയോഗിക്കരുത്. പ്രധാന പോർട്ടിലേക്കുള്ള റിലേ, API പോർട്ടിൻ്റെ (`API_BRIDGE_*`) അപ്സ്ട്രീം ടൈംഔട്ടുകൾ ഉപയോഗിക്കുന്നു.

`API_PORT` സജ്ജീകരിക്കാത്തപ്പോൾ ശ്രോതാവും ആരംഭിക്കുന്നു. `QUOTA_PANEL_PORT` 1 മുതൽ 65535 വരെയുള്ള ഒരു പോർട്ട് ആയിരിക്കണം, അക്കങ്ങളിൽ മാത്രം എഴുതിയിരിക്കുന്നു. ഇത് ഡാഷ്ബോർഡ് പോർട്ടിൽ നിന്നും API പോർട്ടിൽ നിന്നും വ്യത്യസ്തമായിരിക്കണം. തത്സമയ WebSocket സെർവർ ഓണായിരിക്കുമ്പോൾ, അത് `LIVE_WS_PORT` ൽ നിന്ന് വ്യത്യസ്തമായിരിക്കണം (സ്ഥിരസ്ഥിതി 20132). മറ്റേതെങ്കിലും മൂല്യം ഒന്നും തുറക്കില്ല, ഒരു മുന്നറിയിപ്പ് ലോഗ് ചെയ്യുന്നു. നിരസിച്ച മൂല്യത്തെക്കുറിച്ചുള്ള മുന്നറിയിപ്പ് വേരിയബിളിനെ നാമകരണം ചെയ്യുന്നു, മൂല്യം ആവർത്തിക്കുന്നില്ല. ഇതിനകം ഉപയോഗത്തിലുള്ള ഒരു പോർട്ട് ഒന്നും തുറന്ന് ഈ മുന്നറിയിപ്പ് ലോഗ് ചെയ്യുന്നു:

```text
[Quota Panel] Port <port> is already in use. The quota panel port stays off.
```

`OMNIROUTE_BASE_PATH` സെറ്റ് ഉപയോഗിച്ച്, ആ പ്രിഫിക്സിന് കീഴിൽ മുകളിലുള്ള എല്ലാ പാതയും ശ്രോതാവ് പ്രതീക്ഷിക്കുന്നു. ബിൽഡ് ടൈമിലും റൺ ടൈമിലും ഒരേ `OMNIROUTE_BASE_PATH` ഉപയോഗിക്കുക. ഒരു മുൻനിര സ്ലാഷും പിന്നിലുള്ള സ്ലാഷും കൂടാതെ ഇത് എഴുതുക, ഉദാഹരണത്തിന് `/omniroute`. `/`, `/omniroute/` എന്നിവയുൾപ്പെടെ മറ്റൊരു ആകൃതി, ഒരു മുന്നറിയിപ്പോടെ പോർട്ട് ഓഫ് ചെയ്യുന്നു, എന്നിരുന്നാലും ബിൽഡ് ആ ഫോമുകൾ സ്വീകരിക്കുന്നു. ആദ്യ സെഗ്മെൻ്റ് ഒരു ആപ്ലിക്കേഷൻ റൂട്ടിനെ നാമകരണം ചെയ്യുന്ന ഒരു അടിസ്ഥാന പാതയും അങ്ങനെ തന്നെ ചെയ്യുന്നു: `api`, `v1`, `v1beta`, `_next`, `quota`, `dashboard`, `docs`, `login`, `codex`, `responses`, `anthropic`, `openai`, `v0`, അല്ലെങ്കിൽ `connect`.

പരിമിതികൾ:

- ഈ പോർട്ടിൽ 404 എന്നതിന് പിന്നിലുള്ള സ്ലാഷുള്ള `/quota/{provider}/` ഉത്തരം നൽകുന്നു.
- സർവീസ് വർക്കറും വെബ് ആപ്പ് മാനിഫെസ്റ്റും ഈ പോർട്ടിൽ നൽകുന്നില്ല.
- ഡാഷ്ബോർഡിൽ സജ്ജീകരിച്ച ഒരു ഇഷ്ടാനുസൃത ഫാവിക്കോൺ ഈ പോർട്ടിൽ കാണിക്കില്ല.
- ആപ്ലിക്കേഷൻ ഒരു അടിസ്ഥാന പാതയ്ക്ക് കീഴിൽ പ്രവർത്തിക്കുമ്പോൾ ഐക്കണുകൾ കാണിക്കില്ല.
- തുറമുഖം പ്ലെയിൻ HTTP/1.1. സംസാരിക്കുന്നു
- പ്രക്രിയ പുനരാരംഭിക്കുന്നത് വരെ പരാജയപ്പെടുന്ന ഒരു ബൈൻഡ് വീണ്ടും ശ്രമിക്കില്ല.
- ഓരോ ക്ലയൻ്റ് വിലാസത്തിനും ശ്രോതാവിന് കണക്ഷനോ നിരക്ക് പരിധിയോ ഇല്ല.
- കണ്ടെയ്നർ സജ്ജീകരണങ്ങൾ ഈ വിഭാഗത്തിൽ ഉൾപ്പെടുന്നില്ല.

## പ്രശ്നപരിഹാരം

### Redis കോൺഫിഗർ ചെയ്തിട്ടുണ്ടെങ്കിലും കണക്റ്റ് ചെയ്യുന്നില്ല

`ioredis` ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടെന്നും (`npm ls ioredis`) `QUOTA_STORE_REDIS_URL`
ആക്സസ് ചെയ്യാനാകുമെന്നും പരിശോധിക്കുക. കണക്ഷൻ പരാജയപ്പെട്ടാൽ ഫാക്ടറി SQLite-ലേക്ക് ഫാൾബാക്ക് ചെയ്യുന്നു
(`warn`-ൽ ലോഗ് ചെയ്യുന്നു).

### `peek` പഴയ ഡാറ്റ നൽകുന്നു / ഫെയിൽ-ഓപ്പൺ ചെയ്യുന്നു

`peek` എറർ നൽകിയാൽ, `enforceQuotaShare` ഫലത്തെ "അനുവദിക്കുക" (ഫെയിൽ-ഓപ്പൺ) ആയി കണക്കാക്കുന്നു.
മൂലകാരണം തിരിച്ചറിയാൻ `quota:enforce`, `quota:factory` എൻട്രികൾക്കായി `pino` ലോഗുകൾ
പരിശോധിക്കുക.

### ഉപഭോഗ കൗണ്ടറിലെ വ്യതിയാനം

യഥാർഥ പ്രൊവൈഡർ ഉപയോഗം കൗണ്ടറുകളിൽ നിന്ന് വ്യത്യസ്തമാണെങ്കിൽ അത് പ്രതീക്ഷിക്കാവുന്നതാണ് —
2-ബക്കറ്റ് സ്ലൈഡിങ് വിൻഡോയ്ക്ക് വിൻഡോ അതിരുകളിൽ ~1% പിശകുണ്ട്, കൂടാതെ `consume`
റെസ്പോൺസിന് ശേഷം ഫയർ-ആൻഡ്-ഫോർഗെറ്റ് രീതിയിലാണ്. സാച്ചുറേഷൻ സിഗ്നൽ (`saturationSignals.ts`)
30 സെക്കൻഡ് TTL ഉപയോഗിച്ച് യഥാർഥ പ്രൊവൈഡർ ഉപയോഗനില വായിക്കുകയും അതനുസരിച്ച് `globalUsedPercent`
ക്രമീകരിക്കുകയും ചെയ്യുന്നു.

### ബേൺ റേറ്റിനായി പൂൾ "ഡാറ്റയില്ല" എന്ന് കാണിക്കുന്നു

`computeBurnRate`-ന് കുറഞ്ഞത് 2 ചരിത്ര സാമ്പിളുകളെങ്കിലും ആവശ്യമാണ്. മുമ്പ്
`consume` കോളുകൾ ഇല്ലാത്ത പുതിയ പൂളുകൾ `tokensPerSecond: 0`, `timeToExhaustionMs: null` എന്നിവ കാണിക്കും.

## localStorage-ൽ നിന്നുള്ള മൈഗ്രേഷൻ

`/dashboard/costs/quota-share` ആദ്യമായി ലോഡ് ചെയ്യുമ്പോൾ, `useLocalStoragePoolMigration`
ഹുക്ക് ഇനിപ്പറയുന്നവ പരിശോധിക്കുന്നു:

1. `localStorage.getItem("omniroute:quota-share:pools")` ശൂന്യമല്ല.
2. `GET /api/quota/pools` `[]` മടക്കിനൽകുന്നു (DB ശൂന്യമാണ്).

രണ്ടും ശരിയാണെങ്കിൽ, ഓരോ ലെഗസി പൂളും ബാച്ചായി `POST /api/quota/pools`-ലേക്ക് പോസ്റ്റ് ചെയ്യുകയും,
തുടർന്ന് localStorage കീ നീക്കം ചെയ്യുകയും ചെയ്യുന്നു. മൈഗ്രേഷൻ ഐഡംപൊട്ടന്റാണ്: വ്യവസ്ഥ 2
വീണ്ടും മൈഗ്രേറ്റ് ചെയ്യുന്നത് തടയുന്നു.

## DB സ്കീമ സംഗ്രഹം

`078`, `079`, `085` എന്നീ മൈഗ്രേഷനുകൾ ചേർത്ത മൂന്ന് പട്ടികകൾ:

- `quota_pools` + `quota_allocations` — പൂൾ നിർവചനങ്ങളും ഓരോ കീ അലോക്കേഷനുകളും.
- `quota_consumption` — റോളിംഗ് 2-ബക്കറ്റ് കൗണ്ടറുകൾ ഓരോ `(apiKeyId, dimensionKey)`.
- `provider_plans` — മാനുവൽ പ്രൊവൈഡർ പ്ലാൻ അസാധുവാക്കുന്നു (ഒരു connectionId അളവുകൾ JSON ).

എല്ലാ പട്ടികകളും idempotent `CREATE TABLE IF NOT EXISTS` മൈഗ്രേഷനുകൾ വഴി ചേർത്തു.

സമ്മതപത്രം നൽകൽ മൂന്ന് നിരകൾ ചേർക്കുന്നു: `quota_allocations.lending_percent` (പൂർണ്ണസംഖ്യ, സ്ഥിരസ്ഥിതി 0), `quota_allocations.lending_until` (യുഗം മില്ലിസെക്കൻഡ്, അല്ലെങ്കിൽ സമയപരിധിയില്ലാത്ത `NULL` ), `quota_pools.borrow_mode` (സ്ഥിരസ്ഥിതി `saturation`). അതിൻ്റെ മൈഗ്രേഷൻ ഈ കോളങ്ങൾ ചേർക്കുകയും നിലവിലുള്ള വരികളൊന്നും എഴുതുകയും ചെയ്യുന്നില്ല.

ശതമാനം ആട്രിബ്യൂഷൻ ബുക്കിൽ `quota_percent_ledger` (ഒരു കുളത്തിന് ഒരു വരി, അക്കൗണ്ട്, പ്ലാൻ വിൻഡോ), `quota_percent_ledger_tokens` (ഒരു പൂളിന് ഒരു ടോക്കൺ കൗണ്ടർ, അക്കൗണ്ട്, API കീ) എന്നിവ ചേർക്കുന്നു. `src/lib/db/quotaPercentLedger.ts` അവ വായിക്കുകയും എഴുതുകയും ചെയ്യുന്നു.
