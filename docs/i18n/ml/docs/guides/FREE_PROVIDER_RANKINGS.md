> **TL;DR**: **Arena AI (LMArena-ശൈലി) ELO സ്കോറുകൾ** ഉപയോഗിച്ച് OmniRoute അതിന്റെ
> **സൗജന്യ** പ്രൊവൈഡർമാരെ മോഡൽ ഗുണനിലവാരത്തിന്റെ അടിസ്ഥാനത്തിൽ റാങ്ക് ചെയ്യുന്നു. നിങ്ങളുടെ ടാസ്കിന്
> ഏറ്റവും ശക്തമായ മോഡലുകൾ നൽകുന്ന സൗജന്യ പ്രൊവൈഡർമാർ ഏതൊക്കെയെന്ന് കാണാൻ ഡാഷ്ബോർഡിലെ
> **Free Provider Rankings** പേജ് തുറക്കുക — മൊത്തത്തിലുള്ളതോ വിഭാഗം അനുസരിച്ച് ഫിൽട്ടർ ചെയ്തതോ
> (കോഡിംഗ്, റിവ്യൂ, ഡോക്യുമെന്റേഷൻ, ഡീബഗ്ഗിംഗ്).

## ഇത് എന്താണ്

OmniRoute 376 പ്രൊവൈഡർമാരെ രജിസ്റ്റർ ചെയ്യുന്നു; അവയിൽ **സൗജന്യം/ഓത്ത് ആവശ്യമില്ല** എന്ന് അടയാളപ്പെടുത്തിയ 155 കാറ്റലോഗ് എൻട്രികൾ ഉൾപ്പെടുന്നു
(ഓത്ത് ആവശ്യമില്ലാത്തവ,
സൗജന്യ-ടയർ OAuth, അല്ലെങ്കിൽ സൗജന്യ-ടയർ API കീ —
[സൗജന്യ ടയറുകളുടെ ഗൈഡ്](../getting-started/FREE-TIERS-GUIDE.md), കൂടാതെ സമ്പൂർണ്ണ
[സൗജന്യ ടയറുകളുടെ ഡയറക്ടറി](../reference/FREE_TIERS.md) എന്നിവ കാണുക). എന്നാൽ ഒരു പ്രശ്നമുണ്ട്: സൗജന്യ പ്രൊവൈഡർമാർക്കിടയിലെ
മോഡൽ ഗുണനിലവാരത്തിൽ വലിയ വ്യത്യാസമുണ്ട്. അത്യാധുനിക മോഡൽ നൽകുന്ന ഓത്ത് ആവശ്യമില്ലാത്ത പ്രൊവൈഡർ,
ഒരു ചെറിയ കാലഹരണപ്പെട്ട മോഡൽ നൽകുന്ന പ്രൊവൈഡറേക്കാൾ വളരെയധികം പ്രയോജനകരമാണ്.

**സൗജന്യ പ്രൊവൈഡർ റാങ്കിങ്ങുകൾ**, ഓരോ സൗജന്യ പ്രൊവൈഡറുടെയും കാറ്റലോഗിനെ
**Arena AI ലീഡർബോർഡിൽ** നിന്നുള്ള **ക്രൗഡ്-സോഴ്സ് ചെയ്ത ഗുണനിലവാര സ്കോറുകളുമായി** ചേർത്ത്, "**ഏത് സൗജന്യ പ്രൊവൈഡറാണ് എനിക്ക് ഏറ്റവും മികച്ച മോഡൽ നൽകുന്നത്?**" എന്ന ചോദ്യത്തിന് ഉത്തരം നൽകുന്നു
(മനുഷ്യരുടെ മുൻഗണനയെ അടിസ്ഥാനമാക്കിയുള്ള ELO, LMArena
ചാറ്റ്ബോട്ട് അരീനയ്ക്ക് പിന്നിലുള്ള അതേ ആശയം). തുടർന്ന്, പ്രൊവൈഡർമാരുടെ **ഏറ്റവും മികച്ച സൗജന്യ മോഡലിന്റെ** ശേഷിയെ അടിസ്ഥാനമാക്കി അവരെ റാങ്ക് ചെയ്യുന്നു.

മൂന്ന് യഥാർഥ സ്രോതസ്സുകളിൽ നിന്നാണ് റാങ്കിങ് കണക്കാക്കുന്നത്:

1. സൗജന്യ പ്രൊവൈഡർ ലിസ്റ്റുകൾ — `NOAUTH_PROVIDERS`, കൂടാതെ `hasFree` എന്ന് ഫ്ലാഗ് ചെയ്ത `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` എൻട്രികൾ
   (`src/shared/constants/providers.ts`).
2. പ്രൊവൈഡർ രജിസ്ട്രിയിൽ നിന്നുള്ള ഓരോ പ്രൊവൈഡറുടെയും മോഡൽ കാറ്റലോഗ്
   (`open-sse/config/providerRegistry.ts`).
3. Arena ELO സമന്വയ എൻജിൻ (`src/lib/arenaEloSync.ts`) `model_intelligence` DB പട്ടികയിൽ സംഭരിക്കുന്ന, ELO-യിൽ നിന്ന് രൂപപ്പെടുത്തിയ ടാസ്ക്-ഫിറ്റ് സ്കോറുകൾ.

ചേർക്കൽ ലോജിക് `src/lib/freeProviderRankings.ts`-ൽ സ്ഥിതിചെയ്യുന്നു.

## എങ്ങനെ ആക്സസ് ചെയ്യാം

### ഡാഷ്ബോർഡ് പേജ്

ഡാഷ്ബോർഡ് തുറന്ന് **Costs → Free Provider Rankings** എന്നതിലേക്ക് പോകുക, അല്ലെങ്കിൽ നേരിട്ട്
ഇവിടേക്ക് നാവിഗേറ്റ് ചെയ്യുക:

```
/dashboard/free-provider-rankings
```

പേജ് (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) കാണിക്കുന്നത്:

- ഏറ്റവും ഉയർന്ന റാങ്കുള്ള സൗജന്യ പ്രൊവൈഡർമാരുടെ **ആദ്യ 3 പോഡിയം** (🥇 🥈 🥉).
- **Rank**, **Provider**, **Top Model**, **Score**, **Avg Score**, **Models**, **Type**
  എന്നീ കോളങ്ങളുള്ള ഒരു സമ്പൂർണ്ണ **റാങ്കിംഗ് ടേബിൾ**.
- **വിഭാഗ ഫിൽട്ടർ ബട്ടണുകൾ**: _All Categories_, _Default_, _Coding_, _Review_,
  _Documentation_, _Debugging_.

ഓരോ പ്രൊവൈഡറുടെയും **Type** ബാഡ്ജ് അത് എങ്ങനെ സൗജന്യമാണ് എന്ന് വ്യക്തമാക്കുന്നു:

| ബാഡ്ജ്   | അർഥം                                             |
| -------- | ------------------------------------------------ |
| `NOAUTH` | എല്ലായ്പ്പോഴും സൗജന്യം, ക്രെഡൻഷ്യലുകൾ ആവശ്യമില്ല |
| `OAUTH`  | സൗജന്യ ടിയറുള്ള OAuth പ്രൊവൈഡർ (`hasFree`)       |
| `APIKEY` | സൗജന്യ ടിയറുള്ള API-key പ്രൊവൈഡർ (`hasFree`)     |

അടിസ്ഥാന മൂല്യം ഒരു ആപേക്ഷിക റാങ്കിംഗ് ഗുണനിലവാരമാണെന്നും ശതമാനമല്ലെന്നും ഉള്ളതിനാൽ, സ്കോറുകൾ
റോ നമ്പറുകൾക്ക് പകരം മനുഷ്യർക്ക് എളുപ്പം മനസ്സിലാകുന്ന ലേബലുകളായി (ഉദാ. _Elite_,
_Excellent_, _Very Good_, _Good_, _Average_) കാണിക്കുന്നു.

### API എൻഡ്പോയിന്റ്

ഈ പേജിനെ പിന്തുണയ്ക്കുന്നത് ഒരു പൊതു റീഡ് എൻഡ്പോയിന്റാണ്
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

ക്വറി പാരാമീറ്ററുകൾ (Zod ഉപയോഗിച്ച് സാധൂകരിച്ചത്):

| പാരാമീറ്റർ | തരം    | ഡിഫോൾട്ട്    | കുറിപ്പുകൾ                                                                                                     |
| ---------- | ------ | ------------ | -------------------------------------------------------------------------------------------------------------- |
| `category` | string | (ഒന്നുമില്ല) | `default`, `coding`, `review`, `documentation`, `debugging` എന്നിവയിൽ ഒന്ന്. സംയോജിത റാങ്കിംഗിനായി ഒഴിവാക്കുക. |
| `limit`    | number | `50`         | `1–100` പരിധിയിലേക്ക് നിയന്ത്രിച്ചിരിക്കുന്നു.                                                                 |

റെസ്പോൺസ് ഘടന:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` യഥാർഥ Arena ELO മൂല്യമാണ്; `score` നോർമലൈസ് ചെയ്ത ടാസ്ക്-ഫിറ്റ് മൂല്യമാണ്
(താഴെ കാണുക). സ്കോർ ലഭിച്ച മോഡലുകളൊന്നുമില്ലാത്ത പ്രൊവൈഡർമാരെ റെസ്പോൺസിൽ നിന്ന്
ഒഴിവാക്കുന്നു.

## സ്കോറുകൾ എങ്ങനെ പ്രവർത്തിക്കുന്നു

### ഉറവിടം: Arena AI ലീഡർബോർഡ്

Arena ELO സിംക്ക് എഞ്ചിൻ (`src/lib/arenaEloSync.ts`) Arena AI ലീഡർബോർഡ് API-യിൽ
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) നിന്ന് രണ്ട് ലീഡർബോർഡുകൾ — `text`,
`code` — ശേഖരിക്കുന്നു. ആ API ഉപയോഗിക്കാവുന്ന ബോർഡ് നൽകുന്നില്ലെങ്കിൽ, എഞ്ചിൻ Hugging Face
datasets-server-ലെ ഔദ്യോഗിക `lmarena-ai/leaderboard-dataset`-ലേക്ക് ഫോൾബാക്ക് ചെയ്യുന്നു
(`src/lib/arenaEloHfSource.ts`, CC-BY-4.0; `overall` → `text`,
`coding` → `code`); `GET /api/intelligence/sync` `activeSource`, `lastError`,
`lastFailedAt` എന്നിവ റിപ്പോർട്ട് ചെയ്യുന്നു. ഓരോ ലീഡർബോർഡ് എൻട്രിയിലും ഒരു മോഡൽ പേര്, വെണ്ടർ,
ELO `score`, കോൺഫിഡൻസ് ഇൻ്റർവൽ, വോട്ട് എണ്ണം എന്നിവ ഉണ്ട്.

ലീഡർബോർഡ് വിഭാഗങ്ങൾ OmniRoute ടാസ്ക്ക് വിഭാഗങ്ങളുമായി മാപ്പ് ചെയ്യപ്പെടുന്നു:

| Arena ലീഡർബോർഡ് | OmniRoute ടാസ്ക്ക് വിഭാഗങ്ങൾ                      |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### നോർമലൈസേഷൻ (ടാസ്ക്ക്-ഫിറ്റ് സ്കോർ)

അസംസ്കൃത ELO സ്കോറുകൾ ഓരോ ലീഡർബോർഡിനും **`[0.4, 0.98]`-ലുള്ള ടാസ്ക്ക്-ഫിറ്റ് മൂല്യമാക്കി**
നോർമലൈസ് ചെയ്യപ്പെടുന്നു:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

സ്കോർ ഒരിക്കലും `0` ലോ `1` ലോ എത്തുന്നില്ല; ഇത് യൂസർ ഓവർറൈഡുകൾക്ക് ഇടം ഒഴിഞ്ഞുനിൽക്കുന്നു. API
പ്രതികരണത്തിൽ നിങ്ങൾ കാണുന്ന `score` ഫീൽഡും ഡാഷ്ബോർഡിൽ കാണിക്കുന്ന ലേബലും ഇതാണ്.

### കോൺഫിഡൻസ്

ഓരോ എൻട്രിക്കും Arena വോട്ട് എണ്ണത്തെ അടിസ്ഥാനമാക്കി ഒരു കോൺഫിഡൻസ് ലെവൽ ലഭിക്കുന്നു:

| കോൺഫിഡൻസ് | വോട്ടുകൾ |
| --------- | -------- |
| `high`    | ≥ 5,000  |
| `medium`  | ≥ 1,000  |
| `low`     | < 1,000  |

### സംഭരണവും പുതുമയും

നോർമലൈസ് ചെയ്ത എൻട്രികൾ `source = "arena_elo"` എന്നതോടെ `model_intelligence` DB ടേബിളിൽ
എഴുതപ്പെടുന്നു (`src/lib/db/modelIntelligence.ts`). എൻട്രികൾ **7 ദിവസത്തിന് ശേഷം
കാലഹരണപ്പെടും**, അതിനാൽ സിംക്ക് നിർത്തുന്ന ഒരു പ്രൊവൈഡർ പഴയ ഡാറ്റ നൽകുന്നതിന് പകരം ക്രമേണ
പട്ടികയിൽ നിന്ന് ഒഴിഞ്ഞുപോകും.

സിംക്ക് **ഡിഫോൾട്ടായി ഓൺ** ആണ്:

- സെർവർ സ്റ്റാർട്ടപ്പിൽ ഒരു തവണയും തുടർന്ന് ആവർത്തിക ടൈമറിലും ഇത് പ്രവർത്തിക്കുന്നു
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts`-ൽ നിന്ന് ബന്ധിപ്പിച്ചിരിക്കുന്നു).
- ഇത് **നോൺ-ബ്ലോക്കിംഗും ഒരിക്കലും പ്രാണനാശകരമല്ലാത്തതും** ആണ് — അപ്സ്ട്രീം ഫെച്ച് പരാജയപ്പെട്ടാൽ,
  OmniRoute പ്രവർത്തിച്ചുകൊണ്ടേയിരിക്കും, റാങ്കിംഗുകൾ അവസാനത്തെ നല്ല ഡാറ്റ (അല്ലെങ്കിൽ
  ശൂന്യമായ അവസ്ഥ) കാണിക്കും.

രണ്ട് എൻവയൺമെന്റ് വേരിയബിളുകൾ ഇത് നിയന്ത്രിക്കുന്നു
([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)-ൽ ഡോക്യുമെന്റ് ചെയ്തിരിക്കുന്നു):

| വേരിയബിൾ                  | ഡിഫോൾട്ട്     | ഉദ്ദേശ്യം                                                     |
| ------------------------- | ------------- | ------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | ഔട്ട്ബൗണ്ട് സിംക്കിൽ നിന്ന് ഒഴിവാകാൻ `false` ആയി സജ്ജമാക്കുക. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | സിംക്ക് ഇടവേള, സെക്കൻഡിൽ.                                     |

### മാൻുവൽ സിംക്ക് / സ്റ്റാറ്റസ് / മായ്ക്കൽ

ഓപ്പറേറ്റർമാർക്കായി, ഓതന്റിക്കേറ്റ് ചെയ്ത ഒരു മാനേജ്മെന്റ് എൻഡ്പോയിന്റ് മാൻുവൽ നിയന്ത്രണം
നൽകുന്നു (`src/app/api/intelligence/sync/route.ts` — മാനേജ്മെന്റ് ഓത്ത് ആവശ്യമാണ്):

```
GET    /api/intelligence/sync          # നിലവിലെ സിംക്ക് സ്റ്റാറ്റസ് (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # മാൻുവൽ സിംക്ക് ട്രിഗർ ചെയ്യുക; എഴുതാതെ പ്രിവ്യൂ ചെയ്യാൻ body: { "dryRun": true }
DELETE /api/intelligence/sync          # സിംക്ക് ചെയ്ത എല്ലാ arena_elo ഇന്റലിജൻസ് എൻട്രികളും മായ്ക്കുക
```

റാങ്കിംഗ്സ് പേജ് ശൂന്യമാണെങ്കിൽ, ഒരു മാൻുവൽ `POST /api/intelligence/sync` (അല്ലെങ്കിൽ
സെർവർ പുനരാരംഭിക്കൽ മാത്രം) അത് വീണ്ടും നിറയ്ക്കും.

### മോഡലുകളെ ലീഡർബോർഡുമായി പൊരുത്തപ്പെടുത്തൽ

റജിസ്ട്രി മോഡൽ ID-കളും Arena മോഡൽ പേരുകളും എല്ലായ്പ്പോഴും കൃത്യമായി പൊരുത്തപ്പെടണമെന്നില്ല.
റാങ്കിംഗ് ഫ്ലെക്സിബിൾ മാച്ചിംഗ് ഉപയോഗിക്കുന്നു (`src/lib/freeProviderRankings.ts`-ലെ
`findMatchingIntelligence`):

1. നോർമലൈസ് ചെയ്ത മോഡൽ ID-യിൽ കൃത്യമായ പൊരുത്തം.
2. അവസാനത്തെ വേർഷൻ സഫിക്സ് നീക്കം ചെയ്തതിന് ശേഷം പൊരുത്തം (ഉദാ. `kimi-k2.6` → `kimi-k2`).
3. പ്രിഫിക്സ് പൊരുത്തം (ലീഡർബോർഡ് മോഡൽ പേര് റജിസ്ട്രി ID-യുടെ ഒരു പ്രിഫിക്സ് ആണ്).

സിംക്ക് ഭാഗത്ത്, അറിയപ്പെടുന്ന വെണ്ടർ പ്രിഫിക്സുകൾ (`anthropic/`, `openai/`, `google/`, …)
നീക്കം ചെയ്യപ്പെടുന്നു, കൂടാതെ ഒരു ചെറിയ അപരനാമ മാപ്പ് കാനോനിക്കൽ പേരുകളെ OmniRoute ആന്തരികമായി
ഉപയോഗിക്കുന്ന വേരിയന്റുകളിലേക്ക് വികസിപ്പിക്കുന്നു, അതിനാൽ ഏത് പേരിലും മോഡലുകൾ കണ്ടെത്താനാവും.

### ഒരു പ്രൊവൈഡർ എങ്ങനെ റാങ്ക് ചെയ്യപ്പെടുന്നു

ഓരോ സൗജന്യ പ്രൊവൈഡർക്കും, എഞ്ചിൻ അതിന്റെ കാറ്റലോഗിലെ ഓരോ മോഡലിനെയും സ്കോർ ചെയ്യുന്നു,
തുടർന്ന്:

- **Top Model** = പ്രൊവൈഡറുടെ ഏറ്റവും ഉയർന്ന സ്കോർ നേടിയ മോഡൽ.
- **Avg Score** = ആ പ്രൊവൈഡറുടെ സ്കോർ ചെയ്ത എല്ലാ മോഡലുകളുടെയും ശരാശരി സ്കോർ.
- **Models** = പ്രൊവൈഡറുടെ എത്ര മോഡലുകൾക്ക് Arena സ്കോർ ഉണ്ടായിരുന്നു.

പ്രൊവൈഡർമാർ ആദ്യം **ടോപ്പ്-മോഡൽ സ്കോർ** അനുസരിച്ചും തുടർന്ന് ശരാശരി സ്കോർ അനുസരിച്ചും
അടുക്കപ്പെടുന്നു. കുറഞ്ഞത് ഒരു ശക്തമായ സൗജന്യ മോഡലെങ്കിലും പുറത്തിറക്കുന്ന പ്രൊവൈഡർക്ക്
ഇത് പ്രതിഫലം നൽകുന്നു.

## സൗജന്യ പ്രൊവൈഡർമാരെ തിരഞ്ഞെടുക്കാൻ ഇത് ഉപയോഗിക്കൽ

1. **ശരിയായ വിഭാഗം തിരഞ്ഞെടുക്കുക.** ഏജന്റിക്/കോഡ് വർക്ക്ലോഡുകൾക്കായി **Coding** ഫിൽട്ടർ ഉപയോഗിക്കുക, അല്ലെങ്കിൽ
   പൊതുവായ ചാറ്റിനായി അത് **All Categories** / **Default** എന്ന നിലയിൽ വിടുക. ഓരോ ലീഡർബോർഡിലും അതിന്റെ മികച്ച മോഡൽ
   വ്യത്യസ്തമായതിനാൽ, ഒരേ പ്രൊവൈഡറിന് വ്യത്യസ്ത വിഭാഗങ്ങളിൽ വ്യത്യസ്ത റാങ്കുകൾ ലഭിക്കാം.
2. **ഒറ്റത്തവണ സജ്ജീകരണങ്ങൾക്ക് പോഡിയത്തിലുള്ളവയ്ക്ക് മുൻഗണന നൽകുക.** ഒന്നോ രണ്ടോ സൗജന്യ
   പ്രൊവൈഡർമാരെ മാത്രം ബന്ധിപ്പിക്കാനാണ് നിങ്ങൾ ആഗ്രഹിക്കുന്നതെങ്കിൽ, നിങ്ങളുടെ വിഭാഗത്തിൽ ഏറ്റവും ഉയർന്ന റാങ്കുള്ളവയിൽ നിന്ന് ആരംഭിക്കുക.
3. **Type ബാഡ്ജ് പരിശോധിക്കുക.** `NOAUTH` പ്രൊവൈഡർമാരാണ് ഏറ്റവും വേഗത്തിൽ ബന്ധിപ്പിക്കാനാകുന്നത്
   (ക്രെഡൻഷ്യലുകൾ ആവശ്യമില്ല). `OAUTH` / `APIKEY` സൗജന്യ ടയറുകൾക്ക് വേഗത്തിലുള്ള ഒരു സൈൻ-അപ്പ് ആവശ്യമാണെങ്കിലും, അവ പലപ്പോഴും
   കൂടുതൽ ശക്തമായ മോഡലുകൾ ലഭ്യമാക്കുന്നു. ബന്ധിപ്പിക്കുന്നതിനുള്ള ഘട്ടങ്ങൾക്കായി [സൗജന്യ ടയറുകളുടെ ഗൈഡ്](../getting-started/FREE-TIERS-GUIDE.md)
   കാണുക.
4. **നിരവധി പ്രൊവൈഡർമാരെ ബന്ധിപ്പിച്ച് Auto-Combo-യെ തീരുമാനിക്കാൻ അനുവദിക്കുക.** ഈ പേജിന് കരുത്ത് നൽകുന്ന അതേ Arena ELO ഡാറ്റ
   Auto-Combo സ്കോറിംഗ് എഞ്ചിന്റെ **ടാസ്ക്-ഫിറ്റ്നസ് ഘടകത്തിനും** ഇൻപുട്ടായി നൽകുന്നു
   (`open-sse/services/autoCombo/taskFitness.ts`, പരിഹാര ക്രമം
   `user_override → arena_elo → models_dev_tier → static table`). അതിനാൽ, മികച്ച സൗജന്യ പ്രൊവൈഡർമാരെ ബന്ധിപ്പിച്ചശേഷം
   `model: "auto"` ഉപയോഗിച്ചുള്ള റൂട്ടിംഗ് (ഉദാ. `auto/coding`) ഓരോ അഭ്യർത്ഥനയ്ക്കും
   ഉയർന്ന നിലവാരമുള്ള സൗജന്യ മോഡലുകൾക്ക് സ്വയമേവ മുൻഗണന നൽകും. പൂർണ്ണമായ 16-ഘടക സ്കോറിംഗിനായി
   [Auto-Combo](../routing/AUTO-COMBO.md) കാണുക.
