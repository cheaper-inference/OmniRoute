ഒരു ഇഷ്ടാനുസൃത JSON API നോഡ് OpenAI അല്ലെങ്കിൽ Anthropic പ്രോട്ടോക്കോൾ സംസാരിക്കാത്ത ഒരു JSON ബിസിനസ് എൻഡ്പോയിൻ്റിനെ ബന്ധിപ്പിക്കുന്നു. OmniRoute ഒരു JSON അഭ്യർത്ഥന ടെംപ്ലേറ്റ് പൂരിപ്പിക്കുന്നു, അത് പൂർണ്ണമായ എൻഡ് പോയിൻ്റിലേക്ക് അയയ്ക്കുന്നു URL, ഒരു പ്രതികരണ പാതയിൽ നിന്നുള്ള മറുപടി വായിച്ച് ക്ലയൻ്റിൻറെ സ്വന്തം ഫോർമാറ്റിൽ അത് ക്ലയൻ്റിലേക്ക് തിരികെ നൽകുന്നു (ചാറ്റ് പൂർത്തിയാക്കലുകൾ, പ്രതികരണങ്ങൾ, സന്ദേശങ്ങൾ, ...).

ഇത് `apiType: "custom-json"` ഉള്ള ഒരു OpenAI-അനുയോജ്യമായ നോഡാണ്; അതിൻ്റെ ഐഡിക്ക് `openai-compatible-custom-json-<suffix>` എന്ന രൂപമുണ്ട്. ഡാഷ്ബോർഡ് ഫോം ഇതുവരെ ലഭ്യമല്ല. ചുവടെയുള്ള പ്രൊവൈഡർ-നോഡ് API വഴി ഈ നോഡുകൾ സൃഷ്ടിക്കുകയും എഡിറ്റുചെയ്യുകയും ചെയ്യുക.

## ഒരു നോഡ് സൃഷ്ടിക്കുക

`POST /api/provider-nodes` (മാനേജ്മെൻ്റ് ആധികാരികത):

```json
{
  "type": "openai-compatible",
  "apiType": "custom-json",
  "name": "Business API",
  "prefix": "biz",
  "baseUrl": "https://api.example.com/v1/answer",
  "customHeaders": { "X-Tenant": "demo" },
  "customJson": {
    "method": "POST",
    "authType": "api-key",
    "authHeader": "X-Service-Key",
    "requestTemplate": {
      "project_id": "demo-project",
      "question": "{{prompt}}",
      "history": "{{messages}}"
    },
    "responsePath": "data.answer"
  }
}
```

- `baseUrl` ആണ്** പൂർണ്ണമായ** അവസാന പോയിൻ്റ് URL. ഒന്നും ചേർത്തിട്ടില്ല ( `/chat/completions`, `/models` ഇല്ല) കൂടാതെ, മറ്റ് OpenAI-അനുയോജ്യമായ നോഡുകളിൽ നിന്ന് വ്യത്യസ്തമായി, സ്ഥിരസ്ഥിതി URL ഇല്ല. എംബഡഡ് ക്രെഡൻഷ്യലുകളോ `#fragment` യോ ഇല്ലാതെ ഇത് `http(s)` ആയിരിക്കണം, കൂടാതെ നോഡ് സേവ് ചെയ്യുമ്പോഴും ഓരോ അഭ്യർത്ഥനയിലും ഓരോ പ്രൊവൈഡർ നോഡിലും ഒരേ ഔട്ട്ബൗണ്ട് URL ഗാർഡ് കടന്നുപോകുന്നു.
- കണക്ഷൻ കീ അയയ്ക്കുന്ന ഒരു നോഡ് (`authType` `bearer` അല്ലെങ്കിൽ `api-key`, ഡിഫോൾട്ട് ഉൾപ്പെടെ) `https://` ഉപയോഗിക്കണം. ഒരു ലൂപ്പ്ബാക്ക് ഹോസ്റ്റിന് (`localhost`, `127.0.0.0/8`, `::1`) അല്ലെങ്കിൽ കീ അയയ്ക്കാത്ത `authType: "none"` യ്ക്ക് മാത്രമേ പ്ലെയിൻ `http://` സ്വീകരിക്കൂ. സ്വകാര്യ LAN വിലാസങ്ങൾ (`10.x`, `172.16-31.x`, `192.168.x`) ഒഴിവാക്കപ്പെടുന്നില്ല: ആ നെറ്റ്വർക്കിലുള്ള ആർക്കും കീ വായിക്കാൻ കഴിയും. അത്തരത്തിലുള്ള ഒരു നോഡ് സംരക്ഷിക്കുന്നത് `400` ഉപയോഗിച്ച് പരാജയപ്പെടുന്നു, കൂടാതെ ഏതെങ്കിലും അഭ്യർത്ഥന അയയ്ക്കുന്നതിന് മുമ്പ് ഒരേ സന്ദേശമുള്ള എല്ലാ അഭ്യർത്ഥനകളിലും മുമ്പ് സംഭരിച്ച ഒരു നോഡ് പരാജയപ്പെടുന്നു. ഒരു LAN യിലെ ഒരു കീഡ് എൻഡ്പോയിൻ്റിന്, അത് TLS പിന്നിൽ വയ്ക്കുക (ഉദാഹരണത്തിന് ഒരു റിവേഴ്സ് പ്രോക്സി).
- `customJson` Zod ഉപയോഗിച്ച് സാധൂകരിക്കപ്പെടുന്നു; അജ്ഞാത കീകൾ നിരസിച്ചു. ഓരോ ഫീൽഡും ഓപ്ഷണൽ ആണ്:

| ഫീൽഡ്             | മൂല്യങ്ങൾ                                       | സ്ഥിരസ്ഥിതി                                            |
| ----------------- | ----------------------------------------------- | ------------------------------------------------------ |
| `method`          | `POST`, `PUT`, `PATCH`                          | `POST`                                                 |
| `authType`        | `bearer`, `api-key`, `none`                     | `bearer`                                               |
| `authHeader`      | `api-key` ഉപയോഗിക്കുമ്പോൾ തലക്കെട്ടിൻ്റെ പേര്   | `X-API-Key`                                            |
| `requestTemplate` | JSON വസ്തു (≤ 64 KB, ആഴം ≤ 32)                  | `{ "model": "{{model}}", "messages": "{{messages}}" }` |
| `responsePath`    | ഫീൽഡ് പാത്ത്, അല്ലെങ്കിൽ മുഴുവൻ ശരീരത്തിനും `$` | `choices[0].message.content`                           |

- ടെംപ്ലേറ്റിലല്ല, കണക്ഷൻ്റെ API കീയിലാണ് രഹസ്യം നിലനിൽക്കുന്നത്. `bearer` `Authorization: Bearer <key>` അയയ്ക്കുന്നു; `api-key` `<authHeader>: <key>` അയയ്ക്കുന്നു. ഓത്ത് ഹെഡർ `Host`, `Content-Type`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Authorization`, `Cookie` അല്ലെങ്കിൽ ഒരു ഹോപ്പ്-ബൈ-ഹോപ്പ് ഹെഡർ ആവരുത്. `none` ഉപയോഗിച്ച്, കണക്ഷനുകൾക്ക് കീ ആവശ്യമില്ല.
- എക്സ്ട്രാ സ്റ്റാറ്റിക് ഹെഡറുകൾ നോഡിൻ്റെ റെഗുലർ `customHeaders` ഉപയോഗിക്കുന്നു (മറ്റെല്ലാ അനുയോജ്യമായ നോഡുകളുടെയും അതേ മൂല്യനിർണ്ണയം; ഓത്ത് ഹെഡറുകൾ അവിടെ അനുവദനീയമല്ല).

`PUT /api/provider-nodes/<id>` അതേ `customJson` സ്വീകരിക്കുകയും നോഡിൻ്റെ നിലവിലുള്ള എല്ലാ കണക്ഷനുകളിലും `baseUrl` ഉം കോൺഫിഗറും വീണ്ടും എഴുതുകയും ചെയ്യുന്നു. `customJson` ഒഴിവാക്കുന്നത് സംഭരിച്ച കോൺഫിഗറേഷൻ നിലനിർത്തുന്നു; `apiType` ലേക്ക് `chat` അല്ലെങ്കിൽ `responses` ലേക്ക് മാറുന്നത് നോഡിൽ നിന്നും അതിൻ്റെ കണക്ഷനുകളിൽ നിന്നും നീക്കംചെയ്യുന്നു.

തുടർന്ന് നോഡിലേക്ക് സാധാരണ പോലെ ഒരു കണക്ഷൻ ചേർക്കുക (നോഡ് ഐഡിയുള്ള `POST /api/providers` ) കൂടാതെ `<prefix>/<model>` അഭ്യർത്ഥിക്കുക, ഉദാഹരണത്തിന് `biz/assistant-v1`. എൻഡ്പോയിൻ്റ് ഒരു മോഡൽ ലിസ്റ്റും വെളിപ്പെടുത്തുന്നില്ല, അതിനാൽ മോഡൽ ഐഡികൾ കൈകൊണ്ട് ചേർക്കുക.

## ടെംപ്ലേറ്റുകൾ അഭ്യർത്ഥിക്കുക

ടെംപ്ലേറ്റുകൾ പ്ലെയിൻ JSON ആണ്. ഒരു സ്ട്രിംഗ് മൂല്യത്തിൽ `{{placeholder}}` മാർക്കറുകൾ അടങ്ങിയിരിക്കാം; ഒന്നും വിലയിരുത്തുകയോ നിർവ്വഹിക്കുകയോ ചെയ്യുന്നില്ല, ഒബ്ജക്റ്റ് കീകൾ ഒരിക്കലും പകരം വയ്ക്കില്ല.

| പ്ലെയ്സ്ഹോൾഡർ        | മൂല്യം                                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------- |
| `{{prompt}}`         | ഏറ്റവും പുതിയ ഉപയോക്തൃ സന്ദേശത്തിൻ്റെ വാചകം (ടെക്സ്റ്റ് ഭാഗങ്ങൾ പുതിയ ലൈനുകൾക്കൊപ്പം ചേർത്തു) |
| `{{messages}}`       | സംഭാഷണം OpenAI ചാറ്റ് ഫോർമാറ്റിലാണ്                                                           |
| `{{model}}`          | പ്രൊവൈഡർ പ്രിഫിക്സ് ഇല്ലാതെ അഭ്യർത്ഥിച്ച മോഡൽ ഐഡി                                             |
| `{{stream}}`         | എല്ലായ്പ്പോഴും `false` — ഒരു JSON ഡോക്യുമെൻ്റ് ഉപയോഗിച്ച് എൻഡ്പോയിൻ്റ് ഉത്തരം നൽകുന്നു        |
| `{{request.<path>}}` | വിവർത്തനം ചെയ്ത (OpenAI ചാറ്റ് ഫോർമാറ്റ്) അഭ്യർത്ഥനയുടെ ഒരു ഫീൽഡ്                             |

- കൃത്യമായി ഒരു പ്ലെയ്സ്ഹോൾഡർ ആയ ഒരു മൂല്യം അതിൻ്റെ JSON തരം നിലനിർത്തുന്നു (`"{{messages}}"` ഒരു അറേ ആയി മാറുന്നു); ദൈർഘ്യമേറിയ സ്ട്രിംഗിനുള്ളിൽ ഒരു പ്ലെയ്സ്ഹോൾഡർ ടെക്സ്റ്റായി ചേർത്തിരിക്കുന്നു.
- അപൂർണ്ണമായ പേലോഡ് അയയ്ക്കുന്നതിനുപകരം HTTP 400 ഉപയോഗിച്ച് അഭ്യർത്ഥന പരാജയപ്പെടുത്തുന്ന ഒരു പ്ലെയ്സ്ഹോൾഡർ ഒന്നുമില്ല.
- പാതകൾ ഡോട്ട് നൊട്ടേഷനും ന്യൂമറിക് ഇൻഡക്സുകളും (`data.items[0].text`) ഉപയോഗിക്കുന്നു. കീകളിലും പാതകളിലും `__proto__`, `prototype`, `constructor` എന്നിവ നിരസിക്കപ്പെട്ടു.

## പ്രതികരണങ്ങൾ

`responsePath` യിലെ മൂല്യം അസിസ്റ്റൻ്റ് മറുപടിയായി മാറുന്നു: സ്ട്രിംഗുകൾ കടന്നുപോകുന്നു, മറ്റ് JSON മൂല്യങ്ങൾ ക്രമീകരിച്ചിരിക്കുന്നു. നഷ്ടമായ അല്ലെങ്കിൽ `null` ഫീൽഡ് അല്ലെങ്കിൽ JSON അല്ലാത്ത ഒരു ബോഡി HTTP 502 നൽകുന്നു. അപ്സ്ട്രീം പിശക് നിലകൾ കടന്നുപോകുന്നു. സ്ട്രീമിംഗ് ക്ലയൻ്റുകൾക്ക് OmniRoute മുഴുവൻ JSON പ്രതികരണത്തിനായി കാത്തിരിക്കുന്നു, തുടർന്ന് അത് ഒരു ഉള്ളടക്ക ഭാഗവും ഫിനിഷ് ചങ്കും ആയി പുറത്തുവിടുന്നു; ഇത് ടോക്കൺ സ്ട്രീമിംഗ് അല്ല. ടൂൾ കോളുകളും ഉപയോഗ ഫീൽഡുകളും മാപ്പ് ചെയ്തിട്ടില്ല.

## ഒരിക്കലും റീപ്ലേ ചെയ്തിട്ടില്ല

ഒരു ബിസിനസ്സ് അഭ്യർത്ഥന പരാജയപ്പെടുമ്പോൾ പോലും പാർശ്വഫലങ്ങൾ ഉണ്ടാക്കാം. അതിനാൽ OmniRoute അത് ഒരിക്കൽ അയയ്ക്കുന്നു:

- ഗതാഗത പുനഃശ്രമമില്ല, തുടർന്ന് റീഡയറക്ടില്ല;
- മറ്റൊരു കണക്ഷനിൽ വീണ്ടും ശ്രമിക്കരുത് (അക്കൗണ്ട് ഫാൾബാക്ക്) — പരാജയം അതേപടി തിരികെ നൽകുകയും കണക്ഷൻ തണുപ്പിക്കാതിരിക്കുകയും ചെയ്യുന്നു;
- ശൂന്യമായതോ പരാജയപ്പെട്ടതോ ആയ മറുപടിക്ക് പോലും, അടുത്ത കോംബോ ടാർഗെറ്റിലേക്ക് തിരിച്ചുവരില്ല.

പ്രത്യേക ക്ലയൻ്റ് അഭ്യർത്ഥനകളും നിരവധി മോഡലുകളെ വ്യക്തമായി വിളിക്കുന്ന ഫ്യൂഷൻ പാനലുകളും ഇപ്പോഴും സ്വതന്ത്രമായി എൻഡ് പോയിൻ്റ് അഭ്യർത്ഥിക്കുന്നു.

## ഒരു നോഡ് പരിശോധിക്കുന്നു

ഒരു കണക്ഷൻ സംരക്ഷിക്കുന്നു, കണക്ഷൻ** ടെസ്റ്റ്** ബട്ടണും പശ്ചാത്തല ആരോഗ്യ പരിശോധനകളും ഒരിക്കലും എൻഡ്പോയിൻ്റിനെ വിളിക്കില്ല: അവ സംഭരിച്ച കോൺഫിഗറേഷനെ മാത്രം സാധൂകരിക്കുകയും കണക്ഷൻ പരിശോധിക്കാനാകില്ലെന്ന് റിപ്പോർട്ട് ചെയ്യുകയും ചെയ്യുന്നു.

`"apiType": "custom-json"` ഉം നോഡ് ഫീൽഡുകളുമുള്ള `POST /api/provider-nodes/validate` (`baseUrl`, `apiKey`, `customJson`, ഓപ്ഷണൽ `customHeaders`, `modelId`) ഒരു യഥാർത്ഥ അഭ്യർത്ഥന അയയ്ക്കുന്നു, `ping` ഏറ്റവും പുതിയ ഉപയോക്തൃ വാചകമായി. ഇത് `{ "valid": true }` അല്ലെങ്കിൽ അപ്സ്ട്രീം സ്റ്റാറ്റസിന് ഉത്തരം നൽകുന്നു (ഒരിക്കലും അപ്സ്ട്രീം ബോഡി അല്ല).

## സംഭരണം

കോൺഫിഗറേഷൻ `provider_nodes.custom_json_config_json` (മൈഗ്രേഷൻ `240_provider_node_custom_json_config.sql`) യിൽ സംഭരിക്കുകയും ഓരോ കണക്ഷൻ്റെ `providerSpecificData.customJson` ലേക്ക് പകർത്തുകയും ചെയ്യുന്നു.

നടപ്പിലാക്കൽ: `open-sse/utils/customJson.ts` (സാധുവാക്കലും ടെംപ്ലേറ്റിംഗും), `open-sse/executors/customJson.ts` (എക്സിക്യൂട്ടർ), `open-sse/services/combo/noReplayLatch.ts`, `src/sse/handlers/chat/responsePolicies.ts` (നോ-റിപ്ലേ).
