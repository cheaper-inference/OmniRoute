## ഇത് എന്താണ് (എന്തല്ല)

ടോക്കൺ എണ്ണത്തെ ഒരു മോഡലിന്റെ നിരക്കുകൾ കൊണ്ട് ഗുണിച്ച്, ഓരോ completion-നും
അഭ്യർത്ഥനാടിസ്ഥാനത്തിലുള്ള USD ചെലവ് OmniRoute കണക്കാക്കുന്നു. ഈ സംഖ്യകളാണ് **Costs** ഡാഷ്ബോർഡ്,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON എക്സ്പോർട്ടുകൾ, ഓരോ API കീയുടെയും ബജറ്റുകൾ എന്നിവയ്ക്ക് അടിസ്ഥാനം.

> **ഡാഷ്ബോർഡിലെ "cost" ഒരു സേവിംഗ്സ് ട്രാക്കറാണ്, ബിൽ അല്ല.** OmniRoute നിങ്ങളിൽ നിന്ന് ഒരിക്കലും നിരക്ക് ഈടാക്കുന്നില്ല
> — നിങ്ങൾ ഇതിനകം ബന്ധിപ്പിച്ചിട്ടുള്ള പ്രൊവൈഡറുകളിലേക്കാണ് അത് നിങ്ങളുടെ അഭ്യർത്ഥനകൾ റൂട്ട് ചെയ്യുന്നത് (നിങ്ങളുടെ സ്വന്തം
> സബ്സ്ക്രിപ്ഷനുകൾ, സൗജന്യ ടയറുകൾ, API കീകൾ എന്നിവ). സൗജന്യ മോഡലുകളിൽ മാത്രം ഉണ്ടായ "$290 total cost"
> എന്നത്, ഒരു പണമടച്ചുള്ള API-യ്ക്ക് നിങ്ങൾ **ഏകദേശം $290 നൽകേണ്ടി _വന്നില്ല_** എന്നാണ് അർത്ഥമാക്കുന്നത്. അതേ ട്രാഫിക്കിന്
> സാധാരണ ലിസ്റ്റ് നിരക്കുകൾ പ്രകാരം എത്ര ചെലവാകുമായിരുന്നുവെന്നതിന്റെ ഒരു _ഏകദേശ കണക്കാണ്_ ഈ സംഖ്യ.
> അതുവഴി നിങ്ങളുടെ ഉപയോഗം എവിടെയാണ് കേന്ദ്രീകരിച്ചിരിക്കുന്നത് എന്നും വിലകുറഞ്ഞ/സൗജന്യ പ്രൊവൈഡറുകളിലേക്കുള്ള റൂട്ടിംഗ്
> നിങ്ങൾക്ക് എത്ര പണം ലാഭിച്ചുതരുന്നു എന്നും കാണാൻ കഴിയും.

ഈ വിശദീകരണം പ്രോജക്റ്റിന്റെ [README](../../README.md)-ൽ നേരിട്ട് നൽകിയിട്ടുണ്ട് ("ഡാഷ്ബോർഡിലെ
'cost' ഒരു സേവിംഗ്സ് ട്രാക്കറാണ്, ബിൽ അല്ല").

ഈ സംഖ്യ ഒരു ഏകദേശ കണക്കായതിനാൽ:

- ഓരോ മോഡലിനുമായി OmniRoute-ൽ ഉള്ള നിരക്ക് പട്ടികയെ ഇത് ആശ്രയിക്കുന്നു. നിരക്ക്
  എൻട്രിയില്ലാത്ത ഒരു മോഡൽ `0` ചെലവാണ് സംഭാവന ചെയ്യുന്നത് (എക്സ്പ്ലോററിൽ അത് "Legacy / Free" വരിയായി കാണപ്പെടുന്നു).
- സൗജന്യ ടയർ, സബ്സ്ക്രിപ്ഷൻ ട്രാഫിക്കുകൾക്കും ഒരു _ഏകദേശ_ ചെലവ് രേഖപ്പെടുത്തപ്പെടും — അത്
  നിങ്ങൾ ലാഭിക്കുന്ന തുകയാണ്, നൽകാനുള്ള തുകയല്ല.

## ചെലവുകൾ എങ്ങനെയാണ് കണക്കാക്കുന്നത്

### വിലനിർണ്ണയ ഉറവിടം

ഈ മുൻഗണനാക്രമത്തിൽ, [`src/lib/db/settings/pricing.ts`](../../src/lib/db/settings/pricing.ts) യിലെ ലയിപ്പിച്ച വിലനിർണ്ണയ പട്ടികയിൽ നിന്നാണ് ചെലവുകൾ വരുന്നത് (** ഏറ്റവും ഉയർന്നത് ആദ്യം** ):

1. **ഉപയോക്താവ് അസാധുവാക്കുന്നു** — വിലകൾ ഡാഷ്ബോർഡിലോ `PATCH /api/pricing` വഴിയോ സജ്ജീകരിച്ചിരിക്കുന്നു ( `pricing` നെയിംസ്പെയ്സ്).
2. **models.dev സമന്വയം** — വിലനിർണ്ണയം `https://models.dev/api.json` ൽ നിന്ന് ( `models_dev_pricing` നെയിംസ്പേസ്) കണ്ടെത്തി.
3. **LiteLLM സമന്വയം** — വിലകൾ LiteLLM യുടെ പൊതു `model_prices_and_context_window.json` ൽ നിന്ന് ( `pricing_synced` നെയിംസ്പെയ്സ്) കണ്ടെത്തി.
4. **ഹാർഡ്കോഡ് ഡിഫോൾട്ടുകൾ** — നിരക്കുകൾ [`src/shared/constants/pricing/`](../../src/shared/constants/pricing/) ൽ അയച്ചു.

അതേ provider/model യ്ക്ക്, ഉയർന്ന മുൻഗണനയുള്ള ലെയറുകളിൽ നിന്നുള്ള മൂല്യങ്ങൾ താഴ്ന്ന ലെയറുകളിൽ പൊരുത്തപ്പെടുന്ന ഫീൽഡുകളെ പുനരാലേഖനം ചെയ്യുന്നു; മുകളിലെ ലെയറിൽ ഇല്ലാത്ത ഫീൽഡുകൾ ഇപ്പോഴും താഴത്തെ പാളിയിൽ നിന്ന് വരാം. രണ്ട് സ്വതന്ത്ര സമന്വയ ജോലികളും ഒരേ സമയം പ്രവർത്തിക്കുമ്പോൾ പോലും ഓർഡർ സ്ഥിരമായിരിക്കും. `GET /api/pricing?includeSources=1` `pricing`, `sourceMap` എന്നിവ നൽകുന്നു, അതിൻ്റെ ഓരോ മോഡൽ ലേബലുകൾ (`user`, `modelsDev`, `litellm`, `default`) ആ മോഡൽ അടങ്ങുന്ന ഉയർന്ന മുൻഗണനയുള്ള ലെയറിനെ തിരിച്ചറിയുന്നു.

**LiteLLM സമന്വയം** ഓപ്റ്റ്-ഇൻ ആണ്, ഡിഫോൾട്ടായി പ്രവർത്തനരഹിതമാക്കിയിരിക്കുന്നു. അതിൻ്റെ പരിസ്ഥിതി വേരിയബിളുകൾ ( [`.env.example`](../../.env.example) കാണുക) ഇവയാണ്:

| Env var                 | സ്ഥിരസ്ഥിതി | ഉദ്ദേശം                                                                                        |
| ----------------------- | ----------- | ---------------------------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`     | പശ്ചാത്തല LiteLLM വിലനിർണ്ണയ സമന്വയം പ്രവർത്തനക്ഷമമാക്കുക.                                     |
| `PRICING_SYNC_INTERVAL` | `86400`     | ഇടവേളകൾ സെക്കൻഡിൽ (പ്രതിദിനം) സമന്വയിപ്പിക്കുക.                                                |
| `PRICING_SYNC_SOURCES`  | `litellm`   | ഈ സമന്വയത്തിനുള്ള ഉറവിടം തിരഞ്ഞെടുക്കൽ മാത്രം; നിലവിൽ `litellm` മാത്രമേ പിന്തുണയ്ക്കുന്നുള്ളൂ. |

**models.dev സമന്വയം** LiteLLM സമന്വയത്തിൽ നിന്ന് വേറിട്ടതാണ് കൂടാതെ സ്ഥിരസ്ഥിതിയായി പ്രവർത്തനരഹിതമാക്കുകയും ചെയ്യുന്നു. ഇത് ക്രമീകരണങ്ങളിൽ (models.dev സമന്വയം) പ്രവർത്തനക്ഷമമാക്കുക അല്ലെങ്കിൽ ഈ വേരിയബിളുകൾ ഉപയോഗിക്കുക:

| Env var                    | സ്ഥിരസ്ഥിതി             | ഉദ്ദേശം                                                                                                                                                                  |
| -------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `MODELS_DEV_SYNC_ENABLED`  | _(സജ്ജീകരിച്ചിട്ടില്ല)_ | അൺസെറ്റ് ക്രമീകരണങ്ങൾ ടോഗിൾ പിന്തുടരുന്നു; `1/true/on/yes` ഫോഴ്സ് ഓൺ ചെയ്യുകയും `0/false/off/no` ഫോഴ്സ് ഓഫ് ചെയ്യുകയും ചെയ്യുന്നു (ക്രമീകരണങ്ങൾ ഇത് പ്രാപ്തമാക്കിയാലും). |
| `MODELS_DEV_SYNC_INTERVAL` | `86400`                 | ഡിഫോൾട്ട് models.dev സമന്വയ ഇടവേള സെക്കൻ്റുകൾക്കുള്ളിൽ (പ്രതിദിനം).                                                                                                      |

`PRICING_SYNC_SOURCES` ചെയ്യുന്നു** അല്ല** models.dev പ്രവർത്തനക്ഷമമാക്കുക; ഇത് LiteLLM സമന്വയം മാത്രം നിയന്ത്രിക്കുന്നു. ഒരു ഉപയോക്തൃ അസാധുവാക്കൽ ഇല്ലാതാക്കുന്നത് സമന്വയിപ്പിച്ച നെയിംസ്പേസ് മായ്ക്കുന്നില്ല; ലഭ്യമായ അടുത്ത വിലനിർണ്ണയ പാളി ഫലപ്രദമാകും. വിലയില്ലാത്ത മോഡലിന്, ഒരു മാനുവൽ ഓവർറൈഡ് ചേർക്കുന്നതിന് മുമ്പ് സമന്വയ ക്രമീകരണങ്ങളും `sourceMap` ഉം പരിശോധിക്കുക.

### ചെലവ് ഫോർമുല

ടോക്കൺ എണ്ണത്തിൽ നിന്നും ഓരോ ദശലക്ഷത്തിനും ടോക്കൺ നിരക്കുകളിൽ നിന്നും ഓരോ അഭ്യർത്ഥനയ്ക്കും ചെലവ് കണക്കാക്കുന്നു [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`):

- **ഇൻപുട്ട് ടോക്കണുകൾ** (മൈനസ് കാഷെ റീഡുകളും കാഷെ-ക്രിയേഷൻ ടോക്കണുകളും) × `input` നിരക്ക്.
- **കാഷെ റീഡ് ടോക്കണുകൾ** × `cached` നിരക്ക് (ഇൻപുട്ട് നിരക്കിലേക്ക് മടങ്ങുന്നു).
- **കാഷെ സൃഷ്ടിക്കൽ ടോക്കണുകൾ** × `cache_creation` നിരക്ക് (ഇൻപുട്ട് നിരക്കിലേക്ക് മടങ്ങുന്നു).
- **ഔട്ട്പുട്ട് ടോക്കണുകൾ** × `output` നിരക്ക്.
- **ന്യായവാദം ടോക്കണുകൾ** × `reasoning` നിരക്ക് (ഔട്ട്പുട്ട് നിരക്കിലേക്ക് മടങ്ങുന്നു).

എല്ലാ നിരക്കുകളും 1,000,000 ടോക്കണുകൾക്ക് USD ആയി വ്യാഖ്യാനിക്കപ്പെടുന്നു. ഒരു Codex "ഫാസ്റ്റ്"/"പ്രയോറിറ്റി" അല്ലെങ്കിൽ "ഫ്ലെക്സ്" സർവീസ് ടയർ ഒരു കോസ്റ്റ് മൾട്ടിപ്ലയർ (`getCodexFastCostMultiplier`) — പ്രയോഗിക്കുന്നു ഉദാ. ഫ്ലെക്സിന് 50% ടോക്കൺ ഡിസ്കൗണ്ടിൽ ബിൽ ചെയ്യുന്നു** ഫ്ലെക്സ് സേവിംഗ്സ്** ഡാഷ്ബോർഡിൽ.

മോഡൽ പേരുകൾ ആദ്യം നോർമലൈസ് ചെയ്തിരിക്കുന്നു ( `openai/` അല്ലെങ്കിൽ `accounts/fireworks/models/` പോലുള്ള ദാതാവിൻ്റെ-പാത്ത് പ്രിഫിക്സുകൾ നീക്കം ചെയ്തിരിക്കുന്നു) അതിനാൽ ചരിത്രപരമായ വരികൾ ഇപ്പോഴും വിലയുമായി പൊരുത്തപ്പെടുന്നു.

### ചെലവഴിക്കുന്നത് എങ്ങനെയാണ് രേഖപ്പെടുത്തിയിരിക്കുന്നത്

- അഭ്യർത്ഥന പൂർത്തിയാകുമ്പോൾ ഓരോ അഭ്യർത്ഥനയുടെയും ചെലവ് കണക്കാക്കുന്നു. [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) വഴിയുള്ള അടുത്ത ഇവൻ്റ്-ലൂപ്പ് ടിക്കിൽ പങ്കിട്ട ക്വാട്ട ഉപഭോഗം ഷെഡ്യൂൾ ചെയ്തിരിക്കുന്നു.
- API-കീ ചെലവ് [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (ഡിഫോൾട്ട് 60s ഫ്ലഷ് ഇടവേള, 1,000-എൻട്രി ബഫർ) ബാച്ചുകളായി ബഫർ ചെയ്യുകയും ഫ്ലഷ് ചെയ്യുകയും ചെയ്യുന്നു. ഇതുവഴി ട്യൂൺ ചെയ്യാം:

  | Env var                             | സ്ഥിരസ്ഥിതി | ഉദ്ദേശം                                          |
  | ----------------------------------- | ----------- | ------------------------------------------------ |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`     | മില്ലിസെക്കൻഡിൽ ഫ്ലഷ് ഇടവേള.                     |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`      | ഫ്ലഷ് ചെയ്യുന്നതിന് മുമ്പ് പരമാവധി ബഫർ എൻട്രികൾ. |

ചെലവുകൾ ഒരു കൃത്യമായ ദാതാവ് റിപ്പോർട്ട് ചെയ്ത ചാർജ് (`provider_cost_usd`), തുടർന്ന് കാറ്റലോഗ് വിലയുള്ള അഭ്യർത്ഥന സ്നാപ്പ്ഷോട്ട് (`calculated_cost_usd`), തുടർന്ന് നിലവിലെ കാറ്റലോഗിൽ നിന്നുള്ള ടോക്കൺ റീപ്രൈസിംഗ് എന്നിവ തിരഞ്ഞെടുക്കുന്നു. സംഭരിച്ച ചെലവുകൾ അവയുടെ ടോക്കൺ എണ്ണത്തിലൂടെ വീണ്ടും ഈടാക്കില്ല. കാറ്റലോഗ് വില മാറുമ്പോൾ ലെഗസി ടോക്കൺ മാത്രമുള്ള വരികൾ ഇപ്പോഴും മാറും.

### OCR, ഉൾച്ചേർക്കലുകൾ

- വിജയകരമായ `/v1/ocr` അഭ്യർത്ഥനകൾ അപ്സ്ട്രീം `usage_info.pages_processed` ഉപയോഗിക്കുന്നു, അഭ്യർത്ഥിച്ച പേജ് ശ്രേണിയോ നൽകിയ പേജ് ഒബ്ജക്റ്റുകളുടെ എണ്ണമോ അല്ല. എസ്റ്റിമേറ്റ് പേജുകൾ × `ocr_cost_per_page` ആണ് (സമ്പൂർണ USD/page,** അല്ല** USD/million).
- ഡോക്യുമെൻ്റ് അല്ലെങ്കിൽ ബൗണ്ടിംഗ്-ബോക്സ് വ്യാഖ്യാനങ്ങളുള്ള അഭ്യർത്ഥനകൾക്ക് ഒരു പ്രത്യേക `ocr_cost_per_annotated_page` താരിഫ് ആവശ്യമാണ്. അതില്ലാതെ, ചെലവ് അജ്ഞാതമായി തുടരുന്നു; സാധാരണ OCR താരിഫ് നിശബ്ദമായി പകരം വയ്ക്കുന്നില്ല.
- LiteLLM സമന്വയം അതിൻ്റെ അപ്സ്ട്രീം `annotation_cost_per_page` ഫീൽഡ് `ocr_cost_per_annotated_page` ലേക്ക് മാപ്പ് ചെയ്യുന്നു, കേവല USD/page മൂല്യവും വ്യക്തമായ പൂജ്യം ഉൾപ്പെടെയുള്ള വ്യാഖ്യാന-മാത്രം എൻട്രികളും നിലനിർത്തുന്നു. ഒരു സപ്ലൈഡ് കാനോനിക്കൽ ഫീൽഡ് മുൻഗണന നൽകുന്നു; അസാധുവായ അപരനാമ മൂല്യങ്ങൾ അവഗണിക്കപ്പെടുന്നു. ഉപയോക്തൃ വിലനിർണ്ണയ അസാധുവാക്കലുകൾ അവരുടെ സാധാരണ മുൻഗണന നിലനിർത്തുന്നു. [LiteLLM യുടെ OCR വിലനിർണ്ണയ കീകൾ](https://docs.litellm.ai/docs/providers/mistral_batches#batch-ocr-cost-tracking) കാണുക.
- OCR ഉപയോഗം പേജുകളുടെ എണ്ണം, യൂണിറ്റ് വില, കണക്കാക്കിയ USD വില, API കീ, തിരഞ്ഞെടുത്ത കണക്ഷൻ എന്നിവ സംഭരിക്കുന്നു. പേജുകളെ ഒരിക്കലും ടോക്കണുകളായി പ്രതിനിധീകരിക്കുന്നില്ല. കോൾ ലോഗുകളിൽ ബില്ലിംഗ് മെറ്റാഡാറ്റ അടങ്ങിയിരിക്കുന്നു, ഡോക്യുമെൻ്റ് URLs, PDF ബൈറ്റുകൾ അല്ലെങ്കിൽ എക്സ്ട്രാക്റ്റുചെയ്ത വാചകം എന്നിവയല്ല.
- വിജയകരമായ `/v1/embeddings` അഭ്യർത്ഥനകൾ ഒരേ മില്ലിസെക്കൻഡിൽ പൂർത്തിയാക്കിയ പ്രത്യേക ബാച്ചുകൾ ഉൾപ്പെടെ ഓരോ ഫിസിക്കൽ ബാച്ചിലും ഒരു ഉപയോഗ വരി രേഖപ്പെടുത്തുന്നു. ടോക്കൺ എസ്റ്റിമേറ്റുകളേക്കാൾ ദാതാവ് റിപ്പോർട്ട് ചെയ്ത നിരക്കുകൾ മുൻഗണന നൽകുന്നു; കോംബോ റാപ്പറുകൾ ചാർജ് ചേർക്കുന്നില്ല.
- ഉപയോഗ ചരിത്രം, കോസ്റ്റ് അനലിറ്റിക്സ്, provider/account വിൻഡോകൾ, API-കീ ചെലവ് പരിധികൾ, അഭ്യർത്ഥന-ചെലവ് ലെഡ്ജർ, ദൈനംദിന ഉപയോഗ റോളപ്പുകൾ എന്നിവയിൽ ഈ നിരക്കുകൾ ഉൾപ്പെടുന്നു. നോ-ലോഗ് കീകൾ സോഴ്സ് ടെക്സ്റ്റ് നിലനിർത്താതെ സംഖ്യാപരമായ അക്കൗണ്ടിംഗ് നിലനിർത്തുന്നു.
- നഷ്ടമായ ഉപയോഗമോ താരിഫുകളോ ആണ്** അജ്ഞാതം** , സൗജന്യമല്ല: പ്രതികരണ-ചെലവ് തലക്കെട്ട് ഒഴിവാക്കി, നിലവിലുള്ള വിലയില്ലാത്ത ഉപയോഗ നയം പരിമിതമായ API കീകൾക്ക് ബാധകമാണ്. വ്യക്തമായി കോൺഫിഗർ ചെയ്ത പൂജ്യം നിരക്കുകൾ സാധുതയുള്ള സീറോ-കോസ്റ്റ് ഉപയോഗമായി തുടരും.

ഇത് ഫോർവേഡ്-ഒൺലി അക്കൗണ്ടിംഗ് ആണ്. ഉപയോഗ ചരിത്രം ഒരിക്കലും എഴുതാത്ത പഴയ OCR/embedding കോളുകൾ ഈ മൈഗ്രേഷനിൽ നിന്ന് പുനർനിർമ്മിക്കാൻ കഴിയില്ല. കാറ്റലോഗ് എസ്റ്റിമേറ്റുകൾ USD എസ്റ്റിമേറ്റുകളാണ്, ഇൻവോയ്സ് അല്ല, കറൻസി പരിവർത്തനമോ നികുതിയോ കിഴിവുകളോ ഉൾപ്പെടുന്നില്ല.

### സംഭാഷണവും ചിത്രങ്ങളും

- വിജയകരമായ `/v1/audio/transcriptions`, `/v1/audio/speech`, ഇമേജ്-ജനറേഷൻ ശ്രമങ്ങൾ എന്നിവ സംഖ്യാപരമായ അക്കൗണ്ടിംഗ് പങ്കിടുന്നു. ഡയറക്ട്, കോംബോ കോളുകൾ വിളിക്കുന്നയാളുടെ API കീയും തിരഞ്ഞെടുത്ത കണക്ഷനും വഹിക്കുന്നു; ഒരു കോംബോ റാപ്പർ ഒരിക്കലും രണ്ടാമത്തെ ഡെബിറ്റ് ചേർക്കുന്നില്ല.
- വ്യക്തമായ പൂജ്യം ചാർജ് ഉൾപ്പെടെ, ഒരു കാറ്റലോഗ് എസ്റ്റിമേറ്റിൽ ദാതാവ് റിപ്പോർട്ട് ചെയ്ത USD വിജയിക്കുന്നു. OpenRouter ൻ്റെ JSON `usage.cost` `cost_usd` ആയി നോർമലൈസ് ചെയ്തു. അല്ലാത്തപക്ഷം, അളന്ന ടോക്കണുകൾ ടോക്കൺ വിലകൾ ഉപയോഗിക്കുന്നു, ട്രാൻസ്ക്രിപ്ഷൻ സെക്കൻഡുകൾ ഓരോ സെക്കൻഡിലും വിലകൾ ഉപയോഗിക്കുന്നു, സംഭാഷണ ഇൻപുട്ട് യൂണികോഡ് പ്രതീകങ്ങളുടെ എണ്ണം ഉപയോഗിക്കുന്നു, ഫ്ലാറ്റ്-പ്രൈസ് ഇമേജുകൾ യഥാർത്ഥത്തിൽ തിരികെ നൽകിയ സംഖ്യയാണ് ഉപയോഗിക്കുന്നത്, അഭ്യർത്ഥിച്ച `n` അല്ല.
- ബൈനറി OpenRouter TTS JSON ഉപയോഗ ബോഡി ഇല്ല. ഓഡിയോ പൂർത്തിയായതിന് ശേഷം അല്ലെങ്കിൽ കോളർ റദ്ദാക്കിയതിന് ശേഷം, OmniRoute അതിൻ്റെ ജനറേഷൻ ID ൽ അന്വേഷിക്കുന്നു** അതേ** ക്രമീകരിച്ച OpenRouter ഉത്ഭവം. ഒരു EU അഭ്യർത്ഥന ഒരിക്കലും ആഗോള ഉത്ഭവത്തിലേക്ക് മടങ്ങില്ല. ഇതൊരു പരിധിയുള്ള, വായന-മാത്രം തിരയലാണ്; അക്കൌണ്ടിംഗിനായി സിന്തസിസ് വീണ്ടും ശ്രമിച്ചിട്ടില്ല. ഓഡിയോ പൂർത്തിയായതിന് ശേഷം ബില്ലിംഗ് റെക്കോർഡുകൾ ദൃശ്യമാകും: നെറ്റ്വർക്ക് ഡെഡ്ലൈനുകൾ ഉൾപ്പെടെ ഏകദേശം 52 സെക്കൻഡ് വരെ ലുക്ക്അപ്പ് വീണ്ടും ശ്രമിക്കുന്നു.
- ആ ലുക്ക്അപ്പ് സമയത്ത്, ഓഡിയോ പ്രതികരണത്തിന് `X-OmniRoute-Cost-Status: pending` ഉണ്ട്, പ്രതികരണ ചെലവ് തലക്കെട്ടില്ല. ഉപയോഗ ചരിത്രത്തിലും അനലിറ്റിക്സിലും അനുരഞ്ജനത്തിനു ശേഷമുള്ള കീ ലെഡ്ജറിലും അതിൻ്റെ അന്തിമ ചാർജ് ദൃശ്യമാകും. മെറ്റാഡാറ്റ ലഭ്യമല്ലെങ്കിൽ, കോൺഫിഗർ ചെയ്ത താരിഫ് സ്നാപ്പ്ഷോട്ട് ഉപയോഗിക്കുന്നു; അല്ലാത്തപക്ഷം ചെലവ് അജ്ഞാതമായിരിക്കും.
- സെക്കൻഡുകൾ, പ്രതീകങ്ങൾ, ചിത്രങ്ങളുടെ എണ്ണം എന്നിവയ്ക്ക് പ്രത്യേക ബില്ലിംഗ്-യൂണിറ്റ് ഫീൽഡുകളുണ്ട്, ഒരിക്കലും വ്യാജ ടോക്കൺ എണ്ണമല്ല. അക്കൌണ്ടിംഗ് സംഖ്യാപരമായ ഉപയോഗം മാത്രം നിലനിർത്തുന്നു, സംഭാഷണ വാചകമോ ട്രാൻസ്ക്രിപ്റ്റുകളോ ഇമേജ് ബൈറ്റുകളോ അല്ല. നിലവിലുള്ള വിലയില്ലാത്ത ഇമേജ് ഇളവുകൾക്ക് മാറ്റമില്ല: യഥാർത്ഥമായി നഷ്ടമായ ഇമേജ് താരിഫ് ഒരു പരിമിത കീ പുതുതായി ലോക്ക് ചെയ്യുന്നില്ല, കൂടാതെ പ്രതികരണം കോൾ സൗജന്യമായി പ്രഖ്യാപിക്കുന്നതിനുപകരം കോസ്റ്റ് ഹെഡറിനെ ഒഴിവാക്കുന്നു. ഒരു വിലനിർണ്ണയ സ്റ്റോർ പരാജയം പരാജയപ്പെട്ട-ക്ലോസ്ഡ് എൻഫോഴ്സ്മെൻ്റിനുള്ള ഉപയോഗ തെളിവുകൾ ഇപ്പോഴും നിലനിർത്തുന്നു.

ചരിത്രപരമായ speech/image ചാർജ് കണ്ടുപിടിക്കുകയോ ബാക്ക്ഫിൽ ചെയ്യുകയോ ചെയ്തിട്ടില്ല. ഇൻവോയ്സുകൾക്കും ചാർജ്ജ് റിപ്പോർട്ട് ചെയ്യാത്ത കോളുകൾക്കുമുള്ള റഫറൻസായി ദാതാവിൻ്റെ ബില്ലിംഗ് തുടരുന്നു.

## ഡാഷ്ബോർഡ്: ചെലവുകൾ പേജ്

**ചെലവുകൾ** പേജ് `/dashboard/costs` എന്നതിലാണ്
(`src/app/(dashboard)/dashboard/costs/`).
അതിന്റെ പ്രധാന കാഴ്ച **ചെലവ് അവലോകനം** ടാബാണ്
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
ഇത് `GET /api/usage/analytics`-ൽ നിന്ന് എല്ലാ വിവരങ്ങളും ലോഡ് ചെയ്യുന്നു.

ഇത് കാണിക്കുന്നത്:

- **ചെലവ് ടൈലുകൾ** — _ഇന്ന് (1d)_, _7d_, _30d_, തിരഞ്ഞെടുത്ത സമയപരിധി എന്നിവയ്ക്കുള്ള കണക്കാക്കിയ ചെലവ്. പരിധി സെലക്ടർ: `7d`, `30d`, `90d`, `all`.
- **പ്രധാന മെട്രിക്കുകൾ** — സമയപരിധിയിലെ അഭ്യർത്ഥനകൾ, സജീവ ദാതാക്കൾ, സജീവ മോഡലുകൾ, ഓരോ അഭ്യർത്ഥനയ്ക്കുമുള്ള ശരാശരി ചെലവ്.
- **ചെലവ് എക്സ്പ്ലോറർ** — **ദാതാവ്**, **മോഡൽ**, **API കീ**, **അക്കൗണ്ട്**, അല്ലെങ്കിൽ **സേവന ടയർ** എന്നിവ പ്രകാരം ഗ്രൂപ്പുചെയ്ത, സോർട്ട്/ഫിൽട്ടർ ചെയ്യാവുന്ന പട്ടിക; ഇതിൽ ചെലവ്, അഭ്യർത്ഥനകൾ, ടോക്കണുകൾ, ശരാശരി ചെലവ്/അഭ്യർത്ഥന, മൊത്തത്തിലുള്ള വിഹിതം % എന്നിവ ഉൾപ്പെടുന്നു.
- **ടോക്കൺ ഉപയോഗം** — മൊത്തം / ഇൻപുട്ട് / ഔട്ട്പുട്ട് ടോക്കണുകളും ഇൻപുട്ട്:ഔട്ട്പുട്ട് അനുപാതവും.
- **റൂട്ടിംഗ് കാര്യക്ഷമത** — ഫാൾബാക്ക് എണ്ണം, ഫാൾബാക്ക് നിരക്ക്, അഭ്യർത്ഥിച്ച മോഡലിന്റെ കവറേജ്.
- **പ്രതിമാസ പ്രവചനം** — സമീപകാല ദൈനംദിന ശരാശരിയിൽ നിന്ന് മാസാവസാന ചെലവ് പ്രവചിക്കുന്നു.
- **കാലയളവ് താരതമ്യം** — സമയപരിധിയുടെ ആദ്യ പകുതിയും രണ്ടാം പകുതിയും തമ്മിലുള്ള % മാറ്റം.
- **ചാർട്ടുകൾ** — ദൈനംദിന ചെലവ് ട്രെൻഡ്, ദാതാക്കളുടെ വിഹിതം (പൈ), മുൻനിര ദാതാക്കൾ, മുൻനിര മോഡലുകൾ, API കീ പ്രകാരമുള്ള ചെലവ്, അക്കൗണ്ട് പ്രകാരമുള്ള ചെലവ്, പ്രതിവാര ഉപയോഗ പാറ്റേൺ, പ്രവർത്തന ഹീറ്റ്മാപ്പ്.
- **എക്സ്പോർട്ട്** — നിലവിലെ സമയപരിധി **CSV** അല്ലെങ്കിൽ **JSON** ആയി ഡൗൺലോഡ് ചെയ്യുക (പൂജ്യമല്ലാത്ത ചെലവ് ഡാറ്റ ലഭ്യമായാൽ ബട്ടണുകൾ ദൃശ്യമാകും).

നിരക്ക് നിശ്ചയിച്ച ട്രാഫിക് ഇല്ലാത്തപ്പോൾ, `$0` എന്നതിന് പകരം വരികൾ "ലെഗസി / സൗജന്യം" എന്ന ലേബലോടെ റെൻഡർ ചെയ്യപ്പെടും; ഇത് സേവിംഗ്സ്-ട്രാക്കർ മോഡലിനെ പ്രതിഫലിപ്പിക്കുന്നു.

### ബന്ധപ്പെട്ട ചെലവുകളുടെ ഉപപേജുകൾ

ചെലവുകൾ ഏരിയയിൽ ഇനിപ്പറയുന്നവയും ഉൾപ്പെടുന്നു (എല്ലാം `/dashboard/costs/` എന്നതിന് കീഴിൽ):

- **നിരക്ക് നിർണ്ണയം** (`/dashboard/costs/pricing`) — ഓരോ മോഡലിന്റെയും നിരക്കുകൾ കാണുകയും ഓവർറൈഡ് ചെയ്യുകയും ചെയ്യുക (പങ്കിട്ട നിരക്ക് നിർണ്ണയ ടാബ് റെൻഡർ ചെയ്യുന്നു).
- **ബജറ്റ്** (`/dashboard/costs/budget`) — ഓരോ സ്കോപ്പിനുമുള്ള ചെലവ് പരിധികൾ സജ്ജീകരിക്കുക (പങ്കിട്ട ബജറ്റ് ടാബ് റെൻഡർ ചെയ്യുന്നു).
- **ക്വോട്ട പങ്കിടൽ** (`/dashboard/costs/quota-share`) — പങ്കിട്ട ക്വോട്ട പൂളുകളും ബേൺ-റേറ്റ് കാഴ്ചകളും.

## CLI

OmniRoute-ന്റെ CLI ചെലവ്, ഉപയോഗം, നിരക്ക് എന്നിവയ്ക്കുള്ള കമാൻഡുകൾ ലഭ്യമാക്കുന്നു ([`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)-ൽ രജിസ്റ്റർ ചെയ്തിരിക്കുന്നു).

### `omniroute cost`

`/api/usage/analytics`-ൽ നിന്ന് സമാഹരിച്ച ചെലവ് റിപ്പോർട്ട്.

```bash
omniroute cost                          # കഴിഞ്ഞ 30d, ദാതാവിന്റെ അടിസ്ഥാനത്തിൽ ഗ്രൂപ്പുചെയ്തത്
omniroute cost --period 7d              # കഴിഞ്ഞ 7 ദിവസം
omniroute cost --group-by model         # provider | model | combo | api-key | day എന്നിവയുടെ അടിസ്ഥാനത്തിൽ ഗ്രൂപ്പുചെയ്യുക
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

നിരകൾ: ഗ്രൂപ്പ്, അഭ്യർത്ഥനകൾ, ഇൻപുട്ട്/ഔട്ട്പുട്ട് ടോക്കണുകൾ, ചെലവ് (USD), മൊത്തത്തിലുള്ള ശതമാനം. അവസാനം മൊത്തം തുകയുടെ ഒരു വരി പ്രിന്റ് ചെയ്യുന്നു (`--quiet` അല്ലെങ്കിൽ `--output json` ഉപയോഗിച്ച് ഇത് ഒഴിവാക്കാം).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ഓരോ ദാതാവിന്റെയും ചെലവ് സംഗ്രഹം
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ബജറ്റുകൾ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`, `GET /api/pricing/defaults` വായിക്കുന്നു. പകരം ഓരോ മോഡലിന്റെയും നിരക്കുകൾ തിരുത്താൻ **Pricing** ഡാഷ്ബോർഡ് പേജോ `PATCH /api/pricing`-ഓ ഉപയോഗിക്കുക.

## പ്രശ്നപരിഹാരം

- **എല്ലാ ചെലവുകളും $0 / "Legacy / Free" എന്ന് കാണിക്കുന്നു.** ഉപയോഗത്തിലുള്ള മോഡലുകൾക്ക് നിരക്ക് എൻട്രിയില്ല. ബാഹ്യ സമന്വയം പ്രവർത്തനക്ഷമമാക്കി (`PRICING_SYNC_ENABLED=true`) `omniroute pricing sync` പ്രവർത്തിപ്പിക്കുക, അല്ലെങ്കിൽ Pricing പേജ് / `PATCH /api/pricing` വഴി നിരക്കുകൾ സ്വമേധയാ സജ്ജീകരിക്കുക.
- **ഒരു ചരിത്രപരമായ മോഡലിന്റെ നിരക്ക് തെറ്റാണ്.** നിരക്ക് പരിഹരിക്കുക (ഓവർറൈഡ് ചെയ്യുകയോ വീണ്ടും സമന്വയിപ്പിക്കുകയോ ചെയ്യുക) — ഓരോ അനലിറ്റിക്സ് റീഡിലും ടോക്കൺ എണ്ണങ്ങളിൽ നിന്ന് ചെലവ് വീണ്ടും കണക്കാക്കുന്നതിനാൽ, അനുമാനങ്ങൾ മുൻകാല പ്രാബല്യത്തോടെ പുതുക്കപ്പെടും.
- **ചെലവ് തത്സമയത്തേക്കാൾ വൈകിയാണ് കാണിക്കുന്നത്.** ഓരോ കീയുടെയും ചെലവ് ബാച്ചുകളായാണ് പ്രോസസ്സ് ചെയ്യുന്നത്; കൂടുതൽ പുതുമയുള്ള കണക്കുകൾ ആവശ്യമെങ്കിൽ `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` കുറയ്ക്കുക.
