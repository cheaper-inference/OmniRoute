ന്യൂട്രൽ `config/cli-tools-manifest.json` കരാർ കാനോനിക്കൽ IDs, അപരനാമങ്ങൾ, ബൈനറി കാൻഡിഡേറ്റുകൾ, സജ്ജീകരണ പാചകക്കുറിപ്പുകൾ, മോഡൽ ആർഗ്യുമെൻ്റുകൾ, കഴിവുകൾ എന്നിവ പ്രഖ്യാപിക്കുന്നു. `bin/cli/cli-manifest.mjs` ലെ പ്ലെയിൻ നോഡ് അഡാപ്റ്ററും `src/shared/constants/cliIntegrationManifest.ts` യിലെ TypeScript അഡാപ്റ്ററും ഒരേ ഫയൽ വായിക്കുന്നു. റൺടൈം, കാറ്റലോഗ്, കോൺഫിഗർ, പൂർത്തീകരണം, ജനറേറ്ററുകൾ, ബാക്കെൻഡ് രജിസ്ട്രേഷൻ എന്നിവ `tests/unit/cli/cli-manifest-drift.test.ts` ഒരുമിച്ച് പരിശോധിക്കുന്നു. കാറ്റലോഗ് ചെയ്തിരിക്കുന്നത് ഒരു ടൂൾ ലോഞ്ച് ചെയ്യാനോ കോൺഫിഗർ ചെയ്യാനോ കഴിയുമെന്ന് അർത്ഥമാക്കുന്നില്ല. പ്രത്യേകിച്ചും, 5dive കോൺഫിഗർ-മാത്രം.

## കുട്ടികളുടെ പരിസ്ഥിതിയും ജീവിതചക്രവും

`omniroute run`, `omniroute launch`, `omniroute launch-codex` എന്നിവയ്ക്ക് ഒരു OS/terminal അനുയോജ്യത അനുവദനീയമായ ലിസ്റ്റ് അവകാശമായി ലഭിക്കുകയും തിരഞ്ഞെടുത്ത ടാർഗെറ്റിൻ്റെ ക്രെഡൻഷ്യലുകൾ കുത്തിവയ്ക്കുകയും ചെയ്യുന്നു. ബന്ധമില്ലാത്ത ദാതാവിൻ്റെയും ഡാറ്റാബേസ് രഹസ്യങ്ങളും ഡിഫോൾട്ടായി പാരമ്പര്യമായി ലഭിക്കുന്നതല്ല. `--inherit-env` പൂർണ്ണമായ രക്ഷാകർതൃ-പരിസ്ഥിതി അനന്തരാവകാശം പുനഃസ്ഥാപിക്കുന്നു; തിരഞ്ഞെടുത്ത മൂന്നാം കക്ഷി പ്രോസസ്സിന് ആ മൂല്യങ്ങൾ ലഭിക്കുമ്പോൾ മാത്രം അത് ഉപയോഗിക്കുക. ഇതൊരു എൻവയോൺമെൻ്റ് ഫിൽട്ടറിംഗ് ആണ്, ഒരു OS സാൻഡ്ബോക്സ് അല്ല: പ്രോസസ്സ് ഇപ്പോഴും കോളറുടെ ഫയൽസിസ്റ്റം അനുമതികൾക്കൊപ്പം പ്രവർത്തിക്കുന്നു.

തടസ്സപ്പെടുത്തൽ, അവസാനിപ്പിക്കൽ സിഗ്നലുകൾ കുട്ടിക്ക് കൈമാറുന്നു. താൽക്കാലിക കോൺഫിഗറേഷൻ നീക്കം ചെയ്യുന്നതിനുമുമ്പ് ലോഞ്ചർ കുട്ടിയുടെ അടുത്ത പരിപാടിക്കായി കാത്തിരിക്കുന്നു. നിർബന്ധിത അവസാനിപ്പിക്കുന്നതിന് മുമ്പുള്ള ഗ്രേസ് പിരീഡ് `OMNIROUTE_CHILD_SIGNAL_TIMEOUT_MS` നിയന്ത്രിക്കുന്നു (സ്ഥിരസ്ഥിതി 5000 മില്ലിസെക്കൻഡ്).

`omniroute launch <tool>` ( [LAUNCH.md](./LAUNCH.md) കാണുക) അതേ പരിസ്ഥിതി നിയമങ്ങളും സിഗ്നൽ ഫോർവേഡിംഗും പിന്തുടരുന്നു, കൂടാതെ കൂട്ടിച്ചേർക്കുന്നു:

- **ഗേറ്റ്വേ സ്വയമേവ ആരംഭിക്കുക.** ഒരു പ്രാദേശിക ലക്ഷ്യത്തിനായി, പോർട്ടിൽ ഒരു ഗേറ്റ്വേയും ഉത്തരം നൽകാത്തപ്പോൾ, വേർപെടുത്തിയ റീപ്പർ പ്രോസസ്സിന് കീഴിൽ ലോഞ്ചർ `127.0.0.1` ലേക്ക് `omniroute serve --headless --no-open` ബന്ധിപ്പിച്ച് ആരംഭിക്കുന്നു. ഓരോ റണ്ണിംഗ് ലോഞ്ചും `DATA_DIR/launch/leases/` ൽ ഒരു പാട്ടത്തിനെടുക്കുന്നു (ഓരോ 15 സെക്കൻ്റിലും ഹൃദയമിടിപ്പ്, 45 സെക്കൻഡിനു ശേഷമോ അല്ലെങ്കിൽ അതിൻ്റെ പ്രക്രിയ അവസാനിക്കുമ്പോഴോ പഴയത്). നിഷ്ക്രിയ കൃപയ്ക്ക് (`OMNIROUTE_LAUNCH_IDLE_GRACE_MS`, ഡിഫോൾട്ട് 10000 മില്ലിസെക്കൻഡ്) പാട്ടമൊന്നും നൽകിയിട്ടില്ലെങ്കിൽ ഒരിക്കൽ ആരംഭിച്ച ഗേറ്റ്വേ റീപ്പർ നിർത്തുന്നു. ഉപയോക്താവ് ആരംഭിച്ച ഒരു ഗേറ്റ്വേ ഉപയോഗിക്കുന്നു, പക്ഷേ ഒരിക്കലും നിർത്തിയില്ല. `--keep-gateway` അല്ലെങ്കിൽ `omniroute gateway keep` ഒരു ലോഞ്ചർ ഗേറ്റ്വേയെ സാധാരണ ഒന്നാക്കി മാറ്റുന്നു; `--no-start` പഴയ പരാജയം-ഇഫ്-ഡൗൺ പെരുമാറ്റം പുനഃസ്ഥാപിക്കുന്നു. റിമോട്ട് ടാർഗെറ്റുകൾ മാത്രം അന്വേഷിക്കുന്നു.
- **സെഷനുകൾ സമാരംഭിക്കുക.** ഓരോ ലോഞ്ചും പാരൻ്റ് ക്രെഡൻഷ്യലിൽ നിന്ന് (`POST /api/launch/sessions`) ഒരു ഹ്രസ്വകാല `olx_` സെഷൻ ടോക്കൺ മിൻ്റ് ചെയ്യുന്നു, ടൂൾ പ്രവർത്തിക്കുമ്പോൾ അത് ഹൃദയമിടിപ്പ് നൽകുന്നു, ഉപയോഗ സംഗ്രഹം വായിക്കുകയും ടൂൾ പുറത്തുകടന്നതിന് ശേഷം അത് പിൻവലിക്കുകയും ചെയ്യുന്നു. ടോക്കൺ അതിൻ്റെ രക്ഷിതാവിൻ്റെ കർശനമായ ഉപവിഭാഗമാണ്: ഒരേ അനുമതികൾ, അതേ അല്ലെങ്കിൽ ഇടുങ്ങിയ കാറ്റലോഗ്, ഹ്രസ്വമായ ആയുസ്സ്, അതൊരു ഡാഷ്ബോർഡ് ക്രെഡൻഷ്യൽ അല്ല. ടൂളിന് സെഷൻ ടോക്കൺ ലഭിക്കുന്നു, ഒരിക്കലും പേരൻ്റ് ക്രെഡൻഷ്യൽ അല്ല, കൂടാതെ `--tag` നൽകിയിട്ടില്ലെങ്കിൽ അഭ്യർത്ഥനകൾ `launch:<tool>:<sessionId>` ടാഗ് ചെയ്യപ്പെടും. സെഷൻ API ഇല്ലാത്ത ഒരു ഗേറ്റ്വേ അൺസ്കോപ്പ് ലോഞ്ചിലേക്ക് മടങ്ങുന്നതിന് പകരം `GatewayTooOld` ഉപയോഗിച്ച് പരാജയപ്പെടുന്നു.
- **ഓരോ ലോഞ്ച് കോൺഫിഗറേഷനും.** ടൂൾ കോൺഫിഗറേഷൻ ഫയലുകൾ ഒരു സ്വകാര്യ ടെംപ് ഡയറക്ടറിയിലേക്ക് (മോഡ് 0700, പ്രിഫിക്സ് `omnirouter-`) എഴുതുകയും കുട്ടി പുറത്തുകടന്നതിനുശേഷം നീക്കം ചെയ്യുകയും ചെയ്യുന്നു. ലോഞ്ചറിൻ്റെ ഒരു `SIGKILL` ഡയറക്ടറിക്ക് പുറകിൽ പോകുന്നു; `omniroute launch --cleanup` അത്തരം ഡയറക്ടറികൾ ഒരു ദിവസത്തിലധികം പഴക്കമുള്ളപ്പോൾ നീക്കം ചെയ്യുന്നു.

## Gemini സ്ഥിരമായ സജ്ജീകരണം

```bash
omniroute setup-gemini --remote https://omni.example --model provider/model --yes
omniroute configure gemini --model provider/model --yes
omniroute run gemini --model provider/model --dry-run --json
```

ആദ്യത്തെ രണ്ട് കമാൻഡുകൾ തിരഞ്ഞെടുത്ത ലോക്കൽ അല്ലെങ്കിൽ റിമോട്ട് സെർവറിനായി ഈ മെഷീൻ കോൺഫിഗർ ചെയ്യുന്നു. സജ്ജീകരണം ബന്ധമില്ലാത്ത JSON ക്രമീകരണങ്ങൾ സംരക്ഷിക്കുന്നു, Gemini API-കീ ഓത്ത് തിരഞ്ഞെടുക്കുന്നു, കൂടാതെ ഒരു സ്വകാര്യ `.gemini/.env` ഫയലിലേക്ക് എൻഡ് പോയിൻ്റും ക്രെഡൻഷ്യലും എഴുതുന്നു. ഇത് തിരുത്തിയെഴുതുന്നതിനുപകരം അസാധുവായ JSON നിരസിക്കുന്നു. എംബഡഡ് ക്രെഡൻഷ്യലുകളോ അന്വേഷണ പാരാമീറ്ററുകളോ ശകലങ്ങളോ ഇല്ലാതെ എൻഡ്പോയിൻ്റ് URLs HTTP(S) ആയിരിക്കണം. ഡ്രൈ-റൺ പ്രിൻ്റ് പാത്തുകൾ, ക്രെഡൻഷ്യൽ മൂല്യങ്ങളല്ല.

`GEMINI_CLI_HOME` അല്ലെങ്കിൽ `--gemini-home` സ്ഥിരമായ ഹോം റൂട്ട് തിരഞ്ഞെടുക്കുന്നു. ഒരു യഥാർത്ഥ `run gemini` സ്വന്തം താൽക്കാലിക വീട് സൃഷ്ടിക്കുകയും പിന്നീട് നീക്കം ചെയ്യുകയും ചെയ്യുന്നു. Gemini ൻ്റെ വർക്ക്സ്പേസ്-ട്രസ്റ്റ് പരിശോധനകളെ രണ്ട് മോഡും മറികടക്കുന്നില്ല.

## Codex പ്രൊഫൈലുകൾ

`configure codex` ഒരു മോഡലും അതിൻ്റെ OmniRoute പ്രൊവൈഡർ എൻഡ്പോയിൻ്റും ഉള്ള ഒരു സ്വകാര്യ `<name>.config.toml` എഴുതുന്നു. ക്രെഡൻഷ്യലുകൾ `OMNIROUTE_API_KEY` വഴി പരാമർശിക്കപ്പെടുന്നു, ഒരിക്കലും ഉൾച്ചേർത്തിട്ടില്ല. ലോഞ്ച് കമാൻഡ് തിരഞ്ഞെടുത്ത മോഡലിനെ ടോപ്പ്-ലെവൽ `model` കീയിൽ സജ്ജമാക്കുന്നു, `model_providers` ഉള്ളിലല്ല.

പ്രത്യേക പ്രൊഫൈൽ ഫയലുകൾ നിലവിലെ ഡോക്യുമെൻ്റ് ചെയ്ത Codex കരാറാണ്; `codex --profile <name>` ഉപയോഗിച്ച് തിരഞ്ഞെടുക്കുമ്പോൾ അവ ഉപയോക്തൃ കോൺഫിഗറേഷൻ ഓവർലേ ചെയ്യുന്നു. [ഔദ്യോഗിക പ്രൊഫൈൽ റഫറൻസും](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles) [OmniRoute Codex ഗൈഡും](./CODEX-CLI-CONFIGURATION.md) കാണുക.

## ഹെർമെറ്റിക് കമാൻഡ് എക്സിക്യൂഷൻ

വ്യക്തമായ ഒരു `DATA_DIR` ഉപയോഗിച്ച്, `OMNIROUTE_CLI_SKIP_DEFAULT_DATA_ENV=1` സജ്ജീകരിക്കുന്നത് സ്റ്റാർട്ടപ്പിനെ ഡിഫോൾട്ട് യൂസർ ഡാറ്റ ഡയറക്ടറിയുടെ ക്രെഡൻഷ്യൽ എൻവയോൺമെൻ്റിലേക്ക് വീഴുന്നത് തടയുന്നു. ഒറ്റപ്പെട്ട പരിശോധനകൾക്ക് ഇത് ഉപയോഗപ്രദമാണ്. ഇത് മറ്റ് വ്യക്തമായി തിരഞ്ഞെടുത്ത പരിസ്ഥിതി ഫയലുകൾ പ്രവർത്തനരഹിതമാക്കുന്നില്ല.

## വർക്കിംഗ്-ഡയറക്ടറി `.env`

CLI ഈ ക്രമത്തിൽ `.env` ഫയലുകൾ വായിക്കുന്നു, ഒരു കീ സജ്ജീകരിക്കുന്ന ആദ്യ ഫയൽ വിജയിക്കുന്നു: വ്യക്തമായ `DATA_DIR`, ഡിഫോൾട്ട് ഡാറ്റ ഡയറക്ടറി, നിലവിലെ വർക്കിംഗ് ഡയറക്ടറി, തുടർന്ന് പാക്കേജ് ഡയറക്ടറി. ഷെൽ വേരിയബിളുകൾ എല്ലായ്പ്പോഴും വിജയിക്കുന്നു.

പ്രവർത്തിക്കുന്ന ഡയറക്ടറി മറ്റാരുടെയെങ്കിലും (ക്ലോൺ ചെയ്ത ശേഖരം, പാക്ക് ചെയ്യാത്ത ആർക്കൈവ്) ആയിരിക്കാം, കൂടാതെ `omniroute serve` സെർവറിലേക്കും സെർവർ പ്രവർത്തിക്കുന്ന എല്ലാ ഉപകരണത്തിലേക്കും CLI പരിതസ്ഥിതി കൈമാറുന്നു. അതിനാൽ ഒരു `.env` അവിടെ `bin/cli/utils/untrustedCwdEnv.mjs` ൽ ലിസ്റ്റ് ചെയ്തിരിക്കുന്ന ഈ കീകൾ മാത്രമേ സജ്ജീകരിക്കൂ:

| താക്കോൽ                         | അംഗീകരിച്ച മൂല്യങ്ങൾ                                                             |
| ------------------------------- | -------------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`               | ഏത് സാഹചര്യത്തിലും`true`, `1` അല്ലെങ്കിൽ `yes`, സെർവർ പരിഗണിക്കുന്ന മൂല്യങ്ങൾ    |
| `LANG`, `LC_ALL`, `LC_MESSAGES` | 64 അക്ഷരങ്ങൾ വരെ, അക്കങ്ങൾ, `_`, `.`, `@` അല്ലെങ്കിൽ `-`                         |
| `LANGUAGE`                      | അതേ, പ്ലസ് `:`                                                                   |
| `TZ`                            | 64 അക്ഷരങ്ങൾ വരെ, അക്കങ്ങൾ, `_`, `+`, `-` അല്ലെങ്കിൽ `/`, `/` ൽ ആരംഭിക്കുന്നില്ല |
| `NO_COLOR`, `FORCE_COLOR`       | 16 അക്ഷരങ്ങളും അക്കങ്ങളും വരെ                                                    |

`REQUIRE_API_KEY` സ്വീകരിക്കുന്ന എല്ലാ മൂല്യവും ചെക്ക് ഓണാക്കുന്നു, അതിനാൽ ഫയലിന് ചെക്ക് ഓഫ് ചെയ്യാൻ കഴിയില്ല. എന്നിരുന്നാലും, ഇത് ഫലം തീരുമാനിക്കുന്നില്ല: എൻവയോൺമെൻ്റിന് മുമ്പ് ഡാറ്റാബേസിൽ സംഭരിച്ചിരിക്കുന്ന ഒരു `REQUIRE_API_KEY` ഓവർറൈഡ് സെർവർ വായിക്കുന്നു, അതേസമയം API കീ ഇല്ലാതെ എല്ലാ ഇൻ്റർഫേസുകളിലും കേൾക്കുന്നതിനെക്കുറിച്ചുള്ള സ്റ്റാർട്ടപ്പ് മുന്നറിയിപ്പ് പരിസ്ഥിതിയെ മാത്രം വായിക്കുന്നു. `false` ൻ്റെ സംഭരിച്ച ഓവർറൈഡ് ഉപയോഗിച്ച്, ഒരു വർക്കിംഗ് ഡയറക്ടറി `REQUIRE_API_KEY=true` API തുറന്ന് ആ മുന്നറിയിപ്പ് മറയ്ക്കുന്നു. `TZ` റൂൾ POSIX നേക്കാൾ ഇടുങ്ങിയതാണ്: ഇത് `.`, `:`, `,`, `<>` എന്നിവ നിരസിക്കുന്നു, അതിനാൽ `:Area/City` രൂപവും `EST5EDT,M3.2.0,M11.1.0` പോലുള്ള നിയമങ്ങളും ഷെല്ലിലോ `<DATA_DIR>/.env` സജ്ജീകരിക്കേണ്ടതുണ്ട്.

പേരുകൾ വലിയക്ഷരത്തിൽ കൃത്യമായി പൊരുത്തപ്പെടണം. മറ്റേതെങ്കിലും വരി, അതിൻ്റെ ചെക്ക് പരാജയപ്പെടുന്ന ഒരു മൂല്യം, കൂടാതെ പ്ലെയിൻ ASCII അക്ഷരങ്ങൾ, അക്കങ്ങൾ, `_` അല്ലാത്ത ഒരു പേര് (ഉദാഹരണത്തിന് NUL ബൈറ്റ് അല്ലെങ്കിൽ ലുക്ക്-എലൈക്ക് ലെറ്റർ ഉള്ള ഒന്ന്) എന്നിവ ഒഴിവാക്കപ്പെടും. CLI ഒരു മുന്നറിയിപ്പ് പ്രിൻ്റ് ചെയ്യുന്നു, അത് സജ്ജീകരിക്കാൻ കഴിയാത്ത കീകൾക്ക് പേരിടുന്നു, കൂടാതെ അവഗണിച്ച അനുവദനീയമായ കീകൾക്ക് പേരിടുന്നു, ഓരോന്നിനും എന്ത് മാറ്റണം (`TZ (expected a zone name such as Europe/Berlin)`, `lang (write the name as LANG)`). മൂല്യങ്ങളും പ്രിൻ്റ് ചെയ്യുന്നില്ല. ഈ സന്ദേശങ്ങളിലെ ഫയൽ പാത്തുകളും `.env` പാത്ത് `omniroute doctor` റിപ്പോർട്ടുകളും അവയിൽ നിയന്ത്രണമോ ബിഡി പ്രതീകങ്ങളോ അടങ്ങിയിരിക്കുമ്പോൾ രക്ഷപ്പെടും. പ്രവർത്തിക്കുന്ന ഡയറക്ടറി ഡാറ്റ ഡയറക്ടറി അല്ലെങ്കിൽ പാക്കേജ് ഡയറക്ടറി ആയിരിക്കുമ്പോൾ നിയന്ത്രണം ബാധകമല്ല.

`PORT`, `API_PORT`, `DASHBOARD_PORT` എന്നിവ ലിസ്റ്റിൽ ഇല്ല. ഉയർന്ന മുൻഗണനയുള്ള ഉറവിടത്തിൽ നിന്നുള്ള അടിസ്ഥാന URL ഇല്ലാതെ, CLI `localhost:<PORT>` നോട് സംസാരിക്കുന്നു, അവിടെ കേൾക്കുന്നതെന്തും CLI ൻ്റെ API കീയും സന്ദർഭ ടോക്കണും CLI മെഷീൻ ടോക്കണും (`x-omniroute-cli-token`, [CLI_TOKEN.md](../security/CLI_TOKEN.md) കാണുക), മാനേജ്മെൻ്റിനായി ലോക്കൽ സെർവർ സ്വീകരിക്കുന്ന ലൂപ്പ്ബാക്ക് കോളുകൾ സ്വീകരിക്കുന്നു. പ്രവർത്തിക്കുന്ന ഡയറക്ടറിയിൽ നിന്നുള്ള ഒരു പോർട്ട് ആ ഫയലിനെ ശ്രോതാവിനെ തിരഞ്ഞെടുക്കാൻ അനുവദിക്കും, അതിനാൽ ഷെല്ലിൽ, `<DATA_DIR>/.env` അല്ലെങ്കിൽ `--port` ഓപ്ഷൻ (`serve`, `launch`, `run`) ഉള്ള കമാൻഡുകൾ ഉപയോഗിച്ച് പോർട്ടുകൾ സജ്ജമാക്കുക.

പാർസറിന് `export` വാക്യഘടനയില്ല. `export LD_PRELOAD=...` പോലെയുള്ള ഒരു വരി ഒരു വേരിയബിളിനെ `export LD_PRELOAD` എന്ന് വിളിക്കുന്നു; പ്രവർത്തന ഡയറക്ടറിയിൽ നിന്ന് അത് ഒഴിവാക്കി, മറ്റ് `.env` ഫയലുകളിൽ ഒന്നും വായിക്കാത്ത അക്ഷര നാമം സജ്ജീകരിക്കുന്നു.

CLI ഒരു സന്ദർഭത്തിൻ്റെ സംഭരിച്ച ടോക്കണിനെ (ആക്സസ് ടോക്കൺ അല്ലെങ്കിൽ ലെഗസി API കീ) ആ സന്ദർഭത്തിൻ്റെ സ്വന്തം ഉത്ഭവവുമായി മാത്രം ജോടിയാക്കുന്നു: സ്കീം, ഹോസ്റ്റ്, പോർട്ട്, `URL.origin` ആയി താരതമ്യം ചെയ്യുമ്പോൾ. CLI ൻ്റെ HTTP ക്ലയൻ്റ് (`--base-url`, `OMNIROUTE_BASE_URL`, `omniroute connect <new-url>`) വഴിയുള്ള അഭ്യർത്ഥനകൾക്കും മറ്റൊരു ടൂളിൻ്റെ കോൺഫിഗറിലേക്ക് ഒരു അടിസ്ഥാന URL ഉം കീയും എഴുതുന്ന `launch`, `launch codex`, `configure`, `setup-*` കമാൻഡുകൾക്കും ഇത് ബാധകമാണ്. `--remote` ഉള്ള മറ്റൊരു സെർവറിലേക്ക് ചൂണ്ടിക്കാണിക്കുന്നു, ഒരെണ്ണം സജ്ജീകരിച്ചിട്ടുണ്ടെങ്കിൽ അവർ വ്യക്തമായ `--api-key` അല്ലെങ്കിൽ `OMNIROUTE_API_KEY` ഉപയോഗിക്കുന്നു, കൂടാതെ സന്ദർഭ ടോക്കൺ ഇല്ല. താരതമ്യം കൃത്യമാണ്, അതിനാൽ `localhost`, `127.0.0.1`, അല്ലെങ്കിൽ ഒരു ട്രെയിലിംഗ് ഡോട്ടുള്ളതും ഇല്ലാത്തതുമായ ഒരു ഹോസ്റ്റ്, വ്യത്യസ്ത സെർവറുകളായി കണക്കാക്കുകയും സന്ദർഭ ടോക്കൺ ലഭിക്കാതിരിക്കുകയും ചെയ്യുന്നു. ഉപയോക്തൃ വിവരങ്ങളുള്ള ഒരു URL, ഒരു ബാക്ക്സ്ലാഷ് അല്ലെങ്കിൽ വൈറ്റ്സ്പെയ്സ് ഒരിക്കലും പൊരുത്തപ്പെടുന്നില്ല, കാരണം മറ്റ് URL പാഴ്സറുകൾക്ക് (പൈത്തണിൻ്റെ `urllib`, `httpx`, ഉദാഹരണത്തിന്) അതിൽ നിന്ന് മറ്റൊരു ഹോസ്റ്റ് വായിക്കാൻ കഴിയും. അഭ്യർത്ഥനകൾക്കായി CLI സ്വയം അയയ്ക്കുന്നു, ആ ചെക്ക് സ്കീമും അധികാരവും മാത്രമേ ഉൾക്കൊള്ളുന്നുള്ളൂ, അതിനാൽ പാതയിലോ അന്വേഷണത്തിലോ ഇടമുള്ള ഒരു ഐഡി ടോക്കണിനെ സൂക്ഷിക്കുന്നു.
