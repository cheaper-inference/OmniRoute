## 🎯 ഉപയോഗ സാഹചര്യങ്ങൾ

### സാഹചര്യം 1: "എനിക്ക് Claude Pro സബ്സ്ക്രിപ്ഷൻ ഉണ്ട്"

**പ്രശ്നം:** ഉപയോഗിക്കാത്ത ക്വാട്ട കാലഹരണപ്പെടുന്നു, തീവ്രമായ കോഡിംഗിനിടെ നിരക്ക് പരിധികൾ നേരിടുന്നു

```
കോംബോ: "maximize-claude"
  1. cc/claude-opus-4-7        (സബ്സ്ക്രിപ്ഷൻ പൂർണ്ണമായി ഉപയോഗിക്കുക)
  2. glm/glm-4.7               (ക്വാട്ട തീരുമ്പോൾ ചെലവുകുറഞ്ഞ ബാക്കപ്പ്)
  3. if/qwen3.8-max-preview       (അടിയന്തര സാഹചര്യത്തിനുള്ള സൗജന്യ ഫാൾബാക്ക്)

പ്രതിമാസ ചെലവ്: $20 (സബ്സ്ക്രിപ്ഷൻ) + ~$5 (ബാക്കപ്പ്) = ആകെ $25
$20 നൽകുകയും പരിധികളിൽ എത്തുകയും ചെയ്യുന്നതുമായി താരതമ്യപ്പെടുത്തുമ്പോൾ = നിരാശ
```

### സാഹചര്യം 2: "എനിക്ക് ചെലവൊന്നും വേണ്ട"

**പ്രശ്നം:** സബ്സ്ക്രിപ്ഷനുകൾ താങ്ങാനാകുന്നില്ല, വിശ്വസനീയമായ AI കോഡിംഗ് ആവശ്യമാണ്

```
കോംബോ: "zero-cost"
  1. if/kimi-k2.7-code          (സൗജന്യ ആക്സസ് പട്ടികപ്പെടുത്തിയിരിക്കുന്നു; നിരക്ക് പരിധികൾ ബാധകമായേക്കാം)
  2. kr/qwen3-coder-next        (Kiro സൗജന്യ ഫാൾബാക്ക്)

പ്രതിമാസ ചെലവ്: $0
ഗുണനിലവാരം: നിങ്ങളുടെ വർക്ക്ലോഡിനായി മോഡൽ, പരിധികൾ, സ്വകാര്യത, SLA എന്നിവ പരിശോധിക്കുക
```

CLI സ്വയമേവ `~/.omniroute/.env` അല്ലെങ്കിൽ `./.env` എന്നതിൽ നിന്ന് `.env` ലോഡ് ചെയ്യുന്നു.

### ട്രേ മോഡ്

സിസ്റ്റം ട്രേയിൽ OmniRoute ആരംഭിക്കുക:

```bash
omniroute serve --tray
```

സെർവറും ട്രേയും തയ്യാറായ ശേഷം കമാൻഡ് അവസാനിക്കുന്നു.

ടെർമിനൽ ഇല്ലാതെയും സെർവർ പ്രവർത്തനം തുടരുന്നു.

ട്രേ മോഡ് macOS, Windows, ഗ്രാഫിക്കൽ Linux സെഷനുകൾ എന്നിവ പിന്തുണയ്ക്കുന്നു. ട്രേ മോഡ് ഡാഷ്ബോർഡ് സ്വയമേവ തുറക്കില്ല.

ഈ പ്രവർത്തനങ്ങൾക്കായി ട്രേ മെനു ഉപയോഗിക്കുക:

- ഡാഷ്ബോർഡ് തുറക്കുക.
- `/dashboard/logs` തുറക്കുക.
- സ്വയമേവ ആരംഭിക്കൽ മാറ്റുക.
- OmniRoute നിർത്തുക.

ഈ ഓപ്ഷനുകൾക്കൊപ്പം `--tray` ഉപയോഗിക്കരുത്:

- `--daemon`
- `--log`
- `--no-recovery`

ഈ മോഡുകൾക്ക് വ്യത്യസ്ത പ്രോസസ് ഉടമസ്ഥത ആവശ്യമാണ്.

അടുത്ത മെഷീൻ ലോഗിനിൽ സ്റ്റാർട്ടപ്പ് പ്രവർത്തനക്ഷമമാക്കുക:

```bash
omniroute autostart enable
```

macOS, Windows, ഗ്രാഫിക്കൽ Linux സെഷനുകൾ എന്നിവയിൽ സ്വയമേവ ആരംഭിക്കൽ ട്രേ മോഡ് ഉപയോഗിക്കുന്നു. ഹെഡ്ലെസ് Linux നിലവിലുള്ള systemd യൂസർ സർവീസ് ഉപയോഗിക്കുന്നു.

ലോഗിൻ സമയത്തെ സ്റ്റാർട്ടപ്പ് പ്രവർത്തനരഹിതമാക്കുക:

```bash
omniroute autostart disable
```

### അൺഇൻസ്റ്റാൾ ചെയ്യൽ

OmniRoute ഇനി ആവശ്യമില്ലാത്തപ്പോൾ, പൂർണ്ണമായി നീക്കം ചെയ്യുന്നതിനായി ഞങ്ങൾ രണ്ട് ദ്രുത സ്ക്രിപ്റ്റുകൾ നൽകുന്നു:

| കമാൻഡ്                   | പ്രവർത്തനം                                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | സിസ്റ്റം ആപ്പ് നീക്കംചെയ്യുന്നു, എന്നാൽ `~/.omniroute`-ലെ **നിങ്ങളുടെ DB-യും കോൺഫിഗറേഷനുകളും നിലനിർത്തുന്നു**. |
| `npm run uninstall:full` | ആപ്പ് നീക്കംചെയ്യുന്നതിനൊപ്പം **എല്ലാ കോൺഫിഗറേഷനുകളും കീകളും ഡാറ്റാബേസുകളും ശാശ്വതമായി മായ്ക്കുന്നു**.         |

> കുറിപ്പ്: ഈ കമാൻഡുകൾ പ്രവർത്തിപ്പിക്കാൻ, OmniRoute പ്രോജക്റ്റ് ഫോൾഡറിലേക്ക് പോകുക (നിങ്ങൾ അത് ക്ലോൺ ചെയ്തിട്ടുണ്ടെങ്കിൽ) തുടർന്ന് അവ പ്രവർത്തിപ്പിക്കുക. പകരമായി, ആഗോളമായി ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടെങ്കിൽ, `npm uninstall -g omniroute` പ്രവർത്തിപ്പിച്ചാൽ മതി.

### Void Linux (xbps-src)

Void Linux ഉപയോക്താക്കൾക്ക് `xbps-src` ക്രോസ്-കംപൈലേഷൻ ഫ്രെയിംവർക്ക് ഉപയോഗിച്ച് OmniRoute നേറ്റീവായി പാക്കേജ് ചെയ്ത് ഇൻസ്റ്റാൾ ചെയ്യാം. ആവശ്യമായ `better-sqlite3` നേറ്റീവ് ബൈൻഡിങ്ങുകൾക്കൊപ്പം Node.js സ്റ്റാൻഡ്എലോൺ ബിൽഡും ഇത് സ്വയമേവ നിർവഹിക്കുന്നു.

```bash
		aarch64*) _gyp_arch=arm64 ;;
```

## 🧩 നൂതന സവിശേഷതകൾ

### ഇഷ്ടാനുസൃത മോഡലുകൾ

ആപ്പ് അപ്ഡേറ്റിനായി കാത്തിരിക്കാതെ ഏത് പ്രൊവൈഡർക്കും ഏത് മോഡൽ ID-യും ചേർക്കുക:

```bash
# API വഴി
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# ലിസ്റ്റ്: curl http://localhost:20128/api/provider-models?provider=openai
# നീക്കം ചെയ്യൽ: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

അല്ലെങ്കിൽ ഡാഷ്ബോർഡ് ഉപയോഗിക്കുക: **Providers → [Provider] → Custom Models**.

കുറിപ്പുകൾ:

- OpenRouter, OpenAI/Anthropic-അനുയോജ്യ പ്രൊവൈഡറുകൾ എന്നിവ **Available Models**-ൽ നിന്ന് മാത്രം നിയന്ത്രിക്കപ്പെടുന്നു. മാനുവൽ ആഡ്, ഇംപോർട്ട്, ഓട്ടോ-സിംക്ക് എന്നിവയെല്ലാം ഒരേ ലഭ്യ-മോഡൽ ലിസ്റ്റിലാണ് എത്തുന്നത്, അതിനാൽ ആ പ്രൊവൈഡറുകൾക്ക് പ്രത്യേക Custom Models വിഭാഗമില്ല.
- **Custom Models** വിഭാഗം നിയന്ത്രിത ലഭ്യ-മോഡൽ ഇംപോർട്ടുകൾ വാഗ്ദാനം ചെയ്യാത്ത പ്രൊവൈഡറുകൾക്കാണ് ഉദ്ദേശിച്ചത്.

### ഇഷ്ടാനുസൃത OpenAI-അനുയോജ്യ പ്രൊവൈഡറുകൾ

OpenAI API സംസാരിക്കുന്ന ഏത് ഗേറ്റ്വേയെയും (സ്വയം-ഹോസ്റ്റുചെയ്ത പ്രോക്സി, vLLM, മൂന്നാം-കക്ഷി അഗ്രഗേറ്റർ)
സ്വന്തം പ്രൊവൈഡർ നോഡായി ചേർക്കാം:

1. **Providers → Add OpenAI Compatible**.
2. **Name**: നോഡിനായുള്ള ഡിസ്പ്ലേ ലേബൽ.
3. **Prefix**: റൂട്ടിംഗ് പേര്. ക്ലയന്റുകൾ മോഡലുകളെ `<prefix>/<model>` എന്ന രീതിയിൽ വിളിക്കുന്നു, അതിനാൽ
   `mygw` പ്രിഫിക്സുള്ള ഒരു നോഡ് `mygw/gpt-4o-mini` സേവിക്കുന്നു. ആവശ്യമാണ്; അക്ഷര നിയന്ത്രണമൊന്നുമില്ല.
4. **API Type**: ഗേറ്റ്വേ സേവിക്കുന്ന എൻഡ്പോയിന്റ് കുടുംബം (Chat Completions, Responses,
   Embeddings, ഓഡിയോ, ഇമേജുകൾ).
5. **Base URL**: `/v1` ഉൾപ്പെടെ അതുവരെയുള്ള API റൂട്ട് (ഉദാഹരണത്തിന്
   `https://gateway.example.com/v1`), മുഴുവൻ `/chat/completions` പാത അല്ല. സ്റ്റാൻഡേർഡല്ലാത്ത
   പാതകളുള്ള ഗേറ്റ്വേകൾ അവ **Advanced Settings**-ൽ സജ്ജീകരിക്കുന്നു (ചാറ്റ് പാത, മോഡൽസ് പാത).
6. **API Key (for Check)** ഫീൽഡ് കണക്ഷൻ പരീക്ഷിക്കാൻ മാത്രമാണ്. നോഡ് സൃഷ്ടിച്ച ശേഷം,
   അത് തുറന്ന് അഭ്യർത്ഥനകൾ ഉപയോഗിക്കുന്ന കീ സൂക്ഷിക്കാൻ **Add Connection** ഉപയോഗിക്കുക.

നോഡിന് `openai-compatible-<apiType>-<uuid>` രൂപത്തിലുള്ള ഒരു ആന്തരിക ഐഡി ലഭിക്കും; നിങ്ങൾ അത്
ഒരിക്കലും ടൈപ്പ് ചെയ്യേണ്ടതില്ല, പ്രിഫിക്സാണ് പൊതുവായ പേര്.

#### സംവരണം ചെയ്ത പ്രിഫിക്സുകൾ

ഒരു പ്രിഫിക്സ് ബിൽറ്റ്-ഇൻ പ്രൊവൈഡറുടെ ഐഡിയോ അലയസോ (ഉദാഹരണത്തിന് `openai`, `cf`) ആകാൻ പാടില്ല,
ഒഴിവാക്കിയ പ്രൊവൈഡറുടെ ഐഡിയും ആകാൻ പാടില്ല. മോഡൽ റിസോൾവർ ഇഷ്ടാനുസൃത നോഡുകൾക്ക് മുൻപ് ബിൽറ്റ്-ഇൻ
ഐഡികളും അലയസുകളും പരിശോധിക്കുന്നു, അതിനാൽ ആ പ്രിഫിക്സുകളിൽ ഒന്ന് ഉപയോഗിക്കുന്ന നോഡിന് ഒരിക്കലും
ട്രാഫിക് ലഭിക്കില്ല: `<prefix>/model` പകരം ബിൽറ്റ്-ഇൻ പ്രൊവൈഡറിലേക്ക് പോകും, അല്ലെങ്കിൽ ആ പ്രൊവൈഡർ
ഒഴിവാക്കിയിട്ടുണ്ടെങ്കിൽ fail closed ആകും. അത്തരം പ്രിഫിക്സുള്ള നോഡ് സൃഷ്ടിക്കലോ എഡിറ്റ് ചെയ്യലോ
ഇതിനാൽ നിരസിക്കപ്പെടും:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

വ്യത്യസ്തമായ ഒരു പ്രിഫിക്സ് തിരഞ്ഞെടുക്കുക (`mygw`, `acme-proxy`). ബിൽറ്റ്-ഇൻ പ്രൊവൈഡറെയോ അതിന്റെ
ക്രെഡൻഷ്യലുകളെയോ പരാമർശിക്കുന്ന ഒരു എററോടെ ഇഷ്ടാനുസൃത നോഡിലേക്കുള്ള അഭ്യർത്ഥനകൾ പരാജയപ്പെട്ടാൽ,
നോഡിന്റെ പ്രിഫിക്സ് സംവരണം ചെയ്തതാണോ എന്ന് പരിശോധിക്കുക: ഈ നിയമം നിലവിൽ വരുന്നതിന് മുൻപ് സേവ് ചെയ്ത
നോഡുകൾ ഇപ്പോഴും സൂക്ഷിച്ചിട്ടുണ്ട്, എന്നാൽ അവയുടെ പ്രിഫിക്സ് ബിൽറ്റ്-ഇൻ പ്രൊവൈഡറിലേക്ക് റൂട്ട് ചെയ്യും.
നോഡ് എഡിറ്റ് ചെയ്ത് പുതിയ പ്രിഫിക്സ് നൽകുക.

#### ഓരോ കണക്ഷനിലുമുള്ള ഗേറ്റ്വേ ഓപ്ഷനുകൾ

ഈ കീകൾ ഒരു കണക്ഷന്റെ `providerSpecificData`-യിലാണ് നൽകുന്നത് (ഉദാഹരണത്തിന്
`PUT /api/providers/{id}` വഴി):

- `toolNameMaxLength` (പൂർണ്ണസംഖ്യ, 1–1024) — നീളമുള്ള ടൂൾ പേരുകൾ ഗേറ്റ്വേ നിരസിക്കുന്ന OpenAI
  ചാറ്റ്-ഫോർമാറ്റ് അനുയോജ്യ കണക്ഷനുകൾക്കായി. നീണ്ട പേരുകൾ ചെറിയ അലയസുകളായി അയയ്ക്കുകയും
  പ്രതികരണത്തിൽ പുനഃസ്ഥാപിക്കുകയും ചെയ്യും.
- `quotaEndpoint` — ഡാഷ്ബോർഡ് ക്വോട്ട സ്ട്രിപ്പിനും ക്വോട്ട-അവെയർ റൂട്ടിംഗിനും വേണ്ടി വായിക്കുന്ന
  ഗേറ്റ്വേയുടെ ക്വോട്ട/ക്രെഡിറ്റ് എൻഡ്പോയിന്റ്. OpenAI-, Anthropic-അനുയോജ്യ കണക്ഷനുകൾ രണ്ടിലും
  പ്രവർത്തിക്കും; മുഴുവൻ ഘടനയും `open-sse/services/usage/openaiCompatible.ts`-ൽ ഡോക്യുമെന്റ് ചെയ്തിട്ടുണ്ട്.

```json
{
  "toolNameMaxLength": 64,
  "quotaEndpoint": {
    "url": "https://gateway.example.com/key/info",
    "auth": "bearer",
    "quotas": {
      "budget": { "used": "$.info.spend", "total": "$.info.max_budget", "currency": "USD" }
    }
  }
}
```

### OmniRoute പീയറുകൾ ചെയിനിംഗ് ചെയ്യൽ

മറ്റൊരു OmniRoute ഗേറ്റ്വേയെ **Custom OpenAI-compatible** പ്രൊവൈഡറായി ചേർക്കാം. പീയറിന്റെ
`/v1` ബേസ് URL-ഉം ആ പീയർ നൽകിയ ഡെഡിക്കേറ്റഡ്, ഏറ്റവും കുറഞ്ഞ അധികാരങ്ങളുള്ള API കീയും ഉപയോഗിക്കുക.

പരസ്പര അല്ലെങ്കിൽ മൾട്ടി-ഹോപ്പ് ചെയിനുകൾക്ക്, ഓരോ ഗേറ്റ്വേയിലും ഓപ്റ്റ്-ഇൻ ലൂപ്പ് ഗാർഡ് പ്രാപ്തമാക്കുക:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

വ്യക്തമായി അനുവദിച്ച പീയർ URL-ലേക്ക് അയച്ച അഭ്യർത്ഥനകൾക്ക് മാത്രമേ
`X-OmniRoute-Peer-Trace` ഹെഡർ ലഭിക്കൂ. ആവർത്തിച്ച ഇൻസ്റ്റൻസ് ID-യെയോ തീർന്ന ഹോപ്പ്
ബജറ്റിനെയോ ഗേറ്റ്വേ HTTP `508 Loop Detected` ഉപയോഗിച്ച് നിരസിക്കും; സാധാരണ അപ്സ്ട്രീം
പ്രൊവൈഡറുകൾക്ക് പീയർ മെറ്റാഡാറ്റ ലഭിക്കില്ല.

പീയർ ചെയിനിംഗ് ഡാറ്റാബേസ് റെപ്ലിക്കേഷനോ ഹോസ്റ്റ് ഫെയിൽഓവറോ അല്ല. ഓരോ ഗേറ്റ്വേയും സ്വതന്ത്ര
SQLite സ്റ്റേറ്റ്, കാഷികൾ, റേറ്റ് കൗണ്ടറുകൾ, സെഷനുകൾ എന്നിവ സൂക്ഷിക്കുന്നു. ആക്ടീവ്/പാസീവ് അല്ലെങ്കിൽ
ആക്ടീവ്/ആക്ടീവ് ലഭ്യതയ്ക്ക് ഹെൽത്ത്-ചെക്ക്ഡ് റിവേഴ്സ് പ്രോക്സിയോ ക്ലയന്റ് ഫെയിൽഓവറോ ഉപയോഗിക്കുക,
ഒരിക്കലും ഒരു SQLite ഡാറ്റാബേസ് ഒന്നിലധികം പ്രവർത്തിക്കുന്ന OmniRoute ഇൻസ്റ്റൻസുകളിലേക്ക്
മൗണ്ട് ചെയ്യരുത്.

### ഡെഡിക്കേറ്റഡ് പ്രൊവൈഡർ റൂട്ടുകൾ

മോഡൽ വാലിഡേഷനോടെ അഭ്യർത്ഥനകൾ നിർദ്ദിഷ്ട പ്രൊവൈഡറിലേക്ക് നേരിട്ട് റൂട്ട് ചെയ്യുക:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

പ്രൊവൈഡർ പ്രിഫിക്സ് ഇല്ലെങ്കിൽ ഓട്ടോമാറ്റികായി ചേർക്കും. പൊരുത്തമില്ലാത്ത മോഡലുകൾ `400` തിരിച്ചുനൽകും.

### നെറ്റ്വർക്ക് പ്രോക്സി കോൺഫിഗറേഷൻ

```bash
# ആഗോള പ്രോക്സി സജ്ജീകരിക്കുക
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# പ്രൊവൈഡർ-തല പ്രോക്സി
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# പ്രോക്സി പരീക്ഷിക്കുക
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**മുൻഗണന:** കീ-നിർദ്ദിഷ്ടം → കോംബോ-നിർദ്ദിഷ്ടം → ദാതാവ്-നിർദ്ദിഷ്ടം → ആഗോളം → എൻവയൺമെന്റ്.

### മോഡൽ കാറ്റലോഗ് API

```bash
curl http://localhost:20128/api/models/catalog
```

ദാതാവ് അനുസരിച്ച് തരംതിരിച്ച മോഡലുകൾ തരങ്ങളോടെ (`chat`, `embedding`, `image`) തിരികെ നൽകുന്നു.

### ക്ലൗഡ് സിങ്ക്

- ഉപകരണങ്ങളിലുടനീളം ദാതാക്കളെയും കോംബോകളെയും ക്രമീകരണങ്ങളെയും സിങ്ക് ചെയ്യുക
- ടൈംഔട്ട് + ഫെയിൽ-ഫാസ്റ്റ് ഓപ്ഷനുകളോടെ യാന്ത്രിക പശ്ചാത്തല സിങ്ക്
- പ്രൊഡക്ഷനിൽ സെർവർ-സൈഡ് `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` ന് മുൻഗണന നൽകുക

### Cloudflare ക്വിക് ടണൽ

- Docker-ലും മറ്റ് സെൽഫ്-ഹോസ്റ്റഡ് വിന്യാസങ്ങളിലും **ഡാഷ്ബോർഡ് → എൻഡ്പോയിന്റുകൾ** എന്നതിൽ ലഭ്യമാണ്
- നിങ്ങളുടെ നിലവിലെ OpenAI-അനുയോജ്യമായ `/v1` എൻഡ്പോയിന്റിലേക്ക് ഫോർവേഡ് ചെയ്യുന്ന താൽക്കാലിക `https://*.trycloudflare.com` URL സൃഷ്ടിക്കുന്നു
- ആദ്യത്തെ പ്രാപ്തമാക്കൽ ആവശ്യമായപ്പോൾ മാത്രം `cloudflared` ഇൻസ്റ്റാൾ ചെയ്യുന്നു; പിന്നീടുള്ള റീസ്റ്റാർട്ടുകൾ അതേ മാനേജ് ചെയ്യുന്ന ബൈനറി പുനരുപയോഗിക്കുന്നു
- OmniRoute അല്ലെങ്കിൽ കണ്ടെയ്നർ റീസ്റ്റാർട്ടിന് ശേഷം ക്വിക് ടണലുകൾ യാന്ത്രികമായി പുനഃസ്ഥാപിക്കപ്പെടുന്നില്ല; ആവശ്യമുള്ളപ്പോൾ ഡാഷ്ബോർഡിൽ നിന്ന് അവ വീണ്ടും പ്രാപ്തമാക്കുക
- ടണൽ URL-കൾ താൽക്കാലികമാണ്, ടണൽ നിർത്തുകയോ തുടങ്ങുകയോ ചെയ്യുമ്പോഴെല്ലാം മാറുന്നു
- പരിമിതമായ കണ്ടെയ്നറുകളിൽ ശല്യകരമായ QUIC UDP ബഫർ മുന്നറിയിപ്പുകൾ ഒഴിവാക്കാൻ, മാനേജ് ചെയ്യുന്ന ക്വിക് ടണലുകൾ സ്ഥിരസ്ഥിതിയായി HTTP/2 ട്രാൻസ്പോർട്ട് ഉപയോഗിക്കുന്നു
- മാനേജ് ചെയ്യുന്ന ട്രാൻസ്പോർട്ട് തിരഞ്ഞെടുപ്പ് മറികടക്കാൻ `CLOUDFLARED_PROTOCOL=quic` അല്ലെങ്കിൽ `auto` സജ്ജമാക്കുക
- മാനേജ് ചെയ്യുന്ന ഡൗൺലോഡിന് പകരം മുൻകൂട്ടി ഇൻസ്റ്റാൾ ചെയ്ത `cloudflared` ബൈനറി ഉപയോഗിക്കാൻ ഇഷ്ടമാണെങ്കിൽ `CLOUDFLARED_BIN` സജ്ജമാക്കുക
- Cloudflare ക്വിക് ടണൽ, Tailscale Funnel, ngrok ടണൽ പാനലുകൾ **ക്രമീകരണങ്ങൾ → രൂപം** എന്നതിൽ കാണിക്കാനോ മറയ്ക്കാനോ കഴിയും. ഒരു പാനൽ മറയ്ക്കുന്നത് പ്രവർത്തിക്കുന്ന ടണൽ നിർത്തുന്നില്ല.

### LLM ഗേറ്റ്വേ ഇന്റലിജൻസ് (ഘട്ടം 9)

- **സെമാന്റിക് ക്യാഷ്** — സ്ട്രീമിംഗ് അല്ലാത്ത, temperature=0 പ്രതികരണങ്ങൾ യാന്ത്രികമായി ക്യാഷ് ചെയ്യുന്നു (`X-OmniRoute-No-Cache: true` ഉപയോഗിച്ച് ഒഴിവാക്കാം)
- **അഭ്യർത്ഥന ഐഡംപോട്ടൻസി** — `Idempotency-Key` അല്ലെങ്കിൽ `X-Request-Id` ഹെഡർ വഴി 5 സെക്കൻഡിനുള്ളിലെ അഭ്യർത്ഥനകളുടെ തനിപ്പകർപ്പുകൾ നീക്കംചെയ്യുന്നു
- **പുരോഗതി ട്രാക്കിംഗ്** — `X-OmniRoute-Progress: true` ഹെഡർ വഴി ഓപ്റ്റ്-ഇൻ SSE `event: progress` ഇവന്റുകൾ

### റൂട്ടിംഗ് തന്ത്രങ്ങൾ

**ഡാഷ്ബോർഡ് → ക്രമീകരണങ്ങൾ → റൂട്ടിംഗ്** വഴി ക്രമീകരിക്കുക. ഡാഷ്ബോർഡ് ഏറ്റവും കൂടുതൽ ഉപയോഗിക്കുന്ന ആറ് തന്ത്രങ്ങൾ തുറന്നുകാട്ടുന്നു; കോംബോകളും ഓട്ടോ-റൂട്ടറും ആന്തരികമായി കൂടുതൽ വിപുലമായ ഒരു കൂട്ടത്തെ പിന്തുണയ്ക്കുന്നു.

**ഡാഷ്ബോർഡിൽ ദൃശ്യമായ തന്ത്രങ്ങൾ (അക്കൗണ്ട്-തല റൂട്ടിംഗ്):**

| തന്ത്രം                        | വിവരണം                                                                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| **ഫിൽ ഫസ്റ്റ്**                | മുൻഗണനാ ക്രമത്തിൽ അക്കൗണ്ടുകൾ ഉപയോഗിക്കുന്നു — ലഭ്യമാകാത്തതുവരെ പ്രാഥമിക അക്കൗണ്ട് എല്ലാ അഭ്യർത്ഥനകളും കൈകാര്യം ചെയ്യുന്നു           |
| **റൗണ്ട് റോബിൻ**               | ക്രമീകരിക്കാവുന്ന സ്റ്റിക്കി പരിധിയോടെ (സ്ഥിരസ്ഥിതി: അക്കൗണ്ടിന് 3 കോളുകൾ) എല്ലാ അക്കൗണ്ടുകളിലും ചുറ്റിക്കറങ്ങുന്നു                  |
| **P2C (Power of Two Choices)** | ക്രമരഹിതമായി 2 അക്കൗണ്ടുകൾ തിരഞ്ഞെടുത്ത് കൂടുതൽ ആരോഗ്യകരമായതിലേക്ക് റൂട്ട് ചെയ്യുന്നു — ആരോഗ്യം മനസ്സിലാക്കി ലോഡ് സന്തുലിതമാക്കുന്നു |
| **റാൻഡം**                      | Fisher-Yates ഷഫിൾ ഉപയോഗിച്ച് ഓരോ അഭ്യർത്ഥനയ്ക്കും ക്രമരഹിതമായി ഒരു അക്കൗണ്ട് തിരഞ്ഞെടുക്കുന്നു                                       |
| **ലീസ്റ്റ് യൂസ്ഡ്**            | ഏറ്റവും പഴയ `lastUsedAt` ടൈംസ്റ്റാമ്പ് ഉള്ള അക്കൗണ്ടിലേക്ക് റൂട്ട് ചെയ്യുന്നു, ട്രാഫിക് തുല്യമായി വിതരണം ചെയ്യുന്നു                  |
| **കോസ്റ്റ് ഓപ്റ്റിമൈസ്ഡ്**     | ഏറ്റവും കുറഞ്ഞ മുൻഗണനാ മൂല്യമുള്ള അക്കൗണ്ടിലേക്ക് റൂട്ട് ചെയ്യുന്നു, ഏറ്റവും കുറഞ്ഞ ചെലവുള്ള ദാതാക്കൾക്കായി ഒപ്റ്റിമൈസ് ചെയ്യുന്നു   |

**വിപുലമായ കോംബോ, ഓട്ടോ തന്ത്രങ്ങൾ** (ഓരോ കോംബോയ്ക്കും അല്ലെങ്കിൽ `auto/*` പ്രിഫിക്സുകൾ വഴി ക്രമീകരിക്കാം — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) കാണുക):

- `priority` — കർശനമായ ക്രമം, ഒരിക്കലും റൗണ്ട്-റോബിൻ ചെയ്യുന്നില്ല
- `weighted` — ഓരോ മോഡലിന്റേതും ഭാരം അനുസരിച്ച് ആനുപാതിക ട്രാഫിക് വിഭജനം
- `fill-first` — പരിധികൾ എത്തുന്നതുവരെ ആദ്യ മോഡൽ ഉപയോഗിച്ചുതീർക്കുന്നു
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` ഒപ്പം `cost-optimized`
- `auto` — എല്ലാ സാധ്യതകളിലും സ്കോർ-അധിഷ്ഠിതമായി
- `lkgp` (Last Known Good Provider) — അവസാനത്തെ വിജയകരമായ ദാതാവിൽ ഉറപ്പിച്ചുനിർത്തുന്നു, തുടർന്ന് നിയമങ്ങളിലേക്ക് മാറുന്നു
- `context-optimized` — ഏറ്റവും വലിയ സൗജന്യ കോൺടെക്സ്റ്റ് വിൻഡോ ഉള്ള മോഡൽ തിരഞ്ഞെടുക്കുന്നു
- `context-relay` — തുടർന്നുള്ള ടേണുകൾക്കായി ദൈർഘ്യമേറിയ കോൺടെക്സ്റ്റ് മോഡലുകളെ ചങ്ങലയായി യോജിപ്പിക്കുന്നു

#### ബാഹ്യ സ്റ്റിക്കി സെഷൻ ഹെഡർ

ബാഹ്യ സെഷൻ അഫിനിറ്റിക്കായി (ഉദാഹരണത്തിന്, റിവേഴ്സ് പ്രോക്സികൾക്ക് പിന്നിലുള്ള Claude Code/Codex ഏജന്റുകൾ), ഇത് അയയ്ക്കുക:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id` ഉം സ്വീകരിക്കുന്നു, ഫലപ്രദമായ സെഷൻ കീ `X-OmniRoute-Session-Id`-ൽ തിരികെ നൽകുന്നു.

Nginx ഉപയോഗിക്കുകയും അൻഡർസ്കോർ-രൂപത്തിലുള്ള ഹെഡറുകൾ അയയ്ക്കുകയും ചെയ്യുന്നുവെങ്കിൽ, ഇത് പ്രാപ്തമാക്കുക:

```nginx
underscores_in_headers on;
```

#### വൈൽഡ്കാർഡ് മോഡൽ അപരനാമങ്ങൾ

മോഡൽ പേരുകൾ റീമാപ്പ് ചെയ്യാൻ വൈൽഡ്കാർഡ് പാറ്റേണുകൾ സൃഷ്ടിക്കുക:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

വൈൽഡ്കാർഡുകൾ `*` (ഏത് പ്രതീകങ്ങളും) `?` (ഒറ്റ പ്രതീകം) എന്നിവയെ പിന്തുണയ്ക്കുന്നു.

#### ഫോൾബാക്ക് ചെയിനുകൾ

എല്ലാ അഭ്യർത്ഥനകൾക്കും ബാധകമായ ആഗോള ഫോൾബാക്ക് ചെയിനുകൾ നിർവചിക്കുക:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### സാധാരണ ദാതാവ് സംയോജനങ്ങളും റൂട്ടിംഗ് പാറ്റേണുകളും

OmniRoute-ൽ ഒന്നിലധികം ദാതാക്കളെ സംയോജിപ്പിക്കുന്നതിനും അവയ്ക്കിടയിൽ റൂട്ട് ചെയ്യുന്നതിനുമുള്ള ഉദാഹരണ പാറ്റേണുകൾ ഇതാ:

#### 1. കോഡിംഗ് ഏജന്റ് കോംബോ: ചെലവ്/വേഗത ഫോൾബാക്കോടുകൂടിയ ഹൈ-എൻഡ് റീസണിംഗ്

```bash
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

#### 2. ഫ്രീ-ടയർ ഓട്ടോ ഫെയിലോവർ കോംബോ

API ചെലവുകളില്ലാതെ അപ്ടൈം പരമാവധിയാക്കുന്നതിന് ഒന്നിലധികം ഫ്രീ-ടയർ, കീ ആവശ്യമില്ലാത്ത പ്രൊവൈഡറുകളെ ചെയിൻ ചെയ്യുന്നു.

- **സ്ട്രാറ്റജി**: `Least Used` അല്ലെങ്കിൽ `Round Robin` (ക്വോട്ടകളിലുടനീളം ലോഡ് വിതരണം ചെയ്യുന്നു)
- **മോഡലുകൾ**:
  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

```bash
# CLI വഴിയുള്ള ഉദാഹരണം
omniroute combo create free-stack \
  --models "groq/llama-3.3-70b-versatile,gemini/gemini-2.5-flash,cerebras/gpt-oss-120b" \
  --strategy round-robin
```

#### 3. മൾട്ടിമോഡൽ / വിഷൻ & ടെക്സ്റ്റ് പൈപ്പ്ലൈൻ

ഇമേജ് മനസ്സിലാക്കലും കോഡ് ജനറേഷനും ഉൾപ്പെടുന്ന വർക്ക്ഫ്ലോകൾക്കായി പ്രത്യേക വിഷൻ മോഡലുകളെ ഹൈ-സ്പീഡ് ടെക്സ്റ്റ് ജനറേഷനുമായി ജോടിയാക്കുന്നു.

- **പാറ്റേൺ**: വിഷൻ-ശേഷിയുള്ള മോഡലുകളെ ആദ്യം ഉൾപ്പെടുത്തുകയും അവസാനം ഉയർന്ന ത്രൂപുട്ട് ടെക്സ്റ്റ്/കോഡ് മോഡലിനെ ഉൾപ്പെടുത്തുകയും ചെയ്യുന്ന `Priority` കോംബോ.
- **മോഡലുകൾ**:
  1. `gemini/gemini-2.5-pro` (ശക്തമായ ഇമേജ്/മൾട്ടിമോഡൽ മനസ്സിലാക്കൽ)
  2. `openai/gpt-4o` (സന്തുലിതമായ വിഷനും ടൂൾ ഉപയോഗവും)
  3. `deepseek/deepseek-v4-flash` (ടെക്സ്റ്റ്/കോഡ് ജനറേഷൻ)

### റെസിലിയൻസും സർക്യൂട്ട് ബ്രേക്കറുകളും

**Dashboard → Settings → Resilience** വഴി ക്രമീകരിക്കുക.

OmniRoute അഞ്ച് ഘടകങ്ങളോടുകൂടി പ്രൊവൈഡർ-തല റെസിലിയൻസ് നടപ്പിലാക്കുന്നു:

1. **Request Queue & Pacing** — സിസ്റ്റം-തല റിക്വസ്റ്റ് ഷേപ്പിംഗ്:
   - **Requests Per Minute (RPM)** — ഒരു അക്കൗണ്ടിന് ഒരു മിനിറ്റിലെ പരമാവധി റിക്വസ്റ്റുകൾ
   - **Min Time Between Requests** — റിക്വസ്റ്റുകൾക്കിടയിലെ ഏറ്റവും കുറഞ്ഞ ഇടവേള (മില്ലിസെക്കൻഡിൽ)
   - **Max Concurrent Requests** — ഒരു അക്കൗണ്ടിലെ പരമാവധി സമകാലിക റിക്വസ്റ്റുകൾ

2. **Connection Cooldown** — വീണ്ടും ശ്രമിക്കാവുന്ന പരാജയങ്ങൾക്ക് ശേഷം ഒരൊറ്റ കണക്ഷനുള്ള, ഓതെന്റിക്കേഷൻ-തരം അനുസരിച്ചുള്ള ക്രമീകരണം:
   - **Base Cooldown** — വീണ്ടും ശ്രമിക്കാവുന്ന അപ്സ്ട്രീം പരാജയങ്ങൾക്കുള്ള സ്ഥിരസ്ഥിതി കൂൾഡൗൺ വിൻഡോ
   - **Use Upstream Retry Hints** — നൽകിയിട്ടുണ്ടെങ്കിൽ അധികൃത `Retry-After` അല്ലെങ്കിൽ റീസെറ്റ് സൂചനകൾ പാലിക്കുന്നു
   - **Max Backoff Steps** — ആവർത്തിച്ചുള്ള പരാജയങ്ങൾക്കുള്ള പരമാവധി എക്സ്പോനൻഷ്യൽ ബാക്ക്ഓഫ് നില

3. **Provider Circuit Breaker** — എൻഡ്-ടു-എൻഡ് പ്രൊവൈഡർ പരാജയങ്ങളെ ട്രാക്ക് ചെയ്യുകയും, ക്രമീകരിച്ച മുന്നറിയിപ്പ് പരിധിയിൽ പ്രൊവൈഡറെ തകരാറിലായതായി അടയാളപ്പെടുത്തുകയും, ക്രമീകരിച്ച പരാജയ പരിധിയിലെത്തുമ്പോൾ ബ്രേക്കർ തുറക്കുകയും ചെയ്യുന്നു:
   - **Degradation Threshold** — `DEGRADED` നിലയിൽ പ്രവേശിക്കുന്നതിന് മുൻപുള്ള തുടർച്ചയായ പ്രൊവൈഡർ പരാജയങ്ങൾ
   - **Failure Threshold** — `OPEN` നിലയിൽ പ്രവേശിക്കുന്നതിന് മുൻപുള്ള തുടർച്ചയായ പ്രൊവൈഡർ പരാജയങ്ങൾ
   - **Reset Timeout** — പ്രൊവൈഡറെ വീണ്ടും പരിശോധിക്കുന്നതിന് മുൻപുള്ള സമയ വിൻഡോ
   - **CLOSED** (ആരോഗ്യകരം) — റിക്വസ്റ്റുകൾ സാധാരണയായി ഒഴുകുന്നു
   - **DEGRADED** — ഉയർന്ന പരാജയങ്ങൾ ട്രാക്ക് ചെയ്യപ്പെടുമ്പോഴും റിക്വസ്റ്റുകൾ ഒഴുകുന്നു
   - **OPEN** — ആവർത്തിച്ചുള്ള പരാജയങ്ങൾക്ക് ശേഷം പ്രൊവൈഡർ താൽക്കാലികമായി തടയപ്പെടുന്നു
   - **HALF_OPEN** — പ്രൊവൈഡർ പുനഃസ്ഥാപിച്ചോ എന്ന് പരിശോധിക്കുന്നു

   കണക്ഷൻ സ്കോപ്പിലുള്ള `429` റേറ്റ് ലിമിറ്റുകൾ **Connection Cooldown**-ൽ തന്നെ തുടരും; അവ പ്രൊവൈഡർ ബ്രേക്കറിൽ കണക്കാക്കില്ല.

   പ്രൊവൈഡർ ബ്രേക്കറിന്റെ റൺടൈം നില **Dashboard → Health**-ൽ മാത്രമേ കാണിക്കൂ.

4. **Wait For Cooldown** — എല്ലാ സാധ്യതാ കണക്ഷനുകളും ഇതിനകം കൂൾ ഡൗൺ ആയിക്കഴിഞ്ഞാൽ, OmniRoute ഏറ്റവും നേരത്തെയുള്ള കൂൾഡൗണിനായി കാത്തിരിക്കുകയും അതേ ക്ലയന്റ് റിക്വസ്റ്റ് സ്വയമേവ വീണ്ടും ശ്രമിക്കുകയും ചെയ്യും.

5. **Rate Limit Auto-Detection** — അപ്സ്ട്രീം പ്രൊവൈഡറുകൾ വ്യക്തമായ കാത്തിരിപ്പ് വിൻഡോകൾ മടക്കിനൽകുമ്പോൾ, ക്രമീകരണം പ്രവർത്തനക്ഷമമാക്കിയിട്ടുണ്ടെങ്കിൽ ആ സൂചനകൾ പ്രാദേശിക കണക്ഷൻ കൂൾഡൗണിനെ ഓവർറൈഡ് ചെയ്യും.

**പ്രൊ ടിപ്പ്:** ഔട്ടേജിന് ശേഷം തത്സമയ പ്രൊവൈഡർ ബ്രേക്കറുകൾ പരിശോധിക്കാനും റീസെറ്റ് ചെയ്യാനും **Health** പേജ് ഉപയോഗിക്കുക. Resilience പേജ് ക്രമീകരണം മാത്രമേ മാറ്റുന്നുള്ളൂ.

### ഡാറ്റാബേസ് എക്സ്പോർട്ട് / ഇംപോർട്ട്

**Dashboard → Settings → System & Storage**-ൽ ഡാറ്റാബേസ് ബാക്കപ്പുകൾ നിയന്ത്രിക്കുക.

| പ്രവൃത്തി                | വിവരണം                                                                                                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Export Database**      | നിലവിലെ SQLite ഡാറ്റാബേസ് ഒരു `.sqlite` ഫയലായി ഡൗൺലോഡ് ചെയ്യുന്നു                                                                                                               |
| **Export All (.tar.gz)** | ഇവ ഉൾപ്പെടെയുള്ള പൂർണ്ണ ബാക്കപ്പ് ആർക്കൈവ് ഡൗൺലോഡ് ചെയ്യുന്നു: ഡാറ്റാബേസ്, ക്രമീകരണങ്ങൾ, കോംബോകൾ, പ്രൊവൈഡർ കണക്ഷനുകൾ (ക്രെഡൻഷ്യലുകൾ ഇല്ല), API കീ മെറ്റാഡാറ്റ                   |
| **Import Database**      | നിലവിലെ ഡാറ്റാബേസിനെ മാറ്റിസ്ഥാപിക്കാൻ ഒരു `.sqlite` ഫയൽ അപ്ലോഡ് ചെയ്യുക. `DISABLE_SQLITE_AUTO_BACKUP=true` അല്ലെങ്കിൽ, ഇംപോർട്ടിന് മുൻപുള്ള ബാക്കപ്പ് സ്വയമേവ സൃഷ്ടിക്കപ്പെടും |

```bash
# API: ഡാറ്റാബേസ് എക്സ്പോർട്ട് ചെയ്യുക
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: എല്ലാം എക്സ്പോർട്ട് ചെയ്യുക (പൂർണ്ണ ആർക്കൈവ്)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ഡാറ്റാബേസ് ഇംപോർട്ട് ചെയ്യുക
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ഇംപോർട്ട് സാധുതാ പരിശോധന:** ഇംപോർട്ട് ചെയ്ത ഫയൽ അഖണ്ടത (SQLite pragma പരിശോധന), ആവശ്യമായ ടേബിളുകൾ (`provider_connections`, `provider_nodes`, `combos`, `api_keys`), വലുപ്പം (പരമാവധി 100MB) എന്നിവയ്ക്കായി പരിശോധിക്കപ്പെടുന്നു.

**ഉപയോഗ സാഹചര്യങ്ങൾ:**

- യന്ത്രങ്ങൾക്കിടയിൽ OmniRoute മൈഗ്രേറ്റ് ചെയ്യുക
- ഡിസാസ്റ്റർ റിക്കവരിക്കായി ബാഹ്യ ബാക്കപ്പുകൾ സൃഷ്ടിക്കുക
- ടീം അംഗങ്ങൾക്കിടയിൽ ക്രമീകരണങ്ങൾ പങ്കിടുക (എല്ലാം എക്സ്പോർട്ട് ചെയ്യുക → ആർക്കൈവ് പങ്കിടുക)

പൊതുവായ ടാബ് ഇനി റീഡ്-ഓൺലി ലോഗിംഗും ക്യാഷ് കുറിപ്പുകളും ആവർത്തിക്കുന്നില്ല. ഡാറ്റാബേസ് റിടെൻഷൻ, ഒപ്റ്റിമൈസേഷൻ ക്രമീകരണങ്ങൾ `/api/settings/database` വഴി സ്ഥിരമായി സൂക്ഷിക്കപ്പെടുന്നു; മാനുവൽ ക്യാഷ് മായ്ക്കലിന് `DELETE /api/cache` ഉപയോഗിക്കുന്നു. റിക്വസ്റ്റ്, പ്രോക്സി ലോഗ് വരികളുടെ പരമാവധി എണ്ണം `CALL_LOGS_TABLE_MAX_ROWS`, `PROXY_LOGS_TABLE_MAX_ROWS` എന്നിവയാൽ നിയന്ത്രിക്കപ്പെടുന്നു.

### ചെലവുകളും ബജറ്റ് മാനേജ്മെന്റും

**ഡാഷ്ബോർഡ് → ചെലവുകൾ** വഴി ആക്സസ് ചെയ്യുക.

| ടാബ്            | ഉദ്ദേശ്യം                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **ബജറ്റ്**      | ഓരോ API കീയ്ക്കും പ്രതിദിന/പ്രതിവാര/പ്രതിമാസ ബജറ്റുകളോടെയും തത്സമയ ട്രാക്കിംഗോടെയും ചെലവ് പരിധികൾ സജ്ജമാക്കുക                   |
| **വിലനിർണ്ണയം** | മോഡൽ വിലനിർണ്ണയ എൻട്രികൾ കാണുകയും എഡിറ്റ് ചെയ്യുകയും ചെയ്യുക — ഓരോ പ്രോവൈഡർക്കും 1K ഇൻപുട്ട്/ഔട്ട്പുട്ട് ടോക്കണുകൾക്കുള്ള ചെലവ് |

```bash
# API: ബജറ്റ് സജ്ജമാക്കുക
curl -X POST http://localhost:20128/api/usage/budget \
  -H "Content-Type: application/json" \
  -d '{"keyId": "key-123", "limit": 50.00, "period": "monthly"}'

# API: നിലവിലെ ബജറ്റ് നില അറിയുക
curl http://localhost:20128/api/usage/budget
```

**ചെലവ് ട്രാക്കിംഗ്:** ഓരോ റിക്വസ്റ്റും ടോക്കൺ ഉപയോഗം രേഖപ്പെടുത്തുകയും വിലനിർണ്ണയ പട്ടിക ഉപയോഗിച്ച് ചെലവ് കണക്കാക്കുകയും ചെയ്യുന്നു. **ഡാഷ്ബോർഡ് → ഉപയോഗം** എന്നിവിടെ പ്രോവൈഡർ, മോഡൽ, API കീ തിരിച്ചുള്ള വിഭജനങ്ങൾ കാണുക.

### ഓഡിയോ ട്രാൻസ്ക്രിപ്ഷൻ

OmniRoute OpenAI-അനുയോജ്യമായ എൻഡ്പോയിന്റ് വഴി ഓഡിയോ ട്രാൻസ്ക്രിപ്ഷനെ പിന്തുണയ്ക്കുന്നു:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# curl ഉപയോഗിച്ചുള്ള ഉദാഹരണം
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

`deepgram/nova-3` നേറ്റീവ് Deepgram റൂട്ടാണ്, ഇതിന് ഒരു Deepgram API കീ ആവശ്യമാണ്.
OpenRouter മാത്രമേ കോൺഫിഗർ ചെയ്തിട്ടുള്ളൂ എങ്കിൽ, `openrouter/deepgram/nova-3` ഉപയോഗിക്കുക.

**സ്പീച്ച്-ടു-ടെക്സ്റ്റ് (ട്രാൻസ്ക്രിപ്ഷൻ)** പ്രോവൈഡറുകൾ:

- `openai/` (whisper-അനുയോജ്യം)

- `assemblyai/`
- `nvidia/` (Parakeet, Canary)

- `qwen/`

**ടെക്സ്റ്റ്-ടു-സ്പീച്ച് (`POST /v1/audio/speech`)** പ്രോവൈഡറുകൾ:

- `huggingface/`

- `playht/`
- `kie/`
- `aws-polly/`
- `xiaomi-mimo/`
- `coqui/`, `tortoise/`
- `qwen/`

ട്രാൻസ്ക്രിപ്ഷന് പിന്തുണയ്ക്കുന്ന ഓഡിയോ ഫോർമാറ്റുകൾ: `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`. TTS ഔട്ട്പുട്ട് ഫോർമാറ്റുകൾ പ്രോവൈഡറെ ആശ്രയിച്ചിരിക്കുന്നു (mp3, wav, opus, pcm, mulaw).

### കോംബോ ബാലൻസിംഗ് തന്ത്രങ്ങൾ

**ഡാഷ്ബോർഡ് → കോംബോകൾ → സൃഷ്ടിക്കുക/എഡിറ്റ് ചെയ്യുക → തന്ത്രം** എന്നിവിടെ ഓരോ കോംബോയ്ക്കും ബാലൻസിംഗ് കോൺഫിഗർ ചെയ്യുക.

| തന്ത്രം                    | വിവരണം                                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------------------------- |
| **റൗണ്ട്-റോബിൻ**           | മോഡലുകളിലൂടെ ക്രമപ്രകാരം മാറിമാറി റൂട്ട് ചെയ്യുന്നു                                                     |
| **പ്രായോറിറ്റി**           | എല്ലായ്പ്പോഴും ആദ്യത്തെ മോഡൽ ശ്രമിക്കുന്നു; പിശക് സംഭവിക്കുമ്പോൾ മാത്രം ഫോൾബാക്ക് ചെയ്യുന്നു            |
| **റാൻഡം**                  | ഓരോ റിക്വസ്റ്റിനും കോംബോയിൽ നിന്ന് ക്രമരഹിതമായി ഒരു മോഡൽ തിരഞ്ഞെടുക്കുന്നു                              |
| **വെയ്റ്റഡ്**              | ഓരോ മോഡലിനും നൽകിയിരിക്കുന്ന വെയ്റ്റുകളെ അടിസ്ഥാനമാക്കി ആനുപാതികമായി റൂട്ട് ചെയ്യുന്നു                  |
| **ലീസ്റ്റ്-യൂസ്ഡ്**        | ഏറ്റവും കുറവ് സമീപകാല റിക്വസ്റ്റുകളുള്ള മോഡലിലേക്ക് റൂട്ട് ചെയ്യുന്നു (കോംബോ മെട്രിക്സ് ഉപയോഗിക്കുന്നു) |
| **കോസ്റ്റ്-ഒപ്റ്റിമൈസ്ഡ്** | ഏറ്റവും ചെലവ് കുറഞ്ഞ ലഭ്യമായ മോഡലിലേക്ക് റൂട്ട് ചെയ്യുന്നു (വിലനിർണ്ണയ പട്ടിക ഉപയോഗിക്കുന്നു)           |

ആഗോള കോംബോ ഡിഫോൾട്ടുകൾ **ഡാഷ്ബോർഡ് → ക്രമീകരണങ്ങൾ → റൂട്ടിംഗ് → കോംബോ ഡിഫോൾട്ടുകൾ** എന്നിവിടെ സജ്ജമാക്കാം.
കോംബോ ടാർഗറ്റ് ടൈംഔട്ടുകൾ സ്ഥിരസ്ഥിതിയായി നിലവിലെ റിക്വസ്റ്റ് ടൈംഔട്ട് അനന്തരമായി ലഭിക്കും. ഓരോ ടാർഗറ്റിനും കുറഞ്ഞ സമയപരിധി വേഗത്തിലുള്ള ഫോൾബാക്ക് ട്രിഗർ ചെയ്യേണ്ട സാഹചര്യങ്ങളിൽ മാത്രം കോംബോ ഡിഫോൾട്ടുകളിലോ വ്യക്തിഗത കോംബോയിലോ **ടാർഗറ്റ് ടൈംഔട്ട് (സെക്കൻഡുകൾ)** ഉപയോഗിക്കുക.

സീറോ-ലേറ്റൻസി കോംബോ ഒപ്റ്റിമൈസേഷനുകൾ ഓപ്റ്റ്-ഇൻ ആണ്. ഈ ലേറ്റൻസി ഫീച്ചറുകൾ ഫോൾബാക്ക് ടാർഗറ്റുകളുമായി മത്സരിക്കുന്നതിനോ, TTFT ചരിത്രത്തെ അടിസ്ഥാനമാക്കി ടാർഗറ്റുകൾ ഒഴിവാക്കുന്നതിനോ, ഫോൾബാക്ക് റിക്വസ്റ്റുകൾ കംപ്രസ്സ് ചെയ്യുന്നതിനോ ഇടയാക്കാതിരിക്കാൻ **സീറോ-ലേറ്റൻസി ഒപ്റ്റിമൈസേഷനുകൾ** പ്രവർത്തനരഹിതമായി തന്നെ സൂക്ഷിക്കുക; ഇത് പ്രാപ്തമാക്കുമ്പോൾ കോൺഫിഗർ ചെയ്ത ഹെഡ്ജിംഗ്, പ്രവചനാത്മക TTFT സ്കിപ്പുകൾ, മുൻകൈ ഫോൾബാക്ക് കംപ്രഷൻ എന്നിവയ്ക്ക് താഴ്ന്ന ടെയിൽ ലേറ്റൻസിക്ക് വേണ്ടി റൂട്ടിംഗ്/റിക്വസ്റ്റ് ഫിഡെലിറ്റി ക്ഷപോണം ചെയ്യാൻ അനുവദിക്കും.

അപ്പ്സ്ട്രീം പ്രൊവൈഡർമാർക്ക് കർശനമായ `max_tokens` / `maxOutputTokens` പരിധികൾ ആവശ്യമുള്ളപ്പോൾ **റീസണിംഗ് ടോക്കൺ ബഫർ** പ്രവർത്തനരഹിതമാക്കുക. പ്രവർത്തനക്ഷമമാക്കുമ്പോൾ, അറിയപ്പെടുന്ന ഔട്ട്പുട്ട് പരിധിയുള്ള മോഡലുകൾക്ക് കോംബോ റൂട്ടിംഗ് റീസണിംഗ്-മോഡൽ ഹെഡ്റൂം മാത്രമേ ചേർക്കൂ, കൂടാതെ സുരക്ഷിത ബഫർ മൂല്യം ആ പരിധി കവിയുമ്പോൾ client ടോക്കൺ പരിധി മാറ്റമില്ലാതെ നിലനിർത്തുന്നു. Client പരിധി ഇതിനകം അറിയപ്പെടുന്ന പരിധിക്ക് മുകളിലാണെങ്കിൽ, അപ്പ്സ്ട്രീം അഭ്യർത്ഥന അയയ്ക്കുന്നതിന് മുമ്പ് OmniRoute അത് ആ പരിധിയിലേക്ക് കുറയ്ക്കുന്നു.

## 🔌 MCP & A2A സംയോജനം

OmniRoute ഒരു **MCP സെർവറും** (Model Context Protocol) ഒരു **A2A സെർവറും** (Agent-to-Agent JSON-RPC 2.0) ആണ്. MCP-യുമായി പൊരുത്തപ്പെടുന്ന ഏത് IDE-യ്ക്കോ ഏജന്റ് ഹോസ്റ്റിനോ OmniRoute ടൂളുകൾ നേരിട്ട് കോൾ ചെയ്യാനാകും — അധിക റാപ്പർ ആവശ്യമില്ല.

### MCP ട്രാൻസ്പോർട്ടുകൾ

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **സ്ട്രീം ചെയ്യാവുന്ന HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (stdio തിരഞ്ഞെടുക്കുന്ന IDE പ്ലഗിനുകൾക്കായി)

### Claude Desktop ബന്ധിപ്പിക്കുക

macOS-ൽ `~/Library/Application Support/Claude/claude_desktop_config.json` അല്ലെങ്കിൽ Windows/Linux-ലെ തത്തുല്യമായ ഫയൽ എഡിറ്റ് ചെയ്യുക:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCP ബന്ധിപ്പിക്കുക

SSE URL ആയ `http://localhost:20128/api/mcp/sse`-ഉം **Dashboard → API Keys** എന്നതിൽ സൃഷ്ടിച്ച ഒരു Bearer API കീയും ഉപയോഗിക്കുക.

### സ്കോപ്പുകൾ

MCP നിലവിൽ പേരിട്ട 32 സ്കോപ്പുകൾ നിർവചിക്കുന്നു. ഓരോ Bearer കീയും നിർദിഷ്ട സ്കോപ്പുകളിലേക്ക് പരിമിതപ്പെടുത്താനാകും — ആധികാരികമായ സ്കോപ്പ്, ടൂൾ ഇൻവെന്ററികൾക്കായി [MCP-SERVER.md](../frameworks/MCP-SERVER.md)-ഉം JSON-RPC സ്കീമയ്ക്കായി [A2A-SERVER.md](../frameworks/A2A-SERVER.md)-ഉം കാണുക.

## 🧠 കഴിവുകളുടെ സംവിധാനം

- **മാർക്കറ്റ്പ്ലേസ് UI** — **ഡാഷ്ബോർഡ് → കഴിവുകൾ** എന്നതിൽ നിന്ന് കഴിവുകൾ ബ്രൗസ് ചെയ്യുകയും ഇൻസ്റ്റാൾ ചെയ്യുകയും ചെയ്യുക
- **ഓരോ കീയ്ക്കുമുള്ള സ്കോപ്പുകൾ** — ഏതൊക്കെ API കീകൾക്ക് ഏതൊക്കെ കഴിവുകൾ പ്രവർത്തിപ്പിക്കാനാകുമെന്ന് നിയന്ത്രിക്കുക
- **ഇഷ്ടാനുസൃത കഴിവുകൾ** — `src/lib/a2a/skills/` എന്നതിൽ ഒരു TypeScript ഫയൽ ചേർത്ത് അത് രജിസ്റ്റർ ചെയ്യുക; ഉടൻതന്നെ A2A വഴി അത് പ്രവർത്തിപ്പിക്കാനാകും

## 💾 മെമ്മറി സംവിധാനം

ഹൈബ്രിഡ് റിട്രീവലോടുകൂടിയ **ദീർഘകാല സംഭാഷണ മെമ്മറി** OmniRoute നിലനിർത്തുന്നു:

- കഴിഞ്ഞ സംഭാഷണങ്ങളിലുടനീളമുള്ള കീവേഡ് തിരയലിനായി **SQLite FTS5**
- അർത്ഥാധിഷ്ഠിത ഓർമ്മപ്പെടുത്തലിനായി **Qdrant വെക്റ്റർ സ്റ്റോർ** (ഐച്ഛികം)
- **സ്വയമേവയുള്ള വസ്തുതാ വേർതിരിച്ചെടുക്കൽ** — ഓരോ സെഷനുശേഷവും എന്റിറ്റികൾ, മുൻഗണനകൾ, തീരുമാനങ്ങൾ എന്നിവ സംഗ്രഹിച്ച് `memory_facts` പട്ടികയിൽ സംഭരിക്കുന്നു
- ഓരോ API കീയ്ക്കും ഓരോ സെഷനും അനുസരിച്ച് മെമ്മറികൾക്ക് സ്കോപ്പ് നിശ്ചയിച്ചിരിക്കുന്നു

**ഡാഷ്ബോർഡ് → മെമ്മറി** എന്നതിൽ മെമ്മറികൾ കൈകാര്യം ചെയ്യുക (തിരയുക, എഡിറ്റ് ചെയ്യുക, എക്സ്പോർട്ട് ചെയ്യുക, പൂർണ്ണമായി നീക്കം ചെയ്യുക). HTTP ഇന്റർഫേസ് (`/api/memory/*`) ഉപയോഗിച്ച് ഏജന്റുകൾക്ക് പ്രോഗ്രാമാറ്റിക്കായി വസ്തുതകൾ നൽകാനും അന്വേഷിക്കാനും കഴിയും — [MEMORY.md](../frameworks/MEMORY.md) കാണുക.

## 🔔 വെബ്ഹുക്കുകൾ

തത്സമയ നിരീക്ഷണത്തിനും ഓട്ടോമേഷനുമായി OmniRoute ഇവന്റുകൾ സബ്സ്ക്രൈബ് ചെയ്യുക.

- ലക്ഷ്യ URL-ഉം HMAC സൈനിംഗ് സീക്രട്ടും ഉപയോഗിച്ച് **ഡാഷ്ബോർഡ് → വെബ്ഹുക്കുകൾ** എന്നതിൽ ഒരു വെബ്ഹുക്ക് സൃഷ്ടിക്കുക
- ലഭ്യമായ ഇവന്റുകൾ: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- സ്ഥിരീകരണത്തിനായി ഓരോ പേലോഡിലും `X-OmniRoute-Signature` (HMAC-SHA256) ഉൾപ്പെടുന്നു
- വീണ്ടും ശ്രമിക്കൽ: എക്സ്പോണൻഷ്യൽ ബാക്ക്ഓഫോടെ 3 ശ്രമങ്ങൾ, തുടർന്ന് ഡെഡ്-ലെറ്റർ ക്യൂ

OmniRoute ക്ലൗഡ് കോഡിംഗ് ഏജന്റുകളുമായി (**OpenAI Codex Cloud**, **Devin**, **Jules**, **Antigravity**) സംയോജിക്കുന്നു; അതുവഴി നിങ്ങളുടെ ലോക്കൽ റൂട്ടിംഗ് കൈകാര്യം ചെയ്യുന്ന അതേ ഡാഷ്ബോർഡിൽ നിന്ന് ദീർഘനേരം പ്രവർത്തിക്കുന്ന ടാസ്ക്കുകൾ അയയ്ക്കാൻ കഴിയും.

- **ഡാഷ്ബോർഡ് → ക്ലൗഡ് ഏജന്റുകൾ** എന്നതിലോ `POST /api/v1/agents/tasks` വഴിയോ ടാസ്ക്കുകൾ സൃഷ്ടിക്കുക
- ഓരോ ടാസ്ക്കിന്റെയും സ്റ്റാറ്റസ്, ലോഗുകൾ, ആർട്ടിഫാക്റ്റുകൾ എന്നിവ ട്രാക്ക് ചെയ്യുക
- ഓരോ പ്രൊവൈഡർക്കും നിങ്ങളുടെ സ്വന്തം API കീ ഉപയോഗിക്കുക — ക്രെഡൻഷ്യലുകൾ ഒരിക്കലും OmniRoute ഇൻസ്റ്റൻസിൽ നിന്ന് പുറത്തുപോകില്ല

## 🛠️ പ്രോഗ്രാമാറ്റിക് മാനേജ്മെന്റ്

**`manage` സ്കോപ്പുള്ള ഒരു Bearer കീ** ഉപയോഗിച്ച് HTTP വഴി എല്ലാ OmniRoute റിസോഴ്സുകളും (പ്രൊവൈഡറുകൾ, കോംബോകൾ, കീകൾ, ക്രമീകരണങ്ങൾ) കൈകാര്യം ചെയ്യാം.

**ഡാഷ്ബോർഡ് → API കീകൾ → പുതിയ കീ → സ്കോപ്പ്: manage** എന്നതിൽ കീ സൃഷ്ടിച്ച ശേഷം:

```bash
# പ്രൊവൈഡറുകളുടെ പട്ടിക കാണിക്കുക
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# ഒരു പ്രൊവൈഡർ കണക്ഷൻ ചേർക്കുക
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# ഒരു കോംബോ സൃഷ്ടിക്കുക
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API കീകളുടെ പട്ടിക കാണിക്കുക/സൃഷ്ടിക്കുക
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

പൂർണ്ണ എൻഡ്പോയിന്റ് കാറ്റലോഗിനും അഭ്യർത്ഥന/പ്രതികരണ സ്കീമകൾക്കും [API_REFERENCE.md](../reference/API_REFERENCE.md) കാണുക.

## 💻 ആന്തരിക CLI

സജ്ജീകരണം, ഡയഗ്നോസ്റ്റിക്സ്, റൺടൈം നിയന്ത്രണം എന്നിവയ്ക്കായി OmniRoute ഒരു ആന്തരിക CLI (`omniroute …`) സഹിതമാണ് ലഭിക്കുന്നത്. ഇത് മൂന്നാം കക്ഷി CLI-കൾക്ക് (Claude Code, Cursor, Codex, Cline, …) OmniRoute-മായി ആശയവിനിമയം നടത്താൻ കഴിയുന്ന വിധത്തിൽ അവയെ കോൺഫിഗർ ചെയ്യുന്ന ഡാഷ്ബോർഡിലെ **"CLI Tools" പേജിൽ നിന്ന് വ്യത്യസ്തമാണ്**.

```bash
omniroute setup                    # ഇന്ററാക്ടീവ് വിസാർഡ് (പാസ്വേഡ്, പ്രൊവൈഡറുകൾ, കോമ്പോകൾ)
omniroute setup --non-interactive  # CI-ക്ക് അനുയോജ്യം
omniroute doctor                   # ആരോഗ്യനില ഡയഗ്നോസ്റ്റിക്സ് (ഡാറ്റ ഡയറക്ടറി, DB, പ്രൊവൈഡറുകൾ, പോർട്ടുകൾ)
omniroute providers available      # പിന്തുണയ്ക്കുന്ന പ്രൊവൈഡറുകളെ പട്ടികപ്പെടുത്തുക
omniroute providers list           # കോൺഫിഗർ ചെയ്ത കണക്ഷനുകളെ പട്ടികപ്പെടുത്തുക
omniroute providers test <id>      # ഒരു പ്രൊവൈഡർ കണക്ഷൻ തത്സമയം പരിശോധിക്കുക
omniroute combos list              # കോമ്പോകളെ പട്ടികപ്പെടുത്തുക
omniroute combos switch <name>     # ഡിഫോൾട്ട് കോമ്പോ സജ്ജമാക്കുക
omniroute models                   # ലഭ്യമായ മോഡലുകളെ പട്ടികപ്പെടുത്തുക (--json, --search)
omniroute keys add | list | remove # ടെർമിനലിൽ നിന്ന് API കീകൾ കൈകാര്യം ചെയ്യുക
omniroute backup                   # കോൺഫിഗറേഷന്റെയും DB-യുടെയും സ്നാപ്പ്ഷോട്ട് എടുക്കുക
omniroute restore [<timestamp>]    # ഒരു സ്നാപ്പ്ഷോട്ടിൽ നിന്ന് പുനഃസ്ഥാപിക്കുക
omniroute health                   # വിശദമായ ആരോഗ്യനില (ബ്രേക്കറുകൾ, കാഷ്, മെമ്മറി)
omniroute quota                    # പ്രൊവൈഡർ ക്വോട്ട ഉപയോഗം
omniroute mcp status               # MCP സെർവർ നില
omniroute a2a status               # A2A സെർവർ നില
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok ടണലുകൾ
omniroute reset-password           # അഡ്മിൻ പാസ്വേഡ് പുനഃസജ്ജമാക്കുക
omniroute --mcp                    # stdio വഴി MCP സെർവർ ആരംഭിക്കുക
omniroute --port 3000              # ഇഷ്ടാനുസൃത പോർട്ടിൽ സെർവർ ആരംഭിക്കുക
```

നുറുങ്ങ്: ആരോഗ്യകരമല്ലാത്ത പ്രൊവൈഡർ കണക്ഷനുകളെക്കുറിച്ച് മുന്നറിയിപ്പ് ലഭിക്കാൻ `omniroute doctor --json` നിങ്ങളുടെ മോണിറ്ററിംഗ് ടൂളുമായി ചേർത്ത് ഉപയോഗിക്കുക.

## 🖥️ ഡെസ്ക്ടോപ്പ് ആപ്ലിക്കേഷൻ (Electron)

Windows, macOS, Linux എന്നിവയ്ക്കായി ഒരു നേറ്റീവ് ഡെസ്ക്ടോപ്പ് ആപ്ലിക്കേഷനായി OmniRoute ലഭ്യമാണ്.

### ഇൻസ്റ്റാളേഷൻ

```bash
# electron ഡയറക്ടറിയിൽ നിന്ന്:
cd electron
npm install

# ഡെവലപ്മെന്റ് മോഡ് (പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന Next.js ഡെവ് സെർവറുമായി കണക്റ്റ് ചെയ്യുന്നു):
npm run dev

# പ്രൊഡക്ഷൻ മോഡ് (സ്റ്റാൻഡ്അലോൺ ബിൽഡ് ഉപയോഗിക്കുന്നു):
npm start
```

### ഇൻസ്റ്റാളറുകൾ ബിൽഡ് ചെയ്യൽ

```bash
cd electron
npm run build          # നിലവിലെ പ്ലാറ്റ്ഫോം
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg യൂണിവേഴ്സൽ)
npm run build:linux    # Linux (.AppImage)
```

ഔട്ട്പുട്ട് → `electron/dist-electron/`
