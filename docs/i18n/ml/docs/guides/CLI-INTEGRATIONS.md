പങ്കിട്ട എക്സിക്യൂട്ടബിൾ മാനിഫെസ്റ്റിനും നിയന്ത്രിത ചൈൽഡ് എൻവയോൺമെൻ്റുകൾക്കും സ്ഥിരമായ Gemini സജ്ജീകരണത്തിനും, [CLI ലോഞ്ച് കരാറുകൾ](./CLI-LAUNCH-CONTRACTS.md) കാണുക.

OmniRoute അതിൻ്റെ ബാക്കെൻഡ് — ആയി ഉപയോഗിക്കുന്നതിന് ഒരു കോഡിംഗ് CLI (Codex, Claude കോഡ്, OpenCode, Cline, ...) കോൺഫിഗർ ചെയ്യുന്ന `setup-*` കമാൻഡുകളുടെ ഒരു കുടുംബത്തെOmniRoute അയയ്ക്കുന്നു, അതിനാൽ ടൂൾ സംസാരിക്കുന്നു** ഒന്ന്** ഓട്ടോ-ഫാൾബാക്ക് ഉപയോഗിച്ച് ശരിയായ ദാതാവിലേക്കുള്ള എൻഡ് പോയിൻ്റും OmniRoute റൂട്ടുകളും. സെറ്റപ്പ് കമാൻഡുകൾ നിങ്ങളുടെ സജീവ ലോക്കൽ അല്ലെങ്കിൽ റിമോട്ട് OmniRoute സന്ദർഭം ഉപയോഗിക്കുകയും ടൂൾ കോൺഫിഗർ ചെയ്യുകയും ചെയ്യുന്നു** നിങ്ങളുടെ** യന്ത്രം. കാറ്റലോഗ് അടിസ്ഥാനമാക്കിയുള്ള പാചകക്കുറിപ്പുകൾ സെർവറിൽ നിന്ന് മോഡലുകൾ ലഭ്യമാക്കുന്നു; സിംഗിൾ-മോഡൽ പാചകക്കുറിപ്പുകൾ `--model` സ്വീകരിക്കുന്നു അല്ലെങ്കിൽ ഒരു മോഡലിനായി ID ആവശ്യപ്പെടുന്നു. ടൂൾ പിന്തുണയ്ക്കുന്നിടത്തെല്ലാം API കീ ഒരു എൻവയോൺമെൻ്റ് വേരിയബിളാണ് റഫറൻസ് ചെയ്യുന്നത്. ഒരു ടൂൾ-ലോക്കൽ എൻവയോൺമെൻ്റ് ഫയൽ നിലനിൽക്കുന്ന കമാൻഡുകൾ ചുവടെ രേഖപ്പെടുത്തിയിരിക്കുന്നു.

കാറ്റലോഗും ഓട്ടോമേഷൻ കമാൻഡുകളും വ്യത്യസ്ത സെറ്റ് ടൂളുകൾ ഉൾക്കൊള്ളുന്നു:

| ഉപരിതലം                        | എണ്ണുക | എന്താണ് അർത്ഥമാക്കുന്നത്                                                               |
| ------------------------------ | ------ | -------------------------------------------------------------------------------------- |
| ടൂൾ കാറ്റലോഗ്                  | 39     | മാനുവൽ, IDE സംയോജനങ്ങൾ ഉൾപ്പെടെയുള്ള ഡോക്യുമെൻ്റഡ് കോഡിംഗ് ടൂളുകളും ഏജൻ്റുമാരും        |
| `omniroute run <target>`       | 8      | ടാർഗെറ്റിൻ്റെ അവസാന പോയിൻ്റും ക്രെഡൻഷ്യലുകളും മോഡലും നൽകുന്ന അഡാപ്റ്ററുകൾ സമാരംഭിക്കുക |
| `omniroute configure <target>` | 12     | `setup-*` കമാൻഡുകളുടെ പിന്തുണയുള്ള ഇൻ്ററാക്ടീവ് കോൺഫിഗറേഷൻ പാചകക്കുറിപ്പുകൾ            |
| `setup-*` കമാൻഡുകൾ             | 16     | guided/manual എഡിറ്റർ സജ്ജീകരണം ഉൾപ്പെടെ രജിസ്റ്റർ ചെയ്ത സജ്ജീകരണ കമാൻഡുകൾ             |

2026-11-17-ലെ [ടൂൾ മാനിഫെസ്റ്റും](../../config/cli-tools-manifest.json) [കമാൻഡ് രജിസ്ട്രിയും](../../bin/cli/commands/registry.mjs) കണക്കുകൾ പ്രതിഫലിപ്പിക്കുന്നു. ഒരു കാറ്റലോഗ് എൻട്രി ഒരു ലോഞ്ച് അഡാപ്റ്ററിനെ സൂചിപ്പിക്കുന്നില്ല. മുഴുവൻ ഇൻവെൻ്ററിക്കായി [CLI ടൂൾ കാറ്റലോഗ്](../reference/CLI-TOOLS.md) കാണുക.

`claude`, `codex`, `aider`, `goose`, `opencode`, `qwen`, `gemini` അല്ലെങ്കിൽ `whycodes` എന്നിവയ്ക്ക് വലത് env കുത്തിവച്ച്, ഒരു കോൺഫിഗും എഴുതാതെ തന്നെ സൃഷ്ടിക്കുന്ന ഒരു ജനറിക് ലോഞ്ചർ — `omniroute run <target>` — ഉണ്ട്. ടാർഗെറ്റുകളും അവയുടെ അപരനാമങ്ങളും കാനോനിക്കൽ മാനിഫെസ്റ്റ് `bin/cli/cli-manifest.mjs` (`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`, `open-code`, `qwen-code`, `gemini-cli`, `why-codes|why`) ൽ നിന്നാണ് വരുന്നത്, കൂടാതെ `omniroute completion` ഒരേ മാനിഫെസ്റ്റിൽ നിന്ന് ഉരുത്തിരിഞ്ഞ ടാർഗെറ്റ് വാക്കുകൾ വാഗ്ദാനം ചെയ്യുന്നു. `omniroute launch <tool>` ഓരോ ലോഞ്ച് സെഷൻ ടോക്കണും നിങ്ങൾ കണക്റ്റുചെയ്ത ദാതാക്കളിൽ നിന്ന് നിർമ്മിച്ച ഒരു മോഡൽ ലിസ്റ്റും ഉപയോഗിച്ച് പിന്തുണയ്ക്കുന്ന ഒരു കോഡിംഗ് ടൂൾ ആരംഭിക്കുന്നു, ഒന്നും പ്രവർത്തിക്കാത്തപ്പോൾ ഒരു ലോക്കൽ ഗേറ്റ്വേ സ്വയമേവ ആരംഭിക്കുന്നു ( [LAUNCH.md](./LAUNCH.md) കാണുക). ടൂൾ നെയിം (Claude കോഡ്), `omniroute launch-codex` (Codex) — എന്നിവയില്ലാത്ത ലെഗസി പെർ ടൂൾ ലോഞ്ചറുകൾ — `omniroute launch` ലഭ്യമാണ്.

അതേ local/remote സന്ദർഭത്തിൽ നിന്ന് ദാതാവിൻ്റെ ഓൺബോർഡിംഗ് ലഭ്യമാണ്. താഴെയുള്ള API-ആദ്യ കമാൻഡുകൾ മാനേജ്മെൻ്റ് പ്രാമാണീകരണം ദാതാവിൻ്റെ ക്രെഡൻഷ്യലുകളിൽ നിന്ന് വേറിട്ട് സൂക്ഷിക്കുന്നു, ഘടനാപരമായ ഔട്ട്പുട്ടിൽ ഒരിക്കലും ഒരു ക്രെഡൻഷ്യൽ പ്രിൻ്റ് ചെയ്യരുത്:

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

സ്ക്രിപ്റ്റുകൾക്ക്, `--credential-stdin` അല്ലെങ്കിൽ `--credential-env` തിരഞ്ഞെടുക്കുക; നിയന്ത്രിത പ്രാദേശിക ഉപയോഗത്തിനായി `--credential` നിലനിർത്തിയിരിക്കുന്നു. `providers remove` ഒരു നോൺ-ഇൻ്ററാക്ടീവ് ടെർമിനലിൽ `--yes` ആവശ്യമാണ്, കൂടാതെ അഞ്ച് കമാൻഡുകളും സജീവ സന്ദർഭത്തെയോ ആഗോള `--base-url`/`--api-key` ഓപ്ഷനുകളെയോ മാനിക്കുന്നു.

പ്രൊവൈഡർ സെലക്ടർമാർ അവ്യക്തമായ ID പ്രിഫിക്സുകൾ, പേരുകൾ അല്ലെങ്കിൽ ദാതാവിൻ്റെ പേരുകൾ നിരസിക്കുന്നു; നിരവധി കണക്ഷനുകൾ പൊരുത്തപ്പെടുമ്പോൾ ഒരു പൂർണ്ണ കണക്ഷൻ ID ഉപയോഗിക്കുക. സംരക്ഷിച്ച കണക്ഷൻ തിരികെ വായിക്കാൻ കമാൻഡുകൾ സൃഷ്ടിക്കുകയും എഡിറ്റ് ചെയ്യുകയും ചെയ്യുക, നീക്കംചെയ്യൽ അത് ഇനി വായിക്കാനാകില്ലെന്ന് സ്ഥിരീകരിക്കുന്നു. ഒരു ഇറക്കുമതി നിലവിലുള്ള provider/name ജോഡി ഒഴിവാക്കുന്നു. ഇറക്കുമതി ചെയ്ത എൻട്രികൾക്ക് CLI ലേക്ക് വിതരണം ചെയ്ത മാനേജ്മെൻ്റ് എൻഡ് പോയിൻ്റ്, സന്ദർഭം അല്ലെങ്കിൽ മാനേജ്മെൻ്റ് ക്രെഡൻഷ്യലുകൾ എന്നിവ അസാധുവാക്കാൻ കഴിയില്ല.

രണ്ട് സമ്പന്നമായ സംയോജനങ്ങളുടെ ഒറ്റത്തവണ, കൈകൊണ്ട് എഴുതിയ അടിസ്ഥാന സജ്ജീകരണത്തിനായി, ഓരോ ടൂൾ ഡീപ് ഡൈവുകളും കാണുക:

- [Claude കോഡ് കോൺഫിഗറേഷൻ](./CLAUDE-CODE-CONFIGURATION.md)
- [Codex CLI കോൺഫിഗറേഷൻ](./CODEX-CLI-CONFIGURATION.md)
- [റിമോട്ട് മോഡ്](./REMOTE-MODE.md) — നിങ്ങളുടെ ലാപ്ടോപ്പിൽ നിന്ന് ഒരു റിമോട്ട് OmniRoute (VPS / Tailnet) ഡ്രൈവ് ചെയ്യുക
- [VS കോഡ് Copilot ചാറ്റ്](./VSCODE-COPILOT.md) — OmniCopilot വിപുലീകരണം; എഡിറ്ററിനുള്ളിൽ നിന്ന് നിങ്ങൾക്ക് ഈ `setup-*` കമാൻഡുകൾ പ്രവർത്തിപ്പിക്കാനും ഇതിന് കഴിയും

## മാസ്റ്റർ ടേബിൾ

എല്ലാ കൽപ്പനകളും ബഹുമാനിക്കുന്നു** സജീവമായ സന്ദർഭം** ( `omniroute connect` ഉപയോഗിച്ച് സജ്ജമാക്കുക, [റിമോട്ട് മോഡ്](./REMOTE-MODE.md) കാണുക) അല്ലെങ്കിൽ വ്യക്തമായ `--remote <url> --api-key <key>` ഫ്ലാഗുകൾ. താഴെയുള്ള "ലോക്കൽ vs റിമോട്ട്" എന്നതിൻ്റെ അർത്ഥം: ഫ്ലാഗുകളില്ലാതെ അത് `http://localhost:20128` ലക്ഷ്യമിടുന്നു ; `--remote` (അല്ലെങ്കിൽ ഒരു സജീവ വിദൂര സന്ദർഭം) ഉപയോഗിച്ച് ഇത് ആ സെർവറിനെ ബാക്കെൻഡായി ക്രമീകരിക്കുകയും കോൺഫിഗറേഷൻ പ്രാദേശികമായി എഴുതുകയും ചെയ്യുന്നു. കാറ്റലോഗ് അടിസ്ഥാനമാക്കിയുള്ള പാചകക്കുറിപ്പുകളും ആ സെർവറിൽ നിന്ന് മോഡലുകൾ ലഭ്യമാക്കുന്നു.

ഫ്ലാഗുകളെക്കുറിച്ചുള്ള കുറിപ്പുകൾ (കമാൻഡ് ഉറവിടത്തിൽ പരിശോധിച്ചു):

- `--remote <url>` — ഒരു വിദൂര OmniRoute ഉപയോഗിക്കുന്നു ( `--port` ഉം സജീവ സന്ദർഭവും അസാധുവാക്കുന്നു). `--api-key <key>` ആ സെർവറിനുള്ള ക്രെഡൻഷ്യൽ നൽകുന്നു ( `OMNIROUTE_API_KEY` env var, അല്ലെങ്കിൽ സജീവ സന്ദർഭത്തിൻ്റെ ടോക്കണിലേക്ക് സ്ഥിരസ്ഥിതി).
- `--only <patterns>` — കോമയാൽ വേർതിരിച്ച ഉപസ്ട്രിംഗുകൾ; പൊരുത്തപ്പെടുന്ന മോഡൽ IDs മാത്രം സൂക്ഷിക്കുക (ഉദാ `--only glm,kimi`). `setup-codex`, `setup-claude`, `setup-opencode`, `setup-continue`, `setup-cursor`, `setup-crush`, `setup-zed` എന്നിവയിൽ ലഭ്യമാണ്.
- `--dry-run` — ഫയൽസിസ്റ്റം സ്പർശിക്കാതെ കൃത്യമായി എഴുതുന്നത് പ്രിൻ്റ് ചെയ്യുക. എല്ലാ `setup-*` കമാൻഡിലും ലഭ്യമാണ്** ഒഴികെ** `setup-cursor` (ഇത് ഒരിക്കലും ഒരു ഫയൽ എഴുതുന്നില്ല).
- `--model <id>` — ആവശ്യമാണ് (അല്ലെങ്കിൽ സംവേദനാത്മകമായി തിരഞ്ഞെടുത്തത്) മോഡൽ സ്വയമേവ കണ്ടെത്താത്ത ഉപകരണങ്ങൾക്ക്: Cline, കിലോ, Roo, Goose, Qwen, Gemini, Aider, 5dive, WhyCodes. ആ ടൂളുകളും നോൺ-ഇൻ്ററാക്ടീവ് റണ്ണുകൾക്കായി `--yes` സ്വീകരിക്കുന്നു (അതിന് `--model` ആവശ്യമാണ്). ഡിഫോൾട്ട് ടോപ്പ്-ലെവൽ മോഡൽ സജ്ജമാക്കാൻ `setup-opencode` `--model` എടുക്കുന്നു.
- `omniroute run` ലെ`--model <id>` മാനിഫെസ്റ്റിൻ്റെ ഓരോ ടാർഗെറ്റ് വയറിംഗ് (`bin/cli/cli-manifest.mjs`) പിന്തുടരുന്നു:** സഹായി** `--model openai/<id>` സ്വീകരിക്കുന്നു ഒപ്പം** ഓപ്പൺകോഡ്** `--model omniroute/<id>` (ഐഡി ഇതിനകം അത് വഹിക്കാത്തപ്പോൾ മാത്രമാണ് പ്രിഫിക്സ് ചേർക്കുന്നത്);** qwen** ഒപ്പം** മിഥുനം** ഐഡി പദാനുപദമായി സ്വീകരിക്കുക;** ക്ലോഡ്** `ANTHROPIC_MODEL` വഴി അത് ലഭിക്കുന്നു,** വാത്ത്** `GOOSE_MODEL` വഴി,** എന്തുകൊണ്ട് കോഡുകൾ** `-P omniroute -m <id>` വഴി, ഒപ്പം** കോഡെക്സ്** `-c model_providers.omniroute.*` args വഴി.**Qwen എന്നത് `--model`-ആവശ്യമുള്ള ഏക റൺ ടാർജറ്റ് ആണ്** — `omniroute run qwen` ഇല്ലാതെ `2` ഒരു വ്യക്തമായ പിശകോടെ പുറത്തുകടക്കുന്നു.
- `--port <port>` — ലോക്കൽ OmniRoute പോർട്ട് (ഡിഫോൾട്ട് `20128`, `--remote` സജ്ജമാക്കുമ്പോൾ അവഗണിക്കപ്പെടും). എല്ലാ `setup-*` ലും രണ്ട് ലോഞ്ചറുകളിലും അവതരിപ്പിക്കുക.
- `omniroute run` എക്സിറ്റ് കോഡുകൾ: ചൈൽഡ് CLI യുടെ സ്വന്തം എക്സിറ്റ് കോഡ് പദാനുപദമായി പ്രചരിപ്പിക്കുന്നു; `2` = അസാധുവായ ആർഗ്യുമെൻ്റുകൾ (പിന്തുണയില്ലാത്ത ടാർഗെറ്റ്, ആവശ്യമായ `--model`, കണ്ടെയ്നർ ഗാർഡ് നഷ്ടപ്പെട്ടു); `127` = ടാർഗെറ്റ് ബൈനറി `PATH` ൽ അല്ല; `130`/`143`/`129` വിക്ഷേപണം അവസാനിക്കുമ്പോൾ `SIGINT`/`SIGTERM`/`SIGHUP`; `1` = മറ്റ് റൺടൈം ലോഞ്ച് പരാജയം.
- രണ്ട് ലോഞ്ചറുകൾ (`launch`, `launch-codex`) `setup-claude` / `setup-codex` എഴുതിയ ഒരു പ്രൊഫൈൽ തിരഞ്ഞെടുക്കുന്നതിന് `--profile <name>` സ്വീകരിക്കുന്നു, കൂടാതെ അടിസ്ഥാന `claude` / `codex` ബൈനറിക്ക് പാസ്-ത്രൂ ആർഗുകളും.

സംവേദനാത്മക പിക്കർ സജ്ജീകരണ പാചകക്കുറിപ്പുകളും പങ്കിടുന്നു:

```bash
# Pick from the active local or remote model catalog and configure the target.
omniroute configure claude
omniroute configure opencode --provider glm
omniroute configure qwen --model qwen/qwen3.8-max-preview --yes
omniroute configure gemini
omniroute configure whycodes
```

`configure` currently delegates to the tested recipes for `codex`, `claude`, `opencode`, `qwen`, `gemini`, `aider`, `goose`, `cline`, `continue`, `kilo`, `5dive`, and `whycodes`. IDE-only, MITM, and guide-only catalog entries remain explicit `setup-*`/manual flows and are not presented as launchable targets.

> `setup-opencode` ആണ്** ഭാരം കുറഞ്ഞ ഓപ്പണൈ-അനുയോജ്യമാണ്** OpenCode സംയോജനം. `@omniroute/opencode-plugin` ഇൻസ്റ്റാൾ ചെയ്യുന്ന ഒരു സമ്പന്നമായ പ്ലഗിൻ ഇൻ്റഗ്രേഷൻ — `omniroute setup opencode` — ഉണ്ട്. അവ വ്യത്യസ്ത ആജ്ഞകളാണ്; പ്രമാണങ്ങൾ `setup-opencode` മുകളിലുള്ള പട്ടിക.
>
> പ്ലഗിൻ രണ്ട് പാക്കേജുകളിലാണ് വരുന്നത്, ഓരോ OpenCode മേജറിനും ഒന്ന്, കാരണം രണ്ട് ലോഡറുകൾ വ്യത്യസ്ത എൻട്രി പോയിൻ്റുകൾ പ്രതീക്ഷിക്കുന്നു: OpenCode v1-ന് `@omniroute/opencode-plugin`, OpenCode v2-ന് `@omniroute/opencode-plugin-v2`. v2 പാക്കേജ് പുതിയതാണ് (`0.1.0`) കൂടാതെ ഇപ്പോഴും നീങ്ങിക്കൊണ്ടിരിക്കുന്ന ഒരു ഹോസ്റ്റ് കരാറിനെ പിന്തുടരുന്നു, അതിനാൽ ഇത് OpenCode വിത്തുകൾ കാറ്റലോഗ് ഡ്രാഫ്റ്റിലേക്ക് വായിക്കുന്നു. `opencode.json` യിലേക്ക് ഒരു `plugins` എൻട്രി ചേർത്തുകൊണ്ട് ഇത് ഇൻസ്റ്റാൾ ചെയ്യുക; `omniroute setup opencode` ഇപ്പോഴും v1 പാക്കേജ് ഇൻസ്റ്റാൾ ചെയ്യുന്നു. ഓപ്ഷനുകളും ക്രെഡൻഷ്യൽ ലുക്ക്അപ്പ് ഓർഡറും README പാക്കേജിലുണ്ട്.

## പ്രാദേശിക ഉപയോഗം

`localhost:20128`-ൽ OmniRoute പ്രവർത്തിക്കുന്നുണ്ടെങ്കിൽ, നിങ്ങളുടെ ടൂളിനായുള്ള സജ്ജീകരണ കമാൻഡ് പ്രവർത്തിപ്പിച്ചാൽ മതി. കാറ്റലോഗ് പ്രാദേശിക സെർവറിൽ നിന്ന് ലഭ്യമാക്കും.

```bash
# Codex: പൊരുത്തപ്പെടുന്ന ഓരോ മോഡലിനും ~/.codex/-ലേക്ക് ഒരു പ്രൊഫൈൽ എഴുതുക
omniroute setup-codex
codex --profile glm52            # സൃഷ്ടിച്ച പ്രൊഫൈൽ ഉപയോഗിക്കുക

# Claude Code: ഓരോ മോഡലിനും പ്രത്യേകം പ്രൊഫൈലുകൾ എഴുതിയശേഷം ഒന്ന് സമാരംഭിക്കുക
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode: എല്ലാ കാറ്റലോഗ് മോഡലുകളുമുള്ള openai-അനുയോജ്യ പ്രൊവൈഡർ എഴുതുക
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # {env:OMNIROUTE_API_KEY} വഴി പരാമർശിക്കുന്നു, ഒരിക്കലും ഡിസ്കിൽ സംഭരിക്കില്ല
opencode -m omniroute/glm/glm-5.2 "..."

# സ്വയമേവ കണ്ടെത്തൽ ഇല്ലാത്ത ടൂളുകൾക്ക് ഒരു വ്യക്തമായ മോഡൽ ആവശ്യമാണ്:
omniroute setup-aider --model glm/glm-5.2
omniroute setup-qwen --model qwen/qwen3.8-max-preview

# ഒന്നും എഴുതാതെ പ്രിവ്യൂ ചെയ്യുക:
omniroute setup-continue --dry-run
```

ഒരു കോൺഫിഗും എഴുതാതെ സമാരംഭിക്കുക (env ഇൻജക്ഷൻ മാത്രം):

```bash
omniroute launch                 # Claude Code → പ്രാദേശിക OmniRoute
omniroute launch-codex           # Codex CLI → പ്രാദേശിക OmniRoute
omniroute launch-codex --profile glm52
omniroute run claude --model openai/gpt-5.4
omniroute run codex --model openai/gpt-5.4 --dry-run --json
omniroute run aider --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# വ്യക്തമായ കമാൻഡ് പാത: --ന് ശേഷം വരുന്നതെന്തും അതേപടി കൈമാറുക
omniroute run claude -- --print-system-prompt "review this diff"
```

## വിദൂര ഉപയോഗം

`--remote` + `--api-key` ഉപയോഗിച്ച് ഏതൊരു സജ്ജീകരണ കമാൻഡിനെയും ഒരു വിദൂര OmniRoute-ലേക്ക് ചൂണ്ടുക. കാറ്റലോഗ് വിദൂര സിസ്റ്റത്തിൽ നിന്ന് ലഭ്യമാക്കും; കോൺഫിഗ് നിങ്ങളുടെ പ്രാദേശിക മെഷീനിലാണ് എഴുതുക.

```bash
# ഒരു വിദൂര VPS-നെതിരെ OpenCode ഉപയോഗിക്കുക, glm/kimi മോഡലുകൾ മാത്രം നിലനിർത്തുക
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx \
  --only glm,kimi
opencode -m omniroute/glm/glm-5.2 "..."   # ആദ്യം OMNIROUTE_API_KEY എക്സ്പോർട്ട് ചെയ്യുക

# ഒരു വിദൂര കാറ്റലോഗിൽ നിന്നുള്ള Codex പ്രൊഫൈലുകൾ
omniroute setup-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# വിദൂര സിസ്റ്റത്തിനെതിരെ നേരിട്ട് ഒരു CLI സമാരംഭിക്കുക
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

ഓരോ തവണയും `--remote`/`--api-key` നൽകുന്നതിനുപകരം, ഒരിക്കൽ ലോഗിൻ ചെയ്ത് **സജീവ കോൺടെക്സ്റ്റ്** അവ സ്വയമേവ നൽകാൻ അനുവദിക്കുക:

```bash
omniroute connect 192.168.0.15        # പരിധിയിട്ട ടോക്കൺ സൃഷ്ടിച്ച് കോൺടെക്സ്റ്റ് സംഭരിക്കുന്നു
omniroute setup-codex                 # ← ഇപ്പോൾ വിദൂര കാറ്റലോഗ് ഉപയോഗിക്കുന്നു
omniroute setup-opencode              # ← ഇതും അതുപോലെ
omniroute launch                      # ← വിദൂര സിസ്റ്റത്തിനെതിരെ Claude Code
```

കോൺടെക്സ്റ്റുകൾ, സ്കോപ്പുകൾ, ടോക്കൺ മാനേജ്മെന്റ് എന്നിവയ്ക്കായി [വിദൂര മോഡ്](./REMOTE-MODE.md) കാണുക.

## 5 ഡൈവ് ഏജൻ്റ് ഫ്ലീറ്റുകൾ

[5dive](https://5dive.ai) ദീർഘകാലമായി പ്രവർത്തിക്കുന്ന കോഡിംഗ് ഏജൻ്റുമാരുടെ ഒരു കൂട്ടം പ്രവർത്തിക്കുന്നു, ഓരോന്നും സ്വന്തം Unix ഉപയോക്താവിന് കീഴിലുള്ള systemd യൂണിറ്റാണ്. ഇതൊരു കോഡിംഗ് CLI അല്ല, അതിനാൽ `omniroute run` — `5dive` സമാരംഭിക്കാൻ ഒന്നുമില്ല** കോൺഫിഗർ-മാത്രം** ലക്ഷ്യം.

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

രണ്ട് ഫോമുകളും ഒരു 5 ഡൈവ് എഴുതുന്നു** auth പ്രൊഫൈൽ** , ആ പ്രൊഫൈലുമായി ബന്ധിപ്പിച്ചിരിക്കുന്ന ഓരോ `claude` സീറ്റും പിന്നീട് OmniRoute യുമായി സംസാരിക്കുന്നു. ഈ ലക്ഷ്യത്തിന് മൂന്ന് കാര്യങ്ങൾ പ്രത്യേകമാണ്:

- **ഇത് ഫ്ലീറ്റ് ഹോസ്റ്റിൽ റൂട്ട് ആയി പ്രവർത്തിക്കുന്നു.** 5dive ൻ്റെ ക്രിയകൾ ലോക്കൽ systemd യൂണിറ്റുകളിലും ഒരു റൂട്ടിൻ്റെ ഉടമസ്ഥതയിലുള്ള സ്റ്റേറ്റ് ഡിറിലും പ്രവർത്തിക്കുന്നു; റിമോട്ട് മോഡ് ഇല്ല. ഇതിനകം റൂട്ട് അല്ലാത്തപ്പോൾ പാചകക്കുറിപ്പ് `sudo` വഴി വീണ്ടും നടപ്പിലാക്കുന്നു (`--no-sudo` അത് ഓഫാക്കി പകരം കമാൻഡ് പ്രിൻ്റ് ചെയ്യുന്നു).
- **ലൂപ്പ്ബാക്ക് അല്ലാത്തപക്ഷം അവസാന പോയിൻ്റ് `https://` ആയിരിക്കണം.** ഏജൻ്റിൻ്റെ API കീ ഓരോ അഭ്യർത്ഥനയിലും URL റൈഡ് ചെയ്യുന്നു, കൂടാതെ 5dive ഒരു പ്ലെയിൻ ടെക്സ്റ്റ് ഓഫ്-ബോക്സ് എൻഡ്പോയിൻ്റ് നിരസിക്കുന്നു. ഒരു സ്വകാര്യ LAN വിലാസം ഒരു അപവാദമല്ല.
- **ഓരോ സീറ്റിൻ്റെയും സ്വന്തം മോഡൽ പിൻ പ്രൊഫൈലിനെ മറികടക്കുന്നു.** പ്രൊഫൈലിൽ `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` ഉണ്ട്, എന്നാൽ ഒരു സ്റ്റോക്ക് മോഡൽ ഐഡിയിലേക്ക് പിൻ ചെയ്തിരിക്കുന്ന സീറ്റ് _"തിരഞ്ഞെടുത്ത മോഡലിൽ ഒരു പ്രശ്നമുണ്ട്"_ എന്നതിനൊപ്പം അതിൻ്റെ ആദ്യ ടേൺ പരാജയപ്പെടുന്നു. സീറ്റുകളും പിൻ ചെയ്യാൻ `--agent <name>` (ആവർത്തിക്കാവുന്നത്) കടന്നുപോകുക; നിങ്ങൾ ചെയ്യാത്തപ്പോൾ പാചകക്കുറിപ്പ് കമാൻഡ് പ്രിൻ്റ് ചെയ്യുന്നു.

API താക്കോൽ 5dive-ന് കൈമാറുന്നു** stdin** (`--api-key=-`), അതിനാൽ ഇത് ഒരിക്കലും `ps` ഔട്ട്പുട്ടിൽ ദൃശ്യമാകില്ല.

പ്രൊഫൈൽ ഒരു OmniRoute ലേക്ക് ചൂണ്ടിക്കാണിക്കുന്നു** കോംബോ** ഒരൊറ്റ മോഡൽ എന്നതിലുപരി ഫ്ലീറ്റ് പ്രൊവൈഡർ പരാജയപ്പെടാൻ ഇടയാക്കുന്നു: [#11578](https://github.com/cheaper-inference/OmniRoute/issues/11578) ൽ രേഖപ്പെടുത്തിയിരിക്കുന്ന ഓട്ടത്തിൽ പ്രൈമറി എൻഡ്പോയിൻ്റ് ഹാർഡ്-ഡൌൺ മിഡ്-ടേൺ ആയപ്പോൾ, ഏജൻ്റ് അതിൻ്റെ ശേഷിക്കുന്ന ഘട്ടങ്ങൾ ഫാൾബാക്കിൽ പൂർത്തിയാക്കി, ഒരിക്കലും മുടക്കം വരുത്തിയില്ല.

## അടിസ്ഥാന URL കൺവെൻഷനുകൾ (ഏത് ഉപകരണങ്ങൾക്ക് `/v1` ആവശ്യമാണ്)

| `setup-5dive` (ഓത്ത് പ്രൊഫൈലിൽ `ANTHROPIC_BASE_URL` )                      | റൂട്ട്                         | ഇല്ല — Claude കോഡ് `/v1/messages` ചേർക്കുന്നു             |

## അപ്ഡേറ്റിൽ നേറ്റീവ് ഡിപെൻഡൻസികൾ നിലനിർത്തൽ: `--include=optional`

`omniroute update` ഉപയോഗിച്ച് അപ്ഡേറ്റ് ചെയ്യുമ്പോൾ (സ്ഥിരീകരിച്ചതിന് ശേഷം, അല്ലെങ്കിൽ `--apply`
ഉപയോഗിച്ച്), OmniRoute ഇൻസ്റ്റലേഷൻ കമാൻഡിൽ `--include=optional` സ്വതവേ ഉൾപ്പെടുത്തുന്നു:

```bash
npm install -g omniroute@latest --include=optional
```

ഇത് `omniroute update`-ലേക്ക് നിങ്ങൾ നൽകേണ്ട ഫ്ലാഗ് **അല്ല** — അപ്ഡേറ്റർ
എല്ലായ്പ്പോഴും ഇത് പ്രയോഗിക്കുന്നു. നിങ്ങളുടെ npm കോൺഫിഗിൽ `omit=optional`
സജ്ജീകരിച്ചിട്ടുണ്ടെങ്കിലും `optionalDependencies` (`better-sqlite3`, `keytar`,
`tls-client`, LLMLingua SLM സ്റ്റാക്ക്) അപ്ഡേറ്റിന് ശേഷവും നിലനിൽക്കുമെന്ന് ഇത്
ഉറപ്പാക്കുന്നു; അല്ലാത്തപക്ഷം നേറ്റീവ് SQLite ഡ്രൈവറും OS-keyring ബൈൻഡിങ്ങും
യാതൊരു മുന്നറിയിപ്പുമില്ലാതെ ഒഴിവാക്കപ്പെടും. പ്രയോഗിക്കാതെ കൃത്യമായ കമാൻഡ് പ്രിവ്യൂ ചെയ്യാൻ:

```bash
omniroute update --dry-run
# [ഡ്രൈ റൺ] പ്രവർത്തിപ്പിക്കുമായിരുന്ന കമാൻഡ്: npm install -g omniroute@latest --include=optional
```

മറ്റ് `omniroute update` ഫ്ലാഗുകൾ (സോഴ്സിൽ സ്ഥിരീകരിച്ചത്): `--check` (കാലഹരണപ്പെട്ടതാണെങ്കിൽ
exit 1), `--apply` (ചോദിക്കാതെ ഇൻസ്റ്റാൾ ചെയ്യുക), `--changelog`, `--no-backup`,
`--yes`.

## `omniroute run gemini` വഴി Google Gemini CLI

`@google/gemini-cli` 0.50.0-നോട് പരിശോധിച്ച് സ്ഥിരീകരിച്ച കരാർ: CLI
`GOOGLE_GEMINI_BASE_URL` മാനിക്കുകയും അതിനെതിരെ
`POST /v1beta/models/<model>:generateContent` (കൂടാതെ
`:streamGenerateContent?alt=sse`) അഭ്യർത്ഥനകൾ നടത്തുകയും ചെയ്യുന്നു — കൃത്യമായി OmniRoute-ന്റെ
നേറ്റീവ് Gemini ഇന്റർഫേസ് (`/v1beta`). `omniroute run gemini` അത് സ്വയമേവ ക്രമീകരിക്കുന്നു:

- `GOOGLE_GEMINI_BASE_URL` → സജീവമായ OmniRoute അടിസ്ഥാന URL (റൂട്ട്, `/v1` ഇല്ലാതെ);
- `GEMINI_API_KEY` → കണ്ടെത്തിയ OmniRoute ക്രെഡൻഷ്യൽ (ഓപ്ഷൻ/env/കോൺടെക്സ്റ്റ്);
- Google OAuth സെഷൻ (Code Assist) സംഭരിച്ചിട്ടുണ്ടെങ്കിലും OmniRoute-ലേക്ക്
  നയിക്കുന്ന ലോഞ്ചിനെ ഒരിക്കലും അസാധുവാക്കാതിരിക്കാൻ, അതിന്റെ `.gemini/settings.json`
  `gemini-api-key` ഓത്ത് തിരഞ്ഞെടുക്കുന്ന ഒരു **താൽക്കാലികവും ഒറ്റപ്പെട്ടതുമായ `GEMINI_CLI_HOME`** —
  എക്സിറ്റിന് ശേഷം നീക്കംചെയ്യപ്പെടുന്നു;
- **env ശുചിത്വം**: ചൈൽഡ് env-ൽനിന്ന് `GOOGLE_API_KEY`,
  `GOOGLE_GENAI_USE_VERTEXAI`, `GOOGLE_GENAI_USE_GCA` എന്നിവ നീക്കംചെയ്യുന്നു (ഇവ ഓത്തിനെ
  Vertex/Code Assist-ലേക്ക് തിരിച്ചുവിടും), കൂടാതെ അധിക സുരക്ഷയ്ക്കായി
  `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key` സജ്ജീകരിക്കുന്നു — മറ്റ് `run` ടാർഗെറ്റുകൾക്കും
  അവയുടെ പരസ്പരവിരുദ്ധ വേരിയബിളുകളിൽ ഇതേ പരിചരണം ലഭിക്കുന്നു;
- `--provider`/`--model`-ൽനിന്നുള്ള `--model <id>` ഇൻജക്ഷൻ.

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

ഹെഡ്ലെസ് മോഡിലും Gemini-യുടെ വർക്ക്സ്പേസ്-ട്രസ്റ്റ് ഗാർഡ് ബാധകമാണ് — സ്വയം
`--skip-trust` നൽകുക (അല്ലെങ്കിൽ ഡയറക്ടറിയെ ഇന്ററാക്ടീവായി വിശ്വസിക്കുക);
ലോഞ്ചർ മനഃപൂർവം അതിനെ മറികടക്കുന്നില്ല. ഈ ലോഞ്ചർ **ACP
രജിസ്ട്രേഷനിൽനിന്ന്** (`src/lib/acp/registry.ts`, `gemini --acp`) വ്യത്യസ്തമാണ്; അത്
`/dashboard/acp-agents`-നുള്ള ഏജന്റ്-പ്രോട്ടോക്കോൾ ഇന്റഗ്രേഷനായി തുടരുന്നു.

## യഥാർത്ഥ സ്മോക്ക് സ്വീപ്പ് (ഓപ്റ്റ്-ഇൻ)

നിർണായകമായ ലോഞ്ച്-പ്ലാൻ റിഗ്രഷൻ CI-യിൽ പ്രവർത്തിക്കുന്നു (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`). ഒരു യഥാർത്ഥ OmniRoute സെർവറിനെതിരെ യഥാർത്ഥ
ബൈനറികൾ സാധൂകരിക്കുന്നതിന്, ഓപ്റ്റ്-ഇൻ ഹാർനെസ്
`tests/integration/upstream-cli-smoke.int.test.ts` എന്നതിൽ ലഭ്യമാണ്. ഇത് ഒരിക്കലും സ്വയമേവ പ്രവർത്തിക്കില്ല
(`RUN_CLI_SMOKE=1` നൽകിയിട്ടില്ലെങ്കിൽ ഓരോ ഉപ-ടെസ്റ്റും ഒഴിവാക്കപ്പെടും), ക്രെഡൻഷ്യൽ അതിന്റെ മൂല്യമായല്ല,
env-var NAME ആയാണ് കൈമാറുന്നത്, രേഖപ്പെടുത്തിയ ഏതൊരു ഔട്ട്പുട്ടിൽനിന്നും കീയുടെ രൂപത്തിലുള്ള സ്ട്രിങ്ങുകൾ മറയ്ക്കുന്നു,
ബൈനറി ഇൻസ്റ്റാൾ ചെയ്തിട്ടില്ലാത്ത ടാർഗെറ്റുകൾ ഒഴിവാക്കുന്നു, കൂടാതെ പരാജയങ്ങളെ വെറും ബൂളിയൻ മൂല്യത്തിന് പകരം
auth / upstream / config എന്നിങ്ങനെ വർഗ്ഗീകരിക്കുന്നു:

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

ഐച്ഛികം: `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` സ്വീപ്പിനെ നിർദ്ദിഷ്ട ടാർഗെറ്റുകളിലേക്ക് പരിമിതപ്പെടുത്തുന്നു;
`OMNIROUTE_SMOKE_TIMEOUT_MS` ഓരോ ടാർഗെറ്റിനുമുള്ള 120s സമയപരിധിയെ അസാധുവാക്കി മറ്റൊരു മൂല്യം സജ്ജമാക്കുന്നു.
