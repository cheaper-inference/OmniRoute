## 1. കാര്യങ്ങൾ സ്ഥിതിചെയ്യുന്നിടം

- **കിറ്റ്.** `packages/ui-kit/src` എന്നത് `packages/ui-kit/UPSTREAM.md`-ൽ പിൻ ചെയ്തിരിക്കുന്ന commit-ലുള്ള upstream `src/`-ന്റെ byte-for-byte പകർപ്പാണ് (അവിടെ ലൈസൻസ് അനുമതിയും രേഖപ്പെടുത്തിയിട്ടുണ്ട്); പ്രാദേശിക patches `PATCHES.md` പട്ടികപ്പെടുത്തുന്നു (ഒന്നുമില്ല). ഇത് source ആയി ഉപയോഗിക്കുന്നു, build ഇല്ല: `next.config.mjs` ഇത് transpile ചെയ്യുന്നു, കൂടാതെ `tsconfig.json` `@omniroute/ui-kit` → `packages/ui-kit/src`, `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` എന്നിങ്ങനെ map ചെയ്യുന്നു (`vitest.config.ts`-ലും `vitest.mcp.config.ts`-ലും ഇതേ alias ഉണ്ട്). Kit component അതിന്റെ subpath വഴി (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) import ചെയ്യുക; `@omniroute/ui-kit` barrel വഴി ഒരിക്കലും ചെയ്യരുത്: barrel ഓരോ importer-ലേക്കും എല്ലാ components-ഉം (date picker ഉൾപ്പെടെ) വലിച്ചുകൊണ്ടുവരുന്നു. Kit stylesheet `src/app/globals.css` വഴിയാണ് ഉൾപ്പെടുന്നത് (`@import "../../packages/ui-kit/src/ci-styles.css"`, പൂർണ്ണ stylesheet: core `ci-ui.css`-യും എല്ലാ pattern family-കളും).
- **ടോക്കണുകൾ.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` tokens പ്രഖ്യാപിക്കുന്നു; `src/app/globals.css` അവയെ legacy OmniRoute പേരുകളിലേക്ക് (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) bridge ചെയ്യുന്നു, അതിനാൽ നിലവിലുള്ള `var(--color-*)` reads-ഉം Tailwind utilities-ഉം പ്രവർത്തിച്ചുകൊണ്ടിരിക്കും. പുതിയ code Tailwind utilities (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) അല്ലെങ്കിൽ kit classes ഉപയോഗിക്കണം — ഒരിക്കലും hex value ഉപയോഗിക്കരുത് (`tests/unit/design-kit-bridge.test.ts` bridge നിർബന്ധിതമാക്കുന്നു). `text-primary` `--text-color-primary` വഴി `--color-primary-ink`-ലേക്ക് resolve ചെയ്യുന്നു; അതിനാൽ primary text വായിക്കാനാകുന്ന നിലയിൽ തുടരും, അതേസമയം `bg-primary`/`border-primary` accent surface നിലനിർത്തുന്നു: Editions-ൽ ഇത് kit-ന്റെ `--ci-color-accent-active` ആണ് (light-ൽ ആഴമുള്ള copper `#99562f`, dark-ൽ copper accent); Classic-ൽ light-ൽ lime-800-ഉം dark-ൽ lime accent-ഉം ആണ്. Chart series-കൾ `--color-chart-1` … `--color-chart-8` ഉപയോഗിക്കുന്നു; ഓരോന്നിനും text-safe ആയ `--color-chart-N-ink`-ഉം opaque ആയ `--color-chart-N-subtle` chip tint-ഉം ഉണ്ട്, kit series order (`ciChartSeriesOrder`) അനുസരിച്ചാണ് assignment.
- **തീമുകൾ.** `<html className="ci-theme">` (`src/app/layout.tsx`) document-നെ kit theme-ലേക്ക് opt ചെയ്യുന്നു. Preference `light`, `dark` അല്ലെങ്കിൽ `system` ആണ് (`src/shared/constants/appConfig.ts`-ലെ `THEME_CONFIG.defaultTheme = "system"`); `system`, `prefers-color-scheme` പിന്തുടരുന്നു. `src/store/themeStore.ts`-ലെ `applyTheme()` (`src/app/layout.tsx`-ൽ inline ചെയ്തിരിക്കുന്ന, hydration-ന് മുമ്പ് പ്രവർത്തിക്കുന്ന `THEME_BOOT_SCRIPT` ഇതിനെ mirror ചെയ്യുന്നു) `data-theme="dark"|"light"` സജ്ജമാക്കുകയും `<html>`-ലെ `.dark` class ഒരുമിച്ച് toggle ചെയ്യുകയും ചെയ്യുന്നു. Kit-ന്റെ dark token set `data-theme="dark"` അടിസ്ഥാനമാക്കിയാണ് (`packages/ui-kit/src/ci-tokens.css`); OmniRoute-ന്റെ സ്വന്തം dark overrides (`globals.css`-ലെ `.dark` block), legacy Tailwind `dark:` utilities എന്നിവ `.dark` class അടിസ്ഥാനമാക്കിയാണ് പ്രവർത്തിക്കുന്നത്. Accent color presets ഇല്ല: accent എല്ലായ്പ്പോഴും kit-ൽ നിന്നാണ് വരുന്നത്, പഴയ build-ൽ നിന്നുള്ള persisted preset store load ചെയ്യുമ്പോൾ നീക്കംചെയ്യുന്നു.
- **പാലറ്റുകൾ.** രണ്ടെണ്ണം, രണ്ടും kit-ൽ നിന്നുള്ളവ (`src/shared/constants/appearancePalette.ts`): default ആയ `editions`, `classic`. Editions എന്നത് `<html>`-ലെ kit-ന്റെ `data-ci-appearance="editions"` attribute ആണ്; `ci-editions.css` (`ci-ui.css` import ചെയ്യുന്നത്) ഇത് `data-theme`-നൊപ്പം combine ചെയ്യുന്നു. Classic എന്നത് attribute ഇല്ലാത്ത അവസ്ഥയാണ്. Root layout attribute server-render ചെയ്യുന്നു; അതിനാൽ ഒന്നും stored ചെയ്തിട്ടില്ലാത്ത (അല്ലെങ്കിൽ JS ഇല്ലാത്ത) visitor-ന് dashboard, login, `/status`, error pages, `/docs`, PWA എന്നിവയുൾപ്പെടെ എല്ലാ surfaces-ലും Editions ലഭിക്കും. Choice, theme-നൊപ്പം അതേ `theme` store-ൽ (`palette`, `setPalette()`, `applyPalette()` എന്നിവ `src/store/themeStore.ts`-ൽ) persisted ചെയ്യുന്നു; `THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`, layout-ന്റെ `<head>`-ൽ inline ചെയ്തിരിക്കുന്നത്) paint-ന് മുമ്പ് ഇത് പ്രയോഗിക്കുന്നു. Stored palette `"classic"` ആയിരിക്കുമ്പോൾ മാത്രമാണ് attribute നീക്കംചെയ്യുന്നത്; root layout-ന് പുറത്തുള്ള `src/app/global-error.tsx` ഇതേ store-ൽ നിന്ന് ഇത് പ്രയോഗിക്കുന്നു. മറ്റേതെങ്കിലും element-ൽ `data-ci-appearance` ഇടരുത്: kit ഇത് `html:root:has([data-ci-appearance="editions"])` ഉപയോഗിച്ച് match ചെയ്യുന്നതിനാൽ, ഒരു descendant പോലും മുഴുവൻ document-ും switch ചെയ്യും. Editions `data-ci-editions-variant="landing"` variant marketing pages-നുള്ളതാണ്, dashboard-നുള്ളതല്ല. Browser chrome: server default ആയ Editions-നെ `viewport.themeColor`-ലും (ഓരോ `prefers-color-scheme`-നും ഓരോ tag) web manifest-ലും render ചെയ്യുന്നു — `src/shared/constants/pwaThemeColors.ts`-ലെ `PWA_THEME_COLORS`, Editions `--ci-color-background` (`#f3f1e9` / `#11120f`)-ന്റെ ഏക mirror, `tests/unit/pwa-theme-colors.test.ts` വഴി `ci-editions.css`-ലേക്ക് pinned ആണ്. തുടർന്ന് live `<meta name="theme-color">` stored palette-യും mode-ഉം പിന്തുടരുന്നു: `THEME_BOOT_SCRIPT` paint-ന് മുമ്പ് tags rewrite ചെയ്യുന്നു, കൂടാതെ theme store-ന്റെ actions ഓരോ മാറ്റത്തിലും ഇത് ചെയ്യുന്നു (`src/shared/utils/themeColorMeta.ts`-ലെ `resolveThemeColor()` / `applyThemeColor()`, kit-ന്റെ `ciTokens`-ൽ നിന്ന് വായിക്കുന്ന `CLASSIC_PAGE_BACKGROUND` സഹിതം). Explicit light/dark theme എല്ലാ tags-വും ആ mode-ലേക്ക് സജ്ജമാക്കുന്നു; `system` ഓരോ scheme-നും ഓരോ നിറം നിലനിർത്തുന്നു. Manifest Editions ആയി തുടരുന്നു: preference ഇല്ലാതെ ഓരോ install-ലും ഒരിക്കൽ മാത്രമാണ് ഇത് fetch ചെയ്യുന്നത്. Monaco അതിന്റെ നിറങ്ങൾ ഒരു probe-ൽ നിന്ന് വായിക്കുന്നു (`monacoKitTheme.ts`); Editions-ൽ probe read നടക്കുന്ന ഒരു synchronous pass-ിനായി root `data-theme` flip ചെയ്യുന്നു, കാരണം kit root-ൽ നിന്ന് Editions light/dark resolve ചെയ്യുന്നു.

## 2. നിയമങ്ങൾ

   പാലറ്റിന്റെ പരിഹരിച്ച-ഹെക്സ് മിറർ. കാറ്റഗറിക്കൽ പാലറ്റുകൾ ഇനി ഒഴിവാക്കലല്ല:

## 5. കിറ്റ് അപ്ഡേറ്റ് ചെയ്യുന്നു

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` ൽ പിൻ ചെയ്തിരിക്കുന്ന പതിപ്പിനെ അപ്സ്ട്രീം റിപ്പോയുടെ ഏറ്റവും പുതിയ `v*` ടാഗുമായി താരതമ്യം ചെയ്യുകയും ഒരു റിലീസ് കഴിയുമ്പോൾ സമന്വയ കമാൻഡ് പ്രിൻ്റ് ചെയ്യുകയും ചെയ്യുന്നു.

പ്രതിദിന `UI Kit upstream watch` വർക്ക്ഫ്ലോ (`.github/workflows/ui-kit-upstream-watch.yml`) സമാന പരിശോധന നടത്തുന്നു. പിൻ പിന്നിലായിരിക്കുമ്പോൾ, റോളിംഗ് ബ്രാഞ്ചിൽ `chore/ui-kit-sync-latest` ഉയർന്ന `release/vX.Y.Z` ശാഖയ്ക്കെതിരെ `scripts/ci/ui-kit-sync-pr.sh` ഒരു സമന്വയ PR തുറന്നിടുന്നു. ഇത് ഒരിക്കലും ലയിക്കുന്നില്ല: ഓരോ കിറ്റ് റിലീസിനും ഇപ്പോഴും ലോക്കൽ VPS ൽ ഒരു ദൃശ്യ പരിശോധന ആവശ്യമാണ്. ഒരു പുതിയ പതിപ്പ് പുറത്തിറങ്ങുമ്പോൾ ബ്രാഞ്ച് പുനർനിർമ്മിക്കപ്പെടുകയും അല്ലാത്തപക്ഷം തനിച്ചായിരിക്കുകയും ചെയ്യുന്നു. കൈകൊണ്ട് പുഷ് ചെയ്ത കമ്മിറ്റുകളുള്ള ഒരു ഓപ്പൺ PR പുനരാലേഖനം ചെയ്യപ്പെടുന്നില്ല, കൂടാതെ ഒരു മെയിൻ്റനർ അടച്ച പതിപ്പിനുള്ള PR ഒരു പുതിയ റിലീസ് വരെ അടച്ചിരിക്കും.

ഒരു PR തുറക്കാൻ കഴിയാത്തപ്പോൾ (ടാർഗെറ്റ് റിലീസ് ഫ്രീസുചെയ്തിരിക്കുന്നു, PR കൈകൊണ്ട് പുഷ് ചെയ്തിരിക്കുന്നു, PR അടച്ചു, അല്ലെങ്കിൽ PR ടോക്കൺ സജ്ജീകരിച്ചിട്ടില്ല) വർക്ക്ഫ്ലോ ഒരു ട്രാക്കിംഗ് പ്രശ്നം തുറന്ന് സൂക്ഷിക്കുന്നു, അത് എന്തുകൊണ്ടെന്ന് പറയുന്നു.

വർക്ക്ഫ്ലോ രണ്ട് രഹസ്യങ്ങൾ ഉപയോഗിക്കുന്നു:

- `secrets.UI_KIT_READ_TOKEN`: സ്വകാര്യ അപ്സ്ട്രീം റിപ്പോയ്ക്കായി ഒരു വായന-മാത്രം ടോക്കൺ. വർക്ക്ഫ്ലോയ്ക്ക് അപ്സ്ട്രീം വായിക്കാൻ കഴിയാതെ വരുമ്പോൾ (ടോക്കൺ ഇല്ല, ജോലി നിർത്തിയ ടോക്കൺ, അല്ലെങ്കിൽ GitHub ലഭ്യമല്ല) റൺ പച്ചയായി തുടരുന്നു, പക്ഷേ ഒരു മുന്നറിയിപ്പ് എഴുതുകയും ഒരു പ്രത്യേക പ്രശ്നം തുറന്ന് സൂക്ഷിക്കുകയും ചെയ്യുന്നു, അത് ഒരിക്കൽ അടച്ചാൽ പിന്നീടുള്ള ഓട്ടത്തിന് വീണ്ടും അപ്സ്ട്രീം വായിക്കാൻ കഴിയും.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: ഈ ശേഖരത്തിൽ ഉള്ളടക്കവും പുൾ അഭ്യർത്ഥനകളും റൈറ്റ് ആക്സസ് ഉള്ള ഒരു സൂക്ഷ്മമായ ടോക്കൺ. സ്ഥിരസ്ഥിതി `GITHUB_TOKEN` ഇവിടെ PRs സൃഷ്ടിക്കാൻ കഴിയില്ല, കൂടാതെ അത് തുറന്ന ഒരു PR CI ട്രിഗർ ചെയ്യില്ല. ഈ ടോക്കൺ ഇല്ലാതെ വർക്ക്ഫ്ലോ ശാഖയെ മാത്രം തള്ളുന്നു.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` ആ കമ്മിറ്റിലെ അപ്സ്ട്രീം `src/` (`latest` = ഏറ്റവും പുതിയ `v*` ടാഗ്) `packages/ui-kit/src` ലേക്ക് പകർത്തുന്നു, അനുവദനീയമായ ഒറ്റ പരിവർത്തനം പ്രയോഗിക്കുന്നു (അത് ആപേക്ഷിക ഇറക്കുമതികളിൽ നിന്ന് `.js` സഫിക്സ് ഒഴിവാക്കുന്നു), കൂടാതെ `packages/ui-kit/package.json`, `package-lock.json` എന്നിവയിലെ വർക്ക്സ്പെയ്സ് പതിപ്പ് അപ്സ്ട്രീം ഒന്നിലേക്ക് സജ്ജമാക്കുന്നു. തുടർന്ന്: `git diff packages/ui-kit` അവലോകനം ചെയ്യുക, ദാതാക്കൾ, ക്രമീകരണങ്ങൾ, കോമ്പോകൾ, ഉപയോഗം, എൻഡ്പോയിൻ്റ് എന്നിവയിൽ രണ്ട് തീമുകളിലും ഒരു വിഷ്വൽ പാസ് ചെയ്യുക, `npm run check:ui-kit-snapshot`, `npm run test:vitest:ui` എന്നിവ പ്രവർത്തിപ്പിക്കുക, കൂടാതെ അപ്സ്ട്രീം ചേഞ്ച്ലോഗ് ഉപയോഗിച്ച് PR തുറക്കുക.

## 6. README ഡയഗ്രാമുകൾ

റൂട്ട് `README.md` ഉൾക്കൊള്ളുന്ന പന്ത്രണ്ട് ഡയഗ്രാമുകൾ (`docs/diagrams/*.svg`) സ്റ്റാറ്റിക്
ചിത്രത്തിൽ പ്രയോഗിച്ച കിറ്റാണ്; അവ കൈകൊണ്ട് വരച്ചതല്ല, ജനറേറ്റ് ചെയ്തവയാണ്: പന്ത്രണ്ട് ഡയഗ്രാമുകൾക്കും
`gen-readme-diagrams.mjs` ഡ്രൈവറിനുമായി `scripts/docs/gen-readme-*.mjs` എന്ന 13 ജനറേറ്റർ ഫയലുകളും,
ഓരോ ഡയഗ്രാമിനും ഒന്നായി `tests/unit/docs/readme-*-svg.test.ts` എന്ന 12 staleness ടെസ്റ്റുകളും ഉണ്ട്.
ഓരോ ടെസ്റ്റും കമ്മിറ്റ് ചെയ്ത ഫയലിനെ അതിന്റെ ജനറേറ്ററിന്റെ ഔട്ട്പുട്ടുമായി ഓരോ ബൈറ്റും താരതമ്യം ചെയ്യുന്നു
(`test-unit` ജോബ്).

- **ടോക്കണുകൾ.** `scripts/docs/readme-diagram-theme.mjs` Editions പാലറ്റ് (ഡിഫോൾട്ട് രൂപഭാവം)
  `packages/ui-kit/src/ci-editions.css`-ൽ നിന്ന് പകർത്തുന്നു. ഈ ഫയലിനെ
  `tests/unit/docs/readme-diagram-theme.test.ts` പിൻ ചെയ്യുകയും, രണ്ട് സ്കീമുകളിലുമുള്ള എല്ലാ
  ഉപരിതലങ്ങളിലെ ഓരോ ടെക്സ്റ്റ് നിറത്തിനും WCAG AA പരിശോധിക്കുകയും ചെയ്യുന്നു; ഏക അപവാദം, ലൈറ്റ്
  `warn` ആണ്. കിറ്റിന്റെ മൂല്യം കാൻവാസിൽ 4.46:1 ആയതിനാൽ അത് കിറ്റിലെ warning-നെ 10% ഇരുണ്ടതാക്കിയതാണ്.
  ഈ ഫയൽ കിറ്റിന്റെ ടൈപ്പ് സ്കെയിലായ `ci-tokens.css`-ൽ ടെക്സ്റ്റ് റോളുകളും നിർവചിക്കുന്നു:
  എല്ലാത്തിനും Switzer-ന്റെ കിറ്റ് ഭാരങ്ങൾ (400/500/600, display-ന് 500), tracking എന്നിവയും,
  കോഡ് റോളുകൾ (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`) ഒഴികെ.
  കോഡ് റോളുകൾ IBM Plex Mono ആണ്; അവ കമാൻഡുകൾ, URL-കൾ, ഐഡന്റിഫയറുകൾ, ടെർമിനൽ സ്ക്രീനുകൾ
  എന്നിവയ്ക്കായി മാത്രം ഉപയോഗിക്കുന്നു.
  ലൈറ്റ് മൂല്യങ്ങൾ `:root`-ലും, ഡാർക്ക് മൂല്യങ്ങൾ ഫയലിനുള്ളിലെ
  `prefers-color-scheme: dark`-ന് പിന്നിലും സ്ഥിതിചെയ്യുന്നു; അതിനാൽ GitHub-ലെ കാണുന്നയാളുടെ
  സ്കീമിനെ ഓരോ ചിത്രവും പിന്തുടരും.
- **ഫോണ്ടുകൾ.** GitHub Markdown CSS കൈമാറുന്നില്ല, കൂടാതെ camo proxy എല്ലാ ബാഹ്യ fetch-കളും
  തടയുന്നു. അതിനാൽ കിറ്റിന്റെ ടൈപ്പ് ഫയലിനുള്ളിൽ തന്നെ ഉൾക്കൊള്ളണം.
  എല്ലാ ജനറേറ്ററുകളുടെയും അവസാന ഘട്ടമായ `scripts/docs/readme-outline.mjs`, HarfBuzz ഉപയോഗിച്ച്
  Switzer റോളുകൾ രൂപപ്പെടുത്തി അവയെ വെക്റ്റർ ഔട്ട്ലൈനുകളായി (`<defs>` paths, `<use>`) വരയ്ക്കുന്നു;
  Switzer-ന് ഇല്ലാത്ത അമ്പുകളും ജ്യാമിതീയ ചിഹ്നങ്ങളും അതിന്റെ സ്വന്തം മെട്രിക്കുകൾ ഉപയോഗിച്ച് വരയ്ക്കുന്നു.
  ഉൾച്ചേർത്ത ഫോണ്ടല്ല, ഔട്ട്ലൈനുകളാണ് ഉപയോഗിക്കേണ്ടത്: Switzer-ന്റെ ലൈസൻസ്
  (`packages/ui-kit/src/fonts/FFL.txt`) എഴുത്തുപരമായ അനുമതിയില്ലാതെ subsetting-വും format
  conversion-വും നിരോധിക്കുകയും വെക്റ്റർ ഡ്രോയിംഗുകൾ അനുവദിക്കുകയും ചെയ്യുന്നു. അതിനാൽ Switzer
  `@font-face` അല്ലെങ്കിൽ `data:` URI വീണ്ടും അവതരിപ്പിക്കരുത്. ഫയലിൽ ശേഷിക്കുന്ന ഏക ഫോണ്ട്,
  യഥാർത്ഥ കോഡ് ടെക്സ്റ്റായി തുടരുന്നവയ്ക്കുള്ള OFL IBM Plex Mono subset ആണ്
  (`scripts/docs/readme-fonts.mjs`); ഉൾക്കൊള്ളാനാകാത്ത ഏതെങ്കിലും glyph ഉണ്ടായാൽ അത്
  പിശക് ഉയർത്തും.
- **വീണ്ടും ജനറേറ്റ് ചെയ്യുക.** `npm run docs:readme-diagrams` README-യിലെ ക്രമത്തിൽ പന്ത്രണ്ടും
  വീണ്ടും എഴുതുകയും ഓരോ ഫയലിനും അതിന്റെ വലുപ്പത്തോടെ ഒരു വരി പ്രിന്റ് ചെയ്യുകയും ചെയ്യുന്നു.
  ഒരു ജനറേറ്റർ ഒറ്റയ്ക്കും പ്രവർത്തിപ്പിക്കാം (`node scripts/docs/gen-readme-<name>.mjs`;
  `free-tier-budget`-ന് `node --import tsx/esm` ആവശ്യമാണ്, കാരണം അതിലെ കണക്കുകൾ
  `open-sse/config/freeModelCatalog.ts`-ലെ live catalog loader-ൽ നിന്നാണ് വരുന്നത്;
  catalog മാറ്റത്തിന്റെ CI പ്രത്യാഘാതം `docs/architecture/QUALITY_GATES.md` →
  `docs-sync-strict`-ൽ ഉണ്ട്). ജനറേറ്ററും SVG-യും ഒരുമിച്ച് കമ്മിറ്റ് ചെയ്യുക.
  release മോഡിൽ പഴകിയ SVG പരാജയപ്പെടും; feature PR-ൽ, `npm run check:generated-artifacts`
  PR തിരുത്തുന്ന SVG മാത്രം വിലയിരുത്തുന്നു (`docs/architecture/QUALITY_GATES.md` →
  "Generated files and derived baselines").
- **സ്ഥിരീകരണം.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` GitHub അത് നൽകുന്ന
  രീതിയിൽ ഒരു ഫയൽ റെൻഡർ ചെയ്യുന്നു (`<img>` ടാഗ്, camo-യുടെ `Content-Security-Policy`,
  `image/svg+xml`), ലൈറ്റും ഡാർക്കും ആയ ഫ്രെയിമുകൾ പകർത്തുകയും പേജ് നടത്തിയ ബാഹ്യ ഫോണ്ട്
  അഭ്യർത്ഥനകൾ റിപ്പോർട്ട് ചെയ്യുകയും ചെയ്യുന്നു (എണ്ണം 0 ആയിരിക്കണം).
- **ബജറ്റ്.** ഓരോ ഫയലിനും 200 KB-ൽ താഴെ (ഓരോ staleness ടെസ്റ്റും ഇത് ഉറപ്പാക്കുന്നു);
  ഏതെങ്കിലും README ചിത്രത്തിനുള്ള കർശന പരിധി 500 KB ആണ് (SVG studio validator-ന്റെ നിയമം).
- **പകർപ്പ് മാറ്റമില്ലാതെ, എണ്ണങ്ങൾ gate-ൽ നിന്ന്.** റീബ്രാൻഡിംഗ് വാക്കുകളെയല്ല, ടൈപ്പിനെയും
  പാലറ്റിനെയുമാണ് മാറ്റിയത്: ഓരോ ജനറേറ്ററും അതിന്റെ ഡയഗ്രാമിന്റെ പകർപ്പ് ഒരു `*_COPY` constant-ൽ
  സൂക്ഷിക്കുന്നു (അല്ലെങ്കിൽ live catalog-ൽ നിന്ന് നിർമ്മിക്കുന്നു); ഇത് വരച്ച ടെക്സ്റ്റും outlining
  ഘട്ടത്തിന്റെ ഇൻപുട്ടും ഒരുപോലെയാണ്. Canonical കണക്കുകൾ `<text>` nodes-ൽ തന്നെ നിലനിൽക്കും
  (outlined ചെയ്തുകഴിഞ്ഞാൽ അദൃശ്യമാണ്, `fill-opacity:0`), അവ
  `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) വായിക്കുന്നു. gate-ൽ
  വായന നിയന്ത്രിക്കുന്ന ഡയഗ്രാമുകളുടെ staleness ടെസ്റ്റുകൾ generated ഫയലിൽ അതിന്റെ validators-ഉം
  പ്രവർത്തിപ്പിക്കുന്നു. അതിനാൽ code-ൽ നിന്ന് വ്യതിചലിക്കുന്ന ഒരു കണക്ക് ടെസ്റ്റിനെ പരാജയപ്പെടുത്തും —
  ജനറേറ്ററിലെ നമ്പർ ഒരിക്കലും തിരുത്താതെ, gate വായിക്കുന്ന source തിരുത്തുക.
