> **സ്റ്റാറ്റസ്:** ഡാഷ്ബോർഡ് **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`) അടിസ്ഥാനമാക്കിയാണ് നിർമ്മിച്ചിരിക്കുന്നത്; ഇത് `packages/ui-kit` എന്ന വർക്ക്സ്പേസായി വെൻഡോർ ചെയ്തിരിക്കുന്നു (`@omniroute/ui-kit`; അപ്സ്ട്രീം സ്നാപ്ഷോട്ട് `packages/ui-kit/UPSTREAM.md`-ൽ പിൻ ചെയ്തിരിക്കുകയും `npm run check:ui-kit-snapshot` വഴി സംരക്ഷിക്കപ്പെടുകയും ചെയ്യുന്നു). ലൈറ്റ് ആണ് കാനോനിക്കൽ തീം; ഡിഫോൾട്ട് മുൻഗണന `system` ആണ്. ആക്സന്റ് Keak lime ആണ് (`--ci-color-accent`). Inter (letter-spacing 0, `--ci-letter-spacing-ui`) ആണ് UI ഫാമിലി; വലിയ വിരളമായ ഡിസ്പ്ലേ ടെക്സ്റ്റിന് മാത്രം Instrument Serif (`.ci-dashboard-display`); കോഡിന് IBM Plex Mono — എല്ലാം `src/app/globals.css`-ന്റെ മുകളിലുള്ള `@fontsource/*` ഇമ്പോർട്ടുകൾ വഴി സെൽഫ്-ഹോസ്റ്റ് ചെയ്യപ്പെട്ടിരിക്കുന്നു. ഓരോ ഐക്കണും ഒരു Lucide ഗ്ലിഫ് ആണ്.

## 1. എന്തൊക്കെ എവിടെയാണ്

- **കിറ്റ്.** `packages/ui-kit/src` എന്നത് `packages/ui-kit/UPSTREAM.md`-ൽ പിൻ ചെയ്തിരിക്കുന്ന കമ്മിറ്റിലെ അപ്സ്ട്രീം `src/`-ന്റെ ബൈറ്റ്-ഫോർ-ബൈറ്റ് പകർപ്പാണ് (ലൈസൻസ് അനുമതിയും അതിൽ രേഖപ്പെടുത്തിയിട്ടുണ്ട്); പ്രാദേശിക പാച്ചുകൾ `PATCHES.md` പട്ടികപ്പെടുത്തുന്നു (ഒന്നുമില്ല). ബിൽഡ് ഇല്ലാതെ ഇത് സോഴ്സായി തന്നെ ഉപയോഗിക്കപ്പെടുന്നു: `next.config.mjs` ഇതിനെ ട്രാൻസ്പൈൽ ചെയ്യുന്നു, `tsconfig.json` `@omniroute/ui-kit` → `packages/ui-kit/src`, `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` എന്നിങ്ങനെ മാപ്പ് ചെയ്യുന്നു (`vitest.config.ts`-ലും `vitest.mcp.config.ts`-ലും അതേ അലിയാസ് തന്നെയുണ്ട്). ഒരു കിറ്റ് കോമ്പോണന്റ് അതിന്റെ സബ്പാത്ത് വഴി ഇംപോർട്ട് ചെയ്യുക (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), ഒരിക്കലും `@omniroute/ui-kit` ബാരൽ വഴിയല്ല: ബാരൽ എല്ലാ കോമ്പോണന്റുകളെയും (ഡേറ്റ് പിക്കർ ഉൾപ്പെടെ) ഓരോ ഇംപോർട്ടറിലേക്കും വലിച്ചുകൊണ്ടുവരും. കിറ്റ് സ്റ്റൈൽഷീറ്റ് `src/app/globals.css` വഴിയാണ് പ്രവേശിക്കുന്നത് (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **ടോക്കനുകൾ.** `--ci-*` ടോക്കനുകൾ `packages/ui-kit/src/ci-tokens.css` ഡിക്ലയർ ചെയ്യുന്നു; `src/app/globals.css` അവയെ ലെഗസി OmniRoute പേരുകളിലേക്ക് (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) ബ്രിഡ്ജ് ചെയ്യുന്നു, അതിനാൽ നിലവിലുള്ള `var(--color-*)` റീഡുകളും Tailwind യൂട്ടിലിറ്റികളും പ്രവർത്തിച്ചുകൊണ്ടിരിക്കും. പുതിയ കോഡ് Tailwind യൂട്ടിലിറ്റികൾ (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) അല്ലെങ്കിൽ കിറ്റ് ക്ലാസുകൾ ഉപയോഗിക്കുന്നു — ഒരിക്കലും ഒരു ഹെക്സ് മൂല്യമല്ല (`tests/unit/design-kit-bridge.test.ts` ഈ ബ്രിഡ്ജ് നടപ്പിലാക്കുന്നു). `text-primary`, `--text-color-primary` വഴി `--color-primary-ink`-ലേക്ക് റിസോൾവ് ചെയ്യുന്നു (ലൈറ്റിൽ lime-800, ഡാർക്കിൽ lime ആക്സന്റ്), അതിനാൽ `bg-primary`/`border-primary` lime സർഫേസ് നിലനിർത്തുമ്പോൾ തന്നെ പ്രൈമറി ടെക്സ്റ്റ് വായിക്കാവുന്നതായി തുടരും. ചാർട്ട് സീരീസുകൾ `--color-chart-1` … `--color-chart-5` ഉപയോഗിക്കുന്നു.
- **തീമുകൾ.** `<html className="ci-theme">` (`src/app/layout.tsx`) ഡോക്യുമെന്റിനെ കിറ്റ് തീമിലേക്ക് ഓപ്റ്റ്-ഇൻ ചെയ്യുന്നു. മുൻഗണന `light`, `dark` അല്ലെങ്കിൽ `system` ആണ് (`src/shared/constants/appConfig.ts`-ൽ `THEME_CONFIG.defaultTheme = "system"`; `system` `prefers-color-scheme`-നെ പിന്തുടരുന്നു). `src/store/themeStore.ts`-ലെ `applyTheme()` (`src/app/layout.tsx`-ലെ ഇൻലൈൻ ബൂട്ട്സ്ട്രാപ്പ് സ്ക്രിപ്റ്റ് ഇതിന്റെ പ്രതിബിംബമാണ്, അത് ഹൈഡ്രേഷന് മുമ്പ് പ്രവർത്തിക്കുന്നു) `data-theme="dark"|"light"` സെറ്റ് ചെയ്യുകയും `<html>`-ൽ `.dark` ക്ലാസ് ഒരുമിച്ച് ടോഗിൾ ചെയ്യുകയും ചെയ്യുന്നു. കിറ്റിന്റെ ഡാർക്ക് ടോക്കൺ സെറ്റ് `data-theme="dark"` അടിസ്ഥാനമാക്കിയുള്ളതാണ് (`packages/ui-kit/src/ci-tokens.css`); OmniRoute-ന്റെ സ്വന്തം ഡാർക്ക് ഓവർറൈഡുകൾ (`globals.css`-ലെ `.dark` ബ്ലോക്ക്) എന്നിവയും ലെഗസി Tailwind `dark:` യൂട്ടിലിറ്റികളും `.dark` ക്ലാസ് അടിസ്ഥാനമാക്കിയുള്ളതാണ്. ആക്സന്റ് കളർ പ്രീസെറ്റുകളൊന്നുമില്ല: ആക്സന്റ് എപ്പോഴും കിറ്റിൽ നിന്നാണ് വരുന്നത്, ഒരു പഴയ ബിൽഡിൽ നിന്ന് നിലനിൽക്കുന്ന പ്രീസെറ്റ് സ്റ്റോർ ലോഡ് ചെയ്യുമ്പോൾ ഉപേക്ഷിക്കപ്പെടും.
- **കോമ്പോണന്റുകൾ (അഡാപ്റ്ററുകൾ).** `src/shared/components/index.tsx` OmniRoute കോമ്പോണന്റ് API നിലനിർത്തുന്നു (അതേ പേരുകൾ, ഡിഫോൾട്ട് എക്സ്പോർട്ടുകൾ, പ്രോപ്പുകൾ), അതിന് പിന്നിലുള്ള പ്രിമിറ്റീവുകൾ കിറ്റിന് മുകളിലുള്ള അഡാപ്റ്ററുകളാണ്: ഫോമുകൾ (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), ഓവർലേകളും ഫീഡ്ബാക്കും (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`), ഘടന (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`), ടേബിളുകൾ (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`) എന്നിവ. ഒരു അഡാപ്റ്റർ സബ്പാത്ത് വഴി കിറ്റ് കോമ്പോണന്റ് ഇംപോർട്ട് ചെയ്യുകയും ലെഗസി പ്രോപ്പുകളെ അതിലേക്ക് മാപ്പ് ചെയ്യുകയും ചെയ്യുന്നു — ഉദാഹരണത്തിന് `Button variant="primary"` എന്നത് കിറ്റിന്റെ `default` ബട്ടൺ ആണ് (`--ci-button-primary-*`: ലൈറ്റിൽ ഇൻവേർസ് സർഫേസ്, ഡാർക്കിൽ അതിന്റെ `--ci-color-accent-foreground` ഇങ്കോടുകൂടിയ ആക്സന്റ്), `danger` എന്നത് `destructive` ആണ്, `warning` എന്നത് `outline` പ്ലസ് `.ci-button--warning` എക്സ്റ്റൻഷനുമാണ്. `globals.css`-ന്റെ അവസാനത്തെ (`@layer components`) `.ci-button--warning`, `.ci-badge[data-tone]` റൂളുകൾ കിറ്റ് ക്ലാസുകൾക്ക് മുകളിലുള്ള OmniRoute എക്സ്റ്റൻഷനുകളാണ്. `tests/unit/ui/adapters/*.test.tsx` ഓരോ അഡാപ്റ്ററെയും അടിച്ചുറപ്പിക്കുന്നു.
- **ഷെൽ.** `src/app/(dashboard)/layout.tsx` `DashboardLayout` റെൻഡർ ചെയ്യുന്നു, അത് `src/shared/components/layouts/DashboardShell.tsx` റെൻഡർ ചെയ്യുന്നു: കിറ്റ് `SidebarProvider` / `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), OmniRoute-ന്റെ നാവിഗേഷൻ ലോജിക് `src/shared/components/Sidebar.tsx`-ൽ. `#main-content`-ലേക്കുള്ള "ഉള്ളടക്കത്തിലേക്ക് പോകുക" ലിങ്കാണ് ആദ്യത്തെ ഫോക്കസ് ചെയ്യാവുന്ന എലമെന്റ്. `src/shared/components/Header.tsx`-ൽ കിറ്റ് `SidebarTrigger` (ഷെല്ലിലെ ഏക സൈഡ്ബാർ ടോഗിൾ), Keak `ProductSwitcher`, കമാൻഡ്-പലറ്റ് ഓപ്പണർ എന്നിവയുണ്ട്; `#main-content`-നുള്ളിൽ ഒരു കിറ്റ് `PageHeader` (`.ci-page-header`) മൗണ്ട് ചെയ്തിട്ടില്ലാത്തപ്പോൾ മാത്രമേ അത് റൂട്ട് ടൈറ്റിൽ കാണിക്കൂ, അതിനാൽ സ്വന്തം `PageHeader` ഉള്ള ഒരു പേജിന് ഒരൊറ്റ `h1` മാത്രമേ ഉണ്ടാകൂ. `src/shared/components/CommandPalette.tsx` ഒരു കിറ്റ് `Dialog` ആണ്.
- **ഐക്കണുകൾ.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) പേരിനെ (സ്ക്രീനുകൾ ഉപയോഗിക്കുന്ന Material Symbols വൊക്കാബുലറി) `ICON_MAP` (`src/shared/constants/iconMap.ts`) വഴി ഒരു Lucide ഗ്ലിഫിലേക്ക് റിസോൾവ് ചെയ്യുന്നു. ## 4. അഡാപ്റ്റർ ചേർക്കുകയോ മാറ്റുകയോ ചെയ്യുമ്പോൾ

3. കിറ്റിലെ കുറവുകൾ മറികടക്കാനുള്ള വർക്ക്എറൗണ്ടുകൾ അഡാപ്റ്ററിലായിരിക്കണം (പരിഹാരം ഒരു സ്റ്റൈൽ ആണെങ്കിൽ `globals.css`-ിലെ `@layer components`-ൽ), ഒരിക്കലും `packages/ui-kit/src`-ൽ അല്ല.
4. `tests/unit/ui/adapters/<name>.test.tsx` ചേർക്കുകയോ അപ്ഡേറ്റ് ചെയ്യുകയോ ചെയ്യുക. ധാരാളം കോളറുകളുള്ള ഒരു അഡാപ്റ്ററാണെങ്കിൽ, മാറ്റത്തിന് മുമ്പും ശേഷവും റെൻഡർ ചെയ്ത മാർക്കപ്പ് താരതമ്യം ചെയ്യുക — പാഡിംഗിലോ റാപ്പറിലോ ഉള്ള മാറ്റങ്ങൾ എല്ലാ സ്ക്രീനുകളിലേക്കും വ്യാപിക്കും.

## 5. കിറ്റ് അപ്ഡേറ്റ് ചെയ്യൽ

`scripts/dev/sync-ui-kit.sh <commit> [clone]` ആ കമ്മിറ്റിലെ അപ്സ്ട്രീം `src/` `packages/ui-kit/src`-ലേക്ക് പകർത്തുകയും അനുവദിച്ചിരിക്കുന്ന ഏക രൂപാന്തരം പ്രയോഗിക്കുകയും ചെയ്യുന്നു (അത് relative ഇംപോർട്ടുകളിൽ നിന്ന് `.js` സഫിക്സ് നീക്കം ചെയ്യുന്നു). ശേഷം: `git diff packages/ui-kit` അവലോകനം ചെയ്യുക, രണ്ട് തീമുകളിലും providers, settings, combos, usage, endpoint എന്നിവയിൽ ഒരു വിഷ്വൽ പരിശോധന നടത്തുക, `npm run check:ui-kit-snapshot`, `npm run test:vitest:ui` എന്നിവ റൺ ചെയ്യുക, അപ്സ്ട്രീം ചേഞ്ച്ലോഗോടെ PR തുറക്കുക.
