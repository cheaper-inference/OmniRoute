## 1. കാര്യങ്ങൾ എവിടെയാണ് ഉള്ളത്

- **കിറ്റ്.** `packages/ui-kit/src` എന്നത്
  `packages/ui-kit/UPSTREAM.md`-ൽ പിൻ ചെയ്തിരിക്കുന്ന commit-ലെ upstream `src/`-ന്റെ byte-for-byte പകർപ്പാണ്
  (license authorization-ഉം അതിൽ രേഖപ്പെടുത്തിയിട്ടുണ്ട്); പ്രാദേശിക patches (ഒന്നുമില്ല)
  `PATCHES.md`-ൽ പട്ടികപ്പെടുത്തിയിരിക്കുന്നു. build ഇല്ലാതെ ഇത് source ആയി ഉപയോഗിക്കുന്നു:
  `next.config.mjs` ഇതിനെ transpile ചെയ്യുന്നു; `tsconfig.json`, `@omniroute/ui-kit` →
  `packages/ui-kit/src` എന്നും `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` എന്നും മാപ്പ് ചെയ്യുന്നു
  (`vitest.config.ts`, `vitest.mcp.config.ts` എന്നിവയിലും ഇതേ alias ഉണ്ട്). ഒരു kit component അതിന്റെ
  subpath വഴി import ചെയ്യുക (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…);
  `@omniroute/ui-kit` barrel വഴി ഒരിക്കലും ചെയ്യരുത്: ഓരോ importer-ലേക്കും എല്ലാ components-ഉം
  (date picker ഉൾപ്പെടെ) barrel കൊണ്ടുവരും. kit stylesheet, `src/app/globals.css` വഴിയാണ് പ്രവേശിക്കുന്നത്
  (`@import "../../packages/ui-kit/src/ci-ui.css"`).
- **ടോക്കണുകൾ.** `packages/ui-kit/src/ci-tokens.css`, `--ci-*` tokens പ്രഖ്യാപിക്കുന്നു;
  `src/app/globals.css` അവയെ legacy OmniRoute പേരുകളുമായി (`--color-*`, `--radius-*`,
  `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) ബന്ധിപ്പിക്കുന്നു.
  അതിനാൽ നിലവിലുള്ള `var(--color-*)` reads-ഉം Tailwind utilities-ഉം തുടർന്നും പ്രവർത്തിക്കും. പുതിയ
  code Tailwind utilities (`bg-surface`, `text-text-muted`, `border-border`, `text-success`,
  `bg-success-bg`, `bg-chart-1`…) അല്ലെങ്കിൽ kit classes ഉപയോഗിക്കുന്നു — hex value ഒരിക്കലും ഉപയോഗിക്കില്ല
  (`tests/unit/design-kit-bridge.test.ts` ഈ bridge നിർബന്ധമാക്കുന്നു). `text-primary`,
  `--text-color-primary` വഴി `--color-primary-ink` ആയി resolve ചെയ്യുന്നതിനാൽ primary text വായിക്കാവുന്നതായി
  തുടരുന്നു; അതേസമയം `bg-primary`/`border-primary` accent surface നിലനിർത്തുന്നു: Editions-ൽ ഇത് kit-ന്റെ
  `--ci-color-accent-active` ആണ് (light-ൽ ഇരുണ്ട copper `#99562f`, dark-ൽ copper accent); Classic-ൽ
  light-ൽ lime-800-ഉം dark-ൽ lime accent-ഉം. Chart series, `--color-chart-1` …
  `--color-chart-5` ഉപയോഗിക്കുന്നു.
- **തീമുകൾ.** `<html className="ci-theme">` (`src/app/layout.tsx`) document-നെ kit theme-ലേക്ക്
  ഉൾപ്പെടുത്തുന്നു. preference `light`, `dark` അല്ലെങ്കിൽ `system` ആണ്
  (`src/shared/constants/appConfig.ts`-ൽ `THEME_CONFIG.defaultTheme = "system"`; `system`,
  `prefers-color-scheme` പിന്തുടരുന്നു). `src/store/themeStore.ts`-ലെ `applyTheme()` (hydration-ന് മുമ്പ്
  പ്രവർത്തിക്കുന്നതിനായി `src/app/layout.tsx`-ൽ inline ചെയ്ത `THEME_BOOT_SCRIPT` ഇതിനെ പ്രതിഫലിപ്പിക്കുന്നു)
  `data-theme="dark"|"light"` സജ്ജമാക്കുകയും `<html>`-ലെ `.dark` class അതോടൊപ്പം toggle ചെയ്യുകയും ചെയ്യുന്നു.
  kit-ന്റെ dark token set, `data-theme="dark"` അടിസ്ഥാനമാക്കിയാണ് പ്രവർത്തിക്കുന്നത്
  (`packages/ui-kit/src/ci-tokens.css`); OmniRoute-ന്റെ സ്വന്തം dark overrides (`globals.css`-ലെ `.dark`
  block), legacy Tailwind `dark:` utilities എന്നിവ `.dark` class അടിസ്ഥാനമാക്കി പ്രവർത്തിക്കുന്നു. accent
  color presets ഒന്നുമില്ല: accent എപ്പോഴും kit-ൽ നിന്നാണ് വരുന്നത്; പഴയ build-ൽ നിന്ന് persisted ആയ
  preset, store load ചെയ്യുമ്പോൾ നീക്കം ചെയ്യപ്പെടുന്നു.
- **പാലറ്റുകൾ.** രണ്ടെണ്ണമുണ്ട്; രണ്ടും kit-ൽ നിന്നുള്ളവയാണ്
  (`src/shared/constants/appearancePalette.ts`): default ആയ `editions`, പിന്നെ `classic`. Editions എന്നത്
  `<html>`-ലെ kit-ന്റെ `data-ci-appearance="editions"` attribute ആണ്; `ci-editions.css` (`ci-ui.css`
  import ചെയ്യുന്നത്) അതിനെ `data-theme`-മായി സംയോജിപ്പിക്കുന്നു. Classic എന്നത് ആ attribute-ന്റെ
  അഭാവമാണ്. root layout ഈ attribute server-render ചെയ്യുന്നതിനാൽ ഒന്നും store ചെയ്തിട്ടില്ലാത്ത
  (അല്ലെങ്കിൽ JS ഇല്ലാത്ത) സന്ദർശകന് എല്ലാ surfaces-ലും Editions ലഭിക്കുന്നു — dashboard, login,
  `/status`, error pages, `/docs`, PWA എന്നിവയിൽ. theme-ന്റെ തൊട്ടടുത്തായി അതേ `theme` store-ൽ choice
  persist ചെയ്യുന്നു (`src/store/themeStore.ts`-ലെ `palette`, `setPalette()`, `applyPalette()`); layout-ന്റെ
  `<head>`-ൽ inline ചെയ്തിരിക്കുന്ന `THEME_BOOT_SCRIPT`
  (`src/shared/utils/themeBootScript.ts`) paint-ന് മുമ്പ് അത് പ്രയോഗിക്കുന്നു. store ചെയ്ത palette
  `"classic"` ആയിരിക്കുമ്പോൾ മാത്രമാണ് script attribute നീക്കം ചെയ്യുന്നത്; root layout-ന് പുറത്തുള്ള
  `src/app/global-error.tsx`, അതേ store-ൽ നിന്ന് ഇത് പ്രയോഗിക്കുന്നു. മറ്റൊരു element-ലും
  `data-ci-appearance` ഇടരുത്: kit, `html:root:has([data-ci-appearance="editions"])` ഉപയോഗിച്ച് അതിനെ match
  ചെയ്യുന്നതിനാൽ ഒരൊറ്റ descendant പോലും മുഴുവൻ document-നെ switch ചെയ്യും. Editions-ന്റെ
  `data-ci-editions-variant="landing"` variant marketing pages-നുള്ളതാണ്, dashboard-നുള്ളതല്ല. Browser
  chrome-ന് (`viewport.themeColor`, web manifest) CSS-ഓ store ചെയ്ത choice-ഓ വായിക്കാൻ കഴിയാത്തതിനാൽ
  അത് default പിന്തുടരുന്നു: `src/shared/constants/pwaThemeColors.ts`-ലെ `PWA_THEME_COLORS` ആണ് Editions
  `--ci-color-background`-ന്റെ (`#f3f1e9` / `#11120f`) ഏക mirror; ഇത്
  `tests/unit/pwa-theme-colors.test.ts` മുഖേന `ci-editions.css`-ലേക്ക് പിൻ ചെയ്തിരിക്കുന്നു. Monaco അതിന്റെ
  colours ഒരു probe-ൽ നിന്ന് വായിക്കുന്നു (`monacoKitTheme.ts`); Editions-ൽ, kit Editions light/dark
  root-ൽ നിന്ന് resolve ചെയ്യുന്നതിനാൽ, ഒരു synchronous pass-നായി probe read root `data-theme` flip
  ചെയ്യുന്നു.

## 2. നിയമങ്ങൾ

1. ടോക്കണുകൾ, ഒരിക്കലും അക്ഷരങ്ങൾ. ഒഴിവാക്കലുകൾ ഉദ്ദേശ്യത്തോടെ സൂക്ഷിക്കുന്നു: എല്ലായ്പ്പോഴും ഇരുണ്ട കൺസോൾ ടെർമിനലും `STATUS_HEX` (`src/shared/constants/statusColors.ts`), അക്ഷരീയ ഹെക്സ് ആവശ്യമുള്ള വിളിക്കുന്നവർക്കുള്ള കിറ്റ് സ്റ്റാറ്റസ് പാലറ്റിൻ്റെ പരിഹരിച്ച ഹെക്സ് മിററും. വർഗ്ഗീകരണ പാലറ്റുകളും ഇനി ഒരു അപവാദമല്ല: അവ കിറ്റിൻ്റെ അഞ്ച് ചാർട്ട് ടോക്കണുകളിൽ (`--color-chart-1..5`) `src/shared/utils/categoricalPalette.ts` വഴിയും, റൂട്ടിംഗ് തന്ത്രങ്ങൾക്ക് `src/app/(dashboard)/dashboard/combos/strategyPalette.ts` വഴിയും സഞ്ചരിക്കുന്നു; ReactFlow അരികുകളും ഓർക്കസ്ട്രേഷൻ ക്യാൻവാസും തീം-അവബോധമുള്ള `--orch-status-*` വേരിയബിളുകൾ (`src/shared/components/flow/edgeStyles.ts`) വായിക്കുന്നു.
2. കൈകൊണ്ട് ഒരിക്കലും `packages/ui-kit/src` പാച്ച് ചെയ്യരുത്: `scripts/dev/sync-ui-kit.sh <commit>` മായി സമന്വയിപ്പിക്കുക ; പിൻ ചെയ്ത അപ്സ്ട്രീം കമ്മിറ്റിൽ നിന്ന് വ്യത്യസ്തമായ ഏതൊരു ബൈറ്റിലും പ്രീ-കമ്മിറ്റ് ഗേറ്റ് `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) പരാജയപ്പെടുന്നു (അപ്സ്ട്രീം ക്ലോൺ, `UI_KIT_CLONE` അല്ലെങ്കിൽ `_references/cheaper-inference-ui-kit`, ഇല്ലാത്തപ്പോൾ ഒരു മുന്നറിയിപ്പോടെ അത് ഒഴിവാക്കുന്നു). കിറ്റിന് എന്തെങ്കിലും കുറവുണ്ടാകുമ്പോൾ, അഡാപ്റ്ററിലോ സ്ക്രീനിലോ അതിന് ചുറ്റും പ്രവർത്തിച്ച് അപ്സ്ട്രീമിനായി ആവശ്യപ്പെടുക.
3. കിറ്റ് ടെക്സ്റ്റ് ഡിഫോൾട്ടുകൾ ഇംഗ്ലീഷാണ് (`label = "Loading"`, `loadingLabel = "Loading table"`…) — ഒരു കിറ്റ് ഘടകം ടെക്സ്റ്റ് റെൻഡർ ചെയ്യുമ്പോൾ `useTranslations(...)` ൽ നിന്ന് വിവർത്തനം ചെയ്ത സ്ട്രിംഗുകൾ കൈമാറുക.
4. ടെയിൽവിൻഡ് യൂട്ടിലിറ്റികൾ കിറ്റ് കോംപോണൻ്റ് ക്ലാസുകളിൽ വിജയിക്കുന്നു (കിറ്റ് `@layer theme, base, components, utilities` പ്രഖ്യാപിക്കുകയും അതിൻ്റെ നിയമങ്ങൾ `components` ൽ ജീവിക്കുകയും ചെയ്യുന്നു) — കിറ്റ് ഘടകങ്ങൾ വീണ്ടും കളർ ചെയ്യാതിരിക്കാൻ സ്പെയ്സിംഗിനും ലേഔട്ടിനുമായി യൂട്ടിലിറ്റികൾ ഉപയോഗിക്കുക.
5. തലക്കെട്ടുകൾ: പേജിനും വിഭാഗ ശീർഷകങ്ങൾക്കും `.ci-heading` ; പിശക്-പേജ് സ്റ്റാറ്റസ് കോഡ് പോലുള്ള വലുതും വിരളവുമായ ഡിസ്പ്ലേ ടെക്സ്റ്റുകൾക്ക് മാത്രം `.ci-dashboard-display`. ഇരുവരും സ്വിറ്റ്സർ ഉപയോഗിക്കുന്നു.
6. കിറ്റ് ദത്തെടുക്കലിനെ`tests/unit/dashboard-kit-sweep.test.ts` കാക്കുന്നു: `src/app` അല്ലെങ്കിൽ `src/shared/components` കീഴിൽ മെറ്റീരിയൽ ലിഗേച്ചർ സ്പാൻ ഇല്ല; ഡാഷ്ബോർഡ് ട്രീയിൽ (`src/app/(dashboard)`, `src/shared/components`) റോ `<select>`, `<textarea>` അല്ലെങ്കിൽ `<table>`, കൂടാതെ ലിസ്റ്റ് ചെയ്ത ഒഴിവാക്കലുകൾക്ക് പുറത്ത് ഹാൻഡ്-റോൾഡ് `role="dialog"` ഇല്ല ( `Select` അഡാപ്റ്ററിൻ്റെ നേറ്റീവ് ബ്രാഞ്ച്, `RequestLoggerDetail`); എല്ലാ അസംസ്കൃത `<button>` അല്ലെങ്കിൽ `<input>` `kit-exception:` (കാരണസഹിതം) അതിന് മുകളിൽ 3 വരികളിൽ അവസാനിക്കുന്ന ഒരു അഭിപ്രായം ആവശ്യമാണ്; പാലറ്റ് ഹ്യൂസും `dark:` വേരിയൻ്റുകളും ടെസ്റ്റ് ലിസ്റ്റ് ചെയ്യുന്ന ഫയലുകളിൽ മാത്രം.
7. ഒരു PR (സ്ക്രീൻഷോട്ടുകൾ) മുമ്പായി രണ്ട് തീമുകളും 390 px വ്യൂപോർട്ടും പരിശോധിക്കുക; `tests/e2e/a11y.spec.ts` കോടാലി പ്രവർത്തിപ്പിക്കുന്നു.

2. കിറ്റ് സബ്പാത്ത് വഴി ഇമ്പോർട്ട് ചെയ്യുക (`@omniroute/ui-kit/<component>`).
3. കിറ്റിലെ കുറവുകൾക്കുള്ള വേർക്ക് എറൗണ്ടുകൾ അഡാപ്റ്ററിൽ ആയിരിക്കണം (പരിഹാരം ഒരു സ്റ്റൈൽ ആണെങ്കിൽ `globals.css`
   `@layer components`-ൽ), ഒരിക്കലും `packages/ui-kit/src`-ൽ അല്ല.
4. `tests/unit/ui/adapters/<name>.test.tsx` ചേർക്കുകയോ അപ്ഡേറ്റ് ചെയ്യുകയോ ചെയ്യുക. ധാരാളം കോളറുകളുള്ള ഒരു
   അഡാപ്റ്ററിന്, മാറ്റത്തിന് മുമ്പും ശേഷവും റെൻഡർ ചെയ്ത മാർക്കപ്പ് താരതമ്യം ചെയ്യുക — പാഡിംഗ് അല്ലെങ്കിൽ റാപ്പർ
   മാറ്റങ്ങൾ എല്ലാ സ്ക്രീനുകളിലേക്കും പടരും.

## 5. കിറ്റ് അപ്ഡേറ്റ് ചെയ്യുന്നു

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` ൽ പിൻ ചെയ്തിരിക്കുന്ന പതിപ്പിനെ അപ്സ്ട്രീം റിപ്പോയുടെ ഏറ്റവും പുതിയ `v*` ടാഗുമായി താരതമ്യം ചെയ്യുകയും ഒരു റിലീസ് കഴിയുമ്പോൾ സമന്വയ കമാൻഡ് പ്രിൻ്റ് ചെയ്യുകയും ചെയ്യുന്നു.

പ്രതിദിന `UI Kit upstream watch` വർക്ക്ഫ്ലോ (`.github/workflows/ui-kit-upstream-watch.yml`) സമാന പരിശോധന നടത്തുന്നു. പിൻ പിന്നിലായിരിക്കുമ്പോൾ, റോളിംഗ് ബ്രാഞ്ചിൽ `chore/ui-kit-sync-latest` ഉയർന്ന `release/vX.Y.Z` ശാഖയ്ക്കെതിരെ `scripts/ci/ui-kit-sync-pr.sh` ഒരു സമന്വയ PR തുറന്നിടുന്നു. ഇത് ഒരിക്കലും ലയിക്കുന്നില്ല: ഓരോ കിറ്റ് റിലീസിനും ഇപ്പോഴും ലോക്കൽ VPS ൽ ഒരു ദൃശ്യ പരിശോധന ആവശ്യമാണ്. ഒരു പുതിയ പതിപ്പ് പുറത്തിറങ്ങുമ്പോൾ ബ്രാഞ്ച് പുനർനിർമ്മിക്കപ്പെടുകയും അല്ലാത്തപക്ഷം തനിച്ചായിരിക്കുകയും ചെയ്യുന്നു. കൈകൊണ്ട് പുഷ് ചെയ്ത കമ്മിറ്റുകളുള്ള ഒരു ഓപ്പൺ PR പുനരാലേഖനം ചെയ്യപ്പെടുന്നില്ല, കൂടാതെ ഒരു മെയിൻ്റനർ അടച്ച പതിപ്പിനുള്ള PR ഒരു പുതിയ റിലീസ് വരെ അടച്ചിരിക്കും.

ഒരു PR തുറക്കാൻ കഴിയാത്തപ്പോൾ (ടാർഗെറ്റ് റിലീസ് ഫ്രീസുചെയ്തിരിക്കുന്നു, PR കൈകൊണ്ട് പുഷ് ചെയ്തിരിക്കുന്നു, PR അടച്ചു, അല്ലെങ്കിൽ PR ടോക്കൺ സജ്ജീകരിച്ചിട്ടില്ല) വർക്ക്ഫ്ലോ ഒരു ട്രാക്കിംഗ് പ്രശ്നം തുറന്ന് സൂക്ഷിക്കുന്നു, അത് എന്തുകൊണ്ടെന്ന് പറയുന്നു.

വർക്ക്ഫ്ലോ രണ്ട് രഹസ്യങ്ങൾ ഉപയോഗിക്കുന്നു:

- `secrets.UI_KIT_READ_TOKEN`: സ്വകാര്യ അപ്സ്ട്രീം റിപ്പോയ്ക്കായി ഒരു വായന-മാത്രം ടോക്കൺ. വർക്ക്ഫ്ലോയ്ക്ക് അപ്സ്ട്രീം വായിക്കാൻ കഴിയാതെ വരുമ്പോൾ (ടോക്കൺ ഇല്ല, ജോലി നിർത്തിയ ടോക്കൺ, അല്ലെങ്കിൽ GitHub ലഭ്യമല്ല) റൺ പച്ചയായി തുടരുന്നു, പക്ഷേ ഒരു മുന്നറിയിപ്പ് എഴുതുകയും ഒരു പ്രത്യേക പ്രശ്നം തുറന്ന് സൂക്ഷിക്കുകയും ചെയ്യുന്നു, അത് ഒരിക്കൽ അടച്ചാൽ പിന്നീടുള്ള ഓട്ടത്തിന് വീണ്ടും അപ്സ്ട്രീം വായിക്കാൻ കഴിയും.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: ഈ ശേഖരത്തിൽ ഉള്ളടക്കവും പുൾ അഭ്യർത്ഥനകളും റൈറ്റ് ആക്സസ് ഉള്ള ഒരു സൂക്ഷ്മമായ ടോക്കൺ. സ്ഥിരസ്ഥിതി `GITHUB_TOKEN` ഇവിടെ PRs സൃഷ്ടിക്കാൻ കഴിയില്ല, കൂടാതെ അത് തുറന്ന ഒരു PR CI ട്രിഗർ ചെയ്യില്ല. ഈ ടോക്കൺ ഇല്ലാതെ വർക്ക്ഫ്ലോ ശാഖയെ മാത്രം തള്ളുന്നു.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` ആ കമ്മിറ്റിലെ അപ്സ്ട്രീം `src/` (`latest` = ഏറ്റവും പുതിയ `v*` ടാഗ്) `packages/ui-kit/src` ലേക്ക് പകർത്തുന്നു, അനുവദനീയമായ ഒറ്റ പരിവർത്തനം പ്രയോഗിക്കുന്നു (അത് ആപേക്ഷിക ഇറക്കുമതികളിൽ നിന്ന് `.js` സഫിക്സ് ഒഴിവാക്കുന്നു), കൂടാതെ `packages/ui-kit/package.json`, `package-lock.json` എന്നിവയിലെ വർക്ക്സ്പെയ്സ് പതിപ്പ് അപ്സ്ട്രീം ഒന്നിലേക്ക് സജ്ജമാക്കുന്നു. തുടർന്ന്: `git diff packages/ui-kit` അവലോകനം ചെയ്യുക, ദാതാക്കൾ, ക്രമീകരണങ്ങൾ, കോമ്പോകൾ, ഉപയോഗം, എൻഡ്പോയിൻ്റ് എന്നിവയിൽ രണ്ട് തീമുകളിലും ഒരു വിഷ്വൽ പാസ് ചെയ്യുക, `npm run check:ui-kit-snapshot`, `npm run test:vitest:ui` എന്നിവ പ്രവർത്തിപ്പിക്കുക, കൂടാതെ അപ്സ്ട്രീം ചേഞ്ച്ലോഗ് ഉപയോഗിച്ച് PR തുറക്കുക.

## 6. README ഡയഗ്രാമുകൾ

റൂട്ട് `README.md` എംബെഡ് ചെയ്യുന്ന പന്ത്രണ്ട് ഡയഗ്രാമുകൾ (`docs/diagrams/*.svg`) ഒരു സ്റ്റാറ്റിക് ഇമേജിൽ പ്രയോഗിച്ച കിറ്റാണ്; അവ കൈകൊണ്ട് വരച്ചതല്ല, ജനറേറ്റ് ചെയ്തവയാണ്: `scripts/docs/gen-readme-*.mjs`-ൽ 13 ജനറേറ്റർ ഫയലുകൾ (പന്ത്രണ്ട് ഡയഗ്രാമുകളും `gen-readme-diagrams.mjs` ഡ്രൈവറും), കൂടാതെ ഓരോ ഡയഗ്രാമിനും ഒന്ന് വീതം `tests/unit/docs/readme-*-svg.test.ts`-ൽ 12 പഴക്കപരിശോധനകൾ; ഓരോന്നും കമ്മിറ്റ് ചെയ്ത ഫയലിനെ അതിന്റെ ജനറേറ്ററിന്റെ ഔട്ട്പുട്ടുമായി ബൈറ്റ് തലത്തിൽ താരതമ്യം ചെയ്യുന്നു (ജോബ് `test-unit`).

- **ടോക്കണുകൾ.** `scripts/docs/readme-diagram-theme.mjs`, Editions പാലറ്റ് (ഡിഫോൾട്ട് രൂപഭാവം)
  `packages/ui-kit/src/ci-editions.css`-ൽ നിന്ന് പകർത്തുന്നു (`tests/unit/docs/readme-diagram-theme.test.ts` ഉപയോഗിച്ച്
  ആ ഫയലിനോട് പിൻ ചെയ്തിരിക്കുന്നു; രണ്ട് സ്കീമുകളിലെയും എല്ലാ സർഫേസുകളിലെ ഓരോ ടെക്സ്റ്റ് നിറത്തിനും WCAG AA പാലിക്കുന്നുണ്ടെന്നും ഇത് പരിശോധിക്കുന്നു; ഒരേയൊരു അപവാദം ലൈറ്റ് `warn` ആണ്—കിറ്റിലെ മൂല്യം ക്യാൻവാസിൽ 4.46:1 ആയതിനാൽ കിറ്റ് മുന്നറിയിപ്പ് 10 % ഇരുണ്ടതാക്കിയതാണ് ഇത്) കൂടാതെ കിറ്റിന്റെ ടൈപ്പ് സ്കെയിലിൽ (`ci-tokens.css`) ടെക്സ്റ്റ് റോളുകൾ നിർവചിക്കുന്നു: കിറ്റിന്റെ വെയ്റ്റുകളിൽ (400/500/600, ഡിസ്പ്ലേയ്ക്ക് 500) Switzer, എല്ലാറ്റിനും ട്രാക്കിങ്ങും; എന്നാൽ കോഡ് റോളുകൾ (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`) മാത്രം ഇതിൽനിന്ന് വ്യത്യസ്തമാണ്—അവ IBM Plex Mono ഉപയോഗിക്കുന്നു, കൂടാതെ കമാൻഡുകൾ, URL-കൾ, ഐഡന്റിഫയറുകൾ, ടെർമിനൽ സ്ക്രീനുകൾ എന്നിവയ്ക്കായി മാത്രമുള്ളവയാണ്.
  ലൈറ്റ് മൂല്യങ്ങൾ `:root`-ലും ഡാർക്ക് മൂല്യങ്ങൾ ഫയലിനുള്ളിലെ `prefers-color-scheme: dark`-ന് പിന്നിലുമാണ് ഉള്ളത്; അതിനാൽ ഓരോ ഇമേജും GitHub-ൽ കാഴ്ചക്കാരന്റെ സ്കീം പിന്തുടരുന്നു.
- **ഫോണ്ടുകൾ.** GitHub Markdown CSS ഉൾക്കൊള്ളുന്നില്ല, കൂടാതെ camo പ്രോക്സി എല്ലാ ബാഹ്യ ഫെച്ചുകളും തടയുന്നു; അതിനാൽ കിറ്റ് ടൈപ്പ് ഫയലിനുള്ളിൽ തന്നെ ഉൾപ്പെടുത്തണം. ഓരോ ജനറേറ്ററിന്റെയും അവസാന ഘട്ടമായ `scripts/docs/readme-outline.mjs`, HarfBuzz ഉപയോഗിച്ച് Switzer റോളുകൾ ഷേപ്പ് ചെയ്യുകയും അവയെ വെക്റ്റർ ഔട്ട്ലൈനുകളായി (`<defs>` പാത്തുകളും `<use>`-ഉം) വരയ്ക്കുകയും ചെയ്യുന്നു; Switzer-ൽ ഇല്ലാത്ത അമ്പുകളും ജ്യാമിതീയ ചിഹ്നങ്ങളും അതിന്റെ സ്വന്തം മെട്രിക്കുകൾ ഉപയോഗിച്ച് വരയ്ക്കുന്നു. എംബെഡ് ചെയ്ത ഫോണ്ടല്ല, എല്ലായ്പ്പോഴും ഔട്ട്ലൈനുകൾ മാത്രം: Switzer-ന്റെ ലൈസൻസ് (`packages/ui-kit/src/fonts/FFL.txt`) രേഖാമൂലമുള്ള സമ്മതമില്ലാതെ സബ്സെറ്റിങ്ങും ഫോർമാറ്റ് പരിവർത്തനവും നിരോധിക്കുകയും വെക്റ്റർ ഡ്രോയിങ്ങുകൾ അനുവദിക്കുകയും ചെയ്യുന്നതിനാൽ, Switzer `@font-face` അല്ലെങ്കിൽ `data:` URI വീണ്ടും ഉൾപ്പെടുത്തരുത്. ഫയലിൽ അവശേഷിക്കുന്ന ഒരേയൊരു ഫോണ്ട് യഥാർത്ഥ കോഡ് ടെക്സ്റ്റായി തുടരുന്നവയ്ക്കുള്ള OFL IBM Plex Mono സബ്സെറ്റാണ് (`scripts/docs/readme-fonts.mjs`); ആ പ്രതീകങ്ങളിൽ നിന്നാണ് ഇത് നിർമ്മിക്കുന്നത്, എംബെഡ് ചെയ്യാൻ കഴിയാത്ത ഏതൊരു ഗ്ലിഫും പിശക് സൃഷ്ടിക്കും.
- **വീണ്ടും ജനറേറ്റ് ചെയ്യുക.** `npm run docs:readme-diagrams` README ക്രമത്തിൽ പന്ത്രണ്ടെണ്ണവും വീണ്ടും എഴുതുകയും ഓരോ ഫയലിനും അതിന്റെ വലുപ്പം ഉൾപ്പെടുന്ന ഒരു വരി പ്രിന്റ് ചെയ്യുകയും ചെയ്യുന്നു. ഒറ്റ ജനറേറ്ററും തനിച്ച് പ്രവർത്തിപ്പിക്കാം (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget`-ന്റെ കണക്കുകൾ `open-sse/config/freeModelCatalog.ts`-ലെ ലൈവ് കാറ്റലോഗ് ലോഡറിൽ നിന്നാണ് വരുന്നത് എന്നതിനാൽ അതിന് `node --import tsx/esm` ആവശ്യമാണ്; കാറ്റലോഗ് മാറ്റത്തിന്റെ CI പ്രത്യാഘാതം `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict`-ൽ ഉണ്ട്). ജനറേറ്ററും SVG-യും ഒരുമിച്ച് കമ്മിറ്റ് ചെയ്യുക.
- **തെളിവ്.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>`, GitHub ഒരു ഫയൽ നൽകുന്ന അതേ രീതിയിൽ
  അത് റെൻഡർ ചെയ്യുന്നു (ഒരു `<img>` ടാഗ്, camo-യുടെ `Content-Security-Policy`, `image/svg+xml`), ഒരു ലൈറ്റ് ഫ്രെയിമും ഒരു ഡാർക്ക് ഫ്രെയിമും ക്യാപ്ചർ ചെയ്യുകയും പേജ് നടത്തിയ ബാഹ്യ ഫോണ്ട് അഭ്യർത്ഥനകൾ റിപ്പോർട്ട് ചെയ്യുകയും ചെയ്യുന്നു (0 ആയിരിക്കണം).
- **ബജറ്റ്.** ഓരോ ഫയലും 200 KB-യിൽ താഴെയായിരിക്കണം (ഓരോ പഴക്കപരിശോധനയും ഇത് ഉറപ്പാക്കുന്നു); ഏതൊരു README
  ഇമേജിനുമുള്ള പരമാവധി പരിധി 500 KB ആണ് (SVG സ്റ്റുഡിയോ വാലിഡേറ്ററിന്റെ നിയമം).
- **പകർപ്പ് മാറ്റമില്ലാതെ, എണ്ണങ്ങൾ ഗേറ്റിൽ നിന്ന്.** റീബ്രാൻഡിങ്ങിൽ ടൈപ്പും പാലറ്റും മാറി, വാക്കുകൾ മാറിയില്ല: ഓരോ ജനറേറ്ററും അതിന്റെ ഡയഗ്രാമിന്റെ പകർപ്പ് ഒരു `*_COPY` സ്ഥിരാങ്കത്തിൽ ഉൾക്കൊള്ളുന്നു (അല്ലെങ്കിൽ ലൈവ് കാറ്റലോഗിൽ നിന്ന് അത് നിർമ്മിക്കുന്നു); അതുതന്നെയാണ് വരയ്ക്കുന്ന ടെക്സ്റ്റും ഔട്ട്ലൈൻ ഘട്ടത്തിന്റെ ഇൻപുട്ടും. കാനോനിക്കൽ കണക്കുകൾ `<text>` നോഡുകളിൽ തുടരുന്നു (ഔട്ട്ലൈൻ ചെയ്തുകഴിഞ്ഞാൽ അദൃശ്യം, `fill-opacity:0`), അവ `check:docs-counts`
  (`scripts/check/check-docs-counts-sync.mjs`) വായിക്കുന്നു; ആ ഗേറ്റ് വായിക്കുന്ന ഡയഗ്രാമുകളുടെ പഴക്കപരിശോധനകൾ ജനറേറ്റ് ചെയ്ത ഫയലിൽ അതിന്റെ വാലിഡേറ്ററുകളും പ്രവർത്തിപ്പിക്കുന്നു. അതിനാൽ കോഡിൽ നിന്ന് വ്യതിചലിക്കുന്ന ഒരു കണക്ക് പരിശോധന പരാജയപ്പെടുത്തും—ജനറേറ്ററിലെ സംഖ്യയല്ല, ഗേറ്റ് വായിക്കുന്ന സോഴ്സാണ് തിരുത്തേണ്ടത്.
