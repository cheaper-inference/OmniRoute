> **ആധികാരിക ഉറവിടം:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, കൂടാതെ
> `src/app/(dashboard)/dashboard/plugins/`
> **അവസാനം പുതുക്കിയത്:** 2026-06-28 — v3.8.40

OmniRoute-ൽ WordPress മാതൃകയിലുള്ള ഒരു പ്ലഗിൻ സിസ്റ്റം ഉൾപ്പെടുത്തിയിട്ടുണ്ട്. പ്ലഗിനുകൾ സ്വയംപര്യാപ്തമായ
ഡയറക്ടറികളാണ് — ഓരോന്നിലും ഒരു `plugin.json` മാനിഫെസ്റ്റും ഒരു എൻട്രി ഫയലും ഉണ്ടായിരിക്കും — അവ
റിക്വസ്റ്റ് പൈപ്പ്ലൈനിലേക്കും (`onRequest` / `onResponse` / `onError`)
ലൈഫ്സൈക്കിൾ ഇവന്റുകളിലേക്കും (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
ഹുക്ക് ചെയ്യുന്നു.

**പ്ലഗിൻ മാർക്കറ്റ്പ്ലേസ്** ആ സിസ്റ്റത്തിന് മുകളിലുള്ള കണ്ടെത്തൽ ലെയറാണ്. ഇൻസ്റ്റാൾ ചെയ്യാവുന്ന
പ്ലഗിനുകളുടെ ബ്രൗസ് ചെയ്യാവുന്ന ഒരു കാറ്റലോഗ് ഇത് ലഭ്യമാക്കുന്നു. ഡിഫോൾട്ടായി, കാറ്റലോഗ്
ചെറിയൊരു ബിൽറ്റ്-ഇൻ സീഡ് രജിസ്ട്രിയാണ്; ഒരു ഓപ്പറേറ്റർക്ക് അതിനെ ഇഷ്ടാനുസൃത റിമോട്ട്
രജിസ്ട്രി URL-ലേക്ക് ചൂണ്ടിക്കാണിക്കാനാകും. അത്തരം സാഹചര്യത്തിൽ DNS റിസോൾവ് ചെയ്യുന്ന SSRF ഗാർഡ് ഉപയോഗിച്ച്
ഫെച്ച് കൂടുതൽ സുരക്ഷിതമാക്കുന്നു ([സുരക്ഷ](#security) കാണുക).

എല്ലാ പ്ലഗിൻ റൂട്ടുകളും **ലൂപ്പ്ബാക്കിൽ മാത്രം ലഭ്യമാണ്** (ടയർ 1 — `LOCAL_ONLY`): പ്ലഗിനുകൾ ചൈൽഡ്
പ്രോസസുകളിൽ കോഡ് ലോഡ് ചെയ്ത് എക്സിക്യൂട്ട് ചെയ്യുന്നതിനാൽ, ഓതന്റിക്കേഷൻ പരിഗണിക്കാതെ തന്നെ
ലൂപ്പ്ബാക്ക് അല്ലാത്ത ഒറിജിനുകളിൽ നിന്ന് റൂട്ടുകൾ ആക്സസ് ചെയ്യാനാവില്ല.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) കാണുക.

## ഇത് Together എങ്ങനെ യോജിക്കുന്നു

```
Dashboard (/dashboard/plugins)
  ├─ "Installed" tab  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (uninstall)
  └─ "Marketplace" tab → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ no custom URL → built-in SEED_REGISTRY
                            └─ custom URL → isSafeMarketplaceUrl() SSRF guard
                                          → safeOutboundFetch(guard:"public-only")
```

- **രജിസ്ട്രി ലെയർ** — `src/lib/plugins/marketplace.ts`: കാറ്റലോഗ് ലിസ്റ്റുചെയ്യുന്നു / തിരയുന്നു, ഏതെങ്കിലും പരാജയത്തിൽ വിത്ത് രജിസ്ട്രിയിലേക്ക് മടങ്ങുന്നു.
- **ലൈഫ്സൈക്കിൾ പാളി** — `src/lib/plugins/manager.ts` (`pluginManager` singleton): ഇൻസ്റ്റാൾ ചെയ്യുക, അപ്ഗ്രേഡ് ചെയ്യുക, സജീവമാക്കുക, നിർജ്ജീവമാക്കുക, അൺഇൻസ്റ്റാൾ ചെയ്യുക, സ്കാൻ ചെയ്യുക, സ്റ്റാർട്ടപ്പ് ലോഡ് ചെയ്യുക.
- **മാനിഫെസ്റ്റ് പാളി** — `src/lib/plugins/manifest.ts`: Zod `plugin.json` + ഡിഫോൾട്ടുകൾ.
- **സ്കാനർ** — `src/lib/plugins/scanner.ts`: പ്ലഗിൻ ഡയറക്ടറിക്ക് കീഴിലുള്ള ഡിസ്കിൽ പ്ലഗിനുകൾ കണ്ടെത്തുന്നു.
- **ലോഡർ** — `src/lib/plugins/loader.ts`: ഓരോ പ്ലഗിനും ഒരു പ്രത്യേക Node.js ചൈൽഡ് പ്രോസസിൽ രൂപപ്പെടുത്തുകയും ബ്രോക്കർമാരുടെ കോളുകൾ IPC വഴി ഹുക്ക് ചെയ്യുകയും ചെയ്യുന്നു. കുട്ടി ഒരു സാൻഡ്ബോക്സ് അല്ല (ചുവടെയുള്ള "പ്ലഗിൻ എക്സിക്യൂഷൻ ഐസൊലേഷൻ" കാണുക).

## മാർക്കറ്റ്പ്ലേസ് കാറ്റലോഗ്

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`)
`MarketplaceEntry` ഒബ്ജക്റ്റുകളുടെ ഒരു ലിസ്റ്റ് നൽകുന്നു:

| ഫീൽഡ്         | തരം      | കുറിപ്പുകൾ                                        |
| ------------- | -------- | ------------------------------------------------- |
| `name`        | string   | kebab-case പ്ലഗിൻ നാമം                            |
| `version`     | string   | semver                                            |
| `description` | string   | ഹ്രസ്വ സംഗ്രഹം                                    |
| `author`      | string   | രചയിതാവ് / സ്ഥാപനം                                |
| `license`     | string   | SPDX മാതൃകയിലുള്ള ലൈസൻസ് ഐഡി                      |
| `downloadUrl` | string   | സോഴ്സ് ഡൗൺലോഡ് URL (ശൂന്യമാകാം)                   |
| `repository`  | string?  | ഐച്ഛിക റെപ്പോസിറ്ററി URL                          |
| `tags`        | string[] | തിരയൽ/ഫിൽട്ടർ ടാഗുകൾ                              |
| `downloads`   | number   | ഡൗൺലോഡ് എണ്ണം                                     |
| `rating`      | number   | 0–5                                               |
| `verified`    | boolean  | എൻട്രി സ്ഥിരീകരിച്ചതായി അടയാളപ്പെടുത്തിയിട്ടുണ്ടോ |
| `lastUpdated` | string   | ISO മാതൃകയിലുള്ള തീയതി സ്ട്രിംഗ്                  |

ഇഷ്ടാനുസൃത രജിസ്ട്രി URL കോൺഫിഗർ ചെയ്തിട്ടില്ലെങ്കിൽ, കാറ്റലോഗ് ബിൽറ്റ്-ഇൻ
`SEED_REGISTRY` ആയിരിക്കും (നിലവിൽ `request-logger`, `rate-limiter`, `cost-tracker`,
കൂടാതെ `theme-manager`). സീഡ് രജിസ്ട്രി എല്ലായ്പ്പോഴും ലഭ്യമാണ് — കോൺഫിഗർ ചെയ്ത റിമോട്ട്
രജിസ്ട്രി ലഭ്യമല്ലെങ്കിലോ, `200` അല്ലാത്ത സ്റ്റാറ്റസ് നൽകിയാലോ, തിരിച്ചറിയാനാകാത്ത
ബോഡി നൽകിയാലോ, `listMarketplacePlugins()` ഒരു മുന്നറിയിപ്പ് ലോഗ് ചെയ്ത് സീഡ് ലിസ്റ്റിലേക്ക് മടങ്ങും.

> കുറിപ്പ്: മാർക്കറ്റ്പ്ലേസ് **കാറ്റലോഗ്** (ബ്രൗസ്/തിരയൽ) പൂർണമായി ബന്ധിപ്പിച്ചിട്ടുണ്ടെങ്കിലും,
> കാറ്റലോഗിൽ നിന്നുള്ള ഒറ്റ-ക്ലിക്ക് മാർക്കറ്റ്പ്ലേസ് **ഇൻസ്റ്റാൾ** ഇതുവരെ നടപ്പിലാക്കിയിട്ടില്ല —
> ഒരു മാർക്കറ്റ്പ്ലേസ് എൻട്രിയിലെ ഡാഷ്ബോർഡിന്റെ "ഇൻസ്റ്റാൾ" ബട്ടൺ നിലവിൽ
> "ഉടൻ വരുന്നു" എന്ന അറിയിപ്പ് കാണിക്കുന്നു. ഇപ്പോൾ ഇൻസ്റ്റലേഷൻ ലോക്കൽ-പാത്ത് ഇൻസ്റ്റാൾ
> ഫ്ലോ (`POST /api/plugins`) വഴിയും ഡിസ്കിലെ കണ്ടെത്തൽ (`POST /api/plugins/scan`) വഴിയുമാണ് നടക്കുന്നത്.

## REST API

എല്ലാ എൻഡ് പോയിൻ്റുകൾക്കും മാനേജ്മെൻ്റ് ഓത്ത് ആവശ്യമാണ് (`requireManagementAuth`)** ഒപ്പം** ലൂപ്പ്ബാക്ക് മാത്രമുള്ള — `/api/plugins`, `/api/plugins/` `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) ൽ ലിസ്റ്റ് ചെയ്തിരിക്കുന്നു.

| അവസാന പോയിൻ്റ്                     | രീതി   | വിവരണം                                                                   |
| ---------------------------------- | ------ | ------------------------------------------------------------------------ |
| `/api/plugins`                     | GET    | ഇൻസ്റ്റാൾ ചെയ്ത പ്ലഗിനുകൾ ലിസ്റ്റ് ചെയ്യുക (ഓപ്ഷണൽ `?status=` ഫിൽട്ടർ)   |
| `/api/plugins`                     | POST   | പ്ലഗിൻ ഉറവിട ഡയറക്ടറിയിൽ നിന്ന് ഒരു പ്ലഗിൻ ഇൻസ്റ്റാൾ ചെയ്യുക             |
| `/api/plugins/scan`                | POST   | പ്ലഗിൻ ഡയറക്ടറി സ്കാൻ ചെയ്ത് പുതിയ പ്ലഗിനുകൾ രജിസ്റ്റർ ചെയ്യുക           |
| `/api/plugins/marketplace`         | GET    | മാർക്കറ്റ് പ്ലേസ് കാറ്റലോഗ് എൻട്രികൾ ലിസ്റ്റ് ചെയ്യുക                    |
| `/api/plugins/marketplace/install` | POST   | പേരിൽ ഒരു മാർക്കറ്റ്പ്ലേസ് പ്ലഗിൻ ഇൻസ്റ്റാൾ ചെയ്യുക                      |
| `/api/plugins/[name]`              | GET    | ഇൻസ്റ്റാൾ ചെയ്ത പ്ലഗിൻ വിശദാംശങ്ങൾ നേടുക                                 |
| `/api/plugins/[name]`              | DELETE | ഒരു പ്ലഗിൻ അൺഇൻസ്റ്റാൾ ചെയ്യുക                                           |
| `/api/plugins/[name]/activate`     | POST   | സജീവമാക്കുക ( + രജിസ്റ്റർ ഹുക്കുകൾ ലോഡ് ചെയ്യുക)                         |
| `/api/plugins/[name]/deactivate`   | POST   | നിർജ്ജീവമാക്കുക (ഫയർ `onDeactivate`, ഹുക്കുകൾ രജിസ്റ്റർ ചെയ്യാതിരിക്കുക) |
| `/api/plugins/[name]/config`       | GET    | പ്ലഗിൻ കോൺഫിഗറേഷൻ + കോൺഫിഗറേഷൻ സ്കീമ നേടുക                               |
| `/api/plugins/[name]/config`       | PUT    | പ്ലഗിൻ കോൺഫിഗറേഷൻ അപ്ഡേറ്റ് ചെയ്യുക (സ്കീമയ്ക്കെതിരെ സാധൂകരിക്കുന്നത്)   |

`GET /api/plugins` `status` ഫിൽട്ടർ `installed` / `active` / `inactive` / `error` എന്നിവയിലൊന്ന് സ്വീകരിക്കുന്നു. ഒരു അസാധുവായ മൂല്യം `400` നൽകുന്നു.

### ഇൻസ്റ്റാൾ ചെയ്ത പ്ലഗിനുകൾ ലിസ്റ്റ് ചെയ്യുക

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### ഒരു പ്രാദേശിക പാതയിൽ നിന്ന് ഇൻസ്റ്റാൾ ചെയ്യുക

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` ഒരു ആയിരിക്കണം** കേവല** ഒരു ഡയറക്ടറിയിലേക്കുള്ള പാത** പ്ലഗിൻ സോഴ്സ് ഡയറക്ടറിക്കുള്ളിൽ** : പ്ലഗിൻ റൂട്ടിന് അടുത്തായി `plugin-sources`, അതിനാൽ സ്ഥിരസ്ഥിതിയായി `~/.omniroute/plugin-sources/`, അല്ലെങ്കിൽ ആ വേരിയബിൾ സജ്ജമാക്കുമ്പോൾ `<parent of OMNIROUTE_PLUGINS_DIR>/plugin-sources/` (`getPluginSourcesDir()` ൽ `src/lib/plugins/installSource.ts`). ആദ്യം അവിടെ പ്ലഗിൻ പകർത്തുകയോ ക്ലോൺ ചെയ്യുകയോ ചെയ്യുക. പാതയിൽ `..` അല്ലെങ്കിൽ ഒരു നൾ ബൈറ്റ് അടങ്ങിയിരിക്കുമ്പോൾ, ആ ഡയറക്ടറിക്ക് പുറത്ത് കിടക്കുമ്പോൾ, അതിന് പുറത്ത് ഒരു സിംലിങ്കിലൂടെ പരിഹരിക്കപ്പെടുമ്പോൾ, അതിന് പുറത്തുള്ള ടാർഗെറ്റ് ഉള്ള ഒരു സിംലിങ്ക് അടങ്ങിയിരിക്കുമ്പോൾ, അല്ലെങ്കിൽ ഡയറക്ടറി നിലവിലില്ലാത്തപ്പോൾ ഇൻസ്റ്റാളേഷൻ `400`. ഉറവിട ഡയറക്ടറിയിൽ സാധുവായ ഒരു `plugin.json` ഉണ്ടായിരിക്കണം (അല്ലെങ്കിൽ ഒരാളുടെ രക്ഷിതാവായിരിക്കണം). വിജയിക്കുമ്പോൾ, ഇൻസ്റ്റാൾ ചെയ്ത പ്ലഗിൻ റോയ്ക്കൊപ്പം പ്രതികരണം `201` ആണ്.

മറ്റ് പ്ലഗിൻ റൂട്ടുകളിൽ നിന്ന് വ്യത്യസ്തമായി, ലോഗിൻ അപ്രാപ്തമാക്കിയിരിക്കുമ്പോൾ പോലും ഇതിന് മാനേജ്മെൻ്റ് ക്രെഡൻഷ്യൽ (ഒരു ഡാഷ്ബോർഡ് സെഷൻ അല്ലെങ്കിൽ മാനേജ്-സ്കോപ്പ്ഡ് API കീ) ആവശ്യമാണ് (`requireLogin=false`): കോഡ് ഇൻസ്റ്റാൾ ചെയ്യുന്നത് ഒരിക്കലും ഒരു അജ്ഞാത പ്രവർത്തനമല്ല. `POST /api/plugins/marketplace/install` (ബോഡി `{ "name": "<plugin>" }`) യ്ക്കും ഇത് ബാധകമാണ്.

### ചന്തസ്ഥലം ബ്രൗസ് ചെയ്യുക

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### പ്ലഗിൻ കോൺഫിഗറേഷൻ അപ്ഡേറ്റ് ചെയ്യുക

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`src/lib/plugins/manifest.ts` ൽ നിന്ന് `validatePluginConfig()` ഉപയോഗിച്ച് പ്ലഗിൻ്റെ `configSchema` (മാനിഫെസ്റ്റിൽ പ്രഖ്യാപിച്ചത്) വിരുദ്ധ ബോഡിയെ`PUT .../config` സാധൂകരിക്കുന്നു: എല്ലാ കീകളും സ്കീമയിൽ പ്രഖ്യാപിക്കണം, മൂല്യങ്ങൾ പ്രഖ്യാപിത തരവുമായി പൊരുത്തപ്പെടണം, `number` ഫീൽഡുകൾ `min`/`max` മായി പൊരുത്തപ്പെടണം, കൂടാതെ `select` ഫീൽഡുകൾ പ്രഖ്യാപിത `enum` യുമായി പൊരുത്തപ്പെടണം. ഏതെങ്കിലും ലംഘനം `400` നൽകുന്നു, ഒന്നും സംഭരിക്കില്ല. `configSchema` ഇല്ലെന്ന് പ്രഖ്യാപിക്കുന്ന ഒരു പ്ലഗിൻ കോൺഫിഗർ ചെയ്യാവുന്ന കീകളില്ല, അതിനാൽ `400` ഉപയോഗിച്ച് അഭ്യർത്ഥന നിരസിക്കുന്നു ("പ്ലഗിൻ കോൺഫിഗർ ചെയ്യാവുന്ന കീകളൊന്നും പ്രഖ്യാപിക്കുന്നില്ല").

## കോൺഫിഗറേഷൻ

### പ്ലഗിൻ ഡയറക്ടറി

പ്ലഗിനുകൾ OmniRoute ഡാറ്റാ ഡയറക്ടറിക്കു കീഴിലാണ് സ്ഥിതിചെയ്യുന്നത്:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (അല്ലെങ്കിൽ manifest.main ചൂണ്ടിക്കാണിക്കുന്ന മറ്റെന്തെങ്കിലും)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ആ ഡയറക്ടറി മൂന്ന്
ഘട്ടങ്ങളിലായി നിർണ്ണയിക്കുന്നു:

1. **`OMNIROUTE_PLUGINS_DIR`**, സജ്ജീകരിച്ചിട്ടുണ്ടെങ്കിൽ — `HOME` എന്ത് പറഞ്ഞാലും, നൽകിയതുപോലെതന്നെ ഉപയോഗിക്കും. സാധാരണയായി കണ്ടെയ്നറിന്റെ ഹോം ഡയറക്ടറിയുമായി യാതൊരു ബന്ധവുമില്ലാത്ത ഒരു പാത്തിൽ പ്ലഗിൻ ട്രീ ബൈൻഡ്-മൗണ്ട് ചെയ്യുന്ന Docker/K8s-നുള്ള വ്യക്തമായ ക്രമീകരണമാണിത് (#11827).
2. `<home>/.omniroute/plugins`, ഇവിടെ `<home>` എന്നത് `HOME` / `USERPROFILE`
   എൻവയോൺമെന്റ് വേരിയബിളുകളിൽനിന്ന് ലഭിക്കുന്നു.
3. പ്രോസസ് ഹോം ഒന്നും എക്സ്പോർട്ട് ചെയ്യുന്നില്ലെങ്കിൽ `/tmp/.omniroute/plugins`.

ഏത് ഇൻപുട്ടാണ് പ്രാബല്യത്തിൽ വന്നതെന്ന് (`OMNIROUTE_PLUGINS_DIR`, `home`, അല്ലെങ്കിൽ `no-home-fallback`) വ്യക്തമാക്കിക്കൊണ്ട്, നിർണ്ണയിച്ച ഡയറക്ടറി സ്റ്റാർട്ടപ്പിൽ ഒരിക്കൽ `scanner.dir_resolved` ആയി ലോഗ് ചെയ്യപ്പെടുന്നു — അതിനാൽ, നിശ്ശബ്ദമായി ഘട്ടം 3-ൽ എത്തുന്ന ഒരു ഇമേജ് ശൂന്യമായ പ്ലഗിൻ ലിസ്റ്റ് മാത്രം റിപ്പോർട്ട് ചെയ്യാതെ അക്കാര്യം വ്യക്തമാക്കുകയും ചെയ്യും.
അവിടെ സാധുവായ `plugin.json` ഉൾക്കൊള്ളുന്ന ഏതൊരു സബ്ഡയറക്ടറിയെയും `POST /api/plugins/scan` കണ്ടെത്തി രജിസ്റ്റർ ചെയ്യും; `pluginManager.install()` പ്ലഗിനുകൾ പകർത്തുന്നതിന്റെ റൂട്ടും ഇതേ ഡയറക്ടറിയാണ്, അതിനാൽ ഒരു ഓവർറൈഡ് ഡിസ്കവറിയെയും ഇൻസ്റ്റാളേഷനെയും ഒരുമിച്ച് മാറ്റുന്നു.

> **`OMNIROUTE_PLUGINS_DIR` എന്നത് `OMNIROUTE_PLUGIN_PATH` അല്ല.** `omniroute`
> സബ്കമാൻഡുകൾ ചേർക്കുന്ന `omniroute-cmd-*` npm പാക്കേജുകൾ കണ്ടെത്താൻ CLI കമാൻഡ്-പ്ലഗിൻ ലോഡർ
> (`bin/cli/plugins.mjs`) മാത്രമാണ് രണ്ടാമത്തേത് വായിക്കുന്നത് — ഇവിടെ വിവരിച്ചിരിക്കുന്ന റൺടൈം സ്കാനറിൽ
> അതിന് യാതൊരു സ്വാധീനവുമില്ല. അതിനെക്കുറിച്ച് അറിയാൻ [PLUGINS.md](./PLUGINS.md) കാണുക.

### ഇഷ്ടാനുസൃത മാർക്കറ്റ്പ്ലേസ് രജിസ്ട്രി URL

മാർക്കറ്റ്പ്ലേസ് കാറ്റലോഗിന്റെ സോഴ്സ് `pluginMarketplaceUrl` ക്രമീകരണത്തിൽനിന്നാണ് വായിക്കുന്നത്
(`src/lib/plugins/marketplace.ts`, `settings.pluginMarketplaceUrl` വായിക്കുന്നു). ഒരു
`http(s)` URL ആയി സജ്ജീകരിക്കുമ്പോൾ, `listMarketplacePlugins()` ആ URL ഫെച്ച് ചെയ്യുകയും,
എൻട്രികളുടെ ടോപ്പ്-ലെവൽ JSON അറേയോ `plugins` അറേയുള്ള ഒരു ഒബ്ജക്റ്റോ സ്വീകരിക്കുകയും ചെയ്യും;
സ്ട്രിംഗ് `name` ഇല്ലാത്ത എൻട്രികൾ ഫിൽട്ടർ ചെയ്ത് നീക്കും. ഇത് സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ (അല്ലെങ്കിൽ ഫെച്ച്
SSRF ഗാർഡിൽ പരാജയപ്പെടുകയോ മോശം പ്രതികരണം ലഭിക്കുകയോ ചെയ്താൽ), ബിൽറ്റ്-ഇൻ സീഡ് രജിസ്ട്രിയാണ്
ഉപയോഗിക്കുന്നത്.

ഡാഷ്ബോർഡിലെ "Marketplace" ടാബ് ഈ URL-നായി ഒരു ഫീൽഡ് നൽകുന്നു (`GET /api/settings`-ൽനിന്ന്
തിരികെ വായിക്കുന്നു).

> ഇംപ്ലിമെന്റേഷൻ കുറിപ്പ്: ഡാഷ്ബോർഡിലെ "Save" പ്രവർത്തനം
> `pluginMarketplaceUrl` എന്നത് `PATCH /api/settings`-ലേക്ക് അയയ്ക്കുന്നു. ഇത് എഴുതുന്ന സമയത്ത്,
> ഈ കീ `updateSettingsSchema`-യിൽ
> (`src/shared/validation/settingsSchemas.ts`) പ്രഖ്യാപിച്ചിട്ടില്ല; അതിനാൽ ഇതിനെ ആശ്രയിക്കുന്നതിന് മുമ്പ്
> നിങ്ങളുടെ റിലീസിൽ പെർസിസ്റ്റൻസ് പരിശോധിക്കുക — ക്രമീകരണ സ്റ്റോറിൽ കീ നിലവിലുണ്ടായാൽ **റീഡ്**
> പാത്ത് (`getSettings()` → `listMarketplacePlugins()`) അതിനെ മാനിക്കും.

## സുരക്ഷ

### റൂട്ട് ടയർ — ലൂപ്പ്ബാക്ക് മാത്രം

പ്ലഗിനുകൾ സ്പോൺഡ് ചൈൽഡ് പ്രോസസുകളിൽ കോഡ് എക്സിക്യൂട്ട് ചെയ്യുന്നു, അതിനാൽ മുഴുവൻ `/api/plugins` ഉപരിതലവും `LOCAL_ONLY` (ടയർ 1) തരംതിരിക്കുന്നു. ലൂപ്പ്ബാക്ക് എൻഫോഴ്സ്മെൻ്റ് നിരുപാധികമായി പ്രവർത്തിക്കുന്നു** മുമ്പ്** ഏതെങ്കിലും ആധികാരിക പരിശോധന, അതിനാൽ ഒരു തുരങ്കത്തിലൂടെ ബോക്സിൽ എത്തുന്ന ചോർന്ന മാനേജ്മെൻ്റ് ടോക്കണിന് ഇപ്പോഴും ഒരു പ്ലഗിൻ ഇൻസ്റ്റാൾ ചെയ്യാനോ സജീവമാക്കാനോ അൺഇൻസ്റ്റാൾ ചെയ്യാനോ കഴിയില്ല. [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md), ഹാർഡ് റൂൾസ് #15 / #17 എന്നിവ കാണുക.

### മാർക്കറ്റ്പ്ലേസ് രജിസ്ട്രി SSRF ഗാർഡ്

ഒരു ഇഷ്ടാനുസൃത രജിസ്ട്രി URL ആക്രമണകാരിയെ സ്വാധീനിക്കാവുന്ന കോൺഫിഗറേഷനാണ്, അതിനാൽ അത് ലഭ്യമാക്കുന്നതിന് മുമ്പ് `listMarketplacePlugins()` അത് രണ്ട് പാളികളിലൂടെ പ്രവർത്തിപ്പിക്കുന്നു:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` അല്ലാത്ത എന്തും നിരസിക്കുന്നു.
   - അക്ഷരാർത്ഥത്തിലുള്ള private/loopback/link-local/ULA ഹോസ്റ്റുകൾ നിരസിക്കുന്നു (IPv4** ഒപ്പം** IPv6, IPv4-mapped ഉൾപ്പെടെ) കാനോനിക്കൽ `isPrivateHost` (`src/shared/network/outboundUrlGuard.ts`) വഴി.
   - പരിഹരിക്കുന്നു** രണ്ടും** `A`, `AAAA` രേഖപ്പെടുത്തുകയും എങ്കിൽ നിരസിക്കുകയും ചെയ്യുന്നു** ഏതെങ്കിലും** പരിഹരിച്ച വിലാസം സ്വകാര്യ — ആണ്, പൊതു-ഹോസ്റ്റ് നാമം → പ്രൈവറ്റ്-IP ബൈപാസ് അടയ്ക്കുന്നു.
   - **പരാജയം അടച്ചു** : ഒരു DNS റെസലൂഷൻ പരാജയം URL നിരസിക്കുന്നു.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`** (`src/shared/network/safeOutboundFetch.ts`): ലഭ്യമാക്കുന്ന സമയത്ത് പൊതുജനങ്ങൾക്ക് മാത്രമുള്ള URL ഗാർഡ് വീണ്ടും പ്രയോഗിക്കുന്നു** തിരിച്ചുവിടലുകൾ തടയുന്നു** (പൊതു → സ്വകാര്യ `30x` പിവറ്റ് ഇല്ല).

ഒന്നുകിൽ പരാജയപ്പെടുന്ന ഒരു URL അഭ്യർത്ഥന — നിർത്തലാക്കില്ല, മാർക്കറ്റ് പ്ലേസ് നിശബ്ദമായി അന്തർനിർമ്മിത വിത്ത് രജിസ്ട്രിയിലേക്ക് മടങ്ങുകയും ഒരു മുന്നറിയിപ്പ് ലോഗ് ചെയ്യുകയും ചെയ്യുന്നു.

> A + AAAA പരിഹരിക്കാനും IPv4-only പരിശോധനയ്ക്ക് പകരം കാനോനിക്കൽ `isPrivateHost` ഉപയോഗിക്കാനും ഈ ഗാർഡ് പ്രത്യേകമായി PR #3774 ൽ കഠിനമാക്കി.

### പ്ലഗിൻ എക്സിക്യൂഷൻ ഐസൊലേഷൻ

> **പ്ലഗിനുകൾ സ്ഥിരസ്ഥിതിയായി സാൻഡ്ബോക്സ് ചെയ്തിട്ടില്ല.** കുട്ടി OmniRoute ഉപയോക്താവായി പ്രവർത്തിക്കുന്ന ഒരു സാധാരണ Node.js പ്രക്രിയയാണ്, VM സന്ദർഭവും Node.js അനുമതി ഫ്ലാഗുകളുമില്ല, അതിനാൽ പ്ലഗിൻ കോഡിന് ഉപയോക്താവിന് കഴിയുന്ന ഏത് ഫയലും വായിക്കാനും എഴുതാനും പ്രോഗ്രാമുകൾ പ്രവർത്തിപ്പിക്കാനും നെറ്റ്വർക്കിൽ എത്താനും കഴിയും. കുട്ടിക്ക് ഏതൊക്കെ എൻവയോൺമെൻ്റ് വേരിയബിളുകൾ ലഭിക്കുമെന്ന് മാത്രം `requires.permissions` തീരുമാനിക്കുന്നു; മറ്റ് അനുമതികൾ നടപ്പിലാക്കിയിട്ടില്ല. ഓപ്റ്റ്-ഇൻ `PLUGIN_PERMISSION_MODEL_ENABLED` ഫീച്ചർ ഫ്ലാഗ് (ഡിഫോൾട്ടായി ഓഫ്) ഓരോ പ്ലഗിനും പ്രവർത്തിപ്പിക്കുന്നത്, ആ അനുമതികളിൽ നിന്ന് നിർമ്മിച്ച Node.js അനുമതി മോഡലിന് കീഴിലാണ്, `network` ഒഴികെ, Node.js ന് നിയന്ത്രിക്കാൻ കഴിയില്ല ( [`PLUGIN_SDK.md`](./PLUGIN_SDK.md#%E0%B4%85%E0%B4%A8%E0%B5%81%E0%B4%AE%E0%B4%A4%E0%B4%BF-%E0%B4%B8%E0%B4%82%E0%B4%B5%E0%B4%BF%E0%B4%A7%E0%B4%BE%E0%B4%A8%E0%B4%82) കാണുക). നിങ്ങൾ വിശ്വസിക്കുന്ന പ്ലഗിനുകൾ മാത്രം ഇൻസ്റ്റാൾ ചെയ്യുക. താഴെയുള്ള പ്രോസസ്സ് അതിർത്തിയിൽ ക്രാഷുകളും ഹാങ്ങുകളും അടങ്ങിയിരിക്കുന്നു; അതൊരു സുരക്ഷാ അതിർത്തിയല്ല.

- **പ്രോസസ് ഐസൊലേഷൻ** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ഓരോ പ്ലഗിനും ഒരു പ്രത്യേക Node.js ചൈൽഡ് പ്രോസസിൽ സൃഷ്ടിക്കുകയും IPC വഴി ആശയവിനിമയം നടത്തുകയും ചെയ്യുന്നു. ഹുക്ക് കോളുകൾക്ക് `SIGTERM` → `SIGKILL` വർദ്ധനയോടെ സമയപരിധിയുണ്ട്.
- **എൻവി അനുവദനീയ പട്ടിക** — അനുവദനീയമായ പരിസ്ഥിതി വേരിയബിളുകളുടെ ഒരു കൂട്ടം മാത്രമേ കുട്ടിക്ക് ലഭിക്കൂ; മാനിഫെസ്റ്റ് `env` അനുമതി അഭ്യർത്ഥിക്കുമ്പോൾ മാത്രമേ വിശാലമായ സെറ്റ് അനുവദിക്കൂ.
- **ഉറവിട കണ്ടെയ്ൻമെൻ്റ് ഇൻസ്റ്റാൾ ചെയ്യുക** — `POST /api/plugins` പ്ലഗിൻ സോഴ്സ് ഡയറക്ടറിയിൽ നിന്ന് മാത്രമേ വായിക്കുകയുള്ളൂ ("ഒരു പ്രാദേശിക പാതയിൽ നിന്ന് ഇൻസ്റ്റാൾ ചെയ്യുക" കാണുക): പാത `realpath` ഉപയോഗിച്ച് കാനോനിക്കലൈസ് ചെയ്തിരിക്കുന്നു, ആ ഡയറക്ടറിയിൽ കർശനമായി നിൽക്കണം, കൂടാതെ ഒരു സിംലിങ്ക് വഹിക്കുന്ന ഒരു സോഴ്സ് ട്രീ അത് പകർത്തുന്നതിന് മുമ്പ് നിരസിക്കപ്പെടും.
- **പാതയുടെ നിയന്ത്രണം** — install/upgrade/uninstall പ്ലഗിൻ ഡയറക്ടറിയും `manifest.main` പരിഹരിക്കുമെന്ന് ഉറപ്പുനൽകുന്നു** ഉള്ളിൽ** ഏതെങ്കിലും പകർപ്പ് അല്ലെങ്കിൽ ആവർത്തന ഡിലീറ്റ് ചെയ്യുന്നതിന് മുമ്പായി നിയന്ത്രിത പ്ലഗിൻ റൂട്ട് (തകർച്ച വരുത്തിയ DB പാത്തുകൾക്കെതിരെയും `manifest.main` ലെ `../` ട്രാവർസലിനെതിരെയും സംരക്ഷണം നൽകുന്നു). സജീവമാക്കൽ `realpath` വഴിയുള്ള സിംലിങ്കുകൾ പരിഹരിക്കുകയും പ്ലഗിൻ ഡയറക്ടറിയിൽ നിന്ന് രക്ഷപ്പെടുന്ന ഒരു എൻട്രി പോയിൻ്റ് ലോഡ് ചെയ്യാൻ വിസമ്മതിക്കുകയും ചെയ്യുന്നു.
- **ഓപ്ഷണൽ ഇൻ്റഗ്രിറ്റി പിൻ** — ഒരു മാനിഫെസ്റ്റ് ഒരു `integrity` (`sha256-<base64>`, SRI ഫോർമാറ്റ്) ഫീൽഡ് പ്രഖ്യാപിച്ചേക്കാം. നിലവിലുള്ളപ്പോൾ, ലോഡർ, ലോഡ് സമയത്ത് എൻട്രി ഫയൽ ഹാഷ് പരിശോധിക്കുന്നു, പൊരുത്തക്കേടിൽ സജീവമാക്കാൻ വിസമ്മതിക്കുന്നു. ഇത് ഓപ്റ്റ്-ഇൻ ടാമ്പർ-ഡിറ്റക്ഷൻ ആണ്,** അല്ല** ഒരു സുരക്ഷാ അതിർത്തി: ഒരു ലോഡുചെയ്ത പ്ലഗിന് ചെയ്യാൻ കഴിയുന്നതിനെ ഇത് പരിമിതപ്പെടുത്തുന്നില്ല.
- **ഹുക്കുകളിൽ ക്ലയൻ്റ് ക്രെഡൻഷ്യലുകളൊന്നുമില്ല** —, `onRequest`, `onResponse`, `onError` എന്നിവയിലേക്ക് കൈമാറിയ സന്ദർഭം `authorization`, `x-api-key`, `proxy-authorization`, `cookie` തലക്കെട്ടുകൾ നീക്കം ചെയ്തു, കൂടാതെ API കീ റെക്കോർഡിന് കീ മൂല്യം ഇല്ല ( `src/lib/plugins/hooks.ts` ൽ `redactPluginContext()` ).

## മാനിഫെസ്റ്റ് (`plugin.json`)

സാധൂകരിച്ചത് `PluginManifestSchema` (`src/lib/plugins/manifest.ts`):

| ഫീൽഡ്              | ടൈപ്പ് ചെയ്യുക | കുറിപ്പുകൾ                                                          |
| ------------------ | -------------- | ------------------------------------------------------------------- |
| `name`             | ചരട്           | ആവശ്യമാണ്; കബാബ്-കേസ് (`^[a-z0-9-]+$`), 1-100 അക്ഷരങ്ങൾ             |
| `version`          | ചരട്           | ആവശ്യമാണ്; സെംവർ (`MAJOR.MINOR.PATCH`)                              |
| `description`      | ചരട്?          | ≤ 500 അക്ഷരങ്ങൾ                                                     |
| `author`           | ചരട്?          | ≤ 200 അക്ഷരങ്ങൾ                                                     |
| `license`          | ചരട്?          | `MIT` ലേക്കുള്ള ഡിഫോൾട്ടുകൾ                                         |
| `main`             | ചരട്?          | എൻട്രി ഫയൽ; സ്ഥിരസ്ഥിതിയായി `index.js`                              |
| `source`           | എന്നോ?         | `local` \| `marketplace` (defaults to `local`)                      |
| `tags`             | സ്ട്രിംഗ്[]?   | ടാഗുകൾ തിരയുക                                                       |
| `requires`         | വസ്തു?         | `{ omniroute?, permissions[] }`                                     |
| `hooks`            | വസ്തു?         | പ്ലഗിൻ നടപ്പിലാക്കുന്ന ഹുക്ക് ഏതെന്ന് പ്രഖ്യാപിക്കുന്ന ബൂലിയൻസ്     |
| `skills`           | ഒബ്ജക്റ്റ്[]?  | ഓപ്ഷണൽ നൈപുണ്യ നിർവചനങ്ങൾ                                           |
| `enabledByDefault` | ബൂളിയൻ?        | ഇൻസ്റ്റാൾ ചെയ്യുമ്പോൾ സ്വയമേവ സജീവമാക്കുക                           |
| `configSchema`     | വസ്തു?         | കോൺഫിഗറേഷൻ ഫീൽഡുകളുടെ മാപ്പ് (`string`/`number`/`boolean`/`select`) |
| `integrity`        | ചരട്?          | ഓപ്ഷണൽ `sha256-<base64>` എൻട്രി-ഫയൽ പിൻ                             |

`network` / `file-read` / `file-write` / `env` / `exec` എന്നതിൽ നിന്നാണ് അനുമതികൾ ലഭിക്കുന്നത്. `env` മാത്രമേ റൺടൈം ഇഫക്റ്റ് ഉള്ളൂ (കുട്ടിക്ക് വേണ്ടിയുള്ള ഒരു ചെറിയ പരിസ്ഥിതി-വേരിയബിൾ അനുവദനീയമായ ലിസ്റ്റ്); മറ്റുള്ളവ പ്രഖ്യാപനങ്ങളാണ്, അവ നടപ്പാക്കപ്പെടുന്നില്ല.

## ലൈഫ്സൈക്കിൾ പ്രവാഹം

```
install (POST /api/plugins, പാത്ത്)
  → മാനിഫെസ്റ്റ് സ്കാൻ/സാധൂകരിക്കുക → സ്റ്റേജിങ്ങിലേക്ക് പകർത്തുക → main ഡയറക്ടറിക്കുള്ളിലാണെന്ന് ഉറപ്പാക്കുക
  → ~/.omniroute/plugins/<name>-ലേക്ക് ആറ്റോമിക് ആയി പേരുമാറ്റുക → DB വരി ചേർക്കുക
  → onInstall പ്രവർത്തിപ്പിക്കുക → enabledByDefault ആണെങ്കിൽ: activate

activate (POST /api/plugins/{name}/activate)
  → realpath കണ്ടെയ്ൻമെന്റ് പരിശോധന → loadPlugin() (ചൈൽഡ് പ്രോസസ് ആരംഭിക്കുക)
  → പ്രഖ്യാപിച്ച ഹുക്കുകൾ രജിസ്റ്റർ ചെയ്യുക → status = "active" → onActivate പ്രവർത്തിപ്പിക്കുക

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate പ്രവർത്തിപ്പിക്കുക (രജിസ്ട്രേഷൻ നീക്കുന്നതിന് മുമ്പ്) → ഹുക്കുകളുടെ രജിസ്ട്രേഷൻ നീക്കുക
  → ചൈൽഡ് പ്രോസസ് അവസാനിപ്പിക്കുക → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → സജീവമാണെങ്കിൽ deactivate ചെയ്യുക → onUninstall പ്രവർത്തിപ്പിക്കുക
  → കണ്ടെയ്ൻമെന്റ് പരിശോധിച്ച് പ്ലഗിൻ ഡയറക്ടറി ആവർത്തിതമായി ഇല്ലാതാക്കുക → DB വരി ഇല്ലാതാക്കുക
```

ഇൻസ്റ്റാൾ ചെയ്ത പതിപ്പിനേക്കാൾ **കർശനമായി പുതിയ** മാനിഫെസ്റ്റ് പതിപ്പുള്ള ഒരു
ഡയറക്ടറിയിൽ `install` വീണ്ടും പ്രവർത്തിപ്പിക്കുന്നത് സ്വയമേവ അപ്ഗ്രേഡ് ചെയ്യും
(ശുദ്ധമായ പുനഃസ്ഥാപനം; കോൺഫിഗറേഷൻ ഡിഫോൾട്ട് മൂല്യങ്ങളിലേക്ക് പുനഃസജ്ജമാകും).
അതേ പതിപ്പോ അതിലും പഴയ പതിപ്പോ നിരസിക്കപ്പെടും.

## ഡാഷ്ബോർഡ്

`/dashboard/plugins` (`src/app/(dashboard)/dashboard/plugins/page.tsx`) ലെ ഡാഷ്ബോർഡ് പേജ് രണ്ട് ടാബുകൾ നൽകുന്നു:

- **ഇൻസ്റ്റാൾ ചെയ്തു** — ഇൻസ്റ്റാൾ ചെയ്ത പ്ലഗിനുകൾ അവയുടെ പ്രഖ്യാപിത കൊളുത്തുകൾ, ഒരു activate/deactivate ടോഗിൾ, ഒരു അൺഇൻസ്റ്റാൾ ബട്ടൺ, ഒരു "പ്ലഗിനുകൾക്കായി സ്കാൻ ചെയ്യുക" പ്രവർത്തനം (`POST /api/plugins/scan`) എന്നിവ ഉപയോഗിച്ച് പട്ടികപ്പെടുത്തുന്നു.
- **ചന്തസ്ഥലം** ഇഷ്ടാനുസൃത രജിസ്ട്രി URL സജ്ജീകരിക്കുന്നതിനുള്ള ഒരു ഫീൽഡ് ഉള്ള `GET /api/plugins/marketplace` നിന്നുള്ള കാറ്റലോഗ് — കാണിക്കുന്നു.

OmniRoute പ്രോസസ്സിൻ്റെ പൂർണ്ണമായ പ്രത്യേകാവകാശങ്ങളോടെയാണ് പ്ലഗിനുകൾ പ്രവർത്തിക്കുന്നത് എന്ന മുന്നറിയിപ്പ് പേജ് എപ്പോഴും കാണിക്കുന്നു.

ഒരു പ്ലഗിൻ കോൺഫിഗറേഷൻ പേജ് `/dashboard/plugins/[name]/config` (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) ൽ പ്രവർത്തിക്കുന്നു.
