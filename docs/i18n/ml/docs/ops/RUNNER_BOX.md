സ്വയം ആതിഥേയത്വം വഹിക്കുന്ന കുളം പ്രവർത്തിക്കുന്നു**.113** ബോക്സ് (`tomni-proxmox-113`). 2026-10-18 മുതൽ ഓരോ OmniRoute ഓട്ടക്കാരനും ഉണ്ട്**ഒരു വേഷം** , ഒരു ലേബൽ, ഒരു memory/CPU ബഡ്ജറ്റ് അതിൻ്റെ ജോലിഭാരം അളക്കുന്നത്. Turbopack സ്ലോട്ടിന് ബിൽഡിന് ആവശ്യമുള്ളത് ലഭിക്കുന്നു; മറ്റ് സ്ലോട്ടുകൾ അവയുടെ അളന്ന കൊടുമുടികളിലേക്ക് വലുപ്പമുള്ളതാണ്. ഒരു Turbopack ബിൽഡ് ഒരു റിലീസ്-ഗ്രീൻ വെബ്പാക്ക് ബിൽഡും ഒരു ലിൻ്റ് ജോലിയുമായി പൊരുത്തപ്പെടുമ്പോൾ മാത്രമേ ബോക്സ് മറികടക്കുകയുള്ളൂ; ഹോസ്റ്റ് സ്വാപ്പ് (16 GB) അത് ആഗിരണം ചെയ്യുന്നു, കൂടാതെ പുൾ-അഭ്യർത്ഥന ബിൽഡുകൾ ഹോസ്റ്റുചെയ്തിരിക്കുന്നതിനാൽ, Turbopack സ്ലോട്ട് മിക്ക സമയത്തും നിഷ്ക്രിയമാണ്:

പരിധികൾ ഓരോ യൂണിറ്റിൻ്റെയും `/etc/systemd/system/actions.runner.<…>.service.d/override.conf` (മുമ്പത്തെ മൂല്യങ്ങൾ `override.conf.bak-20261018` ആയി സൂക്ഷിച്ചു ) നിലവിലുണ്ട്, കൂടാതെ `systemctl set-property --runtime … MemoryHigh=… MemoryMax=… CPUQuota=…` — പുനരാരംഭിക്കാതെ തത്സമയം പ്രയോഗിച്ചു, അതിനാൽ റണ്ണിംഗ് ജോലിയൊന്നും സ്പർശിച്ചില്ല. റണ്ണേഴ്സ് API (`gh api -X DELETE repos/<repo>/actions/runners/<id>/labels/<label>` / `gh api -X POST repos/<repo>/actions/runners/<id>/labels -f 'labels[]=<label>'`) വഴിയും ലേബലുകൾ മാറ്റുന്നു, തത്സമയം.

## കാവൽക്കാരനെ ഇൻസ്റ്റാൾ ചെയ്യുക (ഒറ്റത്തവണ, ബോക്സിൽ)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): every 30 min, log to /var/log/runner-janitor.log
*/30 * * * * MAX_ACTIVE_RUNNERS=8 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` ആവശ്യമാണ്: അത് നീക്കം ചെയ്യുന്നതിനുമുമ്പ് തുറന്ന ഫയലുകളുടെ ഒരു സ്നാപ്പ്ഷോട്ട് ഉപയോഗിച്ച് പാത്ത് നിഷ്ക്രിയമാണെന്ന് കാവൽക്കാരൻ തെളിയിക്കുന്നു, കൂടാതെ ടൂൾ ഇല്ലാതെ അത് ഒന്നും നീക്കം ചെയ്യുകയും അങ്ങനെ പറയുകയും ചെയ്യുന്നില്ല (പുറത്തുകടക്കുക 1). `--dry-run` ആദ്യം — ഉപയോഗിച്ച് എന്തെങ്കിലും മാറ്റം പരീക്ഷിച്ചുനോക്കൂ, അത് എന്തുചെയ്യുമെന്ന് കൃത്യമായി പ്രിൻ്റ് ചെയ്യുന്നു, ഒന്നും സ്പർശിക്കില്ല.

ഓരോ ഓട്ടത്തിലും അത് എന്താണ് ചെയ്യുന്നത്: നമ്മുടെ സ്വന്തം അവശിഷ്ടങ്ങൾ (`runner-*`, `omniroute-*`, `next-build*`, `e2e-build.tar.gz`) തൂത്തുവാരുന്നു**tmpfs-ൽ 3 മണിക്കൂർ** കൂടാതെ 24 h ഡിസ്കിൽ `_work/_temp`; 75 മിനിറ്റിൽ കൂടുതൽ പഴക്കമുള്ള `next-build` ൽ അലേർട്ടുകൾ നൽകുകയും അത് പ്രവർത്തിക്കുകയും ചെയ്യുന്നു; യൂണിറ്റ് ഉള്ള ഓട്ടക്കാരുടെ 48 മണിക്കൂർ പഴക്കമുള്ള ചെക്ക്ഔട്ടുകൾ വെട്ടിമാറ്റുന്നു**നിർത്തി** ; ഡിസ്കിലെ അലേർട്ടുകൾ ≥ 85 %, മെമ്മറി PSI `full/avg60` ≥ 10 %, കൂടാതെ `MAX_ACTIVE_RUNNERS` നേക്കാൾ കൂടുതൽ ശ്രോതാക്കൾ (ഒരു omniroute/other തകരാർ ഉള്ളത്). എക്സിറ്റ് 1 = ശ്രദ്ധ ആവശ്യമാണ്; ലോഗ് വായിക്കുക.

ഒരു പ്രക്രിയ അനാഥമാണെന്ന് കടന്നുപോകുന്ന സമയം മാത്രം തെളിയിക്കുന്നില്ല. കാവൽക്കാരൻ ഒരിക്കലും പ്രായത്തെ അടിസ്ഥാനമാക്കി സിഗ്നലുകൾ അയയ്ക്കുന്നില്ല. നിലവിലുള്ള `ZOMBIE_BUILD_MAX_MIN`, `ZOMBIE_BUILD_COMM` പരിസ്ഥിതി നാമങ്ങൾ ക്രോൺ കോൺഫിഗറേഷനുകൾക്കായി പിന്തുണയ്ക്കുന്നു. സംശയിക്കപ്പെടുന്ന ഒരു അനാഥയെ വൃത്തിയാക്കുന്നതിന് മുമ്പ്, അതിൻ്റെ കൃത്യമായ GitHub ജോലി ടെർമിനലാണെന്ന് സ്ഥിരീകരിക്കുകയും ആ ജോലിയുമായി ബന്ധപ്പെട്ട പ്രക്രിയകൾ തിരിച്ചറിയുകയും ചെയ്യുക. `Runner.Listener` അതിൻ്റെ ജോലി പുതുക്കാൻ കഴിയാതെ വരുമ്പോൾ, `_diag/Runner_*.log` `POST request to …/renewjob timed out after 100 seconds` കാണിക്കുന്നു, അവസാനത്തെ വിജയകരമായ പുതുക്കലിന് ഏകദേശം പത്ത് മിനിറ്റിന് ശേഷം API ജോലി `completed` (പരാജയം) റിപ്പോർട്ട് ചെയ്യുന്നു, കൂടാതെ `next-build` ഒരു ജോലിയും അറ്റാച്ച് ചെയ്യാതെ പ്രവർത്തിക്കുന്നു (2026-10-18: #17066 ബിൽഡ് 19:43-ന് പരാജയപ്പെട്ടു, അതിൻ്റെ ബിൽഡ് GB അഞ്ച് മിനിറ്റിനുള്ളിൽ തുടർന്നു). ഏറ്റവും പുതിയ `_diag/Worker_*.log` ൽ റെഫർ സ്ഥിരീകരിക്കുക, തുടർന്ന് PID — `next-build`, `npm run build`, `build-next-isolated.mjs`, `_work` തൊഴിലാളികൾ എന്നിവരുടെ ബിൽഡ് ട്രീ SIGTERM മാത്രം. `Runner.Listener`, `RunnerService.js` അല്ലെങ്കിൽ `Runner.Worker` ഒരിക്കലും സ്പർശിക്കരുത്: ജോലി റദ്ദാക്കിയതായി തൊഴിലാളി റിപ്പോർട്ടുചെയ്യുകയും ശ്രോതാവ് സ്വയം ഓൺലൈനിലേക്ക് മടങ്ങുകയും ചെയ്യുന്നു.

## റണ്ണർ യൂണിറ്റുകൾ: KillMode

റണ്ണറിന്റെ ഡിഫോൾട്ട് `KillMode=process`, ഒരു യൂണിറ്റ് നിർത്തുകയോ പുനരാരംഭിക്കുകയോ ചെയ്യുമ്പോൾ `Runner.Worker → npm → next-build` പ്രവർത്തിച്ചുകൊണ്ടിരിക്കാൻ അനുവദിക്കുന്നു — ജോബ് അറ്റാച്ച് ചെയ്തിട്ടില്ലാത്ത ഒരു അനാഥ ബിൽഡ് RAM-ഉം CPU-ഉം തുടർന്നും ഉപയോഗിച്ചുകൊണ്ടിരിക്കും. ഓരോ OmniRoute യൂണിറ്റിലും `KillMode=mixed` ഉള്ള ഒരു drop-in (`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`) ഉണ്ട്: ആദ്യം listener-ലേക്ക് SIGTERM, തുടർന്ന് `TimeoutStop`-ൽ മുഴുവൻ cgroup-ലേക്കും SIGKILL. യൂണിറ്റിന്റെ അടുത്ത പുനരാരംഭത്തിൽ ഇത് പ്രാബല്യത്തിൽ വരും — നിഷ്ക്രിയമാണോയെന്ന പരിശോധനയും പുനരാരംഭവും ഒരേ കമാൻഡിൽ നടത്തി, **ഒരു സമയം ഒരു റണ്ണർ മാത്രം, അത് നിഷ്ക്രിയമായിരിക്കുമ്പോൾ മാത്രം** പുനരാരംഭിക്കുക.
