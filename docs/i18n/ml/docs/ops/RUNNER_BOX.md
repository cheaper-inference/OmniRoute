OmniRoute റണ്ണറിനും **ഒരു റോൾ**, ഒരു ലേബൽ, അതിന്റെ വർക്ക്ലോഡിൽ അളന്ന ആവശ്യത്തിനനുസരിച്ചുള്ള മെമ്മറി/CPU ബജറ്റ്

`systemctl set-property --runtime … MemoryHigh=… MemoryMax=… CPUQuota=…` ഉപയോഗിച്ച് തത്സമയം പ്രയോഗിച്ചു — restart ചെയ്തിട്ടില്ല, അതിനാൽ

(`gh api -X DELETE repos/<repo>/actions/runners/<id>/labels/<label>` /
`gh api -X POST repos/<repo>/actions/runners/<id>/labels -f 'labels[]=<label>'`); ഇതും തത്സമയം തന്നെയാണ്.

## janitor ഇൻസ്റ്റാൾ ചെയ്യുക (ഒറ്റത്തവണ, മെഷീനിൽ)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ഓരോ 30 മിനിറ്റിലും, /var/log/runner-janitor.log-ലേക്ക് ലോഗ് ചെയ്യുക
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` ആവശ്യമാണ്: ഒരു പാത്ത് നീക്കം ചെയ്യുന്നതിനുമുമ്പ് തുറന്നിരിക്കുന്ന ഫയലുകളുടെ ഒരൊറ്റ സ്നാപ്പ്ഷോട്ട് ഉപയോഗിച്ച് അത് നിഷ്ക്രിയമാണെന്ന് janitor ഉറപ്പാക്കുന്നു; ഈ ടൂൾ ഇല്ലെങ്കിൽ അത് ഒന്നും നീക്കം ചെയ്യില്ലെന്നും അക്കാര്യം അറിയിക്കുകയും ചെയ്യും (exit 1). ഏത് മാറ്റവും ആദ്യം `--dry-run` ഉപയോഗിച്ച് പരീക്ഷിക്കുക — അത് എന്താണ് ചെയ്യാൻ പോകുന്നതെന്ന് കൃത്യമായി പ്രിന്റ് ചെയ്യുകയും ഒന്നിലും മാറ്റം വരുത്താതിരിക്കുകയും ചെയ്യും.

ഓരോ റണ്ണിലും ഇത് ചെയ്യുന്നത്: **tmpfs-ൽ 3 മണിക്കൂറിനും** ഡിസ്കിലെ `_work/_temp`-ൽ 24 മണിക്കൂറിനും ശേഷം നമ്മുടെ തന്നെ ശേഷിപ്പുകൾ (`runner-*`, `omniroute-*`, `next-build*`, `e2e-build.tar.gz`) നീക്കം ചെയ്യുന്നു; 75 മിനിറ്റിൽ കൂടുതൽ പഴക്കമുള്ള `next-build` അവസാനിപ്പിക്കുന്നു (ഒരു ജോബും അത്രനേരം പ്രവർത്തിക്കാറില്ല — 2026-08-27-ന് GitHub അതിന്റെ ജോബ് നഷ്ടപ്പെട്ടതായി പ്രഖ്യാപിച്ചതിനുശേഷവും ഒന്ന് 70 മിനിറ്റ് പ്രവർത്തിച്ചു); യൂണിറ്റ് **നിർത്തിയിരിക്കുന്ന** റണ്ണറുകളുടെ 48 മണിക്കൂർ പഴക്കമുള്ള checkouts നീക്കം ചെയ്യുന്നു; ഡിസ്ക് ഉപയോഗം ≥ 85 %, memory PSI `full/avg60` ≥ 10 %, കൂടാതെ listeners-ന്റെ എണ്ണം `MAX_ACTIVE_RUNNERS`-നേക്കാൾ കൂടുതലാകുക എന്നിവയിൽ മുന്നറിയിപ്പ് നൽകുന്നു (omniroute/other വിഭജനത്തോടെ). Exit 1 = ശ്രദ്ധ ആവശ്യമാണ്; ലോഗ് വായിക്കുക.

GitHub ഇതിനകം ഉപേക്ഷിച്ച ഒരു ജോബിന്റെ ബിൽഡ് 75 മിനിറ്റ് നിയമം കണ്ടെത്തില്ല. `Runner.Listener`-ന് അതിന്റെ ജോബ് പുതുക്കാൻ കഴിയാതിരിക്കുമ്പോൾ, `_diag/Runner_*.log`-ൽ `POST request to …/renewjob timed out after 100 seconds` എന്ന് കാണിക്കും; അവസാനമായി വിജയകരമായി പുതുക്കിയതിന് ഏകദേശം പത്ത് മിനിറ്റിനുശേഷം API ജോബ് `completed` (പരാജയം) എന്ന് റിപ്പോർട്ട് ചെയ്യും; എന്നാൽ ജോബ് അറ്റാച്ച് ചെയ്തിട്ടില്ലാതെ `next-build` തുടർന്നും പ്രവർത്തിക്കും (2026-10-18: #17066-ന്റെ ബിൽഡ് 19:43-ന് പരാജയപ്പെട്ടെങ്കിലും അഞ്ച് മിനിറ്റിനുശേഷവും അതിന്റെ ബിൽഡ് 40 GB കൈവശം വച്ചിരുന്നു). ഏറ്റവും പുതിയ `_diag/Worker_*.log`-ൽ ref സ്ഥിരീകരിക്കുക; തുടർന്ന് PID ഉപയോഗിച്ച് ബിൽഡ് ട്രീ മാത്രം SIGTERM ചെയ്യുക — `next-build`, `npm run build`, `build-next-isolated.mjs`, `_work` workers എന്നിവ. `Runner.Listener`, `RunnerService.js`, അല്ലെങ്കിൽ `Runner.Worker` എന്നിവ ഒരിക്കലും സ്പർശിക്കരുത്: worker ജോബ് റദ്ദാക്കിയതായി റിപ്പോർട്ട് ചെയ്യും, listener സ്വയം വീണ്ടും ഓൺലൈനാകും.

## റണ്ണർ യൂണിറ്റുകൾ: KillMode

റണ്ണറിന്റെ ഡിഫോൾട്ട് `KillMode=process`, ഒരു യൂണിറ്റ് നിർത്തുകയോ പുനരാരംഭിക്കുകയോ ചെയ്യുമ്പോൾ `Runner.Worker → npm → next-build` പ്രവർത്തിച്ചുകൊണ്ടിരിക്കാൻ അനുവദിക്കുന്നു — ജോബ് അറ്റാച്ച് ചെയ്തിട്ടില്ലാത്ത ഒരു അനാഥ ബിൽഡ് RAM-ഉം CPU-ഉം തുടർന്നും ഉപയോഗിച്ചുകൊണ്ടിരിക്കും. ഓരോ OmniRoute യൂണിറ്റിലും `KillMode=mixed` ഉള്ള ഒരു drop-in (`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`) ഉണ്ട്: ആദ്യം listener-ലേക്ക് SIGTERM, തുടർന്ന് `TimeoutStop`-ൽ മുഴുവൻ cgroup-ലേക്കും SIGKILL. യൂണിറ്റിന്റെ അടുത്ത പുനരാരംഭത്തിൽ ഇത് പ്രാബല്യത്തിൽ വരും — നിഷ്ക്രിയമാണോയെന്ന പരിശോധനയും പുനരാരംഭവും ഒരേ കമാൻഡിൽ നടത്തി, **ഒരു സമയം ഒരു റണ്ണർ മാത്രം, അത് നിഷ്ക്രിയമായിരിക്കുമ്പോൾ മാത്രം** പുനരാരംഭിക്കുക.
