## ഒരു റിലീസ് ബ്രാഞ്ചിൽ ലാൻഡിംഗ്

ഓമ്നി-ക്യൂ `release/vX.Y.Z` യിലേക്കുള്ള ലാൻഡിംഗുകളെ നിയന്ത്രിക്കുന്നു. ഒരു PR ഇറങ്ങുന്നതിന് മുമ്പ് ഡിഫോൾട്ട് ബ്രാഞ്ചിൽ `config/merge-queue/config.json` ൽ ഉയർന്ന തലത്തിലുള്ള `mode` വായിക്കുക. [ഓമ്നി-ക്യൂ](OMNI_QUEUE.md) കാണുക.

- **`shadow`** മൂല്യനിർണ്ണയം പ്രവർത്തിപ്പിക്കുകയും ലാൻഡിംഗ് ഒരു മാനുവൽ ലയനത്തിലേക്ക് വിടുകയും ചെയ്യുന്നു. അതിൻ്റെ അവസാന തലത്തിലുള്ള അംഗീകൃത PR ലേക്ക് `omni-queue` പ്രയോഗിക്കുക. `npm run queue -- why <PR>` ഉപയോഗിച്ച് യോഗ്യത പരിശോധിക്കുക. `npm run queue -- history --base <branch>` ൽ ആ തലയ്ക്കുള്ള വിധിക്കായി കാത്തിരിക്കുക. `would-land` ൽ തുടരുക. `culprit-found` അല്ലെങ്കിൽ `would-dequeue`, ലയനം അമർത്തിപ്പിടിക്കുക, കാരണം പരിഹരിക്കുക.
- **ഷാഡോ ഒഴിവാക്കലുകൾ.** നിലവിലെ ബേസ് ടിപ്പിനെതിരെ പച്ച നിറത്തിലുള്ള CI ഉള്ള ട്രെയിനിന് പ്രത്യേക ക്യൂ വിധിയില്ലാതെ മുന്നോട്ട് പോകാനാകും. PR തലയിൽ നിലവിലുള്ള അടിസ്ഥാന നുറുങ്ങ് ഇതിനകം അടങ്ങിയിരിക്കുമ്പോൾ ഇതേ ഒഴിവാക്കൽ ബാധകമാണ്.
- **`live`** ലാൻഡിംഗ് ട്രിഗർ ചെയ്യാൻ `omni-queue` ലേബൽ ഉപയോഗിക്കുന്നു. ക്യൂ മാത്രം PR ലാൻഡ് ചെയ്യുന്നു. മെർജ് കമാൻഡുകളും നേരിട്ടുള്ള പുഷുകളും ക്യൂവിലേക്ക് വിടുക.

ഓരോ ലാൻഡിംഗിനും ഉടമയുടെ അംഗീകാരവും ബാധകമായ ആവശ്യമായ പരിശോധനകളും ആവശ്യമാണ്. ഉടമ ലാൻഡിംഗിന് അനുമതി നൽകിയതിന് ശേഷം മാത്രം `omni-queue` പ്രയോഗിക്കുക. ക്യൂവിലുള്ള PRs സംരക്ഷിത പാതകൾക്കും ആ PR യ്ക്ക് ഉടമയുടെ `protected-approved` തീരുമാനം ആവശ്യമാണ്.

"ആക്റ്റീവ് റിലീസിൽ ഗ്രീൻ ഗേറ്റുകൾ ആവശ്യമാണ്" എന്ന റൂൾസെറ്റിന് തലയിൽ പച്ച `Gate / CI`, `Gate / Quality` എന്നിവ ആവശ്യമാണ്. ചുവന്ന ഗേറ്റ് മറികടക്കാൻ ഒരിക്കലും `--admin` ഉപയോഗിക്കരുത്. ഒരു റിലീസ് ഫ്രീസ് ബ്ലോക്കുകൾ ഫ്രോസൺ ബ്രാഞ്ചിലേക്ക് ലയിക്കുന്നു. [ഹാർഡ് റൂൾ 21](HARD_RULES_DETAIL.md) കാണുക. മറ്റൊരു സെഷൻ പ്രവർത്തിക്കുന്നുണ്ടെന്ന് ഒരിക്കലും ലേബൽ ചെയ്യുകയോ ലയിപ്പിക്കുകയോ പുൾ അഭ്യർത്ഥനയിലേക്ക് തള്ളുകയോ ചെയ്യരുത്. [ഹാർഡ് റൂൾ 22](HARD_RULES_DETAIL.md) കാണുക.

## ട്രെയിൻ വലിക്കാനുള്ള അഭ്യർത്ഥന

1. നിലവിലെ റിലീസ് അടിസ്ഥാന ടിപ്പിൽ ഒരു ട്രെയിൻ ബ്രാഞ്ച് ആരംഭിക്കുക. ലയന കമ്മിറ്റുകൾ ഉപയോഗിച്ച് കൃത്യമായ അംഗീകൃത അംഗ മേധാവികളെ സംയോജിപ്പിക്കുക. സ്ക്വാഷും റീബേസും ഒഴിവാക്കി അവരുടെ പ്രതിബദ്ധതയുള്ള ചരിത്രം സംരക്ഷിക്കുക.
2. ട്രെയിൻ ബ്രാഞ്ചിനായി ഒരു പുൾ അഭ്യർത്ഥന തുറക്കുക. നിലവിലെ അടിസ്ഥാന നുറുങ്ങിൽ സ്വന്തം മുഴുവൻ CI ഉപയോഗിച്ച് ആ PR സാധൂകരിക്കുക. ലാൻഡിംഗിന് മുമ്പ് അടിസ്ഥാന ടിപ്പും അംഗീകൃത അംഗ തലങ്ങളും വീണ്ടും പരിശോധിക്കുക. സാധുതയുള്ള കാൻഡിഡേറ്റ് മാറുമ്പോൾ ട്രെയിനും അതിൻ്റെ CI പുതുക്കുക.
3. ബാധകമായ ക്യൂ മോഡിന് കീഴിൽ ഒരു ലയന കമ്മിറ്റ് ഉപയോഗിച്ച് ട്രെയിൻ PR ലാൻഡ് ചെയ്യുക. തത്സമയ മോഡിൽ, ക്യൂവിൻ്റെ `merge-ff` ലാൻഡിംഗ് രീതി ലയന കമ്മിറ്റുകൾ സംരക്ഷിക്കുന്നു. യഥാർത്ഥ അംഗ തലവന്മാർക്ക് റിലീസ് ബ്രാഞ്ചിൽ നിന്ന് എത്തിച്ചേരാനാകും. GitHub അംഗത്തെ PRs ലയിപ്പിച്ചതായി അടയാളപ്പെടുത്തുകയും കമ്മിറ്റുകൾ അവരുടെ രചയിതാക്കളെ നിലനിർത്തുകയും ചെയ്യുന്നു.

ഒരു പൊതു ഉദാഹരണം [PR #21071](https://github.com/cheaper-inference/OmniRoute/pull/21071) ആണ്. ഇത് 18 അംഗ PRs സംയോജിപ്പിക്കുകയും 2026-11-24-ന് ഒരു ലയന കമ്മിറ്റുമായി ഇറങ്ങുകയും ചെയ്തു.

`main` ൽ നിന്ന് അടുത്ത റിലീസ് ബ്രാഞ്ചിലേക്കുള്ള ഒരു സമന്വയവും ഒരു ലയന കമ്മിറ്റിലൂടെ ലാൻഡ് ചെയ്യുന്നു. പിന്നീടുള്ള സമന്വയ-ബാക്കുകൾക്ക് `main` വംശപരമ്പര സംരക്ഷിക്കേണ്ടതുണ്ട്. [വർക്ക്ട്രീ ഐസൊലേഷൻ](WORKTREE_ISOLATION.md#sync-back-landings-are-merge-commits-never-squash) കാണുക.

## ലോക്കൽ മെർജ്-ട്രെയിൻ വാലിഡേറ്റർ

```bash
scripts/release/merge-train.sh [--plan] [--fast] <base-branch> <PR#> [<PR#>...]
```

വാലിഡേറ്റർ ബേസ്, PR തലകൾ ലഭ്യമാക്കുകയും ഒരു ഡിസ്പോസിബിൾ വർക്ക്ട്രീയിൽ അവയെ സംയോജിപ്പിക്കുകയും ചെയ്യുന്നു. തത്ഫലമായുണ്ടാകുന്ന ട്രീയിൽ ഒരിക്കൽ അതിൻ്റെ പാരിറ്റി സ്യൂട്ട് പ്രവർത്തിപ്പിക്കുന്നു. ഒരു പരാജയപ്പെട്ട തല കണ്ടെത്തൽ അല്ലെങ്കിൽ ലയിപ്പിക്കൽ വൈരുദ്ധ്യം PR പുറന്തള്ളുകയും സ്ക്രിപ്റ്റ് ശേഷിക്കുന്ന PRs യിൽ തുടരുകയും ചെയ്യുന്നു.

- **`--plan`** തിരഞ്ഞെടുത്ത മോഡിൻ്റെ ഘട്ടങ്ങൾ പ്രിൻ്റ് ചെയ്ത് ഒരു വർക്ക്ട്രീ സൃഷ്ടിക്കുകയോ റിമോട്ടുമായി ബന്ധപ്പെടുകയോ ചെയ്യാതെ പുറത്തുകടക്കുന്നു. ഫാസ്റ്റ് പ്ലാൻ പരിശോധിക്കാൻ ഇത് `--fast` മായി സംയോജിപ്പിക്കുക.
- **`--fast`** സാധാരണ സ്റ്റാറ്റിക് ഗേറ്റുകൾ പ്രവർത്തിപ്പിക്കുന്നു, തിരഞ്ഞെടുത്ത മാറ്റിയ `node:test` ഫയലുകൾ `tests/unit/`, കൂടാതെ `npm run test:vitest`. ഫാസ്റ്റ് മോഡ് ഉപയോഗിക്കുമ്പോൾ കുമിഞ്ഞുകൂടിയ ടിപ്പിൽ ദിവസത്തിൽ ഒരിക്കലെങ്കിലും പൂർണ്ണമായ പ്രാദേശിക മൂല്യനിർണ്ണയം പ്രവർത്തിപ്പിക്കുക.
- **പൂർണ്ണ മോഡ്** പൂർണ്ണമായ സ്റ്റാറ്റിക് ഗേറ്റുകൾ ചേർക്കുകയും `npm run test:unit`, `npm run test:vitest` എന്നിവ പ്രവർത്തിപ്പിക്കുകയും ചെയ്യുന്നു.

ബേസ് പ്രോബ് ലഭ്യമാണെങ്കിൽ, പരാജയപ്പെടുന്ന സ്റ്റാറ്റിക് ഗേറ്റ് അൺടച്ച്ഡ് ബേസിൽ വീണ്ടും പ്രവർത്തിപ്പിക്കും. സ്ക്രിപ്റ്റ് പാരമ്പര്യമായി ലഭിച്ച പരാജയങ്ങൾ റിപ്പോർട്ടുചെയ്യുകയും എല്ലാ അംഗീകൃത ലംഘന വരികളും അടിത്തട്ടിൽ ദൃശ്യമാകുകയും മൊത്തം എണ്ണം വർദ്ധിക്കാതിരിക്കുകയും ചെയ്യുമ്പോൾ അത് തുടരുന്നു.

## ടയറിംഗ്

- **ഓരോ PR.** CI, ഗുണനിലവാരം എന്നിവ മാറ്റിയ പാതകളെ അടിസ്ഥാനമാക്കിയുള്ള പരിശോധനകൾ തിരഞ്ഞെടുക്കുക. കോഡ് PRs റൺ ഫാസ്റ്റ് ക്വാളിറ്റി ഗേറ്റുകളും ഇംപാക്ടഡ് ടെസ്റ്റുകളും, CI യിൽ പ്രത്യേക യൂണിറ്റും Vitest ജോലികളും ഉണ്ട്.
- **ഓരോ ക്യൂ സ്ഥാനാർത്ഥിക്കും.** CI, Quality എന്നിവ കമ്പോസ് ചെയ്ത കാൻഡിഡേറ്റിൻ്റെ മുഴുവൻ പ്രൊഫൈലും അതിൻ്റെ ക്യൂ റഫറിൽ പ്രവർത്തിപ്പിക്കുന്നു.
- **ഓരോ റിലീസ് നുറുങ്ങിനും.** റിലീസ്-ഗ്രീൻ അതിൻ്റെ പാത്ത് ഫിൽട്ടറുകളുമായി പൊരുത്തപ്പെടുന്ന പുഷുകളിൽ ദ്രുത ഹാർഡ് ഗേറ്റുകൾ പ്രവർത്തിപ്പിക്കുന്നു. പ്രതിദിനം മൂന്ന് ഷെഡ്യൂൾ ചെയ്ത റണ്ണുകൾ റിലീസ് ബ്രാഞ്ചിനായി ഫുൾ സ്വീപ്പ് ഉപയോഗിക്കുന്നു.
- **ഓരോ റിലീസ്.** മുഴുവൻ CI മാട്രിക്സിൽ E2E ഷാർഡുകൾ, പാക്കേജ് മൂല്യനിർണ്ണയം, ടാർബോൾ ബൂട്ട് സ്മോക്ക്, കവറേജ് പരിശോധനകൾ എന്നിവ ഉൾപ്പെടുന്നു. [റിലീസ് ചെക്ക്ലിസ്റ്റ്](RELEASE_CHECKLIST.md) കാണുക.

## `merge-train.sh` പുതിയ-ചെക്കൗട്ട് മുൻവ്യവസ്ഥകൾ

വർക്ക് ട്രീകൾ സൃഷ്ടിക്കുന്നതിന് മുമ്പ് പ്രിഫ്ലൈറ്റ് പ്രവർത്തിക്കുന്നു. `npm ci` ഉപയോഗിച്ച് ഡിപൻഡൻസികൾ ഇൻസ്റ്റാൾ ചെയ്യുക. `node_modules/.bin/tsc` എക്സിക്യൂട്ടബിൾ ആണെന്നും `node_modules/node_modules` ഇല്ലെന്നും സ്ഥിരീകരിക്കുക. `node_modules/.bin/bun --version` വിജയിച്ചോ എന്ന് പരിശോധിക്കുക.

Bun postinstall ഒഴിവാക്കിയിട്ടുണ്ടെങ്കിൽ, `(cd node_modules/bun && node install.js)` പ്രവർത്തിപ്പിക്കുക. ദാതാവിൻ്റെ സ്ഥിരതയും അറിയപ്പെടുന്ന ചിഹ്ന പരിശോധനകളും Bun ഉപയോഗിക്കുന്നു. വാലിഡേറ്റർ `npm run check:cycles:ratchet` ഒരു തടയൽ ഗേറ്റായി പ്രവർത്തിക്കുന്നു. ഒറ്റപ്പെട്ട `npm run check:cycles` കമാൻഡ് ഉപദേശമാണ്.
