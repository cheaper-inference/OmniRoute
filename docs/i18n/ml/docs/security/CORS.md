OmniRoute ഏത് നിയന്ത്രിക്കുന്നു**ബ്രൗസർ ഉത്ഭവം** ഒരൊറ്റ കേന്ദ്രീകൃത അനുവദനീയ ലിസ്റ്റിൽ നിന്നുള്ള ക്രോസ്-ഒറിജിൻ പ്രതികരണങ്ങൾ വായിച്ചേക്കാം. മോഡൽ ആണ്**സ്ഥിരസ്ഥിതിയായി പരാജയപ്പെട്ടു** : നിങ്ങൾ ഒരെണ്ണം തിരഞ്ഞെടുക്കുന്നത് വരെ ഒരു ഉത്ഭവവും അനുവദനീയമല്ല. ഈ പേജ് അനുവദനീയ പട്ടിക എങ്ങനെ പരിഹരിക്കുന്നു, `CORS_ALLOW_ALL=true` യഥാർത്ഥത്തിൽ എന്താണ് തുറന്നുകാട്ടുന്നത് (കൂടാതെ, പ്രധാനമായി, അത് എന്താണ് ചെയ്യുന്നത് എന്ന് രേഖപ്പെടുത്തുന്നു.**അല്ല** ), എങ്ങനെ സുരക്ഷിതമായി dev vs പ്രൊഡക്ഷൻ കോൺഫിഗർ ചെയ്യാം, ഒരു വൈൽഡ്കാർഡ് ലൈവ് ആയിരിക്കുമ്പോൾ ഡാഷ്ബോർഡ് കാണിക്കുന്ന റൺടൈം മുന്നറിയിപ്പ്.

**സത്യത്തിൻ്റെ ഉറവിടം:** `src/server/cors/origins.ts` (`resolveAllowedOrigin`, `applyCorsHeaders`, `getCorsStatus`). അനുവദനീയമായ ലിസ്റ്റ് ഒരിക്കൽ പ്രയോഗിക്കുന്നു, മിഡിൽവെയറിൽ (`src/server/authz/pipeline.ts`) — പെർ-റൂട്ട് ഹാൻഡ്ലറുകൾ `Access-Control-Allow-Origin` സ്വയം സജ്ജമാക്കുന്നില്ല.

## ഒരു ഉത്ഭവം എങ്ങനെ പരിഹരിക്കപ്പെടും

ഓരോ അഭ്യർത്ഥനയ്ക്കും മിഡിൽവെയർ ഈ ക്രമത്തിൽ `Access-Control-Allow-Origin` മൂല്യം കണക്കാക്കുന്നു:

1. **`CORS_ALLOW_ALL=true`** (അല്ലെങ്കിൽ ലെഗസി `CORS_ORIGIN=*`) → ഉപയോഗിച്ച് കോളർ `Origin` ബാക്ക് (അല്ലെങ്കിൽ `Origin` ഹെഡർ ഇല്ലെങ്കിൽ `*` ) `Vary: Origin` പ്രതിധ്വനിക്കുന്നു, അതിനാൽ കാഷെകൾ ശരിയായിരിക്കും. ടോക്കൺ-ആധികാരികമാക്കിയ `/v1*`/`/v1beta*` ഉപരിതലത്തിലെ (`relaxForTokenAuth`, RFC 9110 §12.5.5, ഇഷ്യൂ #6737) ഓരോ 2xx-വിത്ത്-ബോഡി പ്രതികരണത്തിലും ഇതേ `applyCorsHeaders()` ചോക്ക്പോയിൻ്റ് `Vary: Accept-Encoding` ചേർക്കുന്നു, അതിനാൽ downstream/shared കാഷെകൾക്ക് കംപ്രസ് ചെയ്തതും അൺകംപ്രസ്സുചെയ്തതുമായ വേരിയൻ്റുകളെ കൃത്യമായി വേർതിരിച്ചറിയാൻ കഴിയും.
2. അല്ലാത്തപക്ഷം, അഭ്യർത്ഥന `Origin` നോർമലൈസ് ചെയ്തിരിക്കുന്നു (ലോവർ-കേസ്ഡ്, ട്രെയിലിംഗ് സ്ലാഷ് സ്ട്രിപ്പ് ചെയ്തു) ഒപ്പം പൊരുത്തപ്പെടുത്തുകയും ചെയ്യുന്നു**ലയിപ്പിച്ച അനുവദനീയ പട്ടിക** :
   - env **`CORS_ALLOWED_ORIGINS`** — കോമയാൽ വേർതിരിച്ച ലിസ്റ്റ്, കൂടാതെ
   - റൺടൈം**`corsOrigins`** ക്രമീകരണം (ഡാഷ്ബോർഡ് → സെക്യൂരിറ്റി → _CORS അനുവദനീയമായ ഉത്ഭവം_), `src/lib/config/runtimeSettings.ts` ൽ നിന്ന് `setRuntimeAllowedOrigins()` വഴി കുത്തിവയ്ക്കുന്നു.
3. → യുമായി പൊരുത്തപ്പെടുന്നില്ല **`Access-Control-Allow-Origin` തലക്കെട്ടൊന്നും പുറപ്പെടുവിച്ചിട്ടില്ല** . ബ്രൗസർ ക്രോസ് ഒറിജിൻ റീഡ് തടയുന്നു. ഇത് ഉദ്ദേശിച്ച പരാജയ-ക്ലോസ്ഡ് ഡിഫോൾട്ടാണ്.

| Env var                | അർത്ഥം                                                                                                               |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `CORS_ALLOWED_ORIGINS` | അനുവദിക്കുന്നതിന് കൃത്യമായ ഉത്ഭവത്തിൻ്റെCSV (ശുപാർശ ചെയ്യുന്നു).                                                     |
| `CORS_ALLOW_ALL`       | `true`/`1` → ഏതെങ്കിലും ഉത്ഭവം (വൈൽഡ്കാർഡ്) പ്രതിധ്വനിപ്പിക്കുന്നു. ദേവ് മാത്രം.                                     |
| `CORS_ORIGIN`          | പാരമ്പര്യം. `*` `CORS_ALLOW_ALL` പോലെയാണ് പെരുമാറുന്നത്; അനുവദനീയമായ ലിസ്റ്റിലേക്ക് ഒരൊറ്റ മൂല്യം ചേർത്തിരിക്കുന്നു. |

## `CORS_ALLOW_ALL=true` യഥാർത്ഥത്തിൽ തുറന്നുകാട്ടുന്ന ഭീഷണി മോഡൽ —

പൊതുവായ OWASP മുന്നറിയിപ്പ് ("വൈൽഡ്കാർഡ് CORS = ഏത് സൈറ്റിനും നിങ്ങളുടെ API എന്ന് വിളിക്കാം") ഗൗരവമായി എടുക്കേണ്ടതാണ്, എന്നാൽ OmniRoute യുടെ എക്സ്പോഷർ **ജനറിക് കേസിനേക്കാൾ ഇടുങ്ങിയതാണ്** , ഒരു വ്യക്തമായ നടപ്പാക്കൽ വസ്തുത കാരണം:

> **സെൻട്രൽ `applyCorsHeaders()` ഒരിക്കലും `Access-Control-Allow-Credentials` പുറപ്പെടുവിക്കുന്നില്ല.** സെർവർ `Access-Control-Allow-Credentials: true` അയയ്ക്കുന്നില്ലെങ്കിൽ ഒരു ബ്രൗസർ _credentialed_ (കുക്കി-ബെയറിംഗ്) ക്രോസ്-ഒറിജിൻ പ്രതികരണം വെളിപ്പെടുത്തില്ല. OmniRoute ൻ്റെ പങ്കിട്ട CORS പാത ഒരിക്കലും ചെയ്യില്ല.

`CORS_ALLOW_ALL=true` ഉപയോഗിച്ച് പോലും, ഓരോ ഉപരിതലത്തിനും എന്താണ് അർത്ഥമാക്കുന്നത്:

| ഉപരിതലം                             | ഓത്ത് മെക്കാനിസം               | വൈൽഡ്കാർഡ് CORS യുടെ പ്രഭാവം                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ഡാഷ്ബോർഡ് / MANAGEMENT `/api/*`     | കുക്കി സെഷൻ                    | ഉത്ഭവം പ്രതിധ്വനിക്കുന്നു, പക്ഷേ**`Allow-Credentials` ഇല്ലാതെ** ബ്രൗസർ **ബ്ലോക്കുകൾ** യോഗ്യതയുള്ള വായന. ക്ഷുദ്രകരമായ ക്രോസ്-ഒറിജിൻ സൈറ്റ്**വായിക്കാൻ കഴിയില്ല** നിങ്ങളുടെ അംഗീകൃത ഡാഷ്ബോർഡ് പ്രതികരണങ്ങൾ, കൂടാതെ സെഷൻ കുക്കി വെളിപ്പെടുത്തിയിട്ടില്ല.                                                                                                                                                                                                                                                                                                           |
| ക്ലയൻ്റ് API `/v1/*`, `/v1beta/*`   | ബെയറർ / `x-api-key` തലക്കെട്ട് | ഇതിനകം അനുവദനീയമാണ്**ഡിസൈൻ പ്രകാരം** (`relaxForTokenAuth`): ബ്രൗസറുകൾ ഒരിക്കലും `Authorization`/`x-api-key` സ്വയമേവ അറ്റാച്ചുചെയ്യില്ല, അതിനാൽ ഒരു ആക്രമണകാരിയുടെ പേജിന് നിങ്ങളുടെ കീ നൽകാൻ കഴിയില്ല. റിലാക്സ്ഡ് എക്കോയ്ക്ക് ഒരു ക്രെഡൻഷ്യൽ ഹെഡർ മാത്രമല്ല, ഒരിക്കലും `Access-Control-Allow-Credentials` ഉൾപ്പെടുത്താത്ത ഒരു ആധികാരിക വിഷയം (സാധുതയുള്ള API കീ അല്ലെങ്കിൽ ഡാഷ്ബോർഡ് സെഷൻ) ആവശ്യമാണ്. അജ്ഞാത പ്രതികരണങ്ങൾ (`REQUIRE_API_KEY=false`) ഒരു വ്യക്തമായ `CORS_ALLOW_ALL=true` ഓപ്റ്റ്-ഇൻ ഉൾപ്പെടെ കോൺഫിഗർ ചെയ്ത ഒറിജിൻ അനുവദനീയ പട്ടിക ഉപയോഗിക്കുന്നു. |
| പൊതു വായന-മാത്രം (`/api/health`, …) | ഒന്നുമില്ല                     | നോൺ-സെൻസിറ്റീവ്; വൈൽഡ്കാർഡ് നിരുപദ്രവകരമാണ്.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

അങ്ങനെ ദി**അവശിഷ്ടം** `CORS_ALLOW_ALL=true` യുടെ എക്സ്പോഷർ ഇതിലേക്ക് പരിമിതപ്പെടുത്തിയിരിക്കുന്നു: (a) ക്രെഡൻഷ്യൽ അല്ലാത്ത ക്രോസ്-ഒറിജിൻ **വായിക്കുന്നു** ഇതിനകം-ആധികാരികതയില്ലാത്ത ഡാറ്റ, കൂടാതെ (ബി) CORS അനുവദിക്കുന്നു**പ്രീഫ്ലൈറ്റ് പാസ്** ഒരു ക്രോസ് ഒറിജിൻ പേജിന് നൽകാൻ കഴിയാത്ത ഓത്ത് ആവശ്യമായ — മാനേജ്മെൻ്റ് റൂട്ടുകളിൽ. അത്**അല്ല** പങ്കിട്ട CORS പാതയിലെ ഒരു സെഷൻ-ഹൈജാക്ക് അല്ലെങ്കിൽ ക്രെഡൻഷ്യൽ-തെഫ്റ്റ് വെക്റ്റർ.

### ഒരു യഥാർത്ഥ ഒഴിവാക്കൽ — `/api/v1/agents/`

ക്ലൗഡ്-ഏജൻ്റ് റൂട്ടുകൾ (`/api/v1/agents/{health,credentials,tasks,tasks/[id]}`) അവരുടെ സജ്ജീകരിച്ചിരിക്കുന്നു**സ്വന്തം** CORS തലക്കെട്ടുകൾ (`src/lib/cloudAgent/api.ts`, `getCloudAgentCorsHeaders`) കൂടാതെ**ചെയ്യുക** `Access-Control-Allow-Credentials: true` നൊപ്പം `Access-Control-Allow-Origin: <origin>|*` പുറപ്പെടുവിക്കുക. ഉത്ഭവം-എക്കോയും ക്രെഡൻഷ്യലുകളും ഒരുമിച്ച് നിലനിൽക്കുന്ന ഏക പ്രതലമാണിത്**`CORS_ALLOW_ALL` ൽ നിന്ന് സ്വതന്ത്രമായി** . ഈ റൂട്ടുകൾ മാനേജ്മെൻ്റ്-ആധികാരികതയുള്ളതാണ് (`requireManagementAuth`); ഡാഷ്ബോർഡ് ഓഫ്-ഹോസ്റ്റ് തുറന്നുകാട്ടുന്ന ഓപ്പറേറ്റർമാർ, പ്രതികരണ തലക്കെട്ടുകൾ ക്രോസ്-ഒറിജിൻ ക്രെഡൻഷ്യൽ റീഡ് അനുവദിക്കുന്ന ഒരേയൊരു സ്ഥലമാണെന്ന് അറിഞ്ഞിരിക്കണം. ഈ CORS മാർഗ്ഗനിർദ്ദേശത്തിൽ നിന്ന് പ്രത്യേകം പ്രത്യേകം അനുവദനീയമായ ഒരു അനുവദനീയ ലിസ്റ്റിലേക്ക് ഇത് കർശനമാക്കുന്നു.

## പ്രൊഡക്ഷൻ ചെക്ക്ലിസ്റ്റ്

- **ഉൽപ്പാദനത്തിൽ ഒരിക്കലും `CORS_ALLOW_ALL=true` സജ്ജീകരിക്കരുത്.** സജ്ജമാക്കാതെ വിടുക.
- ഒരു സജ്ജമാക്കുക **വ്യക്തമായ** ഉത്ഭവ പട്ടിക — env var അല്ലെങ്കിൽ സെക്യൂരിറ്റി-ടാബ് ഫീൽഡ്:

  ```bash
  CORS_ALLOWED_ORIGINS="https://app.example.com, https://admin.example.com"
  ```

- OmniRoute ഒരു റിവേഴ്സ് പ്രോക്സി / ടണൽ (nginx, Caddy, Cloudflare ടണൽ, Tailscale) പിന്നിൽ പ്രവർത്തിക്കുന്നുവെങ്കിൽ, CORS**അല്ല** നിങ്ങളുടെ ഒരേയൊരു നിയന്ത്രണം — ലൂപ്പ്ബാക്ക് റൂട്ട് ഗാർഡ് ഇപ്പോഴും സ്പോൺ-കപ്പാബിൾ റൂട്ടുകളെ സംരക്ഷിക്കുന്നു ( [ROUTE_GUARD_TIERS](./ROUTE_GUARD_TIERS.md) കാണുക). 403 "ശരിയാക്കാൻ" `X-Forwarded-For: 127.0.0.1` കെട്ടിച്ചമയ്ക്കരുത്; റൂട്ട് ഗാർഡ് അടയ്ക്കുന്ന RCE ക്ലാസ് വീണ്ടും തുറക്കുന്നു.
- റൺടൈം നില സ്ഥിരീകരിക്കുക: ഡാഷ്ബോർഡ് കാണിക്കുന്നു a **സ്ഥിരമായ ആമ്പർ ബാനർ** `CORS_ALLOW_ALL=true` തത്സമയമാകുമ്പോഴെല്ലാം ഡാഷ്ബോർഡ് → സെക്യൂരിറ്റി → ഓതറൈസേഷൻ ഇൻവെൻ്ററിക്ക് കീഴിൽ, `/api/settings/authz-inventory` ഒരു `cors: { allowAll, allowedOrigins }` എൻവലപ്പ് മോണിറ്ററിംഗ് ടൂളുകൾക്ക് വോട്ടുചെയ്യാനാകും.

## വികസന സൗകര്യം — നിർദ്ദിഷ്ട പ്രാദേശിക ഉത്ഭവം അനുവദിക്കുന്നു

dev-ൽ പോലും നിങ്ങൾക്ക് വൈൽഡ്കാർഡ് വളരെ അപൂർവമായി മാത്രമേ ആവശ്യമുള്ളൂ. നിങ്ങൾ ഉപയോഗിക്കുന്ന dev സെർവറുകൾ മാത്രം അനുവദിക്കുക:

```bash
# Vite (5173) + Next.js (3000) dev servers calling a local OmniRoute
CORS_ALLOWED_ORIGINS="http://localhost:5173, http://localhost:3000"
```

അവഗണിച്ച ട്രെയിലിംഗ് സ്ലാഷുമായി ഒറിജിനുകൾ കെയ്സ് ഇൻസെൻസിറ്റീവ് ആയി പൊരുത്തപ്പെടുന്നു, അതിനാൽ `http://localhost:3000`, `http://localhost:3000/` തുല്യമാണ്. റൺടൈമിൽ ഇതേ CSV സജ്ജമാക്കാൻ കഴിയും**ഡാഷ്ബോർഡ് → സെക്യൂരിറ്റി → CORS അനുവദനീയമായ ഉത്ഭവം** പുനരാരംഭിക്കാതെ.

## API കീകൾ vs കുക്കി സെഷനുകൾ

- **ബെയറർ / `x-api-key` ( `/v1/*` അനുമാന ഉപരിതലം):** ബ്രൗസറുകൾ ഒരിക്കലും ഇവ സ്വയമേവ അറ്റാച്ചുചെയ്യില്ല. CORS ഇവിടെ അർത്ഥവത്തായ ഒരു തടസ്സമല്ല — API കീ തടസ്സം — ആണ്, അതുകൊണ്ടാണ് ആ ഉപരിതലം മനഃപൂർവ്വം അനുവദനീയമായതിനാൽ ബ്രൗസറിനും Electron ക്ലയൻ്റുകൾക്കും അവർക്ക് ഇതിനകം അർഹമായ പ്രതികരണങ്ങൾ വായിക്കാൻ കഴിയും. റിലാക്സ്ഡ് എക്കോയ്ക്ക് ഒരു ക്രെഡൻഷ്യൽ ഹെഡർ മാത്രമല്ല, ഒരിക്കലും `Access-Control-Allow-Credentials` ഉൾപ്പെടാത്ത ഒരു ആധികാരിക വിഷയം (സാധുതയുള്ള API കീ അല്ലെങ്കിൽ ഡാഷ്ബോർഡ് സെഷൻ) ആവശ്യമാണ്. അജ്ഞാത പ്രതികരണങ്ങൾ (`REQUIRE_API_KEY=false`) കോൺഫിഗർ ചെയ്ത ഒറിജിൻ അനുവദനീയ പട്ടിക ഉപയോഗിക്കുന്നു, അതിൽ വ്യക്തമായ `CORS_ALLOW_ALL=true` ഓപ്റ്റ്-ഇൻ ഉൾപ്പെടുന്നു. ഓത്ത് നിരസിക്കലുകൾ (401) റീഡബിൾ ആയി തുടരുന്നു, അതിനാൽ ക്ലയൻ്റുകൾക്ക് അസാധുവാക്കപ്പെട്ടതോ തെറ്റായി ടൈപ്പുചെയ്തതോ ആയ കീ (#5242) പുറത്തുവരാൻ കഴിയും: പൈപ്പ്ലൈനിൻ്റെ സ്വന്തം 401 പ്രതിധ്വനി നിലനിർത്തുന്നു, കൂടാതെ പൈപ്പ്ലൈൻ അജ്ഞാതമായി നൽകിയതിന് ശേഷം കീ നിരസിക്കുന്ന ഒരു റൂട്ട് (`/v1/models` ഉം `/v1beta/models` ഉം മാനേജ്മെൻ്റ് ഓത്ത് കോൺഫിഗർ ചെയ്ത, `/v1/files`, `/v1/batches`, `/v1/media`, `/v1/session-leases` എന്നിവ ഉപയോഗിച്ച് ഓട്ടോ-കോംബോ കാൻഡിഡേറ്റ് റൂട്ടുകൾ) `credentialRejectionHeaders()` വഴി ആ 401-ലേക്ക് പ്രതിധ്വനി ചേർക്കുന്നു. ഒരു ക്രെഡൻഷ്യൽ ഹെഡർ (`Authorization`, `x-api-key`, `x-goog-api-key` അല്ലെങ്കിൽ `auth_token` കുക്കി) വഹിക്കുന്ന അഭ്യർത്ഥനയിൽ പ്രതിധ്വനി കീ ചെയ്യുന്നു, അവയിൽ ഏതിലാണ് റൂട്ട് പരിശോധിച്ചത്, `Access-Control-Allow-Credentials` മായി ജോടിയാക്കില്ല; ശരീരം ഒരു നിശ്ചിത പിശക് എൻവലപ്പാണ്. `requireManagementAuth()` (`/api/v1/management/*`, `/api/v1/registered-keys`, `/api/v1/providers/[provider]/limits`, `/api/v1/accounts/[id]/limits`, `/api/v1/issues/report`) പരിരക്ഷിക്കുന്ന `/api/v1/` യുടെ കീഴിലുള്ള മാനേജ്മെൻ്റ് റൂട്ടുകൾ ഈ ക്രെഡൻഷ്യൽ-റിജക്ഷൻ ഒഴിവാക്കൽ ഉപയോഗിക്കില്ല: `REQUIRE_API_KEY=false` ഉപയോഗിച്ച്, അവരുടെ 401/403 പ്രതികരണങ്ങൾ കോൺഫിഗർ ചെയ്ത CORS ഉറവിട നയം പിന്തുടരുന്നു.
- **കുക്കി സെഷൻ (ഡാഷ്ബോർഡ്):** പരാജയപ്പെട്ട ക്ലോസ്ഡ് ഡിഫോൾട്ട് വഴി പരിരക്ഷിച്ചിരിക്കുന്നു**ഒപ്പം** പങ്കിട്ട പാതയിൽ `Access-Control-Allow-Credentials` ഇല്ലാത്തതിനാൽ. അനുവദനീയമായ ഏതെങ്കിലും കോൺഫിഗറേഷനിൽ നിന്ന് management/dashboard ഉത്ഭവം സൂക്ഷിക്കുക; അവ കൃത്യമായി പരാജയപ്പെടാതെ നിൽക്കണം.

## WebSocket ഹാൻഡ്ഷേക്കുകൾ (`/v1/responses`, `/v1/ws`)

WebSocket ലേക്ക് ബ്രൗസറുകൾ CORS പ്രയോഗിക്കുന്നില്ല, അതിനാൽ WebSocket ട്രാൻസ്പോർട്ടുകൾ റിട്ടേൺ ഔട്ട്പുട്ട് `Origin` ഹാൻഡ്ഷേക്ക് പരിശോധിക്കുക (`src/server/origin/wsOrigin.ts`): പ്രതികരണങ്ങൾ WebSocket (`/v1/responses`) കൂടാതെ, `npm start` / `npm run dev` വഴി OmniRoute ഓടുമ്പോൾ `/v1/ws`, `/api/v1/ws` ബ്രിഡ്ജ്, ഇത് `/v1/chat/completions`, `/v1/messages` `/v1/responses` സ്ട്രീം ചെയ്യുന്നു. പാലം വിധിക്കായി `/api/v1/ws?handshake=1` ആവശ്യപ്പെടുകയും ആ റൂട്ട് പരിശോധന നടത്തിയില്ലെങ്കിൽ നവീകരിക്കാൻ വിസമ്മതിക്കുകയും ചെയ്യുന്നു. പ്രാമാണീകരണ ആവശ്യകതകൾ ഇപ്പോഴും പ്രത്യേകം ബാധകമാണ്. ഉത്ഭവ പരിശോധന കടന്നുപോകുമ്പോൾ:

- ഇതിന് `Origin` തലക്കെട്ടില്ല (Codex CLI, SDKs കൂടാതെ മറ്റ് നോൺ-ബ്രൗസർ ക്ലയൻ്റുകളും);
- മുകളിലുള്ള അനുവദനീയ ലിസ്റ്റ് `Origin` അംഗീകരിക്കുന്നു (`CORS_ALLOWED_ORIGINS`, `corsOrigins` ക്രമീകരണം, `CORS_ORIGIN`, `CORS_ALLOW_ALL`);
- `Origin` OmniRoute യുടെ സ്വന്തം പൊതു ഉത്ഭവങ്ങളിൽ ഒന്നാണ് (കോൺഫിഗർ ചെയ്ത പബ്ലിക് ബേസ് URL, വിശ്വസനീയമായ പ്രോക്സിയുടെ ഫോർവേഡ് ചെയ്ത ഉറവിടം, അല്ലെങ്കിൽ IP ലിറ്ററൽ അല്ലെങ്കിൽ `localhost` — ആയി നൽകിയിരിക്കുന്ന നേരിട്ടുള്ള loopback/LAN ഹോസ്റ്റ് ഡാഷ്ബോർഡ് മ്യൂട്ടേഷൻ പരിശോധന ഉപയോഗിക്കുന്ന അതേ കാൻഡിഡേറ്റുകൾ); അല്ലെങ്കിൽ
- HTTP `/v1/*` പ്രതലത്തിലെന്നപോലെ സാധുവായ ഒരു API കീ അത് വഹിക്കുന്നു.

മറ്റെന്തെങ്കിലും `403 ws_origin_forbidden` ലഭിക്കും. ഒരു ഡാഷ്ബോർഡ് സെഷൻ കുക്കി ഒരു വിദേശ `Origin` ഒഴിവാക്കില്ല, കാരണം ബ്രൗസർ അത് ഏത് പേജിൻ്റെ സോക്കറ്റിലേക്കും അറ്റാച്ചുചെയ്യുന്നു. മറ്റൊരു പോർട്ടിലെ `localhost` അതേ ഉത്ഭവമായി കണക്കാക്കില്ല; അത്തരം dev ഉത്ഭവങ്ങൾ `CORS_ALLOWED_ORIGINS` ലേക്ക് ചേർക്കുക.

## ഉദാഹരണം: OmniRoute യുടെ മുന്നിലുള്ള റിവേഴ്സ് പ്രോക്സി

CORS നടപ്പിലാക്കുന്നത് OmniRoute തന്നെയാണ്, അതിനാൽ പ്രോക്സി പൊതുവേ വേണം**അല്ല** `Access-Control-*` തലക്കെട്ടുകൾ ചേർക്കുക അല്ലെങ്കിൽ മാറ്റിയെഴുതുക (ഇരട്ട തലക്കെട്ടുകൾ ബ്രേക്ക് ബ്രൗസറുകൾ). TLS അവസാനിപ്പിച്ച് — ഫോർവേഡ് ചെയ്യുക OmniRoute പ്രിഫ്ലൈറ്റിന് ഉത്തരം നൽകട്ടെ:

```nginx
# nginx — forward to OmniRoute; do NOT inject Access-Control-* here
location / {
    proxy_pass http://127.0.0.1:20128;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    # Keep the forwarding headers: a proxy on the same host connects from loopback, and they are
    # what tells OmniRoute the caller is not the local operator. A proxy that adds none of them
    # makes every remote caller look local. Never set X-Forwarded-For to 127.0.0.1 either.
}
```

പ്രോക്സിയിലല്ല, OmniRoute (`CORS_ALLOWED_ORIGINS` അല്ലെങ്കിൽ സെക്യൂരിറ്റി ടാബിൽ) അനുവദനീയമായ ബ്രൗസർ ഒറിജിനുകൾ സജ്ജമാക്കുക.
